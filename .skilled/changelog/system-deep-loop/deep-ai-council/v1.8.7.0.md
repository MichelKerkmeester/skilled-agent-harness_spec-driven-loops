# v1.8.7.0, Long Prose Lines Become Short Sentences and Lists

The two opening paragraphs of the operational-modes section were each one very long line. The first sorted out what an in-CLI round is. It also sorted out which models the active runtime can seat. It said why no external dispatch is needed.

The second sorted out when external dispatch helps. It named which executors the resolver accepts. It said where that dispatch is invoked from.

Both are now short sentences. The model bench was a bracket of three runtimes in one sentence. It is now a short list with one runtime per line. Instructions address you directly. The instruction comes before the background.

The content did not change. Every runtime name, model name, executor name and alias in the old lines is still there. The rewrite adds nothing new. What selects this skill is exactly as it was. What it loads first is exactly as it was. How a request routes is exactly as it was.

## What's New at a Glance

- **The in-CLI case reads as four lines.** What the council is. What it seats when invoked inside a runtime. Why the common case needs no external dispatch. What supplies seat diversity.

- **The external-CLI case reads as three lines.** When it helps. Which executors the resolver accepts and rejects. Where that dispatch is invoked from.
- **Every fact is the same.** No executor name, model name, alias or routing signal changed. So a request routes where it always did.
