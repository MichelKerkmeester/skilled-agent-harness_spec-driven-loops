# Skilled v2.4.0.0

This release removes a large chunk of old, unused search code.

- It also fixes 35 bugs found during a thorough code review.
- The release also adds several new capabilities to the memory system.

The most important fixes address data integrity issues.

- Leftover database records after deletions.
- Scores going out of range.
- Search filters that silently did nothing.

&nbsp;

## Why This Release

The goal is to make the workflow easier to follow and easier to trust.

## Search and Scoring

The unused V1 search pipeline is deleted. Stemming and filtering are fixed. Ranking math is repaired. Scores stay in bounds.

#### Dead Search Code Removed <a id="c-dead-search-code-removed"></a>

- The memory system had two search pipelines.
- One was the original (V1).
- The other was a newer replacement (V2).
- V1 was no longer used.
- It was still sitting in the codebase as dead code.
- That included 8 functions that were never called.

#### Stemming and Folder Filtering Fixed <a id="c-stemming-and-folder-filtering-fixed"></a>

- Stemming reduces a word to its root form for matching.
- For example, "running" should become "run".
- The stemmer was producing "runn" and "stopp" instead.
- It now handles double consonants.
- The exact-word search filter was a no-op.
- A filter by spec folder compared the wrong kind of identifier.
- So it never actually filtered anything.
- It now does a proper database lookup.

#### Fusion and Ranking Math Repaired <a id="c-fusion-and-ranking-math-repaired"></a>

- When search combined results from multiple query variations, a bonus was applied twice.
- That technique is called "fusion".
- Each result now gets the bonus once.
- The system adjusts search results based on what it thinks you are trying to do.
- Examples are "find recent work" versus "find a definition".
- The time-based component of that adjustment was missing.
- It is now added.
- You can override some scoring weights.
- The rest should then adjust proportionally, so they still sum to 1.0.
- They were not adjusting.
- Now they auto-normalize.
- Core weights are also normalized after document-type adjustments.
- The search pipeline stages share one function for resolving scores.

#### Attention Scores and Large Lists <a id="c-attention-scores-and-large-lists"></a>

- Working memory scores track what the system is currently "paying attention to".
- An unchecked boost could push them above 1.0.
- A decay factor reduces old scores over time.
- That factor was also applied twice to attention scores.
- It made them drop too fast.
- The duplicate is removed.
- A function finds the highest score in a list.
- It used a technique that fails when the list has more than 100,000 items.
- That is a JavaScript engine limit.
- A simple loop replaces it.

#### Search Options and a Tunable Threshold <a id="c-search-options-and-a-tunable-threshold"></a>

- All three search parameters existed internally before this release.
- They were hidden from the tool interface.
- A function detects "interfering" memories, ones too similar to each other.
- It now accepts a custom similarity threshold instead of a fixed value.

#### Smarter Embeddings on Update and Search <a id="c-smarter-embeddings-on-update-and-search"></a>

- Updating a memory used to generate its search embedding from the title alone.
- The embedding is also cached during search.
- The system computes a mathematical representation of your query for similarity search.
- It now reuses that computation instead of doing it twice.
- That applies when constitutional memories are involved.
- These are always-present rules.

## Data Integrity

Before this release, deleting a memory left records behind. Orphaned chunks and self-loops are caught. The deduplication hash is now 128-bit.

#### Deletion Leaves Nothing Behind <a id="c-deletion-leaves-nothing-behind"></a>

- Before this release, deleting a memory left records behind.
- These were graph snapshots, community assignments, summaries, linked entities, causal edges and search index entries.
- Bulk deletions now also clear the cache.

#### Orphaned Chunks and Self-Loops Caught <a id="c-orphaned-chunks-and-selfloops-caught"></a>

- When a parent memory was deleted, its chunks remained in the database.
- Chunks are smaller pieces stored for search.
- There was no way to find or clean them.
- The integrity checker can now optionally remove them too.
- The causal graph tracks how memories relate to each other.
- It could create an edge from a memory to itself.
- That edge is meaningless.
- Orphaned causal edges are now cleaned up as well.

#### A Stronger Deduplication Hash <a id="c-a-stronger-deduplication-hash"></a>

- Session deduplication used a 64-bit hash.
- That hash has a small but real chance of collisions.
- A collision is two different items producing the same hash.
- The hash is now 128-bit.

## Evaluation and Server Upkeep

Evaluation run IDs persist. A server restart no longer resets them.

#### Evaluation Runs Keep Their IDs <a id="c-evaluation-runs-keep-their-ids"></a>

- A counter assigns IDs to evaluation runs.
- It now reads the last-used ID from the database on startup.
- Evaluation reporting also takes a configurable search limit.
- Completed evaluation records can now be updated.
