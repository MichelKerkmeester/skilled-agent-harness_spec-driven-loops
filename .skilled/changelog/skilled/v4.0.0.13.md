# v4.0.0.13, Sessions That Hand Themselves Over

v4.0.0.13 lets a long session carry on past its context limit without you closing the terminal. When a session nears its limit it writes a handoff note, ends itself and a fresh session starts in the same terminal with the note already claimed. Claude, Pi, OpenCode, Codex and Hermes do this on their own. Cursor and Devin do it when you run `/speckit:handoff`, which Cursor names `/speckit-handoff`.

The framework also runs on OpenCode 1 and OpenCode 2 side by side, and the code standards surface for the framework's own code has a name of its own. Smaller fixes make deep-loop state safer to migrate and run more test suites where a failure blocks a merge.

> Spec folders: `specs/hooks/023-session-relaunch-loop` (Level 2), `specs/cli-external-orchestration/082-opencode-v1-v2-dual-compat` (Level 2) and `specs/sk-code/012-sk-code-skilled-rename` (Level 2)

&nbsp;

## Why This Release

A long task used to end in auto-compaction, which squeezes the conversation into a summary and loses detail, or in you saving context by hand and starting again. The in-session handover keeps the detail in a written note and keeps you out of the loop. Running on both OpenCode versions removes the choice between staying on OpenCode 1 and losing the framework's plugins on OpenCode 2.

&nbsp;

## What's New at a Glance

- **A full session restarts itself.** Near 80% of its context window a session writes a handoff note, saves continuity and ends, and a fresh session in the same terminal claims the note and continues.
- **One line in your shell turns it on.** Sourcing `.skilled/bin/skilled-loop-shell.sh` makes `claude`, `pi`, `opencode`, `codex`, `hermes`, `devin` and `cursor-agent` start under the loop when you type them.
- **It works in repositories that link `.skilled`.** A project whose `.skilled` is a symlink to this checkout starts under the loop, and hops on its own when it also links `.claude`, `.codex`, `.opencode`, `.pi` and `.hermes`.
- **`/speckit:handoff` hands over on demand.** It is the trigger on Cursor, as `/speckit-handoff`, and on Devin, and a manual option everywhere else.
- **Every hop leaves a record.** Each hand-over, claim, finish and stalled hop adds a line to a hop history you can read with one command or in `/doctor:setup`, and an opt-in macOS notice tells you when a session hands over.
- **Nothing happens outside the loop.** A session started without the wrapper never gets the handoff request, so it keeps working and auto-compaction stays the fallback.
- **OpenCode 1 and 2 both run the framework.** All sixteen plugins, the agents, the commands and the config load on either version, and `cli-opencode` dispatches to the version it finds.
- **`sk-code-opencode` is now `sk-code-skilled`.** The framework code surface no longer shares a name with the OpenCode runtime.
- **Deep-loop state survives an upgrade.** Older research and review logs keep every row when the loop rebuilds its state, and a moved review log is set aside and replayed.
- **More test suites can fail a build.** The Pi extension, sk-git and two sk-doc suites now run in CI where a failure blocks the merge.

## In-Session Handover

#### The Session Hands Over Before It Fills

A hook reads how full the context window is as the session works. At 80% it asks the session to finish if a few steps remain, and otherwise to write a handoff note with four parts: the goal, what is done, the remaining work and anything in flight. It then saves continuity for the bound spec folder and marks the note ready. A second reminder comes 5% later if the first was missed. If you have told the session not to hand off, it keeps working and auto-compaction takes over as before.

#### A Fresh Session Picks Up the Note

When the session goes idle, a small watcher ends it and `skilled-loop` starts the same runtime again in the same terminal with the model you started it on. The new session claims the note, resumes the spec folder and works only on what the note lists as remaining. It carries your spec-folder answer across, so it does not ask the documentation question again. A hop cap of ten and a ten-minute freshness limit stop a runaway chain.

#### Five Runtimes Hop on Their Own

Claude, Pi, OpenCode, Codex and Hermes each read their own usage signal and hop without you. Cursor and Devin run under the loop too, but they hop only after `/speckit:handoff`, because neither offers an event the loop can trust to end a session safely. Each of the five was proven with a live hop in a repository that links `.skilled` and the runtime folders.

#### A Stuck Hop Tells You What to Run

When the session will not go idle within 30 seconds, the watcher stands down and sends a macOS notification titled "Session relaunch needs attention (killer timed out)" with the exact command to continue by hand. The watcher only ever signals a process the loop started.

#### You Can See Every Hop Afterwards

You can check on hops without watching the terminal. Each hop writes lines to `.skilled/skills/.state/session-relaunch/hop-history.log`: `handed-over` when the loop restarts the session, `claimed` and `done` when the new session picks up and finishes the note, and `timed-out` when a stalled hop gives up. Each line names the time, runtime, hop number, folder and the note's goal. `node .skilled/hooks/session-relaunch/bin/session-relaunch.cjs history` prints the latest lines and `/doctor:setup` shows the last one. Set `SESSION_RELAUNCH_NOTIFY_HOPS=1` in `.skilled/hooks/hook-flags.env` for a macOS notice titled "Session handed over" on each hand-over. It is off unless you set it.

## OpenCode 1 and 2

#### Every Plugin Loads on Both Versions

The sixteen OpenCode plugins load on OpenCode 1.19.3 and OpenCode 2.0.32 from one source. The agents, commands and config are read the same way on both, and `/doctor` gains a battery that runs the plugins on each version.

#### Dispatch Follows the Installed Version

`cli-opencode` reads the version from `opencode --version` rather than from the binary name, prefers `opencode2` within a directory and honors `OPENCODE_BIN` when you set it. A setup helper builds the side-by-side layout without letting one version shadow the other.

&nbsp;

## Framework Code Standards

#### The Framework Surface Has Its Own Name

The sk-code surface for this framework's skills, agents, commands, hooks and scripts was called `sk-code-opencode`, which kept colliding with the OpenCode runtime in searches and routing. It is now `sk-code-skilled`, with the routing alias `code-skilled` and the surface id `SKILLED`. What it checks has not changed.

**Breaking:** anything that matched the surface id `OPENCODE` from sk-code surface detection must now match `SKILLED`, and links to `sk-code/sk-code-opencode/` must point to `sk-code/sk-code-skilled/`.

## Upgrade Notes

- **Turn on the handover.** Add `source <checkout>/.skilled/bin/skilled-loop-shell.sh` to `~/.zshrc` or `~/.bashrc` and open a new terminal. Remove any `claude` alias, because an alias wins over the shim.
- **Want a notice per hop?** Add `SESSION_RELAUNCH_NOTIFY_HOPS=1` to `.skilled/hooks/hook-flags.env`. The hop history needs no setup.
- **Link the runtime folders too.** A repository that links `.skilled` also needs `.claude`, `.codex`, `.opencode`, `.pi` and `.hermes` linked for the automatic hop, because each runtime reads its hooks from the project it starts in.
- **Hermes needs one plugin listed.** Keep `repo-guards` under `plugins.enabled` in `~/.hermes/config.yaml`. The shim sets `HERMES_ENABLE_PROJECT_PLUGINS=1` for wrapped launches only.
- **Codex asks once.** Approve the repository's hooks the first time Codex starts in a project.
- **Repoint the renamed surface.** Replace `sk-code-opencode` with `sk-code-skilled` and the surface id `OPENCODE` with `SKILLED` in your own scripts and links.
- **Pin OpenCode 1 if you need it.** With both versions installed, set `OPENCODE_BIN=opencode` to keep dispatches on OpenCode 1.
