# v4.0.0.13, Endless Sessions & OpenCode v2 Plugin Support

You can now carry a long session past its context limit without closing the terminal. Near 80% of its context window a session writes a handoff note, saves continuity and ends itself. A fresh session starts in the same terminal, claims the note and continues the work. Claude, Pi, OpenCode, Codex and Hermes hand over on their own, while Cursor and Devin hand over when you run `/speckit:handoff`, which Cursor names `/speckit-handoff`.

Every plugin, agent and command now runs on OpenCode 2, the version the framework expects, and still works on OpenCode 1 while users move over, all from one source. All 17 plugins run on both versions, sixteen through one shared adapter and sk-vision on its own. The agents, the commands and one `opencode.json` are shared too. One setup script installs both versions side by side, and `cli-opencode` runs OpenCode 2 whenever it is installed.

The rest of the release renames the framework code surface to `sk-code-skilled`, lists every setting the code reads and strengthens state and reliability.

> Spec folders: `specs/hooks/023-session-relaunch-loop` (Level 2), `specs/cli-external-orchestration/082-opencode-v1-v2-dual-compat` (Level 2), `specs/sk-code/012-sk-code-skilled-rename` (Level 2)

&nbsp;

## Why This Release

A long task used to end in auto-compaction, which squeezes the conversation into a summary and loses detail. OpenCode 2 carried a second loss: it loaded none of the framework's plugins, so moving to it meant losing the guards, the goal tracking and the advisor. Now a session near its limit writes a note that a fresh session claims. Every plugin, agent and command now runs on OpenCode 2 and still works on OpenCode 1 while users move over.

&nbsp;

## What's New at a Glance

- **A full session restarts itself in the same terminal.** Near 80% it writes a note and a fresh session picks it up.
- **One line in your shell turns it on.** Sourcing `.skilled/bin/skilled-loop-shell.sh` puts your runtimes under the loop, and a linked project works too once it links its runtime folders.
- **Sessions outside the loop and sub-agents are safe.** A session outside the loop keeps its note, and a sub-agent never hands over its parent.
- **Every hand-over leaves a record.** A history log records each one, `/doctor:setup` shows the last and names any note nobody picked up, and an optional macOS notice can announce it. The whole loop was proven live in thirteen situations.
- **The whole framework runs on OpenCode 2, with OpenCode 1 still supported.** The 17 plugins, the agents, the commands and one config run on OpenCode 2 and still work on OpenCode 1 while users move over.
- **Both versions install side by side.** One setup script installs each and an `opencode2` launcher gives version 2 its own database.
- **Dispatch prefers OpenCode 2.** `cli-opencode` runs OpenCode 2 whenever it is installed and falls back to OpenCode 1, and both default to DeepSeek V4.1 Flash 1017.
- **Tested live on both versions.** All 17 plugins showed their effect on 2.0.32 and 1.19.3, with three automated checks in CI.
- **`sk-code-opencode` is now `sk-code-skilled`.** The code check no longer shares a name with the OpenCode runtime.
- **Every setting is listed.** `.env.example` names each setting the code reads, and `/doctor:env` shows and saves them.
- **Reliability fixes across the stack.** Advisor lookups, sub-agent hand-off counts, goal records and fresh worktrees all settle down.

## In-Session Handover

A long session no longer ends at its context limit. Near the limit it writes a hand-over note, ends itself and a fresh session in the same terminal carries on.

#### Your Session Restarts at 80 Percent

A hook reads how full the context window is. At 80% it asks the session to finish if a few steps remain. Otherwise it asks for a hand-over note with the goal, what is done, the remaining work and anything in flight. The session saves continuity (its record of the work) and marks the note ready. A second reminder comes 5% later if the first was missed. If you told the session not to hand over, it keeps working and auto-compaction (the automatic summary) takes over.

#### A Fresh Session Picks Up the Work

When the session goes idle, a small watcher ends it. `skilled-loop` then restarts the same runtime in the same terminal with the model you started it on. The new session picks up the note, resumes the spec folder and works only on what remains. It keeps your spec-folder answer, so it does not ask the documentation question again. A limit of ten hand-overs and a ten-minute freshness window stop a chain that runs away.

#### Five Runtimes Hand Over on Their Own

Claude, Pi, OpenCode, Codex and Hermes each read their own usage signal and hand over without you. Cursor and Devin run under the loop too. They hand over only after `/speckit:handoff`, which Cursor names `/speckit-handoff`, because neither offers a safe end-of-session event.

#### Nothing Outside the Loop Is Lost

A session started before you added the shell line runs outside the loop and cannot hand over. At 80% the hook asks it to write the same note and run `session-relaunch.cjs keep`, then it carries on. On Claude Code, Pi and OpenCode, a hook after each automatic summary points it back at its note, so it picks the note up and continues. Codex and Hermes print the command to pick up the note when you keep it, and the session follows that command after the summary.

A sub-agent never hands over the session that started it. Claude Code refuses any hand-over command from a fork or an agent, and OpenCode `task` sub-agents get no reminder. A `claude -p` or `pi -p` started inside a looped session runs outside the loop and cannot restart the session that started it.

#### A Stuck Restart Leaves a Trail

When a session will not go idle within 30 seconds, the watcher stops and sends a macOS notification titled "Session relaunch needs attention (killer timed out)" with the exact command to continue by hand. The watcher only ever signals a process the loop started. The note stays open, and the command to pick it up prints when the session exits. On Pi and OpenCode, a turn you start just after the session was readied cancels the hand-over at once, so your new message is never cut off.

Each hand-over, kept note, pick-up, finish and stalled restart adds a line to `.skilled/skills/.state/session-relaunch/hop-history.log`. `node .skilled/hooks/session-relaunch/bin/session-relaunch.cjs history` prints the latest lines, and `/doctor:setup` shows the last line and names any note nobody picked up. Set `SESSION_RELAUNCH_NOTIFY_HOPS=1` in `.skilled/hooks/hook-flags.env` for a macOS notice titled "Session handed over" on each hand-over. It is off unless you set it.

#### Proven Live in Thirteen Situations

Thirteen situations ran live on each of Claude, Pi and OpenCode, among them two sessions at once, an interrupted hand-over and a busy hand-over. The runs found four faults, now fixed. Two OpenCode sessions started in the same second could write over each other's note. A message sent at hand-over could be cut off on Pi and OpenCode. The shell line's commands failed inside Claude Code's tool shell. A hand-over interrupted before the new session picks up its note now prints a warning with the command to continue.

## OpenCode 2, With OpenCode 1 Still Supported

The 17 plugins, the agents, the commands and one config run on OpenCode 2, the version the framework expects, and still work on OpenCode 1 while users move over, all from one source. The two versions install side by side.

#### All 17 Plugins Run on Both

All 17 plugins run on both versions from one source file each. Sixteen share one adapter that lets them work on OpenCode 2, and sk-vision exports both plugin shapes itself. The shared adapter reports version 2's `shell` tool as `bash` and its `subagent` tool as `task`. Before that adapter, seven plugins loaded on OpenCode 2 and did nothing. sk-vision now runs there too. With automatic inspection on, an image you attach gets its vision evidence through version 2's prompt hook, and its 13 tools register on version 2.

#### Agents and Commands Stay Shared

You keep one set of agents, one set of commands and a single `opencode.json` for both versions. The file keeps the version 1 shape, and OpenCode 2 converts it when it loads. Both versions treat every `.md` file under a `commands/` folder as a command. The 12 files in `.skilled/commands/` that are not commands now use `.markdown`, so your command list is unchanged at 42 on OpenCode 2, its two built-ins included, and 40 on OpenCode 1. Agent `temperature` has no effect on OpenCode 2.0.32 with the `openai-compatible` package, the only package tested.

#### Both Versions Install Side by Side

The setup script at `.skilled/skills/cli-external-orchestration/cli-opencode/scripts/opencode-setup.sh` has four modes: `both`, `v1`, `v2` and `check`. Every step prints its rollback line, so you can reverse each move. `both` installs v2 into `~/.local/opencode-v2` and v1 into `~/.local`, then writes an `opencode2` launcher that sets `OPENCODE_DB`. Without that launcher OpenCode 2 is documented to open v1's `opencode.db` and migrate it in place. Homebrew's formula is v2-only and cannot sit beside a v1 install. `opencode upgrade --major` removes v1, so use the setup script when you want both. Both versions share one `~/.config/opencode` folder, so a key you write for one version is live on the other.

#### Dispatch and Guards Know the Version

The dispatch and the guards both know which version you run, so the right binary and the right rules apply. `cli-opencode` asks the binary it picked for its version with `--version`. With no preference set, it takes the first `opencode2` anywhere on your `PATH` and uses `opencode` only when no `opencode2` is installed. The deep-loop fan-out runtime picks the same way. Set `OPENCODE_BIN` to choose the binary yourself. On OpenCode 2 the dispatch builds `run --standalone` and attaches the variant to the model id as `provider/model#variant`. The dispatch guards recognize `opencode2` and apply each rule to the version that rule was written for. On OpenCode 2 a slash-command route the guards cannot check yet warns you instead of blocking. On Pi, a request authorizes a CLI executor only when you name it in plain text. A name inside a quote, a backtick, a command substitution or a negated sentence no longer counts.

#### One Default Model on Both Versions

When you do not pin a model, dispatch behaves the same on either version. It uses `llmgateway/deepseek-v4.1-flash-1017`, LLM Gateway's 2026-10-17 release of DeepSeek V4.1 Flash, at its `max` variant, with `#max` on OpenCode 2 and `--variant max` on OpenCode 1, and `opencode.json` sets it for both versions. The same model is now the default for Pi, Hermes and the deep-loop fan-out runtime, and it runs Pi's blackhole memory workers at `high`. The older `deepseek-v4.1-flash` stays selectable when you pin it, though LLM Gateway lists DeepSeek's own route for it as closing on October 24, 2026. Before, the default depended on the version. `opencode-go` remains a provider you can select on OpenCode 1.

#### Tested Live on Both Versions

All 17 plugins ran live on OpenCode 2.0.32 and 1.19.3, and each showed its expected effect on both. The run happened twice, once when the work was finished and again on the final files after later fixes. Three automated checks run in CI on every pull request and push that touches their files. The OpenCode Dual-Version Battery installs each version and checks that every plugin loads and is active. It also checks that the repository's skills are visible and fails when a command file is missing or a version lists a non-command file as a command. The other two are OpenCode Plugin Tests and Hook Node Tests. The review covered 323 files in the plugin folder and the hook tree against the framework's own code standards. All 5 critical and 47 high-severity findings were fixed. Separate read-only model sessions reviewed the changes before they shipped.

## Code Standards

#### The Framework Surface Has Its Own Name

The framework's sk-code surface was `sk-code-opencode`, a name that kept colliding with the OpenCode runtime. It is now `sk-code-skilled`, with routing alias `code-skilled` and surface id `SKILLED`. What it checks has not changed.

**Breaking:** anything that matched the surface id `OPENCODE` must now match `SKILLED`, and links to `sk-code/sk-code-opencode/` must point to `sk-code/sk-code-skilled/`.

&nbsp;

## Environment Settings

#### Every Setting Is Listed and Shown

`.env.example` now names about 120 settings it was missing, the whole session-relaunch set among them, each with its default and a line on what it does. Two new sections cover session relaunch and the doctor, tooling and test-runner settings. `/doctor:env` now adds every setting `ENV-REFERENCE.md` misses and saves any switch whose reader takes it from `hook-flags.env`, such as the hand-over notice. It keeps the Code Mode provider keys hidden. The README's Environment Settings section says where each belongs: a shell export, `hook-flags.env`, Claude Code's `settings.local.json` or `.env`.

## Reliability Fixes

#### Advisor Lookups Queue Instead of Piling Up

Two different prompts arriving at the same moment each started their own advisor process, and a lookup that had to wait had no deadline. At most two now run at once and the rest queue in order. A queued lookup gives up after the normal advisor timeout, then skips the advisor rather than running late. A repeat lookup reuses a file's content hash while that file is unchanged. On Pi the advisor no longer prints a JSON diagnostic over the input line, though the record still goes to disk.

#### Sub-Agent Hand-Off Counts Stop Racing

Two hooks updating a session's sub-agent hand-off count at the same moment no longer write the same number, because the update takes a lock that records who holds it. When the lock is busy, the count is left alone and reported as not saved. A lock is broken only when its owner is dead or its stale record has outlived the window. An iteration config file is accepted only from inside the project, so a file or symlink outside it can no longer unlock the exemption.

#### A Corrupt Goal Record Reads Empty

A damaged current goal record used to bring back an older stale goal, and now it reads as no goal. An archive file holding something other than a goal record, such as a bare null, used to hide every archived goal and is now skipped. A packet `goal.md` symlinked to a file outside the workspace is no longer read as the session goal.

#### Saved State and Test Suites Hold Up

Older research and review logs keep every row when the loop rebuilds its state, so a rebuild no longer throws away what earlier runs recorded. The two Pi extension suites, the sk-git suite and two sk-doc suites now run in CI, so a break in any of them shows up on the pull request that causes it.

#### Fresh Worktrees Build What They Need

A fresh worktree could not run the two Pi extension suites or the DESIGN.md backend suite, because the installer skipped the packages they need. It now installs them and says why a run failed. The check for a stale build now looks at the files on disk, so an edit not yet staged in git or a deleted input triggers a rebuild, and a build that writes nothing new no longer rebuilds every time. Pointing the installer at a subfolder now installs what the whole worktree needs.

#### Smaller Fixes Across the Stack

The git pre-commit installer now works in a linked worktree and with a custom `core.hooksPath` setting, because it installs where git looks for hooks. The shared reader for input from another program now stops at 64 MiB. On OpenCode the session-cleanup guards could freeze the event stream for about 32 seconds, and they now run in parallel. Pi's `--fast` flag now registers in the main checkout, and sk-vision on OpenCode 2 releases everything it holds at shutdown.

## Upgrade Notes

- **Turn on the hand-over.** Add `source <checkout>/.skilled/bin/skilled-loop-shell.sh` to `~/.zshrc` or `~/.bashrc`, open a new terminal and remove any `claude` alias, because an alias wins over the wrapper.
- **Link every runtime folder.** Link `.claude`, `.codex`, `.opencode`, `.pi` and `.hermes` beside a linked `.skilled`.
- **Keep `repo-guards` listed for Hermes.** Leave it under `plugins.enabled` in `~/.hermes/config.yaml`.
- **Approve Codex hooks once.** Say yes the first time Codex starts in a project.
- **Ask for a hand-over notice.** Add `SESSION_RELAUNCH_NOTIFY_HOPS=1` to `.skilled/hooks/hook-flags.env`.
- **Move to OpenCode 2.** It is the version the framework expects. OpenCode 1 still works as a fallback while you move over.
- **Expect OpenCode 2 when both are installed.** Dispatch now runs the first `opencode2` on your `PATH` even when an `opencode` comes earlier, so a run that used OpenCode 1 before may now use OpenCode 2.
- **Install both versions in one step.** Run `.skilled/skills/cli-external-orchestration/cli-opencode/scripts/opencode-setup.sh both`, or `check` to see your current layout without changing it.
- **Never run `opencode upgrade --major` beside v1.** Use the setup script instead.
- **Fall back to OpenCode 1 if you need it.** With both versions installed, set `OPENCODE_BIN=opencode`.
- **Set up `llmgateway` on each version or pass `--model`.** An unpinned dispatch now uses `llmgateway/deepseek-v4.1-flash-1017` on both versions.
- **Pin the older DeepSeek model if you need it.** Pin `llmgateway/deepseek-v4.1-flash` to keep the 2026-09-10 release.
- **Repoint the renamed surface.** Replace `sk-code-opencode` with `sk-code-skilled` and the surface id `OPENCODE` with `SKILLED` in your own scripts and links.
- **Repoint links to command-support.** Point `.skilled/command-support/` links at the same path under `.skilled/commands/`, with `.markdown` in place of `.md`.
- **See every setting.** Run `/doctor:env list` and read the README's Environment Settings section before copying a line from `.env.example`.
- **Pass a workspace to goal session actions.** Add `--workspace <repo root>` to every `goal.cjs` session call.
