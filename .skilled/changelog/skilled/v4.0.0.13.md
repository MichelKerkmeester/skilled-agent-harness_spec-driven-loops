# v4.0.0.13, Endless Sessions & OpenCode v2 Plugin Support

A long session now carries past its context limit in the same terminal.

- Near 80% it writes a hand-off note, saves continuity and ends itself.
- A fresh session starts in the same terminal, claims the note and continues.
- Claude, Pi, OpenCode, Codex and Hermes hand over on their own.
- Cursor and Devin hand over only on request.

The whole framework now runs on OpenCode 2, with OpenCode 1 still supported.

- All 17 plugins, the agents and the commands run on both versions.
- All of it comes from one source, with effects shown on 2.0.32 and 1.19.3.
- One setup script installs both versions side by side.
- `cli-opencode` prefers OpenCode 2 whenever it is installed.

The rest renames the code surface, lists settings and strengthens reliability.

- The code surface is now `sk-code-skilled`.
- `.env.example` names every setting the code reads.
- State and reliability get fixes across the stack.

> [!IMPORTANT]
> 1 change can break an existing setup. Read it before you update.
>
> 1. Match the id `SKILLED` and repoint links to `sk-code/sk-code-skilled/`. [The Framework Surface Has Its Own Name](#c-the-framework-surface-has-its-own-name)

&nbsp;

## Why This Release

Long tasks and OpenCode 2 both lost work.

- A long task used to end in auto-compaction. That squeezes the conversation into a summary and loses detail.
- OpenCode 2 loaded none of the framework's plugins.
- So moving to it meant losing the guards, the goal tracking and the advisor.
- Now a session near its limit writes a note. A fresh session claims that note.
- Every plugin, agent and command now runs on OpenCode 2. Each still works on OpenCode 1 while users move over.

## In-Session Handover

A long session no longer ends at its context limit. Near the limit it writes a hand-over note, ends itself and a fresh session in the same terminal carries on.

#### Your Session Restarts at 80 Percent <a id="c-your-session-restarts-at-80-percent"></a>

- A hook reads how full the context window is.
- At 80% it asks the session to finish if a few steps remain.
- Otherwise it asks for a hand-over note.
- The note holds the goal, what is done, the remaining work and anything in flight.
- The session saves continuity (its record of the work).
- It marks the note ready.
- A second reminder comes 5% later if the first was missed.
- If you told the session not to hand over, it keeps working.
- Then auto-compaction (the automatic summary) takes over.

#### A Fresh Session Picks Up the Work <a id="c-a-fresh-session-picks-up-the-work"></a>

- When the session goes idle, a small watcher ends it.
- `skilled-loop` restarts the same runtime in the same terminal.
- It uses the model you started it on.
- The new session picks up the note and resumes the spec folder.
- It works only on what remains.
- It keeps your spec-folder answer, so it does not ask the documentation question again.
- A limit of ten hand-overs stops a chain that runs away.
- So does a ten-minute freshness window.
- Sourcing `.skilled/bin/skilled-loop-shell.sh` puts your runtimes under the loop.
- A linked project works too, once it links its runtime folders.

#### Five Runtimes Hand Over on Their Own <a id="c-five-runtimes-hand-over-on-their-own"></a>

- Claude, Pi, OpenCode, Codex and Hermes each read their own usage signal.
- They hand over without you.
- Cursor and Devin run under the loop too.
- They hand over only on request.
- That is because neither offers a safe end-of-session event.
- In Cursor you run `/speckit-handoff`.
- Devin has no command surface.
- So you ask the session to follow the `/speckit:handoff` command file.
- It reads that file directly.

#### Nothing Outside the Loop Is Lost <a id="c-nothing-outside-the-loop-is-lost"></a>

- A session started before you added the shell line runs outside the loop.
- It cannot hand over.
- At 80% the hook asks it to write the same note.
- It also asks it to run `session-relaunch.cjs keep`.
- Then it carries on.
- On Claude Code, Pi and OpenCode, a hook runs after each automatic summary.
- It points the session back at its note.
- So the session picks the note up and continues.
- Codex and Hermes print the command to pick up the note when you keep it.
- The session follows that command after the summary.
- A sub-agent never hands over the session that started it.
- Claude Code refuses any hand-over command from a fork or an agent.
- OpenCode `task` sub-agents get no reminder.
- A `claude -p` or `pi -p` started inside a looped session runs outside the loop.
- It cannot restart the session that started it.

#### A Stuck Restart Leaves a Trail <a id="c-a-stuck-restart-leaves-a-trail"></a>

- When a session will not go idle within 30 seconds, the watcher stops.
- It sends a macOS notification titled "Session relaunch needs attention (killer timed out)".
- The notice carries the exact command to continue by hand.
- The watcher only ever signals a process the loop started.
- The note stays open.
- The command to pick it up prints when the session exits.
- On Pi and OpenCode, a turn you start just after the session was readied cancels the hand-over at once.
- So your new message is never cut off.
- Each hand-over, kept note, pick-up, finish and stalled restart adds a line to `.skilled/skills/.state/session-relaunch/hop-history.log`.
- `node .skilled/hooks/session-relaunch/bin/session-relaunch.cjs history` prints the latest lines.
- `/doctor:setup` shows the last line and names any note nobody picked up.
- Set `SESSION_RELAUNCH_NOTIFY_HOPS=1` in `.skilled/hooks/hook-flags.env`.
- That gives a macOS notice titled "Session handed over" on each hand-over.
- It is off unless you set it.

#### Proven Live in Thirteen Situations <a id="c-proven-live-in-thirteen-situations"></a>

- The whole loop was proven live in thirteen situations.
- Thirteen situations ran live on each of Claude, Pi and OpenCode.
- They included two sessions at once, an interrupted hand-over and a busy hand-over.
- The runs found four faults, now fixed.
- Two OpenCode sessions started in the same second could write over each other's note.
- A message sent at hand-over could be cut off on Pi and OpenCode.
- The shell line's commands failed inside Claude Code's tool shell.
- A hand-over interrupted before the new session picks up its note now prints a warning.
- The warning carries the command to continue.

## OpenCode 2, With OpenCode 1 Still Supported

The 17 plugins, the agents, the commands and one config now run on OpenCode 2. That is the version the framework expects. Each still works on OpenCode 1 while users move over. All of it comes from one source, and the two versions install side by side.

#### All 17 Plugins Run on Both <a id="c-all-17-plugins-run-on-both"></a>

- All 17 plugins run on both versions, from one source file each.
- Sixteen share one adapter that lets them work on OpenCode 2.
- sk-vision exports both plugin shapes itself.
- The shared adapter reports version 2's `shell` tool as `bash`.
- It reports its `subagent` tool as `task`.
- Before that adapter, seven plugins loaded on OpenCode 2 and did nothing.
- sk-vision now runs there too.
- With automatic inspection on, an image you attach gets its vision evidence.
- That comes through version 2's prompt hook.
- sk-vision's 13 tools register on version 2.

#### Agents and Commands Stay Shared <a id="c-agents-and-commands-stay-shared"></a>

- You keep one set of agents and one set of commands.
- You also keep a single `opencode.json` for both versions.
- The file keeps the version 1 shape.
- OpenCode 2 converts it when it loads.
- Both versions treat every `.md` file under a `commands/` folder as a command.
- The 12 files in `.skilled/commands/` that are not commands now use `.markdown`.
- So your command list is unchanged at 42 on OpenCode 2, its two built-ins included.
- It is 40 on OpenCode 1.
- Agent `temperature` has no effect on OpenCode 2.0.32 with the `openai-compatible` package.
- That is the only package tested.

#### Both Versions Install Side by Side <a id="c-both-versions-install-side-by-side"></a>

- The setup script at `.skilled/skills/cli-external-orchestration/cli-opencode/scripts/opencode-setup.sh` has four modes.
- They are `both`, `v1`, `v2` and `check`.
- Every step prints its rollback line.
- So you can reverse each move.
- `both` installs v2 into `~/.local/opencode-v2` and v1 into `~/.local`.
- It then writes an `opencode2` launcher that sets `OPENCODE_DB`.
- Without that launcher, OpenCode 2 is documented to open v1's `opencode.db`.
- It migrates that file in place.
- Homebrew's formula is v2-only and cannot sit beside a v1 install.
- `opencode upgrade --major` removes v1.
- So use the setup script when you want both.
- Both versions share one `~/.config/opencode` folder.
- So a key you write for one version is live on the other.

#### Dispatch and Guards Know the Version <a id="c-dispatch-and-guards-know-the-version"></a>

- The dispatch and the guards both know which version you run.
- So the right binary and the right rules apply.
- `cli-opencode` asks the binary it picked for its version with `--version`.
- With no preference set, it takes the first `opencode2` anywhere on your `PATH`.
- It uses `opencode` only when no `opencode2` is installed.
- The deep-loop fan-out runtime picks the same way.
- Set `OPENCODE_BIN` to choose the binary yourself.
- On OpenCode 2 the dispatch builds `run --standalone`.
- It attaches the variant to the model id as `provider/model#variant`.
- The dispatch guards recognize `opencode2`.
- They apply each rule to the version that rule was written for.
- On OpenCode 2, a slash-command route the guards cannot check yet warns you.
- It does not block you.
- On Pi, a request authorizes a CLI executor only when you name it in plain text.
- A name inside a quote, a backtick, a command substitution or a negated sentence no longer counts.

#### One Default Model on Both Versions <a id="c-one-default-model-on-both-versions"></a>

- When you do not pin a model, dispatch behaves the same on either version.
- It uses `llmgateway/deepseek-v4.1-flash-1017`, LLM Gateway's 2026-10-17 release of DeepSeek V4.1 Flash.
- It uses the `max` variant, with `#max` on OpenCode 2 and `--variant max` on OpenCode 1.
- `opencode.json` sets it for both versions.
- The same model is now the default for Pi, Hermes and the deep-loop fan-out runtime.
- It runs Pi's blackhole memory workers at `high`.
- The older `deepseek-v4.1-flash` stays selectable on OpenCode and Hermes when you pin it.
- LLM Gateway lists DeepSeek's own route for it as closing on October 24, 2026.
- Pi no longer carries it.
- Before, the default depended on the version.
- `opencode-go` remains a provider you can select on OpenCode 1.

#### Tested Live on Both Versions <a id="c-tested-live-on-both-versions"></a>

- All 17 plugins ran live on OpenCode 2.0.32 and 1.19.3.
- Each showed its expected effect on both.
- The run happened twice.
- It ran once when the work was finished.
- It ran again on the final files after later fixes.
- The review covered 323 files in the plugin folder and the hook tree.
- It checked them against the framework's own code standards.
- All 5 critical and 47 high-severity findings were fixed.
- Separate read-only model sessions reviewed the changes before they shipped.

## Reliability Fixes

Advisor lookups, sub-agent counts, goal records, saved state and worktrees all settle down.

#### Advisor Lookups Queue Instead of Piling Up <a id="c-advisor-lookups-queue-instead-of-piling-up"></a>

- Two different prompts arriving at the same moment each started their own advisor process.
- A lookup that had to wait had no deadline.
- At most two now run at once.
- The rest queue in order.
- A queued lookup gives up after the normal advisor timeout.
- Then it skips the advisor rather than running late.
- A repeat lookup reuses a file's content hash while that file is unchanged.
- On Pi the advisor no longer prints a JSON diagnostic over the input line.
- The record still goes to disk.

#### Sub-Agent Hand-Off Counts Stop Racing <a id="c-sub-agent-hand-off-counts-stop-racing"></a>

- Two hooks can update a session's sub-agent hand-off count at the same moment.
- They no longer write the same number.
- That is because the update takes a lock that records who holds it.
- When the lock is busy, the count is left alone.
- It is reported as not saved.
- A lock is broken in two cases.
- Its owner is dead, or its stale record has outlived the window.
- An iteration config file is accepted only from inside the project.
- So a file or symlink outside it can no longer unlock the exemption.

#### A Corrupt Goal Record Reads Empty <a id="c-a-corrupt-goal-record-reads-empty"></a>

- A damaged current goal record used to bring back an older stale goal.
- Now it reads as no goal.
- An archive file holding something other than a goal record used to hide every archived goal.
- A bare null is one example.
- That file is now skipped.
- A packet `goal.md` symlinked to a file outside the workspace is no longer read as the session goal.

#### Saved State and Test Suites Hold Up <a id="c-saved-state-and-test-suites-hold-up"></a>

- Older research and review logs keep every row when the loop rebuilds its state.
- So a rebuild no longer throws away what earlier runs recorded.
- The two Pi extension suites, the sk-git suite and two sk-doc suites now run in CI.
- So a break in any of them shows up on the pull request that causes it.

#### Fresh Worktrees Build What They Need <a id="c-fresh-worktrees-build-what-they-need"></a>

- A fresh worktree could not run the two Pi extension suites or the DESIGN.md backend suite.
- That is because the installer skipped the packages they need.
- It now installs them.
- It says why a run failed.
- The check for a stale build now looks at the files on disk.
- So an edit not yet staged in git triggers a rebuild.
- A deleted input does too.
- A build that writes nothing new no longer rebuilds every time.
- Pointing the installer at a subfolder now installs what the whole worktree needs.

#### Smaller Fixes Across the Stack <a id="c-smaller-fixes-across-the-stack"></a>

- The git pre-commit installer now works in a linked worktree.
- It also works with a custom `core.hooksPath` setting.
- That is because it installs where git looks for hooks.
- The shared reader for input from another program now stops at 64 MiB.
- On OpenCode the session-cleanup guards could freeze the event stream for about 32 seconds.
- They now run in parallel.
- Pi's `--fast` flag now registers in the main checkout.
- sk-vision on OpenCode 2 releases everything it holds at shutdown.

## Upgrade Notes

These steps apply to everyone. The rest depends on which parts you use.

#### Before You Start <a id="c-before-you-start"></a>

1. Add `source <checkout>/.skilled/bin/skilled-loop-shell.sh` to `~/.zshrc` or `~/.bashrc`.
2. Open a new terminal.
3. Remove any `claude` alias, because an alias wins over the wrapper.
4. Link `.claude`, `.codex`, `.opencode`, `.pi` and `.hermes` beside a linked `.skilled`.

<details>
<summary><b>In-Session Handover</b></summary>

- Keep `repo-guards` listed for Hermes. Leave it under `plugins.enabled` in `~/.hermes/config.yaml`.
- Approve Codex hooks once. Say yes the first time Codex starts in a project.
- Ask for a hand-over notice. Add `SESSION_RELAUNCH_NOTIFY_HOPS=1` to `.skilled/hooks/hook-flags.env`.

</details>

<details>
<summary><b>OpenCode 2, With OpenCode 1 Still Supported</b></summary>

- Move to OpenCode 2.
- It is the version the framework expects.
- OpenCode 1 still works as a fallback while you move over.
- Expect OpenCode 2 when both are installed. Dispatch now runs the first `opencode2` on your `PATH`, even when an `opencode` comes earlier.
- So a run that used OpenCode 1 before may now use OpenCode 2.
- Install both versions in one step. Run `.skilled/skills/cli-external-orchestration/cli-opencode/scripts/opencode-setup.sh both`, or `check` to see your current layout without changing it.
- Never run `opencode upgrade --major` beside v1. Use the setup script instead.
- Fall back to OpenCode 1 if you need it. With both versions installed, set `OPENCODE_BIN=opencode`.
- Set up `llmgateway` on each version or pass `--model`. An unpinned dispatch now uses `llmgateway/deepseek-v4.1-flash-1017` on both versions.
- Pin the older DeepSeek model on OpenCode or Hermes if you need it.
- On OpenCode pass `--model llmgateway/deepseek-v4.1-flash`.
- On Hermes pass `--provider llmgateway --model deepseek-v4.1-flash`.
- That keeps the 2026-09-10 release.
- Pi no longer carries it.
- Repoint links to command-support. Point `.skilled/command-support/` links at the same path under `.skilled/commands/`, with `.markdown` in place of `.md`.
