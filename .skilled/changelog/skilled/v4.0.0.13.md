# v4.0.0.13, The Doctor Checks Say Only What They Can Prove

v4.0.0.13 fixes `/doctor:git setup`, `/doctor:setup` and the advisor's doctor routing where they reported more than they could prove. A healthy install no longer fails outside Claude Code, and a check that could not run no longer passes.

> Spec folders: `specs/sk-git/033-git-setup-customization/007-review-remediation` (Level 1), `specs/system-skill-advisor/035-doctor-command-routing` (Level 2) and `specs/sk-git/033-git-setup-customization/008-out-of-scope-cleanup` (Level 1)

&nbsp;

## What's New at a Glance

- **`/doctor:setup` works in every runtime.** Its sk-git check names the AI tool it runs in, so Codex, Pi, OpenCode, Cursor, Devin and Hermes no longer report a healthy install as FAIL. A DEGRADED sk-git result shows as DEGRADED, not as a failure.
- **The git setup check stops guessing.** A check it could not run shows UNKNOWN, a hook that cannot execute fails and an AI tool adapter counts only when it binds a real handler.
- **The doctor hint fires only when it fits.** "Check" needs a tooling word after it, and a `/doctor:` command quoted inside a prompt no longer pushes a matching skill out of first place.
- **Every command puts its input gate in one place.** sk-create-command states one position, after the title and purpose line, and all nine commands with an input gate follow it.
- **The drift guards pass on a tree with review evidence.** Frozen copies of old files kept as review evidence are skipped, as they already were for the language check.

&nbsp;

## Upgrade

No migration required. Rebuild the advisor runtime (`npm --prefix .skilled/skills/system-skill-advisor/runtime run build`), then rerun `/doctor:setup` from the runtime you use.
