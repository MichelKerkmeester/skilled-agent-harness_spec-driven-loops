# v4.0.0.4, Spec Repairs Write Only What Evidence Proves

v4.0.0.4 stops a run of small fixes to one file from turning into a run of separate top-level packets. Agents now keep a checked answer when you push back with no new fact, and Devin reads the current rules of the checkout it works in. The communication rules state each norm once, and the bundled runtimes pick up security fixes. Two unused deep-loop modes are retired, so the deep loop now runs research, review and AI Council. Every commit in a repository that uses sk-git now carries a Commit-Id, and Pi starts its GPT targets in Fast Mode.

The spec-folder tools change most in this release. Repairs now write only what their evidence proves. An apply on uncommitted files keeps the originals so it can be undone, on a large tree too. The doctor also shows a v3 layout before anything moves. Nested anchors and extra closers now fail validation, and new packets come out of the scaffolder passing their own checks.

The code skill and its guards change as well. A code review now ends on its status line, with a Not checked line above it, and each finding has to show the case that produces it. Hooks stop waiting for input after a deadline, and the commit hook checks a staged skill's generated files. The skill advisor stops routing on a skill name that only sits inside a file path. A template comment that no tool read left every feature catalog, and three drift-guard scripts moved to kebab-case names. Scripts now refuse unknown options, and the README install steps reach a working request on a fresh clone. You can also adapt the code skill to your own stack now. OpenCode is the native surface, Webflow and Obsidian are optional examples, and `/doctor:sk-code setup` names the fix for each failing check.

&nbsp;

## Why This Release

Spec-folder repairs used to guess. A template header could be stamped on a document that did not match its level, a fill could write a trigger phrase the checker later rejected and an apply could not be undone. Nested anchors also passed validation, the pull request gate could not tell a new failure from an old one and Commit-Id stamping stopped without a word in an untrusted clone.

Two deep-loop modes had no remaining use, yet their commands, agent and runtime code still loaded and drew advisor routing. On the code side, a review could end without saying what it skipped, and a hook whose input never closed could hold a tool call open. Many scripts also ignored a misspelled option and ran on with their defaults, and a fresh clone could not reach its first request from the README steps alone.

Adapting the code skill was not a supported path either. The README told you to replace all three code surfaces, the native one included. Deleting an example left over a hundred doctor failures, and a surface you added lost every keyword tie to OpenCode.

## What's New at a Glance

- **Upgrades prove each change, can be undone and show the layout first.** A repair that the packet's own evidence cannot support is refused, and an apply on uncommitted files saves their original contents first, on a large tree too. `/doctor:update check` reports the layout and the pre-v4 signals, and the compat action asks for approval before any move.
- **The bundled runtimes are patched and ClickUp works again.** Six lockfiles carry fixes for a critical advisory in proxy-addr and high ones in the MCP SDK, sharp, source-map-js and nanoid. The ClickUp manual now starts ClickUp's hosted server and asks for one OAuth approval in the browser.
- **Checks catch problems before they merge.** `ANCHORS_VALID` treats nested anchors and extra closers as errors, the pre-commit check blocks template-default trigger phrases and the pull request gate blocks only on failures that are new to the branch. Every commit in a repository that uses sk-git now carries a Commit-Id, an untrusted clone included.
- **The deep loop runs three modes.** The agent-improvement and model-benchmark modes are gone with their commands, agent and runtime code, so `system-deep-loop` routes research, review and AI Council only.
- **sk-code adapts to your own stack.** OpenCode is the native surface and stays, while Webflow and Obsidian are optional examples you can remove, and a surface you add lands ahead of OpenCode. `/doctor:sk-code setup` runs eight read-only checks and prints the command that clears each failure.
- **Code reviews say what they skipped.** A review ends on its status line with one Not checked line above it, and every finding shows the case that produces it. The code agents report what they left unchecked too, and drift-guard warnings show up instead of hiding behind a bare PASS.
- **A fresh clone works, and scripts refuse unknown options.** The README install steps build what the session hooks load, name Node 24 and end in a routed request. A misspelled option used to be ignored while the run went on, and scripts across the skills now stop with a usage error.
- **New work joins the packets it belongs to.** A second fix to a file, script or command that a packet in the same track already changed becomes a child of one series parent, which Gate 3 option C names. `create.sh` lists the packets made in the same track in the last 14 days, writes trigger phrases from the packet's name and refuses an option it does not know.
- **Agents keep checked answers, and Devin reads the current rules.** A settled conclusion reopens only for a reason you can name, such as a failing check or a contradicting fact, and agents answer first instead of restating the request. Devin no longer loads the main checkout's `AGENTS.md` through `~/.claude/CLAUDE.md`, so a worktree session follows its own checkout's rules.
- **Routing ignores skill names inside paths.** A skill named only in a file path or doc target no longer pulls the route, a request to write a test or helper reaches the code skill, the current code surface can break a tie and routing drift fails CI. So does a prompt the Python and Node advisors route differently without an approved reason.
- **Hooks never hang a tool call.** A hook stops waiting for input after a deadline, and the Pi guard reads dispatches wrapped in a shell `-c` payload without blocking a harmless `mkdir -p "$DIR"`.
- **Skill authoring checks catch real problems.** The template comment that no tool read is gone from every feature catalog, changelog entries need a `version:` key and `/create:changelog` numbers against upstream so two branches cannot pick the same version. Every skill doc carries its own version, and the commit hook raises it when the doc changes.

## Spec Upgrades

#### Upgrades Change Only What Evidence Proves

`heal-spec-docs --lane-modes` runs five repairs: anchor wrapping, link repointing, continuity placeholders, filling the level from `spec.md` and header stamping. Each repair reads the text the one before it left, and each one refuses when the packet cannot prove the fix. The command is a dry run by default, and `--apply` writes. `upgrade-legacy --apply` runs the same repairs after its healer and records every refusal in the packet's `upgrade-baseline.json` under `refusals`.

A template header is stamped only when a document's anchors match its level's template exactly, with nothing extra and nothing missing.

#### Fills Come From Each Document's Template

When a fill needs a missing `importance_tier` or `contextType`, it takes the value from the template for that document's class. A value the document already carries is never rewritten. The runtime tables are reached only when no template can be read.

#### Frontmatter Fill Ignores the Frontmatter Block

When a document has frontmatter but no `description`, the fill now takes the description from the body, after every leading frontmatter block. It used to take the block's first line, so a document could end up with `description: 'title: "..."'`.

#### Upgrades Write Only Admitted Phrases

The upgrade no longer writes a trigger phrase that the phrase checker grades as a negative class. When `trigger_phrases` is present but empty in `plan.md`, `tasks.md` or `implementation-summary.md`, the upgrade refills it with phrases derived from the packet folder name, and an inferred phrase is kept only when the checker admits it.

#### Phrase Cleanup Trims Only Generated Phrases

The phrase cleanup trims a trigger phrase only when it is the verbatim eight-word cut of one of the packet's own recorded descriptions. An authored phrase with the same shape keeps all its words.

#### Failures Print Grouped by Rule

`upgrade-legacy` prints each packet's failures under one heading per rule, with the number of details under it, on every dry run and every apply. A packet whose report cannot be read gets its own heading.

## Undoing and Previewing Upgrades

#### Upgrades Can Be Undone

`upgrade-legacy --apply` refuses to run in a repository without git. On a tree with uncommitted changes, it first writes a manifest of before-images for the dirty files inside the failing packets, into the git directory, before it changes anything. A manifest from an earlier run is trusted only while the commit and the packet contents still match it, so a stale manifest stops the apply instead of being overwritten. The dry run lists each finding a baseline will downgrade. Once an apply has passed every packet, a second apply on the same tree prints `plan changes=0`, exits 0 and leaves the tree as it was. The `spec/` README explains how to restore from the manifest.

Each before-image now goes to its own file under `upgrade-legacy.before-images/` in the git directory, named by the sha256 digest of the saved bytes, so the manifest holds only paths and digests. On a 2048-packet tree it came to about 16 MB. The inline form it replaced could grow into one string too long for the engine to write (`Invalid string length`), which refused the apply on a large tree. A later apply removes sidecar files the new manifest does not reference, and a manifest written by an older run still restores from its inline content. The README's restore script reads and checks every sidecar before it writes anything, so one unreadable or altered sidecar leaves the tree untouched. It also refuses a sidecar name that leaves the manifest directory and a sidecar directory that is a symbolic link.

#### Upgrades Survive a Real Repository

`upgrade-legacy` keeps each symbolic link as written when it copies a packet for a preview or an apply. Before, a link that pointed at its own folder made the copy recurse until the path passed the filesystem limit, and the preview failed with `ENAMETOOLONG`. The healer still reports a link that leaves the packet as not followed.

A fresh clone of a v3-era commit with 2048 packets went from 0 to 2045 packets passing in one apply, and the README's restore script brought one packet back byte for byte. The three that remain fail only `METADATA_DISK_PATH_CONSISTENCY`, a rule the upgrade never records a baseline for, so the doctor workflow ends PARTIAL and names them for manual review.

#### Layout Is Checked Before Anything Moves

`/doctor:update check` reads the spec layout and counts the pre-v4 signals in a read-only phase. The compat action is separate. It runs a preflight, previews the layout move and waits for your approval. After the move it previews the upgrade and asks a second time before it applies anything. Nothing is written before the first approval, and nothing under `.skilled/` is written. `upgrade-legacy --layout-map` prints the planned moves as JSON and names each collision with its reason.

#### A Dry Run Reports Legacy Signals

After the per-packet results, the dry run prints a repository era report. It names the layout as v3, v4, both or unknown and says where that answer came from. It also counts documents with and without frontmatter. The underlying classifier also counts template markers, generated metadata and level documents for each packet. The report only reads.

#### A Resumed Compat Run Finishes Its Owed Step

A step the run still owes is not counted as a planned move, so a resume runs it without the dirty-roots refusal. The move log closes on every terminal status reached after a run starts. A layout map that prints no JSON now fails the run. A failed step keeps its run open, so the next resume still lists it as owed.

#### Release Locks Block Legacy Upgrades

`upgrade-legacy` now exits 2 while `.skilled/release/.apply.lock` exists. Its message names the lock file. An apply writes no packet or manifest data. Wait for the release apply to finish before starting an upgrade.

## Spec Validation

#### Nested Anchors Are Errors Now

`ANCHORS_VALID` now checks three things it did not check before. It reports an anchor opened inside another anchor. It also reports a closer that arrives before its opener or while another anchor is still open. A name closed more times than it is opened is reported too. These findings are errors, so a packet that has one fails validation. The one nesting that stays allowed is a decision record's child anchor inside its parent. The nesting check skips inline code, and the other anchor checks still count markers in it.

#### Anchor Repair Previews Before It Writes

`heal-spec-docs --anchor-repair` fixes three kinds of defect. It removes a duplicate anchor pair that sits on a line next to another anchor marker and overlaps another pair. It renames each other isolated duplicate to its name plus its position among the pairs that share the name, so a second `problem` pair becomes `problem-2`. It also moves a questions anchor so it sits directly above its heading. The run is a dry run by default, and `--apply` writes. A document is refused when its heading sits inside another wrapper or when its questions anchor does not hold exactly one heading. A rename is refused when the new name already exists. Each write goes through a temporary file, so a failed write leaves the original in place.

#### New Packets Pass Their Own Checks

`create.sh --phase` writes graph metadata for the parent and every child before it exits, so a fresh phase passes strict validation. Before this change, the metadata failed the integrity and drift checks the moment it existed. New `spec.md` files also place the questions anchor directly above the questions in each level, so anchor-based retrieval and merges see the sections below it.

#### Lean Parents Check Every Child

A phase parent now derives `complete` only when every child's `graph-metadata.json` loads and every child is complete. Otherwise a parent that would read `complete` reads `in_progress`. If no child metadata loads, the parent keeps its stored status. Existing metadata changes only when a later re-derive runs.

## Commit Checks

#### Every Commit Carries a Commit-Id

The commit hooks used to mint a Commit-Id only through the repository's own allocator, which the hook trust gate hides in an untrusted clone, so commits there went out with no id and nothing said so. `prepare-commit-msg` now falls back to the allocator shipped beside the hooks, without running code from the repository, and it stamps a continued revert and a squash commit too. In a repository that uses ids, `commit-msg` refuses a message without one and `pre-push` refuses any added non-merge commit without one. A repository uses ids when it ships the sk-git allocator or spec-kit, or when its last 50 commits carry one. `git config --local skilled.commitId true` or `false` decides before either test.

#### Trigger Phrases Are Checked Before Commit

The pre-commit check compares the trigger phrases of each staged Markdown file with its committed version, and it grades only the phrases you added. A template-default or editor-fallback phrase blocks the commit, and the block message names the bypass. Other negative classes only print a warning. If the linter, its YAML library, `node` or git is unavailable, the check warns and lets the commit through. The phrase cleanup now covers all 18 template kinds, writes each file atomically and routes a file without frontmatter to the fixer instead of counting it as skipped.

#### Commits Check a Staged Skill's Generated Files

When a commit stages a change to a skill, a deletion included, the pre-commit hook runs the leaf manifest check, the parent-skill doctor and the intent-signal check for that skill. A failure blocks the commit and names the command that repairs it. The hook also blocks when the skill's `leaf-manifest.json` or `graph-metadata.json` has unstaged changes. Without `node` the check warns and skips, and without `python3` it skips only the doctor.

#### Changed Docs Raise Their Version at Commit

When a commit stages a skill doc whose body changed and whose version did not go up, the pre-commit hook raises the third segment and stages the file again. A change that touches only the frontmatter raises nothing. Set `SPECKIT_SKIP_DOC_VERSION_BUMP=1` to skip it. A pull request check fails on any changed doc whose version did not go up, and it names `frontmatter-version.mjs bump`, the command that fixes it.

#### Mirror Checks Cover Codex and Hermes

A commit that changes only a `.codex/agents/` file now runs the agent mirror check. The mirror parity gate also runs the Hermes skill and prompt checks before commit, where only CI compared them before. A failed mirror check names the script that fixes it. In a clone whose hooks are not trusted, the hook says it skipped its checks and names the `skilled.trustRepoHooks` setting that turns them on.

## Deep Loop Modes

#### Two Unused Modes Are Retired

**Breaking:** `/deep:agent-improvement` and `/deep:model-benchmark` no longer exist, and nothing in the repository replaces them. The agent-improvement and model-benchmark modes left the mode registry with their packet, their agent in every runtime and the runtime libraries they ran on. `system-deep-loop` now routes three modes: research, review and AI Council.

The skill advisor no longer routes a prompt to either mode, and no other skill documents or links to them. Benchmark authoring keeps two families, behavior and MCP promotion. Spec validation no longer checks a packet's `improvement/` folders, so older packets that hold one stay valid as history.

#### A Finished Run Does Not Start Another

A prompt that mentions a run you already finished, such as "We just finished a deep-research run. Initialize the deep-loop graph", no longer starts a research loop. The deep-loop hub asks what you want instead, and a request that follows the finished-run clause still routes.

#### The Agent Mirror Checker Has a New Home

The checker that keeps each runtime's agent copies in step lived inside the retired packet. It now sits at `.skilled/bin/check-agent-mirror-sync.cjs`.

#### Review Findings Show Their Case

Every `/deep:review` finding now carries one line with the input or situation that produces the wrong result, at every severity. The reducer reads findings written as numbered lines and keeps each one once, even when an iteration restates a structured row. A review folder without `deep-review-config.json` now reduces on defaults in lenient mode. Strict mode fails with "could not read deep-review-config.json" instead of a corrupt-line error, and the hint says `--lenient` reduces past it.

#### Research Merges Refuse Unstamped Lineages

A deep-research fan-out merge now refuses a lineage whose `deep-research-dashboard.md` lacks the reducer stamp `description: Auto-generated reducer view over the research packet.`. Without the stamp the dashboard was written by hand, so the lineage's registry is left out of the merge. The attribution table shows REFUSED in that lineage's Verdict cell, and the JSON output lists it under `refused_reducer_provenance`. A lineage with no dashboard at all still merges, with a warning under `reducer_provenance_warnings`, because nothing shows its registry was written by hand. A dashboard that cannot be read refuses only that one lineage, not the whole merge, and the merge status stays `ok`.

## Adapting the Code Skill

#### OpenCode Is Native and the Examples Are Optional

OpenCode (`sk-code-opencode`) is the native code surface and stays. Webflow (`sk-code-webflow`) and Obsidian (`sk-code-obsidian`) are optional examples you can remove. The README, the hub `SKILL.md` and the hub README now say so, and none of them tells you to replace OpenCode. The README block "What Adapting `sk-code` Looks Like" covers the hooks to install, the folders to keep, removing an example, adding a surface and the checks that prove each step.

#### The Guide Starts From a Fresh Clone

The block's "Before you start" step opens with `bash .skilled/skills/sk-git/scripts/worktree-naming.sh provision .` for a fresh clone and `git config --local skilled.trustRepoHooks true` for a clone that should run the hooks. The removal steps name the two feature-catalog files and regenerate `graph-metadata.json` with `regenerate-skill-derived.cjs`. The add steps name `leaf-scopes.json` and the surface-count lines the documentation claim checker reads.

#### A New Surface Lands Ahead of OpenCode

`/create:skill-parent update --surfaces` writes a new surface into `routerPolicy.tieBreak` after the workflow modes and ahead of the existing surfaces, several in the order you give them, so it wins a keyword tie against OpenCode. Its report names the two steps it cannot run for you: a canary case with its fixture copy and a commit with the hooks installed. If you edit `hub-router.json` by hand and list your own surface after `sk-code-opencode`, doctor check 5l fails and says to move it ahead.

#### Removing an Example Keeps the Checks Working

The sk-code drift guards read only the surface packets on disk and skip archived route gold for a mode the hub no longer declares. The documentation claim checker takes the surface count from `mode-registry.json`, so "two surfaces" passes on a hub with two. Removing an example no longer makes a guard throw.

#### Failures Name Their Fix

When a surface folder is missing, doctor check 3c names the README block that finishes the removal. When a hub's routing inputs change without a re-mint, the compiled-route guard used to print only `Re-mint: <hub>`, and it now names the `compiled-route-manifest.cjs` refresh command, both manifest paths and the copy that clears it. A missing authored compiled-routing folder under `specs/` stops sync and the guard with the folder to restore, where before they passed or printed a stack trace. In a fresh clone `ci-skill-root-metadata.cjs` printed a raw Node stack, and it now prints one line naming the provision command.

#### One Command Checks the Setup

`/doctor:sk-code setup` runs eight read-only checks from the repository root: provisioning, the parent-skill doctor, root metadata, the compiled-route guard, sync, the drift guards, derived freshness and a route probe. Each prints PASS, SKIP or FAIL with a `repair:` line naming the command that clears it, and the run ends `STATUS=OK legs=8` or `STATUS=FAIL failed=<n> skipped=<n>`. The probe passes only on a real compiled route, and it names `SPECKIT_COMPILED_ROUTING` when that variable has switched compiled routing off. On a checkout older than v4 the run reports the missing layout once and skips the other seven checks. `--prompt=<text>` sets the probe's prompt, and the run writes nothing.

## Code Reviews

#### Reviews End on Their Status Line

A code review now ends on its status line, and nothing follows it. One `Not checked:` line sits directly above it, one blank line apart, and names what mattered but could not be checked. Each finding carries a `Case` line with the input that shows it, and a finding with no case is not reported. Findings are numbered once across the severity groups, and the review reads the callers, callees and tests of the changed code before it judges the change. `check-review-final-line.js` and `check-review-findings.js` in the review mode's `scripts/` folder check a saved review against these rules.

#### Reviews Detect Obsidian and Cache Outside Your Repository

The review mode detects OpenCode, Obsidian, Webflow or unknown code with the hub's shared detection rules, where it used to call unknown code Webflow. Its re-review cache now lives at `${XDG_CACHE_HOME:-$HOME/.cache}/sk-code-review/`, so a review never writes into the repository it reviews.

#### Code Agents Say What They Skipped

`@code` lists the callers, tests, fixtures, config and exports a change must reach, and its return carries a required `not_checked` field. `@debug` reads the test setup and build config before it reproduces a bug, says how many hypotheses it left out and ends each response with a Not checked line. `@orchestrate` task briefs gain a Reach field.

## Code Skill

#### One Surface Order Everywhere

Every sk-code file that ranks the code surfaces now says OpenCode, then Obsidian, then Webflow, and a prompt that matches two surfaces lists them in that order. When keywords tie between surfaces, the surface of the session's current work can lead. `compiled-route.cjs --surface-hint` moves a hinted surface the prompt already matched to the front. An unknown hint is ignored, and a hint never adds or drops a target.

#### Restraint Requests Reach the Quality Mode

Prompts that ask for restraint, such as "yagni", "simplify", "over-engineering" or "bloat", now route to the quality mode. The restraint ladder checks what the codebase already has before it reaches for the standard library. Restraint never cuts a P0 item, and accessibility is now one of them.

#### Marked Shortcuts Have a Report

`ceiling-report.sh` in the quality mode lists the `ceiling:` and `intentional-limit:` comments in your code and flags any that names no upgrade trigger or no measurable signal. It only reports, so a valid run exits 0. The quality mode also maps Obsidian plugin changes to the checklists the Obsidian packet ships.

#### Drift Guards Check the Docs and Show Warnings

The sk-code-opencode drift guards run four guards now. The router-sync guard is back, and it also reports reference docs that no router names. A new documentation claim checker flags dead paths, retired names, wrong surface counts and dead anchors. The summary shows each guard's warning count on its PASS line, where it used to print a bare PASS over hundreds of warnings. The router-sync guard skips files git ignores, so a local cache folder no longer fails it.

#### Drift-Guard Scripts Use Kebab-Case Names

**Breaking:** three scripts in sk-code-opencode's `assets/scripts/` were renamed. `router_replay_lib.cjs` is now `router-replay-lib.cjs`, `verify_doc_claims.cjs` is now `verify-doc-claims.cjs` and `verify_router_sync.cjs` is now `verify-router-sync.cjs`. Their tests moved with them.

#### Webflow Runtime Checks Catch Late Errors

The minified-runtime check used to swallow errors thrown by deferred `setTimeout`, `requestAnimationFrame` and `Webflow.push` callbacks, so a script that crashed after load still passed. It now fails that file and names the first error. Callbacks it skips at its depth cap of 20 are counted in a warning under the PASS line.

## Install and First Use

#### Install Steps Reach a Working Request

The README now asks for Node 24, the one line every part accepts. Code Mode's server needs Node 24, the spec-kit CLI needs 22.12 or newer and the advisor needs 20.19 or newer. A new step builds the spec-kit workspace, which the session hooks and the agent mirror check load. The advisor build step says to run it after the dependency install, because it compiles against the types that install brings. A last step sets `skilled.trustRepoHooks`, so a second clone on the same machine runs its pre-commit checks. First Use names all seven runtimes and how each one spells `/speckit:complete`.

#### Missing Builds Say So

Pi warns at session start when the built session-prime adapter is missing, and it names the folder it checked and the build to run. The Codex hook drift message names the build as well, and sk-vision documents its Bun setup.

#### The Mirror Check Skips When It Cannot Run

`check-agent-mirror-sync.cjs` exits 3 with NOT CHECKABLE when its parser is missing or fails to load. Both pre-commit hooks then warn and skip the mirror check. Before, a clone without that build saw the gap reported as mirror drift and the commit blocked.

## Skill Routing

#### Paths and Doc Targets No Longer Pull Routes

The skill advisor no longer counts a skill name that sits inside a file path or right before `SKILL.md`, `ROUTER.md`, a README or a changelog. A write aimed at a skill's own doc skips that skill's author phrases, and the word "findings" no longer boosts a route. "Changelog" counts as a doc target only as `changelog.md` or a `changelog/` path, so a prompt that names the sk-doc changelog mode reaches sk-doc again. The Python advisor also stays on the native scorer after the advisor daemon idles out, where it used to fall back to a local scorer without these rules.

#### Requests to Write Code Reach the Code Skill

A request to add, build, create, implement or write a helper, test or Vitest suite now routes to sk-code even when it names a deep-review phrase or a study artifact. "Write a Vitest covering the resume deep review phrase" used to start the deep-review loop, and "Add a packet-local helper that formats confusion-matrix rows" used to reach spec-kit. A real deep-review resume and an edit to a study template route as before, and the Python and Node advisors now agree on these prompts.

#### Callers Can Pass the Code Surface

`advisor_recommend` accepts a `surfaceHint` of 1 to 64 characters and passes it to the compiled route. The OpenCode plugin sends the surface that its workspace markers name, and it sends OpenCode only for a workspace inside this repository's `.skilled` folder. The Claude and Codex hooks send no hint.

#### Routing Drift Fails CI

`skill-graph-freshness.cjs --strict` exits 1 on a stale, unreadable, ghost or missing compiled entry, on intent-signal drift and on a skill family mismatch, and it names the compiler command. The routing drift workflow runs it beside the intent-signal check. `compiled-route-sync.cjs --check` now compares every served file with its authored source byte for byte and names each copy that differs or is missing. The documented compiled-route rebuild works on a clean checkout again.

## Hooks and Dispatch Guards

#### Hooks Stop Waiting for Input

Hooks that read stdin now stop waiting after a deadline. That covers the shared hooks, the spec-kit runtime hooks, the sk-git message gate and preflight advisory and the Devin vision hook. A hook reads until its input ends or 3 seconds pass, then answers with what it has, so a host that never closes stdin no longer holds a tool call until it kills the hook. The spec-kit readers also cap input at 1 MB. Seven spec-kit entries whose host stops them at 3 seconds wait only 500 ms, and a payload written after that is dropped, so the hook answers as if it had no input.

#### The Pi Guard Reads Wrapped Dispatches

The dispatch inspector now reads the payload of a `bash`, `sh`, `zsh` or `dash` `-c` wrapper, escaped quotes and later wrappers included, so a CLI dispatch inside a wrapper no longer slips past the Pi guard. A variable counts as an executor only in command position, so `mkdir -p "$DIR"` is no longer denied. When the guard denies an ambiguous command, its message says what passes: one executor named by its own name in the user request, not through a variable or alias.

## Agents and Repo Rules

#### Rules Add Restraint Floors and Residual Risk

`prevent-overengineering.md` adds a floor against a short diff the reader has to decode, a tiebreak between equal-cost moves and the full reach set of tests, fixtures, config and exports. It also covers restraint in moves and merges and lists accessibility among what restraint never cuts. The close-out status gains a fifth part for known residual risk, and it now lives in one place, section 1 of `communication-handoff.md`, which `AGENTS.md` and `evidence-and-proof.md` point to.

#### Option C Reads the Same Everywhere

Option C in the Gate 3 menu now carries the same full wording in every runtime, ending "as an existing packet in the same track", so each agent offers the series parent the same way.

#### Child Workers Follow One Gate 3 Rule

When a session is a child worker, marked by `AI_SESSION_CHILD=1`, Gate 3 is pre-resolved before the worker starts. Inside its lineage directory the worker records a halt and continues rather than stopping. The `speckit:plan`, `speckit:implement` and `speckit:complete` commands each define this rule under a `child_dispatch` key, and the system-spec-kit skill and its Hermes copy state the same text.

## Script Options

#### create.sh Refuses Unknown Options

A misspelled option such as `--goal`, where `--with-goal` was meant, used to become part of the new folder's title, and the run still exited 0. `create.sh` now stops on any option it does not know with `Error: unknown option`, points to `--help` and exits 1 before it writes anything.

#### Every Script Refuses Unknown Options

The same check now covers scripts across the skills: the spec-kit CLI, the skill advisor, the deep loop, sk-doc, sk-code, sk-design, sk-git and the shared `.skilled/bin` tools. A misspelled option such as `--modell` used to be ignored, so the run went on with its defaults. Each script now names the unknown option and exits with its usage code, which is 2 for most. A script that already had a usage code keeps it, such as 64 for `frontmatter-version.mjs`, and the deep-loop scripts keep their JSON error with exit 3. Three scripts that reported a problem and still exited 0 now fail. `worktree-naming.sh create` exits 3 when provisioning fails, `migrate-legacy-branch-names.sh` exits 1 when a dry run skips a taken name and `check-comment-hygiene.sh` exits 3 on a file it cannot read. `create.sh --help` now lists `--path`.

#### Healer Inputs Are Checked

Every healer mode now rejects an unknown flag with exit 2. A nonexistent `--folder` or `--roots` path also exits 2 and names the path. Without `--roots <dir>`, the healer exits 2 for a folder outside every repository. A plain folder outside the supplied specs root now gets an outside-root message, while a linked parent keeps the symbolic-link wording.

`heal-spec-docs` also reports a linked `spec.md` as refused when it reads the packet level. That finding keeps the existing exit 0 for linked-document refusals.

#### Removed Flags Explain the Change

Passing `--mode` or `--json` to `heal-spec-docs --lane-modes` now exits 2 with a message that tells you to drop the flag. The `--mode` message says `--lane-modes` runs all five modes. The `--json` message explains that lane mode prints "would apply", "applied" and "refused" lines. Other unknown flags use the generic unknown-argument message.

## Symlink Safety

#### Symlinks Are Refused, Not Followed

Archive, restore, heal, upgrade and repair refuse a packet document or an archive folder that is a symlink, rather than writing through it. An archive folder that resolves outside `specs/` is refused before anything is created through it, and so is a path with a `.` or `..` segment. A dangling link counts as an existing target and is refused. `heal-spec-docs` reports a symlinked document as a symbolic link it did not follow, and its default write is atomic.

The upgrade apply guards each move. A packet whose top-level link resolves outside it is refused before any write, and a linked `upgrade-baseline.json` is no longer read. The validator reports that case with the `UPGRADE_BASELINE_LINK` warning. The leaf manifest generator confines each start scope to the skill before it reads a directory. The description and graph metadata loaders refuse linked files, and the prune report refuses a linked target and writes through an exclusive temporary name.

#### A Linked Packet Argument Is Refused Before Any Write

`heal-spec-docs` refuses a `--folder` that is a link, sits under a link in the specs root, or resolves outside it. It prints that the link was not followed, writes nothing and exits with status 2 in every mode. `repair-derived` leaves a linked `graph-metadata.json` alone and reports why, so its dry run and its apply agree. `generate-leaf-manifest --write` refuses a linked `leaf-manifest.json`, and it writes through a random temporary file and a rename.

#### Linked Paths Stay Packet-Local

Archive and restore now reject any linked path argument with exit 1 before they copy or move a packet. The message names the real folder. `generate-leaf-manifest --check` rejects linked or dangling `leaf-manifest.json` files with exit 2. `upgrade-legacy` rejects a linked reversibility manifest (`upgrade-legacy.manifest.json` in the git directory) or a `--roots` path containing `..` with exit 2.

Graph metadata readers follow links that resolve inside a packet, and a linked folder on the way to a document, such as a `research/` folder, is judged by its real path too. When a link leaves the packet or dangles, `readDoc` reports its document as unknown. Source hashing skips the document. A required `repair-derived` step exits 2.

#### Backfill Roots Stay in Scope

`backfill-graph-metadata --root` now requires the target to stay inside the repository resolved from the working directory. A prune report also needs a `.opencode`-anchored root. Both checks refuse before metadata or a report is written.

## Pull Request and CI Checks

#### Pull Requests Fail Only on New Problems

The changed-packet gate validates each packet that fails at the head, then validates the same packet at the merge base with the same validator. It blocks only on rules that the head fails and the base does not. A report it cannot read counts as a failure, so the gate fails closed. The weekly sweep now downloads the previous successful run's report as its baseline. A folder that passed in that baseline and fails now is marked as a regression. With no previous report, the run records a baseline and reports no error.

#### Pull Requests Check Citations and Catalogs

Every pull request now runs the feature-catalog validator with its fixture test, and checks each `path:line` citation in the skill docs. A catalog failure blocks the pull request. So does a citation the pull request adds or changes that no longer resolves or points past the end of its file. Older broken citations print as one count and do not block, and a push to main only reports.

#### The Two Advisors Must Agree in CI

The routing drift workflow fails a pull request when the Python and Node advisors route a prompt differently and the approved divergence ledger does not list it. It also fails when a listed divergence no longer happens. The check scores against a skill graph built fresh from the checkout at the time the ledger records, so a CI result matches a local run. A second step fails when a scoring surface reads held-out evaluation prompts without declaring them.

#### The Trigger Index Job Gets Less Access

The trigger index rebuild now runs as a rebuild job with read-only access and no secret and a push job that is the only one allowed to write. The push job checks that the bundle it receives holds exactly one commit that changes only the four generated paths, and git hooks stay off in both jobs. The changed-packet gate and the freshness report print folder names and validator output inside a stop-commands block, so a printed name cannot act as a workflow command. The gate also lists changed packets with `git diff -z`, so a folder name with control characters or non-ASCII bytes is no longer skipped.

## Skill Authoring

#### Every Doc Carries Its Own Version

`SKILL.md` carries the skill's version, and every other skill doc carries its own. `frontmatter-version.mjs verify` used to fail on every skill, because it compared each doc with the skill's version. It now checks that each doc has a valid 4-part version, and that `SKILL.md` matches the newest changelog entry. A new doc starts at 1.0.0.0, and every doc template seeds that line. Hand-written docs that had no frontmatter, such as the install guides, now have frontmatter with a version. Generated files such as benchmark output and test fixtures stay without one. The parent-skill doctor no longer fails a hub whose README version differs from `SKILL.md`. A hub `ROUTER.md` keeps its own version too. Doctor check 13a compares only `description.json`, `hub-router.json` and `mode-registry.json` with `SKILL.md`, and `/create:changelog` no longer writes the release version into `ROUTER.md`.

#### Changelog Entries Carry a Version Key

`validate_skill_package.py --strict` fails a skill whose changelog entries have no `version:` key in their frontmatter. Every shipped entry now has one, so the strict package check passes on every skill.

#### Changelogs Number Against Upstream

`/create:changelog` now reads the version entries on the upstream branch and skips a number taken on either side, so two branches no longer choose the same version. After it writes an entry, it sets the new version in every file of the skill root that carries one, and on a hub it runs the parent-skill doctor. In confirm mode a collision moves the build segment up.

#### The Feature Catalog Template Comment Is Retired

Feature catalog scaffolds no longer write `<!-- sk-doc-template: skill_asset_feature_catalog -->` under the title, and the catalog checklist no longer asks for it. No tool read that comment. It is gone from every shipped catalog, and the other `sk-doc-template` comments left the skill docs that still carried one.

#### Hub Checks Report No Warnings

The parent-skill doctor now reports zero warnings on every hub, so a warning on your clone points at a change you made. Each hub README states the version its `SKILL.md` carries, and every mode alias is lowercase and listed among its router keywords.

## Authoring Validators

#### Authoring Tools Explain Themselves

A stale leaf manifest message now lists the added and removed leaves and the full `--write` command. The leaf manifest generator leaves git-ignored files out, so a `__pycache__` folder no longer makes a manifest look stale. It also skips dot-named folders, so a local tool cache cannot change a hub manifest. sk-create-skill names the fields the advisor scorers read and says that `description.json` keywords are not one of them. Its skill and parent-skill README templates no longer offer a "Why It Matters" bullet list.

#### Validators Stop Flagging Correct Paths

The catalog validator treats a committed link or file as present and judges an ignored path by a tracked `.gitignore`, never by personal excludes. The package validator exempts fixture folders from kebab-case and accepts `.ts` and `.txt` files in `scripts/`. It also skips the standalone sections a hub does not need and finds a RULES section by its real heading.

#### Playbook and Catalog Checks Catch Stale Paths

The catalog validator now checks the paths in two-column File tables too. The playbook validator warns about a backticked path that no longer resolves, without failing the run, and its full report survives being piped. It treats a symlink as present and skips the files the release engine writes on install. Backticked paths in 227 playbook files now point at real files, so 258 warnings came down to 1. The check now reads each package's top-level `manual-testing-playbook.md` as well, and the 70 stale paths it found there came down to 1. The Codex tools reference now sets MCP servers under `mcp_servers` in `config.toml`, the file Codex reads, not in a `.codex/settings.json` that does not exist. The citation scan resolves paths against a skill's `runtime/` and `scripts/` folders. With `--overlap` it flags a citation that resolves but sits more than 10 lines from every name the citing line mentions.

## Sessions and Tooling

#### Pi Starts GPT Targets in Fast Mode

The Pi Fast Mode extension is now on by default, in new worktrees too. It still changes only the provider and model pairs in its configuration. A saved state, the `--fast` flag and the value a parent hands to its subagents still decide over the default, so `/fast off` stays off after a restart.

#### Launched Sessions Keep Their Settings

The launcher now exports `SKILLED_WORKTREE_SESSION=1` for launched sessions. `AI_SESSION_CHILD=1` remains the marker for dispatched children. Hermes repo guards treat it alone as a child marker. Launched and in-worktree sessions preserve the operator's `SYSTEM_SPEC_GATE_ENFORCE` value. Only dispatched children receive `0`.

#### Doctor Env Reads the Legacy Tables

`ENV-REFERENCE.md` listed `SYSTEM_SPEC_GATE_DISABLED` twice, and the second row had a different default and type, so `/doctor:env` stopped on the file. The two rows now agree. The env parser accepts the legacy label rows, reads boolean polarity and treats a row with the wrong cell as malformed.

#### Nested Changelogs Keep Every Row

Nested changelog generation keeps every Files Changed row and removes inline HTML comments, including comments that span a line break.

## Upgrade Notes

- **Reinstall dependencies.** An existing install keeps the vulnerable versions until it reinstalls. Rerun the `npm --prefix <package> install` commands from the README setup for each package you installed.
- **Build the spec-kit workspace after you pull.** Run `npm --prefix .skilled/skills/system-spec-kit run build`. The session hooks and the agent mirror check load that build, and without it they warn and skip.
- **Run Node.js 24 for a full install.** Code Mode's server needs `>=24.0.0 <25.0.0`. The advisor runtime's build tools need `^20.19.0 || >=22.12.0`, and the spec-kit runtime CLI needs 22.12, so Node 24 satisfies every part.
- **Expect a Commit-Id check at commit and push.** A repository that uses ids refuses a commit without a `Commit-Id` trailer. Install the hooks so `prepare-commit-msg` stamps one, or run `git config --local skilled.commitId false` in a repository that should not use them.
- **Repair nested anchors before they fail validation.** Run `heal-spec-docs --anchor-repair` as a dry run first, then add `--apply`. The repair refuses some documents and leaves them unchanged, so those need a manual fix.
- **Stop using the two retired deep-loop commands.** `/deep:agent-improvement` and `/deep:model-benchmark` have no replacement. Older spec packets that hold `improvement/` folders need no change.
- **Fix calls that pass unknown options.** A script or alias that passes an option a script does not know now stops with a usage error, exit 1 for `create.sh` and exit 2 for most other scripts. Use `--with-goal` to add a goal with `create.sh`, and run any script with `--help` for its options.
- **Run `/doctor:sk-code setup` after you adapt sk-code.** It names the command that clears each failing check.
- **Expect a pre-commit phrase check.** The hook blocks added template-default and editor-fallback trigger phrases. Set `SPECKIT_SKIP_PHRASE_LINT=1` to skip the check, and the hook prints that bypass when it blocks a commit.
- **Expect a skill check at commit.** Stage the regenerated files the block message names, or set `SPECKIT_SKIP_SKILL_AUTHORING=1` to skip the check.
- **Give your own skill docs a version.** `frontmatter-version.mjs verify` fails a skill doc with frontmatter and no `version:` line. Add `version: 1.0.0.0`, and the commit hook raises it from there.
- **Key your own skill changelogs.** Add a `version:` line to each entry's frontmatter, or `validate_skill_package.py --strict` fails the skill.
- **Move personal skills Devin should see.** Devin no longer reads `~/.claude/`, so a personal skill kept only in `~/.claude/skills` stops reaching it. Put that skill in `~/.agents/skills` instead.
- **Reconnect ClickUp.** Restart your client and approve ClickUp's OAuth prompt once in the browser. The old ClickUp key lines in your own `.env` are unused and safe to delete.
- **Read the refusals before you rerun an upgrade.** Each packet's `upgrade-baseline.json` lists the repairs the upgrade refused under `refusals`. A refused repair stays as it was, so you need to fix it yourself.
- **Apply upgrades from a git checkout.** `upgrade-legacy --apply` exits 2 when the repository has no git. If an apply is interrupted, the saved before-images in the git directory let you restore the files, and the README in `spec/` explains how.
- **Keep a manifest beside its sidecar folder.** Before-images now live as separate files under `upgrade-legacy.before-images/` next to `upgrade-legacy.manifest.json`, so a manifest cannot restore without its sidecar folder. Keep both while you might still need to undo, and delete both together when you do not. Manifests written by older runs hold their contents inline and restore as before.
- **Run the restore script through `UPGRADE_LEGACY_REPO_ROOT`.** The README's restore script resolves every path from that variable, so run it as `UPGRADE_LEGACY_REPO_ROOT="$repo_root" node --input-type=module --eval "$(cat restore.mjs)" "$manifest"`. It checks every sidecar before its first write, so one bad sidecar leaves the tree untouched. To restore one packet, write a packet-scoped copy of the manifest beside the real one, with `beforeImages` and `scopeHashes` reduced to that packet and the `baselineMap` kept as it is, then pass the copy as the manifest argument.
- **Hand-fix packets that fail only `METADATA_DISK_PATH_CONSISTENCY`.** A parent stored as the text `"null"` is now cleared on the next re-derive, so `repair-derived --folder <packet> --apply` fixes that case. A packet that still fails names a real parent that no longer matches its folder. The upgrade never records a baseline for that rule, so the doctor workflow ends PARTIAL and names those packets for manual review. Correct `parent_id` in the packet's `graph-metadata.json` by hand.
- **Wait for a release apply to finish before running `upgrade-legacy`.** It exits 2 while `.skilled/release/.apply.lock` exists.
- **Replace two removed flags with upgrade-legacy.** `check-template-staleness.sh --auto-upgrade` and `quality-audit.sh --fix` were removed. Each now exits 2 and names `upgrade-legacy` as the replacement.
- **Drop `--mode` and `--json` from healer lane runs.** Each now exits 2 with a message that tells you to drop the flag. Without `--mode`, all five modes run.
- **Use real paths, not links, with the packet tools.** Archive and restore refuse a linked argument with exit 1, and the `leaf-manifest.json` check and `upgrade-legacy` refuse a linked manifest with exit 2. Keep `upgrade-legacy --roots` values free of `..`, keep a backfill `--root` inside the working repository and pass `--roots <dir>` when a healer `--folder` sits outside every repository.
- **Rerun the reducer for a refused research lineage.** A fan-out research merge now refuses any lineage whose dashboard lacks the reducer stamp. Rerun the reducer for that lineage so its dashboard carries the stamp, then merge again.
- **Repoint the agent mirror checker.** Run `.skilled/bin/check-agent-mirror-sync.cjs`, because the old path inside the retired packet is gone.
- **Repoint the renamed drift-guard scripts.** Call `router-replay-lib.cjs`, `verify-doc-claims.cjs` and `verify-router-sync.cjs` in place of their snake_case names.
- **Check scripts that read the launcher marker.** Launched sessions set `SKILLED_WORKTREE_SESSION=1` in place of `AI_SESSION_CHILD=1`, which now marks only a dispatched child. They keep your `SYSTEM_SPEC_GATE_ENFORCE` value, and only a dispatched child receives `0`.
- **Turn off Pi Fast Mode with `/fast off`.** Run it once, and the saved state outlasts a restart.
- **Delete the template comment from your own catalogs.** Nothing reads `<!-- sk-doc-template: ... -->`, so the line is safe to remove, and new scaffolds no longer write it.
- **Delete two unused Jev switches.** `JEV_FEATURE_VERDICT_FALLBACK` and `JEV_FEATURE_HALLUCINATION_GRADER` no longer have a reader, so their lines in your own `.env` are safe to delete.
- **Keep a hub `ROUTER.md` version as it is.** The doctor no longer compares it with `SKILL.md`, so a version you matched to a release can stay.
