# v4.0.0.2, Leaner Goals: One Limit, One Command and One Send Rule

v4.0.0.2 makes the goal a spec packet carries cheaper to write, cheaper to send and harder to get wrong. It also gives the skill advisor a prompt hook that holds up in five CLIs.

A parent goal now has one limit. The validator used to warn at 3,000 characters and fail at 4,000, and the lower number read as the limit, so goals were cut short of the real one. Now 4,000 is the only number, and every tool that measures a goal applies it to the same folders.

A goal also has a command that writes it. `/create:goal` authors, amends and retrofits a packet's goal from the packet's own documents, starting from a template for its kind. A checker then catches the mistakes that used to ship, such as an unbound phase, a leftover placeholder or a parent over budget.

A sent goal got smaller. A parent goal sent in chat carries only its directive, because the author instructions that rode along with every send have left the templates. The rule for what a sent goal may contain lives in one place now, and the system-spec-kit docs that used to restate it point there instead.

Goals were also run live on every runtime without a native goal command. The defects that no unit test had caught in Hermes, Pi and OpenCode are fixed at their source.

## Why This Release

v4.0.0.0 moved the goal into the packet. A session binds to a spec packet and the runtime renders that packet's `goal.md` on every turn. The first weeks of real use showed where that left gaps.

Nothing helped an author write a goal, so parent goals ran over budget, phases went unbound and template placeholders shipped. An unfilled phase-parent template sent 2,823 characters in chat, and most of them were instructions to its author. The rule for what a sent goal may contain was restated in many files, and the copies disagreed on whether the 4,000-character limit capped the stored goal or the sent one. The tools that measure a goal did not agree on which folders the limit covers either.

The skill advisor had gaps of its own. Its prompt hook paid on every prompt for routing work nobody read. A slow advisor left four runtimes with nothing, and a turn without a suggestion looked the same as an outage.

## What's New at a Glance

- **One limit for a parent goal.** A top-level or phase-parent goal passes up to 4,000 characters and fails past it. The 3,000-character warning is gone.
- **One budget boundary.** The limit covers every top-level packet and every phase parent, nested or not, and every tool that measures a goal draws the same line.
- **`/create:goal` writes goals.** The create-goal mode in `sk-doc` authors, amends and retrofits a packet's goal from a template for its kind.
- **A checker catches broken goals.** It flags an unbound phase, a leftover placeholder, a criterion count outside three to seven, an over-budget parent and a stray frontmatter fence.
- **A sent goal carries only its directive.** One rule says what never goes out, and a goal is sent only when its budget reads ok.
- **The templates lost their author instructions.** An unfilled phase-parent template now sends 1,218 characters in chat, down from 2,823.
- **system-spec-kit points to one home.** Its phase workflows, references and `create.sh` help send goal authoring to `/create:goal`.
- **Goal commands fail loudly.** `goal.cjs` refuses an action it does not know and exits 1 on every failure.
- **Goals behave on every runtime.** Live runs fixed defects in Hermes, Pi and OpenCode that no unit test had caught.
- **Release notes have their own line.** `.skilled/changelog/skilled/` holds one entry per Skilled release, and system-spec-kit writes its own changelog again.
- **Every changelog can be found.** Every entry carries the search metadata a spec document carries, and new entries are written with it.
- **The skill advisor's prompt hook holds up in five CLIs.** It skips work nobody reads, says why a turn has no suggestion and outlasts a slow advisor. Test runs in five CLIs and a two-model review found the rest, and each defect is fixed.

## The Goal System

A packet's goal is now written by one command, measured by one limit, sent by one rule and served the same way on every runtime.

#### One Limit Instead of Two

A top-level or phase-parent `goal.md` used to warn past 3,000 characters and fail past 4,000. Every runtime goal surface caps at 4,000 or more and nothing caps at 3,000, yet the lower number read as the limit and goals were cut short of the real one. The warning tier is gone from the manifest, the validator, `goal.cjs`, the OpenCode plugin, the template, the playbook and the docs. Up to 4,000 characters passes, past it fails and the budget reads ok, over or unknown. Existing goals that quoted the old template sentence carry the new wording.

&nbsp;

#### One Budget Boundary

The tools that measure a goal disagreed on which folders the limit covers. A phase parent nested inside another packet failed the validator past 4,000 while `goal.cjs` reported unknown, and the goal checker passed a nested parent that `goal.cjs packet` reported over. Section 2 of the create-goal mode's `references/budget-and-handoff.md` now states one boundary. The limit applies to a top-level packet and to every phase parent, nested or not, and exempts only a phase child that is not itself a phase parent. The validator, `goal.cjs` and `check-goal.cjs` draw that same line.

&nbsp;

#### A Command That Writes Goals

`sk-doc` gains the create-goal mode and its `/create:goal` command. It writes a top-level, phase-parent or phase-child goal from the packet's own documents, amends an existing goal and retrofits one onto a packet that has none. Each kind starts from its own template in the mode's `assets/` folder, and a parity test fails when a template drifts from system-spec-kit's `goal.md.tmpl`. The mode hands back the parent's chat slice. It never sets or resends a session goal, which stays with the goal hooks.

&nbsp;

#### A Checker That Catches What Used to Ship

`check-goal.cjs` is read-only and runs five checks. It flags a phase the parent never bound, a placeholder left from the template, a criterion count outside three to seven, a parent over budget and a `---` line that closed the frontmatter early. `/create:goal` hands off only after the checker passes, so an open finding ends the run without a chat slice. The command also refuses a packet path outside its workspace and treats packet prose as data rather than instructions.

&nbsp;

#### A Sent Goal Carries Only Its Directive

Section 4 of `budget-and-handoff.md` is now the one rule for a goal sent in chat. A sent goal never carries frontmatter, HTML comments, anchor markers, `---` dividers, heading section numbers or author instructions. It goes out only at `packet_budget=ok`, and the 4,000-character limit is measured on the durable slice, the goal text between its frontmatter and its log. `AGENTS.md`, system-spec-kit's `SKILL.md`, the set-string playbook, five speckit workflows and the resend reminder point to that section instead of restating it.

&nbsp;

#### Templates Without Author Instructions

The blockquote, the Operator copy section and the criteria introduction are gone from system-spec-kit's `goal.md.tmpl` and from the create-goal mode's three templates, because that text went out with every sent goal. A `GOAL_AUTHORING` comment in each template points to the mode instead. An unfilled phase-parent template fell from 3,156 to 1,624 durable characters and from 2,823 to 1,218 in chat. Section 3 of `budget-and-handoff.md` is the one cut order for a parent over budget, and its new step 3 removes instructions an older template left behind.

&nbsp;

#### Phase Workflows Name /create:goal

system-spec-kit kept its own goal-nesting rules, and none of its phase entry points named the create-goal mode. The speckit `:with-phases` step, Option D in plan and complete, `phase-definitions.md`, `phase-system.md`, the quick reference and the `create.sh` help and next steps now send goal authoring to `/create:goal`. A retrofit has one path, `/create:goal <packet path> retrofit`, and the validator's two goal findings name their fix in the create-goal mode.

&nbsp;

#### Docs That Match the Runtime

Two claims in the docs were wrong. `create.sh --phase --with-goal` writes child goals only, and `--level phase-parent --with-goal` writes the parent goal. The runtime injects the objective slice on every turn, a pointer to `goal.md` with the binding rule for a phased packet and the completion criteria, rather than the whole durable slice. Every surface that said otherwise now matches.

&nbsp;

#### Goal Commands That Fail Loudly

`goal.cjs` used to store `goal.cjs --help` as an objective and exit 0 on every failure. It now refuses an unknown action with `UNKNOWN_ACTION` and exits 1 whenever it fails. The frontmatter match no longer backtracks either. A goal file that opened with 26 comments took 12.6 seconds to parse and stalled every hook render, and one with 2,000 comments now parses in milliseconds. The resend reminder stays on one line, and a packet path that does not exist yet is judged by where its real parent lands.

&nbsp;

#### Goals on Every Runtime

Each runtime without a native goal command was run live. Every defect found there is fixed at its source with a test that fails on the old code.

- **Hermes** injected its raw goal report, which was cut off before the brief. It also rendered the goal before the session had bound it. It now binds the session through the shared goal core and injects the rendered brief.
- **Pi** sent its turn-end nudge while a run was still streaming, which restarted a finished `pi -p` run that then worked on for 18 minutes. The nudge now rides the next user prompt and starts no turn. The completion-evidence advisory had the same defect and now waits the same way.
- **OpenCode** sanitized a bound folder's path, so binding a folder whose name held a line break reported success and bound nothing. It now keeps the path as written and re-checks it on every read.

The OpenCode, Pi, Devin and Hermes playbooks now describe what their runtime really does. The session-goal redirect no longer names `/goal-cursor`, which refuses session actions.

## Changelogs

The framework's release notes have a line of their own, and every changelog in the repository can now be found the way a spec document is.

#### Release Notes With a Home of Their Own

The system-spec-kit changelog had become the framework's release notes. Its v4 entries described the whole framework, and the skill's own history stopped at 3.9.0.0. The 45 release notes moved to `.skilled/changelog/skilled/`, one entry per Skilled release, and system-spec-kit writes entries about itself again. `/create:changelog skilled` writes a release entry, and only that line publishes a GitHub release. The command also resolves a hub such as `sk-doc` to its own changelog or to one mode's, where it used to find no version at all.

&nbsp;

#### Changelogs That Search Can Find

Only 52 of the 542 skill changelog entries declared a search phrase, so Gate 1 and `/speckit:search` reached few of them. Every entry now opens with the five keys a spec document carries, led by phrases that name its component and version. Both changelog writers produce the block, and `validate_document.py` blocks an entry that lacks it. A lookup for `sk-git v1.0.0.0` now ranks that entry first.

## The Skill Advisor

The skill advisor suggests a skill before each prompt reaches the model. Its prompt hook now does less, says more and survives a slow advisor, and running it inside five CLIs found defects no unit test had caught.

#### A Slow Advisor No Longer Empties the Turn

In Claude, Codex, Cursor and Devin the hook runs inside a shim that stopped it at the same moment the hook gave up on the advisor, so a slow advisor left the turn with nothing. The shim still stops the hook after 2,500 ms, and it now gives the hook 2,200 ms for the advisor and caps an operator's budget at that value, so the fallback arrives first. Pi runs the hook inside its own process and races the call against the hook's own budget plus 300 ms, then falls back the same way.

&nbsp;

#### Less Work on Every Prompt

The hook asked the advisor for a routing result that only the OpenCode plugin reads, then threw it away. It now asks the advisor to skip that work, which saved a median 65 ms per prompt. A casual prompt such as `/help` or a short acknowledgement no longer reaches the advisor at all.

&nbsp;

#### A Turn Without a Suggestion Says Why

A turn with no suggestion used to carry the bare fallback text, so the model could not tell an outage from a prompt that matched no skill. The fallback now opens with one line that names the case, and a repeat in a session the hook already knows shrinks to that line. The OpenCode plugin opens its fallback with the same line.

&nbsp;

#### What Five CLIs and a Review Found

The advisor's own test scenarios ran inside Pi, OpenCode, Devin, Cursor and Codex, and a two-model review with its follow-up checks found more. Every defect below is fixed.

- **The healthy advisor stays up.** A second launcher on the same database deleted the live advisor's lease, and the advisor then shut itself down.
- **OpenCode loads the plugin.** OpenCode had refused the advisor plugin, because the file exported helpers beside the factory OpenCode expects.
- **Long prompts get a route.** The callers sent up to 64 KiB where the advisor accepts 10,000 characters, so every longer prompt got the outage message.
- **Prompts stay out of the process list.** Every caller sends the prompt over standard input instead of the command line.
- **A test advisor stays in its sandbox.** An advisor given its own database folder keeps every state file there and can no longer mark the live advisor unavailable.

&nbsp;

#### Codex Runs Each Hook Once

Codex already loads a trusted checkout's own `.codex/hooks.json`, and the hook installer also copied every repository hook into the user-wide `~/.codex/hooks.json`. Each Codex event ran each hook twice, and the copies ran this repository's hooks in Codex sessions started anywhere. The installer now only removes those copies and keeps every third-party entry.

## Deep Loops

#### Fan-Out Runs Close as Complete

A fan-out run splits one research topic or one review across several models, each in its own lineage. Its close-out required a dashboard at the root folder, which a fan-out run never writes because each lineage keeps its own, so every finished fan-out run was logged as incomplete. The root dashboard is now required only for a run without lineages.

&nbsp;

#### Runs Stop Where You Asked

`--stop-policy=max-iterations` now keeps review confirm and both research workflows running to their ceiling. Research confirm also has its quality guards back, so it no longer stops without checking them.

## Editing in Pi

#### A Refused Edit Explains Itself

When Pi reads a file that ends with a newline, it numbers the empty string after that newline as a line. A model that took that line for an artifact asked `edit_lines` to replace one line too few, and the refusal said lines had been inserted or removed, so the model stopped. The `line_count` description and the edit guidance now tell the model to count that final empty line, as Pi's own read notices do. The count check stays exact, because accepting one short would hide a real one-line insertion. The refusal now names the final empty line and says a retry with the full count is safe only when the read's last numbered line was that empty line. An edit that passes line hashes must now pass one for every line in its range.

## Upgrade Notes

To write a goal for a packet, run `/create:goal <packet path>`. To add one to a packet that has none, run `/create:goal <packet path> retrofit`.

- **Goals between 3,000 and 4,000 characters now pass.** Nothing warns below the limit, and a goal past 4,000 still fails.
- **Existing goals keep their text.** A goal keeps its old author instructions until its next amendment or cut, and step 3 of the cut order removes them then.
- **Scripts that read the goal CLI's exit status.** `goal.cjs` exits 1 on every failure, where it used to exit 0.
- **Release notes moved.** A link to a Skilled release note under `.skilled/skills/system-spec-kit/changelog/` now belongs under `.skilled/changelog/skilled/`.
- **Codex hook copies.** Codex loads the repository hooks from `.codex/hooks.json` only for a checkout that `~/.codex/config.toml` marks as trusted, so trust the checkout first. Then run `node .skilled/bin/install-codex-hooks.mjs` once to remove the copies an earlier installer made in `~/.codex/hooks.json`. `--check` then prints `install-codex-hooks: OK`.
- **The advisor hook budget.** A `SPECKIT_CLAUDE_HOOK_TIMEOUT_MS` value above 2,200 now counts as 2,200.
- **An advisor daemon started before this release.** It rejects the hook's new `includeCompiledRoute` option, and the advisor command line retries once without it. Restart the daemon to end the retry.
- **Skill advisor changelog names.** The advisor's entries now carry four-part versions, so a link to `changelog/v0.5.0.md` now belongs on `changelog/v0.5.0.0.md`.
