# v4.0.0.2, A Steadier Skill Advisor, Findable Changelogs and Leaner Goals

v4.0.0.2 is mostly a release for the skill advisor. Its prompt hook suggests a skill before each prompt reaches the model, and it now holds up in every runtime that carries it. The work began as a comparison with the pi-skill-orchestrator extension, and running the advisor's own scenarios inside five CLIs found the rest.

A slow advisor no longer leaves a turn empty. The hook skips work nobody reads, says why a turn has no suggestion and sends every prompt over standard input. A healthy advisor no longer shuts itself down when a second launcher starts, and the move from `.opencode` to `.skilled` no longer costs a turn its suggestion.

Every changelog in the repository can now be found by version too. Each entry opens with the five keys a spec document carries, led by phrases that name its component and version, the search index reads the release notes folder and a validator blocks an entry that lacks the block. Asking for `sk-git v1.0.0.0` returns that entry first.

The goal a spec packet carries is cheaper to write, cheaper to send and harder to get wrong. A parent goal has one 4,000-character limit, `/create:goal` writes it and a sent goal carries only its directive.

Doc validation gains off switches that no longer trap commits, and the README now says what the git hooks block and how to get past them.

## Why This Release

The skill advisor's hook runs before every prompt, and real use showed three gaps in it. Its prompt hook paid on every prompt for routing work nobody read. A slow advisor left four runtimes with nothing, and a turn without a suggestion looked the same as an outage. A comparison with a Pi extension that lets the model search for a skill on demand then ranked what the advisor should adopt.

Changelogs had a gap of their own. Only 52 of the 542 skill changelog entries declared a search phrase, so the trigger index that Gate 1 and `/speckit:search` read held few of them.

Goals, doc validation and the git hooks each had a smaller gap. Nothing helped an author write a goal, so parent goals ran over budget and placeholders shipped. Switching doc validation off trapped every commit that staged a spec doc, and nothing a new user reads said the repository installs git hooks that block commits.

## What's New at a Glance

- **A slow advisor no longer empties the turn.** The shim stops the hook after 2,500 ms and gives it 2,200 ms for the advisor, and Pi races the call against the hook's budget plus 300 ms, so the fallback arrives first.
- **The hook does less on every prompt.** A casual prompt such as `/help` never reaches the advisor, and the hook no longer asks for a routing result it discards, which saved a median 65 ms per prompt.
- **A turn without a suggestion says why.** One line names an outage, a prompt that matched no skill or a skipped prompt, and a repeat in a known session shrinks from 244 bytes to 26 in a live run.
- **The move to `.skilled` stopped costing suggestions.** The hook's fast path had looked for its tools under the old root name and gave up in about 2 ms on every prompt. Pi and the OpenCode plugin cache had smaller faults from the same move, and a prompt such as "delegate this to pi" now routes.
- **Long prompts get a route and stay out of the process list.** Callers sent up to 64 KiB where the advisor accepts 10,000 characters, and every caller now sends the prompt over standard input.
- **The healthy advisor stays up.** A second launcher on the same database used to delete the live advisor's lease, and a sandboxed advisor now keeps every state file in its own folder.
- **Research against pi-skill-orchestrator.** The comparison ran across 15 phases and ranked what the advisor should adopt. Its larger ideas, such as a Pi skill-search tool, wait on replays or A/B tests that have not run.
- **Every changelog can be found by version.** Each entry declares five keys led by identity phrases, the index reads `.skilled/changelog/skilled/` and `validate_document.py` blocks an entry that lacks them.
- **Release notes have their own line and every history reads one way.** `.skilled/changelog/skilled/` holds one entry per Skilled release, system-spec-kit writes its own changelog again and older styles now read in the current format.
- **One limit, one command and one send rule for a goal.** A parent goal passes up to 4,000 characters and fails past it in every tool, `/create:goal` writes and checks it and a sent goal carries only its directive.
- **Goal commands fail loudly and goals behave on every runtime.** `goal.cjs` refuses an action it does not know, and live runs fixed defects in Hermes, Pi and OpenCode that no unit test had caught.
- **Doc validation can be switched off and the README explains the git hooks.** A switched-off run reports as skipped, never as a pass, and every hook block now names its bypass.

## The Skill Advisor

The skill advisor suggests a skill before each prompt reaches the model. Claude, Codex, Cursor and Devin run it through a hook shim, Pi runs it inside its own process and OpenCode runs it as a plugin. This release compared it with pi-skill-orchestrator, then ran its own test scenarios inside Pi, OpenCode, Devin, Cursor and Codex, and a two-model review with follow-up checks found more. Every defect below is fixed.

#### Research Against pi-skill-orchestrator

The comparison covered pi-skill-orchestrator, a Pi extension that lets the model search for a skill when it needs one instead of receiving a suggestion first. It ran as packet 030 in `system-skill-advisor` across 15 phases and ranked what the advisor should adopt. Most of the prompt hook changes below are ones it recommended.

Its larger ideas, such as a skill-search tool for Pi, wait on replays or A/B tests that have not run. The advisor's own changelog entries, `v0.11.2.0` and `v0.12.0.0` under `.skilled/skills/system-skill-advisor/changelog/`, hold the detail of each change.

&nbsp;

#### A Slow Advisor No Longer Empties the Turn

In Claude, Codex, Cursor and Devin the hook runs inside a shim that stops it after 2,500 ms. The hook gave its advisor call the same 2,500 ms, so a slow advisor ran into the shim's limit first and the turn got nothing, not even the fallback. The shim still stops the hook after 2,500 ms, and it now gives the hook 2,200 ms for the advisor and caps an operator's `SPECKIT_CLAUDE_HOOK_TIMEOUT_MS` at that value, so the fallback arrives first.

Pi runs the hook inside its own process and races the call against the hook's budget plus 300 ms, then falls back the same way. It also reads the budget the way the hook does, so a negative value no longer becomes a deadline already in the past that threw away a live suggestion.

&nbsp;

#### Less Work on Every Prompt

The check that keeps casual prompts away from the advisor had lost its only caller, so every prompt started an advisor call. The hook now runs that check first. `/help`, a short acknowledgement or a prompt with too little to route returns a skipped result before any call starts, and a replay over the labeled and golden prompt collections confirmed that the check turns away no prompt that should route.

The hook also asked the advisor for a compiled route, a precomputed routing decision for a skill hub, and then threw it away, because only the OpenCode plugin reads that route. `advisor_recommend` now takes `options.includeCompiledRoute`, which defaults to true, and the hook always sends false. That saved a median 65 ms per prompt on one build against one daemon. A daemon started before this release rejects the option, and the advisor command line then retries once without it.

&nbsp;

#### A Turn Without a Suggestion Says Why

A turn with no suggestion used to carry the bare fallback text, so the model could not tell an outage from a prompt that matched no skill or one the hook skipped. The fallback now opens with one line that names the case. An outage line names the command to route by hand, a no-match line says no skill matched and a skip line says the prompt was skipped.

That line also makes repeats cheap. Within a known session a repeated fallback shrinks to its first line, and in a live run five turns without a route sent the full 244 bytes once and 26 bytes after that. An unknown session, the kill switch and an error still get the whole text. The OpenCode plugin opens its fallback with the same line.

&nbsp;

#### The Move to .skilled Stopped Costing Suggestions

The advisor moved with the rest of the source tree from `.opencode` to `.skilled`, and three things kept the old name. The hook's fast path looked for its tools under the old root, so every prompt in every runtime that runs the hook gave up in about 2 ms with no suggestion. It now tries `.skilled` first and `.opencode` second, and takes its shim, bridge and database folder from the root it found.

Pi held back a delivery as a repeat whenever its directives matched the last one, even when the suggested skill had changed, and it now compares the whole delivery. The OpenCode plugin, started from a subfolder, hashed a skills folder that was not there, so its cached answers never noticed a skill change. It now finds the repository root first.

&nbsp;

#### Short Executor Names and Compiled Routes

The scorer dropped every word of two characters or fewer, so `pi` never counted and a prompt such as "delegate this to pi" got no suggestion at all. That prompt now gets `cli-external-orchestration` with a compiled route to `cli-pi`. Recommendations for `cli-jev` and `sk-design` also carry the hub's compiled route by default, as they already did for five other hubs.

&nbsp;

#### Long Prompts Get a Route and Stay Private

The callers sent up to 64 KiB of prompt where the advisor accepts 10,000 characters, so every longer prompt got the outage message. Every caller now sends at most the 10,000 characters, and a long prompt is routed on its opening.

The prompt used to travel on the command line, where any process list could show it. `skill-advisor.cjs` now reads it from standard input with `--json -`, and `compiled-route.cjs` does the same with `--prompt-stdin`.

&nbsp;

#### A Healthy Advisor Stays Up

A launcher treated a live advisor as abandoned when its parent process was gone. A second launcher on the same database then deleted the lease, and the healthy advisor shut itself down. A lease is now reclaimable only when its process is dead or its heartbeat is stale.

`SYSTEM_SKILL_ADVISOR_DB_DIR` now moves every state file with it. The generation file, the quarantine database, the launcher state and the model server all stay in that folder, so a test advisor can no longer mark the live advisor unavailable.

&nbsp;

#### OpenCode Loads the Plugin

OpenCode refused the advisor plugin because the file exported helpers beside the factory OpenCode expects. The plugin file now exports only its factory, and the helpers live in `.opencode/plugins/lib/skill-advisor-render.js`. OpenCode sessions get the suggestion and the status tool again. The status tool also reports compiled routing when the routing status sits under `.skilled/bin`.

&nbsp;

#### Repeated Transforms Stay Suppressed

With `deduplicateTransforms` on, the plugin shortened a repeated block to its first line before comparing it with the last block for the same message. A second transform for that message then missed the match and delivered the block again. The plugin now compares the full block first and shortens only a block it will deliver, and a parity test holds its fallback text to the hook's.

&nbsp;

#### Diagnostics Name the Real Runtime

A turn that runs the hook as a separate process lost its diagnostic record when the process exited, so the hook now waits up to 100 ms for pending log writes. Each record says which runtime ran the hook and how many bytes it delivered, and the logs are private to their owner.

`advisor_validate` now accepts outcome events from every runtime it knows: Claude, Copilot, OpenCode, Pi, Codex, Cursor and Devin. Events from Pi, Codex, Cursor and Devin were rejected before.

&nbsp;

#### Docs and Scenarios Say Only What They Check

The advisor's command inventory now lists `/create:goal`. Six scenarios now check only the signals their own command can show, such as reading a diagnostic from the diagnostics log rather than from output the shim never forwards. The two scenarios that start a sandboxed advisor clean up without sending a signal. The sandbox advisor exits after 12 idle seconds, and the scenario removes its folder only once nothing holds a file open there. All 45 scenario reruns across Pi, OpenCode, Devin, Cursor and Codex passed.

## Changelogs

Every changelog in the repository can now be found by component and version, the framework's release notes have a line of their own and every history reads in one format.

#### What Every Entry Now Declares

Every entry opens with the five keys a spec document carries: `title`, `description`, `trigger_phrases`, `importance_tier` and `contextType`. The trigger phrases are what a search matches against. The first ones are identity phrases that name the component and the version.

An entry for `sk-git` v1.0.0.0 declares `sk-git v1.0.0.0` and `sk-git 1.0.0.0`, and a Skilled release entry declares `v4.0.0.2 release notes` and `skilled v4.0.0.2`. One or two topic phrases follow, and they carry no version number. Only 52 of the 542 skill changelog entries had any search phrase before this release.

&nbsp;

#### How to Look One Up

A lookup matches the words you type against those phrases. Gate 1 runs one on every prompt. You can run one with `/speckit:search sk-git v1.0.0.0 --triggers`, which reads the trigger index. Without `--triggers` the command scans the words in the text instead of the phrases an author declared.

That lookup now ranks the `sk-git` v1.0.0.0 entry first with an exact match, and `v4.0.0.0 release notes` returns `.skilled/changelog/skilled/v4.0.0.0.md`.

&nbsp;

#### The Search Reads the Release Notes Folder

The index reads four roots: `specs`, `.skilled/skills`, `.skilled/hooks` and now `.skilled/changelog/skilled`. A component changelog sits inside its skill folder, so the skill root already reached it. The Skilled release notes moved out of the system-spec-kit folder, and the new root keeps a lookup such as `v4.0.0.0 release notes` working. Only that one folder joins, because the rest of `.skilled/changelog` is links and the index does not follow links.

&nbsp;

#### The Writers and the Validator Keep It That Way

The changelog writers produce the block, and `validate_document.py` blocks an entry that lacks any of the five keys. A version file must also carry a trigger phrase that contains its version, and the folder a file sits in decides which kind of document it is judged as.

The nested changelog generator, which writes a changelog for each spec packet, now gives every packet its own phrase built from its packet and phase names, where every packet changelog used to share the same fixed phrases. It also escapes the values it writes, so a quote in a spec title or a dollar sign in a summary no longer damages a packet changelog.

&nbsp;

#### Release Notes With a Home of Their Own

The system-spec-kit changelog had become the framework's release notes. Its v4 entries described the whole framework, and the skill's own history stopped at 3.9.0.0. The 45 release notes moved to `.skilled/changelog/skilled/`, one entry per Skilled release, and system-spec-kit writes entries about itself again. `/create:changelog skilled` writes a release entry, and only that line publishes a GitHub release. The command also resolves a hub such as `sk-doc` to its own changelog or to one mode's, where it used to find no version at all.

&nbsp;

#### One Format for Every History

Changelogs had been written in several older styles, so a skill's history read differently from one version to the next. Every entry written in an older style was rewritten in the current format, one skill at a time, the older Skilled release notes included. A fact check held each rewrite to what its original recorded, so every entry still says what shipped in its version, no more and no less.

## The Goal System

A packet's goal is now written by one command, measured by one limit, sent by one rule and served the same way on every runtime.

#### One Limit and One Boundary

A top-level or phase-parent `goal.md` used to warn past 3,000 characters and fail past 4,000. Every runtime goal surface caps at 4,000 or more and nothing caps at 3,000, yet the lower number read as the limit and goals were cut short of the real one. The warning tier is gone from the manifest, the validator, `goal.cjs`, the OpenCode plugin, the template, the playbook and the docs. Up to 4,000 characters passes, past it fails and the budget reads ok, over or unknown. Existing goals that quoted the old template sentence carry the new wording.

The tools that measured a goal also disagreed on which folders the limit covers, so a nested phase parent failed the validator past 4,000 while `goal.cjs` reported unknown. Section 2 of the create-goal mode's `references/budget-and-handoff.md` now states one boundary. The limit applies to a top-level packet and to every phase parent, nested or not, and exempts only a phase child that is not itself a phase parent. The validator, `goal.cjs` and `check-goal.cjs` draw that same line.

&nbsp;

#### A Command That Writes Goals and a Checker

`sk-doc` gains the create-goal mode and its `/create:goal` command. It writes a top-level, phase-parent or phase-child goal from the packet's own documents, amends an existing goal and retrofits one onto a packet that has none. Each kind starts from its own template in the mode's `assets/` folder, and a parity test fails when a template drifts from system-spec-kit's `goal.md.tmpl`. The mode never sets or resends a session goal, which stays with the goal hooks.

`check-goal.cjs` is read-only and runs five checks. It flags a phase the parent never bound, a placeholder left from the template, a criterion count outside three to seven, a parent over budget and a `---` line that closed the frontmatter early. `/create:goal` hands back the parent's chat slice only after the checker passes, so an open finding ends the run without one. The command also refuses a packet path outside its workspace and treats packet prose as data rather than instructions.

&nbsp;

#### A Sent Goal Carries Only Its Directive

Section 4 of `budget-and-handoff.md` is now the one rule for a goal sent in chat. A sent goal never carries frontmatter, HTML comments, anchor markers, `---` dividers, heading section numbers or author instructions. It goes out only at `packet_budget=ok`, and the 4,000-character limit is measured on the durable slice, the goal text between its frontmatter and its log. `AGENTS.md`, system-spec-kit's `SKILL.md`, the set-string playbook, five speckit workflows and the resend reminder point to that section instead of restating it.

The blockquote, the Operator copy section and the criteria introduction are gone from system-spec-kit's `goal.md.tmpl` and from the create-goal mode's three templates, because that text went out with every sent goal. A `GOAL_AUTHORING` comment in each template points to the mode instead. An unfilled phase-parent template fell from 3,156 to 1,624 durable characters and from 2,823 to 1,218 in chat. Section 3 of `budget-and-handoff.md` is the one cut order for a parent over budget, and its new step 3 removes instructions an older template left behind.

&nbsp;

#### One Home for Goal Authoring in the Docs

system-spec-kit kept its own goal-nesting rules, and none of its phase entry points named the create-goal mode. The speckit `:with-phases` step, Option D in plan and complete, `phase-definitions.md`, `phase-system.md`, the quick reference and the `create.sh` help and next steps now send goal authoring to `/create:goal`. A retrofit has one path, `/create:goal <packet path> retrofit`, and the validator's two goal findings name their fix in the create-goal mode.

Two claims in the docs were also wrong. `create.sh --phase --with-goal` writes child goals only, and `--level phase-parent --with-goal` writes the parent goal. The runtime injects the objective slice on every turn, a pointer to `goal.md` with the binding rule for a phased packet and the completion criteria, rather than the whole durable slice. Every surface that said otherwise now matches.

&nbsp;

#### Goal Commands That Fail Loudly

`goal.cjs` used to store `goal.cjs --help` as an objective and exit 0 on every failure. It now refuses an unknown action with `UNKNOWN_ACTION` and exits 1 whenever it fails. The frontmatter match no longer backtracks either. A goal file that opened with 26 comments took 12.6 seconds to parse and stalled every hook render, and one with 2,000 comments now parses in milliseconds. The resend reminder stays on one line, and a packet path that does not exist yet is judged by where its real parent lands.

&nbsp;

#### Goals on Every Runtime

Each runtime without a native goal command was run live. Every defect found there is fixed at its source with a test that fails on the old code.

- **Hermes** injected its raw goal report, which was cut off before the brief. It also rendered the goal before the session had bound it. It now binds the session through the shared goal core and injects the rendered brief.
- **Pi** sent its turn-end nudge while a run was still streaming, which restarted a finished `pi -p` run that then worked on for 18 minutes. The nudge now rides the next user prompt and starts no turn. The completion-evidence advisory had the same defect and now waits the same way.
- **OpenCode** sanitized a bound folder's path, so binding a folder whose name held a line break reported success and bound nothing. It now keeps the path as written and re-checks it on every read.

The OpenCode, Pi, Devin and Hermes playbooks now describe what their runtime really does. The session-goal redirect no longer names `/goal-cursor`, which refuses session actions.

## Doc Validation and Git Hooks

Anyone who does not care whether their docs match this repository's formats can now turn validation off, and a run that was switched off never passes for one that checked. The README also says, for the first time, what the git hooks block.

#### Validation You Can Switch Off

`SPECKIT_SKIP_VALIDATION` existed but trapped commits. With it set, `validate.sh --json` printed nothing, so the pre-commit metadata gate read every staged spec folder as unreadable and blocked the commit. sk-doc's validators had no off switch at all. Now `SPECKIT_SKIP_VALIDATION` turns spec folder validation off and `SKDOC_SKIP_VALIDATION` turns off all twenty sk-doc format validators. Either one can be set in the environment or saved in `.skilled/hooks/hook-flags.env`, and a set environment value wins, even `0`.

A switched-off validator prints one notice naming where the switch was set and exits 0, and a caller that asked for JSON still gets JSON. The tools that write, such as `validate_document.py --fix`, keep running. CI never sets either switch, so the repository's own formats stay enforced.

&nbsp;

#### A Skipped Run Never Passes for a Checked One

A review of the switches found three local tools that read a skipped run as a pass. `progressive-validate.sh --json` mixed the skip notice into its output, so at level 1 the output did not parse. `quality-audit.sh` counted any exit 0 as a pass, and the strict-pass freshness sweep did the same. The wrapper now keeps the notice on stderr and reports `skipped: true`. The audit counts a skipped folder apart, and the sweep gives it a `skipped` status that a later baseline never mistakes for a known failure.

&nbsp;

#### Every Reader of the Flags File Agrees

Four programs read `hook-flags.env`: the Node and shell hook resolvers, sk-doc's Python helper and the dist freshness checker. The example file puts a comment after each value, and the readers took that comment as part of the value, so a line uncommented as the docs say did nothing. A `#` after a space or tab now ends a value in all four.

The review found three smaller splits. The shell reader deleted spaces inside a value, so `o n` read as on, and it could mistake one exact value for an unset variable. The shell reader and the dist checker also kept a byte order mark (an invisible mark some editors save before the first line) on the first switch name. All four readers now trim only a value's edges, let any set environment value answer and drop the mark.

&nbsp;

#### The Validator Judges Only What It Should

`validate_document.py` held two kinds of file to standards they were never meant to meet. `AGENTS.md` is the operating contract every runtime loads at startup, so a section added only to satisfy the validator would load into every session. A surface packet (reference material a hub bundles beside a mode) has none of a mode's sections. The validator now skips `AGENTS.md` unless `--no-exclude` asks for it, and it checks a surface packet against the sections a surface packet has.

&nbsp;

#### The README Explains the Git Hooks

The first AI session in a fresh clone installs git hooks that can block a commit or a push, and until now nothing a new user reads said so. The README's Quick Start now has a Git Hooks section. It says what installs the hooks and what pre-commit, commit-msg and pre-push each block. It also gives the two commands that remove the hooks and keep the next session from putting them back.

&nbsp;

#### Every Block Names Its Way Through

Seven block messages in the commit-msg and pre-commit hooks said what was wrong without saying how to get one commit past it. Each now ends with the variable that lets that one command through, such as `SPECKIT_SKIP_COMMENT_HYGIENE=1 git commit ...`. The agent mirror gate has no switch of its own, so its message names `SYSTEM_GIT_COMMIT_HOOKS_DISABLED=1` and says that this turns off every pre-commit gate.

&nbsp;

#### One Section for Every Off Switch

The off switches for hooks, validators and git hooks were spread over three READMEs and `.env.example`. The README's Configuration section now has an Off Switches section that names each group, says which ones `hook-flags.env` can hold and links the full lists. `.env.example` opens by saying where its switches are read, since only Code Mode loads a `.env` file, and its git hook list now names every bypass the hooks read.

&nbsp;

#### A Contributing Guide for This Repository

`CONTRIBUTING.md` still called the project OpenCode Dev Environment and cloned a URL the repository no longer uses. It now names Skilled, clones `skilled-agent-harness_spec-driven-loops` and states the commit rules the commit-msg hook enforces, such as the required scope and the body a commit of four or more files needs.

## Runtimes, CLIs and Deep Loops

Cursor gains Grok 4.7, and six fixes reach the runtimes, the CLIs that run delegated work and the deep loops.

#### Codex Runs Each Hook Once

Codex already loads a trusted checkout's own `.codex/hooks.json`, and the hook installer also copied every repository hook into the user-wide `~/.codex/hooks.json`. Each Codex event ran each hook twice, and the copies ran this repository's hooks in Codex sessions started anywhere. The installer now only removes those copies and keeps every third-party entry.

&nbsp;

#### Hermes Skill Copies Link to Real Files

Hermes reads each skill from a generated copy in `.hermes/skills/`. The copies kept every relative link exactly as the original wrote it, so each one pointed at a file beside the copy that did not exist, 530 broken links in all. The generator now rewrites each relative link to reach the original file, and it leaves web addresses, in-page anchors and code untouched.

&nbsp;

#### A Refused Pi Edit Explains Itself

When Pi reads a file that ends with a newline, it numbers the empty string after that newline as a line. A model that took that line for an artifact asked `edit_lines` to replace one line too few, and the refusal said lines had been inserted or removed, so the model stopped. The `line_count` description and the edit guidance now tell the model to count that final empty line, as Pi's own read notices do. The count check stays exact, because accepting one short would hide a real one-line insertion. The refusal now names the final empty line and says a retry with the full count is safe only when the read's last numbered line was that empty line. An edit that passes line hashes must now pass one for every line in its range.

&nbsp;

#### Grok 4.7 Runs Through Cursor

Eight Grok 4.7 models joined the list of Cursor models a deep loop may send work to, after a live test run confirmed each one. They are `grok-4.7-low`, `grok-4.7-medium`, `grok-4.7-high` and `grok-4.7-xhigh`, each with a `-fast` twin, and the cli-cursor skill's model roster names them.

&nbsp;

#### cli-jev Answers the Phrasings It Advertises

cli-jev asks the Jev command-line tool for a judgment: a probability, a choice between options or a score. Its router passed on six of the eight phrasings the skill says it answers, such as "ask jev for a probability", because it only recognized jev next to a subcommand. It now recognizes ask jev, use jev, with jev and through jev, so those phrasings reach it.

&nbsp;

#### Fan-Out Runs Close as Complete

A deep-loop fan-out run splits one research topic or one review across several models, each in its own lineage. Its close-out required a dashboard at the root folder, which a fan-out run never writes because each lineage keeps its own, so every finished fan-out run was logged as incomplete. The root dashboard is now required only for a run without lineages.

&nbsp;

#### Deep Loops Stop Where You Asked

`--stop-policy=max-iterations` now keeps review confirm and both research workflows running to their ceiling. Research confirm also has its quality guards back, so it no longer stops without checking them.

## Upgrade Notes

To find a changelog entry by version, run `/speckit:search <component> v<version> --triggers`. To write a goal for a packet, run `/create:goal <packet path>`, and to add one to a packet that has none, run `/create:goal <packet path> retrofit`.

- **Anything that names the old advisor path.** A link or script that names `.opencode/skills/system-skill-advisor/` now belongs under `.skilled/skills/system-skill-advisor/`.
- **The advisor hook budget.** A `SPECKIT_CLAUDE_HOOK_TIMEOUT_MS` value above 2,200 now counts as 2,200.
- **An advisor daemon started before this release.** It rejects the hook's new `includeCompiledRoute` option, and the advisor command line retries once without it. Restart the daemon to end the retry.
- **Prompt length.** The advisor accepts 10,000 characters of prompt, and its callers pass the prompt over standard input with `--json -`.
- **A test advisor's state.** Set `SYSTEM_SKILL_ADVISOR_DB_DIR` and every state file, the model server included, stays in that folder.
- **Skill advisor changelog names.** The advisor's entries now carry four-part versions, so a link to `changelog/v0.5.0.md` now belongs on `changelog/v0.5.0.0.md`.
- **Release notes moved.** A link to a Skilled release note under `.skilled/skills/system-spec-kit/changelog/` now belongs under `.skilled/changelog/skilled/`.
- **Codex hook copies.** Codex loads the repository hooks from `.codex/hooks.json` only for a checkout that `~/.codex/config.toml` marks as trusted, so trust the checkout first. Then run `node .skilled/bin/install-codex-hooks.mjs` once to remove the copies an earlier installer made in `~/.codex/hooks.json`. `--check` then prints `install-codex-hooks: OK`.
- **Goals between 3,000 and 4,000 characters now pass.** Nothing warns below the limit, and a goal past 4,000 still fails.
- **Existing goals keep their text.** A goal keeps its old author instructions until its next amendment or cut, and step 3 of the cut order removes them then.
- **Scripts that read the goal CLI's exit status.** `goal.cjs` exits 1 on every failure, where it used to exit 0.
- **Turning doc validation off.** Set `SPECKIT_SKIP_VALIDATION=1` or `SKDOC_SKIP_VALIDATION=1` in the environment, or save it in `.skilled/hooks/hook-flags.env`. A skipped run exits 0 and says so, and it is no evidence that a document is valid.
- **`SPECKIT_SKIP_VALIDATION` takes truthy values only.** Any non-empty value used to skip. Now only `1`, `true`, `yes` or `on` do.
- **Saved flags with a comment after the value.** A line such as `SYSTEM_DIST_FRESHNESS_DISABLED=1  # note` in `hook-flags.env` now takes effect in every reader. Comment the whole line out to keep a switch off.
- **Scripts that read the quality audit or the freshness sweep.** A switched-off folder now reports `skipped`, where it used to count as a pass.
