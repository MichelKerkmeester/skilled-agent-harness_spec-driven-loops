# v4.0.2.2, One Main Name for Session Handover

This release gives the feature its main name, session handover. The feature used to be called session relaunch. It now uses session handover on every live surface.

This is a breaking change. Anyone who set an old switch must act. The Upgrade Notes list each action.

> Spec folder: `specs/hooks-plugins-extensions/session-turn-boundaries/002-session-relaunch-loop/044-in-session-handover-rename`

&nbsp;

## Why This Release

Every surface now uses one main name. The docs, the switches, the hook folder and the seed match. That makes the feature easier to find and to talk about.

&nbsp;

## What's New at a Glance

- **One main name now covers the whole feature.** The hook folder, the switches, the seed and the docs all say session handover. <!-- section: Names, Switches and State -->
- **The old switch names are no longer read.** Rename each one to its new name. Until then, its setting does nothing. <!-- section: Names, Switches and State -->
- **The in-session spelling works as a second name.** It answers for a switch only while the main name is unset or blank. <!-- section: Names, Switches and State -->
- **A new session starts on the new seed.** The first prompt now opens with the new name. <!-- section: Names, Switches and State -->
- **A typed session handover reaches the handoff command.** The skill advisor now names `/speckit:handoff`. <!-- section: Skill Advisor -->
- **An installed project must render its hooks again.** Until then, its registrations name the old hook folder. <!-- section: Installed Projects -->

&nbsp;

## Names, Switches and State

#### Every Live Surface Says Session Handover

The hook folder is now `.skilled/hooks/session-handover/`. The plugin files and the docs use the same name. The global switch is `SYSTEM_SESSION_HANDOVER_ENABLED`. Each runtime has its own switch, such as `SYSTEM_SESSION_HANDOVER_CODEX_ENABLED`. Tuning variables carry the `SESSION_HANDOVER_` prefix, such as `SESSION_HANDOVER_THRESHOLD`.

#### Old Switch Names Are Ignored

**Breaking:** A switch under an old name is ignored, because the old names have no alias. A Claude Code user who had switched handover off gets it back. It stays on until you set the new switch to 0.

#### The In-Session Spelling Also Works

The switches also accept `SYSTEM_IN_SESSION_HANDOVER_*` as a second spelling. That covers the enable, disable and per-runtime enable switches. It answers only while the main switch is unset or blank, so the main name wins when both hold a value. Tuning variables have no second spelling. `/doctor:env` names the conflict when both hold different values. The main switch decides.

#### Open Handoff Notes Need a Move

**Breaking:** An open handoff note in the old state folder is not found. The folder is git-ignored runtime state. Move it by hand in each checkout.

#### A New Session Starts on the New Seed

The seed is the first prompt in a new session. It now opens with `[session-handover] claim and continue handoff`. The user sees that line first.

#### History and Bare Relaunch Names Stay

Changelogs and spec folders keep the old name. They record what shipped. Bare relaunch names stay too. They are `relaunch.log`, the `skilled-relaunch` folder and the `skilled-loop` wrapper. When `XDG_RUNTIME_DIR` is set, the folder sits under it.

&nbsp;

## Skill Advisor

#### A Typed Session Handover Reaches the Handoff Command

Typing session handover, in session handover or session-handover in a prompt now leads the skill advisor to `/speckit:handoff`. Before this release, none of the three named a command.

&nbsp;

## Installed Projects

#### Hook Registrations Need One Render

A project that installed Skilled still has hook registrations. They name the old hook folder. Until they are rendered again, a hook that names the missing file prints a drift notice.

&nbsp;

## History Lookup Moves to the Handover

#### The Offer Follows the Claim

The history lookup is now offered when a session claims a handoff note, not after a compaction. `prepare` stores a locator for the sending session, and `claim` mints a fresh one, good for 30 minutes, and prints a `## History Lookup` section after the note body. Only Claude Code and Codex senders get one, and the section is withheld when the sender has no transcript, when the note names another runtime, when the sender ran in another checkout, or when the runtime is not built, and the claim then prints what it printed before. Compaction hooks no longer mint a locator or print the section on any runtime, and the OpenCode plugin is gone. Compaction summaries and `/speckit:resume` are unchanged, and replies stay capped and read-only. The shared Claude transcript reader now reads one message written as several lines as one turn, which stopped the lookup from refusing sessions that ran tools in parallel.

## Upgrade Notes

- **If you set a `SYSTEM_SESSION_RELAUNCH_*` or `SESSION_RELAUNCH_*` variable:** rename it in your shell profile or `hook-flags.env` by replacing `SESSION_RELAUNCH` with `SESSION_HANDOVER`. For example, `SYSTEM_SESSION_RELAUNCH_ENABLED` becomes `SYSTEM_SESSION_HANDOVER_ENABLED`. The old names are not read. Claude Code still hands over by default without any setting.
- **If you have an open handoff note:** move `.skilled/skills/.state/session-relaunch/` to `.skilled/skills/.state/session-handover/` in each checkout. Until you move it, the note is not found.
- **If anything matches the seed:** use `[session-handover] claim and continue handoff`.
- **If Skilled is installed in your project:** run `node .skilled/skills/system-spec-kit/runtime/cli/runtime-mirrors/sync-hook-registrations.cjs` from the project root. It rewrites `.claude/settings.json` and `.codex/hooks.json`. Add `--check` to check for drift without writing.
