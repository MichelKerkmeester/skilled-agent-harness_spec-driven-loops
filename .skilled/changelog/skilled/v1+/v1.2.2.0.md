This release fixes 34 bugs. 30 parallel agents found them while auditing Spec Kit v1.2.x. It is a comprehensive remediation. Every P0, P1 and P2 issue is resolved.

The fixes reach core infrastructure and the scoring modules. They also reach the extractors, the templates and the memory commands. They reach the skill documentation, error handling, shared utilities and the embedding providers. The release focuses on fixing important problems and explaining the results in clearer terms.

## Why This Release

The goal is to make the workflow easier to follow and easier to trust. The reliability fixes reduce confusing failures. They make the system more dependable. The template and documentation fixes make the instructions easier to read. They also make them easier to trust.

## What's New at a Glance

- **The vector index schema version is corrected, and so are two query error codes.** Each of those two error codes now has a number of its own.
- **Tier scoring is consistent.** It uses only valid tier names.
- **Provider identification is added.** Each embedding provider can now report its name.
- **Extractor crashes and process exits are fixed.** Where the extractors exited, they now throw an error.
- **The prediction error gate detects contradictions better.** It raises fewer false positives.
- **Templates follow the progressive inheritance chain.** Level 3 templates now correctly inherit the L2 addendum content.
- **Template formatting is fixed.** Section numbering and separators are corrected.
- **Memory commands use the full `spec_kit_memory_` tool prefix.** Tool prefixes are now standardized across the commands.
- **The skill documentation's tool table grows.** It lists 22 tools, up from 14.
- **Documentation details are corrected.** The template line counts and the decision format path are both fixed.

## Core, Scoring and Providers

#### Schema Version and Error Codes Fixed

The vector index had a schema version mismatch. Its schema version moves from 9 to 11.

`QUERY_TOO_LONG` changes from E040 to E042. `QUERY_EMPTY` changes from E041 to E043. Their old codes were duplicates.

&nbsp;

#### Scoring Uses Only Valid Tiers

Folder scoring's `TIER_WEIGHTS` were inconsistent with the authoritative importance tiers. They are now aligned with them. The composite scoring multipliers named "high" and "low" tiers. Those tiers do not exist, and both multipliers are removed. The five factor scoring test now uses valid tier names as well.

&nbsp;

#### Providers Identify Themselves

All 3 embedding providers gain a `getProviderName()` method. The README's API documentation for `process_with_retry()` did not match the function's actual parameters. It is fixed to match them.

---

## Extraction and Error Handling

#### Extractors Throw Errors Instead of Exiting

Null values in `collected_data` and `observations` could crash the file extractor. It now runs defensive null checks on both. The exits were `process.exit(1)` calls in the file extractor and the diagram extractor. Each is now `throw new Error()`.

An error message in the workflow is also improved. It now carries actionable guidance.

&nbsp;

#### Sharper Phrase and Contradiction Matching

Two helpers join the prediction error gate. They are `hasWholeWord()` and `areTermsInSameContext()`. The trigger extractor's deduplication logic also changes. It now prefers longer, more specific phrases over shorter ones.

---

## Templates

#### Templates Follow the Inheritance Chain

The checklist carried L3+ sections. Those sections belong only in `level_3+`, and they are removed from it. The template source comments are updated to reflect the inheritance chain.

&nbsp;

#### Section Numbers and Separators Fixed

The spec template numbered its OPEN QUESTIONS section 10. It is now section 7. The L2 and L3 templates used a doubled separator, `------`. It is fixed to `---`.

---

## Commands and Documentation

#### Complete Tool Names and Tables

The context, manage, save and learn commands carry the full prefix. They carry it in their MCP Matrix tables and allowed-tools lists. Eight missing tools join the skill documentation's tool table: `memory_context`, `task_preflight`, `task_postflight`, `memory_drift_why`, `memory_causal_link`, `memory_causal_stats`, `memory_causal_unlink` and `memory_get_learning_history`.

&nbsp;

#### Line Counts and Paths Corrected

The skill documentation's template line counts did not match the actual sizes. They now read 450 for L1, 890 for L2 and L3 and 1080 for L3+. The decision format path now points to the `validation/` subfolder.
