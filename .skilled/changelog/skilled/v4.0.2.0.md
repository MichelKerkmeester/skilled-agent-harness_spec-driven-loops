# v4.0.2.0, DeepSeek Harness Joins and Hermes Leaves

DeepSeek Harness (`dsh`) is a command-line agent that runs DeepSeek models. It joins the CLIs the framework can hand work to, and a deep-research or deep-review run can use it as one of its parallel workers, called lineages. The mode is experimental. Its LLM Gateway route has answered a real run with an API key, and its OpenCode Go route is set up but not yet proven.

An interactive `dsh` session now gets the same hooks Pi and OpenCode get: the skill-advisor brief, goals, session-start checks, context after compaction, the overlay guard and live decision capture. A parallel worker keeps every guard and skips the parts that would change your goals or saved state.

Hermes Agent leaves. Its executor mode, its `.hermes/` runtime folder and its hooks are gone, so the hub routes seven CLIs.

A new `system-skilled-doctor` skill owns the commands that put Skilled into a project. Its `/doctor:overlay` keeps the local changes a project made to its own copy of Skilled when that copy moves to a newer upstream commit. ClickUp's divider clean-up now runs in a browser you are already logged in to.

> Spec folders: `specs/cli-external-orchestration/085-cli-deepseek-harness-creation`, `specs/cli-external-orchestration/086-cli-hermes-deprecation`, `specs/system-skilled-doctor/001-skill-and-overlay-build`, `specs/mcp-tooling/026-clickup-doc-divider-spacing`, `specs/sk-doc/055-changelog-system/005-concise-release-format` and `specs/sk-code/019-surface-consistency-research`, with smaller packets for the fixes

&nbsp;

## Why This Release

DeepSeek models were reachable only through another CLI's provider list, with none of the dispatch rules or guards the other bridges carry. A project that copies Skilled into its own tree lost every local change on the next copy unless someone replayed it by hand, and nothing stopped an edit to a file that the next copy would overwrite.

ClickUp's clean-up pass ran in an isolated browser, so ClickUp asked for a login on every run. Hermes Agent kept a 177-file runtime folder in step through 553 commits, yet its own session log shows five interactive sessions and none after 2026-10-25.

&nbsp;

- **DeepSeek Harness joins the CLIs.** Thirteen dispatch rules check every run, and the LLM Gateway route is verified. <!-- section: DeepSeek Harness -->

## DeepSeek Harness

#### A New CLI You Can Hand Work To

`cli-deepseek-harness` sends one task to `dsh` with three small config files that `dsh` calls patches. The route patch picks the provider and model, the lineage patch switches off features an unattended run must not use and the guards patch loads the shared safety checks. A run counts as complete only when it exits 0 and its last event says `completed`. Requests that name the harness route to it, and "use cli-opencode with deepseek-v4.1-flash" still goes to `cli-opencode`.

#### Two Routes, One of Them Verified

LLM Gateway `deepseek-v4.1-flash-1017` answered a real run with an API key on 2026-11-06 and is the default. OpenCode Go serves the same model, but a run uses it only when asked by name until a keyed run proves its endpoint.

#### Thirteen Rules Refuse an Unsafe Dispatch

Every `dsh` command is checked before it runs. It must name one of the listed routes with the lineage and guards patches, use a disposable home outside the checkout, run from outside the repository root and find `dsh` on your `PATH`. MCP stays opt-in. A start folder or home written as `$REPO` counts as the checkout, so it is refused like the literal path.

#### Deep Loops Can Run on It

Deep research and deep review can run `dsh` as one of their parallel workers. Two live runs completed on the LLM Gateway route, and a scan of the second found no writes outside its own folder.

## DeepSeek Harness Sessions

A session started with the guards patch and no lineage patch, such as `dsh web`, is interactive. A parallel worker adds the lineage patch, which marks it as a run with nobody at the keyboard.

#### The Advisor Briefs Interactive Sessions

An interactive session gets the skill-advisor brief on each prompt, as Pi and OpenCode do. A parallel worker gets none, because its prompt is a fixed task and a route suggestion would be noise.

#### Goals Work From Inside the Session

`/goal-dsh` and the `dsh_goal` tool run the shared goal command, so a goal set here is the same record every other runtime reads. `DSH_SPEC_FOLDER` brings a packet's goal into the session.

#### Checks at Start and a Save at Close

An interactive session runs six warn-only checks at start, such as the worktree and stale-build warnings. Every session gets its working context back after the conversation is compacted, and an interactive one saves where it left off when it closes.

#### Guards and Decisions Match the Other Runtimes

The overlay guard refuses a write to a file an overlay owns. Answers you give through `ask_user_question` are queued live, a late reply to a timed question included, and `/speckit:save` runs `sweep-dsh.mjs` to recover any answer the live capture missed.

#### Adapters Live in the Hook Library

Each `dsh` adapter now sits beside its hook core under `.skilled/hooks/` or in its owning skill's `hooks/dsh/` folder, the layout Pi uses. The bundle keeps one link per adapter, and `/doctor:runtime-mirrors` reports a missing or stale link.

#### Smaller Fixes

- **The spec gate reads only your prompt.** It classifies what the operator typed and never a guard notice or context snapshot the session added.
- **The advisor knows it is talking to `dsh`.** The adapter reports `dsh` instead of `pi`, and the advisor accepts that runtime label.
- **Parallel workers lose the native goal tools.** `create_goal`, `get_goal` and `update_goal` need a human turn a worker never has, so the lineage patch turns them off.
- **A running session keeps its MCP helpers.** The orphan sweeper treats a live `dsh` session, headless or web, as live and leaves its helpers alone.
- **`/doctor:git setup` checks DSH.** It accepts `--tool dsh` and confirms the DSH git-preflight advisory is registered.

## Hermes Agent Removed

#### The Executor and Runtime Folder Are Gone

**Breaking:** `cli-hermes` is no longer a mode, and deep loops reject it as an executor. The `.hermes/` folder is deleted with its skill copies, prompt templates and `repo-guards` plugin, and a request that names Hermes now routes nowhere.

#### Hooks and the Launcher Drop It

Session relaunch, the dispatch rules, the orphan sweeper and the pre-commit mirror checks no longer know a `hermes` runtime. `skilled-loop` no longer defines a `hermes` shell function, and AGENTS.md no longer describes Hermes personas.

## Skilled in Your Project

#### One Skill Owns the Doctor Commands

Ten doctor commands about putting Skilled into a project were credited to `system-spec-kit` or `sk-doc`, so an install request could land on the skill for spec folders. `system-skilled-doctor` now owns them, and each doctor job routes to its own command.

#### Overlays Keep Your Changes

A project that keeps its own copy of Skilled in its tree, a vendored copy, now keeps its local edits in an overlay folder. `/doctor:overlay status` reports their state without writing anything, and `/doctor:overlay apply` writes them back after an update.

#### Updating the Copy Has a Way Back

`/doctor:overlay repin` moves a vendored copy to a newer upstream commit in one guarded run. It refuses while a file no overlay covers differs from the commit the copy came from, and it backs up every path before its first write. It shows the same run staged on a copy as its plan before it writes, and `--rollback <run-id>` restores a run byte for byte.

#### Edits to Owned Files Are Refused

The overlay-guard hook checks each file a pending write names and refuses one an overlay owns, naming the overlay file to edit instead. A repository with no overlay folder pays two file checks and nothing more.

## ClickUp

#### The Gap Pass Uses Your Logged-In Browser

ClickUp keeps its login only for the browser session, so an isolated browser asked for a login on every run. The divider pass now runs in a background tab of Aside, or of your own Chrome through the new `chrome_devtools_live` manual, and your active tab stays in view. A long page in Aside now runs in short calls, so the 30-second limit on each tool call no longer cuts off the report.

#### Approval and Login Are Checked First

Before the first ClickUp write of a session, a readiness check reports whether the ClickUp MCP is approved and whether ClickUp is logged in, and asks you about each missing piece.

#### Smaller Fixes

- **A clean page reads as clean.** The leftover count comes from the editor, so an image at the end of a block no longer counts as a gap.
- **Only its own tabs close.** Both programs close the tab they opened, even after an error, and never a tab you had open on the same page.

## Docs and Tooling

#### Changelogs Follow a Concise Format

Large releases produced entries as long as the 500-line v4.0.0.0 model. The changelog template now takes length and selection from v4.0.1.0, caps an expanded entry at 240 lines and 26 items and adds a Smaller Fixes list. A shape check stops a draft that breaks a ceiling, and it reads glance order from section comments a reader never sees.

#### Each Runtime Folder Has a README

`.claude/`, `.codex/`, `.opencode/`, `.cursor/`, `.pi/`, `.devin/` and `.dsh/` each have a README that separates what is generated from `.skilled/` from what is authored there and names the command that checks its mirrors.

#### Every Hook Folder Explains Itself

Each folder under `.skilled/hooks/` and the `dsh` guards bundle now has a README saying what each file does, which event it answers and what happens when it fails. The hook library's own docs list every runtime's adapter, `dsh` included.

#### Smaller Fixes

- **A security patch for the spec-kit lock.** `@hono/node-server` resolves to 2.1.6, past the affected 2.1.1.
- **Hyphenated workflow names route.** A request that names `deep-review` or `deep-research` with its hyphen reaches the deep-loop hub, even when it mentions docs.
- **The router-sync guard sees every surface.** It reads `sk-code`'s surfaces from the mode registry, so a new one is checked.
- **README badges pass the render check.** A badge no longer warns as a bare URL.
- **Go code in templates reads as code.** The voice scan no longer counts semicolons inside a Go fence.

Each touched skill and mode has its own changelog entry, in cli-classifier (cli-jev), cli-external-orchestration (cli-deepseek-harness), mcp-tooling (mcp-aside-devtools, mcp-chrome-devtools, mcp-click-up), sk-code, sk-doc (sk-create-changelog, sk-create-readme, sk-create-skill), sk-git, sk-prompt, system-deep-loop with its runtime, system-skill-advisor, system-skilled-doctor and system-spec-kit.

## Upgrade Notes

- **To dispatch to `dsh`:** install `dsh` on your `PATH` and export `LLMGATEWAY_API_KEY`. Never put a key in the repository `.env`.
- **To run an interactive `dsh` session:** pass a route patch and `.dsh/patches/guards.patch.yml` without the lineage patch, and set `DSH_SPEC_FOLDER` to bind a packet goal.
- **A project that vendors Skilled:** move your local edits into an overlay folder, then run `/doctor:overlay status` and `/doctor:overlay apply`. Read the staged plan `/doctor:overlay repin` shows before you let it write.
- **ClickUp through your own Chrome:** add the `chrome_devtools_live` manual from `.utcp_config.json`.
- **If you used Hermes Agent:** open a new shell so the `hermes` function is gone, and remove `repo-guards` from `plugins.enabled` in `~/.hermes/config.yaml`. Your `~/.hermes/` install itself is untouched.
- **To pick up the security patch:** run `npm ci` in `.skilled/skills/system-spec-kit`.
