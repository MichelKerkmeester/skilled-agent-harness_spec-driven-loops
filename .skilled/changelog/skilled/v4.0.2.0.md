# v4.0.2.0, DeepSeek Harness Becomes the Eighth CLI

DeepSeek Harness (`dsh`) is a command-line agent that runs DeepSeek models. It joins as the eighth CLI the framework can hand work to, and a deep-research or deep-review run can bind it as a lineage. The mode is experimental. Its LLM Gateway route passed a keyed run, and its OpenCode Go route is configured but not verified.

An interactive `dsh` session now gets the same hooks Pi and OpenCode get: the skill-advisor brief, goals, session-start checks, context after compaction, the overlay guard and live decision capture. A fan-out lineage keeps every guard and skips the parts that write your state.

A new `system-skilled-doctor` skill owns the commands that put Skilled into a project, and its `/doctor:overlay` keeps a vendored copy's own changes when you move to a newer upstream commit. ClickUp's divider clean-up now runs in a browser you are already logged in to.

> Spec folders: `specs/cli-external-orchestration/085-cli-deepseek-harness-creation`, `specs/system-skilled-doctor/001-skill-and-overlay-build`, `specs/mcp-tooling/026-clickup-doc-divider-spacing`, `specs/sk-doc/055-changelog-system/005-concise-release-format` and `specs/sk-code/019-surface-consistency-research`, with smaller packets for the fixes

&nbsp;

## Why This Release

DeepSeek models were reachable only through another CLI's provider list, with none of the dispatch rules or guards the other bridges carry. A project that copies Skilled into its own tree lost every local change on the next copy unless someone replayed it by hand, and nothing stopped an edit to a file that the next copy would overwrite.

ClickUp's clean-up pass ran in an isolated browser, so ClickUp asked for a login on every run.

&nbsp;

## DeepSeek Harness

#### An Eighth CLI You Can Hand Work To

`cli-deepseek-harness` sends one task to `dsh` with a route patch that picks the provider and model, plus the lineage and guards patches that keep the run local and guarded. A run counts as complete only when it exits 0 and its last event says `completed`. Requests that name the harness route to it, and "use cli-opencode with deepseek-v4.1-flash" still goes to `cli-opencode`.

#### Two Routes, One of Them Verified

LLM Gateway `deepseek-v4.1-flash-1017` answered a keyed run on 2026-11-06 and is the default. OpenCode Go serves the same model but stays explicit-only until a run with a real key settles its endpoint.

#### Thirteen Rules Refuse an Unsafe Dispatch

Every `dsh` command is checked before it runs. It must name a roster route with the lineage and guards patches, use a disposable home outside the checkout, run from outside the repository root and find `dsh` on your `PATH`. MCP stays opt-in. A start folder or home written as `$REPO` counts as the checkout, so it is refused like the literal path.

#### Deep Loops Can Run on It

Deep research and deep review can bind `dsh` as a fan-out lineage. Two live lineages completed on the LLM Gateway route, and the second ran with a clean containment scan.

## DeepSeek Harness Sessions

A session started with the guards patch and no lineage patch, such as `dsh web`, is interactive. A fan-out lineage adds the lineage patch, which marks it as a leaf.

#### The Advisor Briefs Interactive Sessions

An interactive session gets the skill-advisor brief on each prompt, as Pi and OpenCode do. A fan-out leaf gets none, because its prompt is a fixed task and a route suggestion would be noise.

#### Goals Work From Inside the Session

`/goal-dsh` and the `dsh_goal` tool run the shared goal command, so a goal set here is the same record every other runtime reads. `DSH_SPEC_FOLDER` brings a packet's goal into the session.

#### Checks at Start and a Save at Close

An interactive session runs six warn-only checks at start, such as the worktree and stale-build warnings. Every session gets its context back after compaction, and an interactive one saves its continuity when it closes.

#### Guards and Decisions Match the Other Runtimes

The overlay guard refuses a write to a file an overlay owns. Answers you give through `ask_user_question` are queued live, a late reply to a timed question included, and `/speckit:save` runs `sweep-dsh.mjs` to recover any answer the live capture missed.

#### Adapters Live in the Hook Library

Each `dsh` adapter now sits beside its hook core under `.skilled/hooks/` or in its owning skill's `hooks/dsh/` folder, the layout Pi uses. The bundle keeps one link per adapter, and `/doctor:runtime-mirrors` reports a missing or stale link.

## Skilled in Your Project

#### One Skill Owns the Doctor Commands

Ten doctor commands about putting Skilled into a project were credited to `system-spec-kit` or `sk-doc`, so an install request could route to a spec-folder skill. `system-skilled-doctor` now owns them, and each doctor job routes to its own command.

#### Overlays Keep Your Changes

A project that vendors Skilled keeps its own edits in an overlay folder. `/doctor:overlay status` reports their state without writing anything, and `/doctor:overlay apply` writes them back after an update.

#### Moving the Pin Has a Way Back

`/doctor:overlay repin` moves a vendored copy to a newer upstream commit in one guarded run. It refuses while a file no overlay owns differs from the pinned commit and backs up every path before its first write. It shows the same run staged on a copy as its plan before it writes, and `--rollback <run-id>` restores a run byte for byte.

#### Edits to Owned Files Are Refused

The overlay-guard hook checks each file a pending write names and refuses one an overlay owns, naming the overlay file to edit instead. A repository with no overlay folder pays two file checks and nothing more.

## ClickUp

#### The Gap Pass Uses Your Logged-In Browser

ClickUp keeps its login only for the browser session, so an isolated browser asked for a login on every run. The divider pass now runs in a background tab of Aside, or of your own Chrome through the new `chrome_devtools_live` manual, and your active tab stays in view. A long page in Aside now runs in short calls, so Code Mode's 30-second limit no longer cuts off the report.

#### Approval and Login Are Checked First

Before the first ClickUp write of a session, a readiness check reports whether the ClickUp MCP is approved and whether ClickUp is logged in, and asks you about each missing piece.

#### Smaller Fixes

- **A clean page reads as clean.** The leftover count comes from the editor, so an image at the end of a block no longer counts as a gap.
- **Only its own tabs close.** Both programs close the tab they opened, even after an error, and never a tab you had open on the same page.

## Docs and Tooling

#### Changelogs Follow a Concise Format

Large releases produced entries as long as the 500-line v4.0.0.0 model. The changelog template now takes length and selection from v4.0.1.0, caps an expanded entry at 240 lines and 26 items and adds a Smaller Fixes list. A shape check stops a draft that breaks a ceiling, and it reads glance order from section comments a reader never sees.

#### Each Runtime Folder Has a README

`.claude/`, `.codex/`, `.opencode/`, `.cursor/`, `.pi/`, `.devin/` and `.hermes/` each have a README that separates what is generated from `.skilled/` from what is authored there and names the command that checks its mirrors.

#### Smaller Fixes

- **A security patch for the spec-kit lock.** `@hono/node-server` resolves to 2.1.6, past the affected 2.1.1.
- **Hyphenated workflow names route.** A request that names `deep-review` or `deep-research` with its hyphen reaches the deep-loop hub, even when it mentions docs.
- **The router-sync guard sees every surface.** It reads `sk-code`'s surfaces from the mode registry, so a new one is checked.
- **README badges pass the render check.** A badge no longer warns as a bare URL.
- **Go code in templates reads as code.** The voice scan no longer counts semicolons inside a Go fence.

Each touched skill and mode has its own changelog entry, in cli-classifier (cli-jev), cli-external-orchestration (cli-deepseek-harness), mcp-tooling (mcp-aside-devtools, mcp-chrome-devtools, mcp-click-up), sk-code, sk-doc (sk-create-changelog, sk-create-readme, sk-create-skill), sk-git, sk-prompt, system-deep-loop with its runtime, system-skill-advisor, system-skilled-doctor and system-spec-kit.

## Upgrade Notes

- **To dispatch to `dsh`:** install `dsh` on your `PATH` and export `LLMGATEWAY_API_KEY`. Never put a key in the repository `.env`.
- **To run an interactive `dsh` session:** pass a route patch and `.dsh/patches/guards.patch.yml` without the lineage patch, and set `DSH_SPEC_FOLDER` to bind a packet goal.
- **A project that vendors Skilled:** move your local edits into an overlay folder, then run `/doctor:overlay status` and `/doctor:overlay apply`. Read the staged plan `/doctor:overlay repin` shows before you let it write.
- **ClickUp through your own Chrome:** add the `chrome_devtools_live` manual from `.utcp_config.json`.
- **To pick up the security patch:** run `npm ci` in `.skilled/skills/system-spec-kit`.
