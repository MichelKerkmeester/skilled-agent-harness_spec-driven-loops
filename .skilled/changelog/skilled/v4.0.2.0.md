# v4.0.2.0, Skilled in Your Own Project

This release is about using Skilled in your own projects. A new `SETUP.md` at the root shows both ways in. You can link a project to your Skilled checkout. Or you can copy Skilled into the project and keep your own changes as overlays.

The new `system-skilled-doctor` skill owns every setup command. Its `/doctor:overlay` puts your changes back after each update. It moves the copy to a newer commit, with a preview first and a way back. It also works with an overlay folder a project already keeps.

One `/doctor:symlink link` run now links a new project completely. A project whose `specs` folder links into another repository can save again.

A compacted session can now read back its own earlier history. One read-only command does it, on Claude, Codex, Pi, Devin, DSH and OpenCode.

DeepSeek Harness (`dsh`) joins as an experimental CLI. Hermes Agent is removed. ClickUp's clean-up now runs in a browser you are already logged in to.

> Spec folders: `specs/system-skilled-doctor/001-skill-and-overlay-build`, `specs/other/004-context-paging`, `specs/cli-external-orchestration/085-cli-deepseek-harness-creation`, `specs/cli-external-orchestration/086-cli-hermes-deprecation`, `specs/system-speckit/037-symlinked-runtime-root`, `specs/mcp-tooling/026-clickup-doc-divider-spacing`, `specs/sk-doc/055-changelog-system/005-concise-release-format` and `specs/sk-code/019-surface-consistency-research`, with smaller packets for the fixes

## Why This Release

A project that copied Skilled into its own tree lost its local changes on every update. Someone had to replay them by hand. Nothing stopped an edit to a file the next update would overwrite. There was no single setup guide. A project whose `specs` folder links to another repository could not save at all.

Compaction kept a summary and dropped the rest. A detail the summary missed was gone for good.

DeepSeek models had none of the dispatch rules or guards the other CLIs carry. Hermes Agent's 177-file folder was kept in step through 553 commits. Its own log shows no session after 2026-10-25. ClickUp asked for a login on every clean-up run.

## Skilled in Your Project

#### One Skill and One Guide for Setup

Ten doctor commands used to belong to `system-spec-kit` or `sk-doc`. An install request could land on the wrong skill. `system-skilled-doctor` now owns them all.

`SETUP.md` covers both ways in: link a project, or copy Skilled in with overlays. The first `/doctor:symlink link` on a new project now links everything in one run. Links into your checkout are kept out of git. An alias to your own `specs/` folder stays visible, so you can commit it.

#### Overlays Keep Your Changes

A vendored copy is a copy of Skilled kept inside your project. Its local edits now live in an overlay folder. `/doctor:overlay status` shows their state and writes nothing. `/doctor:overlay apply` writes them back after an update.

Already have an overlay folder? Name it in `.skilled-overlays.json`. You don't move a file. A protected file now blocks only its own overlay, and the error names the fix. A re-pin lists every upstream change it skipped as a `not-copied` line. The `.dsh` folder is copied too.

#### Updating the Copy Has a Way Back

`/doctor:overlay repin` moves a vendored copy to a newer upstream commit. It first runs on a temporary copy and shows you the result. It refuses if someone edited a file no overlay covers. It backs up every path before it writes. `--rollback <run-id>` restores a run byte for byte.

#### Edits to Owned Files Are Refused

The overlay-guard hook blocks an edit to a file an overlay owns. It names the overlay file to edit instead. A repository with no overlay folder pays almost nothing.

#### A Linked Specs Folder Saves Again

Some projects keep their packets in another repository and link their `specs` folder to it. Every save there failed with "Refusing to write graph metadata outside a configured specs root". The check now follows the link to where the packet lives. A destination outside every allowed folder is still refused.

## History After Compaction

#### Look Back at What Compaction Dropped

After compaction, the restored context can carry a `## History Lookup` section. It holds one read-only command. The command searches, browses and loads the session's own earlier turns. Each reply is at most 16 KiB. What comes back is treated as information, not instructions.

The handle lasts 30 minutes. It works only for the session and checkout that created it. Search matches part of a word: `dv-2b7e` finds a turn that said `LIVE-MARKER-dv-2b7e`. Devin shows the section with your next prompt. Cursor is not supported yet.

#### Resume Stays First and Saves Name the Session

`/speckit:resume` still recovers a packet from its own files. If anything is missing or stale, the lookup section is left out. `/speckit:save` can now record which runtime and session wrote a packet. Pass `--session-id` and `--runtime` to use it.

## DeepSeek Harness

#### A New CLI You Can Hand Work To

`cli-deepseek-harness` sends one task to `dsh`. Three small config files, called patches, shape each run. The route patch picks the model. The lineage patch turns off what an unattended run must not use. The guards patch loads the shared safety checks. A run counts as complete only when it exits 0 and reports `completed`.

#### Two Routes, One of Them Verified

LLM Gateway `deepseek-v4.1-flash-1017` is the default. It answered a real run on 2026-11-06. OpenCode Go serves the same model, and a keyed run proved it on 2026-11-07. A run uses OpenCode Go only when you ask for it by name.

#### Thirteen Rules Refuse an Unsafe Dispatch

Every `dsh` command is checked before it runs. It must name a listed route and carry the lineage and guards patches. It must use a throwaway home folder and start outside the repository. MCP stays off unless you turn it on.

#### Deep Loops Can Run on It

Deep research and deep review can use `dsh` as a parallel worker. Two live runs completed on LLM Gateway. Neither wrote outside its own folder.

## DeepSeek Harness Sessions

A session started without the lineage patch, such as `dsh web`, is interactive. A parallel worker carries the lineage patch, so it knows nobody is at the keyboard.

#### The Advisor Briefs Interactive Sessions

An interactive session gets the skill-advisor brief on each prompt, as Pi and OpenCode do. A parallel worker gets none. Its task is fixed, so a route hint would be noise.

#### Goals Work From Inside the Session

`/goal-dsh` and the `dsh_goal` tool run the shared goal command. A goal set here is the same goal every other runtime reads. `DSH_SPEC_FOLDER` brings a packet's goal into the session.

#### Checks at Start and a Save at Close

An interactive session runs six warn-only checks when it starts. Every session gets its context back after compaction. An interactive session saves where it left off when it closes.

#### Guards and Decisions Match the Other Runtimes

The overlay guard works here too. Answers you give through `ask_user_question` are recorded as you give them, late replies included. `/speckit:save` recovers any answer the live capture missed.

#### Adapters Live in the Hook Library

Each `dsh` adapter now sits next to the hook it serves, as Pi's do. `/doctor:runtime-mirrors` reports a missing or stale link.

#### Smaller Fixes

- **The spec gate reads only your prompt.** It ignores notices the session adds.
- **The advisor knows it is talking to `dsh`.** It no longer reports itself as `pi`.
- **Parallel workers lose the native goal tools.** Those tools need a person, and a worker never has one.
- **A running session keeps its MCP helpers.** The orphan sweeper leaves a live `dsh` session alone.
- **`/doctor:git setup` checks DSH.** It accepts `--tool dsh`.

## Hermes Agent Removed

#### The Executor and Runtime Folder Are Gone

**Breaking:** `cli-hermes` is no longer a mode, and deep loops reject it as an executor.

The `.hermes/` folder is deleted with its skill copies, prompts and plugin. A request that names Hermes now routes nowhere.

#### Hooks and the Launcher Drop It

No hook or check knows a `hermes` runtime anymore. `skilled-loop` no longer defines a `hermes` shell function. `AGENTS.md` no longer describes Hermes personas.

## ClickUp

#### The Gap Pass Uses Your Logged-In Browser

ClickUp keeps its login only for one browser session. An isolated browser had to log in on every run. The divider pass now runs in a background tab of Aside or of your own Chrome. Your active tab stays in view. Long pages run in short steps, so the 30-second tool limit no longer cuts off the report.

#### Approval and Login Are Checked First

Before the first ClickUp write, a check confirms the ClickUp MCP is approved. It also confirms you are logged in. It asks you about anything missing.

#### Smaller Fixes

- **A clean page reads as clean.** An image at the end of a block no longer counts as a gap.
- **Only its own tabs close.** A tab you opened yourself stays open, even after an error.

## Docs and Tooling

#### Changelogs Follow a Concise Format

Some release entries ran to 500 lines. The template now caps an entry at 240 lines and 26 items. It adds a Smaller Fixes list. A shape check stops a draft that breaks a limit.

#### Each Runtime Folder Has a README

Each runtime folder, from `.claude/` to `.dsh/`, now has a README. It says which files are generated from `.skilled/` and which are written by hand. It names the command that checks them.

#### Every Hook Folder Explains Itself

Each folder under `.skilled/hooks/` now has a README. It says what each file does and which event it answers. It also says what happens when the hook fails.

#### Smaller Fixes

- **A security patch for the spec-kit lock.** `@hono/node-server` now resolves to 2.1.6, past the affected 2.1.1.
- **Hyphenated workflow names route.** `deep-review` and `deep-research` reach the deep-loop hub.
- **The router-sync guard sees every surface.** A new `sk-code` surface is checked too.
- **README badges pass the render check.** A badge no longer warns as a bare URL.
- **Go code in templates reads as code.** The voice scan skips semicolons inside a Go fence.
- **Workers and worktrees stay in place.** An OpenCode worker now stays in its worktree. A new worktree gets each private command in its real form.

Each touched skill and mode has its own changelog entry, in cli-classifier (cli-jev), cli-external-orchestration (cli-deepseek-harness, cli-opencode), mcp-tooling (mcp-aside-devtools, mcp-chrome-devtools, mcp-click-up), sk-code, sk-doc (sk-create-changelog, sk-create-readme, sk-create-skill), sk-git, sk-prompt, system-deep-loop with its runtime, system-skill-advisor, system-skilled-doctor and system-spec-kit.

## Upgrade Notes

- **To set Skilled up in a project:** follow `SETUP.md` at the repository root.
- **A project that vendors Skilled:** move your local edits into an overlay folder. If you already keep one, name it in `.skilled-overlays.json`. Then run `/doctor:overlay status` and `/doctor:overlay apply`. Read the staged plan before a re-pin writes.
- **To use the history lookup:** run `npm run build` in `.skilled/skills/system-spec-kit/runtime`.
- **To pick up the security patch:** run `npm ci` in `.skilled/skills/system-spec-kit`.
- **To dispatch to `dsh`:** install `dsh` on your `PATH` and export `LLMGATEWAY_API_KEY`. Never put a key in the repository `.env`.
- **To run an interactive `dsh` session:** pass a route patch and `.dsh/patches/guards.patch.yml` without the lineage patch. Set `DSH_SPEC_FOLDER` to bind a packet goal.
- **If you used Hermes Agent:** open a new shell so the `hermes` function is gone. Remove `repo-guards` from `plugins.enabled` in `~/.hermes/config.yaml`. Your `~/.hermes/` install itself is untouched.
- **ClickUp through your own Chrome:** add the `chrome_devtools_live` manual from `.utcp_config.json`.
