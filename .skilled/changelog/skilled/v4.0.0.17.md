# v4.0.0.17, Pi Runs in Worktrees and New Skills Share One Routing Shape

v4.0.0.17 fixes a crash that stopped Pi from starting inside any git worktree, and it gives every new skill one routing shape. The creation and check tools now enforce that shape, so a new skill can no longer drift from it.

> Spec folders: `specs/hooks/025-cache-optimizer-single-copy-guard` (Level 1) and `specs/sk-doc/072-skill-routing-and-clarity/003-routing-canon-and-tooling` (Level 2)

&nbsp;

## What's New at a Glance

- **Pi starts inside a git worktree again.** A user-level link that loads the cache optimizer in every project made Pi load two copies of it inside a worktree, and Pi refused to start. The first copy now claims the extension and the second stays quiet, so a worktree run no longer needs `-ne`.
- **New skills start in one routing shape.** A skill opens with a short Smart Routing section of at most 180 words and ends with a Machine Router appendix. A mode packet carries no router file of its own, and a hub keeps one at its root.
- **The old shape is refused where skills are made.** `/create:skill` now blocks on the strict package check, and `package_skill.py --strict` and the parent hub check both reject a skill written in the old shape.
- **Existing skills are held to what they have.** The 54 skills still in the old shape pass as recorded debt. Any new problem, or a higher count of an old one, fails, and CI checks that the debt list never grows.
- **The CI skill is the first one rewritten.** sk-code-ci now follows the new shape, as the worked example for the rest.

&nbsp;

## Upgrade

No migration required. Pi runs from a worktree work once your main checkout has this release, because the user-level link loads the main checkout's copy.
