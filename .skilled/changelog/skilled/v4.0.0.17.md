# v4.0.0.17, Safer Worktree Cleanup and Sharper Routing

v4.0.0.17 makes the numbered worktree sweep from v4.0.0.16 keep a worktree whenever it cannot be sure the worktree is safe to remove. The skill advisor also sends four kinds of request it used to misread to the skill that owns them, and a single-lineage deep-loop run now reports a file you were already editing. The sk-code settings now live in the skill folders, every frontmatter block must be valid YAML, and a skill routing and clarity program has started.

> Spec folders: `specs/sk-git/035-fsmonitor-daemon-and-worktree-relocation-regression` (Level 2), `specs/system-skill-advisor/039-executor-workflow-owner-guard` (Level 2), `specs/system-deep-loop/043-fanout-resume-and-containment` (Level 2), `specs/sk-code/017-portable-code-modes` (Level 3) and `specs/sk-doc/072-skill-routing-and-clarity` (Level 3)

&nbsp;

## Why This Release

The sweep deletes worktrees, so any check that reads a failure as a clean answer can remove work someone still needs. In v4.0.0.16 a failed worktree list, a half-finished process listing and a database inside a build folder each looked safe to delete. The contested-file report from the same release also reached only fan-out runs. Separately, a root `.sk-code/` folder put sk-code's repository settings outside the skills, and a copy shipped with the skills could apply to the wrong repository.

&nbsp;

## What's New at a Glance

- **The worktree sweep keeps a worktree it cannot judge.** When the worktree list cannot be read, the sweep judges no worktree and deletes nothing that run. A process listing that exits with an error counts as busy.
- **Databases and session state are always kept.** A SQLite file (`*.sqlite`, `*.sqlite3` or `*.db`, with its `-wal` and `-shm` journals) or a `.state` folder keeps its worktree in whatever folder it sits.
- **A dry run leaves the repository untouched.** The check for a squash-merged branch now does its trial merge in a throwaway object folder that is deleted afterwards.
- **A packet-local changelog request reaches sk-doc.** "packet-local changelog" used to go to system-spec-kit, although spec folders no longer hold changelogs.
- **An iterative review with an executor stays a deep-loop run.** "Review this change iteratively using cli-opencode as the executor" now reaches system-deep-loop ahead of the CLI hub. The Python fallback also ranks a named deep-loop or spec-kit workflow first, as the native scorer does.
- **Questions about turning off the worktree sweep reach sk-git.** That includes a question that names `SPECKIT_WORKTREE_AUTOREAP` itself, which used to return no recommendation at all.
- **A short word no longer matches a longer compound.** "auto" no longer matches `autoreap` and "open" no longer matches `opencode`, so "auto review this PR" stays on sk-code. A real suffix such as `plan` to `planning` still matches.
- **Single-lineage deep-loop runs report a contested file.** A file that was already dirty before the dispatch and changed during it is written to the run's state log and printed by the dispatch step, as fan-out runs already did.
- **sk-code settings live in the skill folders.** The CI profile is at `.skilled/skills/sk-code/sk-code-ci/repository/ci.json` and the quality config at `.skilled/skills/sk-code/sk-code-quality/repository/quality.json`. A `repository` field limits a shipped copy to the repository it names, the loaders refuse the old root paths and name where to move them, and the CI toggle refuses to switch a workflow off while its profile is ignored.
- **Every frontmatter block is valid YAML.** Twenty-eight invalid blocks were repaired without rewording a value, and an untrue author field was removed from nine `SKILL.md` files. `validate_document.py` rejects invalid frontmatter, strictly with PyYAML and by a line check without it, and a fleet test covers every document.
- **This repository commits its own quality config.** It names one optional `actionlint` check for workflow files and disables no hygiene rule.
- **A skill routing and clarity program has started.** Ten research iterations found each routing decision restated in two to five places. The first phase fixed the routing bugs that research found, and nine more phases restructure the skills. `sk-vision` and the `mcp-magicpath` mode are left out while they are deprecated.

&nbsp;

## Upgrade

A repository that committed `.sk-code/ci.json` or `.sk-code/quality.json` moves each file to its skill-folder path above; the loaders refuse the old paths and name the destination. A worktree that holds a SQLite file or a `.state` folder inside a build or cache folder is now kept, so remove it by hand once you are sure nothing in it matters. Rebuild the advisor runtime with `npm --prefix .skilled/skills/system-skill-advisor/runtime run build` to pick up the routing fixes.
