# v4.0.0.17, Safer Worktree Cleanup and Sharper Routing

v4.0.0.17 makes the numbered worktree sweep from v4.0.0.16 keep a worktree whenever it cannot be sure the worktree is safe to remove. The skill advisor also sends four kinds of request it used to misread to the skill that owns them, and a single-lineage deep-loop run now reports a file you were already editing.

> Spec folders: `specs/sk-git/035-fsmonitor-daemon-and-worktree-relocation-regression` (Level 2), `specs/system-skill-advisor/039-executor-workflow-owner-guard` (Level 2) and `specs/system-deep-loop/043-fanout-resume-and-containment` (Level 2)

&nbsp;

## Why This Release

The sweep deletes worktrees, so any check that reads a failure as a clean answer can remove work someone still needs. In v4.0.0.16 a failed worktree list, a half-finished process listing and a database inside a build folder each looked safe to delete. The contested-file report from the same release also reached only fan-out runs.

&nbsp;

## What's New at a Glance

- **The worktree sweep keeps a worktree it cannot judge.** When the worktree list cannot be read, the sweep judges no worktree and deletes nothing that run. A process listing that exits with an error counts as busy.
- **Databases and session state are always kept.** A SQLite file (`*.sqlite`, `*.sqlite3` or `*.db`, with its `-wal` and `-shm` journals) or a `.state` folder keeps its worktree in whatever folder it sits.
- **A dry run leaves the repository untouched.** The check for a squash-merged branch now does its trial merge in a throwaway object folder that is deleted afterwards.
- **A packet-local changelog request reaches sk-doc.** "packet-local changelog" used to go to system-spec-kit, although spec folders no longer hold changelogs.
- **An iterative review with an executor stays a deep-loop run.** "Review this change iteratively using cli-opencode as the executor" now reaches system-deep-loop ahead of the CLI hub. The Python fallback also ranks a named deep-loop or spec-kit workflow first, as the native scorer does.
- **Questions about turning off the worktree sweep reach sk-git.** That includes a question that names `SPECKIT_WORKTREE_AUTOREAP` itself, which used to return no recommendation at all.
- **A short word no longer matches a longer compound.** "auto" no longer matches `autoreap` and "open" no longer matches `opencode`, so "auto review this PR" stays on sk-code. A real suffix such as `plan` to `planning` still matches.
- **Single-lineage deep-loop runs report a contested file.** A file that was already dirty before the dispatch and changed during it is written to the run's state log and printed by the dispatch step, as fan-out runs already did.

&nbsp;

## Upgrade

No migration required. A worktree that holds a SQLite file or a `.state` folder inside a build or cache folder is now kept, so remove it by hand once you are sure nothing in it matters. Rebuild the advisor runtime with `npm --prefix .skilled/skills/system-skill-advisor/runtime run build` to pick up the routing fixes.
