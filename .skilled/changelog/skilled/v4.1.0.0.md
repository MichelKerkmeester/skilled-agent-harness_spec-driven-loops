# v4.1.0.0, Improved Chat Automation, Search & Session Handover

Long sessions now hand over cleanly, and Claude Code does it by default.

- Near its context limit, a session writes a handoff note and a fresh one picks up in the same terminal.
- The hop carries the running command, the goal and the session's name.
- Pi, OpenCode and Mistral Vibe now finish a hop too.

The skill advisor and the deep loops now say more and guess less.

- The advisor names the slash command behind a hub skill.
- It says whether the agent may run that command, start it or should ask first.
- Mistral Vibe joins as the eighth runtime, with Skilled's guards and advisor brief in every session.
- A deep review fails while a required check still fails, and a script makes that call.

Search, the spec commands and the overlay checks now report what really happened.

- Search answers say how much they left out.
- The spec commands save what they report and check their own work.
- Overlay checks in a vendored project refuse a bad write before it lands.

This release also changes what you install and what an agent may read.

- Skilled now needs a patched Node.js release.
- A new guard keeps the values in a `.env` file away from every agent, on all eight runtimes.

The documentation now matches the code.

- 184 READMEs follow their templates, and a second session checked every one.

> [!IMPORTANT]
> Nine changes can break an existing setup. Read these before you update.
>
> 1. Old session relaunch switch names are no longer read. [Old switch names](#c-old-switch-names-stop-working)
> 2. An open handoff note in the old state folder is not found. [Moving from session relaunch](#c-moving-from-session-relaunch)
> 3. The history lookup is no longer offered after a compaction. [Claimed note history](#c-a-claimed-note-offers-the-senders-history)
> 4. `/deep:ai-council` is gone, so run `/speckit:ai-council`. [AI Council](#c-the-ai-council-is-its-own-agent)
> 5. The standalone git pre-commit hook is gone. [Hook folders](#c-folders-say-what-they-guard)
> 6. Code Mode needs Node 24.22.1 or newer on 24. [Node.js](#c-patched-releases-are-required)
> 7. Code Mode no longer starts a manual marked disabled. [Code Mode skips disabled manuals](#c-code-mode-skips-disabled-manuals)
> 8. Pi no longer ships the llmgateway default provider. [Pi ships without a private provider](#c-pi-ships-without-a-private-provider)
> 9. OpenCode 1 support is removed, and OpenCode 2 is the only supported major. `bash .skilled/skills/cli-external-orchestration/cli-opencode/scripts/opencode-setup.sh remove-v1` removes an old OpenCode 1 package and its `opencode1` launcher, and leaves its data files in place.

## Why This Release

Several parts of Skilled said one thing and did another. Handover existed, but most people never had it on. Checks could pass while something underneath had failed. This release closes those gaps.

- Handover shipped off, so most Claude Code users never had it.
- A hop mid-command came back as a plain chat.
- The advisor named a skill, not the command to type.
- A deep review could pass while a required check failed.
- A search cut at its limit never said what it hid.
- An overlay re-pin could write a wrong value and still pass.
- Code Mode opened sign-in tabs on every session, even with no OAuth tokens.
- Any agent could read `.env` and send its secrets to the model.
- Skilled still accepted Node 20 after an October security patch.
- Many READMEs no longer matched the code they described.

## Session Handover

Handover moves a long session to a fresh one before it runs out of context. The old session writes a note and ends, and a new session claims the note and carries on. This release turns it on for Claude Code by default and makes every hop carry more of the running state.

#### Claude Code Hands Over by Default <a id="c-claude-code-hands-over-by-default"></a>

- On for Claude Code when no switch is set.
- Codex, Pi, OpenCode, Cursor, Devin and Vibe stay off until you turn them on.
- Under `skilled-loop`, a session at 80% writes a note and ends.
- A fresh session claims the note in the same terminal.
- Without the wrapper, the session keeps the note and works on.
- Turn it off with `SYSTEM_SESSION_HANDOVER_CLAUDE_ENABLED=0`.

#### Old Switch Names Stop Working <a id="c-old-switch-names-stop-working"></a>

> [!WARNING]
> Old switch names are no longer read. `SYSTEM_SESSION_RELAUNCH_ENABLED=0` now does nothing, and Claude Code hands over again.

- Main switch: `SYSTEM_SESSION_HANDOVER_ENABLED`.
- Per runtime: such as `SYSTEM_SESSION_HANDOVER_CODEX_ENABLED`.
- Tuning variables: the `SESSION_HANDOVER_` prefix.
- Hook folder: `.skilled/hooks/session-handover/`.
- Seed: `[session-handover] claim and continue handoff`.
- `SYSTEM_IN_SESSION_HANDOVER_*` also works for on and off. The main name wins.
- `/doctor:env` names a conflict between the two.

> [!WARNING]
> An open note in the old state folder is not found. Move it as [Upgrade Notes](#c-moving-from-session-relaunch) says.

#### A Hop Carries the Command and the Goal <a id="c-a-hop-carries-the-command-and-the-goal"></a>

- The note carries an `Active command:` line.
- The next session reruns it with the same mode and arguments.
- Running workers are listed, so they never start twice.
- A Claude session with no goal hands on its packet's goal through `/goal`.
- A goal you met, failed or cleared stays ended.
- A goal that cannot travel prints one `goal not carried:` line.
- The session name carries over as `<title> (2)`, then `(3)`.
- The permission mode and flags such as `--add-dir` carry over too.

#### A Claimed Note Offers the Sender's History <a id="c-a-claimed-note-offers-the-senders-history"></a>

- `claim` prints a `## History Lookup` section after the note.
- Its one read-only command searches the sender's turns for 30 minutes.
- Claude Code, Codex, Mistral Vibe, Pi and OpenCode senders get it.

> [!WARNING]
> The lookup is no longer offered after a compaction. The OpenCode plugin `session-history-lookup.js` is gone.

#### Pi, OpenCode and Vibe Finish a Hop <a id="c-pi-opencode-and-vibe-finish-a-hop"></a>

- Pi and OpenCode finish the same hop as Claude Code.
- OpenCode 2 still drops a model you pick mid-session.
- Vibe hands over with `SYSTEM_SESSION_HANDOVER_VIBE_ENABLED=1` under `skilled-loop vibe`.
- Near its compaction point, a Vibe session writes a note and a fresh one claims it.
- `/speckit-handoff` under the wrapper arms a hop. Any other prompt calls it off.
- The wrapper warns when an exported `MISTRAL_API_KEY` would bill outside your Vibe plan.

## Skill Advisor

The advisor reads each prompt and suggests the skill that fits, so you never have to remember which skill does what. It now also names the slash command behind a hub skill and says whether the agent may run it. Two new doctor checks show whether its brief reaches the model at all.

#### A Hub Skill Names the Command to Type <a id="c-a-hub-skill-names-the-command-to-type"></a>

- A brief head reads `use system-spec-kit → /speckit:plan (start)`.
- A hub that cannot pick a mode says `sk-doc (needs a mode)`.
- `run`: the agent may run it now.
- `start`: it starts without `:auto`, so its setup asks.
- `ask`: the agent offers it and waits.
- A typed command or a direct instruction outranks the policy.

#### Doctor Checks Show Whether the Brief Arrives <a id="c-doctor-checks-show-whether-the-brief-arrives"></a>

- `/doctor:setup` gains a read-only embedder leg and delivery leg.
- The embedder leg reads DEGRADED when meaning matching is off.
- The delivery leg reads DEGRADED when a prompt hook is missing or unapproved.
- On Codex, no brief arrives until you approve the project hooks.
- `/doctor:skill-advisor embedder` sets up meaning matching. It asks before it pulls a model or starts a server.

#### Pasted Replies Keep the Task <a id="c-pasted-replies-keep-the-task"></a>

- The native hook and Python scorer strip an attributed reply before routing the task that follows.
- The hook gate and 10,000-character cut read that task.
- A short follow-up that would switch to a floor-only route prints `Advisor: prompt skipped.`
- Route receipts change only after a brief is delivered, and the lifecycle clock expires stale ones.
- A prompt-hook crash prints `Advisor: outage (...)` with a manual route.

#### Ollama Off the Advisor Prompt Path <a id="c-ollama-off-the-advisor-prompt-path"></a>

- The semantic lane defaults to weight `0`, so prompts skip Ollama. Set `SPECKIT_ADVISOR_LANE_WEIGHTS_JSON` to `'{"semantic_shadow":0.05}'` to turn it back on. The ablation scored 149 of 193 with the lane and 150 without.
- `advisor_status` reports `lane_weight_zero` without a per-prompt warning. At daemon start, an unset or unknown pointer resolves to the registered model without probing the backend. The legacy embedding path is gone.
- The hf model server stays off unless `SPECKIT_SKILL_ADVISOR_MODEL_SERVER_ENABLED=1`. The server exits when its launcher dies. The launcher stops the server when its heartbeat file is over three minutes old.
- Live confidences rise about 5% because the lane no longer counts in the weight total. The 196-prompt corpus had no embeddings, matching how the lane ran when Ollama was not running. The change altered no route and added no fire for a prompt whose answer is none.

#### The Advisor Refreshes Vectors in the Background <a id="c-advisor-vectors-stay-current"></a>

- Once startup IPC is ready and after each watcher reindex, the daemon checks skill and command vector coverage in the background. A complete check returns without a network call. Incomplete coverage triggers one Ollama probe, then only missing or stale rows are embedded. Coverage requires at least one embeddable skill, so an all-current command-only index can still reach the probe. A failed embed leaves the old vector in place. Set `SYSTEM_SKILL_ADVISOR_EMBED_REFRESH=off` to stop these refreshes.
- The default semantic lane weight stays at `0`, so recommendation prompts are not embedded. Raising the weight requires current vectors for every embeddable skill and command. A failed prompt embed marks the lane degraded for that call. Optional semantic health in `advisor_status` reports skill and command coverage and performs its own Ollama readiness probe.
- The real-embedding ablation used the 196-row corpus and gave the same result twice. With the lane at `0.05` it scored 156 correct against 161 without it. It flipped 7 rows and added no new fire for a gold `none` row. The opt-in test keeps the registry default at `0` unless the result meets its pass bar.

## Mistral Vibe

Mistral Vibe is Mistral's coding CLI, and it now joins as the eighth runtime. A Vibe session runs the same guards, advisor brief and goal as the other runtimes, through its own hooks. Skilled can also dispatch work to Vibe headless, under seven safety rules.

#### Vibe Joins as a Runtime <a id="c-vibe-joins-as-a-runtime"></a>

- A dispatch runs headless as `vibe -p`.
- It may pick `deepseek-flash` or `glm-flash`.
- Seven rules refuse an unsafe dispatch.
- Each run needs `--output-dir` and Skilled's guards in its Vibe home.

#### Vibe Sessions Run Skilled's Hooks <a id="c-vibe-sessions-run-skilleds-hooks"></a>

- Start Vibe with `--trust` in your checkout to load all 18 hook entries.
- Each session gets its goal and context at start.
- Each prompt gets the skill advisor brief.
- Five guards run before each tool.
- Decision capture records answers in the question tool.
- A refusal names its guard, such as `env-secret-guard` for a dotenv read.
- Still open: a headless run captures no answers.
- Still open: Vibe accepts a turn after three turn-end refusals.

## Deep Loop

Deep loops run research and review passes on their own until their evidence says stop. Their verdicts and stop calls now come from scripts instead of judgment, so a rerun on the same state always agrees. The AI Council also moves out into an agent of its own.

#### The AI Council Is Its Own Agent <a id="c-the-ai-council-is-its-own-agent"></a>

> [!WARNING]
> `/deep:ai-council` is gone. Run `/speckit:ai-council` instead.

- It binds the spec folder and dispatches `@ai-council` once.
- The agent runs three rounds by default.
- It writes only under the packet's `ai-council/` folder.

#### A Review Fails While a Required Check Fails <a id="c-a-review-fails-while-a-required-check-fails"></a>

- A review returns FAIL when a P0 is open or a required check fails.
- The required checks are evidence, scope and coverage.
- Scripts compute the checks and the verdict.
- Coverage reads every shape a review records.
- The report carries the counts the verdict used.
- Open search debt makes a review CONDITIONAL.

#### Loops Stop the Same Way Every Time <a id="c-loops-stop-the-same-way-every-time"></a>

- `convergence.cjs --stop-decision` makes the stop call as one `stop_decision` object.
- The review vote follows your `convergenceThreshold`.
- A resume rebuilds its counts from the state log.
- Three failed passes in a row end the loop with reason `error`.
- `--restart` and `--dry-run` work on research and review.
- `maxDurationMinutes` ends a run on time.
- A review fan-out takes `--review-target`.
- Each deep command runs from one workflow file.

#### Finished Runs Take More Iterations <a id="c-finished-runs-take-more-iterations"></a>

- `--extend=N` reopens a completed research or review run and adds N iterations.
- It keeps the same session and generation.
- `--extend-minutes=M` adds time to the duration budget.
- A run that still stops on convergence prints a warning first.
- A fan-out config refuses `--extend`.

#### Loops Can Go Deep on Purpose <a id="c-loops-can-go-deep-on-purpose"></a>

- `--depth-mode=expansive` grows a frontier of sub-questions or sub-targets.
- Leaves propose children. A script admits or prunes them.
- `--frontier-max-depth` and `--frontier-max-nodes` cap the tree.
- A review can name custom dimensions beside the default four.
- Without the flag, a run behaves as before.

## Search

Search used to cut its answer at a limit without saying so. Lookups now report how many results they found in total. Free-text search shows one row per file instead of every matching line.

#### A Cut Answer Says What It Hid <a id="c-a-cut-answer-says-what-it-hid"></a>

- The trigger lookup returns `totalCandidates`.
- A cut answer reads `candidates : 2 of 828 (truncated) from 1070 phrase(s)`.
- A crash exits 2, not the no-match code 1.
- A lookup with no hits also reads spec documents the index does not list yet.
- Its JSON then carries `staleFallback`.

#### Free-Text Search Shows Each File Once <a id="c-free-text-search-shows-each-file-once"></a>

- `rg-wrapper.mjs structured` keeps the best row per file.
- `--limit` counts files, 20 by default.
- A cut answer ends with a line such as `+1382 more files with 2681 matches`.
- `/speckit:search` uses this wrapper by default.

## Installs and Overlays

A project can link to one Skilled checkout or keep a copy of its own. A copy keeps your changes in overlays, and the overlay checks now refuse a bad write before it lands. Pi 1.5.2 also loads every hook adapter again, and Claude Code can keep your own hook copy current. Shipped defaults change too. Code Mode skips manuals marked disabled at startup, and Pi ships no provider of its own.

#### Pi Loads Its Hook Adapters Again <a id="c-pi-loads-its-hook-adapters-again"></a>

- On Pi 1.5.2, 16 adapters failed to load and `pi -p` exited 1.
- `sync-hook-registrations.cjs` renders each `.pi/extensions/` entry from one template.
- A missing adapter turns that hook off and shows one notice for the session.
- `/doctor:setup` and `/doctor:symlink` run `hook-wiring-check`, which names the entry and the missing file.
- Pi 1.5.0 and 1.5.2 both load all 22 entries.

#### Pi Ships Without a Private Provider <a id="c-pi-ships-without-a-private-provider"></a>

> [!WARNING]
> Pi no longer uses the llmgateway default, so set your own provider if you relied on it.

- `.pi/settings.json` no longer names a default provider or model.
- The blackhole config drops its observer model for `"sessionFallback": true`.
- The observer falls back to your session model.
- Before, a project vendoring Skilled had to overlay both files to run Pi on its own provider.

#### Code Mode Skips Disabled Manuals <a id="c-code-mode-skips-disabled-manuals"></a>

> [!WARNING]
> A disabled manual no longer loads at startup. Its tools appear only after a task registers it.

- Code Mode skips a manual marked `"disabled": true` at startup, in every install, linked or vendored.
- `clickup_official`, `mobbin` and `refero` ship disabled.
- Before, a developer with no OAuth tokens got sign-in tabs for all three on every session.
- The ask step's `register_manual` loads a disabled manual when a task needs it.

#### Overlays Land Before a Named Line <a id="c-overlays-land-before-a-named-line"></a>

- Set `insertBefore` on a `marked-section` entry, such as `"insertBefore": "## 10. RELATED RESOURCES"`.
- The block lands just before the last line that matches that heading.
- A block an earlier `apply` appended at the end moves before that line on the next `apply`.
- With no matching line, the entry is refused and nothing is appended.
- `apply`, `rewrite`, `move` and `capture` all accept the field.

#### Claude Code Keeps Your Hook Copy in Step <a id="c-claude-code-keeps-your-hook-copy-in-step"></a>

- A hook copy in `~/.claude/settings.json` went stale after a folder rename.
- Outside Skilled it failed with `mk claude hook could not resolve`.
- Each hook now exits quietly where there is no `.skilled/hooks`.
- `SYSTEM_CLAUDE_USER_HOOK_SYNC_ENABLED=1` syncs the copy at each session start.
- Your other settings and hooks stay.
- The first write keeps a backup at `~/.claude/settings.json.pre-skilled-hook-sync`.
- Check the copy with `node .skilled/bin/sync-claude-user-hooks.mjs --check`.

#### A Re-Pin Refuses Before It Writes <a id="c-a-re-pin-refuses-before-it-writes"></a>

- A re-pin plans each `json-entry` file before its backup.
- One that cannot apply exits 2 and writes nothing.
- Before, it could write the wrong array item and still print `RESULT: PASSED`.
- Such a file shows as `cannot-apply` and blocks `apply`.
- A stage with a blocked overlay ends `RESULT: BLOCKED`.
- A re-pin names each upstream change that an overlay overwrites or removes.
- It warns on a missing anchor or an array-index path.
- After a rebase, set a `directory` or `skill-root` overlay's `rebasedOnto` to the new commit.

#### A Failed Apply Keeps Its Records <a id="c-a-failed-apply-keeps-its-records"></a>

- `apply` records what it wrote before any regenerate step.
- A failed step runs again on the next `apply`.
- A killed run leaves the state file whole.
- The state file moves to schema version 2.

#### A Vendored Tree Can Refuse Unowned Writes <a id="c-a-vendored-tree-can-refuse-unowned-writes"></a>

- Set `"strictWrites": true` in the overlay manifest.
- The guard then refuses a new file or unowned edit under a vendored root.
- `/doctor:overlay apply --adopt <path>` turns the path into an overlay.
- A `generated` glob list names paths your generators write.
- `overlay-engine.cjs pre-commit` runs the same test on staged changes.

- Every adapter fails open.
- `SYSTEM_ENV_SECRET_GUARD_DISABLED=1` turns the guard off.

## Upgrade Notes

Start with the two numbered lists, which apply to everyone. The folded groups below apply only if you use that part of Skilled.

#### Before You Start <a id="c-before-you-start"></a>

1. Update Node.js first. Use 22.23.4, 24.22.1, 26.12.1 or newer on those lines. Code Mode needs 24.22.1 or newer on 24. Check with `/doctor:mcp`.
2. If you use more than one Node.js major, run `npm ci` once in `.skilled/skills/system-skill-advisor/runtime`.
3. If you run the advisor from a built copy, run `npm run build` in the same folder.
4. If Skilled is installed in your project, run `node .skilled/skills/system-spec-kit/runtime/cli/runtime-mirrors/sync-hook-registrations.cjs` from the project root. Add `--check` to only check.
5. On Codex, approve the project hooks in `/hooks`, including the new `SessionStart` row.

#### Moving From Session Relaunch <a id="c-moving-from-session-relaunch"></a>

1. If you set a variable with `SESSION_RELAUNCH` in its name, replace that part with `SESSION_HANDOVER`.
2. If you have an open handoff note, move `.skilled/skills/.state/session-relaunch/` to `.skilled/skills/.state/session-handover/`. Do it once the checkout runs this release.
3. If anything matches the seed, use `[session-handover] claim and continue handoff`.
