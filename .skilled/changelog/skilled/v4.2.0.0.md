# v4.2.0.0, Deeper Loops, a Lighter Advisor & Overlays Beside the Tree

Deep loops can now go wider on purpose, keep going after they finish and stop when they are stuck.

- One flag lets a run grow its own sub-questions or sub-targets.
- A finished run takes more iterations, and a stuck one now stops.
- A fan-out run can be previewed, watched, stopped and rerun one lineage at a time.
- Every executor builds one way, and a bad setup is refused before it runs.

The skill advisor no longer has an embedding lane.

- It scores every prompt with four lanes.
- It no longer starts or calls a local model server.
- A pasted earlier reply no longer steers the route.
- One cleanup removes what the old lane left on a machine.

Vendored installs get one overlay layout and more room.

- Every overlay copy has one place, under `framework/` or `root/`.
- The overlay folder can sit beside the vendored tree.
- A failed relayout puts everything back.
- Most overlay refusals name the next command.

OpenCode 2 is now the only supported major.

- The OpenCode 1 paths, launcher names and setup modes are gone.

Browser tools now share one hub.

- Chrome DevTools and Aside move into `mcp-browser-use`.
- Bladebro joins them as a third mode.

> [!IMPORTANT]
> Eighteen changes can break an existing setup. Read these before you update.
>
> 1. OpenCode 1 is no longer supported, and deep-loop runs refuse a major-1 binary. [OpenCode 2 only](#c-opencode-2-is-the-only-supported-major)
> 2. Deep-loop runs no longer look for an `opencode2` launcher. [OpenCode 2 only](#c-opencode-2-is-the-only-supported-major)
> 3. `opencode-setup.sh` takes only `v2` or `check`, so `v1` and `both` are gone. [Setup helper](#c-the-setup-helper-installs-and-checks)
> 4. The plugin builder `dualPlugin` is now `definePlugin`, with no alias. [Plugin builder](#c-plugins-build-with-defineplugin)
> 5. `fanout-run.cjs --allow-single-lineage` is gone, and a one-lineage matrix is refused. [Rerun one lineage](#c-watch-stop-and-rerun-one-lineage)
> 6. A fan-out lineage with the `native` executor kind is refused. [Rerun one lineage](#c-watch-stop-and-rerun-one-lineage)
> 7. A research pass whose quality guards fail now returns `BLOCKED`, not `CONTINUE`. [Repeated blockers](#c-repeated-blockers-end-the-run)
> 8. A finished DeepSeek Harness lineage that asked for `danger-full-access` is refused once on rerun. [Sandbox reports](#c-sandbox-reports-name-the-real-mode)
> 9. Single-executor codex with no model now runs the runtime default, not your codex config default. [One build path](#c-every-executor-builds-one-way)
> 10. Two dispatch setup refusals now exit 64, not 1. [Setup mistakes](#c-setup-mistakes-stop-before-dispatch)
> 11. A manifest with a duplicate or escaping layout link now exits 2. [Layout links](#c-bad-layout-links-are-refused)
> 12. `record-base --pin` refuses a commit with no `.skilled` folder. [Release base](#c-the-release-base-takes-only-a-framework-commit)
> 13. Chrome DevTools and Aside moved out of `mcp-tooling`, so old folder paths are gone. [One browser hub](#c-one-hub-for-browser-tools)
> 14. `advisor_status --include-semantic-health` now fails with exit `64`. [Embedding lane removed](#c-the-advisor-drops-its-embedding-lane)
> 15. `advisor_status --include-embeddings-health` now fails with exit `64`. [Embedding lane removed](#c-the-advisor-drops-its-embedding-lane)
> 16. `advisor_status` no longer reports embedding health or `lane_weight_zero`. [Embedding lane removed](#c-the-advisor-drops-its-embedding-lane)
> 17. The `/doctor:skill-advisor` embedding setup route is gone. [Embedding lane removed](#c-the-advisor-drops-its-embedding-lane)
> 18. A lane weights setting can no longer score the removed lane. [Embedding lane removed](#c-the-advisor-drops-its-embedding-lane)

## Why This Release

The deep loops stopped as soon as their first questions looked answered. A broad topic could end early, and a finished run could not take more work. A stuck run spun until its cap. Fan-out runs were hard to check before launch and hard to stop. The advisor kept an embedding lane that routed worse when it was on. Overlays had no fixed layout.

- A narrow pass looked the same as a thorough one.
- A run at its cap needed a new session for more iterations.
- The same blockers could hold a run until its iteration cap.
- A fan-out showed no lineage command before it started.
- A fan-out reported cost units, never real spend.
- A stop could record a lineage as stopped while it still ran.
- Claude and codex were built by hand, apart from every other kind.
- Some failures were swallowed, so a broken step looked fine.
- The advisor carried a model server for a lane it did not need.
- The doctor commands still set up and checked that lane.
- Overlay copies sat wherever each project put them.
- Skilled still carried OpenCode 1 code that never ran.
- Browser tools sat in a general tool hub, and Bladebro had no home.

## Deep Loop

Deep loops run research and review passes on their own until the evidence says stop. They can now widen a run on purpose, extend a finished one and end one that is stuck.

#### Loops Grow Their Own Questions <a id="c-loops-grow-their-own-questions"></a>

- Pass `--depth-mode=expansive` to `/deep:research` or `/deep:review`.
- Before the first pass, the run splits its topic into depth-1 nodes.
- A review splits its target into sub-targets the same way.
- Leaves then propose child questions while they work.
- A script admits each proposal or prunes it.
- The checks run as relevance, dedupe, depth, fan-out, node cap, budget and cycle.
- A pruned proposal records the check that stopped it.
- The tree stops at depth 3 and six children a node by default.
- `--frontier-max-depth=N` and `--frontier-max-nodes=N` change the caps on a single-executor run.
- Leave the flag out and a run behaves as before.

#### Open Nodes Hold the Stop <a id="c-open-nodes-hold-the-stop"></a>

- A stop candidate becomes `CONTINUE` with `frontierOpen` while a node stays open.
- The iteration cap, a manual stop and stuck recovery still win.
- A review with every node closed and one answered stops on `frontier_drained`.
- The budget splits 50, 35 and 15 percent across three depth bands.
- Unused budget rolls down to a deeper band, never up.
- A band that runs out closes its open nodes as exhausted.
- An expansive dashboard gains a frontier section.

#### Repeated Blockers End the Run <a id="c-repeated-blockers-end-the-run"></a>

> [!WARNING]
> A research pass whose quality guards fail now returns `BLOCKED` with detail `qualityGuardFailed`, not `CONTINUE`. Expect the run to stop once the same guards keep failing.

- Each blocked pass writes a `blocked_stop` row with its blocker set.
- The same blocker set again adds one to a streak.
- A new blocker set restarts the streak at one.
- A new finding, insight or high new-information ratio resets it.
- At the stuck threshold the decision is `STOP` with reason `blockedStop`.
- Review stops at 2 blocked passes and research at 3.
- The reason reaches the terminal row and the report.
- The iteration cap and stuck recovery still run first.

#### Finished Runs Take More Iterations <a id="c-finished-runs-take-more-iterations"></a>

- `--extend=N` reopens a completed research or review run.
- It keeps the same session and generation.
- The earlier report is kept as a versioned snapshot first.
- `--extend-minutes=M` adds time to the duration budget.
- An extension keeps the run's stop policy and convergence mode.
- A fan-out run or an unfinished run is refused.

#### Weak Passes Get Flagged <a id="c-weak-passes-get-flagged"></a>

- Each pass reports tool calls, source reads and the gap to its commit.
- A pass with no reads and no findings is flagged as unexamined.
- A pass stamped later than its commit is flagged too.
- Iteration rows now take their time from the gateway clock.
- The model's own stamp is kept as `claimedTimestamp`.

<details>
<summary><b>Smaller fixes</b></summary>

- A research report keeps the stop reason its own session bound.
- So a run that hit its cap no longer reads as `converged`.
- A resumed research run no longer takes an earlier session's stop reason.
- An expansive review report lists its exhausted and blocked sub-targets as follow-up work.
- A blocked-stop row's adjudicated count no longer copies the candidate count.
- A review can name custom dimensions beside the default four.
- A review run now holds below its `minIterations` floor.
- A divergent pivot gets one retry after a missed quorum.
- An iteration that already landed is never dispatched twice.
- A research run on `cli-claude-code` keeps its configured config dir.
- Next Focus follows open questions, not progress sentences.
- Research sources get a class, so source diversity reads real classes.
- The append gateway now sets every stream identity field itself, so a row cannot fake one.
- An append that reuses an earlier row's key with other content is refused.
- The append script then exits 2 and names the key on stderr.
- A true retry of the same row still dedupes.
- A torn frontier store row is reported with its file and line.

</details>

## Fan-Out Runs

A fan-out run splits one deep loop across several executors, called lineages. It is now easier to check before launch, watch, stop and price. Its budget and sandbox reports now match what each lineage runs.

#### Preview a Fan-Out Before It Starts <a id="c-preview-a-fan-out-before-it-starts"></a>

- With fan-out executors, `--dry-run` first runs `fanout-run.cjs --preview`.
- It prints each lineage's command, with every prompt replaced by its digest.
- It shows the model, effort, sandbox mode and frontier scope.
- It shows the Claude config dir when one is set.
- Nothing is written to the packet.
- The preview JSON carries `dry_run_halt` and `topic_digest`.

#### Watch, Stop and Rerun One Lineage <a id="c-watch-stop-and-rerun-one-lineage"></a>

> [!WARNING]
> `--allow-single-lineage` is gone, and an unknown flag now fails. Rerun one lineage with `--only-lineage LABEL`, or run the single-executor workflow.

> [!WARNING]
> A fan-out lineage with the `native` kind is refused. Give it a `cli-*` kind, or run single-executor with `--executor=native`.

- `fanout-run.cjs --status` prints one row per lineage and writes nothing.
- A row shows iterations, last commit, node counts and flagged passes.
- `--stop` ends a live run from a second terminal, for each lineage it can confirm.
- It signals a pid only while its recorded start time still matches.
- A lineage it cannot confirm is refused, left running and listed with its reason.
- Any refused or surviving lineage makes the stop exit 2 with status `partial`.
- If a lineage's leader has exited, its group's later members are stopped one by one.
- Members that started before the lineage are left alone and listed under `spared`.
- Each stopped lineage gets a `stopped` row and its rerun command.
- A lineage's kept log is redacted when it ends, a `--stop` included.
- A closed terminal or dropped SSH session now stops the lineages too.
- The summary lists each lineage's status, exit code and `rerun_command`.
- `--only-lineage LABEL` reruns one lineage with its full-run share.
- A finished lineage is skipped as `skipped_complete`.
- A finished lineage from another topic or executor refuses the whole run.

#### A Stop Records Who Survived <a id="c-a-stop-records-who-survived"></a>

- Before, a runner stop wrote `stopped` for every lineage right after the signal.
- A lineage that ignored the signal was recorded as stopped while it ran.
- The runner now waits up to 2.5 seconds and checks each lineage.
- Only a lineage that went quiet gets a `stopped` row.
- A lineage still running gets no row and stays open to a later `--stop`.
- It is listed under `survivors` in `run_stopped` and the summary.
- A stop sent to the runner now spares the members `--stop` spares.
- A second `SIGTERM` is forwarded too, instead of killing the bootstrap.

#### One Table Sets a Defaulted Budget <a id="c-one-table-sets-a-defaulted-budget"></a>

- A defaulted expansive fan-out once carried three budgets that could disagree.
- The seed step, the root config and each lineage each had one.
- The runner now writes the root config's `maxIterations` as the largest lineage cap.
- It works that out from the full matrix, before any lineage spawns.
- It writes nothing under `--preview` or an explicit `--max-iterations`.
- It prints one line on stderr, such as this one from a live run.
- `[fanout-run] budget table: ds-a 3, ds-b 2 iterations; root maxIterations 3, the largest lineage cap`

#### A Fan-Out Reports Its Real Cost <a id="c-a-fan-out-reports-its-real-cost"></a>

- The summary carries `provider_cost_usd` per lineage and a run total.
- Cost comes from each lineage's own log.
- Claude lineages now log as `stream-json`, so their cost is readable.
- A log with no cost record reads as unknown, never zero.
- The total stays unknown while any lineage is unknown.

#### Sandbox Reports Name the Real Mode <a id="c-sandbox-reports-name-the-real-mode"></a>

> [!WARNING]
> A DeepSeek Harness lineage that asked for `danger-full-access` and finished under the old report is refused once on rerun as `finished_lineage_mismatch`. Rerun that fan-out with `--restart`, which archives the packet and starts a fresh session.

- A DeepSeek Harness lineage asked for `danger-full-access` runs `workspace-write`.
- It used to claim full access and now reports `workspace-write` with `sandboxNarrowedFrom`.
- Devin and pi have no separate write mode.
- A `workspace-write` request there reports `danger-full-access` with `sandboxWidenedFrom`.
- Single-executor rows now record the same modes.
- A requested read-only sandbox holds for Codex, DeepSeek Harness and built-in lineages.
- OpenCode refuses a requested read-only sandbox, because its Bash tool can write anywhere.
- An OpenCode lineage with no sandbox mode now runs `workspace-write`, not full access.
- That mode denies its file tools outside the working directory, but Bash stays unconfined.
- A Claude lineage reports its permission gate as `compensating`, not preventive.

#### Stdout Overflow Fails the Lineage <a id="c-stdout-overflow-fails-the-lineage"></a>

- Before, output past the 20 MB cap was cut without a word.
- A child killed for it read as timed out and was retried.
- A child that exited 0 passed on cut output.
- The result now carries an `ENOBUFS` error naming the cap.
- The verdict checks it first, so the lineage fails without a retry.

<details>
<summary><b>Smaller fixes</b></summary>

- A merged fan-out review keeps the coverage of every trusted lineage.
- A finding from a rejected or unexamined lineage stays, labelled `_untrusted`.
- The merge lists the excluded lineages under `untrustedLineages`.
- Masking emails in a large lineage log no longer takes seconds.
- Claude's message `uuid` and `request_id` values are now masked in lineage logs.
- The live stdout copy now stops at the same 20 MB cap as the log.

</details>

## Dispatch and Safety

Dispatch starts the executor for each iteration. Single-executor runs now build every kind the way fan-out does. The runtime also refuses a bad setup before anything runs, and failures it once swallowed now show.

#### Every Executor Builds One Way <a id="c-every-executor-builds-one-way"></a>

> [!WARNING]
> Single-executor codex with no model now runs the runtime's default codex model, not the default in your codex config. Set a model to keep your own.

- Claude and codex now build through the fan-out command builder.
- Claude runs as `stream-json` under the same write containment as every kind.
- Stdout streams to `iterations/iteration-NNN.out` and is masked when the iteration ends.
- A long iteration no longer overflows a memory buffer and crashes.
- The session cost lands beside it in `iterations/iteration-NNN.cost.json`.
- `{"iteration":1,"providerCostUsd":2.1483145}`
- A null or missing model resolves to the runtime default.
- The audit row records the model the command runs, never `null`.
- Only an error-shaped JSON line now reads as an unavailable executor.

#### Run Claude From Your Own Session <a id="c-run-claude-from-your-own-session"></a>

- A recursion guard stops a loop from dispatching itself.
- It also refused a Claude dispatch started from your own Claude Code session.
- That run exited 3 on `recursion-guard-ancestry`, with no way around it.
- Set `SPECKIT_ALLOW_HOST_SESSION_EXECUTOR=1` to allow it on purpose.
- It relaxes only the ancestry and session-variable checks.
- The lineage, stack and lockfile checks still refuse a loop into itself.
- The run prints `relaxed the cli-claude-code recursion guard [ancestry, env]`.
- The executor record lists the relaxed layers under `recursionGuardRelaxed`.
- A nested lineage never inherits the switch.
- Leave it unset and the guard behaves as before.

#### Setup Mistakes Stop Before Dispatch <a id="c-setup-mistakes-stop-before-dispatch"></a>

> [!WARNING]
> A missing executor binary or an artifact dir outside the git worktree now exits 64 with a usage line, not 1 with a stack trace. Update any script that checks for exit 1.

- Before, an artifact dir outside the worktree was caught only after the executor ran.
- So the executor could write before the iteration crashed.
- The check now runs before dispatch, and nothing is spawned.
- A path with no worktree or no git is still allowed.
- Fan-out keeps exit 3 for a missing binary.
- Fan-out still uses exit 3 for both bad input and all lineages failed.

#### Hidden Failures Now Surface <a id="c-hidden-failures-now-surface"></a>

- `append-state-record.cjs` refuses a target outside the working directory and exits 1.
- The sandbox setup checks its folder before it runs `rm -rf`.
- It refuses `/tmp` itself, dot segments and links that escape.
- `ERROR: sandbox dir must resolve inside /tmp/: <dir>`
- A failed lock restore now throws both errors instead of stranding the claim.
- The append gateway refuses with `APPEND_FAILED` when it cannot read the ledger.
- Before, it skipped its provenance and idempotency checks.
- A broken rollout mode file now throws with its path.
- Before, every command quietly fell back.
- A resume marks a ledger unreadable only for a ledger error, and any other error shows.
- Provenance records why it failed closed, such as `judge-content-missing`.
- Each script's exit codes and stderr prefix are listed in `.skilled/skills/system-deep-loop/runtime/references/script-interface-contract.md`.

## Skill Advisor

The advisor reads each prompt and suggests the skill that fits, so you never have to remember which skill does what. It now scores with four lanes and no embedding lane, and one cleanup removes what that lane left. The doctor commands match the four lanes, and the advisor ignores a pasted earlier reply.

#### The Advisor Drops Its Embedding Lane <a id="c-the-advisor-drops-its-embedding-lane"></a>

> [!WARNING]
> `advisor_status --include-semantic-health` now fails with exit `64`.
> `advisor_status --include-embeddings-health` now fails with exit `64`.
> Remove both flags from any script that passes them.

- The advisor scores every prompt with four lanes.
- They are explicit author, lexical, skill graph and derived metadata.
- Their weights stay `0.42`, `0.28`, `0.13` and `0.12`.
- `advisor_status` lists those four weights and no embedding health.
- The daemon no longer embeds skills, commands or prompts.
- The launcher no longer starts a local model server.
- The `/doctor:skill-advisor` embedding setup route is gone.
- A lane weights setting that names the removed lane is ignored.
- At start, an advisor database from an older schema is deleted and rebuilt.

#### A Cleanup Removes What the Lane Left <a id="c-a-cleanup-removes-what-the-lane-left"></a>

- `sweep-lane-residue.mjs machine` lists what the lane left behind.
- It checks this checkout and your home folder.
- Its `apply` deletes those leftovers.
- It asks before it deletes the pulled shared model, on every run.
- Without a terminal, `apply` keeps that model unless it gets `--shared-model delete`.
- A server address that names a regular file no longer marks that file for deletion.
- Only a socket at that address is listed.
- A dotenv line it cannot parse now gets a note.
- It finds a model server under a checkout path with spaces again.
- In `repo` mode it fails when a removed name comes back outside its allowlist.
- CI runs that check on every pull request and on pushes to `main` and `skilled/**`.
- On a clean tree it reports 47 allowlisted rows and none live.

#### The Doctor Commands Match Four Lanes <a id="c-the-doctor-commands-match-four-lanes"></a>

- `/doctor:setup` runs six read-only legs. The leg for the removed lane is gone.
- Its target table lists 26 rows.
- `/doctor:skill-advisor` lists six targets.
- `/doctor:install` prints five setup steps.
- `/doctor:update apply` ends with the lane cleanup, after its rebuild prompt.
- The cleanup's result never changes the update's `STATUS`.
- `/doctor:helper` and the advisor send cleanup wording to `/doctor:update`.
- The orphan check leaves the old model server to the cleanup's machine check.
- Four write workflows no longer ask for the lane's status after they write.
- `lane residue CI failing` now ranks `/doctor:update` first and prints `STATUS=OK MATCHES=1`.

#### Pasted Replies Keep the Task <a id="c-pasted-replies-keep-the-task"></a>

- The hook and the Python scorer strip an attributed reply before routing.
- The fire gate and the 10,000-character cut read the task that follows.
- A weak follow-up that only a floor would reroute prints `Advisor: prompt skipped.`
- A hook crash prints `Advisor: outage (...)` with a manual route.

<details>
<summary><b>Smaller fixes</b></summary>

- `advisor_recommend` marks floored routes with `confidenceFloored: true`.
- The daemon now receives the confidence and uncertainty thresholds.
- A pinned daemon keeps the shared generation counter.
- After the machine sleeps, the launcher skips one check before it judges the daemon.
- A daemon now notices a launcher that died during its startup.
- A crash in a disabled prompt hook prints nothing.
- On DSH, a session start or a clean compaction drops the session's route receipt.
- `rebuild-native-modules.sh` writes its Node version marker again.
- `check-native-modules.sh` checks only that marker. It exits 1 when the marker is missing or stale.
- The unused `sharp` and `protobufjs` version pins are gone.

</details>

## Installs and Overlays

A project can keep its own copy of Skilled and store its changes as overlays. Every overlay copy now has one layout path. The overlay folder can also live beside the vendored tree.

#### Overlays Lay Out Under framework/ and root/ <a id="c-overlays-lay-out-under-framework-and-root"></a>

- A copy for `.skilled/X` lays out at `framework/X`.
- Any other copy lays out under `root/`, with leading dots dropped.
- So `.claude/settings.json` lays out at `root/claude/settings.json`.
- An old-layout tree keeps applying and still ends `RESULT: PASSED`.
- `status` prints at most 20 `LAYOUT` notes, then one overflow line.
- `status --json` keeps every move in `offLayout`.
- `/doctor:overlay apply --relayout` moves the copies once.
- A copy under `root/skilled/` is a blocked overlay.

#### The Overlay Folder Can Sit Beside the Tree <a id="c-the-overlay-folder-can-sit-beside-the-tree"></a>

- `.skilled-overlays.json` can name a direct sibling, `../<name>`.
- A deeper path or a link back into the tree is refused.
- A sibling outside the tree's git repository is refused on every command.
- A re-pin backs up the sibling folder's own files.
- `repin --stage <dir>` copies the tree and the overlay folder side by side.

#### A Failed Relayout Puts Everything Back <a id="c-a-failed-relayout-puts-everything-back"></a>

- Before, a failure after the first move left a half-moved folder.
- Now every move, the manifest write and each relink are guarded.
- A failure restores the copies, the manifest and the links.
- It exits 2 with one line naming the step that failed.

#### Bad Layout Links Are Refused <a id="c-bad-layout-links-are-refused"></a>

- A manifest can list one layout link path twice.
- Paths are compared after they are normalized.
- `status` and `apply` then exit 2 before any write.
- They print `layout link path is listed twice: <path>`.
- A link path can also leave the tree.
- It may be absolute, climb out with `..` or pass an outside link.
- That prints `layout link path escapes the tree root: <path>`.
- Relayout and adopt print the same line after `refuse:`.

#### The Audit Checks Overlay READMEs <a id="c-the-audit-checks-overlay-readmes"></a>

- `status --audit` now walks the overlay folder.
- Each folder without a README prints one `DOCS` line.
- A README that fails sk-doc's validator prints one too.
- `docs=<n>` counts them.
- The check is advisory and never changes `RESULT:` or the exit.
- `--json` carries the findings under `docs`.
- A folder with no README prints `DOCS     missing-readme skilled-overlays/framework`, then `docs=1`.

#### Python Caches Stay Out of Overlays <a id="c-python-caches-stay-out-of-overlays"></a>

- A `__pycache__` folder or a `.pyc` or `.pyo` file is a cache.
- A folder named like `x.pyc` is ordinary content.
- Overlays never ship a cache, and status passes over one.
- A dropped folder that holds only caches is removed.
- When apply cannot remove one, it prints a `NOTE` and still succeeds.
- The note names the command that clears the folder.
- A re-pin backs up only the caches its apply may remove.

#### An Apply Can Change a Shape <a id="c-an-apply-can-change-a-shape"></a>

- An entry can switch between a file, a folder and a layout link.
- Apply removes its own old output and writes the new shape.
- An unowned file or folder in the way is refused.
- The refusal names the exact command to move it aside.

#### Env Templates Re-Pin Like Other Files <a id="c-env-templates-re-pin-like-other-files"></a>

- `.env.example` holds no secrets.
- The engine now reads, copies and reports it like a vendored file.
- It is the one template name the env secret guard also lets an agent read.
- Every other `.env` file stays protected.

#### Every Refusal Names the Next Command <a id="c-every-refusal-names-the-next-command"></a>

- Most engine, doctor-script and git-hook refusals now end with `Next:`.
- That line names the exact command to run.
- The write guard names its command inline instead.
- A held lock names the pid to check and the file to remove.
- `status` fails on a `REGEN` line while a regeneration is unfinished.
- A sibling stage prints `staged tree root: <dir>/<tree name>`.
- Pass that folder as `--root` to a later `status`.

#### The Release Base Takes Only a Framework Commit <a id="c-the-release-base-takes-only-a-framework-commit"></a>

- `/doctor:update record-base --pin` records the pinned commit itself.
- Before, it recorded whatever the last fetch named.
- It refuses a commit with no top-level `.skilled` folder.
- The message says to pin the framework commit the tree came from.
- A pre-commit in a linked worktree now checks the right repository.

#### The Hub Check Reads the Hub's Own Repository <a id="c-the-hub-check-reads-the-hubs-own-repository"></a>

- The parent hub check now reads a hub's data from that hub's repository.
- Before, a vendored `sk-code` hub printed 13 `5k-canary` failures.
- Now it prints `PASS: 5k-canary` and exits 0.
- A hub repository with no canary fixture reads as not applicable.

## OpenCode

Skilled ran OpenCode 1 and OpenCode 2 side by side. OpenCode 2, pinned at 2.3.2, is now the only supported major. The OpenCode 1 branches are gone from dispatch, the loops, the plugins and CI.

#### OpenCode 2 Is the Only Supported Major <a id="c-opencode-2-is-the-only-supported-major"></a>

> [!WARNING]
> Deep-loop runs refuse an OpenCode 1 binary. They find only `opencode` or `OPENCODE_BIN`, so set `OPENCODE_BIN` if you named it `opencode2`.

- Any major other than 2 now resolves as `unknown`.
- There is no separate OpenCode 1 refusal any more.
- A deep-loop run refuses an `unknown` binary as unresolved.
- The dispatch guard does not refuse it. It applies every rule instead.
- The doctor battery skips a binary it cannot place.
- The `opencode1` and `opencode2` launcher names are retired.
- CI runs the `OpenCode v2 Battery` workflow, and the v1 leg is gone.

#### The Setup Helper Installs and Checks <a id="c-the-setup-helper-installs-and-checks"></a>

> [!WARNING]
> `opencode-setup.sh` takes only `v2` or `check`. Skilled no longer removes an old OpenCode 1 install, so remove it yourself.

- `v2` installs `@opencode/cli@2.3.2` and its `opencode` launcher.
- `check` reports what each name resolves to.
- The `v1` and `both` modes are gone.
- A `remove-v1` mode was added during the cycle and removed before release.
- So the `remove-v1` step in the v4.1.0.0 notes no longer runs.

#### Plugins Build With definePlugin <a id="c-plugins-build-with-defineplugin"></a>

> [!WARNING]
> An outside plugin that imports `dualPlugin` from `.opencode/plugins/lib/v2-bridge.js` must import `definePlugin` instead.

- The builder in `v2-bridge.js` is renamed `definePlugin`.
- No alias is kept.
- The plugin inventory key `nativeDual` is now `selfRegistered`.
- Neither rename keeps the old name.

<details>
<summary><b>Smaller fixes</b></summary>

- The battery's private server starts with `opencode serve --hostname 127.0.0.1`, so other machines cannot reach it.
- The loop shell shim passes through exactly the 18 subcommands OpenCode 2.3.2 lists.
- Before, words such as `attach` and `web` opened a session outside the wrapper.
- `opencode --completions` passes through too.
- `opencode mini` and `claude attach` pass through, because a hop cannot rebuild them.

</details>

## Browser Use

The browser tools now share one hub, `mcp-browser-use`. It holds three modes. Each mode uses its CLI first. It falls back to its MCP server through Code Mode.

#### One Hub for Browser Tools <a id="c-one-hub-for-browser-tools"></a>

> [!WARNING]
> `mcp-chrome-devtools` and `mcp-aside-devtools` left `mcp-tooling`. Update any link or overlay that names their old folders.

- Both modes now live under `.skilled/skills/mcp-browser-use/`.
- `mcp-tooling` keeps its six other modes.
- The advisor sends browser requests to the new hub.
- The hub picks the mode from the tool you name.
- "Open DevTools" now reaches Chrome DevTools.
- Generic browser automation asks which tool you mean.

#### Bladebro Joins as a Mode <a id="c-bladebro-joins-as-a-mode"></a>

- `mcp-bladebro` drives the Bladebro browser.
- It is pinned to upstream v4.8.2.
- Its default browser uses its own profile.
- Real-browser lanes run only on your request.
- Stealth runs need your authorization.

- `mcp-browser-use` is the eighth hub the compiled router serves.
- One named tool routes to one mode.
- Two named tools route to both, in a fixed order.

## Upgrade Notes

Start with the numbered list, which applies to everyone. The folded groups below apply only if you use that part of Skilled.

#### Before You Start <a id="c-before-you-start"></a>

1. If you vendor Skilled, re-pin as usual. Then run `/doctor:overlay apply --relayout` once.
2. If you use OpenCode, run `bash .skilled/skills/cli-external-orchestration/cli-opencode/scripts/opencode-setup.sh check`.
3. Confirm that `opencode --version` prints `opencode v2.3.2`.

<details>
<summary><b>Deep Loop</b></summary>

- To extend a run, create it with `--convergence-mode=off` or `--stop-policy=max-iterations`.
- Read `blockedStop` as a terminal stop reason in any script that parses stop reasons.

</details>

<details>
<summary><b>Fan-Out Runs</b></summary>

- Replace `--allow-single-lineage` with `--only-lineage LABEL`, or run the single-executor workflow.
- Give every fan-out lineage a `cli-*` executor kind.
- To rerun a finished lineage, archive its `lineages/<label>/` folder first.
- Rerun a finished DeepSeek Harness fan-out that asked for `danger-full-access` with `--restart`.

</details>

<details>
<summary><b>Dispatch and Safety</b></summary>

- Set a model on single-executor codex to keep your codex config's default.
- Expect exit 64, not 1, when a dispatch setup is wrong.
- Set `SPECKIT_ALLOW_HOST_SESSION_EXECUTOR=1` only for a deliberate run from your own session.

</details>

<details>
<summary><b>Skill Advisor</b></summary>

- In a copied project, run `/doctor:update apply` to remove what the embedding lane left on this machine. It runs the cleanup after its rebuild prompt.
- In a linked project, `/doctor:update` stops at the link with `path parent is not a real directory`.
- There, run `node .skilled/skills/system-spec-kit/runtime/cli/retrieval/sweep-lane-residue.mjs machine` from the Skilled checkout instead. When it lists leftovers, run the same script's `apply`.
- Either way, the cleanup asks before it deletes the pulled shared model. Run without a terminal, `apply` keeps that model unless it gets `--shared-model delete`.
- Run `npm ci` in `.skilled/skills/system-skill-advisor/runtime` and in `.skilled/skills/system-spec-kit`. That drops the transformers package from `node_modules`.
- Remove `--include-semantic-health` and `--include-embeddings-health` from any script that calls `advisor_status`.
- Remove any lane weights setting that names the removed lane.
- If `check-native-modules.sh` exits 1, run `rebuild-native-modules.sh` from the same folder.

</details>

<details>
<summary><b>Installs and Overlays</b></summary>

- After the relayout, confirm `status` prints no `LAYOUT` line.
- Keep a sibling overlay folder inside the tree's git repository.
- If `status` exits 2 on a layout link, fix that `layoutLinks` entry first.
- Pass `record-base --pin` the framework commit your copy came from.
- Never put a copy under `root/skilled/`.

</details>

<details>
<summary><b>OpenCode</b></summary>

- Remove any old OpenCode 1 package and its `opencode1` launcher yourself.
- Point scripts that call `opencode1` or `opencode2` at `opencode`.
- Rename `dualPlugin` to `definePlugin` in any plugin you keep outside Skilled.
- Rename `nativeDual` to `selfRegistered` in any plugin inventory you carry.

</details>

<details>
<summary><b>Browser Use</b></summary>

- Point any path under `mcp-tooling/mcp-chrome-devtools` or `mcp-tooling/mcp-aside-devtools` at `mcp-browser-use`.
- Install Bladebro before its CLI lane: `npm install -g bladebro@4.8.2`.
- Remove it with `npm uninstall -g bladebro`.

</details>
