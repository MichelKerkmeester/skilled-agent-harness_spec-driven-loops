# v4.0.0.14, Opt-In Handover That Keeps Your Goal and Model

In-session handover now ships off. Under v4.0.0.13 any terminal that sourced the shell line handed over, and the 80% reminder reached sessions outside the loop as well. Now no session changes until you set `SYSTEM_SESSION_RELAUNCH_ENABLED=1`, and each runtime has its own switch, so one machine can keep it on for Pi and OpenCode and off for Claude Code.

When it is on, the fresh session picks up closer to where the old one stopped. It starts on the model and effort the sender was last using, and it carries the sender's goal on every runtime except Codex. OpenCode 2 now hands over end to end.

The rest of the release tightens the edges of a hand-over and stops the spec validator from hanging on a stuck git file-system monitor.

> Spec folder: `specs/hooks/023-session-relaunch-loop` (Level 2)

&nbsp;

## Why This Release

v4.0.0.13 made the hand-over a headline and left it on for anyone who sourced the shell line. A feature that ends your session for you should be one you choose, and a machine often wants it in one runtime and not another. The hand-over also dropped two things on the way: a model or effort you switched to mid-session and the session's goal.

&nbsp;

## What's New at a Glance

- **In-session handover ships off.** Until you set an enable flag, no session is nudged and auto-compaction handles a full context window.
- **Each runtime has its own switch.** `SYSTEM_SESSION_RELAUNCH_<RUNTIME>_ENABLED` turns one runtime on or off whatever the global flag says.
- **`/speckit:handoff` says why it refused.** While handover is off for its runtime, it stops before touching the note and names the switch that decided.
- **The fresh session keeps your model and effort.** A model or effort you switched to mid-session now survives the hop.
- **The fresh session keeps your goal.** The note names the sender's goal packet and the receiver binds it.
- **OpenCode 2 hands over.** The loop now runs end to end on OpenCode 2, which it could not do in v4.0.0.13.
- **Fewer surprises around a hand-over.** Typing on Claude Code or Codex now calls off a readied hand-over, as it already did on Pi and OpenCode.
- **The spec validator no longer hangs.** Its git calls skip the file-system monitor that could leave it waiting forever.

&nbsp;

## In-Session Handover

#### Handover Is Now Something You Turn On

v4.0.0.13 said one line in your shell turns the hand-over on. It now also needs an enable flag. Set `SYSTEM_SESSION_RELAUNCH_ENABLED=1` in `.skilled/hooks/hook-flags.env`, which git ignores, or export it from your shell profile. The shell line is still what puts your runtimes under the loop.

Without an enable flag, no session gets the 80% reminder, inside or outside the loop. The runtime's own auto-compaction handles a full context window, as it did before the hand-over existed.

**Breaking:** a terminal that handed over under v4.0.0.13 stops handing over until you set the flag.

#### One Switch Per Runtime

Each runtime has its own flag, `SYSTEM_SESSION_RELAUNCH_<RUNTIME>_ENABLED`, where `<RUNTIME>` is `CLAUDE`, `CODEX`, `PI`, `OPENCODE`, `HERMES`, `CURSOR` or `DEVIN`. A flag with a value decides for its runtime, `1` for on and `0` for off. An empty or unset flag leaves the decision to `SYSTEM_SESSION_RELAUNCH_ENABLED`. So `SYSTEM_SESSION_RELAUNCH_ENABLED=1` with `SYSTEM_SESSION_RELAUNCH_CLAUDE_ENABLED=0` hands over everywhere except Claude Code, and `SYSTEM_SESSION_RELAUNCH_PI_ENABLED=1` on its own turns it on for Pi only.

`SYSTEM_SESSION_RELAUNCH_DISABLED=1` and `SYSTEM_HOOKS_DISABLED=1` still win over every enable flag. Each flag is read from the environment first and then from `hook-flags.env`, and every hook and plugin reads them the same way. `.env.example`, `hook-flags.env.example` and `/doctor:env` list all seven, and `/doctor:env` can save any of them to `hook-flags.env`.

#### The Handoff Command Says Why It Refused

`/speckit:handoff` now checks the switch first. While handover is off for its runtime, `prepare` exits with status 2 before it reads or edits the note, inside or outside the loop. Before, a session outside the loop still had its note validated and got a claim command printed with the hand-over off.

The refusal names the switch that decided: a kill switch to unset, the runtime's own flag set to `0` or no enable flag at all, in which case it names both flags you could set. The command reports the reason and changes no flag, because turning the hand-over on is your call.

## What the Fresh Session Keeps

#### The Model and Effort You Were Using

A relaunch used to rebuild its command line from your launch flags, so the fresh session ran at the runtime's default effort and lost any model you had switched to. The wrapper now replays the launch effort in each runtime's own flag. At hand-over it also reads what the sender was last using: Claude Code and Codex from their session logs, Pi from its extension, Hermes from the model each request asked for and Cursor from its config file.

Model and effort move together. A hop onto a different model with no effort of its own starts on the runtime's default effort, never on an effort chosen for another model. On Pi a change of provider counts as a model change too. Devin carries the model only, and OpenCode 2 starts on its configured default, because its command takes neither flag.

#### Your Goal Comes With You

A relaunch starts a new session, and each runtime keeps its goal under the old one, so the fresh session used to start with no goal. The hand-over note now names the sender's goal packet whenever the sender has a goal, and the receiver binds it. A Claude Code receiver starts with `/goal` and the goal's text when it fits Claude's 4,000-character limit. Pi and OpenCode bind the packet when the fresh session starts. Devin and Cursor do the same when you start one from the printed claim command, and Hermes gets it through its spec-folder variable.

A receiver that already has a goal keeps it, and a worker the receiver dispatches never takes the goal on. Codex carries no goal yet, because the framework cannot read which packet a Codex goal belongs to. Set `SESSION_RELAUNCH_GOAL=0` to turn carry-over off.

#### OpenCode 2 Hands Over End to End

Three faults stopped the loop on OpenCode 2. The watcher ended the background server instead of the terminal app, the wrapper read OpenCode 2's exit on a stop signal as you pressing Ctrl-C and the app took longer to close than the watcher waited. All three are fixed.

The wrapper also adds `--standalone` to every OpenCode 2 launch and relaunch, so the session runs in its own server where the loop can see it, so you no longer need to pass the flag yourself. A launch that names `--server` stays on that server, prints a warning and never hands over.

## Steadier Hand-Overs

#### Typing Calls Off a Hand-Over Everywhere

A new message on Claude Code or Codex now calls off a hand-over the session had readied, so the watcher can no longer end a turn you just started. Every runtime and `session-relaunch.cjs cancel` call it off the same way, and the session gets one more reminder later. Once a hand-over is called off, the wrapper no longer starts the runtime a second time.

#### Clearer Notes and Claims

A printed manual claim command now names the model, provider and effort the sender was last using, and a session you start from it binds that note's goal. The pointer back to the note after an automatic summary now dates the note and asks for git evidence before the session trusts its remaining work. A refused claim says what a done, claimed or missing note means.

A note written from a worktree, with its spec folder under that worktree, is now accepted, where the claim used to refuse it and lose the packet. On Pi the hand-over waits for the agent to settle, so a follow-up turn no longer races it.

#### Smaller Fixes

The nudge and the wrapper now read a claim seed with one parser, so the two can no longer disagree about a note path. The shell flag reader honours the older master switch `MK_HOOKS_DISABLED` and trims spaces around a runtime name, as the other readers already did. The relaunch test suites strip any switch your shell exports, so turning the hand-over on no longer breaks them.

&nbsp;

## Spec Kit

#### The Spec Validator No Longer Hangs

`validate.sh` could sit at 0% CPU with no error in a checkout whose git file-system monitor stopped answering, because each git call waited on the monitor. Every git call the validator makes now turns the monitor off, which costs a plain index scan and returns the same output. sk-doc's citation scan, which one validator rule reuses, skips the monitor too.

&nbsp;

## Upgrade Notes

- **Turn the hand-over back on if you use it.** Add `SYSTEM_SESSION_RELAUNCH_ENABLED=1` to `.skilled/hooks/hook-flags.env` or export it. Keep the shell line from v4.0.0.13.
- **Set runtimes one by one where they should differ.** Give `SYSTEM_SESSION_RELAUNCH_<RUNTIME>_ENABLED` a `1` or a `0`.
- **Turn off goal carry-over if you do not want it.** Set `SESSION_RELAUNCH_GOAL=0`.
