# v4.0.2.1, Improved Chat Automation, Search & Session Handover

This release changes what you install, what an agent may read and what it is told to run. Skilled now needs a patched Node.js release. A new guard keeps the values in a `.env` file away from every agent. The skill advisor now names the slash command behind a hub skill. It also says whether the agent may run it.

Long sessions hand over more cleanly, and Claude Code now does it by default. Pi and OpenCode now finish a hop too, and so does Mistral Vibe. The feature now has one main name, session handover. A hop to a fresh session carries the running command, the goal and the session's name and mode. The shell shim trusts only your own checkout. Search answers now say how much they left out. A new spec document is found before the index catches up. The spec commands now save the continuity they report.

Projects that vendor Skilled get stricter overlay checks and an engine that cleans up after itself. Pi 1.5.2 loads every hook adapter again. A plain frontend request now reaches the code skill's frontend guidance. Skilled's own checks and tests also run faster.

Deep loops now stop on a decision a script computes. Each deep command runs from one workflow file. The AI Council leaves Deep Loop and becomes its own agent. A deep review now fails while a required check still fails at its stop. Scripts now compute those checks and the verdict. The agent files now ask only for steps their own tools can take.

## Why This Release

Some gaps put your project at risk. A security notice in October patched Node.js. Skilled still accepted Node 20. Any agent could read `.env` and send every secret in it to the model.

Other gaps cost your agent time. A recommendation said `sk-doc` when you asked for a README. The agent then had to find `/create:readme` on its own. A search cut at its limit never said what it hid. A session that hopped mid-command came back as a plain chat and lost its place. And handover shipped off everywhere, so most Claude Code users never had it. Pi and OpenCode did not finish a hop in a live test either. The switches still said relaunch, while the docs said handover. A spec command reported a save that never wrote a line. A deep loop left its stop call to the model running it. Two runs on the same state could stop differently. A deep review could pass while a required check failed. The model running it judged those checks. The coverage check could not read what reviews recorded. Several agent files asked for steps their own tools could not take.

## Node.js

#### Patched Releases Are Required

A security notice of 23 October 2026 named the patched releases. They are 22.23.4, 24.22.1 and 26.12.1. The Node 20 line has no patched release. Nine packages now declare `^22.23.4 || ^24.22.1 || >=26.12.1`. They used to accept Node 20.11 and later. No package sets `engine-strict`, so npm warns on an older Node and goes on. Every CI step that sets up Node now uses 22.

**Breaking:** Code Mode is stricter. Its server declares `>=24.22.1 <25.0.0`. Its launcher picks an interpreter in that range. Without one it cannot start. Run `/doctor:mcp` to check your machine.

## Dotenv Guard

#### The Guard Refuses the Read

An agent that reads `.env` puts every secret in it into the model's context. The new `env-secret-guard` hook refuses that call. It runs on Claude Code, Codex, Cursor, Devin, OpenCode, Pi, DSH and Mistral Vibe. A file counts when it is named `.env` or `.env.<suffix>`. A link to such a file counts too. The template `.env.example` stays open.

The guard catches file tools, patches and shell reads such as `cat`, `grep -f` and `cp`. It sees through quotes, `$(...)`, globs such as `.e*` and `bash -c` scripts. An app that loads its own env still runs. `node --env-file=.env app.js` and `source .env` are allowed.

#### Answers Without Values

The refusal names the way in. The guard lists the keys, reports lines that fail to parse and fingerprints one value. Two equal fingerprints mean equal values. Every runtime can run `.skilled/hooks/env-secret-guard/cli/env-secret.cjs`. OpenCode also has three `env_secret_*` tools. The fingerprint is an HMAC-SHA256 keyed by `ENV_SECRET_GUARD_PEPPER`. The key comes from your environment, never from a file. Without it, no fingerprint is returned.

#### Two More Layers Behind the Hook

A command's text does not show everything it does. So the guard records your dotenv files before a shell call. Afterwards it puts back any file that changed. It also looks for a dotenv value in the output. OpenCode and Pi replace that value before the model reads it. Mistral Vibe has no after-call check. The other runtimes can only warn that it reached the session.

Claude Code, Devin and Cursor also carry their own deny list for dotenv files. So the file stays closed if the hook fails. On DSH the guard refuses a command that prints a loaded value, such as `printenv`. Every adapter fails open, so a guard bug never stops an agent. `SYSTEM_ENV_SECRET_GUARD_DISABLED=1` turns the guard off. It is read from the environment only.

## Skill Advisor

#### A Hub Skill Names the Command to Type

The advisor used to say `sk-doc` for "create a readme". You then had to find `/create:readme` yourself. Now a hub recommendation carries the command for the mode it picked. A brief head reads `use system-spec-kit → /speckit:plan (start)`. A hub that cannot pick one mode says so, as `sk-doc (needs a mode)`. A deep-loop command is offered only when the prompt asks for depth.

#### Every Command Has a Run, Start or Ask Policy

Each of the 44 tracked commands records what it writes and what it must ask first. The generator turns that record into one policy. `run` means the agent may run it now. `start` means it starts without `:auto`, so its setup asks. `ask` means it offers the command and waits. Gate 2 in `AGENTS.md` now tells the agent how to follow each one. A typed command or a direct instruction outranks the policy.

A typed slash command now reaches the model on every tracked row, with its policy and owner skill. Plain requests reach their command more often too. Paraphrases the tuning never saw still mostly miss.

#### Meaning Matching Has Its Own Doctor Route

A command can also pass on meaning when the local embedder runs. Each scored command row carries its own vector. A prompt needs a close match and a clear lead over the next command. A prompt that asks for no change gets no command this way. `/doctor:skill-advisor embedder` checks the embedder and plans each missing step. It asks before it pulls a model or starts a server. It never installs Ollama itself. The prompt embedding gives up after 750 ms.

#### Doctor Checks Show Whether the Brief Arrives

`/doctor:setup` gains two read-only legs. The embedder leg reads DEGRADED when meaning matching is off. The delivery leg reads DEGRADED when a prompt hook is missing or not approved. On Codex, no brief arrives until you approve the project hooks. A default `embed` now leaves Claude Code a one-line `CLAUDE.md` pointer to `AGENTS.md`.

#### Smaller Fixes

- **A question about the trigger index reaches spec-kit.** It used to end at the doctor helper. A question about index drift still goes to the doctor.
- **The doctor hand-off names the matched command.** It used to name only `/doctor:helper`, even when the exact command was known.
- **A prompt that names a `system-`, `cli-` or `mcp-` skill is read.** The prompt policy used to read only `sk-` names.
- **An OpenCode brief names the command and its policy.** The plugin used to drop both.
- **Three plain spec requests now reach spec-kit.** The advisor used to miss them.
- **A read-only question about git history reaches sk-git.** `show the git log` used to return no skill. The question must name git, a commit or one of the branches main, master and develop.
- **The advisor starts on the Node.js its native module was built for.** An install now records that Node.js. A session on another major version used to fail its first call with `daemon launcher exited with code 1`.
- **A deep review request reaches Deep Loop.** "deep review this branch" now gets `/deep:review`. A question about the AI council gets `/speckit:ai-council`.
- **A hub with many modes routes fast.** The compiled route built one rule for every subset of a hub's modes on every call. A hub with 18 modes built 262,125 rules and timed out. A rule now covers at most four modes.
- **A typed session handover names `/speckit:handoff`.** The advisor named no command for `session handover`, `in session handover` or `session-handover`. It now names the handoff command for all three.

## Session Handover

#### One Main Name Covers the Feature

The hook folder is now `.skilled/hooks/session-handover/`. The main switch is `SYSTEM_SESSION_HANDOVER_ENABLED`. Each runtime has its own, such as `SYSTEM_SESSION_HANDOVER_CODEX_ENABLED`. Tuning variables use the `SESSION_HANDOVER_` prefix, such as `SESSION_HANDOVER_THRESHOLD`. A new session opens with its seed, `[session-handover] claim and continue handoff`. That is the first line you see. The docs use the same name. Bare relaunch names stay on files and folders, such as `relaunch.log` and the `skilled-relaunch` folder. An installed project must render its hooks again, or its registrations still name the old folder.

#### Old Switch Names Stop Working

**Breaking:** A switch under an old name is no longer read. `SYSTEM_SESSION_RELAUNCH_ENABLED=0` does nothing now. A Claude Code user who had switched handover off gets it back. It stays on until you set `SYSTEM_SESSION_HANDOVER_ENABLED` to 0. Rename each switch in your shell profile or `hook-flags.env`.

**Breaking:** An open handoff note in the old state folder is not found. Move `.skilled/skills/.state/session-relaunch/` to `.skilled/skills/.state/session-handover/` in each checkout. Move it once the checkout runs this release, since sessions on the old code still write there.

#### The In-Session Spelling Also Works

The switches also accept `SYSTEM_IN_SESSION_HANDOVER_*` as a second spelling. That covers the enable, disable and per-runtime enable switches. It answers only while the main switch is unset or blank, so the main name wins when both hold a value. Tuning variables have no second spelling. `/doctor:env` names the conflict when both spellings hold different values.

#### Claude Code Hands Over by Default

Handover used to ship off on every runtime. A project that installed Skilled never got it unless someone found the switch. Now Claude Code is on when no switch is set. Codex, Pi, OpenCode, Cursor, Devin and Vibe stay off until you turn them on. Under the `skilled-loop` wrapper, a Claude session at 80% writes a handoff note and ends. A fresh session starts in the same terminal and claims the note. Without the wrapper, the session keeps the note and works on. After auto-compaction it is pointed back at that note. `SYSTEM_SESSION_HANDOVER_CLAUDE_ENABLED=0` turns the default off, and so does a global `SYSTEM_SESSION_HANDOVER_ENABLED=0`.

#### A Hop Carries the Command, the Goal and Live Work

A session that hopped mid-command used to come back as a plain chat. Now the handoff note carries an `Active command:` line. The next session runs that command again, with the same mode and arguments. The command finds its own step. A held deep-loop lock is released first, so the rerun does not wait for it. The note's Goal opens with the packet's purpose line from its `spec.md`, so the why survives each hop. The note also lists running workers, scheduled tasks and added directories. The next session collects a live worker instead of starting it twice. A fan-out rerun now refuses while a lineage from the last run is still alive. A Claude session that never set a goal now hands on its packet's goal. The next session starts on `/goal` with it. Only an unfinished goal in the note's folder or its parent counts. A goal you met, failed or cleared stays ended on every later hop. A session log over 16 MB is now searched whole for its goal. A goal that cannot be carried prints one `goal not carried:` line with the reason. Cursor and Devin keep the goal they were handed. Pi and OpenCode bind the hop goal once, so `/new` or `/fork` starts clean. With goal autonomy on, OpenCode no longer pulls a prepared hop back into work.

#### Pi and OpenCode Finish a Hop

In a live test, a hop on Pi or OpenCode never finished. Pi held its nudge until the whole run ended, so a run that kept calling tools never saw it. OpenCode 2 read its own session as a nested run, so `prepare` printed a claim command instead of arming the hop. Both now finish the same hop as Claude Code, with no input from you. Pi sends the nudge at the end of each turn that used tools, so the model reads it before its next call.

OpenCode 2 still drops a model you pick mid-session. Its root command has no model flag, so the next session starts on the project's model.

#### Mistral Vibe Hands Over on Its Own

Mistral Vibe reads its own switch now, `SYSTEM_SESSION_HANDOVER_VIBE_ENABLED`. Set it to 1 and start Vibe through `skilled-loop vibe`. When the session nears the point where Vibe would compact, it is told to write a handoff note. Its turn ends, and a fresh Vibe session starts, claims the note and finishes the work. Two live hops did all of this with no input, the same as Claude Code. If you type while the hand-over is armed, it is called off and your session carries on.

The nudge can arrive after a tool call, so a long turn hears it too. Vibe gives its tools no session id, so the turn-start hook records it for the loop. A hand-over you start by typing `/speckit-handoff` under `skilled-loop vibe` reads that id and arms the hop too.

A Vibe sender used to be told that nothing would end its session. In one live hop it spent 76 seconds arguing with that line. Now it is told to stop, and two live hops signalled about 5 seconds after `prepare`. Your next prompt now calls off a pending hop before slower turn-start work runs. `skilled-loop vibe` warns when an exported `MISTRAL_API_KEY` would bill outside your Vibe plan.

#### A Claimed Note Offers the Sender's History

A session that took over used to know only what the note said. In a live test, six of six receivers answered `UNKNOWN` when asked for a detail the note left out. Now `claim` prints a `## History Lookup` section after the note body. It holds one read-only command that searches and loads the sender's earlier turns for 30 minutes after the claim. With it, three of three receivers looked the detail up and answered correctly. Claude Code, Codex and Mistral Vibe senders get the section. It is left out when the sender ran in another checkout or the runtime is not built.

**Breaking:** The lookup is no longer offered after a compaction, on any runtime. The OpenCode plugin `session-history-lookup.js` is gone. Compaction summaries and the `/speckit:resume` pointer are unchanged.

The lookup also refused any Claude Code session that ran two tools in one message. The shared transcript reader now reads those lines as one turn.

#### Smaller Fixes

- **A waiting hop never stalls in silence.** On Claude Code only the Stop hook arms a hop, and a question dialog after `prepare` kept the turn open. That dialog is now refused while the hop can still arm, on Claude Code, Pi and OpenCode. A hop waiting on background tasks says so at each Stop. A Stop that cannot arm names the cause. Your next prompt calls a waiting hop off. Pi and OpenCode also tell the model when a new prompt withdraws a hop.
- **A compacted Codex session finds its note.** After a compaction, Codex is pointed at the open note, the way Claude Code already was. If the note is stale, Codex is told so instead.
- **A Pi receiver keeps its claim instructions.** Other extensions add blocks to the seed. The receiver asked for a spec folder again. Pi now reads the seed from its first block.
- **The claim output names the closing step.** Codex claimed its note and never closed it. `claim` now prints the `complete` command after the note body, on every runtime.
- **The shell shim runs only a wrapper it trusts.** It used to run the first `.skilled/bin/skilled-loop` above your folder, so a cloned repository could supply it. It now runs one only in its own checkout or a linked worktree. List another checkout in `SKILLED_LOOP_TRUSTED_CHECKOUTS`.
- **A hop keeps your name, mode and launch flags.** A launch name, a `/rename` title or Claude's own title carries over, numbered `<title> (2)`, then `(3)`. A Claude permission mode and Pi's Plan or Build mode carry too. A live `plan` mode stays behind, so no session stalls on its claim. A flag such as `--add-dir` now comes back. Flags that pick a session, such as `--resume`, are still left out.
- **The wrapper's own lines are right.** A running loop keeps the code it started with, and now says when its file changed: `note: skilled-loop changed on disk after this loop started, restart the wrapper to run the new code`. A declined hop's `skilled-loop <runtime>` line now runs as pasted.
- **An OpenCode parent waits for its sub-agents.** It used to hand over while a background child still worked. The next session also takes the launch name as its title.
- **An unknown Claude window stays quiet.** The nudge assumed 200,000 tokens when no window was set. It now logs `context-nudge-skipped reason=window-unknown` once instead.
- **No folder or old process can plant a hop.** A linked or foreign folder could plant a record that approved a hop. So could a closed terminal whose process id a new wrapper reused. State is now read only from a checked folder, and a new loop removes its own old record.
- **A sub-agent cannot cancel or consume a handover.** The guard refused four lifecycle commands. It now refuses all seven.
- **One waiter reclaims a stale lock.** Several waiters could each remove an old lock and all enter at once.
- **A provider key no longer blocks an OpenCode dispatch.** The cli-opencode guard now ignores `OPENCODE_API_KEY`. Every other `OPENCODE_` variable still trips it.
- **The cli-opencode docs name the OpenCode 2.3.0 commands.** Credentials are under `opencode auth list`. Agents are listed by `opencode debug agents`.

## Search

#### A Cut Answer Says What It Hid

The trigger lookup now returns `totalCandidates`. That is the number of documents that matched before `--limit` cut the list. The text view marks a cut answer as `candidates : 2 of 828 (truncated) from 1070 phrase(s)`. Each row also lists the phrases that matched. A crash inside the lookup used to exit 1, the code for no match. It now prints the error and exits 2.

#### A New Spec Document Is Found Right Away

CI rebuilds the index only after a push. So a packet written an hour ago returned nothing. Now a lookup with no hits compares the `specs/` tree with the paths in the index. It reads the trigger phrases of up to 500 unlisted documents and scores them. JSON then carries `staleFallback`. A phrase edited inside an indexed document still needs a rebuild.

#### Free-Text Search Shows Each File Once

One busy file used to fill every row. `rg-wrapper.mjs structured` now ranks every match, then keeps the best row per file. `--limit` counts files, with 20 as the default. A cut answer ends with a line such as `+1382 more files with 2681 matches`. `/speckit:search` now runs this wrapper for its default search. The `path` and `count` lists are cut at the limit too.

## Spec Workflow

#### Agents Reread the Request Before Done

Acceptance rows come from the spec. An outcome you asked for can be missing there while every check passes. The agent now maps each requested outcome to a met row. Otherwise it names that outcome as not done. The completion hook repeats the reminder on every done claim. It never blocks.

#### Spec Commands Do What They Report

Saves used to write nothing. Plan, implement and complete passed the writer a temp file. They left out `--full-auto`. So the writer only planned, while each step said it saved. Now every save sends its data straight to `generate-context.js --stdin --full-auto`. One strict check runs after it. Each command now saves once. The saves along the way are gone. So is the offer of a second save at the end.

Checks now run after the work they check. Implement used to mark its acceptance checks as met before any code existed. Now it writes them before the build. A new step checks them after it. Plan writes `tasks.md` in a step of its own. Only one step creates the spec folder. Phase splitting takes its level from `recommend-level.sh`.

A check passes only when every part passes. A missing file fails it. So does a file that still holds placeholder text. The message names the parts that failed. A serious gap between the spec, plan and tasks stops the run before the build. After three failed rounds the run stops. It lists what is still open. Checks that no step could ever pass are gone.

You cannot finish without a code review now. A `REQUESTED_CHANGES` answer sends the run back to the build once. A second one stops the run. Plan now sends out only its four context agents. Each agent uses the model its own file names. Each finding names a file and a line.

A command sometimes stops to ask you something. Each of those places now says what confirm, auto and autopilot do. Auto asks only when confidence is below 40. It also asks the spec folder question. Autopilot never asks. You give it its workspace as `workspace_choice`. It makes a branch only with `git worktree add -b`. It never merges or pushes. It ends on one `SPECKIT_AUTOPILOT_RESULT` line. With no workspace set, it stops with `uncertainty_blocked`. It stops before it writes anything.

Resume with no folder now looks in a fixed order. First it takes the folder you typed. Then it reads this session's handoff note. Then it finds the packet tied to this session. It never reads another session's note. If nothing matches, auto says there is no session. Confirm lists up to three recent packets, each marked as not matched. Its panel starts with "No packet is matched to this session." A handoff note counts at any age. One `speckit-resume.yaml` replaces the separate auto and confirm files. Resume no longer matches fixed phrases. It no longer looks in `.opencode/specs/`. It no longer guesses by meaning.

Planning no longer writes `research/research.md`. It lists unknowns in the Technical Context of `plan.md`. An unknown that needs real digging points to `/deep:research`.

#### The Restraint Check Runs When Scope Is Written

The overengineering rule used to wait for code. By then a spec had frozen the addition into scope. The rule now fires on a spec or plan that adds a file, option, layer or dependency. `/speckit:plan` and `/speckit:complete` ask what fails today without it.

#### Packets Move by Command

Moving a spec packet used to mean `git mv` and edits by hand. Many records then kept the old path. Now `relocate.mjs` moves, renumbers or re-parents a packet. It updates every record of the path. A run only shows its plan until you add `--apply`. A dry run ends on a line like this: `moves=1 moved=0 rewrites=33 identity=1 roots=3 ledger=1`. A move that stopped halfway finishes when you run it again. Exit 3 means the move landed, but the packet failed its own checks.

Archived packets are now in reach. `rg-wrapper.mjs --include-archive` searches them. It marks each hit `[archived]`. `validate.sh --recursive --include-archive` checks them too. A new packet never takes an archived number. `suggest-subtracks.mjs` suggests sub-tracks for a long flat track. It changes no files.

#### Reply Rules Are Two Files

Gate 6 named five rule files to load around a reply. Three mostly repeated the others, so they are retired. They are `answer-the-actual-request.md`, `communication-prose.md` and `communication-decisions.md`. Their unique clauses moved into `communication.md` and `uncertainty-and-honesty.md`. Gate 6 now loads `communication.md` before a reply. It loads `communication-handoff.md` before a turn ends.

#### Smaller Fixes

- **A track that mixes packets and sub-tracks fails the sweep.** `sweep-track-roots.mjs` names the flat packets and exits 1. The pre-push check runs it.
- **`/speckit:implement` stops where it should.** It stops on a failing test and on a plan with an open design choice.
- **A plan names the file each phase touches.** A new spec folder also points chat sessions at the authoring card.
- **A waiting save gets its turn.** It could starve behind another process's queued saves.
- **An autonomous changelog release stops on an uncommitted entry.** It also writes the rollback beside each release step.
- **Release notes are detailed by default.** An entry must explain each feature, name every fix and show how it was checked.
- **`/speckit:implement` runs on a worktree branch.** It used to read the packet from the branch name. It stopped with "Not on a feature branch". Now the workflows give `check-prerequisites.sh` your spec folder.
- **`/speckit:save` has one way to write.** Its screen shows blockers, warnings, open decisions and abandoned sessions. Its result comes from the writer's own output.
- **`/speckit:search` explains its flags and errors.** Both kinds of search explain `--limit`. A query that starts with `--` goes to the plain search. Exit 2 or higher always means an error.
- **`/speckit:handoff` says what it does in one place.** Its four status lines sit in one table. It says that `prepare` refuses DSH.
- **Every page about a spec command agrees.** The router, README, dashboard and success line give the same step counts. Plan has 7 steps. Implement has 9. Complete has 13 and resume has 5.
- **Setup asks only what a workflow uses.** The Dispatch Mode question is gone. No workflow used the answer.
- **The spec workflows share one copy of common parts.** Check rules, checkpoint choices, goal prompts, documentation levels and phase splitting now live in `speckit-lifecycle-shared.yaml`. Every path the workflows name now exists. Steps and timers that nothing used are gone.

## Deep Loop

#### A Script Makes the Stop Call

The stop vote used to live as prose in the workflow files. So the model running the loop did the arithmetic. It could reach a different answer on the same state. Now `convergence.cjs --stop-decision` computes the vote. It prints one `stop_decision` object, and the workflow only follows it. Both loops share one list of eight stop reasons. The finer cause sits in `reasonDetail`. The review vote follows your `convergenceThreshold` instead of two fixed numbers.

#### Counts Survive a Resume

The stuck count used to live in the model's memory. A resume lost it. Now the loop rebuilds its stuck and failure counts from the state log on every pass. A resumed run counts the same as one that never paused. A failed pass no longer counts toward convergence. Three failed passes in a row end the loop with reason `error`. Auto then writes up the partial findings. Confirm asks Retry, Skip or Cancel first.

#### Research Runs Restart and Respect Their Limits

A research run in auto mode had no way to restart. A review restart wrote generation 1 into its new config. Now `--restart` works on both commands. The run archives the old packet and keeps its lineage. The packet lock lasted 30 minutes while one dispatch may run 60. The lock now lasts as long as the dispatch timeout. Every halt releases it. `maxDurationMinutes` now ends a run when its time is up. The loop then writes up its findings with reason `maxDurationReached`. The time check runs on every pass. It first sat above the step each pass returns to, so only the first pass ran it.

#### Each Command Runs From One Workflow

Each deep command kept an auto file and a confirm file, and they had drifted. Confirm runs lacked five executor kinds. They also lacked 11 research steps and 4 review steps. Only research confirm could dry-run. Now `/deep:research` and `/deep:review` each run from one workflow file. Confirm only adds its approval gates. So confirm runs gain the heartbeat, the run-now check and every executor kind. `--dry-run` works in both modes.

#### The AI Council Is Its Own Agent

**Breaking:** `/deep:ai-council` is gone. Deep Loop now routes research and review only. The council used to be a third Deep Loop mode, `deep-ai-council`. Its agent leaned on scripts inside that mode. It also ran `node` while its own settings denied the shell. Now `@ai-council` stands alone. `/speckit:ai-council` binds the spec folder and dispatches it once. The agent runs every round itself, three by default. It writes only `ai-council/**` files in the packet. A divergent review pivot still asks the council for a new direction.

#### Deep Loops Fail Clearly

A chat session could call the fan-out runner with one lineage. One process then wrote every iteration and skipped the loop's own setup and save steps. `fanout-run.cjs` now refuses that and names the single-executor workflow. A provider quota refusal now counts as `quota`, not as a crash. A review fan-out takes `--review-target`. A Codex effort above the model's ceiling fails before dispatch.

#### Each Pass Keeps Its Executor

A pass run by a CLI executor used to lose its executor in the state log. The pre-dispatch audit wrote the `iteration_start` row straight into the log. The next refresh rebuilt the log from the ledger and dropped it. Now that row goes through the append gateway. So do the dispatch failure row, the receipt write failure row, `verification_degraded` and both containment rows. A log with no ledger keeps the direct write. A failure row the gateway refuses is written directly, and stderr says the next refresh drops it.

`verify-iteration.cjs` now checks that the executor was recorded. A non-native pass that names no executor fails with `executor_missing`. The gate reads the executor kind from the run config, so native and unconfigured runs pass. A fan-out lineage is checked against the `invocation-metadata.json` the runner writes into its folder. A missing file or a different kind fails it. A pass recorded before this release names no executor, so checking it again fails.

#### A Review Fails While a Required Check Fails

A deep review used to set its verdict from P0 findings alone. P0 is the blocking severity. So a review could stop at its iteration limit with coverage failing and still report PASS. Now the review follows its own contract. It returns FAIL when a P0 is open or a required check still fails at the stop. The three checks are evidence, scope and coverage.

Every stop now writes one record of the three results before the write-up. That covers the iteration limit, the time limit, three failed passes and every manual stop. The verdict, the dashboard and the fan-out merge all read that record. Only the checks at the last stop count, so a run blocked earlier that later converges still passes. A check nobody judged is refused, not read as passing. `terminal-gates.cjs` computes the three checks from the loop's state. `review-verdict.cjs` turns them into the verdict, and the fan-out merge uses the same rule. So the same state always gives the same verdict. A failed check script counts all three checks as failed.

#### Reviews Count What They Record

Review passes record their traceability results in several shapes. The coverage check read only one of them. None of the 12 latest reviews could pass it. It now reads every shape seen in real runs. The pass prompt now shows the shape the check reads. A core check left partial or deferred still fails coverage, as the review contract says.

The scope check compared a finding written as `file:42` with `file` and failed it. It now drops the line number first. A finding in the reviewed packet's own docs now counts as in scope.

#### Smaller Fixes

- **Mistral Vibe runs bill your Vibe plan.** A dispatch now uses the key your `vibe --setup` sign-in stored, so it draws on the Vibe budget. A spent budget now stops the run as `quota`, not as a crash.
- **A finished run's last records name the run.** They used to carry the folder name `review` as the session id.
- **A fan-out lineage with no registry still counts in the merge.** It used to drop out of the merged verdict, even with a failed check in its state log. Now that check fails the merged verdict.
- **A research pass that cannot recover its sources says why.** It reports `timeout` or `stuck` instead of `error`.
- **Deep-loop scripts no longer stall on an open stdin.** A runner that left stdin open could hang them. A non-blocking stdin crashed them with `EAGAIN`.
- **One DeepSeek Harness lineage runs as a single-executor loop.** It runs through `dispatch-iteration.cjs` and needs `--spec-folder`.
- **Deep-loop saves write continuity.** The save ran the continuity writer without `--full-auto`, so it only planned. Now both workflows pass `--full-auto`. Their payloads carry `recent_action`, `next_safe_action`, `blockers` and `key_files`.
