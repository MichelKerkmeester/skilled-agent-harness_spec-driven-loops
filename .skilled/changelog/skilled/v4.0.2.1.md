# v4.0.2.1, Improved Chat Automation, Search & Session Handover

Long sessions hand over more cleanly, and Claude Code now does it by default. The feature has one main name, session handover. A hop to a fresh session carries the running command, the goal and the session's name and mode. Pi, OpenCode and Mistral Vibe now finish a hop too.

The skill advisor now names the slash command behind a hub skill. It also says whether the agent may run it. Mistral Vibe joins as the eighth runtime. Deep loops now stop on a decision a script computes. The AI Council leaves Deep Loop and becomes its own agent. A deep review fails while a required check still fails.

Search answers say how much they left out. A new spec document is found before the index catches up. The spec commands now save the continuity they report. A plain frontend request now reaches the code skill's frontend guidance.

Projects that vendor Skilled get stricter overlay checks and an engine that cleans up after itself. The engine keeps its records through a failed run and says what it skipped. Claude Code can keep your own copy of Skilled's hooks in step. Hook folders now carry names that say what they guard.

This release also changes what you install and what an agent may read. Skilled now needs a patched Node.js release. A new guard keeps the values in a `.env` file away from every agent. Pi 1.5.2 loads its guards again. The shell shim trusts only your own checkout. The dispatch audit log hides a password written inside a URL.

&nbsp;

## Why This Release

These gaps broke a setup, lost work or cost your agent time:

- Handover shipped off everywhere, so most Claude Code users never had it.
- A session that hopped mid-command came back as a plain chat.
- Pi and OpenCode did not finish a hop in a live test.
- A recommendation said `sk-doc` when you asked for a README. The agent then had to find `/create:readme` on its own.
- A deep review could pass while a required check failed.
- A search cut at its limit never said what it hid.
- An overlay re-pin could write one array item's value into another and still pass.
- A failed overlay apply could lose the record of what it wrote.
- A spec command reported a save that never wrote a line.
- A copy of Skilled's hooks in your own Claude settings went stale and failed outside Skilled.

Other gaps put your project at risk:

- A security notice in October patched Node.js. Skilled still accepted Node 20.
- Any agent could read `.env` and send every secret in it to the model.
- On Pi 1.5.2, no session ran with its guards.
- The shell shim ran a wrapper that a cloned repository could supply.
- The dispatch audit log kept any password written inside a URL.

## Session Handover

#### Claude Code Hands Over by Default

Handover used to ship off on every runtime. A project that installed Skilled never got it unless someone found the switch. Now Claude Code is on when no switch is set. Codex, Pi, OpenCode, Cursor, Devin and Vibe stay off until you turn them on.

How it works on Claude Code:

- Under the `skilled-loop` wrapper, a session at 80% writes a handoff note and ends.
- A fresh session starts in the same terminal and claims the note.
- Without the wrapper, the session keeps the note and works on. After auto-compaction it is pointed back at that note.

`SYSTEM_SESSION_HANDOVER_CLAUDE_ENABLED=0` turns the default off. So does a global `SYSTEM_SESSION_HANDOVER_ENABLED=0`.

#### Old Switch Names Stop Working

**Breaking:** A switch under an old name is no longer read. `SYSTEM_SESSION_RELAUNCH_ENABLED=0` does nothing now. A Claude Code user who had switched handover off gets it back. It stays on until you set `SYSTEM_SESSION_HANDOVER_ENABLED` to 0. Rename each switch in your shell profile or `hook-flags.env`.

**Breaking:** An open handoff note in the old state folder is not found. Move `.skilled/skills/.state/session-relaunch/` to `.skilled/skills/.state/session-handover/` in each checkout. Move it once the checkout runs this release. Sessions on the old code still write there.

#### One Main Name Covers the Feature

The new names:

- The hook folder is now `.skilled/hooks/session-handover/`.
- The main switch is `SYSTEM_SESSION_HANDOVER_ENABLED`.
- Each runtime has its own, such as `SYSTEM_SESSION_HANDOVER_CODEX_ENABLED`.
- Tuning variables use the `SESSION_HANDOVER_` prefix, such as `SESSION_HANDOVER_THRESHOLD`.
- A new session opens with its seed, `[session-handover] claim and continue handoff`. That is the first line you see.

The docs use the same name. Bare relaunch names stay on files and folders, such as `relaunch.log` and the `skilled-relaunch` folder. An installed project must render its hooks again, or its registrations still name the old folder.

#### The In-Session Spelling Also Works

The switches also accept `SYSTEM_IN_SESSION_HANDOVER_*` as a second spelling. That covers the enable, disable and per-runtime enable switches. It answers only while the main switch is unset or blank. So the main name wins when both hold a value. Tuning variables have no second spelling. `/doctor:env` names the conflict when both spellings hold different values.

#### A Hop Carries the Command, the Goal and Live Work

A session that hopped mid-command used to come back as a plain chat. Now the handoff note carries an `Active command:` line. The next session runs that command again, with the same mode and arguments. The command finds its own step. A held deep-loop lock is released first, so the rerun does not wait for it.

The note also carries the why and the live work:

- The note's Goal opens with the packet's purpose line from its `spec.md`. So the why survives each hop.
- The note lists running workers, scheduled tasks and added directories. The next session collects a live worker instead of starting it twice.
- A fan-out rerun now refuses while a lineage from the last run is still alive.

A Claude session that never set a goal now hands on its packet's goal. The next session starts on `/goal` with it. Only an unfinished goal in the note's folder or its parent counts. A goal you met, failed or cleared stays ended on every later hop. A session log over 16 MB is now searched whole for its goal. A goal that cannot be carried prints one `goal not carried:` line with the reason.

Cursor and Devin keep the goal they were handed. Pi and OpenCode bind the hop goal once, so `/new` or `/fork` starts clean. With goal autonomy on, OpenCode no longer pulls a prepared hop back into work.

#### A Claimed Note Offers the Sender's History

A session that took over used to know only what the note said. In a live test, six of six receivers answered `UNKNOWN` when asked for a detail the note left out.

Now `claim` prints a `## History Lookup` section after the note body. It holds one read-only command. That command searches and loads the sender's earlier turns for 30 minutes after the claim. With it, three of three receivers looked the detail up and answered correctly.

Claude Code, Codex, Mistral Vibe, Pi and OpenCode senders get the section. Each browsed turn shows the tool call it made, such as `bash {"command":"wc -l README.md"}`. The section is left out when the sender ran in another checkout or the runtime is not built. The lookup also refused any Claude Code session that ran two tools in one message. It now reads those lines as one turn.

**Breaking:** The lookup is no longer offered after a compaction, on any runtime. The OpenCode plugin `session-history-lookup.js` is gone. Compaction summaries and the `/speckit:resume` pointer are unchanged.

#### Pi and OpenCode Finish a Hop

In a live test, a hop on Pi or OpenCode never finished. Pi held its nudge until the whole run ended. So a run that kept calling tools never saw it. OpenCode 2 read its own session as a nested run. So `prepare` printed a claim command instead of arming the hop.

Both now finish the same hop as Claude Code, with no input from you. Pi sends the nudge at the end of each turn that used tools. So the model reads it before its next call.

OpenCode 2 still drops a model you pick mid-session. Its root command has no model flag. So the next session starts on the project's model.

#### Mistral Vibe Hands Over on Its Own

Mistral Vibe reads its own switch now, `SYSTEM_SESSION_HANDOVER_VIBE_ENABLED`. Here is the hop, step by step:

1. Set the switch to 1 and start Vibe through `skilled-loop vibe`.
2. When the session nears the point where Vibe would compact, it is told to write a handoff note.
3. Its turn ends.
4. A fresh Vibe session starts, claims the note and finishes the work.

Two live hops did all of this with no input, the same as Claude Code. If you type while the hand-over is armed, it is called off and your session carries on.

The nudge can arrive after a tool call, so a long turn hears it too. Vibe gives its tools no session id. So the turn-start hook records it for the loop. A hand-over you start by typing `/speckit-handoff` under `skilled-loop vibe` reads that id and arms the hop too.

A Vibe sender used to be told that nothing would end its session. In one live hop it spent 76 seconds arguing with that line. Now it is told to stop. Two live hops signalled about 5 seconds after `prepare`. Your next prompt now calls off a pending hop before slower turn-start work runs. `skilled-loop vibe` warns when an exported `MISTRAL_API_KEY` would bill outside your Vibe plan.

#### Smaller Fixes

- **The shell shim runs only a wrapper it trusts.** It used to run the first `.skilled/bin/skilled-loop` above your folder, so a cloned repository could supply it. It now runs one only in its own checkout or a linked worktree. List another checkout in `SKILLED_LOOP_TRUSTED_CHECKOUTS`.
- **No folder or old process can plant a hop.** A linked or foreign folder could plant a record that approved a hop. So could a closed terminal whose process id a new wrapper reused. State is now read only from a checked folder. A new loop removes its own old record.
- **A sub-agent cannot cancel or consume a handover.** The guard refused four lifecycle commands. It now refuses all seven.
- **A waiting hop never stalls in silence.** On Claude Code only the Stop hook arms a hop. A question dialog after `prepare` kept the turn open. That dialog is now refused while the hop can still arm, on Claude Code, Pi and OpenCode. A hop waiting on background tasks says so at each Stop. A Stop that cannot arm names the cause. Your next prompt calls a waiting hop off. Pi and OpenCode also tell the model when a new prompt withdraws a hop.
- **A hop that cannot arm is called off.** On Codex, Pi and OpenCode, a turn end that failed to arm left its record waiting. A later turn could then hop from a stale note. The record is now marked deferred, and your next prompt withdraws it.
- **A hop keeps your name, mode and launch flags.** A launch name, a `/rename` title or Claude's own title carries over, numbered `<title> (2)`, then `(3)`. A Claude permission mode and Pi's Plan or Build mode carry too. A live `plan` mode stays behind, so no session stalls on its claim. A flag such as `--add-dir` now comes back. Flags that pick a session, such as `--resume`, are still left out.
- **A relaunched session carries one number.** A title could stack numbers, such as `ENGINE LIMITS (2) (4)`. A hop now replaces every trailing number, even one in the launch name. A loop started inside another looped session also counts from 0.
- **A nudge arrives once.** Two hooks running at once could deliver the same nudge twice, 16 ms apart. Claude Code, Codex and Vibe now deliver it once.
- **A compacted Codex session finds its note.** After a compaction, Codex is pointed at the open note, the way Claude Code already was. If the note is stale, Codex is told so instead.
- **The claim output names the closing step.** Codex claimed its note and never closed it. `claim` now prints the `complete` command after the note body, on every runtime.
- **A Pi receiver keeps its claim instructions.** Other extensions add blocks to the seed. The receiver asked for a spec folder again. Pi now reads the seed from its first block.
- **An OpenCode parent waits for its sub-agents.** It used to hand over while a background child still worked. The next session also takes the launch name as its title.
- **A provider key no longer blocks an OpenCode dispatch.** The cli-opencode guard now ignores `OPENCODE_API_KEY`. Every other `OPENCODE_` variable still trips it.
- **An unknown Claude window stays quiet.** The nudge assumed 200,000 tokens when no window was set. It now logs `context-nudge-skipped reason=window-unknown` once instead.
- **One waiter reclaims a stale lock.** Several waiters could each remove an old lock and all enter at once.
- **The wrapper's own lines are right.** A running loop keeps the code it started with. It now says when its file changed: `note: skilled-loop changed on disk after this loop started, restart the wrapper to run the new code`. A declined hop's `skilled-loop <runtime>` line now runs as pasted.
- **The cli-opencode docs name the OpenCode 2.3.0 commands.** Credentials are under `opencode auth list`. Agents are listed by `opencode debug agents`.
- **The handover docs name what the code does.** Cursor's handoff command is `/speckit-handoff`, and a linking repository needs `.vibe` too. The env reference now lists every variable the wrapper exports.

## Skill Advisor

#### A Hub Skill Names the Command to Type

The advisor used to say `sk-doc` for "create a readme". You then had to find `/create:readme` yourself. Now a hub recommendation carries the command for the mode it picked. A brief head reads `use system-spec-kit → /speckit:plan (start)`. A hub that cannot pick one mode says so, as `sk-doc (needs a mode)`. A deep-loop command is offered only when the prompt asks for depth.

#### Every Command Has a Run, Start or Ask Policy

Each of the 44 tracked commands records what it writes and what it must ask first. The generator turns that record into one policy:

- `run` means the agent may run it now.
- `start` means it starts without `:auto`, so its setup asks.
- `ask` means it offers the command and waits.

Gate 2 in `AGENTS.md` now tells the agent how to follow each one. A typed command or a direct instruction outranks the policy.

A typed slash command now reaches the model on every tracked row, with its policy and owner skill. Plain requests reach their command more often too. Paraphrases the tuning never saw still mostly miss.

#### Doctor Checks Show Whether the Brief Arrives

`/doctor:setup` gains two read-only legs. The embedder leg reads DEGRADED when meaning matching is off. The delivery leg reads DEGRADED when a prompt hook is missing or not approved. On Codex, no brief arrives until you approve the project hooks. A default `embed` now leaves Claude Code a one-line `CLAUDE.md` pointer to `AGENTS.md`.

#### Meaning Matching Has Its Own Doctor Route

A command can also pass on meaning when the local embedder runs. Each scored command row carries its own vector. A prompt needs a close match and a clear lead over the next command. A prompt that asks for no change gets no command this way.

`/doctor:skill-advisor embedder` checks the embedder and plans each missing step. It asks before it pulls a model or starts a server. It never installs Ollama itself. The prompt embedding gives up after 750 ms.

#### Smaller Fixes

- **The advisor starts on the Node.js its native module was built for.** An install now records that Node.js. A session on another major version used to fail its first call with `daemon launcher exited with code 1`.
- **A hub with many modes routes fast.** The compiled route built one rule for every subset of a hub's modes on every call. A hub with 18 modes built 262,125 rules and timed out. A rule now covers at most four modes.
- **An OpenCode brief names the command and its policy.** The plugin used to drop both.
- **A prompt that names a `system-`, `cli-` or `mcp-` skill is read.** The prompt policy used to read only `sk-` names.
- **A typed session handover names `/speckit:handoff`.** The advisor named no command for `session handover`, `in session handover` or `session-handover`. It now names the handoff command for all three.
- **A deep review request reaches Deep Loop.** "deep review this branch" now gets `/deep:review`. A question about the AI council gets `/speckit:ai-council`.
- **A read-only question about git history reaches sk-git.** `show the git log` used to return no skill. The question must name git, a commit or one of the branches main, master and develop.
- **Three plain spec requests now reach spec-kit.** The advisor used to miss them.
- **A question about the trigger index reaches spec-kit.** It used to end at the doctor helper. A question about index drift still goes to the doctor.
- **The doctor hand-off names the matched command.** It used to name only `/doctor:helper`, even when the exact command was known.
- **A README request for a hook, plugin or runtime folder gets its own template.** sk-doc gained three README templates for those folders. "README for the session-handover hook" now reaches the hook template.

## Mistral Vibe

#### Vibe Joins as a Runtime Mode

Mistral Vibe is Mistral's coding CLI. It is now the eighth runtime, as the `cli-mistral-vibe` mode. A dispatch runs headless as `vibe -p`. It may pick only two models, `deepseek-flash` and `glm-flash`. Both run at maximum thinking.

Seven rules refuse an unsafe dispatch. One requires `--output-dir`, because only `export.json` says whether a run finished. Another requires Skilled's guards in the run's own Vibe home. Deep loops can run a Vibe lineage beside another executor. The `.vibe/` folder ships generated copies of the agents, skills and commands.

#### Vibe Sessions Run Skilled's Hooks

`.vibe/hooks.toml` registers 18 hook entries. Start Vibe with `--trust` in your checkout, so it loads them. At session start, the model gets its goal and the session context. Each prompt then gets the skill advisor brief.

Before a tool runs, five guards judge it:

- The spec gate.
- The dotenv guard.
- The dispatch check.
- The commit message gate.
- The deep-loop guard.

A refusal reads like this: `env-secret-guard: .env is a dotenv file and its values must not reach the model.`

An edit that leaves a build behind its sources gets a `STALE DIST WARNING` with the tool result. An answer you give through Vibe's question tool lands in the decision queue for `/speckit:save`. A turn that ends on an option menu written in prose is sent back once. The model is told to ask with the question tool instead. After a compaction, the goal, the history lookup offer and any open handoff note come back once.

Two gaps remain, because Vibe sets them. Vibe removes its question tool from a headless run. So answers are captured only in the terminal app. A turn-end refusal becomes a retry, and Vibe accepts the turn after three.

#### Smaller Fixes

- **A background command no longer slips past the guards.** Vibe names that tool `process.start`, and the guards knew only `process_start`. So a background read of `.env` ran unjudged. Every shell guard now judges it.
- **Text typed into a running shell is judged too.** A model could start `bash -i` and type `cat .env` into it. The shell guards now read typed text as a command.
- **A slow startup guard no longer silences the rest.** The startup check gave its guards less time than one guard may need. Then every guard's warning was lost. It now waits 9 s.
- **A dispatch that changes folder first is still checked.** The rule that gives each run its own Vibe home ignored a `cd` before the run.
- **A kill switch in `hook-flags.env` turns a Vibe part off.** The advisor, question-menu and completion parts ignored the file and kept running. Now a switch there stops them.
- **Hooks run from a checkout reached through a link.** Started through a symlinked path, the Vibe hooks printed nothing. Now they print what they print from the real path.

## Deep Loop

#### The AI Council Is Its Own Agent

**Breaking:** `/deep:ai-council` is gone. Deep Loop now routes research and review only. The council used to be a third Deep Loop mode, `deep-ai-council`. Its agent leaned on scripts inside that mode. It also ran `node` while its own settings denied the shell.

Now `@ai-council` stands alone. `/speckit:ai-council` binds the spec folder and dispatches it once. The agent runs every round itself, three by default. It writes only `ai-council/**` files in the packet. A divergent review pivot still asks the council for a new direction.

#### A Review Fails While a Required Check Fails

A deep review used to set its verdict from P0 findings alone. P0 is the blocking severity. So a review could stop at its iteration limit with coverage failing and still report PASS. Now the review follows its own contract. It returns FAIL when a P0 is open or a required check still fails at the stop. The three checks are evidence, scope and coverage.

Every stop now writes one record of the three results before the write-up. That covers the iteration limit, the time limit, three failed passes and every manual stop. The verdict, the dashboard and the fan-out merge all read that record. Only the checks at the last stop count. So a run blocked earlier that later converges still passes. A check nobody judged is refused, not read as passing.

`terminal-gates.cjs` computes the three checks from the loop's state. `review-verdict.cjs` turns them into the verdict, and the fan-out merge uses the same rule. So the same state always gives the same verdict. A failed check script counts all three checks as failed.

#### A Script Makes the Stop Call

The stop vote used to live as prose in the workflow files. So the model running the loop did the arithmetic. It could reach a different answer on the same state. Now `convergence.cjs --stop-decision` computes the vote. It prints one `stop_decision` object, and the workflow only follows it. Both loops share one list of eight stop reasons. The finer cause sits in `reasonDetail`. The review vote follows your `convergenceThreshold` instead of two fixed numbers.

#### Counts Survive a Resume

The stuck count used to live in the model's memory. A resume lost it. Now the loop rebuilds its stuck and failure counts from the state log on every pass. A resumed run counts the same as one that never paused. A failed pass no longer counts toward convergence. Three failed passes in a row end the loop with reason `error`. Auto then writes up the partial findings. Confirm asks Retry, Skip or Cancel first.

#### Research Runs Restart and Respect Their Limits

A research run in auto mode had no way to restart. A review restart wrote generation 1 into its new config. Now `--restart` works on both commands. The run archives the old packet and keeps its lineage.

The packet lock lasted 30 minutes while one dispatch may run 60. The lock now lasts as long as the dispatch timeout. Every halt releases it. `maxDurationMinutes` now ends a run when its time is up. The loop then writes up its findings with reason `maxDurationReached`. The time check now runs on every pass. Before, only the first pass ran it.

#### Each Command Runs From One Workflow

Each deep command kept an auto file and a confirm file, and they had drifted. Confirm runs lacked five executor kinds. They also lacked 11 research steps and 4 review steps. Only research confirm could dry-run. Now `/deep:research` and `/deep:review` each run from one workflow file. Confirm only adds its approval gates. So confirm runs gain the heartbeat, the run-now check and every executor kind. `--dry-run` works in both modes.

#### Reviews Count What They Record

Review passes record their traceability results in several shapes. The coverage check read only one of them. None of the 12 latest reviews could pass it. It now reads every shape seen in real runs. The pass prompt now shows the shape the check reads. A core check left partial or deferred still fails coverage, as the review contract says.

The scope check compared a finding written as `file:42` with `file` and failed it. It now drops the line number first. A finding in the reviewed packet's own docs now counts as in scope.

#### The Report Carries the Verdict's Counts

A review's report took its P0 to P2 counts from the loop agent's own tally. The final self-check could lower that tally. The verdict came from the registry. In 10 of 34 recent reports, the two sets of counts differed. Now the report and the closeout carry the counts the verdict used. The report lists the self-check's calls beside them. A single-executor closeout refuses counts that differ from the registry.

Open search debt now makes a review CONDITIONAL, as the dashboard already did. Search debt is a bug class the search left deferred or blocked. The fan-out merge joins the debt of every lineage.

When a review reaches its last iteration with a core traceability check unfinished, that iteration now goes to the check. A partial check becomes a pass only with a file and line as evidence.

#### Deep Loops Fail Clearly

A chat session could call the fan-out runner with one lineage. One process then wrote every iteration. It skipped the loop's own setup and save steps. `fanout-run.cjs` now refuses that and names the single-executor workflow. A provider quota refusal now counts as `quota`, not as a crash. A review fan-out takes `--review-target`. A Codex effort above the model's ceiling fails before dispatch.

#### Each Pass Keeps Its Executor

A pass run by a CLI executor used to lose its executor in the state log. The next refresh dropped the row that named it. Now that row goes through the append gateway. So do the loop's failure and containment rows. A log with no ledger keeps the direct write. A failure row the gateway refuses is written directly, and stderr says the next refresh drops it.

`verify-iteration.cjs` now checks that the executor was recorded. A non-native pass that names no executor fails with `executor_missing`. Native and unconfigured runs pass. A fan-out lineage is checked against the `invocation-metadata.json` the runner writes into its folder. A missing file or a different kind fails it. A pass recorded before this release names no executor, so checking it again fails.

#### Smaller Fixes

- **Mistral Vibe runs bill your Vibe plan.** A dispatch now uses the key your `vibe --setup` sign-in stored, so it draws on the Vibe budget. A spent budget now stops the run as `quota`, not as a crash.
- **Deep-loop scripts no longer stall on an open stdin.** A runner that left stdin open could hang them. A non-blocking stdin crashed them with `EAGAIN`.
- **Deep-loop saves write continuity.** The save ran the continuity writer without `--full-auto`, so it only planned. Now both workflows pass `--full-auto`. Their payloads carry `recent_action`, `next_safe_action`, `blockers` and `key_files`.

- **A fan-out lineage with no registry still counts in the merge.** It used to drop out of the merged verdict, even with a failed check in its state log. Now that check fails the merged verdict.
- **A research pass that cannot recover its sources says why.** It reports `timeout` or `stuck` instead of `error`.

## Installs and Overlays

#### Pi Loads the Hook Adapters on Every Version

Pi 1.5.1 changed how it loads a linked extension. On Pi 1.5.2, 16 adapters then failed to load and `pi -p` exited 1. Each entry in `.pi/extensions/` is now a one-line file that re-exports its adapter. Pi 1.5.0 and Pi 1.5.2 both load all 22 entries.

#### Claude Code Keeps Your Hook Copy in Step

Some users copy Skilled's hooks into `~/.claude/settings.json`. That copy went stale when a hook folder was renamed. A stale copy ran hooks twice inside Skilled. Outside Skilled it failed with `mk claude hook could not resolve`.

Now each hook command first checks for `.skilled/hooks` and exits quietly without it. A folder that holds only Skilled data, such as `~/.skilled`, does not count. Claude Code runs a command found in both files once.

Set `SYSTEM_CLAUDE_USER_HOOK_SYNC_ENABLED=1` to keep the copy current. Each session start in your Skilled checkout then copies the project's hooks into your user settings.

- It keeps your other settings and your own hooks.
- It writes only when something changed.
- The first write keeps a backup at `~/.claude/settings.json.pre-skilled-hook-sync`.
- A linked worktree never writes.
- Turning the switch off leaves the last copy in place.

`node .skilled/bin/sync-claude-user-hooks.mjs --check` prints `sync-claude-user-hooks: OK` when the copy matches.

#### A Re-Pin Refuses Before It Writes

A re-pin now plans each `json-entry` file its copy leaves in place against the new commit. It does this before its backup. When one cannot be applied, the re-pin exits 2 and writes nothing. Before, it could write one array item's value into another and print `RESULT: PASSED`.

An entry set that cannot be applied to an untouched file now shows as `cannot-apply`. Its fix text says why. It blocks `apply` and a re-pin, as `both-changed` does. The counts line and `status --json` use the new name. A stage that lists a blocked overlay now ends `RESULT: BLOCKED`. So `RESULT: STAGED` always means a clean copy.

A re-pin also works when upstream turns a link into a folder. Once you rebase a `directory` or `skill-root` overlay, set its `rebasedOnto` to the new commit. The re-pin then takes that overlay as rebased.

#### A Failed Apply Keeps Its Records

`apply` now records what it wrote before any regenerate step runs. A later drop still removes what that run added. A failed step runs again on the next `apply`, even when every file is in sync. The state file and the manifest are written through a rename. A killed run leaves the old file whole.

The state file moves to schema version 2. A version 1 file still loads, and the first `apply` rewrites it. A record with a broken path is refused, and the error names the fix.

#### A Vendored Tree Can Refuse Unowned Writes

A project that copies Skilled into its own repository keeps its changes as overlays. The guard used to know only paths an overlay already owned. Set `"strictWrites": true` in the manifest to change that. The guard then refuses a new file or an unowned upstream edit under a vendored root.

The refusal names the fix. `/doctor:overlay apply --adopt <path>` turns the path into an overlay. A `generated` glob list names paths your generators write. `overlay-engine.cjs pre-commit` runs the same test on staged changes.

#### The Overlay Engine Cleans Up After Itself

A project that moved onto the engine reported three bugs and three gaps. All are fixed:

- A killed run's lock is taken over.
- A changed layout link is retargeted.
- A dropped appended item leaves the live file.
- `status` prints `STALE` and `LAYOUT` lines.
- `status --audit` lists drift no overlay owns.
- `apply --relayout` moves sources kept off their layout path.

A re-pin no longer blocks on a file inside a folder an overlay replaces.

#### Overlay Status Says What It Skipped

`status` now prints `NOTE` lines. A note never fails the run. `status --json` lists the same text under `notes`.

- One note names a check that could not run. That happens when the pinned checkout is missing or lacks the pinned commit.
- Another names each `setKeyOnItem`, `insertObjectKeys` or `set` through an array index. Their values stay in the file after they leave the entry set.

A cross-check compares each in-sync `json-entry` file with its entry set applied to the pinned copy. It reports a value no record covers. It skips any file a regenerate step lists in its `outputs`.

#### Checks Pass in a Project That Vendors Skilled

A project that vendors Skilled reported checks that failed for reasons it could not repair. Four are fixed:

- The route sync check and the route-gold check read Skilled's own spec folders, which a project does not have. Both now skip there and name the reason.
- A hub may file all of a surface's paths under one hub intent. The sk-code router check accepts that once `hub-router.json` declares it in `surfaceIntentFolds`.
- The doctor's git check accepts a hook of your own that hands over to a Skilled hook. It also accepts a hook you leave out on purpose.

The advisor's fixture tests read a host's own `.host.json` capture when one sits beside the upstream file.

- **A dropped `set` puts the pinned value back.** Remove a `set` from a `json-entry` overlay, and the next `apply` restores the pin's value. A path through an array index is restored only while the item there is still the pin's. A key the pin lacks is deleted only when the record shows the overlay added it. ## Spec Workflow

#### Spec Commands Do What They Report

Saves used to write nothing. Plan, implement and complete passed the writer a temp file. They left out `--full-auto`. So the writer only planned, while each step said it saved. Now every save sends its data straight to `generate-context.js --stdin --full-auto`. One strict check runs after it. Each command now saves once. The saves along the way are gone. So is the offer of a second save at the end.

Checks now run after the work they check. Implement used to mark its acceptance checks as met before any code existed. Now it writes them before the build. A new step checks them after it. Plan writes `tasks.md` in a step of its own. Only one step creates the spec folder. Phase splitting takes its level from `recommend-level.sh`.

A check passes only when every part passes. A missing file fails it. So does a file that still holds placeholder text. The message names the parts that failed. A serious gap between the spec, plan and tasks stops the run before the build. After three failed rounds the run stops. It lists what is still open. Checks that no step could ever pass are gone.

You cannot finish without a code review now. A `REQUESTED_CHANGES` answer sends the run back to the build once. A second one stops the run. Plan now sends out only its four context agents. Each agent uses the model its own file names. Each finding names a file and a line.

A command sometimes stops to ask you something. Each of those places now says what confirm, auto and autopilot do:

- Auto asks only when confidence is below 40. It also asks the spec folder question.
- Autopilot never asks. You give it its workspace as `workspace_choice`.
- Autopilot makes a branch only with `git worktree add -b`. It never merges or pushes.
- Autopilot ends on one `SPECKIT_AUTOPILOT_RESULT` line. With no workspace set, it stops with `uncertainty_blocked` before it writes anything.

Resume with no folder now looks in a fixed order:

1. The folder you typed.
2. This session's handoff note.
3. The packet tied to this session.

It never reads another session's note. If nothing matches, auto says there is no session. Confirm lists up to three recent packets, each marked as not matched. Its panel starts with "No packet is matched to this session." A handoff note counts at any age. One `speckit-resume.yaml` replaces the separate auto and confirm files. Resume no longer matches fixed phrases. It no longer looks in `.opencode/specs/`. It no longer guesses by meaning.

Planning no longer writes `research/research.md`. It lists unknowns in the Technical Context of `plan.md`. An unknown that needs real digging points to `/deep:research`.

#### Agents Reread the Request Before Done

Acceptance rows come from the spec. An outcome you asked for can be missing there while every check passes. The agent now maps each requested outcome to a met row. Otherwise it names that outcome as not done. The completion hook repeats the reminder on every done claim. It never blocks.

#### The Restraint Check Runs When Scope Is Written

The overengineering rule used to wait for code. By then a spec had frozen the addition into scope. The rule now fires on a spec or plan that adds a file, option, layer or dependency. `/speckit:plan` and `/speckit:complete` ask what fails today without it.

Moving a spec packet used to mean `git mv` and edits by hand. Many records then kept the old path. Now `relocate.mjs` moves, renumbers or re-parents a packet. It updates every record of the path. A run only shows its plan until you add `--apply`. A dry run ends on a line like this: `moves=1 moved=0 rewrites=33 identity=1 roots=3 ledger=1`. A move that stopped halfway finishes when you run it again. Exit 3 means the move landed, but the packet failed its own checks.

Archived packets are now in reach. `rg-wrapper.mjs --include-archive` searches them. It marks each hit `[archived]`. `validate.sh --recursive --include-archive` checks them too. Gate 6 named five rule files to load around a reply. Three mostly repeated the others, so they are retired. ## Dotenv Guard

#### The Guard Refuses the Read

An agent that reads `.env` puts every secret in it into the model's context. The new `env-secret-guard` hook refuses that call. It runs on Claude Code, Codex, Cursor, Devin, OpenCode, Pi, DSH and Mistral Vibe.

What counts as a dotenv file:

- A file named `.env` or `.env.<suffix>`.
- A link to such a file.
- Not the template `.env.example`, which stays open.

The guard catches file tools, patches and shell reads such as `cat`, `grep -f` and `cp`. It sees through quotes, `$(...)`, globs such as `.e*` and `bash -c` scripts. An app that loads its own env still runs. `node --env-file=.env app.js` and `source .env` are allowed.

#### Answers Without Values

The refusal names the way in. The guard can do three things without showing a value:

- List the keys.
- Report lines that fail to parse.
- Fingerprint one value. Two equal fingerprints mean equal values.

Every runtime can run `.skilled/hooks/env-secret-guard/cli/env-secret.cjs`. OpenCode also has three `env_secret_*` tools. The fingerprint is an HMAC-SHA256 keyed by `ENV_SECRET_GUARD_PEPPER`. The key comes from your environment, never from a file. Without it, no fingerprint is returned.

#### Two More Layers Behind the Hook

A command's text does not show everything it does. So the guard records your dotenv files before a shell call. Afterwards it puts back any file that changed. It also looks for a dotenv value in the output. OpenCode and Pi replace that value before the model reads it. Mistral Vibe has no after-call check. The other runtimes can only warn that it reached the session.

Claude Code, Devin and Cursor also carry their own deny list for dotenv files. So the file stays closed if the hook fails. On DSH the guard refuses a command that prints a loaded value, such as `printenv`. Every adapter fails open, so a guard bug never stops an agent. `SYSTEM_ENV_SECRET_GUARD_DISABLED=1` turns the guard off. It is read from the environment only.

## Upgrade Notes

- **Update Node.js first.** Install 22.23.4, 24.22.1, 26.12.1 or a newer release on one of those lines. Code Mode needs 24.22.1 or newer on the 24 line. Run `/doctor:mcp` to confirm.
- **If Claude Code should not hand over:** set `SYSTEM_SESSION_HANDOVER_CLAUDE_ENABLED=0` in `.skilled/hooks/hook-flags.env`. To hand over on another runtime, set its own flag or `SYSTEM_SESSION_HANDOVER_ENABLED=1`.
- **If an agent needs a `.env` value:** it now asks you. Paste the value yourself or compare fingerprints. For fingerprints, run `openssl rand -base64 32` and export the result as `ENV_SECRET_GUARD_PEPPER` in your shell profile. Never put it in a file inside a repository.
- **If Skilled is installed in your project:** run `node .skilled/skills/system-spec-kit/runtime/cli/runtime-mirrors/sync-hook-registrations.cjs` from the project root. It rewrites `.claude/settings.json` and `.codex/hooks.json`. Add `--check` to check for drift without writing.
- **On Codex:** approve the project hooks in `/hooks`, including the new `SessionStart` row. Until then the advisor brief never arrives. The compaction pointer does not run either. To turn on meaning matching anywhere, run `/doctor:skill-advisor embedder`.
- **If you embed the shipped `AGENTS.md`:** run `/doctor:agents-md` to take the new Gate 2 and Gate 6 wording. Remove any link of your own to the three retired reply rules.
- **If you set a `SYSTEM_SESSION_RELAUNCH_*` or `SESSION_RELAUNCH_*` variable:** rename it in your shell profile or `hook-flags.env` by replacing `SESSION_RELAUNCH` with `SESSION_HANDOVER`. For example, `SYSTEM_SESSION_RELAUNCH_ENABLED` becomes `SYSTEM_SESSION_HANDOVER_ENABLED`. The old names are not read. A Claude Code user who had switched handover off gets it back until the new switch is set to 0.
- **If you have an open handoff note:** move `.skilled/skills/.state/session-relaunch/` to `.skilled/skills/.state/session-handover/` in each checkout. Until you move it, the note is not found. Move it once the checkout runs this release, since sessions on the old code still write there.
- **If you run the skill advisor from a built copy:** run `npm run build` in `.skilled/skills/system-skill-advisor/runtime` once.
- **If a project runs sessions on more than one Node.js major:** reinstall the advisor runtime once, with `npm ci` in `.skilled/skills/system-skill-advisor/runtime`. The install writes the record the advisor starts from.
- **If you use Mistral Vibe:** start it with `vibe --trust` in your checkout, so it loads the repository's hooks. Before each dispatch, run `.vibe/plugins/repo-guards/render-home-hooks.cjs` on the run's Vibe home.
- **If you run `/deep:ai-council`:** run `/speckit:ai-council` instead. It writes the same `ai-council/**` files.
- **If a deep review passed with a required check failing:** expect FAIL on this release. Close the failing check and run it again.
- **If a deep review now fails on coverage:** a pass left `spec_code` or `checklist_evidence` partial, failed or deferred. Run a pass that finishes both.
- **If you run a spec command on autopilot:** it no longer merges or pushes. Merge and push the branch yourself.
- **If you read `research/research.md` after planning:** it is no longer written. Read the Technical Context in `plan.md`, or run `/deep:research`.
- **If you keep spec packets under `.opencode/specs/`:** resume no longer looks there. Move them under `specs/`.
- **If you start a runtime in a checkout your shell does not source:** add that checkout's absolute path to `SKILLED_LOOP_TRUSTED_CHECKOUTS`.
- **If Claude no longer nudges near its limit:** set `autoCompactWindow` in the Claude settings or export `SESSION_HANDOVER_WINDOW_TOKENS`. A `[1m]` model needs neither.
- **If you keep Skilled's hooks in `~/.claude/settings.json`:** set `SYSTEM_CLAUDE_USER_HOOK_SYNC_ENABLED=1` in your Skilled checkout's `.skilled/hooks/hook-flags.env`. Or remove the copy.
- **If a dispatch audit log already exists:** run `chmod 600 .skilled/logs/cli-dispatch-audit.log*` so only you can read it.
- **If you vendor Skilled:** strict writes stay off until a manifest sets `strictWrites`. The first `apply` after this release records links, items and `set` values. It rewrites `sync-state.json` as schema version 2. Commit that file. An older engine cannot read it.
- **If a script reads overlay `status`:** add the `cannot-apply` state. `status --json` also carries a `notes` key.
- **If a regenerate step writes a `json-entry` file:** list that file in the step's `outputs`. Otherwise the cross-check reports it on every run.
- **If your hooks hand over to Skilled's:** add the line `# skilled-hook-handover: <folder>` to each one. The folder is the path from your hook to Skilled's hook folder. For a hook you leave out, run `git config --local --add skilled.omitHook <name>`.
- **If your repository links its own files into `.pi/extensions/`:** make each entry a one-line file, `export { default } from '<path>';`.
- **If a script or setting names a hook folder:** use the new name. `dispatch/` is `cli-dispatch/`, `task-dispatch/` is `subagent-dispatch-guard/` and `completion/` is `completion-evidence/`. `codex-watchdog/` and `hook-install/` are now `codex-global-hooks-check/`.
- **If you linked `.skilled/hooks/git/pre-commit`:** run `bash .skilled/scripts/install-git-hooks.sh` to install the primary hooks.
- **If anything matches the seed:** use `[session-handover] claim and continue handoff`.
- **If you match on an advisor command id:** `memory:save` and `command-memory-save` are now `command-speckit-save`. `command-spec-kit` is now one id per command, such as `command-speckit-plan`. `command-prompt-improver` is now `command-prompt-improve`.
- **If a script names `speckit-resume-auto.yaml` or `speckit-resume-confirm.yaml`:** point it at `speckit-resume.yaml`.
- **If a script names a per-mode deep workflow file:** point it at `deep-research.yaml` or `deep-review.yaml`. The `-auto` and `-confirm` files are gone.
- **If you call a deep-loop script with `--loop-type council`:** that loop type is gone. Use the `@ai-council` agent.
- **If a script calls `fanout-run.cjs` with one lineage:** add `--allow-single-lineage`. The goal checker now needs a packet or `--all`.
- **If you parse wrapper JSON:** `results` holds one row per file. Read `schemaVersion`. Use `matchCount` and `fileCount` for the totals. Pass `--no-stale-fallback` to keep a lookup to the index alone.
- **If your sk-code hub files a surface's paths under one hub intent:** add `"surfaceIntentFolds": { "<surface packet>": "<HUB_INTENT>" }` to `hub-router.json`, then refresh the hub's activation manifest.
- **If your own repository keeps flat packets beside sub-tracks:** the sweep now exits 1. Move each flat packet into a sub-track.
