# v4.0.2.1, Improved Chat Automation, Search & Session Handover

Long sessions hand over more cleanly, and Claude Code now does it by default. A hop to a fresh session carries the running command, the goal and the session's name. Pi, OpenCode and Mistral Vibe now finish a hop too.

The skill advisor now names the slash command behind a hub skill. It also says whether the agent may run it. Mistral Vibe joins as the eighth runtime. A deep review now fails while a required check still fails.

Search answers say how much they left out. The spec commands now save what they report. Projects that vendor Skilled get stricter overlay checks.

This release also changes what you install and what an agent may read. Skilled now needs a patched Node.js release. A new guard keeps the values in a `.env` file away from every agent.

&nbsp;

## Why This Release

- Handover shipped off, so most Claude Code users never had it.
- A session that hopped mid-command came back as a plain chat.
- The advisor named a skill, not the command to type.
- A deep review could pass while a required check failed.
- A search cut at its limit never said what it hid.
- An overlay re-pin could write a wrong value and still pass.
- Any agent could read `.env` and send its secrets to the model.
- Skilled still accepted Node 20 after an October security patch.

## Session Handover

#### Claude Code Hands Over by Default

Claude Code now hands over when no switch is set. Codex, Pi, OpenCode, Cursor, Devin and Vibe stay off until you turn them on.

Under the `skilled-loop` wrapper, a session at 80% writes a handoff note and ends. A fresh session starts in the same terminal and claims it. Without the wrapper, the session keeps the note and works on. Set `SYSTEM_SESSION_HANDOVER_CLAUDE_ENABLED=0` to turn it off.

&nbsp;

#### Old Switch Names Stop Working

**Breaking:** The feature now has one name, session handover. Old switch names are no longer read. So `SYSTEM_SESSION_RELAUNCH_ENABLED=0` does nothing, and Claude Code hands over again.

- Main switch: `SYSTEM_SESSION_HANDOVER_ENABLED`.
- Per runtime: such as `SYSTEM_SESSION_HANDOVER_CODEX_ENABLED`.
- Tuning variables: the `SESSION_HANDOVER_` prefix.
- Hook folder: `.skilled/hooks/session-handover/`.
- Seed: `[session-handover] claim and continue handoff`.

`SYSTEM_IN_SESSION_HANDOVER_*` also works for the on and off switches. The main name wins when both are set. `/doctor:env` names a conflict.

**Breaking:** An open note in the old state folder is not found. Move it to the new folder, as Upgrade Notes says.

&nbsp;

#### A Hop Carries the Command and the Goal

The handoff note now carries an `Active command:` line. The next session reruns that command with the same mode and arguments. The note lists running workers, so the next session does not start them twice.

A Claude session with no goal now hands on its packet's goal. The next session starts on `/goal` with it. A goal you met, failed or cleared stays ended. A goal that cannot be carried prints one `goal not carried:` line.

The hop also keeps your session name, numbered `<title> (2)`, then `(3)`. It keeps the permission mode and flags such as `--add-dir`.

&nbsp;

#### A Claimed Note Offers the Sender's History

`claim` now prints a `## History Lookup` section after the note. It holds one read-only command. That command searches the sender's earlier turns for 30 minutes. Claude Code, Codex, Mistral Vibe, Pi and OpenCode senders get it.

**Breaking:** The lookup is no longer offered after a compaction. The OpenCode plugin `session-history-lookup.js` is gone.

&nbsp;

#### Pi, OpenCode and Vibe Finish a Hop

Pi and OpenCode now finish the same hop as Claude Code. OpenCode 2 still drops a model you pick mid-session.

Mistral Vibe hands over too. Set `SYSTEM_SESSION_HANDOVER_VIBE_ENABLED=1` and start Vibe through `skilled-loop vibe`. Near its compaction point, the session writes a note and a fresh one claims it. Typing `/speckit-handoff` under `skilled-loop vibe` also arms a hop. Type anything else while it is armed to call it off. The wrapper warns when an exported `MISTRAL_API_KEY` would bill outside your Vibe plan.

&nbsp;

#### Smaller Fixes

- **The shell shim runs only a wrapper it trusts.** Add other checkouts to `SKILLED_LOOP_TRUSTED_CHECKOUTS`.
- **No foreign folder or old process can plant a hop.**
- **A sub-agent cannot cancel or consume a handover.**
- **A waiting or failed hop no longer stalls.** Your next prompt calls it off.
- **A nudge arrives once.**
- **A title carries one number.** It no longer reads `ENGINE LIMITS (2) (4)`.
- **A provider key no longer blocks an OpenCode dispatch.**
- **The wrapper says when its file changed.** Restart it to run the new code.

## Skill Advisor

#### A Hub Skill Names the Command to Type

A hub recommendation now carries the command for the mode it picked. A brief head reads `use system-spec-kit → /speckit:plan (start)`. A hub that cannot pick a mode says `sk-doc (needs a mode)`.

Each command has one policy:

- `run`: the agent may run it now.
- `start`: it starts without `:auto`, so its setup asks.
- `ask`: the agent offers it and waits.

A typed command or a direct instruction outranks the policy. A typed slash command always reaches the model with its policy.

&nbsp;

#### Doctor Checks Show Whether the Brief Arrives

`/doctor:setup` gains two read-only legs. The embedder leg reads DEGRADED when meaning matching is off. The delivery leg reads DEGRADED when a prompt hook is missing or not approved. On Codex, no brief arrives until you approve the project hooks.

`/doctor:skill-advisor embedder` sets up meaning matching. It asks before it pulls a model or starts a server.

&nbsp;

#### Smaller Fixes

- **The advisor no longer fails on another Node.js major.** It failed with `daemon launcher exited with code 1`.
- **A hub with many modes no longer times out.**
- **An OpenCode brief names the command and its policy.**
- **Git history, deep review and handover requests reach their skill.**
- **A hook, plugin or runtime README gets its own template.**

## Mistral Vibe

#### Vibe Joins as a Runtime

Mistral Vibe is Mistral's coding CLI and now the eighth runtime. A dispatch runs headless as `vibe -p`. It may pick `deepseek-flash` or `glm-flash`. Seven rules refuse an unsafe dispatch. A dispatch needs `--output-dir` and Skilled's guards in the run's Vibe home.

&nbsp;

#### Vibe Sessions Run Skilled's Hooks

Start Vibe with `--trust` in your checkout, so it loads its 18 hook entries. Each session then gets:

- Its goal and session context at start.
- The skill advisor brief on each prompt.
- Five guards before each tool runs.
- Decision capture for answers in the question tool.

A refusal reads: `env-secret-guard: .env is a dotenv file and its values must not reach the model.`

Two gaps remain. A headless run has no question tool, so its answers are not captured. Vibe accepts a turn after three turn-end refusals.

&nbsp;

#### Smaller Fixes

- **Background commands no longer slip past the guards.**
- **Text typed into a running shell is judged too.**
- **A kill switch in `hook-flags.env` turns a Vibe part off.**
- **Hooks run from a symlinked checkout.**

## Deep Loop

#### The AI Council Is Its Own Agent

**Breaking:** `/deep:ai-council` is gone. Run `/speckit:ai-council` instead. It binds the spec folder and dispatches the `@ai-council` agent once. The agent runs three rounds by default. It writes only `ai-council/**` files in the packet.

&nbsp;

#### A Review Fails While a Required Check Fails

A deep review used to set its verdict from P0 findings alone. Now it returns FAIL when a P0 is open or a required check fails at the stop. The three checks are evidence, scope and coverage. Scripts compute them and the verdict. So the same state always gives the same verdict.

The coverage check now reads every shape reviews record. The report carries the counts the verdict used. Open search debt makes a review CONDITIONAL.

&nbsp;

#### Loops Stop the Same Way Every Time

A script now makes the stop call. `convergence.cjs --stop-decision` prints one `stop_decision` object. The review vote follows your `convergenceThreshold`. A resume rebuilds its counts from the state log. Three failed passes in a row end the loop with reason `error`.

- `--restart` works on research and review.
- `maxDurationMinutes` now ends a run on time.
- `--dry-run` works in both modes.
- A review fan-out takes `--review-target`.

Each deep command now runs from one workflow file.

&nbsp;

#### Smaller Fixes

- **Vibe runs bill your Vibe plan.** They use your `vibe --setup` sign-in.
- **A quota refusal counts as `quota`, not a crash.**
- **`fanout-run.cjs` refuses a one-lineage run.**
- **A pass with no recorded executor fails as `executor_missing`.**
- **Deep-loop scripts no longer hang on an open stdin.**
- **Deep-loop saves write continuity.**
- **One DeepSeek Harness lineage runs through `dispatch-iteration.cjs`.** It needs `--spec-folder`.
- **A review that never ran says so.**

## Search

#### A Cut Answer Says What It Hid

The trigger lookup now returns `totalCandidates`. A cut answer reads `candidates : 2 of 828 (truncated) from 1070 phrase(s)`. A crash now exits 2, not the no-match code 1.

A lookup with no hits also reads spec documents the index does not list yet. JSON then carries `staleFallback`.

&nbsp;

#### Free-Text Search Shows Each File Once

`rg-wrapper.mjs structured` now keeps the best row per file. `--limit` counts files, 20 by default. A cut answer ends with a line such as `+1382 more files with 2681 matches`. `/speckit:search` uses this wrapper by default.

## Installs and Overlays

#### Pi Loads Its Hook Adapters Again

On Pi 1.5.2, 16 adapters failed to load and `pi -p` exited 1. Each entry in `.pi/extensions/` is now a one-line re-export. Pi 1.5.0 and 1.5.2 both load all 22 entries.

&nbsp;

#### Claude Code Keeps Your Hook Copy in Step

A copy of Skilled's hooks in `~/.claude/settings.json` went stale after a folder rename. Outside Skilled it failed with `mk claude hook could not resolve`. Each hook now exits quietly where there is no `.skilled/hooks`.

Set `SYSTEM_CLAUDE_USER_HOOK_SYNC_ENABLED=1` to keep the copy current. Each session start in your Skilled checkout then syncs it. Your other settings and hooks stay. The first write keeps a backup at `~/.claude/settings.json.pre-skilled-hook-sync`. Check the copy with `node .skilled/bin/sync-claude-user-hooks.mjs --check`.

&nbsp;

#### A Re-Pin Refuses Before It Writes

A re-pin now plans each `json-entry` file before its backup. If one cannot apply, it exits 2 and writes nothing. Before, it could write the wrong array item's value and print `RESULT: PASSED`.

Such a file now shows as `cannot-apply` and blocks `apply`. A stage with a blocked overlay ends `RESULT: BLOCKED`. After you rebase a `directory` or `skill-root` overlay, set its `rebasedOnto` to the new commit.

&nbsp;

#### A Failed Apply Keeps Its Records

`apply` now records what it wrote before any regenerate step. A failed step runs again on the next `apply`. A killed run leaves the state file whole. The state file moves to schema version 2.

&nbsp;

#### A Vendored Tree Can Refuse Unowned Writes

Set `"strictWrites": true` in the overlay manifest. The guard then refuses a new file or unowned edit under a vendored root. `/doctor:overlay apply --adopt <path>` turns the path into an overlay. A `generated` glob list names paths your generators write. `overlay-engine.cjs pre-commit` runs the same test on staged changes.

&nbsp;

#### Status Says What It Skipped

`status` now prints `STALE`, `LAYOUT` and `NOTE` lines. A note names a check that could not run or a value no record covers. `status --json` lists them under `notes`. `status --audit` lists drift no overlay owns. `apply --relayout` moves sources kept off their layout path.

&nbsp;

#### Smaller Fixes

- **A dropped `set` puts the pinned value back.**
- **A `set` adds a key the file lacks.**
- **A broken entry set blocks only its own overlay.**
- **`/doctor:update apply` runs the overlay status check.**
- **Checks pass in a project that vendors Skilled.**
- **`/doctor:symlink` links `.vibe` and `.dsh` too.** Pass `--runtimes vibe` or `--runtimes dsh`.
- **Browser captures stay out of the repository.**

## Spec Workflow

#### Spec Commands Do What They Report

Saves used to write nothing while each step said it saved. Each command now saves once, through `generate-context.js --stdin --full-auto`. A strict check runs after it.

- Implement checks its acceptance rows after the build.
- A missing file or placeholder text fails a check.
- You cannot finish without a code review.
- Autopilot never asks, merges or pushes.
- Autopilot takes its workspace as `workspace_choice`.
- Resume reads only this session's handoff note.

Planning no longer writes `research/research.md`. Unknowns go in the Technical Context of `plan.md`.

&nbsp;

#### Agents Reread the Request Before Done

The agent maps each requested outcome to a met acceptance row. Otherwise it names that outcome as not done. The restraint check now fires on a spec or plan that adds a file, option, layer or dependency.

&nbsp;

#### Packets Move by Command

`relocate.mjs` moves, renumbers or re-parents a packet. It updates every record of the path. It only shows its plan until you add `--apply`. `rg-wrapper.mjs --include-archive` searches archived packets. `validate.sh --recursive --include-archive` checks them. `suggest-subtracks.mjs` suggests sub-tracks for a long flat track.

&nbsp;

#### Reply Rules Are Two Files

Gate 6 now loads `communication.md` before a reply. It loads `communication-handoff.md` before a turn ends. Three reply rule files are retired.

&nbsp;

#### Smaller Fixes

- **A save reads only its own session's answers.**
- **A live Devin session's answers are found.**
- **`/speckit:implement` runs on a worktree branch.**
- **`/speckit:implement` stops on a failing test.**
- **Setup no longer asks the Dispatch Mode question.**

## Dotenv Guard

#### The Guard Refuses the Read

The new `env-secret-guard` hook refuses an agent's read or write of `.env` or `.env.<suffix>`. It runs on all eight runtimes. The template `.env.example` stays open. It catches file tools, patches and shell reads such as `cat`. An app that loads its own env still runs, as in `node --env-file=.env app.js`.

&nbsp;

#### Answers Without Values

The guard can list keys, report parse errors and fingerprint one value. Run `.skilled/hooks/env-secret-guard/cli/env-secret.cjs` on any runtime. A fingerprint needs `ENV_SECRET_GUARD_PEPPER` in your environment.

&nbsp;

#### Two More Layers

After a shell call, the guard puts back any changed dotenv file. OpenCode and Pi also hide a dotenv value in tool output. Claude Code, Devin and Cursor keep their own deny list. Every adapter fails open. `SYSTEM_ENV_SECRET_GUARD_DISABLED=1` turns the guard off.

&nbsp;

## Node.js

#### Patched Releases Are Required

A security notice of 23 October 2026 named 22.23.4, 24.22.1 and 26.12.1. Skilled now declares `^22.23.4 || ^24.22.1 || >=26.12.1`. npm warns on an older Node and goes on.

**Breaking:** Code Mode needs `>=24.22.1 <25.0.0`. Without it, Code Mode cannot start. Run `/doctor:mcp` to check.

## Upgrade Notes

- **Update Node.js first.** Use 22.23.4, 24.22.1, 26.12.1 or newer on those lines. Code Mode needs 24.22.1 or newer on 24. Check with `/doctor:mcp`.
- **To stop Claude Code handing over:** set `SYSTEM_SESSION_HANDOVER_CLAUDE_ENABLED=0` in `.skilled/hooks/hook-flags.env`.
- **To hand over on another runtime:** set its own flag or `SYSTEM_SESSION_HANDOVER_ENABLED=1`.
- **If an agent needs a `.env` value:** paste it yourself or compare fingerprints.
- **For fingerprints:** export `openssl rand -base64 32` output as `ENV_SECRET_GUARD_PEPPER` in your shell profile. Never put it in a repository file.
- **If Skilled is installed in your project:** run `node .skilled/skills/system-spec-kit/runtime/cli/runtime-mirrors/sync-hook-registrations.cjs` from the project root. Add `--check` to only check.
- **On Codex:** approve the project hooks in `/hooks`, including the new `SessionStart` row.
- **To turn on meaning matching:** run `/doctor:skill-advisor embedder`.
- **If you embed the shipped `AGENTS.md`:** run `/doctor:agents-md`. Remove links to the three retired reply rules.
- **If you set a `SESSION_RELAUNCH` variable:** replace `SESSION_RELAUNCH` with `SESSION_HANDOVER` in its name.
- **If you have an open handoff note:** move `.skilled/skills/.state/session-relaunch/` to `.skilled/skills/.state/session-handover/`. Do it once the checkout runs this release.
- **If you run the advisor from a built copy:** run `npm run build` in `.skilled/skills/system-skill-advisor/runtime`.
- **If you use more than one Node.js major:** run `npm ci` in `.skilled/skills/system-skill-advisor/runtime` once.
- **If you use Mistral Vibe:** start it with `vibe --trust` in your checkout.
- **Before each Vibe dispatch:** run `.vibe/plugins/repo-guards/render-home-hooks.cjs` on the run's Vibe home.
- **If you run `/deep:ai-council`:** run `/speckit:ai-council` instead.
- **If a deep review now fails:** close the failing check and run it again.
- **If it fails on coverage:** run a pass that finishes `spec_code` and `checklist_evidence`.
- **If you use autopilot:** merge and push the branch yourself.
- **If you read `research/research.md` after planning:** read Technical Context in `plan.md`.
- **If you keep packets under `.opencode/specs/`:** move them under `specs/`.
- **If your shell does not source a checkout you use:** add it to `SKILLED_LOOP_TRUSTED_CHECKOUTS`.
- **If Claude no longer nudges near its limit:** set `autoCompactWindow` or export `SESSION_HANDOVER_WINDOW_TOKENS`.
- **If you keep Skilled's hooks in `~/.claude/settings.json`:** set `SYSTEM_CLAUDE_USER_HOOK_SYNC_ENABLED=1`, or remove the copy.
- **If a dispatch audit log exists:** run `chmod 600 .skilled/logs/cli-dispatch-audit.log*`.
- **If you vendor Skilled:** commit `sync-state.json` after the first `apply`. An older engine cannot read it.
- **To refuse unowned writes:** set `strictWrites` in the overlay manifest.
- **If a script reads overlay `status`:** handle `cannot-apply` and the `notes` key.
- **If a regenerate step writes a `json-entry` file:** list it in the step's `outputs`.
- **If your hooks hand over to Skilled's:** add `# skilled-hook-handover: <folder>` to each one.
- **For a hook you leave out:** run `git config --local --add skilled.omitHook <name>`.
- **If you link files into `.pi/extensions/`:** make each a one-line `export { default } from '<path>';`.
- **If a script names a hook folder:** use its new name from Hook Library.
- **If you linked `.skilled/hooks/git/pre-commit`:** run `bash .skilled/scripts/install-git-hooks.sh`.
- **If anything matches the seed:** use `[session-handover] claim and continue handoff`.
- **If you match on advisor command ids:** `memory:save` is now `command-speckit-save`.
- **Other renamed ids:** `command-spec-kit` splits per command, such as `command-speckit-plan`. `command-prompt-improver` is `command-prompt-improve`.
- **If a script names a resume file:** point it at `speckit-resume.yaml`.
- **If a script names a per-mode deep workflow:** use `deep-research.yaml` or `deep-review.yaml`.
- **If you pass `--loop-type council`:** use the `@ai-council` agent.
- **If you call `fanout-run.cjs` with one lineage:** add `--allow-single-lineage`.
- **For the goal checker:** pass a packet or `--all`.
