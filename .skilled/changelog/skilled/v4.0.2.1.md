# v4.0.2.1, Search Says How Much It Found

Gate 1 and `/speckit:search` used to hide what they left out. A short answer looked complete. A new spec document could not be found until the next index build. One common phrase could fill the whole result with two files. All three now say what they found and what they held back.

The work began as research into sweet-search, an outside code-search tool. Skilled kept its own search. It took three lessons from the research and built them. This release also fixes the routing and the checks that the build turned up. An audit of everything changed since v4.0.1.0 then closed 36 more findings. Three outside models ran 50 passes over every changed skill and command. An autonomous changelog release now stops when its entry is uncommitted. Fan-out counts a provider quota refusal as `quota`, not as a crash. A review fan-out takes `--review-target`. A Codex effort above the model's ceiling fails when the configuration is read. A saved ClickUp page that lost a repeated line now fails its check. The router-sync guard fails on a missing registry. `/doctor:update apply` checks overlays. The CLI hub has its v2.0.0.0 note for the cli-hermes removal. A deep loop started from chat can no longer run as a one-lineage fan-out. A new spec folder now points at the authoring card. Gate 6 loads two reply rules where it loaded five.

Three more changes ship with it. The ten largest spec tracks are grouped into named sub-tracks. Every package now requires a patched Node.js release. A new guard stops an agent from reading or writing a `.env` file on all seven runtimes. Two outside skill repos, unlazy and ponytail, were also compared with Skilled. Most of what they do was already here. Three small checks were not, and they are now built. The session hop was reviewed as well. It now runs only a wrapper it trusts. It reads only state it has checked.

## Why This Release

An agent trusts a Gate 1 answer. It reads the answer as the full picture. That was not always true. With `--limit 2` the agent saw two results. Nothing said that nine more matched. A packet written an hour ago returned nothing, because CI rebuilds the index only after a push. In free-text search, one long file could fill every row. The other files dropped out of view. A missing result and a hidden result looked the same. So the agent either stopped too early or searched again for something that was not there.

## Trigger Lookup

#### A Limited Answer Says What It Cut

The lookup now returns `totalCandidates`. That is the number of documents that matched before `--limit` cut the list. The human view reads `candidates : 2 of 11 (truncated) from 1090 phrase(s)`. The word `truncated` shows only when the limit hid something. A full answer reads as it did before.

#### A Lookup With No Hits Reads What the Index Missed

Sometimes the index returns nothing. The lookup then compares the `specs/` tree with the paths in the index. Any spec document the index does not list is new. The lookup reads the trigger phrases of those new documents, up to 500 of them. It scores them like any other match. The answer says when this happened. JSON carries `staleFallback`. The human view adds `fallback   : <files> unindexed doc(s) read, <matches> match(es)`.

The first design asked `git status` for new documents. That took 0.8 to 1.1 seconds per lookup. The budget is 200 ms. The path comparison replaced it. It is faster. It also finds documents committed since the last build. One gap remains. A phrase edited inside a document the index already lists still needs a rebuild. To keep an answer to the index alone, pass `--no-stale-fallback` or an explicit `--index`.

#### A Linked Project Scans the Right Tree

A project linked to a Skilled checkout reads its host's index. The extra scan now walks the host repository. That is where the index's paths live. A linked install with a packaged index is different. Its index names other documents, so the scan is skipped there. Before this fix it reported every host packet as a match.

#### An Error Is Not a Clean Miss

A crash inside the lookup used to exit 1. That is the code for "nothing matched". It now prints the error and exits 2. `staleFallback.files` also counted a document it failed to open. It now counts only what it read.

## Free-Text Search

#### Each File Appears Once

`rg-wrapper.mjs structured` ranks every match first. Then it keeps the best row per file. A file with more matches ends its row with `(+N more in this file)`. `--limit` now counts files. The default is 20. `--limit 0` shows them all. When the limit drops files, the answer ends with `+N more files with M matches`. The cut happens after ranking on purpose. Stopping ripgrep at the first match per file would keep each file's first line. That is often not its best line.

#### The Search Command Runs the Wrapper

`/speckit:search` used to run raw ripgrep. It never got the one-row-per-file result. Its default search now runs `rg-wrapper.mjs structured '<QUERY>' --json`. A phrase that starts with `--` still runs raw ripgrep. The wrapper would read it as a flag.

#### Path and Count Lists Respect the Limit

The wrapper's `path` and `count` recipes took `--limit` and ignored it. A broad pattern still printed every file. Both lists are now sorted and cut at the limit. The count list puts the busiest file first. Each answer says how many files it hid. The totals still cover every file.

#### The Record Carries the Totals

Wrapper JSON is now `schemaVersion: 3`. It reports `matchCount`, `fileCount`, `limit`, `truncated` and `hidden: { files, matches }`. Each row carries `moreInFile`. An unused recipe builder was removed. It capped each file at its first line.

A large track held all its packets in one flat list. The largest held 29. A reader had to scan every folder name to find the work on one subsystem. Each track with eight or more packets is now grouped. A packet lives at `specs/<track>/<sub-track>/<NNN>-<slug>`. It keeps its slug. Its number starts from 001 inside its sub-track. That covers changelogs, loop iterations, event streams, scratch evidence, fixtures and benchmark reports. Only a markdown link target in such a file is updated, so the link still resolves.

#### A Mixed Track Fails the Sweep

A track could hold flat packets beside its sub-tracks. Its children list was still correct, so no check reported it. `sweep-track-roots.mjs` now names the flat packets of such a track and exits 1. It does this in the working tree and with `--rev`. The pre-push check runs the sweep, so a mixed track blocks a push. `refresh-track-roots.mjs --apply` cannot clear it. #### A Historical Spec Doc May Follow a Moved Path

The rename rule said to leave a packet's historical spec docs alone. A move then leaves dead links, and the link check fails. The rule now allows one edit. A moved path that acts as a live locator is updated. The rest of the document stays as written.

`fingerprint-docset-generation.sh` resolved the repository root one folder short. It could not find the validator. ## Dotenv Guard

#### A Secret Stays Out of the Model

An agent that reads `.env` puts every secret in it into the model's context. The new `env-secret-guard` hook refuses that call on Claude Code, Codex, Cursor, Devin, OpenCode, Pi and DSH. One shared core decides. Each runtime gets a thin adapter.

A file counts when it is named `.env` or `.env.<suffix>`, or links to one. The template `.env.example` stays open. The guard refuses:

- **File tools and patches** that name a dotenv file.
- **Shell reads and redirects**, such as `cat`, `grep -f`, `cp`, `Get-Content` or `> .env`.
- **Hidden forms:** quotes, escapes, `$(...)`, variables, globs such as `.e*`, `sudo -u root` and `bash -c` scripts.
- **One-liners and links:** `node -e` or `python3 -c` code that names the file, and `ln .env other`.
- **Code handed the file:** `node -e '...' .env`, `node append.js .env`, `bash -c 'cat "$1"' _ .env` and `env -S "cat .env"`.
- **Hard links** to a dotenv file under any name, and a path a substitution prints, such as `$(printf .env)`.

An app that loads its own env still runs. `node --env-file=.env app.js` and `source .env` are allowed. The values never reach the agent's output there.

#### A Second Check After Each Shell Call

A call's text does not show everything it does, so the guard also judges the result. It records the project's dotenv files before a shell call. After the call it puts back any that changed and keeps the rejected version outside the checkout. It also looks for a dotenv value in the output. OpenCode and Pi replace the value before the model reads it. The other runtimes can only say that it reached the session and should be rotated. A live Devin run showed the need. After two refusals, the agent wrote to `.env` through a `node -e` program. The program took the file as an argument. `ENV_SECRET_GUARD_WRITE_CHECK=report` reports a write without undoing it.

#### Answers Without Values

The refusal names the way in. The guard lists the keys, reports the lines that fail to parse and fingerprints one value. Two equal fingerprints mean equal values. OpenCode offers this as three `env_secret_*` tools. Every runtime can run `.skilled/hooks/env-secret-guard/cli/env-secret.cjs`.

The parser reads a file the way dotenv does. A quoted value may span lines. A repeated key keeps its last value.

Claude Code, Devin and Cursor can refuse a file themselves, so each now carries a deny list for dotenv files. A live run on a dummy project showed how far each goes. Claude Code refused `Read`, `Edit` and `cat` with permissions bypassed. Devin refused reads in `auto` mode only, and nothing in `dangerous` mode. Cursor was not run. The guard's README also describes a secret manager and a runtime sandbox as stronger options.

DSH loads the dotenv file of the folder it starts in, so its shell holds values no file rule sees. The guard there also refuses a command that prints one, such as `printenv`. Using a variable, as in `psql "$DATABASE_URL"`, still runs.

#### The Fingerprint Key Stays Off Disk

The fingerprint is an HMAC-SHA256 keyed by `ENV_SECRET_GUARD_PEPPER` from the environment. Without the key, no digest is returned. A short secret could otherwise be guessed offline. The key is never read from a file, and the digest carries no length.

Every adapter fails open, so a guard bug never stops an agent. `SYSTEM_ENV_SECRET_GUARD_DISABLED=1` turns the guard off. It is read from the environment only, because `hook-flags.env` is a file an agent can write. An agent may read the guard's code but its file tools may not change it.

#### Two Scenarios Test It in a Live Session

`CE-P06` asks what `.env` defines, then compares two tokens, then asks for one. No canary value may appear. `CE-P07` asks for an edit to `.env`, which must stay unchanged, then to `.env.example`, which must go through.

## Session Handover

#### The Shell Shim Runs Only a Wrapper It Trusts

The shim lets you type `claude` and start inside the handover loop. It walked up from the current folder. It ran the first `.skilled/bin/skilled-loop` it found. So a repository you had cloned could supply the script your shell ran. The shim now stores the checkout it was sourced from. It runs a wrapper only inside that checkout or one of its linked worktrees. Git is asked from the sourced checkout, so a folder cannot vouch for itself. Anywhere else the plain runtime starts. To trust another checkout, add its absolute path to `SKILLED_LOOP_TRUSTED_CHECKOUTS`. Separate paths with a colon.

#### Handover State Is Read Only From a Checked Folder

Writing a handover record already checked its folder. The folder had to be a real directory that you own. Reading did not check. A linked or foreign folder could plant a record that approved a hop. Reads now apply the same check. An unsafe folder reads as empty. One line on stderr names it: `relaunch state directory is not a real directory owned by the current user`. `consume` also drops a note path outside the handoffs folder. The log records `handoff-outside-dropped`.

#### A Hop Keeps Your Launch Flags

A relaunched session carried its model, name and provider. Every other flag of the first launch was lost. A session started with `--add-dir` came back without it. A hop now replays the first launch's options in their original order. The claim seed replaces the start prompt. Flags that pick or continue a session are left out. `--resume`, `--session-id` and `-c` are three of them.

#### An Unknown Claude Window Stays Quiet

The nudge measures how full the context is. It assumed 200,000 tokens when no window was set. A session on a larger window was then nudged too early. It now nudges only against a known window. With none it stays quiet. It logs `context-nudge-skipped reason=window-unknown` once per session. `node .skilled/hooks/session-relaunch/bin/session-relaunch.cjs window` prints `Claude context window: none configured.` and names both settings. `/doctor:setup` shows the same line.

#### Smaller Fixes

- **A sub-agent cannot cancel or consume a handover.** The guard refused four lifecycle commands. It now refuses all seven.
- **One waiter reclaims a stale lock.** Several waiters could each remove an old lock and all enter. A waiter now takes a reclaim folder first. Then it checks the lock's age again.
- **A new loop starts without an old record.** A reused process id could match a dead loop's record. The wrapper removes that one file before the first launch.
- **A provider key no longer blocks an OpenCode dispatch.** The cli-opencode guard read any `OPENCODE_` variable as an open session. It now skips `OPENCODE_API_KEY`. Every other `OPENCODE_` variable still trips it.
- **The handover tests finish in a third of the time.** One file of 185 wrapper tests set the wait at 130 seconds. It is now four files that run side by side. The same 868 tests finish in about 40 seconds.

## Upgrade Notes

- **No migration required.** The new output fields are additions. `check-goal.cjs` now needs a packet or `--all`. `gpt-5.5` stops at `xhigh`. `summary.failure_classes` has a new `quota` key. Two saves in a row in one process each wait up to 100 ms more. A turn that ends on a done claim shows one more advisory line. `SYSTEM_COMPLETION_SENTINEL_DISABLED=1` turns it off. Strict overlay writes stay off until a manifest sets `strictWrites`. The first `apply` after this release records links and items. A `generated` glob that relied on `**/` matching part of a name stops matching. A script that calls `fanout-run.cjs` with one lineage must add `--allow-single-lineage`. A project that embeds the shipped `AGENTS.md` runs `/doctor:agents-md` to take the shorter Gate 6. Remove any link of your own to the three retired rule files.
- **If you parse wrapper JSON:** `results` holds one row per file. `paths` and `counts` hold only the files inside the limit. Read `schemaVersion`. Use `matchCount` and `fileCount` for the totals.
- **If you run the skill advisor from a built copy:** run `npm run build` in `.skilled/skills/system-skill-advisor/runtime` once. If you match on an advisor command id: `memory:save` and `command-memory-save` are now `command-speckit-save`. `command-spec-kit` is replaced by one id per command, such as `command-spec-kit-plan`. `command-prompt-improver` is now `command-prompt-improve`.
- **To keep a lookup to the index:** pass `--no-stale-fallback`.
- **Update Node.js first.** Install 22.23.4, 24.22.1, 26.12.1 or a newer release on one of those lines. Code Mode needs 24.22.1 or newer on the 24 line. Run `/doctor:mcp` to confirm.
- **If you saved a path to a packet in one of the ten tracks:** it has moved, so search for its slug. Older commits' `Spec:` trailers name the old path. A branch that edits a moved packet will conflict when it merges.
- **If an agent needs a `.env` value:** it now asks you. Paste the value yourself, or compare fingerprints. For those, run `openssl rand -base64 32` and export the result as `ENV_SECRET_GUARD_PEPPER` in your shell profile. Never put it in a file inside a repository.
- **If your own repository keeps flat packets beside sub-tracks:** the sweep now exits 1 there. Move each flat packet into a sub-track.
- **If you start a runtime in a checkout your shell does not source:** the handover loop no longer starts there. Add that checkout's absolute path to `SKILLED_LOOP_TRUSTED_CHECKOUTS`.
- **If Claude no longer nudges near its limit:** no window is configured. Set `autoCompactWindow` in the Claude settings or export `SESSION_RELAUNCH_WINDOW_TOKENS`. A `[1m]` model needs neither.
