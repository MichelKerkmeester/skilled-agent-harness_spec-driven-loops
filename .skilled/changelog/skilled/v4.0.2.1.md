# v4.0.2.1, Improved Chat Automation, Search & In-Session Handover

This release changes what you install, what an agent may read and what it is told to run. Skilled now needs a patched Node.js release. A new guard keeps the values in a `.env` file away from every agent. The skill advisor now names the slash command behind a hub skill. It also says whether the agent may run it.

Long sessions hand over more cleanly. A hop to a fresh session carries the running command and the folder goal. The shell shim trusts only your own checkout. Search answers now say how much they left out. A new spec document is found before the index catches up.

Projects that vendor Skilled get stricter overlay checks and an engine that cleans up after itself. Pi 1.5.2 loads every hook adapter again. Skilled's own checks and tests also run faster.

## Why This Release

Some gaps put your project at risk. A security notice in October patched Node.js. Skilled still accepted Node 20. Any agent could read `.env` and send every secret in it to the model.

Other gaps cost your agent time. A recommendation said `sk-doc` when you asked for a README. The agent then had to find `/create:readme` on its own. A search cut at its limit never said what it hid. A session that hopped mid-command came back as a plain chat and lost its place.

## Node.js

#### Patched Releases Are Required

A security notice of 23 October 2026 named the patched releases. They are 22.23.4, 24.22.1 and 26.12.1. The Node 20 line has no patched release. Nine packages now declare `^22.23.4 || ^24.22.1 || >=26.12.1`. They used to accept Node 20.11 and later. No package sets `engine-strict`, so npm warns on an older Node and goes on. Every CI step that sets up Node now uses 22.

**Breaking:** Code Mode is stricter. Its server declares `>=24.22.1 <25.0.0`. Its launcher picks an interpreter in that range. Without one it cannot start. Run `/doctor:mcp` to check your machine.

## Dotenv Guard

#### The Guard Refuses the Read

An agent that reads `.env` puts every secret in it into the model's context. The new `env-secret-guard` hook refuses that call. It runs on Claude Code, Codex, Cursor, Devin, OpenCode, Pi and DSH. A file counts when it is named `.env` or `.env.<suffix>`. A link to such a file counts too. The template `.env.example` stays open.

The guard catches file tools, patches and shell reads such as `cat`, `grep -f` and `cp`. It sees through quotes, `$(...)`, globs such as `.e*` and `bash -c` scripts. An app that loads its own env still runs. `node --env-file=.env app.js` and `source .env` are allowed.

#### Answers Without Values

The refusal names the way in. The guard lists the keys, reports lines that fail to parse and fingerprints one value. Two equal fingerprints mean equal values. Every runtime can run `.skilled/hooks/env-secret-guard/cli/env-secret.cjs`. OpenCode also has three `env_secret_*` tools. The fingerprint is an HMAC-SHA256 keyed by `ENV_SECRET_GUARD_PEPPER`. The key comes from your environment, never from a file. Without it, no fingerprint is returned.

#### Two More Layers Behind the Hook

A command's text does not show everything it does. So the guard records your dotenv files before a shell call. Afterwards it puts back any file that changed. It also looks for a dotenv value in the output. OpenCode and Pi replace that value before the model reads it. The other runtimes can only warn that it reached the session.

Claude Code, Devin and Cursor also carry their own deny list for dotenv files. So the file stays closed if the hook fails. On DSH the guard refuses a command that prints a loaded value, such as `printenv`. Every adapter fails open, so a guard bug never stops an agent. `SYSTEM_ENV_SECRET_GUARD_DISABLED=1` turns the guard off. It is read from the environment only.

## Skill Advisor

#### A Hub Skill Names the Command to Type

The advisor used to say `sk-doc` for "create a readme". You then had to find `/create:readme` yourself. Now a hub recommendation carries the command for the mode it picked. A brief head reads `use system-spec-kit → /speckit:plan (start)`. A hub that cannot pick one mode says so, as `sk-doc (needs a mode)`. A deep-loop command is offered only when the prompt asks for depth.

#### Every Command Has a Run, Start or Ask Policy

Each of the 44 tracked commands records what it writes and what it must ask first. The generator turns that record into one policy. `run` means the agent may run it now. `start` means it starts without `:auto`, so its setup asks. `ask` means it offers the command and waits. Gate 2 in `AGENTS.md` now tells the agent how to follow each one. A typed command or a direct instruction outranks the policy.

A typed slash command now reaches the model on every tracked row, with its policy and owner skill. Plain requests reach their command more often too. Paraphrases the tuning never saw still mostly miss.

#### Meaning Matching Has Its Own Doctor Route

A command can also pass on meaning when the local embedder runs. Each scored command row carries its own vector. A prompt needs a close match and a clear lead over the next command. A prompt that asks for no change gets no command this way. `/doctor:skill-advisor embedder` checks the embedder and plans each missing step. It asks before it pulls a model or starts a server. It never installs Ollama itself. The prompt embedding gives up after 750 ms.

#### Doctor Checks Show Whether the Brief Arrives

`/doctor:setup` gains two read-only legs. The embedder leg reads DEGRADED when meaning matching is off. The delivery leg reads DEGRADED when a prompt hook is missing or not approved. On Codex, no brief arrives until you approve the project hooks. A default `embed` now leaves Claude Code a one-line `CLAUDE.md` pointer to `AGENTS.md`.

#### Smaller Fixes

- **A question about the trigger index reaches spec-kit.** It used to end at the doctor helper. A question about index drift still goes to the doctor.
- **The doctor hand-off names the matched command.** It used to name only `/doctor:helper`, even when the exact command was known.
- **A prompt that names a `system-`, `cli-` or `mcp-` skill is read.** The prompt policy used to read only `sk-` names.
- **An OpenCode brief names the command and its policy.** The plugin used to drop both.
- **A read-only question about git history reaches sk-git.** `show the git log` used to return no skill. The question must name git, a commit or one of the branches main, master and develop.
- **The advisor starts on the Node.js its native module was built for.** An install now records that Node.js. A session on another major version used to fail its first call with `daemon launcher exited with code 1`.
- **A hub with many modes routes fast.** The compiled route built one rule for every subset of a hub's modes on every call. A hub with 18 modes built 262,125 rules and timed out. A rule now covers at most four modes.

## Session Handover

#### A Hop Carries the Command and the Goal

A session that hopped mid-command used to come back as a plain chat. Nothing named the running command. Now the handoff note carries an `Active command:` line. The next session runs that command again, with the same mode and arguments. The command finds its own step. A held deep-loop lock is released first, so the rerun does not wait for it. The note also points the next session at the spec folder's goal.

#### A Lost Goal Says Why

A goal that cannot be carried no longer disappears without a word. `prepare` prints one `goal not carried:` line with the reason. Cursor and Devin keep the goal they were handed. Pi and OpenCode bind the hop goal once, so `/new` or `/fork` starts clean. With goal autonomy on, OpenCode no longer pulls a prepared hop back into work. A declined hop prints a `skilled-loop <runtime>` line that now runs as pasted.

#### The Shell Shim Runs Only a Wrapper It Trusts

The shim lets you type `claude` and start inside the handover loop. It used to run the first `.skilled/bin/skilled-loop` it found above your folder. So a repository you had cloned could supply the script your shell ran. The shim now runs a wrapper only inside the checkout it was sourced from or a linked worktree. To trust another checkout, add its absolute path to `SKILLED_LOOP_TRUSTED_CHECKOUTS`.

#### Smaller Fixes

- **A hop keeps your launch flags.** A session started with `--add-dir` used to come back without it. Flags that pick or continue a session, such as `--resume`, are still left out.
- **An unknown Claude window stays quiet.** The nudge assumed 200,000 tokens when no window was set. It now logs `context-nudge-skipped reason=window-unknown` once instead.
- **Handover state is read only from a checked folder.** A linked or foreign folder could plant a record that approved a hop.
- **A sub-agent cannot cancel or consume a handover.** The guard refused four lifecycle commands. It now refuses all seven.
- **One waiter reclaims a stale lock.** Several waiters could each remove an old lock and all enter at once.
- **A provider key no longer blocks an OpenCode dispatch.** The cli-opencode guard now ignores `OPENCODE_API_KEY`. Every other `OPENCODE_` variable still trips it.

## Search

#### A Cut Answer Says What It Hid

The trigger lookup now returns `totalCandidates`. That is the number of documents that matched before `--limit` cut the list. The text view marks a cut answer as `candidates : 2 of 828 (truncated) from 1070 phrase(s)`. Each row also lists the phrases that matched. A crash inside the lookup used to exit 1, the code for no match. It now prints the error and exits 2.

#### A New Spec Document Is Found Right Away

CI rebuilds the index only after a push. So a packet written an hour ago returned nothing. Now a lookup with no hits compares the `specs/` tree with the paths in the index. It reads the trigger phrases of up to 500 unlisted documents and scores them. JSON then carries `staleFallback`. A phrase edited inside an indexed document still needs a rebuild.

#### Free-Text Search Shows Each File Once

One busy file used to fill every row. `rg-wrapper.mjs structured` now ranks every match, then keeps the best row per file. `--limit` counts files, with 20 as the default. A cut answer ends with a line such as `+1382 more files with 2681 matches`. `/speckit:search` now runs this wrapper for its default search. The `path` and `count` lists are cut at the limit too.

## Spec Workflow

#### Agents Reread the Request Before Done

Acceptance rows come from the spec. An outcome you asked for can be missing there while every check passes. The agent now maps each requested outcome to a met row. Otherwise it names that outcome as not done. The completion hook repeats the reminder on every done claim. It never blocks.

#### The Restraint Check Runs When Scope Is Written

The overengineering rule used to wait for code. By then a spec had frozen the addition into scope. The rule now fires on a spec or plan that adds a file, option, layer or dependency. `/speckit:plan` and `/speckit:complete` ask what fails today without it.

#### Reply Rules Are Two Files

Gate 6 named five rule files to load around a reply. Three mostly repeated the others, so they are retired. They are `answer-the-actual-request.md`, `communication-prose.md` and `communication-decisions.md`. Their unique clauses moved into `communication.md` and `uncertainty-and-honesty.md`. Gate 6 now loads `communication.md` before a reply. It loads `communication-handoff.md` before a turn ends.

#### Deep Loops Fail Clearly

A chat session could call the fan-out runner with one lineage. One process then wrote every iteration and skipped the loop's own setup and save steps. `fanout-run.cjs` now refuses that and names the single-executor workflow. A provider quota refusal now counts as `quota`, not as a crash. A review fan-out takes `--review-target`. A Codex effort above the model's ceiling fails before dispatch.

#### Smaller Fixes

- **A track that mixes packets and sub-tracks fails the sweep.** `sweep-track-roots.mjs` names the flat packets and exits 1. The pre-push check runs it.
- **`/speckit:implement` stops where it should.** It stops on a failing test and on a plan with an open design choice.
- **A plan names the file each phase touches.** A new spec folder also points chat sessions at the authoring card.
- **A waiting save gets its turn.** It could starve behind another process's queued saves.
- **An autonomous changelog release stops on an uncommitted entry.** It also writes the rollback beside each release step.
- **Release notes are detailed by default.** An entry must explain each feature, name every fix and show how it was checked.

## Installs and Overlays

#### A Vendored Tree Can Refuse Unowned Writes

A project that copies Skilled into its own repository keeps its changes as overlays. The guard used to know only paths an overlay already owned. Set `"strictWrites": true` in the manifest to change that. The guard then refuses a new file or an unowned upstream edit under a vendored root. The refusal names the fix. `/doctor:overlay apply --adopt <path>` turns the path into an overlay. A `generated` glob list names paths your generators write. `overlay-engine.cjs pre-commit` runs the same test on staged changes.

#### The Overlay Engine Cleans Up After Itself

A project that moved onto the engine reported three bugs and three gaps. All are fixed. A killed run's lock is taken over. A changed layout link is retargeted. A dropped appended item leaves the live file. `status` prints `STALE` and `LAYOUT` lines. `status --audit` lists drift no overlay owns. `apply --relayout` moves sources kept off their layout path. A re-pin no longer blocks on a file inside a folder an overlay replaces.

#### Pi Loads the Hook Adapters on Every Version

Pi 1.5.1 changed how it loads a linked extension. On Pi 1.5.2, 16 adapters then failed to load and `pi -p` exited 1. Each entry in `.pi/extensions/` is now a one-line file that re-exports its adapter. Pi 1.5.0 and Pi 1.5.2 both load all 22 entries.

#### Checks Pass in a Project That Vendors Skilled

A project that vendors Skilled reported checks that failed for reasons it could not repair. Four are fixed. The route sync check and the route-gold check read Skilled's own spec folders, which a project does not have. Both now skip there and name the reason. A hub may file all of a surface's paths under one hub intent. The sk-code router check accepts that once `hub-router.json` declares it in `surfaceIntentFolds`. The doctor's git check accepts a hook of your own that hands over to a Skilled hook. It also accepts a hook you leave out on purpose. An empty `INTENT_SIGNALS` block is read as empty.

#### Smaller Fixes

- **A release update checks the overlays.** `/doctor:update apply` now runs the overlay status check.
- **Three sk-doc checkers run on a vendoring repository.** The README, playbook and feature catalog checks read paths there correctly.
- **Browser captures stay out of the repository.** HAR files, cookie dumps and screenshots go outside it.
- **ClickUp pages are written in the browser first.** A saved page that lost a repeated line now fails its check.
- **The skill converter copies its source on Node 26.** A strict copy used to throw `ERR_FS_CP_EEXIST` there.

## Skilled's Own Repository

These changes touch the Skilled repository itself, not yours.

#### The Slowest Check Finishes Sooner

The wait after a push equals the slowest workflow it starts. Spec-Kit Check now runs its suites as parallel jobs. Its CLI tests run as three shards. Five workflows fetch only the paths they read. Seven more skip the research, review, scratch and archive folders. So do the CLI, runtime and deep-loop test jobs. A typical checkout there takes about 25 s less. Some full checkouts already ran faster, so that gain is not reliable.

#### Fewer False Reds and Faster Local Runs

A push that touches no sk-doc path runs 2 sk-doc test files instead of 56. A dropped `npm ci` download is retried up to three times. Two tests no longer race a child process's start time. A test run no longer leaves scratch database folders behind. The advisory workflow now fails when a gate-critical suite fails. Five workflows that failed on every push to `main` pass again. Local test runs take less than half their old time.

#### Spec Tracks Are Grouped Into Sub-Tracks

Skilled's ten largest spec tracks now group their packets into named sub-tracks. The largest held 29 packets in one flat list. A packet now lives at `specs/<track>/<sub-track>/<NNN>-<slug>`. It keeps its slug and is numbered from 001 inside its sub-track.

## Upgrade Notes

- **Update Node.js first.** Install 22.23.4, 24.22.1, 26.12.1 or a newer release on one of those lines. Code Mode needs 24.22.1 or newer on the 24 line. Run `/doctor:mcp` to confirm.
- **If an agent needs a `.env` value:** it now asks you. Paste the value yourself or compare fingerprints. For fingerprints, run `openssl rand -base64 32` and export the result as `ENV_SECRET_GUARD_PEPPER` in your shell profile. Never put it in a file inside a repository.
- **If you embed the shipped `AGENTS.md`:** run `/doctor:agents-md` to take the new Gate 2 and Gate 6 wording. Remove any link of your own to the three retired reply rules.
- **If you run the skill advisor from a built copy:** run `npm run build` in `.skilled/skills/system-skill-advisor/runtime` once.
- **If you match on an advisor command id:** `memory:save` and `command-memory-save` are now `command-speckit-save`. `command-spec-kit` is now one id per command, such as `command-speckit-plan`. `command-prompt-improver` is now `command-prompt-improve`.
- **On Codex:** approve the project hooks in `/hooks`. Until then the advisor brief never arrives. To turn on meaning matching anywhere, run `/doctor:skill-advisor embedder`.
- **If you start a runtime in a checkout your shell does not source:** add that checkout's absolute path to `SKILLED_LOOP_TRUSTED_CHECKOUTS`.
- **If Claude no longer nudges near its limit:** set `autoCompactWindow` in the Claude settings or export `SESSION_RELAUNCH_WINDOW_TOKENS`. A `[1m]` model needs neither.
- **If you parse wrapper JSON:** `results` holds one row per file. Read `schemaVersion`. Use `matchCount` and `fileCount` for the totals. Pass `--no-stale-fallback` to keep a lookup to the index alone.
- **If a script calls `fanout-run.cjs` with one lineage:** add `--allow-single-lineage`. The goal checker now needs a packet or `--all`.
- **If your own repository keeps flat packets beside sub-tracks:** the sweep now exits 1. Move each flat packet into a sub-track.
- **If you vendor Skilled:** strict writes stay off until a manifest sets `strictWrites`. The first `apply` after this release records links and items.
- **If a project runs sessions on more than one Node.js major:** reinstall the advisor runtime once, with `npm ci` in `.skilled/skills/system-skill-advisor/runtime`. The install writes the record the advisor starts from.
- **If your sk-code hub files a surface's paths under one hub intent:** add `"surfaceIntentFolds": { "<surface packet>": "<HUB_INTENT>" }` to `hub-router.json`, then refresh the hub's activation manifest.
- **If your hooks hand over to Skilled's:** add the line `# skilled-hook-handover: <folder>` to each one. The folder is the path from your hook to Skilled's hook folder. For a hook you leave out, run `git config --local --add skilled.omitHook <name>`.
- **If your repository links its own files into `.pi/extensions/`:** make each entry a one-line file, `export { default } from '<path>';`.
- **If you saved a path to a packet in Skilled's own `specs/`:** it may have moved, so search for its slug.
