# v4.0.2.1, Search Says How Much It Found

Gate 1 and `/speckit:search` used to hide what they left out. A limited lookup looked complete, a new spec document stayed invisible until the next index build and one common phrase filled the whole result with two files. Each of the three now says what it found and what it held back.

The work started as research into sweet-search, an external code-search tool. The research kept Skilled's own lexical retrieval and took three lessons from it. This release builds those three, sends the search command through them and fixes the routing and checks that the build exposed.

> Spec folder: `specs/hooks-plugins-extensions/retrieval-integrations/001-sweet-search-integration`

&nbsp;

## Why This Release

An agent reads a Gate 1 answer as the whole picture. With `--limit 2` it saw two candidates and no sign that nine more matched. A packet written an hour ago returned nothing, because the committed index is rebuilt in CI after a push. In free-text search, one long ledger could take every row and push the other files out of view.

A missing result and a hidden result looked the same. An agent that cannot tell them apart either stops too early or searches again for something that is not there.

&nbsp;

## Trigger Lookup

#### A Limited Answer Says What It Cut

`lookup-trigger-index.mjs` returns `totalCandidates`, the number of documents that matched before `--limit`. The human view reads `candidates : 2 of 11 (truncated) from 1090 phrase(s)`. The word `truncated` appears only when the limit hid something, so an uncut answer reads as before.

#### A Zero-Hit Reads What the Index Missed

When the index returns nothing, the lookup compares the `specs/` tree with the paths the index lists. It scores the declared trigger phrases of the spec documents the index does not have yet, up to 500 of them. The answer says so: JSON carries `staleFallback`, and the human view adds `fallback   : <files> unindexed doc(s) read, <matches> match(es)`.

The first design used `git status` to find new documents. That cost 0.8 to 1.1 seconds per zero-hit against a 200 ms budget, so it was replaced with the path comparison, which also finds documents committed since the last build. A phrase edited inside a document the index already lists still needs a rebuild.

`--no-stale-fallback` or an explicit `--index` keeps the answer to the index.

#### A Linked Project Scans the Right Tree

A project linked to a Skilled checkout reads its host's index. The fallback now walks the host repository, where that index's paths live. The packaged index of a linked install names other documents, so the scan is skipped there. Before this fix it reported every host packet as a match.

#### An Error Is Not a Clean Miss

A rejected promise inside the lookup exited 1, the code for "nothing matched". It now prints the error and exits 2. `staleFallback.files` also counted a document it failed to open. It now counts only what it read.

## Free-Text Search

#### Each File Appears Once

`rg-wrapper.mjs structured` ranks every match, then keeps the best row per file. A row whose file held more matches ends with `(+N more in this file)`. `--limit` now counts files, 20 by default, and `--limit 0` shows all of them. When the limit drops files, the answer ends with `+N more files with M matches`.

The cut happens after ranking on purpose. Stopping ripgrep at the first match per file would keep each file's earliest line, not its best one.

#### The Search Command Runs the Wrapper

`/speckit:search` ran the raw ripgrep recipe, so it never got this shaping. Its default lane now runs `rg-wrapper.mjs structured '<QUERY>' --json`. A phrase that starts with `--` still runs the raw recipe, because the wrapper reads it as a flag.

#### The Record Carries the Totals

Wrapper JSON moved to `schemaVersion: 2`. It reports `matchCount`, `fileCount`, `hidden: { files, matches }`, `limit`, `truncated` and `moreInFile` on each row. An unused recipe builder that capped each file at its first line was removed.

## Routing

#### Index Questions Reach the Skill That Owns the Lookup

The skill advisor holds every skill at a low score on a read-only prompt. With no skill passing, the doctor hand-off claimed any prompt that named the index. A read-only prompt that names the trigger index now lifts `system-spec-kit`. A prompt about index drift is not lifted and still reaches the doctor, which owns the repair.

`system-spec-kit` also gained intent signals for spec-document search, the ripgrep wrapper, trigger phrases and unindexed spec documents.

## Fixes Along the Way

#### Checks That Failed Before This Work

- **The command reference check passes.** It tripped on the gitignored deep-loop graph databases and now skips them.
- **Both READMEs declare the host-only index paths.** The reference check reported them as missing.
- **The speckit command README has its purpose and instructions sections.** The document validator required both.
- **`SPECKIT_RG_BIN` is in the environment reference.** The variable was read by the code and listed nowhere.

#### Found in Review

- **The human view no longer cuts twice.** It printed 20 rows even when `--limit` asked for more, and the hidden count did not cover the difference.
- **The retrofit baseline counts every match.** It counted rows after the cut.
- **Less code in the fallback.** A review against the overengineering rule found no blocking issue and ten small ones. The ones that held were applied: a sort of an already sorted list, three exports nothing imported and four tests that repeated another test.

## How It Was Checked

#### Before and After

| Check | Before | After |
|---|---|---|
| Lookup with `--limit 2`, 11 documents match | 2 candidates, no total | `2 of 11 (truncated)` |
| Lookup for a packet written after the last index build | no result | found, with `fallback : N unindexed doc(s) read` |
| `/speckit:search` for `trigger index` | 2,614 match lines | 20 rows, one per file, and a count of the 1,329 files it hid |
| "Explain which files the trigger index omits" | doctor helper at 0.80 | `system-spec-kit` at 0.85 |
| "Look up a trigger phrase already in the index" | doctor helper at 0.80 | `system-spec-kit` at 0.87 |
| Lookup that throws | exit 1, reads as a miss | error text and exit 2 |

#### What It Costs

The lookup budget is 200 ms at p95 and did not move. A zero-hit takes 89 to 102 ms against the index alone and 155 to 176 ms when the fallback reads 156 documents. A lookup that finds something does not run the fallback, and its median stayed level at 72 ms. The wrapper's median query time stayed at 38 ms.

#### Tests and Scenarios

- **The `system-spec-kit` suite passes.** 4,511 tests passed and none failed. The baseline before the work was 4,071 passed and none failed.
- **The skill advisor suite passes.** 1,387 tests passed and none failed, four more than before the routing change.
- **Three conversation scenarios pass.** A real agent session was asked each question cold: the cut lookup, the unindexed packet and the flooded search. Each one answered from the new output.
- **Routing was probed with stored prompts.** Six of seven now reach the expected skill. The seventh is a three-way tie between `sk-code`, `system-spec-kit` and `sk-doc`, left as it is by decision.
- **Each fix fails without its change.** The human-view and retrofit tests were run against the reverted code and failed.
- **The alignment battery passes.** 55 checks passed and none failed over the changed files.
- **Strict validation passes.** All nine folders of the packet report `RESULT: PASSED`.

`system-spec-kit` (v2.12.41.0 to v2.12.44.0 and v2.12.47.0) and `system-skill-advisor` (v0.18.6.0) have their own changelog entries for this release.

## Upgrade Notes

- **No migration required.** The new output fields are additions.
- **If you parse wrapper JSON:** `results` now holds one row per file. Read `schemaVersion` and use `matchCount` for the total.
- **If you run the skill advisor from a built copy:** run `npm run build` in `.skilled/skills/system-skill-advisor/runtime` once.
- **To keep a lookup to the index:** pass `--no-stale-fallback`.
