# v4.0.2.1, Search Says How Much It Found

Gate 1 and `/speckit:search` used to hide what they left out. A limited lookup looked complete, a new spec document stayed invisible until the next index build and one common phrase filled the whole result with two files. Each of the three now says what it found and what it held back.

> Spec folder: `specs/hooks-plugins-extensions/retrieval-integrations/001-sweet-search-integration`

&nbsp;

## What's New at a Glance

- **A lookup reports its total.** It returns `totalCandidates`, so `--limit 2` over 11 matches says 2 of 11. You can tell a short answer from a cut one.
- **A new document is found before the index catches up.** On a zero-hit the lookup reads the spec documents the index does not list yet. It reports how many it read, and `--no-stale-fallback` keeps the answer to the index.
- **Search shows one row per file.** `/speckit:search` keeps the best row per file and counts what the limit hides. A common phrase used to fill all 20 rows from two files.
- **A question about the index reaches spec-kit.** A read-only prompt that names the trigger index used to end at the doctor helper. It now routes to `system-spec-kit`, and a question about index drift still goes to the doctor.
- **A failed lookup no longer looks like a miss.** An error inside the lookup exited 1, the code for a clean no-hit. It now prints the error and exits 2.

`system-spec-kit` and `system-skill-advisor` have their own changelog entries for this release.
