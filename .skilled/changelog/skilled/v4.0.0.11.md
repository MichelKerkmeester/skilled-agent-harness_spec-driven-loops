# v4.0.0.11, Prove Your Git Setup in One Command

v4.0.0.11 adds `/doctor:git setup`, one read-only command that shows whether sk-git is really enforcing your rules. Adapting sk-git to your own repository used to end without any proof it worked, because several parts failed without a word.

> Spec folder: `specs/sk-git/033-git-setup-customization` (Level 2)

&nbsp;

## What's New at a Glance

- **One command checks the git setup.** `/doctor:git setup` runs eleven read-only checks, from the hook install to the AI tool hooks, and gives each a result and the source it read.
- **Every problem names its fix.** A failing check prints the command that clears it, with every path quoted so it works in any folder, and the run itself writes nothing.
- **A half-working setup no longer reads as healthy.** A check that could not run shows UNKNOWN, and a gate or advisory you switched off ends `STATUS=DEGRADED` with exit 3, kept apart from a failure.
- **The verdict holds in your repository.** The check reads your repository's own hooks and rules file, counts an AI tool hook only when the script it runs exists and never runs code from the repository it inspects.
- **It works in all seven AI tools.** `--tool` names Claude, Codex, Devin, Cursor, OpenCode, Pi or Hermes, and each tool's git advisory must really be wired to pass.
- **Changing one commit rule changes one line.** `/doctor:git standards set` keeps the layout of the shipped commit template again.

&nbsp;

## Upgrade

No migration required. Run `/doctor:git setup` after you adapt sk-git, and run each repair it prints.
