# v4.0.0.11, Prove Your Git Setup in One Command

v4.0.0.11 adds `/doctor:git setup`. It is one read-only command. It shows whether sk-git is really enforcing your rules. Adapting sk-git to your own repository used to end with no proof it worked. That is because several parts failed without a word.

&nbsp;

## What's New at a Glance

- **One command checks the git setup.** `/doctor:git setup` runs eleven read-only checks. They run from the hook install to the AI tool hooks. It gives each check a result and the source it read.
- **Every problem names its fix.** A failing check prints the command that clears it. Every path is quoted, so it works in any folder. The run itself writes nothing.
- **A half-working setup no longer reads as healthy.** A check that could not run shows UNKNOWN. A gate or advisory you switched off ends `STATUS=DEGRADED` with exit 3. That is kept apart from a failure.
- **The verdict holds in your repository.** The check reads your repository's own hooks and rules file. It counts an AI tool hook only when the script it runs exists. It never runs code from the repository it inspects.
- **It works in all seven AI tools.** `--tool` names Claude, Codex, Devin, Cursor, OpenCode, Pi or Hermes. Each tool's git advisory passes only when its hook code really registers the handler. That is read from the code, not matched as text.
- **Changing one commit rule changes one line.** `/doctor:git standards set` keeps the layout of the shipped commit template again.

&nbsp;

## Upgrade

No migration required. Run `/doctor:git setup` after you adapt sk-git. Then run each repair it prints.
