# v4.0.0.5, sk-code Adapts to Your Own Stack

v4.0.0.5 makes `sk-code` safe to adapt. OpenCode (`sk-code-opencode`) is the native surface and stays, while Webflow and Obsidian are optional examples you can remove. A surface you add now ranks ahead of OpenCode, and each check you meet on the way names its fix.

> Spec folder: `specs/sk-code/011-sk-code-poinytail-based-refinement/026-external-surface-priority-build` (Level 2)

&nbsp;

## Why This Release

The README used to tell you to replace all three surfaces, the native one included, and its steps stopped before the checks passed. Deleting an example left over a hundred doctor failures and drift guards that crashed. A surface you added lost every keyword tie to OpenCode.

&nbsp;

## What's New at a Glance

- **One guide takes you from the shipped tree to your own stack.** The README block "What Adapting `sk-code` Looks Like" covers the hooks to install, the folders to keep, removing an example, adding a surface and the checks that prove it.
- **OpenCode is native and the other two are optional examples.** The README, the hub `SKILL.md` and the hub README now say so, and none of them tells you to replace OpenCode.
- **A new surface lands ahead of the shipped ones.** `/create:skill-parent update --surfaces` places it after the workflow modes and before the existing surfaces, so it wins a keyword tie against OpenCode. Its report also names the two steps it cannot run for you: a canary case with its fixture copy and a commit with the hooks installed.
- **Failure messages point at the fix.** The doctor names the README block when a surface folder is missing, and the guard names both manifest paths and the copy that clears it. A pruned `specs/` now stops sync and the guard with the folder to restore, where before they passed or printed a stack trace.
- **The drift checks tolerate a removed example.** They read only the surfaces on disk and take the surface count from `mode-registry.json`, so "two surfaces" passes on a hub with two.
- **`ROUTER.md` keeps its own version.** Doctor check 13a compares only the JSON routing files with `SKILL.md`, and a changelog run no longer writes the release version into `ROUTER.md`.

&nbsp;

## Upgrade

No migration required. A hub `ROUTER.md` whose version you matched to a release can stay as it is, because the doctor no longer compares it. To adapt `sk-code`, follow the README block named above.
