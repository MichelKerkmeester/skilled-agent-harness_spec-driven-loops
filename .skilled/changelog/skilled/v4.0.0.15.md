# v4.0.0.15, Spec Docs a Smaller Model Can Write

A spec packet used to need a strong model. A fast, cheaper model would leave template text unfilled, delete sections it should keep and loop on metadata errors it could not read. This release makes the templates, the validator and a one-page authoring guide clear enough that such a model writes a complete packet, and it keeps every existing packet's verdict exactly as it was.

It also trims what a model has to carry: three add-on templates are gone, scaffolds lose their filler sections, and the validator repairs a draft's generated metadata on its own. The skill advisor stops misrouting typed commands and stops calling most prompts ambiguous.

> Spec folder: `specs/system-speckit/054-weak-model-spec-authoring` (Level 2)

&nbsp;

## Why This Release

Spec-driven work only scales when cheaper models can do the writing. Measured over eight rounds, packets written against these templates scored better than packets written before this work in every round (24.8 against 22.9 out of 30), and authoring took no measurable extra time.

&nbsp;

## What's New at a Glance

- **Templates say what good looks like.** Every section carries a short fill note with a good and a weak example.
- **An unfilled value can no longer ship.** A template value left unfilled passes while the packet is a draft and fails once it is not.
- **One guide, one validator run.** The authoring card tells a model to validate once, fix every failing rule and stop after three rounds.
- **Drafts repair their own metadata.** A strict validation of a draft rewrites stale generated metadata instead of failing on it.
- **Less to carry.** Three add-on templates are gone and scaffolds drop their filler sections.
- **Safer scaffolding.** `create.sh` no longer writes outside the repository through a crafted track or a symlink.
- **The advisor routes typed commands to their owner.** It also flags far fewer prompts as ambiguous.

&nbsp;

## Spec Kit

#### Templates That Teach

Each template section now opens with a fill note: one line on what to write, a good example and a weak one. The examples use a neutral task instead of echoing whatever the model was asked to build, so a model no longer copies them into its own packet. Scaffolds lose the sections small work never needs: the effort estimate and the extended rollback are gone, edge cases shrink to three lines and sign-off to one row.

A `spec.md` now carries a Measured Behavior block for the command the change affects and its real output. The validator warns, without failing, when that block holds neither output nor a reasoned "N/A".

#### An Unfilled Value Cannot Ship

Templates mark each value a writer must supply with a `[YOUR_VALUE_HERE: ...]` token. The validator lets a token stand while the packet's status is Draft, as a warning, and fails the packet at any other status. A token quoted inside inline code or a code block is treated as an example. A code block now ends only on its own fence marker, so a fence quoted inside another one cannot hide a token after it. Docs from before this release validate exactly as they did.

#### One Guide and One Validator Run

The spec authoring card (`spec-authoring-card.md` in system-spec-kit) is a one-page path through a packet for a weaker model. It asks for one `validate.sh --strict --quiet` run, a fix for every failing rule, and a stop after three rounds. When the run fails on generated metadata, the validator's first hint line is the exact repair command.

#### Drafts Repair Their Own Metadata

When every error in a strict validation of a draft comes from generated metadata, the validator runs the repair once, names every file it rewrote and validates again. It never touches body text, never runs in CI and never runs for a packet that is not a draft. A recursive run repairs each draft child the same way.

#### Three Add-Ons Removed

The before-after, roadmap and resource-map add-on templates are gone, leaving seven add-ons. The research and review loops still write their own resource maps, which never read the removed template.

#### Scaffolding Stays Inside the Repository

`create.sh --track` refuses an absolute path or one with `..`. `create.sh --path` judges an existing folder or link by where it really points, so a link out of the repository, a broken link, a regular file and the repository root itself are all refused. A track that already exists as a symlink keeps working by design.

&nbsp;

## Skill Advisor

#### Typed Commands Route to Their Owner

A prompt that types `/deep:research :auto` used to rank system-spec-kit first, because that skill borrowed score from the deep loop it supports. A skill that borrows from a typed command's owner can now rise up to the owner but never past it. Mode suffixes such as `:auto` and `:confirm` no longer count as words in the prompt, so they stop matching any skill that happens to mention "auto".

#### Fewer False Ambiguity Flags

The advisor called 110 of 261 labelled routing prompts ambiguous, mostly because a confidence floor lifts unrelated skills to the same confidence as the top. A skill that only reached that floor now counts as tied only when its score is also close, and a skill held below a typed command's owner never counts as tied with it. Flags fell to 78, every top pick stayed the same, and the hook brief now names a skill that is actually tied.

&nbsp;

## Git Worktrees

#### Private Commands Reach Every Worktree

An operator's private `local-*` commands are git-ignored, so a new worktree used to start without them. Worktree provisioning now links each one in from the primary checkout.

&nbsp;

## Upgrade Notes

- **Drop.** Stop requesting the before-after, roadmap and resource-map add-ons. Existing packets that hold those files still validate.
- **Adopt.** Point a weaker authoring model at the spec authoring card. Set `SPECKIT_DRAFT_AUTO_REPAIR=0` when a validation run must not write.
- No existing packet changes verdict.
