# v4.0.0.3, Update Safely, Commit Clearly, Read Plainly

v4.0.0.3 lets you move your copy of Skilled to a newer release with one command, `/doctor:update`, and it never overwrites a file you changed. Commit message rules now belong to each repository, and every AI tool sees the hard rules. Four Jev features that proved themselves turn on once a Jev key is stored.

The other doctor commands are split so each one checks one part of the framework. The standalone communication skill is removed, and a request for plainer wording now keeps every claim.

&nbsp;

## Why This Release

Updating Skilled used to mean copying files by hand and hoping nothing you had changed got lost. `/doctor:update` did not update anything. It rebuilt databases.

The framework had also grown across more AI tools and documents than its checks covered. Templates described rules the hooks never read, some tools never saw the hard rules and deep-review runs lost their record after the first step.

&nbsp;

## What's New at a Glance

- **One command updates your copy of Skilled.** `/doctor:update` shows what a newer release changes, asks you about every file you edited and can undo the whole update.
- **Repositories own their message rules.** The commit hook, the push check and CI read each repository's own templates. Every commit needs a body, and the message check has no off switch.
- **The hooks trust only their own checkout.** A cloned repository can no longer run its code in your hooks, and one git setting keeps an optional check off across every command.
- **Fresh copies build what they need.** Code Mode builds its own server, and a new worktree arrives ready to use.
- **Each doctor command checks one thing.** The skill advisor, the deep loop and the runtime mirrors have their own commands.
- **Plain-language requests keep every claim.** The communication skill and its rewrite commands are gone, and the rules explain how to fix robotic prose.
- **Every AI tool sees the hard rules.** They fit inside the part of `AGENTS.md` every tool reads, and a new gate loads the reply rules before each answer.
- **Deep-loop runs finish their work.** Review runs keep every step and hold their lock against a second run until they release it. A failed run says why it failed, and parallel workers no longer stop to ask.
- **Jev features turn on with a stored key.** Four features that beat their baselines run on their own, and each has an off switch.
- **Checks catch broken links and stale files.** One shared list decides metadata values, and a scan tells a moved file from a deleted one.
- **Security fixes arrive on their own.** Small security updates merge once their checks pass, and vulnerability reports stay private.

## Updating to a New Release

#### One Command Brings Your Copy Up to Date

`/doctor:update` compares your copy of Skilled with a framework release and brings it up to date. Run it with no action, or with `check`, to see where you stand without changing anything. The report lists each skill and folder as current, updated in the release, new, removed, changed by you or in conflict with the release. It also shows the release notes that apply.

The updater picks the newest stable release. `--release=<tag>` picks a specific one, `--include-prerelease` allows pre-releases and `--scope` limits the update to the skills or folders you name. The database rebuild this command used to run now lives in `/doctor:skill-advisor rebuild`.

#### Your Own Changes Are Never Overwritten

A file you have not touched takes the release version directly. A file you changed waits for your decision. `align` walks through each one and asks whether to keep your version, switch to the release version or merge the two. A merge shows you the full merged file before you accept it, and asks you to finish any part it could not combine. You can also leave a whole skill or folder for later.

Files the framework generates, such as indexes and route manifests, never count as your changes. If you regenerated one yourself, the updater keeps your copy and tells you which command rebuilds it.

#### Every Update Can Be Undone

`apply` shows its full plan and asks once before it writes anything. It brings in the release's changes to files you never touched and your decisions for the rest, then checks the result. Every run keeps a record, and `rollback` restores your copy from it, asking first. `--dry-run` previews any of these steps without writing. A lock stops two updates from running at once.

#### Copied Installs Record Where They Started

A copy of Skilled placed in another repository has no git history to compare against. The first `check` there says so, and `record-base` records which release the copy came from. Commit the file it writes, `.skilled/release/base.json`. If the repository's own remote has no framework tags, `--remote` names the framework repository once, and later runs remember it. A copy made from v4.0.0.0, which keeps one changelog folder as a link, used to stop at that link and now reports it as a file you keep.

## Commit Message Rules

#### Repositories Own Their Message Rules

Each repository's commit, pull-request and branch templates now carry the rules for that repository. The commit hook, the push check, the agent checks and CI all read the same rules, so one repository's rules no longer apply to every other one. Because the push check and CI use the same rules, a commit made with `--no-verify` to skip the local check is still refused when you push it.

#### Every Commit Carries a Body

The commit hook used to ask for a body only when a commit touched four or more files, so small commits said what changed but never why. It now refuses any message without a sentence below the subject line. A trailer such as `Spec:` alone does not count. Merge, revert, `fixup!`, `squash!` and `amend!` commits are exempt.

#### The Message Check Has No Off Switch

`SPECKIT_SKIP_COMMIT_MSG_VALIDATE` used to turn the commit message check off. The variable is gone, so setting it no longer lets a message through. To satisfy a rule, fix the message or change the rule in the repository's template.

#### Commit Rules Catch Wrong Scopes and Long Subjects

A nickname for a scope, such as `spec-kit` for `system-spec-kit`, is now blocked, and the message names the right one. A subject over 80 characters warns, and 100 stays the hard limit. A commit marked as breaking, with a `!` after its type such as `feat!:` or a `BREAKING CHANGE:` line, is refused unless its body explains itself under `Context:`, `Changes:` and `Verification:` headings. Bundled flags such as `git commit -am` no longer hide the message from the check. A message or pull-request description over the length limit is now refused instead of quietly cut short.

## Git Hook Safety

#### Cloned Repositories Cannot Run Code in Your Hooks

The git hooks usually run for every repository on your machine, and they used to load their checks from whichever repository they ran in. A cloned repository could ship its own copies of those checks and have them run on every pull, commit or push. The hooks now use a repository's own checks only in the copy they were installed from, its worktrees or a repository you trust with `git config --local skilled.trustRepoHooks true`. Every other repository gets only the message check.

#### Hooks Stop When a Check Cannot Run

A check that crashed used to let the commit through as if it had passed. It now blocks the commit and says the check crashed. A staged file that git cannot read also blocks the commit instead of skipping its checks.

#### Optional Checks Can Stay Off

Turning off an optional check used to mean adding its `SPECKIT_SKIP_*` variable to every command. Setting `speckit.hooks.<key>` to `off` in git config now keeps it off, and each run prints one line saying so. The two approvals a single push needs, for pushing outside the allowed branches and for deleting many files, still go on the command itself.

#### Push Checks Read What You Push

A spec in the commits you push now counts even if your current files lack it, so a code change and its spec can go up together. The check also looks only at the commits the push adds, so a force-push or a push that carries edits made on GitHub no longer fails on commits the server already has.

## Hooks on More AI Tools

#### Codex Hooks Run Again

Codex 0.160 renamed its shell tool from `exec` to `Bash`, so the git checks, the spec-folder check and the dispatch checks had silently stopped running under Codex. They now recognize both names. Codex asks you to approve the changed hooks once in `/hooks`.

#### Live-Sync Hooks Reach More AI Tools

The hooks that keep each session's copy in step with the shared live branch now run on Cursor and Devin, and Hermes runs the follow hook too. Where a tool cannot run a hook, the hook list now says why.

#### Devin's Write Tool Is Checked

Devin's `write` tool creates or overwrites a file, yet it skipped the spec-folder check and the post-edit check that its `edit` tool runs. Both checks now run for `write` too.

## Fresh Clones and Worktrees

#### Worktrees Check Themselves and Arrive Ready

A worktree is a second working copy of the same repository. Hooks shared from the main copy judged a worktree by the main copy's older rules, which refused the very commit that added a new rule. A worktree now uses its own rules. A new worktree also arrives with spec-kit built and every package it needs installed, so its tools work at once instead of failing with a one-line Node error.

#### Code Mode Builds From a Fresh Copy

A fresh clone or worktree had no Code Mode server built, so it could not start. The server's package file is now committed, and `install.sh` builds the server whenever it is missing or out of date.

The config check, the docs and the MCP doctor now name each key the way Code Mode reads it: the tool's name with each underscore doubled, then the key, such as `clickup__official_CLICKUP_API_KEY`. `/doctor:mcp install` and `debug` now cover Code Mode only, and the `--server` option is gone.

## Doctor Commands

#### Each Doctor Command Checks One Thing

`/doctor:speckit` used to front ten checks owned by different skills. It now checks spec-kit search only: the trigger index, its lookup and the search recipes. The skill advisor's checks moved to `/doctor:skill-advisor`, which gains a `rebuild` that backs up the advisor's database first and restores it if anything fails. The deep loop and the runtime mirrors have `/doctor:deep-loop` and `/doctor:runtime-mirrors`, and the embeddings and fable-mode checks are gone. If you give `/doctor:speckit` an old target name, it tells you which command handles it now. A doctor command that needs a target and gets none shows its menu and waits instead of guessing.

#### Hook Switches and Message Rules in One Place

`/doctor:git hooks` lists each optional check with its saved setting and changes one after showing the exact `git config` command. `/doctor:git standards` copies the shipped templates into the repository's `.sk-git/` folder once, then changes or removes one rule at a time. It refuses any change the hooks would reject. `--dry-run` shows the plan and writes nothing.

#### Settings Saved Only With a Yes

`/doctor:env` shows where each documented setting is set, including every setting the git hooks read, without revealing secret values. It saves a preference only after showing the exact line it will write and getting a yes.

#### The Search Doctor Can Report Healthy

`/doctor:speckit` treated any weak search phrase as a problem, and every real set of documents has a few, so it never came back healthy. Weak phrases are now listed as notes that leave the result unchanged.

#### Doctor Scripts Catch What They Used to Miss

Several of the doctor's own scripts reported a pass on real problems or crashed on bad input. A deleted command no longer hides behind one with a similar name, a crash reports an error and a skill missing from the advisor's records is named. Every doctor script now has tests that run locally and in CI.

## Plain Language

#### Plain Language Keeps Every Claim

The standalone `sk-communication` skill is removed, along with its optional plain-English rewrite of command output and its two rewrite commands. For a plainer reply, ask the assistant to say it more plainly.

The repository rules now tell two requests apart. "I don't follow" asks for a new explanation, with an example, numbered steps or a picture. "Say that more plainly" asks for a copy edit that keeps every claim, number and caveat at the same strength, and keeps code, commands, paths and names exact. If a simpler word changes the claim, the claim wins.

#### Robotic Prose Gets a Plain Fix

The writing rules now name terse, robotic prose: symbols in place of verbs, piled-up nouns, unexplained codes and half sentences. They ask the assistant to use action words, say who does what and explain every code or count.

&nbsp;

## Rules Every Session Loads

#### A Gate Loads the Reply Rules Before Each Answer

The reply rules used to load from one line deep in `AGENTS.md`, and sessions often missed them. `AGENTS.md` now has Gate 6, which loads them before every real reply, even when nothing is being changed. In its final test run it cut missed loads by 38 points without slowing the other gates. Plain search phrases added to 11 rules help an everyday request find the right rule. The rules also now ask for a technical subject to be explained plainly the first time, without dropping a caveat or a number.

#### Every AI Tool Sees the Hard Rules

Devin reads only the first 16 KB of `AGENTS.md`, and the hard rules ran past that point, so Devin never saw rules such as "never fabricate". The sections were reordered so every hard rule fits, and a check now fails if one slips past the limit. Codex reads the root `AGENTS.md` directly, so the separate `.codex/AGENTS.md` copy is gone.

The rule check also fails when a rule's trigger has no matching row in `REPO RULES.md`, the table that tells a session which rule to load. Seven triggers were missing, so no session was ever sent to those rules.

## Deep Review and Research Runs

#### Deep-Review Runs Keep Every Step

A deep review runs in rounds and keeps a log of each one. The log is rebuilt from a master record, and both review workflows wrote their first line into the log directly, in a shape the rebuild could not reproduce. So every round after the first was dropped from the log. Two more faults sat behind it: the master record rejected the review's round format and refused any entry over about 10 KB. All three are fixed. Resume, restart, pause, recovery and blocked-stop records now reach the master record as well, so the log shows them. Restart a review that was opened before this release.

#### Review Runs Release Their Lock and Explain Failures

Review and AI Council runs released their lock without the key they took it with, so every run ended with `released:false` and left the lock in place. They now pass the key, as research runs already did. When an AI tool timed out or crashed mid-run, the run only said a file was missing. It now reports `dispatch_failed` with the exit code, how long the tool ran and whether it hit the time limit. A retry keeps the first attempt's record instead of overwriting it.

A second run could also take a live run's lock, because the lock named a process that had already exited. Every deep loop now renews its lock each round, so a running loop keeps it, and a crashed run's lock frees itself within an hour.

#### Outside Models Must List What They Find

When a deep loop hands a round to another AI tool's model, that model now gets the same output rules as a built-in agent. A round that claims more findings than it lists fails at once. Before, a run could claim 46 findings, list 22 and only fail at the very end.

#### Parallel Workers Finish Without Asking

A deep loop can split its work across parallel workers, each in its own folder. A worker used to stop on rules written for a person at the keyboard, such as asking before a risky step, and nobody was there to answer. Inside its own folder it now records the question and carries on, while acting outside that folder stays barred. A resumed worker keeps its earlier session, and a worker that still ends on a question is reported as `needs_input` instead of being retried.

#### Research Runs Keep Accurate Records

Deep research now opens its run through the same record system as review, releases its lock correctly, ticks off the questions each round answered and keeps its lock files out of git. Its `status`, `query` and `convergence` scripts accept `--read-only`, and `/doctor:deep-loop` uses it so a diagnosis never changes what it reads.

## Agents and Dispatch

#### Dispatched Agents Retry a Failed Edit

An agent started by another agent used to give up when an edit could not find the text it meant to change. That rule exists for live sessions, where a person can step in, but a started agent has nobody to ask, so it ended having written nothing. It now re-reads the file and tries again, and stops only after three failures on the same file.

#### The Goal Check Reads the Right Part

The check that decides whether a session's goal is met read the first 1,200 characters of a long reply, while the proof of being done sits at the end. It now reads the last 1,200. A reply saying "1 P0 fail" next to "done" used to count as met and now does not, while "fail 0" still passes. It also reads the assistant's own earlier text, so a problem named early cannot hide behind a confident last line. A failure a tool printed and the turn then fixed does not count.

#### Claude Code Uses Its Own Subagents

The cli-claude-code skill told a Claude Code session only to "use native capabilities", so a session that wanted another model tried the command line first. It now points to the Agent tool and its `model` setting, and says a subagent runs at the session's effort level unless its definition sets another. The project's default effort is now low for Fable and high for Opus and Sonnet.

#### OpenCode Dispatches Leave Other Work Alone

Before an OpenCode run that skips permission prompts, the safety checklist asked for a clean working folder, which in a shared folder meant committing other sessions' work. It now asks you to commit only your own changes and note that commit as the restore point.

## Jev Classifier

#### Jev Features Run Once a Key Is Stored

Jev is a hosted service that answers a yes-or-no question with a likelihood. Each feature below beat the best rule that uses no AI model. They run on their own once the `jev` command is installed and `jev auth status` passes, so a machine without a stored key never calls the service:

- **Citation drift note.** `validate_document.py` lists a `file:line` reference whose code no longer shows what the text claims. It was right on 35 of 40 against 13 for the plain rule.
- **Injection screen.** After a web fetch in Claude Code, Devin, OpenCode or Pi, a hook adds one warning line when part of the page reads like instructions aimed at an AI. Hermes reaches it through a bridge. Cursor and Codex cannot carry it, because no fetched page reaches their hooks. It was right on 84 of 90 page sections against 68 for a fixed word list.
- **Reviewer verdict fallback.** When `/deep:model-benchmark` scores with `--scorer reviewer`, it asks Jev for the verdict whenever it cannot read one from the reviewer's reply. It read 24 of 24 against 8.
- **Invented-name grader.** When the same benchmark scores with `--scorer 5dim`, it asks Jev about made-up names in answers its own check flags. It graded 55 of 56 against 47.

None of them blocks work, and a failed call leaves things as they would be without Jev. Tools built for Jev ideas that did not beat their baselines, and a local Deem backend, were removed before release.

#### Each Feature Has Its Own Off Switch

`JEV_FEATURES=0` turns all four off. `JEV_FEATURE_CITE_DRIFT`, `JEV_FEATURE_INJECTION_SCREEN`, `JEV_FEATURE_VERDICT_FALLBACK` and `JEV_FEATURE_HALLUCINATION_GRADER` each turn one off. A switch is read from the environment first and then from `.skilled/hooks/hook-flags.env`, so a saved choice holds across sessions.

#### Benchmarks Grade With Jev When They Can

`/deep:model-benchmark` now defaults to `--grader auto`, which grades with Jev when it is ready and otherwise uses the grader that makes no call. Every report says which grader ran. A misspelled grader name now stops the run instead of scoring with a stand-in that printed made-up numbers.

#### One Classifier Hub, Reached Through Pi First

`cli-classifier` is now the one entry point for classifier answers, with `cli-jev` as its only mode, so a future classifier can join without changing how anything calls it. Yes-or-no and choice questions go to Pi's built-in classifier first and fall back to the `jev` command, while scores and batches go straight to it. Each answer says which route gave it, and `JEV_TRANSPORT=jev` skips Pi. A request now reaches the classifier only through the words `jev score` or `jev choice`.

## Skill Advisor

#### A Rebuilt Advisor Restarts Itself

The skill advisor runs as a background service that loads its code once, so after a rebuild it kept answering with the old code until someone restarted it. The next call now replaces a service started before the latest build. `SPECKIT_BRIDGE_RESPAWN_DISABLED=1` turns this off. On a fresh clone, the advisor also installs what it needs before its first build.

#### Advisor Status Tells the Truth

`advisor_status` reported 20 skills while `skill_graph_status` reported all 14 skills as changed, though nothing was out of date. The two compared files differently, and the count included test files. They now agree, count only real skills and report `indexStaleness` when a stored record no longer matches its file. The advisor's safety screen also stopped rejecting skill names such as `system-spec-kit` just for containing the word `system`, and its stress tests now run in CI on every advisor change.

## Model Routes

#### More Model Routes on Pi and OpenCode

MiMo v2.6 Flash joins the Pi and OpenCode model lists, and MiMo Pro and Flash gain routes through OpenCode Go and Cline Pass. Pi 1.0 renamed its ChatGPT sign-in provider from `openai-codex` to `openai`, so runs on Luna and Sol and Pi's own summarizing step failed with a missing-key error. Everything now uses `openai`. ## Documentation Checks

#### One List Decides Metadata Values

Every document opens with metadata, and its `contextType` field had 31 different values across spec docs while four tools kept their own lists. The allowed `contextType` and `importance_tier` values now live in one file, `sk-create-frontmatter/assets/frontmatter-values.json`, which spec-kit, `validate_document.py` and the skill advisor all read. Existing values were mapped to it, leaving 12. A value outside the list now raises the `FRONTMATTER_VALUES` warning, which never fails a check.

#### Research Sources Must Point at Real Lines

The new `SOURCE_TAGS` warning checks each `[SOURCE: path:line]` reference in the research and review files of packets created after 2026-10-04. It warns when the file is gone, has moved or is shorter than the cited line, and never fails a check. A pass means the line exists, not that it supports the claim.

#### Broken References Are Named and Sorted

The evidence check now lists each `file:line` reference that does not lead to a real file and line. The reference scan, `cite-drift-scan.mjs`, now covers spec and research docs and sorts broken references into moved, deleted and past the end of the file. A moved reference names its new path, and checked against git it was right 98% of the time.

#### Stale Search Indexes Are Caught

The search index is a file of trigger phrases that lets a session find past work. The index builder's `--check` now compares the saved index with the current documents without writing anything. CI runs it as a report, and the search doctor uses it as its verdict. The lookup's `--scoring-only` drops weak partial matches, so an empty result is a clean miss.

#### Validation Says When It Guessed

Document checking now warns when it could not tell a document's type and fell back to README rules, and it blocks a skill that names an incomplete MCP tool. The code style checker also flags missing section dividers, code folders without a README and names wrapped in double underscores.

## Skill Authoring

#### Four Skill Versions Restart Lower

The version numbers of system-spec-kit, the system-deep-loop hub, deep-ai-council and the sk-code hub had run ahead of their limits and were renumbered. system-spec-kit and the sk-code hub went from v4 to v2, system-deep-loop from v3.0 to v1.5 and deep-ai-council from v2.4 to v1.8. Skilled's own release numbers did not change.

#### Writing Guides Match the Tools

`/create:changelog` now picks content by what a reader would notice and checks for internal labels and repeated sentences. The step-by-step guide for writing a spec folder now works as written, because its commands match what the tools and the commit hook accept. The total length allowed for skill descriptions rose from 5,600 to 6,400 characters, because the per-skill targets alone added up past the old limit. Nine skills keep their hard rules in a `hard-rules.json` file next to `SKILL.md`, because Claude Code ignored the field they used before.

## Workflow Security

#### Security Fixes Arrive on Their Own

GitHub workflow steps now pin to exact versions, because a moving label such as `actions/checkout@v4` can change what CI runs without any change here. Dependabot keeps those versions current. Security fixes arrive as one combined pull request that merges by itself once its checks pass, as long as every update in it is a small patch. Any other Dependabot pull request still waits for a person.

#### Reports Stay Private and Risky Defaults Are Disclosed

The new `SECURITY.md` explains how to report a vulnerability privately. It also says plainly what Skilled does on your machine: the shipped Claude Code setup skips permission prompts, some agent runs skip approval and first use runs npm installs with their scripts. It shows how to turn approval back on and where to keep keys.

#### Security Scanners See Only This Repository's Code

Copies of other projects kept as research material under `specs/**/context/` caused most of the serious findings in plugin security scans. That folder is no longer in git. Scripts that built shell commands from file paths now pass each part separately, and a benchmark scorer no longer runs model-written code through `Function`.

## Upgrade Notes

- **Update with `/doctor:update`.** Run it to see what this release changes, and on a copied install run `/doctor:update record-base` once first, then commit `.skilled/release/base.json`.
- **Replace rewrite calls.** Ask the assistant directly to say its reply more plainly.
- **Write a body on every commit.** Commits marked as breaking also need `Context:`, `Changes:` and `Verification:` sections, and scopes must use their full name, such as `system-spec-kit`.
- **Stop using the message-check bypass.** `SPECKIT_SKIP_COMMIT_MSG_VALIDATE` is gone. Fix the message or change the template rule.
- **Repoint doctor targets.** `/doctor:speckit` checks search only. Use `/doctor:skill-advisor`, `/doctor:deep-loop` and `/doctor:runtime-mirrors` for the rest, and `/doctor:skill-advisor rebuild` to rebuild the advisor.
- **Use the `openai` provider on Pi 1.0.** Replace `openai-codex` in any Pi model name you keep, such as `openai/gpt-6-luna`.
- **Approve the changed Codex hooks.** Open `/hooks` in Codex once and approve the updated entries.
- **Expect a crashed loop to hold its lock for up to an hour.** `loop-lock.cjs status` names the run that holds it.
- **Restart open sessions and deep-review runs.** Each AI tool reads its hooks when a session starts, and a review opened before this release loses later rounds.
- **Add rules to your message templates.** Add an `Enforced rules` block to each template. If the checks must block merges, mark their CI check as required in your branch settings.
- **Drop `--server` from `/doctor:mcp`.** It covers Code Mode only.
- **Expect two new warnings.** `validate.sh` can warn on a metadata value outside the shared list and on a `[SOURCE:]` reference that does not lead anywhere. Neither fails a check.
- **Compare skill versions by their new numbers.** system-spec-kit, system-deep-loop, deep-ai-council and the sk-code hub now show lower versions than in v4.0.0.2.
- **Remove a `~/.codex/AGENTS.md` link.** Codex reads the root `AGENTS.md`.
- **Save hook switches instead of retyping them.** Set `speckit.hooks.<key>` to `off` in git config, or use `/doctor:git hooks`.
- **Trust another repository's hooks on purpose.** Run `git config --local skilled.trustRepoHooks true` in a repository whose own hook checks should run.
- **Turn Jev features off where you need to.** Set `JEV_FEATURES=0`, or one feature's own switch, in the environment or in `.skilled/hooks/hook-flags.env`. Pass `--grader noop` to `/deep:model-benchmark` for a run that makes no call.
