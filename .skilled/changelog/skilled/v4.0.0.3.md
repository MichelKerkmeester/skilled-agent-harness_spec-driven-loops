# v4.0.0.3, Stronger Repository Rules, Focused Doctor Commands, Clearer Routing and Plain Language

v4.0.0.3 makes the framework more consistent across repositories and runtimes. It aligns message checks with the repository they guard, improves classifier routing and makes trigger-index and document checks clearer. Four Jev features that beat their baselines are now on by default once a Jev key is stored, and each one has an off switch. The skill advisor's status now matches what is on disk.

The doctor commands are reorganized around the part of the framework each one checks. `/doctor:update` now moves a checkout to a newer release, and new commands set up environment switches and the git hooks.

The release also changes how you ask for plainer output. The standalone communication skill and its response rewrite commands are removed. Repository communication rules now distinguish a new explanation from a copy edit that must preserve meaning.

## Why This Release

Framework growth spread guidance and enforcement across more runtimes and documents. Templates could describe rules that hooks never read, evidence checks could miss broken citations and generated indexes could go stale.

The doctor had not kept pace with that growth. One command fronted ten checks owned by different skills, and `/doctor:update` meant a database rebuild rather than an update. Keeping an optional hook gate off meant prefixing every command.

Communication guidance treated confusion and requests for simpler wording as the same need. And the Jev features that won their measurements still had to be switched on by hand.

## What's New at a Glance

- **Repositories own their message rules.** The hook, push, agent and CI gates read each repository's templates, and a spec in the pushed tree counts before it is checked out.
- **Every commit needs a body.** Alias scopes are also blocked, long subjects warn and breaking commits need three named sections. The message check has no bypass switch any more.
- **The hooks trust only their own checkout.** A cloned repository can no longer run its code in your hooks, while a worktree runs its own validator.
- **Optional hook gates can stay off.** A git config setting replaces the per-command variable, and `/doctor:git` changes both the switches and the repository's message rules.
- **Each doctor command checks one owner.** `/doctor:speckit` checks retrieval only, the skill advisor, deep loop and runtime mirrors get their own commands and `/doctor:env` sets environment switches. `/doctor:update` now moves a checkout to a newer release and asks before touching what you changed.
- **Jev features turn on with a stored key.** Four features that beat their baselines are on by default, and each has an off switch. The injection screen covers five runtimes, Jev answers through Pi first and MiMo reaches more providers.
- **The skill advisor tells the truth about itself.** Its status tools agree on which skills changed, a rebuilt advisor replaces its running daemon and CI now runs its stress suite.
- **Checks catch structural drift and broken citations.** Alignment checks cover code structure, spec evidence names citations that cannot resolve and document validation reveals its fallbacks. The citation census tells a moved file from a deleted one, and a new warning checks the source tags in research and review files.
- **Stale trigger indexes are reported.** Lookups can filter weak matches, both CI and the retrieval doctor compare the index with current guidance and a fresh index now reports healthy.
- **One list decides frontmatter values.** Spec-kit, sk-doc and the skill advisor read the same `contextType` and `importance_tier` list, and spec docs outside scratch folders dropped from 31 distinct `contextType` values to 12.
- **Plain-language requests keep every claim.** The rules explain how to fix machine-like prose, the former response commands are removed and a new gate loads the reply rules before every reply.
- **Workflow actions stay pinned and vulnerability reports stay private.** Dependabot tracks updates to commit-pinned actions, small security updates merge on their own and fewer scripts build shell command strings.
- **Dispatched agents and loop runs finish their work.** An agent re-reads a file and retries a failed edit, a review run records every iteration after setup and a command-line lineage must list every finding it claims. Deep-research runs keep their own records straight.

## Repository Checks

#### Repositories Own Their Message Rules

These template-driven message checks read structured rules in each repository's own commit templates. The pull-request template also sets required content. The branch checklist holds branch-name rules. The commit hook, pre-push check, agent gates and CI read the same blocks, so one repository's rules no longer apply to every other repository.

**Breaking:** Skipping the commit hook no longer gets a failing message through. Push and CI checks still reject it. Update the template or the message to pass.

#### Push Checks Read the Pushed Tree

A spec in the pushed tree counts even if the current checkout does not yet contain it. That lets a code change and its spec travel in one push. The push check also reads the whole range in one Git call, so it avoids a separate lookup for each commit.

It checks only the commits the push adds. A push that carries edits merged on the web, a force-push over a tip you have not fetched or a push by URL no longer fails on commits the remote already holds.

#### Every Commit Carries a Body

The commit hook used to ask for a body only when a commit staged four or more files. Small commits went in with a subject alone, so history showed what changed but never why. The hook now refuses any authored message without a prose line below the subject. Trailers do not count as a body, so a message with only a `Spec:` line is refused too. Merge, revert, `fixup!`, `squash!` and `amend!` commits stay exempt.

**Breaking:** A commit with a subject and no body is now refused. Add a sentence below the subject that says why the change was made.

#### Commit Rules Catch Alias Scopes, Long Subjects and Thin Breaking Bodies

Three deviations reached `main` because the checks never looked for them, so the commit template now declares three more rules:

- A scope that is an alias of another, such as `spec-kit` for `system-spec-kit`, is blocked, and the message names the scope to use.
- A subject over 80 characters warns. 100 characters stays the hard limit.
- A breaking commit must carry `Context:`, `Changes:` and `Verification:` sections in its body.

**Breaking:** A breaking commit without all three sections is now refused. Add the missing sections to the body.

A review of these rules closed several more gaps:

- A `Spec: ..` trailer no longer passes as an existing packet.
- A rules block that could never work is now refused when it loads: a warning length at or above the hard limit, an alias that points at another alias or a section label no body line can match.
- Subject lengths quoted in the template or the skill guide must match the enforced values.
- Comment lines are removed only when git would remove them, so a message is judged on the text git stores.
- A rebased copy of a commit is no longer reported as a Commit-Id collision with its original, and a cherry-pick gets a fresh Commit-Id.
- The message preparer removes only attribution trailers and says what it removed.
- The hooks look for templates in the folder `skgit.contractDir` names, then in `.sk-git/`, then in the ones sk-git ships. A path passed with `git -c` or a `GIT_CONFIG_*` variable is ignored.
- A badly written rule pattern can no longer hang a commit. After too much backtracking, the match moves to V8's linear-time engine.
- The pull-request description check skips pull requests opened by Dependabot.
- The skill's worked examples stage explicit paths instead of `git add -A` or whole folders, as its own staging rule says.
- CI now runs the rule tests.

#### The Message Check Has No Bypass

`SPECKIT_SKIP_COMMIT_MSG_VALIDATE` used to turn the commit message check off. The variable is gone and the hook ignores it.

**Breaking:** Setting `SPECKIT_SKIP_COMMIT_MSG_VALIDATE=1` no longer lets a message through. Fix the message, or change the rule in the repository's template.

#### Cloned Repositories Cannot Run Code in Your Hooks

The git hooks usually run for the whole machine through a global `core.hooksPath`, and they used to load their checks from whatever repository they ran in. A cloned repository that shipped its own copies of those checks therefore had them run on every pull, commit or push. The hooks now use a repository's own checks only in the checkout they were installed from and its worktrees, or in a repository whose local git config sets `skilled.trustRepoHooks=true`. A value passed with `git -c` does not count, because a clone cannot write your local config. Every other repository gets only the message check.

#### Worktrees Use Their Own Validator

When the hooks are shared machine-wide from one checkout, a worktree that added a new rule was judged by that checkout's older validator, which refused every commit, including the one adding the rule. The hooks now run a worktree's own validator when the worktree belongs to the same repository.

#### Hooks Block When a Check Cannot Run

A gate whose checker crashed used to pass the commit as if the check had run. It now blocks and reports the crash apart from a rule failure. The commit checks also skipped a staged file whose content git could not read, so that file went in without its comment check. Such a file now blocks the commit. Only a submodule entry is skipped, because it has no content to check.

#### Optional Hook Gates Can Stay Off

Turning off an optional gate used to mean setting its `SPECKIT_SKIP_*` variable on every command. Setting `speckit.hooks.<key>` to `off`, `false`, `no` or `0` in local or global git config now keeps that gate off, and each run prints one line naming the setting. Ten gates can be saved this way. The two per-push approvals, for pushing outside the allowed branches and for mass deletion, still have to be given on the command itself. A value passed with `git -c` never counts, and only a repository the hooks trust reads these settings.

## Doctor Commands

#### Each Doctor Command Checks One Owner

`/doctor:speckit` used to front ten checks owned by different skills, so finding the right one meant knowing its target name. It now checks spec-kit retrieval only: the trigger index, its lookup and the search recipes. The skill advisor's checks moved to `/doctor:skill-advisor`, which also gains `rebuild`. That action backs up the advisor's graph database, rebuilds it and restores the backup if any step fails. The deep loop and the runtime mirrors each have their own command, `/doctor:deep-loop` and `/doctor:runtime-mirrors`. The embeddings and fable-mode checks are removed.

A doctor command that needs a target and gets none shows its menu and waits. It never guesses a target from the conversation or the repository.

**Breaking:** `/doctor:speckit` no longer runs other owners' checks. Given an old target name, it prints the command that owns it now.

#### The Updater Moves a Checkout to a Newer Release

`/doctor:update` used to rebuild the runtime databases. It now compares your checkout with a framework release and brings it up to date. `check` reports where the checkout stands without changing files. Parts you have not changed update directly. A part you changed is never overwritten: `align` records your decision for it, and `apply` acts only on parts that are fully decided. `apply` shows its plan, asks once before its first write and keeps a record that `rollback` can restore. On a copied or freshly installed tree, `record-base` records the starting point once.

The updater takes stable releases unless you pass `--include-prerelease`. Generated files never count as your changes. A release file that would land inside a folder your checkout keeps as a link to another folder is reported as a conflict you keep local. The updater never writes through the link, and the rest of the check still runs. Checkouts from v4.0.0.0, which keep one changelog folder as a link, used to stop at that file.

**Breaking:** `/doctor:update` no longer rebuilds databases, and its rebuild options are gone. Rebuild the advisor graph with `/doctor:skill-advisor rebuild`.

#### Environment Switches Set Up With a Yes

`/doctor:env` reads the list of documented switches at every run, which now includes every switch the git hooks read. It shows where each switch is set without revealing secret values. It saves an eligible preference only after showing the exact line it will write and getting a yes. Switches meant for a single command are shown as usage and never saved.

#### Hook Switches and Message Rules in One Place

`/doctor:git hooks` lists each hook gate with its local, global and effective value, along with whether the hooks are installed. It changes one gate after showing the exact `git config` command.

`/doctor:git standards` copies the shipped commit, PR and branch templates into the repository's `.sk-git/` folder once and never overwrites them. It then changes or removes one rule, or switches off a kind of rule entirely. Each change is checked the way the hooks will check it and refused if they would reject it. It also points out template prose that still describes the old rule. `--dry-run` shows every plan and writes nothing.

#### MCP Checks Focus on Code Mode

`/doctor:mcp install` and `debug` now set up and diagnose only Code Mode, its configuration file and its registration in each runtime. The `--server` option is gone. A flag that neither `install` nor `debug` accepts is refused before anything runs, and the message names the flag the chosen action does accept.

#### Code Mode Builds From a Fresh Clone

A fresh clone could not start Code Mode, because its build output was missing. `install.sh` now builds the server itself and rebuilds whenever its sources are newer. The UTCP config check accepts the shipped MagicPath manual and checks credentials under the names Code Mode reads, so `/doctor:mcp` reports no failures on a freshly built tree.

#### The Retrieval Doctor Can Report Healthy

`/doctor:speckit` flagged weak trigger phrases as a problem whenever any existed, and every real collection of documents has a few, so the check could never come back healthy. Weak phrases are now listed as advisories with their counts and share. They never change the status, so a fresh index reports OK.

#### Doctor Scripts Catch the Drift They Used to Pass

Several of the doctor's own scripts reported PASS on real drift or crashed on bad input. A deleted command row no longer hides behind a command with a similar name, a crash now reports an error instead of drift and a skill on disk that the compiled graph lacks is named. Every doctor script now has tests, and one runner runs them locally and in CI.

#### Doctor Commands Come With Test Scenarios

Every doctor command now has manual test scenarios in the playbook of the skill that owns it. They run in two local worktrees the playbook explains how to build: one made from v4.0.0.0 that holds a changed, a local, a conflicting and a removed part for `/doctor:update` to act on, and one that follows the main branch for the other commands. Each scenario starts from a clean state and ends by restoring it. All 36 passed in a full run before release.

## Classifier and Model Routing

#### Jev Features Run Once a Key Is Stored

Jev is a hosted classifier that answers a yes-or-no question with a probability. Each feature below was measured against the best rule that uses no model, and each asks the exact question it was measured with. The citation drift advisory already ran on its own, while the other three ran only when someone switched them on. All four are now on by default once the `jev` command is installed and `jev auth status` passes, so a machine without a stored key never calls the service:

- **Citation drift advisory.** `validate_document.py` ends its report by listing a `file:line` citation whose code no longer shows the claim. It was right on 35 of 40 citations against 13 for the rule.
- **Injection screen.** After a web fetch, a new hook adds one advisory line when a section of the page reads as instructions aimed at an AI agent. It runs on Claude Code, Devin, OpenCode, Pi and Hermes. Cursor and Codex cannot carry it, because no fetched page reaches a hook there. It was right on 84 of 90 sections against 68 for a fixed word list.
- **Reviewer verdict fallback.** When a `/deep:model-benchmark` run scores with `--scorer reviewer`, it asks Jev for the verdict whenever its parser cannot read one from a reviewer's reply. It read 24 of 24 against 8.
- **Hallucination grader.** When the same benchmark scores with `--scorer 5dim`, it asks Jev about invented names only for outputs its own check flags. It graded 55 of 56 against 47.

None of them blocks work. A failed call leaves the path as it would be without Jev. The fetched page always reaches the model in full, and on Pi and Hermes the advisory line is added after it. Measurement tools built during the cycle for the Jev ideas that did not beat their baselines were removed before release.

#### Each Feature Has Its Own Off Switch

`JEV_FEATURES=0` turns all four off. `JEV_FEATURE_CITE_DRIFT`, `JEV_FEATURE_INJECTION_SCREEN`, `JEV_FEATURE_VERDICT_FALLBACK` and `JEV_FEATURE_HALLUCINATION_GRADER` each turn one off with `0`, `false`, `no` or `off`. A switch is read from the environment first and then from `.skilled/hooks/hook-flags.env`, so a saved preference holds across sessions. `.env.example` and the environment reference list every switch, and `/doctor:env` shows where each one is set.

#### Benchmarks Grade With Jev When They Can

`/deep:model-benchmark` now defaults to `--grader auto`. It grades with Jev when Jev is ready and its switch is on, and falls back to the grader that makes no call otherwise. Every report records which grader ran and why. An explicit `--grader jev` with its switch off stops and names the switch instead of grading nothing.

#### Jev Answers Through Pi First

Jev questions now go to Pi's built-in classifier first, and the `jev` command answers wherever Pi cannot. Each answer carries the route that gave it. `JEV_TRANSPORT=jev` keeps a caller on the `jev` command.

#### One Classifier Hub

`cli-classifier` is now the public hub for typed classifier answers, with `cli-jev` as its only mode. A future classifier joins as a new mode without changing how callers reach the hub. A local Deem backend was built during the cycle and removed before release. The routing words are now `jev score` and `jev choice`, so a request that only mentions a score no longer reaches the classifier. A choice request without a question is refused, and the README explains how to install and sign in to Jev.


#### Session Hooks Reach More Runtimes

The hooks that keep a session's checkout in step with the shared live branch now run at session start on Cursor and Devin, and Hermes runs the follow hook too. Where a runtime cannot carry a hook, the hook registry now says why instead of claiming no counterpart exists.

#### Advisor Status Matches What Is on Disk

`skill_graph_status` hashed each skill file differently from the indexer that stores the hash, so it reported all 14 skills as changed while `advisor_status` called the same index live. Both status tools and the indexer now share one recipe and agree. `advisor_status` counts the 14 skills rather than the 20 metadata files behind them, and it reports embedding health when asked. The doctor's freshness panel now names a compiled graph older than the skills on disk, and marks the check degraded when the advisor database is missing instead of passing it.

#### Skill Names Pass the Advisor's Label Screen

The skill advisor screens every routing label it derives, such as a trigger phrase or keyword, for text written as an instruction to an AI agent. The screen matched single words such as `system`, `tool` and `run`, so it rejected the skill name `system-spec-kit` and phrases such as `run lighthouse`. Seven skills could not record that their labels passed it, and graph validation warned on them. The screen now looks for instruction phrasing, such as an override word near "instructions" or a request to call a tool, and still rejects every injection case in its tests. Its version is now `sanitizeSkillLabel:v2`, all 14 skills carry that stamp and graph validation reports no warnings.

#### A Rebuilt Advisor Replaces Its Daemon

The skill advisor's daemon loads its code once at launch and keeps running across sessions. After a rebuild it went on answering with the old code until someone restarted it, so a change could look broken, or stale warnings could appear, when the new code was correct. The advisor command and the launcher now check whether the running daemon was launched before the current build. If it was, the next call replaces it and is answered by the new build. `SPECKIT_BRIDGE_RESPAWN_DISABLED=1` turns this off.

On a fresh clone, the advisor launcher installs the linked Spec Kit workspace before building the daemon, so the first build no longer stops on missing Node types. CI now runs the advisor's stress suite whenever the advisor, its launcher or its plugin changes. The suite used to run only when someone set a variable by hand, and two of its tests had failed unnoticed against code that had moved on.

#### MiMo Reaches More Provider Routes

MiMo v2.6 Flash joins the Pi and OpenCode rosters. MiMo Pro and Flash also gain routes through OpenCode Go and Cline Pass. Existing DevPass routes remain available. OpenCode needs no new configuration for routes it ships.

#### Pi Routes Follow Pi 1.0

Pi 1.0 renamed its ChatGPT sign-in provider from `openai-codex` to `openai`, so Luna and Sol lineages and Pi's compaction call failed with a missing-key error. The deep-loop fan-out, the compaction config and the cli-pi docs now use `openai`. Deep-loop runs on Pi can also use DeepSeek V4.1 Flash through OpenCode Go, as `opencode-go/deepseek-v4.1-flash`.

## Documentation Checks

#### Alignment Checks Cover Sections and Folders

The alignment checker now checks code organization alongside code conventions. It flags missing section dividers in longer source files. It also finds code folders without READMEs or names wrapped in double underscores. A new architecture template gives maintainers one structure for explaining a package's runtime.

#### Spec Evidence Names Invalid Citations

The acceptance-evidence check now lists each citation that cannot resolve to a file and valid line. It also separates citations joined in one cell and rejects line numbers past the end of the file.

#### One List Decides Frontmatter Values

Spec docs outside scratch folders used 31 distinct `contextType` values while four tools kept their own lists. The legal `contextType` and `importance_tier` values now live in one file, `sk-create-frontmatter/assets/frontmatter-values.json`, which spec-kit, `validate_document.py` and the skill advisor all read. Off-list values in spec docs were mapped to the list, leaving 12, each canonical or a listed alias. A value outside the list now draws the `FRONTMATTER_VALUES` warning, which never fails a run. The 11 session types a save payload uses stay in spec-kit, because they set a save's project phase and memory type.

#### The Citation Census Sorts Broken Citations by Cause

`cite-drift-scan.mjs` now covers spec and research docs as well as skill docs and splits broken citations into moved, gone and past-end. A moved citation names its new path. On random samples checked against git, moved was right 98% of the time, past-end 100% and gone 100%. The census reads paths with spaces such as `REPO RULES.md`, runs in 29% of its old time and can rebuild its rename table with `--rebuild-redirects`. `/doctor:speckit` can run it and summarise the result per doc family.

#### Research Source Tags Must Point at Real Lines

The new `SOURCE_TAGS` warning checks each `[SOURCE: path:line]` tag in the research and review files of packets created after 2026-10-04. It warns when the file is gone, has moved or ends before the cited line, and never fails a run. A tag under a gitignored folder gets the same result in every checkout. A pass means the file and line exist, not that they support the claim. `/doctor:deep-loop` lists the unresolved tags per lineage.

#### Document Validation Calls Out Its Fallbacks

Document validation now warns when no path rule matches and README rules are used by default, so the author can choose the intended type. It also blocks a skill that names an incomplete Model Context Protocol (MCP) tool. That catches an unusable tool entry before the skill is accepted.

#### Descriptions Fit the Budget Again

Seven skill and agent descriptions ran past their soft target and now sit at 119 to 130 characters, and each trimmed skill still wins its own routing prompt. The project-wide ceiling for all descriptions rose from 5,600 to 6,400 characters, so the audit reports headroom instead of a warning.

#### Changelogs Read as Stories

`/create:changelog` now writes release notes as narrative: why the release matters, sections named for what they change and no file inventories or test counts nobody asked for. The Human Voice scan gates every entry. Top-level sections are spaced apart, while the items inside a section run together.

#### The Spec Folder Write Recipe Works as Written

Five steps of the spec folder write recipe could not pass as written. Step 5 passed a folder to the wrong flag and stopped. Step 7 asked for an attribution trailer the commit hook refuses, told the author to stay on `main` and checked a clean `git status` that a shared tree never shows. Each step now does what the tools accept, and the checks look at the author's staged files only.

#### Trigger Lookups Handle No Hits

The trigger-index lookup now accepts `--scoring-only` to drop partial matches with no score before the result cap. With this option, exit 1 and no rows is a clean no-hit. The index generator's `--check` option compares the committed index with current guidance without writing changes. CI runs the check as report-only. The retrieval doctor now uses the same check as its verdict, so it judges a stale index by its content rather than by file times.

## Communication Rules

#### Machine Register Gets a Plain Fix

The communication prose rules now call out terse machine register: symbols standing in for verbs, stacked nouns, unexplained IDs, abbreviations or status codes, bare counts or labels and fragments. They ask the assistant to replace symbols with action words, say who does what, explain each identifier or count and give fragments a subject and verb.

#### Reply Rules Load Before Every Reply

Loading a rule file did not reliably change how replies read, and some runtimes never got the instruction to load one. `AGENTS.md` now makes loading the reply rules its own gate, Gate 6, which cut missed loads by 23 and then 38 points in two measured runs. Devin cuts `AGENTS.md` at 16,384 bytes, which used to drop every hard blocker. Those clauses now sit inside the cut, and CI fails when one slips past it. Codex reads the repository's root `AGENTS.md`, so its separate copy is removed.

The 13 repository rules lost 11.7% of their bytes without losing a rule, and each lists phrases that let a plain search such as "flaky test" find it. `communication.md` adds "Complex topic, simple words": explain a technical subject plainly the first time, without dropping a caveat or a number.

#### Plain Language Keeps Every Claim

**Breaking:** The standalone `sk-communication` skill and its opt-in plain-English projection of CLI output are removed, along with its two response rewrite commands. Replace calls to those commands with a direct request for the assistant to say its reply more plainly.

The repository rules distinguish "I don't follow," which asks for a new explanation using an example, numbered steps, a smaller first step or a picture, from "say that more plainly," which requests a copy edit. The copy edit keeps every claim, number, caveat, instruction, conclusion and logical relationship in the same order and at the same strength. It keeps code, commands, flags, paths, URLs, identifiers, configuration keys, error strings, quotations and numbers byte-exact. The rule links to the Human Voice Rules. If a simpler word changes the claim, the claim wins.

## Agent Dispatch

#### Dispatched Agents Retry a Failed Edit

A command-line agent dispatched by another agent used to stop when an edit could not find its target text. That stop rule exists for interactive sessions, where someone can step in, but a dispatched agent has nobody to hand over to, so it ended having written nothing. The usual cause is that the file changed underneath it. The dispatch preamble now tells the agent to re-read the file and retry, and to stop only after three failures on the same file.

#### Deep-Review Runs Record Every Iteration

A deep-review run keeps its state log as a record the append gateway rebuilds from its ledger. Both review workflows wrote the run's opening config line into that log directly, with fields the rebuild could not reproduce, and the gateway refuses to discard fields it did not write. So every iteration after setup was saved to the ledger but never reached the state log, and each append reported a failure. The workflows now open the run through the gateway, so the log holds only what the gateway writes. The full run settings still live in the run's config file. A run opened before this change keeps the old line. Restart it to open it the new way.

#### Deep-Research Runs Keep Their Records Straight

A deep-research run now opens through the append gateway and releases its lock when it ends. It saves its graph and marks each question it answered, so its ledger, graph and question count match what the run did. The graph scripts gained a read-only mode, which `/doctor:deep-loop` uses to inspect a run without changing it.

A deep-review iteration record was refused as an unknown format, so every review iteration failed its state step. The gateway now records it whole. Any event over about 10 KB was also refused in every mode, and is now accepted.

#### Command-Line Lineages List Their Findings

A research or review lineage run by a command-line model now receives the same per-iteration output rules a native agent follows. An iteration that claims more findings than it lists fails its check at once. Before, a lineage could claim 46 findings, list 22 and pass every iteration until the final step rejected it. Merging lineages also restores findings a lineage recorded in its state but left out of its findings list.

#### Claude Code Sessions Dispatch Natively

A Claude Code session that needed another model checked the Claude Code command line first. The cli-claude-code guard now sends it to a native subagent, says the subagent runs at the session's effort unless its agent definition sets one and says a definition is needed only for a different level.

#### OpenCode Dispatch Leaves Other Sessions' Work Alone

Before a cli-opencode dispatch, the recovery step asked for a clean tree or a commit of all in-flight work. In a shared tree that meant committing other sessions' changes. It now commits only the dispatch target's own changes, staged by explicit path.

## Workflow Security

#### Actions Stay Pinned and Reports Stay Private

GitHub workflow actions now pin to commits. Dependabot tracks updates to those versions, and a grouped npm security update merges on its own when every bump in it is a patch. The repository's security policy directs vulnerability reports to a private channel, states what the repository supports and has a section on what can go wrong, including hooks that run as you, permission defaults that skip approval and MCP servers fetched from the network.

#### Fewer Shell Strings, Smaller Tree

The Webflow minify script runs terser without a shell, and spec-kit's tests start validator scripts with argument lists, so a path with shell characters cannot change the command. The deep-loop benchmark loads a model's scored code as a temporary module. About 32,000 files of third-party repositories vendored under spec folders' `context/` folders are no longer tracked.

## Upgrade Notes

- **Replace rewrite calls.** Ask the assistant directly to say its reply more plainly.
- **Stop using the message-check bypass.** `SPECKIT_SKIP_COMMIT_MSG_VALIDATE` is gone. Fix the message or change the template rule.
- **Write a body on every commit.** Breaking commits also need `Context:`, `Changes:` and `Verification:` sections, and scopes must be canonical, such as `system-spec-kit` instead of an alias.
- **Prepare repository message checks.** Add an `Enforced rules` block to each message template. If the checks need to block merges, mark their CI check as required in your branch rules.
- **Save hook switches instead of prefixing commands.** Set `speckit.hooks.<key>` to `off` in git config, or change it with `/doctor:git hooks`.
- **Trust another repository's hooks on purpose.** Run `git config --local skilled.trustRepoHooks true` in a repository whose own hook checks should run.
- **Repoint doctor targets.** `/doctor:speckit` checks retrieval only. Use `/doctor:skill-advisor`, `/doctor:deep-loop` and `/doctor:runtime-mirrors` for the checks it used to front.
- **Stop using `/doctor:update` to rebuild.** Rebuild the advisor graph with `/doctor:skill-advisor rebuild`. On a copied or fresh tree, run `/doctor:update record-base` once.
- **Drop `--server` from `/doctor:mcp`.** It covers Code Mode only.
- **Expect two new warnings.** `validate.sh` can now warn on a `contextType` or `importance_tier` outside the shared list, and on a `[SOURCE:]` tag that does not resolve. Neither fails a run. Write a canonical value, or edit the tag to the file's current path.
- **Use the `openai` provider on Pi 1.0.** Replace `openai-codex` in any Pi model string you keep, such as `openai/gpt-6-luna`.
- **Turn Jev features off where you need to.** Set `JEV_FEATURES=0`, or one feature's own switch, in the environment or in `.skilled/hooks/hook-flags.env`.
- **Pin a benchmark run that makes no call.** Pass `--grader noop` to `/deep:model-benchmark`, which now grades with Jev when it can.
