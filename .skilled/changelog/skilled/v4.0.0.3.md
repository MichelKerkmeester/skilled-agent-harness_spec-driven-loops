# v4.0.0.3, Update Safely, Commit Clearly, Read Plainly

v4.0.0.3 lets you move your copy of Skilled to a newer release with one command, `/doctor:update`. It never overwrites a file you changed. Commit message rules now belong to each repository. Every AI tool sees the hard rules. Four Jev features that proved themselves turn on once a Jev key is stored.

The other doctor commands are split. Each one checks one part of the framework. The standalone communication skill is removed. A request for plainer wording now keeps every claim.

&nbsp;

## Why This Release

Updating Skilled used to mean copying files by hand. You hoped nothing you had changed got lost. `/doctor:update` did not update anything. It rebuilt databases.

The framework had also grown across more AI tools and documents than its checks covered. Templates described rules the hooks never read. Some tools never saw the hard rules. Deep-review runs lost their record after the first step.

&nbsp;

## What's New at a Glance

- **One command updates your copy of Skilled.** `/doctor:update` shows what a newer release changes. It asks you about every file you edited. It can undo the whole update.
- **Repositories own their message rules.** The commit hook, the push check and CI read each repository's own templates. Every commit needs a body. The message check has no off switch.
- **The hooks trust only their own checkout.** A cloned repository can no longer run its code in your hooks. One git setting keeps an optional check off across every command.
- **Fresh copies build what they need.** Code Mode builds its own server. A new worktree arrives ready to use.
- **Each doctor command checks one thing.** The skill advisor, the deep loop and the runtime mirrors have their own commands.
- **Plain-language requests keep every claim.** The communication skill and its rewrite commands are gone. The rules explain how to fix robotic prose.
- **Every AI tool sees the hard rules.** They fit inside the part of `AGENTS.md` every tool reads. A new gate loads the reply rules before each answer.
- **Deep-loop runs finish their work.** Review runs keep every step. They hold their lock against a second run until they release it. A failed run says why it failed. Parallel workers no longer stop to ask.
- **Jev features turn on with a stored key.** Four features that beat their baselines run on their own. Each has an off switch.
- **Checks catch broken links and stale files.** One shared list decides metadata values. A scan tells a moved file from a deleted one.
- **Security fixes arrive on their own.** Small security updates merge once their checks pass. Vulnerability reports stay private.

## Updating to a New Release

#### One Command Brings Your Copy Up to Date

`/doctor:update` compares your copy of Skilled with a framework release. It brings your copy up to date. Run it with no action, or with `check`, to see where you stand. That changes nothing. The report lists each skill and folder. Each one is current, updated in the release, new, removed, changed by you or in conflict with the release. It also shows the release notes that apply.

The updater picks the newest stable release. `--release=<tag>` picks a specific one. `--include-prerelease` allows pre-releases. `--scope` limits the update to the skills or folders you name. The database rebuild this command used to run now lives in `/doctor:skill-advisor rebuild`.

#### Your Own Changes Are Never Overwritten

A file you have not touched takes the release version directly. A file you changed waits for your decision. `align` walks through each one. It asks whether to keep your version, switch to the release version or merge the two. A merge shows you the full merged file before you accept it. It asks you to finish any part it could not combine. You can also leave a whole skill or folder for later.

Files the framework generates never count as your changes. That includes indexes and route manifests. If you regenerated one yourself, the updater keeps your copy. It tells you which command rebuilds it.

#### Every Update Can Be Undone

`apply` shows its full plan. It asks once before it writes anything. It brings in the release's changes to files you never touched. It brings in your decisions for the rest. Then it checks the result. Every run keeps a record. `rollback` restores your copy from it, asking first. `--dry-run` previews any of these steps without writing. A lock stops two updates from running at once.

#### Copied Installs Record Where They Started

A copy of Skilled placed in another repository has no git history to compare against. The first `check` there says so. `record-base` records which release the copy came from. Commit the file it writes, `.skilled/release/base.json`. If the repository's own remote has no framework tags, `--remote` names the framework repository once. Later runs remember it. A copy made from v4.0.0.0 keeps one changelog folder as a link. That copy used to stop at that link. It now reports the link as a file you keep.

## Commit Message Rules

#### Repositories Own Their Message Rules

Each repository's commit, pull-request and branch templates now carry the rules for that repository. The commit hook, the push check, the agent checks and CI all read the same rules. So one repository's rules no longer apply to every other one. The push check and CI use the same rules. So a commit made with `--no-verify` to skip the local check is still refused when you push it.

#### Every Commit Carries a Body

The commit hook used to ask for a body only when a commit touched four or more files. So small commits said what changed but never why. It now refuses any message without a sentence below the subject line. A trailer such as `Spec:` alone does not count. Merge, revert, `fixup!`, `squash!` and `amend!` commits are exempt.

#### The Message Check Has No Off Switch

`SPECKIT_SKIP_COMMIT_MSG_VALIDATE` used to turn the commit message check off. The variable is gone. So setting it no longer lets a message through. To satisfy a rule, fix the message. Or change the rule in the repository's template.

#### Commit Rules Catch Wrong Scopes and Long Subjects

A nickname for a scope is now blocked, such as `spec-kit` for `system-spec-kit`. The message names the right one. A subject over 80 characters warns. 100 stays the hard limit. A commit marked as breaking is refused unless its body explains itself. That mark is a `!` after its type, such as `feat!:`, or a `BREAKING CHANGE:` line. The body must use `Context:`, `Changes:` and `Verification:` headings. Bundled flags such as `git commit -am` no longer hide the message from the check. A message or pull-request description over the length limit is now refused. It is no longer quietly cut short.

## Git Hook Safety

#### Cloned Repositories Cannot Run Code in Your Hooks

The git hooks usually run for every repository on your machine. They used to load their checks from whichever repository they ran in. A cloned repository could ship its own copies of those checks. It could have them run on every pull, commit or push. The hooks now use a repository's own checks in three places only. One is the copy they were installed from. Another is its worktrees. The third is a repository you trust with `git config --local skilled.trustRepoHooks true`. Every other repository gets only the message check.

#### Hooks Stop When a Check Cannot Run

A check that crashed used to let the commit through as if it had passed. It now blocks the commit. It says the check crashed. A staged file that git cannot read also blocks the commit. It no longer skips its checks.

#### Optional Checks Can Stay Off

Turning off an optional check used to mean adding its `SPECKIT_SKIP_*` variable to every command. Setting `speckit.hooks.<key>` to `off` in git config now keeps it off. Each run prints one line saying so. A single push needs two approvals. One is for pushing outside the allowed branches. The other is for deleting many files. Both still go on the command itself.

#### Push Checks Read What You Push

A spec in the commits you push now counts even if your current files lack it. So a code change and its spec can go up together. The check also looks only at the commits the push adds. So a force-push no longer fails on commits the server already has. The same goes for a push that carries edits made on GitHub.

## Hooks on More AI Tools

#### Codex Hooks Run Again

Codex 0.160 renamed its shell tool from `exec` to `Bash`. So the git checks, the spec-folder check and the dispatch checks had silently stopped running under Codex. They now recognize both names. Codex asks you to approve the changed hooks once in `/hooks`.

#### Live-Sync Hooks Reach More AI Tools

The hooks that keep each session's copy in step with the shared live branch now run on Cursor and Devin. Hermes runs the follow hook too. Where a tool cannot run a hook, the hook list now says why.

#### Devin's Write Tool Is Checked

Devin's `write` tool creates or overwrites a file. Yet it skipped the spec-folder check and the post-edit check that its `edit` tool runs. Both checks now run for `write` too.

## Fresh Clones and Worktrees

#### Worktrees Check Themselves and Arrive Ready

A worktree is a second working copy of the same repository. Hooks shared from the main copy judged a worktree by the main copy's older rules. Those rules refused the very commit that added a new rule. A worktree now uses its own rules. A new worktree also arrives with spec-kit built. Every package it needs is installed. So its tools work at once. They no longer fail with a one-line Node error.

#### Code Mode Builds From a Fresh Copy

A fresh clone or worktree had no Code Mode server built. So it could not start. The server's package file is now committed. `install.sh` builds the server whenever it is missing or out of date.

The config check, the docs and the MCP doctor now name each key the way Code Mode reads it. That is the tool's name with each underscore doubled, then the key, such as `clickup__official_CLICKUP_API_KEY`. `/doctor:mcp install` and `debug` now cover Code Mode only. The `--server` option is gone.

## Doctor Commands

#### Each Doctor Command Checks One Thing

`/doctor:speckit` used to front ten checks owned by different skills. It now checks spec-kit search only. That covers the trigger index, its lookup and the search recipes. The skill advisor's checks moved to `/doctor:skill-advisor`. That command gains a `rebuild`. It backs up the advisor's database first. It restores the database if anything fails. The deep loop and the runtime mirrors have `/doctor:deep-loop` and `/doctor:runtime-mirrors`. The embeddings and fable-mode checks are gone. If you give `/doctor:speckit` an old target name, it tells you which command handles it now. A doctor command that needs a target and gets none shows its menu. It waits instead of guessing.

#### Hook Switches and Message Rules in One Place

`/doctor:git hooks` lists each optional check with its saved setting. It changes one after showing the exact `git config` command. `/doctor:git standards` copies the shipped templates into the repository's `.sk-git/` folder once. Then it changes or removes one rule at a time. It refuses any change the hooks would reject. `--dry-run` shows the plan and writes nothing.

#### Settings Saved Only With a Yes

`/doctor:env` shows where each documented setting is set. That includes every setting the git hooks read. It never reveals secret values. It saves a preference only after showing the exact line it will write. It waits for a yes.

#### The Search Doctor Can Report Healthy

`/doctor:speckit` treated any weak search phrase as a problem. Every real set of documents has a few. So it never came back healthy. Weak phrases are now listed as notes. They leave the result unchanged.

#### Doctor Scripts Catch What They Used to Miss

Several of the doctor's own scripts reported a pass on real problems. Others crashed on bad input. A deleted command no longer hides behind one with a similar name. A crash reports an error. A skill missing from the advisor's records is named. Every doctor script now has tests that run locally and in CI.

## Plain Language

#### Plain Language Keeps Every Claim

The standalone `sk-communication` skill is removed. Its optional plain-English rewrite of command output is gone too. So are its two rewrite commands. For a plainer reply, ask the assistant to say it more plainly.

The repository rules now tell two requests apart. "I don't follow" asks for a new explanation. That can be an example, numbered steps or a picture. "Say that more plainly" asks for a copy edit. It keeps every claim, number and caveat at the same strength. It keeps code, commands, paths and names exact. If a simpler word changes the claim, the claim wins.

#### Robotic Prose Gets a Plain Fix

The writing rules now name terse, robotic prose. That covers symbols in place of verbs, piled-up nouns, unexplained codes and half sentences. They ask the assistant to use action words. They ask it to say who does what. They ask it to explain every code or count.

## Rules Every Session Loads

#### A Gate Loads the Reply Rules Before Each Answer

The reply rules used to load from one line deep in `AGENTS.md`. Sessions often missed them. `AGENTS.md` now has Gate 6. It loads them before every real reply, even when nothing is being changed. In its final test run it cut missed loads by 38 points. It did not slow the other gates. Plain search phrases added to 11 rules help an everyday request find the right rule. The rules also now ask for a technical subject to be explained plainly the first time. That must not drop a caveat or a number.

#### Every AI Tool Sees the Hard Rules

Devin reads only the first 16 KB of `AGENTS.md`. The hard rules ran past that point. So Devin never saw rules such as "never fabricate". The sections were reordered so every hard rule fits. A check now fails if one slips past the limit. Codex reads the root `AGENTS.md` directly. So the separate `.codex/AGENTS.md` copy is gone.

The rule check also fails when a rule's trigger has no matching row in `REPO RULES.md`. That table tells a session which rule to load. Seven triggers were missing. So no session was ever sent to those rules.

## Deep Review and Research Runs

#### Deep-Review Runs Keep Every Step

A deep review runs in rounds. It keeps a log of each one. The log is rebuilt from a master record. Both review workflows wrote their first line into the log directly. That shape was one the rebuild could not reproduce. So every round after the first was dropped from the log. Two more faults sat behind it. The master record rejected the review's round format. It refused any entry over about 10 KB. All three are fixed. Resume, restart, pause, recovery and blocked-stop records now reach the master record as well. So the log shows them. Restart a review that was opened before this release.

#### Review Runs Release Their Lock and Explain Failures

Review and AI Council runs released their lock without the key they took it with. So every run ended with `released:false`. It left the lock in place. They now pass the key, as research runs already did. An AI tool could time out or crash mid-run. The run then only said a file was missing. It now reports `dispatch_failed` with the exit code. It also reports how long the tool ran and whether it hit the time limit. A retry keeps the first attempt's record. It no longer overwrites it.

A second run could also take a live run's lock. That is because the lock named a process that had already exited. Every deep loop now renews its lock each round. So a running loop keeps it. A crashed run's lock frees itself within an hour.

#### Outside Models Must List What They Find

A deep loop can hand a round to another AI tool's model. That model now gets the same output rules as a built-in agent. A round that claims more findings than it lists fails at once. Before, a run could claim 46 findings and list 22. It only failed at the very end.

#### Parallel Workers Finish Without Asking

A deep loop can split its work across parallel workers. Each worker gets its own folder. A worker used to stop on rules written for a person at the keyboard. One example is asking before a risky step. Nobody was there to answer. Inside its own folder it now records the question and carries on. Acting outside that folder stays barred. A resumed worker keeps its earlier session. A worker that still ends on a question is reported as `needs_input`. It is no longer retried.

#### Research Runs Keep Accurate Records

Deep research now opens its run through the same record system as review. It releases its lock correctly. It ticks off the questions each round answered. It keeps its lock files out of git. Its `status`, `query` and `convergence` scripts accept `--read-only`. `/doctor:deep-loop` uses it, so a diagnosis never changes what it reads.

## Agents and Dispatch

#### Dispatched Agents Retry a Failed Edit

An agent started by another agent used to give up. It gave up when an edit could not find the text it meant to change. That rule exists for live sessions, where a person can step in. A started agent has nobody to ask. So it ended having written nothing. It now re-reads the file and tries again. It stops only after three failures on the same file.

#### The Goal Check Reads the Right Part

One check decides whether a session's goal is met. It read the first 1,200 characters of a long reply. The proof of being done sits at the end. It now reads the last 1,200. A reply saying "1 P0 fail" next to "done" used to count as met. It now does not. "fail 0" still passes. It also reads the assistant's own earlier text. So a problem named early cannot hide behind a confident last line. A failure a tool printed and the turn then fixed does not count.

#### Claude Code Uses Its Own Subagents

The cli-claude-code skill told a Claude Code session only to "use native capabilities". So a session that wanted another model tried the command line first. It now points to the Agent tool and its `model` setting. It says a subagent runs at the session's effort level unless its definition sets another. The project's default effort is now low for Fable. It is high for Opus and Sonnet.

#### OpenCode Dispatches Leave Other Work Alone

An OpenCode run can skip permission prompts. Before it, the safety checklist asked for a clean working folder. In a shared folder that meant committing other sessions' work. It now asks you to commit only your own changes. It asks you to note that commit as the restore point.

## Jev Classifier

#### Jev Features Run Once a Key Is Stored

Jev is a hosted service. It answers a yes-or-no question with a likelihood. Each feature below beat the best rule that uses no AI model. They run on their own once the `jev` command is installed. They also need `jev auth status` to pass. So a machine without a stored key never calls the service:

- **Citation drift note.** `validate_document.py` lists a `file:line` reference whose code no longer shows what the text claims. It was right on 35 of 40 against 13 for the plain rule.
- **Injection screen.** A hook runs after a web fetch in Claude Code, Devin, OpenCode or Pi. It adds one warning line when part of the page reads like instructions aimed at an AI. Hermes reaches it through a bridge. Cursor and Codex cannot carry it. That is because no fetched page reaches their hooks. It was right on 84 of 90 page sections against 68 for a fixed word list.
- **Reviewer verdict fallback.** When `/deep:model-benchmark` scores with `--scorer reviewer`, it asks Jev for the verdict whenever it cannot read one from the reviewer's reply. It read 24 of 24 against 8.
- **Invented-name grader.** When the same benchmark scores with `--scorer 5dim`, it asks Jev about made-up names in answers its own check flags. It graded 55 of 56 against 47.

None of them blocks work. A failed call leaves things as they would be without Jev. Some tools were removed before release. They were built for Jev ideas that did not beat their baselines. A local Deem backend was removed too.

#### Each Feature Has Its Own Off Switch

`JEV_FEATURES=0` turns all four off. `JEV_FEATURE_CITE_DRIFT`, `JEV_FEATURE_INJECTION_SCREEN`, `JEV_FEATURE_VERDICT_FALLBACK` and `JEV_FEATURE_HALLUCINATION_GRADER` each turn one off. A switch is read from the environment first. Then it is read from `.skilled/hooks/hook-flags.env`. So a saved choice holds across sessions.

#### Benchmarks Grade With Jev When They Can

`/deep:model-benchmark` now defaults to `--grader auto`. That grades with Jev when it is ready. Otherwise it uses the grader that makes no call. Every report says which grader ran. A misspelled grader name now stops the run. It no longer scores with a stand-in that printed made-up numbers.

#### One Classifier Hub, Reached Through Pi First

`cli-classifier` is now the one entry point for classifier answers. `cli-jev` is its only mode. So a future classifier can join without changing how anything calls it. Yes-or-no and choice questions go to Pi's built-in classifier first. They fall back to the `jev` command. Scores and batches go straight to it. Each answer says which route gave it. `JEV_TRANSPORT=jev` skips Pi. A request now reaches the classifier only through the words `jev score` or `jev choice`.

## Skill Advisor

#### A Rebuilt Advisor Restarts Itself

The skill advisor runs as a background service. It loads its code once. So after a rebuild it kept answering with the old code. That lasted until someone restarted it. The next call now replaces a service started before the latest build. `SPECKIT_BRIDGE_RESPAWN_DISABLED=1` turns this off. On a fresh clone, the advisor also installs what it needs before its first build.

#### Advisor Status Tells the Truth

`advisor_status` reported 20 skills. `skill_graph_status` reported all 14 skills as changed. Nothing was out of date. The two compared files differently. The count included test files. They now agree. They count only real skills. They report `indexStaleness` when a stored record no longer matches its file. The advisor's safety screen also stopped rejecting skill names such as `system-spec-kit`. It rejected them just for containing the word `system`. Its stress tests now run in CI on every advisor change.

## Documentation Checks

#### One List Decides Metadata Values

Every document opens with metadata. Its `contextType` field had 31 different values across spec docs. Four tools kept their own lists. The allowed `contextType` and `importance_tier` values now live in one file, `sk-create-frontmatter/assets/frontmatter-values.json`. Spec-kit, `validate_document.py` and the skill advisor all read it. Existing values were mapped to it, leaving 12. A value outside the list now raises the `FRONTMATTER_VALUES` warning. That warning never fails a check.

#### Research Sources Must Point at Real Lines

The new `SOURCE_TAGS` warning checks each `[SOURCE: path:line]` reference. It reads the research and review files of packets created after 2026-10-04. It warns when the file is gone, has moved or is shorter than the cited line. It never fails a check. A pass means the line exists. It does not mean the line supports the claim.

#### Broken References Are Named and Sorted

The evidence check now lists each `file:line` reference that does not lead to a real file and line. The reference scan, `cite-drift-scan.mjs`, now covers spec and research docs. It sorts broken references into moved, deleted and past the end of the file. A moved reference names its new path. Checked against git, it was right 98% of the time.

#### Stale Search Indexes Are Caught

The search index is a file of trigger phrases. It lets a session find past work. The index builder's `--check` now compares the saved index with the current documents. It writes nothing. CI runs it as a report. The search doctor uses it as its verdict. The lookup's `--scoring-only` drops weak partial matches. So an empty result is a clean miss.

#### Validation Says When It Guessed

Document checking now warns when it could not tell a document's type. It then fell back to README rules. It blocks a skill that names an incomplete MCP tool. The code style checker also flags missing section dividers. It flags code folders without a README. It flags names wrapped in double underscores.

#### Four Skill Versions Restart Lower

Four skill version numbers had run ahead of their limits. They were renumbered. The skills are system-spec-kit, the system-deep-loop hub, deep-ai-council and the sk-code hub. system-spec-kit and the sk-code hub went from v4 to v2. system-deep-loop went from v3.0 to v1.5. deep-ai-council went from v2.4 to v1.8. Skilled's own release numbers did not change.

#### Writing Guides Match the Tools

`/create:changelog` now picks content by what a reader would notice. It checks for internal labels and repeated sentences. The step-by-step guide for writing a spec folder now works as written. That is because its commands match what the tools and the commit hook accept. The total length allowed for skill descriptions rose from 5,600 to 6,400 characters. That is because the per-skill targets alone added up past the old limit. Nine skills keep their hard rules in a `hard-rules.json` file next to `SKILL.md`. That is because Claude Code ignored the field they used before.

## Workflow Security

#### Security Fixes Arrive on Their Own

GitHub workflow steps now pin to exact versions. That is because a moving label such as `actions/checkout@v4` can change what CI runs. It can do that without any change here. Dependabot keeps those versions current. Security fixes arrive as one combined pull request. It merges by itself once its checks pass. That holds as long as every update in it is a small patch. Any other Dependabot pull request still waits for a person.

#### Reports Stay Private and Risky Defaults Are Disclosed

The new `SECURITY.md` explains how to report a vulnerability privately. It also says plainly what Skilled does on your machine. The shipped Claude Code setup skips permission prompts. Some agent runs skip approval. First use runs npm installs with their scripts. It shows how to turn approval back on. It shows where to keep keys.

#### Security Scanners See Only This Repository's Code

Copies of other projects were kept as research material under `specs/**/context/`. They caused most of the serious findings in plugin security scans. That folder is no longer in git. Scripts that built shell commands from file paths now pass each part separately. A benchmark scorer no longer runs model-written code through `Function`.

## Upgrade Notes

- **Update with `/doctor:update`.** Run it to see what this release changes. On a copied install, run `/doctor:update record-base` once first. Then commit `.skilled/release/base.json`.
- **Replace rewrite calls.** Ask the assistant directly to say its reply more plainly.
- **Write a body on every commit.** Commits marked as breaking also need `Context:`, `Changes:` and `Verification:` sections. Scopes must use their full name, such as `system-spec-kit`.
- **Stop using the message-check bypass.** `SPECKIT_SKIP_COMMIT_MSG_VALIDATE` is gone. Fix the message or change the template rule.
- **Repoint doctor targets.** `/doctor:speckit` checks search only. Use `/doctor:skill-advisor`, `/doctor:deep-loop` and `/doctor:runtime-mirrors` for the rest. Use `/doctor:skill-advisor rebuild` to rebuild the advisor.
- **Use the `openai` provider on Pi 1.0.** Replace `openai-codex` in any Pi model name you keep, such as `openai/gpt-6-luna`.
- **Approve the changed Codex hooks.** Open `/hooks` in Codex once and approve the updated entries.
- **Expect a crashed loop to hold its lock for up to an hour.** `loop-lock.cjs status` names the run that holds it.
- **Restart open sessions and deep-review runs.** Each AI tool reads its hooks when a session starts. A review opened before this release loses later rounds.
- **Add rules to your message templates.** Add an `Enforced rules` block to each template. If the checks must block merges, mark their CI check as required in your branch settings.
- **Drop `--server` from `/doctor:mcp`.** It covers Code Mode only.
- **Expect two new warnings.** `validate.sh` can warn on a metadata value outside the shared list. It can warn on a `[SOURCE:]` reference that does not lead anywhere. Neither fails a check.
- **Compare skill versions by their new numbers.** system-spec-kit, system-deep-loop, deep-ai-council and the sk-code hub now show lower versions than in v4.0.0.2.
- **Remove a `~/.codex/AGENTS.md` link.** Codex reads the root `AGENTS.md`.
- **Save hook switches instead of retyping them.** Set `speckit.hooks.<key>` to `off` in git config, or use `/doctor:git hooks`.
- **Trust another repository's hooks on purpose.** Run `git config --local skilled.trustRepoHooks true` in a repository whose own hook checks should run.
- **Turn Jev features off where you need to.** Set `JEV_FEATURES=0`, or one feature's own switch, in the environment or in `.skilled/hooks/hook-flags.env`. Pass `--grader noop` to `/deep:model-benchmark` for a run that makes no call.
