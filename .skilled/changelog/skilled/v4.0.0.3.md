# v4.0.0.3, Stronger Repository Rules, Focused Doctor Commands, Clearer Routing and Plain Language

v4.0.0.3 makes the framework behave the same across repositories and runtimes. Message checks now follow the repository they guard, and every runtime sees the hard rules. Fresh clones and worktrees build what they need. Four Jev features that beat their baselines run on their own once a Jev key is stored.

The doctor commands are reorganized so each one checks one part of the framework. `/doctor:update` now moves a checkout to a newer release.

The standalone communication skill is removed. A request for plainer wording is now a copy edit that keeps every claim.

## Why This Release

Framework growth spread guidance and enforcement across more runtimes and documents. Templates described rules that hooks never read, some runtimes never saw the hard rules and generated indexes went stale without notice.

The doctor had not kept pace. One command fronted ten checks owned by different skills, and `/doctor:update` meant a database rebuild rather than an update.

Deep-review runs also lost their state after setup, left their lock behind and reported a failed executor only as a missing file.

&nbsp;

## What's New at a Glance

- **Repositories own their message rules.** The hook, push, agent and CI gates read each repository's templates. Every commit needs a body, and the message check has no bypass switch.
- **The hooks trust only their own checkout.** A cloned repository can no longer run its code in your hooks, and a git config setting keeps an optional gate off across commands.
- **Each doctor command checks one owner.** The skill advisor, deep loop and runtime mirrors have their own commands, and `/doctor:update` now updates a checkout instead of rebuilding databases.
- **Every runtime sees the hard rules.** They fit inside the part of `AGENTS.md` every runtime loads, and a new gate loads the reply rules before each answer.
- **Plain-language requests keep every claim.** The communication skill and its rewrite commands are gone, and the rules explain how to fix machine-like prose.
- **Deep-loop runs finish their work.** Review runs record every iteration and release their lock, a failed dispatch says how it failed and a lineage must list every finding it claims.
- **Jev features turn on with a stored key.** Four features that beat their baselines run on their own, and each has an off switch.
- **Fresh clones and worktrees build what they need.** Code Mode builds its own server, and a new worktree arrives with every build the toolchain expects.
- **Checks catch drift, broken citations and stale indexes.** One shared list decides frontmatter values, and the citation census tells a moved file from a deleted one.
- **Security updates arrive on their own.** Workflow actions stay pinned, patch-level security fixes merge once their checks pass and vulnerability reports stay private.

## Repository Checks

#### Repositories Own Their Message Rules

The commit, pull-request and branch templates in each repository now carry structured rules. The commit hook, the push check, the agent gates and CI all read those same blocks, so one repository's rules no longer apply to every other repository.

**Breaking:** Skipping the commit hook no longer gets a failing message through. Push and CI checks still reject it. Update the template or the message to pass.

#### Every Commit Carries a Body

The commit hook used to ask for a body only when a commit staged four or more files, so small commits recorded what changed but never why. It now refuses any authored message without a prose line below the subject. A trailer alone is not a body. Merge, revert, `fixup!`, `squash!` and `amend!` commits stay exempt.

**Breaking:** A commit with a subject and no body is now refused. Add a sentence below the subject that says why the change was made.

#### The Message Check Has No Bypass

`SPECKIT_SKIP_COMMIT_MSG_VALIDATE` used to turn the commit message check off. The variable is gone and the hook ignores it.

**Breaking:** Setting `SPECKIT_SKIP_COMMIT_MSG_VALIDATE=1` no longer lets a message through. Fix the message, or change the rule in the repository's template.

#### Commit Rules Catch Alias Scopes and Long Subjects

A scope that is an alias of another, such as `spec-kit` for `system-spec-kit`, is blocked, and the message names the scope to use. A subject over 80 characters warns, and 100 stays the hard limit. A breaking commit must carry `Context:`, `Changes:` and `Verification:` sections.

**Breaking:** A breaking commit without all three sections is now refused. Add the missing sections to the body.

A follow-up review closed smaller gaps. A `Spec:` trailer that points outside the spec folders no longer passes, a badly written rule pattern can no longer hang a commit and a rebased commit no longer collides with its own Commit-Id.

#### Cloned Repositories Cannot Run Code in Your Hooks

The git hooks usually run for the whole machine through a global `core.hooksPath`, and they used to load their checks from whatever repository they ran in. A cloned repository that shipped its own copies of those checks had them run on every pull, commit or push. The hooks now use a repository's own checks only in the checkout they were installed from, its worktrees or a repository whose local git config sets `skilled.trustRepoHooks=true`. A value passed with `git -c` does not count. Every other repository gets only the message check.

#### Hooks Block When a Check Cannot Run

A gate whose checker crashed used to pass the commit as if the check had run. It now blocks and reports the crash apart from a rule failure. A staged file whose content git cannot read also blocks the commit instead of skipping its checks.

#### Codex Shell Hooks Fire Again

Codex 0.160 renamed its shell tool from `exec` to `Bash`, so the git preflight advisory, the git message gate, the spec-folder gate and the dispatch checks had silently stopped running under Codex. They now match both names. Codex asks you to approve the changed hook entries once in `/hooks`.

#### Session Hooks Reach More Runtimes

The hooks that keep a session's checkout in step with the shared live branch now run at session start on Cursor and Devin, and Hermes runs the follow hook too. Where a runtime cannot carry a hook, the hook registry now says why.

#### Optional Hook Gates Can Stay Off

Turning off an optional gate used to mean setting its `SPECKIT_SKIP_*` variable on every command. Setting `speckit.hooks.<key>` to `off` in local or global git config now keeps that gate off, and each run prints one line naming the setting. The two per-push approvals, for pushing outside the allowed branches and for mass deletion, still have to be given on the command itself.

#### Push Checks Read the Pushed Tree

A spec in the pushed tree now counts even if the current checkout does not contain it yet, so a code change and its spec can travel in one push. The check also looks only at the commits the push adds, so a force-push over a tip you have not fetched, or a push carrying edits merged on the web, no longer fails on commits the remote already holds.

#### Worktrees Use Their Own Validator and Arrive Fully Built

The hooks are shared from one checkout, so a worktree that added a new rule was judged by that checkout's older validator, which refused the commit adding the rule. The hooks now run the worktree's own validator.

A new worktree also lacked spec-kit's built runtime and command-line tools, so metadata repair and the continuity writer failed with a one-line Node error. Provisioning now builds both and installs every package that links to the shared spec-kit library.

## Doctor Commands

#### Each Doctor Command Checks One Owner

`/doctor:speckit` used to front ten checks owned by different skills. It now checks spec-kit retrieval only: the trigger index, its lookup and the search recipes. The skill advisor's checks moved to `/doctor:skill-advisor`, which gains a `rebuild` that backs up the advisor's graph database and restores it if any step fails. The deep loop and the runtime mirrors move to `/doctor:deep-loop` and `/doctor:runtime-mirrors`, and the embeddings and fable-mode checks are removed. A doctor command that needs a target and gets none shows its menu and waits rather than guessing.

**Breaking:** `/doctor:speckit` no longer runs other owners' checks. Given an old target name, it prints the command that owns it now.

#### The Updater Moves a Checkout to a Newer Release

`/doctor:update` used to rebuild the runtime databases. It now compares your checkout with a framework release and brings it up to date. `check` reports where the checkout stands without changing files. Parts you have not changed update directly, and a part you changed is never overwritten: `align` records your decision for it and `apply` acts only on decided parts. `apply` asks once before its first write and keeps a record that `rollback` can restore. On a copied or freshly installed tree, `record-base` records the starting point once. The updater takes stable releases unless you pass `--include-prerelease`.

**Breaking:** `/doctor:update` no longer rebuilds databases. Rebuild the advisor graph with `/doctor:skill-advisor rebuild`.

#### Hook Switches and Message Rules in One Place

`/doctor:git hooks` lists each hook gate with its local, global and effective value and changes one after showing the exact `git config` command. `/doctor:git standards` copies the shipped templates into the repository's `.sk-git/` folder once, then changes or removes one rule at a time. It refuses any change the hooks would reject. `--dry-run` shows the plan and writes nothing.

#### Environment Switches Set Up With a Yes

`/doctor:env` shows where each documented switch is set, including every switch the git hooks read, without revealing secret values. It saves a preference only after showing the exact line it will write and getting a yes.

#### Code Mode Builds From a Fresh Clone

A fresh clone or worktree had no Code Mode server manifest and no built server, so the launcher had nothing to start. The manifest is now committed, and `install.sh` builds the server whenever it is missing or older than its sources.

The config check, the docs and the MCP doctor now name credentials the way Code Mode reads them: the manual name with each underscore doubled, then the variable, such as `clickup__official_CLICKUP_API_KEY`. `/doctor:mcp install` and `debug` now cover Code Mode only, and the `--server` option is gone.

#### The Retrieval Doctor Can Report Healthy

`/doctor:speckit` flagged weak trigger phrases as a problem whenever any existed, and every real collection of documents has a few, so the check never came back healthy. Weak phrases are now listed as advisories that never change the status.

#### Doctor Scripts Catch the Drift They Used to Pass

Several of the doctor's own scripts reported PASS on real drift or crashed on bad input. A deleted command row no longer hides behind a command with a similar name, a crash reports an error instead of drift and a skill on disk that the compiled graph lacks is named. Every doctor script now has tests that run locally and in CI.

## Assistant Rules

#### Plain Language Keeps Every Claim

**Breaking:** The standalone `sk-communication` skill, its opt-in plain-English projection of CLI output and its two response rewrite commands are removed. Ask the assistant directly to say its reply more plainly.

The repository rules now tell two requests apart. "I don't follow" asks for a new explanation, using an example, numbered steps or a picture. "Say that more plainly" asks for a copy edit that keeps every claim, number and caveat in the same order and at the same strength, and keeps code, commands, paths and identifiers exact. If a simpler word changes the claim, the claim wins.

#### A Gate Loads the Reply Rules Before Each Answer

The reply rules used to load from one line in the mandates, and sessions often missed them. `AGENTS.md` now carries Gate 6, which loads the communication rules before every substantive reply, read-only turns included. In its final measured run it cut missed loads by 38 points at no cost to the other gates. Plain phrases added across 11 rules let an everyday request find the rule that answers it, and `communication.md` now asks for a technical subject to be explained plainly the first time, without dropping a caveat or a number.

#### Every Runtime Sees the Hard Rules

Devin reads only the first 16,384 bytes of `AGENTS.md`, and the hard rules ran past that point, so Devin never saw the memory save rule or the "never fabricate" mandate. The sections were reordered so every hard rule ends inside that limit, with section numbers kept. A check now fails when a guarded clause moves past the limit. Codex reads the root `AGENTS.md` directly, so the `.codex/AGENTS.md` copy is gone.

The repository rule check also fails when a condition a rule fires on has no row in `REPO RULES.md`. Seven conditions were named only inside their rule, so no session was ever sent there. `measure-rule-compliance.py` reports per runtime how often a session wrote or replied without a rule it needed.

#### Machine Register Gets a Plain Fix

The prose rules now call out terse machine register: symbols standing in for verbs, stacked nouns, unexplained IDs and sentence fragments. They ask the assistant to use action words, say who does what and explain each identifier or count.

## Deep Loops and Agent Dispatch

#### Deep-Review Runs Record Every Iteration

A deep-review run's state log is rebuilt from its ledger by the append gateway. Both review workflows wrote the run's opening line into that log directly, and the gateway refuses to discard fields it did not write, so every iteration after setup was lost from the log. Two more faults sat behind it: the gateway rejected the review iteration record as an unknown format, and the ledger refused any event over about 10 KB. Runs now open through the gateway, review iterations record under their own event type and large events go through. A run opened before this change should be restarted.

#### Review Runs Release Their Lock and Name Failed Dispatches

Review and AI Council runs released their loop lock without the token they took it with, so every run ended with `released:false` and left the lock behind. They now pass it, as research runs already did. A timed-out or crashed executor used to show only as a missing iteration file. The iteration check now reads the dispatch receipt and reports `dispatch_failed` with the exit status, the run time and whether it hit the timeout. A retry keeps the first attempt's receipt instead of overwriting it.

#### Command-Line Lineages List Their Findings

A research or review lineage run by a command-line model now gets the same per-iteration output rules a native agent follows. An iteration that claims more findings than it lists fails at once. Before, a lineage could claim 46 findings, list 22 and pass every iteration until the final step rejected it.

#### Research Runs Keep Honest Books

Deep research now opens its run through the ledger gateway, releases its lock correctly, ticks the questions an iteration answered and keeps its locks and watermarks out of git. The deep-loop `status`, `query` and `convergence` scripts accept `--read-only`, and `/doctor:deep-loop` uses it so a diagnosis never changes the databases it reads.

#### Dispatched Agents Retry a Failed Edit

A command-line agent dispatched by another agent used to stop when an edit could not find its target text. That stop rule exists for interactive sessions, but a dispatched agent has nobody to hand over to, so it ended having written nothing. It now re-reads the file and retries, and stops only after three failures on the same file.

#### The Goal Verifier Judges the Right Evidence

The verifier that decides whether a session goal is met read the first 1,200 characters of a long turn, while the proof of completion sits at the end. It now reads the last 1,200. A turn reporting "1 P0 fail" next to "done" used to count as met and now blocks, while a zero count such as "fail 0" still passes.

#### Claude Code Sessions Dispatch Native Subagents

The cli-claude-code skill told a Claude Code session only to "use native capabilities", so a session that needed another model tried the command-line route first. It now points to the Agent tool and its `model` parameter, and states that a subagent runs at the session's effort unless its definition sets another. The project's per-model effort settings moved to low for Fable and high for Opus and Sonnet.

#### OpenCode Dispatches Leave Other Sessions' Work Alone

Before an OpenCode dispatch that skips permission prompts, the safety checklist asked for a clean working tree, which in a shared tree meant committing other sessions' work. It now asks you to commit only the dispatch target's own changes and record that commit as the recovery point.

## Classifier, Advisor and Model Routing

#### Jev Features Run Once a Key Is Stored

Jev is a hosted classifier that answers a yes-or-no question with a probability. Each feature below beat the best rule that uses no model. They run on their own once the `jev` command is installed and `jev auth status` passes, so a machine without a stored key never calls the service:

- **Citation drift advisory.** `validate_document.py` lists a `file:line` citation whose code no longer shows the claim. It was right on 35 of 40 citations against 13 for the rule.
- **Injection screen.** After a web fetch in Claude Code, Devin, OpenCode or Pi, a hook adds one advisory line when part of the page reads as instructions aimed at an AI agent. Hermes reaches it through a bridge. Cursor and Codex cannot carry it, because no fetched page reaches a hook there. It was right on 84 of 90 sections against 68 for a fixed word list.
- **Reviewer verdict fallback.** When `/deep:model-benchmark` scores with `--scorer reviewer`, it asks Jev for the verdict whenever its parser cannot read one. It read 24 of 24 against 8.
- **Hallucination grader.** When the same benchmark scores with `--scorer 5dim`, it asks Jev about invented names in outputs its own check flags. It graded 55 of 56 against 47.

None of them blocks work, and a failed call leaves the path as it would be without Jev. Tools built for the Jev ideas that did not beat their baselines, and a local Deem backend, were removed before release.

#### Each Feature Has Its Own Off Switch

`JEV_FEATURES=0` turns all four off. `JEV_FEATURE_CITE_DRIFT`, `JEV_FEATURE_INJECTION_SCREEN`, `JEV_FEATURE_VERDICT_FALLBACK` and `JEV_FEATURE_HALLUCINATION_GRADER` each turn one off. A switch is read from the environment first and then from `.skilled/hooks/hook-flags.env`, so a saved preference holds across sessions.

#### Benchmarks Grade With Jev When They Can

`/deep:model-benchmark` now defaults to `--grader auto`, which grades with Jev when it is ready and falls back to the grader that makes no call. Every report records which grader ran. A misspelled grader name now stops the run instead of scoring with a stub that printed made-up numbers.

#### One Classifier Hub, Reached Through Pi First

`cli-classifier` is now the public hub for typed classifier answers, with `cli-jev` as its only mode, so a future classifier joins without changing how callers reach it. Yes-or-no and choice questions go to Pi's built-in classifier first and fall back to the `jev` command, while scores and batches go straight to it. Each answer carries the route that gave it, and `JEV_TRANSPORT=jev` keeps a caller on the `jev` command. The routing words are now `jev score` and `jev choice`, so a request that only mentions a score no longer reaches the classifier.

#### A Rebuilt Advisor Replaces Its Daemon

The skill advisor's daemon loads its code once and keeps running across sessions, so after a rebuild it went on answering with the old code until someone restarted it. The next call now replaces a daemon launched before the current build. `SPECKIT_BRIDGE_RESPAWN_DISABLED=1` turns this off. On a fresh clone, the launcher also installs the linked Spec Kit workspace before its first build.

#### Advisor Status Matches the Index

`advisor_status` reported 20 skills while `skill_graph_status` reported all 14 skill sources as changed, though the index was current. The two hashed skill files differently and the count included test fixtures. They now share one hash and count only real skills, and `advisor_status` reports `indexStaleness`. The advisor's label screen also stopped rejecting skill names such as `system-spec-kit` for containing words like `system`, and its stress suite now runs in CI on every advisor change.

#### More Model Routes on Pi and OpenCode

MiMo v2.6 Flash joins the Pi and OpenCode rosters, and MiMo Pro and Flash gain routes through OpenCode Go and Cline Pass. Pi 1.0 renamed its ChatGPT sign-in provider from `openai-codex` to `openai`, so Luna and Sol lineages and Pi's compaction call failed with a missing-key error. The deep-loop fan-out, the compaction config and the project settings now use `openai`. Pi can also reach DeepSeek V4.1 Flash through OpenCode Go, as `opencode-go/deepseek-v4.1-flash`, or through Cline Pass.

## Documentation Tooling

#### Four Skill Version Lines Restart Lower

The versions of system-spec-kit, the system-deep-loop hub, deep-ai-council and the sk-code hub had run ahead of their caps and were renumbered. system-spec-kit and the sk-code hub went from v4 to v2, system-deep-loop from v3.0 to v1.5 and deep-ai-council from v2.4 to v1.8. Skilled release numbers did not change.

#### One List Decides Frontmatter Values

Spec docs outside archive and scratch folders used 31 distinct `contextType` values while four tools kept their own lists. The legal `contextType` and `importance_tier` values now live in `sk-create-frontmatter/assets/frontmatter-values.json`, which spec-kit, `validate_document.py` and the skill advisor all read. Off-list values were mapped to the list, leaving 12. A value outside the list now draws the `FRONTMATTER_VALUES` warning, which never fails a run.

#### Research Source Tags Must Point at Real Lines

The new `SOURCE_TAGS` warning checks each `[SOURCE: path:line]` tag in the research and review files of packets created after 2026-10-04. It warns when the file is gone, has moved or ends before the cited line, and never fails a run. A pass means the file and line exist, not that they support the claim.

#### Broken Citations Are Named and Sorted by Cause

The acceptance-evidence check now lists each citation that cannot resolve to a file and a valid line. The citation census, `cite-drift-scan.mjs`, now covers spec and research docs and sorts broken citations into moved, gone and past-end. A moved citation names its new path, and checked against git it was right 98% of the time.

#### Stale Trigger Indexes Are Caught

The index generator's `--check` compares the committed trigger index with current guidance without writing anything. CI runs it as a report, and the retrieval doctor uses it as its verdict, so a stale index is judged by its content rather than by file times. The lookup's `--scoring-only` drops unscored partial matches, and with it an empty result is a clean no-hit.

#### Validation Calls Out Its Fallbacks

Document validation now warns when no path rule matches and README rules are used by default, and it blocks a skill that names an incomplete MCP tool. The alignment checker now also flags missing section dividers, code folders without a README and names wrapped in double underscores.

#### Authoring Guides Match the Tools

`/create:changelog` now chooses content by what a reader would notice and checks for internal labels and repeated sentences. The spec folder write recipe now runs as written: its metadata backfill and commit steps match what the tools and the commit hook accept. The skill description ceiling rose from 5,600 to 6,400 characters, because the per-skill targets alone added up past the old one. The nine dispatch skills keep their hard rules in a `hard-rules.json` file beside `SKILL.md`, since Claude Code ignores the frontmatter field they used.

## Workflow Security

#### Security Updates Arrive on Their Own

GitHub workflow actions now pin to commits, because a tag such as `actions/checkout@v4` can change what CI runs without any change here. Dependabot tracks those versions. Security fixes arrive as one grouped pull request that merges once its checks pass when every bump is a patch release. Any other Dependabot pull request still waits for a person.

#### Reports Stay Private and Defaults Are Disclosed

The new `SECURITY.md` directs vulnerability reports to a private channel. It also says what Skilled does on your machine: the shipped Claude Code mode skips permission prompts, write dispatches run with approval off and first use runs npm installs with their scripts. It shows how to turn approval back on and where to keep keys.

#### Plugin Scanners See Only This Repository's Code

Copies of third-party repositories kept as research material under `specs/**/context/` carried most of the high findings in plugin security scans. That folder is no longer tracked. Scripts that built shell commands from paths now pass each argument separately, and the code-task scorer no longer uses the `Function` constructor.

## Upgrade Notes

- **Replace rewrite calls.** Ask the assistant directly to say its reply more plainly.
- **Write a body on every commit.** Breaking commits also need `Context:`, `Changes:` and `Verification:` sections, and scopes must be canonical, such as `system-spec-kit` instead of an alias.
- **Repoint doctor targets.** `/doctor:speckit` checks retrieval only. Use `/doctor:skill-advisor`, `/doctor:deep-loop` and `/doctor:runtime-mirrors` for the checks it used to front.
- **Stop using `/doctor:update` to rebuild.** Rebuild the advisor graph with `/doctor:skill-advisor rebuild`. On a copied or fresh tree, run `/doctor:update record-base` once.
- **Stop using the message-check bypass.** `SPECKIT_SKIP_COMMIT_MSG_VALIDATE` is gone. Fix the message or change the template rule.
- **Use the `openai` provider on Pi 1.0.** Replace `openai-codex` in any Pi model string you keep, such as `openai/gpt-6-luna`.
- **Approve the changed Codex hooks.** Open `/hooks` in Codex once and approve the updated shell hook entries.
- **Restart open sessions and deep-review runs.** Each runtime reads its hook files when a session starts, and a deep-review run opened before this release loses later iterations.
- **Prepare repository message checks.** Add an `Enforced rules` block to each message template. If the checks need to block merges, mark their CI check as required in your branch rules.
- **Drop `--server` from `/doctor:mcp`.** It covers Code Mode only.
- **Expect two new warnings.** `validate.sh` can warn on a `contextType` or `importance_tier` outside the shared list and on a `[SOURCE:]` tag that does not resolve. Neither fails a run.
- **Compare skill versions by their new numbers.** system-spec-kit, system-deep-loop, deep-ai-council and the sk-code hub now report lower versions than in v4.0.0.2.
- **Remove a `~/.codex/AGENTS.md` link.** Codex reads the root `AGENTS.md`.
- **Save hook switches instead of prefixing commands.** Set `speckit.hooks.<key>` to `off` in git config, or use `/doctor:git hooks`.
- **Trust another repository's hooks on purpose.** Run `git config --local skilled.trustRepoHooks true` in a repository whose own hook checks should run.
- **Turn Jev features off where you need to.** Set `JEV_FEATURES=0`, or one feature's own switch, in the environment or in `.skilled/hooks/hook-flags.env`. Pass `--grader noop` to `/deep:model-benchmark` for a run that makes no call.
