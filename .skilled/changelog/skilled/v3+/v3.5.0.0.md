# v3.5.0.0, Memory That Maintains Itself

The previous release was about honesty and hardening. This one is about the runtime getting out of its own way.

Embeddings run locally first, on your own machine through Ollama or a Python-free local server, and reach the cloud only when you ask. The MCP servers are now three separate processes, and the memory one runs as a single shared daemon behind a front-proxy that hides a recycle, so a restart stops surfacing as an error.

The deep-loop engine behind deep-research and deep-review learned to fan out across several executors. And the prompt toolkit became forkable, with a small-model hub for open models.

Underneath, memory still gets smarter on its own after every save and the index keeps itself reconciled. The long-running 026 program documented every one of its phases into one canonical changelog tree before closing itself out. A cleanup pass also removed the vendored research repos that never belonged in the shipping tree, code that was never ours to ship.

> Spec folder: `.opencode/specs/system-spec-kit/026-graph-and-context-optimization/`

## Why This Release

A large part of this release went into the launcher and daemon lifecycle. That surface was behind most of the prior release's friction and a hard-to-pin disconnect. The 026 program's changelogs had also scattered and drifted, so this release made that history canonical.

## What's New at a Glance

- **Cloud embeddings are opt-in only.** Providers like OpenAI or Voyage are never auto-selected.
- **Saves return immediately.** Enrichment and causal relation inference run in the background.
- **`memory_index_scan` maintains itself.** It graduated from a manual trigger.
- **Checkpoints are real database files.** Restores are crash-safe.
- **Memory, code-graph and skill-advisor are separate MCP servers.** Each has its own launcher.
- **Sessions share one `system-spec-memory` daemon.** Each session no longer spawns its own and contends on the database.
- **Sessions can each run in their own worktree.** The worktree is reaped when the session closes.
- **deep-research and deep-review can fan out.** One loop drives several executor lineages and recovers from a flaky one instead of grinding through a single lineage at a time.
- **deep-agent-improvement was renamed deep-improvement this cycle.** The skill gained a skill-benchmark lane and a model-benchmark framework.
- **`sk-prompt` lifts out cleanly.** `sk-prompt-models` drives open models through cli-opencode.
- **Every live 026 changelog is centralized.** A per-program index and a regenerated timeline link each spec folder to its changelog.

## Memory and Embeddings

#### Embeddings Stay on Your Machine

Resolution follows your explicit `EMBEDDINGS_PROVIDER` when set, then a persisted Ollama embedder, then a Python-free local fallback server. Running on a single small nomic model on your own machine, the common case never leaves the box.

This release closed the last place where the local-first rule was not honored. The primary resolver used to pick a cloud provider when Ollama was down and an API key happened to be set, the exact opposite of the intended priority. It now follows the local-first order everywhere, and the legacy cloud-preference tests were rewritten to assert it. The Python-free local server and the consolidation onto a single nomic model matured in the prior release. This release made the resolver match the design.

&nbsp;

#### Enrichment Moves to the Background

Post-insert enrichment, reconsolidation and quality auto-fix are now on by default, and enrichment runs async. A save comes back with `enrichmentStatus: deferred` while a bounded background scheduler enriches graph and entity data after the commit. Reconsolidation stays opt-in behind `SPECKIT_RECONSOLIDATION_ENABLED`.

&nbsp;

#### Lineage Becomes Causal Edges

Spec-document chains and lineage links are now promoted into typed `created_by='auto'` causal edges. The backfill is bounded, dry-run by default and reversible. Two opt-in collectors add a similarity `supports` signal and a structural `contradicts` signal.

A conflict guard refuses to invalidate an existing valid edge. That closes a case where a committed `contradicts` run over a reciprocal lineage pair could silently undo the valid `caused` edge it had just created. The production backfill raised relation coverage from 39.91% to 43.59%. It raised `caused` edges from 3 to 103 and skipped zero conflicting edges.

&nbsp;

#### An Index That Reconciles Itself

Redundant concurrent scans collapse into one, orphans get swept and a relocated spec folder is re-pointed instead of orphaned. The index reports its state through `memory_health`. An active-row uniqueness guard and multi-tenant scope isolation close the door on duplicate rows and cross-scope bleed.

&nbsp;

#### Checkpoints Survive a Crash

Checkpoints used to be in-process snapshots. Create now writes a complete file with `VACUUM INTO`, and restore swaps a finished file in behind a crash-safe journal. If a restore cannot finish, for example after a crash, a `.needs-rebuild` sentinel forces a clean rebuild on the next boot. The downgrade guard was updated for schema v30.

## MCP Servers and Sessions

#### Many Sessions, One Daemon

A lease-holder launcher owns the daemon child, and other launchers bridge their own client to it through a session proxy. The owner stores its real IPC socket path in the lease. A secondary launcher pointed at a different socket directory still finds the live daemon instead of failing with no bridge socket.

&nbsp;

#### Clients Stay Connected Through a Recycle

The front-proxy sits between clients and the daemon. When the daemon recycles, a connected client no longer sees a hard error. The launcher reconnects, re-handshakes on a protocol-version drift and keeps each connected client independently transparent. It is also hardened against an externally killed or slow-booting daemon.

A boot-time full-text-search auto-heal plus a launcher clean-close barrier fixed the daemon-lifecycle root cause behind the recurring corruption-looking failures. The launcher-lease integration suite had been failing every run because its test fixture copied the launcher but not its library tree. It was repaired and un-skipped.

&nbsp;

#### Worktree-Per-Session Isolation

Per-session worktrees prevent the multi-session contention behind much of the prior release's daemon friction. The guard is wired into the Claude session-start chain, and child sessions launched through the CLI dispatchers share the parent's worktree.

## Deep Loops

#### Fan-Out Across Executor Lineages

The fan-out layer is opt-in. Each lineage is an isolated sub-packet with its own state directory, and the lineages run behind a concurrency-capped pool with a status ledger. A salvage path recovers a lineage's work from captured output if its write fails.

A consumer-specific merge folds the lineages back together. Research dedups and attributes findings. Review rolls up severity and fails closed if any lineage reports a P0. The single-executor sequential path stays the default and is byte-identical to before.

&nbsp;

#### Lineages Still Run Serially

In this release the fan-out runs under the cap but still issues its lineages serially. The genuine-concurrency remediation was specced here and lands in the next release.

&nbsp;

#### Two Parser Fixes Behind the Loops

The review transcript parser no longer concatenates a model's prompt-echo into invalid JSON and zeroes out findings. The convergence snapshot writer refuses to coalesce every snapshot to one id and silently overwrite history.

&nbsp;

#### A Skill-Benchmark Lane

The skill-benchmark lane measures how a real agent discovers, routes to and uses a skill in situ. It scores routing accuracy, unprompted discovery, efficiency and usefulness into a ranked, remediable report.

&nbsp;

#### One Framework for Model Benchmarks

A reusable, config-driven model-benchmark framework replaced the one-off rigs. A single profile runs a framework bake-off or a model-versus-model comparison with no mode branches. Correctness is a gate, so a saturated score cannot crown a winner. The verdict is WINNER, TIE or INCONCLUSIVE against a noise floor.

## Prompt Toolkit and Skills

#### Three Layers and a Forkable Core

The prompt toolkit was re-architected into three layers: framework craft in `sk-prompt`, per-model craft in `sk-prompt-models` and executor mechanics in the `cli-*` skills. The model registry and benchmarks moved into `sk-prompt-models`, so the generic `sk-prompt` skill can be lifted out of this repo without dragging the small-model registry with it.

&nbsp;

#### Open Models That Pay Off

The small-model hub holds the per-model prompt-craft profiles, the model registry and the benchmark run-data. Open models like DeepSeek, MiniMax and Xiaomi MiMo can be driven effectively through cli-opencode rather than prompted blind. MiniMax now defaults to its Token Plan provider, and Xiaomi MiMo-V2.5-Pro was added as a selectable executor.

&nbsp;

#### Supporting Skill Work

A new `mcp-click-up` skill handles task work. `sk-code` gained surface-aware routing and mined animation principles, and `sk-git` gained a numbered `wt/{NNNN}-{name}` worktree convention. Feature-catalog standards were applied retroactively across roughly 370 catalog files.

## Upgrade Notes

- **No breaking API changes.** New capability is additive, and the MCP server reports `1.8.0`.
- **Verify and repair with `/doctor`.** After upgrading, the doctor command is the fastest way to confirm each subsystem is healthy. `/doctor <target>` runs a focused diagnostic for `memory`, `embeddings`, `causal-graph`, `code-graph`, `deep-loop`, `skill-advisor` or `skill-budget`. Most targets are read-only and report drift with a recommended action rather than mutating anything. `/doctor:mcp install|debug` covers the MCP launcher and daemon infrastructure, and `/doctor:update` runs a dependency-ordered cross-subsystem alignment with snapshot, validate and rollback. For a quick read-only install check, `bash .opencode/skills/system-spec-kit/scripts/doctor.sh --strict` confirms the memory server's dist and native modules are present.
- **Recycle the daemon after a dist change.** Because many sessions now share one memory daemon, a pulled change to the compiled server only takes effect once that daemon recycles. `dist/` is gitignored, so rebuild after every pull. `bash .opencode/skills/system-spec-kit/scripts/deploy-mcp.sh` rebuilds every MCP dist, and `--recycle` performs the transparent daemon-child recycle that keeps clients connected. A rebuilt `shared/dist`, where the embedding resolver lives, also needs a recycle to take effect.
- **Set `EMBEDDINGS_PROVIDER` only to opt into a specific provider.** `/doctor embeddings` reports provider and model-server status.
- **Force the old synchronous save path if you need it.** Set `SPECKIT_POST_INSERT_ENRICHMENT_SYNC=true`.
- **The causal relation backfill is conservative.** `memory_causal_stats({ backfill: { dryRun: false } })` promotes deterministic structural signals into `caused` and `supports` edges. The conflict guard gates the similarity and `contradicts` collectors. Inspect the graph with `/doctor causal-graph` before you run it.
- **Checkpoints self-heal.** The checkpoint schema is now v30, and the v2 file-based path activates automatically on the next create or restore.
