# v3.3.0.0, Durable Context Recovery and Agent Improvement

Two major programs land in this release.

- The compact code graph program is packet 024, 30 phases.
- It gives AI sessions durable context recovery.
- Recovery works after compaction, restart or runtime switches.
- It covers Claude hook rescue and structural code-graph retrieval.

The compact code graph program covers more recovery work.

- It also covers CocoIndex bridging and hookless bootstrap.
- Cross-runtime parity is included too.
- So is an OpenCode transport and startup plugin.

The agent improver program adds a new skill.

- It is packet 041, 11 phases.
- That skill evaluates any agent across 5 integration-aware dimensions.
- It combines deterministic scoring with dynamic profiling.
- It also adds guarded promotion gates.

&nbsp;

## Why This Release

The goal is to make the workflow easier to follow. It should also be easier to trust.

- Long AI coding sessions no longer depend on the user re-explaining context.
- This holds after compaction, restart or runtime switches.

## Context Preservation Stack

Long sessions lose their short-term memory. This stack restores context across compaction, priming, structural answers and hookless recovery.

#### Claude Sessions Survive Compaction <a id="c-claude-sessions-survive-compaction"></a>

- Claude compaction wiped out the AI's short-term memory.
- After a compact, the assistant lost the active spec folder.
- It lost recent code focus and the rules guiding the work.
- PreCompact caches a recovery payload.
- SessionStart injects it back for `source=compact`.
- Working-memory attention signals, spec-folder detection and token-budget controls keep the recovered brief small enough to fit.
- The recovered brief is still useful.

#### Priming That Fits How a Session Began <a id="c-priming-that-fits-how-a-session-began"></a>

- Startup, resume, clear and compact were treated too similarly.
- That gave the wrong context for each situation.
- Compacts now restore cached context.
- Resumes point at the compact brief.
- Startups surface tool and freshness guidance.
- Clears fall back to minimal recovery instructions.
- Startup is also freshness-aware now.
- Auto-indexing is bounded.

#### Answers to Structural Questions <a id="c-answers-to-structural-questions"></a>

- Semantic search could find code by meaning.
- It could not answer structural questions like "who calls this?" or "what does this file import?".
- The graph fills that gap.
- A SQLite-backed code graph adds structural retrieval.
- It comes with scan, query, status and context-expansion tools.
- Parsing gets a progressive migration from regex-only to tree-sitter-backed.
- Regex is retained as the fallback.

#### The Right Search for Each Question <a id="c-the-right-search-for-each-question"></a>

- Semantic search, structural search and memory search lived beside each other.
- Nothing guided when to use which.
- Intent metadata and routing enforcement now push semantic questions toward CocoIndex.
- They push structural questions toward the graph.
- Session-history questions go toward memory.
- Intent classification recognizes structural, semantic and hybrid intent.
- CocoIndex hits expand into structural neighborhoods.
- Seed resolution and context orchestration form the CocoIndex bridge.

#### Recovery Without Hooks <a id="c-recovery-without-hooks"></a>

- Claude hooks covered only one runtime family.
- Other runtimes depended on the AI remembering to prime itself.
- Runtimes without hooks recover through one main path.
- MCP first-call priming, `session_resume`, `session_health` and `session_bootstrap` are new.
- `session_bootstrap` is the canonical hookless bootstrap surface.
- It comes with an output schema.
- The OpenCode transport layer and the repo-local Copilot startup wrapper extend recovery.
- That recovery reaches beyond hook-based runtimes.
- All runtime-facing docs mirror the routing and recovery tables.

#### Portable MCP Wrapper Paths <a id="c-portable-mcp-wrapper-paths"></a>

- MCP wrapper paths are repo-relative again.
- The checked-in MCP JSON surfaces point `spec_kit_memory` at repo-relative wrapper paths.
- Some checked-in MCP config surfaces drifted to absolute `/Users/...` wrapper paths.
- That made the JSON noisier and less portable than the rest of the repo-local setup.
- The restored paths keep the configuration consistent.
- They match the workspace-relative command style used elsewhere in the project.

#### A Best-Effort Save at Session End <a id="c-a-best-effort-save-at-session-end"></a>

- The system had no reliable way to capture end-of-session state automatically.
- Stop-hook tracking adds a best-effort auto-save.
- Stop-hook tracking now parses transcript usage data.
- It stores metrics and estimates token spend.
- It can trigger a `generate-context.js` save.
- That happens when configured thresholds are met.

#### One Recovery Contract Across Runtimes <a id="c-one-recovery-contract-across-runtimes"></a>

- Runtime instructions, context-prime agents and bootstrap surfaces drifted apart across runtimes.
- Non-hook recovery is now standardized around explicit expected behaviors.
- These are ready, stale or missing structural state and the main `session_bootstrap` path.

## Hook Durability and Correctness

Hook state and the graph pipeline needed hardening. Repairs also covered the parser, the classifier and startup highlights.

#### Safer Hook State and Cache <a id="c-safer-hook-state-and-cache"></a>

- Cache races, weak temp-file handling, session-state collisions and insufficient provenance markers made the hook path fragile.
- The hook-state lifecycle is now tighter.
- It has TTL checks, SHA-256 state names and restrictive file permissions.
- It has provenance fencing and stale-on-read checks.

#### Graph Correctness Holes Closed <a id="c-graph-correctness-holes-closed"></a>

- Early graph work had correctness holes.
- These were collapsed line spans, unsafe DB initialization, transaction gaps and depth leaks.
- The graph pipeline now has multi-line symbol spans and DB initialization guards.
- It has atomic replace operations, strict depth handling and safer handler validation.

#### Parser and Classifier Repairs <a id="c-parser-and-classifier-repairs"></a>

- The first tree-sitter and classifier pass misclassified abstract methods and class expressions.
- It also misclassified multi-import capture and nested Python class names.
- Repaired parser patterns and intent-classifier confidence now fix this.
- The parser and routing layers match the structural expected behavior.

#### Leaner Startup Highlights <a id="c-leaner-startup-highlights"></a>

- Startup highlights wasted space on duplicates, vendored code and the wrong ranking signal.
- The rewritten highlight query uses deduplicated grouping and hard path exclusions.
- It uses incoming-call ranking.

## Agent Improvement Skill

A new skill evaluates any agent definition file. It runs as a bounded, deterministic loop.

#### Five Dimensions, Scored Deterministically <a id="c-five-dimensions-scored-deterministically"></a>

- The new skill is `sk-deep-agent-improvement`.
- Its scores come from deterministic checks.
- No LLM acts as judge.
- Agent prompt files had no systematic way to be evaluated.
- Manual review was inconsistent.
- It could not track improvement over time.
- The skill ships 8 scripts.
- `scan-integration.cjs` discovers all surfaces an agent touches.
- These are main, mirrors, commands, YAML and skills.
- `generate-profile.cjs` derives scoring from any agent's own rules.
- Scoring uses regex, string matching and file-existence checks.
- `score-candidate.cjs` takes a `--dynamic` flag.
- It scores across 5 weighted dimensions.
- `structural` weighs 0.20.
- `ruleCoherence` weighs 0.25.
- `integration` weighs 0.25.
- `outputQuality` weighs 0.15.
- `systemFitness` weighs 0.15.

#### Changes Stay Proposals Until Approved <a id="c-changes-stay-proposals-until-approved"></a>

- Editing main agent files directly during evaluation is dangerous.
- A bad change could break the agent.
- Candidates go to a packet-local runtime area instead.
- The `@agent-improver` agent is the canonical mutator.
- It has a halt condition and merged checklists.
- The improvement loop is proposal-only.
- `/deep:start-agent-improvement-loop` runs it.
- The `@agent-improver` subagent never touches main targets.
- The command is a full rewrite.
- It orchestrates the whole loop: scan, profile, candidate, score, benchmark, reduce and stop-check.
- Its benchmark is a fixture benchmark with an integration report.
- Promotion requires passing all evidence gates.
- It also needs explicit operator approval.

#### The Skill Tested on Itself <a id="c-the-skill-tested-on-itself"></a>

- The skill had never been tested on itself.
- That left uncertainty about self-referential edge cases.
- Phase 009 ran the loop on `agent-improver.md` itself.
- It found a real bug: a stale command path.
- Phase 010 fixed that bug plus 4 reducer issues: family hardcoding, the plateau window, accepted counting and the mirror path.

#### Advisor Routing and README Entries <a id="c-advisor-routing-and-readme-entries"></a>

- The skill advisor routes to the new capabilities.
- The skill advisor had no routing for the new 5-dimension capabilities.
- The root README was missing the agent-improver entries.
- Phase 011 added that routing.
- Phase 011 added 28 routing entries to it.
- They cover 5D scoring plus the `/deep:` and `/create:` commands.
- It bumped the skill version to 1.0.0.0.
- It added Agent-Improver to the root README's Agent Network and Skills Library sections.
- The skill count went from 19 to 20.

## Upgrade Notes

Both programs are additive, and no migration is required. The code graph, hooks and bootstrap surfaces are backward compatible. The `sk-deep-agent-improvement` skill is entirely new and does not affect existing workflows.

#### Before You Start <a id="c-before-you-start"></a>

1. No upgrade needed.
2. If you had custom references to `sk-recursive-agent`, update them to `sk-deep-agent-improvement`.
