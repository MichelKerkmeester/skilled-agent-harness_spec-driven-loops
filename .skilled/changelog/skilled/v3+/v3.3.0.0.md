This release lands two major programs. The compact code graph program (packet 024, 30 phases) gives AI sessions durable context recovery after compaction, restart or runtime switches. It covers Claude hook rescue, structural code-graph retrieval, CocoIndex bridging, hookless bootstrap, cross-runtime parity and an OpenCode transport and startup plugin.

The agent improver program (packet 041, 11 phases) adds a new skill that evaluates any agent across 5 integration-aware dimensions. It combines deterministic scoring with dynamic profiling and guarded promotion gates.

> Spec folder: `.opencode/specs/system-spec-kit/024-compact-code-graph/` and `.opencode/specs/skilled-agent-orchestration/041-sk-recursive-agent-loop/` (Level 3)

## Why This Release

The goal is to make the workflow easier to follow and easier to trust. Long AI coding sessions no longer depend on the user re-explaining context after compaction, restart or runtime switches.

## What's New at a Glance

- **Claude sessions recover after compaction.** PreCompact caches a recovery payload, and SessionStart injects it back for `source=compact`.
- **Session priming now branches by source.** Each way a session can start gets the context that fits it.
- **A SQLite-backed code graph adds structural retrieval.** It comes with scan, query, status and context-expansion tools.
- **CocoIndex hits expand into structural neighborhoods.** Seed resolution and context orchestration form the CocoIndex bridge.
- **Runtimes without hooks recover through one main path.** MCP first-call priming, `session_resume`, `session_health` and `session_bootstrap` are new, and all runtime-facing docs mirror the routing and recovery tables.
- **Stop-hook tracking adds a best-effort auto-save.** It can trigger a `generate-context.js` save when configured thresholds are met.
- **MCP wrapper paths are repo-relative again.** The checked-in MCP JSON surfaces point `spec_kit_memory` at repo-relative wrapper paths.
- **Hook state and the graph pipeline are hardened.** Parsing, intent classification and startup highlights got repairs as well.
- **The new skill is `sk-deep-agent-improvement`.** Its scores come from deterministic checks, with no LLM acting as judge.
- **The improvement loop is proposal-only.** `/deep:start-agent-improvement-loop` runs it, and the `@agent-improver` subagent never touches main targets.
- **The skill was tested on itself.** Phase 010 promoted 6 candidate improvements from that test.
- **The skill advisor routes to the new capabilities.** Phase 011 added 28 routing entries to it, covering 5D scoring plus the `/deep:` and `/create:` commands.

## Context Preservation Stack

#### Claude Sessions Survive Compaction

Claude compaction wiped out the AI's short-term memory. After a compact, the assistant lost the active spec folder, recent code focus and the rules guiding the work.

Working-memory attention signals, spec-folder detection and token-budget controls keep the recovered brief small enough to fit while still being useful.

&nbsp;

#### Priming That Fits How a Session Began

Startup, resume, clear and compact were treated too similarly, which gave the wrong context for each situation. Compacts now restore cached context, and resumes point at the compact brief. Startups surface tool and freshness guidance, and clears fall back to minimal recovery instructions.

Startup is also freshness-aware now, and auto-indexing is bounded.

&nbsp;

#### Answers to Structural Questions

Semantic search could find code by meaning but could not answer structural questions like "who calls this?" or "what does this file import?". The graph fills that gap.

Parsing gets a progressive migration from regex-only to tree-sitter-backed, with regex retained as the fallback.

&nbsp;

#### The Right Search for Each Question

Semantic search, structural search and memory search lived beside each other without guidance about when to use which. Intent metadata and routing enforcement now push semantic questions toward CocoIndex and structural questions toward the graph. Session-history questions go toward memory. Intent classification recognizes structural, semantic and hybrid intent.

&nbsp;

#### Recovery Without Hooks

Claude hooks covered only one runtime family. Other runtimes depended on the AI remembering to prime itself.

`session_bootstrap` is the canonical hookless bootstrap surface and comes with an output schema. The OpenCode transport layer and the repo-local Copilot startup wrapper extend recovery beyond hook-based runtimes.

&nbsp;

#### Portable MCP Wrapper Paths

Some checked-in MCP config surfaces drifted to absolute `/Users/...` wrapper paths. That made the JSON noisier and less portable than the rest of the repo-local setup.

The restored paths keep the configuration consistent with the workspace-relative command style used elsewhere in the project.

&nbsp;

#### A Best-Effort Save at Session End

The system had no reliable way to capture end-of-session state automatically. Stop-hook tracking now parses transcript usage data, stores metrics and estimates token spend.

&nbsp;

#### One Recovery Contract Across Runtimes

Runtime instructions, context-prime agents and bootstrap surfaces drifted apart across runtimes. Non-hook recovery is now standardized around explicit expected behaviors: ready, stale or missing structural state and the main `session_bootstrap` path.

## Hook Durability and Correctness

#### Safer Hook State and Cache

Cache races, weak temp-file handling, session-state collisions and insufficient provenance markers made the hook path fragile. The hook-state lifecycle is now tighter, with TTL checks, SHA-256 state names, restrictive file permissions, provenance fencing and stale-on-read checks.

&nbsp;

#### Graph Correctness Holes Closed

Early graph work had correctness holes: collapsed line spans, unsafe DB initialization, transaction gaps and depth leaks. The graph pipeline now has multi-line symbol spans, DB initialization guards, atomic replace operations, strict depth handling and safer handler validation.

&nbsp;

#### Parser and Classifier Repairs

The first tree-sitter and classifier pass misclassified abstract methods, class expressions, multi-import capture and nested Python class names. Repaired parser patterns and intent-classifier confidence now make the parser and routing layers match the structural expected behavior.

&nbsp;

#### Leaner Startup Highlights

Startup highlights wasted space on duplicates, vendored code and the wrong ranking signal. The rewritten highlight query uses deduplicated grouping, hard path exclusions and incoming-call ranking.

## Agent Improvement Skill

This skill works on any agent definition file and runs its evaluation and improvement as a bounded, deterministic loop.

#### Five Dimensions, Scored Deterministically

Agent prompt files had no systematic way to be evaluated. Manual review was inconsistent and could not track improvement over time.

The skill ships 8 scripts. `scan-integration.cjs` discovers all surfaces an agent touches: main, mirrors, commands, YAML and skills. `generate-profile.cjs` derives scoring from any agent's own rules. Scoring uses regex, string matching and file-existence checks.

`score-candidate.cjs` takes a `--dynamic` flag and scores across 5 weighted dimensions:

- **`structural`** weighs 0.20.
- **`ruleCoherence`** weighs 0.25.
- **`integration`** weighs 0.25.
- **`outputQuality`** weighs 0.15.
- **`systemFitness`** weighs 0.15.

&nbsp;

#### Changes Stay Proposals Until Approved

Editing main agent files directly during evaluation is dangerous: a bad change could break the agent. Candidates go to a packet-local runtime area instead. The `@agent-improver` agent is the canonical mutator, with a halt condition and merged checklists.

The command is a full rewrite and orchestrates the whole loop: scan, profile, candidate, score, benchmark, reduce and stop-check. Its benchmark is a fixture benchmark with an integration report. Promotion requires passing all evidence gates plus explicit operator approval.

&nbsp;

#### The Skill Tested on Itself

The skill had never been tested on itself, which left uncertainty about self-referential edge cases. Phase 009 ran the loop on `agent-improver.md` itself and found a real bug: a stale command path.

Phase 010 fixed that bug plus 4 reducer issues: family hardcoding, the plateau window, accepted counting and the mirror path.

&nbsp;

#### Advisor Routing and README Entries

The skill advisor had no routing for the new 5-dimension capabilities, and the root README was missing the agent-improver entries. Phase 011 added that routing, bumped the skill version to 1.0.0.0 and added Agent-Improver to the root README's Agent Network and Skills Library sections. The skill count went from 19 to 20.

## Upgrade Notes

No migration required. Both programs are additive. The code graph, hooks and bootstrap surfaces are backward compatible. The `sk-deep-agent-improvement` skill is entirely new and does not affect existing workflows. The `plateauWindow` config field defaults to 3, the same as the previous hardcoded value.

If you had custom references to `sk-recursive-agent`, update them to `sk-deep-agent-improvement`.

Full per-phase changelogs live at `.opencode/specs/system-spec-kit/024-compact-code-graph/changelog/` for 024 and `.opencode/specs/skilled-agent-orchestration/041-sk-recursive-agent-loop/changelog/` for 041.
