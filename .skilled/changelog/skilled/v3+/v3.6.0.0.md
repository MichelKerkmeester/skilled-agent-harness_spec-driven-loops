# v3.6.0.0, Harder Core, Longer Reach

v3.6.0.0 makes memory and search more trustworthy in everyday use. Both are more resilient when their supporting services fail. Search cites genuine matches again with honest confidence. It keeps answering when its semantic index is damaged. It protects memory writes from secrets and unwanted overwrites.

Five deep-loop skills now share one hub. Three terminal-driven design skills bring design judgment to the terminal. They also bring Open Design and Figma work there. Both changes are real. Neither asks anything new of you. Kimi K2.7 joins as a small-model option. Shared setup for the MCP skills comes alongside it.

Nothing changes how you call the system. `memory_search`, `memory_save`, the `/deep:*` commands and agent names behave exactly as before.

## Why This Release

Memory and search need to tell the truth about matches. The background services behind them need to recover under stress. They must do so without duplicating themselves or corrupting their data.

## What's New at a Glance

- **Scoped and shell-special-character searches return safer results.** Search applies scope correctly. It includes cold and deprecated entries when they match.
- **Search cites genuine matches again with calibrated confidence.** A 0.89 match reads as a good match. It reports real confidence.
- **Search keeps working when its semantic index is damaged.** A memory-safe keyword engine covers the gap. It does so while the damaged index is repaired.
- **Scores and ranking explanations are consistent.** Results share a 0-to-1 score. An opt-in trace shows why an item ranked where it did.
- **Memory protections cover secrets, human edits and retention.** Long-session snapshots add safeguards for continuity. Vector repair adds safeguards for damaged data.
- **All three background services reconnect to a live daemon.** They do not start a second one. Their recovery covers hung services and writer conflicts.
- **Five deep-loop skills now share one hub.** Existing `/deep:*` commands and agent names are unchanged.
- **Design work gains a judgment skill and Open Design and Figma transports.** The removed `mcp-magicpath` skill gives way to `mcp-open-design`.
- **Kimi K2.7 joins prompt craft and MCP skills share setup.** The Figma skill reaches its first stable release at 1.0.0.0.
- **Review guidance, model provenance and operating rules gain safeguards.** Review depth is configurable. The new operating rules are advisory.
- **Markdown leaves default code-graph indexing.** Maintainers can re-enable it. Search over real code stays unchanged.

## Search

Search picked up fixes across matching, result scope and damaged-index recovery. They keep results findable. They make the score and scope tell the truth.

#### Confidence Matches Reality

A genuine 0.89 match now reads as a good match. It cites its sources and reports real confidence. The confidence step had compared fusion scores against tuned thresholds. Those thresholds were tuned for cosine similarity at 0.7 and 0.4. Fusion scores cluster near 0.03, because RRF compresses them. RRF is a method that blends two ranked result lists. A resolver now reads the right score for confidence. Ranking order does not change.

&nbsp;

#### Keyword Search Uses Less Memory

When the semantic path is unavailable, keyword search packs its data tightly. It weights title and trigger matches above body text. So the right entry ranks first. A realistic warmup once spiked to 687MB. It now holds at 137MB, well under budget. Ranking is unchanged.

&nbsp;

#### Scoped Queries Return Everything

A narrow scoped query now returns the full matching set. It no longer comes back short. The keyword engine gathers all candidates first. Then it applies filters. Only then does it trim results to the requested limit.

&nbsp;

#### Scope Cannot Leak

A scoped search no longer pulls in results from outside its scope. The broaden-and-rescue path had re-queried the index without the spec-folder filter. So injected rows now have that filter applied again.

&nbsp;

#### Punctuation Stays in Queries

A `/memory:search` query with shell-special characters now resolves as typed. Quoting the query argument makes punctuation behave predictably.

&nbsp;

#### Cold Results Stay Reachable

Cold and deprecated entries flow back into keyword and trigger search. That search uses freshness-aware ranking. FSRS guides that ranking. FSRS is a spaced-repetition scheduler that scores how relevant something still is. The semantic lane fills in missing projections. So matching cold entries can appear.

&nbsp;

#### One Score Across Surfaces

Rendered results now show one score name on a plain 0-to-1 scale. It is rounded to two decimals. Older confidence values and percentages are gone from the output. So callers see the same number for the same result.

&nbsp;

#### Ranking Can Be Explained

An opt-in trace now returns a breakdown of the intermediate values behind a result's rank. An inline warning also flags when one memory contradicts or supersedes another.

## Memory Safety

These protections keep sensitive content out of search. They preserve human edits. They stop cleanup or repair from silently damaging data.

#### Secrets Stop Before Indexing

A scrubber runs before hashing, embedding and keyword indexing. It replaces API keys, tokens, bearer values and private-key blocks with typed redaction markers. If scrubbing cannot finish, the write is refused. The value is not stored in the clear.

&nbsp;

#### Human Edits Resist Overwrites

A new provenance column records where each field came from. It records whether a human or an automated writer wrote it. Automated writes skip human-authored content. A companion tagger marks automated writers. So the protection applies across them.

&nbsp;

#### Retention Respects Protected Entries

Cleanup checks an entry's tier and pinned state before deleting it. If a constitutional or critical entry reaches expiry, cleanup logs a refusal. It does not remove the entry.

&nbsp;

#### Long Sessions Refresh Continuity

An opt-in snapshot refreshes handover and continuity notes. It runs just before a long session is compacted. `SPECKIT_AUTHORED_CONTINUITY_SNAPSHOT` controls it. The flag is off by default. Startup reports what it restored.

&nbsp;

#### Damaged Vectors Rebuild Safely

The system detects, quarantines and rebuilds a damaged vector shard. A vector shard is a slice of the semantic search index. The repair survives a restart. A persisted marker and completeness check decide whether to resume repair. They also decide whether to clear a stale flag. So a corrupted slice is not silently replaced with an empty one.

## Resilient Daemons

A daemon is a background service that stays running. It answers requests over a socket. The 026 release gave these services a second way in. This release covers three failures. A connection can drop. A daemon can die. A burst of traffic can hit a limit. In each case the system recovers. It does not duplicate itself or corrupt its data. The memory and daemon work also fixes a stale-cache bug on delete. The save lock reaps only a provably dead owner. The history rebuild is wrapped in a transaction. A write carries human authorship onto its successor. The startup lock reclaims on owner death instead of waiting out a timeout.

#### Advisor Reconnects Safely

The skill-advisor launcher now recovers the way the memory and code services already do. A new session connects to the live daemon. It does not spawn a second one. A hung daemon is reaped and replaced under a lock. Previously, the launcher could reconnect on a dead socket. It then acted as if it had not. That let another session start a second writer.

&nbsp;

#### One Writer Owns the Database

A single-writer lock allows only one process to write to the same database at a time. A second writer loses the lock and exits cleanly. That protects the shared index.

&nbsp;

#### Daemons Gain Scriptable Front Doors

All three daemons expose their full tool sets as scriptable command-line clients. They do so over the existing socket. Spec-memory has 37 tools, code-index has 8 and skill-advisor has 9. These clients are additive to the normal connection. That connection stays primary. At prompt time they are read-only. Maintenance and mutation are blocked. Advisor changes require an explicit trusted flag.

&nbsp;

#### Busy Connections Have More Room

The simultaneous-connection limit rose from eight to 64. Bursts of parallel work now have more room before reaching the ceiling.

&nbsp;

#### Helper Processes Clean Up

Helper processes now exit when their input closes. They also exit when their connection drops. They also exit at a short watchdog timeout. They no longer pile up after their parent is gone. Sixteen stranded processes were cleared in the work that landed the fix.

&nbsp;

#### Launcher Defaults Align

Daemon re-election is now on by default in the launcher itself. It no longer waits for a config to enable it. Four runtime configs were brought into line. Two of them carried a JSON error that left them unparseable, and that is fixed.

&nbsp;

#### Advisor State Stays Outside Specs

The advisor keeps its working files at the repository root, out of spec folders. Run inside a packet, its workspace resolver could fall back to that packet. That could leave a stray `.state/advisor` directory there. The resolver now refuses to write inside a `specs/` subtree. Directories that had already leaked were cleaned up.

## Skills and Design

The deep loops and design tools gain shared surfaces. They keep their distinct jobs and existing user-facing commands.

#### Deep Loops Share One Hub

The deep loops had grown into five separate skills. They shared a backend and kept drifting apart. Their five public identities now live in one hub. Those identities are context, research, review, ai-council and improvement. The hub sits over a shared, frozen backend. It holds no per-mode logic. It reads the requested mode and routes to it. Each mode keeps its own behavior. Advisor routing collapsed five skill identities into one plus a mode alias. The old five-skill surface is gone. Every `/deep:*` command and agent name is unchanged. The only thing you might notice is that diagnostics now check both loop databases instead of missing one.

&nbsp;

#### Parent Skills Have a Pattern

The hub-over-modes structure is now a documented convention. `/create:sk-skill-parent` scaffolds parent skills with mode packets, a README and agent mirrors. The doc skill gained matching templates. A routing-drift check keeps the registry aligned with the code.

&nbsp;

#### Design Judgment Guides the Work

`sk-design-interface` is a standalone, Apache-2.0-only skill. It is based on Anthropic frontend-design principles. It grounds work in the live subject. It names the real-world median and deliberately departs from it. It critiques before building. Design references are read live rather than copied into the tree. The two transports are required to defer to this judgment skill.

&nbsp;

#### Open Design Builds Through Conversation

`mcp-open-design` drives the installed Open Design desktop app from the terminal. It uses its command-line tool and a small server. A run reaches a question. Your answer triggers the build. A final step writes the file. The design-judgment skill is a hard precondition. `mcp-open-design` refuses to do interface work without it. **Breaking:** The `mcp-magicpath` hosted-canvas skill was removed.

&nbsp;

#### Figma Work Uses Safer Defaults

`mcp-figma` drives Figma Desktop from the terminal. It covers install, connect, read, author and export. Read-only commands run freely. Changes ask first. Destructive commands are off by default. The connection ships safe by default through a plugin. It does not patch the app. The more invasive option is gated and paired with a rollback. An optional path supplies design context for code generation.

## Tooling and Operating Rules

#### Shared MCP Setup and Kimi

The five MCP skills now share one install guide. They also share a verify-only install script and a read-only doctor check. Kimi K2.7 joins as a small-model option with a full prompt-craft profile. Prompt-craft evaluation settled on its best prompt framework. The Figma skill reached its first stable release at 1.0.0.0. Cross-references tie both design transports to the judgment skill.

&nbsp;

#### Reviews Name Their Tradeoffs

`sk-code` review rules now require a replacement when a review recommends removing something. They use a marker for deliberate simplification. They forbid quietly cutting scope. `SK_CODE_REVIEW_DEPTH=lite|full|ultra` lets operators name the existing depth tiers. The review contract does not change.

&nbsp;

#### Model Provenance Is Checked

With `SPECKIT_PROVENANCE_CHECK=1`, the executor audit fails loudly. It fails when the model that ran differs from the one requested. A silent model swap can no longer produce a dishonest record. That holds when this check is enabled.

&nbsp;

#### Operating Discipline Is Written Down

Framework docs and constitutional rules now say four things. Confirm claims before making them. Capture a baseline before claiming no regressions. Treat findings as hypotheses until the cited code is opened. Name a rollback before irreversible work. This discipline grew out of a Fable 5 review practice. A typed agent contract backs it. That contract travels with dispatched work. Both are advisory. They never block a valid exchange.

&nbsp;

#### Code Search Leaves Prose Out

Markdown files are no longer part of default code-graph indexing. So prose docs are not treated as code nodes. A maintainer flag can re-enable them. Search over real code is unchanged.

## Internal Seams (No User-Facing Change)

#### Cleaner Seams Over the Database Layer

A five-port adapter now sits over the database layer. It adds testability and cleaner seams. No behavior changes for callers. Two graph walks had a query that defeated the index. A shared in-app traversal replaced them. The results are the same. There are fewer full scans.

&nbsp;

#### Command Routing Splits From Presentation

Command families had their routing separated from their presentation contracts. It is a structural refactor. Behavior is unchanged.

&nbsp;

#### One Seam for Runtime Dependencies

The deep-loop runtime reached into shared modules in scattered places. Those reach-ins were pulled behind one seam. Its lock reclaim and merge steps were made atomic. The runtime's contract is unchanged.

## Upgrade Notes

No migration is required for the common path.

- **Rename.** If you set `SPECKIT_SKILL_ADVISOR_HOOK_DISABLED`, rename it to `SYSTEM_SKILL_ADVISOR_HOOK_DISABLED`.
- **Switch.** Move any design work using the removed `mcp-magicpath` skill to `mcp-open-design`.

The advisor recovery fix takes effect on your next fresh session. Structural protections are on by default. Idempotency, soft-delete tombstones, the acceptance-coverage gate, completion-freshness checking, semantic trigger fallback and learning reducers remain default-off and opt-in.
