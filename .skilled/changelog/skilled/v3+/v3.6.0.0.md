# v3.6.0.0, Harder Core, Longer Reach

v3.6.0.0 makes memory and search more trustworthy in everyday use and more resilient when their supporting services fail. Search cites genuine matches again with honest confidence, keeps answering when its semantic index is damaged and protects memory writes from secrets and unwanted overwrites.

Five deep-loop skills now share one hub, and three terminal-driven design skills bring design judgment and Open Design and Figma work to the terminal. Both changes are real, but neither asks anything new of you. Kimi K2.7 joins as a small-model option, alongside shared setup for the MCP skills.

Nothing changes how you call the system: `memory_search`, `memory_save`, the `/deep:*` commands and agent names behave exactly as before.

## Why This Release

Memory and search need to tell the truth about matches, while the background services behind them need to recover under stress without duplicating themselves or corrupting their data.

## What's New at a Glance

- **Scoped and shell-special-character searches return safer results.** Search applies scope correctly and includes cold and deprecated entries when they match.
- **Search cites genuine matches again with calibrated confidence.** A 0.89 match reads as a good match and reports real confidence.
- **Search keeps working when its semantic index is damaged.** A memory-safe keyword engine covers the gap while the damaged index is repaired.
- **Scores and ranking explanations are consistent.** Results share a 0-to-1 score, with an opt-in trace showing why an item ranked where it did.
- **Memory protections cover secrets, human edits and retention.** Long-session snapshots and vector repair add safeguards for continuity and damaged data.
- **All three background services reconnect to a live daemon.** They do not start a second one, and their recovery covers hung services and writer conflicts.
- **Five deep-loop skills now share one hub.** Existing `/deep:*` commands and agent names are unchanged.
- **Design work gains a judgment skill and Open Design and Figma transports.** The removed `mcp-magicpath` skill gives way to `mcp-open-design`.
- **Kimi K2.7 joins prompt craft and MCP skills share setup.** The Figma skill reaches its first stable release at 1.0.0.0.
- **Review guidance, model provenance and operating rules gain safeguards.** Review depth is configurable and the new operating rules are advisory.
- **Markdown leaves default code-graph indexing.** Maintainers can re-enable it, while search over real code stays unchanged.

## Search

Search picked up fixes across matching, result scope and damaged-index recovery. They keep results findable and make the score and scope tell the truth.

#### Confidence Matches Reality

A genuine 0.89 match now reads as a good match, cites its sources and reports real confidence. The confidence step had compared fusion scores, which cluster near 0.03 because RRF (a method that blends two ranked result lists) compresses them, against thresholds tuned for cosine similarity at 0.7 and 0.4. A resolver now reads the right score for confidence without changing ranking order.

&nbsp;

#### Keyword Search Uses Less Memory

When the semantic path is unavailable, keyword search packs its data tightly and weights title and trigger matches above body text, so the right entry ranks first. A realistic warmup that once spiked to 687MB now holds at 137MB, well under budget, with ranking unchanged.

&nbsp;

#### Scoped Queries Return Everything

A narrow scoped query now returns the full matching set instead of coming back short. The keyword engine gathers all candidates first, applies filters and only then trims results to the requested limit.

&nbsp;

#### Scope Cannot Leak

A scoped search no longer pulls in results from outside its scope. The broaden-and-rescue path had re-queried the index without the spec-folder filter, so injected rows now have that filter applied again.

&nbsp;

#### Punctuation Stays in Queries

A `/memory:search` query containing shell-special characters now resolves as typed. Quoting the query argument makes punctuation behave predictably.

&nbsp;

#### Cold Results Stay Reachable

Cold and deprecated entries flow back into keyword and trigger search under freshness-aware ranking. FSRS (a spaced-repetition scheduler that scores how relevant something still is) guides that ranking, and the semantic lane fills in missing projections so matching cold entries can appear.

&nbsp;

#### One Score Across Surfaces

Rendered results now show one score name on a plain 0-to-1 scale, rounded to two decimals. Older confidence values and percentages are gone from the output, so callers see the same number for the same result.

&nbsp;

#### Ranking Can Be Explained

An opt-in trace now returns a breakdown of the intermediate values behind a result's rank. An inline warning also flags when one memory contradicts or supersedes another.

## Memory Safety

These protections keep sensitive content out of search, preserve human edits and prevent cleanup or repair from silently damaging data.

#### Secrets Stop Before Indexing

A scrubber runs before hashing, embedding and keyword indexing, replacing API keys, tokens, bearer values and private-key blocks with typed redaction markers. If scrubbing cannot finish, the write is refused rather than storing the value in the clear.

&nbsp;

#### Human Edits Resist Overwrites

A new provenance column records whether each field came from a human or an automated writer. Automated writes skip human-authored content, and a companion tagger marks automated writers so the protection applies across them.

&nbsp;

#### Retention Respects Protected Entries

Cleanup checks an entry's tier and pinned state before deleting it. If a constitutional or critical entry reaches expiry, cleanup logs a refusal instead of removing it.

&nbsp;

#### Long Sessions Refresh Continuity

An opt-in snapshot, controlled by `SPECKIT_AUTHORED_CONTINUITY_SNAPSHOT`, refreshes handover and continuity notes just before a long session is compacted. The flag is off by default, and startup reports what it restored.

&nbsp;

#### Damaged Vectors Rebuild Safely

The system detects, quarantines and rebuilds a damaged vector shard (a slice of the semantic search index), and the repair survives a restart. A persisted marker and completeness check determine whether to resume repair or clear a stale flag, so a corrupted slice is not silently replaced with an empty one.

## Resilient Daemons

A daemon is a background service that stays running and answers requests over a socket. The 026 release gave these services a second way in. This release makes sure that when a connection drops, a daemon dies or a burst of traffic hits a limit, the system recovers instead of duplicating itself or corrupting its data. The memory and daemon work also fixes a stale-cache bug on delete, makes the save lock reap only a provably dead owner, wraps the history rebuild in a transaction, makes a write carry human authorship onto its successor and lets the startup lock reclaim on owner death instead of waiting out a timeout.

#### Advisor Reconnects Safely

The skill-advisor launcher now recovers the way the memory and code services already do: a new session connects to the live daemon instead of spawning a second one, and a hung daemon is reaped and replaced under a lock. Previously, the launcher could reconnect on a dead socket and then act as if it had not, allowing another session to start a second writer.

&nbsp;

#### One Writer Owns the Database

A single-writer lock allows only one process to write to the same database at a time. A second writer loses the lock and exits cleanly, protecting the shared index.

&nbsp;

#### Daemons Gain Scriptable Front Doors

All three daemons expose their full tool sets as scriptable command-line clients over the existing socket: 37 tools for spec-memory, 8 for code-index and 9 for skill-advisor. These clients are additive to the normal connection, which stays primary. At prompt time they are read-only, maintenance and mutation are blocked, and advisor changes require an explicit trusted flag.

&nbsp;

#### Busy Connections Have More Room

The simultaneous-connection limit rose from eight to 64. Bursts of parallel work now have more room before reaching the connection ceiling.

&nbsp;

#### Helper Processes Clean Up

Helper processes now exit when their input closes, their connection drops or a short watchdog timeout is reached. They no longer pile up after their parent is gone. Sixteen stranded processes were cleared in the work that landed the fix.

&nbsp;

#### Launcher Defaults Align

Daemon re-election is now on by default in the launcher itself instead of only when a config enables it. Four runtime configs were brought into line, including a fix for the two configs that carried a JSON error that left them unparseable.

&nbsp;

#### Advisor State Stays Outside Specs

The advisor keeps its working files at the repository root, out of spec folders. When run inside a packet, its workspace resolver could fall back to that packet and leave a stray `.state/advisor` directory there. The resolver now refuses to write inside a `specs/` subtree, and directories that had already leaked were cleaned up.

## Skills and Design

The deep loops and design tools gain shared surfaces while keeping their distinct jobs and existing user-facing commands.

#### Deep Loops Share One Hub

The deep loops had grown into five separate skills that shared a backend and kept drifting apart. Their five public identities (context, research, review, ai-council and improvement) now live in one hub over a shared, frozen backend. The hub holds no per-mode logic: it reads the requested mode and routes to it, and each mode keeps its own behavior. Advisor routing collapsed five skill identities into one plus a mode alias, and the old five-skill surface is gone. Every `/deep:*` command and agent name is unchanged. The only thing you might notice is that diagnostics now check both loop databases instead of missing one.

&nbsp;

#### Parent Skills Have a Pattern

The hub-over-modes structure is now a documented convention, and `/create:sk-skill-parent` scaffolds parent skills with mode packets, a README and agent mirrors. The doc skill gained matching templates, and a routing-drift check keeps the registry aligned with the code.

&nbsp;

#### Design Judgment Guides the Work

`sk-design-interface` is a standalone, Apache-2.0-only skill based on Anthropic frontend-design principles. It grounds work in the live subject, names the real-world median and deliberately departs from it, and critiques before building. Design references are read live rather than copied into the tree, and the two transports are required to defer to this judgment skill.

&nbsp;

#### Open Design Builds Through Conversation

`mcp-open-design` drives the installed Open Design desktop app from the terminal through its command-line tool and a small server. A run reaches a question, your answer triggers the build and a final step writes the file. The design-judgment skill is a hard precondition, and `mcp-open-design` refuses to do interface work without it. **Breaking:** The `mcp-magicpath` hosted-canvas skill was removed.

&nbsp;

#### Figma Work Uses Safer Defaults

`mcp-figma` drives Figma Desktop from the terminal for install, connect, read, author and export. Read-only commands run freely, changes ask first and destructive commands are off by default. The connection ships safe by default through a plugin without patching the app, while the more invasive option is gated and paired with a rollback. An optional path supplies design context for code generation.

## Tooling and Operating Rules

#### Shared MCP Setup and Kimi

The five MCP skills now share one install guide, a verify-only install script and a read-only doctor check. Kimi K2.7 joins as a small-model option with a full prompt-craft profile, and prompt-craft evaluation settled on its best prompt framework. The Figma skill reached its first stable release at 1.0.0.0, and cross-references tie both design transports to the judgment skill.

&nbsp;

#### Reviews Name Their Tradeoffs

`sk-code` review rules now require a replacement when a review recommends removing something, use a marker for deliberate simplification and forbid quietly cutting scope. `SK_CODE_REVIEW_DEPTH=lite|full|ultra` lets operators name the existing depth tiers without changing the review contract.

&nbsp;

#### Model Provenance Is Checked

With `SPECKIT_PROVENANCE_CHECK=1`, the executor audit fails loudly when the model that ran differs from the one requested. A silent model swap can no longer produce a dishonest record when this check is enabled.

&nbsp;

#### Operating Discipline Is Written Down

Framework docs and constitutional rules now say to confirm claims before making them, capture a baseline before claiming no regressions, treat findings as hypotheses until the cited code is opened and name a rollback before irreversible work. This discipline grew out of a Fable 5 review practice and is backed by a typed agent contract that travels with dispatched work. Both are advisory and never block a valid exchange.

&nbsp;

#### Code Search Leaves Prose Out

Markdown files are no longer part of default code-graph indexing, so prose docs are not treated as code nodes. A maintainer flag can re-enable them, and search over real code is unchanged.

## Internal Seams (No User-Facing Change)

#### Cleaner Seams Over the Database Layer

A five-port adapter now sits over the database layer for testability and cleaner seams. No behavior changes for callers. Two graph walks whose query defeated the index were replaced by a shared in-app traversal. The results are the same and there are fewer full scans.

&nbsp;

#### Command Routing Splits From Presentation

Command families had their routing separated from their presentation contracts. It is a structural refactor with unchanged behavior.

&nbsp;

#### One Seam for Runtime Dependencies

The deep-loop runtime's scattered reach-ins into shared modules were pulled behind one seam, and its lock reclaim and merge steps were made atomic. The runtime's contract is unchanged.

## Upgrade Notes

No migration is required for the common path.

- **Rename.** If you set `SPECKIT_SKILL_ADVISOR_HOOK_DISABLED`, rename it to `SYSTEM_SKILL_ADVISOR_HOOK_DISABLED`.
- **Switch.** Move any design work using the removed `mcp-magicpath` skill to `mcp-open-design`.

The advisor recovery fix takes effect on your next fresh session. Structural protections are on by default, while idempotency, soft-delete tombstones, the acceptance-coverage gate, completion-freshness checking, semantic trigger fallback and learning reducers remain default-off and opt-in.
