This release improves ranking precision, recall coverage, result diversity and operational observability across the hybrid RAG fusion pipeline. Ten optimizations target specific retrieval bottlenecks and quality gaps, with each finding implemented by a dedicated GPT-5.4 agent.

> Spec folder: `.opencode/specs/system-spec-kit/023-hybrid-rag-fusion-refinement/007-hybrid-search-null-db-fix/` (Level 2)

## Why This Release

A 10-iteration deep research investigation drove this Phase 4 work, with the goal of making the workflow easier to follow and easier to trust.

---

## What's New at a Glance

- **Reciprocal rank fusion now uses a constant of k=40.** This replaces the setting designed for much larger corpora.
- **The L2 response budget rises from 1500 to 2500 tokens.** The larger allowance returns more search matches.
- **FTS5 text search now excludes deprecated memories.** Lexical results follow the same exclusion as vector results.
- **R12 embedding expansion now includes three-token queries.** Technical searches such as "mcp runtime hardening" can receive expansion.
- **Multi-word searches now include exact-phrase matching.** Searches like "spec kit" can favor documents containing the phrase.
- **Reranking metadata now identifies the provider.** Search traces distinguish cross-encoder, local GGUF and fallback sort.
- **Co-activation accepts scalar and object references.** Scalar references use similarity 50.
- **Search scores zero-quality candidates automatically.** `computeBackfillQualityScore()` is also available to maintenance scripts.
- **Chunk creation records each child's `parent_id`.** This connects child chunks to their parent memory.
- **The embedding cache now reports hit and miss statistics.** The statistics include hits, misses and hit rate.
- **Shadow evaluation replay no longer fixes `minState` to `WARM`.** This addresses empty result sets in replay-based evaluation and monitoring.
- **Tool schema tests match the simplified schemas.** Their assertions follow the removal of `oneOf` and `not` for Claude compatibility.

## Search Ranking and Response Size

#### Ranking Fits the Corpus

The previous reciprocal rank fusion smoothing constant, k=60, was designed for corpora with 10,000 or more documents. Its score difference between rank 1 and rank 10 was only 0.002, essentially flat. For a 999-memory database, the new setting doubles that separation to 0.004, making top results meaningfully distinguishable from lower-ranked ones.

&nbsp;

#### More Matches Fit

The old 1500-token response budget often truncated results to one match out of seven or more. The 2500-token budget accommodates the p95 memory content length, so users see three to five results instead of one.

---

## Recall and Coverage

#### Deprecated Memories Stay Out

Vector search excluded 538 deprecated-tier memories while FTS5 text search did not. That mismatch let deprecated content leak into results through the lexical path, so FTS5 received the same exclusion filter.

&nbsp;

#### Three-Token Queries Expand

R12 embedding expansion broadens search by finding related terms from the embedding space. Its gate previously suppressed queries with three or fewer tokens, blocking useful technical searches such as "mcp runtime hardening". The threshold moved from ≤3 to ≤2, allowing three-token queries through.

&nbsp;

#### Exact Phrases Match

A search for "spec kit" previously matched documents containing "spec" or "kit" separately. FTS5 now adds the quoted phrase query `"spec kit"` to boost exact-phrase matches.

---

## Reranking and Diversity

#### Reranking Paths Are Visible

Metadata previously reported only `rerankApplied: true/false` without identifying which reranker ran. The `rerankProvider` field records the actual path, making search traces and ablation studies trustworthy.

---

## Data Quality

#### Co-Activation Reads Both Formats

The co-activation parser expected `related_memories` entries in object form such as `[{id: 39}]`, but the database stores scalar arrays such as `[39]`. The parser silently failed, so co-activation never contributed to search results. It now accepts both formats. Scalar entries previously received a similarity of 0.5. Since boosts divide the 0-100 scale by 100, this produced `0.5/100 = 0.005`, two orders of magnitude weaker than intended. Scalar entries now receive 50 to match that scale.

&nbsp;

#### Zero Scores Get Backfilled

Index-scan ingestion bypassed the quality gate, leaving 520 of 1002 memories, or 52%, with a quality score of 0.0. `computeBackfillQualityScore()` scores content length, trigger phrases, title presence and importance tier. It is available for maintenance scripts and runs during search when a candidate has `quality_score === 0`.

&nbsp;

#### Chunks Keep Their Parent

Child chunks previously lacked their parent memory ID when memories were split into smaller pieces. This broke run history traversal and made chunks appear as orphans. Chunk creation now propagates `parent_id`.

---

## Observability

#### Cache Performance Is Measurable

The embedding cache had no counters, making its effectiveness impossible to measure. It now exposes `cacheHits` and `cacheMisses`, while `getCacheStats()` returns `{hits, misses, hitRate}`.

---

## Operational Reliability

#### Replay Uses Search Results

Interactive handlers were fixed, but shadow evaluation replay still fixed `minState: 'WARM'`. That left shadow evaluation, adaptive feedback and replay-based monitoring evaluating empty result sets, so the fixed value was removed.

&nbsp;

#### Schema Tests Follow the Simplification

- The schema simplification, which removed `oneOf` and `not` for Claude compatibility, had broken expected-behavior tests. Their assertions now match the current schema.
