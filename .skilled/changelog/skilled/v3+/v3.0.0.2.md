## Spec Document Indexing

All four indexing gates now warn on spec documents. Logged concerns no longer block indexing.

#### Spec Documents Reach Indexing <a id="c-spec-documents-reach-indexing"></a>

- The quality gate for saving memories has four checkpoints, in order.
- Validation rules check for required formatting.
- Sufficiency checks for meaningful content.
- Template expected behavior checks for expected template structure.
- Metadata checks for required fields such as trigger phrases.
- The v3.0.0.1 release fixed the metadata check.
- But the three earlier checks were still rejecting spec documents before they reached it.
- So 1,807 spec documents were still being rejected.
- All four checkpoints now log concerns without blocking spec-document indexing.
- Memory files continue to be fully validated through all four checkpoints.

&nbsp;

## Memory Commands

`/memory:analyze` and `/memory:shared` no longer stand alone.

#### Search and Manage Absorb Commands <a id="c-search-and-manage-absorb-commands"></a>

> [!WARNING]
> Update workflows or scripts using `/memory:analyze` to use `/memory:search`. Update those using `/memory:shared` to use `/memory:manage shared`.

- Two of the five separate memory commands overlapped significantly.
- They were merged.
- The resulting four commands are:
- `/memory:search` is the single command for finding and analyzing memories.
- It also runs evaluations, explores causal graphs and views learning history.
- It incorporates `/memory:analyze` and covers 33 tools.
- `/memory:manage` handles database maintenance, the shared-memory lifecycle, checkpoints and bulk operations.
- Its `shared` section covers creating shared spaces, managing memberships and checking status.
- It replaces `/memory:shared`.
- `/memory:save` saves conversation context to memory.
- `/memory:learn` creates and manages constitutional memories.
- These are always-present rules.

Rebuild and restart the MCP server, then verify indexing.

#### Before You Start <a id="c-before-you-start"></a>

1. Rebuild the MCP server. Run `npm run build` in `mcp-server/`.
2. Restart the MCP server.
3. Verify indexing. Run `memory_index_scan({ force: true })` to verify that 0 spec documents are rejected.
