This release expands System Spec Kit in three directions at once. Packet-local nested changelog generation is now a shipped workflow. Packet history no longer depends on hand-written one-offs. The `session_bootstrap` recovery behavior was fixed after review. Its structural safeguards were fixed too. The deep-research and deep-review command surfaces now sit on executable contracts. Those contracts are parity-tested.

It also records the approved Codex command-discoverability direction from Packet 039.

## Why This Release

The goal is to make the System Spec Kit workflow easier to trust in everyday use. This release captures the recovery fixes at the System Spec Kit level. That is because they change the public recovery contract. They also change the reliability of structural startup context. The research and review work matters here because command assets, runtime mirrors and contract tests now live on explicit executable rules. They no longer rest on documentation-only alignment.

---

## What's New at a Glance

- **Spec Kit now ships a nested changelog generator.** Root packets and direct child phases now have a canonical place. That place holds chronological completion history beside their implementation summaries.
- **Packet-aware closeout now teaches one consistent behavior.** Closeout means an implementation summary plus a nested packet changelog.
- **`session_bootstrap` now returns a real `nextActions` payload.** Its tool schema documents the full output shape.
- **The 500-token structural startup ceiling is now enforced in code.** Startup structural context stays bounded.
- **Claude stop-hook autosave now preserves validated active-session state.** Ambiguous transcript-only matches are no longer treated as authoritative.
- **Focused Vitest suites now guard the deep-research and deep-review contracts.** Drift between docs, command assets and runtime mirrors shows up quickly.
- **Deep-review uses main `deep-review-*` artifact names across its live behavior.** Legacy `deep-research-*` names are limited to the intentional scratch migration path.
- **Codex command discoverability has an approved direction.** `references/workflows/quick-reference.md` is the primary command surface. `SKILL.md` remains pointer-only.

## Packet Changelogs

#### One Generator, Two Output Paths

Packet-local changelogs already existed in some specs. But there was no main generator and no approved naming rule. No single workflow explained how root packets and phase folders should produce those files. The new generator detects its target. The target is either a packet root or a direct child phase. Root output writes to `changelog/changelog-<packet>-root.md`. Phase output writes to the parent packet as `changelog/changelog-<packet>-<phase-folder>.md`.

&nbsp;

#### Templates That Define Packet History

Some places were already creating packet changelog files. The repo still lacked main templates for what those files should contain. It also lacked documentation for how they relate to `implementation-summary.md`. Dedicated root and phase changelog templates were added. A workflow reference was added too. It explains the evidence stack, the output paths and the packet-local intent. Packet changelogs are now explicitly documented as additive to `implementation-summary.md`. They are not a replacement for it.

&nbsp;

#### Closeout Commands Speak With One Voice

`/create:changelog`, `/spec_kit:implement` and `/spec_kit:complete` could not speak consistently about packet-local history. That would happen if the generator, templates and workflow docs were updated in isolation. All three command surfaces were updated in the same pass. The shipped generator now handles root and phase naming instead of manual improvisation.

## Recovery

Packet 029 closed the open review findings on the Compact Code Graph and recovery surfaces.

#### Bootstrap Output Matches Its Docs

The public `session_bootstrap` behavior already described recommended next actions. But the handler did not return them. The docs and the implementation were telling slightly different truths. The recovery surface no longer depends on readers inferring behavior from docs. The handler itself did not fulfill those docs.

&nbsp;

#### A Startup Budget Enforced in Code

The structural startup behavior documented the ceiling. But the limit was still advisory. It was not enforced in the shared builder. Now that the shared structural bootstrap builder applies it as code, startup structural context is truthful. It is consistent with the packet docs that promised a hard ceiling.

&nbsp;

#### Safer Provenance and Autosave Targeting

Compact recovery and autosave still had ambiguity at two risky points. Recovered text could appear without the shared provenance fence. Transcript-tail packet detection could promote uncertain scope matches into autosave targets. Compact recovery now wraps recovered text with the shared provenance fence. Autosave now retargets only when transcript evidence clearly shows a new unambiguous packet.

&nbsp;

#### Agent Copies and Packet Docs Agree

The implementation fixes alone were not enough. The recovery story also needed two things to reflect the bootstrap-first behavior and the shipped closeout state. Those were the runtime-facing agent copies and the packet documentation. Claude and Codex `context-prime` definitions now include the explicit Structural Context guidance. The OpenCode version already had it. The related Packet 024 root and phase docs were refreshed. Now the shipped evidence, phase map and recovery behavior tell the same story.

## Research and Review Contracts

Packet 040 (`.opencode/specs/skilled-agent-orchestration/040-sk-auto-deep-research-review-improvement/`) brought both autonomous workflows onto one stronger contract model.

#### One Packet Model for Deep Research

The deep-research workflow still relied on scattered wording. That wording covered run history, lifecycle branches, reducer ownership, packet artifacts and runtime parity. That made its behavior easier to drift and harder to audit. Deep-research now has main run history fields, lifecycle modes and reducer-owned outputs. It also has runtime capability surfaces and executable helpers. The workflow YAML, skill docs, runtime mirrors and packet-closeout rules all point at the same packet model.

&nbsp;

#### Deep-Review Schemas You Can Verify

Deep-review still mixed `deep-research-*` and `deep-review-*` naming. That naming ran across docs, assets and workflow surfaces. Its release-readiness and reducer schemas were also easier to describe than to verify. Deep-review now exposes explicit lifecycle, reducer, severity and release-readiness schemas across its behavior surfaces.

&nbsp;

#### Tests That Catch Contract Drift

Deep-research and deep-review could drift back out of sync without targeted tests. They could still look plausible on manual inspection. The new suites live in the System Spec Kit scripts workspace. For deep-research they cover parity plus reducer idempotency. For deep-review they cover parity plus reducer and readiness schemas. That keeps both behaviors executable.

&nbsp;

#### Runtime Mirrors Move Together

Autonomous workflow instructions can silently diverge across OpenCode, Claude, Codex and compatibility wrappers. That happens when each runtime surface is patched separately. Packet 040 synchronized all runtime mirrors for both deep-research and deep-review in one pass. Lifecycle vocabulary, reducer-owned surfaces and packet file expectations now move together. They no longer fragment by runtime.

## Codex Command Direction

Packet 039 (`.opencode/specs/skilled-agent-orchestration/039-cmd-spec-kit-codex-skill-routing/`) is not a downstream quick-reference implementation release. Its direction covers how Codex-specific command discoverability should be handled. That handling sits inside the System Spec Kit documentation surfaces.

#### Both Truths Kept on Record

The original research recommendation was a narrow four-command shortlist. The user later approved a broader all-commands short-list direction. Without a packet update, the record could imply only one of those truths. Packet 039 now preserves the original four-command recommendation. It also records the approved all-commands short-list override. The downstream implementation target stays explicit. Keeping `SKILL.md` pointer-only avoids duplicating the command matrix. It also avoids reintroducing drift.
