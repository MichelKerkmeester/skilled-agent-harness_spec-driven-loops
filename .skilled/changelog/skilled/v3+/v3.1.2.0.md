# Skilled v3.1.2.0

This release completes the full ESM module compliance migration for the Spec Kit workspace.

- `@spec-kit/shared` and `@spec-kit/mcp-server` move from CommonJS to native ESM.
- `@spec-kit/scripts` keeps CommonJS with proven interop.

The release also hardens the memory save pipeline.

- It fixes the MCP schema that blocked Copilot CLI.
- It eliminates every test skip and failure.

A deep code review by GPT-5.4 agents then found 18 more issues.

- The migration itself missed them.
- This release fixes all of them.
- The work ran in six phases.

&nbsp;

## Why This Release

The goal is to make the workflow easier to follow and easier to trust.

## Native ESM Packages

#### Shared Package Emits Real ESM <a id="c-shared-package-emits-real-esm"></a>

- The shared package had no `"type": "module"` declaration.
- It inherited the root CommonJS compiler baseline.
- It had 48 relative imports without the `.js` extension specifiers that Node ESM requires.
- So it emitted CommonJS output, even though its source used ESM-style import syntax.
- `@spec-kit/shared` and `@spec-kit/mcp-server` declare `"type": "module"`.
- Both compile with `module: "nodenext"` and `verbatimModuleSyntax: true`.
- All 48 imports now use `.js` specifiers.
- `config.ts` and `paths.ts` use `import.meta.dirname` in place of `__dirname`.
- The build script runs `tsc --build` instead of a no-op echo.
- `engines` moves to `>=20.11.0` for `import.meta.dirname` support.

#### 839 Server Imports Made ESM-Safe <a id="c-839-server-imports-made-esm-safe"></a>

- The mcp_server package had 839 relative import and export statements without `.js` extensions.
- That made them invalid under Node ESM resolution.
- It also lacked `"type": "module"`.
- It inherited the root CommonJS compiler settings.
- All 839 extensionless imports across 181 files are rewritten.
- Five parallel GPT-5.4 codex agents did the rewrite.
- Each got an exclusive directory scope to prevent file conflicts.

#### CommonJS Leftovers Replaced for ESM <a id="c-commonjs-leftovers-replaced-for-esm"></a>

- Sixteen production files used `__dirname`, `__filename` or the bare require helper.
- None of these are available in native ESM modules.
- Across 8 files, `__dirname` and `__filename` become `import.meta.dirname` and `import.meta.filename`.
- Eleven require helper calls in 6 files become lazy function-scoped `await import()` calls.
- Those files are archival-manager, tier-classifier, composite-scoring, file-watcher, errors/core and handlers/index.
- `ground-truth-data.ts` imported a `.json` file without the `type: "json"` import attribute.
- NodeNext requires it.
- That JSON import now carries `with { type: 'json' }`.

#### Imports Respect Package Boundaries <a id="c-imports-respect-package-boundaries"></a>

- The `package.json` exports map used `"./*": "./dist/*.js"` wildcards.
- Those exposed internal modules like `lib/search/hybrid-search.js` through the package boundary.
- Explicit entries replace those wildcards.
- `@spec-kit/mcp-server` exports only `./api` and `./api/*`.
- Internal modules no longer resolve through the package name.
- `core/config.ts` imported `../../shared/paths.js` by relative filesystem path.
- That bypassed the expected behavior of the `@spec-kit/shared` package exports.
- It now imports `@spec-kit/shared/paths` instead.

## Scripts Interop and Memory Save

#### CommonJS Scripts Load the ESM Packages <a id="c-commonjs-scripts-load-the-esm-packages"></a>

- The shared and mcp_server packages became ESM.
- Then the CommonJS scripts package could no longer load them with the require helper.
- Top-level `await` in 5 mcp_server modules blocked Node's native CommonJS-to-ESM bridge.
- Node 25's native `require(esm)` connects the CommonJS scripts to the ESM packages.
- No explicit interop helpers are needed.
- The top-level `await import()` calls in archival-manager, tier-classifier, composite-scoring, file-watcher and errors/core are converted back to lazy function-scoped imports.

#### Child Phase Folders Count as Same Spec <a id="c-child-phase-folders-count-as-same-spec"></a>

- The V8 quality rule blocked memory saves that referenced child phase folder names like `001-shared-esm-migration`.
- It treated them as foreign spec contamination, even though they belong to the same parent spec.
- The extract allowed spec ids helper in `validate-memory-quality.ts` now scans the spec folder.
- It looks for `NNN-*` subdirectories that contain `spec.md`.
- It adds them to the allowed set.
- `related_specs` frontmatter also gains allowlist support.

#### A Fallback for Manual Saves <a id="c-a-fallback-for-manual-saves"></a>

- During the ESM migration, `generate-context.js` broke.
- That is because the scripts-to-mcp_server runtime chain crashed on CommonJS globals in ESM output.
- The sufficiency validator blocked manual memory saves via MCP, with primary evidence at 0.
- No fallback existed.
- `memory-save.ts` now adds a manual-fallback source classification.
- It allows the write with deferred indexing when support evidence is at least 3.
- Anchors must be at least 1.
- `markdown-evidence-builder.ts` is expanded.
- It now parses primary evidence from the `Key Decisions`, `Next Steps`, `Outcomes` and `Implementation State` sections.

#### Workflow No Longer Hard-Depends on the Server <a id="c-workflow-no-longer-hard-depends-on-the-server"></a>

- `workflow.ts` had a top-level runtime import of `retryManager` from `@spec-kit/mcp-server/api/providers`.
- That created a hard dependency.
- It crashes when mcp-server is mid-migration.
- A lazy adapter replaces it.
- The adapter imports the module dynamically.
- It falls back to a no-op implementation with a warning when the module is unavailable.

#### Validation Bypass Raises a Warning <a id="c-validation-bypass-raises-a-warning"></a>

- When the scripts validator module failed to load, the v-rule bridge returned `null`.
- That made `memory-save.ts` silently skip all quality validation.
- Saves proceeded without any V-rule enforcement.
- The bridge now returns a structured `{valid: true, _unavailable: true}` signal.
- It gains the is vrule bridge available helper.
- `memory-save.ts` detects the flag and adds a warning to the response.

#### Search Weights Found in ESM Builds <a id="c-search-weights-found-in-esm-builds"></a>

- `vector-index-store.ts` resolved `search-weights.json` under `SERVER_DIR/configs/`.
- In ESM mode `SERVER_DIR` points to `dist/` through `import.meta.dirname`.
- The config file only exists at the package root, not in `dist/`.
- Path resolution now falls back.
- It tries `dist/configs/` first, then `../configs/` at the package root.

## Schemas and Code Standards

#### Schemas That Copilot CLI Accepts <a id="c-schemas-that-copilot-cli-accepts"></a>

- Four MCP tool schemas used `.superRefine()`.
- They are `shared_space_upsert`, `shared_space_membership_set`, `shared_memory_status` and `memory_search`.
- That call generates `oneOf` and `anyOf` in JSON Schema output.
- GPT's function calling API rejects schemas with these constructs at the top level.
- That completely blocked Copilot CLI from connecting to the MCP server.
- Exported tool schemas no longer use `.superRefine()` or `z.union()`.
- The validation logic moves into the handlers.
- The runtime checks such as `validateCallerAuth` and handler-level guards already existed there.
- `.describe()` hints now guide AI callers.

#### Lazy Imports Aligned to sk-code-skilled <a id="c-lazy-imports-aligned-to-sk-code-skilled"></a>

- Lazy import patterns introduced during the ESM migration had inconsistent error handling.
- Some swallowed errors silently.
- Others used unsafe type casts.
- One used `import.meta.url` in a CommonJS context.
- Composite-scoring and errors/core now log an immediate `console.warn` in their catch blocks.
- Memory-save and tier-classifier drop their unsafe double-casts.
- The CommonJS `workflow.ts` goes from `import.meta.url` back to `__dirname`.
- The CommonJS validate-memory-quality goes from an ESM import of `js-yaml` back to the require helper.

#### READMEs Describe the ESM Setup <a id="c-readmes-describe-the-esm-setup"></a>

- The shared, mcp_server, scripts, system-spec-kit workspace and handlers READMEs now carry accurate `type: "module"`, NodeNext and CommonJS interop descriptions.
- Their troubleshooting commands are ESM-compatible.

## Deep Review Fixes

The review's findings split into 14 required fixes and 4 improvements. They cover runtime correctness, security, reliability and performance. Four parallel workstreams carried the fixes.

#### Safe to Import the Server Package <a id="c-safe-to-import-the-server-package"></a>

- `import '@spec-kit/mcp-server'` called the main helper unconditionally.
- Any module that imported the package for its exports would also start a full MCP server process.
- This made the package unsafe to import in test setups or tooling.
- The main helper in `context-server.ts` now sits behind an entrypoint check.
- That check compares `import.meta.url` against `process.argv[1]`.

#### Two ESM Wrapper Scripts Fixed <a id="c-two-esm-wrapper-scripts-fixed"></a>

- `map-ground-truth-ids.ts` and `reindex-embeddings.ts` still referenced `__dirname`.
- It does not exist in native ESM.
- Running either script would throw a `ReferenceError`.
- Both files now use `import.meta.dirname` instead.

#### One Node Floor for Every Package <a id="c-one-node-floor-for-every-package"></a>

- The root, shared, mcp_server and scripts packages each declared different `engines.node` floors.
- The ESM migration requires Node 20.11.0+.
- Not all packages enforced this.
- All four `package.json` files now declare `engines.node >= 20.11.0`.

#### Shared Root Export Points at the Index <a id="c-shared-root-export-points-at-the-index"></a>

- `shared/package.json` had its root export pointing at `dist/embeddings.js` instead of `dist/index.js`.
- Anyone importing `@spec-kit/shared` without a subpath got the embeddings module.
- They did not get the full public surface.
- The root export now points at `dist/index.js`.
- A separate `./embeddings` subpath export is added.

#### Unverified Admin Identity Gets Logged <a id="c-unverified-admin-identity-gets-logged"></a>

- Admin operations like creating shared spaces accepted `actorUserId` and `actorAgentId` directly from the request payload.
- A malicious caller could supply any identity.
- That caller could then perform admin actions on spaces they should not control.
- A trusted-transport warning now logs when caller-supplied identity is used without session binding.
- Full enforcement is documented as a future requirement.

#### The Validation Bridge Fails Closed <a id="c-the-validation-bridge-fails-closed"></a>

- When `scripts/dist/memory/validate-memory-quality.js` was not built, the V-rule bridge returned a successful "unavailable" result.
- Saves would succeed without any quality validation.
- The bridge now returns a failure result that blocks the save.
- It surfaces a clear "build scripts first" error.
- Development workflows can opt out through the `SPECKIT_VRULE_OPTIONAL` environment variable.

#### Paths Bounded by the Workspace Root <a id="c-paths-bounded-by-the-workspace-root"></a>

- The path resolver in `shared/paths.ts` walked up the directory tree looking for a `package.json`.
- It had no upper bound, so running from an unexpected working directory could resolve the database path outside the workspace.
- The new find nearest spec kit workspace root helper finds the monorepo root by its `workspaces` array.
- Paths outside this boundary trigger a fallback to `import.meta.dirname`-relative resolution.

#### Duplicate Checks Stay in Scope <a id="c-duplicate-checks-stay-in-scope"></a>

- The duplicate content check queried by content hash.
- It did not filter by tenant, user, agent or shared-space scope.
- In a multi-tenant database, this could flag a memory as "duplicate" based on another tenant's data.
- The dry-run response also leaked cross-scope metadata.
- The duplicate query now threads governed scope into its WHERE clause.
- Responses redact cross-scope metadata.

#### Typed Warnings for Failed File Writes <a id="c-typed-warnings-for-failed-file-writes"></a>

- A memory could save to the database while the file write failed.
- The warning was lumped into "anchor issues."
- Callers could not distinguish cosmetic anchor warnings from genuine data divergence.
- Warnings now carry typed categories.
- File-persistence failures use a `[file-persistence-failed]` prefix.
- That prefix is exposed as a separate category in `typedWarnings`.

#### One Error Pattern for Dynamic Imports <a id="c-one-error-pattern-for-dynamic-imports"></a>

- `workflow.ts` had three call sites dynamically importing `@spec-kit/mcp-server/api`.
- Each had a different error-handling pattern.
- One silently returned null.
- Another logged a warning.
- The third threw.
- A single try import mcp api helper now serves all three.
- It logs the failure reason and returns null.
- `mcp-server/api/index.ts` also gains barrel width documentation.

#### Search Resolves Its Import Once <a id="c-search-resolves-its-import-once"></a>

- `vector-index-store.ts` used `await import(...)` inside frequently called methods.
- Each search re-resolved the module specifier at runtime.
- A module-level cached lazy loader now resolves the import once.
- It caches the result.

#### Help Text Without the Database <a id="c-help-text-without-the-database"></a>

- `cli.ts` imported all command dependencies at the top level.
- Running `--help` loaded the database, vector index and checkpoint system.
- That happened before printing usage text.
- `--help` and `--version` exit immediately.
- They no longer load the database stack first.
- The heavy imports now wait behind per-command handler functions.

## Upgrade Notes

No migration required. Node.js `>=20.11.0` is now the minimum engine version, up from `>=18.0.0`. All existing runtime behavior is preserved.

- The change is in how the packages are loaded.
- They load as native ESM instead of CommonJS wrappers.

- In production, the validation module should always be built.
