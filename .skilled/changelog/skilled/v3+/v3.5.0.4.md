# v3.5.0.4, The Deferred Lifecycle, Closed

This release closes the owner/daemon lifecycle root causes that v3.5.0.2 deferred. It stops the disposal flap. It ships the five deferred hardening items. It lets the shared daemon outlive its owning session. Last, the operator-facing docs were brought into line with all of it.

A two-model investigation (Opus 4.8 + gpt-5.5) converged and found the still-active flap. Three independent models cross-validated the result. They were a Claude subagent, gpt-5.5-fast via cli-opencode and gpt-5.5 via cli-codex. They caught two real bugs the first pass missed.

The v3.5.0.3 slot belongs to the separate skill-README standardization release. This daemon-reliability work takes v3.5.0.4. It spans the spec packets `017` through `028`.

## Why This Release

v3.5.0.2 fixed the inert session-cleanup hook. It said plainly that this was not the whole story. The flap was still active. When the owning session disposed, every session bridged to that shared daemon lost its transport.

## What's New at a Glance

- **The relaunch timer re-checks before it respawns.** A launcher that is shutting down releases the lease and exits. So does one that has lost its owning runtime. Neither starts a daemon under a dying session.
- **The launcher keeps a persistent log.** `log()` also appends a bounded line on disk. So a flap or disposal race is attributable even when the host drops stderr.
- **A busy owner is no longer reaped as dead.** A sibling reaps and respawns only after N consecutive deep-probe failures. So an owner mid-FTS-merge no longer turns into a duplicate daemon.
- **The Stop hook can sweep ownerless MCP daemons.** It covers the case where no session pid is available. It is flag-gated.
- **Daemon re-election is on by default.** Concurrent sessions keep their MCP transport when the owning session disposes.
- **A cold start no longer spawns a second daemon.** A fresh session after disposal had reclaimed the stale lease. It had started a second writer on the same database.
- **Fresh sessions adopt a warm daemon instead of reaping it.** A stale-lease reclaim also moved under the respawn lock.
- **A wedged sidecar no longer lingers.** The release path escalates a non-exiting model-server sidecar to SIGKILL.
- **The orphan-sweep LaunchAgent template now exists.** It runs dry-run by default and does not fire on load.
- **The local Claude settings file is untracked.** Its portable hooks moved into the shared tracked settings. The file is now gitignored.
- **Operator docs now cover the five features.** A gpt-5.5 audit had found them documented nowhere operator-facing.
- **Importing the code-index launcher runs no side effects.** The comment-hygiene checker also catches more perishable labels. Live code was scrubbed of them.

## The Disposal Flap

#### The Launcher Killed Its Own Daemon

The earlier investigation framed the relaunch as a clean-exit misclassification. Verifying against the code corrected that. The launcher already guards its own shutdown flag. Its shutdown handler `shutdownLauncherForSignal` explicitly sends `SIGTERM` to the context-server child. The real gap was timing.

When the owning session disposed, the child-exit supervisor scheduled a relaunch on a 250 ms backoff. That backoff fired before the launcher's own shutdown signal landed. The fresh daemon came up under a runtime that was already leaving. It was killed again about a second later.

&nbsp;

#### A Gate at Fire Time

Phase 017 stopped the dominant flap. It gates the relaunch at the moment its backoff fires. The launcher captures its parent pid at startup. The timer treats a changed ppid, or a reparent to 1, as a sign. That sign means its owning runtime has gone away.

Crash-recovery and RSS-recycle are untouched. Both run with the owner alive and a matching ppid. So the gate is a no-op for them. The change is additive.

## The Deferred Five

The five items shipped as 018-022. Each is flag-gated and default-safe where it changes process or daemon lifecycle. Among them, 020 gives code-index a reconnect.

#### A Trace That Survives the Host

Before anything else, the launcher learned to leave a durable trace. `log()` keeps its stderr write. Each disk line is timestamped and pid-stamped. It goes in a size-bounded file that rotates to a single previous generation at the cap.

Logging is best-effort by design. So a logging failure can never affect the launcher. It is on by default and `SPECKIT_LAUNCHER_LOG=0` disables it. Its path and size can be overridden.

&nbsp;

#### Slow Owners Stay Alive

The lease-holder check used to declare an owner dead on a single probe miss. Then it respawned. For a daemon momentarily blocked mid-merge, that meant a duplicate.

The retry count is `SPECKIT_LEASE_PROBE_RETRIES`, with a default of 1. Any single live probe short-circuits to a bridge. The default budget stays inside the probe grace ceiling. A genuinely dead socket still fails fast.

&nbsp;

#### Orphans Swept Without Guessing

The Stop hook's session-cleanup no-ops without a session pid. It deliberately refuses to guess one. When enabled, that no-session-pid branch now delegates to the orphan-only sweeper. That sweeper reaps only ownerless processes. So it can never touch a live session. It ships default-off with a dry-run ramp.

&nbsp;

#### A Foundation for Surviving Disposal

The complete fix landed as a flag-gated, default-off foundation. It keeps the shared daemon alive across its owner's exit. When enabled, the owner spawns the daemon detached. On shutdown it releases the daemon for a live secondary to adopt. It does not kill it.

Default-off is byte-identical to prior behavior. Secondary ownership adoption and the released daemon's terminal death are runtime-validation-gated. The flag stays off until that pass.

## Re-election by Default

#### The Runtime Configs Turn It On

The foundation is now the default. The committed runtime configs set `SPECKIT_DAEMON_REELECTION=1` for system-spec-memory across all three runtimes. So a disposing session hands the shared daemon to another live session. It does not kill it. The launcher's code default stays off. So the configs are the single on-switch and `0` is a one-character revert.

&nbsp;

#### Why the Default Is Safe

Turning it on for everyone is safe because the downside is bounded. If a live secondary is connected when the owner disposes, the released daemon survives. That session keeps its transport. If no secondary is connected, the next fresh session reaps the released daemon before spawning a replacement. So the database keeps a single writer exactly as before.

A hermetic integration test drives the real decision functions and real process semantics. It proves flag-on releases the detached daemon. It proves flag-off kills it.

&nbsp;

#### A Live Test Caught a Second Writer

Full multi-session behavior is now proven by a live test, not just observed. A two-session durability test spawns two real launchers. They run against an isolated fake-root that never touches the production lease or database. It confirms three things. A connected secondary keeps transport through an owner disposal. The daemon dies when the flag is off. A fresh session after disposal reaps the released daemon to stay the single writer.

That last case caught a real defect in the first cut. A fresh session reclaimed the stale lease. It spawned a second daemon on the same database. That is because lease liveness keyed on the dead owner pid rather than the live daemon. The reap-before-respawn fix closes it. So the single-writer invariant holds.

&nbsp;

#### Two Loose Ends Closed

The runbook referenced an orphan-sweep LaunchAgent template that was never committed. So a manual-test scenario always failed its lint step. A dispatched cli sub-session called a memory tool with a parent session id. It was rejected with a session-scope error. That rejection is an intended guard against session spoofing, not a defect. It is now documented in the shared cli memory-handback reference.

## The Audit That Closed the Rest

A multi-model deep review ran with gpt-5.5-fast through the official cli-opencode fan-out. It also ran with Opus through a second account. It converged on one real defect and a set of hardening items. The deep-review closure is recorded in `.opencode/specs/skilled-agent-orchestration/139-multi-model-deep` and `140-deep-review-remediation`.

#### Stale Reclaims Run Under the Lock

The reap-before-respawn fix had claimed the owner-lease acquisition as its spawn mutex. That holds only when no prior lease exists. A stale owner lease is left by an owner that crashed without releasing. Reclaiming it is a non-exclusive write. So two fresh launchers racing it could both reap and respawn.

The stale-reclaim reap and spawn now run under the same exclusive respawn lock the dead-socket path already uses. The loser bails and reconnects.

&nbsp;

#### Warm Daemons Are Adopted

A fresh session that finds a stale lease now checks whether the recorded daemon is still alive. It also checks whether its socket is still bridgeable. Reap runs only when the daemon is genuinely gone. So a cold start reuses the live process. It never tears down a daemon a connected secondary is still bridged to.

The release path waits the reap grace window before it escalates. The escalation leaves nothing wedged behind.

&nbsp;

#### Personal Settings Leave the Repo

The tracked local Claude settings file shipped machine-specific permissions. It also shipped an ablation env flag to everyone who cloned the repo. The local file is now stripped to its personal keys.

## Docs and Code Hygiene

#### Operator Docs Caught Up

`ENV_REFERENCE.md` gains eight flag rows. The feature catalog gains five entries. The manual-testing playbook gains five scenarios. The relevant READMEs and the skill doc gain lifecycle rows. The playbook's file-count self-check and the catalog count were reconciled.

&nbsp;

#### Importing the Launcher Is Safe

The post-audit cross-check left two follow-ups. Both shipped next. The code-index launcher used to load env at require time. It forced the maintainer index flags and wrote stderr there too. That is because the entrypoint guard sat below those statements. Its env work moved into a bootstrap function. That function is called only when the file is the process entrypoint.

&nbsp;

#### A Stricter Comment Checker

The comment-hygiene checker grew the patterns it was missing. It now catches RC, single-number DR, hyphen phase and council-seat labels. It scans inline trailing comments rather than only full-line ones. A blanket F-number pattern stayed out by design. That is because almost all of its matches are function keys and figures.

&nbsp;

#### A Repo-Wide Label Sweep

With the checker stricter, the perishable labels it had let through were scrubbed. The daemon-reliability files cleared first. Then a repo-wide sweep cleared the live skill, bin and plugin code. Each comment was rewritten to keep the reason and drop the rotting identifier. Archived specs, scratch directories and the pattern-defining tools were left alone. Git pre-commit wiring waits until that sweep settles. So it does not block other sessions.

## Upgrade Notes

- **Mostly no-ops by default.** The flap guard, launcher log, reap hardening and code-index reconnect (017-020) are live.
- **Re-election (022) is now on by default.** It is set in the runtime configs through `SPECKIT_DAEMON_REELECTION`. It activates on a fresh session.
- **Orphan-sweep (021) stays opt-in.**
- **Changes take effect on a fresh start.** The launcher `.cjs` and `session-cleanup.sh` changes activate on a fresh launcher or session. They do not activate via a recycle. No rebuild is required. That is because the launchers are committed `.cjs`.
