# v3.5.0.1, Right Hooks, Honest Reverts

This small patch release corrects Codex hook registration and two documentation errors. The OpenCode code-graph plugin bridge repair was reverted before release.

> Spec folder: `.opencode/specs/system-spec-kit/026-graph-and-context-optimization/008-runtime-defect-fixes/`

## What's New at a Glance

- **Codex sessions now use Codex-native hooks.** `.codex/hooks.json` had registered Claude's hook scripts for every event. `SessionStart` and `UserPromptSubmit` now point to Codex-native adapters that read the Codex stdin envelope and answer in kind, while unsupported `PreCompact` was removed rather than rewired to a Claude-envelope script.
- **The Codex MCP note now gives the correct code-graph database paths.** The note had the skill-local and legacy shared paths backwards. It now identifies the skill-local path as the default and the legacy shared path as legacy, matching launcher source.
- **The OpenCode code-graph plugin repair was reverted.** Skill extraction moved three imports and left sessions reporting "Code Graph: unavailable." Repointing them made the bridge run and emit the right transport payload, but the resulting bridge initialized the memory database directly in its own process outside the daemon's single-writer lease, the same corruption class the daemon architecture exists to prevent. It stays down until an IPC-backed transport replaces the direct imports.
- **A planned sweep of orphaned launcher processes killed nothing.** Parent-process classification showed all nine running launchers belonged to live sessions. The true orphan class, launchers that outlive an exited owner, is separately scoped daemon-reliability work.

## Upgrade

No code changes ship in this release. The fixes are configuration and documentation. Start a new Codex session for the hook correction to take effect. No other action is needed.
