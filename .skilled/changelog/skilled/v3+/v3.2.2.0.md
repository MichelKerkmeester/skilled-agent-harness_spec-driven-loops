Search usage signals now capture how people use results and what they search or do next. They build a reliable dataset without changing what users see. That dataset is intended to improve ranking in a future release. That future ranking improvement makes the workflow easier to follow and easier to trust.

## Why This Release

The signals need enough volume and validation. That comes before they can safely influence ranking without introducing bias.

## What's New at a Glance

- **Five usage signal types are recorded after every search, in the background.** They capture which results were shown. They capture which results are delivered with full content as citations. They capture whether the next search rephrases or repeats the question. They capture whether a non-search tool runs shortly after. They are stored for later analysis without affecting what users see. Search results are ranked exactly the same way as before.
- **Follow-up searches reveal rephrased queries and retries.** Someone searches again with slightly different wording. That is a rephrased query. Someone repeats nearly the same search. That is a retry. Telling the two apart compares how much word overlap exists between consecutive searches in the same session.
- **The system remembers the most recent session and uses it as a fallback.** Many tools do not carry a session identifier. So a non-search tool run shortly after a search links back to that search. It does so even when the tool knows nothing about sessions.
- **Signal collection adds 0.03ms per search on average.** This is well within the 5ms budget. So search speed is unaffected.

## Upgrade

No migration required. Signal collection activates automatically with no configuration changes.
