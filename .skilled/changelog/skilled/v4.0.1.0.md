# v4.0.1.0, Every Skill Routes From Its Own File

A skill is the instruction file an AI agent reads before it starts a job. Until this release each one also carried the routing tables that scripts use to pick its reference files, and the agent loaded those tables every time it read the skill. They now live in a router file per skill, a `ROUTER.md` beside each `SKILL.md`, so the agent reads less while every request routes exactly as it did. A skill you wrote yourself has to make the same move, and the checks now refuse one that does not.

New doctor commands do that work with you. `/doctor:sk-skill` reports how far a skill sits from the Skilled format and converts one after a plan, `/doctor:agents-md` checks your root instruction file against the shipped template and updates it without losing a line of your own, and `/doctor:helper` names the doctor command that fits a problem you describe in plain words.

Around them sit sharper routing, fixes to Pi, the orphan sweep, the commit hooks and the OpenCode file layout, and three retired surfaces. Those removals are the breaking part of this release.

## Why This Release

Routing tables made up 22 percent of every word in the skill files, and three skills sat within 25 words of the 5,000-word cap, so they could not take a new rule. Most of those tables are pseudocode that only scripts read. Each hub also wrote its routing words in four places that nothing kept in step, so a request could reach a mode and find none of that mode's guidance. And two questions every adopter faces were answered by hand: is this skill in the current format, and which lines of my root instruction file will the next update overwrite.

&nbsp;

## What's New at a Glance

- **Each skill keeps its router in its own file.** The `SKILL.md` an agent loads is about 27 percent smaller across the 54 skills and modes, and the checks reject a skill that keeps its router inside `SKILL.md`.
- **No request routes differently because of the move.** The advisor's accuracy and a replay of the recorded routing cases match their readings from before it.
- **`/doctor:sk-skill` checks a skill and converts one.** A plain agent skill or an older Skilled one becomes a current Skilled skill after a plan and your yes, with its body proved intact.
- **`/doctor:agents-md` keeps your root instruction file current.** It reports where the file stands, embeds the shipped sections around your own block only against a plan you read, and restores one run exactly.
- **`/doctor:helper` names the right doctor command.** Describe the problem in plain words and it ranks the commands that fit, and the advisor now suggests the new commands too.
- **More requests reach the right skill.** Each hub has one checked mode vocabulary, five generic phrases no longer pull ordinary prompts to the wrong hub, and Orca, GitLens, deep-loop and DESIGN.md requests reach the skill that owns them.
- **MagicPath, sk-vision and two gateway model routes are removed.** GPT-6 Luna and Sol stay available on the OpenAI and Codex routes.
- **OpenCode-only files live in `.opencode/`.** The shared tree no longer carries an OpenCode command or the OpenCode plugins.
- **Runtimes, hooks and the sweep behave.** Pi starts inside a git worktree again, a commit no longer ships stale generated copies, the orphan sweep ends abandoned temp-folder processes and installs on any machine, and the git advisory stops one false warning.
- **New skills start clear.** They are created with a router file, scored for human voice, and the shipped skill docs read in short sentences.

## Skill Routing

#### The Router Leaves the Skill File

Every skill used to end with a machine router section: the intent tables, resource maps and pseudocode that scripts read to decide which reference files to load. That section now closes a `ROUTER.md` beside the `SKILL.md`, and the routing section of `SKILL.md` ends with one link to it. The seven parent hubs already had a root router file, so their section joined it.

Measured over the 54 skills and modes, the `SKILL.md` files fell from 328,333 tokens to 238,406, a figure that also counts the doc fixes made after the move.

The tools that read a router follow it. Router replay, the dead-route scan, compiled hub routing and the skill advisor's freshness check read `ROUTER.md`, so an edit to a router alone now reaches the advisor. The Hermes copy of each skill carries its router file, with relative links rewritten so they still resolve.

#### Routing Accuracy Held Through the Move

The move changed where each router lives and nothing it decides. The advisor still scores 155 of 195, 49 of 66 and 19 of 24 on its three labelled prompt sets, the replay report is byte-identical before and after, and every router parses the same as it did before the move.

#### Skills Must Use the New Shape

`/create:skill` and `/create:skill-parent` write a `ROUTER.md` beside every new `SKILL.md`. A router section left in `SKILL.md` fails both `package_skill.py --strict` and the parent hub check, and so does a missing `ROUTER.md` or a `SKILL.md` with no one-line link to it. The routing prose in `SKILL.md` stays at 12 lines and 180 words at most. No skill is excused from the rule.

#### More Requests Reach the Right Skill

A parent hub picks a mode first and a resource second, and it used to write the words for those steps in four places. `hub-router.json` is now the one authored vocabulary, and a check fails CI when any other copy disagrees with it.

Five bare phrases came out. "On its own" and "design reference" pulled coding and documentation prompts to the MCP tools. "State machine", "data model" and "style guide" pulled debugging, schema and API-doc prompts to design. Their qualified forms such as `state machine diagram` stay.

Requests that used to miss now land. A list request that names Orca reaches `cli-orca`, because for a CLI skill the tool's own name now counts as naming it, and an Orca ownership handoff reaches it too. "gitlens start review" and "end idle fsmonitor daemons" reach `sk-git`. A DESIGN.md repaint reaches the diagram mode, a chart theme request reaches the chart mode, and deep-loop review and council terms reach their modes. "Screen examples" and "extract DESIGN.md" no longer pull requests to the MCP tools, a prose mention of raw passthrough no longer switches `sk-prompt` to its raw mode, and "runtime mirror drift" reaches `/doctor:runtime-mirrors` again.

Requests that open with "Show me" or "Explain" still load no skill, because the advisor holds back on a request to explain something by design.

## Doctor Commands

The doctor family checks and repairs the setup one area at a time. Three commands joined it here. One only reads, and the other two write after a plan and a yes.

#### Your Skills, Measured and Converted

Whether a skill matched the Skilled format used to be a question you answered by reading the format rules and comparing them to a folder by hand. `/doctor:sk-skill check`, which a bare `/doctor:sk-skill` runs, reports rows `C1` to `C13` for one skill or one row per skill for the whole fleet, each finding with its repair. `--json` prints the report alone, and `--into-hub <hub>` lists the eleven surfaces a skill still needs under that hub. A skill inside another repository is judged against that repository.

`/doctor:sk-skill convert <skill>` moves a skill onto the format. An older Skilled skill has its inline router moved into a sibling `ROUTER.md` where it sits. A plain agent skill is staged as a copy under `.skilled/skills/<name>`, and its source folder is left exactly as it was. Each open question is asked on its own: the intent phrases a plain skill needs, a description past 130 characters, the `allowed-tools` list and the one edge that links the skill into the advisor graph. A no at any of them ends the run with nothing written.

Nothing is written until the body is proved to survive. Every non-heading line of the source has to appear in the new `SKILL.md`, in `ROUTER.md` or in a reference document, so a rewrite that loses a line stops there. The converted skill is then wired in: the advisor scan, the compiled skill graph, a reach probe on its phrases, the Hermes mirror and the changelog entry, each naming its repair when it fails. The run ends with an undo block that restores the files it overwrote and removes the ones it created.

#### Your Root Instruction File, Kept Current

Every installed repository carries a root instruction file that the framework writes once and never reads back. The template moves on, a fork grows its own sections between the shipped ones, and nothing said which lines belong to you and which the next update will overwrite.

`/doctor:agents-md check`, the default, reports twelve rows, `A1` to `A12`: the install state, the sections lost or reordered, how current each shipped body is, every pin, the delivery budget, the shape of your own block, the lines only you carry, each runtime copy, `REPO RULES.md` and the template's own purity. A row it cannot prove reads `UNKNOWN`, never `PASS`.

`embed` composes everything in memory and prints a plan: each target's diff, your new block, the byte budget, the lines it keeps and a digest. It writes only when you hand that digest back, so the write lands where you looked. Every path is backed up first, the write stays inside an allowlist, and the run then proves against the disk that every line you had is still there. A dropped line restores itself from the backup and the run ends as a failure.

`restore` puts back exactly what one recorded run wrote, removes the files and the empty folders that run created, and keeps the backup. A record that names another folder is refused rather than written to.

#### The Way In Names the Command

Not knowing which doctor command owns a problem was a problem of its own. `/doctor:helper` takes a problem in plain words and ranks the doctor commands that fit it, each with whether it writes and the wording it matched. A read-only pick runs in place, and a writing pick is printed for you to run, so it still asks for its own yes.

The advisor now suggests `/doctor:helper` and `/doctor:agents-md` when a prompt describes their problem, alongside the doctor commands it already suggested, and its accuracy on the three labelled prompt sets is unchanged.

## Retired Surfaces

#### MagicPath and Vision Leave the Framework

**Breaking:** The `mcp-magicpath` mode, the `sk-vision` skill and its `/vision` command no longer exist. A request that names MagicPath ends at the MCP tooling hub's defer path, and no replacement mode exists. The hub now carries eight modes.

#### GPT Models Run on the GPT Provider

The LLM Gateway routes for GPT-6 Luna and Sol came off the Pi and Hermes rosters and the Hermes fan-out allowlist. A Hermes lineage pinned to either gateway id is now refused.

## Runtimes and Fixes

#### OpenCode Files Have One Home

`.opencode/commands` used to be one link to the shared command tree, so `/goal-opencode`, which works only in OpenCode, had to live in the shared tree. `.opencode/commands` is now a real folder that links each shared command one by one, with `.opencode/commands/goal-opencode.md` as its one OpenCode-native file. Hook links, docs, tests and workflows read the plugins from `.opencode/plugins`, and the old plugin link under `.skilled/` is gone.

#### Pi Loads One Copy of Its Extension

A user-level link that loads the cache optimizer in every project made Pi load two copies of it inside a worktree, and Pi refused to start. The first copy now claims the extension and the second stays quiet.

#### Generated Files Match the Commit

The pre-commit hook raises a document's version and checks the copies and routing manifests generated from it. It used to check first and raise second, so a commit shipped copies of the old version and the push guard refused it. The version step now runs first. A commit that stages only a `ROUTER.md` now rebuilds its hub's compiled routing manifest, and a commit that changes a deep-loop doc recompiles the deep command contracts that record it.

#### Abandoned Processes Leave Temp Folders

Benchmark browsers, test servers and stuck repros kept running for days from temp and scratch folders, because `.skilled/scripts/orphan-mcp-sweeper.sh` only knew MCP daemons. It now ends a process the system adopted after its parent died, once that process runs from your temp folder, the Claude scratchpad or a worktree `.scratch-*` folder and is six hours old. `ORPHAN_TEMP_PROCESS_AGE_HOURS` moves that floor. A live session in any of the seven CLI runtimes keeps its helpers, and the skill advisor's servers stay while their launcher lives.

#### The Sweep Installs on Any Machine

The launch agent template that schedules the orphan sweep carried a label naming one personal account. It now carries `com.skilled.orphan-sweep`, its file is named after that label, and its install step fills in your repository and home directory as it copies. Skill docs and playbooks name paths relative to the repository instead of one machine's home folder.

#### The Git Advisory Keeps the Directory

The preflight advisory judges a git command by the state of the directory it runs in. It lost a `cd <dir> &&` when the shell exported a variable before the git command, and then warned that files in the target worktree matched nothing. A cd followed only by variable assignments now keeps its directory, so `cd <dir> && export A=1; git add <file>` is judged where it runs.

## Clearer Skill Docs

#### Long Lines Became Short Sentences

Before the pass, 441 prose lines in the skill, command and agent docs ran past 400 characters, some past 900, each packing several rules into one sentence. They are now short sentences and lists with the same facts, and each hub opens How It Works with a glossary of the routing terms it uses. Fifty-six skill references also open with an overview and number their sections the way the reference template asks.

#### New Skills Are Checked for Human Voice

The skill templates carry one clarity checklist: instructions first, each fact once, one idea per sentence and second person. `/create:skill` and `/create:skill-parent` score the generated `SKILL.md` and `README.md` with the human-voice scanner and block completion on a hard blocker, and the templates now pass that scan themselves.

## Upgrade Notes

- **Coming from v4.0.0.17:** that release was withdrawn and this one replaces it. It kept each router at the end of `SKILL.md`, and a skill in that shape now fails the checks.
- **Skills you wrote yourself:** run `/doctor:sk-skill check` to see which ones still keep a router in `SKILL.md`, then `/doctor:sk-skill convert <skill>` to move it into a sibling `ROUTER.md` after a plan. By hand, move the router, link it from SMART ROUTING and run `.skilled/skills/sk-doc/sk-create-skill/scripts/package_skill.py <skill-folder> --check --strict` until it prints `Result: PASS`.
- **Your root instruction file:** run `/doctor:agents-md check` to see which shipped sections changed and which lines are yours, and `/doctor:agents-md embed` to bring it current after you read the plan.
- **Callers of MagicPath or `/vision`:** stop. Neither has a replacement.
- **Pi or Hermes setups that use the gateway GPT-6 Luna or Sol ids:** switch to the OpenAI or Codex route.
- **Anything that read OpenCode files under `.skilled/`:** read the plugins from `.opencode/plugins` and the goal command from `.opencode/commands/goal-opencode.md`.
- **Pi worktree runs:** the fix works once your main checkout has this release, because the user-level link loads the main checkout's copy. Until then `-ne` still works.
- **To schedule the orphan sweep:** copy `.skilled/scripts/launchagents/com.skilled.orphan-sweep.plist`, fill in the two path placeholders and remove `--dry-run` from your copy. The template keeps the flag, so an unedited copy only logs what it would do.
- **An agent you installed from the older template:** it keeps running under its old label until you follow the upgrade step in `.skilled/scripts/launchagents/README.md`, which unloads the old agent, removes its plist and installs a fresh copy.
- **To pick up the advisor fixes:** rebuild with `npm --prefix .skilled/skills/system-skill-advisor/runtime run build`, restart its daemon, then run `node .skilled/bin/skill-advisor.cjs advisor_rebuild --trusted --force true`.
- **To find the right doctor command:** run `/doctor:helper` with your problem in plain words, or `/doctor:setup` to list every command and target. Neither writes.
