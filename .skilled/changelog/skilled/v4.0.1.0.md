# v4.0.1.0, Every Skill Routes From Its Own File

A skill is the instruction file an AI agent reads before it starts a job. Each one used to carry the routing tables that scripts read to pick its reference files, and the agent loaded those tables every time. They now live in a `ROUTER.md` beside each `SKILL.md`, so the agent reads about 27 percent less and every request routes as it did. A skill you wrote yourself has to make the same move, and a new doctor command does it for you.

The release also links Skilled into your own projects, saves your answers into the decision record, adds a web frontend surface to `sk-code` and retires four surfaces. The retirements are the breaking part.

> Spec folders: `specs/sk-doc/051-hub-routing-quality/002-skill-routing-and-clarity`, `specs/commands/004-doctor-sk-skill-command`, `specs/commands/005-doctor-symlink-install`, `specs/agents-md/016-doctor-agents-md`, `specs/system-speckit/043-decision-capture`, `specs/sk-code/018-frontend-upstream-proposals`, `specs/sk-design/021-deprecate-fundamentals`, `specs/sk-doc/065-conversation-playbook-scenarios` and `specs/sk-doc/066-skill-readability-refinement`, with smaller packets for the fixes

&nbsp;

## Why This Release

Routing tables made up 22 percent of every word in the skill files, and three skills sat within 25 words of the 5,000-word cap. Adopters also had no way to check whether a skill was in the current format, link the framework into their own project or tell which lines of their root instruction file an update would overwrite.

An answer you gave to an AI's question reached a decision record only when someone retyped it. And spacing, colour and motion values lived on the design hub, while the code that builds the screen had none of them.

&nbsp;

## What's New at a Glance

- **Each skill keeps its router in its own file.** The `SKILL.md` an agent loads is about 27 percent smaller, and no request routes differently.
- **More requests reach the right skill.** Orca, GitLens, deep-loop, chart and DESIGN.md requests land where they belong, and a request that says not to write anything no longer counts as a request to write docs.
- **`sk-code` carries a web frontend surface.** It holds web practice, a five-pass Figma check and the design values a screen needs, with a starter `tokens.css`.
- **Doctor commands for your skills and projects.** `/doctor:sk-skill` converts a skill, `/doctor:install` and `/doctor:symlink` link Skilled into your project, `/doctor:agents-md` keeps your root instruction file current and `/doctor:helper` names the command for a problem.
- **Your answers reach the decision record.** A save records each answer you gave an AI's question as a decision, on all five supported runtimes.
- **Playbooks can test a whole conversation.** A scenario can script several turns, answer the AI's questions and restart the session.
- **Four surfaces are retired.** MagicPath, `sk-vision`, the design values mode and two gateway model routes are gone.
- **Skill docs read in order.** Every skill doc was read by hand for layout, and render checks now flag a doc that reads wrong.

&nbsp;

## Skill Routing

#### The Router Leaves the Skill File

The intent tables, resource maps and pseudocode that scripts read now sit in a `ROUTER.md` beside each `SKILL.md`, and `SKILL.md` links to it in one line. Across the 54 skills and modes, the files an agent loads fell from 328,333 tokens to 238,406. The advisor scores the same on its three labelled prompt sets, so nothing routes differently.

#### Skills You Write Must Use the New Shape

`/create:skill` and `/create:skill-parent` write the router file for you and score the new docs for clear, plain writing. A skill that keeps its router inside `SKILL.md`, or has no `ROUTER.md`, now fails `package_skill.py --strict`.

#### More Requests Reach the Right Skill

Each hub now writes its routing words in one checked place instead of four. Five generic phrases such as "state machine" and "style guide" no longer pull ordinary prompts to the wrong hub. Requests about Orca, GitLens, deep-loop reviews, chart choices and DESIGN.md repaints reach the skill that owns them, and a clarity review of a design doc reaches `sk-doc`. A request such as "review this, don't write anything back" no longer counts as a request to write docs.

&nbsp;

## Frontend Surface

#### A Web Surface on the Code Hub

`sk-code-frontend` holds the frontend practice a web change needs: which element carries a behavior, where a focus ring goes and how a long list stays readable. It loads beside a coding workflow when the request is about web UI, with six topic files that load only when the request touches them. A project can replace, extend or switch off any rule under a `Frontend overrides` heading in its own `SKILL.md`.

#### The Figma Check Has Five Passes

A built screen is compared with its Figma frame in five passes: width, each state, the rendered tokens, each Figma variable against your token package, and range and access. A pass that cannot run leaves the verdict `INCOMPLETE`, never `PASS`. Every Figma read that feeds code ends at this check.

#### Design Values Live With the Code

Spacing, type, colour, hierarchy and motion values now come from `sk-code-frontend`, so a screen and its values answer to one owner. It ships a starter `tokens.css` to copy into a project and retune. Under a reduced-motion preference, movement becomes an instant change or a short fade. A design review now loads this surface beside the review workflow.

## Doctor Commands

Each new command either only reads or writes after a plan and your yes.

#### Your Skills, Measured and Converted

`/doctor:sk-skill check` reports how far a skill sits from the Skilled format, each finding with its repair. `/doctor:sk-skill convert <skill>` moves a skill onto the format: an older Skilled skill gets its router moved out, and a plain agent skill is copied in while its source stays untouched. Nothing is written until every line of the old body is found in the new files, and the run ends with an undo block.

#### Your Own Project, Linked In

`/doctor:install` prints the setup steps in order and writes nothing. `/doctor:symlink check` reports how each framework folder in your project is linked, and `link` creates the links after a plan, never overwriting a real file. The ignore lines go to your repository's `.git/info/exclude`, so the links stay out of your commits, and `unlink` undoes one run exactly. A linked project now saves, routes and relinks like a checkout.

#### Your Root Instruction File, Kept Current

`/doctor:agents-md check` shows which shipped sections changed and which lines are yours. `embed` brings the file current around your own block against a plan you read, and restores itself from a backup if any line of yours would be lost. `restore` undoes one run.

#### The Right Command for a Problem

`/doctor:helper` takes a problem in plain words and ranks the doctor commands that fit it. The advisor also suggests the new doctor commands when a prompt describes their problem.

#### The Updater Keeps Its Records Local

`/doctor:update` now keeps its records in a folder git ignores, so `.skilled/release/` no longer ships and each clone records its own base.

## Spec Kit

#### Your Answers Reach the Decision Record

Each answer you give to a question the AI asks is now kept. A full-auto `/speckit:save` writes it into the spec folder's `decision-record.md` as a short decision, with the question, the options and your answer kept word for word. Process questions, such as which folder to use or whether to push, are left out. Claude Code, Codex, Pi, OpenCode and Devin all capture, a plain-chat answer is added only after you confirm it, and a repeat save adds nothing twice.

#### Each Linked Project Keeps Its Own Answers

Projects linked to one Skilled checkout no longer share one answer folder, so a save lists only its own project's sessions. "Record this as a decision" now routes to spec-kit.

&nbsp;

## Manual Testing Playbooks

#### A Scenario Can Follow the Conversation

A playbook scenario used to send one prompt and judge the reply. It can now script several turns, the answers to give, a restart and a check after each turn. `run-conversation-scenario.cjs` plays that script into Claude Code, OpenCode, Codex, Pi or Devin inside a scratch project and keeps the evidence for each turn. It stops the run if anything would write to your repository.

&nbsp;

## Retired Surfaces

#### MagicPath and Vision Leave the Framework

**Breaking:** The `mcp-magicpath` mode, the `sk-vision` skill and its `/vision` command are gone, with no replacement.

#### Design Values Leave the Design Hub

**Breaking:** `sk-design-fundamentals` is retired. `sk-design` keeps three modes, Style Reference extraction, charts and diagrams, and asks which one you want when a request names none.

#### GPT Models Run on the GPT Provider

The LLM Gateway routes for GPT-6 Luna and Sol are removed. Both stay available on the OpenAI and Codex routes.

&nbsp;

## Runtimes and Fixes

#### OpenCode Files Have One Home

OpenCode-only files now live in `.opencode/`: the plugins in `.opencode/plugins` and the goal command in `.opencode/commands/goal-opencode.md`.

#### Smaller Fixes

- **Pi starts inside a worktree again.** It used to load two copies of its cache extension there and refuse to start.
- **Commits ship current generated copies.** The pre-commit hook now raises a doc's version before it checks the copies made from it.
- **The orphan sweep cleans temp folders.** It ends abandoned processes left in temp and scratch folders after six hours, and its launch agent installs on any machine.
- **Worker sessions skip the context nudge.** A worker no longer gets told to save into its parent's spec folder.

&nbsp;

## Clearer Skill Docs

#### Every Skill Doc, Read by Hand

Every skill, router, README, reference and asset in the 13 skills was read for layout and the order of its sections. Text moved, split into lists and gained numbered sections, every claim was kept, and docs that disagreed with their code now match it.

Each touched skill and mode has its own changelog entry, in cli-classifier (cli-jev), cli-external-orchestration (cli-claude-code, cli-codex, cli-cursor, cli-devin, cli-hermes, cli-opencode, cli-pi), cli-orca, mcp-code-mode, mcp-tooling (mcp-aside-devtools, mcp-chrome-devtools, mcp-click-up, mcp-figma, mcp-mobbin, mcp-notion, mcp-obsidian, mcp-refero), sk-code (sk-code-ci, sk-code-quality, sk-code-review, sk-code-skilled), sk-design (sk-design-chart, sk-design-diagram, sk-design-md-generator), sk-doc (sk-create-agent, sk-create-benchmark, sk-create-changelog, sk-create-command, sk-create-diff, sk-create-feature-catalog, sk-create-frontmatter, sk-create-goal, sk-create-quality-control, sk-create-readme, sk-create-repo-rule, sk-create-skill, sk-create-with-human-voice), sk-git, sk-prompt, system-deep-loop (deep-ai-council, deep-research, deep-review) and system-spec-kit.

#### Docs That Read Wrong Are Caught

A doc could pass validation and still read wrong once rendered. Two bold labels on consecutive lines join into one paragraph, and a line above `---` turns into a heading. Sixteen render checks now catch these and docs that open or order their sections wrong, and `package_skill.py --strict` fails a skill on any of them. A citation of a section that does not exist is reported in every kind of doc except changelogs and specs.

#### A Rewrite Has to Keep Every Claim

`doc-rewrite-guard.py --base <ref>` compares each changed doc with its earlier text before you commit. It fails on a changed code sample, a dropped citation or a cited section that was removed or renamed, and it refuses edits to docs that code reads word for word.

## Upgrade Notes

- **Coming from v4.0.0.17:** that release was withdrawn and this one replaces it.
- **Skills you wrote yourself:** run `/doctor:sk-skill check`, then `/doctor:sk-skill convert <skill>` for each one that still keeps its router in `SKILL.md`.
- **To pick up the advisor fixes:** rebuild with `npm --prefix .skilled/skills/system-skill-advisor/runtime run build`, restart its daemon, then run `node .skilled/bin/skill-advisor.cjs advisor_rebuild --trusted --force true`.
- **Callers of `sk-design-fundamentals`:** use `sk-code-frontend` and its starter `tokens.css` instead.
- **Projects that want React Native guidance:** keep it in your own fork. The frontend surface is web-only.
- **To use Skilled in a project of your own:** run `/doctor:install` and follow its steps, then `/doctor:setup` from inside the project to confirm.
- **Your root instruction file:** run `/doctor:agents-md check`, then `/doctor:agents-md embed` after you read the plan.
- **A repository that committed `.skilled/release/`:** run `git rm -r .skilled/release` and commit, then `/doctor:update record-base` in each other clone.
- **Decision capture on Claude Code:** a session already running may need `/hooks` approval or a restart. `SYSTEM_DECISION_CAPTURE_DISABLED=1` turns capture off.
- **Decision capture in a linked project:** run one full-auto `/speckit:save` in each linked project to clear answers left in the shared folder.
- **To run a conversation scenario:** install tmux and run `node .skilled/skills/sk-doc/sk-create-manual-testing-playbook/scripts/run-conversation-scenario.cjs --scenario <file> --runtime <runtime> --scratch <dir> --out <dir>`, with the scratch folder outside the repository.
- **Callers of MagicPath or `/vision`:** stop. Neither has a replacement.
- **Pi or Hermes setups on the gateway GPT-6 Luna or Sol ids:** switch to the OpenAI or Codex route.
- **Anything that read OpenCode files under `.skilled/`:** read them from `.opencode/` instead.
- **To schedule the orphan sweep:** copy `.skilled/scripts/launchagents/com.skilled.orphan-sweep.plist`, fill in the two path placeholders and remove `--dry-run`. An agent installed from the older template needs the upgrade step in `.skilled/scripts/launchagents/README.md`.
- **Before you commit a form-only rewrite of a skill doc:** run `python3 .skilled/skills/sk-doc/shared/scripts/doc-rewrite-guard.py --base <ref> <paths>` and resolve every `HARD` line.
