# v4.0.1.0, Every Skill Routes From Its Own File

A skill is the instruction file an AI agent reads before it starts a job. Until this release each one also carried the routing tables that scripts use to pick its reference files, and the agent loaded those tables every time it read the skill. They now live in a router file per skill, a `ROUTER.md` beside each `SKILL.md`, so the agent reads less while every request routes exactly as it did. A skill you wrote yourself has to make the same move, and the checks now refuse one that does not.

New doctor commands do that work with you. `/doctor:sk-skill` reports how far a skill sits from the Skilled format and converts it after a plan. `/doctor:install` and `/doctor:symlink` link the framework into a project repository of your own. `/doctor:agents-md` keeps your root instruction file current without losing a line of your own, and `/doctor:helper` names the doctor command that fits a problem you describe in plain words.

Around them sit automatic capture of your answers into the decision record, sharper routing, runtime and hook fixes, one home for OpenCode files and three retired surfaces. The retirements are the breaking part of this release.

> Spec folders: `specs/sk-doc/072-skill-routing-and-clarity` phases 003 to 013 (Level 3), `specs/sk-doc/072-skill-routing-and-clarity/014-skill-router-files` (Level 2), `specs/sk-doc/072-skill-routing-and-clarity/015-routing-data-alignment` (Level 3), `specs/sk-doc/074-reference-template-debt` (Level 2), `specs/sk-doc/073-opencode-native-surfaces` (Level 2), `specs/hooks/025-cache-optimizer-single-copy-guard` (Level 1), `specs/system-speckit/056-orphan-sweep-temp-processes` (Level 1), `specs/cli-external-orchestration/084-remove-llmgateway-luna-route` (Level 1), `specs/sk-git/035-fsmonitor-daemon-and-worktree-relocation-regression` (Level 2), `specs/sk-git/036-personal-name-scrub` (Level 1), `specs/sk-git/037-advisory-cd-prefix-env-steps` (Level 1), `specs/sk-doc/075-doctor-sk-skill-command` (Level 2), `specs/agents/021-doctor-agents-md` (Level 2) with phases `001-doctor-agents-md` and `002-doctor-helper` (Level 2) and `003-advisor-bridge-activation` (Level 1), `specs/system-skill-advisor/040-build-freshness-record` (Level 1), `specs/commands/005-doctor-symlink-install` phases 001 to 006 (Level 2), `specs/commands/002-doctor-audit-and-fixes` phases 003 to 006 (Level 2), `specs/system-speckit/037-symlinked-runtime-root` (Level 2) `specs/system-speckit/042-decision-capture` (Level 3), `specs/system-speckit/043-decision-capture` phases 001 to 010 (Level 2), `specs/sk-code/018-frontend-upstream-proposals` phases 001 to 009 (Level 2) and `specs/sk-doc/065-conversation-playbook-scenarios` (Level 3)

## Why This Release

Routing tables made up 22 percent of every word in the skill files, and three skills sat within 25 words of the 5,000-word cap, so they could not take a new rule. Most of those tables are pseudocode that only scripts read. Each hub also wrote its routing words in four places that nothing kept in step, so a request could reach a mode and find none of that mode's guidance. And adopters answered three questions by hand: whether a skill is in the current format, how to link the framework into their own project and which lines of their root instruction file the next update will overwrite.

An answer you gave to an AI's question also reached a decision record only when someone retyped it, so the reason behind a choice got lost.

## What's New at a Glance

- **Each skill keeps its router in its own file.** The `SKILL.md` an agent loads is about 27 percent smaller across the 54 skills and modes, and no request routes differently because of the move.
- **More requests reach the right skill.** Each hub has one checked mode vocabulary, and five generic phrases no longer pull ordinary prompts to the wrong hub. Orca, GitLens, deep-loop and DESIGN.md requests reach the skill that owns them.
- **`sk-code` carries a web frontend surface.** `sk-code-frontend` joins the CI and Skilled surfaces with one core page, a web layer, six web topic files and a five-pass Figma check. It is read-only, it bundles beside a workflow mode from request vocabulary alone, and a pass that cannot run leaves the verdict `INCOMPLETE`.
- **Design values have one owner.** A visual value that a request or a frame leaves open goes to `sk-design-fundamentals`, which now ranks a project profile last and honours reduced motion on web and native.
- **`/doctor:sk-skill` checks a skill and converts one.** A plain agent skill or an older Skilled one becomes a current Skilled skill after a plan and your yes, with its body proved intact.
- **Two commands put Skilled into your own project.** `/doctor:install` prints the setup steps in order. `/doctor:symlink` links the framework folders after a plan and your yes, and undoes one run exactly. A linked project then saves, routes and relinks like a checkout.
- **`/doctor:agents-md` keeps your root instruction file current.** It reports where the file stands, embeds the shipped sections around your own block only against a plan you read, and restores one run exactly.
- **`/doctor:helper` names the right doctor command.** Describe the problem in plain words and it ranks the commands that fit. The advisor suggests the new doctor commands too.
- **`/doctor:update` keeps its records local.** `.skilled/release/` no longer ships, and each clone records its own base in a folder git ignores.
- **Your answers reach the decision record.** Each answer to an AI's question is saved into the spec folder's decision record as a short decision, with the exact exchange kept beside it. Claude Code, Codex, Pi, OpenCode and Devin all capture, each linked project keeps its own answers, and "record this as a decision" routes to the skill that writes them.
- **MagicPath, sk-vision and two gateway model routes are removed.** GPT-6 Luna and Sol stay available on the OpenAI and Codex routes.
- **Runtimes, hooks and the sweep behave.** OpenCode-only files live in `.opencode/`, Pi starts inside a git worktree again and a commit no longer ships stale generated copies. The orphan sweep ends abandoned temp-folder processes and installs on any machine, and worker sessions no longer receive the context nudge.
- **Playbooks can test a whole conversation.** A scenario can script several turns, answer the AI's questions and restart the session, and a shared runner plays it into Claude Code, OpenCode, Codex, Pi or Devin and keeps the evidence.
- **New skills start clear.** They are created with a router file and scored for human voice, and the shipped skill docs read in short sentences.

## Skill Routing

#### The Router Leaves the Skill File

Every skill used to end with a machine router section: the intent tables, resource maps and pseudocode that scripts read to decide which reference files to load. That section now closes a `ROUTER.md` beside the `SKILL.md`, and the routing section of `SKILL.md` ends with one link to it. The seven parent hubs already had a root router file, so their section joined it.

Measured over the 54 skills and modes, the `SKILL.md` files fell from 328,333 tokens to 238,406, a figure that also counts the doc fixes made after the move.

The tools that read a router follow it. Router replay, the dead-route scan, compiled hub routing and the skill advisor's freshness check read `ROUTER.md`, so an edit to a router alone now reaches the advisor. The Hermes copy of each skill carries its router file, with relative links rewritten so they still resolve.

#### Routing Accuracy Held Through the Move

The move changed where each router lives and nothing it decides. The advisor still scores 155 of 195, 49 of 66 and 19 of 24 on its three labelled prompt sets, the replay report is byte-identical before and after, and every router parses the same as it did before the move.

#### Skills Must Use the New Shape

`/create:skill` and `/create:skill-parent` write a `ROUTER.md` beside every new `SKILL.md`. A router section left in `SKILL.md` fails both `package_skill.py --strict` and the parent hub check, and so does a missing `ROUTER.md` or a `SKILL.md` with no one-line link to it. The routing prose in `SKILL.md` stays at 12 lines and 180 words at most. No skill is excused from the rule.

#### More Requests Reach the Right Skill

A parent hub picks a mode first and a resource second, and it used to write the words for those steps in four places. `hub-router.json` is now the one authored vocabulary, and a check fails CI when any other copy disagrees with it.

Five bare phrases came out. "On its own" and "design reference" pulled coding and documentation prompts to the MCP tools. "State machine", "data model" and "style guide" pulled debugging, schema and API-doc prompts to design. Their qualified forms such as `state machine diagram` stay.

Requests that used to miss now land. A list request that names Orca reaches `cli-orca`, because for a CLI skill the tool's own name now counts as naming it, and an Orca ownership handoff reaches it too. "gitlens start review" and "end idle fsmonitor daemons" reach `sk-git`. A DESIGN.md repaint reaches the diagram mode, a chart theme request reaches the chart mode, and deep-loop review and council terms reach their modes. "Screen examples" and "extract DESIGN.md" no longer pull requests to the MCP tools, a prose mention of raw passthrough no longer switches `sk-prompt` to its raw mode, and "runtime mirror drift" reaches `/doctor:runtime-mirrors` again.

Requests that open with "Show me" or "Explain" still load no skill, because the advisor holds back on a request to explain something by design.

#### Router Tooling Follows the Phrases It Ships

A router phrase that was renamed used to stay in the hub's advisor vocabulary, because the generator that copies router phrases up only ever added. `generate-router-intent-signals.cjs --write` now records each phrase it carries up in `intent_signals_generated` beside `intent_signals`, so `--check` names and counts the phrases a router no longer declares and fails on them, and `--write` removes them from both lists while every other signal keeps its place. A phrase listed in `intent_signals_keep` is never reported or removed, and hand-curated signals stay out. The first `--write` on a hub with no provenance list seeds it from the router-declared phrases already there, so every hub carries one and a later rename is reported.

Router reach probes two phrases at a time instead of eight, because a busy advisor's refusals came back as unreachable phrases, and the measured price of two is about half a second per 48 uncached probes. The stage-two leaf replay reads `INTENT_MODEL` when a router declares no `INTENT_SIGNALS` block, nineteen routers use that name, and a keyword declared as a phrase with a weight now adds that weight, where every tuple used to score one. A hyphen and a space now match alike, in the replay and in the compiled hub matchers, and each folded form counts once, so a vocabulary that lists both spellings of one phrase no longer scores its mode twice. The sk-design router now defines the comparator that only its sibling registry compiler had, so a same-score tie among one mode's intents sorts by name instead of throwing and falling back to legacy routing.

## Frontend Surface

Frontend practice used to sit with whoever last shipped a screen: which element carries a behavior, where a focus ring belongs, how a long list keeps its rows readable, and what a Figma comparison must cover. A change reviewed as an unknown surface loaded none of it. One read-only surface now holds that practice for web work.

#### A Web-Only Surface on the Code Hub

`sk-code-frontend` is the third read-only surface on the sk-code hub's surface axis, beside `sk-code-ci` and `sk-code-skilled`. It declares no detection block, so stack detection never returns it; the hub bundles it beside a workflow mode from the `code-frontend-aliases` vocabulary class in `hub-router.json`. In `routerPolicy.tieBreak` it sits ahead of `sk-code-ci` and before `sk-code-skilled`, so a new surface wins a keyword tie and the Skilled fallback still ranks last.

`references/frontend-practice.md` holds the practice the web layer implements, and `references/web-markup-and-css.md` adds the DOM and CSS mechanics. Six topic files load by condition: elements and attributes, cascade and selectors, layout and sizing, accessibility patterns, performance and loading, and internationalization. Phase detection loads the cross-stack core, then the web stack layer, then one topic file when the request touches its concern, and the always-loaded quality floor gains a Frontend row. Every reference opens with an overview of what it covers and what it leaves to other files, and each rule lists its Rule, Why, When not to, Pitfall, Support and See also fields on separate lines. The web layer carries no framework-specific rules beyond its React and Next.js examples.

A project records each change to a core or web-layer statement, whether it replaces, extends or disables it, under a `Frontend overrides` heading in its own `SKILL.md`, naming the section, the action and the reason. The packet writes nothing. When it is bundled, the paired workflow mode applies what it loads; when no workflow mode scores, the hub routes it alone and the acting agent applies it. The surface is web-only: canonical Skilled carries no React Native code.

#### The Figma Check Has Five Passes

`references/figma-to-code.md` compares a built screen with its Figma frame in five passes: the same width, each state, the tokens read once from the rendered page and once from the source, each Figma variable against the installed token package, and the range and access checks. A pass that cannot run is recorded as `NOT RUN` with its reason, and the overall verdict is then `INCOMPLETE`, never `PASS`. A frame that maps cleanly to installed tokens needs no design step. `mcp-figma` ends every Figma read that feeds code at this check, and its playbook gains a figma-to-code category: a node turned into markup on installed tokens, off-scale values reported as drift, and a built screen checked in five passes.

#### Open Design Values Go to `sk-design-fundamentals`

A Figma read that feeds code ends at that check. When a request or a frame leaves a visual value open, or a value sits off every token and scale, `sk-design-fundamentals` decides it, and `sk-code` hands the same question there instead of inventing a value. A built screen and its frame then answer to one owner.

That mode now ranks a project's own values without letting them argue with the scales. A project may add `references/<project>-profile.md`, which loads only when a request names that project's UI and adds no routing phrase; an unknown project loads none. When sources disagree the order is the repository's mode, the tokens the app installs, the design scales, then the profile. Its motion ruleset also closes with `prefers-reduced-motion: reduce` on the web and the platform setting on native: movement becomes an instant change or a short fade, essential feedback stays, nothing auto-plays, and no animation library is named.

## Doctor Commands

The doctor family checks and repairs the setup one area at a time. Five commands joined it here. Two only read, and the other three write after a plan and a yes.

#### Your Skills, Measured and Converted

Whether a skill matched the Skilled format used to be a question you answered by reading the format rules and comparing them to a folder by hand. `/doctor:sk-skill check`, which a bare `/doctor:sk-skill` runs, reports rows `C1` to `C13` for one skill or one row per skill for the whole fleet, each finding with its repair. `--json` prints the report alone, and `--into-hub <hub>` lists the eleven surfaces a skill still needs under that hub. A skill inside another repository is judged against that repository.

`/doctor:sk-skill convert <skill>` moves a skill onto the format. An older Skilled skill has its inline router moved into a sibling `ROUTER.md` where it sits. A plain agent skill is staged as a copy under `.skilled/skills/<name>`, and its source folder is left exactly as it was. Each open question is asked on its own: the intent phrases a plain skill needs, a description past 130 characters, the `allowed-tools` list and the one edge that links the skill into the advisor graph. A no at any of them ends the run with nothing written.

Nothing is written until the body is proved to survive. Every non-heading line of the source has to appear in the new `SKILL.md`, in `ROUTER.md` or in a reference document, so a rewrite that loses a line stops there. The converted skill is then wired in: the advisor scan, the compiled skill graph, a reach probe on its phrases, the Hermes mirror and the changelog entry, each naming its repair when it fails. The run ends with an undo block that restores the files it overwrote and removes the ones it created.

#### Your Own Project, Linked In

People who keep one Skilled checkout and use it in other repositories linked it in by hand, and two shapes grew up side by side: one link per framework folder, or real folders that hold one link per entry so local commands and specs sit beside the shared ones. Nothing checked either, and links into paths the framework later moved stayed broken without a word.

`/doctor:symlink check`, the default, reports each framework folder in a target repository as linked whole, merged, partly merged, missing, broken, linked elsewhere or local. It also warns about an absolute link that git tracks. `link` picks the shape for you: a whole-folder link where nothing exists yet, or a merge into a real folder you already have. It prints a plan and a digest and writes only when you hand that digest back. It never overwrites a real file, and the only link it replaces is a broken one that points into this checkout. The ignore lines go to the repository's own `.git/info/exclude`, so the links stay out of your commits. `unlink` puts back exactly what one recorded run wrote.

#### A Linked Project Works Like a Checkout

A project linked this way had four gaps, now closed. A save from it wrote into the shared checkout and was refused, because the scripts found the project root from their own location. They now use the repository you run them in. The skill advisor refused every linked project, and it now accepts one whose `.skilled` links to this checkout. `/doctor:symlink` failed to relink a project after an unlink, because it reused the old run's folder name, and each run now claims a free one. A copy of `.skilled` one folder below another repository's git root made three doctor scripts read the enclosing repository, so `/doctor:sk-skill` could not find its hub. They now find the framework by its own marker file.

`/doctor:install` is the guide on top. It checks that this checkout is built, asks for the target repository, the runtimes and the link shape, looks at what is already linked and prints the setup steps in order. It writes nothing, so every writing step stays yours to run.

#### Your Root Instruction File, Kept Current

Every installed repository carries a root instruction file that the framework writes once and never reads back. The template moves on, a fork grows its own sections between the shipped ones, and nothing said which lines belong to you and which the next update will overwrite.

`/doctor:agents-md check`, the default, reports twelve rows, `A1` to `A12`: the install state, the sections lost or reordered, how current each shipped body is, every pin, the delivery budget, the shape of your own block, the lines only you carry, each runtime copy, `REPO RULES.md` and the template's own purity. A row it cannot prove reads `UNKNOWN`, never `PASS`.

`embed` composes everything in memory and prints a plan: each target's diff, your new block, the byte budget, the lines it keeps and a digest. It writes only when you hand that digest back, so the write lands where you looked. Every path is backed up first, the write stays inside an allowlist, and the run then proves against the disk that every line you had is still there. A dropped line restores itself from the backup and the run ends as a failure.

`restore` puts back exactly what one recorded run wrote, removes the files and the empty folders that run created, and keeps the backup. A record that names another folder is refused rather than written to.

#### The Way In Names the Command

Not knowing which doctor command owns a problem was a problem of its own. `/doctor:helper` takes a problem in plain words and ranks the doctor commands that fit it, each with whether it writes and the wording it matched. A read-only pick runs in place, and a writing pick is printed for you to run, so it still asks for its own yes.

The advisor now suggests `/doctor:helper` and `/doctor:agents-md` when a prompt describes their problem, and its accuracy on the three labelled prompt sets is unchanged. It suggests `/doctor:install` and `/doctor:symlink` the same way. A doctor problem in your own words, with none of a command's phrases, now reaches `/doctor:helper` too, while an ordinary request that shares a doctor word gains no doctor line.

#### The Updater Keeps Its Records to Itself

`/doctor:update` kept its base record, divergence log, run folders and apply lock in `.skilled/release/`, and Skilled shipped that folder with only an ignore file in it, so every installed copy carried an empty-looking folder. The base record was also a tracked file the updater asked you to commit. All of it now lives in `.skilled/skills/.state/doctor-update/`, which git ignores, so each clone records its own base and `.skilled/release/` no longer ships. A base record committed under the old layout is still read, and the updater prints the command that removes the old copy.

## Spec Kit

#### Your Answers Reach the Decision Record

Each answer you give to a question the AI asks with its question tool is now queued as you give it. A full-auto `/speckit:save` then writes it into the bound spec folder's `decision-record.md` as a short decision, and keeps the question, the offered options and your answer word for word in the same file. Questions about process, such as which spec folder or worktree to use or whether to push, are left out.

Claude Code queues each answer through a hook, Pi through a live extension, and OpenCode and Devin during the session. Each of those runtimes and Codex also read the stored conversation at save for answers the live path missed, under the same key, so nothing is added twice. A question you answered in plain chat, anywhere in the AI's message, is offered as a candidate on every runtime and added only after you confirm it at save. Each candidate carries evidence the save can check: the kind of question, whether your reply names an offered option, the words it shares with the question and whether it starts a new task or changes the subject.

A repeat save changes nothing, and decisions you wrote by hand stay as they are. An answer that matches a row of a hand-written decision table counts as recorded under that row's id instead of being added again. A phase parent may now hold its own decision record for decisions that span every phase.

#### Each Linked Project Keeps Its Own Answers

Projects linked to one Skilled checkout used to share one answer folder, so a save in one project could list another project's sessions. Each project now keeps its answers, the record of answers already saved and its locks in its own folder, named by a short hash of the project's root. Answers queued before this change are still found. A save also tells a failed transcript read from an empty session, and it offers answers that other sessions left behind.

#### Decision Requests Route to Spec Kit

"Record this as a decision" used to match no skill. It now routes to spec-kit, which owns the save step, and so do show and list questions about the decision-capture queue or a chat candidate. A request to research, dispatch or build something about decisions still goes to the skill that does that work.

#### Two Commands Say What They Did

Both changes are in `system-spec-kit`.

The trigger index names the checkout it indexes. Run from a project that links the Skilled source, the generator used to index the source checkout instead of the project and said nothing. When no `--repo-root` is passed and the caller's git root differs from the generator's own checkout, `generate-trigger-index.mjs` now prints one stderr line naming both roots and the `--repo-root` and `--out` flags. The default root, stdout and exit codes are unchanged.

A plan-only save names its skip. Every save that is not `--full-auto` refreshes the packet metadata and leaves the continuity fields alone, and it used to say so only when the payload carried those fields. Each such save now ends its summary with `Continuity fields not written: plan-only save; pass --full-auto to write them`, and its exit codes and written files are unchanged.

## Manual Testing Playbooks

#### A Scenario Can Follow the Conversation

A playbook scenario used to send one prompt and judge the reply, so it could not test what happens after the AI asks a question, after a later turn or after the session restarts. A scenario can now carry a `json conversation` script: the turns to send, the answers to give, a restart or compaction, and a shell check after each turn. `run-conversation-scenario.cjs` plays that script into a real Claude Code, OpenCode, Codex, Pi or Devin session inside a private tmux server and a scratch project, answers each question from the script, runs each check and writes the screens, scrollback and verdict per turn.

The runner fails closed. A scratch project inside the repository, a setup that writes to the repository, a subject that writes to it, a symlink that escapes the scratch, a child process that outlives the run and two turns that would share an evidence folder each stop or fail the run with a named reason. On macOS the subject starts in a sandbox that denies writes to the repository, and an exhausted usage limit is reported as `QUOTA_EXHAUSTED`.

#### One Rule Picks the Scenario Style

Whether a scenario should be a single prompt or a conversation used to be a judgment call. `sk-create-manual-testing-playbook` now asks four ordered questions and stops at the first yes. Each style has its own template, and the conversation template makes the script block required, so an unfilled sample block fails validation. `/create:manual-testing-playbook` reads the rule before writing and records each scenario's style.

#### Skills Gained Conversation Scenarios

The CLI runtimes, the doctor commands and several skills now test their answer-dependent behaviour as conversations. These include session resume and restart, the goal hooks, the dispatch authorization gate, the ambiguous-component pause, the leftover-placeholder refusal and the restraint refusal. Spec Kit's decision capture has three: a timed conversation through two saves, a compaction and a restart, the off switch leaving nothing queued, and a re-proof of table matching and mid-message chat questions. Each lists only the runtimes it was written for or passed on, and a scenario that was tried on another runtime and dropped says why.

## Retired Surfaces

#### MagicPath and Vision Leave the Framework

**Breaking:** The `mcp-magicpath` mode, the `sk-vision` skill and its `/vision` command no longer exist. A request that names MagicPath ends at the MCP tooling hub's defer path, and no replacement mode exists. The hub now carries eight modes.

#### GPT Models Run on the GPT Provider

The LLM Gateway routes for GPT-6 Luna and Sol came off the Pi and Hermes rosters and the Hermes fan-out allowlist. A Hermes lineage pinned to either gateway id is now refused.

## Runtimes and Fixes

#### OpenCode Files Have One Home

`.opencode/commands` used to be one link to the shared command tree, so `/goal-opencode`, which works only in OpenCode, had to live in the shared tree. `.opencode/commands` is now a real folder that links each shared command one by one, with `.opencode/commands/goal-opencode.md` as its one OpenCode-native file. Hook links, docs, tests and workflows read the plugins from `.opencode/plugins`, and the old plugin link under `.skilled/` is gone.

#### Pi Loads One Copy of Its Extension

A user-level link that loads the cache optimizer in every project made Pi load two copies of it inside a worktree, and Pi refused to start. The first copy now claims the extension and the second stays quiet.

#### Generated Files Match the Commit

The pre-commit hook raises a document's version and checks the copies and routing manifests generated from it. It used to check first and raise second, so a commit shipped copies of the old version and the push guard refused it. The version step now runs first. A commit that stages only a `ROUTER.md` now rebuilds its hub's compiled routing manifest, and a commit that changes a deep-loop doc recompiles the deep command contracts that record it.

#### Abandoned Processes Leave Temp Folders

Benchmark browsers, test servers and stuck repros kept running for days from temp and scratch folders, because `.skilled/scripts/orphan-mcp-sweeper.sh` only knew MCP daemons. It now ends a process the system adopted after its parent died, once that process runs from your temp folder, the Claude scratchpad or a worktree `.scratch-*` folder and is six hours old. `ORPHAN_TEMP_PROCESS_AGE_HOURS` moves that floor. A live session in any of the seven CLI runtimes keeps its helpers, and the skill advisor's servers stay while their launcher lives.

#### The Sweep Installs on Any Machine

The launch agent template that schedules the orphan sweep carried a label naming one personal account. It now carries `com.skilled.orphan-sweep`, its file is named after that label, and its install step fills in your repository and home directory as it copies. Skill docs and playbooks name paths relative to the repository instead of one machine's home folder.

#### Worker Sessions Skip the Context Nudge

A worker session started with `AI_SESSION_CHILD=1` inherits its parent's environment, so when its context filled up the nudge told it to save into the parent's spec folder. The nudge now skips such a worker on every runtime, the way the session claim already did.

#### The Git Advisory Keeps the Directory

The preflight advisory judges a git command by the state of the directory it runs in. It lost a `cd <dir> &&` when the shell exported a variable before the git command, and then warned that files in the target worktree matched nothing. A cd followed only by variable assignments now keeps its directory, so `cd <dir> && export A=1; git add <file>` is judged where it runs.

## Clearer Skill Docs

#### Long Lines Became Short Sentences

Before the pass, 441 prose lines in the skill, command and agent docs ran past 400 characters, some past 900, each packing several rules into one sentence. They are now short sentences and lists with the same facts, and each hub opens How It Works with a glossary of the routing terms it uses. Fifty-six skill references also open with an overview and number their sections the way the reference template asks.

#### New Skills Are Checked for Human Voice

The skill templates carry one clarity checklist: instructions first, each fact once, one idea per sentence and second person. `/create:skill` and `/create:skill-parent` score the generated `SKILL.md` and `README.md` with the human-voice scanner and block completion on a hard blocker, and the templates now pass that scan themselves.

## Upgrade Notes

- **Coming from v4.0.0.17:** that release was withdrawn and this one replaces it. It kept each router at the end of `SKILL.md`, and a skill in that shape now fails the checks.
- **Callers of MagicPath or `/vision`:** stop. Neither has a replacement.
- **Pi or Hermes setups that use the gateway GPT-6 Luna or Sol ids:** switch to the OpenAI or Codex route.
- **Anything that read OpenCode files under `.skilled/`:** read the plugins from `.opencode/plugins` and the goal command from `.opencode/commands/goal-opencode.md`.
- **Skills you wrote yourself:** run `/doctor:sk-skill check` to see which ones still keep a router in `SKILL.md`, then `/doctor:sk-skill convert <skill>` to move it into a sibling `ROUTER.md` after a plan. By hand, move the router, link it from SMART ROUTING and run `.skilled/skills/sk-doc/sk-create-skill/scripts/package_skill.py <skill-folder> --check --strict` until it prints `Result: PASS`.
- **To use Skilled in a project of your own:** run `/doctor:install` from this checkout and follow the steps it prints. Run `/doctor:setup` from inside that project afterwards to confirm the result, and run saves from inside the project too.
- **A repository that committed `.skilled/release/`:** `/doctor:update` still reads that base. Remove the tracked copy with `git rm -r .skilled/release` and commit, then run `/doctor:update record-base` in each other clone.
- **Decision capture on Claude Code:** a session that was already running may need `/hooks` approval or a restart before the new hook fires, and the save covers the gap meanwhile. `SYSTEM_DECISION_CAPTURE_DISABLED=1` turns capture off.
- **Decision capture in a linked project:** run one full-auto `/speckit:save` in each linked project to clear answers left in the shared folder from before. After that the files in the root of `.skilled/skills/.state/decision-capture/` can be deleted.
- **Projects that want React Native guidance:** keep it in your own fork. The shipped frontend surface is web-only, and React Native is an unsupported stack in the hub again.
- **Your root instruction file:** run `/doctor:agents-md check` to see which shipped sections changed and which lines are yours, and `/doctor:agents-md embed` to bring it current after you read the plan.
- **To pick up the advisor fixes:** rebuild with `npm --prefix .skilled/skills/system-skill-advisor/runtime run build`, restart its daemon, then run `node .skilled/bin/skill-advisor.cjs advisor_rebuild --trusted --force true`.
- **Pi worktree runs:** the fix works once your main checkout has this release, because the user-level link loads the main checkout's copy. Until then `-ne` still works.
- **To schedule the orphan sweep:** copy `.skilled/scripts/launchagents/com.skilled.orphan-sweep.plist`, fill in the two path placeholders and remove `--dry-run` from your copy. The template keeps the flag, so an unedited copy only logs what it would do.
- **An agent you installed from the older template:** it keeps running under its old label until you follow the upgrade step in `.skilled/scripts/launchagents/README.md`, which unloads the old agent, removes its plist and installs a fresh copy.
- **To run a conversation scenario:** install tmux, keep the scratch folder outside the repository and run `node .skilled/skills/sk-doc/sk-create-manual-testing-playbook/scripts/run-conversation-scenario.cjs --scenario <file> --runtime <runtime> --scratch <dir> --out <dir>`.
- **To find the right doctor command:** run `/doctor:helper` with your problem in plain words, or `/doctor:setup` to list every command and target. Neither writes.
