# v4.0.1.0, Every Skill Routes From Its Own File

A skill is the instruction file an AI agent reads before it starts a job. Until this release each one also carried the routing tables that scripts use to pick its reference files, and the agent loaded those tables every time it read the skill. They now live in a router file per skill, a `ROUTER.md` beside each `SKILL.md`, so the agent reads less while every request routes exactly as it did.

The rest of the routing program tightens the same ground. Each parent hub now has one checked mode vocabulary, new skills are created in the new shape and the skill docs read in short sentences. A check of each skill after the move fixed the docs that still described the old layout.

The doctor commands grew alongside it. `/doctor:sk-skill` reports how far a skill sits from the Skilled format and converts one, `/doctor:agents-md` checks the root instruction file and writes only against a plan you read, and `/doctor:helper` names the command that fits a problem you describe in plain words. The advisor now suggests the new ones.

Around the routing work sit fixes to Pi, the orphan sweep, the commit hooks and the OpenCode file layout. The launch agent template that schedules the sweep carries a neutral label and fills in its own paths at install, so a copy works on any machine. Three retired surfaces are removed, and those removals are the breaking part of this release.

> Spec folders: `specs/sk-doc/072-skill-routing-and-clarity` phases 003 to 013 (Level 3), `specs/sk-doc/072-skill-routing-and-clarity/014-skill-router-files` (Level 2), `specs/sk-doc/072-skill-routing-and-clarity/015-routing-data-alignment` (Level 3), `specs/sk-doc/074-reference-template-debt` (Level 2), `specs/sk-doc/073-opencode-native-surfaces` (Level 2), `specs/hooks/025-cache-optimizer-single-copy-guard` (Level 1), `specs/system-speckit/056-orphan-sweep-temp-processes` (Level 1), `specs/cli-external-orchestration/084-remove-llmgateway-luna-route` (Level 1), `specs/sk-git/035-fsmonitor-daemon-and-worktree-relocation-regression` (Level 2), `specs/sk-git/036-personal-name-scrub` (Level 1), `specs/sk-git/037-advisory-cd-prefix-env-steps` (Level 1), `specs/sk-doc/075-doctor-sk-skill-command` (Level 2), `specs/agents/021-doctor-agents-md` (Level 2) with phases `001-doctor-agents-md` and `002-doctor-helper` (Level 2) and `003-advisor-bridge-activation` (Level 1), and `specs/system-skill-advisor/040-build-freshness-record` (Level 1)

&nbsp;

## Why This Release

Routing tables made up 22 percent of every word in the skill files, and three skills sat within 25 words of the 5,000-word cap, so they could not take a new rule. Most of those tables are pseudocode that only scripts read. Each hub also wrote its routing words in four places that nothing kept in step, so a request could reach a mode and find none of that mode's guidance. The doctor commands answer the same kind of question elsewhere: a skill that drifted from the format, and a root instruction file the framework wrote once and never read back, were both judged by hand until now.

&nbsp;

## What's New at a Glance

- **Each skill keeps its router in its own file, and new skills are born that way.** The `SKILL.md` an agent loads is about 27 percent smaller across the 54 skills and modes, and the package checks reject a skill that keeps its router inside `SKILL.md`.
- **No request routes differently.** The advisor's accuracy and a replay of the recorded routing cases match their readings from before the move.
- **Each hub has one checked mode vocabulary.** Five generic phrases no longer pull ordinary prompts to the wrong hub.
- **Skill docs read in short sentences.** No prose line in a skill, command or agent doc runs past 400 characters.
- **More requests reach the right skill.** Orca handoffs, GitLens reviews, deep-loop terms and DESIGN.md theming now reach the skill or mode that owns them, and the new doctor commands answer to a prompt as well.
- **A doctor for skills and a doctor for the instruction file.** `/doctor:sk-skill` checks a skill against the format and converts one after a plan, `/doctor:agents-md` checks, embeds and restores the root instruction file, and `/doctor:helper` names the command that fits your problem.
- **The orphan sweep installs on any machine.** The launch agent template carries a neutral label and fills in your repository and home paths as it is copied, and the docs name paths relative to the repository.
- **Commit hooks keep generated files current.** A commit that raises a document version or stages only a router file no longer ships stale copies.
- **Runtimes and temp folders clean up after themselves.** Pi starts inside a git worktree again, and the orphan sweep ends abandoned processes without touching a live session's helpers.
- **OpenCode-only files live in `.opencode/`.** The shared tree no longer carries an OpenCode command or the OpenCode plugins.
- **MagicPath, sk-vision and two gateway model routes are removed.** GPT-6 Luna and Sol stay available on the OpenAI and Codex routes.

## Skill Routing

#### The Router Leaves the Skill File

Every skill used to end with a machine router section: the intent tables, resource maps and pseudocode that scripts read to decide which reference files to load. That section now closes a `ROUTER.md` beside the `SKILL.md`, and the routing section of `SKILL.md` ends with one link to it. The seven parent hubs already had a root router file, so their section joined it. The cycle first moved each router to the end of its `SKILL.md`, the shape the withdrawn v4.0.0.17 described, and then out into its own file.

Measured over the 54 skills and modes, the `SKILL.md` files fell from 328,333 tokens to 238,406. That figure runs from just before the move to this release, so it also counts the doc fixes made after it.

The tools that read a router follow it. Router replay, the dead-route scan, compiled hub routing and the skill advisor's freshness check read `ROUTER.md`, so an edit to a router alone now reaches the advisor. The Hermes copy of each skill carries its router file, with relative links rewritten so they still resolve. The same move was carried out on the 16 skills in the separate AI Systems repository.

#### Routing Accuracy Held Through the Move

The move changed where each router lives and nothing it decides. The advisor still scores 155 of 195, 49 of 66 and 19 of 24 on its three labelled prompt sets. The replay report is byte-identical before and after. Every router parses the same as it did before the move, and that held after each doc fix that followed.

#### New Skills Start in the New Shape

`/create:skill` and `/create:skill-parent` write a `ROUTER.md` beside every new `SKILL.md`, laid out like `.skilled/skills/sk-doc/sk-create-skill/assets/skill/skill-router-template.md`. A router section left in `SKILL.md` fails both `package_skill.py --strict` and the parent hub check. So does a missing `ROUTER.md` or a `SKILL.md` with no one-line link to it. The routing prose in `SKILL.md` stays at 12 lines and 180 words at most.

The list of skills excused from the rule is empty, so every skill in the repository passes it. A mode or standalone router may use three deliberate patterns that a hub router may not: an intent that loads nothing, a root file routed without a manifest entry and a second intent table that mirrors the first exactly.

#### One Checked Mode Vocabulary per Hub

A parent hub picks a mode first and a resource second. It wrote the words for those steps in the mode registry, `hub-router.json`, the root router and each packet's trigger line. `hub-router.json` is now the one authored vocabulary, and a check fails CI when any other copy disagrees with it. Closing the drift added the missing terms to every hub's second step.

Five bare phrases came out. "On its own" and "design reference" pulled coding and documentation prompts to the MCP tools. "State machine", "data model" and "style guide" pulled debugging, schema and API-doc prompts to design. Their qualified forms such as `state machine diagram` stay.

#### Docs Around the Move Caught Up

An operator-local alignment check then read each of the 13 skills after the move. It fixed whatever still placed the router in `SKILL.md`: playbook commands and pass criteria, feature catalog rows, README tables and line citations into the shorter files. No fix changed a route.

#### Routing Fixes the Check Found

The check also found routing data it could not change without moving a route, so a follow-up phase fixed it on purpose. "Screen examples" and "extract DESIGN.md" no longer pull requests to the MCP tools, a DESIGN.md repaint reaches the diagram mode and a chart theme request reaches the chart mode. Deep-loop review and council terms reach their modes, and a prose mention of raw passthrough no longer switches `sk-prompt` to its raw mode. An Orca ownership handoff reaches `cli-orca`, "gitlens start review" reaches `sk-git`, and requests that name `system-spec-kit` scripts reach it.

The advisor still scores 155 of 195, 49 of 66 and 19 of 24. The router replay gained one recorded case, the first for `mcp-notion`, and now reads 50 exact of 65. Findings that were correct behavior were refuted with their probe. Requests that open with "Show me" or "Explain" still load no skill, because the advisor holds back on a request to explain something by design.

## Clearer Skill Docs

#### Long Lines Became Short Sentences

Before the pass, 441 prose lines in those docs ran past 400 characters, some past 900, each packing several rules into one sentence. They are now short sentences and lists with the same facts. Each hub also opens How It Works with a glossary of the routing terms it uses.

#### References Follow One Format

Fifty-six skill references, 34 of them in the diagram mode, now open with an overview and number their sections the way the reference template asks. Every section citation inside them was renumbered by one script and checked to land on the same heading. The DESIGN.md format spec and its four samples keep their numbers, because those numbers are the format's own section ids, and the document validator skips them.

#### New Skills Are Checked for Human Voice

The skill templates carry one clarity checklist: instructions first, each fact once, one idea per sentence and second person. `/create:skill` and `/create:skill-parent` score the generated `SKILL.md` and `README.md` with the human-voice scanner and block completion on a hard blocker. The templates now pass that scan themselves, so a new skill no longer fails on its first run.

## Doctor Commands

The doctor family checks and repairs the setup one area at a time. Three commands joined it here. One only reads, and the other two write after a plan and a yes.

#### Skills Are Measured Against the Format

A skill that drifted from the Skilled format used to be a question you answered by reading the format rules and comparing them to a folder by hand. `/doctor:sk-skill` answers it twice: `check` reports how far one skill or the whole fleet is from the format, and `convert` moves one skill onto it.

A bare `/doctor:sk-skill` runs the read-only `check`, so the writing target is only reached when someone types `convert` and names a skill. Each skill gets rows `C1` to `C13` in their shipped order with the repair for every finding, `--json` prints the engine's report alone and `--into-hub <hub>` swaps the rows for the eleven surfaces a skill must land on under that hub. A skill in another repository is judged against that repository, and each row names the repository it read, so a borrowed tool is named as borrowed.

#### A Converted Skill Is Proved and Wired

Both skill shapes convert. An older Skilled skill has its inline router moved into a sibling `ROUTER.md` where it sits, and a plain skill is staged as a copy under `.skilled/skills/<name>` while its source folder is left exactly as it was. Each question is asked on its own, and a no at any of them ends the run with nothing written. A converted plain skill starts with an empty edges map, which the advisor graph refuses as an orphan, so the plan proposes the skill the advisor ranks highest for the approved phrases and only an `enhances` edge is accepted, because it is the one type the skill at the other end never has to mirror.

Nothing is written until the body is proved to survive. Every non-heading line of the source has to appear in the new `SKILL.md`, in `ROUTER.md` or in a reference document, so a rewrite that loses a line stops there instead of shipping. The older Skilled path then runs the same six integration rows as a plain one, each skipping itself when it is already satisfied: the advisor scan, the compiled skill graph, a reach probe against three approved phrases, the regression cases, the Hermes mirror and the changelog entry. A failing row keeps the conversion and names the repair. The run ends with an undo block that restores the files it overwrote and removes the ones it created, and it says that rescuing the advisor graph after an undo is a rescan rather than a copy.

#### The Way In Names the Command

Not knowing which doctor command owns a problem was a problem of its own. `/doctor:helper` takes a problem in plain words and ranks the doctor commands that fit it, with the mutation class and the matched wording on every line. A read-only pick runs in place and a writing pick is printed as one line for you to run, so a command that writes still asks for its own yes.

The root README's doctor section now puts every command in one table, with its targets and which ones write after a yes.

#### The Root Instruction File Is Checked

Every installed repository carries a root instruction file that the framework writes once and never reads back. The template moves on, a fork grows its own sections between the shipped ones, and nothing says which lines belong to the repository and which the next update will overwrite. `/doctor:agents-md check` reports twelve rows, A1 to A12, each on one line with the detail under it: the install state, the sections lost or reordered, how current each shipped body is, every pin, the delivery budget, the shape of your own block, the lines only you carry, each runtime copy, `REPO RULES.md` and the template's own purity.

#### The Write Matches the Plan You Read

`embed` writes only against the digest its own plan printed. The plan composes every target in memory and shows the diffs, the new block, the byte budget, the lines it will keep and a digest, and the apply refuses any bytes that digest no longer describes.

No repository line goes missing. Every path is backed up before the first byte, the write stays inside an allowlist checked in code, and the run then proves against the disk that every line you had is still there and every other line is one the template ships. A dropped line restores itself from the backup and the run ends as a failure.

#### Restore Follows One Run's Record

`restore` is a route, not a manual copy. It puts back exactly the paths one run's own manifest records, removes the files that run created along with any folder it made for them that is empty again, and leaves the backup folder where it is. A record that names another root is refused rather than written to, and the message names the `--root` that would restore that folder.

## Skill Advisor

#### Requests That Used to Miss

A list request that names Orca, such as "List my Orca worktrees and open a terminal in the new one", got no answer, because only a skill's id counted as naming it. For a CLI skill the tool's own name now counts too. Requests phrased as "Orca worktrees" or "managed worktrees in Orca" also reach `cli-orca`.

A request such as "end idle fsmonitor daemons" now reaches `sk-git`, which owns the daemon reaper. "Runtime mirror drift" reaches `/doctor:runtime-mirrors` again instead of `sk-doc`.

#### The Doctor Commands Answer to a Prompt

The four bridges for the helper and for the three agents-md targets were derived but left out of the activation list, so no advisor prompt reached them. They are active now, in both scoring lanes, the doctor routing slice carries their rows and the phrase reach probe proves every phrase and runnable string across 28 bridges. The three labelled prompt sets still read 155 of 195, 49 of 66 and 19 of 24, so a prompt that reached a skill before still reaches it.

#### A Fresh Build Records Itself

The advisor build never wrote its dist freshness record, so the first freshness check after a fresh build wrote one and reported a change nobody made, which failed the first run of a doctor test in a new worktree. The build now prepares and records both dist entries, as the spec-kit build does.

## Commit Hooks

#### Generated Files Match the Commit

The pre-commit hook raises a document's version and checks the copies and routing manifests generated from it. It used to check first and raise second, so a commit shipped copies of the old version and the push guard refused it. The version step now runs first.

A commit that stages only a `ROUTER.md` now rebuilds its hub's compiled routing manifest, which used to go stale. A commit that changes a deep-loop doc now recompiles the deep command contracts that record it, so CI no longer finds them stale. The leaf manifest generator also stops counting git-ignored files when a hook runs it.

&nbsp;

## Safer Git

#### The Advisory Keeps the Directory

The preflight advisory resolves the directory a git command runs in, so a command typed against a worktree is judged by that worktree's state. It recognised `cd <dir> && git ...` and lost the cd when a shell exported a variable in between, which resolved the pathspec against the session checkout and warned that files in the target worktree matched nothing.

A cd that reaches the git command through assignment-only steps now keeps its directory, so `cd <dir> && export A=1; git add <file>` is judged where it runs. Any other command between the two still leaves the directory unproven and the advisory stays silent, because guessing would warn about commands nobody typed.

## Runtimes and Cleanup

#### Pi Loads One Copy of Its Extension

A user-level link that loads the cache optimizer in every project made Pi load two copies of it inside a worktree, and Pi refused to start. The first copy now claims the extension and the second stays quiet.

#### Abandoned Processes Leave Temp Folders

Benchmark browsers, test servers and stuck repros kept running for days from temp and scratch folders, because `.skilled/scripts/orphan-mcp-sweeper.sh` only knew MCP daemons. It now ends a process the system adopted after its parent died, once that process runs from your temp folder, the Claude scratchpad or a worktree `.scratch-*` folder and is six hours old. `ORPHAN_TEMP_PROCESS_AGE_HOURS` moves that floor.

A live session in any of the seven CLI runtimes keeps its helpers. A driver that still runs live sessions is kept, and the skill advisor's servers stay while their launcher lives. Test runs also delete their own temp folders now, so they leave less behind.

#### The Sweep Installs on Any Machine

The launch agent template that schedules the orphan sweep carried a label naming one personal account. It now carries `com.skilled.orphan-sweep`, its file is named after that label, and its install step fills in `/absolute/path/to/repo` and `/absolute/path/to/home` with your repository and home directory as it copies.

Skill docs, playbooks and recorded benchmark evidence also name repository-relative paths now instead of one machine's home folder, and the trigger-phrase migration works out the Claude Code memory folder from the repository it runs in. No recorded result changed.

#### OpenCode Files Have One Home

`.opencode/commands` used to be one link to the shared command tree, so `/goal-opencode`, which works only in OpenCode, had to live in the shared tree. `.opencode/commands` is now a real folder that links each shared command one by one, with `.opencode/commands/goal-opencode.md` as its one OpenCode-native file. Hook links, docs, tests and workflows read the plugins from `.opencode/plugins`, and the old plugin link under `.skilled/` is gone.

&nbsp;

## Retired Surfaces

#### MagicPath and Vision Leave the Framework

**Breaking:** The `mcp-magicpath` mode, the `sk-vision` skill and its `/vision` command no longer exist. A request that names MagicPath ends at the MCP tooling hub's defer path, and no replacement mode exists. The hub now carries eight modes.

#### GPT Models Run on the GPT Provider

The LLM Gateway routes for GPT-6 Luna and Sol came off the Pi and Hermes rosters and the Hermes fan-out allowlist. A Hermes lineage pinned to either gateway id is now refused.

## Upgrade Notes

- **Coming from v4.0.0.17:** that release was withdrawn and this one replaces it. A skill that keeps its router at the end of `SKILL.md` now fails the checks.
- **Skills outside this repository:** move each router into a sibling `ROUTER.md`, link it from SMART ROUTING and run `.skilled/skills/sk-doc/sk-create-skill/scripts/package_skill.py <skill-folder> --check --strict` until it prints `Result: PASS`.
- **Anything that read OpenCode files under `.skilled/`:** read the plugins from `.opencode/plugins` and the goal command from `.opencode/commands/goal-opencode.md`.
- **Callers of MagicPath or `/vision`:** stop. Neither has a replacement.
- **Pi or Hermes setups that use the gateway GPT-6 Luna or Sol ids:** switch to the OpenAI or Codex route.
- **Pi worktree runs:** the fix works once your main checkout has this release, because the user-level link loads the main checkout's copy. Until then `-ne` still works.
- **To schedule the orphan sweep:** copy `.skilled/scripts/launchagents/com.skilled.orphan-sweep.plist`, fill in the two path placeholders and remove `--dry-run` from your copy. The template keeps the flag, so an unedited copy only logs what it would do.
- **An agent you installed from the older template:** it keeps running under its old label until you follow the upgrade step in `.skilled/scripts/launchagents/README.md`, which unloads the old agent, removes its plist and installs a fresh copy.
- **To find the right doctor command:** run `/doctor:helper` with your problem in plain words, or `/doctor:setup` to list every command and target. Neither writes.
- **To pick up the advisor fixes:** rebuild with `npm --prefix .skilled/skills/system-skill-advisor/runtime run build`, restart its daemon, then run `node .skilled/bin/skill-advisor.cjs advisor_rebuild --trusted --force true`.
