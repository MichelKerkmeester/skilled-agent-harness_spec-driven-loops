# v4.0.1.0, Every Skill Routes From Its Own File

A skill is the instruction file an AI agent reads before it starts a job. Until this release each one also carried the routing tables that scripts use to pick its reference files, and the agent loaded those tables every time it read the skill. They now live in a router file per skill, a `ROUTER.md` beside each `SKILL.md`, so the agent reads less while every request routes exactly as it did.

The rest of the routing program tightens the same ground. Each parent hub now has one checked mode vocabulary, new skills are created in the new shape and the skill docs read in short sentences. A check of each skill after the move fixed the docs that still described the old layout.

Around the routing work sit fixes to Pi, the orphan sweep, the commit hooks and the OpenCode file layout. Three retired surfaces are removed, and those removals are the breaking part of this release.

> Spec folders: `specs/sk-doc/072-skill-routing-and-clarity` phases 003 to 013 (Level 3), `specs/sk-doc/072-skill-routing-and-clarity/014-skill-router-files` (Level 2), `specs/sk-doc/072-skill-routing-and-clarity/015-routing-data-alignment` (Level 3), `specs/sk-doc/074-reference-template-debt` (Level 2), `specs/sk-doc/073-opencode-native-surfaces` (Level 2), `specs/hooks/025-cache-optimizer-single-copy-guard` (Level 1), `specs/system-speckit/056-orphan-sweep-temp-processes` (Level 1), `specs/cli-external-orchestration/084-remove-llmgateway-luna-route` (Level 1) and `specs/sk-git/035-fsmonitor-daemon-and-worktree-relocation-regression` (Level 2)

&nbsp;

## Why This Release

Routing tables made up 22 percent of every word in the skill files, and three skills sat within 25 words of the 5,000-word cap, so they could not take a new rule. Most of those tables are pseudocode that only scripts read. Each hub also wrote its routing words in four places that nothing kept in step, so a request could reach a mode and find none of that mode's guidance.

&nbsp;

## What's New at a Glance

- **Each skill keeps its router in its own file.** The `SKILL.md` an agent loads is about 27 percent smaller across the 54 skills and modes.
- **No request routes differently.** The advisor's accuracy and a replay of the recorded routing cases match their readings from before the move.
- **New skills start in the new shape.** The package checks reject a skill that keeps its router inside `SKILL.md`.
- **Each hub has one checked mode vocabulary.** Five generic phrases no longer pull ordinary prompts to the wrong hub.
- **Skill docs read in short sentences.** No prose line in a skill, command or agent doc runs past 400 characters.
- **More requests reach the right skill.** Orca handoffs, GitLens reviews, deep-loop terms and DESIGN.md theming now reach the skill or mode that owns them, and two phrases that pulled design requests to the MCP tools are gone.
- **Commit hooks keep generated files current.** A commit that raises a document version or stages only a router file no longer ships stale copies.
- **Pi starts inside a git worktree again.** A worktree run no longer needs `-ne`.
- **Abandoned processes in temp folders get cleared.** The orphan sweep ends them without touching a live session's helpers.
- **OpenCode-only files live in `.opencode/`.** The shared tree no longer carries an OpenCode command or the OpenCode plugins.
- **MagicPath, sk-vision and two gateway model routes are removed.** GPT-6 Luna and Sol stay available on the OpenAI and Codex routes.

&nbsp;

## Skill Routing

#### The Router Leaves the Skill File

Every skill used to end with a machine router section: the intent tables, resource maps and pseudocode that scripts read to decide which reference files to load. That section now closes a `ROUTER.md` beside the `SKILL.md`, and the routing section of `SKILL.md` ends with one link to it. The seven parent hubs already had a root router file, so their section joined it. The cycle first moved each router to the end of its `SKILL.md`, the shape the withdrawn v4.0.0.17 described, and then out into its own file.

Measured over the 54 skills and modes, the `SKILL.md` files fell from 328,333 tokens to 238,406. That figure runs from just before the move to this release, so it also counts the doc fixes made after it.

The tools that read a router follow it. Router replay, the dead-route scan, compiled hub routing and the skill advisor's freshness check read `ROUTER.md`, so an edit to a router alone now reaches the advisor. The Hermes copy of each skill carries its router file, with relative links rewritten so they still resolve. The same move was carried out on the 16 skills in the separate AI Systems repository.

#### Routing Accuracy Held Through the Move

The move changed where each router lives and nothing it decides. The advisor still scores 155 of 195, 49 of 66 and 19 of 24 on its three labelled prompt sets. The replay report is byte-identical before and after. Every router parses the same as it did before the move, and that held after each doc fix that followed.

#### New Skills Start in the New Shape

`/create:skill` and `/create:skill-parent` write a `ROUTER.md` beside every new `SKILL.md`, laid out like `.skilled/skills/sk-doc/sk-create-skill/assets/skill/skill-router-template.md`. A router section left in `SKILL.md` fails both `package_skill.py --strict` and the parent hub check. So does a missing `ROUTER.md` or a `SKILL.md` with no one-line link to it. The routing prose in `SKILL.md` stays at 12 lines and 180 words at most.

The list of skills excused from the rule is empty, so every skill in the repository passes it. A mode or standalone router may use three deliberate patterns that a hub router may not: an intent that loads nothing, a root file routed without a manifest entry and a second intent table that mirrors the first exactly.

#### One Checked Mode Vocabulary per Hub

A parent hub picks a mode first and a resource second. It wrote the words for those steps in the mode registry, `hub-router.json`, the root router and each packet's trigger line. `hub-router.json` is now the one authored vocabulary, and a check fails CI when any other copy disagrees with it. Closing the drift added the missing terms to every hub's second step.

Five bare phrases came out. "On its own" and "design reference" pulled coding and documentation prompts to the MCP tools. "State machine", "data model" and "style guide" pulled debugging, schema and API-doc prompts to design. Their qualified forms such as `state machine diagram` stay.

#### Docs Around the Move Caught Up

An operator-local alignment check then read each of the 13 skills after the move. It fixed whatever still placed the router in `SKILL.md`: playbook commands and pass criteria, feature catalog rows, README tables and line citations into the shorter files. No fix changed a route.

#### Routing Fixes the Check Found

The check also found routing data it could not change without moving a route, so a follow-up phase fixed it on purpose. "Screen examples" and "extract DESIGN.md" no longer pull requests to the MCP tools, a DESIGN.md repaint reaches the diagram mode and a chart theme request reaches the chart mode. Deep-loop review and council terms reach their modes, and a prose mention of raw passthrough no longer switches `sk-prompt` to its raw mode. An Orca ownership handoff reaches `cli-orca`, "gitlens start review" reaches `sk-git`, and requests that name `system-spec-kit` scripts reach it.

The advisor still scores 155 of 195, 49 of 66 and 19 of 24. The router replay gained one recorded case, the first for `mcp-notion`, and now reads 50 exact of 65. Findings that were correct behavior were refuted with their probe. Requests that open with "Show me" or "Explain" still load no skill, because the advisor holds back on a request to explain something by design.

## Clearer Skill Docs

#### Long Lines Became Short Sentences

Before the pass, 441 prose lines in those docs ran past 400 characters, some past 900, each packing several rules into one sentence. They are now short sentences and lists with the same facts. Each hub also opens How It Works with a glossary of the routing terms it uses.

#### References Follow One Format

Fifty-six skill references, 34 of them in the diagram mode, now open with an overview and number their sections the way the reference template asks. Every section citation inside them was renumbered by one script and checked to land on the same heading. The DESIGN.md format spec and its four samples keep their numbers, because those numbers are the format's own section ids, and the document validator skips them.

#### New Skills Are Checked for Human Voice

The skill templates carry one clarity checklist: instructions first, each fact once, one idea per sentence and second person. `/create:skill` and `/create:skill-parent` score the generated `SKILL.md` and `README.md` with the human-voice scanner and block completion on a hard blocker. The templates now pass that scan themselves, so a new skill no longer fails on its first run.

## Skill Advisor

#### Requests That Used to Miss

A list request that names Orca, such as "List my Orca worktrees and open a terminal in the new one", got no answer, because only a skill's id counted as naming it. For a CLI skill the tool's own name now counts too. Requests phrased as "Orca worktrees" or "managed worktrees in Orca" also reach `cli-orca`.

A request such as "end idle fsmonitor daemons" now reaches `sk-git`, which owns the daemon reaper. "Runtime mirror drift" reaches `/doctor:runtime-mirrors` again instead of `sk-doc`.

&nbsp;

## Commit Hooks

#### Generated Files Match the Commit

The pre-commit hook raises a document's version and checks the copies and routing manifests generated from it. It used to check first and raise second, so a commit shipped copies of the old version and the push guard refused it. The version step now runs first.

A commit that stages only a `ROUTER.md` now rebuilds its hub's compiled routing manifest, which used to go stale. A commit that changes a deep-loop doc now recompiles the deep command contracts that record it, so CI no longer finds them stale. The leaf manifest generator also stops counting git-ignored files when a hook runs it.

&nbsp;

## Runtimes and Cleanup

#### Pi Loads One Copy of Its Extension

A user-level link that loads the cache optimizer in every project made Pi load two copies of it inside a worktree, and Pi refused to start. The first copy now claims the extension and the second stays quiet.

#### Abandoned Processes Leave Temp Folders

Benchmark browsers, test servers and stuck repros kept running for days from temp and scratch folders, because `.skilled/scripts/orphan-mcp-sweeper.sh` only knew MCP daemons. It now ends a process the system adopted after its parent died, once that process runs from your temp folder, the Claude scratchpad or a worktree `.scratch-*` folder and is six hours old. `ORPHAN_TEMP_PROCESS_AGE_HOURS` moves that floor.

A live session in any of the seven CLI runtimes keeps its helpers. A driver that still runs live sessions is kept, and the skill advisor's servers stay while their launcher lives. Test runs also delete their own temp folders now, so they leave less behind.

#### OpenCode Files Have One Home

`.opencode/commands` used to be one link to the shared command tree, so `/goal-opencode`, which works only in OpenCode, had to live in the shared tree. `.opencode/commands` is now a real folder that links each shared command one by one, with `.opencode/commands/goal-opencode.md` as its one OpenCode-native file. Hook links, docs, tests and workflows read the plugins from `.opencode/plugins`, and the old plugin link under `.skilled/` is gone.

&nbsp;

## Retired Surfaces

#### MagicPath and Vision Leave the Framework

**Breaking:** The `mcp-magicpath` mode, the `sk-vision` skill and its `/vision` command no longer exist. A request that names MagicPath ends at the MCP tooling hub's defer path, and no replacement mode exists. The hub now carries eight modes.

#### GPT Models Run on the GPT Provider

The LLM Gateway routes for GPT-6 Luna and Sol came off the Pi and Hermes rosters and the Hermes fan-out allowlist. A Hermes lineage pinned to either gateway id is now refused.

&nbsp;

## Upgrade Notes

- **Coming from v4.0.0.17:** that release was withdrawn and this one replaces it. A skill that keeps its router at the end of `SKILL.md` now fails the checks.
- **Skills outside this repository:** move each router into a sibling `ROUTER.md`, link it from SMART ROUTING and run `.skilled/skills/sk-doc/sk-create-skill/scripts/package_skill.py <skill-folder> --check --strict` until it prints `Result: PASS`.
- **Anything that read OpenCode files under `.skilled/`:** read the plugins from `.opencode/plugins` and the goal command from `.opencode/commands/goal-opencode.md`.
- **Callers of MagicPath or `/vision`:** stop. Neither has a replacement.
- **Pi or Hermes setups that use the gateway GPT-6 Luna or Sol ids:** switch to the OpenAI or Codex route.
- **Pi worktree runs:** the fix works once your main checkout has this release, because the user-level link loads the main checkout's copy. Until then `-ne` still works.
- **To schedule the orphan sweep:** copy the launch agent template from `.skilled/scripts/launchagents/` and remove `--dry-run` from your copy. The template keeps the flag, so an unedited copy only logs what it would do.
- **To pick up the advisor fixes:** rebuild with `npm --prefix .skilled/skills/system-skill-advisor/runtime run build`, restart its daemon, then run `node .skilled/bin/skill-advisor.cjs advisor_rebuild --trusted --force true`.
