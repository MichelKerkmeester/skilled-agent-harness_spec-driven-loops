# v4.0.0.10, Adapt sk-code to Your Stack, Keep Untrusted Clones Out

v4.0.0.10 makes the code skill adapt to your own stack. OpenCode stays as the native surface, the shipped examples are yours to remove and a surface of your own can land ahead of it. A new guide walks you from a fresh clone to a working setup, and one command proves the result.

The git hooks are safer too. A cloned repository the hooks do not trust can no longer run its own code through them, and every commit in a repository that uses ids now carries a Commit-Id.

Pi also starts its GPT targets in Fast Mode.

&nbsp;

## Why This Release

The git hooks are installed once for every repository on a machine, and in a repository they did not trust they still read their helpers from that repository's own tree.

Commit-Id stamping also stopped quietly in those repositories.

Adapting the code skill was not a supported path either. The README told you to replace all three code surfaces, the native one included. Removing an example broke the checks, and a surface you added lost every keyword tie to OpenCode.

&nbsp;

## What's New at a Glance

- **An untrusted clone cannot run code through your git hooks.** The hooks, installed once for every repository, now read their helpers from a path no repository can fill, and they still trust your own checkout, its worktrees and any repository you mark trusted.
- **Every commit carries a Commit-Id.** A repository that uses ids refuses a commit or a push without one, and the stamp comes from an allocator shipped beside the hooks rather than from code in the repository.
- **The code skill adapts to your own stack.** OpenCode is the native surface and stays, Webflow and Obsidian are examples you can remove and a surface you add lands ahead of OpenCode.
- **The adapting guide starts from a fresh clone.** It opens with the provision command, then covers the hooks to install, the folders to keep, removing an example, adding a surface and the checks that prove each step.
- **Removing an example keeps the checks working.** The drift guards read only the surfaces on disk and the documentation claim checker takes its count from the mode registry, so a hub with two surfaces still passes.
- **Failures name their fix.** A missing surface folder, a hub that needs its routes re-minted and a fresh clone all say what to run next, instead of a bare message or a stack trace.
- **One command checks the setup.** `/doctor:sk-code setup` runs eight read-only checks from the repository root and prints the command that clears each failing one.
- **Pi starts GPT targets in Fast Mode.** The extension is on by default in new worktrees too, and `/fast off` stays off after a restart.

## Hook Safety and Commit-Id

#### Untrusted Clones Cannot Run Code Through the Hooks

The git hooks are installed once for every repository on a machine. For a repository they do not trust, they used to read their helpers from a `.skilled-untrusted` folder inside that same repository, so a clone could plant a guard library or a Commit-Id allocator there and have it run on your next commit, pull or push. An untrusted repository's helpers now resolve under `/dev/null`, which no repository can fill, so the hooks read nothing from its tree. The hooks still trust their own checkout and its worktrees, and any repository whose local config sets `skilled.trustRepoHooks=true`. Trust covers the repository, not a branch, so review an untrusted branch in a separate clone.

#### Every Commit Carries a Commit-Id

The commit hooks used to mint a Commit-Id only through the repository's own allocator, which the hook trust gate hides in an untrusted clone, so commits there went out with no id and nothing said so. `prepare-commit-msg` now falls back to the allocator shipped beside the hooks, without running code from the repository, and it stamps a continued revert and a squash commit too. In a repository that uses ids, `commit-msg` refuses a message without one and `pre-push` refuses any added non-merge commit without one. A repository uses ids when it ships the sk-git allocator or spec-kit, or when its last 50 commits carry one. `git config --local skilled.commitId true` or `false` decides before either test. Both checks refuse `0000000`, an id the allocator never mints.

## Adapting the Code Skill

#### OpenCode Is Native and the Examples Are Optional

OpenCode (`sk-code-skilled`) is the native code surface and stays. Webflow (`sk-code-webflow`) and Obsidian (`sk-code-obsidian`) are optional examples you can remove. The README, the hub `SKILL.md` and the hub README now say so, and none of them tells you to replace OpenCode. The README block "What Adapting `sk-code` Looks Like" covers the hooks to install, the folders to keep, removing an example, adding a surface and the checks that prove each step.

#### The Guide Starts From a Fresh Clone

The block's "Before you start" step opens with `bash .skilled/skills/sk-git/scripts/worktree-naming.sh provision .` for a fresh clone and `git config --local skilled.trustRepoHooks true` for a clone that should run the hooks. The removal steps name the two feature-catalog files and regenerate `graph-metadata.json` with `regenerate-skill-derived.cjs`. The add steps name `leaf-scopes.json` and the surface-count lines the documentation claim checker reads.

#### A New Surface Lands Ahead of OpenCode

`/create:skill-parent update --surfaces` writes a new surface into `routerPolicy.tieBreak` after the workflow modes and ahead of the existing surfaces, several in the order you give them, so it wins a keyword tie against OpenCode. Its report names the two steps it cannot run for you: a canary case with its fixture copy and a commit with the hooks installed. If you edit `hub-router.json` by hand and list your own surface after `sk-code-skilled`, the parent-skill doctor fails and says to move it ahead.

#### Removing an Example Keeps the Checks Working

The sk-code drift guards read only the surface packets on disk and skip archived route gold for a mode the hub no longer declares. The documentation claim checker takes the surface count from `mode-registry.json`, so "two surfaces" passes on a hub with two. Removing an example no longer makes a guard throw.

#### Failures Name Their Fix

When a surface folder is missing, the doctor names the README block that finishes the removal. When a hub's routing inputs change without a re-mint, the compiled-route guard used to print only `Re-mint: <hub>`, and it now names the `compiled-route-manifest.cjs` refresh command, both manifest paths and the copy that clears it. A missing authored compiled-routing folder under `specs/` stops sync and the guard with the folder to restore, where before they passed or printed a stack trace. In a fresh clone `ci-skill-root-metadata.cjs` printed a raw Node stack, and it now prints one line naming the provision command.

#### One Command Checks the Setup

`/doctor:sk-code setup` runs eight read-only checks from the repository root: provisioning, the parent-skill doctor, root metadata, the compiled-route guard, sync, the drift guards, derived freshness and a route probe. Each prints PASS, SKIP or FAIL with a `repair:` line naming the command that clears it, and the run ends `STATUS=OK legs=8` or `STATUS=FAIL failed=<n> skipped=<n>`. The probe passes only on a real compiled route, and it names `SPECKIT_COMPILED_ROUTING` when that variable has switched compiled routing off. On a checkout older than v4 the run reports the missing layout once and skips the other seven checks. `--prompt=<text>` sets the probe's prompt, and the run writes nothing. The probe line it prints quotes the prompt, so pasting the line reruns the same prompt.

## Pi

#### Pi Starts GPT Targets in Fast Mode

The Pi Fast Mode extension is now on by default, in new worktrees too. It still changes only the provider and model pairs in its configuration. A saved state, the `--fast` flag and the value a parent hands to its subagents still decide over the default, so `/fast off` stays off after a restart.

&nbsp;

## Upgrade Notes

- **Update every machine that has the hooks installed.** A machine on an older copy still lets a cloned repository run its own code through the hooks. Pull this release in the checkout the hooks link to. In a repository of your own that should run the full checks, run `git config --local skilled.trustRepoHooks true`.
- **Expect a Commit-Id check at commit and push.** A repository that uses ids refuses a commit without a `Commit-Id` trailer. Install the hooks so `prepare-commit-msg` stamps one, or run `git config --local skilled.commitId false` in a repository that should not use them.
- **Run `/doctor:sk-code setup` after you adapt sk-code.** It names the command that clears each failing check.
- **Turn off Pi Fast Mode with `/fast off`.** Run it once, and the saved state outlasts a restart.
