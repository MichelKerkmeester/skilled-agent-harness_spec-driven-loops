# v4.0.0.7, The Deep Loop Runs Three Modes, and Routing Reads Intent

v4.0.0.7 retires two unused deep-loop modes.

- Three modes remain: research, review and AI Council.
- The two commands, agent and runtime code are gone.
- Nothing replaces the retired modes.

The skill advisor now reads a request for what it asks.

- It ignores skill names inside file paths.
- Code-writing requests reach the code skill.
- Routing drift now fails CI.

Smaller fixes protect a finished run and a research merge.

- A finished run no longer starts a research loop.
- Hand-written dashboards no longer enter a research merge.

> [!IMPORTANT]
> 1 change can break an existing setup. Read these before you update.
>
> 1. `/deep:agent-improvement` and `/deep:model-benchmark` no longer exist. [Retired deep-loop modes](#c-two-unused-modes-are-retired)

&nbsp;

## Why This Release

Two deep-loop modes were unused. Routing drift was easy to miss.

- Yet their commands stayed available.
- Their agent shipped in every runtime.
- The libraries they ran on stayed in the tree.
- The skill advisor could still route a prompt to either one.
- The advisor also counted a skill name wherever it appeared.
- That included a name inside a file path.
- So a passing mention could pull a route.
- A request to write a Vitest suite or a small helper used to start the deep-review loop.
- It could also reach spec-kit.
- CI did not fail when the Python and Node advisors disagreed on a route.
- The freshness check let a stale or missing compiled entry pass.
- The documented rebuild also did not work on a clean checkout.

## Deep Loop Modes

The deep loop now runs three modes. Two unused modes are gone.

#### Two Unused Modes Are Retired <a id="c-two-unused-modes-are-retired"></a>

> [!WARNING]
> `/deep:agent-improvement` and `/deep:model-benchmark` no longer exist. Nothing in the repository replaces them. Stop using the two retired deep-loop commands.

- Both modes left the mode registry.
- Their packet and agent left every runtime.
- The runtime libraries they ran on left too.
- `system-deep-loop` now routes three modes: research, review and AI Council.
- The skill advisor no longer routes a prompt to either mode.
- No other skill documents or links to them.
- Benchmark authoring keeps two families, behavior and MCP promotion.
- Spec validation no longer checks a packet's `improvement/` folders.
- So older packets that hold one stay valid as history.
- Two Jev switches were read only by the benchmark mode.
- They now do nothing.

#### A Finished Run Does Not Start Another <a id="c-a-finished-run-does-not-start-another"></a>

- A prompt that mentions a run you already finished no longer starts a research loop.
- One example is "We just finished a deep-research run. Initialize the deep-loop graph".
- The deep-loop hub asks what you want instead.
- A request that follows the finished-run clause still routes.

#### The Agent Mirror Checker Has a New Home <a id="c-the-agent-mirror-checker-has-a-new-home"></a>

- The checker keeps each runtime's agent copies in step.
- It lived inside the retired packet.
- It now sits at `.skilled/bin/check-agent-mirror-sync.cjs`.

#### Research Merges Refuse Unstamped Lineages <a id="c-research-merges-refuse-unstamped-lineages"></a>

- A deep-research fan-out merge now refuses a lineage whose `deep-research-dashboard.md` lacks the reducer stamp.
- The stamp is `description: Auto-generated reducer view over the research packet.`.
- Without the stamp the dashboard was written by hand.
- So the lineage's registry is left out of the merge.
- The attribution table shows REFUSED in that lineage's Verdict cell.
- The JSON output lists it under `refused_reducer_provenance`.
- A lineage with no dashboard at all still merges.
- It gets a warning under `reducer_provenance_warnings`.
- That is because nothing shows its registry was written by hand.
- A dashboard that cannot be read refuses only that one lineage.
- It does not refuse the whole merge, and the merge status stays `ok`.

## Skill Routing

The skill advisor now reads a request for what it asks. Routing drift now fails CI.

#### Paths and Doc Targets No Longer Pull Routes <a id="c-paths-and-doc-targets-no-longer-pull-routes"></a>

- The skill advisor no longer counts a skill name inside a file path.
- It also skips a name right before `SKILL.md`, `ROUTER.md`, a README or a changelog.
- A write aimed at a skill's own doc skips that skill's author phrases.
- The word "findings" no longer boosts a route.
- "Changelog" counts as a doc target only as `changelog.md` or a `changelog/` path.
- So a prompt that names the sk-doc changelog mode reaches sk-doc again.
- The Python advisor also stays on the native scorer after the daemon idles out.
- It used to fall back to a local scorer without these rules.

#### Requests to Write Code Reach the Code Skill <a id="c-requests-to-write-code-reach-the-code-skill"></a>

- A request to add, build, create, implement or write a helper, test or Vitest suite now routes to sk-code.
- It does so even when it names a deep-review phrase or a study artifact.
- "Write a Vitest covering the resume deep review phrase" used to start the deep-review loop.
- "Add a packet-local helper that formats confusion-matrix rows" used to reach spec-kit.
- A real deep-review resume routes as before.
- An edit to a study template routes as before.
- The Python and Node advisors now agree on these prompts.

#### Routing Drift Fails CI <a id="c-routing-drift-fails-ci"></a>

- `skill-graph-freshness.cjs --strict` exits 1 on a stale, unreadable, ghost or missing compiled entry.
- It also exits 1 on intent-signal drift and on a skill family mismatch.
- It names the compiler command.
- The routing drift workflow runs it beside the intent-signal check.
- `compiled-route-sync.cjs --check` now compares every served file with its authored source byte for byte.
- It names each copy that differs or is missing.
- The documented compiled-route rebuild works on a clean checkout again.

#### The Two Advisors Must Agree in CI <a id="c-the-two-advisors-must-agree-in-ci"></a>

- The routing drift workflow fails a pull request.
- That happens when the Python and Node advisors route a prompt differently.
- It also fails when the approved divergence ledger does not list the difference.
- It fails when a listed divergence no longer happens.
- The check scores against a skill graph built fresh from the checkout.
- It uses the time the ledger records, so a CI result matches a local run.
- A second step fails when a scoring surface reads held-out evaluation prompts without declaring them.

## Upgrade Notes

Stop using the two retired deep-loop commands. The other actions are grouped below.

#### Before You Start <a id="c-before-you-start"></a>

1. Stop using `/deep:agent-improvement` and `/deep:model-benchmark`. They have no replacement.

<details>
<summary><b>Deep Loop Modes</b></summary>

- Older spec packets that hold `improvement/` folders need no change.
- A fan-out research merge now refuses any lineage whose dashboard lacks the reducer stamp.
- Rerun the reducer for that lineage so its dashboard carries the stamp.
- Then merge again.
- Repoint the agent mirror checker.
- Run `.skilled/bin/check-agent-mirror-sync.cjs`.
- That is because the old path inside the retired packet is gone.
- Delete two unused Jev switches.
- `JEV_FEATURE_VERDICT_FALLBACK` and `JEV_FEATURE_HALLUCINATION_GRADER` backed only the retired benchmark mode.
- They no longer have a reader.
- So their lines in your own `.env` are safe to delete.
