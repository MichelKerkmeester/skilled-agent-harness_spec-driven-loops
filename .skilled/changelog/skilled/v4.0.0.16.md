# v4.0.0.16, Cheaper CI, Private Skills and Code Modes for Any Repository

CI now runs only where it has work to do. A commit that only rebuilds an index starts no workflow, and a pull request stops paying for a run that a newer push replaced. Skipping that one commit alone cut a measured day's runner-minutes by 43 percent.

The Webflow and Obsidian code guides moved out of the public tree into private skills. That move is the one breaking change in this release.

The code modes now work outside this repository. The quality gate prints one verdict anywhere, and a review raises a blocking finding only for input the code can actually receive. A repository can also drop or replace any quality or review rule outside a fixed floor. The documentation and dependency alert checks both came back clean.

Finished worktrees now remove themselves, the skill advisor routes several requests it used to misread and an interrupted deep-loop lane resumes.

> Spec folders: `specs/system-speckit/053-ci-workflow-efficiency` (Level 2), `specs/sk-code/013-private-surface-skills` (Level 2), `specs/sk-code/014-code-modes-research` (Level 2), `specs/sk-code/015-quality-agnostic-gate` (Level 2), `specs/sk-code/016-review-mode-followups` (Level 2), `specs/sk-code/017-portable-code-modes` (Level 2), `specs/sk-git/035-fsmonitor-daemon-and-worktree-relocation-regression` (Level 2), `specs/sk-doc/070-repo-doc-debt` (Level 2), `specs/sk-doc/071-readme-reference-debt` (Level 2), `specs/system-skill-advisor/039-executor-workflow-owner-guard` (Level 2), `specs/system-deep-loop/043-fanout-resume-and-containment` (Level 2), `specs/cli-external-orchestration/083-gpt-6-1-terra-roster` (Level 1) and `specs/system-speckit/054-weak-model-spec-authoring` phases 025 to 028 (Level 2)

## Why This Release

More than half of the repository's daily CI time came from one automated commit that re-ran thirteen workflows on files they never read. The code modes had the opposite problem. They assumed this repository's layout and house style, fell back to generic advice anywhere else and gave a repository no way to switch a rule off. Every clone also received two sets of guides written for one operator's own projects. And closing a spec folder wrote a third changelog that repeated what its implementation summary already said.

Smaller gaps cost time every day. Merged worktrees stayed on disk, an interrupted deep-loop lane could not resume and the skill advisor sent some clear requests to the wrong skill.

&nbsp;

## What's New at a Glance

- **CI skips work nobody reads.** Rebuild commits start no workflow, older pull-request runs cancel and path filters keep a workflow off files it never touches.
- **CI has switches and a doctor command.** Six repository variables turn CI groups off, and `/doctor:ci` manages the workflows and their switches. In another repository it reads that repository's own conventions from a CI profile.
- **The Webflow and Obsidian guides are private.** A clone that used them no longer gets them from `sk-code`.
- **A quality gate works in any repository.** A repository can also name its own checks in `.skilled/skills/sk-code/sk-code-quality/repository/quality.json`.
- **Review severity follows the code's contract.** A P0 or P1 has to name an input the contract allows, or a caller that sends it. The review agent's pass or fail now follows severity alone.
- **A repository can change the code rules.** Named comment-hygiene rules can be switched off, and this repository's house style now loads only for its own code.
- **Old git daemons and finished worktrees no longer pile up.** Session launches and worktree removal now end the fsmonitor daemons nobody is using, and a session-start sweep removes numbered worktrees whose branch has merged. `SPECKIT_WORKTREE_AUTOREAP=0` turns the sweep off.
- **Spec folders no longer hold changelogs.** Changelogs live in `.skilled/changelog/` and each skill's own `changelog/` folder, and `/create:changelog` refuses `--nested`. An untagged release now takes new work into its own entry.
- **The skill advisor routes more requests as asked.** A named workflow stays ahead of the executor that runs it, typed doctor targets reach their own route and two launchers that start together share one daemon.
- **Deep-loop lanes survive interruptions and shared edits.** A resumed lane runs its executor again, an operator's own edit is no longer quarantined and pi runs GPT-6.1 Terra in deep loops and in fast mode.
- **Open dependency alerts are at zero.** All but one were fixed by updating the package itself.
- **Every README and changelog passes its audit.** The README audit stopped flagging correct documents, and the stricter README checkers now also check slash commands and more count claims.

## CI and GitHub Actions

The repository's 33 workflows used about 3,812 runner-minutes a day before this release.

#### Rebuild Commits Skip CI

The trigger-index rebuild is a bot commit that writes generated files, and it re-ran 13 workflows that read none of what it wrote. A skip condition now keeps that commit out of CI entirely. A day measured after this change alone used 2,191 runner-minutes.

#### Smaller Cuts Across the Pipeline

A pull-request run cancels the moment a newer push arrives, so an outdated run stops instead of finishing work a newer commit replaced. Path filters stop a workflow from running on files it never reads. Checkouts fetch less history and one shared setup step owns the caching. Two overlapping workflows are now one.

#### Slowest Tests Run in Halves

The spec-kit CLI tests were the slowest single step in the pipeline. They now run as two halves at the same time, at a median of 451 seconds against about 791 before.

#### Six Switches and a Doctor Command

Six repository variables turn CI groups off: `SKILLED_CI` and five `SKILLED_CI_*` group switches. Everything defaults to on, so a clone that sets nothing keeps every check. `/doctor:ci` lists the workflows with their on or off state, scaffolds a new workflow and flips a switch. Each write waits for an approved plan.

#### The CI Doctor Reads a Repository Profile

`/doctor:ci` was written for this repository, so in another one its report flagged every workflow and its toggle refused every switch. Each route now reads the repository's conventions from a CI profile in the sk-code-ci skill folder, `.skilled/skills/sk-code/sk-code-ci/repository/ci.json`, such as its default branch, its switch variables and its protected workflows. Without a profile it forces none of them and reads any variable a job compares against `off` as a switch. This repository commits its own profile, so nothing changes here.

The toggle now also refuses a variable that would skip a check the branch ruleset requires. Switching off a protected workflow asks for the variable name a second time.

#### A Skill Mode for Workflow Files

`sk-code-ci` is a new mode in `sk-code` and the standard for writing a GitHub Actions workflow. It covers triggers, permissions, timeouts, caching and pinned action versions.

#### A Timeout and a Permission List per Job

Every job now carries a timeout and only the permissions it needs. A job that hangs fails on its own clock, and a job that never needed write access no longer holds it.

#### Nine Workflows Stay Separate

Merging nine workflows into one file would have saved about 636 runner-minutes a day. The change was declined, because each check has to keep its own pass or fail.

## Private Webflow and Obsidian Skills

#### The Guides Leave the Public Tree

The Webflow and Obsidian code guides held 226 files and about 2 MB between them. The previous release called them optional examples. They are now gone from the public tree, and `sk-code` ships its quality, review, skilled and ci modes.

**Breaking:** A clone that used the Webflow or Obsidian surfaces no longer gets them from `sk-code`. Add your own surface or keep a private, git-ignored skill.

#### Two Private Skills Replace Them

The operator's own copies live in two private skills that git ignores. A commit check refuses to stage either one in any runtime folder, and the skill advisor follows them only on the machine that has them.

#### The Guard Has Limits

`git commit --no-verify` and `git add -f` both bypass the commit check, and the removed files remain in git history. The check stops an accident, not a decision.

## Code Quality in Any Repository

#### One Verdict, Anywhere

The quality mode used to read this repository's layout, and outside it fell back to general advice. Now `node .skilled/skills/sk-code/sk-code-quality/scripts/quality-gate.cjs` prints one verdict for a change in any repository, such as `BLOCKED` or `NO_BLOCKER_FOUND`.

#### A Repository Names Its Own Checks

A repository can commit `.skilled/skills/sk-code/sk-code-quality/repository/quality.json` to name the checks a change has to pass. `/doctor:sk-code quality` plans the file from the repository's own scripts, writes it on `--apply`, refuses to overwrite one that exists and checks it.

#### No Known Surface Still Finishes

A repository whose surface the gate does not recognise still reaches a verdict, on a universal floor of built-in checks.

#### A Done Claim Needs Gate Evidence

An implementation report can no longer call a change done without gate evidence behind it.

#### Comments Read the Same Everywhere

The comment hygiene checker and its report now read a comment the same way in every language they cover. The checker's findings over this repository fell from 63 to zero.

## Code Review

#### Severity Follows the Contract

A P0 or P1 finding has to name an input the code's stated contract allows, or a real caller that sends the failing input. Missing validation for input the contract never allows is P2 hardening. At a trust boundary every value is in reach. The rule settled a false P1 on a clean file, and it now guides the deep review as well.

#### Measured on Live Reviews

In three live runs per case, the review caught a seeded injection bug and a seeded off-by-one bug every time at the right severity. The clean file drew no blocking finding.

#### Workflow Reviews Load the Review Mode

A review of a workflow file used to load the CI standards and stop there. It now loads the review mode plus those standards, so the review reads the workflow the same way it reads a code change.

#### A Disagreeing Summary Fails Its Check

A review report whose summary disagrees with its status line now fails its own check. The report also carries a quality-gate evidence line.

#### A Cache Key Without an Origin

The review cache key now works in a repository with no `origin` remote.

#### The Review Agent Follows the Mode

The review agent used to fail any change that scored below 70, even with no blocking finding, which contradicted the mode's rule that a P2 never blocks. Its verdict now follows severity alone. Any P0 or open P1 fails the review, and the 100-point score is advisory.

The agent also dropped its own house checks, such as commit format and change size. It reads pull request and commit rules from what the reviewed repository declares. The report checkers fail a recommendation that approves over a P0 or P1 finding.

## Rules a Repository Can Change

#### Drop or Replace a Rule

A repository that wanted a different house style had no way to say so, because the shipped rules could only be added to. A checklist can now carry a `## Rule overrides` table. Each row names one rule id and either drops that rule or replaces its text. Every quality and review rule carries an id and a mark that says whether a repository may change it, and a linter checks the section before anything reads it.

#### A Fixed Floor Stays

Parse faults, conflict markers, credentials, input validation, silent failures, resource cleanup, accessibility and the review's severity and security rules can never be overridden. When two checklists at the same level disagree, the rule keeps its default and the gate reads `UNVERIFIED`.

#### Hygiene Rules a Repository Can Switch Off

The 21 core comment-hygiene rules used to block every repository, so a comment such as `Fixes #12` failed rules written for this framework's own planning labels. `commentHygiene.disableRules` in the repository quality config, `.skilled/skills/sk-code/sk-code-quality/repository/quality.json`, now switches named rules off, and the pre-commit hook and the CI hygiene job honor it. The secret and conflict-marker checks stay on.

#### House Style Moved to the Skilled Surface

Every quality run used to load this repository's style guide and, for any `.js` or `.css` file, three checklists of web house style. The shared floor and style guide now hold only rules that hold anywhere. Naming schemes, file layout, line length, required docstrings and strict typing moved to `sk-code-skilled`, which loads only for this repository's code, so its files keep the same rules as before.

#### Review Splits a Floor From a Lens

Review used to apply this repository's preferences to every codebase. Its rules are now either floor, such as security, error handling and test reliability, or a default lens of house rules such as function length and nesting that a repository may drop or replace. Review asks the quality runner which surfaces and checklists apply to each file. Every full review names the checklists it read and each override it applied on a `Rule sources:` line.

Some defaults changed for every repository. A breaking API change or an assertion-free test is P1 at most. Web checks such as XSS and CORS apply only to code that serves or calls HTTP, and the TODO rule no longer asks for a ticket id.

#### The Run Applies Overrides and the Doctor Shows Them

A quality run reads every override section it loads. A section that names a fixed rule or an unknown rule id ends the run with `CONFIG_INVALID`, and each accepted row is recorded in the run's decisions. `/doctor:sk-code quality` lists each checklist with its override rows and the hygiene rules in force.

## Git Worktrees

#### A Reaper for fsmonitor Daemons

On macOS a git fsmonitor daemon never exits on its own, so daemons piled up, one per worktree, and a stuck one held a push open for about 30 minutes. `.skilled/bin/fsmonitor-daemon-reaper.sh` finds a repository's daemons by the worktree each one watches and ends the ones nobody needs. A plain run only reports, and `--apply` acts. Each top-level session launch starts a detached sweep that ends the daemon of any worktree older than 12 hours that no running process is using. Removing a worktree ends its daemon first, and the doctor's worktrees row shows the daemon counts.

#### The Worktree Base Stays Where You Set It

A session launch without `SPECKIT_WORKTREE_BASE` used to record the default base inside the checkout, so every later worktree landed there from then on. The launch now records a base only when it came from `SPECKIT_WORKTREE_BASE`, and logs when the default is in effect.

#### Finished Numbered Worktrees Remove Themselves

Numbered worktrees stayed on disk after their branch merged until someone removed them by hand. A sweep at session start, run at most once every six hours, now removes a numbered worktree once its branch is merged into the live branch, it holds no uncommitted or unrecoverable files and nobody has used it for 48 hours. Build outputs that a rebuild restores no longer keep a worktree. The sweep keeps the worktree of a squash-merged branch and reports it as squash-merged.

#### Hook git Calls Have a Time Limit

Every git call in the commit and push hooks that reads the index now stops after 20 seconds and blocks with `BLOCKED [gate:git-timeout]`. A stuck daemon can no longer hold a commit or a push open.

## Changelogs Live in Skills Only

#### Closing a Spec Folder Writes No Changelog

`/speckit:implement` and `/speckit:complete` now end at `implementation-summary.md`, and `create.sh --phase` stops naming a changelog in a new phase child. A changelog lives in `.skilled/changelog/` for a framework release or in a skill's own `changelog/` folder, both written by `/create:changelog`.

#### The Old Paths Refuse Instead of Writing

`/create:changelog --nested` stops before it writes anything and offers the global entry. The packet changelog generator prints a deprecation notice on every run, and its `--write` refuses a packet that has no changelog yet. A spec folder can still be the source of an entry, which goes to the skill its changed files belong to.

#### A Packet Changelog Request Reaches sk-doc

A request such as "write a changelog for this packet" used to rank the spec-kit workflow first. The skill advisor now ranks sk-doc's changelog mode first, while "add a nested phase to the packet for the changelog work" stays spec-folder work.

#### Existing Packet Changelogs Stay

The changelogs already inside spec folders keep validating, and the generator can still re-render them.

#### An Untagged Release Takes New Work

Release notes are often written before the release is tagged, and work keeps landing in the meantime. For the `skilled` release line, `/create:changelog` now checks origin for a tag on the latest entry. With no tag the release is still open, so the run folds the new work into that entry and keeps its version instead of opening a second untagged release. When the tag check fails, the run numbers a new entry and says so.

## Skill Advisor Routing

#### The Named Workflow Stays First

Asking for a deep research loop with the cli-pi executor used to hand the route to the CLI hub, so the caller ran the executor and skipped the workflow it asked for. The workflow skill now stays first and the executor sits just below it. A prompt that names only an executor routes as before.

#### One Generic Word Counts Once

A skill that listed a bare word such as `browser` in two of its metadata fields scored that word twice. That could rank it above a skill that declares the exact phrase, such as `browser agent`. A repeated bare word now counts once, so the exact phrase wins.

#### Doctor Targets and Run Requests Route as Asked

A typed doctor target such as `/doctor:ci toggle` used to lose to its bare default. A request to run or switch something off and then show the result was treated as a read-only question. Both now route as asked. A request to cut CI cost reaches `sk-code-ci`, and a release request that tags a version reaches `sk-git`.

#### Two Launchers Share One Daemon

When two advisor launchers started at the same moment, the loser could stop itself, a reclaim could delete the winner's fresh lease or a client could kill a daemon that was still starting. Each race is closed, so two sessions that open together share one daemon. A damaged lease file no longer blocks startup.

## Deep-Loop Fan-Out

#### An Interrupted Lane Resumes

Resuming an interrupted lineage named its new dispatch exactly like the first one, so the runtime replayed the old result and the executor never ran. Each later dispatch now gets its own id, so a resume runs the executor again.

#### An Operator's Edit Is Not Quarantined

The write guard used to claim a file the operator was already editing for the lane, as if the lane had written it. A path that was dirty before the lane started and changed during it is now reported as contested, with no quarantine copy or revert.

#### GPT-6.1 Terra on Pi

A deep-loop lineage can now pin `gpt-6.1-terra`, which the pi fan-out used to refuse. Pi's fast mode also sends GPT-6.1 Terra on the priority service tier, as it does GPT-6 Sol and GPT-6 Luna.

## Dependency Security

#### Alerts Reach Zero

Open Dependabot security alerts went to zero. The fixes went to the source versions: zod 4.6.7, vitest 4.1.12 and pi-coding-agent 1.4.0 in the pi extensions, alongside the audit fixes.

#### One Alert Stays Dismissed

One alert stays dismissed as an accepted risk. The Code Mode server stays on zod 3 until its `@utcp` dependencies move to zod 4.

## Documentation

#### Every README and Changelog Passes Its Audit

Under the README audit, every tracked README passes its template check and every README reference resolves, and every changelog passes its check. The audit covered 753 READMEs and 884 changelogs.

#### The Audit Stops Flagging Correct Docs

A git-ignored runtime file or folder, a path relative to its package and a SHA-256 mention no longer count against a document.

#### Stricter README Checkers Read More

The README reference checker now checks a slash command against the command tree, including its mode, and fails a missing command or a near-miss typo. The count checker reads more claim shapes, such as "12 test files" or "Files: 12", and checks a claim about a named folder against that folder. A placeholder path or a shortened link label no longer fails, and a rate or a test result is not read as a count claim. These checkers are stricter than the audit, so they still fail some READMEs the audit passes. Run over the 987 tracked READMEs at release, they failed 318 on references and 54 on counts, against 336 and 59 for the previous checkers, and no README that passed before failed.

The `examples=` figure on each reference checker verdict line always read 0. It now counts the references inside example fences, which still never fail a README.

## Upgrade Notes

- **Clones that used the Webflow or Obsidian surfaces:** add your own surface or keep a private, git-ignored skill.
- **To switch a CI group off:** set a `SKILLED_CI_*` repository variable through `/doctor:ci`. A clone that wants every check sets nothing.
- **To run `/doctor:ci` in another repository:** add `.skilled/skills/sk-code/sk-code-ci/repository/ci.json` to name its switches and protected workflows, or run it without one.
- **To declare your own quality checks:** run `/doctor:sk-code quality`, then `--apply`.
- **Before a checklist carries a `## Rule overrides` section:** check it with `node .skilled/skills/sk-code/shared/scripts/check-rule-overrides.cjs <checklist.md>`. A refused section stops every quality run that loads it.
- **Repositories that relied on the default JavaScript or CSS checklists:** declare your own checklist rows in `.skilled/skills/sk-code/sk-code-quality/repository/quality.json`.
- **To preview the worktree sweep:** run `bash .skilled/bin/worktree-reaper.sh --numbered --dry-run`. Set `SPECKIT_WORKTREE_AUTOREAP=0` to stop it, and remove a squash-merged worktree yourself.
- **Scripts that pass `--nested` to `/create:changelog`:** drop the flag. The run writes the global entry instead.
- **To route packet changelog requests to sk-doc:** rebuild the advisor with `node .skilled/bin/skill-advisor.cjs advisor_rebuild --trusted --force true`.
- **To pick up the advisor routing fixes:** rebuild the advisor runtime with `npm --prefix .skilled/skills/system-skill-advisor/runtime run build`.
