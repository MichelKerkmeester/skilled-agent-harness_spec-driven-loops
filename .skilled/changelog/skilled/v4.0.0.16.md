# v4.0.0.16, Cheaper CI, Private Skills and Code Modes for Any Repository

The pipeline that guards this repository was rebuilt around what triggers work. A commit that only rebuilds an index now runs no CI at all. A pull request that gets a newer push stops paying for the older run, and the rest of the pipeline does the same checks with less overhead.

The Webflow and Obsidian code guides left the public tree. Their 226 files and about 2 MB now live in two private skills that git ignores, and a commit check refuses to stage them in any runtime folder. That is the one break in this release.

Everything else makes the code modes portable. A quality gate prints one verdict in any repository, and a review raises a blocking finding only for input the code can actually receive. The documentation and dependency alert checks both came back clean.

> Spec folders: `specs/system-speckit/053-ci-workflow-efficiency` (Level 2), `specs/sk-code/013-private-surface-skills` (Level 2), `specs/sk-code/014-code-modes-research` (Level 2), `specs/sk-code/015-quality-agnostic-gate` (Level 2), `specs/sk-code/016-review-mode-followups` (Level 2) and `specs/sk-doc/070-repo-doc-debt` (Level 2)

&nbsp;

## Why This Release

More than half of the repository's daily CI time came from one automated commit. That commit rebuilt an index and re-ran thirteen workflows on files they never read, so the bill followed the bot rather than the work. A day measured after the change used 43 percent fewer runner-minutes.

&nbsp;

## What's New at a Glance

- **CI no longer pays for work nobody reads.** Rebuild commits skip CI and older runs cancel when a newer push lands. Path filters keep a workflow off files it never touches.
- **The Webflow and Obsidian guides are private.** They left the public tree for two git-ignored skills, and a clone that used them no longer gets them from `sk-code`.
- **A quality gate works in any repository.** It prints one verdict, `BLOCKED` or `NO_BLOCKER_FOUND`, wherever it runs.
- **Review severity follows the code's contract.** A P0 or P1 has to name an input the contract allows, or a caller that sends it.
- **Every README and changelog passes its check.** The audit ran over the whole repository and found no debt left.
- **Open dependency alerts are at zero.** All but one were fixed by updating the package itself.
- **CI has switches and a doctor command.** `/doctor:ci` lists each workflow, scaffolds a new one and flips a group off.

&nbsp;

## CI and GitHub Actions

The repository's 33 workflows used about 3,812 runner-minutes a day before this work. A measured 24 hours afterwards used 2,191.

#### Rebuild Commits Skip CI

The trigger-index rebuild is a bot commit that writes generated files, and it re-ran 13 workflows that read none of what it wrote. A skip condition now keeps that commit out of CI entirely.

#### Smaller Cuts Across the Pipeline

A pull-request run cancels the moment a newer push arrives, so an outdated run stops instead of finishing work a newer commit replaced. Path filters stop a workflow from running on files it never reads. Checkouts fetch less history and one shared setup step owns the caching. Two overlapping workflows are now one.

#### Slowest Tests Run in Halves

The spec-kit CLI tests were the slowest single step in the pipeline. They now run as two halves at the same time, at a median of 451 seconds against about 791 before.

#### A Timeout and a Permission List per Job

Every job now carries a timeout and only the permissions it needs. A job that hangs fails on its own clock, and a job that never needed write access no longer holds it.

#### Six Switches and a Doctor Command

Six repository variables turn CI groups off: `SKILLED_CI` and five `SKILLED_CI_*` group switches. Everything defaults to on, so a clone that sets nothing keeps every check. `/doctor:ci` lists the workflows with their on or off state, scaffolds a new workflow and flips a switch, and each write waits for an approved plan.

#### A Skill Mode for Workflow Files

`sk-code-ci` is a new mode in `sk-code` and the standard for writing a GitHub Actions workflow. It covers triggers, permissions, timeouts, caching and pinned action versions.

#### Nine Workflows Stay Separate

Merging nine workflows into one file would have saved about 636 runner-minutes a day. The change was declined, because each check has to keep its own pass or fail.

## Private Webflow and Obsidian Skills

#### The Guides Leave the Public Tree

The Webflow and Obsidian code guides held 226 files and about 2 MB between them. The previous release called them optional examples. They are now gone from the public tree.

#### Two Private Skills Replace Them

The operator's own copies live in two private skills that git ignores. A commit check refuses to stage either one in any runtime folder, and the skill advisor follows them only on the machine that has them.

#### sk-code Keeps Four Modes

`sk-code` now ships quality, review, skilled and ci. The ci mode is new in this release.

#### What a Clone Loses

**Breaking:** A clone that used the Webflow or Obsidian surfaces no longer gets them from `sk-code`. Add your own surface or keep a private skill the same way.

#### The Guard Has Limits

`git commit --no-verify` and `git add -f` both bypass the commit check, and the removed files remain in git history. The check stops an accident, not a decision.

&nbsp;

## Code Quality in Any Repository

#### One Verdict, Anywhere

The quality mode used to read this repository's layout, and outside it fell back to general advice. Now `node .skilled/skills/sk-code/sk-code-quality/scripts/quality-gate.cjs` prints one verdict for a change in any repository, such as `BLOCKED` or `NO_BLOCKER_FOUND`.

#### A Repository Names Its Own Checks

A repository can commit `.sk-code/quality.json` to name the checks a change has to pass. `/doctor:sk-code quality` plans the file from the repository's own scripts, writes it on `--apply`, refuses to overwrite one that exists and checks it.

#### No Known Surface Still Finishes

A repository whose surface the gate does not recognise still reaches a verdict, on a universal floor of built-in checks.

#### Comments Read the Same Everywhere

The comment hygiene checker and its report now read a comment the same way in every language they cover. The checker's findings over this one fell from 63 to zero.

#### A Done Claim Needs Gate Evidence

An implementation report can no longer call a change done without gate evidence behind it.

&nbsp;

## Code Review

#### Workflow Reviews Load the CI Standards

A review of a workflow file used to load the CI standards and stop there. It now loads the review mode plus those standards, so the review reads the workflow the same way it reads a code change.

#### A Disagreeing Summary Fails Its Check

A review report whose summary disagrees with its status line now fails its own check, and the report carries a quality-gate evidence line.

#### Severity Follows the Contract

The reach of a finding is now bounded by what the code promises. A P0 or P1 has to name an input the code's stated contract allows, or a real caller that sends the failing input. Missing validation for input the contract never allows is P2 hardening. At a trust boundary every value is in reach. The rule settled a false P1 on a clean file, and it now guides the deep review as well.

#### A Cache Key Without an Origin

The review cache key now works in a repository with no `origin` remote.

#### First Live Accuracy Check

Three runs per case caught seeded injection and off-by-one bugs every time at the right severity. The clean file drew no blocking finding.

&nbsp;

## Documentation

#### Every README and Changelog Passes

Every README passes its template check, every README reference resolves and every changelog passes its check. The audit covered 753 READMEs and 884 changelogs.

#### The Audit Stops Flagging Correct Docs

The README audit itself stopped flagging correct documents. A git-ignored runtime file or folder, a path relative to its package and a SHA-256 mention no longer count against a document.

&nbsp;

## Dependency Security

#### Alerts Reach Zero

Open Dependabot security alerts went to zero. The fixes went to the source versions: zod 4.6.7, vitest 4.1.12 and pi-coding-agent 1.4.0 in the pi extensions, alongside the audit fixes.

#### One Alert Stays Dismissed

One alert stays dismissed as an accepted risk. The Code Mode server stays on zod 3 until its `@utcp` dependencies move to zod 4.

&nbsp;

## Upgrade Notes

- **Clones that used the Webflow or Obsidian surfaces:** add your own surface or keep a private, git-ignored skill.
- **To switch a CI group off:** set a `SKILLED_CI_*` repository variable through `/doctor:ci`. A clone that wants every check sets nothing.
- **To declare your own quality checks:** run `/doctor:sk-code quality`, then `--apply`.
