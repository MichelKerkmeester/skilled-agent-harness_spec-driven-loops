# v4.0.1.4, A Doctor Command for the Root Instruction File

Every installed repository carries a root instruction file that the framework writes once and never reads back. The template moves on, a fork grows its own sections between the shipped ones, and nothing says which lines belong to the repository and which the next update will overwrite. `/doctor:agents-md` answers that in three targets. `check` reports, `embed` writes only after a plan you approved and the digest that plan printed, and `restore` puts the previous bytes back.

> Spec folder: `specs/agents/021-doctor-agents-md` (Level 2)

&nbsp;

## What's New at a Glance

- **`/doctor:agents-md check` reports twelve rows.** The install state, the sections lost or reordered, how current each shipped body is, every pin, the delivery budget, the shape of your own block, the lines only you carry, each runtime copy, `REPO RULES.md` and the template's own purity, each on one line with the detail under it.
- **`embed` writes only against the digest its own plan printed.** The plan composes every target in memory and shows the diffs, the new block, the byte budget, the lines it will keep and a digest. The apply refuses any bytes that digest no longer describes, so the write lands where you looked.
- **No repository line goes missing.** Every path is backed up before the first byte, the write stays inside an allowlist checked in code, and the run then proves against the disk that every line you had is still there and every other line is one the template ships. A dropped line restores itself from the backup and the run ends as a failure.
- **`restore` is a route, not a manual copy.** It puts back exactly the paths one run's own manifest records and removes the file that run created, and the backup folder stays where it is.
- **Your advisor does not suggest it yet.** The three routes derive three advisor bridges and every one is inactive, so the routing activation this family still owes is one decision made in one place.
- **The two claims behind the Cursor mirror are written down as open.** The playbook now carries the question a live Devin session answers and the question a Cursor window answers, each recorded as unknown with its reason rather than as a pass.

&nbsp;

## Upgrade

No migration required. Run `/doctor:agents-md check` in a repository you forked from the template to see where it stands, and read the plan before you give `embed` a digest.
