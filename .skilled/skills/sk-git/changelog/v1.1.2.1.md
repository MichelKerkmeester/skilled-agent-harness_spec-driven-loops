This patch sets the H1 contract for GitHub release bodies. Omit the leading `# vX.X.X.X — Title` from the body. Keep that H1 as the repository changelog's identity. GitHub already renders the release title as `vX.X.X.X — Title`. So repeating it as a heading duplicates it on the Releases page.

&nbsp;

## What's New at a Glance

- Release bodies omit the leading H1.
  - `SKILL.md` adds ALWAYS rule #11.
  - `SKILL.md` renumbers the rules after it.
  - Keep the heading in the repository changelog file.
  - When you publish from a changelog, strip the heading first.
  - Strip the blank lines after it too.
  - Put both in a temporary notes file.
  - Do this before `gh release create/edit --notes-file`.
- The finish workflow now gives the H1 strip procedure.
  - Step 6 is `Create Release`.
  - Step 6's `Important` list replaces a claim.
  - The claim said changelog files begin with summary text.
  - The claim said changelog files have no version header.
  - The claim said changelog files can be used as-is.
  - The list gives the H1 contract and the exact command instead: `tail -n +2 changelog/vX.X.X.X.md | sed '/./,$!d' > /tmp/release-body.md`.
- Common Mistakes covers prevention and detection.
  - The `--notes-file with unprocessed changelog` entry says to strip the H1 into a temporary file.
  - Do not edit the repository file.
  - After publishing, check `gh release view vX.X.X.X --json body --jq .body | head -1`.
  - The result must not start with `# `.
