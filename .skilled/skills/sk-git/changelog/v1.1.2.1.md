This patch sets the H1 contract for GitHub release bodies: omit the leading `# vX.X.X.X — Title` from the body while keeping that H1 as the repository changelog's identity. GitHub already renders the release title as `vX.X.X.X — Title`, so repeating it as a heading duplicates it on the Releases page.

## What's New at a Glance

- **Release bodies omit the leading H1.** `SKILL.md` adds ALWAYS rule #11 and renumbers subsequent rules. Keep the heading in the repository changelog file. When publishing from a changelog, strip the heading and following blank lines into a temporary notes file before using `gh release create/edit --notes-file`.
- **The finish workflow now gives the H1 strip procedure.** In Step 6, `Create Release`, its `Important` list replaces the claim that changelog files begin with summary text, have no version header and can be used as-is with the H1 contract and exact command: `tail -n +2 changelog/vX.X.X.X.md | sed '/./,$!d' > /tmp/release-body.md`.
- **Common Mistakes covers prevention and detection.** The `--notes-file with unprocessed changelog` entry says to strip the H1 into a temporary file rather than edit the repository file. After publishing, check `gh release view vX.X.X.X --json body --jq .body | head -1`. The result must not start with `# `.
