Safety hardening protects owner-first worktree operations. An adversarial review reproduced correctness and safety defects. The original test setups missed them. They had never exercised adversarial inputs.

The release changes no public or tooling interface. It changes no branch grammar or command surface. Its fixes are internal. Permanent regression coverage backs the safety guarantees in code rather than assertion.

&nbsp;

## What's New at a Glance

- `worktree-naming.sh` now reserves distinct numbers during stale-lock recovery.
  - The previous dead-lock reclaim could let two contenders proceed as owner.
  - Both contenders could mint the same number.
  - Only one contender can win the atomic rename-steal.
  - The winner renames the lock directory aside.
  - The winner discards the stale lock.
  - Then the winner races a fresh `mkdir` rather than re-inserting it.
  - N concurrent allocations always yield N distinct, monotonically increasing numbers.
  - A high-water persistence failure now aborts allocation without emitting a number.
  - The validators enforce the documented `0001..9999` bound.
  - The validators also enforce the exact `.worktrees/<pair>` path.
- `worktree-reaper.sh` requires proof that a worktree is safe to remove.
  - The complete session-marker file must match a PID grammar.
  - Malformed markers keep the worktree.
  - That is because ambiguity is not proof of inactivity.
  - A `work/*` branch is reaped only when it is an exact `work/<runtime>/<slug>` triple.
  - The runtime and slug must match the directory basename.
  - `--reap-daemons` signals a daemon only when its referenced worktree or database path is gone.
  - The PID identity must still match.
- `worktree-session.sh` rejects unsafe inputs before they act.
  - A runtime identity that cannot form a legal Git ref is refused before `worktree add`.
  - Child execution no longer passes the diagnostic reason in the runtime arguments.
  - Entries in `SPECKIT_WORKTREE_SHARED_PATHS` containing `..` or absolute components are rejected.
  - Source and destination paths are canonicalized and containment-checked.
  - So a shared-path copy cannot delete or symlink outside the worktree.
- `pre-push` separates invalid names from validator failures.
  - A genuine invalid name still blocks.
  - Internal validator errors fail open.
  - One example is a failed owner-discovery scan.
  - So tooling faults do not block legal pushes.
  - Only version-controlled `SKILL.md` files can authorize remote owners.
  - So an untracked skill can no longer authorize one.
- Sourced allocator behavior and closeout wording are corrected.
  - The sourceable allocator uses a guarded strict-mode pattern.
  - The sourceable allocator does not impose `set -e` on callers that source it.
  - The related closeout docs for the first ship were reconciled.
  - The closeout docs describe the hardened behavior.
  - The closeout docs replace blanket "0-ahead" cleanup wording with reachability-based losslessness.
