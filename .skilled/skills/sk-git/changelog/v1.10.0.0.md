# v1.10.0.0, Git Stays Responsive When fsmonitor Daemons Pile Up

On macOS each worktree gets an fsmonitor daemon. That is the background process that watches files, so git can skip a full scan. It keeps running until the worktree is gone. Idle daemons piled up. One that stopped answering could stall every git command that reads the index. This release adds a script that finds and ends those daemons safely. It then wires the script into session launch, worktree cleanup and the doctor check.

> Spec folder: `specs/sk-git/035-fsmonitor-daemon-and-worktree-relocation-regression` (Level 2)

&nbsp;

## What's New at a Glance

- **A new script ends stray, idle and stuck daemons.** `fsmonitor-daemon-reaper.sh` only reports until you add `--apply`. With that flag it ends a daemon through git's own stop first. It tries anything harsher only after that. It never touches another repository's daemon. It never touches the daemon of a worktree you are still working in, unless that daemon has stopped answering.
- **Each session launch clears idle daemons.** Every top-level launch through the wrapper starts a background sweep. That sweep ends the daemons of worktrees nobody has used for 12 hours. The launch does not wait for it.
- **Worktree cleanup ends the daemon first.** The worktree reaper and the finish workflow's cleanup step both end a worktree's daemon. Both do this before removing the worktree. The finish step now moves to the main checkout to do so. It then checks that no daemon was left behind.
- **The doctor shows your daemons and flags a crowded checkout.** `/doctor:git setup` lists main, worktree and stray daemon counts on its worktrees row. Those counts are information only. The row reads DEGRADED in one case. The worktree folder sits inside the main checkout, and more than three linked worktrees exist.
- **One launch no longer pins worktrees inside the checkout.** The launch wrapper saves the worktree folder to git config in one case only. That case is when you chose the folder with `SPECKIT_WORKTREE_BASE`. A launch that fell back to the default used to fix that default for good.
- **Commit and push checks can no longer hang.** The message validator gives each git call 20 seconds. So a stuck daemon cannot hold a commit or a push open.

&nbsp;

## Upgrade

No migration required. If the doctor reports DEGRADED on the worktrees row, move new worktrees out of the checkout. Use `git config speckit.worktreeBase <dir>` for that. To end stray daemons now, run `bash .skilled/bin/fsmonitor-daemon-reaper.sh --apply`.
