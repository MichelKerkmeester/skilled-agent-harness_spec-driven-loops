Managed task branches now put the owner first in the branch name, with a matching worktree directory. Version 1.2.0.0 also replaces hand-computed counters with clone-wide allocation and adds safeguards for launch-wrapper sessions, cleanup and remote branch naming.

The release also updates the naming guidance and examples while preserving the separate launch-wrapper lane.

## Why This Release

The former `wt/{NNNN}-{name}` namespace left managed task branches in one flat pile. The owner-first form lets a Git-UI branch tree group them by owner.

## What's New at a Glance

- **Task branches now use owner-first names.** Their matching worktree directories carry the same number, owner and slug.
- **`worktree-naming.sh` supplies clone-wide allocation.** Its commands cover naming checks, number assignment and named or detached worktree creation.
- **Wrapper sessions have external pid markers.** `worktree-reaper.sh` uses evidence of inactivity before it automatically cleans up a wrapper worktree.
- **Pre-push naming checks target new remote branches.** Existing non-conformant branches and `skilled/v*` release branches are not blocked.
- **`SKILL.md` reflects the new naming and cleanup rules.** Its router vocabulary adds owner-first terms without replacing legacy terms.
- **`worktree_workflows.md` uses the allocator in its examples.** It also corrects detached-worktree numbering and fast-merge cleanup order.
- **`graph-metadata.json` adds owner-first terms.** The vocabulary additions preserve existing entries.

## Git Branches and Worktrees

#### Owner-First Task Names

Task branches use `{OWNER}/{NNNN}-{slug}`, such as `sk-git/0001-add-oauth`, with a matching `.worktrees/{NNNN}-{OWNER}-{slug}` directory. A canonical skill id comes from the `name:` frontmatter of an `.opencode/skills/**/SKILL.md`. `{OWNER}` can also be the literal `skilled` for cross-cutting, system or release work. `{NNNN}` stays a four-digit zero-padded counter, now clone-wide rather than hand-computed. `main` is unchanged and outside this task-branch grammar. `skilled/vA.B.C.D` release branches and the launch wrapper's `work/{runtime}/{slug}` lane are also unchanged and outside it. Branches using the former `wt/{NNNN}-{name}` form are permitted but non-conformant with the owner-first task grammar.

&nbsp;

#### Clone-Wide Allocation

Allocation holds a lock in the shared common git dir. It seeds the maximum number from the stored high-water mark, every registered worktree basename and all local and remote refs, so a partial scan cannot reissue a live number. Owner ids are discovered live from every `name:` frontmatter under `.opencode/skills/**/SKILL.md`.

&nbsp;

#### Allocator Commands and Functions

The new sourceable `.opencode/skills/sk-git/scripts/worktree-naming.sh` exposes six validators: `is_valid_owner` / `is_valid_slug` / `is_valid_nnnn` / `is_valid_branch` / `is_wrapper_branch` / `is_valid_pair`. Its counter functions are `scan_max_number` / `next_number` / `allocate_number`. Its one-step creation functions are `create_named_worktree` / `create_detached_worktree`.

The CLI subcommands are `skill-ids` / `next` / `allocate` / `scan-max` / `validate-owner` / `validate-slug` / `validate-branch` / `validate-pair` / `create` / `create-detached`.

## Wrapper Session Safety

#### Session Markers Avoid Dirty Trees

Before `exec`, `worktree-session.sh` validates the runtime token against a safe character set and checks it with `command -v`. It writes an active-session marker containing the launching pid, which survives `exec`, to `<common-git-dir>/worktree-sessions/<runtime>-<slug>.pid`. The marker sits outside the worktree so it cannot dirty the tree. A marker write failure is logged and is non-fatal.

&nbsp;

#### Reaping Requires Proof of Inactivity

`worktree-reaper.sh` uses the primary checkout's actual `HEAD` as the live integration target, not a possibly stale local `main`. It automatically reaps only launch-wrapper lane pairs (`work/{runtime}/{slug}`) when the tree is clean, the branch is merged into that live tip and the session marker proves the recorded pid is dead.

Owner-first task worktrees and detached worktrees are report-only. Wrapper worktrees with a missing or unreadable marker or a live pid are report-only too. Cleanup removes the worktree before deleting its branch. Neither call passes `--force`.

## Naming Rules and Enforcement

#### Pre-Push Limits New Branches

Naming-grammar enforcement moves to a migration-tolerant pre-push hook. The hook gates only the creation of brand-new remote branches. Existing non-conformant branches are not rewritten or blocked by the hook. `skilled/v*` release branches are not blocked either.

&nbsp;

#### Skill Rules Match the Grammar

In `SKILL.md`, ALWAYS #4 now specifies the owner-first grammar and points to the allocator instead of a hand-computed counter. New ALWAYS #17 describes cleanup order, the reaper's wrapper-only and proven-inactive scope and the pre-push enforcement contract. The Success Criteria branch-naming line now uses `{OWNER}/{NNNN}-{slug}`.

&nbsp;

#### Router Vocabulary Adds Owner Terms

The Keyword/Owns comment lines and `ON_DEMAND_KEYWORDS` router list add `owner-first branch` / `skill-scoped worktree` / `worktree naming allocator` / `skilled branch`. Existing entries, including `wt-branch` and `wt/ branch`, are not replaced.

## Worktree Documentation

#### Reference Workflows Use the Allocator

Steps 1-4, the Branch Strategy Guide, Decision Matrix and all three Example Workflows replace hand-computed `wt/{NNNN}-{name}` shell snippets with `worktree-naming.sh create` and `create-detached` invocations. Detached-experiment worktrees are documented with numbered paths in the form `.worktrees/{NNNN}-detached-{slug}`, even though they have no branch or owner. The prior documentation incorrectly said that no number was assigned.

&nbsp;

#### Cleanup Examples Remove Worktrees First

The fast-merge cleanup examples remove the worktree before deleting its branch, matching ALWAYS #17. Git refuses to delete a branch that is still checked out by a worktree.

&nbsp;

#### Legacy Migration Joins Naming Notes

The Naming Convention callout includes the owner-first and launch-wrapper two-lane note. It also includes a new legacy-migration note.

&nbsp;

#### Owner Terms Extend Graph Metadata

`graph-metadata.json` adds owner-first naming terms to `domains`, `intent_signals`, `derived.trigger_phrases`, `derived.key_topics` and `derived.intent_signals`. No existing entries are removed.

---

## Upgrade Notes

- **Migrate.** To migrate a legacy `wt/{NNNN}-{name}` branch, rename the branch and its worktree directory into the owner-first form. Never rewrite history.
