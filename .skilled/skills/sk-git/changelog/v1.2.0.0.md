# sk-git v1.2.0.0

Managed task branches now put the owner first in the branch name.

- Their worktree directory matches.
- Task branches use `{OWNER}/{NNNN}-{slug}`.
- Each has a matching `.worktrees/{NNNN}-{OWNER}-{slug}` directory.

Version 1.2.0.0 also replaces hand-computed counters with clone-wide allocation.

- `worktree-naming.sh` supplies the allocator.
- Its commands cover naming checks, number assignment and named or detached worktree creation.

It adds safeguards for launch-wrapper sessions, cleanup and remote branch naming.

- Wrapper sessions have external pid markers.
- The release also updates the naming guidance and examples.
- It preserves the separate launch-wrapper lane.

&nbsp;

## Why This Release

The former `wt/{NNNN}-{name}` namespace left managed task branches in one flat pile.

- The owner-first form lets a Git-UI branch tree group them by owner.

## Git Branches and Worktrees

Managed task branches now put the owner first, and worktree directories match.

#### Owner-First Task Names <a id="c-ownerfirst-task-names"></a>

- Task branches use `{OWNER}/{NNNN}-{slug}`, such as `sk-git/0001-add-oauth`.
- Each has a matching `.worktrees/{NNNN}-{OWNER}-{slug}` directory.
- A canonical skill id comes from the `name:` frontmatter of an `.opencode/skills/**/SKILL.md`.
- `{OWNER}` can also be the literal `skilled` for cross-cutting, system or release work.
- `{NNNN}` stays a four-digit zero-padded counter.
- It is now clone-wide rather than hand-computed.
- `main` is unchanged and outside this task-branch grammar.
- `skilled/vA.B.C.D` release branches are also unchanged and outside it.
- So is the launch wrapper's `work/{runtime}/{slug}` lane.
- Branches using the former `wt/{NNNN}-{name}` form are permitted.
- They are non-conformant with the owner-first task grammar.

#### Clone-Wide Allocation <a id="c-clonewide-allocation"></a>

- Allocation holds a lock in the shared common git dir.
- It seeds the maximum number from the stored high-water mark, every registered worktree basename and all local and remote refs.
- So a partial scan cannot reissue a live number.
- Owner ids are discovered live from every `name:` frontmatter under `.opencode/skills/**/SKILL.md`.

#### Allocator Commands and Functions <a id="c-allocator-commands-and-functions"></a>

- The new sourceable `.opencode/skills/sk-git/scripts/worktree-naming.sh` exposes six validators: `is_valid_owner` / `is_valid_slug` / `is_valid_nnnn` / `is_valid_branch` / `is_wrapper_branch` / `is_valid_pair`.
- Its counter functions are `scan_max_number` / `next_number` / `allocate_number`.
- Its one-step creation functions are `create_named_worktree` / `create_detached_worktree`.
- The CLI subcommands are `skill-ids` / `next` / `allocate` / `scan-max` / `validate-owner` / `validate-slug`.
- The rest are `validate-branch` / `validate-pair` / `create` / `create-detached`.

## Wrapper Session Safety

Wrapper sessions get external pid markers. Reaping needs proof of inactivity.

#### Session Markers Avoid Dirty Trees <a id="c-session-markers-avoid-dirty-trees"></a>

- Before `exec`, `worktree-session.sh` validates the runtime token against a safe character set.
- It also checks the token with `command -v`.
- It writes an active-session marker to `<common-git-dir>/worktree-sessions/<runtime>-<slug>.pid`.
- The marker holds the launching pid, which survives `exec`.
- The marker sits outside the worktree.
- So it cannot dirty the tree.

#### Reaping Requires Proof of Inactivity <a id="c-reaping-requires-proof-of-inactivity"></a>

- `worktree-reaper.sh` uses the primary checkout's actual `HEAD` as the live integration target.
- It does not use a possibly stale local `main`.
- `worktree-reaper.sh` uses evidence of inactivity.
- Only then does it clean up a wrapper worktree automatically.
- It automatically reaps only launch-wrapper lane pairs (`work/{runtime}/{slug}`).
- It does so only under these conditions.
- The tree is clean.
- The branch is merged into that live tip.
- The session marker proves the recorded pid is dead.
- Owner-first task worktrees and detached worktrees are report-only.
- Wrapper worktrees with a missing or unreadable marker or a live pid are report-only too.
- Cleanup removes the worktree before deleting its branch.

## Naming Rules and Enforcement

Naming enforcement moves to a migration-tolerant pre-push hook.

#### Pre-Push Limits New Branches <a id="c-prepush-limits-new-branches"></a>

- Naming-grammar enforcement moves to a migration-tolerant pre-push hook.
- The hook gates only the creation of brand-new remote branches.
- Existing non-conformant branches are not rewritten.
- The hook does not block them.
- `skilled/v*` release branches are not blocked either.

#### Skill Rules Match the Grammar <a id="c-skill-rules-match-the-grammar"></a>

- In `SKILL.md`, ALWAYS #4 now specifies the owner-first grammar.
- It points to the allocator instead of a hand-computed counter.
- New ALWAYS #17 describes cleanup order.
- It also covers the reaper's wrapper-only and proven-inactive scope.
- It covers the pre-push enforcement contract too.
- The Success Criteria branch-naming line now uses `{OWNER}/{NNNN}-{slug}`.

#### Router Vocabulary Adds Owner Terms <a id="c-router-vocabulary-adds-owner-terms"></a>

- The Keyword/Owns comment lines and `ON_DEMAND_KEYWORDS` router list add `owner-first branch` / `skill-scoped worktree` / `worktree naming allocator` / `skilled branch`.
- Existing entries, including `wt-branch` and `wt/ branch`, are not replaced.

## Worktree Documentation

Worktree docs now use the allocator and add naming notes.

#### Reference Workflows Use the Allocator <a id="c-reference-workflows-use-the-allocator"></a>

- Steps 1-4, the Branch Strategy Guide, Decision Matrix and all three Example Workflows replace hand-computed `wt/{NNNN}-{name}` shell snippets.
- They now use `worktree-naming.sh create` and `create-detached` invocations.
- Detached-experiment worktrees are documented with numbered paths.
- The form is `.worktrees/{NNNN}-detached-{slug}`.
- They have no branch or owner.
- The prior documentation incorrectly said that no number was assigned.

#### Cleanup Examples Remove Worktrees First <a id="c-cleanup-examples-remove-worktrees-first"></a>

- The fast-merge cleanup examples remove the worktree before deleting its branch.
- This matches ALWAYS #17.
- Git refuses to delete a branch that is still checked out by a worktree.

#### Legacy Migration Joins Naming Notes <a id="c-legacy-migration-joins-naming-notes"></a>

- The Naming Convention callout includes the owner-first and launch-wrapper two-lane note.
- It also includes a new legacy-migration note.

#### Owner Terms Extend Graph Metadata <a id="c-owner-terms-extend-graph-metadata"></a>

- `graph-metadata.json` adds owner-first naming terms to `domains`, `intent_signals`, `derived.trigger_phrases`, `derived.key_topics` and `derived.intent_signals`.
- No existing entries are removed.

## Upgrade Notes

Legacy `wt/{NNNN}-{name}` branches can be migrated into the owner-first form.

#### Before You Start <a id="c-before-you-start"></a>

1. Migrate. To migrate a legacy `wt/{NNNN}-{name}` branch, rename the branch and its worktree directory into the owner-first form.
2. Never rewrite history.
