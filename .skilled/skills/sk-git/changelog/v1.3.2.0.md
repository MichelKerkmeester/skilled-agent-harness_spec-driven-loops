# v1.3.2.0, Documentation and Hyphen-Case Paths

v1.3.2.0 refreshes the sk-git documentation and moves its resource trees to hyphen-case names. Script behavior, branch grammar and command surface did not change.

## Why This Release

Hyphen-case naming was adopted ahead of the repo-wide program.

## What's New at a Glance

- **Four resource trees now use hyphen-case names.** Their path references were repointed to match.
- **The README and executable surfaces gain documentation.** The README follows the create-readme canon. Four code READMEs cover executable surfaces.
- **Catalogs are checked against their templates.** The optional Root-vs-Feature rule supports fuller scaffold alignment.

---

## Documentation and Paths

#### Resource Paths Use Hyphen-Case

`references/`, `assets/`, `feature-catalog/` and `manual-testing-playbook/` replaced their snake_case names with hyphen-case names. The move covered 66 files and 13 directories. Every path reference was repointed. This included the Smart Router's `RESOURCE_MAP`, `LOADING_LEVELS` and `DEFAULT_RESOURCE`. Relative cross-links, link labels and per-feature metadata also use the new names. Findings from `package_skill.py --check` for snake_case in `references/` and `assets/` are advisory-only until the repo-wide naming program flips the checker.

&nbsp;

#### The README Explains the Work

`README.md` was rewritten to the create-readme canon. Its HOW IT WORKS section conveys the skill's unique surface: the owner-first worktree grammar, clone-wide number allocator and its lock, ask-first workspace rule, launch-wrapper autosync, reaper contract, deterministic commits and safety refusals.

&nbsp;

#### Executable Surfaces Gain READMEs

Four code READMEs were added for `.opencode/skills/sk-git/scripts/`, `.opencode/skills/sk-git/scripts/tests/`, repository-root `.github/workflows/` and repository-root `.github/hooks/scripts/`. Each accurately documents its files, including the Copilot hook wrappers' file-writing fallback.

&nbsp;

#### Catalogs Match Their Templates

Documentation for `feature-catalog` and `manual-testing-playbook` was verified against `sk-doc`'s `create-feature-catalog` and `create-manual-testing-playbook` templates and `template_rules.json`. The optional Root-vs-Feature rule was added for fuller scaffold alignment.

&nbsp;

#### Review Corrects Stale Claims

Every documentation claim surfaced by a fresh independent review was reconciled, including several stale documentation claims. The README's worktree-lane framing marks `wt/{NNNN}-{slug}` as legacy and non-conformant, with owner-first as current. The commit-type priority order matches the runtime rule. The allocator script documentation gives the `create-detached <slug> [base]` and `validate-pair <branch> <dir>` signatures. The expected test output reads `FAIL=0`. Verification commands point to gates that pass.

## Upgrade Notes

- Any external reference to a sk-git resource path should use the hyphen-case name.
- No behavior migration is required. History is preserved, so `git log --follow` continues to work across the rename.
