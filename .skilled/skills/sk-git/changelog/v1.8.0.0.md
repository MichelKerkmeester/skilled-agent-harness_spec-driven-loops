# sk-git v1.8.0.0, Templates Are Now the Rulebook

The templates are now the rulebook.

- Each sk-git template carries an "Enforced rules" JSON block.
- Every gate reads that block from the repository being committed to.
- Edit the template and the enforcement changes with it.

Four gates call one validator.

- `commit-msg`, a new `pre-push` gate, an agent PreToolUse gate and a CI workflow all call `scripts/validate-message.mjs`.
- The bypass variable is gone.
- A commit made with `--no-verify` is caught by `pre-push` and CI.

New rules come from the existing contract.

- `Spec:` must omit the `specs/` prefix and name a packet that exists.
- PR descriptions need a filled Summary and Test Plan with no attribution.
- New branches follow the numbered grammar.

&nbsp;

## Why This Release

The commit rules lived twice. They were prose in the template and regexes in a bash hook.

- So editing the template changed nothing that was enforced.
- The hook is installed machine-wide.
- So every other repository inherited this one's types, scopes and trailers.
- PR descriptions were not checked at all.
- `--no-verify` or `SPECKIT_SKIP_COMMIT_MSG_VALIDATE=1` let any message through.

## Message Contract

#### The Templates Carry the Rules <a id="c-the-templates-carry-the-rules"></a>

- `commit-message-template.md`, `pr-template.md` and `worktree-checklist.md` each hold an "Enforced rules" block.
- Each rule has an id that every block message names.
- Each template's "Enforced rules" block lists types, scope pattern, limits, body rules, trailer order and attribution policy as data.
- A drift check fails when the prose and the block disagree. That holds in either direction.
- `Spec:` must omit the `specs/` prefix. It must name a packet that exists.
- PR descriptions need a filled Summary and Test Plan with no attribution.
- New branches follow the numbered grammar.

#### Every Gate Reads the Same Block <a id="c-every-gate-reads-the-same-block"></a>

- The `commit-msg` hook is now a thin shim over `validate-message.mjs`.
- `pre-push` re-checks every pushed commit, releases and `main` included.
- It also checks the name of a new branch.
- The validator reads `skgit.contractDir`, then `.sk-git/`, then the repository's own sk-git assets.
- A repository with none of them is not checked.
- The agent gate refuses a bad `git commit -m`, `gh pr create` body or branch name before it runs.
- That covers Claude, Codex, Cursor and Devin through the hook registry.
- It covers OpenCode, Pi and Hermes through a plugin or extension each.
- `.github/workflows/message-contract.yml` checks pushed commits, PR commits, PR descriptions and new branch names.
- The bypass variable is gone.
- A commit made with `--no-verify` is caught by `pre-push` and CI.
- `commit-msg`, a new `pre-push` gate, an agent PreToolUse gate and a CI workflow all call `scripts/validate-message.mjs`.

#### Ranges Are Judged Like Real Pushes <a id="c-ranges-are-judged-like-real-pushes"></a>

- A packet counts as existing when the commit's tree or the pushed tip holds it.
- That is because code commits often land before their packet docs.
- A force-pushed rebase is not compared with its own pre-rebase copies.
- This holds when checking `Commit-Id` uniqueness.

## Upgrade Notes

Only a required status check in the branch ruleset makes the guarantee hold for every contributor. Until then CI reports but does not block.
