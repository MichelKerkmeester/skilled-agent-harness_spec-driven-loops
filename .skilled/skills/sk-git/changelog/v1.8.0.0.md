The templates are now the rulebook. Each sk-git template carries an "Enforced rules" JSON block, and every gate reads that block from the repository being committed to. Edit the template and the enforcement changes with it.

> Spec folder: `specs/sk-git/032-template-driven-message-enforcement` (Level 3)

## Why This Release

The commit rules lived twice, as prose in the template and as regexes in a bash hook, so editing the template changed nothing that was enforced. The hook is installed machine-wide, so every other repository inherited this one's types, scopes and trailers. PR descriptions were not checked at all, and `--no-verify` or `SPECKIT_SKIP_COMMIT_MSG_VALIDATE=1` let any message through.

## What's New at a Glance

- **One rulebook per template.** `commit-message-template.md`, `pr-template.md` and `worktree-checklist.md` each hold an "Enforced rules" block, and each rule has an id that every block message names.
- **Your repository, your rules.** The validator reads `skgit.contractDir`, then `.sk-git/`, then the repository's own sk-git assets. A repository with none of them is not checked.
- **Four gates, one verdict.** `commit-msg`, a new `pre-push` gate, an agent PreToolUse gate and a CI workflow all call `scripts/validate-message.mjs`.
- **No bypass.** The bypass variable is gone. A commit made with `--no-verify` is caught by `pre-push` and CI.
- **New rules from the existing contract.** `Spec:` must omit the `specs/` prefix and name a packet that exists. PR descriptions need a filled Summary and Test Plan with no attribution. New branches follow the numbered grammar.

## Message Contract

#### The Templates Carry the Rules

Each template's "Enforced rules" block lists types, scope pattern, limits, body rules, trailer order and attribution policy as data. A drift check fails when the prose and the block disagree, in either direction.

&nbsp;

#### Every Gate Reads the Same Block

The `commit-msg` hook is now a thin shim over `validate-message.mjs`. `pre-push` re-checks every pushed commit, releases and `main` included, and the name of a new branch. The agent gate refuses a bad `git commit -m`, `gh pr create` body or branch name before it runs, in Claude, Codex, Cursor and Devin through the hook registry and in OpenCode, Pi and Hermes through a plugin or extension each. `.github/workflows/message-contract.yml` checks pushed commits, PR commits, PR descriptions and new branch names.

&nbsp;

#### Ranges Are Judged Like Real Pushes

A packet counts as existing when the commit's tree or the pushed tip holds it, because code commits often land before their packet docs. A force-pushed rebase is not compared with its own pre-rebase copies when checking `Commit-Id` uniqueness.

## Upgrade Notes

- **Make the CI check required.** Only a required status check in the branch ruleset makes the guarantee hold for every contributor. Until then CI reports but does not block.
- **Another repository opts in by copying templates.** Put edited copies in `.sk-git/` at its root, or point `skgit.contractDir` at them.
- **A broken rules block blocks commits.** Fix the JSON, or revert the template, to unblock.
