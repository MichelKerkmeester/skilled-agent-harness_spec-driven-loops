# v1.11.8.0, Docs Read in Order and Render as Written

The skill's `SKILL.md`, `ROUTER.md` and `README.md` were read file by file. So were its assets and its references. The reading checked readability, layout and structure. No workflow rule, command, hook gate or source citation changed.

&nbsp;

## What's New at a Glance

- **Overviews open with their purpose and when to use them.** Twelve guide files gain a Purpose subsection. Nine gain a When to Use list. Each is filled from the text its overview already held.
- **Packed paragraphs became lists.** The README's three phases now read one fact per line. So do the remote-branch safety limitation and the continuous-integration reconcile rules. The finish workflow's wrong-account push symptoms do too.
- **Section numbers are integers.** The worktree reference's large-reorg caveats are now section 9. So Troubleshooting, Success Criteria and Related Resources move to 10, 11 and 12. `SKILL.md`, the large-reorg runbook and its feature-catalog entry point at the new numbers.
- **The PR template's issue-linking section is renamed.** "Related Issues Guidelines" is now "Issue Linking Guidelines". So only the closing section is read as related resources.
- **Examples carry placeholders, not packet ids.** The `Spec:` trailer query reads `your-track/your-packet`. The incident notes keep what happened without naming the packet.

&nbsp;

## Upgrade

Links to `worktree-workflows.md#8b-large-reorg-in-a-worktree---caveats` move to `#9-large-reorg-in-a-worktree---caveats`. A reference to its Troubleshooting section by number moves from 9 to 10.
