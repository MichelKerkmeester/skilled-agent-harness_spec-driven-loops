# v1.11.8.0, Docs Read in Order and Render as Written

The skill's `SKILL.md`, `ROUTER.md`, `README.md`, its assets and its references were read file by file for readability, layout and structure. No workflow rule, command, hook gate or source citation changed.

> Spec folder: `specs/sk-doc/066-skill-readability-refinement/009-sk-git` (Level 1)

&nbsp;

## What's New at a Glance

- **Overviews open with their purpose and when to use them.** Twelve guide files gain a Purpose subsection and nine a When to Use list, filled from the text their overviews already held.
- **Packed paragraphs became lists.** The README's three phases, the remote-branch safety limitation, the continuous-integration reconcile rules and the finish workflow's wrong-account push symptoms now read one fact per line.
- **Section numbers are integers.** The worktree reference's large-reorg caveats are now section 9, so Troubleshooting, Success Criteria and Related Resources move to 10, 11 and 12. `SKILL.md`, the large-reorg runbook and its feature-catalog entry point at the new numbers.
- **The PR template's issue-linking section is renamed.** "Related Issues Guidelines" is now "Issue Linking Guidelines", so only the closing section is read as related resources.
- **Examples carry placeholders, not packet ids.** The `Spec:` trailer query reads `your-track/your-packet`, and the incident notes keep what happened without naming the packet.

Links to `worktree-workflows.md#8b-large-reorg-in-a-worktree---caveats` move to `#9-large-reorg-in-a-worktree---caveats`. A reference to its Troubleshooting section by number moves from 9 to 10.
