# v1.9.1.0, The Setup Check No Longer Passes What It Cannot Prove

`/doctor:git setup` could print PASS without proof in three places. Each one now reports what it actually found.

> Spec folder: `specs/sk-git/033-git-setup-customization/007-review-remediation` (Level 1)

&nbsp;

## What's New at a Glance

- **A check that could not run says so.** When the push allowlist probe cannot run, the row shows UNKNOWN and the run ends `STATUS=DEGRADED`, instead of a PASS it never earned.
- **A hook that cannot run fails.** A linked hook without the execute bit now fails its row, because git would skip it without a word.
- **An adapter counts only when it is wired.** The OpenCode and Pi adapters must bind the advisory event to a real handler and import the shared rule checks. A name in a comment or an event set to `false` no longer counts.
- **`/doctor:git setup` runs on Hermes.** It passes `--tool` only for the six tools the check accepts, so a Hermes run no longer stops on a usage error.

&nbsp;

## Upgrade

No migration required. Rerun `/doctor:git setup` to see the stricter results.
