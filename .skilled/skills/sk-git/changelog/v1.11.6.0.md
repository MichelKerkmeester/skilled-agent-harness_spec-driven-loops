# v1.11.6.0, The Machine Router Has Its Own File

This edition keeps skill guidance brief while separating the machine router into its own file.

> Spec folder: `specs/sk-doc/072-skill-routing-and-clarity/014-skill-router-files/005-packet-and-standalone-migration` (Level 1)

&nbsp;

## What's New at a Glance

- **The former router section has its own home.** The old final MACHINE ROUTER section from SKILL.md now lives under the heading 3. MACHINE ROUTER in sibling ROUTER.md. It follows a short overview and intent model and retains the intent map, resource map, default resource, loading levels and routing pseudocode.
- **SMART ROUTING stays concise.** SKILL.md ends the short prose with a link to ROUTER.md. The parsed router is identical to the previous edition, so routing is unchanged.
- **No supporting document needed repointing.** No sk-git reference, playbook, feature catalog entry or asset cited the old router section inside SKILL.md, so this packet left every supporting document where it was and changed only the five router files.
- **Alignment pass: router-adjacent claims now match the files they describe.** The preflight advisory scenario copies `hard-rules.json` beside `SKILL.md` so the documented sequence can fire, the resource-discovery sentence and both GitHub MCP tool pointers name where those resources and tools actually live, the README records the current hook test counts, ROUTER.md names the always-loaded quick reference baseline, and the leaf-manifest note separates the roots the intent router reaches from those the generated manifest reaches.
- **Switching GitHub accounts now includes the way back.** The wrong-account recovery in `finish-workflows.md` pushes, then switches back to the account that was active before, because a switch applies to every session on the machine.
- **Benchmark reports name the skill by its repository path.** Two benchmark reports gave the skill root as an absolute path on one machine. They now use `.opencode/skills/sk-git`.
