# v1.9.0.0, One Command Proves Your Git Setup

`/doctor:git setup` checks every part of sk-git a repository can change and tells you which rules are live, which are missing and which are broken. Several of those parts used to fail without a word, so a repository could look set up while a rule was quietly not enforced.

> Spec folder: `specs/sk-git/033-git-setup-customization` (Level 2)

&nbsp;

## What's New at a Glance

- **Eleven checks in one read-only pass.** The install, hooks, trust, gates, commit rules, push allowlist, worktrees, Commit-Id policy, advisory rules, suppression switches and AI tool hooks each get a result and the source it was read from.
- **Every problem names its fix.** A failing check prints a `repair:` line with the command to run, and `--json` prints the same report as one object for scripts.
- **A half-working setup no longer reads as healthy.** A check it cannot read or a gate you switched off now ends `STATUS=DEGRADED` with exit 3. A failure exits 1, a clean run exits 0 and a bad argument exits 2.
- **The check never runs code from the repository it inspects.** It loads its helpers from its own install, so a cloned repository cannot plant code it runs or change what it reports.
- **The hooks fix fits the repository.** In this checkout the repair names this checkout's hook installer. In any other repository it names a `git config core.hooksPath` line, so a clone's own installer is never suggested.
- **The AI tool check proves the advisory is wired.** Each of the six tool adapters must register the git advisory before its shell tool runs, so a hook registered on the wrong event now fails. `--tool=<name>` names the tool running the check.
- **Changing one commit rule changes one line.** `/doctor:git standards set` keeps the layout of the shipped commit template again, so your `.sk-git/` copy shows a one-line change.

&nbsp;

## Upgrade

No migration required. Run `/doctor:git setup` after you adapt sk-git to your repository, and run each `repair:` line it prints.
