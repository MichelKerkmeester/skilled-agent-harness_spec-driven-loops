# v1.11.11.0, A new worktree can commit again

A worktree you create with `worktree-naming.sh create` can commit again. So can one you fix with `provision`. Provisioning used to turn every private `local-*` command into an absolute link. The mirror gate then blocked every commit there.

&nbsp;

## What's New at a Glance

- **Private commands keep their form.** A command file is copied. A relative mirror link keeps its link text. A private folder stays one shared link. The primary checkout holds them the same way.
- **An edit to a copied file stays in its worktree.** Only a shared folder still reaches every worktree at once.

&nbsp;

## Upgrade

A worktree provisioned before this release still holds absolute links. Remove its private `local-*` entries. Then run `worktree-naming.sh provision` again.
