This additive documentation release makes sk-git's capabilities discoverable and adds manual-testing-playbook coverage for its owner-first worktree tooling. It adds a feature catalog and corrects stale playbook paths. The SKILL router, rules and workflows are unchanged, with no runtime behavior changes.

## What's New at a Glance

- **The feature catalog documents every capability.** `feature-catalog/feature-catalog.md` follows `sk-doc/create-feature-catalog` and groups capabilities under `worktree_naming/`, `session_lifecycle/`, `workflow_playbooks/` and `remote_platform_integration/`, with 11 per-feature files across those categories. Each entry gives its purpose, entry point and when-to-use. Script-backed entries for the owner-first allocator/validators, launch-wrapper session isolator, reaper and pre-push naming hook link to their scripts instead of volatile line numbers.
- **The playbook adds owner-first worktree tooling coverage.** Its new `owner_first_worktree_tooling/` category adds 19 scenarios, `GIT-023`..`GIT-041`. The playbook now has 41 scenarios across 7 categories, up from 22 across 6.
- **Allocator scenarios cover worktree creation.** They exercise locked unique allocation, owner/slug/branch/pair validation, `create` and `create-detached` plus the wrapper-lane exemption.
- **Session-isolator scenarios cover session boundaries.** They exercise top-level isolation, child exec-in-place, runtime-identity validation, the session marker and shared-artifact containment.
- **Reaper and pre-push scenarios cover cleanup and branch checks.** They cover auto-reaping qualifying pairs, keeping non-qualifying pairs, dry-run and orphan-daemon reporting, plus new-branch-only gating, migration tolerance, fail-open, release-branch exemption, bypass env and wrapper-ref rejection.
- **Playbook paths match the on-disk layout.** `SKILL.md` and `README` described scenario files using `manual-testing-playbook/<NN>--<topic>/<NNN>-<scenario>.md`. The actual layout is `manual-testing-playbook/<topic>/<scenario>.md`, with `underscore_case` categories and no numeric prefixes. The root playbook's package-artifacts list and Section 15 cross-reference index had stale hyphenated paths for the existing `GIT-001`..`GIT-022` scenarios and now match their on-disk `underscore_case` names.
- **The root index reflects new coverage.** Its package-artifacts list, scenario count, coverage note and feature-catalog cross-reference reflect the new category and package.

## Upgrade

No migration required. Additive documentation only. No branch grammar, tooling behavior or command surface changed.
