This additive documentation release makes sk-git's capabilities discoverable. It adds manual-testing-playbook coverage for its owner-first worktree tooling. It adds a feature catalog. It corrects stale playbook paths. The SKILL router, rules and workflows are unchanged. There are no runtime behavior changes.

## What's New at a Glance

- **The feature catalog documents every capability.** `feature-catalog/feature-catalog.md` follows `sk-doc/create-feature-catalog`. It groups capabilities under `worktree_naming/`, `session_lifecycle/`, `workflow_playbooks/` and `remote_platform_integration/`. Those categories hold 11 per-feature files. Each entry gives its purpose, entry point and when-to-use. Script-backed entries link to their scripts instead of volatile line numbers. They cover the owner-first allocator/validators, launch-wrapper session isolator, reaper and pre-push naming hook.
- **The playbook adds owner-first worktree tooling coverage.** Its new `owner_first_worktree_tooling/` category adds 19 scenarios, `GIT-023`..`GIT-041`. The playbook now has 41 scenarios across 7 categories. That is up from 22 across 6.
- **Allocator scenarios cover worktree creation.** They exercise locked unique allocation and owner/slug/branch/pair validation. They also exercise `create` and `create-detached`, plus the wrapper-lane exemption.
- **Session-isolator scenarios cover session boundaries.** They exercise top-level isolation and child exec-in-place. They also cover runtime-identity validation, the session marker and shared-artifact containment.
- **Reaper and pre-push scenarios cover cleanup and branch checks.** They cover auto-reaping qualifying pairs and keeping non-qualifying pairs. They cover dry-run and orphan-daemon reporting. They also cover new-branch-only gating, migration tolerance, fail-open, release-branch exemption, bypass env and wrapper-ref rejection.
- **Playbook paths match the on-disk layout.** `SKILL.md` and `README` described scenario files using `manual-testing-playbook/<NN>--<topic>/<NNN>-<scenario>.md`. The actual layout is `manual-testing-playbook/<topic>/<scenario>.md`. It uses `underscore_case` categories and no numeric prefixes. The root playbook's package-artifacts list had stale hyphenated paths. So did its Section 15 cross-reference index. Those paths were for the existing `GIT-001`..`GIT-022` scenarios. They now match their on-disk `underscore_case` names.
- **The root index reflects new coverage.** Its package-artifacts list, scenario count, coverage note and feature-catalog cross-reference reflect the new category and package.

## Upgrade

No migration required. Additive documentation only. No branch grammar, tooling behavior or command surface changed.
