# v1.8.5.0, Worktree and Branch Scripts Report Failure

Two sk-git scripts printed a problem and still exited 0. A caller saw success for a worktree whose dependencies never installed, and for a branch migration that skipped a name collision.

> Spec folder: `specs/sk-code/011-sk-code-poinytail-based-refinement/021-open-ends-remediation/001-typo-proof-parsers` (Level 1)

&nbsp;

## What's New at a Glance

- **A half-provisioned worktree is reported.** `worktree-naming.sh create` still prints the branch and path pair, then exits 3 when provisioning failed, so callers can clean up or retry.
- **Branch migration counts collisions.** `migrate-legacy-branch-names.sh` counts only the pairs it will rename in its summary and exits 1 when a collision was skipped.

&nbsp;

## Upgrade

Callers of `worktree-naming.sh create` that read any non-zero exit as "no worktree" should check for exit 3, which means the worktree exists but still needs provisioning.
