# v1.8.5.0, Worktree and Branch Scripts Report Failure

Two sk-git scripts printed a problem. They still exited 0. A caller saw success for a worktree whose dependencies never installed. A caller also saw success for a branch migration that skipped a name collision.

&nbsp;

## What's New at a Glance

- A half-provisioned worktree is reported.
  - `worktree-naming.sh create` still prints the branch and path pair.
  - The script then exits 3 when provisioning failed.
  - So callers can clean up or retry.
- Branch migration counts collisions.
  - `migrate-legacy-branch-names.sh` counts only the pairs it will rename in its summary.
  - The script exits 1 when a collision was skipped.

&nbsp;

## Upgrade

Callers of `worktree-naming.sh create` that read any non-zero exit as "no worktree" should check for exit 3. Exit 3 means the worktree exists but still needs provisioning.
