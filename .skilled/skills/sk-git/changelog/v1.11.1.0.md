# v1.11.1.0, The Numbered Sweep Stops Keeping Worktrees for Files It Can Rebuild

Two ignored files that a build and an install write into every checkout kept almost every numbered worktree on disk. A branch that had been squash-merged also sat there with no hint of why. The reaper now treats those two files as rebuildable and names a squash-merged branch for what it is.

> Spec folder: `specs/sk-git/035-fsmonitor-daemon-and-worktree-relocation-regression/006-numbered-worktree-cleanup` (Level 2)

&nbsp;

## What's New at a Glance

- **Two build-written files no longer keep a worktree.** An adapter bundle and spec-kit's Node version stamp carry a `# regenerable:` comment in `worktree-provision-paths.txt`, and every other reader of that list still sees a plain comment. SQLite files and `.state/` folders stay protected, because they can hold session state.
- **A squash-merged branch says so.** When a branch is not an ancestor of the live branch but its changes are already in it, the reaper keeps the worktree and reports that the branch was squash-merged and is for you to remove. It never removes one itself.
- **The git skill records the session-start sweep.** Rule 17 now says the sweep runs at most every 6 hours and that `SPECKIT_WORKTREE_AUTOREAP=0` stops it.

&nbsp;

## Upgrade

No migration required. Run `bash .skilled/bin/worktree-reaper.sh --numbered --dry-run` to see each worktree's verdict. To stop another rebuildable ignored file from blocking a removal, add a `# regenerable: <path>` line to `.skilled/skills/sk-git/scripts/worktree-provision-paths.txt`.
