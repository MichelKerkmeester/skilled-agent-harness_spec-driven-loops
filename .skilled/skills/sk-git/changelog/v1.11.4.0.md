# v1.11.4.0, The Routing Summary Comes First

An agent reading this skill met the routing tables before it met a single git rule. The routing material was correct and it sat in the way of the work. The same routing now reads in two parts, a short prose summary that says what selects the skill and what loads first, then a machine router at the end of the file that keeps every table and the pseudocode.

> Spec folder: `specs/sk-doc/072-skill-routing-and-clarity/009-standalone-skills` (Level 2)

&nbsp;

## What's New at a Glance

- **The routing summary is short prose.** Six lines say what selects this skill, what loads first and where the rest of the routing lives.
- **The machine blocks moved over nearly intact.** The loading-level table, every intent table and the resource-loading loop sit in the final `MACHINE ROUTER` section as they were, and no route, keyword or resource changed.
- **One generic loop points at the shared pattern.** The intent-selection loop names the canonical router pattern instead of repeating it. Every intent table, loading level and default resource is unchanged.
- **The routing guidance now points instead of repeating.** The continuous-integration, remote-push and preflight-advisory subsections each state their rule once and link out for the detail, to `references/continuous-integration.md`, `references/remote-branch-policy.md`, `scripts/hooks/README.md` and `scripts/lib/README.md`.
