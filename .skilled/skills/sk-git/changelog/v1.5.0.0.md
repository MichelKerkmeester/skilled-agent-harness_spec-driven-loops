sk-git makes its git safety layer stricter, so no gate can silently strand a push. It adds a SessionStart reconcile for the shared primary checkout. It also adds a helper. The helper restores machine-local spec pointers after a destructive clean.

## What's New at a Glance

- **Every pre-push and commit gate emits a stable `[gate:<name>]` marker when it blocks.** The naming, remote-permission, mass-deletion, skill-root-metadata and test-suite gates name themselves. They also name the exact fix command. They no longer fail with a generic message. A broken optional validator no longer exits past independent gates. Those gates run after it.
- **Blocked autosync pushes leave a durable gate record.** `git-sync.sh` captures and replays the hook output. It identifies the rejecting gate and prints `AUTOSYNC BLOCKED`. It appends `blocked gate=<name> fix=<command>` to the common-dir log. So a gate rejection cannot be mistaken for a silent push race.
- **The primary checkout catches up at session start.** `git-primary-reconcile.sh` runs only in the main checkout. It runs on the resolved live branch, with tracked files clean. It fast-forwards when behind. It rebase-publishes local commits when ahead. So a session that commits directly in the primary does not leave the checkout ahead of and behind origin.
- **Reconcile never touches uncommitted work.** Several things stop it safely and loudly. They are a dirty tracked tree, a linked worktree, a non-live branch, a rebase conflict or a pre-push gate rejection. It ignores untracked build output. It asserts that a rebase abort restores the original clean state. It treats every internal failure as non-fatal, so session start continues.
- **SessionStart runs the reconcile in every runtime.** It starts in the background in Claude, Codex, OpenCode and Pi. So startup is never delayed. This replaces the follower daemon that was never auto-started. The step is now reliably wired.
- **Machine-local spec pointers can be restored after `git clean -fdx`.** `relink-local-specs.sh` recreates the gitignored symlinks. Those are for machine-local spec folders whose real content lives outside the working tree. It is idempotent. It refuses to create a link when the target is missing. So `git clean -fdx` can delete only a re-creatable pointer, never the data behind it.
- **Branch grammar, the allocator and commit rules are unchanged.** Owner-first naming stays untouched. So does the remote-push permission model.
- **Real mass-deletion and remote-permission violations still block.** The change only guarantees that every block is loud and logged.

## Upgrade

The reconcile and autosync loop is on by default in the main checkout. Disable the whole loop with `SYSTEM_LIVE_SYNC_DISABLED=1`. Disable the reconcile leg alone with `SYSTEM_PRIMARY_RECONCILE_DISABLED=1`. Disable the publish leg with `SPECKIT_AUTOSYNC=0`. The full gate map and reconcile behavior live in `references/continuous-integration.md`.
