# sk-git v1.7.0.0

Every authored commit now carries a prose body that says why it exists.

- The `commit-msg` hook refuses a commit without one.
- That holds whether it stages one path or forty.
- Git-generated subjects stay exempt.
- `Merge`, `Revert "`, `fixup!`, `squash!` and `amend!` messages pass as before.

The body must be prose, not commit trailers.

- At least one prose line sits above the trailers.
- That holds whatever the path count.
- A message with only `Spec:` or `Commit-Id:` below the subject is refused.
- Trailers do not count as a body.

The rule now reaches the guides and commit commands.

- Every example shows a body.
- The example commands in the skill's guides now pass one.

&nbsp;

## Why This Release

A body used to be required only when four or more paths were staged. Small commits went in with a subject alone.

- So a search through the history found what changed but not why.
- A one-path commit is searched as often as a large one.
- Its reason is just as easy to lose.

## Commit Bodies

The hook, the written contract and the commit commands now follow one body rule.

#### The Hook Holds Every Commit to One Rule <a id="c-the-hook-holds-every-commit-to-one-rule"></a>

- `commit-msg` no longer counts staged paths.
- An authored message with no prose line below the subject is blocked.
- The message reads "SKILL.md requires a body on every authored commit".
- The bypass stays `SPECKIT_SKIP_COMMIT_MSG_VALIDATE=1`.
- At least one prose line sits above the trailers.
- That holds whatever the path count.
- Trailers do not count as a body.
- A message with only `Spec:` or `Commit-Id:` below the subject is refused.
- Git-generated subjects stay exempt.
- `Merge`, `Revert "`, `fixup!`, `squash!` and `amend!` messages pass as before.

#### The Contract Says the Same Thing Everywhere <a id="c-the-contract-says-the-same-thing-everywhere"></a>

- The body contract in `SKILL.md` now requires a body on every authored commit.
- It keeps the fuller Context, Changes and Verification structure.
- That structure covers fixes, non-obvious reasons and commits that span several areas.
- The reference guides state the same rule.
- So do the commit message template, the feature catalog and the manual testing scenario.
- That scenario covers a conventional commit from a diff.

#### Commands That Commit Pass a Body <a id="c-commands-that-commit-pass-a-body"></a>

- The deep research and deep review checkpoint commits now include a body line.
- So does the hook installer's test commit.
- So do the runbooks that tell an operator to commit.
- Following them no longer runs into the hook.
- Every example shows a body.
- The example commands in the skill's guides now pass one.

## Upgrade Notes

A few short notes cover the upgrade.

#### Before You Start <a id="c-before-you-start"></a>

1. Add a body to small commits. One line of reason below the subject is enough: `git commit -m "type(scope): summary" -m "Why the change exists."`

<details>
<summary><b>Commit scripts</b></summary>

- Scripts that commit need a body or a hooks bypass.
- A script that commits under the global hooks with a subject alone is now refused.
- Give it a second `-m`.
- Or run its throwaway commits with `core.hooksPath=/dev/null`.

</details>

<details>
<summary><b>Existing history</b></summary>

- History stays as it is.
- The hook checks each message as it is written.
- So existing commits are not touched.

</details>
