# v1.11.15.0, A New Worktree Builds Its Advisor Skill-Graph Database

A new worktree used to start without the advisor skill-graph database. The file is gitignored, so the advisor reported degraded health. Its suite failed until someone ran the scan by hand. Provisioning now builds it once, after every install and build succeeds. A fresh worktree reports `ok` health straight away.

&nbsp;

## What's New at a Glance

- Provisioning builds the database with the advisor's own scan.
  - It runs `skill_graph_scan --trusted` once, after every install and build succeeded.
  - A worktree that already has `skill-graph.sqlite` is never rescanned.
  - The scan counts as a built output. A clean run still ends `0 failed`.
- A broken scan fails provisioning.
  - A scan that exits non-zero stops the run.
  - So does a scan that exits 0 with no database.
- The scan leaves the advisor daemon running.
  - It exits on its own after 30 idle minutes.
  - Any advisor hook in that worktree starts the same daemon.

&nbsp;

## How It Was Checked

`worktree-naming.test.sh` passes 190 tests, up from 178. The new cases stub the advisor CLI. Removing the new block fails 6 of them. Before this change, a fresh worktree's advisor suite failed 24 tests. A real provision with no database printed `building the skill-graph database` and health `ok`.

&nbsp;

## Upgrade

No migration required. An existing worktree gets its database on its next `worktree-naming.sh provision <path>` run.
