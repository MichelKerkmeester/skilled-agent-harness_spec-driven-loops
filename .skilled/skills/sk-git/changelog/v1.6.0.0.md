Commit history is easier to cite and search through a contiguous trailer paragraph attached to every commit. Packet work carries a `Spec:` reference, and every commit carries a `Commit-Id:` with a stable repository-wide ordinal.

## Why This Release

Before this release, a commit was reachable only by a hash nobody remembers or by reading `git log`. Finding the commits behind a packet meant searching by eye, and a single commit could not be cited by a short ordinal.

## What's New at a Glance

- **Every commit gets a trailer paragraph.** Packet work carries a `Spec:` reference, and every commit carries a `Commit-Id:`.
- **Hooks stamp and check commit trailers.** `prepare-commit-msg` adds the paragraph, and `commit-msg` enforces its keys.
- **Ordinal tools allocate and stamp commit ids.** The scripts support repository-wide allocation and branch stamping.
- **Git log queries find commits by their trailers.** They can list packet commits, locate an ordinal's commit and list stamped ids.
- **The catalog and playbook cover commit identity.** The catalog adds a subsection, and the manual testing playbook adds scenario GIT-044.

## Commit Trailers

#### Packet and Commit References

Each commit gets a contiguous trailer paragraph. Packet work carries `Spec: <track>/<packet>[/<phase>...]`, and every commit carries `Commit-Id: NNNNNNN`, a seven-digit repository-wide ordinal minted once under a lock. `Refs:` is for external links only, so packet references now live in `Spec:` instead.

&nbsp;

#### Hooks Handle Commit Cases

`prepare-commit-msg` writes a blank line and the trailer paragraph when a commit has a body. It keeps the id on amend because the amended commit already owns it, and re-mints on cherry-pick because the picked commit keeps its own. In a repository without the allocator, the stamper exits silently.

`commit-msg` whitelists `Spec:` and `Commit-Id:`, refuses an id that is not exactly seven digits and refuses an id that already belongs to another commit. Its duplicate scan excludes `HEAD`, so an amend never collides with itself.

## Commit Discovery

#### Ordinals Support Branch Work

`scripts/commit-id-naming.sh` allocates the next value under a lock with a history-derived high-water mark. It exposes `allocate`, `next`, `scan-max`, `validate` and `rebuild-highwater`.

Given a branch and a base, `scripts/stamp-branch.sh` stamps an ordinal onto each unique commit so a rebase does not leave the branch's commits unidentified.

&nbsp;

#### Trailer Queries Find Commits

`git log -E --grep='^Spec: sk-git/028'` lists a packet's commits. `git log --fixed-strings --grep='Commit-Id: 0009113'` finds the commit that owns an ordinal, and `git log --format='%(trailers:key=Commit-Id,valueonly)'` lists every stamped id.

&nbsp;

#### Documentation Covers Commit Identity

The feature catalog carries a "Commit Identity And Search" subsection. The manual testing playbook carries scenario GIT-044.

---

## Git Conventions

#### Existing Rules Are Untouched

The Conventional Commit subject and body grammar, the type and scope priority orders and the artifact-filtering rules are untouched. The numbered-worktree grammar, the per-namespace allocator and every pre-push and pre-commit gate are untouched.

---

## Upgrade Notes

- **Install the updated hooks.** New commits pick up the trailer paragraph automatically once the hooks are installed.
- **No action is required in repositories without the allocator.** The stamper exits silently in those repositories.
- **Existing commits are not rewritten by this release.** They stay as they are until the operator runs the separate, operator-gated history rewrite.
