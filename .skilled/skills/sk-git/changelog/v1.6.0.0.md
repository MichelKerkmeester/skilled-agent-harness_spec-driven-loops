A contiguous trailer paragraph is attached to every commit. That makes commit history easier to cite and search. Packet work carries a `Spec:` reference. Every commit carries a `Commit-Id:` with a stable repository-wide ordinal.

## Why This Release

Before this release, a commit was reachable only by a hash nobody remembers. You could also read `git log`. Finding the commits behind a packet meant searching by eye. A single commit could not be cited by a short ordinal.

## What's New at a Glance

- **Every commit gets a trailer paragraph.** Packet work carries a `Spec:` reference. Every commit carries a `Commit-Id:`.
- **Hooks stamp and check commit trailers.** `prepare-commit-msg` adds the paragraph. `commit-msg` enforces its keys.
- **Ordinal tools allocate and stamp commit ids.** The scripts support repository-wide allocation. They also stamp a branch.
- **Git log queries find commits by their trailers.** They can list packet commits. They can locate an ordinal's commit and list stamped ids.
- **The catalog and playbook cover commit identity.** The catalog adds a subsection. The manual testing playbook adds a scenario for finding commits by packet and identifier.

## Commit Trailers

#### Packet and Commit References

Each commit gets a contiguous trailer paragraph. Packet work carries `Spec: <track>/<packet>[/<phase>...]`. Every commit carries `Commit-Id: NNNNNNN`. That is a seven-digit repository-wide ordinal, minted once under a lock. `Refs:` is for external links only. So packet references now live in `Spec:` instead.

&nbsp;

#### Hooks Handle Commit Cases

`prepare-commit-msg` writes a blank line and the trailer paragraph when a commit has a body. It keeps the id on amend. That is because the amended commit already owns it. It re-mints on cherry-pick. That is because the picked commit keeps its own. In a repository without the allocator, the stamper exits silently.

`commit-msg` whitelists `Spec:` and `Commit-Id:`. It refuses an id that is not exactly seven digits. It refuses an id that already belongs to another commit. Its duplicate scan excludes `HEAD`. So an amend never collides with itself.

## Commit Discovery

#### Ordinals Support Branch Work

`scripts/commit-id-naming.sh` allocates the next value under a lock. It uses a history-derived high-water mark. It exposes `allocate`, `next`, `scan-max`, `validate` and `rebuild-highwater`.

`scripts/stamp-branch.sh` takes a branch and a base. It stamps an ordinal onto each unique commit. So a rebase does not leave the branch's commits unidentified.

&nbsp;

#### Trailer Queries Find Commits

`git log -E --grep='^Spec: sk-git/028'` lists a packet's commits. `git log --fixed-strings --grep='Commit-Id: 0009113'` finds the commit that owns an ordinal. `git log --format='%(trailers:key=Commit-Id,valueonly)'` lists every stamped id.

&nbsp;

#### Documentation Covers Commit Identity

The feature catalog carries a "Commit Identity And Search" subsection. The manual testing playbook carries a scenario that finds commits by packet and identifier.

---

## Git Conventions

#### Existing Rules Are Untouched

The Conventional Commit subject and body grammar are untouched. So are the type and scope priority orders and the artifact-filtering rules. The numbered-worktree grammar and the per-namespace allocator are untouched. So is every pre-push and pre-commit gate.

---

## Upgrade Notes

- **Install the updated hooks.** New commits pick up the trailer paragraph automatically once the hooks are installed.
- **No action is required in repositories without the allocator.** The stamper exits silently in those repositories.
- **Existing commits are not rewritten by this release.** They stay as they are until the operator runs the separate, operator-gated history rewrite.
