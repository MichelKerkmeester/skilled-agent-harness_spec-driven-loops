# v1.9.5.0, Worktrees Provision Every Package and Rebuild What Changed

Worktree provisioning installs and builds the dependencies a new worktree needs. That happens before it can build, test or pass its commit gates. Five tracked package trees were missing from its list. An existing checkout could keep a build that no longer matched its sources. Now every tracked package is provisioned or excluded with a stated reason. A stale output is rebuilt.

&nbsp;

## What's New at a Glance

- **Every tracked package has a place in the list.** A test fails when a tracked `package.json` is neither listed nor excluded. The two Pi extensions join the list. So does the DESIGN.md backend. A fresh worktree can run their suites.
- **The OpenCode plugins install their dependencies.** The `.opencode` folder has its own package. A fresh worktree now installs it. So the plugin suite can import `zod`.
- **Bun packages install with bun.** A package with a `bun.lock` and no `package-lock.json` installs with `bun install --frozen-lockfile`. It builds with `bun run`. A missing bun fails that package. It does not fall back to npm.
- **A stale output is rebuilt.** Each successful build records a fingerprint of its tracked inputs. Provisioning rebuilds an output when that fingerprint no longer matches. A deleted input counts as a change. The fingerprint is taken before the build runs. So an edit made during a build still triggers the next one.
- **Extra build sources count.** A provision-list line can name the source paths a build compiles after its output. A change in one of them rebuilds that output.
- **A subdirectory provisions the whole worktree.** Passing a subdirectory used to skip every entry. It still exited 0. Provisioning now starts from the worktree root.
- **A failed install says why.** Provisioning prints the error lines from an install that fails.
- **The ClickUp placeholder is skipped.** The ClickUp MCP folder declares no dependencies. It runs only an echo script. Its hosted server starts through `npx mcp-remote`. So provisioning skips the folder. It skips the Obsidian placeholder the same way.

&nbsp;

## Upgrade

No migration required. The next provision of an existing worktree rebuilds each output that has no build stamp yet. Then it records one.
