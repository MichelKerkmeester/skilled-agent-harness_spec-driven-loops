# v1.9.5.0, Worktrees Provision Every Package and Rebuild What Changed

Worktree provisioning installs and builds the dependencies a new worktree needs before it can build, test or pass its commit gates. Five tracked package trees were missing from its list, and an existing checkout could keep a build that no longer matched its sources. Every tracked package is now either provisioned or excluded with a stated reason, and a stale output is rebuilt.

&nbsp;

## What's New at a Glance

- **Every tracked package has a place in the list.** A test fails when a tracked `package.json` is neither listed nor excluded. The two Pi extensions and the DESIGN.md backend join the list, so a fresh worktree can run their suites.
- **The OpenCode plugins install their dependencies.** The `.opencode` folder has its own package, and a fresh worktree now installs it, so the plugin suite can import `zod`.
- **Bun packages install with bun.** A package that ships a `bun.lock` and no `package-lock.json` installs with `bun install --frozen-lockfile` and builds with `bun run`. A missing bun fails that package instead of falling back to npm.
- **A stale output is rebuilt.** Each successful build records a fingerprint of its tracked inputs, and provisioning rebuilds an output when that fingerprint no longer matches. A deleted input counts as a change, and the fingerprint is taken before the build runs, so an edit made during a build still triggers the next one.
- **Extra build sources count.** A provision-list line can name the source paths a build compiles after its output. A change in one of them rebuilds that output.
- **A subdirectory provisions the whole worktree.** Passing a subdirectory used to skip every entry and still exit 0. Provisioning now starts from the worktree root.
- **A failed install says why.** Provisioning prints the error lines from an install that fails.
- **The ClickUp placeholder is skipped.** The ClickUp MCP folder declares no dependencies and runs only an echo script. Its hosted server starts through `npx mcp-remote`, so provisioning skips the folder, the same way it skips the Obsidian placeholder.

&nbsp;

## Upgrade

No migration required. The next provision of an existing worktree rebuilds each output that has no build stamp yet, then records one.
