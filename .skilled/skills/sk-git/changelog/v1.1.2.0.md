# v1.1.2.0, Numbered Worktrees and Sharper Git Routing

This release standardizes how named feature worktrees are named. It also sharpens how the skill advisor discovers sk-git.

## What's New at a Glance

- **Named feature worktrees use numbered `wt/{NNNN}-{name}` branches and matching `.worktrees/{NNNN}-{name}` directories.** This replaces `type/short-description` branches and unnumbered `.worktrees/short-desc` directories. The `wt/` prefix groups feature-worktree branches in Git UIs. The global four-digit counter starts at `0001`. It advances using `max(existing NNNN under .worktrees/) + 1`, as in `wt/0001-add-oauth`.
- **Named feature worktrees have one repo-local home.** They live under the already-gitignored `.worktrees/` directory. So directory selection no longer juggles `worktrees/` or a global `~/.config` location.
- **The existing lifecycle strategies are kept under new names.** Fast-merge replaces `main_temp` and is the default. Long-running replaces `feature_branch`. Both branch-creating lifecycles share the same branch name. They differ only in post-creation management.
- **Detached experiment replaces `main_detached`.** Detached experiments create no branch. They receive no number.
- **The launch wrapper's ephemeral worktrees use a separate naming lane.** Their paths are `work/{runtime}/{slug}` and `.worktrees/{runtime}-{slug}`. These per-session worktrees are auto-reaped. They are intentionally not numbered.
- **Git workflow intent now routes reliably to sk-git.** The strengthened description and triggers cover git worktree, create worktree, numbered worktree, restructure worktrees and worktree prefix. They also cover `wt/` branch, branch, commit, conventional commits, pull request and PR. Merge, rebase, finish work, integrate changes and git workflow are covered too. The skill cedes spec-folder, memory, continuity and save-context intent to system-spec-kit. It cedes code-implementation and test-writing intent to sk-code.

## Upgrade

No migration required. Existing worktrees keep their current names. The new `wt/{NNNN}-{name}` convention applies to worktrees created from this release onward. The launch wrapper's ephemeral per-session worktrees are unaffected.
