# v1.11.12.0, A rebase re-mints only on a pick

The sk-git skill said a rebase keeps the `Commit-Id` its message carries. That was wrong. The commit hook re-mints only when the repository asks for ids. It also needs git to set `CHERRY_PICK_HEAD`. The corrected sentence says so. It names the rebase cases that keep the id.

> Spec folder: `specs/hooks-plugins-extensions/session-turn-boundaries/002-session-relaunch-loop/039-hop-dialog-goal-title/018-sk-git-rebase-sentence`

## What's New at a Glance

- **The rebase rule matches the hook.** A pick onto a moved base gets a fresh id. A reword, an unreplayed commit and `git rebase --apply` keep the id.
