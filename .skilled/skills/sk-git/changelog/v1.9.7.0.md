# v1.9.7.0, New Worktrees Get the Operator's Private Commands

A private `local-*` command belongs to the operator, so git ignores it, and a new worktree used to start without it. Provisioning now links each one in from the primary checkout.

&nbsp;

## What's New at a Glance

- **Private commands follow you into a worktree.** `worktree-naming.sh create` and `worktree-naming.sh provision` link every `local-*` entry under the command and prompt folders the root `.gitignore` names, from the primary checkout into the worktree. A new mirror folder added to those ignore rules is picked up with no change to the script.
- **One copy, not several.** Each entry is a link to the primary checkout's copy, so an edit made in any worktree reaches every other.
- **Nothing is overwritten.** A path that already exists in the worktree, file or link, is left alone. A folder that holds only private entries, such as `.skilled/commands/assets/`, is created when something needs linking into it.
- **Private skills are not linked.** Linking a `local-*` skill would change what the skill advisor and graph compilers see inside a worktree, and so what its tests report, so skills stay out of this step.
- **It never fails provisioning.** A checkout with no private command is the common case, and a primary checkout or a bare clone links nothing.

&nbsp;

## Upgrade

No migration required. Run `worktree-naming.sh provision` in an existing worktree to link the private commands it is missing.
