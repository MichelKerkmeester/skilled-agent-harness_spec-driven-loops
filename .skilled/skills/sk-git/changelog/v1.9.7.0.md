# v1.9.7.0, New Worktrees Get the Operator's Private Commands

A private `local-*` command belongs to the operator. So git ignores it. A new worktree used to start without it. Provisioning now links each one in from the primary checkout.

&nbsp;

## What's New at a Glance

- **Private commands follow you into a worktree.** `worktree-naming.sh create` and `worktree-naming.sh provision` link every `local-*` entry into the worktree. They take each one from the primary checkout. The entries sit under the command and prompt folders the root `.gitignore` names. A new mirror folder added to those ignore rules is picked up with no change to the script.
- **One copy, not several.** Each entry is a link to the primary checkout's copy. So an edit made in any worktree reaches every other.
- **Nothing is overwritten.** A path that already exists in the worktree is left alone. That holds for a file or a link. A folder that holds only private entries is created when something needs linking into it. One example is `.skilled/commands/assets/`.
- **Private skills are not linked.** Linking a `local-*` skill would change what the skill advisor and graph compilers see inside a worktree. That would also change what its tests report. So skills stay out of this step.
- **It never fails provisioning.** A checkout with no private command is the common case. A primary checkout or a bare clone links nothing.

&nbsp;

## Upgrade

No migration required. Run `worktree-naming.sh provision` in an existing worktree. That links the private commands it is missing.
