# v1.11.0.0, Finished Numbered Worktrees Clean Themselves Up

Numbered worktrees stayed on disk after their branch was merged until someone removed them by hand, and each one kept an fsmonitor daemon alive. This release lets the worktree reaper remove a numbered worktree once nothing in it is worth keeping, and runs that sweep at session start. It also tightens the fsmonitor reaper and puts a time limit on every git call in the commit and push hooks that reads the index.

> Spec folder: `specs/sk-git/035-fsmonitor-daemon-and-worktree-relocation-regression` (Level 2)

&nbsp;

## What's New at a Glance

- **The worktree reaper removes finished numbered worktrees.** `worktree-reaper.sh --numbered` removes a numbered worktree only when its branch is merged into the live branch and it has no uncommitted, untracked or unrecoverable ignored files. It also needs no process working in it and no activity for 48 hours. Anything else is kept with a one-line reason, and `--dry-run` shows the verdicts without touching anything.
- **Each session start runs that sweep in the background.** The worktree guard starts a detached `--numbered` sweep at most once every 6 hours. `SPECKIT_WORKTREE_AUTOREAP=0` stops only the sweep, and disabling the guard stops both.
- **The doctor counts numbered worktrees.** `/doctor:git setup` reports how many numbered worktrees exist and how many the sweep could remove, as information that never changes the verdict.
- **The fsmonitor reaper checks before it ends a daemon.** It rechecks a daemon's start time right before ending it, stops only a daemon that watches one worktree, and rereads the worktree list on every run. `--orphans` reports and ends daemons whose worktree folder is gone.
- **Hook git calls can no longer hang.** Every git call in the commit and push hooks that reads the index now runs through a shared helper with a 20 second limit (`SPECKIT_GIT_TIMEOUT`). A call that runs out blocks with `BLOCKED [gate:git-timeout]` instead of waiting forever. Creating a worktree from the launcher gets 60 seconds (`SPECKIT_WORKTREE_ADD_TIMEOUT`).

&nbsp;

## Upgrade

No migration required. Run `bash .skilled/bin/worktree-reaper.sh --numbered --dry-run` to see what the sweep would remove. A squash-merged branch never counts as merged, so its worktree is kept, and so is any worktree holding ignored files outside the regenerable list.
