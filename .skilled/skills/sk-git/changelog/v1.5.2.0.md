This release makes the worktree base configurable. Worktrees can live outside the primary checkout.

&nbsp;

## Why This Release

Nesting dozens of worktrees under `.worktrees/` forces tools to walk every worktree's `node_modules` on each pass. Those tools scan from the repo root. They include `git status`, the fsmonitor daemon, Git GUIs and file-sync clients. On large trees, that shows up as sustained CPU.

&nbsp;

## What's New at a Glance

- The worktree base is configurable.
  - Set `SPECKIT_WORKTREE_BASE` or `speckit.worktreeBase` to choose where worktrees live.
  - The environment value takes precedence over git config.
  - The default is still in-checkout `.worktrees`, relative to the main toplevel.
  - So other clones, CI and the test suite are unaffected unless a base is explicitly configured.
- Worktree creation follows the chosen base.
  - Relative values resolve against the main toplevel.
  - A leading `~` expands to `$HOME`.
  - `create` and `create-detached` now create under that base.
  - `create` and `create-detached` emit an absolute directory path.
- Validation accepts worktrees from either base.
  - `is_valid_pair` validates a `worktrees/NNN-slug` branch against a directory.
  - That directory's basename is `NNN-slug`.
  - That directory sits under the configured base or the legacy `.worktrees` parent.
  - So worktrees from before and after relocation both pass.
- Session launch and cleanup use the same base.
  - `worktree-session.sh` places session worktrees there.
  - `worktree-reaper.sh` prunes and daemon-orphan-detects against it.
  - The reaper's orphan detection now anchors on the resolved base.
  - The reaper's orphan detection canonicalizes each candidate path's parent instead of matching a fixed `.worktrees/` string.
  - That also makes it immune to `/var` versus `/private/var` symlink skew.
- Relocation preserves numbering and safety rules.
  - Number allocation scans each registered worktree's basename, regardless of location.
  - So moving the base cannot reissue a live number.
  - Branch grammar (`worktrees/NNN-slug`, `branches/NNN-slug`), the locked per-namespace allocator, remote-push permission and every pre-push/commit gate are unchanged.

&nbsp;

## Upgrade

Opt in per clone with `git config speckit.worktreeBase <absolute-path>`. You can also export `SPECKIT_WORKTREE_BASE`. New worktrees then land there. To relocate existing worktrees, run `git worktree move <old> <new>`. Then run `git worktree repair`. Unset the config to return to the in-checkout `.worktrees` layout. No action is required for a clone that leaves the setting unset.
