This release makes the worktree base configurable so worktrees can live outside the primary checkout.

## Why This Release

Nesting dozens of worktrees under `.worktrees/` forces tools that scan from the repo root, including `git status`, the fsmonitor daemon, Git GUIs and file-sync clients, to walk every worktree's `node_modules` on each pass. On large trees, that shows up as sustained CPU.

## What's New at a Glance

- **The worktree base is configurable.** Set `SPECKIT_WORKTREE_BASE` or `speckit.worktreeBase` to choose where worktrees live. The environment value takes precedence over git config. The default is still in-checkout `.worktrees`, relative to the main toplevel, so other clones, CI and the test suite are unaffected unless a base is explicitly configured.
- **Worktree creation follows the chosen base.** Relative values resolve against the main toplevel and a leading `~` expands to `$HOME`. `create` and `create-detached` now create under that base and emit an absolute directory path.
- **Validation accepts worktrees from either base.** `is_valid_pair` validates a `worktrees/NNN-slug` branch against a directory whose basename is `NNN-slug` under the configured base or the legacy `.worktrees` parent, so worktrees from before and after relocation both pass.
- **Session launch and cleanup use the same base.** `worktree-session.sh` places session worktrees there, while `worktree-reaper.sh` prunes and daemon-orphan-detects against it. The reaper's orphan detection now anchors on the resolved base by canonicalizing each candidate path's parent rather than matching a fixed `.worktrees/` string, which also makes it immune to `/var` versus `/private/var` symlink skew.
- **Relocation preserves numbering and safety rules.** Number allocation scans each registered worktree's basename regardless of location, so moving the base cannot reissue a live number. Branch grammar (`worktrees/NNN-slug`, `branches/NNN-slug`), the locked per-namespace allocator, remote-push permission and every pre-push/commit gate are unchanged.

## Upgrade

Opt in per clone with `git config speckit.worktreeBase <absolute-path>` or by exporting `SPECKIT_WORKTREE_BASE`. New worktrees then land there. To relocate existing worktrees, run `git worktree move <old> <new>` and then `git worktree repair`. Unset the config to return to the in-checkout `.worktrees` layout. No action is required for a clone that leaves the setting unset.
