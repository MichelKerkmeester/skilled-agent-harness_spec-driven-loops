GitKraken MCP gives `sk-git` a second remote-collaboration transport. It sits alongside GitHub MCP. The skill now documents it and routes to it. It safety-gates it as it does GitHub MCP.

&nbsp;

## What's New at a Glance

- GitKraken MCP adds cross-platform collaboration.
  - `gitkraken/mcp` (`@gitkraken/gk`, stdio) reaches GitHub, GitLab, Azure DevOps, Bitbucket and Jira from one tool.
  - Its GitLens AI workflows cover commit composer, launchpad triage, PR review and work-start.
  - GitLens AI workflows have no local equivalent.
- GitKraken requests route to their reference.
  - The `GITKRAKEN_MCP` intent and the `gitkraken` and `gitlens` keyword triggers send cross-platform PR/issue requests to `references/gitkraken-mcp-integration.md`.
  - The intent and the keyword triggers send GitLens-shaped requests there too.
  - The guide covers tool selection and usage examples.
  - The guide also covers error handling.
  - The guide lists the full tool surface, captured live from `gk mcp --list-tools` against an authenticated install.
  - The guide uses that live capture rather than the incomplete upstream README.
  - The guide mirrors the structure of `github_mcp_integration.md`.
  - So the two remote-transport docs read as one family.
- ALWAYS rule #12 keeps local mutations on Bash.
  - It sends `git_add_or_commit`, `git_push`, `git_branch`, `git_checkout`, `git_worktree` and `git_stash` to the existing Bash workflow.
  - The tools duplicate mutations the skill already gates.
  - The gates are the ask-first worktree rule, the no-direct-branch rule and the conventional-commit format.
  - GitKraken MCP is reserved for GitLens AI workflows and cross-platform issue, PR and repository work with no local equivalent.
- Former rule #12, operator direct-push authorization, is now #13.
  - The cross-reference elsewhere in the skill is corrected.
