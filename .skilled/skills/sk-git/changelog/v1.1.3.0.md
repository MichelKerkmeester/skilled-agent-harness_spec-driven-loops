GitKraken MCP gives `sk-git` a second remote-collaboration transport alongside GitHub MCP. The skill now documents and routes to it and safety-gates it as it does GitHub MCP.

## What's New at a Glance

- **GitKraken MCP adds cross-platform collaboration.** `gitkraken/mcp` (`@gitkraken/gk`, stdio) reaches GitHub, GitLab, Azure DevOps, Bitbucket and Jira from one tool. Its GitLens AI workflows cover commit composer, launchpad triage, PR review and work-start, with no local equivalent.
- **GitKraken requests route to their reference.** The `GITKRAKEN_MCP` intent and `gitkraken`/`gitlens` keyword triggers send cross-platform PR/issue and GitLens-shaped requests to `references/gitkraken-mcp-integration.md`. The guide covers tool selection, the full tool surface captured live from `gk mcp --list-tools` against an authenticated install rather than the incomplete upstream README, usage examples and error handling. It mirrors the structure of `github_mcp_integration.md`, so the two remote-transport docs read as one family.
- **ALWAYS rule #12 keeps local mutations on Bash.** It directs `git_add_or_commit`, `git_push`, `git_branch`, `git_checkout`, `git_worktree` and `git_stash` to the existing Bash workflow. These tools duplicate mutations the skill already gates behind the ask-first worktree rule, the no-direct-branch rule and the conventional-commit format. GitKraken MCP is reserved for GitLens AI workflows and cross-platform issue/PR/repository work with no local equivalent.
- **Former rule #12, operator direct-push authorization, is now #13.** Its cross-reference elsewhere in the skill is corrected.
