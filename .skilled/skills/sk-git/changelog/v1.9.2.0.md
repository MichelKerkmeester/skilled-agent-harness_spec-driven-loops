# v1.9.2.0, The Setup Check Holds Outside This Checkout

`/doctor:git setup` gave wrong verdicts. That happened when it inspected a repository other than the one it ships in. Each check now reports what is true for the repository it inspects.

&nbsp;

## What's New at a Glance

- **Clones get the right trust verdict.** A clone whose hooks link into its own tree passes the trust row. It is not told its scripts do not run.
- **The rules check reads the right file.** It validates the repository's own `hard-rules.json`. The advisory reads that file. The check shows DEGRADED when the file is missing.
- **A registration must be able to run.** An AI tool hook counts only when the script or import it names exists. Claude's `"*"` matcher counts as match-all.
- **Repairs work in any folder.** Every repair path is quoted. So a folder name with a space no longer breaks the command.
- **Hermes is the seventh runtime.** `--tool=hermes` is accepted. It checks the Hermes adapter. So a healthy Hermes install reaches OK.
- **Short git prompts reach sk-git.** These prompts now route to sk-git instead of nothing: "pre-push hook", "push allowlist", "hook trust", "hook gates", "cherry pick" and "squash commits".

&nbsp;

## Upgrade

No migration required. Rerun `/doctor:git setup`. In Hermes, pass `--tool=hermes`.
