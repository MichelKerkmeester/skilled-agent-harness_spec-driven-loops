# v1.11.7.0, Environment Steps Between the cd and the Git Command Keep the cd

The preflight advisory resolves the directory a git command runs in. It recognised `cd <dir> && git ...` and looked no further. So a shell that exported a variable in between lost the `cd`. The git command was then judged against the session checkout. `add-pathspec-matches-nothing` warned about files that were sitting in the target worktree.

&nbsp;

## What's New at a Glance

- An assignment step between the `cd` and the git command keeps the `cd`.
  - For `cd wt && export A=1 B=2 C=3; git add f1`, `cd wt && export A=1 && git add f1` and `cd wt && A=1; git add f1` the pathspec now resolves in `wt`.
  - So the false advisory is gone.
- Nothing else is allowed in that position.
  - The step has to be assignments alone.
  - The step may sit behind `export`.
  - The step must be closed by `;` or `&&`.
  - A shape such as `cd wt && echo hi; git add f1` still warns.
  - That is because a command that assigns nothing leaves the chain reaching the git command unproven.
- The rule stays fail-open.
  - A shape the pattern cannot read leaves the effective directory unknown.
  - So the checks stay silent rather than guess.
- Four assertions cover the three recognised shapes and the one rejected shape.
  - The four assertions sit beside the existing `cd` and `-C` cases in the same test.

No action is needed.
