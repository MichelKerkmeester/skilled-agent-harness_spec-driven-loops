# v1.10.1.0, Release Requests That Tag Reach the Git Skill

A request such as "set up a release workflow that tags and publishes" went to the GitHub Actions surface, because that surface carried a bare `release workflow` alias. Tagging and publishing a release is git work this skill owns, so the request now reaches sk-git.

> Spec folder: `specs/sk-code/015-quality-agnostic-gate/011-alignment-fixes` (Level 2)

&nbsp;

## What's New at a Glance

- **A tag-and-publish release request routes to sk-git.** `git tag` and `tags and publishes` now point the advisor at this skill, and the advisor anchors sk-git when a release action such as "cut a release" sits beside a tag. Neither the phrases nor the anchor match the bare word `release`, so a request such as "update skilled to the latest release" keeps its own route.
- **GitHub Actions release work stays with the CI surface.** A request to set up a GitHub Actions release or deploy workflow still routes to `sk-code-ci`.

&nbsp;

## Upgrade

No action is needed. The advisor picks up the new vocabulary on its next index.
