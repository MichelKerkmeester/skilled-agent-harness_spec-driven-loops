# v1.1.12.0, The Parity Table Matches the Live Runs

The live runs on Aside 1.26.626.1517 showed that `page.on` rejects the `console`, `request` and `response` events and that `page.context` is undefined. The parity table still called these patterns confirmed or skip-valid.

&nbsp;

## What's New at a Glance

- Console capture and network capture are recorded as gaps on 1.26.626.1517. The error Aside prints points to `page.console.logs()`, which has not been run.
- Context cookies, including HttpOnly ones, are a gap because `page.context` is undefined. Page-visible cookie names and storage keys ran without error, on a page with no cookies.
- The feature catalog rows and the two parity entries carry the same result.
- The console, network and cookie probe scenarios now require a PASS reason that opens with the outcome, so a report row never reads as a working capture.

&nbsp;

## Upgrade

Do not rely on `page.on('console' | 'request' | 'response')` or `page.context()` on this Aside version.
