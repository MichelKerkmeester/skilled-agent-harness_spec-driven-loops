# v1.1.3.0, All Three Mode Ids Route Together

The follow-up deep review of the hub found four defects that held when checked against source. A prompt naming `mcp-chrome-devtools`, `mcp-aside-devtools` and `mcp-bladebro` routed to only the first two. The hub capability matrix still offered Aside `page.on(...)` events, which throw on Aside 1.26.626.1517. The Aside capture example accepted `./tmp/../..`. The Aside installer piped a downloaded script straight into bash.

&nbsp;

## What's New at a Glance

- `mcp-bladebro` joins Bladebro's aliases, so the three mode ids score alike and route as one ordered bundle in tie-break order.
  - The canary corpus gains that prompt as `three-mode-ids-ordered-bundle`, and the case fails without the alias.
  - `ROUTER.md` now carries every phrase `hub-router.json` does, including `chrome live manual` and `core web vitals`, which it had dropped.
- The hub matrix lists Aside console and network capture as not offered, matching the Aside packet.
- `repl-evidence-capture.sh` rejects a session dir that contains `..`, so a path cannot climb out of `./tmp` after the prefix check.
- The Aside installer downloads the official script to a temporary file, checks its sha256 against a pinned digest and runs it only on a match.
  - A changed vendor script is refused. Read the new script before bumping the digest.
  - The pin covers the install script only. The archive that script downloads is not verified.
- The hub no longer lists `mcp-code-mode` among its keywords, so "fix the code in the parser" stops reaching the hub at the advisor stage.
- `hub-router.json`, `mode-registry.json`, `description.json` and `SKILL.md` read 1.1.3.0. Each Markdown doc keeps its own version line.
- The generated advisor intent signals gain `chrome live manual` and `core web vitals`, the two phrases `ROUTER.md` had dropped.

&nbsp;

## Correction to v1.1.2.0

The v1.1.2.0 note said eight out-of-domain prompts still reached 0.82 or more at the advisor stage. That was true before skill advisor 2.0.2.0, which shipped in the same change. In that release's final replay, none of the 18 out-of-domain prompts reached the hub at 0.8. Its other count, 11 earlier out-of-domain prompts of which 8 routed before, is correct.

&nbsp;

## How It Was Checked

The follow-up replay under `benchmark/reports/compiled-routing/2026-11-24--two-stage-replay--compiled--follow-up/` passes 51 of 52 rows, including two new out-of-domain prompts and the three-mode bundle. MBU-PB-04 still gets no advisor recommendation, the known stage-one gap.

&nbsp;

## Upgrade

No migration required. The hub's activation manifest was re-minted, so compiled routing keeps serving. A vendor update to the Aside installer now needs a digest bump in `scripts/install.sh`.
