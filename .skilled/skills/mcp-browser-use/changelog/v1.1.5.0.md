# v1.1.5.0, The Front Door Takes the Task on Stdin and the Review Advisories Are Closed

v1.1.4.0 moved `SKILL.md` to a stdin heredoc and left the `ROUTER.md` callout on `--prompt "<task>"`, on the belief that a fleet-wide test pinned that wording. The test checks only synthetic fixtures, and every hub now uses stdin. This release also closes the P2 advisories of the generation-4 review that held against source.

&nbsp;

## What's New at a Glance

- The `ROUTER.md` machine-router callout passes the task on stdin through a quoted heredoc, the same as every other hub.
- The Aside install wrapper refuses `ASIDE_CLI_BASE_URL`. It verifies the vendor installer script but not the archive that script downloads, so it no longer lets the environment change where that archive comes from.
- The Aside capture example refuses only a real `..` path segment. A folder name such as `./tmp/a..b` passes.
- The bdg Node fix downloads the nvm installer, asks you to read it, then runs it, instead of piping it into bash.
- `ROUTER.md` now says Core Web Vitals phrasing reaches the advisor, where sk-code still ranks first. It also says this hub's front door never returns `reject` from the CLI, and it calls its machine map the stage-two projection, next to `hub-router.json` for stage one.
- The README release table lists every release, and its description of an entry matches what the entries hold.
- The hub's compiled policy derives its `selectionKinds` from the bundle kinds it emits.

&nbsp;

## How It Was Checked

The two-stage replay under `benchmark/reports/compiled-routing/2026-11-24--two-stage-replay--compiled--p2-triage/` passes 55 of 56 rows, each the same as in v1.1.4.0. MBU-PB-04 still gets no advisor recommendation. The wrapper was run with `ASIDE_CLI_BASE_URL` set and exited before any download. The capture example was run against a stub `aside` with five folder names.

&nbsp;

## Upgrade

No migration required. The activation manifest was re-minted. Unset `ASIDE_CLI_BASE_URL` before running `scripts/install.sh`.
