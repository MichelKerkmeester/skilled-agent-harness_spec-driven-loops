# v1.1.5.0, The Front Door Takes the Task on Stdin and the Review Advisories Are Closed

v1.1.4.0 moved `SKILL.md` to a stdin heredoc. The `ROUTER.md` callout kept `--prompt "<task>"`. A fleet test was thought to pin that line. It checks only synthetic fixtures. Every hub now uses stdin. This release also closes the generation-4 review's P2 advisories that held.

&nbsp;

## What's New at a Glance

- The `ROUTER.md` callout passes the task on stdin. It uses a quoted heredoc, like every other hub.
- The Aside install wrapper refuses `ASIDE_CLI_BASE_URL`. It verifies the vendor script, not the archive that script fetches. So the environment can no longer move that download.
- The Aside capture example refuses only a real `..` path segment. A folder such as `./tmp/a..b` passes.
- The bdg Node fix downloads the nvm installer first. You read it, then run it. Nothing is piped into bash.
- `ROUTER.md` says Core Web Vitals phrasing reaches the advisor. There sk-code still ranks first.
- `ROUTER.md` says the CLI front door never returns `reject`.
- `ROUTER.md` calls its map the stage-two projection. `hub-router.json` holds stage one.
- The README release table lists every release. Its entry description matches the entries.
- The compiled policy derives `selectionKinds` from the bundle kinds it emits.

&nbsp;

## How It Was Checked
