# v1.1.1.0, a 403 Forbidden Prompt Routes Again

The hub's compiled router rejected any prompt whose text held the word "forbidden". So "debug the 403 Forbidden network requests in chrome devtools" reached no mode.

&nbsp;

## What's New at a Glance

- A reject now comes only from the caller's `forbidden` constraint, never from the prompt text.
  - The fix is in the authored router bundle and its promoted copy.
  - A canary case pins the 403 Forbidden prompt to `mcp-chrome-devtools`.
- The post-review hub routing run passed 7 of 7.
  - It supersedes the earlier run, which failed one prompt.
  - The report is `benchmark/reports/2026-11-21--manual-testing-playbook--hub-routing--post-review/`.
- The global changelog tree now reaches this hub.
  - `.skilled/changelog/mcp-browser-use/` links `parent` and all three modes.
  - The two links left under `mcp-tooling/` pointed at the old paths, and they are gone.

&nbsp;

## Upgrade

No migration required.
