# v1.1.2.0, Ordinary Words Stop Routing to a Browser Mode

Several hub aliases were ordinary English words. "Set that aside and fix the failing unit test" and "write a lighthouse keeper short story" both reached a browser mode. So did "rb status of the ruby build", which went to Bladebro.

&nbsp;

## What's New at a Glance

- Bare `aside`, `lighthouse`, `har file`, `export a har`, `performance trace`, `rb status` and `rb attach` are gone from every vocabulary copy.
  - Verb and page forms replace them, such as `use aside`, `run lighthouse`, `export a har of`, `record a performance trace` and `bladebro rb`.
  - All five copies changed together: `hub-router.json`, `mode-registry.json`, the `ROUTER.md` maps, `graph-metadata.json` and `description.json`.
- Tie-break routing takes paraphrases, not only the recorded phrasings.
  - "fill out the form in my signed-in account" now reaches Aside. It returned no skill before.
  - "browse this site without getting flagged as a bot" now reaches Bladebro. It also returned no skill before.
  - The two recorded tie-break rows moved further from the 0.8 floor, to 0.8482 and 0.8525.
- The hub contract now matches the router on browser attachment.
  - A request that names the user's own Chrome goes to Chrome DevTools, whose live instance attaches to the open Chrome.
  - A caller-owned or already-open browser that names no Chrome goes to Bladebro.
  - A request that names both returns an ordered bundle, Chrome DevTools first.
- The two-stage replay under `benchmark/reports/compiled-routing/2026-11-24--two-stage-replay--compiled/` records the before and after numbers.
  - The front door now defers on all 11 out-of-domain prompts from the earlier runs. It routed 8 of them before.
  - Eight out-of-domain prompts still reach 0.82 or more at the advisor stage, through scorer lanes the hub's vocabulary does not control. The report names each one.

&nbsp;

## Upgrade

No migration required. The hub's activation manifest was re-minted, so compiled routing keeps serving.
