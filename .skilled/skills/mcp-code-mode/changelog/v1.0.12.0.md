# v1.0.12.0, Standards alignment

v1.0.12.0 aligns the skill code and docs with sk-create-skill and sk-code-skilled, corrects stale README claims and fixes three bugs in the helper scripts. The MCP server keeps its tools, flags, schemas and responses.

&nbsp;

## What's New at a Glance

- The server source `mcp-server/index.ts` gains the standard module header, numbered sections, named constants for its timeouts and defaults, one shared transport close helper and one response helper pair. A side-by-side MCP session against the old and new builds returned the same tools, schemas, prompt and responses.
- `mcp-server/scripts/check-node.cjs` gains the module header and names its required module ABI.
- `scripts/install.sh` documents its exit codes, uses its package constant instead of repeating the name and splits a masked assignment. `scripts/update.sh` documents its exit codes. `scripts/doctor.sh` now states what exits 20 and 26 actually mean.
- `scripts/validate_config.py` names its known call template types, HTTP methods and report width.
- The `SKILL.md` keyword comment now carries phrases a user would type. Stale pointers to `skill_advisor.py`, to a flat `mcp-chrome-devtools` skill and to Spec Kit as a native MCP tool are corrected.
- The README no longer calls the skill advisor a native MCP server, shows the real `{ success, result, logs }` shape, lists `deregister_manual` and describes what `doctor.sh` checks. `scripts/README.md` lists all five scripts.
- `graph-metadata.json` drops the `mcp-server/README.md` source doc, a symlink to `README.md` that is already listed and that a copy without symlinks reports as dead.

&nbsp;

## Fixed

- **`doctor.sh` no longer reports a false `@utcp/code-mode` failure.** It ran the import checks under the first `node` on PATH, while the server runs under the Node 24 interpreter the launcher picks from the manifest. It now asks the same resolver the launcher uses and falls back to PATH `node` with a note only when the resolver finds nothing.
- **`validate_config.py` prints missing environment variables in a stable order.** The list came from a set and changed order between runs. It is now sorted, so two runs give the same report.
- **`_utils.sh` keeps quotes and backslashes in values as data.** The JSON helpers pasted shell values into embedded Python source, so a path or value with a quote broke the script or ran as code. Values now reach Python as arguments. The bare `except:` clauses now catch only read and parse errors, and `backup_file` no longer masks the status of its `date` call. The `mcp-chrome-devtools` copy carries the same change.
- **The JSON helpers work without their optional arguments.** `json_add_mcp_entry` and `json_add_utcp_entry` defaulted the args and env values to `'[]'` and `'{}'` with the quotes kept, which neither jq nor Python parses, so a call that left them out failed. The defaults are now plain `[]` and `{}`.

&nbsp;

## Upgrade

No migration required. Run `npm run build` in `mcp-server/` under Node 24 to pick up the refactored source.
