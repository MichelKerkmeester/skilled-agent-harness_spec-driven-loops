# v1.0.12.0, Standards alignment

v1.0.12.0 aligns the skill code and docs with sk-create-skill and sk-code-skilled. It corrects stale README claims. It fixes three bugs in the helper scripts. The MCP server keeps its tools, flags, schemas and responses.

&nbsp;

## What's New at a Glance

- The server source `mcp-server/index.ts` gains standard structure.
  - It gains the standard module header.
  - It gains numbered sections.
  - It gains named constants for its timeouts and defaults.
  - It gains one shared transport close helper and one response helper pair.
  - A side-by-side MCP session against the old and new builds returned the same tools, schemas, prompt and responses.
- `mcp-server/scripts/check-node.cjs` gains the module header.
  - It names its required module ABI.
- The shell scripts gain exit code documentation and small code changes.
  - `scripts/install.sh` documents its exit codes.
  - `scripts/install.sh` uses its package constant instead of repeating the name.
  - `scripts/install.sh` splits a masked assignment.
  - `scripts/update.sh` documents its exit codes.
  - `scripts/doctor.sh` now states what exits 20 and 26 actually mean.
- `scripts/validate_config.py` names its known call template types, HTTP methods and report width.
- The `SKILL.md` keyword comment changes and stale pointers are corrected.
  - The keyword comment now carries phrases a user would type.
  - They pointed to `skill_advisor.py`, to a flat `mcp-chrome-devtools` skill and to Spec Kit as a native MCP tool.
- The README and `scripts/README.md` are corrected.
  - The README no longer calls the skill advisor a native MCP server.
  - The README shows the real `{ success, result, logs }` shape.
  - The README lists `deregister_manual`.
  - The README describes what `doctor.sh` checks.
  - `scripts/README.md` lists all five scripts.
- `graph-metadata.json` drops the `mcp-server/README.md` source doc.
  - That doc is a symlink to `README.md`.
  - `README.md` is already listed.
  - A copy without symlinks reports the symlink as dead.

&nbsp;

## Fixed

- `doctor.sh` no longer reports a false `@utcp/code-mode` failure.
  - It ran the import checks under the first `node` on PATH.
  - The server runs under the Node 24 interpreter the launcher picks from the manifest.
  - It now asks the same resolver the launcher uses.
  - It falls back to PATH `node` with a note only when the resolver finds nothing.
- `validate_config.py` prints missing environment variables in a stable order.
  - The list came from a set.
  - The list changed order between runs.
  - The list is now sorted.
  - So two runs give the same report.
- `_utils.sh` keeps quotes and backslashes in values as data.
  - The JSON helpers pasted shell values into embedded Python source.
  - So a path or value with a quote broke the script or ran as code.
  - Values now reach Python as arguments.
  - The bare `except:` clauses now catch only read and parse errors.
  - `backup_file` no longer masks the status of its `date` call.
  - The `mcp-chrome-devtools` copy carries the same change.
- The JSON helpers work without their optional arguments.
  - `json_add_mcp_entry` and `json_add_utcp_entry` defaulted the args and env values to `'[]'` and `'{}'`.
  - The quotes were kept.
  - Neither jq nor Python parses that.
  - So a call that left them out failed.
  - The defaults are now plain `[]` and `{}`.

&nbsp;

## Upgrade

No migration required. Run `npm run build` in `mcp-server/` under Node 24 to pick up the refactored source.
