# v1.0.13.0, The Routing Prose Is Short and the Router Moved to the End

A reader now reaches the naming pattern and the workflows sooner. `SMART ROUTING` is five lines of plain prose that name what selects the skill and the reference page that loads first, and the loading levels, the typed leaf projection and the pseudocode sit unchanged in a final `## 10. MACHINE ROUTER` section. Nothing about which resource loads for which request changed.

> Spec folder: `specs/sk-doc/072-skill-routing-and-clarity/009-standalone-skills` (Level 2)

&nbsp;

## What's New at a Glance

- **The routing section is prose.** Five lines say which request selects this skill, that a native file or shell request belongs to the runtime's own tools, and that `UNKNOWN_FALLBACK` reports a request it cannot place.
- **The router is at the end.** The loading levels table, the typed leaf projection, the four resilience patterns and the smart-router pseudocode moved byte for byte into `## 10. MACHINE ROUTER`, the last section of the file, under the headings they already carried.
- **The naming guide comes first.** The manual namespace contract, the environment variable prefixing and the basic workflow now sit one screen below the routing summary instead of two.

&nbsp;

## Upgrade

No action is needed. The skill routes and loads exactly the resources it did before, and the leaf manifest still checks clean.
