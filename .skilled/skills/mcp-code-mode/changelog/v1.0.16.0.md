# v1.0.16.0, Docs Read in Order and Render as Written

The skill's `SKILL.md`, `ROUTER.md`, `README.md`, five references and two assets were read file by file for readability, layout and structure. No routing behavior or contract changed.

> Spec folder: `specs/sk-doc/066-skill-readability-refinement/004-mcp-code-mode` (Level 1)

&nbsp;

## What's New at a Glance

- **Each overview opens with its purpose and when to use it.** `README.md` moves When to Use up beside Purpose, and the references and assets gain the Purpose and When to Use subsections their template asks for.
- **Run-on lines now render as lists.** Bold field labels in the config template, the before-and-after figures in the architecture reference, the discovery tools in `README.md` and the routing triggers in `ROUTER.md` each sit on their own line.
- **The tool catalog matches `.utcp_config.json`.** It listed ten manuals, and the config holds thirteen, so `magnific`, `notion`, `obsidian` and `webflow` are added.
- **The manifest check command runs.** The tool catalog named a generator under this skill's own `scripts/`, which does not exist, and now names the shared one in `sk-create-skill`.
- **The env template numbers every section.** Its variable naming section is now section 4, the sections after it move down one, and the Notion integrations link is a named link.
