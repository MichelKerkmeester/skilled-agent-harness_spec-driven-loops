# v1.1.4.0, Copied paths and a clean install

v1.1.4.0 points the READMEs at the folders they live in, so a command copied out of one runs where it is pasted. The backend's test dependency moves to vitest `^4.1.12`. Its lockfile picks up the security fixes the audit reported.

> Spec folder: `specs/sk-doc/070-repo-doc-debt/005-reference-and-coverage-fixes` (Level 2)

&nbsp;

## What's New at a Glance

- **Copied commands run unchanged.** The main README and the backend, styles and styles database READMEs print the real hub path `.skilled/skills/sk-design/sk-design-md-generator/` instead of the old top-level one.
- **The test suite runs on the current vitest.** `vitest` moves from `^4.1.11` to `^4.1.12` in `backend/`, so `npx vitest run` uses the release the rest of the repository builds against.
- **A fresh install pulls no flagged packages.** The backend lockfile carries the newer copies of the libraries the audit reported, so `npm install` no longer resolves the older ones.
- **Two reference READMEs read in the same order.** The design-knowledge and examples READMEs open with an overview, then number their sections after it.
- **The styles folder names its tests.** Its README points at `tests/`, which holds the engine tests, the database tests and the parity oracle. The tests README drops a pointer to a manual playbook that is no longer there.

&nbsp;

## Upgrade

No migration required. Run `npm install` in `backend/` to pick up the newer lockfile.
