The Style Reference the stock palette was derived from now lives beside the forms it produced, instead of being read out of a sibling library of roughly twelve hundred regenerable captures. This prevents upstream regeneration from changing `--default` output without a diff or leaving the palette based on a capture that no longer exists.

## What's New at a Glance

- **The cursor capture is stored beside the forms it produced.** `assets/style-reference/cursor/` holds the files copied verbatim: `DESIGN.md`, `source.md`, `css-variables.css`, `tailwind-v4.css`, `design-tokens.json` and `cursor-canonical.json`. Its `origin.md` records where the copy came from and pins every file by hash.
- **`--default` reads the local copy.** `apply-design-md.cjs` no longer reaches into the sibling skill. Themed output is byte-identical to before apart from the provenance line, which now records the local path.
- **Overriding is unchanged.** Pass any `DESIGN.md` path, including one `sk-design-md-generator` has just produced. The stock reference is a default, not a lock.
- **The copy is severed, not linked.** Re-copying is now a deliberate act with a diff. A genuine upstream improvement has to be pulled in on purpose.
- **The new directory is inert to every walker.** The corpus check, gallery builder and screenshot renderer filter to `.html`, leaving the directory's Markdown, CSS and JSON invisible to them.
- **`design-tokens.json` keeps its name.** The applicator reads `darkMode` from a sidecar named exactly `tokens.json` beside a `DESIGN.md`. The bundle file has a different schema under a similar name, so renaming it would make the script consult a file that cannot answer and say nothing.
- **The palette source still names the four values that depart from the reference and why each was moved.** The four values and their reasons are unchanged.

## Upgrade

No migration required.
