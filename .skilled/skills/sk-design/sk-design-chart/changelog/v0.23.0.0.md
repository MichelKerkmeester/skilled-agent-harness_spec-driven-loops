# v0.23.0.0, Each Style Reference Owns Its Colour

v0.18.0.0 derived the stock palette from evilcharts. It kept the values apart from the Style Reference that supplied them. It named the source only in prose. v0.23.0.0 moves the palette into that reference. It turns the relationship into a rule.

## What's New at a Glance

- **Every Style Reference owns a palette.** Each reference must carry `palettes.json` with a derivation. The corpus check rejects a reference with no palette. It also rejects a palette without a derivation.
- **The evilcharts palette sits with its source.** `assets/color/` no longer exists. `palettes.json` and the three palette proof sheets moved into `assets/style-reference/evilcharts/`. They sit beside the `DESIGN.md` they were measured from. Their screenshots followed to `screenshots/style-reference/evilcharts/`. The renderer mirrors that folder from the assets tree without being told.
- **Palette paths follow the default reference.** `check-corpus.cjs` and `apply-design-md.cjs` each name a default reference. Each builds the path from it. The stock values belong to one reference. They are not a file floating free of one.
- **Proof sheets are recognized by filename.** The card anatomy and type scale rules now match `palette-sheet-*.html`. They match it wherever a reference keeps it. Sheets that prove colour rather than draw a chart are exempt. Both rules matched the old directory. That would have meant editing them each time a reference was added.
- **Palette values and encodings did not change.** Templates read the same values. `neutral`, `ordered` and `categorical` still describe what colour encodes. A second reference brings its own three systems. The encodings do not change.

## Upgrade

No migration required.
