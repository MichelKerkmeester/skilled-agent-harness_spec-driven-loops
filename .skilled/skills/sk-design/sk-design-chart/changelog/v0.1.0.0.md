The first release of `sk-design-chart`, a workflow packet in the `sk-doc` parent hub, gives a data-chart request one HTML file that opens on a double click. It needs no install step, no build step and no remote dependency.

## Why This Release

The release adds twenty chart forms, three colour systems and six finished deliveries, indexed by a catalog a check resolves in both directions.

## What's New at a Glance

- **Twenty chart forms cover six question families.** They cover comparison, composition, time, distribution, relationship and matrix questions.
- **Three colour systems distinguish importance, magnitude and identity.** `neutral` ranks by importance, `ordered` encodes magnitude and `categorical` encodes identity.
- **The palette and data follow a template-first contract.** It has thirteen enforced rules.
- **Six finished deliveries ship with the forms.** Each is shaped exactly as a recipient receives it.
- **Thirty-three keywords mark the chart and diagram boundary.** Data-qualified terms catch chart requests while bare type names stay with `sk-design-diagram`.
- **Chart requests pass through both `sk-doc` routing stages.** The advisor selects the hub, then its router selects `sk-design-chart`. The hub carries sixteen modes, including this one.
- **Report mode and its directory were cut.** There are no gallery pages.
- **The catalog check follows entries in both directions.** It checks the catalog against the chart files.
- **A dependency-free corpus check enforces every contract rule.** It calculates contrast from the palette file rather than from a copy.
- **A second reader is the only control for headline accuracy.** A chart can render perfectly while its headline misstates the data beneath it.
- **A manual testing playbook covers chart delivery.** It organizes the scenarios by category.
- **The packet's charts, palettes and scripts are authored here.** Nothing is copied from an outside chart library.

## Charts and Colour

#### Forms Draw Inline Vector Marks

Nothing animates. Nothing fetches. No file carries a colour value outside its palette block.

&nbsp;

#### Contrast Follows Colour's Role

Every value lives in `assets/color/palettes.json` and nowhere else. Values are derived by mixing a base hue toward the surface or the ink until they land on a target contrast ratio.

The gate a value has to clear is selected by what it encodes. A flat pairwise gate is arithmetically unsatisfiable past two values, while a flat ramp gate deletes the light end of every scale. Three palette sheets render the whole set in a browser and recompute the contrast arithmetic from what the browser resolved.

&nbsp;

#### Palette and Data Have Markers

The palette arrives inline as a sentinel-marked block of CSS custom properties. The data arrives in a second sentinel-marked block at the top of the script. Everything below the data renders. A delivered file stays editable by hand end to end.

&nbsp;

#### Finished Examples Cover Every Family

There is one worked delivery per question family. Each differs from its template only in the headline, subtitle, source line and data. The drawing code is the same code, which is the point of having a form.

## Routing and Scope

#### Keywords Mark the Chart Boundary

`sk-design-diagram` already claims bar, line, scatter, radar, Gantt and org-chart types by name. The split is what the artifact carries: values a reader compares, against a structure a reader follows.

Fifteen keywords are form names the neighbour has no file for, such as `treemap`, `heatmap`, `box plot` and `histogram`. Fifteen are explicit chart-authoring phrasings. Three are data-qualified crossovers: `bar chart of`, `line chart of` and `scatter plot of`.

The crossovers catch a request for a data chart while leaving a bare type name with the neighbour. A bare `chart` token was never a candidate because `flowchart`, `org chart`, `gantt chart` and `radar chart` all contain it.

&nbsp;

#### Routing Registers Both Stages

The `sk-design-chart` mode has a registry entry, vocabulary in both stage-one metadata files, router intents and a resource map. It also has a mode-table row, regenerated leaf-manifest entries and a single-route canary case the coverage guard counts.

&nbsp;

#### Reports Would Be a Second Product

A report has its own layouts, selection rules and index. Chart capability does not depend on report mode. Keeping report mode meant authoring twelve page layouts from nothing for a request nobody had made.

One form is one file, and a gallery ships every other form's demo data alongside the one chart somebody asked for.

## Reliable Chart Delivery

#### Catalog Rows Match Chart Files

Every catalog row reaches a file that identifies itself with the same id. Every form on disk carries a catalog row. An index that names a chart it cannot reach is worse than no index, which is why one direction was never enough.

&nbsp;

#### Checks Find Blank Charts, Not Headlines

`scripts/check-corpus.cjs` never asserts that a document contains a particular sentence. With `--render`, it opens each file in a headless browser, the only check that catches a chart drawing nothing.

The render check is opt-in, so a machine with no browser cannot produce a silent skip that looks like a pass. Sustained headless Chrome launches fail intermittently on some machines, which the check reports as a browser that returned no document. The playbook's discriminator is that a different file each run that passes when opened by hand points to the browser, while the same file every run points to a chart drawing nothing.

No check reads a headline against its own numbers.

&nbsp;

#### The Playbook Separates Scenarios

The manual testing playbook has eight operator scenarios across three category folders. Three cover what only a reader can see, three cover the corpus and two cover what reaches a user. Each scenario is admitted on one test that fails for a reason no other scenario catches.

&nbsp;

#### The Packet Owns Its Materials

A licensing rule is in the packet itself. Nothing is copied in from an outside chart library because this repository is MIT and public and cannot hand onward a grant it was never given.

&nbsp;

#### The Version Story Starts at Adoption

The packet was built empty first, then filled. A packet that gains content and structure at once cannot tell you which of the two broke a gate, so the packaging gate ran against the shape alone before any content depended on it.

The colour system, the template contract and the corpus check landed next. The twenty forms were authored on top of them. The version story starts at adoption. This entry describes the finished package rather than the first phase of it.
