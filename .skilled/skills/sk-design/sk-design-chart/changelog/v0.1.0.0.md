## Charts and Colour

Twenty chart forms cover six question families. They cover comparison, composition, time, distribution, relationship and matrix questions. Three colour systems distinguish importance, magnitude and identity.

#### Forms Draw Inline Vector Marks <a id="c-forms-draw-inline-vector-marks"></a>

- Nothing animates.
- Nothing fetches.
- No file carries a colour value outside its palette block.
- Twenty chart forms cover six question families.
- They cover comparison, composition, time, distribution, relationship and matrix questions.

#### Contrast Follows Colour's Role <a id="c-contrast-follows-colours-role"></a>

- Every value lives in `assets/color/palettes.json` and nowhere else.
- Values are derived by mixing a base hue toward the surface or the ink.
- The mixing continues until the value lands on a target contrast ratio.
- The gate a value has to clear is selected by what it encodes.
- Three colour systems distinguish importance, magnitude and identity.
- `neutral` ranks by importance.
- `ordered` encodes magnitude.
- `categorical` encodes identity.

<details>
<summary><b>Contrast gates and palette sheets</b></summary>

- A flat pairwise gate is arithmetically unsatisfiable past two values.
- A flat ramp gate deletes the light end of every scale.
- Three palette sheets render the whole set in a browser.
- They recompute the contrast arithmetic from what the browser resolved.

</details>

#### Palette and Data Have Markers <a id="c-palette-and-data-have-markers"></a>

- The palette arrives inline as a sentinel-marked block of CSS custom properties.
- The data arrives in a second sentinel-marked block at the top of the script.
- Everything below the data renders.
- A delivered file stays editable by hand end to end.
- The palette and data follow a template-first contract.
- It has thirteen enforced rules.

#### Finished Examples Cover Every Family <a id="c-finished-examples-cover-every-family"></a>

- There is one worked delivery per question family.
- Each differs from its template only in the headline, subtitle, source line and data.
- The drawing code is the same code, which is the point of having a form.
- Six finished deliveries ship with the forms.
- Each is shaped exactly as a recipient receives it.

## Routing and Scope

Chart requests pass through both `sk-doc` routing stages. The advisor selects the hub, then its router selects `sk-design-chart`. The hub carries sixteen modes, including this one.

#### Keywords Mark the Chart Boundary <a id="c-keywords-mark-the-chart-boundary"></a>

- `sk-design-diagram` already claims bar, line, scatter, radar, Gantt and org-chart types by name.
- The split is what the artifact carries.
- It is values a reader compares, against a structure a reader follows.
- The crossovers catch a request for a data chart.
- They leave a bare type name with the neighbour.

<details>
<summary><b>Keyword groups</b></summary>

- Fifteen keywords are form names the neighbour has no file for.
- They include `treemap`, `heatmap`, `box plot` and `histogram`.
- Fifteen are explicit chart-authoring phrasings.
- Three are data-qualified crossovers: `bar chart of`, `line chart of` and `scatter plot of`.

</details>

<details>
<summary><b>Why a bare chart token was excluded</b></summary>

- A bare `chart` token was never a candidate.
- That is because `flowchart`, `org chart`, `gantt chart` and `radar chart` all contain it.

</details>

#### Routing Registers Both Stages <a id="c-routing-registers-both-stages"></a>

- The `sk-design-chart` mode has a registry entry.
- It has vocabulary in both stage-one metadata files, router intents and a resource map.
- It also has a mode-table row and regenerated leaf-manifest entries.
- It has a single-route canary case the coverage guard counts.

#### Reports Would Be a Second Product <a id="c-reports-would-be-a-second-product"></a>

- A report has its own layouts, selection rules and index.
- Chart capability does not depend on report mode.
- Keeping report mode meant authoring twelve page layouts from nothing for a request nobody had made.
- One form is one file.
- A gallery ships every other form's demo data alongside the one chart somebody asked for.
- There are no gallery pages.

## How It Was Checked

Checks keep catalog rows aligned with chart files. A render check finds blank charts. A manual playbook separates scenarios by category.

#### Catalog Rows Match Chart Files <a id="c-catalog-rows-match-chart-files"></a>

- Every catalog row reaches a file that identifies itself with the same id.
- Every form on disk carries a catalog row.
- An index that names a chart it cannot reach is worse than no index.
- That is why one direction was never enough.
- It checks the catalog against the chart files.

#### Checks Find Blank Charts, Not Headlines <a id="c-checks-find-blank-charts-not-headlines"></a>

- `scripts/check-corpus.cjs` never asserts that a document contains a particular sentence.
- With `--render`, it opens each file in a headless browser.
- That is the only check that catches a chart drawing nothing.
- The render check is opt-in.
- So a machine with no browser cannot produce a silent skip that looks like a pass.
- A second reader is the only control for headline accuracy.
- A chart can render perfectly while its headline misstates the data beneath it.
- No check reads a headline against its own numbers.

<details>
<summary><b>The corpus check</b></summary>

- A dependency-free corpus check enforces every contract rule.
- It calculates contrast from the palette file rather than from a copy.

</details>

<details>
<summary><b>Browser launch failures</b></summary>

- Sustained headless Chrome launches fail intermittently on some machines.
- The check reports that as a browser that returned no document.
- The playbook has a discriminator.
- A different file each run that passes when opened by hand points to the browser.
- The same file every run points to a chart drawing nothing.

</details>

#### The Playbook Separates Scenarios <a id="c-the-playbook-separates-scenarios"></a>

- The manual testing playbook has eight operator scenarios across three category folders.
- Three cover what only a reader can see.
- Three cover the corpus and two cover what reaches a user.
- Each scenario is admitted on one test that fails for a reason no other scenario catches.
- It organizes the scenarios by category.

#### The Packet Owns Its Materials <a id="c-the-packet-owns-its-materials"></a>

- A licensing rule is in the packet itself.
- The packet's charts, palettes and scripts are authored here.
- Nothing is copied in from an outside chart library.
- Nothing is copied from an outside chart library.
- That is because this repository is MIT and public.
- It cannot hand onward a grant it was never given.

#### The Version Story Starts at Adoption <a id="c-the-version-story-starts-at-adoption"></a>

- A packet can gain content and structure at once.
- Then it cannot tell you which of the two broke a gate.
- The version story starts at adoption.
- This entry describes the finished package rather than the first phase of it.

<details>
<summary><b>Build order</b></summary>

- The packet was built empty first, then filled.
- So the packaging gate ran against the shape alone.
- That ran before any content depended on it.
- The colour system, the template contract and the corpus check landed next.
- The twenty forms were authored on top of them.

</details>
