The corpus check is the packet's contract and had no coverage of its own when two reviews found twenty-one assertions inside it that passed for a reason other than the one their message gave. Each was fixed by hand and re-proved by hand. That is now a suite, and it runs in CI.

## What's New at a Glance

- **The corpus mutation suite gives each review fix a case.** `scripts/tests/corpus-mutations.test.cjs` changes exactly one thing per case and expects one named family to report one specific issue.
- **The corpus workflow blocks changes under the packet.** `check-corpus.cjs` and the suite run on any packet change. The workflow requires the affirmative `RESULT: PASSED` marker rather than trusting the exit code because a run that refuses to start also exits zero.
- **The suite refuses a case that would prove nothing.** It aborts when an anchor is missing. It also aborts when the starting version already fails the target family or when another family causes the failure. It caught two nonexistent anchors and one mutation that removed a comment instead of the declaration the rule reads.
- **The reference-drawing assertion now counts what the loop builds against what it places.** Before, it proved only that something was appended, so a rule could be orphaned while its label was still appended.
- **A single-key case covers the helper's own declaration.** It targets the only form with a single key site, where counting that declaration as a call is the difference between firing and staying silent.
- **The browser-dependent case says it is skipping rather than returning quietly.** A silent skip and a pass read the same in a log.
