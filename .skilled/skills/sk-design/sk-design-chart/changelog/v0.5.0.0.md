The chart corpus can now apply a local v3 `DESIGN.md` Style Reference to delivery copies while
keeping the stock palette and templates byte-stable. The new path derives both theme roles,
proves the same contrast gates, and leaves a hash-bearing provenance trail for the checker.

## What Changed

#### New Features

- **Local DESIGN.md application.** `scripts/apply-design-md.cjs` parses the documented colour, typography and radius tables, derives the chart role vocabulary and writes deterministic copies with `--forms` or `--all`.
- **Provenance-gated delivery system.** The checker accepts `design-md` palette blocks only when both themes carry a well-formed SHA-256 provenance comment and clear the inline text, mark, ramp, separation and emphasis gates.
- **Outside-delivery checks.** `check-corpus.cjs --extra <dir>` runs the file-level families over themed HTML outside the package without adding it to the catalog, gallery or stock geometry set.
- **Shared gate arithmetic.** `scripts/color-gates.cjs` is required by the applicator and checker so their luminance, contrast and rounding cannot drift apart.

#### Fixes

- **Fail-closed derivation.** A missing v3 heading, a URL input, a palette with too few clearing chromatic values or any failed gate stops before the output directory is written and names the nearest clearing table colour.
- **Stock equality remains strict.** The three stock systems still use the original source-equality path; a one-byte stock palette edit remains a `palette-block` failure.

#### Notes

- The stripe example now has a generated `grouped-bars.html` delivery under `assets/examples/` with concrete data and a real headline.
- The static corpus and focused Node tests pass. The render pass remains dependent on Chrome being able to launch in the sandbox; when that launch aborts, no captures are changed.
- Extraction remains in `sk-design-md-generator`; this packet reads local references and never fetches.
