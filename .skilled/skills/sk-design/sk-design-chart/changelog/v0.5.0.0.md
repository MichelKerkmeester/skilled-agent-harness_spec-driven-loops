The chart corpus can now apply a local v3 `DESIGN.md` Style Reference to delivery copies while keeping the stock palette and templates byte-stable. The new path derives both theme roles, applies the same contrast gates and leaves a hash-bearing provenance trail for the checker.

## What's New at a Glance

- **`scripts/apply-design-md.cjs` derives themes from local references.** It parses the documented colour, typography and radius tables to derive chart role vocabulary and both theme roles, then writes deterministic copies with `--forms` or `--all`. A missing v3 heading, URL input, palette with too few clearing chromatic values or any failed gate stops before the output directory is written and names the nearest clearing table colour.
- **The checker gates `design-md` palettes on provenance and contrast.** Both themes need a well-formed SHA-256 provenance comment and must clear the inline text, mark, ramp, separation and emphasis gates.
- **The applicator and checker share gate arithmetic.** `scripts/color-gates.cjs` is required by both so luminance, contrast and rounding cannot drift apart.
- **`check-corpus.cjs --extra <dir>` checks themed HTML outside the package.** It runs the file-level families without adding those files to the catalog, gallery or stock geometry set.
- **The three stock systems still use the original source-equality path.** A one-byte stock palette edit remains a `palette-block` failure.
- **The stripe example adds a generated delivery.** `grouped-bars.html` under `assets/examples/` has concrete data and a real headline.
- **Extraction remains in `sk-design-md-generator`.** This packet reads local references and never fetches.
- **The render pass remains dependent on Chrome being able to launch in the sandbox.** When that launch aborts, no captures are changed.

## Upgrade

No migration required.
