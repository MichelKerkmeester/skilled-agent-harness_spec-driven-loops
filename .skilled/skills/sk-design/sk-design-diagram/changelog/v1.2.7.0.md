# v1.2.7.0, The Routing Prose Is Short and the Router Moved to the End

`sk-design-diagram` now reaches its drawing instructions first. SMART ROUTING is seven lines of plain prose. It used to be 81 lines of shell detection, resource tables and routing rules. That material sits unchanged in a final `## 7. MACHINE ROUTER` section.

&nbsp;

## What's New at a Glance

- The routing section is prose.
  - Seven lines say what selects the mode, what it loads first and where the router is.
  - A reader meets the style-guide gate and the draw workflow without scrolling past four routing trees.
- The router is at the end.
  - The format-resolution rule, the request-shape signals and the phase map moved byte for byte.
  - So did the resource domains, the loading-level table and the router pseudocode.
  - The moved material sits in `## 7. MACHINE ROUTER`, the last H2 of the file.
- Nothing routes differently.
  - The same type reference, pattern file and export procedure load as before.
  - `html-svg` stays the default format.
- The playbook anchor follows the move.
  - The supplemental alias check in the hub-registration playbook now names the `MACHINE ROUTER` section.
  - That is because the intent weights it reads moved there.

&nbsp;

## Upgrade

No action is needed. The router reads the same paths. Every diagram type, skin and export behaves as it did.
