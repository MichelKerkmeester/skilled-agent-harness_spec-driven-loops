# v1.0.4.0, The Machine Router Moves to ROUTER.md

The machine router now lives in sibling `ROUTER.md`. `SKILL.md` keeps SMART ROUTING as short prose that ends with a link to it.

&nbsp;

## What's New at a Glance

- **Router detail has a separate home.** `ROUTER.md` opens with an overview and intent model, then its MACHINE ROUTER section holds the intent map, resource map, default resource, loading levels and routing pseudocode.
- **Existing guidance points to the new file.** The testing playbooks that pointed at the router in `SKILL.md` now point to `ROUTER.md`. This packet ships no feature catalog, and its references never named the router, so neither had a path to update.
- **The fallback keeps its content in the skill.** `ROUTER.md` declares `SCALES` in `NO_LOAD_INTENTS`, so the fallback intent loads nothing because its content sits in `SKILL.md`.
- **Every scenario's proof command resolves.** An alignment pass moved eleven playbook greps off the hub's path and onto this packet's own `SKILL.md` and `references/`, and the README now shows the packet's own name and start command.

&nbsp;

## Upgrade

The parsed router is identical to the previous edition, so no routing migration is needed.
