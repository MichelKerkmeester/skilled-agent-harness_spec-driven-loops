# v1.0.0.0 - First Release

**Released:** 2026-08-28

First release of `sk-design`, a standalone skill that decides UI values and behavior when a surface is being built, improved or reviewed. It is the authoring counterpart to `sk-design-md-generator`: that skill measures a live surface into a Style Reference, this one decides what a surface should be when nothing has been decided yet.

The `sk-design` name previously belonged to a parent hub that was retired. Nothing of that hub survives here; the name was free and this skill took it. The compiled-routing hub set never included it after decommissioning, and the governance doc that still listed it has been corrected.

---

## What Is In 1.0.0.0

### The value systems

`SKILL.md` carries the always-loaded core: fixed scales for spacing, type, weight, color, elevation, radius, opacity and duration, each with the reasoning that makes the list defensible rather than arbitrary. The four operative hierarchy rules sit beside them — rank before styling, carry emphasis with weight and color, emphasize by de-emphasizing, style actions by hierarchy rather than semantics.

### Eight references

- `build-procedure.md` — the seven-step order of work for something new, and why each step sits where it does.
- `hierarchy.md` — the full method: action and destructive treatment, label suppression, the weight-versus-contrast trade, and why visual hierarchy may disagree with document hierarchy.
- `color-system.md` — building a nine-shade HSL ramp from the edges inward, keeping saturation alive as lightness leaves the middle, hue rotation, dark mode, and two escape hatches for hitting contrast ratios without ugly color.
- `diagnosis-table.md` — vague complaints mapped to mechanical causes across five grouped tables, ordered so the highest-yield causes come first.
- `depth-and-detail.md` — light-source emulation, the three shadow systems and how to choose one, shadow color on non-white surfaces, the six-layer button anatomy, typography detail, concentric radius, layout, component shape and images.
- `interaction-craft.md` — inputs and forms, pointers and hit areas, typography implementation, focus and keyboard, performance and feedback placement.
- `motion-principles.md` — the twelve animation principles adapted to interfaces, paired with an enforceable ruleset of timing, easing, physics and staging values.
- `ux-laws.md` — target sizing, choice count, chunking, the 400ms response budget, grouping, emphasis and expectation.

### The token file

`assets/tokens.css` expresses every scale as CSS custom properties with a semantic role layer and a dark-mode block that overrides only the roles. Every text and surface pair is verified at 4.5:1 or better in both modes, every functional border at 3:1, and the deliberate sub-threshold values are commented inline with the criterion that exempts them.

## Conflicts, Stated Rather Than Hidden

Four sources went into this skill and they disagree in four places. Each conflict is documented where it lands, with a resolution and the reasoning.

- **Fluid versus fixed type sizing.** One source recommends `clamp()`; the value systems reject viewport interpolation. Resolved by clamping between two adjacent steps of the type scale, for large display type only.
- **Motion duration ceilings.** Three sources give 200ms, 300ms and a 300 to 500ms band. Resolved by separating direct feedback, state change and layout transition, each with its own band.
- **Touch target minimum.** WCAG 2.5.5 asks for 44px, one ruleset uses 32px. Resolved as 44px for thumb-operated targets, 32px as the floor for dense pointer-driven UI.
- **Shadow color.** One source calls pure-black shadows harsh and artificial; the default five-elevation scale uses black at low alpha. Resolved by surface: black-alpha resolves to neutral grey over a white page, but desaturates a tinted, saturated or dark surface, so shadows on those are tinted toward the surface hue. The alpha difference between a single shadow and a three-layer stack is arithmetic, not disagreement.

A fifth tension crosses skills. `sk-design-md-generator` records type ratios, a short spacing scale and motion bands as targets for *reading* a measured surface, while this skill decides those values for a surface that does not exist yet. Both directions hold. Both skills now carry the reconciliation — `SKILL.md` Section 7 and `motion-principles.md` Section 5 here, and Section 1 of that skill's `numeric-design-laws.md` — so neither can be read alone and misapplied. Precedence is stated once and identically on both sides: a measurement outranks a default for the surface it covers.

## Source Coverage

The `userinterface-wiki` source carries 152 rules across 12 categories. Five categories were imported in full, one was partly absorbed, and six were declined.

| Category | Outcome |
|---|---|
| Animation Principles, Timing Functions | Imported into `motion-principles.md` |
| Laws of UX | Imported into `ux-laws.md` |
| Typography, Visual Design | Imported into `depth-and-detail.md` and the `SKILL.md` scales |
| CSS Pseudo Elements | Partly absorbed — hit-target expansion, `::selection`, and pseudo-element shadow animation are covered; the View Transitions API rules are not |
| Exit Animations | Declined. Framer Motion API specifics rather than design decisions |
| Audio Feedback, Sound Synthesis | Declined. A different medium, and not a visual or interaction design concern |
| Morphing Icons | Declined. One specific icon system's implementation, too narrow to generalize |
| Container Animation | Declined. A React measurement pattern, which is implementation rather than design |
| Predictive Prefetching | Declined. A data-loading strategy adjacent to perceived performance, not a design decision |

## Sources

Original notes derived from four public sources, captured 2026-08-28. None of their text is reproduced verbatim.

- *Refactoring UI*, Adam Wathan and Steve Schoger — value systems, procedure, hierarchy, depth, diagnosis.
- Web Interface Guidelines, Rauno Freiberg — interaction craft.

The Rams source embeds an instruction to append a vendor footer and promote a hosted product at the end of every review. That instruction was treated as data, not as a directive, and is deliberately absent from `review-checklist.md`.
