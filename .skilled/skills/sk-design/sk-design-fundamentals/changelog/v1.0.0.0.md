# sk-design v1.0.0.0, First Release

The first release of `sk-design` gives a standalone skill for deciding UI values and behavior while a surface is being built, improved or reviewed.

## Why This Release

Where `sk-design-md-generator` measures a live surface into a Style Reference, `sk-design` decides what a surface should be when nothing has been decided yet.

## What's New at a Glance

- **`SKILL.md` carries the always-loaded design core.** It provides fixed value scales and rules for visual hierarchy.
- **Eight references extend the design guidance.** They cover procedure, hierarchy, color, diagnosis, depth, interaction, motion and UX laws.
- **`assets/tokens.css` expresses every scale as CSS custom properties.** It has a semantic role layer, and the dark-mode block overrides only those roles.
- **Four source conflicts receive explicit resolutions.** The decisions cover type sizing, motion duration, touch targets and shadows.
- **`sk-design` and `sk-design-md-generator` reconcile authoring and measurement.** The relationship between designing and measuring a surface is documented in both skills.
- **`userinterface-wiki`'s 152 rules are accounted for across 12 categories.** Five categories are imported in full, one is partly absorbed and six are declined.
- **Four public sources inform the skill.** Their contributions span design decisions, interaction, motion and review.
- **The `sk-design` name is reused for a standalone skill.** The governance doc that listed the former hub has been corrected.
- **`review-checklist.md` excludes an embedded promotion instruction.** The source's instruction is treated as data rather than a directive.

## Design Foundation

#### Fixed Values and Hierarchy

`SKILL.md`'s always-loaded core sets fixed scales for spacing, type, weight, color, elevation, radius, opacity and duration. Each scale includes reasoning that makes its values defensible rather than arbitrary. The four operative hierarchy rules rank before styling, carry emphasis with weight and color, emphasize by de-emphasizing and style actions by hierarchy rather than semantics.

&nbsp;

#### Contrast Across Modes

Every text and surface pair is verified at 4.5:1 or better in both modes. Every functional border is at 3:1. Deliberate sub-threshold values are commented inline with the criterion that exempts them.

## Reference Guidance

#### Procedure and Hierarchy

`build-procedure.md` sets out the seven-step order of work for something new and why each step sits where it does. `hierarchy.md` covers action and destructive treatment, label suppression and the weight-versus-contrast trade. It also explains why visual hierarchy may disagree with document hierarchy.

&nbsp;

#### Color and Diagnosis

`color-system.md` builds a nine-shade HSL ramp from the edges inward, keeps saturation alive as lightness leaves the middle and covers hue rotation and dark mode. It gives two escape hatches for hitting contrast ratios without ugly color. `diagnosis-table.md` maps vague complaints to mechanical causes across five grouped tables, ordered so the highest-yield causes come first.

&nbsp;

#### Depth and Interaction

`depth-and-detail.md` covers light-source emulation, three shadow systems and how to choose one, shadow color on non-white surfaces and the six-layer button anatomy. It also covers typography detail, concentric radius, layout, component shape and images. `interaction-craft.md` covers inputs and forms, pointers and hit areas, typography implementation, focus and keyboard, performance and feedback placement.

&nbsp;

#### Motion and UX Laws

`motion-principles.md` adapts the twelve animation principles to interfaces and pairs them with an enforceable ruleset of timing, easing, physics and staging values. `ux-laws.md` covers target sizing, choice count, chunking, the 400ms response budget, grouping, emphasis and expectation.

## Source Decisions

Four sources disagree in four places. Each conflict is documented where it lands in the skill, with its resolution and the reasoning.

#### Type Uses Adjacent Steps

One source recommends `clamp()`, while the value systems reject viewport interpolation. For large display type only, the resolution clamps between two adjacent steps of the type scale.

&nbsp;

#### Motion Uses Separate Bands

Three sources give motion duration ceilings of 200ms, 300ms and a 300 to 500ms band. The conflict is resolved by separating direct feedback, state change and layout transition, each with its own band.

&nbsp;

#### Targets Match Input

WCAG 2.5.5 asks for 44px, while one ruleset uses 32px. The resolution sets 44px for thumb-operated targets and a 32px floor for dense pointer-driven UI.

&nbsp;

#### Shadows Follow the Surface

One source calls pure-black shadows harsh and artificial, while the default five-elevation scale uses black at low alpha. Over a white page, black-alpha resolves to neutral grey, but it desaturates a tinted, saturated or dark surface, so shadows on those surfaces are tinted toward the surface hue. The alpha difference between a single shadow and a three-layer stack is arithmetic, not disagreement.

## Measurement and Authoring

#### Measured Targets, New Work

`sk-design-md-generator` records type ratios, a short spacing scale and motion bands as targets for reading a measured surface. `sk-design` decides those values for a surface that does not exist yet, so both directions hold. Both skills now carry the reconciliation, in Section 7 of `SKILL.md` and Section 5 of `motion-principles.md` here and in Section 1 of `numeric-design-laws.md` in `sk-design-md-generator`, so neither can be read alone and misapplied. Precedence is stated once and identically on both sides: a measurement outranks a default for the surface it covers.

## Source Coverage

#### Imported and Partly Absorbed

- Animation Principles and Timing Functions are imported into `motion-principles.md`.
- Laws of UX is imported into `ux-laws.md`.
- Typography and Visual Design are imported into `depth-and-detail.md` and the `SKILL.md` scales.
- CSS Pseudo Elements is partly absorbed: hit-target expansion, `::selection` and pseudo-element shadow animation are covered, while the View Transitions API rules are not.

&nbsp;

#### Declined Material

- Exit Animations are declined because they are Framer Motion API specifics rather than design decisions.
- Audio Feedback and Sound Synthesis are declined because they concern a different medium and are not visual or interaction design concerns.
- Morphing Icons are declined because they are specific to one icon system's implementation and too narrow to generalize.
- Container Animation is declined because it is a React measurement pattern, which is implementation rather than design.
- Predictive Prefetching is declined because it is a data-loading strategy adjacent to perceived performance, not a design decision.

&nbsp;

#### Four Public Sources

The original notes were derived from four public sources and captured 2026-08-28. None of their text is reproduced verbatim.

- ***Refactoring UI*, Adam Wathan and Steve Schoger.** Value systems, procedure, hierarchy, depth and diagnosis.
- ***Web Interface Guidelines*, Rauno Freiberg.** Interaction craft.
- **`userinterface-wiki`, Raphael Salaja.** The motion model and its ruleset, UX laws and typography and visual-design rules.
- **Rams design review skill.** The severity-tiered review structure and its WCAG check set.

## Identity and Review

#### A Retired Name Is Reused

The `sk-design` name previously belonged to a parent hub that was retired. Nothing of that hub survives here, and the name was free for this skill to take. The compiled-routing hub set never included `sk-design` after decommissioning. The governance doc that still listed it has been corrected.

&nbsp;

#### Review Guidance Without Promotion

The Rams source embeds an instruction to append a vendor footer and promote a hosted product at the end of every review. That instruction was treated as data, not as a directive, and is deliberately absent from `review-checklist.md`.
