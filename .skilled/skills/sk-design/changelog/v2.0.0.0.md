# v2.0.0.0, sk-design Becomes a Parent Hub

`sk-design` moves from a single skill to a parent hub.

- `sk-design` was a single skill.
- It is now a parent hub of four modes.

Modes, commands and surfaces change together.

- Chart and diagram move in from `sk-doc`.
- The md generator returns as a mode.
- Commands land on `/design:`.
- Fundamentals stops being UI-only.

&nbsp;

## Why This Release

`sk-design` projects one design identity. It routes to the mode that owns the decision being asked for.

## Design Modes

This section covers how modes are declared, routed and packaged.

#### Registered Modes Own Routing <a id="c-registered-modes-own-routing"></a>

- `mode-registry.json` declares the modes.
- `hub-router.json` and the root `ROUTER.md` route them.
- `sk-design-md-generator` returns as a mode.
- Four modes are registered for `sk-design`.
- `sk-design-fundamentals` is the default.

#### Commands Follow Mode Rules <a id="c-commands-follow-mode-rules"></a>

- Design commands use the `/design:` surface.
- It includes `/design:extract`, `/design:chart` and `/design:diagram`.
- `sk-design-fundamentals` routes by alias.
- It carries no command of its own.
- Mode tool surfaces did not change.
- `sk-design-md-generator` remains the only mutating mode.

#### Screenshots Stay Out of Leaf Sets <a id="c-screenshots-stay-out-of-leaf-sets"></a>

- Canvas modes have rendered screenshots.
- They cover every form the two canvas modes ship.
- The rendered screenshots sit beside each canvas mode rather than inside `assets/`.
- This means a human-facing picture never enters a mode's loadable leaf set.

## Design Guidance

This section covers the surfaces the fundamentals mode now supports.

#### Fundamentals Covers More Surfaces <a id="c-fundamentals-covers-more-surfaces"></a>

- First-class surfaces include:
  - Slide decks
  - Printed layouts
  - Document surfaces
  - Screen UI
- Fundamentals is no longer UI-only.
- The WCAG review pass still applies only where the surface is a screen.

&nbsp;

## Hub Structure

This section covers the root hub files and the resource contract version.

#### Root Routing Names Its Parts <a id="c-root-routing-names-its-parts"></a>

- The root `SKILL.md` follows the `sk-code` and `sk-doc` shape.
- Its routing rules are explicit.
- The root `SKILL.md` has these routing parts:
  - A surface router
  - A stated discriminator
  - An explicit routing rule
  - An unknown-input fallback

#### A Numeric Contract Version <a id="c-a-numeric-contract-version"></a>

- `resourceContractVersion` is now a number.
- Its value in `mode-registry.json` is `1`, matching every peer hub.
- `resourceContractVersion` had been the string `"1.0.0"`.
- A numeric check reads that as absent.
- That silently disabled the manifest byte-drift check, the target-collision check and the reachability check.

#### Mode Table Gains a Command Column <a id="c-mode-table-gains-a-command-column"></a>

- The mode table gains a command column.
- It shows the same command declared in `mode-registry.json`.

&nbsp;

## Chart and Diagram

This section covers the two modes that moved in from `sk-doc`.

#### Mode Names Join the Hub <a id="c-mode-names-join-the-hub"></a>

- Chart and diagram move from `sk-doc`.
- They take this hub's name.
- Chart and diagram left `sk-doc` and took this hub's name.
- `sk-create-chart` became `sk-design-chart`.
- `sk-create-diagram` became `sk-design-diagram`.
- Both hubs were edited together, so no phrase was claimed twice.

#### Records Keep Their Old Names <a id="c-records-keep-their-old-names"></a>

- The chart corpus contract and its checker moved unmodified.
- Authored spec-folder records, benchmark reports and run artifacts describe what was on disk when they were written.
- They keep the old names.
