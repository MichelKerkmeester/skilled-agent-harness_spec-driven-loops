# v3.0.0.0, Three Modes and No Values Mode

The hub drops its values mode.

- Deciding a spacing, type, colour or motion value now belongs to `sk-code`.
- Reviewing a screen now belongs there too.
- Its frontend surface carries the same scales and review pass.

The hub keeps the three modes that build a design artifact.

- `sk-design-md-generator`, `sk-design-chart` and `sk-design-diagram` remain.
- `routerPolicy.defaultMode` is `null`.
- So a design request with no signal defers.
- It asks which artifact is wanted.

&nbsp;

## Why This Release

Two skills answered the same question. `sk-code-frontend` already sent every open value to `sk-design-fundamentals`.

- So a frontend request crossed two hubs to pick a padding.
- The value guidance now sits where the code that uses it is written.

## Hub Routing

Three modes handle design artifacts. Without a default, a request with no signal defers.

#### Three Build Modes Remain <a id="c-three-build-modes-remain"></a>

- `sk-design-md-generator`, `sk-design-chart` and `sk-design-diagram` remain.

#### No Default Mode Defers <a id="c-no-default-mode-defers"></a>

- `routerPolicy.defaultMode` is `null`.
- So a design request with no signal defers.
- It asks which artifact is wanted.

#### Chart Choice Questions Reach Chart Mode <a id="c-chart-choice-questions-reach-chart-mode"></a>

- "Which chart should I use" and "pick a chart for this data" used to land on the retired default mode.
- They now route to `sk-design-chart`.
- That mode owns the choice of form.

#### Chart Colour Reviews Reach Chart Mode <a id="c-chart-colour-reviews-reach-chart-mode"></a>

- "Review the chart colour system" used to land on `sk-code`.
- Both spellings of the phrase now sit in `derived.trigger_phrases`.
- So the request routes to `sk-design-chart`.

#### Values and Review Intents Removed <a id="c-values-and-review-intents-removed"></a>

- The VALUES and REVIEW intents are gone from the root `ROUTER.md`.

#### Advisor Phrases Describe Three Modes <a id="c-advisor-phrases-describe-three-modes"></a>

- `derived.intent_signals` carries extract, chart and diagram phrases only.
- So a design-value request no longer pulls toward this hub.

&nbsp;

## Removed

One mode is deleted. Some layout guidance is dropped.

#### The Values Mode Is Retired <a id="c-the-values-mode-is-retired"></a>

- `sk-design-fundamentals/` is deleted.
- Its value scales, colour construction, elevation, typography detail, tokens and hard rules are in `sk-code/sk-code-frontend/references/web-visual-values.md`.
- Its hierarchy method, symptom-to-fix tables, build procedure, UX laws and review pass are in `web-visual-hierarchy.md`.
- Its motion and interaction rules are in `web-motion-and-interaction.md`.
- The starter `tokens.css` moved to `sk-code/sk-code-frontend/assets/`.

#### Slides Print and Document Guidance Dropped <a id="c-slides-print-and-document-guidance-dropped"></a>

- Slides, print and document layout guidance is dropped.
- Chart and diagram already carry their own type and spacing scales.

&nbsp;

## Upgrade Notes

A value or visual review request now routes to `sk-code`. Nothing changes for projects using the advisor.

#### Before You Start <a id="c-before-you-start"></a>

- A request for a value or a visual review now routes to `sk-code`.
- Nothing needs to change in a project that loads skills through the advisor.
