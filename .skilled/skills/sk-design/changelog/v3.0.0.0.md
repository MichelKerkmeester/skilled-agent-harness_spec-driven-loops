# v3.0.0.0, Three Modes and No Values Mode

The hub drops its values mode. Deciding a spacing, type, colour or motion value and reviewing a screen now belong to `sk-code`, whose frontend surface carries the same scales and review pass. The hub keeps the three modes that build a design artifact.

> Spec folder: `specs/sk-design/021-deprecate-fundamentals` (Level 2)

&nbsp;

## Why This Release

Two skills answered the same question. `sk-code-frontend` already sent every open value to `sk-design-fundamentals`, so a frontend request crossed two hubs to pick a padding. The value guidance now sits where the code that uses it is written.

&nbsp;

## What's New at a Glance

- **Three modes.** `sk-design-md-generator`, `sk-design-chart` and `sk-design-diagram` remain.
- **No default mode.** `routerPolicy.defaultMode` is `null`, so a design request with no signal defers and asks which artifact is wanted.
- **Chart-choice questions reach the chart mode.** "Which chart should I use" and "pick a chart for this data" used to land on the retired default mode. They now route to `sk-design-chart`, which owns the choice of form.
- **Chart colour-system reviews reach the chart mode.** "Review the chart colour system" used to land on `sk-code`. Both spellings of the phrase now sit in `derived.trigger_phrases`, so the request routes to `sk-design-chart`.
- **The VALUES and REVIEW intents are gone** from the root `ROUTER.md`.
- **The advisor phrases describe the three remaining modes.** `derived.intent_signals` carries extract, chart and diagram phrases only, so a design-value request no longer pulls toward this hub.
- **Slides, print and document layout guidance is dropped.** Chart and diagram already carry their own type and spacing scales.

&nbsp;

## Removed

#### The values mode is retired

`sk-design-fundamentals/` is deleted. Its value scales, colour construction, elevation, typography detail, tokens and hard rules are in `sk-code/sk-code-frontend/references/web-visual-values.md`. Its hierarchy method, symptom-to-fix tables, build procedure, UX laws and review pass are in `web-visual-hierarchy.md`. Its motion and interaction rules are in `web-motion-and-interaction.md`. The starter `tokens.css` moved to `sk-code/sk-code-frontend/assets/`.

&nbsp;

## Upgrade Notes

- A request for a value or a visual review now routes to `sk-code`. Nothing needs to change in a project that loads skills through the advisor.
- A link to `sk-design/sk-design-fundamentals/` no longer resolves. Point it at the matching `sk-code-frontend` reference above.
