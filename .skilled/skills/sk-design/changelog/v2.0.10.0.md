# v2.0.10.0, Routing Rules Move to ROUTER.md

The routing rules for sk-design moved out of SKILL.md and into a final MACHINE ROUTER section of ROUTER.md. SKILL.md stays short, and the hub routes the same way it did before.

> Spec folder: `specs/sk-doc/072-skill-routing-and-clarity/014-skill-router-files/004-hub-router-merge` (Level 1)

&nbsp;

## What's New at a Glance

- **SKILL.md keeps a single pointer.** SKILL.md no longer carries a MACHINE ROUTER section. Its SMART ROUTING section ends with one line that points to ROUTER.md.
- **The compiler finds the checklist in either file.** It reads the fallback checklist from the final MACHINE ROUTER section of ROUTER.md when that section exists. It reads from SKILL.md when the section does not exist.
- **Routing is unchanged.** The map from intent to files is byte for byte the same, and every route the hub selects matches the run before the move. The compiled admission check gives the same result, and the compiled manifest was regenerated from the new sources.
- **The hub meets the routing-shape canon.** Its known-debt entry is removed, so the hub no longer needs an exception in that check.
- **ROUTER.md speaks from its own point of view.** The `SKILL_ROOT` line and the separate-document line now read from the router itself.
- **The playbooks name the file that holds the router.** An alignment pass repointed four hub scenarios from `SKILL.md` to `ROUTER.md`, replaced sk-doc's eighteen-intent list in a diagram scenario with the hub's five leaf intents, and corrected the hub named in the `/design:diagram` and `/design:chart` choreography.
