# v2.0.9.0, One Routing Glossary

The hub `SKILL.md` now opens How It Works with a `### Terms` list. Twelve routing terms the rest of the file leans on are defined there in one line each: `workflowMode`, `packetKind`, `backendKind`, `routingClass`, `mode-registry.json`, `hub-router.json`, `vocabularyClasses`, `tieBreak`, `routerPolicy.defaultMode`, leaf, `ROUTER.md` and `intent_signals`. Routing is unchanged.

> Spec folder: `specs/sk-doc/072-skill-routing-and-clarity/010-prose-clarity-pass` (Level 2)

&nbsp;

## What's New at a Glance

- **One glossary, in the first subsection of How It Works.** A new reader meets the routing vocabulary before the layout and the registry warning that use it.
- **Each line says what the term is in this hub.** The meanings come from the file, `mode-registry.json` and `hub-router.json`, so they agree with the `### The discriminator` list rather than restating it.
- **Routing is unchanged.** The four mode names, the router files and the compiled front door behave as they did, and only the `version` fields moved.

&nbsp;

## Upgrade

No action is needed. The registry, the router and the routing behaviour are unchanged.
