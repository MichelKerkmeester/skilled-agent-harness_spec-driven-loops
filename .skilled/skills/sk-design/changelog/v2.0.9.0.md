# v2.0.9.0, One Routing Glossary

The hub `SKILL.md` now opens How It Works with a `### Terms` list. Twelve routing terms the rest of the file leans on are defined there. Each gets one line. They are `workflowMode`, `packetKind`, `backendKind`, `routingClass`, `mode-registry.json`, `hub-router.json`, `vocabularyClasses`, `tieBreak`, `routerPolicy.defaultMode`, leaf, `ROUTER.md` and `intent_signals`. Routing is unchanged.

&nbsp;

## What's New at a Glance

- One glossary sits in the first subsection of How It Works.
  - A new reader meets the routing vocabulary before the layout and the registry warning that use it.
- Each line says what the term is in this hub.
  - The meanings come from the file, `mode-registry.json` and `hub-router.json`.
  - So they agree with the `### The discriminator` list.
  - The meanings do not restate it.
- Routing is unchanged.
  - The four mode names, the router files and the compiled front door behave as they did.
  - Only the `version` fields moved.

&nbsp;

## Upgrade

No action is needed. The registry, the router and the routing behaviour are unchanged.
