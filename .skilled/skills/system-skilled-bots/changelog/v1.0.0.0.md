# v1.0.0.0, Hub Wiring

The bots runtime already ran from its CLI. This release gives it a hub, so a request to author, run, schedule or check a bot has a route.

&nbsp;

## What's New at a Glance

- Four `metadata` modes: author, run, schedule and status, each in its own packet with a router and one reference leaf.
- `bots inbox` routes to status and `bots answer` routes to run. Neither gets a mode of its own.
- `/bots:author`, `/bots:run`, `/bots:schedule` and `/bots:status`, with tool grants cut to each mode.
- `/doctor:bots` runs the definition checker read-only over a repository's `bots/` folder.
- Every routing signal names a bot, so bare run, schedule and status phrasing does not reach the hub.

&nbsp;

## Upgrade

No migration required. The hub ships without a compiled activation manifest, so the compiled front door returns the legacy sentinel and routing uses `hub-router.json` and the root `ROUTER.md`.
