# v1.9.0.0, The MagicPath Mode Retires

The hub no longer carries MagicPath. The `mcp-magicpath` mode, its packet and every route that reached it are gone, so a request that names MagicPath now ends at the hub's defer path. The five workflow bridges and three read-only transports remain. No replacement mode exists.

> Spec folder: `specs/other/001-retire-magicpath-and-sk-vision/003-remove-mcp-magicpath-mode` (Level 2)

&nbsp;

## Why This Release

The mode was retired by operator decision. Leaving its rows in place would keep a request routed to a packet that no longer exists, and the hub would advertise a capability it cannot serve. Removing both together closes that gap.

&nbsp;

## What's New at a Glance

- **The mcp-magicpath mode is gone.** Its packet, its playbook scenario and its command wrappers no longer exist.
- **Every routing surface forgets MagicPath.** The registry, both routers, the leaf manifest, the graph metadata and the compiled-routing canary no longer name it.
- **A MagicPath request now defers.** The hub has no mode to offer it and no alias that forwards it.
- **The hub carries eight modes.** Five workflow bridges and three read-only transports remain.

&nbsp;

## MCP Tooling Hub

#### The Mode Leaves Every Surface

The removal takes the mode's 33-file packet folder, including its `SKILL.md`, its README, its references, its feature catalog and its changelog. The MagicPath component lookup scenario left the manual testing playbook, the two `magicpath-utcp` wrappers left `.skilled/bin`, and the changelog symlink under `.skilled/changelog/mcp-tooling` went with the packet.

The `magicpath` manual left `.utcp_config.json`, so the config carries no call template for it. The naming example in the `mcp-code-mode` reference now uses `<manual>.<tool>()` and `<manual>.<manual>_<tool>()` placeholders and keeps the rule text.

#### Routing Falls to Defer

The stage-one registry and router no longer carry the mode. Neither do the stage-two intent map, the leaf manifest, the advisor graph or the compiled-routing canary. A request that names MagicPath finds no signal, so the hub defers instead of sending it to a neighbour.

#### The Hub Keeps Eight Modes

Five workflow modes remain: `mcp-chrome-devtools`, `mcp-click-up`, `mcp-obsidian`, `mcp-aside-devtools` and `mcp-notion`. Three read-only transports remain: `mcp-figma`, `mcp-refero` and `mcp-mobbin`. The hub `SKILL.md`, README, description, feature catalog and playbook index state the same count.

&nbsp;

## Upgrade Notes

- **Surviving modes need no action.** Their routes and packets are unchanged.
- **MagicPath callers must stop.** No replacement mode exists, so a request that names MagicPath ends at the hub's defer path instead of reaching a packet.
