# v1.9.0.0, The MagicPath Mode Retires

The hub no longer carries MagicPath.

- The `mcp-magicpath` mode is gone.
- Its packet and every route that reached it are gone too.
- No replacement mode exists.

MagicPath requests now reach the defer path.

- The hub has no mode to offer it.
- It has no alias that forwards it.
- So a request that names MagicPath now ends at the hub's defer path.

The hub carries eight modes.

- Five workflow bridges remain.
- Three read-only transports remain.

&nbsp;

## Why This Release

The mode was retired by operator decision. Removing both together closes that gap.

- Leaving its rows in place would keep a request routed to a packet that no longer exists.
- The hub would also advertise a capability it cannot serve.

## MCP Tooling Hub

The hub no longer carries the `mcp-magicpath` mode. Eight modes remain.

#### The Mode Leaves Every Surface <a id="c-the-mode-leaves-every-surface"></a>

- The removal takes the mode's 33-file packet folder.
- That includes its `SKILL.md`, its README, its references, its feature catalog and its changelog.
- The MagicPath component lookup scenario left the manual testing playbook.
- The two `magicpath-utcp` wrappers left `.skilled/bin`.
- The changelog symlink under `.skilled/changelog/mcp-tooling` went with the packet.
- The `magicpath` manual left `.utcp_config.json`. So the config carries no call template for it.
- The naming example in the `mcp-code-mode` reference now uses `<manual>.<tool>()` and `<manual>.<manual>_<tool>()` placeholders.
- It keeps the rule text.

#### Routing Falls to Defer <a id="c-routing-falls-to-defer"></a>

- Every routing surface forgets MagicPath.
- The stage-one registry and router no longer carry the mode.
- The registry and both routers no longer name it.
- The stage-two intent map no longer carries it.
- Neither do the leaf manifest, the advisor graph and the compiled-routing canary.
- So do the leaf manifest, the graph metadata and the compiled-routing canary.
- A request that names MagicPath finds no signal.
- So the hub defers instead of sending it to a neighbour.

#### The Hub Keeps Eight Modes <a id="c-the-hub-keeps-eight-modes"></a>

- Five workflow modes remain: `mcp-chrome-devtools`, `mcp-click-up`, `mcp-obsidian`, `mcp-aside-devtools` and `mcp-notion`.
- Three read-only transports remain: `mcp-figma`, `mcp-refero` and `mcp-mobbin`.
- The hub `SKILL.md`, README, description, feature catalog and playbook index state the same count.

&nbsp;

## Upgrade Notes

Surviving modes need no action. Their routes and packets are unchanged.
