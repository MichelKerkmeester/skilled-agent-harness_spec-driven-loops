# v1.8.9.0, One Vocabulary for the Hub Router

A prompt that stage one sends to a mode used to reach stage two. There it found no leaf. That is because the root ROUTER.md intents carried fewer words than hub-router.json routes. The intents now carry every routed term. The three copies that had drifted apart are checked against one authored vocabulary.

&nbsp;

## What's New at a Glance

- **Every routed term now reaches stage two.** The root ROUTER.md intents gained 57 terms. Their multi-word forms went into graph-metadata.json intent_signals. The skill advisor reads them there.
- **mcp-obsidian's Health.md, Iconic, Excalidraw and theme terms now load its leaves.** Three words stopped routing instead. `design tokens` now reaches sk-design. `task list` and the `dom inspect` alias reach no hub. So the intents keep only the specific forms such as `inspect the dom`.
- **Two bare terms left the vocabulary.** `on its own` and `design reference` are gone from `hub-router.json`. They are also gone from the root `ROUTER.md` intents and the `graph-metadata.json` intent signals. `design reference` also came off mcp-refero's `Keyword triggers:` line. That is because both pulled ordinary coding and documentation prompts here. `design reference search` stays.
- **One check now guards the vocabulary.** `.skilled/skills/sk-doc/sk-create-skill/scripts/ci-hub-vocabulary-source.cjs` fails when the registry aliases disagree with hub-router.json. It also fails when the root intents or a packet's `Keyword triggers:` line disagree.

&nbsp;

## Upgrade

No action is needed. The vocabulary gained more than it lost. `design reference search` still reaches mcp-refero.
