# mcp-tooling gains mcp-magicpath, a transport whose provider ships no MCP server

mcp-tooling now gives MagicPath's component and design-system surface a route through the hub.

## Why This Release

Every other bridge in the hub binds to an MCP server, and all thirteen manuals registered in `.utcp_config.json` used `call_template_type: "mcp"`. MagicPath publishes no MCP server. Its published integration is a Node CLI plus vendor-authored instruction files dropped into three runtime directories, which bypasses the hub, registry and advisor that every other tool bridge routes through.

The `@utcp/cli` transport was already installed beside `@utcp/mcp` and unused. Registering MagicPath through it avoids standing up and owning a protocol surface the vendor does not ship.

## What's New at a Glance

- **`mcp-magicpath` adds the hub's ninth mode.** It is reached through a UTCP `cli` manual.
- **`mode-registry.json` adds `backendKind: "code-mode-cli"`.** The registry moves from v1.0.2.0 to v1.1.0.0.
- **At the hub level, MagicPath phrasings resolve to `mcp-magicpath`.** Sibling routing is unchanged after the registry change.
- **`graph-metadata.json` adds six MagicPath trigger phrases.** Its causal summary also changes.
- **`feature-catalog/` and `manual-testing-playbook/` now report nine modes.** The playbook adds scenario `MT-011` for MagicPath component lookup.
- **The hub descriptions now name MagicPath.** The transport axis reads four rather than three.
- **`mcp-magicpath` is read-only by design.** The `.tsx`-writing, package-installing, remote-project and component-revision commands listed below are unregistered.
- **Advisor-level precedence is not established.** Adding trigger phrases did not alter the advisor-level outcome.

## MagicPath Transport

#### The First CLI Manual

`mcp-magicpath` is the hub's first member reached through a UTCP `cli` manual rather than an MCP server. The manual is called through Code Mode and described by a mode packet.

&nbsp;

#### A Backend for Vendor CLIs

The existing `backendKind` values cover a local desktop daemon and remote MCP servers. Neither describes a vendor CLI reached through Code Mode, so the `transport-axis` extension records why `code-mode-cli` is needed.

---

## Routing and Discovery

#### MagicPath Routing Signals

`hub-router.json` moves from v1.1.4.0 to v1.2.0.0 and adds the `magicpath-aliases` vocabulary class and a `routerSignals` entry at weight 4. A `routerPolicy.tieBreak` entry also joins the update.

&nbsp;

#### Trigger Phrase Coverage

Every other provider had trigger phrases. MagicPath had none.

&nbsp;

#### Advisor Scoring Gap

A cold MagicPath request naming neither the hub nor the mode has been observed returning no recommendation at all. That behavior belongs to advisor scoring, not the registration.

## Hub Documentation

#### Corrected Mode Counts

The `feature-catalog/` and `manual-testing-playbook/` had claimed seven modes while eight existed after `mcp-notion` was added without updating them. Both now enumerate the axes correctly, and holdout coverage is stated as 7/9 because neither `mcp-notion` nor `mcp-magicpath` has a blind holdout scenario.

&nbsp;

#### Member Descriptions and Leaf Resources

`SKILL.md`, `README.md` and `description.json` move from v1.5.2.0 to v1.6.0.0. `leaf-manifest.json` was regenerated and has four leaf resources.

---

## Workspace Safety

#### Write Commands Stay Unregistered

MagicPath's CLI can write `.tsx` files into the calling project, install npm packages and create remote projects and component revisions. None of those commands is registered, so `mutatesWorkspace: false` holds for the same reason it holds for the remote-MCP transports. The destructive half is unreachable from a tool call rather than merely discouraged.

---

## Upgrade Notes

- **Existing modes.** No upgrade is needed for existing modes.
- **MagicPath credentials.** Authenticate its CLI separately with `magicpath-ai login`, or wire `MAGICPATH_TOKEN` through the dotenv loader as `magicpath_MAGICPATH_TOKEN`.
- **Missing credentials.** Without a credential every tool returns a structured `NOT_AUTHENTICATED` object rather than failing opaquely.
