# mcp-tooling v1.4.2.0: Webflow Routing Removed

After the operator deleted the `mcp-webflow` packet, this release removes every remaining hub surface that advertised or routed to it. The hub no longer offers Webflow as a routable mode.

## Why This Release

The registry, router, advisor description, leaf manifest and shared routing reference still declared `mcp-webflow` as an eighth mode. That declaration would send agents to a nonexistent packet and break the mode-inventory contract. Removing it keeps the hub truthful and keeps routing failures from surfacing to users.

## What's New at a Glance

- **The router removes Webflow signals.** `hub-router.json` (v1.1.2.0) removes `mcp-webflow` from `routerPolicy.tieBreak` and deletes its `routerSignals` entry, along with the `webflow-aliases` and `webflow-operations` vocabulary classes.
- **The registry drops the Webflow mode.** `mode-registry.json` (v1.0.2.0) removes `mcp-webflow` from `extensions.transport-axis.transports` and `crossHubPairing`. It deletes the `modes[]` entry, including the `code-mode-stdio-mcp` backend kind, Webflow token wiring and conditional `sk-design` pairing. The transport-axis description no longer documents a local-stdio Webflow backend.
- **Advisor and routing references remove Webflow.** `description.json` (v1.4.2.0) no longer advertises Webflow operations in its description or keywords. `SKILL.md` (v1.3.2.0) removes Webflow from the mode table and names only `mcp-figma`, `mcp-refero` and `mcp-mobbin` in the transport-axis sentence, with a mandatory `sk-design` pairing. `shared/references/smart-routing.md` removes the `WEBFLOW` intent signals and resource-map entries, and its surface router covers the remaining seven modes.
- **The manifest drops the mode and its report is deleted.** `leaf-manifest.json` was regenerated without the `mcp-webflow` mode block. The `benchmark/reports/2026-08-02--webflow-registration--routing-replay/` report was deleted because it referenced the removed packet.
- **The README conflict blocks are resolved.** The four committed merge-conflict blocks in `README.md` were resolved with the local side kept. Neither side advertised Webflow.

## Upgrade

No migration required.
