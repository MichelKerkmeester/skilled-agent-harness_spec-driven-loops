# v1.8.0.0 - Orca CLI extraction to a standalone skill

**Released:** 2026-09-20

The hub returns to a single responsibility: nine MCP tool bridges, five workflow modes and four read-only design transports. The Orca CLI subject left the hub and now lives as the standalone class-S skill `cli-orca`.

## Why

Orca-managed worktrees, terminals, the embedded browser, automations, artifacts, handoffs and skill sharing are CLI surfaces, not MCP transports. Keeping that subject inside a hub whose identity is MCP tool bridging forced a permanent exception into the hub identity, the mode table, the description, the router vocabulary and the manifest. The subject also gained a knowledge layer the hub could not carry: one authored reference and one verbatim snapshot for each of the eight official Orca skills.

## What Changed

- Removed the `mcp-orca-cli` mode entry from `mode-registry.json`, including its tool surface, aliases and advisor routing metadata. The registry now declares nine modes.
- Removed the stage-one router signal, the `orca-cli-aliases` and `orca-worktree-terminal` vocabulary classes, and the tie-break entry from `hub-router.json`.
- Removed the `ORCA_CLI` intent signal and its two stage-two packet-qualified resources from `ROUTER.md`, and dropped the mode from the router's mode lists.
- Updated the hub `SKILL.md` mode table and identity text, the README mode lists and quick-start prompts, `description.json`, and the graph vocabulary, domains, key files, source documents and entities. No Orca signal remains, so an Orca request now defers here instead of being captured.
- Deleted the retired nested packet from the hub tree. Its routing contract, references and safety envelope were superseded by the standalone `cli-orca` skill.
- Moved the mode's benchmark evidence to `specs/cli-orca/001-mcp-orca-cli/benchmark/reports/orca-integration/`, and its two hub-routing scenarios to `benchmark/reports/hub-routing-archived/` in the same packet.
- Updated the hub feature catalog and manual testing inventory for nine modes, and recorded the retired coverage gap rather than inferring it.
- Regenerated the hub leaf manifest through the canonical metadata command. Every remaining manifest leaf resolves, and all nine modes reach back to a registered mode.

## Safety and Boundaries

The extraction removes vocabulary, not caution. Orca CLI work keeps its own safety envelope in the standalone skill: mutation classification, archive-hook deletion gates, terminal receipt distinctions, tab-scoped browser refs, untrusted page content, publishing permission denials and explicit authorization requirements. Generic Git worktrees stay with `sk-git`, generic terminal work stays with the normal coding workflow, Chrome/CDP work stays with `mcp-chrome-devtools`, generic agentic browser work stays with `mcp-aside-devtools`, and supervised orchestration stays with the official `orchestration` skill.

## Known Limitations

- Compiled routing was not promoted or re-authorised by this change. The hub continues to report its serving authority and cause code honestly, and this change only removes a source mode.
- The retired mode's historical changelog entry remains in this directory as the record of that release.
