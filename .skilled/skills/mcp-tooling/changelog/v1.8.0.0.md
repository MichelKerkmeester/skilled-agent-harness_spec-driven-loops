# v1.8.0.0, Orca CLI Moves to a Standalone Skill

v1.8.0.0 moves the Orca CLI subject out of the MCP tooling hub.

- The subject moves into the standalone class-S skill `cli-orca`.
- The hub returns to a single responsibility.
- That is nine MCP tool bridges, five workflow modes and four read-only design transports.

The hub shed the retired Orca mode and its routing signals.

- `mcp-orca-cli` was removed from the hub.
- An Orca request now defers here instead of being captured.
- Hub guidance and graph metadata changed.
- The hub's identity and routing descriptions were updated.

Orca CLI keeps its safety envelope and moved its records.

- The retired nested packet was deleted from the hub tree.
- Its routing contract, references and safety envelope were superseded by `cli-orca`.
- Orca benchmark records moved to separate destinations.
- Generic work keeps its named owners.

&nbsp;

## Why This Release

Orca-managed worktrees, terminals, the embedded browser, automations, artifacts, handoffs and skill sharing are CLI surfaces. They are not MCP transports. The hub's identity is MCP tool bridging. Keeping that subject inside the hub forced a permanent exception.

- The exception landed in the hub identity, mode table, description, router vocabulary and manifest.
- The subject also gained a knowledge layer the hub could not carry.
- That layer is one authored reference and one verbatim snapshot for each of the eight official Orca skills.

## MCP Tooling Hub

The hub lost the Orca mode and its routing signals. Its guidance and records changed with the move.

#### Orca Routing Leaves the Hub <a id="c-orca-routing-leaves-the-hub"></a>

- `mode-registry.json` lost the `mcp-orca-cli` entry.
- That entry included its tool surface, aliases and advisor routing metadata.
- The registry now declares nine modes.
- `hub-router.json` lost the stage-one router signal.
- It also lost the `orca-cli-aliases` and `orca-worktree-terminal` vocabulary classes.
- The tie-break entry was removed too.
- The `ROUTER.md` changes removed the `ORCA_CLI` intent signal.
- They also removed its two stage-two packet-qualified resources.
- The retired mode was dropped from the router's mode lists.

#### Hub Guidance Follows the Move <a id="c-hub-guidance-follows-the-move"></a>

- The hub `SKILL.md` mode table and identity text changed.
- So did the README mode lists and quick-start prompts and `description.json`.
- Graph metadata changed in its vocabulary, domains, key files, source documents and entities.
- No Orca signal remains.
- The release updated the hub feature catalog and manual testing inventory for nine modes.
- The hub's identity and routing descriptions were updated.

#### Retired Packet Deleted <a id="c-retired-packet-deleted"></a>

- The retired nested packet was deleted from the hub tree.
- Its routing contract, references and safety envelope were superseded by `cli-orca`.

#### Coverage Records Updated <a id="c-coverage-records-updated"></a>

- The hub's coverage records were updated.
- The retired coverage gap was recorded rather than inferred.

#### Leaf Manifest Regenerated <a id="c-leaf-manifest-regenerated"></a>

- The hub leaf manifest was regenerated.
- Every remaining manifest leaf resolves.
- All nine modes reach back to a registered mode.

#### Routing Scope and History <a id="c-routing-scope-and-history"></a>

- For compiled routing, this change only removes a source mode.
- Compiled routing was not promoted or re-authorized.
- The hub continues to report its serving authority and cause code honestly.
- The retired mode's historical changelog entry remains in this directory as the record of that release.

## Orca CLI

The extraction removes vocabulary, not caution. Orca CLI work keeps its own safety envelope. That envelope lives in the standalone skill `cli-orca`.

#### Safety After the Extraction <a id="c-safety-after-the-extraction"></a>

- It covers mutation classification.
- It covers archive-hook deletion gates.
- It covers terminal receipt distinctions.
- It covers tab-scoped browser refs.
- It covers untrusted page content.
- It covers publishing permission denials.
- It covers explicit authorization requirements.

#### Benchmark Records Move <a id="c-benchmark-records-move"></a>

- The mode's benchmark evidence moved to the cli-orca spec track, which was later deleted.
- Its two hub-routing scenarios moved to `benchmark/reports/hub-routing-archived/` in the same packet.
- The move split integration evidence from two hub-routing scenarios.

&nbsp;

## Work Boundaries

Generic work keeps its named owners.

#### Generic Work Keeps Its Owners <a id="c-generic-work-keeps-its-owners"></a>

- Generic Git worktrees stay with `sk-git`.
- Generic terminal work stays with the normal coding workflow.
- Chrome/CDP work stays with `mcp-chrome-devtools`.
- Generic agentic browser work stays with `mcp-aside-devtools`.
- Supervised orchestration stays with the official `orchestration` skill.
- Git, terminal, browser and supervised orchestration work stay with their named surfaces.
