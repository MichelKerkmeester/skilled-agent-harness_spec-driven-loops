# v1.7.0.0 - Orca CLI workflow bridge

Orca owns state that ordinary Git, shell and browser tools cannot observe.

- This release adds a dedicated Orca CLI workflow to the MCP tooling hub.
- The inspected 1.4.205 command registry exposed no native Orca MCP command.
- So the new member remains CLI-only.

The hub gains a nested packet and a registry entry.

- The hub adds a nested `mcp-orca-cli` workflow packet.
- The hub adds a registry entry for `mcp-orca-cli`.
- It records `packetKind: workflow` and `backendKind: cli-only`.

Generic work stays with its designated packets.

- `mcp-chrome-devtools` remains with generic Chrome/CDP work.
- `mcp-aside-devtools` remains with generic agentic browser work.
- Supervised orchestration remains outside this packet.

&nbsp;

## Why This Release

The public Orca skill is a discovery stub.

- Its flags come from the installed Orca version.
- The packet resolves one executable.
- It loads the matching `orca-cli` guide before it relies on command details.
- It does not invent a Code Mode manual.

## Orca CLI Workflow

The hub gains a nested packet, a registry entry and updated routing. Its materials and mutation posture stay explicit.

#### Packet Materials Match the Work <a id="c-packet-materials-match-the-work"></a>

- A runtime contract, README and operator installation guide.
- A version-matched command reference and session/runtime reference.
- Mutation and browser boundaries, a troubleshooting reference and a manual safety matrix.
- A leaf changelog.

#### Workspace Mutation Is Explicit <a id="c-workspace-mutation-is-explicit"></a>

- The registry entry sets explicit workspace mutation posture.
- It sets narrow multi-word aliases.
- It also sets metadata advisor routing.

#### Nested Workflow Packet <a id="c-nested-workflow-packet"></a>

- The hub adds a nested `mcp-orca-cli` workflow packet.
- It covers Orca-managed worktrees, repositories, terminals, handoffs, automations, artifacts, skill sharing, comments and embedded browser state.

#### Registry Entry for the Packet <a id="c-registry-entry-for-the-packet"></a>

- The hub adds a registry entry for `mcp-orca-cli`.
- It records `packetKind: workflow` and `backendKind: cli-only`.

#### Orca Packet Resources <a id="c-orca-packet-resources"></a>

- Stage two adds packet-qualified resources for Orca.
- The router additions also include an Orca stage-one router signal, vocabulary classes and a tie-break entry.

#### Six Hub Items Updated <a id="c-six-hub-items-updated"></a>

- Six hub items were updated.
- The update covered six workflow modes and four transports.
- They were the single hub advisor identity, hub README, root router, description, feature catalog and hub manual-testing inventory.

#### Hub Leaf Manifest Regenerated <a id="c-hub-leaf-manifest-regenerated"></a>

- The canonical metadata command regenerated the hub leaf manifest.
- All Orca reference leaves are reachable through it.

#### Hub Graph Corrected <a id="c-hub-graph-corrected"></a>

- The hub graph was corrected.
- The corrections covered vocabulary, causal context, key files, source documents and packet entities.
- They did not create a second advisor identity.

#### Orca Operations Count as State Changes <a id="c-orca-operations-count-as-state-changes"></a>

- The packet treats listed Orca operations as state-changing.
- These include worktree, terminal, agent, browser, automation, publishing, authentication and skill-sharing operations.

#### Generic Work Stays Put <a id="c-generic-work-stays-put"></a>

- Generic work stays with its designated packets.
- `mcp-chrome-devtools` remains with generic Chrome/CDP work.
- `mcp-aside-devtools` remains with generic agentic browser work.
- Supervised orchestration remains outside this packet.

#### Orca Flags Remain Version Sensitive <a id="c-orca-flags-remain-version-sensitive"></a>

- Orca command flags remain version-sensitive.
- The installed guide and command help outrank this packet's representative examples.

#### Unperformed Checks Get a Status <a id="c-unperformed-checks-get-a-status"></a>

- Unperformed checks have a required status.
- They must be recorded as `SKIP` with their blocker.

&nbsp;

## Safety and Boundaries

The packet keeps its deletion and browser boundaries intact.

#### Deletion and Browser Boundaries <a id="c-deletion-and-browser-boundaries"></a>

- The packet preserves archive-hook deletion gates.
- It preserves terminal receipt distinctions and tab-scoped browser refs.
- It also preserves untrusted page content.
- It preserves publishing permission denials and explicit authorization requirements.

#### Sensitive Scenarios Have Clear Requirements <a id="c-sensitive-scenarios-have-clear-requirements"></a>

- Mutating, authenticated, publishing, terminal and browser scenarios require operator authorization.
- They also require disposable targets.

#### Promotion Controls Routing Status <a id="c-promotion-controls-routing-status"></a>

- Ordinary packet creation does not promote the compiled-routing activation manifest.
- The registry and legacy router remain the source of truth.
- Until a separately authorized promotion refreshes it, the hub status may report legacy authority with a stale-manifest cause.
