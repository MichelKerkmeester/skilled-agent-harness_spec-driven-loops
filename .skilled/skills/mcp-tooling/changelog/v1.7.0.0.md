# v1.7.0.0 - Orca CLI workflow bridge

**Released:** 2026-09-19

The hub adds `mcp-orca-cli`, a workflow packet for Orca-managed worktrees, repositories, terminals, handoffs, automations, artifacts, skill sharing, comments, and embedded browser state.

## Why

Orca owns state that ordinary Git, shell, and browser tools cannot observe. Its public skill is a discovery stub whose flags are supplied by the installed Orca version, so the packet resolves one executable and loads the matching `orca-cli` guide before relying on command details. The inspected 1.4.205 command registry exposed no native Orca MCP command; the new member therefore remains CLI-only rather than inventing a Code Mode manual.

## What Changed

- Added the nested `mcp-orca-cli` workflow packet with its runtime contract, README, operator installation guide, version-matched command reference, session/runtime reference, mutation and browser boundaries, troubleshooting reference, manual safety matrix, and leaf changelog.
- Added the `mcp-orca-cli` registry entry with `packetKind: workflow`, `backendKind: cli-only`, explicit workspace mutation posture, narrow multi-word aliases, and metadata advisor routing.
- Added the Orca stage-one router signal, vocabulary classes, tie-break entry, and stage-two packet-qualified resources.
- Updated the single hub advisor identity, hub README, root router, description, feature catalog, and hub manual-testing inventory for six workflow modes and four transports.
- Regenerated the hub leaf manifest through the canonical metadata command so all Orca reference leaves are reachable.
- Corrected hub graph vocabulary, causal context, key files, source documents, and packet entities without creating a second advisor identity.

## Safety and Boundaries

Orca is treated as state-changing for worktree, terminal, agent, browser, automation, publishing, authentication, and skill-sharing operations. The packet preserves archive-hook deletion gates, terminal receipt distinctions, tab-scoped browser refs, untrusted page content, publishing permission denials, and explicit authorization requirements. Generic Chrome/CDP work remains with `mcp-chrome-devtools`, generic agentic browser work remains with `mcp-aside-devtools`, and supervised orchestration remains outside this packet.

## Known Limitations

- Command flags remain version-sensitive; the installed guide and command help outrank this packet's representative examples.
- Mutating, authenticated, publishing, terminal, and browser scenarios require operator authorization and disposable targets; unperformed checks must be recorded as `SKIP` with their blocker.
- The compiled-routing activation manifest is not promoted by ordinary packet creation. Until a separately authorized promotion refreshes it, the hub status may report legacy authority with a stale-manifest cause; the registry and legacy router remain the source of truth.
