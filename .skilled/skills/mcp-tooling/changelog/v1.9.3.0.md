# v1.9.3.0, Routing Rules Move to ROUTER.md

The routing rules for mcp-tooling moved out of SKILL.md. They now sit in a final MACHINE ROUTER section of ROUTER.md. That section holds the two-axis model and the routing rule. It also holds the outcomes and the surface router. SKILL.md stays short. The move leaves the hub's routes as they were.

&nbsp;

## What's New at a Glance

- SKILL.md keeps a single pointer.
  - SKILL.md no longer carries a MACHINE ROUTER section.
  - Its SMART ROUTING section ends with one line.
  - That line points to ROUTER.md.
- The move changed no route.
  - The map from intent to files is byte for byte the same.
  - Every route the hub selects matches the run before the move.
  - The compiled admission check gives the same result.
- The compiled activation manifest was regenerated.
  - Its sources changed.
  - So the manifest was rebuilt from the new files.
- The hub meets the routing-shape canon.
  - Its known-debt entry is removed.
  - So the hub no longer needs an exception in that check.
- Hub router pointers name `ROUTER.md`.
  - The README and the defer checklist now describe where the machine router actually lives.
  - So do two feature-catalog role tables.
- Two aliases stop steering requests to the wrong mode.
  - "screen examples" no longer scores `mcp-mobbin`.
  - So a request that names neither Refero nor Mobbin defers between the two research transports.
  - That is what the hub contract says.
  - "extract design.md" no longer scores `mcp-figma`.
  - So a DESIGN.md request that names no Figma file reaches `sk-design`.
  - A new primary scenario gives `mcp-notion` the routing gold it lacked.
  - The bare tool-bridge scenario now says it tests the hub's own routing.

No action is needed.
