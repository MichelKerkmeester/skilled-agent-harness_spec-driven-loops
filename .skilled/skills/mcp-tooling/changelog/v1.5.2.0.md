The mcp-tooling hub now gives its root router the declarations needed to identify its routing role and its own entry point.

## Why This Release

The pilot `ROUTER.md` shipped its machine-readable block and prose correctly, but it predated the final frontmatter schema. Completing the declaration was the golden checkpoint's only delta. No routing policy bytes moved.

## What's New at a Glance

- **The root router declares the two-state contract.** `router_state: active` identifies the hub's ownership of second-stage leaf selection. `skill_pointer: SKILL.md` identifies the hub's root `SKILL.md` as its resolvable entry point. Every class-H parent hub's `ROUTER.md` frontmatter requires these fields plus a four-part `version` in both states.
- **The existing prose and machine-readable block are unchanged.** `INTENT_SIGNALS` / `RESOURCE_MAP` remains byte-identical to the frozen baseline with sha256 `8477b664…`, so replay and benchmark behavior is unchanged.
- **The router and hub references align to their release versions.** `ROUTER.md` moves from v1.1.0.0 to v1.1.1.0. The `SKILL.md` version moves from v1.5.1.0 to v1.5.2.0. The `README.md` and `description.json` versions also move from v1.5.1.0 to v1.5.2.0.
- **The default resource already points to the root router.** The unchanged `hub-router.json` has a `defaultResource` that already points at `ROUTER.md`.

## Upgrade

No migration required. Stage-one and stage-two routing semantics are unchanged.
