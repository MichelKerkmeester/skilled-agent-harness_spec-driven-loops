# v1.2.14.0, A First-Use Readiness Check Before the First Write

A new user has to approve the ClickUp MCP once in the browser. A doc page push also needs ClickUp logged in. That login must be in the browser the divider gap pass uses. The agent can do neither. Before this release it found out only when a write failed halfway.

&nbsp;

## What's New at a Glance

- The check runs once per session.
  - `references/mcp-tools.md` section 3, "First-Use Readiness Check", has a Code Mode program.
  - It tests the MCP with a cheap read.
  - It tests the browser with a ClickUp page in a background tab.
  - Aside comes first and Chrome's live manual second.
- Each missing piece has its question.
  - The user gets one structured question per missing login.
  - It gives the exact words to use.
  - The agent waits, rechecks and stops after two tries.
- First use is measured, not assumed.
  - Before the OAuth approval the ClickUp manual has no tools.
  - An approval counts only while a connection waits for it.
  - So the agent warns the user first and then registers the manual.
  - After one approval a reconnect needs no new tab.
- A dropped Aside connection repairs itself.
  - `Error: Not connected` means the `aside` manual is registered again.
  - No question is asked.
- The contract names it.
  - `SKILL.md` section 1 says to run the check before the first write.
  - The setup route now also fires on "log in to clickup", "clickup login" and "oauth".
