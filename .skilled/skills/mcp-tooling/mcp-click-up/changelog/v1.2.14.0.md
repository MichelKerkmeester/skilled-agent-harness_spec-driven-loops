# v1.2.14.0, A First-Use Readiness Check Before the First Write

A new user has to approve the ClickUp MCP once in the browser, and a doc page push also needs ClickUp logged in, in the browser the divider gap pass uses. The agent can do neither, and before this release it found out only when a write failed halfway.

> Spec folder: `specs/mcp-tooling/026-clickup-doc-divider-spacing` (Level 1)

&nbsp;

## What's New at a Glance

- **The check runs once per session.** `references/mcp-tools.md` section 3, "First-Use Readiness Check", has a Code Mode program that tests the MCP with a cheap read and tests the browser with a ClickUp page in a background tab, Aside first and Chrome's live manual second.
- **Each missing piece has its question.** The user gets one structured question per missing login, with the exact words to use, and the agent waits, rechecks and stops after two tries.
- **First use is measured, not assumed.** Before the OAuth approval the ClickUp manual has no tools, and an approval counts only while a connection waits for it, so the agent warns the user first and then registers the manual. After one approval a reconnect needs no new tab.
- **A dropped Aside connection repairs itself.** `Error: Not connected` means the `aside` manual is registered again, with no question.
- **The contract names it.** `SKILL.md` section 1 says to run the check before the first write, and the setup route now also fires on "log in to clickup", "clickup login" and "oauth".
