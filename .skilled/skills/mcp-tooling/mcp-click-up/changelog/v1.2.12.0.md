# v1.2.12.0, The Gap Pass Runs in Your Own Browser in the Background

The editor pass that removes the empty line under each divider ran in an isolated Chrome DevTools browser, so ClickUp asked for a login on every run. It now runs in a browser the user is already logged in to, and it leaves their view alone.

> Spec folder: `specs/mcp-tooling/026-clickup-doc-divider-spacing`

&nbsp;

## What's New at a Glance

- **Aside first.** `references/mcp-tools.md` section 8 has an Aside program that runs the import check, the editor pass and the text-unchanged proof through `aside.aside_repl`. Its tab opens in the background, so the user's active tab stays in view. Run live on four scratch pages: every gap removed, text unchanged, no login prompt, the user's active tabs the same before and after.
- **Chrome as the fallback.** The Chrome program now uses `chrome_devtools_live` from `mcp-chrome-devtools` v1.0.21.0, which attaches to the user's own Chrome. It opens a background tab and closes only that tab. Run live on two scratch pages with the same result.
- **A late login redirect is caught.** ClickUp can send a page to its login screen after the editor check. Both programs now retry a page that shows no editor and look for the login screen once more, and the report carries `editor`. Before, such a page read as done with `login: false`.

&nbsp;

## Upgrade

No migration required. Add the `chrome_devtools_live` manual if you want the Chrome fallback.
