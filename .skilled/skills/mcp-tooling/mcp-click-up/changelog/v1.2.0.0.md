# The MCP Docs Match the Live Server

The skill's MCP guidance was written for a ClickUp server that no longer exists, so many of the calls it taught failed with "tool not found". This release rebuilds that guidance from the 61 tools ClickUp's hosted server registered on 2026-10-08, and an agent following it now makes calls that work.

&nbsp;

## What's New at a Glance

- **Every MCP call name works.** Names keep the inner `clickup_`, as in `clickup_official.clickup_official_clickup_create_task`, and every parameter comes from the server's own schema.
- **Features with no tool are named as such.** Goals, bulk create or update, webhooks, checklist edits, spaces, views, templates, guests, user groups and audit logs have no route, and the skill now tells the user so instead of sending them to a call that fails.
- **Each of the 61 tools has its own feature card.** The 35 cards for tools that are gone were retired.
- **Task and document calls use the right fields.** Task text goes in `markdown_description`, and new documents take a `parent`, a `visibility` and a `create_page` choice. Pages are read and written one at a time with `content_format: "text/md"`.
- **Requests cupt cannot serve now route to the MCP.** Creating, moving or merging a task, adding a subtask, searching and documents used to land on cupt whenever the request also said "list" or "show".
- **Setup requests load the install guide.** The router never found `INSTALL-GUIDE.md` because it sits at the packet root, so setup questions got only the troubleshooting reference. Three docs that pointed at a nonexistent `references/INSTALL-GUIDE.md` now point at the real file.
- **The install script prints the working setup.** It now prints the `clickup_official` manual that reaches the hosted server through `mcp-remote` and signs in with a browser approval, with no API key.

&nbsp;

## Upgrade

Replace an old `clickup` Code Mode manual with the one `scripts/install.sh --mcp-only` prints, then approve the ClickUp sign-in once in the browser.
