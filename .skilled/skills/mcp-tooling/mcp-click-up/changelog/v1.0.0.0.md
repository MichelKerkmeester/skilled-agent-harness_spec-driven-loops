# mcp-click-up v1.0.0.0: Initial Release

The `mcp-click-up` skill brings together ClickUp routing guidance, setup instructions, references, troubleshooting and practical workflows.

## Why This Release

This initial release adds the `mcp-click-up` skill.

## What's New at a Glance

- **`SKILL.md` defines an eight-section skill.** Its routing pseudocode organizes ClickUp work by operation.
- **The skill presents two ClickUp paths.** cupt is primary and the official MCP is secondary.
- **`scripts/install.sh` verifies the cupt installation.** It runs `cupt --version` for the check and offers `--check-only` and `--mcp-only`.
- **`INSTALL-GUIDE.md` provides step-by-step setup.** It includes validation checkpoints.
- **The release includes three reference guides.** They cover cupt commands, MCP tools and troubleshooting.
- **The manual testing playbook covers cupt lifecycle and recovery.** Its phases also include task operations, time and notes and MCP advanced work.
- **`examples/task-queue-workflow.sh` processes a tagged work queue.** It offers `--dry-run` and `--tag` flags.
- **`examples/time-tracking-workflow.sh` is for timer management.** Its subcommands are `start`, `stop`, `log` and `status`.
- **cupt and the official MCP have usage constraints.** The notes cover team filtering, an MCP runtime requirement and cupt maintenance.

## The ClickUp Skill

#### Route Work by Operation

`SKILL.md` Section 1 lists activation triggers and anti-patterns, including `NOT @krodak/clickup-cli`. Section 2 provides `INTENT_SIGNALS` scoring, a `RESOURCE_MAP` and `route_clickup_resources()` pseudocode. cupt and the official ClickUp MCP cover different ClickUp surfaces, which is the reason for operation-based routing.

Section 3 compares the cupt CLI path with the official ClickUp MCP path in a table. Section 4 lists agent invariants for status resolution, dry-run, `--json` and empty-queue handling. Sections 5-8 cover success criteria, integration, quick reference and related resources.

&nbsp;

#### Choose Between Paths

cupt is a Python CLI installed with `pipx install cupt`. The stated reasons for making it primary are its agent-focused design, dry-run, `--offline` support and bundled `SKILL.md`. The ClickUp team maintains the official MCP, which provides 46 tools.

## Setup and References

#### Install cupt

The install script detects Python 3.8+ and installs cupt via pipx (preferred) or pip (fallback). pipx is preferred for isolation and to avoid system contamination.

It prints a read-only official ClickUp MCP configuration JSON snippet without writing files or auto-modifying `opencode.json`.

&nbsp;

#### Follow the Setup Guide

An AI-first install block appears at the top of `INSTALL-GUIDE.md`. Section 1 covers cupt installation and authentication, while Section 2 covers official MCP configuration.

Section 3 provides a verification checklist, followed by a Quick Reference Card.

&nbsp;

#### Find cupt Commands

`references/cupt-commands.md` is the complete cupt CLI reference, covering all command groups: `auth`, `list`, `show`, `done`, `note`, `time`, `tag`, `attach` and `workspace`. Every read command has a `--json` variant.

Its code examples show agent invariants for status resolution, empty queue and per-task status in loops.

&nbsp;

#### Use Official MCP Tools

`references/mcp-tools.md` describes the official ClickUp MCP's 46 tools and includes a HIGH/MEDIUM/LOW priority table. It gives Code Mode `call_tool_chain()` invocation patterns and covers document operations, goal management, bulk creation, webhook examples and error handling patterns.

&nbsp;

#### Diagnose Common Errors

`references/troubleshooting.md` starts with a quick diagnostics sequence. It covers installation issues such as cupt not found and Python version problems, authentication issues such as 401 and expired tokens, status resolution errors, team filter performance, MCP connection issues, PATH conflicts between `cu` and `cupt` and empty result handling.

## Manual Testing Playbook

#### Cover the Main Workflows

The playbook has five phases:

- **Phase 01: cupt Lifecycle.** Install, auth, status and config.
- **Phase 02: Task Operations.** List, show, statuses and done.
- **Phase 03: Time and Notes.** Timer, manual log and comments.
- **Phase 04: MCP Advanced.** Documents and goals.
- **Phase 05: Recovery and Failure.** Auth fail, empty queue and status error.

## Known Limitations

#### Account for Tool Constraints

The cupt team filter runs client-side and is slow on large workspaces, so combine it with `--tag`. The official MCP requires Node.js/npx for `@clickup/mcp-server`.

cupt is a community tool. Future maintenance depends on its author.
