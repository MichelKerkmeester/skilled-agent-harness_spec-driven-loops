## The ClickUp Skill

The `SKILL.md` file defines an eight-section skill for ClickUp work. Its routing pseudocode organizes work by operation.

#### Route Work by Operation <a id="c-route-work-by-operation"></a>

- `SKILL.md` Section 1 lists activation triggers and anti-patterns.
- These include `NOT @krodak/clickup-cli`.
- Section 2 provides `INTENT_SIGNALS` scoring, a `RESOURCE_MAP` and `route_clickup_resources()` pseudocode.
- cupt and the official ClickUp MCP cover different ClickUp surfaces.
- That is why routing works by operation.
- Section 3 compares the cupt CLI path with the official ClickUp MCP path in a table.
- Section 4 lists agent invariants for status resolution, dry-run, `--json` and empty-queue handling.
- Sections 5-8 cover success criteria, integration, quick reference and related resources.

#### Choose Between Paths <a id="c-choose-between-paths"></a>

- cupt is a Python CLI installed with `pipx install cupt`.
- The stated reasons for making it primary are its agent-focused design, dry-run, `--offline` support and bundled `SKILL.md`.
- The ClickUp team maintains the official MCP, which provides 46 tools.

## Setup and References

Setup uses an install script and a step-by-step guide. Three reference guides cover cupt commands, MCP tools and troubleshooting.

#### Install cupt <a id="c-install-cupt"></a>

- `scripts/install.sh` verifies the cupt installation.
- It runs `cupt --version` for the check.
- It offers `--check-only` and `--mcp-only`.
- It detects Python 3.8+ and installs cupt via pipx (preferred) or pip (fallback).
- pipx is preferred for isolation and to avoid system contamination.
- It prints a read-only official ClickUp MCP configuration JSON snippet.
- It writes no files and does not auto-modify `opencode.json`.

#### Follow the Setup Guide <a id="c-follow-the-setup-guide"></a>

- An AI-first install block appears at the top of `INSTALL-GUIDE.md`.
- Section 1 covers cupt installation and authentication.
- Section 2 covers official MCP configuration.
- Section 3 provides a verification checklist, followed by a Quick Reference Card.
- The guide includes validation checkpoints.

#### Find cupt Commands <a id="c-find-cupt-commands"></a>

- `references/cupt-commands.md` is the complete cupt CLI reference.
- It covers all command groups: `auth`, `list`, `show`, `done`, `note`, `time`, `tag`, `attach` and `workspace`.
- Every read command has a `--json` variant.
- Its code examples show agent invariants for status resolution, empty queue and per-task status in loops.

#### Use Official MCP Tools <a id="c-use-official-mcp-tools"></a>

- `references/mcp-tools.md` describes the official ClickUp MCP's 46 tools.
- It includes a HIGH/MEDIUM/LOW priority table.
- It gives Code Mode `call_tool_chain()` invocation patterns.
- It also covers document operations, goal management, bulk creation, webhook examples and error handling patterns.

#### Diagnose Common Errors <a id="c-diagnose-common-errors"></a>

- `references/troubleshooting.md` starts with a quick diagnostics sequence.
- It covers installation issues such as cupt not found and Python version problems.
- It covers authentication issues such as 401 and expired tokens.
- It also covers status resolution errors, team filter performance and MCP connection issues.
- It covers PATH conflicts between `cu` and `cupt` and empty result handling.

## Workflow Examples

Two example scripts show queue processing and timer management.

#### Process a Tagged Queue <a id="c-process-a-tagged-queue"></a>

- `examples/task-queue-workflow.sh` processes a tagged work queue.
- The workflow runs preflight, fetch, inspect, dry-run, complete and handoff.
- It offers `--dry-run` and `--tag` flags.
- The workflow demonstrates safe batch completion with per-task status verification.

#### Manage Timers <a id="c-manage-timers"></a>

- `examples/time-tracking-workflow.sh` is for timer management.
- Its subcommands are `start`, `stop`, `log` and `status`.
- The workflow validates duration formats such as `1h30m`, `45m` and `2h`.
- It detects orphaned timers on exit.

## How It Was Checked

The playbook has five phases.

#### Cover the Main Workflows <a id="c-cover-the-main-workflows"></a>

- Phase 01: cupt Lifecycle. Install, auth, status and config.
- Phase 02: Task Operations. List, show, statuses and done.
- Phase 03: Time and Notes. Timer, manual log and comments.
- Phase 04: MCP Advanced. Documents and goals.
- Phase 05: Recovery and Failure. Auth fail, empty queue and status error.

## Known Limitations

The notes cover usage constraints for cupt and the official MCP.

#### Account for Tool Constraints <a id="c-account-for-tool-constraints"></a>

- The cupt team filter runs client-side.
- It is slow on large workspaces, so combine it with `--tag`.
- The official MCP requires Node.js/npx for `@clickup/mcp-server`.
- cupt is a community tool.
- Future maintenance depends on its author.
