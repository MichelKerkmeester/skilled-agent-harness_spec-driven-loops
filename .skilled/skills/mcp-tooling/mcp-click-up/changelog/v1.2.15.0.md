# v1.2.15.0, The Programs Close Only Their Own Tab and the Catalog Lists 67 Tools

An alignment review covered the last three releases. It found two ways the browser programs could leave or close the wrong tab. It also found docs that still described the server and the login order from before them.

&nbsp;

## What's New at a Glance

- A failed check no longer leaves a tab open.
  - Both browser branches of the readiness check close their tab in a `finally` block.
  - So a slow or redirecting page cannot leave one behind in Aside or the user's Chrome.
- The Chrome gap pass closes its own page, not the user's.
  - The Chrome gap pass records the page ID that appears after `new_page`.
  - The Chrome gap pass selects that ID before each navigation and closes only it.
  - The Chrome gap pass used to match the first tab whose URL fit.
  - That was the user's own tab whenever they had the same page open.
- The check covers MCP writes only.
  - A `cupt` write signs in with its own API token.
  - So a `cupt` write needs neither part of the check.
- The catalog lists all 67 tools.
  - Six tools the server added since 2026-10-08 have cards.
  - The six tools are `clickup_create_space_tag`, `clickup_get_list_location`, `clickup_get_user`, `clickup_update_chat_message`, `clickup_react_to_chat_message` and `clickup_delete_chat_message`.
  - The inventory in `references/mcp-tools.md` and every count now read 67.
- The playbook tests the new flows.
  - MCP-M019 covers the readiness check.
  - MCP-M020 covers the divider gap pass in a background tab.
- The README gives the approval order that works.
  - The README points to the readiness check.
  - There the approval happens while the registration waits.
- Changelog spec lines carry the path only.
  - Twelve older entries dropped their level label.
  - So every entry passes the changelog shape check.
