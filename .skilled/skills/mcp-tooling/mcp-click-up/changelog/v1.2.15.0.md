# v1.2.15.0, The Programs Close Only Their Own Tab and the Catalog Lists 67 Tools

An alignment review of the last three releases found two ways the browser programs could leave or close the wrong tab, and docs that still described the server and the login order from before them.

> Spec folder: `specs/mcp-tooling/026-clickup-doc-divider-spacing`

&nbsp;

## What's New at a Glance

- **A failed check no longer leaves a tab open.** Both browser branches of the readiness check close their tab in a `finally` block, so a slow or redirecting page cannot leave one behind in Aside or the user's Chrome.
- **The Chrome gap pass closes its own page, not the user's.** It records the page ID that appears after `new_page`, selects that ID before each navigation and closes only it. It used to match the first tab whose URL fit, which was the user's own tab whenever they had the same page open.
- **The check covers MCP writes only.** A `cupt` write signs in with its own API token, so it needs neither part of the check.
- **The catalog lists all 67 tools.** Six tools the server added since 2026-10-08 have cards: `clickup_create_space_tag`, `clickup_get_list_location`, `clickup_get_user`, `clickup_update_chat_message`, `clickup_react_to_chat_message` and `clickup_delete_chat_message`. The inventory in `references/mcp-tools.md` and every count now read 67.
- **The playbook tests the new flows.** MCP-M019 covers the readiness check and MCP-M020 the divider gap pass in a background tab.
- **The README gives the approval order that works.** It points to the readiness check, where the approval happens while the registration waits.
- **Changelog spec lines carry the path only.** Twelve older entries dropped their level label, so every entry passes the changelog shape check.
