# v1.0.1.0, Top-Level Install Guide

mcp-click-up v1.0.1.0 makes its install guidance available from a top-level entry point.

&nbsp;

## What's New at a Glance

- A top-level `INSTALL-GUIDE.md` adds an install front door at the packet root.
  - It brings mcp-click-up to install-guide parity with the sibling packets.
  - Those packets are `mcp-chrome-devtools/INSTALL-GUIDE.md` and `mcp-figma/INSTALL-GUIDE.md`.
  - The sibling packets already carry a top-level guide.
  - It promotes and reorganizes the content of `references/INSTALL-GUIDE.md`.
  - That content covers an AI-first install block, a component overview and architecture.
  - It also covers prerequisites + cupt install.
  - Authentication (token and OAuth) is covered too.
  - So is optional Code Mode MCP configuration.
  - The list also covers verification, troubleshooting and a resources table.
  - No content was invented.
  - Every command and configuration block derives from `references/INSTALL-GUIDE.md`, `SKILL.md` and the mcp-servers READMEs.
- The reference now ends with a short pointer note to the new front door.
  - It keeps its FULL content.
  - It remains the smart router's INSTALL-intent target (`SKILL.md §2 RESOURCE_MAP`).
  - All existing inbound links keep resolving to the same step-by-step guide they describe.
  - Those links come from `SKILL.md`, `README.md`, `examples/README.md`, `mcp-servers/clickup-cli/README.md`, `mcp-servers/clickup-mcp/README.md`, `scripts/doctor.sh` and `references/mcp-tools.md`.
  - The front door links back into the reference for the phase-by-phase validation ladder.

&nbsp;

## Upgrade

No migration required. This is a documentation-only change. It does not change the install path, script or routing behavior.
