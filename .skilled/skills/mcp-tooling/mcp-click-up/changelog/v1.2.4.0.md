# v1.2.4.0, Standards Alignment and Example Fixes

v1.2.4.0 aligns the packet with the skill packet rules and the code standards. It corrects README claims that no longer matched the tree or the scripts. It also fixes the two example scripts. cupt exits 0 even when the API rejects a call. So both examples passed their auth preflight on an invalid token. So they reported success for writes that failed.

&nbsp;

## What's New at a Glance

- `SKILL.md` carries a `<!-- Keywords: ... -->` comment.
  - It holds comma-separated phrases a user would type.
  - The old comment was lowercase and space-separated.
  - So the advisor read it as one long keyword.
- Every shell script opens with a COMPONENT header.
  - It documents its usage and exit codes.
  - Error lines from `install.sh` and the two example scripts now go to stderr.
  - `doctor.sh` drops an unused helper and an `A && B || C` shortcut.
  - So shellcheck reports nothing across the packet.
- The READMEs now give the real `cupt --version` format.
  - They give the right line numbers for the example settings.
  - They give the real `cupt time status` message.
  - They no longer claim that the example scripts stop orphaned timers.
  - They no longer claim that `install.sh` reads `requirements.txt`.
  - They no longer claim that the MCP reference has priority tiers.
  - They no longer claim that the MCP is the only route for time tracking.
  - The MCP server README reports the 61 tools seen on 2026-10-08 instead of an older empty result.
- A bad token passed the preflight.
  - cupt prints `ERROR: ... HTTP 401` on stderr and still exits 0.
  - Both example scripts now run cupt through a `cupt_checked` helper.
  - That helper fails a step when stderr carries an `ERROR:` line.
  - So an invalid token stops the run with exit 1.
- `task-queue-workflow.sh --dry-run` used `--dry-run` as the tag.
  - Arguments are now parsed in one loop.
  - A bare first argument still sets the tag.
  - An unknown option exits 1.
  - So does a `--tag` without a value.
- An empty queue exited 5, not 0.
  - The queue was fetched inside `$(...)`.
  - So the empty-queue exit only left the subshell.
  - The log lines landed in the JSON.
  - The fetch now runs in the main shell.
  - So an empty queue exits 0 as the READMEs say.
- A failed completion counted as done.
  - `complete_task` ran inside an `if`, where `set -e` does not apply.
  - So a failed `cupt done` still printed success.
  - `complete_task` now returns the failure.
  - A failed handoff counts as failed too.
  - The run exits 1 when any task failed.
- A stray temp file.
  - The script no longer writes `/tmp/cupt_task_detail.json`.
  - Nothing read that file.
  - Each task's detail prints with `cupt show --notes`.
- `time-tracking-workflow.sh` reported success on failure. `start`, `stop` and `log` now exit 1 when cupt reports an error.
- Paths that broke in a vendored copy.
  - The scripts find `install.sh` relative to their own folder.
  - The install output names packet-relative paths.
  - The READMEs say to run from the packet root.
- `SKILL.md` says to read `cupt status` output rather than its exit code.
  - It says an empty `cupt list` with an `ERROR:` line is a failed call.
  - An empty `cupt list` with an `ERROR:` line is not an empty queue.
