# v1.2.4.0, Standards Alignment and Example Fixes

v1.2.4.0 aligns the packet with the skill packet rules and the code standards, and corrects README claims that no longer matched the tree or the scripts. It also fixes the two example scripts. cupt exits 0 even when the API rejects a call, so both examples passed their auth preflight on an invalid token and reported success for writes that failed.

&nbsp;

## What's New at a Glance

- `SKILL.md` carries a `<!-- Keywords: ... -->` comment with comma-separated phrases a user would type. The old comment was lowercase and space-separated, so the advisor read it as one long keyword.
- Every shell script opens with a COMPONENT header that documents its usage and exit codes. Error lines from `install.sh` and the two example scripts now go to stderr. `doctor.sh` drops an unused helper and an `A && B || C` shortcut, so shellcheck reports nothing across the packet.
- The READMEs now give the real `cupt --version` format, the right line numbers for the example settings and the real `cupt time status` message. They no longer claim that the example scripts stop orphaned timers, that `install.sh` reads `requirements.txt`, that the MCP reference has priority tiers or that the MCP is the only route for time tracking. The MCP server README reports the 61 tools seen on 2026-10-08 instead of an older empty result.

&nbsp;

## Fixed

- **A bad token passed the preflight.** cupt prints `ERROR: ... HTTP 401` on stderr and still exits 0. Both example scripts now run cupt through a `cupt_checked` helper that fails a step when stderr carries an `ERROR:` line, so an invalid token stops the run with exit 1.
- **`task-queue-workflow.sh --dry-run` used `--dry-run` as the tag.** Arguments are now parsed in one loop. A bare first argument still sets the tag, an unknown option or a `--tag` without a value exits 1.
- **An empty queue exited 5, not 0.** The queue was fetched inside `$(...)`, so the empty-queue exit only left the subshell and the log lines landed in the JSON. The fetch now runs in the main shell, so an empty queue exits 0 as the READMEs say.
- **A failed completion counted as done.** `complete_task` ran inside an `if`, where `set -e` does not apply, so a failed `cupt done` still printed success. It now returns the failure, a failed handoff counts as failed too and the run exits 1 when any task failed.
- **A stray temp file.** The script no longer writes `/tmp/cupt_task_detail.json`, which nothing read. Each task's detail prints with `cupt show --notes`.
- **`time-tracking-workflow.sh` reported success on failure.** `start`, `stop` and `log` now exit 1 when cupt reports an error.
- **Paths that broke in a vendored copy.** The scripts find `install.sh` relative to their own folder, the install output names packet-relative paths and the READMEs say to run from the packet root.
- `SKILL.md` says to read `cupt status` output rather than its exit code, and that an empty `cupt list` with an `ERROR:` line is a failed call, not an empty queue.
