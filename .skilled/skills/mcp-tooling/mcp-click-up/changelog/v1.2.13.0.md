# v1.2.13.0, Long Pages Finish and a Clean Page Reads Clean

On a page with 74 dividers, the Aside editor pass ran as one REPL call and passed Code Mode's 30-second limit per tool call. The pass kept going inside Aside and removed the gaps, but the program lost its report. Each call now stops after about 12 seconds of work and keeps its tab for the next call.

The same runs showed `gapsLeft: 1` on pages whose dividers were all tight, because the plain-text count also catches an image at the end of a block. Step 4 would then call a clean page undelivered.

> Spec folder: `specs/mcp-tooling/026-clickup-doc-divider-spacing`

&nbsp;

## What's New at a Glance

- **Long pages finish with a report.** The Aside program in `references/mcp-tools.md` section 8 calls the pass again until it reports `done`, and the report carries `calls`.
- **A clean page reads clean.** Both programs take `gapsLeft` from the editor, which counts only dividers, and report the plain-text count as `plainHits`. A page with an image now reports `gapsLeft: 0`, `plainHits: 1`.
- **One tab per page.** The tab lives in the REPL between calls and closes when the page is done.
- **Tested hidden.** Runs with Aside minimized and in the background removed every gap on pages with 1 to 74 dividers, with the text unchanged and the user's active tabs unchanged.

&nbsp;

## Upgrade

No migration required. Give the `call_tool_chain` call a `timeout` of about 60 seconds per page.
