# v1.2.16.0, The Chrome Gap Pass Says What Was Verified and the Approval Steps Name Their Timing

A review of v1.2.15.0 found one claim that outran its evidence and four places that still gave the approval steps from before the readiness check.

> Spec folder: `specs/mcp-tooling/026-clickup-doc-divider-spacing`

&nbsp;

## What's New at a Glance

- **The Chrome gap pass no longer claims a live run it did not have.** `references/mcp-tools.md` section 8 said the program as written closed only its own tab on two scratch pages. That run used the earlier version, which found its tab by URL. The note now says so, and it names the `chrome-devtools-mcp` 0.26.0 behavior the page-ID tracking relies on.
- **The readiness check names MCP writes.** Section 3 said the check runs before the first ClickUp write, while `SKILL.md` says the first ClickUp MCP write. Both now say MCP write, because a `cupt` write signs in with its own token.
- **The install guide and server notes give the approval timing.** `INSTALL-GUIDE.md` sections 4 and 6 and `mcp-servers/clickup-mcp/README.md` step 1 said to approve OAuth again. They now point to the readiness check, because an approval given after the registration's one-minute timeout saves no token.
- **The readiness scenario can open its approval tab.** MCP-M019 deregistered the manual only, so mcp-remote reconnected from its stored token and no tab opened. It now starts with `~/.mcp-auth` renamed, and its skip step closes the browsers so the skip question appears.
