# v1.2.6.0, Routing Summary Up Front

The routing section of this packet opened with a loading-level block. Then came a twenty-row operation-to-tool table and two hundred lines of pseudocode. A reader seeking where a request lands had to walk it all first. The section now says in a few sentences what selects this packet. It names which two reference files load first. It says where the routing detail lives. The loading levels, the operation-to-tool map and the pseudocode moved. Not a word changed.

&nbsp;

## What's New at a Glance

- The routing section reads as a summary.
  - Five sentences name the hub signal and the CLI and MCP split.
  - The five sentences also name two first reference leaves.
  - The five sentences name the markdown contract that binds before a write.
- The routing detail is unchanged, one section down.
  - The loading levels, the operation-to-tool table and the router pseudocode keep their headings.
  - The loading levels, the operation-to-tool table and the router pseudocode keep their order and every byte.
  - The loading levels, the operation-to-tool table and the router pseudocode sit in a final MACHINE ROUTER section.
- Routing behaves exactly as before.
  - Every intent signal, resource map entry and operation row kept its old value.
  - So the same request loads the same files.
