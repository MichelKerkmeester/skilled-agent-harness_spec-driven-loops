# v1.0.21.0, A Live Manual for Signed-In Work

Both Chrome DevTools manuals run with `--isolated=true`, so every run starts logged out. That is right for testing and wrong for work that needs a login, such as the ClickUp editor pass. A saved profile does not fix it for ClickUp, which keeps its login only for the browser session. The new `chrome_devtools_live` manual attaches to the Chrome the user already has open instead.

> Spec folder: `specs/mcp-tooling/026-clickup-doc-divider-spacing`

&nbsp;

## What's New at a Glance

- **`chrome_devtools_live` uses the user's Chrome.** It runs `chrome-devtools-mcp --autoConnect`, after the user turns on remote debugging once at `chrome://inspect/#remote-debugging`.
- **It stays out of the user's way.** `SKILL.md` section 3 says to open pages with `new_page({ url, background: true })` and close only those, so the user's view never changes.
- **The isolated manuals are unchanged.** `chrome_devtools_1` and `chrome_devtools_2` stay the default for every other task.

&nbsp;

## Upgrade

Add the `chrome_devtools_live` entry from `assets/utcp-chrome-devtools-manuals.md` to your `.utcp_config.json` if you need signed-in work, and turn on remote debugging in Chrome once.
