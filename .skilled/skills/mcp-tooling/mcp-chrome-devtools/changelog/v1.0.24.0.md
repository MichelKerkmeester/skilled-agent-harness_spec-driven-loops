# v1.0.24.0, Captures Stay Out of the Repository

A HAR file, a cookie dump or a screenshot of a logged-in page can hold live session cookies and bearer tokens. The packet had no rule for them. Its recipes wrote them to the folder you had open, and that folder can be a public repository.

> Spec folder: `AI Systems/Product Owner/specs/system/030-system-review-and-vendor-sync`

&nbsp;

## What's New at a Glance

- **A rule for captures.** `SKILL.md` ALWAYS rule 7 covers HAR files, cookie dumps, traces, heap snapshots and screenshots of logged-in pages. They go to a scratch folder or an ignored path and are never committed. Cookie and authorization values are redacted before any quote.
- **The recipes follow the rule.** `references/cdp-patterns.md`, `references/session-management.md`, `references/troubleshooting.md` and `INSTALL-GUIDE.md` write under `"${TMPDIR:-/tmp}"`. The cookie recipes print names and domains, not values.
- **No token-looking cookie values.** The cookie examples use `<throwaway-value>` where they had `secret-token-123` and similar. The storage example reads `theme`, not `token`.
- **The example scripts write outside the repository.** `performance-baseline.sh`, `animation-testing.sh` and `multi-viewport-test.sh` default to a folder under the temp directory. Both READMEs say so.
- **The catalog and playbook agree.** The HAR, cookie, screenshot, eval and baseline entries carry the rule. So do the HAR and cookie scenarios. The HAR scenario now deletes its file.
- **The manuals banner holds in a vendoring project.** `assets/utcp-chrome-devtools-manuals.md` says the three entries are registered in the Skilled repository. A project that vendors the packet checks its own `.utcp_config.json` and adds only the entries it lacks. `SKILL.md`, `README.md` and the server notes now read the same way.

&nbsp;

## Upgrade

No migration required. The three example scripts now write under the temp folder, so look there for their results.
