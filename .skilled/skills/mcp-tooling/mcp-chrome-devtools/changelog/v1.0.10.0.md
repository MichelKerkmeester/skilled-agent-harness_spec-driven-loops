This update brings mcp-chrome-devtools to full inventory parity with sibling mcp-tooling modes by documenting its CLI and MCP capabilities, registered Code Mode manuals and install pointers. All additions derive from the packet's own existing documentation, with no new tool facts invented.

## What's New at a Glance

- **A feature catalog makes the CLI and MCP capability surface discoverable.** The packet had no `feature-catalog/`, so finding capabilities meant reading `SKILL.md`, the references, examples and playbook end to end. The new `feature-catalog/feature-catalog.md` and 29 per-feature files span seven domains (`cli_bdg_lifecycle` / `protocol_discovery` / `dom_and_screenshot` / `console_and_network` / `mcp_parallel_instances` / `automation_and_performance` / `recovery_and_troubleshooting`) and give agents and operators one inventory naming each capability, its command and where execution truth lives, following the packet's manual-testing-playbook categories and mirroring `mcp-click-up`'s catalog structure and frontmatter.

- **Both registered Code Mode manuals now have a packet-local record.** The dual `chrome_devtools_1` and `chrome_devtools_2` registrations existed only in the repo `.utcp_config.json` and had no packet-local record to verify against. `assets/utcp-chrome-devtools-manuals.md` is a byte-true snapshot of both manual entries with the dual-manual-for-parallelism rationale and a verify-don't-re-add provenance contract, making drift between packet documentation and the live registration detectable so nobody re-adds an already-registered manual.

- **The `mcp-servers/` pointers give install guidance a predictable home.** Sibling `mcp-click-up` and `mcp-figma` packets had `mcp-servers/` pointer folders, while this packet had none. It now has `mcp-servers/bdg-cli/README.md`, an install pointer per `INSTALL-GUIDE.md` with nothing vendored and `mcp-servers/chrome-devtools-mcp/README.md` for the Code Mode server behind the manuals, matching the hub-wide embedded-server layout and giving install and verification questions one predictable home.

## Upgrade

No migration required. This is inventory documentation only. It changes no runtime behavior, routing logic or `.utcp_config.json` state.
