# v1.1.5.0, Routing Detail Moves to a MACHINE ROUTER Section

The routing section carried a lot of detail. It held the detection signals, the phase order and the resource inventory. It also held the loading table and the scoring pseudocode. A reader met all of that before reaching how the transport works. That detail now sits unchanged in a final MACHINE ROUTER section. The summary states the signal that selects the packet. It also states the resource that packet loads first.

&nbsp;

## What's New at a Glance

- **The summary names what selects this packet.** That is the hub's `mcp-refero` mode signal. It also covers the request shapes that fire it. It also names the default resource. That resource only ever appears as a fallback suggestion.
- **The moved detail serves the same routes.** The detection signals and the phase order are byte-identical. So are the resource domains, the loading levels and the intent-scoring pseudocode.
- **Resource discovery prose now points at its one home.** One sentence describes the shared helper bodies. It links to `shared-smart-router.md` instead of restating them.
- **Nothing routes differently.** The same five intents apply. So do the same resource map and the same fallback behaviour.

No migration required.
