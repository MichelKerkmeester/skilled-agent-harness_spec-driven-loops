# v1.0.0.0, Refero Evidence for Design Work

The first release brings Refero design-reference research into the `mcp-tooling` hub. It arrives through `mcp-refero`. The package holds the live-discovered tool contract. It also holds examples, catalogs, tests, diagnostics and template-conformant documentation.

## Why This Release

The transport uses the registered Refero MCP manual and Code Mode. It searches real shipped UI styles, screens and flows. It supplies cited references to `sk-design`. `sk-design` is its mandatory judgment partner. Refero provides evidence, not design authority.

## What's New at a Glance

- **`mcp-refero` is a read-only transport in `mcp-tooling`.** Its metadata sets `packetKind: transport` and `mutatesWorkspace: false`.
- **`SKILL.md` defines the guarded five-intent router.** It also specifies discovery-first execution.
- **The packet documented eight read-only tools across three layers.** They cover styles, screens and flows.
- **The 2026-07-16 fixture confirmed the doubled Refero tool names.** It also confirmed their TypeScript callable form.
- **The live schema confirmed `response_format?: "json" | "md"` with default `"md"` on style and screen search.** It also required `platform: "ios" | "web"` on screen search.
- **The packet stated that the Free plan had no MCP access.** It stated that Pro was the first supported tier. Pro has a published quota of 8,000 tool calls per month.
- **The local `mcp-remote` bridge prefers HTTP.** It uses browser OAuth.
- **`feature-catalog/` and `examples/` organize the research guidance.** The catalog describes each tool. The examples walk through research routes.

## Design Transport

#### Routing Guides Safe Research

`SKILL.md` defined Refero-specific activation signals. It also described the styles-to-screens-to-flows research funnel. It covered access limits and read-only safety rules.

&nbsp;

#### The Registered Manual Is Reused

The transport used the existing `refero` Code Mode manual. That manual launched `npx -y mcp-remote https://api.refero.design/mcp`. The transport kept the registered object as a verify-only asset. It did not edit `.utcp_config.json`. It did not create a second manual. `assets/utcp-refero-manual.md` preserved the registered manual snapshot and verify-only posture.

`mcp-servers/refero-mcp/README.md` pointed to the hosted provider and manual registration contract. It did not vendor a server. The official `referodesign/refero_skill` methodology repository was referenced, not vendored.

&nbsp;

#### Allowed Calls Are Listed

Runtime authority stayed minimal. Read, Bash, Grep, Glob and Code Mode calls were allowed. Write, Edit and Task were forbidden.

`mcp-refero` became the canonical transport home for Refero tool-surface facts. `sk-design` kept only its judgment-side framing. It consumed the transport as evidence and did not duplicate its catalog. The package kept one read-only transport contract and one registered backend. It held no packet-local design judgment and no workspace mutation.

Any design-affecting use loaded `sk-design` first. Refero supplied cited references. It never issued taste, accessibility or readiness verdicts. No hub files or live configuration belonged to this packet's release.

## Refero Research

#### Eight Tools Across Three Layers

Style search and detail formed one layer. Screen search, detail, similarity and image retrieval formed another. Flow search and detail formed the third.

Element research stayed a screen-metadata facet through `ui_elements` and `ux_patterns`. The packet did not invent a `search_elements` tool.

&nbsp;

#### Calls Follow Live Discovery

The fixture confirmed all registry names before authentication. The names use dotted doubled form, such as `refero.refero.refero_search_styles`. It confirmed TypeScript callables such as `refero.refero_refero_search_styles(args)`.

Each session still ran `list_tools` and `tool_info` before its first call. It failed closed on drift. Discovery required no OAuth. Authenticated calls remained operator-gated.

&nbsp;

#### Search and Identifiers Stay Precise

Other text-tool formatting stayed a per-tool `tool_info` check. `refero_get_screen_image` never accepted `response_format`.

UUID screen identifiers and numeric flow identifiers stayed distinct. Unknown response fields were preserved. Sparse-flow reconstruction was labeled inference. Screenshots were fetched only after metadata could not answer the question.

## Access and Operations

#### Local Bridge Requirements

The local `mcp-remote` bridge preferred HTTP. It used browser OAuth on port 3334. It stored operator-owned auth state under `~/.mcp-auth`.

Node.js 18 or newer was required. The project was documented on Node 24. The observed Node 25 crash was called out for diagnosis.

&nbsp;

#### Authentication Limits Are Stated

OAuth completion and authenticated calls remained honestly Inferred. That held until an operator completed authorization. Unpublished burst, concurrency, page-size, `Retry-After`, Bearer-acquisition and end-to-end OAuth details stayed UNKNOWN. They were not invented.

The packet preserved the registered manual byte-for-byte. It documented the env-backed Bearer header only as an alternative provider-supported shape. That shape was not the adopted configuration. The package claimed no undocumented tools, arguments, limits or authentication results.

&nbsp;

#### Diagnostics Stay Read-Only

`scripts/install.sh` verified Node, npx, registered-manual presence and the operator OAuth boundary. It installed nothing and mutated nothing. `scripts/doctor.sh` provided read-only diagnostics. It also offered an opt-in unauthenticated endpoint probe. A healthy result was HTTP 401.

## Catalogs and Guidance

#### Examples Lead Through Research

The examples covered the complete styles-to-screens-to-flows funnel. They covered a metadata-first single-tool lookup and an image-last screen fetch. Every walkthrough began with `tool_info`. Each used the doubled callable prefix. Each treated OAuth-gated execution as SKIP-valid when access was unavailable.

&nbsp;

#### Catalogs Preserve Tool Guidance

`feature-catalog/` supplied a root inventory, three domain overviews and one leaf for each tool. Each leaf covered call forms, argument bounds, identifier types, result-shape cautions and mutation class. It also covered cross-links to canonical references.

`references/tool-surface.md` carried the eight-tool contract, funnel, identifier rules and plan gates. It also carried deprecated-surface negative knowledge and open questions. `references/mcp-wiring.md` covered the registered manual, bridge and OAuth behavior. It covered doubled-prefix naming, operator-owned auth state and runtime constraints. `references/troubleshooting.md` covered authentication, entitlement, discovery, Node runtime, batching, quota and drift failures. It gave safe recovery steps.

&nbsp;

#### Testing Covers Key Paths

The nine-scenario manual testing playbook covered registered-manual verification and pre-auth discovery. It covered the full funnel, flow detail, text-format discipline and quota honesty. It covered config-mutation refusal, `sk-design` pairing, routing recall, holdouts and a negative control. Live paid or OAuth-gated steps allowed a documented SKIP. All locally testable routing, schema, refusal and wiring checks required real execution.

`README.md` and `INSTALL-GUIDE.md` described current-state use and operator verification. All packet paths used kebab-case. That included `feature-catalog/`, `manual-testing-playbook/`, their root indexes and `INSTALL-GUIDE.md`.
