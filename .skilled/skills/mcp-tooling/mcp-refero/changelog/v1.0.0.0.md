# v1.0.0.0, Refero Evidence for Design Work

This release brings Refero design-reference research into the `mcp-tooling` hub.

- It arrives through `mcp-refero`.
- The package holds the live-discovered tool contract.
- It also holds examples, catalogs, tests and diagnostics.
- It holds template-conformant documentation.

The packet documented eight read-only tools across three layers.

- They cover styles, screens and flows.
- The 2026-07-16 fixture confirmed the doubled Refero tool names.
- It also confirmed their TypeScript callable form.

&nbsp;

## Why This Release

The transport uses the registered Refero MCP manual and Code Mode. It searches real shipped UI styles, screens and flows.

- It supplies cited references to `sk-design`.
- `sk-design` is its mandatory judgment partner.
- Refero provides evidence, not design authority.

## Design Transport

The transport keeps Refero facts in one read-only home and sends design judgment to `sk-design`.

#### Routing Guides Safe Research <a id="c-routing-guides-safe-research"></a>

- `SKILL.md` defined Refero-specific activation signals.
- It also described the styles-to-screens-to-flows research funnel.
- It covered access limits and read-only safety rules.
- It defines the guarded five-intent router.
- It also specifies discovery-first execution.

#### The Registered Manual Is Reused <a id="c-the-registered-manual-is-reused"></a>

- The transport used the existing `refero` Code Mode manual.
- That manual launched `npx -y mcp-remote https://api.refero.design/mcp`.
- The transport kept the registered object as a verify-only asset.
- It did not edit `.utcp_config.json`.
- It did not create a second manual.
- `assets/utcp-refero-manual.md` preserved the registered manual snapshot and verify-only posture.
- `mcp-servers/refero-mcp/README.md` pointed to the hosted provider and manual registration contract.
- It did not vendor a server.
- The official `referodesign/refero_skill` methodology repository was referenced, not vendored.

#### Allowed Calls Are Listed <a id="c-allowed-calls-are-listed"></a>

- Runtime authority stayed minimal.
- Read, Bash, Grep, Glob and Code Mode calls were allowed.
- Write, Edit and Task were forbidden.
- `mcp-refero` is a read-only transport in `mcp-tooling`.
- `mcp-refero` became the canonical transport home for Refero tool-surface facts.
- `sk-design` kept only its judgment-side framing.
- It consumed the transport as evidence and did not duplicate its catalog.
- The package kept one read-only transport contract and one registered backend.
- It held no packet-local design judgment and no workspace mutation.
- Any design-affecting use loaded `sk-design` first.
- Refero supplied cited references.
- It never issued taste, accessibility or readiness verdicts.
- No hub files or live configuration belonged to this packet's release.

## Refero Research

The packet documents the tool surface and how calls discover it live.

#### Eight Tools Across Three Layers <a id="c-eight-tools-across-three-layers"></a>

- Style search and detail formed one layer.
- Screen search, detail, similarity and image retrieval formed another.
- Flow search and detail formed the third.
- Element research stayed a screen-metadata facet through `ui_elements` and `ux_patterns`.
- The packet did not invent a `search_elements` tool.

#### Calls Follow Live Discovery <a id="c-calls-follow-live-discovery"></a>

- The 2026-07-16 fixture confirmed the doubled Refero tool names.
- It also confirmed their TypeScript callable form.
- The fixture confirmed all registry names before authentication.
- The names use dotted doubled form, such as `refero.refero.refero_search_styles`.
- It confirmed TypeScript callables such as `refero.refero_refero_search_styles(args)`.
- Each session still ran `list_tools` and `tool_info` before its first call.
- It failed closed on drift.
- Discovery required no OAuth.
- Authenticated calls remained operator-gated.

#### Search and Identifiers Stay Precise <a id="c-search-and-identifiers-stay-precise"></a>

- The live schema confirmed `response_format?: "json" | "md"` with default `"md"` on style and screen search.
- It also required `platform: "ios" | "web"` on screen search.
- Other text-tool formatting stayed a per-tool `tool_info` check.
- `refero_get_screen_image` never accepted `response_format`.
- UUID screen identifiers and numeric flow identifiers stayed distinct.
- Unknown response fields were preserved.
- Sparse-flow reconstruction was labeled inference.
- Screenshots were fetched only after metadata could not answer the question.

## Access and Operations

The transport states its bridge needs, access limits and honest unknowns.

#### Local Bridge Requirements <a id="c-local-bridge-requirements"></a>

- The local `mcp-remote` bridge preferred HTTP.
- It used browser OAuth on port 3334.
- It stored operator-owned auth state under `~/.mcp-auth`.
- It uses browser OAuth.
- Node.js 18 or newer was required.
- The project was documented on Node 24.
- The observed Node 25 crash was called out for diagnosis.

#### Authentication Limits Are Stated <a id="c-authentication-limits-are-stated"></a>

- OAuth completion and authenticated calls remained honestly Inferred.
- That held until an operator completed authorization.
- Unpublished burst, concurrency, page-size, `Retry-After`, Bearer-acquisition and end-to-end OAuth details stayed UNKNOWN.
- They were not invented.
- The packet preserved the registered manual byte-for-byte.
- It documented the env-backed Bearer header only as an alternative provider-supported shape.
- That shape was not the adopted configuration.
- The package claimed no undocumented tools, arguments, limits or authentication results.

#### Plan Tiers Are Stated <a id="c-plan-tiers-are-stated"></a>

- The packet stated that the Free plan had no MCP access.
- It stated that Pro was the first supported tier.
- Pro has a published quota of 8,000 tool calls per month.
