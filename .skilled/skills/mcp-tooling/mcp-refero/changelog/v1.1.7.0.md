# v1.1.7.0, Machine Router in ROUTER.md

Separating the short routing guidance from the machine details gives readers a clear path to the information they need.

&nbsp;

## What's New at a Glance

- **The machine router has a sibling file.** `ROUTER.md` holds the intent map, resource map, default resource, loading levels and routing pseudocode under `## 3. MACHINE ROUTER`, after a short overview and intent model.
- **SMART ROUTING stays brief.** `SKILL.md` uses short prose and ends the section with one link to `ROUTER.md`.
- **Existing router pointers are updated.** Testing playbooks now point to `ROUTER.md`; the feature catalog entries and references still cite the old location.
- **The router contract checks signal alignment.** `ROUTER.md` keeps `INTENT_SIGNALS` as an exact mirror of `INTENT_MODEL`. The router contract now checks that match.
- **The frontmatter check no longer pins a version.** The verification row describes the fields instead of naming a number that rots, and the related-document tables list `ROUTER.md`.

&nbsp;

## Upgrade

No migration is required because the parsed router is identical to the previous edition.
