# v1.1.7.0, Machine Router in ROUTER.md

The short routing guidance sits apart from the machine details. Readers get a clear path to the information they need.

&nbsp;

## What's New at a Glance

- The machine router has a sibling file.
  - `ROUTER.md` holds the intent map and the resource map.
  - `ROUTER.md` also holds the default resource, the loading levels and the routing pseudocode.
  - All of them sit under `## 3. MACHINE ROUTER`.
  - A short overview and intent model come first.
- SMART ROUTING stays brief.
  - `SKILL.md` uses short prose.
  - The section ends with one link to `ROUTER.md`.
- Existing router pointers are updated.
  - Testing playbooks now point to `ROUTER.md`.
  - The feature catalog entries and references still cite the old location.
- The router contract checks signal alignment.
  - `ROUTER.md` keeps `INTENT_SIGNALS` as an exact mirror of `INTENT_MODEL`.
  - The router contract now checks that match.
- The frontmatter check no longer pins a version.
  - The verification row describes the fields.
  - The verification row no longer names a number that rots.
  - The related-document tables list `ROUTER.md`.

&nbsp;

## Upgrade

No migration is required. That is because the parsed router is identical to the previous edition.
