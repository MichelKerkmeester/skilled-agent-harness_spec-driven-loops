This release adds Notion support to the mcp-tooling hub as a new `mcp-notion` light workflow mode. It wraps the official Notion MCP so Code Mode can read and write real Notion content instead of routing around the workspace, closes the 5 gaps that MCP leaves open with direct API calls and documents which of Notion's two backends actually runs headless. The work spans deep research, skill authoring, knowledge references, hub and advisor registration and final verification, and closes with the skill routing at 0.95 advisor confidence and canon checks green.

> Spec folder: `specs/mcp-tooling/014-mcp-notion` (Level 2)

---

## New Features

The initial capability surface: the official MCP, the gaps it leaves open, the backend that actually runs headless and how Code Mode calls into it.

#### Official Notion MCP

No Notion skill existed for the mcp-tooling hub before this release. This release registers the official Notion MCP (`@notionhq/notion-mcp-server`) as the `notion` manual in `.utcp_config.json`, giving Code Mode 24 tools across 6 domains: 7 for pages, 5 for blocks, 6 for databases and data sources, 2 for comments, 3 for users and 1 for search. Notion is MCP-only, unlike `mcp-click-up`'s `cupt` CLI, so every call runs through Code Mode against the `notion` manual instead of a terminal command.

&nbsp;

#### Direct-API gap fills

The official MCP does not cover every operation an agent needs. 5 direct Notion REST calls fill the gaps: file uploads, views, non-truncated page property items, async-task polling and daily-note conventions, all reachable with the same `NOTION_TOKEN` the MCP uses. Agents get the missing operations without a second credential or a second server.

&nbsp;

#### Dual-backend routing

Notion ships two MCP backends and only one runs headless. This release registers the local stdio backend (`NOTION_TOKEN`, headless) as the default and documents the remote OAuth backend (`https://mcp.notion.com/mcp`, interactive-only) as the alternative, with the smart router selecting local stdio for headless Code Mode sessions. Code Mode keeps working unattended instead of stalling on an interactive OAuth prompt.

&nbsp;

#### Code Mode invocation

Notion tool names use hyphens, for example `create-a-page` and `query-data-source`, which a dot-property call cannot address safely. Calls use the bracket-safe form instead, `notion["notion_create-a-page"]({...})`, confirmed against `list_tools()` and `tool_info()` before every new call site. Nothing routes through a naming shape Code Mode cannot resolve.

## Architecture

Two shape decisions kept the mode proportional to what Notion actually needs.

#### Light workflow mode over a transport

A thin transport could not cover this skill's needs. Notion mutates the workspace and needs the 5 direct-API calls beyond what the MCP exposes. The skill is authored as a light workflow mode instead, the same shape `mcp-click-up` uses, covering routing between the MCP and the direct-API gap fills. The mode can route between backends and call types instead of exposing one flat tool list.

&nbsp;

#### Right-sized skill depth

A full multi-plugin skill, the `mcp-obsidian` 11-plugin depth, was considered and rejected. Notion has no third-party plugins to route between, so the mode stays scoped to the official MCP plus the 5 gap fills. The mode stays proportional to Notion's actual surface instead of carrying unused routing complexity.

## Upgrade

This is the initial release, so no migration is required.

A few behaviors are worth planning around. Search covers titles only. There is no full-text content search across page or block bodies. Deletes are reversible archive-to-trash moves rather than hard deletes. The headless Code Mode path depends on Notion's local stdio server, and Notion is deprecating that server in favor of the remote OAuth server, so this stays a tracked risk. Async-task polling is not exposed by the local backend, so use a direct API poll or the remote MCP instead. Exact registered tool identifiers differ between the local and remote backends, so confirm names live with `list_tools()` and `tool_info()` before relying on them.
