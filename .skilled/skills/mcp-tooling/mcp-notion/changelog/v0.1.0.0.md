# v0.1.0.0, Notion Content for Code Mode

This initial release gives Code Mode a way to read and write real Notion content.
- It works through the official MCP and direct API calls.
- It fills five gaps in the official MCP.
- It identifies which Notion backend runs headless.

The release draws on several kinds of work.
- The work spans deep research and skill authoring.
- The work spans knowledge references and hub and advisor registration.

&nbsp;

## Why This Release

Two gaps drove this release.
- Notion mutates the workspace.
- The official MCP leaves some operations uncovered.

## Notion Access

Code Mode reaches Notion through the official MCP and direct API calls.

#### Official MCP Tools <a id="c-official-mcp-tools"></a>

- The official Notion MCP has 24 tools across six domains.
- Code Mode uses the registered `notion` manual.
- `@notionhq/notion-mcp-server` is registered as the `notion` manual in `.utcp_config.json`.
- Its 24 tools cover pages (7), blocks (5), databases and data sources (6), comments (2), users (3) and search (1).
- Notion is MCP-only, unlike `mcp-click-up`, which has the `cupt` CLI.

#### Five Missing Operations <a id="c-five-missing-operations"></a>

- Five direct Notion REST calls fill gaps in the official MCP.
- They provide the missing operations with the same `NOTION_TOKEN`, without a second credential or server.
- File uploads
- Views
- Non-truncated page property items
- Async-task polling
- Daily-note conventions

#### Headless Backend Choice <a id="c-headless-backend-choice"></a>

- Local stdio is the default and remote OAuth is the alternative.
- The smart router selects local stdio for headless Code Mode sessions.
- The local stdio backend uses `NOTION_TOKEN` and runs headless.
- The remote OAuth backend at `https://mcp.notion.com/mcp` is interactive-only.

#### Bracket-Safe Tool Calls <a id="c-bracket-safe-tool-calls"></a>

- Notion tool names contain hyphens.
- Code Mode uses bracket-safe calls to address them.
- Names such as `create-a-page` and `query-data-source` contain hyphens that dot-property calls cannot safely address.
- Code Mode uses `notion["notion_create-a-page"]({...})`.
- Tool identifiers were confirmed against `list_tools()` and `tool_info()` before each new call site.
- Exact registered identifiers differ between the local and remote backends.
- So confirm names live with those tools before relying on them.

## Workflow Design

The skill uses a light workflow to route Notion calls.

#### A Light Workflow Mode <a id="c-a-light-workflow-mode"></a>

- `mcp-notion` adds a light workflow to `mcp-tooling`.
- The hub had no Notion skill before this release.
- A thin transport could not cover this skill's needs.
- That is because Notion mutates the workspace.
- It also requires five direct API calls beyond the MCP.
- The mode uses a light workflow shape, the same shape `mcp-click-up` uses.
- It routes between the MCP and direct-API gap fills.
- It also routes between backends and call types.
- It does not expose one flat tool list.

#### Right-Sized Skill Depth <a id="c-right-sized-skill-depth"></a>

- A full multi-plugin skill at the `mcp-obsidian` 11-plugin depth was considered and rejected.
- Notion has no third-party plugins to route between.
- So the mode covers the official MCP and five direct API calls.
- This keeps the mode proportional to Notion's actual surface instead of carrying unused routing complexity.

## Setup and References

The release adds scripts and references for Notion setup.

#### Setup Without Configuration Writes <a id="c-setup-without-configuration-writes"></a>

- The setup scripts cover installation and diagnostics.
- They check runtime and environment details without writing config.
- `scripts/install.sh` checks Node 18+ and `npx`.
- It prints the Code Mode manual snippet and the `notion_NOTION_TOKEN` environment key.
- It writes no config files.
- `scripts/install.sh --check-only` verifies the Node 18+ and `npx` runtime without installing anything or printing the config snippet.
- `scripts/doctor.sh` reports the platform, Node and `npx` versions.
- It reports whether `.utcp_config.json` registers the `notion` manual.
- It reports only whether `notion_NOTION_TOKEN` is present.
- The doctor changes nothing.

#### Capability and Workflow References <a id="c-capability-and-workflow-references"></a>

- The catalog and guides cover Notion capabilities and workflows.
- They include the knowledge layer and three Code Mode examples.
- `feature-catalog/FEATURE-CATALOG.md` inventories the 24 MCP tools by domain and five API-gap fills.
- Its knowledge-layer references cover hierarchy, 22 property types, relations, rollups, Formulas 2.0, rate limits and API-version pinning.
- `examples/README.md` indexes three Code Mode patterns: page creation, a data-source query and adding a relation.
- `scripts/README.md` documents `install.sh` and `doctor.sh`, while `README.md` and `INSTALL-GUIDE.md` cover the skill's front door and step-by-step setup.

## Notion Boundaries

Notion search and deletes have limits, and one server change is a tracked risk.

#### Search and Delete Limits <a id="c-search-and-delete-limits"></a>

- Search covers titles only, with no full-text search across page or block bodies.
- Deletes are reversible archive-to-trash moves rather than hard deletes.

#### Polling and Server Deprecation <a id="c-polling-and-server-deprecation"></a>

- The local backend does not expose async-task polling, so use a direct API poll or the remote MCP.
- Notion is deprecating the local server in favor of the remote OAuth server, so this is a tracked risk.
