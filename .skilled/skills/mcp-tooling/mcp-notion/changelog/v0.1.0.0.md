This initial release gives Code Mode a way to read and write real Notion content through the official MCP and direct API calls. It fills five gaps in the official MCP and identifies which Notion backend runs headless. The work spans deep research, skill authoring, knowledge references and hub and advisor registration.

> Spec folder: `specs/mcp-tooling/014-mcp-notion` (Level 2)

## Why This Release

Notion mutates the workspace, and the official MCP leaves some operations uncovered.

## What's New at a Glance

- **The official Notion MCP has 24 tools across six domains.** Code Mode uses the registered `notion` manual.
- **Five direct Notion REST calls fill gaps in the official MCP.** They provide the missing operations with the same `NOTION_TOKEN`, without a second credential or server.
- **Local stdio is the default and remote OAuth is the alternative.** The smart router selects local stdio for headless Code Mode sessions.
- **`mcp-notion` adds a light workflow to `mcp-tooling`.** The hub had no Notion skill before this release.
- **Notion tool names contain hyphens.** Code Mode uses bracket-safe calls to address them.
- **The manual testing playbook supplies 11 scenarios.** They are read-only or scratch-safe.
- **The setup scripts cover installation and diagnostics.** They check runtime and environment details without writing config.
- **The catalog and guides cover Notion capabilities and workflows.** They include the knowledge layer and three Code Mode examples.

## Notion Access

#### Official MCP Tools

`@notionhq/notion-mcp-server` is registered as the `notion` manual in `.utcp_config.json`. Its 24 tools cover pages (7), blocks (5), databases and data sources (6), comments (2), users (3) and search (1). Notion is MCP-only, unlike `mcp-click-up`, which has the `cupt` CLI.

&nbsp;

#### Five Missing Operations

The direct Notion REST calls cover:

- File uploads
- Views
- Non-truncated page property items
- Async-task polling
- Daily-note conventions

&nbsp;

#### Headless Backend Choice

The local stdio backend uses `NOTION_TOKEN` and runs headless. The remote OAuth backend at `https://mcp.notion.com/mcp` is interactive-only.

&nbsp;

#### Bracket-Safe Tool Calls

Names such as `create-a-page` and `query-data-source` contain hyphens that dot-property calls cannot safely address. Code Mode uses `notion["notion_create-a-page"]({...})`. Tool identifiers were confirmed against `list_tools()` and `tool_info()` before each new call site. Exact registered identifiers differ between the local and remote backends, so confirm names live with those tools before relying on them.

## Workflow Design

#### A Light Workflow Mode

A thin transport could not cover this skill's needs because Notion mutates the workspace and requires five direct API calls beyond the MCP. The mode uses a light workflow shape, the same shape `mcp-click-up` uses. It routes between the MCP and direct-API gap fills, as well as between backends and call types, instead of exposing one flat tool list.

&nbsp;

#### Right-Sized Skill Depth

A full multi-plugin skill at the `mcp-obsidian` 11-plugin depth was considered and rejected. Notion has no third-party plugins to route between, so the mode covers the official MCP and five direct API calls. This keeps the mode proportional to Notion's actual surface instead of carrying unused routing complexity.

## Setup and References

#### Manual Test Scenarios

The release ships no automated test suite. The playbook at `manual-testing-playbook/manual-testing-playbook.md` provides 11 read-only or scratch-safe scenarios. They cover MCP tool round-trips through Code Mode, a direct API call for a gap, backend selection and an auth-failure case.

&nbsp;

#### Setup Without Configuration Writes

`scripts/install.sh` checks Node 18+ and `npx`. It prints the Code Mode manual snippet and the `notion_NOTION_TOKEN` environment key. It writes no config files. `scripts/install.sh --check-only` verifies the Node 18+ and `npx` runtime without installing anything or printing the config snippet. `scripts/doctor.sh` reports the platform, Node and `npx` versions, whether `.utcp_config.json` registers the `notion` manual and only whether `notion_NOTION_TOKEN` is present. The doctor changes nothing.

&nbsp;

#### Capability and Workflow References

`feature-catalog/FEATURE-CATALOG.md` inventories the 24 MCP tools by domain and five API-gap fills. Its knowledge-layer references cover hierarchy, 22 property types, relations, rollups, Formulas 2.0, rate limits and API-version pinning. `examples/README.md` indexes three Code Mode patterns: page creation, a data-source query and adding a relation. `scripts/README.md` documents `install.sh` and `doctor.sh`, while `README.md` and `INSTALL-GUIDE.md` cover the skill's front door and step-by-step setup.

## Notion Boundaries

#### Search and Delete Limits

Search covers titles only, with no full-text search across page or block bodies. Deletes are reversible archive-to-trash moves rather than hard deletes.

&nbsp;

#### Polling and Server Deprecation

The local backend does not expose async-task polling, so use a direct API poll or the remote MCP. Notion is deprecating the local server in favor of the remote OAuth server, so this is a tracked risk.
