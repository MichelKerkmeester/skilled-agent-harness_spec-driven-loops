# v1.0.0.0, Mobbin App-Design Research

The first `mcp-mobbin` release gives the `mcp-tooling` hub a Mobbin app-design research transport through the registered Mobbin MCP manual and Code Mode.

The package brings together the live-discovered tool contract, research intents, examples, catalogs, tests, diagnostics and template-conformant documentation. OAuth and authenticated-call claims are explicitly Inferred and operator-gated.

## Why This Release

The read-only transport searches real app screens, flows and website sections.

## What's New at a Glance

- **The pre-auth fixture recorded three Mobbin search tools.** Each session confirmed discovery before its first call.
- **Screen searches expose mode and output options.** The request can exclude screen IDs and select an image format.
- **Access guidance records plan and rate limits.** It describes the documented plans and recovery after HTTP 429.
- **Catalogs and examples support research intents.** They cover apps, screens, flows and elements.
- **The manual playbook covers live and locally testable scenarios.** Live checks can be marked `SKIP` where the playbook allows it.
- **Setup scripts provide read-only diagnostics.** They check prerequisites and can probe the unauthenticated endpoint.
- **Reference material documents the bridge and research contract.** Setup guides describe current-state setup and verification.
- **The package has one registered backend.** Its transport is marked `packetKind: transport` and `mutatesWorkspace: false`.

## Mobbin Research

#### Route Research Intents

`SKILL.md` defined Mobbin-specific activation signals, a guarded intent router and discovery-first execution. Its research patterns covered apps, screens, flows, elements and website sections, with read-only safety rules.

Apps and elements were query intents over the discovered read-only tools, not separate tool families.

&nbsp;

#### Discover the Search Tools

The 2026-07-16 pre-auth discovery fixture recorded the registry names `mobbin.mobbin.search_screens`, `mobbin.mobbin.search_flows` and `mobbin.mobbin.search_sections`. Their confirmed TypeScript Code Mode calls were `mobbin.mobbin_search_screens(...)`, `mobbin.mobbin_search_flows(...)` and `mobbin.mobbin_search_sections(...)`.

Each session still ran `list_tools` and `tool_info` before its first call and failed closed on discovery drift. `search_flows` supplied ordered per-screen previews for research across a flow. `search_sections` supplied website-section research. Returned ordering was treated as fact, while interpolation, omitted states and cross-app generalization were labeled inference.

&nbsp;

#### Shape Screen Searches

`search_screens` exposed `mode: "deep" | "standard" | "fast"`, `exclude_screen_ids` and `image_format`. The `fast` mode was a deprecated alias for `standard`.

Its declared output used `query` and screen records with `id`, `image_url`, `mobbin_url`, `app_name` and `platform`. Older undeclared fields were probe-required rather than asserted.

&nbsp;

#### Keep Design Judgment Separate

Any design-affecting use loaded `sk-design` first. Mobbin supplied cited evidence and never issued taste, accessibility or readiness verdicts. Design-affecting conclusions were routed to `sk-design`.

## Access and Limits

#### Bridge the Hosted Provider

The registered `mobbin` Code Mode manual launched `npx -y mcp-remote https://api.mobbin.com/mcp` over stdio to bridge the hosted Streamable HTTP provider. Its `env` was intentionally empty because Mobbin MCP used browser OAuth and had no `MOBBIN_API_KEY` or other auth environment variable.

The manual was preserved as a byte-identical reference shape. Its presence was the healthy state and its absence a diagnostic error. The packet did not edit or re-add `.utcp_config.json`.

&nbsp;

#### Document OAuth Boundaries

The packet documented browser OAuth through DCR, PKCE S256 and `openid`. Operator-owned auth state was under `~/.mcp-auth` or `MCP_REMOTE_CONFIG_DIR`. No API key entered config or `.env`.

Discovery and full schemas worked before authentication. OAuth completion, authenticated response shapes, inline-image fidelity and authenticated calls were marked Inferred or UNKNOWN until an operator completed the browser round trip on a paid account.

&nbsp;

#### Record Plan and Rate Limits

Access was documented for Pro, Team or Enterprise plans. Provider evidence relayed Free-plan denial, while its exact status, payload and user experience were unverified.

The published rate contract was 60 requests per 60 seconds per user. On HTTP 429 the workflow honored `Retry-After` and applied exponential backoff with jitter. It did not force load tests or define finer burst, concurrency, per-plan cap or Finance+ coverage contracts.

## Research Support

#### Link Catalogs to the Tool Reference

`feature-catalog/` supplied a root inventory and intent pages for apps, screens, flows and elements. The pages included query recipes, platform rules, schema honesty, plan gates, rate limits and mutation class. They linked to the canonical tool reference.

&nbsp;

#### Show Research Examples

`examples/` supplied a minimum `limit: 1` smoke search, a platform-filtered flow-research walkthrough and an element-intent comparison across apps. Each walkthrough used confirmed call forms, cited `mobbin_url` evidence, preserved unknown fields and labeled reconstruction as inference.

The catalog and examples used the three-tool discovery fixture as their baseline, with per-session confirmation and authenticated-call gates.

&nbsp;

#### Cover Manual Test Scenarios

The nine-scenario manual testing playbook covered registered-manual reporting, pre-auth discovery, screen search, flow intent, platform filtering, rate-limit observation, paid-gate error taxonomy, config and credential mutation refusal, `sk-design` pairing, routing recall, holdouts and a negative control.

Live paid, OAuth, 429 and image-fidelity checks allowed a documented `SKIP`. Locally testable wiring, schema, routing and refusal behavior required real execution.

## Setup and Documentation

#### Diagnose Setup Without Changes

`scripts/install.sh` verified Node 18 or newer, `npx`, registered-manual presence and the operator OAuth boundary without installing or mutating anything. `scripts/doctor.sh` provided read-only diagnostics and an opt-in unauthenticated endpoint probe whose healthy result was HTTP 401.

&nbsp;

#### Document Current Setup

`README.md` and `INSTALL-GUIDE.md` described current-state setup and verification. `scripts/README.md` followed the create-readme code-folder structure for Overview, Architecture, Directory Tree, Key Files, Entrypoints, Validation and Related resources. Its content was grounded in the actual read-only and exit-code behavior of `install.sh` and `doctor.sh`.

Packet paths used kebab-case, including `feature-catalog/`, `manual-testing-playbook/`, their root indexes, `examples/` and `INSTALL-GUIDE.md`.

&nbsp;

#### Preserve Reference Details

`references/tool-surface.md` carried the three live schemas, research-intent workflows, resolved deep-mode contract, response-shape cautions, plan and rate gates, provider disambiguation and open questions. `references/mcp-wiring.md` carried the registered manual, `mcp-remote` bridge, hosted transport, DCR and PKCE behavior, observed naming, operator-owned auth state and discovery-first contract.

`references/troubleshooting.md` covered expected pre-auth 401 responses, OAuth and callback failures, stale discovery, entitlement denial, 429 recovery, image fidelity, context pressure and fixture drift. `assets/utcp-mobbin-manual.md` preserved the registered reference shape and separated completed repository checks from operator-owned OAuth and authenticated smoke checks.

Reference and asset documents followed the create-skill OVERVIEW-first structure with Purpose and Usage. They preserved technical content, frontmatter, filenames, Related Resources placement and Inferred auth claims.

&nbsp;

#### Keep the Provider External

`mcp-servers/mobbin-mcp/README.md` pointed to the hosted provider and registered bridge without vendoring server source. The official `mobbin/skills` repository was referenced rather than vendored. Its optional evidence-board writer stayed outside this read-only packet.

## Transport Boundaries

#### Keep Authority Read-Only

The package retained one registered backend and one read-only transport contract with `packetKind: transport` and `mutatesWorkspace: false`. It had no packet-local design judgment or workspace mutation. Runtime authority allowed Read, Bash, Grep, Glob and Code Mode calls, while Write, Edit and Task were forbidden.

No hub files or live configuration belonged to this release. No undocumented tools, parameters, credentials, limits or authenticated results were claimed.
