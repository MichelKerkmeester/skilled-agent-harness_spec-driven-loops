# mcp-obsidian — v0.6.0.0

Makes the complete Iconic automatic-rule payload the canonical merge source. Until now the skill shipped only a compact schema sample; the docs described the rulebook concept but had no complete payload to apply. Now `assets/plugins/iconic/iconic-rules.full.json` holds all 32 rules (21 file + 11 folder), and every Iconic surface — references, feature card, resource router — points at it with one explicit boundary: merge by stable rule id into a freshly-read vault `data.json`, never replace the whole file.

## 1. NEW

- **Canonical rulebook asset** — `assets/plugins/iconic/iconic-rules.full.json`: the complete automatic-rule payload with all 21 `fileRules` + 11 `folderRules`. It deliberately contains ONLY the two mergeable rule arrays — no `data.json` settings, no `dialogState`, no per-item override maps — so it can never clobber user configuration. Normalized rule objects verified identical across the Obsidian, iCloud, and Barter vaults (content digest `773aa231ec665f49240895f039504cd0fb64f61ca2ca577568b7b3b85778137d`).
- **Merge-only boundary** — the Iconic reference set and the feature card now state the asset must be merged by stable rule id into a freshly-read vault `data.json` (update matching ids, append missing ids), preserving unrelated settings and user overrides; it is never a whole-`data.json` backup or replacement. The small `iconic-rules.example.json` stays untouched as the compact schema sample.
- **Resource-router branch** — `SKILL.md` v0.6.0.0 adds the `PLUGIN_ICONIC` intent (signals: `iconic`, `iconic rulebook`, `icon rules`, `icon automation`, `file icons`, `folder icons`, `icon color`, `iconic data json`, `iconic ruleset`) routing to `plugin-operation-logic.md` plus all four Iconic reference docs; specific-plugin resolution grows from 3 to 4 intents and the intent count prose is corrected from eight to nine.
