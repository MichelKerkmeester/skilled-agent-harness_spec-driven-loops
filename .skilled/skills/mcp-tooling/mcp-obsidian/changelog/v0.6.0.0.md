# v0.6.0.0, The Canonical Iconic Rulebook

The complete Iconic automatic-rule payload is now the canonical merge source. Before this release, the skill shipped only a compact schema sample. The docs described the rulebook without a complete payload to apply.

## What's New at a Glance

- **The full Iconic payload is the canonical rulebook.** `assets/plugins/iconic/iconic-rules.full.json` holds all 32 rules. That is 21 `fileRules` and 11 `folderRules`. Normalized rule objects are verified identical across the Obsidian, iCloud and Barter vaults. It holds only those two mergeable arrays. It has no `data.json` settings, `dialogState` or per-item override maps. So it cannot clobber user configuration.
- **Iconic updates use a merge-only boundary.** The Iconic reference set and feature card say the asset must be merged by stable rule id. It merges into a freshly-read vault `data.json`. Matching ids are updated and missing ids are appended. Unrelated settings and user overrides are preserved. It is never a whole-`data.json` backup or replacement.
- **The resource router adds `PLUGIN_ICONIC`.** `SKILL.md` moves from v0.5.0.0 to v0.6.0.0. It adds the signals `iconic`, `iconic rulebook`, `icon rules`, `icon automation`, `file icons`, `folder icons`, `icon color`, `iconic data json` and `iconic ruleset`. Those signals route to `plugin-operation-logic.md` plus all four Iconic reference docs. The update changes frontmatter, keywords, `INTENT_SIGNALS`, `RESOURCE_MAP`, specific-plugin resolution and reference navigation. It grows specific-plugin resolution from 3 to 4 intents. It corrects the intent-count prose from eight to nine.
- **The Iconic references and feature card advance to v0.6.0.0.** `references/plugins/iconic/iconic.md`, `data-model.md` and `workflows.md` move from v0.5.0.0 to v0.6.0.0. That makes the full asset canonical and the example a compact schema sample. The apply-rulebook recipe names the full asset and the update/append merge rule. `feature-catalog/plugins/iconic.md` moves from v0.5.0.0 to v0.6.0.0. It splits the asset entry into canonical full payload and compact schema sample. It adds a canonical-merge safety sentence to its guardrails.
- **The example and vault files were untouched.** `iconic-rules.example.json` remains byte-for-byte unchanged as the compact schema sample. The new full asset was the only JSON config/asset change.
- **Rendering was not re-verified.** File-layer claims remain JSON round-trip only.

No migration required.
