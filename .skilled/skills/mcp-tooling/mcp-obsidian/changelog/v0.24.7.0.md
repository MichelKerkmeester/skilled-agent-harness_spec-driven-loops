# v0.24.7.0, Docs Read in Order and Render as Written

The mode's `SKILL.md`, `ROUTER.md`, `README.md` and its references and assets were read file by file for readability, layout and structure. No tool, rule or source citation changed.

> Spec folder: `specs/sk-doc/066-skill-readability-refinement/005-mcp-tooling/008-mcp-obsidian` (Level 1)

&nbsp;

## What's New at a Glance

- **The official CLI failures share one section.** Troubleshooting section 5, now Official CLI Issues, holds three subsections: the CLI is not registered, the app is not running, and an error that still exits zero, so sections 6 to 12 keep their numbers.
- **The agent invariants come first.** In the CLI commands reference they are section 4, ahead of the commands they govern, so the command sections move to 5 to 11.
- **Overviews open with their purpose.** The plugin and theme references gain Purpose and When to Use subsections, the plugin development scope note is its Boundaries, and the Health MD chart examples number their sections.
- **Packed paragraphs became lists.** The MCP tools header lines, the when-to-prefer rules for the official CLI and the other dense passages read one fact per line.
