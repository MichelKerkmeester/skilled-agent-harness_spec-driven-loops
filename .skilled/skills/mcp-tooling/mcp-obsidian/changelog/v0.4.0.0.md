This release extends the mcp-obsidian mode's plugin knowledge with Health.md Visualizations. It uses the existing per-plugin reference pattern. That pattern is an index, data model, workflows and troubleshooting.

&nbsp;

## What's New at a Glance

- A new Health.md Visualizations (`health-md`) reference set is at `references/plugins/health-md/`.
  - It covers Apple Health export data files (JSON/CSV/Markdown/Bases) in the vault data folder (default `Health/`).
  - It also covers schema v0–v7 and roll-ups under `Health/Rollups/`.
  - It covers `_healthmd_data_dictionary.json` and render-block placement.
  - It covers the hard rule to never fabricate health data.
  - Health.md Visualizations was installed and enabled in all three vaults (packet Phase 11).
- `SKILL.md` gains activation triggers for health requests.
  - It moves from version 0.3.0.0 to 0.4.0.0 in its frontmatter and keywords.
  - It adds the reference set to load-on-demand.
  - It extends the keyword comment.
  - The data map in `plugin-operation-logic.md` grows from 3 to 4 rows.
- The health-md catalog and playbook entries are added.
  - The feature card `feature-catalog/plugins/health-md.md` is added.
  - So is scenario `OBS-014` (Health.md data-file round-trip).
  - Indexes are updated.
  - The plugin category in `feature-catalog/FEATURE-CATALOG.md` changes from 3 to 4 plugins.
  - `manual-testing-playbook/manual-testing-playbook.md` changes from 19 to 20 scenarios (`OBS-011`..`OBS-014`).
- An example export file is included.
  - `assets/plugins/health-md/healthmd-export.example.json` is an example data file.
  - No plugin code is vendored.
- The three existing plugin reference sets are unchanged.
  - The only exception is the shared data-map table.
