# mcp-obsidian v0.24.0.0

The operator asked for all dedicated plugin support to be removed except Iconic and Health.md. Nothing was uninstalled from the vault: all 24 community plugins are still enabled and still work. What changed is this mode — its documentation and its routing. The mode no longer carries per-plugin reference trees for twelve plugins it cannot operate any better than it can operate any other file the plugin writes, and its router no longer pretends to have twelve plugin answers. It keeps the two documented plugins, the theme system (which is not a plugin and was never in question), the roster that still names every installed plugin, and the generic `PLUGINS` intent that points at how plugin-driven automation actually works.

---

## 1. REMOVED

- **Twelve plugin reference trees, 48 files.** `references/plugins/advanced-canvas/`, `charts/`, `claudian/`, `dataview/`, `git/`, `make-md/`, `meta-bind/`, `notion-bases/`, `obsidian-local-rest-api/`, `obsidian-tables/`, `obsidian42-brat/` and `outliner/` were each a four-file set (`<name>.md`, `data-model.md`, `workflows.md`, `troubleshooting.md`). All 48 files are gone. `references/plugins/iconic/` and `references/plugins/health-md/` are untouched.
- **Five example-asset directories and one loose asset file, 9 files.** `assets/plugins/charts/` (1 file), `assets/plugins/dataview/` (2), `assets/plugins/git/` (2), `assets/plugins/obsidian-tables/` (1) and `assets/plugins/outliner/` (2) were deleted, along with `assets/brat-data-entry.example.json`. The `assets/plugins/iconic/` and `assets/plugins/health-md/` payloads survive, since both plugins remain documented.
- **Eleven feature-catalog cards.** `feature-catalog/plugins/` lost `advanced-canvas.md`, `charts.md`, `claudian.md`, `dataview.md`, `git.md`, `make-md.md`, `meta-bind.md`, `notion-bases.md`, `obsidian-tables.md`, `obsidian42-brat.md` and `outliner.md`. The three cards that remain are `health-md.md`, `iconic.md` and `theme-system.md`.
- **Eleven manual-testing scenarios.** `manual-testing-playbook/plugin-tie-ins/` lost the same eleven plugins' scenario files. `health-md-data.md`, `iconic-rules.md` and `theme-activation.md` remain.
- **Twelve `PLUGIN_*` router intents in `SKILL.md`.** `PLUGIN_ADVANCED_CANVAS`, `PLUGIN_CHARTS`, `PLUGIN_CLAUDIAN`, `PLUGIN_DATAVIEW`, `PLUGIN_GIT`, `PLUGIN_MAKEMD`, `PLUGIN_META_BIND`, `PLUGIN_NOTION_BASES`, `PLUGIN_LOCAL_REST_API`, `PLUGIN_TABLES`, `PLUGIN_BRAT` and `PLUGIN_OUTLINER` are gone from `INTENT_SIGNALS` and `RESOURCE_MAP`, and from the `specific_plugin_intents` tuple, which now holds `PLUGIN_ICONIC`, `PLUGIN_HEALTH` and `THEME_SYSTEM`.

The release removes 79 files across 88 changed files, 12,797 deleted lines in total, of which the 48 deleted reference files account for 8,892. No plugin row was deleted from the roster and no plugin was uninstalled.

## 2. CHANGED

- **`SKILL.md` (+8 −249).** The router went from 22 intents to 10. Frontmatter description, the `keywords` comment, the activation triggers and the §8 reference inventory were all reduced to match the surviving surface. The generic `PLUGINS` intent survives and now points at `references/plugins/plugin-operation-logic.md`, the roster, the two retained plugin indexes (`references/plugins/iconic/iconic.md`, `references/plugins/health-md/health-md.md`) and the theme index (`references/themes/themes.md`). Version 0.23.0.0 → 0.24.0.0.
- **`references/plugins/installed-plugins.md` (+37 −27).** The roster's two-class split no longer described reality, because 13 file-layer plugins lost their docs without losing their file layer. It now carries three classes that sum to the same 24 plugins: **2 documented file-layer** (§2), **13 file-layer whose dedicated docs were removed** (§3), and **9 UI or automatic** (§4). No plugin row was deleted, and the standing warning never to remove `obsidian-local-rest-api` survives unchanged, because it is about the vault plugin rather than about the documentation.
- **`references/plugins/plugin-operation-logic.md` (+6 −13).** Its data map went from ten artifacts to three: health-md, iconic and minimal.
- **`feature-catalog/FEATURE-CATALOG.md` (+3 −69).** §14 now narrates three surfaces — Health.md, Iconic and the theme system — instead of fourteen. The catalog entry total went from 34 to 23.
- **`manual-testing-playbook/manual-testing-playbook.md` (+6 −162).** §12 keeps `OBS-014`, `OBS-015` and `OBS-021` and drops the other eleven scenarios. The three surviving ids were deliberately not renumbered.
- **`assets/workflows.md` (+11 −63).** The Obsidian Tables and BRAT procedures were replaced by pointers to the retained plugins' own workflow files, `references/plugins/iconic/workflows.md` and `references/plugins/health-md/workflows.md`.
- **`README.md` (+3 −14).** The plugin knowledge-layer table went from fourteen rows to three: Health.md, Iconic and the theme system.
- **`references/notion-migration.md` (+1 −7).** The 8-step method is unchanged. Only its pointers into the deleted doc sets were removed. The method still depends on the Notion Bases, Meta Bind, JS Engine and Dataview plugins, and all four are still installed.
- **`feature-catalog/cli/uri-actions.md` (−1).** One dead link to the BRAT reference was removed.

## 3. NOT CHANGED

- **Nothing was uninstalled from the vault.** All 24 community plugins remain enabled in `.obsidian/community-plugins.json` and all of them still work. The reduction is confined to this mode's documentation, routing and test surface.
- **The Local REST API doc set was removed along with the rest, and that is safe.** The plugin is the transport the cyanheads MCP rides on, so its absence from `references/plugins/` deserves to be stated plainly rather than left to inference. Its setup, port, API key and failure modes were already documented outside that doc set — in `INSTALL-GUIDE.md` and in `references/troubleshooting.md` §6 (Local REST API issues) and §7 (authentication issues) — and those sections were verified to stand alone before the removal. The MCP path is unaffected.
- **The theme system under `references/themes/` is untouched.** Themes live under `.obsidian/themes/` and appearance settings, not in `community-plugins.json`; no theme was ever a plugin row and none was in question.
- **All eight router targets of the retained intents resolve.** `PLUGIN_ICONIC`, `PLUGIN_HEALTH`, `THEME_SYSTEM` and `PLUGINS` load only files that exist on disk.
- **Historical changelog entries are left as written.** Entries such as `changelog/v0.22.0.0.md`, which documents the addition of the `make-md` tree and the `PLUGIN_MAKEMD` intent, still record what was true at that release.
