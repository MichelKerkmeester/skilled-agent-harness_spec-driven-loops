# v0.24.0.0, Focused Plugin Documentation

v0.24.0.0 narrows mcp-obsidian's dedicated plugin support. Its documentation, routing and test surface now reflect that narrower scope.

## Why This Release

The operator asked for all dedicated plugin support to be removed except Iconic and Health.md. The mode cannot operate on files written by the twelve removed plugins any better than it can operate on any other file a plugin writes, and its router no longer pretends to have twelve plugin answers.

## What's New at a Glance

- **Twelve dedicated plugin reference trees were removed.** Iconic and Health.md are the documented exceptions.
- **The router now has 10 intents instead of 22.** The generic `PLUGINS` intent points to plugin-driven automation.
- **The roster groups the same 24 plugins into three classes.** No plugin row was deleted.
- **Example assets for removed plugin guidance were deleted.** The five affected directories and loose BRAT asset total nine files.
- **The feature catalog and manual tests now cover the retained surfaces.** Section 14 presents three surfaces instead of fourteen.
- **The Obsidian Tables and BRAT procedures were replaced by pointers to the retained plugins' own workflow files.** The replacement pointers lead to Iconic and Health.md workflows.
- **The plugin operation map and README table were narrowed.** The README table now has three rows instead of fourteen.
- **The eight-step Notion migration method is unchanged.** Only its pointers into the deleted doc sets were removed.
- **The Local REST API reference set was removed.** The cyanheads MCP path is unaffected.
- **The theme system was not part of the plugin removal.** Themes live under `.obsidian/themes/` and appearance settings, not in `community-plugins.json`.
- **No community plugin was uninstalled from the vault.** The reduction is confined to this mode's documentation, routing and test surface.
- **The skill version advanced from 0.23.0.0 to 0.24.0.0.** Historical changelog entries were left as written.

## Plugin Documentation

#### Dedicated References Narrow

The removed reference trees were `references/plugins/advanced-canvas/`, `charts/`, `claudian/`, `dataview/`, `git/`, `make-md/`, `meta-bind/`, `notion-bases/`, `obsidian-local-rest-api/`, `obsidian-tables/`, `obsidian42-brat/` and `outliner/`. Each tree contained `<name>.md`, `data-model.md`, `workflows.md` and `troubleshooting.md`, for 48 deleted reference files. The `references/plugins/iconic/` and `references/plugins/health-md/` trees were untouched.

The release removed 79 files among 88 changed files.

&nbsp;

#### Example Assets Follow Scope

Five example-asset directories and one loose asset file were deleted: `assets/plugins/charts/` (1 file), `assets/plugins/dataview/` (2), `assets/plugins/git/` (2), `assets/plugins/obsidian-tables/` (1), `assets/plugins/outliner/` (2) and `assets/brat-data-entry.example.json`. The `assets/plugins/iconic/` and `assets/plugins/health-md/` payloads were untouched.

&nbsp;

#### Catalog and Tests Match

Eleven cards left `feature-catalog/plugins/`: `advanced-canvas.md`, `charts.md`, `claudian.md`, `dataview.md`, `git.md`, `make-md.md`, `meta-bind.md`, `notion-bases.md`, `obsidian-tables.md`, `obsidian42-brat.md` and `outliner.md`. The remaining cards are `health-md.md`, `iconic.md` and `theme-system.md`. Section 14 of `feature-catalog/FEATURE-CATALOG.md` now narrates three surfaces, Health.md, Iconic and the theme system, instead of fourteen. The catalog total moved from 34 entries to 23.

Eleven scenarios for the removed plugins left `manual-testing-playbook/plugin-tie-ins/`. Section 12 of `manual-testing-playbook/manual-testing-playbook.md` keeps `OBS-014`, `OBS-015` and `OBS-021`, which were deliberately not renumbered. The surviving files are `health-md-data.md`, `iconic-rules.md` and `theme-activation.md`.

&nbsp;

#### Workflow Pointers Change

`assets/workflows.md` points to `references/plugins/iconic/workflows.md` and `references/plugins/health-md/workflows.md` for Iconic and Health.md workflows.

`feature-catalog/cli/uri-actions.md` lost one dead link to the BRAT reference.

## Routing and Reference Records

#### The Intent Set Shrinks

The frontmatter description, `keywords` comment, activation triggers and §8 reference inventory in `SKILL.md` were reduced to match the surviving surface. Twelve `PLUGIN_*` intents left `INTENT_SIGNALS` and `RESOURCE_MAP`: `PLUGIN_ADVANCED_CANVAS`, `PLUGIN_CHARTS`, `PLUGIN_CLAUDIAN`, `PLUGIN_DATAVIEW`, `PLUGIN_GIT`, `PLUGIN_MAKEMD`, `PLUGIN_META_BIND`, `PLUGIN_NOTION_BASES`, `PLUGIN_LOCAL_REST_API`, `PLUGIN_TABLES`, `PLUGIN_BRAT` and `PLUGIN_OUTLINER`. The `specific_plugin_intents` tuple now holds `PLUGIN_ICONIC`, `PLUGIN_HEALTH` and `THEME_SYSTEM`.

The generic `PLUGINS` intent points to `references/plugins/plugin-operation-logic.md`, `references/plugins/installed-plugins.md`, `references/plugins/iconic/iconic.md`, `references/plugins/health-md/health-md.md` and `references/themes/themes.md`. All eight router targets of the retained intents resolve, and `PLUGIN_ICONIC`, `PLUGIN_HEALTH`, `THEME_SYSTEM` and `PLUGINS` load only files that exist on disk.

&nbsp;

#### The Roster Fits the File Layer

The previous two-class split did not describe the thirteen file-layer plugins that lost dedicated documentation without losing their file layer. The roster now has two documented file-layer plugins, thirteen file-layer plugins whose dedicated documentation was removed and nine UI or automatic plugins, adding up to the same 24 plugins.

The roster names every installed plugin. Its standing warning never to remove `obsidian-local-rest-api` was unchanged because it concerns the vault plugin, not its documentation. All 24 community plugins remain enabled in `.obsidian/community-plugins.json` and all of them still work.

&nbsp;

#### Reference Tables Narrow

The data map in `references/plugins/plugin-operation-logic.md` went from ten artifacts to three: health-md, iconic and minimal. The three entries in the `README.md` plugin knowledge-layer table are Health.md, Iconic and the theme system.

&nbsp;

#### Notion Migration Keeps Its Steps

`references/notion-migration.md` still depends on the Notion Bases, Meta Bind, JS Engine and Dataview plugins. All four are still installed.

&nbsp;

#### Version History Stays Intact

`references/plugins/installed-plugins.md` and `references/plugins/plugin-operation-logic.md` were edited without a version bump. The `changelog/v0.22.0.0.md` entry records the addition of the `make-md` tree and the `PLUGIN_MAKEMD` intent.

## Vault and MCP Transport

#### Themes Stay Unchanged

The theme system under `references/themes/` is untouched. It is not a plugin and was never in question. No theme was ever a plugin row.

&nbsp;

#### Local REST API Setup Is Covered

Its setup, port, API key and failure modes were already documented outside the removed reference set in `INSTALL-GUIDE.md` and in `references/troubleshooting.md` §6 (Local REST API issues) and §7 (authentication issues). The Local REST API plugin is the transport the cyanheads MCP rides on.

The setup facts the MCP path depends on were located in their surviving homes: `INSTALL-GUIDE.md`, with Local REST API v4.0.0+, `OBSIDIAN_API_KEY`, `OBSIDIAN_BASE_URL` and the connection-refused and 401 rows, and `references/troubleshooting.md` §6 and §7.

## Upgrade Notes

No upgrade needed.
