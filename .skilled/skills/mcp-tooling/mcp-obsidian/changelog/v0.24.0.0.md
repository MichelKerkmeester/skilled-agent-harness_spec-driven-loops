# v0.24.0.0, Focused Plugin Documentation

v0.24.0.0 narrows mcp-obsidian's dedicated plugin support.

- Twelve dedicated plugin reference trees were removed.
- Iconic and Health.md are the documented exceptions.
- No community plugin was uninstalled from the vault.
- The reduction is confined to this mode's documentation, routing and test surface.

The router and plugin roster were narrowed to match.

- The router now has 10 intents instead of 22.
- The generic `PLUGINS` intent points to plugin-driven automation.
- The roster groups the same 24 plugins into three classes.
- No plugin row was deleted.

The vault and the MCP path were left alone.

- All 24 community plugins remain enabled and still work.
- The cyanheads MCP path is unaffected.
- The theme system was not part of the plugin removal.
- The skill version advanced from 0.23.0.0 to 0.24.0.0.

&nbsp;

## Why This Release

The operator asked to remove all dedicated plugin support except Iconic and Health.md.

- The mode cannot work on files from the twelve removed plugins any better.
- It handles any other plugin's files the same way.
- Its router no longer pretends to have twelve plugin answers.

## Plugin Documentation

Dedicated plugin support was reduced to Iconic and Health.md. Example assets for removed plugin guidance were deleted.

#### Dedicated References Narrow <a id="c-dedicated-references-narrow"></a>

- Twelve dedicated plugin reference trees were removed.
- They were `references/plugins/advanced-canvas/`, `charts/`, `claudian/`, `dataview/`, `git/`, `make-md/`, `meta-bind/`, `notion-bases/`, `obsidian-local-rest-api/`, `obsidian-tables/`, `obsidian42-brat/` and `outliner/`.
- Each tree held `<name>.md`, `data-model.md`, `workflows.md` and `troubleshooting.md`.
- 48 reference files were deleted.
- `references/plugins/iconic/` and `references/plugins/health-md/` were untouched.
- 79 files were removed among 88 changed files.
- 12,797 lines were removed.

#### Example Assets Follow Scope <a id="c-example-assets-follow-scope"></a>

- Example assets for removed plugin guidance were deleted.
- Five example-asset directories and one loose asset file were deleted.
- They were `assets/plugins/charts/` (1 file), `assets/plugins/dataview/` (2), `assets/plugins/git/` (2), `assets/plugins/obsidian-tables/` (1), `assets/plugins/outliner/` (2) and `assets/brat-data-entry.example.json`.
- Five directories and the loose BRAT asset total nine files.
- `assets/plugins/iconic/` and `assets/plugins/health-md/` payloads were untouched.

#### Catalog and Tests Match <a id="c-catalog-and-tests-match"></a>

- The feature catalog and manual tests now cover the retained surfaces.
- Eleven cards left `feature-catalog/plugins/`.
- They were `advanced-canvas.md`, `charts.md`, `claudian.md`, `dataview.md`, `git.md`, `make-md.md`, `meta-bind.md`, `notion-bases.md`, `obsidian-tables.md`, `obsidian42-brat.md` and `outliner.md`.
- The remaining cards are `health-md.md`, `iconic.md` and `theme-system.md`.
- Section 14 of `feature-catalog/FEATURE-CATALOG.md` now narrates three surfaces.
- They are Health.md, Iconic and the theme system.
- It used to narrate fourteen.
- The catalog total moved from 34 entries to 23.
- Eleven scenarios for the removed plugins left `manual-testing-playbook/plugin-tie-ins/`.
- Section 12 of `manual-testing-playbook/manual-testing-playbook.md` keeps `OBS-014`, `OBS-015` and `OBS-021`.
- They were deliberately not renumbered.
- The surviving files are `health-md-data.md`, `iconic-rules.md` and `theme-activation.md`.

#### Workflow Pointers Change <a id="c-workflow-pointers-change"></a>

- The Obsidian Tables and BRAT procedures became pointers.
- They point to the retained plugins' own workflow files.
- The replacement pointers lead to Iconic and Health.md workflows.
- `assets/workflows.md` points to `references/plugins/iconic/workflows.md` and `references/plugins/health-md/workflows.md` for Iconic and Health.md workflows.
- `feature-catalog/cli/uri-actions.md` lost one dead link to the BRAT reference.

## Routing and Reference Records

The router and reference records were narrowed to the retained surface. The roster still names every installed plugin.

#### The Intent Set Shrinks <a id="c-the-intent-set-shrinks"></a>

- The frontmatter description, `keywords` comment, activation triggers and §8 reference inventory in `SKILL.md` were reduced.
- They now match the surviving surface.
- Twelve `PLUGIN_*` intents left `INTENT_SIGNALS` and `RESOURCE_MAP`.
- They were `PLUGIN_ADVANCED_CANVAS`, `PLUGIN_CHARTS`, `PLUGIN_CLAUDIAN`, `PLUGIN_DATAVIEW`, `PLUGIN_GIT`, `PLUGIN_MAKEMD`, `PLUGIN_META_BIND`, `PLUGIN_NOTION_BASES`, `PLUGIN_LOCAL_REST_API`, `PLUGIN_TABLES`, `PLUGIN_BRAT` and `PLUGIN_OUTLINER`.
- The `specific_plugin_intents` tuple now holds `PLUGIN_ICONIC`, `PLUGIN_HEALTH` and `THEME_SYSTEM`.
- The generic `PLUGINS` intent points to `references/plugins/plugin-operation-logic.md`, `references/plugins/installed-plugins.md`, `references/plugins/iconic/iconic.md`, `references/plugins/health-md/health-md.md` and `references/themes/themes.md`.
- All eight router targets of the retained intents resolve.
- `PLUGIN_ICONIC`, `PLUGIN_HEALTH`, `THEME_SYSTEM` and `PLUGINS` load only files that exist on disk.

#### The Roster Fits the File Layer <a id="c-the-roster-fits-the-file-layer"></a>

- The previous two-class split did not describe thirteen file-layer plugins.
- They lost dedicated documentation without losing their file layer.
- The roster now has two documented file-layer plugins.
- It also has thirteen file-layer plugins whose dedicated documentation was removed.
- Nine UI or automatic plugins complete the list.
- They add up to the same 24 plugins.
- The roster names every installed plugin.
- Its standing warning never to remove `obsidian-local-rest-api` was unchanged.
- That is because it concerns the vault plugin, not its documentation.
- All 24 community plugins remain enabled in `.obsidian/community-plugins.json`.
- All of them still work.

#### Reference Tables Narrow <a id="c-reference-tables-narrow"></a>

- The plugin operation map and README table were narrowed.
- The data map in `references/plugins/plugin-operation-logic.md` went from ten artifacts to three.
- The three are health-md, iconic and minimal.
- The `README.md` plugin knowledge-layer table has three entries.
- They are Health.md, Iconic and the theme system.
- The README table now has three rows instead of fourteen.

#### Notion Migration Keeps Its Steps <a id="c-notion-migration-keeps-its-steps"></a>

- The eight-step Notion migration method is unchanged.
- Only its pointers into the deleted doc sets were removed.
- `references/notion-migration.md` still depends on the Notion Bases, Meta Bind, JS Engine and Dataview plugins.
- All four are still installed.

#### Version History Stays Intact <a id="c-version-history-stays-intact"></a>

- `references/plugins/installed-plugins.md` and `references/plugins/plugin-operation-logic.md` were edited without a version bump.
- `changelog/v0.22.0.0.md` records the addition of the `make-md` tree.
- It also records the `PLUGIN_MAKEMD` intent.
- Historical changelog entries were left as written.

## Vault and MCP Transport

The vault and the MCP transport were left untouched. The Local REST API setup was already documented elsewhere.

#### Themes Stay Unchanged <a id="c-themes-stay-unchanged"></a>

- The theme system was not part of the plugin removal.
- The theme system under `references/themes/` is untouched.
- It is not a plugin and was never in question.
- No theme was ever a plugin row.
- Themes live under `.obsidian/themes/` and appearance settings, not in `community-plugins.json`.

#### Local REST API Setup Is Covered <a id="c-local-rest-api-setup-is-covered"></a>

- The Local REST API reference set was removed.
- The cyanheads MCP path is unaffected.
- Its setup, port, API key and failure modes were already documented elsewhere.
- They sit outside the removed reference set.
- They sit in `INSTALL-GUIDE.md`.
- They also sit in `references/troubleshooting.md` §6 (Local REST API issues) and §7 (authentication issues).
- The Local REST API plugin is the transport.
- The cyanheads MCP rides on it.
- The setup facts the MCP path depends on were located in their surviving homes.
- One is `INSTALL-GUIDE.md`.
- It has Local REST API v4.0.0+, `OBSIDIAN_API_KEY`, `OBSIDIAN_BASE_URL` and the connection-refused and 401 rows.
- The other is `references/troubleshooting.md` §6 and §7.
