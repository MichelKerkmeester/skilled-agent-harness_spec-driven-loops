# v0.9.0.0, Effective AI Use Inside Obsidian

This release corrects the skill's stated purpose. It also rewrites the README in the repo-root narrative voice. The skill exists solely for effective AI use inside Obsidian. It works through an agent that can read, write, search and extend the vault. The agent has proper plugin knowledge. So community plugins are operated as data. The three execution surfaces are means to that purpose. They are not the skill's identity. A concurrent deep-loop containment sweep deleted the never-committed entry. Its content was restored from the session record.

## What's New at a Glance

- **`README.md` moves from version `0.1.0.0` to `0.2.0.0`.** It follows the sk-create-skill README template. It uses the repo-root voice as a narrative, purpose-first README. It includes a one-line pitch blockquote. It has AT A GLANCE and a problem-first OVERVIEW. It has a dedicated Plugin Knowledge Layer. That layer names Beancount Ledger, Obsidian Tables, BRAT, Health.md and Iconic. It also has QUICK START. HOW IT WORKS covers the router, file-layer doctrine and safety invariants. INTEGRATION & NAVIGATION and TROUBLESHOOTING follow. It also has FAQ, VERIFICATION and RELATED DOCUMENTS. Those link the feature catalog and manual testing playbook.
- **`SKILL.md` moves from version `0.7.0.0` to `0.9.0.0`.** Its frontmatter `description` changes. The old value was "routes Obsidian between two CLI profiles". The new value is the true purpose. That purpose is effective AI use inside Obsidian. The purpose carries deep plugin knowledge operated at the file layer. The H1 intro carries that corrected message.

## Upgrade

No migration required. Routing logic, rules, references and resource maps were untouched. Assets, feature catalog and playbook content were unchanged. No Markdown outside `README.md` and `SKILL.md` was modified. No vault, plugin, phase or hub files were touched.
