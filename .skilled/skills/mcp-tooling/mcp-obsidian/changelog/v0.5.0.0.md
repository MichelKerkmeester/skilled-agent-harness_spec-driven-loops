# Iconic Support for mcp-obsidian

mcp-obsidian v0.5.0.0 extends the mode's plugin knowledge with Iconic (`iconic`), using the existing per-plugin pattern of an index, data-model, workflows and troubleshooting.

## What's New at a Glance

- **The Iconic reference set covers its single `data.json` configuration and rule schema.** `references/plugins/iconic/` includes visibility toggles, color pickers, per-item icon maps, 21 `fileRules`, 11 `folderRules` and `{id, name, icon lucide-*, color hex, match, conditions, enabled}`.
- **The Iconic reference set carries a mandatory backup-before-merge discipline.** Back up before merging. Merge, never replace. Never downgrade.
- **`SKILL.md` gains activation triggers for icon/rule requests.** It moves from version 0.4.0.0 to 0.5.0.0 in its frontmatter and keywords, adds the Iconic reference set to load-on-demand and extends the keyword comment. The data map in `plugin-operation-logic.md` grows from 4 to 5 rows.
- **The catalog and playbook add Iconic entries.** `feature-catalog/plugins/iconic.md` is the feature card, and the plugin category in `feature-catalog/FEATURE-CATALOG.md` grows from 4 to 5 plugins. `manual-testing-playbook/manual-testing-playbook.md` adds scenario `OBS-015` for an Iconic rulebook merge round-trip, moving from 20 to 21 scenarios (`OBS-011`..`OBS-015`). Indexes are updated.
- **The Iconic asset is an example rulebook excerpt.** `assets/plugins/iconic/iconic-rules.example.json` is the excerpt. No plugin code is vendored.
- **The four existing plugin reference sets were untouched.** The shared data-map table was the exception.
- **Vault install state was untouched.** Iconic v1.1.10 was already installed and enabled in all three vaults with the rulebook already applied.

## Upgrade

No migration required.
