`mcp-obsidian` v0.19.0.0 grounds Notion Bases guidance in the plugin's confirmed README. It also gives `obsidian-local-rest-api` a dedicated reference tree. So readers can find confirmed Notion Bases details. They can also find consolidated local API guidance. This work did not access a vault or install a plugin. The operator's existing v1.12.0 vault installation is the confirming source. The release stays limited to the plugin reference trees, `SKILL.md` and this changelog.

&nbsp;

## Why This Release

Phase 003 authored the Notion Bases reference tree before the plugin was installed anywhere. So its schema examples were correctly marked `VERIFY`. The operator's vault installation at v1.12.0 surfaced the plugin's README. That README confirmed most of those facts. It exposed the `nb-database` embed syntax. It also corrected the rollup keyword from `average` to `avg`.

`obsidian-local-rest-api` was the one enabled vault plugin without a dedicated reference folder. Its behavior was already documented in `SKILL.md` §3, `references/mcp-tools.md` and `references/troubleshooting.md`. But that guidance was scattered. It was not consolidated into the per-plugin shape. Every other plugin uses that shape.

&nbsp;

## What's New at a Glance

- The Notion Bases reference tree now states the README-confirmed schema.
  - A database is a folder with `_database.md` and per-row frontmatter.
  - The README confirms 18 exact column types (`title, text, number, select, multiselect, checkbox, date, url, email, phone, status, formula, relation, lookup, image, rollup, audio, video`).
  - The README confirms 7 exact view types (`table, list, board, gallery, calendar, timeline, chart`).
  - The README confirms 7 exact rollup functions (`sum, count, avg, min, max, count_values, list`).
  - Here `avg` corrects the earlier `average`.
- One upfront note now separates confirmed shapes from unresolved YAML keys.
  - The note replaces repeated `VERIFY exact keys` headers.
  - The note confirms the shapes.
  - The note leaves the exact per-column YAML key spelling inside an `_database.md` declaration unconfirmed.
- The `nb-database` fenced-code-block embed syntax now documents a previously undescribed way to render a view inside a note.
  - The syntax appears in `notion-bases.md` §2 and `data-model.md` §6.
  - `workflows.md` §6 adds a step and checkpoint.
  - `troubleshooting.md` adds matching failure modes.
  - The failure modes cover sections 1, 2, 5, 7 and 8.
- `references/plugins/obsidian-local-rest-api/` now has a four-file tree matching the Dataview shape.
  - The tree consolidates existing guidance from `SKILL.md`, `references/mcp-tools.md` and `references/troubleshooting.md`.
  - That guidance covers the `OBSIDIAN_API_KEY`, `OBSIDIAN_BASE_URL` and `OBSIDIAN_VERIFY_SSL` environment contract.
  - The guidance covers two loopback endpoints (connections to the local computer).
  - The guidance covers the requirement that the app be running.
  - None of this duplicates or moves existing `SKILL.md` content.
- `SKILL.md` adds `PLUGIN_LOCAL_REST_API` as an additive-only router intent.
  - The intent mirrors `PLUGIN_DATAVIEW` across §2 Resource Loading Levels, `INTENT_SIGNALS`, `RESOURCE_MAP`, the `PLUGINS` aggregate and the `specific_plugin_intents` tuple.
  - §8 References also mirrors it.
  - The `INTENT_SIGNALS` count comment changes from eighteen to nineteen.
  - The `SKILL.md` version changes from `0.18.0.0` to `0.19.0.0`.
- The Dataview tree and Phase 003 deliverables stay unchanged.
  - The `references/plugins/dataview/*` tree was not edited.
  - The Notion Bases Dataview-supplement section still points to it.
  - The section does not duplicate its content.
  - `feature-catalog/plugins/notion-bases.md` and the `OBS-022` manual-testing scenario remain as-is.
