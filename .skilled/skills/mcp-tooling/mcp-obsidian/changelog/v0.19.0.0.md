`mcp-obsidian` v0.19.0.0 grounds Notion Bases guidance in the plugin's confirmed README and gives `obsidian-local-rest-api` a dedicated reference tree, so readers can find confirmed Notion Bases details and consolidated local API guidance. This work did not access a vault or install a plugin. The operator's existing v1.12.0 vault installation is the confirming source, and the release stays limited to the plugin reference trees, `SKILL.md` and this changelog.

> Spec folder: `specs/mcp-tooling/015-notion-to-obisidian-migration/003-notion-bases-plugin-tie-in/` (Level 2)

## Why This Release

Phase 003 authored the Notion Bases reference tree before the plugin was installed anywhere, so its schema examples were correctly marked `VERIFY`. The operator's vault installation at v1.12.0 surfaced the plugin's README, which confirmed most of those facts, exposed the `nb-database` embed syntax and corrected the rollup keyword from `average` to `avg`.

`obsidian-local-rest-api` was the one enabled vault plugin without a dedicated reference folder. Its behavior was already documented in `SKILL.md` §3, `references/mcp-tools.md` and `references/troubleshooting.md`, but it was scattered rather than consolidated into the per-plugin shape used by every other plugin.

## What's New at a Glance

- **The Notion Bases reference tree now states the README-confirmed schema.** A database is a folder with `_database.md` and per-row frontmatter. The README confirms 18 exact column types (`title, text, number, select, multiselect, checkbox, date, url, email, phone, status, formula, relation, lookup, image, rollup, audio, video`), 7 exact view types (`table, list, board, gallery, calendar, timeline, chart`) and 7 exact rollup functions (`sum, count, avg, min, max, count_values, list`), with `avg` correcting the earlier `average`.
- **One upfront note now separates confirmed shapes from unresolved YAML keys.** It replaces repeated `VERIFY exact keys` headers, confirms the shapes and leaves the exact per-column YAML key spelling inside an `_database.md` declaration unconfirmed.
- **The `nb-database` fenced-code-block embed syntax now documents a previously undescribed way to render a view inside a note.** It appears in `notion-bases.md` §2 and `data-model.md` §6, while `workflows.md` §6 adds a step and checkpoint and `troubleshooting.md` adds matching failure modes in sections 1, 2, 5, 7 and 8.
- **`references/plugins/obsidian-local-rest-api/` now has a four-file tree matching the Dataview shape.** It consolidates existing guidance from `SKILL.md`, `references/mcp-tools.md` and `references/troubleshooting.md` on the `OBSIDIAN_API_KEY`, `OBSIDIAN_BASE_URL` and `OBSIDIAN_VERIFY_SSL` environment contract, two loopback endpoints (connections to the local computer) and the requirement that the app be running, without duplicating or moving existing `SKILL.md` content.
- **`SKILL.md` adds `PLUGIN_LOCAL_REST_API` as an additive-only router intent.** It mirrors `PLUGIN_DATAVIEW` across §2 Resource Loading Levels, `INTENT_SIGNALS`, `RESOURCE_MAP`, the `PLUGINS` aggregate, the `specific_plugin_intents` tuple and §8 References. The `INTENT_SIGNALS` count comment changes from eighteen to nineteen, and the `SKILL.md` version changes from `0.18.0.0` to `0.19.0.0`.
- **The Dataview tree and Phase 003 deliverables stay unchanged.** The `references/plugins/dataview/*` tree was not edited, and the Notion Bases Dataview-supplement section still points to it without duplicating its content. `feature-catalog/plugins/notion-bases.md` and the `OBS-022` manual-testing scenario remain as-is.

No migration required.
