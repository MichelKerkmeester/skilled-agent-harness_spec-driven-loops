# v0.21.0.0, Notion Parity for the Plugin Stack

This release moves the vault's plugin stack toward Notion parity on Notion Bases.

- Excalidraw and Project Manager are removed from the skill and the vault.
- A Meta Bind reference documents a Notion-style start/stop task timer.
- A Notion Bases Calendar-view recipe is added.
- `PLUGIN_META_BIND` is added to the router.

The installed-plugin roster is reconciled to the 24-plugin vault.

- It adds Meta Bind, JS Engine, Dragger, Bullet Depth Markers and Dynamic Outline.
- It removes the Excalidraw and Project Manager rows.
- Both were uninstalled.

&nbsp;

## Why This Release

Project Manager's task-tracking role is consolidated onto Notion Bases + Meta Bind. So a dedicated PM plugin is redundant.

## Skill Changes

Two plugins leave the skill's wiring, and Meta Bind joins the router.

#### Excalidraw Material Is Removed <a id="c-excalidraw-material-is-removed"></a>

- The plugin was uninstalled from the vault the same day.
- These were deleted: the four-file `references/plugins/excalidraw/` tree, `feature-catalog/plugins/excalidraw.md`, the two-file `assets/plugins/excalidraw/` tree and `manual-testing-playbook/plugin-tie-ins/excalidraw-drawing-note.md`.
- `PLUGIN_EXCALIDRAW` was stripped from `SKILL.md`'s §2 loading.
- It was also stripped from `INTENT_SIGNALS`, `RESOURCE_MAP` and the `PLUGINS` aggregate.
- The same goes for the `specific_plugin_intents` tuple, the headline plugin list and the keyword comment.
- Excalidraw references were also removed from `README.md`, `feature-catalog/FEATURE-CATALOG.md` and `plugin-operation-logic.md`.
- They were removed from the manual-testing playbook scenario `OBS-018` too.

#### Project Manager Material Is Removed <a id="c-project-manager-material-is-removed"></a>

- The four-file `references/plugins/project-manager/` tree was deleted.
- So was `feature-catalog/plugins/project-manager.md`.
- `PLUGIN_PROJECT_MANAGER` was stripped from `SKILL.md`.
- It went at the same wiring points as Excalidraw.
- The roster's overlap note is updated.

#### Meta Bind Joins the Router <a id="c-meta-bind-joins-the-router"></a>

- `PLUGIN_META_BIND` is added to the router.
- The `INTENT_SIGNALS` count comment changes from `twenty-two` to `twenty-one`.
- That follows two removals and one addition.
- The additive intent follows the existing per-plugin pattern.
- In `SKILL.md`, its wiring covers §2 loading, `INTENT_SIGNALS` and `RESOURCE_MAP`.
- It also covers the `specific_plugin_intents` tuple, the `PLUGINS` aggregate and §8 References.
- `SKILL.md` changes from version 0.20.0.0 to 0.21.0.0.

## Notion References

Meta Bind gains a task reference, and Notion Bases gains a calendar recipe.

#### A Notion-Style Task Timer <a id="c-a-notionstyle-task-timer"></a>

- The new four-file `references/plugins/meta-bind/` tree has an index, data-model, workflows and troubleshooting files.
- It sits alongside `feature-catalog/plugins/meta-bind.md`.
- It documents `INPUT[]`/`VIEW[]`/`BUTTON[]` syntax and the `meta-bind-button` action catalog.
- Start/End buttons stamp frontmatter timestamps over a Notion Bases task database.
- A Bases formula column totals them.
- The `js-engine` companion is documented within this tree.
- The evaluated-expression grammar and the `js`-action signature are flagged `VERIFY`.
- They are grounded in the plugin docs fetched 2026-08-22, not invented.

#### Notion Bases Gains a Calendar Recipe <a id="c-notion-bases-gains-a-calendar-recipe"></a>

- It sits in `references/plugins/notion-bases/workflows.md` §6a.
- The recipe builds an inline, Notion-style month calendar.
- It uses the database's own notes and tasks, through a date column.
- There is no external calendar sync.
- It adds a `calendar_view_valid` checkpoint.
