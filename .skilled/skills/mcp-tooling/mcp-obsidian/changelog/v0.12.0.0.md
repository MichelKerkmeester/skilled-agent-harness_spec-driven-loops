# mcp-obsidian v0.12.0.0

A version-scheme correction. The mode was authored on a `1.x` track, but a `1.0` release is a readiness declaration that was never actually made. This release resets the entire package onto a pre-1.0 `0.x` track so the numbers tell the truth: the mode is still maturing. Every historical release was renumbered in order, and the two release heads that had drifted apart are unified.

## 1. NEW

No new CLI, MCP, plugin or theme surface. Skill behavior is unchanged from the prior head. This release is numbering only.

---

## 2. CHANGED

- **Whole-package renumber.** Every `version` field across the package and every changelog filename moved from the old `1.x` track to a `0.x` track, one flat step per release: the first release became `v0.1.0.0`, the last became `v0.11.0.0`, and the two off-track per-file versions moved with their base release. External tool versions (the Local REST API, `obsidian-mcp-server`, `notesmd-cli`, Health.md and Minimal) were left untouched.
- **Heads unified.** `SKILL.md` (was `0.10.0.0`) and `README.md` (was `0.11.0.0`) both move to `0.12.0.0` so the two documents agree on the release head again.

---

## 3. NOT CHANGED

- No reference set, feature-catalog card, playbook scenario, asset or script content changed beyond the version tokens themselves.
- No vault, plugin or runtime data was touched.
- The renumbered changelog entries `v0.1.0.0` through `v0.11.0.0` keep their original wording, with only their own version tokens rewritten to the new track.
