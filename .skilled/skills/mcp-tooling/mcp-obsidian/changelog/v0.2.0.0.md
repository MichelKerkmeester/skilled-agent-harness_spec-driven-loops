## Adopted Surface Set

| Surface | Adopted package or binary | Runtime model |
|---|---|---|
| Headless CLI | Yakitrak notesmd-cli | Operates directly on the vault filesystem with no running app |
| App-backed CLI | Official obsidian CLI in Obsidian desktop v1.12.4+ | Remote-controls a live desktop app after in-app registration |
| Default MCP | cyanheads obsidian-mcp-server@3.2.9 | Code Mode stdio server using Local REST API v4.0.0+ and a bearer token |
| Community plugin data | Beancount Ledger, Tables, and BRAT files | File-layer edits followed by plugin/app reload where rendering or activation must be observed |

---

## Architecture Decisions

| Decision | Choice | Rationale |
|---|---|---|
| Plugin routing | Specific finance, Tables, and BRAT intents plus generic fallback | A finance request should not load unrelated plugin references; bare plugin requests still need a usable catch-all |
| Plugin operations | File-layer data edits | The mode can operate the files each plugin reads without pretending to drive command palettes or dashboards |
| Finance identity | Beancount Ledger from mkshp-dev/obsidian-finance-plugin | The tagged manifest and inspected source define the current plugin identity and data contract |
| Validation boundary | Parse and verify files, then reload when a visible render/activation check is required | A valid file proves persistence, while the app proves the plugin can consume the changed data |

---

## Upgrade Notes

The existing slim plugin indexes remain the front door. Named finance, Tables, or BRAT requests now load the corresponding deep subfolder documents; generic plugin requests load only the shared operation logic and three indexes. The two new playbook scenarios require controlled vault fixtures and preserve the existing PASS/FAIL/SKIP evidence rules.

---

## Known Limitations

- The Tables render check still requires an Obsidian app with the Tables plugin enabled; file parsing alone does not prove the visible view.
- BRAT staging requires a real or captured GitHub release, exact asset selection, curl, and jq; no token value belongs in BRAT data.json.
- Beancount validation and price/query operations depend on the local bean-check, bean-query, and bean-price executables.
- The official obsidian CLI action syntax remains a local VERIFY boundary where the scenarios request an app reload or open action.
