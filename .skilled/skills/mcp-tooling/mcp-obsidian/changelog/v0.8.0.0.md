Health.md example assets and supporting documentation now match the export and chart contracts the plugin implements. The playbook, catalog card and operation-logic row still framed the plugin as Apple-only with no guard against bundled mock data. The assets now follow the researched v7 daily-summary shape and `health-viz` render contract, while the docs carry the mock-fallback guard and Apple/Android framing.

> Research source: `.opencode/specs/mcp-tooling/013-mcp-obsidian/012-skill-support-extension/research/lineages/codex/research.md` (Health.md plugin deep dive: v7 export shape in section 1, health-viz render grammar in section 3, file layers in section 4, Apple/Android boundaries in section 5, reference-set remediation order in section 7).

## What's New at a Glance

- **The fixture follows the v7 export shape.** It uses the `healthmd.health_data` wrapper, `schema_version` 7 and `timezone`, plus two `days` entries with `date` plus `statistics` including canonical `unit` values. The previous fixture included `source`, a key real v7 exports never write, so copy-paste examples no longer teach a false schema that invites validation failures.
- **A new asset shows six researched-validated `health-viz` blocks.** `health-viz-blocks.example.md` shows only researched forms for the registered `step-spiral` renderer, using documented keys (`width`, `height`, `from`, `to`, `last` and `clickAction`) and the `{{today:YYYY-MM-DD}}` dynamic date variable. The old quick-start fence could not be read and used invented options no registered renderer accepts, so charts silently fell back to bundled mock data, and the new asset warns that a chart rendered from an empty folder is bundled mock data, not proof of real exports.
- **The catalog card covers Apple and Android.** It corrects the Apple-only framing and wrong fence description and replaces the JSON-fixture-only asset list with both example assets. It covers Apple v7 plus Android frozen v4 and analytical v5 profiles, shared chart coverage and platform gaps (iOS-only mood and medication, the Android walking-symmetry gap and a steps-derived Stand proxy), then documents `health-viz` render blocks, the mock-fallback warning and guardrails to verify mock fallback, exclude raw/lossless archives and never synthesize observations, roll-ups or dictionaries.
- **The health-md operation-logic row covers both platforms.** `references/plugins/plugin-operation-logic.md` names Apple and Android Health export files and `health-viz` render blocks. It requires verifying the real folder plus an authentic source because bundled mock data renders on an empty folder.
- **OBS-014's scenario moves from `0.4.0.0` to `0.4.1.0`.** The scenario in `manual-testing-playbook/plugin-tie-ins/health-md-data.md` still taught the old fence with invented keys and wrote a `source` key real exports never carry. It now resolves the actual data folder from settings and lists it before any write, verifies the selected folder plus at least one authentic source file, states that a missing or empty folder renders deterministic bundled example data and no chart counts as evidence, writes the schema-true throwaway shape with only `schema_version`/`timezone`/`days` pointing to the canonical fixture, places the researched-validated `health-viz` block (`type: step-spiral`, `last: 7`) and grades mock-only evidence `FAIL`.
