Health.md example assets and supporting documentation now match the export and chart contracts. The plugin implements those contracts. The playbook, catalog card and operation-logic row still framed the plugin as Apple-only. They had no guard against bundled mock data. The assets now follow the researched v7 daily-summary shape. They also follow the `health-viz` render contract. The docs carry the mock-fallback guard and the Apple/Android framing.

> Research source: `.opencode/specs/mcp-tooling/013-mcp-obsidian/012-skill-support-extension/research/lineages/codex/research.md` (Health.md plugin deep dive: v7 export shape in section 1, health-viz render grammar in section 3, file layers in section 4, Apple/Android boundaries in section 5, reference-set remediation order in section 7).

## What's New at a Glance

- **The fixture follows the v7 export shape.** It uses the `healthmd.health_data` wrapper, `schema_version` 7 and `timezone`. It also has two `days` entries with `date` plus `statistics`. Those statistics include canonical `unit` values. The previous fixture included `source`. Real v7 exports never write that key. So copy-paste examples no longer teach a false schema. That schema invites validation failures.
- **A new asset shows six researched-validated `health-viz` blocks.** `health-viz-blocks.example.md` shows only researched forms for the registered `step-spiral` renderer. It uses documented keys (`width`, `height`, `from`, `to`, `last` and `clickAction`). It also uses the `{{today:YYYY-MM-DD}}` dynamic date variable. The old quick-start fence could not be read. It used invented options no registered renderer accepts. So charts silently fell back to bundled mock data. The new asset warns that a chart rendered from an empty folder is bundled mock data. That is not proof of real exports.
- **The catalog card covers Apple and Android.** It corrects the Apple-only framing and the wrong fence description. It replaces the JSON-fixture-only asset list with both example assets. It covers Apple v7 plus Android frozen v4 and analytical v5 profiles. It covers shared chart coverage and platform gaps. Those gaps are iOS-only mood and medication, the Android walking-symmetry gap and a steps-derived Stand proxy. It then documents `health-viz` render blocks and the mock-fallback warning. It also documents guardrails. Those guardrails verify mock fallback, exclude raw/lossless archives and never synthesize observations, roll-ups or dictionaries.
- **The health-md operation-logic row covers both platforms.** `references/plugins/plugin-operation-logic.md` names Apple and Android Health export files. It also names `health-viz` render blocks. It requires verifying the real folder plus an authentic source. That is because bundled mock data renders on an empty folder.
- **The Health.md data-file round-trip scenario moves from `0.4.0.0` to `0.4.1.0`.** The scenario in `manual-testing-playbook/plugin-tie-ins/health-md-data.md` still taught the old fence with invented keys. It wrote a `source` key real exports never carry. It now resolves the actual data folder from settings. It lists that folder before any write. It verifies the selected folder plus at least one authentic source file. It states that a missing or empty folder renders deterministic bundled example data. It states that no chart counts as evidence. It writes the schema-true throwaway shape with only `schema_version`/`timezone`/`days`. That shape points to the canonical fixture. It places the researched-validated `health-viz` block (`type: step-spiral`, `last: 7`). It grades mock-only evidence `FAIL`.
