# mcp-obsidian v0.1.0.0: Initial Release

mcp-obsidian brings Obsidian's headless CLI, app-backed CLI, MCP and plugin data operations into one profile-routed skill.

- It gives users setup guidance, references and examples.
- They help users choose among these surfaces and understand their requirements.

The release documents setup, CLI, MCP and plugin work.

- `SKILL.md` routes Obsidian requests by profile.
- Setup guidance covers installation, registration and MCP configuration.
- Three runnable scripts demonstrate workflows.

Several access paths are documented.

- `notesmd-cli` and the official `obsidian` CLI cover different contexts.
- Cyanheads and StevenStavrakis MCP options are documented.
- Plugin references cover file-layer operations.

&nbsp;

## Why This Release

App-backed paths have hard prerequisites. The headless path does not.

- Runtime profile selection keeps these operating choices distinct.

## Skill Routing

`SKILL.md` is an eight-section skill definition with profile-based routing.

#### Route Requests by Profile <a id="c-route-requests-by-profile"></a>

- It brings activation signals, safety guidance and surface comparisons into one skill.
- Section 1 lists activation signals for Obsidian, vault, note, plugin, Local REST API and MCP.
- Section 2 uses `INTENT_SIGNALS`, `RESOURCE_MAP` and a resource router for CLI, MCP, plugins, installation and troubleshooting requests.
- Section 3 compares headless `notesmd-cli`, the app-backed official `obsidian` CLI and cyanheads MCP.
- Section 4 sets vault, destructive-operation, tool-name and Local REST API safety invariants.
- Sections 5-8 cover success criteria, integrations, a quick reference and related resources.

## Setup and Recovery

The installer and guide describe the setup paths.

#### Install With Clear Boundaries <a id="c-install-with-clear-boundaries"></a>

- `scripts/install.sh` provides embedded installation guidance and a setup pointer.
- It installs `notesmd-cli` through Homebrew when available.
- Otherwise it prints verified Scoop, AUR and source-build alternatives.
- Separately, it prints in-app registration steps for the official `obsidian` CLI.
- It does this without changing the app.
- For Code Mode, it prints the `obsidian` manual and `obsidian_OBSIDIAN_*` environment keys.
- It does this without writing configuration files.
- It supports `--check-only` and `--mcp-only`.
- MCP configuration is documented and printed as a manual only.
- It is not applied automatically.
- The mode must not automatically modify `.utcp_config.json` or `.env.example`.

#### Prepare and Recover <a id="c-prepare-and-recover"></a>

- `INSTALL-GUIDE.md` starts with an AI-first install block.
- It covers headless vault registration and official CLI enablement.
- It gives cyanheads MCP prerequisites and a manual configuration reference.
- It also gives verification and troubleshooting checkpoints.
- `references/troubleshooting.md` covers installation, PATH, app registration, Local REST API, authentication and MCP recovery.

## CLI and MCP Access

`notesmd-cli` works on vault files while the official `obsidian` CLI controls the live app.

#### Choose the Right CLI <a id="c-choose-the-right-cli"></a>

- `notesmd-cli` is the default CLI.
- Yakitrak `notesmd-cli` operates directly on vault files.
- It needs no running app or token.
- One works with vault files.
- The other controls the live app.
- The official `obsidian` binary is the app-backed CLI for live UI and app-context outcomes.
- In Obsidian desktop v1.12.4+, it remote-controls a live app after in-app registration.

#### Keep CLI Commands Verifiable <a id="c-keep-cli-commands-verifiable"></a>

- `references/obsidian-cli-commands.md` is the headless and app-backed CLI reference.
- It covers vault registration, note read and mutate commands, safety patterns and `VERIFY` boundaries for unconfirmed flags.
- The official `obsidian` CLI's full command and flag inventory is not confirmed.
- After enabling it, run `obsidian --help`.
- Mark unconfirmed specifics `VERIFY`.

#### Connect Through Cyanheads MCP <a id="c-connect-through-cyanheads-mcp"></a>

- Cyanheads `obsidian-mcp-server@3.2.9` is the default MCP.
- Of the two documented MCP options, the first is the default.
- It is also a Code Mode stdio (standard input and output) server.
- It provides structured note, search, tag and delete operations through Local REST API.
- It uses Local REST API v4.0.0+ with a bearer token.
- It requires a running Obsidian app and an API key.
- `references/mcp-tools.md` covers Local REST API requirements and Code Mode invocation.
- Five core tool names are confirmed within the 14-tool surface.
- Enumerate the full surface with `list_tools()`.
- Confirm signatures with `tool_info()` before use.

#### Assess the Headless Alternative <a id="c-assess-the-headless-alternative"></a>

- StevenStavrakis `obsidian-mcp@1.0.6` is a filesystem-based headless MCP alternative.
- The second is a filesystem-based alternative.
- It is documented for context only.
- Verify its no-app/no-token behavior in the target environment before relying on it.

## Plugin Data and Examples

Plugin operations are file-layer data edits of the plain files plugins render.

#### Work With Plugin Data <a id="c-work-with-plugin-data"></a>

- They are not plugin UI operations.
- Plugin references cover file-layer operations.
- They include guidance for Beancount data, table data and beta-plugin installation context.
- `references/plugins/` provides file-layer plugin operation references.
- `beancount-finance.md` covers Beancount Ledger data.
- `obsidian-tables.md` documents `.table.md` JSON data.
- `obsidian42-brat.md` gives beta-plugin installation context.
- `plugin-operation-logic.md` describes the general data-over-UI model.

#### Run the Example Workflows <a id="c-run-the-example-workflows"></a>

- They cover headless notes, an MCP roundtrip and a Beancount transaction.
- `examples/headless-notes-workflow.sh` checks vault registration and searches.
- It creates a note idempotently and reads it back using `notesmd-cli`.
- `examples/mcp-roundtrip.sh` is a read-only preflight.
- It prints the Code Mode MCP roundtrip pattern.
- `examples/beancount-transaction.sh` appends a balanced Beancount transaction.
- It can optionally run `bean-check` validation.
- `examples/README.md` indexes the three scripts.
- It lists prerequisites, usage, safety boundaries and troubleshooting.
