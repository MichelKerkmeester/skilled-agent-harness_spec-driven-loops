# mcp-obsidian v0.1.0.0: Initial Release

mcp-obsidian brings Obsidian's headless CLI, app-backed CLI, MCP and plugin data operations into one profile-routed skill. It gives users setup guidance, references and examples for choosing among these surfaces and understanding their requirements.

## Why This Release

App-backed paths have hard prerequisites that the headless path does not. Runtime profile selection keeps these operating choices distinct.

## What's New at a Glance

- **`SKILL.md` routes Obsidian requests by profile.** It brings activation signals, safety guidance and surface comparisons into one skill.
- **Setup guidance covers installation, registration and MCP configuration.** The installer and guide describe these paths without applying MCP configuration automatically.
- **`notesmd-cli` and the official `obsidian` CLI cover different contexts.** One works with vault files while the other controls the live app.
- **Cyanheads and StevenStavrakis MCP options are documented.** The first is the default while the second is a filesystem-based alternative.
- **Plugin references cover file-layer operations.** They include guidance for Beancount data, table data and beta-plugin installation context.
- **Three runnable scripts demonstrate workflows.** They cover headless notes, an MCP roundtrip and a Beancount transaction.

## Skill Routing

#### Route Requests by Profile

`SKILL.md` is an eight-section skill definition with profile-based routing. Section 1 lists activation signals for Obsidian, vault, note, plugin, Local REST API and MCP. Section 2 uses `INTENT_SIGNALS`, `RESOURCE_MAP` and a resource router for CLI, MCP, plugins, installation and troubleshooting requests. Section 3 compares headless `notesmd-cli`, the app-backed official `obsidian` CLI and cyanheads MCP. Section 4 sets vault, destructive-operation, tool-name and Local REST API safety invariants. Sections 5-8 cover success criteria, integrations, a quick reference and related resources.

## Setup and Recovery

#### Install With Clear Boundaries

`scripts/install.sh` provides embedded installation guidance and a setup pointer. It installs `notesmd-cli` through Homebrew when available, otherwise it prints verified Scoop, AUR and source-build alternatives. Separately, it prints in-app registration steps for the official `obsidian` CLI without changing the app. For Code Mode, it prints the `obsidian` manual and `obsidian_OBSIDIAN_*` environment keys without writing configuration files. It supports `--check-only` and `--mcp-only`. MCP configuration is documented and printed as a manual only, not applied automatically, and the mode must not automatically modify `.utcp_config.json` or `.env.example`.

&nbsp;

#### Prepare and Recover

`INSTALL-GUIDE.md` starts with an AI-first install block and covers headless vault registration and official CLI enablement. It gives cyanheads MCP prerequisites and a manual configuration reference, with verification and troubleshooting checkpoints. `references/troubleshooting.md` covers installation, PATH, app registration, Local REST API, authentication and MCP recovery.

## CLI and MCP Access

#### Choose the Right CLI

`notesmd-cli` is the default CLI. Yakitrak `notesmd-cli` operates directly on vault files without a running app or token. The official `obsidian` binary is the app-backed CLI for live UI and app-context outcomes. In Obsidian desktop v1.12.4+, it remote-controls a live app after in-app registration.

&nbsp;

#### Keep CLI Commands Verifiable

`references/obsidian-cli-commands.md` is the headless and app-backed CLI reference. It covers vault registration, note read and mutate commands, safety patterns and `VERIFY` boundaries for unconfirmed flags. The official `obsidian` CLI's full command and flag inventory is not confirmed. After enabling it, run `obsidian --help` and mark unconfirmed specifics `VERIFY`.

&nbsp;

#### Connect Through Cyanheads MCP

Cyanheads `obsidian-mcp-server@3.2.9` is the default MCP and a Code Mode stdio (standard input and output) server. It provides structured note, search, tag and delete operations through Local REST API, and uses Local REST API v4.0.0+ with a bearer token. It requires a running Obsidian app and an API key. `references/mcp-tools.md` covers Local REST API requirements and Code Mode invocation. Five core tool names are confirmed within the 14-tool surface. Enumerate the full surface with `list_tools()` and confirm signatures with `tool_info()` before use.

&nbsp;

#### Assess the Headless Alternative

StevenStavrakis `obsidian-mcp@1.0.6` is a filesystem-based headless MCP alternative documented for context only. Verify its no-app/no-token behavior in the target environment before relying on it.

## Plugin Data and Examples

#### Work With Plugin Data

Plugin operations are file-layer data edits of the plain files plugins render rather than plugin UI operations. `references/plugins/` provides file-layer plugin operation references. `beancount-finance.md` covers Beancount Ledger data, and `obsidian-tables.md` documents `.table.md` JSON data. `obsidian42-brat.md` gives beta-plugin installation context. `plugin-operation-logic.md` describes the general data-over-UI model.

&nbsp;

#### Run the Example Workflows

`examples/headless-notes-workflow.sh` checks vault registration, searches, creates a note idempotently and reads it back using `notesmd-cli`. `examples/mcp-roundtrip.sh` is a read-only preflight that prints the Code Mode MCP roundtrip pattern. `examples/beancount-transaction.sh` appends a balanced Beancount transaction and can optionally run `bean-check` validation. `examples/README.md` indexes the three scripts and lists prerequisites, usage, safety boundaries and troubleshooting.
