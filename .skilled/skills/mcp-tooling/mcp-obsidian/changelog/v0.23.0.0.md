# v0.23.0.0, Official CLI Agent Guidance

The skill's official CLI surface was never documented well enough to drive.

- It was named as one of the skill's three surfaces.
- Running the installed binary showed otherwise on every point.

This release replaces the guesses with measured behavior.

- It adds the agent-facing usage layer.
- It also makes `doctor.sh` report whether the surface can answer.
- Every claim rests on the CLI's observed behavior.

Official CLI questions load app-backed guidance.

- A new `OFFICIAL_CLI` router intent has weight 6.
- The false app-launch claim is corrected.
- A new workflow demonstrates a full round trip.

&nbsp;

## Why This Release

The release makes the skill's named official CLI surface usable. The guidance rests on the CLI's observed behavior.

- Its command list was marked `VERIFY`.
- Its syntax was written as POSIX flags and bare positional arguments.
- Eight files repeated the false app-launch claim.

## Official CLI Guidance

The official `obsidian` CLI is the app-backed surface of the skill. This release measures its behavior from the installed binary.

#### Agent Usage Is Based on the Binary <a id="c-agent-usage-is-based-on-the-binary"></a>

- Every claim in `references/official-cli-agent-usage.md` was observed against desktop 1.13.7 (installer 1.13.4).
- The guide covers the `obsidian version` preflight.
- It covers how to tell "not registered" from "app not running".
- It covers the exit-0 failure contract.
- It covers the stdout check that replaces `$?`.
- The guide covers the `obsidian <command> key=value` grammar.
- It covers the global `vault=` option.
- It indexes all 106 commands and confirmed parameters for the 13 an agent uses most.
- It includes five safety invariants, a worked script and a table.
- The table shows where Obsidian's own documentation disagrees with the binary.
- It closes with a verification-status section. That section lists what stayed UNKNOWN.
- It gives the check that would settle each.

#### Help and File Examples Use CLI Forms <a id="c-help-and-file-examples-use-cli-forms"></a>

- `obsidian --help` was replaced with `obsidian help` in 15 files.
- `obsidian help` is the canonical form.
- It is the form the rest of this release documents.
- The reason first given here was wrong.
- `--help` does not fail. On desktop 1.13.7 it exits 0.
- It prints the full help byte for byte identical to `obsidian help`.
- The `-h`, `-v` and `--version` flags each print `Error: Command "<flag>" not found` on stdout.
- They exit 0 under the same failure contract as other rejected commands.
- `notesmd-cli --help` was untouched. That binary takes POSIX flags.
- Examples using `obsidian "<vault/path>"` and `obsidian "TEST_TARGET"` became `obsidian open file="<name>"`.
- The new form appears in `SKILL.md`, the playbook root and `manual-testing-playbook/official-cli/open-app-action.md`.

## Routing and Availability

Question routing decides which reference an agent loads. This release adds a new official CLI intent.

#### Official Questions Load the Guide <a id="c-official-questions-load-the-guide"></a>

- The new `OFFICIAL_CLI` router intent in `SKILL.md` has weight 6.
- It uses app-backed vocabulary.
- That includes `official cli`, `app-backed`, `register cli`, `backlinks`, `orphans`, `base:query`, `unable to find obsidian` and siblings.
- It is wired into `INTENT_SIGNALS`, `RESOURCE_MAP`, the §2 loading map and the §8 reference inventory.
- It is also wired into the intent count in the routing comment.
- So official-CLI questions load `references/official-cli-agent-usage.md`.
- They do not route to `NOTES_CLI` and its notesmd-centric reference.
- Routing for `NOTES_CLI`, `MCP_ADVANCED`, `PLUGIN_DATAVIEW`, `INSTALL`, `TROUBLESHOOT` and `NOTION_MIGRATION` is unchanged.

#### Doctor Reports App Availability <a id="c-doctor-reports-app-availability"></a>

- `scripts/doctor.sh` now runs `obsidian version`.
- It does not only check PATH.
- When the binary is registered but the app is closed, it warns.
- It does not report a green check.

## Reference and Troubleshooting

The command reference and troubleshooting guide now reflect live behavior.

#### The Reference Confirms Live Capabilities <a id="c-the-reference-confirms-live-capabilities"></a>

- Section 8 of `references/obsidian-cli-commands.md` changed from a `VERIFY` stub to a confirmed capability table.
- Section 3's selection table gained four app-only rows.
- One covers the resolved link graph.
- Another covers the computed tag and task index.
- A third covers Bases and history.
- The fourth covers plugin and theme state.
- Those four capabilities previously had no home in the table.
- Section 9 names `vault=` as the official CLI's single global option.
- Section 11 invariant 5 carries the preflight and the stdout check.

#### Troubleshooting Names Both Failures <a id="c-troubleshooting-names-both-failures"></a>

- `references/troubleshooting.md` §5b covers the app-not-running failure.
- That is `The CLI is unable to find Obsidian` on stderr with exit 1.
- Section 5c covers the exit-0-on-error failure.
- Neither had any coverage anywhere in the skill.

#### Install Guide Adds Troubleshooting Rows <a id="c-install-guide-adds-troubleshooting-rows"></a>

- `INSTALL-GUIDE.md` adds troubleshooting rows.
- The rows cover the app-down failure and POSIX-flag misuse.

## Examples and Skill Guidance

Worked examples and the skill's own tables now describe the live app-backed CLI.

#### The Workflow Completes a Round Trip <a id="c-the-workflow-completes-a-round-trip"></a>

- `examples/official-cli-workflow.sh` demonstrates a preflight-create-append-property-read-delete round trip.
- Its `obs()` wrapper turns the CLI's own `Error:` text back into a non-zero status.
- The workflow reads the created filename from the `Created:` line.
- It cleans up through an exit trap.
- `examples/README.md` indexes it as §3.3.

#### Playbook Scenarios Check Standard Output <a id="c-playbook-scenarios-check-standard-output"></a>

- Both `official-cli/` playbook scenarios preflight with `obsidian version`.
- They judge results by stdout, not by exit status.
- The playbook's command-notation line was corrected to match.

#### Playbook Precondition 5 Corrected <a id="c-playbook-precondition-5-corrected"></a>

- The playbook's global precondition 5 was corrected. It now matches the scenarios' CLI procedure.

#### Skill Tables Describe Live Capabilities <a id="c-skill-tables-describe-live-capabilities"></a>

- `SKILL.md`'s surface tables, quick reference and success criteria now describe the app-backed CLI.
- They describe it by what only the live app can produce.
- The quick reference lists 11 confirmed commands, not 2 unverified ones.

## Documentation Corrections and Versions

Several files were corrected and version numbers were updated.

#### App Launch Guidance Is Corrected <a id="c-app-launch-guidance-is-corrected"></a>

- The false claim was that the CLI launches the app when it is not running.
- It was removed from the eight files that carried it.
- That is 17 lines across 8 files.
- One occurrence was a `references/obsidian-cli-commands.md` table row.
- That row was labelled `Confirmed behavior`.
- Three further files were touched without having carried the claim.
- `README.md` and `manual-testing-playbook/official-cli/register-and-help.md` never asserted a launch.
- So they only gained corrected `obsidian version` guidance.
- `mcp-servers/obsidian-cli/setup.sh` carried the claim.
- Its `(launching it if not running)` line survived this release.
- A contradicting sentence was added underneath it.
- The line was removed later in `e3084476cf`.

- `SKILL.md` changed from 0.22.0.0 to 0.23.0.0.
