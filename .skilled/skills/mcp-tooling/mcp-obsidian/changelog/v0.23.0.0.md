# v0.23.0.0, Official CLI Agent Guidance

The official `obsidian` CLI was named as one of the skill's three surfaces but never documented well enough to drive. Its command list was marked `VERIFY` and its syntax was written as POSIX flags and bare positional arguments. Eight files also repeated the claim that the CLI launches the desktop app when it is not running. Running the installed binary showed otherwise on every point. This release replaces the guesses with measured behavior, adds the agent-facing usage layer and makes `doctor.sh` report whether the surface can answer.

## Why This Release

The release makes the skill's named official CLI surface usable through guidance grounded in its observed behavior.

## What's New at a Glance

- **The official CLI gains an agent usage guide.** It gives agents syntax and failure guidance based on the installed binary.
- **`OFFICIAL_CLI` routes to the new guide.** Official-CLI questions load app-backed guidance instead of notesmd-centric guidance.
- **`doctor.sh` checks the live CLI.** It warns when the binary is registered but the app is closed.
- **The command reference replaces its `VERIFY` stub.** Section 8 becomes a confirmed capability table and section 3 gains four app-only rows.
- **Help and file examples use official command forms.** The guidance uses `obsidian help` and `obsidian open file="<name>"`.
- **The troubleshooting reference covers both CLI failures.** It addresses the app-not-running error and the exit-0-on-error behavior.
- **`INSTALL-GUIDE.md` adds troubleshooting rows.** The rows cover the app-down failure and POSIX-flag misuse.
- **The playbook's global precondition 5 was corrected.** It now matches the scenarios' CLI procedure.
- **The false app-launch claim is corrected.** With the app down, the CLI exits 1 and leaves the app down.

## Official CLI Guidance

#### Agent Usage Is Based on the Binary

Every claim in `references/official-cli-agent-usage.md` was observed against desktop 1.13.7 (installer 1.13.4). The guide covers the `obsidian version` preflight and how to tell "not registered" from "app not running". It covers the exit-0 failure contract and the stdout check that replaces `$?`.

The guide covers the `obsidian <command> key=value` grammar and the global `vault=` option. It indexes all 106 commands and confirmed parameters for the 13 an agent uses most. It includes five safety invariants, a worked script and a table of where Obsidian's own documentation disagrees with the binary. It closes with a verification-status section listing what stayed UNKNOWN with the check that would settle each.

&nbsp;

#### Help and File Examples Use CLI Forms

`obsidian --help` was replaced with `obsidian help` in 15 files. `obsidian help` is the canonical form and the one the rest of this release documents. The reason first given here was wrong: `--help` does not fail. On desktop 1.13.7 it exits 0 and prints the full help byte for byte identical to `obsidian help`.

The `-h`, `-v` and `--version` flags each print `Error: Command "<flag>" not found` on stdout and exit 0 under the same failure contract as other rejected commands. `notesmd-cli --help` was untouched because that binary takes POSIX flags.

Examples using `obsidian "<vault/path>"` and `obsidian "TEST_TARGET"` became `obsidian open file="<name>"` in `SKILL.md`, the playbook root and `manual-testing-playbook/official-cli/open-app-action.md`.

## Routing and Availability

#### Official Questions Load the Guide

The new `OFFICIAL_CLI` router intent in `SKILL.md` has weight 6 and uses app-backed vocabulary including `official cli`, `app-backed`, `register cli`, `backlinks`, `orphans`, `base:query`, `unable to find obsidian` and siblings. It is wired into `INTENT_SIGNALS`, `RESOURCE_MAP`, the §2 loading map, the §8 reference inventory and the intent count in the routing comment, so official-CLI questions load `references/official-cli-agent-usage.md` instead of routing to `NOTES_CLI` and its notesmd-centric reference.

Routing for `NOTES_CLI`, `MCP_ADVANCED`, `PLUGIN_DATAVIEW`, `INSTALL`, `TROUBLESHOOT` and `NOTION_MIGRATION` is unchanged.

&nbsp;

#### Doctor Reports App Availability

`scripts/doctor.sh` now runs `obsidian version` rather than only checking PATH. When the binary is registered but the app is closed, it warns instead of reporting a green check.

## Reference and Troubleshooting

#### The Reference Confirms Live Capabilities

Section 8 of `references/obsidian-cli-commands.md` changed from a `VERIFY` stub to a confirmed capability table. Section 3's selection table gained four app-only rows. One covers the resolved link graph. Another covers the computed tag and task index. A third covers Bases and history. The fourth covers plugin and theme state. Those four capabilities previously had no home in the table.

Section 9 names `vault=` as the official CLI's single global option. Section 11 invariant 5 carries the preflight and the stdout check.

&nbsp;

#### Troubleshooting Names Both Failures

`references/troubleshooting.md` §5b covers the app-not-running failure, `The CLI is unable to find Obsidian` on stderr with exit 1. Section 5c covers the exit-0-on-error failure, neither of which had any coverage anywhere in the skill.

## Examples and Skill Guidance

#### The Workflow Completes a Round Trip

`examples/official-cli-workflow.sh` demonstrates a preflight-create-append-property-read-delete round trip. Its `obs()` wrapper turns the CLI's own `Error:` text back into a non-zero status.

The workflow reads the created filename from the `Created:` line and cleans up through an exit trap. `examples/README.md` indexes it as §3.3.

&nbsp;

#### Playbook Scenarios Check Standard Output

Both `official-cli/` playbook scenarios preflight with `obsidian version` and judge results by stdout rather than exit status. The playbook's command-notation line was corrected to match.

&nbsp;

#### Skill Tables Describe Live Capabilities

`SKILL.md`'s surface tables, quick reference and success criteria now describe the app-backed CLI by what only the live app can produce. The quick reference lists 11 confirmed commands instead of 2 unverified ones.

## Documentation Corrections and Versions

#### App-Launch Guidance Is Corrected

The false claim that the CLI launches the app was removed from the eight files that carried it. That is 17 lines across 8 files. One occurrence was a `references/obsidian-cli-commands.md` table row labelled `Confirmed behavior`.

Three further files were touched without having carried the claim. `README.md` and `manual-testing-playbook/official-cli/register-and-help.md` never asserted a launch, so they only gained corrected `obsidian version` guidance. `mcp-servers/obsidian-cli/setup.sh` carried the claim and its `(launching it if not running)` line survived this release with a contradicting sentence added underneath. It was removed later in `e3084476cf`.

&nbsp;

#### Version Records Track Changes

`SKILL.md` changed from 0.22.0.0 to 0.23.0.0 and `references/obsidian-cli-commands.md` changed from 0.1.0.0 to 0.2.0.0. `references/official-cli-agent-usage.md` was created at 0.1.0.0.

Historical changelog entries were left as written. `changelog/v0.1.0.0.md` records the `obsidian --help` guidance believed correct at that release.
