# v0.20.0.0, Broader Obsidian Plugin Coverage

This release takes `mcp-obsidian` beyond migration plugins.

- It moves into the operator's wider Obsidian stack.
- Broader plugin coverage pairs with references for file data an AI can author.
- So the skill can represent more of the vault's working setup.

Nine community plugins join the real vault.

- The operator requested nine more plugins be installed and supported.
- The request also asked for an all-plugins roster.
- Six of the nine plugins are interface-only or automatic.

Three plugins gain dedicated references and routing intents.

- Advanced Canvas, Claudian and Project Manager have dedicated references.
- Their guides cover plugin-specific file and task data.
- Three plugin-specific routing intents were added.
- They follow the existing per-plugin pattern.

&nbsp;

## Why This Release

The operator requested nine more plugins be installed and supported. The request also asked for a roster that includes plugins without dedicated integration docs.

- Only three of the nine expose a vault syntax or data model an AI can author against.
- The other six are interface-only or automatic.
- They include a formatting toolbar, file-explorer replacement, quick-switcher, favicons, iframe frames and auto-linking.

## Vault Coverage

The new plugins span file-layer data and interface or automatic behavior.

#### Nine Plugins Join the Vault <a id="c-nine-plugins-join-the-vault"></a>

- The BRAT-headless installer added nine plugins to the real vault.
- They are `virtual-linker`, `editing-toolbar`, `notebook-navigator`, `advanced-canvas`, `realclaudian` (Claudian), `obsidian-custom-frames`, `darlal-switcher-plus`, `project-manager` and `link-favicon`.
- Operator approval came on 2026-08-22.
- Each `manifest.id` came from its downloaded manifest. It was not assumed.
- The id count in `community-plugins.json` grew from 12 to 21.
- BRAT `data.json` gained nine frozen-version entries.
- Both files were backed up to timestamped `.bak` files first.
- Obsidian 1.13.4 clears every plugin's `minAppVersion` floor. That floor is the minimum supported app version.

#### The Roster Protects Its Backbone <a id="c-the-roster-protects-its-backbone"></a>

- `references/plugins/installed-plugins.md` warns against removing `obsidian-local-rest-api`.
- That plugin is the MCP transport backbone for the skill's own connection.
- The file documents two soft overlaps as coexisting.
- One is Claudian with Local REST API. The other is Project Manager with Dataview/Notion Bases.
- The roster lists all 21 enabled vault plugins.
- It separates 15 file-layer plugins with dedicated docs from 6 interface or automatic plugins without them.
- The six interface-only or automatic plugins appear only on the roster. That is by design.
- They have no dedicated `references/plugins/<name>/` tree.

#### Additions Leave Existing Plugins <a id="c-additions-leave-existing-plugins"></a>

- The obsolescence review found no plugin should be removed.
- No existing plugin folder was edited.
- No plugin was removed.
- So the change is additive.

## Plugin References

Three plugins gained dedicated reference trees. Each also has an entry in `feature-catalog/plugins/`.

#### Advanced Canvas Details <a id="c-advanced-canvas-details"></a>

- The four-file tree at `references/plugins/advanced-canvas/` documents how Advanced Canvas extends native `.canvas` JSON (structured data).
- Node `styleAttributes` cover `shape` and `border`, plus `textAlign`.
- Edge `styleAttributes` cover `path` and `arrow`, plus `pathfindingMethod`.
- `metadata.startNode` sets presentation order.
- The reference covers `portal` nodes and collapsible groups.
- The node and edge keys were read from installed `main.js` v6.5.4.
- Cross-portal edge serialization is flagged `VERIFY`.

#### Claudian's Vault Model <a id="c-claudians-vault-model"></a>

- The four-file tree at `references/plugins/claudian/` documents the plugin with id `realclaudian` and display name Claudian.
- It embeds coding-agent CLIs (command-line interfaces) inside the vault.
- The `.claude/` artifacts include commands and skills, plus `mcp.json` and settings.
- They were read from installed `main.js` v2.2.4.
- The guide describes the local-CLI-execution model.
- It distinguishes Claudian from ClaudianIA and Claudian Plus.
- Config schemas beyond observed path strings are flagged `VERIFY`.

#### Project Manager Task Fields <a id="c-project-manager-task-fields"></a>

- The four-file tree at `references/plugins/project-manager/` documents the `pm-task` frontmatter schema.
- That schema is the metadata at the top of a note.
- It specifies status and priority vocabularies.
- The schema names `dependencies` and `parentId`, plus `subtaskIds`, `timeLogs` and `customFields`.
- Table, Gantt and Kanban views are driven by frontmatter.
- The fields were read from installed `main.js` v1.8.0.
- Non-scalar `customFields` encoding and `recurrence` fields beyond the three confirmed are flagged `VERIFY`.

#### Earlier Reference Scope <a id="c-earlier-reference-scope"></a>

- Before this release, §8 References omitted seven older plugin folders (`charts`, `dataview`, `excalidraw`, `git`, `outliner`, `minimal`, `health-md`).
- That pre-existing gap was left untouched.
- This release added only its three plugin trees and the roster to §8.

## Skill Routing

Three new intent keys were added. Version and reference registration were updated.

#### Plugin Routing Intents <a id="c-plugin-routing-intents"></a>

- The new intent keys are `PLUGIN_ADVANCED_CANVAS` and `PLUGIN_CLAUDIAN`, plus `PLUGIN_PROJECT_MANAGER`.
- They are additive-only.
- They mirror the existing per-plugin pattern.
- The additions cover §2 Resource Loading Levels and §8 References.
- They also update `INTENT_SIGNALS` and `RESOURCE_MAP`.
- The `specific_plugin_intents` tuple and the `PLUGINS` aggregate changed too.
- The aggregate includes the roster.
- The `INTENT_SIGNALS` count comment changed from nineteen to twenty-two.

#### Version and Reference Registration <a id="c-version-and-reference-registration"></a>

- `SKILL.md` changed from version `0.19.0.0` to `0.20.0.0`.
- `leaf-manifest.json` was regenerated to register the new reference files.
