# v0.20.0.0, Broader Obsidian Plugin Coverage

This release takes `mcp-obsidian` beyond migration plugins and into the operator's wider Obsidian stack. It pairs broader plugin coverage with references for the file data an AI can author, so the skill can represent more of the vault's working setup.

> Spec folder: `specs/mcp-tooling/015-notion-to-obisidian-migration/005-obsidian-plugin-expansion`

## Why This Release

The operator requested nine more plugins be installed and supported, plus a roster that includes plugins without dedicated integration docs. Only three of the nine expose a vault syntax or data model an AI can author against. The other six are interface-only or automatic, including a formatting toolbar, file-explorer replacement, quick-switcher, favicons, iframe frames and auto-linking.

## What's New at a Glance

- **Nine community plugins joined the real vault.** Their additions include both file-layer and interface or automatic plugins.
- **The roster lists all 21 enabled vault plugins.** It distinguishes 15 file-layer plugins with dedicated docs from 6 interface or automatic plugins without them.
- **Advanced Canvas, Claudian and Project Manager have dedicated references.** Their guides cover plugin-specific file and task data.
- **Three plugin-specific routing intents were added.** They follow the existing per-plugin pattern.

## Vault Coverage

#### Nine Plugins Join the Vault

The BRAT-headless installer added `virtual-linker`, `editing-toolbar`, `notebook-navigator`, `advanced-canvas`, `realclaudian` (Claudian), `obsidian-custom-frames`, `darlal-switcher-plus`, `project-manager` and `link-favicon` to the real vault with operator approval on 2026-08-22. Each `manifest.id` came from its downloaded manifest rather than being assumed.

The id count in `community-plugins.json` grew from 12 to 21. BRAT `data.json` gained nine frozen-version entries. Both files were backed up to timestamped `.bak` files first. Obsidian 1.13.4 clears every plugin's `minAppVersion` floor, the minimum supported app version.

&nbsp;

#### The Roster Protects Its Backbone

`references/plugins/installed-plugins.md` warns against removing `obsidian-local-rest-api`, the MCP transport backbone for the skill's own connection. It documents two soft overlaps as coexisting: Claudian with Local REST API and Project Manager with Dataview/Notion Bases.

The six interface-only or automatic plugins appear only on the roster by design and have no dedicated `references/plugins/<name>/` tree.

&nbsp;

#### Additions Leave Existing Plugins

The obsolescence review found no plugin should be removed. No existing plugin folder was edited and no plugin was removed, so the change is additive.

## Plugin References

Each of the three documented plugins also has an entry in `feature-catalog/plugins/`.

#### Advanced Canvas Details

The four-file tree at `references/plugins/advanced-canvas/` documents how Advanced Canvas extends native `.canvas` JSON (structured data). Node `styleAttributes` cover `shape` and `border`, plus `textAlign`. Edge `styleAttributes` cover `path` and `arrow`, plus `pathfindingMethod`.

`metadata.startNode` sets presentation order. The reference covers `portal` nodes and collapsible groups. The node and edge keys were read from installed `main.js` v6.5.4. Cross-portal edge serialization is flagged `VERIFY`.

&nbsp;

#### Claudian's Vault Model

The four-file tree at `references/plugins/claudian/` documents the plugin with id `realclaudian` and display name Claudian. It embeds coding-agent CLIs (command-line interfaces) inside the vault.

The `.claude/` artifacts include commands and skills, plus `mcp.json` and settings, as read from installed `main.js` v2.2.4. The guide describes the local-CLI-execution model and distinguishes Claudian from ClaudianIA and Claudian Plus. Config schemas beyond observed path strings are flagged `VERIFY`.

&nbsp;

#### Project Manager Task Fields

The four-file tree at `references/plugins/project-manager/` documents the `pm-task` frontmatter schema, the metadata at the top of a note. It specifies status and priority vocabularies. The schema names `dependencies` and `parentId`, plus `subtaskIds`, `timeLogs` and `customFields`.

Table, Gantt and Kanban views are driven by frontmatter. The fields were read from installed `main.js` v1.8.0. Non-scalar `customFields` encoding and `recurrence` fields beyond the three confirmed are flagged `VERIFY`.

&nbsp;

#### Earlier Reference Scope

Before this release, §8 References omitted seven older plugin folders (`charts`, `dataview`, `excalidraw`, `git`, `outliner`, `minimal`, `health-md`). That pre-existing gap was left untouched, and this release added only its three plugin trees and the roster to §8.

## Skill Routing

#### Plugin Routing Intents

The new intent keys are `PLUGIN_ADVANCED_CANVAS` and `PLUGIN_CLAUDIAN`, plus `PLUGIN_PROJECT_MANAGER`. They are additive-only and mirror the existing per-plugin pattern.

The additions cover §2 Resource Loading Levels and §8 References. They also update `INTENT_SIGNALS` and `RESOURCE_MAP`. The `specific_plugin_intents` tuple and the `PLUGINS` aggregate changed too. The aggregate includes the roster, and the `INTENT_SIGNALS` count comment changed from nineteen to twenty-two.

&nbsp;

#### Version and Reference Registration

`SKILL.md` changed from version `0.19.0.0` to `0.20.0.0`. `leaf-manifest.json` was regenerated to register the new reference files.

## Upgrade Notes

Open Obsidian the next time to complete activation of the nine installed plugins. The file-layer installation and registration were confirmed, but live loading was not.
