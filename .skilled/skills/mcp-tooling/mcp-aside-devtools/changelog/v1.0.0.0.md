This first release delivered the Aside AI browser as the workflow packet for natural-language browser tasks, deterministic Playwright-compatible evidence capture and MCP composition through Code Mode. It combined the registered `aside` manual, the installed CLI surface, live discovery evidence, Chrome-DevTools-parity guidance, operator validation material and template-conformant package documentation without overstating authenticated or browser-bound behavior.

## Why This Release

Browser work divided into outcome-oriented tasks, deterministic proof steps and multi-tool composition. Each activity required a different surface. Capability claims, installation posture and recovery behavior needed one auditable package rather than scattered prose.

## What's New at a Glance

- **Five weighted intents route work across CLI and MCP.** The router covered TASK, REPL, MCP, INSTALL and TROUBLESHOOT through `aside "<task>"`, `aside --session <id> "<task>"`, `aside repl "<code>"` and the Aside MCP `repl` tool through Code Mode. CLI was the primary operator surface and MCP the composition fallback, so agents could select the simplest suitable lane and keep repeatable evidence work out of the nondeterministic task lane.
- **The registered manual and discovery fixture establish the observed contract.** The release documented the registered stdio manual that launched `aside mcp` with an intentionally empty `env`, preserved its byte-true snapshot in `assets/utcp-aside-manual.md` and treated manual absence as a diagnostic error. A dated 2026-07-16 fixture recorded the single registry tool as `aside.aside.repl` and the TypeScript callable as `aside.aside_repl(args)`, with per-session rediscovery still required because the tool list could change, so consumers could distinguish the dotted discovery name from the underscore call form and diagnose wiring drift without re-registering or editing operator-owned configuration.
- **The references set browser and session boundaries.** Operators needed a version-pinned command surface and clear browser/session boundaries, so the references covered task starts and continuation, account selection and status commands, `aside mcp` and `aside repl`, the three-layer session model, permission and concurrency rules and discovered REPL helpers for tabs, snapshots, display, pages, screenshots, PDF, filesystem utilities, sleep and authenticated fetch. Docs required `console.log` for returned values, neutral-session tab attachment, explicit timeouts, independent artifact verification and a single-writer posture while multi-client isolation remained unresolved. Deterministic calls used the observed helper contract while browser binding, permission inheritance, bound-page result shapes and parallel isolation stayed fail-closed instead of becoming assumptions.
- **Six feature leaves and six matching playbook scenarios cover DevTools parity.** The packet gives an honest map from the discovered Playwright `page` API to browser-debugging jobs covered by `mcp-chrome-devtools`: DOM inspection, screenshots and PDF, console and network event capture, cookies and storage, performance timing and navigation with multiple tabs. The patterns used `page` and `page.context()` APIs confirmed as reachable by the discovery fixture while bound-session executions remained SKIP-valid until an authorized browser session could verify their live result shapes, without claiming native HAR export, Lighthouse audits, raw-CDP passthrough, dedicated console or network tools or parallel isolated browser instances.
- **Capability evidence and recovery material ship together.** The release shipped an 18-capability feature catalog across the five router intents and DevTools-parity family, a 21-scenario manual testing playbook with routing-recall holdouts and recovery cases, three example workflow scripts, a macOS installer wrapper, a read-only doctor with an MCP handshake probe and CLI/MCP server-package pointers. The dated online-research reference corroborated the public CLI/MCP/REPL surface, verbatim `mcp.json` wiring, permission model, hidden-password behavior and installer-only distribution while retaining CONFIRMED, INFERRED and UNKNOWN labels.
- **The full package supports end-to-end operator validation.** Operators could validate installation, registration, discovery, routing, evidence capture and failure recovery end to end, with authenticated smoke calls and browser-bound probes explicitly operator-gated or SKIP-valid.
- **The packet had to match the create-skill and create-readme contracts without changing its runtime behavior.** `SKILL.md`, `README.md`, `INSTALL-GUIDE.md`, references, assets, examples, feature catalogs, playbook scenarios, server pointers and script documentation used kebab-case filesystem names and resolved links. Reference and asset documents used an OVERVIEW-first Purpose and Usage structure, while `scripts/README.md` used code-folder README sections for architecture, directory tree, key files, entrypoints, validation and related resources, grounded in the actual mutation and exit-code behavior of `install.sh` and `doctor.sh`, keeping the package tool-compatible, navigable and strictly aligned with its authoring templates while preserving its technical and epistemic boundaries.
