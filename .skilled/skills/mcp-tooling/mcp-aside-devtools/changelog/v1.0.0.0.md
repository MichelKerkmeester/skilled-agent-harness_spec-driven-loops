This first release delivered the Aside AI browser as the workflow packet. It covered natural-language browser tasks. It covered deterministic Playwright-compatible evidence capture. It covered MCP composition through Code Mode. The package combined the registered `aside` manual, the installed CLI surface and live discovery evidence. It also combined Chrome-DevTools-parity guidance, operator validation material and template-conformant package documentation. It did not overstate authenticated or browser-bound behavior.

## Why This Release

Browser work divided into outcome-oriented tasks, deterministic proof steps and multi-tool composition. Each activity required a different surface. Capability claims, installation posture and recovery behavior needed one auditable package. Scattered prose was not enough.

## What's New at a Glance

- **Five weighted intents route work across CLI and MCP.** The router covered TASK, REPL, MCP, INSTALL and TROUBLESHOOT. It reached them through `aside "<task>"`, `aside --session <id> "<task>"`, `aside repl "<code>"` and the Aside MCP `repl` tool through Code Mode. CLI was the primary operator surface. MCP was the composition fallback. So agents could pick the simplest suitable lane. That kept repeatable evidence work out of the nondeterministic task lane.
- **The registered manual and discovery fixture establish the observed contract.** The release documented the registered stdio manual. That manual launched `aside mcp` with an intentionally empty `env`. The release preserved its byte-true snapshot in `assets/utcp-aside-manual.md`. It treated manual absence as a diagnostic error. A dated 2026-07-16 fixture recorded the single registry tool as `aside.aside.repl`. It recorded the TypeScript callable as `aside.aside_repl(args)`. Per-session rediscovery was still required, because the tool list could change. So consumers could tell the dotted discovery name from the underscore call form. They could diagnose wiring drift without re-registering or editing operator-owned configuration.
- **The references set browser and session boundaries.** Operators needed a version-pinned command surface. They needed clear browser and session boundaries. So the references covered task starts and continuation. They covered account selection and status commands. They covered `aside mcp` and `aside repl`, and the three-layer session model. They covered permission and concurrency rules. They covered discovered REPL helpers for tabs, snapshots, display, pages, screenshots, PDF, filesystem utilities, sleep and authenticated fetch. Docs required `console.log` for returned values and neutral-session tab attachment. They required explicit timeouts and independent artifact verification. They required a single-writer posture while multi-client isolation remained unresolved. Deterministic calls used the observed helper contract, while browser binding, permission inheritance, bound-page result shapes and parallel isolation stayed fail-closed. They did not become assumptions.
- **Six feature leaves and six matching playbook scenarios cover DevTools parity.** The packet gives an honest map from the discovered Playwright `page` API. It maps to browser-debugging jobs covered by `mcp-chrome-devtools`. Those jobs are DOM inspection, screenshots and PDF. They include console and network event capture. They also include cookies and storage, performance timing and navigation with multiple tabs. The patterns used `page` and `page.context()` APIs. The discovery fixture confirmed those APIs as reachable. Bound-session executions remained SKIP-valid until an authorized browser session could verify their live result shapes. The packet did not claim native HAR export, Lighthouse audits or raw-CDP passthrough. It did not claim dedicated console or network tools or parallel isolated browser instances.
- **Capability evidence and recovery material ship together.** The release shipped an 18-capability feature catalog. It covered the five router intents and the DevTools-parity family. It shipped a 21-scenario manual testing playbook with routing-recall holdouts and recovery cases. It shipped three example workflow scripts and a macOS installer wrapper. It shipped a read-only doctor with an MCP handshake probe and CLI/MCP server-package pointers. The dated online-research reference corroborated the public CLI/MCP/REPL surface. It corroborated verbatim `mcp.json` wiring, the permission model, hidden-password behavior and installer-only distribution. It retained CONFIRMED, INFERRED and UNKNOWN labels.
- **The full package supports end-to-end operator validation.** Operators could validate installation, registration, discovery, routing, evidence capture and failure recovery end to end. Authenticated smoke calls and browser-bound probes were explicitly operator-gated or SKIP-valid.
- **The packet had to match the create-skill and create-readme contracts without changing its runtime behavior.** `SKILL.md`, `README.md`, `INSTALL-GUIDE.md`, references, assets, examples and feature catalogs used kebab-case filesystem names and resolved links. Playbook scenarios, server pointers and script documentation did the same. Reference and asset documents used an OVERVIEW-first Purpose and Usage structure. `scripts/README.md` used code-folder README sections for architecture, directory tree, key files, entrypoints, validation and related resources. Those sections were grounded in the actual mutation and exit-code behavior of `install.sh` and `doctor.sh`. The package stayed tool-compatible and navigable. It stayed strictly aligned with its authoring templates. It preserved its technical and epistemic boundaries.
