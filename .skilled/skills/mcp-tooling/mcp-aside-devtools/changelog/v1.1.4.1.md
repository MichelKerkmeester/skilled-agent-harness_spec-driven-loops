# v1.1.4.1, The Router Moves to Its Own Section

`SKILL.md` now states its routing in four plain sentences: the hub mode that selects this packet, the references it loads first and where the machine router lives. The loading-level table, the router resilience bullets and the router pseudocode that followed them moved unchanged into a final `## 9. MACHINE ROUTER` section, which closes the file.

> Spec folder: `specs/sk-doc/072-skill-routing-and-clarity/008-cli-and-mcp-hubs` (Level 2)

&nbsp;

## What's New at a Glance

- **The routing section reads at a glance.** A reader sees the selection signal, the references loaded first and the pointer to the router without scrolling through pseudocode.
- **The router itself is unchanged.** The intent map, resource map, fallback checklist and helper code moved byte for byte, so the same requests reach the same references.
- **The scenario pointers follow the blocks.** Every routing-recall scenario now points at the section that holds the intent tables it checks.
- **Nothing else moved.** Section numbers and order are as they were, and the new section is appended at the end.

No migration required. The routing behavior is identical.
