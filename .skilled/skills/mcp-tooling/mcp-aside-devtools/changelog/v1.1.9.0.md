# v1.1.9.0, Attach for Reading and Open a Tab for Every Mutating Step

Two first-load files gave opposite advice. One said to prefer attaching to an open tab, and the other said never to attach to the user's tab for a mutating step.

> Spec folder: `specs/mcp-tooling/026-clickup-doc-divider-spacing`

&nbsp;

## What's New at a Glance

- **The attach preference is for reading.** `references/mcp-wiring.md` prefers attaching to an open tab only for a read-only step. A step that clicks, types or presses keys opens its own tab.
- **The tabs entry says what openTab does now.** `feature-catalog/devtools-parity/navigation-and-tabs.md` records that `openTab()` opens a background tab the user never sees, that key presses still land in it, and that `chrome.tabs.create` is refused.
- **Changelog spec lines carry the path only.** Eight older entries dropped their level label.
