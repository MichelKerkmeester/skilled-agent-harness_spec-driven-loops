# v1.1.9.0, The Plugin Manifest Reads as a Third-Party File

The connect steps tell you to import `plugin/manifest.json` once, and the connect-modes section repeats it, both times naming the manifest that ships inside the installed `figma-ds-cli` package. The reference check read the token as a path in this repository, found none, and failed the README twice for one file.

The token stays, because it is the name Figma Desktop asks for. The README now declares it in its `readme-check` block with the reason that the installed package carries the manifest and this repository does not. The safe-mode and yolo-mode descriptions are otherwise unchanged.

> Spec folder: `specs/sk-doc/072-skill-routing-and-clarity/012-alignment-remediation` (Level 2)

## What's New at a Glance

- **The README passes the reference check again.** One `allow-ref` entry covers both mentions, with the reason naming the installed package as the owner.
- **The connect instructions are untouched.** Importing the manifest once and keeping `Plugins > Development > FigCli` open is still the safe-mode step.
- **The README edition is raised.** The body changed, so its own edition moves with it.
