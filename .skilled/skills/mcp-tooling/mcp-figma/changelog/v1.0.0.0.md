# v1.0.0.0, First Stable Release

The `mcp-figma` skill gives an agent a CLI-first way to drive Figma Desktop from the terminal through the silships figma-cli, published to npm as `figma-ds-cli`. The CLI is the primary surface for inspecting, exporting and rendering work, managing tokens, variables and components and extracting or importing a design system. The optional Figma MCP runs through this project's Code Mode and is used only to pull Figma design data into the agent for codegen. The spine of the skill is the read-only / mutating / destructive gating taxonomy and the `sk-design-interface` handoff that keeps design judgment where it belongs.

The `SKILL.md` runtime, references, scripts, docs and design decisions formed the skill's first build and remain the core of the 1.0.0.0 surface.

## Why This Release

This release promotes the skill to a stable 1.0.0.0 line. Live external verification is complete. An embedded install scaffold now mirrors the other mcp-server skills.

## What's New at a Glance

- **This release adds `mcp-servers/figma-cli/` as the canonical install entry point.** It mirrors the embedded-server layout used by `mcp-click-up`.
- **This release adds `mcp-servers/figma-mcp/` as a pointer to the optional Framelink `figma` Code Mode MCP.** Nothing is installed through that pointer.
- **The installer selects the full silships repository build over the minimal npm build.** It upgrades from the repository when only the minimal build is present.
- **The canonical npm binary is `figma-ds-cli`.** The unrelated npm package `figma-cli` comes from unic/figma-cli.
- **The shared mcp-skill standard aligns installation and diagnosis.** It places the skill alongside four related MCP skills.
- **Safe connect is the default.** Yolo patching requires `--i-understand-this-patches-figma` before modifying `app.asar`.
- **`SKILL.md` carries its lean house-template runtime instructions forward from the initial build.** They cover when to use the CLI or optional MCP, SMART ROUTING, how it works and its rules.
- **The references group CLI, safety, MCP and troubleshooting guidance.** They include command examples and rollback details.
- **The skill's documentation was conformed to the house voice.** It has no em dashes and no prose semicolons.

## Figma Desktop

#### Follow Sibling Patterns

The skill was modeled on `mcp-chrome-devtools` (CLI-primary plus MCP-via-Code-Mode) and `mcp-open-design` (CLI plus optional MCP, daemon model, gated verbs). `references/figma-cli-reference.md` records binary identity, the connect/daemon model and grouped command examples.

&nbsp;

#### Keep the MCP Optional

`mcp-servers/figma-mcp/` points to the optional Framelink `figma` Code Mode MCP. Nothing is installed there, because the manual is already registered in the repo `.utcp_config.json`, so the README there documents the opt-in path rather than vendoring a server.

`references/mcp-wiring.md` describes a prefixed `.env` token, a discover-first flow and a `call_tool_chain` example. It notes the official Figma Dev Mode MCP as a future option. `scripts/print-utcp-snippets.sh` prints the optional Code Mode wiring without editing files.

&nbsp;

#### Gate Risky Connections

`references/tool-surface.md` defines read-only, mutating, destructive and arbitrary action classes and lists destructive actions with rollbacks. `scripts/connect-safe.sh` guides a safe plugin connection and refuses to patch Figma.

`scripts/connect-yolo.sh` performs the gated yolo connection and requires `--i-understand-this-patches-figma` before patching `app.asar`. `scripts/unpatch.sh` rolls the yolo patch back.

## Installation and Diagnostics

#### Delegate to the Installer

`mcp-servers/figma-cli/setup.sh` delegates to the skill's `scripts/install.sh`. The scaffold installs and references the MIT-licensed CLI without source-vendoring it.

&nbsp;

#### Keep the Package Names Straight

The unrelated npm package `figma-cli` exposes a `figma` binary. The installer never runs `npm i -g figma-cli`. `references/troubleshooting.md` maps symptoms to causes and fixes, including the package collision.

&nbsp;

#### Install and Verify Only

`scripts/install.sh` installs and verifies only, using npm `figma-ds-cli` or the silships repository. It never connects to Figma or patches it.

The skill was verified against `figma-ds-cli` 1.2.0, the full repository build that exposes safe connect, the local daemon, design-system extract and the complete command surface. The minimal npm `figma-ds-cli` 1.0.0 build is still detected.

`scripts/_common.sh` provides shared binary resolution plus helpers.

&nbsp;

#### Share Install and Diagnosis

`mcp-figma` follows the shared mcp-skill install-and-doctor standard alongside `mcp-open-design` and `mcp-chrome-devtools`. `mcp-click-up` and `mcp-code-mode` are part of the same standard. The standard includes an `INSTALL-GUIDE.md`. It also pairs a non-mutating `scripts/install.sh` with a read-only `scripts/doctor.sh`.

The install guide covers installation, connection, daemon use, MCP and safety. The doctor reports binary identity, Figma Desktop, the daemon, ports and the Code Mode `figma` manual. `scripts/daemon.sh` wraps status, diagnose, start, stop, restart and reconnect for the local daemon.

## Skill and Documentation

#### Carry the Runtime Forward

The initial `SKILL.md` build uses lean house-template runtime instructions. Its WHEN TO USE section covers CLI versus optional-MCP triggers, use cases and anti-patterns. SMART ROUTING covers direction plus binary detection, phase flow and a six-intent guarded router.

HOW IT WORKS covers binary verification, the Figma Desktop and daemon model, connect modes, command classes and optional Framelink MCP. RULES organizes ALWAYS / NEVER / ESCALATE IF around the `figma-ds-cli` naming trap, safe-default connect and gating every destructive verb. Sections 5-8 cover references, success criteria, integration points and related resources.

Its runtime `allowed-tools` are minimal: `Read, Bash, Grep, Glob, mcp__code_mode__call_tool_chain`.

&nbsp;

#### Keep Operator Docs Aligned

The house-voice pass covers `SKILL.md` and its references. It also covers `INSTALL-GUIDE.md`, `feature-catalog/feature-catalog.md` plus `manual-testing-playbook/manual-testing-playbook.md`.

The `README.md` gives a narrative house-voice overview. The feature catalog groups capabilities by area and the manual testing playbook gives safe operator validation scenarios.
