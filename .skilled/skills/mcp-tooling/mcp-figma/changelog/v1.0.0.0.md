# v1.0.0.0, First Stable Release

The `mcp-figma` skill gives an agent a CLI-first way to drive Figma Desktop from the terminal.

- It goes through the silships figma-cli, published to npm as `figma-ds-cli`.
- The CLI is the primary surface for inspecting, exporting and rendering work.
- It also manages tokens, variables and components.
- It extracts or imports a design system.

The optional Figma MCP runs through this project's Code Mode.

- It is used only for codegen.
- It pulls Figma design data into the agent.

Risk gating and a design handoff shape the skill.

- The spine of the skill is the read-only / mutating / destructive gating taxonomy.
- It is also the `sk-design-interface` handoff.
- That handoff keeps design judgment where it belongs.

The first build remains the core of the 1.0.0.0 surface.

- The `SKILL.md` runtime, references, scripts and docs formed the skill's first build.
- So did its design decisions.

&nbsp;

## Why This Release

This release promotes the skill to a stable 1.0.0.0 line.

- Live external verification is complete.
- An embedded install scaffold now mirrors the other mcp-server skills.

## Figma Desktop

#### Follow Sibling Patterns <a id="c-follow-sibling-patterns"></a>

- The skill was modeled on `mcp-chrome-devtools`, which is CLI-primary plus MCP-via-Code-Mode.
- It was also modeled on `mcp-open-design`.
- That skill is CLI plus optional MCP, a daemon model and gated verbs.
- `references/figma-cli-reference.md` records binary identity, the connect/daemon model and grouped command examples.

#### Keep the MCP Optional <a id="c-keep-the-mcp-optional"></a>

- `mcp-servers/figma-mcp/` points to the optional Framelink `figma` Code Mode MCP.
- Nothing is installed there.
- That is because the manual is already registered in the repo `.utcp_config.json`.
- So the README there documents the opt-in path rather than vendoring a server.
- `references/mcp-wiring.md` describes a prefixed `.env` token, a discover-first flow and a `call_tool_chain` example.
- It notes the official Figma Dev Mode MCP as a future option.
- `scripts/print-utcp-snippets.sh` prints the optional Code Mode wiring without editing files.

#### Gate Risky Connections <a id="c-gate-risky-connections"></a>

- `references/tool-surface.md` defines read-only, mutating, destructive and arbitrary action classes.
- It lists destructive actions with rollbacks.
- `scripts/connect-safe.sh` guides a safe plugin connection.
- It refuses to patch Figma.
- `scripts/connect-yolo.sh` performs the gated yolo connection.
- It requires `--i-understand-this-patches-figma` before patching `app.asar`.
- `scripts/unpatch.sh` rolls the yolo patch back.

## Installation and Diagnostics

#### Delegate to the Installer <a id="c-delegate-to-the-installer"></a>

- `mcp-servers/figma-cli/setup.sh` delegates to the skill's `scripts/install.sh`.
- The scaffold installs and references the MIT-licensed CLI without source-vendoring it.

#### Keep the Package Names Straight <a id="c-keep-the-package-names-straight"></a>

- The unrelated npm package `figma-cli` exposes a `figma` binary.
- The installer never runs `npm i -g figma-cli`.
- `references/troubleshooting.md` maps symptoms to causes and fixes, including the package collision.

#### Install and Verify Only <a id="c-install-and-verify-only"></a>

- `scripts/install.sh` installs and verifies only, using npm `figma-ds-cli` or the silships repository.
- It never connects to Figma or patches it.
- `scripts/_common.sh` provides shared binary resolution plus helpers.

#### Share Install and Diagnosis <a id="c-share-install-and-diagnosis"></a>

- `mcp-figma` follows the shared mcp-skill install-and-doctor standard alongside `mcp-open-design` and `mcp-chrome-devtools`.
- `mcp-click-up` and `mcp-code-mode` are part of the same standard.
- The standard includes an `INSTALL-GUIDE.md`.
- It also pairs a non-mutating `scripts/install.sh` with a read-only `scripts/doctor.sh`.
- The install guide covers installation, connection, daemon use, MCP and safety.
- The doctor reports binary identity, Figma Desktop, the daemon, ports and the Code Mode `figma` manual.
- `scripts/daemon.sh` wraps status, diagnose, start, stop, restart and reconnect for the local daemon.

## Skill and Documentation

#### Carry the Runtime Forward <a id="c-carry-the-runtime-forward"></a>

- The initial `SKILL.md` build uses lean house-template runtime instructions.
- Its WHEN TO USE section covers CLI versus optional-MCP triggers, use cases and anti-patterns.
- SMART ROUTING covers direction plus binary detection, phase flow and a six-intent guarded router.
- HOW IT WORKS covers binary verification, the Figma Desktop and daemon model, connect modes, command classes and optional Framelink MCP.
- RULES organizes ALWAYS / NEVER / ESCALATE IF around the `figma-ds-cli` naming trap, safe-default connect and gating every destructive verb.
- Sections 5-8 cover references, success criteria, integration points and related resources.
- Its runtime `allowed-tools` are minimal: `Read, Bash, Grep, Glob, mcp__code_mode__call_tool_chain`.

#### Keep Operator Docs Aligned <a id="c-keep-operator-docs-aligned"></a>

- The house-voice pass covers `SKILL.md` and its references.
- It also covers `INSTALL-GUIDE.md`, `feature-catalog/feature-catalog.md` plus `manual-testing-playbook/manual-testing-playbook.md`.
- The `README.md` gives a narrative house-voice overview.
- The feature catalog groups capabilities by area.
- The manual testing playbook gives safe operator validation scenarios.
