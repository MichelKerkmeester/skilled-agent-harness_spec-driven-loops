# v1.1.7.0, Routing Summary Up Front

The routing section of this packet carried five subsections. They ran from direction detection to a hundred-line pseudocode block. So the answer to where a Figma request lands sat below all of it. The section now says in a few sentences what selects this packet. It names which direction wins. It names which two reference files load first. It says where the routing detail lives. The subsections moved without a word changing.

&nbsp;

## What's New at a Glance

- The routing section reads as a summary.
  - Six sentences name the hub signal.
  - The sentences name the CLI-first direction and the two first reference leaves.
  - The sentences name the two binary traps and the design-reference pairing.
  - The sentences name the gated command classes.
- The routing detail is unchanged, one section down.
  - Direction detection, phase detection, resource domains, loading levels and the router pseudocode keep their headings.
  - The subsections keep their order and every byte.
  - The subsections sit in a final MACHINE ROUTER section.
- The section pointers follow the detail.
  - Two places named Section 2 as the routing authority.
  - The two places now name the MACHINE ROUTER section instead.
- Routing behaves exactly as before.
  - Every intent signal, resource map entry and loading-level row kept its old value.
  - So the same request loads the same files.
