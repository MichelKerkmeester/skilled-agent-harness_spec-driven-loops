# v1.1.7.0, Routing Summary Up Front

The routing section of this packet carried five subsections, from direction detection to a hundred-line pseudocode block, so the answer to where a Figma request lands sat below all of it. The section now says in a few sentences what selects this packet, which direction wins, which two reference files load first and where the routing detail lives. The subsections moved without a word changing.

## What's New at a Glance

- **The routing section reads as a summary.** Six sentences name the hub signal, the CLI-first direction, the two first reference leaves, the two binary traps, the design-reference pairing and the gated command classes.
- **The routing detail is unchanged, one section down.** Direction detection, phase detection, resource domains, loading levels and the router pseudocode keep their headings, their order and every byte, in a final MACHINE ROUTER section.

- **Routing behaves exactly as before.** Every intent signal, resource map entry and loading-level row kept its old value, so the same request loads the same files.
