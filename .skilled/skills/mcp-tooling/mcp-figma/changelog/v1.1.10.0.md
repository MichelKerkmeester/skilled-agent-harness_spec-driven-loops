# v1.1.10.0, The Machine Router Moves to ROUTER.md

The machine router now lives in a sibling `ROUTER.md`. Its parsed routes remain identical to the previous edition.

&nbsp;

## What's New at a Glance

- **The router keeps its machine map together.** `ROUTER.md` places `## 3. MACHINE ROUTER` after a short overview and intent model. It holds the intent map, resource map, default resource, loading levels and routing pseudocode.
- **SMART ROUTING stays short.** `SKILL.md` keeps short prose and ends with one line linking to `ROUTER.md`.
- **Related documents use the new path.** Testing playbooks that pointed to the router inside `SKILL.md` now point to `ROUTER.md`; the feature catalog entries and references still cite the old location.
- **The contract checks intent alignment.** `ROUTER.md` keeps `INTENT_SIGNALS` as an exact mirror of `INTENT_MODEL`, which the router contract now checks.
- **Every related-document table reaches the machine router.** The README, the install guide, the examples index and the CLI server README now list `ROUTER.md`.
