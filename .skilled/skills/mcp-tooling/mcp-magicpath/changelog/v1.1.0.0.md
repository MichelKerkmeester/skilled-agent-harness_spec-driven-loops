# v1.1.0.0, Design Authority Binding

MagicPath returns design-system facts that need a design judgment. v1.1.0.0 pairs every invocation with `sk-design`, so the judgment those facts invite has an owner while the transport's read-only surface does not change.

## Why This Release

The previous contract said this packet issued no design verdict and pointed the reader away. That was correct about ownership but left the verdict without value scales, interaction guidelines, motion principles or a WCAG (Web Content Accessibility Guidelines) review pass.

---

## What's New at a Glance

- **`sk-design` loads on every MagicPath invocation.** Wiring checks and theme lookups follow the same route.
- **The `ALWAYS` rule requires reading `sk-design`.** Naming the route in a response does not satisfy that rule.
- **The `NEVER` rule names `sk-design` as the owner of taste verdicts.** A separate `NEVER` rule forbids answering a MagicPath request without the pairing loaded.
- **`ESCALATE` covers retrieved evidence that conflicts with an `sk-design` decision.** Theme variables and component interactions can raise that conflict.
- **`references/design-authority.md` is new.** It sets a written contract for the pairing.
- **The active runtime selects the design agent persona.** Runtime-specific agent directories determine which variant applies.
- **MagicPath and its sibling transports use different design skills.** MagicPath pairs with `sk-design` while the siblings pair with `sk-design-md-generator`.
- **`transport-axis` now names each transport's judgment owner.** `crossHubPairing` has no pairing entry.
- **The MagicPath changelog aggregation path is linked to its entry.** `mcp-notion` and `mcp-obsidian` were linked at the same time.
- **The fourteen registered callables are unchanged.** No tool was added, removed or renamed.

## MagicPath Design Authority

#### Every Invocation Loads the Pairing

`sk-design` loads at STEP 0 of phase detection, before intent scoring and before the first tool call. No keyword, confidence score or test for whether work is design-affecting gates it.

&nbsp;

#### Loading Means Reading

Naming the route in a response does not count as a read. A packet already in context is not read again. The Resource Loading Levels table gained this packet's first `ALWAYS` row.

&nbsp;

#### The Verdict Has an Owner

`When NOT to Use` was rewritten so the packet can be skipped only when work has no MagicPath surface. When there is one, the packet supplies `sk-design` rather than handing back unowned facts.

&nbsp;

#### Conflicting Evidence Needs Resolution

A theme variable failing a contrast floor or a component whose interaction contradicts the guidelines can trigger `ESCALATE`. It asks which source prevails before either reaches an answer.

&nbsp;

#### The Pairing Has a Written Contract

`references/design-authority.md` was created to define the pairing:

- what each side owns
- why the pairing is not gated
- which failure modes it closes

&nbsp;

#### Reading Depends on Prompt Discipline

Nothing mechanically enforces the pairing. The `ALWAYS` rule is prompt-time discipline, and an agent that skips STEP 0 gives the same unowned answer as before. No gate, hook or validator observes whether `sk-design` was read.

## Persona Boundaries

#### The Packet Inherits Operating Rules

The packet operates under the design agent persona. It inherits LEAF-only execution (no sub-agent dispatch), read before edit, verify before claiming completion and mutate only what the request names.

&nbsp;

#### The Persona Does Not Grant Tools

Not inherited: write authority. The persona is write-capable and the transport is not. The conflict is stated explicitly and resolved toward the narrower surface: `mutatesWorkspace: false` holds, and Write, Edit and Task stay forbidden. A persona is a judgment contract, not a grant of tools. Adopting it wholesale would have quietly made the read-only transport mutating and stripped meaning from the hub's transport axis.

&nbsp;

#### Runtime Selects the Persona

The persona resolves from the active runtime's agent directory, including `.opencode/agents/design.md`, `.claude/agents/design.md` and sibling runtime paths. Resolution follows the runtime and never hardcodes one path. The two runtime variants differ in size, are not byte-identical and are not symlinks of each other, so a divergence between them produces a different persona depending on where the packet runs.

&nbsp;

#### Write Exclusion Is Documented

The persona's write-authority exclusion is documented, not enforced. It rests on the existing `allowed-tools` list, which already excludes Write and Edit, and adopting the persona cannot widen that list. Nothing verifies that future edits preserve the reasoning behind the exclusion.

## Design Pairing

#### Sibling Transports Measure Visuals

`mcp-figma`, `mcp-refero` and `mcp-mobbin` pair with `sk-design-md-generator`. It measures a live surface's real CSS (Cascading Style Sheets) into named tokens, which suits retrieved visual material with no token vocabulary of its own.

&nbsp;

#### MagicPath Returns Named Tokens

`get_theme` returns named CSS variables and fonts authored as a design system, so there is nothing to re-measure. The measurement is what the API (application programming interface) hands back, leaving the decide half missing. The divergence from the siblings is deliberate and recorded as such, not an oversight. `sk-design-md-generator` applies unchanged when the reference is an external live site rather than a MagicPath theme.

## Hub Registry

#### Judgment Owners Are Named

The `transport-axis` description now names the judgment owner for each transport instead of asserting one pairing for all four. An attempted `crossHubPairing` entry was reverted after the compiled-routing pre-push gate rejected it because `registry-compiler.cjs:249-255` resolves the object's values as skill IDs against a registry set that `sk-design` cannot join without its own `mode-registry.json`.

`crossHubPairing` is `{}`. It was deliberately emptied after the MT-008 over-routing incident and retained only for provenance hashing, so the pairing lives in prose. The field cannot carry a value for any transport, which leaves readers unable to resolve a transport's design partner from the registry. Closing that gap would require changing the routing compiler and reopening the path MT-008 closed.

&nbsp;

#### Changelog Links Resolve

`.opencode/changelog/mcp-tooling/mcp-magicpath` was symlinked to this packet's `changelog/` directory, matching the sibling entries. `mcp-notion` and `mcp-obsidian` were linked at the same time, so all ten entries resolve. The changelog files are real files in the packet. Only the aggregation directory is a symlink.

## Tool Surface

#### Existing Calls Keep Their Shape

No breaking change affects the tool surface. Every existing call form, argument, bound and error shape is unchanged. A caller that already invoked this packet keeps working and now additionally carries the design authority it previously had to remember to load.
