# v1.1.0.0 - Design Authority Binding

**Released:** 2026-08-29

`sk-design` is now loaded unconditionally on every invocation, under the design agent persona resolved from the active runtime's agent directory. The transport's read-only surface is unchanged: no tool was added, removed, or renamed, and the fourteen registered callables are the same fourteen. What changed is who is accountable for the judgment that MagicPath facts invite.

---

## What Changed

### The Unconditional Pairing

- `sk-design` loads at STEP 0 of phase detection, before intent scoring and before the first tool call. It is **not** trigger-gated: no keyword, no confidence score, and no "is this design-affecting?" test precedes it. A wiring check and a theme lookup load it alike.
- A new ALWAYS rule states that loading means reading. Naming the route in a response does not satisfy it; a packet already in context is not re-read.
- A new ALWAYS row was added to the Resource Loading Levels table, the first `ALWAYS` level this packet has carried.
- `references/design-authority.md` was created as the contract: what each side owns, why the pairing is not gated, and the failure modes it closes.

### The Persona

- The packet operates under the design agent persona, resolved from the ACTIVE runtime's agent directory (`.opencode/agents/design.md`, `.claude/agents/design.md`, and the sibling runtime paths). Resolution is by runtime; the variants are not byte-identical and the path is never hardcoded.
- Inherited: LEAF-only execution, no sub-agent dispatch, read before edit, verify before claiming completion, mutate only what the request names.
- **Not inherited: write authority.** The persona is write-capable and this transport is not. The conflict is stated explicitly and resolved toward the narrower surface: `mutatesWorkspace: false` holds, and Write, Edit, and Task stay forbidden. A persona is a judgment contract, not a grant of tools — had it been adopted wholesale, a read-only transport would have quietly become a mutating one and the hub's transport axis would have stopped meaning anything.

### The Verdict Now Has An Owner

- The previous contract said this packet "issues no design verdict" and pointed the reader away. That was correct about ownership and wrong about outcome: the verdict still got made, just without the value scales, interaction guidelines, motion principles, or the WCAG review pass.
- The "When NOT to Use" bullet was rewritten. Skipping this packet is now correct only when the work has no MagicPath surface in it at all; when it does, the packet supplies `sk-design` rather than handing back unowned facts.
- The NEVER rule about taste verdicts now names `sk-design` as the owner instead of leaving the judgment unassigned, and a new NEVER forbids answering a MagicPath request without the pairing loaded.
- A new ESCALATE case covers retrieved evidence conflicting with an `sk-design` decision — a theme variable failing a contrast floor, a component whose interaction contradicts the guidelines — asking which source prevails before either reaches an answer.

### Why sk-design And Not sk-design-md-generator

- The three sibling design transports (`mcp-figma`, `mcp-refero`, `mcp-mobbin`) pair with `sk-design-md-generator`, which **measures** a live surface's real CSS into named tokens. That is right for them: each retrieves visual material carrying no token vocabulary of its own.
- MagicPath is different. `get_theme` already returns named CSS variables and fonts, authored as a design system, so there is nothing to re-measure — the measurement is what the API hands back. What this surface lacks is the **decide** half.
- The divergence from the siblings is therefore deliberate and is recorded as such, not left to read as an oversight. `sk-design-md-generator` still applies unchanged when the reference is an external live site rather than a MagicPath theme.

### Hub Registry

- The `transport-axis` description now names the judgment owner per transport instead of asserting one pairing for all four.
- `crossHubPairing` stays `{}`. An entry was written and then reverted: the compiled-routing pre-push gate refused it, and `registry-compiler.cjs:249-255` resolves that object's values as skill ids against a registry set `sk-design` cannot join, having no `mode-registry.json` of its own. The field was deliberately emptied after the MT-008 over-routing incident and is retained for provenance hashing only, so the pairing lives in prose.
- `.opencode/changelog/mcp-tooling/mcp-magicpath` was symlinked to this packet's `changelog/` directory, matching the sibling entries; `mcp-notion` and `mcp-obsidian` were linked at the same time, so all ten entries now resolve. The changelog files themselves remain real files in the packet; only the aggregation directory is a symlink.

## Compatibility

No breaking change to the tool surface. Every existing call form, argument, bound, and error shape is unchanged, and the fourteen registered tools are identical. A caller that already invoked this packet keeps working; it now additionally carries the design authority it previously had to remember to load.

---

## Known Limitations

- Nothing enforces the pairing mechanically. The ALWAYS rule is prompt-time discipline, and an agent that skips STEP 0 produces the same unowned answer the previous version did. There is no gate, hook, or validator that observes whether `sk-design` was actually read.
- The pairing is prose-only and stays that way. `crossHubPairing` cannot carry a value for any transport, so no reader can resolve a transport's design partner from the registry. Closing that gap means changing the routing compiler, which reopens the path MT-008 closed.
- The persona's write-authority exclusion is documented, not enforced. It rests on the same `allowed-tools` list that already excluded Write and Edit; adopting a persona cannot widen that list, but nothing verifies the reasoning behind the exclusion survives a future edit.
- The two runtime variants of the design agent (`.opencode/` and `.claude/`) differ in size and are not symlinks of each other. This packet resolves by runtime rather than reconciling them, so a divergence between the variants will produce a correspondingly different persona depending on where the packet runs.
