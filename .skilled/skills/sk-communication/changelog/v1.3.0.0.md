# 1.3.0.0, Copy Editing Declared and Recorded Honestly

The wording standard's reply base is now the instruction the provider receives. The release also updates the rewrite guidance and records reply measurements on two models.

## Why This Release

The copy-editing pass is declared in one place, and unchanged results are reported as no-ops rather than passes.

## What's New at a Glance

- **The reply base is the provider's instruction.** Both profiles read the declaration.
- **Unchanged results are recorded honestly.** The accepted record uses `no-op` as the change kind rather than a pass.
- **The validator no longer stamps pass markers on candidates that never reach the comparisons.** It also rejects candidates that lose claims, caveats or requirements.
- **Both rewrite commands declare the copy-editing pass.** Their text sets the pass's scope and fidelity behavior.
- **The wording-standard section carries one exclusion.** The voice-personality exclusion stays with its ownership reason.
- **The feature catalog records the changed capability.** It records one instruction declaration.
- **Claude mirrors stay identical.** Both mirrors under `.claude/commands/rewrite/` receive the same change and diff empty against their sources.
- **The existing safeguards are unchanged.** The default-off enablement flag and advisor route exclusion are unchanged, and exact-original fallback applies on every failure.
- **Reply measurements show model-specific results.** The weighted mean rose for both measured models.

---

## Copy Editing

#### The Reply Base Is the Instruction

`resolveCopyEditingInstruction()` in `src/config/copy-editing-instruction.ts` builds the instruction and its temperature. It reads the wording standard's reply base from the `sk-doc` skill the first time a prompt profile is built, then caches the result. Nothing is read at import, so a packed install can import the package. A runtime without the standard fails exactly where a provider would run without it.

&nbsp;

#### Profiles Share One Instruction

The local and external-cli profiles resolve to byte-identical instructions. Thinking mode is provider-default on both.

&nbsp;

#### One Home for the Standard

The wording standard is still the Human Voice Rules under `sk-doc`, with one home. The package no longer carries the standard under its `docs/` and the package carries no copy of it.

---

## Validator Outcomes

#### Records Follow the Candidate

The validator stamps its five pass markers only inside the guard, so a candidate that never reaches the comparisons no longer carries markers it did not earn. The claim-omission comparison rejects a candidate that loses a claim, caveat or requirement.

---

## Rewrite Guidance

#### Commands Declare the Pass

Both rewrite commands now describe a copy edit that rewords without reordering, cutting or adding. Their text says the copy edit returns the exact original on any fidelity failure.

&nbsp;

#### Exclusions Match the Reply

The scoring bands of the pre-publish checklist left the exclusion table. They live in the standard's publish supplement, which a reply never loads.

&nbsp;

#### Catalog Records the Changes

The feature catalog records the reply base as the instruction. It also records the claim-omission check and the no-op record.

---

## Reply Measurements

#### Results Differ by Model

On GLM-5.3-Flash, the weighted mean rose from 0.60 to 0.74, no dimension fell and the negative control held. The first-line contract and the visible-item cap showed no measurable effect, so the release gate did not certify release.

On Sonnet 5, the weighted mean rose from 0.71 to 0.73 and the first-line contract worked. The visible-item cap did not change either model's list grouping. The receipts rule held on GLM-5.3-Flash but not on Sonnet 5.
