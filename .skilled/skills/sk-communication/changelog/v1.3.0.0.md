## [**1.3.0.0**] - 2026-09-14

The pass the rewrite performs is now declared in one place and reported honestly. The provider works from the wording standard's reply base, the validator records a no-op when nothing changed, and the documents declare the same pass.

---

## What Changed

#### The instruction is the wording standard's reply base

- **One declaration.** `resolveCopyEditingInstruction()` in `src/config/copy-editing-instruction.ts` builds the instruction and its temperature. It reads the wording standard's reply base from the sk-doc skill the first time a prompt profile is built and caches the result. Nothing is read at import, so a packed install can import the package, and a runtime without the standard fails exactly where a provider would run without it.

- **The packed copy is gone.** The package no longer carries the standard under its `docs/`. The standard has one home in the sk-doc skill, and the package carries no copy of it.

- **Both profiles read the declaration.** The local and external-cli profiles resolve to a byte-identical instruction, and thinking mode is provider-default on both.

#### The validator tells the truth

- **The five pass markers are stamped only inside the guard.** A candidate that never reaches the comparisons no longer carries markers it did not earn.

- **An unchanged candidate records a no-op.** The change kind on the accepted record reads no-op rather than a pass.

- **A dropped claim is rejected.** The claim-omission comparison rejects a candidate that loses a claim, caveat or requirement.

#### The documents declare the pass

- **Both rewrite commands declare the pass in their own text.** They name a copy edit that rewords without reordering, cutting or adding, and that returns the exact original on any fidelity failure.

- **The wording-standard section carries one exclusion.** The scoring bands of the pre-publish checklist left the exclusion table, because they live in the standard's publish supplement, which a reply never loads. The voice-personality exclusion stays with its ownership reason.

- **The feature catalog records the changed capability.** One instruction declaration, the reply base as instruction, the claim-omission check, the no-op record.

- **Claude mirrors stay identical.** Both mirrors under `.claude/commands/rewrite/` receive the same change and diff empty against their sources.

#### What stays

- **The invariants.** The default-off enablement flag, the advisor route exclusion and the exact-original fallback on every failure.

- **The wording standard.** Still the Human Voice Rules under `sk-doc`, one home. The reply base is now also the instruction the provider receives.

## Measured result

The reply harness under `benchmark/reply-harness/` ran once across the pre-change and post-change rule sets on GLM-5.3-Flash. Weighted mean 0.60 to 0.74, no dimension fell, the negative control held. The first-line contract and the visible-item cap showed no measurable effect, so the release gate did not certify release. Details in the program packet's phase 005 summary.

A second run on Sonnet 5 read 0.71 to 0.73. The first-line contract worked there, the visible-item cap did not change either model's list grouping, and the receipts rule held on GLM but not on Sonnet.
