The initial release of `sk-communication` provides a portable projection layer that rewrites terse agent output into plain English while keeping the canonical event stream, transcript, tool data and model context byte-for-byte unchanged. Projection is off by default for everyone, and every unsafe or failed path returns the exact original.

## What's New at a Glance

- **`projectMessage` preserves canonical bytes on non-approved paths.** A provider-transport seam and reject-only default judge keep those paths from changing the original.
- **The capability and privacy gate fails closed.** It consults the compatibility doctor and returns the exact original on unknown, stale or incapable routes. It never routes hosted without a fresh, capable, privacy-approved decision.
- **The evaluation and release gate controls rollout.** It composes a blind non-inferiority signal as a reject-only quality check and blocks a runtime rollout without fresh, dated evidence.
- **OpenCode wires projection through its native plugin.** The plugin uses the `chat.message` hook and is default-off and fail-open.
- **CLI output is wrapped across five runtimes.** Claude Code, Codex, Pi, Devin and Cursor use a shared wrapper framework with per-runtime stream parsers.
- **Projection requires per-machine opt-in.** An operator opts in with `COMMUNICATION_PROJECTION_ENABLED` or a git-ignored `enablement.local.json` at the package root.
- **`sk-communication` is held out of advisor routing.** The route-exclusions denylist prevents the recommender from surfacing it, so you invoke it by hand.
