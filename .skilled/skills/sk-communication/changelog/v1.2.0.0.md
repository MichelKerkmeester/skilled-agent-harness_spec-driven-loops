Version 1.2.0.0 removes the explanation lane after it failed its purpose in terminals. The skill no longer adapts an explanation on two axes and now does only projection, the one thing it did well.

## Why This Release

Version 1.1.0.0's default was inverted the day before this removal so the visual published as a rendered page. That closed the defect but left the question of whether the skill should own visual explanation when the runtimes it targets publish rendered pages themselves.

## What's New at a Glance

- **The explanation lane is removed.** `/rewrite:explain-visually` is gone, leaving the skill focused on projection.
- **Five runtimes have no visual-explanation route.** The repo rule that used to name the command now says so.
- **Lane A is the skill's only lane.** It has six runtime adapters.
- **The Human Voice Rules have one home under `sk-doc`.** Rewrites are still held to them. The standard is routed to rather than copied.

---

## Visual Explanation

#### The Lane's References Are Removed

The removal also takes out:

- its modality reference
- both feature-catalog entries
- both playbook scenarios

&nbsp;

#### The Default Missed Its Purpose

The lane's job was the smallest visual that makes a point land. Its default was a Mermaid block fenced in the reply. A terminal displays that as source, so the reader got the diagram's code and had to imagine the diagram. The lane failed its stated purpose at the last step, every time.

&nbsp;

#### The In-Context Lane Reached All Six

The in-context lane ran on all six runtimes. The native capability that replaces it does not run on all six.

---

## Projection

#### Lane A Carries the Risk

Lane A is the projection lane, with a default-off enablement flag and egress rules. It carried the whole risk profile before the explanation lane was removed and carries it alone now.

&nbsp;

#### Earlier Work Stays in the Record

Version 1.1.0.0's entry and the packets that built the lane stay as written. They record what happened. Retrieval still finds them.
