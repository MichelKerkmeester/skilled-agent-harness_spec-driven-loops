## [**1.2.0.0**] - 2026-09-12

Removes the explanation lane. The skill adapted an explanation on two axes; it now does one thing, which is the one thing it did well.

---

## What Changed

#### The explanation lane is gone

- **`/rewrite:explain-visually` is removed**, with its modality reference, both feature-catalog entries and both playbook scenarios. The skill is projection only.

- **Why it went.** Its job was the smallest visual that makes a point land, and what it produced by default was a Mermaid block fenced in the reply. A terminal displays that as its own source, so the reader got the diagram's code and had to imagine the diagram. The lane failed its stated purpose at the last step, every time.

- **A fix shipped first and was not enough.** Version 1.1.0.0's default was inverted the day before this removal so the visual published as a rendered page. That closed the defect, and left a second question: whether this skill should own visual explanation at all now that the runtimes it targets publish rendered pages themselves.

- **The cost, stated plainly.** The lane was in-context, so it ran on all six runtimes. The native capability that replaces it does not. On the five runtimes without one, there is now no visual-explanation route, and the repo rule that used to name this command now says so.

#### What stays

- **Lane A, the projection lane**, with its six runtime adapters, its default-off enablement flag and its egress rules. It carried the whole risk profile before and carries it alone now.

- **The wording standard.** Rewrites are still held to the Human Voice Rules under `sk-doc`, which has one home and is routed to rather than copied.

- **The history.** Version 1.1.0.0's entry and the packets that built the lane stay as written. They record what happened, and retrieval still finds them.
