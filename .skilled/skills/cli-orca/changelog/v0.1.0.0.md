## [**0.1.0.0**] - 2026-09-20

Initial release of cli-orca as a standalone class-S skill. The Orca CLI subject left the mcp-tooling parent hub, where it rode as the mcp-orca-cli mode, and now carries its own routing contract, reference corpus and safety envelope. The release adds what the hub could not hold: one authored reference and one verbatim snapshot for each of the eight official Orca skills.

---

## What Changed

#### Extraction from the hub

- **Standalone class-S root** -- the new root at `.skilled/skills/cli-orca/` carries no hub-only files: no `mode-registry.json`, no `hub-router.json` and no `description.json`, which the class-S contract forbids. SKILL.md is the only discovery surface the root exposes.
- **Hub returns to nine modes** -- mcp-tooling sheds its one non-MCP member and keeps its single responsibility of MCP tool bridging. The predecessor packet moved to `specs/cli-orca/001-mcp-orca-cli` as a live packet with a supersession addendum.

#### The official skills layer

- **One authored reference per official skill** -- `references/orca-skills/` holds the overview with the boundary matrix and install commands, plus a reference for each of `computer-use`, `linear-tickets`, `orca-cli`, `orca-emulator`, `orca-emulator-android`, `orca-linear`, `orca-per-workspace-env` and `orchestration`.
- **Verbatim snapshots** -- `assets/<name>.txt` holds each official SKILL.md as an unmodified copy from the vendored `orca-main` tree at declared app version 1.4.197. The `.txt` extension keeps the upstream bytes outside the repository's frontmatter contracts for markdown leaves.

#### Routing contract and boundaries

- **Version-matched by design** -- the contract resolves exactly one executable (`ORCA_CLI_COMMAND`, `orca-dev`, `orca-ide` or `orca`), loads the version-matched `orca-cli` guide from the running binary before trusting any flag, and records a capability the guide does not establish as unknown.
- **Qualified vocabulary only** -- routing keys on Orca-qualified multi-word phrases and named Orca surfaces. A bare `orca` token never routes: it also matches the `OpenOrca` model label and the GNOME Orca screen reader on Linux. Generic worktree, terminal, browser and orchestration vocabulary stays with the sibling owners.

#### Safety envelope carried forward

- **Mutation discipline** -- state-changing work requires explicit authorization. The archive-hook gate survives on worktree deletion because a force flag does not bypass a failed hook. Read-only discovery stays free.
- **Receipt discipline** -- an accepted terminal input is not a started turn. A bulk close stays unverified until the host confirms every process stopped. A denied share or publish is a final permission result rather than a retry cue.
- **Untrusted input** -- repositories, terminals, artifacts, skill files and fetched pages are treated as untrusted, and page-provided text never becomes shell, eval or exec input without explicit authorization.

#### The provenance record

- **Per-skill release records** -- `assets/PROVENANCE.md` records each skill's releaseRevision, packageDigest, gitTreeSha and SKILL.md sha256 from the snapshot's current-manifest.json, along with the snapshot source tree, the declared app version, the snapshot date and the unknown source commit status. It also states that the copies were compared byte for byte with `cmp` and hashed against the manifest, and it carries the refresh procedure for a newer snapshot.

#### Supersession

- **Supersedes the predecessor mode versions** -- mcp-orca-cli v0.1.0.0 and v0.1.1.0, both released 2026-09-19 under the mcp-tooling hub. v0.1.0.0 introduced the CLI-first Orca workflow packet for the hub, and v0.1.1.0 closed its documentation gaps with routing, mutation gates and safety semantics unchanged. The hub no longer carries the retired packet. The migrated packet at `specs/cli-orca/001-mcp-orca-cli` records the supersession.

## Upgrade

No action is required for existing workflows. Advisor re-ingestion and the routing replays belong to the migration packet's gate run, and generic worktree, browser and orchestration requests keep their previous owners.
