The first `cli-orca` release moves Orca CLI work out of the `mcp-tooling` hub, where it ran as the `mcp-orca-cli` mode. The standalone skill carries its own routing contract and safety envelope, with an authored reference and a verbatim snapshot for each of the eight official Orca skills.

> Spec folder: `specs/cli-orca/001-mcp-orca-cli` (Level 3)

## Why This Release

The Orca CLI subject needed a separate home for official-skill references and snapshots the hub could not hold. `mcp-tooling` keeps its single responsibility, MCP tool bridging.

## Orca CLI Routing

#### A Standalone Class-S Root

The new root is `.skilled/skills/cli-orca/`. The class-S contract forbids `mode-registry.json`. It also forbids `hub-router.json` and `description.json` in this root. `SKILL.md` is the only discovery surface the root exposes.

&nbsp;

#### The Hub Returns to Nine Modes

Removing the non-MCP `mcp-orca-cli` mode returns `mcp-tooling` to nine modes. The predecessor packet moved to `specs/cli-orca/001-mcp-orca-cli` as a live packet with a supersession addendum.

&nbsp;

#### Qualified Terms Route Requests

The skill routes on Orca-qualified multi-word phrases and named Orca surfaces. A bare `orca` stays unmatched because it also matches the `OpenOrca` model label and the GNOME Orca screen reader on Linux. Generic worktree, terminal, browser and orchestration requests stay with their sibling owners.

&nbsp;

#### Flags Follow the Running CLI

The contract resolves exactly one executable from `ORCA_CLI_COMMAND`, `orca-dev`, `orca-ide` or `orca`. Before trusting a flag, it loads the version-matched `orca-cli` guide from that binary and records a capability the guide does not establish as unknown.

## Official Orca Skills

#### References Cover Eight Skills

`references/orca-skills/` holds an overview with the boundary matrix and install commands. It also contains an authored reference for each of `computer-use`, `linear-tickets`, `orca-cli`, `orca-emulator`, `orca-emulator-android`, `orca-linear`, `orca-per-workspace-env` and `orchestration`.

&nbsp;

#### Copies Preserve Upstream Bytes

`assets/<name>.txt` holds each official `SKILL.md` as an unmodified copy from the vendored `orca-main` tree at declared app version `1.4.197`. The `.txt` suffix keeps upstream bytes outside the repository's frontmatter contracts for Markdown leaves.

---

## Safety Boundaries

#### State Changes Need Authorization

State-changing work requires explicit authorization, while read-only discovery stays free. Worktree deletion keeps its archive-hook gate because a force flag cannot bypass a failed hook.

&nbsp;

#### Receipts and Inputs Stay Bounded

An accepted terminal input does not prove a turn started. A bulk close stays unverified until the host confirms every process stopped, while a denied share or publish is a final permission result rather than a retry cue. The input policy treats repositories, terminals, artifacts, skill files and fetched pages as untrusted. Page-provided text cannot become shell, `eval` or `exec` input without explicit authorization.

## Snapshot Provenance

#### Provenance Records Track Sources

`assets/PROVENANCE.md` records each skill's `releaseRevision`, `packageDigest`, `gitTreeSha` and `SKILL.md` sha256 from the snapshot's `current-manifest.json`. It also records the snapshot source tree, declared app version, snapshot date and unknown source-commit status. The copies were compared byte for byte with `cmp` and hashed against the manifest. The provenance file carries the refresh procedure for a newer snapshot.

## Supersession

#### Earlier Mode Releases Are Superseded

The `mcp-orca-cli` mode releases `v0.1.0.0` and `v0.1.1.0` both shipped under the `mcp-tooling` hub on `2026-09-19`. Version `v0.1.0.0` introduced the CLI-first Orca workflow packet for the hub. Version `v0.1.1.0` closed its documentation gaps while leaving routing and safety semantics unchanged. It also left the mutation gates unchanged. The hub no longer carries the retired packet. The migrated packet at `specs/cli-orca/001-mcp-orca-cli` records the supersession. Advisor re-ingestion and the routing replays belong to the migration packet's gate run.
