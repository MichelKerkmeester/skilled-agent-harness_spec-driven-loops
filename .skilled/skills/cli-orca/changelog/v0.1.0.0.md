# v0.1.0.0, cli-orca: Orca CLI as a Standalone Skill

The first `cli-orca` release moves Orca CLI work out of the `mcp-tooling` parent hub, where it ran as the `mcp-orca-cli` mode. The standalone class-S skill brings its own routing contract and safety envelope, with authored references and verbatim snapshots for all eight official Orca skills.

## Why This Release

The `mcp-tooling` hub could not hold one authored reference and one verbatim snapshot for each official Orca skill.

## What's New at a Glance

- **Orca CLI now has a standalone class-S skill.** The `mcp-orca-cli` mode leaves the `mcp-tooling` parent hub.
- **Authored references cover all eight official Orca skills.** The set includes an overview.
- **Each official skill has a verbatim snapshot.** The copies come from the vendored `orca-main` tree at declared app version `1.4.197`.
- **The routing contract follows the running Orca CLI version.** It loads that version's guide before trusting a flag.
- **Routing uses Orca-qualified multi-word phrases and named Orca surfaces.** A bare `orca` token does not route.
- **The safety envelope is carried forward.** The archive-hook gate survives on worktree deletion because a force flag does not bypass a failed hook.
- **Receipt rules cover terminal inputs, bulk closes and denied share or publish outcomes.** An accepted terminal input is not a started turn.
- **The release records snapshot provenance for each skill.** It includes the source, declared app version and manifest data.
- **The predecessor mode versions are superseded.** The hub no longer carries the retired packet.

## Orca CLI Skill

#### A Root Without Hub Files

The class-S root is `.skilled/skills/cli-orca/`, and `SKILL.md` is its only discovery surface. The class-S contract forbids `mode-registry.json`, `hub-router.json` and `description.json` there.

&nbsp;

#### The Hub Returns to Nine Modes

The hub returns to nine modes as `mcp-tooling` sheds one non-MCP member and keeps its single responsibility of MCP tool bridging. The predecessor packet moved to `specs/cli-orca/001-mcp-orca-cli` as a live packet with an addendum recording its supersession.

## Official Orca Skills

#### References Cover Each Skill

`references/orca-skills/` contains an authored reference for `computer-use`, `linear-tickets`, `orca-cli`, `orca-emulator`, `orca-emulator-android`, `orca-linear`, `orca-per-workspace-env` and `orchestration`. Its overview includes the boundary matrix and install commands.

&nbsp;

#### Snapshots Preserve Upstream Files

`assets/<name>.txt` contains each official `SKILL.md` as an unmodified copy from the vendored `orca-main` tree. The `.txt` extension keeps upstream bytes outside the repository's frontmatter contracts for Markdown leaves.

## Routing Boundaries

#### Flags Follow the Running CLI

The contract resolves exactly one executable: `ORCA_CLI_COMMAND`, `orca-dev`, `orca-ide` or `orca`. It loads the version-matched `orca-cli` guide from that binary before trusting any flag, then records a capability the guide does not establish as unknown.

&nbsp;

#### Qualified Terms Set the Route

A bare `orca` token never routes because it also matches the `OpenOrca` model label and the GNOME Orca screen reader on Linux. Orca-qualified multi-word phrases and named Orca surfaces define routing, while generic worktree, terminal, browser and orchestration vocabulary stays with the sibling owners.

---

## Safety Boundaries

#### The Safety Envelope Carries Forward

State-changing work requires explicit authorization. Read-only discovery stays free.

&nbsp;

#### Receipts Keep Actions Unconfirmed

A bulk close stays unverified until the host confirms every process stopped. A denied share or publish is a final permission result rather than a retry cue.

&nbsp;

#### Untrusted Inputs Stay Untrusted

Repositories, terminals, artifacts, skill files and fetched pages are treated as untrusted. Page-provided text never becomes shell, `eval` or `exec` input without explicit authorization.

---

## Snapshot Provenance

#### Provenance Records Each Snapshot

`assets/PROVENANCE.md` records each skill's `releaseRevision`, `packageDigest`, `gitTreeSha` and `SKILL.md` sha256 from the snapshot's `current-manifest.json`. It also records the snapshot source tree, declared app version, snapshot date and unknown source commit status.

The copies were compared byte for byte with `cmp` and hashed against the manifest. The provenance record includes the refresh procedure for a newer snapshot.

## Supersession

#### Earlier Mode Versions Are Superseded

The superseded `mcp-orca-cli` versions are `v0.1.0.0` and `v0.1.1.0`, both released under the `mcp-tooling` hub on `2026-09-19`. The first introduced the CLI-first Orca workflow packet for the hub. The second closed its documentation gaps, with routing, mutation gates and safety semantics unchanged. Advisor re-ingestion and the routing replays belong to the migration packet's gate run.
