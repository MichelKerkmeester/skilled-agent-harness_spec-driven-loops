# v0.1.5.0, Long Prose Lines Become Short Sentences and Lists

Five passages in the cli-orca skill were written as one very long line each: the opening summary, the handoff paragraph, the terminal paragraph, the embedded-browser paragraph and the automations paragraph. A reader had to untangle four or five rules out of a single sentence.

Those lines are now short sentences, and a line that carried several rules or steps is now a short list. The instruction comes before the background it needs, and instructions address you directly.

The content did not change. Every path, link target, command and number in the old lines is still there, and the rewrite adds nothing new. What selects this skill, what loads first and how a request routes are exactly as they were.

> Spec folder: `specs/sk-doc/072-skill-routing-and-clarity/010-prose-clarity-pass` (Level 2)

&nbsp;

## What's New at a Glance

- **The opening summary is two short paragraphs.** The list of Orca surfaces stays, then the versioned-runtime rule reads as an instruction to load the matching guide before relying on a flag.
- **The handoff paragraph is a list.** Reporting the new worktree, the agent handle and the prompt receipt comes first, and the two prohibitions each get their own bullet.
- **The terminal paragraph separates the rules.** Reading before sending and the wait-submit behavior open, then the ambiguous-transport replay and the bulk-close verdict stand as bullets.
- **The browser paragraph is split.** The scope and the snapshot loop open, tab-scoped refs and untrusted page content each get a bullet, and the ownership pointer closes it.
- **The automations paragraph is split.** Mutually exclusive scopes and starting disabled open, then the separate sharing permissions and the no-secrets rule follow.
- **Every fact is the same.** No lane, intent signal, reference path or command changed, so a request routes where it always did.
