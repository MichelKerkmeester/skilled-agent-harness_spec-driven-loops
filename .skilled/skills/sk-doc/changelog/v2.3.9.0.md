# v2.3.9.0, Root Playbook Paths Checked

The playbook validator's backticked path report read scenario files only. So a root `manual-testing-playbook.md` could keep citing a path its scenario had already corrected. Nothing reported it. The root file is now checked the same way. The warning stays report-only.

&nbsp;

## What's New at a Glance

- **Root files are checked.** A backticked path in a package's root playbook file that resolves from no base prints `BACKTICK_PATH_UNRESOLVED` under the file name `manual-testing-playbook.md`.
- **A regression case covers it.** The validator test appends a missing path to a fixture root. It expects exactly that one warning.
- **The playbooks, catalogs and README agree with the router's new home.** Every scenario reads the intent maps in `ROUTER.md` section 3 rather than a `SKILL.md` block. The anchor tables name `ROUTER.md` as the router under test. The overview lists all fifteen modes. The intent model sends diagram work to the `sk-design` hub. The replay entry quotes the 64-row gold and the eight unscored `sk-code` rows. The README map names `ROUTER.md`.
