# v2.3.5.0, Version names the skill edition

v2.3.5.0 keeps the frontmatter version on SKILL.md only, so verify passes on every skill, and widens the catalog, citation and playbook checks.

> Spec folder: `specs/sk-code/011-sk-code-poinytail-based-refinement/021-open-ends-remediation/003-doc-and-catalog-truth` (Level 1)

&nbsp;

## What's New at a Glance

- **Version lives on SKILL.md only.** `frontmatter-version.mjs` versions `SKILL.md` alone, as the skill edition, and `verify` now exits 0 on all 14 skills where it failed on all 14. `package_skill.py` checks a version on changelog entries only, the post-edit router fires the version gate for `SKILL.md` only, and the playbook validator no longer asks a scenario for one.
- **Child docs lost their version line across the fleet.** One script run removed the stale line from 2,845 child docs in all 14 skills. The line removal is housekeeping that this contract owns, so it is recorded here and the other skills are not bumped for it.
- **The standard and templates match.** `frontmatter-versioning.md` drops the per-doc build count and the amend ritual, and `frontmatter-templates.md` keeps `version` on the `SKILL.md` template only.
- **Two-column catalog tables are checked.** `validate_catalog_package.py` now checks the paths in a `| File | Role |` table.
- **Citations relative to runtime/ and scripts/ resolve.** `cite-drift-scan.mjs` tries a skill's `runtime/` and `scripts/` directories, and `--overlap` prints an advisory line for each in-range citation whose window lost its identifier.
- **Backticked playbook paths are reported.** The playbook validator warns, without failing, on a backticked path that resolves from no scenario, playbook, skill, hub or repository base, and its piped report now arrives whole.

&nbsp;

## Upgrade

No migration required. A new child doc carries no `version`; only `SKILL.md` and changelog entries do.
