# v2.3.8.0, Playbook Paths That Resolve

The playbook validator's backticked path report flagged two kinds of path that were never drift. A symlink whose target is a build output counted as missing until the build ran, so the same tree printed a different count before and after a build. The `/doctor:update` scenarios name `base.json`, `divergence.json` and run records under `.skilled/release/`, which the command writes into an installed tree and the source repository never holds. Both now resolve, and the warning stays report-only.

> Spec folder: `specs/sk-code/011-sk-code-poinytail-based-refinement/022-doc-version-and-playbook-paths/002-playbook-path-repair` (Level 2)

&nbsp;

## What's New at a Glance

- **A symlink is a repository path.** A backticked path that names a symlink resolves even when the link's target has not been built yet.
- **Installed-tree release state is skipped.** A path under `.skilled/release/` is expected not to resolve in the source repository.
- **The pipe test seeds its own report.** The regression that proves a large report arrives whole now builds a package with 1,500 unresolved paths, because the corpus no longer prints enough warnings to fill a pipe.
