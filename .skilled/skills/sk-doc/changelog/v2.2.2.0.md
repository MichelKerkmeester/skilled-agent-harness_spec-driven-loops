# v2.2.2.0, No Changelog Entry Escapes the Check

The validator now checks every changelog entry it is given. Three packet changelogs about install guides were typed as install guides and failed rules meant for another kind of document, and five in a phase folder named for its fixtures were skipped as a fixture tree. All eight now pass the changelog check.

> Spec folder: `specs/sk-doc/061-skilled-release-changelog/003-adjacent-alignment` (Level 2)

## What's New at a Glance

- **The folder decides the type.** A document under a `changelog/` folder is a changelog before any word in its name counts, so `changelog-003-003-install-guide-docs.md` is checked as a changelog.
- **A numbered folder is never a fixture tree.** The fixture skip still covers folders such as `fixtures/` and `test-fixtures/`, but it passes over a folder whose name starts with a spec number, such as `001-shared-mode-contracts-and-fixtures`. The spec documents in those folders are checked too.
- **Three tests cover it.** One for each defect fails on the old validator, and a third shows that real install guides and fixture trees keep their handling.
- **The catalog and the frontmatter reference list the check.** The hub's feature catalog gains a Document Validation entry, and the frontmatter reference lists changelog entries as a document type with the five keys they carry.

## Upgrade

No migration required. The eight entries already carried their metadata, so they pass as they are.
