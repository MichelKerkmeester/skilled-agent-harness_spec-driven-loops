# v2.2.2.0, No Changelog Entry Escapes the Check

The validator now checks every changelog entry it is given. Three packet changelogs about install guides were typed as install guides. They failed rules meant for another kind of document. Five sat in a phase folder named for its fixtures. They were skipped as a fixture tree. All eight now pass the changelog check.

> Spec folder: `specs/sk-doc/061-skilled-release-changelog/003-adjacent-alignment` (Level 2)

## What's New at a Glance

- **The folder decides the type.** A document under a `changelog/` folder is a changelog. That holds before any word in its name counts. So `changelog-003-003-install-guide-docs.md` is checked as a changelog.
- **A numbered folder is never a fixture tree.** The fixture skip still covers folders such as `fixtures/` and `test-fixtures/`. But it passes over a folder whose name starts with a spec number. One example is `001-shared-mode-contracts-and-fixtures`. The spec documents in those folders are checked too.
- **Three tests cover it.** One test for each defect fails on the old validator. A third shows that real install guides and fixture trees keep their handling.
- **The catalog and the frontmatter reference list the check.** The hub's feature catalog gains a Document Validation entry. The frontmatter reference lists changelog entries as a document type. It gives the five keys they carry.

## Upgrade

No migration required. The eight entries already carried their metadata. So they pass as they are.
