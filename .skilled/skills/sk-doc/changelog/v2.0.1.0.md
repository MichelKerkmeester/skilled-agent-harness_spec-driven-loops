# sk-doc changelog: v2.0.1.0, Root Router Adoption

The sk-doc hub's second-stage surface router now has a first-class root `ROUTER.md`, following the two-state root-router document standard.

## What's New at a Glance

- **The second-stage surface router now lives in root `ROUTER.md`.** It is v1.0.1.0 with `router_state: active` and `skill_pointer: SKILL.md`.
- **The machine-readable routing block is preserved.** `INTENT_SIGNALS` / `RESOURCE_MAP` is byte-identical to the legacy file (sha256 `2ad1469c…`), while the prose describes the active root router and every mapped path resolves on disk.
- **The hub's documentation points to the router.** Section 2 (two-stage routing) of `SKILL.md` gains a Surface Router pointer. The layout tree gains the `ROUTER.md` entry while REFERENCES gains the surface-router entry. An ALWAYS rule pins the `RESOURCE_MAP` / `leaf-manifest.json` + `leaf-aliases.json` sync.
- **The root router is now stage two in the hub docs.** `SKILL.md` and `README.md` advance from v2.0.0.0 to v2.0.1.0. `description.json` makes the same version change.
- **`leaf-manifest.json` is regenerated through the owner tool.** Its delta is a pre-existing staleness fix: the generator walks only `references/` and `assets/` leaf roots, and the on-disk `sk-create-skill` v4 upgrade leaf is now listed.
- **Routing behavior is unchanged.** `mode-registry.json`, `hub-router.json`, the `null` default mode, bundle rules and every create packet are untouched. The stage-one default `shared/references/quick-reference.md` is byte-identical.
- **The shared quality-control backbone is unchanged.** The shared `sk-create-quality-control` backbone, its scripts and the shared reference base did not change.
- **Historical references are untouched.** This includes changelog entries and dated benchmark reports that name the legacy path.
- **`shared/references/smart-routing.md` is deleted.** Compiled-manifest freshness remains the downstream fleet-rebuild gate.

No migration required.
