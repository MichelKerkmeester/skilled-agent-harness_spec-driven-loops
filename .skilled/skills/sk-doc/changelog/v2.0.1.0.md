# sk-doc changelog: v2.0.1.0

The hub's second-stage surface router is now a first-class root `ROUTER.md` per the two-state root-router document standard.

## Added

- Root `ROUTER.md` (v1.0.1.0): the stage-two surface router now lives at the hub root with `router_state: active` and `skill_pointer: SKILL.md`. The machine-readable `INTENT_SIGNALS` / `RESOURCE_MAP` block is byte-identical to the legacy file (sha256 `2ad1469c…`); the prose was rewritten to describe the active root router and every mapped path resolves on disk.
- A Surface Router pointer in `SKILL.md` Section 2 (two-stage routing), the `ROUTER.md` entry in the layout tree, an ALWAYS rule pinning the `RESOURCE_MAP` / `leaf-manifest.json` + `leaf-aliases.json` sync, and the surface-router entry in REFERENCES.

## Changed

- `SKILL.md` (v2.0.0.0 → v2.0.1.0), `README.md` (v2.0.0.0 → v2.0.1.0), `description.json` (v2.0.0.0 → v2.0.1.0): the hub docs now name the root router as stage two.
- `leaf-manifest.json` regenerated through the owner tool; the delta is a pre-existing staleness fix (the generator walks only `references/`/`assets/` leaf roots and the on-disk `sk-create-skill` v4 upgrade leaf is now listed).

## Not Changed

- Routing behavior. `mode-registry.json`, `hub-router.json`, the `null` default mode, bundle rules, and every create packet stay untouched; the stage-one default `shared/references/quick-reference.md` is preserved byte-for-byte.
- The shared sk-create-quality-control backbone, its scripts, and the shared reference base.
- Historical changelog entries and dated benchmark reports that name the legacy path.

## Deleted

- `shared/references/smart-routing.md` after standalone contract validation. The parent doctor then passed; compiled-manifest freshness remains the downstream fleet-rebuild gate.
