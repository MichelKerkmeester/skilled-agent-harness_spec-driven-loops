# v2.3.23.0, Benchmark Companions Get Their Own Document Type

A benchmark run folder holds a README plus companion files such as `failed-runs.md` and `source.md`, whose shape the report contract owns. The validator matched no rule for them, fell back to README rules and failed every one for a missing Overview. It now gives them their own type, and it skips a test fixture folder whose name ends in `-fixture`.

> Spec folder: `specs/sk-doc/070-repo-doc-debt/007-alignment-fixes` (Level 2)

&nbsp;

## What's New at a Glance

- **Companion files validate clean.** `failed-runs.md`, `source.md`, `skill-benchmark-report.md` and `findings-and-recommendations.md` in a run folder under `benchmark/reports/` are typed `benchmark_companion`, which requires no section.
- **The run README keeps README rules.** Only the four companion names in a run folder take the new type, so the same names elsewhere are typed as before.
- **A singular fixture folder is test input.** A folder such as `review-output-fixture/` is skipped like a `fixtures/` folder, while a numbered spec folder ending in `-fixture` is still checked.
- **The flowchart validator test finds its script again.** `scripts/tests/test-flowchart-validator.sh` points at `validate-flowchart.sh` in sk-design-diagram, where the script now lives, and the scripts README no longer lists it as a local file.

&nbsp;

## Upgrade

No migration required. Pass `--type benchmark_companion` to check a companion file outside a run folder.
