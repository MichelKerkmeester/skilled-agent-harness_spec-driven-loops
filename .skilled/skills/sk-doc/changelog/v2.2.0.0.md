`sk-doc` gains the `sk-create-goal/` mode, which writes a spec packet's `goal.md` from the packet's own documents and runs at `/create:goal`. The document validator also stops failing two kinds of file that were never meant to carry its standard sections.

> Spec folder: `specs/sk-doc/060-create-goal-mode` (Level 2)

## Why This Release

The mode shipped with its own changelog, but the hub entry owed for a new mode was never written, so the hub's newest entry still described fourteen modes. This entry closes that gap and records the validator changes that shipped with the mode's last phase.

## What's New at a Glance

- **`sk-create-goal` is the hub's fifteenth mode.** `/create:goal` authors, amends and retrofits a packet's goal, and the mode's own changelog tracks its releases.
- **The hub routes goal authoring to the new mode.** `mode-registry.json`, `hub-router.json`, `graph-metadata.json` and `leaf-manifest.json` carry its entry and signals.
- **The validator leaves `AGENTS.md` alone.** `validate_document.py` skips a file named exactly `AGENTS.md`, the operating contract a coding agent loads at startup, the way it skips templates and fixture trees.
- **Surface packets pass on their own shape.** A skill that opens with WHEN THE HUB BUNDLES THIS is read-only evidence a hub bundles beside a mode, so it now needs only that section, REFERENCE MAP and SURFACE STANDARDS. The three sk-code surface packets and their generated copies now validate clean.

## Upgrade

No migration required. A new surface packet should open with a WHEN THE HUB BUNDLES THIS section, because that heading is how the validator recognizes the shape. To check `AGENTS.md` against the readme standard anyway, run `validate_document.py AGENTS.md --no-exclude`.
