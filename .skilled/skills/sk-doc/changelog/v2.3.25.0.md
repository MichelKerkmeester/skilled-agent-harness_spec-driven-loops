# v2.3.25.0, Frontmatter That Is Not YAML Now Blocks Validation

Every frontmatter check read the block key by key, so a document whose value held an unquoted `: ` passed the validator while every strict YAML reader rejected it. `validate_document.py` now parses the block and reports `frontmatter_invalid_yaml` as blocking, at the line the parser names. **Without PyYAML, the common failures still block.** A Python without PyYAML flags an unquoted `: `, an unquoted `{{` placeholder and an unescaped inner double quote; other parse errors need the strict parser. The hub and its modes carry the values that broke, and each one is now quoted with no word of it changed.

> Spec folder: `specs/sk-code/017-portable-code-modes/015-frontmatter-yaml-validity` (Level 2)

&nbsp;

## What's New at a Glance

- **A block a parser rejects can no longer pass.** The issue is blocking, names the line, and says to quote the value, so a document is judged the way a reader's tooling will judge it.
- **Without PyYAML, the common failures still block.** A Python without PyYAML flags an unquoted `: `, an unquoted `{{` placeholder and an unescaped inner double quote; other parse errors need the strict parser.
- **The quote is the only edit.** The descriptions that held an indicator are wrapped in quotes and read exactly as they did, and the `author: OpenCode` line left the metadata block because nothing read it and it was not true.
