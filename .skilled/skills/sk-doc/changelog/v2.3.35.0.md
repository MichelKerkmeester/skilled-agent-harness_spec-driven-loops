# v2.3.35.0, Playbook Conversation Requests Reach Their Own Leaves

A request to script a multi-turn playbook conversation used to load only the playbook README at the hub. So the author never saw the conversation format. The hub now has its own intent for that request. It routes the request to the conversation reference.

&nbsp;

## What's New at a Glance

- **A playbook-conversation intent.** `ROUTER.md` gains `PLAYBOOK_CONVERSATION`, which loads the conversation-scenario reference and the conversation snippet template. It scores double. That is because "manual testing playbook" also matches "testing playbook". That match would otherwise outscore one conversation phrase. So a request naming both loads both leaf sets.
- **Conversation scenario template.** The `PLAYBOOK_CONVERSATION` intent now loads the conversation snippet template instead of the single-prompt snippet template.
- **New routing phrases.** `hub-router.json` routes "playbook conversation", "multi-turn conversation script", "playbook scenario" and "manual test scenario" to `sk-create-manual-testing-playbook`. A request to write a per-feature manual test scenario used to route to `sk-prompt`.
- **Regenerated routing data.** `graph-metadata.json` carries the new intent signals. The compiled routing manifest is regenerated. So are the advisor graph export and the Hermes mirror.
- **The hub scenarios list 19 intents.** The 14 hub playbook scenarios that name the intent list include `PLAYBOOK_CONVERSATION`.

&nbsp;

## Upgrade

No migration required. The router is read at request time. The regenerated routing data ships with this change.
