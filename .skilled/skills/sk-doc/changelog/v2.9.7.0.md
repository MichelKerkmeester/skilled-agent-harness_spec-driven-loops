# v2.9.7.0, A Merge No Longer Raises a Doc Twice

The pre-commit version bump compared every staged doc with HEAD alone. On a merge from main, main's docs looked edited, so their versions went up a second time. The gate had to be skipped by hand.

> Spec folder: `specs/sk-doc/067-doc-tooling-prose-and-release-amend`

&nbsp;

## What's New at a Glance

- **Docs from the other side keep their version.** A doc staged exactly as a merged-in parent has it is left alone.
- **A resolved conflict is still raised.** A doc the merge itself edited differs from every parent, so it still goes up.
- **Ordinary commits are unchanged.** Outside a merge the bump runs exactly as before.

&nbsp;

## Upgrade

No migration required. Drop any `SPECKIT_SKIP_DOC_VERSION_BUMP=1` you added for merges.
