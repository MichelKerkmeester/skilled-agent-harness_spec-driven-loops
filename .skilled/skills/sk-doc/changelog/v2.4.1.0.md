# v2.4.1.0, Hub Docs Read in Order and Style References Skip the Validator

The hub's `SKILL.md`, `ROUTER.md`, `README.md` and `shared/` docs were read file by file. The reading checked readability, layout and structure. Text moved and split. Every claim was kept or corrected to match the code. One validator rule changed. `validate_document.py` now skips a mode's Style Reference file. No command or template contract changed.

&nbsp;

## What's New at a Glance

- **Style References skip the document validator.** `validate_document.py` now excludes one file named `DESIGN.md`. That file sits directly in an `assets/style-reference/<name>/` folder. It is excluded because its scripts find each section by its literal heading. A sibling README is still validated. So are other files in that folder and style-library bundles. Two new tests pin both sides.
- **Shared references open with their purpose.** The core standards, validation, evergreen packet-id and filesystem naming docs each gained a Purpose and a When to Use. So did the quick reference and shared scripts docs. The quick reference's closing footer moved into its Related Resources.
- **The README reads one surface per line.** What It Does lists the hub's seven surfaces as bullets. When to Use moved up into the overview. The script roles are a list.
- **The router leads with its compiled-routing directive.** `ROUTER.md` gained a short intro. It moved the compiled-routing note to the top of its routing section.
- **Facts match the code.** The core standards list every `--type` value the validator accepts. That includes `skill_router` and `benchmark_companion`. The shared README counts five leaf aliases. Four of them are `shared/` paths. The shared scripts index lists `cite-drift-labels.jsonl`, `cite-drift-gate.mjs` and `git_env.py`.
