# v2.4.2.0, Clarity Reviews Reach the Doc Quality Mode

A clarity review request used to land on `sk-code`. The words describe work on a file. So the hub read them as code work. The phrase now sits in the hub's own routing vocabulary. The request reaches the document quality mode that owns it.

&nbsp;

## What's New at a Glance

- A clarity review is a document review.
  - "Document for clarity" is now an intent signal for the hub.
  - It is also a derived trigger phrase.
  - So a request to review a design document for clarity scores `sk-doc` first.
  - It routes to the single `sk-create-quality-control` mode.
- The router knows the alias class.
  - A `create-quality-control-aliases` class names the request shapes the mode answers.
  - `ROUTER.md` carries the matching `DOC_QUALITY` intent.

&nbsp;

No migration required.
