# v2.4.2.0, Clarity Reviews Reach the Doc Quality Mode

A request to review a document for clarity used to land on `sk-code`. The words describe work on a file, so the hub read them as code work. The phrase now sits in the hub's own routing vocabulary, and the request reaches the document quality mode that owns it.

> Spec folder: `specs/sk-design/021-deprecate-fundamentals` (Level 2)

&nbsp;

## What's New at a Glance

- **A clarity review is a document review.** "Document for clarity" is now an intent signal and a derived trigger phrase for the hub, so a request to review a design document for clarity scores `sk-doc` first and routes to the single `sk-create-quality-control` mode.
- **The router knows the alias class.** A `create-quality-control-aliases` class names the request shapes the mode answers, and `ROUTER.md` carries the matching `DOC_QUALITY` intent.
