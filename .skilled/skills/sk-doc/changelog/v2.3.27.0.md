# v2.3.27.0, the Hub Routing Section in the Canon Shape

The hub `SKILL.md` SMART ROUTING section carried both routing stages, the compiled-routing directive and the whole machine rule in one 58-line block, so a reader met the operator detail before the route. It is now eleven lines of prose: how a prompt reaches a mode, where the second stage lives, and how to call the compiled router. The directive, the surface-router text, the discriminator and the routing rule moved unchanged into a final MACHINE ROUTER section, so nothing was rewritten to make room.

> Spec folder: `specs/sk-doc/072-skill-routing-and-clarity/006-sk-doc-hub` (Level 2)

&nbsp;

## What's New at a Glance

- **The routing prose is short and readable.** Stage one names `hub-router.json` `vocabularyClasses` as the one authored vocabulary and the check that holds the registry aliases, the packet trigger lines and the root intents to it. Stage two names the root `ROUTER.md`, and the compiled router call sits beside both.
- **The machine detail moved, unchanged.** The compiled-routing directive with its bash fence, the surface-router text, the discriminator and the routing rule now close the file as `## 6. MACHINE ROUTER`, the last H2. The directive and the routing rule are byte-for-byte what they were.
- **The `ROUTER.md` rationale is stated once.** The hub now links to the parent-skill reference that explains why the leaf router stays in `ROUTER.md`, rather than restating the reason.
