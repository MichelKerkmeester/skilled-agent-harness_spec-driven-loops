# v2.3.27.0, the Hub Routing Section in the Canon Shape

The hub `SKILL.md` SMART ROUTING section carried both routing stages. It also carried the compiled-routing directive and the whole machine rule. All of it sat in one 58-line block. So a reader met the operator detail before the route.

It is now eleven lines of prose. They say how a prompt reaches a mode. They say where the second stage lives and how to call the compiled router. The directive, the surface-router text, the discriminator and the routing rule moved unchanged into a final MACHINE ROUTER section. So nothing was rewritten to make room.

&nbsp;

## What's New at a Glance

- **The routing prose is short and readable.** Stage one names `hub-router.json` `vocabularyClasses` as the one authored vocabulary. Stage one also names the check that holds the registry aliases, the packet trigger lines and the root intents to it. Stage two names the root `ROUTER.md`. The compiled router call sits beside both.
- **The machine detail moved, unchanged.** The compiled-routing directive with its bash fence now closes the file. So do the surface-router text, the discriminator and the routing rule. They close it as `## 6. MACHINE ROUTER`, the last H2. The directive and the routing rule are byte-for-byte what they were.
- **The `ROUTER.md` rationale is stated once.** The hub now links to the parent-skill reference. That reference explains why the leaf router stays in `ROUTER.md`. The hub does not restate the reason.

&nbsp;

## Upgrade

No migration required. The routing decision and every path it loads are unchanged.
