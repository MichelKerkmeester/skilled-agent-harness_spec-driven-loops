# v2.3.0.0, A Census That Knows a Moved File

The citation drift scan now covers spec docs, and it separates a citation whose file was renamed from one whose file is gone. Most broken citations turn out to point at a file that only moved. The document validator also warns on a `contextType` or `importance_tier` outside the list spec docs use.

> Spec folder: `specs/system-speckit/050-open-knowledge-format-adoption` (Level phase)

## What's New at a Glance

- **The scan reads spec docs.** `cite-drift-scan.mjs --corpus specs` or `all` covers spec packets and research artifacts, grouped by track, with archives left out.
- **A renamed file is not a broken one.** A redirect table built from git's rename history turns about 27,000 citations from broken into moved, each with its new path.
- **A guess is no longer counted as healthy.** A citation that matches only by file name is reported as basename-only instead of in range.
- **Moved citations can be listed.** `--moved` prints each moved citation with its new path, and the default output is unchanged without it.
- **Frontmatter values are checked against the shared list.** `validate_document.py` warns, never blocks, on a value outside sk-create-frontmatter's `assets/frontmatter-values.json`, the list spec-kit's validator reads too.

## Upgrade

No migration required. The default scan still makes no model call and writes no file.
