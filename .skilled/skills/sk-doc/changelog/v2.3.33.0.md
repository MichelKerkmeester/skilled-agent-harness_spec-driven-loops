# v2.3.33.0, The Catalog Lists the Skill Format Command

A capability a catalog does not record is one a reader has to find by accident. The hub's feature catalog now carries the command that reads a skill against the format and converts one, in the same shape as the hub's other entries.

> Spec folder: `specs/sk-doc/075-doctor-sk-skill-command/007-docs-and-changelogs` (Level 2)

&nbsp;

## What's New at a Glance

- **The catalog names the command and both its targets.** `/doctor:sk-skill check` reports one skill or the fleet row by row, and `convert` moves one skill onto the format after a plan and a yes.
- **The rows and the hub report are described as they print.** The entry lists rows `C1` to `C13` in their shipped order and the eleven surfaces `--into-hub <hub>` reports against a parent hub, so a reader knows which question each line answers.
- **The refusal set is stated rather than implied.** A hub declaration, a nested packet tree, a reserved or persona name prefix and a name collision each stop the run, and a long description, a plain skill's intent phrases or a missing `allowed-tools` is a question instead.
- **A plain skill's intent phrases are asked for, not assumed.** The workflow shows the phrases its message suggests, takes at least eight of three or more words with their own yes, and passes each one back as `--approved-phrase`, so the intent signals are the operator's own words rather than the slug defaults.
- **A missing `allowed-tools` list is proposed, and a doubled field is refused.** A plain skill with no approved list, and an older Skilled skill that declares no such field, both print `allowed-tools: approval required; propose [...]` naming `Bash` only when the skill ships a `scripts/` folder, and a field declared twice stops the run with `ALLOWED_TOOLS_DUPLICATE`.
- **A skill in another repository is judged against that repository.** `check` reads the changelog index and the mirrors of the repository that owns the target, and each of that skill's rows names the repository it read.
- **The conversion's temporary files share one scratch root.** The agent output, the preservation snapshot and the staging copy live under `.skilled/skills/.state/doctor-sk-skill/<name>/scratch/`, which the run deletes when a question is declined and again once it has reported.
- **The entry links the adopter guide.** A reader who wants the decision rule behind a hub conversion reaches the guide from the same page.
