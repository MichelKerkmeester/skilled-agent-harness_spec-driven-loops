# v2.3.33.0, The Catalog Lists the Skill Format Command

A catalog that does not record a capability leaves the reader to find it by accident. The hub's feature catalog now carries the command that reads a skill against the format. The same command converts one. The entry has the same shape as the hub's other entries.

> Spec folder: `specs/sk-doc/075-doctor-sk-skill-command/007-docs-and-changelogs` (Level 2)

&nbsp;

## What's New at a Glance

- **The catalog names the command and both its targets.** `/doctor:sk-skill check` reports one skill or the fleet, row by row. `convert` moves one skill onto the format. It does so after a plan and a yes.
- **The rows and the hub report are described as they print.** The entry lists rows `C1` to `C13` in their shipped order. It also lists the eleven surfaces `--into-hub <hub>` reports against a parent hub. So a reader knows which question each line answers.
- **The refusal set is stated rather than implied.** A hub declaration stops the run. So does a nested packet tree, a reserved or persona name prefix and a name collision. A long description is a question instead. So are a plain skill's intent phrases and a missing `allowed-tools`.
- **A plain skill's intent phrases are asked for, not assumed.** The workflow shows the phrases its message suggests. It takes at least eight of three or more words. Each one needs its own yes. It passes each one back as `--approved-phrase`. So the intent signals are the operator's own words, not the slug defaults.
- **A missing `allowed-tools` list is proposed, and a doubled field is refused.** A plain skill with no approved list prints `allowed-tools: approval required; propose [...]`. So does an older Skilled skill that declares no such field. Both name `Bash` only when the skill ships a `scripts/` folder. A field declared twice stops the run with `ALLOWED_TOOLS_DUPLICATE`.
- **A skill in another repository is judged against that repository.** `check` reads the changelog index of the repository that owns the target. It reads that repository's mirrors too. Each of that skill's rows names the repository it read.
- **The conversion's temporary files share one scratch root.** The agent output, the preservation snapshot and the staging copy live under `.skilled/skills/.state/doctor-sk-skill/<name>/scratch/`. The run deletes that root when a question is declined. It deletes it again once it has reported.
- **The entry links the adopter guide.** A reader may want the decision rule behind a hub conversion. That reader reaches the guide from the same page.
