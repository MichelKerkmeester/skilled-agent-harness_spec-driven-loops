# v2.9.2.0, Rewrite guard and section citations resolve the cited file

The doc rewrite guard no longer reports a citation of another file with the same name. The section-reference check now reads citations written as a code span or a link.

&nbsp;

## What's New at a Glance

- The rewrite guard resolves a citation to one file.
  - `doc-rewrite-guard.py` resolves a cited path from the citing doc's folder or the repository root.
  - It matches a bare name only to a sibling.
  - It also matches the one same-named doc in its skill.
  - It never matches `SKILL.md`, `README.md` or `ROUTER.md` across folders.
  - A citation renumbered together with its section is no longer reported.
  - Four new tests cover these cases.
- Section references work through links and code spans.
  - `validate_document.py` resolves a `§` citation whose file is written as ``x.md`` or `[text](x.md)`.
  - A new fixture and test cover it.
- The render ledger is documented.
  - `validation-and-packaging.md` lists all sixteen render checks.
  - The file gains a Render Ledger and Rewrite Guard section.
  - The ledger description and the shared scripts README now say the packager skips exempt docs.
  - The ledger description and the shared scripts README also say the validator reports their findings as labelled warnings.
- Routing sends rewrite-guard and render-ledger prompts to `sk-create-skill`.
  - The hub `ROUTER.md` and `hub-router.json` route rewrite-guard and render-ledger prompts to `sk-create-skill`.
  - So does the `sk-create-skill` router.
- Stale references are fixed.
  - The `sk-create-agent` README drops a stale count marker.
  - The `sk-create-with-human-voice` scripts README cites section 7.

&nbsp;

No migration required.
