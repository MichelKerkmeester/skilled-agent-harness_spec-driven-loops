# v2.9.2.0, Rewrite guard and section citations resolve the cited file

The doc rewrite guard no longer reports a citation of another file with the same name, and the section-reference check now reads citations written as a code span or a link.

> Spec folder: `specs/sk-doc/066-skill-readability-refinement/014-sk-create-skill-refinements/004-alignment-fixes` (Level 2)

&nbsp;

## What's New at a Glance

- **Citations resolve to one file.** `doc-rewrite-guard.py` resolves a cited path from the citing doc's folder or the repository root, matches a bare name only to a sibling or the one same-named doc in its skill, and never matches `SKILL.md`, `README.md` or `ROUTER.md` across folders. A citation renumbered together with its section is no longer reported. Four new tests cover these cases.
- **Section references through links and code spans.** `validate_document.py` resolves a `§` citation whose file is written as ``x.md`` or `[text](x.md)`, with a new fixture and test.
- **Render ledger documented.** `validation-and-packaging.md` lists all sixteen render checks and gains a Render Ledger and Rewrite Guard section. The ledger description and the shared scripts README now say the packager skips exempt docs and the validator reports their findings as labelled warnings.
- **Routing.** The hub `ROUTER.md`, `hub-router.json` and the `sk-create-skill` router route rewrite-guard and render-ledger prompts to `sk-create-skill`.
- **Stale references fixed.** The `sk-create-agent` README drops a stale count marker, and the `sk-create-with-human-voice` scripts README cites section 7.
