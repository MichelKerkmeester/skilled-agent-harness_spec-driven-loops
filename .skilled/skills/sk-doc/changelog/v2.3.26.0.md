# v2.3.26.0, One Vocabulary Source for Every Routing Layer

Routing vocabulary was authored in four places, so a term could reach one layer and stay invisible to the next. `hub-router.json` is now the one authored mode vocabulary, and the root `ROUTER.md` stage-two intents carry every term it routes to each mode, so a prompt stage one sends to a mode always finds that mode's leaves. A new check fails when the layers disagree, and `SKILL.md` now names that file and the check as the source of truth.

> Spec folder: `specs/sk-doc/072-skill-routing-and-clarity/004-single-vocabulary-source` (Level 2)

&nbsp;

## What's New at a Glance

- **Every routed term now reaches the leaves.** The root `ROUTER.md` stage-two intents gained all 89 terms `hub-router.json` routes to each mode, and their multi-word forms went into `graph-metadata.json` intent signals, where the skill advisor reads them.
- **A disagreement between layers now fails a check.** `ci-hub-vocabulary-source.cjs` fails when the registry aliases, the root intents or a packet's `Keyword triggers:` line disagree with `hub-router.json`.
- **Seventeen terms that no mode routed now reach their packets.** The eleven slash-command terms now route, including `/create:agent`, `/create:skill-parent` and `/doc:quality`. The sk-create-diff terms such as `docx diff` no longer defer and `behavior_benchmark` finds its packet. `mcp bake-off` is gone from sk-create-benchmark because its `off` token pulled unrelated prompts such as `kick off another deep-review wave` into sk-doc.
- **`runtime agent directory` and `skill metadata drift gate` are gone from every vocabulary layer.** Their bare `runtime` and `drift` tokens pulled `runtime mirror drift` into sk-doc instead of its doctor bridge, so neither phrase earns a place in the hub's routing vocabulary.
