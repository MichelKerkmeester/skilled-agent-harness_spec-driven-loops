sk-doc's skill-authoring contract is now enforced end-to-end. The packaging validator checks reference and asset frontmatter, versioning, naming and the smart-router pattern, and the create commands and markdown agent seed those from the templates by construction.

> Spec folder: `.opencode/specs/skilled-agent-orchestration/154-sk-design-parent`

## Why This Release

A fast multi-model build of the `sk-design` skill family produced skills that passed the old `package_skill.py` despite kebab-case reference names, references/assets missing the `version` field and SKILL.md SMART ROUTING sections with no smart-router pseudocode. The four `assets/skill/*_template.md` files documented a stronger contract than the validator enforced, making drift the path of least resistance. The gap surfaced during that build, whose phase parent is the spec folder named above.

---

## What's New at a Glance

- **Reference and asset metadata now enters package validation.** The old validator let references and assets without `version` pass.
- **Nested filenames and router structure now receive checks.** Validation reaches domain subfolders and required SMART ROUTING markers.
- **New checks warn rather than hard-fail.** The additions keep the contract advisory for the existing corpus.
- **Create commands seed the documented requirements.** Full-create and reference/asset creation draw from the templates.
- **The markdown agent now has a Skill Authoring Contract.** It covers templates, versions, router pseudocode and the completion gate.
- **Skill-creation guides now reflect the authoring contract.** The workflow and validation guidance align with its version and completion rules.

## Packaging Validation

#### Reference and Asset Metadata

`scripts/package_skill.py` now applies the full frontmatter contract to `references/**/*.md` and `assets/**/*.md`. The required fields are:

- `title`
- `description`
- `trigger_phrases`
- `importance_tier`
- `contextType`
- `version`

`SKILL.md` also requires `version`. Every frontmatter-bearing `.md` in these locations also requires it:

- `feature-catalog`
- `manual-testing-playbook`
- `changelog`
- `README`

Frontmatter-less documents are skipped, not failed.

&nbsp;

#### Nested Checks Catch Gaps

Snake_case filename enforcement now reaches domain subfolders recursively. The old scan stopped at the top level, so `scripts/package_skill.py` never flagged the kebab-case reference `references/color/oklch-workflow.md`. The old check also accepted SKILL.md Section 2 SMART ROUTING without smart-router pseudocode. It now checks `discover_markdown_resources`. It also checks `_guard_in_skill` and `UNKNOWN_FALLBACK`.

&nbsp;

#### Warnings Protect the Corpus

The new checks emit warnings, not hard errors. A blast-radius sweep showed hard-erroring would newly fail 16 of 25 existing skills, so the contract is advisory to avoid breaking the corpus.

## Skill Creation

#### Creation Starts From Templates

Full-create in `commands/create/assets/create_sk_skill_{auto,confirm}.yaml` now seeds SKILL.md Section 2 with pseudocode from `skill_smart_router.md` and stamps the SKILL.md version. Reference and asset creation requires snake_case filenames and the full five-field frontmatter plus `version`, seeded from `skill_reference_template.md` and `skill_asset_template.md`. `package_skill.py --check` is pinned as a blocking completion gate.

&nbsp;

#### Author Instructions Include the Gate

`.opencode/agents/markdown.md` and `.claude/agents/markdown.md` add a Skill Authoring Contract. It says to follow all four skill templates, version every authored `.md` and seed the router pseudocode. It also says to run `package_skill.py --check` before claiming done.

---

## Skill-Creation Guidance

#### Guides Match the Contract

`references/skill_creation/creation-workflow.md` changes `version` from optional to required and replaces the three-part example with a four-part example, matching the validator's mandatory four-part requirement. It directs references and assets to seed from templates and the SMART ROUTING step to seed pseudocode. `references/skill_creation/validation-and-packaging.md` adds a Completion Gate section and corrects the required-fields list.
