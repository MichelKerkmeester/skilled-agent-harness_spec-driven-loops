# v1.8.1.0, Skill Authoring Contract Enforced End-to-End

sk-doc's skill-authoring contract is now enforced end-to-end.

- The packaging validator checks reference and asset frontmatter.
- It checks versioning, naming and the smart-router pattern.

Skill creation now seeds the documented requirements from templates.

- Create commands seed the router pseudocode and SKILL.md version.
- The markdown agent adds a Skill Authoring Contract.
- Skill-creation guides now match the contract.

New warnings protect the existing corpus.

- New checks warn rather than hard-fail.
- No upgrade is needed.

&nbsp;

## Why This Release

A fast multi-model build of the `sk-design` skill family produced skills that passed the old `package_skill.py`.

- They had kebab-case reference names.
- Their references/assets missed the `version` field.
- Their SKILL.md SMART ROUTING sections had no smart-router pseudocode.
- The four `assets/skill/*_template.md` files documented a stronger contract than the validator enforced.
- That made drift the path of least resistance.
- The gap surfaced during that build.
- Its phase parent is the spec folder named above.

## Packaging Validation

The validator now enforces the authoring contract across references and assets.

#### Reference and Asset Metadata <a id="c-reference-and-asset-metadata"></a>

- `scripts/package_skill.py` now applies the full frontmatter contract to `references/**/*.md` and `assets/**/*.md`.
- The required fields are `title`, `description`, `trigger_phrases`, `importance_tier`, `contextType` and `version`.
- `SKILL.md` also requires `version`.
- Every frontmatter-bearing `.md` in these locations also requires it: `feature-catalog`, `manual-testing-playbook`, `changelog`, `README`.
- Frontmatter-less documents are skipped, not failed.

#### Nested Checks Catch Gaps <a id="c-nested-checks-catch-gaps"></a>

- Snake_case filename enforcement now reaches domain subfolders recursively.
- The old scan stopped at the top level.
- So `scripts/package_skill.py` never flagged the kebab-case reference `references/color/oklch-workflow.md`.
- The old check also accepted SKILL.md Section 2 SMART ROUTING without smart-router pseudocode.
- It now checks `discover_markdown_resources`.
- It also checks `_guard_in_skill` and `UNKNOWN_FALLBACK`.

#### Warnings Protect the Corpus <a id="c-warnings-protect-the-corpus"></a>

- The new checks emit warnings, not hard errors.
- The additions keep the contract advisory for the existing corpus.

&nbsp;

## Skill Creation

The create commands and the markdown agent seed those from the templates by construction.

#### Creation Starts From Templates <a id="c-creation-starts-from-templates"></a>

- Full-create in `commands/create/assets/create_sk_skill_{auto,confirm}.yaml` now seeds SKILL.md Section 2 with pseudocode from `skill_smart_router.md`.
- It also stamps the SKILL.md version.
- Reference and asset creation requires snake_case filenames.
- It also requires the full five-field frontmatter plus `version`.
- These are seeded from `skill_reference_template.md` and `skill_asset_template.md`.
- `package_skill.py --check` is pinned as a blocking completion gate.

#### Author Instructions Include the Gate <a id="c-author-instructions-include-the-gate"></a>

- `.opencode/agents/markdown.md` and `.claude/agents/markdown.md` add a Skill Authoring Contract.
- It covers templates, versions, router pseudocode and the completion gate.
- It says to follow all four skill templates.
- It says to version every authored `.md` and seed the router pseudocode.
- It also says to run `package_skill.py --check` before claiming done.

## Skill-Creation Guidance

The workflow and validation guidance align with its version and completion rules.

#### Guides Match the Contract <a id="c-guides-match-the-contract"></a>

- `references/skill_creation/creation-workflow.md` changes `version` from optional to required.
- It replaces the three-part example with a four-part example.
- That matches the validator's mandatory four-part requirement.
- It directs references and assets to seed from templates.
- It also directs the SMART ROUTING step to seed pseudocode.
- `references/skill_creation/validation-and-packaging.md` adds a Completion Gate section.
- It also corrects the required-fields list.

&nbsp;

## How It Was Checked

The validator now checks frontmatter, filenames and router markers.

#### Before and After <a id="c-before-and-after"></a>

| Check | Before | After |
|---|---|---|
| `scripts/package_skill.py` on frontmatter | References and assets without `version` passed | The full contract applies |
| `scripts/package_skill.py` on filenames | The old scan stopped at the top level | Snake_case reaches subfolders recursively |
| `scripts/package_skill.py` on SMART ROUTING | Pseudocode was not required | Router markers are checked |
