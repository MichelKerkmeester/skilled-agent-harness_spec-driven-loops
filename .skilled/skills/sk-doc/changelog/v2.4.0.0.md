# v2.4.0.0, The Validator Reads How a Reference Renders

The document validator now reads the body it used to skip. Ten checks report shapes that render wrong or mislead a reader. Each one lands as a warning. So no existing document starts failing.

&nbsp;

## Why This Release

A reference could pass every check and render wrong. A bold label could read as a paragraph. A divider could read as a setext heading. A URL could read as plain text. That is because no check read a paragraph.

The same blind spot accepted a compound overview heading. It accepted an overview that opened with a rule id. It accepted a related section that was not last. The validator now names those shapes. Strict packaging can promote them where a skill publishes guidance.

&nbsp;

## What's New at a Glance

- Ten render checks.
  - They cover a joined bold label, a setext underline and a bare URL.
  - They also cover a compound overview heading and an overview without orientation.
  - The rest cover a repeated sentence, a repeated label and an H2 number with a letter suffix.
  - The last two are a related section that is not last and an intro that restates its Purpose.
- They read the body, not the fence.
  - Every check skips frontmatter and fenced code.
  - So an example inside a fence is never a finding.
- Each finding is a warning.
  - A document that already renders this way stays valid.
  - Only a strict packaging run turns the finding into an error.
- Four document types opt in.
  - Reference, asset, skill and router documents declare the checks.
  - A router keeps MACHINE ROUTER as its permitted last section.
- A related section is now last.
  - Reference, asset and skill documents declare the pattern.
  - A trailing MACHINE ROUTER is the one exception.
- Both directions have fixtures.
  - A known-bad control raises the checks.
  - Look-alike documents that must stay clean do not.

&nbsp;

## Upgrade

No action is needed for validation. A strict packaging run now reports these findings as errors. That holds unless the skill records them in the render known-debt ledger.
