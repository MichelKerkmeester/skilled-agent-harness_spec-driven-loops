# v2.10.0.0, The Create Skill Command Is Now sk-skill

`/create:skill` is now `/create:sk-skill` on every runtime, with no alias. The old file name caused the bug. A command file named `skill.md` makes Claude Code read its folder as one skill. Every other command in that folder disappears from the listing.

> Spec folder: `specs/system-skill-advisor/routing-and-scoring/008-command-surfacing-build/016-claude-create-reach-and-doctor-default`

&nbsp;

## Why This Release

Claude Code showed 32 of the 44 tracked commands. The create folder held a file named `skill.md` beside twelve other commands. Claude read the folder as one skill named `create`, so those twelve names never appeared.

The cause is an open bug in Claude Code (`anthropics/claude-code#85786`). It holds for any capitalisation of `skill.md` and on any filesystem. The only documented way out is another file name. So no command file may carry that name now.

An alias would keep a `skill.md` file alive, and the bug with it. The old name is retired with no alias, on every runtime.

&nbsp;

## What's New at a Glance

- **The command is now `/create:sk-skill`.** The typed, plain and slash variants all reach it. No command file has the old name. The skill advisor reads a typed `/create:skill` as `/create:sk-skill`. <!-- section: Create Skill Command -->
- **No live file spells the old name.** Command files, catalogs, hub metadata, docs and runtime stubs carry the new name. <!-- section: Create Skill Command -->
- **Mode and asset names stay.** The `sk-create-skill` packet, its folder and the `create-skill-*` asset files keep their names. <!-- section: Create Skill Command -->
- **Claude Code lists all 44 commands.** Its create folder keeps `sk-skill.md` beside the twelve other commands. <!-- section: Claude Code Reach -->
- **A `skill.md` file fails the mirror check now.** The check has no allowlist, and it looks at every capitalisation. <!-- section: Claude Code Reach -->

&nbsp;

## Create Skill Command

#### Type the New Name

`/create:sk-skill` replaces `/create:skill` in the command file, its three assets, the two command catalogs and the sk-doc hub metadata. The command behaves as before. Only the name a reader types changed. The mode id, the packet folder and the `create-skill-*` asset file names keep their old spelling.

#### Breaking: The Old Name Is Gone

**Breaking:** No command file answers to `/create:skill` now. The skill advisor reads a typed `/create:skill` as `/create:sk-skill`. Any script, saved prompt or doc that still names it needs the new spelling. There is no alias to fall back on.

&nbsp;

## Claude Code Reach

#### All 44 Commands Appear

The regenerated Claude tree holds `create/sk-skill.md` and twelve siblings. No file under `.claude/commands` is named `skill.md` in any capitalisation. The runtime mirror check reads `visibility claude 44/44`, up from `32/44`.

#### The Check Has No Exception

The mirror check now fails any command folder that holds a `skill.md` file, whatever its capitalisation. Its old allowlist is gone. That stops a future command from bringing the collapsed folder back.

## Upgrade Notes

- **Scripts and docs that type `/create:skill`:** change them to `/create:sk-skill`. No command file answers to the old name. The skill advisor reads it as `/create:sk-skill`.
- **Saved prompts and snippets:** retype the command, then confirm the create skill answers.
- **Skill authors who copied the old command path:** point references at `.skilled/commands/create/sk-skill.md`.
- **Mode and asset names:** the `sk-create-skill` packet, its mode id and the `create-skill-*` asset files keep their names. Leave them as they are.
