# v2.3.22.0, The Naming Guard Accepts the Synthesis Marker the Deep Loop Writes

The deep-loop runtime writes a file named `synthesis_complete.json` when a research or review lineage closes, so every new lineage added a name the kebab-case guard rejects. Renaming the tracked copies would not have helped, because the next run writes the same name again. The guard now exempts that exact runtime-generated file name, the same way it already exempts lockfiles and tool-mandated names.

> Spec folder: `specs/system-speckit/053-ci-workflow-efficiency/012-alignment-fixes` (Level 2)

&nbsp;

## What's New at a Glance

- **A closed lineage no longer fails the guard.** The marker file is accepted wherever the deep loop writes it.
- **The exemption is the exact name and nothing wider.** A sibling such as `synthesis_pending.json` still fails, and so does a directory with the marker's name.

&nbsp;

## Upgrade

No action is needed. A push that only adds synthesis markers now passes the guard.
