The document validator now holds every changelog entry to the search metadata a spec document carries. An entry that lacks its frontmatter block, one of the five keys or a phrase naming its version fails validation, because the trigger index finds an entry only through that block.

> Spec folder: `specs/sk-doc/061-skilled-release-changelog/002-changelog-findability` (Level 3)

## What's New at a Glance

- **Changelog entries must carry search metadata.** `validate_document.py` blocks an entry that has no frontmatter block. It also blocks an entry whose block lacks `title`, `description`, `trigger_phrases`, `importance_tier` or `contextType`.
- **A version file must name its version.** An entry named `v2.2.1.0.md` needs a trigger phrase that contains `2.2.1.0`, so a reader who asks for that version finds it.
- **Only entry files are held to it.** The check applies to version files and packet-local `changelog-*.md` files. A README in a changelog folder keeps the structural rules alone.
- **The check reads the block where the index reads it.** It skips leading blank lines and HTML comments before the block, as the trigger index does.
- **The template rules list the five keys.** The `changelog` document type in `template-rules.json` names them as required frontmatter fields.
- **The create-changelog mode writes the block.** `sk-create-changelog` gains a Frontmatter Contract, and its own changelog describes the change.

## Upgrade

No migration required. Existing changelog entries received their metadata in the same change, and `/create:changelog` writes the block into each new entry.
