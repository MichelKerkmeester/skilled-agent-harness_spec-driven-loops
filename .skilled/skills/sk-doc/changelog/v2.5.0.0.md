# v2.5.0.0, Render Checks for Overviews, Citations, Intros and H2 Numbering

`shared/scripts/validate_document.py` now catches the layout defects that a file-by-file readability pass found by hand. The packaging gate in `sk-create-skill` reports the new codes as advisory until the fleet is cleared.

> Spec folder: `specs/sk-doc/066-skill-readability-refinement/014-sk-create-skill-refinements/001-render-checks-and-gate` (Level 2)

&nbsp;

## What's New at a Glance

- **OVERVIEW opens with its orientation.** `render_overview_subsections` reports a reference OVERVIEW that does not open with `### Purpose` then `### When to Use`, and an asset OVERVIEW without Purpose then Usage. The rule lives in `shared/assets/template-rules.json` as `overviewSubsections`.
- **Section citations resolve.** `render_section_reference` reports a citation such as `§8 EXAMPLES` or `loop-state-and-gates.md §3` whose number is missing from the cited file, or whose title names a different section. A bare number in prose is checked only against a named file, and a capitalized word counts as a title only when it names a real section.
- **Intros give a reason to open the file.** `render_intro_missing` reports a heading straight after the H1, `render_intro_pointer` an intro sentence such as "This reference explains...", and `render_intro_sentence_restates` an intro sentence that repeats the Purpose or the frontmatter description.
- **H2 numbers run 1, 2, 3.** `render_h2_sequence` reports a gap or a repeat, and a first numbered H2 other than 1.
- **Four check defects fixed.** The related-resources section is a heading that opens with `related` and carries no colon topic, so UNRELATED CHANGES and RELATED SPECS: UPDATE VS CREATE no longer match. Two bold labels split by a hard line break no longer count as joined. An H2 numbered `7.1` is reported as a sub-number, not as unnumbered. A callout, list, table or fenced block under the H1 counts as an intro.
