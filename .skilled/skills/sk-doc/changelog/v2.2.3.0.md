# v2.2.3.0, One Switch for Every sk-doc Validator

Someone who does not care whether their docs match this repository's formats can now turn every sk-doc validator off at once. `SKDOC_SKIP_VALIDATION` works from the environment or from `.skilled/hooks/hook-flags.env`. Before this release the only control relaxed three structure rules inside one validator.

> Part of [Skilled v4.0.0.2](../../../changelog/skilled/v4.0.0.2.md).
>
> Spec folder: `specs/sk-doc/062-doc-validation-off-switches` (Level 2)

## What's New at a Glance

- **Twenty validators share one switch.** With `SKDOC_SKIP_VALIDATION` on, each sk-doc format validator prints one line on stderr naming where the switch was set, then exits 0 without checking.
- **JSON callers still get JSON.** A validator asked for JSON prints `{"skipped": true, "valid": true, ...}`, so a caller that reads `valid` counts the skip as no finding.
- **Writers and self-tests keep running.** The switch turns off checks, never the tools that write. `validate_document.py --fix`, the `--self-test` modes and `frontmatter-version.mjs compute` and `apply` run as before.
- **The report safety check stays on.** The create-diff report validator proves a generated report is safe to open rather than checking a format, so it keeps running.
- **The flags file reads the same everywhere.** The Python helper ends a value at a `#` that follows a space or tab, as the hooks' own readers do, so a line uncommented from the example works as it stands.
- **CI keeps enforcing.** The switch reads local state only, and no workflow sets it.

## Upgrade

No migration required. The switch is off until you set it.
