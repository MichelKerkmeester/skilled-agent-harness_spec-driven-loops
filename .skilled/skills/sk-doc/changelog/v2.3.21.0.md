# v2.3.21.0, Rename Fixture Snapshots Tolerate a Deleted Tracked File

The rename fixture tooling fingerprints a protected checkout before and after a run to prove it wrote nothing there. A tracked file deleted but not yet committed made that fingerprint stop with an error, so an ordinary edit in progress broke the run. Such a file is now recorded as absent. A file that goes missing during a run still changes the fingerprint.

> Spec folder: `specs/sk-doc/071-readme-reference-debt` (Level 2)

&nbsp;

## What's New at a Glance

- **A deleted tracked file no longer stops the snapshot.** It is marked absent, which stays distinct from an empty file.
- **The rename fixture tests no longer depend on your checkout.** They build a small throwaway repository with committed, edited, deleted and untracked files, so another session's uncommitted work cannot decide whether they pass.
