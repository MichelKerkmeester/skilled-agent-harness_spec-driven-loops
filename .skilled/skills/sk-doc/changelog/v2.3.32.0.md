# v2.3.32.0, Routing Rules Move to ROUTER.md

The routing rules for sk-doc moved out of SKILL.md and into a final MACHINE ROUTER section of ROUTER.md. This follows the v2.3.31.0 canon, which moved machine routers into a sibling ROUTER.md so that SKILL.md stays short. The hub routes the same way it did before.

> Spec folder: `specs/sk-doc/072-skill-routing-and-clarity/014-skill-router-files/004-hub-router-merge` (Level 1)

&nbsp;

## What's New at a Glance

- **SKILL.md keeps a single pointer.** SKILL.md no longer carries a MACHINE ROUTER section. Its SMART ROUTING section ends with one line that points to ROUTER.md.
- **Routing is unchanged.** The map from intent to files is byte for byte the same, and every route the hub selects matches the run before the move. The compiled admission check gives the same result, and the compiled manifest was regenerated from the new sources.
- **The hub meets the routing-shape canon.** Its known-debt entry is removed, so the hub no longer needs an exception in that check.
- **The playbook reads its checklist from ROUTER.md.** The fallback checklist now sits in section 5 of ROUTER.md, and the playbook no longer names two settings that sk-doc does not have.
- **The routing docs name ROUTER.md.** The compiled-routing feature catalog entry and the router's `SKILL_ROOT` line both name ROUTER.md.
- **The document validator knows a router.** `validate_document.py` reads a file named `ROUTER.md` as a `skill_router`, which needs an Overview and a final machine router, instead of falling back to README rules.
- **The DESIGN.md format spec and its samples are skipped by name.** `validate_document.py` skips `design-md-format.md` and the four sample `DESIGN.md` files under `sk-design-md-generator`, because their section numbers are the format's own ids. Each is matched by its exact path, so the `writing-notes.md` files beside the samples are still validated.
