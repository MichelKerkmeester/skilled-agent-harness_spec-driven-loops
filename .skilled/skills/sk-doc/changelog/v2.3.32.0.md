# v2.3.32.0, Routing Rules Move to ROUTER.md

The routing rules for sk-doc moved out of SKILL.md. They now sit in a final MACHINE ROUTER section of ROUTER.md. This follows the v2.3.31.0 canon. That canon moved machine routers into a sibling ROUTER.md, so SKILL.md stays short. The hub routes the same way it did before.

&nbsp;

## What's New at a Glance

- SKILL.md keeps a single pointer.
  - SKILL.md no longer carries a MACHINE ROUTER section.
  - Its SMART ROUTING section ends with one line.
  - That line points to ROUTER.md.
- Routing is unchanged.
  - The map from intent to files is byte for byte the same.
  - Every route the hub selects matches the run before the move.
  - The compiled admission check gives the same result.
  - The compiled manifest was regenerated from the new sources.
- The hub meets the routing-shape canon.
  - Its known-debt entry is removed.
  - So the hub no longer needs an exception in that check.
- The playbook reads its checklist from ROUTER.md.
  - The fallback checklist now sits in section 5 of ROUTER.md.
  - The playbook no longer names two settings that sk-doc does not have.
- The routing docs name ROUTER.md.
  - The compiled-routing feature catalog entry names ROUTER.md.
  - So does the router's `SKILL_ROOT` line.
- The document validator knows a router.
  - `validate_document.py` reads a file named `ROUTER.md` as a `skill_router`.
  - That type needs an Overview and a final machine router.
  - It no longer falls back to README rules.
- The DESIGN.md format spec and its samples are skipped by name.
  - `validate_document.py` skips `design-md-format.md`.
  - The validator also skips the four sample `DESIGN.md` files under `sk-design-md-generator`.
  - That is because their section numbers are the format's own ids.
  - Each is matched by its exact path.
  - So the `writing-notes.md` files beside the samples are still validated.
