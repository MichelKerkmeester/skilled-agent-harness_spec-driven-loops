# v2.3.34.0, The Command Contract Lists the Root Instruction File Command

The command contract is the one place that says what a command owns. It also says what a command may write. Every router generator reads it. A command missing from it has a presentation that can drift from its router. Nothing is left to compare the two against.

&nbsp;

## What's New at a Glance

- **The doctor family entry names the new router.** `.skilled/commands/doctor/agents-md.md` joins the family's router list. Its argument hint gains the target and flag grammar. That grammar covers all three targets.
- **The three targets are listed as execution targets.** `check` maps to the read-only workflow. `embed` maps to the plan, digest and yes workflow. `restore` maps to the workflow that puts a recorded run back.
- **The owned assets are named.** The three workflows each get a row. The presentation contract, the shipped manifest and the two engines get one too. So a generator can follow any of them to the file that owns it.
- **Two destructive operations are gated.** `embed apply` and `restore` are declared destructive and gated. They use the same shape the contract already uses. That shape covers the family's other writing routes.

&nbsp;

## Upgrade

No migration required. The contract is read at generation time. So the next router generation picks the entry up.
