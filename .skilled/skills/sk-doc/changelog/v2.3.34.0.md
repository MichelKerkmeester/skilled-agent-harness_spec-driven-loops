# v2.3.34.0, The Command Contract Lists the Root Instruction File Command

The command contract is the one place that says what a command owns and what it may write, and every router generator reads it. A command missing from it is a command whose presentation can drift from its router with nothing to compare them against.

> Spec folder: `specs/agents/021-doctor-agents-md/001-doctor-agents-md/004-command-plumbing` (Level 2)

&nbsp;

## What's New at a Glance

- **The doctor family entry names the new router.** `.skilled/commands/doctor/agents-md.md` joins the family's router list and its argument hint gains the target and flag grammar for all three targets.
- **The three targets are listed as execution targets.** `check` maps to the read-only workflow, `embed` to the plan, digest and yes workflow and `restore` to the workflow that puts a recorded run back.
- **The owned assets are named.** The three workflows, the presentation contract, the shipped manifest and the two engines each get a row, so a generator can follow any of them to the file that owns it.
- **Two destructive operations are gated.** `embed apply` and `restore` are declared destructive and gated, in the same shape the contract already uses for the family's other writing routes.

&nbsp;

## Upgrade

No migration required. The contract is read at generation time, so the next router generation picks the entry up.
