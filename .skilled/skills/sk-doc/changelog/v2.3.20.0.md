# v2.3.20.0, The README Audit Clears a Runtime Folder It Cannot See

The README audit asks git which of a README's missing references are ignored. So a log file or a state file is reported as a runtime artifact, not broken. Git matches a folder-only rule such as `runs/` against a path without its trailing slash. It does that only when the folder exists. A runtime folder is absent from a clean checkout. That is by design. A README that named one stayed broken. So a folder reference is now also asked with its trailing slash.

&nbsp;

## What's New at a Glance

- **A referenced runtime folder stops counting as broken.** The audit now asks git about the folder in the form the ignore rule matches. That form is the folder with its trailing slash.
- **A mistyped folder still fails.** The folder holding the path must exist or be ignored itself. So a broad rule cannot clear a link that points at nothing.

&nbsp;

## Upgrade

No migration required. The audit reads the same references. Only the verdict on a missing runtime folder changes.
