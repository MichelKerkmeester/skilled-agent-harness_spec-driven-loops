# v2.3.20.0, The README Audit Clears a Runtime Folder It Cannot See

The README audit asks git which of a README's missing references are ignored, so a log file or a state file is reported as a runtime artifact rather than as broken. Git matches a folder-only rule such as `runs/` against a path without its trailing slash only when that folder exists, and a runtime folder is absent from a clean checkout by design. A README that named one stayed broken, so a folder reference is now also asked with its trailing slash.

> Spec folder: `specs/sk-doc/070-repo-doc-debt/006-audit-and-validator-accuracy` (Level 2)

&nbsp;

## What's New at a Glance

- **A referenced runtime folder stops counting as broken.** The audit now asks git about the folder in the form the ignore rule matches, which is the folder with its trailing slash.
- **A mistyped folder still fails.** The folder holding the path must exist or be ignored itself, so a broad rule cannot clear a link that points at nothing.

&nbsp;

## Upgrade

No migration required. The audit reads the same references and only the verdict on a missing runtime folder changes.
