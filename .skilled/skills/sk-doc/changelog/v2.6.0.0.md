# v2.6.0.0, One Exempt Loader and a Doc Rewrite Guard

Docs whose text code depends on are now decided in one place, and a rewrite for form can be checked for lost claims before it is committed.

> Spec folder: `specs/sk-doc/066-skill-readability-refinement/014-sk-create-skill-refinements/002-exempt-and-rewrite-guard` (Level 3)

&nbsp;

## What's New at a Glance

- **One exempt loader.** `shared/scripts/render_exempt.py` reads the render ledger's `exempt` map and its new `pinned` list for the validator and the packager. An entry counts only when its doc exists and its consumer file names the doc, with the doc's folder too for a generic name such as `DESIGN.md`. `--check` lists every bad entry and exits 1 when there is one.
- **Exempt docs are labelled, not hidden.** `validate_document.py` now validates an exempt doc, reports each finding as a warning that names the code reading the doc, and refuses `--fix` on it. The two Style Reference `DESIGN.md` files moved from a hard-coded skip into the exempt map. The DESIGN.md format spec stays a skip, since no code reads it.
- **A rewrite guard.** `shared/scripts/doc-rewrite-guard.py --base <ref> [paths]` exits 1 on a changed frontmatter field other than `version`, an edited or missing fenced block, a dropped citation, a removed cited anchor or numbered section, or any edit to an exempt or pinned doc. Lost lines and intro changes print as advisory. It compares a renamed doc with its old text, reads from the repository top wherever it runs, and honors `SKDOC_SKIP_VALIDATION`.
- **A pinned scan.** `render_exempt.py --scan-pinned` lists code that reads a Markdown file by a literal path and every pinned doc no such read reaches. It always exits 0.
