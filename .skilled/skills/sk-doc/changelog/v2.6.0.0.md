# v2.6.0.0, One Exempt Loader and a Doc Rewrite Guard

Docs whose text code depends on are now decided in one place. A rewrite for form can be checked for lost claims before it is committed.

> Spec folder: `specs/sk-doc/066-skill-readability-refinement/014-sk-create-skill-refinements/002-exempt-and-rewrite-guard` (Level 3)

&nbsp;

## What's New at a Glance

- **One exempt loader.** `shared/scripts/render_exempt.py` reads the render ledger's `exempt` map. It also reads its new `pinned` list, for the validator and the packager. An entry counts only when its doc exists. Its consumer file must also name the doc. For a generic name such as `DESIGN.md`, it must name the doc's folder too. `--check` lists every bad entry. It exits 1 when there is one.
- **Exempt docs are labelled, not hidden.** `validate_document.py` now validates an exempt doc. It reports each finding as a warning. That warning names the code reading the doc. It refuses `--fix` on it. The two Style Reference `DESIGN.md` files moved from a hard-coded skip into the exempt map. The DESIGN.md format spec stays a skip. That is because no code reads it.
- **A rewrite guard.** `shared/scripts/doc-rewrite-guard.py --base <ref> [paths]` exits 1 on a changed frontmatter field other than `version`. It also exits 1 on an edited or missing fenced block. So does a dropped citation. So does a removed cited anchor or numbered section. So does any edit to an exempt or pinned doc. Lost lines and intro changes print as advisory. It compares a renamed doc with its old text. It reads from the repository top wherever it runs. It honors `SKDOC_SKIP_VALIDATION`.
- **A pinned scan.** `render_exempt.py --scan-pinned` lists code that reads a Markdown file by a literal path. It also lists every pinned doc no such read reaches. It always exits 0.
