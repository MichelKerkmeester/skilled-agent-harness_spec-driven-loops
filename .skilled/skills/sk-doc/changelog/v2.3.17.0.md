# v2.3.17.0, The README Audit and Changelog Check Stop Flagging What Is Not Broken

The README audit reported a link to a log file, a state file or a build output as broken, although such a path is absent from a clean checkout by design. It now asks git, in one call, whether each unresolved path inside the repository is ignored, and reports an ignored path as resolved with the evidence `gitignored_runtime_path`. The folder holding the path must exist or be ignored as well, so a broad rule cannot hide a mistyped link. A bare path in a package's docs, written the way the package's own tooling sees it, now also resolves from the nearest folder above the README that holds a `package.json`.

Discovery now matches `README.md` and `README.markdown` exactly. The `/create:readme` command file, named `readme.md`, was audited as a README and drew a template failure and a coverage finding; it is no longer read. A folder whose name ends in `-fixture` is now test input, like one named `fixture` or `fixtures`, while a numbered spec folder with that ending stays in scope.

The changelog omission check read the hash name SHA-256 as an internal id. Algorithm names such as SHA-256 and AES-256 no longer warn. Decision, requirement and task ids still warn, and a task id written as a letter T and three digits now warns too.

## What's New at a Glance

- **Runtime paths stop counting as broken.** A link to a git-ignored path inside the repository is reported as resolved, with its evidence.
- **Package docs resolve the way the package reads.** A bare path also resolves from the nearest package root.
- **Only real READMEs are audited.** The lowercase command file and folders named as fixtures are left out, and the durable-directory manifest follows the same rule.
- **Algorithm names are not ids.** SHA-256 and AES-256 no longer draw the internal-id warning.
