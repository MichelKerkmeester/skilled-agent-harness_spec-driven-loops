# v2.1.0.0, Human Voice Mode

`sk-doc` gains a new mode for prose checks.

- `sk-create-with-human-voice/` applies the Human Voice Rules to a draft.
- It also scores prose against them.
- The mode is available at `/create:with-human-voice`.

The mode reads one standard at run time.

- The scope gate runs first.
- It decides which text the standard governs.
- `scripts/hvr_scan.py` reads the standard at runtime.
- It does not carry a copied term list.

The hub records the new mode in its routing files.

- The hub adds the new mode to its routing records.
- `hub-router.json` adds a signal for the new mode.
- Its `SKILL.md` version advances to v2.1.0.0.

Routing outside the new mode keeps its contract.

- The stage-one default and bundle rules keep their contracts.
- Every pre-existing mode keeps its contract.
- Historical changelog entries are unchanged.

## Human Voice Rules

The rules work through a scope gate, a scanner and penalty rules.

#### The Scope Gate Protects Exempt Text <a id="c-the-scope-gate-protects-exempt-text"></a>

- The scope gate runs first.
- It decides which text the standard governs.
- The standard does not govern quotations, error strings, commands, code, generated files, released changelog entries or byte-pinned fixtures.
- A voice edit to any of them is a defect rather than an improvement.
- `references/scope-and-exemptions.md` records the scope decision.
- It also records three classes the standard never covered.
- They are text you are carrying, text something else pins and text that is about the banned words.
- The last class is exempt because the standard lists every blocked term and so scores catastrophically against itself.

#### The Scanner Reads One Standard <a id="c-the-scanner-reads-one-standard"></a>

- On every run, `scripts/hvr_scan.py` parses punctuation bans, hard blocker words, phrase blockers and soft deductions from `hvr-rules.md`.
- The packet holds no copy of any term list.
- The scanner keys on section titles, which survive renumbering.
- A renamed section produces a fail-closed error instead of a clean scan.

#### Penalty Rules Prevent Double Charges <a id="c-penalty-rules-prevent-double-charges"></a>

- Penalty precedence settles overlapping matches.
- One occurrence costs one penalty.
- The longest matching term claims the span.
- A term listed as both an extended blocker and context-dependent is charged once as the blocker.
- A transition costs a point only from its third use onward.

## sk-doc Routing

The hub records the new mode across its routing files.

#### The Hub Documents Its Mode <a id="c-the-hub-documents-its-mode"></a>

- The hub adds the new mode to its routing records.
- `SKILL.md` moves from v2.0.1.0 to v2.1.0.0.
- The same version change applies to `README.md` and `description.json`.
- The hub now declares fourteen modes across thirteen packets.
- Its mode table gains a row for `sk-create-with-human-voice`.
- The routing prose names the human-voice pass among the stage-two leaf intents.

#### Routing Gains Mode Signals <a id="c-routing-gains-mode-signals"></a>

- `hub-router.json` adds a `sk-create-with-human-voice` signal at weight 4.
- It adds the `create-with-human-voice-aliases` vocabulary class and a tie-break slot.
- `mode-registry.json`, `graph-metadata.json` and `leaf-manifest.json` carry the new mode entry.
- They include its intent signals and domains.
- They also carry the regenerated leaf set.

#### Existing Routing Keeps Its Contract <a id="c-existing-routing-keeps-its-contract"></a>

- Routing behavior outside the new mode is unchanged.
- The stage-one default and bundle rules keep their contracts.
- Every pre-existing mode keeps its contract.
- Historical changelog entries are unchanged.
