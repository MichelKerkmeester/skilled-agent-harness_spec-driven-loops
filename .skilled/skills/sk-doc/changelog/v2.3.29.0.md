# v2.3.29.0, Skill Scaffolds Pass Their Own Document Gate

The three skill scaffolds that `create-skill` ships were typed as asset documents by `validate_document.py`. The asset rule requires an Overview section. A `SKILL.md` has no Overview. So the templates that render one could not pass the validator they are written against. The cause is a taxonomy mismatch rather than a missing template section. The scaffolds mirror the `SKILL.md` contract. The renderer never emits an Overview.

A scaffold is now typed as a `skill` document. That is the type its rendered output must satisfy. So it is held to the same required sections a real `SKILL.md` is. The marker is narrow. The file name carries `scaffold` and the path sits under an `assets/` folder. Either signal alone would also catch written documentation. So both are needed. Any other asset document keeps the asset rule, Overview included.

## What's New at a Glance

- The scaffolds validate against the contract they render.
  - `skill-scaffold-template.md`, `hub-skill-scaffold.md` and `packet-skill-scaffold.md` are typed `skill`.
  - So no Overview is required of them.
  - Each reports zero blocking issues.
- A narrow marker decides, not a blanket exemption.
  - A file counts as a scaffold template only when its name carries `scaffold`.
  - The file must also sit under an `assets/` tree.
  - Nothing is skipped.
  - The scaffolds are checked against the full `SKILL.md` section set.
- Written asset documents are unchanged.
  - An asset file that documents something still needs its Overview.
  - The asset rule still blocks one that omits it.
- New test file `scripts/tests/test_scaffold_template_typing.py`.
  - A regression test covers the classification.
  - It pins all three shipped scaffolds.
  - It checks that no document-type fallback warning appears.
  - It proves that an ordinary asset file without an Overview is still blocked.
  - It pins the three shipped scaffolds and their validation result.
  - It also pins the asset rule that keeps applying everywhere else.
- The tests folder README lists it.
  - The tests folder README now lists that test in its structure table.
  - Its fixture row points at the fixture files the folder holds.
  - The structure table names the scaffold typing test beside the validator tests.
  - Its fixture row names the fixture documents the folder actually ships, not a pattern nothing matches.
