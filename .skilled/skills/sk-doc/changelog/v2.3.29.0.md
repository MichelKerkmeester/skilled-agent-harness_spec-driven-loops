# v2.3.29.0, Skill Scaffolds Pass Their Own Document Gate

The three skill scaffolds that `create-skill` ships were classified by `validate_document.py` as asset documents, and the asset rule requires an Overview section. A `SKILL.md` has no Overview, so the templates that render one could not pass the validator they are written against. The cause is a taxonomy mismatch rather than a missing template section: the scaffolds mirror the `SKILL.md` contract, and the renderer never emits an Overview.

A scaffold is now typed as a `skill` document, the type its rendered output must satisfy, so it is held to the same required sections a real `SKILL.md` is. The marker is narrow: the file name carries `scaffold` and the path sits under an `assets/` folder. Either signal alone would also catch written documentation, so both are needed. Any other asset document keeps the asset rule, Overview included.

The classification is covered by a regression test that pins all three shipped scaffolds, checks that no document-type fallback warning appears, and proves that an ordinary asset file without an Overview is still blocked. The tests folder README now lists that test in its structure table, and its fixture row points at the fixture files the folder holds.

> Spec folder: `specs/sk-doc/072-skill-routing-and-clarity/012-alignment-remediation` (Level 2)

## What's New at a Glance

- **The scaffolds validate against the contract they render.** `skill-scaffold-template.md`, `hub-skill-scaffold.md` and `packet-skill-scaffold.md` are typed `skill`, so no Overview is required of them and each reports zero blocking issues.
- **A narrow marker decides, not a blanket exemption.** A file is treated as a scaffold template only when its name carries `scaffold` and it sits under an `assets/` tree. Nothing is skipped: the scaffolds are checked against the full `SKILL.md` section set.
- **Written asset documents are unchanged.** An asset file that documents something still needs its Overview, and the asset rule still blocks one that omits it.
- **New test file `scripts/tests/test_scaffold_template_typing.py`.** It pins the three shipped scaffolds, their validation result, and the asset rule that keeps applying everywhere else.
- **The tests folder README lists it.** The structure table names the scaffold typing test beside the validator tests, and its fixture row names the fixture documents the folder actually ships rather than a pattern nothing matches.
