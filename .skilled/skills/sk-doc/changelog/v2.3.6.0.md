# v2.3.6.0, Typo-Proof Script Options

Many sk-doc scripts read only the options they expected and ignored the rest. A misspelled `--check` or `--format` ran the default mode and reported success. Each script now names the unknown option and exits with its usage error code, 64 for `frontmatter-version.mjs` and 2 for the rest.

> Spec folder: `specs/sk-code/011-sk-code-poinytail-based-refinement/021-open-ends-remediation/001-typo-proof-parsers` (Level 1)

&nbsp;

## What's New at a Glance

- **CI checks refuse unknown options.** The leaf manifest, derived freshness, root metadata and router vocabulary checks under `sk-create-skill`, plus their generators and the playbook and routing scenario validators, exit 2 on an option they do not know.
- **`--format` takes only `text` or `json`.** The freshness and root metadata checks reject any other value instead of falling back to text.
- **Repo rule, goal and doc model scripts follow suit.** `build-rule-cards.cjs`, `check-repo-rules.cjs`, `lint-goal-criteria.cjs` and `validate-doc-model-refs.js` fail on an unknown option, and `lint-goal-criteria.cjs` exits 2 when its input cannot be parsed.

&nbsp;

## Upgrade

Replace any misspelled option with the one the script's usage line lists.
