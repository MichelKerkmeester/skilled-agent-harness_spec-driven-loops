# v1.9.0.0, The Router Contract Accepts Deliberate Patterns

The router parses the same way as in the previous edition. The contract now states which deliberate patterns mode and standalone routers support.

&nbsp;

## What's New at a Glance

- **The machine router now lives in a sibling file.** `ROUTER.md` holds the intent map, resource map, default resource, loading levels and routing pseudocode. These sit under `## 3. MACHINE ROUTER`, after a short overview and intent model. `SKILL.md` keeps short `SMART ROUTING` prose. It ends with one link to `ROUTER.md`.
- **Mode and standalone routers allow three deliberate patterns.** `NO_LOAD_INTENTS` may name intents that load nothing. `ROOT_RESOURCES` may route a markdown file at the router's own root. That file needs no leaf-manifest entry. `INTENT_SIGNALS` may sit beside `INTENT_MODEL`. That holds only when both have exactly the same keys and keywords. Hubs cannot use any of these patterns. Tests cover each allowed case and the failure it must still catch.
- **Comments and prose no longer count.** The check reads these lists and intent maps the way the runtime does. A `#` comment is skipped. An apostrophe inside a comment no longer opens a string. A `NO_LOAD_INTENTS` or `ROOT_RESOURCES` line in prose declares nothing. That holds outside the fenced machine block.
- **The router's move is reflected across the documentation.** The testing playbooks, feature catalog entries and references that pointed to the router inside `SKILL.md` now point to `ROUTER.md`. The overview, skill template and authoring rules now say the machine router lives there.
- **Every skill and mode owns `ROUTER.md`.** The routing-shape known-debt ledger is empty.
- **The packet's own paperwork catches up with the canon it defines.** The lockstep inventory names each hub's `ROUTER.md`. The router template and the schema reference document the three patterns a standalone or packet router may use. The README scaffold and the packet README carry a `ROUTER.md` row. The scripts inventory lists every shipped script.
- **The leaf manifest reads the same inside a git hook.** A hook exports `GIT_DIR`. That made git treat the skill folder as the work tree. So `generate-leaf-manifest.cjs` missed the root `.gitignore` and counted ignored files such as `__pycache__` as leaves. It now drops the hook's git variables before asking git. A test covers the hook environment.
