# v1.9.0.0, The Router Contract Accepts Deliberate Patterns

The router parses the same way as in the previous edition. The contract now states which deliberate patterns mode and standalone routers support.

&nbsp;

## What's New at a Glance

- **The machine router now lives in a sibling file.** `ROUTER.md` contains the intent map, resource map, default resource, loading levels and routing pseudocode under `## 3. MACHINE ROUTER`, after a short overview and intent model. `SKILL.md` keeps short `SMART ROUTING` prose and ends with one link to `ROUTER.md`.
- **Mode and standalone routers allow three deliberate patterns.** `NO_LOAD_INTENTS` may identify intents that load nothing. `ROOT_RESOURCES` may route a markdown file at the router's own root without a leaf-manifest entry. `INTENT_SIGNALS` may sit beside `INTENT_MODEL` only when both have exactly the same keys and keywords. Hubs cannot use any of these patterns. Tests cover each allowed case and the failure it must still catch.
- **Comments and prose no longer count.** The check reads these lists and intent maps the way the runtime does: a `#` comment is skipped, an apostrophe inside a comment no longer opens a string, and a `NO_LOAD_INTENTS` or `ROOT_RESOURCES` line in prose outside the fenced machine block declares nothing.
- **The router's move is reflected across the documentation.** The testing playbooks, feature catalog entries and references that pointed to the router inside `SKILL.md` now point to `ROUTER.md`. The overview, skill template and authoring rules now say that the machine router lives there.
- **Every skill and mode owns `ROUTER.md`.** The routing-shape known-debt ledger is empty.

&nbsp;

No migration is required.
