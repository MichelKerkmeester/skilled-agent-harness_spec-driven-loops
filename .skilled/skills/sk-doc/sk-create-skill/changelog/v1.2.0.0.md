# v1.2.0.0, README Templates Set a Descriptive Default

The refined README templates were correct, but the READMEs they produced read thin: authors who filled every placeholder to its minimum shipped concise reference cards, not the descriptive narrative the repo root README delivers, and this release revises both the standalone skill template and the parent-hub template so the default output is descriptive and narrative in the root README voice, at skill scale, while the Human Voice Rules stay intact. The cause was in the templates. Their defaults steered toward the floor: prose blocks capped at a few sentences, an architecture diagram marked optional, capability sections that were table-only and no room for a value beat or a story.

## What's New at a Glance

- **The standalone template raises OVERVIEW's prose ceiling.** It now asks for a three-to-six-sentence problem narrative that puts the reader in a concrete failing situation before the solution. A worked example modeled on the root README sits in the scaffold as a deletable comment.
- **Capability sections require a prose lead-in.** The prose carries the why and the table carries the what, with one clarifying analogy permitted.
- **The standalone template makes a connection diagram expected for multi-step skills.** HOW IT WORKS previously marked the diagram optional, and an ASCII diagram stub sits in the scaffold.
- **OVERVIEW can include an optional Why It Matters value beat.** Outcome bullets state benefits first and are modeled on the root README's reasons-to-try bullets.
- **The blockquote pitch can have a narrative hook.** A two-to-three-sentence hook may follow it. AT A GLANCE stays the first numbered section so the validator contract holds.
- **Sentence guidance distinguishes clarity from length.** One idea per sentence governs clarity, not length, so a descriptive multi-clause sentence is allowed when it reads naturally aloud. The Human Voice Rules hard blockers stay exactly as they were: no em dash, no semicolon, no Oxford comma and no banned words. The revision clarifies sentence length only.
- **The parent-hub template mirrors the standalone template's narrative changes.** It adds a narrative Why This Hub Exists story, a hub connection diagram stub, a modes-table prose lead-in and the optional value beat.
- **Both template versions advance.** `skill-readme-template.md` moves from `1.9.0.0` to `1.10.0.0`. `parent-skill-readme-template.md` moves from `1.0.0.0` to `1.1.0.0`.
- **The standalone template adds two validation-checklist rows.** They check for a problem narrative and a connection diagram so a thin README fails the author self-check.
- **The section model stays in place.** The numbered ALL-CAPS structure and OVERVIEW as the only required section stay in place. `SKILL.md`, the reference-file template, scripts and the mode registries stay untouched. No shipped README was rewritten in this release.

## Upgrade

No migration required. This is template guidance only.
