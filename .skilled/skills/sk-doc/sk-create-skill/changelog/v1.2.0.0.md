# v1.2.0.0 - README template descriptive-voice revision

**Released:** 2026-08-05

The refined README templates were correct but the READMEs they produced read thin. Authors who filled every placeholder to its minimum shipped concise reference cards, not the descriptive narrative the repo root README delivers. The cause was in the templates. Their defaults steered toward the floor: prose blocks capped at a few sentences, an architecture diagram marked optional, capability sections that were table-only and no room for a value beat or a story. This release revises both the standalone skill template and the parent-hub template so the default output is descriptive and narrative in the root README voice, at skill scale, while the Human Voice Rules stay intact.

## What Changed

- Raised the OVERVIEW prose ceiling and now ask for a short problem narrative, three to six sentences, that puts the reader in a concrete failing situation before the solution. A worked example modeled on the root README sits in the scaffold as a deletable comment.
- Gave the capability section a prose lead-in requirement and licensed one clarifying analogy, so the prose carries the why and the table carries the what.
- Promoted the HOW IT WORKS connection diagram from an optional "only if" to expected for any multi-step skill, with an ASCII diagram stub in the scaffold.
- Added an optional Why It Matters value beat inside OVERVIEW, outcome bullets stated benefit-first, modeled on the root README reasons-to-try bullets.
- Permitted a 2 to 3 sentence narrative hook after the blockquote pitch, with AT A GLANCE kept as the first numbered section so the validator contract holds.
- Clarified that one idea per sentence governs clarity, not length, so a descriptive multi-clause sentence is allowed when it reads naturally aloud.
- Mirrored the same changes into the parent-hub template: narrative Why This Hub Exists story, a hub connection diagram stub, a modes-table prose lead-in and the optional value beat.
- Bumped `skill-readme-template.md` from `1.9.0.0` to `1.10.0.0` and `parent-skill-readme-template.md` from `1.0.0.0` to `1.1.0.0`.
- Added two validation-checklist rows to the standalone template so a thin README fails the author self-check: a problem-narrative row and a connection-diagram row.

## Not Changed

- The Human Voice Rules hard blockers stay exactly as they were. No em dash, no semicolon, no Oxford comma and no banned words. The revision clarifies sentence length only.
- `SKILL.md`, the reference-file template, scripts and the mode registries stay untouched. The change is template guidance only.
- The section model, the numbered ALL-CAPS structure and OVERVIEW as the only required section stay in place. No shipped README was rewritten in this release.
