# v1.5.5.0, The Provision Command and the Order Given

In a fresh clone the skill's root-metadata check now prints one line naming the provision command instead of a raw Node module stack. The parent scaffold now writes several new surfaces in the order given.

> Spec folders: `specs/sk-code/011-sk-code-poinytail-based-refinement/026-external-surface-priority-build/001-scaffold-surface-placement` and `specs/sk-code/011-sk-code-poinytail-based-refinement/029-surface-setup-build/001-clone-path-and-messages` (Level 2)

&nbsp;

## What's New at a Glance

- **A fresh clone names the fix.** When the shared frontmatter parser is not built, `ci-skill-root-metadata.cjs` prints one line with the provision command, `bash .skilled/skills/sk-git/scripts/worktree-naming.sh provision .`, then exits 1. No stack reaches the terminal.
- **Other load errors keep their own message.** Only the missing shared package is relabeled. Every other load error still surfaces as the error it is.
- **Several new surfaces keep the order given.** `/create:skill-parent update --surfaces` writes several new surfaces into `routerPolicy.tieBreak` in the order given. Before, the order of two surfaces added in one run was undefined.

&nbsp;

## Upgrade

No migration required. Existing hubs keep their `tieBreak` order.
