# v1.11.1.0, Code-Bound Docs Exempt from the Render Check

The packet's docs were read file by file for readability, layout and structure, and every claim was kept or corrected to match the code. One change reaches the code: the render check in `scripts/package_skill.py` now reads an `exempt` map. No command or template contract changed.

> Spec folder: `specs/sk-doc/066-skill-readability-refinement/008-sk-doc` (Level 1)

&nbsp;

## What's New at a Glance

- **Code-bound docs are exempt from the render check.** `scripts/render-known-debt.json` gained an `exempt` map that lists each doc whose exact text code depends on, with the code file that reads or generates it and a reason. `package_skill.py` skips those docs during the render check.
- **A stale exemption exempts nothing.** An entry is honored only when it carries exactly a `consumer` and a non-blank `reason` and the consumer file exists, so a missing consumer leaves the doc checked. Two new regression tests cover both cases.
- **The debt map is empty.** The `debt` map in `render-known-debt.json` no longer lists any skill, and six deep-loop assets that scripts write, generate or send whole are listed under `exempt` instead.
- **Skill trees show what init writes.** The init example and the skill-shape trees now list `ROUTER.md`, `README.md` and the files `init_skill.py` writes, including `graph-metadata.json`, the leaf manifest files and the playbook and benchmark indexes. The docs also say `--path` is required.
- **Commands use repository-root paths.** The README checks table, the validation and packaging reference and the hub README template now give full paths from the repository root, and the README says to run them from there.
- **Counts and lists match the tree.** The compiled router now serves seven hubs, `hub-router.json` has five top-level fields, `sk-design` has four workflow modes, and the leaf-route replay expects `pass 26`. Packed template and reference paragraphs became bullet lists.
