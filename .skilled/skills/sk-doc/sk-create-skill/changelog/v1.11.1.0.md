# v1.11.1.0, Code-Bound Docs Exempt from the Render Check

The packet's docs were read file by file. The read covered readability, layout and structure. Every claim was kept or corrected to match the code. One change reaches the code. The render check in `scripts/package_skill.py` now reads an `exempt` map. No command or template contract changed.

&nbsp;

## What's New at a Glance

- **Code-bound docs are exempt from the render check.** `scripts/render-known-debt.json` gained an `exempt` map. It lists each doc whose exact text code depends on. Each entry gives the code file that reads or generates it and a reason. `package_skill.py` skips those docs during the render check.
- **A stale exemption exempts nothing.** An entry is honored only in one case. It carries exactly a `consumer` and a non-blank `reason`. The consumer file also exists. So a missing consumer leaves the doc checked. Two new regression tests cover both cases.
- **The debt map is empty.** The `debt` map in `render-known-debt.json` no longer lists any skill. Six deep-loop assets are listed under `exempt` instead. Scripts write, generate or send those assets whole.
- **Skill trees show what init writes.** The init example and the skill-shape trees now list `ROUTER.md` and `README.md`. They also list the files `init_skill.py` writes. That includes `graph-metadata.json`, the leaf manifest files and the playbook and benchmark indexes. The docs also say `--path` is required.
- **Commands use repository-root paths.** The README checks table now gives full paths from the repository root. So do the validation and packaging reference and the hub README template. The README says to run them from there.
- **Counts and lists match the tree.** The compiled router now serves seven hubs. `hub-router.json` has five top-level fields. `sk-design` has four workflow modes. The leaf-route replay expects `pass 26`. Packed template and reference paragraphs became bullet lists.
