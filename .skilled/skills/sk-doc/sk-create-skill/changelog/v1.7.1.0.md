# v1.7.1.0, The Routing Prose Is Short and the Router Moved to the End

A reader now meets the skill-authoring instructions sooner. `SMART ROUTING` is six lines of plain prose that say what selects this packet, what it loads first and where the router is, and the mode tree, the route selection, the resource domains and the smart-router pseudocode sit unchanged in a final `## 7. MACHINE ROUTER` section. Nothing about what routes where changed.

> Spec folder: `specs/sk-doc/072-skill-routing-and-clarity/006-sk-doc-hub` (Level 2)

&nbsp;

## What's New at a Glance

- **The routing section is prose.** Six lines name the two workflow modes, the resources that load first and the section that holds the router, so a reader reaches the creation workflow without scrolling past a tree and a table.
- **The router is at the end.** The mode tree, the route selection, the resource domains table and the pseudocode moved byte for byte into `## 7. MACHINE ROUTER`, the last H2 of the file, under the headings they already carried.
- **One statement of why a hub's router stays in `ROUTER.md`.** `references/parent-skill/parent-skills-nested-packets.md`, now version 1.2.7.0, carries a "Why the leaf router stays in `ROUTER.md`" subsection in its registry and router contract. It is the one full explanation of why a hub's machine block stays out of the hub `SKILL.md`, and a hub `SKILL.md` links to it rather than restating it.

&nbsp;

## Upgrade

No action is needed. The packet routes and loads exactly the resources it did before; only the section that holds the routing detail changed.
