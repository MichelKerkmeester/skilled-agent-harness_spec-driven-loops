# v1.8.0.0, Every Skill Routes From Its Own ROUTER.md

Every skill and mode packet now keeps its machine router in a sibling `ROUTER.md`. The router sits under a final `## MACHINE ROUTER` heading. `SKILL.md` keeps its short routing prose and a link to that file. The router a reader parses sits in a file of its own.

&nbsp;

## What's New at a Glance

- Every skill and mode packet owns a ROUTER.md.
  - The machine router moves out of `SKILL.md` into a sibling file.
  - `SKILL.md` links to it with a relative path.
  - That path must resolve.
- A mode packet now needs its own ROUTER.md.
  - Before this release, a mode packet with a `ROUTER.md` failed the check.
  - The rule reverses.
  - A missing file is now the failure.
- The check reports each gap separately.
  - A `MACHINE ROUTER` section left in `SKILL.md` fails it.
  - So does a missing sibling `ROUTER.md`.
  - So does a `SKILL.md` with no working link to that file.
- The link rule reads the same in both checks.
  - `package_skill.py --strict` and doctor check 12b count the pointer only in one case.
  - It must be a one-line markdown link to exactly `ROUTER.md`.
  - A leading `./` and any `#anchor` are stripped first.
  - Several forms do not count.
  - These are a title, an image, angle brackets, trailing text and a split label.
  - A link only in the frontmatter does not count.
  - A link to a nested `child/ROUTER.md` does not count.
- A sibling router must be a real file inside the skill.
  - A directory fails the router-file check.
  - So does a dangling symlink.
  - So does a symlink that leaves the folder.
  - A known-debt entry excuses only a missing file.
  - Recorded debt for a leftover machine router section excuses one case only.
  - That case is a machine router section at the end of `SKILL.md`.
  - A machine block in the routing prose always fails.
- Unmoved skills stay on a known-debt ledger.
  - `routing-shape-known-debt.json` records each skill that has not moved yet.
  - So the repository keeps passing until that skill migrates.
- The root router check covers standalone skills and mode packets.
  - Before this release, it checked parent hubs only.
- Compiled routing reads ROUTER.md when a skill has one.
  - A skill without one keeps reading `SKILL.md`.
  - So existing routes stay the same.
- New skills and packets start with a router file.
  - The scaffold writes `ROUTER.md`.
  - A fresh mode packet points its router at a starter `references/workflow.md` leaf.
- A standalone skill can name its package index.
  - It may route to `feature-catalog/feature-catalog.md` without a manifest entry.
  - It may also route to `manual-testing-playbook/manual-testing-playbook.md`.
  - Hubs and packets get no such exemption.

&nbsp;

## Upgrade

A skill outside this repository now fails `--strict` if its router sits inside `SKILL.md`. Move the router in three steps:

1. Create `ROUTER.md` beside `SKILL.md`. Put it in the skill folder or the mode packet folder. Place the router block under a final `## MACHINE ROUTER` heading. The `skill-router-template.md` asset in this packet shows the layout.
2. In `SKILL.md`, add a relative link to `./ROUTER.md` in the SMART ROUTING section. Then remove the old `## MACHINE ROUTER` section.
3. Run `package_skill.py <skill-folder> --check --strict` from this packet's `scripts/` folder. Expect `Result: PASS`. Then remove the skill's entry from `routing-shape-known-debt.json`. Do that if the ledger lists it. A skill outside this repository normally has no entry there.
