# v1.8.0.0, Every Skill Routes From Its Own ROUTER.md

Every skill and mode packet now keeps its machine router in a sibling `ROUTER.md`, under a final `## MACHINE ROUTER` heading. `SKILL.md` keeps its short routing prose and a link to that file. The router a reader parses sits in a file of its own.

&nbsp;

## What's New at a Glance

- **Every skill and mode packet owns a ROUTER.md.** The machine router moves out of `SKILL.md` into a sibling file. `SKILL.md` links to it with a relative path that must resolve.
- **A mode packet now needs its own ROUTER.md.** Before this release, a mode packet that carried a `ROUTER.md` failed the check. The rule reverses. A missing file is now the failure.
- **The check reports each gap separately.** A `MACHINE ROUTER` section left in `SKILL.md` fails it. So does a missing sibling `ROUTER.md`. So does a `SKILL.md` with no working link to that file.
- **The link rule reads the same in both checks.** `package_skill.py --strict` and doctor check 12b count the pointer only when it is a one-line markdown link to exactly `ROUTER.md`, after a leading `./` and any `#anchor` are stripped. A title, an image, angle brackets, trailing text, a split label, a link only in the frontmatter or a link to a nested `child/ROUTER.md` does not count.
- **A sibling router must be a real file inside the skill.** A directory, a dangling symlink or a symlink that leaves the folder fails the router-file check, and a known-debt entry excuses only a missing file. Recorded debt for a leftover machine router section excuses only a machine router section at the end of `SKILL.md`, and a machine block in the routing prose always fails.
- **Unmoved skills stay on a known-debt ledger.** `routing-shape-known-debt.json` records each skill that has not moved yet, so the repository keeps passing until that skill migrates.
- **The root router check covers standalone skills and mode packets.** Before this release, it checked parent hubs only.
- **Compiled routing reads ROUTER.md when a skill has one.** A skill without one keeps reading `SKILL.md`, so existing routes stay the same.
- **New skills and packets start with a router file.** The scaffold writes `ROUTER.md`. A fresh mode packet points its router at a starter `references/workflow.md` leaf.
- **A standalone skill can name its package index.** It may route to `feature-catalog/feature-catalog.md` or `manual-testing-playbook/manual-testing-playbook.md` without a manifest entry. Hubs and packets get no such exemption.

&nbsp;

## Upgrade

A skill outside this repository that keeps its router inside `SKILL.md` now fails `--strict`. Move the router in three steps:

1. Create `ROUTER.md` beside `SKILL.md`, in the skill folder or the mode packet folder. Place the router block under a final `## MACHINE ROUTER` heading. The `skill-router-template.md` asset in this packet shows the layout.
2. In `SKILL.md`, add a relative link to `./ROUTER.md` in the SMART ROUTING section. Then remove the old `## MACHINE ROUTER` section.
3. Run `package_skill.py <skill-folder> --check --strict` from this packet's `scripts/` folder. Expect `Result: PASS`. Then remove the skill's entry from `routing-shape-known-debt.json` if the ledger lists it. A skill outside this repository normally has no entry there.
