# v1.15.0.0, Every Render Check Enforced

A render finding now fails `--strict` packaging wherever the packager scans, because no code or scope is held advisory any more.

> Spec folder: `specs/sk-doc/066-skill-readability-refinement/014-sk-create-skill-refinements/003-templates-and-fleet` (Level 3)

&nbsp;

## What's New at a Glance

- **No staged render checks.** `package_skill.py` ships `RENDER_STAGED_CODES` and `RENDER_STAGED_SCOPES` empty, and the frozen ratchet snapshot records both as empty, so a stage cannot come back without a reviewed snapshot change.
- **README.md is scanned.** `RENDER_SCAN_SCOPES` adds `README.md`, so a skill's README faces the same render checks as its SKILL.md and ROUTER.md.
- **Generated hub routers open with OVERVIEW.** `init_skill.py` writes the stage-one hub `ROUTER.md` with `## 1. OVERVIEW` first, then the machine-readable router, promotion and machine router sections as 2 to 4.
- **Tests stage their own codes.** The staging and ratchet tests set the staged sets they exercise, since the shipped sets are empty.

&nbsp;

## Upgrade

A skill that still carries a render finding fails `package_skill.py --check --strict` until the finding is fixed or recorded in `render-known-debt.json`. `RENDER_STAGED_OFF=1` no longer changes the result, since nothing is staged.
