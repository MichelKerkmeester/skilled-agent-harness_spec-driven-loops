# v1.5.7.0, An Outside Surface Can Declare the Checklists It Applies

The quality runner loads the checklists a surface declares. An outside skill had no way to declare any. So its files ran with no checklist of its own. An optional block now says which files each checklist covers. The gate refuses a block the runner could not resolve.

&nbsp;

## What's New at a Glance

- A skill declares its checklists.
  - An outside `graph-metadata.json` may carry a `quality` block.
  - Each row names a checklist file and at least one selector.
  - The selector is one of `paths`, `extensions` or `contentMarkers`.
- A malformed block fails the gate.
  - `ci-skill-root-metadata.cjs` reports `GRAPH_METADATA_INVALID_QUALITY` for a command key or an empty row list.
  - `ci-skill-root-metadata.cjs` reports the same code for a row with no selector.
  - `ci-skill-root-metadata.cjs` also reports it for an extension without its dot.
  - `ci-skill-root-metadata.cjs` reports it for a file that is not a relative `.md` path.
- The contract rows say both.
  - `references/shared/skill-root-metadata-contract.md` gains the optional key row.
  - `references/shared/skill-root-metadata-contract.md` also gains the violation code row.
  - The gate tests cover a valid block and a broken one.

&nbsp;

## Upgrade

No migration required. The block is optional. A skill root that carries none passes the gate exactly as it did before.
