# v1.5.7.0, An Outside Surface Can Declare the Checklists It Applies

The quality runner loads the checklists a surface declares, and an outside skill had no way to declare any, so its files ran with no checklist of its own. An optional block now says which files each checklist covers, and the gate refuses a block the runner could not resolve.

&nbsp;

## What's New at a Glance

- **A skill declares its checklists.** An outside `graph-metadata.json` may carry a `quality` block whose rows name a checklist file and at least one selector, one of `paths`, `extensions` or `contentMarkers`.
- **A malformed block fails the gate.** `ci-skill-root-metadata.cjs` reports `GRAPH_METADATA_INVALID_QUALITY` for a command key, an empty row list, a row with no selector, an extension without its dot or a file that is not a relative `.md` path.
- **The contract rows say both.** `references/shared/skill-root-metadata-contract.md` gains the optional key row and the violation code row, and the gate tests cover a valid block and a broken one.

&nbsp;

## Upgrade

No migration required. The block is optional, and a skill root that carries none passes the gate exactly as it did before.
