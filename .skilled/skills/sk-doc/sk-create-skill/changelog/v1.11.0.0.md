# v1.11.0.0, The Templates Show a Reference Body

The templates that teach a new skill now show the shape of a reference body. They show more than its frontmatter. Strict packaging also reads the rendered shape of every reference and asset. A ledger keeps an existing skill from failing on debt it carried before this release.

> Spec folder: `specs/sk-code/018-frontend-upstream-proposals/010-reference-readability-research` (Level 2)

&nbsp;

## Why This Release

Every render defect this release targets upstream began in a template. The skill template left its example frontmatter unfenced. The asset template joined three bold labels. The reference template never showed a body. So an author copied a shape the validator could not see. No completion gate read it either. A gate that inspects only frontmatter cannot catch what a template teaches.

&nbsp;

## What's New at a Glance

- **The reference template shows a body.** It gains a skeleton. The skeleton starts with the intro hook and `## 1. OVERVIEW`. Purpose and When to Use come first. Then come integer content sections and bullet rule fields. It shows link form and a blank line above every divider. A related section comes last.
- **A duplicated template section is gone.** `### When to Create References` no longer repeats guidance the rest of the file gives.
- **The GOOD examples differ from their Purpose.** The reference and asset examples pair a hook with a Purpose. The hook names the job. The Purpose names the outcome.
- **The templates stop teaching the defects.** The example frontmatter is fenced. Three asset example blocks use one bullet per label. So does the skill dependency list.
- **Numbering and routing guidance tighten.** H2 numbers are integers only. The router overview prompt names signal and resource families. It leaves exact keywords to INTENT MODEL.
- **A surface packet has a section order.** The hub template lists WHEN THE HUB BUNDLES THIS, REFERENCE MAP, SMART ROUTING and SURFACE STANDARDS before packet sections.
- **Related resources come last in the scaffold.** The hub scaffold and the metadata contract move related resources. They sit behind the sections a reader needs first.
- **Guidance names the render checks.** The creation workflow adds a reference and asset content review. It sits beside the completion gate. The packaging reference names the checks as the deterministic half of content quality.
- **Strict packaging reads rendered shape.** Render findings on `references/` and `assets/` become errors under `--strict`. The errors apply past a ledger. The ledger tolerates only what a skill was already listed with. It never tolerates a new finding.

&nbsp;

## Upgrade

No action is needed for a new skill. An existing skill that carries render findings passes. It passes until its listed debt grows. Its ledger entry comes out when the documents render clean.
