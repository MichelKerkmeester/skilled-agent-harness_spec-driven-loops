# v1.11.0.0, The Templates Show a Reference Body

The templates that teach a new skill now show the shape a reference body takes, not only its frontmatter. Strict packaging also reads the rendered shape of every reference and asset, and a ledger keeps an existing skill from failing on debt it carried before this release.

> Spec folder: `specs/sk-code/018-frontend-upstream-proposals/010-reference-readability-research` (Level 2)

&nbsp;

## Why This Release

Every render defect this release targets upstream began in a template. The skill template left its example frontmatter unfenced, the asset template joined three bold labels, and the reference template never showed a body, so an author copied a shape the validator could not see and no completion gate read. A gate that inspects only frontmatter cannot catch what a template teaches.

&nbsp;

## What's New at a Glance

- **The reference template shows a body.** It gains a skeleton with the intro hook, `## 1. OVERVIEW`, Purpose and When to Use first, integer content sections, bullet rule fields, link form, a blank line above every divider and a related section last.
- **A duplicated template section is gone.** `### When to Create References` no longer repeats guidance the rest of the file gives.
- **The GOOD examples differ from their Purpose.** The reference and asset examples pair a hook that names the job with a Purpose that names the outcome.
- **The templates stop teaching the defects.** The example frontmatter is fenced, and three asset example blocks and the skill dependency list use one bullet per label.
- **Numbering and routing guidance tighten.** H2 numbers are integers only, and the router overview prompt names signal and resource families while leaving exact keywords to INTENT MODEL.
- **A surface packet has a section order.** The hub template lists WHEN THE HUB BUNDLES THIS, REFERENCE MAP, SMART ROUTING and SURFACE STANDARDS before packet sections.
- **Related resources come last in the scaffold.** The hub scaffold and the metadata contract move related resources behind the sections a reader needs first.
- **Guidance names the render checks.** The creation workflow adds a reference and asset content review beside the completion gate, and the packaging reference names the checks as the deterministic half of content quality.
- **Strict packaging reads rendered shape.** Render findings on `references/` and `assets/` become errors under `--strict`, past a ledger that tolerates only what a skill was already listed with and never a new finding.

&nbsp;

## Upgrade

No action is needed for a new skill. An existing skill that carries render findings passes until its listed debt grows, and its ledger entry comes out when the documents render clean.
