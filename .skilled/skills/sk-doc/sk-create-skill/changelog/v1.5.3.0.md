# v1.5.3.0, The RULES check reads the RULES section

`package_skill.py` now reads the real `## N. RULES` section instead of the first heading that contains the word.

> Spec folder: `specs/sk-code/011-sk-code-poinytail-based-refinement/016-residual-closeout/001-package-strict` (Level 1)

&nbsp;

## What's New at a Glance

- **The RULES check is anchored.** The pattern starts at a line start and needs the word RULES right after the section number, so a `### Rules` subsection or a heading such as `## 6. SCENARIO DESIGN RULES` is no longer read as the section. sk-create-manual-testing-playbook passes the strict check as a result, and no other skill's result changes.
- **A regression test covers it.** `test_package_skill_regressions.py` fails on the old pattern and passes on the new one.
