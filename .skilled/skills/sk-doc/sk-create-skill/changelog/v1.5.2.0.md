# v1.5.2.0, Guidance That Matches What the Tools Read

Authors following sk-create-skill were sent to the wrong file for routing words and told to bump one version field when a hub carries five. The guidance now matches the tools, and a stale leaf manifest says what moved.

> Spec folder: `specs/sk-code/011-sk-code-poinytail-based-refinement/014-skill-authoring-ux-research/006-create-skill-guidance` (Level 1)

&nbsp;

## What's New at a Glance

- **Routing words go where the scorer looks.** The creation checklist names SKILL.md `keywords`, graph-metadata.json `domains` and `intent_signals`, and the intent-signal generator for a hub. It says plainly that no scorer reads `description.json`.
- **One command bumps a release.** The maintenance reference sends a version bump through `/create:changelog`, which sets every carrier, and names the doctor that confirms a hub.
- **A stale leaf manifest names the change.** `generate-leaf-manifest.cjs --check` lists each added and removed leaf and prints the full `--write` command.
- **The regenerator's header matches its exits.** `regenerate-skill-derived.cjs` documents its real arguments and exit codes.
