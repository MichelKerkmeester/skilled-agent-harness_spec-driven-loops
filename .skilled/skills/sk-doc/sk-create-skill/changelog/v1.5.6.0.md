# v1.5.6.0, Private Skill Roots Stay Local

The root-metadata gate now checks an optional `surface_detection` block in `graph-metadata.json` field by field. A block that the surface detectors would skip without a word now fails the gate. The message names the broken rule. The gate and the derived-file tools also leave a private `local-*` skill root alone, so a skill that belongs to one checkout never reaches tracked output.

&nbsp;

## What's New at a Glance

- **A broken surface block fails the gate.** `ci-skill-root-metadata.cjs` reports one `GRAPH_METADATA_INVALID_SURFACE_DETECTION` finding per broken rule, such as a missing label, a role other than `specific` or a blank marker.
- **Private skill roots are never scanned.** The root-metadata gate, the router intent-signal writer and the derived-block regenerator all skip a `local-*` directory. The derived-freshness gate reuses that same listing.
- **The regenerator refuses a private root.** `regenerate-skill-derived.cjs --root` stops on a `local-*` path. It judges both the typed path and its real target, so a link with a neutral name cannot reach one.
- **A new test guards the skip.** `skill-root-reader-inventory.test.cjs` fails when a tracked script lists the skills root without a `local-*` rule.
- **A hub at a repository root passes the checks.** A hub can declare a `repo-root-hub` extension in `mode-registry.json`, which lists the repository's own top-level paths. The package checks skip those paths, and a repo-root hub's folder name is matched in kebab case.
- **The upgrade guide names the live surfaces.** Its sk-code example drops the removed Webflow surface and names `sk-code-skilled` and `sk-code-ci`.

&nbsp;

## Upgrade

Check any `surface_detection` block in `graph-metadata.json` before the next gate run. The gate now fails a block that breaks the rules in `references/shared/skill-root-metadata-contract.md`. No other migration is required.
