# v1.7.3.0, A Standalone Skill Can Limit Its Leaf Root

A standalone skill walked every configured leaf root in full, so each file under it became a leaf, down to runtime helpers no router ever loads. A skill without a mode registry had no way to say that only its Markdown is routable.

`leaf-scopes.json` already narrowed a hub's mode to its own packet-relative subtrees. The standalone path now reads the same file through the same helpers, so one option serves both kinds of skill and a scope is spelled the same way in either.

> Spec folder: `specs/sk-doc/072-skill-routing-and-clarity/009-standalone-skills` (Level 2)

&nbsp;

## What's New at a Glance

- **A standalone leaf root can be scoped.** A skill lists the subtrees or single files it wants for its workflow mode, and the generator walks only those.
- **A bad scope stops the build.** A scope outside a declared leaf root raises `OUT_OF_ROOT_LEAF_SCOPE` and a scope naming a mode the config does not declare raises `ORPHAN_LEAF_SCOPE_MODE`, so a typo cannot quietly widen a manifest.
- **The same rules as a hub.** The standalone path calls the shared scope reader, scope normaliser and file walker, and it re-applies the index-file exclusion to the scoped candidates, so both kinds of skill answer to one implementation.
- **`system-skill-advisor` is Markdown only under `hooks/`.** Nine runtime `.ts`, `.py` and `.json` files left its leaf manifest and its alias file, and no route changed.
- **The CLI takes either argument order.** `<dir> --check` now works as well as `--check <dir>`.

&nbsp;

## Upgrade

No action is needed. A skill with no `leaf-scopes.json`, or with an empty scope list, walks its full leaf roots exactly as before.
