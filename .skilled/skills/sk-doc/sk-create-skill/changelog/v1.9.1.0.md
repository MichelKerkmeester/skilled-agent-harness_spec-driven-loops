# v1.9.1.0, The Skill Format Command Joins the Packet's Own Docs

A scaffold that points at a file the reader then deletes is a trap. The leaf manifest config template now names the router in the sibling `ROUTER.md`. It does not name it in `SKILL.md`. The router reach check can score one skill. The packet documents the command that brings an existing skill onto this format.

> Spec folder: `specs/sk-doc/075-doctor-sk-skill-command/007-docs-and-changelogs` (Level 2)

&nbsp;

## What's New at a Glance

- **The leaf manifest template says where the router lives.** Its note now reads that only the docs the router in the sibling `ROUTER.md` actually routes into belong in `leafRoots`. So a scaffolded leaf entry follows a file that exists.
- **The router reach check takes one skill.** `ci-router-vocabulary-reach.cjs --skill <name>` scores that root instead of walking every hub. It refuses `--hub` beside `--skill`. That is because the two probe different sets.
- **The packet says how a skill already in the world gets here.** Section 6 and the adopter guide name `/doctor:sk-skill`. They list the read-only check. They also list the in-place conversion of an older Skilled skill. The staged conversion of a plain one is listed as well.
- **The gaps a conversion closes are listed where an adopter reads them.** The guide no longer claims a single skill has no way off the old shape. It keeps the hub path at `/create:skill-parent` for a skill that really holds two jobs.
- **The playbook follows the command end to end.** Four scenarios cover the read-only check with its hub report. They also cover the conversion of an existing skill. They cover the plain-skill conversion and the hub refusal. So an operator can run each path instead of inferring it.
- **The follow-ups are stated as the command asks them. So is the scratch root.** A plain skill's phrases are approved before any plan prints. A skill with no `allowed-tools` field is offered the list its plan proposes. A field declared twice is refused. The agent output, snapshot and staging copy share one scratch root under `.skilled/skills/.state/doctor-sk-skill/<name>/scratch/`.

&nbsp;

## Upgrade

No migration required. A skill scaffolded before this release keeps its leaf manifest config. The router it names still resolves.
