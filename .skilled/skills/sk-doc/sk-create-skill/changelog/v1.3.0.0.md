# v1.3.0.0, README Template Value-First and Emoji-Register Alignment

The README templates now teach an opening that matches the root README's value-first SUMMARY and state the emoji policy explicitly. This aligns their guidance with the root README's updated structure and the two-register policy introduced in `sk-create-readme` v1.2.0.0. Before this release, neither template said a word about emoji.

## What's New at a Glance

- **`### What It Does` now opens the OVERVIEW.** It says what the skill is and what the reader gets, following the root README's SUMMARY section and benefit bullets. Value-first replaces the problem-first mandate.
- **`### Why This Skill Exists` is optional.** Use it when the pain needs telling before the mechanism lands. The scaffold's amnesia example comment quoting the root README section the operator removed is gone.
- **The emoji rule is added to the writing rules.** Use semantic emoji only (`✅ ❌ ⚠️ 🔒 🚨`) for rules and status markers, never decorative section emoji. Formatting follows the technical register per `core-standards.md`.
- **Stale root-README references are updated.** The writing-rule bullet describing the removed problem opening and the triage-nurse analogy quote were updated. The model name `Reasons to try it` became `Why it earns a place`.
- **The validation checklist checks the new structure.** The OVERVIEW row checks for a value-first opening. The problem-narrative row applies only when the optional subsection is present.
- **The parent-hub template mirrors the guidance.** `### What It Does` comes first and `### Why This Hub Exists` is optional. The emoji rule and checklist row are mirrored too.
- **Both README templates use version `1.3.0.0`.** `skill-readme-template.md` moved from `1.2.0.15` and `parent-skill-readme-template.md` moved from `1.2.0.4`.
- **The `sk-create-readme` register reference now states the same deal from the other side.** It keeps technical formatting and allows an engaging voice. `types-and-voice.md` moved to `1.2.1.0`.
- **The README section model stays in place.** The numbered ALL-CAPS structure and AT A GLANCE table stay in place and OVERVIEW remains the only required section. The Human Voice Rules hard blockers are unchanged.

## Upgrade

No migration required. This is template guidance only. No shipped skill README was rewritten. The guidance applies to new and updated documents. `SKILL.md`, the reference templates, scripts and the mode registries stay untouched.
