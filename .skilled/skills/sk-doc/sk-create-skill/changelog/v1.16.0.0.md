# v1.16.0.0, A Standalone Skill May Own Slash Commands

Only a hub could declare its slash commands. A standalone skill that owned a command had no file to record it in. Now `command-metadata.json` is optional on a standalone root too.

> Spec folder: `specs/system-skill-advisor/routing-and-scoring/008-command-surfacing-build/002-command-inventory-and-risk-metadata`

&nbsp;

## What's New at a Glance

- **A standalone root may carry `command-metadata.json`.** It was forbidden there. Add it only when the skill ships slash commands.
- **Each entry's `ownerMode` is the skill's own id.** A standalone root has no mode registry. Any other owner fails the root metadata gate as `COMMAND_METADATA_UNKNOWN_OWNER_MODE`.
- **The same core checks run on both kinds of root.** The command file must exist and every listed resource must resolve.

&nbsp;

## Upgrade

No migration required. A standalone skill without slash commands needs no change.
