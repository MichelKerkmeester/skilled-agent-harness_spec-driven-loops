# v1.14.0.0, Templates That Pass Their Own Checks

A skill built from these templates now clears the render checks the packager runs, instead of copying the shapes those checks flag.

> Spec folder: `specs/sk-doc/066-skill-readability-refinement/014-sk-create-skill-refinements/003-templates-and-fleet` (Level 3)

&nbsp;

## What's New at a Glance

- **OVERVIEW opens with Purpose.** `skill-reference-template.md` and `skill-asset-template.md` each open their own OVERVIEW with Purpose then Usage, and both validate with 0 findings. The reference body skeleton still teaches Purpose then When to Use.
- **Intros are hooks.** The intro guidance says the description and the intro say different things, calls the intro a hook rather than a summary, and lists the pointer openings the validator flags.
- **READMEs open with OVERVIEW.** The skill and parent-skill README templates fold the four-row table into OVERVIEW as its first subsection, `### At a Glance`, and renumber the sections after it.
- **One REFERENCES section, last.** The SKILL.md skeleton, its section guidance and `skill-scaffold-template.md` carry one `REFERENCES AND RELATED RESOURCES` section as the last H2. The template stops recommending the combined `SMART ROUTING & REFERENCES` heading, which packaging still accepts.
- **Two recommended sections.** `package_skill.py` recommends SUCCESS CRITERIA and INTEGRATION POINTS. RELATED RESOURCES is no longer listed apart, since the required closing section carries it.
- **One size table.** `skill-md-template.md` section 3 holds the one `### Size Limits` table, built from the `package_skill.py` constants. The other size statements in the templates and references point at it.

&nbsp;

## Upgrade

No migration required. Existing skills keep validating; the templates change what a new skill starts from.
