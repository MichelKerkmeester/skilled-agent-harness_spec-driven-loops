# The Optional Scope File Is Documented

A standalone skill could author `leaf-scopes.json`, but nothing in this packet said so. The generator had read the file since the standalone scoping release, and `system-skill-advisor` already depends on it to keep `hooks/` Markdown-only, yet an author following the skill met the capability only in a changelog entry.

The skill now says what the file is for, where it sits in the standalone shape, and what a bad scope does. The class table also names `hooks/` among the corpora a standalone skill routes, and that is the corpus the first scope had to narrow.

> Spec folder: `specs/sk-doc/072-skill-routing-and-clarity/012-alignment-remediation` (Level 2)

&nbsp;

## What's New at a Glance

- **The file is named where an author looks.** The standalone shape lists `leaf-scopes.json` as optional, and the prose says which roots it narrows and why.
- **The contract has a row for it.** The root metadata matrix marks it optional and authored for both classes, and a new section explains the default walk when it is absent.
- **`hooks/` is named as a routed corpus.** The class table lists it beside `references/`, `assets/`, `feature-catalog/` and `manual-testing-playbook/`, so a scope over a hook doc reads correctly.
- **A bad scope has a name.** `OUT_OF_ROOT_LEAF_SCOPE` and `ORPHAN_LEAF_SCOPE_MODE` are documented next to that row.
- **The playbook runs the case.** The standalone root-metadata scenario adds the scope when a leaf root needs narrowing and proves both failures.
- **The count is right.** The contract says nine metadata JSON files, not eight, and the add-a-root recipe names the optional file.

&nbsp;

## Upgrade

No action is needed. A root without `leaf-scopes.json` generates the same manifest it did before.
