# The Routing Canon and Its Gates

A skill's `SMART ROUTING` section now says how a prompt reaches the skill. It does so in a few lines of prose. The pseudocode that loads its resources sits in a final `## MACHINE ROUTER` section. Two gates hold that shape. `package_skill.py --strict` and `parent-skill-check.cjs` check `12b-routing-shape`.

&nbsp;

## What's New at a Glance

- **Section 2 reads as prose.** A hub's `SMART ROUTING` points at its one root `ROUTER.md`. A mode packet's is 8 to 12 lines of plain prose. It has no `ROUTER.md` of its own. A request that matches no mode returns `UNKNOWN_FALLBACK` rather than a silent default.
- **The machine router has one home.** Any `INTENT_SIGNALS` or `RESOURCE_MAP` block belongs in the final `## MACHINE ROUTER` section. So the executable routing stays intact and out of the prose.
- **`package_skill.py --strict` rejects the old shape.** Four codes report it. `RS-001` covers a `SMART ROUTING` over 12 non-blank lines or 180 words. `RS-002` covers a machine block outside the final section. `RS-003` covers that section not being last. `RS-004` covers a mode packet carrying its own `ROUTER.md`. A machine block is a fenced block or an unfenced run of router lines. A fence closes only on a run of the same character. That run must be at least as long as the one that opened it.
- **The hub gate applies the same rule.** `parent-skill-check.cjs` check `12b-routing-shape` audits the hub root and every packet in `mode-registry.json`. So `/create:skill-parent` rejects an old-shape packet too.
- **`/create:skill` now blocks on the shape.** Its completion gate runs `validate_skill_package.py --strict`. So a routing-shape finding blocks creation. It does not print as a warning. The hub scaffold also keeps the compiled-routing directive in its final `## MACHINE ROUTER` section. That section is now numbered.
- **Existing skills are recorded, not broken.** `routing-shape-known-debt.json` keys each listed skill by its path relative to `.skilled/skills`. One example is `sk-code/sk-code-review`. A folder outside that root is never debt. An entry records its `lines`, `words`, `machineBlocks` and `codes`. The skill fails only when a count grows past the record. It also fails when it shows a code the entry does not record. An entry in any other form is ignored.
- **New scaffolds start on the canon.** The skill and hub templates now emit it. So do the packet scaffold, the references and both `/create:skill` and `/create:skill-parent`. A fresh parent scaffold passes `parent-skill-check`. That is because `init_skill.py` renders `allowed-tools` as a list. Its `## MACHINE ROUTER` section keeps the `UNKNOWN_FALLBACK_CHECKLIST` the compiled router reads.

&nbsp;

## Upgrade

Existing skills stay valid as known debt. Each is listed in `routing-shape-known-debt.json` with the shape it had. It fails once its line or word count grows. It also fails when its count of misplaced machine blocks grows. It fails too when it shows a finding code its entry does not record. A ledger entry may only shrink. `routing-shape-known-debt-ratchet.test.cjs` compares the ledger with a frozen snapshot. It fails on a new key, a higher count or a new code.

To migrate one, move its machine router block into a final `## MACHINE ROUTER` section. Shorten `SMART ROUTING` to prose. Delete any `ROUTER.md` the packet carries. Remove its entry from the ledger.
