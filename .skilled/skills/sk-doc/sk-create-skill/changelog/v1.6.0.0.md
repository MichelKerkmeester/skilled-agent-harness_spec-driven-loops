# The Routing Canon and Its Gates

A skill's `SMART ROUTING` section now says how a prompt reaches the skill in a few lines of prose, and the pseudocode that loads its resources sits in a final `## MACHINE ROUTER` section. Two gates hold that shape: `package_skill.py --strict` and `parent-skill-check.cjs` check `12b-routing-shape`.

> Spec folder: `specs/sk-doc/072-skill-routing-and-clarity/003-routing-canon-and-tooling` (Level 2)

&nbsp;

## What's New at a Glance

- **Section 2 reads as prose.** A hub's `SMART ROUTING` points at its one root `ROUTER.md`, a mode packet's is 8 to 12 lines of plain prose with no `ROUTER.md` of its own, and a request that matches no mode returns `UNKNOWN_FALLBACK` rather than a silent default.
- **The machine router has one home.** Any `INTENT_SIGNALS` or `RESOURCE_MAP` block belongs in the final `## MACHINE ROUTER` section, so the executable routing stays intact and out of the prose.
- **`package_skill.py --strict` rejects the old shape.** Four codes report it: `RS-001` for an over-long `SMART ROUTING`, `RS-002` for a machine block outside the final section, `RS-003` for that section not being last, and `RS-004` for a mode packet carrying its own `ROUTER.md`.
- **The hub gate applies the same rule.** `parent-skill-check.cjs` check `12b-routing-shape` audits the hub root and every packet in `mode-registry.json`, so `/create:skill-parent` rejects an old-shape packet too.
- **Existing skills are recorded, not broken.** `routing-shape-known-debt.json` lists each skill still in the old shape with the `SMART ROUTING` line count it was listed at, so a listed skill fails only when that section grows.
- **New scaffolds start on the canon.** The skill and hub templates, the packet scaffold, the references and both `/create:skill` and `/create:skill-parent` now emit it. A fresh parent scaffold passes `parent-skill-check` because `init_skill.py` renders `allowed-tools` as a list, and its `## MACHINE ROUTER` section keeps the `UNKNOWN_FALLBACK_CHECKLIST` the compiled router reads.

&nbsp;

## Upgrade

Existing skills stay valid as known debt: they are already listed in `routing-shape-known-debt.json`, and a listed skill fails only if its `SMART ROUTING` section grows.

To migrate one, move its machine router block into a final `## MACHINE ROUTER` section, shorten `SMART ROUTING` to prose, delete any `ROUTER.md` the packet carries, and remove its entry from the ledger.
