# The Routing Canon and Its Gates

A skill's `SMART ROUTING` section now says how a prompt reaches the skill in a few lines of prose, and the pseudocode that loads its resources sits in a final `## MACHINE ROUTER` section. Two gates hold that shape: `package_skill.py --strict` and `parent-skill-check.cjs` check `12b-routing-shape`.

> Spec folder: `specs/sk-doc/072-skill-routing-and-clarity/003-routing-canon-and-tooling` (Level 2)

&nbsp;

## What's New at a Glance

- **Section 2 reads as prose.** A hub's `SMART ROUTING` points at its one root `ROUTER.md`, a mode packet's is 8 to 12 lines of plain prose with no `ROUTER.md` of its own, and a request that matches no mode returns `UNKNOWN_FALLBACK` rather than a silent default.
- **The machine router has one home.** Any `INTENT_SIGNALS` or `RESOURCE_MAP` block belongs in the final `## MACHINE ROUTER` section, so the executable routing stays intact and out of the prose.
- **`package_skill.py --strict` rejects the old shape.** Four codes report it: `RS-001` for a `SMART ROUTING` over 12 non-blank lines or 180 words, `RS-002` for a machine block outside the final section, `RS-003` for that section not being last, and `RS-004` for a mode packet carrying its own `ROUTER.md`. A machine block is a fenced block or an unfenced run of router lines, and a fence closes only on a run of the same character at least as long as the one that opened it.
- **The hub gate applies the same rule.** `parent-skill-check.cjs` check `12b-routing-shape` audits the hub root and every packet in `mode-registry.json`, so `/create:skill-parent` rejects an old-shape packet too.
- **`/create:skill` now blocks on the shape.** Its completion gate runs `validate_skill_package.py --strict`, so a routing-shape finding blocks creation instead of printing as a warning. The hub scaffold also keeps the compiled-routing directive in its final `## MACHINE ROUTER` section, which is now numbered.
- **Existing skills are recorded, not broken.** `routing-shape-known-debt.json` keys each listed skill by its path relative to `.skilled/skills`, for example `sk-code/sk-code-review`; a folder outside that root is never debt. An entry records its `lines`, `words`, `machineBlocks` and `codes`, and the skill fails only when a count grows past the record or it shows a code the entry does not record. An entry in any other form is ignored.
- **New scaffolds start on the canon.** The skill and hub templates, the packet scaffold, the references and both `/create:skill` and `/create:skill-parent` now emit it. A fresh parent scaffold passes `parent-skill-check` because `init_skill.py` renders `allowed-tools` as a list, and its `## MACHINE ROUTER` section keeps the `UNKNOWN_FALLBACK_CHECKLIST` the compiled router reads.

&nbsp;

## Upgrade

Existing skills stay valid as known debt: each is listed in `routing-shape-known-debt.json` with the shape it had, and it fails once its line or word count or its count of misplaced machine blocks grows, or it shows a finding code its entry does not record. A ledger entry may only shrink: `routing-shape-known-debt-ratchet.test.cjs` compares the ledger with a frozen snapshot and fails on a new key, a higher count or a new code.

To migrate one, move its machine router block into a final `## MACHINE ROUTER` section, shorten `SMART ROUTING` to prose, delete any `ROUTER.md` the packet carries, and remove its entry from the ledger.
