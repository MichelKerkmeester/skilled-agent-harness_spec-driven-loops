# One Vocabulary Source per Hub

A parent hub's mode vocabulary now has one authored home, so the words that route a request cannot drift apart between the registry, the root router and the packets. A new check holds that agreement. The reach check gains six two-hub disputes it can now probe.

> Spec folder: `specs/sk-doc/072-skill-routing-and-clarity/004-single-vocabulary-source` (Level 2)

&nbsp;

## What's New at a Glance

- **One vocabulary source, checked on three legs.** `scripts/ci-hub-vocabulary-source.cjs` reads `vocabularyClasses` in every parent hub's `hub-router.json` and fails when a registry alias, a root `ROUTER.md` intent or a packet `Keyword triggers:` line disagrees with it, with `sk-code` exempt from the root-intent leg because its router is a surface router.
- **The gate runs with the registry drift workflow.** `routing-registry-drift` now runs the check, so a vocabulary mismatch fails CI instead of waiting for a reader to notice. The check ships with its own test.
- **Six ownership disputes join the reach allowlist.** `router-reach-allowlist.json` now records `opencode skill`, `opencode agent`, `opencode command`, `claude code agent`, `release readiness` and `decision branch`, the two-hub phrases the reach check probes.

&nbsp;

## Upgrade

No action is needed. This release adds a gate and extends the reach allowlist without changing anything a reader has to adopt.
