# v1.5.11.0, The Router Reach Check Judges the Shipped Fleet

`ci-router-vocabulary-reach.cjs` printed `RESULT: FAILED` on an operator's machine and passed in CI, because a private surface linked into that checkout tied two shipped hubs on phrases they declare. The check now decides every phrase over the shipped fleet, so it gives the same verdict on every machine, and it still tells the operator when a private surface takes a phrase there.

> Spec folder: `specs/sk-code/017-portable-code-modes/013-router-reach-local-ties` (Level 2)

&nbsp;

## What's New at a Glance

- **A private surface can no longer fail the run.** It is dropped from the ranking before the declaring hub is judged, so a tie or a win on one machine stops reading as a broken shipped phrase.
- **It cannot hide a real loss either.** When a shipped hub other than the declaring one leads after the drop, the phrase still fails as outranked or wrong-hub.
- **The tie is reported as a note.** A new `operator-local` count and a `note` line give the private surface's confidence beside the shipped hub's, and never its name, so a private folder name stays off the screen and out of logs.
