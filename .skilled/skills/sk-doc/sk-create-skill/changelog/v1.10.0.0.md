# v1.10.0.0, Renamed Router Phrases Leave the Advisor

A router phrase that is renamed used to stay in the hub's advisor vocabulary, because the generator that copies router phrases up only ever added. Now the generator remembers what it added, so a phrase it carried up and a router later dropped is reported and removed. Hand-curated signals are never touched.

&nbsp;

## What's New at a Glance

- **The generator records provenance.** `generate-router-intent-signals.cjs --write` adds each phrase it carries up to `intent_signals_generated` as well as `intent_signals`.
- **A dropped generated phrase is an orphan.** `--check` names and counts each orphan and fails on it, and `--write` removes it from both lists while every other signal keeps its place.
- **A keep list pins a phrase.** A generated phrase listed in `intent_signals_keep` is never reported or removed, for a phrase that should outlive its router entry.
- **The root-metadata gate admits both lists.** `ci-skill-root-metadata.cjs` accepts `intent_signals_generated` and `intent_signals_keep`, and reports `GRAPH_METADATA_INVALID_SIGNAL_LIST` when one holds anything but non-blank strings.
- **Router reach defaults to concurrency 2.** At 8, a busy advisor's refusals came back as unreachable phrases. The measured price of 2 is about half a second per 48 uncached probes.

&nbsp;

## Upgrade

No migration required. No hub carries the provenance list yet, so every live hub reports zero orphans until its next `--write`, which starts the list. A phrase generated before this release is not tracked; if a router drops one, remove it from `intent_signals` by hand once.
