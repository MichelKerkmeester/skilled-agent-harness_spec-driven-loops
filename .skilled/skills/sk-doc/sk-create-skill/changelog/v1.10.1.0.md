# v1.10.1.0, The Leaf Replay Reads Every Router Grammar

`leaf-route-replay.cjs` read only an `INTENT_SIGNALS` dict, so a packet router that names its map `INTENT_MODEL`, which the root-router contract allows, replayed to no intent at all. It now reads the grammar the router declares, and keyword matching no longer depends on how a prompt spells a hyphen.

> Spec folders: `specs/sk-code/018-frontend-upstream-proposals/005-inferred-confirmations` and `006-open-items-and-alignment` (Level 2)

&nbsp;

## What's New at a Glance

- **`INTENT_MODEL` routers replay.** The replay reads `INTENT_MODEL` when no `INTENT_SIGNALS` block is declared. Nineteen routers use that name, `sk-design-fundamentals` among them.
- **Tuple weights count.** A `("phrase", weight)` keyword adds its own weight, where every tuple used to score 1.
- **Hyphen and space match alike.** `keywordHits` folds hyphen runs to one space on both the task text and the keyword, so "widget-panel" hits "widget panel" and the reverse. The compiled hub matchers fold the same way.
- **The docs say what the generator records.** The root-metadata contract, the script header and `plan()` comment say a router-declared phrase is recorded on the first `--write` and is pruned on a later rename unless `intent_signals_keep` pins it. The scripts README names the orphan check, the prune and the keep list, and the replay's feature-catalog entries name the grammar above and the 66-row gold.

&nbsp;

## Upgrade

- The first `--write` on a hub without `intent_signals_generated` now seeds it from the router-declared phrases already present in `intent_signals`, so a later router rename is reported as an orphan.

No migration required. The seven hub replays give the same results, since no hub router uses either form.
