# v1.10.1.0, The Leaf Replay Reads Every Router Grammar

`leaf-route-replay.cjs` read only an `INTENT_SIGNALS` dict. The root-router contract allows a packet router to name its map `INTENT_MODEL`. Such a router replayed to no intent at all. The replay now reads the grammar the router declares. Keyword matching no longer depends on how a prompt spells a hyphen.

&nbsp;

## What's New at a Glance

- **`INTENT_MODEL` routers replay.** The replay reads `INTENT_MODEL` when no `INTENT_SIGNALS` block is declared. Nineteen routers use that name. `sk-design-fundamentals` is one of them.
- **Tuple weights count.** A `("phrase", weight)` keyword adds its own weight. Every tuple used to score 1.
- **Hyphen and space match alike.** `keywordHits` folds hyphen runs to one space. It does this on both the task text and the keyword. So "widget-panel" hits "widget panel" and the reverse. The compiled hub matchers fold the same way.
- **The docs say what the generator records.** Three places say a router-declared phrase is recorded on the first `--write`. They are the root-metadata contract, the script header and the `plan()` comment. It is pruned on a later rename, unless `intent_signals_keep` pins it. The scripts README names the orphan check, the prune and the keep list. The replay's feature-catalog entries name the grammar above and the 66-row gold.

&nbsp;

## Upgrade

- The first `--write` on a hub without `intent_signals_generated` now seeds it from the router-declared phrases already present in `intent_signals`. So a later router rename is reported as an orphan.

No migration required. The seven hub replays give the same results. That is because no hub router uses either form.
