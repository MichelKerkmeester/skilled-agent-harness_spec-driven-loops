# v1.5.9.0, The Skill-Root Generators Stop Waiting on a Stuck git Daemon

The leaf-manifest generator and the derived-metadata regenerator both ask git which files it ignores. A git fsmonitor daemon that stopped answering made those calls wait forever. One such wait held a push in the skill-root gate for about 30 minutes. Each call now skips the daemon. Each call has a 20-second ceiling. A missing answer no longer turns into a wrong one.

&nbsp;

## What's New at a Glance

- **No git call waits on the daemon.** The ignore checks run with `core.fsmonitor=false`. They stop after 20 seconds. After the first failure, the manifest generator stops calling git for the rest of a run.
- **A timed-out manifest write refuses.** `generate-leaf-manifest.cjs` leaves the existing `leaf-manifest.json` in place. It exits non-zero, because without git's answer it cannot tell which leaves git ignores.
- **A timed-out manifest check says why.** `--check` now reports the git timeout. It exits non-zero. It no longer shows a stale-manifest diff. That diff blamed a correct manifest and pointed at a write that would refuse too.
- **The regenerator keeps what it cannot verify.** `regenerate-skill-derived.cjs` cannot learn whether a referenced path is ignored. Then it keeps the reference. It does not prune real routing signal.

&nbsp;

## Upgrade

No migration required. If a manifest write or check reports a git timeout, end the stuck fsmonitor daemon. Then run it again.
