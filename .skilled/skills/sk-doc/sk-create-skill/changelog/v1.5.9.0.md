# v1.5.9.0, The Skill-Root Generators Stop Waiting on a Stuck git Daemon

The leaf-manifest generator and the derived-metadata regenerator both ask git which files it ignores. A git fsmonitor daemon that stopped answering made those calls wait forever, and one such wait held a push in the skill-root gate for about 30 minutes. Each call now skips the daemon and has a 20-second ceiling, and a missing answer no longer turns into a wrong one.

> Spec folder: `specs/sk-git/035-fsmonitor-daemon-and-worktree-relocation-regression` (Level 2)

&nbsp;

## What's New at a Glance

- **No git call waits on the daemon.** The ignore checks run with `core.fsmonitor=false` and stop after 20 seconds, and the manifest generator stops calling git for the rest of a run after the first failure.
- **A timed-out manifest write refuses.** `generate-leaf-manifest.cjs` leaves the existing `leaf-manifest.json` in place and exits non-zero, because without git's answer it cannot tell which leaves git ignores.
- **A timed-out manifest check says why.** `--check` now reports the git timeout and exits non-zero, instead of showing a stale-manifest diff that blames a correct manifest and points at a write that would refuse too.
- **The regenerator keeps what it cannot verify.** When `regenerate-skill-derived.cjs` cannot learn whether a referenced path is ignored, it keeps the reference rather than pruning real routing signal.

&nbsp;

## Upgrade

No migration required. If a manifest write or check reports a git timeout, end the stuck fsmonitor daemon and run it again.
