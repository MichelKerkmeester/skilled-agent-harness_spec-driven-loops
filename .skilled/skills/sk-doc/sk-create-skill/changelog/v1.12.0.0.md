# v1.12.0.0, One Strict Gate, a Wider Render Scan and a Ledger Ratchet

The packaging gate now reads every doc a skill hands a reader, and the docs name one command for it. New render checks and newly scanned files report as advisory until the fleet is cleared, so no skill fails today.

> Spec folder: `specs/sk-doc/066-skill-readability-refinement/014-sk-create-skill-refinements/001-render-checks-and-gate` (Level 2)

&nbsp;

## What's New at a Glance

- **One completion gate.** `SKILL.md`, `README.md` and `references/skill/creation-workflow.md` name `scripts/validate_skill_package.py <path> --strict`. The stale line saying the gate reads resource frontmatter only is gone, since the gate runs the render checks.
- **The render scan reads more of a skill.** `package_skill.py` now checks `SKILL.md`, `ROUTER.md`, `shared/references/` and `runtime/references/` besides `references/` and `assets/`, and records the scope of each finding.
- **New codes and scopes start advisory.** `RENDER_STAGED_CODES` and `RENDER_STAGED_SCOPES` hold the render codes and scan scopes added in this release plus `README.md`. Their findings print as `render advisory:`, which `--strict` does not promote. `RENDER_STAGED_OFF=1` enforces them, to list a skill's findings before fixing them.
- **A stale debt entry fails strict.** The message for a ledger entry that records more findings than remain now starts `render check: stale known debt:`, so `--strict` promotes it.
- **The ledger and the staged sets can only shrink.** `scripts/tests/render-known-debt-ratchet.test.cjs` compares them with a frozen fixture and fails on a new debt key, a raised count, a new exempt key or a new staged code or scope.
- **Fenced headings no longer satisfy a required section.** The SKILL.md section scan skips headings inside fences, so `references/shared/common-pitfalls.md` drops its `\##` escapes and the note that explained them.
- **CI runs the gate.** `.github/workflows/sk-doc-script-tests.yml` gained a `render-gate` job that runs the ratchet and packages every skill and mode under `--strict`.

&nbsp;

## Upgrade

No migration required. Run `validate_skill_package.py <path> --strict` where `validate_skill_package.py <path>` ran before.
