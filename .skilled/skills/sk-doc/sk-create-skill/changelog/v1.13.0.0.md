# v1.13.0.0, the Shared Exempt Loader, a Pinned List and a Guard Step

Packaging now trusts an exemption only when the code behind it names the doc, and refining an existing skill's docs has a guard step before commit.

> Spec folder: `specs/sk-doc/066-skill-readability-refinement/014-sk-create-skill-refinements/002-exempt-and-rewrite-guard` (Level 3)

&nbsp;

## What's New at a Glance

- **Packaging uses the shared loader.** `package_skill.py` drops its own exempt reader and calls `render_exempt.load_exempt()`, so an entry whose consumer does not name its doc no longer exempts it.
- **The ledger gains a pinned list.** `scripts/render-known-debt.json` lists `sk-code/shared/references/universal/code-quality-standards.md` and `sk-code/sk-code-review/references/review-core.md`, pinned by `check-rule-copies.js`. Render checks still run on them, and the rewrite guard refuses to change them.
- **Ledger entries name real consumers.** The two Style Reference `DESIGN.md` files joined the exempt map with `apply-design-md.cjs`, and the contract snapshot's consumer is now the contract that names its path.
- **A guard step before commit.** The Update Workflow in `references/skill/examples-and-maintenance.md` and Step 6 of `creation-workflow.md` run `doc-rewrite-guard.py --base HEAD <skill-folder>` when a change rewrites existing docs.
