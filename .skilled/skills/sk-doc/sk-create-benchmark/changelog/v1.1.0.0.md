# create-benchmark v1.1.0.0: Behavior Benchmark Authoring

`create-benchmark` now pairs its unchanged MCP-promotion workflow with a new authoring path for deep-loop behavior benchmarks.

## What's New at a Glance

- **`behavior_benchmark` is the second benchmark family for deep-loop modes.** Its packages specify executor-model behavior at the invocation surface and instantiate the shared measurement framework, whose five-dimension rubric, terminal buckets, budget formula, entry-surface and clarity enums, per-package ID-prefix table and runner stay in `system-deep-loop/shared/behavior-benchmark/framework.md`, outside this packet.
- **The MCP-promotion workflow is unchanged.** It uses `mcp-server/benchmarks/benchmark-<YYYY-MM-DD>/` with a ten-section `benchmark_report.md` and `SOURCE.md`.
- **The index template defines the package outline.** `assets/behavior-benchmark/behavior-benchmark-index-template.md` is a fillable scaffold for a `behavior_benchmark.md` index with OVERVIEW and a declared-extensions subsection, SCENARIO TABLE, AXIS COVERAGE, EXECUTION and RELATED RESOURCES.
- **The scenario template defines each scenario contract.** `assets/behavior-benchmark/behavior-benchmark-scenario-template.md` is a fillable scaffold for `<PREFIX>-NNN-<slug>.md` with the runner-parsed JSON machine contract plus Rationale, Pass shape and Failure modes prose.
- **The shipped scenario has no frontmatter or OVERVIEW heading.** When copied, the template's frontmatter, usage comment and Overview are stripped.
- **The baseline template prepares Claude capture.** `assets/behavior-benchmark/behavior-benchmark-baseline-template.md` is a fillable scaffold for `baselines/claude-baseline.md` with Overview, Baseline Table, Capture Provenance and Notes, using `pending` / `not_captured` cells until a real Claude leg lands.
- **The guide covers the full authoring workflow.** `references/behavior-benchmark/behavior-benchmark-guide.md` explains what behavior benchmarks measure, how they differ from MCP promotion, package layout, naming conventions, the eight-step workflow, scenario-matrix design rules and validation.
- **`SKILL.md` describes both benchmark families.** The release adds §8 BEHAVIOR BENCHMARK PACKAGES, the in-contract summary of the new family: package shape, template map, authoring workflow, naming and its own ALWAYS/NEVER plus success criteria. §1 gains a Benchmark Families router table and behavior activation and keyword triggers, and the description, keywords and Family Boundary now cover both families.
- **Template links now point to `assets/`.** The release corrects broken `assets/benchmark/...` paths in `SKILL.md` and both README files (`README.md` plus `references/shared/README.md`) because the `assets/benchmark/` subdirectory does not exist and the templates live directly under `assets/`.
- **A follow-up link sweep is flagged for the broken path.** The `assets/benchmark/...` path still appears in `changelog/v1.0.0.0.md` (a historical record left intact) and `references/shared/worked-example.md` (outside this release's scope).
- **Behavior packages belong in the owning `system-deep-loop` mode-packet.** This packet ships only the templates and guide and has no packet-local `graph-metadata.json` or bound `/create:` slash command, while its single advisor identity lives at the `sk-doc` hub root.
