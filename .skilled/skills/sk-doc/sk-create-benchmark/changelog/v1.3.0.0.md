# v1.3.0.0, Lane A Authoring Guide Completes Six-Family Coverage

`create-benchmark` adds the Lane A (agent-improvement) authoring guide, completing the packet's six-family document-creation coverage. The previous release authored four families: MCP promotion, behavior, skill-benchmark and model-benchmark, while Lane A was code-owned.

## What's New at a Glance

- **Lane A now has an authoring guide.** `references/agent-improvement/agent-improvement-authoring-guide.md` covers the doc-only inputs an author fills before a run: the improvement charter and strategy scaffolds, target-onboarding classification, candidate proposal format and profiling / integration-scanning setup. The five-dimension `score_dimensions.md` rubric, `evaluator_contract.md`, `promotion_gate_contract.md` and code-coupled `improvement_config.json` stay lane-local and are cross-linked, never restated.
- **Lane A's existing Smart Routing row now names the guide.** In `SKILL.md` §2, its OWNS entry changes from `Nothing` as a `NON-GOAL` to the authoring guide. The rubric, config and templates stay in-lane code-owned routes. The §1 framing and Lane A routing paragraph were reworded. §13 REFERENCES gained the guide. Edits stayed word-neutral to hold the SKILL under its word cap.
- **Authoring links now run in both directions.** The previously missing lane-to-hub back-pointers were added to `deep-alignment/behavior-benchmark/behavior-benchmark.md` and the Lane A `assets/agent-improvement/README.md`. The behavior file now has its first reference to `create-benchmark`. The `create-benchmark`-to-lane link is in the guide, which links the lane contract.
- **Run and scoring materials stay outside `create-benchmark`.** The `Single home` distinction means one home for authoring guidance. Run and scoring ownership stays with the lanes that execute. No measurement contract, scoring rubric, schema, scorer, runner or code-coupled template moved into `create-benchmark`. Run/scoring contracts, schemas and code-coupled templates stay lane-owned in `system-deep-loop/deep-improvement` and are cross-linked, never relocated (see the packet decision record, ADR-002).

## Upgrade

No migration required.
