# v1.6.7.0, A Marker Counts Only After a Run Fails It

A marker such as an expected string passes any reply that contains it. A run that skipped the behavior could still pass. Authors must now show each marker failing once and name that run.

> Spec folder: `specs/other/006-repo-wide-unlazy-tail/004-benchmark-negative-control`

&nbsp;

## What's New at a Glance

- **A negative control comes first.** A marker, target or postcondition counts only after a run that skips the behavior has failed it. The author names that run in the scenario's Failure modes.
- **Four documents carry the rule.** The scenario template has a guidance row and `SKILL.md` has an ALWAYS rule. Step 6 of the guide names the control, and pitfalls lists the mistake.
- **No tooling changed.** The runner and the scenario JSON fields are as before. The idea comes from the unlazy and ponytail skill repos.

&nbsp;

## Upgrade

No migration required. Existing scenarios score as before. Add a negative control the next time you edit one.
