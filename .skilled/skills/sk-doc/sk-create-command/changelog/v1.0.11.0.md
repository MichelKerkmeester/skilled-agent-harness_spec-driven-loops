# v1.0.11.0, Authoring Steps and Rules Read as Lists

The packet's `SKILL.md`, `ROUTER.md`, `README.md`, command template and references were read file by file. The reading looked at readability, layout and structure. Text moved and split. Every claim was kept. No command, contract or template behavior changed.

> Spec folder: `specs/sk-doc/066-skill-readability-refinement/008-sk-doc` (Level 1)

&nbsp;

## What's New at a Glance

- **Authoring steps read one per line.** The README had one packed paragraph. It covered resolving the invocation path, reading existing commands, classifying the type, writing frontmatter and scoping `allowed-tools`. That paragraph is now five bold-led bullets.
- **The router lists what reaches it.** `ROUTER.md` names the six request types as a list. It then names the two resource families, `references/` and `assets/`, as a second list.
- **The rule blocks have headings.** `SKILL.md`'s Always, Never and Escalate If blocks are now subsections. The loader gating note moved to its own spot.
- **References open with their purpose.** Three references gained Purpose and When to Use sections. They are common-pitfalls, router-presentation-split and worked-example. The split reference now states its behavior-preserving rule before the before and after example.
- **The README covers the whole packet.** Its document table now lists `ROUTER.md`, two more references and the command contract files. The validator command uses the README's repository-root path.
- **The template's last two sections swapped.** In the command template, Command Contract is now section 19. Related Resources is section 20. Their content is unchanged.
