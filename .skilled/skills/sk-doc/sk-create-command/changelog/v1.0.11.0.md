# v1.0.11.0, Authoring Steps and Rules Read as Lists

The packet's `SKILL.md`, `ROUTER.md`, `README.md`, command template and references were read file by file for readability, layout and structure. Text moved and split, and every claim was kept. No command, contract or template behavior changed.

> Spec folder: `specs/sk-doc/066-skill-readability-refinement/008-sk-doc` (Level 1)

&nbsp;

## What's New at a Glance

- **Authoring steps read one per line.** The README's packed paragraph on resolving the invocation path, reading existing commands, classifying the type, writing frontmatter and scoping `allowed-tools` is now five bold-led bullets.
- **The router lists what reaches it.** `ROUTER.md` names the six request types as a list, then the two resource families, `references/` and `assets/`, as a second list.
- **The rule blocks have headings.** `SKILL.md`'s Always, Never and Escalate If blocks are now subsections, and the loader gating note moved to its own spot.
- **References open with their purpose.** The common-pitfalls, router-presentation-split and worked-example references gained Purpose and When to Use sections, and the split reference now states its behavior-preserving rule before the before and after example.
- **The README covers the whole packet.** Its document table now lists `ROUTER.md`, two more references and the command contract files, and the validator command uses the README's repository-root path.
- **The template's last two sections swapped.** In the command template, Command Contract is now section 19 and Related Resources is section 20, with their content unchanged.
