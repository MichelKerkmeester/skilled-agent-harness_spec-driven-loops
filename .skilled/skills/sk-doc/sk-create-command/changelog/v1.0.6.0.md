# v1.0.6.0, The CI Toggle Contract Reads the Repository Profile

The command contract's operations list described the `/doctor:ci` toggle with this repository's six `SKILLED_CI` names and a README check. The toggle now reads its switch names from the repository CI profile. The contract says that instead.

&nbsp;

## What's New at a Glance

- The toggle's write names the profile.
  - The toggle sets one switch variable from the repository CI profile to off, or deletes it.
  - The write happens after an approved plan.
- The toggle's refusals are listed.
  - The toggle refuses a variable behind a status check the live ruleset requires.
  - The toggle refuses a `neverOff` variable.
  - The toggle refuses one the workflows README keeps unset.
  - The toggle also refuses a change to the state a variable already has.
- The second confirmation is named.
  - The toggle asks a second named confirmation before it switches off a protected workflow.
- The `/doctor:ci` argument hint is a summary.
  - The contract's per-command hint now reads `[report|scaffold|toggle] [flags] | list | ?`.
  - The hint matches the router's hint.
  - That is because the router took a ninth flag, `--profile=<path>`, and lists every flag in its execution targets table.
