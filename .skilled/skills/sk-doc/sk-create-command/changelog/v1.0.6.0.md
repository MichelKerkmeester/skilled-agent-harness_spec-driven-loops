# v1.0.6.0, The CI Toggle Contract Reads the Repository Profile

The command contract's operations list described the `/doctor:ci` toggle with this repository's six `SKILLED_CI` names and a README check. The toggle now reads its switch names from the repository CI profile, so the contract says that instead.

> Spec folder: `specs/sk-code/017-portable-code-modes/007-ci-repo-profile` (Level 2)

&nbsp;

## What's New at a Glance

- **The toggle's write names the profile.** It sets one switch variable from the repository CI profile to off or deletes it, after an approved plan.
- **Its refusals are listed.** It refuses a variable behind a status check the live ruleset requires, a `neverOff` variable, one the workflows README keeps unset and a change to the state a variable already has.
- **The second confirmation is named.** It asks a second named confirmation before it switches off a protected workflow.
- **The `/doctor:ci` argument hint is a summary.** The contract's per-command hint now reads `[report|scaffold|toggle] [flags] | list | ?`, as the router's does, because the router took a ninth flag, `--profile=<path>`, and lists every flag in its execution targets table.
