# v1.0.4.0, One Place for the Input Gate

The packet gave two different positions for a command's input gate. So a new command could follow either. It now states one rule everywhere. That rule comes from the commands that already ship.

&nbsp;

## What's New at a Glance

- **One rule.** The gate sits after the H1 and its purpose line. It comes before any workflow step. The skill, README, references, template and playbook all say so.
- **The examples follow it.** Four example skeletons in the template moved their gate below the H1. So did the worked example.
- **Every shipped command matches.** `/doctor:git` moved its gate to the same place. So all nine commands with an input gate agree.

&nbsp;

## Upgrade

No migration required. A command whose gate sits above its H1 still works. Moving it below the H1 matches the rule.
