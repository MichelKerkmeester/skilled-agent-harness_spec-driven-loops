# v1.0.10.0, The Doctor Contract Covers the Skill Format Command

A doctor command the contract has never heard of is a command nothing checks. `/doctor:sk-skill` now sits in the contract's doctor row with both of its targets. So a contract check compares the shipped command against a stated claim, not nothing.

&nbsp;

## What's New at a Glance

- **The doctor family lists the new command.** `/doctor:sk-skill` joins the doctor command files and the route selector. Its two targets are `check` and `convert`.
- **The argument hint names both targets and their flags.** The contract states `[check|convert] [<name-or-path>] [--json] [--into-hub <hub>] [--dry-run]`. So the hub report and the dry run belong to the claim, not an operator's guess.
- **The write policy covers the whole conversion.** The destructive-operations entry names the staged root and the backup folder. It names the approved field flags and the changelog entry with its link. It names the four integration rows. That is what the engine writes and its undo block restores.
- **Three follow-ups are questions, and a doubled field is a refusal.** The contract says three things are asked, not refused. They are the intent phrases a plain skill needs and a description past 130 characters. A skill that declares no `allowed-tools` field is asked too. It also says `ALLOWED_TOOLS_DUPLICATE` stops the run. So a reader can tell a follow-up from a stop.
