# v1.0.10.0, The Doctor Contract Covers the Skill Format Command

A doctor command the contract has never heard of is a command nothing checks. `/doctor:sk-skill` now sits in the contract's doctor row with both of its targets, so a contract check compares the shipped command against a stated claim instead of against nothing.

> Spec folder: `specs/sk-doc/075-doctor-sk-skill-command` (Level 2)

&nbsp;

## What's New at a Glance

- **The doctor family lists the new command.** `/doctor:sk-skill` joins the doctor command files and the route selector, with `check` and `convert` as its two targets.
- **The argument hint names both targets and their flags.** The contract states `[check|convert] [<name-or-path>] [--json] [--into-hub <hub>] [--dry-run]`, so the hub report and the dry run belong to the claim rather than to an operator's guess.
- **The write policy covers the whole conversion.** The destructive-operations entry names the staged root, the backup folder, the approved field flags, the changelog entry with its link and the four integration rows, which is what the engine writes and what its undo block restores.
- **Three follow-ups are questions, and a doubled field is a refusal.** The contract says the intent phrases a plain skill needs, a description past 130 characters and a skill that declares no `allowed-tools` field are each asked rather than refused, and that `ALLOWED_TOOLS_DUPLICATE` stops the run, so a reader can tell a follow-up from a stop.
