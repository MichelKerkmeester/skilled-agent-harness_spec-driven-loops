## Command Authoring

#### A Defined Creation Workflow

The workflow scaffolds and refactors OpenCode slash commands under `.opencode/commands/`. It decides whether a command is warranted, resolves its invocation path and reads existing files first. It then classifies the command type and chooses the output package shape. It authors frontmatter with the fields `description`, `argument-hint` and `allowed-tools`.

The workflow's remaining steps add mandatory input gates for required arguments and write the command body. They implement argument dispatch and `:auto`/`:confirm` mode routing, then enforce the thin-router and presentation-asset split for larger mode-based commands. They also add destructive-action safety and validate before delivery. The rules require least-privilege `allowed-tools`, mandatory gates for required arguments and presentation text outside thin routers. Unclear invocation contracts are escalation conditions.

&nbsp;

#### References Guide Authoring

`references/README.md` is the overflow route map indexing the single-concern references. `references/worked-example.md` provides the canonical file contract and a fully worked split command with a router `.md` and presentation `.txt`. `references/router-presentation-split.md` covers router and presentation ownership, the before-and-after transformation and the behavior-preserving rule.

`references/argument-hints-and-modes.md` covers argument-hint design patterns, `:auto`/`:confirm` mode design and frontmatter/description budget tips. `references/common-pitfalls.md` covers command-vs-skill-vs-agent selection and the common command-authoring mistakes table.

&nbsp;

#### Templates for Command Families

`assets/command/command-template.md` provides command-type templates, examples, vocabulary and a validation checklist. `assets/command/command-presentation-template.md` is the full `_presentation.txt` skeleton for split mode-based command families.
