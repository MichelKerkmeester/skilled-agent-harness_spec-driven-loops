The operator validator now checks a scenario's prompt in its contract, execution table, conversation chain and root summary. It warns when copies differ. The Prompt Synchronization Gate said not to ship unsynchronized prompt fields. Nothing checked it.

&nbsp;

## What's New at a Glance

- `validate-playbook-package.cjs` adds the `PROMPT_UNSYNCED` warning.
  - It compares every copy with the structured prompt in `SCENARIO CONTRACT`.
  - That prompt is the reference.
  - It checks the execution table's `Exact Prompt` cell, a conversation chain's Turn 1 input and the root summary's prompt.
  - Each disagreement is reported at its own file and line.
  - Turn 1 is the input a scenario runner sends.
  - So a drifting chain runs a different test from the one the root indexes.
- Root summaries are matched through their scenario link.
  - They are found by walking out from the link to the scenario.
  - A heading block that links more than one scenario is an index, not a summary.
  - A block with two prompts is ambiguous.
  - So neither is attributed to a scenario.
- Formatting-only differences do not trigger a warning.
  - A copy that differs only in quotes, backticks, emphasis or spacing is not reported.
- `SKILL.md` documents the warning as advisory.
  - Its version changes from `1.0.1.2` to `1.0.2.0`.
  - The Prompt Synchronization Gate lists the Turn 1 copy.
  - The Prompt Synchronization Gate names `PROMPT_UNSYNCED`.
  - The validator scope paragraph records that the finding is advisory.
- `README.md` removes the prompt synchronization spot-check.
  - The validator now covers it.
- The advisory warning does not change package status or the fleet exit code.
  - `PROMPT_UNSYNCED` is never a violation.
  - At release, 58 packages report the same status and violation counts before and after.
  - There are 60 warnings across 12 packages to fix separately.
- Missing prompts continue to use `REQUIRED_PROMPT`.
  - `PROMPT_UNSYNCED` compares only copies that are present.
- Released changelog entries stay byte-identical.
  - The entries are `v1.0.0.0` through `v1.0.1.2`.
