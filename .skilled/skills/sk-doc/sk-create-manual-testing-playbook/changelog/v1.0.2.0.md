# create-manual-testing-playbook v1.0.2.0

The Prompt Synchronization Gate said not to ship unsynchronized prompt fields, but nothing checked it. A scenario could state one prompt in its contract and another in its table or root summary, and the validator passed it. `validate-playbook-package.cjs` now compares every copy against the contract and reports each one that disagrees.

## 1. NEW

- `PROMPT_UNSYNCED` warning. The structured prompt in `SCENARIO CONTRACT` is the reference. The execution table's `Exact Prompt` cell, a conversation chain's Turn 1 input and the root summary's prompt are each compared with it, and each copy that says something else is reported at its own file and line.
- Turn 1 joins the gate. A conversation chain's first input is the copy a scenario runner actually sends, so a chain that drifts from the contract runs a different test from the one the root indexes.
- Root summaries are found by walking out from the link to the scenario. A heading block that links more than one scenario is an index rather than a summary, and a block with two prompts is ambiguous, so neither is attributed to a scenario.
- Eight suite assertions pin both directions: a changed table cell, root summary or Turn 1 is reported, and a copy that differs only in quotes, backticks, emphasis or spacing is not.

---

## 2. CHANGED

- `SKILL.md` version `1.0.1.2` to `1.0.2.0`. The Prompt Synchronization Gate lists the Turn 1 copy and names the warning, and the validator scope paragraph records that the finding is advisory.
- `README.md` no longer lists prompt synchronization as a manual spot-check, since the validator now covers it.

---

## 3. NOT CHANGED

- The finding is a warning, never a violation, so no package changes status and the fleet exit code is unchanged. On the corpus at release, 58 packages report the same status and violation counts before and after, with 60 warnings across 12 packages to fix separately.
- A missing prompt is still `REQUIRED_PROMPT`. The new check compares only the copies that are present.
- The released changelog entries `v1.0.0.0` through `v1.0.1.2` stay byte-identical.
