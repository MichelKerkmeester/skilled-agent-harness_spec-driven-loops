The operator validator now checks whether a scenario's prompt matches across its contract, execution table, conversation chain and root summary, and warns when copies differ. The Prompt Synchronization Gate said not to ship unsynchronized prompt fields, but nothing checked it.

## What's New at a Glance

- **`validate-playbook-package.cjs` adds the `PROMPT_UNSYNCED` warning.** It compares every copy with the structured prompt in `SCENARIO CONTRACT` as the reference. The execution table's `Exact Prompt` cell, a conversation chain's Turn 1 input and the root summary's prompt are checked, and each disagreement is reported at its own file and line. Turn 1 is the input a scenario runner sends, so a drifting chain runs a different test from the one the root indexes.
- **Root summaries are matched through their scenario link.** They are found by walking out from the link to the scenario. A heading block that links more than one scenario is an index rather than a summary, and a block with two prompts is ambiguous, so neither is attributed to a scenario.
- **Formatting-only differences do not trigger a warning.** A copy that differs only in quotes, backticks, emphasis or spacing is not reported.
- **`SKILL.md` documents the warning as advisory.** Its version changes from `1.0.1.2` to `1.0.2.0`. The Prompt Synchronization Gate lists the Turn 1 copy and names `PROMPT_UNSYNCED`, and the validator scope paragraph records that the finding is advisory.
- **`README.md` removes the prompt synchronization spot-check.** The validator now covers it.
- **The advisory warning does not change package status or the fleet exit code.** `PROMPT_UNSYNCED` is never a violation. At release, 58 packages report the same status and violation counts before and after, with 60 warnings across 12 packages to fix separately.
- **Missing prompts continue to use `REQUIRED_PROMPT`.** `PROMPT_UNSYNCED` compares only copies that are present.
- **Released changelog entries stay byte-identical.** The entries are `v1.0.0.0` through `v1.0.1.2`.
