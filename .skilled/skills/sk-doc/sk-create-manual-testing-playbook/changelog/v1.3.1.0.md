# v1.3.1.0, --reports Accepts Only the Skill or Its Hub

The v1.3.0.0 check only asked whether the folder above `benchmark/reports` contained the playbook. Any folder above the playbook passed, so `--reports benchmark/reports` from the repository root, the disk root or a folder inside the playbook would all have written a run there.

&nbsp;

## What's New at a Glance

- The recorder now accepts a `--reports` folder only when it belongs to the playbook's own skill or to that skill's direct parent hub, and that parent counts as a hub only when it holds `mode-registry.json`. Without that marker, `.skilled/skills/` itself would pass as the parent of every top-level skill.
- Paths are compared after resolving symlinks, so a hub reached through a link, or `/var` against `/private/var` on macOS, is still the same hub.
- The hub-reports test covers a parent without `mode-registry.json`, a folder above the hub, a folder inside the playbook and a hub reached through a symlink. The hub fixture sits one level inside its temp folder, so a refused ancestor can never be the system temp folder.
- `SKILL.md` describes the tighter rule.

&nbsp;

## Upgrade

No action is needed. Every `--reports` value the shipped playbooks use names the owning hub and still passes.
