# v1.2.1.0, The run recorder is safer

A review of v1.2.0.0 found one bug that saved the wrong verdicts. It also found smaller gaps in the recorder, the coverage report and the docs.

&nbsp;

## What's New at a Glance

- A reused runner folder is safe.
  - `scenario.json` now lists the runtimes the run played.
  - The recorder saves only those runtimes.
  - Leftover folders from an earlier scenario are ignored.
- A failed save leaves nothing behind.
  - The run folder is built under a staging name and renamed last.
  - A write that fails is a refusal, and a retry works.
- Bad input is refused, not crashed on.
  - Unreadable runner output names its file.
  - A quote inside a comment line no longer breaks the CSV.
  - Problems name the real file line.
  - An impossible date is refused.
- Labels and evidence keep their shape.
  - A label may have more than one variant part.
  - Evidence text that starts with a slash is kept as written.
- Coverage reads CSV fields that span lines.
  - It counts the same scenario ids the recorder accepts.
- The printed `save results:` command is valid shell.
- sk-doc's report index has a run table, so its runs can be saved.
- Playbook docs that still named a renderer or a hand-written record now name the recorder.

&nbsp;

## Upgrade

No action is needed. Run folders written by v1.2.0.0 stay valid.
