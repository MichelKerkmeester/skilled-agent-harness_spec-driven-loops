# v1.0.1.0 - Smart-Routing Conformance

`SKILL.md` now satisfies the canonical section contract. That contract is enforced by `create-skill/scripts/package_skill.py`. Workflow behavior did not change. Existing prose was preserved. The required routing and references sections now use headings the matcher recognizes.

&nbsp;

## Why This Release

The section matcher strips a leading `N.`. It then substring-tests the uppercased H2 text. `SMART_ROUTING` does not contain the `SMART ROUTING` substring. The resources heading lacked the `REFERENCES` token. So the required sections did not resolve.

&nbsp;

## What's New at a Glance

- WHEN TO USE and SMART ROUTING now have separate headings.
  - The merged `## 1. WHEN TO USE + SMART_ROUTING` is split into `## 1. WHEN TO USE` and `## 2. SMART ROUTING`.
  - The decision-rule block and family-boundary note are under SMART ROUTING.
- A keyword trigger line supports discoverability.
  - `Keyword triggers:` was added inside WHEN TO USE.
- The resources section now satisfies the REFERENCES match.
  - Its heading is `## 9. RESOURCES FOR DEEP DETAIL & REFERENCES`.
  - The heading keeps its original intent.
- `SKILL.md` adds a SUCCESS CRITERIA section.
  - `## 8. SUCCESS CRITERIA` describes done-conditions for a playbook package.
- H2 headings run contiguously from 1 to 9.
  - No intra-file numeric cross-references needed adjustment.
