# v1.0.1.0 - Smart-Routing Conformance

`SKILL.md` now satisfies the canonical section contract enforced by `create-skill/scripts/package_skill.py` without changing workflow behavior. Existing prose was preserved, and the required routing and references sections now use headings the matcher recognizes.

## Why This Release

The section matcher strips a leading `N.` and substring-tests the uppercased H2 text. `SMART_ROUTING` does not contain the `SMART ROUTING` substring, and the resources heading lacked the `REFERENCES` token, so the required sections did not resolve.

## What's New at a Glance

- **WHEN TO USE and SMART ROUTING now have separate headings.** The merged `## 1. WHEN TO USE + SMART_ROUTING` is split into `## 1. WHEN TO USE` and `## 2. SMART ROUTING`, with the decision-rule block and family-boundary note under SMART ROUTING.
- **A keyword trigger line supports discoverability.** `Keyword triggers:` was added inside WHEN TO USE.
- **The resources section now satisfies the REFERENCES match.** Its heading is `## 9. RESOURCES FOR DEEP DETAIL & REFERENCES`, keeping its original intent.
- **`SKILL.md` adds a SUCCESS CRITERIA section.** `## 8. SUCCESS CRITERIA` describes done-conditions for a playbook package.
- **H2 headings run contiguously from 1 to 9.** No intra-file numeric cross-references needed adjustment.

## Upgrade

No migration required.
