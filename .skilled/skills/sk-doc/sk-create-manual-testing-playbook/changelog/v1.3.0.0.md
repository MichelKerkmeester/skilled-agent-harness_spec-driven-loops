# v1.3.0.0, A mode saves its runs into its hub

A mode packet inside a hub often has no `benchmark/` folder of its own. Until now the recorder could only save into the playbook's own skill, so three playbooks named a destination the recorder could not reach.

&nbsp;

## What's New at a Glance

- The recorder takes `--reports <hub>/benchmark/reports`.
  - It refuses a path that does not end in `benchmark/reports`.
  - It refuses a reports folder whose skill does not contain the playbook, so a typo cannot scatter run folders.
  - A new index there carries the hub's name, not the mode's.
- The conversation runner takes the same `--reports` and puts it in the `save results:` command it prints.
- Three playbooks now save where they say they do.
  - `sk-code-ci` and `sk-code-frontend` name `--reports .skilled/skills/sk-code/benchmark/reports`.
  - `cli-mistral-vibe` saved its results in a `Recorded Result` block in each scenario file. Those 25 verdicts moved into two recorder runs under `cli-external-orchestration/benchmark/reports/`, dated 2026-11-14 and 2026-11-15, and the blocks are gone. A run no longer edits a scenario file.
- `SKILL.md` and the root template describe the option.

&nbsp;

## Upgrade

No action is needed for a playbook that saves into its own skill. A mode playbook that saves into its hub adds `--reports` to its record command.
