# v1.2.0.0, Playbook runs are saved into the benchmark folder

A playbook run left nothing behind unless someone wrote the report by hand. The mode said reports were hand-written in one place and never hand-written in another. The validator only warned when a root dropped the results rule.

&nbsp;

## What's New at a Glance

- One command saves a run.
  - `scripts/record-playbook-run.cjs` writes the run into a new dated folder.
  - The folder holds `results.csv`, `README.md` and `source.md`.
  - It puts the run first in `benchmark/reports/README.md`.
  - It creates that index when a skill has none.
  - It refuses an unknown scenario id or a `FAIL` or `SKIP` without a reason.
  - It refuses an existing folder too, and then writes nothing.
- Conversation runs hand off.
  - The runner writes `scenario.json` when it ends.
  - It prints the `save results:` command.
- The results rule is enforced.
  - A root without the results marker is now an error.
  - The 11 roots that lacked it carry it now.
  - The fleet still passes.
- Coverage is visible.
  - `--coverage` lists the scenario ids with no saved verdict.
  - It never fails the run.

&nbsp;

## Upgrade

A root outside Skilled without the marker now fails. Copy the Result persistence block from the root template. Inside Skilled the fleet stays at 55 PASS and 4 SKIP.
