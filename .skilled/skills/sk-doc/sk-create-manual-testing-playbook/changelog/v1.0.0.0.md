The initial release of `create-manual-testing-playbook` adds one of the ten workflow packets in the `sk-doc` parent hub's workflow-only architecture. It authors manual testing playbooks with deterministic per-feature scenarios, so another operator or agent can reproduce the verdict.

## What's New at a Glance

- **Manual playbooks use reproducible scenario packages.** A `manual-testing-playbook/` package has a root `manual_testing_playbook.md` and numbered `NN--category-name` folders of per-feature files. Each file carries a deterministic scenario contract with an exact prompt, exact command sequence, expected signals, evidence, pass/fail criteria and failure triage.
- **`SKILL.md` defines the authoring and release process.** Its packet contract covers activation triggers and non-triggers, the canonical package shape and 18-step authoring workflow. It sets scenario design rules for determinism, natural-human vs RCAF prompt voice and the prompt synchronization gate, plus validation and release gates.
- **References and templates support package authoring.** `references/manual_testing_playbook_creation.md` gives standards and rationale for package structure, root-vs-per-feature responsibilities, prompt quality and validation. `assets/testing_playbook/manual-testing-playbook-template.md` scaffolds the root playbook, while `assets/testing_playbook/manual-testing-playbook-snippet-template.md` scaffolds per-feature scenarios.
- **Validation uses shared scripts.** The packet has no packet-local `scripts/`. Validation runs through `../shared/scripts/validate_document.py` and `extract_structure.py`.
- **The packet has no packet-local `graph-metadata.json`.** The single advisor identity and mode registry live at the `sk-doc` hub root.
