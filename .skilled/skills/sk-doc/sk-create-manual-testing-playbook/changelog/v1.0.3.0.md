# v1.0.3.0, The Validator Checks Backticked Paths

The playbook validator now checks every repository path a scenario names in a code span. It warns when one no longer resolves. Until this release only markdown links were checked. So a scenario that named a moved file in a code span passed the strict fleet gate.

&nbsp;

## What's New at a Glance

- **Backticked paths are checked.** Every repository path a scenario names in a code span is resolved. It is checked against the scenario's folder and its playbook root. It is also checked against its skill and hub roots. Those roots carry their `runtime/` and `scripts/` code. The repository root counts too. A path that resolves from none of them is reported as a warning at its file and line. That warning changes neither the package status nor the exit code. Placeholders, globs, absolute and home paths and runtime output are expected not to resolve. They are skipped.
- **The root playbook is read too.** The top-level `manual-testing-playbook.md` gets the same backticked-path check as the scenarios. Its findings are reported under that file name.
- **Symlinks and installed release state no longer produce warnings.** A backticked path that names a symlink resolves. That holds even when its target is a build output. That output has not been built yet. Paths under `.skilled/release/` are expected not to resolve. That is because the `/doctor:update` scenarios name release files. The command writes those files into an installed tree.
- **The whole report survives a pipe.** The validator now sets its exit code instead of forcing the process to end. Forcing the end used to drop whatever the report had not written yet. Before this, a piped fleet run stopped at 65,536 bytes. It lost its summary and exit line.
- **A scenario no longer needs a version to pass.** The validator's frontmatter check asks for a title and a description. A missing or malformed 4-part `version` is no longer reported.
