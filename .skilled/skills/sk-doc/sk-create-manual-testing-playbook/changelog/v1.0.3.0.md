# v1.0.3.0, The Validator Checks Backticked Paths

The playbook validator now checks every repository path a scenario names in a code span and warns when one no longer resolves. Until this release only markdown links were checked, so a scenario that named a moved file in a code span passed the strict fleet gate.

&nbsp;

## What's New at a Glance

- **Backticked paths are checked.** Every repository path a scenario names in a code span is resolved against the scenario's folder, its playbook root, its skill and hub roots with their `runtime/` and `scripts/` code, plus the repository root. A path that resolves from none of them is reported as a warning at its file and line without changing the package status or the exit code. Placeholders, globs, absolute and home paths and runtime output are expected not to resolve and are skipped.
- **The root playbook is read too.** The top-level `manual-testing-playbook.md` gets the same backticked-path check as the scenarios. Its findings are reported under that file name.
- **Symlinks and installed release state no longer produce warnings.** A backticked path that names a symlink resolves even when its target is a build output that has not been built yet. Paths under `.skilled/release/` are expected not to resolve, because the `/doctor:update` scenarios name release files the command writes into an installed tree.
- **The whole report survives a pipe.** The validator now sets its exit code instead of forcing the process to end, which used to drop whatever the report had not written yet. Before this, a piped fleet run stopped at 65,536 bytes and lost its summary and exit line.
- **A scenario no longer needs a version to pass.** The validator's frontmatter check asks for a title and a description. A missing or malformed 4-part `version` is no longer reported.
