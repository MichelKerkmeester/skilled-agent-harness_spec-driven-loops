# v1.1.0.0, Conversation Runner

The playbook skill now ships a shared conversation runner and the runner's own scripted scenario, which covers question tools, chat replies, restart and compaction.

&nbsp;

## What's New at a Glance

- **A scenario covers the runner itself.** It exercises single-select, multi-select, Other, chat, restart and compaction on Claude Code, OpenCode, Codex, Pi and Devin.
- **Codex hook trust is opt-in.** A script that sets `trust_hooks` lets Codex trust the scratch project's hooks. The runner removes or restores every trust entry it caused and refuses when Codex would also trust a hook outside the project.
- **Runs fail closed.** A symlinked scratch project, a setup that changes the repository, an unreadable watched folder and a child process that survives cleanup each stop or fail the run with a named reason, and Codex keeps its own workspace sandbox.
- **An exhausted usage limit is named as such.** When a launch or a turn has already failed, the runner reads the screen once, and a line that matches a usage-limit message reports the failure as `QUOTA_EXHAUSTED` with that line as its blocker. A passing turn is never reclassified, and only Codex's wording is confirmed from a recorded screen.
- **Each scenario's style is chosen by one rule.** `SKILL.md` §6 Choosing the Scenario Style asks four ordered questions that decide between a single prompt and a conversation. The router, the template, the references and `/create:manual-testing-playbook` all point to it, and the command records each scenario's style and deciding question and runs the package validator. A new scenario checks the choice.
- **Scenario templates are split by style.** The snippet template builds single-prompt scenarios only. The new `manual-testing-playbook-conversation-snippet-template.md` carries the required conversation block with placeholders, so an unfilled sample block can no longer pass validation.
- **The subject cannot write to the repository.** On macOS Claude Code, OpenCode, Pi and Devin start through `/usr/bin/sandbox-exec` with writes denied under the repository, the runner's own checkout and the git common dir. Codex keeps its own workspace sandbox and `--no-sandbox` turns the wrapper off. Each `result.json` records `seatbelt`, `codex-workspace-write`, `off` or `unavailable`, and an unsandboxed fallback writes one stderr line.
- **Wrapped questions match as one line.** A question that wraps over several screen lines is joined before its `match` pattern runs, so a pattern written for the whole sentence finds it on Claude Code, OpenCode and Pi.
- **Option labels can be short.** An `answer.select` label picks the option it equals, ignoring case, or else the one option that contains it, so `Skip` chooses `D) Skip documentation (Recommended)`. A label found in several options fails the turn instead of guessing.
- **The runner contract is documented.** The reference covers CLI options, exit codes, evidence files, timeouts and repository-change detection.
- **Multi-runtime guidance is included.** Setup copies each available project configuration into the scratch project, and run notes record the model used by each runtime.
- **The snippet template and README list the runner.** Conversation scenarios use the runner command as their command sequence.

## Upgrade

Use `references/conversation-scenarios.md` when running a conversation scenario. Use `manual-testing-playbook/conversation-runner/drive-a-scripted-conversation.md` as the worked example of a conversation scenario.
