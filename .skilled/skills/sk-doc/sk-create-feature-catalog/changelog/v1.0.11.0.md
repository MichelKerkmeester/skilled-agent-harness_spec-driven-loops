# v1.0.11.0, Authoring Order Numbered and Package Checks Named

The packet's `SKILL.md`, `ROUTER.md`, `README.md` and references were read file by file. The reading looked at readability, layout and structure. Text moved and split, and every claim was kept. A few statements were corrected to match the tree. No command, contract or template behavior changed.

&nbsp;

## What's New at a Glance

- The authoring order is numbered.
  - The README now walks five steps.
  - The steps run from reading the target system to validating the root and every leaf.
  - The README's When to Use moved up beside What It Does.
- The package validator is named.
  - The README's checks table gained a row for `scripts/validate_catalog_package.py`.
  - That row reports root and leaf bijection, source-file existence and the validation taxonomy.
  - So the manual review row now covers links and source anchors only.
- The router lists its resources.
  - `ROUTER.md` names the scaffolds under `assets/` and the overflow references under `references/`.
  - `ROUTER.md` gives them as two bullets.
  - `ROUTER.md` states that `references/README.md` is the default and fallback.
- The fallback is spelled out.
  - `SKILL.md` now says to report `UNKNOWN_FALLBACK` with the router's disambiguation checklist.
  - That applies when nothing matches.
- References point where they resolve.
  - The route map now names `system-skill-advisor/feature-catalog/` as the walked-through catalog.
  - The pitfalls and examples references point at `../assets/` for the templates.
