# v1.0.0.0, A Canonical Feature Catalog

The initial release of `create-feature-catalog`, one of the ten workflow packets in the `sk-doc` parent hub's workflow-only architecture, gives a system's shipped behavior a single reviewable current-state reference. It authors canonical feature-inventory packages with a root catalog organized into numbered category folders and one source-anchored per-feature file for each root entry.

## What's New at a Glance

- **`SKILL.md` defines when and how to create a feature catalog.** It distinguishes a catalog from a README summary and a playbook and sets the canonical package shape: `feature_catalog.md`, `NN--category-name/` folders and one per-feature file for each root entry. It covers the 14-step creation workflow, root and per-feature content requirements and ALWAYS/NEVER/ESCALATE rules.
- **The packet supplies deep guidance and two catalog templates.** `references/feature_catalog_creation.md` covers guidance beyond the inline workflow. The root-catalog template at `assets/feature-catalog/feature-catalog-template.md` scaffolds `feature-catalog/feature-catalog.md`. The snippet template at `assets/feature-catalog/feature-catalog-snippet-template.md` scaffolds each per-feature file.
- **The shared `sk-doc` backbone provides validation and advisor identity.** The packet has no packet-local `scripts/` or `graph-metadata.json`.
