# v1.0.1.0, Smart-Routing Section Conformance

This release makes the feature-catalog skill's section structure conform to the canonical contract enforced by the shared `package_skill.py --check`. It fixes headings and the reference surface without changing workflow, rules or authoring guidance.

## Why This Release

The former `WHEN TO USE + SMART_ROUTING` heading did not match the required `SMART ROUTING` section token, so the headings, not the content, blocked packaging validation. Making these headings explicit keeps the packet legible and machine-checkable.

## What's New at a Glance

- **The routing guidance now has separate sections.** In `SKILL.md`, `## 1. WHEN TO USE` covers activation triggers and the when-not-to-use boundary. `## 2. SMART ROUTING` covers the creation decision rule, decision pseudocode and family boundary.
- **References and success criteria have dedicated sections.** `## 11. REFERENCES` makes the required references surface a first-class heading instead of leaving it only in an inline resource list. `## 10. SUCCESS CRITERIA` captures the completion bar for a catalog package.
- **A Keywords comment was added.** The top-of-file `<!-- Keywords: ... -->` comment supports discovery.
- **Section numbers and one reference now match.** H2 headings are numbered contiguously, and the one intra-file cross-reference shifted by the renumbering was updated.

## Upgrade

No migration required.
