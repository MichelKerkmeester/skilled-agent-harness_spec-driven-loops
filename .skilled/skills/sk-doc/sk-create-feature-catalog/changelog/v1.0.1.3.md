# v1.0.1.3, Path Checks That Judge the Repository

`validate_catalog_package.py` now tells a correct path from a missing one by the repository's own rules. A catalog that names a build output or a local runtime file no longer fails, and a typo or a broken link no longer slips through.

> Spec folders: `specs/sk-code/011-sk-code-poinytail-based-refinement/014-skill-authoring-ux-research/010-validator-false-positives` and `016-sk-doc-tooling-followups` (Level 1)

&nbsp;

## What's New at a Glance

- **A committed symlink is judged by its target.** A link whose target is missing passes only when that target is ignored by a tracked `.gitignore`, such as a build output; any other dangling link is reported missing.
- **An ignored path that is absent is a note.** It prints as `ignored_path_absent` and never changes a package's verdict or the exit code.
- **Only repository rules count.** Matches from `.git/info/exclude` or a personal excludes file no longer hide a missing path, so every machine gets the same result.
