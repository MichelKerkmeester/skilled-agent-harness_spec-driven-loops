# v1.0.1.3, Path Checks That Judge the Repository

`validate_catalog_package.py` now tells a correct path from a missing one. It uses the repository's own rules. A catalog that names a build output no longer fails. The same goes for a local runtime file. A typo or a broken link no longer slips through.

&nbsp;

## What's New at a Glance

- **A committed symlink is judged by its target.** A link with a missing target passes in one case. That target must be ignored by a tracked `.gitignore`, such as a build output. Any other dangling link is reported missing.
- **An ignored path that is absent is a note.** It prints as `ignored_path_absent`. It never changes a package's verdict or the exit code.
- **Only repository rules count.** Matches from `.git/info/exclude` no longer hide a missing path. The same goes for a personal excludes file. So every machine gets the same result.
