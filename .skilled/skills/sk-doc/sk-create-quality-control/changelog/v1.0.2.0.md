# v1.0.2.0 - Runnable commands and repaired cross-references

This release makes the documented quality-control commands runnable and repairs references that sent readers to the wrong `SKILL.md` sections. It changes no workflow, rule or standard.

## What's New at a Glance

- **The documented script invocations use `python3`.** The 18 script invocations changed from `python`, which is not on PATH in this environment and made every documented command exit `command not found`. This packet was the only one of the twelve `sk-doc` mode packets still using bare `python`.
- **`SKILL.md` uses repo-root-relative script paths.** It now uses `.opencode/skills/sk-doc/shared/scripts/<name>.py`, matching every sibling packet and this packet's own `README.md`. Previously, its `../shared/scripts/<name>.py` paths resolved only when the shell had already moved into the packet directory. The references now match as well.
- **Three recipes in `references/workflow-examples.md` now run.** Example 1 changed out of the repository root before using a path relative to it. The batch recipe passed `quick_validate.py` every directory under `.opencode/skills/`, including non-skills, while the spec example used `specs/042/spec.md`, a folder shape the spec tree does not use. All three are replaced with recipes that were executed before being written down.
- **`quick_validate.py` is for directories, not files.** `SKILL.md` §4 Step 6 said to run it `for the file`, and `references/validation-and-enforcement.md` assigned authored-name lowercase-kebab-case checks to it. It reads a skill or packet directory's `SKILL.md` and reports `SKILL.md not found` for a file path, while `check_authored_name_kebab.py` handles filename case. Both descriptions now state what the script does.
- **The `Validation not running` row points to §2.** It previously sent readers to §1, the overview, instead of the section where the checks live.
- **Seven references now use the correct `SKILL.md` section numbers.** Release `v1.0.1.0` renumbered the `SKILL.md` H2 sections from 2-7 to 3-8 and recorded that no intra-file cross-reference depended on the old numbers, which was true of `SKILL.md` but false of its five reference siblings. Pointers in `workflows.md`, `optimization.md`, `transformation-patterns.md`, `validation-and-enforcement.md` and `workflow-examples.md` now resolve, including the one that sent readers to `Interpret Quality Gates` at §3 Step 3 instead of the sixteen transformation patterns.
- **The four workflow mode names now match `SKILL.md`.** `references/workflows.md` used script-assisted review, structure checks, content optimization and audit snapshot, while `SKILL.md` §3 Step 1 used report-only audit, structure validation, content optimization and batch snapshot. As a routed leaf for the hub's `DOC_QUALITY` intent, `workflows.md` could leave an agent loading both files with two vocabularies for one decision, so it now uses the `SKILL.md` names.
- **Three reference titles drop the stale `Mode 1` labels.** `workflows.md` describes the numbered-mode scheme as replaced by `sk-doc` packets.
