# v1.0.2.0 - Runnable commands and repaired cross-references

**Released:** 2026-08-31

Every command this packet documented failed at the shell, and every reference file pointed at the wrong `SKILL.md` section. Both are fixed; no workflow, rule or standard changed.

## What Changed

#### Executable commands

- **Interpreter corrected to `python3`.** All 18 script invocations across `SKILL.md`, `README.md`, `references/workflows.md`, `references/validation-and-enforcement.md` and `references/workflow-examples.md` said `python`. That binary is not on PATH in this environment, so every documented command exited `command not found`. This packet was the only one of the twelve `sk-doc` mode packets still on the bare `python` form.
- **Script paths made repo-root relative.** `SKILL.md` addressed the shared scripts as `../shared/scripts/<name>.py`, which resolves only when the shell has already been moved into the packet directory. Every sibling packet, and this packet's own `README.md`, use `.opencode/skills/sk-doc/shared/scripts/<name>.py`. `SKILL.md` and the references now match.
- **`references/workflow-examples.md` recipes actually run.** Example 1 changed directory out of the repository root and then used a path relative to it; the batch recipe fed `quick_validate.py` every directory under `.opencode/skills/` including non-skills; the spec example used a folder shape (`specs/042/spec.md`) that the spec tree does not use. All three are replaced with recipes that were executed before being written down.

#### Corrected claims

- **`quick_validate.py` takes a directory, not a file.** `SKILL.md` §4 Step 6 told the reader to run it "for the file", and `references/validation-and-enforcement.md` described its action as validating authored names against lowercase kebab-case. Neither is true: it reads a skill or packet directory's `SKILL.md` and errors with `SKILL.md not found` on a file path, and filename case is `check_authored_name_kebab.py`'s job. Both descriptions now state what the script does.
- **Troubleshooting pointer fixed.** The "Validation not running" row sent readers to section 1, which is the overview; the checks live in section 2.

#### Cross-references

- **Every `SKILL.md` section reference shifted by one.** Release `v1.0.1.0` renumbered the `SKILL.md` H2 sections from 2-7 to 3-8 and recorded that no intra-file cross-reference depended on the old numbers. That was true of the file itself and false of its five reference siblings, which were left pointing one section low. A reader sent to §3 Step 3 for the sixteen transformation patterns landed on "Interpret Quality Gates" instead. Seven references across `workflows.md`, `optimization.md`, `transformation-patterns.md`, `validation-and-enforcement.md` and `workflow-examples.md` now resolve.

#### Vocabulary

- **One set of execution-mode names.** `references/workflows.md` named the four modes script-assisted review, structure checks, content optimization and audit snapshot, while `SKILL.md` §3 Step 1 named them report-only audit, structure validation, content optimization and batch snapshot. `workflows.md` is a routed leaf for the hub's `DOC_QUALITY` intent, so an agent could load both and carry two vocabularies for one decision. `workflows.md` now uses the `SKILL.md` names.
- **Stale "Mode 1" labelling removed.** Three reference titles still carried the pre-packet numbered-mode scheme that `workflows.md` itself describes as replaced by `sk-doc` packets.
