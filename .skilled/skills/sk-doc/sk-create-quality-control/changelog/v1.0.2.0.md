# v1.0.2.0 - Runnable commands and repaired cross-references

This release makes the documented quality-control commands runnable. It also repairs references that sent readers to the wrong `SKILL.md` sections. It changes no workflow, rule or standard.

## What's New at a Glance

- **The documented script invocations use `python3`.** The 18 script invocations changed from `python`. That name is not on PATH in this environment. It made every documented command exit `command not found`. This packet was the only one of the twelve `sk-doc` mode packets still using bare `python`.
- **`SKILL.md` uses repo-root-relative script paths.** It now uses `.opencode/skills/sk-doc/shared/scripts/<name>.py`. That matches every sibling packet and this packet's own `README.md`. Previously, its `../shared/scripts/<name>.py` paths resolved only inside the packet directory. The shell had to move there first. The references now match as well.
- **Three recipes in `references/workflow-examples.md` now run.** Example 1 changed out of the repository root. Then it used a path relative to that root. The batch recipe passed `quick_validate.py` every directory under `.opencode/skills/`, including non-skills. The spec example used `specs/042/spec.md`, a folder shape the spec tree does not use. All three are replaced with recipes that were executed before being written down.
- **`quick_validate.py` is for directories, not files.** `SKILL.md` §4 Step 6 said to run it `for the file`. `references/validation-and-enforcement.md` assigned authored-name lowercase-kebab-case checks to it. It reads a skill or packet directory's `SKILL.md`. For a file path it reports `SKILL.md not found`. `check_authored_name_kebab.py` handles filename case. Both descriptions now state what the script does.
- **The `Validation not running` row points to §2.** It previously sent readers to §1, the overview. That is not the section where the checks live.
- **Seven references now use the correct `SKILL.md` section numbers.** Release `v1.0.1.0` renumbered the `SKILL.md` H2 sections from 2-7 to 3-8. It recorded that no intra-file cross-reference depended on the old numbers. That was true of `SKILL.md` but false of its five reference siblings. Pointers in `workflows.md`, `optimization.md`, `transformation-patterns.md`, `validation-and-enforcement.md` and `workflow-examples.md` now resolve. One of them sent readers to `Interpret Quality Gates` at §3 Step 3. It should have sent them to the sixteen transformation patterns.
- **The four workflow mode names now match `SKILL.md`.** `references/workflows.md` used script-assisted review, structure checks, content optimization and audit snapshot. `SKILL.md` §3 Step 1 used report-only audit, structure validation, content optimization and batch snapshot. `workflows.md` is a routed leaf for the hub's `DOC_QUALITY` intent. So an agent loading both files could get two vocabularies for one decision. It now uses the `SKILL.md` names.
- **Three reference titles drop the stale `Mode 1` labels.** `workflows.md` describes the numbered-mode scheme as replaced by `sk-doc` packets.
