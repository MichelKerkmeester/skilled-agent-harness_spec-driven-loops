# v1.0.1.0 - Smart-routing section conformance

In `SKILL.md`, the merged `WHEN TO USE + SMART_ROUTING` heading made the packet read as missing its routing section. The section matcher tests headings by substring, and `SMART_ROUTING` did not contain the required `SMART ROUTING` token. This release separates the merged heading into distinct `## 1. WHEN TO USE` and `## 2. SMART ROUTING` sections so the packaging check recognizes the routing section.

## What's New at a Glance

- **The `sk-doc` dispatch boundary has its own section.** Family-boundary prose about dispatch within the `sk-doc` hub and advisor identity moved under `## 2. SMART ROUTING`. Activation triggers and skip criteria stay under `## 1. WHEN TO USE`.
- **The remaining H2 sections were renumbered contiguously.** HOW IT WORKS through REFERENCES shifted from 2-7 to 3-8. The old numbers were not used by intra-file cross-references. All prose, workflow steps, rules, success criteria and references are preserved unchanged, so this is a structural normalization only.
