The initial release of `create-quality-control` adds a workflow for auditing and optimizing existing Markdown documents in the `sk-doc` parent hub's ten-packet workflow-only architecture.

## What's New at a Glance

- **The audit scores document quality.** It extracts structure and metrics, then computes a Document Quality Index (DQI) score and quality band. It applies Human Voice Rules (HVR) for natural writing.
- **Choose a workflow mode.** Select a target Markdown document and choose report-only audit, structure validation, content optimization or batch snapshot. The workflow interprets blocking failures, warnings and recommendations, then reports findings.
- **Optimization targets the same document.** Only when explicitly requested, the workflow makes targeted improvements to the same document's structure, clarity and AI-friendliness. `SKILL.md` has a separate content-optimization path for question-answering transformation patterns when edits are in scope, and `references/optimization.md` gives full transformation-pattern examples and AI-friendly documentation heuristics for that path.
- **`references/workflows.md` gives extended mode examples.** It also covers phase interactions, batch patterns and troubleshooting for the core workflow.
- **The packet uses shared scripts and standards.** It has no packet-local `assets/` or `scripts/` directories. It runs the shared `../shared/scripts/extract_structure.py`, `validate_document.py` and `quick_validate.py`, and reads the shared `../shared/references/` standards (core standards, validation bands and HVR rules) rather than duplicating them locally.
