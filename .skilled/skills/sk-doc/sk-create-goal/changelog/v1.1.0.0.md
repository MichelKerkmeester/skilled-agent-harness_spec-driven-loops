Every goal now starts from a blank that already fits its kind, a top-level packet, a phase parent or a phase child, so an author rewrites less of the template by hand. The release also documents the checker's code folders and retires the references index.

> Spec folder: `specs/sk-doc/060-create-goal-mode/010-asset-templates-and-folder-readmes` (Level 2)

## What's New at a Glance

- **Three goal templates live in `assets/`.** `goal-top-level-template.md`, `goal-phase-parent-template.md` and `goal-phase-child-template.md` each hold system-spec-kit's goal template for that kind, with placeholders that say what the kind needs. Only the phase-parent template has the binding section.
- **The templates cannot drift from system-spec-kit.** A parity test compares each template's fixed text with system-spec-kit's goal template and fails on the first line that differs. It replaces the mode's old rule against keeping any local template copy.
- **The checker catches an unfilled template.** `check-goal.cjs` now reads the placeholder wording from all three templates, so an unfilled copy of any of them fails its placeholder check.
- **`/create:goal` fills the template for the goal's kind.** Both workflows start from the matching template instead of the inline renderer. A child that `create.sh --with-goal` scaffolded keeps its own file.
- **The checker's code folders have READMEs.** `scripts/` and `scripts/tests/fixtures/` now describe the checker, its entry points, its tests and the fixture packets.
- **The references index is gone.** The mode's router falls back to `parent-and-nested-goals.md`, and the `sk-doc` hub sends goal-authoring requests to the three templates.

## Upgrade

No migration required. Goals already written keep their structure, because the templates carry the same fixed text.
