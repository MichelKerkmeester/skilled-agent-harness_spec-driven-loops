The release gives `create-goal` a template for each kind of goal it writes, so an author starts from a blank that already fits a top-level packet, a phase parent or a phase child. It also documents the checker's code folders and retires the references index.

> Spec folder: `specs/sk-doc/060-create-goal-mode/010-asset-templates-and-folder-readmes` (Level 2)
> phase 10 of 10

## What's New at a Glance

- **Three goal templates live in `assets/`.** `goal-top-level-template.md`, `goal-phase-parent-template.md` and `goal-phase-child-template.md` each hold the system-spec-kit goal template for that kind, with placeholders that say what the kind needs. Only the phase-parent template has the binding section.
- **The templates cannot drift from system-spec-kit.** `template-parity.test.cjs` compares each template's fixed text with `goal.md.tmpl` at that template's level and fails on the first line that differs. This check replaces the mode's old rule against any local template copy.
- **The checker catches an unfilled template.** `check-goal.cjs` now reads the placeholder wording from the three templates as well as from `goal.md.tmpl`, so an unfilled copy of any of them fails the `placeholder` check. A scan of all 302 active goals gave the same report before and after the change. The suite now runs 15 tests.
- **`/create:goal` fills the template for the goal's kind.** Both workflow files, the presentation contract, `SKILL.md` and the workflow reference now start from the matching template instead of the inline renderer. A child that `create.sh --with-goal` scaffolded keeps its own file.
- **`scripts/` and `scripts/tests/fixtures/` have code READMEs.** They describe the checker, its entrypoints, its tests and the fixture packets, and both pass the code-folder validator.
- **`references/README.md` is gone.** The mode's router falls back to `parent-and-nested-goals.md`, and the sk-doc hub routes goal-authoring requests to the three templates instead. The compiled route was republished with 22 of 22 canary cases passing.

## Upgrade

No migration required. Goals already written keep their structure, because the templates carry the same fixed text.
