# v1.2.0.0, Sent Goals Carry Only Directives

A parent goal sent in chat now carries only its directive.

- The goal templates lost their author instructions.
- Those instructions used to ride along with every send.

One rule now says what a sent goal may contain. It lives in one place.

- That place is this mode.
- system-spec-kit's phase workflows also stop keeping their own copy of the goal rules.

They send goal authoring to `/create:goal`. So a rule changes in one file.

- A deep review of the change then tightened the budget rule. It also tightened the goal checker.
- It also tightened the goal CLI and `/create:goal` itself.

&nbsp;

## Why This Release

A parent goal sent in chat carried the template's author instructions. They went out with it. That was about a third of the text. This packet's own parent sent it.

- The rule for what a sent goal may contain was restated. Many files held it.
- The copies disagreed on the 4,000-character limit. Did it cap the stored goal or the sent one?
- system-spec-kit and speckit also kept their own cut order. They kept their own nesting rules.
- None of them named this mode.

## Sending a Goal in Chat

#### One Rule for What a Sent Goal Holds <a id="c-one-rule-for-what-a-sent-goal-holds"></a>

- The rule for a goal sent in chat used to be restated. Many files carried it.
- The copies disagreed on the 4,000-character limit. Which text did it cap?
- Section 4 of `references/budget-and-handoff.md` is now the one statement.
- A sent goal never carries frontmatter or HTML comments. It never carries anchor markers or `---` dividers.
- It never carries heading section numbers or author instructions.
- A goal goes out only at `packet_budget=ok`.
- The limit is measured on the durable slice.
- That is the goal text between its frontmatter and its log.
- `AGENTS.md` and system-spec-kit's `SKILL.md` now point to that section. They no longer restate it.
- So do the set-string playbook, the speckit workflows and the resend reminder.

#### Templates Without Author Instructions <a id="c-templates-without-author-instructions"></a>

- The blockquote, the Operator copy section and the criteria introduction are gone. They are gone from system-spec-kit's `goal.md.tmpl`.
- They are also gone from this mode's three templates.
- That text went out with every sent goal.
- A `GOAL_AUTHORING` comment sits in each template. It now points to this mode instead.
- The unfilled phase-parent template now measures 1,624 durable characters. That is down from 3,156.

#### One Cut Order for an Over-Budget Parent <a id="c-one-cut-order-for-an-overbudget-parent"></a>

- Section 3 of `budget-and-handoff.md` is now the full cut order.
- A new step 3 removes instructions. An older template left them behind.
- The set-string playbook and `validation-rules.md` point to it. The speckit workflows point to it too.
- So do this mode's README and both `/create:goal` workflows.
- They keep no copy.

## One Home for the Goal Rules

#### Phase Workflows Name /create:goal <a id="c-phase-workflows-name-creategoal"></a>

- system-spec-kit kept its own goal-nesting rules.
- None of its phase entry points named this mode.
- The speckit `:with-phases` step now sends goal authoring here. Option D in plan and complete does too.
- So do `phase-definitions.md` and `phase-system.md`.
- The quick reference and the `create.sh` help also send it here. The next steps do too.
- The inline-renderer recipe is gone from the set-string playbook.
- So a retrofit has one path: `/create:goal <packet> retrofit`.

#### Corrected Facts About Scaffolding <a id="c-corrected-facts-about-scaffolding"></a>

- The docs said `create.sh --phase --with-goal` writes a parent goal.
- It writes child goals only.
- `--level phase-parent --with-goal` writes the parent goal.
- The budget reference had a stale live figure in section 6. That figure is gone.
- The three templates' fixed-text cost replaced it.

## Safer Checks and Commands

#### One Budget Boundary <a id="c-one-budget-boundary"></a>

- Earlier releases said every phase child is exempt from the budget.
- That was wrong for a child. That child is itself a phase parent.
- The goal checker passed a nested phase parent. `goal.cjs packet` reported it over.
- Section 2 of `budget-and-handoff.md` now states one boundary.
- The cap applies to a top-level packet. It applies to every phase parent, nested or not.
- It exempts only a phase child. That child is not itself a phase parent.
- `check-goal.cjs` and `goal.cjs packet` now draw the same line.

#### A Fifth Check for Stray Fences <a id="c-a-fifth-check-for-stray-fences"></a>

- `check-goal.cjs` gains `frontmatter-fence`.
- It flags a `---` line left before the first heading.
- That line is the sign of an inner fence. That fence closed the frontmatter early.
- The authoring standards now forbid one inside frontmatter.

#### Goal Parsing That Cannot Stall <a id="c-goal-parsing-that-cannot-stall"></a>

- A goal file opened with many comments. It stalled every hook render.
- The match now finishes quickly. It takes time proportional to the file's length.
- The resend reminder stays on one line.
- A packet path may not exist yet. It is judged by where its real parent lands.

#### A Command That Refuses Bad Input <a id="c-a-command-that-refuses-bad-input"></a>

- `/create:goal` refuses a packet path outside its workspace.
- It treats packet prose as data rather than instructions.
- It hands off only after the goal checker passes.
- So an open finding ends the run without a chat slice.
- The goal CLI used to store `goal.cjs --help`. It stored it as an objective.
- It exited 0 on every failure.
- It now refuses the flag with `UNKNOWN_ACTION` and exits 1.

#### Scenarios That Match the Mode <a id="c-scenarios-that-match-the-mode"></a>

- The over-budget-parent cut scenario now grades the cut order. It grades all six steps.
- The leftover-placeholder refusal scenario seeds a placeholder. The asset template carries it.

## Upgrade Notes

Existing goals keep their text. The goal CLI exit status changes. So does the checker output.

#### Before You Start <a id="c-before-you-start"></a>

1. Each goal keeps its old author instructions. It keeps them until its next amendment or cut.
2. Step 3 of the cut order removes them then.
3. `AGENTS.md` overrides any resend wording they still carry.
