A parent goal sent in chat now carries only its directive. The goal templates lost the author instructions that used to ride along with every send, and the rule for what a sent goal may contain now lives in one place, in this mode.

system-spec-kit's phase workflows also stop keeping their own copy of the goal rules. They send goal authoring to `/create:goal`, so a rule changes in one file. A deep review of the change then tightened the budget rule, the goal checker, the goal CLI and `/create:goal` itself.

> Spec folder: `specs/sk-doc/060-create-goal-mode/012-goal-send-and-dedupe` (Level 2)

## Why This Release

A parent goal sent in chat carried the template's author instructions with it, about a third of the text this packet's own parent sent. The rule for what a sent goal may contain was restated in many files, and the copies disagreed on whether the 4,000-character limit capped the stored goal or the sent one. system-spec-kit and speckit also kept their own cut order and nesting rules, and none of them named this mode.

## What's New at a Glance

- **One rule says what a sent goal contains.** Frontmatter, comments, anchors, dividers, section numbers and author instructions never go out, and a goal is sent only when its budget reads ok.
- **The templates carry no author instructions.** The unfilled phase-parent template is about half its old size.
- **One cut order.** Section 3 of the budget reference holds the full order, and every other copy points to it.
- **system-spec-kit sends goal authoring here.** Its phase workflows, references and `create.sh` help name `/create:goal` instead of restating the rules.
- **One budget boundary.** The cap applies to every top-level packet and every phase parent, and it exempts only a phase child that is not itself a phase parent.
- **A fifth check.** The goal checker now catches a `---` line that closed the frontmatter too early.
- **A stricter command and CLI.** `/create:goal` refuses a path outside its workspace and hands off only after a clean check, and the goal CLI fails loudly instead of storing a stray flag.

## Sending a Goal in Chat

#### One Rule for What a Sent Goal Holds

The rule for a goal sent in chat used to be restated in many files, and the copies disagreed on which text the 4,000-character limit caps. Section 4 of `references/budget-and-handoff.md` is now the one statement. A sent goal never carries frontmatter, HTML comments, anchor markers, `---` dividers, heading section numbers or author instructions.

A goal goes out only at `packet_budget=ok`, and the limit is measured on the durable slice (the goal text between its frontmatter and its log). `AGENTS.md`, system-spec-kit's `SKILL.md`, the set-string playbook, the speckit workflows and the resend reminder now point to that section instead of restating it.

&nbsp;

#### Templates Without Author Instructions

The blockquote, the Operator copy section and the criteria introduction are gone from system-spec-kit's `goal.md.tmpl` and from this mode's three templates. That text went out with every sent goal. A `GOAL_AUTHORING` comment in each template now points to this mode instead.

The unfilled phase-parent template now measures 1,624 durable characters, down from 3,156.

&nbsp;

#### One Cut Order for an Over-Budget Parent

Section 3 of `budget-and-handoff.md` is now the full cut order. A new step 3 removes instructions an older template left behind. The set-string playbook, `validation-rules.md`, the speckit workflows, this mode's README and both `/create:goal` workflows point to it instead of keeping a copy.

## One Home for the Goal Rules

#### Phase Workflows Name /create:goal

system-spec-kit kept its own goal-nesting rules, and none of its phase entry points named this mode. The speckit `:with-phases` step, Option D in plan and complete, `phase-definitions.md`, `phase-system.md`, the quick reference and the `create.sh` help and next steps now send goal authoring here. The inline-renderer recipe is gone from the set-string playbook, so a retrofit has one path: `/create:goal <packet> retrofit`.

&nbsp;

#### Corrected Facts About Scaffolding

The docs said `create.sh --phase --with-goal` writes a parent goal. It writes child goals only, and `--level phase-parent --with-goal` writes the parent goal. The stale live figure in section 6 of the budget reference gave way to the three templates' fixed-text cost.

## Safer Checks and Commands

#### One Budget Boundary

Earlier releases said every phase child is exempt from the budget. That was wrong for a child that is itself a phase parent, and the goal checker passed a nested phase parent that `goal.cjs packet` reported over. Section 2 of `budget-and-handoff.md` now states one boundary: the cap applies to a top-level packet and to every phase parent, nested or not, and it exempts only a phase child that is not itself a phase parent. `check-goal.cjs` and `goal.cjs packet` now draw the same line.

&nbsp;

#### A Fifth Check for Stray Fences

`check-goal.cjs` gains `frontmatter-fence`, which flags a `---` line left before the first heading. That line is the sign that an inner fence closed the frontmatter early. The authoring standards now forbid one inside frontmatter.

&nbsp;

#### Goal Parsing That Cannot Stall

A goal file that opened with many comments stalled every hook render. The match now finishes in time proportional to the file's length. The resend reminder stays on one line, and a packet path that does not exist yet is judged by where its real parent lands.

&nbsp;

#### A Command That Refuses Bad Input

`/create:goal` refuses a packet path outside its workspace and treats packet prose as data rather than instructions. It hands off only after the goal checker passes, so an open finding ends the run without a chat slice. The goal CLI used to store `goal.cjs --help` as an objective and exit 0 on every failure. It now refuses the flag with `UNKNOWN_ACTION` and exits 1.

&nbsp;

#### Scenarios That Match the Mode

SCG-004 now grades the full six-step cut order, and SCG-005 seeds the placeholder the asset template carries.

## Upgrade Notes

- **Existing goals keep their text.** Each goal keeps its old author instructions until its next amendment or cut, and step 3 of the cut order removes them then. `AGENTS.md` overrides any resend wording they still carry.
- **Scripts that read the goal CLI's exit status.** `goal.cjs` now exits 1 on every failure, where it used to exit 0.
- **Pinned checker output.** A clean `check-goal.cjs` run now reads `5/5 checks`, where it read `4/4`.
