A parent goal sent in chat now carries only its directive. The goal templates lost their author instructions. Those instructions used to ride along with every send. The rule for what a sent goal may contain now lives in one place. That place is this mode.

system-spec-kit's phase workflows also stop keeping their own copy of the goal rules. They send goal authoring to `/create:goal`, so a rule changes in one file. A deep review of the change then tightened the budget rule and the goal checker. It also tightened the goal CLI and `/create:goal` itself.

## Why This Release

A parent goal sent in chat carried the template's author instructions with it. That was about a third of the text this packet's own parent sent. The rule for what a sent goal may contain was restated in many files. The copies disagreed on whether the 4,000-character limit capped the stored goal or the sent one. system-spec-kit and speckit also kept their own cut order and nesting rules. None of them named this mode.

## What's New at a Glance

- **One rule says what a sent goal contains.** Frontmatter, comments, anchors, dividers, section numbers and author instructions never go out. A goal is sent only when its budget reads ok.
- **The templates carry no author instructions.** The unfilled phase-parent template is about half its old size.
- **One cut order.** Section 3 of the budget reference holds the full order. Every other copy points to it.
- **system-spec-kit sends goal authoring here.** Its phase workflows, references and `create.sh` help name `/create:goal` instead of restating the rules.
- **One budget boundary.** The cap applies to every top-level packet and every phase parent. It exempts only a phase child that is not itself a phase parent.
- **A fifth check.** The goal checker now catches a `---` line that closed the frontmatter too early.
- **A stricter command and CLI.** `/create:goal` refuses a path outside its workspace. It hands off only after a clean check. The goal CLI fails loudly instead of storing a stray flag.

## Sending a Goal in Chat

#### One Rule for What a Sent Goal Holds

The rule for a goal sent in chat used to be restated in many files. The copies disagreed on which text the 4,000-character limit caps. Section 4 of `references/budget-and-handoff.md` is now the one statement. A sent goal never carries frontmatter, HTML comments, anchor markers or `---` dividers. It never carries heading section numbers or author instructions.

A goal goes out only at `packet_budget=ok`. The limit is measured on the durable slice. That is the goal text between its frontmatter and its log. `AGENTS.md` and system-spec-kit's `SKILL.md` now point to that section instead of restating it. So do the set-string playbook, the speckit workflows and the resend reminder.

&nbsp;

#### Templates Without Author Instructions

The blockquote, the Operator copy section and the criteria introduction are gone from system-spec-kit's `goal.md.tmpl`. They are also gone from this mode's three templates. That text went out with every sent goal. A `GOAL_AUTHORING` comment in each template now points to this mode instead.

The unfilled phase-parent template now measures 1,624 durable characters, down from 3,156.

&nbsp;

#### One Cut Order for an Over-Budget Parent

Section 3 of `budget-and-handoff.md` is now the full cut order. A new step 3 removes instructions an older template left behind. The set-string playbook, `validation-rules.md` and the speckit workflows point to it. So do this mode's README and both `/create:goal` workflows. They keep no copy.

## One Home for the Goal Rules

#### Phase Workflows Name /create:goal

system-spec-kit kept its own goal-nesting rules. None of its phase entry points named this mode. The speckit `:with-phases` step and Option D in plan and complete now send goal authoring here. So do `phase-definitions.md` and `phase-system.md`. The quick reference and the `create.sh` help and next steps also send it here. The inline-renderer recipe is gone from the set-string playbook. So a retrofit has one path: `/create:goal <packet> retrofit`.

&nbsp;

#### Corrected Facts About Scaffolding

The docs said `create.sh --phase --with-goal` writes a parent goal. It writes child goals only. `--level phase-parent --with-goal` writes the parent goal. The stale live figure in section 6 of the budget reference is gone. The three templates' fixed-text cost replaced it.

## Safer Checks and Commands

#### One Budget Boundary

Earlier releases said every phase child is exempt from the budget. That was wrong for a child that is itself a phase parent. The goal checker passed a nested phase parent that `goal.cjs packet` reported over. Section 2 of `budget-and-handoff.md` now states one boundary. The cap applies to a top-level packet and to every phase parent, nested or not. It exempts only a phase child that is not itself a phase parent. `check-goal.cjs` and `goal.cjs packet` now draw the same line.

&nbsp;

#### A Fifth Check for Stray Fences

`check-goal.cjs` gains `frontmatter-fence`. It flags a `---` line left before the first heading. That line is the sign that an inner fence closed the frontmatter early. The authoring standards now forbid one inside frontmatter.

&nbsp;

#### Goal Parsing That Cannot Stall

A goal file that opened with many comments stalled every hook render. The match now finishes in time proportional to the file's length. The resend reminder stays on one line. A packet path that does not exist yet is judged by where its real parent lands.

&nbsp;

#### A Command That Refuses Bad Input

`/create:goal` refuses a packet path outside its workspace. It treats packet prose as data rather than instructions. It hands off only after the goal checker passes. So an open finding ends the run without a chat slice. The goal CLI used to store `goal.cjs --help` as an objective. It exited 0 on every failure. It now refuses the flag with `UNKNOWN_ACTION` and exits 1.

&nbsp;

#### Scenarios That Match the Mode

The over-budget-parent cut scenario now grades the full six-step cut order. The leftover-placeholder refusal scenario seeds the placeholder the asset template carries.

## Upgrade Notes

- **Existing goals keep their text.** Each goal keeps its old author instructions until its next amendment or cut. Step 3 of the cut order removes them then. `AGENTS.md` overrides any resend wording they still carry.
- **Scripts that read the goal CLI's exit status.** `goal.cjs` now exits 1 on every failure. It used to exit 0.
- **Pinned checker output.** A clean `check-goal.cjs` run now reads `5/5 checks`. It used to read `4/4`.
