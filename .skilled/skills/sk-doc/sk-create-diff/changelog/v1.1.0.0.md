# v1.1.0.0, Functional Engine

This release turns `create-diff` from a preview-gated orchestration stub into a working, self-contained document diff mode. Skill-owned scripts carry the comparison engine with it, so the mode produces real before-and-after reports without waiting on an external package.

## Why This Release

Embedding the engine is a documented amendment to the original wrapper-only design (see `.opencode/specs/sk-doc/016-create-diff-mode/001-research-and-requirements/decision-record.md`, ADR-002). The mode works with zero install rather than relying on a separate portable npm package.

## What's New at a Glance

- **`scripts/create_diff.py` provides the comparison engine.** It uses the Python 3 standard library.
- **Extraction covers several document formats.** Plain text and Markdown are full fidelity, while HTML, DOCX and text-layer PDFs use format-specific extraction.
- **Binary input is refused with exit code `3`.** This covers binary office, media and archive formats and any file with binary content.
- **Comparisons offer baseline and explicit-pair paths.** The commands are `snapshot`, `compare` and `compare-pair`.
- **Comparison results are deterministic.** The output is organized by line.
- **Reports use accessible, self-contained HTML.** They support unified and side-by-side views with dark and light display.
- **The report receives a dedicated validation step.** `scripts/validate_report.py` asserts a report is safe and self-contained.
- **References and a runnable example accompany the mode.** They cover the workflow and demonstrate before-and-after comparison.
- **The release adds a feature catalog and a manual testing playbook.** They provide capability and manual validation material.
- **The skill documentation now describes the functional contract.** `SKILL.md` and `README.md` carry the updated mode guidance.

## Document Comparison

#### Format Extraction Sets Expectations

Plain text and Markdown are extracted at full fidelity. HTML and DOCX provide visible or structural text. Text-layer PDFs use `pdftotext`, `pypdf` or `pdfplumber` when available. Scanned and image-only PDF OCR remains out of scope. Each format has explicit fidelity tiers and warnings. Richer formats degrade honestly instead of guessing.

&nbsp;

#### Unsupported Inputs Are Declined

Examples of the refused binary office, media and archive formats include `.xlsx`, `.pptx`, `.png` and `.zip`. The mode avoids raw-byte "text" diffs that would produce meaningless reports. Unknown text-like extensions still fall back to text with a stated assumption.

&nbsp;

#### Baselines Keep Their Context

`snapshot` and `compare` use content-addressed baseline snapshots. `compare-pair` provides an explicit-pair fallback, while `status`, `cleanup` and `capabilities` are lifecycle commands.

&nbsp;

#### Diffs Show Local Changes

The engine creates line-level diffs with inline word-level highlighting. It also uses a cheap move heuristic.

## Reports

#### Reports Offer Two Views

The accessible HTML report uses no JavaScript and includes a restrictive CSP and escaped source content. `SOURCE_DATE_EPOCH` enables byte-reproducible output.

&nbsp;

#### Validation Ignores Escaped Text

`scripts/validate_report.py` checks for a doctype, `lang`, a CSP meta tag, zero `<script>` elements, no inline handlers and no remote references. It inspects real markup only, so escaped hostile text in document content does not cause a false positive.

## Guidance and Examples

#### References Cover the Workflow

`references/` contains capabilities and fidelity guidance, a workflow, a CLI reference and an accessibility contract. It also includes a worked example behind a route map, while `assets/fixtures/` holds a runnable before-and-after worked example.

&nbsp;

#### Catalogs Set Expectations

`feature-catalog/` is the canonical capability inventory, with a root `feature-catalog.md` and 8 per-feature files across 3 categories. It was authored to the create-feature-catalog template. `manual-testing-playbook/` is an operator-facing manual validation package, with a root `manual-testing-playbook.md` and 11 deterministic scenario files across 3 categories. It was authored to the create-manual-testing-playbook template.

## Skill Integration

#### Documentation Describes the Contract

`SKILL.md` and `README.md` were rewritten around the functional contract and no longer use the "engine pending" preview language. They add `INTEGRATION POINTS` and `RELATED RESOURCES`, align to the create-* canon and wire in the feature catalog and playbook.

&nbsp;

#### The Mode Has Two Routes

`/create:diff` remains optional and unbuilt. The mode routes through advisor aliases and direct script invocation. There is still no packet-local `graph-metadata.json` or `description.json`.
