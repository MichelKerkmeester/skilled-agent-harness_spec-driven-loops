# v1.1.0.0, Functional Engine

This release turns `create-diff` from a preview-gated orchestration stub into a working, self-contained document diff mode.

- Skill-owned scripts carry the comparison engine with it.
- So the mode produces real before-and-after reports without waiting on an external package.

The engine comes with the skill, and reports get a validation step.

- `scripts/create_diff.py` provides the comparison engine.
- It uses the Python 3 standard library.
- The report receives a dedicated validation step.

&nbsp;

## Why This Release

Embedding the engine is a documented amendment to the original wrapper-only design.

- See `.opencode/specs/sk-doc/016-create-diff-mode/001-research-and-requirements/decision-record.md`.
- That is the decision that surfaced the mode as a nested `sk-doc` mode.
- The mode works with zero install rather than relying on a separate portable npm package.

## Document Comparison

The engine extracts text from several formats, refuses binary input and keeps baseline snapshots.

#### Format Extraction Sets Expectations <a id="c-format-extraction-sets-expectations"></a>

- Extraction covers several document formats.
- Plain text and Markdown are extracted at full fidelity.
- HTML and DOCX provide visible or structural text.
- Text-layer PDFs use `pdftotext`, `pypdf` or `pdfplumber` when available.
- Scanned and image-only PDF OCR remains out of scope.
- Each format has explicit fidelity tiers and warnings.
- Richer formats degrade honestly instead of guessing.

#### Unsupported Inputs Are Declined <a id="c-unsupported-inputs-are-declined"></a>

- Binary input is refused with exit code `3`.
- This covers binary office, media and archive formats and any file with binary content.
- Examples of the refused binary office, media and archive formats include `.xlsx`, `.pptx`, `.png` and `.zip`.
- The mode avoids raw-byte "text" diffs that would produce meaningless reports.
- Unknown text-like extensions still fall back to text with a stated assumption.

#### Baselines Keep Their Context <a id="c-baselines-keep-their-context"></a>

- Comparisons offer baseline and explicit-pair paths.
- The commands are `snapshot`, `compare` and `compare-pair`.
- `snapshot` and `compare` use content-addressed baseline snapshots.
- `compare-pair` provides an explicit-pair fallback.
- `status`, `cleanup` and `capabilities` are lifecycle commands.

#### Diffs Show Local Changes <a id="c-diffs-show-local-changes"></a>

- `scripts/create_diff.py` provides the comparison engine.
- It uses the Python 3 standard library.
- The engine creates line-level diffs with inline word-level highlighting.
- It also uses a cheap move heuristic.
- Comparison results are deterministic.
- The output is organized by line.

## Reports

Reports render as accessible HTML and get a dedicated validation step.

#### Reports Offer Two Views <a id="c-reports-offer-two-views"></a>

- Reports use accessible, self-contained HTML.
- They support unified and side-by-side views with dark and light display.
- The accessible HTML report uses no JavaScript.
- It includes a restrictive CSP and escaped source content.
- `SOURCE_DATE_EPOCH` enables byte-reproducible output.

#### Validation Ignores Escaped Text <a id="c-validation-ignores-escaped-text"></a>

- The report receives a dedicated validation step.
- `scripts/validate_report.py` asserts a report is safe and self-contained.
- `scripts/validate_report.py` checks for a doctype, `lang` and a CSP meta tag.
- It also checks for zero `<script>` elements.
- It checks for no inline handlers and no remote references.
- It inspects real markup only.
- So escaped hostile text in document content does not cause a false positive.
