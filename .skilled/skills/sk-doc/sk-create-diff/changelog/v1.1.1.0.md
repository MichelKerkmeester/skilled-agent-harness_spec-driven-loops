# v1.1.1.0 - Multi-file Boundary Dividers

Aggregate before/after reports now make every file transition unmistakable.

## What's New at a Glance

- **Aggregate pairs need matching file envelopes.** Strict validation needs at least two file envelopes in pre-composed aggregate pairs. Each must be unique, ordered and path-matched. Malformed or incidental marker text follows the ordinary document path.
- **File markers become semantic start and end bands.** Validated markers render as full-width `START FILE` and `END FILE` row groups in unified and side-by-side reports. They use the existing safe HTML dialect and design tokens. They replace ordinary context lines.
- **Collapsed context keeps recognized boundaries.** Every recognized boundary survives collapsed context. This holds even when long unchanged runs collapse.
- **Later files have a visual gap.** A 32px canvas-colored gap appears before each file after the first. The gap is accessibility-inert. It masks the frame edges beside the whitespace. So start bands no longer attach to the preceding diff.
- **Markdown headings stay within their file.** Section context resets at file transitions. So one file's heading cannot label the next file's changes.
- **Multi-file review uses aggregate inputs.** The CLI still compares one before document with one after document. Native directory comparison stays out of scope. So do repeated multi-file CLI arguments.
- **Snapshot behavior and diff statistics are unchanged.** Extraction fidelity is unchanged too. So are the CSP and command assets.

No migration required.
