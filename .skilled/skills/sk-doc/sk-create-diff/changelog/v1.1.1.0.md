# v1.1.1.0 - Multi-file Boundary Dividers

Aggregate before/after reports now make every file transition unmistakable.

## What's New at a Glance

- **Aggregate pairs require matching file envelopes.** Strict validation requires at least two unique, ordered and path-matched file envelopes in pre-composed aggregate pairs. Malformed or incidental marker text follows the ordinary document path.
- **File markers become semantic start and end bands.** Validated markers render as full-width `START FILE` and `END FILE` row groups in unified and side-by-side reports, using the existing safe HTML dialect and design tokens instead of ordinary context lines.
- **Collapsed context keeps recognized boundaries.** Every recognized boundary is preserved through collapsed context, even when long unchanged runs collapse.
- **Later files have a visual gap.** A 32px canvas-colored, accessibility-inert gap appears before each file after the first. It masks the frame edges beside the whitespace so start bands no longer attach to the preceding diff.
- **Markdown headings stay within their file.** Section context resets at file transitions, so one file's heading cannot label the next file's changes.
- **Multi-file review uses aggregate inputs.** The CLI still compares one before document with one after document. Native directory comparison and repeated multi-file CLI arguments remain out of scope.
- **Snapshot behavior and diff statistics are unchanged.** Extraction fidelity, the CSP and command assets are also unchanged.

No migration required.
