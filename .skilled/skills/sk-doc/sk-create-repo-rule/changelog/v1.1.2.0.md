# v1.1.2.0, The Router Link Resolves and the Counts Go

The template told authors to link the router as `../REPO%20RULES.md`, which resolves from a root `repo-rules/` folder but not from `.skilled/repo-rules/`, where rules actually live. It now gives `../../REPO%20RULES.md` for that folder and keeps the short form for a root folder. The references also stop stating how many rules share each element, because `check-repo-rules.cjs` counts them on the live corpus.

> Spec folder: `specs/sk-code/015-quality-agnostic-gate` (Level 2)

&nbsp;

## What's New at a Glance

- **A new rule links to the router correctly.** The routed-from line and the back-link both resolve from the folder the rule sits in.
- **The references cannot go stale.** They point at the checker for counts instead of quoting numbers.
- **The index requirement is stated plainly.** The trigger row and the index row are required, and the governed-section pointer is the default.

&nbsp;

## Upgrade

A rule written from the old template under `.skilled/repo-rules/` should change its routed-from and back-links to `../../REPO%20RULES.md`.
