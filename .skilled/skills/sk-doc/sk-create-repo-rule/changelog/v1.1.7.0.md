# v1.1.7.0, Tests, Elements and Checks Read as Lists

The packet's `SKILL.md`, `ROUTER.md`, `README.md` and references were read file by file for readability, layout and structure. Text moved and split, and every claim was kept. No command, contract or template behavior changed.

> Spec folder: `specs/sk-doc/066-skill-readability-refinement/008-sk-doc` (Level 1)

&nbsp;

## What's New at a Glance

- **The decision tests read one per line.** The README lists Test 1 to Test 4 as bold-led bullets, then the ten fixed elements a rule fills, from six-key frontmatter to the link back to the router.
- **The packet lists its files.** `SKILL.md` now lists the four references and two assets with what each holds, `ROUTER.md` names its two resource families, and the README document table gained `ROUTER.md` and `references/README.md`.
- **The corpus checks are itemized.** The rule-anatomy reference lists the checker's eleven checks one per bullet, and its overview gained a Purpose and a When to Use.
- **References say when to open them.** The index, wiring, creation-standards and decision-tests references each gained a When to Use, and the wiring reference splits its pointer rules into two cases.
- **Router order is stated where it applies.** The wiring reference now says a repository with no `REPO RULES.md` gets its router emitted first, and rule-anatomy section 5 is now titled "Inter-Rule Cross-References".
