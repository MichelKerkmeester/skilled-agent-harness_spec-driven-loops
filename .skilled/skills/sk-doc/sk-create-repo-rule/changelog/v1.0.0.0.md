The first release adds `create-repo-rule`. It is a workflow packet in the `sk-doc` parent hub. It gives requested behavior and recurring failures a route into repository guidance. The spec folder has seven phases.

> Spec folder: `specs/sk-doc/040-create-repo-rules` (Level 2)

## What's New at a Glance

- **Rules live in `repo-rules/` and connect to `REPO RULES.md`.** `create-repo-rule` also revises and retires them. A repo rule supplements the `harness` rather than binding it. A live operator instruction can override a rule. A rule can change when it stops matching the work. It can be removed when it stops earning its load.
- **Four decision tests refuse most requests.** They cover Always-loaded, scope boundary, a four-part refusal test and restraint. Each refusal names the test it failed. It also names where the content belongs instead.
- **The rule template derives from the corpus instead of copying it.** Ten elements are fixed. That is because all eight shipped rules carry them. The numbered body is open. That is because section count follows the subject.
- **A router template is emitted as a prerequisite when a repository has no trigger table.** The router shares almost no structure with the rules it routes to. So it is a separate template rather than a variant.
- **Creation standards add five reader tests.** They decide whether a structurally correct rule is worth loading.
- **The integration and lifecycle contract protects interrupted changes.** It defines three wiring points. It also defines create, revise and retire orderings. They are chosen so stopping halfway always leaves an unreferenced file, not a router row pointing at nothing.
- **`/create:repo-rule` supports auto and confirm workflows.** It includes a presentation contract. `retire` defaults to confirm even with an auto suffix. That is because it deletes a file and removes two router rows.
- **Rule length bands are operator-set.** The maximum is 250. A length of 200 is good. 160 or lower is preferred, including frontmatter.
- **Generated rules default to zero sideways cross-references.** The reference corpus carries four across eight files. So the rules are nearly independent.
- **The common refusal path works, but the accept path has not run end to end.** The refusal path names destinations. The accept path is built and structurally proven in parts. A five-iteration review saturated the reference set. It returned zero warranted new rules. So no genuine accept case exists in this repository yet.
