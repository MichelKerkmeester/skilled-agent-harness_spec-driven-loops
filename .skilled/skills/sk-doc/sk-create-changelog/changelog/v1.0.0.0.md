The initial release gives the `sk-doc` family the dedicated changelog-authoring contract it lacked. `create-changelog` is one of ten workflow packets. They sit in the `sk-doc` parent hub. That hub uses a workflow-only architecture.

It turns a spec folder, component hint or recent git history into one of two outputs. The output is either a global component changelog or a packet-local nested changelog.

## What's New at a Glance

- **The inline `SKILL.md` workflow defines seven steps.** It analyzes context and resolves the output target. It determines the version and generates content. Then it validates, writes and reports. It also detects whether output is global or packet-local. It defines activation triggers and required inputs. It sets the format contract and validation checks. It also sets always, never and escalate rules.
- **Global changelogs use four-part versioned paths.** `create-changelog` dynamically discovers components under `.opencode/changelog/`. It writes global entries to `.opencode/changelog/{component}/v{VERSION}.md`. Those paths use four-part semantic versioning. It creates packet-local nested changelogs through the spec-kit nested generator.
- **Version-bump detection covers auto, major, minor, patch and build.** The shared changelog template drives the choice of compact or expanded format. Both output types are formatted from it.
- **Examples cover both global and packet-local output.** `references/changelog_creation.md` gives worked examples and edge cases for both. `README.md` gives a packet overview and a quick start.
- **No `assets/` or `scripts/` ship in the packet.** The packet reuses the shared template at `../shared/assets/changelog-template.md`. It also reuses shared validators under `../shared/scripts/`.
