The initial release gives the `sk-doc` family the dedicated changelog-authoring contract it lacked. As one of the ten workflow packets in the `sk-doc` parent hub's workflow-only architecture, `create-changelog` turns a spec folder, component hint or recent git history into either a global component changelog or a packet-local nested changelog.

> Spec folder: `.opencode/specs/skilled-agent-orchestration/125-sk-doc-parent` (Level 3)

## What's New at a Glance

- **The inline `SKILL.md` workflow defines seven steps.** It analyzes context, resolves the output target, determines the version, generates content, validates, writes and reports. It also detects whether output is global or packet-local and defines activation triggers, required inputs, the format contract, validation checks and always/never/escalate rules.
- **Global changelogs use four-part versioned paths.** `create-changelog` dynamically discovers components under `.opencode/changelog/` and writes global entries to `.opencode/changelog/{component}/v{VERSION}.md` with four-part semantic versioning. It creates packet-local nested changelogs through the spec-kit nested generator.
- **Version-bump detection covers auto, major, minor, patch and build.** The shared changelog template drives selection of compact or expanded format, and both output types are formatted from it.
- **Examples cover both global and packet-local output.** `references/changelog_creation.md` provides worked examples and edge cases for both. `README.md` provides a packet overview and quick start.
- **No `assets/` or `scripts/` ship in the packet.** The packet reuses the shared template at `../shared/assets/changelog-template.md` and shared validators under `../shared/scripts/`.

## Upgrade

No migration required. This is the packet's initial release.
