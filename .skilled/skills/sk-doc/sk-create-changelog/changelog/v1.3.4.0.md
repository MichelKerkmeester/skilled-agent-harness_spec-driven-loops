# v1.3.4.0, One Number Across Branches and One Bump Across Files

`/create:changelog` now picks a version no other branch has already taken, and it leaves the skill's version copies agreeing with the entry it writes. Two branches that each numbered from their own checkout used to choose the same version and collide at merge, and a hub's version lived in up to five files that a hand bump could leave behind.

> Spec folder: `specs/sk-code/011-sk-code-poinytail-based-refinement/014-skill-authoring-ux-research/005-changelog-single-bump` (Level 1)

&nbsp;

## What's New at a Glance

- **Numbering reads upstream too.** The version step lists the entries on the branch's upstream, or `origin/main`, with `git ls-tree`, takes the highest of both lists and skips any number taken on either side. Without a reachable upstream it numbers locally and says so.
- **One bump moves every copy.** After writing the entry, the workflow sets the new version in each carrier the skill root already has: `SKILL.md`, `ROUTER.md`, `description.json`, `hub-router.json` and `mode-registry.json`. `README.md` keeps its own document version.
- **A hub is checked before the step ends.** The workflow runs `parent-skill-check.cjs` on a hub and stops when a version copy still disagrees.

&nbsp;

## Upgrade

No migration required. Existing entries and versions stay as they are.
