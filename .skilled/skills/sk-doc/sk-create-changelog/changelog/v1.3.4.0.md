# v1.3.4.0, One Number Across Branches and One Bump Across Files

`/create:changelog` now picks a version no other branch has already taken. It also leaves the skill's version copies agreeing with the entry it writes. Two branches each numbered from their own checkout. They used to pick the same version and collide at merge. A hub's version lived in up to five files. A hand bump could leave them behind.

&nbsp;

## What's New at a Glance

- Numbering reads upstream too.
  - The version step lists the entries on the branch's upstream, or `origin/main`, with `git ls-tree`.
  - The version step takes the highest of both lists.
  - The version step skips any number taken on either side.
  - Without a reachable upstream it numbers locally and says so.
- One bump moves every copy.
  - The workflow writes the entry first.
  - Then it sets the new version in each carrier the skill root already has: `SKILL.md`, `ROUTER.md`, `description.json`, `hub-router.json` and `mode-registry.json`.
  - `README.md` keeps its own document version.
- A hub is checked before the step ends.
  - The workflow runs `parent-skill-check.cjs` on a hub.
  - The workflow stops when a version copy still disagrees.

&nbsp;

## Upgrade

No migration required. Existing entries and versions stay as they are.
