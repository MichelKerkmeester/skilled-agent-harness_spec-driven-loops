# v1.2.0.0, A Release Line of Its Own

The changelog workflow gains a release line for the Skilled framework, named by the operator and never guessed from a changed file. Components now match by whole path segment. Only that line publishes a tag and GitHub release, so a component version can never become a repository tag.

> Spec folder: `specs/sk-doc/061-skilled-release-changelog/001-release-line-split` (Level 2)

## What's New at a Glance

- **A framework release line.** `.skilled/changelog/skilled/` holds one entry per Skilled release, and the workflow writes there only when the operator names `skilled`.
- **Components match by whole path segment.** A changed path resolves to the folder whose name equals one of its segments, never to a name that is merely a substring, and a path never selects `skilled`.
- **Only the release line publishes.** `--release` tags and publishes for `skilled` alone. Any other component keeps its changelog and skips the tag, because a component version must never become a repository tag.
- **Releases carry their editorial title.** The GitHub release is titled with its tag followed by the entry's editorial title.
- **The version reader sees generation folders.** It lists the entries at a folder's top level and in `v1+/`, `v2+/` and so on, never in a mode folder, so a folder whose newest entries were grouped still resolves its latest version.
- **The exemplar has a new home.** The canonical exemplar is `.skilled/changelog/skilled/v4.0.0.0.md`.
- **Three playbook scenarios cover the release line.** CHG-008 to CHG-010 check naming `skilled`, path-segment matching and the skipped release.

## Upgrade

Run `/create:changelog skilled` to write a framework release entry. `--release` on any other component now skips the tag and the GitHub release, and the changelog file stays written.
