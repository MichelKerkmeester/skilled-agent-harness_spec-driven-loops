# v1.2.0.0, A Release Line of Its Own

The changelog workflow gains a release line for the Skilled framework. The operator names it. It is never guessed from a changed file. Components now match by whole path segment. Only that line publishes a tag and GitHub release. So a component version can never become a repository tag.

## What's New at a Glance

- **A framework release line.** `.skilled/changelog/skilled/` holds one entry per Skilled release. The workflow writes there only when the operator names `skilled`.
- **Components match by whole path segment.** A changed path resolves to the folder whose name equals one of its segments. It never resolves to a name that is merely a substring. A path never selects `skilled`.
- **Only the release line publishes.** `--release` tags and publishes for `skilled` alone. Any other component keeps its changelog and skips the tag. That is because a component version must never become a repository tag.
- **Releases carry their editorial title.** The GitHub release is titled with its tag, then the entry's editorial title.
- **The version reader sees generation folders.** It lists the entries at a folder's top level and in `v1+/`, `v2+/` and so on. It never lists them in a mode folder. So a folder whose newest entries were grouped still resolves its latest version.
- **The exemplar has a new home.** The canonical exemplar is `.skilled/changelog/skilled/v4.0.0.0.md`.
- **Three playbook scenarios cover the release line.** They check that a Skilled release entry routes to that line. They check that a changed path never infers it. They check that any other component skips the release.

## Upgrade

Run `/create:changelog skilled` to write a framework release entry. `--release` on any other component now skips the tag and the GitHub release. The changelog file stays written.
