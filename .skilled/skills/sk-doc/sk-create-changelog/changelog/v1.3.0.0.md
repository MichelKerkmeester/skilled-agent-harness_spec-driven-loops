# v1.3.0.0, Entries That Search Can Find

A changelog entry is now as easy to find as a spec document. Every entry the workflow writes opens with a frontmatter block of search metadata. So a reader who asks for a component and version reaches that entry. A reader who asks for the change itself reaches it too.

## What's New at a Glance

- **Every entry opens with search metadata.** The block carries `title`, `description`, `trigger_phrases`, `importance_tier` and `contextType` in that order. These are the five keys a spec document carries.
- **Identity phrases come from the entry's path.** A skill entry declares `<component> v<version>` and `<component> <version>`. A Skilled release entry declares `v<version> release notes` and `skilled v<version>`.
- **Topic phrases name what changed.** One or two short phrases in the entry's own words find it. They help a reader who does not know its version.
- **The whole workflow writes the block.** The template's two skeletons and the worked example now include it. So do both `/create:changelog` workflows and the format checks.
- **Two playbook scenarios cover it.** They check the block on a global entry. They also check the identity phrase the nested generator writes into a packet-local entry.

## Upgrade

No migration required. Existing entries received their metadata in the same change. And `validate_document.py` now reports an entry that lacks it.
