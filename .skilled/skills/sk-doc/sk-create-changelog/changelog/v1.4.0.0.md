# v1.4.0.0, Long Releases Come Out Short

A release with many changes used to produce an entry. The entry had no length limit. That is because the template set its ceilings at one entry. The 535-line v4.0.0.0 entry set them. The expanded format now has ceilings of its own. They are modeled on the shorter v4.0.1.0 release entry. A shape gate stops a draft that runs past them. It stops the draft before it is written.

&nbsp;

## What's New at a Glance

- An expanded entry has a ceiling.
  - The entry runs at most 240 lines below its frontmatter.
  - The entry has at most 26 items.
  - Each item is one paragraph, or two for a breaking change.
- Two entries model the format.
  - v4.0.1.0 sets the length, the selection and the section shape.
  - v4.0.0.0 still sets the voice and the opening of a major release.
- Small fixes share one list.
  - A reader would notice some fixes, but they need no paragraph.
  - Each goes into an optional Smaller Fixes item at the end of its section.
- Upgrade notes follow the sections.
  - Each note opens with the reader's situation.
  - The note sits in section order, in place of the Adopt, Repoint and Drop lead-ins.
- Glance bullets name their section.
  - Each expanded glance bullet carries a section tag.
  - So the gate can check that the list follows the body.
- A shape gate stops long drafts.
  - `check_changelog_shape.py` fails a draft past a ceiling.
  - `check_changelog_shape.py` fails an out-of-order glance list.
  - `check_changelog_shape.py` fails a spec-folder line with a level label.
  - `/create:changelog` runs it before writing.

&nbsp;

## Upgrade

No migration required. Entries already published are not checked again.
