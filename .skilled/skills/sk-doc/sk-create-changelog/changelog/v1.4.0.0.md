# v1.4.0.0, Long Releases Come Out Short

A release with many changes used to produce an entry with no length limit, because the template set its ceilings at whatever the 535-line v4.0.0.0 entry did. The expanded format now has ceilings of its own, modeled on the shorter v4.0.1.0 release entry, and a shape gate stops a draft that runs past them before it is written.

> Spec folder: `specs/sk-doc/055-changelog-system/005-concise-release-format`

&nbsp;

## What's New at a Glance

- **An expanded entry has a ceiling.** It runs at most 240 lines below its frontmatter and 26 items, and each item is one paragraph, or two for a breaking change.
- **Two entries model the format.** v4.0.1.0 sets the length, the selection and the section shape, and v4.0.0.0 still sets the voice and the opening of a major release.
- **Small fixes share one list.** A fix a reader would notice, but that needs no paragraph, goes into an optional Smaller Fixes item at the end of its section.
- **Upgrade notes follow the sections.** Each note opens with the reader's situation and sits in section order, in place of the Adopt, Repoint and Drop lead-ins.
- **Glance bullets name their section.** Each expanded glance bullet carries a section tag, so the gate can check that the list follows the body.
- **A shape gate stops long drafts.** `check_changelog_shape.py` fails a draft past a ceiling, an out-of-order glance list or a spec-folder line with a level label, and `/create:changelog` runs it before writing.

&nbsp;

## Upgrade

No migration required. Entries already published are not checked again.
