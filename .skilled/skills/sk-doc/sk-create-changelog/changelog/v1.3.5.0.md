# v1.3.5.0, A Hub ROUTER.md Keeps Its Own Version

A hub `ROUTER.md` carries its own document version, so `/create:changelog` no longer writes the release version into it. This reverses v1.3.4.0, which listed a hub `ROUTER.md` among the files a release updates.

> Spec folder: `specs/sk-code/011-sk-code-poinytail-based-refinement/026-external-surface-priority-build/004-router-version-parity` (Level 2)

&nbsp;

## What's New at a Glance

- **A hub `ROUTER.md` is left alone.** The global version step drops it from the list of files a release updates, in the workflow contract and in both command files, so a hub's router keeps the version it already carries.
- **Four carriers still move.** `SKILL.md`, `description.json`, `hub-router.json` and `mode-registry.json` are set to the new version, and `README.md` keeps its own document version as before.

&nbsp;

## Upgrade

No migration required. A hub `ROUTER.md` keeps the version it carries today.
