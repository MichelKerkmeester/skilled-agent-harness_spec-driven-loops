# v1.5.0.0, Release Notes That Explain and Prove Themselves

The v4.0.2.1 notes took four requests to get right. The first draft was thin. The second had long sentences. The published release then had to be republished twice. Each of those is now the default, so nobody has to ask.

> Spec folder: `specs/sk-doc/authoring-modes-and-playbooks/006-release-writing-defaults`

&nbsp;

## What's New at a Glance

- **A feature says how it works.** Each new feature gets its steps and one real line of output.
- **Every fix is named.** A fix a reader could run into gets its own bullet.
- **An expanded entry shows its proof.** `## How It Was Checked` holds a before-and-after table and each suite's result.
- **Sentences are short.** The shape check fails a sentence past 22 words or an average above 10.
- **A published release follows its entry.** An edit to a published entry updates the release body in the same run.
- **The release link is always reported.** When nothing is published the report names the `--release` flag.
- **Moving a tag still needs a yes.** The skill recommends it and asks once, with the old tag object named.

&nbsp;

## Upgrade

No migration required. Entries written before v4.0.2.1 fail the sentence rules, and nothing reruns the check on them.
