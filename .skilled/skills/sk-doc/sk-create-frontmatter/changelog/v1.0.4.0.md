# v1.0.4.0, The Packet's Own Descriptions Parse as YAML

This packet writes the rules other documents follow. Two of its own pages broke one. The workflow file and the versioning reference each carried a description. Each value had a colon in the middle. A strict YAML parser reads that as the start of a nested mapping. Both values are now quoted. They read as they did.

&nbsp;

## What's New at a Glance

- The contract now holds on the packet that states it.
  - Both descriptions keep their wording.
  - So the field list and the description budget use the same words.
- A parser reads the block, not a tolerance for colons.
  - A strict reader accepts the two files.
  - So does the validator's new blocking check.
