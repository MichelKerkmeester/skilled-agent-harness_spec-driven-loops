# v1.0.4.0, The Packet's Own Descriptions Parse as YAML

This packet writes the rules other documents follow, and two of its own pages broke one. The workflow file and the versioning reference each carried a description with a colon in the middle of the value, which a strict YAML parser reads as the start of a nested mapping. Both values are now quoted and read as they did.

> Spec folder: `specs/sk-code/017-portable-code-modes/015-frontmatter-yaml-validity` (Level 2)

&nbsp;

## What's New at a Glance

- **The contract now holds on the packet that states it.** Both descriptions keep their wording, so the field list and the description budget are described in the same words.
- **A parser reads the block, not a tolerance for colons.** The two files are accepted by a strict reader and by the validator's new blocking check.
