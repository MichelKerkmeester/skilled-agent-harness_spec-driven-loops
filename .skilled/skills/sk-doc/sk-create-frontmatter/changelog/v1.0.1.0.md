The `contextType` and `importance_tier` lists now live in this mode, in `assets/frontmatter-values.json`, and the contract says their aliases are legal. A value outside the list warns in spec-kit and sk-doc and fails the skill-advisor checker.

> Spec folder: `specs/system-speckit/050-open-knowledge-format-adoption/003-context-type-unification` (Level 2)

## What's New at a Glance

- **Aliases are legal.** Values such as `review` for `research` and `high` for `important` pass, though new docs should write the canonical value.
- **This mode holds the lists.** `assets/frontmatter-values.json` carries the document `contextType` values, the tiers and their aliases. spec-kit, sk-doc and the skill advisor all read it, and the contract points at it instead of repeating the values.

## Upgrade

No migration required.
