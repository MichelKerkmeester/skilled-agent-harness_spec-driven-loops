# v1.0.9.0, Field Rules Read One per Line

The packet's `README.md`, `ROUTER.md`, templates asset and versioning reference were read file by file for readability, layout and structure. Text moved and split, and every claim was kept. No command, contract or template behavior changed.

> Spec folder: `specs/sk-doc/066-skill-readability-refinement/008-sk-doc` (Level 1)

&nbsp;

## What's New at a Glance

- **The README says why frontmatter matters in a list.** What routes on `trigger_phrases`, what discovery drops and what fails a corpus gate are three bullets, and the description trim rules are three more.
- **The router lists what reaches it.** `ROUTER.md` names five request types as bullets, then its two resources, the templates asset that loads on every path and the versioning reference that loads only for `version` questions.
- **The templates asset opens with its purpose.** It gained a Purpose and a Usage note, and the decision tree for which block a document gets moved up to sit beside them.
- **Per-class requirements are itemized.** The extra fields for references and assets, changelogs, feature catalogs, playbooks and agents each have their own bullet, and the frontmatter checker's two limits read as two bullets.
- **The versioning reference says when to open it.** Its overview gained a Purpose and a When to Use, and the before and after budget example no longer cites a packet number.
