# v1.0.9.0, Field Rules Read One per Line

The packet's `README.md`, `ROUTER.md`, templates asset and versioning reference were read file by file. The reading covered readability, layout and structure. Text moved and split. Every claim was kept. No command, contract or template behavior changed.

&nbsp;

## What's New at a Glance

- **The README says why frontmatter matters in a list.** Three bullets cover what routes on `trigger_phrases`, what discovery drops and what fails a corpus gate. The description trim rules are three more bullets.
- **The router lists what reaches it.** `ROUTER.md` names five request types as bullets. Then it names its two resources. One is the templates asset, which loads on every path. The other is the versioning reference, which loads only for `version` questions.
- **The templates asset opens with its purpose.** It gained a Purpose and a Usage note. The decision tree moved up to sit beside them. It covers which block a document gets.
- **Per-class requirements are itemized.** The extra fields for references and assets, changelogs, feature catalogs, playbooks and agents each have their own bullet. The frontmatter checker's two limits read as two bullets.
- **The versioning reference says when to open it.** Its overview gained a Purpose and a When to Use. The before and after budget example no longer cites a packet number.
