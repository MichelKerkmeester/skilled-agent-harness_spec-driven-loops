`create-frontmatter` gives the YAML frontmatter contract an owning mode and connects it through both routing stages. Six sibling packets emit frontmatter. Every one of their templates defers to the same specification.

## Why This Release

The hub's shared tier let any mode read the specification but left none accountable for it. A contract that many producers read and no producer owns gets edited by whoever passes and drifts from the validators enforcing it. This is the third correction of that ownership pattern in the hub and the largest.

## What's New at a Glance

- **The complete references move into `create-frontmatter`.** Both documents move as whole units. Every consumer is repointed to the specification.
- **The mode is routed, not just registered.** The advisor selects the hub. The hub router selects this mode.
- **Every route keyword is qualified.** The bare `frontmatter` keyword is not used.
- **A manual testing playbook ships with the mode.** It holds eleven operator scenarios.
- **The mode owns the rules while enforcement stays shared.** The enforcement scripts stay in `shared/scripts/`.
- **The move adds no hub alias.** The alias table is byte-identical to before the move.
- **Historical wording is retained.** The `v1.8.0.0` entry and three dated benchmark report bundles keep their wording.
- **The changelog template link is repointed.** Hub link failures went from 113 to 112.

## Frontmatter Contract

#### Two Complete References

`assets/frontmatter-templates.md` carries the eleven-section field reference, per-class templates, the description budget and common fixes. `references/frontmatter-versioning.md` carries the 4-part `X.Y.Z.W` standard: scope, format, changelog-anchored derivation, the numstat gate and the insertion rule. Neither document splits because no section of either has a second constituency.

---

## Routing

#### Two Stages Select Different Targets

For a frontmatter request, the advisor selects the hub at confidence 0.95. The hub router then selects this mode from a lone target.

&nbsp;

#### Registration Is Only the Start

A registry entry alone is not a route. The mode carries its registry entry, hub vocabulary, router intents, resource map and leaf-manifest entries.

&nbsp;

#### Qualified Keywords Protect Routes

`agent-creation` already owns `agent frontmatter`. A bare `frontmatter` token would have tied with it and turned that mode's exclusive route into a bundle. All seventeen candidate keywords were checked for substring collisions against every existing keyword in both routing surfaces before they were added.

## Operator Guidance

#### Scenario Coverage and Limits

The scenarios cover field-and-class resolution, the description budget and version derivation. Like every other `sk-doc` mode packet, this playbook is not visible to the benchmark scenario loader. The loader recognises a scenario only by a routing-gold key that the operator contract excludes.

---

## Shared Rules and History

#### Enforcement Stays Shared

`frontmatter-version.mjs`, its corpus-gate wrapper and `quick_validate.py` stay in `shared/scripts/`. A post-edit hook outside this hub resolves one of them by literal path on every qualifying edit. Enforcement serves many consumers in the shared tier, while the rules belong to this mode.

&nbsp;

#### No Alias Bridges the Mismatch

The hub's alias table maps a leaf id to a disk path when the two disagree. Adding an alias here would have preserved the mismatch this packet exists to remove.

&nbsp;

#### Historical Wording Stays Accurate

The old location survives only where it stays true. The released changelog entry recording where the file sat at `v1.8.0.0` is history and keeps its wording. Three dated benchmark report bundles keep their wording for the same reason.

&nbsp;

#### The Changelog Link Finds Its Reference

The changelog template pointed at a same-directory copy of the field reference that has never existed there. Repointing it changed link failures across the hub from 113 to 112.
