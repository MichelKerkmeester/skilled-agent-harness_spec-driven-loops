# v1.3.3.0, README Checkers That Agree With the Audit

The reference checker and the count checker failed most READMEs. The failures were on things that are not broken. Those things are slash commands, model ids and import specifiers. Prose such as "in one file" is another. Both now judge only what they can check. Every link target is still checked. So is every inventory row and file tree line. So a failure points at a real broken path or a stale count.

&nbsp;

## What's New at a Glance

- Every link target is checked.
  - A Markdown link that is not a URL or an anchor is checked as before.
  - Its form does not matter.
  - `[dir](missing-dir/)`, `[noext](missing-file)`, `[deep](sub/missing.md)` and `[img](missing.png)` all fail when the target is gone.
  - Only a target that does not normalize to a path is skipped.
  - One example is a `{placeholder}`.
- Anchored code spans resolve from three bases.
  - The audit reads some code spans as a path.
  - Examples are `./run.sh`, `../gone.md` and `.skilled/scripts/absent.sh`.
  - Each resolves from the README folder, its nearest `package.json` folder and the repository root.
  - A bare name or unanchored path keeps that release's resolution.
  - The false-positive rules of v1.3.2.0 still read it.
  - So its `readme-check` markers stay valid.
  - Fenced commands are read by the audit's anchored rule only.
- Inventory rows and tree lines are claims.
  - A table cell made only of code spans is one claim.
  - An example is `` `gone.py` ``.
  - A file tree entry drawn with box glyphs or ASCII is another.
  - The ASCII forms are `+--`, `|--` and `` `-- ``.
  - Both are checked against the README folder, its package root and the repository root.
  - They fail only when none of them holds the file.
- Git-ignored runtime paths pass.
  - A path the repository ignores is cleared.
  - One example is a log folder.
  - It is cleared in two batched `git check-ignore` calls per run.
  - That replaces one call per path.
  - A typo of it still fails.
  - A README kept inside an ignored folder is not cleared.
- The count checker counts only the README's own folder.
  - A number counts files only when a plural term follows it directly.
  - One example is "three scripts".
  - A number is skipped only when its own sentence names another path.
  - That path must not be the README's folder.
  - So "`.claude/hooks/` contains 25 symlinks" beside a link to another README is still checked.
  - The label, bound, named-folder and `allow-count` rules of v1.3.2.0 still apply.
- The git calls no longer wait on fsmonitor.
  - The audit's `git ls-files` and `git check-ignore` calls pass `-c core.fsmonitor=false`.
  - So does both checkers' root lookup.
  - So a checkout with a stalled fsmonitor daemon does not hang a run.
- The scripts README documents both gates.
  - `scripts/README.md` now says what each checker checks.
  - It gives each usage line, `--self-test` flag and exit codes (0 pass, 1 fail, 2 no README given).
  - It covers the batched git-ignore clearing and fsmonitor-off git calls.
  - It says the full sk-doc suite runs both.
- A stale count still fails.
  - "Three scripts" over a folder that holds two is still reported.
  - So is a count with no complete file list behind it.

&nbsp;

## Upgrade

No migration required. A README that failed only on slash commands, model ids, import specifiers or prose now passes. A README with a stale inventory row or tree line fails. It fails until the row is corrected.
