# v1.3.3.0, README Checkers That Agree With the Audit

The reference checker and the count checker failed most READMEs on things that are not broken: slash commands, model ids, import specifiers and prose such as "in one file". Both now judge only what they can check, while every link target, inventory row and file tree line is still checked, so a failure points at a real broken path or a stale count.

> Spec folder: `specs/sk-doc/070-repo-doc-debt/007-alignment-fixes` (Level 2)

&nbsp;

## What's New at a Glance

- **Every link target is checked.** A Markdown link that is not a URL or an anchor is checked as before, whatever its form: `[dir](missing-dir/)`, `[noext](missing-file)`, `[deep](sub/missing.md)` and `[img](missing.png)` all fail when the target is gone. Only a target that does not normalize to a path, such as a `{placeholder}`, is skipped.
- **Anchored code spans resolve from three bases.** A code span the audit reads as a path, such as `./run.sh`, `../gone.md` or `.skilled/scripts/absent.sh`, resolves from the README folder, its nearest `package.json` folder and the repository root. A bare name or unanchored path, which the false-positive rules of v1.3.2.0 still read, keeps that release's resolution, so its `readme-check` markers stay valid. Fenced commands are read by the audit's anchored rule only.
- **Inventory rows and tree lines are claims.** A table cell made only of code spans, such as `` `gone.py` ``, and a file tree entry drawn with box glyphs or ASCII (`+--`, `|--`, `` `-- ``) are checked against the README folder, its package root and the repository root. They fail only when none of them holds the file.
- **Git-ignored runtime paths pass.** A path the repository ignores, such as a log folder, is cleared in two batched `git check-ignore` calls per run instead of one call per path, while a typo of it still fails and a README kept inside an ignored folder is not cleared.
- **The count checker counts only the README's own folder.** A number counts files only when a plural term follows it directly, as in "three scripts". It is skipped only when its own sentence names another path and not the README's folder, so "`.claude/hooks/` contains 25 symlinks" beside a link to another README is still checked. The label, bound, named-folder and `allow-count` rules of v1.3.2.0 still apply.
- **The git calls no longer wait on fsmonitor.** The audit's `git ls-files` and `git check-ignore` calls and both checkers' root lookup pass `-c core.fsmonitor=false`, so a checkout with a stalled fsmonitor daemon does not hang a run.
- **The scripts README documents both gates.** `scripts/README.md` now says what each checker checks, its usage line, `--self-test` flag and exit codes (0 pass, 1 fail, 2 no README given), the batched git-ignore clearing and fsmonitor-off git calls, and that the full sk-doc suite runs both.
- **A stale count still fails.** "Three scripts" over a folder that holds two, or a count with no complete file list behind it, is still reported.

&nbsp;

## Upgrade

No migration required. A README that failed only on slash commands, model ids, import specifiers or prose now passes. A README with a stale inventory row or tree line fails until the row is corrected.
