# v1.3.4.0, README Checkers That Check Slash Commands and More Count Claims

v1.3.3.0 stopped failing READMEs on slash commands by skipping them. So a mistyped or removed command passed. Its count checker missed claims phrased as "12 test files" or "Files: 12". The checkers now catch both. Every v1.3.3.0 rule, resolution base and self-test stays as it was. On the same 987 tracked READMEs, the v1.3.3.0 checkers fail 336 on references and 59 on counts. The new ones fail 318 and 54. No README that passes v1.3.3.0 fails now.

&nbsp;

## What's New at a Glance

- **Slash commands resolve against the command tree.** `/create:changelog` resolves to its command file under `.skilled/commands`, grouped or top-level. A trailing mode such as `:auto` must be one the command declares. A missing command fails. So does an undeclared mode. So does a hyphen-form typo that nearly spells a real command in its group. A command inside an HTML comment is not checked. Neither is a placeholder such as `/<family>:<name>`. A checkout with no command tree skips the check.
- **Placeholders are not references.** A code span such as `path/to/document.md` names a shape, not a file. So it no longer fails. The same goes for one that opens with a bracketed segment, such as `[spec-folder]/spec.md`. A bracketed folder further in, as in `app/[id]/page.tsx`, is still a real path. A placeholder used as a link target is still checked.
- **A shortened link label passes.** A code-span label in front of a working link passes. That holds when the link target ends with the label's path. The example is `` [`runtime/lib/README.md`](./runtime/lib/README.md) ``. A label that names a different file than its target still fails.
- **More count claims are read.** "12 test files", "12 plugin scripts", "Files: 12" and "several test files" are claims now. A tree line describes its folder with or without a `#`. Test files named `.test.mjs`, `.test.cjs`, `.test.sh`, `test_*.py` or `test-*.sh` count as tests. A rate such as "max 300 files/session" is not a claim. Neither is a test result such as "20/20 pass". Neither is a subset such as "2 more test files".
- **A named folder is counted on its own.** A claim about a folder the sentence names is checked against that folder. It is never checked against the README folder's inventory.
- **A deleted file fails.** A bare name no longer resolves when its only tracked match has been deleted from the working tree.

&nbsp;

## Upgrade

No migration required. A README that names a removed command on purpose should describe it in plain prose. It should not use a code span. A count claim the checker cannot prove from a folder listing needs an `allow-count` entry. That entry needs its reason.
