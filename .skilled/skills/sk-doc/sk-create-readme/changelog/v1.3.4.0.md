# v1.3.4.0, README Checkers That Check What They Used to Skip

v1.3.2.0 cleared the false positives by skipping whole classes of reference, so a mistyped slash command or a count that drifted from its folder passed unseen. The checkers now resolve those classes instead of skipping them, while keeping every v1.3.2.0 rule, marker block and self-test. Run on the same 987 tracked READMEs, the v1.3.2.0 checkers fail 371 on references and 74 on counts, the new ones 350 and 63, and no README that passes v1.3.2.0 fails now. A full sweep also got faster, from about 51 to 21 seconds for references.

> Spec folder: `specs/system-speckit/054-weak-model-spec-authoring/027-alignment-preexisting-gaps` (Level 2)

&nbsp;

## What's New at a Glance

- **Slash commands resolve against the command tree.** `/create:changelog` resolves to its command file, grouped or top-level, and a trailing mode such as `:auto` must be one the command declares. A missing command or an undeclared mode now fails, and a deliberate mention of a removed command goes in an `allow-ref` entry with its reason.
- **A bare filename must exist on disk.** `spec.md` passes when a tracked file by that name exists anywhere in the repository, and a tracked file deleted from the working tree now fails. A path with a slash resolves only from the README folder or the repository root, so a broken path never borrows a same-named file elsewhere.
- **Spec docs resolve through their templates.** A doc that ships only as a scaffold, such as `phase-parent.spec.md`, resolves through its `.tmpl` file.
- **Placeholders and HTML comments are not references.** `[name]` and `path/to/` placeholders and text inside `<!-- -->` no longer count against a README. A shell-assignment value, a path in a fenced comment and the code-span label of a working link are checked only when they are anchored paths. The result line reports what was set aside in a new `skipped` count.
- **A count is checked against the folder it names.** A claim is a quantity followed by a plural count term, as in `42 files`. When the sentence names a folder in a code span, or a tree line in Unicode or plain-text style describes one, the checker counts that folder's tracked files and passes or fails on the real number. One `git ls-files` call serves every claim, so the result matches across checkouts.
- **An unprovable count still fails, and says why.** A claim that names no folder fails as before and is also counted as `unverified`, so the fix is clear: name the folder, list the files or record an `allow-count` entry with its reason. `--strict` is still accepted and changes nothing.
- **Gitignore and on-demand config rules are narrower.** Only an ignore pattern without a slash skips a bare name, and a nested `.gitignore` applies only to READMEs at or below its folder. Also, only the exact tokens `.sk-code/quality.json` and `.sk-git/` count as config a doctor command creates.

&nbsp;

## Upgrade

No migration required. A README that names a removed command on purpose needs an `allow-ref` entry for it, and three READMEs in this repository gained one. A count claim that names no folder now needs the folder named, the files listed or an `allow-count` entry with its reason.
