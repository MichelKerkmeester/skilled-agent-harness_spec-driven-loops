# v1.3.4.0, README Checkers That Stop Flagging Correct References

The reference checker read every token with a slash as a path, so slash commands, placeholders and filenames named without their folder all failed. Across the seven READMEs the alignment run checks, unresolved references went from 608 to 0, and a typo still fails.

> Spec folder: `specs/system-speckit/054-weak-model-spec-authoring/027-alignment-preexisting-gaps` (Level 2)

&nbsp;

## What's New at a Glance

- **Slash commands resolve against the command tree.** `/create:changelog` resolves to its command file, grouped or top-level, and a trailing mode such as `:auto` must be one the command declares. A missing command or an undeclared mode still fails.
- **A bare filename resolves anywhere in the repository.** `spec.md` passes when a file by that name exists. A path with a slash resolves only from the README folder or the repository root, so a broken path never borrows a same-named file elsewhere.
- **Spec docs resolve through their templates.** A doc that ships only as a scaffold, such as `phase-parent.spec.md`, resolves through its `.tmpl` file.
- **What the repository cannot check stops failing.** Gitignored files, config a doctor command creates on demand, placeholders such as `path/to/document.md`, home and absolute paths, comments in fenced commands and the code-span label of a working link no longer count against a README. The result line reports the skipped references in a new `skipped` count.
- **A count claim is a number that counts something.** The count checker reads a claim only where a quantity is followed by a plural count term, as in `42 files`. A number that only shares the line, a single item, a threshold such as "more than 100 files" and a compound such as "9-step workflow" no longer trigger it.
- **A count is checked against the folder it names.** When the sentence names a folder in a code span, or a tree line carries `(N files)`, the checker counts that folder and passes or fails on the real number. A claim that names no folder is reported as unverified instead of failed, and `--strict` turns those into failures.

&nbsp;

## Upgrade

No migration required. The checkers read the same READMEs, and only the verdict on references and counts they cannot check changes.
