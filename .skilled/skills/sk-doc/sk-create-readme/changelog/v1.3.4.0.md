# v1.3.4.0, README Checkers That Check Slash Commands and More Count Claims

v1.3.3.0 stopped failing READMEs on slash commands by skipping them, so a mistyped or removed command passed, and its count checker missed claims phrased as "12 test files" or "Files: 12". The checkers now catch both, while every v1.3.3.0 rule, resolution base and self-test stays as it was. Run on the same 987 tracked READMEs, the v1.3.3.0 checkers fail 336 on references and 59 on counts and the new ones 318 and 54, and no README that passes v1.3.3.0 fails now.

> Spec folder: `specs/system-speckit/054-weak-model-spec-authoring/027-alignment-preexisting-gaps` (Level 2)

&nbsp;

## What's New at a Glance

- **Slash commands resolve against the command tree.** `/create:changelog` resolves to its command file under `.skilled/commands`, grouped or top-level, and a trailing mode such as `:auto` must be one the command declares. A missing command, an undeclared mode or a hyphen-form typo that nearly spells a real command in its group fails. A command inside an HTML comment or written as a placeholder such as `/<family>:<name>` is not checked, and a checkout with no command tree skips the check.
- **Placeholders are not references.** A code span such as `path/to/document.md`, or one that opens with a bracketed segment such as `[spec-folder]/spec.md`, names a shape, not a file, so it no longer fails. A bracketed folder further in, as in `app/[id]/page.tsx`, is still a real path. A placeholder used as a link target is still checked.
- **A shortened link label passes.** A code-span label in front of a working link passes when the link target ends with the label's path, as in `` [`runtime/lib/README.md`](./runtime/lib/README.md) ``. A label that names a different file than its target still fails.
- **More count claims are read.** "12 test files", "12 plugin scripts", "Files: 12" and "several test files" are claims now, a tree line describes its folder with or without a `#`, and test files named `.test.mjs`, `.test.cjs`, `.test.sh`, `test_*.py` or `test-*.sh` count as tests. A rate such as "max 300 files/session", a test result such as "20/20 pass" and a subset such as "2 more test files" are not claims.
- **A named folder is counted on its own.** A claim about a folder the sentence names is checked against that folder, never against the README folder's inventory.
- **A deleted file fails.** A bare name whose only tracked match has been deleted from the working tree no longer resolves.

&nbsp;

## Upgrade

No migration required. A README that names a removed command on purpose should describe it in plain prose rather than as a code span, and a count claim the checker cannot prove from a folder listing needs an `allow-count` entry with its reason.
