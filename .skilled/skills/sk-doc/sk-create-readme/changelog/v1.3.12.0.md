# v1.3.12.0, Lifecycle Numbered and Every Output Named

The packet's `SKILL.md`, `ROUTER.md`, `README.md`, README template and references were read file by file for readability, layout and structure. Text moved and split, every claim was kept and the README now lists files the packet already ships. No command, contract or template behavior changed.

> Spec folder: `specs/sk-doc/066-skill-readability-refinement/008-sk-doc` (Level 1)

## What's New at a Glance

- **The lifecycle is numbered.** The README walks four steps, from reading local evidence to validating links, and the two failures behind the skill, a README from memory and one template for everything, are now bullets.
- **Every output is named.** The README says the packet also writes a skill package's `ARCHITECTURE.md`, and `ROUTER.md` lists its three templates, the general, code-folder and architecture scaffolds.
- **The README lists the packet's checks.** Its checks table gained the reference-integrity and derived-count scripts, and its document table gained the architecture template and the manual testing playbook.
- **The rule blocks have headings.** `SKILL.md`'s Always, Never, Human Voice Rules and Escalate If blocks are now subsections, and it says to report `UNKNOWN_FALLBACK` when nothing matches.
- **References open with their purpose.** The quality, types-and-voice and writing-patterns references each open with a Purpose, a When to Use and a Core Principle heading, and their packed formatting rules became bullets.
