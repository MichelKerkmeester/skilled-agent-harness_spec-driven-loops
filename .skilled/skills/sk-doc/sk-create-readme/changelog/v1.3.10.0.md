# v1.3.10.0, Filename Templates and Count Phrases

README reference checks now resolve a bracketed token in a file basename as a
filename template against that folder. Bracketed route folders such as
`app/[id]` stay literal paths, so the checker continues to verify the route
file itself.

Count checks recognize known file categories such as shell scripts and Node
test files while leaving compound concept phrases such as reader tests and
example scripts as prose. This prevents design and test concepts from being
mistaken for inventories of files.

> Spec folder: `specs/sk-doc/072-skill-routing-and-clarity/012-alignment-remediation` (Level 2)

&nbsp;

## What's New at a Glance

- **Filename placeholders resolve by folder.** References such as
  `changelog/v[version].md` pass when a matching file exists in that folder.
- **Compound concepts stay prose.** Only direct file counts and recognized
  category modifiers are treated as README inventory claims.
