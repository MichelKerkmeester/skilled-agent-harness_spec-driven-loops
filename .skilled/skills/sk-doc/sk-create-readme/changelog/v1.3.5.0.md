# v1.3.5.0, A Committed .sk-code File Resolves From Any README

The repository now commits its CI profile at `.sk-code/ci.json`. The reference checker resolved a `.sk-code/` path only from the README's own folder, so a README below the root that named the profile failed with "path does not exist" while the file was tracked. A path under `.sk-code/` now also resolves from the repository root, like `.github/` and `.skilled/` do.

> Spec folder: `specs/sk-code/017-portable-code-modes/007-ci-repo-profile` (Level 2)

&nbsp;

## What's New at a Glance

- **`.sk-code/` is a repository-root folder.** A code span such as `.sk-code/ci.json` resolves from the repository root as well as from the README's folder. A missing file under it, such as `.sk-code/gone.json`, still fails, and `.sk-code/quality.json` keeps passing as a config the doctor commands create on demand.
- **Two self-test cases cover it.** One README below the root names a tracked `.sk-code/ci.json` and must pass, and one names a missing file there and must fail.
