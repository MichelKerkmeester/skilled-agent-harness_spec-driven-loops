# v1.2.0.0, README Writing Guidance

This release turns the root README rework into writing guidance for the front-page marketing register and the technical register used by other READMEs. It adds formatting rules and patterns for emoji use, feature-named headings, itemized inventories and paragraph length.

## Why This Release

The root README rework established formatting patterns that made the front page scannable.

## What's New at a Glance

- **`SKILL.md` adds four README format rules.** They cover the two-register emoji policy, headings named for a feature or artifact, per-item inventory descriptions and a 2-4 sentence paragraph bound. Its version moves from `1.1.0.0` to `1.2.0.0`.
- **`writing-patterns.md` adds rules for emoji, paragraphs and inventories.** It adds the `Emoji Use` structural rule, the `Paragraphs and Bullets` rule and the `Itemized Inventory` table pattern with bold names followed by bullets and `#####` groupings. Its version moves from `1.1.0.6` to `1.2.0.0`.
- **`types-and-voice.md` defines the front-page and technical registers.** Its `Front-Page vs Technical Register` subsection says the repository front page may pitch while every other README keeps technical formatting and may borrow the front page's engaging voice. The version moves from `1.1.0.7` to `1.2.1.0`. The subsection was refined after `sk-create-skill`'s README templates moved to value-first openings.
- **`quality-and-checklist.md` adds checks for the new writing guidance.** It adds checks for emoji-register adherence, feature-named headings, per-item inventory descriptions and paragraph length. Its version moves from `1.1.0.7` to `1.2.0.0`.
- **`readme-template.md` adds an itemized inventory pattern.** It includes an inventory-description writing rule, a worked example and a scaffold comment pointing to the pattern. Its version moves from `1.1.0.39` to `1.2.0.0`.
- **`core-standards.md` updates the shared README standard.** Its README block replaces the blanket `Allowed` wording with the two emoji registers. Across sk-doc packets, the one-YAML-block change in this shared file tightens rather than relaxes the previous wording. Its version moves from `2.1.0.36` to `2.1.0.37`.
- **`readme-code-template.md` stays at `1.1.0.8`.** Code-folder READMEs already use the technical register and take the general rules through the `SKILL.md` Section 6 cross-reference.

These additions are opt-in or scoped to the README types they fit. They describe options and rules for new or revised documents. No README was rewritten, and existing valid READMEs remain valid.

`hvr_scan.py`, `audit_readmes.py`, `check_derived_readme_counts.py` and `check_readme_references.py` are untouched.

The new rules are guidance-level and need no scanner changes.

## Upgrade

No migration required.
