# v1.2.0.0, README Writing Guidance

This release turns the root README rework into writing guidance. The guidance covers a front-page marketing register. It also covers the technical register other READMEs use. It adds formatting rules and patterns. They cover emoji use, feature-named headings, itemized inventories and paragraph length.

&nbsp;

## Why This Release

The root README rework established formatting patterns. Those patterns made the front page scannable.

&nbsp;

## What's New at a Glance

- `SKILL.md` adds four README format rules.
  - The rules cover the two-register emoji policy.
  - The rules cover headings named for a feature or artifact.
  - The rules also cover per-item inventory descriptions.
  - The rules also cover a 2-4 sentence paragraph bound.
  - Its version moves from `1.1.0.0` to `1.2.0.0`.
- `writing-patterns.md` adds rules for emoji, paragraphs and inventories.
  - The file adds the `Emoji Use` structural rule.
  - The file adds the `Paragraphs and Bullets` rule.
  - The file adds the `Itemized Inventory` table pattern.
  - That pattern uses bold names, then bullets and `#####` groupings.
  - Its version moves from `1.1.0.6` to `1.2.0.0`.
- `types-and-voice.md` defines the front-page and technical registers.
  - Its `Front-Page vs Technical Register` subsection says the repository front page may pitch.
  - Every other README keeps technical formatting.
  - Other READMEs may borrow the front page's engaging voice.
  - The version moves from `1.1.0.7` to `1.2.1.0`.
  - The subsection was refined after `sk-create-skill`'s README templates moved to value-first openings.
- `quality-and-checklist.md` adds checks for the new writing guidance.
  - The new checks cover emoji-register adherence.
  - The new checks cover feature-named headings.
  - The checks also cover per-item inventory descriptions.
  - The checks also cover paragraph length.
  - Its version moves from `1.1.0.7` to `1.2.0.0`.
- `readme-template.md` adds an itemized inventory pattern.
  - The template includes an inventory-description writing rule.
  - The template includes a worked example.
  - The template also includes a scaffold comment pointing to the pattern.
  - Its version moves from `1.1.0.39` to `1.2.0.0`.
- `core-standards.md` updates the shared README standard.
  - Its README block replaces the blanket `Allowed` wording with the two emoji registers.
  - Across sk-doc packets, the one-YAML-block change in this shared file tightens the previous wording.
  - The change does not relax the previous wording.
  - Its version moves from `2.1.0.36` to `2.1.0.37`.
- `readme-code-template.md` stays at `1.1.0.8`.
  - Code-folder READMEs already use the technical register.
  - Code-folder READMEs take the general rules through the `SKILL.md` Section 6 cross-reference.
- These additions are opt-in or scoped to the README types they fit.
- The additions describe options and rules for new or revised documents.
- No README was rewritten.
- Existing valid READMEs remain valid.
- `hvr_scan.py`, `audit_readmes.py`, `check_derived_readme_counts.py` and `check_readme_references.py` are untouched.
- The new rules are guidance-level. They need no scanner changes.
