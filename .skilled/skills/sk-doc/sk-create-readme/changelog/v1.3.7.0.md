# v1.3.7.0, The Checker Stops Treating .sk-code as a Root Folder

The repository settings moved into the skill folders, so `.sk-code/` is no longer a folder a README can point at from any folder. The reference checker drops it from its repository-root prefixes, which means a README that links into `.sk-code/` now fails unless the path is one of the two the checker still allows by name.

> Spec folder: `specs/sk-code/017-portable-code-modes/016-repository-config-in-skill` (Level 2)

&nbsp;

## What's New at a Glance

- **The new quality config path is the on-demand one.** `.skilled/skills/sk-code/sk-code-quality/repository/quality.json` is exempt as the file `/doctor:sk-code quality` creates, and `.sk-git/` keeps the same treatment.
- **The two old root paths pass only as a described move.** `.sk-code/ci.json` and `.sk-code/quality.json` stay allowed so a document can name them while it explains the refusal, and the module docstring says the loaders refuse them.
- **The self-test follows the change.** One case resolves a tracked profile under the packet's `repository/` folder from a README below the root, and the on-demand case names the new config path.

&nbsp;

## Upgrade

No migration required.
