# v1.3.7.0, The Checker Stops Treating .sk-code as a Root Folder

The repository settings moved into the skill folders. So `.sk-code/` is no longer a folder a README can point at from any folder. The reference checker drops it from its repository-root prefixes. So a README that links into `.sk-code/` now fails. It fails unless the path is one of the two. The checker still allows those two by name.

&nbsp;

## What's New at a Glance

- **The new quality config path is the on-demand one.** `.skilled/skills/sk-code/sk-code-quality/repository/quality.json` is exempt. It is the file `/doctor:sk-code quality` creates. `.sk-git/` keeps the same treatment.
- **The two old root paths pass only as a described move.** `.sk-code/ci.json` and `.sk-code/quality.json` stay allowed. So a document can name them while it explains the refusal. The module docstring says the loaders refuse them.
- **The self-test follows the change.** One case resolves a tracked profile under the packet's `repository/` folder. It does so from a README below the root. The on-demand case names the new config path.

&nbsp;

## Upgrade

No migration required.
