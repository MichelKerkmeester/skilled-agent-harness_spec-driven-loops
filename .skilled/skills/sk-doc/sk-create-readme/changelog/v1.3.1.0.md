# v1.3.1.0, A README Audit That Knows What Is Runtime

Package docs often link a log file, a state file or a build output. The README audit reported all of them as broken. It now asks git which missing paths are ignored. It reads a bare path from the nearest package root. So a correct link stops drawing a finding. It also reads only real README files.

&nbsp;

## What's New at a Glance

- A runtime artifact stops counting as broken.
  - A missing reference that git ignores is reported as resolved.
  - Its evidence is `gitignored_runtime_path`.
- An absent runtime folder clears too.
  - A folder reference is also asked with its trailing slash.
  - So a rule that ignores the whole folder matches.
  - The rule matches even when the folder is not in this checkout.
- Package docs resolve the way the package reads.
  - A bare path also resolves from the nearest folder above the README.
  - That folder holds a `package.json`.
- Only real READMEs are read.
  - `README.md` and `README.markdown` match exactly.
  - That drops the lowercase `/create:readme` command file from the audit.
  - A folder named with a `-fixture` suffix counts as test input.

&nbsp;

## Upgrade

No migration required. The audit reads the same references. Only the verdict on a missing path changes.
