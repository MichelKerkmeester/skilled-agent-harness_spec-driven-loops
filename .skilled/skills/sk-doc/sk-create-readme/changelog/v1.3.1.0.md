# v1.3.1.0, A README Audit That Knows What Is Runtime

Package docs often link a log file, a state file or a build output, all of which the README audit reported as broken. It now asks git which missing paths are ignored and reads a bare path from the nearest package root, so a correct link stops drawing a finding. It also reads only real README files.

> Spec folder: `specs/sk-doc/070-repo-doc-debt/006-audit-and-validator-accuracy` (Level 2)

&nbsp;

## What's New at a Glance

- **A runtime artifact stops counting as broken.** A missing reference that git ignores is reported as resolved, with `gitignored_runtime_path` as its evidence.
- **An absent runtime folder clears too.** A folder reference is also asked with its trailing slash, so a rule that ignores the whole folder matches even when the folder is not in this checkout.
- **Package docs resolve the way the package reads.** A bare path also resolves from the nearest folder above the README that holds a `package.json`.
- **Only real READMEs are read.** `README.md` and `README.markdown` match exactly, which drops the lowercase `/create:readme` command file from the audit. A folder named with a `-fixture` suffix counts as test input.

&nbsp;

## Upgrade

No migration required. The audit reads the same references and only the verdict on a missing path changes.
