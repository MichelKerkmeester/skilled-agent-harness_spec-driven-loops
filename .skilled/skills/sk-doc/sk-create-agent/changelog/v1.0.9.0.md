# v1.0.9.0, the Registry Step Covers One Agent Directory

Step 13 ordered a registry record for every new agent. The roster check reads `.skilled/agents/` alone. A record for a Claude-only agent therefore failed that check. The step now names the directory it covers. The README, the playbook and the routing vocabulary caught up with it.

> Spec folder: `specs/agents/007-agent-alignment-follow-ups/005-alignment-report-fixes`

&nbsp;

## What's New at a Glance

- **The step names its directory.** Steps 13 and 14 apply to an agent under `.skilled/agents/`. An agent that lives only in `.claude/agents/` gets no record.
- **The README covers the step.** Quick start, troubleshooting and verification now name the registry record. They also name the roster check.
- **A playbook scenario runs the check.** Scenario `AGV-003` runs the roster check without a record and with one. The playbook now holds seven scenarios.
- **Registry prompts reach the skill.** `agent registry` is a routing phrase. A prompt that named only the registry used to route elsewhere.
- **The command adds the record.** `/create:agent` now writes the registry record and runs the roster check.
