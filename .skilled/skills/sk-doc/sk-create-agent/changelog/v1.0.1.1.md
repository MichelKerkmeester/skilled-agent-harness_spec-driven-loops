This release documents a clear choice between an agent, skill and command for ambiguous requests and records why the packet uses flat resource folders. It gives mixed requests a defined route.

## What's New at a Glance

- **Ambiguous requests resolve to a clear owner.** The distinguishing signals, lighter-alternative cues and decision rule of the agent-vs-skill-vs-command decision path live in `references/agent-vs-skill-vs-command.md`. The file is loaded when a request could plausibly be a skill or command or mixes responsibilities, so ambiguity does not default to an agent.
- **The packet adds no per-key resource subfolders.** It uses flat `references/` and `assets/` folders without keyed `references/<key>/` directories. The small resource set makes the route map in `references/README.md` clearer than keyed runtime discovery.

## Upgrade

No migration required.
