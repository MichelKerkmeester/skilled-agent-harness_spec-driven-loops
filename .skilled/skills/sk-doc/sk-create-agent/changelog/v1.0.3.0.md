# v1.0.3.0, The Routing Prose Is Short and the Router Moved to the End

A reader now meets the agent-authoring instructions sooner. `SMART ROUTING` is five lines of plain prose. They say what selects this packet and what it loads first. The same lines say where the router is. The component decision, the smart-router pseudocode and the router resilience rules sit unchanged. They sit in a final `## 7. MACHINE ROUTER` section. Nothing about what routes where changed.

&nbsp;

## What's New at a Glance

- The routing section is prose.
  - Five lines name the request that selects this packet.
  - The five lines name the resource that loads first and the section that holds the router.
  - So a reader reaches the creation workflow.
  - A reader does not scroll past a decision tree and a code block.
- The router is at the end.
  - The component decision and its tree moved byte for byte into `## 7. MACHINE ROUTER`.
  - So did the smart-router pseudocode and the router resilience rules.
  - `## 7. MACHINE ROUTER` is the last H2 of the file.
  - The moved items sit under the headings they already carried.

&nbsp;

## Upgrade

No action is needed. The packet routes and loads exactly the resources it did before. Only the section that holds the routing detail changed.
