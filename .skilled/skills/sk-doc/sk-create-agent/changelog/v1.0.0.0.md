# v1.0.0.0 - create-agent packet established

The first release of `create-agent` provides a workflow. It scaffolds or updates a single runtime agent markdown file. `create-agent` is one of the ten workflow packets in the `sk-doc` parent hub. The workflow guides you through several steps. First, decide whether a request needs an agent rather than a skill or command. Then resolve the active runtime agent directory. Then write frontmatter and an authority boundary. Then add workflow and verification sections. Then validate before delivery.

## What's New at a Glance

- **`SKILL.md` sets the agent decision and creation workflow.** It covers the agent-versus-skill-or-command decision. It covers the output package and the active runtime directory (`.opencode/agents/` or `.claude/agents/`). It adds an ordered 14-step creation workflow and a validation gate. It also covers the canonical frontmatter shape. That shape is the unified `permission:` object and `task` gating for orchestration authority. It covers the required body shape too. That shape is a hard boundary, core workflow, capability scan, output verification, anti-patterns and related resources.
- **`references/agent_creation.md` adds deeper creation guidance.** It holds long-form creation standards, current-reality notes and common-mistake examples. These are used only for deeper detail beyond the `SKILL.md` contract.
- **`assets/agent-template.md` provides the canonical scaffold.** Copy it first. Then replace placeholders with the agent's role, permissions, workflow and boundaries.
- **Advisor identity and validation are shared with `sk-doc`.** There is no packet-local advisor graph identity (`graph-metadata.json`). The single advisor identity and workflow registry live at the `sk-doc` hub root. This packet has no `scripts/`. So validation reuses the shared `validate_document.py` and `extract_structure.py` under `../shared/scripts/`.
