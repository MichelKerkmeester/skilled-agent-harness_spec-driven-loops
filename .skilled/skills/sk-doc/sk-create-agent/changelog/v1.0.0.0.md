# v1.0.0.0 - create-agent packet established

The first release of `create-agent`, one of the ten workflow packets in the `sk-doc` parent hub, provides a workflow for scaffolding or updating a single runtime agent markdown file. It guides you through deciding whether a request needs an agent rather than a skill or command, resolving the active runtime agent directory, writing frontmatter and an authority boundary, adding workflow and verification sections, then validating before delivery.

## What's New at a Glance

- **`SKILL.md` sets the agent decision and creation workflow.** It covers the agent-versus-skill-or-command decision, output package and active runtime directory (`.opencode/agents/` or `.claude/agents/`), plus an ordered 14-step creation workflow and validation gate. It also covers the canonical frontmatter shape (the unified `permission:` object and `task` gating for orchestration authority) and the required body shape (hard boundary, core workflow, capability scan, output verification, anti-patterns and related resources).
- **`references/agent_creation.md` adds deeper creation guidance.** It contains long-form creation standards, current-reality notes and common-mistake examples, used only for deeper detail beyond the `SKILL.md` contract.
- **`assets/agent-template.md` provides the canonical scaffold.** Copy it before replacing placeholders with the agent's role, permissions, workflow and boundaries.
- **Advisor identity and validation are shared with `sk-doc`.** There is no packet-local advisor graph identity (`graph-metadata.json`). The single advisor identity and workflow registry live at the `sk-doc` hub root. This packet has no `scripts/`, so validation reuses the shared `validate_document.py` and `extract_structure.py` under `../shared/scripts/`.
