# v1.0.1.0 - Smart-routing section conformance

This release normalizes `SKILL.md` to the canonical section contract so the packet satisfies every required H2. This structural pass changes no workflow guidance. All prose, tables, decision rules and reference links were preserved verbatim apart from the restructure.

## What's New at a Glance

- **The routing headings now separate two required sections.** The merged `WHEN TO USE + SMART_ROUTING` became `## 1. WHEN TO USE` and `## 2. SMART ROUTING`. The underscore meant automated section matching did not recognize the `SMART ROUTING` heading, so the required section registered as missing even though its content was present.
- **Routing guidance sits under SMART ROUTING.** The routing-away guidance ("use a different `sk-doc` workflow when") and agent-vs-alternative decision-rule block moved there, while the applicability list stayed under `WHEN TO USE`.
- **WHEN TO USE now names its keyword triggers.** A `Keyword triggers:` line surfaces the same trigger vocabulary as the keyword comment.
- **References now have their own required section.** The former `OVERFLOW REFERENCES` subsection moved out of `RULES` into the top-level `## 6. REFERENCES`, with every reference link preserved.
- **A `## 5. SUCCESS CRITERIA` H2 is added.** It summarizes the delivery bar: runtime placement, runtime-correct frontmatter schema, required body sections, linked-not-pasted depth and clean validation.
- **The H2 headings now run from one through six.** No numeric intra-file cross-references existed, so nothing else shifted.
- **The packet still carries no local advisor graph identity.** Validation continues to reuse the shared sk-doc validators under `../shared/scripts/`.

## Upgrade

No migration required.
