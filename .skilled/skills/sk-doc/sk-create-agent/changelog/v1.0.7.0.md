# v1.0.7.0, Agent Guidance Reads One Rule per Line

The packet's `SKILL.md`, `README.md`, agent template and references were read file by file for readability, layout and structure. Text moved and split, and every claim was kept. No command, contract or template behavior changed.

> Spec folder: `specs/sk-doc/066-skill-readability-refinement/008-sk-doc` (Level 1)

&nbsp;

## What's New at a Glance

- **Boundary variants are a list.** The four agent boundary shapes in `SKILL.md`, from LEAF write-capable to command-driven, now read one per bullet instead of one long sentence.
- **Routing sentences were split.** How the hub selects this packet, when to stay in it and where the route map sits each read as their own short line.
- **The README opens with what it does.** "What It Does" now comes before "Why This Skill Exists", and the document table lists `ROUTER.md` beside the other packet files.
- **References say when to open them.** The component-choice, common-pitfalls and permission-design references each gained a When to Use list, and the permission section heading now reads "Mode and Temperature Selection".
- **The naming rule moved in the template.** The agent template's filename and `name` pattern rule sits at a new spot in the file, with its wording unchanged.
