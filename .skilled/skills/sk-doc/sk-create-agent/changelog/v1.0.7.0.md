# v1.0.7.0, Agent Guidance Reads One Rule per Line

The packet's `SKILL.md`, `README.md`, agent template and references were read file by file. The reading looked at readability, layout and structure. Text moved and split. Every claim was kept. No command, contract or template behavior changed.

> Spec folder: `specs/sk-doc/066-skill-readability-refinement/008-sk-doc` (Level 1)

&nbsp;

## What's New at a Glance

- **Boundary variants are a list.** `SKILL.md` holds four agent boundary shapes. They run from LEAF write-capable to command-driven. Each now reads as its own bullet, not one long sentence.
- **Routing sentences were split.** Each of three things reads as its own short line. They are how the hub selects this packet, when to stay in it and where the route map sits.
- **The README opens with what it does.** "What It Does" now comes before "Why This Skill Exists". The document table lists `ROUTER.md` beside the other packet files.
- **References say when to open them.** Three references each gained a When to Use list. They are component-choice, common-pitfalls and permission-design. The permission section heading now reads "Mode and Temperature Selection".
- **The naming rule moved in the template.** The agent template's filename and `name` pattern rule sits at a new spot. Its wording is unchanged.
