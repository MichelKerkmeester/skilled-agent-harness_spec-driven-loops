The packet can now measure how well a model reads the Human Voice Rules tells that need a reader. A new lens draws a labeled sample of tracked skill sections and compares a backend against the operator's labels, and its default run makes no model call.

> Spec folder: `specs/cli-jev/003-cli-jev-workflow-integration/034-hvr-reader-needed-lens` (Level 1)

## Why This Release

The scanner settles what a machine can settle. Synonym cycling, significance inflation and false ranges need a reader, so the scanner's floor flags none of them and no count of them can come from the text alone. Until now the packet had no way to show whether a model reads those tells any better than the floor. This release measures that question offline against labels the operator writes.

## What's New at a Glance

- **A new lens measures the tells a reader has to settle.** `scripts/hvr_reader_lens.py` reads tracked skill markdown at its recorded commit and asks three fixed questions about synonym cycling, significance inflation and false ranges. It runs the unchanged scanner over that committed text outside the repository, so uncommitted edits never change the census (the counts the sample rests on).
- **The default run makes no model call.** It prints the census, the three questions with their hashes, `margin: 0.10` and the keep rule line, then stops at the label gate. It writes no file and holds no credential.
- **`--draw --seed <n>` writes the labels file the measurement reads.** It writes 150 rows, 50 per category, each carrying its doc, its section lines, the commit and the section hash with an empty label. The operator labels each row `yes` or `no` and no model writes a label. The file lands at `scripts/hvr-reader-lens-labels.jsonl` by default and `--labels <path>` names another.
- **A label gate holds every measurement until all 150 rows carry a label.** Below that the run prints `labels: labeled=<n> of 150` and `stop: fewer than 150 labeled rows`. With the rows labeled it prints each category's baseline line and then `headroom (<category>): baseline wrong on <n> of <K>`, `no headroom (<category>)` or `underpowered (<category>)`, and fewer than two categories able to pass prints `stop: fewer than 2 categories can pass`.
- **`--jev --out <dir>` and `--deem --out <dir>` each measure one backend behind its own gate.** Each switch needs `--out` so every call is recorded, and the run refuses it without that before any call. With both switches set the Jev run comes first and the Deem run follows, each on its own gate. A gate that fails prints its skip line, such as `jev arm skipped: no credential` or `deem arm skipped: stub backend`, and that backend measures nothing.
- **`scripts/hvr_scan.py` is byte-identical.** The lens reads the scanner's `--json` output and this release changes no rule and no scored doc.
