# v1.0.0.0, Human Voice Rules Get a Workflow

This release gives the Human Voice Rules a workflow for writing.

- It applies the rules to writing.
- Three parts define how that work runs.
- A scope gate and a scanner are two parts.
- A required verification record is the third.

The scan reads the standard and charges each match once.

- `scripts/hvr_scan.py` reads rules from `hvr-rules.md`.
- The packet carries no copied term list.
- The longest matching term claims each span.
- A fresh scan gates every rewrite.

The standard keeps its path and its separate owners.

- Its established address is kept for the files that use it.
- The audit and voice method have separate owners.
- No alias moved between them.

&nbsp;

## Why This Release

The rules were written down but nothing ran them.

- They had long been in `sk-doc/shared/references/`.
- Hundreds of files pointed to them.
- Nothing ran them.

## Scope and Scanning

The scope gate decides which spans the standard governs. The scanner reads the standard and scores matches.

#### Scope Excludes Protected Text <a id="c-scope-excludes-protected-text"></a>

- The scope gate runs before edits.
- `references/scope-and-exemptions.md` decides which spans the standard governs.
- Quotations, error strings, commands and code are outside scope.
- So are generated files, released changelog entries and byte-pinned fixtures.
- A voice edit to any of them is a defect.
- It is not an improvement.

#### The Scan Follows Its Source <a id="c-the-scan-follows-its-source"></a>

- On every invocation `scripts/hvr_scan.py` reads its rules from `hvr-rules.md`.
- The rules are punctuation bans and hard blocker words.
- They also include phrase blockers and soft deductions.
- The packet holds no copy of any term list.
- So editing the standard changes the scan.
- Nothing else needs an update.

#### Overlapping Terms Cost Once <a id="c-overlapping-terms-cost-once"></a>

- Scoring resolves overlapping matches.
- Precedence arithmetic stops double-charging.
- One occurrence costs one penalty.
- The longest matching term claims the span.
- A word can be listed as an extended blocker and as context-dependent.
- It is charged once, as the blocker.
- A transition costs a point only from its third use onward.

#### Rewrites Need a Full Record <a id="c-rewrites-need-a-full-record"></a>

- Rewrites have a completion gate.
- The workflow requires a fresh scan before an edit is considered finished.
- Rewriting to remove a tell introduces new ones.
- A single after-score proves nothing about what the pass did.
- A rewrite is not finished until the scanner has run again on the new text.
- Both numbers have to be reported.
- A report template captures the review record.
- It includes mechanical results and reader judgment.
- The report template carries the exemptions, both scan numbers, judgment findings and accepted exceptions.

## Reading Scan Results

The scan reports findings, but it leaves judgment to the reader.

#### Allowed Uses Can Be Flagged <a id="c-allowed-uses-can-be-flagged"></a>

- `sk-create-repo-rule/README.md` was written to this standard and reviewed before it shipped.
- Scanning it finds two hard blockers.
- Both are `harness` used as a noun for the AI runtime.
- That is the literal sense the standard permits.
- Two recorded exemptions mean no edit.
- A permitted use can appear as a finding.
- The scanner over-reports on purpose.
- A scanner that guessed at word sense would start hiding real findings.

#### Scores Leave Room for Readers <a id="c-scores-leave-room-for-readers"></a>

- Mechanical scores do not replace a reader.
- The scanner distinguishes mechanical findings from qualities that need judgment.
- A clean mechanical result is not a clean document.
- Structure, rhythm, synonym cycling, significance inflation and personality need a reader.
- The scanner prints that list on every run so the two are never confused.

#### Long References Change the Measure <a id="c-long-references-change-the-measure"></a>

- Long references use a different score view.
- The report changes its measure for long documents.
- The 100-point scale assumes a piece of writing, not a 900-line reference.
- Past roughly 400 lines the report switches to hard blockers plus deduction density.
- It says which measure it used.

#### A Thin Parse Stops the Scan <a id="c-a-thin-parse-stops-the-scan"></a>

- A thin parse fails closed.
- The scanner does not report a clean result when it has not read enough of the standard.
- A parse thinner than its floors stops the run with exit 2.
- It does not report a clean scan from a standard it never read.
- Renaming a section heading in the standard triggers this.
- Renumbering one does not because the parser keys on titles.

## Standard and Audit Boundaries

These boundaries keep the standard where files expect it and keep two owners apart.

#### The Standard Keeps Its Path <a id="c-the-standard-keeps-its-path"></a>

- The standard's location does not change.
- Its established address is kept for the files that use it.
- The standard stays at `.opencode/skills/sk-doc/shared/references/hvr-rules.md`.
- Hundreds of files carry this path.
- Most of them are frozen spec documents, plus a spec-kit golden snapshot.
- Relocating it would rewrite shipped history and break a test suite.
- The gain would be a tidier folder.

#### Audit and Voice Work Separate <a id="c-audit-and-voice-work-separate"></a>

- The audit and voice method have separate owners.
- No alias moved between them.
- `sk-create-quality-control` keeps the file-level audit and its `HVR` routing vocabulary.
- This mode owns the voice method that step performs.
