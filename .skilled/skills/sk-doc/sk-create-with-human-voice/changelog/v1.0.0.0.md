The Human Voice Rules have been in `sk-doc/shared/references/` for a long time and
hundreds of files point at them. Nothing ran them. This packet is the workflow that does.

> Spec folder: `specs/sk-doc/039-create-with-human-voice` (Level 2)

---

## What Changed

#### New Features

- **A scope gate that runs before any edit.** `references/scope-and-exemptions.md` decides which spans the standard governs. Quotations, error strings, commands, code, generated files, released changelog entries and byte-pinned fixtures are never in scope, and a voice edit to any of them is a defect rather than an improvement.
- **A mechanical pass that parses the standard at run time.** `scripts/hvr_scan.py` reads the punctuation bans, the hard blocker words, the phrase blockers and the soft deductions out of `hvr-rules.md` on every invocation. The packet holds no copy of any term list, so editing the standard changes the scan with nothing else to update.
- **Precedence arithmetic that stops double-charging.** One occurrence costs one penalty, the longest matching term claims the span, a word listed as both an extended blocker and context-dependent is charged once as the blocker, and a transition costs a point only from its third use onward.
- **A verification step with teeth.** A rewrite is not finished until the scanner has been re-run on the new text and both numbers reported. Rewriting to remove a tell introduces new ones, and a single after-score proves nothing about what the pass did.
- **A report template** carrying the exemptions, both scan numbers, the judgment findings and the accepted exceptions.

#### Notes

- **The standard did not move.** It stays at `.opencode/skills/sk-doc/shared/references/hvr-rules.md`. Hundreds of files carry that path, most of them frozen spec documents, plus a spec-kit golden snapshot. Relocating it would rewrite shipped history and break a test suite in exchange for a tidier folder.
- **The scanner over-reports on purpose.** Scanning `sk-create-repo-rule/README.md`, written to this standard and reviewed before it shipped, finds two hard blockers. Both are `harness` used as a noun for the AI runtime, which is the literal sense the standard permits. Two recorded exemptions, no edit. A scanner that guessed at word sense would start hiding real findings.
- **A clean mechanical result is not a clean document.** Structure, rhythm, synonym cycling, significance inflation and personality all need a reader, and the scanner prints that list on every run so the two are never confused.
- **The 100-point scale assumes a piece of writing, not a 900-line reference.** Past roughly 400 lines the report switches to hard blockers plus deduction density, and says which measure it used.
- **The scanner fails closed.** A parse thinner than its floors stops the run with exit 2 rather than reporting a clean scan from a standard it never read. Renaming a section heading in the standard triggers this. Renumbering one does not, because the parser keys on titles.
- `sk-create-quality-control` keeps the file-level audit and its `HVR` routing vocabulary. This mode owns the voice method that step performs. No alias moved between the two.
