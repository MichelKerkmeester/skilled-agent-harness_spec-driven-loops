This release gives the Human Voice Rules a workflow. The workflow applies them to writing. Three parts define how that work is carried out. They are a scope gate and a scanner that reads the standard directly. A required verification record is the third part.

## Why This Release

The rules had long been in `sk-doc/shared/references/`. Hundreds of files pointed to them. Nothing ran them.

## What's New at a Glance

- **The scope gate runs before edits.** `references/scope-and-exemptions.md` decides which spans the standard governs.
- **`scripts/hvr_scan.py` reads from `hvr-rules.md`.** The packet does not carry a copied term list.
- **Scoring resolves overlapping matches.** Precedence arithmetic stops double-charging.
- **Rewrites have a completion gate.** The workflow requires a fresh scan before an edit is considered finished.
- **A report template captures the review record.** It includes mechanical results and reader judgment.
- **The standard's location does not change.** Its established address is kept for the files that use it.
- **A permitted use can appear as a finding.** The scanner over-reports on purpose.
- **Mechanical scores do not replace a reader.** The scanner distinguishes mechanical findings from qualities that need judgment.
- **Long references use a different score view.** The report changes its measure for long documents.
- **A thin parse fails closed.** The scanner does not report a clean result when it has not read enough of the standard.
- **The audit and voice method have separate owners.** No alias moved between them.

## Scope and Scanning

#### Scope Excludes Protected Text

Quotations, error strings, commands and code are outside scope. So are generated files, released changelog entries and byte-pinned fixtures. A voice edit to any of them is a defect. It is not an improvement.

&nbsp;

#### The Scan Follows Its Source

On every invocation, `scripts/hvr_scan.py` reads its rules from `hvr-rules.md`. Those rules are the punctuation bans and hard blocker words. They also include phrase blockers and soft deductions. The packet holds no copy of any term list. So editing the standard changes the scan. Nothing else needs an update.

&nbsp;

#### Overlapping Terms Cost Once

One occurrence costs one penalty. The longest matching term claims the span. A word can be listed as an extended blocker and as context-dependent. It is charged once, as the blocker. A transition costs a point only from its third use onward.

&nbsp;

#### Rewrites Need a Full Record

Rewriting to remove a tell introduces new ones. A single after-score proves nothing about what the pass did. A rewrite is not finished until the scanner has run again on the new text. Both numbers have to be reported. The report template carries the exemptions, both scan numbers, judgment findings and accepted exceptions.

## Reading Scan Results

#### Allowed Uses Can Be Flagged

`sk-create-repo-rule/README.md` was written to this standard and reviewed before it shipped. Scanning it finds two hard blockers. Both are `harness` used as a noun for the AI runtime. That is the literal sense the standard permits. Two recorded exemptions mean no edit. A scanner that guessed at word sense would start hiding real findings.

&nbsp;

#### Scores Leave Room for Readers

A clean mechanical result is not a clean document. Structure, rhythm, synonym cycling, significance inflation and personality need a reader. The scanner prints that list on every run so the two are never confused.

&nbsp;

#### Long References Change the Measure

The 100-point scale assumes a piece of writing, not a 900-line reference. Past roughly 400 lines the report switches to hard blockers plus deduction density. It says which measure it used.

&nbsp;

#### A Thin Parse Stops the Scan

A parse thinner than its floors stops the run with exit 2. It does not report a clean scan from a standard it never read. Renaming a section heading in the standard triggers this. Renumbering one does not because the parser keys on titles.

## Standard and Audit Boundaries

#### The Standard Keeps Its Path

The standard stays at `.opencode/skills/sk-doc/shared/references/hvr-rules.md`. Hundreds of files carry this path. Most of them are frozen spec documents, plus a spec-kit golden snapshot. Relocating it would rewrite shipped history and break a test suite. The gain would be a tidier folder.

&nbsp;

#### Audit and Voice Work Separate

`sk-create-quality-control` keeps the file-level audit and its `HVR` routing vocabulary. This mode owns the voice method that step performs.
