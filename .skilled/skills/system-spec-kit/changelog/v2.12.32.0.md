# v2.12.32.0, Docs Read in Order and Render as Written

The skill's `SKILL.md`, `ROUTER.md`, `README.md`, its assets, references and shared module READMEs were read file by file for readability, layout and structure. No validation rule, command, template contract or source citation changed.

> Spec folder: `specs/sk-doc/066-skill-readability-refinement/013-system-spec-kit` (Level 1)

&nbsp;

## What's New at a Glance

- **Overviews open with their purpose and when to use them.** Reference and asset files gain the Purpose and When to Use subsections their template asks for, and eight Purpose sections now say why the file exists instead of repeating its intro.
- **Sections sit in the order a reader uses them.** The complexity matrix gives the dimension signals before the score-to-level table, folder routing lists bypass options before the interactive prompt, the decision format explains dual-threshold validation before its examples, the rename pattern warns about case sensitivity before the workflow, and related resources close every file.
- **The auto-mode contract has integer sections.** Its three-tier flow is now part of the overview, so the PRE-BOUND schema stays section 2 and every other section keeps the number commands already cite.
- **Packed paragraphs became lists.** The sub-folder versioning note and the other dense passages now read one fact per line, and the agent I/O contract keeps its compatibility rules in its contract-status section.
- **Dead traceability tables are gone.** The two decision matrices no longer map requirement ids to a `spec.md` the skill does not have, and history notes keep what happened without naming the packet.
- **One path is corrected.** The shared IPC README names `runtime/advisor-server.ts`, where the advisor server lives.
