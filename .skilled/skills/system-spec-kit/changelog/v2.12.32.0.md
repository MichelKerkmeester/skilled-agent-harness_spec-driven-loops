# v2.12.32.0, Docs Read in Order and Render as Written

The skill's `SKILL.md`, `ROUTER.md` and `README.md` were read file by file. So were its assets, references and shared module READMEs. The reading looked at readability, layout and structure. No validation rule, command, template contract or source citation changed.

> Spec folder: `specs/sk-doc/066-skill-readability-refinement/013-system-spec-kit` (Level 1)

&nbsp;

## What's New at a Glance

- **Overviews open with their purpose and when to use them.** Reference and asset files gain the Purpose and When to Use subsections their template asks for. Eight Purpose sections now say why the file exists. They do not repeat the intro.
- **Sections sit in the order a reader uses them.** The complexity matrix gives the dimension signals before the score-to-level table. Folder routing lists bypass options before the interactive prompt. The decision format explains dual-threshold validation before its examples. The rename pattern warns about case sensitivity before the workflow. Related resources close every file.
- **The auto-mode contract has integer sections.** Its three-tier flow is now part of the overview. So the PRE-BOUND schema stays section 2. So every other section keeps the number commands already cite.
- **Packed paragraphs became lists.** The sub-folder versioning note now reads one fact per line. So do the other dense passages. The agent I/O contract keeps its compatibility rules in its contract-status section.
- **Dead traceability tables are gone.** The two decision matrices no longer map requirement ids to a `spec.md` the skill does not have. History notes keep what happened without naming the packet.
- **One path is corrected.** The shared IPC README names `runtime/advisor-server.ts`. That is where the advisor server lives.
