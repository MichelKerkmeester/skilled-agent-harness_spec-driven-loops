# v3.4.0.0, Memory That Actually Sticks

This release changes how the system remembers things between sessions. Your memory now lives inside the spec documents you already track. Picking up where you left off is faster, more reliable and easier to reason about.

Alongside the memory rewrite, the search stack got smarter, the code graph got safer to traverse and the deep-loop skills became fully auditable. The CLI skills now check prompt quality before they call external models.

A cleanup pass on the skill advisor removed dead routing code and added coverage for the kinds of phrases people actually type. The intake command surface also consolidated around a shared intake contract.

> Spec folder: `.opencode/specs/system-spec-kit/026-graph-and-context-optimization/`

## Why This Release

Memory used to sit in standalone files beside the spec documents. That meant separate files to maintain and a parallel history that could drift against the record. Keeping continuity in the spec documents gives the record one place and leaves no parallel tree to keep in sync.

## What's New at a Glance

- **Continuity lives in the spec docs.** The old `memory/*.md` files are retired.
- **Every spec folder has a machine-readable identity.** Its `graph-metadata.json` file makes the spec tree navigable by tools, not just by humans reading markdown.
- **Continuity commands got simpler.** `/spec_kit:handover`, `/spec_kit:debug` and the `@handover` and `@speckit` agents are retired.
- **`/spec_kit:start` is gone.** Intake now runs through `/spec_kit:plan --intake-only`.
- **You pick the embedding provider.** The search stack is no longer hardcoded to a single backend.
- **The live cross-encoder path is on Voyage `rerank-2.5`.** Long documents no longer lose ground just for being long.
- **Continuity search has its own tuned profile.** It is built for picking up where you left off.
- **Every code graph edge names the detector that found it.** Traversal won't explode on big graphs, and multi-file queries are first-class.
- **The skill advisor catches missing skills before they ship.** A cleanup fixed 36 broken routing keys and added 15 new phrase routes.
- **Every deep-loop stop has a name.** Convergence runs on a real coverage graph, and parallel sessions no longer collide.
- **Review and research folders always sit at the spec root.** They no longer land inside nested child phases.
- **Every external CLI call gets a pre-flight prompt check.** Complex prompts escalate to a shared helper agent.

## Memory and Commands

#### No More Memory Folders

`[spec]/memory/` directories are no longer created, and new spec folders never get one. Older ones stay on disk as a read-only archive, so nothing gets deleted out from under you. The code that wrote those files is gone and the save workflow no longer renders them. Indexing now flows directly through your canonical spec docs.

The old 589-line memory template is deleted. Four checklist templates lose their "Findings saved to memory/" row, and the legacy test fixtures migrated over.

&nbsp;

#### Every Save Finds Its Document

Session notes, decisions and handover hints now go into the spec documents. Every save routes into the right document automatically. Decisions land in `decision-record.md`, progress updates land in `implementation-summary.md` and handover notes land in `handover.md`. A content router picks the destination without you thinking about it.

Session resume checks one clear order. It reads `handover.md` first, then the `_memory.continuity` block inside `implementation-summary.md`, then the spec docs themselves. The first source with useful content wins.

Quick session notes skip the full save pipeline. The AI can edit the continuity block directly, and the full indexed save is reserved for work that needs database visibility. Session stop hooks autosave by default, so shutting a session no longer loses context. Five validation checks run before every save, and a broken save rolls back instead of corrupting your spec folder.

&nbsp;

#### A Metadata File per Folder

Each `graph-metadata.json` describes what its folder holds, what it depends on and what it relates to. The file has two sections. A `manual` block is where you declare relationships (`depends_on`, `supersedes`, `related_to`). A `derived` block auto-refreshes with trigger phrases, key files, entities, status and timestamps.

Saves refresh the metadata automatically. Your manual relationships are preserved while the derived half regenerates on its own.

Search, ranking and the causal graph all use this file. Searches surface packet roots directly, ranking respects the relationships you have declared and graph queries traverse the tree in a single lookup. Entity extraction is clean and bounded: shell commands are filtered out, long or multi-line names are rejected and there are no duplicates. The initial backfill populated 515 spec-folder roots.

&nbsp;

#### Shared Memory Fully Removed

The dead shared-memory subsystem's handlers, storage, governance flags, four MCP tools and all related aliases are deleted. A one-time cleanup runs on startup to drop the stale database column if it is still there.

&nbsp;

#### Fewer Commands and Agents

The two wrapper commands and two exclusive-writer agents retired in this release became redundant once continuity moved into canonical spec docs. The agents are gone across all four runtimes, 15 paths total.

The old `@speckit` exclusive-writer rule is replaced with a distributed governance rule. Any agent writing spec folder docs must use the provided templates, run strict validation after every write and route continuity through `/memory:save`. `@deep-research` and `@debug` keep write access only for their own specific files. `/memory:save` becomes the canonical maintainer of the handover log.

`/spec_kit:complete` loses its `:auto-debug` flag. If implementation fails three times, the workflow surfaces the diagnostic and you decide whether to dispatch `@debug` yourself.

&nbsp;

#### One Intake Contract

The `--intake-only` flag on `/spec_kit:plan` is backed by a shared intake contract. That contract consolidates three parallel intake surfaces into one canonical module.

## Search and Ranking

Scoring no longer runs on one hardcoded profile, and save routing is smarter on mixed content.

#### Your Choice of Embedding Backend

The checked-in configs in `.mcp.json`, `.claude/mcp.json`, `.vscode/mcp.json` and `opencode.json` now share `EMBEDDINGS_PROVIDER=auto`. The same repo can run with the default cloud path or a local fallback without rewriting config.

&nbsp;

#### A Reranker Tuned for Real Results

`getRerankerStatus()` now reports `hits`, `misses`, `staleHits` and `evictions`. That makes cache behavior visible when a result moves.

`applyLengthPenalty` still exists for compatibility, but it now resolves to a neutral `1.0`. Long handover and implementation docs keep their place when they are the best match.

Stage 3 reranking also waits for enough evidence to matter. The cutoff moved from 2 results to 4, and the same boundary now holds for both the cloud reranker and the local reranker path.

&nbsp;

#### Weights Tuned for Resuming Work

Resume-style lookups use `0.52 / 0.18 / 0.07 / 0.23` weights for semantic, keyword, recency and graph signals instead of reusing the generic weights. The profile was checked against a judged 12-query continuity fixture, which kept the baseline `K=60` recommendation.

&nbsp;

#### Causal Lineage Keeps Anchor Detail

Two links between the same docs can now stay separate when they point at different sections. Schema version `26` added `source_anchor` and `target_anchor` to `causal_edges` to make that possible.

## Code Graph

Traversal is tighter and easier to trust in multi-file work.

#### Richer Answers, Same Trust Boundaries

Bounded traversal stays scoped to graph-owned outputs, not every startup surface. You get richer code-graph answers, but the trust boundaries from the other graph packets still stay in place.

&nbsp;

#### Edges That Carry Real Provenance

Every node and edge can now carry a real source label instead of a loose parser string. The runtime serializes a dedicated detector-provenance vocabulary, with a compatibility mapper back to the older `ParserProvenance` names so existing surfaces do not break.

Graph-local results also carry better evidence. Shared payloads can now include `edgeEvidenceClass` and `numericConfidence`, which makes it easier to tell whether a relationship came from strong structural evidence or a weaker graph-local guess.

&nbsp;

#### Union Queries Across Many Files

Multi-file union is now a real mode instead of an implied merge. `unionMode: 'multi'` combines several source files without duplicate results. High-degree files add a `hotFileBreadcrumb`, so you can see when one file is dominating the walk.

## Skill Advisor

The production skill graph that powers routing is hardened and future-proofed.

#### Missing Skills Fail the Build

If a skill is referenced but not defined, the compiler fails the build fast. Previously missing edges on central skills are filled, and bad sibling pairings are removed.

The compiler emits intent signals and prerequisite relationships into the runtime graph, so callers can tell whether a match came from a graph signal or a direct keyword hit. All 21 per-skill metadata files migrated to schema v2 with new derived blocks. The compiler stays compatible with the old format during the transition, so nothing breaks mid-migration.

&nbsp;

#### Routing Keys in the Right Dict

The advisor's broken routing keys were multi-character keys sitting in the wrong routing dict, where they never matched anything because of how the tokenizer works. All of them are removed from it. 33 moved into the right dict (the one that matches multi-word phrases), and three were dropped because the same routing already existed at a higher weight.

One conflicting routing was resolved. `"code audit"` used to point to two different skills in two different dicts. The version that was actually working at runtime stays and the dead pointer is deleted, so nothing changes at runtime.

The new phrase routes cover identifiers that were going unrouted. A new inline comment warns future contributors not to put multi-word or hyphenated keys into the wrong dict.

For example, the query `"5-dimension agent scoring"` used to misroute to `sk-prompt` at 0.77 confidence through a weak keyword hit on `scoring`. After the fix it routes to `sk-deep-agent-improvement` at 0.95.

## Deep-Loop Skills

The runtime behind the deep-research and deep-review skills is now ready to scale. An offline optimizer can tune configs against real traces without ever touching production.

#### An Audit Trail for Every Stop

The deep-loop runtime now records stop decisions in a form you can inspect. Each named reason comes from the same small taxonomy: `converged`, `max_iterations`, `blocked`, `user_stop` or `error`. The legal-stop gate now checks convergence, coverage and quality together before a run is allowed to stop.

That audit trail is no longer implied by scattered notes. Blocked and claim-adjudication decisions now persist as explicit events, and the dashboards stay generated markdown backed by the same structured state underneath.

&nbsp;

#### A Coverage Graph Beneath Convergence

`deep-loop-graph.sqlite` stores nodes, edges and snapshots. Four graph tools expose gaps, contradictions, provenance chains, hot nodes and stop blockers directly instead of rolling everything up into one abstract score.

Concurrent runs on the same packet no longer share graph state by accident. The graph store now keys records by `(spec_folder, loop_type, session_id, id)`, so two sessions can write the same local node id without colliding.

&nbsp;

#### Large Targets Split Into Bounded Waves

Wave mode turns on only when the scale justifies it, at `1000+` review files or `50+` research domains. Smaller runs keep the old single-stream path. Deterministic segmentation plus keyed merge lets provenance survive the join.

&nbsp;

#### One Resolver for Artifact Folders

A shared `resolveArtifactRoot(specFolder, mode)` function walks up the directory tree to find the root parent spec. When a deep-review or deep-research targets a child phase, the artifacts go to `{root}/review/{phase-subfolder}/` instead of `{child}/review/`.

Both reducers, all four command YAMLs and all eight agent definitions (four runtimes, two skills) use the shared resolver. A standalone spec with no parent behaves the same as before.

## CLI Prompt Quality

#### A Quality Card in Every CLI Skill

A lightweight quality card lives inside each CLI skill (`cli-claude-code`, `cli-codex` and `cli-copilot`), and routine prompts pass through it. Complex prompts, those flagged by a complexity score or explicit isolation signals, escalate to the shared `@prompt-improver` agent. That agent runs the full prompt-engineering methodology in a fresh context.

&nbsp;

#### Card Copies Kept in Sync

A sync script hashes the canonical card and all three mirror copies. Drift fails a local check before it reaches review.
