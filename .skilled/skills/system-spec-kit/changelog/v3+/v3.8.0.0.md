# v3.8.0.0

The system-spec-kit README moved from a tabular reference card to the purpose-first narrative standard the repo adopted for standalone skill READMEs. It now opens with the outcome the skill delivers, states the reader's situation before any feature list and keeps every shipped fact in a structure a person can scan.

## What Changed

#### The README Rewrite

- **CHANGED** The README now leads with a one-line pitch and a problem-first OVERVIEW, modeled on the mcp-obsidian pilot and the refined skill README template. AT A GLANCE opens the document, numbered ALL-CAPS sections carry the detail and capability tables state what the skill operates at the file and data level.
- **CHANGED** The validation story was corrected to the current registry state: 45 rules with four strict-only rules gated behind `--strict`, replacing the stale 36-of-38 counts.
- **CHANGED** The lifecycle diagram now reflects current Gate 3 options (Option E for skip) and the phase-parent resume pointer behavior.
- **NOT CHANGED** Every shipped behavior claim from the previous README survived the rewrite: the four documentation levels, the phase parent lean trio, the packet-local changelog workflow, the five retrieval channels, the FSRS decay tiers, the save arbitration outcomes, the hardening defaults, the launcher recycle error codes and the full script inventory.

#### Version and Changelog

- **CHANGED** The README frontmatter version moves from `3.6.0.99` to `3.8.0.0`, the next version after the latest changelog entry (`v3.7.1.0`). The README version now reads the current release state of the skill documentation.
