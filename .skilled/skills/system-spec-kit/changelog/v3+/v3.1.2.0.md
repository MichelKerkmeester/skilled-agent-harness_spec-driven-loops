This release completes the full ESM module compliance migration for the Spec Kit workspace. `@spec-kit/shared` and `@spec-kit/mcp-server` move from CommonJS to native ESM, while `@spec-kit/scripts` keeps CommonJS with proven interop.

The release also hardens the memory save pipeline, fixes the MCP schema that blocked Copilot CLI and eliminates every test skip and failure.

A deep code review by GPT-5.4 agents then found 18 more issues that the migration itself missed. This release fixes all of them. The work ran in six phases.

> Spec folder: `.opencode/specs/system-spec-kit/023-hybrid-rag-fusion-refinement/` (Level 2)

## Why This Release

The goal is to make the workflow easier to follow and easier to trust.

## What's New at a Glance

- **`@spec-kit/shared` and `@spec-kit/mcp-server` declare `"type": "module"`.** Both compile with `module: "nodenext"` and `verbatimModuleSyntax: true`.
- **Node 25's native `require(esm)` connects the CommonJS scripts to the ESM packages.** No explicit interop helpers are needed.
- **`@spec-kit/mcp-server` exports only `./api` and `./api/*`.** Internal modules no longer resolve through the package name.
- **Manual memory saves have a fallback when `generate-context.js` is unavailable.** They can write with deferred indexing instead of being blocked.
- **Memory saves can reference child phase folders.** The V8 quality rule no longer treats them as foreign spec contamination.
- **Copilot CLI can connect to the MCP server.** Exported tool schemas no longer use `.superRefine()` or `z.union()`.
- **Importing `@spec-kit/mcp-server` no longer starts a server.** The server only starts when its file is run directly.
- **A missing validation module blocks the save.** It surfaces a clear "build scripts first" error.
- **Duplicate detection respects governance scope.** Another tenant's data can no longer flag a memory as a duplicate.
- **File-write failures after a save get their own warning category.** Callers can tell them apart from cosmetic anchor warnings.
- **`--help` and `--version` exit immediately.** They no longer load the database stack first.

## Native ESM Packages

#### Shared Package Emits Real ESM

The shared package had no `"type": "module"` declaration, inherited the root CommonJS compiler baseline and had 48 relative imports without the `.js` extension specifiers that Node ESM requires. As a result, it emitted CommonJS output even though its source used ESM-style import syntax.

All 48 imports now use `.js` specifiers. `config.ts` and `paths.ts` use `import.meta.dirname` in place of `__dirname`, and the build script runs `tsc --build` instead of a no-op echo. `engines` moves to `>=20.11.0` for `import.meta.dirname` support.

&nbsp;

#### 839 Server Imports Made ESM-Safe

The mcp_server package had 839 relative import and export statements without `.js` extensions, which made them invalid under Node ESM resolution. It also lacked `"type": "module"` and inherited the root CommonJS compiler settings.

All 839 extensionless imports across 181 files are rewritten. Five parallel GPT-5.4 codex agents did the rewrite, each assigned an exclusive directory scope to prevent file conflicts.

&nbsp;

#### CommonJS Leftovers Replaced for ESM

Sixteen production files used `__dirname`, `__filename` or the bare require helper, and none of these are available in native ESM modules. Across 8 files, `__dirname` and `__filename` become `import.meta.dirname` and `import.meta.filename`. Eleven require helper calls in 6 files become lazy function-scoped `await import()` calls: archival-manager, tier-classifier, composite-scoring, file-watcher, errors/core and handlers/index.

`ground-truth-data.ts` imported a `.json` file without the `type: "json"` import attribute, which NodeNext requires. That JSON import now carries `with { type: 'json' }`.

&nbsp;

#### Imports Respect Package Boundaries

The `package.json` exports map used `"./*": "./dist/*.js"` wildcards, which exposed internal modules like `lib/search/hybrid-search.js` through the package boundary. Explicit entries replace those wildcards.

`core/config.ts` imported `../../shared/paths.js` by relative filesystem path, bypassing the expected behavior of the `@spec-kit/shared` package exports. It now imports `@spec-kit/shared/paths` instead.

## Scripts Interop and Memory Save

#### CommonJS Scripts Load the ESM Packages

Once the shared and mcp_server packages became ESM, the CommonJS scripts package could no longer load them with the require helper. Top-level `await` in 5 mcp_server modules blocked Node's native CommonJS-to-ESM bridge.

The top-level `await import()` calls in archival-manager, tier-classifier, composite-scoring, file-watcher and errors/core are converted back to lazy function-scoped imports.

&nbsp;

#### Child Phase Folders Count as Same Spec

The V8 quality rule blocked memory saves that referenced child phase folder names like `001-shared-esm-migration`. It treated them as foreign spec contamination even though they belong to the same parent spec.

The extract allowed spec ids helper in `validate-memory-quality.ts` now scans the spec folder for `NNN-*` subdirectories that contain `spec.md` and adds them to the allowed set. `related_specs` frontmatter also gains allowlist support.

&nbsp;

#### A Fallback for Manual Saves

During the ESM migration, `generate-context.js` broke because the scripts-to-mcp_server runtime chain crashed on CommonJS globals in ESM output. The sufficiency validator blocked manual memory saves via MCP, with primary evidence at 0. No fallback existed.

`memory-save.ts` now adds a manual-fallback source classification. It allows the write with deferred indexing when support evidence is at least 3 and anchors are at least 1. `markdown-evidence-builder.ts` is expanded to parse primary evidence from the `Key Decisions`, `Next Steps`, `Outcomes` and `Implementation State` sections.

&nbsp;

#### Workflow No Longer Hard-Depends on the Server

`workflow.ts` had a top-level runtime import of `retryManager` from `@spec-kit/mcp-server/api/providers`. That created a hard dependency that crashes when mcp-server is mid-migration.

A lazy adapter replaces it. The adapter imports the module dynamically and falls back to a no-op implementation with a warning when the module is unavailable.

&nbsp;

#### Validation Bypass Raises a Warning

When the scripts validator module failed to load, the v-rule bridge returned `null`, which made `memory-save.ts` silently skip all quality validation. Saves proceeded without any V-rule enforcement.

The bridge now returns a structured `{valid: true, _unavailable: true}` signal and gains the is vrule bridge available helper. `memory-save.ts` detects the flag and adds a warning to the response.

&nbsp;

#### Search Weights Found in ESM Builds

`vector-index-store.ts` resolved `search-weights.json` under `SERVER_DIR/configs/`, but in ESM mode `SERVER_DIR` points to `dist/` through `import.meta.dirname`. The config file only exists at the package root, not in `dist/`.

Path resolution now falls back: it tries `dist/configs/` first, then `../configs/` at the package root.

## Schemas and Code Standards

#### Schemas That Copilot CLI Accepts

Four MCP tool schemas used `.superRefine()`: `shared_space_upsert`, `shared_space_membership_set`, `shared_memory_status` and `memory_search`. That call generates `oneOf` and `anyOf` in JSON Schema output. GPT's function calling API rejects schemas with these constructs at the top level, which completely blocked Copilot CLI from connecting to the MCP server.

The validation logic moves into the handlers, where the runtime checks such as `validateCallerAuth` and handler-level guards already existed. `.describe()` hints now guide AI callers.

&nbsp;

#### Lazy Imports Aligned to sk-code-opencode

Lazy import patterns introduced during the ESM migration had inconsistent error handling. Some swallowed errors silently, others used unsafe type casts and one used `import.meta.url` in a CommonJS context.

Composite-scoring and errors/core now log an immediate `console.warn` in their catch blocks, and memory-save and tier-classifier drop their unsafe double-casts. The CommonJS `workflow.ts` goes from `import.meta.url` back to `__dirname`. The CommonJS validate-memory-quality goes from an ESM import of `js-yaml` back to the require helper.

&nbsp;

#### READMEs Describe the ESM Setup

The shared, mcp_server, scripts, system-spec-kit workspace and handlers READMEs now carry accurate `type: "module"`, NodeNext and CommonJS interop descriptions. Their troubleshooting commands are ESM-compatible.

## Deep Review Fixes

The review's findings split into 14 required fixes and 4 improvements across runtime correctness, security, reliability and performance. Four parallel workstreams carried the fixes.

#### Safe to Import the Server Package

`import '@spec-kit/mcp-server'` called the main helper unconditionally, meaning any module that imported the package for its exports would also start a full MCP server process. This made the package unsafe to import in test harnesses or tooling.

The main helper in `context-server.ts` now sits behind an entrypoint check that compares `import.meta.url` against `process.argv[1]`.

&nbsp;

#### Two ESM Wrapper Scripts Fixed

`map-ground-truth-ids.ts` and `reindex-embeddings.ts` still referenced `__dirname`, which does not exist in native ESM. Running either script would throw a `ReferenceError`.

Both files now use `import.meta.dirname` instead.

&nbsp;

#### One Node Floor for Every Package

The root, shared, mcp_server and scripts packages each declared different `engines.node` floors. The ESM migration requires Node 20.11.0+, but not all packages enforced this.

All four `package.json` files now declare `engines.node >= 20.11.0`.

&nbsp;

#### Shared Root Export Points at the Index

`shared/package.json` had its root export pointing at `dist/embeddings.js` instead of `dist/index.js`. Anyone importing `@spec-kit/shared` without a subpath got the embeddings module instead of the full public surface.

The root export now points at `dist/index.js`, and a separate `./embeddings` subpath export is added.

&nbsp;

#### Unverified Admin Identity Gets Logged

Admin operations like creating shared spaces accepted `actorUserId` and `actorAgentId` directly from the request payload. A malicious caller could supply any identity to perform admin actions on spaces they should not control.

A trusted-transport warning now logs when caller-supplied identity is used without session binding. Full enforcement is documented as a future requirement.

&nbsp;

#### The Validation Bridge Fails Closed

When `scripts/dist/memory/validate-memory-quality.js` was not built, the V-rule bridge returned a successful "unavailable" result. Saves would succeed without any quality validation.

The bridge now returns a failure result that blocks the save. Development workflows can opt out through the `SPECKIT_VRULE_OPTIONAL` environment variable.

&nbsp;

#### Paths Bounded by the Workspace Root

The path resolver in `shared/paths.ts` walked up the directory tree looking for a `package.json` but had no upper bound. Running from an unexpected working directory could resolve the database path outside the workspace.

The new find nearest spec kit workspace root helper finds the monorepo root by its `workspaces` array. Paths outside this boundary trigger a fallback to `import.meta.dirname`-relative resolution.

&nbsp;

#### Duplicate Checks Stay in Scope

The duplicate content check queried by content hash without filtering by tenant, user, agent or shared-space scope. In a multi-tenant database, this could flag a memory as "duplicate" based on another tenant's data. The dry-run response also leaked cross-scope metadata.

The duplicate query now threads governed scope into its WHERE clause, and responses redact cross-scope metadata.

&nbsp;

#### Typed Warnings for Failed File Writes

When a memory saved to the database but the file write failed, the warning was lumped into "anchor issues." Callers could not distinguish cosmetic anchor warnings from genuine data divergence.

Warnings now carry typed categories. File-persistence failures use a `[file-persistence-failed]` prefix, exposed as a separate category in `typedWarnings`.

&nbsp;

#### One Error Pattern for Dynamic Imports

`workflow.ts` had three call sites dynamically importing `@spec-kit/mcp-server/api`, each with a different error-handling pattern. One silently returned null, another logged a warning and the third threw.

A single try import mcp api helper now serves all three, logging the failure reason and returning null. `mcp-server/api/index.ts` also gains barrel width documentation.

&nbsp;

#### Search Resolves Its Import Once

`vector-index-store.ts` used `await import(...)` inside frequently called methods. Each search re-resolved the module specifier at runtime.

A module-level cached lazy loader now resolves the import once and caches the result.

&nbsp;

#### Help Text Without the Database

`cli.ts` imported all command dependencies at the top level. Running `--help` loaded the database, vector index and checkpoint system before printing usage text.

The heavy imports now wait behind per-command handler functions.

## Upgrade Notes

- **No migration required.** Node.js `>=20.11.0` is now the minimum engine version, up from `>=18.0.0`. All existing runtime behavior is preserved. The change is in how the packages are loaded, as native ESM instead of CommonJS wrappers.
- **Development opt-out.** Setting `SPECKIT_VRULE_OPTIONAL=1` allows saves without validation during development. In production, the validation module should always be built.
