# v3.4.1.0, Now You Can Watch It Run

v3.4.1.0 brings the framework's production paths into view and makes its health easier to judge. The code graph now reads real parser output, the skill advisor runs as a daemon behind live hooks, CocoIndex handles disconnects and concurrent starts more safely, and doctor commands bring health checks into one place. The release also hardens memory continuity, graph explanations, deep-loop execution, documentation, naming and upgrade paths.

The memory migration is now complete in production, where legacy writes had remained. The code graph no longer silently falls back before reading the parser output, and startup payloads that three of four runtimes had been dropping are restored.

## Why This Release

The doctor commands, trust badges, freshness indicators and telemetry surfaces this release adds are all built so a single command can answer "is this thing healthy right now?"

## What's New at a Glance

- **Memory saves now start with a plan.** Eight save-flow defects are fixed, and the default is a non-mutating dry run with a full-auto fallback.
- **The code graph reads the real parser output.** The production scan recovers roughly 11 times more nodes than the old fallback.
- **`/doctor:code-graph` diagnoses and repairs graph problems.** Its modes report health or offer verification-gated repair with rollback.
- **Graph results explain their connections and trust.** Edges carry explanations, memory results carry trust badges and stale graphs block impact analysis.
- **The Skill Advisor now runs as a native daemon.** Live hooks and an MCP surface use the same advisor behavior.
- **Causal-graph routing reaches short, natural queries.** The graph channel can serve decision and spec searches at any query tier.
- **Deep loops can emit resource maps and choose executors.** Research and review can attach an evidence-based map and select a native or CLI executor.
- **CocoIndex survives common disconnect and startup failures.** Its logs, shutdown and concurrent starts now have bounds.
- **The Multi-AI Council has a complete output contract.** Its state, completion advice and scoped artifact writes have defined behavior.
- **Names and discovery now match the shipped surfaces.** Skills, agents and runtime directories use updated names, and description budgets have guardrails.
- **Manual testing playbooks use natural-human prompts.** Three new playbooks add 66 scenarios, and all 16 playbooks use the revised voice.
- **CLI and doctor entry points are consolidated.** `cli-copilot` is retired, `cli-codex` is the cost-optimized default, and doctor targets use the new positional surface.

## Memory Continuity

The memory migration from v3.4.0.0 was only half complete in production. This release closes the remaining write paths and corrects defects in save and search behavior.

#### Canonical writes and safer saves

Five legacy write paths to `[spec]/memory/*.md` are retired, leaving canonical spec documents as the write surface. 183 stale memory-file rows from prior runs were pruned, along with 1,141 dependent causal edges that referenced them. `/memory:save` now defaults to a planner-first, non-mutating dry run with full-auto fallback, and four ancillary subsystems that previously fired on every save now run only when their opt-in environment flags are set.

Eight JSON-mode save defects are fixed. The corrections cover truncation boundaries, junk phrases in synthesized trigger phrases, predecessor discovery for causal lineage, post-save verification and metadata drift after partial failures.

&nbsp;

#### Gates catch save drift

Six gates run before a save: spec-document structure, anchor parity, trigger-phrase sanity, canonical paths in `key-files`, status derivation and continuity-pointer integrity. A failing gate is surfaced instead of allowing a corrupt save.

&nbsp;

#### Search defects are catalogued

A 17-bug catalogue records memory-search runtime defects. Three P0 defects were fixed in this release: a truncation-wrapper sanity check, a confidence floor for the intent classifier (it had been routing at 0.098 confidence in some traces) and enforcement against forbidden synthesized phrases. The other 14 P1/P2 defects are documented for follow-on remediation.

&nbsp;

#### The memory-indexer review

A deep-review of the memory-indexer packet returned a CONDITIONAL verdict. A live MCP rescan blocker (CHK-T15) gates the FINAL release until verified on a freshly restarted daemon.

## The Code Graph

The code graph was missing 60 to 80 percent of the symbols in a codebase because its production parser path was not running. This release restores parser-backed scans and adds diagnostics, freshness details and more resilient query behavior.

#### Production scans recover symbols

The tree-sitter grammar path pointed to the source tree rather than the compiled `dist/` location, so production silently used a regex fallback. Broad scans now return 56,843 nodes instead of the fallback's 5,000, recovering roughly 11 times more symbols.

Broad-scan crash rate fell from 17.5% to 0.72%, a 24x improvement, and a 9,314-file scan ran with zero B2 cascades. Whole-repo scans now complete reliably and the previous broad-scope failures are gone.

&nbsp;

#### One command checks graph health

`/doctor:code-graph` has `auto`, `confirm` and `apply` modes. Auto and confirm report parser status, scan freshness, scope coverage and known stale areas without changing data. Apply offers verification-gated repair. It runs a 28-query gold battery before and after each operation and restores the last known-good snapshot when the post-flight battery fails. Its operations map to a three-procedure recovery playbook covering SQLite corruption, partial-scan failure and bad-apply rollback, with exclude rules tiered by high, medium and low confidence.

&nbsp;

#### Freshness and scope are visible

Code-graph responses now carry freshness status and highlight stale graphs. Default excludes skip `z-future/`, `z_archive/` and CocoIndex internal paths unless explicitly requested. `.gitignore` entries are honored and multi-file queries deduplicate results across files.

The code-graph package is now self-contained at `mcp-server/code-graph/`. Five hardening areas address scan idempotence, query timeouts, error recovery, diagnostic accuracy and test isolation.

&nbsp;

#### Hook results carry graph context

`CALLS` resolution now handles fully qualified names when symbol names collide. Blocked reads return a typed `BlockedResult` with an explicit reason, and CocoIndex ranking fidelity is preserved through the response path. Startup payloads expose `graphQualitySummary` across the four runtime surfaces.

&nbsp;

#### Three production paths tightened

- **Indexer scope matches the plural roots.** `mcp-server/lib/utils/index-scope.ts` now aligns code-graph indexing to the plural `.opencode/skills/`, `.opencode/agents/` and `.opencode/commands/` roots, so newly-shipped files are picked up.
- **Layer coverage is complete.** `mcp-server/lib/architecture/layer-definitions.ts` adds `memory_retention_sweep` to the L4 mutation-tool registry.
- **Diagnostics move off the MCP channel.** `mcp-server/code_graph/lib/structural-indexer.ts` now logs through `console.error` instead of `console.info`, keeping MCP stdio responses clean across runtime surfaces.

## Graph Impact and Trust

Eight packets shipped under graph impact and affordance uplift.

#### Edges explain their impact

Edges can carry `reason` and `step` metadata, and `blast_radius` returns depth groups, risk levels, confidence filtering and ambiguity candidates. The result explains why files are implicated rather than presenting a flat list.

&nbsp;

#### Memory results show their trust

Memory-search results now carry per-result confidence, age and orphan-state badges derived from causal-edge data. An orphan result is a memory row with no incoming or outgoing edges.

&nbsp;

#### Stale graphs stop impact analysis

The read-only `detect_changes` preflight blocks impact analysis when the graph is stale and tells the caller to rescan. It no longer returns an impact map from stale graph data.

&nbsp;

#### Affordances use existing routes

Tool and resource affordances now flow through existing scorer lanes after sanitization rather than expanding the graph vocabulary. This lets the advisor route on needs such as a skill requiring CocoIndex or writing to the spec folder.

&nbsp;

#### License posture is recorded

A clean-room adaptation audit cleared the governance posture for the remaining external work and recorded PolyForm Noncommercial 1.0.0 as the operating license for the affected packets. Umbrella docs across the root README, MCP server docs, install guide, feature catalogs and testing-playbook indexes were updated to describe the shipped behavior.

## Skill Advisor

The advisor now has a native daemon runtime that uses the routing dictionaries v3.4.0.0 cleaned up and the graph compiler it shipped. It also serves live prompt hooks and an MCP interface.

#### A daemon serves recommendations

A native daemon now backs the advisor with watcher-driven freshness and a single-writer lease to prevent concurrent processes from corrupting the compiled graph. The previous Python script and OpenCode plugin paths still work and route through compatibility shims to the native behavior. The new MCP tools are `advisor_recommend`, `advisor_status` and `advisor_validate`, making the advisor a first-class tool instead of a hook-only side effect.

&nbsp;

#### Live hooks fail open

`UserPromptSubmit` hooks in Claude, Copilot and Codex call `buildSkillAdvisorBrief(prompt, {runtime})` and emit sanitized recommendations with freshness, confidence and uncertainty fields. Errors return `{}` so an advisor failure does not block a prompt. A reference doc at `.opencode/skills/system-skill-advisor/hooks/skill-advisor-hook.md` documents the contract.

&nbsp;

#### Scoring and routing are aligned

The five-lane fusion scorer is now written in TypeScript. Family affinity and graph-derived transitive boosts flow through the scorer.

The smart router cleans up stale routes, validates the router statically in CI, tunes `ON_DEMAND` keywords, asks for disambiguation on `UNKNOWN` instead of silently falling back to a CLI, and keeps telemetry observe-only. Its OpenCode plugin `spec-kit-skill-advisor` uses the same producer and renderer as the hooks. The plugin keeps per-instance closure state instead of sharing module state across plugin instances, deduplicates in-flight bridge calls so concurrent identical cache misses share one bridge call and bounds payloads with cache LRU eviction. `ON_DEMAND` hit rate rose from 5.5% to 48.0%.

&nbsp;

#### Advisor setup has a command

`/doctor:skill-advisor` analyzes the current skill set, optimizes advisor scoring tables and re-indexes the skill graph. A standards pass aligned metadata across 21 skill files and closed routing inconsistencies that had accumulated as the advisor evolved.

The ambiguity detector now flags a candidate when either the score gap or the confidence gap is at most 0.05. Previously it used the score gap alone.

## Causal Graph Routing

The causal-edge graph holds 1,328 live edges. Before this release, the graph channel only ran for complex queries with more than eight terms, leaving it unused on natural one-to-five-term queries.

#### Short queries reach the graph

The router now activates the graph channel for `find_decision` and `find_spec` intents at any tier. It also activates for entity-rich queries that name memory rows with three or more outgoing causal edges.

The override sits above the tier classifier, so telemetry tier assignments stay stable while the graph channel serves the newly eligible queries. `memory_health.data.routing.graphChannelInvocationRate` reports channel use over a 200-decision rolling buffer.

&nbsp;

#### The graph-channel override has an opt-out

`SPECKIT_GRAPH_CHANNEL_PRESERVATION` is on by default and allows opt-out. Routing latency stays under 5 ms at p99. Live runs show graph-channel invocation at 0.625 after the new gates take traffic, well above the 0.30 floor.

## Deep Loops and Shared Artifacts

Deep research and review gained a resource map at convergence and a configurable execution path. The changes reuse evidence already captured by the loop runtime.

#### Convergence emits resource maps

`resource-map.md` is a new spec document containing a flat inventory of files touched by a packet. It is a template alongside `handover.md`, `debug-delegation.md`, `research.md` and `decision-record.md`.

`sk-deep-review` and `sk-deep-research` emit maps at convergence. Review maps carry P0/P1/P2 finding counts, while research maps carry citation counts per iteration. Both use evidence the loop runtime already captures, with no new scan cost. 135 child packets were migrated to local-owner folders for the new template, 155 canonical references were rewritten across the docs surface and 541 spec-folder packets were refreshed with the new graph metadata.

&nbsp;

#### Deep loops can choose executors

`sk-deep-research` and `sk-deep-review` previously hardcoded `model: opus` and disallowed CLI-in-a-loop execution. Their YAML dispatch now supports `native`, `cli-codex` and `cli-claude-code` as executor choices, with configuration validation for executor-specific flags.

Markdown prompt packs are executor-agnostic, and model-specific directives are stripped at dispatch. The native execution path is byte-for-byte identical to the v3.4.0.0 baseline.

## Spec Authoring

The old Level 1, Level 2, Level 3 and Level 3+ taxonomy combined line count, capability set and template shape into one flat dimension that did not scale to phase parents, audit packets or research-only packets. The new manifest separates those concerns and provides a shared source for scaffolding and validation.

#### A manifest replaces the flat taxonomy

The Level 1/2/3/3+ taxonomy is being retired. A C+F hybrid manifest-driven framework puts capabilities and presets in `spec-kit-docs.json`, which both scaffolders and validators read. The PARTIAL backward-compat framing was rejected, and five ADRs formalize the decisions.

The framework distinguishes human-authored scaffold documents from command- or agent-owned lazy add-ons. The implementation plan has four phases: add the manifest and resolver (shipped), modify the scaffolder, modify the validators and delete the legacy taxonomy code. The validator stays inclusive of legacy phase parents during the transition. 86 source files collapse into roughly 15 manifest files in the new design.

&nbsp;

#### Authoring references match current behavior

The sweep updated stale references in `SKILL.md` and skill-bundled assets. It also added brief coverage of `SPECKIT_POST_VALIDATE`, exit codes, path hardening, save locking, batch inline rendering and phase-mode syntax.

Three more sweeps ran in parallel: command markdown and YAML alignment, fleet-wide validation of `SPECKIT_LEVEL` and `SPECKIT_TEMPLATE_SOURCE` markers and a separate sweep over the `z_archive/` corpus.

## CocoIndex Daemon Resilience

The `mcp-coco-index` daemon leaked processes and log volume under load. Disconnect handling, concurrent starts and shutdown now have bounded behavior.

#### Disconnects no longer spiral

Stale daemons had held 244 open file descriptors, and client disconnects caused CPU spikes of about 90% while tracebacks were formatted. Broken-pipe handling now lets the daemon survive client disconnects instead of crashing the writer again.

&nbsp;

#### Logs have a fixed ceiling

Logs are limited to 10 MB per file with five backups, for 60 MB total. A logging double-write was also fixed so each line is not written through both stream and file handlers unless the stream is a TTY.

&nbsp;

#### Concurrent starts converge

Concurrent starts now use an atomic PID-file lock on POSIX and Win32, with sibling detection inside the lock before the PID is written. The listener backlog rose from the standard-library default of 1 to 128 so 16-way client storms queue at the OS level instead of failing with connection-refused.

Shutdown now has a 10-second task-join limit. One recovery procedure covers a half-stuck daemon, a fully stuck daemon or duplicate daemons.

## Multi-AI Council

The Multi-AI Council now has an explicit output protocol, state contract and artifact boundary. Its runtime artifacts can be checked without turning the advisory checker into a blocking gate.

#### Council outputs have a contract

The agent now documents the output protocol, invocation contract, state schema, convergence signal, caller-persistence protocol and summary. Four shared references under `system-spec-kit/references/ai-council/` cover folder layout, seat-diversity patterns, convergence signals and JSONL state format.

The v1.1 state metadata adds `schema_version`, `protocol` and `producer` fields while remaining readable by v1 readers. `--memory-save-payload-out` writes a memory-save payload only when requested.

&nbsp;

#### Completion advice stays advisory

`advise-council-completion.cjs` reports missing artifacts, missing reports and seat-count mismatches. It always exits 0 so it can run in pre-commit hooks without gating strict validation.

&nbsp;

#### Writes stay inside council artifacts

The council writes to its own `ai-council/**` artifact tree. Permission across the three runtime mirrors is `write: allow / edit: allow` and `bash: deny / patch: deny`. The writer rejects an out-of-bounds target with `OUT_OF_SCOPE_WRITE`.

The audit trail adds `artifact_written` and `rollback` event types in v1.2, and v1 readers continue to parse v1.2 files. A round-NNN folder is the rollback unit: on a seat error or convergence failure, that round's artifacts move to `failed/round-NNN-<timestamp>/` and the audit trail marks them with `superseded_by: "rollback"`. Three ADRs document the write-permission model, the audit-trail schema and the rollback semantics.

## Names and Discovery

Names now match the skills and agents' roles, and descriptions fit back under Claude Code's discovery budget. New guardrails make future description changes easier to audit.

#### Renamed skills and agents

`sk-improve-prompt` is now `sk-prompt`, `@improve-prompt` is now `@prompt-improver`, and `@improve-agent` is now `@deep-agent-improvement`. `sk-prompt` aligns with the single-capability skill family of `sk-code`, `sk-doc` and `sk-git`. `@prompt-improver` follows the noun-form agent family of `@code`, `@review`, `@debug` and `@orchestrate`. `@deep-agent-improvement` aligns with the underlying `deep-agent-improvement` skill and the `/deep:start-agent-improvement-loop` command. The `.opencode/skill/` directory is now `.opencode/skills/`, with sibling runtime mounts using the plural form too.

&nbsp;

#### Descriptions fit the budget

Project descriptions were trimmed from 7,646 to 5,391 characters, a 42% reduction that preserves routing keywords. The result sits 209 characters below the 5,600-character project ceiling.

`/doctor:skill-budget` reports per-item descriptions, the project total, headroom and suggested trims. Its `--json` and `--fail-over=N` flags make the report scriptable for CI and pre-commit use.

Soft-target validation now sets limits of 130 characters for skill descriptions and 110 for command descriptions. Updated sk-doc authoring docs declare a hard cap of 1,536 characters and a project soft ceiling of 5,600 characters. The checks are wired into `/create:sk-skill` and `/create:agent`.

&nbsp;

#### Playbooks use natural prompts

Three manual-testing playbooks add 66 scenarios: `sk-code-review` has 17, `sk-git` has 21 and `sk-prompt` has 28. The `sk-code-review` scenarios span 6 categories covering small PR, large refactor, multi-commit, auth, injection, secrets, blockers, class-of-bug, cross-consumer, scope, baseline-vs-surface, test code, re-review, stale architecture and AI-generated suspect quality. The `sk-git` scenarios cover the worktree-to-commit-to-finish lifecycle. The `sk-prompt` scenarios span 7 categories covering mode detection, smart routing, depth/clear/loop, CLEAR scoring, framework selection, escalation tiers and format modes.

All 16 manual-testing playbooks were also rewritten from formulaic role prompts into natural-human voice. RCAF-pattern prompts are reserved for cross-CLI delegation, multi-agent dispatch and safety-refusal flows where role context determines behavior.

The prompt-equality contract remains byte-for-byte across both locations, the SCENARIO CONTRACT and the nine-column scenario table. Packets covering renames, descriptions, Multi-AI Council and testing playbooks are under `.opencode/specs/skilled-agent-orchestration/080-097/`.

## CLI and Doctor Commands

The CLI executor choices and doctor surfaces changed to make dispatch less costly and health checks easier to reach. The underlying doctor YAML workflows did not change when the markdown command surface was consolidated.

#### Copilot is retired

`cli-copilot` is retired because GitHub Copilot price increases pushed it above the cost threshold. Its entire skill tree is gone, including 50+ playbook scenarios, hooks, the matrix-runner adapter and 2 test files. References were scrubbed from 101 files across sibling `cli-*` skills, the advisor, agents, commands and root docs. The advisor no longer recommends it, and `cli-codex` is the cost-optimized default external executor.

&nbsp;

#### OpenCode dispatch closes stdin

`opencode run` could hang under stdout and stderr redirection because it reads stdin during startup and blocks when it receives no EOF. Dispatch now adds `</dev/null`. The hang had been costing 12 minutes per dispatch in stuck timeout cycles.

The EOF redirect is applied to deep-research and deep-review auto and confirm workflows, the `cli-opencode` skill and stress-test dispatch scripts. The rule is documented as a permanent ALWAYS in `cli-opencode` SKILL.md §4.

&nbsp;

#### Codex config matches 0.130

Codex CLI configuration now matches the 0.130 schema. `[features].hooks = true` replaces the deprecated `codex_hooks` key, and the hook-policy detector at `mcp-server/lib/codex-hook-policy.ts` matches both keys for transition compatibility.

Codex profiles for `codex exec -p <name>` live at user level in `~/.codex/config.toml`, where Codex actually loads them. Stale `.opencode/skill/` (singular) paths in `~/.codex/hooks.json` and the `spec_kit_memory` MCP server config are now plural.

&nbsp;

#### Doctor has three entry points

Ten `/doctor:*` markdown commands collapsed to three: `/doctor <target>`, `/doctor:mcp` and `/doctor:update`. `/doctor:mcp` takes the `install` and `debug` sub-actions. The argv-positional router covers memory, causal-graph, code-graph, deep-loop, cocoindex, skill-advisor and skill-budget through `.opencode/commands/doctor/_routes.yaml`. `/doctor:update` is unchanged.

The route manifest is the source for each target's YAML asset, setup variables, allowed flags, mutation class, MCP tool subset and Skill Advisor trigger phrases. The router reads it, CI validates it and the advisor's lexical lane indexes it. A new `route-validate.{sh,py}` script, PyYAML-based with no external `yq` required, checks that every route references an existing asset, that every `mcp_tools` entry is in the `allowed-tools` union of the router and that no target name is duplicated.

&nbsp;

#### Prompts lead with the upgrade

A user arriving from 3.3.0.0 now sees the update path as option 1 in the `/doctor` menu. All 11 interactive prompts use numeric, verb-first, one-line options, and responses accept numbers, letters or verb keywords while preserving defaults.

&nbsp;

#### Command docs match their contracts

The router, MCP and update markdown commands use H2 numbered sections instead of H1 sections and document `STATUS=OK|FAIL|CANCEL|ROLLED_BACK|RESTART_REQUIRED` values. Six of the ten doctor workflow YAMLs had been missing canonical top-level blocks, and all ten now use the canonical top-level block sequence.

The doctor-update orchestrator packet at `.opencode/specs/system-spec-kit/026-graph-and-context-optimization/010-doctor-update-orchestrator/` gained `003-router-phase/` for additive ship and `004-cutover-phase/` for hard cutover. The phase-changelog index is at `.opencode/specs/system-spec-kit/026-graph-and-context-optimization/changelog/`, with relative symlinks named `changelog-026-<phase>-<slug>.md`.

## Upgrade Notes

- **Adopt.** Use `/spec_kit:plan --intake-only` instead of the retired `/spec_kit:start`, which was removed in v3.4.0.0.
- **Adopt.** Use `cli-codex` as the cost-optimized external executor or choose `cli-claude-code`. `cli-copilot` is retired.
- **Repoint.** Update external callers from `@improve-prompt` to `@prompt-improver`, from `@improve-agent` to `@deep-agent-improvement` and from `sk-improve-prompt` to `sk-prompt`.
- **Repoint.** Change `.opencode/skill/` paths to `.opencode/skills/`. External symlinks to the singular form break and need the path changed.
- **Repoint.** Under stdout or stderr redirection, run `opencode run` with `</dev/null` so stdin reaches EOF.
- **Repoint.** Invoke `/doctor:memory`, `/doctor:causal-graph`, `/doctor:code-graph`, `/doctor:deep-loop`, `/doctor:cocoindex`, `/doctor:skill-advisor` and `/doctor:skill-budget` as `/doctor <target>`. For example, `/doctor:memory --dry-run` becomes `/doctor memory --dry-run`, and `/doctor:causal-graph --confidence-threshold=0.8` becomes `/doctor causal-graph --confidence-threshold=0.8`. Skill Advisor lexical routing handles old-form prompts through target trigger phrases in `_routes.yaml`.
- **Repoint.** Invoke `/doctor:mcp_debug` and `/doctor:mcp_install` as `/doctor:mcp debug` and `/doctor:mcp install`.
- **Keep.** `/doctor:update` is unchanged.
- **No migration required** for memory continuity. Legacy `memory/*.md` files in old spec folders remain readable as an archive, and new writes no longer flow there.
