# v3.5.0.2, Sessions Keep Their Hands to Themselves

This patch stops one session's cleanup from killing the MCP launchers of other open sessions, refuses to serve a memory index that a dirty shutdown has corrupted and salvages the live index that was already damaged. It closes a long-open case: why MCP transports kept dying mid-session even after the front-proxy work. The answer was not in the daemon at all.

> Spec folder: `.opencode/specs/system-spec-kit/026-graph-and-context-optimization/007-mcp-daemon-reliability/016-cross-session-kill-scoping/`

## Why This Release

The session-cleanup hook took its identity from `CLAUDE_SESSION_PID` and, when that was missing, guessed with the hook's parent pid. Under a shared terminal that guess resolved to an ancestor common to every open session, so "walk my descendants" quietly became "walk everyone's descendants" and one session ending would sweep away its siblings' MCP launchers by name. The result was the whole familiar failure of a dead launcher, a dirty daemon exit, a stale socket and a refused connection, all from one bad fallback. The probe work that followed found the damage was not hypothetical: the live memory index was already structurally corrupted by the dirty shutdowns the cleanup bug had been causing.

## What's New at a Glance

- **Session cleanup now needs explicit session identity.** The Stop-hook cleanup in `session-cleanup.sh` is supposed to reap only the MCP helpers of the session that just ended, and with no identity it now does nothing at all.
- **Each kill re-proves ancestry first.** Ancestry is no longer trusted from a snapshot: immediately before each kill, the script walks the candidate's live parent chain and proceeds only if it reaches this session's pid. A sibling session's process can never satisfy that, and the session's own helpers still die on schedule.
- **Every kill and skip is logged.** Each entry carries `matched_by=` and `ancestor_ok=` fields, so if a transport ever vanishes again the log answers who and why.
- **A boot after a dirty shutdown checks the whole database.** The daemon already marked dirty shutdowns with an `.unclean-shutdown` marker but only ran a detect-only check of the FTS shadow index. A marker present at open now also triggers a whole-database `PRAGMA quick_check`, and clean shutdowns skip the probe entirely, so the common case pays nothing.
- **A corrupted database is refused, never served.** On a failed check the store writes the checkpoint `.needs-rebuild` sentinel, the same crash-safe machinery checkpoints already use, and refuses to start rather than serve a silently malformed index. It fails loudly because that beats serving corrupted rows to every connected session.
- **The live index was salvaged the same evening.** Pointed at the live `context-index.sqlite`, the gate reported real b-tree damage (invalid page numbers and doubly-referenced pages) with no checkpoint to restore. `sqlite3 .recover` rebuilt a clean candidate that passed `quick_check`, kept 9,888 of 9,890 memory rows and parked 368 orphaned rows in `lost_and_found` for triage.
- **The swap is reversible by design.** The corrupted original remains on disk beside the recovered file.
- **Two flagged hardening items had already shipped.** Recording the daemon child pid in the launcher lease and reclaiming a stale bootstrap lockdir came in earlier daemon-reliability phases, and both were verified in source and recorded as no-ops.
- **The remaining root causes keep their existing owners.** The bridge liveness probe, the provider dispose and the exit watchdog are planned phases that this release deliberately did not touch.
- **A suite rerun and an index reconcile are owed.** The vitest runner would not start in this sandbox, an environmental problem, and the suite rerun is owed to the next dev session. An embedding-reconcile pass over the recovered index is the recorded follow-up.

## Upgrade

- **No API changes.** The cleanup fix is active on the next session stop. The integrity gate activates on the next daemon start. Dist is rebuilt, so if a daemon is already running, recycle it.
- **A refused boot is the gate working.** If a future start stops with a needs-rebuild sentinel, the checkpoint rebuild path takes it from there.
- **`/doctor memory` remains the fastest health read** after any daemon lifecycle event.
