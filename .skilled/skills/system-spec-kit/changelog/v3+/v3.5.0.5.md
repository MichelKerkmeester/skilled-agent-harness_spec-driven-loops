# v3.5.0.5, A Second Door to the Same Daemon

This release gives the memory system a second door. It ships the dual-stack answer: `node .opencode/bin/spec-memory.cjs`, a daemon-backed CLI that fronts the identical 37-tool surface over the same unchanged daemon. The MCP registration stays exactly where it was. The CLI is the resilience and universal surface for hooks, cron, CI and transport-down recovery, not a replacement.

The spec packet holds research and workstreams under `001-spec-memory-cli/` through `003-skill-advisor-cli/` and release cleanup under `004-release-and-program-cleanup/`.

> Spec folder: `.opencode/specs/system-spec-kit/028-mcp-to-cli-tool-transition/`

## Why This Release

The MCP transport has been the memory system's only door, and it is a fragile one. When a transport drops mid-session, Claude Code never reconnects it, so the 37 tools vanish for the rest of the session. Every session also pays the tool-schema token overhead up front, and every runtime needs its own MCP registration.

## What's New at a Glance

- **All 37 memory tools become CLI commands.** They are generated at runtime from `TOOL_DEFINITIONS`, so there is no manifest to drift.
- **One exit taxonomy is shared verbatim across all three sibling CLIs.** `0` is success, `1` a runtime error, `64` a usage or schema error, `69` a protocol or dist mismatch and `75` a retryable daemon error.
- **`--warm-only` probes the socket and exits `75` rather than cold-spawning the launcher.** A transport-down probe costs about a millisecond, so prompt-time hooks fail open instead of booting a daemon from the prompt path.
- **The stable shim refuses a missing or stale `dist/spec-memory-cli.js` with exit `69`.** It will not run old code.
- **Claude and Codex hooks reach memory without MCP.** They probe the socket first, use the CLI when warm and fail open when cold.
- **OpenCode gets the new `system-spec-memory.js` plugin.** OpenCode memory access is no longer MCP-only.
- **All three CLIs exit naturally with drain-awaited writes.** That fixes a 64KB pipe-truncation hazard.
- **The docs caught up.** `ENV_REFERENCE.md` gains twenty new rows, and the feature catalog gains new entries.

## The Spec-Memory CLI

#### The Daemon Was Never the Weak Point

The system-spec-memory daemon was always sturdier than the path to it. The 026/027 launcher work made the daemon survive owner disposal, re-election and lease races. But a session whose MCP transport died still lost its memory tools permanently, because the client never re-establishes the transport.

The incident class was never the daemon. It was the single door.

&nbsp;

#### A Second Client, Not a New Daemon

The CLI is a second IPC client over the daemon that already existed. Nothing about the daemon changed. The same handler queue serializes writes, and the same launcher owns the lifecycle.

`list-tools` answers offline. Every other command validates argv with the existing Zod schemas and speaks JSON-RPC `tools/call` over the IPC socket. `spec-memory list-tools --format json` returns `count: 37` straight from `TOOL_DEFINITIONS`, which makes surface parity against the MCP registration a one-command check.

&nbsp;

#### Guards Before Every Dispatch

The shim guards before it dispatches. It defaults the socket directory and rejects socket paths over the Darwin `sun_path` limit. It maps a spawn failure to exit `75`, so callers can retry instead of guessing.

For the dist check, `SPECKIT_SPEC_MEMORY_CLI_DEV_ALLOW_STALE=1` is the development override.

## Runtimes Reach Memory Without MCP

#### Hooks Fail Open Instead of Blocking

Claude `session-prime`, `compact-inject` and `session-stop` and Codex `session-start` gain a shared warm-only CLI fallback helper. That helper, `spec-memory-cli-fallback.ts`, sits beside `code-index-cli-fallback.ts` for the sibling. It wraps the CLI in a socket probe plus a `--warm-only --timeout-ms` invocation.

No socket means a fast fail-open return, while a warm call measured 117 to 198 ms. The hook result then omits the CLI-backed extras rather than blocking the prompt. Cold spawn stays confined to SessionStart, explicit prewarm, cron and non-prompt maintenance. The one-shot native bridge, measured at 824.8 ms, stays banned from the prompt path.

&nbsp;

#### A Plugin Bridge With No Database Imports

The plugin gives OpenCode its first non-MCP route to memory. Its bridge uses CLI/IPC transport exclusively, with zero in-process database imports, so the dual-writer hazard class cannot return.

The earlier in-process import approach was rejected precisely because a second process importing the database directly is a dual-writer waiting to happen.

## The Dual-Stack Window

#### MCP Removal Waits on Real Use

The dual-stack window is open, not closed. The runtime transport-down drills run during real production use. The measured MCP reference surface of 93 files and 1,041 references migrates only after the window proves the CLI in practice.

MCP removal is a separately-gated decision after that. Until then, both doors stay open.

## Upgrade Notes

No upgrade needed. The MCP registration is untouched and every existing caller keeps working.

- **The CLI is available immediately.** `node .opencode/bin/spec-memory.cjs list-tools --format text` answers offline, and any tool call auto-spawns the daemon through the launcher unless `--warm-only` forbids it.
- **Exit `69` means a rebuild.** If the shim refuses with exit `69`, rebuild the dist with `npm run build --workspace=@spec-kit/mcp-server`.
- **The new env flags are documented.** They live in `mcp-server/ENV-REFERENCE.md`.
