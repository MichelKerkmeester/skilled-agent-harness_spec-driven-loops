This release corrects misleading ablation benchmark results by aligning the benchmark database and reference data, making the workflow easier to follow and trust. It also lets benchmark searches return raw results and points all six configuration files at the repository database.

> Spec folder: `.opencode/specs/system-spec-kit/022-hybrid-rag-fusion/023-ablation-benchmark-integrity/` (Level 2)

## What's New at a Glance

- **The ablation benchmark checks its data before running.** It measures search quality by selectively disabling features and now checks that its test data and active database share the same memory IDs. When they do not match, it stops with a clear error instead of producing meaningless scores.
- **Benchmark searches can use `evaluationMode: true`.** This returns raw results without normal search's confidence filters and token budgets, which help in production but distort benchmark measurements by hiding results the benchmark needs. Normal users are unaffected.
- **The refreshed reference data corrects a mistaken full-text search conclusion.** The outdated test data was rebuilt from scratch with 294 test cases across 126 memory IDs and shows full-text search helps search quality. An earlier benchmark wrongly found it harmful because of the database mismatch.
- **All six configuration files now point to the repository database.** The OpenCode, Claude, VS Code, Codex, Agents and root configuration files use the database with 2,417 memories instead of the external `~/.codex/memories/` database with only 44 records. A backwards-compatibility symlink lets the Codex CLI find the database at its old expected location.

## Upgrade

- Pull the latest version, run `npm run build` in `.opencode/skills/system-spec-kit` and restart any running MCP servers so they pick up the new database path.
- Verify with `SPECKIT_ABLATION=true npx tsx .opencode/skills/system-spec-kit/scripts/evals/run-ablation.ts`. It should complete without alignment errors.
