# v3.9.0.0, Leaner Templates and Bounded Search

v3.9.0.0 brings five template-and-context optimizations from a deep-research packet. The research template renders less at low documentation levels, while the spec, plan, tasks and implementation-summary templates render byte-for-byte identically to before at every level. It adds default acceptance-coverage advice, an opt-in scope check and a response budget for `memory_search`.

> Spec folder: `specs/system-speckit/033-spec-template-context-optimization/` (Level 2)

## Why This Release

The research template rendered in full at every documentation level, while the spec templates repeated full copies across levels.

## What's New at a Glance

- **The research template now renders less at low levels.** Level 1 gets an essentials scaffold, while Level 3, Level 3+ and phase retain the complete document.
- **Four spec templates now share a core.** Per-level additions replace near-identical copies without changing rendered output.
- **The template guide points agents to rendered views.** Agents are directed to use the level-appropriate output rather than raw `.tmpl` files.
- **`AC_COVERAGE` is on by default.** It reports under-coverage as a non-blocking INFO advisory.
- **Scope adherence is an opt-in advisory.** `check-scope-adherence.sh` flags changed files outside a packet's declared *Files to Change*.
- **`memory_search` limits response size.** It drops lowest-score results first to keep large result sets from flooding caller context.
- **Feedback telemetry follows returned search results.** Only results actually returned are included.
- **Documentation and packet history were aligned.** References cover the new rules, and originating research is consolidated into packet 034.

## Templates and Guidance

#### Low-Level Research Stays Focused

The `research.md.tmpl` template rendered its full document at every documentation level, so a Level 1 packet carried the complete document. It now renders an essentials-only scaffold at Level 1, while Level 3, Level 3+ and phase still render the complete document byte-for-byte identically to before.

&nbsp;

#### Spec Templates Share a Core

The spec, plan, tasks and implementation-summary templates each held four near-identical full copies. They now use one shared core with per-level additions, and the *Reading a Template (Agents)* guide directs agents to use the rendered, level-appropriate view instead of the raw `.tmpl` file. Every level still renders byte-for-byte identically to before.

---

## Acceptance and Scope Checks

#### Acceptance Coverage Runs by Default

The `AC_COVERAGE` rule was implemented but disabled by default. It now runs by default as a non-blocking INFO advisory: under-coverage surfaces a message but never warns, errors or blocks `--strict`. The manual-infeasible escape hatch and the 0.9 floor are unchanged.

&nbsp;

#### Scope Checks Flag Out-of-Scope Changes

The new opt-in `check-scope-adherence.sh` (`SCOPE_ADHERENCE`) advisory warns when changed files fall outside a packet's declared *Files to Change*. Supply a change-set through `SYSTEM_SCOPE_CHANGED_FILES` or `SYSTEM_SCOPE_BASE`. Packet documentation is always in scope. With no supplied change-set, the rule does nothing.

---

## Memory Search

#### Search Fits Its Budget

Large `memory_search` result sets could flood the caller's context. The search now enforces a token budget by dropping lowest-score results first, mirroring `memory_context`, and truncates before feedback telemetry is emitted so telemetry records only the results actually returned.
