Search usage signals now capture how people use results and what they search or do next, building a reliable dataset without changing what users see. That dataset is intended to improve ranking in a future release, making the workflow easier to follow and easier to trust.

> Spec folder: `.opencode/specs/system-spec-kit/023-hybrid-rag-fusion-refinement/014-feedback-signal-pipeline` (Level 2)

## Why This Release

The signals need enough volume and validation before they can safely influence ranking without introducing bias.

## What's New at a Glance

- **Five usage signal types are recorded after every search, in the background.** They capture which results were shown, which are delivered with full content as citations, whether the next search rephrases or repeats the question and whether a non-search tool runs shortly after. They are stored for later analysis without affecting what users see, and search results are ranked exactly the same way as before.
- **Follow-up searches reveal rephrased queries and retries.** When someone searches again with slightly different wording, that is a rephrased query. When they repeat nearly the same search, that is a retry, and telling the two apart compares how much word overlap exists between consecutive searches in the same session.
- **The system remembers the most recent session and uses it as a fallback.** Many tools do not carry a session identifier, so a non-search tool run shortly after a search links back to that search even when the tool knows nothing about sessions.
- **Signal collection adds 0.03ms per search on average.** This is well within the 5ms budget, so search speed is unaffected.

## Upgrade

No migration required. Signal collection activates automatically with no configuration changes.
