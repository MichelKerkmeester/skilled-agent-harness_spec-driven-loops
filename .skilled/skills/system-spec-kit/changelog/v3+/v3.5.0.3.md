# v3.5.0.3, One Voice for Every Skill README

This release rewrites the skill READMEs into one narrative voice, the same warm, problem-first voice the repo root README and these changelogs use, and updates the sk-doc template so new skills start there. The rewrites were grounded in each skill's real files, not invented. The context gather behind them caught real drift along the way, from a wrong MCP integration recipe to a stale embedder claim, and every fix landed in the rewrite.

> Spec folder: `.opencode/specs/skilled-agent-orchestration/135-skill-readme-standardization/`

## Why This Release

The repo root README and these changelogs read in one voice, with a problem-first opener, an at-a-glance table near the top, outcome-named section headers, sparse tables and a verification close, but the skill READMEs had drifted apart. Each one was a tabular reference card with no human entry point that led with an Overview or a feature inventory, hid its key facts in a Key Statistics block and named its sections for their function rather than the reader's goal. They ranged from 228 to 1084 lines, so a reader moving between skills re-learned the layout every time. New skills inherited the old shape because the sk-doc template still encoded it.

## What's New at a Glance

- **The 22 skill READMEs now open the same way.** Each starts with a frontmatter block, an H1 and a one-line pitch, followed by an At a Glance table a reader scans in five seconds as Section 1 and an Overview that states the problem before the solution as Section 2. The reference detail is kept below.
- **Later sections follow as each skill needs them.** Quick Start, How It Works, Integration, Troubleshooting, FAQ and Related Documents appear where they fit, with prose carrying the explanation and tables only for genuine lookups.
- **Every README follows the same voice rules.** None carries em dashes, double-hyphen separators, semicolons, Oxford-comma lists or filler words.
- **The sk-doc skill-README template was updated to match.** It now encodes the narrative skeleton plus the writing and validation rules.
- **The system-spec-kit README was restyled in place rather than compressed and stays a complete reference manual.** The largest README in the repo carries dense reference content, from the 37 memory tools and the five-channel search pipeline to the index schema history and the environment table. Regenerating that body would have risked dropping or paraphrasing facts, so the restyle reframed the top and swept the house voice through the existing text while keeping every reference block.
- **Two models drafted each README from a verified map of the skill.** A two-iteration, read-only context gather read the SKILL.md, the code and the references to map the skill's tools, modes, key files and boundaries, then DeepSeek v4 Pro and MiMo v2.5 Pro each drafted from that map against the locked template and the golden example. The orchestrator merged the stronger draft, grafted in the best parts of the other, applied the voice rules and verified the result against source, so the documented facts match the code. Nothing shipped on a model's word alone.
- **Stale claims that had outlived the code were corrected in the same pass.** An MCP integration recipe pointed at the wrong tool namespace and config key, a code skill listed a surface that no longer existed and a scorer README described a single shipped embedder when the shared registry now holds several. Version footers, tool counts and script counts had fallen behind their source, and each correction shipped with the README it belonged to.

## Upgrade

No migration required. This release is documentation only and makes no API changes. No SKILL.md, code or behavior changed, so nothing needs a rebuild or a restart.

- **New skills inherit the voice.** Author a new skill README from the updated sk-doc template and it lands in the narrative shape by default.
- **The skills index is the closing step.** The `.opencode/skills/README.md` catalog is the final piece of the standardization and ships as the last phase of the packet.
