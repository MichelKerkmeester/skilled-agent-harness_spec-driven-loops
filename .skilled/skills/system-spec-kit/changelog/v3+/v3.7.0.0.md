# v3.7.0.0, Honest Verdicts, Earned Flags and a Search That Surfaces

v3.7 makes search more trustworthy from the verdict through the rows a reader receives. It also repairs generated spec records and makes code-graph history safe to read.

A live query returned one result where it should have found many spec folders. The connected graph-history path could also expose closed edges in live reads, so the release fixes both read paths and measures result-changing flags against real data.

Four dark-flag families earned graduation, while structural protections now run by default. Those dark-flag graduates keep their existing default-off flags until enabled. The true-citation ledger stays at refine until it can clear the reranker bar.

## Why This Release

Similarity scores, response limits and closed graph edges could each leave a result less reliable than it appeared. The release checks those paths against actual queries and data, then keeps dark-flag graduates behind their existing default-off flags while the honesty suite and safety protections run by default.

## What's New at a Glance

- **Search confidence follows evidence.** Keyword support, adjusted relevance and evidence depth now shape the verdict, and a build gate refuses to pass when search returns a good verdict on a term it should know nothing about.
- **Matching folders stay in the response.** Trigger-lane matches reach the reader, while budget overflow becomes compact rows.
- **Generated spec records stay consistent.** Status and lineage rules prevent drift, while unchanged reads leave metadata alone.
- **Advisor outages are visible.** A lane that could not run is reported as degraded. Stale embeddings fail closed.
- **Code-graph answers keep their history.** Callers can request an earlier generation while live reads show current edges.
- **Deep Loop preserves useful state.** Merges stay stable, recovery exposes broken state and interrupted work leaves a summary.
- **Dark-flag graduates stay opt-in.** Their existing flags remain default-off, while safety checks run by default and unsupported work stays out.

## Search

#### Keyword Evidence Comes First

A high similarity score alone can no longer produce a good verdict. The top result needs a matching term in its title, trigger phrases or body. A BM25 keyword score already on the row also counts. So a fluent but absent term such as `kubernetes`, which once earned a confident citation from a single spurious high-cosine hit, now reads weak. The lexical-grounding floor shipped quietly earlier and graduated to on for everyone this cycle.

&nbsp;

#### Relevance Shows True Signal

Search subtracts a measured corpus noise floor for `nomic-embed-text-v1.5` before deciding whether a match is real. Embedder drift no longer pushes a marginal match into looking good. A semantic result now reports the same number the system ranks on, the calibrated absolute relevance on a 0-to-1 cosine scale, rather than the compressed RRF fusion magnitude that clusters low near 0.03. This fixes a residual path that was still reporting the wrong figure for semantic rows. Relationship and degree rows display their relevance rather than a blank dash.

&nbsp;

#### Thin Evidence Lowers Confidence

When evidence is thin, search caps a good verdict down to weak, and the evidence-gap warning beside the verdict now always agrees with it. Both had been broken. The cap was wired to a signal nothing ever set, so it never fired and a known gap could surface beside a confident verdict. The warning was driven by a peakedness statistic, how far the top result stood above the pack, rather than by relevance, so a strong, tightly clustered set of good matches got the warning while a flat spread of weak off-topic matches slipped through clean. The cap is now connected, and the warning keys off the same noise-floor-subtracted relevance the verdict uses, so a search for a real term like `graph` stays quiet while a genuine gap is flagged once, consistently. A benchmark of the old warning found it raised false alarms on two of every three strong queries. The redesign brought that to zero.

&nbsp;

#### A Guard Against Confident Hallucination

A build gate now refuses to pass when search returns good verdicts on terms it should know nothing about. Six bare off-corpus queries run through the production verdict path: kubernetes, oauth, kafka, terraform, graphql and webpack. The gate fails if too many false confirms slip through, with the ceiling set at zero. It is the regression net under the grounding and noise-floor work above.

&nbsp;

#### Results Keep Their Meaning

The dashboard header count now matches the rows actually shown rather than a pre-trim total, and a long folder path displays its leaf title instead of being cut off mid-string. A status field that had reported an unrelated mechanism now reports the expected status.

&nbsp;

#### Search Works Through Outages

When the embedding service is unavailable or returns no embedding, search falls back to keyword matching and marks the dense channel as skipped, so an outage returns the best lexical answer rather than an empty result. The healthy path stays unchanged.

&nbsp;

#### Budget Trimming Keeps Answers

Tail-appended backfill rows are now exempt from the response-serialization token budget, so a backfill row added past the limit is not the first thing cut. If trimming threatens the primary results, the response now reserves at least one primary row and keeps a pinned constitutional rule ahead of additive backfill, so the squeeze can thin the result set without ever sacrificing the answer you asked for.

&nbsp;

#### Multi-Hop Fills Deep Results

The deterministic multi-hop and lane-champion backfill appends were measured and graduated for deep-K readers. They now reach readers who request deep result sets. Complete recall at twenty rose from just over half to almost all on labelled multi-target queries, while shallow rankings stayed flat.

&nbsp;

#### Query Shape Controls Expansion

Every query is classified once by its retrieval shape before the pipeline runs. The five-class query classifier is on for everyone. When shape routing is enabled, a single-hop lookup skips graph-relation expansion while a multi-hop question keeps graph-aware ranking, without changing how you call search. Shape routing stays opt-in behind `SPECKIT_RETRIEVAL_CLASS_ROUTING`, which is off by default, and so do the per-class weight profiles.

&nbsp;

#### More Matching Folders Surface

Trigger-lane matches, which had been excluded from the surfaced results even when they ranked, now reach them. A display floor of ten now holds, and budget overflow becomes compact rows at both the pipeline and envelope levels instead of being deleted outright. The folder-discovery listing also excludes `z_future` folders, so future-staged folders stop diluting the live result set. The same live `memory_search` query that had returned one result now returns six, with one full row and five compact rows.

&nbsp;

#### Valid Inputs Reach Search

An empty-string filter now reads as a no-op instead of being rejected as malformed. Search also accepts `retrievalLevel` instead of rejecting it, so either input can reach the query.

&nbsp;

#### A Probe Shows Citation Readiness

The true-citation emitter is sound but stays at refine until real session-carrying traffic accumulates. This release adds a density probe that surfaces through the health check and reports when the ledger has accumulated enough session-scoped pairs. Its per-class floor and minority-ratio floor keep a lopsided ledger from graduating the reranker on a count alone, and the probe observes without flipping anything on.

&nbsp;

#### Citation Holds Across Models

A 144-cell benchmark drove `/memory:search` with four models, MiMo, Kimi, DeepSeek and gpt-5.5 fast, across twelve deliberately vague queries. The verdict held up where it should. On clearly aligned and clearly empty queries every model agreed, and the citation rule was obeyed wherever a model emitted a full verdict. The divergence is on borderline queries, where two of the twelve split the verdict because each model refined the vague search differently and landed on different results, not because the verdict logic wavered. The benchmark also isolated the off-corpus false confidence that the grounding and noise-floor graduations then closed. DeepSeek came out the most efficient and stable driver, while Kimi over-explores expensively on the vaguest queries.

&nbsp;

#### Follow-Up Fixes Hold Their Contract

The forty-one spec-kit P1 items shipped a cluster of real fixes. The evaluator now reads the DB path it was handed rather than a shared reference. A BM25 sync guard keeps the keyword index aligned with the rows it scores. `QUALITY_FLOOR` documentation now describes the floor the code enforces.

Three further fixes that had been deferred were completed. Query surrogates now sit under their own `SPECKIT_QUERY_SURROGATES` gate, so the feature is opt-in. Reorganizing a folder now repoints its index rows instead of dropping its embeddings. The global `retrievalLevel` branch now honors the `SPECKIT_DUAL_RETRIEVAL` kill switch alongside the archived-deny default and constitutional injection.

## Spec Records

The generated `description.json` and `graph-metadata.json` files that feed memory search and graph traversal had been hand-driftable and noisy.

#### Statuses Stay Within Their Set

Generated spec metadata now uses a closed status set rather than free-form prose. A first-class validator checks `description.json` and `graph-metadata.json`. Legacy hand-edited statuses are re-derived into safe values and surfaced for review rather than left to leak through.

&nbsp;

#### Reads Leave Files Clean

When generated content is unchanged, the generator skips the write even if volatile timestamps differ. A targeted cache update can refresh one folder without rebuilding its neighbors.

Access and freshness telemetry now lives in the index layer rather than generated JSON, so reading or resuming no longer dirties unchanged metadata.

&nbsp;

#### Refreshes Stay Scoped

The backfill tool now takes a folder argument and defaults to that single folder, so a one-folder intent no longer quietly dirties the whole tree. A repository-wide run requires `--all`. Archived and future-staged folders stay out of the descriptions cache under one policy. Archive memory behavior remains intact.

&nbsp;

#### Lineage Survives Partial Refresh

Parent and child relationships reconcile across partial rescans, so a valid parent survives when a subscan misses it. Child lists grow safely unless an operator explicitly prunes them.

The description and causal-summary fields now derive from one shared synopsis rule, so they stop drifting apart. A drift checker re-derives them on read against a stored source-document hash and reports staleness without writing anything. A saved source fingerprint shows freshness without rereading the document.

&nbsp;

#### Backfill Damage Was Corrected

A backfill against the wrong base path polluted eleven `description.json` files with incorrect `parentChain` values. The cleanup restored correct lineage, corrected four earlier remediation claims against the real state and restored four missing `children_ids` to a phase parent.

&nbsp;

#### The Migration Settles Cleanly

The whole spec tree, 2,049 spec folders including archives, was regenerated under the new metadata contracts. The second run produced byte-identical output with no validation violations. A graduation benchmark then measured every default-off flag against the migrated tree, and twelve flags earned their way to default-on or enforcing, covering the metadata integrity gates and the search-honesty suite.

&nbsp;

#### Pending Refreshes Stay Open

The local embedding provider remains degraded with its retry circuit breaker open, blocking a `parentChain` index refresh until the provider recovers. A `validate.sh` global-index-reconciliation preventive is deferred to a later cycle.

## Skill Advisor

#### Down Lanes Are Not Empty

When a scoring lane is runtime-degraded, the advisor no longer counts it against a skill as if it had run and found no match. Degraded lanes leave the confidence denominator, while a lane that ran without a match still counts.

Advisor output and abstention explanations now name the degraded state plainly instead of hiding it inside a low score.

&nbsp;

#### Old Embeddings Fail Closed

The advisor records which vector model produced each semantic projection and checks it against the active embedder on every read. A mismatch marks the semantic shadow lane degraded, and the lane then follows the same lane-health rule, rather than quietly trusting a projection built by a different model. Legacy projections without a model signature now fail closed instead of being assumed safe.

&nbsp;

#### Fusion Keeps Its Safety Net

Reciprocal-rank fusion (RRF) lifted top-one by one on a widened forty-two-prompt set with no regressions and near-total deterministic agreement. It graduated with conflict reranking, which repairs a case plain fusion would otherwise break.

&nbsp;

#### The Alias Penalty Covers Both

The separate self-recommendation guard was cut as behaviorally redundant because the generic explainer floor and an un-flagged penalty already did its work. The remaining implicit penalty was the only thing stopping the advisor from recommending itself on an audit or explainer prompt. That penalty was undocumented, so a future refactor could have removed it without anyone noticing, and it now carries a durable explanation. It had also matched only the advisor's exact id and missed its alias, which still recommended itself to the top in the default configuration. The penalty now matches the canonical ID set, so both the exact name and the alias are demoted. The penalty value is unchanged. This behavior change is not flag-gated.

## Code Graph

#### Parser Hiccups Can Recover

A parser hiccup no longer condemns a file to permanent invisibility. Transient parse failures now retry up to `SPECKIT_PARSER_SKIP_LIST_MAX_RETRIES`, which defaults to 5. A successful reparse clears the skip-list entry, while a fatal entry still skips immediately for human review.

&nbsp;

#### Graph Order Stays Stable

Equal-trust context edges now sort by stable content-derived keys instead of database return order. Repeating a query over the same data produces the same order across scan rebuilds, without phantom reordering in a diff.

&nbsp;

#### Documents Join Graph Search

The documentation lane now indexes Markdown headings and JSON, JSONC, YAML and TOML config keys as graph symbols, all from local parsing so nothing leaves your machine. Config indexing runs by default, while Markdown extraction is opt-in through globs.

&nbsp;

#### Generation Shows Freshness

Each promoted scan advances a generation number that only increases. Freshness envelopes expose it as `metadata.freshness.generation`, while failed promotions and no-op scans leave the number unchanged.

Reads continue serving the generation that is present even when it is stale. A hard gate that rejects stale-generation reads remains deferred.

&nbsp;

#### Reparse Cost Has a Bound

The reverse-dependency degree cap decides how many importers get re-bound when a high-fan-in dependency is renamed. Before this release it defaulted to uncapped, so renaming a thirty-importer module re-parsed all thirty. It now defaults to fifteen, which fully repairs the common-to-moderate refactor at negligible cost while bounding the unmeasured hundred-plus-importer tail. The cap is read only inside the force-parse branch, which is off by default. A high-fan-in rename above the cap leaves overflow importer edges stale until each importer is next edited.

A cost sweep found rebinding grew linearly, at about a third of a millisecond to under a millisecond per importer over a seventeen-millisecond scan floor.

&nbsp;

#### Historical Queries Return Past State

The first wiring left the as-of reader with no caller, so the feature was held out of scope instead of being claimed as done. Code-graph queries now accept an optional as-of generation, so a historical read can include edges to nodes deleted since that generation. A query without the parameter returns the current graph exactly as before. The history surface stays byte-identical while its flag is off.

&nbsp;

#### Live Reads Keep Current Edges

The bitemporal close-and-insert writer was built but never wired into the reindex path, so it was held at refine. The production-readiness pass wired it in, and before the fix, turning its flag on would have corrupted every live read. The live edge readers had no filter for closed edges, so after a reindex they returned both the superseded edge and its replacement. The full-scan prune deleted dangling edges regardless of the flag, and node replacement deleted a symbol's edges before the close path could run, so an as-of query came back empty. With history enabled, node replacement and full-scan pruning close old edges instead of deleting them, live readers return only current edges and a generation-stamp correction gives every superseded edge a real readable window instead of a zero-width one.

## Deep Loop and Release Decisions

The deep-research and deep-review loops, the multi-iteration `/deep:*` workflows that fan work out across parallel model workers, gained determinism, recovery and observability fixes.

#### New Runs Can Reduce State

A brand-new deep-research run no longer crashes on its first pass. The strategy template now includes the anchors where carried-forward state is written. A fresh deep-research run has somewhere to land its first reduction and can carry state into the next pass.

&nbsp;

#### Parallel Results Merge Consistently

Research and review registries now sort lineage labels and worker identity before merging parallel results. The combined output no longer depends on which worker finishes first.

&nbsp;

#### Stops Need Outside Evidence

Before accepting a STOP for lack of new ground, deep-research compares the run's novelty report with graph-observed changes to stored questions, findings and evidence. It blocks a stop the graph cannot support.

&nbsp;

#### Conflicts Remain Visible

When workers return the same finding ID with different content, the merge keeps both as conflicting variants instead of letting the first arrival erase the other. A person can review the actual disagreement.

&nbsp;

#### Retries Keep Their Budget

Fan-out timeouts, exits and salvage misses are tracked as separate failure types. A salvage miss means recoverable output went missing. Only transient failures retry, while durable run logs preserve retry counts across crashes.

&nbsp;

#### Recovery Shows Broken State

Recovery stops when a state file is missing or corrupt instead of treating the run as new. It also marks worker lineages that started but never reported back, so partial state remains visible.

&nbsp;

#### Interrupted Runs Keep Their Work

Live fan-outs report pending, failed and lag gauges from real run state. An interrupted run leaves a partial summary of the work completed before it stopped.

&nbsp;

#### Open Questions Carry Forward

Deep-research carries unresolved questions into the next iteration without another model call. The reducer builds a continuity thread from the previous pass and derives the next focus from those questions or the latest finding.

&nbsp;

#### Dedup Checks the Title

The near-duplicate finding collapse graduated on a clean benchmark and was then scale-validated past its original handful of synthetic records on a larger free-text set. That scale test showed the dedup key ignored the finding title, so two distinct findings that shared a body but differed only in their title collapsed into one. The key now applies a title-overlap gate, so disjoint titles stay separate while a true restatement still merges. Title-only false collapses fell from one in two to zero, while exact duplicates still collapse and distinct-finding recall holds.

&nbsp;

#### Lag Measures Real Stalls

The old lag gauge counted time since a worker was queued, which is queue back-pressure, so any healthy fan-out wider than its concurrency tripped the alarm. It now measures time since the last completion while work remains pending, keeping healthy busy pools quiet and firing once for a genuinely hung worker.

The recommended ceiling dropped from five minutes to two now that it no longer drifts on healthy load. The committed default stays off, because turning the gauge on is the separate graduation step.

&nbsp;

#### Graduates Keep Their Boundaries

Four of the eight dark-flag families earned graduation on the real graph and corpus: multi-hop appends, code-graph staleness repair, advisor RRF fusion and Deep Loop deduplication. The code-graph staleness degree cap graduated with a benchmarked default, the bitemporal edge writer graduated after the review caught its corruption and the repair closed it, and the Deep Loop dedup graduated with its lag and heartbeat gauges. These result-changing graduates keep their existing default-off flags and remain byte-identical while off, so the production flip stays a separate, evidence-gated decision.

&nbsp;

#### Protections Run by Default

Lexical grounding, noise-floor subtraction, evidence-gap handling, relevance-aware warnings and calibrated scores run on with the cite-with-caveat tier, the envelope-fidelity guard, spec-metadata integrity gates and the false-confirm build gate. The type-safe status validator runs in a non-blocking report mode during the migration window before it enforces.

Three flags also ship on without a headline because they make the records safer rather than the verdicts smarter. Derived-id provenance gives every causal edge a content-addressed ID, retention-forgetting is a deletion safety guardrail that keeps a cleanup from removing more than it should, and the world-summary grounding prelude seeds a search with a short factual frame before it runs. None of them change a number you read.

&nbsp;

#### Measured Cuts Stay Out

A large body of work was built in full, measured against the corpus and then declined because it did not earn its place. The entire semantic-edge layer family went this way: the edge vector index, edge triplet search, edge semantic dedup and invalidation, edge presence currentness and bitemporal recall. So did agentic recall, sleeptime consolidation, the procedural-reliability lane, the cardinality penalty, summary fusion, the grounding-signal field and deterministic ranking.

The dark-flag reckoning then cut five more on a measured loss or tie. The per-class retrieval weights hurt single-hop precision to guard a cost that did not exist, and the save reconsolidation cosine band merged almost nothing it should have. The seeded PageRank tied the flat walk on every metric, and a later revisit, run once the prerequisite the original benchmark record had named was built, reconfirmed the cut with a wider margin. The closed-vocabulary edge governance was cut too. The advisor self-recommendation guard was redundant with logic already running. A purely informational flag was removed because it showed no measured gain.

&nbsp;

#### Freshness Unblocked Two Flags

- The first metadata migration did not write the freshness field two flags needed.
- A rerun wrote that field, which allowed both flags to graduate.

&nbsp;

#### Remaining Advisories Stay Scoped

The two surviving advisories concern only the as-of read surface while its flag is enabled. Neither applies to a live read.

A follow-up deep review surfaced fourteen P0, sixty-nine P1 and eighty-four P2 findings. ## Upgrade Notes

No migration is required, and nothing changed on the common path.

- Stop setting `SPECKIT_DETERMINISTIC_RANKING` if you used it. The flag was removed. Ranking follows recency as it did by default.
- Choose whether to enable the dark-flag graduates.
- When enabling bitemporal edge reads, the recommended degree cap is fifteen and code-graph queries accept the optional as-of generation.
- When enabling Deep Loop gauges, use a two-minute lag ceiling and a thirty-second heartbeat.
- The advisor self-recommendation penalty change is the one deliberate behavior shift that is not flag-gated, because demoting the advisor's own alias on an audit prompt is a correctness fix that the un-aliased path already applied.
- The search-surfacing fix is a correctness change on the live read path, so a query that under-surfaced before now returns its full match set with overflow degraded into compact rows.
