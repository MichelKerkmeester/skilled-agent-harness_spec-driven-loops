Spec documents now enter indexing without being rejected for lacking memory-file metadata. This makes spec content searchable. The goal is to make the workflow easier to follow and easier to trust.

> Spec folder: `specs/system-spec-kit/022-hybrid-rag-fusion/001-hybrid-rag-fusion-epic/012-pre-release-remediation/`

## What's New at a Glance

- **Indexing warns instead of rejecting spec documents.** About 97% of spec documents had been silently rejected because the quality gate required memory metadata such as trigger phrases and importance tiers. Spec documents such as `spec.md`, `plan.md` and `tasks.md` follow their own templates and intentionally lack that metadata. They now pass indexing with warnings, while the normal save path for memory files continues to enforce all checks.
- **Re-indexing can build spec-document causal chains.** Only about 7 links existed while spec documents were rejected. After re-indexing, hundreds of chains can form across spec documents, plans, tasks, checklists and implementation summaries through `caused` and `supports` relationships.
- **Save orchestration handles a TypeScript build error.** The code assumed a value was always a list, but it could sometimes be an empty object, and the added check handles both cases.
- **A one-time cleanup removed stale memories and repaired orphaned records.** It purged 128 stale memories: 112 marked as deprecated, 14 leftover test entries and 2 test stubs. It also repaired 3,035 orphaned causal edges and 2 orphaned chunks. These were records pointing to deleted parents.
- **The full re-index recovered previously missed files.** The memory count rose from 358 to 407.

## Upgrade

- **Rebuild.** Run `npm run build` in `mcp-server/`.
- **Restart the MCP server.**
- **Re-index.** Run `memory_index_scan({ force: true })` to re-index all spec documents and rebuild causal chains.
- No database migration is required.
