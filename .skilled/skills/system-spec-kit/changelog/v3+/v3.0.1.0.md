The memory database now handles search, saving, restore and access more safely. Five critical issues could cause data loss, silent corruption or security bypass: memories from different users could overwrite each other, the database could be created with wrong-sized vector storage, a database restore could accidentally wipe tables, anyone could create shared memory spaces without authentication and merged memories became invisible to search. This release closes the 121-finding code audit with 117 fixes implemented, three findings rejected as non-issues and none remaining.

Pass 1 fixed 80 critical and required findings: five data-loss-risk blockers and 75 required fixes. Pass 2 fixed 22 improvement findings and rejected three. Pass 3 fixed the remaining 15 deferred findings and aligned all documentation. These passes were previously tracked as v3.0.1.0 (Pass 1), v3.0.2.0 (Pass 2) and v3.1.0.0 (Pass 3), now consolidated into one release.

Sprint 1 covered Search and Data Integrity (15 fixes), Sprint 2 covered Correctness and Schema (13 fixes), Sprint 3 covered Security and Governance (9 fixes) and Sprint 4 covered the remaining fixes.

> Spec folder: `.opencode/specs/system-spec-kit/022-hybrid-rag-fusion/026-memory-database-refinement/` (Level 2)

## Why This Release

The goal is to make the workflow safer and easier to trust.

---

## What's New at a Glance

- **Creator identity separates memory histories.** Memories without identity data keep their old keys, while shared-space controls distinguish creation rights from modification rights.
- **Restores and merges preserve usable memories.** Restore merges limit changes to restored data, and merged memories become findable through every search path.
- **Search ranking follows the configured channels.** Ranking stages retain useful results, and response budgets account for nested metadata.
- **Saves protect files and records.** Files are finalized before database records are written, and large files receive the same checks as normal saves.
- **Database upgrades preserve valid state.** Required migration steps fail hard, while embedding storage uses the vector size selected by its generator.
- **Text processing preserves source content.** Chunking and parsing retain unmarked text, metadata and checked checklist items.
- **Graph and error responses reflect the operation.** Relationship direction, graph limits and domain-specific errors are represented in results.
- **Session and evaluation records retain their boundaries.** Cursors, learning history and benchmark measurements keep their scope or channel detail.

## Memory Safety and Access

#### Creator identity protects memory history

The system built a logical key from a spec folder, file path and anchor but left out who created the memory. Different users, agents or tenants working on the same path could therefore collide on one version history. Keys now include a hashed identifier derived from the creator's tenant, user, agent, session or shared space. Memories without identity data keep their old keys for backward compatibility.

&nbsp;

#### Shared-space controls enforce roles

Shared-memory tools took identity from server configuration instead of the request, so a connected client could create spaces in any tenant, claim admin ownership and rewrite memberships. Every shared-memory request now requires the caller's identity. Creating new spaces requires admin credentials. Modifying existing spaces requires the caller to be either an admin or the space owner. Status checks derive identity from the authenticated caller instead of accepting arbitrary identity parameters in the request body.

&nbsp;

#### Restore merges preserve unrelated data

When merge-mode restore had no specific folder scope, it could delete all working memory, session state and shared spaces before reinserting restored data. A failed reinsertion could leave those tables empty. Restore now limits deletes to the data being restored and wraps each table's delete-and-reinsert in a savepoint (a mini-transaction), so a failure in one table does not leave the others empty. The response reports which tables had partial failures.

&nbsp;

#### Merged memories reach every search path

A merge archived the old memory and created a new one without updating the search projection, text search index or run history chain, leaving the new memory invisible to search. Merges now follow the full indexing process used by normal saves and update the search projection, text search index and run history chain. The BM25 (exact word matching) index also receives the merged memory, which is immediately findable through all search paths.

## Search and Saving

#### Search thresholds use the correct scale

Fallback tiers treated `0.3` as 30% similarity even though the search function expected `30`. That made the effective threshold 0.3%, allowing almost every result through. Fallbacks now use the expected percentage scale.

&nbsp;

#### Search settings stay independent

Fallback search re-enabled channels that callers had disabled, and graph search could leave its degree channel on after direct graph lookup was disabled. Fallbacks now preserve the caller's allowed channels, while turning off graph search disables both graph parts. Text-search weighting also varied with the graph channel, so full-text and BM25 channels now receive consistent weights regardless of which other channels are active.

&nbsp;

#### Ranking preserves useful candidates

Confidence filtering ran before diversity filtering, relationship boosting and folder relevance scoring, which could have rescued useful results. It now runs after all ranking stages. Focused mode also used to skip relevance ranking when narrowing results to a specific area, so it now applies ranking in that mode too.

&nbsp;

#### Response budgets count nested fields

Response-size estimates counted top-level fields but missed nested metadata, and they accepted the first result even when it exceeded the budget. Estimates now count every field and apply the budget starting with the first result. The estimate measures tokens, roughly words, used by each result in a response.

&nbsp;

#### Scoped saves reject missing identity

When checking whether a new memory superseded an existing one, matching accepted an existing memory with no user or tenant scope. A scoped save could then replace an unscoped legacy memory. A missing scope now counts as a mismatch.

&nbsp;

#### Files finish before database records

The save process wrote to the database before renaming the temporary file to its final location, so a failed rename could leave a record pointing to a missing file. It now finalizes the file before writing the database record. Slow embedding generation also held a database write lock during its network call and blocked other writes. Saving now separates planning, which needs no lock, from a brief mutation phase that holds the lock.

&nbsp;

#### Large saves receive quality checks

Large files entered chunking before the quality gate, duplicate detection and other normal-save checks. All checks now run before the chunking decision, including duplicate detection for chunked files. Force-saving to the same path used to be rejected by the duplicate checker, so an explicit `force: true` save now skips duplicate detection.

&nbsp;

#### Search projection writes are mandatory

Failures to update the search projection were silently ignored, so a memory could be saved but remain invisible to search. Projection updates now happen within the same transaction as the save and cannot be ignored. Global variables for the active database connection also let simultaneous database instances interfere with one another, so each instance now tracks its own connection.

&nbsp;

#### Nested saves use savepoints

Manual transaction commands conflicted with internal transaction calls during bulk operations and could cause a nested-transaction crash. The save pipeline now uses savepoints for nested work.

&nbsp;

#### Text indexes track archives and updates

Archived memories remained in the in-memory text search index and could appear in word-match results until the server restarted. Archives now leave that index immediately. Full rebuilds indexed titles, trigger phrases and file paths, while real-time updates indexed only content bodies. Both now use the same fields.

&nbsp;

#### Re-indexing keeps original memory

The incremental scanner could miss fast file changes when writes shared a modification timestamp, so it now uses content hashes as a secondary change signal. Re-indexing previously deleted the old record before the replacement was fully indexed, risking memory loss if indexing failed. It now indexes the replacement first and deletes the old record afterward. Force re-indexing also clears the old search-projection entry before inserting the new one to avoid a unique-constraint failure.

&nbsp;

#### Supersede chains stay in one file

A new memory could supersede a semantically similar memory from another file, creating a version chain across file boundaries. Supersede chains now connect only memories for the same file path.

## Database and Document Integrity

#### Required migration steps fail hard

A migration step could fail partway through, log a warning and still advance the database version. A later startup would then skip the incomplete migration, so required migration steps now fail hard instead of being recorded as successful. Folder-name standardization also ran after history records were populated, preserving old names there. Migrations now run before history population.

&nbsp;

#### Schema migrations preserve records

The migration for the constitutional importance tier previously warned when an old database could not support it instead of updating the schema. A real migration now rebuilds the table to support that tier. Another migration dropped and recreated the conflicts table, losing its audit records. It now renames the old table, copies data with column mapping and drops the old table only after the transfer succeeds.

&nbsp;

#### Embedding dimensions match providers

Embedding providers produce vectors of different sizes, such as 768 or 1024 numbers. Startup previously guessed the database's vector size from available API keys using logic different from the embedding generator. It now uses the generator's exact size-resolution logic and fails immediately with a clear error if an existing database has a different size. The embedding cache also includes dimensions in its key so a reconfigured model cannot return a vector of the wrong size.

&nbsp;

#### Provider fallback reports actual use

When a preferred cloud embedding provider failed, the system silently switched to a local alternative. Logs showed the switch, but the system continued to report the original provider. It now tracks which provider was requested, which was used and why the switch happened.

&nbsp;

#### API keys are checked before provider commitment

The system could select a cloud embedding provider and commit its vector dimensions to the database before discovering that the API key was invalid. It now validates the API key before committing to the provider.

&nbsp;

#### Anchor chunking keeps surrounding text

Anchor-based chunking discarded introductions, transitions and conclusions outside marked sections. Those unmarked portions now become their own chunks. Failed metadata assignment could also leave chunk records without metadata, so record creation and metadata assignment now run in one transaction with cleanup on failure.

&nbsp;

#### Code examples survive chunking

Fallback chunking split text at markdown headings such as `# Heading`. It also split at `# comment` lines inside code blocks, breaking code examples apart. The fallback now uses a markdown parser that treats code blocks as atomic.

&nbsp;

#### Parsed content preserves source data

Body text that looked like YAML could overwrite metadata already extracted from the frontmatter. Parsing now stops after frontmatter extraction. Improperly nested or unclosed anchor tags were also accepted and could make chunking unpredictable, so nesting validation now rejects them. Content normalization preserves checked checklist markers instead of changing `- [x]` items to `- [ ]`.

&nbsp;

#### Trigger phrases stay useful

Common words such as `the`, `and` and `is` could be stored as trigger phrases. A stopword filter and minimum-specificity check now reject them. Parse errors during trigger matching were silently dropped, so the matcher now surfaces structured error information when parsing fails and callers know matching was degraded.

## Graph, Responses and Session Records

#### Causal paths preserve connections

In a diamond-shaped graph, whichever path reached a node first marked it visited and caused the other path's connection to be dropped. Traversal now tracks the current path instead of marking nodes globally. Relationship strength also used to be calculated independently for each link, so it now decays cumulatively with distance through the chain.

&nbsp;

#### Drift results distinguish direction

When asking why a memory changed, drift analysis returned the same relationship types for causes and effects. Its response now separates incoming relationships from outgoing relationships.

&nbsp;

#### Graph scores respect limits

Self-referencing relationships were counted twice in degree calculations, once as outgoing and once as incoming, so self-loops now count once. The degree cache was cleared for new links but not for removed links, archived memories or merged memories, so it now invalidates for all of those changes. The advertised 0.15 cap on the degree channel's influence was not applied in score calculations, so the cap now limits its effect on final rankings.

&nbsp;

#### Graph refresh honors its flag

Setting `SPECKIT_GRAPH_REFRESH_MODE=off` did not disable graph enrichment. The flag is now checked in all relevant code paths, so `off` disables graph refresh.

&nbsp;

#### Pagination cursors preserve scope

The progressive-disclosure system returned results in pages without checking whether the person requesting a later page had the same permissions as the person who requested the first page. Cursor tokens now encode scope information and validate it when a page resumes.

&nbsp;

#### Errors identify the failed operation

Search, save and graph failures all returned `SEARCH_FAILED`, and graph handlers used that search code for graph failures. Responses now use domain-specific error codes, including graph-specific codes across all four graph handlers. Client errors included raw stack traces and internal file paths, so full details are now logged server-side and clients receive generic messages. Unhandled server exceptions now use the standard response format, and context-tool handler failures return error responses instead of success envelopes.

&nbsp;

#### Responses retain useful metadata

Response formatting discarded fields such as total count, truncation status and search metadata. It now preserves all metadata fields. When the database connection changed, some components also kept the old connection and usage counters carried over from the previous database. Reconnection events now reach all registered components, and all usage counters reset when the connection changes.

&nbsp;

#### Trigger matching applies scope filters

The trigger-matching tool exposed filters for spec folder, tenant, user, agent and shared space, but its handler did not read them. The handler now passes every scope field to the matching logic.

&nbsp;

#### Session resume uses context

Resuming a previous session required exact trigger words. Resume detection now uses context such as a spec folder or prior session state instead of requiring specific keywords.

&nbsp;

#### Learning records retain each cycle

Post-task measurements could overwrite another session's baseline when sessions shared a task ID. Measurement keys now include the session ID. Completed tasks also discarded later learning cycles, so they now allow multiple completion entries and preserve the full learning history.

&nbsp;

#### Evaluation preserves channel detail

The evaluation dashboard merged metrics from different search channels into aggregate values, losing the channel-by-channel view. It now preserves each channel's breakdown. The ground-truth alignment check introduced in v3.0.0.4 was not called before benchmark runs, so benchmarks now call it.

## Upgrade Notes

- Most deployments need no migration. Schema migrations are backward-compatible and run automatically on startup.
- **Potential breaking change for old databases:** The constitutional-tier migration now fails startup on databases that still have the legacy importance-tier constraint. If affected, run a manual table rebuild before upgrading.
- Shared-memory requests without caller identity receive authentication errors. Error responses use specific codes instead of `SEARCH_FAILED`, `memory_drift_why` now returns incoming and outgoing buckets instead of flat lists, and search fallback no longer re-enables channels the caller disabled.
