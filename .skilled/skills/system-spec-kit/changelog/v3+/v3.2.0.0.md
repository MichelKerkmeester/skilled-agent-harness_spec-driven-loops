This release combines the ESM Module Compliance packet (023, 13 phases), at `.opencode/specs/system-spec-kit/023-hybrid-rag-fusion-refinement/` (Level 2), with the Compact Code Graph packet (024, 28 phases). Together, the 41 phases move the shared package and MCP server to native ESM, add a structural code graph and extend session recovery through compaction and hookless runtimes.

Search recovers from a zero-result outage, and structured memory saves now use the information supplied. Data cleanup and indexing changes address drift in spec content and search state.

> Spec folder: `.opencode/specs/system-spec-kit/024-compact-code-graph/` (Level 3)

## Why This Release

The goal is to make the workflow safer and easier to trust.

## What's New at a Glance

- **The shared package and MCP server use native ESM.** `@spec-kit/scripts` keeps its CommonJS behavior.
- **Session recovery responds to its source.** Compaction, startup, resume and clear each receive tailored context.
- **Hookless runtimes have a recovery path.** MCP priming and session tools support recovery beyond Claude hooks.
- **Structural search complements semantic search.** The code graph answers caller, import and dependency questions.
- **Search returns results and handles exact phrases.** Vector and FTS5 channels contribute to results, and multi-word queries can match phrases.
- **Structured saves retain supplied details.** JSON and STDIN requests reach extraction in normalized form, including saves without transcripts.
- **Search controls respect scope boundaries.** Ordinary queries work without governed scope, and duplicate checks stay within their boundaries.
- **Indexing handles canonical labels and repository moves.** Reindexing no longer rejects legitimate files because batch inputs lacked file-path awareness and topic checks rejected memory notes.
- **Runtime recovery and tool routing share a contract.** Hooks and tools use shared recovery logic, and routing directs questions to the matching search surface.

## Runtime & ESM

#### Shared code matches its module contract

`@spec-kit/shared` used modern import syntax in source, but its package behavior did not match what Node runs. Package metadata, compiler settings and 48 relative import paths were rewritten so consumers get the native ESM behavior the source expects.

&nbsp;

#### MCP startup follows its module system

The MCP server looked modern in source while relying on CommonJS assumptions such as the require helper, `__dirname`, `__filename` and loose JSON loading. The migration rewrote 839 imports across 181 files, replaced CommonJS-only globals, converted the remaining require-helper holdouts and repaired ESM startup details so runtime behavior matches the package's module system. The MCP server package also declares `engines.node >= 20.11.0`.

&nbsp;

#### Scripts preserve caller expectations

Switching `@spec-kit/scripts` to ESM for consistency would have broken callers that rely on its CommonJS behavior. Scripts use Node 25's native `require(esm)` where needed. Loading blockers were removed at the package boundary, and the memory-save path was hardened at the same time.

## Session Recovery & Context

#### Compaction restores working context

Claude compaction erased short-term context, including the active spec folder, recent code focus and the rules guiding the work. `PreCompact` now caches a compact recovery payload, and `SessionStart` injects it only for `source=compact`. Attention signals, spec-folder detection and token-budget controls keep the recovered brief small enough to use.

&nbsp;

#### Each session source gets the right brief

Startup, resume, clear and compact previously received too much context or the wrong context because they were treated too similarly. Priming now restores cached context for compacts, points resumes to the compact-brief flow, surfaces tool and freshness guidance at startup and gives clears minimal recovery instructions.

&nbsp;

#### End-of-session state can be saved

Session usage had little durable tracking, and end-of-session state was not reliably captured automatically. Stop-hook tracking parses transcript usage, records hook-state metrics and estimates token spend. Configured thresholds can trigger a best-effort `generate-context.js` save.

&nbsp;

#### Hookless runtimes can recover

Runtimes outside the Claude hook family depended on manual priming. MCP first-call priming plus `session_resume`, `session_health` and `session_bootstrap` provide one main recovery path, with structural bootstrap expected behaviors and startup briefs for OpenCode-style flows.

&nbsp;

#### Hook recovery handles stale state

Cache races, weak temporary-file handling, session-state collisions and insufficient provenance markers made the hook path fragile. TTL checks, SHA-256-based state names, restrictive file permissions, provenance fencing, stale-on-read checks and response-envelope cleanup tightened the hook-state lifecycle.

&nbsp;

#### Context budgets share unused capacity

Fixed shares wasted capacity when one source was quiet, while a pure shared pool could starve important context. Floors-plus-overflow budgeting gives constitutional context, graph context, semantic hints and triggered memories a baseline allocation while sharing spare capacity.

&nbsp;

#### Startup highlights show relevant code

Early structural highlights repeated symbols, included vendored code and used the wrong ranking rule. Follow-on phases added shared startup brief builders, an explicit structural-bootstrap expectation and a final cleanup that deduplicates symbols, excludes non-project paths and ranks by incoming callers instead of outgoing callers.

## Structural Code Graph

#### Structural questions get direct answers

Semantic search could find code by meaning but could not answer questions about callers, imports or dependency chains. A structural indexer extracts symbols, relationships and call edges into a SQLite-backed graph, with scan, query, status and context-expansion tools exposed through MCP.

&nbsp;

#### Parsing handles more code shapes

Regex-only parsing misclassified abstract methods, class expressions, multi-import captures and nested class names. Parser adapters moved extraction toward tree-sitter while retaining regex as a fallback, and follow-on fixes improved classification accuracy.

&nbsp;

#### Structural answers use fresh state

A stale graph could look authoritative while pointing at the wrong branch. Readiness checks, HEAD-change detection and tracked-file modification times now support reindexing before answers drift, with status reported as fresh, stale or empty.

&nbsp;

#### Semantic hits expand into structure

Semantic search, structural search and memory search had little guidance on when to use each one. Seed resolution and context orchestration now let CocoIndex hits expand into nearby structural relationships, while intent metadata guides semantic, structural and session-history questions to their respective search surfaces.

## Search & Retrieval

#### Queries survive broken filters

Two filters silently discarded every result from a healthy database of 999 memories. Unscoped queries were treated as having no owned access, and a lifecycle-state check used a column that did not exist. Scope enforcement now requires deliberate opt-in. The lifecycle-state filter was removed while state storage remains unimplemented. Queries then returned 4-5 results with both vector and FTS5 channels contributing.

&nbsp;

#### Top matches stand apart

The reciprocal rank fusion smoothing constant `k=60` was designed for corpora of 10,000 or more documents, but with 999 memories it left only 0.002 between rank 1 and rank 10. Changing `k` to 40 doubled that separation to 0.004, making higher-ranked results easier to distinguish.

&nbsp;

#### Exact phrases match together

Searching for `spec kit` previously matched documents containing `spec` or `kit` individually. A double-quoting bug could wrap already-quoted phrases again and create invalid FTS5 syntax that silently dropped results. Multi-word queries now add FTS5 phrase variants beside individual tokens, and the FTS5 path detects already-quoted terms so they do not get a second pair of quotes. Exact-phrase matches are now boosted properly.

&nbsp;

#### Focused searches keep candidates

Folder discovery could become a hard search filter, and deep mode could mistake an ephemeral `sessionId` for governance scope. Folder discovery no longer turns into a hard scope filter. An empty discovered-folder pass retries without that scope, and Stage-1 candidate generation no longer treats a plain `sessionId` as governed input.

&nbsp;

#### Long matches use less space

The 1,500-token search budget often cut results down to one of seven or more matches, and unusually long matches could cause whole results to be removed too early. The budget is now 2,500 tokens. Oversized content is shortened before results are dropped, and additional matches keep compact metadata after full-content slots run out.

&nbsp;

#### Deprecated memories stay excluded

Vector search excluded deprecated-tier memories while FTS5 did not, so deprecated content could return through the lexical path. Both channels now apply the same exclusion, keeping results consistent across search paths.

&nbsp;

#### Related memories join results

Co-activation expected `related_memories` in object form while the database stored scalar arrays, so the parser silently failed and co-activation never contributed. Scalar entries also received similarity `0.5` on a 0-100 scale, making boosts two orders of magnitude weaker than intended. The format and scale were corrected, and co-activated memories now enter the fusion candidate pool properly.

&nbsp;

#### Reranking preserves diversity

Concatenating a title and body before scoring let a strong title match cancel against a weak body. They are now scored separately. The MMR diversity pass runs even when the full reranker is unavailable, and a new `rerankProvider` metadata field records which reranker path was taken.

&nbsp;

#### Search traces show active channels

It was hard to tell which channels contributed or whether graph signals were active. Stage 1 now reports `activeChannels` and Stage 2 emits zero-contribution graph diagnostics. Per-stage timing is persisted and the embedding cache tracks hit and miss statistics.

&nbsp;

#### Vector search stays on populated data

After lazy Voyage-4 initialization, vector search could switch from the populated `context-index.sqlite` database to an empty provider-specific one. Database selection now stays with the active populated database, and startup reports its path and refuses to rebind consumers to an empty database.

## Saving Memories

#### Structured saves keep their details

JSON and STDIN payloads bypassed normalization, so the extractor chain received empty input despite the information in the request. Structured payloads now pass through the existing normalization path before extraction, and JSON-mode structured saves moved from unusable 0/100 output to a repeatable 55-75/100 quality range.

&nbsp;

#### Transcript-free saves tell a story

Structured saves without a transcript lacked narrative material and collapsed into thin placeholders with generic titles and summaries. The extractor stack now synthesizes a minimal structured conversation when prompts are absent and derives title and summary fields from session data.

&nbsp;

#### Decision lists scan cleanly

Decision strings could repeat themselves, and noisy file lists could bury important references. The changes reduce repeated decisions and tighten key-file shaping so saved memories are easier to scan.

&nbsp;

#### Sibling references score fairly

The quality validator treated valid references to nearby child phases from the same workstream as foreign contamination. It now relaxes that check for structured same-parent sibling references without opening a broad cross-spec bypass.

&nbsp;

#### Shared saves respect boundaries

Shared-memory admin operations lacked transport warnings, and path handling needed stronger workspace boundaries. Admin paths now carry trusted-transport warnings, the V-rule bridge stops with an error and shared paths validate workspace boundaries.

## Cross-Runtime Parity

#### Hooks and tools share recovery

A hook-only design would have made recovery strong in Claude and second-class elsewhere. Hooks remain where they work well, tool-driven recovery is available to other runtimes and both paths share logic rather than forking the recovery model.

&nbsp;

#### Runtime recovery follows one contract

Runtime instructions, context-prime agents and bootstrap surfaces had drifted apart, leaving different wording and guarantees for the same recovery concept. Non-hook recovery now defines ready, stale and missing structural states, uses `session_bootstrap` as the main path and mirrors routing and recovery tables across runtime-facing docs and agent definitions.

&nbsp;

#### Tool routing follows the question

Passive instructions to use CocoIndex let the AI fall back to `Grep` or `Glob` when a better tool was available. Routing nudges now reach server instructions, PrimePackage state, tool hints, runtime docs and context-prime agents, directing semantic questions to CocoIndex, structural questions to the code graph and session-history questions to memory surfaces.

## Security

#### Duplicate checks honor scope

Duplicate detection did not fully respect governed scope, so one scope could learn that matching content existed somewhere it could not inspect. Duplicate checks now stay inside the caller's governed boundary and redact cross-boundary details, with governed scope and metadata redaction applied to duplicate-preflight queries as well.

## Data Quality & Indexing

#### Spec and memory data was cleaned

Spec documents and memory files had frontmatter and anchor drift, and some memory files blocked indexing. The audit covered 186 spec folders. It corrected 2,081 frontmatter issues, added 4,291 anchors and removed 46 hard-block memory files. Orphaned vectors were cleaned, and the memory database was rebuilt from clean inputs. Final status was 175/175 in-scope folders at zero validation errors, down from 97 active and 65 archived.

&nbsp;

#### Bulk reindex accepts valid files

The reindex validator rejected 1,106 legitimate files because batch inputs lacked file-path context and topic checks rejected memory notes for describing outcomes in plain language. File-path context was added. Topic checks no longer apply to memory notes or spec-defining documents, and forced rebuilds treat quality issues as warnings. Blocked files fell from 1,106 to zero.

&nbsp;

#### Context types use canonical names

Aliases such as `decision` and `discovery` remained where the model expected `planning` and `general`, causing validation noise and brittle migrations. Canonical context types now apply across parser logic, migrations, runtime consumers and a database CHECK constraint. The schema moves from version 24 to 25 and migrates old values before that constraint is enforced. `contextType` values use `research`, `implementation`, `planning` or `general`. The cleanup migrated 2,009 legacy values and removed 13,211 duplicate rows.

&nbsp;

#### Indexing and adaptive fusion stabilized after the repository move

A repository move left CocoIndex on stale state, required a BM25 rebuild and made adaptive-fusion defaults unevenly visible across clients. CocoIndex was rebuilt against the active repository with 51,820 files and 663,336 chunks. BM25 was re-indexed against 1,228 memories, the code-graph database gained first-use lazy initialization and fused output preserves lexical provenance.

## Upgrade Notes

No migration required. Schema changes are backward-compatible and migrate automatically on startup.

- **Use canonical `contextType` values.** New values should be `research`, `implementation`, `planning` or `general`, not legacy aliases such as `decision` and `discovery`.
- **Enable access-scope enforcement deliberately.** Multi-tenant deployments should turn it on explicitly because it is opt-in.
- **Expect source-aware recovery.** Session recovery branches by `compact`, `startup`, `resume` and `clear`. Each source gets tailored context.
- **Expect tool-routing guidance.** Semantic questions are directed toward CocoIndex, structural questions toward the code graph and session-history questions toward memory surfaces.
- **Keep scripts on their CommonJS contract.** `@spec-kit/shared` and `@spec-kit/mcp-server` use native ESM, while `@spec-kit/scripts` remains CommonJS.
