This patch scopes save-time entity linking to the memory just written and makes scheduled graph refresh perform real work instead of a warning-only no-op. It is a direct runtime patch in `system-spec-kit` memory and causal-graph code paths and uses no spec folder.

## What's New at a Glance

- **Entity linking now follows the saved memory.** Instead of rescanning the full cross-document entity graph on every save, the incremental path resolves the saved memory's entities, expands them through aliases and finds only matching memories in other spec folders. It creates only those cross-document edges, bounding normal save-time work to the changed memory while keeping the full linker as a broad fallback.
- **Scheduled refresh now runs its callback.** Scheduled refresh could queue work but log that no refresh function was registered. The MCP server now registers a global refresh function at startup, which recomputes the dirty-node set against the live database, clears dirty markers after success and logs the applied refresh with dirty-node and updated-edge counts.

## Upgrade

No migration required. This patch is runtime-only and backward compatible.
