This release completes the remaining spec-document indexing fix from v3.0.0.1 and combines overlapping memory commands. Spec documents can pass the indexing gates without being blocked, and memory work is grouped into four commands instead of five.

> Spec folder: `specs/system-spec-kit/022-hybrid-rag-fusion/022-spec-doc-indexing-bypass/`

## Why This Release

The release as a whole aims to make the workflow easier to follow and easier to trust.

## What's New at a Glance

- **All four indexing gates now warn on spec documents.** Logged concerns no longer block indexing.
- **`/memory:analyze` and `/memory:shared` no longer stand alone.** Search takes over analyze, while manage now contains shared operations.
- **Documentation reflects the command consolidation.** Updated references include manual testing scenarios and agent definitions.

---

## Spec Document Indexing

#### Spec Documents Reach Indexing

The quality gate for saving memories has four checkpoints in order: validation rules check for required formatting, sufficiency checks for meaningful content, template expected behavior checks for expected template structure and metadata checks for required fields such as trigger phrases. The v3.0.0.1 release fixed the metadata check, but the three earlier checks were still rejecting spec documents before they reached it, so 1,807 spec documents were still being rejected.

All four checkpoints now log concerns without blocking spec-document indexing. Memory files continue to be fully validated through all four checkpoints.

---

## Memory Commands

#### Search and Manage Absorb Commands

Two of the five separate memory commands overlapped significantly and were merged. The resulting four commands are:

- **`/memory:search`.** This is the single command for finding and analyzing memories, running evaluations, exploring causal graphs and viewing learning history. It incorporates `/memory:analyze` and covers 33 tools.
- **`/memory:manage`.** It handles database maintenance, the shared-memory lifecycle, checkpoints and bulk operations. Its `shared` section covers creating shared spaces, managing memberships and checking status, replacing `/memory:shared`.
- **`/memory:save`.** It saves conversation context to memory.
- **`/memory:learn`.** It creates and manages constitutional memories, which are always-present rules.

## Documentation

#### References Follow New Commands

Spec folders, feature catalog entries and manual testing scenarios were updated to reflect the command consolidation. Agent definitions across all four runtime directories were updated to reference the new command names. Evaluation test IDs were remapped for consistency.

## Upgrade Notes

- **Rebuild the MCP server.** Run `npm run build` in `mcp-server/`.
- **Restart the MCP server.**
- **Verify indexing.** Run `memory_index_scan({ force: true })` to verify that 0 spec documents are rejected.
- **Breaking:** Update workflows or scripts using `/memory:analyze` to use `/memory:search`, and those using `/memory:shared` to use `/memory:manage shared`.
- **Database migration.** None is required.
