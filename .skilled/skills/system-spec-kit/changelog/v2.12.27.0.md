# v2.12.27.0, The Catalogs Cover the Root Instruction File

A command a catalog does not record is one a reader has to find by accident. The doctor commands category now carries `/doctor:agents-md` in the same shape as the entries beside it, and the manual testing playbook adds the two scenarios that no suite can run.

> Spec folder: `specs/agents/021-doctor-agents-md/001-doctor-agents-md/005-verification-and-docs` (Level 2)

&nbsp;

## What's New at a Glance

- **The category names the command and its three targets.** `check` reports twelve rows and writes nothing, `embed` composes and writes only against the digest its own plan printed, and `restore` puts back the paths one recorded run wrote.
- **The engines are listed as they are owned.** The check engine, the embed engine, the manifest generator and the shipped manifest each get their own row, so a reader reaches the file that answers a question rather than the router that dispatches it.
- **The router list is corrected rather than recounted.** The description said eight routers and named nine commands, so the count is gone and every router the family ships is named once.
- **Two scenarios ask what a live session sees.** One asks a Devin session to quote the last line of the repository block, the other asks a Cursor window to quote a line of the generated rule file. Each records `UNKNOWN` with its reason until an operator runs it, because a default pass would claim a fact nobody observed.
- **The playbook index carries both rows.** `DOC-396` and `DOC-397` sit beside the other doctor scenarios, and the category README says where they run, which is a throwaway folder rather than the shared test environment.

&nbsp;

## Upgrade

No migration required. A repository that copies this catalog or playbook picks up the new entries when it refreshes that copy.
