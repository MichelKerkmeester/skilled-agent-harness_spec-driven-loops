# v2.12.27.0, The Catalogs Cover the Root Instruction File

A command a catalog does not record is one a reader has to find by accident. The doctor commands category now carries `/doctor:agents-md`. It has the same shape as the entries beside it. The manual testing playbook adds two scenarios. No suite can run them.

&nbsp;

## What's New at a Glance

- **The category names the command and its three targets.** `check` reports twelve rows and writes nothing. `embed` composes and writes only against the digest its own plan printed. `restore` puts back the paths one recorded run wrote.
- **The engines are listed as they are owned.** The check engine, the embed engine, the manifest generator and the shipped manifest each get their own row. So a reader reaches the file that answers a question, not the router that dispatches it.
- **The router list is corrected rather than recounted.** The description said eight routers and named nine commands. So the count is gone. Every router the family ships is named once.
- **Two scenarios ask what a live session sees.** One asks a Devin session to quote the last line of the repository block. The other asks a Cursor window to quote a line of the generated rule file. Each records `UNKNOWN` with its reason until an operator runs it. That is because a default pass would claim a fact nobody observed.
- **The playbook index carries both rows.** `DOC-396` and `DOC-397` sit beside the other doctor scenarios. The category README says where they run. That place is a throwaway folder, not the shared test environment.

&nbsp;

## Upgrade

No migration required. A repository that copies this catalog or playbook picks up the new entries. It picks them up when it refreshes that copy.
