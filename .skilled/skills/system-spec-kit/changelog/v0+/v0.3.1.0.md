This release completes alignment remediation for spec 023/016. It fixes save-quality-gate persistence edge cases and hybrid-search deduplication and fallback routing behavior while bringing feature-summary documentation in line with runtime truth. The work makes the workflow easier to follow and trust by addressing important problems and explaining results more clearly.

> Spec folder: `.opencode/specs/system-spec-kit/022-hybrid-rag-fusion/016-refinement-phase-5` (Level 2)

## What's New at a Glance

- **Save quality gate tracks each active database handle.** It tracks config-table ensure state per handle and reruns the database schema safely after handle changes.
- **Activation timestamp initialization handles restarts.** `ensureActivationTimestampInitialized` preserves the persisted warn-only window state across restart.
- **The save quality gate gains two focused regressions.** One checks that the config table is set up again for each new database handle, and the other that a save leaves an existing activation timestamp in place, so a warn-only window that already ran out still enforces.
- **Canonical ID dedup now spans both search paths.** It applies in `combinedLexicalSearch()` and legacy `hybridSearch()` for `42`, `"42"` and `mem:42`.
- **Tier-2 fallback forces all retrieval channels.** It uses `forceAllChannels` and bypasses simple-route channel reduction.
- **Hybrid search gains three regressions.** One checks that lexical search drops duplicate canonical ids, a second that the legacy hybrid path drops them across channels, and a third that tier-2 fallback forces every retrieval channel for simple-routed queries.
- **Parent summary wording is corrected.** It covers RSF/shadow/fallback semantics, the R11 default and shadow-period wording, TM-05 hook scope and dead-code references.
- **S5/entity-linking wording is corrected.** It covers global density checks, database batching and MPAB naming. It also corrects PI-B3 labeling and active search-flag count.
- **Child Level 2 docs now show tranche status.** The docs in `016-refinement-phase-5` mark tranche-1 through tranche-4 as completed.
