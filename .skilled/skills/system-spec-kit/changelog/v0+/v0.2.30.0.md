# system-spec-kit v0.2.30.0

This release fixes the MCP server's SQLite "no such table" errors in `/memory:manage`.

- The fix has four layers.
- Tool access and a health-check guard are two.
- Schema resilience and actionable error messages are the rest.

A code review pass also cleaned up variable naming.

- It also cleaned up shared error handling.
- It also cleaned up stale section references.
- It also cleaned up the health table list.

&nbsp;

## Why This Release

The errors hit the `memory_index` and `checkpoints` tables.

- They came when the LLM fell back to raw `sqlite3` Bash commands.
- Those commands ran against uninitialized databases.

## The Manage Command

The command gains an explicit tool enforcement block and two error handling rows.

#### Tool Rules and Recovery Rows <a id="c-tool-rules-and-recovery-rows"></a>

- `/memory:manage` drops Bash from its allowed tools.
- The LLM loses the fallback that led to the errors.
- The command gains an explicit tool enforcement block.
- That block prohibits direct database access.
- The two new error handling rows are "MCP tool unavailable" and "Database not initialized".
- They give actionable guidance when a tool or the database is not ready.

#### References and Tables Brought Current <a id="c-references-and-tables-brought-current"></a>

- Seven stale section number references in the command's routing tree are fixed.
- One example is a Section 5 reference that now reads Section 7.
- The health check output template now includes the `memory_history`, `checkpoints` and `memory_conflicts` tables.
- It no longer lists `session_state`.
- That table is managed by session-manager, not companion tables.

&nbsp;

## Database Safety

The health check now reports a missing schema. Companion tables are created on both paths.

#### Health Checks Report a Missing Schema <a id="c-health-checks-report-a-missing-schema"></a>

- `handleMemoryHealth()` now awaits `checkDatabaseUpdated()`.
- It was the only handler missing this standard guard.
- A missing table used to leave the health check silently reporting a "degraded" status.
- The handler now detects "no such table".
- It returns `E_SCHEMA_MISSING` with recovery instructions.

#### Companion Tables on Both Paths <a id="c-companion-tables-on-both-paths"></a>

- Companion table setup is extracted into `ensureCompanionTables()`.
- The companion tables are now always created, even when `memory_index` already exists.
- `ensureCompanionTables()` carries TSDoc.
- It holds idempotent `CREATE TABLE IF NOT EXISTS` statements for `memory_history`, `checkpoints` and `memory_conflicts` plus their indexes.
- `create_schema()` calls it from both its existing-database early-return path and its new-database path.

#### Errors That Name a Fix <a id="c-errors-that-name-a-fix"></a>

- Error messages suggest specific recovery actions.
- Four null-database responses are also aligned with each other.
- The improved messages cover the null-database responses in `requireDb()`, `checkpoints.getDatabase()`, `handleMemoryList()` and `handleMemoryStats()`.
- The checkpoints module also drops its module prefix from the error it throws.

&nbsp;

## Code Cleanup

A code review pass cleaned up variable naming and shared error handling.

#### Consistent camelCase Names <a id="c-consistent-camelcase-names"></a>

- Local variables move from snake_case to camelCase.
- `spec_folder` becomes `specFolder` and `checkpoint_name` becomes `checkpointName`.
- The rename covers all snake_case local variables in `handleMemoryDelete`, `handleMemoryUpdate`, `handleMemoryList` and `handleMemoryStats`.
- One example is `allow_partial_update` to `allowPartialUpdate`.
- The backward-compatible snake_case alias block gains a comment with removal guidance.

#### One Shared Error Helper <a id="c-one-shared-error-helper"></a>

- Checkpoints share one error helper.
- `toErrorMessage()` replaces all eight inline error patterns.
- The checkpoints module imports `toErrorMessage()` from the db helpers.
- Each replaced pattern had the form `error instanceof Error ? error.message : String(error)`.

#### Standard Types and Shorthand <a id="c-standard-types-and-shorthand"></a>

- `requireDb()` returns a standard `NonNullable<>` type.
- The health handler response also uses ES2015 property shorthand.
- The `NonNullable<>` utility type replaces the `and {}` intersection trick in the `requireDb()` return type.
- The property shorthand applies to `embeddingModelReady` and `memoryCount`.
