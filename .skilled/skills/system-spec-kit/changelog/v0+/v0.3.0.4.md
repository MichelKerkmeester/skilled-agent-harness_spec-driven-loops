This release finalizes canonical frontmatter normalization. It also finalizes an idempotent reindex workflow. Both apply to templates, spec and memory markdown. It makes instructions and release notes easier for non-developers to follow. It also makes the workflow easier to follow and trust.

## What's New at a Glance

- **Normalization and composition follow a deterministic schema.** The rule applies to the targeted markdown classes.
- **The migration runs in apply or dry-run mode.** Both modes showed stable behavior on a second run.
- **Archived invalid-anchor warnings remain non-blocking.** They were documented. They were intentionally not remediated in this scope. Performance and formal governance controls remain tracked in the checklist.

## Upgrade

For new corpus updates, run the migration in dry-run mode first. Then apply it and rerun reindex. Keep the order as normalize, verify, rebuild. That preserves deterministic outcomes. No database schema migration is required.
