# system-spec-kit v0.1.0.0

This release corrects memory decay and adds token-budget information to handler responses.

- Every handler response includes the `TokenBudget` field in its metadata.
- Memories had been decaying about 4.5 times slower than the FSRS v4 standard.
- `Console.error` logging was updated for cases when token budgets were exceeded.

It also addresses reliability problems in memory-index behavior.

- Security handling for `SafeParseJson` was aligned across modules.
- The vector index lost dead code.
- The project lost nine orphaned files.

The goal is to make the workflow easier to follow and easier to trust.

- The instructions and release notes were made easier for non-developers to follow.
- MCP server and memory-system documentation changed.
- Reported test failures were resolved.

## Memory and Response Behavior

Handlers now expose token budgets. The FSRS memory-decay calculation was corrected.

#### Budget Signals Reach Responses <a id="c-budget-signals-reach-responses"></a>

- Every handler response includes the `TokenBudget` field in its metadata.
- `Console.error` logging was updated for cases when token budgets were exceeded.
- Hint injection in responses was updated for cases when budget thresholds are hit.

#### Memory Decay Uses the Corrected Formula <a id="c-memory-decay-uses-the-corrected-formula"></a>

- The factor changed from 19.0 to 19/81 (~0.2346).
- The formula changed from `R = (1 + t/(FACTOR*S))^(-0.5)` to `R = (1 + FACTOR*t/S)^(-0.5)`.
- The corrected result is `R(S,S) = 0.9` as specified.
