## Hybrid Retrieval

Retrieval now returns a typed envelope that shows its work. Strategy follows the artifact class and the intent.

#### Retrieval Shows Its Work <a id="c-retrieval-shows-its-work"></a>

- Every retrieval now returns a typed `ContextEnvelope`.
- It carries a stage trace.
- It also carries retrieval metadata.
- The envelope's stage trace covers candidate, filter, fusion, rerank and fallback.
- It also states the expected behavior for degraded mode.

#### Weights Follow the Artifact and the Intent <a id="c-weights-follow-the-artifact-and-the-intent"></a>

- Retrieval strategy routes across 9 artifact classes.
- Artifact-aware routing uses deterministic weight tables.
- Adaptive hybrid fusion adds intent-aware profiles.
- The intent-aware fusion profiles support `fix_bug`, `add_feature`, `understand`, `refactor`, `security_audit`, `find_spec` and `find_decision`.

#### A Safe Path to Adaptive Fusion <a id="c-a-safe-path-to-adaptive-fusion"></a>

- Adaptive fusion can be compared in a dark run.
- Dark-run comparison mode sets adaptive behavior against deterministic fusion.
- It does this without changing live retrieval output.
- The feature-flag safety model is retained for controlled rollout behavior.
- `SPECKIT_ADAPTIVE_FUSION` remains default-off.

#### Telemetry Covers Two Memory Tools <a id="c-telemetry-covers-two-memory-tools"></a>

- Extended telemetry now covers `memory_search` and `memory_context`.
- It captures latency, mode, fallback and quality-proxy dimensions.
- `SPECKIT_EXTENDED_TELEMETRY` remains default-on.

## Safer Memory Handling

The ledger records every memory change without allowing edits. Extraction and eviction now follow deterministic rules.

#### Immutable Ledger Entries With Hash Chains <a id="c-immutable-ledger-entries-with-hash-chains"></a>

- An append-only mutation ledger records create, update, delete and reindex operations.
- Its entries are immutable.
- SQLite triggers enforce the immutability of each ledger entry.
- The entries carry hash-chain linkage.

#### Predictable Extraction and Memory Eviction <a id="c-predictable-extraction-and-memory-eviction"></a>

- Extraction, provenance and configuration are hardened.
- Extraction now falls back to a deterministic `memory_id`.
- Cognitive config parsing now uses Zod validation.
- Working-memory eviction now enforces deterministic LRU ordering.
