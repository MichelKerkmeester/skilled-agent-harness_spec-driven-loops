This release hardens the post-update MCP recovery guide. It rewrites the Spec Kit Memory install guide to workflows-documentation standards. It adds operator-ready recovery and verification guidance for update-related MCP failures. The instructions and release notes are easier for non-developers to follow. The workflow is easier to follow and trust.

## What's New at a Glance

- **The INSTALL GUIDE follows the install-guide template.** It uses a structured format. It has an AI-first flow, phased validation checkpoints and better scannability.
- **The guide clarifies what contributes to the root cause.** It names `node_modules` relocation as one contributor. That relocation is not the sole root cause. It also covers workspace install/build mismatch and native ABI mismatch.
- **The guide standardizes guidance on the runtime database path.** It names `mcp-server/dist/database/context-index.sqlite` as the main runtime database path. It documents compatibility symlink behavior.
- **The guide adds a fast recovery sequence for post-update failures.** The sequence uses install, build and native checks.
- **The guide adds procedures for specific error signatures.** They address a reliability problem. That problem involves `@spec-kit/shared` module resolution failures, `ERR_DLOPEN_FAILED`/`NODE_MODULE_VERSION` and `sqlite-vec` degradation mode.
- **The guide adds operational health checks.** It gives concrete verification commands. It also gives expected outcomes for post-recovery validation.

## Upgrade

No migration required. Pull the latest version. If you hit post-update MCP startup issues, follow the recovery flow in INSTALL GUIDE.
