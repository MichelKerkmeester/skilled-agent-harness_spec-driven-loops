This release fixes two MCP server bugs. They blocked Claude API tool calls. They also made `memory_save` with `force: true` fail after incomplete deletions. It makes the workflow easier to follow and easier to trust.

## What's New at a Glance

- **`memory_delete` no longer uses top-level `oneOf`.** The Claude API rejects `oneOf`, `allOf` and `anyOf` at the top level of tool schemas. That blocked all MCP tool calls, including subagent dispatch.
- **A defensive delete precedes vector inserts.** `memory_index` has no AUTOINCREMENT. So SQLite can reuse the rowids of deleted rows. Those rows had a `vec_memories` counterpart that was not cleaned up. That made `memory_save` with `force: true` fail with a UNIQUE constraint error.

## Upgrade

No migration required. Both fixes are backward-compatible. The `memory_delete` handler already validates the either/or constraint server-side. So removing `oneOf` affects Claude API compatibility only. The defensive delete does nothing when no orphaned vector entry exists.
