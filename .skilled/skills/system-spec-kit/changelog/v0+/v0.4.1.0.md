This release corrects spec-folder paperwork to match completed work and actual validator behavior. So the workflow is easier to follow and trust.

## What's New at a Glance

- **Decision-record statuses now match completion.** In 014, three records changed from Proposed to Accepted after the work was complete.
- **The 014 checklist separates verification from sign-offs.** It identifies completed verification separately from Product Owner approval and Security review. Those are deferred until production handoff. The checklist explains why they do not block completion.
- **The Level 2 `015-skill-alignment` checklist corrects its validation claim.** The validation script exits with errors because the validator flags relative paths such as `../../../../skill/...` as broken. The checklist explains that these paths resolve correctly from deep inside the spec-folder tree. It explains why the errors are acceptable.
- **The implementation summary documents relative-path resolution.** It explains that the `015-skill-alignment` folder's depth inside `.opencode/specs/...` lets `../../../../skill/` correctly reach `.opencode/skills/`. That dependency had been assumed.

## Upgrade

No migration required. These documentation-only changes make no code changes. They have no runtime impact.
