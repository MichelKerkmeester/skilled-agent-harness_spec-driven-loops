# system-spec-kit v0.2.4.0

Project READMEs are a fourth memory source.

- This release expands the memory system.
- It indexes project READMEs alongside spec files, constitutional files and skill READMEs.
- `findProjectReadmes()` discovers them.
- The `IncludeReadmes` parameter controls README scanning.

Anchor lookups and template IDs changed.

- It also adds anchor prefix matching. Lookups fall back to prefix matching.
- A short anchor name now finds the composite IDs that start with it.
- The context template uses short anchor IDs.
- All 24 drop their `{{SESSION_ID}}-{{SPEC_FOLDER}}` suffixes.

Resume detection is more reliable.

- Resume detection bugs are fixed.
- They traced back to five root causes.

The release focuses on non-developers.

- It focuses on making the instructions easier for non-developers to follow.
- It focuses on making the release notes easier for non-developers to follow.

## README Indexing

The memory system gained a fourth source. Project READMEs join spec files, constitutional files and skill READMEs.

#### Project READMEs Join the Index <a id="c-project-readmes-join-the-index"></a>

- Until this release the memory system indexed only three sources.
- `findProjectReadmes()` is a new discovery function for project-level README files.
- It gives them an importance weight of 0.4.
- The `IncludeReadmes` parameter belongs to `memory_index_scan`.
- It defaults to true.
- Importance weights are tiered across user work, project READMEs and skill READMEs.
- The scoring formula applies them as `score *= (0.5 + importance_weight)`.

#### Anchors and Frontmatter for READMEs <a id="c-anchors-and-frontmatter-for-readmes"></a>

- 74 READMEs across the project are anchored.
- Those READMEs carry about 473 anchor tags under the README anchor schema.
- A README can include YAML frontmatter.
- It holds `title`, `description`, `trigger_phrases` and `importance_tier`.

#### Symlinked READMEs No Longer Missed <a id="c-symlinked-readmes-no-longer-missed"></a>

- `FindSkillReadmes()` used to miss symlinked READMEs.
- Symlinked READMEs are discovered.
- `FindSkillReadmes()` now handles them.
- An `isSymbolicLink()` check closes that gap.
- An audit counted 96 READMEs on disk and 93 to 94 indexed.
- Coverage was 100% after the symlink fix.

## Anchors

Anchor handling changed in two ways. Lookups accept short names and template IDs became clean names.

#### Short Anchor Names Find Composite IDs <a id="c-short-anchor-names-find-composite-ids"></a>

- A lookup with anchors set to `['summary']` used to return empty.
- The keys were composite IDs such as `summary-session-...`.
- Anchor lookups fall back to prefix matching.
- A short anchor name now finds the composite IDs that start with it.
- An exact match now takes priority.
- The shortest prefix is the fallback.
- Anchor filtering in search results supports prefix matching.
- It enforces hyphen boundaries.

#### Clean Anchor IDs in the Context Template <a id="c-clean-anchor-ids-in-the-context-template"></a>

- The context template uses short anchor IDs.
- All 24 drop their `{{SESSION_ID}}-{{SPEC_FOLDER}}` suffixes.
- The template-generated IDs ran 80 to 120 characters with underscores.
- They violated `VALID_ANCHOR_PATTERN`.
- With those suffixes gone, each ID is a clean semantic name.

#### No Parsing Bug in Check-Anchors <a id="c-no-parsing-bug-in-checkanchors"></a>

- The check-anchors awk was incorrectly reported as having a `/` parsing bug.
- The B5 audit confirmed that no bug exists.

## Resume Detection

Resume detection had several failures. Five root causes were resolved.

#### Five Root Causes Resolved <a id="c-five-root-causes-resolved"></a>

- Two causes sat in the glob patterns.
- They were a wrong base path and insufficient glob depth.
- Two more sat in the tiers.
- Tier 2 used the wrong semantic query.
- Tier 3 used a trigger that was too generic.
- The fifth was tier skipping.

## Documentation

Documentation now reflects four-source indexing. Several docs were added or updated.

#### New and Updated Documentation <a id="c-new-and-updated-documentation"></a>

- A new README documents the directory structure.
- The memory system doc now says "four sources" where it said "three sources".
- The save workflow doc adds project READMEs to its indexed content documentation.
- `SKILL.md` expands its README Content Discovery section.
- It adds `findProjectReadmes()` and the weight tiers.
- Docs catch up with four-source indexing.
- `readme_indexing.md` is a comprehensive reference for the README indexing pipeline.

#### Documentation Mismatches Corrected <a id="c-documentation-mismatches-corrected"></a>

- Documentation mismatches are fixed.
- One README had 17 parameter documentation mismatches.
- Among the README parameter fixes, three phantom parameters are removed.
- 14 undocumented ones are added.
- The troubleshooting doc's version moves from v1.7.1 to v1.7.2.
- The troubleshooting doc also documents the dual decay model (FSRS day-based plus turn-based).
- A README anchor name mismatch is corrected from `structure` to `architecture`.
