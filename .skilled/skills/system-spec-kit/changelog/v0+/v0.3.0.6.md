This state-sync release brings Spec Kit's phase system to recommendations, creation, command routing and recursive validation. It makes instructions and release notes easier for non-developers to follow. The goal is to make the workflow easier to follow and trust.

&nbsp;

## What's New at a Glance

- Recommendation adds `--recommend-phases` and `--phase-threshold`.
  - They support phase scoring and recommendation outputs.
- Creation adds `--phase`, `--phases` and `--phase-names`.
  - Phase creation includes parent/child linkage metadata.
- `/spec_kit:phase` adds the phase command.
  - Its workflow assets support autonomous and confirm-style flows.
- `validate --recursive` enables recursive validation.
  - Phase-link rules support parent-child spec trees.
- PHASE boosts intent, resource and command routing.
  - The SKILL routing maps now include those boosts.
- Four existing commands gain phase-aware behavior.
  - The updated commands are `/spec_kit:plan`, `/spec_kit:implement`, `/spec_kit:complete` and `/spec_kit:resume`.
- Phase references and Gate 3 guidance are synchronized.
  - The update covers phase definitions, structure references and validation docs.
  - The update also covers the node graph entry and Gate 3 Option E documentation.
- Spec evidence marks most implementation tasks complete.
  - Three fixture-oriented tasks remain pending.

&nbsp;

## Upgrade

Use phase-specific flags and recursive validation in phase-based workflows. The flags are `--recommend-phases`, `--phase` and `--recursive`. Functional behavior is available now. But fixture-driven closure and final governance sign-off remain pending for this spec. So full verification remains open.
