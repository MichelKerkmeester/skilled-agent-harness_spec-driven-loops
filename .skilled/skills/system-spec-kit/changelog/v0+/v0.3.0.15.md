# v0.3.0.15, MCP Server Remediation

Sprint 8 of the MCP server remediation fixes 15 critical bugs.

- It also removes dead code.
- It applies 13 performance improvements.
- It makes 4 test quality fixes.
- The work ran as three waves of parallel agent delegation.

The changes span storage, scoring, search and dead code.

- Scores stay in range and stop over-counting.
- Search filters and tokenization are fixed.
- Dead shadow-scoring and RSF branches leave hybrid search.
- Four test quality fixes land.

## Storage

Storage covers reconsolidation, checkpoints, causal edges and memory save.

#### Reconsolidation Uses a Real Column <a id="c-reconsolidation-uses-a-real-column"></a>

- Reconsolidation referenced a `frequency_counter` column that does not exist.
- It now uses `importance_weight` merge logic instead.

#### Checkpoint Restores Keep Their Transactions <a id="c-checkpoint-restores-keep-their-transactions"></a>

- SQLite silently auto-commits when it meets a database schema statement.
- During a restore in checkpoints, that corrupted the transaction boundaries.
- The schema statements now run before `BEGIN`.

#### Causal Edge Queries Group Their Conditions <a id="c-causal-edge-queries-group-their-conditions"></a>

- A query in causal edges had an operator precedence bug.
- It read `WHERE a AND b OR c`.
- It now reads `WHERE a AND (b OR c)`.

#### Memory Save Checks That Updates Landed <a id="c-memory-save-checks-that-updates-landed"></a>

- Memory save reported success on `UPDATE` statements that changed zero rows.
- A `.changes > 0` guard on those statements now catches them.

## Scoring and Search

This area covers scores, search filters, tokenization and entity resolution.

#### Composite Scores Stay Between 0 and 1 <a id="c-composite-scores-stay-between-0-and-1"></a>

- A composite score could fall outside the [0,1] range.
- Composite scoring now clamps it with `Math.max(0, Math.min(1, composite))`.

#### Citation Scores Stop Using Recency <a id="c-citation-scores-stop-using-recency"></a>

- Citation scoring had a fallback chain that conflated recency with citation authority.
- That chain is removed.
- The score is 0 when there is no citation data.

#### Cycles and Pairs No Longer Inflate Boosts <a id="c-cycles-and-pairs-no-longer-inflate-boosts"></a>

- The recursive CTE in causal boost used `UNION ALL`.
- That let cycles amplify the boost.
- It now uses `UNION`.
- In temporal contiguity, the inner loop now starts at `j = i + 1`.
- That eliminates the double-counting of pair boosts.

#### Ablation Math Handles Large Inputs <a id="c-ablation-math-handles-large-inputs"></a>

- The ablation framework computed binomial coefficients the naive way.
- That could overflow for n>50.
- It now computes them in log space.

#### Quality Filters Screen the Right Candidates <a id="c-quality-filters-screen-the-right-candidates"></a>

- Summary candidates in Stage 1 now pass through the `minQualityScore` filter in stage1 candidate gen.
- In channel representation, `QUALITY_FLOOR` drops from 0.2 to 0.005.
- That is because RRF scores sit around 0.01 to 0.03.
- The old floor filtered them out.

#### One Tokenizer for Both Text Indexes <a id="c-one-tokenizer-for-both-text-indexes"></a>

- The bm25 index and sqlite fts did not share their FTS5 (built-in text search) tokenization.
- Both now run through one shared `sanitizeQueryTokens()` array.

#### Entity Resolution and Shared Helpers <a id="c-entity-resolution-and-shared-helpers"></a>

- In the extraction adapter, a failed entity resolution now returns null.
- `normalizeEntityName` existed as divergent functions.
- `computeEdgeDensity` was duplicated.
- Each is now consolidated into one version.
- The surviving `normalizeEntityName` is Unicode-aware.

## Dead Code

This area removes code that no longer runs.

#### Dead Flags, State and Exports Removed <a id="c-dead-flags-state-and-exports-removed"></a>

- The dead feature flag functions `isShadowScoringEnabled()`, `isRsfEnabled()` and `isInShadowPeriod()` are removed with the branches.
- So is the dead module-level state `stmtCache`, `lastComputedAt`, `activeProvider` and `flushCount`.
- That goes with 3 dead config fields.
- The dead functions and exports removed are the single-node `computeCausalDepth`, `getSubgraphWeights`, `RECOVERY_HALF_LIFE_DAYS` and `logCoActivationEvent`.

<summary><b>What stayed</b></summary>

- `computeStructuralFreshness` and `computeGraphCentrality` in fsrs are preserved.
- That is because they are planned features and not dead code.

</details>

## Performance

This area makes queries, lookups and trees cheaper to build.

#### Summaries and Counts Scale Safely <a id="c-summaries-and-counts-scale-safely"></a>

- The tfidf summarizer replaces `Math.max(...spread)` with a reduce-based max.
- That prevents a RangeError.
- The unbounded query in memory summaries gains a `LIMIT` clause.
- The mutation ledger now counts with a database `COUNT(*)` and `json_extract`.
- That replaces an O(n) JS scan.

#### The Entity Linker Looks Up Less <a id="c-the-entity-linker-looks-up-less"></a>

- The entity linker used O(n) `.includes()` checks.
- It now uses a `Set` for O(1) lookups.
- Its edge counts ran as N+1 queries.
- They now come from a batch query.

#### Fewer Round-Trips and a Cached Tree <a id="c-fewer-round-trips-and-a-cached-tree"></a>

- Causal edges drops the SELECT that followed each upsert.
- It reads `lastInsertRowid` instead.
- That cuts 3 round-trips to 2.

<details>
<summary><b>Smaller fixes</b></summary>

- `buildHierarchyTree()` in spec folder hierarchy now sits behind a WeakMap TTL cache.
- The cache lasts 60 seconds.

</details>
