# v2.8.4.0, Every Setting in /doctor:env

`/doctor:env` built its list from `ENV-REFERENCE.md` alone. So it could not show or save about 170 settings. Only `.env.example` listed them, the session-relaunch tuning among them. It now reads both. The docs say where to set a value on your own machine.

> Spec folder: `specs/hooks/023-session-relaunch-loop/017-hop-history` (Level 2)

&nbsp;

## What's New at a Glance

- **Every setting appears.** `/doctor:env` adds each `.env.example` setting that `ENV-REFERENCE.md` does not document. The default and description sit on that line. A reference row still wins where both name a setting.
- **More switches can be saved.** `hook-flags.env` is offered for any switch whose reader takes it from that file. So the Jev switches and `SESSION_RELAUNCH_NOTIFY_HOPS` can be saved. The kill switches and validation switches can be saved too.
- **Keys stay hidden.** The Code Mode provider keys in `.env.example` section 1 count as secrets. So `/doctor:env` shows only where each is set. It never asks for one.
- **A token count is not a secret.** A name with `TOKEN` followed later by `FLOOR`, `THRESHOLD` or a similar word counts text tokens. So `SPECKIT_ADVISOR_PROMPT_POLICY_LENGTH_AND_TOKEN_MEANINGFUL_FLOOR` shows its default again.
- **Setting a value locally is written down.** The root README's new Environment Settings section, both example files and `ENV-REFERENCE.md` say where each setting belongs. The choices are a shell export, `hook-flags.env`, Claude Code's `settings.local.json` and `.env`.

&nbsp;

## Upgrade

No migration required. Run `/doctor:env list` to see every setting and where it is set.
