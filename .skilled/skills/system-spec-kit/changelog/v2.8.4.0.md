# v2.8.4.0, Every Setting in /doctor:env

`/doctor:env` built its list from `ENV-REFERENCE.md` alone, so it could not show or save about 170 settings that only `.env.example` listed, the session-relaunch tuning among them. It now reads both, and the docs say where to set a value on your own machine.

> Spec folder: `specs/hooks/023-session-relaunch-loop/017-hop-history` (Level 2)

&nbsp;

## What's New at a Glance

- **Every setting appears.** `/doctor:env` adds each `.env.example` setting that `ENV-REFERENCE.md` does not document, with the default and description written on that line. A reference row still wins where both name a setting.
- **More switches can be saved.** `hook-flags.env` is offered for any switch whose reader takes it from that file, so the Jev switches and `SESSION_RELAUNCH_NOTIFY_HOPS` can be saved as well as the kill switches and validation switches.
- **Keys stay hidden.** The Code Mode provider keys in `.env.example` section 1 count as secrets, so `/doctor:env` shows only where each is set and never asks for one.
- **A token count is not a secret.** A name with `TOKEN` followed later by `FLOOR`, `THRESHOLD` or a similar word counts text tokens, so `SPECKIT_ADVISOR_PROMPT_POLICY_LENGTH_AND_TOKEN_MEANINGFUL_FLOOR` shows its default again.
- **Setting a value locally is written down.** The root README's new Environment Settings section, both example files and `ENV-REFERENCE.md` say which of a shell export, `hook-flags.env`, Claude Code's `settings.local.json` and `.env` each setting belongs in.

&nbsp;

## Upgrade

No migration required. Run `/doctor:env list` to see every setting and where it is set.
