# v2.12.5.0, A Quoted Fence No Longer Hides a Token, and --path Checks Where a Link Points

A deep review of the weak-model authoring work found two defects. The placeholder gate had a defect. It treated ``` and ~~~ as one fence marker, so a ``` line quoted inside a ~~~ block ended the block early. A later unfilled value token went unreported. And `create.sh --path` checked only the parent of a path. That path already existed as a symlink. So a packet could be written outside the repository.

&nbsp;

## What's New at a Glance

- **A v2.3 fence closes only on its own marker.** A fence opens with ``` or ~~~. In both the validator and the shell rule, it closes only on a line of the same character. That line must be at least as long. It must hold nothing but spaces or tabs after it. Pre-v2.3 docs keep the old toggle. So no existing verdict moves.
- **CRLF docs read the same in both scanners.** The shell rule drops a trailing carriage return. The validator already did.
- **`--path` is judged by its real target.** An existing link or folder is resolved first. That happens before the containment check. A link outside the repository is refused. A broken link is refused too. So is a regular file and the repository root. The packet keeps the name you typed.
- **The Draft repair reads less.** Its before-and-after snapshot keeps a digest. That digest covers the `.md` and `.json` files the repair can write. It does not keep every file whole.
- **Docs say what the code does.** `validation-rules.md` states that a recursive run repairs each Draft child. The shell rule's header names what still runs it. The `/speckit:*` command docs no longer describe the warn-only rules in changelog tense.

&nbsp;

No migration required.
