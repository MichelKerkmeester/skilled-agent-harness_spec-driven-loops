# v2.12.5.0, A Quoted Fence No Longer Hides a Token, and --path Checks Where a Link Points

A deep review of the weak-model authoring work found two defects. The placeholder gate treated ``` and ~~~ as one fence marker, so a ``` line quoted inside a ~~~ block ended the block early and a later unfilled value token went unreported. And `create.sh --path` checked only the parent of a path that already existed as a symlink, so a packet could be written outside the repository.

> Spec folder: `specs/system-speckit/054-weak-model-spec-authoring/023-deep-review-remediation` (Level 2)

&nbsp;

## What's New at a Glance

- **A v2.3 fence closes only on its own marker.** In both the validator and the shell rule, a fence opened with ``` or ~~~ closes only on a line of the same character, at least as long, with nothing but spaces or tabs after it. Pre-v2.3 docs keep the old toggle, so no existing verdict moves.
- **CRLF docs read the same in both scanners.** The shell rule drops a trailing carriage return, as the validator already did.
- **`--path` is judged by its real target.** An existing link or folder is resolved before the containment check. A link outside the repository, a broken link, a regular file and the repository root are refused. The packet keeps the name you typed.
- **The Draft repair reads less.** Its before-and-after snapshot keeps a digest of the `.md` and `.json` files the repair can write, not every file whole.
- **Docs say what the code does.** `validation-rules.md` states that a recursive run repairs each Draft child, the shell rule's header names what still runs it, and the `/speckit:*` command docs no longer describe the warn-only rules in changelog tense.
