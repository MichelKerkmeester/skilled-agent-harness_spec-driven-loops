# v2.12.52.0, The Close-Out and Scope Checks Move Earlier

Two checks ran too late. The completion hook judged the evidence but never the request. The restraint rule waited for code. Both now run where the work is decided. The ideas come from the unlazy and ponytail skill repos.

> Spec folder: `specs/other/006-repo-wide-unlazy-tail`

&nbsp;

## What's New at a Glance

- **The hook reminds on every done claim.** A claim in a packet-bound session now draws one reminder. With sound evidence the line reads `claimed done: reread the request and confirm each outcome it asks for is met or named not done`.
- **Missing evidence keeps its words first.** The reminder follows the evidence complaint in the same line.
- **A check that cannot run stays silent.** A timeout or failed spawn still returns ok. The same message in the same packet advises once.
- **Delivery differs by runtime.** Pi and dsh show the line to the model. Claude, Codex and Devin write it to stderr and the log. Cursor and OpenCode log it only.
- **The templates ask the restraint question.** The SCOPE note in `spec.md` and the ARCHITECTURE note in `plan.md` carry the rule. Name what fails today without each new file, option, layer or dependency. Otherwise drop it.
- **The commands run both passes.** `/speckit:plan` and `/speckit:complete` run the restraint pass at the specification and planning steps. `/speckit:implement` and `/speckit:complete` end with a reread of the request.

&nbsp;

## Upgrade

No migration required. A turn that ends on a done claim now shows one extra advisory line. Set `SYSTEM_COMPLETION_SENTINEL_DISABLED=1` to turn the hook off. Whether the model sees Claude's stderr is not confirmed.
