# v2.7.10.0, create.sh Refuses Unknown Options

`create.sh` used to treat any argument it did not recognize as part of the title. A misspelled flag such as `--goal` for `--with-goal` became the start of the folder name, the goal file was never written, and the run still exited 0. It now prints `Error: unknown option '--goal'` with a pointer to `--help` and exits 1 before it writes anything.

> Spec folder: `specs/sk-code/011-sk-code-poinytail-based-refinement/018-create-sh-unknown-options` (Level 1)

&nbsp;

## What's New at a Glance

- **A mistyped flag fails loudly.** Any argument that starts with `-` and matches no option stops the run with exit code 1, the same code the script's other argument errors use.
- **The literal-naming test scenario uses the real flag.** Its command passed `--phase-count`, which never existed and was quietly added to the title. It now passes `--phases`.

&nbsp;

## Upgrade

A title that starts with a dash is now read as an option and refused. Reword such a title, and replace any misspelled flag with the one `create.sh --help` lists.
