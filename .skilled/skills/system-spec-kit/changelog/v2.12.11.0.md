# v2.12.11.0, The Changed-Packet Gate Test Reads Its Event Values From the Step

The changed-packet gate used to write the pull request and push SHAs straight into its script. It now passes them through `env:` entries on the step and reads them as shell variables, which keeps event text out of the script itself. The rule-set comparison test runs that same script against a fixture repository, so it now reads the step's `env:` entries and supplies them as the runner would, and the gate's real comparison is still what the test exercises.

> Spec folder: `specs/sk-code/017-portable-code-modes/008-ci-drift-flags` (Level 2)

&nbsp;

## What's New at a Glance

- **The test follows the workflow's own shape.** It takes the event values from the step rather than from text written into the script, so a later change to those entries reaches the test without an edit, as long as it uses an event value the test already substitutes.

No action is needed. No hook or CLI command changed behaviour.
