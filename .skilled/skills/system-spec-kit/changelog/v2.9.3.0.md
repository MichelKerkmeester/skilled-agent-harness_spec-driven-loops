# v2.9.3.0, Tighter v2.3 Gates and a Card That Says One Thing

A deep review of the weak-model authoring work found gaps.

- Some new gates let a defect through.
- The card or the templates told a model two different things.
- This release closes those gaps.

Every gate change applies only to docs stamped v2.3.

- So a packet written on older templates gets the same verdict. It got that verdict before.
- The three placeholder checkers share one marker scan.
- The card gives one answer per question.

The release also stops the trigger index build from waiting on git.

- Its corpus walker now skips the monitor. The validator's git calls already do.
- The release brings the catalog, playbook and reference docs in line. They now match what the code does.

&nbsp;

## Why This Release

The previous release taught a weak model to fill templates. It gated the leftovers.

- The review showed the gate and guidance still disagreed. The disagreements were small.
- A token could hide where one checker looked. The other checker would miss it.
- A required section could go missing without an error.
- The card gave three answers to the same question.
- A model that follows instructions literally fails on exactly these gaps.

## Validation Gates

Each fix below reads the v2.3 template stamp first. So v2.2 docs keep their verdicts.

#### Missing Required Sections Fail <a id="c-missing-required-sections-fail"></a>

- `ANCHORS_VALID` now reports each section anchor a v2.3 doc lacks. It does so when its template requires it.
- Before, strict validation passed a packet. The packet had deleted a required `tasks.md` section.
- A benchmark run showed a model will do that.
- The registry entry for the rule describes the new error.

#### One Marker Scan for Every Checker <a id="c-one-marker-scan-for-every-checker"></a>

- The validator, the shell rule and the standalone `check-placeholders.sh` scan now align. They apply the same rules.
- Those rules cover code spans, fenced blocks and titles.
- Before, a token on a mixed line could pass one checker. It could fail another.
- The same went for a token inside an indented fence. It also went for one in angle brackets.
- The standalone scan could report zero placeholders. That was in a folder full of tokens.

#### Every Status Row Counts <a id="c-every-status-row-counts"></a>

- A v2.3 `spec.md` with a Draft row now reads as complete. It does so when a Complete row follows.
- Before, only the first Status row decided.
- So a later row was invisible to the token gate.

#### Template Titles Are Caught <a id="c-template-titles-are-caught"></a>

- A v2.3 `spec.md` whose title still reads `[template: ...]` now fails `SCAFFOLD_NEVER_TOUCHED`.
- That check used to miss it.

#### Long Descriptions End at a Clause <a id="c-long-descriptions-end-at-a-clause"></a>

- A generated description that is too long now ends at the last comma. It also ends at a semicolon or colon.
- That cut falls in the second half of the limit. It does not fall mid-phrase at a word.
- Only specs stamped v2.3 or later get the new cut.
- So stored descriptions on older specs stay in sync.

#### Tracks Stay Inside `specs/` <a id="c-tracks-stay-inside-specs"></a>

- `create.sh` now refuses a `--track` value that is absolute.
- It also refuses one that holds `.`, `..` or an empty segment.
- It does this before it creates any folder.
- A track that is a deliberate symlink still works.
- That is because the value is checked as written and never resolved.

## Authoring Guidance

#### The Card Stops Contradicting Itself <a id="c-the-card-stops-contradicting-itself"></a>

- A plan longer than four steps now has one answer.
- Stop and ask, as the card's last section says.
- The task check counts open and done tasks alike.
- The token check covers every packet doc.
- The card names the `graph-metadata.json` write that `create.sh` makes.
- It also says when to open the long guide.
- It hands continuity and metadata refresh to the authoring checklist.

#### Templates and Examples Teach the Task Format <a id="c-templates-and-examples-teach-the-task-format"></a>

- The `tasks.md` template's description and its sample tasks now carry the `Verify:` clause. The format requires it.
- Every task line in the four level examples ends with one.
- The links note in `spec.md` gained the good and weak examples. So did the checklist note in `tasks.md`.
- The other notes already had those examples.
- `template-mapping.md` now teaches the value-token form.
- It describes `decision-record.md` as created on request.

#### Commands and the Doc Agent Name the Card <a id="c-commands-and-the-doc-agent-name-the-card"></a>

- The `/speckit:plan` and `/speckit:implement` entry points name the authoring card. They also name the token rule.
- Their prompt contracts name them too.
- The markdown agent's spec-doc row names the token rule. It also names the two guards.
- The retired `/spec_kit:` prefix is gone from the template and reference docs.
- Those docs still used it.

## Guards and Speed

#### Guards Fail Loudly and Completely <a id="c-guards-fail-loudly-and-completely"></a>

- `check-example-drift.sh` and `check-card-sync.sh` exit with a message when `rg` is missing.
- The drift guard used to print OK on a drifted tree.
- The drift guard also fails on reordered anchors.
- It fails on a level with no example too.
- The card guard runs every check before it fails.
- It requires the checklist's example route and reads every mode's leaves.

#### The Index Build Skips Git's Monitor <a id="c-the-index-build-skips-gits-monitor"></a>

- The trigger-index corpus walker now turns git's file-system monitor off. It does so for its one git listing.
- So a slow or stuck monitor no longer stalls the index build.
- The source-tag scanner is unchanged here.
- This release carries the v2.9.1.0 scanner fix as it shipped.
- It adds nothing to it.

&nbsp;

## Docs Brought in Line

The catalog leaves, playbook scenarios and reference pages now describe behavior. That behavior is what ships.

#### Docs Describe the Shipped Behavior <a id="c-docs-describe-the-shipped-behavior"></a>

- They cover the gates, the guards, the source-tag rule and `create.sh --track`.
- So do the validation rules reference. The level, folder-structure and template guides do too.
- That includes `acceptance-criteria.md` listed as required at Levels 2 and 3.
- It includes the checklist described as a `tasks.md` section.
- It includes the stale size labels removed from the level specifications.

&nbsp;

## Upgrade Notes

No migration required. Packets stamped v2.2 keep their verdicts.

- A v2.3 packet that deleted a required section now fails strict validation.
- So will one that kept a template title.
- So will one that left a token the shell rule missed.
- Restore the section or fill the value.
