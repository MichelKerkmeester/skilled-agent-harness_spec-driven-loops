# v2.9.3.0, Tighter v2.3 Gates and a Card That Says One Thing

A deep review of the weak-model authoring work found gaps. Some new gates let a defect through. The card or the templates told a model two different things. This release closes those gaps. Every gate change applies only to docs stamped v2.3. So a packet written on older templates gets the same verdict it got before.

The release also stops the trigger index build from waiting on git. It brings the catalog, playbook and reference docs in line with what the code now does.

&nbsp;

## Why This Release

The previous release taught a weak model to fill templates. It gated the leftovers. The review showed the gate and the guidance still disagreed in small ways. A token could hide where one checker looked and the other did not. A required section could go missing without an error. The card gave three answers to the same question. A model that follows instructions literally fails on exactly these gaps.

&nbsp;

## What's New at a Glance

- **Strict validation now names a missing required section.** A v2.3 doc that drops a section its template requires fails with the section's name.
- **The three placeholder checkers agree.** They share one marker scan, so a token cannot pass one and fail another.
- **A scaffold cannot escape `specs/`.** `create.sh --track` refuses a track that would write outside it.
- **The card gives one answer per question.** Long plans, task checks and token counts each have a single rule.
- **Example tasks show the format they teach.** Every example task line ends with a `Verify:` clause.
- **The guards fail loudly.** Both guards stop when `rg` is missing. They report every problem they find.
- **The trigger index build stops waiting on git's file monitor.** Its corpus walker now skips the monitor, as the validator's git calls already do.
- **The docs match the code.** Catalog, playbook and reference pages describe the behavior this release ships.

&nbsp;

## Validation Gates

Each fix below reads the v2.3 template stamp first. So v2.2 docs keep their verdicts.

#### Missing Required Sections Fail

`ANCHORS_VALID` now reports each section anchor a v2.3 doc lacks when its template requires it. Before, strict validation passed a packet that had deleted a required `tasks.md` section. A benchmark run showed a model will do that. The registry entry for the rule describes the new error.

#### One Marker Scan for Every Checker

The validator, the shell rule and the standalone `check-placeholders.sh` scan now apply the same rules. Those rules cover code spans, fenced blocks and titles. Before, a token on a mixed line could pass one of them and fail another. The same went for a token inside an indented fence or in angle brackets. The standalone scan could report zero placeholders in a folder full of tokens.

#### Every Status Row Counts

A v2.3 `spec.md` with a Draft row followed by a Complete row now reads as complete. Before, only the first Status row decided. So a later row was invisible to the token gate.

#### Template Titles Are Caught

A v2.3 `spec.md` whose title still reads `[template: ...]` now fails `SCAFFOLD_NEVER_TOUCHED`. That check used to miss it.

#### Long Descriptions End at a Clause

A generated description that is too long now ends at the last comma, semicolon or colon. That cut falls in the second half of the limit, not mid-phrase at a word. Only specs stamped v2.3 or later get the new cut. So stored descriptions on older specs stay in sync.

#### Tracks Stay Inside `specs/`

`create.sh` now refuses a `--track` value that is absolute. It also refuses one that holds `.`, `..` or an empty segment. It does this before it creates any folder. A track that is a deliberate symlink still works. That is because the value is checked as written and never resolved.

## Authoring Guidance

#### The Card Stops Contradicting Itself

A plan longer than four steps now has one answer. Stop and ask, as the card's last section says. The task check counts open and done tasks alike. The token check covers every packet doc. The card names the `graph-metadata.json` write that `create.sh` makes. It also says when to open the long guide. It hands continuity and metadata refresh to the authoring checklist.

#### Templates and Examples Teach the Task Format

The `tasks.md` template's description and its sample tasks now carry the `Verify:` clause the format requires. Every task line in the four level examples ends with one. The links note in `spec.md` and the checklist note in `tasks.md` gained the good and weak examples. The other notes already had those examples. `template-mapping.md` now teaches the value-token form. It describes `decision-record.md` as created on request.

#### Commands and the Doc Agent Name the Card

The `/speckit:plan` and `/speckit:implement` entry points name the authoring card and the token rule. Their prompt contracts name them too. The markdown agent's spec-doc row names the token rule and the two guards. The retired `/spec_kit:` prefix is gone from the template and reference docs. Those docs still used it.

&nbsp;

## Guards and Speed

#### Guards Fail Loudly and Completely

`check-example-drift.sh` and `check-card-sync.sh` exit with a message when `rg` is missing. The drift guard used to print OK on a drifted tree. The drift guard also fails on reordered anchors. It fails on a level with no example too. The card guard runs every check before it fails. It requires the checklist's example route and reads every mode's leaves.

#### The Index Build Skips Git's Monitor

The trigger-index corpus walker now turns git's file-system monitor off for its one git listing. So a slow or stuck monitor no longer stalls the index build. The source-tag scanner is unchanged here. This release carries the v2.9.1.0 scanner fix as it shipped. It adds nothing to it.

&nbsp;

## Docs Brought in Line

The catalog leaves, playbook scenarios and reference pages now describe the shipped behavior. They cover the gates, the guards, the source-tag rule and `create.sh --track`. So do the validation rules reference and the level, folder-structure and template guides. That includes `acceptance-criteria.md` listed as required at Levels 2 and 3. It includes the checklist described as a `tasks.md` section. It includes the stale size labels removed from the level specifications.

&nbsp;

## Upgrade Notes

No migration required. Packets stamped v2.2 keep their verdicts. A v2.3 packet that deleted a required section will now fail strict validation. So will one that kept a template title. So will one that left a token the shell rule missed. Restore the section or fill the value.
