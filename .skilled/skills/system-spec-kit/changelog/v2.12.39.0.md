# v2.12.39.0, a repeated track-root entry is drift

A packet named twice in a track root's `children_ids` now counts as drift.

> Spec folder: `specs/system-speckit/044-named-subtracks-and-host-repos/007-children-list-duplicates`

&nbsp;

## What's New at a Glance

- **Repeats are reported.** `track-roots.mjs` compared the list and the folders as sets, so a list naming one packet twice still matched. `sweep-track-roots.mjs` now prints `declared more than once: <names>` for that root and exits 1, and the pre-push track-root gate blocks it.
- **The writer removes them.** `refresh-track-roots.mjs` names each repeat in its dry run as `drop duplicate <names>`, and `--apply` writes each packet once. A list that is only unsorted still matches.
- **The specs root lists nothing stale.** Skilled's own `specs/graph-metadata.json` no longer names two deleted sandbox packets, which a host that mirrors Skilled's specs under its own `specs/` saw as drift.

&nbsp;

## Upgrade

Run `node .skilled/skills/system-spec-kit/runtime/cli/spec/refresh-track-roots.mjs --apply` once if the sweep prints `declared more than once` for a track root. A push is blocked until the repeat is gone.
