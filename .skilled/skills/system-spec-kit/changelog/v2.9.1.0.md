# v2.9.1.0, The Validator No Longer Hangs on a Stuck Git Monitor

`validate.sh` could sit at 0% CPU with no error. It could do that in a checkout whose git file-system monitor had stopped answering. Each git call it made waited on that monitor. Every git call the validator makes now turns the monitor off. That costs a plain index scan. It returns the same output.

&nbsp;

## What's New at a Glance

- **Every rule that asks git is covered.** The acceptance-criteria coverage rule skips the monitor. So do the spec-doc integrity and source-tag rules. The continuity freshness check skips it too.
- **The source-tag rule's shared scan is covered too.** It reuses sk-doc's citation scan. That scan skips the monitor in the same release.
