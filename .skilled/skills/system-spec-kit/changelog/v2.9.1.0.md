# v2.9.1.0, The Validator No Longer Hangs on a Stuck Git Monitor

`validate.sh` could sit at 0% CPU with no error in a checkout whose git file-system monitor had stopped answering, because each git call it made waited on that monitor. Every git call the validator makes now turns the monitor off, which costs a plain index scan and returns the same output.

> Spec folder: `specs/hooks/023-session-relaunch-loop/035-known-gap-fixes` (Level 2)

&nbsp;

## What's New at a Glance

- **Every rule that asks git is covered.** The acceptance-criteria coverage, spec-doc integrity and source-tag rules skip the monitor, and so does the continuity freshness check.
- **The source-tag rule's shared scan is covered too.** It reuses sk-doc's citation scan, which skips the monitor in the same release.
