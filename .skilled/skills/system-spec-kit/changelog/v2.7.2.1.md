# v2.7.2.1, A Test Pins the Late Hook Payload

The hooks whose host allows only 3 seconds stop reading stdin after 500 ms. A host that writes the payload later loses it, and the hook answers as if stdin were empty. That was recorded as a known limitation with no test behind it. The suite now pins it, so a change to the deadline or to the empty-payload answer shows up as a failing test instead of a silent difference on a slow host.

> Spec folder: `specs/sk-code/011-sk-code-poinytail-based-refinement/013-root-cause-and-ux-research/006-hook-late-write-test` (Level 1)

&nbsp;

## What's New at a Glance

- **A late-write case.** `runtime/hooks/lib/hook-stdin-deadline.test.mjs` spawns the Claude prompt-submit shim with stdin held open, writes the payload after 800 ms and checks that the shim exits on its own within the short-host bound and answers `{}`.
- **A write delay in the spawn helper.** `runHook` takes a `writeDelayMs` option, so a test can write a held-open payload after a delay. At 0 it behaves as before.
