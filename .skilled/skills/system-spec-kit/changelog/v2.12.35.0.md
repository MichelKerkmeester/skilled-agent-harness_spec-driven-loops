# v2.12.35.0, Saves Work Through a Linked Specs Folder

Some projects keep their packets in another repository. They link their own `specs` folder to it. In such a project, every save used to stop. So did every metadata refresh and backfill. The message was "Refusing to write graph metadata outside a configured specs root". They now write to the packet where it really lives.

&nbsp;

## What's New at a Glance

- **Saves land through the link.** The write check now follows a linked `specs` folder. It goes to where its packets really are. So a save run inside the project is accepted.
- **Refreshes keep the path you gave.** A metadata refresh checks the folder as you named it. It still writes the real file.
- **Stray destinations stay refused.** A packet outside every allowed folder still gets no metadata. That covers the project and the repository it links into.

&nbsp;

## Upgrade

No migration required. A project that worked around the refusal by saving from the other repository can now save from its own checkout.

&nbsp;
