# v2.12.35.0, Saves Work Through a Linked Specs Folder

Some projects keep their packets in another repository and link their own `specs` folder to it. Every save, metadata refresh and backfill in such a project used to stop with "Refusing to write graph metadata outside a configured specs root". They now write to the packet where it really lives.

> Spec folder: `specs/system-speckit/037-symlinked-runtime-root`

&nbsp;

## What's New at a Glance

- **Saves land through the link.** The write check now follows a linked `specs` folder to where its packets really are, so a save run inside the project is accepted.
- **Refreshes keep the path you gave.** A metadata refresh checks the folder as you named it and still writes the real file.
- **Stray destinations stay refused.** A packet outside every allowed folder of the project and of the repository it links into still gets no metadata.

&nbsp;

## Upgrade

No migration required. A project that worked around the refusal by saving from the other repository can now save from its own checkout.
