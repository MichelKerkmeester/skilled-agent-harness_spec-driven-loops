# v4.1.1.0, The Spec Kit Goal Settles on One Limit and One Command

The spec-kit goal now has one limit and one authoring path. A top-level or phase-parent goal passes the validator up to 4,000 characters and fails past it. The goal template carries no author instructions, and the phase workflows send goal authoring to `/create:goal`.

> Part of [Skilled v4.0.0.2](../../../changelog/skilled/v4.0.0.2.md), the release that makes goals leaner.

## What's New at a Glance

- **One limit for a parent goal.** The goal validator and `goal.md.tmpl` lost the 3,000-character warning tier. A top-level or phase-parent goal passes up to 4,000 characters and fails past it.
- **The limit covers the same folders everywhere.** The validator applies the limit to every top-level packet and every phase parent, nested or not, and exempts only a phase child that is not itself a phase parent. It draws the same line as the other goal tools.
- **One home for the send rule.** system-spec-kit's `SKILL.md` and five speckit workflows point to section 4 of the create-goal mode's `references/budget-and-handoff.md` for what a sent goal may carry, instead of restating the rule.
- **The goal template lost its author instructions.** The blockquote, the Operator copy section and the criteria introduction are gone from `goal.md.tmpl`, because that text went out with every sent goal. A `GOAL_AUTHORING` comment points to the create-goal mode instead.
- **Phase workflows name `/create:goal`.** The speckit `:with-phases` step, Option D in plan and complete, `phase-definitions.md`, `phase-system.md`, the quick reference and the `create.sh` help and next steps send goal authoring to `/create:goal`. A retrofit has one path, `/create:goal <packet path> retrofit`, and the validator's two goal findings name their fix in the create-goal mode.
- **Docs that match the runtime.** `create.sh --phase --with-goal` writes child goals only, and `--level phase-parent --with-goal` writes the parent goal. The docs now say so.

## Upgrade

Goals between 3,000 and 4,000 characters now pass the validator with no warning, and a goal past 4,000 still fails. To add a goal to a packet that has none, run `/create:goal <packet path> retrofit`.
