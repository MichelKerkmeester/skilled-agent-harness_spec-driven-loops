This release hardens the post-update MCP recovery guide by rewriting the Spec Kit Memory install guide to workflows-documentation standards and adding operator-ready recovery and verification guidance for update-related MCP failures. The instructions and release notes are easier for non-developers to follow. The workflow is easier to follow and trust.

> Spec folder: `.opencode/specs/system-spec-kit/z_archive/018-mcp-issues-after-update/`

## What's New at a Glance

- **The INSTALL GUIDE uses a structured format aligned with the install-guide template.** It has an AI-first flow, phased validation checkpoints and improved scannability.
- **The guide clarifies root-cause contributors.** It identifies `node_modules` relocation as a contributor but not the sole root cause. It also covers workspace install/build mismatch and native ABI mismatch.
- **The guide standardizes runtime database path guidance.** It names `mcp-server/dist/database/context-index.sqlite` as the main runtime database path and documents compatibility symlink behavior.
- **The guide adds a fast recovery sequence for post-update failures.** The sequence uses install, build and native checks.
- **The guide adds targeted error-signature procedures.** It addresses a reliability problem involving `@spec-kit/shared` module resolution failures, `ERR_DLOPEN_FAILED`/`NODE_MODULE_VERSION` and `sqlite-vec` degradation mode.
- **The guide adds operational health checks.** It gives concrete verification commands and expected outcomes for post-recovery validation.

## Upgrade

No migration required. Pull the latest version and follow the recovery flow in INSTALL GUIDE if you encounter post-update MCP startup issues.
