## Why This Release

The release focuses on fixing important problems and explaining results more clearly. The result is a workflow that is easier to follow and trust.

## What's New at a Glance

- **Upgrades fail fast on missing shared libraries.** `Upgrade level` exits immediately when the shared library cannot be sourced.
- **Failed upgrades roll back the spec folder.** The new `restore_from_backup()` function returns it to its pre-upgrade state.
- **Backups preserve nested memory folders.** Nested `memory/` directories are no longer silently skipped.
- **Generated upgrade output is clearer.** Comment lines no longer leak into generated output, and the `OPEN QUESTIONS` warning surfaces visibly during upgrades.
- **Upgrade matching is more precise.** Pattern checks avoid false positives and partial matches and `find_insert_point()` is capped at 200 iterations.
- **Run history and documentation are clearer.** The cross-lineage audit resolves contradictions, while Level 3+ documentation gains an evidence-cited checklist.

## Upgrade Reliability

#### Missing Libraries Stop Early

`Upgrade level` now exits immediately if the shared library cannot be sourced. This reduces confusing failures and makes the system more dependable.

&nbsp;

#### Failed Upgrades Restore the Spec Folder

Backup logic preserves nested directory structures under `memory/` instead of silently skipping them. When an upgrade fails, the new `restore_from_backup()` function restores the spec folder to its pre-upgrade state.

---

## Clearer Upgrade Output

#### Plans and Warnings Reach the Reader

`Upgrade_plan()` and `upgrade_checklist()` no longer inject stray comment lines into generated output. The `OPEN QUESTIONS` warning is now emitted to stderr so it surfaces visibly during upgrades.

---

## More Reliable Matching

#### Matching Avoids False Results

Multi-Agent detection is anchored to a table-row pattern to prevent false positives. The complexity flag exit pattern is tightened to avoid partial matches. The unused `SED_INPLACE_FLAG` variable is eliminated because it was no longer needed.

&nbsp;

#### Search Has a Clear Limit

`find_insert_point()` is capped at 200 iterations to prevent infinite loops. Level detection is anchored to the start of a line for reliable matching.

## Memory and Documentation

#### Memory and Guidance Gain Clarity

The 121 orphan memory cleanup deleted junk constitutional memory #1346 and regenerated it as #1361. The cross-lineage audit resolved contradictions across the 121-to-123-to-124 chain. Full Level 3+ documentation includes an evidence-cited checklist with complete traceability.
