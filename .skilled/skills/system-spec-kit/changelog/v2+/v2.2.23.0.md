This release revises HVR references and implementation-summary guidance across the templates. It also changes how writers open and organize summaries and adds guidance for verification, limitations and delivery stages.

> Spec folder: `.opencode/specs/system-spec-kit/z_archive/019-readme-and-summary-with-hvr/`

## Why This Release

The changes aim to make instructions and release notes easier for non-developers to follow, while making the workflow easier to follow and trust.

## What's New at a Glance

- **HVR references now point to `references/`.** The path update covers all 8 templates.
- **Implementation-summary guidance follows spec 136 patterns.** Decision-record guidance was updated as well.
- **Templates now guide openings and feature sections.** The new direction covers all levels and gives Level 3/3+ templates a per-feature structure.
- **Files Changed tables now depend on level.** Level 1-2 keeps its table while higher levels carry the summary in narrative.
- **The voice guide standardizes verification and limitations.** Level 3+ also gains delivery-stage guidance.

---

## Template Guidance

#### HVR References Point to Their New Location

HVR_REFERENCE comments and footer paths were updated after the HVR rules moved to `references/`. The stale HVR_REFERENCE path in the 137 implementation summary now points to the new `references/` location.

&nbsp;

#### Summary Templates Use Reference Patterns

Spec 136 reference patterns informed improvements to the core implementation-summary template and the other implementation-summary templates, including the Level 3+ version. Decision-record guidance was updated in both the general and Level 3+ decision records. Spec 136 was also added as a reference in voice guide comments.

&nbsp;

#### Openings Lead With Impact

Opening-hook guidance was added at all levels. Templates now guide writers to lead with impact in 2-4 sentences.

&nbsp;

#### Summary Tables Follow Levels

Level 3/3+ templates now use `### [Feature Name]` subsections for each feature instead of file tables. The Files Changed table was removed for Level 3/3+, where narrative carries the summary at higher documentation levels. Level 1-2 retains the table.

---

## Voice and Delivery Guidance

#### Verification Shows Failures

The voice guide now says: "Be honest. Show failures alongside passes." This gives writers direct guidance for reporting verification.

&nbsp;

#### Limitations and Delivery Stages

All levels now use `1. [Limitation] [Specific detail with workaround.]` for numbered limitations. Level 3+ guidance now covers delivery stages: testing, rollout and verification.
