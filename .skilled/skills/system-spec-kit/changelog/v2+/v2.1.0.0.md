This release corrects memory decay, adds token-budget information to handler responses and addresses reliability problems in memory-index behavior. It also aligns security handling across modules and updates MCP server guidance. The goal is to make the workflow easier to follow and easier to trust.

## Why This Release

The instructions and release notes were made easier for non-developers to follow.

## What's New at a Glance

- **Handlers now expose token budgets.** Every handler response includes the `TokenBudget` field in its metadata.
- **The FSRS memory-decay calculation was corrected.** Memories had been decaying about 4.5 times slower than the FSRS v4 standard.
- **Dead code and stray files were removed.** The vector index lost dead code and the project lost nine orphaned files, making it smaller and easier to maintain.
- **Security handling for `SafeParseJson` was aligned.** This applies across modules.
- **The test suite was repaired.** Reported test failures were resolved and integration test paths were corrected.
- **MCP server and memory-system documentation changed.** These changes make instructions easier for non-developers to follow.

---

## Memory and Response Behavior

#### Budget Signals Reach Responses

`Console.error` logging was updated for cases when token budgets were exceeded. Hint injection in responses was updated for cases when budget thresholds are hit.

&nbsp;

#### Memory Decay Uses the Corrected Formula

The factor changed from 19.0 to 19/81 (~0.2346). The formula changed from `R = (1 + t/(FACTOR*S))^(-0.5)` to `R = (1 + FACTOR*t/S)^(-0.5)`. The corrected result is `R(S,S) = 0.9` as specified.

## Index Reliability and Security

#### Safer Parsing and Index Calls

- **`SafeParseJson`.** Security alignment was applied across modules.
- **`ClearConstitutionalCache`.** In the vector index, it called the wrong internal method. The release corrected the bug.
- **Vector-index facade.** Three broken delegations were fixed.
- **Search weights.** Dead parameters and regex patterns were cleaned out.
- **Orphaned files.** Seven of them were `dist` `.js` files and two were orphan test files.
- **The orphan core was no longer needed.** It shadowed the `dist/core/` directory, and that shadowing issue was corrected.
