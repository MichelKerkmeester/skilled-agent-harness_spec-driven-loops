This release is a memory save path-resolution hotfix for `.opencode/specs` inputs. Generate context folder detection now resolves JSON SPEC_FOLDER values that include `.opencode/specs/...` directly instead of falling through to nested auto-detection.

## What's New at a Glance

- **JSON spec-folder values now normalize.** `detectSpecFolder()` recognizes absolute paths, `specs/...` and `.opencode/specs/...` in collected data.
- **Folder alignment uses the resolved path.** Folder-alignment checks now run against the resolved folder basename and parent directory. That prevents malformed join results.
- **Symlink duplicates no longer compete.** Existing specs directories are de-duplicated by realpath, so `specs` to `.opencode/specs` no longer appears as two competing roots.
- **Misrouted memory is recovered.** The session memory file was moved to the intended spec folder and re-indexed under `04--agent-orchestration/021-codex-orchestrate`.
- **Stale index entries are removed.** Wrong-folder memory rows created by fallback routing were deleted from the memory index.

## Upgrade

No migration required. Pull latest and use `/memory:save` with either `specs/...` or `.opencode/specs/...` folder forms.
