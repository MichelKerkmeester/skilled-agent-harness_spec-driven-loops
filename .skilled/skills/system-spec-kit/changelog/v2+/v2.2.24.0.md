This release completes the hybrid memory retrieval rollout and closes its verification. It documents every feature that shipped from spec 136: a typed retrieval trace, artifact-aware routing, adaptive fusion, a mutation ledger, telemetry, extraction and configuration hardening and the final closure of the deferred tests.

> Spec folder: `.opencode/specs/system-spec-kit/020-mcp-working-memory-hybrid-rag/`

## Why This Release

The release focuses on fixing important problems and explaining the results in clearer terms. The goal is to make the workflow easier to follow and easier to trust.

## What's New at a Glance

- **Every retrieval now returns a typed `ContextEnvelope`.** It carries a stage trace and retrieval metadata.
- **Retrieval strategy routes across 9 artifact classes.** Adaptive hybrid fusion adds intent-aware profiles.
- **Adaptive fusion can be compared in a dark run.** `SPECKIT_ADAPTIVE_FUSION` remains default-off.
- **Extended telemetry now covers `memory_search` and `memory_context`.** It captures latency, mode, fallback and quality-proxy dimensions.
- **An append-only mutation ledger records create, update, delete and reindex operations.** Its entries are immutable.
- **Extraction, provenance and configuration are hardened.** Cognitive config parsing now uses Zod validation.
- **Three deferred test suites now run as active suites.** They are `api key validation.vitest`, `api validation.vitest` and `lazy loading.vitest`.
- **Root and addendum docs are synchronized.** Spec 136's root docs and the `007-documentation-alignment` package now reflect current totals and closure evidence.
- **The staged rollout is complete.** Feature enablement moved through 10%, 50% and 100% gates.
- **Governance and outcome confirmation are complete.** Technical, data and product approval artifacts were produced.

## Hybrid Retrieval

#### Retrieval Shows Its Work

The envelope's stage trace covers candidate, filter, fusion, rerank and fallback. It also states the degraded-mode expected behavior.

&nbsp;

#### Weights Follow the Artifact and the Intent

Artifact-aware routing uses deterministic weight tables. The intent-aware fusion profiles support `fix_bug`, `add_feature`, `understand`, `refactor`, `security_audit`, `find_spec` and `find_decision`.

&nbsp;

#### A Safe Path to Adaptive Fusion

Dark-run comparison mode sets adaptive behavior against deterministic fusion without changing live retrieval output. The feature-flag safety model is retained for controlled rollout behavior, with `SPECKIT_EXTENDED_TELEMETRY` remaining default-on.

---

## Safer Memory Handling

#### Immutable Ledger Entries With Hash Chains

SQLite triggers enforce the immutability of each ledger entry. The entries carry hash-chain linkage.

&nbsp;

#### Predictable Extraction and Memory Eviction

Extraction now falls back to a deterministic `memory_id`, causal-seed selection is bounded and the main boost import path is normalized. Working-memory eviction now enforces deterministic LRU ordering.

## Tests and Documentation

Embedding-provider architecture drift is closed. Legacy `lib/interfaces/embedding-provider` references were removed from active test paths and aligned to the shared provider expected behaviors and factory.
