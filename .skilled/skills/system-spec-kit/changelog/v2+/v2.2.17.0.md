Spec 126 adds full spec-folder document indexing, and Spec 127 aligns all documentation with the post-126 state.

> Spec folder: `specs/system-spec-kit/127-spec126-documentation-alignment/`

## Why This Release

The documentation alignment focuses on making instructions and release notes easier for non-developers to follow. The goal is a workflow that is easier to follow and trust.

## What's New at a Glance

- **Schema v13 adds document metadata to the index.** It adds fields for document type and spec level.
- **The index recognizes 11 document types.** The recognized set spans specs, plans, memory and other documentation.
- **Document types receive different scoring multipliers.** The type determines how strongly a document contributes to scoring.
- **Search adds two intents.** Search can now target specifications and decisions.
- **A crawler finds spec-folder documents.** It searches `.opencode/specs/` for these documents.
- **Causal chains connect spec documents.** The links follow the spec-to-implementation path.
- **Scans can include spec-folder documents.** You can control whether a scan includes them.
- **Indexing adds a new document source.** It brings spec-folder documents into the content available for indexing.
- **The documentation aligns with the post-126 state.** Readers get instructions and release notes aligned with the post-126 changes.

## Spec Document Indexing

#### Simplify Index Maintenance

Schema v13 adds `Document_type TEXT DEFAULT 'memory'` and `spec_level INTEGER` columns to `memory_index`. This makes setup and maintenance easier to manage.

&nbsp;

#### Identify Document Types

The 11 document types are:

- `Spec`
- `plan`
- `tasks`
- `checklist`
- `decision_record`
- `implementation_summary`
- `research`
- `handover`
- `memory`
- `readme`
- `constitutional`

&nbsp;

#### Score by Document Type

The document-type scoring multipliers are:

- `spec`: 1.4x
- `plan`: 1.3x
- `constitutional`: 2.0x
- `memory`: 1.0x
- `readme`: 0.8x
- `scratch`: 0.6x

&nbsp;

#### Find Specs and Decisions

The new intents are `Find_spec` and `find_decision`. The total rises from 5 to 7.

&nbsp;

#### Crawl Spec Folders

`FindSpecDocuments()` is the crawler for spec-folder documents. It walks `.opencode/specs/` to find them.

&nbsp;

#### Connect Spec Records

`CreateSpecDocumentChain()` creates `spectoplantotaskstoimpl_summary` edges. The chain runs from spec to plan to tasks to `impl_summary`.

&nbsp;

#### Control Spec-Document Scans

The `SPECKIT_INDEX_SPEC_DOCS` environment variable controls spec-document indexing. The `memory_index_scan` tool accepts the `includeSpecDocs` parameter.

&nbsp;

#### Expand the Source Set

Spec-folder documents join memory, constitutional material, skill READMEs and project READMEs as an indexing source. They are the fifth source.
