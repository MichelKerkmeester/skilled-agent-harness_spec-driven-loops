This release corrects importance-tier classification in memory exports while making the instructions and release notes easier for non-developers to follow and the workflow easier to follow and trust.

## What's New at a Glance

- **The template now uses one importance tier field.** The context template replaces `importance_tier: "normal"` and `importanceTier: "{{IMPORTANCE_TIER}}"` with `importance_tier: "{{IMPORTANCE_TIER}}"`. After rendering, both fields persisted with different values, and frontmatter parsers read the fixed default first instead of the dynamically resolved value, such as `"critical"`, which caused incorrect classification.
- **The camelCase alias is removed from serialization.** `importanceTierAlias` was removed from the `ManagedFrontmatter` interface and its serialization path in `serializeFrontmatter()`.
- **Legacy dual-field values are resolved consistently.** The `resolveImportanceTierValue()` helper in `buildManagedFrontmatter()` handles existing memory files with both fields and prefers the non-`"normal"` value.

## Upgrade

No schema migration is required. Existing memory files with dual importance tier fields are resolved correctly on the next frontmatter backfill run.
