This release makes the legacy node index read as what it is: a supplemental navigation layer and not a replacement for SKILL. Wording that implied the opposite is fixed in the SKILL Graph Status header, the index and all 8 spec documents in 002-skill-graph-integration. The focus is instructions and release notes a non-developer can follow and a workflow that is easier to follow and easier to trust.

> Spec folder: `.opencode/specs/system-spec-kit/022-hybrid-rag-fusion/002-skill-graph-integration/`

## What's New at a Glance

- **The Graph Status header now frames the node index.** It calls the legacy node index a supplemental navigation layer, not a replacement for SKILL.
- **SKILL and the index carry explicit labels.** SKILL is explicitly labeled as the primary entrypoint for activation rules, routing and core behavior. The index is labeled as supplemental navigation, an optional deep-dive covering specific topics.
- **A navigation note was added to the index.** It reads: "This is a supplemental deep-dive index. SKILL remains the primary entrypoint".
- **One block carries corrected supplemental framing.** It replaces the old "running in graph mode" / "compatibility entrypoint" block.
- **~35 replacement-implying phrases were fixed across 8 spec documents.** The fixes span the spec, decision record, implementation summary, plan, tasks, checklist, handover and research in 002-skill-graph-integration.
- **Old wording that implied replacement is out.** Gone from the documents are "compatibility entrypoint", "during migration", "were monolithic" and "decomposed into".
- **New wording names the roles directly.** The documents now say "primary entrypoint", "supplemental node navigation" and "Graph Status header".

## Upgrade

No migration required. Language-only changes with no behavioral impact.
