This release expands the memory system to index project READMEs alongside spec files, constitutional files and skill READMEs. It also adds anchor prefix matching, simplifies the context template's anchor IDs and fixes resume detection.

It focuses on making the instructions and release notes easier for non-developers to follow.

## Why This Release

The goal is a workflow that is easier to follow and easier to trust. The anchor and resume detection fixes reduce confusing failures and make the system more dependable.

## What's New at a Glance

- **Project READMEs are a fourth memory source.** `findProjectReadmes()` discovers them, and the `IncludeReadmes` parameter controls README scanning.
- **READMEs gain anchors and can carry YAML frontmatter.** 74 READMEs across the project are anchored.
- **Symlinked READMEs are discovered.** `FindSkillReadmes()` now handles them.
- **Anchor lookups fall back to prefix matching.** A short anchor name now finds the composite IDs that start with it.
- **The context template uses short anchor IDs.** All 24 drop their `{{SESSION_ID}}-{{SPEC_FOLDER}}` suffixes.
- **Resume detection bugs are fixed.** They traced back to five root causes.
- **Docs catch up with four-source indexing.** `readme_indexing.md` is a comprehensive reference for the README indexing pipeline.
- **Documentation mismatches are fixed.** One README had 17 parameter documentation mismatches, and the troubleshooting doc's version moves from v1.7.1 to v1.7.2.

## README Indexing

#### Project READMEs Join the Index

Until this release the memory system indexed only three sources. `findProjectReadmes()` is a new discovery function for project-level README files, and it gives them an importance weight of 0.4. The `IncludeReadmes` parameter belongs to `memory_index_scan` and defaults to true.

Importance weights are tiered across user work, project READMEs and skill READMEs. The scoring formula applies them as `score *= (0.5 + importance_weight)`.

&nbsp;

#### Anchors and Frontmatter for READMEs

Those 74 READMEs carry about 473 anchor tags under the README anchor schema. The YAML frontmatter a README can include holds `title`, `description`, `trigger_phrases` and `importance_tier`.

&nbsp;

#### Symlinked READMEs No Longer Missed

`FindSkillReadmes()` used to miss symlinked READMEs. An `isSymbolicLink()` check closes that gap. An audit counted 96 READMEs on disk and 93 to 94 indexed, with 100% coverage after the symlink fix.

## Anchors

#### Short Anchor Names Find Composite IDs

A lookup with anchors set to `['summary']` used to return empty when the keys were composite IDs such as `summary-session-...`. An exact match now takes priority, with the shortest prefix as the fallback. Anchor filtering in search results supports prefix matching with hyphen-boundary enforcement.

&nbsp;

#### Clean Anchor IDs in the Context Template

The template-generated IDs ran 80 to 120 characters with underscores and violated `VALID_ANCHOR_PATTERN`. With those suffixes gone, each ID is a clean semantic name.

&nbsp;

#### No Parsing Bug in Check-Anchors

The check-anchors awk was incorrectly reported as having a `/` parsing bug. The B5 audit confirmed that no bug exists.

---

## Resume Detection

#### Five Root Causes Resolved

Two causes sat in the glob patterns: a wrong base path and insufficient glob depth. Two more sat in the tiers: tier 2 used the wrong semantic query and tier 3 used a trigger that was too generic. The fifth was tier skipping.

#### New and Updated Documentation

A new README documents the directory structure. The memory system doc now says "four sources" where it said "three sources". The save workflow doc adds project READMEs to its indexed content documentation. `SKILL.md` expands its README Content Discovery section with `findProjectReadmes()` and the weight tiers.

&nbsp;

#### Documentation Mismatches Corrected

Among the README parameter fixes, three phantom parameters are removed and 14 undocumented ones are added. The troubleshooting doc also documents the dual decay model (FSRS day-based plus turn-based). A README anchor name mismatch is corrected from `structure` to `architecture`.
