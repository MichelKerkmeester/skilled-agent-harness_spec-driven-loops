This release adds 3 new response fields to `memory_stats()` so the `/memory:manage` stats dashboard can report tier counts, database size and the last indexed time without raw `sqlite3` CLI queries. It focuses on making the instructions and release notes easier for non-developers to follow. The goal is a workflow that is easier to follow and easier to trust.

## What's New at a Glance

- **`memory_stats()` returns a tier breakdown.** The new `tierBreakdown` field carries per-tier memory counts such as `{ "constitutional": 5, "working": 12, "normal": 89 }`. Callers no longer run `SELECT importance_tier, COUNT(*) ... GROUP BY` through the shell.
- **The stats dashboard can report database size.** `memory_stats()` now returns `databaseSizeBytes` via `fs.statSync()` on the SQLite file. Callers no longer need `ls -la` or `wc -c` to report database size.
- **The last indexed time is part of the stats.** `memory_stats()` now returns `lastIndexedAt` with `MAX(updated_at)` from `memory_index`, replacing the raw `sqlite3` `SELECT MAX(updated_at)` fallback and a reliability problem around the timestamp.
- **The MCP README warns about zsh glob negation.** Its diagnostic commands section advises `<>` over `!=` to avoid glob negation errors.

## Upgrade

No migration required. Restart any running MCP server processes to pick up the new `memory_stats()` fields. The 3 new fields (`tierBreakdown`, `databaseSizeBytes`, `lastIndexedAt`) are additive and backward-compatible.
