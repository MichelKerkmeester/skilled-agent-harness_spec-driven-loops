This release finalizes canonical frontmatter normalization and an idempotent reindex workflow for templates, spec and memory markdown. It makes instructions and release notes easier for non-developers to follow and the workflow easier to follow and trust.

> Spec folder: `.opencode/specs/system-spec-kit/022-hybrid-rag-fusion/004-frontmatter-indexing/`

## What's New at a Glance

- **Normalization and composition follow a deterministic schema.** The rule applies to the targeted markdown classes.
- **The migration runs in apply or dry-run mode.** Both modes showed stable behavior on a second run.
- **Archived invalid-anchor warnings remain non-blocking.** They were documented and intentionally not remediated in this scope. Performance and formal governance controls remain tracked in the checklist.

## Upgrade

For new corpus updates, run the migration in dry-run mode before applying it, then rerun reindex. Keep the order as normalize, verify, rebuild to preserve deterministic outcomes. No database schema migration is required.
