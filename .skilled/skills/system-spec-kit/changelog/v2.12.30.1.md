# v2.12.30.1, Decision Routing Stops Taking Other Skills' Requests

A follow-up to v2.12.30.0 added "decision capture" and "chat candidate" to the DECISION routing intent. Any request that named the feature then went to spec-kit, even one that asked to research it, dispatch it to a CLI or build a component for it. Both phrases are replaced with four narrower ones: "decision capture queue", "decision capture folder", "decision capture state" and "this chat candidate".

> Spec folders: `specs/system-speckit/043-decision-capture/008-project-scoped-state`, `009-chat-answer-evidence` and `010-decision-routing-vocabulary` (Level 2)

&nbsp;

## What's New at a Glance

- **Other skills get their requests back.** "Dispatch this decision capture work to the Claude Code CLI" routes to the CLI skill again, and "Research how other tools handle decision capture" and "Add a chat candidate list component" no longer route to spec-kit.
- **Requests about the feature's own objects still reach spec-kit.** "Which folder holds the decision capture state for this project?", "Clear the answers left in the shared decision capture folder" and "Why did the save skip this chat candidate?" route to spec-kit through the new phrases, and "Record this as a decision" through the original four. Show and list questions about the queue reach spec-kit through system-skill-advisor v0.18.1.0.
- **The hook core and the save agree on the project folder.** Both now ask git for the project root with the file-system monitor turned off. Before, only the save did, so a stalled monitor could send the hook to a different answer folder than the one the save reads.
- **The off switch is documented.** `SYSTEM_DECISION_CAPTURE_DISABLED` is now in `.env.example`, `hook-flags.env.example` and the runtime env reference. It was already read by every capture hook and plugin but listed in none of them.
- **Playbook checks catch a failed folder lookup.** The live-conversation and sibling re-proof playbooks now require the answer folder to be an absolute path, so a lookup that prints `undefined` stops the check. The transcript-sweeps scenario lists the chat-candidate evidence rows in its pass criteria.
- **Tests cover the older answer folder.** A session-stop test seeds answers in the shared root folder that saves used before folders were per project, and the nudge counts them. The test that seeds the project folder fails when its temp folder sits inside a git checkout, which would otherwise point it at that checkout's live answers.
