# v2.7.1.0, Hooks Stop Waiting on an Open Stdin

Spec-kit's hooks used to read stdin until the stream closed, so a host that never closed it held the hook until its own timeout killed it. Every hook except `claude/user-prompt-submit.ts`, which still waits and is left for a follow-up, now stops after 3000 ms and takes the same exit it takes on an empty payload.

> Spec folder: `specs/sk-code/011-sk-code-poinytail-based-refinement/010-round-three-remediation/007-spec-kit-hook-deadlines` (Level 1)

## What's New at a Glance

- **One deadline for the plain hooks.** `runtime/hooks/lib/hook-adapter-shared.mjs` now settles when stdin ends or after 3000 ms, and every `.mjs` and `.cjs` hook reads through it.
- **The same deadline for the compiled hooks.** The new `runtime/hooks/shared-stdin.ts` serves the Claude, Codex, Cursor and Devin lifecycle adapters and keeps their 1 MB payload cap.
- **A test that leaves stdin open.** `runtime/hooks/lib/hook-stdin-deadline.test.mjs` spawns every hook entry with stdin held open and checks that each one exits on its own with its usual empty-payload result.

## Upgrade

Rebuild the runtime with `npm run build` in `.skilled/skills/system-spec-kit/runtime`, so the compiled hooks in `dist/` pick up the deadline.
