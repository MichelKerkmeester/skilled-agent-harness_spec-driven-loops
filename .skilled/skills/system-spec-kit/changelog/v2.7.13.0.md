# v2.7.13.0, Typo-Proof Script Options

Many spec-kit scripts read the options they expected and ignored the rest, so a misspelled flag ran the default mode and reported success. Each one now names the unknown option and exits with its usage error code. A few checks also printed a problem and still exited 0, which let a caller treat the failure as a pass.

> Spec folder: `specs/sk-code/011-sk-code-poinytail-based-refinement/021-open-ends-remediation/001-typo-proof-parsers` (Level 1)

&nbsp;

## What's New at a Glance

- **A mistyped option fails loudly.** `generate-context`, `generate-description`, the validation audits, the smart router tools, the process sweep tools, `is-phase-parent`, `repo-era`, `template-phrase-lint`, `strict-pass-freshness`, `check-markdown-links`, the command router generator and the rule helpers refuse an option they do not know.
- **Found problems now fail the run.** `check-native-modules.sh` exits 1 when a module fails to load, `dist-freshness` exits 1 when it reports an error and the frontmatter values helper exits 2 when it cannot read the document.
- **`create.sh --help` lists `--path`.** The option worked but was missing from the help text.
- **`validate-command-tree-parity.sh` needs `--left` and `--right` together.** Passing only one now exits 64.

&nbsp;

## Upgrade

Replace any misspelled option with the one the script's usage line lists.
