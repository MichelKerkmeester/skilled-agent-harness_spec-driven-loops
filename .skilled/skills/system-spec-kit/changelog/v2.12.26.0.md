# A Doctor Command That Answers Which Doctor Command

The family reached thirteen commands. The only way to pick one was to read the route manifest. `/doctor:helper` reads that manifest for you. Describe the problem in your own words. It names the commands that fit, best first. Every line shows the mutation class and the wording that matched.

&nbsp;

## What's New at a Glance

- **One entry point for thirteen commands.** `/doctor:helper` ranks the doctor routes against a described problem. It also ranks standalone commands, standalone actions and MCP sub-actions. It reads `_routes.yaml` at run time. So a new doctor command appears in it. No edit to the command itself is needed.
- **The reason on every line is evidence.** Each candidate quotes the manifest phrase that best matched. It also quotes the terms it matched in that phrase. So a wrong pick can be read, not guessed at.
- **A read-only pick runs, a writing pick is handed back.** A read-only candidate runs in place. It runs under that command's own router and presentation. A candidate classed `add-only` or `mutates` is printed as one line for you to run. So its plan and its own approval stay under its own gate. The helper never appends an argument to a line it prints.
- **Nothing matches, and it says so.** With no candidate above the floor, it closes on `STATUS=NO_MATCH FALLBACK=/doctor:setup`. That is the read-only command that lists the family.
- **Its accuracy is pinned, not asserted.** A held-out set is frozen in the tests with a sha256. It holds forty-eight described problems and twelve unrelated ones. The suite prints its top-1, top-3 and negative figures on every run.
- **A new doctor command can no longer be unreachable.** A contract suite fails the build when a router file has no manifest route. It also fails when the file has no phrase. It fails when the file has no `/doctor:setup` row. It fails when the helper has no matching entry.
- **The manifest gained twelve phrases.** The ranking exposed a gap. It is fixed by adding the wording operators actually use. That also reaches the advisor. Each added phrase is checked by the reach probe. Three of the twelve came from ten fresh probes against the shipped command. Those probes fixed the two that missed. They also fixed the one that picked a writing route on a shared word.
- **The command contract now lists `setup.md` and `helper.md`.** The doctor family's `router_path` had never carried `setup.md`. The router generator now checks both.
- **Two manual scenarios cover it.** One ranks a problem and runs a read-only pick. The other hands a writing pick back and exercises the fallback.
