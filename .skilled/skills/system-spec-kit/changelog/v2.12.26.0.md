# A Doctor Command That Answers Which Doctor Command

The family reached thirteen commands, and the only way to pick one was to read the route manifest. `/doctor:helper` reads that manifest for you: describe the problem in your own words, and it names the commands that fit, best first, with the mutation class and the wording that matched on every line.

&nbsp;

## What's New at a Glance

- **One entry point for thirteen commands.** `/doctor:helper` ranks the doctor routes, standalone commands, standalone actions and MCP sub-actions against a described problem. It reads `_routes.yaml` at run time, so a new doctor command appears in it with no edit to the command itself.
- **The reason on every line is evidence.** Each candidate quotes the manifest phrase that best matched and the terms it matched in that phrase, so a wrong pick can be read rather than guessed at.
- **A read-only pick runs, a writing pick is handed back.** A read-only candidate runs in place under that command's own router and presentation. A candidate classed `add-only` or `mutates` is printed as one line for you to run, so its plan and its own approval stay under its own gate. The helper never appends an argument to a line it prints.
- **Nothing matches, and it says so.** No candidate above the floor closes on `STATUS=NO_MATCH FALLBACK=/doctor:setup`, the read-only command that lists the family.
- **Its accuracy is pinned, not asserted.** A held-out set of forty-eight described problems and twelve unrelated ones is frozen in the tests with a sha256, and the suite prints its top-1, top-3 and negative figures on every run.
- **A new doctor command can no longer be unreachable.** A contract suite fails the build when a router file has no manifest route, no phrase, no `/doctor:setup` row, or no matching entry in the helper.
- **The manifest gained nine phrases.** A gap the ranking exposed is fixed by adding the wording operators actually use, which also reaches the advisor, and each added phrase is checked by the reach probe.
- **The command contract now lists `setup.md` and `helper.md`.** The doctor family's `router_path` had never carried `setup.md`, and the router generator now checks both.
- **Two manual scenarios cover it.** DOC-393 ranks a problem and runs a read-only pick; DOC-394 hands a writing pick back and exercises the fallback.
