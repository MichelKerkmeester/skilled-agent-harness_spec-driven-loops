# v2.12.10.0, The Runtime Lint Check Passes Again

The runtime's `npm run check` failed before it reached the type check. Its lint configuration accepted an underscore-named unused binding only in TypeScript files, while the linter also reads the hooks and scripts written in plain JavaScript. Fixing that rule cleared most of the errors. The rest were real: unused imports and helpers, loose `any` types in the CLI tests and two `require()` calls in ESM test files. Each was fixed where it sits, and no rule was switched off.

> Spec folder: `specs/system-speckit/053-ci-workflow-efficiency/012-alignment-fixes` (Level 2)

&nbsp;

## What's New at a Glance

- **The check runs to the end.** `npm run check` in the runtime now exits 0, so the type check behind the lint step runs too.
- **The underscore convention holds in every file type.** A binding named `_` or `_reason` reads as deliberately unused in `.js`, `.cjs` and `.mjs` files as it already did in TypeScript.
- **The CLI package is held to the same lint rules.** Its dead imports and helpers are gone, and its tests describe the shapes they assert on with real types instead of `any`.
- **The spec gate states why it reads the process environment.** Its kill-switch helper took an environment it never used. It now takes none, and a comment records that passing one would skip the saved hook-flags file.

## Upgrade

No action is needed. No hook or CLI command changed behaviour.
