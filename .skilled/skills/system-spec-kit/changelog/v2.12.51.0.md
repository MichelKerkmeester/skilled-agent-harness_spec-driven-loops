# v2.12.51.0, A Waiting Save Gets Its Turn

A process with several saves queued kept the workflow lock for its whole queue. A save in another process could wait 30 seconds.

&nbsp;

## What's New at a Glance

- **A waiting save gets its turn.** A process took the workflow lock again 1 to 6 ms after it released it. In a traced run one process held it for 26 seconds. A process now pauses 100 ms before it takes back a lock it just released.
- **Waiters poll every 25 ms.** A waiter used to back off for up to 4 seconds. That was longer than any free window. The longest traced wait fell from 26.2 to 6.4 seconds.
- **The staleness checker runs on Bash 4 and later.** It read an array length with a default. It counted with bare arithmetic commands. Both end the script on a Linux runner. It printed nothing there.
- **Three CLI tests pass on the runner.** The hook registration test expects 116 bindings. The host-root upgrade test leaves the workflow lock out of its copy.

&nbsp;

## Upgrade

No migration required. Two saves in a row in one process each wait up to 100 ms more.
