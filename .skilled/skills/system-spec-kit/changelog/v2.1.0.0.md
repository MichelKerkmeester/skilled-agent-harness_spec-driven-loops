# v2.1.0.0, The Spec Kit Adopts Your History: One Command, One Question

This release starts with the work you already have. Spec folders from v1.x fail strict validation almost without exception. Until now every workflow stopped at that failure. A new command repairs them in one pass. No language model is involved. It fills what a document lacks. It does not rewrite a word you wrote.

The tools that create, move and archive spec folders now keep them consistent. Track roots list what they hold. Archives keep packets with their family. New packets land in the canonical root. Saves write only the fields they carry.

The gate that binds a session to a spec folder grew quieter at the same time. The question arrives once, at your first real file change. It comes through whatever channel the runtime has. It reaches every repository. It no longer exempts the ones that live in scratch space.

One false alarm went quiet in the same pass. The completion sentinel no longer reads a cited document as a missing packet.

> Shipped in [Skilled v4.0.0.1](../../../changelog/skilled/v4.0.0.1.md), the hardening release that brought old spec folders forward.

## Why This Release

A rebuild as large as v2.0.0.0 moves so much. So its own history becomes the fastest way to find the seams. Everything in this part of the release was measured against real packets, real sessions and real dispatches. It was not measured against a demo.

This release also carries the one thing a person upgrading from v1.x needs most. Old spec folders should cost one command to adopt. They should not cost a repair project paid for in AI time. This release ships that command. It also ships the validator change that keeps old findings from blocking new work.

## What's New at a Glance

- **Old spec folders upgrade in one command.** A tool with no language model fills what v1 documents lack. It records the findings it cannot clear. So strict validation passes and old debt stops blocking new work.
- **Track roots list the packets they hold.** A writer keeps every list true to disk. A push that would publish a lie stops at the hook.
- **Archives keep packets with their family.** Archiving a packet or a single phase stays inside its track or its parent. It restores the same way.
- **New packets land where the tools look.** Scaffolding writes to the canonical specs root. It numbers from the highest folder instead of restarting at 001.
- **Saves write only what they own.** A save records the fields it carries. It leaves the files a whole track shares alone.
- **Level upgrades add whole sections.** A level upgrade no longer injects changed template lines. So the upgraded packet passes strict validation straight away.
- **The spec-folder question arrives once.** It waits for your first real file change instead of riding every turn. The answer is remembered on disk.
- **Every runtime hears the question.** Hermes receives the same delivery the other runtimes have. The pages that described the old behavior were corrected against the code.
- **The gate covers every repository.** A repository is gated wherever it lives. Scratch space outside it stays exempt.
- **A false alarm goes quiet.** The completion sentinel no longer reads a cited document as a missing packet.

## Spec Folders and Their Tools

Spec folders now behave like one system. They are created in the right place. They are numbered once. They are archived with their family. They are saved without collateral damage.

#### Old Specs Upgrade Without a Model

A person coming from v1.x holds spec folders that fail strict validation almost without exception. Every workflow stops at that failure. `node .skilled/skills/system-spec-kit/runtime/cli/spec/upgrade-legacy.mjs` fixes this in one pass. It needs no language model. It works on packets in a top-level `specs/` folder, where v2 reads them. If yours still live in `.opencode/specs`, it stops and prints the one move that fixes that. It is a dry run until you pass `--apply`. `--roots <dir>` narrows it to the folders you name. `--include-archive` brings archived packets in too.

For each active packet that fails, it fills in the frontmatter keys a document lacks. Those keys are the metadata block at the top of each document. It does not rewrite any value already there. A document whose metadata block it cannot read is left as it is. The run names it. It then runs the existing repair tools on the packet. It writes every finding they cannot clear into the packet's `upgrade-baseline.json`.

The validator now reads that file. A finding listed there is a warning. So old findings stop blocking new work. A finding the file does not list is still an error. So a new mistake in an upgraded packet still fails. Findings about generated metadata are never listed for an active packet. That is because re-deriving the metadata clears them. One run was measured on snapshots of this repository's own v1 history. It took two large trees from 2 of 170 and 0 of 995 active packets passing. Both trees ended at 170 of 170 and 995 of 995. A second run changed nothing.

The same work tightens the backfill that regenerates a packet's derived metadata. It exits with a failure when a folder cannot be re-derived. So the repair tool reports the failure instead of calling the packet repaired. The pre-commit hook therefore blocks a commit whose metadata cannot be re-derived.

&nbsp;

#### Track Roots List What They Hold

Fifteen of the eighteen track roots listed packets they did not hold. They also missed packets they did. Nothing wrote these lists. The one check compared counts and ran nowhere. A writer now sets each track root's list from disk. Scaffolding adds a new packet to its track's list as it creates it. A push whose lists disagree with the folders beside them stops at the hook.

&nbsp;

#### Archives Keep Packets at Home

Archiving used to send everything to one pile at the specs root. A track packet left its track. A restore dropped it at the root. Same-numbered phases from different packets collided there. A packet now archives into the `z_archive/` beside its own track. A phase archives into its parent's. A restore returns each one where it came from. The track list refreshes after every move. So the push gate has nothing to block.

&nbsp;

#### New Packets Land in the Right Place

New packets were briefly written to a tree nothing reads. Each new name started its numbering at 001. Scaffolding now writes to the canonical `specs/` root. A packet created at the root uses the highest number already there. Making one no longer fetches or prunes remotes. So it never touches your network or your refs. It also works in a fresh checkout with no install. It writes the same documents the full toolchain would. It names the missing build when a generated file cannot be written.

&nbsp;

#### Saves Write What They Carry

A save used to ignore the continuity fields it was given. Those fields are the session bookkeeping a packet records. It also rewrote one file that every packet in the track shares. Together, those two meant concurrent sessions kept colliding and resume state went stale. The save now writes those fields into the packet that holds the work. The track's pointer lives in the store that resume reads first. The reader also accepts hand-written continuity blocks as people write them. So a block you wrote by hand is read rather than rejected.

&nbsp;

#### Level Upgrades Add Whole Sections

Upgrading a packet's level injected changed template lines along with the new sections. It left a second title and broken tables behind. A level upgrade now adds whole sections only. The upgraded packet passes strict validation straight away. The phase-map tool beside it now changes only the rows that disagree with their child. It reports a completion mismatch instead of writing over it.

## The Spec Gate

The gate that decides which folder a session's work belongs in grew quieter and more complete at once.

#### One Question at the First Save

The gate used to append its option menu to every turn that looked like a write. One recent session carried 52 injections with most gate states still open. The question now arrives once per session at your first real file change. It comes through whatever channel the runtime has. That is an interactive dialog on Pi, a tool-call notice elsewhere and a one-shot deferral where nothing better exists. The answer is remembered on disk. So a later write stays quiet. Answering also works for a folder you name that does not exist yet.

&nbsp;

#### Every Runtime Hears the Question

Moving the question left one runtime holding a gate that opened and never spoke. That is because the shared adapter had gone silent and the plugin's own mocks hid it. Hermes receives the same delivery the other runtimes have now. The pages that still described the old turn-time behavior were corrected against the code. That includes two claims that were wrong about when the question appears.

&nbsp;

#### The Gate Covers Every Repository

The gate used to exempt anything under `/tmp`. That switched it off for a repository that itself lives there. A repository is now gated wherever it lives. Scratch space outside it stays exempt. The CI workarounds that the old rule forced are gone. The recorded probe scripts run under the shell standard the drift check expects.

&nbsp;

#### A Cited Document Is Not a Missing Packet

The completion sentinel no longer reads a cited document as a missing packet. It is the advisory that checks a completion claim against the evidence a packet recorded. A reply that cites a document inside a packet resolves to the packet folder now. The false alarm is gone.

## Upgrade Notes

- Upgrading from v1.x? If your packets still live in `.opencode/specs`, move them first with `rm -f specs && git mv .opencode/specs specs && ln -s ../specs .opencode/specs`. A v1 checkout tracks `specs` as a link to `.opencode/specs`. So the link goes first. `rm -f` never removes a real folder. Then run `node .skilled/skills/system-spec-kit/runtime/cli/spec/upgrade-legacy.mjs`. It shows what it would change. It writes nothing until you pass `--apply`.
- Set `SPECKIT_SKIP_SPEC_REMINT=1` when you mean to bypass the pre-commit check that blocks a commit whose packet metadata cannot be re-derived.
