# v2.1.0.0, The Spec Kit Adopts Your History: One Command, One Question

This release starts with the work you already have.

- Spec folders from v1.x fail strict validation almost without exception.
- Until now every workflow stopped at that failure.
- A new command repairs them in one pass.
- No language model is involved.

The tools that create, move and archive spec folders now keep them consistent.

- Track roots list what they hold.
- Archives keep packets with their family.
- New packets land in the canonical root.
- Saves write only the fields they carry.

The gate that binds a session to a spec folder grew quieter at the same time.

- The question arrives once, at your first real file change.
- It comes through whatever channel the runtime has.
- It reaches every repository.
- It no longer exempts the ones that live in scratch space.

One false alarm went quiet in the same pass.

- The completion sentinel no longer reads a cited document as a missing packet.
- A reply that cites a document inside a packet resolves to the packet folder now.

&nbsp;

## Why This Release

A rebuild as large as v2.0.0.0 moves so much. So its own history becomes the fastest way to find the seams. Everything in this part of the release was measured against real packets, real sessions and real dispatches. It was not measured against a demo.

- This release also carries the one thing a person upgrading from v1.x needs most.
- Old spec folders should cost one command to adopt.
- They should not cost a repair project paid for in AI time.
- This release ships that command.
- It also ships the validator change that keeps old findings from blocking new work.

## Spec Folders and Their Tools

Spec folders now behave like one system. The tools that create, move and archive spec folders now keep them consistent. They are created in the right place. They are numbered once. They are archived with their family. They are saved without collateral damage.

#### Old Specs Upgrade Without a Model <a id="c-old-specs-upgrade-without-a-model"></a>

- A person coming from v1.x holds spec folders that fail strict validation almost without exception.
- Every workflow stops at that failure.
- `node .skilled/skills/system-spec-kit/runtime/cli/spec/upgrade-legacy.mjs` fixes this in one pass.
- It needs no language model.
- It fills what a document lacks.
- It does not rewrite a word you wrote.
- It works on packets in a top-level `specs/` folder, where v2 reads them.
- If yours still live in `.opencode/specs`, it stops and prints the one move that fixes that.
- It is a dry run until you pass `--apply`.
- `--roots <dir>` narrows it to the folders you name.
- `--include-archive` brings archived packets in too.
- For each active packet that fails, it fills in the frontmatter keys a document lacks.
- Those keys are the metadata block at the top of each document.
- It does not rewrite any value already there.
- A document whose metadata block it cannot read is left as it is.
- The run names it.
- It then runs the existing repair tools on the packet.
- It writes every finding they cannot clear into the packet's `upgrade-baseline.json`.
- The validator now reads that file.
- A finding listed there is a warning.
- So old findings stop blocking new work.
- A finding the file does not list is still an error.
- So a new mistake in an upgraded packet still fails.
- Findings about generated metadata are never listed for an active packet.
- That is because re-deriving the metadata clears them.
- The same work tightens the backfill that regenerates a packet's derived metadata.
- It exits with a failure when a folder cannot be re-derived.
- So the repair tool reports the failure instead of calling the packet repaired.
- The pre-commit hook therefore blocks a commit whose metadata cannot be re-derived.

#### Track Roots List What They Hold <a id="c-track-roots-list-what-they-hold"></a>

- Fifteen of the eighteen track roots listed packets they did not hold.
- They also missed packets they did.
- Nothing wrote these lists.
- The one check compared counts and ran nowhere.
- A writer now sets each track root's list from disk.
- Scaffolding adds a new packet to its track's list as it creates it.
- A push whose lists disagree with the folders beside them stops at the hook.

#### Archives Keep Packets at Home <a id="c-archives-keep-packets-at-home"></a>

- Archiving used to send everything to one pile at the specs root.
- A track packet left its track.
- A restore dropped it at the root.
- Same-numbered phases from different packets collided there.
- A packet now archives into the `z_archive/` beside its own track.
- A phase archives into its parent's.
- A restore returns each one where it came from.
- The track list refreshes after every move.
- So the push gate has nothing to block.

#### New Packets Land in the Right Place <a id="c-new-packets-land-in-the-right-place"></a>

- New packets were briefly written to a tree nothing reads.
- Each new name started its numbering at 001.
- Scaffolding now writes to the canonical `specs/` root.
- A packet created at the root uses the highest number already there.
- Making one no longer fetches or prunes remotes.
- So it never touches your network or your refs.
- It also works in a fresh checkout with no install.
- It writes the same documents the full toolchain would.
- It names the missing build when a generated file cannot be written.

#### Saves Write What They Carry <a id="c-saves-write-what-they-carry"></a>

- A save used to ignore the continuity fields it was given.
- Those fields are the session bookkeeping a packet records.
- It also rewrote one file that every packet in the track shares.
- Together, those two meant concurrent sessions kept colliding and resume state went stale.
- The save now writes those fields into the packet that holds the work.
- The track's pointer lives in the store that resume reads first.
- The reader also accepts hand-written continuity blocks as people write them.
- So a block you wrote by hand is read rather than rejected.

#### Level Upgrades Add Whole Sections <a id="c-level-upgrades-add-whole-sections"></a>

- Upgrading a packet's level injected changed template lines along with the new sections.
- It left a second title and broken tables behind.
- A level upgrade now adds whole sections only.
- The upgraded packet passes strict validation straight away.

- It reports a completion mismatch instead of writing over it.

## The Spec Gate

The gate that decides which folder a session's work belongs in grew quieter and more complete at once.

#### One Question at the First Save <a id="c-one-question-at-the-first-save"></a>

- The gate used to append its option menu to every turn that looked like a write.
- One recent session carried 52 injections with most gate states still open.
- The question now arrives once per session at your first real file change.
- It comes through whatever channel the runtime has.
- That is an interactive dialog on Pi, a tool-call notice elsewhere and a one-shot deferral where nothing better exists.
- The answer is remembered on disk.
- So a later write stays quiet.
- Answering also works for a folder you name that does not exist yet.

#### Every Runtime Hears the Question <a id="c-every-runtime-hears-the-question"></a>

- Moving the question left one runtime holding a gate that opened and never spoke.
- That is because the shared adapter had gone silent and the plugin's own mocks hid it.
- Hermes receives the same delivery the other runtimes have now.
- The pages that still described the old turn-time behavior were corrected against the code.
- That includes two claims that were wrong about when the question appears.

#### The Gate Covers Every Repository <a id="c-the-gate-covers-every-repository"></a>

- The gate used to exempt anything under `/tmp`.
- That switched it off for a repository that itself lives there.
- A repository is now gated wherever it lives.
- Scratch space outside it stays exempt.
- The CI workarounds that the old rule forced are gone.
- The recorded probe scripts run under the shell standard the drift check expects.

#### A Cited Document Is Not a Missing Packet <a id="c-a-cited-document-is-not-a-missing-packet"></a>

- The completion sentinel no longer reads a cited document as a missing packet.
- It is the advisory that checks a completion claim against the evidence a packet recorded.
- A reply that cites a document inside a packet resolves to the packet folder now.
- The false alarm is gone.

## Upgrade Notes

The steps below apply to a person upgrading from v1.x. Move your packets, then run the upgrade command.

#### Before You Start <a id="c-before-you-start"></a>

1. If your packets still live in `.opencode/specs`, move them first with `rm -f specs && git mv .opencode/specs specs && ln -s ../specs .opencode/specs`.
2. Then run `node .skilled/skills/system-spec-kit/runtime/cli/spec/upgrade-legacy.mjs`.
3. It shows what it would change.
4. It writes nothing until you pass `--apply`.

<details>
<summary><b>Moving old packets</b></summary>

- A v1 checkout tracks `specs` as a link to `.opencode/specs`.
- So the link goes first.
- `rm -f` never removes a real folder.

</details>

<details>
<summary><b>Bypassing the metadata check</b></summary>

- Set `SPECKIT_SKIP_SPEC_REMINT=1` when you mean to bypass the pre-commit check that blocks a commit whose packet metadata cannot be re-derived.

</details>
