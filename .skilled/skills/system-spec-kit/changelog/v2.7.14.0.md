# v2.7.14.0, Checks Fail Only What Is Broken

Three spec-kit checks failed content that was fine, and `create.sh` let a stray dash through. All four now behave.

> Spec folders: `specs/system-speckit/034-spec-folder-tooling/021-follow-up-defect-fixes` and `specs/sk-code/011-sk-code-poinytail-based-refinement/031-epic-review-fixes` (Level 2 and Level 1)

&nbsp;

## What's New at a Glance

- **A parent stored as the text `null` counts as no parent.** Packets whose `graph-metadata.json` stored `parent_id` as the string "null" no longer fail the metadata path check or need a hand fix. The next re-derive writes JSON null.
- **The placeholder scan skips research and review folders.** They hold the output of the deep-research and deep-review workflows, which write and regenerate it, so a finished packet now passes the check.
- **A markdown link label no longer reads as a placeholder.** The scan strips `[label](` from a link before it rechecks, so a bracketed link label stops failing the check.
- **`create.sh` refuses a lone `-` like any other unknown option.** The dash no longer becomes part of the new folder name. The run prints `Error: unknown option '-'` and exits 1 before it writes anything.

&nbsp;

## Upgrade

Run `repair-derived --folder <packet> --apply` on any packet left for a hand fix, so the stored `null` parent clears. Nothing else is required.
