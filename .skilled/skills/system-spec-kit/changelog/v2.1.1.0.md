# v2.1.1.0, The Spec Kit Goal Settles on One Limit and One Command

The spec-kit goal now has one limit and one authoring path. A top-level or phase-parent goal passes the validator up to 4,000 characters. It fails past that. The goal template carries no author instructions. The phase workflows send goal authoring to `/create:goal`.

&nbsp;

## What's New at a Glance

- One limit for a parent goal.
  - The goal validator and `goal.md.tmpl` lost the 3,000-character warning tier.
  - A top-level or phase-parent goal passes up to 4,000 characters.
  - The goal fails past that.
- The limit covers the same folders everywhere.
  - The validator applies the limit to every top-level packet.
  - The validator also applies it to every phase parent, nested or not.
  - The validator exempts only a phase child that is not itself a phase parent.
  - The validator draws the same line as the other goal tools.
- One home for the send rule.
  - system-spec-kit's `SKILL.md` and five speckit workflows point to section 4 of the create-goal mode's `references/budget-and-handoff.md`.
  - That section covers what a sent goal may carry.
  - The `SKILL.md` and the workflows point there instead of restating the rule.
- The goal template lost its author instructions.
  - The blockquote, the Operator copy section and the criteria introduction are gone from `goal.md.tmpl`.
  - That is because that text went out with every sent goal.
  - A `GOAL_AUTHORING` comment points to the create-goal mode instead.
- Phase workflows name `/create:goal`.
  - The phase workflows all send goal authoring to `/create:goal`.
  - The workflows are the speckit `:with-phases` step and Option D in plan and complete.
  - The workflows also include `phase-definitions.md`, `phase-system.md`, the quick reference and the `create.sh` help and next steps.
  - A retrofit has one path, `/create:goal <packet path> retrofit`.
  - The validator's two goal findings name their fix in the create-goal mode.
- Docs that match the runtime.
  - `create.sh --phase --with-goal` writes child goals only.
  - `--level phase-parent --with-goal` writes the parent goal.
  - The docs now say so.

&nbsp;

## Upgrade

Goals between 3,000 and 4,000 characters now pass the validator with no warning. A goal past 4,000 still fails. To add a goal to a packet that has none, run `/create:goal <packet path> retrofit`.
