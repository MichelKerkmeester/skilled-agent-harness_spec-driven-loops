# v2.12.13.0, Spec Folders No Longer Hold Changelogs

Changelogs now live in two places only: `.skilled/changelog/` and each skill's own `changelog/` folder, both written by `/create:changelog`. The closing workflows and the phase scaffold stopped creating a third copy inside the spec folder, which repeated what `implementation-summary.md` already records.

> Spec folder: `specs/system-speckit/054-weak-model-spec-authoring/025-deprecate-nested-changelogs` (Level 2)

&nbsp;

## What's New at a Glance

- **Closing a packet writes no changelog.** `/speckit:implement` and `/speckit:complete` end at `implementation-summary.md`, and the closeout display drops its changelog line.
- **A new phase child names no changelog.** `create.sh --phase` stops writing the `**Changelog**:` line and the note that told the phase to refresh one.
- **The generator says it is deprecated.** `nested-changelog.js` prints a notice on stderr on every run, `--help` included. Its stdout is unchanged so `--json` callers still parse it, and a test pins the notice.
- **The generator only re-renders.** `nested-changelog.js --write` refuses a packet that has no changelog. It throws an error that points at `/create:changelog` and writes nothing, so the generator can no longer start a new packet changelog.
- **The docs say where changelogs live now.** The skill, README, references, template guide, feature catalog and playbook mark packet changelogs deprecated and point at `/create:changelog`. The level-change steps now record the change in `implementation-summary.md` or in the spec.md CHANGE LOG section at Level 3+. The skill router loads the deprecated changelog page for research requests instead of on every `/speckit:complete`. `SKILL.md` is back under its 5000-word cap.

&nbsp;

## Upgrade

No migration required. The changelogs already inside spec folders stay and still validate, and the generator can still re-render them.
