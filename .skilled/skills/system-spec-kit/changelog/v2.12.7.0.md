# v2.12.7.0, README Paths Lead to Real Files

Some README instructions sent the reader to a file that was not there. Each one now names the file the repository tracks. The sample folder names read as shapes to fill in. They are not names to copy.

> Spec folder: `specs/sk-doc/070-repo-doc-debt/005-reference-and-coverage-fixes` (Level 2)

&nbsp;

## What's New at a Glance

- **Instructions open the file they name.** A README that pointed at a compiled `.js` name now points at the tracked `.ts` source. A path at the wrong depth now resolves from the skill root.
- **The test commands run from the skill root.** The docs give two commands. Both assume a folder that matches the one you are in.
- **Example folder names read as placeholders.** A walkthrough writes `specs/<track>/<NNN-name>/`. That replaces a sample name a reader could copy as given.
- **The two package files are described.** The skill README and the CLI README name their `package.json` and `tsconfig.json`. So you can see what builds the package. You can also see where the output lands.

&nbsp;

## Upgrade

No action is needed. These are documentation changes. So nothing about how the skill runs is different.
