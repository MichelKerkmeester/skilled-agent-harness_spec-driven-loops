# v2.12.7.0, README Paths Lead to Real Files

Some instructions in these READMEs sent the reader to a file that was not there. Each one now names the file the repository tracks. The sample folder names read as shapes to fill in rather than names to copy.

> Spec folder: `specs/sk-doc/070-repo-doc-debt/005-reference-and-coverage-fixes` (Level 2)

&nbsp;

## What's New at a Glance

- **Instructions open the file they name.** Where a README pointed at a compiled `.js` name it now points at the tracked `.ts` source. Where a path sat at the wrong depth it now resolves from the skill root.
- **The test commands run from the skill root.** Both commands the docs give are written so that the folder they assume matches the one you are in.
- **Example folder names read as placeholders.** A walkthrough writes `specs/<track>/<NNN-name>/` in place of a sample name a reader could copy as given.
- **The two package files are described.** The skill README and the CLI README name their `package.json` and `tsconfig.json`, so you can see what builds the package and where the output lands.

&nbsp;

## Upgrade

No action is needed. These are documentation changes, so nothing about how the skill runs is different.
