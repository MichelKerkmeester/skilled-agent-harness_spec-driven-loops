# v2.0.0.0, The Spec Kit Rebuilt: Top-Level Specs and Lexical Retrieval

The spec kit changed the most under the surface. The memory database behind `memory_search` is gone. The specs folder moved to the top level. The runtime was renamed and nested. The completion gate was made coherent. Most of the depth is in what left.

An entire retrieval engine was replaced by two small lexical tools. The SQLite database left the tree. So did the embedder. So did the spec-memory MCP server, the tool endpoint agents queried. So did its daemon. Retrieval now runs on a committed trigger index and ripgrep (fast text search). Both sit behind `/speckit:search`. A miss is a clean no-hit rather than a degraded guess.

The paths changed with it. Specs now live in a physical top-level `specs/` directory. The old `.opencode/specs/` location still resolves through a compatibility symlink. The engine itself moved to `.skilled/skills/system-spec-kit/runtime/cli/`. The old `scripts/` and `mcp-server/` paths are gone.

Two quieter changes round out the release. The completion gate grew two checks of its own. The core templates were consolidated into one shared core. It renders byte-for-byte identically to before.

> Shipped in [Skilled v4.0.0.0](../../../changelog/skilled/v4.0.0.0.md), the framework release that rebuilt the foundation.

## Why This Release

The kit carried more machinery than it used. A database, an embedder and a background daemon existed to answer questions. A committed index and a text search now answer them. Each of those three was another thing to keep alive.

The same pattern ran through the rest of the kit. The specs sat under a tool-specific folder. The runtime still called itself an MCP server. The gate asked packets for things they could not satisfy from inside themselves. Three research rounds then cut the kit back to what a machine reads.

This release lands the cut: fewer moving parts, clearer paths and a gate you can trust.

## What's New at a Glance

- **Specs live at the top level.** Canonical spec paths are now `specs/...`. The old `.opencode/specs/` location still resolves through a compatibility symlink.
- **The memory database is retired.** SQLite, embeddings and the `memory_search` and `memory_save` tools are gone.
- **Search runs through `/speckit:search`.** It reads a committed trigger index with no daemon. It returns a clean no-hit when a phrase is absent.
- **The runtime is renamed and nested.** The engine lives at `.skilled/skills/system-spec-kit/runtime/cli/`. The old `scripts/` and `mcp-server/` paths are gone.
- **The completion gate tells the truth.** It returns the same verdict in every environment. It counts one fault once. It registers forty rules. A warning is advice rather than a failure.
- **Two new checks guard a packet's close.** Scope adherence refuses changes outside what a spec names. Acceptance coverage runs on by default as an advisory.
- **Two documents join the packet contract.** `acceptance-criteria.md` decides closure at Levels 2 and 3. An optional `goal.md` holds the durable directive you set as the session objective.
- **A repair tool recomputes recorded facts.** It fixes what a packet records wrongly but a machine can recompute. It refuses to invent what only a person can write.
- **The templates are smaller.** The spec, plan, tasks and implementation-summary templates share one core. They carry level-gated addenda and render identically to before.

## Spec Paths

#### Specs Move to the Top Level

Your spec paths have a new root. The specs folder moved from `.opencode/specs/` to a physical top-level `specs/` directory. Canonical spec paths are now `specs/...`.

**Breaking:** The canonical path changed. So update references that point at `.opencode/specs`. The old location still resolves through a compatibility symlink. Existing references keep working while you catch up.

---

## Retrieval Without the Database

#### The Memory Database Retired

The Spec-Kit Memory engine is gone. The SQLite database, the embedder and the spec-memory MCP server were decommissioned end to end. Its daemon went too. So did the `memory_search` and `memory_save` tools.

What replaced them is deliberately small:

- A committed trigger index, generated from every document's `trigger_phrases` frontmatter
- A lookup script that reads it with no daemon
- A set of ripgrep recipes that handle free text

All of it sits behind `/speckit:search`. The kit's own context writer handles continuity. Retrieval is lexical now (exact word matching). A miss is a clean no-hit rather than a degraded guess.

---

## The Runtime's New Home

#### The Runtime Renamed and Nested

The surviving package no longer carries an identity it lost. Its engine lives at `.skilled/skills/system-spec-kit/runtime/cli/`:

- `spec/validate.sh`, `spec/create.sh`, `spec/repair-derived.cjs` and `spec/recommend-level.sh` for the packet lifecycle
- `continuity/` for saves
- `spec-folder/` for generated metadata
- `retrieval/` for the trigger index

**Breaking:** The old `scripts/` and `mcp-server/` paths are gone. So anything you pinned to them needs repointing. A shared package underneath carries the Gate-3 classifier and the frontmatter parser. Every other skill now imports it rather than copies it.

## The Completion Gate

#### A Gate That Tells the Truth

The gate decides whether a packet may close. It now returns the same verdict whatever the environment. It counts one fault once. It no longer asks a packet for what it cannot satisfy from inside itself. Forty rules are registered. A warning is advice that does not fail a run.

It grew two checks of its own. Scope adherence refuses a packet whose changed files fall outside what its spec names. It is driven by `SYSTEM_SCOPE_CHANGED_FILES` and `SYSTEM_SCOPE_BASE`. Acceptance coverage runs on by default as an advisory.

Two documents joined the packet contract. `acceptance-criteria.md` decides closure at Levels 2 and 3. An optional `goal.md` holds the durable directive you set as the session objective. A repair tool fixes the facts a packet records wrongly but a machine can recompute. Those include its folder, level and generated fingerprints. It refuses to invent the facts only a person can write.

---

## Smaller Templates

#### Same Output at Every Level

The spec, plan, tasks and implementation-summary templates were consolidated into one shared core. It carries level-gated addenda. The template source dropped to 1,275 lines across four core templates. Not a single rendered byte changed. The research template shrinks by level too.

A Level 1 spec now gets a short research doc instead of the full one. A Level 1 research doc renders at 175 lines instead of 944. You see smaller, level-appropriate templates. What they produce is identical.
