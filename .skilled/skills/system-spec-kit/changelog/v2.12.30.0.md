# v2.12.30.0, Each Linked Project Keeps Its Own Decision Answers

Every project linked to one Skilled checkout used to write its captured operator answers into the same state folder, because that folder sits inside the shared `.skilled` link. A save in one project could list another project's sessions as orphans, and one project's consumed keys could hide another's. Each project now writes into its own subfolder.

> Spec folders: `specs/system-speckit/043-decision-capture/008-project-scoped-state`, `009-chat-answer-evidence` and `010-decision-routing-vocabulary` (Level 2)

&nbsp;

## What's New at a Glance

- **Each project has its own answer folder.** Captured answers, the consumed-key log, nudges and locks live in `.skilled/skills/.state/decision-capture/<project-token>/`, where the token is a short hash of the project's real root. The hook core and the save-time writer and matcher compute the same folder, and a test holds them together.
- **Older answers are still found.** Files a save left in the folder's root before this change are still read, so nothing captured earlier is lost. The orphan list at save time reads only the project's own folder, so it no longer names another project's sessions.
- **Chat answer candidates carry evidence.** Each candidate a sweep prints now has an `evidence` object: the question's type, whether the reply names an offered option, how many words it shares with the question, whether it opens with a new task and whether it changes the subject. The save step reads it, still decides for itself, and ends each chat entry's reason with an `Evidence:` sentence so the choice can be checked later. No candidate is accepted or rejected by code.
- **"Record this as a decision" routes to spec-kit.** Four phrases and a DECISION intent send a request to record an answer as a decision to the skill that owns the save step. Before, it routed nowhere.

&nbsp;

## Upgrade

No migration required. Run a full-auto save in each linked project once to clear answers left in the shared root; after that the root files can be deleted.
