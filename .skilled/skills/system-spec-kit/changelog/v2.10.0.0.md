# v2.10.0.0, The Freshness Check Can Run Without Writing

This release follows 2.9.2.0. The dist freshness library can now answer a caller that may not write anything. A read-only run returns the verdict it always did and leaves no cache record beside the dist entry it checked.

&nbsp;

## What's New at a Glance

- **A freshness check can return its verdict without writing.** `checkPackageFreshness` and `checkAllFreshness` take a `readOnly` option, and the library CLI takes `--no-write`, so a shell caller asks for the same mode. A read-only run still reads a stored record when one matches and computes the same verdict when none does.
- **Every existing caller keeps the writable default.** Four session-start hooks and `--all` still read and write the record, which is what makes a second run cheap. Only a caller that asks for the mode skips the write.
- **A built file resolves to the package that builds it.** `packageForDistFile` maps a dist path back to its package and to the entry name that package declares, so `checkFileFreshness` returns that package's verdict for a built file instead of `unmatched`. The dist checker that calls this library prints a `DIST FRESHNESS CHECK UNMATCHED:` line in read-only mode for a path no package owns, so a caller reads an unverifiable build output as unverified rather than as clean.
- **A package with hoisted dependencies is provisioned.** `isPackageProvisioned` accepts a `node_modules` in the package folder or at any ancestor up to the workspace root, so an npm workspace that hoists dependencies no longer makes every package under it read as unprovisioned. Without the walk a provisioned worktree answered `unprovisioned` for a package it had installed, and a stale branch behind that answer reported a clean build. The walk stops at the workspace root, so a `node_modules` above a checkout can never make one look provisioned.

&nbsp;

## Upgrade

No migration required. A caller that needs the read-only path passes `readOnly: true` through the option or `--no-write` on the CLI. The shipped dist checker reaches it through `SPECKIT_DIST_READ_ONLY=1`, which the quality runner sets on its per-file calls. A checkout whose dependencies resolve from an ancestor needs no change, because the provisioning walk finds them there.
