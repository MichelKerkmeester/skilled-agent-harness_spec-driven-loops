# v2.7.2.0, Every Hook Now Stops Waiting on an Open Stdin

Spec-kit's hooks used to read stdin until the stream closed, so a host that never closed it held the hook until the host killed it. All sixteen readers now stop at a deadline and take the same exit they take on an empty payload. The hooks whose host allows only 3 seconds stop after 500 ms and the rest stop after 3000 ms, which leaves the host's budget to the work after the read.

The deadline was built in two rounds. The first round was written up as its own 2.7.1.0, but that number went to the repair and upgrade release, so both rounds ship together here.

> Spec folders: `specs/sk-code/011-sk-code-poinytail-based-refinement/010-round-three-remediation/007-spec-kit-hook-deadlines` and `specs/sk-code/011-sk-code-poinytail-based-refinement/011-round-four-remediation/007-hook-deadline-margins` (Level 1)

&nbsp;

## What's New at a Glance

- **One deadline for the plain hooks.** `runtime/hooks/lib/hook-adapter-shared.mjs` settles when stdin ends or at its deadline, and every `.mjs` and `.cjs` hook reads through it.
- **The same deadline for the compiled hooks.** The new `runtime/hooks/shared-stdin.ts` serves the Claude, Codex, Cursor and Devin lifecycle adapters and keeps their 1 MB payload cap.
- **The prompt-submit shim is bounded.** `runtime/hooks/claude/user-prompt-submit.ts` reads stdin with its own 500 ms deadline and keeps its 1 MB cap and its `{}` answer on an empty, invalid or oversized payload.
- **A deadline sized to the host timeout.** The Claude `PreCompact` and `SessionStart` hooks, the Codex `SessionStart` and `UserPromptSubmit` adapters and the Claude and Codex prompt classifiers read with `SHORT_HOST_STDIN_TIMEOUT_MS`, 500 ms. Hooks with a longer host timeout keep 3000 ms.
- **A test that leaves stdin open.** `runtime/hooks/lib/hook-stdin-deadline.test.mjs` spawns all sixteen readers with stdin held open and checks that each one exits on its own with its usual empty-payload result, every 3 second entry under 2500 ms. It also checks that a payload written to a stdin that stays open still reaches the shim's advisor and the Claude and Codex session hooks.

&nbsp;

## Upgrade

Rebuild the runtime with `npm run build` in `.skilled/skills/system-spec-kit/runtime`, so the compiled hooks in `dist/` pick up the deadlines.
