# v2.12.14.0, Review Dispatch Marks and Reads Its Reviews

The review mode promised a `CODE-REVIEW` marker that a dispatcher adds to every code review prompt, and nothing added it. The orchestrator now adds it, the `/speckit:implement` and `/speckit:complete` review entries state it and a severity gate for any step that dispatches the review, and the orchestrator reads the quality verdict the code agent reports.

> Spec folder: `specs/sk-code/017-portable-code-modes/006-review-agent-and-dispatch` (Level 2)

&nbsp;

## What's New at a Glance

- **The marker is added.** The orchestrator starts a code review prompt with the `CODE-REVIEW` line and one blank line, and never adds it to a deep-loop dispatch. Both speckit review entries state the same marker for a step that dispatches the review.
- **The review gate follows severity.** The speckit review entries say a P0 or an open P1 fails the review gate, and the review's advisory score never blocks.
- **The orchestrator reads the quality gate field.** It names the code agent's `Quality Gate` field and says what to do for each runner verdict, so a blocked or unverified run is never taken as done.
- **A contract test pins all three.** It fails when a review entry loses the marker, when the gate gains a score threshold or when the orchestrator stops naming the field.
