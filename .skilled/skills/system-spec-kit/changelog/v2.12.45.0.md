# v2.12.45.0, moved paths in historical spec docs and two test roots

Regrouping ten spec tracks into sub-tracks moved 174 packets. The rename rule told authors to leave historical spec docs alone, which would have left hundreds of dead links. Two shell tests also turned out to have been checking nothing.

> Spec folder: `specs/system-speckit/spec-folder-tooling/002-named-subtracks-and-host-repos/009-rename-rule-and-test-root-fixes`

&nbsp;

## What's New at a Glance

- **A historical spec doc may follow a moved path.** `references/workflows/rename-pattern.md` still preserves the content of a packet's historical spec docs. It now allows one edit: a moved path that acts as a live locator is updated when the link check would otherwise fail.
- **The fingerprint test runs the validator.** `fingerprint-docset-generation.sh` resolved its repository root one folder short, at `.skilled/`, so every validator call failed and every count read 0. Three of its seven cases failed and the other four passed by accident. It now passes 7 of 7.
- **The write-containment test no longer skips itself.** `graph-metadata-write-containment.sh` had the same root, could not find the compiled parser and printed `SKIP` on every run. It now runs and passes 7 cases.
