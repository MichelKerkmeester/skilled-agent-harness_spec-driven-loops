# v2.12.37.0, a compacted session can read its own history

A compaction summary drops details. A session on Claude, Codex, Pi, Devin, DSH or OpenCode can now read back its own earlier turns through one read-only command, so a dropped detail is not lost.

> Spec folder: `specs/other/004-context-paging`

&nbsp;

## What's New at a Glance

- **The recovered context offers the lookup.** After a compaction it can end with a `## History Lookup` section that holds one command. The section appears only when the stored locator is fresh and the runtime's reader is ready.
- **Four operations, small replies.** `search`, `browse`, `load` and `page` answer in at most 16 KiB. Each reply holds only what the conversation showed, and the session treats it as data, not instructions.
- **A handle reaches one session.** It lasts 30 minutes and works only for the session and checkout that minted it.
- **Search finds a fragment.** `MARKER` or `dv-2b7e` finds the turn that said `LIVE-MARKER-dv-2b7e`.
- **Saves name their session.** `/speckit:save --session-id --runtime` records which session wrote a packet, and resume can fill gaps from it.
- **Recall requests reach this skill.** Prompts such as "history lookup", "earlier turns" or "before this compaction" now route to system-spec-kit.
- **Readers are stricter.** A Devin session whose turns are not in its database falls back to its transcript, and an OpenCode message stored twice is read once.

&nbsp;

## Upgrade

Run `npm run build` in `.skilled/skills/system-spec-kit/runtime` so the lookup command exists. Cursor does not get the offer yet.
