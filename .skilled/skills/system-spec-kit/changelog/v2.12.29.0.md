# v2.12.29.0, Saves From a Linked Project Land in That Project

Some projects link `.skilled` from a shared Skilled checkout. Such a project used to save into the wrong repository. That is because the scripts found the project root from their own location. That location is the shared checkout. They now take it from the folder you run them in. So a save from a linked project writes into that project's spec folders.

&nbsp;

## What's New at a Glance

- **The project root is the repository you work in.** The root is the git top-level of your working folder when it uses spec-kit. Then it is the working folder itself. The runtime's own repository is the last fallback. A note on stderr says so. Before, a save from a linked project looked for its packet in the shared checkout. It was refused as a duplicate.
- **Scripts run through a link do their work.** A script started through a linked path compared two spellings of its own path. It decided it was not the entry point. It exited 0 without doing anything. Both sides are now resolved before the comparison.
- **A save can name its root.** `generate-context` accepts `--project-root`. It refuses a root that is missing. It also refuses a root outside the repository you run it from.
- **Two maintenance scripts follow the same rule.** `backfill-frontmatter` and `migrate-trigger-phrase-residual` use the shared resolver. So they also work on the linked project.
- **Child sessions no longer get the context nudge.** A worker started with `AI_SESSION_CHILD=1` inherits its parent's environment. So at high context fill the nudge told it to save into the parent's packet. Every runtime adapter now skips the nudge for such a worker.
- **A phase parent may hold a decision record.** A decision can span every phase. One example is a log of the operator's answers across a long conversion. That decision can live in the parent's `decision-record.md`. Every other heavy doc stays in the children.

&nbsp;

## Upgrade

No migration required. Run saves from inside the repository that should receive them.
