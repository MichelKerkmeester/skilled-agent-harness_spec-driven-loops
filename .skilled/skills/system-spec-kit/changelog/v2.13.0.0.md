# v2.13.0.0, Packets Move by Command and Archives Can Be Searched

Moving a spec packet meant `git mv` and hand edits. Several records still named the old path afterwards. This release adds one command that moves a packet and fixes every record.

A track could grow into one long flat list. A new tool reads a track and proposes sub-tracks (named groups inside a track). It only prints. The spec-folder question now offers a sub-track too.

Archives were half supported. Search skipped them and recursive validation never entered them. Numbering ignored them, so a new packet could take an archived number. Each gap is closed. The archive search and validation are opt-in.

> Spec folder: `specs/system-speckit/spec-folder-tooling/005-subtrack-proposal-and-archive-reach`

&nbsp;

## Why This Release

A packet's path is written in many places. Its own metadata holds it. So do parent lists, track roots, links in other packets, the description cache and the trigger index. A hand move left most of them stale. Renumbering had the same cost.

Sub-tracks existed only as a hand-written declaration. No tool suggested one and no tool created one. An archived packet was out of reach for search and for validation, with no switch to change that.

&nbsp;

## What's New at a Glance

- **One command moves a packet.** `relocate.mjs` moves, renumbers and re-parents packets. It rewrites every record of the path. <!-- section: Moving Packets -->
- **A move is a dry run first.** The run prints its plan and writes nothing. `--apply` writes. <!-- section: Moving Packets -->
- **A tool proposes sub-tracks.** `suggest-subtracks.mjs` groups a flat track's packets and prints a map. It writes nothing. <!-- section: Sub-Tracks -->
- **The spec-folder question offers a sub-track.** Option C names an existing sub-track or a new one. `create.sh` prints one hint line. <!-- section: Sub-Tracks -->
- **Every sub-track has its own archive.** `archive.sh` moves a sub-track's packet into that sub-track's `z_archive/`. <!-- section: Archives -->
- **Numbering counts archived packets.** A new packet never takes an archived number. A restore onto a taken number picks the next free one. <!-- section: Archives -->
- **Search can reach archives.** `rg-wrapper.mjs --include-archive` also searches archived packets. Each such hit is marked `[archived]`. <!-- section: Archive Search and Validation -->
- **Validation can reach archives.** `validate.sh --recursive --include-archive` also checks archived packets. <!-- section: Archive Search and Validation -->

## Moving Packets

#### One Command Moves a Packet

`relocate.mjs` takes one of four inputs. `--map <file.json>` moves many packets. `--from <path> --to <path>` moves one. `--renumber <folder>` gives a packet the next free number. `--declare-subtrack <track>/<name>` creates a sub-track. A map is a list of pairs:

```json
[{ "from": "<track>/NNN-slug", "to": "<track>/<sub>/NNN-slug" }]
```

On `--apply` it moves each folder, with `git mv` when git tracks it. It rewrites every mention of the old path under `specs/` and recomputes relative links. Then it runs the tools that own each record. Those cover packet metadata, track roots and the trigger index. Each move is added to a committed ledger. The run ends with a sweep and a strict validation of each moved packet.

#### A Dry Run Comes First

Without `--apply` the run prints every move and every file it would change. A real dry run ends like this:

```text
moves=1 moved=0 rewrites=33 identity=1 roots=3 ledger=1
```

Exit 0 means nothing is left to do. Exit 1 means a dry run found work. Exit 2 means the plan was refused or a step failed. A second `--apply` of the same map prints `relocate: nothing to do`. A map that stopped part-way finishes on the next run.

#### Unsafe Plans Are Refused Early

Every refusal comes before the first write, so a refused plan changes nothing. The run refuses a collision, a taken number and a bad name. It refuses a track left with both flat packets and sub-tracks. It refuses a second sub-track level, a path outside `specs/` and a path through a link. It also refuses uncommitted work on a path it would touch. Each refusal prints a `refused:` line.

#### Code and CI Paths Are Reported

A moved path can be hard-coded in code or in a CI workflow. `relocate.mjs` never rewrites those files. It names each file and line and exits 2. Fix them by hand, then run the map again.

#### Smaller Fixes

- **A map that names one source twice is refused.** Such a map passed the checks. The apply step moved the first entry and failed on the second. The tree was left half moved.
- **A packet moved to a flat track loses its old parent.** `repair-derived.cjs` kept the parent recorded before the move. It now clears it.
- **More documents get their path pointer healed.** `repair-derived.cjs` now also fixes `goal.md`, `acceptance-criteria.md`, `resource-map.md` and `decision-record.md`.

## Sub-Tracks

#### A Tool Proposes the Groups

Run `suggest-subtracks.mjs --track <track>` on a flat track. It reads each packet's `description.json` and `graph-metadata.json`. It drops words that most packets share, since those describe the whole track. It groups packets that share enough of the rest. Each group is named from its two most shared words. Packets that match nothing go to a sub-track named `general`.

The map names every live packet once, in the format `relocate.mjs --map` accepts. A track under 8 live packets gets a reason instead:

```text
track cli-classifier has 6 live packets, below the threshold of 8; no map
```

`--threshold <n>` changes that number. The tool never writes. Moving stays with `relocate.mjs` after you approve the map.

#### It Places a New Packet

Add `--describe "<text>"` on a track that already has sub-tracks. The tool scores the text against each one. A fit needs at least 2 matched words. The tool names the best fit or says none fits:

```text
best fit: system-speckit/spec-folder-tooling
```

#### The Question Offers a Sub-Track

Option C of the spec-folder question now includes a sub-track of the track. That can be an existing one. It can also be a new one, proposed as a map for the whole track.

`create.sh` adds one hint line on stderr in three cases. The track has grown into clusters. The packet fits no existing sub-track. The packet fits another sub-track better than the one you named. The line never stops the scaffold:

```text
[speckit] Track demo has grown into clusters. Consider sub-tracks: node .skilled/skills/system-spec-kit/runtime/cli/spec/suggest-subtracks.mjs --track demo
```

#### A Sub-Track Can Be Declared

`relocate.mjs --declare-subtrack <track>/<name> --apply` creates a sub-track. It writes the description, the graph metadata and `z_archive/.gitkeep`. It refuses a track that still holds flat packets, since that would leave the track mixed. A map that names a new sub-track declares it in the same run.

## Archives

#### Each Sub-Track Has an Archive

`archive.sh` moves a packet into the `z_archive/` beside it. For a packet in a declared sub-track, that is the sub-track's own folder. `refresh-track-roots.mjs --apply` creates a missing one with an empty `.gitkeep`. A dry run lists it and exits 1:

```text
demo/sub: create z_archive/.gitkeep
```

An existing `z_archive/` is left alone. One that is a symlink is refused with exit 2.

#### The Sweep Names a Missing Archive

`sweep-track-roots.mjs` prints one line per declared sub-track without a `z_archive/`. The line names the command that creates it. It never changes the exit code. It shows only on a working-tree run, never with `--rev`.

#### New Numbers Skip Archived Ones

`create.sh` reads the numbers in the target folder and in its `z_archive/`. With `001-a` live and `z_archive/007-b` archived, the new packet is `008`. An archive that holds only lower numbers changes nothing.

#### A Restore Finds a Free Number

`archive.sh --restore` returns a packet to the folder its archive belongs to. A live packet with another name may now hold its number. The restore then lands on the next free number through `relocate.mjs`. In one check, `001-old` came back as `011-old` beside a live `001-holder`. A restore onto a live folder with the same name is still refused.

#### The Description Cache Follows a Move

`archive.sh` now rebuilds `specs/descriptions.json` after each archive and each restore. The old path's row goes and the new path's row appears. A failed rebuild prints a warning and the move stands.

The rebuild took 13 seconds in a test clone and 30 on the full tree. It can also rewrite a packet's `description.json`.

## Archive Search and Validation

#### Search Reaches Archived Packets

Add `--include-archive` to any `rg-wrapper.mjs` recipe. The run drops the one rule that hides `z_archive` and keeps the other three exclusions. Each archived path ends with `[archived]`:

```text
specs/sk-doc/z_archive/019-skill-routing-refactor/spec.md  [archived]
```

With the flag, JSON rows carry `archived: true` or `archived: false`. Without it, the command and its output are unchanged. Resume and the trigger index still leave archives out.

#### A Second Lane Lists Archived Metadata

The same run searches a second time, in metadata files only. It lists each archived `description.json` and `graph-metadata.json` that holds the phrase:

```text
json    : 1 archived metadata file(s)
```

The run exits 0 when either search matches.

#### Validation Reaches Archived Packets

`validate.sh <folder> --recursive --include-archive` also checks the packets in that folder's `z_archive/`. For a track root it adds each declared sub-track's `z_archive/` too. It reads one level only. It does not enter the archive of a packet it visits. It does not enter an archived packet's phase children. The flag alone exits 2:

```text
ERROR: --include-archive requires --recursive
```

Old archived packets fail today's rules, so expect exit 2 from a run with the flag.

#### Smaller Fixes

- **The `validate.sh` help states the real reach of the flag.** It claimed every `z_archive/` beside each visited folder. It now names the folder given and a track root's sub-tracks.
- **Archived packets no longer record a stale parent.** `repair-derived.cjs` clears it. The count fell from 35 of 267 to 0.

#### Tests and Scenarios

- **The full suite passed after the review fixes.** `npm test` exited 0. 211 files passed and 3 skipped. 2567 tests passed and 20 skipped, with 0 failed in every stage. Before the review fixes 2558 tests passed. The baseline was 206 files and 2524 tests.
- **Five new suites cover the release.** They hold 33 cases for moving, proposing, numbering, archive search and archive validation.
- **The review fixes added nine cases.** They cover the twice-named source, declaring a sub-track, a restore onto a free number and archive seeding.
- **The whole-track map was checked on a test track only.** No real flat track holds 8 live packets. A 10-packet test track gave a 10-entry map that `relocate.mjs` accepted.
- **The relocate suite does not run the full chain.** Six follow-up tools are stubs there. The clone run above covers the chain.
- **A stopped `--renumber` run does not finish on a rerun.** When an applied `relocate.mjs --renumber` run stops at a later step, a rerun of `--renumber` finds no moves and exits 0. The remaining steps stay undone. Run `repair-derived.cjs` and `refresh-track-roots.mjs` on the moved packets by hand. This was seen once, on a test track with invalid graph metadata.

## Upgrade Notes

- **Everyone:** No migration required. Search and validation act as before without the new flag.
- **Moving a packet:** Run `relocate.mjs` from the repository root as a dry run first. Commit your work on the paths it touches before `--apply`.
- **Scripts that read `create.sh` stderr:** Expect one more line on some tracks. Stdout is unchanged.
- **Scripts that predict the next packet number:** Count the numbers in `z_archive/` too.
- **Sub-tracks you declared by hand:** Run `refresh-track-roots.mjs --apply` to create a missing `z_archive/`.
- **After an archive or a restore:** Check `git status`. Commit or drop any rewritten `description.json`.
