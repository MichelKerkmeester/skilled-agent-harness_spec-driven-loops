# v2.12.40.0, a host names its trigger index folder

A host repository can now name the folder that holds its trigger index. A host that names none keeps `.speckit-index`.

> Spec folder: `specs/system-speckit/047-v4-release-line-research/023-configurable-host-index-folder`

&nbsp;

## What's New at a Glance

- **One setting names the folder.** Put `{ "indexDir": ".index" }` in a `.skilled-host.json` at the host root. The generator, the lookup and host detection all follow it, and a linked project reads the setting from the host it links into.
- **A bad setting stops the run.** `generate-trigger-index.mjs`, `lookup-trigger-index.mjs` and `upgrade-legacy.mjs` exit 2 and name the file when the setting cannot be used.
- **The folder is judged by where it lands.** A link that leaves the host is refused. So is a regular file. So is a tool-owned name, `.skilled`, `specs`, `.git` or `node_modules`, in any letter case.
- **A half-finished move is named.** When the named folder holds no index and `.speckit-index` still does, the lookup says so in one line on stderr.

&nbsp;

## Upgrade

No action is needed to keep `.speckit-index`. To move the index, add `.skilled-host.json` with `indexDir`, run `node .skilled/skills/system-spec-kit/runtime/cli/retrieval/generate-trigger-index.mjs` from the host root, commit the new folder and delete the old one.
