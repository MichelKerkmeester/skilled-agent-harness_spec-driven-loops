# v2.7.0.0, One Value List and Checked Sources

Spec docs and skill docs now read their `contextType` and `importance_tier` values from one file, and `validate.sh` warns on a value outside it. A second warning checks the `[SOURCE: path:line]` tags in new research and review packets. Both only warn, so no packet that passed before fails now.

> Spec folder: `specs/system-speckit/050-open-knowledge-format-adoption` (Level phase)

## What's New at a Glance

- **One list for frontmatter values.** sk-create-frontmatter's `assets/frontmatter-values.json` holds the four document `contextType` values, the six tiers and their aliases, and spec-kit and sk-doc both read it. The session list stays in `shared/context-types.ts`.
- **A warning for values outside the list.** The `FRONTMATTER_VALUES` rule names the values to use instead. The corpus was cleaned first, so it prints nothing today.
- **Source tags are checked in new packets.** The `SOURCE_TAGS` rule warns when a tag names a gone file, a moved file or a line past the end, and names a moved file's new path. A tag that resolves proves only that the path and line exist.
- **Old packets are left alone.** `SOURCE_TAGS` skips packets created on or before `SPECKIT_SOURCE_TAG_CUTOFF`, which defaults to 2026-10-04.
- **Saves keep their own list.** A save payload's `contextType` is checked against an 11-value session list, so `debugging` and `decision` still set the project phase. `discovery` is now accepted there too.
- **The doctor reports citations.** `/doctor:speckit speckit-retrieval` can run the citation-drift census and name each moved citation's new path, and `deep-loop` lists unresolved source tags per lineage.

## Upgrade

No migration required. Write a canonical value in new docs, and cite code in research as `[SOURCE: path:line]` with the path as it is now.
