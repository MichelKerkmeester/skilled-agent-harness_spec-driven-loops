# v2.13.2.0, Spec Commands Do What They Report

The spec commands said they saved your work. They did not. This release fixes the save first. Each command now saves once.

Plan, implement and complete now check work after it exists. A check fails when a file is missing or still empty. You cannot finish without a code review. Each mode says what it does whenever a command would stop to ask.

Autopilot stays in the workspace you give it. Resume opens the packet this session owns. If it finds none, it says so. Every page that describes a command now matches what the command does.

&nbsp;

## Why This Release

A save step said it worked. The writer had only planned the save. So a session could end with nothing saved. Nothing warned you.

Other steps also said one thing and did another. Implement marked its acceptance checks as met before any code existed. A check could pass with a required file missing. Auto mode was told never to ask and also to ask for approval. Autopilot could merge on its own. Resume could open another session's packet. The router, the README and the dashboard each gave different step counts.

## Saves

#### Saves Write Your Work Again

Plan, implement and complete passed the writer a temp file. They left out `--full-auto`. So the writer only planned and wrote nothing. Each step still said it saved. Now every save sends its data straight to one call:

```text
generate-context.js --stdin --full-auto --session-id <id> --runtime <slug> {spec_path}
```

The writer updates `description.json` and `graph-metadata.json` itself. Then one check runs: `validate.sh {spec_path} --strict`.

#### Each Command Saves Once

Each workflow used to save at points along the way. Each also offered a second save at the end. Both are gone. Plan, implement and complete each save once. Each workflow's closing text now sits in one place.

&nbsp;

## Gates and Review

#### Checks Come After the Work

Implement used to mark its acceptance checks as met before any code existed. Now it writes them before the build. A new step checks them after it. Complete's final check runs after the save it scores. Plan writes `tasks.md` in a step of its own.

Only one step creates the spec folder. Splitting work into phases comes after the request is read. It takes its level from `recommend-level.sh`. It names the phases it did not plan. Implement stops at step 1 when `plan.md` leaves a choice open.

#### A Check Passes Only When Every Part Passes

Checks used to add up points against a target. Now each check lists its parts. Each part names the step that makes it true. A file check fails when the file is missing. It also fails when the file still holds `YOUR_VALUE_HERE:`. So an empty template no longer counts as a plan.

A serious gap between the spec, plan and tasks stops the run before the build. So does a top-priority requirement with no task. The message names the step to go back to. After three failed rounds the run stops. It lists what is still open. Checks that no step could ever pass are removed.

#### You Cannot Finish Without a Code Review

Implement and complete now ask for a code review before they finish. The review prompt starts with `CODE-REVIEW`. It names the spec folder and the changed files. A `REQUESTED_CHANGES` answer blocks `implementation-summary.md`. The run goes back to the build once. A second request stops the run.

#### One Rule for Every Helper Agent

Plan now sends out only its four context agents. The old parallel settings are gone. Each agent uses the model its own file names. Each finding names a file and a line.

#### The Setup Check Knows Your Packet

`check-prerequisites.sh` read the packet from the branch name. On a worktree branch it stopped with "Not on a feature branch". So implement stopped at step 1. Now the three workflows set `SPECIFY_FEATURE` to your spec folder.

## Modes and Autopilot

#### Each Mode Says What It Does

A command sometimes stops to ask you something. Each of those places now says what confirm, auto and autopilot do there. Auto asks only when confidence is below 40. It also asks the spec folder question. Everywhere else it takes the stated default. Autopilot never asks. The approval rules are split in two. So auto is no longer told to ask and not to ask.

#### Autopilot Stays in Your Workspace

You give autopilot its workspace as `workspace_choice`. It makes a branch only with `git worktree add -b`. It never merges or pushes. It ends on one line:

```text
SPECKIT_AUTOPILOT_RESULT
```

With no workspace set, it stops with `uncertainty_blocked`. It stops before it writes anything. The start screen offers autopilot, and the dashboard shows it.

## Resume

#### Resume Opens This Session's Packet

Resume with no folder now looks in a fixed order. First it takes the folder you typed. Then it reads the handoff note this session claimed. Then it finds the packet tied to this session. It never reads another session's note. It skips a note whose folder is gone.

If nothing matches, auto says there is no session. Confirm lists up to three recent packets. Each is marked as not matched. Then it waits for you. Its panel starts with "No packet is matched to this session." A handoff note counts at any age.

#### One Resume Workflow

`speckit-resume.yaml` replaces `speckit-resume-auto.yaml` and `speckit-resume-confirm.yaml`. It picks its mode from `execution_mode`. Three old lookups are gone. Resume no longer matches fixed phrases. It no longer looks in `.opencode/specs/`. It no longer guesses by meaning. The router lists its flags, including `--no-redirect`.

## Command Contracts

#### Unknowns Go in the Plan

Planning no longer writes `research/research.md`. It lists unknowns in the Technical Context of `plan.md`. An unknown that needs real digging points to `/deep:research`. Research starts when confidence is below 40 percent, in every file.

#### Save, Search and Handoff Each Say What They Do

`/speckit:save` has one way to write: full-auto. Its screen shows blockers, warnings, open decisions and abandoned sessions. Its result comes from the writer's own output.

`/speckit:search` explains `--limit` for both kinds of search. Path and count searches go through the wrapper. A query that starts with `--` goes to the plain search. Exit 2 or higher always means an error.

`/speckit:handoff` lists its four status lines once, in one table. Its list of runtimes matches `session-relaunch.cjs --runtime`. It says that `prepare` refuses DSH.

#### Every Page About a Command Agrees

The router, README, dashboard and success line give the same step counts. Plan has 7 steps. Implement has 9. Complete has 13 and resume has 5. Autopilot adds step 13.5 to complete. The README table copies each router's argument line. Its file list names every file.

Setup no longer asks the Dispatch Mode question. No workflow used the answer. The earlier saved-work answer is now `prior_continuity_choice` in every file.

&nbsp;

## Workflow Cleanup

#### Shared Parts Live in One File

Five parts now live in `speckit-lifecycle-shared.yaml`. They are the check rules, the checkpoint choices, goal prompts, documentation levels and phase splitting. Each workflow points to that one copy. Two copies had drifted apart. Now they match.

#### Paths Work and Unused Steps Are Gone

Every path the workflows name now starts from the repository root, and each one exists. Complete names `specs/` where it named `.opencode/specs/`. Scoring steps and timers that nothing used are gone. So are the two 10-minute escalation triggers.

#### Smaller Fixes

- **The command contract names only real files.** It still named the two deleted resume workflows. So the router check failed.
- **Three plain spec requests now reach spec-kit.** The advisor used to miss them.

## Upgrade Notes

- **If you run a spec command on autopilot:** it no longer merges or pushes. Merge and push its branch yourself.
- **If a script names `speckit-resume-auto.yaml` or `speckit-resume-confirm.yaml`:** point it at `speckit-resume.yaml`.
- **If you keep spec packets under `.opencode/specs/`:** resume no longer looks there. Move them under `specs/`.
- **If you read `research/research.md` after planning:** it is no longer written. Read the Technical Context in `plan.md`, or run `/deep:research`.
- **If you answer setup questions from a script:** drop the Dispatch Mode answer. Renumber the answers after it.
