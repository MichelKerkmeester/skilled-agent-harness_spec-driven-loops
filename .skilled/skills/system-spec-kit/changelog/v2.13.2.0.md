# v2.13.2.0, Spec Commands Do What They Report

The spec commands said they saved continuity, but the save never wrote. This release fixes that save first. Plan, implement and complete each save once now.

The three lifecycle commands also check work after it exists. A gate fails on a missing or unfilled file. Completion needs a code review. Each mode says what it does at every stop.

Autopilot stays inside the workspace you give it. Resume opens the packet this session owns, or says it found none. Every description of a command now matches its workflow.

> Spec folder: `specs/system-speckit/spec-authoring-and-continuity/007-speckit-command-gates-step-order-drift`

&nbsp;

## Why This Release

A save step reported success while the writer only planned. So a session could end with no continuity at all. Nothing warned about it.

The workflows had other gaps between what they said and what they did. Implement marked acceptance rows met before any code existed. A gate could pass with a required file missing. Auto mode was told both to never prompt and to get approval. Autopilot could merge on its own. Resume could open a packet another session owned. Routers, READMEs and dashboards gave different step counts.

&nbsp;

## Saves

#### Lifecycle Saves Write Continuity

Plan, implement and complete handed the writer a temp file without `--full-auto`. So the writer ran plan-only and wrote nothing. Each step still reported a save. Now every lifecycle save pipes JSON to one call:

```text
generate-context.js --stdin --full-auto --session-id <id> --runtime <slug> {spec_path}
```

The writer refreshes `description.json` and `graph-metadata.json` itself. One `validate.sh {spec_path} --strict` runs after it.

#### Each Command Saves Once

Each workflow used to save at checkpoints mid-run. Each also offered a second save at the end. The three checkpoint saves and the three closing offers are gone. Plan, implement and complete each run one save step. Each workflow's closing text now sits in its termination message.

&nbsp;

## Gates and Review

#### Checks Come After Their Producer

Implement used to mark acceptance rows met before any code existed. It now writes them before development. A new step verifies them after it. Complete's exit gate runs after the save it scores. Plan writes `tasks.md` in a task breakdown step of its own.

Only one step creates the spec folder. Phase splitting runs after request analysis and takes its level from `recommend-level.sh`. It names the children it did not plan. Implement stops at step 1 when `plan.md` leaves a design choice open.

#### A Gate Passes Only When Every Check Passes

Gates used to add up points against a threshold. Now each gate lists its checks, and each check names the step that makes it true. A document check fails when the file is missing. It also fails when the file still holds a `YOUR_VALUE_HERE:` token. So an unfilled scaffold no longer counts as a plan.

A CRITICAL or HIGH consistency finding stops the run before development. So does a P0 requirement with no task. The message names the step to return to. After three failed rounds the run stops and reports what is open. Checks that no step could ever satisfy are removed.

#### Completion Needs a Code Review

Implement and complete now dispatch a code review before done. Its prompt opens with `CODE-REVIEW` and passes the spec folder and the changed files. A `REQUESTED_CHANGES` verdict blocks `implementation-summary.md`. It sends the run back to development once. A second one halts the run.

#### One Dispatch Rule for Every Agent

Plan now dispatches only its four context explorers. The parallel and multi-agent settings are gone. Each explorer uses the model its agent file names. Each finding it reports carries a file path and a line number.

#### The Prerequisites Check Knows the Packet

`check-prerequisites.sh` read the packet from the branch name. On a worktree branch it exited 1 with "Not on a feature branch". So implement stopped at step 1. The three workflows now set `SPECIFY_FEATURE` to the bound spec folder.

## Modes and Autopilot

#### Every Stop Says What Each Mode Does

Every stop-and-ask branch now carries a map for confirm, auto and autopilot. Under auto, only a confidence below 40 and the Gate 3 question still ask. Every other branch names its default. Under autopilot no branch asks. The approval rules are split into confirm-only and auto-and-autopilot. So auto is no longer told both to never prompt and to get approval.

#### Autopilot Stays in Your Workspace

Autopilot takes its workspace from you as `workspace_choice`. It creates a branch only with `git worktree add -b`. It never merges or pushes. It ends on one line:

```text
SPECKIT_AUTOPILOT_RESULT
```

With no bound workspace it stops with `uncertainty_blocked` before any write. The startup screen offers autopilot, and the dashboard shows it.

## Resume

#### Resume Opens This Session's Packet

Resume with no folder now looks in a fixed order. It takes the command argument first. Then it reads the handoff note this session claimed. Then it reads the packet whose session record matches. A note another session owns is never read. A note that names a missing folder is skipped.

When none names a packet, auto prints the No Session result. Confirm lists up to three recent packets, each marked as not matched, and waits. Its panel opens with "No packet is matched to this session." A handoff note is read at any age.

#### One Resume Workflow

`speckit-resume.yaml` replaces `speckit-resume-auto.yaml` and `speckit-resume-confirm.yaml`. It picks its mode from `execution_mode`. The fixed-phrase match, the `.opencode/specs/` root and the semantic fallbacks are gone. The router lists its flags, including `--no-redirect`.

&nbsp;

## Command Contracts

#### Planning Records Unknowns in the Plan

Planning no longer writes `research/research.md`. It records unknowns in the Technical Context of `plan.md`. An unknown that needs digging names `/deep:research`. The research trigger reads below 40 percent everywhere.

#### Save, Search and Handoff State One Contract

`/speckit:save` names one writing mode, full-auto. Its display shows blockers, advisories, pending decisions and orphaned sessions. Its result block comes from the writer's own output.

`/speckit:search` documents `--limit` on both lanes. Path and count searches run through the wrapper. A query that starts with `--` goes to the raw recipe. Exit 2 or higher always means an error.

`/speckit:handoff` states its four status lines once, in one table. It names its runtime list as the `session-relaunch.cjs --runtime` values. It says that `prepare` refuses DSH.

#### Every Description Agrees

The router, README, dashboard and success line give the same step counts. Plan has 7 steps, implement 9, complete 13 and resume 5. Autopilot adds step 13.5 to complete. The README command table copies each router's argument hint. Its file tree lists every asset.

Setup no longer asks the Dispatch Mode question, which no workflow read. The prior continuity answer is named `prior_continuity_choice` in every file.

## Workflow Cleanup

#### Shared Blocks Live Once

Five blocks now live in `speckit-lifecycle-shared.yaml`. They are the check grammar, the checkpoint options, goal prompting, documentation levels and phase splitting. Each workflow points at the shared copy. Two copies had drifted apart, and both now read the same.

#### Paths Resolve and Unused Steps Are Gone

Every path the workflows name now resolves from the repository root. Complete names `specs/` where it named `.opencode/specs/`. The scoring steps and wall-clock timers no step used are removed. So are the two 10-minute escalation triggers.

#### Smaller Fixes

- **The command contract names only real files.** It still listed the two deleted resume workflows, so the router drift check failed.
- **Three plainly worded spec requests reach spec-kit.** The advisor used to miss them.

## Upgrade Notes

- **If you run a spec command on autopilot:** it no longer merges or pushes. Merge and push its branch yourself.
- **If a script names `speckit-resume-auto.yaml` or `speckit-resume-confirm.yaml`:** point it at `speckit-resume.yaml`.
- **If you keep spec packets under `.opencode/specs/`:** resume no longer looks there. Move them under `specs/`.
- **If you read `research/research.md` after planning:** it is no longer written. Read the Technical Context in `plan.md`, or run `/deep:research`.
- **If you answer setup prompts from a script:** drop the Dispatch Mode answer. Renumber the later answers.
