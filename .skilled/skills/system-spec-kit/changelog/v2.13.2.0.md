# v2.13.2.0, Spec Commands Do What They Report

The spec commands said they saved continuity, but the save never wrote. This release fixes that save. It also makes each command's gates, modes and resume match what the command says.

Plan, implement and complete now check work after it exists. They ask for a code review before done. Autopilot stays inside the workspace you give it.

> Spec folder: `specs/system-speckit/spec-authoring-and-continuity/007-speckit-command-gates-step-order-drift`

&nbsp;

## What's New at a Glance

- **Lifecycle saves write again.** Each save used to pass a temp file without `--full-auto`, so the writer only planned. Saves now pipe JSON to `generate-context.js --stdin --full-auto`, once per command.
- **Each gate runs after what it checks.** Acceptance rows are written before development and verified after it. A failed gate names the checks that failed.
- **Done needs a code review.** A `REQUESTED_CHANGES` result sends the run back to development once. A second one halts it.
- **Every ask says what each mode does.** Under auto, only a confidence below 40 and the Gate 3 question still ask.
- **Autopilot never merges or pushes.** It takes `workspace_choice` from you and branches only with `git worktree add -b`. It ends on one `SPECKIT_AUTOPILOT_RESULT` line.
- **Resume looks for this session's packet first.** It reads the command argument, then the handoff note, then the session record. With no match, confirm opens with "No packet is matched to this session."
- **Planning records unknowns in `plan.md`.** It no longer writes `research/research.md`. It names `/deep:research` instead.

&nbsp;

## How It Was Checked

`test-phase-command-workflows.js` passed 143 checks and failed none.

&nbsp;

## Upgrade

- **Repoint:** a script that names `speckit-resume-auto.yaml` or `speckit-resume-confirm.yaml` now uses `speckit-resume.yaml`.
- **Adopt:** after an autopilot run, merge and push its branch yourself.
- **Drop:** any step that reads `research/research.md` after planning. Read the Technical Context in `plan.md` instead.
