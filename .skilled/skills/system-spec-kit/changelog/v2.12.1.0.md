# v2.12.1.0, The Docs Catch Up With the Weak-Model Authoring Work

An audit of the weak-model authoring releases found several problems. A CI gate was failing. Docs still described v2.3 templates. Some features had no catalog entry, playbook scenario or advisor route. This patch fixes each finding. It does not change how a packet validates.

&nbsp;

## What's New at a Glance

- **The CLI check passes again.** The Draft auto-repair test imports the validation orchestrator. That import is now allowlisted. So the import-policy step of `npm run check` no longer fails.
- **Playbook scenarios expect v2.4 stamps.** The placeholder gate scenarios read the stamp a fresh scaffold prints. New scenarios cover `MEASURED_BEHAVIOR` and Draft auto-repair.
- **The catalog lists every shipped feature.** `MEASURED_BEHAVIOR` and Draft auto-repair have entries. The repair and authoring card entries describe the current behavior. Stale paths and counts are gone.
- **Guards and tests follow the code standards.** `check-example-drift.sh` gained its header and strict mode. The new test files carry module headers.
- **Commands and agents say what validate does.** The orchestrate agent requires an explicit `RESULT: PASSED`. The speckit commands list `MEASURED_BEHAVIOR`. `.env.example` names `SPECKIT_DRAFT_AUTO_REPAIR`.
- **Examples stop teaching effort estimates.** The filled task examples, the level guides and the complexity matrix match the templates. The templates have no effort field.
- **The skill advisor routes the new features here.** The skill's advisor metadata now names the authoring card. It also names the measured behavior block, `repair-derived` and Draft auto-repair.
- **READMEs and changelogs match the code.** Rule counts, document-kind counts and module counts are current. The packet changelogs record what each phase shipped.

&nbsp;

## Upgrade

No migration required. No validation rule changed. So every packet keeps its verdict.
