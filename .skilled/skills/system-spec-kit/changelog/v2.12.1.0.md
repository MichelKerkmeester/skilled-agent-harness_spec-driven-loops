# v2.12.1.0, The Docs Catch Up With the Weak-Model Authoring Work

An audit of the weak-model authoring releases found a failing CI gate, docs that still described v2.3 templates and features with no catalog entry, playbook scenario or advisor route. This patch fixes each finding without changing how a packet validates.

> Spec folder: `specs/system-speckit/054-weak-model-spec-authoring/020-alignment-audit-fixes` (Level 2)

&nbsp;

## What's New at a Glance

- **The CLI check passes again.** The Draft auto-repair test's import of the validation orchestrator is now allowlisted, so the import-policy step of `npm run check` no longer fails.
- **Playbook scenarios expect v2.4 stamps.** The placeholder gate scenarios read the stamp a fresh scaffold prints, and new scenarios cover `MEASURED_BEHAVIOR` and Draft auto-repair.
- **The catalog lists every shipped feature.** `MEASURED_BEHAVIOR` and Draft auto-repair have entries, the repair and authoring card entries describe the current behavior and stale paths and counts are gone.
- **Guards and tests follow the code standards.** `check-example-drift.sh` gained its header and strict mode, and the new test files carry module headers.
- **Commands and agents say what validate does.** The orchestrate agent requires an explicit `RESULT: PASSED`, the speckit commands list `MEASURED_BEHAVIOR` and `.env.example` names `SPECKIT_DRAFT_AUTO_REPAIR`.
- **Examples stop teaching effort estimates.** The filled task examples, the level guides and the complexity matrix match the templates, which have no effort field.
- **The skill advisor routes the new features here.** The skill's advisor metadata now names the authoring card, the measured behavior block, `repair-derived` and Draft auto-repair.
- **READMEs and changelogs match the code.** Rule counts, document-kind counts and module counts are current, and the packet changelogs record what each phase shipped.

&nbsp;

## Upgrade

No migration required. No validation rule changed, so every packet keeps its verdict.
