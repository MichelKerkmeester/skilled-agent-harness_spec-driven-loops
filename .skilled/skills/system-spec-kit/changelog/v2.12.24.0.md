# Hermes Router Links Resolve

Hermes now gets working links in its router copies. Before this release, each `ROUTER.md` reached Hermes byte for byte, so a relative link such as `../sk-doc/...` resolved only from the canonical skill folder. Once the hub routing prose moved from `SKILL.md` into `ROUTER.md`, those links pointed at nothing under the Hermes skill folder.

&nbsp;

## What's New at a Glance

- **Router links resolve in Hermes.** The sync rewrites relative links in each `ROUTER.md` copy the same way it already rewrote them in the `SKILL.md` copy, so a link works from the Hermes skill folder.
- **Router maps stay exact.** Fenced code blocks and inline code spans copy unchanged, so the routing maps a tool parses match the source. The frontmatter is unchanged too.
- **A skill without a router gets no router copy.** The sync removes any leftover copy, so `--check` passes for that skill.

&nbsp;

## Upgrade

Run the Hermes sync once so existing router copies pick up the rewritten links: `node .skilled/skills/system-spec-kit/runtime/cli/hermes/sync-skills-hermes.cjs`. Then run it with `--check` to confirm the copies match.
