# v2.11.0.0, Seven Add-ons and One Validate Run

A timed authoring loop showed where a model spends its spare calls on a spec packet: piping validator output through filters, looping on generated-metadata failures and validating the same packet three times. This release cuts those calls and drops three add-on templates that every template change had to carry but few packets used.

> Spec folders: `specs/system-speckit/054-weak-model-spec-authoring/013-addon-removal-and-speed-refinements` and `014-removed-template-reality-sweep` (Level 2)

&nbsp;

## What's New at a Glance

- **Seven add-ons instead of ten.** `before-after.md`, `roadmap.md` and the `resource-map.md` add-on template are removed, and `--with-lazy-addons` now scaffolds `timeline.md` and `decision-record.md`. `/deep:research` and `/deep:review` still write their own resource map.
- **One validate run, and it is quiet.** The card runs `validate.sh --strict --quiet` once, after the last edit, and reads the full report only when that line says `FAILED`.
- **Fix every failing rule, then rerun.** A round fixes all failing rules before the next run, and after three rounds the card records the rules in `goal.md` and stops.
- **The repair hint leads with the fix.** The `repair-derived.cjs --apply` command comes first, followed by what it rewrites, and the dry run is an optional last line.
- **Templates say how ids are numbered.** `spec.md` and `acceptance-criteria.md` state that a new REQ or AC id takes the highest plus one, and the closure note forbids counts and id ranges.

&nbsp;

## Upgrade

No migration required. `create.sh --with-lazy-addons` no longer writes `before-after.md` or `roadmap.md`. A packet that already holds a before-after, roadmap or packet-root resource-map file keeps it and gains no failure, because no template defines those files any more and the validator no longer checks them.
