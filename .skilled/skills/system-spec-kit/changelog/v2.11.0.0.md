# v2.11.0.0, Seven Add-ons and One Validate Run

A timed authoring loop showed where a model spends its spare calls on a spec packet. It pipes validator output through filters. It loops on generated-metadata failures. It validates the same packet three times. This release cuts those calls. It also drops three add-on templates. Every template change had to carry them, but few packets used them.

&nbsp;

## What's New at a Glance

- **Seven add-ons instead of ten.** These templates are removed: `before-after.md`, `roadmap.md` and the `resource-map.md` add-on template. `--with-lazy-addons` now scaffolds `timeline.md` and `decision-record.md`. `/deep:research` and `/deep:review` still write their own resource map.
- **One validate run, and it is quiet.** The card runs `validate.sh --strict --quiet` once, after the last edit. It reads the full report only when that line says `FAILED`.
- **Fix every failing rule, then rerun.** A round fixes all failing rules before the next run. After three rounds the card records the rules in `goal.md` and stops.
- **The repair hint leads with the fix.** The `repair-derived.cjs --apply` command comes first. Then comes what it rewrites. The dry run is an optional last line.
- **Templates say how ids are numbered.** `spec.md` and `acceptance-criteria.md` state that a new REQ or AC id takes the highest plus one. The closure note forbids counts and id ranges.

&nbsp;

## Upgrade

No migration required. `create.sh --with-lazy-addons` no longer writes `before-after.md` or `roadmap.md`. If a packet already holds a before-after, roadmap or packet-root resource-map file, it keeps it and gains no failure. That is because no template defines those files any more, and the validator no longer checks them.
