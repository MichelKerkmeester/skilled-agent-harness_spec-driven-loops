# v2.11.0.0, Seven Add-ons and One Validate Run

A timed authoring loop showed where a model spends its spare calls on a spec packet: piping validator output through filters, looping on generated-metadata failures and validating the same packet three times. This release cuts those calls and drops three add-on templates that every template change had to carry but few packets used.

> Spec folder: `specs/system-speckit/054-weak-model-spec-authoring/013-addon-removal-and-speed-refinements` (Level 2)

&nbsp;

## Why This Release

The before-after, roadmap and resource-map add-ons appeared in a handful of packets, yet each one needed manifest entries, phrase maps, snapshots and doc mentions kept in step with every template edit. Separately, in the 2026-10-26 speed loop (24 runs, tables in the spec folder's `scratch/analysis/`) 84 of 120 validate calls were filtered through a pipe, 30 of 39 failed calls named only the generated-metadata rules, and the card asked for three validate runs where one proves the packet.

&nbsp;

## What's New at a Glance

- **Seven add-ons instead of ten.** `before-after.md`, `roadmap.md` and the `resource-map.md` add-on template are removed. `--with-lazy-addons` now scaffolds `timeline.md` and `decision-record.md`.
- **One validate run, and it is quiet.** The card runs `validate.sh --strict --quiet` once, after the last edit, and reads the full report only when that line says `FAILED`.
- **Fix every failing rule, then rerun.** A round fixes all failing rules before the next run, and the card stops after three rounds.
- **The repair hint leads with the fix.** The `repair-derived.cjs --apply` command comes first, followed by what it rewrites; the dry run is an optional last line.
- **Templates say how ids are numbered.** `spec.md` and `acceptance-criteria.md` state that a new REQ or AC id takes the highest plus one, and the closure note forbids counts and id ranges.

&nbsp;

## Add-on Removal

#### Three Templates Gone

`addons/before-after.md.tmpl`, `addons/roadmap.md.tmpl` and `addons/resource-map.md.tmpl` are deleted, along with their manifest entries, `create.sh` phrase lists and seeds, the phrase census and cleanup maps, the template-structure name lists and the unused `shared.resource_map` path in the `/speckit:plan`, `/speckit:implement` and `/speckit:complete` workflows. The reference docs, catalog, playbook, skill README, `SKILL.md` and the root README now list the seven add-ons that remain.

#### The Deep Loops Keep Their Map

`/deep:research` and `/deep:review` still write their own `research/resource-map.md` and `review/resource-map.md` from their evidence, and `--no-resource-map` and the coverage gate are unchanged. That output never read the template: the renderer builds its ten categories from a fixed list in code, and the deep-loop catalog and playbook now say so. The runtime name lists that recognise a `resource-map.md` file stay, so existing copies resume and validate as before.

#### Docs Match the Code

A sweep of every README, skill doc, command, agent and runtime mirror removed the last mentions of the deleted templates and fixed the lines that no longer matched the code: the add-on and test counts, the templates tree, and the docs that called `decision-record.md` required at Level 3, which is an add-on on request at every level. `SKILL.md` and the orchestrate agent now ask for one `--quiet` validate run after the last doc write, and say the `/speckit` workflows keep their own gate after each doc-writing step.

#### Existing Files Stay

Packets that already hold a before-after, roadmap or packet-root resource-map file keep it. No rule requires or removes them, and because no template defines them any more, the validator no longer checks them, so no packet gains a failure.

&nbsp;

## Authoring Speed

#### Validate Once, Quietly

Section 9 of the authoring card runs `validate.sh <folder> --strict --quiet`, which prints one `RESULT:` line per packet, the folder named first. The close step points at that run instead of running the validator again.

#### One Round Fixes Every Rule

When the quiet line says `FAILED`, the model runs the same command once without `--quiet`, fixes every failing rule in one pass and reruns the quiet command. That is one round; after three rounds the model records the rules in `goal.md` and stops.

#### Repair Command First

When generated metadata drifts, the validator's hint now opens with `node .skilled/skills/system-spec-kit/runtime/cli/spec/repair-derived.cjs --folder <folder> --apply`, says it rewrites generated metadata, frontmatter packet pointers and the Spec Folder row and never other text, and tells the model to validate once after it. A new test pins that order.

#### Id Numbering in the Templates

The `spec.md` template's requirements section and the `acceptance-criteria.md` template each carry one visible line on how ids are numbered. The closure note asks for Yes or No plus one sentence and names a criterion only when it blocks closure.

&nbsp;

## Upgrade Notes

No migration required. `create.sh --with-lazy-addons` no longer writes `before-after.md` or `roadmap.md`. `upgrade-legacy` no longer fills a missing `contextType` in an existing root `resource-map.md`, because no template defines its values; the file is left as written.
