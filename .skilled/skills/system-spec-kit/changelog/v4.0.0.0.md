# v4.0.0.0, The Spec Kit Rebuilt: Top-Level Specs and Lexical Retrieval

The spec kit changed the most under the surface. The memory database that powered `memory_search` is gone, the specs folder moved to the top level, the runtime was renamed and nested, and the completion gate was made coherent. Most of the depth is in what left.

An entire retrieval engine was replaced by two small lexical tools. The SQLite database, the embedder, the spec-memory MCP server (the tool endpoint agents queried) and its daemon left the tree. Retrieval now runs on a committed trigger index and ripgrep (fast text search) behind `/speckit:search`. A miss is a clean no-hit rather than a degraded guess.

The paths changed with it. Specs now live in a physical top-level `specs/` directory, and the old `.opencode/specs/` location still resolves through a compatibility symlink. The engine itself moved to `.skilled/skills/system-spec-kit/runtime/cli/`, and the old `scripts/` and `mcp-server/` paths are gone.

Two quieter changes round out the release. The completion gate grew two checks of its own, and the core templates were consolidated into one shared core that renders byte-for-byte identically to before.

> Shipped in [Skilled v4.0.0.0](../../../changelog/skilled/v4.0.0.0.md), the framework release that rebuilt the foundation.

## Why This Release

The kit carried more machinery than it used. A database, an embedder and a background daemon existed to answer questions that a committed index and a text search now answer, and every one of them was another thing to keep alive.

The same pattern ran through the rest of the kit. The specs sat under a tool-specific folder, the runtime still called itself an MCP server, and the gate asked packets for things they could not satisfy from inside themselves. Three research rounds then cut the kit back to what a machine reads.

This release lands the cut: fewer moving parts, clearer paths and a gate you can trust.

## What's New at a Glance

- **Specs live at the top level.** Canonical spec paths are now `specs/...`, and the old `.opencode/specs/` location still resolves through a compatibility symlink.
- **The memory database is retired.** SQLite, embeddings and the `memory_search` and `memory_save` tools are gone.
- **Search runs through `/speckit:search`.** It reads a committed trigger index with no daemon and returns a clean no-hit when a phrase is absent.
- **The runtime is renamed and nested.** The engine lives at `.skilled/skills/system-spec-kit/runtime/cli/`, and the old `scripts/` and `mcp-server/` paths are gone.
- **The completion gate tells the truth.** It returns the same verdict in every environment, counts one fault once and registers forty rules, with a warning that is advice rather than a failure.
- **Two new checks guard a packet's close.** Scope adherence refuses changes outside what a spec names, and acceptance coverage runs on by default as an advisory.
- **Two documents join the packet contract.** `acceptance-criteria.md` decides closure at Levels 2 and 3, and an optional `goal.md` holds the durable directive you set as the session objective.
- **A repair tool recomputes recorded facts.** It fixes what a packet records wrongly but a machine can recompute, and it refuses to invent what only a person can write.
- **The templates are smaller.** The spec, plan, tasks and implementation-summary templates share one core with level-gated addenda and render identically to before.

## Spec Paths

#### Specs Move to the Top Level

Your spec paths have a new root. The specs folder moved from `.opencode/specs/` to a physical top-level `specs/` directory, so canonical spec paths are now `specs/...`.

**Breaking:** The canonical path changed, so update references that point at `.opencode/specs`. The old location still resolves through a compatibility symlink, so existing references keep working while you catch up.

---

## Retrieval Without the Database

#### The Memory Database Retired

The Spec-Kit Memory engine is gone. The SQLite database, the embedder, the spec-memory MCP server, its daemon and the `memory_search` and `memory_save` tools were decommissioned end to end.

What replaced them is deliberately small:

- A committed trigger index, generated from every document's `trigger_phrases` frontmatter
- A lookup script that reads it with no daemon
- A set of ripgrep recipes that handle free text

All of it sits behind `/speckit:search`, and the kit's own context writer handles continuity. Retrieval is lexical now (exact word matching), and a miss is a clean no-hit rather than a degraded guess.

---

## The Runtime's New Home

#### The Runtime Renamed and Nested

The surviving package no longer carries an identity it lost. Its engine lives at `.skilled/skills/system-spec-kit/runtime/cli/`:

- `spec/validate.sh`, `spec/create.sh`, `spec/repair-derived.cjs` and `spec/recommend-level.sh` for the packet lifecycle
- `continuity/` for saves
- `spec-folder/` for generated metadata
- `retrieval/` for the trigger index

**Breaking:** The old `scripts/` and `mcp-server/` paths are gone, so anything you pinned to them needs repointing. A shared package underneath carries the Gate-3 classifier and the frontmatter parser that every other skill now imports rather than copies.

---

## The Completion Gate

#### A Gate That Tells the Truth

The gate that decides whether a packet may close now returns the same verdict whatever the environment, counts one fault once, and no longer asks a packet for what it cannot satisfy from inside itself. Forty rules are registered, and a warning is advice that does not fail a run.

It grew two checks of its own. Scope adherence refuses a packet whose changed files fall outside what its spec names, driven by `SYSTEM_SCOPE_CHANGED_FILES` and `SYSTEM_SCOPE_BASE`. Acceptance coverage runs on by default as an advisory.

Two documents joined the packet contract. `acceptance-criteria.md` decides closure at Levels 2 and 3, and an optional `goal.md` holds the durable directive you set as the session objective. A repair tool fixes the facts a packet records wrongly but a machine can recompute, such as its folder, level and generated fingerprints. It refuses to invent the facts only a person can write.

---

## Smaller Templates

#### Same Output at Every Level

The spec, plan, tasks and implementation-summary templates were consolidated into one shared core with level-gated addenda. The template source dropped to 1,275 lines across four core templates without changing a single rendered byte, and the research template shrinks by level too.

A Level 1 spec now gets a short research doc instead of the full one, and a Level 1 research doc renders at 175 lines instead of 944. You see smaller, level-appropriate templates. What they produce is identical.
