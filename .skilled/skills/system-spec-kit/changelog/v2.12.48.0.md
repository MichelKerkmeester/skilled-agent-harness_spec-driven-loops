# v2.12.48.0, the path and count recipes take the file limit

`rg-wrapper.mjs` accepted `--limit` on every recipe and applied it only to `structured`. The path-only and count recipes now apply it too and say what they left out.

> Spec folder: `specs/hooks-plugins-extensions/retrieval-integrations/001-sweet-search-integration/008-routing-and-release-alignment`

&nbsp;

## What's New at a Glance

- **`path` and `count` cut at `--limit`.** The default is 20 files and `--limit 0` lists every file, the same as `structured`.
- **Both lists have a fixed order.** Paths sort by name and counts by busiest file first. Ripgrep's own order changes between runs, so a cut used to keep different files each time.
- **The cut is reported.** The human view ends with `+N more files`, and the count recipe adds `with M matches`. The path view used to print 20 paths and drop the rest without a word.
- **The count view lists its files.** It printed one total line. It now prints each shown file with its count.
- **JSON moves to `schemaVersion: 3`.** Both recipes fill `fileCount`, `limit`, `truncated` and `hidden`. The count recipe also fills `matchCount`. The path-only recipe stops at one match per file, so its `hidden.matches` is `null`.
- **The retrofit baseline still counts files.** It reads `fileCount` for these two recipes, so the cut does not change its numbers.

&nbsp;

## Upgrade

If you read `paths` or `counts` from wrapper JSON and need every file, pass `--limit 0` or read `fileCount`.
