# v2.12.31.0, The Trigger Index and a Plan-Only Save Say What They Did

Two commands did something different from what a caller would expect and stayed quiet about it. Run from a project that links the Skilled source, the trigger-index generator indexed the source checkout instead of the project. A save without `--full-auto` refreshed the folder metadata and skipped the continuity fields, but said so only when the payload carried those fields. Both now say what they did.

> Spec folders: `specs/sk-code/018-frontend-upstream-proposals/005-inferred-confirmations` and `006-open-items-and-alignment` (Level 2)

&nbsp;

## What's New at a Glance

- **The trigger index names the root it indexes.** When no `--repo-root` is passed and the caller's git root differs from the generator's own checkout, `generate-trigger-index.mjs` prints one stderr line naming both roots and the `--repo-root` and `--out` flags. The default root, stdout and exit codes are unchanged.
- **A plan-only save names its skip.** Every save that is not `--full-auto` ends its summary with `Continuity fields not written: plan-only save; pass --full-auto to write them`. Exit codes and written files are unchanged.

&nbsp;

## Upgrade

No migration required. A linked project that wants its own index passes `--repo-root .`, and `--out <path>` to leave the shared index untouched.
