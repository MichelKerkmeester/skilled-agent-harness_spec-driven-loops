# v2.8.2.0, The Setup Check Names a Stale Advisor

`/doctor:setup` treated every advisor exit 75 as a harmless SKIP, but the advisor also exits 75 when its build is stale, which is the moment every prompt's routing breaks. The advisor check now tells those cases apart.

> Spec folder: `specs/system-skill-advisor/035-doctor-command-routing` (Level 2)

&nbsp;

## What's New at a Glance

- **A stale advisor build fails.** The advisor check reports FAIL and names the build command, instead of a SKIP that reads as healthy.
- **The other advisor states are named.** A stopped daemon is SKIP and a skill graph that is not live is DEGRADED.
- **A crashed sk-git check is ERROR.** It is no longer reported as an ordinary FAIL, and on Hermes the sk-git check now runs with `--tool=hermes`.
- **The docs give working commands.** Every `advisor_status` example passes `--workspace-root`, and the README Quick Start and spec-kit docs list `/doctor:setup`.
- **Commands put the input gate in one place.** `/deep:research`, `/deep:review`, `/deep:ai-council` and `/prompt:improve` now bind their input before section 1, like every other command.

&nbsp;

## Upgrade

No migration required. Rebuild the advisor runtime, then rerun `/doctor:setup`.
