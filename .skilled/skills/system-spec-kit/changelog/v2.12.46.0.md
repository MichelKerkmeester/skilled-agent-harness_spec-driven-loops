# v2.12.46.0, the sweep fails a track that mixes packets and sub-tracks

After ten tracks were regrouped into sub-tracks, two of them still held one flat packet beside their sub-tracks. Every check passed, because the children lists were correct. The sweep now reports that layout.

> Spec folder: `specs/system-speckit/spec-folder-tooling/002-named-subtracks-and-host-repos/010-mixed-track-sweep-guard`

&nbsp;

## What's New at a Glance

- **A mixed track is reported.** `sweep-track-roots.mjs` prints `flat packets beside sub-tracks:` with the packet names under a track that holds both, then exits 1. It does so in the working tree and with `--rev`.
- **Refreshing does not clear it.** The children list of a mixed track can be correct, so `refresh-track-roots.mjs --apply` changes nothing. Each flat packet moves into a sub-track.
- **Only top-level tracks are checked.** A sub-track holds packets alone, and a track with no sub-tracks stays flat as before.
- **A host repository may start failing.** A repository that vendors this sweep and keeps flat packets beside sub-tracks now gets exit 1 until those packets move.
