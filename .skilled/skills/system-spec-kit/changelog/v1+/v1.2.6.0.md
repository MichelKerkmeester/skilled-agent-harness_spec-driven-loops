This release carries out deep analysis and remediation across the whole project, improving memory-conflict reliability and aligning its schema, gate guidance and project naming. It also updates the instructions and release notes that guide the workflow.

## Why This Release

The release focuses on making instructions and release notes easier for non-developers to follow. The goal is to make the workflow easier to follow and trust.

---

## What's New at a Glance

- **Three critical bugs are fixed.** These fixes make the system more dependable.
- **Migration v12 updates `memory_conflicts`.** The schema moves from version 11 to version 12.
- **Memory-conflict handling is more reliable.** A `CREATE_LINKED` database constraint was added. Silent errors now produce logs.
- **Gate numbering is standardized.** The guidance follows the AGENTS sequence and removes older gate references.
- **Project naming changes.** `CLAUDE` is replaced with `AGENTS`.
- **Skill references and capability lists are refreshed.** The updated guidance corrects references and adds missing commands and scripts.
- **The Skill advisor, context server and access tracker are updated.** The advisor adds memory/context intent support and debug disambiguation, while the server and tracker change shutdown behavior.

---

## Memory Schema

#### One Conflict Schema

The vector index, `create_schema()` and prediction error gate used incompatible column names for `memory_conflicts`. They were unified in a 14-column schema applied with DROP+CREATE. The schema migration test now uses the v12 column names. README schema references were also updated.

&nbsp;

#### Conflict Writes Fail Clearly

A `CREATE_LINKED` database constraint was added to the `memory_conflicts` CHECK constraint in the migration v4 schema and `create_schema()`. `Ensure_conflicts_table()` became a no-op in the prediction error gate. Silent try/catch was replaced with `console.error()` logging. Both INSERT paths now use `similarity` instead of `Similarity_score` and `reason` instead of `notes`. These changes reduce confusing failures and make the system more dependable.

---

## Workflow Guidance

#### Gate Guidance Matches

Gate enforcement now maps Gate 1 to Understanding, Gate 2 to Skill Routing and Gate 3 to Spec Folder. Stale Gate 4/5/6 references were removed. The legacy install guide changed from seven gates to three gates plus three behavioral rules. Decision format and epistemic vectors received gate-number corrections.

&nbsp;

#### Project Naming Matches AGENTS

Fifty-nine files were updated with about 218 replacements from CLAUDE to AGENTS. This standardizes the naming used across the project.

---

## Skill References

#### References and Lists Align

Five section references were fixed. Template file counts were standardized across speckit, SKILL and README. The Capability Scan gained 4 missing commands and 3 scripts. SKILL's Key Scripts table gained 3 scripts.

&nbsp;

#### A Complete Tool Architecture

The speckit tool layers were rewritten from the wrong 5-layer structure to a 7-layer, 22-tool architecture. References to `memory_drift_context` and `memory_drift_learn` were removed.

---

## Runtime Behavior

#### Intent Support and Shutdown

The Skill advisor's memory/context intent boost passes the 0.8 threshold. Debug disambiguation was added. In the context server, `toolCache.shutdown()` was added for shutdown signal, termination signal and `uncaughtException`. The access tracker no longer has duplicate shutdown signal and termination signal handlers.
