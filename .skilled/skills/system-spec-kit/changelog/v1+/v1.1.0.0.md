This release is a major upgrade to the cognitive memory system. It brings FSRS power-law decay, Prediction Error Gating to prevent duplicates and 30 bug fixes from a comprehensive 10-agent audit.

The memory commands also align with the template standards. The release focuses on fixing important problems and explaining the results in clearer terms.

## Why This Release

The goal is to make the workflow easier to follow and easier to trust.

## What's New at a Glance

- **Memory decay follows the FSRS power law.** It replaces arbitrary exponential decay and is validated on 100M+ users.
- **Prediction Error Gating prevents duplicate memories.** It adds duplicate detection and conflict resolution.
- **Memories move through five states.** Each memory is HOT, WARM, COLD, DORMANT or ARCHIVED.
- **Composite scoring now weighs retrievability.** Similarity counts for less than before.
- **Three critical (P0) bugs are fixed.** The FSRS function now executes and two pairs of tiers no longer share a threshold.
- **The remaining fixes cover P1 to P3.** They guard against data loss, ReDoS, NaN values and partial transaction commits.
- **Memory commands follow the template standards.** The checkpoint, database, save and search commands get section and emoji fixes.

## Cognitive Memory

#### Power-Law Decay and the Testing Effect

The decay formula is `R(t,S) = (1 + (19/81) * t/S)^(-0.5)`, implemented in `fsrs-scheduler.js`. Attention decay in the MCP server integrates the FSRS decay functions.

Under the Testing Effect, accessing a memory strengthens its stability through a desirable difficulty bonus.

&nbsp;

#### Duplicates Stopped at the Gate

Prediction Error Gating uses four thresholds: `DUPLICATE` at 0.95, `HIGH_MATCH` at 0.90, `MEDIUM_MATCH` at 0.70 and `LOW_MATCH` at 0.50. The gate is implemented in `prediction-error-gate.js`.

&nbsp;

#### Five States From HOT to ARCHIVED

The tier classifier is extended from a 3-state model to a 5-state model. The thresholds are HOT at 0.8 or above, WARM from 0.25 to 0.8, COLD from 0.05 to 0.25, DORMANT from 0.02 to 0.05 and ARCHIVED below 0.02.

&nbsp;

#### Composite Scoring and Schema v4

Composite scoring adds a retrievability weight of 0.15 and lowers the similarity weight from 0.30 to 0.25. Schema v4 adds the `stability`, `difficulty`, `last_review` and `review_count` columns plus a `memory_conflicts` table.

## Memory Reliability

The fixes are ranked by priority, from critical (P0) to low (P3).

#### Critical Fixes for FSRS and Thresholds

The FSRS function never executed because of a signature mismatch in the tier classifier, which is now fixed (BUG-001). `MEDIUM_MATCH` equaled `LOW_MATCH`, so `LOW_MATCH` changed to 0.50 (BUG-002). The COLD and DORMANT thresholds were equal, so DORMANT changed to 0.02 (BUG-003).

&nbsp;

#### Safer Restores, Parsing and Error Handling

Eight high-priority (P1) bugs are fixed:

- **Cache methods.** `LRUCache` gains the `keys()` and `delete()` methods it was missing (BUG-004).
- **Database checks.** The delete and update handlers now await their database check (BUG-005).
- **Promise rejections.** `reinforce_existing_memory` is wrapped in try/catch, so its promise rejection is no longer unhandled (BUG-006).
- **Missing timestamps.** With no timestamps, an early return with a 0.5 default stops NaN from propagating (BUG-007).
- **Checkpoint restores.** A SAVEPOINT/ROLLBACK pattern in checkpoints prevents data loss when a restore fails (BUG-008).
- **YAML parsing.** The memory parser reads YAML line by line instead of through a regex exposed to ReDoS (BUG-009).
- **Trigger patterns.** Bounded greedy quantifiers in the trigger extractor remove ReDoS from trigger patterns (BUG-010).
- **Delete errors.** Delete errors are no longer silent and are logged with `console.warn` (BUG-011).

&nbsp;

#### Steadier Caches, Scores and Transactions

Nine medium-priority (P2) bugs are fixed:

- **Cache loading.** A loading flag with try/finally prevents a cache thundering herd (BUG-012).
- **Tier weights.** Inconsistent tier weights are centralized in importance tiers (BUG-013).
- **Environment variables.** `isNaN()` validation in working memory stops env vars from producing NaN (BUG-014).
- **Negative scores.** Co-activation clamps scores with `Math.max(0, score)` (BUG-015).
- **Partial commits.** A transaction tracks failures and rolls back everything instead of committing part of its work (BUG-016).
- **Token metrics.** Token metrics were taken in the wrong order and are now captured before reassignment (BUG-017).
- **Undo.** Undo now checks its result by verifying `changes > 0` in history (BUG-018).
- **Migrations.** A `database.transaction()` wrapper makes migration transactional (BUG-019).
- **UTF-16 BE.** Manual byte-swap conversion adds support for UTF-16 BE (BUG-020).

Ten low-priority (P3) fixes, BUG-021 through BUG-030, cover input validation, error sanitization, Unicode boundaries, symlink detection and division guards.
