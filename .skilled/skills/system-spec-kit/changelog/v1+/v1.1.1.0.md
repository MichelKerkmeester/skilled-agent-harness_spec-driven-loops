This release fixes the 29 additional issues. A quality audit of the earlier 121-issue code review found them. One was a blocker that risked data loss. 17 were required fixes. 11 were improvements. Eighteen GPT-5.4 Codex CLI agents made the fixes in parallel.

The fixes reach checkpoint restore, search, saving, indexing, duplicate detection, caching and five spec documents. Several replace copied code with shared helpers. Others stop blank IDs and failures from passing silently.

## Why This Release

The goal is to make the workflow easier to trust in everyday use.

## What's New at a Glance

- **Checkpoint restore no longer erases other tenants' data.** When Tenant A and Tenant B share a spec folder, restoring Tenant A's checkpoint leaves Tenant B's data in place.
- **Duplicate detection now pages through vector matches.** It stops once it has enough in-scope matches. It also stops when it runs out of candidates.
- **Blank and padded IDs no longer slip through.** Actor, tenant and session IDs are each checked or normalized now.
- **Two concurrent saves can no longer overwrite each other.** The spec-folder lock is now acquired before the file rename.
- **Deferred chunks keep their own index entries.** Later chunks no longer overwrite earlier ones in the active projection table.
- **Malformed anchors return an empty map instead of corrupted content.** Crossed or unclosed anchors used to produce wrong content boundaries.
- **Search no longer comes back empty when every match is over the token budget.** An empty answer no longer hides relevant results that exist.
- **The constitutional memory cache no longer leaks across database switches.** Each entry's key now includes the active database path.
- **Two cache fixes were already in place.** The graph-signal cache fix dates from Sprint 4. The embedding cache key change dates from a prior sprint.
- **Rollback errors and database rebind failures are no longer lost.** Rollback errors now surface in warning and error responses for debugging.
- **Shared helpers replace three sets of duplicated code.** The `memory_conflicts` DDL, the fallback ladder and lineage row loading each live in one place now.
- **Five spec documents match the codebase again.** Seven required (P1) documentation fixes corrected claims that had drifted from the code.

## Tenant Safety

#### Restores Stay Inside the Caller's Scope

A checkpoint can be created for a specific spec folder. Restoring it deleted all data matching that folder. It did this whichever tenant, user or agent owned the data. The clear-before-restore path had the same flaw. So did the merge-restore path.

Checkpoint restore now intersects the `spec_folder` filter with the caller's tenant, user, agent and shared-space scope. The clear path adds scope predicates alongside the folder predicate. An unscoped restore still works folder-wide. Merge mode respects scope boundaries.

&nbsp;

#### Duplicate Detection Pages Past Other Tenants

The pre-existing duplicate detector (PE gating) fetched the top N*3 vector matches. It then filtered by governance scope. In a noisy multi-tenant database, all of those top matches could belong to other tenants. So the system could miss the real in-scope duplicate. The new paging loop widens the window from N*3 to N*6 to N*12 and onward.

&nbsp;

#### Blank and Padded IDs Are Handled

The shared-memory handler trusts actor identity from tool arguments. Full server-bound authentication is out of scope for this MCP server architecture. But blank or whitespace-only actor IDs were silently accepted. That made impersonation trivially easy. Input validation now rejects empty or whitespace actor IDs with a structured error. A code comment documents the trust boundary. It recommends authenticated transport middleware for untrusted environments.

`validateCheckpointScope` now trims `tenantId`. It rejects an empty string when any actor or shared-space field is present. `handleGetLearningHistory` now normalizes the `sessionId` before querying. That matches the write-side behavior. It prevents misses when a caller passes a padded session ID.

## Saving and Indexing

#### Saves Take the Lock Before Renaming

The atomic save function renamed a pending file to its final path. It did this before it acquired the spec-folder mutex. A second concurrent save could run in that gap. It could rename its own pending file to the same path. That let one save silently overwrite the other. The rename and the database mutation now happen inside the same critical section. Rollback stays within the locked section too.

&nbsp;

#### Deferred Chunks Keep Their Anchors

A large document is split into chunks. Some chunks are deferred for later processing. The deferred path omitted the anchor identity. All deferred children shared a null-anchor key. The deferred path now passes `anchorId: chunk.label` to `indexMemoryDeferred`. That matches the embedded (immediate) path.

&nbsp;

#### Anchor Extraction Validates First

The anchor extraction function (regex-based) and the anchor validation function (stack-based) were independent. Validation flagged a malformed document as invalid. Extraction still processed it. The extract anchors helper now calls the validate anchors helper first. It stops when validation detects structural errors.

## Search and Caching

#### A Top Result Survives the Token Budget

The token-budget truncation function uses a greedy loop to fit results within the allowed size. When every candidate exceeded the budget, the loop accepted zero results. It returned an empty array. Now, when the loop accepts zero results but candidates exist, the system keeps the highest-ranked candidate with overflow metadata. That matches the existing single-result fallback pattern.

&nbsp;

#### Caches Follow the Active Database

The constitutional memory cache keyed its entries only on `spec_folder` and `includeArchived`. A switch to a different database can happen through `set_active_database_connection`. After that, cached results from the old database could appear in queries against the new one. The entire cache now clears when the active connection changes.

&nbsp;

#### Graph-Signal and Embedding Caches

The quality audit flagged three files. They change causal edges directly without clearing the graph-signal cache. Investigation showed the fix was already implemented across all three mutation paths. Those paths are vector-index-mutations, corrections and graph-lifecycle. No additional code changes were needed.

The embedding cache primary key now includes dimensions. Two dimension variants for the same content and model can now coexist. Neither overwrites the other.

## Code Health

#### Failures Leave Structured Detail

Rollback and cleanup catch blocks used to reduce the original error to a boolean. They now preserve it as structured metadata (`rollbackError` and `pendingCleanupError`). The listener path in `db-state.ts` now checks the boolean that `rebindDatabaseConsumers` returns. It logs an error when that boolean is false. It no longer silently discards the result.

&nbsp;

#### One Definition for the Conflicts Table

The `memory_conflicts` table DDL and its companion indexes were defined identically in three places. Those places are the helper function, migration v4 and bootstrap. Changes to the table shape required updating all three in lockstep. Bootstrap and migration v4 now call the shared create memory conflicts table helper. They also call the create memory conflict indexes helper. They no longer inline the DDL.

&nbsp;

#### One Fallback Plan for Search

The fallback ladder was implemented identically in two helpers. It holds threshold constants, channel overrides and retry markers. The two helpers are the search with fallback helper and the collect raw candidates helper. Changes to fallback behavior required updating both in lockstep. A shared execute fallback plan helper now encapsulates the threshold constants, channel overrides and retry tagging. Both callers consume staged results. Each decides its own post-processing.

&nbsp;

#### One Loader for Lineage Rows

Lineage row loading now goes through a shared load run history rows for memory helper. `inspectLineageChain`, `summarizeLineageInspection` and the active and as-of resolution functions all reuse it. That reduces code duplication.
