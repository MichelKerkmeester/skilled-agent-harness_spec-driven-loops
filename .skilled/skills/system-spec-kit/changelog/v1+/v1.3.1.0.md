# v1.3.1.0, Session, Wave and Optimizer Fixes

This patch release fixes session isolation problems in the review-improvement bundle.

- Coverage-graph reads now enforce session scope.
- Cross-session aggregation requires explicit admin scope.
- Non-admin reads require `sessionId`.

It also fixes wave-state and optimizer-boundary problems there.

- Optimizer output and search stay within declared limits.
- Corpus helpers no longer hide integrity failures.
- Hotspot scoring now blocks false positives.

It aligns board merging, replay metrics and coverage-graph behavior.

- Board merging and replay metrics now use consistent contracts.
- Finding identity and replay metric shape are aligned.
- Coverage-graph session normalization is centralized.

&nbsp;

## Why This Release

These changes make day-to-day use safer and more predictable. The release scope does not change.

## Session and Optimizer Safety

Coverage-graph reads now enforce session scope. Optimizer output and search stay within declared limits.

#### Coverage Queries Stay Session-Bound <a id="c-coverage-queries-stay-session-bound"></a>

- Coverage-gap, unresolved-finding and contradiction queries used bare IDs in subqueries.
- So records from another session could satisfy them.
- The queries now apply the full `spec_folder`, `loop_type` and `session_id` identity.
- They do this in their `NOT EXISTS` subqueries and contradiction joins.
- Read tools allowed cross-session aggregation without explicit admin scope.
- Non-admin reads now require `sessionId`.
- A shared query helper applies the same scope everywhere.
- `coverage-graph-signals.ts` carries it through nested edge lookups.

#### Optimizer Changes Stay Bounded <a id="c-optimizer-changes-stay-bounded"></a>

- The promotion-report save path could write to arbitrary repository locations.
- Promotion output is now limited to a dedicated audit directory. It rejects symlinks.
- Config search accepted out-of-bounds changes and changes to locked fields.
- The evaluator now requires a manifest.
- It takes the search space from that manifest. It rejects unknown or locked fields.
- Corpus helpers hid integrity failures.
- They now fail loudly when integrity checks break.

&nbsp;

## Wave Behavior

Hotspot scoring and wave transitions now block false positives and illegal jumps.

#### Hotspots Need Composite Evidence <a id="c-hotspots-need-composite-evidence"></a>

- The hotspot spread calculation treated every directory at median complexity as a hotspot.
- That produced false waves in otherwise uniform inventories.
- Hotspots now need a composite score strictly above baseline.
- That score includes churn and issues.
- It is not `complexity >= median` alone.

#### Research Domains Cluster Correctly <a id="c-research-domains-cluster-correctly"></a>

- Cluster assignment relied on the TLD.
- That grouped unrelated research domains together.
- Fallback clusters now use a registrable-domain or topic-based rule.

#### Wave Phases Follow Required Order <a id="c-wave-phases-follow-required-order"></a>

- Phase advancement enforced forward progress.
- But it allowed jumps straight to merge, skipping required phases.
- An allowed-transition matrix now restricts the phase order.
- Non-adjacent jumps need an explicit audited API.

## Board and Replay

Board merging and replay metrics now use consistent contracts.

#### Finding Merges Keep Their Identity <a id="c-finding-merges-keep-their-identity"></a>

- Deduplicating by `findingId` alone collapsed distinct segment findings.
- Storage and replay now use `(sessionId, generation, segment, wave, findingId)` as the full composite key.

#### One Merge Path Preserves Provenance <a id="c-one-merge-path-preserves-provenance"></a>

- Lifecycle, board and segment-state each implemented merge and provenance rules differently.
- The board module now owns a shared merge path.
- Lifecycle and segment-state call it instead of carrying separate versions.

#### Board Status Follows Lifecycle <a id="c-board-status-follows-lifecycle"></a>

- The board transition API existed.
- But the main board did not advance its own status.
- `updateBoard()` now routes lifecycle updates through `transitionBoardStatus()`.
- That lets the board advance its own status.

#### Replay Metrics Match <a id="c-replay-metrics-match"></a>

- Corpus extraction and the runner expected different replay metric shapes.
- The corpus builder now emits the shape the replay runner expects.

&nbsp;

## Coverage Graph

Coverage-graph session normalization is centralized.

#### Session Scope Reaches Auto-Created Nodes <a id="c-session-scope-reaches-auto-created-nodes"></a>

- Session handling in `coverage-graph-core.cjs` now uses a shared normalization helper.
- Auto-created nodes propagate `metadata.sessionId`.

#### Edge Activity Has One Name <a id="c-edge-activity-has-one-name"></a>

- The helper was called `computeMomentum`.
- It is now called `computeRecentEdgeActivity` in `coverage-graph-signals.cjs`.
- The compatibility alias was removed.
- The TypeScript export adds a `sessionId` parameter.

#### Graph Rules Match Their Contracts <a id="c-graph-rules-match-their-contracts"></a>

- Cycle handling in `coverage-graph-signals.cjs` skipped the documented fallback for cyclic components.
- It now uses that fallback.
- `coverage-graph-session.cjs` rejects mixed-session edges without explicit `edge.sessionId` or documents the precedence rule.
