This major release implements SpecKit Reimagined. It spans 33 features and 107 tasks across five workstreams, and it adds 5 new memory commands.

The workstreams are session management (W-S), search and retrieval (W-R), decay and scoring (W-D), the causal memory graph (W-G) and infrastructure (W-I). Alongside them come MCP tool changes, four database schema versions and updates to templates, commands and YAML workflow assets.

> Spec folder: `specs/003-memory-and-spec-kit/082-speckit-reimagined/`

## Why This Release

The release adds session deduplication, a causal memory graph, intent-aware retrieval, BM25 (exact word matching) hybrid search and comprehensive crash recovery.

## What's New at a Glance

- **Sessions stop resurfacing the same memories.** Session deduplication brings 50% token savings.
- **Interrupted sessions come back after a crash.** Crash recovery generates a CONTINUE SESSION automatically.
- **Search adds BM25 (exact word matching) hybrid search.** A pure JavaScript BM25 gives search a lexical fallback.
- **Retrieval is intent-aware across 5 intent types.** Cross-encoder reranking and fuzzy matching join the retrieval path.
- **Memory decay becomes type-specific and multi-factor.** Nine memory types have their own half-lives with distinct decay rates.
- **A causal memory graph links memories.** Six relationship types describe how one memory connects to another.
- **The system learns from corrections.** Stability penalties and boosts apply to replacements.
- **Errors carry recovery hints.** A catalog of 49 error codes gives actionable recovery guidance.
- **Embedding failures degrade gracefully through deferred indexing.** A fallback chain runs from the primary API to local to BM25-only.
- **Tool responses share a standardized envelope.** Responses follow the `{summary, data, hints, meta}` structure.
- **Five new memory commands arrive.** `/memory:continue`, `/memory:context`, `/memory:why`, `/memory:correct` and `/memory:learn` join the command set.
- **Existing commands and workflows are updated.** All 9 memory commands, all 7 spec_kit commands and 12 YAML workflow assets change.

## Sessions and Crash Recovery

#### Sessions That Remember and Recover

Session deduplication relies on hash-based tracking. Crash recovery rests on a session_state table. The SessionStateManager API adds resetInterruptedSessions() and recoverState(), and recoverState() comes with a `_recovered` flag.

---

## Search and Retrieval

#### Better Ranking for Hybrid Results

RRF fusion gains a K=60 parameter and a 10% convergence bonus for multi-source results. Cross-encoder reranking works with Voyage, Cohere or local providers and applies a length penalty at a 100 character threshold.

&nbsp;

#### Retrieval That Reads Intent

The five intent types are `add_feature`, `fix_bug`, `refactor`, `security_audit` and `understand`. An intent classifier handles intent detection for them.

&nbsp;

#### Fuzzy Matching With Acronyms

Fuzzy matching accepts a Levenshtein distance of 2 or less and adds an `ACRONYM_MAP` with 30+ entries. The fuzzy match module for Levenshtein and acronym expansion was never implemented.

---

## Decay and Scoring

#### Decay That Weighs More Factors

Multi-factor decay adds pattern alignment and citation recency as factors. Usage boost scoring comes with enhanced 5-factor composite scoring.

&nbsp;

#### Consolidation and Automatic Archival

The consolidation pipeline covers duplicate detection and semantic merge in 5 phases. Its consolidation module was never implemented. An archival manager adds automatic archival as a background job.

---

## Causal Memory Graph

#### Memories Linked by Cause

The relationship types are `caused`, `enabled`, `supersedes`, `contradicts`, `derived_from` and `supports`. Decision lineage traces decision run history with depth-limited traversal of at most 10 hops and cycle detection.

&nbsp;

#### Learning From Corrections

Penalties are set at 0.5x and boosts at 1.2x. The memory corrections tracking module was never implemented.

---

## Infrastructure

#### Safer Keys and Pre-Flight Gates

API key validation handles keys securely and gives actionable guidance. Pre-flight quality gates run ANCHOR validation, duplicate detection and token budget checks.

&nbsp;

#### Fallbacks, Retries and Safe Transactions

The fallback chain comes with logging. The provider chain module for this embedding fallback was never implemented. Lazy model loading defers embedding initialization, and protocol abstractions give provider-agnostic embedding interfaces. Retry logic uses exponential backoff of 1s, 2s and 4s with jitter. Transaction atomicity follows SAVEPOINT/ROLLBACK patterns.

&nbsp;

#### Organized and Cached Tool Output

Tools sit in a 7-layer MCP architecture, L1 to L7, and memory context is the unified entry at L1 (orchestration). Tool output caching uses a 60s TTL with LRU eviction. Incremental indexing makes diff updates based on content hash and mtime.

&nbsp;

#### Schema Versions V8 to V11

V8 adds the causal_edges table with 6 relation types, strength and evidence. V9 adds the memory_corrections table for stability tracking and pattern extraction. V10 adds the session_state table for crash recovery, with a dirty flag. V11 adds the is_archived and archived_at columns.

## Commands, Tools and Templates

#### Five New Memory Commands

- **`/memory:continue`** recovers a session from a crash or compaction.
- **`/memory:context`** is a unified entry with intent awareness.
- **`/memory:why`** traces decision run history through the causal graph.
- **`/memory:correct`** learns from mistakes with stability penalties.
- **`/memory:learn`** captures explicit learning of patterns, pitfalls and insights.

&nbsp;

#### MCP Tools for Causal Queries

The memory_drift_why tool traces the causal chain for "why" queries. The memory_causal_link tool creates causal relationships between memories, and memory_causal_stats gives graph statistics and coverage metrics. The memory_causal_unlink tool, which removes causal relationships, was no longer needed in its old form, and the release removes or retires it. The memory_drift_context tool (unified context with intent awareness) and the memory_drift_learn tool (capture explicit learning) were never implemented and were removed from the roadmap.

&nbsp;

#### Templates Carry the New Features

Context template v2.2 adds a CONTINUE_SESSION section, `session_dedup` metadata and `causal_links`. The Save template gains Phase 0 pre-flight validation, section 16 on session deduplication and deferred indexing. The Search template covers hybrid search architecture, intent-aware retrieval and compression tiers.

&nbsp;

#### Commands and Workflows Updated

The memory commands gain spec 082 cross-references, and the spec_kit commands pick up the Five Checks Framework. The YAML workflow assets gain context loading integration. The folder detector now gives CLI arguments priority over alignment validation, so it never overrides explicit user intent.
