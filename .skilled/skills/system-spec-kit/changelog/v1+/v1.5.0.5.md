# v1.5.0.5, A Second Door to the Same Daemon

This release gives the memory system a second door.

- It ships the dual-stack answer: `node .opencode/bin/spec-memory.cjs`.
- That is a daemon-backed CLI.
- It fronts the identical 37-tool surface over the same unchanged daemon.

The MCP registration stays exactly where it was.

- The CLI is the resilience and universal surface for hooks, cron, CI and transport-down recovery.
- It is not a replacement.

A spec packet holds the work behind this release.

- The spec packet holds research and workstreams under `001-spec-memory-cli/` through `003-skill-advisor-cli/`.
- It holds release cleanup under `004-release-and-program-cleanup/`.

&nbsp;

## Why This Release

The MCP transport has been the memory system's only door.

- It is a fragile one.
- When a transport drops mid-session, Claude Code never reconnects it.
- So the 37 tools vanish for the rest of the session.
- Every session also pays the tool-schema token overhead up front.
- Every runtime also needs its own MCP registration.

## The Spec-Memory CLI

The CLI is a second IPC client over the daemon that already existed.

#### The Daemon Was Never the Weak Point <a id="c-the-daemon-was-never-the-weak-point"></a>

- The system-spec-memory daemon was always sturdier than the path to it.
- The 026/027 launcher work made the daemon survive owner disposal, re-election and lease races.
- But a session whose MCP transport died still lost its memory tools permanently.
- That is because the client never re-establishes the transport.
- The incident class was never the daemon.
- It was the single door.

#### A Second Client, Not a New Daemon <a id="c-a-second-client-not-a-new-daemon"></a>

- Nothing about the daemon changed.
- The same handler queue serializes writes.
- The same launcher owns the lifecycle.
- `list-tools` answers offline.
- Every other command validates argv with the existing Zod schemas.
- It speaks JSON-RPC `tools/call` over the IPC socket.
- All 37 memory tools become CLI commands.
- They are generated at runtime from `TOOL_DEFINITIONS`.
- So there is no manifest to drift.
- `spec-memory list-tools --format json` returns `count: 37` straight from `TOOL_DEFINITIONS`.
- That makes surface parity against the MCP registration a one-command check.

#### One Exit Taxonomy <a id="c-one-exit-taxonomy"></a>

- The exit taxonomy is shared verbatim across all three sibling CLIs.
- `0` is success.
- `1` is a runtime error.
- `64` is a usage or schema error.
- `69` is a protocol or dist mismatch.
- `75` is a retryable daemon error.

#### Guards Before Every Dispatch <a id="c-guards-before-every-dispatch"></a>

- The shim guards before it dispatches.
- It defaults the socket directory.
- It rejects socket paths over the Darwin `sun_path` limit.
- It maps a spawn failure to exit `75`.
- So callers can retry instead of guessing.
- For the dist check, `SPECKIT_SPEC_MEMORY_CLI_DEV_ALLOW_STALE=1` is the development override.

#### Writes Drain Before Exit <a id="c-writes-drain-before-exit"></a>

- All three CLIs exit naturally with drain-awaited writes.
- That fixes a 64KB pipe-truncation hazard.

## Runtimes Reach Memory Without MCP

#### Hooks Fail Open Instead of Blocking <a id="c-hooks-fail-open-instead-of-blocking"></a>

- Claude and Codex hooks reach memory without MCP.
- They probe the socket first.
- They use the CLI when warm.
- They fail open when cold.
- Claude `session-prime`, `compact-inject` and `session-stop` and Codex `session-start` gain a shared warm-only CLI fallback helper.
- That helper, `spec-memory-cli-fallback.ts`, sits beside `code-index-cli-fallback.ts` for the sibling.
- It wraps the CLI in a socket probe plus a `--warm-only --timeout-ms` invocation.
- `--warm-only` probes the socket and exits `75` rather than cold-spawning the launcher.
- A transport-down probe costs about a millisecond.
- So prompt-time hooks fail open instead of booting a daemon from the prompt path.
- No socket means a fast fail-open return.
- A warm call measured 117 to 198 ms.
- The hook result then omits the CLI-backed extras rather than blocking the prompt.
- Cold spawn stays confined to SessionStart, explicit prewarm, cron and non-prompt maintenance.
- The one-shot native bridge, measured at 824.8 ms, stays banned from the prompt path.

#### A Plugin Bridge With No Database Imports <a id="c-a-plugin-bridge-with-no-database-imports"></a>

- OpenCode gets the new `system-spec-memory.js` plugin.
- The plugin gives OpenCode its first non-MCP route to memory.
- Its bridge uses CLI/IPC transport exclusively, with zero in-process database imports.
- So the dual-writer hazard class cannot return.
- The earlier in-process import approach was rejected.
- That is because a second process importing the database directly is a dual-writer waiting to happen.
