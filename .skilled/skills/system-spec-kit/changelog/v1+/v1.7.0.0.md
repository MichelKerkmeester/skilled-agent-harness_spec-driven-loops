# v1.7.0.0, Honest Verdicts, Earned Flags and a Search That Surfaces

v1.7 makes search more trustworthy, from the verdict down to the rows a reader receives.

- A live query returned one result, though it should have found many spec folders.
- A high similarity score alone can no longer produce a good verdict.
- The release measures result-changing flags against real data.

The release repairs generated spec records and makes code-graph history safe to read.

- Generated spec records had been hand-driftable and noisy.
- Status and lineage rules prevent drift.
- The connected graph-history path could expose closed edges in live reads.

Four dark-flag families earned graduation, and structural protections now run by default.

- Graduates keep their existing default-off flags until enabled.
- The true-citation ledger stays at refine until it clears the reranker bar.
- Unproven work was cut after measurement.

&nbsp;

## Why This Release

Similarity scores, response limits and closed graph edges could each leave a result less reliable than it appeared.

- The release checks those paths against actual queries and data.
- It keeps dark-flag graduates behind their existing default-off flags.
- The honesty suite and safety protections run by default.

## Search

Search now grounds verdicts in evidence and keeps matching folders in the response.

One live query returned one result where it should have found many spec folders.

#### Keyword Evidence Comes First <a id="c-keyword-evidence-comes-first"></a>

- A high similarity score alone can no longer produce a good verdict.
- The top result needs a matching term in its title, trigger phrases or body.
- A BM25 keyword score already on the row also counts.
- A fluent but absent term such as `kubernetes` once earned a confident citation.
- That came from a single spurious high-cosine hit.
- It now reads weak.
- The lexical-grounding floor shipped quietly earlier.
- It graduated to on for everyone this cycle.

#### Relevance Shows True Signal <a id="c-relevance-shows-true-signal"></a>

- Search subtracts a measured corpus noise floor for version 1.5 of the embedding model.
- It does that before deciding whether a match is real.
- Embedding provider drift no longer makes a marginal match look good.
- A semantic result now reports the number the system ranks on.
- That is calibrated absolute relevance on a 0-to-1 cosine scale.
- It is not the compressed RRF fusion magnitude clustering low near 0.03.
- This fixes a residual path reporting the wrong figure for semantic rows.
- Relationship and degree rows show their relevance, not a blank dash.

#### Thin Evidence Lowers Confidence <a id="c-thin-evidence-lowers-confidence"></a>

- When evidence is thin, search caps a good verdict down to weak.
- The evidence-gap warning now always agrees with the verdict.
- Both had been broken.
- The cap was wired to a signal nothing ever set.
- So it never fired.
- A known gap could surface beside a confident verdict.
- The warning was driven by a peakedness statistic.
- That statistic measured how far the top result stood above the pack.
- It was not driven by relevance.
- So a strong, tightly clustered set of good matches got the warning.
- A flat spread of weak off-topic matches slipped through clean.
- The cap is now connected.
- The warning keys off the same noise-floor-subtracted relevance the verdict uses.
- So a search for a real term such as `graph` stays quiet.
- A genuine gap is flagged once and consistently.

<summary><b>Tests and scenarios</b></summary>

- A benchmark of the old warning found false alarms on two of every three strong queries.
- The redesign brought that to zero.

</details>

#### A Guard Against Confident Hallucination <a id="c-a-guard-against-confident-hallucination"></a>

- A build gate now refuses to pass when search returns good verdicts on terms it should know nothing about.
- Six bare off-corpus queries run through the production verdict path: kubernetes, oauth, kafka, terraform, graphql and webpack.
- The gate fails if too many false confirms slip through.
- The ceiling is set at zero.
- It is the regression net under the grounding and noise-floor work above.

#### Results Keep Their Meaning <a id="c-results-keep-their-meaning"></a>

- The dashboard header count now matches the rows actually shown.
- It does not match a pre-trim total.
- A long folder path displays its leaf title.
- It is not cut off mid-string.
- A status field had reported an unrelated mechanism.
- It now reports the expected status.

#### Search Works Through Outages <a id="c-search-works-through-outages"></a>

- The embedding service can be unavailable.
- It can also return no embedding.
- Then search falls back to keyword matching.
- It marks the dense channel as skipped.
- So an outage returns the best lexical answer rather than an empty result.
- The healthy path stays unchanged.

#### Budget Trimming Keeps Answers <a id="c-budget-trimming-keeps-answers"></a>

- Tail-appended backfill rows are now exempt from the response-serialization token budget.
- So a backfill row added past the limit is not the first thing cut.
- Trimming can threaten the primary results.
- The response now reserves at least one primary row.
- It keeps a pinned constitutional rule ahead of additive backfill.
- So the squeeze can thin the result set.
- It never sacrifices the answer you asked for.

#### Multi-Hop Fills Deep Results <a id="c-multi-hop-fills-deep-results"></a>

- The deterministic multi-hop and lane-champion backfill appends were measured.
- They graduated for deep-K readers.
- They now reach readers who request deep result sets.
- Complete recall at twenty rose from just over half to almost all on labelled multi-target queries.
- Shallow rankings stayed flat.

#### Query Shape Controls Expansion <a id="c-query-shape-controls-expansion"></a>

- Every query is classified once by its retrieval shape.
- That happens before the pipeline runs.
- The five-class query classifier is on for everyone.
- Shape routing can be enabled.
- Then a single-hop lookup skips graph-relation expansion.
- A multi-hop question keeps graph-aware ranking.
- How you call search does not change.
- Shape routing stays opt-in behind `SPECKIT_RETRIEVAL_CLASS_ROUTING`, which is off by default.
- The per-class weight profiles stay opt-in too.

#### More Matching Folders Surface <a id="c-more-matching-folders-surface"></a>

- Trigger-lane matches had been excluded from surfaced results, even when they ranked.
- They now reach them.
- A display floor of ten now holds.
- Budget overflow becomes compact rows at the pipeline and envelope levels.
- It is not deleted outright.
- The folder-discovery listing also excludes `z_future` folders.
- So future-staged folders stop diluting the live result set.
- The same live `memory_search` query had returned one result.
- It now returns six, with one full row and five compact rows.

#### Valid Inputs Reach Search <a id="c-valid-inputs-reach-search"></a>

- An empty-string filter now reads as a no-op.
- It is not rejected as malformed.
- Search also accepts `retrievalLevel` instead of rejecting it.
- So either input can reach the query.

#### A Probe Shows Citation Readiness <a id="c-a-probe-shows-citation-readiness"></a>

- The true-citation emitter is sound.
- It stays at refine until real session-carrying traffic accumulates.
- This release adds a density probe.
- It surfaces through the health check.
- It reports when the ledger has accumulated enough session-scoped pairs.
- Its per-class floor and minority-ratio floor keep a lopsided ledger from graduating the reranker on a count alone.
- The probe observes without flipping anything on.

#### Citation Holds Across Models <a id="c-citation-holds-across-models"></a>

- A 144-cell benchmark drove `/memory:search` with four models.
- The models were MiMo, Kimi, DeepSeek and gpt-5.5 fast.
- It ran across twelve deliberately vague queries.
- The verdict held up where it should.
- On clearly aligned and clearly empty queries every model agreed.
- The citation rule was obeyed wherever a model emitted a full verdict.
- The divergence is on borderline queries.
- Two of the twelve split the verdict there.
- That is because each model refined the vague search differently and landed on different results.
- It is not because the verdict logic wavered.
- The benchmark also isolated the off-corpus false confidence.
- The grounding and noise-floor graduations then closed it.
- DeepSeek came out the most efficient and stable driver.
- Kimi over-explores expensively on the vaguest queries.

#### Follow-Up Fixes Hold Their Contract <a id="c-follow-up-fixes-hold-their-contract"></a>

## Spec Records

The generated `description.json` and `graph-metadata.json` files feed memory search and graph traversal.

They had been hand-driftable and noisy.

#### Statuses Stay Within Their Set <a id="c-statuses-stay-within-their-set"></a>

- Generated spec metadata now uses a closed status set, not free-form prose.
- A first-class validator checks `description.json` and `graph-metadata.json`.
- Legacy hand-edited statuses are re-derived into safe values.
- They are surfaced for review rather than left to leak through.

#### Reads Leave Files Clean <a id="c-reads-leave-files-clean"></a>

- Generated content can be unchanged.
- Then the generator skips the write, even if volatile timestamps differ.
- A targeted cache update can refresh one folder without rebuilding its neighbors.
- Access and freshness telemetry now lives in the index layer.
- It does not live in generated JSON.
- So reading or resuming no longer dirties unchanged metadata.

#### Refreshes Stay Scoped <a id="c-refreshes-stay-scoped"></a>

- The backfill tool now takes a folder argument.
- It defaults to that single folder.
- So a one-folder intent no longer quietly dirties the whole tree.
- A repository-wide run requires `--all`.
- Archived and future-staged folders stay out of the descriptions cache under one policy.
- Archive memory behavior remains intact.

#### Lineage Survives Partial Refresh <a id="c-lineage-survives-partial-refresh"></a>

- Parent and child relationships reconcile across partial rescans.
- So a valid parent survives when a subscan misses it.
- Child lists grow safely unless an operator explicitly prunes them.
- The description and causal-summary fields now derive from one shared synopsis rule.
- So they stop drifting apart.
- A drift checker re-derives them on read against a stored source-document hash.
- It reports staleness without writing anything.
- A saved source fingerprint shows freshness without rereading the document.

#### Backfill Damage Was Corrected <a id="c-backfill-damage-was-corrected"></a>

- A backfill against the wrong base path polluted eleven `description.json` files.
- It wrote incorrect `parentChain` values.
- The cleanup restored correct lineage.
- It corrected four earlier remediation claims against the real state.
- It restored four missing `children_ids` to a phase parent.

#### The Migration Settles Cleanly <a id="c-the-migration-settles-cleanly"></a>

- The whole spec tree was regenerated under the new metadata contracts.
- That is 2,049 spec folders, including archives.
- The second run produced byte-identical output with no validation violations.
- A graduation benchmark then measured every default-off flag against the migrated tree.
- Twelve flags earned their way to default-on or enforcing.
- They cover the metadata integrity gates and the search-honesty suite.

#### Pending Refreshes Stay Open <a id="c-pending-refreshes-stay-open"></a>

- The local embedding provider remains degraded.
- Its retry circuit breaker is open.
- That blocks a `parentChain` index refresh until the provider recovers.
- A `validate.sh` global-index-reconciliation preventive is deferred to a later cycle.

## Skill Advisor

Advisor lanes now report degradation instead of hiding it inside a low score.

Old projections fail closed, and fusion keeps its safety net.

#### Down Lanes Are Not Empty <a id="c-down-lanes-are-not-empty"></a>

- A scoring lane can be runtime-degraded.
- Then the advisor no longer counts it against a skill as if it had run and found no match.
- Degraded lanes leave the confidence denominator.
- A lane that ran without a match still counts.
- Advisor output and abstention explanations now name the degraded state plainly.
- They do not hide it inside a low score.

#### Old Embeddings Fail Closed <a id="c-old-embeddings-fail-closed"></a>

- The advisor records which vector model produced each semantic projection.
- It checks that against the active embedding provider on every read.
- A mismatch marks the semantic shadow lane degraded.
- The lane then follows the same lane-health rule.
- It does not quietly trust a projection built by a different model.
- Legacy projections without a model signature now fail closed.
- They are not assumed safe.

#### Fusion Keeps Its Safety Net <a id="c-fusion-keeps-its-safety-net"></a>

- Reciprocal-rank fusion (RRF) lifted top-one by one on a widened forty-two-prompt set.
- It had no regressions and near-total deterministic agreement.
- It graduated with conflict reranking.
- That repairs a case plain fusion would otherwise break.

#### The Alias Penalty Covers Both <a id="c-the-alias-penalty-covers-both"></a>

- The separate self-recommendation guard was cut as behaviorally redundant.
- The generic explainer floor and an un-flagged penalty already did its work.
- The remaining implicit penalty was the only thing stopping the advisor from recommending itself.
- That held on an audit or explainer prompt.
- That penalty was undocumented.
- So a future refactor could have removed it without anyone noticing.
- It now carries a durable explanation.
- It had also matched only the advisor's exact id and missed its alias.
- The alias still recommended itself to the top in the default configuration.
- The penalty now matches the canonical ID set.
- So both the exact name and the alias are demoted.
- The penalty value is unchanged.
- This behavior change is not flag-gated.

## Code Graph

Code-graph reads now keep their history without corrupting live edges.

Parsers recover from hiccups, and order stays stable.

#### Parser Hiccups Can Recover <a id="c-parser-hiccups-can-recover"></a>

- A parser hiccup no longer condemns a file to permanent invisibility.
- Transient parse failures now retry up to `SPECKIT_PARSER_SKIP_LIST_MAX_RETRIES`.
- That defaults to 5.
- A successful reparse clears the skip-list entry.
- A fatal entry still skips immediately for human review.

#### Graph Order Stays Stable <a id="c-graph-order-stays-stable"></a>

- Equal-trust context edges now sort by stable content-derived keys.
- They do not sort by database return order.
- Repeating a query over the same data produces the same order across scan rebuilds.
- There is no phantom reordering in a diff.

#### Documents Join Graph Search <a id="c-documents-join-graph-search"></a>

- The documentation lane now indexes Markdown headings as graph symbols.
- It also indexes JSON, JSONC, YAML and TOML config keys.
- All of that comes from local parsing, so nothing leaves your machine.
- Config indexing runs by default.
- Markdown extraction is opt-in through globs.

#### Generation Shows Freshness <a id="c-generation-shows-freshness"></a>

- Each promoted scan advances a generation number that only increases.
- Freshness envelopes expose it as `metadata.freshness.generation`.
- Failed promotions and no-op scans leave the number unchanged.
- Reads continue serving the generation that is present, even when it is stale.
- A hard gate rejecting stale-generation reads remains deferred.

#### Reparse Cost Has a Bound <a id="c-reparse-cost-has-a-bound"></a>

- The reverse-dependency degree cap decides how many importers get re-bound.
- That happens when a high-fan-in dependency is renamed.
- Before this release it defaulted to uncapped.
- So renaming a thirty-importer module re-parsed all thirty.
- It now defaults to fifteen.
- That fully repairs the common-to-moderate refactor at negligible cost.
- It also bounds the unmeasured hundred-plus-importer tail.
- The cap is read only inside the force-parse branch, which is off by default.
- A high-fan-in rename above the cap leaves overflow importer edges stale.
- They stay stale until each importer is next edited.

<details>
<summary><b>What it costs</b></summary>

- A cost sweep found rebinding grew linearly.
- It ran at about a third of a millisecond to under a millisecond per importer over a seventeen-millisecond scan floor.

</details>

#### Historical Queries Return Past State <a id="c-historical-queries-return-past-state"></a>

- The first wiring left the as-of reader with no caller.
- So the feature was held out of scope.
- It was not claimed as done.
- Code-graph queries now accept an optional as-of generation.
- So a historical read can include edges to nodes deleted since that generation.
- A query without the parameter returns the current graph exactly as before.
- The history surface stays byte-identical while its flag is off.

#### Live Reads Keep Current Edges <a id="c-live-reads-keep-current-edges"></a>

- The bitemporal close-and-insert writer was built but never wired into the reindex path.
- So it was held at refine.
- The production-readiness pass wired it in.
- Before the fix, turning its flag on would have corrupted every live read.
- The live edge readers had no filter for closed edges.
- So after a reindex they returned both the superseded edge and its replacement.
- The full-scan prune deleted dangling edges regardless of the flag.
- Node replacement deleted a symbol's edges before the close path could run.
- So an as-of query came back empty.
- History can be enabled.
- Then node replacement and full-scan pruning close old edges instead of deleting them.
- Live readers return only current edges.
- A generation-stamp correction gives every superseded edge a real readable window.
- It is not a zero-width one.

## Deep Loop and Release Decisions

The deep-research and deep-review loops are the multi-iteration `/deep:*` workflows.

They fan work out across parallel model workers. They gained determinism, recovery and observability fixes.

#### New Runs Can Reduce State <a id="c-new-runs-can-reduce-state"></a>

- A brand-new deep-research run no longer crashes on its first pass.
- The strategy template now includes the anchors where carried-forward state is written.
- A fresh deep-research run has somewhere to land its first reduction.
- It can carry state into the next pass.

#### Parallel Results Merge Consistently <a id="c-parallel-results-merge-consistently"></a>

- Research and review registries now sort lineage labels and worker identity.
- They do this before merging parallel results.
- The combined output no longer depends on which worker finishes first.

#### Stops Need Outside Evidence <a id="c-stops-need-outside-evidence"></a>

- Deep-research can accept a STOP for lack of new ground.
- Before that, it compares the run's novelty report with graph-observed changes.
- Those changes cover stored questions, findings and evidence.
- It blocks a stop the graph cannot support.

#### Conflicts Remain Visible <a id="c-conflicts-remain-visible"></a>

- Workers can return the same finding ID with different content.
- Then the merge keeps both as conflicting variants.
- It does not let the first arrival erase the other.
- A person can review the actual disagreement.

#### Retries Keep Their Budget <a id="c-retries-keep-their-budget"></a>

- Fan-out timeouts, exits and salvage misses are tracked as separate failure types.
- A salvage miss means recoverable output went missing.
- Only transient failures retry.
- Durable run logs preserve retry counts across crashes.

#### Recovery Shows Broken State <a id="c-recovery-shows-broken-state"></a>

- A state file can be missing or corrupt.
- Then recovery stops instead of treating the run as new.
- It also marks worker lineages that started but never reported back.
- So partial state remains visible.

#### Interrupted Runs Keep Their Work <a id="c-interrupted-runs-keep-their-work"></a>

- Live fan-outs report pending, failed and lag gauges from real run state.
- An interrupted run leaves a partial summary.
- That summary covers the work completed before it stopped.

#### Open Questions Carry Forward <a id="c-open-questions-carry-forward"></a>

- Deep-research carries unresolved questions into the next iteration without another model call.
- The reducer builds a continuity thread from the previous pass.
- It derives the next focus from those questions or the latest finding.

#### Dedup Checks the Title <a id="c-dedup-checks-the-title"></a>

- The near-duplicate finding collapse graduated on a clean benchmark.
- It was then scale-validated past its original handful of synthetic records on a larger free-text set.
- That scale test showed the dedup key ignored the finding title.
- So two distinct findings collapsed into one.
- They shared a body but differed only in their title.
- The key now applies a title-overlap gate.
- So disjoint titles stay separate.
- A true restatement still merges.
- Title-only false collapses fell from one in two to zero.
- Exact duplicates still collapse.
- Distinct-finding recall holds.

#### Lag Measures Real Stalls <a id="c-lag-measures-real-stalls"></a>

- The old lag gauge counted time since a worker was queued.
- That is queue back-pressure.
- So any healthy fan-out wider than its concurrency tripped the alarm.
- It now measures time since the last completion while work remains pending.
- That keeps healthy busy pools quiet.
- It fires once for a genuinely hung worker.
- The recommended ceiling dropped from five minutes to two.
- That is because it no longer drifts on healthy load.
- The committed default stays off.
- Turning the gauge on is the separate graduation step.

#### Graduates Keep Their Boundaries <a id="c-graduates-keep-their-boundaries"></a>

- Four of the eight dark-flag families earned graduation on the real graph and corpus.
- They are multi-hop appends, code-graph staleness repair, advisor RRF fusion and Deep Loop deduplication.
