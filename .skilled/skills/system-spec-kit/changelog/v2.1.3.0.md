# v2.1.3.0, Packet Changelogs That Parse for Any Title

A packet changelog now renders correctly whatever its spec says. The generator pasted a spec title raw inside double quotes, so a title holding a quote broke the frontmatter. It also read `$'` or `$&` in a summary as a replacement pattern, which cut the summary short and pasted template text in its place.

> Part of [Skilled v4.0.0.2](../../../changelog/skilled/v4.0.0.2.md).
>
> Spec folder: `specs/sk-doc/061-skilled-release-changelog/003-adjacent-alignment` (Level 2)

## What's New at a Glance

- **Frontmatter values are escaped.** The title, description and identity phrase are escaped for the double-quoted YAML the templates wrap them in, so a title holding `"` or `\` still parses.
- **Every value lands as written.** The template is filled in one pass, so `$&`, `$'` and placeholder text inside a value stay literal.
- **A test fails on the old renderer.** A new case renders a quoted title and a summary holding `$'`, `$&` and a placeholder, then parses the frontmatter.
- **The catalog and the playbook cover the generator.** A feature catalog entry describes it, and scenario 458 checks a real phase's identity phrase and its lookup rank.
- **The retrieval library README names every corpus root.** It lists `.skilled/changelog/skilled/` beside `specs/`, `.skilled/skills/` and `.skilled/hooks/`.

## Upgrade

No migration required. A scan of the committed packet changelogs found no damaged title or summary, so none needs regenerating.
