# v2.12.42.0, stale index fallback

Gate 1 can find spec docs written since the trigger index was built. A phrase edited inside a doc the index already lists is still only caught by a rebuild. It checks their declared phrases after an indexed lookup has no scored candidate.

> Spec folder: `specs/hooks-plugins-extensions/028-sweet-search-integration/005-stale-index-fallback`

&nbsp;

## What's New at a Glance

- **Zero-hit lookup checks docs missing from the index.** It scores declared trigger phrases in up to 500 unindexed spec docs inside a git work tree.
- **Fallback activity appears in the answer.** JSON includes `staleFallback`, and human output adds `fallback   : <files> unindexed doc(s) read, <matches> match(es)` or reports when no git work tree is available.
- **A host's index is matched against the host's tree.** When a linked project reads its host's index, the scan walks the host repository, where that index's paths live. An index outside the walked tree, such as the packaged index of a linked install, skips the scan.
- **Fallback can be disabled.** `--no-stale-fallback` or an explicit `--index` keeps the answer index-only.
