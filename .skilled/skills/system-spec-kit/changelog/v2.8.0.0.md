# v2.8.0.0, One Command to Start With the Doctors

The doctor commands each check one area, so a new user had to know which one to run first. `/doctor:setup` is the front door: it shows every doctor command and runs the setup checks that matter on a fresh clone.

> Spec folder: `specs/system-skill-advisor/035-doctor-command-routing` (Level 2)

&nbsp;

## What's New at a Glance

- **Every doctor target in one table.** `/doctor:setup` prints all 17 doctor commands and targets with what each one checks, starting with itself.
- **Five setup checks in one run.** It runs the sk-code setup, the sk-git setup, the trigger index, the runtime mirrors and the skill advisor, and gives each a PASS, FAIL or SKIP.
- **Each failure names its doctor command.** A failing check points to `/doctor:sk-code setup`, `/doctor:git setup`, `/doctor:speckit`, `/doctor:runtime-mirrors` or `/doctor:skill-advisor rebuild`. An advisor that is not running counts as SKIP, never as a failure.
- **It writes nothing.** The run is read-only, so it is safe on a fresh clone or a live checkout.

&nbsp;

## Upgrade

No migration required. Run `/doctor:setup` on a fresh clone, then run the doctor command each failing check names.
