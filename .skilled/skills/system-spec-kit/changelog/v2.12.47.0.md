# v2.12.47.0, trigger-index prompts route here and the stale fallback is leaner

A prompt about a trigger phrase or an unindexed spec document now ranks `system-spec-kit` first. A review of the retrieval code from v2.12.41.0 to v2.12.44.0 removed what no caller used.

> Spec folder: `specs/hooks-plugins-extensions/retrieval-integrations/001-sweet-search-integration/008-routing-and-release-alignment`

&nbsp;

## What's New at a Glance

- **Trigger-index prompts route here.** `intent_signals` gains `trigger index`, `trigger phrase` and `unindexed spec`. "Look up a trigger phrase already in the index" went to the doctor helper at 0.80 and now ranks `system-spec-kit` first at 0.873.
- **A duplicate signal is gone.** `spec docs` was listed twice in `intent_signals`.
- **The fallback counts what it read.** `staleFallback.files` counted a document it failed to open. It now counts only the documents it loaded.
- **A failed lookup exits 2.** A rejected promise in `lookup-trigger-index.mjs` exited 1, the code for a clean no-hit. It now prints the error and exits 2.
- **Less code in the fallback.** `findStaleFallback` no longer sorts rows the lookup sorts again. `SPEC_DOC_NAMES`, `MAX_FALLBACK_FILES` and `listUnindexedDocs` are no longer exported, because nothing outside the module used them.
- **Four tests removed.** Each one repeated another test or compared the code with itself. The fallback and wrapper suites keep every behavior they covered.
