# Sweep Abandoned Temp-Path Processes

The orphan sweeper now also clears a process the system took over. The system took it over when its parent died. The process must work inside a temp path. It must also have run long enough. A leftover test server or background job no longer sits in a temp directory for days. The sweep still leaves the helpers of a live session alone.

&nbsp;

## What's New at a Glance

- **Temp-path orphans are now swept.** A process qualifies when init adopted it and you own it. It must not be a zombie. Its command line must point into your temp dir, `/tmp/claude-<uid>/` or a worktree `.scratch-*` folder. It must have run for at least six hours. Set `ORPHAN_TEMP_PROCESS_AGE_HOURS` to move that age floor.
- **A live session keeps its own helpers.** On macOS the session tree is read with `pgrep -a`. That is because macOS `pgrep` hides its own ancestors. A sweep started inside a session would otherwise reap that session's MCP helpers. Linux keeps plain `pgrep`, where `-a` means something else.
- **Every CLI runtime keeps its helpers.** The session tree now recognises all seven runtimes the repository drives. They are claude, opencode, codex, pi, hermes, devin and cursor-agent. Before, only claude, opencode and codex sessions protected their MCP helpers.
- **A detached driver keeps the sessions it started.** A temp-path orphan is preserved with reason `drives-live-session`. That holds when it still has a live session among its descendants. A fan-out driver script running from a scratch folder is that case. Its own parent is gone while the sessions it started are still working.
- **The skill advisor never gets cut.** The shared advisor launcher retires on its own idle timeout. Its advisor server and model server stay while that launcher is their parent. A server whose launcher has already died stays sweepable.
- **An open port is not a reason to survive.** The sweeper rechecks the process shape right before it sends each signal. So a leftover fixture server still goes while it holds a TCP listener. Apps that macOS runs from AppTranslocation never match.
- **Tests stop leaving debris.** The spec-kit vitest setup now deletes its per-file temp dirs. So do the deep-loop spawn helper and the fanout research fixture. So a test run no longer gives the sweeper leftovers to remove.
- **The age floor covers every candidate.** `ORPHAN_AGE_MIN_SEC`, five minutes by default, is now a floor for every candidate. It reports the reason `younger-than-age-min`. Before, it spared only the newest instance of each class. So a younger duplicate helper could be swept.
- **A sweeper-only change now runs its tests in CI.** `.github/workflows/spec-kit-check.yml` triggers on `.skilled/scripts/**` and `.opencode/scripts/**`. So a change that touches only the sweeper still runs the sweeper tests.

&nbsp;

## Upgrade

Run the sweeper by hand and no migration is needed. To put it on a schedule, copy `.skilled/scripts/launchagents/com.skilled.orphan-sweep.plist` to `~/Library/LaunchAgents/`. Delete `--dry-run` from that copy. Then load it with `launchctl bootstrap gui/$(id -u) <plist path>`. The repository template keeps `--dry-run`. So an unedited copy only logs what it would do.

Raise `ORPHAN_TEMP_PROCESS_AGE_HOURS` above the runtime of your longest legitimate background job. Any process younger than the floor is left untouched.
