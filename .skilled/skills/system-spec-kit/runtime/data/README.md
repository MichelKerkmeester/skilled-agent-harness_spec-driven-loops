# Runtime Data: Trigger Index

## 1. OVERVIEW

`data/` holds the one generated artifact the runtime package ships: the trigger index. It is committed, so a fresh clone answers the Gate 1 lookup without a build step or a daemon. The folder is not a code module and stays limited to data that has to live beside the runtime package.

Current state:

- `trigger-index.json` is regenerated by `../cli/retrieval/generate-trigger-index.mjs` and read by `../cli/retrieval/lookup-trigger-index.mjs`.
- The generator's corpus manifest, phrase variants and diagnostics live with the generator under `../cli/retrieval/fixtures/`, not here.
- The dist-freshness table excludes this folder, so regenerating the index never marks the runtime build stale.

---

## 2. KEY FILES

| File | Responsibility |
|---|---|
| `trigger-index.json` | Author-declared `trigger_phrases` mapped to the documents that declare them; byte-identical across runs over the same tree. |

---

## 3. USAGE NOTES

- Regenerate after any `trigger_phrases` change and commit the result; two runs must hash identically.
- Do not hand-edit the index; the generator is the only writer.
- Do not place databases, logs, or large artifacts here.

### Host Repository Index

A host repository that vendors Skilled keeps its own index at `.speckit-index/trigger-index.json` in the host root. Nothing selects that file automatically: the lookup's default stays the packaged `runtime/data/trigger-index.json`, so the host passes its path with `--index`.

```bash
# generate from the host root
node .skilled/skills/system-spec-kit/runtime/cli/retrieval/generate-trigger-index.mjs \
  --repo-root . --out .speckit-index/trigger-index.json

# Gate 1 lookup against the host index
node .skilled/skills/system-spec-kit/runtime/cli/retrieval/lookup-trigger-index.mjs \
  --index .speckit-index/trigger-index.json --json -- "<prompt>"

# freshness check against the same file
node .skilled/skills/system-spec-kit/runtime/cli/retrieval/generate-trigger-index.mjs \
  --check --repo-root . --out .speckit-index/trigger-index.json
```

`--out` alone writes the corpus manifest, diagnostics and phrase variants beside the index. Regenerate it after any `trigger_phrases` change in the host's docs.
