# v2.1.17.0, The Rust References Say What Each File Settles

Each Rust reference now opens with the decision it settles. It also names the triggers that send a reader to it. The language introductions state the problem instead of naming their own sections. The section order follows the template rather than authoring history.

&nbsp;

## Why This Release

All fourteen Rust references carried one Purpose sentence. Each also carried one three-bullet When to Use. So the text meant to tell them apart read the same in every file. The language intros also repeated the Purpose directly below them. Two sections were ordered by when they were written. They were not ordered by what a reader needs first.

&nbsp;

## What's New at a Glance

- **Each Rust reference has its own orientation.** Purpose names that file's outcome. When to Use names the triggers that reach it.
- **Three language intros become hooks.** The TypeScript, JavaScript and shell references now open with the decision their rules protect.
- **SMART ROUTING is section 3.** The letter suffix is gone. The sections below shift. The quality checklist map is now at section 6.
- **The assets section names one topic.** `## 5. SUPPORTING ASSETS` replaces the old heading. That heading joined assets, other surface areas and on-demand loading with a dash.
- **Related resources come last.** The alignment reference swaps RELATED RESOURCES with the alignment authority interface.
- **Repeated evidence becomes one line.** The shell style guide names both evidence paths on one `**Evidence**` line.
- **Three overviews orient first.** Core Principle follows When to Use in the code organization, hook and naming references.

&nbsp;

## Upgrade

No action is needed. Local docs that cite the quality checklist map as section 5 should point at section 6.
