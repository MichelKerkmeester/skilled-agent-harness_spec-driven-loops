# v2.1.17.0, The Rust References Say What Each File Settles

Each Rust reference now opens with the decision it settles and the triggers that send a reader to it. The language introductions state the problem instead of naming their own sections, and the section order follows the template rather than authoring history.

> Spec folder: `specs/sk-code/018-frontend-upstream-proposals/010-reference-readability-research` (Level 2)

&nbsp;

## Why This Release

All fourteen Rust references carried one Purpose sentence and one three-bullet When to Use, so the text meant to tell them apart read the same in every file. The language intros also repeated the Purpose directly below them, and two sections were ordered by when they were written rather than by what a reader needs first.

&nbsp;

## What's New at a Glance

- **Each Rust reference has its own orientation.** Purpose names that file's outcome, and When to Use names the triggers that reach it.
- **Three language intros become hooks.** The TypeScript, JavaScript and shell references now open with the decision their rules protect.
- **SMART ROUTING is section 3.** The letter suffix is gone and the sections below shift, with the quality checklist map now at section 6.
- **The assets section names one topic.** `## 5. SUPPORTING ASSETS` replaces the heading that joined assets, other surface areas and on-demand loading with a dash.
- **Related resources come last.** The alignment reference swaps RELATED RESOURCES with the alignment authority interface.
- **Repeated evidence becomes one line.** The shell style guide names both evidence paths on one `**Evidence**` line.
- **Three overviews orient first.** Core Principle follows When to Use in the code organization, hook and naming references.

&nbsp;

## Upgrade

No action is needed. Local docs that cite the quality checklist map as section 5 should point at section 6.
