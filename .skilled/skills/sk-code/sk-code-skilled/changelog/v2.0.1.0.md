# v2.0.1.0, The Checks Follow the Hub's Current Surfaces

The framework surface's docs and checks still described a hub with more surfaces than it ships. Two surfaces were removed, the detection order changed and a CI surface joined, so the router replay and the sync guard had to catch up. This release brings them in line with the hub.

&nbsp;

## What's New at a Glance

- **The docs describe the hub as it is.** The README no longer calls this surface the hub's only one. It explains that declared surfaces are checked first and SKILLED last.
- **The router replay follows the declared order.** It reads the detection order from each surface's own declaration, so it tests the order the hub really uses.
- **The sync guard covers the CI surface.** The router-sync check now includes the CI surface in the map it compares against the hub, and its tests no longer look for the two removed surfaces.
- **Test files stop tripping the header check.** The alignment drift check exempts `.test.sh` files and TypeScript test files that sit beside their scripts.
- **Naming problems no longer block.** The naming items in the JavaScript, TypeScript and Python checklists are P1, so a misnamed identifier does not block completion.

&nbsp;

## Upgrade

Repoint any link to the universal code style guide that still names the hub's shared path. The guide now lives at `sk-code-quality/references/code-style-guide.md`. No other migration is required.
