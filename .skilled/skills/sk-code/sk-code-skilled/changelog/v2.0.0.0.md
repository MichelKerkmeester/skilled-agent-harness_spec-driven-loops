# v2.0.0.0, The Framework Surface Gets Its Own Name

This surface holds the standards for this framework's own code.

- It was called `sk-code-opencode`.
- It covers skills, agents, commands, hooks and runtime scripts for every runtime.
- It is not only for OpenCode.

The old name collided with two parts of the OpenCode runtime.

- It collided with the OpenCode runtime's own `.opencode/` folder.
- It also collided with the `cli-opencode` executor.
- A search for one kept turning up the other.

Three new names identify the surface now.

- It is now `sk-code-skilled`.
- The routing alias is `code-skilled`.
- The surface id the router reports is `SKILLED`.

What the surface does did not change.

- Nothing about what the surface does has changed.
- Only what it is called has changed.

> [!IMPORTANT]
> 1 change can break an existing setup. Read it before you update.
>
> 1. Anything matching surface id `OPENCODE` must now match `SKILLED`. [The Surface Reports SKILLED](#c-the-surface-reports-skilled)

&nbsp;

## Why This Release

A name that means two things makes routing, search and review harder than they need to be.

- The framework surface has a name of its own.
- So a reader can tell at a glance whether a reference is about the framework.
- They can also tell whether it is about the OpenCode runtime.

## Routing

Routing decides which surface handles a framework code request. Both stages now send those requests to the renamed surface.

#### Both Routing Stages Use the New Name <a id="c-both-routing-stages-use-the-new-name"></a>

- The advisor and the sk-code hub both send framework code requests to `sk-code-skilled`.
- The skill advisor rebuilt its index from the renamed hub.
- The hub's compiled route was re-minted.
- A request about framework code now resolves to `workflowMode: sk-code-skilled` at both stages.

#### The Surface Reports SKILLED <a id="c-the-surface-reports-skilled"></a>

> [!WARNING]
> Anything that matched surface id `OPENCODE` from sk-code surface detection must now match `SKILLED`.

- Surface detection, playbook scenarios and the review checklist report the new id.
- The advisor plugin's post-edit surface detection reports `SKILLED` too.

#### The OpenCode Runtime Keeps Its Names <a id="c-the-opencode-runtime-keeps-its-names"></a>

- `.opencode/`, `cli-opencode` and the `opencode` binary are unchanged.

&nbsp;

## History

Renamed records now read with the new name. A few kinds of records keep their original name.

#### The Packet Folder Moves <a id="c-the-packet-folder-moves"></a>

- The packet folder is `sk-code/sk-code-skilled/`.
- Every path, mirror and changelog link now uses it.

#### Old Records Read With the New Name <a id="c-old-records-read-with-the-new-name"></a>

- Spec docs, changelogs and archived packets were renamed as well.
- That includes the spec folders whose own names carried the old one.
- Machine logs and recorded benchmark JSON keep the name they were written with.

&nbsp;

## Upgrade Notes

These steps apply wherever you named the surface.

#### Before You Start <a id="c-before-you-start"></a>

1. Use `sk-code-skilled`, `code-skilled` and `SKILLED` wherever you named the surface.
2. Repoint paths under `.skilled/skills/sk-code/sk-code-opencode/` that now live under `.skilled/skills/sk-code/sk-code-skilled/`.
3. The changelog link is `.skilled/changelog/sk-code/code-skilled`.
