# v1.2.4.0, Example-tolerant drift guards

v1.2.4.0 lets the router-sync and doc-claims drift guards pass after an example surface is removed, and leaves their results on the full hub unchanged.

> Spec folder: `specs/sk-code/011-sk-code-poinytail-based-refinement/026-external-surface-priority-build/003-example-tolerant-drift-guards` (Level 2)

&nbsp;

## What's New at a Glance

- Router-sync check 2 reads only the surface packets present on disk, so a removed example no longer throws ENOENT.
- Router-sync check 3 skips an archived route-gold destination whose mode the leaf manifest no longer declares, and still fails a declared mode that does not resolve.
- Router-sync check 1a starts its prose scan at the first `## N. <NAME> MAP` heading in ROUTER.md instead of the Webflow map heading.
- Doc-claims `surfaces` takes the surface count from the `packetKind` `surface` modes in `mode-registry.json`, so "two surfaces" passes on a two-surface hub and a stale count fails.
