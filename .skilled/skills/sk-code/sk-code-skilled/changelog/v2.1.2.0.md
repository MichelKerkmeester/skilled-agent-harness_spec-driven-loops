# v2.1.2.0, The Surface Readers Are Tested Against Each Other

The hub reads a skill's declared surfaces in one function. The advisor plugin keeps its own copy of it. Nothing checked that the two agreed, so they could drift apart unnoticed. A new test calls both on the same inputs and fails when their labels differ.

> Spec folder: `specs/sk-code/015-quality-agnostic-gate/009-review-closeout` (Level 2)

&nbsp;

## What's New at a Glance

- **The two readers are checked together.** `declared-surfaces-parity.test.cjs` runs the hub reader and the advisor plugin's copy on the same inputs.
- **A change to one reader fails the test.** Editing one reader without the other makes the test fail, so the labels cannot drift quietly.

&nbsp;

## Upgrade

No migration required. No skill needs a change to pass the new test.
