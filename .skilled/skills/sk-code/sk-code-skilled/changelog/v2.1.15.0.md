# The Tools Read a Router in ROUTER.md

A skill can now keep its machine router in a sibling `ROUTER.md`, beside `SKILL.md`, and the sk-code tools read it from there. This release only teaches the tools to find the file, so no router has moved and every existing skill routes as it did before.

&nbsp;

## What's New at a Glance

- **One rule decides where the router lives.** The tools check `ROUTER.md` first, then `SKILL.md`, and find no router when neither document declares one. Router replay, router sync and the dead-route scan all follow that rule, so they read the same router.
- **A router declared twice is a fault.** Two declarations could disagree about the same intent, so the tools read neither. Router replay returns no routes for that skill, and the dead-route scan, run with `--check-router`, reports it.
- **The dead-route scan names the right file.** A route that points at a missing resource is reported against the document that declares it, so a broken route in `ROUTER.md` points at `ROUTER.md`.

&nbsp;

## Upgrade

No migration required. Keep each router in one document, because a skill that declares it in both `SKILL.md` and `ROUTER.md` is reported as a fault.
