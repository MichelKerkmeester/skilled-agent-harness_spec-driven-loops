# v2.1.8.0, The TODO Format Reaches Review

The review mode now asks only that a TODO says what is left, because a portable default cannot demand a ticket id that some repositories forbid in comments. This framework's own code keeps its stricter format, an owner on every TODO, by saying so in the form the review reads.

> Spec folder: `specs/sk-code/017-portable-code-modes/005-review-floor-lens-overrides` (Level 2)

&nbsp;

## What's New at a Glance

- **One override row for every SKILLED file.** The universal checklist gains a `## 7. RULE OVERRIDES` section that replaces the review TODO rule with the SKILLED format: every TODO names its owner and what is left, and carries no ticket id, which this repository's comment rules keep out of comments.
- **TODO examples carry no ticket id.** The universal, Python and shell checklists and the Python and shell quality standards now ask for an owner and what is left, and every example reads `TODO(owner)`. The old ticket examples broke this repository's own rule against ticket ids in comments.
- **Review handoffs point at the row.** The Python and shell review handoff sections now say the review reads its rules through the quality runner and name the one lens rule this surface changes, and they keep their language guidance.
