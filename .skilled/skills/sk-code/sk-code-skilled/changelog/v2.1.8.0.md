# v2.1.8.0, The TODO Format Reaches Review

The review mode now asks only that a TODO says what is left. That is because a portable default cannot demand a ticket id that some repositories forbid in comments. This framework's own code keeps its stricter format. Every TODO names an owner. It says so in the form the review reads.

&nbsp;

## What's New at a Glance

- **One override row for every SKILLED file.** The universal checklist gains a `## 7. RULE OVERRIDES` section. That section replaces the review TODO rule with the SKILLED format. Every TODO names its owner and what is left. It carries no ticket id. That is because this repository's comment rules keep ticket ids out of comments.
- **TODO examples carry no ticket id.** The universal, Python and shell checklists now ask for an owner and what is left. So do the Python and shell quality standards. Every example reads `TODO(owner)`. The old ticket examples broke this repository's own rule against ticket ids in comments.
- **Review handoffs point at the row.** The Python and shell review handoff sections now say the review reads its rules through the quality runner. They name the one lens rule this surface changes. They keep their language guidance.
