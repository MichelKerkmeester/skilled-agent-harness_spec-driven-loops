# v2.1.1.0, The Doc-Claims Reason Names the Real Readers

The doc-claims check allowed the run envelope schema id through an allowlist whose reason named no reader of it. It now names the two readers, and a new test holds the stage-two restraint route that the router change relies on.

> Spec folder: `specs/sk-code/015-quality-agnostic-gate/005-consumers-and-routing` (Level 2)

&nbsp;

## What's New at a Glance

- **The reason names the readers.** `verify-doc-claims.cjs` now says the id is read by `workflow-verify.md` step 2 and by the @code RETURN Quality Gate field, so the allowlist says why it exists.
- **A test holds the restraint route.** `scripts/tests/router-stage-two-quality.test.cjs` asserts that "apply yagni to this change" resolves to CODE_QUALITY at stage two and that simplify stays out of the stage-one intent signals.
- **The replay library passes the quality block through.** `assets/scripts/router-replay-lib.cjs` hands a skill's `quality` block to its reader as written, so a value that is not an object is reported instead of reading as a skill that declared nothing.

&nbsp;

## Upgrade

No migration required. The check and the route behave as before. Only the reason text and the test coverage changed.
