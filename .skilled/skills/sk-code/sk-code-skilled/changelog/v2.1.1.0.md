# v2.1.1.0, The Doc-Claims Reason Names the Real Readers

The doc-claims check let the run envelope schema id through an allowlist. Its reason named no reader of it. It now names the two readers. A new test holds the stage-two restraint route. The router change relies on that route.

&nbsp;

## What's New at a Glance

- **The reason names the readers.** `verify-doc-claims.cjs` now names the id's two readers. One is `workflow-verify.md` step 2. The other is the @code RETURN Quality Gate field. So the allowlist says why it exists.
- **A test holds the restraint route.** `scripts/tests/router-stage-two-quality.test.cjs` asserts one thing. "apply yagni to this change" resolves to CODE_QUALITY at stage two. It also asserts that simplify stays out of the stage-one intent signals.
- **The replay library passes the quality block through.** `assets/scripts/router-replay-lib.cjs` hands a skill's `quality` block to its reader as written. So a value that is not an object is reported. It does not read as a skill that declared nothing.

&nbsp;

## Upgrade

No migration required. The check and the route behave as before. Only the reason text and the test coverage changed.
