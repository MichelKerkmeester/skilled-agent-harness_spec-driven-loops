# v2.3.0.0, The Rust Set Covers an App as Well as a Binding

The Rust set was written for one shape: a Rust module behind napi-rs, WASM or a sidecar, matched byte for byte against TypeScript. A Rust binary that owns its own entry point fell outside its scope, and so did a port of a program written in another language. This release opens the scope and adds the rules that shape needs. Each rule is restated in sk-code's own words with a `rust-anything, <file>:<line>` anchor.

&nbsp;

## What's New at a Glance

- **The scope names app-style Rust.** `assets/checklists/rust-checklist/overview-and-p0-parity.md` adds a binary with no TypeScript oracle to the scope, limits the TypeScript-ownership sentence to a project where a TypeScript backend owns the process, and adds a process contract row. The `SKILL.md` rule now reads "Rust preserves the TypeScript contract where there is one".
- **An app's entry point and errors.** `references/rust/quality-standards/docs-errors-and-async.md` allows `anyhow` in every layer of a crate with no ABI boundary, and adds §Application Entry Point: `main` returns `ExitCode` around a fallible `run`, and one print macro ignores a closed stdout.
- **Layout, lints and tests for a binary.** `references/rust/quality-standards/build-and-organization.md` adds the single-crate layout with a clap derive parser, the single-crate `[lints.rust]` and `[lints.clippy]` form and tests that run the built executable through `CARGO_BIN_EXE_<name>`. It also adds trycmd case files and the rule that a child's stdout never reaches a stream the parent's protocol owns. It names ratatui and crossterm as the terminal screen case, which has no rendering rules yet.
- **Porting against a recorded original.** `references/rust/quality-standards/determinism-and-parity.md` adds §Porting Against a Recorded Original: the recorded cases are the oracle, three checks catch a port that passes without porting, and a float tolerance forgives rounding only. §Serialized Output gains the `serde_json` `float_roundtrip` and `preserve_order` rules.
- **TypeScript ownership is scoped.** `overview-and-data-ownership.md`, `quick-reference/overview-and-boundary-template.md`, `style-guide/interop-model.md` and `style-guide/overview-and-file-header.md` keep TypeScript as the owner of transport and CLI wiring where a TypeScript backend owns the process, and name the app-style binary as the owner of its own entry point.
- **Regex engines and Java `char`.** `references/rust/quality-standards/modeling-collections-and-api.md` says when to use `fancy-regex` and how to keep ASCII-only classes ASCII-only, and refuses mapping a Java `char` to Rust `char`.
- **A Rust app routes here without a `.rs` path.** The RUST list in `ROUTER.md` adds `clap cli`, `clap crate`, `clap derive`, `clap::`, `ratatui` and `crossterm`, and moves `#[napi]` and `#[wasm_bindgen]` to the end, because the replay parser stopped at the first `]` and dropped every keyword after it. `detectSkilledLanguages` in `assets/scripts/router-replay-lib.cjs` matches the same app vocabulary. The bare word `clap` stays out, so a prompt about a clap animation routes nowhere.
- **`#[expect]` over `#[allow]`.** `assets/checklists/rust-checklist/p1-required.md` and the Clippy Baseline example prefer `#[expect]`, so a stale suppression is reported. The example now uses a comparison the lint fires on. The deny list names `#[expect(clippy::expect_used, reason = "infallible: ...")]` for a state the original also treats as impossible.

&nbsp;

## Upgrade

No migration required. An existing `#[allow]` with a reason still passes the checklist, which now prefers `#[expect]`.
