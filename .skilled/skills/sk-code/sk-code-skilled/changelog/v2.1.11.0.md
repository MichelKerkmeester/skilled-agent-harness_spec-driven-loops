# v2.1.11.0, The SKILLED Frontmatter Parses Under a Strict YAML Parser

The SKILLED README described what system-code work under this repository's own tree holds to, and that sentence lists six language rule sets after a colon in an unquoted value. A strict YAML parser read the colon as the start of a nested mapping and refused the block, while the router that reads the file went on finding its phrases. The value is quoted now and its wording is unchanged. The surface SKILL.md also loses the `author: OpenCode` line, a field nothing read and that was not true.

> Spec folder: `specs/sk-code/017-portable-code-modes/015-frontmatter-yaml-validity` (Level 2)

&nbsp;

## What's New at a Glance

- **The README description is quoted.** A strict YAML parser reads the SKILLED frontmatter, and the sentence that lists the rule sets reads exactly as before.
- **The unused author line is gone.** The metadata block no longer claims OpenCode as its author, so the header states only the family and packet kind the router reads.
