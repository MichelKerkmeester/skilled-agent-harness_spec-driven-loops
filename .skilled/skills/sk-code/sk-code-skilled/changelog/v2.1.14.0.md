# v2.1.14.0, The Examples Match the House Style

The reference examples and the style guide described two different house styles. So a reader could follow either one and be wrong about the code next door. The guide now shows the `MODULE` header and the `//` dividers the code uses. It keeps the older box as a legacy allowance. It says which module format each extension follows. On the playbook side, three routes were only named before. Each now has a scenario that runs it.

> Spec folder: `specs/sk-doc/072-skill-routing-and-clarity/012-alignment-remediation` (Level 2)

&nbsp;

## What's New at a Glance

- **The examples match the code.** Every JavaScript example opens on the `MODULE` header. Its dividers use `//` with the section names the code uses. The guide keeps the older box for files that already carry it.
- **A module format follows its package.** A package `"type": "module"` selects ESM. `.cjs` stays CommonJS. The guide explains why `.js` and `.cjs` keep the strict directive, even where it is redundant.
- **Shell headers say `COMPONENT:`.** The shell examples use the marker the shell guides require. A role name no longer stands in for it.
- **Line length is a soft limit.** The JavaScript guide follows the shared range of roughly 100 to 120 characters. That range replaces a hard 100.
- **Three more routes are graded.** A JavaScript intent, the six-path shared tier and the surface detection each have a scenario. So the set a prompt loads is checked, not assumed.
- **Two scenarios now check what they claim.** One declared nine of the twelve paths it called full. Another only checked that two documents exist. Both hold the whole list now. Both run the gate those documents describe.
