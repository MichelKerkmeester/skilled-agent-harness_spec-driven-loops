# v1.1.7.0, The CI Profile Moves Into the Packet

The profile carries a repository's branch names, switch variables, protected workflows and path twins, and it sat at the repository root as `.sk-code/ci.json`, a folder this packet did not own. It now sits beside the packet that reads it, at `repository/ci.json`, and the same path applies under `.opencode/` where a repository installs its skills there.

> Spec folder: `specs/sk-code/017-portable-code-modes/016-repository-config-in-skill` (Level 2)

&nbsp;

## What's New at a Glance

- **A profile names the repository it was written for.** A `repository` field of `<owner>/<name>` limits the file, so a copy shipped with the skills into another repository is reported as ignored and not applied. A file with no field still applies everywhere.
- **A profile at the old root path is refused.** `.sk-code/ci.json` exits 3 with `PROFILE_LEGACY_LOCATION`, and the message names the path to move it to, so a stale copy cannot look configured while the routes read the generic default. A `--profile` or git config path inside `.sk-code/` is refused the same way.
- **The toggle keeps its protections when the profile is ignored.** It prints the ignored file and refuses to switch a workflow off until the profile names this repository or is passed with `--profile`, because the default profile protects nothing.
- **This repository's profile moved and its report reads the same.** The committed file names this repository, and `/doctor:ci report` prints the same values with only `profile.path` different. The README, the protected-set reference and the workflow template comment name the new path.

&nbsp;

## Upgrade

A repository that committed `.sk-code/ci.json` moves it to `.skilled/skills/sk-code/sk-code-ci/repository/ci.json`, or names the new path with `--profile` or `skcode.ciProfile`. A repository with no profile needs nothing.
