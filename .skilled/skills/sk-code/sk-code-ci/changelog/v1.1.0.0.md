# v1.1.0.0, The CI Doctor Command Arrives

The `/doctor:ci` command puts this packet's rules to work on the repository's workflows. Its `report` route is read-only, and its `scaffold` and `toggle` routes change a workflow or a repository switch only after you say yes. Doctor commands have no changelog of their own, so this packet records the command.

&nbsp;

## What's New at a Glance

- **Report every workflow's switches.** `/doctor:ci report` lists each workflow with its switch state, triggers, path filters and drift flags. It writes nothing.
- **Scaffold a workflow from the templates.** `/doctor:ci scaffold` writes one new workflow after a yes. It refuses a path that already exists and a protected workflow name, and it never edits an existing workflow.
- **Toggle one CI switch.** `/doctor:ci toggle` turns one of the six switch variables off or back on after a yes. It refuses to switch off the message-contract variable or the master switch, because a skipped job reports Success and a commit with a wrong message could then merge.
- **Checkout keeps no token.** A job that holds a write scope or pushes checks out with `persist-credentials: false`, so no later step can reuse the token. Both scaffold templates now emit it.
- **The protected set is corrected.** The rule said a switched-off required check stays pending. A skipped job reports Success, so the check stops blocking, and the rule now says so.
- **Workflow paths reach the CI rules.** A request that names a `.github/workflows/` path now loads the CI rules, and a bare "concurrency group" no longer does.

&nbsp;

## Upgrade

No migration required. Existing workflows are not rewritten. Run `/doctor:ci report` to see each workflow's switch state.
