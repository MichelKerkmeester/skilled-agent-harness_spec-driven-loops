# v1.0.0.0, The CI Surface Is Established

The first `sk-code-ci` release gives the repository's GitHub Actions workflows one written standard. The packet is a read-only surface on the `sk-code` hub's surface axis. It is bundled beside a workflow mode. It is never routed as a primary.

&nbsp;

## Why This Release

Only path parity between `.skilled/` and `.opencode/` was machine-enforced. SHA pinning was a convention held in review memory. So was a README row per workflow. So were timeouts, permissions, concurrency and the cached setup action. A workflow-YAML diff was reviewed as an unknown surface. It loaded none of them.

&nbsp;

## What's New at a Glance

- **Ten rule families, each with a citation.** They are the twin rule, the rebuild-commit skip rule and push-only scope. Then timeout sizing, least privilege and the concurrency template. Then the composite setup action, the switch `if:` shape, the protected set and the scaffold templates.
- **A protected set.** It lists the workflows protected by function. A change to one needs a second named confirmation.
- **An intentional exception.** `message-contract.yml` pushes on every branch. That is because it checks every pushed branch's name and commits. The trigger is recorded as an intentional exception. The workflow file is unchanged.
- **Two scaffold templates.** One is a whole-workflow template. The other is a job template. Both start with the switch condition, permissions, concurrency, a timeout and SHA-pinned steps.
- **One routing scenario.** The packet playbook carries a scenario. The hub's router-sync guard replays it.

&nbsp;

## Upgrade

No migration required. The packet is additive. It edits no workflow.
