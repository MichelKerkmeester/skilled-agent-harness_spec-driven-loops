# v1.1.2.0, The Shell-Strictness Rule Matches the Workflows

The standard asked for strict shell mode in every multi-line step but did not say where the repository departs from it. It now counts the workflows that comply and lists each step that deliberately leaves one flag off, with the reason. The playbook also gains the review and sub-agent sections the playbook layout expects.

> Spec folder: `specs/system-speckit/053-ci-workflow-efficiency` (Level 2)

## What's New at a Glance

- **The rule names its exceptions.** Each step that runs without the exit-on-error flag is listed with the reason it needs to.
- **The playbook follows the standard layout.** Review protocol and sub-agent planning now sit where every other playbook keeps them.
