# v1.1.5.0, The CI Routes Read a Repository Profile

`/doctor:ci` was written for this repository. Its report, scaffold and toggle assumed the `SKILLED_CI` switch names. They assumed the `main` branch, the `.opencode/` twin, the workflows README and the setup action. In another repository the report flagged every workflow. The toggle refused every switch. Each route now reads the repository's own conventions from a CI profile. This repository commits its profile, so nothing changes here. Doctor commands have no changelog of their own. So this packet records the command.

&nbsp;

## What's New at a Glance

- **A repository profile states the conventions.** `.sk-code/ci.json` names the default branch and the switch variables. It names the protected workflows, the path twins and the workflows README. It also names the rebuild trailer and the setup action. `--profile` or `git config skcode.ciProfile` can name another file. An unknown key is an error.
- **No profile forces nothing.** Without a profile the report requires no switch. It checks no README row and reads the branch GitHub names. A foreign repository with its own switches and three workflows now reports its real switch state. It needs no flag.
- **Switches are read by shape.** Any variable a job compares against `off` is a switch. So a repository's own names are read, and the toggle accepts them.
- **The toggle refuses from the live ruleset.** A variable that skips a job is refused. That applies when the branch ruleset requires the job's status context. The profile's `neverOff` list still refuses. So does a `must stay unset` sentence in the README. A change to the state a variable already has is refused as a no-op.
- **A protected workflow needs a second confirmation.** Switching off `SKILLED_CI_FRESHNESS` or `SKILLED_CI_REPORTS` here now names the protected workflows it stops. It names their roles. It asks for the variable name a second time. It used to take one yes.
- **An unread ruleset is shown, not hidden.** Sometimes the toggle cannot read the branch ruleset. Then a plan to switch a variable off now prints `Required checks: not read (<reason>); the ruleset refusal was not applied`. It prints that before the approval prompt. The plan used to look cleared even though no required status check had been checked.
- **The command takes `--profile=<path>`.** `/doctor:ci report`, `scaffold` and `toggle` now accept the flag. They pass it to their script. So a repository can name its profile file per run. The scripts took it before. The routes rejected it as an unknown flag.
- **The templates take profile values.** The scaffold renders the workflow and job templates from the profile. Here it prints the same files as before. In another repository it prints none of this repository's names.
- **The references say which lines are examples.** The trigger, job-shape and standards references now state each rule universally. They mark this repository's values as Skilled examples. The protected set doc now also describes the profile.

&nbsp;

## Upgrade

No action is needed in this repository. That is because it commits `.sk-code/ci.json` with today's values. Another repository can run `/doctor:ci report` without a profile. Or it can add `.sk-code/ci.json` to name its own switches and protected workflows.
