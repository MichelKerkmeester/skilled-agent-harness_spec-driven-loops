# v1.1.5.0, The CI Routes Read a Repository Profile

`/doctor:ci` was written for this repository. Its report, scaffold and toggle assumed the `SKILLED_CI` switch names, the `main` branch, the `.opencode/` twin, the workflows README and the setup action. In another repository the report flagged every workflow and the toggle refused every switch. Each route now reads the repository's own conventions from a CI profile, and this repository commits its profile, so nothing changes here. Doctor commands have no changelog of their own, so this packet records the command.

> Spec folder: `specs/sk-code/017-portable-code-modes/007-ci-repo-profile` (Level 2)

&nbsp;

## What's New at a Glance

- **A repository profile states the conventions.** `.sk-code/ci.json` names the default branch, the switch variables, the protected workflows, the path twins, the workflows README, the rebuild trailer and the setup action. `--profile` or `git config skcode.ciProfile` can name another file, and an unknown key is an error.
- **No profile forces nothing.** Without a profile the report requires no switch, checks no README row and reads the branch GitHub names. A foreign repository with its own switches and three workflows now reports its real switch state with no flag.
- **Switches are read by shape.** Any variable a job compares against `off` is a switch, so a repository's own names are read and the toggle accepts them.
- **The toggle refuses from the live ruleset.** A variable that skips a job whose status context the branch ruleset requires is refused. The profile's `neverOff` list and a `must stay unset` sentence in the README still refuse, and a change to the state a variable already has is refused as a no-op.
- **A protected workflow needs a second confirmation.** Switching off `SKILLED_CI_FRESHNESS` or `SKILLED_CI_REPORTS` here now names the protected workflows it stops, with their roles, and asks for the variable name a second time. It used to take one yes.
- **An unread ruleset is shown, not hidden.** When the toggle cannot read the branch ruleset, a plan to switch a variable off now prints `Required checks: not read (<reason>); the ruleset refusal was not applied` before the approval prompt. The plan used to look cleared even though no required status check had been checked.
- **The command takes `--profile=<path>`.** `/doctor:ci report`, `scaffold` and `toggle` now accept the flag and pass it to their script, so a repository can name its profile file per run. The scripts took it before, but the routes rejected it as an unknown flag.
- **The templates take profile values.** The scaffold renders the workflow and job templates from the profile. Here it prints the same files as before, and in another repository it prints none of this repository's names.
- **The references say which lines are examples.** The trigger, job-shape and standards references now state each rule universally and mark this repository's values as Skilled examples. The protected set doc now also describes the profile.

&nbsp;

## Upgrade

No action is needed in this repository, because it commits `.sk-code/ci.json` with today's values. Another repository can run `/doctor:ci report` without a profile, or add `.sk-code/ci.json` to name its own switches and protected workflows.
