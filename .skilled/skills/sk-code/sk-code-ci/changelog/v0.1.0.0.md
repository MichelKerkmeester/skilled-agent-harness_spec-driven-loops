# v0.1.0.0, The CI Surface Is Established

The first `sk-code-ci` release gives the repository's GitHub Actions workflows a single written standard. The packet is a read-only surface on the `sk-code` hub's surface axis, bundled beside a workflow mode and never routed as a primary.

## Why This Release

Only path parity between `.skilled/` and `.opencode/` was machine-enforced. SHA pinning, a README row per workflow, timeouts, permissions, concurrency and the cached setup action were conventions held in review memory. A workflow-YAML diff reviewed as an unknown surface and loaded none of them.

## What's New at a Glance

- **Ten rule families, each with a citation.** The twin rule, the rebuild-commit skip rule, push-only scope, timeout sizing, least privilege, the concurrency template, the composite setup action, the switch `if:` shape, the protected set and the scaffold templates.
- **A protected set.** The workflows protected by function, with the rule that a change to one needs a second named confirmation.
- **An intentional exception.** `message-contract.yml` pushes on every branch because it checks every pushed branch's name and commits. The trigger is recorded as an intentional exception and the workflow file is unchanged.
- **Two scaffold templates.** A whole-workflow template and a job template that start with the switch condition, permissions, concurrency, a timeout and SHA-pinned steps.
- **One routing scenario.** The packet playbook carries a scenario the hub's router-sync guard replays.

&nbsp;

## Upgrade

No migration required. The packet is additive and edits no workflow.
