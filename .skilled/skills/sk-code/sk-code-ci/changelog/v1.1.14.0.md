# v1.1.14.0, Routing Reads Like the Other Surface Packets

The CI surface now numbers and words its routing section the way the other surface packets do. Its router overview names the families a request falls into and leaves the exact keywords to the intent model, so the same list is no longer stated twice.

> Spec folder: `specs/sk-code/018-frontend-upstream-proposals/010-reference-readability-research` (Level 2)

&nbsp;

## Why This Release

The router overview listed every trigger, all four reference paths and the default resource, and INTENT MODEL repeated them a few lines later. Two reference introductions also restated their own overview, and one section opened with a bare status line that told a reader nothing. The packet now says each thing once and explains why a reader should care before it gives the rules.

&nbsp;

## What's New at a Glance

- **SMART ROUTING is section 3.** The letter suffix is gone, a divider opens the section, and SURFACE STANDARDS and INTEGRATION POINTS shift to 4 and 5.
- **The skill body points at its triggers.** SMART ROUTING names section 1 for the signals instead of repeating them.
- **The router overview names families.** It describes the signal and resource families and leaves the exact keywords, paths and default resource to INTENT MODEL.
- **Two references open with a hook.** The trigger and job-shape introductions now say what goes wrong when a reader ignores them, instead of listing what each file covers.
- **The protected set orients first.** Purpose and When to Use precede The Profile, so a reader knows which two guards the reference explains.
- **A stray status token is gone.** The composite setup section no longer opens with a line that belonged to no reader.

&nbsp;

## Upgrade

No action is needed. A local copy that cites `## 2b. SMART ROUTING` should point at section 3 instead.
