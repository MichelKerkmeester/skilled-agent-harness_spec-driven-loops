# v1.1.4.0, Every Workflow Now Carries a Concurrency Block

The job shape rules counted 30 of 32 workflows with a concurrency block and named the two without one. Both now carry a block, so the count reads 32 of 32. The Dependabot auto-merge workflow queues its runs rather than cancelling them, because a cancelled run could stop before it turns auto-merge on, and the rules now name it beside the rebuild workflow as the second one that does.

> Spec folder: `specs/sk-code/017-portable-code-modes/008-ci-drift-flags` (Level 2)

&nbsp;

## What's New at a Glance

- **The concurrency count matches the tree.** Thirty workflows use the pull-request-only cancel value and two queue their runs.
- **The queueing exception is named.** A reader who finds `cancel-in-progress: false` in the auto-merge workflow finds the reason in the rules.

&nbsp;

## Upgrade

No action is needed. Only the concurrency count and its explanation changed.
