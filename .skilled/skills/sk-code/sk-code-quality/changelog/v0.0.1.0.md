# v0.0.1.0, The Quality Frontmatter Parses Under a Strict YAML Parser

The quality SKILL.md described the gate as running after implementation, before verification, with the colon that sentence needs in an unquoted value. A strict YAML parser read that colon as the start of a nested mapping and refused the block, while the gate itself ran on either way. The value is quoted now and its wording is unchanged. The metadata block also loses the `author: OpenCode` line, a field nothing read and that was not true.

> Spec folder: `specs/sk-code/017-portable-code-modes/015-frontmatter-yaml-validity` (Level 2)

&nbsp;

## What's New at a Glance

- **The description is quoted.** A strict YAML parser reads the quality frontmatter, and the sentence that says when the gate runs reads exactly as before.
- **The unused author line is gone.** The metadata block no longer claims OpenCode as its author, so the header states only the family the router reads.
