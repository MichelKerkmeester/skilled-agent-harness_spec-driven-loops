# v1.12.0.0, The Gate Is Measured for What It Catches and What It Costs

This release answers two questions the mode could not answer before. Nobody knew what the gate catches on a change with a known defect. Nobody knew what a run costs. A live measurement now records both. A rendered report states each result against its target. Seven playbook scenarios let a reader replay every verdict for themselves.

&nbsp;

## What's New at a Glance

- The catch rate is measured.
  - A seeded change spans six language families and carries seven forbidden comment labels.
  - The gate blocked on all seven in a repository that declares no code surface at all.
- The false-positive set stays clean.
  - Measurement ratios, encoding names, hash and RFC names produced no finding.
  - A status code and a CWE id produced none either.
- A full run fits the target.
  - The 50-file set finished in 1661 ms at the slowest of five full runs.
  - Both built-in checks were running.
  - The target is 2 seconds.
- Every quality prompt reached the mode.
  - Four prompts each resolved a single route to this mode.
  - The prompts include an agent edit, a CI workflow edit and a rails request.
- Seven scenarios replay each verdict.
  - The scenarios cover a foreign polyglot change.
  - The scenarios cover a language with no comment family.
  - The scenarios also cover a CI target and a private surface.
  - The rest are an absent required tool, an envelope round trip and a restraint prompt.
- The mode's own router knows the restraint and envelope words.
  - `envelope`, `restraint` and `yagni` now select the quality intent.
  - So a request to read a gate envelope no longer falls back to the default resources.
  - Neither does a request to apply yagni.
- The report sits with the mode's other runs.
  - `benchmark/reports/` holds the curated folder.
  - The report is rendered from the measurement record.
  - One table holds the four measures and their targets.

&nbsp;

## Upgrade

No migration required. The numbers describe the gate this release ships. So a later change to a sensor, a label pattern or a checklist moves them. That change earns a new run rather than an edit to this report.
