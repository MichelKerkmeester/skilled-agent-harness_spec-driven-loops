# v1.11.0.0, A Sibling Skill's Checklists Join the Run

This release follows the runner-limit release. A skill outside the hub could declare its own quality rows. The runner never read them. So its files met the hub's rows alone. It now reads those rows. It refuses any row that leaves the skill that shipped it. It reports a row it cannot follow by name.

&nbsp;

## What's New at a Glance

- A sibling skill's rows reach the run.
  - The runner reads the `quality` block of every `graph-metadata.json` that names the hub's family.
  - The runner uses the same surface discovery the labels come from.
  - So a skill's checklist loads for a file it detected itself.
- A row cannot leave the skill that declares it.
  - An absolute path is refused with `CHECKLIST_OUTSIDE_SKILL`.
  - So is a `..` segment.
  - So is a path that resolves outside the skill folder.
  - So is a link that leads out.
  - The file is never read.
  - Containment is decided on the deepest part of the path that exists.
  - So a link above a name that is not there is refused before anything tests it.
  - Both ends are compared in their on-disk spelling.
  - So a link to the skill's own file written in another case stays inside.
- A malformed block or row is reported, not skipped.
  - An unknown key reads `CHECKLIST_ROW_INVALID`.
  - So does an empty list.
  - So does a row with no selector.
  - So does a non-dotted extension.
  - So does a value that is not a JSON object.
  - So a declaration nobody could follow never looks like no declaration.
- A row belongs to the skill that detected the file.
  - Two skills may share a label or a skill id.
  - Each one's rows now apply only to the files it detected.
  - The rows resolve against the skill's own folder.
- A private folder name is matched in any case.
  - A folder called `Local-Folder` used to slip past the private-name match.
  - The folder reached the envelope, which no tracked file may name.
  - The folder prints as its label now, in either spelling.
- A row that names a folder is missing.
  - Only a regular file satisfies a row.
  - So a folder spelled like a checklist reads `CHECKLIST_MISSING`.
- One bad row stops the verdict.
  - The gate reads `ERROR` and exits 3.
  - That comes ahead of any `BLOCKED` another check found.

&nbsp;

## Upgrade

No migration required. A skill that declares checklists in its `graph-metadata.json` now has them loaded. A skill whose rows leave its own folder is refused until the path points inside it.
