# v1.13.2.0, A Minified File Keeps Its Message

A node child that exits while an async stderr write is still queued loses what the stdio channel its parent created could not take at once: 8 KiB under a Node 20 parent and 64 KiB under Node 22 and later on macOS. For a minified one-line file that cut the report inside the quoted source line, so the `syntax-node` finding fell back to a run of source text instead of the `SyntaxError:` message. Linux writes to pipes and sockets synchronously, so it should not show the loss.

> Spec folder: `specs/sk-code/017-portable-code-modes/011-node20-test-fixes` (Level 2)

&nbsp;

## What's New at a Glance

- **Each child writes its report to a file.** The parallel syntax helper gives every `node --check` child its own stderr file in a temporary folder the run owns, reads it back inside the same per-record budget once the child exits, and removes the folder when it leaves.
- **The test reads its reference the same way.** The long-line case captured the direct `node --check` report through a pipe, so on Node 20 it failed before it reached the helper. It now writes that report to a file too, and its file is long enough to fail a pipe-reading helper under every Node. The case passes on Node 20, 22 and 26.

&nbsp;

## Upgrade

No action is needed. The record format the runner reads is unchanged.
