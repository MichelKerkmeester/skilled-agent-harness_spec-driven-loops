# v1.13.2.0, A Minified File Keeps Its Message

A node child exits while an async stderr write is still queued. It loses what the stdio channel its parent created could not take at once. The limit is 8 KiB under a Node 20 parent. It is 64 KiB under Node 22 and later on macOS. For a minified one-line file, that cut the report inside the quoted source line. So the `syntax-node` finding fell back to a run of source text. It did not show the `SyntaxError:` message. Linux writes to pipes and sockets synchronously. So it should not show the loss.

&nbsp;

## What's New at a Glance

- Each child writes its report to a file.
  - The parallel syntax helper gives every `node --check` child its own stderr file.
  - That file sits in a temporary folder the run owns.
  - The helper reads it back once the child exits.
  - The read stays inside the same per-record budget.
  - The helper removes the folder when it leaves.
- The test reads its reference the same way.
  - The long-line case captured the direct `node --check` report through a pipe.
  - So on Node 20 it failed before it reached the helper.
  - It now writes that report to a file too.
  - Its file is long enough to fail a pipe-reading helper under every Node.
  - The case passes on Node 20, 22 and 26.

&nbsp;

## Upgrade

No action is needed. The record format the runner reads is unchanged.
