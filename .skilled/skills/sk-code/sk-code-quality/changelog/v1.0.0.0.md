# v1.0.0.0, Quality Mode Established

This is the first release of the `quality` workflow mode on the `sk-code` hub. Born in the parent-hub refactor that collapsed `sk-code` from eight sub-skills to four surface-primary packets, the author-side quality gate is now a single mode child.

## What's New at a Glance

- **`SKILL.md` is the mode contract.** It defines the gate's timing, checklist choice and `code-review` boundary.
- **`README.md` is new.** It gives the mode at-a-glance and layout.
- **The `quality` gate follows surface implementation.** It runs after `code-webflow` or `code-opencode` implements changes and before the surface's verification workflow or done-claim.
- **Checklist selection uses the detected surface and target path.** The mode consumes the parent shared surface router, and the new `assets/code-quality-checklist.md` is the shared quality-gate checklist.
- **The gate applies P0/P1/P2 author-side checks.** It checks comment hygiene per modified file with `check-comment-hygiene.sh` and fixes gate failures in place.
- **The mode edits only files the surface skill already changed.** It creates no new files and dispatches no subagents.
- **Findings-only output belongs in `code-review`.** Spec-folder authoring belongs in `system-spec-kit`.
- **Distribution staleness has a dedicated check.** `check-dist-staleness.sh` checks for it.
- **`scripts/` also holds the Claude PostToolUse post-edit hook and router.** Their paths are `hooks/` and `lib/post-edit-router.cjs`.
- **The mode benchmark uses a `quality-gate` routing scenario.** `manual-testing-playbook/` holds it.
- **The skill benchmark has router and live baselines.** `benchmark/` holds `router-mode-a` and `live-mode-b`.
- **The packet is currently at `1.0.0.1`.** A post-establishment metadata sweep made no behavior change.

## Upgrade

No migration required.
