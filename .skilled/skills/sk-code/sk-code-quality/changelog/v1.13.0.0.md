# v1.13.0.0, Configured Checks Wait for a Trust Grant

A repository can name its own quality checks in a committed `.sk-code/quality.json`. Until now the gate ran every command that file named as soon as a run started, including in a clone whose owner had never seen the file. The gate now asks for a grant first. When the grant is missing, the verdict says which check it held back and the one command that releases it.

Two more gaps close in this release. A broken checklist row in another installed skill no longer fails every run when that skill does not touch the change. The node syntax check runs its files side by side, so a fifty-file change finishes in under a second on the reference machine.

> Spec folder: `specs/sk-code/015-quality-agnostic-gate/009-review-closeout` (Level 2)

&nbsp;

## Why This Release

The gate trusted too much in two places. A committed config is written by whoever owns the repository, so a clone should not run its commands without a choice. The git hooks already ask for one. A single malformed row in one skill should not turn every run in every repository into an error.

&nbsp;

## What's New at a Glance

- **A committed config waits for a grant.** Its commands run once the repository is trusted. Until then each one reads `SKIPPED_UNTRUSTED` with the repair line.
- **The hub's own repository needs no grant.** Its configured checks run as before.
- **The doctor shows trust without setting it.** `/doctor:sk-code quality` reports the trust state and the rule behind it. It writes no git config.
- **A broken row errors only where it applies.** A fault in a skill that reaches no changed file is listed as a warning and leaves the gate unchanged.
- **The syntax check runs in parallel.** A fifty-file run fell from 1849 ms to 725 ms at the slowest of five runs, with the same findings in the same order.

&nbsp;

## Configured Checks

#### Committed commands wait for a grant

**Breaking:** A repository whose committed `.sk-code/quality.json` ran checks before this release needs one command, run once inside that repository: `git config --local skilled.trustRepoChecks true`. Until the grant is set, each configured check reads `SKIPPED_UNTRUSTED`, starts nothing and carries that repair line. A required check then leaves the run `UNVERIFIED`, which exits 4. Built-in checks run as before.

#### Four ways a config earns trust

The runner trusts a configured check in one of four cases. The operator named the file with `--config`. The operator stored a `skcode.qualityConfig` path in the repository's own local git config. The operator set `skilled.trustRepoChecks` to true in that repository. Or the repository is the hub's own. `--no-run` still lists a configured check without starting it, so the listing does not change.

#### The doctor reports trust without setting it

`/doctor:sk-code quality` applies the same rule the runner applies. It prints the trust state, the rule that decided it and the repair line when checks are held back. It writes no git config, so the grant stays the operator's to set.

&nbsp;

## Checklists From Other Skills

#### A broken row errors only where it applies

A skill outside sk-code can declare its own quality checklist. Before this release, one malformed block or row in any such skill made every run `ERROR`, even for a change that skill never reaches. A fault now errors the gate when that skill applies to at least one file in the change. A fault on a skill that applies to no changed file is listed in `config.warnings` with its code, the skill and the reason. The gate and the exit code stay what they would be without it.

&nbsp;

## The Node Syntax Check

#### Fifty files check in under a second

The `node --check` pass ran one file after another. It now runs the files through a bounded pool, sized to the machine's core count, so the findings come out the same and in the same order. On the reference machine, an Apple M5 Max with 18 cores, a 50-file run fell from 1849 ms to 725 ms at the slowest of five full runs.

When the runner stops the pool, every `node --check` it started stops with it, and each file keeps at most 4096 characters of error text, its start and its end. On Windows, where a process group does not exist, each check runs in a hidden window and is stopped on its own.

&nbsp;

## Upgrade Notes

- Run `git config --local skilled.trustRepoChecks true` once inside each repository whose committed `.sk-code/quality.json` ran checks before this release. Until then those checks read `SKIPPED_UNTRUSTED`.
- A repository with no committed config needs nothing.
- The verdict gains `config.trust` and `config.warnings`. Both are additions, so a reader that ignores fields it does not know keeps working.
