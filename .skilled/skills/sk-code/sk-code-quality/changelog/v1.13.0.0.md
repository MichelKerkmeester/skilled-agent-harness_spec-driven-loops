# v1.13.0.0, Configured Checks Wait for a Trust Grant

A repository can name its own quality checks in a committed `.sk-code/quality.json`.

- Until now the gate ran every command that file named.
- It did so as soon as a run started.
- That included a clone whose owner had never seen the file.
- The gate now asks for a grant first.

Two more gaps close in this release.

- A broken checklist row in another installed skill no longer fails every run.
- That holds when the skill does not touch the change.
- The node syntax check runs its files side by side.
- So a fifty-file change finishes in under a second on the reference machine.

> [!IMPORTANT]
> 1 change can break an existing setup. Read these before you update.
>
> 1. A committed config now needs a grant before its checks run. [Committed commands wait for a grant](#c-committed-commands-wait-for-a-grant)

&nbsp;

## Why This Release

The gate trusted too much in two places.

- A committed config is written by whoever owns the repository.
- So a clone should not run its commands without a choice.
- The git hooks already ask for one.
- A single malformed row in one skill should not turn every run into an error.
- That applies in every repository.

## Configured Checks

When the grant is missing, the verdict names the check it held back. It also names the one command that releases it.

#### Committed commands wait for a grant <a id="c-committed-commands-wait-for-a-grant"></a>

> [!WARNING]
> A repository whose committed `.sk-code/quality.json` ran checks before this release needs one command. Run it once inside that repository: `git config --local skilled.trustRepoChecks true`.

- Until the grant is set, each configured check reads `SKIPPED_UNTRUSTED`.
- It starts nothing and carries that repair line.
- A required check then leaves the run `UNVERIFIED`, which exits 4.
- Built-in checks run as before.

#### Four ways a config earns trust <a id="c-four-ways-a-config-earns-trust"></a>

- The runner trusts a configured check in one of four cases.
- The operator named the file with `--config`.
- The operator stored a `skcode.qualityConfig` path in the repository's own local git config.
- The operator set `skilled.trustRepoChecks` to true in that repository.
- Or the repository is the hub's own. It needs no grant.
- Its configured checks run as before.
- `--no-run` still lists a configured check without starting it, so the listing does not change.

#### The doctor reports trust without setting it <a id="c-the-doctor-reports-trust-without-setting-it"></a>

- `/doctor:sk-code quality` applies the same rule the runner applies.
- It prints the trust state and the rule that decided it.
- It also prints the repair line when checks are held back.
- It writes no git config.
- So the grant stays the operator's to set.

## Checklists From Other Skills

A skill outside sk-code can declare its own quality checklist.

#### A broken row errors only where it applies <a id="c-a-broken-row-errors-only-where-it-applies"></a>

- Before this release, one malformed block or row made every run `ERROR`.
- That applied to any such skill.
- That held even for a change that skill never reaches.
- A fault now errors the gate in one case.
- The skill applies to at least one file in the change.
- A skill may apply to no changed file.
- A fault there goes in `config.warnings`.
- The entry gives its code, the skill and the reason.
- The gate and the exit code stay what they would be without it.

&nbsp;

## The Node Syntax Check

The `node --check` pass ran one file after another. It now runs the files through a bounded pool.

#### Fifty files check in under a second <a id="c-fifty-files-check-in-under-a-second"></a>

- The pool is sized to the machine's core count.
- So the findings come out the same and in the same order.
- When the runner stops the pool, every `node --check` it started stops with it.
- Each file keeps at most 4096 characters of error text.
- It keeps the start and the end.
- On Windows, a process group does not exist.
- There each check runs in a hidden window.
- It is stopped on its own.

## How It Was Checked

The syntax check was timed on the reference machine.

#### Before and After <a id="c-before-and-after"></a>

| Check | Before | After |
|---|---|---|
| 50-file `node --check` run | 1849 ms | 725 ms |

<details>
<summary><b>Tests and scenarios</b></summary>

- The reference machine is an Apple M5 Max with 18 cores.
- The 50-file run fell from 1849 ms to 725 ms at the slowest of five full runs.

</details>

## Upgrade Notes

The steps below apply to repositories with a committed config.

#### Before You Start <a id="c-before-you-start"></a>

1. Run `git config --local skilled.trustRepoChecks true` once inside each repository whose committed `.sk-code/quality.json` ran checks before this release.

<details>
<summary><b>Configured Checks</b></summary>

- Until then those checks read `SKIPPED_UNTRUSTED`.
- A repository with no committed config needs nothing.
- The verdict gains `config.trust` and `config.warnings`. Both are additions.
- So a reader that ignores fields it does not know keeps working.

</details>
