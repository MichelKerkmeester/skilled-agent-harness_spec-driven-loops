# v1.4.0.0, The JavaScript and CSS Checks Drop the Webflow House Style

The checklists loaded for every `.js` or `.css` target still carried the Webflow site's house style. They made `snake_case` variable and function names P0. They required an `INIT_FLAG` guard. They asked for `--vw-*` properties and BEM classes. SKILLED is the hub's only public surface. It says camelCase in JavaScript in four places. So a SKILLED file could not pass both. The Webflow conventions now live only in the private `local-webflow` skill. That skill already carries them. The public checklists keep the checks that hold on every surface.

> Spec folder: `specs/sk-code/013-private-surface-skills/008-deferred-surface-items` (Level 1)

&nbsp;

## What's New at a Glance

- **No Webflow rule binds a SKILLED file.** These are gone from the public checklists: the `snake_case` naming, semantic prefixes, `INIT_FLAG` guard, IIFE wrapper and `/* */` section headers. The `CATEGORY:` header is gone too. So are the `WEBFLOW:`, `MOTION:` and `LENIS:` prefixes. The five-per-ten comment budget is gone as well. So are the 120-character lines, `--vw-*` prefixes, `i` selector flag, BEM classes and `snake_case` CSS file names.
- **Duplicates of the surface checklist are gone too.** Header width, numbered ALL-CAPS sections, commented-out code, WHY comments and function purpose comments are already rules. They are in the SKILLED JavaScript checklist and the style guide. JSDoc, constants, indentation, braces, semicolons and quotes are already rules in both.
- **Eight checks stay.** For JavaScript they are CHK-HDR-06, CHK-SEC-09, CHK-CMT-07 and CHK-FMT-05. For CSS they are CHK-CSS-05, CHK-CSS-09, CHK-CSS-10 and CHK-CSS-11. Each keeps its priority. So the GPU-only animation check stays P0.
- **Naming defects are P1.** The naming section points to the surface convention. It also points to the shared P1 naming tier.
- **The loaders say what loads.** `SKILL.md` and the README call the two files surface-neutral additions to the surface's own language checklist. They are not a JavaScript and CSS overlay.
- **The verification summary matches.** Its templates and pass criteria list the remaining checks. They state that the JavaScript P0 items come from the surface checklist.
- **The comment-hygiene checker drops its Webflow exceptions.** `check-comment-hygiene.sh` no longer treats `WEBFLOW:`, `MOTION:` or `LENIS:` as allowed tokens. An allowed token skips every violation pattern on its line. So `// WEBFLOW: see ADR-004` used to pass. A plain prefixed comment still passes. That is because the prefix alone matches no violation pattern. New test cases cover both sides. The comment-hygiene hook playbook scenario lists the allowed tokens that remain.

&nbsp;

## Upgrade

No migration required. The three checklist files keep their names. So every path that names them still resolves. `DEFAULT_RESOURCE` and `RESOURCE_MAP["QUALITY"]` are unchanged.
