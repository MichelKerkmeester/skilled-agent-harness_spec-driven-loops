# v1.5.0.0, The Comment Checker Covers What It Claims

The comment-hygiene checker blocks ephemeral labels in comments, but it read nine extensions and missed several comment forms. It now reads one comment-family table, `assets/comment-syntax.json`, which the ceiling report and the post-edit router read too. Go, Rust, YAML, CSS, TOML, SQL, `.mts` and `.cts` files are checked, and a missing checker is reported instead of passed.

&nbsp;

## What's New at a Glance

- **One table names the languages.** Each language lists its extensions, interpreters and comment family. A shebang that names a known interpreter decides the language before the extension does.
- **Missed comment forms are checked.** A URL or a standard code such as `CWE-79` no longer hides the rest of its line, and block-comment bodies count as comment text. A Python docstring counts too, where Python or its tools read one: first in a module, first in a def or class body, or right after an assignment. A triple-quoted string inside brackets, such as a call argument or a list item, is data.
- **Text is never read as a comment.** A YAML block scalar, with or without an anchor or a tag, a TOML multi-line string and a Go raw string hold text, so a Markdown heading there passes. A Rust char literal such as `'"'` opens no string, and a leading `*` is a comment body line only in the C family.
- **Issue numbers are flagged.** A closing word such as `fixes`, `closes` or `issue` followed by `#` and a number fails the check. `--ticket-prefix`, `--extension` and `--extra-pattern` add a repository's own terms.
- **Ratios pass.** The slash rule used to flag any two three-digit numbers joined by a slash. It now needs a zero-padded second number, so a ratio such as `100/250` passes and `026/005` still fails.
- **Each finding names its reason.** Text output ends with the reason in brackets. `--json` prints a `comment-hygiene/v1` document with a status for every file, and a usage error exits 3 instead of 2. A file that cannot be opened and whose extension names no language is skipped, as before.
- **Readers find the checker.** The ceiling report reads the repository it runs in, and takes each family's comment tokens from the table, so an SQL `--` marker counts. The post-edit router finds the checker beside its own path first and returns one `quality-notice` when none exists.
- **Two known false positives stay.** The `phase 0` and four-digit task id rules are unchanged, so `two-phase commit: phase 0 prepares` and `T1000` in a comment still need `hygiene-ok`.

The checker and ceiling suites now cover every form and rule above, and CI runs all four bash suites. The universal checklist now names `specs/` and `.skilled/specs/` as its spec roots. Its retitle as the house checklist for this framework's own code is still pending.

&nbsp;

## Upgrade

A caller that read exit 2 as a usage error should read exit 3. The checker reads any argument that starts with `--` as an option, so a caller that passes file names should put `--` before them, as the CI job does and both pre-commit hooks now do. Pre-commit and CI check whole files, so existing comments in newly covered forms fail when their files are touched. The pattern baseline ran the previous checker and this one over every tracked file. Its first run found 30 new findings outside `specs/`. This release rewrote 29 of them to their durable reason, and the last was Markdown inside a YAML block scalar, which the checker no longer reads as a comment. The final run has no delta line outside `specs/`. Its 21 delta lines all sit in packet artifacts under `specs/`. The 19 added lines stay as accepted debt, the other 2 are findings this checker no longer reports, and they fall in four classes:

- **New languages, YAML and TOML.** 11 lines in 7 files.
- **Python docstrings.** 7 lines in 5 files.
- **Files chosen by shebang.** 1 line in 1 file.
- **Findings the narrowed slash rule removes.** 2 lines in 1 file.

URL spans, block-comment bodies and the issue rule added no delta line. A rerun after the narrower docstring rule, the TOML, Go and Rust lexing and the standard-code change gave the same 21 lines in the same classes. A packet artifact with one of the 19 new findings fails when it is touched, until the finding is rewritten to its durable reason or marked `hygiene-ok` where the label is the subject of the line.
