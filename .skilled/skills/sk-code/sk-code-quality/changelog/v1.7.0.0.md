# v1.7.0.0, A Repository Names Its Own Checks in One Committed File

The runner ran built-in checks only, so a repository's own typecheck, lint command or ticket prefixes had no place to live. A repository now commits `.sk-code/quality.json`, and the runner runs the checks it names. `references/quality-config.md` documents the file, and `assets/quality-config.template.json` is the empty form `/doctor:sk-code quality` fills.

> Spec folder: `specs/sk-code/015-quality-agnostic-gate/003-config-and-doctor` (Level 2)

&nbsp;

## What's New at a Glance

- **One config source per run.** `--config <path>` wins, then a file-scoped `skcode.qualityConfig` git config value, then `.sk-code/quality.json` at the root. A value set with `git -c` is ignored. A named path that does not exist exits 3 with `CONFIG_PATH_MISSING`, and a committed file that resolves outside the repository is refused.
- **Strict validation before anything starts.** `schemaVersion` must be 1, an unknown key is an error and every fault lands in `config.errors` with exit 3 and `CONFIG_INVALID`. An exact sensor cannot be switched off, a ticket prefix must be letters and digits and an extra pattern must compile in 200 characters or fewer.
- **An extension can be added, never remapped.** The shipped comment-syntax table owns its extensions, so a `commentHygiene.extensions` key that names one the table already maps is a config error, and a repository can only add an extension the table lacks.
- **A pattern Python would refuse is a config error.** A `\p` or `\P` property escape, a `\k<name>` backreference and a `(?<name>` group that is not a lookbehind are refused before a check starts. A bracketed character class is scanned as literal text, so a construct inside one does not read as a fault. A value the checker still refuses once the run starts ends it with `CONFIG_INVALID`, exit 3 and one `config.errors` row naming the field, in place of an `ERROR` row and an `UNVERIFIED` run. The refusal is read from the checker's own `ERROR:` line, so a warning the interpreter prints above that line no longer hides it.
- **Configured checks run as argv arrays.** Each check matches files by `languages` and `paths`, expands `{files}` relative to its `cwd` (the root or the nearest package folder) and runs with no shell under its own deadline. It starts as the leader of a process group that the runner kills at the deadline and when it exits. A required P0 check that fails blocks the run, and an absent tool reads `SKIPPED_ABSENT` with a repair line.
- **A relative program starts from the repository root.** An `argv[0]` that holds a slash resolves from the root whatever `cwd` says, so a check in a package folder starts the file the presence probe found.
- **One guard window per command.** Each configured check runs in its own workspace guard window, so `CHECK_MUTATED_WORKSPACE` names the one command that changed the tree, and the first mutation stops the rest. Outside git a configured check reads `ERROR` with `GUARD_UNAVAILABLE` and never starts.
- **Suggestions never run.** The runner reads `package.json`, `pyproject.toml`, `Cargo.toml`, `go.mod`, the workflow folder and a Makefile `lint:` target, and lists what they imply under `suggested_checks` with the exact entry that would enable each. It never suggests a test, fix or format script, or one that holds `--write` or `--fix`.
- **Repository hygiene additions reach the checker.** Ticket prefixes, extension families and extra patterns pass as the checker's own flags, and a mapped extension gives a file a family the runner and the checker both read. CI and pre-commit keep the core set.
- **Help that reads nothing.** `-h` and `--help` print the flags, the discovery order and the exit codes, and exit 0.

The `node --test` suite gains `quality-config.test.cjs` and `configured-checks.test.cjs`, beside the runner suite.

&nbsp;

## Upgrade

No migration required. A repository with no config behaves as in 1.6.0.0, except that `suggested_checks` now lists what its manifests imply. `--config` now reads the named file instead of exiting 3. The verdict's `config.source` reads `cli`, `git-config`, `repo` or `none` in place of `defaults`, and the base layer moved to `config.defaults`.
