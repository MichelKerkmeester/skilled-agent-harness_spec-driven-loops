# v1.7.0.0, A Repository Names Its Own Checks in One Committed File

The runner ran built-in checks only. So a repository's own typecheck, lint command or ticket prefixes had no place to live. A repository now commits `.sk-code/quality.json`. The runner runs the checks it names. `references/quality-config.md` documents the file. `assets/quality-config.template.json` is the empty form `/doctor:sk-code quality` fills.

&nbsp;

## What's New at a Glance

- **One config source per run.** `--config <path>` wins. Then a file-scoped `skcode.qualityConfig` git config value. Then `.sk-code/quality.json` at the root. A value set with `git -c` is ignored. A named path that does not exist exits 3 with `CONFIG_PATH_MISSING`. A committed file that resolves outside the repository is refused.
- **Strict validation before anything starts.** `schemaVersion` must be 1. An unknown key is an error. Every fault lands in `config.errors` with exit 3 and `CONFIG_INVALID`. An exact sensor cannot be switched off. A ticket prefix must be letters and digits. An extra pattern must compile in 200 characters or fewer.
- **An extension can be added, never remapped.** The shipped comment-syntax table owns its extensions. So a `commentHygiene.extensions` key that names one the table already maps is a config error. A repository can only add an extension the table lacks.
- **A pattern Python would refuse is a config error.** A `\p` or `\P` property escape is refused before a check starts. So is a `\k<name>` backreference. So is a `(?<name>` group that is not a lookbehind. A bracketed character class is scanned as literal text. So a construct inside one does not read as a fault. A value the checker still refuses once the run starts ends it with `CONFIG_INVALID` and exit 3. One `config.errors` row names the field. That replaces an `ERROR` row and an `UNVERIFIED` run. The refusal is read from the checker's own `ERROR:` line. So a warning the interpreter prints above that line no longer hides it.
- **Configured checks run as argv arrays.** Each check matches files by `languages` and `paths`. It expands `{files}` relative to its `cwd`, the root or the nearest package folder. It runs with no shell under its own deadline. It starts as the leader of a process group. The runner kills that group at the deadline and when it exits. A required P0 check that fails blocks the run. An absent tool reads `SKIPPED_ABSENT` with a repair line.
- **A relative program starts from the repository root.** An `argv[0]` with a slash resolves from the root, whatever `cwd` says. So a check in a package folder starts the file the presence probe found.
- **One guard window per command.** Each configured check runs in its own workspace guard window. So `CHECK_MUTATED_WORKSPACE` names the one command that changed the tree. The first mutation stops the rest. Outside git a configured check reads `ERROR` with `GUARD_UNAVAILABLE`. It never starts.
- **Suggestions never run.** The runner reads `package.json`, `pyproject.toml`, `Cargo.toml`, `go.mod`, the workflow folder and a Makefile `lint:` target. It lists what they imply under `suggested_checks`, with the exact entry that would enable each. It never suggests a test, fix or format script. It never suggests one that holds `--write` or `--fix`.
- **Repository hygiene additions reach the checker.** Ticket prefixes, extension families and extra patterns pass as the checker's own flags. A mapped extension gives a file a family the runner and the checker both read. CI and pre-commit keep the core set.
- **Help that reads nothing.** `-h` and `--help` print the flags, the discovery order and the exit codes. They exit 0.

The `node --test` suite gains `quality-config.test.cjs` and `configured-checks.test.cjs`. Both sit beside the runner suite.

&nbsp;

## Upgrade

No migration required. A repository with no config behaves as in 1.6.0.0. The one change is that `suggested_checks` now lists what its manifests imply. `--config` now reads the named file instead of exiting 3. The verdict's `config.source` reads `cli`, `git-config`, `repo` or `none` in place of `defaults`. The base layer moved to `config.defaults`.
