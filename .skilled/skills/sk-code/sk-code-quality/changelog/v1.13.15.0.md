# v1.13.15.0, Typed Scripts and a Playbook That Reaches the Edges

The gate's scripts were written for behaviour alone. A function's parameters had to be read from its body. Its private helpers looked like public ones. They now carry typed signatures and docstrings. A leading underscore marks what stays internal. The containment check the gate and the config loader each kept is now one helper. A test sits beside it. The playbook grew over the same pass. It now covers behaviours it used to leave implicit.

&nbsp;

## What's New at a Glance

- **An ancestor link claims nothing.** `.opencode/plugins` can point at `..` or `../..`. Then `.opencode/agents/b.js` and `vendor/.opencode/d.js` stay `UNKNOWN` instead of inheriting the hub's surfaces.
- **A broken link still runs.** A link that dangles or loops reports the same surfaces as a repository with no link there. The run finishes rather than crashing.
- **The guard cases run against a shared check.** Both plugins-link cases sit in `scripts/tests/quality-gate-surfaces.test.cjs`. The rule they prove now comes from the helper the gate and the config loader both import. A case covers a child name that begins with two dots.
- **The scripts say what they accept and return.** Every function carries typed signatures, docstrings and a leading underscore on what stays internal. Each handler names the read and process errors it expects. So an unexpected one still reaches the run.
- **The shell tests moved and their old paths still work.** Their bodies sit under `scripts/tests/`. They keep the component header, the strict mode and the exit codes they use. The old paths stay as forwarding wrappers.
- **No script is past the split point.** `quality-gate.cjs` (2,878 lines) is now a 134-line CLI entry over `lib/gate-*.cjs` modules. Each module holds one concern. The concerns are arguments, context, files and surface labels, checklist seats and overrides. They also include the check plan, spawned and configured checks, layers, the runner, the verdict, rendering and explain mode. `lib/quality-config.cjs` is a 61-line entry over schema, discovery, trust and hygiene modules. `check-comment-hygiene.sh` is a thin entry over the `lib/comment_hygiene/` package. Every flag, output byte, exit code and exported name is unchanged.
- **The test suites split the same way.** The gate suite, the repository-config suite and the configured-check suite are now parts under 500 lines. They sit over shared helper modules. The case count is the same as before, and all pass.
- **The docs point at the part that holds each case.** The feature catalog, both playbook corpora and `SKILL.md` cite the split test parts in place of the three suites they replaced. Each scenario's `--test-name-pattern` and `sed` steps run against the part that holds its case.
- **A missing rule-override contract is a usage error.** `--disable-rule` with an unreadable contract exits 3 with the usage message instead of crashing on an undefined name. A test proves it.
- **The checker leaves no cache behind.** It turns bytecode writing off before it loads its modules. So a run inside a skill folder writes no `__pycache__` folder. The test that imports the package directly runs Python with `-B` for the same reason. The package's own README says so for any other direct caller.
- **The parallel-child test watches its own fixture.** It starts a stub that records its pid and then blocks. So it no longer asks the host process table what the helper is holding.
- **The playbook covers what the corpus skipped.** The dist adapter, the ceiling report, the write-time hook, the hygiene layers and the debt rule each have a scenario. So do the flag surface, the refusals, the no-evidence states, the same-level conflict, the manifest suggestions and the doctor. Each scenario has an expected-result table.
- **A path a scenario creates is written as a placeholder.** `<fixture>/<path>` replaces an invented repository path. That cleared every unresolved-path warning. The notation is documented where the other notation lives.
- **The scenarios leave the tree as they found it.** Four used to keep their scratch folder. Two named a repository-relative config path instead of an absolute one. Each now closes on a `git status` check. That check proves the committed config was untouched.
- **The coverage note says what the corpus leaves out.** It names the tools a scenario needs. It defines a verdict per scenario instead of by one path test. Every per-feature file carries a `Catalog` row. So a missing catalog link shows up.
