# v1.13.3.0, One Explain Call for Many Files

Review and other callers can now ask the quality runner, read-only, which surfaces and rule files apply to each file in a change. They get the answer from one resolver, so they no longer need their own surface detection. A private surface that declares no quality block can still be loaded, because the explanation names its folder.

> Spec folder: `specs/sk-code/017-portable-code-modes/004-quality-resolver` (Level 2)

&nbsp;

## What's New at a Glance

- **`--explain` takes several paths.** List them after the flag, as `--files` does, or repeat the flag once per path. A `files` array holds one entry per file, and one resolution covers them all, as a run does.
- **Each surface names its folder.** `surface_skills` gives every detected surface's label, whether the hub or an outside skill owns it, and the folder to load it from. A trusted `local-*` link counts through the same trusted-root rule the declared-surfaces reader applies.
- **Each checklist names its seat.** `source` and `sources` say whether the base layer, the repository config, a hub surface or an outside skill listed the checklist for that file.
- **Each checklist carries its overrides.** `overrides` is the `## Rule overrides` section read through the shared linter, with its rows and its errors. A section with any error is marked `refused`, such as one that tries to drop a floor rule.

&nbsp;

## Upgrade

No action is needed. A single-path call prints every field it printed before, in the same order, and only gains the new fields. The exit code stays 2, and nothing runs.
