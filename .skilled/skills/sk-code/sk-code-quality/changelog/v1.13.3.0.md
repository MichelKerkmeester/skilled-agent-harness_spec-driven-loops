# v1.13.3.0, One Explain Call for Many Files

Review and other callers can now ask the quality runner which surfaces and rule files apply to each file in a change. The call is read-only. They get the answer from one resolver. So they no longer need their own surface detection. A private surface that declares no quality block can still be loaded. That is because the explanation names its folder.

&nbsp;

## What's New at a Glance

- **`--explain` takes several paths.** List them after the flag, as `--files` does. Or repeat the flag once per path. A `files` array holds one entry per file. One resolution covers them all, as a run does.
- **Each surface names its folder.** `surface_skills` gives every detected surface's label. It says whether the hub or an outside skill owns it. It gives the folder to load it from. A trusted `local-*` link counts through the same trusted-root rule. The declared-surfaces reader applies that rule.
- **Each checklist names its seat.** `source` and `sources` say who listed the checklist for that file. It can be the base layer, the repository config, a hub surface or an outside skill.
- **Each checklist carries its overrides.** `overrides` is the `## Rule overrides` section, read through the shared linter. It holds its rows and its errors. A section with any error is marked `refused`. One example is a section that tries to drop a floor rule.

&nbsp;

## Upgrade

No action is needed. A single-path call prints every field it printed before, in the same order. It only gains the new fields. The exit code stays 2. Nothing runs.
