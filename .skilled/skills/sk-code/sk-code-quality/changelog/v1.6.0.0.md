# v1.6.0.0, One Runner Gives a Verdict in Any Repository

The quality mode had a checker and a list of checklists. It had no command that said what a change needed. In a repository with no `.skilled/` tree it escalated. It gave no answer. `scripts/quality-gate.cjs` now prints one verdict for the change in any repository. `references/runner-contract.md` documents every field of that verdict.

&nbsp;

## What's New at a Glance

- The runner gives one verdict per change.
  - The runner reads `--worktree`, `--base <ref>` or `--files`.
  - It prints `json`, `text` or the `code-quality/v1` envelope.
  - Its gate is `NO_BLOCKER_FOUND`, `BLOCKED`, `NOTHING_CHECKED`, `ERROR` or `UNVERIFIED`.
  - Exit codes run from 0 to 4.
  - No value means pass.
- The runner uses only built-in checks and makes no writes.
  - It runs conflict-marker, secret and debug-leftover sensors.
  - It makes one comment-hygiene call.
  - It applies a parse floor chosen by shebang before extension.
  - It writes no file and runs no repository command.
  - A content-hash guard ends the run with exit 3 if a check changes the workspace.
  - The conflict and secret sensors scan every readable text file.
  - That includes a `.env` or Markdown file.
  - No part of a key reaches any output.
  - That includes a parser's error message.
- Old debt stops blocking new work.
  - A hygiene finding on a changed line blocks.
  - One on an unchanged line of a touched file blocks only in one case.
  - A pre-commit or CI layer that scans whole files must be present.
  - The verdict probes those layers instead of assuming them.
- Missing tools are never clean.
  - When `python3` is absent, hygiene reads `SKIPPED_ABSENT`.
  - The run then exits 4 with `UNVERIFIED`.
- Checklists come from declarations.
  - The universal floor and this mode's rows live in `assets/quality-defaults.json`.
  - Each surface declares its own rows.
  - The target map in `SKILL.md` renders them.
  - A test keeps the two equal.
- The workflow runs the runner.
  - `SKILL.md` names it in its tree, loading table, workflow, envelope and rules.
  - The workflow applies the Design Restraint Ladder before a gate fix adds code.
  - `DEFAULT_RESOURCE` now names the runner contract in place of the SKILLED checklist.
  - `README.md` describes the same flow.
- The `node --test` suite holds twelve named fixtures and fifteen unit cases.
- CI runs it beside the four bash suites.

&nbsp;

## Upgrade

The SKILLED universal checklist now loads only when SKILLED is a resolved surface of the target. A caller that loaded it for every target should load what the verdict's `checklists[]` names instead. `--config` is rejected with exit 3 in this release.
