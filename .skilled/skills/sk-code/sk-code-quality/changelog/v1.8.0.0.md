# v1.8.0.0, The Checklists Speak the Runner's Language

This release follows 1.7.0.0. The quality runner never claims a pass, but the verification template still asked for `PASS` or `BLOCKED`, and the mode still escalated on any unknown surface. Both now match the amended doctrine, which gives an unknown surface the universal floor.

> Spec folder: `specs/sk-code/015-quality-agnostic-gate/004-doctrine` (Level 2)

&nbsp;

## What's New at a Glance

- **The template records the runner's gate.** Both Gate Result lines in `verification-quick-reference-and-related.md` take `NO_BLOCKER_FOUND`, `BLOCKED`, `NOTHING_CHECKED`, `UNVERIFIED` or `ERROR`, the gate the runner printed. No value means pass.
- **The mode escalates on a check it cannot prove.** The first ESCALATE IF item in `SKILL.md` now fires when a required P0 check is UNVERIFIED and only the operator can name or install its tool. An unknown surface no longer escalates, because it gets the floor. The P0 table points at the tier rules and the P0 categories in `code-quality-standards.md`.
- **No checklist names a private skill.** Three lines that named the operator's private Webflow skill now say an operator-private Webflow surface skill, because a tracked file never names a private skill.
- **The GPU-only animation check is P2.** CHK-CSS-09 moved from P0 to P2, since performance polish is P2 in the universal tiers. The CSS pass criteria now rest on CHK-CSS-10 and CHK-CSS-11.
- **The style guide points at the repository.** It names the repository's `AGENTS.md`, when present, in place of one user's projects.

&nbsp;

## Upgrade

A summary that recorded `PASS` now records the gate the runner printed. CSS animation work that relied on CHK-CSS-09 to block completion now relies on CHK-CSS-10 and CHK-CSS-11 at P1.
