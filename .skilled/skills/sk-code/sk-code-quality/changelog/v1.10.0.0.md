# v1.10.0.0, The Runner Closes Its Own Gaps

This release follows 1.9.0.0. Five items the runner's own record left open are now settled. A green pre-commit layer proves the checker its hook names can run. A declared build output is checked with no file written anywhere. Fifty changed files finish under two seconds. The guard's blind spots are written down. A framework checklist no longer reaches a repository the runner cannot check.

&nbsp;

## What's New at a Glance

- **A present pre-commit layer proves the checker can run.** The probe reads the path its hook names. It resolves that path against the repository and both source roots. It reports `broken` with a repair line when the path is missing. It reports the same when the path is a directory or lacks the execute bit. That state also decides whether a finding on an untouched line blocks the run. So a checker that never runs no longer lends it that authority.
- **The dist adapter checks the build outputs this repository ships.** Eight generated paths are declared. A declared path reaches the adapter even though the base layer excludes `**/dist/**`. No other check reads it. The runner asks the freshness library for its read-only path. So the verdict is unchanged. No cache record appears beside a dist entry.
- **Fifty changed files take under a second.** A run read the untracked files three times. It read them once for the scope and once per guard snapshot. Each read walked the whole tree. One bounded listing is now shared. A named-file scope reads none of it. The same command measured 1.97 s to 2.32 s before the change. It measures 0.72 s to 0.98 s after it.
- **The guard boundary is stated rather than implied.** It hashes the tracked diff and the named files. It also hashes the untracked files inside the folders the scope reaches. It hashes the commit `HEAD` names. No ignored path is hashed. A bounded ignored watch was measured at the folders a scope lands on. It was refused. That is because 327 to 1232 ms against a 50 ms budget is coverage no contract could promise. No contract could promise that run to run.
- **The spec-folder checklist stays in the repository that owns the hub.** A base-layer row may now carry a repository condition. A foreign repository holding a `specs/` folder lists no framework-specific checklist. This repository's own spec files keep theirs. The three `.js` and `.css` rows keep matching by path alone.
- **A review round closed four gaps the first pass left.** Every declared build output is now checked against the package that builds it. That is because the freshness library maps a dist entry back to its package. The adapter reads an unmatched verdict for a declared path as `ERROR`. A `--files` run bounds both guard snapshots to the folders its named files sit in. So a file a check creates beside one is caught. A configured check that reads source no longer reads a base-declared build output. The repository's own `exclude` list can take one out of a run. A hook that quotes its checker path variable resolves to the checker. So does a hook that builds it with `$(...)`. Neither reads `broken`.
- **A dist check that cannot answer reads as an error.** In the read-only mode the checker prints one `DIST FRESHNESS CHECK ERROR:` line. That line names the file and the reason. It prints when the checker throws, exits non-zero or prints nothing. It also prints for a payload with no status. It prints for a package reported unprovisioned. The adapter scores that line as `ERROR`. So a build nobody could verify no longer reads clean. The session path stays quiet. That is because a broken checker there is no news a hook can act on.
- **The hook probe reads the spellings hooks use, and a repository runs its own build row.** A checker named by a plain path now reads `present`. So does a path after `sh`, `bash`, `cd ... &&` or a trailing `|| true`. So does one reached through a `${NAME:-default}/` default or a nested `$(...)`. A mention that sits only in a shell comment names no checker. It reads `absent`. A repository may declare its own `generated` row. That row runs on the paths it declares. The configured matcher had inverted that. The runner contract states the named-file guard bound and its measured cost. It states the error rule for an unassessable dist check. It states these spellings.

&nbsp;

## Upgrade

No migration required. A repository that wants its own build outputs checked declares them. They go in the `generated` rows of its quality config. Such a row runs on the paths it names. A gate run over a foreign repository no longer lists the framework's spec-folder checklist. The runner contract states what the guard can and cannot see.
