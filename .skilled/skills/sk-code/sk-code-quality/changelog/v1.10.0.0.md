# v1.10.0.0, The Runner Closes Its Own Gaps

This release follows 1.9.0.0. Five items the runner's own record left open are now settled. A green pre-commit layer proves the checker its hook names can run, a declared build output is checked with no file written anywhere, fifty changed files finish under two seconds, the guard's blind spots are written down, and a framework checklist no longer reaches a repository the runner cannot check.

> Spec folder: `specs/sk-code/015-quality-agnostic-gate/008-runner-limit-closeout` (Level 2)

&nbsp;

## What's New at a Glance

- **A present pre-commit layer proves the checker can run.** The probe reads the path its hook names, resolves it against the repository and both source roots, and reports `broken` with a repair line when the path is missing, is a directory or lacks the execute bit. That state also decides whether a finding on an untouched line blocks the run, so a checker that never runs no longer lends it that authority.
- **The dist adapter checks the build outputs this repository ships.** Eight generated paths are declared, and a declared path reaches the adapter even though the base layer excludes `**/dist/**`, while no other check reads it. The runner asks the freshness library for its read-only path, so the verdict is unchanged and no cache record appears beside a dist entry.
- **Fifty changed files take under a second.** A run read the untracked files three times, once for the scope and once per guard snapshot, and each read walked the whole tree. One bounded listing is now shared, and a named-file scope reads none of it. The same command that measured 1.97 s to 2.32 s before the change measures 0.72 s to 0.98 s after it.
- **The guard boundary is stated rather than implied.** It hashes the tracked diff, the untracked files inside the folders the scope reaches, the commit `HEAD` names and the named files. No ignored path is hashed. A bounded ignored watch was measured at the folders a scope lands on and refused, because 327 to 1232 ms against a 50 ms budget is coverage no contract could promise run to run.
- **The spec-folder checklist stays in the repository that owns the hub.** A base-layer row may now carry a repository condition. A foreign repository holding a `specs/` folder lists no framework-specific checklist, while this repository's own spec files keep theirs, and the three `.js` and `.css` rows keep matching by path alone.
- **A review round closed four gaps the first pass left.** Every declared build output is now checked against the package that builds it, because the freshness library maps a dist entry back to its package and the adapter reads an unmatched verdict for a declared path as `ERROR`. A `--files` run bounds both guard snapshots to the folders its named files sit in, so a file a check creates beside one is caught. A configured check that reads source no longer reads a base-declared build output, and the repository's own `exclude` list can take one out of a run. A hook that quotes its checker path variable, or builds it with `$(...)`, resolves to the checker instead of reading `broken`.
- **A dist check that cannot answer reads as an error.** In the read-only mode the checker prints one `DIST FRESHNESS CHECK ERROR:` line, naming the file and the reason, when the checker throws, exits non-zero, prints nothing, prints a payload with no status or reports the package unprovisioned. The adapter scores that line as `ERROR`, so a build nobody could verify no longer reads clean. The session path stays quiet, because a broken checker there is no news a hook can act on.
- **The hook probe reads the spellings hooks use, and a repository runs its own build row.** A checker named by a plain path, by a path after `sh`, `bash`, `cd ... &&` or a trailing `|| true`, through a `${NAME:-default}/` default or through a nested `$(...)` now reads `present`, while a mention that sits only in a shell comment names no checker and reads `absent`. A repository that declares its own `generated` row has that row run on the paths it declares, which the configured matcher had inverted. The runner contract states the named-file guard bound and its measured cost, the error rule for an unassessable dist check, and these spellings.

&nbsp;

## Upgrade

No migration required. A repository that wants its own build outputs checked declares them in the `generated` rows of its quality config, and such a row runs on the paths it names. A gate run over a foreign repository no longer lists the framework's spec-folder checklist, and the runner contract states what the guard can and cannot see.
