# v1.13.7.0, The Gate Applies Rule Overrides and the Doctor Shows Them

A repository could write a `## Rule overrides` section in its checklist, but only `--explain` read it. A run ignored the section, so a refused row passed unseen and an accepted one left no record. `/doctor:sk-code quality` showed the config and its tools, never what the gate would apply.

> Spec folder: `specs/sk-code/017-portable-code-modes/009-integration-fixes` (Level 2)

&nbsp;

## What's New at a Glance

- **A run reads every override section it loads.** A section the shared linter refuses, such as one that names a hard-floor rule, ends the run `ERROR` with `CONFIG_INVALID`, exit 3. So does a row whose rule id no declaring document carries, read from the hub's new rule id registry. The error names the checklist and every reason.
- **Accepted rows are recorded.** The verdict gains `rule_overrides`. The envelope's `p0_p1_p2_decisions` lists each row that applies as `override <rule id> <none|replace> from <checklist file>`, ahead of `PENDING_AGENT_JUDGMENT`, which stays for the agent's own dispositions.
- **Conflicts keep the default.** Two checklists at the same precedence level that disagree on one rule for one file are listed in `rule_conflicts` and as `override-conflict` in the decisions. The rule keeps its default and joins `summary.unverified`, so the gate reads `UNVERIFIED`. Rows that give the same action and text agree. `--explain` gains a per-file `rule_conflicts` field from the same pass.
- **The doctor lists what the gate would apply.** Status names each checklist with its seat (`default`, `repo-config`, `hub-surface` or `outside-skill`), its override rows or refusal reasons, each `override-conflict` a sampled file reaches and the hygiene rules in force. It reads them through `quality-gate.cjs --explain` over a sample of the tree and runs no check.
- **Every repository checklist is checked.** A `checklists[]` row the sample did not reach is listed as declared, its file must exist and its section must lint and name known rules. A missing file or a refused section fails the status with the code a gate run would give.
- **The docs name the outside-repository limit.** A surface skill in another repository is never discovered. `SKILL.md` and `references/quality-config.md` say how such a repository declares its rules in `.sk-code/quality.json` instead.

&nbsp;

## Upgrade

No migration required in a repository whose checklists carry no `## Rule overrides` section. A checklist with a refused section now stops every run that loads it, so check one with `node .skilled/skills/sk-code/shared/scripts/check-rule-overrides.cjs <checklist.md>` before the config names it.
