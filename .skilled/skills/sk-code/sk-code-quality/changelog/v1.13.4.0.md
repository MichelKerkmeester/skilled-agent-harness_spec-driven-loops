# v1.13.4.0, A Repository Can Switch Hygiene Rules Off

The 21 core comment-hygiene rules blocked at P0 in every repository. None could be turned off. A repository whose comments say `Fixes #12` or name a model such as `T1000` was blocked. The rules that blocked it were written for this framework's own planning labels.

&nbsp;

## What's New at a Glance

- A `commentHygiene.disableRules` key in `.sk-code/quality.json` lists core rules to switch off.
  - Write a rule bare (`task`) or with its class (`hygiene.task`).
  - The names come from the checker's own pattern table.
  - An unknown id is `CONFIG_INVALID`, exit 3.
  - So is any id the shared `rule-overrides.json` fixes, such as `secret.private-key`.
  - The secret and conflict-marker sensors stay separate checks.
  - No key switches them off.
  - `schemaVersion` stays 1.
- The checker accepts a `--disable-rule ID` flag.
  - The checker takes the flag directly.
  - You can repeat it.
  - The checker refuses an unknown or fixed id with a usage error.
  - Its JSON document gains `disabled_rules` only when a rule is off.
- The verdict names which rules are off.
  - `config.hygiene.disabled` lists each disabled rule as `hygiene.<rule>`.
  - `config.hygiene.disabled` is empty when the key is absent.
  - The text format adds a `hygiene disabled:` line only when a rule is off.
- Pre-commit and CI honor `disableRules` only.
  - A new helper, `scripts/hygiene-config-flags.cjs`, reads the key through the runner's own loader.
  - The helper prints one `--disable-rule` flag per disabled rule.
  - The pre-commit hook and the CI hygiene job call it.
  - So a rule a repository switched off no longer blocks its commit or its pull request.
  - A ticket prefix, an extra pattern or a mapped extension still reaches the runner alone, as before.
  - A config that does not validate leaves both layers on every core rule, with a warning.
- The doctor shows and suggests `disableRules`.
  - `/doctor:sk-code quality status` prints the disabled rules.
  - `init` in a repository with no `specs/` folder suggests the 15 spec-kit vocabulary rules for `disableRules`.
  - `init` never writes them.

&nbsp;

## Upgrade

No action is needed. A repository with no `disableRules` key runs every core rule in every layer. Its other `commentHygiene` keys reach the runner alone, as before.
