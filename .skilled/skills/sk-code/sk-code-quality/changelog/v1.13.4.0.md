# v1.13.4.0, A Repository Can Switch Hygiene Rules Off

The 21 core comment-hygiene rules blocked at P0 in every repository, and none could be turned off. A repository whose comments say `Fixes #12` or name a model such as `T1000` was blocked by rules written for this framework's own planning labels.

> Spec folder: `specs/sk-code/017-portable-code-modes/002-quality-hygiene-policy` (Level 2)

&nbsp;

## What's New at a Glance

- **`commentHygiene.disableRules` in `.sk-code/quality.json`.** It lists core rules to switch off, written bare (`task`) or with their class (`hygiene.task`). The names come from the checker's own pattern table. An unknown id is `CONFIG_INVALID`, exit 3, and so is any id the shared `rule-overrides.json` fixes, such as `secret.private-key`. The secret and conflict-marker sensors stay separate checks that no key switches off. `schemaVersion` stays 1.
- **`--disable-rule ID` on the checker.** The checker takes the flag directly, repeatable, and refuses an unknown or fixed id with a usage error. Its JSON document gains `disabled_rules` only when a rule is off.
- **The verdict names what is off.** `config.hygiene.disabled` lists each disabled rule as `hygiene.<rule>`, and it is empty when the key is absent. The text format adds a `hygiene disabled:` line only when a rule is off.
- **Pre-commit and CI honor `disableRules` only.** A new helper, `scripts/hygiene-config-flags.cjs`, reads the key through the runner's own loader and prints one `--disable-rule` flag per disabled rule. The pre-commit hook and the CI hygiene job call it, so a rule a repository switched off no longer blocks its commit or its pull request. A ticket prefix, an extra pattern or a mapped extension still reaches the runner alone, as before. A config that does not validate leaves both layers on every core rule, with a warning.
- **The doctor shows and suggests it.** `/doctor:sk-code quality status` prints the disabled rules. `init` in a repository with no `specs/` folder suggests the 15 spec-kit vocabulary rules for `disableRules` and never writes them.

&nbsp;

## Upgrade

No action is needed. A repository with no `disableRules` key runs every core rule in every layer, and its other `commentHygiene` keys reach the runner alone, as before.
