# v1.13.9.0, The Quality Config Lives Inside the Skill Folder

A repository's quality config names the commands the gate runs and the checklists it applies, and it sat at the repository root as `.sk-code/quality.json`. It now travels with the mode that reads it, at `repository/quality.json` in the `sk-code-quality` packet, so an install under `.opencode/` keeps the same path.

> Spec folder: `specs/sk-code/017-portable-code-modes/016-repository-config-in-skill` (Level 2)

&nbsp;

## What's New at a Glance

- **Discovery reads the skill-folder file.** The order is `--config`, the stored `skcode.qualityConfig`, then `repository/quality.json` in the packet, resolved under `.skilled/` or `.opencode/`, then none. `init` writes the same path and refuses a skill folder that resolves outside the repository.
- **A config names the repository it was written for.** A `repository` field of `<owner>/<name>` applies only where the checkout matches, read from `GITHUB_REPOSITORY` in CI and from the origin remote otherwise. A copy that names another repository is reported as `ignored` by the gate and the doctor, and applied to nothing.
- **A config at the old root path is refused.** `.sk-code/quality.json` exits 3 with `CONFIG_LEGACY_LOCATION` and a repair line that names the move, so a stale copy cannot look configured while the gate reads nothing. A `--config` or git config path inside `.sk-code/` is refused the same way. The quality reference, the README, the playbook and the runner tests name the new path.

&nbsp;

## Upgrade

A repository that committed `.sk-code/quality.json` moves it to `.skilled/skills/sk-code/sk-code-quality/repository/quality.json`, or names the new path with `--config` or `skcode.qualityConfig`. A repository with no config needs nothing.
