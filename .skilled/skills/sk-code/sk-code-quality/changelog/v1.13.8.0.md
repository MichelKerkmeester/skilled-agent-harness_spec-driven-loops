# v1.13.8.0, The Quality Docs Describe the Rules a Repository Can Change

The README and the scripts READMEs still described a quality gate whose rules no repository could change, and the playbook had no scenario for a repository that does not share the house style. They now describe the shipped behavior and the playbook proves it.

> Spec folder: `specs/sk-code/017-portable-code-modes/010-docs-and-doctor-alignment` (Level 2)

&nbsp;

## What's New at a Glance

- **A new README section lists the levers.** It names the fixed and overridable floor rules, the `## Rule overrides` section of a checklist the repository already declares and `commentHygiene.disableRules`, with the verdict field that lists what is off.
- **The explain entry is documented as it works.** `--explain` takes several paths, and each file's entry lists its surfaces, the folder each surface loads from, the seat that declared each checklist and its parsed override rows. `SKILL.md` carries the same description.
- **The library and script READMEs match the code.** `quality-config.cjs` lists the hygiene helpers and the `disableRules` validation, and the runner row describes the multi-file explain output.
- **Two playbook scenarios were added.** One shows a repository that switches a hygiene rule off and is no longer blocked by it, and the other shows a hard-floor row and a fixed hygiene id refused. Both were run, and the existing scenario ids are unchanged.
- **The feature catalog is current.** The quality gate and repository config entries are updated, and a new entry covers the rule overrides and the hygiene policy.
