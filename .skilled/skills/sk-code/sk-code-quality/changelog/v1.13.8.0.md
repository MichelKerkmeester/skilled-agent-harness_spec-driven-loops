# v1.13.8.0, The Quality Docs Describe the Rules a Repository Can Change

The README and the scripts READMEs still described a quality gate. No repository could change its rules. The playbook had no scenario for a repository that does not share the house style. They now describe the shipped behavior. The playbook proves it.

&nbsp;

## What's New at a Glance

- **A new README section lists the levers.** It names the fixed and overridable floor rules. It names the `## Rule overrides` section of a checklist the repository already declares. It names `commentHygiene.disableRules` and the verdict field that lists what is off.
- **The explain entry is documented as it works.** `--explain` takes several paths. Each file's entry lists its surfaces and the folder each surface loads from. It lists the seat that declared each checklist and its parsed override rows. `SKILL.md` carries the same description.
- **The library and script READMEs match the code.** `quality-config.cjs` lists the hygiene helpers and the `disableRules` validation. The runner row describes the multi-file explain output. It also describes what a run does with an override section. A refused section or an unknown rule id is `CONFIG_INVALID`. Accepted rows are recorded. A same-level conflict makes the rule unverified. The scripts README also names the doctor as a consumer. Two of its count claims carry a reason marker.
- **The README says what a run applies.** The section on rules a repository can change states the refusal. It states the recorded decisions and the conflict outcome. It points at `/doctor:sk-code quality` for the whole-repository view.
- **Two playbook scenarios were added.** One shows a repository that switches a hygiene rule off. That repository is no longer blocked by it. It sees both its rows recorded in the run's decisions. The other shows a hard-floor row and a fixed hygiene id refused. Both were run. The existing scenario ids are unchanged.
- **The feature catalog is current.** The quality gate and repository config entries are updated. A new entry covers the rule overrides and the hygiene policy.
