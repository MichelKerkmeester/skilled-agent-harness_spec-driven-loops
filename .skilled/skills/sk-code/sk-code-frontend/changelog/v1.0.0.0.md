# v1.0.0.0, The Frontend Surface Is Established

The first `sk-code-frontend` release gives web work a single written standard. The packet is a read-only surface on the `sk-code` hub's surface axis, bundled beside a workflow mode and never routed as a primary.

> Spec folders: `specs/sk-code/018-frontend-upstream-proposals/001-frontend-surface-mode` and `007-web-only-frontend` (Level 2)

&nbsp;

## Why This Release

Frontend practice was spread across the framework in the head of whoever last shipped a screen. Which element carries a behavior, where a focus ring belongs, how a long list keeps its rows readable and what a Figma comparison must cover were review memory rather than a reference. A frontend change reviewed as an unknown surface loaded none of it.

&nbsp;

## What's New at a Glance

- **A core page and a web layer.** `references/frontend-practice.md` holds the practice the web layer implements, then `references/web-markup-and-css.md` adds the DOM and CSS mechanics for the app in front of you.
- **Six web topic references, loaded by condition.** The files cover elements and attributes, cascade and selectors, layout and sizing, accessibility patterns, performance and loading, and internationalization.
- **A five-pass Figma check.** `references/figma-to-code.md` compares a built screen with its Figma frame in five passes. A pass that cannot run is marked `NOT RUN` with its reason, and the overall verdict is `INCOMPLETE`.
- **An overrides contract.** A project records each change to a core or web-layer statement under a `Frontend overrides` heading in its own `SKILL.md`, naming the section, the kind of change and the reason.
- **Shared workflow doctrine through symlinks.** Implement, debug and verify arrive from `shared/references/` rather than a forked copy.
- **Nothing is written.** The packet supplies evidence and the paired workflow mode applies it.

&nbsp;

## Upgrade

No migration required. The packet is additive and edits no project file.
