# v1.0.3.0, One Routing Position Across the Surface Packets

The frontend surface puts SMART ROUTING where the other two surface packets put it, and the Figma-to-code check now reads in the order the work happens. Two support fields also lost a sentence pair that an earlier merge had duplicated.

> Spec folder: `specs/sk-code/018-frontend-upstream-proposals/010-reference-readability-research` (Level 2)

&nbsp;

## Why This Release

A reader who learned the section order on one surface packet met a different order here, because SMART ROUTING sat last instead of third and the packets disagreed about how a surface opens. Inside the Figma check, the passes and the verdict came before the tool ladder and the transport that decide which passes can run. Both now follow the order a reader uses them in.

&nbsp;

## What's New at a Glance

- **SMART ROUTING is section 3.** SURFACE STANDARDS becomes 4 and FRONTEND OVERRIDES becomes 5, so all three surface packets open the same way.
- **The Figma check follows the work.** The tool ladder and the transport come before the five passes, and the verdict and report close the section after the capture mechanics.
- **The Figma overview orients first.** Purpose and When to Use now precede Core Principle.
- **Support fields state each fact once.** The repeated `srcset` and `overscroll-behavior` sentence pairs are reduced to one each.

No action is needed.
