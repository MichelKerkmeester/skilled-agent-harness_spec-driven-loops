# v1.0.2.0, References That Render As Written

The third `sk-code-frontend` release changes how the references read, not what they say. The packet is still a read-only surface on the `sk-code` hub's surface axis, and its routing is unchanged.

> Spec folder: `specs/sk-code/018-frontend-upstream-proposals/009-reference-restructure` (Level 2)

&nbsp;

## Why This Release

The rule files wrote each rule as six bold-labelled lines with nothing between them, so Markdown joined Rule, Why, When not to, Pitfall, Support and See also into one paragraph. In `web-markup-and-css.md`, six `**Deeper:**` lines sat directly above a horizontal rule, which renders them as headings. The overview sections were content sections with `OVERVIEW AND` added to the title, so no file said what it was for before its first rule. The web layer also carried Angular-only rules, although it is framework-neutral web practice.

&nbsp;

## What's New at a Glance

- **One line per rule field.** Every rule is a bulleted field list, so each field renders on its own line. A rule that named two or three features keeps them in one `Support` field.
- **A real overview in every file.** Each reference opens with a one-line intro and a `## 1. OVERVIEW` holding Purpose, When to Use and Boundaries. The first rule group moves into its own numbered section.
- **Linked sources.** Every `See also` is a titled link instead of a bare URL.
- **Content where it belongs.** The `bdg` capture recipes move from `web-markup-and-css.md` into `figma-to-code.md`, as "Capture Mechanics on the Web" under the check. `P10. Main-thread long tasks` moves from image delivery to the interaction section.
- **No Angular-specific rules.** The Angular framework block, `I8` and the Angular locale section are removed, and `CS3`, `A15`, `A16`, `A17` and `A18` read framework-neutral. `I9` keeps its id.

&nbsp;

## Upgrade

No migration required. Rule ids are stable apart from the removed `I8`. The core, web-layer and Figma-check section anchors that other files link to are unchanged. In the rule files, the sections after the overview are renumbered by one, and the sibling links that pointed at them follow.
