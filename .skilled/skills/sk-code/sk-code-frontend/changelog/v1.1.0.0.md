# v1.1.0.0, The Surface Decides Visual Values

The frontend surface now carries the value scales and visual review it used to borrow. An open value is decided here, from a scale, rather than handed to the design hub.

> Spec folder: `specs/sk-design/021-deprecate-fundamentals` (Level 2)

&nbsp;

## What's New at a Glance

- **`web-visual-values.md`** holds the spacing, type, weight, opacity, shadow, radius and duration scales, the HSL colour ramp method, elevation, typography detail, tokens and the hard rules.
- **`web-visual-hierarchy.md`** holds the hierarchy method, the symptom-to-fix tables, the build procedure, the UX laws and the WCAG-cited visual review pass.
- **`web-motion-and-interaction.md`** holds the animation principles, the enforceable motion ruleset and the input, touch, focus, performance and feedback rules.
- **`assets/tokens.css`** is a contrast-verified starter token file.
- **Three router intents,** `WEB_VISUAL_VALUES`, `WEB_VISUAL_HIERARCHY` and `WEB_MOTION`, load them. The hierarchy intent now loads `web-accessibility-patterns.md`, so a visual review finding can point at the accessibility pattern that fixes it. `WEB_A11Y` also catches focus-outline and missing-label review phrases.
- **Focus rings stay visible in forced-colors mode.** The new references point to the A5 and A8 accessibility items instead of recommending a shadow-only ring.
- **An animated shadow no longer repaints on every frame.** The elevation guidance puts the target shadow on a pseudo-element and fades the pseudo-element's opacity for 180ms, in the direct-feedback band.
- **A session-expiry redirect is a UX convenience, not a security boundary.** The motion guidance says the server still refuses every data request from the expired session and the client clears its cached protected data.
