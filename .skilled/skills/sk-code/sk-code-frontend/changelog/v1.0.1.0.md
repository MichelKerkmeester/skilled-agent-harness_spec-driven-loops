# v1.0.1.0, A Playbook And A Uniform Reference Shape

The second `sk-code-frontend` release gives the surface an operator corpus. It also finishes the shape of the references it ships. The packet is still a read-only surface on the `sk-code` hub's surface axis. It is bundled beside a workflow mode. It is never routed as a primary.

&nbsp;

## Why This Release

Two intent families shipped with no way to check them by hand. A reviewer could read `ROUTER.md` and believe the web and Figma paths were wired. But nothing replayed a prompt and compared the emitted resources with the map. The references also read unevenly. Some opened straight into a rule table. Long tables ran from one section into the next with no break. One recipe went further and named a call that does not work. So a reader following the token check could not reproduce it.

&nbsp;

## What's New at a Glance

- **A packet-level manual testing playbook.** `manual-testing-playbook/manual-testing-playbook.md` is the root index. `manual-testing-playbook/frontend-surface/` holds two scenarios. `frontend-surface-web` is for `FRONTEND_WEB`. `frontend-surface-figma-check` is for `FIGMA_TO_CODE`.
- **Routes the hub's guard replays.** Each scenario declares the `expected_intent` and `expected_resources` the packet router emits for its exact prompt. So check 4 of `sk-code-skilled/assets/scripts/verify-router-sync.cjs` now walks the frontend packet as well as the CI packet.
- **A graded Figma verdict.** The Figma scenario checks the verdict rule as well as the route. A pass that cannot run is recorded as `NOT RUN` with its reason. The overall Figma verdict is then `INCOMPLETE`, never `PASS`.
- **An overview section on every reference.** Each file in `references/` now opens with a `## 1. OVERVIEW` section. It states what it owns and which layer it belongs to. So a reader knows the boundary before the rules.
- **Dividers between sections.** Every reference separates its numbered sections with a horizontal rule. So a long table ends where the next section starts.
- **The working bdg call.** The web token check names `bdg cdp Runtime.evaluate` as the read for resolved styles. That is because `bdg dom eval` failed with "Session target not found" in the same session. `references/web-markup-and-css.md` carries the recipe set that ran against `bdg` 0.6.10. That set includes the viewport, colour-scheme, state and zoom calls.
- **Routing adds two aliases.** `keyboard focus` joins `WEB_A11Y` and `figma frame` joins `FIGMA_TO_CODE`. Both are in `ROUTER.md` and in the hub's mirrored vocabulary. The resource map is unchanged. The playbook asserts the routes rather than changing them.

&nbsp;

## Upgrade

No migration required. The playbook is additive. The reference edits change no path. The packet still edits no project file.
