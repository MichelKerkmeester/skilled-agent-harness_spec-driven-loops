# v1.0.1.0, A Playbook And A Uniform Reference Shape

The second `sk-code-frontend` release gives the surface an operator corpus and finishes the shape of the references it ships. The packet is still a read-only surface on the `sk-code` hub's surface axis, bundled beside a workflow mode and never routed as a primary.

> Spec folders: `specs/sk-code/018-frontend-upstream-proposals/006-open-items-and-alignment` and `007-web-only-frontend` (Level 2)

&nbsp;

## Why This Release

Two intent families shipped with no way to check them by hand. A reviewer could read `ROUTER.md` and believe the web and Figma paths were wired, but nothing replayed a prompt and compared the emitted resources with the map. The references also read unevenly: some opened straight into a rule table, and long tables ran from one section into the next with no break. One recipe went further and named a call that does not work, so a reader following the token check could not reproduce it.

&nbsp;

## What's New at a Glance

- **A packet-level manual testing playbook.** `manual-testing-playbook/manual-testing-playbook.md` is the root index, and `manual-testing-playbook/frontend-surface/` holds two scenarios: `frontend-surface-web` for `FRONTEND_WEB` and `frontend-surface-figma-check` for `FIGMA_TO_CODE`.
- **Routes the hub's guard replays.** Each scenario declares the `expected_intent` and `expected_resources` the packet router emits for its exact prompt, so check 4 of `sk-code-skilled/assets/scripts/verify-router-sync.cjs` now walks the frontend packet as well as the CI packet.
- **A graded Figma verdict.** The Figma scenario checks the verdict rule as well as the route: a pass that cannot run is recorded as `NOT RUN` with its reason, and the overall Figma verdict is then `INCOMPLETE`, never `PASS`.
- **An overview section on every reference.** Each file in `references/` now opens with a `## 1. OVERVIEW` section that states what it owns and which layer it belongs to, so a reader knows the boundary before the rules.
- **Dividers between sections.** Every reference separates its numbered sections with a horizontal rule, so a long table ends where the next section starts.
- **The working bdg call.** The web token check names `bdg cdp Runtime.evaluate` as the read for resolved styles, because `bdg dom eval` failed with "Session target not found" in the same session. `references/web-markup-and-css.md` carries the recipe set that ran against `bdg` 0.6.10, including the viewport, colour-scheme, state and zoom calls.
- **Routing adds two aliases.** `keyboard focus` joins `WEB_A11Y` and `figma frame` joins `FIGMA_TO_CODE`, in `ROUTER.md` and in the hub's mirrored vocabulary. The resource map is unchanged, and the playbook asserts the routes rather than changing them.

&nbsp;

## Upgrade

No migration required. The playbook is additive, the reference edits change no path, and the packet still edits no project file.
