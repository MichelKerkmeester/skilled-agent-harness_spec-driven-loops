# v3.9.24.0, Routing Rules Move to ROUTER.md

The routing rules for sk-code moved out of SKILL.md and into a final MACHINE ROUTER section of ROUTER.md. SKILL.md stays short, and the hub routes the same way it did before.

> Spec folder: `specs/sk-doc/072-skill-routing-and-clarity/014-skill-router-files/004-hub-router-merge` (Level 1)

&nbsp;

## What's New at a Glance

- **SKILL.md keeps a single pointer.** SKILL.md no longer carries a MACHINE ROUTER section. Its SMART ROUTING section says compiled routing is the default and points to ROUTER.md.
- **The compiled-routing tooling reads the fallback checklist from ROUTER.md.** The tooling takes the checklist from the final MACHINE ROUTER section, and it hashes ROUTER.md with the other sources. Its two compiled-route test suites build their fixtures with ROUTER.md too.
- **The setup checks pass again.** Two more sk-code tests, the quality declaration test and the quality gate runner unit test, now compile the hub with its ROUTER.md machine router section. They and the surface-hint test check that the heading exists before they read the section.
- **The compiled routing entry names ROUTER.md.** The feature catalog entry for compiled routing names ROUTER.md as the home of the directive.
- **Routing is unchanged.** The map from intent to files is byte for byte the same, and every route the hub selects matches the run before the move. The compiled admission check gives the same result, and the compiled manifest was regenerated from the new sources.
- **The hub meets the routing-shape canon.** Its known-debt entry is removed, so the hub no longer needs an exception in that check.
