# sk-code v1.0.0.0, Project-Agnostic Stack Stubs

This release reconciles the multi-stack scaffolding.

- It replaces that scaffolding with honest, project-agnostic stubs.
- The change covers the NEXTJS and GO stacks.
- The Webflow stack remains live and untouched.

The stubs change folders, assets and routes.

- The NEXTJS folder changes from `nextjs` to `react`.
- Asset trees are created for NEXTJS and GO.
- `SKILL.md` marks NEXTJS and GO as scaffolded stubs.

The change also touches guidance and an older packet.

- Four carry-over guides become project-agnostic stubs.
- Cross-stack pairing guidance uses generic small-scope language.
- Packet 056 is superseded.

&nbsp;

## Why This Release

Packet 056 left the multi-stack scaffolding in a partial state.

## Stack Scaffolding

#### Folder Rename: nextjs to react <a id="c-folder-rename-nextjs-to-react"></a>

- The NEXTJS folder changes from `nextjs` to `react`.
- The folder rename ran `git mv references/nextjs references/nextjs`.
- It aligns the disk path with the `STACK_FOLDERS["NEXTJS"]` contract.
- That contract is used by `SKILL.md`, `references/stack-detection.md`, `references/smart-routing.md`, `description.json` and `graph-metadata.json`.
- Every `resource_map_for(NEXTJS)` path now resolves.

#### Stub Assets Follow a Canonical Template <a id="c-stub-assets-follow-a-canonical-template"></a>

- NEXTJS and GO receive project-agnostic stub content.
- The release created the `assets/nextjs/{checklists,patterns,integrations}/` and `assets/go/{checklists,patterns}/` directory trees.
- Those trees were previously absent.
- The release added 43 stub files across `references/{react,go}/` and `assets/{react,go}/`.
- That is 23 NEXTJS files (12 references + 3 checklists + 5 patterns + 3 integrations).
- It is also 20 GO files (12 references + 3 checklists + 5 patterns).
- Each stub uses the canonical placeholder template.
- The template has YAML frontmatter (`status: stub`, `populated: false`, `last_synced_at: 2026-04-30`).
- It also has a short Intended-scope paragraph, Outline (TODO) bullets and See-also references.
- Markdown stubs contain no fenced code blocks.
- The stubs contain no library version pins and no project-specific names.

#### Code Stubs Have No Bodies <a id="c-code-stubs-have-no-bodies"></a>

- The `.tsx`, `.ts`, `.go`, `.css.ts` and `_test.go` stubs have no function bodies.
- They are comment-only, with two exceptions.
- Go files include the trivial `package patterns` declaration.
- The test stub uses an empty `TestStub` placeholder.

## Stack Guidance

#### Routes Distinguish the Stubs <a id="c-routes-distinguish-the-stubs"></a>

- In the Routes block (§2) of `SKILL.md`, NEXTJS and GO change from "full live content" to "scaffolded stub content".
- In Resource Domains (§2), both directories change from `LIVE` to `STUB (target: …)`.
- There, `cross_stack_pairing.md` is identified as canonical rather than a stub.
- In the frontmatter description, Webflow stays live.
- NEXTJS and GO are described as scaffolded stubs for the future.

#### Carry-Over Guides Become Project-Agnostic Stubs <a id="c-carry-over-guides-become-project-agnostic-stubs"></a>

- The release rewrote four carry-over files from packet 056 as project-agnostic stubs.
- They are `references/{react,go}/README.md` and `references/{react,go}/implementation/implementation_workflows.md`.
- The rewrite removed project-specific phrasing.
- It kept the subfolder map, asset map, verification commands and see-also sections.

&nbsp;

## Cross-Stack Pairing

#### Pairing Guidance Stays Intact <a id="c-pairing-guidance-stays-intact"></a>

- `references/cross_stack_pairing.md` remains the canonical contract.
- The release removed the project-name keyword and project-scoped phrasing.
- It used generic small-scope language instead.
- Its topology, error envelope, JWT handoff, CORS, pagination, deploy table and drift detection sections are intact.

&nbsp;

## Packet Lineage

#### Packet 056 Is Superseded <a id="c-packet-056-is-superseded"></a>

- This release supersedes packet `skilled-agent-orchestration/056-sk-code-fullstack-branch`.
- Its `spec.md` now carries a `superseded_by` frontmatter line for discoverability.
