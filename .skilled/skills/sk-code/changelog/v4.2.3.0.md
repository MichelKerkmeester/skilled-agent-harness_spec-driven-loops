# v4.2.3.0 — sk-code-mobile-cli surface de-registered from the hub

The `sk-code-mobile-cli` surface packet is retired. The hub no longer advertises, detects, routes, or
bundles it: a request shaped like Pi Remote Mobile-CLI work (`app-mobile/`, Svelte design-system, token
or editability topics) now resolves no mobile surface at all. The packet directory itself is retired
separately; this entry covers the hub's de-registration.

## Removed

- `mode-registry.json` — the `sk-code-mobile-cli` `modes[]` entry and its `extensions.surface-axis.surfaces`
  member; the mode permutation now covers five modes (two workflow, three surface).
- `hub-router.json` — the mode's `routerSignals` entry, its `code-mobile-cli-aliases` /
  `code-mobile-cli-runtime` vocabulary classes, and its `routerPolicy.tieBreak` slot.
- `ROUTER.md` — the `MOBILE_CLI` intent key, every `RESOURCE_MAP` entry under the removed packet, and the
  `PI_REMOTE` example in the §1 evidence-surface paragraph.
- `SKILL.md` — the mode's row in the §1 surface table, plus its mentions in the frontmatter description,
  the Keyword comment, and the version-authority paragraph.
- `description.json` — the removed surface's description clause and its keyword cluster.
- `shared/references/stack-detection.md` — the `PI_REMOTE` detection block and its markers (`app-mobile/`,
  `app-relay/`, `packages/pi-*`), the precedence entry, the positive test row, and the frontmatter mention.

## Why

The Pi Remote Mobile-CLI stack is retired, so a surface packet that teaches it only mis-routes live work
and inflates the hub's mode permutation with a mode nothing can reach. Removing the mode on every authored
surface at once keeps stage-one registration and stage-two routing in agreement instead of leaving a
registered-but-unreachable entry behind.

## Compatibility

Historical release notes that describe the surface (`v4.2.2.0`) are marked as superseded there; they are
not rewritten, because they record what those releases did. The regenerated `leaf-manifest.json` and the
derived vocabulary block in `graph-metadata.json` follow from their own generators.
