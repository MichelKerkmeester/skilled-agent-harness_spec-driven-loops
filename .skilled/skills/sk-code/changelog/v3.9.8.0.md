# v3.9.8.0, CI Routing Reads Cost Requests and Leaves Git Releases Alone

A request to cut CI cost went to the documentation skill, and a plain git release request went to the GitHub Actions surface. The CI surface's vocabulary now fits both cases, and the hub's feature catalog lists the features its modes ship.

> Spec folder: `specs/sk-code/015-quality-agnostic-gate/011-alignment-fixes` (Level 2)

&nbsp;

## What's New at a Glance

- **CI cost requests reach the CI surface.** "Cut our CI costs", "reduce CI spend on this repo", "make the CI pipeline cheaper", "halve our GitHub Actions minutes" and "our GitHub Actions bill is too high" now route to `sk-code-ci`. The new phrases name CI, Actions or runner minutes, such as `ci cost`, `ci spend`, `ci bill`, `reduce ci costs`, `cut ci minutes`, `ci pipeline cheaper`, `ci runs cheaper`, `make ci cheaper`, `runner minutes`, `github actions minutes`, `github actions bill` and `github actions cost`. A pipeline, a run or minutes count only next to a cost word, so a request for meeting minutes, a flowchart of the CI pipeline stages, a heatmap of CI minutes or a blog post about CI costs stays out.
- **A failing CI pipeline reaches the CI surface.** "Fix the failing CI pipeline" and "debug the CI pipeline" route to `sk-code-ci` through `failing ci`, `ci failure`, `ci is failing`, `broken ci` and `debug the ci`.
- **A git release stays with git.** The aliases `release workflow` and `deploy workflow` became `github actions release workflow`, `github actions deploy workflow`, `release workflow yaml` and `deploy workflow yaml`, so "tag the version and follow the release workflow" no longer routes to the CI surface.
- **The feature catalog covers the mode features.** New entries describe the quality gate, the repository quality config, `/doctor:sk-code`, `/doctor:ci` with its switches and the review reach rule.

&nbsp;

## Upgrade

No action is needed. A release request that relied on the bare `release workflow` phrase to reach the CI surface should name GitHub Actions.
