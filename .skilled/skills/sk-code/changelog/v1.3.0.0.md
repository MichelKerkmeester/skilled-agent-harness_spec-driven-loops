# v1.3.0.0, Language-Specific Webflow Guidance

This release gives Webflow work language-specific guidance.

- It adds annotated scaffolding, so agents and authors can work from the right rules and examples.
- It also expands CSS and HTML quality guidance.

It reorganizes sk-code's routing references.

- It reconnects reference paths left missing after the refactor.
- The spec folder is complete.

> [!IMPORTANT]
> 2 changes can break an existing setup. Read these before you update.
>
> 1. External consumers must repoint old standards paths. [Language Rules Have Separate Homes](#c-language-rules-have-separate-homes)
> 2. External consumers must update hardcoded routing paths. [Routing References Follow Barter](#c-routing-references-follow-barter)

&nbsp;

## Why This Release

This release fixes a long-standing problem.

- AI agents on Webflow sites pulled JavaScript rules into CSS tasks.
- They pulled CSS rules into JavaScript tasks too.
- They then produced code with wrong comment style, naming and banner formatting.
- The root cause was one monolithic standards folder.
- That folder mixed three languages in five files.

## Webflow Guidance

The Webflow rules now have language-specific homes.

#### Language Rules Have Separate Homes <a id="c-language-rules-have-separate-homes"></a>

> [!WARNING]
> External consumers that referenced files under the old standards folder must update those paths to the per-language tree.

- The old `references/webflow/standards/` folder held all coding rules in five files.
- A model loading the skill for a CSS-only task pulled in all JavaScript rules too.
- That led to wrong choices.
- One was applying snake_case to CSS class names.
- Another was applying CSS animation property restrictions to JavaScript callbacks.
- The old standards folder is physically deleted.
- The new tree mirrors the OpenCode side of the skill.
- `webflow/javascript/` carries `style_guide.md`, `quality_standards.md` and `quick_reference.md`.
- `webflow/css/` carries the same three references.
- It adds a fourth file, `patterns.md`.
- That is the 1,263-line Webflow CSS deep-dive.
- It was previously misfiled under `implementation/`.
- `webflow/html/` carries `style_guide.md` and `quality_standards.md`.
- `webflow/shared/` holds shared rules for file naming, comment principles and file-header banner format.
- It also holds the cross-language enforcement workflow and DevTools patterns.

#### Production Comment Patterns <a id="c-production-comment-patterns"></a>

- The previous JavaScript and CSS commenting sections invented rules.
- Those rules did not match production practice.
- The JavaScript style guide's section 5 now has nine subsections.
- They are grounded in code from `anobel.com/src/3_staging/`.
- The former `max 5 comments per 10 lines` rule was wrong.
- Real Webflow JavaScript averages one comment per five to ten lines.
- The JavaScript section-header closing format `──── */` was wrong.
- It had a space before the closing.
- Production uses `────*/` glued together.
- The JavaScript guidance also adds function preambles and group-introductory comments.
- It adds silent-catch shorthand `catch (_) {}`.
- It adds underscore prefixes for internal state.
- The CSS style guide gains a new section 7.
- It covers file-header banners, with the correct format and a space before the closing.
- It covers section-header sub-numbering, using `1.1` for fine-grained sub-states.
- It covers multi-line section descriptions for non-obvious sections.
- Section 7 also covers CSS-specific comment density.
- That is sparser than JavaScript.
- The file header is always there, and so are section headers.
- Sub-section headers appear sometimes.
- So do headers above complex selector groups, when warranted.

#### CSS Covers Seven Quality Patterns <a id="c-css-covers-seven-quality-patterns"></a>

- The CSS quality guidance lacked several common CSS patterns.
- It adds these seven deep dives:
- Fluid typography. Per-breakpoint variable overrides scale type from mobile through ultra-wide displays.
- They avoid the brittleness of `clamp()`.
- Autofill overrides. The `:-webkit-autofill` quartet covers default, hover, focus and active states.
- It uses the `box-shadow inset` trick and a `5000s transition` to paint over Chrome's yellow autofill background.
- Color-mix states. `color-mix(in srgb, var(--color-brand) 90%, white)` derives hover and active tints from one brand color token.
- Below-fold rendering. `content-visibility` uses the `auto` value with `contain-intrinsic-size` to skip render work on below-fold sections.
- Keyboard focus. The `:focus-visible` versus `:focus` guidance covers migration from the legacy `body.using-keyboard` JavaScript pattern to the modern browser-native heuristic.
- Parent-state patterns. `:has()` patterns eliminate JavaScript class toggles for form-field validation, card layouts and section visibility.
- Print stylesheets. The `@media print` reset hides navigation and modals, forces a white background and shows full URLs after links.
- The guidance also covers modern `@page` rules.

#### HTML Panels Gain Comment Rules <a id="c-html-panels-gain-comment-rules"></a>

- The HTML style guide gains a new section 7.
- It covers Webflow Site Settings custom code panels, Head and Footer.
- It adds file-level markers.
- It adds three-line section headers with five-space indentation, because `<!--` is wider.
- It adds parenthetical-context titles.
- It adds Title-cased inline labels above each script or link tag.
- It adds end-markers for multi-line script blocks.
- It also covers one convention.
- Sub-sections use letter suffixes (`4b.`) rather than decimal sub-numbering.

#### HTML Quality Gets a Home <a id="c-html-quality-gets-a-home"></a>

- `references/webflow/html/quality-standards.md` gives HTML the quality-standards companion.
- JavaScript and CSS already had one.
- It consolidates data-attribute hygiene and ARIA state-sync enforcement.
- It consolidates custom embed validation and Head and Footer panel structure validation.
- Those rules previously lived nowhere, or were scattered across other docs.

## Routing

The routing references now follow a flatter layout.

#### Routing References Follow Barter <a id="c-routing-references-follow-barter"></a>

> [!WARNING]
> External consumers that hardcoded paths under the old routing layout must update them to the new references.

- The previous routing layer spread four things across four files under `references/router/`.
- They were detection, intent scoring, resource loading and phase lifecycle.
- The Barter sk-code fork is the production sibling in the Barter monorepo.
- It uses a flatter pattern.
- It puts `stack_detection.md`, `smart_routing.md` and `phase_detection.md` at the references root.
- `router/code_surface_detection.md` is now `references/stack-detection.md`.
- `router/phase_lifecycle.md` is now `references/phase-detection.md`.
- Intent classification and resource loading content is consolidated into one new file, `references/smart-routing.md`.
- That content came from `router/intent_classification.md` and `router/resource-loading.md`.
- The new file holds the authoritative routing pseudocode in one place.
- `SKILL.md` section 2 SMART ROUTING adds explicit ANCHOR markers.
- It also adds a Phase Detection visual matching the Barter format.
- All 24 cross-references in the skill that pointed to old `router/` paths have been updated.
- Internal sk-code routing already uses generic key-derived patterns.
- It required no changes for the surface itself.
- The new per-language sub-keys resolve natively.

## Templates and Deployment

The release adds annotated templates and a staging guide.

#### Templates Cover Common Scaffolding <a id="c-templates-cover-common-scaffolding"></a>

- The five production-style annotated templates provide scaffolding.
- They cover Webflow components, embeds, Site Settings code and forms.
- The new `assets/webflow/templates/` directory contains all five:
- `component_template.js` (8.9 KB) implements the JavaScript style guide conventions.
- It includes a file header, numbered sections, an IIFE wrapper and an `INIT_FLAG` guard.
- It also includes snake_case identifiers, function preambles, a cleanup hook and an optional public API.
- `component_template.css` (7.1 KB) covers a file header, numbered sections and BEM naming.
- It covers custom properties with semantic prefixes.
- It also covers attribute selectors with the case-insensitivity flag and GPU-only animation properties.
- It adds a `prefers-reduced-motion` override and sub-numbered breakpoint sections.
- `embed_template.html` (3.9 KB) provides a `data-component` root.
- It adds `data-action` and `data-target` hooks for JavaScript event delegation.
- ARIA initial state matches the visual state.
- JavaScript handoff notes sit at the bottom.
- `head_footer_code_template.html` (9.4 KB) covers all eight standard Head sections.
- They are analytics, security meta tags, connection hints, preloads, speculative prefetch, JavaScript detection, module scripts and schema markup.
- Its two standard Footer sections cover third-party libraries and custom scripts.
- `form_scaffold_template.html` (8.9 KB) provides `data-form-field` and `data-form-input` validation hooks and ARIA attributes.
- It adds a custom select bridge pattern.
- A complete JavaScript handoff notes block sits at the bottom.

#### Staging Promotion Has Guidance <a id="c-staging-promotion-has-guidance"></a>

- A new file at `references/webflow/deployment/webflow-staging-production.md` covers staging-to-production promotion.
- That workflow was previously missing from the deployment folder.
- The file documents Webflow's built-in `.webflow.io` staging subdomain.
- It documents the `noindex` headers gotcha, which gives false-negative SEO scores on staging.
- It also documents the CSS export workflow for source-controlled mirror projects like A. Nobel.
- For externally hosted JavaScript bundles, the guide covers version-pin discipline.
- A query such as `?v=1.4.0` serves as a cache-busting value.
- It also serves as a promotion gate and a rollback hook.
- The guide also covers schema markup and structured-data sync considerations.
- It covers CDN cache invalidation behavior on R2 versus jsDelivr.
- It also covers a full pre-promote checklist.

## Reference Navigation

After the refactor, several reference paths were repaired.

#### A Missing Quick Reference Returns <a id="c-a-missing-quick-reference-returns"></a>

- The JavaScript quick reference was accidentally deleted during the refactor.
- Four other files already cross-referenced it.
- It was untracked at the time of recovery.
- So `git checkout HEAD --` did not restore it.
- The file is restored as `webflow/javascript/quick-reference.md`.
- It has a pre-commit checklist and snippets such as `waitForElement` and `waitForLibrary`.
- It has eleven one-liners.
- They cover MutationObserver, IntersectionObserver, Lenis `scrollTo`, Motion.dev `animate` and `inView`, custom event dispatch, optional chaining and form validation classes.

#### Moved Links Now Resolve <a id="c-moved-links-now-resolve"></a>

- Six bare-filename references in `references/webflow/shared/enforcement.md` now point to the correct per-language tree paths.
- One example is `[code_quality_standards.md](code-quality-standards.md)`.
- This release rewrites the surrounding "Related Documents" block as a five-link tree map.
- `implementation/css_patterns.md` moved to `css/patterns.md`.
- After that, three internal links still used unresolved same-directory `./` paths.
- The old `./` paths no longer resolved.
- Examples are `./animation_workflows.md` and `./webflow_patterns.md`.
- Those files are in `../implementation/`, not the new `css/` location.
- Three more broken paths in `shared/dev_workflow.md` section 9 now point to sibling files.
- Those files are under `../implementation/` and `../debugging/`.
- That fixes all six paths.
