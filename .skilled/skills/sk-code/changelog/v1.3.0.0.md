This release gives Webflow work language-specific guidance. It reorganizes sk-code's routing references. It adds annotated scaffolding, so agents and authors can work from the right rules and examples. It also expands CSS and HTML quality guidance. It reconnects reference paths left missing after the refactor.

The spec folder is complete.

## Why This Release

This release fixes a long-standing problem. AI agents working on Webflow sites pulled JavaScript rules into CSS tasks, and the reverse. They then produced code with the wrong comment style, naming and banner formatting. The root cause was one monolithic standards folder. It mixed three languages in five files.

## What's New at a Glance

- **Webflow rules now have language-specific homes.** JavaScript, CSS and HTML have separate references, with shared guidance for rules that apply across languages.
- **Routing references follow the Barter sk-code pattern.** The consolidated routing reference is `references/smart-routing.md`.
- **Comment guidance now reflects production conventions.** The JavaScript, CSS and HTML style guides each cover their language's comment practices.
- **CSS quality guidance gains seven deep dives.** HTML also gains its own quality-standards reference.
- **Five annotated Webflow templates provide starting points.** They cover JavaScript and CSS components, embeds, Site Settings code and forms.
- **Staging promotion now has a guide.** It covers Webflow staging and externally hosted JavaScript bundles.
- **The JavaScript quick reference returns and moved links are repaired.** Inbound references were added to the orphan deep-dive. Bidirectional cross-references were added between performance docs.

## Webflow Guidance

#### Language Rules Have Separate Homes

The old `references/webflow/standards/` folder held all coding rules in five files. A model loading the skill for a CSS-only task pulled in all the JavaScript rules too. That led to wrong choices. Examples are applying snake_case to CSS class names, or CSS animation property restrictions to JavaScript callbacks. The old standards folder is physically deleted.

The new tree mirrors the OpenCode side of the skill. `webflow/javascript/` carries `style_guide.md`, `quality_standards.md` and `quick_reference.md`. `webflow/css/` carries the same three references. It adds a fourth file, `patterns.md`. That is the 1,263-line Webflow CSS deep-dive, previously misfiled under `implementation/`. `webflow/html/` carries `style_guide.md` and `quality_standards.md`. `webflow/shared/` holds the shared rules for file naming, comment principles and file-header banner format. It also holds the cross-language enforcement workflow and DevTools patterns.

**Breaking:** External consumers that referenced files under the old standards folder must update those paths to the per-language tree.

&nbsp;

#### Production Comment Patterns

The previous JavaScript and CSS commenting sections invented rules. Those rules did not match production practice. The JavaScript style guide's section 5 now has nine subsections. They are grounded in code from `anobel.com/src/3_staging/`. The former `max 5 comments per 10 lines` rule was wrong. Real Webflow JavaScript averages one comment per five to ten lines. The JavaScript section-header closing format `──── */` was wrong. It had a space before the closing. Production uses `────*/` glued together. The JavaScript guidance also adds function preambles, group-introductory comments, silent-catch shorthand `catch (_) {}` and underscore prefixes for internal state.

The CSS style guide gains a new section 7. It covers file-header banners, with the correct format and a space before the closing. It covers section-header sub-numbering, using `1.1` for fine-grained sub-states. It covers multi-line section descriptions for non-obvious sections. Section 7 also covers CSS-specific comment density. That is sparser than JavaScript. The file header is always there, and so are section headers. Sub-section headers appear sometimes. So do headers above complex selector groups, when warranted.

&nbsp;

#### CSS Covers Seven Quality Patterns

The CSS quality guidance lacked several common CSS patterns. It adds these seven deep dives:

- **Fluid typography.** Per-breakpoint variable overrides scale type from mobile through ultra-wide displays. They avoid the brittleness of `clamp()`.
- **Autofill overrides.** The `:-webkit-autofill` quartet covers default, hover, focus and active states. It uses the `box-shadow inset` trick and a `5000s transition` to paint over Chrome's yellow autofill background.
- **Color-mix states.** `color-mix(in srgb, var(--color-brand) 90%, white)` derives hover and active tints from one brand color token.
- **Below-fold rendering.** `content-visibility` uses the `auto` value with `contain-intrinsic-size` to skip render work on below-fold sections.
- **Keyboard focus.** The `:focus-visible` versus `:focus` guidance covers migration from the legacy `body.using-keyboard` JavaScript pattern to the modern browser-native heuristic.
- **Parent-state patterns.** `:has()` patterns eliminate JavaScript class toggles for form-field validation, card layouts and section visibility.
- **Print stylesheets.** The `@media print` reset hides navigation and modals, forces a white background and shows full URLs after links. The guidance also covers modern `@page` rules.

&nbsp;

#### HTML Panels Gain Comment Rules

The HTML style guide gains a new section 7. It covers Webflow Site Settings custom code panels, Head and Footer. It adds file-level markers. It adds three-line section headers with five-space indentation, because `<!--` is wider. It adds parenthetical-context titles. It adds Title-cased inline labels above each script or link tag. It adds end-markers for multi-line script blocks. It also covers one convention. Sub-sections use letter suffixes (`4b.`) rather than decimal sub-numbering.

&nbsp;

#### HTML Quality Gets a Home

`references/webflow/html/quality-standards.md` gives HTML the quality-standards companion. JavaScript and CSS already had one. It consolidates data-attribute hygiene, ARIA state-sync enforcement, custom embed validation and Head and Footer panel structure validation. Those rules previously lived nowhere, or were scattered across other docs.

## Routing

#### Routing References Follow Barter

The previous routing layer spread four things across four files under `references/router/`. They were detection, intent scoring, resource loading and phase lifecycle. The Barter sk-code fork is the production sibling in the Barter monorepo. It uses a flatter pattern. It puts `stack_detection.md`, `smart_routing.md` and `phase_detection.md` at the references root.

`router/code_surface_detection.md` is now `references/stack-detection.md`. `router/phase_lifecycle.md` is now `references/phase-detection.md`. Intent classification and resource loading content is consolidated into one new file, `references/smart-routing.md`. That content came from `router/intent_classification.md` and `router/resource-loading.md`. The new file holds the authoritative routing pseudocode in one place. `SKILL.md` section 2 SMART ROUTING adds explicit ANCHOR markers. It also adds a Phase Detection visual matching the Barter format. All 24 cross-references in the skill that pointed to old `router/` paths have been updated.

Internal sk-code routing already uses generic key-derived patterns. It required no changes for the surface itself. The new per-language sub-keys resolve natively. **Breaking:** External consumers that hardcoded paths under the old routing layout must update them to the new references.

## Templates and Deployment

#### Templates Cover Common Scaffolding

The five production-style annotated templates provide scaffolding. They cover Webflow components, embeds, Site Settings code and forms. The new `assets/webflow/templates/` directory contains all five:

- **`component_template.js` (8.9 KB).** It implements the JavaScript style guide conventions. These include a file header, numbered sections, an IIFE wrapper and an `INIT_FLAG` guard. They also include snake_case identifiers, function preambles, a cleanup hook and an optional public API.
- **`component_template.css` (7.1 KB).** It covers a file header, numbered sections, BEM naming and custom properties with semantic prefixes. It also covers attribute selectors with the case-insensitivity flag and GPU-only animation properties. It adds a `prefers-reduced-motion` override and sub-numbered breakpoint sections.
- **`embed_template.html` (3.9 KB).** It provides a `data-component` root. It adds `data-action` and `data-target` hooks for JavaScript event delegation. ARIA initial state matches the visual state. JavaScript handoff notes sit at the bottom.
- **`head_footer_code_template.html` (9.4 KB).** Its Head template covers all eight standard sections. They are analytics, security meta tags, connection hints, preloads, speculative prefetch, JavaScript detection, module scripts and schema markup. Its two standard Footer sections cover third-party libraries and custom scripts.
- **`form_scaffold_template.html` (8.9 KB).** It provides `data-form-field` and `data-form-input` validation hooks and ARIA attributes. It adds a custom select bridge pattern. A complete JavaScript handoff notes block sits at the bottom.

&nbsp;

#### Staging Promotion Has Guidance

A new file at `references/webflow/deployment/webflow-staging-production.md` covers the staging-to-production promotion workflow. That workflow was previously missing from the deployment folder. The file documents Webflow's built-in `.webflow.io` staging subdomain. It documents the `noindex` headers gotcha, which gives false-negative SEO scores on staging. It also documents the CSS export workflow for source-controlled mirror projects like A. Nobel.

For externally hosted JavaScript bundles, the guide covers version-pin discipline. A query such as `?v=1.4.0` serves as a cache-busting value. It also serves as a promotion gate and a rollback hook. The guide also covers schema markup and structured-data sync considerations. It covers CDN cache invalidation behavior on R2 versus jsDelivr. It also covers a full pre-promote checklist.

## Reference Navigation

A multi-AI council audit ran over the post-refactor tree. It used three lenses: maintainability, discoverability, symmetry. It surfaced 14 alignment findings. All 14 are resolved in this release.

#### A Missing Quick Reference Returns

The JavaScript quick reference was accidentally deleted during the refactor. Four other files already cross-referenced it. It was untracked at the time of recovery. So `git checkout HEAD --` did not restore it. The file is restored as `webflow/javascript/quick-reference.md`. It has a pre-commit checklist and snippets such as `waitForElement` and `waitForLibrary`. It has eleven one-liners. They cover MutationObserver, IntersectionObserver, Lenis `scrollTo`, Motion.dev `animate` and `inView`, custom event dispatch, optional chaining and form validation classes.

&nbsp;

#### Moved Links Now Resolve

Six bare-filename references in `references/webflow/shared/enforcement.md` now point to the correct per-language tree paths. One example is `[code_quality_standards.md](code-quality-standards.md)`. This release rewrites the surrounding "Related Documents" block as a five-link tree map.

`implementation/css_patterns.md` moved to `css/patterns.md`. After that, three internal links still used unresolved same-directory `./` paths. The old `./` paths no longer resolved. Examples are `./animation_workflows.md` and `./webflow_patterns.md`. Those files are in `../implementation/`, not the new `css/` location. Three more broken paths in `shared/dev_workflow.md` section 9 now point to sibling files. Those files are under `../implementation/` and `../debugging/`. That fixes all six paths.

Three workflow files displayed `[shared_patterns.md]`. They linked to `../shared/dev_workflow.md`. Their display text now matches the actual filename, `dev_workflow.md`.

&nbsp;

#### Deep-Dive References Connect

After the move, `css/patterns.md` had zero inbound references. It now has inbound links from four files. They are `css/style-guide.md`, `css/quality-standards.md`, `implementation/webflow_patterns.md` and `implementation/animation_workflows.md`.

The umbrella `implementation/performance_patterns.md` and the five topical references under `webflow/performance/` had zero cross-references. Bidirectional links now connect the umbrella to all five deep-dives. They are Core Web Vitals remediation, resource loading, third-party scripts, interaction-gated loading and Webflow platform constraints.

&nbsp;

#### CSS Joins Implementation Guidance

Eight of the nine implementation references previously pointed only to `../javascript/quality-standards.md`. That left CSS as an unintentional second-class citizen. Five references with CSS overlap now also point to `../css/quality-standards.md`. They cover animation, Webflow patterns, form upload, focus management and Swiper.
