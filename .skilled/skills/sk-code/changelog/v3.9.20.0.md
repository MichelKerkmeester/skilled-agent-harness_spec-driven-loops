# v3.9.20.0, The Hub States Its Routing Once

The hub now says how a prompt reaches a mode. It does this in a few lines. The resolver detail sits in one appendix. `ROUTER.md` no longer repeats the intent keywords. It already carries them in its machine block.

&nbsp;

## What's New at a Glance

- The hub's routing statement is three short paragraphs.
  - The paragraphs name the compiled router command.
  - They send the legacy fallback, the surface hint and the pseudocode to a final `MACHINE ROUTER` section.
- One document names the routing authority.
  - `SKILL.md` §2 says `hub-router.json` is the mode vocabulary.
  - `SKILL.md` §2 says `ROUTER.md` is the leaf-set router.
  - Both files point back to it instead of restating the split.
- `ROUTER.md` §2 stops repeating the keyword table.
  - It points at the `INTENT_SIGNALS` block in §9.
  - The phase boost no longer names `testing`.
  - §9 does not carry that intent.
- The catalog defers routing authority to the hub.
  - `feature-catalog.md` and its two-axis page now present `mode-registry.json` as the list of modes and packets.
  - `hub-router.json` and `ROUTER.md` carry the routing authority.
  - The hub's `SKILL.md` section 2 names that authority.

&nbsp;

No action is needed.
