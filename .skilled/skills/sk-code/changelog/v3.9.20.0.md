# v3.9.20.0, The Hub States Its Routing Once

The hub now says how a prompt reaches a mode in a few lines and leaves the resolver detail in one appendix. `ROUTER.md` no longer repeats the intent keywords it already carries in its machine block.

> Spec folder: `specs/sk-doc/072-skill-routing-and-clarity/005-sk-code-hub` (Level 2)

&nbsp;

## What's New at a Glance

- **The hub's routing statement is three short paragraphs.** They name the compiled router command and send the legacy fallback, the surface hint and the pseudocode to a final `MACHINE ROUTER` section.
- **One document names the routing authority.** `SKILL.md` §2 says `hub-router.json` is the mode vocabulary and `ROUTER.md` is the leaf-set router, and both files point back to it instead of restating the split.
- **`ROUTER.md` §2 stops repeating the keyword table.** It points at the `INTENT_SIGNALS` block in §9, and the phase boost no longer names `testing`, an intent §9 does not carry.
- **The catalog defers routing authority to the hub.** `feature-catalog.md` and its two-axis page now present `mode-registry.json` as the list of modes and packets, with `hub-router.json` and `ROUTER.md` carrying the routing authority the hub's `SKILL.md` section 2 names.
