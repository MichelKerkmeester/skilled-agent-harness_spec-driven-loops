# v3.1.0.0, The Quality Mode Checks the Languages It Claims

This release carries sk-code-quality 1.5.0.0 to the hub. The comment-hygiene checker reads one comment-family table, so Go, Rust, YAML, CSS, TOML, SQL, `.mts` and `.cts` files are checked the same way in the editor hook, at commit and in CI. No mode or surface was added or removed.

&nbsp;

## What's New at a Glance

- **One comment-family table.** `sk-code-quality/assets/comment-syntax.json` is read by the checker, the ceiling report and the shared post-edit router, so the three agree on which file extensions are checked. The checker and the ceiling report also take each family's comment tokens from it.
- **The post-edit hook finds its checker.** The shared router resolves the checker beside its own real path before the project folder, so a project that reaches the hub through a link is still checked. A missing checker comes back as one `quality-notice`.
- **CI fails loudly.** The comment-hygiene job fails on any checker exit above 2 and annotates each finding with its line and reason. The script-tests job runs the quality mode's four bash suites.
- **The quality mode's wording matches the tree.** It names `specs/` as the spec root, hands fixes back to the acting agent applying `workflow-implement.md` and lists its three always-loaded resources in `DEFAULT_RESOURCE`.

&nbsp;

## Upgrade

Existing comments in newly covered languages can fail pre-commit and CI once their files are touched. Rewrite each finding to its durable reason, or mark it `hygiene-ok` where the label is the subject of the line.

The four mode packets keep their own changelogs and version lines, so read the sk-code-quality 1.5.0.0 entry for the checker changes and this repository's baseline counts.
