Motion.dev is now a discoverable cross-stack peer category inside `sk-code`, so animation guidance can live in one place instead of being buried under Webflow-only docs. The smart router recognizes `motion_dev/` beside `webflow/` and `opencode/`, while Webflow CDN-specific guidance stays linked rather than duplicated. The manual testing playbook covers Motion regressions and cross-browser performance.

> Spec folder: `specs/skilled-agent-orchestration/069-sk-code-motion-dev-and-playbook` (Level 1)

## What's New at a Glance

- **The `motion_dev/` category has cross-stack references and assets.** `references/motion_dev/` includes `quick_start`, `animate_and_timelines`, `scroll_and_gestures`, `performance_and_pitfalls`, `decision_matrix` and `integration_patterns`. `assets/motion_dev/` includes an install card, playbook hooks and reusable JavaScript snippets. Motion.dev works the same across stacks.
- **The manual testing playbook extends to animation and performance.** `manual-testing-playbook/` covers Motion integration, animation regression, cross-browser drift and performance-gate scenarios. Authors writing animation code now have ready-made test scenarios.
- **Existing Webflow docs that mention Motion.dev gained additive `motion_dev/` See-also pointers.** Discovery and routing both improve without duplicating Webflow content.
- **The new resources are discoverable through memory search.** They use the same query paths that surface every other `sk-code` resource. The phase parent has 3 child packets: `specs/skilled-agent-orchestration/069-sk-code-motion-dev-and-playbook/001-playbook`, `specs/skilled-agent-orchestration/069-sk-code-motion-dev-and-playbook/002-motion-dev` and `specs/skilled-agent-orchestration/069-sk-code-motion-dev-and-playbook/003-cross-ref-metadata-sync`.

## Upgrade

No migration required. Existing Webflow callers are unaffected, and the new Motion.dev references and assets are additive.
