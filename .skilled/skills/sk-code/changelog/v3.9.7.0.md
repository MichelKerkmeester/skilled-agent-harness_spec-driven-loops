# v3.9.7.0, One Contract for Dropping or Replacing a Code Rule

A repository that wants a different house style had no way to say so. The shipped rules could only be added to. The hub now defines how a checklist drops or replaces a rule. It also defines which rules stay fixed whatever a repository says. And it defines a linter that checks the section before anything reads it. The quality and review modes adopt the contract in later releases. So neither changes behavior yet.

&nbsp;

## What's New at a Glance

- **A checklist can carry a `## Rule overrides` table.** Each row names one rule id. It either drops the rule with `none` or puts `replace: <text>` in its place. A reason is optional.
- **The hard floor is written down once.** Some rules can never be overridden. They cover parse faults, conflict markers, credentials, input validation and silent failures. They also cover initialization safety, resource cleanup and accessibility for UI code. The review severity, reach and baseline security and correctness rules are on the list too. One JSON list holds them. The linter reads it. A test keeps the reference table identical.
- **Precedence is fixed.** The floor wins. Then come the repository checklist, a specific surface, the SKILLED fallback and the shipped default. When two sources at the same level disagree, the shipped default applies. The conflict is recorded.
- **The linter refuses a bad section.** `node .skilled/skills/sk-code/shared/scripts/check-rule-overrides.cjs <checklist.md>` exits 1 on a floor id. It also exits 1 on a `replace:` row for a rule the runner checks itself. An unknown action or a malformed row exits 1 too. It exits 0 on a valid section or none.

&nbsp;

## Upgrade

No action is needed. Nothing reads an override section yet. So every checklist and review runs exactly as before. The contract is at `.skilled/skills/sk-code/shared/references/universal/rule-overrides.md`.
