# v3.9.7.0, One Contract for Dropping or Replacing a Code Rule

A repository that wants a different house style had no way to say so: the shipped rules could only be added to. The hub now defines how a checklist drops or replaces a rule, which rules stay fixed whatever a repository says and a linter that checks the section before anything reads it. The quality and review modes adopt the contract in later releases, so neither changes behavior yet.

> Spec folder: `specs/sk-code/017-portable-code-modes/001-shared-rule-contract` (Level 2)

&nbsp;

## What's New at a Glance

- **A checklist can carry a `## Rule overrides` table.** Each row names one rule id and either drops it with `none` or puts `replace: <text>` in its place, with an optional reason.
- **The hard floor is written down once.** Parse faults, conflict markers, credentials, input validation, silent failures, initialization safety, resource cleanup, accessibility for UI code and the review severity, reach and baseline security and correctness rules can never be overridden. One JSON list holds them. The linter reads it, and a test keeps the reference table identical.
- **Precedence is fixed.** The floor wins, then the repository checklist, then a specific surface, then the SKILLED fallback, then the shipped default. When two sources at the same level disagree, the shipped default applies and the conflict is recorded.
- **The linter refuses a bad section.** `node .skilled/skills/sk-code/shared/scripts/check-rule-overrides.cjs <checklist.md>` exits 1 on a floor id, a `replace:` row for a rule the runner checks itself, an unknown action or a malformed row, and 0 on a valid section or none.

&nbsp;

## Upgrade

No action is needed. Nothing reads an override section yet, so every checklist and review runs exactly as before. The contract is at `.skilled/skills/sk-code/shared/references/universal/rule-overrides.md`.
