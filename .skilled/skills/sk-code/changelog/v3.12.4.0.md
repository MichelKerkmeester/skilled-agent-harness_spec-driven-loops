# v3.12.4.0, A Small Frontend Change Still Reports Browser Evidence

The new conversation scenario RD-006 asked Claude Code to change one heading color through sk-code. In two live runs the agent made the change and reported it done without opening a browser or writing NOT RUN. The browser step lived in `ROUTER.md` §5 and the frontend references, and the agent skipped both for a one-value CSS change. `SKILL.md` is the only sk-code file the agent read in full.

&nbsp;

## What's New at a Glance

- `SKILL.md` §4 has a new ALWAYS rule: meet the changed surface's row in `ROUTER.md` §5 before reporting a change complete, however small. For a changed stylesheet, markup or component file, that means reading the `mcp-browser-use` hub to find an installed browser mode, checking for the `bdg` and `bladebro` command-line tools before concluding none is installed, opening the page in a browser session the agent owns and reporting a screenshot and the console. When no mode can run, the report says NOT RUN and the reason. Aside runs on the signed-in account, so it is used only when the user asks.
- `sk-code-frontend/references/frontend-practice.md` (1.0.6.0) adds the same browser step to its pre-completion checklist.
- The sk-code playbook (1.5.23.0) adds the conversation scenario RD-006, which runs that request live and checks the reply for browser evidence or NOT RUN. An Aside call or a signed-in browser lane the user did not ask for fails it.

&nbsp;

## Upgrade

No action is needed. A frontend completion report now carries browser evidence or says why it has none.
