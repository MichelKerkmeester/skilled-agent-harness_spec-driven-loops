# v3.3.0.0, A Repository Names Its Own Quality Checks and the Doctor Creates the File

This release carries sk-code-quality 1.7.0.0 to the hub. A repository commits `.sk-code/quality.json` to name its own checks. The quality runner runs them behind the workspace guard. `/doctor:sk-code` now has two targets. `setup` is still the default. `quality` reports, checks and creates that file. No mode or surface was added or removed.

> Spec folder: `specs/sk-code/015-quality-agnostic-gate/003-config-and-doctor` (Level 2)

&nbsp;

## What's New at a Glance

- **The quality mode reads a repository config.** sk-code-quality 1.7.0.0 finds one config per run. The order is `--config`, then the file-scoped `skcode.qualityConfig` git config value, then `.sk-code/quality.json`. It validates the config before any check starts. It runs each check it names as an argv array in its own process group. Its entry holds the schema and the trust boundary.
- **`/doctor:sk-code quality` is new.** It shows which config the gate reads. It shows whether each tool that config names is on PATH. It shows the config's errors. When no config exists, it shows a plan built from the repository's own manifests. In that case it creates `.sk-code/quality.json` once after you approve. It never runs a command the config names. It never overwrites an existing file.
- **The setup battery has nine legs.** The new quality leg checks that `python3` is on PATH. It checks that the runner and the checker are executable. It checks that the two tables parse. It checks that the quality tests pass. It checks that a fixed quality prompt routes to `sk-code-quality`. The run now ends `STATUS=OK legs=9`. A checkout older than v4 skips eight legs.
- **The advisor names each doctor target.** The `/doctor:sk-code` bridge became `command-doctor-sk-code-setup` and `command-doctor-sk-code-quality`. That is the same shape as the git targets. The system-skill-advisor 0.17.1.0 entry has the details.
- **The playbook scenarios expect nine legs.** The doctor setup scenario expects nine PASS lines. Under `SPECKIT_COMPILED_ROUTING=0`, it also expects a failing quality leg beside the failing probe. The pre-v4 checkout scenario expects eight SKIP lines. The hub README names the quality leg and the quality target.

&nbsp;

## Upgrade

No migration required. A repository with no `.sk-code/quality.json` keeps the 3.2.0.0 behavior. The exception is that the verdict lists the checks its manifests imply as suggestions. A script that matched `STATUS=OK legs=8` from the setup battery must match `legs=9`. A bare `/doctor:sk-code` still runs setup. The advisor matches its slash command to a bridge only when the target is typed. It does the same for `/doctor:git`.
