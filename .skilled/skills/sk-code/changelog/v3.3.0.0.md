# v3.3.0.0, A Repository Names Its Own Quality Checks and the Doctor Creates the File

This release carries sk-code-quality 1.7.0.0 to the hub. A repository commits `.sk-code/quality.json` to name its own checks, and the quality runner runs them behind the workspace guard. `/doctor:sk-code` now has two targets: `setup`, still the default, and `quality`, which reports, checks and creates that file. No mode or surface was added or removed.

> Spec folder: `specs/sk-code/015-quality-agnostic-gate/003-config-and-doctor` (Level 2)

&nbsp;

## What's New at a Glance

- **The quality mode reads a repository config.** sk-code-quality 1.7.0.0 finds one config per run (`--config`, then the file-scoped `skcode.qualityConfig` git config value, then `.sk-code/quality.json`), validates it before any check starts and runs each check it names as an argv array in its own process group. Its entry holds the schema and the trust boundary.
- **`/doctor:sk-code quality` is new.** It shows which config the gate reads, whether each tool that config names is on PATH and the config's errors. When no config exists, it shows a plan built from the repository's own manifests and creates `.sk-code/quality.json` once after you approve. It never runs a command the config names, and it never overwrites an existing file.
- **The setup battery has nine legs.** The new quality leg checks that `python3` is on PATH, the runner and the checker are executable, the two tables parse, the quality tests pass and a fixed quality prompt routes to `sk-code-quality`. The run now ends `STATUS=OK legs=9`, and a checkout older than v4 skips eight legs.
- **The advisor names each doctor target.** The `/doctor:sk-code` bridge became `command-doctor-sk-code-setup` and `command-doctor-sk-code-quality`, the same shape as the git targets. The system-skill-advisor 0.17.1.0 entry has the details.
- **The playbook scenarios expect nine legs.** The doctor setup scenario expects nine PASS lines and, under `SPECKIT_COMPILED_ROUTING=0`, a failing quality leg beside the failing probe. The pre-v4 checkout scenario expects eight SKIP lines. The hub README names the quality leg and the quality target.

&nbsp;

## Upgrade

No migration required. A repository with no `.sk-code/quality.json` keeps the 3.2.0.0 behavior, except that the verdict lists the checks its manifests imply as suggestions. A script that matched `STATUS=OK legs=8` from the setup battery must match `legs=9`. A bare `/doctor:sk-code` still runs setup, but the advisor matches its slash command to a bridge only when the target is typed, as it does for `/doctor:git`.
