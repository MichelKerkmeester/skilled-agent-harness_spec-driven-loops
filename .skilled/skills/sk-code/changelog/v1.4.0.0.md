This release brings the sk-code slice of the packet 146 ponytail-based refinement into the code-work skill. It transplants reusable restraint teachings from an external reference. Implementers can then choose the least code that still meets a requirement. The release adds three restraint-guidance changes and a structural check. These sit on top of the existing routing. Surface detection does not change. Surface precedence (SKILLED over WEBFLOW over UNKNOWN) does not change. The Iron Law does not change.

> Spec folder: `.opencode/specs/skilled-agent-orchestration/142-sk-code-ponytail-based-refinement` (Level 2)

## What's New at a Glance

- **The Design Restraint Ladder guides the least-code choice.** The ladder is roughly thirteen lines. It sits in always-loaded `references/universal/code-quality-standards.md`. It checks whether code needs to exist at all (YAGNI). Then it climbs through these rungs. The first is a standard-library primitive. Next comes a native platform or runtime feature. Then an already-installed dependency. Then a one-line expression. The last rung is a minimal custom implementation. The ladder runs after surface and intent routing. It works as a post-read reflex that consumes the detected surface. For implementation intent, the Phase 0 to Phase 1 gate in `references/phase-detection.md` requires the laziest viable rung. `SKILL.md` names the ladder in its Phase Overview before the first line of new code. Phase 3 verification is still required.
- **The implementer avoids scope-question stalls.** A new §4 ALWAYS bullet in `SKILL.md` directs the implementer to build the simplest correct implementation of the stated requirement. If part seems unnecessary, the implementer implements it as specified. It also raises a scope-amendment recommendation in the same response. It never silently cuts scope, because SCOPE-LOCK still holds. It never blocks solely to ask when a safe minimal version already satisfies the requirement.
- **The `ceiling:` convention marks deliberate shortcuts as intent.** Section 4 of `references/universal/code-style-guide.md` defines a neutral comment. It names the shortcut, its known ceiling and its upgrade path or trigger. That comment is a durable WHY, not a brand or tool prefix. A brand prefix reads as a perishable cargo-cult label. The convention stays off the comment-hygiene checker's allowed-pattern list. It already passes without a forbidden id. Allow-listing it would let a forbidden id on the same line slip through. The convention is the producer-side companion to the reviewer-side downgrade rule. That rule shipped in `sk-code-review` v1.4.0.0.
- **The STACK_FOLDERS validator checks declared surfaces against their folders.** If a declared surface had no folders, the router would silently load nothing. If a surface-shaped folder existed with no declaration, the router would drift from its documented contract. Neither case gave a warning. `assets/scripts/verify_stack_folders.py` parses the `STACK_FOLDERS` literal out of `SKILL.md`. It asserts that every declared surface resolves to an on-disk `references/<surface>/` folder. It asserts the same for an `assets/<surface>/` folder. It checks that no undeclared surface folder exists in the `references/` tree. It checks the same for the `assets/` tree. The shared `universal/` material and the `scripts/` tooling directory are exempt by design. Mismatches produce a per-problem report with a non-zero exit.

## Upgrade

No migration required. The ladder, anti-stall rule and `ceiling:` convention are additive guidance. They change how the implementer approaches new code. They do not change surface routing or the verification contract. The validator is standalone. Run `python3 .opencode/skills/sk-code/assets/scripts/verify_stack_folders.py` to confirm every declared surface resolves to real folders.
