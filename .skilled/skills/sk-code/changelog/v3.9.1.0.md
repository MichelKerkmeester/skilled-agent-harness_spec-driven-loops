# v3.9.1.0, The Router Counts Straight Through

The hub `ROUTER.md` still numbered its sections from 6 after earlier sections left, so a reader met a document that began in the middle. The sections now run 1 to 10 and every citation of them follows. The router also learned the words operators use for the quality config and for CI switches, and the playbook now tests the two CI doctor routes that had no scenario.

> Spec folder: `specs/sk-code/015-quality-agnostic-gate` (Level 2)

&nbsp;

## What's New at a Glance

- **The router has no numbering gap.** Sections 1 to 10 read in order, and the shared-controls section that other docs cite is now section 9.
- **Quality and CI prompts route sooner.** Phrases such as an untrusted repository check, the quality config file name, turning off CI, a deploy or release workflow and the workflows folder now reach the right mode. A CI phrase no longer counts twice inside a longer one, so a review of a workflow still bundles the review mode with the CI surface.
- **The CI doctor routes have scenarios.** One covers the scaffold route as a dry run and a decline. The other covers the toggle route, including a refusal of a bad variable.
- **The compiled-routing scenarios read the same way.** Each states its surface, its bundle and its expected route in one layout.

&nbsp;

## Upgrade

A document of your own that cites `ROUTER.md` section 11 should cite section 9 instead. No other migration is required.
