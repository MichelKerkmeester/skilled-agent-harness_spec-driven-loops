# v3.9.0.0, Repository Checks Wait for a Trust Grant

This release follows 3.8.0.0.

- It carries sk-code-quality 1.13.0.0 and sk-code-skilled 2.1.2.0 to the hub.
- The change a repository owner will notice comes first.

Repository checks wait for a trust grant.

- A committed quality config runs its commands only after the operator grants trust.
- So each affected repository needs one command.
- Its configured checks run again after that.

The code agent finds the gate itself.

- The code agent no longer depends on a fixed location for the gate.
- Its quality step runs the runner from the folder where the sk-code skill is installed.
- So it works in a repository with no `.skilled/` tree.

> [!IMPORTANT]
> 1 change can break an existing setup. Read this before you update.
>
> 1. Committed checks wait for a trust grant. [Committed Commands Wait for a Grant](#c-committed-commands-wait-for-a-grant)

&nbsp;

## Why This Release

A committed config is written by the repository's owner. It is not written by the person running the gate.

- So a clone should not run its commands without a choice.
- The code agent's quality step also named a path.
- That path exists only inside this repository.
- The benchmark notes did not say which report folders predate the renderer.

## Quality Gate

Both gate changes are described in sk-code-quality 1.13.0.0. The hub entry names only the action a repository owner needs.

#### Committed Commands Wait for a Grant <a id="c-committed-commands-wait-for-a-grant"></a>

> [!WARNING]
> A repository whose committed `.sk-code/quality.json` ran checks before this release needs `git config --local skilled.trustRepoChecks true`. Run it once inside that repository.

- A committed quality config runs its commands once the repository is trusted.
- Until then its configured checks read `SKIPPED_UNTRUSTED`.
- A required one leaves the run `UNVERIFIED` with exit 4.
- The hub's own repository is trusted.
- So it needs nothing.

#### A Broken Row Errors Only Where It Applies <a id="c-a-broken-row-errors-only-where-it-applies"></a>

- A fault in another skill's checklist fails the gate only when that skill reaches a changed file.
- Otherwise it is listed in `config.warnings`.
- That list never changes the gate or the exit code.

&nbsp;

## Code Agent

The code agent no longer depends on a fixed location for the gate. Its quality step runs the runner from the skill's own folder.

#### The Quality Step Names the Skill's Own Folder <a id="c-the-quality-step-names-the-skills-own-folder"></a>

- The @code agent reads sk-code's `SKILL.md` wherever the runtime installed it.
- Its quality step runs the runner from that folder.
- The source agent and each runtime mirror carry the same wording.

&nbsp;

## Surface Readers

The surface readers stay in step.

#### The Hub and the Advisor Agree on Surfaces <a id="c-the-hub-and-the-advisor-agree-on-surfaces"></a>

- The hub's declared surface reader now drops the same surface blocks.
- So does the advisor plugin's copy.
- A parity test in sk-code-skilled 2.1.2.0 keeps the two readers from drifting apart again.

&nbsp;

## Benchmark Reports

The benchmark notes name the legacy folders.

#### Pre-Renderer Folders Are Marked Legacy <a id="c-pre-renderer-folders-are-marked-legacy"></a>

- The sk-code benchmark README names seven report folders as legacy.
- Those folders predate the renderer.
- `--check` does not apply to them.
- So an old folder is not held to the current renderer's output.

&nbsp;

## Upgrade Notes

The upgrade depends on whether a repository has a committed quality config.

#### Before You Start <a id="c-before-you-start"></a>

1. Run `git config --local skilled.trustRepoChecks true` once inside each repository whose committed `.sk-code/quality.json` ran checks before this release.
2. A repository with no committed config needs nothing.
