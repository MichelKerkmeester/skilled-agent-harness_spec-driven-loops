# v3.9.0.0, Repository Checks Wait for a Trust Grant

This release follows 3.8.0.0 and carries sk-code-quality 1.13.0.0 and sk-code-skilled 2.1.2.0 to the hub. The change a repository owner will notice comes first. A committed quality config runs its commands only after the operator grants trust, so each affected repository needs one command before its configured checks run again.

The code agent no longer depends on a fixed location for the gate. Its quality step runs the runner from the folder where the sk-code skill is installed, so it works in a repository with no `.skilled/` tree.

> Spec folder: `specs/sk-code/015-quality-agnostic-gate/009-review-closeout` (Level 2)

&nbsp;

## Why This Release

A committed config is written by the repository's owner, not by the person running the gate, so a clone should not run its commands without a choice. The code agent's quality step also named a path that exists only inside this repository. The benchmark notes did not say which report folders predate the renderer.

&nbsp;

## What's New at a Glance

- **Repository checks wait for a grant.** A committed quality config runs its commands once the repository is trusted. Without a grant each check reads `SKIPPED_UNTRUSTED` with its repair line.
- **The code agent finds the gate itself.** Its quality step runs the runner from the skill's own folder, so the step works in a repository with no `.skilled/` tree.
- **Broken rows in other skills stop blocking every run.** A fault errors the gate only where the skill that declares it applies to the change.
- **The syntax check is faster.** A fifty-file run fell from 1849 ms to 725 ms at the slowest of five runs.
- **The surface readers stay in step.** A new test fails when the hub's reader and the advisor plugin's copy return different labels.
- **The benchmark notes name the legacy folders.** Seven report folders dated before the renderer are marked legacy. `--check` does not apply to them.

&nbsp;

## Quality Gate

Both gate changes are described in sk-code-quality 1.13.0.0. The hub entry names only the action a repository owner needs.

#### Committed commands wait for a grant

**Breaking:** A repository whose committed `.sk-code/quality.json` ran checks before this release needs `git config --local skilled.trustRepoChecks true`, run once inside that repository. Until then its configured checks read `SKIPPED_UNTRUSTED`. A required one leaves the run `UNVERIFIED` with exit 4. The hub's own repository is trusted, so it needs nothing.

#### A broken row errors only where it applies

A fault in another skill's checklist fails the gate only when that skill reaches a changed file. Otherwise it is listed in `config.warnings`, which never changes the gate or the exit code.

&nbsp;

## Code Agent

#### The quality step names the skill's own folder

The @code agent reads sk-code's `SKILL.md` wherever the runtime installed it. Its quality step runs the runner from that folder. The source agent and each runtime mirror carry the same wording.

&nbsp;

## Surface Readers

#### The hub and the advisor agree on surfaces

The hub's declared surface reader and the advisor plugin's copy now drop the same surface blocks. A parity test in sk-code-skilled 2.1.2.0 keeps the two readers from drifting apart again.

&nbsp;

## Benchmark Reports

#### Pre-renderer folders are marked legacy

The sk-code benchmark README names the seven report folders that predate the renderer as legacy. `--check` does not apply to them, so an old folder is not held to the current renderer's output.

&nbsp;

## Upgrade Notes

- Run `git config --local skilled.trustRepoChecks true` once inside each repository whose committed `.sk-code/quality.json` ran checks before this release.
- A repository with no committed config needs nothing.
