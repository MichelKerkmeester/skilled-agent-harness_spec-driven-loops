# v3.12.6.0, A Rust App Routes to the Rust Set

The RUST row knew only binding vocabulary: `.rs`, the Cargo markers, napi-rs and wasm-bindgen. A prompt about a clap CLI or a ratatui screen with no `.rs` path and no word "rust" missed the Rust set. Two replays of the parity scenario also showed readers skipping the TypeScript `quick-reference` parts the route had selected. This release fixes both.

&nbsp;

## What's New at a Glance

- The RUST row names the app-crate vocabulary.
  - `shared/references/stack-detection.md` adds `clap cli`, `clap crate`, `clap derive`, `clap::`, `ratatui` and `crossterm`.
  - `ROUTER.md` and the `code-skilled-runtime` keywords in `hub-router.json` carry the same phrases.
  - The bare word `clap` is not a keyword, so "clap animation" and "thunderclap" route nowhere.
  - `graph-metadata.json` adds `rust`, `napi-rs`, `ratatui`, `crossterm` and `clap cli` to the intent signals the advisor reads.
- The bracketed keywords sit last in the RUST list.
  - The replay parser stopped at the first `]`, so `#[napi]` and `#[wasm_bindgen]` in the middle dropped every keyword after them.
- A reader opens every routed file.
  - `ROUTER.md` §7 says to open every file the route selects before naming the standards applied, each `quick-reference` part included.
  - The never-overrides paragraph in `stack-detection.md` says a parity task loads every routed part of both sets.
- The playbook checks a Rust-only app.
  - LS-007 asks for a review of a clap CLI in `src/main.rs`. It passes when the Rust set loads and no TypeScript, Python, Shell or Config reference does.
  - The playbook now holds 23 operator scenarios and 32 files.
