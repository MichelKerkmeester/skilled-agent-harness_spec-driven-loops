# v3.9.4.0, Review Blockers Need a Reachable Input

A review finding that failed only because it was handed input the code's own contract rules out, such as `NaN` passed where a number is promised, no longer blocks a merge. It is reported as P2 hardening instead, so the merge gate answers only for input that can reach the code.

> Spec folder: `specs/sk-code/016-review-mode-followups` (Level 2)

&nbsp;

## What's New at a Glance

- **Security findings at a trust boundary are not narrowed.** Data from users, the network, files, the environment or another service can always arrive, so the new bar never lowers a finding on it.
- **The review agent and its runtime copies carry the same rule.** Every copy states the calibration beside its severity table, so a run answers the same way whichever surface loads it.
- **The review mode moves to v1.9.3.0.** See its changelog for the live rerun.
