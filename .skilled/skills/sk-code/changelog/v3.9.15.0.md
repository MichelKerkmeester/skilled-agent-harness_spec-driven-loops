# v3.9.15.0, The Repository Settings Live Inside the Skill Folder

The CI profile and the quality config used to sit at the repository root. They sat under `.sk-code/`. They now travel with the skill that reads them. So the hub README names the new path. So do the router keywords, the shared references, the feature catalog and the doctor playbook. Each file can state the repository it was written for.

&nbsp;

## What's New at a Glance

- **The hub docs name the skill-folder paths.** The CI profile is `.skilled/skills/sk-code/sk-code-ci/repository/ci.json`. The quality config is `.skilled/skills/sk-code/sk-code-quality/repository/quality.json`. The README and the intent keywords in `ROUTER.md` and `hub-router.json` now say so. The phase, verify and rule-override references now say so. The feature catalog leaves and the CI report scenario now say so.
- **One shared module reads the repository's identity.** `shared/scripts/lib/repository-identity.cjs` takes `GITHUB_REPOSITORY` first. Otherwise it takes the origin remote. It reads the https, ssh and scp-like forms through one parser. It reports an unknown repository instead of throwing. So a mode can tell whether a config was written for this checkout.
- **The catalog and the playbook follow the move.** The quality config, setup and CI leaves describe the new location. The doctor CI report scenario expects `profile.path` to read the packet's `repository/ci.json`.
