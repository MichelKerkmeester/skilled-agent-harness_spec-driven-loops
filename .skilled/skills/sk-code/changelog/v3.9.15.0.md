# v3.9.15.0, The Repository Settings Live Inside the Skill Folder

The CI profile and the quality config used to sit at the repository root, under `.sk-code/`. They now travel with the skill that reads them, so the hub README, the router keywords, the shared references, the feature catalog and the doctor playbook name the new path, and each file can state the repository it was written for.

> Spec folder: `specs/sk-code/017-portable-code-modes/016-repository-config-in-skill` (Level 2)

&nbsp;

## What's New at a Glance

- **The hub docs name the skill-folder paths.** The CI profile is `.skilled/skills/sk-code/sk-code-ci/repository/ci.json` and the quality config is `.skilled/skills/sk-code/sk-code-quality/repository/quality.json`. The README, the intent keywords in `ROUTER.md` and `hub-router.json`, the phase, verify and rule-override references, the feature catalog leaves and the CI report scenario now say so.
- **One shared module reads the repository's identity.** `shared/scripts/lib/repository-identity.cjs` takes `GITHUB_REPOSITORY` first and the origin remote otherwise, reads the https, ssh and scp-like forms through one parser and reports an unknown repository instead of throwing, so a mode can tell whether a config was written for this checkout.
- **The catalog and the playbook follow the move.** The quality config, setup and CI leaves describe the new location, and the doctor CI report scenario expects `profile.path` to read the packet's `repository/ci.json`.
