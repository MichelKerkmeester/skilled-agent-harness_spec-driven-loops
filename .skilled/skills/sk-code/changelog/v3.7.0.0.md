# v3.7.0.0, Comment Hygiene and Restraint Reach the Quality Mode

This release follows 3.6.0.0 and carries sk-code-review 1.9.0.0, sk-code-skilled 2.1.1.0 and sk-code-ci 1.1.1.0 to the hub. A request that asks for comment hygiene, yagni or over-engineering used to get no sk-code recommendation at or above 0.8, and a CI workflow prompt could not reach both the quality mode and the CI standards. Both now resolve.

> Spec folder: `specs/sk-code/015-quality-agnostic-gate/005-consumers-and-routing` (Level 2)

&nbsp;

## What's New at a Glance

- **Comment hygiene reaches the hub at stage one.** The hub keywords and the intent signals carry the phrase, so the advisor scores sk-code on it. The other restraint words stay at stage two alone, because a prose prompt about yagni or over-engineering pulled sk-code to 0.82 with them at stage one.
- **The quality intent carries the restraint words.** `ROUTER.md` CODE_QUALITY now lists comment hygiene, restraint, yagni, simplify, over-engineering and bloat, so a request that uses one of them resolves to the quality mode.
- **The quality map names the runner contract.** `sk-code-quality/references/runner-contract.md` sits in the CODE_QUALITY resource map, so a quality run reads the envelope grammar beside its checklists.
- **The house checklist is scoped to SKILLED.** The CODE_QUALITY row says `universal-checklist.md` loads only when SKILLED resolves. A foreign surface loads the floor in `code-quality-standards.md` and the rows it declares.
- **The shared aliases move to the SKILLED surface.** Alignment verifier and stable jsonl keys left the quality aliases for sk-code-skilled, and the quality-gates vocabulary class hands stable jsonl keys, add set -euo pipefail and alignment verifier to code-skilled-runtime. No alias now sits under two owners.
- **A ci.yml prompt bundles the CI packet.** The CI vocabulary gains that file name, which ties the quality and CI classes at two hits each, so stage one returns a surface bundle with sk-code-ci as evidence.
- **The quality runner reads a sibling skill's checklists.** sk-code-quality 1.11.0.0 loads the rows a skill outside the hub declares in its `graph-metadata.json`, refuses any row that leaves that skill's folder, reports a malformed row by name and reads one refused row as `ERROR` with exit 3.

&nbsp;

## Upgrade

No migration required. Each moved alias keeps one owner, and both registries carry the moved phrases in their new classes. A reader that pins the hub version reads 3.7.0.0 in `SKILL.md`, `hub-router.json`, `mode-registry.json` and `description.json`.
