# v3.10.0.0, The Hub Gains a Third Surface

The sk-code hub's surface axis now carries three read-only evidence packets. `sk-code-frontend` joins `sk-code-ci` and `sk-code-skilled`, so web and React Native practice plus a Figma-to-code check arrive through the same bundling rule as the other two.

&nbsp;

## What's New at a Glance

- **A third surface on the axis.** `sk-code-frontend` is registered in `mode-registry.json` as a `surface` packet on the `evidence-base` backend, so the hub bundles it beside a workflow mode exactly as it bundles the other two.
- **Bundled from request vocabulary alone.** Like `sk-code-ci`, it declares no detection block. The hub bundles it from the `code-frontend-aliases` vocabulary class in `hub-router.json`, so surface detection never returns `sk-code-frontend`.
- **The fallback keeps last place.** `sk-code-frontend` sits in `routerPolicy.tieBreak` after `sk-code-ci` and before `sk-code-skilled`, so a keyword tie still ranks the SKILLED fallback last.
- **The shared doctrine knows the third surface.** The shared README lists it beside the other surfaces and carries its three workflow symlink lines, and surface detection, phase detection and the feature catalog name it wherever they named the other two.
- **Phase evidence for frontend work.** Phase detection gains a frontend table that loads the cross-stack core, then the stack layer, then one topic file when the request touches its concern.
- **Read-only throughout.** The packet writes nothing, and the paired workflow mode applies the guidance it loads.
