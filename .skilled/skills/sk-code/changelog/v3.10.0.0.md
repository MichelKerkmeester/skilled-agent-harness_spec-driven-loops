# v3.10.0.0, The Hub Gains a Third Surface

The sk-code hub's surface axis now carries three read-only evidence packets. `sk-code-frontend` joins `sk-code-ci` and `sk-code-skilled`. So web practice and a Figma-to-code check arrive through the same bundling rule as the other two.

&nbsp;

## What's New at a Glance

- **A third surface on the axis.** `sk-code-frontend` is registered in `mode-registry.json` as a `surface` packet. It sits on the `evidence-base` backend. So the hub bundles it beside a workflow mode, exactly as it bundles the other two.
- **Bundled from request vocabulary alone.** Like `sk-code-ci`, it declares no detection block. The hub bundles it from the `code-frontend-aliases` vocabulary class in `hub-router.json`. So surface detection never returns `sk-code-frontend`.
- **The newest surface leads the existing ones.** `sk-code-frontend` sits in `routerPolicy.tieBreak` ahead of `sk-code-ci`. It sits before `sk-code-skilled`. So a new surface wins a keyword tie against the surfaces already there. The SKILLED fallback still ranks last.
- **The shared doctrine knows the third surface.** The shared README lists it beside the other surfaces. It carries its three workflow symlink lines. Surface detection, phase detection and the feature catalog name it wherever they named the other two.
- **Phase evidence for frontend work.** Phase detection gains a frontend table. It loads the cross-stack core, then the web stack layer. Then it loads one web topic file when the request touches its concern.
- **The front doors name the surface.** The always-loaded quality floor gains a Frontend row. That row carries web practice and the Figma check. The hub description names its three surfaces. The compiled-routing gold scenario `CB-CR-009` routes the frontend surface alone.
- **Read-only throughout.** The packet writes nothing. The paired workflow mode applies the guidance it loads.

&nbsp;

## Upgrade

No action is needed.
