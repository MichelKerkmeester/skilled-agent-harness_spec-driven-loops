# v2.4.0.0, A CI Surface for GitHub Actions Workflows

A request about a GitHub Actions workflow reached the hub with no surface to bundle, so it reviewed as an unknown surface and loaded none of the repository's workflow rules. The hub now has a second read-only surface, `sk-code-ci`, that holds those rules next to the file and line that prove each one.

## What's New at a Glance

- **`sk-code-ci` is a surface packet.** It is read-only, advisor-invisible and bundled beside a workflow mode, and its tool surface is `Read`, `Bash`, `Grep` and `Glob`.
- **Four references carry the rules.** The rule index, the trigger and filter rules, the job shape rules and the protected set.
- **Two scaffold templates.** A whole-workflow template and a job template start with the switch condition, permissions, concurrency, a timeout and SHA-pinned steps.
- **message-contract's every-branch push is a recorded exception.** The trigger is correct as written, so the workflow file is unchanged and the exception is a labelled row in the trigger rules.
- **The hub registration lists the new surface.** `mode-registry.json`, `hub-router.json`, `description.json`, `ROUTER.md`, the leaf manifest and the router-sync guard all name it, and the hub prose counts two surfaces.
- **A CI prompt resolves to the surface.** "review the github actions workflow yaml" resolves to `[sk-code-review, sk-code-ci]` and a canary case and a compiled-route test cover it. Each CI phrase counts once against the review keyword, and the runtime keywords `build matrix`, `branch ruleset` and `actions cache key` keep a test matrix, a scorer ruleset or a loader cache key out of the CI surface.

&nbsp;

## Upgrade

No migration required. The registration is additive and removes no mode or surface.
