# v3.11.3.0, The Router-Sync Guard Reads Its Surfaces From the Registry

A surface you register in `mode-registry.json` is now compared with the hub's routing map, with no second list to update.

> Spec folder: `specs/sk-code/019-surface-consistency-research` (Level 2)

&nbsp;

## What's New at a Glance

- **Registered surfaces are checked.** `verify-router-sync.cjs` reads every `surface` packet from `mode-registry.json`, instead of a hand-kept list.
- **Unreachable surfaces fail.** The guard fails when a registered surface has no tie-break position or route signal in `hub-router.json`.
- **Workflow links named.** The `sk-code-skilled` Workflow line names its three links to the hub's implement, debug and verify references.
