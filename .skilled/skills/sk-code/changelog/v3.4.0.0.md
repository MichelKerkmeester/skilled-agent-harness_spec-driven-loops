# v3.4.0.0, An Unknown Surface Gets the Universal Floor

This release follows 3.3.0.0 and carries sk-code-quality 1.8.0.0 and sk-code-skilled 2.1.0.0 to the hub. A repository with no declared surface could never finish the quality gate, because the gate was required and every standard was barred there. The shared doctrine now gives that repository a floor it can complete.

> Spec folder: `specs/sk-code/015-quality-agnostic-gate/004-doctrine` (Level 2)

&nbsp;

## What's New at a Glance

- **An unknown surface gets the floor and the built-in checks.** Iron Law 3 in `shared/references/phase-detection.md` now gives an UNKNOWN surface the universal floor, the quality runner's built-in checks, the quality mode's surface-neutral checklists that the runner lists and the quality checks the repository's quality config names. The config can come from `--config`, the git config key `skcode.qualityConfig` or `.sk-code/quality.json`, and it never supplies a verification command. The spec-folder authoring checklist applies only where the SKILLED surface resolves, and no other standard or discovered command applies. The UNKNOWN rows in `stack-detection.md` and `code-quality-standards.md` say the same.
- **The universal floor is defined in one place.** Sections 3 to 5 of `code-quality-standards.md` are the floor every surface gets. A mechanical floor at the top of section 3 makes a parse failure, merge-conflict markers and a credential signature P0 on every surface, and a parse finding in plain JavaScript stays heuristic and does not block.
- **Authors can predict review severity.** Each rule in sections 3 to 5 now sits in a table with a review-severity column that maps it onto review's own ids. Review keeps its ids and its judgement on each finding.
- **The handoffs name the runner.** The implement and debug workflows say the quality mode runs `quality-gate.cjs` first. The verify workflow reads the envelope's `checker_outputs` field and hands back to quality only on `BLOCKED`, `ERROR` or a field still reading `PENDING_AGENT_JUDGMENT`. It handles `UNVERIFIED` and `NOTHING_CHECKED` itself, and it states that the quality config never supplies verification commands.

&nbsp;

## Upgrade

No migration required. A repository that wants more than the floor declares a surface or commits `.sk-code/quality.json`. Read the sk-code-quality 1.8.0.0 and sk-code-skilled 2.1.0.0 entries for the packet changes.
