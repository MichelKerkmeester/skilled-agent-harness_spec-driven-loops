This release brings the sk-code slice of the packet 146 ponytail-based refinement into the code-work skill, transplanting reusable restraint teachings from an external reference so implementers can choose the least code that still meets a requirement. It adds three restraint-guidance changes and a structural check on top of the existing routing without changing surface detection, surface precedence (OPENCODE over WEBFLOW over UNKNOWN) or the Iron Law.

> Spec folder: `.opencode/specs/skilled-agent-orchestration/142-sk-code-ponytail-based-refinement` (Level 2)

## What's New at a Glance

- **The Design Restraint Ladder guides the least-code choice.** The roughly thirteen-line ladder in always-loaded `references/universal/code-quality-standards.md` checks whether code needs to exist at all (YAGNI), then climbs from a standard-library primitive to a native platform or runtime feature, an already-installed dependency, a one-line expression and finally a minimal custom implementation. It runs after surface and intent routing as a post-read reflex that consumes the detected surface. For implementation intent, the Phase 0 to Phase 1 gate in `references/phase-detection.md` requires the laziest viable rung, and `SKILL.md` names the ladder in its Phase Overview before the first line of new code, with Phase 3 verification still required.
- **The implementer avoids scope-question stalls.** A new §4 ALWAYS bullet in `SKILL.md` directs the implementer to build the simplest correct implementation of the stated requirement. If part seems unnecessary, the implementer implements it as specified and raises a scope-amendment recommendation in the same response, never silently cutting scope because SCOPE-LOCK still holds and never blocking solely to ask when a safe minimal version already satisfies the requirement.
- **The `ceiling:` convention marks deliberate shortcuts as intent.** Section 4 of `references/universal/code-style-guide.md` defines a neutral comment naming the shortcut, its known ceiling and its upgrade path or trigger as a durable WHY rather than a brand or tool prefix, with a brand prefix reading as a perishable cargo-cult label. The convention stays off the comment-hygiene checker's allowed-pattern list because it already passes without a forbidden id, and allow-listing it would let a forbidden id on the same line slip through, while it serves as the producer-side companion to the reviewer-side downgrade rule shipped in `sk-code-review` v1.4.0.0.
- **The STACK_FOLDERS validator checks declared surfaces against their folders.** If a declared surface had no folders, or a surface-shaped folder existed with no declaration, the router would silently load nothing or drift from its documented contract with no warning. `assets/scripts/verify_stack_folders.py` parses the `STACK_FOLDERS` literal out of `SKILL.md`, asserts that every declared surface resolves to both an on-disk `references/<surface>/` folder and an `assets/<surface>/` folder, and checks that no undeclared surface folder exists in either the `references/` or the `assets/` tree, with the shared `universal/` material and `scripts/` tooling directory exempt by design and mismatches producing a per-problem report with a non-zero exit.

## Upgrade

No migration required. The ladder, anti-stall rule and `ceiling:` convention are additive guidance that changes how the implementer approaches new code and does not change surface routing or the verification contract. The validator is standalone. Run `python3 .opencode/skills/sk-code/assets/scripts/verify_stack_folders.py` to confirm every declared surface resolves to real folders.
