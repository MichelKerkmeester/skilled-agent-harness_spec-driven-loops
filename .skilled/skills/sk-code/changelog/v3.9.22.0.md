# v3.9.22.0, The Playbook Proves the Routes It Names

Three surfaces the playbook only named now have a scenario that runs them: JavaScript sub-detection, Rust sub-detection and the quality doctor. The rest of the document catches up with the code it describes, so a scenario ends `PASS`, `FAIL` or `SKIP` and the four that change a file carry the undo each one owns. The shared override checker gained the documentation its exported helpers were missing.

> Spec folder: `specs/sk-doc/072-skill-routing-and-clarity/012-alignment-remediation` (Level 2)

&nbsp;

## What's New at a Glance

- **Three routes stop being assumptions.** JavaScript sub-detection, Rust sub-detection and the quality doctor each have a scenario that runs their commands and grades the exit status.
- **A fourth verdict is gone.** A minor resource-loading drift that used to score `PARTIAL` is now a `FAIL` with the drift named, so a release gate cannot rest on an outcome the standard does not allow.
- **The scenarios that change a file say so.** The four that mutate a tree carry the undo their own file records and run one at a time beside the existing parallel cap.
- **The advisor criteria work on either output path.** A run served by the local scorer prints no `score`, so every probe gates on `confidence` and a health check names which path is serving.
- **The automated tests are mapped again.** The cross-reference now says what each suite proves and which scenario repeats it by hand, and it names the comment-hygiene suite the old text said did not exist.
- **Every scenario row names its catalog entry.** The index gained a column for it and each per-feature file gained a `Catalog:` line, so a missing link shows up.
- **The shared override checker documents its helpers.** The contract loader and the checker entry point carry their parameters, return shapes and the error each one raises.
