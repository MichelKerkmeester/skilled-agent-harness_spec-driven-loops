# v3.9.14.0, The Hub Docs Describe the Rule Overrides

The hub README and the feature catalog still described the quality and review modes. They described them as they stood before a repository could change their rules. They now say what ships. They say which rules stay fixed. They say how a repository drops or replaces the others. They say where each mode reads the answer.

&nbsp;

## What's New at a Glance

- **The hub README names the repository's levers.** A new subsection lists the `## Rule overrides` section and `commentHygiene.disableRules`. It gives the rule ids and the hard floor. It says the SKILLED house style lives in the Skilled surface.
- **The shared README reads overrides through the linter.** One line said the modes "will call" the linter. It now says they read their rule overrides through it. The standards row mentions ids and the fixed or overridable marks.
- **The contract states who applies a row.** `rule-overrides.md` says the review mode applies the rows it reads. It records them on its `Rule sources` line. The quality runner reads the section of every checklist it loads through the same linter. It applies and records the rows. It takes its known rule ids from a shared registry. The shared README lists the registry module and its test.
- **The feature catalog has three new entries.** Rule overrides and the hygiene policy each get a leaf. So do the review's floor, default lens and overrides. So does the review agent's severity verdict. The quality config and doctor entries are brought up to date.
- **The applying run is documented.** A refused section or an unknown rule id is `CONFIG_INVALID` with exit 3. Accepted rows are recorded in the run's decisions. Two checklists that disagree at one level make the rule unverified. The root README and the catalog say the same.
- **The CI doctor entries read the profile.** The catalog describes the profile lookup. It describes the shape-based switch detection. It describes the toggle's ruleset refusal and its second confirmation. The doctor-commands playbook scenarios now name the profile and the protected-workflow confirmation. The hub README and the router table name the profile.
- **A stale pointer is gone.** The related-documents table named a changelog file that no longer exists. It now points at the changelog folder.
