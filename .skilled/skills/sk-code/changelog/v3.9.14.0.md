# v3.9.14.0, The Hub Docs Describe the Rule Overrides

The hub README and the feature catalog still described the quality and review modes as they stood before a repository could change their rules. They now say what ships: which rules stay fixed, how a repository drops or replaces the others, and where each mode reads the answer.

> Spec folder: `specs/sk-code/017-portable-code-modes/010-docs-and-doctor-alignment` (Level 2)

&nbsp;

## What's New at a Glance

- **The hub README names the repository's levers.** A new subsection lists the `## Rule overrides` section and `commentHygiene.disableRules`, with the rule ids and the hard floor, and the mode table says the SKILLED house style now lives in sk-code-skilled.
- **The shared README reads overrides through the linter.** The line that said the modes "will call" the linter now says they read their rule overrides through it, and the standards row mentions ids and the fixed or overridable marks.
- **The contract states who applies a row.** `rule-overrides.md` says the review mode applies the rows it reads and records them on its `Rule sources` line, and that the quality runner reads each declared section through the same linter.
- **The feature catalog has three new entries.** Rule overrides and the hygiene policy, the review's floor, default lens and overrides, and the review agent's severity verdict each get a leaf, and the quality config and doctor entries are brought up to date.
- **A stale pointer is gone.** The related-documents table named a changelog file that no longer exists and now points at the changelog folder.
