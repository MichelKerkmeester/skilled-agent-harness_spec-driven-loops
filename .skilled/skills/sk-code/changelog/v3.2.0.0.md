# v3.2.0.0, Surfaces Declare the Checklists the Quality Runner Loads

This release carries sk-code-quality 1.6.0.0 to the hub. The quality runner prints one verdict for a change in any repository, and the SKILLED and `sk-code-ci` surfaces now declare the checklists it lists. No mode or surface was added or removed.

> Spec folder: `specs/sk-code/015-quality-agnostic-gate/002-builtin-runner` (Level 2)

&nbsp;

## What's New at a Glance

- **Surfaces declare their checklists.** The SKILLED and `sk-code-ci` entries in `mode-registry.json` carry `quality.checklists` rows, each selecting by path globs or extensions and naming one checklist. A row carries no command.
- **The compiler checks the declarations.** The registry compiler rejects a malformed `quality` block with `QUALITY_DECLARATION_INVALID`, beside `SURFACE_DETECTION_INVALID`, and the sk-code activation manifest was refreshed for the new registry.
- **The surface reader keeps each marker kind.** `surfaceEntry` in the router replay library adds `pathMarkers`, `fileMarkers` and `contentMarkers` lists beside the merged list, so a reader of real files can match each kind on its own input. The exported names are unchanged.
- **The runner is a fourth surface reader.** `shared/references/stack-detection.md` lists it in its reader table, beside the advisor plugin, the review mode and the router replay.
- **The `/doctor:ci` report scenario expects the CI surface.** Its prompt asks about GitHub Actions workflows, so the hub routes it to `sk-code-ci`. The scenario had expected no route, which the compiled-serving admission check scored as drift.

&nbsp;

## Upgrade

No migration required. The four mode packets keep their own changelogs, so read the sk-code-quality 1.6.0.0 entry for the runner and the sk-code-skilled 2.0.2.0 entry for the reader change.
