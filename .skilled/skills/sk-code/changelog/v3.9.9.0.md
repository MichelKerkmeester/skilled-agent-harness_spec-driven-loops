# v3.9.9.0, Every Floor Rule Has an Id

The universal floor said a surface could only add rules, and it carried this repository's own preferences as if every codebase shared them. Each floor rule now has an id a repository can name in a `## Rule overrides` section, and a mark that says whether it may. The rules that stay fixed are the hard floor of the shared override contract.

> Spec folder: `specs/sk-code/017-portable-code-modes/003-quality-floor-and-style-split` (Level 2)

&nbsp;

## What's New at a Glance

- **Ids and marks on every floor rule.** Parse faults, conflict markers, credential signatures, hardcoded secrets, input validation, silent failures, initialization safety, resource cleanup and accessibility are FIXED. Commented-out code, comment pointers, tests, error messages, typing, naming and documentation are overridable.
- **Precedence replaces add-only.** The floor now points at the override contract's order: the hard floor, then the repository checklist, then a specific surface, then the SKILLED fallback.
- **House rules left the floor.** Required docstrings on public APIs, strict TypeScript without `any`, Python hints and the camelCase and snake_case examples now live in the SKILLED checklists. The floor keeps a universal form of each: type checks pass, names follow the declared convention and complex code explains why.
- **Wiring is labelled as this repository's.** The write-time, pre-commit and CI hygiene layers move to the quality mode's own description of this repository's wiring. The floor says only that the verdict's `layers` field reports what a repository has.
- **An unknown surface gets no house style.** It gets the floor, the runner's built-in checks and what its own quality config names, each with its overrides applied.
- **A test keeps the marks honest.** The linter suite fails when a FIXED mark and the contract's floor list disagree, or when a floor rule has no id.

&nbsp;

## Upgrade

No action is needed. A repository that wants a floor rule changed names its id in a `## Rule overrides` section of a checklist its config already lists.
