This release adds the missing guidance on when and why to choose motion in sk-code's Motion.dev animation references, along with a recipe for checking animations visually. sk-code's animation references were strong on API how-to (animate/timelines, scroll/gestures, integration, a decision matrix, performance pitfalls) but light on when and why: which easing to pick, concrete duration and stagger values, plus anticipation and arc guidance. They had no animation-specific visual-verification recipe. Material from the MIT-licensed `Schmandarine/web-motion-skill` was translated to the Motion.dev API, with the deep analysis and draft outsourced to `gpt-5.5-fast` (xhigh) in an isolated worktree (RM-8).

> Spec folder: `.opencode/specs/skilled-agent-orchestration/129-sk-code-animation-mining` (Level 2)

## What's New at a Glance

- **`references/motion_dev/animation-principles.md` adds guidance on motion choices.** It adds a motion vocabulary table (feedback → emphasis timing ladder) plus easing-as-perceived-physics guidance (cubic-bezier arrays, not GSAP eases), stagger direction/offset guidance, anticipation/overshoot/secondary-action ranges and arc/depth notes alongside a visual-review checklist. The Motion.dev-framed reference links to existing motion_dev references and carries MIT attribution, with the source's GSAP-specific material left out.
- **`assets/motion_dev/snippets/principled-reveal.js` composes the animation principles into a reusable reveal.** Its `@source` carries MIT attribution for the snippet, which combines anticipation (scale 0.98→1) with the timing vocabulary, `stagger(offset, { from })` direction plus a `prefers-reduced-motion` fallback. Each of the previous nine snippets demonstrated a single API, making this the first reusable production-style reveal to combine several principles.
- **The performance guide adds a frame-level visual-checking recipe.** In `references/motion_dev/performance-and-pitfalls.md`, the recipe checks timing and easing by eye through capture → extract frames → contact-sheet → drill-in. The folded-in recipe carries MIT attribution and uses the project's existing bdg/chrome-devtools/Playwright tooling instead of the source repo's recording scripts.
- **Animation routes now reach the new material.** `references/smart-routing.md` adds the §2 Phase-1 synonyms `easing`/`stagger`/`motion principles`/`motion language` for ANIMATION and `stagger()`/`animation principles` for MOTION_DEV, then adds `animation_principles.md` and `principled_reveal.js` to the §5 MOTION_DEV map and §11 machine-readable `RESOURCE_MAP["MOTION_DEV"]`. The PERFORMANCE row notes the recipe while the snippet README lists the new entry and `webflow/implementation/animation_workflows.md` gains a cross-reference.

## Upgrade

No migration required. This is purely additive: it adds a reference, a snippet, routing entries and a folded-in recipe. Existing motion_dev references, snippets and routes are unchanged.
