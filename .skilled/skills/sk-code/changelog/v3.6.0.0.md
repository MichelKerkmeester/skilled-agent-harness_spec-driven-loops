# v3.6.0.0, The Quality Gate Proves What It Claims

This release follows 3.5.0.0 and carries sk-code-quality 1.10.0.0 to the hub. The code family's author gate stops lending authority it cannot prove. A layer that names a checker is green only when that checker can run, a declared build output is checked with no file written anywhere, a fifty-file run finishes under a second, and a framework checklist no longer reaches a repository the runner cannot read.

> Spec folder: `specs/sk-code/015-quality-agnostic-gate/008-runner-limit-closeout` (Level 2)

&nbsp;

## What's New at a Glance

- **The quality gate proves the checker a hook names.** A `present` pre-commit layer now means the named checker resolves to an executable file, and a hook naming a deleted checker reads `broken` with the path to install. The layer state decides whether a finding on an untouched line blocks the run, so that authority now rests on a checker that will actually scan.
- **A declared build output is checked with nothing written.** The runner declares the dist entries this repository ships and sends each one to the freshness checker on its read-only path, so the verdict holds and no cache record appears beside the output. The contract states what the guard hashes and what stays outside it.
- **A fifty-file run finishes under a second.** One bounded workspace listing replaces three whole-tree walks, and a named-file scope reads none of it. The recorded command reads 0.72 s to 0.98 s against 1.97 s to 2.32 s before the change, which is the budget the measurement phase gates on.
- **The spec-folder checklist stays in this repository.** A base-layer row may carry a repository condition, so a foreign repository holding a `specs/` folder no longer receives the framework's spec-folder standard. The shared doctrine, the surface declarations and the route are unchanged.
- **A review round tightened four edges.** A declared build output is checked against the package that builds it rather than reported unmatched, a `--files` run bounds its guard snapshots to the folders its named files sit in, a repository-configured check skips a declared build output, and a hook that quotes its checker variable resolves to the checker instead of reading `broken`.

&nbsp;

## Upgrade

No migration required. A repository that wants its own build outputs checked declares them in the `generated` rows of its quality config. A consumer that reads the layer states gains one sharper meaning for `broken`, which now names an installed layer whose checker cannot run.
