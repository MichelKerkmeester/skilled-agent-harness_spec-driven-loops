# v3.9.13.0, One Registry of the Rule Ids an Override May Name

A `## Rule overrides` row misspelled its rule id. It was accepted and changed nothing. The shared linter checks grammar, action and the floor by design. So the check that an id exists had no home.

&nbsp;

## What's New at a Glance

- **The known ids come from their own documents.** `shared/scripts/lib/rule-registry.cjs` reads the runner's ids from `runner-contract.md` section 5. It reads the `floor.*` ids from `code-quality-standards.md`. It reads the `review.*` ids from `review-core.md` section 8. A row added to one of those tables is known at once. A missing section or table stops the read with its name. So does a table row whose first cell names no id. So does a reworded hygiene template. Both report their file and line.
- **A shared suite keeps the tables honest.** It fails when the floor or review tables and the contract's fixed list disagree. It also fails when a shipped checklist carries an override row. That row names an id the registry does not know.

&nbsp;

## Upgrade

Nothing to do. The quality mode reads the registry, as its own 1.13.7.0 entry describes.
