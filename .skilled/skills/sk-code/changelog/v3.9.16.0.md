# v3.9.16.0, The Hub Frontmatter Parses Under a Strict YAML Parser

A colon followed by a space inside an unquoted value reads as the start of a nested mapping, so a strict YAML parser refused the hub README's description block even though the rendering that reads it day to day never complained. The value is quoted now and its wording is unchanged. The hub SKILL.md also drops the `author: OpenCode` line from its metadata block, a field nothing read and that was not true.

> Spec folder: `specs/sk-code/017-portable-code-modes/015-frontmatter-yaml-validity` (Level 2)

&nbsp;

## What's New at a Glance

- **The README description is quoted.** A strict YAML parser reads the hub README frontmatter, and the sentence itself reads exactly as before.
- **The unused author line is gone.** The hub SKILL.md metadata block no longer claims OpenCode as its author, so the block states only what the skill is.
