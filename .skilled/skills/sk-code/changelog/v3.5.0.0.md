# v3.5.0.0, The Hub Carries One Reader for Comment Text

This release carries sk-code-quality 1.9.0.0 to the hub. The comment-hygiene checker now reads three things as text. One is a template literal that spans lines. Another is a shell heredoc body. The third is a bare Python string statement. The ceiling report now takes its comment text from the checker. It does not use a rule copy of its own.

&nbsp;

## What's New at a Glance

- A string stops being a comment.
  - Three things now read as text.
  - One is a template literal that spans lines.
  - Another is a heredoc body.
  - The third is a bare string statement.
  - So the checker flags a label only where a person reads it.
  - An `f` prefix keeps a Python string as data.
- The reading holds under harder code.
  - A regex literal is skipped whole.
  - So a backtick inside one opens no string.
  - A literal also opens after a closed block comment.
  - A literal opens after the `)` of a same-line header too.
  - A word after a `.` divides.
  - So does a postfix `++` or `--`.
  - An interpolation reads as code, with a nested template literal tracked on a stack.
  - A backslash continuation that ends in a string closes its logical line.
  - An arithmetic expansion closes at the `))` that matches its opener.
  - So a pair nested inside one does not end it early.
- The ceiling report has one source.
  - It loads the checker from beside its own real path.
  - It does this for the family table and for each line's comment text.
  - A marker after an optional comment prefix still counts.
  - It reads each line with universal newlines.
  - So a CRLF heredoc closes at its word.
  - It exits 2 with one line on any table load error.
  - That includes a table with no `hash` fallback family.
- The tree is clean.
  - The whole-tree run went from 63 findings in 41 files at f69e5cd2e8 to 0.
  - The extraction removed 3 of them.
  - The rest were rewritten to their durable reason or marked as frozen evidence.
  - The measurement is from 2026-10-26.
  - The measurement used a TypeScript scanner over every tracked JavaScript and TypeScript file.
  - The checker misses 7 of 119,929 comment lines.
  - All are scanner artifacts the base checker shares.
  - That is against 8 before.
  - The checker reports 1,220 lines the scanner does not, against 1,907 before.
- No mode or surface moved.
  - Every mode and surface the registry declared before this release is still declared.
  - The skilled mode is unchanged.
