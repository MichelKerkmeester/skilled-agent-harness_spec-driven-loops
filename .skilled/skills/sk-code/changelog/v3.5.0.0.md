# v3.5.0.0, The Hub Carries One Reader for Comment Text

This release carries sk-code-quality 1.9.0.0 to the hub. The comment-hygiene checker now reads a template literal that spans lines, a shell heredoc body and a bare Python string statement as text, and the ceiling report takes its comment text from the checker instead of a rule copy of its own.

> Spec folder: `specs/sk-code/015-quality-agnostic-gate/007-checker-debt-closeout` (Level 2)

&nbsp;

## What's New at a Glance

- **A string stops being a comment.** A template literal that spans lines, a heredoc body and a bare string statement now read as text, so the checker flags a label only where a person reads it. An `f` prefix keeps a Python string as data.
- **The reading holds under harder code.** A regex literal is skipped whole, so a backtick inside one opens no string. A literal also opens after a closed block comment and after the `)` of a same-line header, while a word after a `.` and a postfix `++` or `--` divide. An interpolation reads as code with a nested template literal tracked on a stack. A backslash continuation that ends in a string closes its logical line. An arithmetic expansion closes at the `))` that matches its opener, so a pair nested inside one does not end it early.
- **The ceiling report has one source.** It loads the checker from beside its own real path for the family table and each line's comment text, and a marker after an optional comment prefix still counts. It reads each line with universal newlines, so a CRLF heredoc closes at its word, and it exits 2 with one line on any table load error, including a table with no `hash` fallback family.
- **The tree is clean.** The whole-tree run went from 63 findings in 41 files at f69e5cd2e8 to 0. The extraction removed 3 of them, and the rest were rewritten to their durable reason or marked as frozen evidence. Measured 2026-10-26 against a TypeScript scanner over every tracked JavaScript and TypeScript file, the checker misses 7 of 119,929 comment lines, all scanner artifacts the base checker shares, against 8 before, and it reports 1,220 lines the scanner does not, against 1,907 before.
- **No mode or surface moved.** Every mode and surface the registry declared before this release is still declared, and the skilled mode is unchanged.
