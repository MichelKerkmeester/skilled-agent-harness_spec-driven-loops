This release adds the missing guidance on when and why to choose motion. The guidance sits in sk-code's Motion.dev animation references. It also adds a recipe for checking animations visually. sk-code's animation references were strong on API how-to. The strong parts were animate/timelines, scroll/gestures, integration, a decision matrix, performance pitfalls. They were light on when and why. That covers which easing to pick, concrete duration and stagger values, plus anticipation and arc guidance. They had no animation-specific visual-verification recipe. Material from the MIT-licensed `Schmandarine/web-motion-skill` was translated to the Motion.dev API. The deep analysis and draft were outsourced to `gpt-5.5-fast` (xhigh). That work happened in an isolated worktree (RM-8).

## What's New at a Glance

- **`references/motion_dev/animation-principles.md` adds guidance on motion choices.** It adds a motion vocabulary table (feedback → emphasis timing ladder). It adds easing-as-perceived-physics guidance (cubic-bezier arrays, not GSAP eases). It adds stagger direction/offset guidance. It adds anticipation/overshoot/secondary-action ranges and arc/depth notes. A visual-review checklist sits alongside them. The Motion.dev-framed reference links to existing motion_dev references. It carries MIT attribution. The source's GSAP-specific material is left out.
- **`assets/motion_dev/snippets/principled-reveal.js` composes the animation principles into a reusable reveal.** Its `@source` carries MIT attribution for the snippet. The snippet combines anticipation (scale 0.98→1) with the timing vocabulary. It also combines `stagger(offset, { from })` direction and a `prefers-reduced-motion` fallback. Each of the previous nine snippets demonstrated a single API. So this is the first reusable production-style reveal to combine several principles.
- **The performance guide adds a frame-level visual-checking recipe.** The recipe lives in `references/motion_dev/performance-and-pitfalls.md`. It checks timing and easing by eye. The steps are capture → extract frames → contact-sheet → drill-in. The folded-in recipe carries MIT attribution. It uses the project's existing bdg/chrome-devtools/Playwright tooling. It does not use the source repo's recording scripts.
- **Animation routes now reach the new material.** `references/smart-routing.md` adds the §2 Phase-1 synonyms `easing`/`stagger`/`motion principles`/`motion language` for ANIMATION. It adds `stagger()`/`animation principles` for MOTION_DEV. It then adds `animation_principles.md` and `principled_reveal.js` to the §5 MOTION_DEV map. It adds both to the §11 machine-readable `RESOURCE_MAP["MOTION_DEV"]`. The PERFORMANCE row notes the recipe. The snippet README lists the new entry. `webflow/implementation/animation_workflows.md` gains a cross-reference.

## Upgrade

No migration required. This is purely additive. It adds a reference, a snippet, routing entries and a folded-in recipe. Existing motion_dev references, snippets and routes are unchanged.
