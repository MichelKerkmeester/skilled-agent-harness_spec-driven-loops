# v3.8.0.0, Compiled Routing Evidence and Measured Results

This release follows 3.7.0.0 and carries sk-code-quality 1.12.0.0 to the hub. The three quality-mode routing canaries stop reading `pending` and record the authority that served each route, and a rendered report can now state the measures a run was built to report.

> Spec folder: `specs/sk-code/015-quality-agnostic-gate/006-measurement` (Level 2)

&nbsp;

## What's New at a Glance

- **The quality canaries record what served them.** Each one carries the compiled serving authority, the flag state, the cause and the manifest digest, so a reader can tell a compiled route from a legacy one without replaying the request.
- **A CI prompt still reaches the CI standards.** The CI workflow canary resolves a single route to the quality mode and then selects the CI intent at stage two, so the standards arrive beside the verdict.
- **A report can carry its measures.** The report renderer draws an optional results section between the run fields and the file index, from a list the record supplies, and a record without that list renders byte for byte as before.
- **The quality mode reports its catch rate.** sk-code-quality 1.12.0.0 adds seven replayable scenarios and the measured report that states the catch rate, the false positives, the wall time and the intent recall.

&nbsp;

## Upgrade

No migration required. A report record may now carry a `measures` list, and one that omits it renders without the results section, so an archived folder keeps the bytes it has.
