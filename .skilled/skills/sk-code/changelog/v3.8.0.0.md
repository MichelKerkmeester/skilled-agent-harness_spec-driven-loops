# v3.8.0.0, Compiled Routing Evidence and Measured Results

This release follows 3.7.0.0. It carries sk-code-quality 1.12.0.0 to the hub. The three quality-mode routing canaries stop reading `pending`. They record the authority that served each route. A rendered report can now state the measures a run was built to report.

&nbsp;

## What's New at a Glance

- **The quality canaries record what served them.** Each one carries the compiled serving authority. It carries the flag state, the cause and the manifest digest. So a reader can tell a compiled route from a legacy one. They need not replay the request.
- **A CI prompt still reaches the CI standards.** The CI workflow canary resolves a single route to the quality mode. Then it selects the CI intent at stage two. So the standards arrive beside the verdict.
- **A report can carry its measures.** The report renderer draws an optional results section. It sits between the run fields and the file index. It comes from a list the record supplies. A record without that list renders byte for byte as before.
- **The quality mode reports its catch rate.** sk-code-quality 1.12.0.0 adds seven replayable scenarios. It adds the measured report. That report states the catch rate, the false positives, the wall time and the intent recall.

&nbsp;

## Upgrade

No migration required. A report record may now carry a `measures` list. A record that omits it renders without the results section. So an archived folder keeps the bytes it has.
