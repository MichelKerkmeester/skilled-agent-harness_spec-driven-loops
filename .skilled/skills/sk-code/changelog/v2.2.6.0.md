# v2.2.6.0, Surface Bundles Follow Detection Precedence

A prompt that names two code surfaces now follows the hub's documented detection order. That order is OpenCode, then Obsidian, then Webflow. Before this release, `obsidian plugin webflow implementation` listed the Webflow packet first. That held even though an Obsidian plugin outranks Webflow everywhere else in the hub.

&nbsp;

## What's New at a Glance

- **Review and implementation prompts agree.** A review-phrased Obsidian and Webflow prompt already put Obsidian first. Implementation phrasing now does too. The routing canary checks both.
- **The hub page says why the order reads that way.** `SKILL.md` now states that the router's tie-break list orders surfaces by detection precedence. So a later edit to that list keeps the rule.
- **OpenCode now leads Webflow when both match.** A Webflow prompt that also carries OpenCode vocabulary used to list the Webflow packet first. That vocabulary includes `typescript`, `vitest`, `json` or `config`. It now lists the OpenCode packet first. Which packets load does not change. Only their order changes.
