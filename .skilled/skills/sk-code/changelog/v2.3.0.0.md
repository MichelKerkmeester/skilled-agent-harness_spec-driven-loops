# v2.3.0.0, A Setup Battery for the Hub

The README battery for adapting sk-code was six commands copied by hand, and its route probe could pass a hub that routes nothing. `/doctor:sk-code setup` runs the adaptation checks as one read-only pass and names the repair command for each failing leg. The adaptation guide was rewritten around that check: OpenCode is the native surface, and Webflow and Obsidian are optional examples you can remove or keep.

> Spec folder: `specs/sk-code/011-sk-code-poinytail-based-refinement/029-surface-setup-build/002-doctor-sk-code-setup` (Level 2)

&nbsp;

## What's New at a Glance

- **The hub has a doctor setup check.** `/doctor:sk-code setup` runs eight legs from the repository root, and the hub `SKILL.md` and README point to it after you add or remove a surface.
- **OpenCode is the native surface.** The surface list now names it native with Webflow and Obsidian as optional examples, and the adaptation guide covers keeping, removing or adding a surface.
- **A pasted probe line reruns the same prompt.** The setup report shell-quotes the probe prompt, so quotes or special characters in your prompt no longer change what a pasted line runs.
- **The setup check has manual test scenarios.** The playbook walks the battery on a clean tree and in a checkout that predates the v4 layout.
