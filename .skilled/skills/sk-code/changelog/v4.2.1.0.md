# v4.2.1.0 root ROUTER.md adoption

`sk-code` now owns its second-stage surface router as root `ROUTER.md`. Hub-shared controls are explicit rather than treated as packet-owned leaves, while all 20 intent/resource keys and the stage-one fallback are preserved.

## What's New at a Glance

- **Ten shared paths now use contained `shared/...` paths.** They were normalized from legacy-file-relative paths. Eight mapped hub-shared paths are declared in `SHARED_CONTROL_RESOURCES`. They resolve on disk but never project as typed leaves.
- **The active router now lives at root `ROUTER.md`.** The file sets `router_state: active` and `skill_pointer: SKILL.md`. It carries the existing surface-routing policy. The stage-two default preamble no longer has the obsolete router self-reference.
- **`hub-router.json` keeps its default resource.** Its `routerPolicy.defaultResource` is exactly `["shared/README.md"]`.
- **Hub references now use root `ROUTER.md`.** Hub docs, description, graph key paths, deep-alignment adapter and live router-sync guard use that path.
- **`SKILL.md`, README and description now align.** Each is at version 4.2.1.0.
- **All 20 intent/resource keys and the stage-one fallback are preserved.** The intent/resource key sets and order, two workflow modes, two surface packets, surface-bundle policy and advisor identity are unchanged.
- **Frozen evidence and historical records are unchanged.** Frozen replay/scorer bytes and protected digests, historical changelog and benchmark evidence are unchanged. The Barter cross-project note remains a deliberate external reference to that project's independent legacy layout.
