# v4.2.1.0 root ROUTER.md adoption

sk-code now owns its second-stage surface router as root `ROUTER.md`. The move preserves all 20 intent/resource keys and the stage-one fallback while making hub-shared controls explicit instead of pretending they are packet-owned leaves.

## What Changed

- Added root `ROUTER.md` with `router_state: active`, `skill_pointer: SKILL.md`, and the existing surface-routing policy.
- Removed the obsolete router self-reference from the stage-two default preamble.
- Normalized ten legacy-file-relative shared paths to contained `shared/...` paths.
- Declared the eight mapped hub-shared paths in `SHARED_CONTROL_RESOURCES`; they resolve on disk but never project as typed leaves.
- Preserved `hub-router.json` `routerPolicy.defaultResource` exactly as `["shared/README.md"]`.
- Updated the hub docs, description, graph key paths, deep-alignment adapter, and live router-sync guard to use root `ROUTER.md`.
- Aligned `SKILL.md`, README, and description at version 4.2.1.0.

## Not Changed

- Intent/resource key sets or their order.
- The two workflow modes, two surface packets, surface-bundle policy, or advisor identity.
- Frozen replay/scorer bytes and protected digests.
- Historical changelog and benchmark evidence. The Barter cross-project note remains a deliberate external reference to that project's independent legacy layout.

## Verification Boundary

Standalone root-contract validation and the parent doctor must pass after legacy deletion. Compiled-manifest freshness remains the downstream fleet-rebuild and canonical-sync gate.
