# sk-code v3.0.0.0, Project-Agnostic Stack Stubs

This release reconciles the multi-stack scaffolding and replaces it with honest, project-agnostic stubs across the NEXTJS and GO stacks. The Webflow stack remains live and untouched.

> Spec folder: `skilled-agent-orchestration/057-sk-code-multi-stack-placeholders`

## Why This Release

Packet 056 left the multi-stack scaffolding in a partial state.

## What's New at a Glance

- **The NEXTJS folder changes from `nextjs` to `react`.** Its path aligns with the `STACK_FOLDERS["NEXTJS"]` contract.
- **Asset trees are created for NEXTJS and GO.** Their directories were previously absent.
- **NEXTJS and GO receive project-agnostic stub content.** The stubs follow a canonical placeholder template.
- **`SKILL.md` marks NEXTJS and GO as scaffolded stubs.** Its routes, resource domains and frontmatter description distinguish them from live content.
- **Four carry-over guides become project-agnostic stubs.** Their structural sections are preserved.
- **Cross-stack pairing guidance uses generic small-scope language.** The canonical contract keeps its structural sections.
- **Packet 056 is superseded.** Its `spec.md` gains a `superseded_by` frontmatter line.

---

## Stack Scaffolding

#### Folder Rename: nextjs to react

The folder rename ran `git mv references/nextjs references/nextjs` to align the disk path with the `STACK_FOLDERS["NEXTJS"]` contract used by `SKILL.md`, `references/stack-detection.md`, `references/smart-routing.md`, `description.json` and `graph-metadata.json`. Every `resource_map_for(NEXTJS)` path now resolves.

&nbsp;

#### Stub Assets Follow a Canonical Template

The release created the `assets/nextjs/{checklists,patterns,integrations}/` and `assets/go/{checklists,patterns}/` directory trees, which were previously absent.

The release added 43 stub files across `references/{react,go}/` and `assets/{react,go}/`: 23 NEXTJS (12 references + 3 checklists + 5 patterns + 3 integrations) and 20 GO (12 references + 3 checklists + 5 patterns). Each stub uses the canonical placeholder template with YAML frontmatter (`status: stub`, `populated: false`, `last_synced_at: 2026-04-30`), a short Intended-scope paragraph, Outline (TODO) bullets and See-also references.

Markdown stubs contain no fenced code blocks. The stubs contain no library version pins and no project-specific names.

&nbsp;

#### Code Stubs Have No Bodies

The `.tsx`, `.ts`, `.go`, `.css.ts` and `_test.go` stubs have no function bodies. They are comment-only except that Go files include the trivial `package patterns` declaration and the test stub uses an empty `TestStub` placeholder.

## Stack Guidance

#### Routes Distinguish the Stubs

In the Routes block (§2) of `SKILL.md`, NEXTJS and GO change from "full live content" to "scaffolded stub content". In Resource Domains (§2), both directories change from `LIVE` to `STUB (target: …)`, and `cross_stack_pairing.md` is identified as canonical rather than a stub. In the frontmatter description, Webflow stays live, while NEXTJS and GO are described as scaffolded stubs for the future.

&nbsp;

#### Carry-Over Guides Become Project-Agnostic Stubs

The release rewrote `references/{react,go}/README.md` and `references/{react,go}/implementation/implementation_workflows.md`, four carry-over files from packet 056, as project-agnostic stubs. The rewrite removed project-specific phrasing and kept the subfolder map, asset map, verification commands and see-also sections.

---

## Cross-Stack Pairing

#### Pairing Guidance Stays Intact

`references/cross_stack_pairing.md` remains the canonical contract. The release removed the project-name keyword and project-scoped phrasing in favor of generic small-scope language. Its topology, error envelope, JWT handoff, CORS, pagination, deploy table and drift detection sections are intact.

---

## Packet Lineage

#### Packet 056 Is Superseded

This release supersedes packet `skilled-agent-orchestration/056-sk-code-fullstack-branch`. Its `spec.md` now carries a `superseded_by` frontmatter line for discoverability.
