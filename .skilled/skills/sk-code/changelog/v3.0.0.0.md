# v3.0.0.0, Declared Surfaces Now Lead Detection

This is a major release for sk-code.

- The hub shipped two surfaces for specific stacks, Webflow and Obsidian.
- Both are gone.
- An operator who used the removed surfaces can rebuild each one.
- The rebuild is an operator-private `local-*` skill with its own detection block.

Detection also changed order.

- It checked the native surface first.
- So a surface you added could never outrank it.
- Each detected surface now declares its own detection block.
- The native surface is checked last.

The hub ships one native surface for this framework's own code.

- It also ships one CI surface for GitHub Actions workflows.
- Work on the framework's own files keeps its standards.
- That is because the native surface still leads whenever no specific surface matches.

> [!IMPORTANT]
> 2 changes can break an existing setup. Read these before you update.
>
> 1. A task matching a specific surface now loads that surface first. [The Native Surface Leads Only Alone](#c-the-native-surface-leads-only-alone)
> 2. A project depending on Webflow or Obsidian standards loses them from this hub. [Webflow And Obsidian Leave The Hub](#c-webflow-and-obsidian-leave-the-hub)

&nbsp;

## Why This Release

The hub carried web-era material it no longer needed. Its detection order was also fixed in code. So a stack you declared could never outrank the native surface.

- Your stack can lead.
- A surface you add outranks the native surface when both match.
- An operator-private skill outranks the native surface when both match.
- The hub stays focused.
- Two shipped surfaces leave.
- The hub keeps one native surface and one CI surface.
- The order is checked.
- The registry compiler stops a hub whose native fallback is not ranked last.

## Detection Order

Stack detection reads the order from the declared surface blocks. For the hub's own surfaces, that is `mode-registry.json`. For skills outside the hub, that is `graph-metadata.json`.

Specific surfaces come first. Then the outside skills that declare a `surface_detection` block. Then the native surface and UNKNOWN last.

#### The Native Surface Leads Only Alone <a id="c-the-native-surface-leads-only-alone"></a>

> [!WARNING]
> A task that matches a specific surface now loads that surface first. That holds even when it also touches `.skilled/` files. If a route depended on the native standards leading, check it after you upgrade.

- A specific surface and the native surface can both match.
- Then the specific surface leads.
- The native standards come along as second evidence.
- The native surface leads only when no specific surface matched.
- A `--surface-hint SKILLED` hint changes nothing.
- That is because the native surface already ranks last.

#### Your Surface Can Outrank The Native One <a id="c-your-surface-can-outrank-the-native-one"></a>

- A surface you add to the hub ranks ahead of the native one in `routerPolicy.tieBreak`.
- A skill outside the hub can also outrank the native surface.
- It declares a `surface_detection` block in its `graph-metadata.json`.
- It names `sk-code` as its family.
- It ranks after the hub's own specific surfaces.
- The block needs the role `specific`, a label and at least one marker.
- Without those, it never matches.

## Removed Surfaces

#### Webflow And Obsidian Leave The Hub <a id="c-webflow-and-obsidian-leave-the-hub"></a>

> [!WARNING]
> A project that depended on the Webflow or Obsidian standards loses them from this hub. Rebuild each one as a `local-*` skill, as the upgrade notes describe.

- The Webflow and Obsidian surface packets are deleted.
- Their routes, playbook scenarios and catalog entries are deleted too.
- v2.3.0.0 called them optional examples you could keep.
- That is no longer true.
- The hub ships no code for either stack.

#### Shared References Moved Or Went <a id="c-shared-references-moved-or-went"></a>

- Six files left `shared/references/`.
- Five were deleted and one moved.
- The universal debugging and verification checklists are gone.
- `workflow-verify.md` gained the few gates only the verification checklist had.
- The error recovery notes became the command failure recovery section of `workflow-debug.md`.
- The performance checklist and the multi-agent research audit are deleted.
- The hub no longer routes performance work.
- The code style guide moved into the quality mode that owns it.

#### Naming Is A P1 Item <a id="c-naming-is-a-p1-item"></a>

- In the shared code quality standard, naming moved from P0 to P1.
- A misnamed identifier needs a fix or an approved deferral.
- It no longer blocks completion by itself.

## Doctor And Agents

#### Private Skills Stay Out Of Catalogs <a id="c-private-skills-stay-out-of-catalogs"></a>

- The catalog mirror check and the skill graph freshness check now skip `local-*` skills.
- A private skill lives in one checkout.
- So it never counts toward a tracked catalog.
- The parent-skill check no longer lists Webflow and Obsidian as example surfaces.
- That is because the hub ships none.

#### Agents Fall Back To Private Skills <a id="c-agents-fall-back-to-private-skills"></a>

- When sk-code returns UNKNOWN, `@code` and `@review` ask the skill advisor for a top pick.
- This holds in every runtime copy of the agent.
- A `local-*` pick loads as the standards overlay.
- Without one, `@code` escalates an unknown route.
- `@review` reviews against the baseline security and correctness minimums.
- It says it is uncertain.

#### A Doctor Command For CI Workflows <a id="c-a-doctor-command-for-ci-workflows"></a>

- `/doctor:ci` belongs to the hub's CI surface.
- Its `report` route is the default.
- It reads every workflow with its switch state, triggers, path filters and drift flags.
- It writes nothing.

<details>
<summary><b>Scaffold and toggle routes</b></summary>

- `scaffold` writes one new workflow from the CI templates after you say yes.
- `toggle` turns one `SKILLED_CI*` variable off or back on after you say yes.
- It refuses to switch off `SKILLED_CI_MESSAGES` or `SKILLED_CI`.
- That is because a skipped job reports Success.
- The required message check would then pass a commit with a wrong message.

</details>

## Routing Vocabulary

#### Web And Motion Words Leave Routing <a id="c-web-and-motion-words-leave-routing"></a>

- Web, motion and Obsidian terms left the hub's routing vocabulary.
- So a prompt that names only those stacks no longer routes here.
- The CI surface gained job, pinned action and workflow path terms.
- A review that names only a `.github/workflows/` path now loads the CI rules.
- A surface routes alone when no workflow mode scores.
- Plain bug, bash and `.ts` prompts now route to the native surface.

#### A Correction To v2.4.0.0 <a id="c-a-correction-to-v2400"></a>

- v2.4.0.0 said its registration removed no mode or surface.
- That was wrong.
- The Webflow and Obsidian packets were already gone from the tree that release shipped.
- It also said two runtime keywords kept a test matrix or a scorer ruleset out of the CI surface.
- The keywords are `build matrix` and `branch ruleset`.
- Neither keyword ships.
- Of the three keywords that entry named, only `actions cache key` does.

## Upgrade Notes

The upgrade notes say what an adopter must change. Paths below are relative to `.skilled/skills/sk-code/`.

#### Before You Start <a id="c-before-you-start"></a>

1. Rebuild each removed surface as an operator-private `local-*` skill. This repository ignores `local-*` skills. So keep it in your own checkout. Give it a `surface_detection` block with `"role": "specific"`, a label and at least one marker.
2. Then check the route with `node .skilled/bin/compiled-route.cjs --hub sk-code --prompt "<a prompt about your stack>"`.
3. When you add a surface by hand, keep `sk-code-skilled` last in `routerPolicy.tieBreak` in `hub-router.json`. The registry compiler rejects a hub whose fallback is not last.
