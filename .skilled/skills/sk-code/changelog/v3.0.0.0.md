# v3.0.0.0, Declared Surfaces Now Lead Detection

This is a major release for sk-code. The hub shipped two surfaces for specific stacks, Webflow and Obsidian. Both are gone. Detection also changed order. It checked the native surface first, so a surface you added could never outrank it. Each detected surface now declares its own detection block. The native surface is checked last.

The hub ships one native surface for this framework's own code and one CI surface for GitHub Actions workflows. Work on the framework's own files keeps its standards, because the native surface still leads whenever no specific surface matches. An operator who used the removed surfaces can rebuild each one as an operator-private `local-*` skill with its own detection block. The upgrade notes say what an adopter must change.

&nbsp;

## Why This Release

The hub carried web-era material it no longer needed. Its detection order was also fixed in code, so a stack you declared could never outrank the native surface.

- **Your stack can lead.** A surface you add, or an operator-private skill, outranks the native surface when both match.
- **The hub stays focused.** Two shipped surfaces leave, and the hub keeps one native surface and one CI surface.
- **The order is checked.** The registry compiler stops a hub whose native fallback is not ranked last.

&nbsp;

## What's New at a Glance

- **Webflow and Obsidian leave the hub.** Their surface packets, routes, playbook scenarios and catalog entries are deleted.
- **Declared surfaces lead detection.** A specific surface matches first, and the native standards follow as second evidence.
- **Shared references moved or went.** Five shared references were deleted, and the code style guide moved into the quality mode.
- **Private skills stay out of doctor checks.** The catalog and freshness checks skip `local-*` skills.
- **Agents fall back to private skills.** `@code` and `@review` load a `local-*` top pick when sk-code returns UNKNOWN.
- **A doctor command for CI.** `/doctor:ci` reports, scaffolds and toggles GitHub Actions workflows.
- **A correction to v2.4.0.0.** Its no-migration note was wrong, and two of the three keywords it named never shipped.

&nbsp;

## Detection Order

Stack detection reads the order from the declared surface blocks, in `mode-registry.json` for the hub's own surfaces and in `graph-metadata.json` for skills outside the hub. Specific surfaces come first, then the outside skills that declare a `surface_detection` block, then the native surface and UNKNOWN last.

#### The Native Surface Leads Only Alone

When a specific surface and the native surface both match, the specific surface leads and the native standards come along as second evidence. The native surface leads only when no specific surface matched. A `--surface-hint SKILLED` hint changes nothing, because the native surface already ranks last.

**Breaking:** A task that matches a specific surface now loads that surface first, even when it also touches `.skilled/` files. If a route depended on the native standards leading, check it after you upgrade.

#### Your Surface Can Outrank The Native One

A surface you add to the hub ranks ahead of the native one in `routerPolicy.tieBreak`. A skill outside the hub can also outrank the native surface. It declares a `surface_detection` block in its `graph-metadata.json` and names `sk-code` as its family, and it ranks after the hub's own specific surfaces. The block needs the role `specific`, a label and at least one marker, or it never matches.

## Removed Surfaces

#### Webflow And Obsidian Leave The Hub

The Webflow and Obsidian surface packets are deleted, along with their routes, playbook scenarios and catalog entries. v2.3.0.0 called them optional examples you could keep. That is no longer true, and the hub ships no code for either stack.

**Breaking:** A project that depended on the Webflow or Obsidian standards loses them from this hub. Rebuild each one as a `local-*` skill, as the upgrade notes describe.

#### Shared References Moved Or Went

Six files left `shared/references/`: five were deleted and one moved. The universal debugging and verification checklists are gone. `workflow-verify.md` gained the few gates only the verification checklist had. The error recovery notes became the command failure recovery section of `workflow-debug.md`. The performance checklist and the multi-agent research audit are deleted, and the hub no longer routes performance work. The code style guide moved into the quality mode that owns it.

#### Naming Is A P1 Item

In the shared code quality standard, naming moved from P0 to P1. A misnamed identifier needs a fix or an approved deferral, but it no longer blocks completion by itself.

## Doctor And Agents

#### Private Skills Stay Out Of Catalogs

The catalog mirror check and the skill graph freshness check now skip `local-*` skills. A private skill lives in one checkout, so it never counts toward a tracked catalog. The parent-skill check no longer lists Webflow and Obsidian as example surfaces, because the hub ships none.

#### Agents Fall Back To Private Skills

When sk-code returns UNKNOWN, `@code` and `@review` ask the skill advisor for a top pick, in every runtime copy of the agent. A `local-*` pick loads as the standards overlay. Without one, `@code` escalates an unknown route, and `@review` reviews against the baseline security and correctness minimums and says it is uncertain.

#### A Doctor Command For CI Workflows

`/doctor:ci` belongs to the hub's CI surface. Its `report` route is the default. It reads every workflow with its switch state, triggers, path filters and drift flags. It writes nothing. `scaffold` writes one new workflow from the CI templates after you say yes. `toggle` turns one `SKILLED_CI*` variable off or back on after you say yes. It refuses to switch off `SKILLED_CI_MESSAGES` or `SKILLED_CI`, because a skipped job reports Success and the required message check would then pass a commit with a wrong message.

&nbsp;

## Routing Vocabulary

#### Web And Motion Words Leave Routing

Web, motion and Obsidian terms left the hub's routing vocabulary, so a prompt that names only those stacks no longer routes here. The CI surface gained job, pinned action and workflow path terms. A review that names only a `.github/workflows/` path now loads the CI rules, and a surface routes alone when no workflow mode scores. Plain bug, bash and `.ts` prompts now route to the native surface.

#### A Correction To v2.4.0.0

v2.4.0.0 said its registration removed no mode or surface. That was wrong, because the Webflow and Obsidian packets were already gone from the tree that release shipped. It also said the runtime keywords `build matrix` and `branch ruleset` kept a test matrix or a scorer ruleset out of the CI surface. Neither keyword ships. Of the three keywords that entry named, only `actions cache key` does.

## Upgrade Notes

Paths below are relative to `.skilled/skills/sk-code/`.

- **Adopt.** Rebuild each removed surface as an operator-private `local-*` skill. This repository ignores `local-*` skills, so keep it in your own checkout. Give it a `surface_detection` block with `"role": "specific"`, a label and at least one marker. Then check the route with `node .skilled/bin/compiled-route.cjs --hub sk-code --prompt "<a prompt about your stack>"`.
- **Adopt.** When you add a surface by hand, keep `sk-code-skilled` last in `routerPolicy.tieBreak` in `hub-router.json`. The registry compiler rejects a hub whose fallback is not last.
- **Adopt.** Run `/doctor:ci report` to see each workflow's switch state before you toggle one.
- **Repoint.** `shared/references/universal/code-style-guide.md` is now `sk-code-quality/references/code-style-guide.md`.
- **Repoint.** Use `shared/references/workflow-debug.md` for the debugging steps that `shared/references/universal-debugging-checklist.md` held, and `shared/references/workflow-verify.md` for the gates that `shared/references/universal-verification-checklist.md` held. Both checklist files are gone.
- **Repoint.** `shared/references/universal/error-recovery.md` is now the Command Failure Recovery section of `shared/references/workflow-debug.md`.
- **Drop.** `shared/references/universal/multi-agent-research.md` and `shared/references/performance-loading-checklist.md`. The hub has no replacement for either.
- **Drop.** The Webflow and Obsidian surface packets, and any path, route or scenario that names them.

The four mode packets keep their own changelogs and version lines, so read their entries for the changes that belong to them.
