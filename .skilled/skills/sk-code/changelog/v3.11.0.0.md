# v3.11.0.0, Visual Value Requests Reach the Frontend Surface

A request to pick a padding, build a palette, fix a screen that looks wrong, time an animation or review a design now lands on `sk-code` and loads the frontend surface's visual references.

> Spec folder: `specs/sk-design/021-deprecate-fundamentals` (Level 2)

&nbsp;

## What's New at a Glance

- **A `code-frontend-visual` vocabulary class** sends visual-value phrases to `sk-code-frontend`.
- **The advisor knows the phrases.** `graph-metadata.json` `intent_signals` carries the screen-design vocabulary the design hub gave up.
- **Design review requests reach both surfaces.** "design review", "design review findings" and "review this design" now bring in code review and the frontend surface together, so the visual review pass runs.
- **The review route loads the accessibility patterns.** `WEB_VISUAL_HIERARCHY` now also loads `web-accessibility-patterns.md`, so a visual review finding can point at the accessibility pattern that fixes it.
- **The hub docs name the new owner and what it carries.** `SKILL.md` and `README.md` send an open visual value to `sk-code-frontend`. The hub description and surface table list the three visual references and the starter `tokens.css` file.
