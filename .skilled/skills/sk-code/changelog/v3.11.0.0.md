# v3.11.0.0, Visual Value Requests Reach the Frontend Surface

A request can pick a padding, build a palette or time an animation. It can fix a screen that looks wrong or review a design. That request now lands on `sk-code`. It loads the frontend surface's visual references.

&nbsp;

## What's New at a Glance

- **A `code-frontend-visual` vocabulary class** sends visual-value phrases to `sk-code-frontend`.
- **The advisor knows the phrases.** `graph-metadata.json` `intent_signals` carries the screen-design vocabulary. The design hub gave that vocabulary up.
- **Design review requests reach both surfaces.** Three phrases now bring in code review and the frontend surface together. They are "design review", "design review findings" and "review this design". So the visual review pass runs.
- **The review route loads the accessibility patterns.** `WEB_VISUAL_HIERARCHY` now also loads `web-accessibility-patterns.md`. So a visual review finding can point at the accessibility pattern that fixes it.
- **The hub docs name the new owner and what it carries.** `SKILL.md` and `README.md` send an open visual value to `sk-code-frontend`. The hub description and surface table list the three visual references. They also list the starter `tokens.css` file.
