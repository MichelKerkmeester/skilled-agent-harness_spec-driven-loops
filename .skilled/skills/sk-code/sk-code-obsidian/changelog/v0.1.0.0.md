# v0.1.0.0 — obsidian surface established

First release of the `sk-code-obsidian` surface packet on the `sk-code` hub's surface axis, and the
single source of truth for the Note Database Obsidian plugin. Code work on the plugin previously
resolved to `UNKNOWN`, loading none of its conventions: not the Obsidian plugin API boundary, not
the single-stylesheet ownership model, not the `.db-*` class grammar, not the screenshot harness
contract. This surface makes `OBSIDIAN` a first-class detected surface, bundled alongside a
workflow mode exactly as `sk-code-webflow` / `sk-code-opencode` / `sk-code-mobile-cli` are, and the
plugin tree now carries the source conventions this packet documents.

## Packet content

- `SKILL.md` — the surface contract with a `metadata` block (`family: sk-code`, `packetKind:
  surface`), the reference map, the machine-readable SMART ROUTING, the non-negotiable
  design/security standards, an assets section, and the read-only rules — mirroring the sibling
  surface-packet structure.
- `references/` — 18 files across the top level and four purpose-named subfolders plus 3
  symlinked workflow documents: `obsidian-plugin-api.md`, `data-layer.md`,
  `view-renderer-architecture.md`, `stylesheet-ownership.md`, `theme-variables.md`,
  `db-class-naming.md`, `comment-grammar.md`, `folder-docs.md`, `screenshot-harness.md`,
  `mobile-and-touch.md`, `accessibility.md`, `verification.md`, plus
  `setup/setup.md`, `standards/code-standards.md`, `standards/platform-support.md`,
  `operations/operations.md`, `release/release-verification.md`, `quality/doc-quality-gate.md`, and
  the shared implement/debug/verify doctrine symlinked from `../../shared/`
  (`workflow-implement.md`, `workflow-debug.md`, `workflow-verify.md`).
- `assets/` — 7 checklists: `comment-banner-checklist.md`, `db-class-rename-checklist.md`,
  `fixture-authoring-checklist.md`, `folder-docs-checklist.md`, `modal-coverage-checklist.md`,
  `screenshot-coverage-checklist.md`, `verification-checklist.md`.
- `manual-testing-playbook/` — 7 routing scenarios (`db-class-rename-routing.md`,
  `debugging-routing.md`, `folder-docs-routing.md`, `modal-screenshot-routing.md`,
  `renderer-feature-routing.md`, `stack-standards-routing.md`, `verification-routing.md`) plus an
  index (`manual-testing-playbook.md`).
- `scripts/run-source-gates.sh` — one entry point that runs the plugin's four source gates
  (`scan-naming.mjs`, `scan-comments.mjs`, `scan-folder-docs.mjs`, `scan-skill-references.mjs`) in
  sequence from the plugin repo root, printing a PASS/FAIL line per guard.
- `README.md`, `changelog/`.

## Hub wiring (parent `sk-code`)

- `mode-registry.json` — new `modes[]` entry (`packetKind: surface`, `backendKind: evidence-base`,
  read-only `toolSurface`, `routingClass: metadata`) and `extensions.surface-axis.surfaces`.
- `hub-router.json` — `routerSignals["sk-code-obsidian"]`, vocabulary classes
  `code-obsidian-{aliases,runtime}`, and `routerPolicy.tieBreak` membership.
- `shared/references/stack-detection.md` — the `OBSIDIAN` surface's markers (`manifest.json` with
  `minAppVersion`, `esbuild.config.mjs`, `from "obsidian"` imports, the single `styles.css` carrying
  `.db-*` classes), its precedence (`OPENCODE > OBSIDIAN > PI_REMOTE > WEBFLOW > UNKNOWN`, with an
  explicit symlink guard so an `OPENCODE` target only wins when its resolved real path lands inside
  the hub's own `.opencode/` directory), and test cases.
- `ROUTER.md` and the router-sync drift guard's `SURFACES` list were deliberately **not** modified.
  Unlike `sk-code-mobile-cli`, this packet exposes no leaf resources that need a stage-two routing
  entry, so it is reached only through the mode-registry bundle path
  (`routerPolicy.outcomes.surfaceBundle`), with no `RESOURCE_MAP` projection to keep in sync.

## Plugin-side convention adoption

- **Folder docs**: 19 files (10 `README.md`, 9 `CODE.md`) across every source folder under `src/`
  and `tools/` that owes them, turning `scan-folder-docs.mjs` from 19 violations to a clean exit.
- **Stylesheet sections**: `styles.css`'s 312-line Chinese tutorial preamble replaced with a real
  English header, and its 33 section banners renumbered and rewritten as numbered upper-case
  box-drawing sections, in place, with a byte-equality guard proving no CSS rule moved.
- **Kebab-case rename**: 235 files renamed from PascalCase/camelCase to lowercase-kebab via
  `git mv` (0 failures, 0 collisions), with 189 import specifiers and 56 repo-relative path
  references rewritten from the same manifest, plus 10 bare-filename references across 6 renamed
  target files that only vitest's live test run caught.
- **Three scanners** (`scan-naming.mjs`, `scan-folder-docs.mjs`, `scan-comments.mjs`) plus a fourth
  (`scan-skill-references.mjs`) checking this surface packet's own cross-repo plugin-path
  references, all runnable together via `scripts/run-source-gates.sh`.

## Notes

`packetKind: surface`, `backendKind: evidence-base`, read-only (`toolSurface` ⊆ {Read, Bash, Grep,
Glob}), advisor-invisible (`routingClass: metadata`). Reached only by the hub bundling it alongside
a workflow mode via `routerPolicy.outcomes.surfaceBundle`; it never routes as a primary and mutates
nothing.

This release is not a closed packet. `scan-comments.mjs` still reports 249 files missing the
per-file `MODULE:` banner and numbered sections — that pass was deliberately deferred, not part of
the folder-doc/stylesheet work above, and remains future work. `description.json` could not be
generated for any phase leaf in this packet's spec-kit trail because the `system-spec-memory` MCP
was down for the duration of this work; every leaf carries that as a known environmental gap.
Doc-template conformance and surface-reality conformance audits (verifying every packet document
against its sk-doc template, and every claim this surface makes against the real plugin tree) have
not yet run.
