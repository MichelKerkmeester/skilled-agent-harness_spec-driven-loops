# v0.1.0.0, Obsidian Surface Established

The first `sk-code-obsidian` release gives the Note Database Obsidian plugin a single source of truth in a surface packet. The surface packet is on the `sk-code` hub's surface axis and makes `OBSIDIAN` a first-class detected surface, bundled alongside a workflow mode exactly as `sk-code-webflow` and `sk-code-opencode` are.

## Why This Release

Code work on the plugin previously resolved to `UNKNOWN`, loading none of its conventions: not the Obsidian plugin API boundary, not the single-stylesheet ownership model, not the `.db-*` class grammar and not the screenshot contract in `screenshot-harness.md`.

## What's New at a Glance

- **`OBSIDIAN` is a first-class detected surface.** The parent `sk-code` hub's `shared/references/stack-detection.md` records the `OBSIDIAN` surface's markers, its precedence and test cases.
- **`SKILL.md` defines the Obsidian surface contract.** The packet provides reference material, assets and routing scenarios for the plugin.
- **The plugin tree now carries the source conventions this packet documents.** Source folders have docs, stylesheet sections were rewritten and files use lowercase-kebab names.
- **A packet script runs four plugin source gates.** `scripts/run-source-gates.sh` runs them from the plugin repo root.
- **The hub exposes the surface as read-only bundled evidence.** The surface is reached through `routerPolicy.outcomes.surfaceBundle`, not as a primary route.
- **This release is not a closed packet.** Comment-banner work was deferred, phase metadata could not be generated and conformance audits have not run.

## Surface Packet

#### A Surface-Specific Contract

`SKILL.md` mirrors the sibling surface-packet structure and carries the surface contract with `metadata` values `family: sk-code` and `packetKind: surface`. `SKILL.md` also holds the reference map, the machine-readable SMART ROUTING, the non-negotiable design and security standards, an assets section and the read-only rules.

&nbsp;

#### References Cover Plugin Conventions

Across the top level and four purpose-named subfolders, `references/` contains 18 files. They cover the Obsidian plugin API boundary, data layer, view-renderer architecture, stylesheet ownership, theme variables, `.db-*` class naming, comment grammar, folder docs, the screenshot contract in `screenshot-harness.md`, mobile and touch, accessibility, verification, setup, code and platform standards, operations, release verification and doc quality. Three shared workflow documents, `workflow-implement.md`, `workflow-debug.md` and `workflow-verify.md`, are symlinked from `../../shared/`.

&nbsp;

#### Obsidian Stack Detection

In the parent `sk-code` hub, `shared/references/stack-detection.md` records the `OBSIDIAN` surface's markers: `manifest.json` with `minAppVersion`, `esbuild.config.mjs`, `from "obsidian"` imports and the single `styles.css` carrying `.db-*` classes. It records the surface's precedence, `OPENCODE > OBSIDIAN > WEBFLOW > UNKNOWN`, with an explicit symlink guard so an `OPENCODE` target only wins when its resolved real path lands inside the hub's own `.opencode/` directory.

&nbsp;

#### Checklists and Routing Scenarios

`assets/` contains seven checklists: `comment-banner-checklist.md`, `db-class-rename-checklist.md`, `fixture-authoring-checklist.md`, `folder-docs-checklist.md`, `modal-coverage-checklist.md`, `screenshot-coverage-checklist.md` and `verification-checklist.md`. `manual-testing-playbook/` contains seven routing scenarios: `db-class-rename-routing.md`, `debugging-routing.md`, `folder-docs-routing.md`, `modal-screenshot-routing.md`, `renderer-feature-routing.md`, `stack-standards-routing.md` and `verification-routing.md`. `manual-testing-playbook.md` indexes them.
The packet also contains `README.md` and `changelog/`.

## Plugin Conventions

#### Folder Docs Cover Source Folders

The plugin gained 19 folder docs across every source folder under `src/` and `tools/` that owes them, turning `scan-folder-docs.mjs` from 19 violations to a clean exit. They comprise 10 `README.md` files and 9 `CODE.md` files.

&nbsp;

#### Stylesheet Sections Are Reworked

The 312-line Chinese tutorial preamble in `styles.css` was replaced with a real English header. Its 33 section banners were renumbered and rewritten in place as numbered upper-case box-drawing sections, and no CSS rule moved.

&nbsp;

#### Names and References Use Kebab-Case

The rename moved 235 files from PascalCase or camelCase to lowercase-kebab via `git mv`, with 0 failures and 0 collisions. From the same manifest, 189 import specifiers and 56 repo-relative path references were rewritten, plus 10 bare-filename references across 6 renamed target files that only vitest's live test run caught.

&nbsp;

#### Four Source Gates Run Together

The packet's `scripts/run-source-gates.sh` is one entry point that runs the plugin's four source gates in sequence from the plugin repo root. It runs `scan-naming.mjs`, `scan-comments.mjs`, `scan-folder-docs.mjs` and `scan-skill-references.mjs`, printing a PASS/FAIL line per guard. `scan-skill-references.mjs` checks this surface packet's own cross-repo plugin-path references.

## Hub Routing

#### Read-Only Evidence Entry

`mode-registry.json` adds a `modes[]` entry with `packetKind: surface`, `backendKind: evidence-base` and a read-only `toolSurface` limited to `Read`, `Bash`, `Grep` and `Glob`. Its `routingClass: metadata` makes it advisor-invisible, and `extensions.surface-axis.surfaces` lists the surface.

&nbsp;

#### Bundle-Only Routing

`hub-router.json` adds `routerSignals["sk-code-obsidian"]`, the vocabulary classes `code-obsidian-{aliases,runtime}` and membership in `routerPolicy.tieBreak`. The packet is reached only through the mode-registry bundle path `routerPolicy.outcomes.surfaceBundle`, never routes as a primary and mutates nothing. It exposes no leaf resources that need a stage-two routing entry, so no `RESOURCE_MAP` projection needs to stay in sync. `ROUTER.md` and the router-sync drift guard's `SURFACES` list were deliberately not modified.

## Known Gaps

#### Comment Banners Were Deferred

`scan-comments.mjs` still reports 249 files missing the per-file `MODULE:` banner and numbered sections. This pass was deliberately deferred, was not part of the folder-doc or stylesheet work and remains future work.

&nbsp;

#### Phase Metadata Gap

`description.json` could not be generated for any phase leaf in this packet's spec-kit trail because the `system-spec-memory` MCP was down for the duration of this work. Every leaf carries that as a known environmental gap.

&nbsp;

#### Conformance Audits Have Not Run

The doc-template conformance audit verifies every packet document against its `sk-doc` template and has not yet run. The surface-reality conformance audit verifies every claim this surface makes against the real plugin tree and has not yet run either.

## Upgrade Notes

No upgrade needed.
