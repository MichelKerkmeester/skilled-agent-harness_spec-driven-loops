# v1.9.6.0, The Review Agent Follows the Mode

The review agent used to carry a checklist of its own. It failed any change that scored below 70, even with no blocking finding. That contradicted the mode's rule that a P2 never blocks. Now the agent applies the mode's floor and lens. Its pass or fail follows severity alone. The two report checkers catch an agent report whose recommendation disagrees with its findings.

&nbsp;

## What's New at a Glance

- **The verdict follows severity.** Any P0, or an open P1, fails the review. The 100-point score stays as advisory information. It never decides the verdict.
- **No house rules in the agent.** Commit-format, merge-commit, change-size, complexity and browser-only checks are gone. PR and commit rules come from what the reviewed repository declares. That includes its sk-git rule files or its contributing guide.
- **One verdict vocabulary.** Every agent report states its verdict as `APPROVED`, `REQUESTED_CHANGES` or `COMMENTED`. These are the same values as the final status line.
- **The checkers read the Recommendation line.** A `Recommendation` must match the status line. That holds when its whole value is a status. It also holds for an older `APPROVE`, `REQUEST CHANGES` or `BLOCK` token. Prose that only mentions approval is not a verdict.
- **Every verdict follows the findings.** The findings checker fails a `Recommendation` or a final status that approves or comments over a P0 or P1 finding. It also fails one that requests changes over P2 findings alone.
- **The Rule sources line is checked when present.** A malformed group, entry or rule id fails. The id grammar comes from the shared linter. A report without the line still passes.
- **The marker has a dispatcher.** The orchestrator adds the `CODE-REVIEW` marker when it dispatches a review. So the floor now says a dispatcher adds it.
- **The canary runs in other repositories.** `check-rule-copies.js --mode-only` checks only the skill's own pins. It prints a `SKIPPED:` line for the `AGENTS.md` checks, from any folder.

&nbsp;

## Upgrade

A gate used to fail a change on a low score with no P0 or open P1. It now passes that change. CI keeps running the canary in its full mode.
