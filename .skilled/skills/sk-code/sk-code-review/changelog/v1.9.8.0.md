# v1.9.8.0, The Fixtures Name the Checklist Path Inside the Skill Folder

The review reads its overrides from the checklists a repository's quality config names, and the fixtures still built their scratch repository around `.sk-code/`. They now write the config and its checklists under `repository/` in the `sk-code-quality` packet, so each scenario proves the path the gate reads today.

> Spec folder: `specs/sk-code/017-portable-code-modes/016-repository-config-in-skill` (Level 2)

&nbsp;

## What's New at a Glance

- **The three foreign-repository scenarios moved their fixture folder.** Each one creates the packet's `repository/` folder in its scratch repository, and the scenario that reports a `Rule sources` line expects the new path in its `Overrides:` group.
- **The two output fixtures carry the new path.** The valid and the malformed `Rule sources` fixtures name the checklist and the quality config under the packet, and the self-test expects the malformed entry's message to quote the same path.
