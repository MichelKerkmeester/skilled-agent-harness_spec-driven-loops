# v1.9.2.0, A Review Report That Cannot Contradict Itself

The Overall assessment at the top of a review report and the final `Review status:` line at its bottom could disagree while the checker still passed the file. The PR-state cache needed an `origin` remote before it could take a fingerprint, and nothing measured whether a live review finds real defects. This release closes those gaps and makes the mode's examples repository-neutral.

> Spec folder: `specs/sk-code/016-review-mode-followups` (Level 2)

&nbsp;

## What's New at a Glance

- **The summary must agree with the status line.** The final-line checker now fails a report whose Overall assessment names a different status than its final `Review status:` line, and a contradictory report fixture proves it.
- **The header says whether quality evidence came in.** Every report states `Quality gate evidence: present` or `absent`. A quality run verdict stays input evidence only, so no baseline check is skipped.
- **The review cache works without a remote.** A repository with no `origin` falls back to its root path for the cache key, and an optional pathspec gives each monorepo package its own signature and cache file.
- **User-authored modes have a review contract.** The mode now states what a security surface supplies, what a consuming workflow may rely on and which floors no mode may lower, and a playbook scenario replays a user security surface through both routing stages.
- **Finding accuracy is measured.** New live scenarios seed an injection and an off-by-one and add a clean control, and the first live run records executor, model, duration and tokens. It found both seeded defects and drew a false positive on the clean control.
- **Examples no longer assume this repository.** The mode names the runtime's review agent instead of an agent path, and the scripts README gives packet-relative commands.

&nbsp;

## Upgrade

A report whose Overall assessment and final status line disagree now fails the final-line checker, so fix the report rather than the check. A cache written before this release keeps its key whenever the repository has an `origin` remote and no pathspec is used.
