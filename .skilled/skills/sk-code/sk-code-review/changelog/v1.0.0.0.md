# v1.0.0.0, code-review mode established

This is the first release of the `code-review` workflow mode on the `sk-code` hub, establishing it as the hub's findings-first review mode. It folds in the standalone `sk-code-review` skill and repoints every `sk-code-review` name reference to `sk-code`. The v1.1.0.0 through v1.5.0.0 entries were inherited from and authored under the standalone `sk-code-review` skill, predate this establishment entry chronologically, and are retained unchanged.

## What's New at a Glance

- **Reviews use a findings-first baseline.** The mode pairs its stack-agnostic review baseline with `sk-code` surface-standards evidence for the detected surface. For unknown surfaces, it reviews against the baseline and discloses uncertainty.
- **Reviews rank findings and enforce minimums.** Findings carry severity rankings and `file:line` evidence, with mandatory security and correctness minimums.
- **A new `README.md` was added.** It gives the mode at-a-glance and layout.
- **The `references/` folder holds the review doctrine.** It consists of `review_core.md`, `review_ux_single_pass.md`, `pr_state_dedup.md` and `quick_reference.md`.
- **Reusable checklists cover six areas.** They address security, code quality, SOLID, test quality, fix completeness and removal plan.
- **Routing scenarios cover review conditions.** The `manual-testing-playbook` covers baseline review flow, scope and precedence, severity-and-evidence discipline, security and correctness minimums, structural-impact preflight, re-review with stale context, efficiency and restraint, cross-CLI orchestration and intra-routing recall.
- **Skill-benchmark baselines cover routing and live review.** The baselines are `router-mode-a` and `live-mode-b`.
- **Copied review rules have a divergence guard.** `scripts/check-rule-copies.js`, with its test, guards against divergence between copied review rules.
- **Review and correction use separate homes.** `code-review` does not edit the code under review. Author-side correction before review lives in `code-quality`. Applying accepted fixes lives in `code-webflow` and `code-opencode`.
