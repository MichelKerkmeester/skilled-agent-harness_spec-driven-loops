# v1.5.0.0, Review Checklists Move to Assets

This release moves the review checklists out of `references/` into `assets/`.

- That is where reusable checklist artifacts belong under the sk-doc skill convention.
- Each one is aligned to the asset template.
- The review doctrine is unchanged.

What changed is where the checklists live.

- Their overview sections also read differently.
- All routing, README, metadata, playbook and cross-skill references were updated in the same pass.
- So no load path breaks.

Six checklist artifacts move from `references/` to a new `assets/` folder.

- Four genuine references stayed in `references/`.
- `SKILL.md §2` now routes checklist requests to asset paths.
- The Resource Domains block names `assets/*_checklist.md` and `assets/removal-plan.md`.

> [!IMPORTANT]
> 1 change can break an existing setup. Read this before you update.
>
> 1. External references to moved checklists must change. [Before You Start](#c-before-you-start)

&nbsp;

## Why This Release

The six checklists are artifacts a reviewer applies. They are not doctrine a reviewer reads. So the sk-doc convention places them with reusable assets.

## Review Checklist Assets

#### Applied Checklists Have an Asset Home <a id="c-applied-checklists-have-an-asset-home"></a>

- The moved checklist artifacts are `code_quality_checklist.md`, `security_checklist.md`, `solid_checklist.md`, `test_quality_checklist.md`, `fix-completeness-checklist.md` and `removal_plan.md`.
- Four genuine references stayed in `references/`.
- They are `review_core.md` (doctrine), `review_ux_single_pass.md` (single-pass UX behavior), `quick_reference.md` (index) and `pr_state_dedup.md` (the M-1 dedup spec).

<details>
<summary><b>Reference updates</b></summary>

- Every by-path reference was updated in lockstep.
- That covers the §2 routing tables and `RESOURCE_MAP`.
- It covers the README table and `graph-metadata.json`.
- It covers bidirectional sibling cross-links.
- It covers nineteen manual-testing per-feature files.
- It covers the two cross-skill `sk-code/references/opencode/{python,shell}/quality-standards.md` pointers.
- The `.claude` and `.codex` runtime mirrors were re-synced.

</details>

#### Checklist Overviews Explain Their Use <a id="c-checklist-overviews-explain-their-use"></a>

- The moved checklists had a reference-flavored overview.
- It had `### Purpose` and `### Core Principle`.
- Each now also carries the asset template's `### Usage` subsection.
- That subsection says how a reviewer applies it.
- Core Principle stays.

<details>
<summary><b>Smaller fixes</b></summary>

- `fix-completeness-checklist.md` was the outlier.
- It had lowercase `## 1. Overview`, Title-Case sections and no subsections.
- It was restructured to match its siblings.
- The restructure uses `## 1. OVERVIEW`, Purpose and Usage, upper-cased section names, dividers and a Related Resources section.

</details>

#### Documented Routing Matches the New Home <a id="c-documented-routing-matches-the-new-home"></a>

- The `SKILL.md §2` Resource Domains block still described the checklists as living under `references/`.
- It now points to `assets/*_checklist.md` and `assets/removal-plan.md`.
- That matches the documented domain map to the resolved load paths.
