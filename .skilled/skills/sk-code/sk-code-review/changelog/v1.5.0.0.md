This release moves the review checklists out of `references/` and into `assets/`, where reusable checklist artifacts belong under the sk-doc skill convention, and aligns each one to the asset template. The review doctrine is unchanged. What changed is where the checklists live and how their overview sections read. All routing, README, metadata, playbook and cross-skill references were updated in the same pass, so no load path breaks.

> Spec folder: `.opencode/specs/skilled-agent-orchestration/142-sk-code-ponytail-based-refinement/008-sk-code-review-checklist-reclassification` (Level 1)

## Why This Release

The six checklists are artifacts a reviewer applies, not doctrine a reviewer reads, so the sk-doc convention places them with reusable assets.

## What's New at a Glance

- **Six review checklist artifacts move from `references/` to a new `assets/` folder.** The four genuine references stayed in `references/`.
- **The moved checklist overviews gain a `### Usage` subsection.** It says how a reviewer applies the checklist while retaining `### Core Principle`.
- **`SKILL.md §2` now routes checklist requests to asset paths.** The Resource Domains block names `assets/*_checklist.md` and `assets/removal-plan.md`.

---

## Review Checklist Assets

#### Applied Checklists Have an Asset Home

The moved checklist artifacts are `code_quality_checklist.md`, `security_checklist.md`, `solid_checklist.md`, `test_quality_checklist.md`, `fix-completeness-checklist.md` and `removal_plan.md`. Four genuine references stayed in `references/`: `review_core.md` (doctrine), `review_ux_single_pass.md` (single-pass UX behavior), `quick_reference.md` (index) and `pr_state_dedup.md` (the M-1 dedup spec).

Every by-path reference was updated in lockstep: the §2 routing tables and `RESOURCE_MAP`, the README table and `graph-metadata.json`, bidirectional sibling cross-links, nineteen manual-testing per-feature files and the two cross-skill `sk-code/references/opencode/{python,shell}/quality-standards.md` pointers. The `.claude` and `.codex` runtime mirrors were re-synced. The rule canary keys on `pr_state_dedup.md`, which stayed, so it remains green.

&nbsp;

#### Checklist Overviews Explain Their Use

The moved checklists had a reference-flavored overview with `### Purpose` and `### Core Principle`. Each now also carries the asset template's `### Usage` subsection, which says how a reviewer applies it while keeping Core Principle.

`fix-completeness-checklist.md` was the outlier: it had lowercase `## 1. Overview`, Title-Case sections and no subsections. It was restructured to match its siblings with `## 1. OVERVIEW`, Purpose and Usage, upper-cased section names, dividers and a Related Resources section.

&nbsp;

#### Documented Routing Matches the New Home

The `SKILL.md §2` Resource Domains block still described the checklists as living under `references/`. It now points to `assets/*_checklist.md` and `assets/removal-plan.md`, matching the documented domain map to the resolved load paths.
