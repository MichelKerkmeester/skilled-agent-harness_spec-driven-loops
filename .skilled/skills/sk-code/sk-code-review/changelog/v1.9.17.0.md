# v1.9.17.0, Each Rule Is Stated Once and the Depth Alias Needs Its Threshold

Twelve statements in the mode's documents disagreed with their source or repeated a rule another file owns. Each is fixed. No severity, floor or status line changed.

> Spec folder: `specs/sk-code/hub-architecture/006-sk-code-audit-remediation`

&nbsp;

## What's New at a Glance

- **`lite` skips nothing without a threshold.** The depth alias applies the M-2 skip only when `SK_CODE_REVIEW_MIN_CHANGED_LINES` is set. The README says the same. This is audit row `RV-02`.
- **The `Rule sources:` separators match the checker.** Checklist files take a comma. Entries in the other four groups take a semicolon. The line never starts with `Overall assessment`. These are rows `RV-01` and `RV-10`.
- **`Write` is scoped where it is granted.** `SKILL.md` says the tool exists for the cache file alone. It names the registry note that states the same scope. This is row `RV-03`.
- **The M-1 gate has one specification.** `references/pr-state-dedup.md` keeps the formula, the cache format and the retention cap. `SKILL.md` section 8.1 summarises it and links there. This is row `RV-04`.
- **Two rules live in one file each.** The instance-only opt-out stays in the fix-completeness checklist. The reach rule stays in the review core. `SKILL.md` and the README link to them. These are rows `RV-05` and `RV-06`.
- **The router states its intents once.** Section 2 of `ROUTER.md` points at the block in section 3. Two on-demand keywords no document explained are gone. These are rows `RV-07` and `RV-13`.
- **The checklists call the quick reference an index.** Five checklists described it as the review flow and severity contract. This is row `RV-08`.
- **The playbook package validator is named.** `SKILL.md` and the README list it beside the document validator. This is row `RV-09`.
- **The fix-completeness checklist has its divider.** A `---` line now stands before its first section, as in the other five assets. This is row `RV-12`.
