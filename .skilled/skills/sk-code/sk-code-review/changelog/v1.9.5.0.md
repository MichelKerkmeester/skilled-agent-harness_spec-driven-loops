# v1.9.5.0, A Repository Can Change the Review Lens

Review used to apply this repository's house preferences to every codebase it read. Nothing a repository said could switch one off. Now each review rule is either floor or part of a default lens. Floor holds everywhere. A repository or surface may drop or replace a lens rule. It uses the same `## Rule overrides` rows the quality mode reads. Review also stops guessing which rules apply to a file. It asks the quality runner instead.

> Spec folder: `specs/sk-code/017-portable-code-modes/005-review-floor-lens-overrides` (Level 2)

&nbsp;

## What's New at a Glance

- **Floor and lens, each with an id.** Security sections 2 to 6, error handling, boundaries, contract safety, test coverage and test reliability are floor. Function length, nesting, the Law of Demeter and the Rule of Three are lens rules. So are test layout and the other house rules. A repository may change those. The id table lives in `review-core.md` section 8.
- **One resolver for every file.** Review runs the quality runner's `--explain` on the reviewed files. It reads their surfaces, checklists and parsed overrides from it. The router adds some surfaces from request words. Such a surface applies only to the files the runner places in it.
- **Overrides are reported.** Every full review carries a `Rule sources:` line. It names the checklists it read. It names each override it applied, refused, ignored or found in conflict.
- **Severity hints follow the reach rule.** A breaking API change is no longer P0 by default. So is an assertion-free test. So is a test that swallows its own assertion.
- **The TODO rule defers to the repository.** It no longer asks for a ticket id. The repository's comment-hygiene rules forbid that id. A hygiene rule switched off in quality raises no review finding.
- **Web checks reach only web code.** XSS, SSRF, headers, CORS, cookies and rate limits apply only to code that serves or calls HTTP.
- **A review with no files stays neutral.** Outside this framework's own checkout, it no longer brings the SKILLED surface's standards along.

&nbsp;

## Upgrade

Some defaults change for every repository. A breaking API change is P1 at most. So is an assertion-free test. So is a test that swallows its own assertion. Each is P2 when no caller or changed behavior is in reach. The TODO rule no longer asks for a ticket id. XSS, SSRF, header, CORS, cookie and rate-limit checks skip code. That code neither serves nor calls HTTP. A review with no files outside this framework's checkout drops the SKILLED standards. A repository adds a `## Rule overrides` row only to change a lens rule further. That row goes in a checklist its `.sk-code/quality.json` already names.
