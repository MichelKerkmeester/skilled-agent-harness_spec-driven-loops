# v1.9.13.0, One Vocabulary for the Review Checkers

The review scripts kept three copies of the same status tokens and two copies of the same command-line reader, so a change to either vocabulary meant editing every copy or letting them drift. They now build their patterns from one frozen status map and one severity list, and both checkers read their input through the same reader. The playbook covers behaviour it never touched, from the gate that skips a repeat review to the lines every review has to carry.

> Spec folder: `specs/sk-doc/072-skill-routing-and-clarity/012-alignment-remediation` (Level 2)

&nbsp;

## What's New at a Glance

- **The checkers read one vocabulary.** The status tokens and the finding severities are declared once and every pattern is built from them, so a new severity cannot reach one checker and miss the other.
- **Both checkers read input the same way.** One reader handles the file argument, the stdin case and the two usage errors, and each script now opens on the `MODULE` header with its built-in imports kept apart from the local ones.
- **The routing scenarios can fail again.** Four of the seven expected a resource list every review loads anyway, so each now reports the intent and score the router picks and then runs a second prompt that must not pick it.
- **The playbook covers the gates that skip work.** The dedup gate, the opt-in minimum-evidence threshold and both populated override outcomes have a scenario with its own expected result.
- **A seeded defect can no longer be approved.** The seeded and clean-control scenarios run the findings checker as well as the final-line checker, so a review that reports a blocker and approves over it fails.
- **The review fixtures sit in the tests tree.** The sixteen complete review outputs moved from `scripts/review-output-fixture/` to `scripts/tests/fixtures/review-output/`, as the SKILLED test-layout rule asks; the canary test, the scripts README and the PR-shape scenario point at the new folder.
- **The canary works on a copy.** The tamper case seeds a scratch copy of the files the canary reads, so the failure is demonstrated without writing to a tracked file.
- **The playbook stops asserting what it cannot check.** The release checklist says what the operator validator proves and what still needs a structural read, and the index lines that pointed at nothing now point at the right file.
