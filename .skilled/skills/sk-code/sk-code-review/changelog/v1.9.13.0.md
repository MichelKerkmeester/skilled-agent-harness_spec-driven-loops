# v1.9.13.0, One Vocabulary for the Review Checkers

Review scripts kept three copies of the same status tokens. They kept two copies of the same command-line reader. So a change to either vocabulary meant editing every copy, or letting them drift.

They now build their patterns from one frozen status map and one severity list. Both checkers read their input through the same reader. The playbook covers behaviour it never touched. It runs from the gate that skips a repeat review to the lines every review has to carry.

&nbsp;

## What's New at a Glance

- The checkers read one vocabulary.
  - The status tokens and the finding severities are declared once.
  - Every pattern is built from them.
  - So a new severity cannot reach one checker and miss the other.
- Both checkers read input the same way.
  - One reader handles the file argument, the stdin case and the two usage errors.
  - Each script now opens on the `MODULE` header.
  - Its built-in imports are kept apart from the local ones.
- The routing scenarios can fail again.
  - Four of the seven expected a resource list every review loads anyway.
  - Each now reports the intent and score the router picks.
  - Each then runs a second prompt that must not pick it.
- The playbook covers the gates that skip work.
  - The dedup gate, the opt-in minimum-evidence threshold and both populated override outcomes have a scenario.
  - Each has its own expected result.
- A seeded defect can no longer be approved.
  - The seeded and clean-control scenarios run the findings checker.
  - Both scenarios also run the final-line checker.
  - So a review that reports a blocker and approves over it fails.
- The review fixtures sit in the tests tree.
  - The sixteen complete review outputs moved from `scripts/review-output-fixture/` to `scripts/tests/fixtures/review-output/`.
  - The SKILLED test-layout rule asks for that.
  - The canary test, the scripts README and the PR-shape scenario point at the new folder.
- The canary works on a copy.
  - The tamper case seeds a scratch copy of the files the canary reads.
  - So the failure is shown without writing to a tracked file.
- The playbook stops asserting what it cannot check.
  - The release checklist says what the operator validator proves.
  - The checklist also says what still needs a structural read.
  - The index lines that pointed at nothing now point at the right file.
