# v1.2.0.0, The Drift Gate Reads the Prose

Renames kept the routers and manifests in step while the prose that cites them drifted, and no guard read that prose. The drift gate now runs a fourth guard that does.

> Spec folder: `specs/sk-code/011-sk-code-poinytail-based-refinement/010-round-three-remediation/005-opencode-and-guards` (Level 1)

## What's New at a Glance

- **A documentation claim guard joins the gate.** `assets/scripts/verify_doc_claims.cjs` reports path references that do not resolve, retired packet names, surface counts that miss the third surface and `ROUTER.md` load-tier claims that `DEFAULT_RESOURCE` does not back. `scripts/run-all-drift-guards.sh` now runs four guards.
- **Deliberate legacy names are allowlisted with a reason.** A line that keeps an old identifier on purpose sits in one data block in the guard, and every other line is still reported.
- **The router guard reads the shared controls from the router.** Check 2 takes the hub-level shared controls from the `ROUTER.md` `SHARED_CONTROL_RESOURCES` list and `DEFAULT_RESOURCE` preamble and a workflow mode's own leaves from `leaf-manifest.json`, so the guard keeps no list of its own.
- **The packet uses the current packet names.** Hand-offs, comments and playbook groups now say `sk-code-review`, `sk-code-quality`, `sk-code-webflow` and `sk-code-opencode`.
- **The comment budget is labelled as this surface's setting.** The OpenCode style guides keep three comments per ten lines and point to the shared comment-density rule.
- **OpenCode workflow rules live in the OpenCode tier.** `references/shared/workflow-guardrails.md` now holds the implementation guardrails, the verification command chain and the runtime build traps that the shared workflow files carried for this surface only.

## Upgrade

No migration required. A doc that names a missing file, an old packet name or a stale surface count now fails `run-all-drift-guards.sh`. Keep a deliberate legacy name by adding a row with its reason to the allowlist in `verify_doc_claims.cjs`.
