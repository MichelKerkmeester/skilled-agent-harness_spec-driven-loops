# v1.0.0.4, Rust Language Support

Rust joins the OpenCode surface's language slice as a first-class language alongside TypeScript, Python, shell, JavaScript and config.

## What's New at a Glance

- **Rust-touching tasks now pull Rust standards.** The new `references/rust/` holds Rust standards for the OpenCode surface: the system-code alignment gate applied to Rust plus the napi-rs, wasm-bindgen, WASI and cdylib FFI-boundary rules.
- **A Rust checklist joins the surface.** `assets/checklists/rust_checklist.md` is the per-language Rust quality gate.
- **Rust detection uses file extensions and project markers.** The `.rs` extension establishes Rust within the OpenCode surface. `Cargo.toml` and `Cargo.lock` select it when no `.rs` file is touched. napi-rs and wasm-bindgen vocabulary are intent signals, not stand-alone surface detectors.
- **Language slicing moved from a single first-match language to the full touched-language set.** A task touching two languages now pulls both slices, and multi-language tasks pull every touched language's slice instead of only the first detected one. This supersedes the v1.0.0.0 "one language per task" standard with "touched-language set, not one-per-task."
- **Rust is the sixth OpenCode language.** Surface routing, the parent language union and the shared router-replay now register it.
- **`OC-009` is the new Rust routing scenario for the surface benchmark.** It is `manual-testing-playbook/language-standards/009-rust-standards.md`.
- **A duplicate Rust playbook feature file was removed.** It collided with the config-schema scenario on id `OC-004`. The Rust scenario is now `OC-009`, and the surface benchmark loads nine unique scenarios.
- **Builds 1.0.0.1 through 1.0.0.3 made no surface-behavior change.** These were repository sweeps and frontmatter maintenance. This is the first surface changelog entry since v1.0.0.0 was established. The version is reconciled to 1.0.0.4 across `SKILL.md`, `README.md` and this changelog.

# v1.0.0.0, OpenCode Surface Established

This is the first release of the `opencode` surface packet. The system-code evidence that previously lived under the workflow modes, in `code-implement/references/opencode/`, `code-quality/assets/opencode-checklists/` and `shared/references/opencode-shared/`, is now consolidated under one read-only surface packet on the `sk-code` hub's surface axis.

## What's New at a Glance

- **The packet is `packetKind: surface` and `backendKind: evidence-base`.** It is read-only, since its `toolSurface` uses no tools beyond `Read`, `Bash`, `Grep` or `Glob`, and advisor-invisible, with `routingClass: metadata`.
- **The hub bundles this evidence alongside a workflow mode and slices it by the detected language.** The packet never routes as a primary and mutates nothing.
- **`SKILL.md` is the surface contract.** It covers when the hub bundles this evidence, the language-sliced reference map, the non-negotiable system-code standards and the on-demand authoring checklists. The standards are that plugins never write to the TUI, descriptors are load-bearing, alignment drift is a verification gate and one language per task.
- **`references/` holds the TypeScript, Python, shell, config and JavaScript standards.** It also holds the language-agnostic `shared/` tier, which covers universal patterns, code organization, hooks and alignment verification.
- **The checklists cover component authoring and language quality.** `assets/checklists/` includes authoring checklists for skill, agent, command and mcp-server components plus per-language quality gates.
- **`README.md` gives the packet at a glance.** It also gives the layout.
- **Spec-folder authoring is outside this surface packet.** It lives in `system-spec-kit`.

## Upgrade

No migration required.
