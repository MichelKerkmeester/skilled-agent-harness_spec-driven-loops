# v1.1.0.0, The Checker Sees Sections and Folders

The alignment checker now finds the drift it used to miss. In its default mode it reported nothing on runtimes where many long files had no numbered sections and some code folders had no README. Two new flags, both off by default, make those gaps visible, so the default output stays exactly as it was.

> Spec folder: `specs/system-deep-loop/036-deep-loop-innovation/029-align-runtime-code-with-sk-code-opencode` (Level 2)

## What's New at a Glance

- **`--check-sections` finds long files without numbered sections.** A non-test file over 150 lines needs numbered dividers, and a file that mixes divider styles is flagged too. A header rule followed directly by a divider is accepted.
- **`--check-folders` finds undocumented and misnamed folders.** It reports a code folder that has no `README.md` and any folder whose name starts and ends with two underscores.
- **The shell guide's detailed header example now uses `COMPONENT:`.** It used to show `SPECKIT:`, which the exact-header check rejects, so the guide and the checker now agree.
- **The test layout guidance allows a flat `tests/` folder.** The example tree no longer shows a `test-helpers/` folder inside `lib/`.

## Upgrade

No migration required. Add `--check-sections --check-folders` to a run to use the new checks.
