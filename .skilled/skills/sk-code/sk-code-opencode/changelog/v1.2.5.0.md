# v1.2.5.0, A named failure for an unreadable registry

The documentation claim guard used to stop before it printed any check line when `mode-registry.json` did not parse. The surfaces check now contains that read and reports a named problem.

> Spec folder: `specs/sk-code/011-sk-code-poinytail-based-refinement/026-external-surface-priority-build/003-example-tolerant-drift-guards` (Level 2)

&nbsp;

## What's New at a Glance

- **An unreadable registry fails with a named problem.** The message names the parse error or the missing `modes` array, so the guard reaches its check summary instead of stopping mid-run.
- **The surface count follows the registry.** The packet `SKILL.md` and the scripts README now say the check matches every count against the surface modes in `mode-registry.json`, not a fixed three-surface hub.
