# v1.2.1.0, The Claim Guard Checks Anchors and Labels

The documentation claim guard passed a link whenever its file existed, even when the section it named was gone or its label named a file that does not exist. It now checks both, and it stops reporting load claims that apply to some routes only.

> Spec folder: `specs/sk-code/011-sk-code-poinytail-based-refinement/011-round-four-remediation/005-doc-claims-hardening` (Level 1)

&nbsp;

## What's New at a Glance

- **Anchors must name a real section.** A link or a quoted path that ends in `#section` now fails when the target file has no heading or explicit anchor by that name. Headings are matched the way GitHub names them.
- **Short link labels are checked.** A label such as `assets/checklists/x.md` must name a file in the doc's own packet or end the path it links to.
- **Conditional load bullets are left alone.** A `ROUTER.md` loading bullet that says when or only describes a load that depends on the route, so the tier check no longer reports it.
- **A wrong hub folder gets a usage line.** A missing `--root` folder now prints one usage line and exits 2 instead of a stack trace.
- **The workflow guardrails read without semicolons.** Each joined clause in the OpenCode guardrails is now its own sentence, with the meaning unchanged.

&nbsp;

## Upgrade

No migration required. A doc whose anchor or short label no longer matches its target now fails `run-all-drift-guards.sh`. Fix the link, or keep a deliberate line by adding a row with its reason to the allowlist in `verify_doc_claims.cjs`.
