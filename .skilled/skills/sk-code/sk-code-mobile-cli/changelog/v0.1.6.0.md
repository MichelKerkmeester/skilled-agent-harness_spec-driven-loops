# v1.6.0.0 — surface optimization: stale purge + source-grammar and verification references

The surface was measured against the `sk-code-opencode` bar and brought up to it: the migration-era
staleness was purged, the app's richest source knowledge was extracted into retrievable references, and
the routing map was rewired so a workflow actually loads that knowledge by intent.

## Added

- Nine references extracting the source grammar and the verification methods that were previously trapped
  inline in `SKILL.md` §3b or undocumented: `scoped-style-ownership`, `css-class-naming-bem`,
  `svelte-runes-effects`, `comment-grammar`, `folder-docs`, `a11y-parity`,
  `browser-free-verification-recipe`, `component-story-upkeep`, and `skill-reference-integrity`. Each is
  grounded in real app source and backed by an executable check.
- Four checklist assets: `bem-rename`, `runes-effect-audit`, `story-coverage`, and `a11y-parity`.
- `scripts/run-source-gates.sh` — a single self-locating entry point that runs the app's five source
  scans (naming, comments, folder-docs, skill-references, token-identity) as one PASS/FAIL gate, mirroring
  the model surface's `run-all-drift-guards.sh`.
- All thirteen new references and checklists are wired into the §2b `RESOURCE_MAP` by intent (and the
  hub `ROUTER.md` §11 union), so they route rather than sit unreferenced.

## Fixed

- Purged the migration-era staleness the surface still carried: the §3b "co-located CSS files"
  subsection contradicted §3's scoped-`<style>` truth (the co-located `.css` architecture was reverted —
  the app has 66 scoped `<style>` blocks and 0 component `.css`), `contrast.test.tsx` should be
  `contrast.test.ts`, and eleven reference/asset docs named removed paths (`apps/pi-remote-web`,
  `apps/pi-remote-relay`, `style.css`, `App.tsx`). Every reference and asset now passes
  `scan-skill-references.mjs` at `broken : 0`.
- Corrected a functional surface-detection bug in the hub: PI_REMOTE detection keyed off
  `apps/pi-remote-web` and "React 19 / Vite / Tailwind 4 / style.css", so it never matched the current
  `app-mobile/` SvelteKit tree. Detection markers and routing keywords now target Svelte / `app-mobile`.

## Why

v1.5 added the correct BEM section but left the contradicting stale one in place, and the surface still
described a React app that no longer exists — so a bundled workflow could load evidence that misroutes
or misleads. This lands the surface as an accurate, retrievable, intent-routed evidence base.
