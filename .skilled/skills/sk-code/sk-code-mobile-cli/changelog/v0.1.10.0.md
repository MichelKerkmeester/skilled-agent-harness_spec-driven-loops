# v1.10.0.0 — merge the over-split references, add the two missing operational docs

The folder grouping in v1.9.0.0 made the set navigable but left it over-split: thirty-three documents
averaging nine hundred words, where the reference template targets 500–3000 *lines* per file. Five
short documents became two substantial ones, and two gaps that had never been written are now filled.

## Added

- `references/storybook/running-storybook.md` — how to start the catalog for someone. Storybook is a
  long-running server, so a foreground start looks like a hang; this says to background it, hand back
  **http://localhost:6006**, and what to tell the user about the theme switch and the token
  playground. Includes the static-build rule (one output directory, one writer) and the failures that
  actually happen.
- `references/setup/device-preview.md` — putting the whole app on a phone-shaped screen. Chrome device
  emulation at the archive's `402 x 874`, the iOS Simulator (shares the Mac's network, so
  `localhost` works, and the only surface that renders through WebKit), an Android emulator (needs
  `10.0.2.2`, not `localhost`), and a real phone on the tailnet. States plainly what each cannot prove.

## Changed

- `verification/browser-free-verification-recipe.md` merged into `verification/verification.md`. Both
  described the same resolver method from opposite ends; one document now carries the principle, the
  value oracle, the CDP structural gates, the workspace gate and the recipe in order.
- `svelte/a11y-parity.md` and `svelte/svelte-runes-effects.md` merged into `svelte/svelte.md`. They
  are one subject — runtime correctness no gate can see — and the router that sat above two documents
  was pure overhead.
- `design-system.md` and `conventions.md` now open with `## 1. OVERVIEW` carrying Core Principle,
  When to Use and Key Sources, with the routing table as section 2. They previously opened straight
  into the routing table, which broke the reference template's structure contract.
- `quality/pi-remote-full-access-runtime-baseline.md` gained an OVERVIEW and numbered sections; it had
  neither.

## Fixed

- The repository-wide markdown link guard reports **0 broken links**, down from 5. Four were in
  `sk-code-obsidian/SKILL.md`, pointing at documents that had been renamed without updating the
  referrer (`obsidian-api-boundary` → `obsidian-plugin-api`, `single-stylesheet-ownership` →
  `stylesheet-ownership`, `screenshot-fixture-harness` → `screenshot-harness`) plus one,
  `source-naming.md`, that no longer exists in any form and whose promise was removed. The fifth was a
  runtime-written log path, now allowlisted with its reason.
- `validate-doc-model-refs.js` flagged a supported-model allowlist table on every commit in this
  repository. Its default-marker test used `context.includes('default')`, which also matches inside
  the identifier `PI_DEFAULT_MODEL` — so a table listing every supported id beside the real default
  read as each id being cited as the default. The test now blanks `*_DEFAULT_*` identifiers before
  looking for prose, and still reports a genuinely stale model cited as default.

## Why it matters

Fewer, larger documents route better. A reader choosing between two 1,500-word documents makes one
decision; choosing between five 700-word documents makes five, and the router that was supposed to
help was itself another read. The two new documents close the gap between "the catalog exists" and
"someone can actually look at the app", which is the question a user asks first.
