# v1.9.0.0 — group the loose references into subject folders, each with a router

`references/` held fourteen loose documents beside six purpose-named folders. Finding the right one
meant scanning fourteen filenames, and the SKILL.md table that listed them had grown to seventeen
rows including a duplicate. The loose set is now four folders, each following the same
`<folder>/<folder>.md` entry pattern the existing folders use.

## Added

- `references/design-system/` — how the app looks, in one place: the three-layer token model, the
  Layer-3 per-surface families, the theme remap, two worked retints, which file a CSS rule belongs
  in, and the `block--element` class grammar.
- `references/verification/` — proving a change: the browser-free resolver method (already named
  `verification.md`, so it became the folder's entry doc unchanged), why the CSP forbids screenshot
  value checks, and the cross-repo path drift guard.
- `references/conventions/` — how source reads: comment grammar, the `Do not edit — <why>` fences,
  and when a folder owes a `CODE.md`.
- `references/svelte/` — the two runtime defects a green suite cannot see: `$effect`
  self-invalidation, and the react-aria → bits-ui accessibility contract.
- An entry document for each new folder that routes by what the reader is doing, so one read reaches
  the right contract instead of scanning filenames.

## Changed

- SKILL.md's reference table is folder-first: eleven rows naming each folder, its entry document and
  what it carries, replacing seventeen file rows. The duplicate `comment-grammar.md` row is gone,
  and the separate folder bullet list it repeated is gone with it.
- `DEFAULT_RESOURCE` and the `IMPLEMENTATION` / `CODE_QUALITY` / `DEBUGGING` buckets now lead with
  the folder routers rather than a leaf document, so a routed agent lands on the map.
- Thirty-eight bullet-list cross-references that named a sibling in backticks are now real relative
  links. They were unresolvable before the move and would have silently rotted after it.
- README.md described the pre-migration monorepo — `apps/pi-remote-web/`, `apps/pi-remote-relay/`,
  `src/style.css`, a `catalog.html`. Those became `app-mobile/`, `app-relay/`, `app-mobile/src/app.css`
  and the Storybook catalog. The path scanner went from nine broken app paths to zero.

## Why it matters

The folders are not tidying. `references/` is what a routed agent reads to decide what to load, and a
flat list of fourteen makes that decision cost fourteen descriptions. Four routers make it cost four.
The README fix matters more: it had been describing a directory layout the app has not had since the
SvelteKit migration, which is worse than no map at all.
