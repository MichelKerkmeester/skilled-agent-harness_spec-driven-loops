This release hardens the advisor's persistence and routing. It answers deep-review P1 findings from the 028 playbook-findings remediation. The dispatch attempted a routing change. That change was reverted as incomplete before release.

&nbsp;

## What's New at a Glance

- The highest-weight routing match-terms are now sanitized.
  - Three fields were unsanitized highest-weight routing match-terms.
  - The three fields are `derived.trigger_phrases`, `derived.key_topics` and `derived.entities`.
  - So instruction-shaped values from skill graph metadata reached the scorer unfiltered.
  - That differed from `source_docs` and `key_files`.
  - Instruction-shaped, control-character and over-length values in those fields are now removed before projection.
  - The separate `skill_docs` upsert path still writes and reads `title`, `description` and `trigger_phrases` raw.
- Concurrent metrics writes no longer lose records.
  - Previously, concurrent advisor invocations in one workspace could overwrite each other's records.
  - That is because writes read and rewrote the full file without a lock.
  - Writes now append atomically.
  - Writes are serialized per path through an in-process queue.
  - Bounding is retained under the same queue.
  - Trimming is delayed until the file exceeds 1.5 times the cap.
  - So the common path stays a cheap append.
- Hook diagnostics cannot surface unhandled rejections.
  - Two unhandled-rejection paths arose.
  - Asynchronous diagnostic writes were not awaited inside synchronous try blocks.
  - This happened in Claude and Codex `user-prompt-submit` hooks and the Codex `prompt-wrapper` hook.
  - The writes now catch and swallow failures.
  - So diagnostics do not affect hook behavior.
- Rollback removes only the derived block.
  - Previously, it also erased `lifecycle_status` and `redirect_to`.
  - That silently un-deprecated skills and dropped supersession redirects.
  - The two fields are now preserved.

&nbsp;

## Upgrade

No migration required. Adopt via a fresh session. So the daemon respawns with the new dist. The sanitizer affects only skills whose derived metadata carries instruction-shaped or over-length values. So a clean corpus is byte-identical. To verify, index a skill with an instruction-shaped `trigger_phrases` value. Confirm it does not appear in the projection's `derivedTriggers`.
