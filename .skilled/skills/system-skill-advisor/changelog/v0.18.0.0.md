# v0.18.0.0, Doctor Problems in Your Own Words Reach the Helper

The advisor suggested a doctor command only when a prompt used that command's own phrases, so a problem described in your own words reached none of them. It now hands such a prompt to `/doctor:helper`, and it no longer refuses projects that link Skilled from this checkout.

> Spec folders: `specs/commands/005-doctor-symlink-install` phases `003-integration-and-docs` and `006-doctor-helper-handoff` (Level 2), `specs/commands/002-doctor-audit-and-fixes/005-advisor-linked-project-workspace` (Level 2)

&nbsp;

## What's New at a Glance

- **A doctor problem in plain words gets a doctor line.** When no doctor command matches and you did not type one, the advisor asks `/doctor:helper`'s own ranker whether the prompt describes a doctor problem and offers the helper when it does. On the helper's held-out doctor problems, the share that reach a doctor command rose from 4 to 15 of 48.
- **Ordinary requests stay as they were.** The hand-off needs a stated problem, such as something broken or wrong. The advisor's four labelled prompt sets gain no hand-off.
- **Reworded install and link prompts route.** "Set up skilled in my other repository" reaches `/doctor:install` instead of `/doctor:setup`, and "the skilled links in my project are broken" reaches `/doctor:symlink` instead of nothing.
- **Linked projects are no longer refused.** A project linked with `/doctor:symlink` holds `.skilled` pointing at this checkout, and the advisor daemon refused every such workspace with exit 64. It now accepts a workspace whose `.skilled` or `.opencode` resolves to this checkout's own folder. Copies, and links to another checkout, are still refused.

&nbsp;

## Upgrade

Rebuild with `npm --prefix .skilled/skills/system-skill-advisor/runtime run build`, restart the advisor daemon, then run `node .skilled/bin/skill-advisor.cjs advisor_rebuild --trusted --force true`.
