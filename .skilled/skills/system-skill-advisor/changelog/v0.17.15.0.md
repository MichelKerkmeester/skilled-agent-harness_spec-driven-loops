# v0.17.15.0, An Exact Declared Phrase Beats a Bare Word Declared Twice

A surface that listed a bare word such as `browser` or `css` both in its keywords and in its intent signals scored that one word twice. Two weak hits reached the cap of the advisor's author lane, so with such a surface installed, typing `browser agent` ranked it above mcp-tooling, which declares that exact phrase, and `css extraction` ranked it above sk-design. The fix was measured on fixture skills of that shape.

> Spec folder: `specs/sk-code/017-portable-code-modes/014-advisor-phrase-calibration` (Level 2)

&nbsp;

## What's New at a Glance

- **A repeated bare word counts once.** The author lane now scores a single word a skill declares once, however many of its metadata fields list it. A multi-word phrase declared in two fields still counts for each, and two different declared words still add up as before. On the fixture skills, the hub that declares the exact two-word phrase now outranks the skill that repeats one of its words.
- **The fallback scorer agrees on the fixture.** When the advisor answers from its Python scorer, a bare-word keyword that repeats the same skill's matched intent signal no longer adds a second boost when another skill matched an exact phrase holding that word. A skill's own word with no such rival, such as `mobbin`, keeps both boosts. A test runs both scorers on the same fixture skills and checks they pick the same hub.
- **Measured routing held.** Corpus, holdout and ambiguity accuracy, the doctor and router phrase-reach checks, and every pre-existing divergence-ledger row read the same as before. Four prompts joined the harder corpus to guard the change, and one of them, where the Python scorer already abstained, is recorded as a new approved divergence.

## Upgrade

No action is needed. Rebuild the advisor runtime so the daemon serves the new scorer.
