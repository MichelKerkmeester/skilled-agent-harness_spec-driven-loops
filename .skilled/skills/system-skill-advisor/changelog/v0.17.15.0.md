# v0.17.15.0, An Exact Declared Phrase Beats a Bare Word Declared Twice

A surface could list a bare word in two places. It could list it in its keywords and in its intent signals. Words like `browser` or `css` scored twice that way. Two weak hits reached the cap of the advisor's author lane. So with such a surface installed, typing `browser agent` ranked it above mcp-tooling. mcp-tooling declares that exact phrase. Typing `css extraction` ranked it above sk-design. The fix was measured on fixture skills of that shape.

&nbsp;

## What's New at a Glance

- **A repeated bare word counts once.** The author lane now scores one declared word once. That holds however many of its metadata fields list it. A multi-word phrase declared in two fields still counts for each. Two different declared words still add up as before. On the fixture skills, the hub declares the exact two-word phrase. It now outranks the skill that repeats one of its words.
- **The fallback scorer agrees on the fixture.** The advisor can answer from its Python scorer. In that case a bare-word keyword no longer adds a second boost. That applies when it repeats the same skill's matched intent signal. That holds when another skill matched an exact phrase holding that word. A skill's own word with no such rival, such as `mobbin`, keeps both boosts. A test runs both scorers on the same fixture skills. It checks they pick the same hub.
- **Measured routing held.** Corpus, holdout and ambiguity accuracy read the same as before. So do the doctor and router phrase-reach checks. So does every pre-existing divergence-ledger row. Four prompts joined the harder corpus to guard the change. One of them is recorded as a new approved divergence. The Python scorer already abstained on that one.

&nbsp;

## Upgrade

No action is needed. Rebuild the advisor runtime so the daemon serves the new scorer.
