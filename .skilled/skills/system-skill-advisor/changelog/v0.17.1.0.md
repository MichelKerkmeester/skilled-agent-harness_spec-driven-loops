# v0.17.1.0, One Doctor Bridge per sk-code Target

`/doctor:sk-code` gained a second target, `quality`, beside `setup`. The advisor had one bridge for the whole command. So it now carries one bridge per target. That is the same shape as the `/doctor:git` targets.

&nbsp;

## What's New at a Glance

- **Two bridges replace one.** `command-doctor-sk-code` became `command-doctor-sk-code-setup`. It keeps the old ranking order. `command-doctor-sk-code-quality` takes the next free order in the TypeScript and Python lists. So no other bridge moves.
- **The quality bridge has its own phrases.** Prompts such as "create the quality config file" suggest `/doctor:sk-code quality`. So does "which checks does the quality gate run".
- **Generated code was regenerated, not edited.** `derive-command-bridges.cjs` rewrote the generated blocks in `projection.ts`, `render.ts` and `skill_advisor.py`. It also rewrote the generated bridge file from `scoring-compatibility.json`.
- **The tests type the target.** The doctor ordering test names `/doctor:sk-code setup` and the setup bridge. So does the Python advisor test. So do the doctor routing-accuracy prompts. A bare `/doctor:sk-code` matches no target bridge by slash command. A bare `/doctor:git` does not either.

&nbsp;

## Upgrade

Rebuild the advisor runtime (`npm --prefix .skilled/skills/system-skill-advisor/runtime run build`). A caller that read the bridge id `command-doctor-sk-code` reads `command-doctor-sk-code-setup` instead.
