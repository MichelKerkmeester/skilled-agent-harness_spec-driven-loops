# v0.17.1.0, One Doctor Bridge per sk-code Target

`/doctor:sk-code` gained a second target, `quality`, beside `setup`. The advisor had one bridge for the whole command, so it now carries one bridge per target, the same shape as the `/doctor:git` targets.

> Spec folder: `specs/sk-code/015-quality-agnostic-gate/003-config-and-doctor` (Level 2)

&nbsp;

## What's New at a Glance

- **Two bridges replace one.** `command-doctor-sk-code` became `command-doctor-sk-code-setup`, which keeps the old ranking order, and `command-doctor-sk-code-quality`, which takes the next free order in the TypeScript and Python lists, so no other bridge moves.
- **The quality bridge has its own phrases.** Prompts such as "create the quality config file" or "which checks does the quality gate run" suggest `/doctor:sk-code quality`.
- **Generated code was regenerated, not edited.** `derive-command-bridges.cjs` rewrote the generated blocks in `projection.ts`, `render.ts` and `skill_advisor.py` and the generated bridge file from `scoring-compatibility.json`.
- **The tests type the target.** The doctor ordering test, the Python advisor test and the doctor routing-accuracy prompts name `/doctor:sk-code setup` and the setup bridge. A bare `/doctor:sk-code` matches no target bridge by slash command, as a bare `/doctor:git` does.

&nbsp;

## Upgrade

Rebuild the advisor runtime (`npm --prefix .skilled/skills/system-skill-advisor/runtime run build`). A caller that read the bridge id `command-doctor-sk-code` reads `command-doctor-sk-code-setup` instead.
