# v0.13.0.0, An Offline Tie-Break Eval

The advisor can now be measured against a model on its hardest calls, the near-ties, without any change to how it routes. A new offline script scores the labeled corpus, counts the rows a better tie-break could fix and, only when asked, lets Jev or the local Deem reorder each near-tie cluster under a keep rule fixed before any run.

> Spec folder: `specs/cli-jev/003-cli-jev-workflow-integration/002-advisor-jev-tiebreak-arm` (Level 1)

## What's New at a Glance

- **A zero-call census comes first.** `runtime/scripts/routing-accuracy/score-jev-tiebreak.mjs` reproduces the pinned holdout top-1 of 53/70, counts the movable rows per file and split, scores the scorer's order against three zero-call comparators and prints the win rate a `keep` would need. It spawns no model binary.
- **Each model arm has its own switch and its own gate.** `--jev` runs only when `jev 0.6.2` is on PATH and holds a key for its provider. `--deem` runs only when `cli-deem health` reports the pinned local model. A failed gate prints one skip line and leaves the census unchanged, and the script never reads a key. An arm whose gate passes needs `--out <dir>`, and without it the script exits 2 before any call.
- **Every verdict follows a rule fixed in advance.** Each arm prints one column and one `keep`, `kill`, `inconclusive` or `underpowered` line from an exact sign test, a comparator check, right@3 and a flip-rate cap. A Deem verdict names the commit pair it was measured on, and every `--deem` run adds a calibration line.
- **Runs leave a record.** `--out <dir>` writes one `calls.jsonl` line per call with its wall time, and a `report.json` that holds each column's four keep conditions.

## Upgrade

No migration required. Nothing calls the script, and the advisor routes exactly as before.
