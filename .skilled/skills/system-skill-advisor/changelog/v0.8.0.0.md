# v0.8.0.0, Doc Frontmatter Feeds Routing

This release gives detailed frontmatter on skill reference and asset docs a real runtime consumer.

- A new `skill_docs` table sits behind `SPECKIT_ADVISOR_DOC_TRIGGERS`.
- It feeds routing signal and matched-file pointers.
- Doc-specific prompts rank the owning skill.
- They point to the exact file to open.

Document phrases and matched files stay within clear bounds.

- Document phrases add a dampened `derived_generated` signal.
- Their volume can assist ranking.
- It cannot hard-route on its own.

Reference edits refresh skills, and the flag reaches the daemon.

- The daemon watcher tracks harvestable docs for freshness.
- The Python advisor follows the same flag.
- The daemon launcher forwards the feature flag.
- `SPECKIT_ADVISOR_DOC_TRIGGERS` now reaches the daemon child.

&nbsp;

## Why This Release

With the flag off, behavior is byte-identical to v0.7.0.0.

- The flag defaults off.
- With the flag off, behavior is byte-identical to v0.7.0.0.

## Advisor Matching

`skill_graph_scan` reads frontmatter from harvestable docs into `skill_docs`. Document matches assist ranking, and matched files stay bounded.

#### Frontmatter Joins the Scan <a id="c-frontmatter-joins-the-scan"></a>

- `skill_graph_scan` harvests `title`, `description`, `trigger_phrases`, `importance_tier` and `contextType`.
- It reads them from each skill's `references/` and `assets/` markdown into `skill_docs`.
- It allows one row per skill and document path.

<details>
<summary><b>Storage and coverage</b></summary>

- The table adds schema and migration support.
- It deletes its rows when a skill is deleted.
- The skill-frontmatter authoring campaign grows document coverage.
- At release, `trigger_phrases` sits on 84 of about 355 docs.

</details>

#### Bounded Document Harvest <a id="c-bounded-document-harvest"></a>

- Every scan harvests each skill.
- Document edits do not touch `graph-metadata.json`.
- So node-level hash skips cannot block this work.
- Per-document content hashes keep it cheap.
- The walker excludes READMEs.
- It reads `references/` and `assets/` recursively to depth 6.
- It reads up to 200 docs per skill.

<details>
<summary><b>Parser and cleanup</b></summary>

- The parser accepts block and inline `[a, b]` list forms.
- It limits phrases to 12 per doc.
- It clamps each field at 300 characters.
- Stale rows are swept per skill.
- Unreadable docs warn with `DOC-READ-FAILED` and continue.

</details>

#### Document Matches Assist Ranking <a id="c-document-matches-assist-ranking"></a>

- For each skill, the scorer takes the three strongest document matches.
- It multiplies each by its importance-tier weight.
- It sums the results up to 0.45.
- Weights run from 1.0 for constitutional/critical to 0.2 for deprecated.
- That keeps document volume below the contribution from one curated skill-level phrase.

<details>
<summary><b>Signal limits</b></summary>

- At normal tier, a document-only match reaches about 0.68 confidence.
- The existing `derived_generated` lane adds this signal.
- It adds no sixth lane and no weight redistribution.

</details>

#### Matched Documents Stay Bounded <a id="c-matched-documents-stay-bounded"></a>

- `matchedDocs` is an optional field on the strict schema.
- It holds up to three skill-relative paths.
- The release adds a new `doc_reference_signal` evidence type.

<details>
<summary><b>Path safety</b></summary>

- Paths are extracted from `doc:` evidence behind a sanitization allowlist.
- That allowlist allows only Markdown beneath `references/` or `assets/`.
- It rejects traversal.

</details>

## Document Freshness

Reference edits refresh their skill. The Python advisor harvests the same doc phrases from disk under the same flag.

#### Reference Edits Refresh Skills <a id="c-reference-edits-refresh-skills"></a>

- When the flag is on, each harvestable document becomes a `doc-frontmatter` watch target.
- Editing a reference reindexes its skill without a manual scan.

#### Python Scoring Uses the Active Loader <a id="c-python-scoring-uses-the-active-loader"></a>

- The Python `skill_advisor.py` harvests the same doc phrases from disk under the same flag.
- The SQLite loader merges the source-metadata signal.
- The SQLite loader always wins in this repo.
- It now merges it too.

<details>
<summary><b>Earlier behavior</b></summary>

- Source-metadata signal merging had applied only to the legacy JSON graph path.

</details>

&nbsp;

## Flag Delivery

The flag reaches the daemon through the launcher allowlist.

#### The Daemon Receives the Flag <a id="c-the-daemon-receives-the-flag"></a>

- The daemon child did not receive `SPECKIT_ADVISOR_DOC_TRIGGERS`.
- That is because `system-skill-advisor-launcher.cjs` forwards only `CHILD_ENV_ALLOWLIST` keys.
- The flag is now on that list.
- Future advisor environment flags need the same entry to reach the daemon.

&nbsp;

## Upgrade Notes

Set the flag in each runtime config, then start a fresh session.

#### Before You Start <a id="c-before-you-start"></a>

1. Set `SPECKIT_ADVISOR_DOC_TRIGGERS=true` in the advisor env block of each runtime config.
2. This repo sets it in `opencode.json`, `.claude/mcp.json` and `.codex/config.toml`.
3. Every advisor-attached session must end before a fresh session respawns the daemon with the flag.
4. Run a trusted `skill_graph_scan` and expect `docs` counters.
5. Then use `advisor_recommend` with a doc-specific phrase and expect `matchedDocs`.

<details>
<summary><b>Advisor Matching</b></summary>

- No migration is required.
- `skill_docs` is created additively on open.
- Unset the flag to leave the rows persisted but ignored.
- Or drop the `skill_docs` table.

</details>

<details>
<summary><b>Flag Delivery</b></summary>

- The advisor launcher exits if its daemon child is SIGTERMed.
- Launchers spawned before the flag change keep their old environment.

</details>
