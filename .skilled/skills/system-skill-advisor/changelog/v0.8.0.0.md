This release gives the detailed frontmatter on skill reference and asset docs a real runtime consumer. A new `skill_docs` table sits behind the `SPECKIT_ADVISOR_DOC_TRIGGERS` flag. It feeds routing signal and matched-file pointers.

## Why This Release

The flag defaults off. With the flag off, behavior is byte-identical to v0.7.0.0.

## What's New at a Glance

- **Doc-specific prompts rank the owning skill.** They point to the exact file to open.
- **Document phrases add a dampened `derived_generated` signal.** Their volume can assist ranking. It cannot hard-route on its own.
- **Reference edits refresh their skill.** The daemon watcher tracks harvestable docs for freshness.
- **The Python advisor follows the same flag.** `skill_advisor.py` harvests from disk. The SQLite loader merges the source-metadata signal.
- **The daemon launcher forwards the feature flag.** `SPECKIT_ADVISOR_DOC_TRIGGERS` now reaches the daemon child.

## Advisor Matching

#### Frontmatter Joins the Scan

`skill_graph_scan` harvests `title`, `description`, `trigger_phrases`, `importance_tier` and `contextType`. It reads them from each skill's `references/` and `assets/` markdown into `skill_docs`.

The table adds schema and migration support. It allows one row per skill and document path. It deletes its rows when a skill is deleted. The skill-frontmatter authoring campaign grows document coverage. At release, `trigger_phrases` sits on 84 of about 355 docs.

&nbsp;

#### Bounded Document Harvest

Every scan harvests each skill. Document edits do not touch `graph-metadata.json`. So node-level hash skips cannot block this work. Per-document content hashes keep it cheap. Stale rows are swept per skill. Unreadable docs warn with `DOC-READ-FAILED` and continue.

The walker excludes READMEs. It reads `references/` and `assets/` recursively to depth 6. It reads up to 200 docs per skill. The parser accepts block and inline `[a, b]` list forms. It limits phrases to 12 per doc. It clamps each field at 300 characters.

&nbsp;

#### Document Matches Assist Ranking

For each skill, the scorer takes the three strongest document matches. It multiplies each by its importance-tier weight. It sums the results up to 0.45. Weights run from 1.0 for constitutional/critical to 0.2 for deprecated. That keeps document volume below the contribution from one curated skill-level phrase. At normal tier, a document-only match reaches about 0.68 confidence. The existing `derived_generated` lane adds this signal. It adds no sixth lane and no weight redistribution.

&nbsp;

#### Matched Documents Stay Bounded

`matchedDocs` is an optional field on the strict schema. It holds up to three skill-relative paths. Paths are extracted from `doc:` evidence behind a sanitization allowlist. That allowlist allows only Markdown beneath `references/` or `assets/`. It rejects traversal. The release adds a new `doc_reference_signal` evidence type.

## Document Freshness

#### Reference Edits Refresh Skills

When the flag is on, each harvestable document becomes a `doc-frontmatter` watch target. Editing a reference reindexes its skill without a manual scan.

&nbsp;

#### Python Scoring Uses the Active Loader

The Python `skill_advisor.py` harvests the same doc phrases from disk under the same flag. Source-metadata signal merging had applied only to the legacy JSON graph path. The SQLite loader always wins in this repo. It now merges it too.

---

## Flag Delivery

#### The Daemon Receives the Flag

The daemon child did not receive `SPECKIT_ADVISOR_DOC_TRIGGERS`. That is because `system-skill-advisor-launcher.cjs` forwards only `CHILD_ENV_ALLOWLIST` keys. The flag is now on that list. Future advisor environment flags need the same entry to reach the daemon.

---

## Upgrade Notes

- **Schema.** No migration is required. `skill_docs` is created additively on open.
- **Enable.** Set `SPECKIT_ADVISOR_DOC_TRIGGERS=true` in the advisor env block of each runtime config. This repo sets it in `opencode.json`, `.claude/mcp.json` and `.codex/config.toml`.
- **Start fresh.** Every advisor-attached session must end before a fresh session respawns the daemon with the flag. The advisor launcher exits if its daemon child is SIGTERMed. Launchers spawned before the flag change keep their old environment.
- **Verify.** Run a trusted `skill_graph_scan` and expect `docs` counters. Then use `advisor_recommend` with a doc-specific phrase and expect `matchedDocs`.
- **Rollback.** Unset the flag to leave the rows persisted but ignored. Or drop the `skill_docs` table.
