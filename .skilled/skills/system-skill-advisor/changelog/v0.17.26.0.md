# v0.17.26.0, The Skill Format Command Reaches the Advisor

A command nobody is routed to is a command nobody runs. The advisor now carries a bridge for `/doctor:sk-skill`. A request to check a skill against the format lands on that command. So does a request to convert one. The compiled skill graph is rebuilt for the new identity.

&nbsp;

## What's New at a Glance

- The skill format command has a bridge.
  - Each target is scored from the route manifest's own trigger phrases.
  - So a request such as `how far a skill is from the Skilled format` reaches `/doctor:sk-skill check`, not a create command.
- The Python reference and the TypeScript scorer agree on more prompts.
  - The description change in `sk-prompt` stopped a duplicated-intent scoring prompt from landing there.
  - So the corpus parity baseline rose from 113 to 114.
  - The corpus parity baseline's hook-preserved count rose from 109 to 110.
- One prompt rejoined the accepted list.
  - The Python-vs-TypeScript baseline rose from 107 to 109 and from 100 to 101.
  - The case that prompted it sits on the accepted list again.
  - That is because the pinned native scorer still misses it.
  - A native side that has not moved is a reason to accept a divergence.
  - That is not a reason to hide one.
- The divergence ledger is one row shorter.
  - The entry that recorded that prompt as a standing divergence is gone.
  - That is because it no longer diverges.
- The compiled skill graph is regenerated.
  - The new `sk-prompt` intent signal reached the graph.
  - The freshness guard reported the old copy as drift.

&nbsp;

## Upgrade

No migration required. A repository that keeps its own skill graph rebuilds it from the updated metadata. That happens the next time it scans.
