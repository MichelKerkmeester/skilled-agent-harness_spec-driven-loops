# v0.17.7.0, A Confidence Floor Is No Longer a Tie

The advisor called a prompt ambiguous far more often than it was, because a confidence floor lifts any skill with modest evidence to within reach of a top that earned its place. It now flags only real ties, and a typed slash command reaches the skill that owns it instead of a skill that borrows from it.

> Spec folder: `specs/system-speckit/054-weak-model-spec-authoring` (Level 2)

&nbsp;

## What's New at a Glance

- **A floored skill ties on score alone.** When the top earned its confidence from its own evidence, a skill whose confidence only reached the floor joins the ambiguity cluster through the score margin, not the confidence margin. Two floored skills still tie.
- **Flags fell from 110 to 78 of 261 labelled prompts.** The correct top skill stayed at 202 and no top skill changed.
- **A typed command's owner stays on top.** A skill that borrows graph support from the owner of a typed command can rise up to that owner's score but never past it, so `/deep:research :auto` no longer ranks system-spec-kit first.
- **A held skill is not a tie.** A skill capped below a typed command's owner records that owner as `heldBelow` and stays out of its cluster.
- **Mode suffixes are not prompt words.** After a slash command, `:auto`, `:confirm`, `:autopilot` and `:unattended` are dropped before matching, in the scorer and its Python twin.
- **The brief trusts the scorer.** It uses the scorer's `ambiguous` answer, and "vs" names a skill inside the cluster.
- **Under-specified prompts still abstain.** The low-information abstention reads the wider cluster, so a skill the floor rule leaves out cannot become its top.

&nbsp;

## Upgrade

No action is needed. Typed commands now route to their owner, and a cli-classifier replay baseline built from `ambiguousWith` will shift on its next run.
