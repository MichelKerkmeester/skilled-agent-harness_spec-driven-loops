# v0.17.7.0, A Confidence Floor Is No Longer a Tie

The advisor called a prompt ambiguous far more often than it was. That is because a confidence floor lifts any skill with modest evidence. It lifts that skill to within reach of a top that earned its place. It now flags only real ties. A typed slash command reaches the skill that owns it. It no longer reaches a skill that borrows from it.

&nbsp;

## What's New at a Glance

- **A floored skill ties on score alone.** The top earned its confidence from its own evidence. In that case, a skill whose confidence only reached the floor joins the ambiguity cluster. It joins through the score margin, not the confidence margin. Two floored skills still tie.
- **Flags fell from 110 to 78 of 261 labelled prompts.** The correct top skill stayed at 202. No top skill changed.
- **A typed command's owner stays on top.** A skill that borrows graph support from the owner of a typed command can rise up to that owner's score. It never rises past it. So `/deep:research :auto` no longer ranks system-spec-kit first.
- **A held skill is not a tie.** A skill is capped below a typed command's owner. It records that owner as `heldBelow`. It stays out of its cluster.
- **Mode suffixes are not prompt words.** After a slash command, `:auto`, `:confirm`, `:autopilot` and `:unattended` are dropped before matching. The drop happens in the scorer and its Python twin.
- **The brief trusts the scorer.** It uses the scorer's `ambiguous` answer. The word "vs" names a skill inside the cluster.
- **Under-specified prompts still abstain.** The low-information abstention reads the wider cluster. So a skill the floor rule leaves out cannot become its top.

&nbsp;

## Upgrade

No action is needed. Typed commands now route to their owner. A cli-classifier replay baseline built from `ambiguousWith` will shift on its next run.
