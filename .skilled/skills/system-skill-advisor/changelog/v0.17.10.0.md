# v0.17.10.0, The Plugin Suite Runs on Node 20 and the Watcher Case Holds on macOS

The advisor's engines range is `^20.19.0 || >=22.12.0`, and the plugin itself runs on Node 20, but its test suite stubbed imports with `module.registerHooks`, which exists only from Node 22.15 and 23.5. On Node 20 the suite stopped at load with `TypeError: registerHooks is not a function` before any case ran. CI runs the suite on Node 22, so it never saw the failure.

> Spec folder: `specs/sk-code/017-portable-code-modes/011-node20-test-fixes` (Level 2)

&nbsp;

## What's New at a Glance

- **One stub rule, two loaders.** The suite keeps `module.registerHooks` where it exists and otherwise registers the same resolve rule through `module.register`, passing the stubs to the off-thread hooks as data. The read-counting stub still reaches the test, because stub modules evaluate on the main thread.
- **The suite runs on every supported Node.** It passes on Node 20, 22 and 26. Nothing changed in the plugin.
- **The newborn-skill watcher case no longer flakes on macOS.** FSEvents can lag several seconds while `fseventsd` is busy, longer than the case waits, so the case that drives real chokidar now uses stat polling on macOS. Linux keeps the native watcher the daemon runs in production.
