# v0.16.2.0, Short Prompts Route Again

A review found that the doctor routing from v0.16.0.0 made short prompts like "git hooks" and "git setup" route to nothing, because a doctor command that matched no phrase still took part in the tie check. Doctor commands no longer change how a skill scores.

> Spec folder: `specs/system-skill-advisor/035-doctor-command-routing` (Level 2)

&nbsp;

## What's New at a Glance

- **Short skill prompts route again.** "git hooks", "git setup", "git standards", "git rules" and "speckit doctor" reach their skill with the same confidence as before doctor routing existed.
- **Twelve more short prompts have a home.** "pre-push hook", "push allowlist", "hook trust", "hook gates", "cherry pick", "squash commits", "env vars", "mcp tools", "runtime mirrors", "resume spec" and "validate spec" now route to their skill. "environment variables" stays unrouted so "check my environment variables" keeps `/doctor:env` first.
- **The doctor line survives a busy result.** When three skills match, the `Also: /doctor:...` line still shows instead of falling off the top three.
- **"run /doctor:x" counts as typing it.** Run, execute, start, launch, use and kick off before a `/doctor:` command put that command first. A quoted mention still does not, and the Python fallback follows the same rule.
- **The setup hint is fast and better aimed.** It costs 2 ms on a 600,000-character paste instead of 15 seconds, catches "check my config" and "reinstall skilled" and no longer fires on unrelated uses of "tool" or "hooks".

&nbsp;

## Upgrade

No migration required. Rebuild the advisor runtime (`npm --prefix .skilled/skills/system-skill-advisor/runtime run build`).
