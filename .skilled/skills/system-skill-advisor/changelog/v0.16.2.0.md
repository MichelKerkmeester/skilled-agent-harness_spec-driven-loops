# v0.16.2.0, Short Prompts Route Again

Short prompts like "git hooks" and "git setup" routed to nothing. The doctor routing from v0.16.0.0 caused it. That is because a doctor command that matched no phrase still counted in the tie check. Doctor commands no longer change how a skill scores.

&nbsp;

## What's New at a Glance

- **Short skill prompts route again.** "git hooks", "git setup", "git standards", "git rules" and "speckit doctor" reach their skill. They do so with the same confidence as before doctor routing existed.
- **Twelve more short prompts have a home.** "pre-push hook", "push allowlist", "hook trust", "hook gates" and "cherry pick" now route to their skill. "squash commits", "env vars", "mcp tools", "runtime mirrors", "resume spec" and "validate spec" now route there too. "environment variables" stays unrouted. So "check my environment variables" keeps `/doctor:env` first.
- **The doctor line survives a busy result.** When three skills match, the `Also: /doctor:...` line still shows. It does not fall off the top three.
- **"run /doctor:x" counts as typing it.** Run, execute, start, launch, use and kick off can come before a `/doctor:` command. Each one puts that command first. A quoted mention still does not. The Python fallback follows the same rule.
- **The setup hint is fast and better aimed.** It costs 2 ms on a 600,000-character paste instead of 15 seconds. It catches "check my config" and "reinstall skilled". It no longer fires on unrelated uses of "tool" or "hooks".

&nbsp;

## Upgrade

No migration required. Rebuild the advisor runtime (`npm --prefix .skilled/skills/system-skill-advisor/runtime run build`).
