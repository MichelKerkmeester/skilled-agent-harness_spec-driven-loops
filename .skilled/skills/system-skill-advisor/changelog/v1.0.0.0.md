# v1.0.0.0, A Hub Skill Names the Command to Type

The advisor used to answer "create a readme" with `sk-doc`. The reader then had to find `/create:readme` alone. Now a hub recommendation carries the slash command for the mode it picked.

Each `/speckit` command and `/prompt:improve` now has its own scored row. Such a row passes on its own words, or on meaning when the local embedder runs. Four old command ids are gone, so this is a major release.

Every tracked command also records a policy. It says whether a model may run it, start it or must ask first.

A typed command now reaches the model with that policy. More plain requests reach their command. Each test run also records whether the brief arrived.

> Spec folder: `specs/system-skill-advisor/routing-and-scoring/008-command-surfacing-build`

&nbsp;

## Why This Release

A skill id is not something a reader can type. `sk-doc` alone owns thirteen commands. Naming the skill left the last step to the reader.

The `/speckit` commands had rows, but the scorer never used them. A generic `command-spec-kit` row and two save ids answered instead. So the advisor could not say which `/speckit` command a prompt wanted.

A command helps only when it reaches the model. Some typed commands never did. No test run said whether the brief arrived at all.

## Hub Commands

#### The Recommendation Carries the Command

A hub's compiled route can pick exactly one mode. When it does, the advisor looks that mode up in a table of 19 commands. The table is built from each hub's own command files. The command then rides on the recommendation as a new optional field:

```json
"command": "/create:readme"
```

A route that picks no mode gets no command. So does a route that picks several. A hub also skips a command whose own row already ranks in the same result. So one command never takes two slots. A caller that ignores the field sees no change.

#### Deep-Loop Commands Wait for Depth

`/deep:research`, `/deep:review` and `/deep:ai-council` start a long run of many passes. So the advisor offers one only when the prompt asks for that effort. The effort words are a short list, such as "in depth", "thorough" and "deep dive". Typing a `/deep:` command also counts.

The prompt "research loop on incremental indexing approaches" gets the research route and no command. Add "in depth" and it gets `/deep:research`.

## Command Rows

#### Each Speckit Command Is Scored on Its Own

The seven `/speckit` commands and `/prompt:improve` each had a row, but the scorer left them off. Now all eight are scored. Their phrases come from the owning skill's command metadata. A typed `/speckit:save` now returns `command-speckit-save` beside `system-spec-kit`.

#### Command Rows Need Their Own Words

A command row now needs its own words. The prompt must hold one of its phrases or its slash string. A meaning match is the one exception. Before, single everyday words could carry a row over the line. That rule used to cover doctor commands only. Without it, a bug-fix prompt was offered `/prompt:improve` during this work.

#### A Command Row and Its Owner Are One Answer

The advisor marks a result ambiguous when its top answers score close together. A command row and the skill that owns it used to count as two answers. Now they count as one. On `/speckit:save` the two rows land about 0.04 apart. The result is not ambiguous. Two different skills close together still count as a tie.

#### Four Command Ids Are Retired

**Breaking:** `command-spec-kit`, `memory:save`, `command-memory-save` and `command-prompt-improver` no longer exist. `memory:save` and `command-memory-save` become `command-speckit-save`. `command-spec-kit` gives way to one id per command, such as `command-spec-kit-plan`. `command-prompt-improver` becomes `command-prompt-improve`.

## Meaning Matching

#### A Paraphrase Can Reach Its Command

A paraphrase shares no words with a command's phrases, so it used to reach nothing. Now each of the 45 scored command rows has its own vector. The text behind it is the row's job sentence and its own phrases. Both are written as a person would ask. A doctor row uses its router's description and trigger phrases instead. A skill-graph scan stores these vectors in their own table, beside the skill vectors.

#### How a Meaning Match Passes

The prompt's embedding is compared with each command vector. A row passes when the match reaches a cosine of 0.72. It must also lead the next command row by 0.02. Even then it ranks first only when it leads the top skill by 0.02. The bars sit above the closest match any silent prompt reached. A wrong command costs more than none.

#### Questions and No-Edit Prompts Stay Safe

A meaning match lifts a command past the floor that holds back answers to plain questions. So a command that changes files could have been offered for a question. Two rules close that gap. A prompt that asks for no change rules out every command on meaning. Examples are "no edits", "do not change", "just show" and "just list". A question that only wants an answer lets a command pass on meaning only if it just reads. Phrase matches were already held to this by the floor.

#### No Embedder, No Change

The local embedder is Ollama serving `nomic-embed-text`. Without it no real match score exists. The advisor then gives the phrase-only result. The word-overlap stand-in used in tests never counts as meaning.

## Command Policies

#### Every Command Says Whether to Ask First

Each of the 44 tracked commands records what it may change, where it writes and what it must ask first. A doctor command records this once per route. The bridge generator turns each record into one policy: run, start or ask. An ask-first reason always means ask. So does a doctor route that changes files. A read-only command may run. So may one that only adds files inside the spec folder. Everything else starts as an ordinary task. Counted per command, 17 ask, 7 run and 20 start. `/create:changelog` asks first, because its `--release` flag pushes a tag and publishes a GitHub release. A command file with no record fails the generator. The policies sit in `commandPolicies` in the generated bridge file. Nothing reads them yet.

## Prompt Hook

#### The Hook Asks for the Compiled Route

The hook's fallback call to the advisor now sends `includeCompiledRoute: true`. The command is derived from that route, so without it no command arrives. The hook keeps the `command` field it receives. The brief it prints names the command and its policy.

#### Only the Top Pick Gets a Route

Each route lookup starts a separate process. That costs time inside the hook's budget. So `advisor_recommend` gains the option `compiledRouteTopOnly`, which is off by default. Set to `true`, it looks up the route for the first recommendation only. The hook sends it as `true`, because the brief leads with the top pick. So only the top pick can carry a command in the hook.

A daemon started from an older build rejects the new options. The CLI then retries once without them.

## Typed Commands

#### A Typed Command Arrives With Its Policy

A user who types a tracked slash command now sees it on the top recommendation. It carries its `run`, `start` or `ask` policy and the skill that owns it. Before, 7 of the 44 typed rows reached the model with no command. Eight more had a command but no policy. Now 24 typed rows carry the command on their own row. The other 20 carry it on the owning skill. A typed command with no row of its own puts its owner first. That moves `/create:goal` and `/create:skill-parent` to their owner. A typed command also wins over a command a hub route picked, because the user typed it.

#### Hook Health Shows in the Status

`advisor_status` now carries `hookHealth`. It reports invocations, the p95 time, the fail-open rate and the cache-hit rate. The `/doctor:setup` advisor leg shows it. The hook writes these records only when `SKILL_ADVISOR_DEBUG` is set. So hook health shows only after such a run.

## Plain Requests

#### The Doctor Hand-Off Names the Command

The doctor hand-off used to name `/doctor:helper`, even when the helper's ranker had found the exact command. It now names that command when its policy is `run`. A command that must ask first still goes through the helper, which explains the choice before anything changes:

```text
Advisor: live; use system-skilled-doctor → /doctor:agents-md check (run) 0.80/0.26 pass.
```

#### A Hub Says It Needs a Mode

A hub holds back its command when the prompt names no single mode. The brief used to show the bare hub. It now says why no command came:

```text
Advisor: live; use sk-doc (needs a mode) 0.91/0.12 pass.
```

#### More Wordings Reach a Command

The `sk-doc` hub gained six aliases, such as `agent definition` and `prompt shortcut`. Each deep mode gained one plain wording: `find out everything`, `findings stop changing` and `several models`. Three create rows gained one narrow phrase each. All of them came from the tuning prompts. So they barely help on wording the advisor has not seen.

#### Skill Names Beyond `sk-` Count

The prompt policy read only `sk-` names as a named skill. So `use the system-deep-loop skill` printed `Advisor: prompt skipped.` It now reads `system-`, `cli-` and `mcp-` names too.

## Brief Delivery

#### An OpenCode Brief Names the Command

The OpenCode plugin dropped the command, its policy, its owner and the mode flag. Its brief named only the skill. The plugin now keeps all four. So an OpenCode brief names the attached command the way the hook brief does.

#### A Test Run Records Whether the Brief Arrived

The behaviour log now records whether the advisor brief reached the model. It reads this from each runtime's own session store. An offer then counts only when delivery is not false. Claude Code, Devin and Pi received the brief on 24 of 24 runs. DSH received it on 23. Codex received it on none, because its hooks were not approved. OpenCode keeps no trace of its brief, so its delivery stays unknown.

#### The Behaviour Runner Leaves No Trace

The runner now restores the checkout after every turn and reports any path left behind. It refuses a Codex arm whose hooks are not approved before any turn runs. A loop started without its init now counts as unsafe. A typed command that Claude Code expands itself now counts as a start.

The corpus now has 176 rows. One held-out prompt moved to the tuning set, and a new one took its place. That is why the tuning set counts 45. Without the embedder, rows match whole phrases. So they miss the held-out paraphrases. With the real embedder the held-out set reaches 2 of 44. That misses the target of 5. The held-out set was measured three times. The first round used a bar of 0.74 and no margin. It reached 4. The second round led each text with the job sentence and used the current bars. It reached 3. The third run followed the no-edit fix and reached 2. That fix took away one held-out hit. Its prompt is classed as a read-only question and had been answered by `/speckit:resume`, a command that is not read-only. The bars came from the tuning set only. Typed prompts stay at 24 of 44.

The new wordings were measured without the embedder. At every check, typed prompts stayed at 24 of 44. Prompts that should get no command stayed at 0 of 35.

Each figure comes from one run of the hook over 44 prompts on a shared machine. Meaning matching left the hook median near 200 ms. Three runs before it read about 199 ms. Three runs after it read 206, 195 and 205 ms.

## Upgrade Notes

- **If you call `advisor_recommend`:** read the optional `command` field to learn which slash command runs the routed mode.
- **If you match on an advisor command id:** replace `memory:save` and `command-memory-save` with `command-speckit-save`. Replace `command-spec-kit` with the id of the command you mean, such as `command-spec-kit-plan`. Replace `command-prompt-improver` with `command-prompt-improve`.
- **If you want meaning matching:** run Ollama with `nomic-embed-text`, then run `skill_graph_scan` so the command vectors are built.
- **If you want hook health in `/doctor:setup`:** run the hook once with `SKILL_ADVISOR_DEBUG=1`.
- **If you run Codex:** approve its hook in `/hooks`. Until then no brief arrives there.
- **If you run the advisor from a built copy:** run `npm run build` in `.skilled/skills/system-skill-advisor/runtime` once.
