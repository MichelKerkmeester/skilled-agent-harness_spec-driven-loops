# v0.12.0.0, A Prompt Hook That Holds Up in Five CLIs

The skill advisor's prompt hook suggests a skill before each prompt reaches the model. This release makes that hook cheaper and clearer. It skips work nobody reads, keeps casual prompts away from the advisor and tells the model why a turn carries no suggestion. A slow advisor no longer leaves a turn with nothing.

The work began as a comparison with the pi-skill-orchestrator extension for Pi, which lets the model search for a skill when it needs one instead of receiving a suggestion first. The comparison ranked what the advisor should adopt, and most of the hook changes here are ones it recommended. Its larger ideas, such as a skill search tool for Pi, wait on replays or A/B tests that have not run.

The advisor then ran its own test scenarios inside Pi, OpenCode, Devin, Cursor and Codex. Those runs found a launcher rule that shut the healthy advisor down and a plugin OpenCode refused to load. A two-model review of the hook changes found more, and checking its fixes turned up prompts too long for the advisor to accept. Each is fixed here.

> Part of [Skilled v4.0.0.2](../../../changelog/skilled/v4.0.0.2.md).
>
> Spec folder: `specs/system-skill-advisor/030-pi-skill-orchestrator-based-research-refinement` (Level 2)

## Why This Release

- **Some runtimes got nothing from a slow advisor.** The shim that runs the hook in Claude, Codex, Cursor and Devin stopped it at the same moment the hook gave up on the advisor, so the fallback never arrived.
- **Every prompt paid for work nobody read.** The hook asked for routing data it then threw away, and it sent even a one-word reply to the advisor.
- **A turn without a suggestion looked like every other failure.** The model could not tell an outage from a prompt that matched no skill.

## What's New at a Glance

- **A slow advisor no longer empties the turn.** The hook's own fallback now arrives before the shim that runs it gives up.
- **Casual prompts skip the advisor.** `/help`, a short acknowledgement or a prompt with too little to route returns before any advisor call.
- **The hook asks only for what it reads.** It no longer requests compiled routes, which saved a median 65 ms per prompt when measured.
- **A turn without a suggestion says why.** One line names an outage, a prompt that matched no skill or a skipped prompt. A repeat in the same session shrinks to that line.
- **Long prompts get a route.** Every caller sends at most the 10,000 characters the advisor accepts, so a long prompt is routed on its opening instead of getting the outage message.
- **Prompts stay out of the process list.** Every advisor caller sends the prompt over standard input rather than on the command line.
- **The healthy advisor stays up.** A second launcher no longer shuts the live advisor down when it opens the same database.
- **A sandboxed advisor stays in its sandbox.** An advisor started with its own database folder keeps every state file inside that folder.
- **OpenCode loads the plugin.** The plugin file now exports only the factory OpenCode expects, so OpenCode sessions get the suggestion and the status tool.
- **Diagnostics name the real runtime.** Each record says which runtime ran the hook and how many bytes it delivered, and the logs are private to their owner.
- **`advisor_validate` accepts every runtime.** Outcome events from Pi, Codex, Cursor and Devin were rejected before.

## The Prompt Hook

The hook runs before every prompt, so each change here pays back on every turn.

#### A Slow Advisor No Longer Empties the Turn

In Claude, Codex, Cursor and Devin the hook runs inside a system-spec-kit shim that stops it after 2,500 ms. The hook gave its own advisor call the same 2,500 ms, so a slow advisor ran into the shim's limit first and the turn got nothing, not even the fallback. The shim now gives the hook at most 2,200 ms, and system-spec-kit v2.1.4.0 records that change.

A turn that runs the hook as a separate process also lost its diagnostic record when the process exited. The hook now waits up to 100 ms for pending log writes before it exits.

Pi runs the hook inside its own process rather than through the shim. It now races that call against the hook's budget plus a small margin and falls back to the fixed fallback text when the advisor is late. It also reads the budget the way the hook does, so a negative value no longer becomes a deadline already in the past that threw away a live suggestion.

&nbsp;

#### Casual Prompts Skip the Advisor

The check that keeps casual prompts away from the advisor had lost its only caller, so every prompt started an advisor call. The hook now runs that check first. `/help`, a short acknowledgement or a prompt with too little to route returns a skipped result before any call starts. A replay over the labeled and golden prompt collections confirmed that the check turns away no prompt that should route.

&nbsp;

#### The Hook Asks Only for What It Reads

For each compiled hub among its top results, every hook turn built a compiled route (a precomputed routing decision for a skill hub) and then discarded it, because only the OpenCode plugin reads that route. `advisor_recommend` now takes `options.includeCompiledRoute`, which defaults to true, and the hook always sends false. Measured on one build against one daemon, that saved a median 65 ms per prompt.

An advisor daemon started before this release rejects the new option as unknown. The advisor command line then retries once without it, so an older daemon still answers until it restarts.

&nbsp;

#### A Turn Without a Suggestion Says Why

A turn with no suggestion used to carry the bare fallback text, so the model could not tell an outage from a prompt that matched no skill or one the hook skipped. The fallback now opens with one line that names the case. An outage line names the command to route by hand, a no-match line says no skill matched and a skip line says the prompt was skipped.

That line also makes repeats cheap. Within a known session a repeated fallback shrinks to its first line, and in a live run five turns without a route sent the full 244 bytes once and 26 bytes after that. An unknown session, the kill switch and an error still get the whole text. Pi's debug line names each case too, instead of reading the first line as a live route.

&nbsp;

#### Long Prompts Get a Route

`advisor_recommend` accepts at most 10,000 prompt characters, while the hooks and the OpenCode plugin sent up to 64 KiB. Every longer prompt failed that check and got the outage message instead of a route. Every caller now sends the first 10,000 characters. The plugin also keeps the whole request inside its size limit, and the Python command line counts characters the way JavaScript does, so a prompt full of emoji fits too.

## The Advisor Daemon

The daemon is the background process that holds the skill index and scores each prompt. Its defects surfaced only when several runtimes and test runs shared one machine.

#### The Healthy Advisor Stays Up

A launcher treated a live owner as abandoned whenever the owner's parent process was gone. The command line starts every launcher detached, so every healthy owner looked abandoned, and a second launcher on the same database deleted the owner's lease. The healthy advisor then shut itself down at its next heartbeat. A lease is now reclaimable only when its process is dead or its heartbeat is stale, which is what the lease contract always said.

&nbsp;

#### A Sandboxed Advisor Stays in Its Sandbox

`SYSTEM_SKILL_ADVISOR_DB_DIR` points an advisor at its own database folder, but its generation file, quarantine database, launcher state and model server still used the shared locations, so a test advisor could mark the live one unavailable. All four now move under the chosen folder, and the daemon gets the model-server address its launcher prepared. Without the override every path stays where it was.

&nbsp;

#### Prompts Stay Out of the Process List

Any local process listing could read a prompt, because the callers passed it on the command line. The advisor command line now takes `--json -` and reads the same request from standard input, and the compiled-route front door takes `--prompt-stdin`. The hook fallback, the OpenCode plugin and the daemon all send the prompt that way. The command-line forms still work for anyone who types them.

&nbsp;

#### Diagnostics Name the Runtime and Stay Private

Diagnostic records now carry the runtime that ran the hook and the bytes it delivered, where Codex, Cursor and Devin turns used to be recorded as Claude. The metrics folder and each log are readable by their owner only, and a folder or log an older writer left open is tightened. `advisor_validate` accepts outcome events from all seven runtimes, and a switched-off advisor's status names the flag that switched it off.

## The OpenCode Plugin

#### OpenCode Loads the Plugin

OpenCode refused the advisor plugin, because the plugin file exported helper functions beside the factory OpenCode expects. OpenCode sessions therefore never got the skill suggestion or the advisor status tool. The helpers moved to `.opencode/plugins/lib/skill-advisor-render.js`, and the plugin file exports only its factory.

&nbsp;

#### Repeated Transforms Stay Suppressed

With `deduplicateTransforms` on, the plugin shortened a repeated block to its first line before comparing it with the last block for the same message. A second transform for that message then missed the match and delivered the block again. The plugin now compares the full block first and shortens only a block it will deliver. Its fallback opens with the same status line the hook uses, and a parity test holds the two texts together.

## Documentation and Test Scenarios

#### Docs That Match the Hook

The feature catalog, the playbooks and the READMEs now describe the hook as it runs: the status line, the prompt check in front of the command line, the new option, the one retry for an older daemon and the runtime each adapter names. A new catalog entry covers Pi's prompt advisor, and the catalog states the shim's 2,200 ms cap on the hook budget.

The advisor's command inventory also lists `/create:goal`, which sk-doc added, so the inventory's freshness check passes again.

&nbsp;

#### Scenarios That Check What They Can See

Six advisor scenarios now check only signals their commands can show, such as reading a diagnostic from the diagnostics log rather than from output the shim never forwards. The two scenarios that start a sandboxed advisor clean up without sending a signal. The sandbox advisor exits after 12 idle seconds, and the scenario removes its folder only once nothing holds a file open there.

## Upgrade Notes

- **New inputs.** `advisor_recommend` takes `options.includeCompiledRoute`, true by default. The advisor command line reads its request from standard input with `--json -`, and the compiled-route front door reads the prompt with `--prompt-stdin`.
- **An older daemon.** A daemon started before this release rejects `includeCompiledRoute`, and the command line retries once without it. Restarting the daemon ends the retry.
- **Plugin helpers moved.** Code that imported a helper from `.opencode/plugins/system-skill-advisor.js` should import it from `.opencode/plugins/lib/skill-advisor-render.js`, since the plugin file now exports only its factory.
