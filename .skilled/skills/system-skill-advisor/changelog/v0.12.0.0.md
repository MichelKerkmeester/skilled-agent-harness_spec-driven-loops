# v0.12.0.0, A Prompt Hook That Holds Up in Five CLIs

The prompt hook suggests a skill before each prompt reaches the model.

- This release makes the hook cheaper and clearer.
- It skips work nobody reads.
- It keeps casual prompts away from the advisor.
- It tells the model why a turn carries no suggestion.

A slow advisor no longer leaves a turn with nothing.

- The work began as a comparison with the pi-skill-orchestrator extension for Pi.
- That extension lets the model search for a skill when it needs one.
- It does not receive a suggestion first.
- The comparison ranked what the advisor should adopt.

Most of the hook changes here are ones it recommended.

- Its larger ideas wait on replays or A/B tests that have not run.
- One example is a skill search tool for Pi.
- The advisor then ran its own test scenarios inside Pi, OpenCode, Devin, Cursor and Codex.
- Those runs found a launcher rule that shut the healthy advisor down.

They also found a plugin OpenCode refused to load.

- A two-model review of the hook changes found more.
- Checking its fixes turned up prompts too long for the advisor to accept.
- Each is fixed here.

> Part of [Skilled v4.0.0.2](../../../changelog/skilled/v4.0.0.2.md).

&nbsp;

## Why This Release

- Some runtimes got nothing from a slow advisor.
- The shim runs the hook in Claude, Codex, Cursor and Devin.
- It stopped the hook at the same moment the hook gave up on the advisor.
- So the fallback never arrived.
- Every prompt paid for work nobody read.
- The hook asked for routing data it then threw away.
- It sent even a one-word reply to the advisor.
- A turn without a suggestion looked like every other failure.
- The model could not tell an outage from a prompt that matched no skill.

## The Prompt Hook

The hook runs before every prompt. So each change here pays back on every turn.

#### A Slow Advisor No Longer Empties the Turn <a id="c-a-slow-advisor-no-longer-empties-the-turn"></a>

- In Claude, Codex, Cursor and Devin the hook runs inside a system-spec-kit shim.
- That shim stops it after 2,500 ms.
- The hook gave its own advisor call the same 2,500 ms.
- So a slow advisor ran into the shim's limit first.
- The turn got nothing, not even the fallback.
- The shim now gives the hook at most 2,200 ms.
- system-spec-kit v2.1.4.0 records that change.
- Pi runs the hook inside its own process rather than through the shim.
- It now races that call against the hook's budget plus a small margin.
- It falls back to the fixed fallback text when the advisor is late.
- It also reads the budget the way the hook does.
- So a negative value no longer becomes a deadline already in the past.
- That deadline threw away a live suggestion.

<details>
<summary><b>Smaller fixes</b></summary>

- A turn that runs the hook as a separate process also lost its diagnostic record.
- That happened when the process exited.
- The hook now waits up to 100 ms for pending log writes before it exits.

</details>

#### Casual Prompts Skip the Advisor <a id="c-casual-prompts-skip-the-advisor"></a>

- The check that keeps casual prompts away from the advisor had lost its only caller.
- So every prompt started an advisor call.
- The hook now runs that check first.
- `/help`, a short acknowledgement or a prompt with too little to route returns a skipped result.
- That happens before any call starts.
- A replay over the labeled and golden prompt collections confirmed one thing.
- The check turns away no prompt that should route.

#### The Hook Asks Only for What It Reads <a id="c-the-hook-asks-only-for-what-it-reads"></a>

- Every hook turn built a compiled route for each compiled hub among its top results.
- A compiled route is a precomputed routing decision for a skill hub.
- The turn then discarded it, because only the OpenCode plugin reads that route.
- `advisor_recommend` now takes `options.includeCompiledRoute`.
- That option defaults to true.
- The hook always sends false.
- Measured on one build against one daemon, that saved a median 65 ms per prompt.
- An advisor daemon started before this release rejects the new option as unknown.
- The advisor command line then retries once without it.
- So an older daemon still answers until it restarts.

#### A Turn Without a Suggestion Says Why <a id="c-a-turn-without-a-suggestion-says-why"></a>

- A turn with no suggestion used to carry the bare fallback text.
- So the model could not tell an outage from a prompt that matched no skill.
- It could not tell a skipped prompt either.
- The fallback now opens with one line that names the case.
- An outage line names the command to route by hand.
- A no-match line says no skill matched.
- A skip line says the prompt was skipped.
- That line also makes repeats cheap.
- Within a known session a repeated fallback shrinks to its first line.
- In a live run five turns without a route sent the full 244 bytes once.
- They sent 26 bytes after that.
- An unknown session, the kill switch and an error still get the whole text.
- Pi's debug line names each case too.
- It does that instead of reading the first line as a live route.

#### Long Prompts Get a Route <a id="c-long-prompts-get-a-route"></a>

- `advisor_recommend` accepts at most 10,000 prompt characters.
- The hooks and the OpenCode plugin sent up to 64 KiB.
- Every longer prompt failed that check.
- It got the outage message instead of a route.
- Every caller now sends the first 10,000 characters.
- The plugin also keeps the whole request inside its size limit.
- The Python command line counts characters the way JavaScript does.
- So a prompt full of emoji fits too.

## The Advisor Daemon

The daemon is the background process that holds the skill index. It scores each prompt. Its defects surfaced only when several runtimes and test runs shared one machine.

#### The Healthy Advisor Stays Up <a id="c-the-healthy-advisor-stays-up"></a>

- A launcher treated a live owner as abandoned whenever the owner's parent process was gone.
- The command line starts every launcher detached.
- So every healthy owner looked abandoned.
- A second launcher on the same database deleted the owner's lease.
- The healthy advisor then shut itself down at its next heartbeat.
- A lease is now reclaimable only when its process is dead.
- It is also reclaimable when its heartbeat is stale.
- That is what the lease contract always said.

#### A Sandboxed Advisor Stays in Its Sandbox <a id="c-a-sandboxed-advisor-stays-in-its-sandbox"></a>

- `SYSTEM_SKILL_ADVISOR_DB_DIR` points an advisor at its own database folder.
- Its generation file, quarantine database, launcher state and model server still used the shared locations.
- So a test advisor could mark the live one unavailable.
- All four now move under the chosen folder.
- The daemon gets the model-server address its launcher prepared.
- Without the override every path stays where it was.

#### Prompts Stay Out of the Process List <a id="c-prompts-stay-out-of-the-process-list"></a>

- Any local process listing could read a prompt.
- That is because the callers passed it on the command line.
- The advisor command line now takes `--json -`.
- It reads the same request from standard input.
- The compiled-route front door takes `--prompt-stdin`.
- The hook fallback, the OpenCode plugin and the daemon all send the prompt that way.
- The command-line forms still work for anyone who types them.

#### Diagnostics Name the Runtime and Stay Private <a id="c-diagnostics-name-the-runtime-and-stay-private"></a>

- Diagnostic records now carry the runtime that ran the hook.
- They also carry the bytes it delivered.
- Codex, Cursor and Devin turns used to be recorded as Claude.
- The metrics folder and each log are readable by their owner only.
- A folder or log an older writer left open is tightened.
- `advisor_validate` accepts outcome events from all seven runtimes.
- A switched-off advisor's status names the flag that switched it off.

## The OpenCode Plugin

These changes affect the OpenCode plugin.

#### OpenCode Loads the Plugin <a id="c-opencode-loads-the-plugin"></a>

- OpenCode refused the advisor plugin.
- That is because the plugin file exported helper functions beside the factory OpenCode expects.
- OpenCode sessions therefore never got the skill suggestion or the advisor status tool.
- The helpers moved to `.opencode/plugins/lib/skill-advisor-render.js`.
- The plugin file exports only its factory.

#### Repeated Transforms Stay Suppressed <a id="c-repeated-transforms-stay-suppressed"></a>

- With `deduplicateTransforms` on, the plugin shortened a repeated block to its first line.
- It did that before comparing it with the last block for the same message.
- A second transform for that message then missed the match.
- It delivered the block again.
- The plugin now compares the full block first.
- It shortens only a block it will deliver.
- Its fallback opens with the same status line the hook uses.
- A parity test holds the two texts together.

## Documentation and Test Scenarios

The docs and the scenarios were brought in line with the hook.

#### Docs That Match the Hook <a id="c-docs-that-match-the-hook"></a>

- The feature catalog, the playbooks and the READMEs now describe the hook as it runs.
- They cover the status line.
- They cover the prompt check in front of the command line.
- They cover the new option.
- They cover the one retry for an older daemon.
- They cover the runtime each adapter names.
- A new catalog entry covers Pi's prompt advisor.
- The catalog states the shim's 2,200 ms cap on the hook budget.
- The advisor's command inventory also lists `/create:goal`.
- sk-doc added it.
- So the inventory's freshness check passes again.

#### Scenarios That Check What They Can See <a id="c-scenarios-that-check-what-they-can-see"></a>

- Six advisor scenarios now check only signals their commands can show.
- One example reads a diagnostic from the diagnostics log.
- It does not read output the shim never forwards.
- The two scenarios that start a sandboxed advisor clean up without sending a signal.
- The sandbox advisor exits after 12 idle seconds.
- The scenario removes its folder only once nothing holds a file open there.

## Upgrade Notes

Callers pass prompts and options differently now. Two groups have extra steps.

#### Before You Start <a id="c-before-you-start"></a>

1. `advisor_recommend` takes `options.includeCompiledRoute`, true by default.
2. The advisor command line reads its request from standard input with `--json -`.
3. The compiled-route front door reads the prompt with `--prompt-stdin`.

<details>
<summary><b>The Advisor Daemon</b></summary>

- A daemon started before this release rejects `includeCompiledRoute`.
- The command line retries once without it.
- Restarting the daemon ends the retry.

</details>

<details>
<summary><b>The OpenCode Plugin</b></summary>

- Code that imported a helper from `.opencode/plugins/system-skill-advisor.js` should import it from `.opencode/plugins/lib/skill-advisor-render.js`.
- The plugin file now exports only its factory.

</details>
