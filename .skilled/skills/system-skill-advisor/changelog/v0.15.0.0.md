# v0.15.0.0, Routes Follow the Request, Not the Path

A prompt that names a file under a skill, or edits a skill's own SKILL.md, no longer routes to that skill just because its name appears. The sk-code probe battery moves from 12 of 17 positives and 2 of 5 false positives to 14 of 17 and 0 of 5.

> Spec folders: `specs/sk-code/011-sk-code-poinytail-based-refinement/014-skill-authoring-ux-research/007-advisor-name-mention-scoring` and `008-advisor-surface-hint` (Level 1)

&nbsp;

## What's New at a Glance

- **A name in a path is a location.** A skill name or author phrase counts only when it is not inside a path token and not right before SKILL.md, ROUTER.md, a README or a changelog.
- **Editing a skill's doc routes to the doc work.** When a write verb targets a skill's own doc file, that skill's author phrases are skipped, and `skill.md` and `router.md` count as doc surfaces.
- **A .skilled/ path is never an executor handoff.** The executor-delegation guard matches `.skilled/` as well as `.opencode/`, in both the native and the Python scorer.
- **The generic word findings no longer lifts sk-code.** Its token boost is gone from both scorers.
- **advisor_recommend takes a surface hint.** `options.surfaceHint`, such as `WEBFLOW`, is forwarded to the compiled-route front door as `--surface-hint`; an unknown surface is ignored there.
- **The runtime declares its Node floor.** `package.json` now sets `engines.node` to `>=20.19.0`, the version its build dependencies need, so npm warns on an older Node.

&nbsp;

## Upgrade

No migration required. Rebuild the runtime (`npm run build` in `runtime/`) so the daemon serves the new scorer.
