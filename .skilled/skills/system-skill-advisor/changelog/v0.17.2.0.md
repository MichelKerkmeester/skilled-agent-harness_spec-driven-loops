# v0.17.2.0, The Plugin Drops a Surface With No Marker

The OpenCode plugin keeps its own copy of the declared surface reader. That copy kept a surface block that declared no marker at all. It now drops such a block, as the sk-code hub reader already does, so both readers list the same surfaces.

> Spec folder: `specs/sk-code/015-quality-agnostic-gate/009-review-closeout` (Level 2)

&nbsp;

## What's New at a Glance

- **The plugin matches the hub reader.** A surface block with no path, file or content marker no longer appears in the advisor's surface list.
- **A parity test guards the pair.** The sk-code-skilled test fails when the two readers return different labels for the same inputs.

&nbsp;

## Upgrade

No migration required. A surface block that carries a path, file or content marker behaves as before.
