This release gives the detailed frontmatter on skill reference and asset docs a real runtime consumer. Behind the `SPECKIT_ADVISOR_DOC_TRIGGERS` flag, a new `skill_docs` table feeds routing signal and matched-file pointers.

> Spec folder: `.opencode/specs/skilled-agent-orchestration/145-advisor-doc-trigger-harvest/`
> Contract origin: `system-spec-kit/027-xce-research-based-refinement/000-release-cleanup/009-skill-frontmatter-alignment/001-frontmatter-benefit-investigation/`

## Why This Release

The flag defaults off, and flag-off behavior is byte-identical to v0.7.0.

## What's New at a Glance

- **Doc-specific prompts rank the owning skill.** They point to the exact file to open.
- **Document phrases add a dampened `derived_generated` signal.** Their volume can assist ranking without hard-routing alone.
- **Reference edits refresh their skill.** The daemon watcher tracks harvestable docs for freshness.
- **The Python advisor follows the same flag.** `skill_advisor.py` harvests from disk, and the SQLite loader merges the source-metadata signal.
- **The daemon launcher forwards the feature flag.** `SPECKIT_ADVISOR_DOC_TRIGGERS` now reaches the daemon child.

## Advisor Matching

#### Frontmatter Joins the Scan

`skill_graph_scan` harvests `title`, `description`, `trigger_phrases`, `importance_tier` and `contextType` from each skill's `references/` and `assets/` markdown into `skill_docs`.

The table adds schema and migration support, allows one row per skill and document path and deletes its rows when a skill is deleted. The skill-frontmatter authoring campaign grows document coverage, with `trigger_phrases` on 84 of about 355 docs at release.

&nbsp;

#### Bounded Document Harvest

Every scan harvests each skill because document edits do not touch `graph-metadata.json`, so node-level hash skips cannot block this work. Per-document content hashes keep it cheap, stale rows are swept per skill, and unreadable docs warn with `DOC-READ-FAILED` and continue.

The walker excludes READMEs and reads `references/` and `assets/` recursively to depth 6, up to 200 docs per skill. The parser accepts block and inline `[a, b]` list forms, limits phrases to 12 per doc and clamps each field at 300 characters.

&nbsp;

#### Document Matches Assist Ranking

For each skill, the scorer takes the three strongest document matches, multiplies each by its importance-tier weight and sums the results up to 0.45. Weights run from 1.0 for constitutional/critical to 0.2 for deprecated, keeping document volume below the contribution from one curated skill-level phrase. At normal tier, a document-only match reaches about 0.68 confidence. The existing `derived_generated` lane adds this signal without a sixth lane or weight redistribution.

&nbsp;

#### Matched Documents Stay Bounded

`matchedDocs` is an optional field on the strict schema, with up to three skill-relative paths. Paths are extracted from `doc:` evidence behind a sanitization allowlist that allows only Markdown beneath `references/` or `assets/` and rejects traversal. The release adds a new `doc_reference_signal` evidence type.

## Document Freshness

#### Reference Edits Refresh Skills

When the flag is on, each harvestable document becomes a `doc-frontmatter` watch target. Editing a reference reindexes its skill without a manual scan.

&nbsp;

#### Python Scoring Uses the Active Loader

The Python `skill_advisor.py` harvests the same doc phrases from disk under the same flag. Source-metadata signal merging had applied only to the legacy JSON graph path. The SQLite loader, which always wins in this repo, now merges it too.

---

## Flag Delivery

#### The Daemon Receives the Flag

The daemon child did not receive `SPECKIT_ADVISOR_DOC_TRIGGERS` because `system-skill-advisor-launcher.cjs` forwards only `CHILD_ENV_ALLOWLIST` keys. The flag is now on that list, and future advisor environment flags need the same entry to reach the daemon.

## Upgrade Notes

- **Schema.** No migration is required because `skill_docs` is created additively on open.
- **Enable.** Set `SPECKIT_ADVISOR_DOC_TRIGGERS=true` in the advisor env block of each runtime config. This repo sets it in `opencode.json`, `.claude/mcp.json` and `.codex/config.toml`.
- **Start fresh.** Every advisor-attached session must end before a fresh session respawns the daemon with the flag. The advisor launcher exits if its daemon child is SIGTERMed, and launchers spawned before the flag change keep their old environment.
- **Verify.** Run a trusted `skill_graph_scan` and expect `docs` counters, then use `advisor_recommend` with a doc-specific phrase and expect `matchedDocs`.
- **Rollback.** Unset the flag to leave the rows persisted but ignored, or drop the `skill_docs` table.
