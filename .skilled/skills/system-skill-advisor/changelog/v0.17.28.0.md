# v0.17.28.0, Three Derived Bridges for the Root Instruction File

The advisor's command bridges come from the route manifest. They are never written by hand. So a new doctor command reaches the advisor as soon as the manifest names it. It reaches every surface the generator owns.

&nbsp;

## What's New at a Glance

- **Three routes became three bridge entries.** `check`, `embed` and `restore` each derive one entry from `_routes.yaml`. Each entry has the trigger phrases the manifest declares. It also has the runnable command its route names.
- **The generated surfaces stayed generated.** The bridge file, the TypeScript projection, the render list and the Python markers all come from one generator run. A second run reports them fresh with nothing changed.
- **All three bridges are inactive.** Nothing in this release activates them. So a scoring change cannot reach the live scorer. That stays true until the activation list carries them. It also stays true until the reach probe proves every phrase.
- **No other bridge moved.** The doctor routes that were live stayed live. Their phrases still reach them. The reach probe checks that on every run.

&nbsp;

## Upgrade

No migration required. An inactive bridge costs nothing at run time. It appears in the next generated build.
