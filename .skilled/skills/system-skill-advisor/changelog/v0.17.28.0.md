# v0.17.28.0, Three Derived Bridges for the Root Instruction File

The advisor's command bridges are generated from the route manifest, never written by hand. A new doctor command therefore reaches the advisor the moment the manifest names it, in every surface the generator owns.

> Spec folder: `specs/agents/021-doctor-agents-md/001-doctor-agents-md/004-command-plumbing` (Level 2)

&nbsp;

## What's New at a Glance

- **Three routes became three bridge entries.** `check`, `embed` and `restore` each derive one entry from `_routes.yaml`, with the trigger phrases the manifest declares and the runnable command its route names.
- **The generated surfaces stayed generated.** The bridge file, the TypeScript projection, the render list and the Python markers all come from one generator run, and a second run reports them fresh with nothing changed.
- **All three bridges are inactive.** Nothing in this release activates them, so a scoring change cannot reach the live scorer until the activation list carries them and the reach probe proves every phrase.
- **No other bridge moved.** The doctor routes that were live stayed live and their phrases still reach them, which the reach probe checks on every run.

&nbsp;

## Upgrade

No migration required. An inactive bridge costs nothing at run time and appears in the next generated build.
