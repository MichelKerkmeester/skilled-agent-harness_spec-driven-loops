# v0.15.4.0, Scorer Drift Now Fails CI

The advisor has two scorers. One is Python and one is TypeScript. A test lists every prompt where they pick different skills. No CI job ran that test. So a new disagreement never stopped a push. CI now runs it. It also runs a wider check. That check keeps the held-out prompts separate from everything that tunes or tests the scorer.

> Spec folder: `specs/sk-code/011-sk-code-poinytail-based-refinement/021-open-ends-remediation/004-routing-parity-ci` (Level 1)

&nbsp;

## What's New at a Glance

- **A new scorer disagreement fails the push.** The comparison between the two scorers runs as its own blocking CI step. Any disagreement missing from the approved list stops the build.
- **The comparison gives one answer everywhere.** It builds a fresh copy of the skill graph for both scorers. It scores at a fixed date. So a machine with a running advisor, a clean CI runner and next year's calendar all agree.
- **The holdout stays honest across every test that scores prompts.** Each test that shares prompts with the holdout has to say so. It also has to say why. A new shared prompt or a new scoring test that has not said so fails CI.
- **A green result says what it proves.** The comparison now states what it checks. It checks the two scorers inside the test run, not the live advisor.

&nbsp;

## Upgrade

No migration required. A new disagreement between the scorers now needs a reviewed entry in the approved list. CI passes only after that.
