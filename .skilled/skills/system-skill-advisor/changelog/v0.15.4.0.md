# v0.15.4.0, Scorer Drift Now Fails CI

The advisor has two scorers, a Python one and a TypeScript one, and a test that lists every prompt where they pick different skills. No CI job ran that test, so a new disagreement never stopped a push. CI now runs it, together with a wider check that the held-out prompts stay separate from everything that tunes or tests the scorer.

> Spec folder: `specs/sk-code/011-sk-code-poinytail-based-refinement/021-open-ends-remediation/004-routing-parity-ci` (Level 1)

&nbsp;

## What's New at a Glance

- **A new scorer disagreement fails the push.** The comparison between the two scorers runs as its own blocking CI step, and any disagreement missing from the approved list stops the build.
- **The comparison gives one answer everywhere.** It builds a fresh copy of the skill graph for both scorers and scores at a fixed date, so a machine with a running advisor, a clean CI runner and next year's calendar all agree.
- **The holdout stays honest across every test that scores prompts.** Each test that shares prompts with the holdout has to say so and why, and a new shared prompt or a new scoring test that has not said so fails CI.
- **A green result says what it proves.** The comparison now states that it checks the two scorers inside the test run, not the live advisor.

&nbsp;

## Upgrade

No migration required. A new disagreement between the scorers now needs a reviewed entry in the approved list before CI passes.
