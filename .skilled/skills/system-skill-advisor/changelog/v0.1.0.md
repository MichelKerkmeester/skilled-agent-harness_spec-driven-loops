This first preview release gives prompt-time skill recommendations a standalone MCP home, so the advisor can be installed, tuned or replaced independently of `system-spec-kit`. It exposes eight public tools through the `mcp__system_skill_advisor__*` namespace and connects the package to every install and diagnostic surface.

## What's New at a Glance

- **The advisor ships as a standalone MCP package.** It has the `system_skill_advisor` identity and its own runtime. The package ships at `.opencode/skills/system-skill-advisor/` with `.opencode/bin/system-skill-advisor-launcher.cjs` and a package-local SQLite database at `mcp-server/database/skill-graph.sqlite`, so it can be installed, tuned or replaced independently. Rollback to the Python CLI shim is one environment variable away.
- **The advisor is decoupled from Spec Kit runtime imports.** It was extracted from and decoupled from the `system-spec-kit` source tree, where advisor recommendations mixed skill-graph and advisor scoring with spec-kit memory and lifecycle code. Phase 1 isolation lifted it out of `system-spec-kit` runtime imports, and Phase 2 + 3 hybrid decoupling moved shared types into `@spec-kit/shared` and inlined what stayed local so preview iterations are not coupled to the spec-kit memory release cadence.
- **Four MCP tools provide native advisor recommendations.** `advisor_recommend`, `advisor_rebuild`, `advisor_status` and `advisor_validate` are available through `mcp__system_skill_advisor__*`. `advisor_recommend` returns prompt-safe `recommendations[]` plus cache and lifecycle metadata, while `advisor_validate` returns real corpus, holdout, parity, safety and latency measurements. Prompts needed lifecycle redirects and freshness trust gates that the legacy Python shim could not deliver directly inside MCP.
- **Every runtime can use the same advisor surface.** The MCP-native surface uses fail-open semantics instead of per-host subprocess shims. The 0.1 line keeps shadow-mode and parity gates in place while corpus and holdout metrics mature.
- **Four MCP tools expose the skill graph.** `skill_graph_scan`, `skill_graph_query`, `skill_graph_status` and `skill_graph_validate` expose the package-local SQLite graph, letting maintainers inspect, query and validate it without advisor scoring. Its lifecycle, freshness and trust state mirror the advisor tools, giving graph rebuilds, audits and integration checks a stable MCP surface.
- **The Python shim and OpenCode bridge support existing callers.** Existing prompt hooks and CLI consumers depended on `skill_advisor.py` and the OpenCode plugin bridge. `skill_advisor.py` probes the native advisor first, translates its response to the legacy JSON-array shape and falls back to the local Python scorer when the native probe is unavailable. The `--force-native` and `--force-local` testing toggles support rollback debugging, and the OpenCode plugin bridge follows the same fail-open pattern so existing automation keeps working as the native advisor moves toward 1.0.
- **Install and diagnostic surfaces register the advisor.** The skill already had an `INSTALL-GUIDE.md`, but the master install README and `/doctor:mcp install` / `/doctor:mcp debug` enumerated four MCP servers without `system_skill_advisor`. The master install README adds a §10.5 Skill Advisor subsection, and `mcp-doctor.sh` registers `system_skill_advisor` through a new `diagnose_system_skill_advisor()` function. `doctor_mcp_install.yaml`, `doctor_mcp_debug.yaml` and `mcp.md` also register it, while `.vscode/mcp.json` adds its previously missing block for runtime parity across all six configs. Discovery, install and runtime diagnostics now follow the same surface as the other MCP servers.
- **Package documentation describes its surfaces.** The README and `ARCHITECTURE.md` follow the sk-doc skill template, while `feature-catalog/feature-catalog.md` and `manual-testing-playbook/manual-testing-playbook.md` are package-local. Each `mcp-server/**/README.md` describes a code surface, giving one package view of what it owns, how to operate it and where each piece of code lives.

## Upgrade

No migration required. This is a pre-1.0 preview, and the public tool ids (`advisor_recommend`, `advisor_rebuild`, `advisor_status`, `advisor_validate` and `skill_graph_*`) are stable. Existing configs that referenced `system_skill_advisor` should rename the entry to `system_skill_advisor` and point `command`/`args` at `.opencode/bin/system-skill-advisor-launcher.cjs`. The Python shim (`skill_advisor.py`) remains available. Set `SPECKIT_SKILL_ADVISOR_FORCE_LOCAL=1` to fall back to the legacy local scorer for diagnosis.
