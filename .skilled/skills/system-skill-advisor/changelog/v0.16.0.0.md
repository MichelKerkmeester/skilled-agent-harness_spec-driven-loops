# v0.16.0.0, The Advisor Points to the Doctor Commands

The advisor knew every skill but none of the doctor commands, so a prompt like "help me set up skilled" or "check my environment variables" got no suggestion at all. It now names the doctor command to run, as a line you can paste, without taking first place from a skill that fits.

> Spec folder: `specs/system-skill-advisor/035-doctor-command-routing` (Level 2)

&nbsp;

## What's New at a Glance

- **Setup and health prompts name a doctor command.** "Help me set up skilled" suggests `/doctor:setup` and "check my environment variables" suggests `/doctor:env list`, each as a runnable line rather than an internal id.
- **A matching skill keeps first place.** "Check my git hooks setup" still routes to sk-git, and the brief adds `Also: /doctor:git setup` as a second line. No prompt that routed correctly before changed its answer.
- **The doctor routes come from the doctor route list.** The routes are generated from the doctor commands' own route file. A new target still needs its activation entry in `scoring-compatibility.json` before the advisor suggests it.
- **The Python fallback answers typed commands only.** It routes a typed `/doctor:git setup`, and plain wording is left to the main scorer, which keeps the fallback from over-firing.
- **A setup prompt with no match gets a hint.** When nothing matches and the prompt says set up, install, check or configure, the line adds "For setup or health checks, run /doctor:setup." An unrelated prompt gets no hint.
- **The hint holds when the advisor is down.** The outage line carries the same hint ahead of its route-by-hand command, because `/doctor:setup` also checks the advisor, and the command stays last so it can still be copied.
- **Claude, Pi and OpenCode show the same text.** Pi passes the setup check on its deadline path, and the OpenCode plugin renders the hint from its own copy of the check, kept equal to the hook's.
- **The skill-advisor doctor steps run again.** `/doctor:skill-advisor` and its rebuild workflow called `advisor_status` without the workspace root it requires, which exited 64. They now pass it.

&nbsp;

## Upgrade

No migration required. Rebuild the advisor runtime (`npm --prefix .skilled/skills/system-skill-advisor/runtime run build`) so the hooks load the new renderer.
