# A Router Edit Now Reaches the Advisor

The advisor now treats a skill's `ROUTER.md` as part of the skill. Before this release, a change to only the router passed the freshness check unnoticed.

&nbsp;

## What's New at a Glance

- **A router edit marks the index stale.** The freshness signature includes `ROUTER.md` when a skill has one, so a router-only change is caught the same way a `SKILL.md` change is.
- **The daemon reindexes after a router edit.** The watcher now watches each `ROUTER.md`, so the edit goes through the same reindex path as `SKILL.md`.
- **A skill without a router keeps its signature.** Nothing is added for a skill with no `ROUTER.md`, so an index built earlier stays fresh for it.
- **The OpenCode plugin computes the same signature.** Its copy probes `ROUTER.md` the same way, and a parity test fails when the two copies drift apart.

&nbsp;

## Upgrade

Rebuild the advisor and restart its daemon, because a running daemon keeps the code it started with: `npm --prefix .skilled/skills/system-skill-advisor/runtime run build`.
