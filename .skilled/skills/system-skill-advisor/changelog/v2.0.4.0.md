# v2.0.4.0, a skill counts as named only on a word few skills share

Version 2.0.3.0 left the shared lexical anchor alone. A trace of each 0.82 lift showed three paths. Some lifts came from a lexical score built on words many skills list, such as "run" and "check". Some came from the strong-score lift, which never asked whether the prompt named the skill at all. And one came from the id-noun rule accepting "patch", a synonym of "fix", as the prompt's second word.

&nbsp;

## What's New at a Glance

- A lexical score of 0.45 or more names a skill only when the prompt holds one of that skill's words that at most a quarter of the skills list. Command entries are left out of that count, because each one repeats its owner's words. "run the doctor update check" now lifts system-skilled-doctor alone, not cli-classifier and sk-doc beside it.
- The strong-score lift at 0.65 needs a named anchor too. "rewrite this prompt so it is shorter" no longer lifts sk-code, and "fix the code in the parser" no longer lifts local-webflow.
- The id noun's second word must be a word the prompt holds, read from the skill's own text instead of the capped evidence list.
- A typed command names the skill that owns it. `/create:skill-parent deploy-hub with three modes` keeps sk-doc on top.

&nbsp;

## How It Was Checked

Every accuracy ratchet metric held: full corpus 161, unknown 14, holdout 49, ambiguity 21, review 25, memory save 27, delegation 22 and five false fires. The full advisor suite passes except the known `system-skilled-bots` empty-description test, and no pinned command, doctor or golden row moved. Three earlier, stricter candidate rules each moved pinned rows and were dropped. The mcp-browser-use two-stage replay is unchanged at 55 of 56. A new test, `tests/scorer/lexical-anchor-naming.vitest.ts`, fails without the change.

&nbsp;

## Known Limitation

Three of the five probe prompts still lift a second skill. "fix the container orchestration config" lifts mcp-code-mode and the browser hub, "rewrite this prompt so it is shorter" lifts sk-doc, and "update the plan for the mode rollout" lifts cli-external-orchestration. Each shares a word with the prompt that few skills list, so a stricter rule is needed, and the stricter rules tried moved pinned rows.

&nbsp;

## Upgrade

No migration required.
