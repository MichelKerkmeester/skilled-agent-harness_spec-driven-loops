# v0.16.3.0, More Doctor Commands and Fewer False Matches

The advisor now suggests three more doctor commands and stops crediting a short prompt word that only appears inside a longer skill word, which had sent "list" to "allowlist" and "spec" to "inspect". The bare prompt "environment variables" no longer routes to nothing.

> Spec folders: `specs/system-skill-advisor/036-routing-and-launcher-hardening` (Level 2) and `specs/sk-git/033-git-setup-customization/010-open-ends-cleanup` (Level 1)

&nbsp;

## What's New at a Glance

- **Three more doctor commands are suggested.** `/doctor:deep-loop`, `/doctor:mcp install` and `/doctor:mcp debug` show as a second line after the matching skill.
- **"environment variables" has a home.** The bare prompt routes to system-spec-kit, and "check my environment variables" still puts `/doctor:env` first.
- **A route can name lead phrases.** `_routes.yaml` accepts an optional `lead_phrases` list for a phrase where the doctor command must rank above a matching skill.
- **Partial words match one way.** A prompt word gets partial credit only when it contains the skill word, or the skill word starts with it, so "list" no longer reaches "allowlist".
- **An offline launcher keeps its packages.** A stale build whose `node_modules` already matches the lockfile is rebuilt without a reinstall, so a failed `npm ci` can no longer empty it.
- **The hub check refuses a standalone skill.** `/doctor:skill-advisor parent-skill` on a skill that is not a hub stops with `target is not a parent hub` and exit 2, instead of failing five hub checks.

&nbsp;

## Upgrade

No migration required. Rebuild the advisor runtime (`npm --prefix .skilled/skills/system-skill-advisor/runtime run build`).
