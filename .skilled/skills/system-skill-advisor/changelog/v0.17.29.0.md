# v0.17.29.0, the Runtime Build Attests Its Own Dist

A build of the advisor runtime used to compile and copy, and leave the freshness record for whatever check happened to read the dist first. That check wrote one carrying `origin: "checker"` into `dist/runtime/`, a folder the quality suites snapshot while they run, so the first run after a fresh provision could fail an assertion that a run changed nothing on disk and every later run passed.

> Spec folder: `specs/system-skill-advisor/040-build-freshness-record` (Level 1)

&nbsp;

## What's New at a Glance

- **The build prepares and records both dist entries.** A `prebuild` step stores the source hash of the tree about to be compiled for `default` and `skill-advisor-cli`, and the existing `postbuild` promotes both to `origin: "build"` attestations after the data copy. The `build` script itself is unchanged, so provisioning and the documented rebuild command run the same thing they always ran.
- **An un-prepared build still succeeds.** When `record-build` reports that no preparation exists, the fallback writes a checker-origin cache for that entry instead of failing a compile that succeeded, which is the same trade the spec-kit runtime build makes.
- **A contract test holds the scripts to the freshness registry.** The registry decides which dist entries exist. Adding one there without teaching the build to attest it now fails `tests/dist-build-record-contract.vitest.ts` rather than leaving the next fresh checkout to discover it.
- **Nothing about routing changed.** No bridge, score or trigger phrase moved; the release ships a build step and a record.

&nbsp;

## Upgrade

No migration required. The next build writes both records, and a checkout whose records still read `origin: "checker"` keeps working until that build happens.
