# A Doctor Helper Bridge and a Wider Route Vocabulary

The doctor route manifest gained one route and twelve trigger phrases. Both reach the advisor through the same generator as every other doctor bridge.

&nbsp;

## What's New at a Glance

- The inventory grows by one.
  - `command-doctor-helper` is derived into the generated bridge file.
  - The bridge is also derived into the TypeScript projection, the Python projections and the rendered command list.
  - That makes twenty-five doctor routes and fifty-two bridges in total.
- The bridge ships inactive, and the reason is recorded.
  - Activating a doctor bridge needs a routing-slice row and a scorer rebaseline beside it.
  - Neither belongs to the release that adds the route.
  - So the bridge is derived and reachable through `/doctor:helper`.
  - The advisor routes no prompt to it yet.
- Twelve route phrases widen what the doctor vocabulary carries.
  - One is a branch-name pattern.
  - Another is a skill's frontmatter shape.
  - One is a description that is too long.
  - One is a Hermes prompt copy.
  - One is a quality `json` that is missing.
  - One is a UTCP config that is broken.
  - One is an overview of the doctor family.
  - One is a loop that never converges.
  - One is a runtime copy that drifted from its source.
  - Three more came from running ten fresh probes against the shipped command.
  - One is a description longer than the limit allows.
  - One is runtime prompts that are out of date after a pull.
  - One is a model server or helper process still running after the session closed.
  - Each one is an operator's wording that the manifest did not carry.
  - The reach probe confirms every one of them still reaches its own bridge.
- No fusion rule moved.
  - A skill still keeps first place over a doctor bridge.
  - A doctor bridge still changes no skill's score.
