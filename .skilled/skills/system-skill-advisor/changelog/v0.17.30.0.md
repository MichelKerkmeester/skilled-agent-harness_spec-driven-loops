# v0.17.30.0, The Doctor Helper and Agents-md Bridges Route

A derived bridge is knowledge the advisor cannot use. Four doctor routes had reached the generated bridge inventory. They stayed out of the activation list. So a prompt asking which doctor command to run reached a skill or nothing. This release makes them routable. It proves that with the same gates every other bridge passes.

&nbsp;

## What's New at a Glance

- **Four bridges are active.** `command-doctor-helper`, `command-doctor-agents-md-check`, `command-doctor-agents-md-embed` and `command-doctor-agents-md-restore` each carry their entry in both the `typescript` and `python` lists. So the activation list now holds 33 TypeScript and 43 Python entries. Every derived doctor route is admitted.
- **The generated surfaces stayed generated.** One deriver run refreshed the bridge file, the TypeScript projection and the Python markers. A second run reports `fresh` with 28 doctor routes and 55 generated bridges.
- **The reach probe covers the whole surface.** It now proves 28 bridges over 164 declared phrases, runnable command strings included. Every one reaches its own bridge as the top pick or as the first doctor line behind a passing skill. The manifest needed no phrase change.
- **The routing slice carries each bridge.** Thirteen rows sit in four new waves, one wave per bridge. So a row asserts only once every doctor id it names is active. A prompt asks which doctor command to run. It lands on `/doctor:helper` as the second line. A typed `/doctor:agents-md embed` puts that bridge first. Two natural phrasings per target are pinned beside them.
- **No accuracy metric moved.** Full corpus 155 of 195 (0.7949), holdout 49 of 66 (0.7424), ambiguity 19 of 24 (0.7917). There are 13 unknown and 5 gold-none false fires. All three intent buckets are unchanged. So the committed baseline stands and no re-capture was needed.
- **The catalog stops calling the exception the rule.** The doctor routing feature note named six active bridges. It read as if the rest were not active. It now states that every derived bridge is active. It also states that a route added without its activation entry stays unrouted.

&nbsp;

## Upgrade

No migration required. The new bridges are already in the generated inventory of an existing checkout. So the release that ships this entry routes to them. It does so on its own build.
