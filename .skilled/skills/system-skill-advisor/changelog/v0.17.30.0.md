# v0.17.30.0, The Doctor Helper and Agents-md Bridges Route

A derived bridge is knowledge the advisor cannot use. Four doctor routes had reached the generated bridge inventory and stayed out of the activation list, so a prompt asking which doctor command to run reached a skill or nothing. This release makes them routable and proves it with the same gates every other bridge passes.

> Spec folder: `specs/agents/021-doctor-agents-md/003-advisor-bridge-activation` (Level 1)

&nbsp;

## What's New at a Glance

- **Four bridges are active.** `command-doctor-helper`, `command-doctor-agents-md-check`, `command-doctor-agents-md-embed` and `command-doctor-agents-md-restore` each carry their entry in both the `typescript` and `python` lists, so the activation list now holds 33 TypeScript and 43 Python entries and every derived doctor route is admitted.
- **The generated surfaces stayed generated.** One deriver run refreshed the bridge file, the TypeScript projection and the Python markers, and a second run reports `fresh` with 28 doctor routes and 55 generated bridges.
- **The reach probe covers the whole surface.** It now proves 28 bridges over 164 declared phrases, runnable command strings included, and every one reaches its own bridge as the top pick or as the first doctor line behind a passing skill. The manifest needed no phrase change.
- **The routing slice carries each bridge.** Thirteen rows in four new waves, one wave per bridge, so a row asserts only once every doctor id it names is active. A prompt that asks which doctor command to run lands on `/doctor:helper` as the second line, a typed `/doctor:agents-md embed` puts that bridge first, and two natural phrasings per target are pinned beside them.
- **No accuracy metric moved.** Full corpus 155 of 195 (0.7949), holdout 49 of 66 (0.7424), ambiguity 19 of 24 (0.7917), 13 unknown and 5 gold-none false fires, and all three intent buckets unchanged, so the committed baseline stands and no re-capture was needed.
- **The catalog stops calling the exception the rule.** The doctor routing feature note named six active bridges as if the rest were not; it now states that every derived bridge is active and that a route added without its activation entry stays unrouted.

&nbsp;

## Upgrade

No migration required. The new bridges are already in the generated inventory of an existing checkout, so the release that ships this entry routes to them on its own build.
