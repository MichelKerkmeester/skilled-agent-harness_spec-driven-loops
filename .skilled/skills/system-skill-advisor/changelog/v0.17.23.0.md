# A Cli Tool's Name Lifts the Read-Only Floor

A prompt that opens with a read-only verb such as `list` or `show` sits on the explainer floor, at confidence 0.25, unless it names the skill it wants. Only the skill's id counted as naming it, so "List my Orca worktrees and open a terminal in the new one" abstained even though cli-orca led sk-git by 0.19. For a cli skill, the tool's own name now counts too: `orca` for cli-orca, `classifier` for cli-classifier. Both Orca prompts the alignment probe uses now return cli-orca as top-1, and routing accuracy holds at 155/195, 49/66 and 19/24.

The leaf-inventory note listed three leaf roots while `leaf-manifest.config.json` declares five. A reader comparing the note with `leaf-manifest.json` could not account for the `hooks/` leaves, or for an `assets/` root that contributes none.

The note now names all five and says how `hooks/` stays Markdown-only.

The `/doctor:skill-advisor skill-budget` audit now counts each command's description once.

> Spec folder: `specs/sk-doc/072-skill-routing-and-clarity/012-alignment-remediation` (Level 2)

## What's New at a Glance

- **A cli skill's tool name names the skill.** A read-only prompt that says `orca` reaches cli-orca at 0.84 instead of abstaining at 0.25. Prefixes other families use, such as `sk-` and `mcp-`, still need the full id, because their bare suffixes (`git`, `code`, `tooling`) are ordinary words.
- **All five declared leaf roots are named.** `references/`, `assets/`, `feature-catalog/`, `manual-testing-playbook/` and `hooks/`.
- **`hooks/` is Markdown-only through `leaf-scopes.json`.** The scope names its five hook docs, so the nine runtime `.ts`, `.py` and `.json` files beside them are never leaves.
- **`assets/` is accounted for.** It is declared and has no docs to contribute.
- **The budget audit counts each command once.** A native file that repeated a canonical command was counted a second time. The audit now keeps the canonical copy, which it reads first. It skips the repeat.
