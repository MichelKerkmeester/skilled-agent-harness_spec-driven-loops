# v1.1.0.0, Hook Health Without the Debug Flag

The prompt hook now writes a health record on every prompt. So `/doctor:setup` shows hook health with no setup. The record holds no prompt text.

The brief also offers commands with more care. A prompt that rules out a change gets no command from a hub. A deep-loop command needs its own name or a request for depth.

One command row also has a new id. That change breaks a caller that matches on the old id. Renamed Command below says what to change.

> Spec folder: `specs/system-skill-advisor/routing-and-scoring/008-command-surfacing-build`

&nbsp;

## Why This Release

The v1.0.0.0 hook wrote health records only with `SKILL_ADVISOR_DEBUG` set. Most machines never set it. So `advisor_status` had no hook health to report.

Some briefs also offered the wrong command. A hub could offer a writing command to a prompt that asked for no edits. A mention of `/deep:review` opened the gate for `/deep:research`. A file name could read as a typed command.

&nbsp;

## What's New at a Glance

- **Every prompt writes a health record.** It carries no prompt, skill label or error text. <!-- section: Hook Health -->
- **`hookHealth` shows answers from the local scorer.** It also gives the time of the newest record. <!-- section: Hook Health -->
- **A hub says `(needs a mode)` only when you named it.** A hub the scorer guessed shows no label. <!-- section: Brief Commands -->
- **The top hub keeps its command in the hook.** A row the brief never shows can no longer take it. <!-- section: Brief Commands -->

- **A no-edit prompt gets no command on any path.** More wordings now count as no-edit. <!-- section: No-Edit Prompts -->
- **The create-skill command row has a new id.** It is now `command-create-sk-skill`. <!-- section: Renamed Command -->
- **The OpenCode brief drops a repeated route line.** The head already names the hub and its command. <!-- section: OpenCode Plugin -->

## Hook Health

#### A Record on Every Prompt

The Claude, Codex, Cursor, Devin, Pi and DSH hooks share one handler. That handler now appends a health record on every prompt. Before, it wrote one only with `SKILL_ADVISOR_DEBUG` set. A record holds the runtime, the status, the freshness, the duration and the cache hit. A disabled hook writes one too:

```json
{"timestamp":"2026-11-13T20:30:20.999Z","runtime":"claude","status":"skipped","freshness":"unavailable","durationMs":1,"cacheHit":false}
```

`SKILL_ADVISOR_DEBUG=1` now only adds the skill label and the error text. The log trims back to the newest 200 records once it passes 300. The OpenCode plugin writes no record.

#### Health Shows Degraded Answers

`advisor_status` carries `hookHealth` once any hook has written a record. It still summarizes the newest 30 records. Two fields are new. `rollingDegradedRate` is the share of answers from the CLI's local scorer. `lastRecordAt` is the time of the newest record. A runtime that stopped writing now shows its age.

#### Smaller Fixes

- **A runaway Python scorer child can no longer fill memory.** The brief builder keeps at most 1 MiB of each output stream.
- **A busy database still gets its one retry.** The busy marker counts even past that cap or split across two writes.

## Brief Commands

#### The Mode Label Needs Your Words

A hub that cannot pick one mode says `(needs a mode)`. It now says so only when the prompt names that hub. A hub the scorer guessed shows no label. The label used to point at modes you never asked about. The head now names the hub, never a raw command row id.

#### The Top Hub Keeps Its Command

The hook asks for the top pick's route only. A hub used to drop its command when a lower row carried the same one. That row never reached the brief. So the command was lost. The top hub now keeps it.

#### Deep-Loop Commands Need Their Own Name

A deep-loop command still waits for a request for depth. Typing that same command also counts. Typing any other `/deep:` command no longer does. So a mention of `/deep:review` no longer offers `/deep:research`.

#### File Names Are Not Commands

A typed command must end on a word boundary. A dot or slash before more letters now continues a file name. So `/create:sk-skill.md` is no longer read as a typed command.

#### A Mode Suffix Still Counts

A command typed with its mode suffix reads as that command. So `/deep:review:auto` attaches `/deep:review`. The suffixes are `:auto`, `:confirm` and `:autopilot`. Any other suffix reads as no command.

#### The Retired Create-Skill Name Still Reads

A typed `/create:skill` now reads as `/create:sk-skill`. So a prompt that types the old name gets `sk-doc` with `/create:sk-skill (start)`. No command file answers to the old name. The retired name lives only in the `RETIRED_COMMANDS` table in `runtime/lib/command-attach.ts`. `runtime/tests/command-attach-guards.vitest.ts` covers it. A path such as `docs/create:skill.md` still reads as no command.

#### The Doctor Helper for Missing Tools

A prompt that says a tool does not show up now counts as a strong problem cue. The same holds when a tool does not appear. The brief then adds `/doctor:helper` beside the skills. "Appear to" and "up-to-date" stay out of the cue. A contraction typed with a curly apostrophe counts like a straight one.

&nbsp;

## No-Edit Prompts

#### No Command When You Rule Out a Change

The scorer already held back commands on a no-edit prompt. The hub route did not. A hub could offer a writing command to "just list" or "no edits". Now one shared check covers the hub route, both scorer gates and the read-only check.

#### More Wordings Count as No-Edit

The check now reads "make no changes" and "no changes yet". It reads "don't make any changes", with or without the apostrophe. A curly apostrophe counts like a straight one. "Don't create it" counts too, because its object names nothing in particular. "Don't add tools" still asks for a change and keeps its command.

One gap remains. A request that only limits its scope can also lose its command. "Make no changes to the public API" reads as no-edit. Losing an offer costs less than offering a wrong one.

&nbsp;

## Renamed Command

#### The Create-Skill Row Has a New Id

**Breaking:** The command row `command-create-skill` is now `command-create-sk-skill`. Its slash markers are now `/create:sk-skill`. A typed `/create:skill` reads as `/create:sk-skill`, as Brief Commands above says. The rename itself is in the `sk-doc` v2.10.0.0 entry.

&nbsp;

## OpenCode Plugin

#### One Head Line in the Brief

The OpenCode plugin used to push a second line with the compiled route. Its target list printed `targets=none`, because routes now carry objects. The head already names the hub, its command and its policy. So the plugin now sends the head alone.

The command rename has its own entry in `sk-doc` v2.10.0.0.

## How It Was Checked

#### Before and After

| Check | Before | After |
|---|---|---|
| Disabled hook run, `SKILL_ADVISOR_DEBUG` unset | No record written | One `skipped` record, no prompt text |
| "make no changes, explain the readme layout" | Not no-edit | No-edit |
| "don't edit anything, describe the hooks", typed with a curly apostrophe | Not no-edit | No-edit |
| "don't add tools to the agent" | Not no-edit | Not no-edit |
| "the linter does not appear in the tool list" | No cue | Strong cue |
| "it doesn't appear to cover the routing case" | No cue | No cue |
| "open /create:sk-skill.md and read it" | Typed command | No typed command |
| Research route on a prompt that names `/deep:review` | `/deep:research` | No command |
| Research route on "research caching in depth" | `/deep:research` | `/deep:research` |

The no-edit and cue rows ran the old and new patterns side by side. The hook row and every After cell ran on the built advisor. The other Before cells come from reading the v1.0.0.0 code. The hook run sent its log to a private temp folder.

## Upgrade Notes

- **This release as a whole:** run `npm run build` in `.skilled/skills/system-skill-advisor/runtime` once if you run a built copy.
- **If you want hook health in `/doctor:setup`:** send one prompt. Set `SKILL_ADVISOR_DEBUG=1` only to log the skill label and error text.
- **If you match on an advisor command id:** replace `command-create-skill` with `command-create-sk-skill`.
- **If you type `/create:skill`:** type `/create:sk-skill` instead. The old name has no alias.
