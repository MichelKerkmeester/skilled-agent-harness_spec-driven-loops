# v1.1.0.0, Hook Health Without the Debug Flag

The prompt hook now writes a health record on every prompt.
- So `/doctor:setup` shows hook health with no setup.
- The record holds no prompt text.
- `SKILL_ADVISOR_DEBUG=1` only adds the skill label and error text.

The brief also offers commands with more care.
- A prompt that rules out a change gets no command from a hub.
- A deep-loop command needs its own name or a request for depth.
- It adds a measure of which workflow a run opened.

One command row also has a new id.
- That change breaks a caller that matches on the old id.
- Renamed Command below says what to change.

> [!IMPORTANT]
> 1 change can break an existing setup. Read these before you update.
>
> 1. The create-skill command row has a new id. [The Create-Skill Row Has a New Id](#c-the-create-skill-row-has-a-new-id)

&nbsp;

## Why This Release

The v1.0.0.0 hook wrote health records only with `SKILL_ADVISOR_DEBUG` set. Most machines never set it. So `advisor_status` had no hook health to report.

- Some briefs also offered the wrong command.
- A hub could offer a writing command to a prompt that asked for no edits.
- A mention of `/deep:review` opened the gate for `/deep:research`.
- A file name could read as a typed command.
- This release also stops offering a command where none fits the request.

## Hook Health

The shared handler now writes a health record on every prompt. Before, it wrote one only with `SKILL_ADVISOR_DEBUG` set.

#### A Record on Every Prompt <a id="c-a-record-on-every-prompt"></a>

- The Claude, Codex, Cursor, Devin, Pi, DSH and Vibe hooks share one handler.
- That handler now appends a health record on every prompt.
- Before, it wrote one only with `SKILL_ADVISOR_DEBUG` set.
- A record holds the runtime, the status, the freshness, the duration and the cache hit.
- A disabled hook writes one too:

```json
{"timestamp":"2026-11-13T20:30:20.999Z","runtime":"claude","status":"skipped","freshness":"unavailable","durationMs":1,"cacheHit":false}
```

- `SKILL_ADVISOR_DEBUG=1` now only adds the skill label and the error text.
- The log trims back to the newest 200 records once it passes 300.
- The OpenCode plugin writes no record.

#### Health Shows Degraded Answers <a id="c-health-shows-degraded-answers"></a>

- `advisor_status` carries `hookHealth` once any hook has written a record.
- It still summarizes the newest 30 records.
- Two fields are new.
- `rollingDegradedRate` is the share of answers from the CLI's local scorer.
- `lastRecordAt` is the time of the newest record.
- A runtime that stopped writing now shows its age.

#### The Direct Call Reads the Switch <a id="c-the-direct-call-reads-the-switch"></a>

- A direct `advisor_recommend` call now abstains whenever the skill-advisor hooks are off.
- It decides in the caller's own process, under `SYSTEM_SKILL_ADVISOR_DISABLED`, its aliases, the master switch or the flags file.
- That happens before any daemon starts or the scorer runs.
- The launcher passes no switch name to a daemon it starts.

<details>
<summary><b>Smaller fixes</b></summary>

- A runaway Python scorer child can no longer fill memory.
- The brief builder keeps at most 1 MiB of each output stream.
- A busy database still gets its one retry.
- The busy marker counts even past that cap or split across two writes.

</details>

## Brief Commands

Commands now need a clearer signal before the brief offers them.

#### The Mode Label Needs Your Words <a id="c-the-mode-label-needs-your-words"></a>

- A hub that cannot pick one mode says `(needs a mode)`.
- It now says so only when the prompt names that hub.
- A hub the scorer guessed shows no label.
- The label used to point at modes you never asked about.
- The head now names the hub, never a raw command row id.

#### The Top Hub Keeps Its Command <a id="c-the-top-hub-keeps-its-command"></a>

- The hook asks for the top pick's route only.
- A hub used to drop its command when a lower row carried the same one.
- That row never reached the brief.
- So the command was lost.
- The top hub now keeps it.

#### Deep-Loop Commands Need Their Own Name <a id="c-deep-loop-commands-need-their-own-name"></a>

- A deep-loop command still waits for a request for depth.
- Typing that same command also counts.
- Typing any other `/deep:` command no longer does.
- So a mention of `/deep:review` no longer offers `/deep:research`.

#### File Names Are Not Commands <a id="c-file-names-are-not-commands"></a>

- A typed command must end on a word boundary.
- A dot or slash before more letters now continues a file name.
- So `/create:sk-skill.md` is no longer read as a typed command.

#### A Mode Suffix Still Counts <a id="c-a-mode-suffix-still-counts"></a>

- A command typed with its mode suffix reads as that command.
- So `/deep:review:auto` attaches `/deep:review`.
- The suffixes are `:auto`, `:confirm` and `:autopilot`.
- Any other suffix reads as no command.

#### The Retired Create-Skill Name Still Reads <a id="c-the-retired-create-skill-name-still-reads"></a>

- A typed `/create:skill` now reads as `/create:sk-skill`.
- So a prompt that types the old name gets `sk-doc` with `/create:sk-skill (start)`.
- No command file answers to the old name.
- The retired name lives only in the `RETIRED_COMMANDS` table in `runtime/lib/command-attach.ts`.
- `runtime/tests/command-attach-guards.vitest.ts` covers it.
- A path such as `docs/create:skill.md` still reads as no command.

#### The Doctor Helper for Missing Tools <a id="c-the-doctor-helper-for-missing-tools"></a>

- A prompt that says a tool does not show up now counts as a strong problem cue.
- The same holds when a tool does not appear.
- The brief then adds `/doctor:helper` beside the skills.
- "Appear to" and "up-to-date" stay out of the cue.
- A contraction typed with a curly apostrophe counts like a straight one.

#### A Weak Cue Beside a Words-Only Skill <a id="c-a-weak-cue-beside-a-words-only-skill"></a>

- A passing skill used to block the doctor hand-off unless the prompt carried a strong cue.
- Now a weak cue such as "missing" or "drifted" is enough when every passing skill matched on shared single words alone.
- The doctor ranker must still score the prompt at 10 or more.
- So "the agents md file is missing the gate sections" leads with `/doctor:agents-md check` and keeps `sk-doc` after it.
- A skill named by one of its own phrases still gets no doctor command on a weak cue.

## No-Edit Prompts

The scorer already held back commands on a no-edit prompt. The hub route did not.

#### No Command When You Rule Out a Change <a id="c-no-command-when-you-rule-out-a-change"></a>

- The scorer already held back commands on a no-edit prompt.
- The hub route did not.
- A hub could offer a writing command to "just list" or "no edits".
- Now one shared check covers the hub route, both scorer gates and the read-only check.
- A command you typed yourself stays, because what you typed outranks the wording around it.

#### More Wordings Count as No-Edit <a id="c-more-wordings-count-as-no-edit"></a>

- The check now reads "make no changes" and "no changes yet".
- It reads "don't make any changes", with or without the apostrophe.
- A curly apostrophe counts like a straight one.
- "Don't create it" counts too, because its object names nothing in particular.
- "Don't add tools" still asks for a change and keeps its command.
- One gap remains.
- A request that only limits its scope can also lose its command.
- "Make no changes to the public API" reads as no-edit.
- Losing an offer costs less than offering a wrong one.

## Command Fit

A command the prompt refuses or asks about is not offered.

#### A Refusal or a Question Is Not a Request <a id="c-a-refusal-or-a-question-is-not-a-request"></a>

- A command the prompt refuses or asks about is not offered.
- The lead must sit right before the command.
- A command named after a history lead is withheld too.
- Such leads are `ran`, `already ran`, `was running` and `undo what`.
- Any other named command is offered.
- Its owner and route gates still apply.
- A typed command is the reader's own wording.
- A request that states history and then asks keeps its command.
- `why not use` counts as that ask.
- A later `run it` binds to the nearest command.

#### Refusals Cover the Whole List <a id="c-refusals-cover-the-whole-list"></a>

- `no need to run` and `stop using` count as refusals.
- A refusal over a list joined by `or` refuses every command in it.
- That holds for a command written as `the /x command`.

#### A Question Gets No Start <a id="c-a-question-gets-no-start"></a>

- A question about a command gets no start offer.
- A question mark ends the sentence before it.
- A question that opens with `is the` before a command reads as a question.

#### A Small Correction Keeps the Skill <a id="c-a-small-correction-keeps-the-skill"></a>

- A small correction inside an existing readme, catalog or playbook keeps the skill.
- It carries no creation command.
- The gate sits on the readme, catalog and playbook commands.

#### A Weak Cue Needs a Score <a id="c-a-weak-cue-needs-a-score"></a>

- A weak doctor cue is a bare word that ordinary work also uses.
- It needs a ranker score of 9.
- That score sits between the strong-cue bar and the no-cue bar of 10.

## One Head on Every Runtime

The head row now keeps its command under every request shape.

#### The Head Row Keeps Its Command <a id="c-the-head-row-keeps-its-command"></a>

- The head row now keeps its command under every request shape.
- An every-row request no longer drops it.
- The brief offers the same command either way.
- On Vibe, a head that names a command also names each command's document under `.skilled/commands/`.
- Vibe has no command loader.

#### The OpenCode Brief Leads With the Passing Row <a id="c-the-opencode-brief-leads-with-the-passing-row"></a>

- The OpenCode plugin asks for the top-only route the hooks ask for.
- Its label comes from the first row that passes.
- The renderer leads with that row too.

#### The Companion Line Names Its Policy <a id="c-the-companion-line-names-its-policy"></a>

- The doctor companion line now prints its policy word.
- It reads `Also: /doctor:update (ask)`.
- It is left out when the head or its partner already prints that command.

## Workflow Measure

The transcript summary sorts each run into one path.

#### Six Paths and Two Rates <a id="c-six-paths-and-two-rates"></a>

- The transcript summary sorts each run into one path.
- `command` means it read the command's own document, or the host expanded it first.
- `skill` means it loaded the owning skill's `SKILL.md` or `ROUTER.md`.
- `otherMode` means it loaded another mode under the same hub.
- `asked` means the run offered the command and waited.
- `improvised` means it wrote without loading either.
- `none` means it loaded nothing and wrote nothing.
- `loadRate` counts the `command` and `skill` runs over every owned run.
- An `otherMode` run sits in its denominator only.
- `followedRate` adds `asked` to `command` and `skill` over every owned scored run.
- On the stored final arm the followed rate reads claude 8 of 16 and devin 16 of 16.
- It reads dsh 13 of 15, opencode 14 of 16 and pi 12 of 16.

#### Every Shape a Load Takes <a id="c-every-shape-a-load-takes"></a>

- A load is a read tool, a skill tool or a shell read.
- The shell readers include `cat`, `sed -n` and `head`.
- An in-place `sed` is not a read.
- A `prompts/<namespace>-<name>.md` mirror counts too.
- On Codex, one `exec_command` body counts as one shell step.

#### What Does Not Count <a id="c-what-does-not-count"></a>

- A search is not a load, and neither is a heredoc line.
- A write outside the checkout, such as a temp note, no longer sets the boundary for a load.

#### The Counts on Sealed Rows <a id="c-the-counts-on-sealed-rows"></a>

- Nobody tuned the 44 sealed plain rows.
- The brief carries the right command 1 time in the fixture regime.
- With the real embedding that count is 4.
- On the tuned rows the same counts are 28 of 45 and 33 of 45.
- The head carries a command on 8 of the 24 sealed decline rows.

#### The Limits of the Reading <a id="c-the-limits-of-the-reading"></a>

- The rates count a workflow opened before the first write.
- They use tuned rows with one run each.
- So they do not show that the brief makes a model follow a correct workflow more often.
- A load is not a followed step.
- The Codex numbers are thin counts.
- No brief reached Codex in either arm.

#### A Paired Arm Awaits Its Runs <a id="c-a-paired-arm-awaits-its-runs"></a>

- The runner can run the same fresh rows with the advisor off and on.
- The scorer pairs the two arms on each row.
- A row only one arm scored counts as unpaired.
- The first run was stopped before any scoring.
- So it gives no rate yet.

## Renamed Command

One command row has a new id. It breaks callers that match on the old id.

#### The Create-Skill Row Has a New Id <a id="c-the-create-skill-row-has-a-new-id"></a>

> [!WARNING]
> The command row `command-create-skill` is now `command-create-sk-skill`.
>
> Replace `command-create-skill` with `command-create-sk-skill` if you match on an advisor command id.

- Its slash markers are now `/create:sk-skill`.
- A typed `/create:skill` reads as `/create:sk-skill`, as Brief Commands above says.
- The rename itself is in the `sk-doc` v2.10.0.0 entry.

&nbsp;

## OpenCode Plugin

The OpenCode plugin used to push a second line with the compiled route.

#### One Head Line in the Brief <a id="c-one-head-line-in-the-brief"></a>

- The OpenCode plugin used to push a second line with the compiled route.
- Its target list printed `targets=none`, because routes now carry objects.
- The head already names the hub, its command and its policy.
- So the plugin now sends the head alone.
- The command rename has its own entry in `sk-doc` v2.10.0.0.
