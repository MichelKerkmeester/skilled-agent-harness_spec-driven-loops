# v2.0.0.0, The Embedding Lane Is Gone

The advisor no longer has an embedding lane.

- It scores every prompt with four lanes.
- The lane weights it keeps are unchanged.
- A setting can no longer turn the old lane back on.

Routing needs no model on your machine.

- The launcher no longer starts a local model server.
- The daemon no longer embeds skills, commands or prompts.
- No Skilled code loads a model any more.

Status and doctor output got smaller.

- `advisor_status` drops its embedding health fields.
- The doctor drops its embedding setup route.

> [!IMPORTANT]
> Five changes can break an existing setup. Read these before you update.
>
> 1. `advisor_status --include-semantic-health` now fails with exit `64`. [Status lists four lanes](#c-status-lists-four-lanes)
> 2. `advisor_status --include-embeddings-health` now fails with exit `64`. [Status lists four lanes](#c-status-lists-four-lanes)
> 3. `advisor_status` no longer reports embedding health or `lane_weight_zero`. [Status lists four lanes](#c-status-lists-four-lanes)
> 4. The `/doctor:skill-advisor` embedding setup route is gone. [Doctor drops the embedding setup](#c-doctor-drops-the-embedding-setup)
> 5. A lane weights setting can no longer score the removed lane. [Four lanes score every prompt](#c-four-lanes-score-every-prompt)

&nbsp;

## Why This Release

The embedding lane cost more than it gave. It needed a model server, a pulled model and a background refresh. Its default weight was `0`, so most setups paid that cost for nothing.

- The daemon kept embeddings current for a lane that scored nothing.
- Doctor checks read DEGRADED whenever no model server ran.
- Status output carried health fields most setups never used.

## Scoring

The scorer turns each prompt into a ranked list of skills. It now fuses four lanes and no longer embeds anything.

#### Four Lanes Score Every Prompt <a id="c-four-lanes-score-every-prompt"></a>

> [!WARNING]
> A lane weights setting can no longer turn the removed lane on. Drop its key from `SPECKIT_ADVISOR_LANE_WEIGHTS_JSON`.

- The lanes are explicit author, lexical, skill graph and derived metadata.
- Their weights stay `0.42`, `0.28`, `0.13` and `0.12`.
- A command row still passes on its own phrases or its slash string.
- A lane weights setting that names the removed lane is ignored.

#### The Model Server Is Gone <a id="c-the-model-server-is-gone"></a>

- The launcher no longer starts, watches or stops a local model server.
- It no longer passes model server or embedding refresh settings to the daemon.
- The daemon no longer embeds at start, on a scan or after a reindex.
- The shared embeddings package left `system-spec-kit` with the server, and the embedding provider setting went with it.
- The transformers package left the advisor and `system-spec-kit` manifests.
- The `sharp` and `protobufjs` version pins went with it, since nothing else installs those packages.

#### Named MCPs and Browser Tests Keep Their Owners <a id="c-named-mcps-and-browser-tests-keep-their-owners"></a>

- A prompt that names an MCP goes to that MCP's owner.
- "aside mcp through Code Mode" used to rank `mcp-code-mode` first.
- The Code Mode bonus now skips a prompt that names another server as `<name> mcp`.
- "fix the flaky browser automation test" used to go to the browser hub.
- A new `automation test` anchor hands that prompt to `sk-code`.
- Browser automation requests still route to `mcp-browser-use`.

## Status and Doctor

The status tool and the doctor routes report on the advisor. They no longer report on a lane that is gone.

#### Status Lists Four Lanes <a id="c-status-lists-four-lanes"></a>

> [!WARNING]
> `advisor_status --include-semantic-health` now fails with exit `64`.
> `advisor_status --include-embeddings-health` now fails with exit `64`.
> Remove both flags from any script that passes them.
> Scripts that read `lane_weight_zero` or embedding health find neither.

- `advisor_status` lists the four lane weights.
- It no longer carries an embedding health block or `lane_weight_zero`.
- The refusal names the flag it refused.
- The CLI prints `"exitCode": 64` for either flag.

#### Doctor Drops the Embedding Setup <a id="c-doctor-drops-the-embedding-setup"></a>

> [!WARNING]
> The `/doctor:skill-advisor` embedding setup route is gone. Remove it from any runbook that calls it.

- `/doctor:skill-advisor` now lists six targets.
- Its embedding setup route is gone.
- `/doctor:setup` runs six legs and no longer probes embedding health.
- Install steps no longer pull a model.
- Install, update, overlay and symlink runs no longer report embedding coverage.

## Advisor Database

The advisor keeps its skill graph in a local database. That database lost its embedding tables.

#### Old Databases Rebuild on Their Own <a id="c-old-databases-rebuild-on-their-own"></a>

- The database now carries schema version `2`.
- At start, a database from an older schema is deleted.
- Its journal files go with it. No copy is kept.
- The scan that runs before the daemon serves builds it again.
- A lock, read or permission error never counts as an old schema.

## Upgrade Notes

Step 1 depends on how your project holds Skilled. Step 2 is the same for everyone. The folded group applies only if you script the status tool.

#### Before You Start <a id="c-before-you-start"></a>

1. Clear what the embedding lane left on your machine. In a copied project, run `/doctor:update apply`, which runs the cleanup after its rebuild prompt. In a linked project, `/doctor:update` stops at the link. Run `node .skilled/skills/system-spec-kit/runtime/cli/retrieval/sweep-lane-residue.mjs machine` from the Skilled checkout instead. When it lists leftovers, run the same script's `apply`. Either way, it asks before deleting the pulled shared model and lists what only you can remove. Run without a terminal, `apply` keeps that model unless it gets `--shared-model delete`.
2. Run `npm ci` in `.skilled/skills/system-skill-advisor/runtime` and in `.skilled/skills/system-spec-kit`. That drops the transformers package from `node_modules`.
