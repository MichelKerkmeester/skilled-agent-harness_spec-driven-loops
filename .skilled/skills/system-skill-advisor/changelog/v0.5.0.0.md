# v0.5.0.0, Prompt-Knowledge Drift Guard Extended and Wired into CI

The prompt-quality card guard now enforces the full one-home-per-fact invariant. That invariant covers the three-layer prompt-knowledge architecture. So structural drift is caught automatically. Previously, the guard ran manually. It checked only the framework + CLEAR tables across the 5 `cli-*` cards. Its checks are structural. They cover pointer presence, table absence, registry membership and trigger membership. They are not semantic or NLP matching.

## What's New at a Glance

- **Tier-3 trigger details have one canonical home.** `check-prompt-quality-card-sync.sh` rejects any `cli-*/SKILL.md` that re-enumerates canonical escalation triggers. Each must point to the canonical card. The check catches the precedence-drift class.
- **Adopted models must have complete registry links.** An adopted model is a `model-profiles.json` entry with `recommended_frameworks`. It must have a profile and an `_index.md` row. Every profile must map back to a registry id. The check catches zero-hub-weight entries. It exempts unadopted stubs.
- **Adopted models must be reachable by name.** Every adopted model must be reachable by name in each dispatching executor's `graph-metadata.json`. This catches the model-unreachable-by-name case. One example is `qwen3.6`.
- **The guard blocks drift on commit and in CI.** `check-prompt-quality-card-sync.sh` runs as a blocking gate in `.opencode/scripts/git-hooks/pre-commit`. It runs when a prompt-knowledge surface is staged. `SPECKIT_SKIP_CARD_SYNC=1` is the bypass. `.github/workflows/prompt-card-sync.yml` runs the guard in CI.
