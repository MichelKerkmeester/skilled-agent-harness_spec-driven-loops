# v0.17.11.0, The Workflow You Named Stays First

Asking for "a deep research loop with the cli-pi executor" used to hand the route to the CLI hub, so the caller ran the executor and skipped the workflow it asked for. The advisor now keeps the named workflow first and the executor just below it. Delegation phrased around an object reaches its executor too. The parity tests give the same answer on any machine and any day.

> Spec folder: `specs/system-skill-advisor/039-executor-workflow-owner-guard` (Level 2)

&nbsp;

## What's New at a Glance

- **A named workflow outranks the executor that runs it.** When system-deep-loop or system-spec-kit has an explicit workflow match, it stays first and the CLI hub sits directly below it. A prompt that names only an executor routes as before.
- **"Delegate this refactor to codex" finds its executor.** "delegate <object> to <executor>" and "hand <object> off to <executor>" now lift the matching CLI skill. Plain prose such as "delegate the decision to the team" lifts nothing. The Python scorer gives the same answer as the TypeScript one.
- **Private skills no longer move the parity results.** The advisor's test suites clear `SPECKIT_PRIVATE_SKILL_ROOTS` for their run, so local-* skills on one machine cannot shift counts measured on a clean checkout.
- **The scorer baseline is scored at a fixed date.** A capture reads the date from `SPECKIT_EVAL_BASELINE_SCORING_DATE` or from the `capturedAt` already recorded, never from the wall clock. Recapturing on a later day no longer moves the numbers through the age discount on older skill metadata.

&nbsp;

## Upgrade

No action is needed. To measure the baseline at a new date, export `SPECKIT_EVAL_BASELINE_SCORING_DATE` before running the capture script.
