# v0.18.6.0, A question about the trigger index reaches spec-kit

A read-only question that names the trigger index now routes to `system-spec-kit`, the skill that owns the lookup. It used to end at the doctor helper.

> Spec folder: `specs/hooks-plugins-extensions/retrieval-integrations/001-sweet-search-integration/008-routing-and-release-alignment`

&nbsp;

## What's New at a Glance

- **An explain or tell prompt about the trigger index passes.** The read-only floor held every skill at 0.25 on such a prompt. With no skill passing, the doctor hand-off claimed it on the index noun alone. `readOnlyRouteAllowed` now lifts `system-spec-kit` when a read-only prompt names the trigger index.
- **Two stored prompts changed route.** "Explain which research run-output files the trigger index omits" went to the doctor helper at 0.80. It now ranks `system-spec-kit` first at 0.85. The prompt that asks how many documents a limited lookup matched does the same at 0.82.
- **Drift stays with the doctor.** A prompt that names trigger-index drift is not lifted, so "explain trigger index drift and repair it" still reaches the doctor helper.
- **Four cases cover it.** `route-gates.vitest.ts` tests the lift, the other-skill gate, the drift exception and a prompt with no index noun.
