This release delivers the advisor portion of the packets 108 and 110 auto-review uplift. Four practices from the upstream `dzianisv/opencode-plugins` auto-review package now apply to the skill internals and `system-skill-advisor.js`, moving metrics persistence to awaited asynchronous file operations and adding layered configuration while preserving bounded retention and compatibility for existing users.

> Spec folder: `.opencode/specs/skilled-agent-orchestration/108-auto-review-quick-wins-verdict-markers-logging` and `.opencode/specs/skilled-agent-orchestration/110-auto-review-stretch-config-dedup-gates` (Level 3)

## What's New at a Glance

- **Metrics persistence now uses awaited asynchronous file operations.** In `mcp-server/lib/metrics.ts`, both persistence entrypoints now await asynchronous `mkdir` and `writeFile` operations from `fs/promises`. Synchronous writes blocked the event loop on every advisor invocation, and each invocation now waits for its awaited writes to finish. A closure-scoped `dirReady = false` flag ensures the directory check runs exactly once per process. The read-then-rewrite-last-N sequence preserves bounded retention, which fire-and-forget writes could have let grow without limit between rotations. Existing files are read and rewritten through the awaited path, and the on-disk metrics format and schema are unchanged.
- **Diagnostic persistence is opt-in.** Advisor diagnostics previously flushed on every invocation, even when no one was reading them. `SKILL_ADVISOR_DEBUG=1` enables diagnostic record writes, while leaving it unset keeps diagnostic persistence disabled by default. Outcome records remain unconditional as part of the bounded-retention metrics contract.
- **The plugin now reads four configuration tiers.** Previously, `system-skill-advisor.js` read only `rawOptions`, leaving no way to override advisor behavior outside OpenCode config. It now checks `rawOptions`, the JSON file at `~/.config/opencode/plugin/system-skill-advisor.json`, seven additive `SYSTEM_SKILL_ADVISOR_*` environment-variable fallbacks and hardcoded defaults, in that order.
- **Existing configuration setups remain compatible.** Raw-options-only and environment-only setups continue to work, with `rawOptions` first in the precedence order and hardcoded defaults unchanged from v0.2.0 when neither source is used. The legacy `SPEC_KIT_PLUGIN_NODE_BINARY` variable is preserved as a backward-compatible fallback for the node-binary path, while existing environment-variable disable handling is unchanged, so users who only used that switch see no behavior change.
- **Configuration resolves before the plugin reports its options.** `configPromise` loads at module initialization, and the factory awaits it before option normalization. OpenCode receives the plugin's option surface only after configuration is fully resolved, removing the race where a synchronous factory returned before the config file finished loading.

## Upgrade

No migration required. On first invocation, the plugin discovers any pre-existing `~/.config/opencode/plugin/system-skill-advisor.json`. Set `SKILL_ADVISOR_DEBUG=1` if you want diagnostic records persisted. Leave it unset for the quiet default.
