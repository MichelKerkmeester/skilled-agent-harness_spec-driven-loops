# v2.0.3.0, one shared word no longer names a skill

Version 2.0.2.0 let the last word of a skill id name that skill, such as "doctor" for system-skilled-doctor. Ordinary words share that slot. "fix the infinite loop in this function" lifted system-deep-loop to the 0.82 floor, "update the build tooling" lifted mcp-tooling and "the mode rollout" lifted mcp-code-mode. A bare "staging" also anchored the browser hub on deploy work that has no browser in it.

&nbsp;

## What's New at a Glance

- The id noun names a skill only when the prompt shares another word with that skill too. "run the doctor update check" still reaches system-skilled-doctor; "fix the infinite loop in this function" routes nowhere.
- A bare `staging` is no longer an explicit token or a lexical hint for the browser hub. "staging site", "staging url", "staging website" and the new "staging portal" still route there.
- The browser hub no longer lists `mcp-code-mode` among its keywords, so "fix the code in the parser" stops reaching it.
- One doctor-slice control row, "my doctor update came in", shared only the word "doctor" with the doctor skill. It now routes nowhere and is re-pinned to no recommendation.

&nbsp;

## How It Was Checked

Every accuracy ratchet metric held: full corpus 161 of 196, unknown 14, holdout 49 of 63, ambiguity 21 of 24, review 25, memory save 27, delegation 22 and five false fires. No browser replay row changed between pass and fail. The full advisor suite passes except the known `system-skilled-bots` empty-description test, which failed before this change too.

&nbsp;

## Known Limitation

A task verb still expands to synonyms such as "fix" to "debug", so a prompt with two generic words can pass the 0.45 lexical anchor. "fix the container orchestration config" still lifts sk-code, mcp-code-mode and the browser hub to 0.82. That anchor is shared by every skill and is left for its own change.

&nbsp;

## Upgrade

No migration required. A request that named a skill by one shared word may now abstain, so name the skill or its domain phrase.
