# system-skill-advisor v0.5.0: Prompt-Knowledge Drift Guard Extended and Wired into CI

The prompt-quality card guard now enforces the full one-home-per-fact invariant for the three-layer prompt-knowledge architecture, so structural drift is caught automatically. Previously, it ran manually and checked only the framework + CLEAR tables across the 5 `cli-*` cards. Its checks are structural: pointer presence, table absence, registry membership and trigger membership, not semantic or NLP matching.

> Spec folder: `.opencode/specs/skilled-agent-orchestration/130-prompt-knowledge-layering/009-refine-hub-cli-connections/`

## What's New at a Glance

- **Tier-3 trigger details have one canonical home.** `check-prompt-quality-card-sync.sh` rejects any `cli-*/SKILL.md` that re-enumerates canonical escalation triggers. Each must point to the canonical card. The check catches the precedence-drift class.
- **Adopted models must have complete registry links.** An adopted model is a `model-profiles.json` entry with `recommended_frameworks`. It must have a profile and an `_index.md` row, and every profile must map back to a registry id. The check catches zero-hub-weight entries and exempts unadopted stubs.
- **Adopted models must be reachable by name.** Every adopted model must be reachable by name in each dispatching executor's `graph-metadata.json`. This catches the model-unreachable-by-name case, such as `qwen3.6`.
- **The guard blocks drift on commit and in CI.** `check-prompt-quality-card-sync.sh` runs as a blocking gate in `.opencode/scripts/git-hooks/pre-commit` when a prompt-knowledge surface is staged, with `SPECKIT_SKIP_CARD_SYNC=1` as the bypass. `.github/workflows/prompt-card-sync.yml` runs the guard in CI.
