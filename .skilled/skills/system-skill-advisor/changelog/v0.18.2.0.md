# v0.18.2.0, Docs Read in Order and Render as Written

The skill's `SKILL.md`, `ROUTER.md`, `README.md` and its references were read file by file for readability, layout and structure. No command, contract, score, baseline or source citation changed.

> Spec folder: `specs/sk-doc/066-skill-readability-refinement/012-system-skill-advisor` (Level 1)

&nbsp;

## What's New at a Glance

- **Overviews open with their purpose and when to use them.** The README's "Why This Skill Exists" is now its Purpose, its When to Use moved up beside it, and `ROUTER.md` splits who it serves from what selection draws on.
- **Packed paragraphs became lists.** The CLI fallback rules, routing-phrase sources, prompt-time plugin behavior, database path policy, freshness rules and lane-weight experiment rules now read one fact per line.
- **The skill lifecycle is a numbered sequence.** How a new skill becomes routable, from the watcher to a manual rescan, now reads as seven ordered steps.
- **The operating rules have headings.** `SKILL.md`'s Always, Never and Escalate If blocks are now subsections, and its primary contract entry is a link.
- **Purpose sections no longer repeat the intro.** The drift and tool-ids references now say why each exists, which clears the skill's two remaining render findings.
