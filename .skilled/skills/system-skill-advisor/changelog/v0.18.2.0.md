# v0.18.2.0, Docs Read in Order and Render as Written

The skill's `SKILL.md`, `ROUTER.md`, `README.md` and its references were read file by file. It looked at readability, layout and structure. No command, contract, score, baseline or source citation changed.

&nbsp;

## What's New at a Glance

- **Overviews open with their purpose and when to use them.** The README's "Why This Skill Exists" is now its Purpose. Its When to Use moved up beside it. `ROUTER.md` splits who it serves from what selection draws on.
- **Packed paragraphs became lists.** The CLI fallback rules now read one fact per line. So do the routing-phrase sources and the prompt-time plugin behavior. The database path policy, freshness rules and lane-weight experiment rules do too.
- **The skill lifecycle reads in order.** How a new skill becomes routable is three ordered steps. They run from the watcher to the reindex. The other paths follow. They are a cold start, a manual rescan and a deleted root.
- **The operating rules have headings.** `SKILL.md`'s Always, Never and Escalate If blocks are now subsections. Its primary contract entry is a link.
- **Purpose sections no longer repeat the intro.** The drift and tool-ids references now say why each exists. That clears the skill's two remaining render findings.
