# v0.17.18.0, Three Routing Gaps Closed and the Executor Guard Catalogued

Three prompts reached the wrong skill or tied at the floor. "packet-local changelog" went to system-spec-kit, "Review this change iteratively using cli-opencode as the executor" went to the CLI hub ahead of the deep-loop workflow, and "how do I turn off the automatic worktree cleanup at session start" tied sk-git with two other skills. Each now reaches its owner, and the feature catalog gains the entry that explains how a named workflow and a CLI executor are ranked.

> Spec folder: `specs/system-skill-advisor/039-executor-workflow-owner-guard` (Level 2)

&nbsp;

## What's New at a Glance

- **A packet-local changelog reaches sk-doc without an authoring verb.** The corpus-study rule read `packet-local` as study vocabulary unless a verb such as write or create governed the changelog, so sk-doc's own declared phrase and "Document a packet-local changelog" ranked system-spec-kit first. `packet-local` now counts as study vocabulary only when it qualifies something other than a changelog. A packet-local prompt template, helper or iteration keeps its route.
- **`iteratively` is a loop word.** The research-loop and review-loop checks knew `iterative` and `iterations` but not the adverb, so the workflow-owner guard never saw a deep-loop owner on an iteratively phrased review and the CLI hub took the route. The adverb now counts like `iterative`. A prompt that asks for no review or research is unaffected. The Python fallback's deep-mode scoring reads the adverb as it reads `iterate`.
- **Requests to turn off the worktree cleanup reach sk-git.** sk-git now declares `worktree cleanup`, `worktree reaper` and `numbered worktree sweep`, plus `session-start worktree cleanup` as a trigger phrase, so the turn-off phrasing no longer ties three skills at the confidence floor. The variable name `SPECKIT_WORKTREE_AUTOREAP` is not declared: its spaced form yields the word `autoreap`, which the lexical lane matches against every prompt that says "auto", and that moved "auto review this PR" off sk-code. A question that names only the variable therefore still gets no recommendation, and a prompt that starts with "explain" is still held at the read-only explainer floor for every skill.
- **The catalog describes executor delegation.** A new scorer-fusion entry covers the resolver, split handoffs such as "delegate this refactor to codex", the 0.95 lift and the workflow-owner guard, and says that the Python fallback mirrors the resolver but not the guard.

&nbsp;

## Upgrade

No action is needed. The daemon reindexes sk-git's metadata on its own and serves the new scorer once `dist/` is rebuilt.
