# v0.17.18.0, Three Routing Gaps Closed and the Executor Guard Catalogued

Three prompts reached the wrong skill or tied at the floor. "packet-local changelog" went to system-spec-kit. "Review this change iteratively using cli-opencode as the executor" went to the CLI hub. The CLI hub ranked ahead of the deep-loop workflow. "how do I turn off the automatic worktree cleanup at session start" tied sk-git with two other skills. Each now reaches its owner. The feature catalog gains the entry that explains how a named workflow and a CLI executor are ranked.

> Spec folder: `specs/system-skill-advisor/039-executor-workflow-owner-guard` (Level 2)

&nbsp;

## What's New at a Glance

- **A packet-local changelog reaches sk-doc without an authoring verb.** The corpus-study rule read `packet-local` as study vocabulary. It did so unless a verb such as write or create governed the changelog. So sk-doc's own declared phrase ranked system-spec-kit first. So did "Document a packet-local changelog". `packet-local` now counts as study vocabulary only when it qualifies something other than a changelog. A packet-local prompt template, helper or iteration keeps its route.
- **`iteratively` is a loop word.** The research-loop and review-loop checks knew `iterative` and `iterations`. They did not know the adverb. So the workflow-owner guard never saw a deep-loop owner on an iteratively phrased review. The CLI hub took the route. The adverb now counts like `iterative`. A prompt that asks for no review or research is unaffected. The Python fallback's deep-mode scoring reads the adverb as it reads `iterate`.
- **Requests to turn off the worktree cleanup reach sk-git.** sk-git now declares `worktree cleanup`, `worktree reaper` and `numbered worktree sweep`. It also declares `session-start worktree cleanup` as a trigger phrase. So the turn-off phrasing no longer ties three skills at the confidence floor. The variable name `SPECKIT_WORKTREE_AUTOREAP` is not declared. Its spaced form yields the word `autoreap`. The lexical lane matches that word against every prompt that says "auto". That moved "auto review this PR" off sk-code. A question that names only the variable therefore still gets no recommendation. A prompt that starts with "explain" is still held at the read-only explainer floor for every skill.
- **The catalog describes executor delegation.** A new scorer-fusion entry covers the resolver. It covers split handoffs such as "delegate this refactor to codex". It covers the 0.95 lift and the workflow-owner guard. It says that the Python fallback mirrors the resolver but not the guard.

&nbsp;

## Upgrade

No action is needed. The daemon reindexes sk-git's metadata on its own. It serves the new scorer once `dist/` is rebuilt.
