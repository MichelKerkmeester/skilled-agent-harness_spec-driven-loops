# v0.17.12.0, Typed Doctor Targets and Run Requests Route Where They Belong

Three routing faults sent a clear request to the wrong place or to nothing. A typed doctor target lost to its bare default on the fallback path, a request that asked to run or switch something off and then show the result was treated as a read-only question, and a release request that tags found no skill.

> Spec folder: `specs/sk-code/015-quality-agnostic-gate/011-alignment-fixes` (Level 2)

&nbsp;

## What's New at a Glance

- **A typed doctor target wins over its bare default.** `/doctor:ci toggle`, `/doctor:ci scaffold`, `/doctor:git standards` and `/doctor:sk-code quality` now rank their own target first when the advisor answers from its fallback scorer, because a marker that contains the current match replaces it. The bare `/doctor:ci` still lands on the report, and a prompt that types two separate commands keeps the first one.
- **A run or switch-off request is treated as work.** A prompt such as "run the quality gate and tell me which checks fail" or "turn off the nightly CI workflow, then show me" now gets a recommendation instead of the read-only floor. `run`, `rerun`, `execute`, `turn on`, `turn off`, `switch on`, `switch off`, `enable` and `disable` now count as write verbs.
- **A release that names a tag reaches sk-git.** "Cut a release: tag the version and push the tag" now routes to sk-git, because a release action next to a tag anchors the git skill. The bare word `release` anchors nothing, so "update skilled to the latest release" keeps its own route. A tag counts only as a git tag, a tag push, "tag it" or a version number such as v2.3.0, and release notes, a release blog post or a release announcement are not a release action, so "publish the release blog post with tags for SEO" stays off sk-git.

&nbsp;

## Upgrade

No action is needed. Rebuild the advisor runtime so the daemon serves the new scorer.
