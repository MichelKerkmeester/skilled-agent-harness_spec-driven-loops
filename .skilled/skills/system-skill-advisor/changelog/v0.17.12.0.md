# v0.17.12.0, Typed Doctor Targets and Run Requests Route Where They Belong

Three routing faults sent a clear request to the wrong place. Some sent it to nothing. A typed doctor target lost to its bare default on the fallback path. A request asked to run or switch something off, then show the result. It was treated as a read-only question. A release request that tags found no skill.

&nbsp;

## What's New at a Glance

- **A typed doctor target wins over its bare default.** `/doctor:ci toggle`, `/doctor:ci scaffold`, `/doctor:git standards` and `/doctor:sk-code quality` now rank their own target first. That happens on the advisor's fallback scorer. That is because a marker that contains the current match replaces it. The bare `/doctor:ci` still lands on the report. A prompt with two separate commands keeps the first one.
- **A run or switch-off request is treated as work.** One prompt asks to "run the quality gate and tell me which checks fail". It now gets a recommendation. So does "turn off the nightly CI workflow, then show me". Both now skip the read-only floor. `run`, `rerun`, `execute`, `turn on`, `turn off`, `switch on`, `switch off`, `enable` and `disable` now count as write verbs.
- **A release that names a tag reaches sk-git.** One request asks to "Cut a release: tag the version and push the tag". It now routes to sk-git. That is because a release action next to a tag anchors the git skill. The bare word `release` anchors nothing. So "update skilled to the latest release" keeps its own route. A tag counts only as a git tag, a tag push or "tag it". A version number such as v2.3.0 also counts. Release notes are not a release action. Neither is a release blog post or a release announcement. So "publish the release blog post with tags for SEO" stays off sk-git.

&nbsp;

## Upgrade

No action is needed. Rebuild the advisor runtime so the daemon serves the new scorer.
