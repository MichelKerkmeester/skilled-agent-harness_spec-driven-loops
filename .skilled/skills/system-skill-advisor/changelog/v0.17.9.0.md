# v0.17.9.0, The Plugin Trusts Only a Verified Private Link

The plugin reads sk-code surface declarations from every skill in the skills root to pick a session's surface hint. It followed any link there, so a `local-*` link into an undeclared folder could add a surface that outranks SKILLED. It now applies the same trusted-root rule as the advisor's other readers.

> Spec folder: `specs/sk-code/013-private-surface-skills/009-alignment-fixes` (Level 2)

&nbsp;

## What's New at a Glance

- **A private link counts only when its target is trusted.** The reader keeps real skill folders and a `local-*` link whose real target lies inside the skills root or a folder named in `SPECKIT_PRIVATE_SKILL_ROOTS`. It loads that rule from `runtime/lib/private-skill-target.cjs`, and when the module cannot load it rejects every link and writes one stderr line.
- **The trusted-root rule loads on every supported Node version.** It moved into the plain CommonJS module `runtime/lib/private-skill-target.cjs`, which `private-skill-target.ts` wraps with types, so readers outside the runtime no longer depend on TypeScript stripping, which Node 20 lacks.
- **Requests about private skill roots reach the advisor.** Five phrases and one topic about private, git-ignored skill roots join `graph-metadata.json`, so such a request no longer ties with sk-git on its git words.

&nbsp;

## Upgrade

Declare a private skill's target folder in `SPECKIT_PRIVATE_SKILL_ROOTS` when it lives outside the skills root, or the plugin ignores its surface. Then run `node .skilled/bin/skill-advisor.cjs advisor_rebuild --trusted --force true`.
