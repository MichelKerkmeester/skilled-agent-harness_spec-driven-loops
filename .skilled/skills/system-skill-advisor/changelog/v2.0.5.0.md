# v2.0.5.0, a scan of one skill keeps the rest

One advisor bug erased more than it touched. A scan of one skill folder wiped every other skill from the graph. Several shared stores trusted any path, and nobody checked its owner. This release fixes both, then clears the code nothing called.

&nbsp;

## What's New at a Glance

- A scan of one skill folder keeps every other skill in the graph. It deletes only the nodes under the folder it scanned.
- The CLI and the launcher check who owns a socket before they connect. The metrics, shadow, calibration and route-receipt stores share one folder check. It refuses a symlink or a folder owned by another user. The write is skipped instead of crashing. On Windows the check reads ACLs, not mode bits.
- The TypeScript scorer and the Python fallback agree on 24 shared cases. One fixture pins both to the same answers. A new test pins the scoring stage order. The word `review` now counts as task intent, so a review prompt reaches `sk-code`.
- The Python fallback warns and keeps going when its policy file is missing or malformed.
- Supersession, schema migration and part of rollback are gone. The catalog drops 3 entries and the playbook 2. Docs now describe the launcher's trusted default as it is.
- Four helpers with no production caller are gone. They are `lib/compat/redirect-metadata.ts`, `lib/lifecycle/rollback.ts`, `sanitizeEnvelopeSkillLabel` and `filterDefaultRoutable`. Their tests and doc rows went too.
- The advisor stress workflow now runs on a hooks-only pull request.

&nbsp;

## How It Was Checked

The advisor suite passes with 3201 tests and 4 skipped. A one-skill scan on a database copy kept 15 nodes and 59 edges. Before, it left 1 node. The catalog reads 44 features and the playbook 53 scenarios.

&nbsp;

## Upgrade

No migration required.
