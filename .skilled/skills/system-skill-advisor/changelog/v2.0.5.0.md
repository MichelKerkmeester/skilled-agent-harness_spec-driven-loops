# v2.0.5.0, a scan of one skill keeps the rest

One advisor bug erased more than it touched. A scan of one skill folder wiped every other skill from the graph. Several shared stores trusted any path, and nobody checked its owner. This release fixes both, then removes features nothing used.

&nbsp;

## What's New at a Glance

- A one-skill scan now deletes only the nodes under the folder it scanned.
- The CLI and the launcher check who owns a socket before they connect.
- Four shared stores skip writes to a symlinked or foreign-owned folder, on Windows too.
- A `review` prompt now reaches `sk-code` as task intent.
- The Python fallback warns and runs on without a valid policy file.
- The unused supersession, schema-migration and partial rollback features are gone.
- The advisor stress workflow now runs on a hooks-only pull request.
- Six doctor commands now credit `system-skilled-doctor` in the brief, as in `use system-skilled-doctor → /doctor:git hooks (ask)`.
- The command-routing baseline counts a hub's own command offer as owner-led.

&nbsp;

## How It Was Checked

The advisor suite passes with 3201 tests and 4 skipped. The Python fallback matches the main scorer on 24 shared cases. A new test pins the order of the scoring stages. One run scanned one skill on a database copy. It kept 15 nodes and 59 edges. Before, it left 1 node.

&nbsp;

## Upgrade

No migration required.
