# v2.1.2.0, Merged Fan-Out Reviews Keep Their Coverage

A review that fans out to several lineages used to lose the coverage each lineage had recorded when the results were merged. The merge now carries those surfaces through, so the merged review shows what every lineage covered.

&nbsp;

## What's New at a Glance

- Dimension coverage is a union. `dimensionCoverage` holds every dimension the lineages covered, with sorted keys.
- Traceability keeps the strictest status. `fail` beats `blocked`, then `partial`, `pass` and `notApplicable`. An undecided status never replaces a decided one.
- Search and candidate coverage are merged. `searchCoverage` holds sorted unions, and each `candidateCoverage` bucket lists the lineages that reported it.
- Divergence stays per lineage. `divergenceByLineage` keeps each lineage's pivot state under its label. No merged `divergence` is written.
- Ruled-out candidates name their lineage. Each entry carries a `lineage` field and is deduplicated on lineage and id.
- The merge is order-independent. Lineages are read in label order, so arrival order never changes the result.

&nbsp;

## Upgrade

No migration required. This release adds the data only. No stop decision reads these surfaces yet.
