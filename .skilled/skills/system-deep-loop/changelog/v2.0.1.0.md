# v2.0.1.0, The Post-Dispatch Gate Checks Executor Identity

The gate every review and research iteration passes, `verify-iteration.cjs`, now fails a non-native iteration whose state log names no executor. Since `v1.6.27.0` the executor survives in the state log, and this release makes the workflows notice when it is missing.

&nbsp;

## What's New at a Glance

- **A missing executor fails the iteration.** When the run's config names a non-native executor and neither the iteration record nor an `iteration_start` row of that iteration carries an `executor` object, the gate exits with `executor_missing`.
- **The kind comes from the run config.** The gate reads `executor.kind` from `deep-review-config.json` or `deep-research-config.json`, so no workflow step passes a new argument.
- **Native and unconfigured runs pass.** A native executor, a missing config and a config with no executor block are never checked.
- **Fan-out lineages are exempt.** A lineage runs its iterations inline without the pre-dispatch audit, so the gate skips it when `SPECKIT_FANOUT_LINEAGE_ID` is set, the config marks a lineage or the artifact folder sits under `lineages/`.
- **The hub reads v2.0.1.0.** Four routing files carry the new version.

&nbsp;

## Upgrade

No migration is required. An iteration recorded before `v1.6.27.0` under a non-native executor names no executor, so checking it again now fails with `executor_missing`. The gate runs on each new iteration, so a running loop is not affected.
