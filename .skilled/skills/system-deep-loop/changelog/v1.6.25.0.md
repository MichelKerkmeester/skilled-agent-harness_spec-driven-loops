# v1.6.25.0, A One-Lineage Fan-Out Is Refused

A chat session started a deep-research loop by calling the fan-out runner with one lineage. One process then wrote every iteration. The packet's lock, init and save steps never ran. Nothing reported it. The runner now refuses that call and names the workflow to use.

> Spec folder: `specs/system-speckit/spec-authoring-and-continuity/005-goldfish-cold-read-plan-review`

&nbsp;

## What's New at a Glance

- **A one-lineage fan-out is refused.** `fanout-run.cjs` exits 3 before it makes a folder or starts a process. The message names the single-executor `/deep:research` or `/deep:review` workflow.
- **One flag keeps the direct route open.** `--allow-single-lineage` runs one lineage on purpose. The flag alone counts, and so do the values `true` and `1`. Any other value is refused.
- **A one-entry `--executors` matrix runs the single-executor path.** The docs used to send every `--executors` value to fan-out. One lineage now sets `config.executor`. Two or more set `config.fanout`.
- **The docs say what an iteration count sets.** In a one-entry matrix the `iterations` value becomes `config.maxIterations`.
- **The review workflow checks a Claude config directory.** Its single-executor branch passed a caller's directory straight into the environment. It now runs the check fan-out already ran. Only `~/.claude*` or a `.claude*` folder in the repository passes, written with `~` or as the full path.
- **The refusal reads the runner's own list of loop types.** A loop type added later is covered without a second edit.

&nbsp;

## Upgrade

No migration required for `/deep:research` or `/deep:review`. A script that calls `fanout-run.cjs` with one lineage must add `--allow-single-lineage`. The DeepSeek Harness re-pin runbook already passes it. A count above 1 still makes a fan-out, so `--count=2` is not refused. Each lineage of a real fan-out still runs its iterations in one process.
