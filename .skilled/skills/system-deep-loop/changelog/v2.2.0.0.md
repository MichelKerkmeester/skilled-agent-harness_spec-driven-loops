# v2.2.0.0, Blocked Runs Stop and Every Executor Builds One Way

A run no longer spins on the same blockers.

- The same blocker set, pass after pass, now ends the run.
- A failed research quality guard now blocks and writes its row.

Fan-out budgets and sandbox reports now agree with the run.

- A defaulted fan-out takes its budget from one table.
- Sandbox reports now name what each lineage really runs.

Single-iteration dispatch builds every kind one way.

- Claude and codex now build through the fan-out builder.
- Claude logs `stream-json` and writes its cost beside the iteration.

> [!IMPORTANT]
> Three changes can alter an existing run. Read these before you update.
>
> 1. A research pass whose quality guards fail now returns `BLOCKED`, not `CONTINUE`. [A failed research guard now blocks](#c-a-failed-research-guard-now-blocks)
> 2. Single-iteration codex with no model now runs the runtime default, not your codex config default. [Unset models use the default](#c-unset-models-use-the-default)
> 3. A finished DeepSeek Harness lineage that asked for `danger-full-access` is refused once on rerun. [A narrowed DeepSeek sandbox is reported](#c-a-narrowed-deepseek-sandbox-is-reported)

&nbsp;

## Why This Release

Runs and their reports had drifted apart. A blocked run had no exit of its own. A fan-out could carry three budgets at once.

- The same blockers could hold a run until its iteration cap.
- A failed research guard wrote no row, so nothing counted it.
- The seed step, the root config and each lineage each had a budget.
- A DeepSeek lineage claimed a sandbox mode it never ran.
- Claude and codex were built by hand, apart from every other kind.

## Stop Decision

The stop decision now gives a blocked run its own exit. The blocked-stop rows it reads also match what each loop has.

#### Repeated Blockers End the Run <a id="c-repeated-blockers-end-the-run"></a>

- The loop counters build a blocked streak from the `blocked_stop` rows.
- The same sorted blocker key adds one, and a new key restarts at one.
- A review pass resets it by recording a new finding.
- A research pass resets it with an insight or a high new-information ratio.
- At the stuck threshold the decision is `STOP` with reason `blockedStop`.
- Review stops at 2 and research at 3, with detail `blockedStreakReached`.
- The iteration cap and stuck recovery still run first.
- Under expansive depth the streak is per run, the stuck count per node.

#### A Failed Research Guard Now Blocks <a id="c-a-failed-research-guard-now-blocks"></a>

> [!WARNING]
> A research pass whose quality guards fail now returns `BLOCKED` with detail `qualityGuardFailed`. Expect the run to stop once the same guards keep failing.

- Before, the pass returned `CONTINUE` and wrote no row.
- It now writes the existing `blocked_stop` row.
- The review ledger accepts `blockedStop` as a terminal stop reason.
- Both workflows carry it to the terminal row and the synthesis reason.

#### Blocked-Stop Rows Tell the Truth <a id="c-blocked-stop-rows-tell-the-truth"></a>

- A review row's adjudicated count is P0 and P1 findings minus missing packets.
- Before, it copied the candidate count.
- Research rows drop the hotspot saturation gate the research loop lacks.

## Fan-Out

The fan-out runner now writes one budget. Its sandbox reports name what each lineage runs. A flooded lineage now fails.

#### One Table Sets a Defaulted Budget <a id="c-one-table-sets-a-defaulted-budget"></a>

- The runner writes the root config's `maxIterations` as the largest lineage cap.
- It computes that from the full matrix, before any lineage spawns.
- It writes nothing under `--preview` or an explicit `--max-iterations`.
- It never creates a missing root config.
- It prints one line on stderr, such as this one.
- `[fanout-run] budget table: L1 6, L2 6 iterations; root maxIterations 6, the largest lineage cap`
- A defaulted seed no longer reports a whole-seed budget.

#### A Narrowed DeepSeek Sandbox Is Reported <a id="c-a-narrowed-deepseek-sandbox-is-reported"></a>

> [!WARNING]
> A DeepSeek Harness lineage that asked for `danger-full-access` and finished under the old report is refused once on rerun as `finished_lineage_mismatch`. Its recorded sandbox mode no longer matches. Rerun that fan-out with `--restart`, which archives the packet and starts a fresh session.

- A DeepSeek lineage asked for `danger-full-access` runs `workspace-write`.
- Its report claimed full access before, with no enforcement.
- It now reports `workspace-write`, preventive enforcement and `sandboxNarrowedFrom`.
- The command line itself is unchanged.

#### Stdout Overflow Fails the Lineage <a id="c-stdout-overflow-fails-the-lineage"></a>

- Before, output past the 20 MB cap was cut without a word.
- A child killed for it read as timed out and was retried.
- A child that exited 0 passed on cut output.
- The result now carries an `ENOBUFS` error naming the cap.
- The verdict checks it first, so the lineage fails without a retry.

<details>
<summary><b>Smaller fixes</b></summary>

- A Claude lineage reports its permission gate as `compensating`, not preventive.
- Under `bypassPermissions` it reports `none`.
- The window check and salvage judge a claimed stamp by one rule.
- A string claim is judged, and anything else falls back to the gateway time.
- An untimed Claude log with no `tool_use` block counts as a pass with no tool call.
- Before, one dead attempt made every pass of the next one read as unknown.

</details>

## Dispatch

Single-iteration dispatch now builds Claude and codex like the other kinds. One helper replaces four copies of the same setup.

#### Claude Builds Like Every Kind <a id="c-claude-builds-like-every-kind"></a>

- Claude runs through the same containment path as every other kind.
- Its stdout stays off the terminal, and it logs `stream-json`.
- Its session cost lands in `iterations/iteration-NNN.cost.json`.
- The audited runner calls a new `onStdout` callback once per child.
- It runs whatever the exit status.
- Single-iteration Claude now has the write-containment report.
- With no sandbox mode set, it records `workspace-write`.

#### Unset Models Use the Default <a id="c-unset-models-use-the-default"></a>

> [!WARNING]
> Single-iteration codex with no model now runs the runtime's default codex model, not the default in your codex config. Set a model to keep your own.

- A null Claude model resolves to the default, not the string `"null"`.
- A missing binary now throws an `INPUT_VALIDATION` usage error.
- That happens before any receipt is written.
- Before, codex returned 1 and Claude spawned and recorded a crash.

#### Tool Output No Longer Reads as a Halt <a id="c-tool-output-no-longer-reads-as-a-halt"></a>

- With JSON events on stdout, a tool result could mention quota.
- The unavailability check read that as a halt.
- A JSON line now counts only when it is shaped as an error.
- Plain-text lines keep the word match.

&nbsp;

## Ledger

The append gateway now mints every identity field a row could fake. It applies the same rule on every branch.

#### The Gateway Mints Every Stream Field <a id="c-the-gateway-mints-every-stream-field"></a>

- Before, the stem and `event_type` branches read the raw row.
- A row could name its own stream id, sequence, correlation and causation.
- The strip list now covers those fields and recording time, in both spellings.
- Recorded time always comes from the gateway clock.
- Stem and `event_type` rows keep a caller-named event id and key.
- The reducer and review workflow name them so a re-emitted row matches.

## How It Was Checked

The contract drift check prints `OK commands=2` on the final tree. The review contract snapshot check passes too. This round has no separate runtime, deep-research or deep-review entry.

#### Before and After <a id="c-before-and-after"></a>

| Check | Before | After |
|---|---|---|
| Same blocker set at the stuck threshold | ran to its cap | `STOP` with `blockedStop` |
| Research pass with failed quality guards | `CONTINUE`, no row | `BLOCKED`, `blocked_stop` row |
| Defaulted expansive fan-out budget | three budgets that could disagree | one table, one summary line |
| DeepSeek lineage asked for full access | reported `danger-full-access` | `workspace-write` with `sandboxNarrowedFrom` |
| Lineage stdout past 20 MB | timed out and retried | `ENOBUFS`, failed, no retry |
| Single-iteration dispatch, missing binary | returned 1 or recorded a crash | `INPUT_VALIDATION` usage error |

## Upgrade Notes

Most runs need no action. Codex users and finished DeepSeek runs may.

#### Before You Start <a id="c-before-you-start"></a>

1. If you dispatch single-iteration codex without a model, set one to keep your codex config's default.
2. If a DeepSeek Harness fan-out that asked for `danger-full-access` finished before this update, rerun it with `--restart`. That archives the packet.
