# v1.6.24.0, Fan-Out Names Quota Failures and Takes a Review Target

A fan-out run that lost a lineage to an exhausted provider quota reported a plain exit, and every review lineage was told to review the spec folder whatever the operator asked for. Both are fixed, along with six smaller defects an audit of the changes since v4.0.1.0 found.

&nbsp;

## What's New at a Glance

- **A quota refusal is its own failure class.** The runner reads a failed lineage's stderr and the tail of its stdout for the provider's refusal, keeps that wording in the failure message and counts the lineage under `quota` in the summary. The class is fatal, because the same account answers the same way on retry.
- **A review fan-out can name its target.** `fanout-run.cjs` takes `--review-target` and `--review-target-type`, and both review workflows pass the bound target through. The spec folder stays the default target and the owner of every write.
- **A Codex effort above the model's ceiling is rejected.** `gpt-5.5` stops at `xhigh` and `gpt-6-luna` at `max`. A higher effort now fails at configuration with a message that names the ceiling, not at the provider.
- **A corrected review attempt shows once.** The dashboard kept the numeric iteration when it deduplicated, so a second attempt at the same iteration no longer adds a row. The review workflows take the resume ordinal from that same number.
- **The harness executor is labelled fan-out only.** The executor help says so and shows an invocation that works. The exit message no longer suggests a flag that does not exist.
- **Help text matches behavior.** The council setup calls its mode a label and names the executor kind as what routes. The research protocol calls a low average novelty ratio a stop candidate, subject to the stop policy and the quality gates.
- **Per-lineage steering is documented.** The scripts README shows a `steer.md` that gives one lineage its own angle.
- **One unused export is gone.** `EXPERIMENTAL_EXECUTOR_KINDS` gated nothing and was removed.

&nbsp;

## Upgrade

No migration required. A caller that reads `summary.failure_classes` sees one more key, `quota`. A saved Codex configuration that pairs `gpt-5.5` with `max` or `ultra` now fails at configuration and needs its effort lowered to `xhigh`.
