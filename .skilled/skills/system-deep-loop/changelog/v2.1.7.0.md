# v2.1.7.0, The Expansive Frontier Runtime and Its Routing

Expansive depth mode shipped in the mode changelogs, deep-research v1.16.0.0 and deep-review v1.13.0.0. The shared runtime behind it had no hub entry. This entry records it, with the routing words that reach it.

&nbsp;

## What's New at a Glance

- **`runtime/scripts/frontier-admit.cjs` owns the frontier node store.** It seeds depth-1 nodes and admits or prunes proposals. It also closes nodes, renders the prompt block and projects the graph.
- **Admission runs six checks in a fixed order.** They are relevance, dedupe, depth, fan-out, budget and cycle. A pruned proposal names the check that failed.
- **A pruned node stays pruned.** A close can no longer revive it as live work.
- **Review scope files may come as named lists.** Admission reads one list or one list per kind, as the terminal gates do.
- **The stop decision gains a frontier veto.** `convergence.cjs` turns a stop candidate into `CONTINUE` with `frontierOpen` while a node stays open.
- **A drained frontier can stop a review.** With every node closed and one answered, the review gets the `frontier_drained` candidate.
- **Fan-out deals the seeded nodes round-robin.** `fanout-run.cjs` gives each lineage its share and its own store. It sizes each unsized lineage from that share.
- **`fanout-merge.cjs` merges the lineage frontiers.** A partition guard names any dealt node no lineage reports.
- **Both reducers report a torn store row.** The row is skipped, and the reducer prints its file and line.
- **An extension's ceiling must match its run.** The ledger refuses a `run_extended` event whose new cap is not the continued run plus the added iterations.
- **Expansive-depth requests route to the hub.** The research aliases gained "this research run" and the follow-up question frontier phrasings. The review aliases gained "review target" and "sub-targets". The advisor gained "depth-capped frontier".

&nbsp;

## How It Was Checked

The frontier, stop-decision, fan-out, ledger and reducer suites pass. The golden tests keep a default run's output byte for byte.

&nbsp;

## Upgrade

No migration required. The frontier code runs only under `--depth-mode=expansive`. The extension check applies to every run. The extend step already writes a matching ceiling.
