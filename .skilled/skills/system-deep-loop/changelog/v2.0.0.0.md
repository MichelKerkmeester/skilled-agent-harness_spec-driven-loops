# v2.0.0.0, The Planning Council Leaves the Hub

The deep-loop hub ran three modes: research, review and a planning council. The council never ran as a loop the way the other two do. One agent convenes its seats in one round, and nothing iterates to convergence. It now runs as the standalone `@ai-council` agent, and the hub keeps the two modes that are loops.

&nbsp;

## Why This Release

A council request used to route into `system-deep-loop`, load a mode packet of 139 files and run a workflow built for iteration. The agent that did the work needed none of that. Keeping the mode meant every hub surface, the contract compiler and the advisor carried a third case. Removing it leaves one command and one agent for a council, and a hub whose every mode stops for a reason a script computes.

&nbsp;

## What's New at a Glance

- **The hub routes two modes.** `research` and `review` remain. A council prompt now defers at the hub. <!-- section: Hub Routing -->
- **`/deep:ai-council` is gone.** Use `/speckit:ai-council`, which binds the spec folder and dispatches `@ai-council` once. <!-- section: Commands -->
- **The advisor offers the new command.** Council wording no longer scores for the hub. <!-- section: Advisor -->
- **The council loop type left the runtime.** The scripts accept `research`, `review` and `context`, and the council graph, ledger and reducer libraries are deleted. <!-- section: Runtime -->

&nbsp;

## Hub Routing

#### Two Modes in Every Routing Surface

The mode registry, the hub router, the root `ROUTER.md`, the graph metadata and the command metadata listed `ai-council` as a third mode. All five now list `research` and `review`. The `council` loop type left the registry with it. The leaf manifest and the compiled routes were regenerated from those files.

**Breaking:** the `ai-council` workflow mode and the `deep-ai-council` packet no longer exist. A script or doc that names `system-deep-loop/deep-ai-council/` points at nothing. The packet's 20 changelog entries stay at `.skilled/changelog/system-deep-loop/deep-ai-council/`.

#### The Pivot Seats Stay

A stalled research or review run can still convene pivot seats through the divergent pivot. That feature reads `runtime/lib/council/multi-seat-dispatch.cjs`, which is unchanged.

#### Smaller Fixes

- **The shared benchmark runner covers two modes.** The `seat_artifacts` evidence kind and the `ACB` scenario prefix are removed from `shared/behavior-benchmark`.
- **The hub playbook lists 11 scenarios.** Three council-only scenarios are deleted, and the totals are recounted.

&nbsp;

## Commands

#### One Council Command

**Breaking:** `/deep:ai-council` is removed with its two workflow files, its compiled contract and its mirrors in every runtime folder. Run `/speckit:ai-council <question> [:auto|:confirm] [--spec-folder=PATH]` instead. It writes under the bound packet's `ai-council/` folder, as before.

#### The Contract Compiler Knows Two Commands

`compile-command-contracts.cjs` and `render-command-contract.cjs` accept `deep/research` and `deep/review`. The in-CLI seat branch that only the council used is removed, and both remaining contracts are recompiled.

&nbsp;

## Advisor

#### Council Wording Reaches the Command

The scorer boosted the hub for phrases such as "ai council" and "planning council". Those lanes competed with the `/speckit:ai-council` row, and both dropped to a confidence of 0.25. The lanes are removed from the TypeScript scorer and the Python router. A prompt that asks to convene a council is also lifted off the read-only floor, because the question a council compares is not itself a read-only request.

```text
convene an ai council to compare three migration plans
  -> command-speckit-ai-council, confidence 0.84, /speckit:ai-council
```

&nbsp;

## Runtime

#### No Council Loop Type

**Breaking:** `convergence.cjs`, `upsert.cjs`, `query.cjs` and `status.cjs` reject `--loop-type council`, and `convergence.cjs` drops the `--round-id` flag that only that branch read. The council graph, convergence, scoring, cost-guard and round-state libraries are deleted with the council ledger, reducer and sealed-artifact libraries, their tests and their fixtures. `runtime/lib/council/` keeps `multi-seat-dispatch.cjs`, which the divergent pivot calls.

#### Smaller Fixes

- **`/doctor:deep-loop` takes `--scope=research|review|both|all`.** The `council` scope is removed.
- **`runtime/database/council-graph.sqlite` stays on disk.** No script reads or writes it.
- **Callers outside the hub follow.** The CLI bridge docs, the root README, the spec-kit command index and the Gate 3 resume phrases name `/speckit:ai-council`. The plugin guard fixtures register two modes.

&nbsp;

## How It Was Checked

#### Before and After

| Check | Before | After |
|---|---|---|
| Modes in `mode-registry.json` | `research review ai-council` | `research review` |
| `node runtime/scripts/check-contract-drift.cjs` | `OK commands=3` | `OK commands=2` |
| `node runtime/scripts/convergence.cjs --loop-type council` | a council convergence verdict | `INPUT_VALIDATION`, `loopType must be "research", "review", or "context"` |
| Hub route for "run deep research on the caching options" | `deep-research` | `deep-research` |
| Hub route for "convene an ai council to compare three migration plans" | the `ai-council` mode, through its alias class | defer |
| Advisor for the same council prompt | hub and command both at 0.25, nothing offered | `/speckit:ai-council` at 0.84 |

#### Tests and Scenarios

- **The per-hub gate passes with the hub path.** `parent-skill-check.cjs` prints `declares 2 modes`.
- **The compiled-route guard reports every hub fresh.** Seven hubs resolve.
- **The scorer baseline moved on one metric.** Two council rows left the holdout, so holdout top-1 went from 50 of 66 to 49 of 64. Every other metric is unchanged.

&nbsp;

## Upgrade Notes

- **Anyone who ran `/deep:ai-council`:** run `/speckit:ai-council` with the same question.
- **Docs or scripts that name the `ai-council` mode or the `deep-ai-council` packet:** point them at `.skilled/agents/ai-council.md` or the new command.
- **Research and review:** no upgrade needed.
