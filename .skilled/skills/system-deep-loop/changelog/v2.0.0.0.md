# v2.0.0.0, The Planning Council Leaves the Hub

The deep-loop hub ran three modes: research, review and a planning council.

- The council never ran as a loop the way the other two do.
- One agent convenes its seats in one round.
- Nothing iterates to convergence.

The council now runs outside the hub.

- It runs as the standalone `@ai-council` agent.
- The hub keeps the two modes that are loops.

> [!IMPORTANT]
> 3 changes can break an existing setup.
>
> 1. The `ai-council` mode and the `deep-ai-council` packet no longer exist. [Two Modes in Every Routing Surface](#c-two-modes-in-every-routing-surface)
> 2. `/deep:ai-council` is removed. [One Council Command](#c-one-council-command)
> 3. The scripts reject `--loop-type council`. [No Council Loop Type](#c-no-council-loop-type)

&nbsp;

## Why This Release

A council request used to route into `system-deep-loop`. It used to load a mode packet of 139 files and run a workflow built for iteration.

- The agent that did the work needed none of that.
- Keeping the mode meant every hub surface, the contract compiler and the advisor carried a third case.
- Removing it leaves one command and one agent for a council.
- It also leaves a hub whose every mode stops for a reason a script computes.

## Hub Routing

Five surfaces now list two modes instead of three.

#### Two Modes in Every Routing Surface <a id="c-two-modes-in-every-routing-surface"></a>

- The mode registry, the hub router and the root `ROUTER.md` listed `ai-council` as a third mode.
- The graph metadata and the command metadata listed `ai-council` as a third mode too.
- All five now list `research` and `review`.
- The `council` loop type left the registry with it.
- The leaf manifest and the compiled routes were regenerated from those files.

> [!WARNING]
> The `ai-council` workflow mode and the `deep-ai-council` packet no longer exist. A script or doc that names `system-deep-loop/deep-ai-council/` points at nothing.

- The packet's 20 changelog entries stay at `.skilled/changelog/system-deep-loop/deep-ai-council/`.

#### The Pivot Seats Stay <a id="c-the-pivot-seats-stay"></a>

- A stalled research or review run can still convene pivot seats through the divergent pivot.
- That feature reads `runtime/lib/council/multi-seat-dispatch.cjs`.
- That file is unchanged.

<details>
<summary><b>Smaller fixes</b></summary>

- The shared benchmark runner covers two modes.
- The `seat_artifacts` evidence kind is removed from `shared/behavior-benchmark`.
- The `ACB` scenario prefix is removed from `shared/behavior-benchmark`.
- The hub playbook lists 11 scenarios.
- Three council-only scenarios are deleted.
- The totals are recounted.

</details>

## Commands

One command now handles a council.

#### One Council Command <a id="c-one-council-command"></a>

> [!WARNING]
> `/deep:ai-council` is removed with its two workflow files, its compiled contract and its mirrors in every runtime folder. Run `/speckit:ai-council <question> [:auto|:confirm] [--spec-folder=PATH]` instead.

- It writes under the bound packet's `ai-council/` folder, as before.

#### The Contract Compiler Knows Two Commands <a id="c-the-contract-compiler-knows-two-commands"></a>

- `compile-command-contracts.cjs` and `render-command-contract.cjs` accept `deep/research` and `deep/review`.
- The in-CLI seat branch that only the council used is removed.
- Both remaining contracts are recompiled.

&nbsp;

## Advisor

The advisor now points council prompts to the new command.

#### Council Wording Reaches the Command <a id="c-council-wording-reaches-the-command"></a>

- The scorer boosted the hub for phrases such as "ai council" and "planning council".
- Those lanes competed with the `/speckit:ai-council` row.
- Both dropped to a confidence of 0.25.
- The lanes are removed from the TypeScript scorer and the Python router.
- A prompt that asks to convene a council is also lifted off the read-only floor.
- Because the question a council compares is not itself a read-only request.

```text
convene an ai council to compare three migration plans
  -> command-speckit-ai-council, confidence 0.84, /speckit:ai-council
```

&nbsp;

## Runtime

The council loop type and its libraries are gone.

#### No Council Loop Type <a id="c-no-council-loop-type"></a>

> [!WARNING]
> `convergence.cjs`, `upsert.cjs`, `query.cjs` and `status.cjs` reject `--loop-type council`, and `convergence.cjs` drops the `--round-id` flag that only that branch read.

- The council graph, convergence, scoring, cost-guard and round-state libraries are deleted.
- The council ledger, reducer and sealed-artifact libraries are deleted too.
- Their tests and their fixtures are deleted too.
- `runtime/lib/council/` keeps `multi-seat-dispatch.cjs`.
- The divergent pivot calls that file.

<details>
<summary><b>Smaller fixes</b></summary>

- `/doctor:deep-loop` takes `--scope=research|review|both|all`.
- The `council` scope is removed.
- `runtime/database/council-graph.sqlite` stays on disk.
- No script reads or writes it.
- Callers outside the hub follow.
- The CLI bridge docs, the root README, the spec-kit command index and the Gate 3 resume phrases name `/speckit:ai-council`.
- The plugin guard fixtures register two modes.

</details>
