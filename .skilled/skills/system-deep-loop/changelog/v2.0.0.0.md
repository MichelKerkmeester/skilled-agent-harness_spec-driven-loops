# system-deep-loop v2.0.0.0: Reunification with deep-loop-runtime

The frozen, MCP-free `deep-loop-runtime` backend now sits inside `deep-loop-workflows` as a nested `runtime/` infrastructure layer. The unified skill takes the name `system-deep-loop` and uses `system-deep-loop/runtime/` for that infrastructure.

## Why This Release

Era 1 was the FULL_ISOLATE_NO_MCP split into two skills (packet 116, 2026-05-22). The major version reset marks the family's second era.

## What's New at a Glance

- **The two skills become one.** `deep-loop-runtime` joins `deep-loop-workflows` as nested `runtime/` infrastructure.
- **Internal paths follow the new nesting.** Relative references between runtime and workflow content were repaired in both directions.
- **Runtime guidance moves into its README.** The runtime's operating rules and agent-mirror convention now live with its infrastructure.
- **Three command routers use the renderer's new path.** Their update was pulled into this phase so the live command surface worked.
- **The public deep-loop names stay fixed.** Existing commands, agents and mode-packet folder names keep their names through the skill rename.
- **Compatibility paths bridge the external-reference migration.** Two temporary links preserve the former skill paths until that later phase is complete.

---

## Skill Identity

#### One Unified Skill

The former `deep-loop-workflows` skill is now `system-deep-loop`, with `deep-loop-runtime` folded into it. The runtime is infrastructure rather than a mode and has no separate advisor-routable identity.

&nbsp;

#### Advisor Graph Is Rebuilt

`graph-metadata.json` is fresh-authored rather than merged from the two prior source files. The `depends_on`/`siblings` edges between `deep-loop-runtime` and `deep-loop-workflows` are dropped entirely, because that relationship is now structure inside one skill. The `depends_on: system-spec-kit` weight rises from 0.6 to 0.7 to also cover the TypeScript tooling borrow of `runtime/`.

&nbsp;

#### Public Names Stay Fixed

The public surface stays intact above the hub. The names `/deep:*`, `@ai-council`, `@deep-research`, `@deep-review` and `@deep-improvement` stay fixed. The remaining mode-packet folder names stay fixed too.

## Runtime

#### Operating Guidance and History

The former `runtime/SKILL.md`'s ALWAYS/NEVER/ESCALATE rules and per-runtime agent-mirror convention move into `runtime/README.md` §9A, `Operating Rules`. The routable-skill frontmatter no longer applies to that file. Its operational content remains load-bearing.

The workflow skill's `changelog/{v1.0.0.0,v1.1.0.0}.md` histories remain separate from the runtime's history. The former runtime's seven entries in `runtime/changelog/*.md` are frozen at v1.5.0.1, with no new entries going there.

&nbsp;

#### Internal Paths Follow Nesting

Bidirectional relative-path coupling between `runtime/` and workflow content was repaired at the new nesting depth across about 45 code files. About 29 additional self-referencing paths in `deep-improvement/` test files named `.opencode/skills/deep-loop-workflows/`. They were simple workspace-root-anchored renames, unaffected by the depth change because `deep-improvement/` itself did not move deeper.

&nbsp;

#### Tooling References Follow Nesting

`runtime/package.json`'s `typecheck` script and `runtime/tsconfig.json`'s `typeRoots` carry a pre-existing borrow of `system-spec-kit`'s TypeScript tooling, now repointed for the new depth with one more `..`. The reverse references in `system-spec-kit/mcp-server/package.json` (`test:council`) and `vitest.config.ts` were repointed to `system-deep-loop/runtime/`. Decoupling the runtime's TypeScript tooling from `system-spec-kit` to use its own local `typescript` and `@types` instead of reaching into a sibling remains a follow-up hardening task.

&nbsp;

#### Council Gate Keeps Working

The `system-spec-kit/mcp-server/tests/council-playbook-anchor-integrity.vitest.ts` test is part of `test:council`'s run list and hard-crashed on its old hardcoded playbook path. That path was fixed because `test:council`'s own exit gate depends on the test.

&nbsp;

#### Tracked Runtime State Moves

`runtime/database/observability-events.jsonl` moves with the runtime and keeps its Git history and content intact. The checksums of both gitignored SQLite files match their pre-move values.

## Command Surface

The `.opencode/commands/deep/{research,review,ai-council}.md` routers now invoke `render-command-contract.cjs` at its new path. This reference move was pulled forward from the planned external-reference migration because this phase's live-verification step needed a working command surface.

## External References

The temporary compatibility paths `deep-loop-workflows -> system-deep-loop` and `deep-loop-runtime -> system-deep-loop/runtime` stay in place for the external-reference migration. That later phase covers commands, agents, READMEs, hooks and `system-skill-advisor`'s routing corpus. The links are removed once its residual grep is clean.

&nbsp;

#### Advisor Identity Awaits Lockstep Update

`check-contract-drift.vitest.ts`'s compiled-contract-staleness assertions continue to reflect a pre-existing failure against the still-unrenamed `skill: "deep-loop-workflows"` values. Those fields in `mode-registry.json` and `hub-router.json` were deliberately left unchanged in this phase to avoid desynchronizing `system-skill-advisor`'s drift guard before the lockstep update handled by the external-reference migration.
