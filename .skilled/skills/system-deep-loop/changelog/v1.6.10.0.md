# v1.6.10.0, Deep Review Adopts the Reach Calibration

The deep-review severity table rated a missing check the same way whatever input it was worried about, so a review could block on a helper no caller hands a bad value to. The table now defers to the reach calibration its review reference applies. A blocker has to name an input the code's contract allows or a real caller that sends it. Anything else is P2 hardening.

> Spec folder: `specs/sk-code/016-review-mode-followups` (Level 2)

&nbsp;

## What's New at a Glance

- **Both review paths answer the same way.** Deep review and a single review pass now rate the same failing input the same, so a loop run cannot block where one pass would not. The deep-review changelog carries the paragraph as written.
