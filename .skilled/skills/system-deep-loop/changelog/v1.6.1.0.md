Since v1.5.6.0 the review reducer reduces a folder with no `deep-review-config.json` on default settings. The strict path fails with the file named. Its headline still read `parseJsonl detected 1 corrupt line(s) in <state log>`. But the state log parsed clean.

&nbsp;

## What's New at a Glance

- The headline names what failed.
  - A missing config reads `could not read deep-review-config.json`.
  - Corrupt state-log lines keep their `parseJsonl detected N corrupt line(s)` headline.
  - A folder with both lists both.
- The hint fits either cause.
  - The hint now says `--lenient` reduces past these warnings.
  - The hint does not say the flag ignores corruption.
- The error code is unchanged.
  - Callers that match `STATE_CORRUPTION` see no difference.

No migration required.
