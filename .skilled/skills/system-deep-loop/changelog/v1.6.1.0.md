Since v1.5.6.0 the review reducer reduces a folder with no `deep-review-config.json` on default settings, and the strict path fails with the file named. Its headline still read `parseJsonl detected 1 corrupt line(s) in <state log>`, though the state log parsed clean.

## What's New at a Glance

- **The headline names what failed.** A missing config reads `could not read deep-review-config.json`. Corrupt state-log lines keep their `parseJsonl detected N corrupt line(s)` headline, and a folder with both lists both.
- **The hint fits either cause.** It now says `--lenient` reduces past these warnings, rather than that it ignores corruption.
- **The error code is unchanged.** Callers that match `STATE_CORRUPTION` see no difference.

## Upgrade

No migration required.
