# v2.1.6.0, Research Runs Use the Configured Claude Config Dir

A research run on Claude ignored the config dir the operator set. It ran under whichever account the shell had. Research now honors the configured dir.

&nbsp;

## What's New at a Glance

- Research honors `--config-dir=PATH` on `cli-claude-code` runs.
- The dir is checked before the prompt is read. A dir outside the allowed roots is refused.
- Claude runs under the configured dir. It overrides an inherited `CLAUDE_CONFIG_DIR`.
- The audit record names the dir the run used.
- A run that names no dir behaves as before.

&nbsp;

## How It Was Checked

New cases cover the flag, its validation and the audit record. All ten dispatch cases pass in a detached run. Inside a Claude session, two skip under the Claude ancestry guard.

&nbsp;

## Upgrade

No migration required. Set `configDir` in the run's executor config to pin the account. An inherited `CLAUDE_CONFIG_DIR` still reaches a research run that names no dir. Stripping it would change every default run, so it stays as it is.
