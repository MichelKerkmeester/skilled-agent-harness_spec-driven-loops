# v1.5.0.0, Alignment Mode and Conformance Retirement

`system-deep-loop` v1.5 retires the alignment mode.

- It also retires the conformance-benchmark capability that mode powered.
- The mode key and commands were public surfaces.
- So their removal is a major release.

The hub narrows from seven registered modes to six.

- It goes from eight deep commands to six.
- Two commands, six agents and a 126-file mode packet are gone.
- Surviving modes, the improvement lanes and the shared behavior-benchmark framework are untouched.

> [!IMPORTANT]
> 2 changes can break an existing setup. Read these before you update.
>
> 1. The alignment mode is retired. [The Hub Registers Six Modes](#c-the-hub-registers-six-modes)
> 2. Conformance benchmarking leaves both public surfaces. [Conformance Ends on Both Surfaces](#c-conformance-ends-on-both-surfaces)

&nbsp;

## Why This Release

The alignment mode was not standalone. It held the shared conformance engine.

- `/deep:command-benchmark` and the `/create:benchmark` conformance axis ran on that engine.
- Removing the mode alone would have left those surfaces pointing at a deleted engine.
- The operator approved the cascade.

## Deep Loop

The hub's mode list loses its alignment entry. Six modes remain registered.

#### The Hub Registers Six Modes <a id="c-the-hub-registers-six-modes"></a>

- The `alignment` mode key is removed.
- The hub goes from seven registered modes to six.
- The surviving modes are `research`, `review`, `ai-council`, `agent-improvement`, `model-benchmark` and `skill-benchmark`.
- Their convergence math, state shapes and artifacts are unchanged.
- The improvement lanes are unchanged.
- `shipped-census` counts were reconciled from eight to seven.
- Alignment was removed from roughly twenty-five shared files.
- The `deep-alignment` leaf agent is removed across all six runtime directories.
- The removed 126-file `deep-alignment/` mode packet included the command-behavior matrix scheduler.

<details>
<summary><b>Smaller fixes</b></summary>

- Three alignment state-backend rows were dropped from the frozen baseline census.
- That census is the packet-001 `state-backend-census.json`.
- Leaving the rows would have broken a surviving test.

</details>

## Benchmarking

Conformance benchmarking ends here. The other benchmark families are unchanged.

#### Conformance Ends on Both Surfaces <a id="c-conformance-ends-on-both-surfaces"></a>

> [!WARNING]
> Stop invoking `/deep:alignment` or `/deep:command-benchmark`. Neither has a replacement.

- Both `/deep:alignment` and `/deep:command-benchmark` are removed.
- The hub's `/deep:*` commands go from eight to six.
- The `/create:benchmark` `conformance_benchmark` axis is also removed.
- So is the `sk-create-benchmark` conformance family.
- `mcp_promotion` is the surviving `/create:benchmark` family.

#### Other Benchmark Families Continue <a id="c-other-benchmark-families-continue"></a>

- The behavior, model, skill and agent-improvement benchmark families are unchanged.
- The shared `shared/behavior-benchmark/` framework is unchanged.
- It is independent of the retired mode.

&nbsp;

## Documentation

Documentation now reflects the smaller mode set. Historical records keep their original wording.

#### References Match the New Scope <a id="c-references-match-the-new-scope"></a>

- The hub now advertises six user modes and four workflow families.
- The runtime and shared-progress READMEs no longer name `alignment` as a live mode.
- So do the behavior-benchmark references and the benchmark authoring guide.
- The scenario template also no longer names `alignment` as a live mode.
- The behavior-benchmark prefix set is now `RSB`, `RVB`, `ACB` and `IMB`.

#### Historical and Follow-Up Records <a id="c-historical-and-follow-up-records"></a>

- Historical changelogs, benchmark reports and spec packets keep their original references as immutable records.

<details>
<summary><b>Smaller fixes</b></summary>

- Two orphaned prompt mirrors survived the first removal pass.
- They sit under `.codex/prompts/` and `.pi/prompts/`.
- Dangling command-mirror symlinks also survived.
- They sit under `.claude/commands/deep/` and `.cursor/commands/`.
- Both survived because the mirror generators were not re-run.
- Review found both, and follow-up commits closed them.

</details>
