# system-deep-loop v2.2.3.0, Root Router

This release moves the second-stage surface router from `shared/references/smart-routing.md` to root `ROUTER.md`. Historical changelog and benchmark evidence that names the former path is left unchanged.

## What's New at a Glance

- **The legacy router file is removed.** Root `SKILL.md`, the README, the description, the feature catalog and the manual-testing index now point to `ROUTER.md` instead.
- **The root router declares its active state and skill pointer.** Its frontmatter sets `router_state: active` and `skill_pointer: SKILL.md`.
- **The legacy default resource now points to `ROUTER.md`.** In `hub-router.json`, only the literal legacy entry in `routerPolicy.defaultResource` changes. `mode-registry.json` remains the companion fallback resource.
- **The routing contract stays intact.** The machine-readable Python fence is byte-for-byte unchanged at SHA-256 `f9f410c1e3d0e70c7db23d952041811dab95be478237fdd2bf5e3523e7f9d274`. The seven workflow modes, routing keywords, intent/resource key sets, tie-break order, outcomes and default mode are unchanged. Frozen replay and scorer bytes are unchanged.
- **Root router's control-plane role.** Advisor identity and typed leaf ownership are unchanged. The root router is a control-plane document, not a leaf or graph identity. Compiled policy freshness remains gated on the fleet rebuild and promoted sync.

## Upgrade

No migration required.
