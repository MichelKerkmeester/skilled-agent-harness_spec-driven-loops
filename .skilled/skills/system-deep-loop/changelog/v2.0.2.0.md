# v2.0.2.0, Fan-Out Lineages Get the Executor Check

The post-dispatch gate from `v2.0.1.0` skipped fan-out lineages, because a lineage runs its iterations inline and writes no executor row. It now checks them too, against the executor the fan-out runner records for each lineage.

> Spec folder: `specs/cli-external-orchestration/runtime-lifecycle/002-cli-deepseek-harness-creation/023-dsh-lineage-executor-check`

&nbsp;

## What's New at a Glance

- **A lineage is checked against its invocation metadata.** The runner writes `invocation-metadata.json` in each lineage folder before every spawn. The gate passes when its `effectiveConfig.kind` matches the config's executor kind.
- **A missing or mismatched record fails.** A missing, unreadable or kindless file, or a different kind, fails with `executor_missing` and names the file or the kind.
- **Native and unconfigured lineages pass.** A native lineage and one whose config has no executor block are not checked.
- **The opening row counts on any log.** `validateIterationOutputs` accepts the executor on the iteration's `iteration_start` row with or without a ledger, the same rule the gate uses.
- **The hub reads v2.0.2.0.** Four routing files carry the new version.

&nbsp;

## Upgrade

No migration is required. A lineage iteration recorded before the runner wrote invocation metadata fails if it is checked again. The gate runs on each new iteration, so a running fan-out is not affected.
