# v1.6.16.0, One Authored Vocabulary for the Mode Router

The hub routes in two stages. `hub-router.json` picks the mode, then the stage-two intents in `ROUTER.md` pick the leaves that mode loads. Stage one could send a prompt to a mode on a term stage two did not carry, so the mode was chosen and had nothing to load. Every term the router routes now appears in that mode's stage-two intent.

> Spec folder: `specs/sk-doc/072-skill-routing-and-clarity/004-single-vocabulary-source` (Level 2)

&nbsp;

## What's New at a Glance

- **Every routed term reaches a leaf.** Thirteen terms were added across the three intents, including `deep review`, `deep-research` and `multi-seat planning council`, so a mode picked in stage one is never left without its resources.
- **The advisor reads the same phrases.** The multi-word forms were also added to the hub's intent signals in `graph-metadata.json`, where the skill advisor scores a request.
- **A drift check keeps the copies honest.** `ci-hub-vocabulary-source.cjs` fails when the registry aliases, the root `ROUTER.md` intents or a packet's `Keyword triggers:` line disagree with `hub-router.json`, which is now the one authored mode vocabulary.
