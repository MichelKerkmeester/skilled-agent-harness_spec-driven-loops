# v1.4.4.0, Artifact Progress Counts as Liveness

Version 1.4.4.0 gives fan-out liveness monitoring one more signal. The signal comes when a non-streaming executor writes artifacts as it works. The allowance is bounded. Work with no artifact writes and no streamed output still trips every guard. The executor timeout remains the hard limit.

&nbsp;

## Why This Release

A controlled reproduction overturned one report. The report said DeepSeek via cli-pi "requeues to death". One cli-pi review lineage completed with status `fulfilled` after all iterations. The shipped runtime does not forward `lagCeilingAction`. So the lag-ceiling abort is not armed. A live pi process does not trigger post-exit orphan handling. That path requires a subprocess exit. `stall_detected` only logs without aborting. No ledger records a real `orphan_requeue`. Because both are true, this release adds defense-in-depth for latent requeue paths. It also adds liveness for incremental writers. It is not a fix for an active loop.

&nbsp;

## What's New at a Glance

- Lineage artifact writes report progress.
  - A per-lineage poller watches the artifact directory.
  - The artifact directory's on-disk output can advance.
  - Files may be added, grown or rewritten.
  - When that happens, the poller resets the stall watchdog.
  - The poller also reports progress to the pool.
  - The progress reports reset the pool's stall clock.
  - Resetting the stall clock closes the lag-ceiling abort path.
  - The reports also record the progress time.
  - So fresh writes within the post-exit grace window count as ongoing work.
- Buffered cli-pi output can still log one warning.
  - This pi config buffers all disk writes until the run ends.
  - So it emits no incremental artifact signal.
  - The lineage still logs one advisory `stall_detected` warning.
  - Then it completes.
  - Silencing that warning would need a subprocess-liveness heartbeat.
  - That applies to an executor with no incremental writes.
  - A heartbeat weakens the watchdog's "alive but wedged" advisory meaning.
  - So it was deliberately left out.
- Existing runtime contracts are unchanged.
  - The `write-containment.ts` fail-closed contract is unchanged.
  - Executor rosters, allowlists and dispatch env are unchanged.
  - Convergence and stop-policy are unchanged too.
  - Every mode's ledger/reducer surface is also unchanged.
- Streaming executors are unaffected.
  - `opencode` and `codex` settle items and emit stdout as before.
