# v1.6.28.0, Failure Rows Survive and the Loop Save Writes Continuity

Three more writers now go through the append gateway. So their rows survive a state log refresh. The executor row has done that since `v1.6.27.0`. The release also fixes two faults. The first live DeepSeek Harness review hit both. One was a graph upsert that crashed on a non-blocking stdin. The other was a loop save that only planned.

> Spec folder: `specs/cli-external-orchestration/runtime-lifecycle/002-cli-deepseek-harness-creation/020-dsh-direct-writer-gateway`

&nbsp;

## What's New at a Glance

- **Failure rows reach the ledger.** On a ledger-backed state log the dispatch failure row goes through the append gateway. So does the receipt write failure row. Review carries them whole under its iteration stem. Research gains two stems for them.
- **The post-dispatch audit names its call.** The step calls `appendExecutorAuditToLastRecord`. That call records the executor once. It does so on the iteration's opening row.
- **Every audited dispatch passes the session id.** The four review and research workflows pass it to each runner call. So the gateway scopes each row to its run.
- **Recording a failure never throws.** With no session id, or when the gateway refuses, the row is written directly. In that case, stderr says the next refresh drops it.
- **The CLI entrypoints leave stdin alone.** `status`, `query` and `convergence` no longer read stdin. `upsert` reads it only for `--events -`. It retries on EAGAIN.
- **The loop save writes continuity.** All six review, research and AI Council workflows run the continuity writer with `--full-auto`. The review and research payloads carry the four continuity fields.
- **The hub reads v1.6.28.0.** Four routing files carry the new version.

&nbsp;

## Upgrade

No migration is required. A script that piped data to `status.cjs`, `query.cjs` or `convergence.cjs` was ignored before. It is still ignored. A deep loop's save now writes continuity into the packet's canonical docs. Before, it only planned.
