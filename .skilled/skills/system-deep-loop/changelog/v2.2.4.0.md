# system-deep-loop v2.2.4.0

## Changed

- Added artifact-progress liveness to the fan-out runner so a non-streaming executor is judged live while it is genuinely working. A per-lineage poller in `runtime/scripts/fanout-run.cjs` watches the lineage artifact directory; when its on-disk output advances (files added, grown, or rewritten) it resets the stall-watchdog (`markLineageEvent`) and reports progress back to the pool (`context.reportProgress`). `runtime/scripts/fanout-pool.cjs` threads that callback into the worker context: it resets the pool's stall clock (closing the lag-ceiling abort path) and records the progress time so the post-exit-orphan watchdog treats fresh writes within its grace window as "still working." The allowance is bounded — a lineage that writes nothing *and* streams nothing still trips every guard, and the executor's own timeout remains the hard bound, so a genuine hang is still caught.
- Added four unit tests in `runtime/tests/unit/fanout-pool.vitest.ts`: a silent worker that keeps reporting artifact progress is not lag-aborted; an exited-but-still-writing worker is not orphaned; and both are still caught once progress stops (bounded negatives). The two positive tests fail with the pool fix stashed, so they exercise the change by construction. Pool suite 31/31; fan-out + cli-pi stress 38 passed / 2 skipped.

## Why (diagnosis overturned the premise)

- The change was scoped from a report that DeepSeek-via-cli-pi "requeues to death." Controlled reproduction disproved it: a single cli-pi review lineage completes `fulfilled` with all iterations. The shipped runtime does not forward `lagCeilingAction`, so the lag-ceiling abort is never armed; the post-exit-orphan needs a real subprocess exit a live pi never triggers; and `stall_detected` is advisory-only (it logs, it does not abort). No ledger anywhere records a real `orphan_requeue`. So this release is bounded defense-in-depth for the latent requeue paths plus real liveness for any executor that writes incrementally — not a fix for an active loop.
- Live confirmation: a post-fix run drove cli-pi through the full loop (all iterations + report) with zero requeue/orphan events. It then exercised the v2.2.2.0 write boundary — DeepSeek wrote out-of-scope into a sibling packet and write-containment reverted it. The net works on cli-pi.

## Known caveat

- This pi config buffers *all* disk writes to the end of the run, so it emits no incremental artifact signal. The poller therefore cannot silence its advisory `stall_detected` — the lineage still logs one stall warning and completes anyway (it is log-only). Fully silencing that for a zero-incremental-write executor would require a subprocess-liveness heartbeat in the stall-watchdog, a separate change that weakens the watchdog's "alive but wedged" advisory meaning; it was deliberately not taken here.

## Not Changed

- `write-containment.ts` and its fail-closed contract; executor rosters, allowlists, dispatch env; convergence, stop-policy, and every mode's ledger/reducer surface. Streaming executors (opencode, codex) settle items and emit stdout as before and are unaffected by the added progress path.
