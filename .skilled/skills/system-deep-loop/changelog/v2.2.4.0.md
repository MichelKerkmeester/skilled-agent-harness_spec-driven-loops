# v2.2.4.0, Artifact Progress Counts as Liveness

Version 2.2.4.0 gives fan-out liveness monitoring an additional signal when a non-streaming executor writes artifacts as it works. The allowance is bounded: work with no artifact writes and no streamed output still trips every guard, and the executor timeout remains the hard limit.

## Why This Release

A controlled reproduction overturned the report that DeepSeek via cli-pi "requeues to death": one cli-pi review lineage completed with status `fulfilled` after all iterations. The shipped runtime does not forward `lagCeilingAction`, so the lag-ceiling abort is not armed. A live pi process does not trigger post-exit orphan handling because that path requires a subprocess exit. Because `stall_detected` only logs without aborting and no ledger records a real `orphan_requeue`, this release adds defense-in-depth for latent requeue paths and liveness for incremental writers, not a fix for an active loop.

## What's New at a Glance

- **Lineage artifact writes report progress.** A per-lineage poller watches the artifact directory. When its on-disk output advances through files being added, grown or rewritten, it resets the stall watchdog and reports progress to the pool. Those reports reset the pool's stall clock, closing the lag-ceiling abort path. They also record the progress time so fresh writes within the post-exit grace window count as ongoing work.
- **Buffered cli-pi output can still log one warning.** This pi config buffers all disk writes until the run ends, so it emits no incremental artifact signal. The lineage still logs one advisory `stall_detected` warning and completes. Silencing that warning for an executor with no incremental writes would require a subprocess-liveness heartbeat, which weakens the watchdog's "alive but wedged" advisory meaning and was deliberately left out.
- **Existing runtime contracts are unchanged.** The `write-containment.ts` fail-closed contract, executor rosters, allowlists and dispatch env are unchanged. Convergence and stop-policy are unchanged too. Every mode's ledger/reducer surface is also unchanged.
- **Streaming executors are unaffected.** `opencode` and `codex` settle items and emit stdout as before.

## Upgrade

No migration required.
