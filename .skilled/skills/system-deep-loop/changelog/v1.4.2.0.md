# v1.4.2.0, Fan-Out Boundaries for Weaker Models

This release hardens the shared fan-out lineage prompt. `buildLoopPrompt` in `runtime/scripts/fanout-run.cjs` renders it for every mode. DeepSeek Flash treated its path-only wording as permission to run repository tools during an observation pass. The prompt now spells out the observation boundary. So a weak model can follow it. It no longer depends on a strong model inferring it.

&nbsp;

## What's New at a Glance

- The fan-out prompt names forbidden tools across all eight modes on cli-opencode and cli-pi.
  - It names `generate-context.js`, `validate.sh` (especially `--recursive`) and any `git` write/checkout/commit as off-limits during observation.
  - The old instruction only said not to touch paths outside a lineage directory.
  - A cheaper model treated that as permission to run tools.
  - A real deep-review lineage ran `generate-context.js` and `validate.sh`.
  - The lineage edited files across the tree.
  - Then write-containment failed it for reverting eight out-of-scope tracked paths.
- A live two-executor review now succeeds on both lineages.
  - The baseline was a clean worktree.
  - A fan-out review ran on codex `gpt-5.6-luna` and `opencode-go/deepseek-v4-flash`.
  - The review went from 1 succeeded and 1 failed to 2 succeeded and 0 failed.
  - The DeepSeek lineage flipped from `rejected` to `fulfilled`.
  - The DeepSeek lineage's real forbidden-tool invocations dropped from 26/24 to 0/0.
  - That count comes from a command-parse of the session log.
  - Earlier raw counts were prompt-text and SKILL echoes, not runs.
  - Write-containment recorded zero violations.
  - The strong-model lineage was unaffected.
- The write-containment backstop is unchanged.
  - `write-containment.ts` remains the enforced backstop.
  - `write-containment.ts` has detection, HEAD-revert of in-scope breaches and a fail-closed contract.
  - Prompt hardening improves the odds.
  - Prompt hardening does not replace the net.
  - The evidence that prompt-hardening alone drove DeepSeek to zero breaches is why the heavier `prevent-not-revert` write-jail was ruled out.
  - Executor rosters, allowlists, dispatch env construction, convergence and stop-policy logic are unchanged.
  - Every mode's ledger/reducer/certificate surface is unchanged too.
  - No behavior changes for strong-model executors.
