# deep-loop-workflows v1.1.0.0, Parent-Hub Canon Alignment

deep-loop-workflows v1.1.0.0 aligns the hub with the canonical parent-skill contract. It adds the required hub description and router, canon fields across every mode and operator materials, while leaving the three-tier discriminator and `advisorRouting` projections unchanged.

## What's New at a Glance

- **`description.json` adds the required hub description.** It contains the canon fields `name`, `description`, `version` and `keywords`, plus the seven modes and their three backend kinds.
- **`hub-router.json` adds the router the canon requires.** It defines one `routerSignals` entry per mode, `<mode>-aliases` vocabulary classes from registry `aliases[]`, `hub-identity`, `tieBreak` coverage for all seven modes and resources pointing to packet `SKILL.md` files. It also unblocks `parent-hub-vocab-sync`, which silently no-ops without a router.
- **`manual-testing-playbook/` adds operator-run scenarios.** They cover mode routing, improvement-lane routing, advisor integration, runtime/backend discrimination and state/convergence discipline. Each expected route derives from `mode-registry.json`.
- **`benchmark/` adds the first Lane-C skill-benchmark baseline.** The baseline uses router mode, and `benchmark/README.md` accompanies it.
- **`mode-registry.json` declares two active extensions.** `runtime-loop` is the research, review and council convergence backend, and `advisor-projection` provides the drift-guard-checked projection maps. These extensions activate fields in place and do not relocate anything.
- **`mode-registry.json` adds canon fields to every mode.** Each mode has `packetKind: "workflow"`, `grandfatheredFolderMismatch: false` and a well-formed `toolSurface`. All seven modes are mutating loop/host orchestrators. Research additionally grants WebFetch for outward investigation, and every folder matches `packetSkillName`. The three-tier discriminator and every `advisorRouting` projection block are unchanged.
- **`changelog/` now contains real hub changelog files only.** Five hub-level per-mode symlinks were removed under the real-files-only policy. Packet changelogs live in their packets, and one of the five, for `deep-context`, was dangling.
- **Versioning now uses the four-segment scheme.** It changed from `1.0.0.0` to `1.1.0.0` in `SKILL.md`, `mode-registry.json`, `hub-router.json` and `description.json`.
