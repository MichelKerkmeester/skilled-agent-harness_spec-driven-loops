# system-deep-loop v1.2.0.0: Reunification with deep-loop-runtime

The two skills become one.

- The frozen, MCP-free `deep-loop-runtime` backend now sits inside `deep-loop-workflows`.
- It is a nested `runtime/` infrastructure layer.
- The unified skill takes the name `system-deep-loop`.
- It uses `system-deep-loop/runtime/` for that infrastructure.

Internal paths follow the new nesting.

- Relative references between runtime and workflow content were repaired.
- The repair went in both directions.
- The runtime's operating rules and agent-mirror convention now live with its infrastructure.
- Three command routers use the renderer's new path.

The public deep-loop names stay fixed.

- Existing commands, agents and mode-packet folder names keep their names.
- They keep them through the skill rename.
- Two temporary links preserve the former skill paths.
- They stay until that later phase is complete.

## Skill Identity

The renamed skill keeps its public surface. Its advisor graph is fresh-authored.

#### One Unified Skill <a id="c-one-unified-skill"></a>

- The former `deep-loop-workflows` skill is now `system-deep-loop`.
- `deep-loop-runtime` is folded into it.
- `deep-loop-runtime` joins `deep-loop-workflows` as nested `runtime/` infrastructure.
- The runtime is infrastructure rather than a mode.
- It has no separate advisor-routable identity.

#### Advisor Graph Is Rebuilt <a id="c-advisor-graph-is-rebuilt"></a>

- `graph-metadata.json` is fresh-authored.
- It was not merged from the two prior source files.
- The `depends_on`/`siblings` edges between `deep-loop-runtime` and `deep-loop-workflows` are dropped entirely.
- That is because the relationship is now structure inside one skill.
- The `depends_on: system-spec-kit` weight rises from 0.6 to 0.7.
- It also covers the TypeScript tooling borrow of `runtime/`.

#### Public Names Stay Fixed <a id="c-public-names-stay-fixed"></a>

- The public surface stays intact above the hub.
- The names `/deep:*`, `@ai-council`, `@deep-research`, `@deep-review` and `@deep-improvement` stay fixed.
- The remaining mode-packet folder names stay fixed too.

&nbsp;

## Runtime

The runtime becomes nested infrastructure. Its guidance, paths and state move with it.

#### Operating Guidance and History <a id="c-operating-guidance-and-history"></a>

- The former `runtime/SKILL.md`'s ALWAYS/NEVER/ESCALATE rules move into `runtime/README.md` §9A, `Operating Rules`.
- Its per-runtime agent-mirror convention moves there too.
- The routable-skill frontmatter no longer applies to that file.
- Its operational content remains load-bearing.
- The workflow skill's `changelog/{v1.0.0.0,v1.1.0.0}.md` histories remain separate from the runtime's history.
- The former runtime's seven entries in `runtime/changelog/*.md` are frozen at v1.5.0.1.
- No new entries go there.

#### Internal Paths Follow Nesting <a id="c-internal-paths-follow-nesting"></a>

- Relative-path coupling between `runtime/` and workflow content ran both ways.
- It was repaired at the new nesting depth.
- That repair covered about 45 code files.
- About 29 additional self-referencing paths in `deep-improvement/` test files named `.opencode/skills/deep-loop-workflows/`.
- They were simple workspace-root-anchored renames.
- The depth change did not affect them, because `deep-improvement/` itself did not move deeper.

#### Tooling References Follow Nesting <a id="c-tooling-references-follow-nesting"></a>

- `runtime/package.json`'s `typecheck` script carries a pre-existing borrow.
- So does `runtime/tsconfig.json`'s `typeRoots`.
- The borrow is of `system-spec-kit`'s TypeScript tooling.
- That borrow is now repointed for the new depth.
- It adds one more `..`.
- The reverse references in `system-spec-kit/mcp-server/package.json` (`test:council`) and `vitest.config.ts` were repointed to `system-deep-loop/runtime/`.
- Decoupling the runtime's TypeScript tooling from `system-spec-kit` remains a follow-up hardening task.
- It would use its own local `typescript` and `@types`.
- It would not reach into a sibling.

#### Council Gate Keeps Working <a id="c-council-gate-keeps-working"></a>

- The `system-spec-kit/mcp-server/tests/council-playbook-anchor-integrity.vitest.ts` test is part of `test:council`'s run list.
- It hard-crashed on its old hardcoded playbook path.
- That path was fixed, because `test:council`'s own exit gate depends on the test.

#### Tracked Runtime State Moves <a id="c-tracked-runtime-state-moves"></a>

- `runtime/database/observability-events.jsonl` moves with the runtime.
- It keeps its Git history and content intact.
- The checksums of both gitignored SQLite files match their pre-move values.

## External References

Temporary compatibility paths cover the old paths during the external-reference migration.

#### Compatibility Links Cover Old Paths <a id="c-compatibility-links-cover-old-paths"></a>

- The temporary compatibility paths `deep-loop-workflows -> system-deep-loop` and `deep-loop-runtime -> system-deep-loop/runtime` stay in place.
- They stay for the external-reference migration.
- They stay until that later phase is complete.
- That later phase covers commands, agents, READMEs and hooks.
- It also covers `system-skill-advisor`'s routing corpus.
- The links are removed once its residual grep is clean.

#### Advisor Identity Awaits Lockstep Update <a id="c-advisor-identity-awaits-lockstep-update"></a>

- `check-contract-drift.vitest.ts`'s compiled-contract-staleness assertions continue to reflect a pre-existing failure.
- That failure is against the still-unrenamed `skill: "deep-loop-workflows"` values.
- Those fields in `mode-registry.json` and `hub-router.json` were deliberately left unchanged in this phase.
- That avoids desynchronizing `system-skill-advisor`'s drift guard before the lockstep update.
- The external-reference migration handles that update.
