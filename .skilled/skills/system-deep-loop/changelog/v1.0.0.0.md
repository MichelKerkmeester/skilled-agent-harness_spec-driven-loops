# v1.0.0.0 - Initial Release

The deep-loop family now follows the parent-skill pattern. It has one invokable hub and one advisor identity. The hub is routing-only. The loop logic lives in nested mode packets.

&nbsp;

## What's New at a Glance

- Four modes sit behind the hub.
  - The hub's `SKILL.md` now carries the smart-routing contract.
  - So invoking `Skill(deep-loop-workflows)` loads the hub.
  - The hub's router reads the request.
  - The router loads a matching mode packet.
  - The active modes are `deep-research`, `deep-review`, `deep-ai-council` and `deep-improvement`.
  - Each is registered in `mode-registry.json`.
  - Each holds its loop logic behind the hub's single `graph-metadata.json` identity.

&nbsp;

## Upgrade

No migration required. The `/deep:*` commands and the deep agents keep working unchanged.
