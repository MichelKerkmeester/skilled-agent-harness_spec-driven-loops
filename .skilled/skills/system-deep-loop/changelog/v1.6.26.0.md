# v1.6.26.0, One DeepSeek Harness Lineage Runs in Review and Research

The DeepSeek Harness now runs as a single lineage in both `:auto` workflows. That corrects the note in `v1.6.24.0.md:25`. That note said the DeepSeek Harness was fan-out only. The release also bounds the runner environment. It sweeps stale homes and folds a finding that moved line.

&nbsp;

## What's New at a Glance

- The DeepSeek Harness runs as a single lineage in `:auto`.
  - Both workflows dispatch it once per iteration.
  - The shared command builder owns the command.
- `dispatchEnv` takes only named keys.
  - The runner checks each caller key against a short per-kind list.
  - Any other key throws before a receipt or a child exists.
- A stale DeepSeek Harness home is swept.
  - Both auto workflows and the fan-out runner remove old `dsh-home-XXXXXX` folders.
  - The cutoff is 24 hours.
- The event stream is counted, not echoed.
  - The dispatch prints one stderr line with the byte count.
  - The completion check still reads the whole stream.
- `:confirm` refuses an unbranched executor kind.
  - Both confirm workflows stop with exit 2 and name `:auto`.
- The hub reads v1.6.26.0.
  - Four routing files carry the new version.
- A finding at a shifted line folds into its first row.
  - A legacy record with no content hash matches on file and title.
  - A moved line then adds no second row.
- A leaf's dimension id folds to the canonical id.
  - A review upsert stores `dim:security`, `DIM-TRACEABILITY` and `dimension:Security` as `dimension:security`.
  - Its edges end there too.

&nbsp;

## Upgrade

Run `:auto` for the DeepSeek Harness. `:confirm` now refuses that kind. A scripted confirm run must move to `:auto` or to one of the three kinds confirm still branches. No other migration is required.
