# v1.0.0.0, deep-review Becomes a Standalone Skill

This first release makes `deep-review` a standalone skill.

- It owns all iterative code review and quality auditing.
- It takes all review-mode functionality from the unified `deep-research` skill v1.2.2.0.
- It gains its own command, YAML workflows, reference documentation and manual testing playbook.

The goal is to make the review workflow easier to follow.

- It should also be easier to trust.
- Four references document review work.

Review routing and runtime definitions point to the standalone skill.

- The skill advisor and the Barter advisor both handle review keywords.
- Agent definitions across `.claude`, `.opencode`, `.agents` and `.codex` were updated.
- Agent guidance and skill catalogs gained entries for the new skill.

> [!IMPORTANT]
> 1 change can break an existing setup. Read these before you update.
>
> 1. `/speckit:deep-research:review` is no longer supported. [New command and workflows](#c-the-new-command-and-workflows)

&nbsp;

## Why This Release

Review-mode functionality came from the unified `deep-research` skill v1.2.2.0. The goal is to make the review workflow easier to follow.

## Review Workflow

`deep-review` has its own command and workflow set. Its own command gives review work a separate entry point. The review-specific assets moved into its package.

#### The New Command and Workflows <a id="c-the-new-command-and-workflows"></a>

> [!WARNING]
> `/speckit:deep-research:review` is no longer supported. Replace it with `/speckit:deep-review`.

- The new command `/speckit:deep-review` offers `:auto` and `:confirm` modes.
- Its YAML workflows are `spec_kit_deep-review_auto.yaml` and `spec_kit_deep-review_confirm.yaml`.
- Both were renamed from `spec_kit_deep-research_review_*.yaml`.
- The old `/speckit:deep-research:review` command is no longer supported.

#### Review Assets Move with the Skill <a id="c-review-assets-move-with-the-skill"></a>

- The review-specific assets moved into the `deep-review` package.
- `deep_review_strategy.md`
- `deep_review_dashboard.md`
- `review_mode_expected behavior.yaml`
- `deep_review_config.json`

&nbsp;

## Review Documentation

Four references document review work. They cover the loop, convergence, state formats and quick lookup.

#### References Cover Each Stage <a id="c-references-cover-each-stage"></a>

- `references/loop-protocol.md` describes the review loop lifecycle of init, iterate, synthesize and save.
- It also covers scope discovery, dimension ordering, cross-reference protocols and claim adjudication.
- `references/convergence.md` documents the severity-weighted ratio, P0 override and dimension coverage signal.
- It also covers quality guards and provisional verdict logic.
- `references/state-format.md` describes state file schemas for config, JSONL, strategy and iteration files.
- It also covers the review report, dashboard, claim adjudication and finding registry.
- `references/quick-reference.md` provides a review-only cheat sheet.
- Its numbered H2 sections align to `skill_reference_template.md`.

## Skill Routing

Review routing was updated with the skill split. Runtime definitions point to the standalone skill.

#### Review Keywords Follow the Split <a id="c-review-keywords-follow-the-split"></a>

- The skill advisor routes review keywords to `deep-review` instead of `deep-research`.
- The Barter repo's `skill_advisor.py` received the same review-keyword routing.

#### Runtimes Receive the New Entry <a id="c-runtimes-receive-the-new-entry"></a>

- Agent definitions across `.claude`, `.opencode`, `.agents` and `.codex` were updated.
- They reference `/speckit:deep-review` and `deep-review`.
- The `.agents` runtime received a new wrapper at `.agents/commands/speckit/deep-review.toml`.
- Agent guidance and the root and `.opencode` catalogs gained entries for the new skill.

&nbsp;

## How It Was Checked

The skill includes a manual testing playbook. Its review scenarios follow the `deep-research` structure.

#### Review Stages Guide Scenarios <a id="c-review-stages-guide-scenarios"></a>

- The playbook's review-specific scenarios mirror the `deep-research` structure.
- They cover entry points and modes.
- They cover initialization and state setup.
- They cover iteration execution and state discipline.
- They cover convergence and recovery.
- They cover pause, resume and fault tolerance.
- They cover synthesis, save and guardrails.
