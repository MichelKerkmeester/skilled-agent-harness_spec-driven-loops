Deep-review now lets you choose which AI runs each review iteration. You do this through an optional CLI executor. The YAML workflow continues to own state tracking. It also owns convergence detection, the findings registry, dashboard and reducer. So the CLI is a tool inside the workflow, not a replacement.

The release ships as a symmetric pair with deep-research v1.8.0.0. That is because asymmetric shipping creates the bug class Phase 017 Cluster D was built to prevent. Its design rationale is in `decision-record.md`. That record covers the decision to ship the deep-review symmetry in the same pull request, not a follow-up.

&nbsp;

## What's New at a Glance

- Review iterations can select an executor.
  - `executor.kind` selects the default `native` branch or the `cli-codex` branch.
  - The `native` branch keeps the same review agent dispatch through Claude Opus.
  - The `cli-codex` branch runs `codex exec`.
  - The `cli-codex` branch takes model, reasoning effort and service tier from config.
  - The `cli-codex` branch pipes the review iteration prompt through stdin.
- Both executor paths share the review prompt.
  - The review iteration context lived inline in the YAML.
  - The review iteration context is extracted into the new `assets/prompt-pack-iteration.md.tmpl`.
  - Both paths render it and receive the same context.
  - That context is state summary, dimension, target and scope files.
  - The context also covers prior findings counts, quality gates, verdicts and claim adjudication requirements.
  - Review constraints cover correctness, security, traceability and maintainability.
  - Review constraints also cover evidence, scope, coverage quality gates and FAIL, CONDITIONAL and PASS verdicts with a `hasAdvisories=true` option.
  - Review constraints cover the claim adjudication schema for new P0 and P1 findings.
- Review and research share the executor config contract.
  - `deep_review_config.json` adds an `executor` block.
  - That block is bit-identical to the block in `deep_research_config.json`.
  - The `executor` block has the same six fields, defaults and validation.
  - One contract serves both consumers.
  - One contract keeps the configs aligned by design.
- Review setup adds five executor flags.
  - The consolidated setup prompt in `deep-review.md` at `.opencode/commands/deep/review.md` adds `--executor`, `--model`, `--reasoning-effort`, `--service-tier` and `--executor-timeout`.
  - The setup prompt also adds the conditional executor question.
  - Precedence is CLI flag, config file then schema default.
  - That gives users the same UX across both iterative skills.
- Non-native review records add an executor audit block.
  - When a non-native executor runs a review iteration, the workflow appends `executor: {kind, model, reasoningEffort, serviceTier}` as a new top-level field.
  - `dimensions`, `filesReviewed`, `findingsSummary` and `newFindingsRatio` remain unchanged.
  - Review dimensions, findings severity and verdict logic also stay unchanged.
- Every dispatch requires a narrative and JSONL delta.
  - Native and CLI executors must produce a markdown narrative file.
  - Native and CLI executors must also produce a JSONL delta record with the required review fields.
  - The shared validator checks both after dispatch.
  - Missing or malformed output fires a canonical `schema_mismatch` conflict event.
  - Three consecutive validation failures trigger the existing stuck-recovery path.
- The `SKILL.md` forward-looking note at line 63 was replaced by a full executor contract.
  - The section parallels the research skill's contract.
  - The section documents shipped and reserved kinds and executor invariants.
  - The section also documents review JSONL requirements and where the config and template live.
- Loop recovery guidance now covers executor selection.
  - Section 3 of `references/loop-protocol.md` explains how branch selection interacts with `schema_mismatch` and stuck recovery.
  - Section 3 states that branch selection does not change review-specific recovery semantics.

## Upgrade

No migration required. `executor.kind` defaults to `native`. So users who set nothing get the same agent dispatch and iteration file. They also get the same JSONL record with review dimensions and findings registry semantics as before.

To opt into `cli-codex` dispatch for review:

```sh
/deep:review :auto "target" \
  --executor=cli-codex \
  --model=gpt-5.4 \
  --reasoning-effort=high \
  --service-tier=fast
```

This requires `codex` on PATH. The config enum also declares reserved `cli-copilot` and `cli-claude-code` kinds. Config loading throws `ExecutorNotWiredError` for these kinds. The error points to future specs.

No review-specific TypeScript was added. The four shared TypeScript modules are consumed by both skills. All four YAMLs use the same two-branch structure. Those are research auto, research confirm, review auto and review confirm.
