Deep-review now lets you choose which AI runs each review iteration through an optional CLI executor. The YAML workflow continues to own state tracking, convergence detection, the findings registry, dashboard and reducer, so the CLI is a tool inside the workflow rather than a replacement. The release ships as a symmetric pair with deep-research v1.8.0.0 because asymmetric shipping creates the bug class Phase 017 Cluster D was built to prevent, with its design rationale in `decision-record.md` (ADR-005).

> Spec folder: `.opencode/specs/system-spec-kit/026-graph-and-context-optimization/017-sk-deep-cli-runtime-execution/001-executor-feature` (Level 3)

## What's New at a Glance

- **Review iterations can select an executor.** `executor.kind` selects the default `native` branch or the `cli-codex` branch. The former keeps the same review agent dispatch through Claude Opus, while the latter runs `codex exec` with model, reasoning effort and service tier from config and pipes the review iteration prompt through stdin.
- **Both executor paths share the review prompt.** The review iteration context that lived inline in the YAML is extracted into the new `assets/prompt-pack-iteration.md.tmpl`, and both paths render it and receive the same context: state summary, dimension, target, scope files, prior findings counts, quality gates, verdicts and claim adjudication requirements. Review constraints cover correctness, security, traceability and maintainability, evidence, scope, coverage quality gates and FAIL, CONDITIONAL and PASS verdicts with a `hasAdvisories=true` option, as well as the claim adjudication schema for new P0 and P1 findings.
- **Review and research share the executor config contract.** `deep_review_config.json` adds an `executor` block bit-identical to the block in `deep_research_config.json`, with the same six fields, defaults and validation. One contract serves both consumers and keeps the configs aligned by design.
- **Review setup adds five executor flags.** The consolidated setup prompt in `deep-review.md` at `.opencode/commands/deep/review.md` adds `--executor`, `--model`, `--reasoning-effort`, `--service-tier` and `--executor-timeout`, plus the conditional executor question. Precedence is CLI flag, config file then schema default, giving users the same UX across both iterative skills.
- **Non-native review records add an executor audit block.** When a non-native executor runs a review iteration, the workflow appends `executor: {kind, model, reasoningEffort, serviceTier}` as a new top-level field, while `dimensions`, `filesReviewed`, `findingsSummary` and `newFindingsRatio` remain unchanged. Review dimensions, findings severity and verdict logic also stay unchanged.
- **Every dispatch requires a narrative and JSONL delta.** Native and CLI executors must produce a markdown narrative file plus a JSONL delta record with the required review fields, which the shared validator checks after dispatch. Missing or malformed output fires a canonical `schema_mismatch` conflict event, and three consecutive validation failures trigger the existing stuck-recovery path.
- **The `SKILL.md` forward-looking note at line 63 was replaced by a full executor contract.** The section parallels the research skill's contract and documents shipped and reserved kinds, executor invariants, review JSONL requirements and where the config and template live.
- **Loop recovery guidance now covers executor selection.** Section 3 of `references/loop-protocol.md` explains how branch selection interacts with `schema_mismatch` and stuck recovery, and states that branch selection does not change review-specific recovery semantics.

## Upgrade

No migration required. `executor.kind` defaults to `native`, so users who set nothing get the same agent dispatch, iteration file, JSONL record with review dimensions and findings registry semantics as before.

To opt into `cli-codex` dispatch for review:

```sh
/deep:review :auto "target" \
  --executor=cli-codex \
  --model=gpt-5.4 \
  --reasoning-effort=high \
  --service-tier=fast
```

This requires `codex` on PATH. The config enum also declares reserved `cli-copilot` and `cli-claude-code` kinds. Config loading throws `ExecutorNotWiredError` for these kinds with a pointer to future specs.

No review-specific TypeScript was added. The four shared TypeScript modules are consumed by both skills, and all four YAMLs, research auto, research confirm, review auto and review confirm, use the same two-branch structure.
