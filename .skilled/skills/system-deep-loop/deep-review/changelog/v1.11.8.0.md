# v1.11.8.0, Severity Follows the Reach Calibration

A deep review could rate a missing check as a blocker on a helper that never receives the value it was worried about. The severity table now says a P0 or P1 finding has to name input the code's contract allows or a real caller that sends it, so the loop's own scale no longer contradicts the calibration its review reference already applies.

> Spec folder: `specs/sk-code/016-review-mode-followups` (Level 2)

&nbsp;

## What's New at a Glance

- **A blocker has to name a reachable input.** "Missing validation" is P1 only when the unvalidated input can arrive. Validation the code never claimed, for input outside its stated contract, is P2 hardening.
- **A trust boundary stays wide.** Every value the outside can send is in reach there, so security findings keep the severity they had.
- **The loop decides the way a single review does.** The paragraph points at the calibration in the review reference, so deep review and a one-pass review rate the same failing input the same way.
