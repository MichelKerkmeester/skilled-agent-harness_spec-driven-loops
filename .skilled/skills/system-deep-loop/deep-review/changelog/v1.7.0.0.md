This release brings `deep-research` v1.10.0.0 hardening across the review loop, giving review runs the same safeguards as research. It also updates review's readiness and retry guidance.

> Spec folder: `.opencode/specs/system-spec-kit/026-graph-and-context-optimization/018-cli-executor-remediation` (Level 3)

## What's New at a Glance

- **Review iterations capture non-native executor identity first.** In `deep_review_auto.yaml` and `deep_review_confirm.yaml`, `step_dispatch_iteration` runs `writeFirstRecordExecutor` before every non-native dispatch and writes executor identity to the iteration's first JSONL record. The dimensions and `filesReviewed`, `findingsSummary` and `newFindingsRatio` schema are unchanged, and missing provenance fails fast during post-dispatch validation.
- **Review failures retain executor attribution.** A review iteration crash or timeout emits `{type:'event', event:'dispatch_failure', executor, reason, iteration, timestamp}`. This preserves attribution when no valid iteration record exists.
- **Copilot review prompts use `@path` when large.** The `if_cli_copilot` branch in both review YAMLs checks for prompts over 16 KB and uses the research path's `Read the instructions in @<path>` wrapper above that threshold. Review prompt paths use `review/prompts/`.
- **Description repair safety applies to review packets.** The shared `generate-description.ts` loader uses the new discriminated-result loader and `mergePreserveRepair` for review `description.json` files as well, and the helper is packet-agnostic.
- **The readiness contract names four live trust states.** The `deep-review/SKILL.md` readiness contract lists `live`, `stale`, `absent` and `unavailable` as the four trust-state values emitted by the seven code-graph handlers. It marks `cached`, `imported`, `rebuilt` and `rehomed` as compatibility vocabulary not emitted on that surface.
- **Review contracts document the executor guarantees.** The `deep-review/SKILL.md` Executor Selection Contract records the first-write audit path, `dispatch_failure` and the preservation guarantee for non-native executor identity. `review_mode_contract.yaml` aligns with the first-write audit path.
- **Research and review share the hardening pass.** Both skills ship it in the same release cycle and consume shared modules unchanged: `executor-audit.ts`, `post-dispatch-validate.ts`, `description/repair.ts`, `continuity/timestamp-normalize.ts`, `enrichment/retry-budget.ts` and `scripts/validation/evidence-marker-audit.ts`. The research auto, research confirm, review auto and review confirm YAMLs have identical first-write audit wiring and Copilot `@path` fallback logic, with design rationale in the spec packet's `decision-record.md` ADRs 010 through 013. No review-specific TypeScript was added.

## Upgrade

No migration required. Native-path review users see identical behavior. Non-native review users (`cli-codex`, `cli-copilot`, `cli-claude-code`) gain first-write executor provenance automatically. Large-prompt Copilot review invocations use the `@path` fallback. The retry-budget heuristic language is corrected. The rollback path is the same as `deep-research` v1.10.0.0.
