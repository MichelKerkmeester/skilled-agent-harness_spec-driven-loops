This release finishes what v1.5.0.0 started: Phase 018 wired `cli-codex` as the only new executor for review iterations. Two more, `cli-copilot` and `cli-claude-code`, were reserved in the config enum but rejected at load time. This release wires both for review, matching deep-research v1.9.0.0, while the YAML workflow keeps owning state, convergence, the findings registry and the reducer.

> Spec folder: `.opencode/specs/system-spec-kit/026-graph-and-context-optimization/017-sk-deep-cli-runtime-execution/002-runtime-matrix` (Level 3)

## What's New at a Glance

- **Review dispatch now accepts `kind: cli-copilot`.** It runs `copilot -p "PROMPT" --model X --allow-all-tools --no-ask-user` using the review-flavored prompt-pack template shipped in v1.5.0.0. The prompt is passed positionally because Copilot has no stdin, as in the research path.
- **Review also accepts `cli-claude-code` as an executor.** It runs `claude -p "PROMPT" --model claude-opus-4-6 --permission-mode acceptEdits --output-format text` with optional `--effort`. The required `plan` to `acceptEdits` permission-mode override lets Claude Code write the review narrative and append to the JSONL state log.
- **Review configuration validates flags by executor kind.** Each CLI has a different flag surface, so the shared config schema validates flags per kind. `executor-config.ts` applies its `EXECUTOR_KIND_FLAG_SUPPORT` map to review as it does to research, and `serviceTier` with `cli-copilot` produces the same typed error for review. No review-specific TypeScript was added, and the review path consumes the shared modules unchanged.
- **Non-native review runs record executor audits.** The `record_executor_audit` step from v1.5.0.0 fires on any non-native run. `cli-copilot` and `cli-claude-code` produce the same `executor` audit block as `cli-codex`, added to the last JSONL record per iteration alongside the full review dimension schema.
- **`deep-review.md` offers all four executor choices.** Q-Exec lists A for native, B for `cli-codex`, C for `cli-copilot` and D for `cli-claude-code`. It uses the same brief per-CLI notes as the research command, so executor selection works the same way in both iterative skills.
- **`SKILL.md` marks all three CLI kinds as shipped.** Its Executor Selection Contract table reports `Shipped (spec 019)`. The review JSONL schema is preserved unchanged across executors, and its requirements for `dimensions`, `filesReviewed`, `findingsSummary` and `newFindingsRatio` are unchanged from v1.5.0.0.
- **`SKILL.md` documents cross-CLI delegation as design intent.** Any review executor can shell out to other CLIs in theory. Self-recursion is forbidden, authentication and environment propagation between CLIs are the user's responsibility, and runtime enforcement is out of scope.
- **`references/loop-protocol.md` covers all four executor kinds.** Section 3 gives canonical dispatch shapes for review, including `review/prompts/`, the review JSONL schema and the `@deep-review` agent. It cites per-kind flag-compatibility enforcement in the shared validator.
- **Review and research ship the matrix in the same release cycle.** Shared `executor-config.ts`, `post-dispatch-validate.ts`, `executor-audit.ts` and `prompt-pack.ts` keep behavior bit-identical across the two iterative loops. The design rationale is in the spec packet's `decision-record.md`, ADR-006 through ADR-009.

## Upgrade

No migration required. The default `kind: native` is unchanged, and users already on `cli-codex` for review get no behavior change. Users previously blocked by `ExecutorNotWiredError` can now run `cli-copilot` or `cli-claude-code` for review.

To opt into a new CLI for review, invoke:

```
/deep:review :auto "target" \
  --executor=cli-claude-code \
  --model=claude-opus-4-6 \
  --reasoning-effort=high
```

Each CLI must be on PATH and authenticated. The shared validator enforces per-kind flag compatibility, and config parsing rejects a flag the chosen CLI does not support.
