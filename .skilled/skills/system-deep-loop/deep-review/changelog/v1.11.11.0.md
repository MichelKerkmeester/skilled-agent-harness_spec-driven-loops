# v1.11.11.0, A Short Routing Summary Opens the Skill and the Router Keeps Its Own Section

The deep-review skill opened with one long routing section that held both a summary and the router itself. A reader had to work through the loading levels, the scoring pseudocode and the phase table to find out what the skill does with a request. The section is now a short prose summary: what selects this packet, what it loads first and where the rest lives.

The router blocks did not change. The loading levels, the intent signals, the resource map, the fallback checklist and the discovery and phase pseudocode moved as they were to a final machine router section at the end of the file. Every intent, every resource path and every loading level is the same, so a request routes exactly where it did before.

> Spec folder: `specs/sk-doc/072-skill-routing-and-clarity/007-sk-design-and-deep-loop-hubs` (Level 2)

&nbsp;

## What's New at a Glance

- **The top of the skill reads as a summary.** A few lines say what selects deep-review, what loads first and where the router is, instead of tables and code.
- **The router keeps its own section.** The loading levels, the intent signals, the resource map, the fallback checklist and the pseudocode now sit together at the end of the file.
- **Nothing routes differently.** Every machine line is byte-identical to the previous release, and the manual-testing playbooks that named the old section number now name the new one.

&nbsp;

## Upgrade

No migration required. Anything that pointed at the routing section of this skill now points at the machine router section instead.
