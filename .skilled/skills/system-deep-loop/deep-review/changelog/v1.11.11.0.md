# v1.11.11.0, A Short Routing Summary Opens the Skill and the Router Keeps Its Own Section

The deep-review skill opened with one long routing section. It held both a summary and the router itself. A reader had to work through the loading levels, the scoring pseudocode and the phase table. Only then did they find out what the skill does with a request. The section is now a short prose summary. It says what selects this packet. It says what loads first and where the rest lives.

The router blocks did not change. The loading levels, the intent signals, the resource map and the fallback checklist moved as they were. So did the discovery and phase pseudocode. They went to a final machine router section. It sits at the end of the file. Every intent, every resource path and every loading level is the same. So a request routes exactly where it did before.

&nbsp;

## What's New at a Glance

- **The top of the skill reads as a summary.** A few lines say what selects deep-review. They say what loads first and where the router is. They stand in place of tables and code.
- **The router keeps its own section.** The loading levels, the intent signals, the resource map and the fallback checklist now sit together. So does the pseudocode. They are at the end of the file.
- **Nothing routes differently.** Every machine line is byte-identical to the previous release. The manual-testing playbooks that named the old section number now name the new one.

&nbsp;

## Upgrade

No migration required. Anything that pointed at the routing section of this skill now points at the machine router section instead.
