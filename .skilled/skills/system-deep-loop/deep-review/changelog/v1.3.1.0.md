This patch closes the remaining 042 closing-audit issues affecting `deep-review`. It brings the `deep-review` loop and its reducer into agreement with its documentation. It corrects five gaps. In each gap, the workflow promised behavior the runtime did not deliver.

> Spec folder: `.opencode/specs/skilled-agent-orchestration/042-deep-research-review-improvement-2/` (Level 3)

## Why This Release

A review could reach PASS with incomplete required evidence. Concurrent sessions could overwrite each other's coverage-graph nodes and edges. Dashboards or guidance could misstate whether a review was ready to finish.

## What's New at a Glance

- **New P0 and P1 findings require complete claim-adjudication packets.** Missing or malformed evidence can block a review from stopping.
- **Graph entries now include the review session in their identity.** Two sessions can write the same logical ID and keep both entries.
- **The interactive lifecycle gate offers only working choices.** Choose `resume`, `restart` or `cancel`. `fork` and `completed-continue` are deferred.
- **The canonical review agent now follows the reducer's format.** Findings written from its template no longer disappear from the review registry.
- **Stop-gate guidance now matches the `blocked_stop` event.** The third convergence signal is dimension coverage, not `Novelty Ratio`.
- **Active Risks now reports more than P0 findings.** Reviewers can see required work before synthesis.

## Review Workflow

#### Claim Packets Gate Each Stop

A claim-adjudication packet is a short JSON block. It names the claim and cites file-and-line evidence. It lists the counter-evidence the reviewer looked for. Then it records final severity and a confidence number. The documentation said the loop would refuse to stop. It would not stop until every new P0 or P1 finding had a valid packet. But the loop never read the flag that tracked this. So stop-checking ran as if a missing or incomplete packet were fine. Both interactive and autonomous review workflows run a universal pre-check. It comes first in every stop-check cycle. If the latest adjudication result failed, the workflow blocks stop. It gives a recovery message asking the reviewer to rewrite missing packets. The legal-stop decision tree gains a dedicated gate. That gate surfaces adjudication status alongside the other five gates. The result is persisted to the state log as a typed event. So the next iteration can read it back.

&nbsp;

#### Only Supported Lifecycle Choices

When an operator re-entered a review session, the interactive workflow offered `resume` (continue where you left off) and `restart`. It also offered `fork` (start a sibling run history). It offered `completed-continue` as well (reopen a finished run after snapshotting its synthesis). Only `resume` and `restart` were implemented. Selecting either unsupported mode did not branch the run. The state log silently kept the same session ID. That left earlier work open to overwrite. `fork` and `completed-continue` are now explicitly deferred. The skill guidance, workflows and runtime mirrors all mark both modes as deferred. The gate offers `resume`, `restart` or `cancel`. `restart` starts a new generation. Both paths append a typed event to the state log. That event carries the run history fields. They are session ID, parent session ID, run history mode, continued-from-run, generation, archive path and timestamp.

## Review Evidence

#### Concurrent Sessions Keep Their Graph Entries

The coverage graph cache was shared by all review sessions in a spec folder. It used bare logical IDs such as `d-correctness` and `f-001`. Concurrent sessions could write nodes or edges with the same ID. The later write replaced the earlier content, even though filtered reads still worked. Graph entries are now scoped to their spec folder and review session. Loop type and logical ID are included in the identity. This preserves same-ID nodes and edges in separate sessions.

**Breaking:** Direct callers outside the module cannot use the former bare-ID graph helper signatures. The break is at the type level and intentional. That is because the new signatures make it impossible to reference a node or edge. Every reference must be scoped to a session.

&nbsp;

#### Review Findings Match the Reducer

The canonical `deep-review` agent's authoring skeleton did not match the reducer's strict input format. Its top-level heading differed. Its section names and finding bullets differed too. A reviewer following that skeleton could produce iterations the reducer silently dropped. That left the review registry empty while the loop continued. Every heading, subsection and bullet shape in the skeleton now matches the reducer parser exactly. The matching headings include:

- `## Focus`
- `## Findings`
- `## Ruled Out`

The skeleton flags the format as parser-sensitive. It includes a ready-to-copy claim-adjudication packet example. The `completed-continue` snapshot wording was retracted. The new prose says to preserve machine-owned markers.

## Review Guidance

#### Stop Guidance Matches Saved Events

The convergence reference described a nested `legalStop` record that the workflow never wrote. The actual blocked-stop record is a top-level `blocked_stop` event. It has a flat gate-results map and a recovery-strategy hint. Tools built on the documented shape got no matches. The reference now shows the actual event shape. It also lists the six gate names the workflow emits. It gives a worked example with non-trivial values.

The reference also corrects the third convergence signal. It moves from `Novelty Ratio` to dimension coverage. Every configured review dimension must be reached by at least one iteration. It must also remain stable for one extra pass. The severity-weighted new-findings ratio feeds the rolling-average and noise-floor signals. It does not cast its own stop vote.

&nbsp;

#### Active Risks Show Review Debt

Active Risks on the dashboard previously checked only for P0 findings. So it could report `None active beyond normal review uncertainty`. That happened when P1 findings, a failed claim-adjudication gate or a rejected blocked-stop event remained. It now reports the latest iteration error. It also counts active P0 and P1 findings. It includes the latest adjudication failure. It also lists the findings that lack packets. It also includes the latest blocked-stop event. That event shows its blockers and recovery hint. The P2 tech-debt count appears only when no higher-severity debt is present. `None active` means the session is clean rather than merely free of P0 findings.

## Upgrade Notes

- **Adjudicate findings.** Emit a complete typed claim-adjudication packet for every new P0 or P1 finding. Missing or malformed packets veto stop on the next convergence check.
- **Update direct graph calls.** Pass the namespace as the first argument to:
  - `getNode(id)`
  - `getEdge(id)`
  - `getEdgesFrom(sourceId)`
  - `getEdgesTo(targetId)`
  - `updateEdge(id, updates)`
  - `deleteNode(id)`
  - `deleteEdge(id)`
- **Handle deferred lifecycle modes.** If you planned to use `fork` or `completed-continue`, you should archive the prior `review/` folder manually. Or choose `restart`, which archives it and starts a new generation.

Existing review packets and state logs remain readable. The state-log format did not change. No state-log migration is required. The graph database is a derived cache that rebuilds itself from iteration events. So its version bump is transparent.
