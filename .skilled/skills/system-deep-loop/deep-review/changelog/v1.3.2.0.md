# v1.3.2.0, Deep Review Becomes Easier to Trust

This patch release corrects reducer behavior.

- The reducer now records terminal stop metadata.
- Adjudication now sets finding severity.
- Corrupt JSONL is checked before output writes.

It isolates session scope and aligns workflow behavior with expectations.

- Lifecycle events now shape review history.
- Blocked-stop events now carry graph blocker detail.
- Review dimensions now share one normalization.

It corrects reference documentation.

- The iteration skeleton now follows one template.
- `convergence.md` now follows the persisted `blocked_stop` schema.
- Deep review is easier to trust in everyday use.

&nbsp;

## Why This Release

The fixes make the workflow more predictable in normal use.

## Review State

These fixes correct reducer behavior. They make the workflow more predictable in normal use.

#### Completion Events Set Terminal State <a id="c-completion-events-set-terminal-state"></a>

- Before this change, the reducer ignored `synthesis_complete`.
- It based dashboard status on stale config.
- It now parses the latest `synthesis_complete` JSONL record.
- It derives `stopReason` and the terminal legal-stop bundle.

#### Run History Tracks Restarts <a id="c-run-history-tracks-restarts"></a>

- The `resumed` and `restarted` events were emitted to JSONL.
- They never reached config-visible fields.
- The dashboard showed run history mode as `new` after a resume.
- The reducer now detects those events.
- It updates `parentSessionId`, `continuedFromRun` and run historyMode in the registry and dashboard.

#### Adjudication Sets Final Severity <a id="c-adjudication-sets-final-severity"></a>

- The reducer ignored `finalSeverity` from claim-adjudication packets.
- So the findings registry kept the original severity when adjudication changed it.
- It now parses `claim_adjudication` events by `findingId`.
- It uses `finalSeverity` as the main registry value.
- It seeds transitions from the packet.

#### Resolved Findings Clear Vetoes <a id="c-resolved-findings-clear-vetoes"></a>

- A failed adjudication could leave a STOP veto on the dashboard after all active P0/P1 findings were resolved.
- The veto is surfaced only when the latest failed adjudication still applies to active P0/P1 findings.

#### Corrupt Logs Stop Before Writes <a id="c-corrupt-logs-stop-before-writes"></a>

- The reduce review state helper silently continued on corrupt JSONL when `lenient` was false.
- It wrote output files before checking for corruption.
- Corruption checking now runs before any file writes.
- When corruption is detected and `lenient` is false, the function throws a structured error.

#### `ACTIVE RISKS` Avoids Raw Objects <a id="c-active-risks-avoids-raw-objects"></a>

- The blocked-stop dashboard path rendered raw objects as `[object Object]`.
- A list-formatting helper was added.
- The `ACTIVE RISKS` section now reuses normalized entries from `blockedStopHistory`.

#### Blocked Stops Include Graph Details <a id="c-blocked-stops-include-graph-details"></a>

- The `deep_review_auto.yaml` and `_confirm.yaml` workflows emitted `blocked_stop` events without the structured `graphBlockerDetail` payload.
- Both workflows now include that payload in the emitted event.

#### Dimensions Share One Parse <a id="c-dimensions-share-one-parse"></a>

- The dimensions array was parsed in two places.
- This created divergent sources of truth.
- Initialization now normalizes it once.
- The same parsed array feeds `deep-review-config.json` and the JSONL config row.

## Review Documentation

These fixes correct reference documentation. Deep review is easier to trust in everyday use.

#### Iterations Follow One Template <a id="c-iterations-follow-one-template"></a>

- The agent definition in `deep-review.md` had an internally contradictory iteration skeleton.
- Its heading names differed from the reducer parser's expected sections.
- It now has one main fenced template.
- The template matches the sections `reduce-state.cjs` consumes.

#### Blocked Stops Use One Schema <a id="c-blocked-stops-use-one-schema"></a>

- Later sections of `convergence.md` had remaining `legalStop` references.
- Those references now use the persisted `blocked_stop` event schema throughout.

#### Replay Guidance Matches Behavior <a id="c-replay-guidance-matches-behavior"></a>

- `loop_protocol.md` contained conflicting delta-replay text.
- That text was removed.
- The file now describes full-history replay.
- This is what the reducer does.

#### Review Modes Match Three Options <a id="c-review-modes-match-three-options"></a>

- `review_mode_contract.yaml` listed `fork` and `completed-continue` as live review modes.
- It now lists only `new`, `resume` and `restart`.
