This patch release corrects reducer behavior, isolates session scope, aligns workflow behavior with expectations and corrects reference documentation, making deep review easier to trust in everyday use.

> Spec folder: `.opencode/specs/skilled-agent-orchestration/042-deep-research-review-improvement-2/` (Level 3)

## Why This Release

The fixes make the workflow more predictable in normal use.

## What's New at a Glance

- **The reducer now records terminal stop metadata.** The dashboard can reflect how a loop stopped.
- **Lifecycle events now shape review history.** The dashboard can reflect a resumed run.
- **Adjudication now sets finding severity.** The findings registry uses the adjudicated value.
- **The STOP veto reflects the latest failed adjudication.** It appears only while that adjudication applies to active P0/P1 findings.
- **Corrupt JSONL is checked before output writes.** Corruption detected with `lenient` false produces a structured error.
- **`ACTIVE RISKS` now uses normalized blocked-stop entries.** The dashboard avoids displaying raw objects.
- **Blocked-stop events now carry graph blocker detail.** The review workflows include the structured payload.
- **Review dimensions now share one normalization.** Both configuration outputs use the same parsed array.
- **The iteration skeleton now follows one template.** Its headings match the sections the reducer consumes.
- **`convergence.md` now follows the persisted `blocked_stop` schema.** Later guidance uses the event's persisted form.
- **`loop_protocol.md` now gives one replay account.** Its guidance describes full-history replay.
- **Review mode guidance now lists three choices.** The live modes are `new`, `resume` and `restart`.

## Review State

#### Completion Events Set Terminal State

Before this change, the reducer ignored `synthesis_complete` and based dashboard status on stale config. It now parses the latest `synthesis_complete` JSONL record to derive `stopReason` and the terminal legal-stop bundle.

&nbsp;

#### Run History Tracks Restarts

The `resumed` and `restarted` events were emitted to JSONL but never reached config-visible fields. The dashboard showed run history mode as `new` after a resume. The reducer now detects those events and updates `parentSessionId`, `continuedFromRun` and run historyMode in the registry and dashboard.

&nbsp;

#### Adjudication Sets Final Severity

The reducer ignored `finalSeverity` from claim-adjudication packets, so the findings registry kept the original severity when adjudication changed it. It now parses `claim_adjudication` events by `findingId`, uses `finalSeverity` as the main registry value and seeds transitions from the packet.

&nbsp;

#### Resolved Findings Clear Vetoes

A failed adjudication could leave a STOP veto on the dashboard after all active P0/P1 findings were resolved. The veto is surfaced only when the latest failed adjudication still applies to active P0/P1 findings.

&nbsp;

#### Corrupt Logs Stop Before Writes

The reduce review state helper silently continued on corrupt JSONL when `lenient` was false and wrote output files before checking for corruption. Corruption checking now runs before any file writes. When corruption is detected and `lenient` is false, the function throws a structured error.

&nbsp;

#### `ACTIVE RISKS` Avoids Raw Objects

The blocked-stop dashboard path rendered raw objects as `[object Object]`. A list-formatting helper was added, and the `ACTIVE RISKS` section now reuses normalized entries from `blockedStopHistory`.

&nbsp;

#### Blocked Stops Include Graph Details

The `deep_review_auto.yaml` and `_confirm.yaml` workflows emitted `blocked_stop` events without the structured `graphBlockerDetail` payload. Both workflows now include that payload in the emitted event.

&nbsp;

#### Dimensions Share One Parse

The dimensions array was parsed in two places, creating divergent sources of truth. Initialization now normalizes it once, and the same parsed array feeds `deep-review-config.json` and the JSONL config row.

## Review Documentation

#### Iterations Follow One Template

The agent definition in `deep-review.md` had an internally contradictory iteration skeleton because its heading names differed from the reducer parser's expected sections. It now has one main fenced template matching the sections `reduce-state.cjs` consumes.

&nbsp;

#### Blocked Stops Use One Schema

Later sections of `convergence.md` had remaining `legalStop` references. Those references now use the persisted `blocked_stop` event schema throughout.

&nbsp;

#### Replay Guidance Matches Behavior

`loop_protocol.md` contained conflicting delta-replay text. That text was removed, and the file now describes full-history replay, which is what the reducer does.

&nbsp;

#### Review Modes Match Three Options

`review_mode_contract.yaml` listed `fork` and `completed-continue` as live review modes. It now lists only `new`, `resume` and `restart`.
