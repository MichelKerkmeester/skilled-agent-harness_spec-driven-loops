As the deep-review portion of the packets 108 plus 110 auto-review uplift, this release applies four reusable teachings from the upstream `dzianisv/opencode-plugins` auto-review package to every deep-review iteration, all as prompt and dispatcher-config changes with no source-code changes. Because current prompts pass state and metadata pointers rather than embedded file contents and let reviewers fetch evidence on demand, H-9 bounded evidence, first proposed in packet 106 to keep oversized embedded file content from crowding out context, is deferred to packet 111 plus and will be revisited if an interpolating path is introduced. Implementation followed via `cli-opencode + deepseek-v4-pro --pure`.

> Spec folder: `.opencode/specs/skilled-agent-orchestration/108-auto-review-quick-wins-verdict-markers-logging` and `.opencode/specs/skilled-agent-orchestration/110-auto-review-stretch-config-dedup-gates` (Level 3)

## What's New at a Glance

- **Deep-review iterations end with a parseable plain-text verdict.** Iterations used to end with prose, so synthesis and dispatch logic had to guess the outcome. Each iteration must end with a plain-text final line of the form `Review verdict: PASS`, `Review verdict: CONDITIONAL` or `Review verdict: FAIL`, not Markdown bold. PASS means no P0 or P1 findings, CONDITIONAL means at least one P1 but no P0 and FAIL means any P0. `deep-review-auto.yaml` and `deep-review-confirm.yaml` derive the verdict from actual P0 and P1 counts and correct a misreported line before synthesis.
- **The rendered deep-review prompt keeps its role marker at the top.** Long iterations occasionally drifted off-role when the banner scrolled out of context. `prompt_pack_iteration.md.tmpl` now starts with `DEEP-REVIEW`, and both `deep-review-auto.yaml` and `deep-review-confirm.yaml` fail fast if rendering omits it. Reference templates that ship YAML frontmatter were left untouched because a marker inside frontmatter would corrupt the loader.
- **The deep-review skill prohibits restating findings across iterations.** Its `SKILL.md` `CONSTRAINTS` section tells reviewers to omit a finding from an earlier iteration of the same review or extend its original entry with new evidence. The reviewer carries the intent through iteration n while still seeing iterations 1 through n minus 1 in context.
- **Synthesis dedup now catches cross-dimension and wording-drift matches.** The old file-plus-line-plus-normalized-title key missed cross-dimension restatements and minor wording drift, so the existing synthesis path, not a parallel one, now checks `content_hash = sha256(file_path + line_range + finding_type + normalized_description_80chars)` first, falls back to the legacy key for records that predate this release and collapses matches into one entry with `dimensions: [<list>]`, naming every dimension that surfaced the finding.
- **Deep-research is not included in H-7 dedup.** It is single-dimension, and its changelog documents this decision for the same release window.

## Upgrade

No migration required. Historical packets do not need rerunning, and reviewers picking up the new prompts start emitting the final-line verdict and cross-dimension dedup metadata immediately. Source commits: 73e9e361e, 74782acfb, 8b3039a1a.
