This release is the deep-review portion of the packets 108 plus 110 auto-review uplift. It applies four reusable teachings to every deep-review iteration. The teachings come from the upstream `dzianisv/opencode-plugins` auto-review package. All changes are prompt and dispatcher-config changes. No source code changed.

Current prompts pass state and metadata pointers, not embedded file contents. Reviewers fetch evidence on demand. So H-9 bounded evidence is deferred to packet 111 plus. Packet 106 first proposed it, to keep oversized embedded file content from crowding out context. It will be revisited if an interpolating path is introduced.

Implementation followed via `cli-opencode + deepseek-v4-pro --pure`.

## What's New at a Glance

- **Deep-review iterations end with a parseable plain-text verdict.** Iterations used to end with prose. So synthesis and dispatch logic had to guess the outcome. Each iteration must end with a plain-text final line. The form is `Review verdict: PASS`, `Review verdict: CONDITIONAL` or `Review verdict: FAIL`. It is not Markdown bold. PASS means no P0 or P1 findings. CONDITIONAL means at least one P1 but no P0. FAIL means any P0. `deep-review-auto.yaml` and `deep-review-confirm.yaml` derive the verdict from actual P0 and P1 counts. They correct a misreported line before synthesis.
- **The rendered deep-review prompt keeps its role marker at the top.** Long iterations occasionally drifted off-role. That happened when the banner scrolled out of context. `prompt_pack_iteration.md.tmpl` now starts with `DEEP-REVIEW`. Both `deep-review-auto.yaml` and `deep-review-confirm.yaml` fail fast if rendering omits it. Reference templates that ship YAML frontmatter were left untouched. A marker inside frontmatter would corrupt the loader.
- **The deep-review skill prohibits restating findings across iterations.** Its `SKILL.md` `CONSTRAINTS` section gives reviewers two options. They omit a finding from an earlier iteration of the same review. Or they extend its original entry with new evidence. The reviewer carries the intent through iteration n. It still sees iterations 1 through n minus 1 in context.
- **Synthesis dedup now catches cross-dimension and wording-drift matches.** The old file-plus-line-plus-normalized-title key missed cross-dimension restatements. It also missed minor wording drift. So the existing synthesis path now checks `content_hash = sha256(file_path + line_range + finding_type + normalized_description_80chars)` first. It is not a parallel path. It falls back to the legacy key for records that predate this release. It collapses matches into one entry with `dimensions: [<list>]`. That entry names every dimension that surfaced the finding.
- **Deep-research is not included in H-7 dedup.** It is single-dimension. Its changelog documents this decision for the same release window.

## Upgrade

No migration required. Historical packets do not need rerunning. Reviewers picking up the new prompts start emitting the final-line verdict immediately. They also start emitting cross-dimension dedup metadata immediately. Source commits: 73e9e361e, 74782acfb, 8b3039a1a.
