# v1.3.0.0, Deep Review

This release changes how the live review loop runs and stops.

- Phase 008 of the 042 Deep Research & Review Runtime Improvement Bundle changes `deep-review`.
- The live review loop now uses the coverage graph.
- Blocked-stop bundles persist through reducer-owned surfaces.

Bad input now stops the review instead of passing quietly.

- Malformed JSONL now fails loudly instead of silently.
- So do missing machine-owned anchors.

Recurring findings get separate buckets while behavior stays stable.

- `repeatedFindings` is split into `persistentSameSeverity` and `severityChanged`.
- That gives more precise triage.
- Idempotency is preserved.

> [!IMPORTANT]
> 2 changes can break an existing setup. Read these before you update.
>
> 1. Malformed JSONL makes the reducer exit non-zero. [Corrupt Inputs Surface as Errors](#c-corrupt-inputs-surface-as-errors)
> 2. Missing machine-owned anchors now fail closed. [Corrupt Inputs Surface as Errors](#c-corrupt-inputs-surface-as-errors)

&nbsp;

## Why This Release

The goal is to make the workflow easier to follow and easier to trust.

- Malformed JSONL was silently dropped.
- Recurring findings and severity changes shared one field.

## Review Flow

This area covers how the loop reaches a stop. This release adds gate context, graph evidence, frozen pause names and session isolation.

#### Blocked Stops Carry Gate Context <a id="c-blocked-stops-carry-gate-context"></a>

- `step_emit_blocked_stop` adds a `blocked_stop` JSONL event to both review workflows.
- The event carries the full `blockedBy` / `gateResults` / `recoveryStrategy` payload.
- The gates are `convergenceGate` and `dimensionCoverageGate`.
- They also include `p0ResolutionGate` and `evidenceDensityGate`.
- `hotspotSaturationGate` is the fifth gate.
- The reducer no longer drops non-iteration events.
- Its blocked-stop history builder scans `blocked_stop` rows.
- It supports the legacy nested `legalStop` payload shape.
- It exposes `blockedStopHistory` as a registry field.

#### Pause Reasons Use Frozen Names <a id="c-pause-reasons-use-frozen-names"></a>

- `step_normalize_pause_events` rewrites raw `paused` to `userPaused` and `stuck_recovery` to `stuckRecovery` at emission time.
- The names come from the frozen `STOP_REASONS` enum.
- Emitted events use the frozen names.

#### Graph Evidence Guards Stops <a id="c-graph-evidence-guards-stops"></a>

- The `deep_review_{auto,confirm}.yaml` workflows call `deep_loop_graph_upsert` after `step_reduce_review_state`.
- They call `deep_loop_graph_convergence` before the inline review convergence vote in `step_check_convergence`.
- `STOP` requires both the inline vote and graph decision to agree.
- `STOP_BLOCKED` routes to blocked-stop emission.
- `buildGraphConvergenceRollup(records)` scans `graph_convergence` JSONL events.
- It adds `graphConvergenceScore` and `graphDecision` to the registry alongside `convergenceScore`.
- It also adds `graphBlockers` there.
- The OpenCode `deep-review` agent gains explicit graph tool permissions.
- The Claude agent mirrors them.

#### Concurrent Reviews Keep Separate State <a id="c-concurrent-reviews-keep-separate-state"></a>

- Shared coverage-graph reads accept and propagate `sessionId`.
- Review packets with multiple concurrent sessions no longer bleed across each other's graph state.

## Reducer and Triage

This area covers malformed input and finding history. Bad input now fails closed and findings split by severity history.

#### Corrupt Inputs Surface as Errors <a id="c-corrupt-inputs-surface-as-errors"></a>

> [!WARNING]
> Malformed JSONL makes the v1.3.0.0 reducer exit non-zero. Pass `--lenient` to preserve the prior fail-open behavior while still reporting corruption in the registry.
> Missing machine-owned anchors now fail closed. Pass `--create-missing-anchors` or `createMissingAnchors:true` or create the missing anchor blocks manually to bootstrap.

- `parseJsonl` is backed by `parseJsonlDetailed`.
- That helper collects malformed lines in `corruptionWarnings` instead of silently dropping them.
- `parseJsonl` continues to return the plain records array for backward compatibility.
- When `corruptionWarnings.length > 0`, the reduce review state helper warns on stderr.
- It then exits with code `2`.
- The CLI's `--lenient` option preserves the v1.2.0.0 fail-open behavior for legacy packets.
- So does the `lenient:true` function option.
- The replace anchor section helper throws `Error('Missing machine-owned anchor "<id>" in deep-review strategy file...')` when a required anchor is absent.

#### Severity History Guides Triage <a id="c-severity-history-guides-triage"></a>

- `repeatedFindings` is deprecated and retained as a backward-compatible union of two arrays.
- `persistentSameSeverity` contains findings observed in at least two iterations without severity transitions.
- It holds only the initial discovery entry.
- `severityChanged` contains findings with one or more P0↔P1↔P2 transitions in their `transitions` history.
- The dashboard shows both counters in TREND.
- That makes triage at 50+ findings possible.
- It does so without conflating a recurring finding with a severity upgrade.

## Dashboard and Recovery

This area covers what the dashboard shows and how next-iteration direction is chosen.

#### Reducer State Has Dedicated Sections <a id="c-reducer-state-has-dedicated-sections"></a>

- The dashboard adds a `BLOCKED STOPS` section.
- It also adds `GRAPH CONVERGENCE` and `CORRUPTION WARNINGS` sections.
- Entries show timestamps, gate result summaries and recovery strategy hints.

#### Next Focus Prefers the Latest Blocker <a id="c-next-focus-prefers-the-latest-blocker"></a>

- The strategy `next-focus` anchor prefers the latest blocked-stop `recoveryStrategy`.
- It does this when a blocked stop is the most recent loop event.
- Operators see the blocker before choosing next-iteration direction.

## Upgrade Notes

Existing packets stay backward-compatible as long as their JSONL files are clean and their strategy files have all machine-owned anchors.

#### Before You Start <a id="c-before-you-start"></a>

1. Check that your JSONL files are clean.
2. Check that your strategy files have all machine-owned anchors.
3. Packets created under v1.3.0.0 or later need no migration.

<details>
<summary><b>Reducer and Triage</b></summary>

- For malformed JSONL, pass `--lenient` to preserve fail-open behavior while corruption is still reported in the registry.
- For missing anchors, pass `--create-missing-anchors` or `createMissingAnchors:true` or create the blocks manually.
- Consumers of `repeatedFindings` can continue using its deprecated union of `persistentSameSeverity` and `severityChanged`.
- New code should read the split arrays directly.
