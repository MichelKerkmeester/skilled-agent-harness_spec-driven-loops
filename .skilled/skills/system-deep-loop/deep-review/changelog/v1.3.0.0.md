Phase 008 of the 042 Deep Research & Review Runtime Improvement Bundle makes `deep-review` use the coverage graph during the live review loop and persist blocked-stop bundles through reducer-owned surfaces. Malformed JSONL and missing machine-owned anchors now fail loudly instead of silently. `repeatedFindings` is split into `persistentSameSeverity` and `severityChanged` for more precise triage. Idempotency is preserved.

## Why This Release

The goal is to make the workflow easier to follow and easier to trust.

## What's New at a Glance

- **Blocked-stop events capture review gates.** Both review workflows include blocker and recovery details.
- **Graph evidence helps govern stops.** The loop uses graph decisions alongside its inline vote.
- **Coverage-graph reads carry `sessionId`.** Concurrent review sessions no longer bleed across graph state.
- **Pause reasons use normalized names.** Emitted events use the frozen names.
- **Malformed JSONL fails loudly.** Corrupted input is surfaced instead of silently dropped.
- **Missing machine-owned anchors fail closed.** The replace anchor section helper throws when a required anchor is absent.
- **Recurring findings split by severity history.** `persistentSameSeverity` and `severityChanged` give distinct triage buckets.
- **The dashboard surfaces reducer state.** It shows blocked stops, graph convergence and corruption warnings.
- **Next focus favors the latest blocker.** The strategy anchor prefers blocked-stop recovery when that event is the latest loop event.

## Review Flow

#### Blocked Stops Carry Gate Context

`step_emit_blocked_stop` adds a `blocked_stop` JSONL event to both review workflows. The event carries the full `blockedBy` / `gateResults` / `recoveryStrategy` payload. The gates are `convergenceGate` and `dimensionCoverageGate`. They also include `p0ResolutionGate` and `evidenceDensityGate`. `hotspotSaturationGate` is the fifth gate. The reducer no longer drops non-iteration events. Its blocked-stop history builder scans `blocked_stop` rows and supports the legacy nested `legalStop` payload shape. It exposes `blockedStopHistory` as a registry field.

&nbsp;

#### Pause Reasons Use Frozen Names

`step_normalize_pause_events` rewrites raw `paused` to `userPaused` and `stuck_recovery` to `stuckRecovery` at emission time. The names come from the frozen `STOP_REASONS` enum.

&nbsp;

#### Graph Evidence Guards Stops

The `deep_review_{auto,confirm}.yaml` workflows call `deep_loop_graph_upsert` after `step_reduce_review_state`. They call `deep_loop_graph_convergence` before the inline review convergence vote in `step_check_convergence`. `STOP` requires both the inline vote and graph decision to agree. `STOP_BLOCKED` routes to blocked-stop emission. `buildGraphConvergenceRollup(records)` scans `graph_convergence` JSONL events. It adds `graphConvergenceScore` and `graphDecision` to the registry alongside `convergenceScore`. It also adds `graphBlockers` there. The OpenCode `deep-review` agent gains explicit graph tool permissions, and the Claude agent mirrors them.

&nbsp;

#### Concurrent Reviews Keep Separate State

Shared coverage-graph reads accept and propagate `sessionId`. Review packets with multiple concurrent sessions no longer bleed across each other's graph state.

## Reducer and Triage

#### Corrupt Inputs Surface as Errors

`parseJsonl` is backed by `parseJsonlDetailed`, which collects malformed lines in `corruptionWarnings` instead of silently dropping them. `parseJsonl` continues to return the plain records array for backward compatibility. When `corruptionWarnings.length > 0`, the reduce review state helper warns on stderr and exits with code `2`. The CLI's `--lenient` option and the `lenient:true` function option preserve the v1.2.0.0 fail-open behavior for legacy packets. The replace anchor section helper throws `Error('Missing machine-owned anchor "<id>" in deep-review strategy file...')` when a required anchor is absent.

&nbsp;

#### Severity History Guides Triage

`repeatedFindings` is deprecated and retained as a backward-compatible union of two arrays. `persistentSameSeverity` contains findings observed in at least two iterations without severity transitions and only the initial discovery entry. `severityChanged` contains findings with one or more P0↔P1↔P2 transitions in their `transitions` history. The dashboard shows both counters in TREND, making triage at 50+ findings possible without conflating a recurring finding with a severity upgrade.

## Dashboard and Recovery

#### Reducer State Has Dedicated Sections

The dashboard adds a `BLOCKED STOPS` section. It also adds `GRAPH CONVERGENCE` and `CORRUPTION WARNINGS` sections. Entries show timestamps, gate result summaries and recovery strategy hints. Two new manual playbook scenarios in `manual-testing-playbook/04--convergence-and-recovery/`, `blocked-stop-reducer-surfacing.md` and `023-stop with an error-reducer.md`, cover blocked-stop surfacing and fail-closed behavior. The same directory also contains `fail-closed-reducer.md`, a manual test for fail-closed behavior.

&nbsp;

#### Next Focus Prefers the Latest Blocker

The strategy `next-focus` anchor prefers the latest blocked-stop `recoveryStrategy` when a blocked stop is the most recent loop event. Operators see the blocker before choosing next-iteration direction.

## Upgrade Notes

- Existing packets stay backward-compatible as long as their JSONL files are clean and their strategy files have all machine-owned anchors.
- **Breaking:** For malformed JSONL, the v1.3.0.0 reducer exits non-zero. Pass `--lenient` to preserve the prior fail-open behavior while still reporting corruption in the registry.
- **Breaking:** For missing machine-owned anchors, pass `--create-missing-anchors` or `createMissingAnchors:true` or create the missing anchor blocks manually to bootstrap.
- Consumers of `repeatedFindings` can continue using its deprecated union of `persistentSameSeverity` and `severityChanged`. New code should read the split arrays directly.
- Packets created under v1.3.0.0 or later need no migration.
