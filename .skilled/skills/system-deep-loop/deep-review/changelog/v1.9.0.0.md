This release brings `deep-review`'s documentation into line with current sk-doc templates. It also aligns the docs with the Human Voice Rules. The README, runtime guide, references, assets, feature catalog and playbook are updated. No behavioral code ships. The reducer (`scripts/reduce-state.cjs`) was bug-scan only, under the surgical-edit policy.

Work ran in three phases inside packet `131/000/003-deep-review`. A Level-3 spec packet was authored end-to-end. A surgical audit produced 23 schema-validated findings. Every actionable finding was resolved or formally closed with rationale. Zero deferrals shipped. The README rewrite then closed the release.

## Why This Release

The documentation baseline is set before the broader 116-deep-skill-evolution arc begins.

---

## What's New at a Glance

- **The README follows the nine-section `system-spec-kit/README.md` pattern.** Readers can navigate `deep-review` through a familiar structure.
- **The runtime `SKILL.md` moves implementation details out of its activation section.** Its version frontmatter now aligns with this release.
- **All four reference files gain a `When to Use` subsection.** The convergence threshold guidance has a dedicated reference home.
- **The asset dashboard intro is shorter.** The raw prompt template avoids structural changes that would affect rendered prompts.
- **Resource Map Emission is now listed in the root feature catalog.** The catalog totals 21 entries: one root entry and 20 feature snippets.
- **The playbook index now includes the missing stress-test groups.** Readers can find command-flow and review-depth scenarios in the index.
- **Twelve current-document references were migrated to `deep-loop-runtime`.** They span the `SKILL.md`, references and playbook tests.
- **Playbook command and corpus references are corrected.** The stress-test path and sample extension now match their targets.
- **Four colliding playbook basenames now match their DRV IDs.** Tooling that identifies scenarios by DRV ID continues to work.
- **The surgical audit closed all 23 findings.** No findings were deferred or left open.

## Skill Documentation

#### A Familiar README

The previous README ran in a mixed technical voice. That voice predated the shift toward marketing-leaning HVR copy. The rewrite covers every unique feature in the catalog. The catalog holds 21 entries. They span loop lifecycle, state management, review dimensions and severity. Cross-system links name explicit target paths. The voice was calibrated to roughly 70 percent of the root `Public/README.md` voice.

&nbsp;

#### Runtime Guide Moves

The `Executor Selection Contract` and `Code-Graph Readiness TrustState` moved from section 1 to section 3. That is because they describe how the skill works, not when to invoke it. The two REFERENCES sections merged into one. A packet-citation parenthetical left a section heading. A deprecated planning placeholder was removed.

The frontmatter changed from 1.4.0.0 to 1.9.0.0. That matches the changelog stream after entries had reached 1.8.0.0. The Smart Router section was preserved exactly as shipped. Convergence math, severity model, verdict logic, state schemas and JSONL events did not change. So the runtime contract needs no migration. Any consumer reading `SKILL.md`, the four `references/`, the asset templates, or the JSONL contract continues to work without code changes.

&nbsp;

#### Reference Guide Navigation

The four files are `convergence.md`, `loop_protocol.md`, `state_format.md` and `quick_reference.md`. Each one places `### When to Use` inside `## 1. OVERVIEW`. The convergence threshold semantics block moved from the `SKILL.md` preamble to `references/convergence.md`. The references' meta-commentary line was removed. So were 33 em dash marks. The wording changed from `seamlessly` to `cleanly`.

&nbsp;

#### Asset Template Boundaries

Two markdown assets and one prompt template had 19 em dash marks removed between them. The asset dashboard intro went from three sentences to two. `prompt_pack_iteration.md.tmpl` stayed structurally unchanged. That is because `prompt-pack.ts` consumes it as a raw template through `readFileSync`. Adding YAML frontmatter would inject metadata text into the rendered agent prompt. So would condensing the intro or inserting horizontal rules. So the template-conformance rules in `skill_asset_template.md` do not apply to that file.

&nbsp;

#### Audit Findings Closed

The closeout included 2 P0, 8 P1 and 13 P2 findings. Zero were deferred and zero stayed open. Every actionable finding was resolved or formally closed with rationale.

Five findings were closed as resolved-with-rationale rather than edited away. Three concerned the raw-template exception for `prompt_pack_iteration.md.tmpl`. One corrected the audit's claim that historical changelogs failed the current template convention. Later `####` category subheaders had been counted as leading H1s. One confirmed that the playbook root frontmatter already carried a description field.

The root `feature-catalog/feature-catalog.md` was missing one of six loop-lifecycle entries. The missing entry was Resource Map Emission. Its snippet `06-resource-map-emission.md` already existed on disk. The new entry sits in the correct position and links to that snippet.

The two stress-test categories had no body sections. They were also absent from the index. Sections 15 and 16 now give per-scenario summaries. ## Deep-Review Paths

#### Current Runtime Destinations

The 118-FULL_ISOLATE_NO_MCP arc moved deep-loop code out of `system-spec-kit/mcp-server/`. It moved into the peer `deep-loop-runtime/` skill. But deep-review's docs did not get the memo. Twelve current-document references now point to the new locations. They span the `SKILL.md`, references and playbook tests. The targets are `deep-loop-runtime/lib/deep-loop/`, `deep-loop-runtime/lib/coverage-graph/` and `deep-loop-runtime/tests/integration/`. The review graph-events playbook scenario now verifies the current `LoopType='review'` contract in `coverage-graph-db.ts`. It no longer checks an archived test.

&nbsp;

#### Current Commands and Corpus

Two stress-test references changed from `commands/speckit/deep-review.md` to `commands/deep/review.md`. The `sample-040-corpus.json` typo now uses the `.jsonl` extension. Seven historical changelog references in v1.0.0.0 through v1.3.1.0 were preserved as written. That keeps the chronological record accurate for paths that existed when those entries were authored.

&nbsp;

#### Playbook Filename Alignment

Files numbered 015 and 021 through 023 sit in `manual-testing-playbook/04--convergence-and-recovery/`. They collided with files in sibling directories, even though they mapped to different DRV IDs. They were renamed to match the stop-on-max-iterations, graph-convergence, blocked-stop-history and fail-closed-reducer scenarios, respectively. One updated basename is `stop-on-max-iterations.md`. The review graph-events, stop-on-max-iterations, graph-convergence, blocked-stop-history and fail-closed-reducer scenarios carry the same contracts as before. Tooling keyed to DRV IDs continues to work. Fourteen cross-references elsewhere pointed to old filenames. They were updated in the same commit. The v1.2.0.0 and v1.3.0.0 changelogs also had their internal path references patched. Their historical structure was preserved. **Breaking:** Tooling keyed to the old basenames must update to the new ones.
