This release brings `deep-review`'s documentation into line with current sk-doc templates and Human Voice Rules. It updates the README, runtime guide, references, assets, feature catalog and playbook without shipping behavioral code. The reducer (`scripts/reduce-state.cjs`) was bug-scan only under the surgical-edit policy.

Work ran in three phases inside packet `131/000/003-deep-review`: a Level-3 spec packet was authored end-to-end, a surgical audit produced 23 schema-validated findings, and every actionable finding was resolved or formally closed with rationale, with zero deferrals shipped. The README rewrite then closed the release.

> Spec folder: `.opencode/specs/skilled-agent-orchestration/116-deep-skill-evolution/000-release-cleanup/003-deep-review/` (Level 3)

The documentation baseline is set before the broader 116-deep-skill-evolution arc begins.

## Skill Documentation

#### A Familiar README

The previous README ran in a mixed technical voice that predated the shift toward marketing-leaning HVR copy. The rewrite covers every unique feature in the catalog, 21 entries spanning loop lifecycle, state management, review dimensions and severity. Cross-system links name explicit target paths. The voice was calibrated to roughly 70 percent of the root `Public/README.md` voice.

&nbsp;

#### Runtime Guide Moves

The `Executor Selection Contract` and `Code-Graph Readiness TrustState` moved from section 1 to section 3 because they describe how the skill works rather than when to invoke it. The two REFERENCES sections merged into one, a packet-citation parenthetical left a section heading and a deprecated planning placeholder was removed.

The frontmatter changed from 1.4.0.0 to 1.9.0.0, matching the changelog stream after entries had reached 1.8.0.0. The Smart Router section was preserved exactly as shipped. Convergence math, severity model, verdict logic, state schemas and JSONL events did not change, so the runtime contract needs no migration. Any consumer reading `SKILL.md`, the four `references/`, the asset templates, or the JSONL contract continues to work without code changes.

&nbsp;

#### Reference Guide Navigation

The four files, `convergence.md`, `loop_protocol.md`, `state_format.md` and `quick_reference.md`, each place `### When to Use` inside `## 1. OVERVIEW`. The convergence threshold semantics block moved from the `SKILL.md` preamble to `references/convergence.md`. The references' meta-commentary line and 33 em dash marks were removed. The wording changed from `seamlessly` to `cleanly`.

&nbsp;

#### Asset Template Boundaries

Two markdown assets and one prompt template had 19 em dash marks removed between them. The asset dashboard intro went from three sentences to two. `prompt_pack_iteration.md.tmpl` stayed structurally unchanged because `prompt-pack.ts` consumes it as a raw template through `readFileSync`. Adding YAML frontmatter, condensing the intro or inserting horizontal rules would inject metadata text into the rendered agent prompt, so the template-conformance rules in `skill_asset_template.md` do not apply to that file.

&nbsp;

#### Audit Findings Closed

The closeout included 2 P0, 8 P1 and 13 P2 findings, with zero deferred and zero open. Every actionable finding was resolved or formally closed with rationale.

Five findings were closed as resolved-with-rationale rather than edited away. Three concerned the raw-template exception for `prompt_pack_iteration.md.tmpl`, one corrected the audit's claim that historical changelogs failed the current template convention because later `####` category subheaders had been counted as leading H1s and one confirmed that the playbook root frontmatter already carried a description field.

## Deep-Review Paths

#### Current Runtime Destinations

The 118-FULL_ISOLATE_NO_MCP arc moved deep-loop code out of `system-spec-kit/mcp-server/` into the peer `deep-loop-runtime/` skill, but deep-review's docs did not get the memo. Twelve current-document references across the `SKILL.md`, references and playbook tests now point to `deep-loop-runtime/lib/deep-loop/`, `deep-loop-runtime/lib/coverage-graph/` and `deep-loop-runtime/tests/integration/`. &nbsp;

#### Current Commands and Corpus

Two stress-test references changed from `commands/speckit/deep-review.md` to `commands/deep/review.md`. The `sample-040-corpus.json` typo now uses the `.jsonl` extension. Seven historical changelog references in v1.0.0.0 through v1.3.1.0 were preserved as written to keep the chronological record accurate for paths that existed when those entries were authored.

&nbsp;

#### Playbook Filename Alignment

Files numbered 015 and 021 through 023 in `manual-testing-playbook/04--convergence-and-recovery/` collided with files in sibling directories despite mapping to different DRV IDs. They were renamed to match DRV-030 and DRV-032 through DRV-034, respectively. One updated basename is `stop-on-max-iterations.md`. The DRV-015, DRV-030, DRV-032, DRV-033 and DRV-034 scenarios carry the same contracts as before. Tooling keyed to DRV IDs continues to work. Fourteen cross-references elsewhere that pointed to old filenames were updated in the same commit. The v1.2.0.0 and v1.3.0.0 changelogs also had their internal path references to the renamed files patched, with their historical structure preserved. **Breaking:** Tooling keyed to the old basenames must update to the new ones.
