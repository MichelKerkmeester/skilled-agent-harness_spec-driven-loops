This release changes where deep-review artifacts for child phases land. Their `review/` folders now sit under the spec-tree root, so reviews no longer scatter through deeply nested child folders. The shared path resolver and updated review guidance align the reducer, command YAMLs, agent definitions and documentation with the new location.

> Spec folder: `.opencode/specs/skilled-agent-orchestration/042-deep-research-review-improvement-2/010-root-level-review-research-convention` (Level 2)

## What's New at a Glance

- **Child-phase reviews now land under the spec-tree root.** Previously, running deep-review on a child phase created `review/` inside that child folder, scattering reviews across dozens of directories three or four levels deep and making a specific review depend on knowing its exact nesting path. A matching phase-path subfolder now sits inside the root `review/`, while standalone specs without a parent behave as before: `040-feature/` writes to `040-feature/review/`, child `026/009-playbook/` writes to `026/review/009-playbook/` and grandchild `026/010-search/001-fusion/` writes to `026/review/010-search-001-fusion/`.
- **Review consumers now share one path resolver.** The new `resolveArtifactRoot(specFolder, mode)` function in `system-spec-kit/shared/review-research-paths.cjs` walks up to find the root parent spec and returns `{ rootDir, subfolder }`. The reducer, command YAML assets and agent dispatch context use it.
- **Iteration guidance documents the live review format.** OpenCode, Claude and Codex deep-review agent docs name Dispatcher, Files Reviewed, Findings - New with P0/P1/P2 subsections, Traceability Checks, Confirmed-Clean Surfaces and Next Focus as the live iteration format, while the reducer accepts both old and new schemas for backward compatibility.
- **A combined deep review covered packets 009, 010, 012 and 014.** It found 1 P0, 114 P1 and 133 P2 findings. All 243 were addressed across 28 implementation batches covering 11 workstreams, with key fixes including reconsolidation scope-boundary validation (P0), path-boundary hardening, dead tool removal, status drift cleanup across 49 files, workflow quality score override, context-server timeout abort and frontmatter YAML comment stripping.
- **Agent paths now match their runtimes.** Claude agents and all 10 Codex TOML files referenced `.opencode/agents/`. All path references now point to the correct runtime directories: Claude agents use `.claude/agents/` and Codex files use `.codex/agents/`.
- **Documentation reflects root-level review placement.** OpenCode, Claude and Codex deep-review agent docs describe root-level placement and the `SKILL.md` State Packet Location section describes it with phase subfolders. The `SKILL.md` and `README.md` folder diagrams reflect the convention and all root docs give the `@context` agent the LEAF-only guardrail.
