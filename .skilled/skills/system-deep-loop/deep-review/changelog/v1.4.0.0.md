This release completes the 118 FULL_ISOLATE_NO_MCP migration for deep-review. Its shared loop infrastructure now belongs to the peer `deep-loop-runtime` skill. That gives deep-review a clearer boundary. It does not carry the deleted MCP tool surface forward.

&nbsp;

## What's New at a Glance

- The loop runtime moved to a peer skill.
  - Shared runtime libraries now live in `.opencode/skills/deep-loop-runtime/`.
  - So do coverage-graph ownership and direct script entry points.
  - SQLite storage and runtime tests live there too. They no longer live in the system-spec-kit MCP server.
- The tool cutover changed workflows and test organization.
  - The 118 arc replaced four `deep_loop_graph_*` MCP tools with direct `.cjs` invocations. It updated workflow YAMLs too.
  - Tests were split by runtime responsibility.
- Version 1.4.0.0 marks the dependency relocation.
  - Phase H of 116/008 bumped `deep-review` from `1.3.2.0` to `1.3.3.0`.
  - But the existing `v1.3.3.0.md` from May 7 described unrelated feature-catalog work.
  - The 118 closeout uses `v1.4.0.0` for the dependency relocation. That gives the version history a clean marker for the architecture change.
  - This release note replaces stale May 7 feature-catalog content. `v1.4.0.0.md` had carried that content.
- The 118 closeout records its commit span.
  - Its visible committed spine through phase 007 is `f41f5c9a5d`, `8e09f1ec6b`, `35503d4b78`, `243369d358` and `300bfe603a`.
  - The phase-008 commit handoff records the broader closeout span. That span is `f41f5c9a5d..<this commit>`, per the 118 closeout packet.

&nbsp;

## Upgrade

No migration required. Workflow behavior is intended to remain the same. The runtime dependency path changed. It moved from the system-spec-kit MCP server internals to the peer `deep-loop-runtime` skill.
