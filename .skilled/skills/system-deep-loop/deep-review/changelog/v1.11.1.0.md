A fan-out review (one review split across several models, each running its own lineage) now closes as complete once its report is written. It also counts its iterations correctly, and review confirm keeps going to its ceiling when asked to.

> Part of [Skilled v4.0.0.2](../../../../changelog/skilled/v4.0.0.2.md).
>
> Spec folder: `specs/system-skill-advisor/030-pi-skill-orchestrator-based-research-refinement` (Level 2)

## What's New at a Glance

- **A finished fan-out review closes as complete.** The close-out required a dashboard at the review root, which a fan-out review never writes because each lineage keeps its own, so every finished fan-out review was logged as incomplete. The root dashboard is now required only when no lineage logs exist, and a single review without one still fails.
- **A fan-out review reports its real iteration count.** Review now folds its lineage state logs into its totals the way research does.
- **`--stop-policy=max-iterations` holds in review confirm.** The confirm workflow now runs to its iteration ceiling when asked, instead of stopping at convergence.
- **The close-out runs from one shared script.** Both review workflows call the deep-loop runtime's close-out script, which refuses a symlinked artifact.
- **The skill says where fan-out dashboards live.** The completion rule in `SKILL.md` states that a fan-out run keeps its dashboards per lineage.
