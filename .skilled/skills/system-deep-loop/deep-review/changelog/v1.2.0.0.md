## Review Controls

These controls decide when a review loop may stop and how that decision is recorded. They also set the lifecycle semantics shared across review surfaces.

#### Seven Stop Outcomes <a id="c-seven-stop-outcomes"></a>

- Review stop decisions now use a frozen taxonomy and five required gates.
- The frozen stop-reason enum contains `converged`, `maxIterationsReached`, `blockedStop`, `stuckRecovery`, `error`, `manualStop` and `userPaused`.
- Legacy review stop strings map through a single migration path.

#### Every Gate Must Pass <a id="c-every-gate-must-pass"></a>

- The five requirements are convergence, dimension coverage, P0 resolution, evidence density and hotspot saturation.
- They must all pass together before the loop accepts a STOP verdict.
- Every listed condition must pass before the loop accepts STOP.

#### Blocked Decisions Can Replay <a id="c-blocked-decisions-can-replay"></a>

- A blocked stop is stored as a first-class JSONL record with `blockedBy`, full `gateResults` and a review-specific `recoveryStrategy` hint.
- The `blockedBy` value can include `["dimensionCoverageGate", "p0ResolutionGate"]`.
- That gives resume flows the recorded decision to replay.
- Resume flows can replay the saved gate results.

#### Lifecycle Records Align <a id="c-lifecycle-records-align"></a>

- Four lifecycle modes and run-history fields were aligned across review surfaces.
- The release made `resume`, `restart`, `fork` and `completed-continue` semantics consistent across config, JSONL, strategy, references and command docs.
- It made run-history fields consistent across the same surfaces.
- A later audit found gaps in two of those advertised modes.
- They are detailed below.

## Shared Review Runtime

This area gives the review runtime a single owner for state and one capability matrix. It mirrors the long-standing `deep-research` behavior.

## Post-release Corrections

A post-release audit exposed two contract gaps. Version `v1.3.1.0` retracts the unwired modes and wires claim adjudication into stop paths.

#### Two Lifecycle Modes Were Unwired <a id="c-two-lifecycle-modes-were-unwired"></a>

- The release described `resume`, `restart`, `fork` and `completed-continue` as aligned across the review surfaces.
- The post-release audit dated 2026-04-11 found that `fork` and `completed-continue` had no workflow wiring.
- So selecting either silently did the same thing as `resume`.
- Version `v1.3.1.0` retracts those two modes.

#### Claim Adjudication Was Skipped <a id="c-claim-adjudication-was-skipped"></a>

- The claim-adjudication packet was described as a hard-stop gate.
- But the stop-checking logic never consulted it.
- A reviewer could skip the packet.
- The loop could still finish as if everything were fine.
- Version `v1.3.1.0` wires the gate into every stop path.
- That includes a universal pre-check before the hard stops.

#### Follow-up Repairs Close Gaps <a id="c-followup-repairs-close-gaps"></a>

- Version `v1.3.1.0` makes the shared graph database safe for concurrent sessions.
