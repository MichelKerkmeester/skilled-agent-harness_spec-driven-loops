To close the long-standing architectural gap between `deep-review` and `deep-research`, this release lands the 042 Deep Research & Review Runtime Improvement Bundle for `deep-review` with explicit stop outcomes, coverage-aware convergence and reducer-owned state updates. The bundle gives `deep-review` the same reducer script and runtime-capability resolver that `deep-research` has always had, unifying the two packet expected behaviors at the code level, and adds optimizer guidance.

A post-release audit found that two advertised lifecycle modes were unwired and the claim-adjudication packet was not checked before a stop. Version `v1.3.1.0` retracts the unwired modes, adds the missing gate and corrects other runtime details.

## Why This Release

The goal is to make the workflow easier to follow and easier to trust.

---

## What's New at a Glance

- **Review stop decisions now use a frozen taxonomy and five required gates.** Every listed condition must pass before the loop accepts STOP.
- **Blocked stops preserve the decision and its recovery hint.** Resume flows can replay the saved gate results.
- **Graph events now inform review convergence.** An uncovered required dimension blocks STOP.
- **Stuck recovery pivots to the least-covered dimension.** The pivot gives the loop a deterministic escape from plateaus.
- **The reducer now owns review-state refreshes.** Iteration agents no longer update the findings registry, dashboard or strategy anchors directly.
- **The reducer tracks finding lifecycle across iterations.** It derives the provisional PASS, CONDITIONAL or FAIL verdict from active P0/P1 counts. The dashboard shows that verdict alongside `hasAdvisories`.
- **Review runtime capabilities now match `deep-research`.** One main matrix now resolves the OpenCode, Claude, Codex and legacy `.agents` review runtimes.
- **Three convergence weights are published for operators.** They show the signals used to reason about convergence.
- **Optimizer guidance separates suggested thresholds from hand-tuned ones.** Recommendations remain advisory and are never applied automatically.
- **Four lifecycle modes and run-history fields were aligned across review surfaces.** A later audit found that two of the modes had no workflow wiring.
- **The manual playbook now covers graph events and graph-aware convergence.** Its scenarios exercise both behaviors in review mode.
- **A post-release audit exposed two contract gaps.** Version `v1.3.1.0` retracts the unwired modes and wires claim adjudication into stop paths.

## Review Controls

#### Seven Stop Outcomes

The frozen stop-reason enum contains `converged`, `maxIterationsReached`, `blockedStop`, `stuckRecovery`, `error`, `manualStop` and `userPaused`. Legacy review stop strings map through a single migration path.

&nbsp;

#### Every Gate Must Pass

The five requirements are convergence, dimension coverage, P0 resolution, evidence density and hotspot saturation. They must all pass together before the loop accepts a STOP verdict.

&nbsp;

#### Blocked Decisions Can Replay

A blocked stop is stored as a first-class JSONL record with `blockedBy`, full `gateResults` and a review-specific `recoveryStrategy` hint. The `blockedBy` value can include `["dimensionCoverageGate", "p0ResolutionGate"]`, giving resume flows the recorded decision to replay.

&nbsp;

#### Lifecycle Records Align

The release made `resume`, `restart`, `fork` and `completed-continue` semantics and run-history fields consistent across config, JSONL, strategy, references and command docs. A later audit found gaps in two of those advertised modes, detailed below.

## Shared Review Runtime

#### State Refresh Has One Owner

Operators invoking `/speckit:deep-review` now get reducer-owned updates through `scripts/reduce-state.cjs`. The reducer parses the JSONL iteration log, per-iteration `iteration-NNN.md` files and the strategy file, then regenerates `deep-review-findings-registry.json`, `deep-review-dashboard.md` and machine-owned strategy anchors. Identical inputs produce byte-identical output.

&nbsp;

#### Findings Track Their Lifecycle

The reducer records `firstSeen` and `lastSeen`, tracks severity transitions and detects repeated findings across iterations, removing manual registry bookkeeping. It derives dimension coverage from JSONL `dimensions` fields and strategy anchors. Active P0/P1 counts determine a provisional PASS, CONDITIONAL or FAIL verdict, which appears on the dashboard alongside `hasAdvisories`.

&nbsp;

#### Runtimes Share a Capability Matrix

The new `scripts/runtime-capabilities.cjs` and `assets/runtime-capabilities.json` let the review runtimes, OpenCode, Claude, Codex and the legacy `.agents` wrapper, resolve from one main matrix, matching the long-standing `deep-research` behavior. `deep_review_config.json` declares `reducerScriptPath` and `runtimeCapabilityResolver`. Both `spec_kit_deep-review_auto.yaml` and `spec_kit_deep-review_confirm.yaml` invoke the reducer with `node .opencode/skills/deep-loop-workflows/deep-review/scripts/reduce-state.cjs {spec_folder}` during `step_reduce_review_state`, with an idempotency guarantee.

## Coverage and Recovery

#### Graph Events Reconstruct Review Scope

Review iterations can emit optional `graphEvents` arrays on each JSONL record so the coverage graph can reconstruct review scope, covered dimensions and cross-reference protocols. The coordination-board expected behavior includes the same field. Review convergence now consults the graph, and the dimension-coverage gate changed from `warning` to `blocking` so an uncovered required dimension cannot silently allow STOP.

&nbsp;

#### Recovery Escapes Plateaus

Stuck recovery records a JSONL event and pivots to the least-covered dimension before the legal-stop gates. This gives the loop a deterministic way out of plateaus before it reaches those gates.

&nbsp;

#### Convergence Signals Are Published

The weights for `rollingAvg`, `madScore` and `dimensionCoverage` are published in `quick_reference.md` and the strategy asset. Operators can use them to reason about why the review loop converged.

---

## Optimizer Guidance

#### Thresholds Have Guardrails

`deep_review_config.json` marks `convergenceThreshold`, `stuckThreshold` and `maxIterations` as `_optimizerManaged` tunables. Reducer wiring, file protection, session identity and review dimensions are locked against optimizer drift.

&nbsp;

#### Recommendations Stay Advisory

Command docs link the optimizer manifest, replay corpus and advisory promotion gate. They distinguish machine-suggested thresholds from hand-tuned ones, and the loop never applies optimizer recommendations automatically.

## Post-release Corrections

#### Two Lifecycle Modes Were Unwired

The release described `resume`, `restart`, `fork` and `completed-continue` as aligned across the review surfaces. The post-release audit dated 2026-04-11 found that `fork` and `completed-continue` had no workflow wiring, so selecting either silently did the same thing as `resume`. Version `v1.3.1.0` retracts those two modes.

&nbsp;

#### Claim Adjudication Was Skipped

The claim-adjudication packet was described as a hard-stop gate, but the stop-checking logic never consulted it. A reviewer could skip the packet and the loop could still finish as if everything were fine. Version `v1.3.1.0` wires the gate into every stop path, including a universal pre-check before the hard stops.

&nbsp;

#### Follow-up Repairs Close Gaps

Version `v1.3.1.0` makes the shared graph database safe for concurrent sessions and rewrites the canonical agent template so the reducer can parse it. It also replaces the phantom stop-contract shape in the convergence reference with the real `blocked_stop` event. `v1.3.1.0.md` gives plain-English Problem/Fix pairs for each change.

## Upgrade Notes

No migration is required for existing review packets. Legacy stop-reason strings map through the taxonomy on the fly. The new `scripts/` directory mirrors the `deep-research` layout exactly.
