This release lands the deep-research part of the packets 108 plus 110 auto-review uplift program. It applies two practices from the upstream `dzianisv/opencode-plugins` auto-review package to every deep-research iteration. The first is a role marker at the rendered-prompt boundary. The second is a rule against repeating findings. The marker addresses long research iterations that sometimes drifted out of role. That happened when the banner scrolled past the visible context window. The changes land in prompts and dispatcher configuration, not source code.

## Why This Release

The H-7 synthesis content-hash dedup shipped in deep-review v1.8.0.0 was not applied here. It keys partly on a `dimension` field. Deep-research is single-dimension by design. It produces no cross-dimension restatements. So the dedup would add metadata fields with no behavioral payoff. The deep-review v1.8.0.0 changelog documents the mechanism in full.

## What's New at a Glance

- **Rendered prompts start with `DEEP-RESEARCH`.** The marker sits on line 1 of `prompt_pack_iteration.md.tmpl`. So it stays at the top whatever the template holds. The auto dispatcher fails fast if it is missing after rendering. Reference templates with YAML frontmatter were left untouched. A marker inside frontmatter would corrupt the loader.
- **Researchers must not repeat findings across iterations.** The `CONSTRAINTS` section of the deep-research `SKILL.md` sets the rule. A researcher must omit a finding already reported in a prior iteration of the same research arc. Or the researcher must extend its prior entry with new evidence. The prompt-level rule guides iteration n while the researcher still sees iterations 1 through n−1 in context.

## Upgrade

No migration required. Existing iteration records remain valid. The iteration-record schema is unchanged.
