This release lands the deep-research portion of the packets 108 plus 110 auto-review uplift program, applying two practices from the upstream `dzianisv/opencode-plugins` auto-review package to every deep-research iteration: a role marker at the rendered-prompt boundary and a rule against repeating findings. The marker addresses long research iterations that occasionally drifted out of role when the banner scrolled past the visible context window. The changes land in prompts and dispatcher configuration, not source code.

> Spec folder: `.opencode/specs/skilled-agent-orchestration/108-auto-review-quick-wins-verdict-markers-logging` (Level 3)

## Why This Release

The H-7 synthesis content-hash dedup shipped in deep-review v1.8.0.0 was not applied here. It keys partly on a `dimension` field. Deep-research is single-dimension by design and produces no cross-dimension restatements, so the dedup would add metadata fields without behavioral payoff. The deep-review v1.8.0.0 changelog documents the mechanism in full.

## What's New at a Glance

- **Rendered prompts start with `DEEP-RESEARCH`.** The marker sits on line 1 of `prompt_pack_iteration.md.tmpl`, keeping it at the top regardless of template content, and the auto dispatcher fails fast if it is missing after rendering. Reference templates with YAML frontmatter were left untouched because a marker inside frontmatter would corrupt the loader.
- **Researchers must not repeat findings across iterations.** The `CONSTRAINTS` section of the deep-research `SKILL.md` requires researchers to omit a finding already reported in a prior iteration of the same research arc or extend its prior entry with new evidence. The prompt-level rule guides iteration n while the researcher still sees iterations 1 through n−1 in context.

## Upgrade

No migration required. Existing iteration records remain valid, and the iteration-record schema is unchanged.
