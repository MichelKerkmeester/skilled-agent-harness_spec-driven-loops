This release gives deep-research a consistent place for research artifacts across nested phases. Previously, research folders could be scattered through child folders, making a specific output hard to find without knowing the exact nesting path.

> Spec folder: `.opencode/specs/skilled-agent-orchestration/042-deep-research-review-improvement-2/010-root-level-review-research-convention` (Level 2)

## What's New at a Glance

- **Deep-research organizes research folders under the spec-tree root.** Child-phase runs create a subfolder matching the phase path under the root `research/` folder, rather than placing `research/` inside the child. A standalone spec with no parent behaves as before: `040-feature/` writes to `040-feature/research/`. For child phases, `026/014-memory-save/` writes to `026/research/014-memory-save/`, while grandchild `026/010-search/001-fusion/` writes to `026/research/010-search-001-fusion/`.
- **Deep-research and deep-review share one path resolver.** Both use the same `resolveArtifactRoot(specFolder, mode)` function from `system-spec-kit/shared/review-research-paths.cjs`, and the reducer, the command YAML assets and the agent dispatch context all resolve through it.
- **Deep-research agent paths match their runtimes.** The Claude and Codex agent definitions now reference their own runtime directories instead of `.opencode/agents/`.
- **Deep-research archives use `research_archive`.** Both command YAMLs now set `archive_root` to `research_archive`, matching the archive directory naming convention.
- **Deep-research agent guidance matches across three runtimes.** All three runtime copies describe the root-level research convention. The SKILL.md State Packet Location section and README folder-structure diagrams are updated to match.
