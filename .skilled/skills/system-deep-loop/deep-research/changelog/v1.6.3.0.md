This release gives deep-research a consistent place for research artifacts across nested phases. Previously, research folders could be scattered through child folders. Because of that, a specific output was hard to find without knowing the exact nesting path.

## What's New at a Glance

- **Deep-research organizes research folders under the spec-tree root.** Child-phase runs create a subfolder under the root `research/` folder. The subfolder matches the phase path. Child-phase runs place `research/` outside the child, not inside it. A standalone spec with no parent behaves as before. `040-feature/` writes to `040-feature/research/`. For child phases, `026/014-memory-save/` writes to `026/research/014-memory-save/`. A grandchild `026/010-search/001-fusion/` writes to `026/research/010-search-001-fusion/`.
- **Deep-research and deep-review share one path resolver.** Both use the same `resolveArtifactRoot(specFolder, mode)` function from `system-spec-kit/shared/review-research-paths.cjs`. The reducer, the command YAML assets and the agent dispatch context all resolve through it.
- **Deep-research agent paths match their runtimes.** The Claude and Codex agent definitions now reference their own runtime directories instead of `.opencode/agents/`.
- **Deep-research archives use `research_archive`.** Both command YAMLs now set `archive_root` to `research_archive`. This matches the archive directory naming convention.
- **Deep-research agent guidance matches across three runtimes.** All three runtime copies describe the root-level research convention. The SKILL.md State Packet Location section and README folder-structure diagrams are updated to match.
