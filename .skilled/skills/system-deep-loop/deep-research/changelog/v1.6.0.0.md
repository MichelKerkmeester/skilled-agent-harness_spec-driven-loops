# v1.6.0.0, Deep Research Gains Graph-Aware Stops

Phase 008 closes the recommendations from a deep-research audit.

- It is part of the 042 Deep Research & Review Runtime Improvement Bundle.
- It closes the 12 P0/P1/P2 recommendations.
- The 20-iteration deep-research audit surfaced them.

Graph checks and blocked-stop details reach the live path.

- Coverage-graph checks enter the live `deep-research` loop.
- Blocked-stop details reach reducer views.
- `deep_loop_graph_upsert` and `deep_loop_graph_convergence` run in the auto and confirm workflows.

## Deep Research Workflows

Both research workflows emit blocked stops and run graph checks.

#### Blocked Stops Carry Context <a id="c-blocked-stops-carry-context"></a>

- Both research workflows emit a first-class `blocked_stop` JSONL event.
- They emit it through `step_emit_blocked_stop`.
- Its `blockedBy`, `gateResults`, `recoveryStrategy` and full session run history reach downstream reducers.
- They give the exact blocker and recovery context.

#### Pause Reasons Stay Constrained <a id="c-pause-reasons-stay-constrained"></a>

- At emission, `step_normalize_pause_events` maps raw `paused` and `stuck_recovery` to `userPaused` and `stuckRecovery`.
- It uses the frozen `STOP_REASONS` enum.
- The live workflow no longer passes free-form strings into `synthesis_complete.stopReason`.

#### Graph Checks Gate Stops <a id="c-graph-checks-gate-stops"></a>

- In `deep_research_auto.yaml` and `deep_research_confirm.yaml`, `deep_loop_graph_upsert` runs after `step_reduce_state`.
- It persists iteration `graphEvents` to the SQLite store.
- `deep_loop_graph_convergence` runs before the inline three-signal vote in `step_check_convergence`.
- `STOP_BLOCKED` routes to `blocked_stop` emission.
- The OpenCode `deep-research` agent gains explicit graph tool permissions.
- The Claude agent mirrors them.

## Coverage Graph and Reducers

This area covers graph signals, reducer event streams and the registry.

#### Graph Signals Share One Authority <a id="c-graph-signals-share-one-authority"></a>

- The MCP handler is the main implementation.
- `scripts/lib/coverage-graph-convergence.cjs` is a thin adapter.
- It points to the authoritative `mcp-server/lib/coverage-graph/coverage-graph-signals.ts` implementation.
- There, `sourceDiversity`, `contradictionDensity`, `questionCoverage` and `evidenceDepth` are harmonized.

#### Stop Events Reach Reducers <a id="c-stop-events-reach-reducers"></a>

- The reducer no longer filters non-iteration JSONL rows.
- Its `events` stream preserves `blocked_stop`, `userPaused` and `stuckRecovery`.
- The blocked-stop history builder and graph-convergence rollup builder use them.

#### Graph Results Reach the Registry <a id="c-graph-results-reach-the-registry"></a>

- `buildGraphConvergenceRollup(events)` consumes `graph_convergence` JSONL events.
- It adds `graphConvergenceScore`, `graphDecision` and `graphBlockers` beside `convergenceScore`.
- Stop events also contribute `blockedStopHistory`.
- `state_format.md` §5 documents the registry fields.
- It also documents the `blocked_stop` and `graph_convergence` event schemas and the combined-stop rule.

#### Dashboard Shows Both Outcomes <a id="c-dashboard-shows-both-outcomes"></a>

- The render dashboard helper emits `BLOCKED STOPS` and `GRAPH CONVERGENCE` sections.
- Both use event data collected by the reducer.

#### Next Focus Names Recovery <a id="c-next-focus-names-recovery"></a>

- When a blocked stop is the latest loop event, the update strategy content helper overrides the `next-focus` anchor.
- It uses its `recoveryStrategy`.
- Operators see the blocker and recovery hint before they choose the next iteration direction.

## Session-Scoped Graph Reads

Shared coverage-graph reads accept a session scope.

#### Session Reads Stay Compatible <a id="c-session-reads-stay-compatible"></a>

- Shared coverage-graph reads accept `sessionId`.
- They live in `coverage-graph-query.ts`, `coverage-graph/convergence.ts`, `coverage-graph/query.ts` and `coverage-graph/status.ts`.
- They scope aggregation by `specFolder + loopType + sessionId`.
- When `sessionId` is absent, backward-compatible behavior is preserved.

## How It Was Checked

Testing uses an interrupted-session fixture and manual-testing scenarios.

#### Before and After <a id="c-before-and-after"></a>

| Check | Before | After |
|---|---|---|
| Reducer on non-iteration JSONL rows | Filtered them out | Preserves `blocked_stop`, `userPaused` and `stuckRecovery` |
| Pause reason in `synthesis_complete.stopReason` | Free-form strings | Normalized `userPaused` and `stuckRecovery` |
| STOP decision | Inline three-signal vote | Inline vote plus graph decision |

#### Interrupted Sessions Have a Fixture <a id="c-interrupted-sessions-have-a-fixture"></a>

- The new `scripts/tests/fixtures/interrupted-session/` fixture is a deep-research packet.
- It has two complete iterations and a third truncated mid-write.
- It includes truncated Markdown and a malformed JSONL tail.
- It demonstrates reducer recovery under `--lenient`.
