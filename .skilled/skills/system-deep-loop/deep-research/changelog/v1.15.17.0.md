# v1.15.17.0, Focus and Findings Checks Read the Leaf Fields

Two checks could not see the fields a leaf wrote. Both now read them. They run on every research run, with no flag.

&nbsp;

## What's New at a Glance

- The state log keeps ten leaf fields.
- The list includes `findingsCount`, `keyQuestions` and `sourcesQueried`.
- The `findings_not_enumerated` gate reads the real `findingsCount`.
- `focusAlignment` is live on default research runs.
- It judges the latest record that carries both question lists.
- Reducer consumers now receive the fields.
- A single `keyQuestions` entry resolves its question.
- `sourcesQueried` feeds the source list.
- The dashboard shows `focusTrack` and `findingsCount`.

&nbsp;

## How It Was Checked

The replay ran five real generation-two deltas. `focusAlignment` failed on four of them. The findings gate and route proof passed on all five. Iterations 2, 3 and 5 answered an unlisted question. Iteration 4 wrote its key question as a bare id, `Q6`. That id does not match the answered text.

&nbsp;

## Upgrade

A `focusAlignment` failure can now hold a run at CONTINUE. The hold clears on the next aligned iteration. The guard judges only the latest record with both lists. The prompt pack asks for the exact question text. Write `keyQuestions` with no id prefix, such as `Q1:`.
