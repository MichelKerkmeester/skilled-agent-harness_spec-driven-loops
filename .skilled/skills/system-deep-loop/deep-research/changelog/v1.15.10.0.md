# v1.15.10.0, Long Prose Lines Become Short Sentences and Lists

Several paragraphs in the deep-research skill were written as one very long line each. A reader had to untangle the executor rules, the event-record contract or the state packet layout out of a single sentence.

Those lines are now short sentences, and a line that listed several rules or steps is now a short list. The instruction comes before the background, and instructions address you directly.

The content did not change. Every file path, resource name, command, field, executor name and number in the old lines is still there, and the rewrite adds nothing new. What selects this skill, what it loads first and how a request routes are all exactly as they were.

> Spec folder: `specs/sk-doc/072-skill-routing-and-clarity/010-prose-clarity-pass` (Level 2)

&nbsp;

## What's New at a Glance

- **The executor contract reads as steps.** What the workflow owns, what is discouraged, which file owns the executor kinds and which YAML branch covers which executor now each stand alone.
- **The event record rule reads as four lines.** The required fields, the single-object rule, the reducer-owned delta file and the ledger refresh are separate points.
- **The state packet location is split by target kind.** Root-spec targets, child-phase targets and the flat-first subfolder rule each get their own sentence.
- **The late-init anchoring steps are numbered.** The lock, the folder state, the bounded context seed and the findings fence replacement read in run order.
- **Every fact is the same.** No routing signal, resource path, loading level or command changed, and every fenced line is byte-identical.
