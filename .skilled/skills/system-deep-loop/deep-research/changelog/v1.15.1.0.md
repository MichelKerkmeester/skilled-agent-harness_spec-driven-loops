A fan-out research run (one research topic split across several models, each running its own lineage) now closes as complete once its synthesis is written. Both research workflows also run to their ceiling when asked, and confirm mode checks quality again before it stops.

> Part of [Skilled v4.0.0.2](../../../../changelog/skilled/v4.0.0.2.md).
>
> Spec folder: `specs/system-skill-advisor/030-pi-skill-orchestrator-based-research-refinement` (Level 2)

## What's New at a Glance

- **A finished fan-out run closes as complete.** The convergence step required a dashboard at the research root, which a fan-out run never writes because each lineage keeps its own, so every finished fan-out run was logged as incomplete. The root dashboard is now required only when no lineage logs exist, and a single run without one still fails.
- **`--stop-policy=max-iterations` holds in both workflows.** Auto and confirm now run to their iteration ceiling when asked. The rule is its own step, so the default convergence mode cannot skip it.
- **Confirm mode has its quality guards back.** An earlier edit that aligned the two workflows dropped the quality checks from confirm's convergence step, so it could stop without them. They are back, and a test now holds each confirm workflow to its auto twin.
- **The close-out runs from one shared script.** Both research workflows call the deep-loop runtime's close-out script, which also matches a finding by its `findingId` field.
