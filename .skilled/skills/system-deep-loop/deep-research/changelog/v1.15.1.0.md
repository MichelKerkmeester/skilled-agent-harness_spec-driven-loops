A fan-out research run splits one research topic across several models. Each model runs its own lineage. The run now closes as complete once its synthesis is written.

Both research workflows also run to their ceiling when asked. Confirm mode checks quality again before it stops.

> Part of [Skilled v4.0.0.2](../../../../changelog/skilled/v4.0.0.2.md).
## What's New at a Glance

- **A finished fan-out run closes as complete.** The convergence step required a dashboard at the research root. A fan-out run never writes one, because each lineage keeps its own. So every finished fan-out run was logged as incomplete. The root dashboard is now required only when no lineage logs exist. A single run without one still fails.
- **`--stop-policy=max-iterations` holds in both workflows.** Auto and confirm now run to their iteration ceiling when asked. The rule is its own step. So the default convergence mode cannot skip it.
- **Confirm mode has its quality guards back.** An earlier edit aligned the two workflows. That edit dropped the quality checks from confirm's convergence step. So confirm could stop without them. They are back. A test now holds each confirm workflow to its auto twin.
- **The close-out runs from one shared script.** Both research workflows call the deep-loop runtime's close-out script. That script also matches a finding by its `findingId` field.
