This release gives `deep-research` explicit, executable packet behavior. That covers run history, lifecycle rules and runtime parity.

## Why This Release

The goal is to make the workflow easier to follow. It should also be easier to trust.

## What's New at a Glance

- **The `deep-research` packet has explicit lineage and lifecycle rules.** Run history and lifecycle branches are defined. Reducer-owned outputs are separated from agent-authored artifacts.
- **Canonical packet artifacts are aligned.** Skill docs, references, runtime mirrors and workflow assets carry the packet contract.
- **Capability lookup and state reduction have executable helpers.** The runtime capability matrix has a programmatic lookup. Packet state can be reduced into synchronized outputs.

---

## Research Contract

#### Run History and Lifecycle

The packet contract now makes lineage fields explicit and shared. They are `sessionId`, `parentSessionId`, `run historyMode`, `generation` and `continuedFromRun`. It documents the `resume`, `restart`, `fork` and `completed-continue` lifecycle branches. They are the same across the skill.

&nbsp;

#### Generated State Has Clear Ownership

Reducer-owned outputs are separated from agent-authored iteration artifacts. This removes ambiguity around dashboard, strategy and registry refreshes.

&nbsp;

#### Canonical Artifacts Are Frozen

Canonical `deep-research-*` packet artifacts are now frozen. They are frozen across the skill docs, references, runtime mirrors and workflow assets. `SKILL.md` freezes the lifecycle vocabulary, reducer ownership, lineage and runtime contract guidance. The README reframes the skill around the canonical research-only packet model.

---

## Runtime and Workflow Parity

#### Matching Runtime Expectations

OpenCode, Claude, Codex and the compatibility wrapper now describe the same expected behavior. That is the deep-research packet behavior. The auto and confirm workflow YAML assets carry the same lifecycle, migration, registry and reducer expectations. The manual testing playbook now describes reducer-owned refresh behavior. It does so consistently in the root playbook and concrete iteration scenarios.

---

## Executable Helpers

#### Capability Lookup from One Matrix

A machine-readable runtime capability matrix was added. So was a human-readable capability reference. The new `runtime-capabilities.cjs` resolves runtime metadata programmatically from the main matrix.

&nbsp;

#### Synchronized Packet State

The new `reduce-state.cjs` reduces packet state into synchronized outputs. Those are strategy, findings-registry and dashboard outputs. Helper packaging uses `.cjs` entry points to match the repo's ESM boundary. It avoids incompatible CommonJS-in-ESM paths.

## Upgrade Notes

No upgrade needed. Normal `deep-research` use requires no migration. Packet lineage, reducer refreshes, runtime parity and closeout verification are now defined by one executable contract. That replaces scattered doc-only guidance.
