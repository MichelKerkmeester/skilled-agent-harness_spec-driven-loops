- Reducer-owned outputs are separated from agent-authored artifacts.

Canonical packet artifacts and runtime behavior align across the skill.

- Canonical packet artifacts are aligned.
- Skill docs, references, runtime mirrors and workflow assets carry the packet contract.

- The runtime capability matrix has a programmatic lookup.
- Packet state can be reduced into synchronized outputs.

## Research Contract

The packet contract defines lineage, lifecycle and generated state ownership.

#### Run History and Lifecycle <a id="c-run-history-and-lifecycle"></a>

- The packet contract now makes lineage fields explicit and shared.
- They are `sessionId`, `parentSessionId`, `run historyMode`, `generation` and `continuedFromRun`.
- It documents the `resume`, `restart`, `fork` and `completed-continue` lifecycle branches.
- They are the same across the skill.

#### Generated State Has Clear Ownership <a id="c-generated-state-has-clear-ownership"></a>

- Reducer-owned outputs are separated from agent-authored iteration artifacts.
- This removes ambiguity around dashboard, strategy and registry refreshes.

#### Canonical Artifacts Are Frozen <a id="c-canonical-artifacts-are-frozen"></a>

- Canonical `deep-research-*` packet artifacts are now frozen.
- They are frozen across the skill docs, references, runtime mirrors and workflow assets.
- `SKILL.md` freezes the lifecycle vocabulary, reducer ownership, lineage and runtime contract guidance.
- The README reframes the skill around the canonical research-only packet model.

&nbsp;

## Runtime and Workflow Parity

Runtimes and workflow assets share the same expectations.

#### Matching Runtime Expectations <a id="c-matching-runtime-expectations"></a>

- OpenCode, Claude, Codex and the compatibility wrapper now describe the same expected behavior.
- That is the deep-research packet behavior.
- The auto and confirm workflow YAML assets carry the same lifecycle, migration, registry and reducer expectations.
- The manual testing playbook now describes reducer-owned refresh behavior.
- It does so consistently in the root playbook and concrete iteration scenarios.

&nbsp;

## Executable Helpers

Executable helpers cover capability lookup and synchronized state.

#### Capability Lookup from One Matrix <a id="c-capability-lookup-from-one-matrix"></a>

- A machine-readable runtime capability matrix was added.
- So was a human-readable capability reference.
- The new `runtime-capabilities.cjs` resolves runtime metadata programmatically from the main matrix.

#### Synchronized Packet State <a id="c-synchronized-packet-state"></a>

- The new `reduce-state.cjs` reduces packet state into synchronized outputs.
- Those are strategy, findings-registry and dashboard outputs.
- Helper packaging uses `.cjs` entry points to match the repo's ESM boundary.
- It avoids incompatible CommonJS-in-ESM paths.

&nbsp;

## Upgrade Notes

No upgrade needed. Normal `deep-research` use requires no migration. Packet lineage, reducer refreshes, runtime parity and closeout verification are now defined by one executable contract. That replaces scattered doc-only guidance.
