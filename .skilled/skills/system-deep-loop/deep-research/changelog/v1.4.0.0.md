This release gives `deep-research` explicit, executable packet behavior covering run history, lifecycle rules and runtime parity.

## Why This Release

The goal is to make the workflow easier to follow and easier to trust.

## What's New at a Glance

- **The `deep-research` packet has explicit lineage and lifecycle rules.** Run history and lifecycle branches are defined, and reducer-owned outputs are separated from agent-authored artifacts.
- **Canonical packet artifacts are aligned.** Skill docs, references, runtime mirrors and workflow assets carry the packet contract across those surfaces.
- **Capability lookup and state reduction have executable helpers.** The runtime capability matrix has a programmatic lookup, and packet state can be reduced into synchronized outputs.

---

## Research Contract

#### Run History and Lifecycle

The packet contract now makes lineage fields explicit and shared: `sessionId`, `parentSessionId`, `run historyMode`, `generation` and `continuedFromRun`. It documents the `resume`, `restart`, `fork` and `completed-continue` lifecycle branches consistently across the skill.

&nbsp;

#### Generated State Has Clear Ownership

Reducer-owned outputs are separated from agent-authored iteration artifacts. This removes ambiguity around dashboard, strategy and registry refreshes.

&nbsp;

#### Canonical Artifacts Are Frozen

Canonical `deep-research-*` packet artifacts are now frozen across the skill docs, references, runtime mirrors and workflow assets. `SKILL.md` freezes the lifecycle vocabulary, reducer ownership, lineage and runtime contract guidance, and the README reframes the skill around the canonical research-only packet model.

---

## Runtime and Workflow Parity

#### Matching Runtime Expectations

OpenCode, Claude, Codex and the compatibility wrapper now describe the same deep-research packet expected behavior. The auto and confirm workflow YAML assets carry the same lifecycle, migration, registry and reducer expectations. The manual testing playbook now describes reducer-owned refresh behavior consistently in the root playbook and concrete iteration scenarios.

---

## Executable Helpers

#### Capability Lookup from One Matrix

A machine-readable runtime capability matrix and a human-readable capability reference were added. The new `runtime-capabilities.cjs` resolves runtime metadata programmatically from the main matrix.

&nbsp;

#### Synchronized Packet State

The new `reduce-state.cjs` reduces packet state into synchronized strategy, findings-registry and dashboard outputs. Helper packaging uses `.cjs` entry points to match the repo's ESM boundary instead of incompatible CommonJS-in-ESM paths.

## Upgrade Notes

No upgrade needed. Normal `deep-research` use requires no migration, and packet lineage, reducer refreshes, runtime parity and closeout verification are now defined by one executable contract instead of scattered doc-only guidance.
