# v1.5.0.0, deep-research decision traces and legal-stop gates

Legal-stop gates and decision traces lead this release.

- A blocked `deep-research` run now carries a decision trace.
- Legal-stop gates define when a run can finish.

The 042 Deep Research & Review Runtime Improvement Bundle also adds semantic coverage signals.

- It adds reducer-owned audit rollups.
- It adds a dashboard refresh that stays deterministic across re-runs.

The bundle also adds recovery and tuning.

- It adds a plateau-recovery path.
- It adds advisory tuning through the offline optimizer.

&nbsp;

## Why This Release

The goal is to make the workflow easier to follow and easier to trust.

## Stop Decisions and Lifecycle

Stop decisions now carry a frozen taxonomy and four gates. Blocked stops keep their detail, and lifecycle claims were corrected.

#### Seven Stop Outcomes <a id="c-seven-stop-outcomes"></a>

- The stop-reason taxonomy is frozen.
- The enum contains `converged`, `maxIterationsReached`, `blockedStop`, `stuckRecovery`, `error`, `manualStop` and `userPaused`.
- Legacy strings are mapped on the fly through a single migration path.

#### Four Gates Before STOP <a id="c-four-gates-before-stop"></a>

- The legal-stop decision tree checks convergence math and key-question coverage.
- It also checks evidence density and hotspot saturation.
- STOP is accepted only when all four gates pass.

#### Blocked Stops Carry Detail <a id="c-blocked-stops-carry-detail"></a>

- Blocked stops preserve their decision trace.
- Blocked-stop events are saved as first-class JSONL records.
- They carry `blockedBy`, `gateResults` and a `recoveryStrategy` hint.
- Resume flows can replay the decision trace from those fields.

#### Lifecycle Modes Corrected <a id="c-lifecycle-modes-corrected"></a>

- This release advertised four lifecycle modes for re-entering a research session.
- They were `resume`, `restart`, `fork` and `completed-continue`.
- A post-release update retracts two modes.
- They had no workflow behavior.

<details>
<summary><b>Correction history</b></summary>

- Configuration, JSONL, strategy and command docs described consistent run-history fields for all four.
- The v1.5.0.0 upgrade note said `resume` and `completed-continue` carried the v1.4.0.0 lineage contract.
- That contract was extended with legal-stop gate results and optional graph events.
- On 2026-04-11, a post-release correction clarified that only `resume` and `restart` had workflow behavior.
- `fork` (start a sibling lineage) and `completed-continue` (reopen a finished run) had none.
- Selecting either silently did the same thing as `resume`.
- Release `v1.6.1.0` retracts both modes to deferred status.
- See `v1.6.1.0.md` for the full story and the one-session contract the runtime supports.

</details>

## Coverage and Convergence

Coverage graphs and semantic signals now shape convergence.

#### Iterations Emit Graph Events <a id="c-iterations-emit-graph-events"></a>

- Iterations can emit `graphEvents`.
- Each JSONL record can carry an optional `graphEvents` array.
- The array has the shape `{type, id, label, relation?, source?, target?}`.
- The reducer and MCP surfaces can use these events to reconstruct coverage graph nodes and edges.

#### Graph Signals Can Block STOP <a id="c-graph-signals-can-block-stop"></a>

- Convergence consults the coverage graph.
- In that graph, contradiction density, graph momentum and depth/degree signals can block STOP.
- These signals can prevent a stop even when ratio-based gates already pass.

#### Novelty and Focus Stay Aligned <a id="c-novelty-and-focus-stay-aligned"></a>

- Novelty justification includes a semantic novelty lens.
- The 3-signal convergence weights are published in `quick_reference.md` and the strategy asset.
- Those published weights let operators reason about why the loop converged.
- The `sourceStrength` field and the `originalKeyQuestions` focus-alignment guard close the last remaining drift paths.

## Run State and Recovery

The reducer now owns audit rollups, and plateaus have an escape.

#### The Reducer Owns the Audit <a id="c-the-reducer-owns-the-audit"></a>

- The reducer owns the audit journal rollup and timing metrics.
- It also owns coverage depth, evidence-quality summary and claim ledger verification.
- Iteration agents no longer author these sections directly.
- The rollups are part of the reducer's idempotent output.
- So dashboard refresh stays deterministic across re-runs.

#### Analytical Work Does Not Look Stuck <a id="c-analytical-work-does-not-look-stuck"></a>

- `scripts/reduce-state.cjs` excludes `thought` and `insight` iterations from the stuck count and rolling-average trend.
- This fixes a false `stuck` signal for analytical-only iterations.

#### Plateaus Have a Recovery Path <a id="c-plateaus-have-a-recovery-path"></a>

- A `stuck_recovery` JSONL event and a least-covered-dimension pivot fallback together give the loop a deterministic escape from plateaus.
- The pivot happens before the legal-stop gates trip.

&nbsp;

## Optimizer Tuning

Optimizer tuning is bounded and advisory.

#### Tuning Has Boundaries <a id="c-tuning-has-boundaries"></a>

- `deep_research_config.json` declares the fields the offline optimizer may tune through `_optimizerManaged`.
- Those fields are `convergenceThreshold`, `stuckThreshold` and `maxIterations`.
- Locked fields are protected from drift.
- The optimizer manifest, replay corpus, rubric and advisory promotion gate are wired into command docs.
- So operators know which thresholds are machine-suggested and which are hand-tuned.
- Promotion stays advisory-only.
- The loop never auto-applies optimizer recommendations.
