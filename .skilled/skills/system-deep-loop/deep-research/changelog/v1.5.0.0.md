A blocked `deep-research` run now carries a decision trace, and legal-stop gates define when a run can finish. The 042 Deep Research & Review Runtime Improvement Bundle also adds semantic coverage signals, reducer-owned audit rollups and a dashboard refresh that stays deterministic across re-runs, a plateau-recovery path and advisory tuning through the offline optimizer.

## Why This Release

The goal is to make the workflow easier to follow and easier to trust.

- **Four gates control STOP acceptance.** A run stops only when every required condition passes.
- **Blocked stops preserve their decision trace.** Resume flows can replay the saved decision.
- **Lifecycle-mode claims are corrected.** A post-release update retracts two modes that had no workflow behavior.
- **Coverage graphs inform convergence.** Graph signals can block STOP after ratio-based gates pass.

- **Plateaus gain a recovery path.** A least-covered-dimension pivot happens before legal-stop gates trip.

## Stop Decisions and Lifecycle

#### Seven Stop Outcomes

The frozen stop-reason enum contains `converged`, `maxIterationsReached`, `blockedStop`, `stuckRecovery`, `error`, `manualStop` and `userPaused`. Legacy strings are mapped on the fly through a single migration path.

&nbsp;

#### Four Gates Before STOP

The legal-stop decision tree checks convergence math, key-question coverage, evidence density and hotspot saturation. STOP is accepted only when all four gates pass.

&nbsp;

#### Blocked Stops Carry Detail

Blocked-stop events are persisted as first-class JSONL records with `blockedBy`, `gateResults` and a `recoveryStrategy` hint. Resume flows can replay the decision trace from those fields.

&nbsp;

#### Lifecycle Modes Corrected

This release advertised four lifecycle modes for re-entering a research session: `resume`, `restart`, `fork` and `completed-continue`. Configuration, JSONL, strategy and command docs described consistent run-history fields for all four. The v1.5.0.0 upgrade note said `resume` and `completed-continue` carried the v1.4.0.0 lineage contract, extended with legal-stop gate results and optional graph events.

On 2026-04-11, a post-release correction clarified that only `resume` and `restart` had workflow behavior. `fork` (start a sibling lineage) and `completed-continue` (reopen a finished run) had none, and selecting either silently did the same thing as `resume`.

Release `v1.6.1.0` retracts both modes to deferred status. See `v1.6.1.0.md` for the full story and the one-session contract the runtime supports.

## Coverage and Convergence

#### Iterations Emit Graph Events

Each JSONL record can carry an optional `graphEvents` array with the shape `{type, id, label, relation?, source?, target?}`. The reducer and MCP surfaces can use these events to reconstruct coverage graph nodes and edges.

&nbsp;

#### Graph Signals Can Block STOP

Convergence consults the coverage graph, where contradiction density, graph momentum and depth/degree signals can block STOP. These signals can prevent a stop even when ratio-based gates already pass.

&nbsp;

#### Novelty and Focus Stay Aligned

Novelty justification includes a semantic novelty lens, and the 3-signal convergence weights are published in `quick_reference.md` and the strategy asset. Those published weights let operators reason about why the loop converged.

The `sourceStrength` field and the `originalKeyQuestions` focus-alignment guard close the last remaining drift paths.

---

## Run State and Recovery

#### The Reducer Owns the Audit

The reducer owns the audit journal rollup, timing metrics, coverage depth, evidence-quality summary and claim ledger verification. Iteration agents no longer author these sections directly.

The rollups are part of the reducer's idempotent output, so dashboard refresh stays deterministic across re-runs.

&nbsp;

#### Analytical Work Does Not Look Stuck

`scripts/reduce-state.cjs` excludes `thought` and `insight` iterations from the stuck count and rolling-average trend. This fixes a false `stuck` signal for analytical-only iterations.

&nbsp;

#### Plateaus Have a Recovery Path

A `stuck_recovery` JSONL event and a least-covered-dimension pivot fallback give the loop a deterministic escape from plateaus. The pivot happens before the legal-stop gates trip.

---

## Optimizer Tuning

#### Tuning Has Boundaries

`deep_research_config.json` declares the fields the offline optimizer may tune through `_optimizerManaged`: `convergenceThreshold`, `stuckThreshold` and `maxIterations`. Locked fields are protected from drift.

The optimizer manifest, replay corpus, rubric and advisory promotion gate are wired into command docs so operators know which thresholds are machine-suggested and which are hand-tuned. Promotion stays advisory-only, and the loop never auto-applies optimizer recommendations.

## Operator Guidance

#### Graph Guidance Covers the Workflow

The manual testing playbook adds `graph-events-emission.md` and `graph-convergence-signals.md` to exercise graph emission and graph-aware convergence end to end. `references/convergence.md`, `references/state-format.md` and `references/quick-reference.md` reflect the legal-stop and blocked-stop model plus the graph-convergence lens.

## Upgrade Notes

- Existing research packets need no migration. Legacy stop-reason strings are mapped on the fly.
- Operators who want a fresh lineage should choose `restart`. It archives the existing `research/` folder and mints a new session id.
