Research iterations can now run through `codex exec` with a chosen model, reasoning effort and service tier instead of relying only on the native research agent with Claude Opus. The YAML workflow continues to own state tracking, convergence detection, lifecycle events and the reducer. The CLI runs inside that workflow, not as a replacement, and this release ships as a symmetric pair with `deep-review` v1.5.0.0.

> Spec folder: `.opencode/specs/system-spec-kit/026-graph-and-context-optimization/017-sk-deep-cli-runtime-execution/001-executor-feature` (Level 3)

## What's New at a Glance

- **Choose an executor for each iteration.** `executor.kind` selects `native` or `cli-codex`, with `native` as the default and the same agent dispatch as before. The `cli-codex` branch runs `codex exec` with the model and flags from config, piping the iteration prompt through stdin.
- **Render both executor prompts from one template.** The iteration context that lived inline in the YAML, its state summary, focus area, constraints and file paths, is extracted into `assets/prompt-pack-iteration.md.tmpl`, because a CLI executor needs a file it can read. Before, the YAML runtime could pass the inline string directly into the native agent's context, whereas both dispatch paths now render the same template and see the same content, leaving no implicit context gap between the native agent path and the CLI path.
- **Configure executor settings in one block.** `deep_research_config.json` adds `executor.kind`, `model`, `reasoningEffort`, `serviceTier`, `sandboxMode` and `timeoutSeconds`. `kind: "native"` is the default and the other fields default to null. Invalid combinations, such as `cli-codex` without a model or an unwired reserved executor, produce typed errors at config load.
- **Set up executor choices with flags.** The `deep-research.md` command doc at `.opencode/commands/deep/research.md` adds `--executor`, `--model`, `--reasoning-effort`, `--service-tier` and `--executor-timeout`. Flags take precedence over config, which takes precedence over the schema default. When none of these flags is set and the topic does not mention an executor, setup asks one optional question to choose `native` or `cli-codex`.
- **Record non-native executor details per iteration.** The JSONL record gains `executor: {kind, model, reasoningEffort, serviceTier}` so readers can identify the executor for each iteration. Native runs omit the audit because the YAML identifies their executor.
- **Check iteration outputs after dispatch.** Each executor must produce a markdown narrative file and a JSONL delta record with required fields. Missing or empty iteration output, a missing delta or missing required fields emits a canonical `schema_mismatch` conflict event, and three consecutive validation failures trigger the existing stuck-recovery path.
- **Document the executor contract.** `SKILL.md` replaces a forward-looking note with the shipped and reserved kinds, executor invariants, failure detection and recovery, and the locations of the config and template.
- **Explain executor recovery in the loop protocol.** Section 3 of `references/loop-protocol.md` describes how branch selection interacts with `schema_mismatch` and stuck recovery. Branch selection does not change recovery semantics, and the existing flow handles CLI failures like agent failures.

## Upgrade

No migration required. The `native` default preserves the same agent dispatch, iteration file and JSONL record, and existing config files need no changes.

To opt into `cli-codex` dispatch, invoke:

```
/deep:research :auto "topic" \
  --executor=cli-codex \
  --model=gpt-5.4 \
  --reasoning-effort=high \
  --service-tier=fast
```

Requires `codex` on PATH. Reserved kinds `cli-copilot` and `cli-claude-code` are declared in the config enum but throw `ExecutorNotWiredError` at config load with a pointer to future specs.
