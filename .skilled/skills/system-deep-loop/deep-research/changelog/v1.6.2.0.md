This patch tightens the research reducer and surrounding reference docs so they describe the same behavior. It fixes state handling, restores visible run-history data and closes a few cases where the workflow could silently drift from the docs.

> Spec folder: `.opencode/specs/skilled-agent-orchestration/042-deep-research-review-improvement-2/` (Level 3)
> Review session: `rvw-2026-04-12T11-30-00Z`

## What's New at a Glance

- **Dashboard status follows the latest `synthesis_complete` event.** `reduce-state.cjs` parses that event instead of deriving status from stale config.
- **Run history now shows resume and restart lineage.** The reducer detects lifecycle events and updates run-history fields in the registry and dashboard, propagating lineage emitted to JSONL into config-visible state and surfacing `continuedFromRun`, which the dashboard never surfaced.
- **Graph convergence has a fallback.** When `blendedScore` is absent from `graph_convergence` events, the score uses the same numeric fallback pattern as review instead of collapsing to `0`.
- **Corrupt JSONL now raises an error.** `reduceResearchState()` throws a structured corruption error instead of returning quietly, matching the deep-review side.
- **Completed sessions are no longer re-entered for synthesis.** Both workflow YAMLs routed completed sessions straight to the synthesize step, although the expected behavior called that unsupported. A completed packet is now a hard stop that requires an explicit operator choice to restart, archive or exit.
- **The config template lists three modes.** `deep_research_config.json` removes `fork` and `completed-continue`, changes `archiveRoot` to `research_archive`, and lists `new`, `resume` and `restart`.
- **The protocol reflects shipped planning and replay.** `loop_protocol.md` updates the wave section from the older question-count model and corrects replay from delta-based to full-history.
- **Step 1 names its config input.** `deep-research.md` now lists `research/deep-research-config.json` as an explicit input.
- **The playbook references the current graph event interface.** `graph-events-emission.md` now references the flat `graphEvents` schema and `handleCoverageGraphUpsert()` interface.
