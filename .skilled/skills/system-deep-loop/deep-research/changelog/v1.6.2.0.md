This patch tightens the research reducer and the surrounding reference docs. Both now describe the same behavior. It fixes state handling and restores visible run-history data. It also closes a few cases where the workflow could silently drift from the docs.

&nbsp;

## What's New at a Glance

- Dashboard status follows the latest `synthesis_complete` event.
  - `reduce-state.cjs` parses that event.
  - It no longer derives status from stale config.
- Run history now shows resume and restart lineage.
  - The reducer detects lifecycle events.
  - It updates run-history fields in the registry and the dashboard.
  - It propagates lineage emitted to JSONL into config-visible state.
  - The dashboard now surfaces `continuedFromRun`, which it never surfaced.
- Graph convergence has a fallback.
  - When `blendedScore` is absent from `graph_convergence` events, the score uses the same numeric fallback pattern as review.
  - It does not collapse to `0`.
- Corrupt JSONL now raises an error.
  - `reduceResearchState()` throws a structured corruption error.
  - It no longer returns quietly.
  - This matches the deep-review side.
- Completed sessions are no longer re-entered for synthesis.
  - Both workflow YAMLs sent completed sessions straight to the synthesize step.
  - The expected behavior called that unsupported.
  - A completed packet is now a hard stop.
  - It requires an explicit operator choice to restart, archive or exit.
- The config template lists three modes.
  - `deep_research_config.json` removes `fork` and `completed-continue`.
  - It changes `archiveRoot` to `research_archive`.
  - It lists `new`, `resume` and `restart`.
- The protocol reflects shipped planning and replay.
  - `loop_protocol.md` updates the wave section from the older question-count model.
  - It corrects replay from delta-based to full-history.
- Step 1 names its config input.
  - `deep-research.md` now lists `research/deep-research-config.json` as an explicit input.
- The playbook references the current graph event interface.
  - `graph-events-emission.md` now references the flat `graphEvents` schema.
  - It also references the `handleCoverageGraphUpsert()` interface.
