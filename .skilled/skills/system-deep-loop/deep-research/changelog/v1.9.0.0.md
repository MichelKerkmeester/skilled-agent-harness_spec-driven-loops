This release completes the executor expansion begun in v1.8.0.0 by making `cli-copilot` and `cli-claude-code` available for research iterations and rejecting settings their CLIs do not support. Phase 018 wired `cli-codex` as its only new executor and reserved the two new CLIs in the config enum while rejecting them at load time. The YAML workflow keeps ownership of state, convergence, lifecycle and the reducer, and this release ships as a symmetric pair with `deep-review` v1.6.0.0.

> Spec folder: `.opencode/specs/system-spec-kit/026-graph-and-context-optimization/017-sk-deep-cli-runtime-execution/002-runtime-matrix` (Level 3)

## What's New at a Glance

- **Research iterations can use `cli-copilot`.** Config parsing previously rejected `kind: cli-copilot` with `ExecutorNotWiredError`. Dispatch now runs `copilot -p "PROMPT" --model X --allow-all-tools --no-ask-user`. Copilot has no stdin support or CLI flags for reasoning effort and service tier, so reasoning effort must be set in `~/.copilot/config.json` ahead of time.
- **Iterations can use `cli-claude-code`.** Dispatch runs `claude -p "PROMPT" --model claude-opus-4-6 --permission-mode acceptEdits --output-format text`, adding `--effort X` when `reasoningEffort` is set. The default `plan` permission mode is read-only, so dispatch uses `acceptEdits` to let iterations write outputs. Claude Code has no service-tier flag, which the config rejects.
- **Flag checks follow the selected CLI.** The config validates non-default settings against that CLI's supported flags and returns an error naming an incompatible field and kind. For example, a `serviceTier` error for `cli-copilot` lists `model`, `sandboxMode` and `timeoutSeconds` as supported. Phase 018's flat config block, the same six fields in both `deep_research_config.json` and `deep_review_config.json`, is preserved. A Zod discriminated union with per-kind sub-schemas was rejected because it would break the config symmetry between the two skills and churn the optimizer manifest every time a new kind lands.
- **Non-native runs record executor details.** Each non-native run adds `executor: {kind, model, reasoningEffort, serviceTier}` to the last state-log entry. Readers can identify which of the four executor kinds produced each iteration.
- **The `deep-research` setup prompt expands from two executors to four.** It previously offered native (A) and `cli-codex` (B), and now adds `cli-copilot` (C) and `cli-claude-code` (D), with canonical flags and notable limitations for each. Passing `--executor=cli-copilot` on the command line skips the question.
- **Both executor contracts mark the new CLIs shipped.** The `SKILL.md` contract tables replace the earlier not-wired status for `cli-copilot` and `cli-claude-code` with `Shipped (spec 019)`.
- **Cross-CLI delegation is documented as design intent.** Both `SKILL.md` files gain a Cross-CLI Delegation subsection under the Executor Selection Contract. Any CLI executor can shell out to another CLI from its iteration sandbox, while self-recursive invocation is forbidden and each individual CLI skill warns against it. Users handle authentication and environment propagation because each CLI uses its own credentials and the deep-loop workflow does not mediate them. Runtime enforcement is out of scope.
- **Loop protocol references cover all four kinds.** Section 3 of both `references/loop-protocol.md` files now gives canonical dispatch shapes for native, `cli-codex`, `cli-copilot` and `cli-claude-code` instead of only native and `cli-codex`. It also cites per-kind flag-compatibility enforcement.

## Upgrade

No migration required. The default `kind: native` is unchanged, and users already on `cli-codex` get no behavior change. Users previously blocked from `cli-copilot` or `cli-claude-code` can now run either.

Each CLI must be on PATH and authenticated. To opt into `cli-copilot`, run:

```
/deep:research :auto "topic" \
  --executor=cli-copilot \
  --model=gpt-5.4
```

To opt into `cli-claude-code`, run:

```
/deep:research :auto "topic" \
  --executor=cli-claude-code \
  --model=claude-opus-4-6 \
  --reasoning-effort=high
```

At config parse time, a setting unsupported by the selected CLI, such as `--service-tier=fast` with `--executor=cli-copilot`, is rejected with an error naming the unsupported field.
