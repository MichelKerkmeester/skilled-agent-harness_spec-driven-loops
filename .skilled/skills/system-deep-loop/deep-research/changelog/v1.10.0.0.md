This release hardens the shipped CLI executor matrix. It also closes related gaps in metadata handling, continuity and documentation. Non-native dispatches carry executor identity from their first record. Failed runs preserve attribution without a valid iteration record. Description repair now preserves authored content in parseable schema-invalid files. Continuity and readiness guidance state the boundaries their existing rules and handlers use.

> Spec folder: `.opencode/specs/system-spec-kit/026-graph-and-context-optimization/018-cli-executor-remediation` (Level 3)

## Why This Release

A 30-iteration deep-research pass covered Phase 017 refinements. It surfaced seven P1 findings in the shipped CLI executor matrix.

## What's New at a Glance

- **Non-native runs now record executor identity before dispatch.** Each iteration gets provenance from its first record.
- **A typed `dispatch_failure` event covers runs without a valid iteration record.** It keeps executor attribution after a crash or timeout.
- **Copilot now uses `@path` for prompts above 16 KB.** Large prompts avoid shell argument-length limits.
- **Graph metadata now carries `save_lineage`.** Its values distinguish metadata refreshed together from later one-sided rewrites.
- **A precision-aware timestamp helper is available for future validator wiring.** Existing validator callers are untouched this release.
- **Retry decisions now emit `retry_attempt` telemetry.** The retry budget remains `N=3`.
- **Evidence-marker parsing now handles indented and nested fences.** Indented fences no longer cause false-positive warnings. Nested fences are tracked as content.
- **Description repair preserves authored content in parseable schema-invalid files.** Canonical derived fields take precedence.
- **Readiness docs distinguish emitted trust states from compatibility vocabulary.** This reflects the values the seven code-graph handlers emit.
- **Copilot guidance now states concurrency caps and reasoning-effort configuration.** It distinguishes repository guidance from upstream limits.
- **Continuity and retry docs now label their budgets as heuristics.** The 10-minute and `N=3` values are unchanged.
- **Caller-context coverage now includes three async boundaries.** The added boundaries cover `setImmediate`, `queueMicrotask` and `timers/promises`.

## CLI Dispatch

#### Failures Keep Executor Provenance

Before this release, the `executor` audit block was merged onto the last JSONL record. That happened only after validation. So a crash or empty output could leave the failure anonymous. `writeFirstRecordExecutor` now stamps executor identity on the first iteration record before dispatch. Post-dispatch validation rejects non-native runs without the `executor` field. It uses the `executor_missing` reason. Native runs are unchanged.

&nbsp;

#### Dispatch Failures Keep Attribution

A crash, timeout or missing output now produces a typed `dispatch_failure` record. It carries the executor block, reason, iteration and timestamp. The reducer accepts this record without a duplicate `schema_mismatch`. Three consecutive records trigger the existing stuck-recovery path.

&nbsp;

#### Copilot Handles Large Prompts

Phase 019 documented the `@path` fallback but did not implement it. Four dispatch branches now check the rendered prompt file. They are the deep-research and deep-review auto and confirm branches. Prompts at or below 16 KB use the positional form. Larger prompts use `copilot -p "Read the instructions in @<path> and follow them exactly. Do not deviate." --model X --allow-all-tools --no-ask-user`.

## Metadata and Continuity

#### Save Lineage Clarifies Freshness

`graph-metadata.json` now has an optional `derived.save_lineage` field. Its values are `description_only`, `graph_only` and `same_pass`. The canonical save path stamps `same_pass` when description and graph metadata refresh together. The graph-metadata backfill stamps `graph_only` on existing files during migration. The values distinguish same-pass refreshes from later one-sided rewrites. They do this without relying on timestamp subtraction alone.

&nbsp;

#### A Helper for Future Validation

The new `lib/continuity/timestamp-normalize.ts` module exposes `isLowPrecision(raw)`, `normalizeTimestampPrecision(raw)` and `comparePrecisionAware(a, b, thresholdMs)`. Date-only and midnight-UTC values count as low precision. The helper bypasses strict staleness thresholds for them. It is additive for future validator wiring. Existing validator callers are untouched this release. The 10-minute continuity threshold is unchanged.

&nbsp;

#### Retry Decisions Emit Records

Each retry decision emits a structured `retry_attempt` record. It carries `memoryId`, `step`, `reason`, `attempt`, `outcome` and `timestamp`. `MAX_RETRIES = 3` is unchanged.

&nbsp;

#### Caller Context Covers Async Boundaries

The `AsyncLocalStorage` caller-context path now has committed regression coverage for these async boundaries:

- `setImmediate`
- `queueMicrotask`
- `timers/promises`

## Description Repair

#### Schema-Invalid Files Keep Content

Phase 017's `generate-description.js` treated parse failures and schema violations as the same `null` result. It then rebuilt a minimal replacement. That replacement could discard authored rich content. The 30-iteration research found 29 of 86 packet-level `description.json` files in the `026` tree. Each was one invalid edit away from lossy repair.

The loader now returns a result with `ok` and optional `partial` data. It also returns a reason of `file_missing`, `parse_error` or `schema_error`. Parse errors use the minimal replacement. For parseable schema-invalid files, repair preserves authored narrative and extension keys. Canonical derived fields win on conflict.

## Evidence and Documentation

#### Fence Parsing Avoids False Warnings

Indented code blocks no longer trigger false-positive evidence-marker warnings. This covers blocks whose triple-backtick fences start after four spaces. A line-start triple-backtick fence nested inside an open fence is tracked as content. It is not treated as a closer. An isolated four-backtick fence remains safe. Mismatched or unclosed fences remain separate false-negative cases. Regression fixtures document their expected behavior.

&nbsp;

#### Readiness Docs Match Emitted States

The seven code-graph handlers emit four trust states in practice. They are `live`, `stale`, `absent` and `unavailable`. The shared type declares eight. Readiness-contract documentation in `deep-research/SKILL.md` and `deep-review/SKILL.md` now marks four values as compatibility vocabulary. They are `cached`, `imported`, `rebuilt` and `rehomed`. The audited handler set does not emit them.

&nbsp;

#### Copilot Guidance Clarifies Limits

The Phase 018 `feedback_copilot_concurrency_override` memory rule sets the repo-safe concurrency cap at 3. The upstream API cap is 5. `cli-copilot/SKILL.md` describes reasoning effort as config-driven through `~/.copilot/config.json`. It is not a CLI flag.

&nbsp;

#### Budgets Are Policy Heuristics

Continuity docs now describe the 10-minute threshold as a one-sided policy budget pending telemetry. This replaces wording that suggested empirical calibration. `system-spec-kit/SKILL.md` labels `N=3` a bounded-hot-loop heuristic. Calibration will follow once `retry_attempt` telemetry produces real attempt histograms.

## Upgrade Notes

- No migration required. Existing native-path users see identical behavior.
- Existing `cli-codex` users gain first-write executor provenance automatically.
- Copilot prompts above 16 KB use the `@path` fallback instead of risking shell argument-length failure.
- `save_lineage` is optional in this release. A follow-up packet will require it once the backfill script runs across production metadata.
- **Rollback.** The `SPECKIT_DESCRIPTION_REPAIR_MERGE_SAFE` flag defaults to on. Setting `SPECKIT_DESCRIPTION_REPAIR_MERGE_SAFE=false` restores Phase 017 minimal-replacement behavior. Reverting the packet in one commit restores the full Phase 019 surface.
