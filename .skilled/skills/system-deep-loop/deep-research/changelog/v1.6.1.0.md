This patch closes the remaining 042 closing-audit fallout for `deep-research`. It retracts two lifecycle choices that never worked, documents the graph-event format the runtime depends on and prevents session collisions in the shared graph cache.

> Spec folder: `.opencode/specs/skilled-agent-orchestration/042-deep-research-review-improvement-2/` (Level 3)

## What's New at a Glance

- **The two unsupported lifecycle modes are deferred.** When a research packet already existed, the workflow asked operators how to continue: `resume` the same run, start a fresh run, `fork` into a sibling run history, or use `completed-continue` to reopen a finished run after snapshotting its synthesis. The first two choices worked. `fork` and `completed-continue` had no workflow wiring and did the same thing as `resume` and quietly kept the old session id, so operators who thought they had branched a research run history ended up overwriting the original. `SKILL.md`, `README.md`, both loop-protocol references, both command workflows and the Claude Code and Codex agent definitions now mark the modes as deferred, while the normal happy path stays the same with `new`, `resume` and `restart` as the visible choices. The v1.5.0.0 changelog gained an append-only "Update (post-release)" block that points at this release.
- **`resume` and `restart` record typed session events.** `resume` keeps the current session id and appends a typed `resumed` event to the state log, while `restart` archives the existing `research/` folder under a timestamped `research_archive/` directory, mints a fresh session id and appends a typed `restarted` event with the archive path. Both events carry the full run-history field set the reducer reads.
- **The graph-event contract is documented.** Each iteration can emit a `graphEvents` array in its state-log record for the coverage-graph MCP tools to persist in the shared SQLite cache, and `references/state-format.md` now supplies the event shape missing from `state_format.md`, including how nodes and edges relate, every field (`type`, `id`, `label`, optional `relation`, `source`, `target` and `metadata`), accepted type (`question`, `finding`, `claim`, `source` and `edge`), a worked example and four session-scope rules. After an external consumer started salting ids with the session id to avoid collisions and broke provenance tracing, `references/state-format.md` warns producers against session-id salting because storage handles isolation.
- **The shared graph cache now prevents session collisions.** Filtered reads worked, while writes keyed on the bare id, so two sessions using the same logical node or edge id (`q-reconnect`, `f-001`, etc.) could silently overwrite each other's rows. The shared coverage-graph database moves from schema version 1 to version 2, with a composite primary key of spec folder, loop type, session id and logical id on both its node and edge tables. Its first open after the upgrade drops the old tables and creates the new ones, so callers can safely reuse ids and `deep-research`'s `graphEvents` still round-trip unchanged through the graph convergence MCP tool.

## Upgrade

No migration required. Existing research packets continue to resume exactly as before, and their state logs parse unchanged. The graph database is a dev-only derived cache that rebuilds from iteration `graphEvents`. Operators relying on `fork` or `completed-continue` should archive the prior `research/` folder manually or choose `restart`, which does both in one step. Both deferred modes are reserved for a future release and will return only with first-class event emission and replay coverage.
