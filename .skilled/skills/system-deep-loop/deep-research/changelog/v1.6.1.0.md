This patch closes the remaining 042 closing-audit fallout for `deep-research`. It retracts two lifecycle choices that never worked. It documents the graph-event format the runtime depends on. It also prevents session collisions in the shared graph cache.

## What's New at a Glance

- **The two unsupported lifecycle modes are deferred.** When a research packet already existed, the workflow asked operators how to continue. The choices were `resume` the same run or start a fresh run. The other two were `fork` into a sibling run history and `completed-continue` to reopen a finished run after snapshotting its synthesis. The first two choices worked. `fork` and `completed-continue` had no workflow wiring. They did what `resume` did and quietly kept the old session id. So operators who thought they had branched a research run history overwrote the original. `SKILL.md`, `README.md`, both loop-protocol references and both command workflows now mark the modes as deferred. So do the Claude Code and Codex agent definitions. The normal happy path stays the same. The visible choices are `new`, `resume` and `restart`. The v1.5.0.0 changelog gained an append-only "Update (post-release)" block that points at this release.
- **`resume` and `restart` record typed session events.** `resume` keeps the current session id. It appends a typed `resumed` event to the state log. `restart` archives the existing `research/` folder under a timestamped `research_archive/` directory. It mints a fresh session id. It appends a typed `restarted` event with the archive path. Both events carry the full run-history field set the reducer reads.
- **The graph-event contract is documented.** Each iteration can emit a `graphEvents` array in its state-log record. The coverage-graph MCP tools persist that array in the shared SQLite cache. `references/state-format.md` now supplies the event shape missing from `state_format.md`. It covers how nodes and edges relate. It lists every field: `type`, `id`, `label`, optional `relation`, `source`, `target` and `metadata`. It lists the accepted type: `question`, `finding`, `claim`, `source` and `edge`. It adds a worked example and four session-scope rules. An external consumer started salting ids with the session id to avoid collisions. That broke provenance tracing. So `references/state-format.md` warns producers against session-id salting, because storage handles isolation.
- **The shared graph cache now prevents session collisions.** Filtered reads worked. Writes keyed on the bare id. Two sessions could use the same logical node or edge id (`q-reconnect`, `f-001`, etc.). So they could silently overwrite each other's rows. The shared coverage-graph database moves from schema version 1 to version 2. Both its node and edge tables get a composite primary key. The key is spec folder, loop type, session id and logical id. Its first open after the upgrade drops the old tables and creates the new ones. So callers can safely reuse ids. `deep-research`'s `graphEvents` still round-trip unchanged through the graph convergence MCP tool.

## Upgrade

No migration required. Existing research packets continue to resume exactly as before. Their state logs parse unchanged. The graph database is a dev-only derived cache. It rebuilds from iteration `graphEvents`. Operators relying on `fork` or `completed-continue` should archive the prior `research/` folder manually. Or they should choose `restart`, which does both in one step. Both deferred modes are reserved for a future release. They will return only with first-class event emission and replay coverage.
