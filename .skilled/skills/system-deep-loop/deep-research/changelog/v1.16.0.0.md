# v1.16.0.0, Expansive Depth Mode for Research

Deep research stops once its starting questions are answered. This release adds an opt-in mode that lets a run grow its own questions. It also lets a completed run take more iterations in place.

- Leaves propose new sub-questions while the run works.
- Each proposal passes fixed checks before it joins the question set.

Runs without the flag keep their behavior.

- Nothing changes unless the flag is passed.
- The one difference is one paragraph in CLI lineage prompts.

&nbsp;

## Why This Release

A run that answers its starting questions narrowly looks finished. Nothing could add a question once the run began. So a broad topic could stop early.

- Narrow coverage looked the same as converged coverage.
- The new mode lets the run widen within fixed bounds.

## Turning It On

Turning the mode on takes one flag. Without the flag, a run keeps its old behavior. Its dashboard gains no new section.

#### Widen a run with one flag <a id="c-widen-a-run-with-one-flag"></a>

- Pass `--depth-mode=expansive` to a research run.
- Leave the flag out to keep the old behavior.
- Passing `--depth-mode=default` also keeps the old behavior.
- `rg -n -- '--depth-mode' .skilled/commands/deep/research.md` finds the flag row.

#### Default runs keep their output <a id="c-default-runs-keep-their-output"></a>

- A default run writes the same registry, dashboard, focus and prompt pack as before.
- The stop config echo stays the same.
- The mode key appears only on expansive runs.
- CLI lineage prompts gain one paragraph in the agent persona.
- That paragraph has no effect on a default run.

#### See the frontier on the dashboard <a id="c-see-the-frontier-on-the-dashboard"></a>

- An expansive run adds a `## 6B. FRONTIER` section to its dashboard.
- The section shows frontier size and pruned nodes.
- It also shows revisits and budget spent at each depth.
- A default dashboard has no such section.

## Admitting New Questions

Leaves propose sub-questions as rows. The run checks each one before it changes the question set.

#### Open questions exist before the first pass <a id="c-open-questions-exist-before-the-first-pass"></a>

- The run splits its topic into starting nodes before iteration one.
- The model running the loop writes those nodes.
- It works from the topic and its key questions.
- Every starting node passes the same checks.
- A repeated launch adds no second set of nodes.

#### Every proposal passes six fixed checks <a id="c-every-proposal-passes-six-fixed-checks"></a>

- The checks run in one fixed order.
- Relevance comes first, then dedupe, depth, fan-out, budget and cycle.
- Relevance needs evidence, a scope and a parent that exists.
- Dedupe refuses a question the run already holds.
- Depth stops at three levels.
- Fan-out caps each parent at six children.
- Fan-out also caps the total node count.
- A child cannot hold more budget than its parent.
- A cycle is refused.

#### Rejected proposals name their reason <a id="c-rejected-proposals-name-their-reason"></a>

- The first failing check decides the reason.
- A pruned proposal keeps its reason in the node store.
- A pruned proposal never reaches the research inbox.
- An admitted proposal adds one question with origin `frontier`.

&nbsp;

## Steering and Stopping

Once nodes exist, the run works the shallowest one. It stops only when no node stays open within budget.

#### Focus goes to the shallowest open node <a id="c-focus-goes-to-the-shallowest-open-node"></a>

- Next Focus picks the open node at the lowest depth.
- Ties go to the least visited node.
- The oldest node wins any remaining tie.
- The focus line reads `Frontier node <id> (depth <n>, scope <scope>): <question>`.
- A visit to a node does not answer its question.
- A reworded focus still counts as a visit.
- It must keep the node's marker.

#### A run keeps going while nodes stay open <a id="c-a-run-keeps-going-while-nodes-stay-open"></a>

- A run that looks converged keeps going while a node is open within budget.
- The veto applies only when the expansive flag is on.
- The iteration cap still wins.
- Consecutive failures, stuck recovery and pause still win.
- The max-duration stop still wins.
- The off setting and the max-iterations policy still win.
- A held run reports `frontierOpen` as its reason detail.
- Under `--convergence-mode=divergent`, a pivot waits until no frontier node is open or active.

#### Budget is shared across three depth bands <a id="c-budget-is-shared-across-three-depth-bands"></a>

- The iteration budget splits 50, 35 and 15 percent across three depth bands.
- Unused budget rolls down to a deeper band.
- Unused budget never rolls up.
- A band that runs out closes its open nodes as exhausted for budget.
- With `--max-iterations` left at its default, the run sizes its budget from the seed. The formula is `min(24, max(10, 2 × (S + maxDepth − 1)))` iterations for S seeded depth-1 nodes, 16 at six seeds.
- The seed step prints the derived budget, and the node cap stays half of it.
- A fan-out lineage dealt no seed node runs at its floor.
- The floor is 12 iterations for a native lineage and 10 for a CLI one.
- An explicit `--max-iterations`, marker, setup answer or fan-out matrix `iterations` value is kept as given.

#### Finished nodes stop counting as open <a id="c-finished-nodes-stop-counting-as-open"></a>

- A node that finishes resolves its question and records its status.
- A finished node stops lowering question coverage and source diversity.
- A stuck run closes its active node as exhausted.
- Focus then moves on.
- A run whose nodes have all finished can reach a clean stop.

## Completed Runs

A run that stopped at its iteration cap can take more iterations without starting a new session.

#### A finished run takes more iterations <a id="c-a-finished-run-takes-more-iterations"></a>

- `--extend=N` reopens a run whose config carries `status: "complete"`.
- The run keeps its `sessionId` and generation and enters lineage mode `completed-continue`.
- The iteration cap becomes the iterations run so far plus N.
- `--extend-minutes=M` adds M minutes to the later of the prior duration budget and the time elapsed since `createdAt`.
- Without the flag, the added minutes equal the prior budget, so the budget grows by that amount.
- One `run_extended` ledger event is recorded and projected as one `extended` row. No `resumed` row is written.
- The prior synthesis is copied to `research/synthesis-v{generation}-r{continuedFromRun}.md` before the first new iteration.
- The extension keeps the stop policy and convergence mode the run was created with.
- An extension is refused with fan-out and on a run that is not complete.

&nbsp;

## Fan-Out Runs

Fan-out runs share the starting nodes across their lineages. Then the merge checks the split.

#### Lineages share the starting nodes <a id="c-lineages-share-the-starting-nodes"></a>

- The starting nodes deal out round-robin across the lineages.
- Each lineage writes its share to its own store first.
- The orchestration summary records which lineage holds which node.
- The merged result carries the frontier from every lineage.

#### The merge names a missing node <a id="c-the-merge-names-a-missing-node"></a>

- The merge checks that every starting node reached a lineage.
- A node that no lineage holds is named in a warning on stderr.
- The merge still finishes.
- One missing node does not cost the synthesis.

## Upgrade Notes

No action is needed for existing runs. Only a run that passes a new flag changes.

#### Before You Start <a id="c-before-you-start"></a>

1. Keep your research commands as they are. They behave as before.
2. A finished run that needs more iterations takes `--extend=N`. It continues in the same session instead of starting a new one.

<details>
<summary><b>Turning It On</b></summary>

- Add `--depth-mode=expansive` to a research run to let it widen.
- Read the `## 6B. FRONTIER` section of the dashboard.
- The section shows what the run added.

</details>
