Deep-research's graph work now has a peer skill of its own. The change gives its workflows a direct route to graph state instead of relying on a separate skill's MCP server.

> Spec folder: `.opencode/specs/skilled-agent-orchestration/116-deep-skill-evolution/` (Level 3)

## Why This Release

Before arc 118, workflow steps that needed graph state passed through an MCP marshalling layer. The arrangement had accumulated drift with no ADR to justify it.

Arc 118, a user-directive override of the 117 AI Council SPLIT ruling, consolidated deep-loop runtime infrastructure in a peer skill. Operators tracing a deep-research bug now stay within `deep-loop-runtime/` and `deep-research/` instead of traversing another skill's MCP server source tree.

## What's New at a Glance

- **Graph operations now belong to `deep-loop-runtime`.** It is the new peer skill in `FULL_ISOLATE_NO_MCP` mode for deep-research graph work.
- **Workflow YAMLs now call `.cjs` scripts directly.** The four `mcp__system_spec_memory__deep_loop_graph_*` tools are removed.
- **The deep-research version is `v1.12.0.0`.** Its `SKILL.md` frontmatter now matches the changelog history.

## Deep Research

#### Graph Runtime Leaves the MCP Server

Two consumer skills, `deep-research` and `deep-review`, depended on internals of `system-spec-kit/mcp-server/`. The 13 lib files and four graph operations, convergence, upsert, query and status, previously hosted there now live in `deep-loop-runtime/`.

Any deep-research-adjacent code that imported from `system-spec-kit/mcp-server/lib/deep-loop/*` or `system-spec-kit/mcp-server/lib/coverage-graph/*` now imports from `deep-loop-runtime/lib/{deep-loop,coverage-graph}/*`.

The `deep-loop-graph.sqlite` database moved with its schema-owner code to `.opencode/skills/deep-loop-runtime/storage/`.

The `mcp-server/vitest.config.ts` include glob now discovers tests at `../deep-loop-runtime/tests/**/*.{vitest,test}.ts`. A single `pnpm vitest run` exercises both surfaces. The only test that stayed in `mcp-server/tests/deep-loop/` is `review-depth-reducer.vitest.ts`, which tests `deep-review/scripts/reduce-state.cjs` in `deep-review/`, not the migrated runtime.

&nbsp;

#### Graph Work Runs Through Scripts

Before arc 118, `deep_research_auto.yaml` and `deep_research_confirm.yaml` dispatched graph operations through tools registered with the spec-memory MCP server. Both workflows now invoke scripts directly for convergence, upsert, query and status, following the pattern already used by `reduce-state.cjs`.

For example, the convergence script is `node .opencode/skills/deep-loop-runtime/scripts/convergence.cjs --spec-folder "{spec_folder}" --loop-type "research" --session-id "{session_id}"`. Output bindings stay byte-equivalent, and the scripts emit the same JSON-on-stdout shape as the removed tools.

**Breaking:** The four `mcp__system_spec_memory__deep_loop_graph_*` tools have no aliases. External code that hardcoded those tool names must switch to the script paths.
