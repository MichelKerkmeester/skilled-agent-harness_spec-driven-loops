# v1.12.0.0, Graph Work Moves to a Peer Skill

Deep-research's graph work now has a peer skill of its own.

- `deep-loop-runtime` is the new peer skill for deep-research graph work.
- It runs in `FULL_ISOLATE_NO_MCP` mode.
- Graph operations now belong to `deep-loop-runtime`.

Its workflows reach graph state directly.

- Workflow YAMLs now call `.cjs` scripts directly.
- Both workflows invoke scripts for convergence, upsert, query and status.
- Output bindings stay byte-equivalent.
- The scripts emit the same JSON-on-stdout shape as the removed tools.

They no longer rely on a separate skill's MCP server.

- The four `mcp__system_spec_memory__deep_loop_graph_*` tools are removed.
- The deep-research version is now `v1.12.0.0`.
- Its `SKILL.md` frontmatter now matches the changelog history.

> [!IMPORTANT]
> 1 change can break an existing setup. Read this before you update.
>
> 1. The four `mcp__system_spec_memory__deep_loop_graph_*` tools have no aliases. [Graph Work Runs Through Scripts](#c-graph-work-runs-through-scripts)

&nbsp;

## Why This Release

Before arc 118, workflow steps that needed graph state passed through an MCP marshalling layer. The arrangement had accumulated drift. No ADR justified it.

- Arc 118 overrode the 117 AI Council SPLIT ruling by user directive.
- It consolidated deep-loop runtime infrastructure in a peer skill.
- Operators tracing a deep-research bug now stay within `deep-loop-runtime/` and `deep-research/`.
- They no longer traverse another skill's MCP server source tree.

## Deep Research

Two consumer skills depended on internals of `system-spec-kit/mcp-server/`. They are `deep-research` and `deep-review`.

#### Graph Runtime Leaves the MCP Server <a id="c-graph-runtime-leaves-the-mcp-server"></a>

- `deep-research` and `deep-review` depended on internals of `system-spec-kit/mcp-server/`.
- That folder hosted 13 lib files and four graph operations.
- The operations are convergence, upsert, query and status.
- The 13 lib files and the four operations now live in `deep-loop-runtime/`.
- Any deep-research-adjacent code that imported from `system-spec-kit/mcp-server/lib/deep-loop/*` or `system-spec-kit/mcp-server/lib/coverage-graph/*` now imports from `deep-loop-runtime/lib/{deep-loop,coverage-graph}/*`.
- The `deep-loop-graph.sqlite` database moved to `.opencode/skills/deep-loop-runtime/storage/`.
- Its schema-owner code moved with it.

#### Graph Work Runs Through Scripts <a id="c-graph-work-runs-through-scripts"></a>

- Before arc 118, `deep_research_auto.yaml` and `deep_research_confirm.yaml` dispatched graph operations through tools.
- Those tools were registered with the spec-memory MCP server.
- Both workflows now invoke scripts directly for convergence, upsert, query and status.
- They follow the pattern already used by `reduce-state.cjs`.
- For example, the convergence script is `node .opencode/skills/deep-loop-runtime/scripts/convergence.cjs --spec-folder "{spec_folder}" --loop-type "research" --session-id "{session_id}"`.
- Output bindings stay byte-equivalent.
- The scripts emit the same JSON-on-stdout shape as the removed tools.

> [!WARNING]
> The four `mcp__system_spec_memory__deep_loop_graph_*` tools have no aliases. External code that hardcoded those tool names must switch to the script paths.
