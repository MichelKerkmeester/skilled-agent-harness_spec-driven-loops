This first release makes `deep-ai-council` a dedicated skill, giving AI council deliberation its own home and runtime agent. The advisor learns to route council prompts to the new skill, and the planning-only boundary is enforced through scoped-write helpers that only ever touch packet-local `ai-council/**` artifacts. References and persistence support ship with the skill, with two packets creating its surface and documenting its agent contract.

> Spec folder: `.opencode/specs/skilled-agent-orchestration/101-deep-multi-ai-council-skill/{001-deep-ai-council-skill-creation, 003-deep-ai-council-reference-expansion}` (Level 1)

## Why This Release

Before this release, council deliberation was a multi-strategy planning idea threaded through `system-spec-kit`, while its references, persistence scripts and routing lived inside an unrelated skill. That made it hard to evolve council behavior without touching spec-folder governance.

## What's New at a Glance

- **Council deliberation has a dedicated skill.** The package separates council work from `system-spec-kit`.
- **The runtime agent is now `@deep-ai-council`.** OpenCode, Claude and Codex use the new identity.
- **The advisor routes explicit council prompts.** Prompts for council deliberation reach its skill.
- **Council artifact writes are scoped to packet-local storage.** The state log records artifact writes and round rollback events.
- **References and the README document council operation.** Their topics include persistence, Depth 0 versus Depth 1 detection, troubleshooting and the runtime mirrors.

## Council Skill

#### A Codebase-Agnostic Council

The skill owns activation triggers, smart routing across eight council intents, the planning-only operational boundary and the rules for reproducible council reports. Any project can dispatch a council without inheriting Webflow or OpenCode-specific patterns.

&nbsp;

#### A Documented Agent Contract

The runtime agent body documents the nine-step workflow from RESOLVE through DELIVER. It defines Depth 0 parallel dispatch via `Task`, Depth 1 sequential dispatch via `sequential_thinking` MCP and the fixed writer order that gives every artifact an audit event.

## Runtime and Routing

#### One Name Across Runtimes

The runtime agent ships as `@deep-ai-council` across OpenCode, Claude and Codex. This replaces the former `multi-ai-council` name in all three runtime mirrors.

Natural prompts like "Run an AI council deliberation to compare implementation plans" used to fall through to a generic explainer because the source scorer's read-only guard tripped on phrases like "compare implementation plans". The advisor source scorer now allows explicit `deep-ai-council` council phrases through that guard and routes them to the skill.

## Persistence and State

The persistence boundary keeps council artifacts within each packet's `ai-council/` tree and preserves an additive-only event history.

#### Council Writes Stay In Scope

Scoped-write helpers refuse destinations outside packet-local `ai-council/**` with an `OUT_OF_SCOPE_WRITE` error. The persistence library exposes seven named writer functions, one per artifact type: `writeConfig`, `writeStrategyMd`, `writeStateJsonl`, `writeSeat`, `writeDeliberation`, `writeCritique` and `writeReport`. Each writer resolves its destination under `<packet>/ai-council/` and appends an `artifact_written` audit event with byte count and SHA-256 checksum to the append-only state log.

&nbsp;

#### Existing State Stays Readable

The state log keeps the v1 event types `round_start` / `seat_returned` / `deliberation_synthesized` / `round_end` / `council_complete`. It also adds the v1.2 audit events `artifact_written` / `rollback` / `artifact_superseded` without breaking older readers. The protocol string stays `multi-ai-council` for compatibility with existing state rows produced before the rename. The policy is additive only and never rewrites history.

&nbsp;

#### Failed Rounds Keep Their Record

Failed rounds move into `ai-council/failed/round-NNN-<timestamp>/` with matching `artifact_superseded` markers in the state log. Operators can inspect the failed round folder for forensic context, then dispatch a fresh round. In-place retry is intentionally out of scope so the audit trail stays clean.

## Dispatch

#### Non-Council Callers Keep Working

No new top-level commands ship in this release. The agent is dispatched through normal Task delegation patterns. The `.opencode/skills/deep-loop-workflows/deep-ai-council/scripts/persist-artifacts.cjs` helper is now a thin CLI entry point that delegates to the library for callers that persist a captured council report from outside the agent context, so non-council callers still work unchanged.

---

## Upgrade Notes

No migration is required because the state schema stays additive-only, so existing `ai-council/` artifacts produced before the rename remain readable. Callers that previously dispatched `@multi-ai-council` should switch to `@deep-ai-council`. No shim is provided because no active runtime consumer of the old name was found at rename time. If a downstream consumer still depends on the old name, surface concrete evidence before adding a compatibility shim. The project adds shims only when a real consumer requires one.
