# v1.8.11.0, One Writer and One Round per Call

The `@ai-council` agent file ran past its 600-line cap. It also stated three rules it could not keep. Its persistence, state, convergence and rollback sections now live here. The agent keeps the rules and a pointer.

&nbsp;

## What's New at a Glance

- **One writer per run.** The agent writes a run that dispatches it. The helper writes runs that never dispatch it, such as `/deep:ai-council`. `command-wiring.md` says so.
- **One round per invocation.** The caller owns the round loop. `max_rounds` defaults to 3. Resume reads the round artifacts on disk. `state-format.md` section 6 holds the steps.
- **No projection claim.** The gateway keeps events in the mode ledger. It never refreshes `ai-council-state.jsonl` for this mode.
- **Depth 1 by default.** Seats are dispatched only when the prompt states operator invocation.
- **One threshold table.** `scoring-rubric.md` uses contiguous lead bands. `seat-diversity-patterns.md` drops the temperature column.
- **Rollback recovery steps.** `failure-handling.md` gains the operator steps. The caller moves a failed round, not the agent.

No migration required. Old citations of agent sections 12 to 17 now point at these references.
