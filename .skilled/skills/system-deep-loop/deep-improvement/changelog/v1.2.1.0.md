This patch release corrects `deep-improvement` documentation that described a multi-session lifecycle the runtime never shipped. The correction is documentation-only and brings the written guidance in line with the real runtime.

> Spec folder: `.opencode/specs/skilled-agent-orchestration/042-sk-deep-research-review-improvement-2/` (Level 3)

## What's New at a Glance

- **The documentation now describes a `new`-only lifecycle.** The `deep-improvement` runtime-truth section and `/deep:agent-improvement` command definition no longer list `resume`, `restart`, `fork` or `completed-continue` as supported modes. Each `/deep:agent-improvement` invocation starts a fresh session with generation 1.
- **The v1.1.0.0 changelog points here.** It gained an append-only "Update (post-release)" block that points at this release.

## Upgrade

No migration required. Existing `improve/` session folders continue to read exactly as before. Operators who want to continue an evaluation should archive the prior `improve/` folder under a timestamped path and re-invoke `/deep:agent-improvement`. A future release that ships real multi-session run history will arrive with first-class event emission, reducer ancestry output and replay coverage. Until then, treat every invocation as a standalone evaluation.
