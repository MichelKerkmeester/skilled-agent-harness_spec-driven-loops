v1.1.0.0 delivers the 042 Phase 5 "agent-improver deep-loop alignment" work and the `sk-agent-improver to deep-improvement` rename. Improvement sessions gain canonical stop reasons and an audit journal, along with mutation coverage, trade-off detection, candidate run history and benchmark stability scoring. This aligns the runtime truth model with `sk-deep-research` and `sk-deep-review`.

## Why This Release

The goal is to make the workflow easier to follow and easier to trust.

## What's New at a Glance

- **`deep-improvement` replaces `sk-agent-improver`.** The existing `/deep:agent-improvement` command continues to drive the loop.
- **Improvement sessions now report canonical stop reasons and record audit events.** The proposal-only agent constraint is preserved because the orchestrator emits all new journal entries.
- **Candidate evaluation now tracks mutations, trade-offs, run history and benchmark stability.** Promotion decisions can trace candidate derivation and account for measurement reliability.
- **Scoring weights can be tuned per target profile.** The score dynamic helper accepts a `weights` override without forking the base scorer.
- **Benchmark scanner output now feeds `run-benchmark.cjs`.** The coverage graph can ingest actual run results instead of synthesized metrics.
- **A new `07--runtime-truth/` playbook category covers runtime truth behavior.** Its scenarios add operator guidance alongside the graph-era cases.
- **Four documented lifecycle modes were not wired into the command.** `v1.2.1.0` retracts the continuation promise.

## Skill Identity

#### One Skill Name, One Command

The skill and its sibling `sk-prompt` adopted the verb-first `deep/root` convention used by the other `/deep:*` slash commands. The update covered every playbook scenario and agent mirror, plus each command doc, YAML workflow, asset and reference path. `/deep:agent-improvement` continues to drive the loop, and no operator-facing command changed.

**Breaking:** Legacy `sk-agent-improver` paths are fully removed from live surfaces. Update external references to `deep-improvement`.

## Improvement Sessions

#### Canonical Stop Reasons

The frozen `STOP_REASONS` enum sits alongside `SESSION_OUTCOMES`, and improvement sessions use it to report canonical stop reasons. `SKILL.md` documents the current accepted values, while the helper validator rejects deprecated labels such as `convergedImprovement`, `benchmarkPlateau`, `rejectCandidate` and `rollbackTriggered`.

&nbsp;

#### A Reviewable Audit Trail

`scripts/improvement-journal.cjs` appends validated event types to an append-only JSONL journal. Its event types are `session_start`, `candidate_generated`, `scored`, `gate_evaluation` and `session_end`. A `session_ended` event requires `stopReason` and `sessionOutcome`.

Journal emission is orchestrator-only and never comes from the improver itself, preserving the proposal-only agent constraint (ADR-001). The CLI form is `node .../improvement-journal.cjs --emit <event-json> | --read <session>`. Replay tools and tests can consume the journal directly.

## Candidate Evaluation

#### Mutation Coverage Without Collisions

`scripts/mutation-coverage.cjs` tracks candidate mutations in a coverage graph scoped to sessions with `loop_type: "improvement"`. It shares the SQLite-backed graph store used by the deep-research and deep-review loops without collisions.

&nbsp;

#### Trade-Offs Stay Visible

`scripts/trade-off-detector.cjs` detects dimension trade-offs with Pareto-aware comparison. When a candidate improves one dimension but regresses another, the detector surfaces the trade-off rather than silently accepting the regression.

&nbsp;

#### Candidate History Guides Promotion

`scripts/candidate-run history.cjs` creates a directed run history graph for candidate genealogy. Promotion decisions can trace a proposed candidate through its full derivation history.

&nbsp;

#### Stable Benchmarks Guide Promotion

`scripts/benchmark-stability.cjs` computes the benchmark stability coefficient `1 - (stddev / mean)` across replicate runs. Promotion is gated on measurement reliability.

&nbsp;

#### Scoring Uses Profile Weights

The score dynamic helper accepts a `weights` override to tune five-dimension scoring per target profile without forking the base scorer. `run-benchmark.cjs` maps benchmark scanner output so the coverage graph can ingest actual run results instead of synthesized metrics. The reducer rejection enum adds `reject-candidate`, allowing a failed candidate to be journaled without appearing as an error.

## Operator Guidance

#### Playbook Covers Runtime Truth

Seven scenarios in the new `07--runtime-truth/` category, from `025-stop-reason-taxonomy.md` through `031-parallel-candidates-opt-in.md`, cover stop reasons, audit journal emission, resume continuation, legal-stop gates, benchmark stability, dimension trajectory and opt-in parallel candidates. Three additions in `06--end-to-end-loop/` cover mutation coverage tracking (`022`), trade-off detection (`023`) and candidate run history (`024`).

&nbsp;

#### Session Continuation Was Not Wired

This release documented four lifecycle modes for re-entering a session: `resume`, `restart`, `fork` and `completed-continue`, but none was wired up. `/deep:agent-improvement` has no input for lineage mode, the reducer does not carry ancestry across sessions and the journal helper has no multi-session boundary event, so every invocation is a fresh `new` session.

Release `v1.2.1.0` retracts that promise, and `v1.2.1.0.md` tells the full story.

## Upgrade Notes

- Existing improvement sessions without the new runtime-truth fields continue to run unchanged.
- Invoking `/deep:agent-improvement` provides a reviewable audit journal, mutation coverage graph, trade-off detection and stability-aware promotion gates, all enforced orchestrator-side to preserve the proposal-only agent constraint.
- To continue evaluating an agent across sessions, archive the prior `improve/` folder under a timestamped path and re-invoke the command.
