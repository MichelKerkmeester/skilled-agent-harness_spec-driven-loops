## Why This Release

The release targets reducer schema mismatches, dead helper code, journal taxonomy gaps and workflow enforcement to make the workflow easier to trust in everyday use.

## What's New at a Glance

- **Run history fields now align.** The reducer can read the producer's run-history artifacts.
- **Coverage can be derived from raw arrays.** The reducer can report coverage when computed metrics are absent.
- **Replay data now appears in the dashboard.** Journal summary, candidate run history and mutation coverage each have dedicated sections.
- **Legal-stop events now come from both workflows.** Auto and confirm workflows emit structured events with gate bundles.
- **Journal rows now carry scored dimensions.** This supports trajectory extraction from `candidate_scored` payloads.
- **Plateau exits have a distinct stop reason.** `plateau` replaces the former `converged` label for these exits.
- **Phase 005 helpers now run in auto and confirm workflows.** All four are called at appropriate points.

## Reducer and Workflow Reliability

#### One Shape for Run History

The reducer silently failed to read run-history files. `candidate-run history.cjs` wrote `candidateId`/`parentCandidateId` while the reducer expected `id`/`parentId`.

&nbsp;

#### Coverage From Raw Results

The reducer expected a `metrics` block that `mutation-coverage.cjs` never wrote. When the computed metrics block is missing, the reducer derives the coverage ratio and uncovered counts from the raw arrays.

&nbsp;

#### Replay Results Reach the Dashboard

The reducer read replay artifacts into the registry but dropped them from the dashboard, leaving operators without visibility. Dedicated sections now show journal summary, candidate run history and mutation coverage.

&nbsp;

#### Legal Stops Are Recorded

The deep-improvement loop did not emit `legal_stop_evaluated` or `blocked_stop` events that other reducers depend on. The auto and confirm workflow YAMLs now emit structured legal-stop events with gate bundles.

&nbsp;

#### Journal Trajectories Match

Journal-based trajectory extraction did not fit the emitted `candidate_scored` payloads because journal rows lacked the scored-dimension array. `trade-off-detector.cjs` now emits that array into the journal row.

&nbsp;

#### Plateau Has Its Own Label

The stop-reason taxonomy could not represent plateau exits, so they were labeled `converged`. `plateau` was added to the `STOP_REASONS` enum in `improvement-journal.cjs`.

&nbsp;

#### Helpers Join the Workflow

The four helpers had no calls from the auto or confirm workflow steps: `mutation-coverage.cjs`, `candidate-run history.cjs`, `trade-off-detector.cjs` and `benchmark-stability.cjs`. Explicit loop steps now call them at appropriate workflow points.

&nbsp;

#### Scans Target the Right Agent

`scan-integration.cjs` received the profile label instead of the real target agent identifier, so it scanned the wrong file. Both workflow YAMLs now pass the real target agent identifier.

&nbsp;

#### Confirm Mode Enforces the Gate

The confirm-mode session-boundary gate was advisory and had no `verify`/`on_fail` enforcement. Confirm mode now mirrors the auto workflow's structured halt pattern.

&nbsp;

`034-replay-consumer.md` now describes journal, run history and coverage as registry-only outputs. It no longer describes them as dashboard sections, which did not exist yet. This release adds those dashboard sections.
