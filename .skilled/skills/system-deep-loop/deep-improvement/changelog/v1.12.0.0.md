This release adds the capability-discrimination layer to the model-benchmark framework.

> Spec folder: `.opencode/specs/skilled-agent-orchestration/127-reusable-model-benchmark-framework` (Level 2)

## Why This Release

Everything is additive over the existing Lane B grader and the config-driven sweep.

## What's New at a Glance

- **Three fixture packs cover harder computation and strict validation.** The additions include partial-credit cases for model comparison.
- **Each fixture pack has its own capability profile.** All three profiles use the same correctness gate and group results by model.
- **Dispatch runs use temporary directories.** Agentic model writes stay outside the repository.
- **MiniMax-M3 is the more reliable model.** Two independent runs with disjoint fixtures produced the verdict.
- **The benchmark adds tiered-taxonomy seeds.** One seed is T1 and the other is T4.
- **A strict-validation comparison separates the models.** Raw computational difficulty alone did not separate them.
- **The trustworthiness reporter has a known follow-up.** Its `TIE-on-format` label can mislead when the correctness gate separates the pair.

## Fixture Packs

#### Hard Cases Earn Partial Credit

The hard T4 pack contains these fixtures:

- `hard-merge-intervals`
- `hard-parse-csv-line`
- `hard-roman-to-int`
- `hard-eval-expr`

Their partial-credit oracles have 16–18 cases each. Reference implementations scored 1.0 while wrong implementations scored 0.33–0.625.

&nbsp;

#### Harder Cases Reach Saturation

The harder T4 pack contains these fixtures:

- `harder-semver-compare`
- `harder-normalize-path`
- `harder-int-to-words`

Each has 24 cases. The `005-sharper-discrimination` result was negative: the fixtures saturated frontier models, so raw difficulty alone did not separate MiniMax-M3 and MiMo-V2.5-Pro.

&nbsp;

#### Strict Validation Separates Models

The validation T4 pack contains these invalid-dominant strict validators:

- `validate-ipv4`
- `validate-date`
- `validate-semver`

They have 26–28 cases, with 64–74% adversarial-invalid inputs. Reference implementations scored 1.0 while lax implementations scored 0.75–0.889. Strict input validation, rather than computation, is where the two models diverge. These fixtures belong to `006-strict-validation-fixtures`.

&nbsp;

#### Seeds Extend the Tiered Taxonomy

Two tiered-taxonomy seeds were added:

- `t1-smoke-echo` (T1)
- `t4-adversarial-tokenizer` (T4)

## Model Comparison

#### Profiles Set Comparison Rules

The profiles are:

- **Hard pack:** `capability-m3-vs-mimo.json` (n=3)
- **Harder pack:** `capability-m3-vs-mimo-v2.json` (n=5)
- **Validation pack:** `capability-m3-vs-mimo-v3.json` (n=5)

All three use `mode: model-vs-model`. Each sets `correctnessGate.threshold: 1.0` and `reporting.groupBy: model`.

&nbsp;

#### Disjoint Runs Support the Verdict

This is the first reproducible MiniMax-M3 vs MiMo-V2.5-Pro capability verdict. Across two independent runs with disjoint fixtures, MiniMax-M3 was perfect and correctness-gate-eligible in 32 of 32 cells. On `004-capability-discrimination` computational+roman fixtures it scored 1.0 against MiMo-V2.5-Pro's 0.898. On `006-strict-validation-fixtures` validation+roman fixtures it scored 1.0 against 0.891. MiMo-V2.5-Pro had an approximately one-in-five catastrophic-failure rate on hard validation plus a mild roman-numeral gap, keeping it below the correctness gate in every run. Reproducibility across disjoint fixtures certifies a verdict when the paired-bootstrap CI defaults to a format-TIE under correctness saturation. Per-phase verdicts live in each phase's `eval/synthesis.md`.

&nbsp;

#### Sample Size Changes the Read

The baked-in methodology de-risks at n=2 for saturation and ranks at n≥5. The n=2 de-risk briefly flipped the read after it surfaced a rare MiniMax-M3 truncation. The n=5 run corrected it. Per-model ranking needs at least five samples because catastrophic failures occur about one time in five.

&nbsp;

#### Correct the Saturation Label

**Known follow-up (P2).** The trustworthiness reporter prints `TIE-on-format` whenever correctness saturates. That label is misleading when the correctness gate separates the pair, with one model eligible and the other not. The recommended correction is to report the sole gate-eligible model as the correctness winner.

## Dispatch Isolation

#### Model Writes Stay Outside the Repo

`sweep-benchmark.cjs` sets each dispatch's `cwd` and `--dir` to a per-cell directory under `os.tmpdir()`. The directory is removed in a `try/finally`, so agentic model file writes land in the throwaway directory instead of the repo.
