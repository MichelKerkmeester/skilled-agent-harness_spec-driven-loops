Phase 008 of the 042 Deep Research & Review Runtime Improvement Bundle aims to make the `deep-improvement` skill's `/deep:agent-improvement` workflow easier to follow and trust. It wires the visible auto and confirm workflows to the journal, sets minimum sample sizes for trade-off and stability reports and surfaces replay evidence in refreshed state and the dashboard.

## What's New at a Glance

- **The workflow records journal events at three boundary points.** `/deep:agent-improvement` calls `improvement-journal.cjs` at session start, at every iteration boundary from candidate generation through scoring and gate evaluation and at session end. The orchestrator-only constraint is preserved. The proposal-only agent still never writes journal rows itself.
- **Trade-off and stability verdicts require three samples by default.** `trade-off-detector.cjs` returns `{state: "insufficientData", dataPoints: n, minRequired: 3}` below its threshold instead of fabricating confidence from 2 points, while `benchmark-stability.cjs` returns `{state: "insufficientSample", replayCount: n, minRequired: 3}` and treats that state as not stable. The tools export `MIN_DATA_POINTS_DEFAULT = 3` and `MIN_REPLAY_COUNT_DEFAULT = 3`.
- **Reducer refresh exposes journal, lineage and coverage summaries.** ADR-002 Option A is accepted: replay consumers are implemented rather than downgrading the docs to ledger-only reality. `improvement-journal.jsonl` supplies top-level `journalSummary` fields `lastSessionStart` plus `lastSessionEnd` plus `totalEvents` and `eventTypeCounts` and terminal `stopReason` and `sessionOutcome` from the latest `session_end` event. `candidate-run history.json` supplies `candidateLineage` fields `run historyDepth` (max depth from root) plus `totalCandidates` and `currentLeaf` while `mutation-coverage.json` supplies `mutationCoverage` fields `coverageRatio` and `uncoveredMutations`.
- **The reducer dashboard gains a new Sample Quality section.** The reducer also surfaces `insufficientDataIterations` and `insufficientSampleIterations` as new registry fields propagated from the Part A sample-size gates, while the section shows `replayCount` and `stabilityCoefficient` plus those two counts as distinct fields from generic benchmark failure counters. When either insufficient count is above zero, the section includes an explicit operator guidance note.
- **The journal example and wiring contract match the helper.** The CLI example in the `agent-improvement` command doc now uses `--emit session_start --payload '<json>'` instead of the malformed `--event=session_initialized`, matching the helper's interface. `SKILL.md` adds a Journal Wiring Contract that documents the three boundaries along with the frozen `STOP_REASONS` enum (`converged` / `maxIterationsReached` / `blockedStop` / `manualStop` / `error` / `stuckRecovery`) and frozen `SESSION_OUTCOMES` enum (`keptBaseline` / `promoted` / `rolledBack` / `advisoryOnly`) aligned with the helper's actual validator, plus the orchestrator-only emission rule.

## Upgrade

No migration required. This release is backward-compatible: sessions without `improvement-journal.jsonl` or `candidate-run history.json` or `mutation-coverage.json` still work without an error. Each absent artifact's consumer field defaults to `null`. On new sessions, the thresholds default to three data points and three replays. Constructor options or environment variables can override `minDataPoints` and `minReplayCount` for legacy replay flows. The visible workflow emits the journal events promised in v1.1.0.0, closing the contract break surfaced in Phase 008 Part A.
