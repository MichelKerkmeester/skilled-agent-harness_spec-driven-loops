# v1.9.0.0, Two Lanes for Deep Improvement

v1.9.0.0 gives deep-improvement a first-class model-benchmark mode and, on top of it, makes deep-improvement a genuine two-lane skill. The lanes now sit side by side across the command, documentation, agent guidance and on-disk layout.

Two independent deep-review and remediation cycles, one with gpt-5.5 and one with Opus 4.8, hardened the capability before Lane B shipped.

> Spec folder: `.opencode/specs/skilled-agent-orchestration/121-deep-improvement-benchmark-mode`

## Why This Release

This release covers the whole 121 program. Arc 1 designed, researched, built and hardened the model-benchmark mode in phases 001 to 007, and Arc 2 elevated it from a Mode 4 bolt-on to a lane co-equal with agent improvement in phases 008 to 018, consolidated by the 019 doc closeout. Arc 1's tri-model hardening review first ran as separate packet 122 and was folded into 121 as phase 007, which is why remediation phase 004 carries a lower number than the review it remediates.

## What's New at a Glance

- **Deep-improvement supports two co-equal lanes.** Lane A improves agent files while Lane B benchmarks models or prompt frameworks.
- **The command can resolve both lanes.** Agent paths follow Lane A and benchmark requests can reach Lane B.
- **Benchmark runs can choose a scorer and grader.** The `pattern` scorer is the default. The `5dim` scorer and the `noop`, `mock` and `llm` graders are also available.
- **Lane-specific structure covers references, assets and scripts.** The folders now map to `agent-improvement`, `model-benchmark` and `shared`.
- **Acceptance and bundle criteria have execution gates.** Acceptance criteria use a default-on gate with a documented opt-out.
- **Model scores are bounded.** The D4 grader clamps them to `[0,1]`.
- **The dashboard presents the lane mix.** It provides global and per-profile summaries.

## Lane Routing and Scoring

#### Each Lane Has an Entry

`/deep:agent-improvement` now resolves a use-case lane. An agent path auto-resolves to Lane A and runs exactly as before under the CMD-1 behavioral identity, so existing invocations are untouched. Use `--lane=model-benchmark` or a `--profile` argument to select Lane B. The lane question appears only when the choice is ambiguous.

`/deep:model-benchmark` is a dedicated Lane B command. Its two workflow YAMLs, `deep_model-benchmark_{auto,confirm}.yaml`, run `loop-host.cjs --mode=model-benchmark`, reduce, journal and offer mode-aware promotion. The advisor's `deep-model-benchmark` alias and bounded command-level disambiguation route benchmark phrasing to it.

&nbsp;

#### One Loop Runs Both Lanes

Phase 001 designed the mode selector and three pluggable seams before any code was written, producing ADRs and a build plan. Phase 002 deep-researched the build with MiniMax M2.7 to converge a verified, build-ready delta through seam contracts and a build-delta over 5 evidence iterations. `loop-host.cjs` gained a mode-switch entry point that dispatches between the existing, untouched `agent-improvement` path and `--mode=model-benchmark`, so the same loop shape drives either an agent definition or a model or prompt benchmark. The TST-1 byte-identity gate holds the agent-improvement branch byte-identical through every build and reorg, so the existing lane provably never regresses. The new generic dispatcher `dispatch-model.cjs` is the Lane B equivalent of dispatching a Claude agent, running arbitrary models against fixtures under prompt-framework variants across the five executors. Its path joins were re-depthed, and its config load is positively asserted to resolve to a real file, closing a silent-fallback risk. Loop state now carries a `mode` field, so a benchmark run reaches `benchmark-complete` and the journal and registry can tell it apart from agent-improvement runs.

&nbsp;

#### Scoring and Grading Choices

The decoupled 120/003 scorer was ported into `scripts/model-benchmark/scorer/`, with deterministic checks under `scorer/deterministic/`, the LLM grader in `scorer/grader/` and `score-model-variant.cjs`, making benchmark scoring a first-class part of the skill rather than a packet-local one-off. `run-benchmark.cjs` gained `--scorer pattern|5dim` and `--grader noop|mock|llm`. The default stays `pattern`, and its path stays byte-identical. The `5dim` scorer loads only when selected, and the scorer choice is recorded as `scoringMethod` in the report and state log. This closed the hardening-review deferral, F-P2-1 and F-P2-2, that had flagged the ported 5-dim rubric as built but unwired. Regression tests cover both scorer paths and the fallback for an unknown scorer.

`SKILL.md` documented the model-benchmark mode for the first time, with a WHEN TO USE case and the scorer options, and its DQI moved from 94 to 97, in the excellent band.

`loop-host.cjs` never forwarded `--scorer` and `--grader` to `run-benchmark.cjs`, so selecting `5dim` or a `mock` or `llm` grader through any command path silently fell back to `pattern` and `noop` while the report disagreed with the journal. Both flags are now forwarded in the model-benchmark branch only. This fix leaves the agent-improvement branch byte-identical, so TST-1 stays green.

## Deep Loop Runtime

#### Archives Start Only When Needed

Deep-loop init no longer creates empty `{mode}_archive` directories. All four restart branches now archive lazily behind guards, and pre-existing empty archive directories were swept.

&nbsp;

#### The Remediation Closes Advisories

Arc 1's independent tri-model hardening review, with gpt-5.5 and MiniMax M2.7 and Opus 4.8 as arbiter, audited the build for correctness, security, traceability and maintainability and returned a CONDITIONAL verdict. Phase 004 remediated the 3 unique confirmed P1 defects, each with a regression test. The phase 004 remediation closed the actionable P2 advisories: Atomics-based backoff replaced the busy-wait, `dispute.cjs` gained dependency-injected `fs` in place of a global monkey-patch, the grader cache gained a raw-input gate, a deterministic-scoring regression test and delta-units documentation were added, and the REQ-004 `--cwd` wording was reconciled. Two non-defects, an intended deferral and a dedup artifact, were recorded as no-change with rationale.

Phase 015 closed all 1 P0, 16 P1 and 16 P2 findings before Lane B shipped. Phase 018 closed all 4 P1 and 13 P2 Opus findings with one disposition each.

## Benchmark Safeguards

#### Criteria Execution Has Separate Gates

Acceptance criteria ran shell commands without a gate. They now run behind a `criteria-exec` gate that defaults ON and has a documented opt-out. The bundle gate also has its own `criteria-exec` gate.

&nbsp;

#### Path Checks Respect Boundaries

Sibling-prefix paths were misclassified by the D3 path guard. The guard now bounds the path prefix with a separator.

&nbsp;

#### Working Directory Reaches Every Executor

The dispatcher dropped the requested `--cwd` working directory for four of five executors. `--cwd` now propagates to `spawnSync` for all five.

&nbsp;

#### Grader Scores Are Bounded

The D4 grader accepted unbounded model scores. It now clamps scores to `[0,1]`.

## Lane Guidance and Organization

#### Guidance Presents Both Lanes

`SKILL.md` now presents Lane A and Lane B as parallel sections instead of modes 1 to 3 plus a trailing Mode 4, and adds a two-lane WHEN TO USE table. Its smart router gained a `MODEL_BENCHMARK` intent at weight 5 and a matching `RESOURCE_MAP` entry. Dead Mode-4 anchors were removed.

DQI stayed in the excellent band at 97.

The `@deep-improvement` awareness note changed from "Mode awareness" to "Lane awareness" across all 4 runtime mirrors, byte-identical with zero mirror drift. It identifies one agent, with Lane B dispatching models through `dispatch-model.cjs`, never a second Claude agent. The feature catalog and manual testing playbook label each entry by lane.

&nbsp;

#### References, Assets and Scripts Follow Lanes

The `references/` and `assets/` trees now group content under `agent-improvement/`, `model-benchmark/` and `shared/`, replacing the v1.8.0.0 function groups `scoring`, `promotion-gates`, `integration` and `workflow`, which were an intermediate step. Every literal was repointed, including `SKILL.md`'s `RESOURCE_MAP`, `DEFAULT_RESOURCE` and `RUNTIME_ASSETS`, both lanes of command YAMLs, both command docs, the README, graph metadata, scripts, the feature catalog and playbook, and the benchmark profile's internal `fixtureDir`. The 16 scripts moved into `scripts/{agent-improvement,model-benchmark,shared}/`. `loop-host.planInvocation()` was kept byte-identical, and a new `resolveScriptPath()` helper resolves lane paths at spawn time, so TST-1 holds. All references were rewritten, including the Vitest path literals. `scorer/` sits under `model-benchmark/`, while `lib/` and `tests/` stay at the scripts root.

The README structure table was refreshed for the new scripts and `scorer/` subtree. Every source script subfolder gained a local code-folder README from the sk-doc code template, and the existing READMEs were audited.

**Breaking:** External callers that hardcode `scripts/<name>.cjs` must update to `scripts/<lane>/<name>.cjs`.

&nbsp;

#### Dashboard Shows Lane Mix

The registry stores per-profile and global modes, and the dashboard shows the Lane (mode) mix in its global summary and each profile. `reduce-state.cjs` now surfaces the `mode` metadata it already recorded, closing F-P2-5. A missing mode counts as `agent-improvement`, so legacy ledgers still total. This is display only. Routing is untouched.

&nbsp;

#### Benchmark Promotion Has a Path

Lane B benchmark-mode promotion has an executable path that matches its documentation. The materializer now has a fixture-id guard.

## Upgrade Notes

- For model or prompt-framework benchmarking, use `/deep:model-benchmark` or add `--lane=model-benchmark` to `/deep:agent-improvement`.
- Use `--scorer=5dim` to opt into the 5-dim rubric.
- Existing `/deep:agent-improvement` calls with an agent path need no migration.
