The initial release of `deep-improvement` gives bounded agent improvement an evaluator-first workflow. It evaluates each agent across the system surfaces it touches, not only keyword presence in its markdown file, with dynamic profiles, deterministic benchmarks and guarded promotion. The skill was developed across eight phases.

> Spec folder: `.opencode/specs/skilled-agent-orchestration/041-sk-recursive-agent-loop` (Level 2)

## Why This Release

The workflow aims for an agent-improvement process that is easier to follow and easier to trust.

---

## What's New at a Glance

- **Promotion requires evidence gates and explicit operator approval.** Candidate work is evaluated before canonical changes.
- **`handover` and `context-prime` have different promotion eligibility.** The first is promotion-eligible and the second is candidate-only.
- **`run-benchmark.cjs` scores fixture outputs.** It scores them against required headings, required patterns and forbidden patterns.
- **The `scan-integration.cjs` scanner examines an agent's connected surfaces.** It detects mirror sync by matching signal strings against the main body.
- **`generate-profile.cjs` supports evaluation of any agent under `.opencode/agents/`.** Each generated profile follows that agent's own structure.
- **`--dynamic` activates integration-aware scoring.** Legacy `--profile` mode remains available with fixed keyword checks and backward compatibility.
- **`reduce-state.cjs` tracks scores by dimension across iterations.** A plateau across every dimension can trigger an automatic stop.
- **Runtime parity covers all 4 runtimes.** The `@agent-improver` agent and `/deep:agent-improvement` command are mirrored across OpenCode, Claude, Codex and `.agents`.
- **A 21-scenario manual testing playbook accompanies the skill.** Its categories span the evaluation workflow from integration scanning through the end-to-end loop.

## Evaluator-First Architecture (Phase 001-002)

#### Proposal-Only Workflow

Candidates are written to packet-local runtime areas rather than editing main agent files directly. A deterministic evaluator scores each candidate independently, target-specific fixture sets benchmark it and an append-only JSONL ledger tracks it.

&nbsp;

#### Two Target Profiles

The profiles are static. Each defines its own scoring rubric, fixture directory, aggregate score threshold and repeatability tolerance.

&nbsp;

#### Promotion and Rollback

Canonical mutation requires a `candidate-better` score, a passing benchmark report, repeatability evidence, manifest boundary compliance and explicit approval. Rollback restores the archived pre-promotion backup and records a post-rollback comparison for audit continuity.

## 5-Dimension Evaluation (Phase 008)

#### Integration Surface Scanning

The `scan-integration.cjs` script discovers an agent's main definition and three runtime mirrors in Claude, Codex and `.agents`. It also finds command dispatch references, YAML workflow references, skill mentions, global documentation references and Skill Advisor routing entries.

&nbsp;

#### Profiles from Agent Structure

The `generate-profile.cjs` script parses YAML frontmatter, `ALWAYS`/`NEVER`/`ESCALATE IF` rules, the output verification checklist, capability scan, anti-patterns and related resources. This removes the need for manually created profiles.

&nbsp;

#### Five Weighted Dimensions

The refactored `score-candidate.cjs` applies weighted scoring through `--dynamic`. Five dimensions measure different parts of agent quality:

| Dimension | Weight | What It Measures |
| --- | --- | --- |
| Structural Integrity | 0.20 | Agent template compliance and required sections |
| Rule Coherence | 0.25 | Alignment between ALWAYS/NEVER rules and workflow steps |
| Integration Consistency | 0.25 | Mirror sync, command coverage and skill references |
| Output Quality | 0.15 | Output verification items and absence of placeholders |
| System Fitness | 0.15 | Permission-capability alignment and valid resource references |

&nbsp;

#### Dimensional Progress Tracking

Per-dimension scores are tracked across iterations and shown in a Dimensional Progress table in the dashboard. When all dimensions have three or more identical scores, the refactored `reduce-state.cjs` triggers an automatic stop.

## Documentation and Packaging (Phases 003-007)

#### Consistent Skill Packaging

All skill documentation surfaces follow sk-doc template standards: `SKILL.md`, `README.md`, 11 references, 4 markdown assets, the command and the agent. They use retrieval anchors, frontmatter, section dividers and HVR-compliant language.

&nbsp;

#### Manual Testing Playbook

The playbook covers six categories: integration scanner, profile generator, 5D scorer, benchmark integration, reducer dimensions and the end-to-end loop. Each of the 21 scenarios has copy-pasteable commands and verification one-liners.

## Skill Rename (Phase 008)

#### Coordinated Renaming

`sk-recursive-agent` was renamed to `deep-improvement` across 187+ files and 1129+ occurrences. The command moved from `/speckit:recursive-agent` to `/deep:agent-improvement`, and the agent was renamed from `@recursive-agent` to `@agent-improver`.
