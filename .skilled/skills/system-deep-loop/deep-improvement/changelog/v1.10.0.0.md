v1.10.0.0 makes `deep-improvement` a three-lane skill and brings Lane C to release status by completing its live half. It adds the prerequisite that makes a real skill benchmarkable and a Mode B that benchmarks a skill against its own `manual_testing_playbook`. The script test suites now sit beside the lanes they cover.

> Spec folder: `.opencode/specs/skilled-agent-orchestration/122-deep-improvement-skill-benchmark-mode`

## Why This Release

Lane C already had Mode A, a deterministic router-replay benchmark built under packet 122. Mode B runs a skill's own playbook live through `cli-opencode`, the way the skill is actually used, not as a synthetic replay. This release ships phases `009-sk-code-router-benchmarkability` and `010-skill-benchmark-live-playbook-mode`, first authored as standalone packets 126/127 and then consolidated into the 122 program as phases 009/010. Phase 010 realizes the Mode B that `122/002-implementation-deep-research` scoped as a deferred follow-on.

## What's New at a Glance

- **Lane C adds router-benchmarkability and live Mode B.** `sk-code` can be measured through its referenced router, while a skill can be benchmarked through its own playbook.
- **Router replay handles always-loaded resources.** A skill's routing preamble can count as covered even when it is not mapped to an intent.
- **One playbook corpus feeds router and live runs.** Gold is captured as authored, which surfaces router-to-gold drift.
- **Browser runs report honest outcomes.** Browser-gated scenarios return PASS, `PARTIAL-NEEDS-ARTIFACT` or `SKIP-NO-BROWSER`, never a fabricated PASS.
- **Test suites move beside their lanes.** External callers that hardcode the former test paths need to update them.
- **Live runs check the observed surface.** A disagreement with the expected surface now fails routing.

## Skill Benchmarking

#### Referenced Routers Become Measurable

Lane C's Mode A needs an `INTENT_SIGNALS` and `RESOURCE_MAP` router to replay. `sk-code` keeps its router in a referenced doc, `references/smart-routing.md`, rather than inline in `SKILL.md`, so the benchmark could not read it. A machine-readable router block was added to `smart_routing.md` with `DEFAULT_RESOURCE`, 14 intents and a `RESOURCE_MAP` covering every routable content file. A drift-guard regression test fails if any mapped path goes missing on disk or any routable doc stops being covered. The replay parser now resolves the referenced router document when the dictionaries are absent from `SKILL.md`, and stamps the `routerSource`. `d5-connectivity.cjs` and `contamination-lint.cjs` also thread `skillRoot` through so reference-following resolves correctly.

&nbsp;

#### Always-Loaded Docs Count

`DEFAULT_RESOURCE` is now a list. The replay parser, route builder and D5 connectivity coverage check accept a list of always-loaded resources, and the string form is still supported. A skill's routing preamble, the docs consulted on every route rather than mapped to one intent, now counts as covered instead of orphaned.

&nbsp;

#### Router Signals Match Real Work

The `sk-code` router was tuned from its own benchmark. Because `sk-code` always detects stack, detects phase and consults the router before code work, those three docs moved into `DEFAULT_RESOURCE`. That cleared three orphan references and lifted D5 to 100. Language-standards and config intents gained file-extension signals such as `.ts`, `.py`, `.sh` and `.json`, which match how `sk-code` routes by target path and were not copied from benchmark scenario text. Router-mode aggregate rose 31 to 40, D2 rose 29 to 44 and routed-intra failures fell 12 to 5. The residual router-replay failures are the documented surface-flattening replay artifacts that live mode resolves.

&nbsp;

#### The Playbook Drives Both Modes

The `manual_testing_playbook` is parsed into normalized gold scenarios tagged `routing`, `advisor` and `browser`. The `sk-code` playbook has 24 scenarios. The same scenarios run in `router` mode as the deterministic CI gate, with real-gold D1-intra, D2 and D3 instead of empty-gold placeholders. The operator default is `live` mode and uses the same scenario set. `score-skill-benchmark.cjs` accepts the legacy fixture shape and adds A-to-B divergence, while `build-report.cjs` adds coverage, per-classKind, routed-out, divergence and contamination sections.

&nbsp;

#### Live and Browser Runs

`live-executor.cjs` dispatches each scenario as a routing-analysis prompt through `cli-opencode` and parses the real NDJSON event schema. It captures activation, observed reads and the model's stated routing JSON across fenced, bare and prose response shapes, with parsing that works across models. `browser-executor.cjs` runs browser-gated MR/CB scenarios through `bdg`, which is Chrome-only. It reports a real PASS where a scenario is automatable and `PARTIAL-NEEDS-ARTIFACT` or `SKIP-NO-BROWSER` otherwise, never a fabricated PASS.

&nbsp;

#### Optional Playbook Tools

The D4 usefulness ablation, `d4-ablation.cjs`, grades skill-on against skill-off runs with the existing `gradeD4` grader. Skill-off sets `SYSTEM_SKILL_ADVISOR_HOOK_DISABLED=1` and adds a "don't read the skill" preamble, verified by `observedReads==0`, and attribution is stamped `approximate` by design. The opt-in `playbook-generator.cjs` can author scenarios for a skill without a playbook. It writes only to `_generated_staging/` and never to the live playbook. Its four validation gates are contamination, parser round-trip, structural and self-consistency.

&nbsp;

#### Live Run Controls

`loop-host.cjs` gained `--scenarios`, `--executor` and `--playbook-dir`. The internal default stays `router` for deterministic direct runs. `--playbook-dir` now reaches the parser instead of being dropped by the orchestrator. The usage text describes the flag.

## Test Organization

#### Suites Follow Their Lanes

Vitest suites moved from the flat `scripts/tests/` directory to `agent-improvement/tests/`, `model-benchmark/tests/`, `skill-benchmark/tests/` and `shared/tests/`. The suite index moved to `shared/tests/`, while cross-lane fixtures moved to `scripts/shared/tests/fixtures/`. `vitest.config.mjs` now includes `*/tests/**/*.vitest.ts`. **Breaking:** External callers hardcoding `scripts/tests/<name>.vitest.ts` should update to `scripts/<lane>/tests/<name>.vitest.ts`. References were repointed in `scripts/README.md`, the relocated suite/fixtures READMEs, the feature catalog, the manual testing playbook anchors, `/deep:skill-benchmark` and the `deep-improvement` agent Lane C note. Historical changelogs and deep-research/review iteration logs were left as point-in-time records.

## Benchmark Reliability

#### Path Checks Respect Boundaries

The D5 skill-root containment check used a bare `startsWith`, which could let a sibling such as `<root>-evil/…` pass as inside the root. It now requires a path-separator boundary.

&nbsp;

#### Scenario IDs Describe Behavior

Scenario IDs were lifted out of code comments into behavioral descriptions. They were kept only in executable branch and data values, where they are the runtime contract.

&nbsp;

#### Surface Mismatches Fail Routing

A live result whose observed surface disagrees with the scenario's expected surface now caps D1-intra below the pass line and reports a `surface-mismatch` funnel stage instead of passing on incidental resource overlap. Router mode has no observed surface and is unaffected.

## Upgrade Notes

- **No migration for existing callers.** `--trace-mode` defaults to `router` for direct and CI runs, so the deterministic gate is unchanged.
- **Opt into live benchmarking.** Pass `--trace-mode live` and set `SKILL_BENCH_OPENCODE_MODEL` and `SKILL_BENCH_OPENCODE_VARIANT`. Use `gpt-5.5-fast --variant high`, because `xhigh` timed out at more than 4 minutes per dispatch.
