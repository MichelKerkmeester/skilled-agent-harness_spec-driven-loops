This release makes D4-R task-outcome grading follow the requested dimension and allows longer answers through its higher pre-grading limit. It also hardens routing, configuration handling and the supporting benchmark documentation.

> Spec folder: `.opencode/specs/skilled-agent-orchestration/122-deep-improvement-skill-benchmark-mode/014-d4r-grader-fidelity-remediation` (Level 2)

## Why This Release

An independent MiMo-v2.5-pro deep review of the v1.11.0.0 `skill:deep-improvement` skill-benchmark work surfaced 28 issues: 8 should-fix and 20 advisory, with no blockers. The review of record is sibling phase `013-skill-benchmark-fidelity-track/review/review-report.md`. This release resolves all 28 with none deferred.

## What's New at a Glance

- **The grader derives its user-prompt tail from the requested dimension.** The D4-R task-outcome system prompt no longer conflicts with the prompt tail.
- **Longer D4-R task-outcome answers reach grading.** Thorough skill-on patch plans are no longer clipped before scoring.
- **Resume hints quote the sentinel and loop-host paths.** An existing config file with malformed JSON now triggers a warning.
- **Profile-command execution has an explicit gate.** The trusted-profile default is preserved, with `DEEP_AGENT_ALLOW_CRITERIA_EXEC=0` documented as an opt-out.
- **The benchmark docs now name `SKILL_BENCHMARK runtime_assets` as a router branch.** The same `SKILL.md` update adds six previously missing scripts in §11.

## D4-R Grading

#### Dimension-Aware Fallbacks

`composeGraderPrompt`, `parseGraderResponse`, the mock dispatcher, the cache key and cache metadata now thread `dimId`, which defaults to `'D4'` so existing callers are unchanged. `normalizeParsedPayload` backs strict, fenced, regex and score-only parse paths, stamping the expected dimension when one is missing and normalizing a mismatched `dim_id` to the requested dimension with capped confidence and an annotated rationale. Fallback parsing no longer mislabels or accepts malformed payloads. This grader fallback path is the most consequential change: a D4-R result routed through a parser fallback can no longer be silently stamped `D4` or accepted with a missing `dim_id`.

Those mismatches receive new `*_dim_mismatch` parse statuses. The score-only last resort uses the threaded `dimId` instead of hardcoding `'D4'`. `dispatchReal` sends the rubric through `--append-system-prompt` and the candidate output through `-p` instead of concatenating both into one `-p` argument.

&nbsp;

#### Full Answers Reach Grading

The pre-grading limit in `live-executor.parseLiveResult` changed from 2000 to `GRADED_RESPONSE_MAX_CHARS = 8000`. A thorough skill-on patch plan is no longer clipped and under-scored before grading.

## Routing and Safeguards

#### Nested Routing Payloads

`extractRoutingJson` now uses the string-aware, brace-balanced `collectBraceBalancedObjects` scanner, which handles nested-brace routing payloads rejected by the old bare-object regex. `runDispatch` also backfills a missing model to `DEFAULT_MODEL`.

&nbsp;

#### Quoted Resume Hints

`dispatch-model.buildResumeHint` uses the `shellQuote` helper to POSIX-shell-quote the sentinel and loop-host paths. This removes the shell-injection surface in the resume hint.

&nbsp;

#### Visible Configuration Errors

`loadConfig` stays silent when the optional file is missing with `ENOENT`. When an existing file contains malformed JSON, it warns instead of silently returning `{}`.

&nbsp;

#### Explicit Criteria Gate

`score-model-variant` routes profile-command execution through `criteriaExecAllowed`. The gate warns when it is not explicitly set, preserves the trusted-profile default and documents `DEEP_AGENT_ALLOW_CRITERIA_EXEC=0` as the opt-out.

## Scoring and Documentation

#### Score Results Stay Unchanged

`scoreScenario` was decomposed into helpers with byte-identical formulas. The D1-intra weights and surface-mismatch cap are now named constants. Mode-A scoring reads `WEIGHTS`. Negative-scenario `wastedCount` semantics were clarified and there were no score changes. Duplicated grader-base construction in `d4-ablation` and event-stream parsing in `sweep-benchmark` were de-duplicated into shared helpers.

&nbsp;

#### Benchmark Guidance Matches

`README.md` reconciles the references count from 14 to 17, the scripts table, the structure block and the trigger phrases from 6 to 9.

`scoring_contract.md` completes the funnel stages and documents `advisorySignals`. The v1.11.0.0 changelog ties the D4-R scenarios to the `DEFAULT_D4R_SCENARIOS` constant.

## Upgrade Notes

No upgrade needed. All changes are behavior-preserving. Weighted dimensions, the `skill-benchmark-report.v1` report schema and the deterministic CI/router path are unchanged. The `sk-code` router drift guard is unchanged. New grader `parse_status` values (`*_dim_mismatch`) appear only when a grader returns a dimension id different from the one requested.
