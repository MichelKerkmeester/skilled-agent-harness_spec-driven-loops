The deep-improvement portion of the packets 108 and 110 auto-review uplift program brings a reusable teaching from the upstream `dzianisv/opencode-plugins` auto-review package into the mutation-coverage pipeline. Signature-based dedup prevents the same mutation from being proposed twice across iterations of one improvement arc.

> Spec folder: `.opencode/specs/skilled-agent-orchestration/110-auto-review-stretch-config-dedup-gates` (Level 3)

## What's New at a Glance

- **Signatures are stored with each mutation in `mutation-coverage.json`.** The signature is `sha256(dimension + ":" + mutationType + ":" + targetSection + ":" + normalized_body.slice(0,64))`. The council's section 10.6 review made this file the authoritative store instead of `agent-improvement-state.jsonl`, so the replay consumer and coverage reducer share one source of truth. That JSONL state file is event-sourced and append-only, so dedup queries there would have to scan the entire history on every proposal.
- **A matching proposal is skipped with `EXHAUSTED-FROM: iter-NNN`.** The skip points to the iteration that first proposed the mutation.
- **Older coverage keeps its legacy path.** The reducer falls back to legacy equality checks when an entry has no `signature`. New proposals receive the field before append, so dedup engages on the next iteration.
- **The dedup bypass is invocation-only.** Set `DEEP_AGENT_IMPROVEMENT_SKIP_DEDUP=1` to retry an exhausted mutation for the duration of a run, such as after editing its target section or when a prior failure seems environmental rather than substantive. It is not a permanent config setting, so leave it unset for the safe default.
