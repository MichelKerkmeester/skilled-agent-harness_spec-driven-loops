# v1.9.10.0, The Docs Name the Files the Repository Holds

The runtime README listed its configuration files but not its package manifest, so a reader had to open the folder to find where the dependencies and the commands come from. Two module READMEs also named compiled files that the repository does not carry, so an import line led nowhere.

> Spec folder: `specs/sk-doc/070-repo-doc-debt/005-reference-and-coverage-fixes` (Level 2)

&nbsp;

## What's New at a Glance

- **The runtime README lists the package manifest.** The row says what the file is and that it holds the runtime's dependencies with its two commands.
- **Two module READMEs name the tracked source files.** Where an import line named a compiled file the repository does not carry, it now names the source file you can open.

No action is needed. This is a documentation change, so the runtime runs exactly as it did.
