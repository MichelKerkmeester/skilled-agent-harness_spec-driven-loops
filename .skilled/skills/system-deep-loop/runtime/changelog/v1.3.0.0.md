v1.3.0.0 aligns the deep-loop runtime's database directory with its sibling convention, stops shipping a committed runtime SQLite file and completes README coverage across the test subfolders.

> Spec folder: `.opencode/specs/skilled-agent-orchestration/116-deep-skill-evolution/000-release-cleanup/001-deep-loop-runtime/`

## Why This Release

Two structural issues remained after v1.2.0. The runtime directory was `storage/` while the sibling `system-spec-kit/mcp-server/` used `database/`. The committed SQLite database meant external repository users received a stale copy instead of regenerating a fresh database on first run, and four of five test subfolders lacked READMEs.

## What's New at a Glance

- **The runtime directory is now `database/`, not `storage/`.** The `git mv storage database` preserves history and follows the sibling `system-spec-kit/mcp-server/` convention. The lifecycle test's hardcoded lock path was updated to match the new directory, and current documentation uses the new path while historical changelogs preserve `storage/` as an accurate point-in-time record.
- **The runtime SQLite database is now a generated artifact.** It is no longer committed, and new `.gitignore` rules cover `database/*.sqlite` and its `-shm`, `-wal` and `.bak` files. `database/README.md` stays tracked, and a fresh checkout initializes the database on the first script run.
- **All five test subfolders now have READMEs.** The four new guides cover `unit/`, `integration/`, `lifecycle/` and `council/`, describe the test files and the module or surface each tests, match the existing `helpers/README.md` style and are linked from `tests/README.md` §2.

## Upgrade

The script argv contract, stdout JSON shape, exit codes and TypeScript import paths are unchanged. No consumer action is required for them. The only load-bearing code change is the `COVERAGE_GRAPH_DATABASE_DIR` constant in `coverage-graph-db.ts`, which changed from `storage` to `database`. The four `.cjs` scripts and writer-lock path derive the runtime database path from that constant. Consumers that hardcoded `storage/` should switch to `COVERAGE_GRAPH_DATABASE_DIR`. None were found in the repository.
