deep-loop-runtime now explains how to tell whether the runtime is healthy. It also says where its consumers and tests live. This closes two sk-doc conformance gaps. Runtime behavior does not change.

> Spec folder: `.opencode/specs/skilled-agent-orchestration/116-deep-skill-evolution/008-deep-skill-doc-evolution` (Level 2)

## What's New at a Glance

- **SKILL.md adds a `SUCCESS CRITERIA` section.** It fills a missing explicit health contract. The contract names the JSON stdout contract for every script entry point. It names consumer `lib/` import resolution. It names runtime SQLite and schema presence. It names Vitest discovery. Consumer skills get a concrete checklist for checking runtime health.
- **The references block now extends beyond ADRs.** It names the consumer skills `deep-review` and `deep-research`. It names the cross-package Vitest config that discovers this skill's tests. It names the changelog directory. So readers can trace the runtime to everything that depends on it.
- **The runtime's references stay flat by design.** It has four focused reference files and few consumers. By contrast, four reference-heavy `deep-*` skills moved to thematic subfolders.
