deep-loop-runtime now explains how to tell whether the runtime is healthy. It also says where its consumers and tests live. This closes two sk-doc conformance gaps. Runtime behavior does not change.

&nbsp;

## What's New at a Glance

- SKILL.md adds a `SUCCESS CRITERIA` section.
  - The section fills a missing explicit health contract.
  - The contract names the JSON stdout contract for every script entry point.
  - The contract names consumer `lib/` import resolution.
  - The contract names runtime SQLite and schema presence.
  - The contract names Vitest discovery.
  - Consumer skills get a concrete checklist for checking runtime health.
- The references block now extends beyond ADRs.
  - The block names the consumer skills `deep-review` and `deep-research`.
  - The block names the cross-package Vitest config that discovers this skill's tests.
  - The block names the changelog directory.
  - So readers can trace the runtime to everything that depends on it.
- The runtime's references stay flat by design.
  - The runtime has four focused reference files and few consumers.
  - By contrast, four reference-heavy `deep-*` skills moved to thematic subfolders.
