Version `1.0.0` is the first shipped release of `deep-loop-runtime`, replacing the `v0.1.0` phase-001 scaffold with a populated and verified peer skill. Shared libraries, coverage graph ownership, direct script entry points, SQLite storage and runtime tests now live together outside `system-spec-kit/mcp-server/`.

> Spec folder: `.opencode/specs/skilled-agent-orchestration/116-deep-skill-evolution/003-deep-loop-runtime/009-verification-changelog-closeout/` (Level 2)

## Why This Release

Before 118, every change to the deep-review or deep-research loop infrastructure required touching files inside `system-spec-kit/mcp-server/`. Two consumer skills (`deep-review`, `deep-research`) depended on internals of a third skill (`system-spec-kit`), and the MCP tool surface (`mcp__system_spec_memory__deep_loop_graph_*`) added a marshalling layer between workflow YAMLs and the SQLite-backed coverage graph. The arrangement was accumulated drift from early MCP server scaffolding, with no ADR to justify it.

Arc 118 (`FULL_ISOLATE_NO_MCP`) consolidated all deep-loop runtime infrastructure into this peer skill, removed the MCP tool surface and replaced it with direct `.cjs` script invocation, following the pattern `reduce-state.cjs` already used. It was a user-directive override of the 117 AI Council `SPLIT` ruling. Workflow YAML calls became one-step (`bash: node .../scripts/<name>.cjs`) instead of two-step (MCP dispatch then JSON parse).

New contributors fixing a `deep-review` bug can work entirely within `deep-loop-runtime/` and `deep-review/` without MCP-server traversal. The phase parent is `.opencode/specs/skilled-agent-orchestration/116-deep-skill-evolution/spec.md`, and the superseded 117 ruling is ADR-001 in `.opencode/specs/skilled-agent-orchestration/116-deep-skill-evolution/003-deep-loop-runtime/001-core-isolation-deliberation/decision-record.md`. The 118/003 ADR-001 records the script interface contract and the transfer of DB lifecycle ownership, and the 118/004 ADR-001 records the rationale for removing the MCP tool surface.

## What's New at a Glance

- **The runtime owns its coverage graph.** The graph and its SQLite database now sit with the peer skill.
- **Workflow YAMLs call direct scripts.** Four entry points replace the MCP graph tools.
- **Runtime guides ship with the skill.** The feature catalog, operator playbook and references cover runtime capabilities and interfaces.

## Runtime Ownership

#### Runtime Owns the Graph

The peer skill owns the coverage graph and its SQLite database at `.opencode/skills/deep-loop-runtime/storage/deep-loop-graph.sqlite`. `coverage-graph-db.ts`, `coverage-graph-query.ts` and `coverage-graph-signals.ts` are under `.opencode/skills/deep-loop-runtime/lib/coverage-graph/`. The database module contains the schema, connection lifecycle and node-kind allow-list. The query module builds queries, while the signals module extracts convergence signals. The `deep-review` v1.4.0.0 and `deep-research` v1.12.0.0 changelogs depend on this runtime.

&nbsp;

#### Shared Support Lives Together

Ten shared TypeScript modules under `.opencode/skills/deep-loop-runtime/lib/deep-loop/` cover executor config, executor audit, prompt-pack rendering, post-dispatch validation, atomic state, JSONL repair, loop locking, permissions, Bayesian scoring and fallback routing. Runtime-focused unit, integration and lifecycle tests moved into `.opencode/skills/deep-loop-runtime/tests/`. The `system-spec-kit/mcp-server/vitest.config.ts` includes `'../deep-loop-runtime/tests/**/*.{vitest,test}.ts'` for cross-package test discovery, so a single `pnpm vitest run` exercises both surfaces. The only retained test in the old location is `mcp-server/tests/deep-loop/review-depth-reducer.vitest.ts`, which tests `deep-review/scripts/reduce-state.cjs` in `deep-review/`, not the migrated runtime.

## Workflow Calls

#### YAML Uses Direct Scripts

Workflow YAMLs previously used MCP dispatch followed by JSON parsing. The removed `mcp__system_spec_memory__deep_loop_graph_*` tools are replaced by four CommonJS scripts:

- **`scripts/convergence.cjs`.** Replaces `mcp__system_spec_memory__deep_loop_graph_convergence`.
- **`scripts/upsert.cjs`.** Replaces `_upsert`.
- **`scripts/query.cjs`.** Replaces `_query`.
- **`scripts/status.cjs`.** Replaces `_status`.

The scripts parse CLI args such as `--spec-folder`, `--loop-type` and `--session-id`. They open the SQLite database in a `try` block, call the relevant library function, write JSON to stdout and close the database in a `finally` block. Exit codes are 0 for success, 1 for script error, 2 for DB error and 3 for input validation error. **Breaking:** Existing workflow YAMLs must use the direct script invocation shown in Upgrade Notes.

## Upgrade Notes

- **Workflow YAMLs.** Replace the removed convergence tool `mcp__system_spec_memory__deep_loop_graph_convergence` with this direct invocation and its outputs:

  ```yaml
  bash: 'node .opencode/skills/deep-loop-runtime/scripts/convergence.cjs --spec-folder "{spec_folder}" --loop-type "review" --session-id "{session_id}"'
  outputs:
    - graph_decision
    - graph_signals_json
    - graph_blockers_json
    - graph_blockers_csv
    - graph_stop_blocked
  ```
