# v1.9.17.0, The Drift Checker Tests Facts

The deep-loop docs had drifted from the code. They named workflow files that were merged away. They named paths that never existed. The drift checker now tests those facts, so the next drift fails a check.

&nbsp;

## What's New at a Glance

- `--facts` runs three rules.
  - `scripts/check-documentation-drift.cjs --facts` checks a stated executor count against `EXECUTOR_KINDS`.
  - The checker checks that each named file exists.
  - The checker checks the routing step of each command doc against its flag table.
- A plain run includes the facts.
  - With no flag the checker runs every check.
  - A failure prints a line such as `facts: <file>:<line>: names confirm.yaml, which does not exist` and exits 1.
- Changelogs, benchmarks and tests are skipped.
  - They keep old names on purpose.
- The live tree is clean.
  - The first run reported 463 errors.
  - The checker now prints `"errors": []`.
  - `tests/unit/check-documentation-drift.vitest.ts` holds 11 cases.
- The runtime docs name the single workflow files.
  - `references/integration-points.md`, `feature-catalog/` and `manual-testing-playbook/` name `deep-research.yaml` and `deep-review.yaml`.
  - The hub `ARCHITECTURE.md` names `runtime/scripts/lib/cli-guards.cjs` and `runtime/scripts/loop-lock.cjs`.
