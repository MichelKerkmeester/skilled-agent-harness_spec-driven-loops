The review reducer only read `- **F###**:` bullets. An iteration in the agent's own numbered shape had no structured rows behind it. So it reached the registry with no findings. The reducer now reads both shapes. A cli-pi child also receives the one variable that keeps pi-blackhole from compacting it mid-run.

&nbsp;

## What's New at a Glance

- **Numbered findings reach the registry.** `reduce-state.cjs` reads `N. **Title** -- file:line -- Description` lines. It gives each the delta-row id `R<iteration>-<severity>-<NNN>`. So a later iteration can resolve it.
- **Structured rows still come first.** An iteration that recorded delta finding rows or `findingDetails` keeps those. Its numbered narrative is not counted a second time.
- **Evidence lines stay evidence.** The Finding class, Scope proof, Affected surface hints and Case lines are not counted as findings. Nested lists and adjudication JSON under a finding are not counted either.
- **The F### shape still works.** Older iterations reduce exactly as before.
- **`PI_BLACKHOLE_PASSIVE` passes the cli-pi filter.** `executor-audit.ts` lets that one variable through for cli-pi only. It still strips every unlisted variable.
