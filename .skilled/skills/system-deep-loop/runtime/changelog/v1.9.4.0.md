Research verification and the fan-out merge share one parser. It counted every numbered line in a findings section. So a step listed under a finding counted as its own finding. An iteration's count could disagree with the findings it claimed. It now counts only findings that start at the left margin. It also reads the F### bullet shape.

> Spec folder: `specs/sk-code/011-sk-code-poinytail-based-refinement/011-round-four-remediation/006-deep-loop-findings-parser` (Level 1)

&nbsp;

## What's New at a Glance

- **Sub-steps stay sub-steps.** A numbered line indented under a finding is part of that finding. It is not a new one.
- **F### bullets are read.** A findings section can be written as `- **F001**:` bullets. It now yields its findings instead of none. A bullet with words between the id and the colon is a restatement. It is not read, as in the review reducer.
- **One shape per section.** A section restates its findings in a second shape. It counts each finding once.
- **Review findings count once.** The review reducer now lets an F### bullet yield to its iteration's structured row. That row carries the same id. Numbered findings already yield to the rows of theirs. So a review folder counts each finding once. That holds when its narrative restated its structured rows. A finding only the narrative recorded is kept.
