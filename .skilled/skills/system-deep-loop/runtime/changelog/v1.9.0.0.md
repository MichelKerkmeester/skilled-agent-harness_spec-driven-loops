v1.9.0.0 adds `score-fanout-pairs.cjs`. It is an offline fan-out pair replay. It reads the recorded fan-out lineage registries. It prints the near-line and cross-body candidate pairs. It prints the merge's own decision on each pair, with deduplication on and off. It also adds the unit tests behind that census. The default run makes no model call and writes no file. `fanout-merge.cjs` is unchanged.

## Why This Release

The fan-out merge collapses near-duplicate findings with one title-overlap rule. It never compares two findings whose bodies differ. So the pairs it judged have never been measured against a second opinion. Neither have the pairs it skipped. The tracked lineage registries already hold every one of those pairs. `score-fanout-pairs.cjs` prints that census. It prints the merge's own decision on each pair under both deduplication settings. Then it scores one backend's same-or-different judgment against the operator's pair labels. That happens when an arm is named.

## What's New at a Glance

- **The default run makes no model call and writes no file.** `node .skilled/skills/system-deep-loop/runtime/scripts/score-fanout-pairs.cjs` reads the recorded fan-out lineage registries. It prints the pair census and the merge's own decision on each pair. Logging stubs for `jev` and `cli-deem` were first on `PATH`. No stub was called.
- **A pair sheet starts the measurement.** `--write-pair-sheet <path>` writes at most the first 60 pairs of each class. They are ordered by the SHA-256 of the pair key. Each row carries both findings' text, their lineages, the run path and an empty `label`. The operator fills that label with `same` or `different`. `--labels <file>` reads the filled sheet back. A path inside the repository prints `refusing to write the pair sheet inside the repository` and writes no file.
- **The label gate needs 40 labeled pairs and 10 of them cross-body.** Below either floor the run prints `stop: fewer than 40 labeled pairs` or `stop: fewer than 10 labeled cross-body pairs`. No model call happens. When the merge's own decisions are already right on more than nine labeled pairs in ten, the run prints `no headroom`. It leaves both arms closed.
- **Both arms are opt-in and each runs behind its own gate.** `--jev` and `--deem` each need `--out <dir>`, so every call is recorded. Either switch without it exits 2 before any call. With both switches the Jev gate and arm run first. Then the Deem gate and arm run. Each runs regardless of the other's outcome. A failed gate prints its own skip line, such as `deem arm skipped: stub backend` or `jev arm skipped: no credential`.
- **One fixed rule decides each measured column.** Coverage, loss, margin, a sign test and flips are checked in a fixed order. The baseline is the merge's own decision. Only a column that passes them all is kept. No run has printed a `verdict` line. So this entry claims none.
- **The merge is unchanged.** The script reads each decision by calling the merge's own functions. It does not copy the collapse rule. So the census always reports what the shipped rule does. Nothing about the merge changes.

## Upgrade

No migration required. The script is new and `fanout-merge.cjs` is unchanged.
