# cli-jev v1.0.1.0

## Changed

- **The authenticated surface is observed rather than source-read.** The operator stored an
  `official` credential in the machine's credential store, and the two previously SKIP rows now
  carry recorded PASSes: `auth status` reports `ok`/`stored`/store path at exit 0, `auth test`
  reports `valid` with the model id, and one judgment per type returned the documented shapes
  (`noul` a probability, `choice` a submitted key, `score` a zero-based position). The run lives in
  `benchmark/reports/2026-09-20-authenticated-verification/`.
- **The truth surfaces were reconciled with that run**: the playbook's provider boundary and its
  scenario index, the two scenario files' recorded results, the provider reference's
  confirmed-versus-unconfirmed section, the catalog's unconfirmed section, and the SKILL.md
  availability bullet.
- **One new source-read distinction is recorded**: once a credential file exists, an absent provider
  is reported as `stored <provider> API key is empty` rather than `<provider> API key is not
  stored`; both are exit 3 with empty stdout (`src/jev_cli/__init__.py:99`).

## Notes

- The key lives only in the machine's credential store. No packet file or captured stream carries
  it, and the no-key scenarios reproduce by pointing `XDG_CONFIG_HOME` at an empty directory.
- The `vercel`, `openrouter` and `custom` response bodies, their pinned-default-model currency, and
  every quota or latency figure remain unconfirmed.
