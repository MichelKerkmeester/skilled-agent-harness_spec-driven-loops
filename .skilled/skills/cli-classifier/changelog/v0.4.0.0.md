The Jev transport moves into `cli-classifier` as mode `cli-jev` over the `cli-usage` packet, and the hub joins the compiled serving fleet in the place the retired `cli-jev` hub held.

> Spec folder: `specs/cli-jev/003-cli-jev-workflow-integration/009-cli-jev-hub-move/` (Level 1)

## What's New at a Glance

- **Two transports, one hub.** `mode-registry.json` lists `cli-deem` and `cli-jev`. Mode `cli-jev` runs over the packet folder `cli-usage`, which moved from `.skilled/skills/cli-jev/cli-usage/` with its references, feature catalog, playbook, benchmark runs and changelog. Both modes are `packetKind: "transport"` under the `transport-axis` extension.
- **The router picks a backend by name.** `hub-router.json` carries the Jev vocabulary and signals the `cli-jev` hub used, beside the Deem ones. `tieBreak` lists `cli-jev` then `cli-deem`, so a request that names both backends by their aliases routes to both as an ordered bundle. A request that names only the hub defers, because the hub name does not choose a backend.
- **The hub serves compiled routes.** The rollout child `009-parent-hub-rollout/008-cli-classifier` compiles both modes, and `013-live-activation/activation/cli-classifier/manifest.json` pins that policy at generation 1 with `servingAuthority: "compiled"`. The hub takes `cli-jev`'s place in every cohort list, so the fleet stays at seven hubs.
- **The dispatch audit names the hub.** A `jev` dispatch now records skill `cli-classifier` with packet path `cli-classifier/cli-usage`.
- **The hub files merge.** `SKILL.md`, `README.md`, `ROUTER.md`, `description.json`, `graph-metadata.json` and `leaf-manifest.json` describe both modes. The hub playbook's routing scenarios cover `cli-jev`, `cli-deem` and out-of-domain requests. The routing files move to version `1.1.0.0`.

## Upgrade

Replace `--hub cli-jev` with `--hub cli-classifier` in any compiled-route call. The mode name `cli-jev` and the packet name `cli-usage` are unchanged, so a request that names `cli-jev` still reaches the Jev transport.
