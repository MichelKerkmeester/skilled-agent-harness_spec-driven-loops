The hub's `ROUTER.md` now ships `router_state: active`. So all seven judgment intents across the two transports resolve to packet-local leaf resources from `leaf-manifest.json`. Stage one gained the vocabulary. That vocabulary closes the phrasings which used to defer.

&nbsp;

## What's New at a Glance

- The surface router is live.
  - `ROUTER.md` moves from `router_state: stage1-only` to `active`.
  - Its seven intents (`JEV_JUDGMENT`, `JEV_QUESTION`, `JEV_PROVIDER`, `JEV_MCP`, `DEEM_JUDGMENT`, `DEEM_PROVENANCE` and `DEEM_LIFECYCLE`) map to packet-local leaf resources from `leaf-manifest.json`.
  - Each intent lists its mode's baseline first.
- Stage one routes the old name and the new phrasings.
  - The vocabulary class `cli-usage-aliases` is now `cli-jev-aliases`.
  - The vocabulary class keeps the `cli-usage` keyword.
  - So a request with the old name still reaches `cli-jev`.
  - Thirteen phrases joined `jev-dispatch` and `deem-dispatch`.
  - So "which provider and model id does jev use" routes to `cli-jev`.
  - And "roll deem back to the previous commit" routes to `cli-deem`.
  - Both deferred before.
- The script folders gained code-folder READMEs.
  - These folders now each hold one: `shared/scripts/`, `shared/scripts/tests/`, `cli-deem/scripts/`, `cli-deem/scripts/tests/`, `benchmark/pi-transport/tests/` and `benchmark/injection-screen/tests/`.

&nbsp;

## Upgrade

No migration required. Routing decisions that were correct before stay the same.
