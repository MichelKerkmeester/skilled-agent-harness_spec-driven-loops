Jev questions now reach Pi's native classifier first, and the `jev` CLI answers wherever Pi cannot. Every call record says which route answered. The scorers that ask Jev share one report module, and the injection screen now pins its inputs and keeps a checked-in live verdict.

> Spec folder: `specs/cli-jev/003-cli-jev-workflow-integration/` (Level 2, phased), with the follow-up fixes in `specs/cli-jev/005-cli-classifier-quality-fixes/` (Level 1)

## What's New at a Glance

- **Pi answers first.** `shared/scripts/jev-transport.mjs` sends `choice` and `noul` questions to Pi's classifier when its preflight passes and falls back to the `jev` CLI otherwise. `JEV_TRANSPORT=jev` forces the CLI. Each provider maps to the Pi classifier on its own host.
- **Every answer names its route and model.** Outcomes carry `transport` and the answering model, and a Pi answer carries its token usage. All six callers now record `transport`, including `score-clarify-default.cjs`, which used to label Pi answers as Jev.
- **One shared report module.** `shared/scripts/scorer-report.mjs` gives the scorers the same row pin, probability-aware pick, margin slack and cluster bootstrap, so their report lines read alike.
- **A reproducible injection screen.** The scorer pins its corpus and ships a trust package, adds a probability-aware verdict beside the majority one, and keeps earlier runs instead of overwriting them. Its latest live run kept Jev at 84 of 90 right against 68 for the lexical screen, recorded in `benchmark/reports/2026-10-03--injection-screen--jev-pi-default/`.
- **Clearer docs and narrower routing.** The cli-jev references gained Overview sections, the README says how to install `jev`, and the hub keywords now say `jev score` and `jev choice` instead of bare `score` and `choice`, so a prompt that only asks to "score" something no longer routes here.

## Upgrade

No migration is required. To keep a caller on the CLI, set `JEV_TRANSPORT=jev`.
