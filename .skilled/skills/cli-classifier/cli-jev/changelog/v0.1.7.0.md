# v0.1.7.0, Baseline references load only on a matched route

The router used to load both baseline references on every request, including one that matched no intent. It now follows the cli-classifier hub, where each intent loads its baseline first and an unmatched request loads nothing.

> Spec folder: `specs/sk-doc/072-skill-routing-and-clarity/002-baseline-and-routing-correctness` (Level 2)

&nbsp;

## What's New at a Glance

- **The baseline rides the matched route.** `references/cli-reference.md` and `references/integration-patterns.md` still open every scored route, so a judgment starts with the contract it needs.
- **A no-match loads nothing.** An unmatched request returns the disambiguation checklist alone, so asking a question no longer pays for context it does not use.

&nbsp;

## Upgrade

No action is needed.
