# v0.1.8.0, Routing Summary Moves to a Short Section

The routing section carried the availability probe, the phase tree, the resource domains, the loading levels and the whole discovery pseudocode, so a reader waded through a hundred and thirty lines before reaching the transport contract. Those blocks now sit in a final `## 9. MACHINE ROUTER` section, unchanged, and the section above is five lines of plain prose. It says what selects this packet, what it loads first and where the router blocks went.

> Spec folder: `specs/sk-doc/072-skill-routing-and-clarity/008-cli-and-mcp-hubs` (Level 2)

## What's New at a Glance

- **A judgment runs exactly as before.** The intent model, the resource map, the load levels and the fallback checklist moved byte for byte, so no request loads a different reference.
- **The routing section reads in one pass.** Five lines name the hub signal, the binary probe and the credential check the transport needs.
- **The pseudocode sits last.** One `MACHINE ROUTER` section holds the discovery and routing functions, which is where the package checks now read them.
