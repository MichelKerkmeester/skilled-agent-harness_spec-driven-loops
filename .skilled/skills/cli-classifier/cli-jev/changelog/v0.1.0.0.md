The hub now routes typed Jev judgments through `cli-jev`. Jev reads state. It prints a value. It does not edit or run anything.

&nbsp;

## What's New at a Glance

- The hub gains its first `packetKind: "transport"` mode, `cli-jev`.
  - Through the hub's `transport-axis` extension, it dispatches the TypeSafe Jev CLI (`jev`).
  - The CLI is pinned at 0.6.2.
  - The CLI handles `noul` probabilities, `choice` selections, `score` positions and batched `run` requests.
  - The CLI declares `mutatesWorkspace: false`.
  - The CLI forbids `Write`, `Edit` and `Task`.
- Eight hard rules have implemented checks.
  - The checks cover availability and stdin bounding.
  - The checks cover `choice` and `score` cardinality.
  - The checks cover `--value` against `run` and the `custom` endpoint requirement.
  - The checks cover inline credentials and host-only `jev-mcp`.
- Dispatch identifies Jev by command.
  - `jev` and `jev-mcp` resolve to `cli-jev` from the command.
  - The commands do not resolve from text that merely contains the word.
- Four references and one asset document Jev.
  - The references include the CLI contract and its exit-code taxonomy.
  - The references include the provider and model table with per-provider translation.
  - The references include four integration patterns.
  - The references include the `jev-mcp` server contract with its operator step.
  - The question-shaping card is the asset.
- `jev-mcp` remains unwired in repository MCP config.
  - `jev-mcp` ships in the same installation.
  - `jev-mcp` is documented.
  - The operator chooses the host and config file.
- Live provider responses remain unconfirmed.
  - The workspace has no Jev provider key.
  - So `references/providers-and-models.md` marks every statement about live provider responses as unconfirmed.
  - `references/providers-and-models.md` records a conclusion with receipts.
  - The conclusion comes from the vendored source.
  - An OpenAI-compatible LLM Gateway key cannot front Jev without a translating proxy.
  - That is because the request and response use the native System One contract.
- Jev cannot be pinned as a `/deep:research` executor.
  - Jev has no file tools, loop or lineage.
  - So `EXECUTOR_KINDS` gains no entry.
