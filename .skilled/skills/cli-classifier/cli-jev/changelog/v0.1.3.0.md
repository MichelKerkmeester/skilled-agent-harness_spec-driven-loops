A `choice` question can now run on Pi's classifier runtime behind `JEV_TRANSPORT` or a per-call option, with the `jev` CLI as the default and the fallback.

## What's New at a Glance

- **The switch is `JEV_TRANSPORT` and the `transport` option.** An unset value, `''` or `jev` means the CLI, `pi` means Pi for a `choice` request, and an unknown value prints `skip: unknown transport '<value>', using jev CLI` once before the CLI runs. The per-call option wins over the environment.
- **`choice` only.** `auth`, `noul`, `score`, `run` and a `choice` call with an unmappable flag stay on the CLI unchanged and print nothing. Only the declared `choice` shape has a transport decision to make.
- **Four skip lines.** A failed package, model, credential or backend check prints exactly one `skip: pi transport unavailable (<gate>), using jev CLI` line and then runs the CLI, so a caller always reads a CLI-shaped outcome and no Pi failure is silent.
- **The answer keeps the CLI's shape.** `answers.answer.choice`, `answers.answer.probabilities`, a top-level `model`, compact JSON on stdout and exit code 0. A caller that opts in changes one call, not its parsing.
- **Credentials stay in Pi's store.** The transport calls `ModelRuntime.create()` and lets Pi resolve its own credential. It reads no `.env`, prints no environment variable and copies no key.
- **Two callers opt in.** `leaf-route-replay.cjs` and `score-clarify-default.cjs` reach the transport at `shared/scripts/jev-transport.mjs`. Switch-off bytes are unchanged, because the CLI branch is the callers' own bounded spawn.
- **The Pi route exists on a recorded verdict.** The predecessor phase's run printed `verdict pi-transport: adopt` over `choice` rows only.

## Upgrade

No migration required. The `jev` CLI stays the default, so a caller that names no transport sees no change.
