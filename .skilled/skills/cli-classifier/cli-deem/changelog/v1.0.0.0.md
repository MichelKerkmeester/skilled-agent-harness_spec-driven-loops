A Node client asks the locally served Deem model for typed judgments and answers in the field names `jev` readers already parse.

> Spec folder: `specs/cli-jev/003-cli-jev-workflow-integration/008-cli-classifier-hub/` (Level 1)

## What's New at a Glance

- **`cli-deem health` is the one availability check for Deem.** It passes only when the local server answers `status` `ok` from the `torch` or `ensemble:` backend with the model id `deem-0.8-v1`. It then prints the commit pair read from the install. The stub backend and any other model id exit 3. A stopped server exits 4. No code path starts the server.
- **Four judgment subcommands speak Deem's own request shape.** `noul`, `choice`, `score` and `run` post to `/v1/systemone` with `options` and `levels` lists, the shape the Python `jev` CLI cannot send.
- **Answers arrive in the `jev` field names.** `value` becomes `noul`. The chosen description maps back to its `choice` key. `level` becomes its zero-based `score` position. Probabilities are rekeyed the same way.
- **Caps are checked before sending.** More than 26 options, more than 64 questions and a duplicate option description or key exit 2 with a named message and no request.
- **The client talks only to this machine.** `CLI_DEEM_URL` must be an `http://` URL on `127.0.0.1`, `localhost` or `[::1]`. Anything else exits 2 before any request.
- **Exit codes mirror `jev`.** 0 success, 1 an unexpected response, 2 usage, 3 a refused backend, 4 unreachable and 130 interrupted.
- **The client sends no key.** It is one file with `node:` imports only. Its tests run against an in-process fake server and never reach port 8300. They pin the 500 ms `--hook` budget and the 2,000 ms health budget.
- **Three references document the rest.** The wire contract lists every field. The lifecycle reference covers `deem-ctl`. The model-pin reference explains when a kept result must be requalified.
