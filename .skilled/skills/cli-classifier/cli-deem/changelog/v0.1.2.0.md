The client now reads the answer shapes the real Deem server sends instead of the legacy `value` and `level` fields it used to translate.

> Spec folder: `specs/cli-jev/003-cli-jev-workflow-integration/044-deem-answer-shape-fix/` (Level 2)

## What's New at a Glance

- **`noul` passes through.** Deem answers `{"type":"noul","noul":<number>,"x_confidence":…,"x_temperature":…}`. The client range-checks `noul` in `[0, 1]` and passes the answer through unchanged; the `value` rename is gone.
- **`score` passes through.** Deem answers with `score`, the expected level — a float from `0` to the last level index — plus a `legend` mapping each index to its level text and `probabilities` keyed by index. The client range-checks `score` and prints the answer as sent; the `level` lookup and the probability rekey are gone.
- **`choice` is unchanged.** The chosen option text still maps back to the submitted key, and `probabilities` are still rekeyed by key.
- **New exit-1 messages.** `unexpected response: noul is not a number in [0, 1]` and `unexpected response: score is not a number in range` replace the old shape errors.

## Upgrade

No migration required. Callers that parsed `noul` and `score` keep working; only the translation step was removed.
