# v1.1.0.0, Overlays for Projects That Already Have Them

A project that already keeps its own overlay folder can now use `/doctor:overlay` without moving a file. The first real project to try it got a full report on every overlay, where it used to get one error and no report.

> Spec folder: `specs/system-skilled-doctor/001-skill-and-overlay-build/005-barter-parity`

&nbsp;

## What's New at a Glance

- **A protected file blocks only its own overlay.** The rest of the report still covers every other overlay, and the `MISS` line names the file to add to that entry's `protectedPaths`. A re-pin refuses such an entry before it takes its backup.
- **A re-pin tells you what it left out.** Each upstream change it does not copy, such as a new root file or a path under `repin.exclude`, prints as a `not-copied` line so you can carry it over by hand. The screen shows the first 20 and `report.json` keeps them all.
- **A staged re-pin says what it skipped.** A stage now counts the regenerate and verify steps it did not run, so a clean stage no longer reads as a full rehearsal.
- **`.dsh` is copied with the other runtime folders.** A re-pin no longer leaves that runtime folder on the old commit.
- **A missing overlay folder points at the fix.** When the engine cannot find the manifest, the error says to name the folder in `.skilled-overlays.json`.

&nbsp;

## Upgrade

A project whose overlay folder is not `skilled-overlays/` names it in `.skilled-overlays.json`, for example `{"overlayDir":"my-overlays"}`. An overlay that walks a folder holding a token-named file it needs lists that file in its `protectedPaths`.
