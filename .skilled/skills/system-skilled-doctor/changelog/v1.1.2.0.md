# v1.1.2.0, Removed Folders Stay Removed

A skill-root overlay can remove folders from an upstream skill. When upstream added a file inside one of those folders, `/doctor:overlay` called it a live edit, told you to capture it, and `apply` refused. The file now counts as removed, and `apply` deletes it.

> Spec folder: `specs/system-skilled-doctor/003-removed-folder-classification`

&nbsp;

## What's New at a Glance

- **Removed means removed.** A file under a skill-root entry's `remove` list shows as `overlay-edited` with the fix `apply`, never as `live-edited`. `apply` deletes it and exits 0.
- **Re-pin no longer blocks on it.** `repin --stage` treats an upstream addition inside a removed folder as removed, so the stage no longer stops with a blocked line for that entry.
- **A replaced file inside a removed folder stays yours.** A file the entry's `replace` list names keeps its overlay copy, even when its folder is removed.
- **Capture says why it refuses.** `apply --capture` on a removed path writes nothing and says the path is scheduled for removal by its overlay.

&nbsp;

## Upgrade

Nothing to run. If you added `repin.exclude` entries only to get past this refusal, you can delete them on your next re-pin.
