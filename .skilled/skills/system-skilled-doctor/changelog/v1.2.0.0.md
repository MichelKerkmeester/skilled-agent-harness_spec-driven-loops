# v1.2.0.0, Re-Pin a Vendored Copy With a Rollback

A project that vendors Skilled can now move to a newer upstream commit without a hand-run runbook. `/doctor:overlay repin` shows a staged result first, then copies, re-applies the overlays and checks, and a failed run can be rolled back byte for byte.

> Spec folder: `specs/system-skilled-doctor/001-skill-and-overlay-build/003-repin`

## What's New at a Glance

- **A staged run comes first.** It builds the re-pinned tree in a copy and lists the overlays to rebase, leaving your tree untouched. <!-- section: Re-Pin -->
- **Every re-pin has a backup.** The paths a run will touch are saved before its first write, and `--rollback` puts them back. <!-- section: Re-Pin -->
- **In-place edits are caught.** A re-pin refuses while a file no overlay owns differs from the pinned commit, and names that file. <!-- section: Safety -->
- **Re-pins apply cleanly.** A file that still holds its pinned upstream bytes after the copy now reads as ready to apply. <!-- section: Overlay Engine -->

## Re-Pin

#### One Guarded Run

`repin --upstream <checkout> --to <commit>` copies the `.skilled` paths upstream changed and each runtime folder whole, removes what upstream deleted, sets the pin and applies the overlays twice. A path in the manifest's `repin.exclude` list is never copied over.

&nbsp;

#### Rolling Back

A run keeps its backup in `<overlayDir>/repin-runs/<run-id>/`. When it fails after the backup it prints the rollback line, and the rollback restores every file and removes what the run created.

---

## Safety

#### Unowned Edits and Secret Files

A re-pin refuses before any write when an unowned file differs from the pinned commit, and when upstream ships a `.env` path.

---

## Overlay Engine

#### Pinned Bytes Apply

After the pin moves, a destination that holds exactly its pinned upstream bytes reads `overlay-edited` rather than `upstream-moved`, so `apply` writes the overlay over it.

---

## Upgrade

1. **Re-Pin:** list any project folder that upstream ships as a link, such as a real `.opencode/scripts`, in `repin.exclude`. List files your project regenerates as outputs of a regenerate step, so the drift check treats them as managed.

`/doctor:overlay` itself has no separate changelog. Its `repin` target ships with this release.
