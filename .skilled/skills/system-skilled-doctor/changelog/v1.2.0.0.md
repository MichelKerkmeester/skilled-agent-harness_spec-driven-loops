# v1.2.0.0, Overlays Lay Out Under framework/ and root/

Every overlay copy now has its layout path under `framework/` for a `.skilled/` destination, or under `root/` for any other. After the re-pin, run `/doctor:overlay apply --relayout` once to move an existing folder onto it. Nothing breaks if you skip that: status still passes and every overlay keeps applying.

&nbsp;

## What's New at a Glance

- The layout path has two roots, the default for every tree.
  - `.skilled/X` lays out at `framework/X`, and `.skilled` itself at `framework`.
  - Any other destination lays out at `root/` plus the path with its leading dots dropped, so `.claude/settings.json` lays out at `root/claude/settings.json`.
- An old-layout tree keeps working.
  - The engine reads each `source`, `fragment` and `base` exactly as the manifest names it.
  - `status` prints a `LAYOUT` note per off-layout copy and still ends `RESULT: PASSED`.
- `status` caps the `LAYOUT` notes.
  - It prints at most 20, then one line: `LAYOUT   … <n> more; run node .skilled/commands/doctor/scripts/overlay-engine.cjs apply --relayout`.
  - `status --json` keeps every move in `offLayout`.
- `root/skilled/` holds no copy.
  - A `source`, `fragment` or `base` there is a blocked overlay.
  - Adopt and relayout refuse to write there, so one destination never has two sources.
- Adopt places each new copy at its `framework/` or `root/` path.
  - For a path under `repin.exclude`, adopt also accepts a copy at the older path and prefers the `framework/` or `root/` one when both exist.

&nbsp;

## The Overlay Folder Can Sit Beside the Tree

- `.skilled-overlays.json` can name a direct sibling, `../<name>`, as well as a folder inside the tree.
  - A deeper path, the tree itself, a link back into the tree or a dangling link is refused with `.skilled-overlays.json names a folder outside the tree root: <value>`.
  - A backslash or an absolute path is refused with `.skilled-overlays.json must name a relative folder with forward slashes: <value>`.
  - `pre-commit` exits 2 when the folder sits outside the tree's git repository.
- A re-pin backs up the sibling folder's own files.
  - They go under `<run>/overlay-backup/` as `area: "overlay"` entries.
  - Rollback restores each file against its own root.
- `repin --stage <dir>` copies the tree to `<dir>/<tree name>` and the overlay folder to `<dir>/<overlay name>`.
  - It writes nothing live.
  - It refuses a stage folder inside the overlay folder.
- A relayout keeps its backup in `<overlay folder>/relayout-runs/<stamp>/`, keyed from the overlay root.

&nbsp;

## Upgrade

Re-pin as usual, then run `/doctor:overlay apply --relayout` once and confirm `status` prints no `LAYOUT` line. If you skip the relayout, new adopts land under `framework/` or `root/` while older copies stay where they are, so the folder holds both layouts until you run it.
