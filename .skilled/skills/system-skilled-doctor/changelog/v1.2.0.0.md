# v1.2.0.0, Overlays Lay Out Under framework/ and root/

Every overlay copy now has one layout path.

- A `.skilled/` destination lays out under `framework/`.
- Any other destination lays out under `root/`.
- One relayout moves an older folder onto it.

The overlay folder can sit beside the tree.

- `.skilled-overlays.json` can name `../<name>`.
- A re-pin backs up and stages that folder too.

Applies and relayouts got safer, and reports got clearer.

- Bad layout links stop before any write.
- `status --audit` checks the overlay folder's READMEs.
- Most refusals end with a `Next:` line.

> [!IMPORTANT]
> One change can stop a setup that passed before.
>
> 1. A duplicate or escaping layout link now exits 2. [Layout links](#c-bad-layout-links-are-refused)

&nbsp;

## Why This Release

Overlay copies sat wherever each project put them. Two projects never matched, so a teammate had to hunt for each one. The overlay folder also had to live inside the copy. A broken layout link could pass `status` and fail later. Refusals named a fix in prose, not a command to run.

## The Layout

The layout path is now the default for every tree. Older trees keep applying until one relayout moves them.

#### Two Roots for Every Copy <a id="c-two-roots-for-every-copy"></a>

- `.skilled/X` lays out at `framework/X`.
- `.skilled` itself lays out at `framework`.
- Any other destination lays out under `root/`.
- Its leading dots are dropped there.
- So `.claude/settings.json` lays out at `root/claude/settings.json`.
- `root/skilled/` holds no copy.
- A `source`, `fragment` or `base` there is a blocked overlay.
- Adopt and relayout refuse to write there.

#### Old Trees Keep Working <a id="c-old-trees-keep-working"></a>

- The engine reads each `source`, `fragment` and `base` as named.
- `status` prints a `LAYOUT` note per off-layout copy.
- It still ends `RESULT: PASSED`.
- It prints at most 20 notes, then one overflow line.
- `status --json` keeps every move in `offLayout`.
- Adopt places each new copy at its layout path.
- Under `repin.exclude`, adopt also accepts the older path.

```text
LAYOUT   other-files: source other-source belongs at root/other-live; run node .skilled/commands/doctor/scripts/overlay-engine.cjs apply --relayout
```

## The Overlay Folder Beside the Tree

The setting file can now point one level up. The tree still names its own overlays.

#### A Sibling Folder Is Allowed <a id="c-a-sibling-folder-is-allowed"></a>

- `.skilled-overlays.json` can name a direct sibling, `../<name>`.
- A deeper path or the tree's own name is refused.
- So is a dangling link.
- Each prints `.skilled-overlays.json names a folder outside the tree root: <value>`.
- A sibling link back into the tree gets its own refusal.
- It prints `.skilled-overlays.json names a sibling that resolves into the tree root: <value>`.
- A sibling holding the tree root is refused too.
- It prints `.skilled-overlays.json names a sibling that resolves to a folder holding the tree root: <value>`.
- A backslash or an absolute path is refused.
- It prints `.skilled-overlays.json must name a relative folder with forward slashes: <value>`.
- A folder outside the tree's git repository stops every command.
- `status`, `apply`, `guard` and `pre-commit` all exit 2 then.

#### A Re-Pin Carries the Sibling <a id="c-a-re-pin-carries-the-sibling"></a>

- A re-pin backs up the sibling folder's own files.
- They go under `<run>/overlay-backup/`.
- Rollback restores each file against its own root.
- `repin --stage <dir>` copies both folders into `<dir>`.
- It writes nothing live.
- It prints `staged tree root: <dir>/<tree name>`.
- Pass that folder as `--root` to a later `status`.
- `--json` carries it as `stagedRoot`.
- A stage folder inside the overlay folder is refused.
- A relayout keeps its backup in `relayout-runs/<stamp>/`.

## Safer Applies

Each of these stops a run that once failed halfway, or failed for no good reason.

#### Bad Layout Links Are Refused <a id="c-bad-layout-links-are-refused"></a>

- A manifest can list one layout link path twice.
- Paths are compared after they are normalized.
- `status` and `apply` then exit 2 before any write.
- They print `layout link path is listed twice: <path>`.
- A link path can also leave the tree.
- It may be absolute, climb out with `..` or pass an outside link.
- That prints `layout link path escapes the tree root: <path>`.
- Relayout and adopt print the same line after `refuse:`.

> [!WARNING]
> A manifest that passed before can now exit 2. Fix the named `layoutLinks` entry, then rerun `status`.

#### A Failed Relayout Puts Everything Back <a id="c-a-failed-relayout-puts-everything-back"></a>

- Before, a failure after the first move left a half-moved folder.
- Now every move, the manifest write and each relink are guarded.
- A failure restores the copies, the manifest and the links.
- It exits 2 with one line naming the step that failed.
- Relayout refuses a move onto a documentation-only README.

#### An Apply Can Change a Shape <a id="c-an-apply-can-change-a-shape"></a>

- An entry can switch between a file, a folder and a layout link.
- Apply removes its own old output first.
- Then it writes the new shape in the same run.
- An unowned file, folder or link in the way is refused.
- The refusal names the command that moves it aside.

```text
  Next: mv /path/to/tree/thing /path/to/tree/thing.keep, then from /path/to/tree: node .skilled/commands/doctor/scripts/overlay-engine.cjs apply
```

#### Python Caches Stay Out of Overlays <a id="c-python-caches-stay-out-of-overlays"></a>

- Only a `__pycache__` folder counts as a cache folder.
- Only a `.pyc` or `.pyo` file counts as a cache file.
- A folder named like `x.pyc` is ordinary content.
- Overlays never ship a cache, and status passes over one.
- A dropped folder holding only caches is removed.
- When apply cannot remove one, it prints a `NOTE`.
- The note names the clearing command, and the apply still succeeds.
- A re-pin backs up only the caches its apply may remove.

#### Env Templates Re-Pin Like Other Files <a id="c-env-templates-re-pin-like-other-files"></a>

- `.env.example` holds no secrets.
- The engine now reads, copies and reports it like a vendored file.
- It is the one template name the env secret guard also lets an agent read.
- Every other `.env` file stays protected.

## Clearer Reports

The reports now say what to do next. The audit also looks at the overlay folder itself.

#### The Audit Checks Overlay READMEs <a id="c-the-audit-checks-overlay-readmes"></a>

- `status --audit` now walks the overlay folder.
- Each folder without a README prints one `DOCS` line.
- A README that fails sk-doc's validator prints one too.
- `docs=<n>` counts them.
- The check is advisory.
- It never changes `RESULT:` or the exit.
- `--json` carries the findings under `docs`.
- A README is documentation only unless an entry ships it.
- A README a `retained` path keeps inside a `replace` folder never ships.

```text
DOCS     missing-readme skilled-overlays/framework
docs=1
```

#### Every Refusal Names the Next Command <a id="c-every-refusal-names-the-next-command"></a>

- Most engine, doctor-script and git-hook refusals now end with `Next:`.
- That line names the exact command to run.
- The write guard names its command inline instead.
- A held lock names the pid to check and the file to remove.
- `status` fails on a `REGEN` line while a regeneration is unfinished.

## How It Was Checked

The overlay engine suites ran 392 tests, and all 392 passed. The 11 overlay scenarios in the manual playbook were rerun in temporary trees. Their expected signals now match the engine's output line for line.

| Command | Before | After |
|---|---|---|
| `status --audit` on a folder with no READMEs | Not measured, since the check is new | `audit=2`, four `DOCS` lines, `docs=4`, then `checked=` |

## Upgrade Notes

1. Re-pin as usual.
2. Run `/doctor:overlay apply --relayout` once.
3. Confirm `status` prints no `LAYOUT` line.
4. If `status` exits 2 on a layout link, fix that entry first.

Skipping step 2 breaks nothing. New adopts still land under `framework/` or `root/`. Older copies stay where they are until you run it.
