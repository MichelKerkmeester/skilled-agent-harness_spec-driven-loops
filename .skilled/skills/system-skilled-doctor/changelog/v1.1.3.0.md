# v1.1.3.0, A Release Update Checks the Overlays

A release update could replace a file an overlay owns and the post-apply battery never looked.

&nbsp;

## What's New at a Glance

- **The update battery checks overlays.** A tree with an overlay manifest gets an overlay status row after `/doctor:update apply`, with `/doctor:overlay apply` named as the repair.
- **A clean re-pin names its next step.** `/doctor:overlay repin` points at `/doctor:update record-base`, because the release-update base keeps the old pin until it is recorded again.
- **The helper knows two more complaints.** "mcp tools are missing" reaches `/doctor:mcp debug` and "advisor daemon is stale" reaches `/doctor:skill-advisor rebuild`. Both returned no match.
- **The MCP fallback goes somewhere useful.** When Code Mode is healthy and another subsystem fails, the row names `/doctor:setup` and `/doctor:helper`.
- **The symlink workflows drop `--source`.** The check and link workflows offered a checkout override the route manifest refuses. The engine keeps the flag for its tests and for unlink.
