# v1.3.0.0, The Doctor Follows the Retired Advisor Lane Out

The skill advisor retired one of its lanes, and the doctor commands now match. They stop checking that lane. `/doctor:update apply` clears what it left on your machine. A cleanup request in plain words now reaches that command.

&nbsp;

## What's New at a Glance

- `/doctor:setup` runs six read-only legs.
  - The leg that checked the retired advisor lane is gone.
  - Its target table drops that lane's row and lists 26.
- `/doctor:skill-advisor` lists six targets.
  - The action that set up the retired lane is gone, with its workflow file and its argument hint entry.
- `/doctor:install` prints five setup steps.
  - The step that set up the retired lane is gone.
- `/doctor:update apply` ends with the lane cleanup.
  - It runs after the advisor rebuild prompt.
  - It runs on every path that reached that prompt.
  - It deletes what the retired lane left in this checkout.
  - It asks before it deletes the pulled shared model, on every run.
  - Its result never changes the update's `STATUS`.
- The orphan check no longer names the retired model server.
  - The lane cleanup's own machine check finds that process instead.
- Four workflows drop their health report for the retired lane.
  - They are `/doctor:overlay apply`, `/doctor:overlay repin`, `/doctor:symlink link` and `/doctor:update apply`.
  - Each made one status call about the lane after its write.

&nbsp;

## Cleanup Requests Reach the Right Command

- `/doctor:helper` and the skill advisor send cleanup wording to `/doctor:update`.
  - Examples are `clean embedding model` and `lane residue gate failing`.
  - A plain CI failure, model cache or shared model question does not match them.
  - A request to remove leftovers after an upgrade does, because those two words are all a request naming the retired product carries.
  - In `/doctor:helper`, a request that names the retired product matches through its other words.
- A linked project cannot run `/doctor:update`.
  - It stops at the link with `path parent is not a real directory: <project>/.skilled`.
  - Run `node .skilled/skills/system-spec-kit/runtime/cli/retrieval/sweep-lane-residue.mjs machine` from the Skilled checkout instead.
  - When it lists leftovers, run the same script's `apply`.
  - In a terminal, `apply` asks before it deletes the pulled shared model. Without one it keeps that model unless it gets `--shared-model delete`.
- `INSTALL-SKILLED.md` names the cleanup for linked and copied projects.
- The setup playbook now counts six legs and 26 rows.
- The advisor side of this change is in the `system-skill-advisor` v2.0.0.0 entry.

&nbsp;

## Upgrade

In a copied project, run `/doctor:update apply` once. On a copy already at the release, its plan holds one write, the recorded base. The cleanup still runs after the rebuild prompt. In a linked project, run the cleanup script from the Skilled checkout, as above.
