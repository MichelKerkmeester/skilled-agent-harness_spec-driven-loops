# v1.0.0.0, Skilled in Your Project, Kept Current

The first `system-skilled-doctor` release gives one owner to the doctor commands.

- Those commands are about putting Skilled into a project.
- One skill owns eleven doctor commands.
- Every command name works as before.

The release also adds `/doctor:overlay`.

- So a project that vendors Skilled keeps its own changes.
- That holds when it moves to a newer upstream commit.
- Re-pins come with a rollback.

Edits go to the overlay.

- The `overlay-guard` hook refuses an agent's edit to a file an overlay owns.
- It names the overlay file to change instead.

Each request reaches the right place.

- A request that names one doctor job reaches that command.
- A request about Skilled in a project reaches this skill.
- So does a request about a vendored copy.

## Doctor Commands

These commands put Skilled into a project. One skill owns them.

#### One Owner for Skilled Integration <a id="c-one-owner-for-skilled-integration"></a>

- Install, symlink, update, agents-md, runtime-mirrors, env, setup, helper, speckit, mcp and overlay credit `system-skilled-doctor`.
- Ten existing commands each changed one line.
- That line is their `skill_agent` tag.
- Nine came from `system-spec-kit`.
- `/doctor:agents-md` came from `sk-doc`.
- The scripts they call stay in `system-spec-kit`.
- Those include the trigger-index lookup and `ENV-REFERENCE.md`.

#### Domain Commands Stay Put <a id="c-domain-commands-stay-put"></a>

- `/doctor:sk-code`, `/doctor:ci`, `/doctor:git`, `/doctor:sk-skill`, `/doctor:skill-advisor` and `/doctor:deep-loop` stay with the skill whose own checks they run.

&nbsp;

## Overlays

Overlays let a vendored copy keep its own changes across a new upstream commit.

#### One Engine for Status, Apply and Re-Pin <a id="c-one-engine-for-status-apply-and-re-pin"></a>

- `/doctor:overlay status` reports each overlay that is out of sync.
- It reports that overlay's fix too.
- `apply` puts the overlays back.
- Status and apply read the same record of what was last applied.
- So a changed overlay applies over its earlier copy. No restore script is needed.
- The engine owns its lock. The operations in one JSON overlay apply in order.
- A project names its overlay folder in `.skilled-overlays.json`.
- The default is `skilled-overlays/`.

#### Re-Pin to a Newer Commit <a id="c-re-pin-to-a-newer-commit"></a>

- `/doctor:overlay repin` shows a staged result first.
- It backs up every path it will touch. It can undo a failed run byte for byte.
- `repin --upstream <checkout> --to <commit>` copies the `.skilled` paths upstream changed.
- It copies each runtime folder whole. It removes what upstream deleted.
- It sets the pin and applies the overlays twice.
- A run refuses before any write when a file no overlay owns differs from the pinned commit.
- The run names that file.
- Each run keeps its backup in `<overlayDir>/repin-runs/<run-id>/`.
- `--rollback` restores it.

#### Secret Files Stay Unread <a id="c-secret-files-stay-unread"></a>

- A `.env` file is never read.
- A re-pin refuses when upstream ships one.
- A file whose name contains `token` is read only where the manifest names its exact path.
- That holds through `protectedPaths` for an entry that walks a folder.

&nbsp;

## Guard Hook

The `overlay-guard` hook handles edits to files an overlay owns.

#### Refuse, Never Apply <a id="c-refuse-never-apply"></a>

- The `overlay-guard` hook refuses an agent's edit to a file an overlay owns.
- It names the overlay file to change instead.
- Claude, Codex, Cursor, Devin and Pi register the same `overlay-guard` hook.
- It only asks the engine whether a path is owned.
- So a refused edit leaves the tree as it was.
- In a repository without an overlay folder it allows every edit.
- An engine error or timeout allows the edit with a one-line note.

## Routing

Requests reach the command or skill that owns them.

#### Commands Win Their Own Requests <a id="c-commands-win-their-own-requests"></a>

- A request that names one doctor job reaches that command.
- A request about Skilled in a project reaches this skill.
- So does a request about a vendored copy.
- The regenerated command bridges credit each command to this skill.
- Each route carries the phrasings people use.
- The skill's own routing words describe Skilled in a project and vendored copies.
- So they never outrank a command on its own request.
- The word "doctor" on its own reaches this skill.

## Upgrade Notes

The steps below apply to the groups that use each part.

#### Before You Start <a id="c-before-you-start"></a>

1. For doctor commands, nothing to do. A project that pins advisor results for the moved commands should expect `system-skilled-doctor` where it saw `system-spec-kit` or `sk-doc`.
2. In a repository without overlays, nothing to do for the guard hook.

<details>
<summary><b>Overlays</b></summary>

- A project with overlays adds `.skilled-overlays.json`.
- That is unless its folder is `skilled-overlays/`.
- A directory entry that walks a token-named file it needs lists that file in `protectedPaths`.
- Before a re-pin, list any folder upstream ships as a link in `repin.exclude`.

</details>

<details>
<summary><b>Guard Hook</b></summary>

- Set `SYSTEM_OVERLAY_GUARD_DISABLED=1` to switch the hook off.

</details>

<details>
<summary><b>Overlay and hook notes</b></summary>

- `/doctor:overlay` and the `overlay-guard` hook have no separate changelogs.
- The hook's README is `.skilled/hooks/overlay-guard/README.md`.

</details>
