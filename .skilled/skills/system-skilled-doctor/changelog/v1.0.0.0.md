# v1.0.0.0, Skilled Integration Commands Get Their Own Skill

The first `system-skilled-doctor` release gives the doctor commands about putting Skilled into a project an owner whose purpose matches them. A request to install, link or update Skilled now routes here instead of to the spec-folder skill.

> Spec folder: `specs/system-skilled-doctor/001-skill-and-overlay-build/001-skill-and-tag-move`

## What's New at a Glance

- **One skill owns ten doctor commands.** Install, symlink, update, agents-md, runtime-mirrors, env, setup, helper, speckit and mcp now credit `system-skilled-doctor`. <!-- section: Doctor Commands -->
- **Every command name keeps working.** No command file moved, and each one runs exactly what it ran before. <!-- section: Doctor Commands -->
- **Integration requests route to the new skill.** "Put Skilled into my project repo" now ranks it first. <!-- section: Routing -->

## Doctor Commands

#### One Owner for Skilled Integration

The ten commands each changed one line, their `skill_agent` tag. Nine came from `system-spec-kit` and `/doctor:agents-md` came from `sk-doc`. The skill's README now holds the command table that used to sit in the `system-spec-kit` README.

&nbsp;

#### Domain Commands Stay Put

`/doctor:sk-code`, `/doctor:ci`, `/doctor:git`, `/doctor:sk-skill`, `/doctor:skill-advisor` and `/doctor:deep-loop` stay with the skill whose own checks they run.

---

## Routing

#### The Advisor Credits the New Owner

The regenerated command bridges credit each moved command to `system-skilled-doctor`. The scripts those commands call, such as the trigger-index lookup and `ENV-REFERENCE.md`, stay in `system-spec-kit`.

---

## Upgrade

1. **Doctor Commands:** nothing to do. Every `/doctor:*` name works as before.
2. **Routing:** a project that pins advisor results for these commands should expect `system-skilled-doctor` where it saw `system-spec-kit` or `sk-doc`.
