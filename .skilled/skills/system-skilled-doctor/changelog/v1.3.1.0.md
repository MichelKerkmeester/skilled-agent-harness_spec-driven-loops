# v1.3.1.0, Requests Reach the Right Doctor Command

A request that names one doctor job, such as "which doctor command fits my problem" or "run the doctor setup checks", now reaches that command instead of stopping at this skill.

> Spec folder: `specs/system-skilled-doctor/001-skill-and-overlay-build/001-skill-and-tag-move`

## What's New at a Glance

- **Commands win their own requests.** The skill's routing words describe Skilled in a project and vendored copies, and no longer copy each command's own phrasing. <!-- section: Routing -->
- **More ways to ask.** Install, symlink, environment, setup, runtime-mirror, trigger-index, Code Mode, update, AGENTS.md and overlay requests each gained the phrasings people use. <!-- section: Routing -->
- **Re-pins reach this skill.** "Re-pin my vendored Skilled copy" now ranks this skill first, ahead of `sk-git`. <!-- section: Routing -->
- **A bare "doctor" reaches this skill.** A prompt that only says "doctor" now lands here. <!-- section: Routing -->

## Routing

#### A Bare "Doctor" Reaches This Skill

The word "doctor" now names this skill, so a prompt that says only "doctor" reaches it. The doctor routing test set expects that for its one such prompt.
