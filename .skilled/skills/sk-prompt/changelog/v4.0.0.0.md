`sk-prompt` now improves a prompt in one pass. The DEPTH thinking framework is removed. `references/depth-framework.md` became `references/improvement-checklist.md`. The new file reads the prompt once against ten rows. Then it writes once from one skeleton. Then it delivers. There are no rounds and no phases left to count.

## Why This Release

DEPTH asked a reader to think in rounds before writing. The rounds gave the skill a shape it could not justify. A good prompt still went through the same loop. A caller could never tell how many rounds had run. One pass over named rows is checkable. So the same result arrives faster. A prompt that was already good is returned untouched.

## What's New at a Glance

- **DEPTH is removed.** One pass over ten rows replaces it. Each row is marked present, absent or not needed, with a reason.
- **Good prompts exit early.** A prompt that already passes comes back unchanged. Or it comes back with the smallest edit the caller asked for.
- **Effort levels replace rounds and energy.** Quick, standard and thorough set how much of the checklist runs. `$raw` runs no pass at all.
- **The quick test is local.** Two or three inputs run through the old prompt and the new one when a model can run them. Otherwise the test is reported as not run.
- **The seven frameworks are optional presets.** They sit on top of one default skeleton. None is scored to pick one.
- **Repair means the same thing everywhere.** The skill, the agent and the command all allow up to three cycles.
- **Routing only reads the caller's own words.** A pasted prompt is set aside before any mode token is matched.
- **The skill stays model-agnostic.** No per-model profiles are added.

## One Pass Replaces DEPTH

#### DEPTH Is Gone, the Checklist Is New

`references/depth-framework.md` was deleted. `references/improvement-checklist.md` holds the replacement. It works in one pass over ten rows. The rows are task and outcome, role or audience, context, constraints and priority order. They also cover process, output format, examples, success criteria, unknowns and wording. Every row is marked present, absent or not needed, with a one-line reason. That is because a mark without a reason is an opinion. A mark with a reason can be argued with. No prompt has to contain every row. A row marked not needed is not added.

#### Early Exit

When every row is present or not needed, the prompt comes back unchanged. It may also come back with the smallest edit the caller explicitly asked for. The reply names the rows already covered, so the judgment is visible. The early exit also covers the narrow request. A caller who asks for one wording change gets that change. The reply also notes that the rest of the prompt stands. Work is not invented to justify the pass.

#### Effort Levels Replace Rounds and Energy

Effort decides checklist breadth and whether the quick test runs. It never decides a hidden count of thinking rounds. **Quick** (`$short`) checks rows 1, 3, 4 and 6. Those rows are task, context, constraints and output format. **Standard** is the default and checks all ten rows. **Thorough** (`$refine`) checks all ten rows and adds the quick test. `$raw` runs no pass. The prompt passes through as written, for a caller that owns its own prompt handling.

#### The Quick Test

Two or three representative inputs run through the old prompt and the new one when a target model can run them. The reply reports what differed. When no model can run the inputs, the reply says `Quick test: NOT RUN`. The work continues. A skipped test is a stated fact, not a failure. The test runs locally. It depends on no hosted evaluation service. It is evidence, not proof. A handful of inputs shows direction, not distribution.

## Frameworks, Screening and Repair

#### The Seven Frameworks Become Presets

RACE, RCAF, COSTAR, CIDI, CRISPE, TIDD-EC and CRAFT stay. They are optional presets applied on top of one default skeleton. None of them is scored to decide which one to use. So the checklist decides the content. A preset only reshapes it. One skeleton on every prompt keeps the shape of each prompt in a session alike. That is what makes later comparison possible.

#### CLEAR Stays a Structural Screen

CLEAR is unchanged. It is defined once, in `patterns-evaluation.md` section 10. It is still a 50-point structural screen with a pass at 40. The reason is written before each score. So the number follows the argument rather than replacing it. A CLEAR score is not proof the prompt works. It measures the presence and shape of components. It does not measure the quality of the answer they produce.

#### Repair Is Three Cycles Everywhere

The skill, the agent and the command used to disagree on how many attempts a weak draft got. One place gave one retry. Another gave three cycles. All three now repair up to three cycles. Then they deliver the best version, with a note saying what remained weak.

## Delivery and Routing

#### Deliver First

The prompt comes before any commentary, so it can be copied without hunting for it. Every default and assumption becomes a numbered open item after the prompt. It never sits inside the prompt. That is because a default inside a prompt reads as a requirement the caller never chose. One question is asked in only two cases. There is no prompt and no task to work from. Or two mode commands conflict and only the caller can settle which was meant. Everything else is delivered with a stated assumption.

#### Routing Reads Only the Caller's Words

Mode detection now reads only words the caller wrote. A pasted prompt is set aside before matching. That covers a fenced code block. It covers a quoted span of three or more words in double, single or curly quotes. It covers text after a lead-in such as `prompt:` or `improve:`. Mode tokens then match whole tokens only. So a word that merely contains a token no longer selects a mode. Two mode commands that disagree return `COMMAND_CONFLICT` and one question. Examples are `$raw` with `$json`, or `$short` with `$refine`. That replaces a guess from keyword scores.

#### Router Fixtures

`benchmark/router/run_fixtures.sh` is new. It runs nineteen fixtures against the real `ROUTER.md` block. The fixtures include pasted prompts that contain mode tokens. They also include conflicting mode commands. So the routing rules above are checked against the text that ships, not a copy of it.

## Surface Changes

#### The Output Block Gains Two Lines

Responses now carry a `TEST:` line holding the quick-test outcome. They also carry a `CHANGES:` line holding the change report. The report stays one line per heading: added, changed, removed, skipped.

#### Agent and Command Follow

`@prompt-improver` and `/prompt:improve` are updated to the one-pass flow. They also take the three effort levels and the same repair bound as the skill. Their confirm checkpoints are renamed to `after_checklist`, `after_draft` and `after_screen`. So each name says which stage it guards.

#### The Skill Stays Model-Agnostic

No per-model profiles are added. The checklist describes prompt content. It leaves model choice to the caller and to the CLI executors that delegate here.

---

## Upgrade

- Callers that parsed a `DEPTH Rounds` field must read the checklist marks instead. They must also read the `TEST:` and `CHANGES:` lines. The rounds count no longer exists.
- Callers that parsed the old checkpoint names must switch to `after_checklist`, `after_draft` and `after_screen`.
- References to `references/depth-framework.md` must point at `references/improvement-checklist.md`.
