v2.2.0.0 extends `sk-prompt` beyond text tasks to the framework's design-generation tools. Its generic text-prompt engine had seven frameworks, DEPTH, CLEAR and three format guides. But it could not write a brief for `mcp-open-design` `start_run`. There, generic briefs produce the median AI look. The house design skill exists to resist that look. A new reference and router wiring close that gap. They add no pipeline.

&nbsp;

## What's New at a Glance

- Design prompts get a grounded pattern.
  - `references/design-generation-patterns.md` layers design-specific slots onto COSTAR, CRISPE and CRAFT.
  - The reference does not add a framework.
  - The reference specifies an anti-default brief with a subject and single job.
  - The reference also specifies design-system reuse-before-generate and an explicit avoid-list.
  - The brief carries one aesthetic risk and a fidelity target.
  - The reference adds the String Seed of Thought anti-median variation technique.
  - That is a random 12-char string.
  - Its ASCII sum mod N indexes brief-grounded directions before reasoning.
  - The reference also pre-answers Open Design's multi-turn discovery form.
  - So a run does not drift to its recommended defaults.
  - The reference points to `claude_design_parity.md` §6's handoff manifest for the move into `sk-code`.
  - The reference owns only the prompt.
  - The reference defers the look to `sk-design-interface`.
  - The reference defers run transport to the two MCP skills.
- The smart router recognizes `DESIGN_GEN`.
  - Its new `INTENT_MODEL` entry in `SKILL.md` has these keywords.
  - The keywords are open design, start_run, design generation, generate ui, canvas, design brief and variations.
  - `RESOURCE_MAP` loads the new reference alongside `patterns_evaluation.md`.
  - The Resource Domains block also names the new reference.
  - So do the §1 use-case list, the §5 references and the §9 resource list.
  - The Resource Loading Levels table gains a CONDITIONAL row for it.

&nbsp;

## Upgrade

No migration required. Existing modes, frameworks and CLEAR scoring are unchanged. Design-generation routing is additive. Design-generation routing engages only when a request carries design-generation signals. Text-prompt behavior is identical to 2.1.3.0.
