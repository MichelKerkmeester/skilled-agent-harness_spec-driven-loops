v2.2.0.0 extends `sk-prompt` beyond text tasks to the framework's design-generation tools. Its generic text-prompt engine had seven frameworks, DEPTH, CLEAR and three format guides, but it could not write a brief for `mcp-magicpath` canvas authoring or `mcp-open-design` `start_run`, where generic briefs produce the median AI look the house design skill exists to resist. A new reference and router wiring close that gap without adding a pipeline.

> Spec folder: `.opencode/specs/skilled-agent-orchestration/145-mcp-open-design/006-sk-prompt-design-tool-usecases/` (Level 2)

## What's New at a Glance

- **Design prompts get a grounded pattern.** `references/design-generation-patterns.md` layers design-specific slots onto COSTAR, CRISPE and CRAFT rather than adding a framework. It specifies an anti-default brief with a subject and single job, design-system reuse-before-generate, an explicit avoid-list, one aesthetic risk and a fidelity target, plus the String Seed of Thought anti-median variation technique: a random 12-char string whose ASCII sum mod N indexes brief-grounded directions before reasoning. The reference also pre-answers Open Design's multi-turn discovery form so a run does not drift to its recommended defaults, points to `claude_design_parity.md` §6's handoff manifest for the move into `sk-code`, owns only the prompt and defers the look to `sk-design-interface` and run transport to the two MCP skills.
- **The smart router recognizes `DESIGN_GEN`.** Its new `INTENT_MODEL` entry in `SKILL.md` has the keywords magicpath, open design, start_run, design generation, generate ui, canvas, design brief and variations. `RESOURCE_MAP` loads the new reference alongside `patterns_evaluation.md`. The Resource Domains block, the §1 use-case list, the §5 references and the §9 resource list also name the new reference, and the Resource Loading Levels table gains a CONDITIONAL row for it.

## Upgrade

No migration required. Existing modes, frameworks and CLEAR scoring are unchanged. Design-generation routing is additive: it engages only when a request carries design-generation signals, and text-prompt behavior is identical to 2.1.3.0.
