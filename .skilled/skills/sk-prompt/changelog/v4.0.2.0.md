# v4.0.2.0, Docs Read in Order and Render as Written

The skill's `SKILL.md`, `ROUTER.md`, `README.md`, two references and four assets were read file by file for readability, layout and structure. No routing behavior, checklist row or scoring rule changed.

> Spec folder: `specs/sk-doc/066-skill-readability-refinement/010-sk-prompt` (Level 1)

## What's New at a Glance

- **The checklist reference states effort first.** EFFORT LEVELS is now section 2, ahead of THE CHECKLIST, because the effort level decides which rows run. The sections between move down one, and the playbook scenarios that cite them by number follow.
- **Intros say when to open each file.** The three format guides, the CLI quality card and the checklist reference open with one line on when to reach for them.
- **Multi-step paragraphs became lists.** The README's one-pass workflow, the default skeleton in `patterns-evaluation.md` and the pre-planning guidance in the CLI quality card each read as steps or bullets.
- **The routers list every asset.** `ROUTER.md` maps the CLI quality card to its CLI fast-path loading level, and `SKILL.md` lists `framework-registry.json`.
