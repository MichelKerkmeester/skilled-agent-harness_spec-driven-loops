# v4.0.2.0, Docs Read in Order and Render as Written

The skill's `SKILL.md`, `ROUTER.md`, `README.md`, two references and four assets were read file by file. The read covered readability, layout and structure. No routing behavior, checklist row or scoring rule changed.

&nbsp;

## What's New at a Glance

- **The checklist reference states effort first.** EFFORT LEVELS is now section 2, ahead of THE CHECKLIST. That is because the effort level decides which rows run. The sections between move down one. The playbook scenarios that cite them by number follow.
- **Intros say what each file is for.** The three format guides and the CLI quality card open with one line. That line says when to reach for them. The checklist reference opens with what its ten rows and delivery rules decide.
- **Multi-step paragraphs became lists.** The README's one-pass workflow reads as steps or bullets. So do the default skeleton in `patterns-evaluation.md` and the pre-planning guidance in the CLI quality card.
- **The routers list every asset.** `ROUTER.md` maps the CLI quality card to its CLI fast-path loading level. `SKILL.md` lists `framework-registry.json`.
