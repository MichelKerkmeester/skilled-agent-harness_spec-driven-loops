# v3.0.8.0, The Routing Prose Is Short and the Router Moved to the End

A reader now reaches the enhancement pipeline sooner. `SMART ROUTING` is six lines of plain prose that name the command prefixes, the intent scoring and the two reference files that load first, and the rest of the routing detail sits unchanged in a final `## 10. MACHINE ROUTER` section. Nothing about which resource loads for which request changed.

> Spec folder: `specs/sk-doc/072-skill-routing-and-clarity/009-standalone-skills` (Level 2)

&nbsp;

## What's New at a Glance

- **The routing section is prose.** The prefixes, the near-tie rule and the zero-score fallback are stated in six lines, so the pipeline comes before the router instead of after it.
- **The router is at the end.** The detection signal, the phase tree, the resource domains, the loading levels and the smart-router pseudocode moved byte for byte into `## 10. MACHINE ROUTER`, the last section of the file, under the headings they already carried.
- **Two pointers follow the move.** The pipeline note and the reference loading note now cite Section 10 for the pseudocode and for the loading rules.

&nbsp;

## Upgrade

No action is needed. The skill routes and loads exactly the resources it did before, and only the section that holds the routing detail changed.
