# v3.0.11.0, The Machine Router Moves to ROUTER.md

The machine router from `SKILL.md` now lives in sibling `ROUTER.md`, after a short overview and an intent model. The resource map, default resource, loading levels and routing pseudocode sit under the `MACHINE ROUTER` heading. The move changed no routing decision; its one addition to the parsed router is the `NO_LOAD_INTENTS` constant that names `RAW` as deliberately loading nothing.

&nbsp;

## What's New at a Glance

- **SMART ROUTING stays concise.** The prose in `SKILL.md` ends with one line linking to `ROUTER.md`.
- **Supporting documents follow the new path.** Testing playbooks and references that pointed to the router in `SKILL.md` now point to `ROUTER.md`.
- **RAW says it loads nothing.** `ROUTER.md` names RAW in `NO_LOAD_INTENTS = ("RAW",)` beside its empty `RESOURCE_MAP` entry, so the router check can tell the deliberate passthrough from an intent that lost its resources. RAW still skips DEPTH and every reference.
- **The advertised surfaces now match what ships.** The design-generation promise names the framework library it actually loads, the asset and document indexes list the CLI prompt quality card, and the playbook's scenario contracts grade against the router that runs.
- **RAW now loads nothing, as it says.** The router reads `NO_LOAD_INTENTS` before it loads anything, so a `$raw` token anywhere in the request skips DEPTH and every reference. The prose phrase "raw passthrough" no longer selects RAW, because passthrough is asked for by the token and never inferred from prose. Before this, "raw passthrough" selected RAW and still loaded the DEPTH reference. The advisor also now reaches sk-prompt on a design-generation brief or prompt.
