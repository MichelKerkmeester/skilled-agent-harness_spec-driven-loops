`sk-prompt` now gives prompt engineering a standalone routed-resource home. It replaces the former parent-hub shape. The prompt-engineering engine is now the skill itself. The small-model prompt-craft capability it used to dispatch to is retired.

## Why This Release

Prompt-engineering requests now reach the skill directly by advisor identity. They skip the hub's two-stage resolution.

## What's New at a Glance

- **The prompt-engineering engine is now the skill itself.** The skill name and `/prompt:improve` command are unchanged.
- **Small-model prompt-craft profiles are retired.** A prompt naming only a model no longer resolves to that model's CLI executor. The advisor's alias table no longer does that lookup.
- **The canonical CLI prompt-quality card has a new home.** `sk-prompt/assets/cli-prompt-quality-card.md` is the card that `cli-*` executors delegate to.
- **Prompt-improvement methods are unchanged.** The seven frameworks, DEPTH and CLEAR scoring behave identically.

---

## Prompt Engineering

#### The Engine Joins the Root

The engine's content moved from the nested packet to the skill root by rename. Internal paths were repointed. Its version history follows it. So the skill's version line continues from the engine's. This release is 3.0.0.0, not a hub 1.x successor. The standalone skill binds its slash command from the command definition. It does not use a `command-metadata.json` entry. That matches other standalone skills that own slash commands.

&nbsp;

#### Hub Routing Surface Is Removed

One workflow mode was left. So the hub's routing surface described a dispatch decision with a single possible answer. The surface had five components. All five are forbidden on a standalone root:

- `mode-registry.json`
- `hub-router.json`
- `description.json`
- `command-metadata.json`
- The stage-two `ROUTER.md`

The feature catalog was removed. Both entries documented hub routing only. That left it with no subject once the hub was gone. The skill is also withdrawn from the compiled-routing serving closure. It is withdrawn from its live-activation fence too.

&nbsp;

#### Small-Model Profiles Retire

The per-model reference set covered DeepSeek-v4-pro, Kimi-k2.7-code, MiniMax-M3, MiMo-V2.5-Pro, GLM-5.2 and Composer-2.5. Its model registry is retired with it. So are the per-model context budgets, quota-fallback and output-verification references and pattern index. This capability has no replacement.

&nbsp;

#### CLI Guidance Keeps Its Card

The card contains the seven-framework selection table. It holds the CLEAR pre-dispatch check. It also holds the escalation rule that every `cli-*` executor's local card delegates to. Its content is prompt-improvement doctrine, not per-model profile data.

&nbsp;

#### Advisor Metadata Narrows

`graph-metadata.json` moves to the standalone family. It drops the small-model domains, triggers and entities. It keeps one `enhances` edge to the CLI orchestration hub. That edge describes the canonical-card relationship.

&nbsp;

#### Manifest Outputs Follow Config

`leaf-manifest.config.json` is authored. `leaf-manifest.json` and `leaf-aliases.json` are regenerated from it.

## Upgrade Notes

- Consumers that read the retired per-model profiles must drop that step. There is no replacement.
- Consumers pointing at the card's old nested location should read `sk-prompt/assets/cli-prompt-quality-card.md`.
