`sk-prompt` now gives prompt engineering a standalone routed-resource home instead of the former parent-hub shape. The prompt-engineering engine is now the skill itself, while the small-model prompt-craft capability it used to dispatch to is retired.

## Why This Release

Prompt-engineering requests now reach the skill directly by advisor identity rather than through the hub's two-stage resolution.

## What's New at a Glance

- **The prompt-engineering engine is now the skill itself.** The skill name and `/prompt:improve` command are unchanged.
- **Small-model prompt-craft profiles are retired.** A prompt naming only a model no longer resolves to that model's CLI executor through the advisor's alias table.
- **The canonical CLI prompt-quality card has a new home.** `sk-prompt/assets/cli-prompt-quality-card.md` is the card that `cli-*` executors delegate to.
- **Prompt-improvement methods are unchanged.** The seven frameworks, DEPTH and CLEAR scoring behave identically.

---

## Prompt Engineering

#### The Engine Joins the Root

The engine's content moved from the nested packet to the skill root by rename. Internal paths were repointed. Its version history follows it, so the skill's version line continues from the engine's and this release is 3.0.0.0 rather than a hub 1.x successor. The standalone skill binds its slash command from the command definition rather than a `command-metadata.json` entry, matching other standalone skills that own slash commands.

&nbsp;

#### Hub Routing Surface Is Removed

With one workflow mode left, the hub's routing surface described a dispatch decision with a single possible answer. The surface comprised five components, all forbidden on a standalone root:

- `mode-registry.json`
- `hub-router.json`
- `description.json`
- `command-metadata.json`
- The stage-two `ROUTER.md`

The feature catalog was removed because both entries documented hub routing exclusively, leaving it with no subject once the hub was gone. The skill is also withdrawn from the compiled-routing serving closure and its live-activation fence.

&nbsp;

#### Small-Model Profiles Retire

The per-model reference set covered DeepSeek-v4-pro, Kimi-k2.7-code, MiniMax-M3, MiMo-V2.5-Pro, GLM-5.2 and Composer-2.5. Its model registry, per-model context budgets, quota-fallback and output-verification references and pattern index are retired with it. This capability has no replacement.

&nbsp;

#### CLI Guidance Keeps Its Card

The card contains the seven-framework selection table, the CLEAR pre-dispatch check and the escalation rule that every `cli-*` executor's local card delegates to. Its content is prompt-improvement doctrine rather than per-model profile data.

&nbsp;

#### Advisor Metadata Narrows

`graph-metadata.json` moves to the standalone family and drops the small-model domains, triggers and entities. It keeps one `enhances` edge to the CLI orchestration hub describing the canonical-card relationship.

&nbsp;

#### Manifest Outputs Follow Config

`leaf-manifest.config.json` is authored. `leaf-manifest.json` and `leaf-aliases.json` are regenerated from it.

## Upgrade Notes

- Consumers that read the retired per-model profiles must drop that step. There is no replacement.
- Consumers pointing at the card's old nested location should read `sk-prompt/assets/cli-prompt-quality-card.md`.
