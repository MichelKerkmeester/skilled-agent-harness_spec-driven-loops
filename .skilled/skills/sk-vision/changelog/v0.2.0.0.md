Vision is now opt-in. OpenCode, Cursor and Pi use `/vision` to activate image reading while Devin calls the MCP tool directly. OpenCode and Pi stay idle by default. Each command call can tear down the local runtime to prevent memory and GPU creep.

---

## What Changed

#### Commands

- **Opt-in activation**: OpenCode, Cursor and Pi provide `/vision`. `/vision <question>` answers against the most-recent image. Bare `/vision` returns a full read in OpenCode. Cursor and Pi ask in the conversation or return a full read because prompt files cannot open a UI input box. Devin has no command surface and calls `sk_vision_inspect` directly.
- **Host behavior**: OpenCode handles `/vision` in a `command.execute.before` hook and injects a `<SK-VISION COMMAND>` evidence block. Cursor's prompt drives its registered MCP tool. Pi's prompt drives a hidden tool that remains callable without appearing in the tool list. Claude has no sk-vision integration.

#### Runtime

- **Default posture**: OpenCode does not register sk-vision tools by default. Pi registers them hidden. Cursor and Devin keep their MCP tools available. No host auto-inspects an attached image during a normal message.
- **Teardown**: `SK_VISION_TEARDOWN=close` shuts down the runtime after each `/vision` call. `unload` frees the model and keeps the process. `keep` leaves the process running.
- **Reversibility**: `SK_VISION_AUTOINSPECT=1` restores legacy always-on auto-inspect and visible tools in OpenCode and Pi.
