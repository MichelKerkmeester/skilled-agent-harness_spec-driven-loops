Vision is now opt-in, so you can ask for image evidence instead of having an attached image inspected during a normal message. A command can also tear down the local runtime to prevent memory and GPU creep.

> Spec folder: `specs/sk-vision/001-sk-vision-fork-of-opencode-senses/023-command-gated-vision-and-runtime-teardown`

## What's New at a Glance

- **Request image reading with `/vision`.** OpenCode, Cursor and Pi support `/vision <question>` against the most-recent image. Bare `/vision` returns a full read in OpenCode. Cursor and Pi ask in the conversation or return a full read because prompt files cannot open a UI input box. Devin has no command surface and calls `sk_vision_inspect` directly.
- **Hooks and prompts carry `/vision`.** OpenCode's `command.execute.before` hook injects a `<SK-VISION COMMAND>` evidence block. Cursor's prompt drives its registered MCP tool, while Pi's prompt drives a hidden tool that remains callable without appearing in the tool list. Claude has no sk-vision integration.
- **Tool registration differs by host.** OpenCode does not register sk-vision tools by default and Pi registers them hidden. Cursor and Devin keep their MCP tools available, but no host auto-inspects an attached image during a normal message.
- **Choose how the runtime tears down.** `SK_VISION_TEARDOWN=close` shuts down the runtime after each `/vision` call. `unload` frees the model and keeps the process, while `keep` leaves the process running.
- **Restore legacy behavior.** `SK_VISION_AUTOINSPECT=1` restores legacy always-on auto-inspect and visible tools in OpenCode and Pi.

## Upgrade

No migration is required. Invoke `/vision` when you need image evidence. Set `SK_VISION_AUTOINSPECT=1` only when you need the legacy OpenCode or Pi behavior.
