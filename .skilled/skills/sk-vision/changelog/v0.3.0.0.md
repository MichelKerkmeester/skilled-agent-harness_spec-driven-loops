# v0.3.0.0, Vision Evidence for Devin and Cursor

Vision evidence now reaches Devin through its prompt hook and Cursor through an on-demand CLI. OpenCode and Pi are unchanged.

The MCP transport is retired, so the skill no longer depends on the MCP SDK and no longer ships a second bundle.

## Why This Release

Nothing could reach the MCP transport: Cursor's registration had already been dropped and Devin's permission allowlist never granted the `mcp__sk-vision__*` namespace.

## What's New at a Glance

- **MCP access is removed.** Its stdio server, both host configs and both mirror symlinks are gone.
- **Devin receives vision evidence with the prompt.** Its hook responds when a prompt names an existing image path.
- **Cursor can call vision on demand.** Its `/vision` command and always-apply rule invoke the CLI.
- **Both hosts share the same evidence rules.** The Devin hook and Cursor CLI use the same analysis and image-path detection.
- **Only real image files trigger analysis.** When a prompt names several images, the last one is used.
- **The Devin hook fails open.** Errors and unavailable runtime conditions produce an empty response.
- **Devin owns its MCP configuration.** `.devin/mcp_config.json` carries only `code_mode`.
- **A clean checkout can install the runtime.** The package manifest and `bun.lock` are tracked together.
- **Rendered text remains difficult for the default model.** `moondream2` recovers codes and digits but garbles surrounding words.
- **Cold model loads can outlast the Devin hook timeout.** The first image-bearing turn after a cold start can arrive without evidence.

## Host Integrations

#### Devin Gets Prompt-Time Evidence

On `UserPromptSubmit`, Devin's new hook `hooks/devin/sk-vision.mjs` checks a prompt for an image path that resolves on disk to a file, analyzes it and injects a `<SK-VISION EVIDENCE>` block into that turn. The model does not have to ask for the evidence and cannot decline evidence already in its context.

The hook is registered through `hook-registry.json` rather than by hand, keeping the generated Devin registration and `.devin/hooks` mirror in parity.

&nbsp;

#### Cursor Calls Vision on Demand

The new CLI `vision-runtime/dist/vision-cli.js` accepts an image path with an optional question or `--from-text` to find an image path inside prose. Cursor's `/vision` command and always-apply rule invoke it. Cursor delivers no prompt-time hook event, as a probe against build `2026.09.02-c22c1a3` confirmed with `sessionStart` as a positive control, so injection is impossible there and the call has to be made rather than forced.

&nbsp;

#### MCP Access Is Removed

The MCP stdio server and `sk-vision-mcp` binary entry are removed. The `mcp` script and `@modelcontextprotocol/sdk` dependency are also removed, along with both host configs and both mirror symlinks. The runtime no longer ships its second bundle.

&nbsp;

#### Devin's Config Has One Owner

`.devin/mcp_config.json` is now Devin's own file and carries only `code_mode`. It had been a symlink into the vision skill, which meant that skill owned Devin's entire MCP configuration. Ownership moved before deletion, so Code Mode was never momentarily unregistered.

## Vision Evidence

#### Shared Evidence Rules

The Devin hook and Cursor CLI use a shared evidence core, `src/evidence/prompt-evidence.ts`, for image-path detection, analysis, evidence wrapping and per-call teardown. Both hosts therefore use identical analysis and detection rules.

&nbsp;

#### Only Existing Images Trigger Analysis

A candidate counts only when it has an image extension and resolves to an existing file, so a filename mentioned in passing does not start the local GPU. When several images are named, the last one wins.

&nbsp;

#### The Hook Fails Open

The Devin hook returns an empty response for malformed payloads or a disabled kill-switch. It also does so for an unbuilt runtime, a prompt without an image or any error. `SYSTEM_SK_VISION_DISABLED=1` disables this hook. `SYSTEM_HOOKS_DISABLED=1` disables every hook in the repository. Both switches use the shared `hook-flags` resolver. The hook never blocks a turn and never writes to stderr.

&nbsp;

#### Evidence Keeps Its Outer Marker

The outer wrapper is `<SK-VISION EVIDENCE>`. A bare `<SK-VISION>` would nest inside the per-signal blocks the renderers already emit and strand a closing tag.

&nbsp;

#### The Model Defines Its Tasks

The dead `MOONDREAM3_ONLY_TASKS` constant is removed. It was defined and never read, and it listed `ocr`, contradicting the OCR handler's own comment. Gating is done by `_require_task` and `_supports`, which ask the loaded model what it advertises.

## Installable Runtime

#### Clean Checkouts Can Install It

`.opencode/.gitignore` ignores `package.json` and `package-lock.json` along with `bun.lock` repo-wide to keep vendored third-party server checkouts out of the tree. First-party packages override that rule. Eleven were already force-added. This package's manifest was the one first-party exception, so its dependency state existed only in working trees and a clean checkout had no manifest to install or build from.

The runtime manifest and `bun.lock` are now tracked together, so a clean checkout can install the pinned dependencies. This matches every sibling. The manifest is version `0.3.0` and no longer contains the `sk-vision-mcp` binary entry, `mcp` script or MCP SDK dependency.

&nbsp;

#### The Published Claim Is Corrected

An earlier commit message in this release claimed the MCP SDK dependency was dropped while the file carrying it was untracked. The claim was true on disk but not reproducible from the repository. The published commit was not amended. This entry corrects that claim. The tracked manifest now contains the state it described.

## Model Behavior

#### Rendered Text Has Limits

The default `moondream2` checkpoint reads rendered text poorly: it recovers codes and digits but garbles surrounding words. `SK_VISION_MODEL=moondream3-preview` is the configuration the benchmark reports used, at the cost of a larger weight download.

&nbsp;

#### Cold Loads Can Skip Evidence

The Devin hook timeout is 60 seconds. A warm model answers in about 13 seconds. A cold first load downloads the weights and exceeds the timeout, so the hook is skipped and the first image-bearing turn after a cold start arrives without evidence.

No upgrade needed.
