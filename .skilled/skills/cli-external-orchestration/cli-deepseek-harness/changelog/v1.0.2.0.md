# v1.0.2.0, The Mistral route is retired

The closed roster is back to two routes, LLM Gateway and OpenCode Go. The Mistral route from v1.0.1.0 failed its first keyed runs, and Mistral work now goes through `cli-mistral-vibe`.

> Spec folder: `specs/cli-external-orchestration/runtime-lifecycle/004-cli-mistral-vibe-creation/003-dsh-mistral-route`

&nbsp;

## What's New at a Glance

- **The Mistral route patch is gone.** `.dsh/patches/route-mistral-deepseek.patch.yml` is deleted, and the preflight refuses a dispatch that names it.
- **Why it failed.** Mistral's OpenAI-compatible endpoint answers 422 to the `store` field. With any reasoning level it also streams the reply as a list of `thinking` chunks, which dsh rejects with `text-delta text must be a string`. Only a run with reasoning off completed, and dsh 0.2.2-rc.3 accepts no native Mistral API.
- **The rules name two routes again.** The `route-patch-required` and `closed-roster` messages and the roster table list LLM Gateway and OpenCode Go only.
- **The reason is recorded.** `references/providers-and-models.md` section 4 lists Mistral among the routes that are never dispatched, with the evidence.

&nbsp;

## Upgrade

Dispatch Mistral models with `cli-mistral-vibe`. The two remaining dsh routes are unchanged.
