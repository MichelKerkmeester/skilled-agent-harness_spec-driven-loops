This v1.0.0.0 entry records the initial DeepSeek Harness mode packet and the runtime, guard, mirror, executor and hub-routing work added since. The harness picks its own model, so each dispatch names an approved route and uses the guarded command shape.

> Spec folder: `specs/cli-external-orchestration/085-cli-deepseek-harness-creation`

&nbsp;

## What's New at a Glance

- **Every dsh dispatch names the full patch set.** It picks one roster route patch, adds the lineage and guards patches, sends the prompt on standard input and reads the JSON event stream.
- **Two routes may run and nothing else.** LLM Gateway and OpenCode Go both serve DeepSeek V4.1 Flash. LLM Gateway `deepseek-v4.1-flash-1017` answered a keyed run on 2026-11-06 and is the default, and a keyed run proved the OpenCode Go endpoint on 2026-11-07 with an API key against `https://opencode.ai/zen/go/v1`.
- **Thirteen rules refuse unsafe dispatches.** They require a roster route, lineage and guards patches and an installed `dsh`, isolate the harness home, reject repository-root runs and keep MCP opt-in. A `$REPO` start folder or home counts as the checkout.
- **Every flag comes from the installed binary.** The command reference was checked against help text captured from the pinned release, and anything only a keyed run can show is marked as unconfirmed.
- **The runtime and routing work now ships.** The `.dsh/` folder, repo-guards plugin, opt-in MCP patch, generated skill, prompt and persona mirrors and fan-out executor are present. The hub registers this mode, and two fan-out lineages completed on the LLM Gateway route. The mode stays experimental while dsh is a release candidate.
- **Interactive sessions reach hook parity.** A session with the guards patch and no lineage patch, such as `dsh web`, gets the skill-advisor brief, `/goal-dsh` with the `dsh_goal` tool, six session-start checks and an autosave at session close. A fan-out leaf keeps every guard and skips those four. The lineage patch also turns off the native `create_goal`, `get_goal` and `update_goal` tools, which need a human turn a leaf never has.
- **More guards and context run on DSH.** The overlay guard refuses a write to a file an overlay owns, context returns after compaction and answers to `ask_user_question` are captured live. `/speckit:save` runs `sweep-dsh.mjs` to recover any answer the live capture missed.
- **The adapters live in the hook library.** All 20 sit under `.skilled/hooks/<concern>/dsh/` or their owning skill's `hooks/dsh/` folder. `.dsh/plugins/repo-guards/adapters/` holds one link per adapter, and `/doctor:runtime-mirrors` checks those links.

&nbsp;

## Upgrade

No migration is required. The hub registers and routes this mode, and the shared runtime carries its executor kind. Set `LLMGATEWAY_API_KEY` in your environment to use the verified route.
