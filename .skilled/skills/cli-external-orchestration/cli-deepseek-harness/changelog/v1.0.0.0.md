This v1.0.0.0 entry records the initial DeepSeek Harness mode packet and the runtime, guard, mirror, executor and hub-routing work added since. The harness picks its own model, so each dispatch names an approved route and uses the guarded command shape.

> Spec folder: `specs/cli-external-orchestration/085-cli-deepseek-harness-creation`

&nbsp;

## What's New at a Glance

- **Every dsh dispatch names the full patch set.** It picks one roster route patch, adds the lineage and guards patches, sends the prompt on standard input and reads the JSON event stream.
- **Two routes may run and nothing else.** LLM Gateway and OpenCode Go both serve DeepSeek V4.1 Flash, and the OpenCode Go endpoint stays unknown until a run with a real key settles it.
- **Twelve rules refuse unsafe dispatches.** They require a roster route, lineage and guards patches, isolate the harness home, reject repository-root runs and keep MCP opt-in.
- **Every flag comes from the installed binary.** The command reference was checked against help text captured from the pinned release, and anything only a keyed run can show is marked as unconfirmed.
- **The runtime and routing work now ships.** The `.dsh/` folder, repo-guards plugin, opt-in MCP patch, generated skill, prompt and persona mirrors and fan-out executor are present. The hub registers this mode, but no keyed route has completed, so it remains experimental.

&nbsp;

## Upgrade

No migration is required. The hub registers and routes this mode, and the shared runtime carries its executor kind. Keyed route results remain unverified.
