This v1.0.0.0 entry records the initial Mistral Vibe mode packet and the runtime folder, guard bundle, fan-out executor kind and session-start hook that ship with it. Vibe picks its model from a config row, so each dispatch names one roster alias and uses the print-mode command shape.

&nbsp;

## What's New at a Glance

- **Every Vibe dispatch runs print mode.** `vibe -p TEXT`, a pipe into a bare `vibe -p`, and `vibe --prompt-file PATH` all run headless. A bare `vibe` and `vibe-acp` are refused, because an unattended run has no terminal and ACP writes no `export.json`.
- **Two aliases may run and nothing else.** `deepseek-flash` and `glm-flash` are both `mistral`-provider rows with `thinking = "max"`. Vibe refuses an unknown id, but its built-in `mistral-medium-3.5` stays selectable unless `allowed_models` lists the two model names, so the preflight is the only gate.
- **Seven rules refuse unsafe dispatches.** They require print mode and `--output-dir`, isolate `VIBE_HOME`, close the roster, reject repository-root runs, require `</dev/null` and require the repository hooks rendered into the home before the run. A `VIBE_HOME` inside the checkout counts as the checkout.
- **The outcome comes from `export.json`.** `--output` carries no exit code and a denied tool call still lets the turn continue, so a run counts as complete only when the record holds `exit_code` 0 and `outcome` `finished`.
- **Every flag comes from a captured run.** The command reference was checked against a 3.1.2 run in this repository or read from the code that writes the record, and anything outside those captures is marked UNKNOWN with its reason.
- **The `.vibe/` runtime folder ships with generated mirrors.** `config.toml` and `SYNC.md` are hand-authored; `agents/`, `skills/` and `prompts/` are generated from `.skilled/agents`, `.skilled/skills` and `.skilled/commands` by the three `sync-*-vibe.cjs` generators, each with a `--check` drift mode. Vibe reads the folder from the checkout root only, and only when that root is trusted.
- **The repo guards run as Vibe hooks.** `.vibe/hooks.toml` declares the guard bundle under `.vibe/plugins/repo-guards/`: the spec gate, the env-secret guard, the dispatch preflight, the overlay guard, the MCP route guard, the git message gate, the deep-loop guard, post-edit quality, the injection screen and session cleanup. Each script imports its runtime-neutral core from `.skilled/`, so a rule changes in one place. A strict deny refuses one call without failing the run, and the deny is read from the session journal. The project file loads only in the trusted checkout, so `render-home-hooks.cjs` writes the same hooks into a dispatch's or a lineage's disposable `VIBE_HOME` with absolute paths, and Vibe loads the home file whatever the cwd.
- **The deep-loop runtime carries a `cli-mistral-vibe` executor kind.** The kind accepts only the two roster aliases, runs Vibe as a fan-out lineage beside a second executor group, gives each lineage its own `VIBE_HOME`, closes stdin and scores the lineage from `export.json`. A lineage runs with `--auto-approve` and with no confinement; the runner renders the repository's guard hooks into its home and passes `VIBE_SPEC_FOLDER`.
- **The hub registers and routes this mode.** `mode-registry.json`, `hub-router.json`, the hub router and the graph metadata carry the entry, and the packet ships its own sibling `ROUTER.md`.
- **One session-start hook carries the goal and the session context.** The single `session_start` entry runs `.skilled/hooks/session-lifecycle/vibe/session-start.mjs`, which composes the bound packet's goal `chat_slice`, the session-prime context, the startup-guard warnings and the stale-dist warning into one `additional_context` value. Each part is skipped when it is empty or fails, so the hook never blocks and always exits 0. A dispatch or a lineage receives the slice through the rendered home hooks when `VIBE_SPEC_FOLDER` names the packet.

&nbsp;

## Upgrade

No migration is required. Set `MISTRAL_API_KEY` in the child's environment and copy the repository's `.vibe/config.toml` into a fresh `VIBE_HOME` before the first dispatch. After a skill, agent or command source changes, rerun the three `sync-*-vibe.cjs` generators, or their `--check` form to confirm the mirrors still match.
