This v1.0.0.0 entry records the initial Mistral Vibe mode packet. It also records the runtime folder, guard bundle, fan-out executor kind and session-start hook. These ship with it. Vibe picks its model from a config row. So each dispatch names one roster alias and uses the print-mode command shape.

&nbsp;

## What's New at a Glance

- Every Vibe dispatch runs print mode.
  - `vibe -p TEXT`, a pipe into a bare `vibe -p` and `vibe --prompt-file PATH` all run headless.
  - A bare `vibe` and `vibe-acp` are refused. Because an unattended run has no terminal and ACP writes no `export.json`.
- Two aliases may run and nothing else.
  - `deepseek-flash` and `glm-flash` are both `mistral`-provider rows with `thinking = "max"`.
  - Vibe refuses an unknown id, but its built-in `mistral-medium-3.5` stays selectable.
  - The built-in `mistral-medium-3.5` stays selectable unless `allowed_models` lists the two model names.
  - So the preflight is the only gate.
- Seven rules refuse unsafe dispatches.
  - The rules require print mode and `--output-dir`.
  - The rules isolate `VIBE_HOME`.
  - The rules close the roster.
  - The rules reject repository-root runs.
  - The rules require `</dev/null`.
  - And the rules require the repository hooks rendered into the home before the run.
  - A `VIBE_HOME` inside the checkout counts as the checkout.
- The outcome comes from `export.json`.
  - `--output` carries no exit code.
  - A denied tool call still lets the turn continue.
  - So a run counts as complete only when the record holds `exit_code` 0 and `outcome` `finished`.
- Every flag comes from a captured run.
  - The command reference was checked against a 3.1.2 run in this repository. Or it was read from the code that writes the record.
  - And anything outside those captures is marked UNKNOWN with its reason.
- The `.vibe/` runtime folder ships with generated mirrors.
  - `config.toml` and `SYNC.md` are hand-authored.
  - `agents/`, `skills/` and `prompts/` are generated from `.skilled/agents`, `.skilled/skills` and `.skilled/commands`.
  - The three `sync-*-vibe.cjs` generators generate them, each with a `--check` drift mode.
  - Vibe reads the folder from the checkout root only, and only when that root is trusted.
- The repo guards run as Vibe hooks.
  - `.vibe/hooks.toml` declares the guard bundle under `.vibe/plugins/repo-guards/`.
  - The guards are the spec gate, the env-secret guard and the dispatch preflight. They include the overlay guard and the MCP route guard.
  - The bundle also holds the git message gate and the deep-loop guard. It also holds post-edit quality, the injection screen and session cleanup.
  - Each script imports its runtime-neutral core from `.skilled/`.
  - So a rule changes in one place.
  - A strict deny refuses one call without failing the run.
  - And the deny is read from the session journal.
  - The project file loads only in the trusted checkout.
  - So `render-home-hooks.cjs` writes the same hooks into a dispatch's or a lineage's disposable `VIBE_HOME`. The paths are absolute.
  - And Vibe loads the home file whatever the cwd.
- The deep-loop runtime carries a `cli-mistral-vibe` executor kind.
  - The kind accepts only the two roster aliases.
  - The kind runs Vibe as a fan-out lineage beside a second executor group.
  - The kind gives each lineage its own `VIBE_HOME`.
  - The kind closes stdin.
  - And the kind scores the lineage from `export.json`.
  - A lineage runs with `--auto-approve` and with no confinement.
  - The runner renders the repository's guard hooks into its home.
  - And the runner passes `VIBE_SPEC_FOLDER`.
- The hub registers and routes this mode.
  - `mode-registry.json`, `hub-router.json`, the hub router and the graph metadata carry the entry.
  - And the packet ships its own sibling `ROUTER.md`.
- One session-start hook carries the goal and the session context.
  - The single `session_start` entry runs `.skilled/hooks/session-lifecycle/vibe/session-start.mjs`.
  - That script composes the bound packet's goal `chat_slice`, the session-prime context, the startup-guard warnings and the stale-dist warning. It puts them into one `additional_context` value.
  - Each part is skipped when it is empty or fails.
  - So the hook never blocks and always exits 0.
  - A dispatch or a lineage receives the slice through the rendered home hooks when `VIBE_SPEC_FOLDER` names the packet.

## Upgrade

No migration is required. Set `MISTRAL_API_KEY` in the child's environment. And copy the repository's `.vibe/config.toml` into a fresh `VIBE_HOME` before the first dispatch. After a skill, agent or command source changes, rerun the three `sync-*-vibe.cjs` generators. Or rerun their `--check` form to confirm the mirrors still match.
