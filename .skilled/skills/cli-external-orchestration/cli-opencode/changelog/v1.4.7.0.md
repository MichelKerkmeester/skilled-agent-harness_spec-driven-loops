This release applies the operator-directed cutover to this skill's MiMo IDs. A documented ID that fails to resolve is a failure this skill has already hit once, which is why its printed IDs now use the `mimo-v2.6` generation spelling.

## What's New at a Glance

- **Every printed `mimo-v2.5`-family ID now uses the `mimo-v2.6` spelling.** Across seven living documents, each ID remains in the same breath as the gateway it names. The case-for-case update includes `MiMo-V2.5-Pro` in prose, dispatch examples, the reference roster, prompt templates, the variant playbook row and frontmatter keywords. Nothing else moved.
- **The pi settings received the matching cutover.** The two `enabledModels` entries changed in the same pass.
- **Providers and variant/effort behavior are unchanged.** The providers (`xiaomi` Direct and `xiaomi-token-plan-ams`) and the variant/effort behavior around those IDs are unchanged. The generation changed, not the route.
- **Historical entries in this folder stay unchanged.** They describe what was true when written, including that the releases they describe shipped the v2.5 IDs.
- **Other IDs and benchmark evidence keep their scope.** The bare IDs `mimo-v2`, `mimo-v2-pro` and `mimo-v2-omni` belong to a different generation, remain served by the catalogs and were untouched. Dated benchmark-evidence citations and profiles elsewhere in the repository still describe the model that was benchmarked.

## Upgrade

No migration required. The operator's resolution check is whether the installed pi's bundled catalogs already serve the `mimo-v2.6` spellings. `cli-opencode` documents these IDs but does not mint them.
