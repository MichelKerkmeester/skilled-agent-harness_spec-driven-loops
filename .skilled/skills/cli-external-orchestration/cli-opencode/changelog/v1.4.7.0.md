The MiMo ids move to the v2.6 generation. Every id this skill prints — the dispatch
examples, the reference roster, the prompt templates, the variant playbook row, even the
frontmatter keywords — now reads the `mimo-v2.6` spelling in the same breath as the
gateway it names, because a documented id that fails at resolution is the failure this
skill has already hit once.

## What Changed

#### Changed

- Every `mimo-v2.5`-family id in the seven living documents became its `mimo-v2.6`
  spelling, case for case (`MiMo-V2.5-Pro` prose included). Nothing else moved.
- The providers (`xiaomi` Direct, `xiaomi-token-plan-ams`) and the variant/effort behavior
  around those ids are unchanged — the generation changed, not the route.

#### Not Changed

- The historical entries in this folder. They record what was true when written, and the
  releases they describe did ship the v2.5 ids.
- The bare `mimo-v2`, `mimo-v2-pro` and `mimo-v2-omni` ids: a different generation, still
  served by the catalogs, deliberately untouched by a `v2.5`-anchored replacement.
- The dated benchmark-evidence citations and profiles elsewhere in the repository: they
  describe the model that was actually benchmarked.

## Why Now

The operator directed the cutover. The matching settings-side half — the two
`enabledModels` entries in the pi settings — moved in the same pass, and whether the
installed pi's bundled catalogs already serve the v2.6 spellings is the operator's
resolution check: this skill documents the id, it does not mint it.
