The DevPass roster carried a DeepSeek id the gateway had switched off. It is the DeepSeek V4.1
Flash line now, and two other claims in that section were checked against the live API rather
than carried forward.

## What Changed

#### Breaking

- **The DevPass DeepSeek row is `llmgateway/deepseek-v4.1-flash`.** It was
  `llmgateway/deepseek-v4-flash-vision-exp`, which the gateway now answers `410` for. The
  replacement is image-capable like the id it replaces, keeps the 1.05M context and 384K output,
  and bills $0.15 in and $0.60 out per million tokens with cached reads at $0.003. That is well
  under the gateway's Premium threshold, so the no-weekly-cap note still holds. This row is the
  DevPass route only. The `opencode-go` and `cline-pass` DeepSeek rows are different routes and
  are untouched.

#### Fixes

- **The effort table carries the documented ladder.** It said the DevPass DeepSeek route had a
  sparse ladder with no `minimal`, `medium` or `xhigh`. All three are accepted, and they fold onto
  the three levels that differ. `minimal` reaches low, `medium` and `xhigh` reach high, and
  `max` reaches max, with `none` disabling thinking and `high` as the default. `ultra` and the
  integer form are rejected on this route.
- **The model count is measured, not remembered.** The gateway fronts 262 ids, not 183. The
  closed-roster rule and the two in-scope rows are unchanged.
- **The bare-id footgun names a live id.** The example and the upstream-rewrite note both moved
  off the deactivated id.

## Verification

- Live gateway probe: bare returns `200`, prefixed returns `400`, the retired id returns `410`,
  and `ultra` plus every integer return `Invalid request parameters`.
- Effort ladder taken from DeepSeek's thinking-mode guide, not inferred from status codes.
- Model listing counted directly from the gateway's own `/v1/models`.
