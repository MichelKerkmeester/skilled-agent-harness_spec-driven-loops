# v1.5.5.0, A Short Routing Summary Over Its Own Router Section

The routing section carried the summary, the binary probe, the guard, a loading table, four pattern notes and the intent dictionaries in one long scroll. It is now seven lines of prose that name what selects the packet, the leaves the hub router gives it, the three use cases and the always-loaded pair. The router blocks moved into the final MACHINE ROUTER section, the pattern notes and the call sequence each became one sentence pointing at the shared helper contract, and no route changed.

> Spec folder: `specs/sk-doc/072-skill-routing-and-clarity/008-cli-and-mcp-hubs` (Level 2)

&nbsp;

## What's New at a Glance

- **The routing summary fits on one screen.** It names what selects the packet, the always-loaded pair, the use cases and the section that holds the rest.
- **The router keeps its own section.** The intent dictionaries, the resource map, the loading levels, the fallback checklist, the probe and the guard all sit in the final MACHINE ROUTER section.
- **One contract for the shared helpers.** The pattern notes and the call sequence point at the single helper document instead of restating it.
- **Nothing routes differently.** The same request loads the same references, and a session already inside OpenCode is still refused unless it asks for a parallel detached session.
