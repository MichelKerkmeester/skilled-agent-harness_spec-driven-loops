# v1.5.5.0, A Short Routing Summary Over Its Own Router Section

The routing section was one long scroll. It held the summary, the binary probe and the guard. It held a loading table, four pattern notes and the intent dictionaries.

It is now seven lines of prose. They name what selects the packet. They name the leaves the hub router gives it. They name the three use cases and the always-loaded pair.

The router blocks moved into the final MACHINE ROUTER section. The pattern notes and the call sequence each became one sentence. Both point at the shared helper contract. No route changed.

&nbsp;

## What's New at a Glance

- **The routing summary fits on one screen.** It names what selects the packet. It names the always-loaded pair and the use cases. It names the section that holds the rest.
- **The router keeps its own section.** The intent dictionaries, the resource map and the loading levels sit in it. So do the fallback checklist, the probe and the guard. All sit in the final MACHINE ROUTER section.
- **One contract for the shared helpers.** The pattern notes and the call sequence point at the single helper document. They do not restate it.
- **Nothing routes differently.** The same request loads the same references. A session already inside OpenCode is still refused. It is refused unless it asks for a parallel detached session.
