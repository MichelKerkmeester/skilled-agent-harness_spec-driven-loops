# cli-opencode v1.4.0.0 — dedicated providers-and-models catalog (new reference leaf, roster de-dup + curation)

**Released**: 2026-07-29
**Status**: Minor feature — a new reference subsystem. Extracts the provider/model/effort facts into a single routable catalog and trims the duplicated roster out of `cli-reference.md` and `SKILL.md`. No default-model, dispatch-envelope, or auth-pre-flight behavior changes.

---

## Summary

The provider roster, model ids, `--variant` effort map, and dispatch shapes had drifted into three places (`SKILL.md`, `references/cli-reference.md` §5, and inline prose), so "which provider, which model, which effort, how to dispatch" had no single authority and every roster edit risked a partial update. This release gives cli-opencode — the multi-provider master of the cli modes — one source of truth: `references/providers-and-models.md`, registered as a routable leaf in the hub `leaf-manifest.json`.

The catalog's provider section is now a heading + table per provider (`deepseek`, `minimax`, `xiaomi`, `openai`) rather than a flat list, so each provider's model ids and notes read at a glance. The published roster was curated down to the providers actually reachable and supported: `deepseek` (v4-pro default / v4-flash), `minimax` Direct (MiniMax-M3), `xiaomi` Direct (mimo-v2.5-pro + -ultraspeed), and OpenAI GPT-5.6 across sol/terra/luna × base/fast/pro. The retired or unsupported entries — `kimi-for-coding`, `zai-coding-plan` (GLM), the Token-Plan providers (`minimax-coding-plan`, `xiaomi-token-plan-ams`), and the plain `gpt-5.6` slugs — were dropped from the catalog roster.

`cli-reference.md` §5 and the `SKILL.md` roster keep only a compact residue plus a pointer to the new catalog; mode-specific mechanics that genuinely belong inline — the provider auth pre-flight, the default-invocation shape, and the child/detached dispatch envelope — were deliberately kept where they were and are not duplicated in the catalog.
