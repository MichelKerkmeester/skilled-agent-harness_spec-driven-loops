# cli-opencode v1.4.0.0: One Catalog for Providers and Models

Minor feature: `cli-opencode` is the multi-provider master of the cli modes. It now has a dedicated catalog. The catalog is the single source of truth for provider and model guidance. That guidance had drifted across `SKILL.md`, `references/cli-reference.md` §5 and inline prose. The drift risked partial roster updates. The catalog brings together the provider roster, model ids, `--variant` effort map and dispatch shapes. The default-model, dispatch-envelope and auth pre-flight behavior are unchanged.

## What's New at a Glance

- **Provider guidance now has a routable catalog.** `references/providers-and-models.md` is registered as a reference leaf in the hub's `leaf-manifest.json`. Each provider has a heading and table. It no longer appears in a flat list.
- **The catalog roster is limited to reachable, supported providers.** `deepseek` lists `v4-pro` as the default and `v4-flash`. `minimax` Direct lists MiniMax-M3. `xiaomi` Direct lists `mimo-v2.5-pro` and `-ultraspeed`. `openai` GPT-5.6 covers sol/terra/luna × base/fast/pro. It drops `kimi-for-coding`, `zai-coding-plan` (GLM) and the Token-Plan providers (`minimax-coding-plan` and `xiaomi-token-plan-ams`). It drops plain `gpt-5.6` slugs. These are retired or unsupported.
- **The existing rosters now point to the catalog.** `SKILL.md` keeps the default and common alternates. `references/cli-reference.md` §5 keeps a compact residue. It points to the full roster, GPT-5.6 slug grid and per-provider `--variant` map.
- **Guidance that belongs in place stays authoritative there.** The provider auth pre-flight, default-invocation shape and child/detached dispatch envelope remain inline. They are not duplicated in the catalog. `references/cli-reference.md` remains authoritative for the flag surface and provider auth pre-flight.
- **The skill and README versions align at 1.4.0.0.** The `SKILL.md` frontmatter version moves from `1.3.15.3` to `1.4.0.0`. The `README.md` frontmatter version moves to `1.4.0.0`.
