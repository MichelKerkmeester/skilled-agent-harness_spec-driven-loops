# cli-opencode v1.4.0.0: One Catalog for Providers and Models

Minor feature: `cli-opencode`, the multi-provider master of the cli modes, now has a dedicated catalog as the single source of truth for provider and model guidance that had drifted across `SKILL.md`, `references/cli-reference.md` §5 and inline prose, risking partial roster updates. It brings together the provider roster, model ids, `--variant` effort map and dispatch shapes. The default-model, dispatch-envelope and auth pre-flight behavior are unchanged.

> Spec folder: `.opencode/specs/cli-external-orchestration/033-per-mode-provider-model-reference/`

## What's New at a Glance

- **Provider guidance now has a routable catalog.** `references/providers-and-models.md` is registered as a reference leaf in the hub's `leaf-manifest.json`. Each provider has a heading and table instead of appearing in a flat list.
- **The catalog roster is limited to reachable, supported providers.** `deepseek` lists `v4-pro` as the default and `v4-flash`. `minimax` Direct lists MiniMax-M3. `xiaomi` Direct lists `mimo-v2.5-pro` and `-ultraspeed`. `openai` GPT-5.6 covers sol/terra/luna × base/fast/pro. It drops `kimi-for-coding`, `zai-coding-plan` (GLM), the Token-Plan providers (`minimax-coding-plan` and `xiaomi-token-plan-ams`) and plain `gpt-5.6` slugs as retired or unsupported.
- **The existing rosters now point to the catalog.** `SKILL.md` keeps the default and common alternates. `references/cli-reference.md` §5 keeps a compact residue and points to the full roster, GPT-5.6 slug grid and per-provider `--variant` map.
- **Guidance that belongs in place stays authoritative there.** The provider auth pre-flight, default-invocation shape and child/detached dispatch envelope remain inline and are not duplicated in the catalog. `references/cli-reference.md` remains authoritative for the flag surface and provider auth pre-flight.
- **The skill and README versions align at 1.4.0.0.** The `SKILL.md` frontmatter version moves from `1.3.15.3` to `1.4.0.0` and the `README.md` frontmatter version moves to `1.4.0.0`.
