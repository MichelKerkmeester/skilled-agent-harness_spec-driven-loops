v1.3 adds a credential check before dispatch, so the AI asks the user before choosing another model rather than silently substituting one they have not approved. It restores `opencode-go/deepseek-v4-pro` with `--variant high` as the `cli-opencode` default and removes `github-copilot` from the skill's provider set.

The release updates default-position invocations, provider-auth guidance and the multi-provider playbook. It also refreshes the skill's provider metadata.

> Spec folder: `specs/051-cli-opencode-providers/` (Level 1)

## Why This Release

Provider Auth Pre-Flight (Smart Fallback) makes the ASK-not-substitute decision explicit in the three credential states.

## What's New at a Glance

- **`opencode-go/deepseek-v4-pro` with `--variant high` is the default again.** The documented v1.2 default was `github-copilot/gpt-5.4`.
- **`cli-opencode` documents `opencode-go` and `deepseek` as its two providers.** `deepseek` remains the direct API option outside the gateway.
- **Provider Auth Pre-Flight (Smart Fallback) adds a credential check before dispatch.** Its three states route to the default or a user prompt.

- **Twenty-eight other playbook entries replace Copilot model examples.** The changes cover eight playbook sections.

## Provider Defaults

#### Restore the OpenCode Go Default

Default-position examples now use the restored command in `SKILL.md`, `README.md`, all four `references/*.md` files and `assets/prompt-templates.md`. Within `SKILL.md`, this also updates the §3 Default Invocation block, the override and Model Selection tables, Agent Delegation patterns and ALWAYS rule 3. Seven Essential Commands examples in `SKILL.md` were included in the update. The OpenCode Go gateway routes DeepSeek and other open models. DeepSeek's reasoning model provides elevated reasoning at low cost without per-provider OAuth friction.

&nbsp;

#### Keep Direct DeepSeek Access

The `deepseek` provider calls DeepSeek's API directly and bypasses the OpenCode Go gateway. The direct DeepSeek API surface stays unchanged.

&nbsp;

#### Keep Caller Names Distinct

The `cli-copilot` sibling skill remains. `Copilot` mentions in cross-AI handback prose also remain because they identify external-runtime callers, not the removed provider.

&nbsp;

#### Remove the GitHub Copilot Provider

`github-copilot/` is fully removed as a `cli-opencode` provider. **Breaking:** Operators who used `github-copilot/<id>` should migrate to an equivalent `opencode-go/<id>` when the upstream model is available through the gateway or log in to `opencode-go` or `deepseek` before their first dispatch.

## Provider Authentication

#### Choose Before Dispatch

`SKILL.md` adds the pre-dispatch auth check in a new §3 subsection. ALWAYS rule 11 requires a one-shot `bash` check at session start, before the first dispatch. The check runs `opencode providers list` and captures the `OPENCODE_GO_OK` and `DEEPSEEK_OK` flags. The decision table routes `default-available` to the default and prompts the user in the other two states. In `default-missing-fallback-ready`, the prompt offers A to use the configured fallback, B to log in to the default or C to name a different model. In `both-missing`, the user prompt presents a login-command menu.

&nbsp;

#### Retry After Authentication Errors

An authentication error during dispatch clears the saved credential result, then the pre-flight runs again before retry. The Error Handling table sends `provider/model not found` and `401 Unauthorized` back to the same pre-flight.

## Upgrade Notes

- **Adopt.** Replace the documented v1.2 invocation with the v1.3 command.

```bash
# Old (v1.2):
opencode run --model github-copilot/gpt-5.4 --variant high --agent general --format json --dir <repo>

# New (v1.3):
opencode run --model opencode-go/deepseek-v4-pro --variant high --agent general --format json --dir <repo>
```

- **Repoint.** Operators previously relying on `github-copilot/<id>` should migrate to an equivalent `opencode-go/<id>` when the upstream model is available through the gateway or log in before the first dispatch. Gateway model ID examples are `opencode-go/glm-5.1` and `opencode-go/kimi-k2.6`. The login commands are `opencode providers login opencode-go` and `opencode providers login deepseek`. Operators expecting a silent fallback should explicitly approve option A in the prompt.
