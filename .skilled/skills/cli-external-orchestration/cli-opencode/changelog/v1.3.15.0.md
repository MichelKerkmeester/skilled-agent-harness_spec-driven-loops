# v1.3.15.0, OpenCode Go Removal

This logic update changes `cli-opencode`'s default provider from the OpenCode Go gateway to the direct DeepSeek API. It also removes the gateway from skill logic while preserving the RM-8 incident record and leaving gateway-specific manual-test scenarios for a separate decision.

## Why This Release

The OpenCode Go gateway routes DeepSeek and other open models through one shared credit pool. A live dispatch returned `401 Insufficient balance` (`CreditsError`), and because the skill defaulted to the gateway, the failure surfaced mid-run rather than at pre-flight. Routing the default through the direct DeepSeek API removes the gateway as a single point of billing failure.

---

## What's New at a Glance

- **The provider list drops from eight to seven.** The direct DeepSeek API takes the default slot.
- **Gateway model choices are narrowed.** Direct `kimi-for-coding/k2p7` replaces gateway `kimi-k2.6`.
- **The `manual-testing-playbook/` suite still references `opencode-go`.** It includes two scenarios dedicated to the gateway path.

---

## Provider Routing

#### Direct DeepSeek Default

The default changes from `opencode-go/deepseek-v4-pro --variant high` to `deepseek/deepseek-v4-pro --variant high`. The underlying model and variant are unchanged, while the provider and billing pool change to the direct DeepSeek API and a separately funded credential. **Breaking:** The direct default requires the `deepseek` provider credential. If it is not configured, pre-flight asks the user rather than silently falling back.

&nbsp;

#### Gateway References Leave the Workflow

The `opencode-go` gateway is removed from every operational surface of the skill. The provider-auth pre-flight and decision tree no longer reference it, and `OPENCODE_GO_OK` is removed. Model-selection tables, prompt templates, examples and keywords no longer reference the gateway. The fallback templates are switched to the direct DeepSeek default.

&nbsp;

#### Fallback Providers Stay Available

Fallback providers remain `openai`, `xiaomi`, `kimi-for-coding` and `minimax`. The `minimax` fallback is available through Token Plan and Direct API.

---

## Model Choices

#### Gateway-Only Models Are Removed

`glm-5.1`, `glm-5.2` and `qwen3.6-plus` are no longer offered because they have no direct-provider equivalents. The gateway duplicate `deepseek-v4-flash` and the free `mimo-v2.5-free` gateway path are also removed.

---

## Manual Testing

#### Gateway Scenarios Need a Decision

The `manual-testing-playbook/` test suite still references `opencode-go`, including `07--prompt-templates/deepseek-v4-via-opencode-go-with-sk-prompt-models.md` and `kimi-k2-6-via-opencode-go-with-sk-prompt-models.md`, which are dedicated to the gateway path. These scenarios exercise a now-removed provider and need a separate delete-or-rewrite decision.

---

## Historical Records

#### RM-8 Keeps Its Provenance

The RM-8 destructive-scope-violation incident is recorded in `SKILL.md` (ALWAYS rule 13) and `references/destructive-scope-violations.md`. The record still names the `opencode-go/deepseek-v4-pro` dispatch that deleted 44 files on 2026-05-04. Removing this factual incident record would erase the provenance of the safety lesson. Prior changelog entries are unchanged.
