# v1.3.15.0, OpenCode Go Removal

This logic update changes `cli-opencode`'s default provider.

- It moves from the OpenCode Go gateway to the direct DeepSeek API.
- It also removes the gateway from skill logic.

The RM-8 record stays and gateway scenarios are left for a decision.

- The RM-8 incident record stays.
- Gateway-specific manual-test scenarios are left for a separate decision.

> [!IMPORTANT]
> 1 change can break an existing setup. Read it before you update.
>
> 1. The direct default requires the `deepseek` provider credential. [Direct DeepSeek Default](#c-direct-deepseek-default)

&nbsp;

## Why This Release

The OpenCode Go gateway routes DeepSeek and other open models through one shared credit pool. A live dispatch returned `401 Insufficient balance` (`CreditsError`).

- The skill defaulted to the gateway.
- So the failure surfaced mid-run rather than at pre-flight.
- Routing the default through the direct DeepSeek API removes the gateway as a single point of billing failure.

## Provider Routing

The `opencode-go` gateway is removed from every operational surface of the skill.

#### Direct DeepSeek Default <a id="c-direct-deepseek-default"></a>

> [!WARNING]
> The direct default requires the `deepseek` provider credential.
>
> If it is not configured, pre-flight asks the user rather than silently falling back.
>
> Run `opencode providers login deepseek` if the `deepseek` provider credential is not configured.

- The default changes from `opencode-go/deepseek-v4-pro --variant high` to `deepseek/deepseek-v4-pro --variant high`.
- The underlying model and variant are unchanged.
- The provider and billing pool change to the direct DeepSeek API and a separately funded credential.

#### Gateway References Leave the Workflow <a id="c-gateway-references-leave-the-workflow"></a>

- The provider-auth pre-flight and decision tree no longer reference it.
- `OPENCODE_GO_OK` is removed.
- Model-selection tables, prompt templates, examples and keywords no longer reference the gateway.
- The fallback templates are switched to the direct DeepSeek default.

#### Fallback Providers Stay Available <a id="c-fallback-providers-stay-available"></a>

- Fallback providers remain `openai`, `xiaomi`, `kimi-for-coding` and `minimax`.
- The `minimax` fallback is available through Token Plan and Direct API.

&nbsp;

## Model Choices

`glm-5.1`, `glm-5.2` and `qwen3.6-plus` are no longer offered.

#### Gateway-Only Models Are Removed <a id="c-gatewayonly-models-are-removed"></a>

- They have no direct-provider equivalents.
- The gateway duplicate `deepseek-v4-flash` is also removed.
- So is the free `mimo-v2.5-free` gateway path.

&nbsp;

## Manual Testing

The `manual-testing-playbook/` test suite still references `opencode-go`.

#### Gateway Scenarios Need a Decision <a id="c-gateway-scenarios-need-a-decision"></a>

- That includes `07--prompt-templates/deepseek-v4-via-opencode-go-with-sk-prompt-models.md` and `kimi-k2-6-via-opencode-go-with-sk-prompt-models.md`.
- Both are dedicated to the gateway path.
- These scenarios exercise a now-removed provider.
- They need a separate delete-or-rewrite decision.
