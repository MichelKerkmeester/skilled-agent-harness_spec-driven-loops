cli-opencode v1.2.0.0 reshapes its documented provider choices. It centers them on the providers registered for the operator. It sets a Copilot default. It narrows the named Copilot and direct DeepSeek models. It updates the multi-provider playbook.

## Why This Release

The previous guidance named provider prefixes outside the operator's authentication set. It also used a default that depended on separate provider login.

## What's New at a Glance

- **Copilot now supplies the documented default.** The default invocation uses `github-copilot/gpt-5.4`. It runs with high variant effort.
- **The documented provider set has three prefixes.** It covers `github-copilot`, `opencode-go` and `deepseek`.
- **The named model choices are narrower.** The skill names two Copilot models and two direct DeepSeek models.
- **The multi-provider playbook follows the lineup.** Its scenario names and variant caps now reflect the documented provider choices.

---

## Provider Defaults

#### Copilot Takes the Default

The default invocation changed from `opencode-go/deepseek-v4-pro` to `github-copilot/gpt-5.4 --variant high`. For active subscribers, Copilot is pre-authenticated. It exposes the broadest model surface under one OAuth token. That surface includes Claude and GPT variants. This removes the per-provider login friction that came with the previous default.

`gpt-5.4` accepts `minimal / low / medium / high / xhigh`. So the existing `--variant high` setting carries over without behavioral change. During the release, the default moved from `gpt-5.5` to `gpt-5.4`. That matches the `cli-copilot` default and operator preference. `opencode models` confirmed that `github-copilot/gpt-5.4` and `github-copilot/gpt-5.5` are valid model ids.

**Breaking:** Callers using the prior invocation must replace its model value with the Copilot default.

&nbsp;

#### Documented Providers Match Access

The operator's registered providers were OpenAI, GitHub Copilot, DeepSeek and OpenCode Go. `anthropic/` and `google/` were not reachable through that authentication setup. The documented prefixes are now `github-copilot`, `opencode-go` and `deepseek`. They replace the previous Anthropic, OpenAI, Google, `opencode-go` and DeepSeek mix.

Within `cli-opencode`, `--model anthropic/...`, `--model openai/...` and `--model google/...` were removed. They were removed from invocation strings, override tables, model-selection tables, FAQ entries and the variant matrix. **Breaking:** Operators using those prefixes should override per invocation when separately authenticated or migrate to the equivalent `github-copilot/<id>` model.

## Model Choices

#### Copilot Models Stay Focused

The skill names `gpt-5.4` as the default. It names `claude-sonnet-4.6` as the Anthropic alternative for code review and balanced reasoning. The full Copilot lineup remains available through `--model github-copilot/<id>` overrides. That lineup includes Opus, Haiku, additional GPT models and Grok variants. It is not listed in the skill's tables.

&nbsp;

#### Direct DeepSeek Stays Separate

The direct DeepSeek API bypasses `opencode-go`. `deepseek/` and `opencode-go/` remain independent surfaces rather than aliases. The direct API keeps `deepseek-v4-pro` for reasoning effort. It keeps `deepseek-v4-flash` as its non-reasoning latency sibling. The model-selection tables and override examples drop `deepseek/deepseek-reasoner` and `deepseek/deepseek-chat`.

## Playbook and Documentation

#### Multi-provider Scenarios Are Updated

The `manual-testing-playbook/03--multi-provider/` section replaces its OpenCode Go default and OpenAI model scenarios with Copilot scenarios. It then adds a direct DeepSeek API scenario. The Copilot default scenario now uses `--model github-copilot/gpt-5.4 --variant high`. It uses a multi-dimensional architecture trade-off prompt. The Copilot Claude Sonnet alternative scenario covers the Anthropic alternative under Copilot OAuth. It uses a TypeScript helper code-generation prompt and `tsc` validation. The direct DeepSeek API scenario covers the direct API that bypasses the `opencode-go` gateway. It uses a small implementation-planning prompt.

The `004-variant-levels-comparison.md` table drops Anthropic, OpenAI and Google rows. It now lists `github-copilot/gpt-5.4` at `xhigh`. It lists `github-copilot/claude-sonnet-4.6` at `max`. It lists `opencode-go/deepseek-v4-pro` as provider-specific. It lists `deepseek/deepseek-v4-pro` as accepting reasoning effort.

## Upgrade Notes

- **Adopt.** Old (v1.1): `opencode run --model opencode-go/deepseek-v4-pro --variant high --agent general --format json --dir <repo>`. New (v1.2): `opencode run --model github-copilot/gpt-5.4 --variant high --agent general --format json --dir <repo>`. The new default is reachable in environments where `opencode providers list` reports `github-copilot` as authenticated. So verify that before the first dispatch. With an active Copilot subscription, use `github-copilot/claude-sonnet-4.6` for Anthropic. Or use `github-copilot/gpt-5.4` for OpenAI.
- **Repoint.** **Breaking:** External scripts that reference `001-opencode-go-default-deepseek.md` must use `001-copilot-default-gpt-5-4.md`. References to `002-openai-gpt-5-5.md` must use `002-copilot-claude-sonnet-4-6.md`. Scripts referencing the multi-provider scenarios must use `003-deepseek-direct-api.md` for the new direct API scenario.
- **Drop.** To keep using `anthropic/`, `openai/` or `google/` with a direct provider, run `opencode providers login <provider>`. Then continue using the original prefix per invocation.
