# v1.5.9.0, Workers stay in their worktree

An OpenCode worker you start in a linked worktree now stays there. OpenCode tells the model its working directory from the inherited `PWD`. So a worker spawned from Node read files in your main checkout instead. It sometimes wrote files there too.

&nbsp;

## What's New at a Glance

- The worktree rule says what holds.
  - Rule 15's worktree layer now says this.
  - A Node `spawn()` with `cwd` must also set `PWD`.
  - The prompt must carry the repository-root line.
- The dispatch preamble opens with the repository root.
  - The preamble tells the model to ignore the "Workspace root folder" OpenCode names.
  - That folder is the repository's first checkout.
- A probe checks a dispatch shape.
  - `scripts/probe-worktree-confinement.cjs` runs one read-only worker in a throwaway worktree.
  - The probe exits 1 when a tool path leaves it.
  - The probe costs one model run.

&nbsp;

## Upgrade

A script that spawns `opencode run` from Node with `cwd` passes `env: { ...process.env, PWD: cwd }`. The script also puts the repository-root line at the top of its prompt. That line comes from the child-dispatch preamble.
