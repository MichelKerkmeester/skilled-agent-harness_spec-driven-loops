# v1.5.9.0, Workers stay in their worktree

An OpenCode worker you start in a linked worktree now stays there. OpenCode tells the model its working directory from the inherited `PWD`, so a worker spawned from Node read, and sometimes wrote, files in your main checkout instead.

> Spec folder: `specs/cli-external-orchestration/087-opencode-worktree-confinement`

&nbsp;

## What's New at a Glance

- **The worktree rule says what holds.** Rule 15's worktree layer now says a Node `spawn()` with `cwd` must also set `PWD`, and the prompt must carry the repository-root line.
- **The dispatch preamble opens with the repository root.** It tells the model to ignore the "Workspace root folder" OpenCode names, which is the repository's first checkout.
- **A probe checks a dispatch shape.** `scripts/probe-worktree-confinement.cjs` runs one read-only worker in a throwaway worktree and exits 1 when a tool path leaves it. It costs one model run.

&nbsp;

## Upgrade

A script that spawns `opencode run` from Node with `cwd` passes `env: { ...process.env, PWD: cwd }` and puts the repository-root line from the child-dispatch preamble at the top of its prompt.
