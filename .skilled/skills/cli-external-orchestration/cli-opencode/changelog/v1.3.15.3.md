# cli-opencode v1.3.15.3, Content Hygiene Fixes

This documentation and instruction-content release corrects five pre-existing `cli-opencode` content bugs that degraded trust in its instructions. The whole-program deep review (`.opencode/specs/skilled-agent-orchestration/125-cli-external-parent/review/review-report.md` §3 WS-A) and Fable-5 finding `A-P1-3` surfaced the bugs, none of which was caused by v1.3.15.2's GPT-5.6 model-roster rename. This release builds on the rename rather than reverting it, leaves the bare tier, Sol/Terra/Luna families, `gpt-5.6-sol` flagship default, model roster, providers and prior changelog entries untouched and changes no runtime script or automation code.

> Spec folder: `.opencode/specs/skilled-agent-orchestration/125-cli-external-parent`

## What's New at a Glance

- **Rule 16 now scopes cleanup to its captured process.** Its former blanket `pkill -9 -f "opencode run"` matched every such process on the machine, including external operator-owned sessions that ALWAYS Rule 5 protects. Rule 5 says not to auto-kill those sessions, and the 2026-05-23 operator directive excludes `opencode run` from `pkill`. Rule 16 now captures the dispatched process's PID (process ID) at launch and uses the direct-PID form `kill -9 "$OC_PID"; pkill -9 -P "$OC_PID"` (also written `kill -9 "$OC_PID" 2>/dev/null; pkill -9 -P "$OC_PID" 2>/dev/null`) to kill that PID and its children. Its inline note says to kill only the dispatch you started, by captured PID, never with a blanket `pkill -9 -f "opencode run"` pattern, and ends `see Rule 5.` This preserves cleanup of the dispatcher's own orphans between single-dispatch-discipline runs while changing only the kill scope. The process-group form `kill -9 -- -"$OC_PID"` silently targeted a nonexistent group because a backgrounded `opencode run &` is not a process-group leader without `setsid` or `set -m`. If an intermediate shell wrapper launches it, `$!` is the wrapper's PID, so scripted cleanup must capture the actual `opencode run` PID.
- **The sibling-boundary table now lists only the live `cli-*` skills.** It removes a duplicate `cli-opencode` row left behind by the packet-122 `cli-codex` deprecation, which carried the retired skill's OpenAI description of sandboxed coding, repo analysis, PR review and live web research. The table now lists `cli-opencode` / OpenCode and `cli-claude-code` / Anthropic. The sentence that the `cli-*` skills each dispatch to a different provider and never overlap needed no change and still holds. Related but out-of-scope drift remains in `graph-metadata.json`: its `causal_summary` still says `the four sibling cli-* skills`, last updated 2026-06-03 before `cli-codex` retired. It was outside the five findings and was left untouched.
- **The parallel-detached quick start now confirms before sharing.** README Step 4's `opencode run --share --port 4096 …` example previously omitted that `--share` requires prior operator confirmation. The new one-line note directly above the code block says `--share` publishes the session and exposes its contents at a browser-accessible URL, so it asks for operator confirmation first, as the `share-requires-confirmation` `hard_rule` requires. This matches SKILL.md's NEVER Rule 2 / CHK-033.
- **The default-dispatch recipe puts the agent request in the prompt body.** README Step 3 removes top-level `--agent context` because current OpenCode rejects a top-level `--agent` and ALWAYS Rule 3 forbids it. The old recipe also contradicted the next README sentence, which says `context` is a subagent and should not be passed as a top-level `--agent`. The new prompt says: `Act as a context-retrieval agent: search memory context and return the top findings.`
- **The six corrupted manual-testing-playbook links use the real filenames.** A concurrent session's blanket `sk-prompt-models` → `sk-prompt/prompt-models` find/replace split a filename segment and turned links into nonexistent `.../with-sk-prompt/prompt-models.md` paths. The repairs cover the CO-035 and CO-036 Feature-File links, both PROMPT TEMPLATES index-list links and one self-reference trailer in each DeepSeek and Kimi file. The corrected targets use `07--prompt-templates/deepseek-v4-direct-with-sk-prompt-models.md` and `07--prompt-templates/kimi-k2-7-direct-with-sk-prompt-models.md`. The descriptive prose `through sk-prompt/prompt-models + sk-prompt` remains unchanged because it is prose, not a filename, and neither file was renamed.
