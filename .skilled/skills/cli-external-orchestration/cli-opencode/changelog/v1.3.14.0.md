# v1.3.14.0: Xiaomi Direct API and MiniMax M2.7 Removal

This is a documentation-only update. It revises OpenCode's provider, model and routing guidance.

&nbsp;

## What's New at a Glance

- Xiaomi Direct API uses pay-per-token billing.
  - The `xiaomi` provider uses `xiaomi/mimo-v2.5-pro`.
  - That is the same model as the `xiaomi-token-plan-ams` Token Plan provider, under different billing.
  - Its endpoint is provider-managed.
  - It has no documented base URL, so do not fabricate one.
- MiMo routing covers both billing paths.
  - `XIAOMI_DIRECT_OK` detects `xiaomi` and excludes `xiaomi-token-plan-ams`.
  - `XIAOMI_DIRECT_OK` has four cases.
  - The four cases are Token Plan default, Token Plan missing, Direct API requested and Direct API missing.
- MiniMax-M3 is the sole model for both MiniMax billing paths.
  - All `MiniMax-M2.7` and `-highspeed` references are removed.
  - The `minimax-coding-plan/MiniMax-M2.7-highspeed` fallback is gone.
  - `minimax/MiniMax-M2.7` is now `minimax/MiniMax-M3`.
  - The 120/003 TIDD-EC + dense contract was originally benchmarked on M2.7.
  - The 120/003 TIDD-EC + dense contract carries forward to M3 pending re-benchmark.
- Provider and variant phrases match the release.
  - `graph-metadata.json` removes `minimax-2.7`, `-highspeed` variants, `m3-highspeed` and `minimax-m3-highspeed` trigger phrases.
  - `graph-metadata.json` adds `xiaomi-api`, `xiaomi api`, `xiaomi direct` and `xiaomi/mimo-v2.5-pro`.

&nbsp;

## Upgrade

To use Xiaomi Direct API, sign in with `opencode providers login xiaomi`. Confirm the live model ID with `opencode models xiaomi` before dispatch. Use the Token Plan invocation flags for Direct API: `--variant high` and omit `--agent`. Choose `MiniMax-M3` for `minimax-coding-plan` and `minimax`.
