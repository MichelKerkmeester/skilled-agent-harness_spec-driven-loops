# v1.3.14.0: Xiaomi Direct API and MiniMax M2.7 Removal

This documentation-only update revises OpenCode's provider, model and routing guidance.

## What's New at a Glance

- **Xiaomi Direct API uses pay-per-token billing.** The `xiaomi` provider uses `xiaomi/mimo-v2.5-pro`, the same model as the `xiaomi-token-plan-ams` Token Plan provider, under different billing. Its endpoint is provider-managed and has no documented base URL, so do not fabricate one.
- **MiMo routing covers both billing paths.** `XIAOMI_DIRECT_OK` detects `xiaomi` while excluding `xiaomi-token-plan-ams`. Its four cases are Token Plan default, Token Plan missing, Direct API requested and Direct API missing.
- **MiniMax-M3 is the sole model for both MiniMax billing paths.** All `MiniMax-M2.7` and `-highspeed` references are removed: the `minimax-coding-plan/MiniMax-M2.7-highspeed` fallback is gone and `minimax/MiniMax-M2.7` is now `minimax/MiniMax-M3`. The 120/003 TIDD-EC + dense contract, originally benchmarked on M2.7, carries forward to M3 pending re-benchmark.
- **Provider and variant phrases match the release.** `graph-metadata.json` removes `minimax-2.7`, `-highspeed` variants, `m3-highspeed` and `minimax-m3-highspeed` trigger phrases. It adds `xiaomi-api`, `xiaomi api`, `xiaomi direct` and `xiaomi/mimo-v2.5-pro`.

## Upgrade

To use Xiaomi Direct API, sign in with `opencode providers login xiaomi` and confirm the live model ID with `opencode models xiaomi` before dispatch. Use the Token Plan invocation flags for Direct API: `--variant high` and omit `--agent`. Choose `MiniMax-M3` for `minimax-coding-plan` and `minimax`.
