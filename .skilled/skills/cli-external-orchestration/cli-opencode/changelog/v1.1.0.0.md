cli-opencode now defaults to a model registered in the operator's OpenCode authentication, corrects long-standing primary-versus-subagent guidance and routes playbook scenarios through a primary agent. The playbook filename and its creation template now use the same lowercase canonical name.

> Spec folder: `.opencode/specs/system-spec-kit/026-graph-and-context-optimization/011-manual-testing-playbook-coverage-and-run/` (Level 3)

## Why This Release

Every cli-opencode dispatch failed at provider lookup because the former model default was absent from the operator's configured authentication. Agent documentation described subagents as directly callable, a long-standing confusion with OpenCode's primary-agent surface. The playbook's creation template still prescribed an uppercase name after the root playbook had been renamed.

## What's New at a Glance

- **The canonical default is `opencode-go/deepseek-v4-pro --variant high`.** It uses the opencode-go subscription at high reasoning effort.
- **SKILL.md §3 now separates primary agents and subagents in two tables.** The tables distinguish agents that can be called directly from those dispatched by a primary.
- **Five playbook scenarios now route subagents through `orchestrate`.** This follows OpenCode's primary-agent routing.
- **The playbook name is now `manual_testing_playbook.md`.** The creation template also prescribes the lowercase canonical name.

---

## Model Defaults

#### Use the Registered Default

The former default, `anthropic/claude-opus-4-7`, was not registered in the operator's environment. Its configured providers were copilot, opencode-go, deepseek and openai. The opencode-go provider/model identifier follows the `opencode-go/<model-id>` format, as described in the opencode-go documentation.

The opencode-go DeepSeek route honors `--variant`, including `high` and `minimal`.

## Agent Routing

#### Identify Callable Agents

Earlier guidance described nine agents as callable with `--agent`, though only four are primary and directly callable. `general` and `plan` are OpenCode built-ins. `orchestrate` is `mode=primary`. `multi-ai-council` is `mode=all`.

The other eight agents are in `mode=subagent` and dispatch through the Task tool from a primary:

- `context`
- `debug`
- `review`
- `write`
- `deep-research`
- `deep-review`
- `deep-agent-improvement`
- `prompt-improver`

&nbsp;

#### Route Scenarios Through Orchestrate

OpenCode warns that a subagent is not a primary agent when a scenario invokes it directly, then falls back to the default agent. Scenarios CO-014 (`context`), CO-015 (`review`), CO-016 (`write`), CO-032 (`deep-research`) and CO-033 (`deep-review`) now use `--agent orchestrate` with the prompt prefix `"Use the <subagent> subagent to ..."`.

CO-013 (`general`), CO-017 (`multi-ai-council`) and CO-034 (`orchestrate`) already used primary agents and were correctly routed. The run encountered real OpenCode runtime hangs on `--agent write`. This was a separate runtime issue rather than a skill-level issue. `openai/gpt-5.5` was unavailable because it was not in the registry. The Google provider was not authenticated.

## Playbook Naming

#### Keep the Lowercase Name

The playbook was renamed from `MANUAL_TESTING_PLAYBOOK.md` to `manual_testing_playbook.md`. Its 120 scenario-file cross-references now use the lowercase canonical name.

The `manual_testing_playbook_creation.md` template previously prescribed the uppercase name. It now prescribes `manual_testing_playbook.md`, so future `/create:testing-playbook` runs use that name by default.

## Upgrade Notes

- **Keep the documented default invocation.** Callers using `opencode run --model opencode-go/deepseek-v4-pro --variant high --agent general --format json` need no script changes.
- **Restore or override Anthropic access.** **Breaking:** Operators who relied on `anthropic/claude-opus-4-7` as the default should either run `opencode auth login anthropic` or pass `--model anthropic/claude-opus-4-7` per invocation.
- **Check the assumed authentication path.** The opencode-go subscription is the assumed default. Use `opencode auth list` to confirm `opencode-go` is registered.
- **Reroute direct subagent calls.** **Breaking:** Callers using `opencode run --agent <subagent>` directly must instead use `opencode run --agent orchestrate "Use the <subagent> subagent to ..."`.
