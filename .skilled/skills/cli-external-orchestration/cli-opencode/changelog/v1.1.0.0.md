# v1.1.0.0, Model Defaults, Agent Routing and Playbook Naming

cli-opencode now defaults to a model registered in the operator's OpenCode authentication.

- The former default was absent from configured authentication.
- The new default uses the opencode-go subscription at high reasoning effort.
- Operators relying on Anthropic access should restore or override it.

Agent guidance and playbook scenarios now follow OpenCode's primary-agent routing.

- Primary-versus-subagent guidance was a long-standing confusion.
- Five playbook scenarios now route subagents through `orchestrate`.
- Only four agents are primary and directly callable.

The playbook filename and creation template now use one lowercase canonical name.

- The playbook was renamed to `manual_testing_playbook.md`.
- Cross-references and the creation template now use the lowercase name.

> [!IMPORTANT]
> 2 changes can break an existing setup. Read these before you update.
>
> 1. Operators who relied on `anthropic/claude-opus-4-7` as the default should restore or override access. [Use the Registered Default](#c-use-the-registered-default)
> 2. Callers using `opencode run --agent <subagent>` directly must reroute through orchestrate. [Route Scenarios Through Orchestrate](#c-route-scenarios-through-orchestrate)

&nbsp;

## Why This Release

This release closes gaps in model defaults, agent guidance and playbook naming.

- Every cli-opencode dispatch failed at provider lookup.
- That is because the former model default was absent from the operator's configured authentication.
- Agent documentation described subagents as directly callable.
- That was a long-standing confusion with OpenCode's primary-agent surface.
- The playbook's creation template still prescribed an uppercase name.
- This came after the root playbook had been renamed.

## Model Defaults

Model defaults now match what the operator's authentication registers.

#### Use the Registered Default <a id="c-use-the-registered-default"></a>

> [!WARNING]
> Restore or override Anthropic access. Operators who relied on `anthropic/claude-opus-4-7` as the default should either run `opencode auth login anthropic` or pass `--model anthropic/claude-opus-4-7` per invocation.

- The canonical default is `opencode-go/deepseek-v4-pro --variant high`.
- It uses the opencode-go subscription at high reasoning effort.
- The former default, `anthropic/claude-opus-4-7`, was not registered in the operator's environment.
- Its configured providers were copilot, opencode-go, deepseek and openai.
- The opencode-go provider/model identifier follows the `opencode-go/<model-id>` format.
- The opencode-go documentation describes that format.
- The opencode-go DeepSeek route honors `--variant`, including `high` and `minimal`.

&nbsp;

## Agent Routing

Agent routing now follows OpenCode's primary-agent routing. The guidance separates primary agents from subagents.

#### Identify Callable Agents <a id="c-identify-callable-agents"></a>

- SKILL.md §3 now separates primary agents and subagents in two tables.
- The tables distinguish agents that can be called directly from those dispatched by a primary.
- Earlier guidance described nine agents as callable with `--agent`.
- Only four are primary and directly callable.
- `general` and `plan` are OpenCode built-ins.
- `orchestrate` is `mode=primary`.
- `multi-ai-council` is `mode=all`.
- The other eight agents are in `mode=subagent` and dispatch through the Task tool from a primary:
  - `context`
  - `debug`
  - `review`
  - `write`
  - `deep-research`
  - `deep-review`
  - `deep-agent-improvement`
  - `prompt-improver`

#### Route Scenarios Through Orchestrate <a id="c-route-scenarios-through-orchestrate"></a>

> [!WARNING]
> Reroute direct subagent calls. Callers using `opencode run --agent <subagent>` directly must instead use `opencode run --agent orchestrate "Use the <subagent> subagent to ..."`.

- Five playbook scenarios now route subagents through `orchestrate`.
- This follows OpenCode's primary-agent routing.
- OpenCode warns that a subagent is not a primary agent.
- This happens when a scenario invokes it directly.
- OpenCode then falls back to the default agent.
- The context, review, write, deep-research and deep-review scenarios now use `--agent orchestrate`.
- They use the prompt prefix `"Use the <subagent> subagent to ..."`.
- The general, multi-ai-council and orchestrate scenarios already used primary agents.
- They were correctly routed.

## Playbook Naming

The playbook now uses one lowercase canonical name across files and templates.

#### Keep the Lowercase Name <a id="c-keep-the-lowercase-name"></a>

- The playbook filename and its creation template now use the same lowercase canonical name.
- The playbook name is now `manual_testing_playbook.md`.
- The creation template also prescribes the lowercase canonical name.
- The playbook was renamed from `MANUAL_TESTING_PLAYBOOK.md` to `manual_testing_playbook.md`.
- Its 120 scenario-file cross-references now use the lowercase canonical name.
- The `manual_testing_playbook_creation.md` template previously prescribed the uppercase name.
- It now prescribes `manual_testing_playbook.md`.
- So future `/create:testing-playbook` runs use that name by default.

## Upgrade Notes

These steps confirm the new default.

#### Before You Start <a id="c-before-you-start"></a>

1. Keep the documented default invocation. Callers using `opencode run --model opencode-go/deepseek-v4-pro --variant high --agent general --format json` need no script changes.
2. Check the assumed authentication path. The opencode-go subscription is the assumed default. Use `opencode auth list` to confirm `opencode-go` is registered.
