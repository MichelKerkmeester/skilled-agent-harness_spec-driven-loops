# cli-opencode v1.4.4.0

## Changed

- **OpenRouter removed from the closed roster** (spec `specs/cli-external-orchestration/068-drop-openrouter-provider/`). The `### openrouter` section of `references/providers-and-models.md` is gone with both of its rows, `openrouter/deepseek/deepseek-v4-flash-vision-exp` and `openrouter/z-ai/glm-5.3-flash`. `SKILL.md` now says **six** providers are reachable rather than seven: `opencode-go` (default), `openai`, `cline-pass`, `llmgateway`, `minimax` and `xiaomi`.
- `SKILL.md`: `openrouter` left the Keywords line, so a prompt naming the gateway no longer pulls advisor vocabulary toward a mode that cannot dispatch it. The id-shape footgun paragraph now contrasts `llmgateway`'s bare two-segment id against `cline-pass`'s slashed three-segment one, the two shapes that remain.
- **The GLM-5.3-Flash workaround kept both of its live routes.** cline-pass cannot serve that model on this CLI, and the callout that says so pointed at OpenRouter first; it now points at `opencode-go/glm-5.3-flash` and `llmgateway/glm-5.3-flash`, which are both already on the roster.
- `references/cli-reference.md`: the `opencode providers login openrouter` line left the all-providers-missing pre-flight tree. Offering a login for an off-roster gateway invites a dispatch the roster forbids.
- Playbooks: the retired-CO-011 note and the CO-012 scenario prose no longer list OpenRouter among the routes that carry DeepSeek-family reasoning models.

## Not Changed

- **`changelog/v1.4.3.0.md`.** It records that the OpenRouter three-model allowlist survived the 056 roster retirement. That was true when it was written.
- **The mode default.** `opencode-go/deepseek-v4-flash-vision-exp --variant max` was never routed through OpenRouter, so §3 and every dispatch example are untouched.
- **Every other provider and model row**, the `--variant` effort table, and the closed-roster discipline rule. cli-opencode has no code-enforced allowlist, so this catalog *is* the enforcement and narrowing it is the whole change.
