cli-opencode removes OpenRouter from the provider roster. It also updates the guidance around that roster. It has no code-enforced allowlist. So the catalog is the enforcement. Narrowing it is the whole change.

## What's New at a Glance

- **OpenRouter leaves the reachable provider roster.** The `### openrouter` section is gone from `references/providers-and-models.md`. So are its `openrouter/deepseek/deepseek-v4-flash-vision-exp` and `openrouter/z-ai/glm-5.3-flash` rows. `SKILL.md` now says six providers are reachable rather than seven. They are `opencode-go` (default), `openai`, `cline-pass`, `llmgateway`, `minimax` and `xiaomi`.
- **Provider guidance reflects the remaining routes.** `openrouter` leaves the `SKILL.md` Keywords line. So a prompt naming OpenRouter no longer pulls advisor vocabulary toward a mode that cannot dispatch OpenRouter. The id-shape footgun paragraph now contrasts the two shapes that remain. It sets `llmgateway`'s bare two-segment id against `cline-pass`'s slashed three-segment one.
- **The GLM-5.3-Flash workaround keeps two live routes.** Its callout says `cline-pass` cannot serve that model on this CLI. It previously pointed at OpenRouter first. It now points at `opencode-go/glm-5.3-flash` and `llmgateway/glm-5.3-flash`. Both are already on the roster.
- **Setup help and playbooks follow the roster.** `references/cli-reference.md` no longer offers `opencode providers login openrouter` in the all-providers-missing pre-flight tree. That is because it invites a dispatch the roster forbids. The retired `CO-011` note and `CO-012` scenario prose no longer list OpenRouter among routes that carry DeepSeek-family reasoning models.
- **One earlier claim is historical.** `changelog/v1.4.3.0.md` records that the OpenRouter three-model allowlist survived the 056 roster retirement. That was true when written. The default `opencode-go/deepseek-v4-flash-vision-exp --variant max` was never routed through OpenRouter. So §3 and every dispatch example remain untouched. Every other provider and model row also remains unchanged. So do the `--variant` effort table and the closed-roster discipline rule.

## Upgrade

No migration required.
