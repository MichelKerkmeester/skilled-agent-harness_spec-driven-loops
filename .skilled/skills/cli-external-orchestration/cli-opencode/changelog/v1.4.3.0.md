v1.4.3.0 retires several dispatch options and centers cli-opencode guidance on DeepSeek V4 Flash through `opencode-go`, with flash max-tier-pinned by policy.

> Spec folder: `specs/cli-external-orchestration/056-roster-drop-deepseek-api-pro-terra/`

## What's New at a Glance

- **The roster drops retired providers and models.** The direct DeepSeek API provider, every DeepSeek V4 Pro entry across roster rows, the cline-pass route, examples and pre-flight trees, and every GPT-5.6 Terra slug (base/fast/pro) were removed.
- **Dispatch guidance now uses one flash default.** The default command is `opencode run --model opencode-go/deepseek-v4-flash --variant max --format json --dir <repo-root>`. The default is applied consistently across the skill guidance and references, including the destructive-scope fallback advice. The cli-reference pre-flight decision tree now checks `opencode-go` instead of `deepseek` as the default.
- **Authentication and fallback guidance follow the default.** The provider auth pre-flight one-shot script now keys the default on `OPENCODE_GO_OK`. The fallback ASK-user trees offer `opencode-go` setup instead of `opencode providers login deepseek`.
- **Playbooks reflect the roster and default changes.** CO-011 (DeepSeek direct API) was retired and its feature file deleted. CO-012 keeps flash variant coverage on the `opencode-go` route, and CO-001/CO-014/CO-015/CO-017/CO-034 command sequences now pin the flash default to `--variant max`.
- **The skill version advances to 1.4.3.0.** SKILL.md frontmatter moved from 1.4.2.0 to 1.4.3.0.
- **Unrelated routes and catalogs remain unchanged.** The OpenRouter three-model allowlist, cline-pass flash/GLM routes and minimax/xiaomi/openai catalogs were not changed. `references/destructive-scope-violations.md` keeps its 2026-05-04 incident narrative verbatim.
