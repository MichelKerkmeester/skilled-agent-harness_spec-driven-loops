v1.4.6.0 moves the OpenCode mode's DeepSeek Flash default to V4.1, updates the Cline DeepSeek row and corrects a catalog price claim. It also brings the deep-loop effort-pin assertion into line with the default.

## Why This Release

The default moves to a newer DeepSeek Flash model without changing the route, listed price or image support.

## What's New at a Glance

- **The mode default is now `opencode-go/deepseek-v4.1-flash`.** It stays on the same route with the existing `--variant max` policy pin.
- **The Cline row lists `cline-pass/cline-pass/deepseek-v4.1-flash` as listing-only.** Cline's own API lists `deepseek/deepseek-v4.1-flash`.
- **The opencode-go price claim now matches the catalog.** The correction applies to every Flash ID on that route.
- **The deep-loop effort-pin assertion now follows the default.** The existing pin pattern already covers the new ID.

---

## Model Routes

#### Newer Default, Same Route

**Breaking:** The former mode default was `opencode-go/deepseek-v4-flash-vision-exp`. The change keeps image support, the 1M context and the 384K output ceiling. The `--variant max` policy pin is unchanged and still lands on a tier this route carries. All eight references to the default were updated.

The superseded row claimed $0.22 in and $0.66 out per million tokens. The catalog lists $0.15 in and $0.60 out for every Flash ID on that route, with cached reads at $0.003.

&nbsp;

#### Cline Route Resolution

**Breaking:** models.dev has no cline-pass V4.1 entry. OpenCode resolves provider models from models.dev, so the Cline ID fails at resolution with `Unexpected server error` before any request leaves the machine. The GLM-5.3-Flash note in the same section already documents that error signature.

A live `--variant max` dispatch on the opencode-go default returned a token. The Cline route is not reported as working: on 2026-09-11 every attempt returned `429 monthly Clinepass limit`, including the previously working V4-Flash ID.

---

## Deep-Loop Configuration

#### Effort Pin Follows Default

The private effort-pin assertion previously used the old default ID and now follows the current default. Its existing pin pattern already covered the new ID, so no runtime change was needed.

---

## Upgrade Notes

- **Fallback.** `cline-pass/cline-pass/deepseek-v4-flash` remains available upstream. The row names it as the fallback until a live turn passes with `cline-pass/cline-pass/deepseek-v4.1-flash`.
