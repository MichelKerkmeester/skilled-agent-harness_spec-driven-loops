# v1.4.6.0, DeepSeek Flash Default Moves to V4.1

The OpenCode mode's DeepSeek Flash default moves to V4.1.

- The default is now `opencode-go/deepseek-v4.1-flash`.
- It stays on the same route with the existing `--variant max` policy pin.
- The route, listed price and image support do not change.

The Cline DeepSeek row changes.

- The Cline row lists `cline-pass/cline-pass/deepseek-v4.1-flash` as listing-only.
- Cline's own API lists `deepseek/deepseek-v4.1-flash`.

A catalog price claim is corrected.

- The opencode-go price claim now matches the catalog.
- The correction applies to every Flash ID on that route.

The deep-loop effort-pin assertion follows the default.

- The assertion now follows the default.
- The existing pin pattern already covers the new ID.

> [!IMPORTANT]
> 2 changes can break an existing setup. Read these before you update.
>
> 1. The mode default moves to V4.1. [Newer default, same route](#c-newer-default-same-route)
> 2. The Cline route does not resolve. [Cline route resolution](#c-cline-route-resolution)

&nbsp;

## Model Routes

The default moves to `opencode-go/deepseek-v4.1-flash`. The Cline row lists `cline-pass/cline-pass/deepseek-v4.1-flash` as listing-only.

#### Newer Default, Same Route <a id="c-newer-default-same-route"></a>

> [!WARNING]
> The former mode default was `opencode-go/deepseek-v4-flash-vision-exp`.

- The default is now `opencode-go/deepseek-v4.1-flash`.
- It stays on the same route with the existing `--variant max` policy pin.
- The change keeps image support.
- It keeps the 1M context and the 384K output ceiling.
- The `--variant max` policy pin is unchanged.
- It still lands on a tier this route carries.
- All eight references to the default were updated.

<details>
<summary><b>Smaller fixes</b></summary>

- The superseded row claimed $0.22 in and $0.66 out per million tokens.
- The catalog lists $0.15 in and $0.60 out for every Flash ID on that route.
- Cached reads are $0.003.

</details>

#### Cline Route Resolution <a id="c-cline-route-resolution"></a>

> [!WARNING]
> models.dev has no cline-pass V4.1 entry.

- OpenCode resolves provider models from models.dev.
- So the Cline ID fails at resolution with `Unexpected server error`.
- It fails before any request leaves the machine.
- The GLM-5.3-Flash note in the same section already documents that error signature.
- The Cline route is not reported as working.

&nbsp;

## Deep-Loop Configuration

The deep-loop effort-pin assertion follows the default.

#### Effort Pin Follows Default <a id="c-effort-pin-follows-default"></a>

- The private effort-pin assertion previously used the old default ID.
- It now follows the current default.
- Its existing pin pattern already covered the new ID.
- So no runtime change was needed.

&nbsp;

## How It Was Checked

A live dispatch checked the opencode-go default. Cline route attempts were also checked.

<details>
<summary><b>Tests and scenarios</b></summary>

- A live `--variant max` dispatch on the opencode-go default returned a token.
- On 2026-09-11 every attempt returned `429 monthly Clinepass limit`.
- That includes the previously working V4-Flash ID.

</details>

The Cline DeepSeek row names a fallback model.
