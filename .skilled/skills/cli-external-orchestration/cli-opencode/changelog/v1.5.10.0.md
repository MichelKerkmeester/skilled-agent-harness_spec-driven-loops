# v1.5.10.0, The provider key no longer trips the guard

The layer 1 self-invocation check now ignores `OPENCODE_API_KEY` alone. Every other `OPENCODE_*` variable still trips the guard.

> Spec folder: `specs/cli-external-orchestration/opencode-platform/004-self-invocation-guard-api-key`

&nbsp;

## What's New at a Glance

- **The provider key no longer counts as a session marker.** That variable is the credential a shell exports for the provider.
- **Every other `OPENCODE_*` variable still trips the guard.** `OPENCODE_BIN` is included.
- **The check has one exemption.** It runs `env | grep -v '^OPENCODE_API_KEY=' | grep -q '^OPENCODE_'`.

&nbsp;

No action needed.
