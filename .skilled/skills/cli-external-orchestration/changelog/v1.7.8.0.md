# One Authored Mode Vocabulary

The hub now keeps a single authored mode vocabulary that the root router and the advisor both read, so a prompt that stage one sends to a mode finds that mode's leaves. A new check fails when a copy disagrees with hub-router.json.

> Spec folder: `specs/sk-doc/072-skill-routing-and-clarity/004-single-vocabulary-source` (Level 2)

&nbsp;

## What's New at a Glance

- **Every routed term reaches stage two.** The root router's mode intents now carry all 34 terms that hub-router.json routes to each mode. Their multi-word forms sit in the advisor's intent signals.
- **A drift check guards the copies.** `ci-hub-vocabulary-source.cjs` fails when the registry aliases, the root router intents or a packet's keyword triggers disagree with hub-router.json, which is now the single authored vocabulary.
- **Two borrowed terms leave cli-opencode.** `spec kit runtime` and `spec kit memory` name system-spec-kit. The advisor already sends them there.
