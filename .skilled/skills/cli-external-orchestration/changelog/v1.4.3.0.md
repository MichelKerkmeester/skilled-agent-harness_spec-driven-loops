# cli-external-orchestration v1.4.3.0

## Changed

- Pinned DeepSeek V4 Flash to its **max thinking tier** across the external CLI fan-out. Operator policy: Flash is never dispatched below max. "Flash Max" is a thinking/effort level, not a distinct model id — DeepSeek V4 Flash is a reasoning model (`reasoning: true` with a `max` `thinkingLevelMap` entry, confirmed live in `models-store.json` and `opencode models deepseek`/`opencode-go`).
  - **Enforcement** (`fanout-run.cjs`, mirroring `executor-config.ts`): the fan-out command builders now force `deepseek-v4-flash` (bare on cli-pi, provider-prefixed on cli-opencode) to max effort — cli-pi emits `--thinking max`, cli-opencode emits `--variant max` — even when a lineage names a lower effort or none. The recorded `reasoningEffort` reflects the pinned value. A new `isFlashMaxPinnedModel` predicate is the single source of truth; the devin `deepseek-v4-flash-max` uid (which already bakes the tier in) is intentionally not matched.
  - **cli-devin** is unchanged in enforcement — its roster already carries only `deepseek-v4-flash-max` for the Flash family. A policy note was added.
- Corrected the catalogs that wrongly described Flash as "non-reasoning (`--variant` ignored)": the cli-pi and cli-opencode `providers-and-models.md` now state Flash is a reasoning model pinned to the max thinking tier.

## Not Changed

- Routing behavior and the enforced model rosters. Flash remains in every roster; only its dispatch effort is pinned.
- **cli-cursor** — never carried a DeepSeek model; untouched.
- Raw `pi` / `opencode` binary invocations outside the fan-out — the pin lives in the fan-out command builders, not the underlying binaries.
- Every other model and effort mapping (DeepSeek Pro, GLM, GPT-5.6, Grok, SWE, Gemini, MiniMax, MiMo, Qwen) is unchanged.
