# v1.7.0.0 — the cli-jev transport moved out

## Removed

- **The `cli-jev` mode.** The transport left this family and is now `cli-usage`, the first mode of its
  own `cli-jev` hub at `.skilled/skills/cli-jev/`. This hub is back to seven `packetKind: "workflow"`
  modes, and every mode that remains classifies intent, chooses a provider and conducts a dispatched
  session whose writes land in this repository.
- **The `transport-axis` extension.** `mode-registry.json` no longer declares
  `extensions["transport-axis"]`: the axis belongs to the hub that now owns the transported mode, and
  its `transports` list names `cli-usage`. Declaring an axis here with no packet behind it was the
  alternative, and the per-hub gate refuses a transport whose packet does not resolve.
- **The router's `cli-jev` signal and its two vocabulary classes.** `hub-router.json` carries no
  `cli-jev-aliases` or `jev-dispatch` class and no `cli-jev` entry in `tieBreak`. The vocabulary moved
  with the mode, so a request that names Jev resolves the `cli-jev` hub rather than a mode of this one.
- **The description, graph and prose traces.** `description.json` and `graph-metadata.json` carry no
  transport keywords or transport documents, the `SKILL.md` mode table lists seven modes with no second
  axis, `README.md` describes one kind of packet, and `ROUTER.md` maps no Jev intent or leaf.

## Changed

- **The dispatch shape keeps its display name.** A `jev` judgment command still resolves to `cli-jev` in
  the audit, because that is the hub id the request now belongs to; only the packet path the enforcement
  guards read moved, to `cli-jev/cli-usage/SKILL.md`.
- **The compiled artifacts were re-derived** for the seven-mode registry, and this hub reports fresh
  against its new inputs.

## Not Changed

- The seven executor modes, their contracts, their invariants and their evidence.
- The rule that a judgment is not an authorization. It moved with the transport, and the hub that
  carries the mode states it.
