Version 2.1 registers Mistral Vibe (`vibe`) as the eighth CLI mode. So a request that names the Vibe CLI reaches a packet. The packet composes and checks the dispatch. The mode is experimental. Print mode is pinned on `vibe 3.1.2`. The roster is closed at two aliases. ACP (`vibe-acp`) is deferred.

&nbsp;

## What's New at a Glance

- `cli-mistral-vibe` is the eighth CLI mode.
  - The mode dispatches one task to `vibe -p` from a scratch cwd with a disposable `VIBE_HOME` and an `--output-dir`.
  - The mode counts a run complete only when `export.json` records `exit_code` 0 and `outcome` `finished`.
- Vibe words route to the mode, the bare word does not.
  - `mistral vibe`, `vibe -p`, `delegate to vibe` and `vibe print mode` select the mode.
  - A bare "vibe" stays design language and selects no mode.
  - So "a calmer vibe" still defers.
- The roster is closed at two aliases.
  - `deepseek-flash` and `glm-flash` are the only rows.
  - Each is a `mistral`-provider row with `thinking = "max"`.
  - The model row owns reasoning effort, so no reasoning flag exists.
- The mode sits right after `cli-deepseek-harness` in the tie-break.
  - `routerPolicy.tieBreak` lists it eighth.
  - So a request that names several executors runs it last in the ordered bundle.
- Stage two loads the CLI reference and the prompt-quality card.
  - The packet carries no integration-pattern guide.
  - So the card takes that slot, the same shape `cli-deepseek-harness` uses.
- Every hub count now says eight.
  - The mode table, the mode roster, the keywords and the mode count in `SKILL.md`, `README.md` and `description.json` include the new mode.
  - The graph metadata carries its stage-one vocabulary.

&nbsp;

## Upgrade

No migration required. A request that names Mistral Vibe now reaches the packet instead of deferring. The seven existing modes keep their contracts and routing.
