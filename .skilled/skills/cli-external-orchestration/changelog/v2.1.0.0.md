Version 2.1 registers Mistral Vibe (`vibe`) as the eighth CLI mode, so a request that names the Vibe CLI reaches a packet that composes and checks the dispatch. The mode is experimental: print mode is pinned on `vibe 3.1.2`, the roster is closed at two aliases, and ACP (`vibe-acp`) is deferred.

> Spec folder: `specs/cli-external-orchestration/runtime-lifecycle/004-cli-mistral-vibe-creation/010-hub-registration-and-routing`

&nbsp;

## What's New at a Glance

- **`cli-mistral-vibe` is the eighth CLI mode.** It dispatches one task to `vibe -p` from a scratch cwd with a disposable `VIBE_HOME` and an `--output-dir`, and counts a run complete only when `export.json` records `exit_code` 0 and `outcome` `finished`.
- **Vibe words route to it, the bare word does not.** `mistral vibe`, `vibe -p`, `delegate to vibe` and `vibe print mode` select the mode. A bare "vibe" stays design language and selects no mode, so "a calmer vibe" still defers.
- **The roster is closed at two aliases.** `deepseek-flash` and `glm-flash` are the only rows, each a `mistral`-provider row with `thinking = "max"`. The model row owns reasoning effort, so no reasoning flag exists.
- **The mode sits right after the harness in the tie-break.** `routerPolicy.tieBreak` lists it eighth, so a request that names several executors runs it last in the ordered bundle.
- **Stage two loads the CLI reference and the prompt-quality card.** The packet carries no integration-pattern guide, so the card takes that slot, the same shape the harness uses.
- **Every hub count now says eight.** The mode table, the mode roster, the keywords and the mode count in `SKILL.md`, `README.md` and `description.json` include the new mode, and the graph metadata carries its stage-one vocabulary.

&nbsp;

## Upgrade

No migration required. A request that names Mistral Vibe now reaches the packet instead of deferring, and the seven existing modes keep their contracts and routing.
