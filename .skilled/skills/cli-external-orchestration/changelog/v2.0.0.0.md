Version 2.0 records the removal of the `cli-hermes` mode. The hub now routes to seven CLI modes. The mode, its `.hermes` runtime folder and its sync scripts were deleted on 2026-11-07, and no release note said so until this one.

> Spec folder: `specs/cli-external-orchestration/runtime-lifecycle/003-cli-hermes-deprecation/`

&nbsp;

## What's New at a Glance

- **`cli-hermes` is gone.** Hermes Agent is a user-level personal agent, and the per-repository layer cost more to keep in step than it returned. The mode no longer exists as an executor or a hub mode, and a request that names it reaches no packet.
- **Seven modes, counted the same everywhere.** The feature catalog called the DeepSeek harness the eighth mode. It is the seventh, and the catalog and its feature page now say so.
- **One status for the OpenCode Go route.** The hub README and the catalog said the route was not verified. It answered a keyed run on 2026-11-07, which is what the skill and the mode docs already recorded.
- **Every mode states who runs the process.** The Claude Code and OpenCode modes gained the Execution Ownership section the other five carry. The shared deep-loop runtime builds and runs research and review lineages, and no mode adds its own spawn path.
- **One Devin default.** The Devin mode named `swe` in five places and `swe-2-max` in its default table. Every place now names `swe-2-max`, the id the fan-out runner dispatches.
- **The harness dry run checks the guards patch.** The composition check ran with the route and lineage patches only. It now adds the guards patch every real dispatch carries and looks for the `repo-guards` row.

&nbsp;

## Upgrade

Remove any `cli-hermes` executor from a saved fan-out configuration and any `hermes` call from a local script. The `.hermes` folder and the `hermes` shell function are no longer provided. Nothing else needs to change.
