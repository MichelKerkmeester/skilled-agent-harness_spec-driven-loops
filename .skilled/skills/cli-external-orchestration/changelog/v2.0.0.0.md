Version 2.0 records the removal of the `cli-hermes` mode. The hub now routes to seven CLI modes. The mode was deleted on 2026-11-07. So were its `.hermes` runtime folder and its sync scripts. No release note said so until this one.

&nbsp;

## What's New at a Glance

- **`cli-hermes` is gone.** Hermes Agent is a user-level personal agent. The per-repository layer cost more to keep in step than it returned. The mode no longer exists as an executor or a hub mode. A request that names it reaches no packet.
- **Seven modes, counted the same everywhere.** The feature catalog called the DeepSeek Harness the eighth mode. It is the seventh. The catalog and its feature page now say so.
- **One status for the OpenCode Go route.** The hub README and the catalog said the route was not verified. It answered a keyed run on 2026-11-07. The skill and the mode docs already recorded that.
- **Every mode states who runs the process.** The Claude Code and OpenCode modes gained the Execution Ownership section the other five carry. The shared deep-loop runtime builds and runs research and review lineages. No mode adds its own spawn path.
- **One Devin default.** The Devin mode named `swe` in five places. Its default table named `swe-2-max`. Every place now names `swe-2-max`, the id the fan-out runner dispatches.
- **The tool's dry run checks the guards patch.** The composition check ran with the route and lineage patches only. It now adds the guards patch every real dispatch carries. It looks for the `repo-guards` row.

&nbsp;

## Upgrade

Remove any `cli-hermes` executor from a saved fan-out configuration. Remove any `hermes` call from a local script. The `.hermes` folder and the `hermes` shell function are no longer provided. Nothing else needs to change.
