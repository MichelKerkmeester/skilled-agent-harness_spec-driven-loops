The hub's Codex hook parity scenario now matches how Codex loads hooks. Codex reads a trusted checkout's own `.codex/hooks.json`, so the scenario runs its live step from the checkout and expects the hook installer to remove repository copies from the user-wide `~/.codex/hooks.json` rather than add them.

> Part of [Skilled v4.0.0.2](../../../changelog/skilled/v4.0.0.2.md).
>
> Spec folder: `specs/system-skill-advisor/030-pi-skill-orchestrator-based-research-refinement` (Level 2)

## What's New at a Glance

- **The live step runs from the checkout.** The scenario starts `codex exec` in the checkout root, which `~/.codex/config.toml` marks as trusted, so Codex loads the repository hooks from the project file.
- **The installer step checks removal.** A dry run lists the repository entries it would remove and the third-party entries it keeps, a second run changes nothing and `--check` prints `install-codex-hooks: OK`.
- **The scenario counts the adapters it lists.** Its text said eight adapters where its table lists seven, and it now says seven.
