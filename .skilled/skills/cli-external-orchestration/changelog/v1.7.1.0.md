The hub's Codex hook parity scenario now matches how Codex loads hooks. Codex reads a trusted checkout's own `.codex/hooks.json`. So the scenario runs its live step from the checkout. For the same reason, it expects the hook installer to remove repository copies from the user-wide `~/.codex/hooks.json` rather than add them.

> Part of [Skilled v4.0.0.2](../../../changelog/skilled/v4.0.0.2.md).
## What's New at a Glance

- **The live step runs from the checkout.** The scenario starts `codex exec` in the checkout root. `~/.codex/config.toml` marks that root as trusted. So Codex loads the repository hooks from the project file.
- **The installer step checks removal.** A dry run lists the repository entries it would remove. It also lists the third-party entries it keeps. A second run changes nothing. `--check` prints `install-codex-hooks: OK`.
- **The scenario counts the adapters it lists.** Its text said eight adapters. Its table lists seven. It now says seven.
