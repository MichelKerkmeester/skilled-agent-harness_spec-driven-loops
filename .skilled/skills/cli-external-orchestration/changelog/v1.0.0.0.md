This release brings `cli-opencode` and `cli-claude-code` under the `cli-external` hub, giving the advisor one identity while keeping both workflow names available to delegation.

> Spec folder: `.opencode/specs/skilled-agent-orchestration/125-cli-external-parent/`

## What's New at a Glance

- **The hub routes two workflow modes.** `mode-registry.json` and `hub-router.json` connect `cli-opencode` and `cli-claude-code` to the `cli-external` advisor identity as `packetKind: "workflow"` modes. The hub adds no surface or transport axis.
- **Both skills' signals carry forward.** The merged identity uses `skill_id: cli-external` in `family: cli` and carries the union of their edges, domains and intent signals.
- **Delegation keeps the mode names.** The resolver takes executor aliases from each mode's `packetSkillName` in `mode-registry.json`, so prompts continue to resolve to `cli-opencode` and `cli-claude-code`, never to the non-executor `cli-external` hub.
- **Both skill trees moved under the hub.** The `cli-opencode/*` tree moved under `cli-external/cli-opencode/*` and the `cli-claude-code/*` tree moved under `cli-external/cli-claude-code/*`.
- **Live references follow the new paths.** The fail-open `PreToolUse` dispatch-preflight hook, constitutional CLI-dispatch skill-preload path template and reciprocal `sk-prompt` advisor edge were repointed. Other live functional and prose references were updated too.
- **No command was created for the hub or either mode.** Both modes remain advisor-routed and cross-skill-referenced, with each mode's packet-local `changelog/` version history unchanged.

## Upgrade

No migration required.
