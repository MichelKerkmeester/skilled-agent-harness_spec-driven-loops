v1.4.0.0 adds two GPT-5.6 IDs to `cli-cursor`, four model IDs to `cli-devin` and documents `opencode-go/glm-5.3` in `cli-opencode`'s gateway roster. It updates `cli-devin` routing guidance and corrects stale model counts. All model additions were confirmed in live CLI listings on 2026-08-14.

> Spec folder: `specs/cli-external-orchestration/043-roster-update-luna-deepseek-glm-gemini/`

## What's New at a Glance

- **`cli-cursor` adds `gpt-5.6-luna-max` and `gpt-5.6-luna-max-fast`.** They introduce its first GPT-5.6 persona and expand its allowlist, the set of permitted models, from 18 to 20 IDs. See `cli-cursor/changelog/v1.4.0.0.md`.
- **`cli-devin` adds four model IDs.** It adds `deepseek-v4-pro-max`, `deepseek-v4-flash-max`, `gpt-5-6-luna-max` and `gpt-5-6-luna-max-priority`, growing from four model families to five with GPT-5.6 included. Grok 4.6 support, which was already complete (packet 036), remains unchanged: `cli-cursor` keeps all eight `cursor-grok-4.6-*` IDs and `cli-devin` all four `grok-4-6-*` UIDs. See `cli-devin/changelog/v1.4.0.0.md`.
- **`cli-opencode` documents `opencode-go/glm-5.3`.** Its opencode-go gateway roster lists the model as documentation only because `cli-opencode` has no code-enforced allowlist. See `cli-opencode/changelog/v1.4.2.0.md`.
- **`cli-devin` routing guidance now names GPT-5.6 Luna Max.** `shared/references/smart-routing.md` lists it alongside the existing families. The hub still reads `hub-router.json` and `mode-registry.json` with the same `tieBreak` order and `cli-opencode` as the default mode.
- **Roster counts now match the documented model sets.** The sweep changes `cli-cursor` from "18-id" to "20-id" and `cli-devin` from "four families" to "five". It also corrects two stale "10"-count claims that predate packet 036's growth of the Cursor roster to 18.
