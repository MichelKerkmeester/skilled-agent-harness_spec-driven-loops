Version 1.4.5.0 clarifies which model IDs `cli-pi` and `cli-opencode` allow by policy and documents a limit on `cli-opencode`'s Cline route.

> Spec folder: `specs/cli-external-orchestration/055-glm-5-3-flash-gemini-roster/`

## What's New at a Glance

- **`cli-pi` and `cli-opencode` forbid dispatching IDs outside their closed model rosters.** Neither roster gained or lost a model.
- **`cli-pi`'s deep-loop fan-out rejects off-roster IDs.** Direct `pi` calls have no allowlist and rely on discipline. This release leaves fan-out behavior unchanged and replaces the earlier phrase "roster is machine state, not a contract" with "closed roster."
- **`cli-opencode` relies on discipline for its closed-roster rule.** Although `--model provider/id` accepts any ID, its deep-loop fan-out does not gate OpenCode IDs. A live ID outside the catalog remains forbidden.
- **`GLM-5.3-Flash` is unavailable through `cli-opencode`'s Cline route.** The `cline-pass` adapter returns `Unexpected server error` for every ID form, including `cline-pass/z-ai/glm-5.3-flash` and `cline-pass/cline-pass/glm-5.3-flash`, as verified 2026-08-27. `opencode models cline-pass` lists only `glm-5.3` with no `-flash`, so use `openrouter/z-ai/glm-5.3-flash` or `opencode-go/glm-5.3-flash` instead.
- **The `cli-pi` Cline route remains available.** `cline-pass/z-ai/glm-5.3-flash` still works because Pi passes the raw Cline ID straight through.
- **`cli-cursor` and `cli-devin` remain unaffected.** Their hard-enforced model rosters were not changed.

## Upgrade

No migration required.
