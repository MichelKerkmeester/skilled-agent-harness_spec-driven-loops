# v1.6.0.0, Jev Joins as a Transport

`cli-jev` brings Jev's CLI/MCP surface into the hub as a transport. The release also gives that mode registry, routing and dispatch support.

> Spec folder: `specs/cli-jev/001-cli-jev-creation/` (Level 3)

## Why This Release

A transport selects one typed value while a workflow acts. Declaring the `transport-axis` extension registers it rather than leaving it ad hoc.

## What's New at a Glance

- **`cli-jev` becomes the hub's eighth mode and first `packetKind: "transport"`.** It bridges the Jev CLI/MCP surface.
- **`mode-registry.json` declares the `transport-axis` extension.** Its `transports` list names `cli-jev`.
- **The `cli-jev/` packet includes a benchmark baseline and changelog.** Its `SKILL.md` declares eight hard rules.
- **The dispatch audit resolves `jev noul|choice|score|run` and `jev-mcp` to `cli-jev`.** It uses command structure for both.
- **The routing surfaces add Jev's signal and intent.** `hub-router.json` adds the `cli-jev` signal and two vocabulary classes. `ROUTER.md` adds the `JEV` intent row and its two-lead `RESOURCE_MAP`. `leaf-manifest.json` registers five leaves.
- **The false `packetKind` exclusion is removed from `mode-registry.json` and the hub `SKILL.md`.** The wording now accounts for the new transport.
- **Hub metadata carries the release value `1.6.0.0`.** `description.json`, `mode-registry.json`, `hub-router.json`, `ROUTER.md` and the hub `SKILL.md` carry it.
- **The seven existing workflow modes stay unchanged.** Registry edits are additive apart from the version and corrected transport wording.
- **No deep-loop `ExecutorKind` is added.** Jev cannot run a lineage.
- **The repository does not register `jev-mcp` in MCP configuration.** The `jev-mcp` surface ships in the same package and is documented.

## Jev Transport

#### One Value, No Workspace Writes

The `noul`, `choice`, `score` and `run` commands each return one typed value from a state. `cli-jev` writes nothing into this workspace, forbids `Write`, `Edit` and `Task` and sets `mutatesWorkspace` to `false`.

&nbsp;

#### A Declared Transport Axis

`mode-registry.json` declares `extensions["transport-axis"].transports: ["cli-jev"]`, registering the axis rather than leaving it ad hoc. The per-hub gate enforces `routingClass` `metadata`, `mutatesWorkspace: false`, the forbidden `Write`, `Edit` and `Task` set and membership in the axis.

&nbsp;

#### Jev Guidance in One Packet

At `cli-jev/`, the packet includes four references: `cli-reference.md`, `providers-and-models.md`, `integration-patterns.md` and `mcp-server.md`. It also includes a question-shaping card, a feature catalog and a 22-scenario manual testing playbook.

&nbsp;

#### Checks Back the Rules

Eight implemented checks back the packet's rules. They cover availability, `stdin` bounding, `choice` cardinality, `score` cardinality, `--value` against `run`, the `custom` endpoint requirement, inline credentials and the `jev-mcp` host-only rule.

## Hub Routing

#### Jev Reaches the Routing Surfaces

The hub `SKILL.md` carries the transport row, second axis and layout. `ROUTER.md` and the hub registry prose name the transport throughout.

&nbsp;

#### PacketKind Wording Corrected

The earlier `packetKind` wording in `mode-registry.json` said no mode here could be a transport, which the eighth mode disproves. The hub `SKILL.md` and `mode-registry.json` now describe two axes and one extension. The discriminator prose is the registry's own contract, so it moved with the registry.

&nbsp;

#### One Release Value

`description.json`, `mode-registry.json`, `hub-router.json`, `ROUTER.md` and the hub `SKILL.md` all carry `1.6.0.0`. The hub's version authority requires one release value across them.

&nbsp;

#### Existing Workflow Modes Stay Put

No workflow mode's behavior, contract, rules or routing changed. The registry edits are additive apart from the version and the prose that the new mode disproved.

---

## Execution Boundaries

#### Jev Stays Outside Execution

The executor-delegation note says the scorer reads `workflow` modes and deliberately leaves `cli-jev` out. An executor there means a CLI that can take a task, while a transport runs nothing. Jev has no file tools, iteration model or stop policy, so it cannot run a lineage and no deep-loop `ExecutorKind` was added.
