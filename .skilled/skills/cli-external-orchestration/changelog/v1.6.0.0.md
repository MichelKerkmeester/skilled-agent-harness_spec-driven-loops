# v1.6.0.0, Jev Joins as a Transport

Jev joins the hub as a transport.

- It becomes the hub's eighth mode.
- It is the first `packetKind: "transport"`.
- It bridges the Jev CLI/MCP surface.

The registry and routing surfaces carry the transport.

- `mode-registry.json` declares the `transport-axis` extension.
- Its `transports` list names `cli-jev`.
- Hub metadata carries the release value `1.6.0.0`.
- The routing surfaces add Jev's signal and intent.

Existing modes and execution boundaries stay unchanged.

- The seven existing workflow modes stay unchanged.
- Registry edits are additive apart from the version and corrected transport wording.
- No deep-loop `ExecutorKind` is added.
- The repository does not register `jev-mcp` in MCP configuration.

&nbsp;

## Why This Release

A transport selects one typed value while a workflow acts. Declaring the `transport-axis` extension registers it. That keeps it from being ad hoc.

## Jev Transport

`cli-jev` brings Jev's CLI/MCP surface into the hub as a transport. The release also gives that mode registry, routing and dispatch support.

#### One Value, No Workspace Writes <a id="c-one-value-no-workspace-writes"></a>

- The `noul`, `choice`, `score` and `run` commands each return one typed value from a state.
- `cli-jev` writes nothing into this workspace.
- It forbids `Write`, `Edit` and `Task`.
- It sets `mutatesWorkspace` to `false`.

#### A Declared Transport Axis <a id="c-a-declared-transport-axis"></a>

- `mode-registry.json` declares `extensions["transport-axis"].transports: ["cli-jev"]`.
- That registers the axis rather than leaving it ad hoc.
- The per-hub gate enforces `routingClass` `metadata`.
- It enforces `mutatesWorkspace: false`.
- It enforces the forbidden `Write`, `Edit` and `Task` set.
- It also enforces membership in the axis.

#### Jev Guidance in One Packet <a id="c-jev-guidance-in-one-packet"></a>

- The `cli-jev/` packet includes a benchmark baseline and changelog.
- Its `SKILL.md` declares eight hard rules.
- At `cli-jev/`, the packet includes four references.
- They are `cli-reference.md`, `providers-and-models.md`, `integration-patterns.md` and `mcp-server.md`.
- It also includes a question-shaping card.
- It includes a feature catalog and a 22-scenario manual testing playbook.
- The `jev-mcp` surface ships in the same package and is documented.

#### Checks Back the Rules <a id="c-checks-back-the-rules"></a>

- Eight implemented checks back the packet's rules.
- They cover availability and `stdin` bounding.
- They cover `choice` cardinality and `score` cardinality.
- They cover `--value` against `run` and the `custom` endpoint requirement.
- They cover inline credentials and the `jev-mcp` host-only rule.

## Hub Routing

The routing surfaces add Jev's signal and intent.

#### Jev Reaches the Routing Surfaces <a id="c-jev-reaches-the-routing-surfaces"></a>

- The routing surfaces add Jev's signal and intent.
- `hub-router.json` adds the `cli-jev` signal and two vocabulary classes.
- `ROUTER.md` adds the `JEV` intent row and its two-lead `RESOURCE_MAP`.
- `leaf-manifest.json` registers five leaves.
- The dispatch audit resolves `jev noul|choice|score|run` and `jev-mcp` to `cli-jev`.
- It uses command structure for both.
- The hub `SKILL.md` carries the transport row, second axis and layout.
- `ROUTER.md` and the hub registry prose name the transport throughout.

#### PacketKind Wording Corrected <a id="c-packetkind-wording-corrected"></a>

- The earlier `packetKind` wording in `mode-registry.json` said no mode here could be a transport.
- The eighth mode disproves that.
- The false `packetKind` exclusion is removed from `mode-registry.json` and the hub `SKILL.md`.
- The wording now accounts for the new transport.
- The hub `SKILL.md` and `mode-registry.json` now describe two axes and one extension.
- The discriminator prose is the registry's own contract.
- So it moved with the registry.

#### One Release Value <a id="c-one-release-value"></a>

- Hub metadata carries the release value `1.6.0.0`.
- `description.json`, `mode-registry.json`, `hub-router.json`, `ROUTER.md` and the hub `SKILL.md` all carry `1.6.0.0`.
- The hub's version authority requires one release value across them.

#### Existing Workflow Modes Stay Put <a id="c-existing-workflow-modes-stay-put"></a>

- The seven existing workflow modes stay unchanged.
- No workflow mode's behavior, contract, rules or routing changed.
- The registry edits are additive apart from the version and the prose that the new mode disproved.

&nbsp;

## Execution Boundaries

The executor-delegation note leaves `cli-jev` out.

#### Jev Stays Outside Execution <a id="c-jev-stays-outside-execution"></a>

- The executor-delegation note says the scorer reads `workflow` modes.
- It deliberately leaves `cli-jev` out.
- An executor there means a CLI that can take a task.
- A transport runs nothing.
- Jev has no file tools, iteration model or stop policy.
- So it cannot run a lineage.
- No deep-loop `ExecutorKind` was added.
