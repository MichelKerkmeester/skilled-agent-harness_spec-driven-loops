`cli-external-orchestration` 1.4.2.0 moves its second-stage surface router to a root `ROUTER.md`. It follows the two-state root-router document standard. The hub keeps the same routing behavior.

## What's New at a Glance

- **`ROUTER.md` replaces the shared router document.** It replaces `shared/references/smart-routing.md` at the hub root. It declares `router_state: active` and `skill_pointer: SKILL.md`. Its `INTENT_SIGNALS` and `RESOURCE_MAP` block is byte-identical to the legacy file. The prose link to `hub-router.json` was rebased for the root location.
- **`hub-router.json` only changes the literal `defaultResource` entry.** `routerPolicy.defaultResource` now points to `ROUTER.md` instead of the literal legacy entry. `mode-registry.json` stays in the fallback list. `tieBreak` keeps its order and outcomes. `defaultMode` does not change.
- **`SKILL.md` and `README.md` document the root router.** `SKILL.md` is versioned to 1.4.2.0. It adds the two-stage routing pointer and the Surface Router section. It adds the `ROUTER.md` layout entry, two `RESOURCE_MAP`/leaf-manifest sync rules and the surface-router reference. `README.md` is versioned to 1.4.2.0. It adds the stage-two router to the routing chain and the related-documents table. `description.json` aligns to 1.4.2.0.
- **The legacy file and empty `shared/` tree are removed.** `shared/references/smart-routing.md` was deleted after standalone contract validation. The parent doctor passed. Compiled-manifest freshness remains the downstream fleet-rebuild gate.
- **The existing roster and records stay intact.** Every pre-existing roster entry and self-invocation guard stays unchanged. The per-mode dispatch contracts stay unchanged too. Historical changelog entries and dated benchmark reports that name `shared/references/smart-routing.md` also stay unchanged.

No migration required.
