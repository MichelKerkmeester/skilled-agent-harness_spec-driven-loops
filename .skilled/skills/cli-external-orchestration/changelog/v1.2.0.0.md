Codex is now part of the hub's shared workflow model. Routing is gated by the command. Execution is handled by the audited runtime.

&nbsp;

## What's New at a Glance

- `cli-codex` returns as a nested workflow mode.
  - It sits beside `cli-opencode` and `cli-claude-code`.
  - That reverses its earlier deprecation.
- The hub registers Codex under its single identity.
  - `mode-registry.json` and `hub-router.json` use the same fields as existing modes.
  - The advisor and executor-delegation scorer route `cli-codex` through that identity.
- Routing stops when Codex is unavailable.
  - Every routing surface checks `command -v codex` before advertising or dispatching `cli-codex`.
  - If the command is missing, each surface refuses the route.
- Execution uses the audited deep-loop runtime.
  - It runs `codex exec` with Codex CLI 0.144.1.
  - `cli-codex` advertises the route and owns the availability probe.
  - The deep-loop runtime handles execution.
