# v1.7.12.0, Routing Rules Move to ROUTER.md

The routing rules for cli-external-orchestration moved out of SKILL.md and into a final MACHINE ROUTER section of ROUTER.md. That section holds the two-axis model, the routing rule, the outcomes, the per-mode file sets and executor delegation. SKILL.md stays short, and the way the hub routes stays the same.

> Spec folder: `specs/sk-doc/072-skill-routing-and-clarity/014-skill-router-files/004-hub-router-merge` (Level 1)

&nbsp;

## What's New at a Glance

- **SKILL.md keeps a single pointer.** SKILL.md no longer carries a MACHINE ROUTER section. Its SMART ROUTING section ends with one line that points to ROUTER.md.
- **Routing is unchanged.** The map from intent to files is byte for byte the same, and every route the hub selects matches the run before the move. The compiled admission check gives the same result.
- **The compiled activation manifest was regenerated.** Its sources changed, so the manifest was rebuilt from the new files.
- **The hub meets the routing-shape canon.** Its known-debt entry is removed, so the hub no longer needs an exception in that check.
- **The docs name the machine router's home.** The manual testing playbook and the compiled-routing feature catalog entry both name section 5 of ROUTER.md as the home of the machine router.
