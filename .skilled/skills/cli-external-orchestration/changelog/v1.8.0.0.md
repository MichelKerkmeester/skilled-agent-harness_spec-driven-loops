Version 1.8 registers DeepSeek Harness (`dsh`) as the eighth CLI mode, so a request that names the harness reaches a packet that composes and checks the dispatch. The mode is experimental. No route has answered a keyed run yet, so a dsh result is not something to rely on.

> Spec folder: `specs/cli-external-orchestration/085-cli-deepseek-harness-creation/`

&nbsp;

## What's New at a Glance

- **`cli-deepseek-harness` is the eighth CLI mode.** It dispatches one task to `dsh --profile headless` with the prompt on stdin, from a scratch cwd with a disposable `DSH_HOME`. A run counts as complete only on exit 0 plus a `completed` final event.
- **Harness words route to it, model words do not.** `dsh`, `dsh headless`, `deepseek harness` and `delegate to dsh` select the mode. "Use cli-opencode with deepseek-v4.1-flash" still goes to `cli-opencode`.
- **The roster is closed at two routes.** LLM Gateway and OpenCode Go both serve DeepSeek V4.1 Flash, chosen by a checked-in route patch. The OpenCode Go endpoint is still UNKNOWN.
- **The dispatch audit recognizes dsh commands and checks twelve rules.** A headless dsh command is judged before it spawns for the route, lineage and guards patches, the closed roster, the opt-in MCP patch, the isolated home, the version pin, the approval policy and the repository-root `.env`.
- **Roster surfaces name eight modes.** The hub tables, the mode roster, the feature catalog, the prompt-improver eligibility table and the persona-attach table include the new mode. The seven existing modes keep their contracts and routing.
