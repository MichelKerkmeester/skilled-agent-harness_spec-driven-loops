# v1.2.0.0, cli-claude-code

`cli-claude-code` now requires a Claude subscription OAuth session before dispatch.

- `cli-claude-code` checks `claude auth status` before dispatch.
- Without a session, the skill asks for `claude auth login`.
- Machines that relied on `ANTHROPIC_API_KEY` must establish OAuth before their next dispatch.

`cli-claude-code` adds current-generation choices to `cli_reference.md`.

- Three current model IDs are selectable through `--model`.
- This works where the target CLI supports them.

Security rules and existing defaults stay unchanged.

- `claude-sonnet-4-6` remains the skill default.
- Dispatch flags, routing, permission modes and every dispatch rule are unchanged.
- The generic NEVER rule for secrets remains.

> [!IMPORTANT]
> 1 change can break an existing setup. Read it before you update.
>
> 1. Dispatch no longer accepts `ANTHROPIC_API_KEY`. [OAuth Controls Dispatch](#c-oauth-controls-dispatch)

&nbsp;

## Why This Release

The earlier pre-flight treated `ANTHROPIC_KEY_OK` and `CLAUDE_OAUTH_OK` as two authentication paths.

- Once API-key dispatch is removed, the pre-flight checks the OAuth session that remains.

## Authentication

`cli-claude-code` now requires a Claude subscription OAuth session before dispatch.

#### OAuth Controls Dispatch <a id="c-oauth-controls-dispatch"></a>

> [!WARNING]
> Dispatch no longer accepts `ANTHROPIC_API_KEY`. Run `claude auth login` when no session exists.

- The former pre-flight chose between `ANTHROPIC_KEY_OK` and `CLAUDE_OAUTH_OK`.
- Now `cli-claude-code` checks `claude auth status`.
- Without an OAuth session, the skill asks the user to run `claude auth login`.
- It does not dispatch.

#### Auth Guidance Gives OAuth Choices <a id="c-auth-guidance-gives-oauth-choices"></a>

- Sections 3, 11 and 12 of `cli_reference.md` remove the `ANTHROPIC_API_KEY` method.
- They also remove the Anthropic Console key-management link.
- Both are removed from authentication, environment-variable and troubleshooting guidance.
- Use `claude auth login` for an interactive browser flow.
- Use `claude setup-token` for a non-interactive OAuth token for CI/CD.

&nbsp;

## Model Reference

`cli-claude-code` adds current model IDs to `cli_reference.md`.

#### Current Models Join the List <a id="c-current-models-join-the-list"></a>

- Section 6 of `cli_reference.md` adds `claude-opus-4-8` (Opus 4.8), `claude-sonnet-5` (Sonnet 5) and `claude-fable-5` (Fable 5).
- They sit beside `claude-opus-4-6`, `claude-sonnet-4-6` and `claude-haiku-4-5-20251001`.
- Set `--model` to an ID where the target CLI supports it.

#### Existing Defaults Stay <a id="c-existing-defaults-stay"></a>

- `claude-sonnet-4-6` remains the skill default.
- Dispatch flags, routing, permission modes and every dispatch rule are unchanged.

&nbsp;

## Security

The generic NEVER rule remains.

#### Secret Rules Stay Separate <a id="c-secret-rules-stay-separate"></a>

- It covers sending secrets such as API keys or passwords in prompts.
- Security-audit playbook fixtures seed a hardcoded `sk-ant-...` secret into a deliberately vulnerable test file.
- Those fixtures are unchanged.
- That is because they are test inputs, not auth config.

&nbsp;

## Upgrade Notes

Machines that relied on `ANTHROPIC_API_KEY` must establish OAuth before their next dispatch.

#### Before You Start <a id="c-before-you-start"></a>

1. If a machine relied on `ANTHROPIC_API_KEY`, run `claude auth login` once.
2. You can also use `claude setup-token` for CI/CD to establish an OAuth session.
