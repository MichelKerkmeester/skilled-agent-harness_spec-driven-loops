`cli-claude-code` now requires a Claude subscription OAuth session before dispatch and adds current-generation choices to `cli_reference.md`. Machines that relied on `ANTHROPIC_API_KEY` must establish OAuth before their next dispatch.

## Why This Release

The earlier pre-flight treated `ANTHROPIC_KEY_OK` and `CLAUDE_OAUTH_OK` as two authentication paths. Once API-key dispatch is removed, the pre-flight checks the OAuth session that remains.

## What's New at a Glance

- **Dispatch stops without OAuth.** `cli-claude-code` checks `claude auth status` and asks for `claude auth login` when no session exists.
- **Current model IDs join `cli_reference.md`.** `claude-opus-4-8`, `claude-sonnet-5` and `claude-fable-5` are selectable through `--model` where the target CLI supports them.

---

## Authentication

#### OAuth Controls Dispatch

The former pre-flight chose between `ANTHROPIC_KEY_OK` and `CLAUDE_OAUTH_OK`. Now `cli-claude-code` checks `claude auth status`. Without an OAuth session, the skill asks the user to run `claude auth login` and does not dispatch. **Breaking:** Dispatch no longer accepts `ANTHROPIC_API_KEY`.

&nbsp;

#### Auth Guidance Gives OAuth Choices

Sections 3, 11 and 12 of `cli_reference.md` remove the `ANTHROPIC_API_KEY` method and Anthropic Console key-management link from authentication, environment-variable and troubleshooting guidance. Use `claude auth login` for an interactive browser flow or `claude setup-token` for a non-interactive OAuth token for CI/CD.

---

## Model Reference

#### Current Models Join the List

Section 6 of `cli_reference.md` adds `claude-opus-4-8` (Opus 4.8), `claude-sonnet-5` (Sonnet 5) and `claude-fable-5` (Fable 5) beside `claude-opus-4-6`, `claude-sonnet-4-6` and `claude-haiku-4-5-20251001`. Set `--model` to an ID where the target CLI supports it.

&nbsp;

#### Existing Defaults Stay

`claude-sonnet-4-6` remains the skill default. Dispatch flags, routing, permission modes and every dispatch rule are unchanged.

---

## Security

#### Secret Rules Stay Separate

The generic NEVER rule against sending secrets such as API keys or passwords in prompts remains. Security-audit playbook fixtures that seed a hardcoded `sk-ant-...` secret into a deliberately vulnerable test file are unchanged because they are test inputs, not auth config.

---

## Upgrade Notes

- **Authenticate.** If a machine relied on `ANTHROPIC_API_KEY`, run `claude auth login` once or use `claude setup-token` for CI/CD to establish an OAuth session.
- **Choose a model.** To use a current-generation model, pass its ID with `--model`, such as `--model claude-opus-4-8`, where the target CLI supports it.
