`cli-claude-code` now has one routable place for its Anthropic model roster, effort setting and non-interactive dispatch shapes, so these details are no longer spread across two references. `SKILL.md` §3 and `references/cli-reference.md` §6 keep compact residues while model IDs, the default pin and dispatch behavior remain unchanged.

> Spec folder: `.opencode/specs/cli-external-orchestration/033-per-mode-provider-model-reference/`

## Why This Release

`SKILL.md` §3 and `references/cli-reference.md` §6 both held the full model list, default pin, `--effort` lever and dispatch shape. Changing a model meant updating both copies, which risked drift.

## What's New at a Glance

- **`references/providers-and-models.md` is the single-source catalog.** As a routable reference leaf, it gives the router and readers one authority for Anthropic model IDs, the `claude-sonnet-4-6` default pin, the `--effort` reasoning-effort lever and the default and spec-gate-neutralized child envelopes for non-interactive dispatch.
- **The catalog groups model details under `### Anthropic`.** Its `## 2. PROVIDERS & MODELS` section has a table of IDs, the default, tiers and use-case notes. `cli-claude-code` remains single-provider, though the layout can accommodate another provider if one is added.
- **`references/cli-reference.md` §6 MODELS keeps its compact table and a bold pointer.** The `### Available Models` table points to `providers-and-models.md` for the full catalog, tiers, defaults and `--effort` mapping. The exhaustive model prose no longer lives in §6.
- **The version is 1.4.0.0 in both `SKILL.md` and `README.md`.** The two-sentence Model Selection residue points to `references/providers-and-models.md` and retains the default pin and Opus/Haiku guidance, while stating that current-generation IDs are selectable by name. The six-ID roster remains inline: `claude-opus-4-8`, `claude-sonnet-5`, `claude-fable-5`, `claude-opus-4-6`, `claude-sonnet-4-6` and `claude-haiku-4-5-20251001`.
- **`cli-claude-code` remains Anthropic-only, with no roster curation.** Skill routing, permission modes and every dispatch rule remain unchanged.

## Upgrade

No migration required. For the full model roster, tiers, defaults, the `--effort` lever and dispatch envelopes, read `references/providers-and-models.md`.
