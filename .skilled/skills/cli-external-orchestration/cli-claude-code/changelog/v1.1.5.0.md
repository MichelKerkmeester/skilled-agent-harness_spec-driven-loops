This release ports the Provider Auth Pre-Flight (Smart Fallback) pattern into §3 of `cli-claude-code` and adds a Default Invocation block. It is part of the 052 `cli-skill-patterns` harmonization, which brings all five `cli-*` siblings to a shared structural surface for patterns they all need without flattening provider-native flag names or unique value props.

> Spec folder: `specs/052-cli-skill-patterns/` (Level 2)

## What's New at a Glance

- **Check Anthropic credentials before dispatch.** A one-shot bash pre-flight checks `$ANTHROPIC_API_KEY` and OAuth/setup-token output from `claude config list`, then records `ANTHROPIC_KEY_OK` and `CLAUDE_OAUTH_OK`. Its three-state decision table covers default-available, API-key-missing/OAuth-ready and both-missing. The A/B/C prompt offers an OAuth fallback when the API key is missing but OAuth is ready, while the both-missing login menu includes `claude auth login` and `claude setup-token`. Both user-prompt templates make the ASK-not-substitute rule explicit: ask the user rather than silently substitute. On an auth error mid-dispatch, cache invalidation reruns the pre-flight before retry. The pre-flight matches the `cli-opencode` v1.3 pattern exactly, including its three-state column structure, ASK-not-substitute language and cache-invalidation contract. Its substitutions are limited to the detection command, variable names, model invocations and login commands, following `specs/052-cli-skill-patterns/scratch/provider-auth-preflight-template.md`.
- **Set a canonical default invocation.** The default is `claude -p "<prompt>" --model claude-sonnet-4-6 --output-format text`. The override table covers five user-phrasing patterns, including Opus extended thinking (`--model claude-opus-4-6 --effort high`), JSON schema output (`--json-schema '<schema>' --output-format json`), cost-capped use (`--max-budget-usd 1.00`) and plan mode (`--permission-mode plan`).
- **Keep the existing `SKILL.md` §3 structure intact.** Both new subsections sit between Prerequisites and Core Invocation Pattern, matching the `cli-opencode` donor ordering. No existing subsections are renamed or reordered.

## Upgrade

No invocation breaking changes. Existing dispatches keep working as before. AI consumers should run `claude config list 2>&1; env | grep -E '^ANTHROPIC_API_KEY'` once before the first dispatch in each session, cache the result for that session and apply the three-state decision table if `ANTHROPIC_KEY_OK=0`.
