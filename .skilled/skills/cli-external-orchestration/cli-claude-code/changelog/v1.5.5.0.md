# v1.5.5.0, the routing section is a short summary

The routing section used to hold eighty-seven lines of probes, guards, loading tables and intent dictionaries before a reader reached how the packet works. It is now six sentences: what selects this packet, the two leaves a dispatch starts from, and the baseline it loads first. All of that machinery moved without a word changed to a new `## 9. MACHINE ROUTER` section that closes the file.

> Spec folder: `specs/sk-doc/072-skill-routing-and-clarity/008-cli-and-mcp-hubs` (Level 2)

&nbsp;

## What's New at a Glance

- **The routing section now reads as prose.** A reader learns which hub signal arrives here, which leaves a dispatch starts from, and where the deterministic router lives.
- **The router moved, it did not change.** The prerequisite probe, the self-invocation guard, the loading-level table and the intent dictionaries sit word for word in the last section of the file.
- **The six-step call sequence is stated in one place.** The shared helpers are documented once in `shared-smart-router.md` and this packet points there, so the two copies cannot drift apart.
- **The starting leaf list points at the hub router.** The packet no longer offers its own version of the leaves a dispatch starts from, because the hub `ROUTER.md` already names them.
- **Two section pointers were repointed.** The notice at the top and the reference loading notes now name the machine router section rather than the routing section that used to hold the router.

## Upgrade

Nothing to do. No routing behavior, leaf set, model default or dispatch flag changed.
