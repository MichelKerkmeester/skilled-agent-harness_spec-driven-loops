# v1.5.5.0, the routing section is a short summary

The routing section used to hold eighty-seven lines. They were probes, guards, loading tables and intent dictionaries. A reader had to pass them to reach how the packet works. It is now six sentences. They say what selects this packet. They name the two leaves a dispatch starts from. They name the baseline it loads first. All of that machinery moved to a new `## 9. MACHINE ROUTER` section. That section closes the file. Not a word changed.

&nbsp;

## What's New at a Glance

- **The routing section now reads as prose.** A reader learns which hub signal arrives here. They learn which leaves a dispatch starts from. They also learn where the deterministic router lives.
- **The router moved, it did not change.** The prerequisite probe sits word for word in the last section of the file. So does the self-invocation guard. So do the loading-level table and the intent dictionaries.
- **The six-step call sequence is stated in one place.** The shared helpers are documented once in `shared-smart-router.md`. This packet points there. So the two copies cannot drift apart.
- **The starting leaf list points at the hub router.** The packet no longer offers its own list. Those are the leaves a dispatch starts from. That is because the hub `ROUTER.md` already names them.
- **Two section pointers were repointed.** The notice at the top now names the machine router section. So do the reference loading notes. They do not name the routing section that used to hold the router.

&nbsp;

## Upgrade

Nothing to do. No routing behavior, leaf set, model default or dispatch flag changed.
