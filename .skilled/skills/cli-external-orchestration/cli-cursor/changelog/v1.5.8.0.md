# v1.5.8.0, The Child Preamble Rule Applies to Every Dispatch

An earlier prose pass folded the per-session worktree wrapper into one instruction. That instruction copies the child-dispatch preamble into a prompt. The trailing clause read as a condition. So a dispatch that skips the wrapper would have left the preamble out. A child given only `AI_SESSION_CHILD=1` still stops to ask the documentation-scope question. It writes nothing.

The instruction is now one sentence on its own. Copy the preamble to the top of every non-interactive prompt. The wrapper is the next line. It names the same path. It keeps the note that a dispatched `cursor-agent -p` shares the parent's worktree. That agent does not take its own. The rest of the rule is as it was. That includes the distinction from Cursor's native `-w` flag.

> Spec folder: `specs/sk-doc/072-skill-routing-and-clarity/012-alignment-remediation` (Level 2)

&nbsp;

## What's New at a Glance

- **The preamble rule is unconditional.** It applies to every non-interactive dispatch. That holds whether or not the wrapper launched the session.
- **The wrapper gets its own line.** The path `.skilled/bin/worktree-session.sh` is unchanged. So is the shared-worktree behavior.
- **Nothing routes differently.** No intent dictionary, resource map, loading level, guard or default changed.
