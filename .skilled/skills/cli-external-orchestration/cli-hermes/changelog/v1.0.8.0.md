# v1.0.8.0, The Routing Summary Gets Short and the Router Gets Its Own Section

The routing section had become a mixed bag of prose, two probes, a guard, a loading table and the intent dictionaries, so a reader had to scroll past the router to learn what the packet was for. The summary is now six lines of prose that name what selects the packet, the leaves the hub router gives it, the always-loaded pair and where everything else sits. Every router block moved byte for byte into the final MACHINE ROUTER section, and nothing about how a request routes changed.

> Spec folder: `specs/sk-doc/072-skill-routing-and-clarity/008-cli-and-mcp-hubs` (Level 2)

&nbsp;

## What's New at a Glance

- **The routing summary fits on one screen.** It names what selects the packet, the always-loaded pair and the section that holds the rest, so a reader knows the shape before scrolling.
- **The router keeps its own section.** The intent dictionaries, the resource map, the loading levels, the fallback checklist, the fan-out model line, the probes and the guard all sit in the final MACHINE ROUTER section.
- **Nothing routes differently.** The same request loads the same references, and a session already inside Hermes is still refused before any dispatch.
