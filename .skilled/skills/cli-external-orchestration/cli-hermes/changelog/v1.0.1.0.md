The closed roster's MiMo entry moves to `mimo-v2.6-pro` — and Pi's-roster-minus-one keeps
its shape at the new spelling, because that pairing lives in the enforcement, not in this
skill's preference: the HerMeS supported set, its fan-out mirror and the test that asserts
the two agree all moved in the same pass as the surfaces documenting them.

## What Changed

#### Changed

- The seven-id closed roster across `SKILL.md`, the fan-out dispatch feature catalog, the
  provider reference and the testing playbook now read the v2.6 spelling of the one MiMo
  id HerMeS serves.
- The skill's own version, so a reader can tell which generation the roster describes.

#### Not Changed

- The `-ultraspeed` exclusion, which survives as the rationale it always was: the gateway
  answered HTTP 400 "not supported" for that id on this route — an observation recorded
  against the previous spelling, and the pairing (Hermes = Pi's roster minus that id) is
  unchanged by this release. Whether the v2.6 spelling answers the same way is what the
  pairing test guards structurally; a live re-probe belongs to the playbook's next run.

## Why Now

This skill's own contract says it: to change a roster id, amend the documentation here and
`HERMES_SUPPORTED_MODELS` together, never one without the other. That is what this release
did, in one pass, which is why both halves are in the same record.
