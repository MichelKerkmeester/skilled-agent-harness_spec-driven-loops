# v1.0.10.0, SOUL.md Reads as a Hermes Runtime File

The README names `SOUL.md` in the session-isolation row and again in the troubleshooting table, both times as a file `--ignore-rules` keeps out of the leaf prompt. The reference check read each mention as a path in this repository, found none, and failed the README.

Both mentions stay. `SOUL.md` is Hermes's own instruction file, created by the runtime beside the checkout rather than kept in it, so the README now declares the token in its `readme-check` block with that reason. Every other path in the README still resolves, and the isolation claim is the same one it always made.

> Spec folder: `specs/sk-doc/072-skill-routing-and-clarity/012-alignment-remediation` (Level 2)

## What's New at a Glance

- **The README passes the reference check again.** One `allow-ref` entry covers both mentions, with the reason stating that the runtime owns the file.
- **The isolation claim is untouched.** `--ignore-rules` still keeps `SOUL.md`, memories, session search and the CWD instruction files out of the leaf prompt on every dispatch.
- **The README edition is raised.** The body changed, so its own edition moves with it.
