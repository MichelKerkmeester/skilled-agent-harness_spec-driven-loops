# v1.0.9.0, Long Prose Lines Become Short Sentences and Lists

Five passages in the cli-hermes skill were written as one very long line each: the execution-ownership note, the closed model roster, two dispatch-critical gotchas and the persona rule. A reader had to untangle four or five rules out of a single sentence.

Those lines are now short sentences, and a line that carried several rules or steps is now a short list. The instruction comes before the background it needs, and instructions address you directly.

The content did not change. Every model id, flag, path, command, exit code and number in the old lines is still there, and the rewrite adds nothing new. What selects this packet, what loads first and how a request routes are exactly as they were.

> Spec folder: `specs/sk-doc/072-skill-routing-and-clarity/010-prose-clarity-pass` (Level 2)

&nbsp;

## What's New at a Glance

- **Execution ownership reads as who owns what.** The packet owns routing, the probe and the prompt, the shared runtime owns process construction, and the rule against a packet-local wrapper stands on its own line.
- **The closed roster is a list.** The five served models stay in one sentence, and the rotation default, the probed-live note, the off-roster GPT families, the fan-out rejection and the amendment path each get their own bullet.
- **The `--yolo` gotcha is a list of observations.** What happened without the flag, what happened to the destructive command, and what happened with the flag are three bullets. The rule that a read-only dispatch is read-only because of its `-t` list follows on its own.
- **The project-skills gotcha is split.** The trust prerequisite and the mirrored-copy rule read first, the scanner behavior sits under it, and the preload and listing commands follow.
- **The persona rule is a list.** Resolving the persona, the missing native surface, and the inline instruction each stand alone, and the canonical contract keeps its own line.
- **Every fact is the same.** No routing signal, reference path, model id or command changed, so a request routes where it always did.
