Hermes Agent becomes the seventh `cli-external-orchestration` runtime.

## What Changed

#### Added

- **The `cli-hermes` mode packet.** `SKILL.md` with eight hard rules (`stdin-redirect-required`, `hermes-availability-required`, `yolo-required-for-writes`, `ignore-rules-required`, `explicit-toolsets-required`, `no-worktree-flag`, `mcp-config-operator-required`, `hooks-user-level`), the quiet-oneshot dispatch shape, the self-invocation guard on `HERMES_AGENT` and `HERMES_SESSION_ID`, and seven references: CLI reference, providers and models, Hermes-unique tools, integration patterns, agent delegation, hook contract, MCP policy. Assets: a prompt-quality card delegating to the canonical card, and dispatch templates.
- **The seventh executor kind.** `cli-hermes` joins `EXECUTOR_KINDS`; `buildHermesLineageCommand` emits `chat -Q --oneshot --query-file -` with the prompt on stdin, `--yolo` for write leaves, `--ignore-rules`, `--source tool`, an explicit toolset list without `delegation` and `memory`, a run budget one margin under the lineage timeout, and the pinned `max` reasoning tier. The web-search policy maps to the `web` toolset (`live` and `inherit` include it, `disabled` omits it).
- **A two-id closed roster.** `deepseek-v4.1-flash` and `glm-5.3-flash` through the operator's `llmgateway` custom provider; `HERMES_SUPPORTED_MODELS` and its byte mirror reject everything else, including provider-prefixed ids and `auto`.
- **Hub registration.** `mode-registry.json`, `hub-router.json` (signals, vocabulary classes, tie-break), `ROUTER.md`, the hub `SKILL.md` mode table and layout, `description.json`, `graph-metadata.json`, and a regenerated `leaf-manifest.json`.
- **Per-lineage MCP servers.** `liveTools.mcpServers` names the MCP servers a Hermes leaf may reach; the builder appends them to `-t` because a configured server is invisible to a run unless named there. Only `cli-hermes` accepts a non-empty list; `delegation`, `memory` and `clarify` are refused.
- **Seven dispatch rule checks** behind the hard rules, wired into the dispatch hook.
- **The `.hermes/` runtime folder.** Generated markdown-only copies of every canonical `SKILL.md` and of every shared agent (`agent-<name>`) under `skills/` from `sync-skills-hermes.cjs`, an `agents/` link to the shared agent files, and the plugin's persona binding through `HERMES_AGENT_PERSONA` (a symlinked directory is scanned in full by Hermes: the whole-tree link took ten minutes per session and quarantined every hub, and one linked skill was quarantined on its references and scripts), generated prompt stubs from `sync-prompts-hermes.cjs`, the `repo-guards` project plugin bridging the shared guard cores (`pre_tool_call`, `pre_verify`, `on_session_end`, a frozen session prompt section), and `SYNC.md`.
- **Hook parity.** The `repo-guards` plugin bridges every repo hook core Hermes's plugin API can reach: the skill advisor and spec gate at prompt time (`pre_llm_call`), the task-dispatch and MCP route guards and sk-vision before a tool call, post-edit quality on a write result, the shared goal core at session start, the session-start guards as a prompt section, and session cleanup at session end; only the OpenCode-, Claude- and Devin-specific hooks and the installer stay out.
- **Council seats, benchmark dispatch and the stress matrix.** `cli-hermes` is an AI-council seat executor (prompt on stdin) and a model-benchmark executor; `cli-hermes.vitest.ts` implements the fourteen hermetic stress cells through `hermes-shim.cjs`.
- **A manual-testing playbook and a feature catalog** at the sibling depth, with the first playbook pass recorded under `benchmark/reports/`.
- **Dispatch audit.** The runtime-neutral inspector recognizes `hermes chat` with a query flag and the top-level `-z` oneshot as a dispatch, and ignores bare `hermes` management subcommands.

#### Corrected on live evidence

- **`--yolo` gates only flagged actions.** The research read "a headless chat without `--yolo` denies writes"; live, an ordinary write succeeded without the flag and only a dangerous command (`rm -rf <scratch dir>`) was blocked headless, then ran with `--yolo`. The hard rule, the builder comment, the references and the card now say so; a write leaf still carries the flag so a flagged step cannot fail it mid-task, and a read-only run is read-only through its `-t` list.
- **Gateway errors print to stdout**, `--run-budget` does not bound a stalled stream (the runner's ceiling, twice `iterations × timeoutSeconds`, does), `-Q` stdout can carry the model's reasoning before the answer, and MCP tools require the server name in `-t`.

#### Evidence

- Phase 001 of `specs/cli-external-orchestration/071-cli-hermes-creation`: two forced-depth research lineages (DeepSeek V4 Flash Max, 10 iterations; SWE-2 Max, 5 iterations), fourteen citations verified against the installed Hermes v0.21.1 source.
- Phase 002 pinned the contract live under the operator-authorized `llmgateway` provider: smoke exit 0 with `session_id:` on stderr, `--query-file` verbatim, off-roster exit 1, budget expiry exit 0, the `--yolo` cases both ways, trust and scan verdict.
- Phase 003 ran one live `cli-hermes` research lineage through the fan-out runner (exit 0, 1042 s, full artifact set); phases 005 and 006 proved skill reach, a command template, the `code_mode` MCP server and the plugin's self-dispatch refusal in live sessions.
