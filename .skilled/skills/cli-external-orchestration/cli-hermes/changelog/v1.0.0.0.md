# v1.0.0.0, Hermes Joins External Orchestration

This release adds the `cli-hermes` mode packet with its quiet-oneshot dispatch shape, a two-id closed model roster, per-lineage MCP servers and the `repo-guards` plugin.

> Spec folder: `specs/cli-external-orchestration/071-cli-hermes-creation` (Level 3)

## Why This Release

Hermes Agent becomes the seventh runtime in `cli-external-orchestration`.

## What's New at a Glance

- **The `cli-hermes` packet sets eight hard rules for dispatch.** Seven dispatch rule checks are wired into the dispatch hook.
- **`cli-hermes` is the seventh executor kind.** Its lineage command uses a quiet one-shot form and sends the prompt on stdin.
- **The Hermes model roster has two supported IDs.** Everything outside those IDs is rejected.
- **MCP servers are named per lineage.** A Hermes leaf can reach the servers named in its live tools configuration.
- **The release adds the `.hermes/` runtime folder.** It includes generated skill and agent files.
- **The release includes the `repo-guards` project plugin.** It is part of the `.hermes/` runtime setup.
- **The hub registers `cli-hermes` in its registry, router and metadata.** The `hub-router.json` router records its signals, vocabulary classes and tie-break.
- **`cli-hermes` runs as an AI-council seat and a model-benchmark executor.** The council-seat prompt is sent on stdin.
- **The dispatch inspector recognizes Hermes one-shot forms.** It ignores bare management subcommands.
- **Live evidence corrected five Hermes behavior claims.** The corrections cover `--yolo`, gateway errors, `--run-budget`, `-Q` output and MCP tool naming.

## Hermes Dispatch and Models

#### Set Hermes Dispatch Rules

The `cli-hermes` mode packet's `SKILL.md` defines eight hard rules:

- `stdin-redirect-required`
- `hermes-availability-required`
- `yolo-required-for-writes`
- `ignore-rules-required`
- `explicit-toolsets-required`
- `no-worktree-flag`
- `mcp-config-operator-required`
- `hooks-user-level`

The self-invocation guard checks `HERMES_AGENT` and `HERMES_SESSION_ID`.

&nbsp;

#### Send Quiet One-Shot Prompts

`cli-hermes` joins `EXECUTOR_KINDS` as the seventh executor kind. `buildHermesLineageCommand` emits `chat -Q --oneshot --query-file -` with the prompt on stdin. The command uses `--ignore-rules` and `--source tool`, adds `--yolo` for write leaves and supplies an explicit toolset list without `delegation` or `memory`.

Its run budget sits one margin under the lineage timeout. Its reasoning tier is pinned to `max`. For `live` and `inherit`, the web-search policy maps to the `web` toolset. For `disabled`, it omits the toolset.

&nbsp;

#### Keep the Model Roster Closed

`deepseek-v4.1-flash` and `glm-5.3-flash` are supported through the operator's `llmgateway` custom provider. `HERMES_SUPPORTED_MODELS` and its byte mirror reject everything else, including provider-prefixed IDs and `auto`.

&nbsp;

#### Name MCP Servers Per Lineage

`liveTools.mcpServers` names the MCP servers a Hermes leaf may reach. The builder appends those named servers to `-t` because a configured server is invisible to a run unless named there.

Only `cli-hermes` accepts a non-empty list. `delegation`, `memory` and `clarify` are refused.

&nbsp;

#### Audit Hermes Dispatch Forms

The runtime-neutral inspector recognizes `hermes chat` with a query flag and a top-level `-z` one-shot as dispatches. It ignores bare `hermes` management subcommands.

&nbsp;

#### Correct Claims on Live Evidence

`--yolo` gates only flagged actions. The research read that a headless chat without `--yolo` denies writes. Live, an ordinary write succeeded without the flag and only a dangerous command (`rm -rf <scratch dir>`) was blocked headless, then ran with `--yolo`.

The hard rule, the builder comment, the references and the card now say so. A write leaf still carries the flag so a flagged step cannot fail it mid-task, and a read-only run is read-only through its `-t` list.

The same live evidence showed that gateway errors print to stdout and that `-Q` stdout can carry the model's reasoning before the answer. `--run-budget` does not bound a stalled stream. The runner's ceiling, twice `iterations × timeoutSeconds`, does. MCP tools require the server name in `-t`.

## Hermes Runtime and Hooks

#### Add the Hermes Runtime Folder

`.hermes/` contains generated Markdown-only copies of every canonical `SKILL.md` and every shared agent (`agent-<name>`) under `skills/`, produced by `sync-skills-hermes.cjs`. The `agents/` link points to the shared agent files. `.hermes/` also carries the plugin's persona binding through `HERMES_AGENT_PERSONA`.

Hermes scans a symlinked directory in full. The whole-tree link took ten minutes per session. It quarantined every hub. One linked skill was quarantined on its references and scripts. `sync-prompts-hermes.cjs` generates prompt stubs. `.hermes/` includes `SYNC.md`.

&nbsp;

#### Bridge Repository Hooks

The `repo-guards` project plugin bridges every repo hook core Hermes's plugin API can reach. It bridges the shared guard cores (`pre_tool_call`, `pre_verify`, `on_session_end` and a frozen session prompt section).

At prompt time (`pre_llm_call`), it runs the skill advisor and spec gate. Before a tool call, it runs task-dispatch and MCP route guards plus `sk-vision`. Post-edit quality runs on a write result. The shared goal core runs at session start. Session-start guards appear as a prompt section. Session cleanup runs at session end. Only the OpenCode-, Claude- and Devin-specific hooks and the installer stay out.

&nbsp;

#### Extend Council and Benchmark Runs

`cli-hermes.vitest.ts` implements fourteen hermetic stress cells. It uses `hermes-shim.cjs`.

## Hub Registration and Guidance

#### Register Hermes in the Hub

`mode-registry.json` registers the mode. `ROUTER.md`, the hub `SKILL.md` mode table and layout, `description.json` and `graph-metadata.json` are updated. `leaf-manifest.json` is regenerated.

&nbsp;

#### Guide Hermes Users

The mode packet has seven references: the CLI reference, providers and models, Hermes-unique tools, integration patterns, agent delegation, the hook contract and MCP policy. The prompt-quality card delegates to the canonical card. Dispatch templates accompany the mode.

The release adds a manual-testing playbook and a feature catalog at the sibling depth. The first playbook pass is recorded under `benchmark/reports/`.
