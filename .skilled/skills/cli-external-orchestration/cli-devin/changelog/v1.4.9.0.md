# v1.4.9.0, Routing Summary Up Front

The routing section opened with a prerequisite probe. It also opened with a self-invocation guard, a loading-level table and a page of router dictionaries. So a reader looking for where a Devin request lands had to walk all of it first.

The section now says in three paragraphs which hub signal selects this packet. It names the two references that load on every invocation. It says where the routing detail lives.

The probe, the guard, the loading levels and the intent map moved down the file. Not a word changed.

&nbsp;

## What's New at a Glance

- **The routing section reads as a summary.** Three short paragraphs name the hub's `cli-devin` mode signal. They name the Devin surfaces that fire it. They name the two references loaded on every invocation. They name the final section that holds the rest.
- **The routing detail is unchanged, one section down.** The prerequisite probe, the self-invocation guard and the loading-level table keep their headings. So do the intent map and the fallback checklist. Every byte stays, in a final MACHINE ROUTER section.
- **The six shared helper steps are stated once.** They are now one sentence. It points at the family reference that documents the helper bodies. So this packet no longer restates them.
- **Routing behaves exactly as before.** Every intent signal, resource map entry and loading level kept its old value. So the same request loads the same files.

No migration required.
