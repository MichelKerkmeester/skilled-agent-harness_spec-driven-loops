# v1.4.9.0, Routing Summary Up Front

The routing section opened with a prerequisite probe, a self-invocation guard, a loading-level table and a page of router dictionaries, so a reader looking for where a Devin request lands had to walk all of it first. The section now says in three paragraphs which hub signal selects this packet, which two references load on every invocation and where the routing detail lives. The probe, the guard, the loading levels and the intent map moved down the file without a word changing.

## What's New at a Glance

- **The routing section reads as a summary.** Three short paragraphs name the hub's `cli-devin` mode signal and the Devin surfaces that fire it, the two references loaded on every invocation and the final section that holds the rest.
- **The routing detail is unchanged, one section down.** The prerequisite probe, the self-invocation guard, the loading-level table, the intent map and the fallback checklist keep their headings and every byte, in a final MACHINE ROUTER section.
- **The six shared helper steps are stated once.** They are now one sentence pointing at the family reference that documents the helper bodies, so this packet no longer restates them.
- **Routing behaves exactly as before.** Every intent signal, resource map entry and loading level kept its old value, so the same request loads the same files.
