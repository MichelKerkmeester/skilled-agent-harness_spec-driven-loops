Cognition released SWE-2 and repointed the bare `swe` alias to it. `devin models list` on version 3000.10.21 prints `SWE-2 (swe-2)` with `aliases: swe`, and `swe` is this skill's documented default — so every dispatch that took the default was already running SWE-2 while eight surfaces said it was running SWE-1.7 Lightning. This entry closes that gap, adds the three SWE-2 effort ids to the enforced allowlist, and keeps SWE-1.7 documented as an explicit pin.

---

#### The `swe` alias is documented as what the CLI resolves it to

Every live surface that stated `swe` → `swe-1-7-lightning` now states `swe` → `swe-2`. Two claims travelled with the old alias and went with it. The default was described as a lightning speed tier, and SWE-2 has no lightning tier, so a caller picking the default for latency was picking on a false premise — `swe-1-7-lightning` is now named as the only lightning option and the only metered one. The curated roster's out-of-scope note also claimed Devin fronts 37 families; the CLI reports 48.

#### SWE-2 joins the allowlist; SWE-1.7 keeps its rows

`DEVIN_SUPPORTED_MODELS` in `executor-config.ts` and its hand-duplicated mirror `DEVIN_ALLOWED_MODELS` in `fanout-run.cjs` both add `swe-2-high`, `swe-2-max` and `swe-2-medium`, sorted alphabetically after the SWE-1.7 ids. Without this the fan-out would have refused `swe-2-max` before sending a request. There is **no bare `swe-2` id** — the family name is not dispatchable, only the three effort tiers are — so the rejection fixture now asserts that `swe-2` and `swe-1-7-lightning-medium` both stay out. SWE-1.7 lost the alias and the default position, not its ids: `swe-1-7`, `swe-1-7-medium` and `swe-1-7-lightning` are all still served and still pinnable.

#### List-verified AND dispatch-tested, for max only

`devin models list` on 2026-09-12 printed all three ids verbatim, free, at 262K context. A live `devin -p --model swe-2-max` probe returned the requested reply at exit 0 on the same day, so max is dispatch-tested. `swe-2-high` and `swe-2-medium` are list-verified only and are documented that way — no dispatch claim is made for them.

#### Routing vocabulary widened, not replaced

A hub routes in two stages: the advisor scores the hub from `graph-metadata.json`, then `hub-router.json` and `ROUTER.md` pick the mode. A keyword added to the router alone never reaches the advisor. `swe-2` therefore went into all three, beside the existing `swe-1.7` entries rather than over them, because both generations dispatch and a prompt naming either should still route to this mode.
