Cognition released SWE-2 and repointed the bare `swe` alias to it. Since `swe` is this skill's documented default, dispatches taking it were already running SWE-2 while eight surfaces still said SWE-1.7 Lightning. This release closes that documentation gap.

> Spec folder: `specs/cli-external-orchestration/070-swe-2-model-cutover/`

## What's New at a Glance

- **The documented `swe` alias matches the CLI resolution.** The live surfaces now map `swe` → `swe-2` instead of `swe` → `swe-1-7-lightning`. `devin models list` on Devin CLI version `3000.10.21` prints `SWE-2 (swe-2)` with `aliases: swe`.
- **The lightning guidance and roster count are corrected.** The old wording called the default a lightning speed tier, so callers choosing it for latency relied on a false premise. SWE-2 has no lightning tier, making `swe-1-7-lightning` the only lightning option and the only metered one. Devin's curated roster out-of-scope note now gives the CLI-reported family count of 48 instead of 37.
- **Three SWE-2 effort IDs are accepted for dispatch.** The allowlist adds the alphabetically sorted IDs `swe-2-high`, `swe-2-max` plus `swe-2-medium` after the SWE-1.7 IDs, so fan-out accepts `swe-2-max` instead of refusing it before a request. `swe-2` is not dispatchable without an effort tier and `swe-1-7-lightning-medium` remains unsupported. The IDs `swe-1-7`, `swe-1-7-medium` plus `swe-1-7-lightning` remain served and documented as explicit pins despite losing the alias and default position.
- **`swe-2-max` is dispatch-tested while the other effort IDs are list-verified only.** On 2026-09-12, `devin models list` printed all three IDs verbatim as free with 262K context. A live `devin -p --model swe-2-max` probe returned the requested reply at exit 0 that day. `swe-2-high` and `swe-2-medium` have no dispatch claim.
- **Routing vocabulary covers both model generations.** Both generations dispatch, so `swe-2` was added beside `swe-1.7` across `graph-metadata.json`, `hub-router.json` and `ROUTER.md`. The advisor scores the hub from `graph-metadata.json` before `hub-router.json` and `ROUTER.md` pick the mode, so adding the keyword to `ROUTER.md` alone would not reach the advisor and prompts naming either generation should still route to this mode.
