The rule for Devin's dangerous permission mode now agrees with the skill's own default. The default invocation passes `--permission-mode dangerous`, while NEVER rule 1 forbade that mode without explicit approval and never said how far one approval reached. It now says one approval from the user covers a whole task.

> Spec folder: `specs/system-skill-advisor/030-pi-skill-orchestrator-based-research-refinement/012-reverify-follow-ups` (Level 1)

## What's New at a Glance

- **One approval covers a whole task.** NEVER rule 1 forbids `dangerous` only in a task the user has not approved it for. That approval covers every dispatch in the task, the default invocation included, and a new task needs a new one.
- **The escalation rule says the same.** ESCALATE IF rule 4 asks once for the whole task, so the two rules no longer read as two different bars.

## Upgrade

No migration required. Before the first `dangerous` dispatch in a task, ask the user once.
