# v1.5.22.0, Mistral joins the roster for direct dispatch

Pi can now reach the operator's Mistral subscription through its builtin `mistral` provider. Two ids are in scope, for direct dispatch only. The deep-loop fan-out roster does not change.

> Spec folder: `specs/cli-external-orchestration/runtime-lifecycle/004-cli-mistral-vibe-creation/002-mistral-provider-roster`

&nbsp;

## What's New at a Glance

- **Five providers are reachable.** `mistral` joins `openai`, `opencode-go`, `llmgateway` and `minimax`. No `.pi/models.json` block is needed.
- **Two Mistral ids are allowed.** `mistral/deepseek-v4-1-flash-1017` and `mistral/zai-glm-5-3-flash` each replied `OK` under `pi -p` on 2026-11-14. `.pi/settings.json` lists both in `enabledModels`.
- **The fan-out still refuses them.** Neither id is in `PI_SUPPORTED_MODELS`, so a deep-loop run cannot pick them.
- **Mistral ids use dashes.** `mistral/deepseek-v4.1-flash-1017` does not resolve.

&nbsp;

## Upgrade

Save the key once with `pi auth login mistral --api-key` before dispatching to it.
