# cli-pi v1.5.0.0

Pi's dispatch rules now allow a named override.

- A Pi session may now dispatch `cli-pi` only when the user names it.
- The shared explicit-override rule still denies unnamed dispatches.
- The `cli-pi` exception covers only `ancestry` and `lockfile`.
- The other guard layers retain their boundaries.

The delegation package is retired and its guide is redirected.

- The release retires `pi-subagents`, the community package that supplied delegation.
- Pi dropped its subagents feature.
- `references/agent-delegation.md` now guides readers to Pi's built-in tools and CLI dispatch.

The two documents now carry the same version.

- `SKILL.md` and `README.md` now use version 1.5.0.0.
- Their previous version mismatch is resolved.

&nbsp;

## Why This Release

The self-invocation prohibition was stated in `SKILL.md`. The Pi preflight hook enforced it by name. The shared deep-loop guard enforced it in structure.

- Removing only the guidance would have left the preflight refusing a dispatch.
- The guidance permitted that dispatch.
- So all three changed together.

## Pi Dispatch

Pi's dispatch rules change in `SKILL.md` and the preflight hook. The other guard layers keep their limits.

#### Named Overrides Apply <a id="c-named-overrides-apply"></a>

- `SKILL.md` removes the `self-invocation-prohibited` hard rule.
- It removes the critical self-invocation block and `detect_self_invocation()`.
- It also removes the `You ARE Pi already` bullet.
- It also removes one lifecycle step, one ALWAYS rule, one ESCALATE condition and one success criterion.
- The `NEVER` list now names the bounds that remain.
- The Pi preflight no longer contains the `dispatchSkill === "cli-pi"` deny branch.
- It also drops its `Pi cannot dispatch itself` rejection message.
- It now applies the same explicit-override rule as its sibling executors.
- The Pi preflight hook runs inside Pi.

<details>
<summary><b>Test results</b></summary>

- The authoring runtime did not run a live dispatch from a real Pi session.
- So live dispatch remains unverified.

</details>

#### Other Guard Limits Remain <a id="c-other-guard-limits-remain"></a>

- The `cli-pi` exception covers only `ancestry` and `lockfile`.
- The `lineage` layer still refuses dispatch from inside a fan-out lineage.
- The `stack` layer still refuses when the executor kind already appears in the dispatch stack.
- Both limits apply to every kind, including `cli-pi`.
- The `env` layer was already inert for `cli-pi`.
- That is because Pi's session variable was never confirmed.
- `EXECUTOR_SESSION_ENV_BY_KIND` carries no entry, and none was added.
- `cli-codex`, `cli-claude-code`, `cli-opencode`, `cli-cursor` and `cli-devin` still refuse on all five layers.
- The stress self-invocation scenario still asserts fan-out recursion blocking.

## Pi Delegation

The delegation package is retired. The delegation guide is rewritten.

#### Retire the Delegation Package <a id="c-retire-the-delegation-package"></a>

- `pi-subagents` was removed from the activation trigger and the `AGENT_DELEGATION` router keywords.
- It also left hard rule 6, the README FAQ and four references.
- It left the prompt templates, the playbook index and the hub's advisor vocabulary.

#### Delegation Guide Rewritten <a id="c-delegation-guide-rewritten"></a>

- `references/agent-delegation.md` now guides readers to Pi's built-in tools and CLI dispatch.
- It was rewritten rather than deleted because it is a declared leaf.

#### The Scenario and Trust Records <a id="c-the-scenario-and-trust-records"></a>

- The `PI-009` agent-bridge playbook scenario was deleted with `pi-subagents`.
- `pi-mcp-extension` remains documented as a community package behind the same trust gate.
- Changelog and benchmark records continue to state what was true when they were written.
