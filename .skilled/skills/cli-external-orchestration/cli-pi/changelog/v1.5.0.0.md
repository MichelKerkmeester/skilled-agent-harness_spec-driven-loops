v1.5.0.0 brings Pi's dispatch and delegation guidance into line with the rules and routes that remain available.

> Spec folder: `specs/cli-external-orchestration/066-pi-self-dispatch-and-subagents-retirement/`

## Why This Release

The self-invocation prohibition was stated in `SKILL.md`, enforced by name in the Pi preflight hook and enforced structurally by the shared deep-loop guard. Removing only the guidance would have left the preflight refusing a dispatch that the guidance permitted, so all three changed together.

## What's New at a Glance

- **A Pi session may now dispatch `cli-pi` only when the user names it.** The shared explicit-override rule still denies unnamed dispatches.
- **The `cli-pi` exception covers only `ancestry` and `lockfile`.** The other guard layers retain their boundaries.
- **The release retires `pi-subagents`, the community package that supplied delegation.** Pi dropped its subagents feature.
- **`references/agent-delegation.md` now guides readers to Pi's built-in tools and CLI dispatch.** It was rewritten rather than deleted because it is a declared leaf.
- **`SKILL.md` and `README.md` now use version 1.5.0.0.** Their previous version mismatch is resolved.

## Pi Dispatch

#### Named Overrides Apply

`SKILL.md` removes the `self-invocation-prohibited` hard rule, the critical self-invocation block, `detect_self_invocation()` and the `You ARE Pi already` bullet. It also removes one lifecycle step, one ALWAYS rule, one ESCALATE condition and one success criterion. The `NEVER` list now names the bounds that remain.

The Pi preflight no longer contains the `dispatchSkill === "cli-pi"` deny branch or its `Pi cannot dispatch itself` rejection message. It now applies the same explicit-override rule as its sibling executors.

The Pi preflight hook runs inside Pi. The authoring runtime did not run a live dispatch from a real Pi session, so live dispatch remains unverified.

&nbsp;

#### Other Guard Limits Remain

The `lineage` layer still refuses dispatch from inside a fan-out lineage. The `stack` layer still refuses when the executor kind already appears in the dispatch stack. Both limits apply to every kind, including `cli-pi`.

The `env` layer was already inert for `cli-pi` because Pi's session variable was never confirmed. `EXECUTOR_SESSION_ENV_BY_KIND` carries no entry, and none was added. `cli-codex`, `cli-claude-code`, `cli-opencode`, `cli-cursor` and `cli-devin` still refuse on all five layers. The stress self-invocation scenario still asserts fan-out recursion blocking.

## Pi Delegation

#### Retire the Delegation Package

`pi-subagents` was removed from the activation trigger and the `AGENT_DELEGATION` router keywords. It also left hard rule 6, the README FAQ, four references, the prompt templates, the playbook index and the hub's advisor vocabulary.

&nbsp;

#### The Scenario and Trust Records

The `PI-009` agent-bridge playbook scenario was deleted with `pi-subagents`. `pi-mcp-extension` remains documented as a community package behind the same trust gate. Changelog and benchmark records continue to state what was true when they were written.
