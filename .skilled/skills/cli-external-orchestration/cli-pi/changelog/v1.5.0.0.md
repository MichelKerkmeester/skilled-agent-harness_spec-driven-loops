# cli-pi v1.5.0.0

## Changed

- **A Pi session may now dispatch `cli-pi`** (spec `specs/cli-external-orchestration/066-pi-self-dispatch-and-subagents-retirement/`). The prohibition was stated in `SKILL.md`, enforced by name in the Pi preflight hook, and enforced structurally by the shared deep-loop guard; all three were changed together, because removing only the prose would have left the hook refusing what the prose permitted.
- **`SKILL.md`**: the `self-invocation-prohibited` hard rule, the `CRITICAL — SELF-INVOCATION PROHIBITED` block, the `detect_self_invocation()` guard, the "You ARE Pi already" bullet, one lifecycle step, one ALWAYS rule, one ESCALATE condition and one success criterion are gone. The `NEVER` list now names the bounds that actually remain.
- **`.opencode/hooks/dispatch/pi/dispatch-preflight-lint.ts`**: the `dispatchSkill === "cli-pi"` deny branch and its "Pi cannot dispatch itself" block message are gone. A `cli-pi` dispatch is now judged by the same explicit-override rule as any sibling executor, so a dispatch the user did not name is still denied.
- **`system-deep-loop/runtime/lib/deep-loop/executor-audit.ts`**: a `cli-pi`-keyed exemption set is consulted by the `ancestry` and `lockfile` layers only.
- **`pi-subagents` retired.** Pi dropped its subagents feature, so the community package that supplied delegation is gone from the activation trigger, the `AGENT_DELEGATION` router keywords, hard rule 6, the README FAQ, four references, the prompt templates, the playbook index and the hub's advisor vocabulary. `references/agent-delegation.md` was rewritten around Pi's built-in tools and the CLI dispatch route rather than deleted, because it is a declared leaf. The `PI-009` agent-bridge scenario was deleted with the package it tested.
- Frontmatter version moved to 1.5.0.0 in both `SKILL.md` (from 1.3.0.0) and `README.md` (from 1.4.0.0), resolving a drift between them.

## Not Changed

- **The `lineage` and `stack` guard layers, for every kind including `cli-pi`.** They refuse a dispatch from inside a fan-out lineage and one whose kind is already in the dispatch stack. Those bound a runaway spawn chain, which is a different question from whether the caller is inside Pi.
- **The other five executors.** The exemption is keyed to `cli-pi`; `cli-codex`, `cli-claude-code`, `cli-opencode`, `cli-cursor` and `cli-devin` still refuse on all five layers.
- **The `env` layer.** It was already inert for `cli-pi` — `EXECUTOR_SESSION_ENV_BY_KIND` carries no entry, because Pi's session variable was never confirmed — and no entry was added.
- **`stress/self-invocation.md` and its stress cell.** It asserts fan-out recursion blocking, which still holds; the file and its manifest contract are untouched.
- **`pi-mcp-extension`**, which remains documented as a community package behind the same trust gate.
- Changelog and benchmark records, which state what was true when they were written.

## Verification

- `tests/unit/executor-audit.vitest.ts`: 49 passed, up from 35. The new cases assert the exemption applies to `cli-pi` on both layers, that the other five kinds still refuse on both, and that `cli-pi` is still refused on `lineage` and `stack`.
- `tests/stress/cli-adapter/cli-pi.vitest.ts`: 19 passed, 1 skipped, unchanged — the negative control proving the carve-out did not reach the stack layer.
- `dispatch-preflight-lint.test.ts`: 33 passed, including a new row asserting an unnamed `cli-pi` dispatch is still denied.
- `grep -ric "pi-subagents"` over the hub: hits only under `changelog/` and `benchmark/reports/`.

## Known Limitation

The Pi preflight hook runs inside Pi. Its unit tests prove the branch is gone from the source; a live dispatch from a real Pi session was not run from the authoring runtime and is recorded as unverified rather than inferred.
