# v1.5.3.0, DeepSeek Routes Refreshed

The cli-pi update refreshes the DeepSeek route roster.

- It also refreshes the guidance that uses its model identifiers.
- It also aligns the manual-testing id-format control with the wired configuration.
- The opencode-go row now uses `deepseek-v4.1-flash`.
- It now shares a model name with DevPass.

The cline-pass listing moves to the new model name too.

- The row now lists `cline-pass/cline-pass/deepseek-v4.1-flash`.
- No dispatch has been recorded for this id.

The dispatch examples and manual-testing control are updated.

- The dispatch examples now use `deepseek-v4.1-flash`.
- Both match the roster row they illustrate.
- The id-format control now matches `.pi/settings.json`.
- A `429` reads as `route never exercised`, not a pass or model failure.

> [!IMPORTANT]
> 2 changes can break an existing setup. Read these before you update.
>
> 1. The opencode-go DeepSeek row changed its id. [One Literal, Separate Routes](#c-one-literal-separate-routes)
> 2. The cline-pass DeepSeek row changed its id. [The Cline Listing's Limit](#c-the-cline-listings-limit)

## DeepSeek Routes

Two DeepSeek route entries change their ids.

#### One Literal, Separate Routes <a id="c-one-literal-separate-routes"></a>

> [!WARNING]
> The opencode-go DeepSeek row changed from `deepseek-v4-flash-vision-exp` to `deepseek-v4.1-flash`.
>
> Replace the opencode-go id `deepseek-v4-flash-vision-exp` with `deepseek-v4.1-flash`.

- DevPass's bare literal became `deepseek-v4.1-flash` first.
- The opencode-go id has now caught up.
- So both DeepSeek routes name the same model again.
- One literal maps to one provider.
- Only the DevPass route appears in the fan-out map.
- That map lists the routes used for parallel dispatch.
- So the routes remain separate.
- The opencode-go row keeps its direct-dispatch-only note and its `--thinking max` pin.
- That pin is a tier this route carries.

#### The Cline Listing's Limit <a id="c-the-cline-listings-limit"></a>

> [!WARNING]
> The cline-pass DeepSeek row is now `cline-pass/cline-pass/deepseek-v4.1-flash`.
>
> The row names `cline-pass/cline-pass/deepseek-v4-flash` as the fallback until one V4.1 turn passes after the quota window resets.

- The `.pi` provider block and picker entry moved to match.
- This id is listing-only.
- No dispatch has been recorded for it.
- Cline's own API lists `deepseek/deepseek-v4.1-flash`.

## Manual Testing

The manual-testing control had drifted from the wired config.

#### Id Checks Match Settings <a id="c-id-checks-match-settings"></a>

- The manual-testing playbook's id-format control had drifted from `.pi/settings.json`.
- Its model id and expected `defaultModel` no longer matched the wired config.
- Its skip list no longer matched either.
- The skip list now accepts the quota blocker.
- So a `429` reads as `route never exercised`.
- It does not read as a pass or a model failure.
- The scenario contract and execution table were both updated with that expectation.
- So the playbook cannot disagree with itself.
