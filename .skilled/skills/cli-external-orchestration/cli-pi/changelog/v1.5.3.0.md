The cli-pi update refreshes the DeepSeek route roster and the guidance that uses its model identifiers. It also aligns the manual-testing id-format control with the wired configuration.

## Why This Release

The updated entries carry different dispatch evidence: opencode-go is dispatch-proven through its own client, while cline-pass is listed upstream only.

## What's New at a Glance

- **The opencode-go DeepSeek row now uses `deepseek-v4.1-flash`.** It now shares a model name with DevPass.
- **The cline-pass row now lists `cline-pass/cline-pass/deepseek-v4.1-flash`.** No dispatch has been recorded for this id.
- **The dispatch examples now use `deepseek-v4.1-flash`.** The quick-invocation snippet and child-session envelope match the roster row they illustrate.
- **The manual-testing id-format control now matches `.pi/settings.json`.** A `429` reads as `route never exercised`, not a pass or model failure.

---

## DeepSeek Routes

#### One Literal, Separate Routes

**Breaking:** The opencode-go DeepSeek row changed from `deepseek-v4-flash-vision-exp` to `deepseek-v4.1-flash`. DevPass's bare literal became `deepseek-v4.1-flash` first, and the opencode-go id has now caught up, so both DeepSeek routes name the same model again. One literal maps to one provider, and only the DevPass route appears in the fan-out map (the list of routes used for parallel dispatch), so the routes remain separate. The opencode-go row keeps its direct-dispatch-only note and its `--thinking max` pin. That pin is a tier this route carries.

&nbsp;

#### The Cline Listing's Limit

**Breaking:** The cline-pass DeepSeek row is now `cline-pass/cline-pass/deepseek-v4.1-flash`, with the `.pi` provider block and picker entry moved to match. This id is listing-only: no dispatch has been recorded for it, though Cline's own API lists `deepseek/deepseek-v4.1-flash`. Every attempt on 2026-09-11 with this id and the previously verified `cline-pass/cline-pass/deepseek-v4-flash` returned `429 "You have reached your monthly Clinepass limit"`. That shared failure identifies the account's quota, not the id, as the block. No context, output or price figure is claimed for the new row because none was measured. The cline-pass row names `cline-pass/cline-pass/deepseek-v4-flash` as the fallback until one V4.1 turn passes after the quota window resets.

## Dispatch Examples

#### Examples Follow the Roster

The quick-invocation snippet and child-session envelope previously used `deepseek-v4-flash-vision-exp`, the superseded opencode-go id. Both now use `deepseek-v4.1-flash`, matching the roster row each illustrates.

---

## Manual Testing

#### Id Checks Match Settings

The manual-testing playbook's id-format control had drifted from `.pi/settings.json`: its model id, expected `defaultModel` and skip list no longer matched the wired config. The skip list now accepts the quota blocker, so a `429` reads as `route never exercised` rather than as a pass or a model failure. The scenario contract and execution table were both updated with that expectation so the playbook cannot disagree with itself.
