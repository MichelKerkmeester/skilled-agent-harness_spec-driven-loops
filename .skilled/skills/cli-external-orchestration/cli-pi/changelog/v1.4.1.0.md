The `cli-pi` update keeps the provider guide aligned with the closed roster and the model selected by deep-loop fan-out.

> Spec folder: `specs/cli-external-orchestration/056-roster-drop-deepseek-api-pro-terra/`

## What's New at a Glance

- **The provider roster removes retired options.** `references/providers-and-models.md` removes the direct DeepSeek API provider, DeepSeek V4 Pro in every form, and GPT-5.6 Terra. The six providers are `openai-codex` (sol/luna), `minimax`, `xiaomi`, `opencode-go` (DeepSeek V4 Flash, Qwen 3.8 Max, GLM-5.3-Flash), `openrouter` and `cline-pass` (flash + GLM-5.3-Flash). The OpenRouter three-model allowlist and cline-pass flash/GLM routes are unchanged.
- **DeepSeek V4 Flash examples use `opencode-go`.** The bare `deepseek-v4-flash` literal is documented as opencode-go-fronted. Sections 3 and 5 of `references/providers-and-models.md` now use `--provider opencode-go --model deepseek-v4-flash --thinking max`, and no example uses the direct `--provider deepseek` dispatch shape. The `--thinking` lever semantics and flash max-tier pin policy are unchanged.
- **Deep-loop fan-out defaults to DeepSeek V4 Flash.** `PI_DEFAULT_MODEL` in `executor-config.ts` changed from `deepseek-v4-pro` to `deepseek-v4-flash`. The enforcement allowlists dropped `deepseek-v4-pro` and `gpt-5.6-terra`.
- **The frontmatter version advances.** It moved from `1.0.0.0` to `1.1.0.0`.
