This release gives cli-pi a single source of truth for its providers and models. Until now the provider roster, authenticated model ids, the `--thinking` effort lever, and the dispatch shapes were spread across `cli-reference.md` §13 and `SKILL.md`, so any roster drift had to be chased through two documents and the model guidance competed for space with the general CLI reference. Consolidating that surface into one dedicated, routable leaf makes the catalog the place callers look first and keeps the CLI reference focused on invocation mechanics.

The new `references/providers-and-models.md` is that catalog: it documents cli-pi's providers, their authenticated model ids, the standalone `--thinking off|minimal|low|medium|high|xhigh|max` effort flag, and the dispatch shapes, and it is registered as a routable leaf so the advisor can surface it directly. Its section 2 is restructured into a heading-plus-table block per provider so each provider's ids read as their own unit. `cli-reference.md` §13 and `SKILL.md` are trimmed to a compact residue that keeps the load-bearing facts — the passthrough reality, the `--thinking` scale, and the "don't copy Codex `-c` reasoning-effort syntax into Pi" caveat — and points at the new catalog for the full roster.

The roster itself was curated against the authoritative `PI_SUPPORTED_MODELS` set in `executor-config.ts` rather than a machine-local snapshot. `openai-codex` is kept to the base persona slugs `gpt-5.6-sol` / `gpt-5.6-luna` / `gpt-5.6-terra` — Pi has no `-fast` / `-pro` speed tiers, confirmed against `PI_SUPPORTED_MODELS`; `minimax` is kept to MiniMax-M3; `xiaomi` is kept to `mimo-v2.5-pro` and `mimo-v2.5-pro-ultraspeed`. The stale entries `gpt-5.3-codex-spark`, `gpt-5.4`, `gpt-5.4-mini`, `gpt-5.5`, the MiniMax-M2.7 variants, and the older mimo ids were removed. `gpt-5.6-terra` is retained on the authority of `PI_SUPPORTED_MODELS` even though it was absent from this machine's `models-store.json` snapshot.
