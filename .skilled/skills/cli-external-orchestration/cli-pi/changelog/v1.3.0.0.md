## What's New at a Glance

- **The catalog is directly discoverable.** `references/providers-and-models.md` lists cli-pi's providers, authenticated model IDs, the standalone `--thinking off|minimal|low|medium|high|xhigh|max` effort flag and dispatch shapes. It is registered as a routable leaf so the advisor can surface it directly.
- **Provider IDs are grouped by provider.** Section 2 now gives each provider a heading and table so its IDs read as a unit.
- **The CLI reference stays focused on invocation.** `cli-reference.md` §13 and `SKILL.md` retain the passthrough reality, the `--thinking` scale and the warning not to copy Codex `-c` reasoning-effort syntax into Pi, then point to the catalog for the full roster.
- **The roster follows `PI_SUPPORTED_MODELS`.** The catalog was curated against the set in `executor-config.ts`, not a machine-local snapshot. It retains `gpt-5.6-terra` even though that model was absent from this machine's `models-store.json` snapshot.
- **Provider entries use their supported model IDs.** `openai-codex` keeps only the base persona slugs `gpt-5.6-sol`, `gpt-5.6-luna` and `gpt-5.6-terra`, with no `-fast` or `-pro` speed tiers. `minimax` is limited to MiniMax-M3. `xiaomi` is limited to `mimo-v2.5-pro` and `mimo-v2.5-pro-ultraspeed`.
- **Stale model IDs are removed.** The roster drops `gpt-5.3-codex-spark`, `gpt-5.4`, `gpt-5.4-mini`, `gpt-5.5`, MiniMax-M2.7 variants and older mimo IDs.
