This first release makes Pi the sixth workflow mode in the external command-line interface (CLI) orchestration hub.

> Spec folder: `../../../specs/cli-external-orchestration/031-cli-pi-creation/001-pi-contract-pin/implementation-summary.md`

## What's New at a Glance

- **Pi's route refuses self-invocation.** A guarded check confirms the `pi` program is available. The packet does not add a second advisor identity or a packet-local execution adapter.
- **Routing guidance covers print, JSON and RPC.** The local Pi contract pin confirmed the headless (without an interactive interface) entry point, a JSON (structured data format) event stream and persistent RPC (remote procedure call) surface.
- **The local contract pin confirms Pi's installed version and failure behavior.** It records the failure when a provider is missing and inconsistent failure exit codes (numbers returned when a command fails). The pin also confirms extension validation and the trusted install verb for `pi-subagents`.
- **Native Pi resources are distinct from community packages.** Pi's native skills and prompt-template discovery remain documented but unconfirmed. `pi-subagents` and `pi-mcp-extension` are community packages, not first-party Pi features.
