The Xiaomi roster rows in the provider reference move to the v2.6 generation:
`mimo-v2.6-pro` and `mimo-v2.6-pro-ultraspeed`. A reference that names what the gateway
serves is only useful while it names the generation the gateway answers for — this entry
is that catch-up.

## What Changed

#### Changed

- `references/providers-and-models.md`: the two Xiaomi roster rows, mechanically and
  case-preserving. The low-latency tier note travels with the `-ultraspeed` row, because
  the tier structure it describes is the one being renamed, not a separate fact.
- The skill's own version, so the reference's audience can tell which generation it
  documents.

#### Not Changed

- The dated evidence cell in the allowlist-smoke playbook: it records the capture it made
  against the enforcement source of that moment, and that record stays.
- The changelog history: these releases shipped the ids they shipped.

## Why Now

The enforcement moved in the same cutover — the deep-loop Pi allowlist, its fan-out
mirrors, the provider map and the pairing tests — so the reference, the enforcement and
the tests now read one generation. Whether the installed pi's bundled catalogs serve the
v2.6 spellings yet is a question for the machine that runs pi; the resolution check
belongs to the operator, not to this file.
