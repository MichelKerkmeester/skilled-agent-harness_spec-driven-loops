A build dispatched through Pi could read for forty minutes and never edit. Two things caused it,
and the skill now names both.

## What Changed

#### Fixes

- **Build briefs carry one change each.** A new ALWAYS rule asks for one change per brief, naming the
  file, the edit and the check that proves it, with the changes chained as separate dispatches. A
  DeepSeek V4.1 Flash brief that carried five changes across five runtime files read about 995,000
  characters in 25 minutes and wrote nothing.
- **pi-blackhole no longer compacts a dispatched child.** The operator's global packages load in a
  child session, and pi-blackhole auto-compacts at 272,000 tokens mid-run, replacing what the child
  has read with a structural summary, so a child still reading starts again. A new dispatch gotcha
  says to set `PI_BLACKHOLE_PASSIVE=true` in the child's environment. The child envelope in
  `references/providers-and-models.md` does not carry the variable yet, because that file holds
  another session's uncommitted edits.
