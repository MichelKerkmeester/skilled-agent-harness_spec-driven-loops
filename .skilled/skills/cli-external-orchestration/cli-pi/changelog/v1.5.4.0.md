This release adds two Pi dispatch guidelines for work that reads without editing.

## Why This Release

A build dispatched through Pi could read for forty minutes and never edit. A DeepSeek V4.1 Flash brief with five changes across five runtime files read about 995,000 characters in 25 minutes and wrote nothing.

## What's New at a Glance

- **Build briefs carry one change each.** The new ALWAYS rule asks each brief to name the file, the edit and the check that proves it. Chain each change as a separate dispatch.
- **Keep a dispatched child from starting over.** When the operator's global packages load in a child session, pi-blackhole auto-compacts at 272,000 tokens. It replaces what the child has read with a structural summary, so a child still reading starts again.

## Upgrade

Set `PI_BLACKHOLE_PASSIVE=true` in the child's environment. The child envelope in `references/providers-and-models.md` does not carry this variable yet.
