This release adds two Pi dispatch guidelines. They cover work that reads without editing.

&nbsp;

## Why This Release

A build dispatched through Pi could read for forty minutes and never edit. A DeepSeek V4.1 Flash brief covered five changes across five runtime files. It read about 995,000 characters in 25 minutes and wrote nothing.

&nbsp;

## What's New at a Glance

- Build briefs carry one change each.
  - The new ALWAYS rule asks each brief to name the file, the edit and the check that proves it.
  - Chain each change as a separate dispatch.
- Keep a dispatched child from starting over.
  - When the operator's global packages load in a child session, pi-blackhole auto-compacts at 272,000 tokens.
  - pi-blackhole replaces what the child has read with a structural summary.
  - So a child still reading starts again.

&nbsp;

## Upgrade

Set `PI_BLACKHOLE_PASSIVE=true` in the child's environment. The child envelope in `references/providers-and-models.md` does not carry this variable yet.
