# v1.9.5.0, Each Repository Hook Runs Once

Codex now runs each repository hook once. Codex already loads a trusted checkout's own `.codex/hooks.json`, so the copies `install-codex-hooks.mjs` wrote into the user-wide `~/.codex/hooks.json` registered every hook a second time. Each Codex event ran it twice, and the copies ran this repository's hooks in Codex sessions started anywhere.

> Part of [Skilled v4.0.0.2](../../../../changelog/skilled/v4.0.0.2.md).
>
> Spec folder: `specs/system-skill-advisor/030-pi-skill-orchestrator-based-research-refinement` (Level 2)

## What's New at a Glance

- **The installer only removes.** `.skilled/bin/install-codex-hooks.mjs` takes this repository's entries out of `~/.codex/hooks.json`, including any whose hook script no longer exists, and keeps every third-party entry. It backs the file up before changing it, and `--check` reports `duplicate=N` while a copy remains.
- **The docs say where Codex finds the hooks.** The README, the hook contract and the full-auto hooks scenario say Codex reads the checkout's `.codex/hooks.json`, and no step sends a tester to the user-wide file to find them.

## Upgrade

Codex loads `.codex/hooks.json` only for a checkout that `~/.codex/config.toml` marks as trusted, so trust the checkout first. Then run `node .skilled/bin/install-codex-hooks.mjs` once to remove the copies an earlier version wrote. `node .skilled/bin/install-codex-hooks.mjs --check` then prints `install-codex-hooks: OK`.
