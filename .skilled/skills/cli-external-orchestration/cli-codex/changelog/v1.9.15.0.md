# v1.9.15.0, the Default Model Is GPT-6 Luna

The skill default is now `gpt-6-luna` at `medium` on the `fast` tier. It matches `~/.codex/config.toml`. `gpt-5.5` stays on the roster as an alternate. But a ChatGPT-account login refused it. So the docs now say a login accepts only the models its plan lists. They also say a caller passes `-m <model>` when in doubt.

&nbsp;

## What's New at a Glance

- The default is `gpt-6-luna`.
  - `SKILL.md`, `README.md`, the references, the prompt card and the prompt templates name it as the zero-input default.
  - The canonical dispatch is `--model gpt-6-luna -c model_reasoning_effort="medium" -c service_tier="fast"`.
- The plan limit is written down.
  - A ChatGPT-account login accepts only the models its plan lists.
  - So pass `-m <model>` when in doubt.
- The roster keeps five models.
  - `gpt-5.5`, `gpt-5.6-terra`, `gpt-6.1-terra` and `gpt-6-sol` remain documented alternates.
  - The `.codex/agents/*.toml` pins name `gpt-6-luna` too.
  - That is because the generator `system-spec-kit/runtime/cli/codex/sync-agents.cjs` now defaults to it.
- The playbook follows the default.
  - The default-invocation and default-model scenarios dispatch `gpt-6-luna`.
  - The model-lock scenario smoke-tests the four alternates.
  - The model-lock scenario's feature file is now `cli-invocation/default-model-lock.md`.

&nbsp;

## Upgrade

No migration is required for a caller that already passes `--model` explicitly. A caller that relied on the documented default now sends `gpt-6-luna`. Pass `-m gpt-5.5` to keep the old model where the plan lists it.
