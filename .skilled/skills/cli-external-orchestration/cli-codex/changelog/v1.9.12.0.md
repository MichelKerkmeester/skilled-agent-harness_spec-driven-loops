# v1.9.12.0, The Child Preamble Rule Applies to Every Dispatch

An earlier prose pass joined two sentences in the `AI_SESSION_CHILD=1` rule. The result read as if the preamble only needs copying when a session goes through the per-session worktree wrapper. A dispatch that skips the wrapper would follow that condition and drop the preamble. A child given only the environment variable still stops to ask the documentation-scope question and writes nothing.

The rule now opens with the instruction on its own. Copy the preamble to the top of every non-interactive prompt. The wrapper keeps its own line below it, with the same path and the same note that a dispatched `codex exec` is a sub-session that shares the parent's worktree.

Nothing else in the rule moved, and no flag, path, model id or command changed.

> Spec folder: `specs/sk-doc/072-skill-routing-and-clarity/012-alignment-remediation` (Level 2)

&nbsp;

## What's New at a Glance

- **The preamble rule is unconditional.** It applies to every non-interactive dispatch, whether or not the wrapper launched the session.
- **The wrapper keeps its own line.** The path `.skilled/bin/worktree-session.sh` and the shared-worktree behavior are unchanged.
- **Nothing routes differently.** No intent dictionary, resource map, loading level, guard or default changed.
