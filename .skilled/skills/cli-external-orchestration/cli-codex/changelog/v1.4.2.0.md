cli-codex was missing the Provider Auth Pre-Flight. cli-opencode v1.3 already had it. v1.4.2.0 adds the Smart Fallback pattern to `SKILL.md` §3. This is part of harmonizing all five `cli-*` siblings. They share one structural surface.

> Spec folder: `specs/052-cli-skill-patterns/` (Level 2)

## What's New at a Glance

- **The pre-flight ports cli-opencode v1.3.** `cli-codex` uses the same ASK-not-substitute language. It uses the same three-state column structure. Its detection command, variable names, model invocation and login commands are the substitutions.
- **Credential checks set two session flags.** A one-shot bash pre-flight (a single shell check) reads `$OPENAI_API_KEY`. It also reads the ChatGPT OAuth output from `codex auth status`. Then it captures `OPENAI_KEY_OK` and `CODEX_OAUTH_OK`. Its three states are `default-available`, `API-key-missing-OAuth-ready` and `both-missing`.
- **Missing credentials prompt before fallback.** When the API key is missing but OAuth is ready, the prompt offers an OAuth fallback in an A/B/C menu. When both are missing, it shows login commands including `codex login`. Neither prompt switches routes without asking.
- **Auth errors refresh the check.** A mid-dispatch auth error invalidates cached results. It reruns the pre-flight before retry. This matches the donor's cache-invalidation contract.
- **The default invocation stays explicit.** In `default-available`, the section shows `codex exec --model gpt-5.5 -c model_reasoning_effort="medium" -c service_tier="fast"`.
- **The addition preserves the existing layout.** `cli-codex` already had a Default Invocation block. It was added in an earlier release. Provider Auth Pre-Flight was the only missing subsection. The new subsection sits between Prerequisites and Default Invocation. That matches cli-opencode's ordering. No existing content was modified. No subsections were renamed or reordered.

## Upgrade

No invocation breaking changes are introduced. Existing `codex exec` dispatches keep working. At session start, AI consumers should run the Provider Auth Pre-Flight. Do this before the first dispatch. First check `codex auth status 2>&1`. Then check `env | grep -E '^OPENAI_API_KEY'`. Cache `OPENAI_KEY_OK` and `CODEX_OAUTH_OK` for the session. Then apply the three-state decision tree if `OPENAI_KEY_OK=0`.
