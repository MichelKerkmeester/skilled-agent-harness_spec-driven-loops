cli-codex was missing the Provider Auth Pre-Flight that cli-opencode v1.3 already had. v1.4.2.0 adds the Smart Fallback pattern to `SKILL.md` §3 as part of harmonizing all five `cli-*` siblings around a shared structural surface.

> Spec folder: `specs/052-cli-skill-patterns/` (Level 2)

## What's New at a Glance

- **The pre-flight ports cli-opencode v1.3.** `cli-codex` uses the same ASK-not-substitute language and three-state column structure. Its detection command, variable names, model invocation and login commands are the substitutions.
- **Credential checks set two session flags.** A one-shot bash pre-flight (a single shell check) reads `$OPENAI_API_KEY` and the ChatGPT OAuth output from `codex auth status`, then captures `OPENAI_KEY_OK` and `CODEX_OAUTH_OK`. Its three states are `default-available`, `API-key-missing-OAuth-ready` and `both-missing`.
- **Missing credentials prompt before fallback.** When the API key is missing but OAuth is ready, the prompt offers an OAuth fallback in an A/B/C menu. When both are missing, it shows login commands including `codex login`. Neither prompt switches routes without asking.
- **Auth errors refresh the check.** A mid-dispatch auth error invalidates cached results and reruns the pre-flight before retry, matching the donor's cache-invalidation contract.
- **The default invocation stays explicit.** In `default-available`, the section shows `codex exec --model gpt-5.5 -c model_reasoning_effort="medium" -c service_tier="fast"`.
- **The addition preserves the existing layout.** `cli-codex` already had a Default Invocation block, added in an earlier release, and Provider Auth Pre-Flight was the only missing subsection. The new subsection sits between Prerequisites and Default Invocation, matching cli-opencode's ordering, with no existing content modified or subsections renamed or reordered.

## Upgrade

No invocation breaking changes are introduced, and existing `codex exec` dispatches keep working. At session start, before the first dispatch, AI consumers should run the Provider Auth Pre-Flight by checking `codex auth status 2>&1` followed by `env | grep -E '^OPENAI_API_KEY'`, cache `OPENAI_KEY_OK` and `CODEX_OAUTH_OK` for the session, then apply the three-state decision tree if `OPENAI_KEY_OK=0`.
