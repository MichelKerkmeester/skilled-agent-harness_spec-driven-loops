Before this release, OpenAI provider and model details for `cli-codex` had no single owner. Roster changes had to be made in both `SKILL.md` and `references/cli-reference.md` §5, where the duplicated facts could silently drift. The release gives those details one dedicated home.

> Spec folder: `.opencode/specs/cli-external-orchestration/033-per-mode-provider-model-reference/`

## What's New at a Glance

- **`references/providers-and-models.md` is the single-source catalog.** It names the OpenAI provider and states that ChatGPT OAuth is the only access method. The effort ceilings are `xhigh` for `gpt-5.5` and `max` for both `gpt-5.6-luna` and `gpt-5.6-terra`. `gpt-5.6-sol` has a ceiling of `ultra`.
- **The default and effort controls are documented.** The catalog records the `gpt-5.5 medium fast` default and the default invocation shape. It also records the `-c model_reasoning_effort=` lever and its eight-level ladder. Dispatch envelopes are listed there too.
- **The catalog is a routable leaf for model and effort intents.** The smart router can load it for those requests. Section 2 uses a per-provider heading and table with `### OpenAI`, so a second provider can use a sibling heading without a schema change (a change to the table's structure).
- **The former rosters now point to the catalog.** `SKILL.md` Model Selection and `references/cli-reference.md` §5 MODEL SELECTION keep only the routing decision in compact residues and point to `references/providers-and-models.md` for the full roster, ceilings and ladder. Config-profile mechanics stay inline in `references/cli-reference.md`.
- **The model roster and behavior stay unchanged.** No model was added or removed. Routing behavior, model, default and rule stayed unchanged. This documentation-only pass extracts the catalog, trims the former rosters and restructures Section 2.
