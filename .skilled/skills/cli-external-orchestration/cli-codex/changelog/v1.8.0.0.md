The provider/model facts for cli-codex — the four OpenAI model ids and their per-model effort ceilings, the `gpt-5.5 medium fast` default, and the `-c model_reasoning_effort=` lever with its 8-level ladder — were duplicated across `SKILL.md` and `references/cli-reference.md` §5 with no single owner, so any roster change had to be edited in two places and could silently drift. This release gives cli-codex one dedicated model catalog and demotes the two former homes to a compact residue plus a pointer.

`references/providers-and-models.md` is the new single-source catalog: the OpenAI provider (ChatGPT OAuth only), the four models and their ceilings (`gpt-5.5` ≤ `xhigh`, `gpt-5.6-luna` / `gpt-5.6-terra` ≤ `max`, `gpt-5.6-sol` ≤ `ultra`), the default-invocation shape, the `model_reasoning_effort` effort lever and its 8-level ladder, and the dispatch envelopes. It is registered as a routable leaf so the smart router can load it on model/effort intents. Its section 2 is laid out as a per-provider heading + table (`### OpenAI`) so a second provider would slot in as a sibling heading rather than force a schema change.

`references/cli-reference.md` §5 MODEL SELECTION and the `SKILL.md` Model Selection roster were trimmed to a compact residue that keeps only the routing decision (and the config-profile mechanics inline), each pointing at the new catalog for the full roster, ceilings, and ladder. No routing behavior, model, default, or rule changed — this is a documentation single-sourcing pass. cli-codex had no roster curation this release (no model added or removed): catalog extraction, trim, and the section-2 restructure only.
