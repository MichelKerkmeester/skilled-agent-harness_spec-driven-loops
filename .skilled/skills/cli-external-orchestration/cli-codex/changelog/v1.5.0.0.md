# v1.5.0.0, Codex Requests Route Through the Hub

Codex requests now route through `cli-codex` under `cli-external-orchestration`.

- `cli-codex` is a nested workflow packet under the hub.
- The retired contract returns within the hub.
- The hub adds workflow mode `cli-codex`.

The revived contract keeps its dispatch safeguards.

- Availability remains fail-closed.
- Codex self-invocation remains prohibited.
- Codex requests use the mode through `cli-external-orchestration`.

Orchestrated execution reuses the existing path.

- Execution delegates to the existing deep-loop runtime.
- It does not add a second process path.

> [!IMPORTANT]
> 1 change can break an existing setup. Read it before you update.
>
> 1. Codex requests now use the hub's workflow mode. [Before You Start](#c-before-you-start)

## Codex Dispatch

Dispatch keeps its checks and uses one execution path.

#### Contract Has a Nested Home <a id="c-contract-has-a-nested-home"></a>

- The retired skill contract moved into `cli-external-orchestration/cli-codex/`.
- It moved there as a nested mode.
- Its contract follows nested-packet metadata rules.

#### Dispatch Checks Codex First <a id="c-dispatch-checks-codex-first"></a>

- Before dispatch, `command -v codex` must succeed.
- Codex self-invocation remains prohibited.
- Availability remains fail-closed.

#### Execution Keeps One Path <a id="c-execution-keeps-one-path"></a>

- Orchestrated execution delegates to the existing deep-loop `cli-codex` adapter.
- It continues through the deep-loop runtime.
- It does not add a second process path.

&nbsp;

## Hub Integration

The hub now registers the new mode and resolves its paths.

#### Mode and Paths Align <a id="c-mode-and-paths-align"></a>

- The hub registry and lexical router now include workflow mode `cli-codex`.
- Operator and reference paths now resolve from the renamed hub topology.
- Codex requests use the mode through `cli-external-orchestration`.
