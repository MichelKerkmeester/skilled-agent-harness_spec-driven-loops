This release corrects two things the GPT-6 cutover left wrong. The default-model scenarios in the playbook agree with `SKILL.md` again, and every effort-ceiling statement gives `gpt-5.6-terra` the `ultra` ceiling that Codex's model cache reports.

> Spec folder: `specs/cli-external-orchestration/077-gpt-6-luna-sol-cutover` (Level 2)

---

## What Changed

#### Model Roster

- **Terra reaches `ultra`** -- v1.9.1.0 gave `gpt-5.6-terra` a `max` ceiling, but Codex's model cache lists `low` through `ultra` for it. The skill, the README, the provider reference and the prompt templates now say `ultra`, and Sol is no longer called the only model that reaches it.
- **`gpt-6-astra` stays off the roster** -- v1.9.1.0 said Terra has no GPT-6 counterpart in Codex's catalog. More exactly, the catalog names no GPT-6 successor to Terra, but it does list a third GPT-6 model, `gpt-6-astra`, described as frontier intelligence for the most demanding work, with a `low` to `ultra` ladder. This release does not add it; the roster stays `gpt-5.5`, `gpt-6-luna`, `gpt-5.6-terra` and `gpt-6-sol`.

#### Manual Testing Playbook

- **CX-001 and CX-002 test the real default** -- the cutover's playbook sweep had both scenarios call `gpt-6-luna` the documented default, and CX-002's roster loop listed Luna twice and left Sol out. Both scenarios again assert `gpt-5.5` at `medium`, CX-002 runs Luna, Terra and Sol once each and reads all three outputs, and it notes that the fan-out's own `gpt-6-luna` fallback is outside its scope.
