Codex dispatch now stops before it starts when no OAuth session is active.

## Why This Release

Before this release, the pre-flight decision used both `OPENAI_KEY_OK` and `CODEX_OAUTH_OK`.

## What's New at a Glance

- **Codex sign-in now follows one ChatGPT OAuth route.** The pre-flight and reference guidance follow the same sign-in requirement.

---

## Codex Authentication

#### Use ChatGPT OAuth

`codex login` starts a browser sign-in with a ChatGPT account. It requires a ChatGPT Plus, Pro, Business, Edu or Enterprise account. **Breaking:** `OPENAI_API_KEY` is no longer offered for Codex authentication.

&nbsp;

#### Wait for Sign-In

The pre-flight now checks only for an OAuth session. When Codex is not logged in, `cli-codex` asks you to run `codex login` and waits instead of dispatching. The model roster, routing, sandbox modes and every dispatch rule remain unchanged.

&nbsp;

#### Remove API-Key Setup

`cli_reference.md` sections 3 (Authentication), 13 (Troubleshooting) and 14 (Environment Variables) remove the API-key method, `OPENAI_API_KEY` and the `platform.openai.com` key-management link. The generic NEVER rule against sending API keys or passwords in prompts remains because it covers secret handling, not authentication.

---

## Upgrade Notes

If a machine relied on `OPENAI_API_KEY` for Codex, run `codex login` once to establish a ChatGPT OAuth session. Dispatch flags are otherwise unchanged.
