Seven playbook-authoring bugs surfaced when the cli-codex manual playbook ran against Codex 0.125.0. This release restores the affected scenarios to the working pattern. The remaining authoring-related failures traced to playbook drift rather than Codex runtime issues and are expected to pass on the next re-run.

> Spec folder: `.opencode/specs/system-spec-kit/026-graph-and-context-optimization/011-manual-testing-playbook-coverage-and-run/` (Level 3)

## What's New at a Glance

- **Five prompts now include the pre-approved Gate 3 preamble.** CX-008, CX-016, CX-018, CX-021 and CX-022 add `Spec folder: <path> (pre-approved, skip Gate 3)` as required by SKILL.md ALWAYS rule 8. Codex previously inherited the project's `CLAUDE.md` and `AGENTS.md` gate rules and paused in non-interactive `exec` mode for a spec-folder choice no human would answer. The preamble lets the dispatched task run.
- **CX-014 keeps the intended off-by-one bug.** The `printf` block was meant to create a deliberately broken JavaScript file, but `let i = 0.` and `I <= arr.length. I++` stopped Codex from parsing it. It now writes `for (let i = 0; i <= arr.length; i++)`, leaving the off-by-one as the only flaw. `codex exec` also redirects stdin with `< /dev/null` as required by ALWAYS rule 5.
- **CX-017 resumes from the actual session UUID.** The prompt asked the model to end with `SESSION_ID: <id>`, but it treated the marker literally and emitted `cx017`, making resume calls use an invalid id. The scenario now extracts the UUID from Codex's verbose header using `session id: [a-f0-9-]+` with `ls -t ~/.codex/state/` as a fallback. It removes `--sandbox` from `codex exec resume` because the subcommand rejects it as an invalid flag and redirects stdin from `/dev/null` for every call.
- **The playbook uses a lowercase filename.** `MANUAL_TESTING_PLAYBOOK.md` is now `manual_testing_playbook.md`, and scenario references use the new name. The sk-doc template now defaults `/create:testing-playbook` to the lowercase convention for future runs.
- **The `--search` diagnosis is corrected.** Codex 0.125.0 accepts the flag, so flag positioning did not explain CX-019 and CX-024, neither of which was patched. Their failures may relate to entitlement or rate limits.

## Upgrade

- **Re-pull and re-run.** Operators using the cli-codex manual playbook should do this to get the corrected scenarios.
- **Keep existing dispatch defaults.** Scripts using the documented `gpt-5.5 + medium + fast` defaults are unaffected. The release makes no skill-surface changes.
