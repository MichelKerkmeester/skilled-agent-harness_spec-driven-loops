# v1.9.11.0, long prose lines become short ones

Readers met fifteen single lines that each ran 400 to 1,300 characters. Rules 11 to 18, four dispatch gotchas and the memory handback paragraph were walls of text holding several instructions inside one line, so a reader had to separate them before acting. Every one is now short sentences and short lists, and the commands, paths, flags, model ids and numbers are the ones that were already there.

> Spec folder: `specs/sk-doc/072-skill-routing-and-clarity/010-prose-clarity-pass` (Level 2)

&nbsp;

## What's New at a Glance

- **The rules read in one pass.** Each numbered rule states its instruction first and its background after it, and a rule that lists several steps carries them as a short list.
- **The gotchas break at the idea.** The top-level `--search` flag, the `--sandbox workspace-write` socket limit and the `</dev/null` stdin rule each run as two or three lines, with the failure on one line and the fix on the next.
- **The manifest fields are a list.** The `DESIGN_DISPATCH_MANIFEST v1` block names its five fields one per line rather than inside a sentence.
- **Nothing was dropped.** Every command, flag, path, environment variable, model id and observed version appears exactly as it did before.
- **Nothing routes differently.** No intent dictionary, resource map, loading level, guard or default changed, and the machine blocks are byte for byte what they were.

&nbsp;

## Upgrade

Nothing to do. The prose is the only change.
