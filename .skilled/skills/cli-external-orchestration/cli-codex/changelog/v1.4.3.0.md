# cli-codex v1.4.3.0: Pre-planning density guidance

v1.4.3.0 adds planning-density guidance to the cli-codex prompt-quality card, alongside its existing framework-selection guidance. The release changes documentation only.

> Spec folder: `specs/skilled-agent-orchestration/113-cli-devin-prompt-quality/006-cross-cli-rcaf-propagation/`

## Why This Release

An empirical run in `specs/skilled-agent-orchestration/113-cli-devin-prompt-quality/003-eval-loop/` on cli-devin SWE 1.6 found that medium-density pre-planning scored ~10-15% higher in aggregate than dense pre-plans with 4+ steps and full I/O contracts per step. The finding likely generalizes across CLI orchestrators because just-enough structure without too much is a model-agnostic prompt-engineering principle.

The run's other two SWE-1.6 findings, "standard-over-strict bundle-gate" and "framework-dominates-anti-hallucination," were not propagated because they came from a small coding-specialized model and may not generalize to claude-opus-4.7, gpt-5.5 and deepseek-v4-pro. `specs/skilled-agent-orchestration/113-cli-devin-prompt-quality/007-cross-model-validation/` will test whether they hold on deepseek-v4-pro and kimi-k2.6 before any cross-CLI propagation.

## What's New at a Glance

- **The card now recommends medium-density pre-planning.** The "Pre-planning density" note follows the task-to-framework table in `assets/prompt-quality-card.md` §3 and defines medium plans as 3-4 ordered steps with per-step acceptance and verification. It complements the existing RCAF default in that section, which mirrors `sk-prompt`'s general default.
- **`SKILL.md` keeps its body while its version metadata advances.** The frontmatter version moves from 1.4.2.0 to 1.4.3.0.
