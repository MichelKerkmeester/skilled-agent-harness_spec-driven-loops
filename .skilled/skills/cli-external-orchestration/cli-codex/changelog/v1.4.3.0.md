# cli-codex v1.4.3.0: Pre-planning density guidance

v1.4.3.0 adds planning-density guidance to the cli-codex prompt-quality card. The card keeps its existing framework-selection guidance. The release changes documentation only.

&nbsp;

## Why This Release

An empirical run on cli-devin SWE 1.6 found a difference. Medium-density pre-planning scored ~10-15% higher in aggregate than dense pre-plans. Dense pre-plans had 4+ steps and full I/O contracts per step. The run is in `specs/skilled-agent-orchestration/113-cli-devin-prompt-quality/003-eval-loop/`.

The finding likely generalizes across CLI orchestrators. That is because just-enough structure without too much is a model-agnostic prompt-engineering principle.

The run had two other SWE-1.6 findings. They are "standard-over-strict bundle-gate" and "framework-dominates-anti-hallucination." Neither was propagated. Both came from a small coding-specialized model. They may not generalize to claude-opus-4.7, gpt-5.5 and deepseek-v4-pro. `specs/skilled-agent-orchestration/113-cli-devin-prompt-quality/007-cross-model-validation/` will test whether they hold on deepseek-v4-pro and kimi-k2.6. That test comes before any cross-CLI propagation.

&nbsp;

## What's New at a Glance

- The card now recommends medium-density pre-planning.
  - The "Pre-planning density" note follows the task-to-framework table in `assets/prompt-quality-card.md` §3.
  - The note defines medium plans as 3-4 ordered steps.
  - Each step has acceptance and verification.
  - The note complements the existing RCAF default in that section.
  - That default mirrors `sk-prompt`'s general default.
- `SKILL.md` keeps its body while its version metadata advances.
  - The frontmatter version moves from 1.4.2.0 to 1.4.3.0.
