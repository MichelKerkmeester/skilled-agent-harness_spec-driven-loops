# v1.9.10.0, the routing section is a short summary

The routing section used to hold eighty-six lines. Those lines were probes, guards, loading tables and intent dictionaries. A reader reached how the packet works only after all of it.

It is now six sentences. They say what selects this packet. They name the two leaves a dispatch starts from. They give the baseline it loads first.

All of that machinery moved to a new `## 9. MACHINE ROUTER` section. That section closes the file. Not a word changed.

> Spec folder: `specs/sk-doc/072-skill-routing-and-clarity/008-cli-and-mcp-hubs` (Level 2)

## What's New at a Glance

- **The routing section now reads as prose.** A reader learns which hub signal arrives here. A reader learns which leaves a dispatch starts from. A reader learns where the deterministic router lives.
- **The router moved, it did not change.** The prerequisite probe sits word for word in the last section of the file. So do the self-invocation guard, the loading-level table and the intent dictionaries.
- **The six-step call sequence is stated in one place.** The shared helpers are documented once in `shared-smart-router.md`. This packet points there. So the two copies cannot drift apart.
- **Two section pointers were repointed.** The notice at the top now names the machine router section. So do the reference loading notes. Neither names the routing section that used to hold the router.

Nothing to do. No routing behavior changed. No leaf set, model default, sandbox mode or dispatch flag changed.
