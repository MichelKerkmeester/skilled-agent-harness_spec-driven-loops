# /doctor:ci Presentation Contract

Presentation source of truth for `/doctor:ci <target>`. The router owns target resolution and asset loading. Workflow YAML owns execution. This file owns visible prompts, plan layouts, result displays, the troubleshooting table and next-step suggestions.

## 1. ARGUMENT FAILURE

Every argument failure happens before any workflow YAML loads, prints the wording below with the bracketed parts filled in, and ends with the status line. Nothing is read or changed.

| Situation | Wording |
|-----------|---------|
| The first token is not a target | `Unknown target: [target]` then `Try: /doctor:ci menu` then `STATUS=FAIL ERROR="unknown_target"` |
| A flag no target accepts | `Unknown flag: [flag]` then `Accepted for [target]: [flags]` then `STATUS=FAIL ERROR="unknown_flag"` |
| A flag that belongs to another target | `Flag '[flag]' is not valid for target '[target]'. Did you mean /doctor:ci [suggested-target] [flag]?` then `STATUS=FAIL ERROR="cross_target_flag_injection"` |

## 2. STARTUP PRESENTATION

This command is always interactive and has no `:auto` mode. With no target, `report` runs because it only reads. The menu below appears for `menu`, `list` and `?`. Ask it once, then wait.

```text
What do you want to do with the CI workflows?

1) report
2) scaffold
3) toggle
X) Cancel
```

Accepted answers:

| Answer | Result | Meaning |
|--------|--------|---------|
| `1` | target = `report` | List every workflow with its switch state, triggers, filters and drift flags. Reads only |
| `2` | target = `scaffold` | Create one new workflow from the workflow standards templates, after you approve the whole file |
| `3` | target = `toggle` | Turn one CI switch from the repository CI profile off or back on, after you approve the exact command |
| `X`, empty, `cancel` | `STATUS=CANCELLED ACTION=cancelled` | Stop. Nothing changes |

On any other response, re-emit the menu once. On a second invalid response, return `STATUS=FAIL ERROR="unknown_selection"`.

Valid targets: report, scaffold, toggle

## 3. DASHBOARD AND PLAN LAYOUT

### Route Manifest Display

Render this table for `menu`, `list` or `?`. Values should mirror `_routes.yaml`.

| Target | Workflow | Mutation Class | One-Line Purpose |
|--------|----------|----------------|------------------|
| `report` | `doctor-ci-report.yaml` | read-only | List every workflow with its switch state, triggers, path filters, purpose and drift flags, and name the newest non-rebuild commit on the default branch |
| `scaffold` | `doctor-ci-scaffold.yaml` | mutates | Create one new `.github/workflows/` file from the standards templates, after an explicit yes |
| `toggle` | `doctor-ci-toggle.yaml` | mutates | Set or clear one switch variable from the repository CI profile, after an explicit yes |

### Setup Dashboard

Render this compact panel after target resolution and before YAML execution when the target or flags were non-trivial.

```text
DOCTOR ROUTE SETUP
Target: [target]
Workflow: .skilled/commands/doctor/assets/[yaml]
Mutation class: [the target's mutating value in _routes.yaml]
Execution mode: INTERACTIVE
Setup values: [key=value list]
Presentation: .skilled/commands/doctor/assets/doctor-ci-presentation.txt
Next: load workflow YAML
```

### Report Summary

Render the script's table as returned, one row per workflow, under this header.

```text
CI WORKFLOW REPORT
Workflows: [n]  Jobs: [n]
Variables: [none | NAME=state for each variable that is set | unknown (reason)]
Profile: [default | repo | cli | git-config] ([the profile path, when there is one])[; ignored [path], written for [repository], this repository is [current or unknown]; shown only when the skill-folder profile names another repository]
Newest non-rebuild SHA: [40 hex | none] ([reason])

[table: Workflow | Switch | Jobs | Events | Filters | Drift flags | Purpose]

Not checked: path-parity, shell-strict-mode, matrix-guidance. The workflow standards packet owns these rules, so a clean row is not a pass for them.
```

Switch values: `on` (every job runs), `off` (every job is skipped by a variable set to off), `partial` (some jobs skip and some run), `missing` (no job carries a switch while the CI profile requires one) and `unknown` (gh could not be read). A variable is shown as `off`, `unset`, `other` or `unknown`, never by its value. The variables are the profile's declared switches, then any other name a workflow compares against `off`.

### Scaffold Plan And Approval

```text
WORKFLOW SCAFFOLD PLAN
Target file: .github/workflows/[name].yml
Templates: .skilled/skills/sk-code/sk-code-ci/assets/workflow-template.yml, .skilled/skills/sk-code/sk-code-ci/assets/job-block-template.yml
Switch group: [a group from the CI profile, here TESTS|REPORTS|REVIEW|FRESHNESS|MESSAGES | none]
Timeout: [n] minutes
README rows to add by hand: [one row per table the profile's workflowsReadme lists | none, the profile names no README]

--- proposed file ---
[the whole file]
--- end of file ---

Write this file? [yes/no]
```

With `--dry-run`, follow the plan with `Dry run: nothing was written.` and stop without asking.

A refused name prints one of these lines, `STATUS=FAIL ERROR="refused"` and exits without a plan:

```text
REFUSE: the target path already exists; scaffold creates new workflows only
REFUSE: [name] is a protected workflow
REFUSE: [name] is not a bare lowercase hyphen-case name ending in .yml
```

### Toggle Plan And Approval

```text
SWITCH CHANGE PLAN
Variable: [name]
Now: [on|off|unknown] ([unset|set to off|set to another value|not readable])
Change: [off|on]
Covers: [the workflows whose jobs read the variable]
Required checks: not read ([reason]); the ruleset refusal was not applied
Command: [gh variable set [name] --body off | gh variable delete [name]]
Undo: [gh variable delete [name] | gh variable set [name] --body off]
Run this command? [yes/no]
```

The `Required checks` line appears only for a change to off when the planner could not read the branch ruleset, so no required status check was checked. Leave it out otherwise.

Every display the toggle prints carries this one extra line immediately before its status line when the skill-folder profile names another repository:

```text
Profile: ignored [path], written for [repository], this repository is [current or unknown]; the protected workflows it lists are not checked
```

That profile is the one this repository committed, so the protected workflows and the `neverOff` names it lists are not checked here. A change to `off` would skip a workflow nothing names, so it is refused; a change to `on` only deletes a variable, so it is still planned.

When the plan lists protected workflows, the change switches off a workflow the CI profile protects. After the first yes, ask once more and accept only the variable name:

```text
Protected workflows this switches off:
- [file]: [the role the profile records for it]
Second confirmation: Type [name] to confirm a second time that these protected workflows stop running:
```

A refused change prints one of these lines, `STATUS=FAIL ERROR="refused"` and exits without a plan. The required-check lines come from the live branch ruleset, the ignored-profile line from a skill-folder profile written for another repository, and the last two from the profile's `neverOff` list and its workflows README:

```text
REFUSE: [name] is not a documented switch
REFUSE: [name] must stay unset because the CI profile was ignored, so the protected workflows cannot be checked: fix its repository field or name it with --profile
REFUSE: [group] must stay unset while the ruleset requires that context
REFUSE: [master] must stay unset because it also skips [file], the only check the ruleset requires, and a skipped job reports Success
REFUSE: [name] must stay unset because the CI profile lists it in neverOff
REFUSE: [name] must stay unset, as [README path] says
```

In this repository the ruleset requires the message-contract context, so the two required-check lines read:

```text
REFUSE: SKILLED_CI_MESSAGES must stay unset while the ruleset requires that context
REFUSE: SKILLED_CI must stay unset because it also skips message-contract.yml, the only check the ruleset requires, and a skipped job reports Success
```

## 4. RESULTS DISPLAY

### Report Result

```text
DOCTOR DIAGNOSTIC RESULT
Target: report
Switch states: [n] on, [n] off, [n] partial, [n] missing, [n] unknown
Drift flags: [n] workflows carry at least one
Changed: none
STATUS=[OK|FAIL|ERROR]
```

When the report script exits 2 or 3, render the failure summary with the script's message and this accepted invocation on its `Next:` line: `/doctor:ci report [--json] [--sha=<sha>] [--no-gh] [--profile=<path>]`.

### Mutating Result

```text
DOCTOR MUTATING RESULT
Target: [scaffold|toggle]
Workflow: [yaml]
Approved change: [the file created, or the gh variable command run]
Changed: [the new .github/workflows/ file | the repository variable]
Verification: [first line of the file read back | the variable list read back]
Undo: [delete the new file | gh variable delete [name] or gh variable set [name] --body [previous]]
STATUS=OK
```

### No Change

Render this when the toggle finds the variable already in the requested state.

```text
DOCTOR TARGET UNCHANGED
Target: toggle
Variable: [name]
State: [on|off], already as requested
Changed: none
STATUS=OK
```

### Cancelled

```text
DOCTOR TARGET CANCELLED
Target: [target]
Changed: none
STATUS=CANCELLED ACTION=cancelled
```

### Failure Summary

```text
DOCTOR TARGET FAILED
Target: [target]
Step: [setup|workflow phase]
Error: [message]
Changed: [changes applied before the failure, or none]
Next: [recommended command or manual action]
STATUS=FAIL ERROR="[message]"
```

## 5. TROUBLESHOOTING DISPLAY

| Situation | Suggested Action |
|-----------|------------------|
| Every switch reads `unknown` | `gh` is missing, not logged in, or `--no-gh` was passed. Run `gh auth status`, then rerun `/doctor:ci report` |
| The newest non-rebuild SHA is `none` | The last 100 runs on the default branch are all rebuild commits, or gh could not read them. Pass `--sha=<40 hex>` to name a commit yourself |
| A workflow shows `missing` | The CI profile requires a switch on every job and no job in it carries one. Add the condition the job-shape rules show, or add the file to the profile's `switch.exempt` |
| The report, scaffold or toggle exits 3 | The CI profile is missing where `--profile` or `git config skcode.ciProfile` points, or a key is unknown or malformed. Fix the field the error names |
| The report, scaffold or toggle refuses `.sk-code/ci.json` | That root path is no longer read. Move `.sk-code/ci.json` to `.skilled/skills/sk-code/sk-code-ci/repository/ci.json`, then delete the root `.sk-code/` folder |
| The profile line reads `Profile: default ... ignored` | The skill-folder profile names another repository, so this one runs on the default. Write this repository's own `repository` value in the profile, or pass `--profile` |
| The toggle refuses a variable because the CI profile was ignored | The skill-folder profile names another repository, so its protected workflows and `neverOff` names are not checked and no change to `off` is planned. Write this repository's own `repository` value in the profile, or pass `--profile` |
| A workflow shows `partial` | Some jobs sit in a switched group and some do not. Read the job conditions in that file |
| `event-in-run` flags a workflow | A run block interpolates an event field. A hex SHA or a number is allowed, so read the line before changing it |
| A workflow file fails to parse | Fix the YAML error the report names. The other rows still print |
| The scaffold refuses a name | Pick a name that is not already a workflow and is not in the protected set, then rerun with `--name=<file>` |
| The toggle refuses a variable behind a required check | The branch ruleset requires a status context that job holds, and a skipped job reports Success. Leave the variable unset. Here that is the message variable and the master switch |
| The toggle asks for a second confirmation | The change switches off a workflow the CI profile protects. Type the variable name only if you mean to stop that workflow |
| `gh variable set` fails with a permission error | The login cannot write repository variables. Run the printed command with an account that can, or set the variable under Settings, Secrets and variables, Actions |
| Route manifest parse error | Run `bash .skilled/commands/doctor/scripts/route-validate.sh` |

## 6. NEXT-STEP SUGGESTIONS

| Condition | Suggested Command | Reason |
|-----------|-------------------|--------|
| The report shows a drift flag | `/doctor:ci report --json` | The JSON names the flag per workflow for a script or a review |
| The report shows `off` for a group | `/doctor:ci toggle --variable=<name> --state=on` | Clears the variable so the group runs again |
| A new workflow is needed | `/doctor:ci scaffold --name=<file>.yml` | Starts from the standards templates and prints the file first |
| A scaffolded file was written | Add its rows to the workflows README the profile names | The scaffold prints the rows but never edits the README |
| You want to review a workflow change | Review the diff with the workflow standards packet loaded | The packet carries the rules the report cannot check |

End interactive presentations with: `What would you like to do next?`
