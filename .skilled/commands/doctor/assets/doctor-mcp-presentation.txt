# /doctor:mcp Presentation Contract

This file defines user-facing prompts and reports for the Code Mode install and debug workflows.

## Startup

When `$ARGUMENTS` has no positional sub-action, ask:

```text
What do you want to do with Code Mode?
   1) Install or configure
   2) Debug and repair
   X) Cancel
```

| Answer | Result |
|--------|--------|
| `1`, `I`, `install` | `sub_action = install` |
| `2`, `D`, `debug` | `sub_action = debug` |
| `X`, empty, `cancel` | `STATUS=CANCEL` |

For an unknown sub-action, show:

```text
Unknown sub-action '[sub_action]'. Valid: install, debug. Try `/doctor:mcp install` or `/doctor:mcp debug`.
STATUS=FAIL ERROR="unknown_sub_action"
```

## Arguments and Setup

`install` accepts `--runtime <name>` with `opencode`, `claude`, `codex`, `cursor`, `pi`, or `devin`. `claude` covers both `.mcp.json` and `.claude/mcp.json`.

`debug` accepts `--fix`. It enables individually approved repairs; it does not approve changes automatically.

Reject flags that do not belong to the selected sub-action:

```text
Flag '--fix' is only valid for `debug`. Did you mean `/doctor:mcp debug --fix`?
STATUS=FAIL ERROR="cross_sub_action_flag_injection"
```

```text
Flag '--runtime' is only valid for `install`. Did you mean `/doctor:mcp install --runtime <name>`?
STATUS=FAIL ERROR="cross_sub_action_flag_injection"
```

Render the setup dashboard after the sub-action and flags resolve:

```text
DOCTOR MCP SETUP
Sub-action: [install|debug]
Workflow: .skilled/commands/doctor/assets/[doctor-mcp-install.yaml|doctor-mcp-debug.yaml]
Runtime: [name|all|n/a]
Fix mode: [true|false|n/a]
Presentation: .skilled/commands/doctor/assets/doctor-mcp-presentation.txt
Next: load workflow YAML
```

## Install

Show one Code Mode assessment row:

```text
CODE MODE INSTALL ASSESSMENT

| Component | Build | UTCP config | Runtime wiring |
|-----------|-------|-------------|----------------|
| Code Mode | [READY|STALE|MISSING|BLOCKED] | [VALID|INVALID|MISSING] | [WIRED|UNWIRED|UNVALIDATED] |
```

Explain before any writes that a missing `.skilled/skills/mcp-code-mode/mcp-server/package.json` blocks the install. Do not make any changes after that finding.

For work that can proceed, ask:

```text
Assessment complete. Choose what to do:

A) Install missing dependencies and build when needed
B) Review each proposed change individually
C) Show the report and stop
D) Cancel
```

Request explicit approval for each dependency install, build, `.utcp_config.json` edit, or runtime config edit. When no runtime is selected, plan changes for all seven supported project configs; `--runtime` narrows that plan. Preserve existing manuals and unrelated config entries. Never request, display, or write credential values. Ask for a credential variable name only; the operator manages its value in root `.env` outside the workflow.

When documenting a manual credential, use neutral names only. Example: manual `example_service` with `${API_TOKEN}` expects the key `example_service_API_TOKEN`; report whether the key is present or missing, never its value.

Supported runtime files:

| Runtime | Config files |
|---------|--------------|
| `opencode` | `opencode.json` |
| `claude` | `.mcp.json`, `.claude/mcp.json` |
| `codex` | `.codex/config.toml` |
| `cursor` | `.cursor/mcp.json` |
| `pi` | `.pi/mcp.json` |
| `devin` | `.devin/mcp_config.json` |

For a Codex TOML config, Python `tomllib` validates when available. If unavailable, report `UNVALIDATED` and do not claim a validation pass. Hermes registration is user-level in `~/.hermes/config.yaml` and is not checked.

## Debug

Show one Code Mode diagnostic row:

```text
CODE MODE DEBUG FINDINGS

| Component | Status | Findings |
|-----------|--------|----------|
| Code Mode | [PASS|WARN|FAIL] | [summary] |
```

For each finding, show its check name, detail, and proposed repair. The health script runs as `bash .skilled/commands/doctor/scripts/mcp-doctor.sh --json`; never pass `--fix` to the script. Its report contains `status`, `exitCode`, `summary`, and `checks`.

With `--fix`, present repairs one at a time and ask:

```text
Finding: [check]
Detail: [detail]
Proposed repair: [description]
Command or file change: [repair]

Apply this repair? [Y/n]
```

Do not repair credentials during debug. Report expected key names with present or missing status only. For each approved repair, rerun the JSON health check and report what changed.

## Examples

```text

```

## Troubleshooting

| Situation | Suggested action |
|-----------|------------------|
| Install prerequisites are missing | Install Node.js 24 and npm, then rerun. |
| Code Mode package manifest is missing | Stop; restore the package manifest in the project before installing. |
| Build output is stale | Review the source timestamp findings, then approve a rebuild if appropriate. |
| Codex TOML cannot be validated | Install Python 3.11 or later, or review the TOML manually; keep the result unvalidated. |
| Debug repair did not resolve the finding | Read the Code Mode install guide and apply its documented resolution after approval. |
| Code Mode is healthy but another subsystem check fails | Use `/doctor:speckit <target>` for that subsystem. |

End interactive presentations with: `What would you like to do next?`
