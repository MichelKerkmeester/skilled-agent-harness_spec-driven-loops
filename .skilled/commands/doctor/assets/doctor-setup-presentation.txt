# /doctor:setup Presentation Contract

This file is the single source of truth for user-facing presentation in `/doctor:setup`: the argument failure, the doctor target list, the per-leg result table, result templates, and next-step text. The command router owns asset routing only. The workflow YAML owns execution behavior.

## 1. Argument Failure

```text
Unknown argument: [argument]
/doctor:setup takes no target and no flag. Run /doctor:setup on its own.
STATUS=FAIL ERROR="unknown_argument"
```

| Leg | Command | Result | Repair |

## 4. Result Templates

### Summary

```text
DOCTOR DIAGNOSTIC RESULT
Target: setup
Status: [OK|FAIL|ERROR]
Mutation class: read-only
Evidence: [N] legs, [N] passed, [N] failed, [N] skipped, [N] degraded, [N] errors
Recommendation: [the doctor command for each failing or degraded leg, or none]
Last session hop: [the first line `session-relaunch.cjs history --last 1` printed, or no hop recorded yet]
[open notes: N handoff notes not claimed yet, oldest <filename>; shown only when history printed it]
[orphans: N, about M MB; list them with node .skilled/commands/doctor/scripts/orphan-process-check.cjs --reap]
STATUS=[status]
```

The last session hop line is informational. It shows when a session last handed over, kept, claimed or finished a handoff, and it never changes the status. The open notes line appears only while a handoff note is still open, so a hand-over nobody finished stays visible.
The orphan line is informational only and never changes the doctor status. A model server kept on purpose with `SPECKIT_HF_MODEL_SERVER_ORPHAN_REAP=0` also shows as unsupervised, so do not reap it. With no orphan processes, print `orphans: none`. Run the listed `--reap` command to see each process, then use its confirmation command with `--yes` only when those are the processes to stop.

### Failure Summary

```text
DOCTOR TARGET FAILED
Target: setup
Step: [leg]
Error: [message]
Next: [recommended command or manual action]
STATUS=ERROR ERROR="[message]"
```

## 5. Troubleshooting Display

| Situation | Suggested Action |
|-----------|------------------|
| A leg reports FAIL | Run the doctor command in that leg's Repair cell, then rerun `/doctor:setup` |
| The advisor leg reports SKIP | Exit 75 has no `staleDistWarning` in stderr JSON. The advisor daemon is stopped because `--warm-only` does not start it |
| The advisor leg reports FAIL for a stale build | Exit 75 includes `staleDistWarning` in stderr JSON. Run `npm --prefix .skilled/skills/system-skill-advisor/runtime run build` |
| The advisor leg reports DEGRADED | Exit 0 has `data.freshness` other than `live`. The skill graph is not live. Run `/doctor:skill-advisor rebuild` |
| The sk-git leg reports DEGRADED | No sk-git check failed, but one is unknown or a gate is saved off. Run `/doctor:git setup` to see which. On a runtime the battery cannot name, such as Hermes, the AI-tool check stays unknown |
| The trigger-index leg reports stale documents | Run `/doctor:speckit` to see which documents are stale |
| Route manifest parse error | Run `bash .skilled/commands/doctor/scripts/route-validate.sh` |

End interactive presentations with: `What would you like to do next?`
