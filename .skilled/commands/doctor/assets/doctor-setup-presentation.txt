# /doctor:setup Presentation Contract

This file is the single source of truth for user-facing presentation in `/doctor:setup`: the argument failure, the doctor target list, the per-leg result table, result templates, and next-step text. The command router owns asset routing only. The workflow YAML owns execution behavior.

## 1. Argument Failure

```text
Unknown argument: [argument]
/doctor:setup takes no target and no flag. Run /doctor:setup on its own.
STATUS=FAIL ERROR="unknown_argument"
```

## 4. Result Templates

### Summary

```text
DOCTOR DIAGNOSTIC RESULT
Target: setup
Status: [OK|FAIL|ERROR]
Mutation class: read-only
Evidence: [N] legs, [N] passed, [N] failed, [N] skipped, [N] degraded, [N] errors
Recommendation: [the doctor command for each failing or degraded leg, or none]
Last session hop: [the first line `session-handover.cjs history --last 1` printed, or no hop recorded yet]
[open notes: N handoff notes not claimed yet, oldest <filename>; shown only when history printed it]
[the line `session-handover.cjs window` printed: Claude context window: N tokens, or Claude context window: none configured with the two settings that supply one]
[orphans: N, about M MB; list them with node .skilled/commands/doctor/scripts/orphan-process-check.cjs --reap]
STATUS=[status]
```

The last session hop line is informational. It shows when a session last handed over, kept, claimed or finished a handoff, and it never changes the status. The open notes line appears only while a handoff note is still open, so a hand-over nobody finished stays visible.
The Claude context window line is informational and never changes the status. It shows the window the Claude relaunch nudge measures against. When no window is configured it names `autoCompactWindow` and `SESSION_HANDOVER_WINDOW_TOKENS`, and the nudge stays off until one is set or a `[1m]` model runs.
The orphan line is informational only and never changes the doctor status. With no orphan processes, print `orphans: none`. Run the listed `--reap` command to see each process, then use its confirmation command with `--yes` only when those are the processes to stop.

### Failure Summary

```text
DOCTOR TARGET FAILED
Target: setup
Step: [leg]
Error: [message]
Why: [the reason the leg's checker printed, else what that leg checks]
Next: [the checker's own Next: line when it printed one, else the repair command for that leg]
STATUS=ERROR ERROR="[message]"
```

This block is for a leg that could not run at all, such as a checker that crashed or was called wrongly. A leg that ran and failed is a row in the per-leg table with its repair command, not this block. Every leg only reads, so nothing was changed.

## 5. Troubleshooting Display

| Situation | Suggested Action |
|-----------|------------------|
| A leg reports FAIL | Run the doctor command in that leg's Repair cell, then rerun `/doctor:setup` |
| The advisor leg reports SKIP | Exit 75 has no `staleDistWarning` in stderr JSON. It is another retryable failure: the daemon or backend may be absent or unavailable, the CLI or daemon launcher may fail to start, a connection or request may time out, the socket may close, JSON-RPC may return -32000 or -32001, SQLite may return SQLITE_BUSY, or transport may return ECONNREFUSED, ENOENT, ECONNRESET, EPIPE or ETIMEDOUT, or another error the CLI marks retryable. Read stderr for the cause; `--warm-only` never starts a daemon |
| The advisor leg reports FAIL for a stale build | Exit 75 includes `staleDistWarning` in stderr JSON. Run `npm --prefix .skilled/skills/system-skill-advisor/runtime run build` |
| The advisor leg reports DEGRADED | Exit 0 has `data.freshness` other than `live`. The skill graph is not live. Run `/doctor:skill-advisor rebuild` |
| The sk-git leg reports DEGRADED | No sk-git check failed, but one is unknown or a gate is saved off. Run `/doctor:git setup` to see which. On a runtime the battery cannot name, the AI-tool check stays unknown |
| The trigger-index leg reports stale documents | Run `/doctor:speckit` to see which documents are stale |
| The delivery leg reports DEGRADED | A runtime cannot receive the advisor brief. Run the repair the leg names, then rerun /doctor:setup. The install still works without it |
| Route manifest parse error | Run `bash .skilled/commands/doctor/scripts/route-validate.sh` |

End interactive presentations with: `What would you like to do next?`
