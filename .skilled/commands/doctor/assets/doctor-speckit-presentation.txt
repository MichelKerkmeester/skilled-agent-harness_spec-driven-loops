# /doctor:speckit Presentation Contract

This file is the single source of truth for user-facing presentation in `/doctor:speckit`: the route manifest display, the moved-target notice, setup dashboards, diagnostic dashboards, result templates, troubleshooting, and next-step text. The command router owns route binding and asset routing only. The workflow YAML owns execution behavior.

## 1. Moved-Target Notice

`/doctor:speckit` diagnoses spec-kit retrieval only. When the positional names a target another doctor command now owns, show this notice and stop without loading any workflow:

```text
'[target]' moved to [new command].
Run: [new command] [new target, if any] [the same flags]
STATUS=CANCEL REASON="target_moved"
```

| Old target | New command |
|------------|-------------|
| `deep-loop` | `/doctor:deep-loop` |
| `skill-advisor` | `/doctor:skill-advisor tune` |
| `skill-budget` | `/doctor:skill-advisor skill-budget` |
| `parent-skill` | `/doctor:skill-advisor parent-skill` |
| `skill-graph-freshness` | `/doctor:skill-advisor skill-graph-freshness` |
| `router-reach` | `/doctor:skill-advisor router-reach` |
| `runtime-mirrors` | `/doctor:runtime-mirrors` |

`fable-mode` was retired with no replacement; for it, show `'fable-mode' was retired.` followed by `STATUS=CANCEL REASON="target_retired"`.

### Unknown Argument Failure

```text
Unknown argument: [argument]
/doctor:speckit takes no target. Run it bare, or use list to see what it checks.
STATUS=FAIL ERROR="unknown_argument"
```

## 2. Route Manifest Display

Render this table for `list`, `?`, or `--list`. Values should mirror `_routes.yaml`.

| Target | Workflow | Mutation Class | One-Line Purpose |
|--------|----------|----------------|------------------|
| `speckit-retrieval` | `doctor-speckit-retrieval.yaml` | add-only | Diagnose the generated trigger index and the ripgrep retrieval conventions; report staleness and recommend action |

## 3. Setup Prompts

The retrieval diagnostic asks for no setup value beyond its startup confirmation. It never regenerates the index itself and asks for no regeneration mode; its recommendation names the generator command, `node .skilled/skills/system-spec-kit/runtime/cli/retrieval/generate-trigger-index.mjs`, which republishes the whole corpus in one pass.

Render this compact panel after setup and before YAML execution.

## 5. Diagnostic Result Templates

Use the workflow output contract when it provides a stricter report shape. Use these templates for summary display and fallback rendering.

### Diagnostic Summary

```text
DOCTOR DIAGNOSTIC RESULT
Target: speckit-retrieval
Status: [OK|STALE|MISSING|ATTENTION|CANCELLED|FAIL]
Evidence: [index verdict, lookup exit class, recipe hits, report path]
Advisories: [non-zero phrase-quality classes with counts and share, or none]
Recommendation: [operator action or none]
STATUS=[status]
```

### Failure Summary

```text
DOCTOR TARGET FAILED
Target: speckit-retrieval
Step: [setup|workflow phase]
Error: [message]
Next: [recommended command or manual action]
STATUS=FAIL ERROR="[message]"
```

## 6. Troubleshooting Display

| Situation | Suggested Action |
|-----------|------------------|
| Trigger index stale or missing | Run `node .skilled/skills/system-spec-kit/runtime/cli/retrieval/generate-trigger-index.mjs` |
| Skill advisor routes to the wrong skill | Use `/doctor:skill-advisor` |
| Deep-loop graph empty or stale | Use `/doctor:deep-loop` |
| Runtime mirror drift | Use `/doctor:runtime-mirrors` |
| Route manifest parse error | Run `bash .skilled/commands/doctor/scripts/route-validate.sh` |

End interactive presentations with: `What would you like to do next?`
