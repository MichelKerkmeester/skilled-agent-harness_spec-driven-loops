# /doctor:skill-advisor Presentation Contract

This file is the single source of truth for user-facing presentation in `/doctor:skill-advisor <target>`: startup questions, the route manifest display, setup prompts, the rebuild plan and approval, diagnostic dashboards, result templates, troubleshooting, and next-step text. The command router owns target resolution and asset routing only. The workflow YAML owns execution behavior.

## 1. Startup Presentation

When `$ARGUMENTS` lacks a recognized positional target, ask this prompt first after reading `_routes.yaml`.

```text
What do you want to do with the skill advisor?

   1) Re-tune routing                    (which skill gets recommended)
   2) Rebuild the skill graph            (skill-graph.sqlite from graph-metadata.json)
   3) Check skill-graph freshness        (compiled vs sqlite vs disk drift)
   4) Check router reach                 (declared phrases reach their hub)
   5) Set up meaning matching            (embedder for commands, asks before any change)
   6) Audit description budget           (char counts, CI-friendly)
   7) Audit parent-skill structure       (mode registry, graph metadata)
   H) Help me decide
   X) Cancel
```

Accepted answers:

| Answer | Result |
|--------|--------|
| `1` | target = `tune` |
| `2` | target = `rebuild` |
| `3` | target = `skill-graph-freshness` |
| `4` | target = `router-reach` |
| `5` | target = `embedder` |
| `6` | target = `skill-budget` |
| `7` | target = `parent-skill` |
| `H` | Show the help block, then ask the startup prompt again |
| `X`, empty, `cancel` | `STATUS=CANCEL` |

On any other response, re-emit the menu once. On a second invalid response, return `STATUS=FAIL ERROR=unknown_selection`.

### Help Block

```text
Pick by symptom:

   Advisor recommends the wrong skill                  -> 1  Re-tune routing
   New skill not appearing in advisor results          -> 2  Rebuild, then 3 to confirm
   advisor_status reports stale, absent or unavailable -> 2  Rebuild
   Compiled/sqlite/disk skill-graph disagree           -> 3  Skill-graph freshness
   Declared router phrase reaches the wrong hub        -> 4  Router reach
   A plain request never gets its command offered      -> 5  Meaning matching setup
   Description char-count over hard cap                -> 6  Description budget
   Parent skill graph-metadata or mode registry drift  -> 7  Parent-skill structure

Quick reference for confusable pairs:
   Re-tune (1) edits scoring lanes after per-skill review; Rebuild (2) only re-derives the graph
   Freshness (3) reports drift; Rebuild (2) repairs it
   Description budget (6) audits CHAR COUNTS, not routing quality

Press 1-6, H, or X.
```

### Unknown Target Failure

```text
Unknown target: [target]
Valid targets: tune, rebuild, skill-graph-freshness, router-reach, embedder, skill-budget, parent-skill
Try: /doctor:skill-advisor list
STATUS=FAIL ERROR="unknown_target"
```

### Cross-Target Flag Failure

```text
Flag '[flag]' is not valid for target '[target]'. Did you mean `/doctor:skill-advisor [suggested-target] [flag]`?
STATUS=FAIL ERROR="cross_target_flag_injection"
```

## 2. Route Manifest Display

Render this table for `list`, `?`, or `--list`. Values should mirror `_routes.yaml`.

| Target | Workflow | Mutation Class | One-Line Purpose |
|--------|----------|----------------|------------------|
| `tune` | `doctor-skill-advisor-tune.yaml` | mutates | Audit and re-tune the advisor's scoring lanes, with per-skill review before any write |
| `rebuild` | `doctor-skill-advisor-rebuild.yaml` | mutates | Rebuild skill-graph.sqlite from graph-metadata.json through the advisor CLI, behind a backup |
| `skill-graph-freshness` | `doctor-skill-graph-freshness.yaml` | read-only | Diagnose skill-graph representation drift across compiled, sqlite, and disk sources |
| `router-reach` | `doctor-router-reach.yaml` | read-only | Ask the live advisor whether every phrase a hub's router advertises actually reaches it |
| `embedder` | `doctor-skill-advisor-embedder.yaml` | mutates | Set up meaning matching for commands: probe Ollama and the model, show each step's cost and undo, and change nothing before a yes |
| `skill-budget` | `doctor-skill-budget.yaml` | read-only | Audit skill, command, and agent description budgets |
| `parent-skill` | `doctor-parent-skill.yaml` | read-only | Audit parent-skill structure, routing manifests, root metadata, router contract, and version consistency |

## 3. Setup Prompts

Ask only prompts needed for unresolved setup variables. Do not split a required setup question into multiple visible turns.

### Tune Scope

Ask only when `--scope` was not passed.

```text
Which scoring lanes should be checked?
   1) all       - explicit, derived, and lexical
   2) explicit  - TOKEN_BOOSTS and PHRASE_BOOSTS
   3) derived   - graph-metadata triggers and topics
   4) lexical   - CATEGORY_HINTS
```

Accept `1-4` or the corresponding name; empty defaults to `all`.

### Parent-Skill Directory

Ask only when `--dir` was not passed: `Which parent skill hub should be audited? (path under .skilled/skills/)`. The fleet-wide metadata gate runs either way.

### Router-Reach Scope

`--hub` and `--concurrency` are optional. With neither, the whole fleet is probed at the script's default concurrency; ask nothing.

## 4. Rebuild Plan And Approval

Render the plan after the probe, before any write.

```text
SKILL GRAPH REBUILD PLAN
Advisor status: [live|stale|absent|unavailable] (daemon: [running|absent])
Database: .skilled/skills/system-skill-advisor/runtime/database/skill-graph.sqlite ([size], modified [time] | not present)
Backup: [backup path | none, no database yet]
Source: [N] graph-metadata.json files under .skilled/skills/
Will run:
   node .skilled/bin/skill-advisor.cjs advisor_rebuild --trusted --force true
   node .skilled/bin/skill-advisor.cjs skill_graph_scan --trusted
```

With `--dry-run`, follow the plan with `Dry run: nothing was written.` and `STATUS=OK`.

Otherwise ask:

```text
Rebuild the skill graph now? The current database is backed up first and restored if the rebuild fails.
Reply approve to rebuild, or no to cancel.
```

## 7. Troubleshooting Display

| Situation | Suggested Action |
|-----------|------------------|
| Advisor CLI exits 75 | The daemon is not running; a warm-only probe never starts it. `rebuild` does not need it |
| Rebuild failed and was rolled back | Read the failing command's output, fix the named graph-metadata.json, rerun `/doctor:skill-advisor rebuild` |
| Cross-target flag rejected | Use the suggested target from the error |
| Route manifest parse error | Run `bash .skilled/commands/doctor/scripts/route-validate.sh` |

## 8. Embedder Setup Presentation

Render these blocks for `/doctor:skill-advisor embedder`. The probe runs first and changes nothing. Every value is printed as the probe or the cost script returned it, and an unread value stays unread. The advisor daemon refreshes missing vectors on start and after skill changes when Ollama is reachable. This workflow scans the skill graph after approved setup steps or when Ollama is already set up and coverage is incomplete.

### Probe Dashboard

Render after the read-only probe and before the plan.

```text
EMBEDDER SETUP PROBE
Ollama binary: [present at <path>|missing]
Server: [answering at <url>, version <version>|absent at <url>]
Model: [nomic-embed-text:v1.5 present, <size> on disk|missing]
Advisor daemon: [present|absent]
Active embedder: [<backend> <model>|none|unread, the daemon is absent]
Skills: [<current> of <total> current (<stale> stale, <missing> missing)|unread, the daemon is absent]
Commands: [<current> of <total> current (<stale> stale, <missing> missing)|unread, the daemon is absent]
Coverage complete: [true|false|unread, the daemon is absent]
Ollama backend: [reachable|unreachable|model_missing|unread, the daemon is absent]
semantic lane weight [<laneWeights.semantic_shadow>]
```

A missing binary, an absent server and a missing model are findings, not failures of the route. An exit 75 from `advisor_status` means the daemon is absent, so the active embedder, both coverage objects, coverage state, backend state and lane weight stay `unread`. Print the lane-weight line on its own; at weight 0 with complete coverage, use `semantic lane weight 0: vectors ready, lane off by default`. With incomplete coverage, say the lane is off by default and vector coverage is incomplete.

### Plan Table

Render one row per missing step, in dependency order. A step the probe found present is not listed and is not run. Each cost comes from `measure-embedder-cost.mjs` or, when the cost script cannot run, from the install guide with a note that the live measurement was unavailable.

```text
EMBEDDER SETUP PLAN
Missing: [comma-separated steps, or none]

| Step | Cost | Undo |
|------|------|------|
| Install Ollama (printed only, never run by this route) | [the install guide's cost] | [the package manager's uninstall command] |
| Start ollama serve in the background | [.memory.serveRssKb from the cost script] resident | Stop the pid this run started |
| Pull nomic-embed-text:v1.5 | [.model.sizeBytes from the cost script] on disk | ollama rm nomic-embed-text:v1.5 |
| Scan the skill graph to fill vectors | [scan runtime plus .warm.medianMs per embedded prompt] | None, skill-graph.sqlite is derived state and a rerun rewrites it |

Will run after approval:
   [the listed steps, in dependency order, or none]
```

Include the scan row when Ollama is installed and either setup steps are planned or coverage is incomplete. When no Ollama step is missing and coverage is complete, skip the table and render the final result as already set up.

### Approval Prompt

Ask once, after the plan is on screen. Nothing is pulled, started or written before the answer, and approve is the only answer that proceeds.

```text
Set up meaning matching now? Only the steps in the plan run.
Steps:
   [one line per approved step with its cost]
Repository write: [the approved scan writes .skilled/skills/system-skill-advisor/runtime/database/skill-graph.sqlite as derived state, with no other repository files written|none when no scan is listed]
Never: an Ollama install or upgrade, a model the plan did not list, a model removal, a second server
Reply approve to continue, or no to cancel.
```

Anything other than approve renders the cancelled result and stops.

```text
EMBEDDER SETUP CANCELLED
Nothing was pulled, started or written.
Next: /doctor:skill-advisor embedder
STATUS=CANCELLED ACTION=cancelled
```

### Dry-Run Result

With `--dry-run`, stop after the plan, before the approval, and render this block.

```text
EMBEDDER SETUP DRY RUN
[the probe dashboard]
[the plan table, with each missing step's cost and undo]

Dry run: nothing was pulled, started or written.
STATUS=OK
```

### Final Result

Render after the post-scan probe. When no Ollama step is missing and `coverageComplete` is true, render the block from the probe values as already set up, ask nothing and run nothing. When coverage is incomplete, the plan includes the scan and asks for approval before it runs.

```text
EMBEDDER SETUP RESULT
Server: [answering at <url>, version <version>|absent at <url>]
Model: [nomic-embed-text:v1.5, <size> on disk|missing]
Skills: [<current>/<total> current (<stale> stale, <missing> missing)]
Commands: [<current>/<total> current (<stale> stale, <missing> missing)]
Coverage complete: [true|false|unread]
Ollama backend: [reachable|unreachable|model_missing|unread]
semantic lane weight [<laneWeights.semantic_shadow>]
Next: [none|start the advisor daemon with Ollama up so it refreshes missing vectors|/doctor:skill-advisor embedder]
STATUS=[OK|DEGRADED|FAIL]
```

Report `STATUS=OK` when coverage is complete and the backend is reachable. Report `STATUS=DEGRADED` when the backend is not reachable, even if coverage is complete; say routing continues on the other lanes and point to `/doctor:skill-advisor embedder`. When the backend is reachable but coverage is incomplete, report the stale and missing counts and say the daemon refreshes them on its next start with Ollama up. An absent daemon leaves coverage unread and is DEGRADED. Never fail because `laneEnabled` is false or the semantic lane weight is 0. Print the weight on its own info line; when it is 0 and coverage is complete, use `semantic lane weight 0: vectors ready, lane off by default`. When it is 0 and coverage is incomplete, say the lane is off by default and vector coverage is incomplete.

End interactive presentations with: `What would you like to do next?`
