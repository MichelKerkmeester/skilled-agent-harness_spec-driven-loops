# /doctor:sk-code Presentation Contract

This file is the single source of truth for user-facing presentation in `/doctor:sk-code`: the argument failure, the per-leg result table, result templates, and next-step text. The command router owns asset routing only. The workflow YAML owns execution behavior.

## 1. Argument Failure

```text
Unknown argument: [argument]
/doctor:sk-code runs one target, setup, and accepts only --prompt=<text>.
STATUS=FAIL ERROR="unknown_argument"
```

## 2. Per-Leg Result Table

Render one row per leg the workflow ran, in the workflow's order.

| Leg | Command | Result | Repair |
|-----|---------|--------|--------|
| [leg] | [check-only command] | [PASS|FAIL|SKIP] | [the repair command the leg printed, or none] |

## 3. Result Templates

### Summary

```text
DOCTOR DIAGNOSTIC RESULT
Target: setup
Status: [OK|FAIL|ERROR]
Mutation class: read-only
Evidence: [N] legs, [N] passed, [N] failed, [N] skipped
Recommendation: [the repair command for each failing leg, or none]
STATUS=[status]
```

### Failure Summary

```text
DOCTOR TARGET FAILED
Target: setup
Step: [leg]
Error: [message]
Next: [recommended command or manual action]
STATUS=ERROR ERROR="[message]"
```

## 4. Troubleshooting Display

| Situation | Suggested Action |
|-----------|------------------|
| A leg reports FAIL | Run the `repair:` command printed under that leg, then rerun `/doctor:sk-code setup` |
| The provisioning leg fails | Run `bash .skilled/skills/sk-git/scripts/worktree-naming.sh provision .` |
| The guard leg fails after a routing edit | Run the refresh and copy commands the guard leg's `repair:` line names, or commit with the hooks installed so the pre-commit gate does both |
| The probe leg fails on the legacy stub | The hub serves no compiled route; run the `repair:` command printed under the probe leg |
| A leg reports SKIP | The skipped legs wait on provisioning; run the provisioning leg's `repair:` command and rerun |
| Route manifest parse error | Run `bash .skilled/commands/doctor/scripts/route-validate.sh` |

End interactive presentations with: `What would you like to do next?`
