# SpecKit Plan Presentation Contract

Presentation source of truth for `/speckit:plan`. The command router owns only mode selection and asset loading. Workflow YAML owns execution. This file owns visible prompts, dashboard layout, and final result displays.

## 1. Startup Presentation

For `:confirm` or no suffix, the consolidated setup prompt is the first visible response. Ask all applicable questions once, then wait. No analysis or tool calls precede the prompt unless the workflow already has an explicit path that needs read-only folder-state classification.

For `:auto`, do not show the consolidated prompt by default. Resolve setup through the auto-mode table below. Ask targeted questions only for fields marked Tier 2.

For `:autopilot`, `:unattended` or `--unattended`, resolve setup like `:auto` and also bind `workspace_choice` to `worktree` or `current_branch`. Nothing is asked after startup. A required field or a `workspace_choice` that is neither pre-bound nor answered at startup ends the run with the Autopilot Result line and reason `uncertainty_blocked`, before any write.

### Auto Pre-Bound Setup Answers

Accept one optional marker block in the prompt body before applying defaults.

```yaml
PRE-BOUND SETUP ANSWERS:
  feature_description: Add passwordless login
  spec_folder: <spec-folder>
  execution_mode: AUTONOMOUS
  dispatch_mode: single_agent
  memory_choice: skip
  research_intent: add_feature
  context_integration: false
  phase_decomposition: false
  phase_count: 3
  phase_names: ""
  phase_folder: ""
  intake_only: false
  selected_level: ""
  start_state: ""
  repair_mode: ""
  record_relationships: false
  depends_on: ""
  related_to: ""
  supersedes: ""
```

Unknown fields warn. Malformed lines are parse errors. Marker values override flags; omitted fields fall back to defaults.

### Consolidated Prompt Template

```text
SpecKit Plan setup

Mode: [auto|confirm|ask]
Feature flags: [with-context yes/no] [with-phases yes/no] [intake-only yes/no]

Q0. Feature Description, if not provided: What feature should be planned?
Q1. Spec Folder: A) Use existing  B) Create new (new or unrelated work only)  C) Related (Use a related folder, phase child, new or existing sub-track, or a series parent for a different change to the same artifact as an existing packet in the same track)  D) Skip documentation
Q2. Execution Mode, if no suffix: A) Autonomous  B) Interactive  C) Autopilot (unattended; also answer Workspace: worktree or current branch)
Q3. Dispatch Mode: A) Single Agent  B) Multi-Agent (1+2)  C) Multi-Agent (1+3)
Q4. Prior Work Context, only when prior records exist: A) Latest  B) Recent 3  C) Skip
Q5. Research Intent: A) add_feature  B) fix_bug  C) refactor  D) understand
Q6. Phase Decomposition, if not already enabled: A) No  B) Yes
Q7. Phase Count, if phase decomposition is enabled and not provided: default 3
Q8. Phase Names, if phase decomposition is enabled and not provided: optional comma-separated names
Q9. Session Goal (optional): A) Offer or reference a session goal for this workflow  B) Set goal: <objective>  C) Skip

If folder intake is required, include the intake interview in this same prompt.

Reply format covers Q0-Q9 in order, with `-` for omitted conditional answers: "Add auth, B, A, B-single, C, add_feature, A, -, -, A" or "-, B, A, A, -, fix_bug, B, 3, (api; tests; docs), B".
```

Never split these questions into separate visible prompts. If `--intake-only` is present, stop after intake emit and do not continue to planning steps.

### Auto Fail-Fast Display

```text
SpecKit Plan auto setup failed
Missing required inputs: [field-list]
Provide the missing inputs or rerun with :confirm.
STATUS=FAIL ERROR="missing required setup inputs"
```

Under autopilot the display ends with the result line in place of the `STATUS=FAIL` line:

```text
SpecKit Plan autopilot setup failed
Missing required inputs: [field-list]
SPECKIT_AUTOPILOT_RESULT {"mode":"autopilot","ok":false,"reason":"uncertainty_blocked","branch":"<branch>","merged":false,"verification":"not run"}
```

## 3. Results Display

### Success

```text
SpecKit Planning Complete - All 7 steps executed.
Artifacts: spec.md, plan.md, tasks.md, acceptance-criteria.md when Level 2+, graph-metadata.json scaffolded, continuity refreshed in canonical spec docs
Ready for: /speckit:implement [spec-folder-path]
Defaults taken: [none | each default an auto run took in place of a question]
STATUS=OK PATH=[spec-folder-path]
```

### Intake-Only Result

Shown when `/speckit:plan --intake-only` stops at `step_0.6_intake_only_gate`. It replaces the Success block, because no planning step ran.

```text
Intake-only mode complete.
Published trio at [spec-folder-path]: spec.md, description.json, graph-metadata.json
Planning Steps 1-7 bypassed.
Next: run /speckit:plan [spec-folder-path] without --intake-only to resume planning.
STATUS=OK PATH=[spec-folder-path]
```

### Failure

```text
SpecKit Planning Failed
Error: [description] | Step: [number]
Defaults taken: [none | each default an auto run took in place of a question]
STATUS=FAIL ERROR="[message]"
```

### Autopilot Result

An autopilot run ends with exactly one of these two lines, in place of the Success or Failure block. The schema and the reason codes are `unattended_autopilot.terminal_result` in the workflow.

```text
SPECKIT_AUTOPILOT_RESULT {"mode":"autopilot","ok":true,"reason":null,"branch":"<branch>","merged":false,"verification":"passed"}
SPECKIT_AUTOPILOT_RESULT {"mode":"autopilot","ok":false,"reason":"<no_eligible_tasks|retry_exhausted|verification_failed|uncertainty_blocked>","branch":"<branch>","merged":false,"verification":"<summary>"}
```

The first line reports a run that passed verification and the second a stop. Autopilot never merges and never pushes, so `merged` is always false and the merge is left to the operator.

### Next-Step Suggestions

| Condition | Suggested Command | Reason |
|-----------|-------------------|--------|
| Ready to implement | `/speckit:implement [spec-folder-path]` | Continue to implementation |
| Need stakeholder review | Share `plan.md` | Get approval before coding |
| Technical uncertainty | `/deep:research [topic]` | Investigate first |
| Need continuity refresh | `/speckit:save [spec-folder-path]` | Refresh canonical continuity |

End interactive presentations with: `What would you like to do next?`
