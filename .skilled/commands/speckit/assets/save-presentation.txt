# SpecKit Save Presentation Contract

Single source of truth for `/speckit:save` startup questions, dashboards, and result displays.

## 1. Startup Question Policy

Use the shortest prompt that resolves the target folder.

| Situation | Display |
| --- | --- |
| Explicit folder in `$ARGUMENTS` | No startup question. Validate the folder and continue. |
| Gate 3 carry-over exists | Announce `Using active spec folder from this session: <folder>` and continue. |
| One clear session folder from touched files | Ask `Save context to <folder>? [Y/n]`. |
| Multiple plausible folders | Ask `Which spec folder should receive this save?` and list only the candidate folders. |
| No plausible folder | Ask for a target spec folder and stop until answered. |

Do not show a long option menu unless there are multiple candidates.

## 2. Save Plan Display

```text
SPECKIT:SAVE PLAN
--------------------------------------------------
Folder      <spec_folder>
Mode        plan-only
Route       <route_category>
Targets     <target_1>, <target_2>
Blockers    <blocker, or none>
Advisories  <advisory, or none>
Decisions   <count> pending operator answer(s), listed and not written, or none
Orphans     <count> <session-id> for each other session with pending answers, or none

Proposed edits
- <edit summary>

Follow-up
- <full-auto|regenerate-trigger-index|none>

STATUS=OK ACTION=plan TARGET=<spec_folder>
```

## 3. Full-Auto Result Display

```text
SPECKIT:SAVE FULL-AUTO
--------------------------------------------------
Folder      <spec_folder>
Targets     <target_1>, <target_2>, <target_3>
Continuity  Wrote continuity to <pointer>
Decisions   Wrote <n> operator decision(s) to <folder>
Session ref session_ref skipped: <reason>

Triggers
<phrase_1> | <phrase_2> | <phrase_3>

STATUS=OK TARGETS=<count>
```

The Continuity, Decisions and Session ref rows quote lines the writer printed.
When the writer printed `Continuity fields not written: <reason>`, the Continuity row shows that line.
Leave out the Decisions row when the writer printed no decision line, and the Session ref row when it printed no `session_ref skipped` line.

## 4. Error Display

```text
SPECKIT:SAVE
--------------------------------------------------
FAIL        <short reason>
Recovery    <next safe action>

STATUS=FAIL ERROR="<message>"
```

## 5. Display Rules

- Keep output parseable: stable labels, one status line, no decorative menu dumps.
- Report save quality review issues only when returned by the save script or tool.
- Say plainly when the trigger index was not regenerated; saved documents remain durable even if retrieval is stale.
- End with one concise next action, not an open-ended option list.
