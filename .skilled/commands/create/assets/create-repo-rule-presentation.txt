# User-facing wording only. No routing logic.

Run this automatic self-check before setup. This is not a user question.

```text

- Template-first workflow capabilities are available

If all indicators are present:

- Continue to setup

If any indicator is missing or uncertain:
- Stop before loading workflow YAML

```

Hard-block message:

```text
BLOCKED: /create:repo-rule requires the @markdown agent.

This command authors a rule file, edits REPO RULES.md, and adds a pointer to the
always-loaded document. Run it as @markdown so the template-first workflow and
the decision tests are in force.

Re-invoke as: @markdown /create:repo-rule <what the rule should bind>
```

## 3. NON-INTERACTIVE SETUP (:auto)

Under `:auto`, the setup prompt is skipped when the prompt body carries a
pre-bound answers block. Honor every field present and resolve the rest from the
defaults below. Missing a required field with no default stops the run.

```text
PRE-BOUND SETUP ANSWERS:
  request: <what the rule should bind, in the user's words>
  operation: create
  rule_name: <kebab-name>
  target_repo: .
  execution_mode: AUTONOMOUS
```

Default resolution table:

| Field | Required | Resolves Via | Default | Tier-2 Candidate |
| --- | --- | --- | --- | --- |
| `request` | Yes | Positional argument or marker `request` | none | Yes, when empty |
| `operation` | Yes | `create`/`revise`/`retire` token or marker | `create` | No |
| `rule_name` | Conditional | `--rule` or marker; required for revise and retire | none | Yes, for revise and retire |
| `target_repo` | No | Marker `target_repo` | repository root | No |
| `execution_mode` | Yes | `:auto`, `:confirm`, or marker | `AUTONOMOUS` under `:auto` | No |

Retire never runs unattended on an inferred operation. It deletes a rule file and
strips two router rows, so it runs autonomously only when the operator wrote the
`retire` operation and `:auto` together.

## 5. REFUSAL WORDING

  A refusal is a useful answer, not a dead end. Always name both the test and
  the destination. Never refuse without saying where the content should go.

  Most requests are refused. That is the design.

## 6. CHECKPOINT DISPLAY (:confirm)

  Step {n}/6 — {step_name}
    {what this step produced}

  A) approve   B) review   C) modify   D) abort

  The decision gate is not a checkpoint. A refusal there ends the run and is
  reported, never offered for approval.
