# PRESENTATION CONTRACT — /create:goal
# User-facing wording only. No routing logic.

## 1. Phase 0 Verification Display

Run this automatic self-check before setup. This is not a user question.

```text
SELF-CHECK: Are you operating as the @markdown agent?

Indicators:
- Invoked with @markdown prefix
- Template-first workflow capabilities are available
- Packet-goal authoring behavior is available
- Goal rendering through system-spec-kit is available

If all indicators are present:
- create_agent_verified = true
- Continue to setup

If any indicator is missing or uncertain:
- Stop before loading workflow YAML
- Display the hard-block message below
```

Hard-block message:

```text
BLOCKED: /create:goal requires the @markdown agent.

This command renders a packet goal through system-spec-kit's template and fills it
against the authoring standards. Run it as @markdown so the template-first workflow
is in force.

Re-invoke as: @markdown /create:goal <packet path>
```

## 2. SESSION-GOAL REDIRECT

When the request is to "set the goal" or "resend the goal" as a session objective,
show this block, write nothing, and stop.

```text
  This request is a session objective, not a packet goal file.
  Session objectives belong to the goal hooks: /goal, /goal-opencode, /goal-pi,
  /goal-cursor, or the host's native goal command.
  /create:goal authors goal.md files only. Nothing was written.

  STATUS=OK ACTION=redirected TARGET=goal-hooks
```

## 4. NON-INTERACTIVE SETUP (:auto)

Under `:auto`, the setup prompt is skipped when the prompt body carries a
pre-bound answers block. Honor every field present and resolve the rest from the
defaults below. Missing a required field with no default stops the run.

```text
PRE-BOUND SETUP ANSWERS:
  packet_path: <spec packet directory>
  operation: top-level
  execution_mode: AUTONOMOUS
```

Default resolution table:

| Field | Required | Resolves Via | Default | Tier-2 Candidate |
| --- | --- | --- | --- | --- |
| `packet_path` | Yes | Positional argument or marker `packet_path` | none | Yes, when empty |
| `operation` | Yes | Operation token or marker | resolved from the packet's own files | No |
| `execution_mode` | Yes | `:auto`, `:confirm`, or marker | `AUTONOMOUS` under `:auto` | No |
