# v1.0.0.0 - First Release

**Released:** 2026-08-29

The initial release delivered `mcp-magicpath` as the read-only MagicPath transport in the `mcp-tooling` hub (`packetKind: transport`, `mutatesWorkspace: false`). It documented the fourteen read-only tools the `magicpath` Code Mode manual registers, the credential and calling convention phase 002 established, and the mutation boundary that keeps the CLI's write surface out of reach, without granting the transport any design or workspace-mutation authority.

---

## What's In 1.0.0.0

### Core Transport And Backend

- `SKILL.md` defined MagicPath-specific activation signals, a guarded multi-intent router, discovery-first execution, the read funnel (reachability -> search/list -> inspect/get -> share last), the synchronous calling convention, and read-only safety rules.
- The transport used the existing `magicpath` Code Mode manual, a UTCP `cli` transport whose manual command runs `node .opencode/bin/magicpath-utcp-manual.cjs` and whose tool calls run through `node .opencode/bin/magicpath-utcp-exec.cjs`, which shells out to the `magicpath-ai` binary. The packet preserved the registered manual as a verify-only asset rather than editing `.utcp_config.json` or creating a second manual.
- The packet stated that MagicPath ships no MCP server and that the bridge is the `magicpath-ai` Node CLI (installed version 2.6.1), reached through Code Mode's UTCP `cli` transport.
- Runtime authority stayed minimal: Read, Bash, Grep, Glob, and Code Mode calls were allowed, while Write, Edit, and Task were forbidden.

### Registered Code Mode Surface

- The packet documented fourteen read-only tools across six themes: session (`info`, `whoami`), components (`search_components`, `inspect_component`, `list_components`), projects (`list_projects`, `active_project`, `share_link`), teams (`list_teams`, `list_members`), themes (`list_themes`, `get_theme`), and local & canvas (`list_installed`, `selection`).
- The callable form was documented as `magicpath.<tool>(...)`, from Code Mode's `{manual}.{tool}` rule applied once, because the tool names have no `magicpath_` prefix of their own. Discovery names appear dotted as `magicpath.<tool>`. A per-session `tool_info` confirmation stayed mandatory, and the packet failed closed on drift.
- The hard constraints were recorded: every tool is read-only; `limit` is declared as a `string`, not a number; `list_components` paginates by cursor (`after`), not by page number; `share_link` takes a component generated name or a numeric project id in one `identifier`; `info` is the only tool that answers without a credential.

### Calling Convention And Credential

- The packet recorded the synchronous calling convention established by phase 002: inside `call_tool_chain`, tools are synchronous; no `await`, no top-level `await`, no returned Promise (a returned Promise silently marshals as `{}`); plain JavaScript only, because TypeScript type annotations fail to parse; and a failing command does not throw but returns the error text or a JSON error object as an ordinary value, so callers must inspect the returned value rather than rely on `try`/`catch`.
- The credential path was documented: `magicpath-ai login` (browser) or the `MAGICPATH_TOKEN` environment variable, wired as `magicpath_MAGICPATH_TOKEN` in `.env` (Code Mode prefixes env vars with the manual name). Without a credential, a call returns structured JSON `{"error":"Not authenticated. Set MAGICPATH_TOKEN or run \`magicpath-ai login\`.","code":"NOT_AUTHENTICATED","suggestion":"..."}`, except `info`, which answers without credentials.
- The stale-surface warning was recorded: `magicpath-ai info -o json` reports a `cli.commands` list that is stale and under-reports the real surface; `magicpath-ai --help` is authoritative, and the registered manual is the source of truth for what an agent can call.

### Mutation Boundary

- The packet stated that the registered surface is read-only on purpose. The CLI can also write `.tsx` files into the calling project, install npm packages, and create remote projects and component revisions (`add`, `code`, `image`, `create-project`, `clone`), but those commands are deliberately not registered, so an agent cannot reach them through a tool call.
- `inspect_component` was flagged as the safe read path: it reads source, dependencies, and imports without installing anything and without a package manifest, so it is the only way to read a component into a non-React project.
- The packet refused to invoke, document as reachable, or route to any unregistered write command, and escalated write requests to the operator or a workflow that runs the CLI directly outside a tool call.

### Feature Catalog

- `feature-catalog/` supplied a root inventory, six domain overviews (one per theme), and one leaf for each of the fourteen tools, including call forms, argument bounds, the cursor-pagination rule, the `identifier` union, the credential split, mutation class, and cross-links to the canonical references.
- The per-tool leaf count equaled the fourteen registered tools, and the catalog treated any live drift from those tools as a fail-closed escalation.

### References, Assets, And Documentation

- `references/tool-surface.md` carried the fourteen-tool contract, the read funnel, the stale-`cli.commands` warning, the calling convention, and open questions.
- `references/credential-setup.md` carried the registered manual, the env-var wiring, the unauthenticated failure shape, the callable naming rule, and the discovery-first contract.
- `references/mutation-boundary.md` carried the registered read-only surface versus the deliberately unregistered write surface, and the escalation path for write requests.
- `assets/utcp-magicpath-manual.md` preserved the registered manual snapshot, the env-var wiring, and the exec-wrapper behavior (placeholder stripping and structured JSON errors).
- `README.md` described current-state use, the read funnel, the wiring, the mutation boundary, troubleshooting, and verification. All packet paths used kebab-case.

### Boundaries

- No hub files or live configuration belonged to this packet's release. The packet created no `description.json`, `graph-metadata.json`, `mode-registry.json`, or `hub-router.json`; those are hub-root-only and were left for phase 004.
- No undocumented tools, arguments, limits, or authentication results were claimed, and no capability from MagicPath's website or README beyond the registered manual's output was documented.
