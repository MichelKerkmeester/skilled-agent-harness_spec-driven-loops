# mcp-obsidian — v1.3.0.0

Extends the mode's plugin knowledge with Iconic, mirroring the existing per-plugin reference pattern (index + data-model + workflows + troubleshooting).

## 1. NEW

- **Iconic (`iconic`) reference set** — `references/plugins/iconic/`: the single `data.json` configuration surface (visibility toggles, color pickers, per-item icon maps, `fileRules` 21 + `folderRules` 11), the rule schema (`{id, name, icon lucide-*, color hex, match, conditions, enabled}`), and the mandatory backup-before-merge discipline (merge, never replace; never downgrade). Verified against the live vault state: v1.1.10 enabled in all three vaults with the rulebook already applied.
- **Router + docs** — `SKILL.md` v1.3.0.0: activation triggers for icon/rule requests, the reference set added to load-on-demand, keyword comment extended. `plugin-operation-logic.md` data map grows from 4 to 5 rows.
- **Catalog + playbook** — feature card `feature-catalog/plugins/iconic.md`; scenario `OBS-015` (Iconic rulebook merge round-trip); indexes updated.
- **Asset** — `assets/plugins/iconic/iconic-rules.example.json`.

## 2. CHANGED

- `SKILL.md` version 1.2.0.0 → 1.3.0.0 (frontmatter + keywords).
- `feature-catalog/FEATURE-CATALOG.md` plugin category: 4 → 5 plugins.
- `manual-testing-playbook/manual-testing-playbook.md`: 20 → 21 scenarios (OBS-011..OBS-015).

## 3. NOT CHANGED

- No vendored plugin code; the asset is an example rulebook excerpt.
- Existing four plugin reference sets untouched (except the shared data-map table).
- Vault install state untouched — Iconic was already installed + rulebook applied in all vaults.
