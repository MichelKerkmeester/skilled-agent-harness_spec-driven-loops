Corrects the Health.md plugin example assets and the docs that teach them so they match the export contract the plugin actually implements. The previous fixture carried a key real exports never write, the quick-start examples used a code fence the plugin cannot read, and the playbook, catalog card, and operation-logic row still framed the plugin as Apple-only with no guard against bundled mock data. The assets now follow the researched v7 daily-summary shape and the health-viz render contract, and the docs carry the mock-fallback guard plus the Apple/Android framing.

> Research source: `.opencode/specs/mcp-tooling/013-mcp-obsidian/012-skill-support-extension/research/lineages/codex/research.md` (Health.md plugin deep dive: v7 export shape in section 1, health-viz render grammar in section 3, file layers in section 4, Apple/Android boundaries in section 5, reference-set remediation order in section 7).

## What Changed

#### Bug Fixes

- **Schema-true export fixture** -- The example JSON contained a `source` key that real v7 exports never write, teaching a false schema and inviting validation failures. The fixture is rewritten to the researched shape only: `healthmd.health_data` wrapper, `schema_version` 7, `timezone`, and two `days` entries with `date` plus `statistics` including canonical `unit` values. Copy-paste examples now match what the plugin actually reads.

#### Documentation

- **health-viz render blocks** -- Quick-start examples used a code fence the plugin cannot read plus invented options that no registered renderer accepts, so example charts silently fell back to bundled mock data. The new `health-viz-blocks.example.md` shows only the researched block forms: the registered `step-spiral` renderer with documented keys (`width`, `height`, `from`, `to`, `last`, `clickAction`, and the `{{today:YYYY-MM-DD}}` dynamic date variable), plus the explicit warning that a rendered chart from an empty folder is bundled mock data, not proof of real exports.
- **Catalog card aligned to the researched contract** -- The feature-catalog card framed Health.md as Apple-only, described the wrong fence, and listed only the JSON fixture. It now covers Apple v7 plus Android frozen v4 / analytical v5 profiles with shared chart coverage and the platform gaps (iOS-only mood/medication; Android walking-symmetry gap and steps-derived Stand proxy), documents the `health-viz` render block and the mock-fallback warning, lists both example assets, and adds guardrails: mock-fallback verification, raw/lossless archive exclusion, and never synthesizing observations, roll-ups, or dictionaries.
- **Operation-logic row covers Apple + Android** -- The health-md row in `references/plugins/plugin-operation-logic.md` framed the data surface as Apple export files only. It now names Apple + Android Health export files, the `health-viz` render blocks, and the requirement to verify the real folder plus an authentic source because the bundled mock-data fallback renders on an empty folder.

#### Testing

- **OBS-014 playbook scenario reworked** -- `manual-testing-playbook/plugin-tie-ins/health-md-data.md` still taught the old fence with invented keys, wrote a `source` key real exports never carry, and had no guard against the bundled mock-data fallback. The scenario (1.2.0.0 → 1.2.1.0) now resolves the actual data folder from settings and lists it before any write, stating that a missing or empty folder renders deterministic bundled example data and that no chart can count as evidence; verifies the selected folder plus at least one authentic source file; writes the schema-true throwaway shape (schema_version/timezone/days only, pointing at the canonical fixture); places the researched-validated `health-viz` block (`type: step-spiral`, `last: 7`); and grades mock-only evidence as FAIL.
