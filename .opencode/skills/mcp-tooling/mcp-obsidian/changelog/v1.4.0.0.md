Corrects the Health.md plugin example assets so they teach the export contract the plugin actually implements. The previous fixture carried a key real exports never write, and the quick-start examples used a code fence the plugin cannot read, so copying them produced charts that never render or a false schema. Both assets now follow the researched v7 daily-summary shape and the health-viz render contract.

> Research source: `.opencode/specs/mcp-tooling/013-mcp-obsidian/012-skill-support-extension/research/lineages/codex/research.md` (Health.md plugin deep dive: v7 export shape in section 1, health-viz render grammar in section 3, file layers in section 4).

---

## What Changed

#### Bug Fixes

- **Schema-true export fixture** -- The example JSON contained a `source` key that real v7 exports never write, teaching a false schema and inviting validation failures. The fixture is rewritten to the researched shape only: `healthmd.health_data` wrapper, `schema_version` 7, `timezone`, and two `days` entries with `date` plus `statistics` including canonical `unit` values. Copy-paste examples now match what the plugin actually reads.

#### Documentation

- **health-viz render blocks** -- Quick-start examples used the `health-md` fence and invented options (`type: chart`, `dateRange`) that no registered renderer accepts, so example charts silently fell back to bundled mock data. The new `health-viz-blocks.example.md` shows only the researched block forms: the registered `step-spiral` renderer with documented keys (`width`, `height`, `from`, `to`, `last`, `clickAction`, and the `{{today:YYYY-MM-DD}}` dynamic date variable), plus the explicit warning that a rendered chart from an empty folder is bundled mock data, not proof of real exports.
