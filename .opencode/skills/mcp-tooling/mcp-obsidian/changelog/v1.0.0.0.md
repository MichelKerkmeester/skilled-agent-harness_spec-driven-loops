## Adopted Surface Set

| Surface | Adopted package or binary | Runtime model |
|---|---|---|
| Headless CLI | Yakitrak `notesmd-cli` | Operates directly on the vault filesystem with no running app |
| App-backed CLI | Official `obsidian` CLI in Obsidian desktop v1.12.4+ | Remote-controls a live desktop app after in-app registration |
| Default MCP | cyanheads `obsidian-mcp-server@3.2.9` | Code Mode stdio server using Local REST API v4.0.0+ and a bearer token |
| Headless MCP alternative | StevenStavrakis `obsidian-mcp@1.0.6` | Filesystem-based; verify no-app/no-token behavior before relying on it |

---

## Architecture Decisions

| Decision | Choice | Rationale |
|---|---|---|
| Default CLI | `notesmd-cli` | It operates on vault files without a running app or token |
| App-backed CLI | Official `obsidian` binary | It is the appropriate surface for live UI and app-context outcomes |
| Default MCP | Cyanheads `obsidian-mcp-server@3.2.9` | It provides the live-app structured note, search, tag, and delete surface through Local REST API |
| Routing model | Runtime profile selection | The app-backed paths have hard prerequisites the headless path does not |
| MCP configuration | Document and print the manual only | This mode must not auto-modify `.utcp_config.json` or `.env.example` |
| Plugin operations | File-layer data edits | The mode can operate the plain files plugins render without pretending to drive their UI |

## Known Limitations

- The official `obsidian` CLI's full command and flag inventory is not confirmed here; run `obsidian --help` after enabling it and mark unconfirmed specifics `VERIFY`.
- Five MCP core tool names are confirmed; enumerate the full 14-tool surface with `list_tools()` and confirm signatures with `tool_info()` before use.
- The cyanheads MCP is app-backed: it needs a running Obsidian app, Local REST API v4.0.0+, and an API key.
- The StevenStavrakis headless MCP alternative is documented for context only; verify its no-app/no-token behavior in the target environment.
