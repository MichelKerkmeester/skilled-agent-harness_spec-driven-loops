# mcp-obsidian v0.15.0.0

Two small, evidence-backed refinements: ground the couple of VERIFY markers that the installed plugin sources actually resolve, and promote the Local REST API surface from a caveat note to a real reference.

---

## 1. NEW

- **`references/lra-rest-surface.md`** — a reference for the `obsidian-local-rest-api` plugin's own surface: its 14 REST endpoints (read authoritatively from the plugin's `GET /openapi.yaml`, installed `self: 5.1.0`) and its built-in Streamable-HTTP MCP at `/mcp/` (confirmed live via an `initialize` handshake). It documents the bearer-token + loopback-only TLS boundary and how to tell this surface apart from the cyanheads `obsidian-mcp-server` (`obsidian_*` tools). Wired into `SKILL.md` `MCP_ADVANCED` routing and cross-linked from `references/mcp-tools.md`.

## 2. CHANGED

- **`references/plugins/minimal/data-model.md`** — grounded the enabled-snippets key: it is `enabledCssSnippets` in `appearance.json` (absent until the first snippet is enabled), replacing the prior VERIFY.
- **`references/plugins/charts/data-model.md`** — grounded the block-language set: the installed 3.9.0 registers exactly `chart` and `advanced-chart` (confirmed from `main.js` `registerMarkdownCodeBlockProcessor`), replacing the prior VERIFY.
- `SKILL.md` version 0.14.0.0 → 0.15.0.0.

## 3. NOT CHANGED

- The remaining `VERIFY` markers stay as honest-uncertainty: they are genuine runtime/per-vault/large-API caveats or details only extractable by deobfuscating minified plugin bundles (which would risk fabrication). Only the two cleanly source-confirmed markers were grounded.
- No vault, plugin, or runtime data was touched. `README.md` stays at `0.12.0.0`.
