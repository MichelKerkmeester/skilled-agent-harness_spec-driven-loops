# mcp-obsidian — v1.1.0.1

Doc corrections from the live playbook validation run (18/19 scenarios PASS + routing benchmark PASS 98, executed by deepseek-v4-flash via cli-pi and cli-opencode against a live vault).

## 1. FIXES

- **notesmd-cli `search` (title) is broken in v0.3.6** — it returns "Cannot find note in vault" even for on-disk notes (validated, the run's only scenario failure). `SKILL.md` and `references/obsidian-cli-commands.md` now steer name lookups to `notesmd-cli list` + filter (or `search-content` for bodies); `search-content` is the reliable body-search surface.
- **Second MCP server documented** — the `obsidian-local-rest-api` plugin (v5.1.0+) ships its OWN built-in MCP at `https://127.0.0.1:27124/mcp/` exposing **16 `vault_*` tools**, distinct from the cyanheads `obsidian-mcp-server` `obsidian_*` surface this catalog documents. `SKILL.md` and `references/mcp-tools.md` now warn not to conflate the two tool namespaces.

## 2. VERIFIED SURFACES

Headless notesmd-cli (7/8), MCP round-trip over the live Local REST API (6/6), plugin file-layer ops for beancount/tables/BRAT (3/3), and the official `obsidian` CLI (2/2) all ran green; the 7-mode hub routing benchmark passed at 98.
