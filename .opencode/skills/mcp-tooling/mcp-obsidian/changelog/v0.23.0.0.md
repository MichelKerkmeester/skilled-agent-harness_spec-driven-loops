# mcp-obsidian v0.23.0.0

The official `obsidian` CLI was named as one of the skill's three surfaces but never documented well enough to drive. Its command list was marked `VERIFY`, its syntax was written as POSIX flags and bare positional arguments, and eight files repeated that the CLI launches the desktop app when it is not running. Running the installed binary showed otherwise on every point. This release replaces the guesses with measured behavior, adds the agent-facing usage layer, and makes `doctor.sh` report whether the surface can actually answer.

---

## 1. ADDED

- **`references/official-cli-agent-usage.md`**. The agent contract for the official CLI, with every claim observed against desktop 1.13.7 (installer 1.13.4). It covers the `obsidian version` preflight and how to tell "not registered" from "app not running". It covers the exit-0 failure contract and the stdout check that replaces `$?`, the `obsidian <command> key=value` grammar and the global `vault=` option, and a grouped index of all 106 commands plus confirmed parameters for the 13 an agent uses most. It closes with five safety invariants, a worked script, a table of where Obsidian's own documentation disagrees with the binary, and a verification-status section listing what stayed UNKNOWN with the check that would settle each.
- **`OFFICIAL_CLI` router intent** in `SKILL.md`. weight 6 with app-backed vocabulary (`official cli`, `app-backed`, `register cli`, `backlinks`, `orphans`, `base:query`, `unable to find obsidian` and siblings) so official-CLI questions stop resolving to `NOTES_CLI` and loading the notesmd-centric reference. Wired into `INTENT_SIGNALS`, `RESOURCE_MAP`, the §2 loading map, the §8 reference inventory, and the intent count in the routing comment.
- **`examples/official-cli-workflow.sh`**. A preflight-create-append-property-read-delete round trip that demonstrates the `obs()` wrapper turning the CLI's own `Error:` text back into a non-zero status, reads the created filename back out of the `Created:` line, and cleans up through an exit trap. Indexed as §3.3 in `examples/README.md`.
- **Live probe in `scripts/doctor.sh`**. Runs `obsidian version` rather than only checking PATH, so a registered binary with a closed app now warns instead of reporting a green check.
- **`troubleshooting.md` §5b and §5c**. The app-not-running failure (`The CLI is unable to find Obsidian`, stderr, exit 1) and the exit-0-on-error failure, neither of which had any coverage anywhere in the skill.

## 2. CHANGED

- **The "launches the app" claim is false and was removed from the eight files that carried it:** `references/obsidian-cli-commands.md` (5 places, one of them a table row labelled `Confirmed behavior`), `SKILL.md` (4), `manual-testing-playbook/official-cli/open-app-action.md` (3) and one place each in `INSTALL-GUIDE.md`, `references/troubleshooting.md`, `feature-catalog/FEATURE-CATALOG.md`, `feature-catalog/cli/open-note-or-vault.md` and `scripts/install.sh`. That is 17 lines across 8 files. With the app down the CLI exits 1 and leaves the app down.
- **Three further files were touched without having carried the claim.** `README.md` and `manual-testing-playbook/official-cli/register-and-help.md` never asserted a launch, so they only gained the corrected `obsidian version` guidance. `mcp-servers/obsidian-cli/setup.sh` did carry the claim and kept it: its `(launching it if not running)` line survived this release with a contradicting sentence added underneath and was removed later in `f140793f3a`.
- **`obsidian --help` replaced with `obsidian help` in 15 files.** `obsidian help` is the canonical form and the one the rest of this release documents. The reason first given here was wrong. `--help` does not fail: on desktop 1.13.7 it exits 0 and prints the full help, byte for byte identical to `obsidian help`. The flags that fail are `-h`, `-v` and `--version`, each printing `Error: Command "<flag>" not found` on **stdout** and exiting **0**, under the same exit-0 failure contract as any other rejected command. `notesmd-cli --help` is untouched, since that binary does take POSIX flags.
- **Positional-argument examples replaced with the real grammar.** `obsidian "<vault/path>"` and `obsidian "TEST_TARGET"` became `obsidian open file="<name>"` in `SKILL.md`, the playbook root and `official-cli/open-app-action.md`.
- **`references/obsidian-cli-commands.md` §8 rewritten** from a `VERIFY` stub into a confirmed capability table, and §3's selection table gained the four app-only capability rows (resolved link graph, computed tag and task index, Bases and history, plugin and theme state) that previously had no home. §9 now notes the official CLI's single global option, and §11 invariant 5 carries the preflight and the stdout check.
- **`SKILL.md` surface tables, quick reference and success criteria** now describe the app-backed CLI by what only the live app can produce, and the quick reference lists 11 confirmed commands instead of 2 unverified ones.
- **Both `official-cli/` playbook scenarios** preflight with `obsidian version` and judge results by stdout rather than exit status. The playbook's global precondition 5 and its command-notation line were corrected to match.
- **`INSTALL-GUIDE.md` troubleshooting table** gained rows for the app-down failure and for POSIX-flag misuse.

## 3. VERIFICATION

- Command surface captured from `obsidian help` on the installed binary: 106 commands.
- Failure contract established by negative control. With the app down: `obsidian version` printed to stderr and exited 1, and the app was **not** launched. With the app running: a missing file, an unknown command and an unknown vault each printed to stdout and exited **0**.
- Active-file hazard confirmed: a bare `obsidian read` returned the note open in the UI.
- Collision behavior confirmed: `create` against an existing name produced `<name> 1.md` and exited 0.
- Round trip exercised on one scratch note (create, append, `property:set`, read, `search`, `search:context`, permanent delete), with the vault's markdown file count reconciled to its pre-change baseline afterwards.
- `doctor.sh` run in both conditions: warns with the app down, reports the version with the app up.
- `examples/official-cli-workflow.sh` run in both conditions: exits 1 with actionable guidance when the app is down, completes the round trip and removes its note when the app is up.
- Router verified by executing `SKILL.md`'s own `route_obsidian_resources` against test prompts: five official-CLI phrasings resolve to `OFFICIAL_CLI` and load the new reference, while `NOTES_CLI`, `MCP_ADVANCED`, `PLUGIN_DATAVIEW`, `INSTALL`, `TROUBLESHOOT` and `NOTION_MIGRATION` are unchanged.
- `bash -n` passes on all four touched shell scripts.
