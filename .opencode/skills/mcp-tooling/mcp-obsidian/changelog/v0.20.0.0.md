# mcp-obsidian v0.20.0.0

Expands `mcp-obsidian` beyond the migration plugins to the operator's broader stack. Nine community plugins were installed into the real vault; the three with an AI-authorable file-layer data model got dedicated reference trees; a roster now lists every enabled vault plugin (including the ones that intentionally have no dedicated docs); and the three new plugins are wired into the router.

---

## 1. CHANGED

- **Installed nine community plugins into the operator's real vault** via BRAT-headless (operator-approved, executed 2026-08-22): `virtual-linker`, `editing-toolbar`, `notebook-navigator`, `advanced-canvas`, `realclaudian` (Claudian), `obsidian-custom-frames`, `darlal-switcher-plus`, `project-manager`, `link-favicon`. Each `manifest.id` was derived from the downloaded manifest (never assumed); `community-plugins.json` went 12 → 21 ids and BRAT `data.json` gained nine frozen-version entries, both backed up to timestamped `.bak` first. Obsidian 1.13.4 clears every plugin's `minAppVersion` floor.
- **New `references/plugins/advanced-canvas/` 4-file tree** documenting how the plugin extends the native `.canvas` JSON — node `styleAttributes` (shape/border/textAlign), edge `styleAttributes` (path/arrow/pathfindingMethod), `metadata.startNode` presentation order, `portal` nodes, and collapsible groups. Node/edge keys were read from the installed `main.js` (v6.5.4); the cross-portal edge serialization is flagged `VERIFY`.
- **New `references/plugins/claudian/` 4-file tree** documenting the plugin that embeds coding-agent CLIs inside the vault (id `realclaudian`, display name "Claudian"). Covers the `.claude/` in-vault artifacts (commands, skills, `mcp.json`, settings) read from `main.js` (v2.2.4), the local-CLI-execution model, and a three-name disambiguation (Claudian vs ClaudianIA vs Claudian Plus). Config schemas beyond observed path strings are flagged `VERIFY`.
- **New `references/plugins/project-manager/` 4-file tree** documenting the `pm-task` frontmatter schema (status/priority vocab, `dependencies`/`parentId`/`subtaskIds`, `timeLogs`, `customFields`) read from `main.js` (v1.8.0) — Table/Gantt/Kanban views driven from frontmatter. Non-scalar `customFields` encoding and `recurrence` fields beyond the three confirmed are flagged `VERIFY`.
- **Three new `feature-catalog/plugins/` entries** for the plugins above.
- **New `references/plugins/installed-plugins.md` roster** — all 21 enabled vault plugins, split into 15 file-layer (with dedicated docs) and 6 UI/automatic (without). Includes the "do not remove `obsidian-local-rest-api`" warning (it is the MCP transport backbone) and the two documented soft overlaps.
- **`SKILL.md`: three new router intents** (`PLUGIN_ADVANCED_CANVAS`, `PLUGIN_CLAUDIAN`, `PLUGIN_PROJECT_MANAGER`), additive-only, mirroring the existing per-plugin pattern — §2 Resource Loading Levels, `INTENT_SIGNALS`, `RESOURCE_MAP`, the `specific_plugin_intents` tuple, the `PLUGINS` aggregate (plus the roster), and §8 References. The `INTENT_SIGNALS` count comment updated `nineteen` → `twenty-two`.
- `SKILL.md` version `0.19.0.0` → `0.20.0.0`; `leaf-manifest.json` regenerated to register the new reference files.

---

## 2. WHY

- The operator requested nine more plugins be installed and supported in the skill, and asked for a roster that displays every plugin in use — even those that get no dedicated integration docs.
- Only three of the nine expose a vault syntax or data model an AI authors against, so only those three got reference trees; the other six are UI-only or automatic (formatting toolbar, file-explorer replacement, quick-switcher, favicons, iframe frames, auto-linking) with nothing to author against.
- The obsolescence review found no plugin should be removed: two soft overlaps (Claudian vs Local REST API, Project Manager vs Dataview/Notion Bases) are documented as coexisting, and removing Local REST API would break the skill's own MCP path.

## 4. NOT CHANGED

- The six UI/automatic plugins get no dedicated `references/plugins/<name>/` tree by design — they appear only on the roster.
- No existing plugin folder was edited and no plugin was removed; the change is additive.
- §8 References already omitted seven older plugin folders (charts, dataview, excalidraw, git, outliner, minimal, health-md) before this release; that pre-existing gap was left untouched (scope lock) — this release added only its own three plus the roster.
- Activation of the nine installed plugins completes on the operator's next Obsidian open; this session confirmed the file-layer install and registration, not the live load.
