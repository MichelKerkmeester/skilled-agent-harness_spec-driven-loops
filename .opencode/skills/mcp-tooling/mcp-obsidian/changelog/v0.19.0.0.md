# mcp-obsidian v0.19.0.0

Two jobs on the shipped `mcp-obsidian` skill: ground-truth the Notion Bases plugin reference tree against the plugin's now-confirmed README (the plugin is installed at v1.12.0 in the operator's vault), and add the missing `obsidian-local-rest-api` plugin reference folder — the one enabled vault plugin that had no `references/plugins/<name>/` tree.

---

## 1. CHANGED

- **`references/plugins/notion-bases/{notion-bases,data-model,workflows,troubleshooting}.md` de-hedged against confirmed facts.** The plugin's own README confirms: the database definition (a folder + `_database.md` + per-row frontmatter), the 18 exact column types (`title, text, number, select, multiselect, checkbox, date, url, email, phone, status, formula, relation, lookup, image, rollup, audio, video`), the 7 exact view types (`table, list, board, gallery, calendar, timeline, chart`), the 7 exact rollup functions (`sum, count, avg, min, max, count_values, list` — corrects the earlier `average` to the plugin's actual `avg` keyword), and the `nb-database` fenced-code-block embed syntax (previously undocumented — a view had no described way to render inside a note). The repeated per-example `VERIFY exact keys` hedge headers were consolidated into a single up-front note: the shapes above are confirmed, only the exact per-column YAML key spelling inside a `_database.md` declaration remains unconfirmed.
- **Added the `nb-database` embed syntax** to `notion-bases.md` §2, `data-model.md` §6, and a new workflow step + checkpoint in `workflows.md` §6, plus matching failure-mode entries in `troubleshooting.md` (§1, §2, §5, §7, §8).
- **New `references/plugins/obsidian-local-rest-api/` 4-file tree** (`obsidian-local-rest-api.md`, `data-model.md`, `workflows.md`, `troubleshooting.md`), mirroring the Dataview plugin's 4-file shape. Consolidates what `SKILL.md`, `references/mcp-tools.md`, and `references/troubleshooting.md` already documented about the plugin (the `OBSIDIAN_API_KEY`/`OBSIDIAN_BASE_URL`/`OBSIDIAN_VERIFY_SSL` env contract, the two loopback endpoints, and the app-must-be-running boundary) without duplicating or moving any existing SKILL.md content.
- **`SKILL.md`: new `PLUGIN_LOCAL_REST_API` router intent**, additive-only, mirroring the `PLUGIN_DATAVIEW` pattern — §2 Resource Loading Levels, `INTENT_SIGNALS`, `RESOURCE_MAP`, the `PLUGINS` aggregate, the `specific_plugin_intents` tuple, and §8 References. The `INTENT_SIGNALS` count comment updated `eighteen` → `nineteen`.
- `SKILL.md` version `0.18.0.0` → `0.19.0.0`.

---

## 2. WHY IT WAS MISSED

- Phase 003 (`specs/mcp-tooling/015-notion-to-obisidian-migration/003-notion-bases-plugin-tie-in/`) authored the Notion Bases reference tree before the plugin was installed anywhere, so every schema example was correctly flagged `VERIFY` at the time. The plugin's install in the operator's vault (v1.12.0) surfaced its README, confirming most of what was previously hedged and revealing one new mechanic (`nb-database` embeds) and one naming correction (`avg`, not `average`).
- `obsidian-local-rest-api` was the one enabled vault plugin without a dedicated reference folder — its behavior was already documented, but scattered across `SKILL.md` §3, `references/mcp-tools.md`, and `references/troubleshooting.md` rather than consolidated into the per-plugin shape every other plugin uses.
