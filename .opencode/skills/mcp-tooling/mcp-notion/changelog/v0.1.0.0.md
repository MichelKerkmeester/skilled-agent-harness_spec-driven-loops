# v0.1.0.0 — Initial Release

**Released:** 2026-08-21

---

## What's New

Initial `mcp-notion` **light workflow mode**, authored from the BUILD verdict of the `014-mcp-notion` deep-research synthesis. The mode mirrors the `mcp-click-up` pattern (a light workflow mode, not a thin transport and not a full multi-plugin skill) because Notion mutates the workspace, needs direct-API calls beyond the MCP, and must route between two backends.

### Capability Surface

- **Official Notion MCP** — `@notionhq/notion-mcp-server`, **24 tools** across 6 domains: pages (7), blocks (5), databases/data-sources (6), comments (2), users (3), search (1). Registered as the `notion` manual in `.utcp_config.json` and invoked via Code Mode.
- **5 direct-API gap fills** — file uploads, views, non-truncated page property items, async-task polling, and daily-note conventions — reachable with direct Notion REST calls using the same `NOTION_TOKEN`.
- **Dual backend** — local stdio (`NOTION_TOKEN`, headless, the registered default) versus remote (`https://mcp.notion.com/mcp`, OAuth, interactive-only). Smart-router selects local stdio for headless Code Mode.

### Supporting Docs

- `feature-catalog/FEATURE-CATALOG.md` — current-state inventory: 24 MCP tools by domain, 5 API-gap fills, and the knowledge-layer references (hierarchy, 22 property types, relations/rollups/Formulas 2.0, rate limits, API-version pinning).
- `manual-testing-playbook/manual-testing-playbook.md` — 11 read-only / scratch-safe scenarios: MCP tool round-trips via Code Mode, an API-gap direct call, backend selection, and auth failure.
- `examples/README.md` — Code Mode workflow index: page create, data-source query, add relation.

### Scripts

- `scripts/install.sh` — checks Node 18+ and `npx`, prints the Code Mode manual snippet and the `notion_NOTION_TOKEN` env key. Writes no config files. Supports `--check-only` and `--mcp-only`.
- `scripts/doctor.sh` — read-only diagnostics: Node/npx, whether the `notion` manual is registered in `.utcp_config.json`, and whether `notion_NOTION_TOKEN` is set (presence only). No mutation.

## Architecture Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Skill shape | Light workflow mode (mcp-click-up pattern) | Notion mutates the workspace and needs direct-API calls beyond the MCP |
| Not a thin transport | Rejected | A transport cannot make the 5 direct-API calls or route between two backends |
| Not a full skill | Rejected | Notion has no third-party plugin ecosystem; the mcp-obsidian 11-plugin depth is unnecessary |
| Primary tool | Official Notion MCP (24 tools) | Maintained by Notion; covers all CRUD |
| Gap fills | Direct Notion REST | 5 tooling gaps the MCP does not expose |
| Backend | Local stdio registered; remote noted | Code Mode is headless; the remote OAuth server cannot run headless |
| CLI | None | Notion is MCP-only |

## Known Limitations

- Search is **title-only** — there is no full-text content search (a structural platform limit).
- No **hard delete** — deletes are reversible archive-to-trash.
- Notion is deprecating the open-source **local stdio server** in favor of the remote OAuth server; the headless Code Mode path depends on the local server, so this is a tracked risk.
- Async-task polling is not exposed by the local backend — use a direct API poll or the remote MCP.
- Exact registered tool identifiers differ between the local and remote backends; confirm names live with `list_tools()` / `tool_info()`.
