## [**1.5.2.0**] - 2026-08-21

This release makes the worktree base directory configurable so worktrees can live outside the primary checkout. Nesting dozens of worktrees under the checkout at `.worktrees/` forces everything that scans from the repo root — `git status`, the fsmonitor daemon, Git GUIs, and file-sync clients — to walk every worktree's `node_modules` on each pass, which shows up as sustained CPU on large trees. A new `speckit.worktreeBase` (or `SPECKIT_WORKTREE_BASE`) resolves in the allocator, the launch wrapper, and the reaper; it defaults to the in-checkout `.worktrees`, so a clone that sets nothing behaves exactly as before. Branch grammar, number allocation, the gates, and the commit rules are unchanged.

---

## What Changed

#### The worktree base directory is configurable

- **`worktree-naming.sh` resolves a base via `_wn_base_dir`.** Precedence is env `SPECKIT_WORKTREE_BASE`, then git config `speckit.worktreeBase`, then the default `.worktrees` relative to the main toplevel. A relative value resolves against the toplevel; a leading `~` expands to `$HOME`. `create` and `create-detached` now create under that base and emit an absolute directory path.
- **`is_valid_pair` is migration-tolerant.** A `worktrees/NNN-slug` branch validates against a directory whose basename is `NNN-slug` sitting under either the configured base or the legacy `.worktrees` parent, so worktrees created before and after a relocation both pass.
- **The launch wrapper and reaper resolve the same base.** `worktree-session.sh` places session worktrees under the resolved base; `worktree-reaper.sh` prunes and daemon-orphan-detects against it. The reaper's orphan detection now anchors on the resolved base by canonicalizing each candidate path's parent rather than matching a fixed `.worktrees/` string, which also makes it immune to `/var` vs `/private/var` symlink skew.

## Not Changed

- The default is still in-checkout `.worktrees`. Other clones, CI, and the test suite are unaffected unless a base is explicitly configured.
- Branch grammar (`worktrees/NNN-slug`, `branches/NNN-slug`), the locked per-namespace allocator, remote-push permission, and every pre-push/commit gate are untouched.
- Number allocation is location-independent — it scans each registered worktree's basename regardless of where it lives — so relocating the base can never reissue a live number.

---

## Migration Notes

Opt in per clone with `git config speckit.worktreeBase <absolute-path>` (or export `SPECKIT_WORKTREE_BASE`); new worktrees then land there. Relocate existing worktrees with `git worktree move <old> <new>` and run `git worktree repair` afterward. Unset the config to return to the in-checkout `.worktrees` layout. No action is required for a clone that leaves the setting unset.
