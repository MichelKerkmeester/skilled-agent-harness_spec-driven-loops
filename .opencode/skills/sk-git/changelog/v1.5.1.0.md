## [**1.5.1.0**] - 2026-08-20

This release closes a way the live-sync reconcilers could silently rewind a branch and drop a just-made commit. When a stale or foreign rebase state directory was present, a blanket `git rebase --abort` reset the branch to that rebase's orig-head; the fast-forward-only follower then advanced the now-behind branch, so the commit disappeared locally while surviving on the remote. Both reconcilers now refuse a rebase they did not start and restore the pre-rebase commit if any abort moves HEAD. Branch grammar, the allocator, the gates, and the commit rules are unchanged.

---

## What Changed

#### The live-sync reconcilers no longer abort a foreign rebase

- **`git-primary-reconcile.sh` and `git-sync.sh` refuse a pre-existing rebase.** Before rebasing onto the live tip, each script checks for an existing `rebase-merge`/`rebase-apply` state directory. If one is present the script records a block and stops without touching it — it never aborts a rebase it did not start. This removes the path where a leftover rebase (a killed or stale one) made the script's own `git rebase` fail instantly and the blanket `git rebase --abort` fallback then reset the branch to the foreign rebase's orig-head.
- **A detected rewind is now undone, not just reported.** After its own abort, each script compares HEAD to the commit that was checked out before the rebase and force-restores it with `git reset --hard` if the abort landed elsewhere. `git-primary-reconcile.sh` previously detected this drift but only warned and exited, leaving the branch rewound; `git-sync.sh` captured no pre-rebase SHA at all and recorded the rewind as `aborted cleanly`. Both now put HEAD back before reporting.

## Not Changed

- No branch grammar, allocator, or commit rule changed. The owner-first naming, remote-push permission model, and every pre-push/commit gate are untouched.
- `git-live-follow.sh` is unchanged. It is fast-forward-only and was the collateral advance after the branch was rewound, never the destructive actor.
- The genuine-conflict and clean-publish paths are unchanged: an own-rebase conflict still aborts cleanly with the local commits preserved, and a clean divergence still rebases and publishes.

---

## Migration Notes

No action required — the guards take effect at the next SessionStart reconcile and the next post-commit sync. The disable flags are unchanged: `MK_LIVE_SYNC_DISABLED=1` for the whole loop, `MK_PRIMARY_RECONCILE_DISABLED=1` for the SessionStart reconcile leg, `SPECKIT_AUTOSYNC=0` for a single publish. If a stale rebase directory is ever present, `git-primary-reconcile.log` / `git-sync.log` now record a `pre-existing rebase in progress; refused` block instead of a rewind. The full model and safety contract live in `references/continuous-integration.md`.
