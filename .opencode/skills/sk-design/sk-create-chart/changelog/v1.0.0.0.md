First release of `sk-create-chart`, a workflow packet in the `sk-doc` parent hub. It answers a request for a data chart with one HTML file that opens on a double click, with no install step, no build step and no remote dependency of any kind. Twenty chart forms, three colour systems and six finished deliveries ship inside it, indexed by a catalog a check resolves in both directions, and a chart request now reaches the mode through both hub routing stages.

---

## What Changed

#### New Features

- **Twenty chart forms, one file each.** They cover six question families: comparison, composition, time, distribution, relationship and matrix. Every form draws its own marks as inline vector output. Nothing animates, nothing fetches and no file carries a colour value outside its palette block.
- **Three colour systems, separated by what colour encodes.** `neutral` ranks by importance, `ordered` encodes magnitude and `categorical` encodes identity. Every value lives in `assets/color/palettes.json` and nowhere else, derived by mixing a base hue toward the surface or the ink until it lands on a target contrast ratio. The gate a value has to clear is selected by what it encodes, because a flat pairwise gate is arithmetically unsatisfiable past two values and a flat ramp gate deletes the light end of every scale. Three palette sheets render the whole set in a browser and recompute the contrast arithmetic from what the browser resolved.
- **A catalog checked in both directions.** Every row reaches a file that identifies itself with the same id, and every form on disk carries a row. An index that names a chart it cannot reach is worse than no index, which is why one direction was never enough.
- **A template-first contract of thirteen enforced rules.** The palette arrives inline as a sentinel-marked block of CSS custom properties, the data arrives in a second sentinel-marked block at the top of the script and everything below the data renders. A delivered file stays editable by hand end to end.
- **A corpus check with no dependencies.** `scripts/check-corpus.cjs` enforces every rule the contract states, computes contrast from the palette file rather than from a copy and never asserts that a document contains a particular sentence. With `--render` it opens each file in a headless browser, which is the only check that catches a chart drawing nothing.
- **Six worked deliveries, one per family.** Each is shaped exactly as a recipient receives it. A delivery differs from a template in the headline, the subtitle, the source line and the data. Nothing else changes. The drawing code is the same code, which is the point of having a form.
- **A stated boundary against `sk-create-diagram`,** which already claims bar, line, scatter, radar, Gantt and org-chart types by name. The split is what the artifact carries: values a reader compares, against a structure a reader follows. Thirty-three keywords split three ways to hold that line. Fifteen are form names the neighbour has no file for, such as `treemap`, `heatmap`, `box plot` and `histogram`. Fifteen are explicit chart-authoring phrasings. Three are data-qualified crossovers, `bar chart of`, `line chart of` and `scatter plot of`, which catch a request for a data chart while leaving the bare type name with the neighbour. A bare `chart` token was never a candidate, because `flowchart`, `org chart`, `gantt chart` and `radar chart` all contain it.
- **Both routing stages, not just registration.** The hub now carries sixteen modes and this is one of them. It has a registry entry, vocabulary in both stage-one metadata files, router intents and a resource map, a mode-table row, regenerated leaf-manifest entries and a single-route canary case the coverage guard counts. The advisor selects the hub for a chart request and the hub router then selects this mode.
- **A manual testing playbook.** Eight operator scenarios across three category folders, each admitted on one test: it fails for a reason no other scenario catches. Three cover what only a reader can see, three cover the corpus and two cover what reaches a user.
- **A licensing rule in the packet itself.** Every chart, palette and script here is authored here. Nothing is copied in from an outside chart library, because this repository is MIT and public and cannot hand onward a grant it was never given.

#### Notes

- **The packet was built empty first, then filled.** A packet that gains content and structure at once cannot tell you which of the two broke a gate, so the packaging gate ran against the shape alone before any content depended on it. The colour system, the template contract and the corpus check landed next, and the twenty forms were authored on top of them. The version story starts at adoption, and this entry describes the finished package rather than the first phase of it.
- **The check was written before the corpus grew, then broken nine ways on purpose.** Every break was applied to a passing corpus, run and then restored from a backup taken beforehand. A validator that has only ever passed is not evidence. It also caught two defects in itself during construction, an inverted monotonic comparison and a check that could fail without registering an assertion count.
- **The forms were authored in three batches with the check run after each one,** so a mistake in the idiom surfaced on three files rather than on twenty. The first pass was proven complete before the second started.
- **A visual pass found eight defects no automated check could see.** Every template and delivery was opened from a `file://` URL and the rendered page read. Three of the eight were headlines that misstated the data beneath them, on files that rendered perfectly and passed every check. No check reads a headline against its own numbers, and a second reader is the only control there is.
- **Report mode is cut, and its directory with it.** A report is a second product with its own layouts, its own selection rules and its own index, and nothing in the chart capability depends on it. Keeping it meant authoring twelve page layouts from nothing for a request nobody has made. There are no gallery pages either: one form is one file, and a gallery ships every other form's demo data alongside the one chart somebody asked for.
- **The render check is opt-in, so that a machine with no browser can never produce a silent skip that looks like a pass.** Sustained headless Chrome launches fail intermittently on some machines, which the check reports as a browser that returned no document. The discriminator is written down in the playbook: a different file each run that passes when opened by hand is the browser, and the same file every run is a chart drawing nothing.
