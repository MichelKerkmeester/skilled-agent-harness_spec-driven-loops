The corpus check is the packet's contract, and it had no coverage of its own. Two reviews found
twenty-one assertions inside it that passed for a reason other than the one their message gave.
Each was fixed by hand and re-proved by hand. That is now a suite, and it runs in CI.

## What Changed

#### New Features

- **`scripts/tests/corpus-mutations.test.cjs`.** Thirty-seven cases, each breaking exactly one thing and expecting one named family to say one specific thing about it. Every fix from the two review rounds has a case.
- **A blocking workflow.** `check-corpus.cjs` and the suite run on any change under the packet, gated on the affirmative `RESULT: PASSED` marker rather than on an exit code, since a run that refuses to start also exits zero.

#### Notes

- **The harness refuses a case that would prove nothing.** A patch whose anchor is missing, a base that already fails the family it is about to be mutated for, or a failure from a family other than the one named all abort the case. Three cases were caught by that on the way in: two anchors that did not exist, and one mutation that removed a comment rather than the declaration the rule actually reads.
- **The suite was checked against the fixes it exists to guard.** Reverting three of them made three cases fail each time — except the first pass, where reverting one made nothing fail. That fix had no case, and the one that isolates it was added: the only form with a single key site, where counting the helper's own declaration as a call is the difference between firing and staying silent.
- **Writing the suite found one more.** The reference-drawing assertion proved that *something* was appended, so orphaning the rule while still appending its label passed. It now counts what the loop builds against what it places.
- The browser-dependent case says it is skipping rather than returning quietly, because a silent skip and a pass read the same in a log.
