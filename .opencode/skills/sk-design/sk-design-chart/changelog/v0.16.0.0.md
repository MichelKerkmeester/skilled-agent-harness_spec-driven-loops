The mutation suite covered the families this line of work had touched and left the other thirty
resting on nobody having broken them yet. It now covers every family the checker registers, and
asserts that it does.

## What Changed

#### New Features

- **Thirty more cases.** Every family the corpus check registers has one, except the five that need a browser, which are named with the reason they cannot have one.
- **The suite asserts its own completeness.** A family that arrives without a case fails. So does a case naming a family that no longer exists, and an exemption that outlives the family it excuses.
- **A second route for the families an extra cannot reach.** Several are scoped to the shipped directories, and one trips on any copy at all because two files then declare the same identity. Those cases mutate the file where it lives, inside a package copy.

#### Notes

- **Writing the cases was mostly discovering what each rule actually reads.** Nine mutations broke something adjacent to the assertion rather than the assertion: the tooltip rule skips a file whose attribute is gone, so removing it proved nothing; the catalog's system column is a different column from the one I changed; the corner rule watches stylesheets and mark attributes, not arbitrary code. The harness refused each one rather than passing, which is the whole reason it refuses.
- **The guard was checked against itself.** Adding a family with no case fails with its name. So does renaming a family a case depends on.
- Coverage is one case per family, not per assertion. A family with six assertions is held against one of them; that is a floor, and it is stated rather than implied.
