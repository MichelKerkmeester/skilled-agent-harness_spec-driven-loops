# sk-design v1.7.1.0 - Root ROUTER.md Adoption

> Migrates the hub's second-stage surface router from `shared/references/smart-routing.md` to a first-class root `ROUTER.md` per the two-state root-router document standard, with the machine block preserved byte-for-byte and the literal legacy stage-one default repointed.

---

## Added

- Root `ROUTER.md` (v1.1.1.0): the stage-two surface router now lives at the hub root with `router_state: active` and `skill_pointer: SKILL.md`. The machine-readable `INTENT_SIGNALS` / `RESOURCE_MAP` block is byte-identical to the legacy file (sha256 `0a787088…`); the `hub-router.json` link was rebased for the root location.
- A Surface Router pointer in `SKILL.md` Section 2 (two-stage routing), the `ROUTER.md` entry in the layout tree, an ALWAYS rule pinning the `RESOURCE_MAP` / `leaf-manifest.json` sync, and the surface-router entry in REFERENCES.

## Changed

- `hub-router.json` (v1.4.3.0 → v1.4.4.0): `routerPolicy.defaultResource` repointed from the literal legacy path to `ROUTER.md`; `mode-registry.json` stays in the fallback list.
- `SKILL.md` (v1.7.0.0 → v1.7.1.0), `README.md` (v1.7.0.0 → v1.7.1.0), `description.json` (v1.7.0.0 → v1.7.1.0): the hub docs now name the root router as stage two.
- Deleted `shared/references/smart-routing.md` after standalone contract validation. The parent doctor then passed; compiled-manifest freshness remains the downstream fleet-rebuild gate.

## Not Changed

- Routing behavior. `mode-registry.json`, `tieBreak` order, the `interface` default mode, bundle rules, and every mode packet stay untouched; only the stage-two router location and the literal legacy default path changed.
- The `styles/lib/` retrieval adapters, the shared reference base, and the mode-local contracts.
- Historical changelog entries and dated benchmark reports that name the legacy path.
