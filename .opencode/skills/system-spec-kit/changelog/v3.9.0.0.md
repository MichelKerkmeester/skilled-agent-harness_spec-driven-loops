# v3.9.0.0

Five template-and-context optimizations from a deep-research packet. The research template and the four multi-level spec templates now render less at lower documentation levels, an acceptance-coverage check runs by default as a non-blocking advisory, a new scope-adherence check flags out-of-scope change-sets, and `memory_search` bounds its own response size. Every template change is proven to render byte-for-byte identically where it matters, so nothing an agent reads at a given level changed by accident.

> Spec folder: `specs/system-speckit/033-spec-template-context-optimization/` (Level 2)

---

## What Changed

#### Research template renders lean at low levels

- **CHANGED** `research.md.tmpl` was a single 944-line document that rendered in full at every documentation level. It is now level-gated: a Level 1 scaffold renders ~175 lines (the essentials), while Level 3/3+/phase still render the complete document byte-for-byte identical to before. Authors of low-level packets no longer read a 944-line wall.

#### Spec templates consolidated without changing output

- **CHANGED** The spec, plan, tasks and implementation-summary templates each held four near-identical full copies (one per level). They now use one shared core plus small per-level additions (about 55% less source), and every level renders byte-for-byte identical to before, proven by a per-level render-hash gate.
- **ADDED** A "Reading a Template (Agents)" guide directs agents to read the rendered (level-appropriate) view rather than the raw `.tmpl` file.

#### Acceptance-coverage check is on by default (advisory)

- **CHANGED** The `AC_COVERAGE` validation rule was implemented but disabled by default. It now runs by default as a non-blocking advisory (INFO): on under-coverage it surfaces a message but never warns, errors, or blocks `--strict`. The manual-infeasible escape hatch and the 0.9 floor are unchanged.

#### New scope-adherence check

- **ADDED** `check-scope-adherence.sh` (`SCOPE_ADHERENCE`) is a new opt-in advisory rule. Given a change-set (via `MK_SCOPE_CHANGED_FILES` or `MK_SCOPE_BASE`), it warns when changed files fall outside a packet's declared "Files to Change", while always treating the packet's own docs as in-scope. It is a no-op when no change-set is supplied.

#### memory_search bounds its own size

- **CHANGED** `memory_search` now enforces a token budget on its response (dropping lowest-score results first), mirroring `memory_context`, so a large result set can no longer flood the caller's context. Feedback telemetry now records only the results actually returned, because truncation runs before the telemetry is emitted.

#### Review and documentation alignment

- **CHANGED** A 10-iteration deep-review (verdict CONDITIONAL) drove a remediation pass: stale golden snapshots regenerated, the packet's own metadata regenerated so it passes `--strict`, and the packet marked Complete behind an evidence-backed checklist.
- **CHANGED** Documentation across skills, playbooks, the env reference, and the feature-catalog was reconciled to the new behavior (the AC_COVERAGE default, the new scope vars, and the registry rule-count references, now 46).
- **CHANGED** The originating 033 research packet was consolidated into 034: its synthesis, four fan-out lineages, and source context now live under `034/research/`, so the whole effort (research plus implementation) sits in one packet.
