The MCP transport is retired. Devin now has evidence injected at prompt time by a lifecycle hook, and Cursor runs a CLI from its command and rule. OpenCode and Pi are unchanged. The skill no longer depends on the MCP SDK and no longer ships a second bundle.

---

## What Changed

#### Host adapters

- **Devin gains injection**: `hooks/devin/sk-vision.mjs` runs on `UserPromptSubmit`. When a prompt names an image path that resolves on disk, the hook analyzes it and injects a `<SK-VISION EVIDENCE>` block into the same turn. The model does not have to ask, and cannot decline evidence already in its context. Registered through `hook-registry.json` rather than by hand, so the generated Devin registration and the `.devin/hooks` mirror stay in parity.
- **Cursor gains a CLI**: `vision-runtime/dist/vision-cli.js` takes an image path with an optional question, or `--from-text` to find a path inside prose. Its `/vision` command and always-apply rule invoke it. Cursor delivers no prompt-time hook event, confirmed by probe against build `2026.09.02-c22c1a3` with a `sessionStart` positive control, so injection is impossible there and the call has to be made rather than forced.
- **MCP transport removed**: the stdio server, its test, the `sk-vision-mcp` bin entry, the `mcp` script, the `@modelcontextprotocol/sdk` dependency, the second bundle step, both host configs and both mirror symlinks are gone. Nothing could reach it: Cursor's registration had already been dropped, and Devin's permission allowlist never granted the `mcp__sk-vision__*` namespace.

#### Runtime

- **Shared evidence core**: `src/evidence/prompt-evidence.ts` holds image-path detection, analysis, evidence wrapping and per-call teardown. Both the Devin hook and the CLI consume it, so the two hosts see identical analysis and identical detection rules.
- **Conservative detection**: a candidate path counts only when it carries an image extension and resolves to a file that exists, so a filename mentioned in passing never spins the local GPU. When several images are named, the last one wins.
- **Evidence marker**: the outer wrapper is `<SK-VISION EVIDENCE>`. A bare `<SK-VISION>` would nest inside the per-signal blocks the renderers already emit and strand a closing tag.
- **Fail-open guarantee**: a malformed payload, a disabled kill-switch, an unbuilt runtime, a prompt naming no image, or any error resolves the Devin hook to an empty response. It never blocks a turn and never writes to stderr.
- **Kill-switch**: `SYSTEM_SK_VISION_DISABLED=1` disables the hook; `SYSTEM_HOOKS_DISABLED=1` disables every hook in the repository. Both resolve through the shared `hook-flags` resolver.
- **Dead constant removed**: `MOONDREAM3_ONLY_TASKS` was defined and never read, and it listed `ocr`, contradicting the OCR handler's own comment. Gating is done by `_require_task` and `_supports`, which ask the loaded model what it advertises.

#### Devin configuration ownership

- **`.devin/mcp_config.json` is now Devin's own file**, carrying only `code_mode`. It had been a symlink into this skill, which meant a vision skill owned Devin's entire MCP configuration. Ownership moved before the deletion so Code Mode was never momentarily unregistered.

## Notes

The default `moondream2` checkpoint reads rendered text poorly. It recovers codes and digits but garbles surrounding words. `SK_VISION_MODEL=moondream3-preview` is the configuration the benchmark reports used, at the cost of a larger weight download.

`vision-runtime/package.json` is gitignored by a repo-wide rule and has never been tracked. Every dependency and script change to that package, including this release's removal of the MCP SDK, lives only in a working tree. A fresh clone gets no manifest for the package at all, so `bun test` and `bun run scripts/build.ts` cannot run there until someone restores one. That is a pre-existing repository condition rather than something this release introduced, but it means the dependency removal described above is not reproducible from the repository.

The Devin hook's timeout is 60 seconds. A warm model answers in about 13 seconds. A cold first load downloads the weights and will exceed it, and a timed-out hook is skipped, so the first image-bearing turn after a cold start arrives without evidence.
