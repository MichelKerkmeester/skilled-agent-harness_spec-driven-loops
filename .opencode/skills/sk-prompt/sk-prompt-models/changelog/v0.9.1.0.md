# prompt-models v0.9.1.0

## Changed

- Added a **weak-model observation drift** failure pattern to the CLI prompt-quality card (`assets/cli-prompt-quality-card.md` §6). It captures a lesson proven live in the deep-loop: a cheaper model (DeepSeek, MiniMax, Qwen) told to "review" or "observe" a repo will run the repo's own tooling — `generate-context.js`, `validate.sh`, `git` writes — and edit files it was only meant to read, unless the prompt forbids it by name. The directive tells composers that, for any observation-only or single-directory-scoped dispatch, they must state the exact write surface *and* name the forbidden tooling: "stay inside your directory" is inferred by strong models but ignored by weak ones, so the boundary must be made followable, not just present.
- Bumped the skill release track to `0.9.1.0` to match this changelog entry.

## Not Changed

- The three-tier prompt-composition precedence, the framework tables, the CLEAR pre-dispatch check, and every per-model profile. This is an additive guardrail in the common-failure-patterns section, not a change to how prompts are composed.
