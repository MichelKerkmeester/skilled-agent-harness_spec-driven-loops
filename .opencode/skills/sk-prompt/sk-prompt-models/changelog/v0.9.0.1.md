# prompt-models v0.9.0.1

The README conformance pass from the skill-readme refinement packet. The old README read as a tabular reference card that buried the model-selection story behind feature tables and a numbered quick-start list. This release rewrites it purpose-first on the refined skill-readme template: a one-line pitch right after the title, a problem-first OVERVIEW, the AT A GLANCE table first and a capability layer that names what the hub operates. The rewrite keeps every fact (model inventory, navigation chain, quick start, framework map) and clears the Human Voice Rules gates.

## 1. NEW

- A one-line pitch in a blockquote after the H1, stating the delivered outcome (pick the right prompt shape before dispatch) before any tool name.
- A problem-first OVERVIEW that opens with why small models drift without a single prompt-craft source, then states what the hub does.
- The Per-Model Prompt-Craft Layer capability table, naming the profile store, the model index, the registry and the executor pointer.
- A version field aligned with the skill release track at `0.9.0.1`.

---

## 2. CHANGED

- `README.md` rewritten from the tabular reference-card shape to the refined template section model: numbered ALL-CAPS H2 sections with `---` dividers, AT A GLANCE first, then OVERVIEW, QUICK START, HOW IT WORKS, INTEGRATION & NAVIGATION, TROUBLESHOOTING, FAQ, VERIFICATION and RELATED DOCUMENTS.
- `README.md` version `0.8.0.14` to `0.9.0.1`. The field lagged the `SKILL.md` release track (`0.9.0.1`) while the README text did not move. This release catches the field up so the frontmatter and the changelog agree.
- `README.md` prose cleaned to the Human Voice Rules: zero em dashes, zero semicolons and zero Oxford commas in the body.
- The model inventory, the navigation chain, the quick-start steps, the framework map, the registry facts and the four-owner split survive the rewrite unchanged in content.

---

## 3. NOT CHANGED

- `SKILL.md` stays at `0.9.0.1`. No skill file, reference, asset, benchmark or template asset moved in this release.
- The released changelog entries `v0.1.0.0` through `v0.9.0.0` stay byte-identical.
- No vault, plugin or runtime data was touched.
