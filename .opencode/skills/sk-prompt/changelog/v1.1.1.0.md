- Migrated the hub's second-stage surface router from `shared/references/smart-routing.md` to a first-class root `ROUTER.md` per the two-state root-router document standard. The root `ROUTER.md` declares `router_state: active` and `skill_pointer: SKILL.md`; the prose link to `hub-router.json` was rebased for the root location.
- Replaced the one stale `RESOURCE_MAP` entry for the `DESIGN_PROMPT` intent (`sk-prompt-improve/references/design-generation-patterns.md`, deleted upstream) with the live generic evaluation leaf `sk-prompt-improve/references/patterns-evaluation.md`; the rest of the machine-readable `INTENT_SIGNALS` / `RESOURCE_MAP` block is byte-identical to the legacy file. The hub release surfaces align at version 1.1.1.0.
- Updated the hub docs for the root router: `SKILL.md` (v1.1.1.0) gained the two-stage routing pointer, a Surface Router section, the `ROUTER.md` layout entry, the RESOURCE_MAP/leaf-manifest sync rule, and the surface-router reference; `README.md` (v1.1.1.0) gained the stage-two router in the overview and the related-documents table; `description.json` aligned to v1.1.1.0.
- Regenerated `leaf-manifest.json` through the owner tool; the only delta is removal of the deleted `sk-prompt-improve/references/design-generation-patterns.md` leaf.
- Preserved the `hub-router.json` `routerPolicy.defaultResource` (`sk-prompt-improve/SKILL.md`) byte-for-byte.
- Deleted the legacy `shared/references/smart-routing.md` after standalone contract validation; the parent doctor then passed, while compiled-manifest freshness remains the downstream fleet-rebuild gate; the empty `shared/` tree was removed.

## Not Changed

- Historical changelog entries and dated benchmark reports that name the legacy path.
