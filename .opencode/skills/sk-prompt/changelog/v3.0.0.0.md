`sk-prompt` is now a standalone routed-resource skill instead of a parent hub. The small-model prompt-craft capability it used to dispatch to is retired, and the prompt-engineering engine that was nested one level down is now the skill itself. The name, the `/prompt:improve` command, the seven frameworks, DEPTH and CLEAR scoring are all unchanged.

---

## What Changed

#### Removed

- **Small-model prompt-craft profiles** -- the per-model reference set (DeepSeek-v4-pro, Kimi-k2.7-code, MiniMax-M3, MiMo-V2.5-Pro, GLM-5.2, Composer-2.5), the model registry that indexed them, the per-model context budgets, the quota-fallback and output-verification references, and the pattern index. This capability has no replacement. A prompt naming only a model no longer resolves to that model's CLI executor through the advisor's alias table.
- **Hub routing surface** -- `mode-registry.json`, `hub-router.json`, `description.json`, `command-metadata.json` and the stage-two `ROUTER.md`. All five are forbidden on a standalone root: with one workflow mode left, they described a dispatch decision with a single possible answer.
- **Feature catalog** -- both entries documented hub routing exclusively, so the catalog had no subject once the hub was gone.
- **Compiled routing** -- the skill is withdrawn from the compiled-routing serving closure and its live-activation fence. Prompt-engineering requests now reach the skill directly by advisor identity rather than through a hub's two-stage resolution.

#### Changed

- **Layout flattened** -- the engine's `references/`, `assets/`, `manual-testing-playbook/`, `changelog/`, `SKILL.md` and `README.md` moved from the nested packet up to the skill root by rename, so the engine's version history follows it. The skill's version line continues from the engine's, which is why this release is 3.0.0.0 rather than a hub 1.x successor.
- **Canonical CLI prompt-quality card kept and relocated** -- `assets/cli-prompt-quality-card.md` holds the seven-framework selection table, the CLEAR pre-dispatch check and the escalation rule that every `cli-*` executor's local card delegates to. Its content is prompt-improvement doctrine rather than per-model profile data, so it survived the removal and now sits in this skill's assets.
- **Advisor identity** -- `graph-metadata.json` moves to the standalone family, drops the small-model domains, triggers and entities, and keeps one enhances edge to the CLI orchestration hub describing the canonical-card relationship.
- **Manifest contract** -- `leaf-manifest.config.json` is authored; `leaf-manifest.json` and `leaf-aliases.json` are regenerated from it.

## Upgrade

`/prompt:improve` is unaffected — a standalone skill binds its command from the command definition rather than a `command-metadata.json` entry, matching the other standalone skills that own slash commands. Framework selection, DEPTH and CLEAR scoring behave identically.

Consumers that read the retired per-model profiles must drop that step; there is no replacement path. Consumers that pointed at the canonical CLI prompt-quality card under the old nested location should read it from `sk-prompt/assets/cli-prompt-quality-card.md`.
