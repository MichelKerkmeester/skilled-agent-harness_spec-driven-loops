# system-deep-loop v2.1.0.0

The hub README moves from a tabular reference card to the purpose-first narrative voice the fleet now uses. It leads with a one-line pitch and a problem-first overview, so a new reader understands what deep-loop workflows deliver before they meet the routing machinery. No skill behavior changed.

## 1. NEW

- **One-line pitch:** a blockquote right after the H1 states the delivered outcome before any tool name, following the refined skill README template and the mcp-obsidian exemplar.
- **The Mode Family table:** one row per workflow mode stating what the mode runs, modeled on the pilot's Plugin Knowledge Layer pattern.
- **FAQ section:** four questions a new reader actually asks, covering the single-identity design, the `runtime/` boundary, artifact locations and mode routing.
- **Verification close:** the README validator, the hub canon check, the advisor drift-guard and the manual testing playbook in one section.

## 2. CHANGED

- **README voice and structure:** the old reference-card style becomes the numbered ALL-CAPS section model with AT A GLANCE first and OVERVIEW as the required section.
- **Problem-first overview:** Why This Skill Exists opens with the five-identity disambiguation problem before any feature list.
- **Version field:** 2.0.0.0 to 2.1.0.0 in the README frontmatter.
- **Durable facts preserved:** invoke routes, mode names, the three-tier discriminator, the layout, the artifact locations and the add-a-mode surfaces all survive the rewrite.

## 3. NOT CHANGED

- No SKILL.md content changed. The runtime instruction surface stays untouched.
- No mode packet, registry, router, manifest or vault file changed.
- The hub changelog history and the frozen `runtime/` changelog stay in place.
