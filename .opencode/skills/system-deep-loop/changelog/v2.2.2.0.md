# system-deep-loop v2.2.2.0

## Changed

- Hardened the shared fan-out lineage prompt in `runtime/scripts/fanout-run.cjs` (`buildLoopPrompt`), which every mode's fan-out lineage renders. The old boundary said only "do not touch any path outside your lineage dir." A cheaper model (DeepSeek Flash) read that as license to run the repo's own tooling during an observation pass — a real deep-review lineage ran `generate-context.js` and `validate.sh`, edited files across the tree, and was failed by write-containment for reverting eight out-of-scope tracked paths. The prompt now spells out the observation boundary and names the exact tooling to avoid — `generate-context.js`, `validate.sh` (especially `--recursive`), and any `git` write/checkout/commit — so the boundary is followable by a weak model, not just inferable by a strong one. Because the write boundary is loop-type- and executor-agnostic, this one change reaches all eight modes on cli-opencode and cli-pi alike.
- Added a regression test in `runtime/tests/stress/cli-adapter/fanout.vitest.ts` asserting the rendered prompt names the forbidden tooling for research and review on both cli-opencode and cli-pi. The red is by construction: the asserted strings exist only in the new prompt, so the test cannot pass against the prior text.
- Proven live: a two-executor fan-out review (codex `gpt-5.6-luna` + `opencode-go/deepseek-v4-flash`) against a clean worktree baseline went from 1-succeeded/1-failed to **2 succeeded / 0 failed**. The DeepSeek lineage flipped from `rejected` to `fulfilled`, its real forbidden-tool invocations dropped 26/24 → **0/0** (a command-parse of the session log; earlier raw counts were prompt-text and SKILL echoes, not runs), and write-containment recorded zero violations. The strong-model lineage was unaffected.

## Not Changed

- The `write-containment.ts` enforcement layer — detection, HEAD-revert of in-scope breaches, and the fail-closed contract — is untouched. It remains the enforced backstop for a model that ignores the prompt; the hardening improves the odds, it does not replace the net. The evidence that prompt-hardening alone drove DeepSeek to zero breaches is why the heavier "prevent-not-revert" write-jail was ruled out.
- Executor rosters, allowlists, dispatch env construction, convergence and stop-policy logic, and every mode's ledger/reducer/certificate surface. No behavior change for strong-model executors.
