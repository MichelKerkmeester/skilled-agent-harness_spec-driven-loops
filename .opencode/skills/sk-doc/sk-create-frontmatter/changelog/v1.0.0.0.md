`create-frontmatter` gives the YAML frontmatter contract an owning mode. Six sibling packets emit frontmatter and every one of their templates defers to the same specification, which until now sat in the hub's shared tier where any mode could read it and none was accountable for it. The specification moves into this packet, every consumer is repointed, and the mode is wired through both routing stages.

---

## What Changed

#### New Features

- **A mode packet for the frontmatter contract.** Shared was the right reach and the wrong ownership. A contract many producers read and no producer owns gets edited by whoever passes, and drifts from the validators enforcing it. This is the third time that shape has been corrected in this hub, and the largest.
- **The field reference and the versioning standard, moved in whole.** `assets/frontmatter-templates.md` carries the eleven-section field reference, the per-class templates, the description budget and the common fixes. `references/frontmatter-versioning.md` carries the 4-part `X.Y.Z.W` standard: scope, format, the changelog-anchored derivation, the numstat gate and the insertion rule. Neither document splits, because no section of either has a second constituency.
- **Both routing stages, not just registration.** A registry entry is not a route. The mode carries a registry entry, hub vocabulary, router intents, a resource map, leaf-manifest entries, and a single-route canary case that the coverage guard counts. The advisor selects the hub for a frontmatter request at confidence 0.95, and the hub router then selects this mode from a lone target.
- **Vocabulary that does not take a sibling's route.** Every keyword is qualified. A bare "frontmatter" was deliberately not used: agent-creation already owns "agent frontmatter", and a bare token would have tied with it and turned that mode's exclusive route into a bundle. All seventeen candidates were checked for substring collision against every existing keyword in both routing surfaces before being added.
- **A manual testing playbook.** Eleven operator scenarios across field-and-class resolution, the description budget, and version derivation. The package passes the operator-scenario validator with zero violations and, unlike most packages in the fleet, is visible to the benchmark scenario loader.

#### Notes

- **The mode owns the rules, and the shared tier keeps the enforcement.** `frontmatter-version.mjs`, its corpus-gate wrapper and `quick_validate.py` all stay in `shared/scripts/`, because a post-edit hook outside this hub resolves one of them by literal path on every qualifying edit. Enforcement is exactly the many-consumer utility a shared tier is for. The rules are exactly what it is not.
- **No alias was added.** The hub's alias table maps a leaf id to a disk path when the two disagree. Using it here would have preserved the mismatch this packet exists to remove, so the table is byte-identical to what it was before the move.
- **The old location survives only where it stays true.** A released changelog entry recording where the file sat at v1.8.0.0 is history and keeps its wording. Three dated benchmark report bundles keep theirs for the same reason.
- **The packet was built empty first, then filled.** A packet that gains content and structure at once cannot tell you which of the two broke a gate. The packaging gate ran against the shape alone before any content depended on it, and caught a description two characters over its own soft target, which is the contract this mode now owns.
- **Repointing fixed a link that was already broken.** The changelog template pointed at a same-directory copy of the field reference that has never existed there. Link failures across the hub went from 113 to 112.
