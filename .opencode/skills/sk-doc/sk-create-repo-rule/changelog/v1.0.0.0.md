Initial release of `create-repo-rule`, a workflow packet in the `sk-doc` parent hub. It turns a user's request — a behaviour they want, or a failure that keeps happening — into a rule file under `repo-rules/`, wired into that repository's `REPO RULES.md` router. It also revises and retires rules, because a repo rule supplements the harness rather than binding it: overridable by a live operator instruction, changeable when it stops matching the work, removable when it stops earning its load.

> Spec folder: `specs/sk-doc/040-create-repo-rules` (Level 2, seven phases)

---

## What Changed

#### New Features

- **Four decision tests that refuse most requests.** Always-loaded, scope boundary, a four-part refusal test, and restraint. Every refusal names the test it failed and where the content belongs instead. Recovered from the phases that established them and verified against the ten candidates the reference set had already declined — all ten still fail, each by the test its original reason names.
- **A rule template derived from the corpus rather than copied from it.** Ten elements are fixed because all eight shipped rules carry them; the numbered body is open because section count follows the subject. A rule generated from it matched a shipped rule on all eleven structural assertions.
- **A router template**, emitted as a prerequisite when a repository has no trigger table. The router shares almost no structure with the rules it routes to, so it is a separate template rather than a variant.
- **Creation standards** — five reader tests deciding whether a structurally correct rule is worth loading. Every one passes on all eight shipped rules and fails a deliberately thin sample.
- **An integration and lifecycle contract.** Three wiring points, and create/revise/retire orderings chosen so that stopping halfway always leaves an unreferenced file rather than a router row pointing at nothing.
- **`/create:repo-rule`**, with auto and confirm workflows and a presentation contract. `retire` defaults to confirm even under an auto suffix, because it deletes a file and removes two router rows.

#### Notes

- Length bands are operator-set: 250 maximum, 200 good, 160 or lower preferred, frontmatter included.
- Generated rules default to **zero** sideways cross-references. The reference corpus carries four across eight files, so rules turn out to be nearly independent.
- The accept path is built and structurally proven in parts but has not run end to end. The reference set was saturated by a five-iteration review that returned zero warranted new rules, so no genuine accept case exists in this repository yet. The refusal path — the common one — works and names its destinations.
