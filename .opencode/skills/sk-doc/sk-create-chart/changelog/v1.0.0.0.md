First release of `sk-create-chart`, a workflow packet in the `sk-doc` parent hub. It carries the package shape and no chart corpus. The version story starts at adoption rather than at the first later edit, so the empty shell is a release rather than an untracked intermediate state.

---

## What Changed

#### New Features

- **The packet shape**, built from the create-skill packet scaffold: `SKILL.md`, `README.md`, a reference index, a corpus tree under `assets/`, a scripts directory, a playbook directory and this changelog.
- **A template-first contract** in `SKILL.md`. A render block is taken from a template that already renders, one color system is applied per artifact and the output is a single file that opens with no install step.
- **A stated boundary against `sk-create-diagram`**, which already claims bar, line, scatter and radar by name. The split is what the artifact carries: values a reader compares, against a structure a reader follows.
- **A licensing rule in the packet itself.** Every chart, palette and script here is authored here. Nothing is copied in from an outside chart library, because this repository is MIT and public and cannot hand onward a grant it was never given.

#### Notes

- The corpus directories exist and are empty. The packaging gate passes against the empty shell on purpose: a failure against an empty package names a wrong shape, while the same failure against a full one could be either shape or content.
- The packet is not yet registered with the hub, so nothing routes to it. Registration is a separate act across the hub registry, the router, the hub mode table and the advisor vocabulary.
