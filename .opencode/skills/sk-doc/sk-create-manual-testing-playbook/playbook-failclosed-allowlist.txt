# Playbook roots held to the operator-scenario contract as a blocking gate.
#
# A root listed here must validate with zero violations. The CI workflow
# .github/workflows/playbook-operator-contract.yml runs each one with its own
# --package path, which is what gives it its own package id and its own tier.
#
# Why per-root, and why this file exists: a single fleet run resolves a nested
# package to its PARENT id, so a sub-package silently inherits the parent's
# playbook-corpus-manifest.json warnPackages entry and stops blocking. That
# roll-up is how large backlogs accumulated unseen under warn-listed parents.
#
# Adding a line is how a cleaned package becomes permanent: once listed, a later
# edit that reintroduces a violation fails the gate instead of joining a backlog.
# Never remove a line to make a red build green — fix the package instead.
