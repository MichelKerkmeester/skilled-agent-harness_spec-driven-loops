# v4.2.2.0 — PI_REMOTE detection de-staled; mobile-cli RESOURCE_MAP union extended

The hub's PI_REMOTE surface detection and routing metadata still described the pre-migration React app,
and the `sk-code-mobile-cli` surface grew thirteen new routable references and checklists that had to be
folded into the machine `RESOURCE_MAP` union.

## Fixed

- **Surface-detection bug:** PI_REMOTE keyed off `apps/pi-remote-web` and "React 19 / Vite / Tailwind 4 /
  style.css" across `shared/references/stack-detection.md`, `ROUTER.md`, `hub-router.json`,
  `description.json`, `mode-registry.json`, and `graph-metadata.json` — so it never matched the current
  `app-mobile/` SvelteKit tree. All markers, keywords, and aliases now target Svelte / `app-mobile`.

## Changed

- `ROUTER.md` §11 `RESOURCE_MAP` extends the `sk-code-mobile-cli/` union with the surface's nine new
  source-grammar/verification references and four checklists, kept exactly equal to the child §2b map
  (the router-sync bijection guard passes). `leaf-manifest.json` regenerated.

## Why

Detection that names a removed React workspace cannot select the surface it is meant to bundle, and a
router that does not list a surface's evidence cannot load it. Both are corrected without touching the
Webflow, OpenCode, or Motion.dev surfaces.
