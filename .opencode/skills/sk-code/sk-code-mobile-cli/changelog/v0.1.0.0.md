# v1.0.0.0 — mobile-cli surface established

First release of the `mobile-cli` surface packet on the `sk-code` hub's surface axis, and the single
source of truth for the Pi Remote Mobile-CLI app (`apps/pi-remote-web/`). Code work on the app
previously detected as UNKNOWN and loaded none of its conventions; this surface makes PI_REMOTE a
first-class detected surface, a full structural peer of `sk-code-webflow` / `sk-code-opencode`, and the
home for the app's design-system evidence and documentation.

## Packet content

- `SKILL.md` — the surface contract with a `metadata` block (`family: sk-code`, `packetKind: surface`),
  the reference map, the machine-readable SMART ROUTING (standard intent taxonomy), the non-negotiable
  design/security standards, an assets section, and the read-only rules — mirroring the sibling
  surface-packet structure.
- `references/` — design-system evidence: `token-library.md` (primitive→semantic→component model +
  frozen values), `component-tokens.md` (the `--model-sheet-*` / `--slash-*` / `--diff-*` families and
  their blast radius), `retint-recipes.md` (role- and component-level retint recipes with resolver
  proof), `theme-remap.md` (light/dark `@ds theme:` remap), `ds-grammar.md`, `editability-guardrails.md`,
  `verification.md`, and the shared implement→debug→verify doctrine symlinked from `../../shared/`.
- `assets/` — `token-retint-checklist.md`, `guardrail-audit-checklist.md`, `ds-verification-checklist.md`.
- `manual-testing-playbook/` — routing scenarios (token-edit, ds-grammar, guardrail, debugging,
  verification, language-standards, accessibility) plus an index.
- `references/app-guide/` — the full Pi Remote app documentation, relocated from the CLI repo root
  `docs/` so the skill is the single source: operations, setup, security, rollback, release-verification,
  incident playbooks, platform support, code standards, install/onboarding, the `feature-catalog/`,
  `quality/` baselines, and `design-reference/` (teardown, UI map, research, screens).
- `README.md`, `changelog/`.

## Hub wiring (parent `sk-code`)

- `mode-registry.json` — new `modes[]` entry (`packetKind: surface`, `backendKind: evidence-base`,
  read-only `toolSurface`, `routingClass: metadata`) and `extensions.surface-axis.surfaces`.
- `hub-router.json` — `routerSignals["sk-code-mobile-cli"]`, `vocabularyClasses`
  `code-mobile-cli-{aliases,runtime}`, and `routerPolicy.tieBreak`.
- `ROUTER.md` — PI_REMOTE documented as a bundled evidence surface in §1, and its SMART ROUTING map
  **folded into the §11 machine `RESOURCE_MAP`** — re-prefixed `sk-code-mobile-cli/` and unioned under
  the shared intent keys, exactly as the Webflow and OpenCode surfaces are.
- `shared/references/stack-detection.md` — the PI_REMOTE marker, precedence
  (`OPENCODE > PI_REMOTE > WEBFLOW > UNKNOWN`), and test cases.
- `leaf-manifest.json` — regenerated to type every packet reference/asset leaf.
- `sk-code-router-sync.vitest.ts` — the decentralization drift guard's `SURFACES` now includes
  `sk-code-mobile-cli`, so the parent-projection-equals-union invariant is enforced across all three
  surfaces.
- Compiled-routing activation manifest (runtime + authored) refreshed for the new mode.

## App-doc single-source dedup

The feature catalog and the manual testing playbook are now maintained as the single source of truth at
the **Pi Remote app repository root** (`feature-catalog/` and `manual-testing-playbook/`, each authored
via a DeepSeek-writes / Sonnet-verifies pipeline and covering all 43 shipped features). The surface's
`references/app-guide/feature-catalog/` duplicate (30 files) has been removed and replaced with two
pointer files (`app-guide/feature-catalog.md`, `app-guide/manual-testing-playbook.md`) so the skill
copy cannot drift from the canonical app-root docs. `leaf-manifest.json` and `SKILL.md` §2 were updated
accordingly.

## Notes

`packetKind: surface`, `backendKind: evidence-base`, read-only (`toolSurface` ⊆ {Read, Bash, Grep,
Glob}), advisor-invisible (`routingClass: metadata`). Reached only by the hub bundling it alongside a
workflow mode via `routerPolicy.outcomes.surfaceBundle`; it never routes as a primary and mutates
nothing. It carries no packet-level advisor metadata (a nested `graph-metadata.json`/`description.json`
would be a `NESTED_IDENTITY` violation); the hub keeps the single `sk-code` advisor identity.
