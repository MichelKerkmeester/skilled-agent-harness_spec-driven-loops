# v1.2.0.0 — shipped Svelte tree conventions

The mobile-cli surface now teaches the tree that ships: a SvelteKit app under
`app-mobile/`, its relay peer under `app-relay/`, and the single shared protocol package under
`packages/pi-rpc-protocol/`. The guidance is no longer provisional and its routing keywords
identify Svelte, runes, scoped styles, source naming, comments, and folder documentation.

## Changed

- Updated the live evidence paths for the catalog, design-system token library, designer editability
  guide, shared application stylesheet, and contrast test.
- Replaced the section-divider guidance with the paired box-drawing rules and numbered sections used by
  shipped modules, including the `MODULE:` banner convention.
- Folded the source naming grammar into the main surface guidance: kebab-case, the kind-first component
  list, screen names, feature-component names, and the SvelteKit route-tree exemption with its URL
  contract reason.
- Documented the `shared/` ownership folders and one-reason-to-change rule.
- Documented the sentence-case comment grammar, the no-commented-out-code rule, the `@ds` seam markers, and
  the executable comment and folder-documentation scans.
- Added the README/CODE folder-documentation pair and mapped each document to its sk-doc template.
- Added the runes self-invalidation failure mode, including transitive API tracing and whole-file effect
  audits.
- Replaced the old language-routing vocabulary with Svelte, runes, scoped styles, `app.css`, and
  source-convention signals.

## Not Changed

- The frozen token model, `@ds` grammar, guardrails, contrast requirements, read-only packet contract, and
  browser-free verification principle.
- The shared workflow references and their symlink topology.
