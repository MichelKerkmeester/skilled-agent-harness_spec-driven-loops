# v1.5.0.0 — CSS class naming and comment brevity as source conventions

The surface now teaches the two source conventions the web client adopted: a BEM `block--element` class
grammar and a concise durable-WHY comment density.

## Changed

- §3b SOURCE TREE CONVENTIONS gains a **CSS class names** subsection: the `block--element` form with a
  `--` delimiter, the `is-*` state prefix kept single-dash, the three dynamic-construction forms
  (template, concat, ternary) that must resolve to a matching rule, and the rule that ids, tokens, and
  wire enums sharing a class's string stay data. It names the token-identity, class-orphan, `test:web`,
  and before/after catalog screenshot-diff proofs a rename passes.
- §3b **Module and comment grammar** gains a brevity rule: a comment carries the durable WHY a reader
  cannot infer, never narration, a restated name, or a multi-line prose essay.

## Why

A blanket rename moved the web client's classes to `block--element` and a comment pass tightened its
inline prose, but the surface still described only file naming and banner structure. A workflow bundling
this surface could rename a class or trim a comment without the grammar the tree now follows — including
the dynamic-construction and shared-string traps that only a screenshot diff catches. This lands both
conventions as evidence.
