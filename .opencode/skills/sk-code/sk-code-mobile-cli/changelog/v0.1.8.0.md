# v1.8.0.0 — document the screenshot archive and how the catalog is actually used

The catalog reference covered the story-per-component contract and its gates, but said nothing about
the tracked screenshot archive beside it, and nothing about the two different jobs the catalog does:
an agent asking "did this break something a test cannot see?" and a designer asking "what happens if I
change this?". Both were tribal knowledge. This adds them.

It also corrects a claim the skill was repeating: the designs addon does not place a Figma frame beside
each surface. It is installed and wired to nothing, because this app has no Figma source — the design
system was authored in code. The same false claim lives in the app's own `STORYBOOK.md` and is being
corrected there.

## Added

- `references/screenshot-archive.md` — how a shot is taken (fixed frame, pinned clock, frozen motion,
  content crop, stability retry), why some shots are transparent and some sit on the page tone, what
  the archive's determinism is really worth, how an agent uses it (audit both themes, pin the clock,
  set the theme after settle, prove fixes by re-measuring, negative-control the check itself), and how
  a designer uses it (token playground, the `flips` badge, state controls, editable seams).
- Registered the reference in the reference map and in the `CODE_QUALITY` routing bucket.

## Changed

- `references/component-story-upkeep.md` — the addon section no longer claims a Figma frame sits beside
  each surface; it names the three addons that are wired, states plainly that designs is installed and
  unused, and points at the two catalog-tooling surfaces that live outside the app bundle.
- Bumped the skill version to 0.1.8.0.

## Why it matters

The archive's hardest-won lessons are the ones a reader cannot reconstruct. The headline one is that
the archive is not byte-stable, and the reference now says so with a number rather than a hedge: six
capture runs compared against the first gave five differing of five, and a capture from before the most
recent change gave the same five of five. Small samples have already produced a wrong call here in both
directions — one matching pair once read as proof of stability, and a three-run sample later read as
proof of a regression that six runs disproved.

Two more that no gate expresses: a change that looks correct in the diff can render nothing at all when
its class is scoped to a different component, and geometry and colour checks pass straight over a CSS
comment rendered as body text. Those are now written down where the next reader will look.
