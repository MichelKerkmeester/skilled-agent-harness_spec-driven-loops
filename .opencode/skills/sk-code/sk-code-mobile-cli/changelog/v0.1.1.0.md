# v1.1.0.0 — app-guide dissolved into purpose-named folders

Second release of the `mobile-cli` surface packet. The flat `references/app-guide/` bucket is dissolved
into six purpose-named folders so the app documentation reads by intent on first glance, the two
single-source pointer files are removed, and the README now locates the Mobile CLI app repository
explicitly. Documentation-only; no routing behavior, no app code, no design-system or security contract
changes.

## New

- Five purpose-named documentation folders under `references/`, each grouping one concern:
  `operations/` (operations, incident-playbooks, rollback), `release/` (ai-deploy-playbook,
  release-verification), `setup/` (setup, install-and-onboarding), `standards/` (code-standards,
  security, platform-support), and `quality/` (the doc-quality gate and the full-access-runtime
  baseline).
- README `### The Mobile CLI App Repository` subsection under OVERVIEW: names the app repo as a separate
  repository from this skills hub, explains that `apps/…` / `packages/…` paths resolve against that repo
  as the working tree, and points at `specs/003-pi-remote-design-system/` as the design-system contract.
- `---` dividers between the numbered sections of the three `assets/` checklists, matching the
  create-skill reference/asset template.

## Changed

- `references/app-guide/` removed as a grouping; its files relocated into the six folders above (content
  preserved verbatim; only their paths changed).
- SKILL.md §2 app-documentation paragraph rewritten to describe the six folders and their files.
- The four flat sibling cross-links broken by the relocation (`security.md`, `setup.md`,
  `platform-support.md`, `release-verification.md`) repaired to their new subfolder-relative paths across
  `operations/operations.md`, `setup/setup.md`, and `setup/install-and-onboarding.md`.
- Parent `sk-code/leaf-manifest.json` regenerated to re-type every relocated leaf; `--check` passes.

## Removed

- The two single-source pointer files `references/app-guide/feature-catalog.md` and
  `references/app-guide/manual-testing-playbook.md`. The **feature catalog** and the **manual testing
  playbook** remain the single source of truth at the app repository root; this surface no longer mirrors
  them even as pointers, so they cannot drift. SKILL.md and the leaf-manifest were updated accordingly.

## Not Changed

- The surface contract (`packetKind: surface`, `backendKind: evidence-base`, read-only `toolSurface`,
  `routingClass: metadata`, advisor-invisible), the frozen design/security contracts, and the SMART
  ROUTING map (which never listed app-guide paths).
- The seven design-system references, the workflow doctrine symlinks, and the token/grammar/guardrail
  evidence — untouched.
- The pre-existing `../ARCHITECTURE.md` link in `setup/install-and-onboarding.md` — it was already
  dangling before this release and resolves to the same path after, so it is out of this change's scope.
