# v1.0.0.0 — mobile-cli surface established

First release of the `mobile-cli` surface packet on the `sk-code` hub's surface axis. Code work on the
Pi Remote Mobile-CLI app (`apps/pi-remote-web/`) previously detected as UNKNOWN and loaded none of the
app's design-system conventions; this surface makes PI_REMOTE a first-class detected surface and
supplies the design system as read-only evidence.

## New

- `SKILL.md` — the surface contract: when the hub bundles this evidence, the reference map, the
  machine-readable intent→reference routing, the non-negotiable design/security standards, and the
  read-only rules.
- `README.md` — packet at-a-glance, overview, quick start, detection/bundling, FAQ, and verification.
- `references/` — `token-library.md` (the primitive→semantic→component model + frozen values),
  `ds-grammar.md` (the `@ds` editability grammar), `editability-guardrails.md` (the do-not-edit fences),
  `verification.md` (the browser-free resolver gate), and the shared implement→debug→verify doctrine
  symlinked from `../../shared/references/`.
- `changelog/` — this file.

## Hub wiring (parent `sk-code`)

- `mode-registry.json` — new `modes[]` entry (`packetKind: surface`, `backendKind: evidence-base`,
  read-only `toolSurface`, `routingClass: metadata`) and `extensions.surface-axis.surfaces`.
- `hub-router.json` — `routerSignals["sk-code-mobile-cli"]`, `vocabularyClasses`
  `code-mobile-cli-{aliases,runtime}`, and `routerPolicy.tieBreak`.
- `ROUTER.md` — PI_REMOTE added to the §1 surface map as a bundled evidence surface; the machine
  `RESOURCE_MAP` (a Webflow / OpenCode / Motion.dev projection) is intentionally left unchanged.
- `shared/references/stack-detection.md` — the PI_REMOTE marker, precedence, and test cases.
- `leaf-manifest.json` — regenerated to type the packet's four reference leaves.

## Notes

This packet is `packetKind: surface`, `backendKind: evidence-base`, read-only (`toolSurface` ⊆
{Read, Bash, Grep, Glob}), and advisor-invisible (`routingClass: metadata`). It is reached only by the
hub bundling it alongside a workflow mode via `routerPolicy.outcomes.surfaceBundle`; it never routes as
a primary and mutates nothing. It carries no packet-level advisor metadata (a nested
`graph-metadata.json`/`description.json` would be a `NESTED_IDENTITY` violation); the hub keeps the
single `sk-code` advisor identity.
