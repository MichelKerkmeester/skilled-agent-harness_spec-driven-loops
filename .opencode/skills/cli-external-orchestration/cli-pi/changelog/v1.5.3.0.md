Two DeepSeek routes on this roster now name V4.1 Flash. One is dispatch-proven through its own
client; the other is listed upstream and nothing more, because the account is out of quota.

## What Changed

#### Breaking

- **The opencode-go DeepSeek row is `deepseek-v4.1-flash`.** It was
  `deepseek-v4-flash-vision-exp`. Both DeepSeek routes now name the *same* model again — the DevPass
  bare literal became `deepseek-v4.1-flash` first, and the opencode-go id has now caught up — but they
  remain separate routes, because one literal maps to one provider and only the DevPass one is in the
  fan-out map. The row keeps its direct-dispatch-only note and its `--thinking max` pin, a tier this
  route carries.
- **The cline-pass DeepSeek row is `cline-pass/cline-pass/deepseek-v4.1-flash`**, with the `.pi`
  provider block and the picker entry moved to match. It is **listing-only: no dispatch has been
  recorded for this id.** Cline's own API lists `deepseek/deepseek-v4.1-flash`, but every attempt made
  2026-09-11 returned `429 "You have reached your monthly Clinepass limit"` — and so did the
  previously verified `cline-pass/cline-pass/deepseek-v4-flash`. That shared failure is how we know the
  block is the account's quota and not the id. No context, output or price figure is claimed for the
  new row, because none was measured. **`cline-pass/cline-pass/deepseek-v4-flash` stays the fallback**
  until one V4.1 turn passes after the quota window resets, and the row says so.

#### Fixes

- **The dispatch examples name a route that still exists.** The quick-invocation snippet and the
  child-session envelope both used the superseded opencode-go id; they now match the roster row they
  are meant to illustrate.
- **The manual-testing playbook's id-format control matches the wired config.** Its model id, its
  expected `defaultModel` and its skip list had all drifted from `.pi/settings.json`. The skip list now
  also accepts the quota blocker, so a `429` reads as "route never exercised" rather than as a pass or
  as a model failure — both copies of that expectation, the scenario contract and the execution table,
  were updated together so the file cannot disagree with itself.

## Verification

- `pi --list-models` after `pi update --models`: `opencode-go  deepseek-v4.1-flash` at 1M context,
  384K output, `thinking yes`, `images yes`.
- `pi update --models` was required to see it: pi's catalog was stale relative to models.dev and did
  not carry the id until refreshed.
- The opencode-go route returned a real reply through its `opencode` client. The pi-side turn is
  verified too: on 2026-09-12, `pi -p --offline --model llmgateway/deepseek-v4.1-flash --thinking max "Reply with the single word: ok" </dev/null` exited 0 and returned `ok`.
- The cline-pass route is measured as reachable in Cline's own model listing only. It is not reported
  as dispatch-verified.
- `fanout-run.vitest.ts` and `executor-config.vitest.ts` together: 213 tests, 213 pass, 0 fail.
