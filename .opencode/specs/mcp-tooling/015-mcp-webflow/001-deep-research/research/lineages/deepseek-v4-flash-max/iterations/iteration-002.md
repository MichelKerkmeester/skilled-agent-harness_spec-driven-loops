# Iteration 2: Tool action inventory and operation classification

## Focus

Extract the complete per-module action inventory from `src/tools/*.ts` and classify every action into read-only / draft-safe / destructive / publish-capable / deployment-capable buckets (Q1), noting Designer (bridge-bound) vs Data (REST) tool families.

## Findings

1. **Combined-tool pattern with per-action schemas.** Every Data module registers ONE MCP tool (`data_<name>_tool`) whose `inputSchema.actions` is an array of optional per-action objects; each action key maps to a Webflow Data API v2 endpoint documented as a comment (e.g. `// POST https://api.webflow.com/v2/sites/:site_id/publish`). Designer modules register `de_<name>_tool` / `element_builder` / `element_tool` / `element_snapshot_tool` / `style_tool` / `variable_tool` / `asset_tool`, forwarding `actions` via RPC to the bridge companion app. `annotations.readOnlyHint` is `false` on all combined data/designer tools; it is `true` only for `element_snapshot_tool`, `webflow_guide_tool`, and `ask_webflow_ai`. [SOURCE: https://raw.githubusercontent.com/webflow/mcp-server/main/src/tools/*.ts]
2. **sites** (`data_sites_tool`): `list_sites` (GET), `get_site` (GET) — read-only; `publish_site` (POST /publish) — **publish-capable** (publishes full site to customDomains and/or webflow.io subdomain via `publishToWebflowSubdomain` flag). [SOURCE: logs/evidence/tools/sites.ts]
3. **pages** (`data_pages_tool`): `list_pages`, `get_page_metadata`, `get_page_content` (GET) — read-only; `update_page_settings` (PUT /v2/pages/:page_id) — **draft-safe metadata update that can flip publishing status** (payload includes page status draft/published per schema describe); `update_static_content` (POST /v2/pages/:page_id/dom) — draft-safe content mutation (no separate publish action at page level; goes live via site publish). [SOURCE: logs/evidence/tools/pages.ts]
4. **cms** (`data_cms_tool`): reads `get_collection_list`, `get_collection_details`, `list_collection_items`; draft-safe writes `create_collection`, `create_collection_static_field`, `create_collection_option_field`, `create_collection_reference_field`, `update_collection_field`, `create_collection_items` (bulk), `update_collection_items` (bulk, includes `isArchived`); **`publish_collection_items` is the explicit publish action**; `delete_collection_items` is **destructive** (delete is a live-site-capable mutation — official FAQ confirms CMS mutations can hit the live site; source comments show "create and publish new items directly to the live site" variants were considered and commented out). [SOURCE: logs/evidence/tools/cms.ts]
5. **scripts** (`data_scripts_tool`): reads `list_registered_scripts`, `list_applied_scripts`, `get_page_script`; draft-safe `add_inline_site_script` (POST), `upsert_page_script` (PUT); **destructive** `delete_all_site_scripts`, `delete_all_page_scripts` (DELETE). [SOURCE: logs/evidence/tools/scripts.ts]
6. **components** (`data_components_tool`): reads `list_components`, `get_component_content`, `get_component_properties`; draft-safe `update_component_content` (POST dom), `update_component_properties` (POST properties) — component changes ship with site publish. [SOURCE: logs/evidence/tools/components.ts]
7. **workflows** (`data_workflows_tool`): `list_workflows`, `list_workflow_runs`, `get_workflow_run` (GET) — read-only; `run_workflow` (POST /workflows/:workflow_id/run) — **deployment-capable**: executes a managed Webflow-side workflow (which may publish or deploy per its configuration). [SOURCE: logs/evidence/tools/workflows.ts]
8. **webhooks / comments / enterprise / aiChat / rules / localDeMCPConnection**: webhooks — `list_webhooks`, `get_webhook` (GET) read-only; `create_webhook` (POST), `delete_webhook` (DELETE) infra mutation. comments — all three actions (`list_comment_threads`, `get_comment_thread`, `list_comment_replies`) are GET read-only. enterprise — 301 redirect CRUD (`list_301_redirects`, `create_301_redirect`, `update_301_redirect`, `delete_301_redirect`), robots.txt management (`get/update/replace/delete_robots_txt`), `add_well_known_file`, `remove_well_known_files`, `list_site_activity_logs` (read-only); enterprise plan required. aiChat — `ask_webflow_ai` single message action (readOnlyHint true, chats with Webflow AI over docs). rules — `webflow_guide_tool` static guidelines, readOnlyHint true. localDeMCPConnection — `get_designer_app_connection_info` returns the local `http://localhost:<port>` URL for the bridge app. [SOURCE: logs/evidence/tools/webhooks.ts, comments.ts, enterprise.ts, aiChat.ts, rules.ts, localDeMCPConnection.ts]
9. **Designer (bridge-bound) tools** — all operate on the live canvas via the companion app: `de_page_tool` (`create_page`, `create_page_folder`, `get_current_page`, `switch_page`); `element_builder` (create element on active page); `element_tool` (`get_all_elements`, `get_selected_element`, `select_element`, `remove_element`, `add_or_update_attribute`, `remove_attribute`, `update_id_attribute`, `set_text`, `set_style`, `set_link`, `set_heading_level`, `set_image_asset`, `query_elements`, `get_children_info`); `element_snapshot_tool` (visual snapshot, readOnlyHint true); `style_tool` (`create_style`, `get_styles`, `update_style`, `remove_style`, `query_styles`); `variable_tool` (variable collection/mode CRUD, typed variable create/update for color/size/number/percentage/font-family, `rename_variable`, `delete_variable`, `query_variables`); `asset_tool` (`create_folder`, `get_all_assets_and_folders`, `update_asset`); `de_component_tool` (`transform_element_to_component`, `insert_component_instance`, `open/close_component_view`, `get_all_components`, `get_component`, `get_component_metadata`, `set_component_metadata`, `rename_component`, `unregister_component`). Mutations are draft/canvas-level; they become live only through the Data publish actions. [SOURCE: logs/evidence/tools/dePages.ts, deElement.ts, deStyle.ts, deVariable.ts, deAsset.ts, deComponents.ts]

## Assessment

- **newInfoRatio: 0.85** — Action-level inventory and operation classes are net-new; module list and bridge-app finding carried from iteration 1.
- Confidence: high — every action and HTTP method extracted directly from official server source. Residual unknown: exact live-site semantics of `delete_collection_items` on published items (official FAQ states CMS live-site mutation is possible; exact cascade behavior UNKNOWN).

## Reflection

- What worked: comment-to-endpoint mapping in tool source makes HTTP-method classification trivial and authoritative; Designer tools recognized by RPC forwarding to the bridge app.
- What failed: Designer action schemas are nested unions (16-space indent variants) — needed a second extraction pass; `update_page_settings` publish semantics need doc verification (iteration 4).
- Ruled out: treating Designer mutations as publish-capable (they are canvas-draft; publishing is Data-tool-only).
