# Implementation Plan: Phase 6 - Webflow hub registration and advisor surface

<!-- SPECKIT_LEVEL: 1 -->

<!-- ANCHOR:summary -->
## 1. SUMMARY
| Aspect | Value |
|--------|-------|
| **Workflows** | sk-create-skill packaging and validation contracts |
| **Inputs** | Phase 2 classification, Phase 3-5 package surfaces, hub manifests |
| **Outputs** | Registered, routed, advisor-discoverable mode with current generated assets |
| **Safety** | Manifest edits limited to hub-owned files; no leaf-packet advisor metadata; no external mutation |

Register the source inputs first (registry, router, smart-routing, hub docs), then regenerate every derived artifact with the hub's canonical scripts so hand-edit drift is impossible.
<!-- /ANCHOR:summary -->

---

<!-- ANCHOR:quality-gates -->
## 2. QUALITY GATES
### Definition of Ready
- [ ] Phase 5 catalog/playbook validate.
- [ ] Phase 2 classification is accepted and recorded.
- [ ] Hub validator scripts are runnable locally.

### Definition of Done
- [ ] Registry, router, and smart-routing resolve Webflow intents to `mcp-webflow`.
- [ ] Generated assets are fresh per the freshness checks.
- [ ] Parent-skill, root-metadata, and compiled-routing validators pass.
- [ ] Hub docs list the mode and the changelog records it.
<!-- /ANCHOR:quality-gates -->

---

<!-- ANCHOR:architecture -->
## 3. ARCHITECTURE
### Pattern
Source-of-truth inputs edited by hand; every derived artifact regenerated by the canonical generator.

### Key Components
- **Registry entry**: `mode-registry.json` mode object mirroring Phase 2 classification and the Phase 2 permission surface.
- **Router layer**: `hub-router.json` vocabulary/signals plus `smart-routing.md` per-mode leaf sets.
- **Advisor surface**: hub-root `description.json`/`graph-metadata.json` only.
- **Generated assets**: `leaf-manifest.json` and derived metadata via `generate-leaf-manifest.cjs` / `regenerate-skill-derived.cjs`.
- **Compiled routing**: scenario fixtures validated by `validate-compiled-routing-scenarios.cjs`.

### Data Flow
Phase 2 classification -> registry + router inputs -> generators -> leaf manifest + derived metadata -> compiled-routing scenarios -> hub validation -> changelog.
<!-- /ANCHOR:architecture -->

<!-- ANCHOR:phases -->
## 4. IMPLEMENTATION PHASES
### Phase 1: Setup
- [ ] Load sk-create-skill packaging/validation contracts and the root-metadata contract.
- [ ] Confirm Phase 2 classification and the accepted permission surface.
- [ ] Snapshot current hub manifests and generator outputs as the regression baseline.

### Phase 2: Registration
- [ ] Add the `mcp-webflow` entry to `mode-registry.json`.
- [ ] Add Webflow vocabulary/signals to `hub-router.json` and leaf sets to `smart-routing.md`.
- [ ] Update hub `SKILL.md`, refresh hub-root advisor metadata, and draft the changelog entry.

### Phase 3: Generation and Validation
- [ ] Regenerate `leaf-manifest.json` and derived metadata with canonical scripts.
- [ ] Add compiled-routing scenarios covering Webflow intents and boundaries.
- [ ] Run root-metadata, parent-skill, freshness, and compiled-routing validators; record evidence.
- [ ] Update summary and hand off to Phase 7.
<!-- /ANCHOR:phases -->

<!-- ANCHOR:testing -->
## 5. TESTING STRATEGY
| Test Type | Scope | Tools |
|-----------|-------|-------|
| Structural | Manifest schema and required fields | JSON schema + validators |
| Routing | Webflow intent resolves to the mode | Router scenarios / compiled-routing validator |
| Freshness | Generated assets match generators | Freshness CI scripts |
| Hub integrity | No duplicate metadata, no leaf-packet advisor files | `ci-skill-root-metadata.cjs`, `parent-skill-check.cjs` |
| Non-regression | Sibling modes still resolve | Full compiled-routing suite |
<!-- /ANCHOR:testing -->

<!-- ANCHOR:rollback -->
## 7. ROLLBACK PLAN
- **Trigger**: A validator fails, routing resolves to the wrong mode, or a sibling mode regresses.
- **Procedure**: Restore the pre-registration snapshot of the affected hub files, regenerate derived assets, re-run the full hub validation suite, and confirm sibling modes resolve before retrying registration.
<!-- /ANCHOR:rollback -->
