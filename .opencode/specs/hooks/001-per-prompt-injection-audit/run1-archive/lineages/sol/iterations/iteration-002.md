# Iteration 2: Claude Code Hook Adapter End-to-End Audit

## Focus
Audit the configured Claude Code `SessionStart` and `UserPromptSubmit` paths end to end: exact ordering, owning functions/templates, content variants, conditional/fail-open behavior, and the distinction between configured artifacts and evidence of live delivery. The dispatch focus overrides the strategy's broader token-cost question for this iteration; exact byte/token measurement is deferred, but the variant boundaries and source anchors needed for it are captured.

## Findings
1. **Configured order comprises two independent per-turn injections.** `.claude/settings.json` registers one catch-all `UserPromptSubmit` matcher whose hook array runs the compiled advisor shim first and `spec-gate-classify.mjs` second. The first emits an advisor/directives block on a valid prompt unless explicitly disabled or unable to parse input; the second emits the Gate-3 menu only when `classifyIntent()` returns a question. Claude Code, rather than either module, combines the two hook results, so they must be measured as separate blocks in configured array order. 2. **The first per-turn block has three model-visible content variants plus a no-output path.** The normal single recommendation is `Advisor: {live|stale}; use {label} {confidence}/{uncertainty} pass.`; an ambiguous two-result form is `Advisor: {freshness}; ambiguous: ... vs ... pass.`; both append `Directives:` and the exact comment-hygiene, governor, and proof-over-appearance lines. Any non-renderable advisor result (including skipped empty and command-only prompts) falls back to those directives without an `Advisor:` line. `SPECKIT_SKILL_ADVISOR_HOOK_DISABLED=1`, invalid JSON, a missing prompt field, or an uncaught exception returns `{}` and injects nothing. 3. **Advisor fallback layering is warm-first, constitutional-second.** `handleClaudeUserPromptSubmit()` calls the main producer, conditionally retries via the bounded CLI fallback when `shouldTrySkillAdvisorCliFallback()` permits it, renders the resulting live/stale recommendation, then substitutes `renderAdvisorFallbackDirective()` if rendering returns null. This means later measurement needs at least normal-single, normal-ambiguous, stale-recommendation, directives-only, and zero-output fixtures; the separate `renderAdvisorTimeoutFallback()` string is not called by this Claude entrypoint. 4. **Gate 3 is a conditional second block with exact fixed bytes and session state.** The Claude classifier extracts `prompt`, `session_id`, and project directory, calls shared `classifyIntent()`, and emits only `result.question`. The canonical five-line A-E menu is owned by `GATE_3_QUESTION`; absent/invalid input and internal errors fail open. It is not an always-per-turn block: the shared policy parses answers to an open gate or opens one on mutation intent, while the configured environment sets enforcement to advisory (`MK_SPEC_GATE_ENFORCE=0`). 5. **SessionStart has one injecting hook, then four maintenance checks whose stdout may still be visible but is not structured context.** The configured array invokes compiled `session-prime.js` first, followed by worktree guard, git-hook check, dist-staleness check, and Codex-hook drift check. Only `session-prime.ts` deliberately formats model context. It dispatches by `source`: `startup` (Session Context + Recovery Tools + optional Session Continuity), `resume` (Session Resume), `clear` (Fresh Context), and `compact` (cached Recovered Context + Recovery Instructions + optional Active Spec Folder, or one of three Context Recovery fallbacks). Startup/resume without recovered continuity also append a `Spec Memory CLI Fallback` section containing a bounded session-resume brief or `Memory: CLI fallback skipped ({reason})`. 6. **SessionStart output shape and budgets are deterministic, but payload size is data-dependent.** Sections render as `## {title}\n{content}` separated by blank lines. Startup/resume/clear use a 2,000-token estimate cap and compact uses 4,000; pressure above 70% lowers the cap, above 90% lowers it to 20% with a 200-token floor. Compact recovery embeds a sanitized cached payload, startup can embed cached continuity, and the CLI section is variable, so token measurement needs controlled fixtures for every source and cache/continuity/pressure branch rather than one static count. ## Ruled Out
- Counting the SessionStart maintenance commands as deliberate prompt blocks: their registrations are real, but only `session-prime` uses the repository's context formatter; runtime capture is required to determine whether incidental stdout becomes visible.
- Counting the dormant code-graph merge helper: it has no caller in either current source or configured compiled shim.
- Treating `renderAdvisorTimeoutFallback()` as a Claude variant: the Claude hook uses CLI fallback followed by the directives-only fallback, with no call to that renderer.

## Dead Ends
No source path was exhausted. README prose is insufficient for live behavior where it contradicts executable source.
