## 2. PROBLEM & PURPOSE

The two-model deep review of the skill-metadata program returned CONDITIONAL with one P1 (fixed in the predecessor packet) and ten distinct P2 findings recorded as an operator-gated hardening backlog. The P2s cluster into three real weaknesses: fleet gates that can report a false-green pass on bad input, validator probes that touch authored filesystem paths without a containment check, and undocumented deliberate fallbacks that read as bugs to the next maintainer. None blocks release, but each erodes trust in the enforcement surface the program exists to provide. This packet closes all ten.
<!-- /ANCHOR:problem -->

---

<!-- ANCHOR:scope -->
## 3. SCOPE

In scope: the ten P2 findings A–J from the review report, each fixed at its cited site with a proving test where the behavior is testable. Surfaces touched — the two fleet-gate CLIs (`ci-skill-root-metadata.cjs`, `ci-leaf-manifest-freshness.cjs`), the standalone manifest generator (`generate-leaf-manifest.cjs`), the command-metadata schema library, the advisor daemon watcher (`watcher.ts`), the watcher and journey-proof and contract test suites, and the pre-push hook comment. Out of scope: any change to the H/S class contract itself, the command-metadata schema shape, or generated-file bytes; the shared `safeReaddir` helper refactor suggested in the report's lane A is deliberately not taken (the two call sites are documented in place instead — the finding was documentation, not a shared abstraction).
<!-- /ANCHOR:scope -->

<!-- ANCHOR:requirements -->
## 4. REQUIREMENTS

| ID | Requirement | Acceptance Criteria |
|----|-------------|---------------------|
| REQ-001 | Fleet gates never report a false-green pass on bad input | Both CLIs exit 2 ("cannot run") for a missing or non-directory `--skills-dir`; a non-ENOENT `readdir` error at the top level surfaces instead of becoming zero roots |
| REQ-002 | Authored paths are contained before filesystem access | A standalone `packet` that resolves outside the skill root throws `PACKET_OUT_OF_ROOT`; choreography resources resolve repo-root-relative only, matching the stated contract |
| REQ-003 | Within-entry duplicate signals are flagged | A command listing the same owned signal twice emits `DUPLICATE_OWNED_SIGNAL_WITHIN_ENTRY`, distinct from the cross-command code |
| REQ-004 | Containment predicate is platform-correct | `isWithin` rejects a cross-drive Windows child; no POSIX behavior change |
| REQ-005 | Tests resolve dependencies portably and assert equivalence | The watcher test resolves chokidar from the advisor's own `node_modules` first; the journey proof asserts scaffold-vs-template shape equivalence |
| REQ-006 | Deliberate fallbacks are documented | The skip-and-continue walkers and the pre-push first-push diff-guard fallback carry a WHY comment; the two gates' exit codes are reconciled and documented |
| REQ-007 | No regression | Full gate sweep green; generated bytes byte-identical; fleet 11/11 |
<!-- /ANCHOR:requirements -->

<!-- ANCHOR:success-criteria -->
## 5. SUCCESS CRITERIA

All ten P2 findings closed at their cited sites; three new negative-case tests prove the new load-bearing behaviors (within-entry dedup, gate exit-2 on non-directory input, standalone packet containment); the existing unit, watcher, journey-proof, and drift-guard suites stay green; both fleet gates report 11/11 with byte-identical generated manifests; the adversarial verify returns no unrefuted P0/P1.
<!-- /ANCHOR:success-criteria -->

<!-- ANCHOR:risks -->
## 6. RISKS & DEPENDENCIES

| Type | Item | Mitigation |
|------|------|------------|
| Risk | The `watcher.ts` change is live daemon code | The change is a pure containment-predicate hardening, additive on POSIX (`isAbsolute(relative(a,b))` is unreachable on POSIX where `relative` never returns an absolute path); proven by the full watcher suite |
| Risk | Dropping the choreography skillDir fallback could reject a legitimate authored entry | Fleet gate passes 11/11, proving no current authored entry relied on hub-relative resolution; the contract has always stated repo-root-relative |
| Risk | The exit-code change (freshness gate 1→2 on bad input) could confuse a caller keying on exit 1 | Exit 1 stays reserved for a real stale/failed manifest; only the "cannot run" case moved to 2, now documented in both headers |
| Dependency | The review backlog | Fixed against the exact landed program tip; each finding re-verified against source before action |
<!-- /ANCHOR:risks -->
