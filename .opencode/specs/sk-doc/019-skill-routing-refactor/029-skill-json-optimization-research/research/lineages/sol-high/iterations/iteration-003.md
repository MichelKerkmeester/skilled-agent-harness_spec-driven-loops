# Iteration 3: Automation gaps and lifecycle ownership

## Focus
Dimension 3 only: identify where scaffolding, generation, freshness, reconciliation, and lifecycle ownership stop short across the eight governed skill-root JSON types plus advisor graph/index and compiled-route projections. The selected interpretation treats human routing meaning (`edges`, modes, aliases, intent vocabulary, command choreography, serving authority) as authored policy, while class boilerplate, repeated identities, corpus inventories, derived labels, and consumer-specific projections are automation candidates. Effectiveness and test-depth judgments remain deferred to iterations 4 and 5.

## Findings
1. **Highest leverage — creation does not produce a contract-complete skill root.** The standalone path writes `SKILL.md`, `graph-metadata.json`, and `leaf-manifest.config.json`, then tells the operator only to edit prose, add resources, and run an unspecified validator; it never invokes the fleet gate that creates required `leaf-manifest.json` and S-class `leaf-aliases.json`. The parent path similarly writes the five authored H JSON surfaces and an empty command surface but no leaf manifest; only compiled routing has an optional mint/freshness branch. Because both classes require a generated manifest and S additionally requires generated aliases, `init_skill.py` hands off a structurally incomplete root and leaves lifecycle ownership to human memory. The scaffold should finish by running the canonical generated-artifact producer/check, without inventing authored policy. 6. **Medium leverage — compiled-route artifact mechanics are automated, but source-change-to-refresh ownership is not fleet-integrated.** The compiler consumes exactly `SKILL.md`, `hub-router.json`, and `mode-registry.json`; mint creates a canonical generation-1 manifest, while refresh recompiles one generation ahead, preserves serving authority/shadow state, takes a writer lease, and publishes atomically. ## Ruled Out
- **Using spec-folder `generate-description.js` or `backfill-graph-metadata.js` to repair skill-root identity.** The fleet gate explicitly excludes the spec tree because same-named files there use a separate continuity schema; sharing a filename is not shared lifecycle ownership. [SOURCE: .opencode/skills/sk-doc/create-skill/scripts/ci-skill-root-metadata.cjs:21-26]
- **Generating all H JSON from packet folders.** Mode semantics, router weighting, compatibility relocation, graph relationships, command intent/choreography, and activation authority are not inferable boilerplate; the root contract permits unattended writes only for class-specific generated manifest/alias projections. [SOURCE: .opencode/skills/sk-doc/create-skill/scripts/lib/skill-root-metadata-contract.cjs:125-152]
- **Keeping the output-first freshness scanner as a second authoritative lifecycle gate.** It can byte-check committed manifests but cannot see missing adoption; the SKILL-root fleet gate already owns that complete discovery boundary. [SOURCE: .opencode/skills/sk-doc/create-skill/scripts/ci-leaf-manifest-freshness.cjs:54-84] [SOURCE: .opencode/skills/sk-doc/create-skill/scripts/ci-skill-root-metadata.cjs:74-86]

## Dead Ends
- No generator can safely infer authored routing vocabulary, edge meaning/weights, compatibility relocations, command choreography, or serving-authority flips from directory structure alone. Automation should project and reconcile identities around those declarations, not replace them.

## Edge Cases
- Ambiguous input: the named spec-folder description/graph generators share filenames with skill metadata but own a different schema; they were classified as an intentional boundary, not reused.
- Contradictory evidence: three shapes currently claim ownership of schema-v2 `derived` data (scaffold legacy shape, TypeScript sync shape, Python compiler shape); the conflict remains unresolved and blocks declaring any one producer canonical.
- Missing dependencies: none required; local source established the lifecycle paths.
- Partial success: one broad repository grep returned sibling-lineage matches despite the lineage read restriction. Those matches were discarded, are not cited, and did not inform the findings; all evidence above comes from production/config sources or this lineage's prior state.
