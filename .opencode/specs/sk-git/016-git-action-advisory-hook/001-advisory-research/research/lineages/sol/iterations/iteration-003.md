# Iteration 3: Staging and Commit Semantics

## Canonical Route Proof

`Resolved route: mode=research target_agent=deep-research`; `agent_definition_loaded=true`; detached lineage `sol`; run/iteration `3`; LEAF execution with no sub-agent dispatch.

## Focus

Investigate broad staging, commit-time staging and path selection, pathspec expansion, partial rename staging, hook-time index mutation, and cheap preflight probes. The narrow advisory target is a direct shell-visible `git`/`git -C` command. A preflight may report objective path sets and counts, but it must not call them “another session's” work when Git has no ownership metadata. Interactive choices and stdin-generated pathspecs are deferred because their final selections do not exist before execution.

## Findings

1. **Broad add needs an objective delta, not an ownership accusation.** **Operation:** `git add -A|--all [--] [<pathspec>...]`, `git add .`, or `git add <directory>`; resolve global `-C <repo>` and the command cwd before interpreting `.`. **Specific pre-execution state:** snapshot `S0 = git diff --cached --name-only -z`, then run the same selection as `git add -n`/`--dry-run` to obtain candidate updates `A`; report only facts such as “index already has |S0| paths; broad add would update |A| more.” In the present primary checkout, `S0=0`, `git add -n -A -- .` reported 151 candidate entries, and `git add -n -u -- .` reported 47. **Genuine pre-run availability:** the sets are available to a stateful PreToolUse process with the actual cwd; the current evaluator receives only command text, and Git does not encode session ownership. **Noise:** exact broad-add invocation frequency is not measured; current exposure is measured. A rule requiring a nonempty pre-existing index would stay silent now despite 149 dirty paths, so it is precise but incomplete. **Source classification:** named sk-git scoped-staging rule (commit workflow Step 7 / ALWAYS #13) plus the observed add-directory incident. **Confidence:** confirmed for command semantics, current counts, and lack of ownership state; inferred for the best threshold. Recommend an advisory only for exact broad shapes with a material objective delta, phrased neutrally; silence when the only claim would be cross-session ownership. 2. **`commit -a` is a separate broad-staging operation, but path count alone is a noisy false friend.** **Operation:** `git commit -a|--all ...` (including `--amend -a`), excluding `--dry-run`. **Specific pre-execution state:** current staged set, all modified/deleted tracked paths that `-a` would add, unmerged entries, worktree identity, and native `git commit --dry-run --porcelain` with the same selection options. The current checkout has 0 staged, 46 unstaged tracked, and 103 untracked paths; `-a` would consider the tracked modifications/deletions but not the untracked paths. **Genuine pre-run availability:** those sets and whether this is the primary or a linked worktree are locally available; which tracked edits belong to another session is not. The current pure evaluator cannot obtain them without a stateful probe layer. **Noise:** option-specific use is not measured. In the latest 500 commits, 453 (90.6%) touched at least 2 paths, 389 (77.8%) at least 4, and 287 (57.4%) at least 10, so “many paths” is demonstrably normal commit history and cannot by itself justify a warning. **Source classification:** new extension of the named scoped-staging rule, justified because Git performs implicit tracked-file staging at commit time. **Confidence:** confirmed for Git semantics, current state, and history rates; inferred for contamination risk. Retain only an exact `-a` advisory with objective dirty-set context in a shared/primary tree; do not warn merely because the candidate contains many paths. 3. **Path arguments silently select `--only` semantics even when `--only` is absent.** **Operation:** `git commit [--only|-o] [options] -- <pathspec>...` and ordinary `git commit [options] <pathspec>...`; special no-path forms `git commit --only --amend` and `git commit --only --allow-empty` are distinct. **Specific pre-execution state:** resolve the pathspec against HEAD/index/worktree, snapshot staged paths outside the selected set, and use `git commit --dry-run --porcelain` with the same options to display selected versus held-back paths. Git documents that named paths use working-tree contents, disregard staged contents for other paths, and leave those held-back paths staged. **Genuine pre-run availability:** the probable pre-hook selection and holdback set are available before execution; whether holdback is intentional is not. **Noise:** exact path-commit frequency and omitted-request rate are not measured; the observed dropped-named-path incident proves cost but not prevalence. **Source classification:** observed `commit --only` incident, extended by official Git semantics showing that explicit path arguments imply the same behavior without spelling `--only`. **Confidence:** confirmed for operation semantics and probe availability; inferred for operator intent. Warn only when the native dry-run reveals a surprising condition—requested changed paths absent or a nonempty staged set held back—and state the sets without saying the omission is accidental. [SOURCE: https://git-scm.com/docs/git-commit/2.50.0] [SOURCE: .opencode/specs/sk-git/016-git-action-advisory-hook/001-advisory-research/research/BRIEFING.md:21-32] [INFERENCE: comparing the parsed requested pathspec, HEAD-relative changes, and Git's own dry-run is the narrowest preflight test for a named path that would not enter the candidate commit]

4. **`--include` is the opposite path-commit mode and usually should remain silent.** **Operation:** `git commit -i|--include <pathspec>...`; do not confuse `-i` here with `git add -i`. **Specific pre-execution state:** existing staged paths, selected tracked worktree paths, unmerged entries, and merge/cherry-pick state. Git says this stages the named paths *in addition to* staged contents and is usually used to conclude a conflicted merge. **Genuine pre-run availability:** all local sets and operation markers are available, but ownership and the final conflict-resolution intent are not. **Noise:** invocation frequency is not measured. **Source classification:** new missed case with justification: it can combine more than the explicit path list, but the behavior is explicit and designed for conflict completion. **Confidence:** confirmed for Git semantics; inferred for attention cost. Recommend silence by default; at most reuse the neutral “pre-existing index plus selected paths” summary when a separate scoped-staging rule already has positive evidence. [SOURCE: https://git-scm.com/docs/git-commit/2.50.0] [INFERENCE: an unconditional advisory would restate an explicit mode and distract during conflict recovery]

5. **Pathspec cardinality is probeable only after respecting the shell/Git boundary.** **Operation:** quoted Git patterns such as `git add -- '*.md'`, pathspec magic such as `git add -- ':(glob)**/*.md'`, directory pathspecs, unquoted shell globs such as `git add *.md`, and `git add|commit --pathspec-from-file=<file> [--pathspec-file-nul]`; stdin form `--pathspec-from-file=-` is separate. **Specific pre-execution state:** actual cwd, quoting/token boundaries, preexisting readable pathspec-file bytes, Git pathspec expansion, candidate set, and top-level spread. **Genuine pre-run availability:** quoted Git pathspecs and a stable regular file are reproducible with a dry-run; unquoted shell expansion has not happened when the Bash PreToolUse hook sees the command string, and stdin/pipeline-generated pathspec content may not yet exist. Emulating arbitrary shell expansion or consuming stdin is not a cheap safe probe. **Noise:** exact invocation rates are not measured; 46/500 commits (9.2%) legitimately touched at least two top-level roots, so cross-root expansion is evidence for review, not contamination. **Source classification:** new with justification, because broadness can be hidden behind patterns or a pathspec file rather than `.`/a directory token. **Confidence:** confirmed for Git's pathspec-file options and the measured history proxy; inferred for shell-emulation limits. Probe only reproducible direct forms; remain silent on ownership and on non-reproducible stdin/interactive selections. [SOURCE: bounded Git evidence: `git add -h`; installed Git 2.50.1] [SOURCE: https://git-scm.com/docs/git-commit/2.50.0] [SOURCE: bounded Git evidence: 500-commit top-level spread]

6. **Partial rename staging is detectable as a heuristic pair, not as index ownership.** **Operation:** `git add [--] <old-path>` or `<new-path>`, a directory/pathspec selecting only one side of a worktree rename, and broad add shapes whose candidate set intersects only one side after exclusions. **Specific pre-execution state:** `git diff --name-status -M` rename/copy pairs, current `git diff --cached --name-status -M`, and the dry-run-selected paths; flag only a pair where exactly one side would change index state. The current checkout has no inferred worktree or staged rename entry. **Genuine pre-run availability:** rename similarity and selected paths are available, but Git records snapshots and infers renames during diff; a preflight cannot prove semantic identity or another session's ownership. Exactly simulating the post-add index would require a temporary alternate index, which is heavier than the cheap read-only probes. **Noise:** 36/500 commits (7.2%) contained an inferred rename/copy, while one-sided staging frequency is not measured. **Source classification:** named sk-git ALWAYS #10 (“confirm R-status”), extended from the observed half-rename incident. **Confidence:** confirmed for current absence and history rate; inferred for pair-level prediction. Emit only a neutral one-line “selected one side of inferred rename old → new” advisory; do not warn on every rename, and do not treat delete+add as proof of an error. 7. **Forced ignored-file staging is a quieter missed case; interactive and intent-only staging are false friends.** **Operation:** retain `git add -f|--force <pathspec>` when the candidate includes ignored files; exclude `git add -n|--dry-run`, `git add -N|--intent-to-add`, and `git add -p|--patch|-i|--interactive|-e|--edit` from content-sweep advisories. **Specific pre-execution state:** exact dry-run candidate set plus `git check-ignore -v --no-index` for ignored candidates; for interactive/edit modes, only the offered set exists before the operator chooses hunks. **Genuine pre-run availability:** ignored status and direct path candidates are available; the final interactive/edit selection is not. **Noise:** invocation frequency is not measured. **Source classification:** new with justification: `-f` deliberately crosses ignore protection and can expose generated artifacts or secrets, while the excluded modes are dry-run, metadata-only, or operator-selection flows. **Confidence:** confirmed for installed option semantics; inferred for risk classification. Advise only when `-f` has a nonempty ignored candidate set, naming count/path class without exposing content; remain silent for the excluded modes. 8. **PreToolUse can describe only the pre-hook candidate; hooks own a later mutable boundary.** **Operation:** any `git commit` selection mode, especially `git commit --only <paths>`, `git commit -a`, and plain `git commit`; `--no-verify` separately bypasses the current `pre-commit` and `commit-msg` gates. **Specific pre-execution state:** command text, cwd, HEAD, worktree/index snapshots, installed hook files, and Git's dry-run candidate. The current outer pre-commit and nested comment-hygiene hook inspect `git diff --cached`; the commit-msg hook reads staged-path count and blocks a bodyless message at four or more paths. Their inspected bodies contain no direct `git add` or `git update-index`, but they invoke validators, so only the inspected direct layer is confirmed read-only. **Genuine pre-run availability:** all of that is inspectable before `git commit`; changes made after command start—by hook code, concurrent processes, or interactive message/patch flows—are not a guaranteed PreToolUse fact. Git runs commit hooks after entry to `git commit`, and hook implementations are allowed to alter repository state unless project policy forbids it. **Noise:** hook-induced index mutation was not observed or measured in repository history; ordinary history cannot record it. **Source classification:** new boundary finding required by evaluator/hook architecture, with current-hook evidence. **Confidence:** confirmed for current direct hook reads, hook ordering surface, and the command-only evaluator; inferred for possible child-hook mutation. Advisory wording must say “would be selected before hooks,” never “the commit will contain exactly.” [SOURCE: .opencode/scripts/git-hooks/pre-commit:17-118] [SOURCE: .opencode/hooks/pre-commit:7-58] [SOURCE: .opencode/scripts/git-hooks/commit-msg:145-175] [SOURCE: .opencode/skills/cli-external-orchestration/cli-opencode/scripts/lib/dispatch-rule-checks.mjs:68-125] [SOURCE: https://git-scm.com/docs/git-commit/2.50.0]

9. **The cheap discriminator is set comparison plus isolation evidence; there is no reliable ownership probe.** **Operation:** run only after matching an exact broad/selective shape: broad `git add`, `git commit -a`, or path-limited `git commit [--only] <pathspec>`. **Specific pre-execution state:** (1) `git status --porcelain=v2 -z`, (2) staged names, (3) unstaged tracked names, (4) untracked names only when the operation can include them, (5) native add/commit dry-run with identical pathspecs, and (6) registered worktree/current-worktree identity. Compare baseline index to candidate, coalesce to one line, and cap path samples. **Genuine pre-run availability:** objective sets, counts, rename heuristics, and worktree isolation are available if cwd is trustworthy; session ownership, author intent, and later hook mutation are unavailable. **Noise:** real-history proxies show 90.6% of 500 commits were multi-path, 77.8% had at least four paths, 57.4% had at least ten, and 9.2% crossed top-level roots. Therefore thresholds based only on 2/4/10 paths or multiple roots would fire on normal intentional work. Exact advisory fire rate is not measured because argv telemetry does not exist. **Source classification:** new synthesis justified by the briefing's noise requirement and measured repository history. **Confidence:** confirmed for probe inputs and history rates; inferred for the recommended gate. Recommend silence unless an exact broad/selective command combines with a concrete mismatch (held-back staged paths, one-sided inferred rename, ignored file forced in, or reproducible expansion materially beyond explicit paths). ## PreToolUse vs Hook-Time Boundary

- **PreToolUse can know:** the direct Bash command text; a trustworthy cwd/`git -C` target if supplied; current HEAD/index/worktree/config/refs; current hook bodies; reproducible Git pathspec expansion; native dry-run output; and current worktree registration. The present evaluator itself knows only command text and would need an explicit bounded probe layer for repository state. [SOURCE: .opencode/skills/cli-external-orchestration/cli-opencode/scripts/lib/dispatch-rule-checks.mjs:68-125]
- **PreToolUse cannot guarantee:** unquoted shell expansions not yet performed, stdin/interactive selections not yet produced, ownership of dirty/staged paths, concurrent edits, hook-time index mutations, or the final commit tree. The current inspected direct hooks are read-oriented, but that local observation is not a universal hook contract. [SOURCE: .opencode/scripts/git-hooks/pre-commit:17-118] [SOURCE: .opencode/hooks/pre-commit:7-58] [SOURCE: .opencode/scripts/git-hooks/commit-msg:145-175] [INFERENCE: command execution and hooks occur after the preflight snapshot]

## Ruled Out

- Unconditional warnings on any directory pathspec, wildcard, multi-path commit, four-or-more staged files, or cross-top-level commit: measured history shows these are normal shapes, and none proves ownership.
- Warning on every `git commit --only` or every commit with path arguments: selective commits intentionally hold other staged paths back; use Git's dry-run to surface only concrete mismatches.
- Treating `git commit --include` as inherently suspicious: it is an explicit conflict-completion mode.
- Predicting interactive `add -p/-i/-e` or `commit -p` selections, or consuming `--pathspec-from-file=-` input in preflight.
- Claiming an inferred rename is semantic identity, or claiming a pre-hook candidate is the immutable final commit tree.

## Dead Ends

- Ordinary Git history still cannot measure `add -A`, `commit -a`, `commit --only`, `--include`, pathspec, interactive, or failed-command frequency. The 500-commit tree sample measures false-positive pressure from committed path breadth and rename incidence only; exact fire rates require normalized future PreToolUse telemetry.
- Git's index, status, worktree registry, and commit metadata contain no session-owner field. Without an external ownership declaration, an advisory must remain neutral or silent rather than infer contamination.

## Edge Cases

- Ambiguous input: “cross-session contamination” could mean pre-staged paths, shared-primary worktree edits, or changes from another linked worktree. This iteration uses only objective set mismatches and isolation evidence; ownership remains deferred.
- Contradictory evidence: broad/multi-path selection is discouraged by scoped-staging rules in a dirty shared tree, while 90.6% of sampled commits legitimately touch multiple paths. The resolution is not a path-count threshold; it is an exact operation plus a concrete selection mismatch.
- Missing dependencies: no normalized Bash/PreToolUse argv telemetry exists, and the redirected Git add/glossary web version pages did not provide stable versioned text. Installed Git 2.50.1 help and the successful official commit documentation were used instead.
- Partial success: exact option-specific historical rates and ownership are unavailable, but enough direct semantics, current-state probes, hook evidence, and history noise measurements support bounded candidate rules and explicit silence cases. Status remains `complete` because at least one in-scope question is answered with cited evidence.

## Reflection

- What worked and why: combining official selection semantics, current hook bodies, native dry-run shapes, current dirty-set counts, and 500-commit path breadth prevented the observed incidents from turning into generic broad-path warnings.
