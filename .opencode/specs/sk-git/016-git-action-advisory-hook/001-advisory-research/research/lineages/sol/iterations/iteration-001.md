# Iteration 1: Git Operation Families and Pre-Execution State

## Focus
Inventory direct `git` invocation families that a Bash `PreToolUse` hook can classify before execution, then separate command-only predicates from checks that need repository, worktree, index, ref, remote, or config reads. The selected interpretation is limited to direct shell-visible Git shapes; aliases, shell functions, commands assembled by `eval`, and arbitrary scripts are deferred because classifying their eventual Git subprocess is not reliable from the original Bash text.

## Findings

The current evaluator is a command-string engine: `evaluate(command, rules)` passes only the composed command to pure check functions. It can host command-only predicates today, but every stateful candidate below would require the PreToolUse path to add bounded read-only probes and a trustworthy command working directory. 1. **Direct branch creation — command-only advisory.** **Operation:** `git branch <new> [<start>]`, `git checkout -b|-B <new> [<start>]`, or `git switch -c|-C <new> [<start>]` (including direct `git -C <repo> ...` forms). **Pre-execution state:** the command shape is sufficient for the named prohibition; branch existence and registered worktrees are optional refinements obtainable with `git show-ref --verify` and `git worktree list --porcelain`. **Genuinely available:** yes for a direct invocation; no for a Git command hidden in an opaque script or alias expansion. **Noise:** not measured—Git reflogs do not preserve these argv forms, and only 7/1,482 HEAD-reflog entries were checkouts, which is not a branch-creation count. **Source classification:** named sk-git rule, NEVER #2; it requires branch creation through the allocator-backed `git worktree add -b` flow. **Confidence:** confirmed for the rule and command classifier; inferred for operational fire rate. [SOURCE: .opencode/skills/sk-git/SKILL.md:210-221] [SOURCE: .opencode/skills/sk-git/SKILL.md:482-486] [SOURCE: bounded command evidence: `git reflog --format=%gs HEAD`]

2. **Blanket hook bypass — command-only advisory.** **Operation:** direct `git commit ... --no-verify` or `git push ... --no-verify`, accepting option placement before or after the subcommand's ordinary arguments. **Pre-execution state:** only the parsed presence of `--no-verify`; repository state is not needed. **Genuinely available:** yes for direct commands. **Noise:** not measured because reflogs and commit history omit invocation options. **Source classification:** named sk-git rule, NEVER #9; this is especially advisory-worthy because the operation disables the enforcement layer that would otherwise own the check. **Confidence:** confirmed. [SOURCE: .opencode/skills/sk-git/SKILL.md:482-493] [SOURCE: .opencode/scripts/git-hooks/pre-commit:46-55]

3. **Amending published or integrated HEAD — stateful advisory.** **Operation:** `git commit --amend ...` (including `--amend --no-edit`). **Pre-execution state:** resolve `HEAD`; test whether a local remote-tracking ref or protected/integration branch contains that commit (`git for-each-ref --contains HEAD refs/remotes refs/heads`), and identify the current branch/worktree. **Genuinely available:** locally yes, but only relative to possibly stale remote-tracking refs; whether another clone has consumed the commit is not knowable pre-execution. **Noise:** 7 amend events among 1,482 current-worktree HEAD-reflog entries (0.47%); the hazardous published subset was not measured. **Source classification:** named sk-git rule, NEVER #10. **Confidence:** confirmed for the rule, available local state, and repository count; inferred for publication completeness. [SOURCE: .opencode/skills/sk-git/SKILL.md:492-493] [SOURCE: bounded command evidence: `git reflog --format=%gs HEAD`]

4. **Rebasing published/shared history — stateful advisory, not a generic rebase warning.** **Operation:** `git rebase ...`, `git pull --rebase ...`, or `git pull ...` when `pull.rebase=true`; include an autostash dimension when `--autostash`, `rebase.autoStash=true`, or `merge.autoStash=true` applies. **Pre-execution state:** current branch/detachment, remote-tracking refs containing the commits to rewrite, ahead/behind counts, dirty-path count, unmerged entries, and relevant Git config. **Genuinely available:** yes locally before execution; remote freshness and concurrent consumers remain unknown. **Noise:** 44 rebase events among 1,482 HEAD-reflog entries (2.97%); an unconditional rebase warning would therefore be materially noisier than a published-history-only predicate. The exact autostash subset was not measured because reflogs omit flags/config. **Source classification:** named sk-git rules NEVER #8 and ALWAYS #14; it extends, rather than restates, the briefing incident by gating on publication state as well as dirty-tree/autostash risk. **Confidence:** confirmed for local state and measured broad rate; inferred for the final combined predicate. [SOURCE: .opencode/skills/sk-git/SKILL.md:325-327] [SOURCE: .opencode/skills/sk-git/SKILL.md:491-493] [SOURCE: bounded command evidence: `git reflog --format=%gs HEAD`]

5. **Discarding worktree/index content — stateful advisory across four exact shapes.** **Operation:** `git reset --hard [<tree-ish>]`, `git clean -f|-fd|-fdx [-- <pathspec>...]`, `git checkout -- <pathspec>...`, or `git restore --worktree [--source=<tree-ish>] [-- <pathspec>...]`. **Pre-execution state:** pathspec-resolved tracked modifications, staged changes that `reset --hard` would replace, matching untracked/ignored paths for `clean`, and unmerged entries. **Genuinely available:** yes via read-only diffs/status plus Git's own pathspec semantics before execution; exact shell-expanded paths must be parsed first. **Noise:** the reflog contains 201 reset events (13.56%), but does not record reset mode, so 13.56% is only a broad upper bound; `clean`, path checkout, and restore frequency were not measured. A warning on every `reset` is ruled out; warn only when the exact command would intersect nonempty at-risk state. **Source classification:** new, justified by immediate loss of uncommitted content and by the high measured noise of the broad family. **Confidence:** confirmed for the broad reset count; inferred for the proposed path-impact predicate. [SOURCE: bounded command evidence: `git reflog --format=%gs HEAD`] [INFERENCE: exact at-risk paths can be computed from pre-command index/worktree state, while reset flags are absent from reflog evidence]

6. **Deleting a local branch with unmerged commits — stateful advisory.** **Operation:** `git branch -D <branch>...` (not ordinary `-d`, whose merged check is already a Git safety gate). **Pre-execution state:** whether each named branch is checked out in any registered worktree, its configured upstream, and commits unique relative to upstream and the live integration tip. **Genuinely available:** yes locally before execution; absence of a remote branch does not prove no other clone has the commits. **Noise:** not measured because branch deletion argv is not retained in HEAD reflog/history. **Source classification:** new with justification, derived from ALWAYS #17's required worktree-before-branch order and its proof-before-reap model. **Confidence:** inferred; the source confirms the ordering and safety model, not a current advisory. [SOURCE: .opencode/skills/sk-git/SKILL.md:329-330] [INFERENCE: `-D` bypasses the merged-branch protection that makes ordinary `-d` lower risk]

7. **Forced worktree removal — stateful advisory.** **Operation:** `git worktree remove --force <path>` or `git worktree remove -f <path>`. **Pre-execution state:** target registration, cleanliness from `git -C <path> status --porcelain`, branch merge status against the actual live integration tip, lock state, and the wrapper-session marker/PID when present. **Genuinely available:** yes if the target path and common Git directory remain readable; a missing/unreadable activity marker must remain unknown, not be interpreted as inactive. **Noise:** not measured; Git history does not retain worktree-removal commands. **Source classification:** named sk-git rule ALWAYS #17, which explicitly requires clean, merged, proven-inactive state for automatic removal and otherwise report-only behavior. **Confidence:** confirmed. [SOURCE: .opencode/skills/sk-git/SKILL.md:329-330]

8. **Force-updating or deleting remote branches — command plus local/remote state, with enforcement de-duplication.** **Operation:** `git push [<remote>] --force|--force-with-lease [<refspec>...]`, leading-`+` refspecs, `git push <remote> --delete <branch>...`, or deletion refspecs such as `:<dst>`. **Pre-execution state:** parsed destination refs, resolved remote URL, local expected old SHA/lease, local remote-tracking SHA, allowlist, and whether the destination is `main`/`master`/a protected integration branch. **Genuinely available:** local state yes; authoritative remote tip and server protection require a network read and can race after the check, so they are only partially available. **Noise:** not measured because push argv and rejected pushes do not enter reflogs. **Source classification:** named sk-git rules NEVER #1 and ESCALATE #4 for protected force-push; remote deletion is new with justification. The existing pre-push hook already enforces naming and permission for branch refs, so a new advisory should not duplicate those messages; it should target force/delete semantics the hook does not inspect. **Confidence:** confirmed for current hook coverage and gap; inferred for remote race handling. [SOURCE: .opencode/skills/sk-git/SKILL.md:482-500] [SOURCE: .opencode/scripts/git-hooks/pre-push:77-159]

9. **Rewriting or deleting release tags — command plus partially remote state.** **Operation:** `git tag -f <tag> [<object>]`, `git tag -d <tag>...`, `git push <remote> --force refs/tags/<tag>`, or `git push <remote> :refs/tags/<tag>`. **Pre-execution state:** whether the local tag exists, annotated/lightweight type, target object, version-like naming, and any locally known remote tag; authoritative remote existence requires `git ls-remote --tags` and can race. **Genuinely available:** local state yes, remote state only partially. **Noise:** not measured. **Source classification:** new with justification: rewriting a release identity is high cost, and current pre-push explicitly skips tags and other non-branch refs. **Confidence:** confirmed for the enforcement gap; inferred for a version-tag-only advisory threshold. [SOURCE: .opencode/scripts/git-hooks/pre-push:77-88] [INFERENCE: limiting the predicate to an existing version-like tag avoids warning on normal first-time tag creation]

10. **Destroying stash/recovery pointers — stateful advisory only when recovery state is implicated.** **Operation:** `git stash clear`, `git stash drop [<stash>]`, `git reflog expire ... refs/stash`, or an immediate-prune operation while stash/autostash recovery pointers exist. **Pre-execution state:** stash entries and messages, `MERGE_AUTOSTASH`/autostash refs, `refs/autostash-rescue/*`, unmerged index state, and whether the selected commit is reachable from another durable ref. **Genuinely available:** yes before deletion/pruning while the refs still exist. **Noise:** fire frequency not measured; this checkout currently has 20 stash entries, which demonstrates nonempty state but is not an invocation-rate denominator. **Source classification:** named sk-git rule ALWAYS #14 for autostash orphan risk, extended to the exact destructive follow-on commands. **Confidence:** confirmed for named risk and current stash count; inferred for reachability-based suppression. [SOURCE: .opencode/skills/sk-git/SKILL.md:325-327] [SOURCE: bounded command evidence: `git stash list`]

11. **Implicit broad staging by commit — stateful advisory.** **Operation:** `git commit -a|--all ...`. **Pre-execution state:** already-staged paths, modified/deleted tracked paths that `-a` would add, total path count, and top-level ownership spread. **Genuinely available:** yes for the resulting pre-hook index candidate, but whether a path belongs to another session is not encoded in Git and therefore cannot be confirmed. **Noise:** exact `-a` use was not measured; 1,090/1,482 reflog entries (73.55%) are commits, so generic commit warnings are categorically too noisy. **Source classification:** new extension of named scoped-staging discipline and the broad-add incident; it goes beyond `git add <dir>` because `commit -a` performs its own broad tracked-file staging. **Confidence:** confirmed for the available Git sets and broad commit rate; inferred for any ownership/top-level heuristic. [SOURCE: .opencode/skills/sk-git/references/commit-workflows.md:215-248] [SOURCE: bounded command evidence: `git reflog --format=%gs HEAD`]

12. **Repository-wide history rewrite or immediate object pruning — command plus recovery-state advisory.** **Operation:** `git filter-branch ...`, `git filter-repo ...`, `git reflog expire --expire=now --all`, `git gc --prune=now`, or `git prune --expire=now`. **Pre-execution state:** clean/dirty status, current refs and worktrees, stash/recovery refs, remote-tracking refs, and objects reachable only through reflogs or rescue refs. **Genuinely available:** most local state is available before execution, although exhaustively proving external consumers or remote recoverability is impossible. **Noise:** not measured; these argv are not retained in normal Git history. **Source classification:** new with justification: these are explicit, rare operations capable of removing the recovery path for rewritten or orphaned commits, including the autostash-loss scenario named by ALWAYS #14. **Confidence:** inferred for advisory design; confirmed only that the named source treats stash drop/clear/GC as the permanent-loss boundary. [SOURCE: .opencode/skills/sk-git/SKILL.md:325-327] [INFERENCE: explicit immediate-expiry/prune tokens are quieter classifiers than warning on routine `git gc`]

## Command/State Boundary and Noise Threshold

- **Command-only predicates reliable enough for the current evaluator:** direct branch-creation shapes and direct `--no-verify`; explicit destructive tokens such as `--hard`, `--force`, `-D`, `--prune=now`, and deletion refspecs are also command-classifiable, but should usually be combined with state to avoid noise. The checker already demonstrates exact-regex, fail-open command predicates, but has no repository-state argument. [SOURCE: .opencode/skills/cli-external-orchestration/cli-opencode/scripts/lib/dispatch-rule-checks.mjs:71-96] [SOURCE: .opencode/skills/cli-external-orchestration/cli-opencode/scripts/lib/dispatch-rule-checks.mjs:105-125]
- **Stateful predicates genuinely available pre-execution:** current worktree/index/status, config, local refs, registered worktrees, local remote-tracking refs, remotes, and active Git-operation marker refs/files. Network-backed remote state is only a snapshot and is raceable. Operator intent, path ownership by another session, and what another clone has fetched are not Git state. [INFERENCE: based on the local-state fields required by Findings 3-12 and the pre-push hook's distinction between local input refs and remote SHA input at execution time]
- **Provisional noise line:** unconditional advisories are defensible only for explicit opt-out or destructive-intent shapes that are expected to be rare. Any broad family at or above roughly 1% of observed Git transitions should be state-gated; the sample places amend at 0.47%, rebase at 2.97%, reset at 13.56%, and commit at 73.55%. A practical initial budget is **under 1 advisory per 100 Git mutations per rule and under 3 per 100 in aggregate**, but this is inferred, not validated: the repository lacks a Bash-hook invocation log, so reflog rates are prevalence ceilings rather than true advisory fire rates. [SOURCE: bounded command evidence: `git reflog --format=%gs HEAD`] [INFERENCE: attention cost rises when generic rebase/reset/commit warnings repeatedly fire without confirmed hazardous state]

## Impossible Post-Execution-Only Checks

1. **Do not promise to predict merge/rebase/cherry-pick conflicts or successful autostash reapplication.** Pre-state can identify risk (dirty paths, merge bases, config), but the authoritative conflict/result state is created by execution and hooks. [SOURCE: .opencode/skills/sk-git/SKILL.md:325-327]
2. **Do not treat push success, HTTP 403, branch-protection acceptance, or authorization as preflight facts.** Active account/remote owner and local refs are clues; server policy, collaborator rights, concurrent remote updates, and network outcome are decided remotely. [SOURCE: .opencode/skills/sk-git/SKILL.md:495-501]
3. **Do not claim the exact final commit tree from `git commit --only <paths>` before hooks run.** The current index/worktree and a dry-run can expose likely omissions, but pre-commit hooks can inspect or mutate state, and the actual commit object does not exist yet. [SOURCE: .opencode/scripts/git-hooks/pre-commit:46-118] [INFERENCE: post-hook commit contents are not identical to a guaranteed pre-hook snapshot]
4. **Do not infer actual command options from Git history.** Reflog records outcomes such as `reset`, `rebase`, and `commit (amend)`, not the complete argv, so it cannot distinguish `reset --hard` from safer reset modes or count `--no-verify`, `commit -a`, force-push, branch deletion, or worktree removal. [SOURCE: bounded command evidence: `git reflog --format=%gs HEAD`]

## Ruled Out

- Unconditional warnings for every `git commit`, `git reset`, `git rebase`, `git pull`, or `git push`: measured broad-family rates and existing enforcement make these attention-consuming rather than protective.
- A second advisory for non-allowlisted push permission or new-branch naming: the pre-push hook already blocks and gives an exact retry; only force/delete/tag semantics are uncovered.
- Using `git log` or reflog as exact shell-command telemetry: neither preserves full argv or failed commands.
- Treating a successful preflight remote query as authoritative through execution: remote state can change between check and push.

## Dead Ends

- Exact historical fire rates for option-sensitive predicates cannot be recovered from ordinary Git history. The reducer should preserve this as negative knowledge; future noise calibration needs opt-in PreToolUse telemetry that records only normalized operation class and whether the state predicate matched, not raw commands.

## Edge Cases

- Ambiguous input: the scope could include Git aliases and arbitrary scripts; this iteration chose direct shell-visible `git`/`git -C` invocations because they are the narrowest reliably classifiable surface. Alias/script expansion is deferred.
- Contradictory evidence: none.
- Missing dependencies: no Bash-hook invocation telemetry exists, so exact advisory noise was unavailable; bounded HEAD reflog and repository counts were used only as explicit upper bounds/proxies.
- Partial success: none; the operation/state inventory was completed, while exact noise calibration remains a later question.

## Reflection

- What worked and why: pairing exact sk-git rules and hook coverage with a bounded 1,482-entry HEAD-reflog sample separated command risk from alert frequency and exposed where existing enforcement already owns the outcome.
- What did not work and why: Git history cannot recover option-sensitive invocation frequency or failed commands because it stores resulting ref actions, not shell argv.
- What I would do differently: instrument a privacy-preserving dry-run classifier over future PreToolUse events, recording normalized family and predicate match only, to replace reflog proxies with actual fire-rate denominators.

## Recommended Next Focus

Design and test bounded read-only state probes for the highest-value stateful candidates—published-HEAD amend/rebase, destructive path overwrite, forced worktree/branch deletion, and remote/tag force/delete—then estimate their actual match rate against sampled present repository states without implementing the hook.
