# Iteration 2: Destructive History and Recovery Operations

## Focus

Validate or reject iteration 1's destructive-history candidates using exact direct-Git shapes, bounded read-only probes, current repository measurements, Git's built-in safety gates, and existing sk-git hooks. The narrow interpretation is a preflight advisory for direct shell-visible commands; aliases and opaque scripts remain outside reliable classification. Probes run only after an exact destructive token matches, and positive local evidence is treated as evidence—not as proof that remotes or concurrent worktrees cannot change before execution.

## Findings

1. **Published amend remains a high-value, positive-evidence advisory.** **Operation:** `git commit ... --amend ...`, including `git commit --amend --no-edit`; ordinary commits and `--fixup=amend:*` are not the same operation. **Specific pre-execution state/probe:** resolve `HEAD`, then run `git for-each-ref --contains=HEAD` over `refs/remotes` and other local integration refs, excluding only the current branch itself. The current `HEAD` (`b1024adc...`) is contained by `refs/remotes/origin/skilled/v4.0.0.0`, so the predicate would match now. **Genuinely available:** positive local containment is available before execution; a missing match is only unknown because remote-tracking refs may be stale and another clone's consumption is unknowable. **Noise:** 7 amend outcomes among 1,486 HEAD-reflog entries (0.47%); the published subset is not measurable from reflog argv and must remain explicitly unmeasured. **Source classification:** named sk-git NEVER #10. **Confidence/decision:** confirmed for command shape, named rule, local positive state, and broad rate; inferred for completeness of “published.” Validate the candidate only on positive containment, never as an unconditional commit warning. **Race window:** a remote or local ref can move after the probe. [SOURCE: .opencode/skills/sk-git/SKILL.md:491-493] [SOURCE: bounded Git evidence: `git for-each-ref --format=%(refname) --contains=HEAD refs/remotes refs/heads`; `git reflog --format=%gs HEAD`; `git commit -h`]

2. **Published rebase is probeable for explicit rewrite sets, but `pull --rebase` cannot be predicted exactly before its internal fetch.** **Operation:** `git rebase [--onto <newbase>] <upstream> [<branch>]` after excluding recovery/control forms such as `--abort`, `--continue`, `--skip`, `--quit`, and `--show-current-patch`; also `git pull --rebase` or config-induced pull-rebase. **Specific pre-execution state/probe:** for an explicit rebase, derive the commits to replay from the parsed upstream/fork point and intersect them with commits reachable from `refs/remotes`; separately read dirty tracked state and `rebase.autoStash`/`pull.rebase`. **Genuinely available:** the explicit local rewrite set is available; for `pull --rebase`, the command's fetch can change the upstream after PreToolUse, so only already-known publication and dirty/autostash risk are available. **Noise:** 44 rebase outcomes among 1,486 reflog entries (2.96%); the published subset and option/config subsets are not measured. **Source classification:** named sk-git NEVER #8 and ALWAYS #14. **Confidence/decision:** confirmed for the rule, local inputs, installed `--autostash` behavior, and broad rate; inferred for the final intersection predicate. Validate state-gated explicit rebase, reject generic rebase warnings—especially warnings on recovery forms. **Race window:** refs and the worktree can change; `pull --rebase` adds an unavoidable fetch-to-rebase window. [SOURCE: .opencode/skills/sk-git/SKILL.md:326-328] [SOURCE: .opencode/skills/sk-git/SKILL.md:491-493] [SOURCE: bounded Git evidence: `git rebase -h`; `git reflog --format=%gs HEAD`]

3. **`reset --hard` needs two independent risk gates: uncommitted overwrite and branch-tip retreat.** **Operation:** `git reset --hard [<tree-ish>]`; do not match `git reset` in other modes. **Specific pre-execution state/probe:** resolve the target (default `HEAD`), use read-only diffs to test whether index/worktree content differs from it, inspect unmerged entries, and count commits in `<target>..HEAD` that lack another durable local/remote ref. The current tree has 44 tracked paths differing from `HEAD`, 0 staged paths, and 137 total status paths, so `git reset --hard HEAD` would match the content-loss gate now. **Genuinely available:** yes locally before execution, including the target's current object and current diffs; untracked paths are affected only in collision cases and must not be broadly claimed from status alone. **Noise:** 201 reset outcomes among 1,486 reflog entries (13.53%); mode-specific hard-reset frequency is not measured. **Source classification:** new, justified by immediate uncommitted-content loss and by sk-git ALWAYS #15's prohibition on resetting a dirty/concurrent primary tree. **Confidence/decision:** confirmed for installed `--hard` semantics and current counts; inferred for the durable-ref suppression. Validate only when either gate is nonempty; reject every-reset warnings. **Race window:** concurrent edits or ref movement after the diff can invalidate the snapshot. [SOURCE: .opencode/skills/sk-git/SKILL.md:327-327] [SOURCE: bounded Git evidence: `git reset -h`; `git status --porcelain=v1 --untracked-files=all`; `git diff --name-only HEAD --`; `git reflog --format=%gs HEAD`]

4. **`git clean` has an exact built-in preflight, so warnings should depend on its dry-run result.** **Operation:** destructive forms `git clean -f|-ff` with the same `-d`, `-x`/`-X`, exclusions, and pathspec as the proposed command; `git clean -n`/`--dry-run` is explicitly excluded. **Specific pre-execution state/probe:** replace destructive force with `-n` while preserving selection flags/pathspec and warn only if Git reports at least one removal. On the current repository, `git clean -nd` reports 84 candidates and `git clean -ndx` reports 611, showing why `-x` materially changes risk. **Genuinely available:** yes; Git itself applies ignore and pathspec semantics in the dry run. **Noise:** invocation frequency is not measured because command flags are absent from history; the present-state match is measured, not a historical fire rate. **Source classification:** new, justified by deletion of untracked/ignored content. **Confidence/decision:** confirmed. Validate `clean -f*` plus nonempty dry-run; eliminate no-force and dry-run forms because Git's force requirement or read-only mode already protects them. **Race window:** untracked files can appear or disappear between dry run and execution. [SOURCE: bounded Git evidence: `git clean -h`; `git clean -nd`; `git clean -ndx`]

5. **Worktree restore is advisory-worthy only when it intersects an actual tracked delta; staged-only restore should remain silent.** **Operation:** `git restore [--worktree] [--source=<tree-ish>] -- <pathspec>...` and legacy `git checkout [<tree-ish>] -- <pathspec>...`; exclude branch checkout and `git restore --staged` without `--worktree`. **Specific pre-execution state/probe:** for default worktree restore, test unstaged deltas against the index for the exact pathspec; for `--source=<tree-ish>`, compare the selected paths against that source; if both `--staged --worktree` are present, include index differences. The current tree has 44 tracked paths differing from `HEAD`, so only matching pathspecs should trigger. **Genuinely available:** yes locally, but Git has no native restore dry-run, so the evaluator must faithfully preserve source and pathspec semantics. **Noise:** not measured; reflogs do not record path restores. **Source classification:** new, justified by silent overwrite of tracked worktree content. **Confidence/decision:** confirmed for installed restore modes and current delta; inferred for a parser-equivalent impact probe. Validate exact worktree-overwrite matches; eliminate staged-only unstage operations as recoverable routine use. **Race window:** edits after the diff can create a false negative. [SOURCE: bounded Git evidence: `git restore -h`; `git diff --name-only HEAD --`]

6. **Force branch deletion should warn only for non-checked-out branches with unique commits; Git already owns two safer cases.** **Operation:** `git branch -D <branch>...` or `git branch --delete --force <branch>...`; ordinary `-d` is excluded. **Specific pre-execution state/probe:** map checked-out branches with `git worktree list --porcelain`, resolve each target, and count commits not in the live primary `HEAD`, its upstream, or another durable ref. Current measurements: 46 local branches, 34 checked out, and 13 non-merged branches with commits absent from the primary `HEAD`. **Genuinely available:** yes locally. **Noise:** deletion invocation frequency is not measured. **Source classification:** named sk-git ALWAYS #17 plus a new unique-commit refinement; the discard workflow documents `-D` only after explicit confirmation. **Confidence/decision:** confirmed for `-d` versus `-D`, current branch/worktree state, and required cleanup ordering; inferred for which comparison refs represent all valuable integration tips. Validate `-D` only when an unoccupied target has unique commits. Eliminate ordinary `-d` because Git checks mergedness, and eliminate the checked-out-branch subcase because Git refuses deletion while a worktree owns it. **Race window:** a worktree may attach after the probe, but Git's execution-time refusal remains the final guard. [SOURCE: .opencode/skills/sk-git/SKILL.md:329-330] [SOURCE: .opencode/skills/sk-git/references/shared-patterns.md:197-201] [SOURCE: .opencode/skills/sk-git/references/finish-workflows.md:258-281] [SOURCE: bounded Git evidence: `git branch -h`; `git worktree list --porcelain`; `git merge-base --is-ancestor`; `git rev-list --count HEAD..<branch>`]

7. **Forced worktree removal is valuable only for dirty or positively active targets; routine cleanup and `worktree prune` should not warn.** **Operation:** `git worktree remove -f|--force <path>`; distinguish this from ordinary `git worktree remove <path>` and `git worktree prune`. **Specific pre-execution state/probe:** resolve the registered target, check tracked/untracked status, branch/detachment, merge relation to the primary checkout's live `HEAD`, lock state, and a wrapper-session marker with a live PID. Of 35 registered worktrees, 20 are dirty and 15 clean; one is detached. **Genuinely available:** cleanliness and registration are available; positive wrapper liveness is available when the marker is readable, while missing markers cannot prove inactivity. **Noise:** invocation frequency is not measured. **Source classification:** named sk-git ALWAYS #17. **Confidence/decision:** confirmed. Validate forced removal when the target is dirty or positively live. Eliminate ordinary dirty removal because Git requires force, ordinary clean removal because sk-git uses it as normal cleanup, and `git worktree prune` because it clears stale administration rather than deleting a present worktree. The existing reaper already restricts automatic removal to clean, merged, proven-inactive wrapper worktrees and reports all other lanes. **Race window:** status, PID liveness, and registration can change after the probe; a PID can also be reused. [SOURCE: .opencode/skills/sk-git/SKILL.md:329-330] [SOURCE: .opencode/bin/worktree-reaper.sh:64-88] [SOURCE: .opencode/bin/worktree-reaper.sh:136-186] [SOURCE: bounded Git evidence: `git worktree -h`; `git worktree list --porcelain`; per-worktree `git status --porcelain=v1`]

8. **Stash destruction is not generally protected by the autostash guard; gate it on the exact target's durable rescue.** **Operation:** `git stash drop [<stash>]` and `git stash clear`; exclude `stash apply`, and exclude `stash pop` because Git keeps the entry when application conflicts. **Specific pre-execution state/probe:** resolve the symbolic selector to a SHA immediately before execution, enumerate `refs/autostash-rescue/*` and other durable refs for that SHA, and for `clear` count unrescued entries. The repository has 20 stash entries, one autostash-rescue ref, and 0 current stash entries directly anchored by that rescue ref—20 current entries are unrescued by this mechanism. **Genuinely available:** yes before deletion, but `stash@{n}` is a moving selector under concurrent stash operations. **Noise:** command frequency is not measured; current exposure is measured. **Source classification:** named sk-git ALWAYS #14, extended to distinguish ordinary stash entries from guarded autostashes. **Confidence/decision:** confirmed for guard scope and current counts; inferred for suppression when another durable ref reaches the stash commit. Validate drop/clear when selected entries lack durable rescue; suppress or lower the advisory for a matching rescue ref to avoid duplicating the existing hook. **Race window:** another process can push/drop a stash and renumber selectors after the probe. [SOURCE: .opencode/skills/sk-git/SKILL.md:326-326] [SOURCE: .opencode/scripts/git-hooks/lib/autostash-orphan-guard.sh:14-43] [SOURCE: bounded Git evidence: `git stash -h`; `git stash list --format=%H`; `git for-each-ref refs/autostash-rescue`]

9. **Immediate reflog expiry has an exact dry-run and should warn about pointer loss, not claim immediate object deletion.** **Operation:** `git reflog expire --expire=now ...`, `--expire-unreachable=now`, especially with `--all`; ordinary expiry and `--dry-run` are excluded. **Specific pre-execution state/probe:** rerun the selected refs with `--dry-run --verbose` to count entries that Git would prune, and only after the exact token match optionally compare `git rev-list --reflog --all` with `git rev-list --all`. The current repository has 390 commits reachable through reflogs but not durable refs. **Genuinely available:** yes as a local snapshot. **Noise:** invocation frequency is not measured. **Source classification:** new, justified because immediate expiry destroys recovery pointers even though objects may survive until later pruning. **Confidence/decision:** confirmed for installed dry-run support and the 390-commit exposure; inferred for which reflog-only commits are operator-important. Validate immediate-expiry forms with nonempty dry-run; eliminate default expiry and dry-run invocations. **Race window:** refs and reflogs can change between probe and execution. [SOURCE: bounded Git evidence: `git reflog expire -h`; set difference of `git rev-list --reflog --all` and `git rev-list --all`]

10. **Immediate object pruning warrants a command-shape advisory; an expensive reachability scan cannot certify safety under concurrent writers.** **Operation:** `git gc --prune=now` and `git prune --expire=now`; exclude `git prune -n|--dry-run` and routine `git gc` when effective config does not make expiry immediate. **Specific pre-execution state/probe:** command tokens and effective `gc.pruneExpire` are the cheap gate; only after a match may `git prune -n --expire=now` estimate deletions. A broader read-only `git fsck --unreachable --no-reflogs` found 87,410 unreachable objects (including 1,627 commits), but that is an exposure indicator—not the exact set either command will delete. No local `gc.pruneExpire` override is configured. **Genuinely available:** current object/config state is available, but no preflight can prove another Git process will not create an object after the check. **Noise:** invocation frequency is not measured. **Source classification:** new, justified by collapsing the recovery window after rewrites, stash loss, or ref deletion. **Confidence/decision:** confirmed for installed immediate-prune options, config absence, and measured exposure; inferred for concurrency consequences and actual deletion set. Validate explicit/effective immediate pruning; eliminate ordinary GC/prune and all dry runs. Coalesce a chained immediate reflog-expire plus prune into one advisory. **Race window:** unavoidable object-writer TOCTOU makes “safe now” an invalid guarantee. [SOURCE: bounded Git evidence: `git gc -h`; `git prune -h`; `git config --show-origin --get-all gc.pruneExpire`; `git fsck --unreachable --no-reflogs`]

## Cheap Probe Ordering

1. Parse only direct `git`/`git -C` commands and exact destructive tokens; reject continuation, dry-run, and safer-mode shapes before repository reads. [INFERENCE: based on the eliminated command shapes in Findings 2, 4, 5, 6, 7, 9, and 10]
2. Prefer boolean/short-circuit probes: `rev-parse`, `diff --quiet`, `diff --cached --quiet`, `for-each-ref --contains`, `worktree list --porcelain`, and the selected command's native dry-run. [INFERENCE: based on the bounded probes validated in Findings 1-9]
3. Run path enumeration, rewrite-set intersections, reflog set differences, `prune -n`, or `fsck` only after an exact rare command match; `fsck` is too broad for routine per-command use. [SOURCE: bounded Git evidence: the repository scan traversed 87,410 unreachable objects]
4. Emit one line per command, coalescing overlapping causes such as dirty tree plus branch retreat or immediate reflog expiry plus prune. [INFERENCE: based on the briefing's attention-budget requirement and overlapping predicates above]

## Ruled Out

- Generic `rebase`, `reset`, `restore`, `clean`, branch-delete, worktree-cleanup, reflog, or GC warnings; each family has routine/recovery forms that must remain quiet.
- Rebase control forms (`--abort`, `--continue`, `--skip`, `--quit`) because a warning would obstruct recovery rather than prevent loss.
- `git clean` without force and every clean dry-run because Git's own force gate/read-only mode already protects them.
- `git restore --staged` without `--worktree` because it unstages rather than destroys the working copy.
- Ordinary `git branch -d` and deletion of a checked-out branch because Git already enforces mergedness/worktree ownership; only unoccupied unique-commit `-D` remains.
- Ordinary dirty `git worktree remove`, clean routine removal, and `git worktree prune`; Git or the existing conservative reaper already owns those safety decisions.
- `git stash apply`, conflicted `stash pop`, guarded autostashes with a matching rescue ref, default reflog expiry, routine `git gc`, and all dry-run prune forms.

## Dead Ends

- Ordinary Git history still cannot measure option-sensitive invocation frequency, failed destructive commands, or the final state-gated advisory rate. This approach remains exhausted; future calibration requires privacy-preserving normalized PreToolUse telemetry rather than another reflog pass.
- Remote-tracking containment can confirm locally known publication but cannot prove non-publication. Network reads would still be snapshots and would introduce latency plus a second race, so absence must remain unknown rather than “safe.”

## Edge Cases

- Ambiguous input: “published” can mean remote-tracking containment, another local integration ref, or actual consumption by another clone. This iteration uses positive local containment as the narrow preflight predicate and defers unknowable external consumption.
- Contradictory evidence: the discard workflow permits `git branch -D` after exact `discard` confirmation, while ALWAYS #17 mandates worktree-before-branch cleanup. These are compatible only when the target branch is no longer checked out; the advisory should report unique commits, while Git's checked-out-branch refusal remains authoritative. [SOURCE: .opencode/skills/sk-git/references/finish-workflows.md:258-281] [SOURCE: .opencode/skills/sk-git/SKILL.md:329-329]
- Missing dependencies: exact Bash invocation telemetry does not exist. Current-state measurements and broad reflog rates were used only where labeled; option-specific noise remains explicitly unmeasured.
- Partial success: none. The destructive subset has actionable probes and eliminations, while whole-system noise calibration remains open.

## Reflection

- What worked and why: exact installed-Git help plus current-state probes separated dangerous intent from commands whose safer forms are already protected, and quantified real exposure without executing mutations.
- What did not work and why: reflog/history cannot recover flags, pathspecs, failed commands, or state-predicate matches; repeating broad rate measurement added only denominator drift.
- What I would do differently: benchmark latency and false-positive rate of the retained probes against normalized future PreToolUse telemetry, especially worktree-wide status and reflog/prune scans.
