# /create:diagram Presentation Contract

This file is the single source of truth for user-facing presentation in `/create:diagram`: startup questions, setup/status dashboards, and result display. The command router owns asset routing only. The workflow YAML owns execution behavior.

## 1. Phase 0 Verification Display

Run this automatic self-check before setup. This is not a user question.

```text
SELF-CHECK: Are create-diagram packet resources available?

Indicators:
- `.opencode/skills/sk-doc/sk-create-diagram/SKILL.md` is readable
- `.opencode/skills/sk-doc/sk-create-diagram/references/foundations/style-guide.md` is readable
- `.opencode/skills/sk-doc/sk-create-diagram/references/types/type-*.md` pattern references are available
- `.opencode/skills/sk-doc/sk-create-diagram/scripts/drawio_extract.py` and `scripts/mermaid_extract.py` exist

If all indicators are present:
- create_diagram_verified = true
- Continue to setup

If any indicator is missing or uncertain:
- Stop before loading workflow YAML
- Display the hard-block message below
```

Hard-block message:

```text
CREATE-DIAGRAM RESOURCES REQUIRED

This command requires the create-diagram packet for:
- The shared editorial design system, complexity budget, and taste gate
- Per-type layout conventions (27 diagram types)
- draw.io and Mermaid extraction for redraw requests

Required references:
.opencode/skills/sk-doc/sk-create-diagram/references/foundations/style-guide.md
.opencode/skills/sk-doc/sk-create-diagram/references/types/type-<name>.md

STATUS=FAIL ERROR="create-diagram resources unavailable"
```

## 2. Auto Setup Resolution

For `:auto`, resolve setup using the system auto-mode contract, then load `create-diagram-auto.yaml` only when every required field is available.

Resolution tiers:

| Tier | Use When | Output |
| --- | --- | --- |
| Tier 1 | `$ARGUMENTS`, flags, pre-bound answers, and defaults resolve all required fields | Persist config and load auto workflow |
| Tier 2 | One or two required fields remain genuinely ambiguous | Ask one narrow question per missing field |
| Tier 3 | Required fields remain unresolved | Emit missing-inputs error and do not load YAML |

Pre-bound setup schema:

```yaml
PRE-BOUND SETUP ANSWERS:
  request_shape: generate
  target_diagram_path: docs/diagrams/example-architecture.html
  source_content: Describe the system, process, or data model to diagram.
  diagram_type: architecture
  import_source_path: ""
  export_format: ""
  execution_mode: AUTONOMOUS
```

Default resolution table:

| Field | Required | Resolves Via | Default | Tier-2 Candidate |
| --- | --- | --- | --- | --- |
| `request_shape` | Yes | marker `request_shape`, a `--import` flag or `.drawio`/`.mmd`/`.mermaid` source (implies `import`), an `export`/`png`/`svg`/`rasterize` keyword against an existing diagram (implies `export`), otherwise `generate` | derive when confidence >=80% | Yes, when ambiguous |
| `target_diagram_path` | Conditional | Positional `.html` path or marker `target_diagram_path` (required when `request_shape=generate` or `import`) | none | Yes, when missing |
| `source_content` | Conditional | Remaining positional text, prompt-body source, or marker `source_content` (required when `request_shape=generate`) | none | Yes, when missing |
| `diagram_type` | Conditional | `--type` flag, marker `diagram_type`, or derived from `source_content` against the 27-type selection guide (required when `request_shape=generate`) | derive when confidence >=80% | Yes, when ambiguous |
| `import_source_path` | Conditional | `--import` flag or marker `import_source_path` (required when `request_shape=import`) | none | Yes, when missing |
| `export_format` | Conditional | `--format` flag or marker `export_format` (required when `request_shape=export`; `png`, `svg`, or `html+png`) | none | Yes, when missing |
| `execution_mode` | Yes | `:auto`, `:confirm`, or marker `execution_mode` | `AUTONOMOUS` under `:auto` | No |

## 3. Consolidated Startup Prompt

Ask one prompt containing only applicable questions. Do not split these questions across turns.

```text
Before proceeding, please answer:

Q0. Request Shape (if not clear)
A) Generate a new diagram from a description
B) Import and redraw an existing .drawio or Mermaid source
C) Export an already-generated diagram to PNG/SVG

Q1. Target Diagram Path (if not provided, for generate or import)
Where should the self-contained HTML file be created?
Format: workspace-relative `.html` path, for example docs/diagrams/architecture.html.

Q2. Source Content or Import Path (if not provided)
For generate: what should the diagram show — components, process steps, entities, or events?
For import: the workspace-relative path to the `.drawio`, `.drawio.png`, `.drawio.svg`, `.mmd`, `.mermaid`, or Markdown-with-fenced-Mermaid source.

Q3. Diagram Type (if not clear, generate only)
One of: architecture, IT current-state, flowchart, sequence, state machine, ER/data model, timeline, swimlane, quadrant, radar, loop, nested, tree, org chart, layer stack, venn, pyramid/funnel, bar, line, Gantt, scatter, high-level, process, medallion, data flow, DP integration, DP security matrix.

Q4. Execution Mode (if no :auto/:confirm suffix)
A) Interactive - confirm at each step
B) Autonomous - execute without prompts

Reply with answers, for example: A, docs/diagrams/architecture.html, "frontend, backend, database, Redis cache", architecture, B
```

Hard stops:

- Do not proceed until all applicable questions are answered.
- Do not generate a diagram without an explicit target path and source content.
- Do not redraw an import source without an explicit source path.
- Do not auto-select execution mode without suffix or explicit choice.
- Do not infer diagram content from context, screenshots, or conversation history.

## 4. Setup Dashboard

After parsing setup, display or maintain this dashboard internally before loading YAML.

| Field | Required | Value | Source |
| --- | --- | --- | --- |
| `create_diagram_verified` | Yes | `[value]` | Phase 0 self-check |
| `request_shape` | Yes | `[value]` | Q0, derived shape, or pre-bound marker |
| `target_diagram_path` | Conditional | `[value]` | Q1 or `$ARGUMENTS` (generate/import) |
| `source_content` | Conditional | `[value]` | Q2 (generate) |
| `diagram_type` | Conditional | `[value]` | Q3, derived type, or `--type` (generate) |
| `import_source_path` | Conditional | `[value]` | Q2 or `--import` (import) |
| `export_format` | Conditional | `[value]` | `--format` (export) |
| `execution_mode` | Yes | `[value]` | Suffix or Q4 |

Proceed only when every required field (and every conditional field the resolved shape makes required) has a value.
