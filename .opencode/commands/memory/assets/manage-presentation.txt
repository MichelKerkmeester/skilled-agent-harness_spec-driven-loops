# Memory Manage Presentation Contract — RETIRING

`/memory:manage` is retiring. The indexed-continuity database it administered is being
decommissioned, so every dashboard, confirmation gate and result envelope this contract once
defined described a store that no longer answers. Enumerating them here as live render shapes
would be a false promise, so they are gone rather than kept as decoration.

This asset now defines exactly one display: the retiring notice.

## 1. General Display Rules

- Render the notice below and stop. There is no mode to route, no confirmation to gate and no
  result to envelope.
- Use a single `STATUS=` line.
- Never suggest raw SQL recovery, and never offer to reach the retired store by another route.

## 2. Retiring Notice Display

```text
MEMORY:MANAGE
--------------------------------------------------
RETIRING     The indexed-continuity database is being decommissioned.
Removed by   phase 003 of the memory decommission

Instead
  /memory:search                find a phrase in spec docs and skill docs
  /memory:save                  write session context into a packet
  /speckit:resume               recover a session and get one next step
  /doctor memory                check the trigger index and the retrieval conventions

Trigger-index maintenance
  node .opencode/skills/system-spec-kit/scripts/retrieval/generate-trigger-index.mjs

STATUS=OK ACTION=retiring
```

## 3. Former Subcommand Redirects

When the operator types a former subcommand, name its successor rather than failing silently.

| Former subcommand | Line to render under `Instead` |
| --- | --- |
| `stats`, `health`, `validate` | `/doctor memory` — index present, lookup runs, recipes resolve |
| `scan [--force]` | `node .opencode/skills/system-spec-kit/scripts/retrieval/generate-trigger-index.mjs` |
| `cleanup`, `retention-sweep`, `bulk-delete`, `delete` | No successor. Packet documents are the record and are managed as files |
| `learned-expire`, `learned-clear` | No successor. `trigger_phrases` is an author-controlled frontmatter field |
| `tier`, `triggers` | Edit the document's frontmatter, then rerun the generator |
| `checkpoint create/list/restore/delete` | Git. The packet documents are versioned files |
| `ingest start/status/cancel` | No successor. The generator reads frontmatter directly |
| `ledger-sweep` | No successor. The ledgers lived in the same database |

## 4. Capability Loss Wording

When the operator asks for something the retired store provided and nothing replaces, say so plainly
rather than substituting a keyword search:

```text
MEMORY:MANAGE
--------------------------------------------------
UNSUPPORTED  <capability>
Why          <what the retired mechanism did that text matching cannot>
Instead      <the nearest honest alternative, or "none">

STATUS=OK ACTION=unsupported
```

Semantic paraphrase, vector and BM25 fusion, decay, access tracking, session dedup and causal
traversal are unsupported. Retrieval is lexical: a phrase that is not written in the corpus is not
found, and a miss is reported as a miss.

## 5. Forbidden Vocabulary

Never render a dashboard, count, tier distribution, health verdict or checkpoint list. There is no
store behind them, and a rendered shape implies one exists.
