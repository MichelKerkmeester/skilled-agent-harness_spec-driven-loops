## 2. Auto Setup Resolution

For `:auto`, resolve setup from `$ARGUMENTS`, flags and any pre-bound answers, then load
`create-chart-auto.yaml` only when every required field has a value.

Resolution tiers:

| Tier | Use When | Output |
| --- | --- | --- |
| Tier 1 | `$ARGUMENTS`, flags, pre-bound answers and defaults resolve all required fields | Persist config and load the auto workflow |
| Tier 2 | One or two required fields remain genuinely ambiguous | Ask one narrow question per missing field |
| Tier 3 | Required fields remain unresolved | Emit the missing-inputs error and do not load YAML |

Pre-bound setup schema:

```yaml
PRE-BOUND SETUP ANSWERS:
  target_chart_path: docs/charts/where-the-budget-went.html
  reader_question: Where did the budget go across departments and teams
  chart_form: treemap
  chart_data: |
    Engineering/Platform 420000, Engineering/Product 310000, Sales/Field 180000
  colour_system: categorical
  execution_mode: AUTONOMOUS
```

Default resolution table:

| Field | Required | Resolves Via | Default | Tier-2 Candidate |
| --- | --- | --- | --- | --- |
| `target_chart_path` | Yes | Positional `.html` path or marker `target_chart_path` | none | Yes, when missing |
| `reader_question` | Yes | Remaining positional text, prompt body or marker `reader_question` | none | Yes, when missing |
| `chart_form` | Yes | `--form` flag, marker `chart_form`, or resolved from `reader_question` against the catalog index | resolve when confidence is 80% or better | Yes, when two rows tie |
| `chart_data` | Yes | Prompt body, an attached file named in `$ARGUMENTS`, or marker `chart_data` | none | Yes, when missing |
| `colour_system` | Yes | `--system` flag or marker `colour_system` | `neutral` | No |
| `execution_mode` | Yes | `:auto`, `:confirm`, or marker `execution_mode` | `AUTONOMOUS` under `:auto` | No |

`neutral` is the default because it is the fallback the colour document names, and a
system is left only when the data plainly carries the property another system encodes.

## 3. Consolidated Startup Prompt

Ask one prompt holding only the questions that are still open. Do not split them across
turns.

```text
Before proceeding, please answer:

Q1. Target Path (if not provided)
Where should the chart be written?
Format: a workspace-relative `.html` path.

Q2. The Reader's Question (if not provided)
What comparison does the reader need to make? Write it the way they would say it,
not as a chart name. "Which depot is slowest" rather than "a bar chart".

Q3. The Data (if not provided)
Paste the values, or name the file that holds them. Every value the chart displays
is typed into the file, so a chart cannot be built from a description of the data.

Q4. Chart Form (only when two catalog rows answer the question equally well)
Name the row to draw, or say which of the two offered rows matches the data you hold.

Q5. Colour System (if a system other than the default is wanted)
A) neutral (default, ranks by lightness)
B) ordered (the data has a position on a scale)
C) categorical (four or fewer unordered categories)

Q6. Execution Mode (if no :auto/:confirm suffix)
A) Interactive, confirm at each step
B) Autonomous, execute without prompts

Reply with answers, for example: docs/charts/pick-times.html, "which depot is slowest",
<pasted values>, bar-rows, A, B
```

Hard stops:

- Do not proceed until every applicable question is answered.
- Do not invent values. A chart drawn from numbers nobody supplied is a fabrication.
- Do not pick a chart form from the reader's vocabulary alone. The question picks the row.
- Do not auto-select an execution mode without a suffix or an explicit choice.
- Do not infer the data from context, screenshots or conversation history.

## 5. Catalog Resolution Report

Show which row answers the question, and how it was reached.

```text
  Question : {reader_question}
  Family   : {family}
  Form     : {chart_form}   ({data shape from the catalog row})
  Source   : {index row | reader-name table | offered pair, operator chose}
```

When the reader's word is not an index id, say which table answered it. `heatmap`,
`donut chart`, `histogram`, `waffle chart`, `parallel coordinates`, `combo chart` and
`calendar heatmap` all resolve through the reader-name table, and two of those seven are
substitutions rather than matches. Say which one the reader is getting and why.

## 6. Checkpoint Display (:confirm)

```text
Step {n}/7 — {step_name}
  {what this step produced}

A) approve   B) review   C) modify   D) abort
```

A reported gap is not a checkpoint. When no row answers the question the run ends and is
reported, never offered for approval.

```text
STATUS=OK PATH={target_chart_path}
```

## 8. Gap Output

```text
No Form For This Question

Question : {reader_question}
Checked  : the catalog index and the reader-name table

The corpus draws no form that answers this. Reporting the gap is the designed outcome.
Sending a reader to a chart that answers a different question costs more than saying so.

Closest rows considered: {row} ({why it answers a different question})

STATUS=OK ACTION=gap-reported QUESTION="{reader_question}"
```
