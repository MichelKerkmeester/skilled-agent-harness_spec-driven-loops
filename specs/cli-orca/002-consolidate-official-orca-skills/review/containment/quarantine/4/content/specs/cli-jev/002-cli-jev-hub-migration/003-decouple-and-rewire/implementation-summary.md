## What Was Built

The repository now has one home for the transport and no stale path to it. `cli-external-orchestration` is back to seven `packetKind: "workflow"` modes with no extension, no `cli-jev` router signal and no axis, while the packet answers from `.skilled/skills/cli-jev/cli-usage/`. The dispatch chain reads that location: a live preflight of `jev run @request.json --value` is refused with the packet's own `[jev-value-not-with-run]` rule text, which is the same command that was approved while the rules failed open. Every roster, both hook suites and every generated surface name the new home, and the hub's own release line starts at `0.1.0.0`.

### Phase 3: decouple-and-rewire

The decoupling landed while this phase was being planned: a parallel writer committed `e66dccd6a2`, which removed the old hub's mode row, `transport-axis` extension, router signal, vocabulary classes, `tieBreak` entry, leaf entry and prose traces. This phase verified that work rather than repeating it, then executed the half that was still wired to the retired path.

## How It Was Delivered

Five passes, each gated before the next. First the landed decoupling was read back from disk — registry, router, `tieBreak`, prose — and attributed to commit `e66dccd6a2`, so nothing was redone and nothing was reverted. Second the enforcement hole was closed: the audit row moved, both suites were updated and run under their own runners, and the same preflight call that phase 002 recorded as approved was replayed and refused. Third the rosters moved together, each through the contract that owns it — canonical `.skilled` edit, the same body in the `.claude` twin, then the two generators, which wrote two files each and left the other ten byte-identical. Fourth the hub's release line was reset to `0.1.0.0` by operator direction, with the changelog renamed by `git mv` so the history stays attached, and the old hub's last stale prose claims were fixed and its manifest re-minted. Fifth every generated surface was re-derived by its own writer, each delta measured before it was accepted.

<!-- ANCHOR:decisions -->
## Key Decisions

| Decision | Why |
|----------|-----|
| Verify the parallel writer's decoupling instead of repeating it | Their commit had already landed the registry, router and prose half; redoing it would have fought a writer on the same files, and reverting it was never this phase's call |
| Keep `skill: 'cli-jev'` and move only `packetPath` | The display name is what a request already names and what the playbook asserts; the path is what the guards join to find the packet `SKILL.md` |
| Run each hook suite under its own runner and scope the vitest filter | The audit suite imports vitest while the rule-checks suite uses `node:test`; the repository-root glob also collects the parallel writer's quarantined snapshot, which would have reported its own unresolvable paths as this change's failure |
| Regenerate the Pi tree even though it was already stale | The mirror contract requires regeneration as part of any roster edit, and the generator's own output bounded the delta to the two edited agents before it was accepted |
| Reset the hub's release line to `0.1.0.0` | Operator direction: the new hub starts its own line, while the transport's `1.x` history stays recorded in the mode's own changelog |
| Fix the old hub's residual prose and re-mint rather than leave it | Its `SKILL.md` still claimed one extension with an empty `transports`, and its `README.txt` still counted eight modes; leaving a false claim would have contradicted the changelog that says the traces were removed |
| Insert the description-cache rows through the targeted upsert | The library exposes a single-entry writer, so the new track's rows arrive without a whole-tree rescan that would have rewritten 3,900 unrelated rows |
| Leave the Hermes mirror, the sk-doc guard and the Pi suite's `cli-devin` case alone | Each has a cause this phase does not own; refreshing or fixing them would have hidden another writer's pending work or an unrelated pre-existing failure |

## Known Limitations

1. **The Hermes skill mirror is unrefreshed.** `sync-skills-hermes.cjs --check` reports eight drifted entries and one stale, five of them on skills this program never touched. The generator is a whole-tree walker with no scoping flag, so a refresh would absorb those unrelated drifts and delete the orphan; phase 002 recorded the same item and this phase leaves it to the operator.
2. **The sk-doc hub's compiled manifest is stale.** The parallel writer has an uncommitted `sk-create-readme/SKILL.md` version bump, which is one of that hub's routing inputs; the guard reports `sk-doc  stale-manifest` and the pre-commit route-remint gate re-mints it when they commit. It is not this phase's file to mint.
3. **The Pi preflight suite carries a pre-existing failure.** Its `cli-devin` advisory case expects a non-blocking result, while the packet's `stdin-redirect-required` rule has been `severity: error` since commit `687de40016a` (2026-09-15). Both the rule and the expectation were verified unchanged at `HEAD`, so the mismatch is unrelated to this migration and was left for its owner.
4. **A sibling packet still records the retired path.** `specs/cli-external-orchestration/075-cli-runtime-readme-refresh/` names `.skilled/skills/cli-external-orchestration/cli-jev/README.md` in its scope and summary tables, which is the record of what that in-progress packet touched in its own era. Rewriting another packet's frozen scope was out of bounds here.
5. **The parallel writer's review workspace contains pre-move snapshots.** `specs/cli-orca/002-consolidate-official-orca-skills/review/containment/` holds quarantined copies of this repository, including the old packet path and the pre-regeneration fixtures. They are their artifacts, excluded from the census, and were not edited.
6. **The description cache holds packet rows, not a track row.** `specs/descriptions.json` now carries the new track's twelve packet and child rows; there is no row for `specs/cli-jev` itself because the cache's shape has none for any track.
7. **This phase's edits are uncommitted.** The decoupling half arrived as commit `e66dccd6a2`; everything this phase changed sits in the working tree, because the program does not commit or push without an operator request.
