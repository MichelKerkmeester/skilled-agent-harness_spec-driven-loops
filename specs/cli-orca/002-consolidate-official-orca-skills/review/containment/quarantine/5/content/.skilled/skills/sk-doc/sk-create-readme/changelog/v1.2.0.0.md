# create-readme v1.2.0.0

The writing-style release, distilled from the root README rework. The guidance now separates the front-page marketing register from the technical register every other README uses, and it documents the formatting patterns that made the front page scannable: feature-named headings, per-item inventory descriptions and a 2-4 sentence paragraph bound. Every addition is opt-in or scoped to the README types it fits, so existing conformant READMEs stay conformant.

## 1. NEW

- `SKILL.md` format rules gain four entries: the two-register emoji policy, the rule that headings name the feature or artifact, per-item descriptions for inventories and the 2-4 sentence paragraph bound.
- `writing-patterns.md` gains an `Emoji Use` structural rule, a `Paragraphs and Bullets` rule and the `Itemized Inventory` table pattern with the bold-name-plus-bullets shape and `#####` grouping.
- `types-and-voice.md` gains the `Front-Page vs Technical Register` subsection: the repository front page may pitch, every other README explains.
- `quality-and-checklist.md` gains checklist items for emoji-register adherence, feature-named headings, per-item inventory descriptions and paragraph length.
- `readme-template.md` gains an inventory-description writing rule, the itemized pattern with a worked example and a scaffold comment pointing at it.
- `core-standards.md` README block now names the two emoji registers instead of a blanket `Allowed`.
