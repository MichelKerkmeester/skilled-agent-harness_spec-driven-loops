# Orchestrator rulings on design.md section 6 (2026-09-29)

1. Every section 6 answer is accepted as proposed.
2. Hub version: `parent-skill-check.cjs` invariants 13a and 13b require the sk-doc hub's `SKILL.md` version to equal its newest changelog entry and every other hub version field. So the doc step that writes `changelog/v2.2.3.0.md` (re-derive the number at build time) is followed by one step that sets that same version in `SKILL.md`, `ROUTER.md`, `description.json`, `hub-router.json` and `mode-registry.json`, checked by `node .skilled/commands/doctor/scripts/parent-skill-check.cjs .skilled/skills/sk-doc` printing `OK`.
3. `--draw --seed <n>` on the real tree is the session's run, not an executor's, and no model writes a label. The phase stops at its label gate until the operator labels.
4. Gate order (parent D1, "Jev first, else Deem"): with both switches, the Jev gate and arm run first, then the Deem gate and arm, each on its own gate and regardless of the other's outcome. A failed gate prints its skip line and never runs the other backend in its place.
5. Docs name only what the code prints. A `verdict` line is claimed nowhere unless a run printed it.
6. Tests run on a machine whose global git config sets `core.hooksPath`, and its commit-msg hook rejects a commit without a body. Every test that creates a git repository passes `-c core.hooksPath=/dev/null` (beside `-c commit.gpgsign=false`) to each `git commit` it runs, as `cli-classifier/benchmark/injection-screen/tests/score-injection-screen.test.mjs` line 48 does. Test code and the scripts never run the machine's hooks.
7. Lessons from sibling builds, binding on every code step. (a) Every `spawnSync` or `execFileSync` of git passes `maxBuffer: 268435456`: this repository's `git ls-files -z` prints about 15.7 MB and Node's default is 1 MB, which made a sibling's default run exit 1 on the real tree while its tests passed. (b) A default run on the real tree finishes in a few seconds; no `git grep` over every tracked file under `specs/`. (c) Each step's tests pass using only functions from that step or an earlier one. (d) No test asserts a count read from the real repository.
