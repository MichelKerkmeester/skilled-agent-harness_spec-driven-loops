### Phase 39: hub-cleanup

The phase will make the cli-classifier hub say what it is. The Jev packet folder `.skilled/skills/cli-classifier/cli-usage/` becomes `cli-jev/` with `git mv`, and `cli-usage` stays in the alias vocabulary and the mode registry alias list so an old prompt still routes to mode `cli-jev`. Every version field in the hub continues under `0.x` by the mapping in `scratch/context/context.md`, so no skill, mode or README reaches `1.0.0.0`, and the six 1.x changelog files are renamed and retitled with their history kept. `cli-deem` gains a `manual-testing-playbook/` package through sk-doc, covering the health-check gate, each judgment type and the dormant path, with every scenario on a stub or a refused call. The compiled routing, the leaf manifest and the Hermes copies are regenerated by their tools, never hand-edited.

Nothing was dropped before this phase. `jev 0.6.2` is on `PATH`, and the mode registry simply maps workflowMode `cli-jev` to the packet folder `cli-usage`, because commit `ea883967d4` moved the old nested packet under cli-classifier and kept the folder name.
