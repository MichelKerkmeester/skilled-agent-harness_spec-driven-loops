4. **The awk `getline` design does not work on macOS.** When BSD awk (the macOS awk, version 20200816) runs `getline` on a directory, it returns 0 and then aborts the whole awk program at close or exit with `awk: i/o error occurred on <dir>` and exit 2. This happens with or without `close()`. I reproduced it on 2026-09-27. Under `validate.sh`'s `set -e`, a citation that names a directory would stop the rule, which breaks NFR-R01. So the plan's "inside the same awk pass" (plan section 3, NFR-P01, and the spec risk row "treat a read that returns no lines as unresolved") is replaced. Awk now only carries the citations out as a fifth field. Bash builtins in `run_check` resolve them with `-f`/`-r` and a `read` loop that stops at the cited line. That still adds no process per citation and makes one `git` call per run (NFR-P02). The design passed 41/41 under `/bin/bash` 3.2 in a scratch copy.
5. **The legacy parser had no test case before.** `tests/check-ac-coverage.sh` never called `_ac_analyze_traceability`. Brief 05's two fixtures are its first coverage.
