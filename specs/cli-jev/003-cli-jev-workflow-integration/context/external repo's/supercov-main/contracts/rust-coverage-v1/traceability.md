## R2 architecture correction — 2026-08-28

An earlier process-per-test prototype proved that external splitting cannot be
the public ordinary-libtest model because it changes shared process state and
aggregate output. The replacement is an exact-toolchain `library/test`
companion that keeps stock scheduling, shared state, capture and presentation
while emitting the frozen authenticated `rust-libtest-event-v1` stream.

Proven locally: the source preparer hashes and atomically patches the exact
toolchain tree; bundle schema v2 binds its source, event runtime, artifact
bytes, exact rustc identity and compiler-companion build; injection is limited
to genuine test-harness units; and each Cargo artifact executes once with its
original libtest arguments. The binary stream rejects wrong tokens, symlinks,
unknown kinds/results/flags, nonzero reserved fields, reordering, truncation
and tampering. Persisted transport is recombined and repartitioned before it is
trusted, including zero-selected-test background evidence. Real gates preserve
`--test-threads=1`, `--show-output`, `--nocapture`, pretty, quiet, ignored,
filtered and fail-fast behavior, plus mixed custom-harness and rustdoc runs.

Still open and release-blocking: make companion construction kernel-locked and
fully crash-recoverable; preserve intentional libtest non-execution modes such
as `--list` and `--help`; complete exact concurrent child-thread, async-task and
subprocess propagation under the stock process; expand timeout/partial/crash
outcome gates; and run the supported-platform and broader
presentation/custom-runner corpus. These requirements supersede every older
statement that in-process libtest was merely a future optimization.

The open gates are intentional release blockers, not deferred semantics.
