What it does: it reads the recorded fan-out lineage registries (deep-research and deep-review runs with at least two lineages), finds the candidate duplicate pairs the merge judged (near-line and cross-body), and prints the merge's own decision on each with deduplication on and off. It then scores one backend's same-or-different judgment against the operator's labels when an arm is named. The merge is not changed. The default run makes no model call and writes no file.
A pair is `undecidable` when the merge drops either finding on its own before comparing (a review finding that is not active, or a finding with no id or title), since a one-finding result then says nothing about the pair.
Labels: `--write-pair-sheet <path>` writes at most the first 60 pairs of each class, ordered by the SHA-256 of the pair key, each row with both findings' text, their lineages, the run path and an empty label. The operator fills `same` or `different`. `--labels <file>` reads the filled sheet back.

Exit 2, each before any census line:
- `--jev` or `--deem` without `--out` prints `--jev needs --out <dir> so every call is recorded` or `--deem needs --out <dir> so every call is recorded`; both switches without `--out` print `--jev and --deem need --out <dir> so every call is recorded`.
- A pair-sheet path inside the repository prints `refusing to write the pair sheet inside the repository` and writes no file.
- A bad labels row prints its row and fault, for example `labels row 3: label must be same or different, got "x"` or `labels row 3: duplicate pair <key>`.
Zero model calls by default: logging stubs for `cli-deem` and `jev` first on PATH were never called.
