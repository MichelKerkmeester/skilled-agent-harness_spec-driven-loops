# Implementation Plan: Design authority for mcp-magicpath

<!-- SPECKIT_LEVEL: 2 -->

---

<!-- ANCHOR:summary -->
## 1. SUMMARY

### Technical Context

| Aspect | Value |
|--------|-------|
| **Language/Stack** | Markdown entry contract and JSON metadata in the packet and the hub root |
| **Framework** | The hub's mode registry and transport axis, audited by the fleet metadata tool |
| **Storage** | None |
| **Testing** | The fleet metadata audit, a tool-surface count, a permission re-read, and a residual-claim sweep |

### Overview

Settle the authority conflict before writing a single rule, because the conflict decides what the rule is allowed to say. A write-capable persona adopted into a read-only transport either narrows to the transport or silently widens it, and the answer has to be reached deliberately rather than discovered later in a diff.

Then the binding itself, which is small: one always-load, one reference document, and the rules that carry it. The larger half of the work is the sweep — a binding that makes this mode's pairing different from its three siblings turns several hub sentences false, and each one has to be found rather than assumed absent.

The symlink is independent of all of it and can land at any point.

<!-- ANCHOR:architecture -->
## 3. ARCHITECTURE

### Pattern

Two contracts meet at this packet and disagree in exactly one place. The resolution rule is **narrower surface wins**: a persona supplies judgment discipline, never tools. Anything else lets a packet acquire authority by adopting a document.

### Key Components

| Component | Role |
|-----------|------|
| The always-load | Places `sk-design` ahead of intent scoring, removing the trigger that could fail to fire |
| `references/design-authority.md` | Carries the full contract: ownership split, why it is ungated, what the persona withholds, the failure modes closed |
| `crossHubPairing` | Makes the pairing resolvable from the registry rather than only from prose |
| The hub sweep | Repairs the statements the divergence invalidates |
| The aggregation symlink | Puts the mode where a reader looks for a hub member's release history |

### Data Flow

A request arrives; the design authority and the persona load; wiring is verified; intent is scored; the read funnel runs; the retrieved facts are handed to `sk-design`, which owns whatever judgment the answer contains. The transport never closes the loop itself.

<!-- ANCHOR:phases -->
## 4. IMPLEMENTATION PHASES

### Phase 1: Settle the authority

Read the sibling pairing and the persona's own contract. Decide `sk-design` over `sk-design-md-generator` on the evidence that MagicPath themes arrive tokenised. Resolve the write-capability conflict toward the transport. Nothing is written until this is decided.

### Phase 2: Bind and sweep

The always-load, the reference document, the rules, the packet changelog. Then the registry field and the hub statements the binding invalidates, found by sweeping rather than by memory. The symlink lands here.

### Phase 3: Prove the surface did not widen

Count the registered tools, re-read the permission list, re-read the declared posture, sweep for residual false claims, and run the fleet audit — watching it fail on manifest staleness first, so the pass afterwards means something.
<!-- /ANCHOR:phases -->

<!-- ANCHOR:testing -->
## 5. TESTING STRATEGY

There is no runtime to exercise, so every check is a state assertion against the final files: a tool count from the emitter's own output, a permission list read from the frontmatter and the registry, a residual-claim sweep by pattern, a symlink resolution, and the fleet audit observed failing and then passing.

The one thing no check here can establish is whether a future agent actually loads the skill the contract names. That is prompt-time discipline with no observer, and it is recorded as a limitation rather than covered by a check that would only appear to test it.
<!-- /ANCHOR:testing -->

<!-- ANCHOR:rollback -->
## 7. ROLLBACK PLAN

Every change is additive prose, one additive registry field, a regenerated manifest, and a symlink. Reverting means restoring the touched files from git and removing the symlink; no state, no migration, and no consumer holds anything that would break. The tool surface was never touched, so a caller mid-flight is unaffected either way.
