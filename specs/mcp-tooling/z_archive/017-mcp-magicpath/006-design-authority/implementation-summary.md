## What Was Built

An unconditional load, a contract document, a sweep, three symlinks, and one registry field that had to be put back the way it was found.

The packet used to decline design judgment and say so: "this packet is a read-only transport and issues no such verdict." Correct about ownership, wrong about consequence. A caller who receives a theme's CSS variables and no judgment does not stop, they decide anyway — without the value scales, the interaction guidelines, or the WCAG pass. The refusal produced an unowned verdict rather than no verdict.

`sk-design` now loads at STEP 0, before wiring is checked and before intent is scored, with nothing gating it. Not a keyword, not a confidence score, not a design-shaped test. A theme lookup and a credential probe load it alike, because the cost of loading it on a plumbing request is far below the cost of a design answer produced without it.

The persona came with a conflict worth naming. The design agent declares itself "LEAF-only and write-capable"; this transport declares `mutatesWorkspace:false` with Write, Edit and Task forbidden. Adopting it wholesale would have converted a read-only transport into a mutating one by document rather than by decision. The resolution is stated in the contract: a persona is a judgment contract, never a grant of tools, and the narrower surface wins.

## How It Was Delivered

The authority conflict was settled before a single rule was written, because a rule written first and rationalised afterwards is how a packet acquires a permission nobody decided to grant.

The larger half of the work turned out to be the sweep rather than the binding. Making one transport's pairing different from its three siblings quietly falsified several hub sentences that had been true when all four were alike — "Every design-affecting operation pairs in `sk-design-md-generator`", "Design work always pairs a transport with `sk-design-md-generator`", "partner for the four design transports". Each was found by searching for the assumption rather than by recalling where it had been written.

That sweep also surfaced something older: `SKILL.md`'s `packetKind: "transport"` line enumerated three transports and omitted `mcp-magicpath` entirely, stale since the mode was added in the previous phase. It was corrected here because the same sentence had to be rewritten anyway.

Verification ran against the two things that could have gone wrong invisibly. The tool count and the permission list were re-read from the emitter's own output and from the registry, not assumed unchanged, because "adopting a persona widened nothing" is exactly the kind of claim that is easy to make and easy to be wrong about. The fleet audit was watched failing on manifest staleness first, so that its pass afterwards meant the manifest had actually been regenerated.

<!-- ANCHOR:decisions -->
## Key Decisions

- **`sk-design`, not `sk-design-md-generator`.** The three sibling design transports pair with the measure skill, and copying them would have been the low-friction choice. It would also have been wrong: `get_theme` already returns named CSS variables and fonts, so the measurement is what the API hands back. What this surface lacks is the decide half. `sk-design-md-generator` still applies when the reference is an external live site rather than a MagicPath theme, and that carve-out is written down rather than left implied.
- **Ungated, not trigger-gated.** A pairing that fires on design keywords fails on exactly the request that needs it most — a design-affecting question phrased as plumbing. Removing the condition removes the failure mode; paying for the load on a wiring check is the cheaper side of that trade.
- **Narrower surface wins.** The persona's write capability is withheld explicitly. Had it been inherited, any transport adopting a write-capable persona would silently leave the transport axis, and the axis would stop meaning anything.
- **Leave `crossHubPairing` empty, having first wrongly populated it.** It sat as `{}` while the axis carried the pairings in prose, which read as an unfinished field. It is not: `registry-compiler.cjs:249-255` resolves its values as skill ids against `judgmentRegistries`, fails closed on one it cannot find, and its own comment records that the live path was removed after MT-008 over-routed `sk-design`'s md-generator alongside `mcp-refero`. `sk-design` has no `mode-registry.json` and can never join that set. The field is deliberately inert; the reversal is ADR-001.
- **Diagnose the blocked gate, do not skip it.** The pre-push failure offered `SPECKIT_SKIP_PREPUSH_ROUTE_GATE=1` in its own message. Taking it would have pushed a registry that no longer compiles. A bisect against the pre-change registry isolated the field in four probes.
- **Fix what the change broke.** The hub sentences this binding falsified were repaired. `mcp-notion` and `mcp-obsidian`, originally out of scope, were added on an explicit operator request recorded as ADR-004.

<!-- ANCHOR:limitations -->
## Known Limitations

- **Nothing enforces the pairing.** Every check in this phase reads final state; none observes an agent loading `sk-design` during a real request. An agent that skips STEP 0 produces exactly the unowned answer the previous version did, and no gate, hook, or validator would notice. The contract is prompt-time discipline, and calling it anything stronger would be false.
- **The pairing is prose-only and will stay that way.** `crossHubPairing` cannot carry a value for any transport, so a reader still cannot resolve a transport's design partner from the registry. That is the gap this phase set out to close and did not. Making it closable means changing the routing compiler, which reopens the path MT-008 closed and belongs in its own packet with its own evidence.
- **This phase asserted the opposite first.** It recorded the field as populated and the criterion as met, and only a pre-push gate caught it. Nothing in the packet's own verification would have: the fleet audit, the strict validator and the tool-surface checks all passed with the broken registry in place. The gate that caught it is not one this packet owns or runs.
- The two runtime variants of the design agent differ — `.opencode/agents/design.md` is 15654 bytes and `.claude/agents/design.md` is 15468, and they are not symlinks of each other. This packet resolves by runtime rather than reconciling them, so the adopted persona differs slightly depending on where the packet runs. Whether that divergence is intentional was not investigated.
- The persona's write-authority exclusion rests on the `allowed-tools` list that already excluded Write and Edit. Adopting a persona cannot widen that list, but nothing verifies the reasoning survives a future edit to either document.
- `mcp-notion` and `mcp-obsidian` are still missing from the changelog aggregation directory. Both are real gaps, found while establishing this phase's baseline, and neither was this mode's to fix.
- The advisor-level routing gap recorded by phase 004 is untouched. Hub-level routing resolves MagicPath correctly; an operator who describes a MagicPath task without naming it may still get no advisor recommendation, and that diagnosis still lives in the advisor's own scoring internals.
