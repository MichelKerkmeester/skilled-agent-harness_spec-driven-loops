## 1. Executive Summary

The eight-phase packet that deleted the advisor's MCP transport and made `node .opencode/bin/skill-advisor.cjs` the single front door (goal.md D1–D10) teaches five things its own defect hunt (009) could not, because a defect hunt hunts survivors while a lessons study asks how the survivors survived:

1. **The failures that hit were lifecycle failures, and the fallback-era verification class could not see them.** Five failures surfaced only when the CLI became primary (§5): a freshness module whose root/database resolved under the dead name (`Advisor: stale` after a cold start), a front-door entry point whose dist path hid in a split `path.join`, a shim whose compiled `dist` still held the old path, an exit-taxonomy smoke case orphaned by the shim set's collapse, and — the mechanism under all of them — a verification practice (payload parity, judged by exit code, against a warm daemon) structurally blind to exactly that class.
2. **Residue comes in seven classes, and the sweep's machinery is blind to half of them.** Beyond the 87→0 name-references the packet itself swept (008:117), a transport removal leaves mechanism-claims whose referents are gone (R4), departed coverage nobody accounts for (R5 — the class the existing sweep missed *by construction*: absence has no grep), records that stopped being written (R6), and waived derivatives whose blast radius was recorded but whose discharge was never owned (R7) — plus the fix-echo: the remediation's own diff needs the next scan (009-report:16).
3. **A repeatable, cost-ordered checklist exists, and this packet practiced it step-by-step, under fire** (§7, §8): eleven steps, ordered door-down → criterion-down → discovery-latency → trust-erosion, each with an observable pass condition, mapped onto the packet's own load-bearing D6 skeleton.
4. **The checklist's three gaps are themselves lessons**: review-generation decay (the prior hunt's unclosed findings became the next hunt's P1s — the packet needed its defect hunt twice), waiver score-qualification (a waived regeneration silently changed advisor fusion scores and nothing re-qualified them), and the general truth that a checklist cannot certify what waivers silently changed.
5. **The migration paid, measurably**: the prompt hook's warm path went 2,096 → 819 ms (002's recorded baseline → 008's final criterion), while preservation (D2) held. A lessons study that only lists pitfalls would undersell the packet.

## 5. Question One — Latent Failures Behind the Fallback

### LF1 — `runtime/lib/freshness.ts` resolved its script root and DB path under the old name
The module that decides whether the installation is current looked under the pre-rename tree; the daemon answered `Advisor: stale` after a cold start (006 defects table, row 1). **Hidden by:** (a) *warm-masks-disk* — a long-lived daemon holds its resolutions; only a cold start re-derives them, and the cold start was the rare path while the CLI was the fallback ("Two failures surfaced only because the daemon was stopped before the hook ran, which is the cold path real sessions hit first", 006:83); (b) *exit-0 degradation* — D9's graceful degradation means a stale advisor still answers, renders the route line, and exits 0, so every exit-code-verified gate stays green while the answer is wrong (008:84-85; D9). The lesson stuck twice: the degraded marker became documented live instruction ("the brief renders that as `Advisor: stale`", AGENTS.md:101, verified by rg this study, 1 hit), and the cold/unreachable states became a standing criterion — "Brief arrives in three daemon states | PASS. Warm and cold both render a route; unreachable renders a degraded line" (008:115).

### LF2 — `.opencode/bin/skill-advisor.cjs` used a split `path.join` form
The front door "would not have resolved its own dist" (006 defects, row 2); the references "survive[d] in forms no path-shaped search finds: string elements split across lines in a `path.join` call, and bare `'mcp-server'` literals. Two of those were the CLI's own entry point and the module that computes the freshness signature, and each one alone was enough to break the front door" (006:60-62). **Hidden by:** *true-until-renamed* (the fragment-join resolved correctly while `mcp-server/` existed — the failure existed only in waiting) compounded by *search-invisibility* (the tool every sweep in this repository reaches for cannot see a literal split across lines) and by the fallback era's rare exercise of the entry point.

### LF3 — the spec-kit shim printed `TARGET_UNRESOLVED`
Its "compiled `dist` still held the old path; a rebuild was required" (006 defects, row 3). **Hidden by:** *dist-duality, both directions* — source edits are silent no-ops when the old compiled tree still serves ("the hook runs from `dist`, so the source edit alone had no effect", 006 §Key Decisions), and missed references keep resolving while the stale tree exists ("a surviving `dist/mcp-server/` would keep a missed reference working, and the failure would only appear after a later clean build", 006:99). The MCP-primary, always-warm world postponed every clean rebuild; the CLI-primary world forces them.

### LF4 — the exit-taxonomy smoke's orphaned case
"The `SHIMS` map defines only `skill-advisor`, while a case still asks for `shim: 'code-index'`, so `spawnSync` runs `node undefined` and exits 1 instead of 64" (006 limitations, item 1) — the guardian of the exit contract itself lied, because the shim set collapsed (D1) while the asserting case survived. Surfaced when 006 first exercised the front door as primary; closed by retirement, not resurrection: "Exit-taxonomy smoke | PASS. 3/3, after removing a case that named a shim deleted from the lookup table" (008:119).

### LF5 — the structural mechanism: the verification class could not see the failure class
Every fallback-era verification shared three properties: it judged payloads, not lifecycles; it ran against a *live daemon* ("22 frozen cases across all nine commands, run against the live daemon", 003/verdict.md epigraph); and it judged results, not outputs. LF1–LF3 are lifecycle/environment failures. A harness member cannot catch a non-member: the failures surfaced "solely because it became the primary path" in the precise sense that becoming primary changed which verification class ran (006's cold-start probes; 008's three-states, re-measure, and baseline disciplines — 008:84-85, 98, 100, 115-119 — disciplines the earlier phases had to invent afterwards).

## 8. Question Four — The Backtest, What the Checklist Misses, and the Dividend

**The packet practiced the checklist under fire, in the checklist's own order.** Steps 0–1: practiced at inception (002's baseline and wire-freeze; 003's taxonomy freeze) — and still insufficient without the discipline, which is the point: the warm-mechanism document did not immunize; the cold-START execution did (006:83). Steps 2–4: invented mid-packet (006's cold-start probes, clean rebuild, the two-phase-late retire). Steps 5–6: partial (007/008's exemplary survivor-bucketing; the absence half and the frozen-name disposition invented at 008–009). Steps 7–10: late or never (002/004/005's records; the fix-echo caught post hoc; 008's final-state machinery the strong habit). **The validation:** the packet's pain arc — door-down (006) → criterion-down (008/AC:91) → discovery-latency (009-report:94) → record-erosion (009-F003) — runs in exactly the checklist's tier order. The order is not the study's invention; it is the packet's experienced sequence.

**The checklist's own misses (the study's additions):**
1. **Review-generation decay** — the prior hunt's three unclosed findings became the next generation's P1s by promotion ("prior F010 → F001 here; prior F012 → F002 here; prior F015 → F003 here", 009-report:15); the 11th step closes it, grounded in the packet's own review-of-review rule (009/implementation-summary.md:112).
2. **Waiver score-qualification** — the corpus waiver "changed advisor fusion scores" (006:95) and nothing recorded re-qualified the routing quality; 008's recorded criterion was latency (008:116); whether the 009-fix's regeneration restored the scores is uncited (**hypothesis, labeled**). The it3 exclusion of benchmarking ("D3 discharged") needed this qualification — recorded here rather than silently patched into it3 (an iteration-003 pass condition amended by its own review, which is the checklist working).
3. **A checklist cannot certify what waivers silently changed** — 008/AC:92's exemplary hand-corrected allowlist still verifies NAMES, not scores; the 47-path question stays unsayable at close. Post-waiver re-measurement, not waiver record-keeping, closes the epistemic gap.

**The affirmative dividend** (lest the lessons read as costs): hook warm p50 2,096 ms at 002 (pre-rewire baseline) → 819 ms at 008 (final) — ~2.5× — while the CLI's own warm call came in at 736 ms against its recorded 1,100 and the cold start at 1,566–1,812 against 3,500 (008:116; the 1,100's provenance — criterion vs 002's 823 measured — labeled, unreconciled). The daemon was kept AND rewired: D3's measurement was conclusive enough for both.

## 9. Mechanisms That Hide: A Unified Account

The study's eight hiding mechanisms, each instantiated in this packet: (1) *warm-masks-disk* — a long-lived daemon masks on-disk breakage (LF1, 006:83); (2) *exit-0 degradation* — graceful answers succeed, so exit gates see nothing (LF1, D9, 008:84-85); (3) *true-until-renamed* — references that were correct, then silently weren't (LF2); (4) *search-invisibility* — the split-join and bare-literal forms no path-shaped search finds (LF2, 006:60-62); (5) *dist-duality* — compiled trees both mask misses and no-op edits (LF3, 006:99); (6) *plan-time records* — summaries drafted in the planning voice, never refreshed ("Not started", 005:49-56); (7) *review-generation decay* — prior conclusions absorbed as settled, then promoted (009-report:15); (8) *waiver-silence* — waived artifacts keep pre-removal semantics until someone re-measures (006:95, 008/AC:92). Each maps to a checklist step: 1–2 → (1)(2); 2 → (3)(4); 3 → (5); 7 → (6); 11 → (7); 8+10 → (8).
