**2. Arm design: keep 144 sessions per runtime, but spend them on rows, not repeats.**

- **Decision.** 36 fresh rows, two runs each, arms `off` and `on` at one commit, all six runtimes. That is 864 sessions, with a hard cap of 900 to allow one rerun pass for harness faults only.
- **Row mix.** 20 rows that fit a command (10 start, 5 run, 5 ask, at least 15 distinct commands, every family at least twice), 8 skill-only and 8 decline (two per kind: refusal, question, small-edit, app-problem). The decline share is raised because the head carries a command on 8 of 24 sealed decline rows and 0 of 24 skill-only rows (outcome-evidence.txt:13-14).
- **Is the proposal too big or too small.** The session count is right. The shape is wrong: three runs on 24 rows buys repeats when rows are the scarce thing. No affordable size gives a per-runtime verdict. At 16 rows a rate reads 0.28 to 0.72 (outcome-evidence.txt:16), and the tuned arms had about 30 percent of rows change, so a per-runtime sign test would need about 40 owned rows.
- **Smallest valid design.** One run per row, 288 sessions, is enough for the pooled sign test, since run noise is symmetric between arms. The second run is what removes limit 3 ("each row ran once"). The pooled test can show a strong effect, about three gains per loss, and will not show a weak one.
- **Where the rows come from.** A new file, `RAD/behaviour-fresh-prompts.jsonl`, with split `fresh`. The runner reads only `command-prompts.jsonl` and refuses split `holdout` (RAD/run-command-behaviour.mjs:66 and :633), so the sealed rows cannot be used. A separate file keeps the fresh rows out of the capture's published per-row results, which would otherwise show a later tuner which rows miss.
- **Who writes them blind.** One DeepSeek worker session under the same protocol as the 48 fit rows: class definitions, row shape, the command listing and skill names only, no lib file, no existing row, no advisor run on a draft (PK/023-untuned-outcome-evidence/tasks.md:78). The file's hash is logged and the rows are frozen at the first session.
- **Brief off.** `SKILL_ADVISOR_HOOK_DISABLED` and `SKILL_ADVISOR_PLUGIN_DISABLED` (.skilled/skills/system-skill-advisor/hooks/skill-advisor-hook.md:169-173). The runner already passes the `SKILL_ADVISOR_` prefix to the child (run-command-behaviour.mjs:872). AGENTS.md is identical in both arms, so only the brief differs, which removes limit 4. A run whose brief delivery does not match its arm is unscored and rerun once.
- **What must be built.**
  - Arms `off` and `on` added to the closed list (run-command-behaviour.mjs:951).
  - A `--set fresh` that reads the new file, with the holdout guard and a repeated-text refusal.
  - Pairing over both runs of a row. Today the pair map keys on row id, so a second run overwrites the first (RAD/score-command-transcripts.mjs:1745). A row gains when its on count beats its off count.

- **Which script prints each number.** `score-command-transcripts.mjs --summary <logs> --pair off,on` prints the followed rates with ranges, the paired lines, the decline starts and the pooled line. The run log's `offeredCommand` and `briefDelivered` fields give the offer counts.
