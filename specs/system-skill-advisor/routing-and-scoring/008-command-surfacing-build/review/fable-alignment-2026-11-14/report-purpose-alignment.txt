FINDINGS

1. **P1: the outcome measure scores only the 16 tuned rows.** There is one run each, no holdout, no skill-only row and no negative row (019 `spec.md:209`). Fix: score a fresh untuned row set with at least three repeats per row before quoting any share as the outcome.
2. **P1: the share formula is asymmetric.** `none` leaves the denominator, a load with no action enters the numerator, and a correct ask-and-wait earns nothing (`score-command-transcripts.mjs:668`, `:1414-1417`). Fix: report `none` beside the share and count an `ask` row that asked and wrote nothing as a followed workflow.
3. **P1: the brief offers a `start` command on a question and on a trivial edit.** See the `/create:readme` cases in answer 2; the hub attach path has no question or edit-size gate (`command-attach.ts:333-374`). Fix: withhold the attached command when the prompt is interrogative about the command or asks for an in-place edit of an existing file.
4. **P1: no completion criterion measures the outcome.** `goal.md:91-97` can close green with models improvising. Fix: add one criterion that names the workflow share on untuned rows and the operator's target.
5. **P2: free choice depends on `AGENTS.md` being loaded.** The brief itself says "use X → /cmd (policy)" (`render.ts:603`). Fix: change the head to wording that names the command as an option, such as "use sk-doc; command offered: /create:readme (start)".
6. **P2: the policy sentences in `AGENTS.md:68` read as mandates.** Fix: prefix them with "If you take the command:".
7. **P2: a wrong mode under the right hub counts as followed** (`score-command-transcripts.mjs:614`). Fix: when the row expects a command, require the mode folder that command maps to.
8. **P2: any redirect before the load flips a run to improvised** (`:284`). Fix: ignore writes outside the repository when setting the first-write boundary.
9. **P2: "do not run it" is not read as a refusal, and the command prints twice** (`command-attach.ts:308`, `render.ts:563-569`). Fix: add the "do not run/start" forms to `NO_EDIT_REQUEST` and drop a companion equal to the head command.
10. **P2: a command row can lead a higher-confidence owning skill**, so the command is the headline even when the skill scored better. Fix: when the owner skill passes with higher confidence, render the skill first and the command as the option.
11. **P2: plain requests that clearly fit a command get no brief** ("plan a new feature…", "my skilled hooks are not showing up"). Fix: treat the holdout plain rate as the reach number to raise, by matching, not by more phrases.
