**Question 3: does the scorer print the target as written?**
Yes, except for the `unpaired` gap and the hand-pooled skill-only starts.
- **`signTestP` (`:1743-1755`):** it sums exact binomial coefficients from `gained` to `n` in BigInt and rounds half up to four decimals.
  - 15 gained, 5 lost: the tail is 15504 + 4845 + 1140 + 190 + 20 + 1 = 21700 over 1048576 = 0.020695, printed 0.0207.
  - 12 gained, 6 lost: the tail is 18564 + 8568 + 3060 + 816 + 153 + 18 + 1 = 31180 over 262144 = 0.118942, printed 0.1189.
  - 0 and 0 returns null.
- **Pooling:** `pooledPair` sums `gained`, `lost`, ties and `unpaired` over the runtimes and tests the pooled counts (`:2040-2058`).
- **Gain, loss and ties:** they compare followed counts over equal run counts (`:2016-2024`), with followed meaning `command`, `skill` or `asked` (`:1846`).
- **Delivery mismatch:** the run is left unscored before the session is loaded (`:1567-1569`). It still counts in `runs`, `unscored` and `unscoredRuns`, and it leaves the pairing.
- **Unknown delivery:** it is scored and counted in `deliveryUnknown` for every line, scored or not (`:1955`). A line with no `briefDelivered` field is treated the same way.
- **Unpaired row:** it is counted only when both arms scored the row at least once (the P1 item above).
- **Start counts:** decline and skill-only starts print per runtime and arm with their denominators, and each start is listed with its row, run and command.
