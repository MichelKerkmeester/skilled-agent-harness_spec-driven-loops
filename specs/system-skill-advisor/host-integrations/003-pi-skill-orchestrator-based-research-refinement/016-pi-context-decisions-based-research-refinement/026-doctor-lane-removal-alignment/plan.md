## 3. ARCHITECTURE

### Pattern
Other: documentation alignment over three existing mechanisms. The first is the workflow YAML that `/doctor:update` follows. The second is the routing manifest that the advisor derives its bridges from. The third is the doctor release skill.

### Key Components
- **`/doctor:update` route in `_routes.yaml`**: the trigger phrases that `doctor-helper-match.cjs` and the advisor read. It gains the cleanup phrases. Each one has three or more words and holds no residue term.
- **`derive-command-bridges.cjs`**: turns the route into the advisor bridge. It runs in write mode after the route edit, and its `--check` mode is the gate.
- **`release-update.cjs apply`**: the engine that `doctor-update-apply.yaml` phases 1 to 6 run. This plan reads it and observes it on fixtures, and it changes no code.
- **`sweep-lane-residue.mjs machine` and `apply`**: the cleanup. Copied installs reach it through phase 7. Linked installs run it from the Skilled checkout.
- **Install and upgrade documents**: `INSTALL-SKILLED.md` section 5, the advisor's `v2.0.0.0.md` Upgrade Notes, and line 459 of the update presentation. These state the per-install commands.

### Data Flow
A cleanup phrase enters the helper match and the advisor. The `/doctor:update` route carries it to `doctor-update-apply.yaml`. A copied install runs `apply`, and phase 7 runs the residue tool's `machine` check, then its `apply` only when `machine` lists leftovers. A linked install runs the residue tool from the Skilled checkout, because `/doctor:update` does not serve it. REQ-003 records the refusal the fixture prints.

### Release 1.3.0.0 Items
The changelog entry, required by REQ-007, names these six items:
1. The setup route drops its embedder leg, so it runs six read-only legs (commit `0c2ab52b3b3`).
2. The install route drops its advisor embedder step, so it lists five steps (same commit).
3. `/doctor:update apply` adds phase 7, the lane cleanup, after its rebuild prompt.
4. The orphan check no longer classifies a retired model server. Detecting retired processes stays with the residue tool's M4 check (commit `1f85a9dd6dd`).
5. The overlay and symlink workflows and update apply lose their vector coverage steps and lines (the 024 doctor surface).
6. This packet's discoverability fixes: the cleanup phrases, the per-install guide, and the setup counts.

Each item is written with the gate-safe wording "retired advisor lane", because the changelog is a tracked file outside `specs/` that the residue gate scans.

Required inventories:
- Same-class producers: `rg -n 'cleanup|residue|sweep-lane-residue' .skilled/commands/doctor` shows where the doctor names the cleanup.

- Route invariant: a cleanup phrase counts as routed only when `doctor-helper-match.cjs` returns the `/doctor:update` entry as the top or a candidate for it.
