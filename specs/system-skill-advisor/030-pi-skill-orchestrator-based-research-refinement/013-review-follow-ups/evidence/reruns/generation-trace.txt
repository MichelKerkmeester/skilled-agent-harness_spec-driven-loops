The mechanism, from the code (paths under .skilled/skills/system-skill-advisor/runtime/)
- The live daemon held 283 files open for reading (watched-files.txt): 281 skill source files it watches, the
  skills folder's .DS_Store and its own database. gen-monitor.py leaves out the database, so its header counts 282.
  When a watched file is written, the watcher waits for the write to settle for 1 second and then debounces for
  2 seconds (lib/daemon/watcher.ts:103-104, :420-429 and :510-532). If the file's hash changed or the file was
  removed, it reindexes and publishes a new generation with the reason advisor-server-watcher-reindex
  (lib/daemon/watcher-orchestrator.ts:86-124, advisor-server.ts:360).
- The live daemon writes the file on other occasions too, each with its own reason: its startup scan
  (advisor-server.ts:138-153), its shutdown with the state unavailable (lib/daemon/lifecycle.ts:109-116), a stale
  lease takeover (lib/daemon/lifecycle.ts:50-68), a skill_graph_scan call (handlers/skill-graph/scan.ts:53-62) and
  an advisor_rebuild call (handlers/advisor-rebuild.ts:88-96). A start or a stop also changes the live pids. In
  both FAIL windows below the new generation carried the reindex reason, and the live launcher and daemon were
  87524 and 87539 from 07:24:53Z (state-before.txt) to 07:50:21Z (../goal-reverify/crit3-sandbox-daemon.txt).
- A daemon started with SYSTEM_SKILL_ADVISOR_DB_DIR set opens its databases under that folder
  (lib/skill-graph/skill-graph-db.ts:270-274) and publishes its generation there too
  (lib/freshness/generation.ts:31-46). Its startup scan (advisor-server.ts:126-162) and its shutdown
  (lib/daemon/lifecycle.ts:109-116) both publish through that function. The crash test saw the sandbox daemon
  hold the sandbox's own databases, so it ran with the override.

Verdict
- Both FAILs trace to another session's edits to watched skill files, which made the live daemon publish during the

- Since the file records no writer, a quiet rerun points to the sandbox only when no watched file changes, the live
  advisor keeps its pids and no scan or rebuild runs during the block.
