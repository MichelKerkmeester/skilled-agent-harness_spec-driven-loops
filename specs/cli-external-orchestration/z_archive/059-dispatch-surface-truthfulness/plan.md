## 4. IMPLEMENTATION PHASES

### Phase 1: Setup
Confirm the failure is a quota wall rather than a hang, using the debug level that surfaces what silent mode swallows, and read the runtime constant that owns the executor roster.

### Phase 2: Implementation
Remove the default at every site that states it, replace it with a pre-flight check, correct the roster in the authored source, and regenerate the compiled contract from it.

### Phase 3: Verification
Diff the doc roster against the runtime constant, and prove the pre-flight distinguishes a dead model from a live one.
<!-- /ANCHOR:phases -->

<!-- ANCHOR:testing -->
## 5. TESTING STRATEGY

The pre-flight is its own test. Point it at the exhausted model and it reports the quota message; point it at a live one and it answers. Both were observed before this packet closed, which is what makes the check worth documenting rather than merely asserting.

Roster correctness is a diff: the executor names in the doc must equal the names in the runtime's exported constant.
