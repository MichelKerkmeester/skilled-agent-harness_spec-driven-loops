## What Was Built

Nothing was added to either roster, and that is the outcome rather than a shortfall. Union Alpha's stealth period ended one day after this packet was planned: OpenRouter now answers the id with a `404` announcing that the model was Unbiased's Pareto, the opencode-go gateway answers `Model is unavailable`, and both ids have left `opencode models`. The packet was implemented up to the point where the plan requires re-reading the live catalogs, and that re-read stopped it.

### Add Union Alpha to the cli-opencode and cli-pi rosters through opencode-go and OpenRouter

You gain a closed roster that still tells the truth. Both `cli-pi` and `cli-opencode` are rosters where a listed model is a model you are permitted to dispatch, so four rows naming a withdrawn id would have handed you four permissions that fail on use — and the failure would have surfaced mid-task, not here. The OpenRouter half would have cost more than that: the only argument for reversing packet 068's deliberate retirement of that provider was that a roster row is what makes a model dispatchable. With no dispatchable model, un-retiring OpenRouter buys a policy reversal and nothing else.

What you gain instead is the finding, recorded where the next session will look: which routes died and how each one announces it, the successor OpenRouter names and what it costs, and the two controls that separate a withdrawn model from a broken client.

## How It Was Delivered

The plan's testing strategy opens with "re-read before writing, not after", on the reasoning that a stealth id can move between the day a plan is written and the day it is implemented. It moved. The re-read ran first, before a single roster row was drafted, which is the only reason no false row ever reached a file.

Four dispatches and two controls, all on 2026-09-18, all classified on output text rather than exit code:

| Route | Result |
|-------|--------|
| `pi --model openrouter/stealth/union-alpha` | `404` — "Thank you for participating in the Stealth Union Alpha testing period. This model was Unbiased's Pareto." |
| `pi --model opencode-go/union-alpha` | `400` — "Error from provider (Console Go): Upstream request failed: Model is unavailable." |
| `opencode run --model openrouter/stealth/union-alpha` | `UnknownError` / "Unexpected server error" — the models.dev resolution signature |
| `opencode run --model opencode-go/union-alpha` | Same signature |
| **Control** `opencode run --model opencode-go/glm-5.3-flash --variant max` | Returned the expected token, exit 0 |
| **Control** `pi --model llmgateway/glm-5.3-flash --thinking max` | Returned the expected token, exit 0 |

The controls are what make this a finding rather than a guess. Without them, six failures in a row read just as easily as a broken client, an expired credential or a gateway outage, and the packet's own history shows how convincing a wrong reading can look: the `tokens.reasoning` counter had already produced a clean, plausible `0` that a control proved meaningless.

Rollout was the plan's rollback plan run forward: nothing to undo, because nothing shipped.

## Key Decisions

| Decision | Why |
|----------|-----|
| Ship no roster row rather than ship a hedged one | A row in a closed roster is a permission to dispatch. The spec forbids the listing-only hedge outright (REQ-009), and a hedged row still grants the permission — it just warns you afterwards |
| Leave packet 068's OpenRouter retirement standing | Restoring the provider was justified solely by the one model it would carry. With that model gone, un-retiring OpenRouter changes policy and delivers no route |
| Record `unbiased/pareto` without adopting it | OpenRouter's own `404` names the successor, so losing that pointer would cost the next session the whole investigation. Adopting it is a different decision: it is $2.50 in and $7.50 out per million against Union Alpha's $0/$0, so the free-model argument does not transfer |
| Correct the packet's own evidence rather than leave it | T001 and T002 read "all four green". Left alone, the next reader would implement against them. The 2026-09-17 record stands as written, with the supersession dated beside it |
| Keep the roster docs' four uncorrected sentences on the books | The spec had folded a known `--provider`/`--model` defect into this packet's roster edit. That edit never ran, so the defect needs its own carrier rather than silently disappearing with the packet |

<!-- ANCHOR:limitations -->
## Known Limitations

1. **The packet's goal is undelivered and cannot be delivered as written.** Union Alpha is gone from every route it had. No workaround exists for the model itself; the decision in front of the operator is to retire this packet, or to repoint it at a successor.

2. **`unbiased/pareto` is a candidate, not a drop-in.** It matches on context (262,144) and on the absence of a reasoning parameter, but it is paid where Union Alpha was free, and the packet's scope rule ("only Union Alpha is added") does not cover it. Adopting it needs a fresh cost argument and an operator decision, and every figure would have to be re-derived from the live catalog rather than carried across.

3. **The opencode-go thinking contradiction is recorded unresolved and now unresolvable.** The catalog said `thinking: yes`; the one behavioral test saw no `reasoning` part. The route was withdrawn before a discriminator could settle it. The instrument lesson does carry forward: `tokens.reasoning` reads `0` even for a known-good reasoning model, so only the `reasoning` part type in the event stream distinguishes.

4. **`pi --list-models` still advertises both dead ids.** Pi lists from its builtin catalog rather than from a live provider query, so a listing outlives the route it names. Anyone reading that column today would conclude both routes are available. This is a trap for the next reader and is not something this packet could fix.

5. **Four sentences in `cli-pi/references/providers-and-models.md` still document a rejected dispatch shape.** They describe route selection as `--provider opencode-go --model <id>`, which §2 of that same file says the enforcement guard refuses before launch. The spec had deliberately folded fixing them into this packet's roster edit; that edit never ran, so they remain and need a carrier of their own.

6. **Two pre-existing provider-count drifts in `cli-opencode/README.md`** (lines 131 and 50 say four providers where `SKILL.md` has said six since packet 068) were named as out of scope by the spec and are still out of scope. They predate this packet.
