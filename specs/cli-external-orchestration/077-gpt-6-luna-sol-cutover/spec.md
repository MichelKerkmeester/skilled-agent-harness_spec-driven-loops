## 2. PROBLEM & PURPOSE

### Problem Statement

OpenAI's GPT-6 Luna and Sol are live. Codex's model cache lists `gpt-6-luna` and `gpt-6-sol`, `opencode models openai` lists both plus their `-fast` variants, and LLM Gateway's `/v1/models` lists both as bare ids. The ids are `gpt-6-luna` and `gpt-6-sol`; the "6.0" the request used is not part of the id. The cli-codex, cli-opencode, cli-pi and cli-hermes documents, the deep-loop allowlists that decide whether a Pi, Hermes or Codex dispatch resolves at all, `.pi/settings.json`, and the pi fast-mode extension all still name `gpt-5.6-luna` and `gpt-5.6-sol`. Pi reaches Luna only through the `openai-codex` subscription route, and its bundled catalog carries no GPT-6 Luna or Sol id on any provider, so a renamed `openai-codex/gpt-6-luna` entry would not resolve without a definition. cli-claude-code's living docs name `claude-opus-4-6` and `claude-opus-4-8`; they hold no "opus 5.0" string, and the current Opus id is `claude-opus-5-5`.

### Purpose

Every living dispatch surface names the GPT-6 Luna and Sol ids and every paired roster copy moves with it. Pi and Hermes both reach `gpt-6-luna` through LLM Gateway, and cli-claude-code names `claude-opus-5-5` as its one Opus id.

## 3. SCOPE

### In Scope
- The case-preserving token rename `gpt-5.6-luna` → `gpt-6-luna` and `gpt-5.6-sol` → `gpt-6-sol`, which carries the `-fast` and `-pro` suffixes and the `openai/` and `openai-codex/` prefixes with it, plus the display names `GPT-5.6 Luna` → `GPT-6 Luna` and `GPT-5.6 Sol` → `GPT-6 Sol`. The Cursor and Devin "GPT-5.6 Luna Max" personas (`gpt-5.6-luna-max`, `gpt-5-6-luna-max`) are separate catalog ids and do not change.
- The living documents of cli-codex, cli-opencode, cli-pi and cli-hermes, and the generated `.hermes/skills` mirrors of the skills this packet touches, regenerated by `sync-skills-hermes.cjs`.
- The deep-loop enforcement: `PI_SUPPORTED_MODELS`, `HERMES_SUPPORTED_MODELS` and the reasoning-tier comment in `executor-config.ts`; `CODEX_DEFAULT_MODEL`, `PI_ALLOWED_MODELS`, `PI_MODEL_PROVIDERS` and `HERMES_ALLOWED_MODELS` in `fanout-run.cjs`; the default in `codex-dispatch.cjs`; and every test and fixture that pins those ids.
- Pi: `.pi/settings.json` renames `openai-codex/gpt-5.6-luna` and adds `llmgateway/gpt-6-luna`. `.pi/models.json` adds `gpt-6-luna` to the existing `llmgateway` block and defines nothing under `openai-codex`: the operator keeps that file to the custom `llmgateway` and `cline-pass` providers, and `pi update --models` refreshes Pi's own catalog so it carries `openai-codex/gpt-6-luna` and `gpt-6-sol`. `.pi/custom-providers.md` documents the fourth gateway model.
- Pi defaults and config (operator-directed 2026-09-23): `.pi/settings.json` defaults to `llmgateway/gpt-6-luna` at the global `xhigh`, `.pi/pi-blackhole-config.json` compacts with `openai-codex/gpt-6-luna` at `medium`, and `.pi/models.json` drops its `xiaomi` block because both MiMo ids are native to Pi's catalog.
- Hermes: the roster rename puts `gpt-6-luna` and `gpt-6-sol` on Hermes's `llmgateway` route. The closed roster stays at seven ids.
- The pi fast-mode extension: its priority-tier model list, the repo config it ships, its tests, README and playbook.
- cli-claude-code: every Opus id in the living docs (`claude-opus-4-8`, `claude-opus-4-6`) becomes `claude-opus-5-5`; the one `claude-opus-4.7` sits in a dated benchmark report and stays, the `Opus 4.x` labels become `Opus 5.5`, and roster rows that would now duplicate each other merge into one.
- A patch version bump and one changelog entry for each affected skill: cli-codex 1.9.1.0, cli-opencode 1.4.9.0, cli-pi 1.5.7.0, cli-hermes 1.0.2.0, cli-claude-code 1.5.1.0.

- **Cursor and Devin Luna Max personas** and their allowlists, including the hub `ROUTER.md` line naming them. They belong to Cursor's and Devin's catalogs, not OpenAI's.
- **`gpt-5.6`, `gpt-5.6-terra` and `gpt-6-astra`.** The operator named Luna and Sol only.
- **Opus ids outside cli-claude-code**, such as `CLAUDE_DEFAULT_MODEL` in `fanout-run.cjs` and `anthropic/claude-opus-4-8` in other skills. The operator scoped Opus to cli-claude-code. The fan-out's family test accepts any `claude-opus-` id, so the fallback does not break.
- **Operator-level config outside the repository:** `~/.codex/config.toml` (default `gpt-5.6-luna`), `~/.hermes/config.yaml` and `~/.pi/agent/`.
- **The pre-existing `.pi/settings.json` reorder hunk**, which predates this packet and rides along in the same file.
- **Pre-existing test failures** in the council and model-benchmark suites, which reject a stale `deepseek-v4-flash` literal and have nothing to do with Luna or Sol.
- **The sk-doc routing-test fixture** `evidence_model: gpt-5.6-luna`, which is sample evidence rather than a dispatch surface.

## L2: EDGE CASES

### Data Boundaries
- Luna Max personas: `gpt-5.6-luna-max`, `gpt-5.6-luna-max-fast` and Devin's `gpt-5-6-luna-max` keep their ids.
- Negative test inputs such as `gpt-5.6-sol-high-fast`, which exist to be rejected by the Cursor allowlist, move to `gpt-6-sol-high-fast` and stay rejected.

### Error Scenarios
- A Pi dispatch of a bare `gpt-6-luna` literal still maps to `openai-codex`, because one literal maps to one provider; the LLM Gateway route is direct-dispatch only, as `llmgateway/mimo-v2.6-pro` is.

### State Transitions
- An operator whose `~/.codex/config.toml` still defaults to `gpt-5.6-luna` keeps that default until they change it; the skill docs no longer recommend it.
