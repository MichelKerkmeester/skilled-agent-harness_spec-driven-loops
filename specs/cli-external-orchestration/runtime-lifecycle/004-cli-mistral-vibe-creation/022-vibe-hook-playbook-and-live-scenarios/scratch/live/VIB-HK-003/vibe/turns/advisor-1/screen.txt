  Quick correction that saves you time: a Vibe skill doesn't have a README — its entry point is a SKILL.md file. That's the file to write.                                                              
                                                                                                                                                                                                        
  Where to start:                                                                                                                                                                                       
                                                                                                                                                                                                        
   1. Pick a directory (this is the "scope" decision):                                                                                                                                                  
      ▪ .vibe/skills/<slug>/SKILL.md — this project only                                                                                                                                                
      ▪ ~/.vibe/skills/<slug>/SKILL.md — available in every project                                                                                                                                     
   2. Write the file with YAML frontmatter plus a Markdown body:                                                                                                                                        
  ┌─ markdown ──────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────┐   
  │ ---                                                                                                                                                                                             │   
  │ name: my-skill                                                                                                                                                                                  │   
  │ description: Load this skill when ... (the "when", not the "what")                                                                                                                              │   
  │ ---                                                                                                                                                                                             │   
  │                                                                                                                                                                                                 │   
  │ # My Skill                                                                                                                                                                                      │   
  │                                                                                                                                                                                                 │   
  │ Durable instructions: steps, conventions, commands, gotchas.                                                                                                                                    │   
  └─────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────┘   
   3. Rules that matter:                                                                                                                                                                                
      ▪ name: lowercase/hyphens only, matches the directory name, never collides with a built-in (vibe:*) or existing skill — collisions are silently skipped.                                          
      ▪ description: this is the only text I see before deciding to load the skill, so make it a routing hint ("Load this skill when the user wants X"), not a summary.                                 
      ▪ The body is loaded only after selection, so keep it focused on instructions the model should follow every time.                                                                                 
      ▪ Anything that speculates or references spec/task IDs belongs in the description-routing or nowhere — don't put bookkeeping junk in comments or body text.                                       
   4. Support files: add extra Markdown/JSON/YAML files next to SKILL.md in the same directory only when they earn their place, and reference them by relative path.                                    
                                                                                                                                                                                                        
  After writing, the skill is picked up in a running session automatically — otherwise /reload.
