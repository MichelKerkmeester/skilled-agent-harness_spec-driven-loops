  Done. Both files written and verified.

  lib/retry.mjs — withRetry(operation, options). Exponential backoff with jitter, capped at maxDelayMs; shouldRetry(error, attempt) to bail on non-transient failures; onRetry({ error, attempt, delay
  }) for logging. sleep and random are injectable so tests run instantly and deterministically. The last error is rethrown unchanged, so callers keep the original type and stack.

  src/uploader.mjs — upload(file, { fetchImpl, ...retryOptions }) now wraps the fetch. Retries 408/425/429/500/502/503/504 and network throws; other 4xx return immediately. Exhausted retries surface
  as UploadError with .status and .response.

  Two things worth your attention:

  • Contract change. upload used to return any response, including a 503. It now throws on retryable statuses. Callers checking response.ok will see exceptions instead.
  • Assumption I did not validate: file must be replayable (Blob, File, string). A ReadableStream body is consumed by the first attempt, so retries would send an empty body. If streams are in scope,
    the helper needs a replay guard.
