2. Q4, the v1 load trigger (probes/v1-trigger/). OpenCode 1.19.3 logs no plugin line at INFO or DEBUG, with `--print-logs` on stderr and in its log file, for `debug agent build` and `debug startup` (debug-agent-build.err, debug-agent-build-DEBUG.err; 001's findings record the same for `serve`). `debug agent build` does resolve plugin-registered tools: its output lists `opencode_goal` and `opencode_goal_status` (debug-agent-build.out:799-800). With one plugin broken on purpose in a copy outside the repo, v1 still exits 0 and prints no error (broken-agent.err), so OpenCode 1 gives no per-plugin failure signal at all. The research's log-line oracle (iteration-017 F2, V1-6) does not exist on 1.19.3. Decision: the v1 legs follow 001's decision change 1. `plugin-discovered` reads `opencode debug config </dev/null` into a file and requires every top-level `.opencode/plugins/*.js` file among its `plugin_origins`; `plugin-load` runs an import harness in a child node process that imports each top-level plugin file and calls its v1 entry with a v1-shaped input, as 001's scratch/v1-harness.mjs does. Each v1 command runs with XDG_DATA_HOME pointed at a temporary folder, because v1 opens a database there on start.

3. Q5, the v2 service (probes/v2-private/). 001's decision change 3 already decided that the battery uses a private server. Reprobed here: `opencode2 serve --port <free port>` with OPENCODE_DB and XDG_DATA_HOME in a temporary folder prints `server listening on http://127.0.0.1:<port>` and `server password <value>` on stdout; the password goes to `opencode2 api --server` through OPENCODE_PASSWORD and is never printed. `GET /api/plugin?location%5Bdirectory%5D=<root>` returned 0 entries on four quick reads and then 121 entries, 16 under the worktree's `.opencode/plugins`, all `active`, on four reads 3 s apart (plugin-1..8.json). `/api/skill` answered at once (skill-1.json). The private instance spawned one MCP launcher from opencode.json, which had exited by the time the server was stopped; stopping the server left the process list identical to process-before.txt (process-after-probes.txt). Decision: the v2 leg starts and stops its own private server, never touches the shared service, reads until two consecutive non-zero counts match, up to a fixed bound, and filters entries to source paths under the root.
