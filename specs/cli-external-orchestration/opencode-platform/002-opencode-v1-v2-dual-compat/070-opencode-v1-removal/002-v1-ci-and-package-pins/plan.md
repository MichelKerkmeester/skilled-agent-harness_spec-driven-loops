## 1. SUMMARY

### Technical Context

| Aspect | Value |
|--------|-------|
| **Language/Stack** | GitHub Actions YAML, Bash, Node.js (CommonJS) and npm manifests |
| **Framework** | None. The four suites run under `node --test`; the CI workflow runs them on the runner |
| **Storage** | None |
| **Testing** | `node --test` for the suites; `ruby -ryaml` for the workflow parse; `gh run list` for the CI result after the push |

### Overview
This phase makes the CI workflow test one OpenCode major at the pinned version. It moves the four v1-gated suites into an unconditional step first, so their coverage survives, and then deletes the v1 matrix entry and the both-versions job. It drops the `@opencode-ai/plugin` pin only if the usage check shows that v2 does not need it, and it bumps the OpenCode 2 pin to 2.3.2 in the workflow and the setup helper. The CI proof needs a push, so it waits for the operator's go-ahead.

<!-- ANCHOR:architecture -->
## 3. ARCHITECTURE

### Pattern
One matrix entry for one major. The workflow tests what is installed and pinned, and nothing else.

### Key Components
- **CI workflow** (`.github/workflows/opencode-dual-version.yml`): keeps the battery and the unconditional suite step. It loses the v1 entry and the both-versions job.
- **Package manifests** (`.opencode/package.json`, `.skilled/package.json`): keep only the SDK pins that the usage check shows are used.
- **Compat tests** (`opencode-compat-layout.test.cjs`, `opencode-config-shape.test.cjs`): assert the v2 layout and config only.
- **Setup helper pin** (`V2_PKG` in `opencode-setup.sh`): the single source of the v2 pin for local installs.

### Data Flow
The pin in the setup helper and the workflow installs `@opencode/cli@2.3.2`. The workflow runs the version assertion against it, then the battery and the unconditional suites. No data leaves the runner except the uploaded battery summary.

## 4. IMPLEMENTATION PHASES

Setup checks the npm registry for `@opencode/cli@2.3.2`, the live binary version, the SDK usage and the root `variant` behavior, and records each result in `scratch/`.
Implementation moves the four suites to an unconditional step, deletes the v1 entry and the both-versions job, bumps the pins, applies the SDK and `variant` decisions, and regenerates the lockfiles with npm.
Verification reruns the four suites, parses the workflow, checks the zero-match greps, and claims CI green only after the operator's push go-ahead.

The ordered task list is in `tasks.md`, which owns the Setup, Implementation and Verification checkboxes.

### Files to Change
- CI workflow: `.github/workflows/opencode-dual-version.yml` (unconditional step, v1 entry and `both` job removed, `name:` and v2 pin changed).
- Manifests and lockfiles: `.opencode/package.json`, `.skilled/package.json`, and both `package-lock.json` files, regenerated by npm.
- Compat and config tests: `.skilled/bin/tests/opencode-compat-layout.test.cjs`, `.skilled/bin/tests/opencode-config-shape.test.cjs`, and `default-model-id.test.cjs` (conditional).
- Setup helper pin: `opencode-setup.sh`, changed only at `V2_PKG`, after phase 001 finished with the file.
- Root config: `opencode.json`, changed only if the live `variant` check says v2 does not read it.

The full list with change types is the spec's Files to Change table.
