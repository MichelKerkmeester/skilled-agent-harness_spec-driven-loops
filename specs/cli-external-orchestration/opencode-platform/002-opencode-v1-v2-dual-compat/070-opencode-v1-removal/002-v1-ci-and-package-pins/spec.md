## Phase Context

This is **Phase 2** of the Remove OpenCode v1 support from the repository specification.

**Scope Boundary**: The CI workflow, the two package manifests and their lockfiles, the compat and config-shape tests, the default-model-id test, the v2 pin in the setup helper and the root `opencode.json` variant decision. The setup helper's v1 modes belong to phase 001, and the docs belong to phase 003.

**Dependencies**:
- Phase 001 finished editing `opencode-setup.sh`, so this phase's pin bump does not conflict with it.
- The npm registry has `@opencode/cli@2.3.2`, which T001 checks.

**Deliverables**:
- A v2-only workflow with the four formerly gated suites running unconditionally.
- Pins at 2.3.2, and the package decisions recorded in `scratch/`.

<!-- ANCHOR:problem -->
## 2. PROBLEM & PURPOSE

### Problem Statement
The CI workflow `.github/workflows/opencode-v2-battery.yml` still runs a v1 matrix entry that installs `opencode-ai@1.19.4`, plus a `both` job that installs both majors side by side. Four config-level suites (config-shape, battery, default-model-id and models-form) run only inside the v1 entry, behind `if: matrix.family == 'v1'`. Deleting that entry without first moving them would stop them silently. The v2 pin is `@opencode/cli@2.3.0` in the workflow and in the setup helper, while the installed binary reports 2.3.2. Two package manifests still pin `@opencode-ai/plugin` 1.19.5, and the inventory sweep found no runtime import of either OpenCode SDK package. The compat test still asserts that the v1 SDK is present.

### Purpose
A CI workflow that tests one OpenCode major at the pinned version, with no v1 leg, and package manifests that pin only what v2 uses.
<!-- /ANCHOR:problem -->

<!-- ANCHOR:measured-behavior -->
### Measured Behavior
```text
$ rg -n "family: v1|matrix.family == 'v1'" .github/workflows/opencode-v2-battery.yml

132:        if: matrix.family == 'v1'
```
The two lines are the v1 matrix entry and the gated step that runs the four suites. REQ-001 moves that step and REQ-002 removes the entry, so the same grep prints nothing after the phase.

## 3. SCOPE

### In Scope
- Moving the four v1-gated suites into an unconditional step, then deleting the v1 matrix entry and the `both` job.
- Renaming the workflow's `name:` to describe v2 only, and keeping its file path (see the open questions).
- Bumping the OpenCode 2 pin to 2.3.2 in the workflow, its version assertion and the setup helper.
- Deciding the `@opencode-ai/plugin` pins from a usage check, and updating the two compat tests.
- Deciding the root `opencode.json` `variant` keys from a live check.

### Out of Scope
- The setup helper's v1 modes and `--remove-v1` (phase 001).
- The docs, playbooks and generated artifacts (phase 003).
- Pushing the branch. The CI proof needs a push, and every push needs a separate operator go-ahead.
