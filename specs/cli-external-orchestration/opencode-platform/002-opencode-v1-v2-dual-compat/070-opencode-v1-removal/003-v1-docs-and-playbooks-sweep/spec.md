## Phase Context

This is **Phase 3** of the Remove OpenCode v1 support from the repository specification.

**Scope Boundary**: The cli-opencode skill and its references, assets and playbooks; the plugin and root docs; the cross-skill mentions; the deep-loop protocol and presentation files and their compiled contracts; the feature catalog; the derived trigger index and retrieval fixtures; and the cli-opencode changelog entry. Code changes belong to phases 001 and 002.

**Dependencies**:
- Phases 001 and 002 are complete, so the docs describe the code that exists.
- The `--pure` removal makes the widened test from phase 001 pass (REQ-003).
- A live OpenCode 2.3.2 run needs an explicit model, which the operator names (see the open questions).

**Deliverables**:
- The v2-only docs, playbooks and cross-skill mentions.
- Regenerated compiled contracts, trigger index and retrieval fixtures.
- A cli-opencode changelog entry and the live verification record in `scratch/`.

<!-- ANCHOR:problem -->
## 2. PROBLEM & PURPOSE

### Problem Statement
The cli-opencode skill, its references and playbooks, the plugin docs and several cross-skill docs still describe the v1 install, the v1 launcher and the v1 dispatch. The deep-loop protocol docs and the presentation files show `--pure` in an `opencode run` example, and the inventory records that the flag is absent from the v2 `run` command, so a reader who copies the example gets an error. The trigger index, compiled deep contracts and retrieval fixtures are derived from these docs, so they go stale once the docs change.

### Purpose
Every operator-facing document describes OpenCode 2 only, the derived artifacts match their sources, and the live v2 checks prove the result on the pinned binary.
<!-- /ANCHOR:problem -->

Its baseline is taken again at the start of this phase (T001), because phases 001 and 002 may have changed the count.
