## Findings
- **F1 (P1, root cause — hypothesis CONFIRMED with a decisive refinement).** The claim listener survives from the pre-trust pass into the trusted pass on the shared per-loader event bus, and every final-pass copy stands down. The refinement: the copy that wins the claim is the **user-scope symlink alias** (`~/.pi/agent/extensions/pi-fast-mode-w-subagent-support` → main checkout) loaded by the untrusted pre-trust pass, not any project copy. Real-run trace: one `on` (pass A claim) then one `emit` with `listeners=1` (pass B probe → marked claimed → stand-down).
- **F2 (P1, the zero-flag mechanism).** In the trusted main checkout the alias is **pruned from the final set** by realpath dedupe (alias realpath == project copy realpath; project scope outranks user scope), so the claimed+flagged pass-A entry is discarded while the surviving project copy stood down → zero `--fast`. Final set: 31 extensions, single flagless fast-mode entry. In a worktree the alias realpath (main checkout) differs from the worktree copy, so BOTH entries survive; the pass-A alias entry keeps `flags=[fast]` → exactly one. This explains all four observed counts, including `-a`/`-na` (single-pass, no pre-trust listener, project copy claims).
- **F3 (P1, blast radius).** In the trusted main checkout the stand-down kills the whole extension, not just the flag: the factory returns before `/fast` command registration, status handling and session-start wiring (same early return at src/index.ts:123-124). Inference from the confirmed early return; flag absence is directly observed.
- **F4 (P2).** The extension source comment's model ("Pi ... fails the whole load when two copies register one flag") is contradicted by the loader: conflicts are reported as diagnostics and "precedence is handled by load order" [SOURCE: /Users/michelkerkmeester/.local/lib/node_modules/@earendil-works/pi-coding-agent/dist/core/resource-loader.js:583-585].
- **F5 (P2, claim design).** Recommended design — **gate only side effects on the claim; register the flag before/outside the claim early-return** (minimal change to `claimPackage` usage). Verified by mechanics against all four observed layouts: main trusted → dedupe leaves only the project copy, which registers unconditionally (exactly 1, no conflict); worktree trusted → alias entry + worktree copy both register, conflict is a diagnostic and load-order precedence (project rank 0 first) makes the worktree copy the effective one; untrusted → only the alias copy loads and registers; `-a`/`-na` → single pass, project/worktree copy claims and registers. Residual: `/fast` and other side-effect registrations stay claim-gated, so in the trusted main checkout they remain dead until the deeper fix; full-unconditional registration (drop the claim) fixes everything but runs both copies' handlers in coexistence layouts.
- **F6 (P2, upstream fix path).** Pi-side options: release pre-trust event-bus subscriptions when `reload()` discards the pre-trust set, or have `loadFinalExtensionSet` prefer a final-pass copy over a pruned-path preloaded claim. Runtime-scoping will NOT fix it: the final pass reuses the pre-trust runtime [SOURCE: /Users/michelkerkmeester/.local/lib/node_modules/@earendil-works/pi-coding-agent/dist/core/resource-loader.js:560,577].
- **F7 (P3, ruled out).** Release-on-`project_trust` claim design: refuted in sandbox (the internally re-run pre-trust pass re-claims and is pruned again). Realpath-keyed claims with same-file takeover: fragile across a second `reload()` on the same loader (stale listeners re-mark fresh probes); not recommended without an eviction primitive.
- Observation (method): a harness that calls `loadProjectTrustExtensions()` and then `reload({resolveProjectTrust})` runs the pre-trust pass TWICE and distorts which copy claims; real runs run it exactly once inside `reload()`.

## Questions Answered
- Why does a plain `pi --help` in the trusted main checkout register no `--fast`, and what claim design registers exactly one copy in every layout? — Answered: root cause F1+F2; design F5 (flag registration outside the claim gate), with F6 as the upstream fix and F7 recording refuted alternatives.
