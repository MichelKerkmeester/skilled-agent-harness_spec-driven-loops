## Findings

### A30-1. Architecture decision (the deliverable of this iteration)

**Recommendation: one bridge per surface (behavior translation stays local), converged with ONE shared enforcement layer (disk-derived inventories + explicit exceptions manifests, run in blocking CI).**

What stays per-surface — these four bridges already exist, are merged and documented; each encodes a genuinely different mismatch:

1. **Plugins** — the `dualPlugin` bridge (`lib/v2-bridge.js`): mapped hook set, event aliases, two synthesized stream→event mappings, `skippedKeys` accounting.
2. **Commands/agents/config** — single shared trees via symlinks (`.opencode/commands` → `.skilled/commands`, same for agents) plus the v1-shape `opencode.json` that OpenCode 2 converts on load, guarded against v2-only keys by the config-shape test.
3. **cli dispatch** — the `opencode-version.cjs` version resolver plus per-version argv documentation and a doctor battery that parses `--version` rather than pinning.
4. **Provisioning** — `worktree-provision-paths.txt` driving `provision_worktree` (bun vs npm choice, lockfile-frozen installs).

What becomes shared — a *pattern*, not a module: every surface gets an inventory derived from disk, a test asserting derived-equals-expected, and a manifest-gated exceptions list. Concretely:

- Plugins: a `plugin-inventory` module `readdir`s `.opencode/plugins`, classifies entries (regular `.js` = bridge consumer; symlink/dist bundle = native-dual exception), feeds both v2 suites, and is checked both ways (unlisted entry fails; manifest entry naming a missing file fails).
- Provisioning: a test enumerating tracked `package.json` files under `.skilled/`, `.opencode/`, `.pi/` against the provision list.
- Listings: doctor/listing batteries subtract the non-tree builtins (`init`, `review`) and normalize OpenCode 2's ancestor `.opencode` walk-up before comparing.
- CI: a coverage rule that every suite named in a trigger path has a job that runs it.

**Where enforcement belongs: in tests and CI (blocking), not the doctor battery.** The pinned literals that drifted all live in test suites and prose docs (README count, `PLUGIN_NAMES`, `PLUGINS`, the provision list, the phase-011 proof rows) — the doctor battery already derives its families from `--version` and pins only timeouts/attempt counts. So guards sit where the literals sit: derived-from-disk test assertions plus CI wiring; doctor mirrors them interactively but is not the enforcement point.

**How sk-vision's native-dual exception fits.** It is *designed, not drift*: sk-vision registers a hook key (`chat.message`) outside the bridge's mapped set and needs v2-native surface (`ctx.session.hook("prompt")`, `ctx.tool.transform`) alongside its v1 `server` entry, plus its own venv runtime client. It cannot be forced through the bridge, and it should not be. In the architecture it becomes **Class B: a manifest-gated native-dual exception** — an explicit exceptions manifest (initially just `sk-vision`) with a free-text justification, checked in both directions; its v2 leg keeps its behavior-level coverage in the hard suite; and its hand-maintained v2 context type carries a standing obligation to be re-verified against the published `@opencode/plugin` types at each OpenCode 2 bump (015 f-004). The exception is the sanctioned escape hatch the shared enforcement layer must keep loud, not an architecture violation to eliminate.

**Rejected alternatives (two plus the tempting cheap one):**

| Alternative | Why rejected |
| --- | --- |
| **One shared adapter layer across all surfaces** | The surfaces' mismatch axes are disjoint vocabularies: hook/event names for plugins, markdown-registration and listing semantics for commands, JSON schema shape for config, lockfile/package-manager behavior for provisioning, a runtime protocol for vision. One shared layer must encode the union of all of them — larger than the four bridges it replaces — and still cannot absorb sk-vision (unmapped hook key + native v2 setup + its own venv runtime) without fragmenting into special cases, which recreates the per-surface split one level down. It would also couple all four merged branches' remediation to a single refactor at the moment the run's goal is to *close drift*, not to centralize design. |
| **Migrate everything to sk-vision-style native dual (retire the bridge)** | The 16 bridged plugins are behavior-preserving wraps; the bridge gives them event aliasing/synthesis and `skippedKeys` accounting for free. Rewriting them doubles per-plugin code while OpenCode 1.19.3 remains a supported host, and re-opens the exact regression class that once let `session-relaunch.js` reach main with only a v1 factory. |
| **Keep pinned lists and refresh them during remediation** | Every drift this research found IS a pinned literal: README:77 says "11 plugins" against a 12-entry assertion; the suites' union of lists covers the directory only by coincidence; the provision list is missing five tracked trees; the phase-011 proof rows snapshot "16 plugins" against today's 17. A refresh decays on the next rename; a disk-derived inventory does not. |
