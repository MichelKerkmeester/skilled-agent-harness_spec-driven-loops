## What Was Built

The 11 mechanical plugins now export `{ id, setup, server }` and register on v2 as well as v1. One shared bridge builds every v2 `setup` leg from the unchanged v1 `server`, two core modules hold the moved test seams, a local identity helper replaces the `tool` import, both package folders carry the pins, and one classifier fix removes the last import-time `argv[1]` failure. The plugin suite moved from 303 to 331 passing tests with zero failures, and the v2 read shows all 11 ported plugins active.

### Phase 2: pins-imports-dual-export

The phase changed the export shape of the 11 mechanical plugins, pinned both package folders, added the bridge, the identity helper and two core modules, and moved ten test files to the new shape. Its file list is in `spec.md` section 3, and the recorded deviations sit in the scope note of `spec.md` and the architecture note of `plan.md`.

## How It Was Delivered

The registration file ran first against the unported tree and failed all 11 cases (`scratch/negative-control-registration.txt:12-15`). Luna ported the 11 plugins one dispatch at a time, and the orchestrator ran the registration case and the plugin suite after each one. A bridge review (`scratch/review-1-bridge.log`) and a whole-phase review (`scratch/review-2-phase.log`) followed, and every P0 and P1 item they raised has a fix in the final tree. The orchestrator then reran the registration file, the plugin suite, the v1 harness, the v1 tool-id read, the v2 read and the grep checks from the final state. The strict validator runs at closeout and its only errors are the expected GENERATED_METADATA items that the orchestrator repairs. A round 2 closeout pass then captured the v2 service state and reran the scope comparison after the xcrun cache was removed, closing AC-005 and AC-009 (`scratch/service-state.txt:2-5`, `scratch/scope-check.txt:80-86`). The same pass recorded the child-refusal audit (`scratch/child-refusals.txt:3-45`) and the task and file agreement check (`scratch/doc-agreement.txt:1-22`), and decision 15 amended T031 and CHK-051 so every cited capture is kept (`scratch/decisions.txt:16`).

## Known Limitations

1. **A live v2 `execute` of a bridged tool is not observed.** The result conversion to `{ content, metadata }` is unit-tested and type-checked, and the live call is owed before phase 3 closes (decision 9, `scratch/decisions.txt:10`).
2. **Live v2 session event delivery is not observed.** The `properties.info` mapping for `session.*` events is unit-tested and type-checked (`scratch/bridge-final.txt:1-3`, `scratch/replay-session-event.txt:1-4`), and the phase 1 findings keep the delivery question open (decision 13, `scratch/decisions.txt:14`).
3. **One load-dependent timing test.** An earlier full run had one failure, the timing test "cache TTL starts when CLI work completes", under heavy machine load. It passed 3 of 3 runs alone, passes on main, and passed in the next full run. It is recorded as load-dependent, not a regression (`scratch/evidence.md:15`).
