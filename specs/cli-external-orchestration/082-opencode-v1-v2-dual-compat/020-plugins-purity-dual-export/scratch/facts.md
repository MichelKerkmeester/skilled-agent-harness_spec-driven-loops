# Facts for phase 020 (every claim cites its evidence)

- CI "Spec-Kit Check" on main commit `22f563b032` (run `39373558502`) failed in its "Runtime vitest project" step: `runtime/tests/opencode-plugins-folder-purity.vitest.ts` reported `.skilled/plugins/classifier-injection-screen.js object default export has no recognized OpenCode hook keys`. The project reported 1 failed, 108 passed, 3 skipped test files. Its earlier "CLI vitest project" step passed on that run.
- Why it surfaced only now: the job stops at its first failing step, and the "CLI vitest project" step had failed on every main run since `47371b495f`, so the later "Runtime vitest project" step did not run until `22f563b032` repaired the CLI step.
- Reproduced locally: 1 failed, exit 1 (`scratch/before/plugins-purity-vitest.txt`).
- Cause: commit `f7b54c52db` ("load the eleven mechanical plugins on OpenCode 2") made the plugins default-export `dualPlugin(id, server)` from `.opencode/plugins/lib/v2-bridge.js`, which returns the object `{ id, server, setup }`, where `server` is the v1 factory the host calls. The purity test treats any object default export as a hook object, so every dual plugin fails it; classifier-injection-screen.js is reported because it is the first file in sorted order. `f7b54c52db` is not an ancestor of `47371b495f`, so it reached main after the CLI step was already red.
- Fix: the purity test now recognises the dual export. When the default export has a `server` function it requires a `setup` function, calls `server({})`, and requires the returned object to carry a recognised OpenCode hook key, the same way commit `27763681f7` made the session-relaunch conformance suite call `default.server`. The plain factory and plain hook-object branches are unchanged, and no plugin changed.
- After: the purity test passes, 1 of 1, exit 0 (`scratch/after/plugins-purity-vitest.txt`). The whole Runtime vitest project passes locally: 109 files passed, 3 skipped; 1333 tests passed, 13 skipped; exit 0 (`scratch/after/runtime-project-summary.txt`).
- Main status: Spec-Kit Check is proven only locally so far. A CI run on main has not shown it green yet.
- Mutation probes, each a temporary `.opencode/plugins/zz-mutation-probe.js` deleted after its run, all make the fixed test fail with exit 1: a dual export whose `server` returns no hook keys fails "dual plugin server factory returned no recognized OpenCode hook keys" (`scratch/after/mutation-dual-server-no-hooks.txt`); a dual-shaped object missing `server` and a plain object with no hook keys both fail "object default export has no recognized OpenCode hook keys" (`scratch/after/mutation-dual-missing-server.txt`, `scratch/after/mutation-plain-object-no-hooks.txt`).
- Branch map: all 16 regular plugin files in `.skilled/plugins/` take the dual branch (`scratch/after/plugin-branch-map.txt`).
- Known gap, unchanged by this fix: `sk-vision.js` is a symlink to `../skills/sk-vision/vision-runtime/dist/plugin.js`, so its Dirent is not a regular file and the test never scans it. Its built bundle has the dual shape locally. That target is gitignored and Spec-Kit Check does not build sk-vision, so widening the filter to symlinks would make CI import a missing file; the gap is recorded instead.
- Rerun after all edits: the whole CLI vitest project passes locally, 180 files passed and 3 skipped, 2059 tests passed and 20 skipped, exit 0 (`scratch/after/cli-project-summary.txt`); the Runtime project gave the same counts as above (`scratch/after/runtime-project-summary.txt`).
