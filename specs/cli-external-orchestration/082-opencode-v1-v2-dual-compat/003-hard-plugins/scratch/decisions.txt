Orchestrator decisions for this phase (T003). Evidence: scratch/v2-types.txt (the v2 types survey), scratch/phase1-answers.txt (phase 1 verdicts plus the live re-probe), and phase 2 decisions 8 to 15 (../../002-pins-imports-dual-export/scratch/decisions.txt).

1. Class of system-skill-advisor: hard. It reads session messages through the v1 client (system-skill-advisor.js:1231), and it reacts to `session.compacted` (lines 770 and 1403), an event v2 does not deliver (phase1-answers.txt, live re-probe Q6). Both need the v2 mappings below, so it is ported here, not as a mechanical plugin.
2. Seam homes, one core module per plugin, read only where a test reads the seam:
   - system-completion-sentinel: the seam at line 170 moves to lib/completion-sentinel-core.js. tests/system-completion-sentinel.test.cjs reads it (lines 60, 86, 105, 130).
   - system-spec-gate: no test reads the seam at line 301 (grep over .opencode/plugins/tests), so the seam is removed and lib/system-spec-gate-core.js is not created.
   - opencode-goal: the seam at lines 3364 to 3390 moves to lib/opencode-goal-core.js. Its readers are the goal test files, and the export contract keeps its pinned key list against the core module.
   - system-skill-advisor: no `__test` seam exists, so none moves.
3. The sk-vision named export `SkVisionPlugin` (vision-runtime/src/plugin.ts:13) is removed. Nothing outside the bundle imports it, and parent decision D1 wants one default export. The separate hooks/opencode/sk-vision.ts source is a different file and is not touched.
4. The sk-vision package pin of @opencode-ai/plugin 1.17.15 stays. The bundle uses the type and the `tool` helper only, v1 1.19.3 loads the current bundle (001 baseline), and a pin change would add a bun install to this phase for no load or behaviour gain. The bundle's v2 load is proven by the rebuilt dist on v2, not by the pin.
   Both hosts register the same sk-vision command: v1 keeps `command.execute.before`, and v2 registers the `vision` command through `ctx.command.transform` with the same handler (v2-types.txt, command section). v2 has no command interception hook.
5. Amendment to the per-plugin v2 legs in spec.md section 3 and tasks T009 to T012: the shared bridge from phase 2 (lib/v2-bridge.js) carries the v2 leg for the four JavaScript hard plugins, so each v1 hook body stays unchanged (decision L2) and the v2 mapping lives in one place. The bridge gains three things:
   a. A v1-shaped client built from the v2 ctx, passed as `client` in the v1 input: session.messages over ctx.session.context, session.promptAsync over ctx.session.prompt with delivery "queue", session.create over ctx.session.create, session.prompt over ctx.session.generate, and session.delete over ctx.session.remove (v2-types.txt part 2). The fields v2 cannot provide are listed there and stay absent, never invented.
   b. Event aliases, from the live re-probe: v2 `session.execution.succeeded` is also delivered to v1 hooks as `session.idle`, and v2 `session.compaction.ended` is also delivered as `session.compacted`, each with properties.sessionID and properties.info.id set from data.sessionID.
   c. Any v1 event name the four plugins listen for with no v2 equivalent is recorded as a gap with its evidence (decision L5), not claimed.
   Because lib/v2-bridge.js and its test file are phase 2 files, this phase edits them under this amendment and reruns the phase 2 bridge and registration tests.
6. Orchestrator test edit: the goal port left tests/opencode-goal-tool-path.test.cjs reading an undefined `testDir` (it uses `__dirname`, unlike its sibling tests), which failed 13 of 138 goal tests with a ReferenceError. The orchestrator changed that one identifier to `__dirname`. The goal suite then passed 138 of 138 (scratch/port-b-tests.txt).
7. OpenCode 2 was confirmed as officially released on 2026-10-18 at 2.0.32, the packet's target (../../scratch/v2-official-release.md). The official guide matches decisions 1 and 5: one default export with `setup` for v2 and `server` for v1.
8. Review rulings. The four P1s from the review (kit run p003-review) go to one fix run: idle and compaction alias dedupe, the spec-gate test environment, the sk-vision base64 data URL, and the goal evidence and usage aliases (session.text.ended to message.part.updated, session.step.ended to message.updated). Each was confirmed by the orchestrator first: the spec-gate case fails 8/9 with AI_SESSION_CHILD=1 and passes 9/9 without it; @opencode/schema prompt.js:16-18 types FileAttachment.data as bare Base64; opencode-goal.js:3232-3240 reads only the two v1 message events, which run2-events.jsonl never shows.
9. Recorded v2 gaps (decision 5c), not fixed in this phase:
   a. opencode-goal blocked-by-prompt guard keys on question.asked/replied/rejected. v2 has form.created/replied/cancelled with a different payload. On v2 a pending form does not block the next continuation.
   b. Plugin options. The bridge calls server(input) with one argument, and no port reads ctx.options. A v2 config entry's options reach no plugin. Phase 4 owns the config entry, so the plumbing is deferred there.
   c. system-skill-advisor and system-spec-gate handle session.resumed, server.instance.disposed and global.disposed. v2 has none of the three, so the advisor's resume boundary and runtime-state reset never fire on v2.
   d. sk-vision with SK_VISION_AUTOINSPECT=1 uses the v1 chat.message hook, which the bridge skips. Automatic image evidence is absent on v2; the /vision command still works.
   e. The v1 client shim ignores the {signal} opencode-goal passes, so withDeadline cannot cancel a v2 session call when it times out. The deadline still returns; the v2 call runs on.
10. Fix-run results (kit run p003-fix, then the orchestrator's gates). The orchestrator also wrapped two more spec-gate cases (kill switch off, and the ctx.client fallback) in withEnv('AI_SESSION_CHILD', undefined), because both expect the gate to open and the gate is off for a child session. The plugin suite then passed 353 of 353 both with AI_SESSION_CHILD unset and with it set to 1 (scratch/suite-after-fix.txt, scratch/suite-after-fix-child.txt).
11. Unconfirmed limitation. The bridge maps v2 session.step.ended tokens to v1 message.updated tokens, and the field names match TokenUsage.Info (@opencode/schema token-usage.js). The goal charges each message ID only for its increase over what it already charged. If v2 step tokens count one step rather than the whole message, a multi-step assistant message is undercounted. The schema does not say which, and a live multi-step run would settle it.
12. The sk-vision fix exports a named helper, toV1FileUrl, beside the default export, so the plugin test can reach it. REQ-012 constrains only the default export, which keeps id, setup and server. A throwaway v1 1.19.3 probe (a plugin module with an object default export plus a named function that writes a marker file) showed v1 calls the default's server and never calls the named function. The v2 load check, run after the rebuild, lists sk-vision active. So the helper is not loaded as a plugin on either version.
13. Scope check (scratch/scope-check-003.txt). Every changed path is in spec.md section 3, the phase scratch folder or the parent packet's scratch folder, except four, each ruled in scope here:
   a. .opencode/plugins/lib/v2-bridge.js and tests/v2-bridge.test.cjs. Decision 5 moved the v2 legs into the shared bridge, so the bridge and its tests carry them.
   b. .opencode/plugins/tests/system-spec-gate.test.cjs. The spec-gate seam was removed (decision 2), so its comments and calls changed, and the review's environment fix (decision 10) touched the cases that expect the gate to deny or open.
   c. .skilled/skills/sk-vision/vision-runtime/src/plugin.test.ts. This is the test for the plugin.ts base64 fix, in the source folder that section 3 lists.
   The untracked build output hooks/opencode/sk-vision.js was present before the phase and is not committed.
14. Fix verification (scratch/review-003-verify.txt). DeepSeek closed findings 1 to 4 and found no new P0 or P1. Of its three P2 notes, N1 is decision 11 and N3 is the closure docs. N2 is new and recorded here as gap 9f, not fixed: the bridge aliases only session.execution.succeeded to session.idle, so a v2 turn ending in session.execution.failed or session.execution.interrupted gives the v1 sentinel and goal handlers no idle for that turn. That v1 idles after a failed turn is inferred, not captured, so changing the mapping waits for a v1 failed-turn capture.
15. Finding classes for the four review P1s (CHK-FIX-001). Finding 1, the alias double fire: class-of-bug. Any v2 event the bridge aliases can also arrive natively, so the dedupe covers both aliases, not one. Finding 2, the spec-gate case under AI_SESSION_CHILD: test-isolation. The fix also wrapped the other spec-gate cases that expect the gate to deny or open (decision 10). Finding 3, the sk-vision base64 url: instance-only, the one place that maps v2 attachments. Finding 4, goal evidence and usage: cross-consumer. The aliases deliver v1 message events to every plugin with an event hook, and the verification (review-003-verify.txt, check b) found opencode-goal the only consumer, with sk-vision's v2 setup registering no event hook.
