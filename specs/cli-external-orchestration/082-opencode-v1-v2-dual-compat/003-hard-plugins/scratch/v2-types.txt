THIN SHIM: `client.session.messages({path:{id}, query:{limit, directory}})` — CAN BE BUILT
from ctx.session.context, and the shape can be faked to `{ data: [...] }`.
Fields that would be MISSING or DEGRADED:
  - `parts` array. v2 has no parts array at all: the discriminator is `type` on the message
    itself, user text is `message.text`, assistant text is an element of `message.content`
    with `type === "text"`. A shim must synthesise a parts array.
  - `part.ignored`. CONFIRMED ABSENT: `grep -c "ignored"` over CLG/types.d.ts = 0. The
    sentinel's `!part.ignored` filter (:50) cannot be reproduced; the shim must either drop
    the filter or hardcode ignored=false.
  - `part.synthetic`. Also not present on SessionMessageAssistantText. v1 TextPart had both
    `synthetic?` and `ignored?` (V1S/types.gen.d.ts:142-156). v2 models "synthetic" as a
    separate MESSAGE type (SessionMessageSynthetic, CLG/types.d.ts:566-577), not a part flag.
  - per-part ids / part.messageID / part.sessionID. v2 flattens content to
    { type, text, state? } with no id.
  - `info.role`. v1 used `role: "user" | "assistant"`; v2 uses `type: "user" | "assistant"`.
    Both call-site filters (`info.role === 'assistant'` at sentinel:86, `info.role !== 'user'`
    at spec-gate:99 / advisor:1247) need rewriting, or the shim must map type -> role.
  - `query.limit` / `query.directory`. Not accepted. v2 `context` returns the whole context
    for the session and ignores directory; the shim must slice to the last N client-side,
    and must apply the directory scoping itself (or drop it).
  - `time.completed` is optional on assistant; v1 callers did not read it, so no loss there.
  - response envelope: v2 returns a bare array, not `{ data, cursor }`. Only relevant if a
    shim wants to be byte-compatible with `response.data` — cheap to fake.
NET: the DATA needed by all three readers (last assistant text; last user text) is fully
available. The shim is viable; the only real semantic losses are the `ignored`/`synthetic`
part flags and server-side pagination/filtering.

2.6  SHIM VERDICT
----------------------------------------------------------------------
Could a thin v1-shaped shim (`client.session.messages`, `client.session.promptAsync`, and
the other three methods) be built from the v2 ctx?

  paging/filtering, and the per-call generation overrides (model, agent, system, tools,
