<!-- ANCHOR:problem -->
## 2. PROBLEM & PURPOSE

`sk-design` is referenced across ~180 files. A blind sweep would corrupt frozen historical evidence (benchmark reports, deep-improvement fixtures, past spec docs) and hand-edit generated artifacts (advisor skill-graph, compiled routing) that must instead be regenerated by their own tooling. Before any mutation, every reference must be classified.

**Purpose:** produce `dependency-map.md` — the authoritative, reviewable classification of every `sk-design` / `interface:` / `sk-design-interface` / `sk-design-md-generator` / `styles/` reference, each tagged with its reconcile bucket and the exact action a later phase will take.
<!-- /ANCHOR:problem -->

---

<!-- ANCHOR:scope -->
## 3. SCOPE

**In scope**

- Repository-wide `rg` sweeps for the reference tokens above.
- Classifying each hit into exactly one bucket:
  - **live-contract** — edit in 006 (READMEs, AGENTS.md, README.txt, `cli-*/SKILL.md` Design Standards Loading, agent defs, `opencode.json`, mcp-tooling pairing, deep-alignment adapters).
  - **frozen-evidence** — leave untouched (`**/benchmark/reports/**`, `deep-improvement/**/fixtures/sk-design*`, `specs/**` history).
  - **generated-artifact** — regenerate via tooling in 006 (advisor `skill-graph.json`/corpus, `.opencode/bin/lib/compiled-routing/**`).
  - **to-extract** — moves with the skill in 002 (`sk-design-md-generator/**` + `styles/**`).
  - **to-delete** — removed in 005 (the `sk-design/` hub + `sk-design-interface/**` + `commands/interface/**`).
- Recording per-bucket counts and the exact live-contract file list with a one-line action each.

**Out of scope**

- Any edit to a referenced file (strictly read-only outside this packet).
- Extraction, deletion, or regeneration (those are 002-006).
<!-- /ANCHOR:scope -->

<!-- ANCHOR:requirements -->
## 4. REQUIREMENTS

- **REQ-001** — Run `rg` sweeps for `sk-design`, `interface:`, `sk-design-interface`, `sk-design-md-generator`, and `styles/{lib,library,database}`; capture per-token totals as the reconciliation baseline.
- **REQ-002** — Classify every discovered hit into exactly one bucket per §3 (no unclassified hits).
- **REQ-003** — Emit `dependency-map.md` with a classification table, per-bucket counts, and the live-contract file list carrying a concrete one-line action each.
- **REQ-004** — Confirm the phase mutated nothing outside its own packet folder (`git status`).
<!-- /ANCHOR:requirements -->

<!-- ANCHOR:success-criteria -->
## 5. SUCCESS CRITERIA

- Every `rg`-discovered hit appears in `dependency-map.md` under exactly one bucket.
- The live-contract bucket lists exact paths, each with a reconcile action a later phase can execute verbatim.
- Bucket counts reconcile against a fresh `rg` total (reviewer-diffable).
- `git status` shows only `001-inventory-and-dependency-map/` changed.
<!-- /ANCHOR:success-criteria -->

<!-- ANCHOR:risks -->
## 6. RISKS & DEPENDENCIES

- **Risk: misclassification** — a live contract mislabeled frozen would be silently skipped in 006. Mitigation: reviewer diffs the map's total against a fresh `rg -c` and spot-checks the frozen/generated buckets.
- **Dependency:** none upstream; this is the first child. Downstream, 002-006 all consume this map.
<!-- /ANCHOR:risks -->
