# Phase 010 — design-md-style-reference

**Folder:** `specs/sk-design/019-sk-design-diagram-upgrade/010-design-md-style-reference`

**Objective (parent decision D14).** A diagram delivery can be themed from a Style Reference the way a
chart delivery already is: point the packet at a local `DESIGN.md` — one `sk-design-md-generator` just
produced, or one written by hand — and get a copy of the chosen forms painted in that language, gated
before anything is written. The stock look becomes one reference among several rather than the only
one the packet can draw.

**Read the sibling contract before planning anything.**
`.opencode/skills/sk-design/sk-design-chart/references/design-md-theming.md` and
`.opencode/skills/sk-design/sk-design-chart/scripts/apply-design-md.cjs`. The diagram packet mirrors
its shape: a v3 reference parsed by heading, a role mapping stated in a table, gates read from the
packet's own token source, `RESULT: PASSED` or `RESULT: FAILED` with no output on a failure, no force
option, a URL refused, and provenance written into the palette block as a comment carrying the input
path and the file's SHA-256.

**Where diagrams differ from charts, and the plan must say so.** A chart has four series plus
emphasis; a diagram has structural roles — paper, paper-2, ink, muted, soft, rule, rule-solid, accent,
accent-tint, link, backend-fill — and three skins rather than two grounds. The mapping table has to
name, for each diagram role, which reference rows can fill it and what happens when none can. The
terminal skin has nine roles of its own and no equivalent in a typical reference; decide whether a
reference themes it at all, and state the answer.

**The stock reference and its provenance.** The packet carries one reference under
`assets/style-reference/<name>/` with `DESIGN.md`, `origin.md` and an optional `tokens.json`, so
`--default` has something to derive from. Its `origin.md` must say plainly that it was written FROM
this packet's recorded palette rather than measured from an external product — the chart packet's
reference is a copy of a real library and its provenance says so; ours is not, and claiming otherwise
would be a fabrication.

**The property that makes the default honest.** `apply-design-md.cjs --default` must derive the stock
palette exactly: every role value equal to `assets/color/diagram-palette.json`, and the forms it
writes byte-identical to the shipped ones. That is the same property `--default` already carries in
`apply-diagram-tokens.cjs`, and it is what proves the reference and the corpus have not drifted apart.

**Also deliverable.** `references/design-md-theming.md` written for the diagram packet, a checker
family or an extension of the existing palette family that accepts a `system=design-md` block by its
provenance comment and gates its inline values, and mutation cases for whatever new rule lands.

**What must hold.** `--default` reproduces the stock palette and the stock bytes; a second, different
reference produces a themed copy that passes the gates; a reference missing a required heading is
refused by name; checker `RESULT: PASSED`; suite green.

**Execution model.** DeepSeek V4.1 Flash at max thinking through cli-pi writes the script against the
chart sibling as its worked example; the conductor verifies the two identity properties by running
them.
