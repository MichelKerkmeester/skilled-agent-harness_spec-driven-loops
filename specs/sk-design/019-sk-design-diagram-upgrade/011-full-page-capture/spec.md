## 2. PROBLEM & PURPOSE

### Problem Statement
`render-screenshots.cjs` captures every form at a fixed `1280x900` Chrome window with no full-page option (confirmed empirically in this authoring pass: two-pass measurement shows Chrome's `--screenshot` flag always outputs exactly the requested `--window-size`, never auto-trimmed to content). Six forms in the current corpus lay out taller than 900px — `template-full` (1364px), `example-sequence-oauth` (1004px), `example-sequence-oauth-full` (1411px), `example-sequence-oauth-dark` (1004px), `example-loop-terminal` (1039px) and `example-quadrant-consultant` (1342px) — one more than the six the manual review's S10 named (which omitted `sequence-oauth-dark`) and two more than the first CAP-001 report's "three sequence captures cropped" phrasing. Each loses its bottom section — legend, info card, or footer — in the committed image, which is exactly what hid `template-full`'s P1 legend defect (F1) from a reader working only from the screenshots.

### Purpose
Every committed screenshot shows its form's full content, `sk-design-chart`'s own committed images are provably unaffected, and CAP-001 runs a second time against the corrected captures with each of the first report's five findings recorded as closed or carried forward with a reason.

## 3. SCOPE

### In Scope
- Adding an opt-in `--full-page` CLI flag to `render-screenshots.cjs` that, when absent, leaves capture behavior byte-identical to today.
- A height-measurement pass: for each source file, a temporary copy is rendered with an injected script that reads `document.documentElement.getBoundingClientRect().height` after settle and writes it into the DOM, read back through `--dump-dom` — proven working in this authoring pass (`template-full.html` measured 1364px at a 900px viewport, and a follow-up capture at `--window-size=1280,1364` produced an exact 1364px-tall PNG with no crop).
- Threading the measured height into the real capture of the pristine original file (never the temp copy), so the flag changes only the window size, not the rendered content.
- Re-shooting every HTML form under `assets/diagrams/` (and `assets/icons.html`) into `screenshots/diagrams/` (and `screenshots/icons.png`), and removing the now-orphaned `screenshots/examples/` and `screenshots/templates/` directories.
- Proving `sk-design-chart`'s unflagged capture stays byte-identical: a fresh, unflagged render into a scratch directory diffed against the committed `sk-design-chart/screenshots/` (already confirmed reproducible in this authoring pass — two fresh unflagged renders of `example-bar.html` were byte-identical to each other and to the committed PNG).
- Re-running CAP-001 through `run-manual-playbook-scenario.cjs`, producing a second dated report and addressing the first report's five findings.
- Updating `sk-design-diagram/README.md`'s regeneration snippet to show `--full-page`, and adding the playbook note that a review reads full-page images.

### Out of Scope
- Fixing the dp-integration, venn, template-full or swimlane content defects themselves — 007's job; this phase only records their state in the second CAP-001 report.
- Merging `assets/examples/` and `assets/templates/` into `assets/diagrams/` — 009's job; this phase assumes that directory exists by execution time.
- Reconciling S7-S9 or any doctrine question — 008's job.
- Building a DESIGN.md style reference or a second theming pass — 010's job.
- Any change to `sk-design-chart/`'s own files, its README snippet, or its committed screenshots (D12).
- A new corpus-checker family for capture height — the checker asserts markup and derivation, not rendered pixel dimensions; this phase's height proof is a one-time capture-closure check, not a standing CI gate.

## L2: NON-FUNCTIONAL REQUIREMENTS

### Performance
- **NFR-P01**: Full-page mode spawns Chrome twice per file (one measurement pass, one capture pass) instead of once, roughly doubling wall-clock time for the flagged path only; the default, unflagged path used by `sk-design-chart` is unaffected.
- **NFR-P02**: No throughput target applies beyond completing a 38-file diagram corpus plus `icons.html` in one run, matching today's `render-screenshots.cjs` scale.

### Security
- **NFR-S01**: No new external reachability. The measurement pass renders a local temp copy of an already-local file; the `no-external` corpus family's one-entry Google Fonts allowlist is untouched.
- **NFR-S02**: Temp files created for measurement MUST be removed in a `finally` block, including on error, so no stray file survives a failed run.

### Reliability
- **NFR-R01**: Determinism target: two full-page runs of the same file, on the same machine, produce byte-identical PNGs — the same property already confirmed empirically for the unflagged path in this authoring pass (two fresh renders of `example-bar.html` matched each other and the committed PNG exactly).
- **NFR-R02**: A measurement failure on one file degrades to that file's legacy fixed-height capture rather than failing the entire corpus run.

## L2: EDGE CASES

### Data Boundaries
- A form shorter than 900px (e.g. `example-bar.html`, measured at 813px) shrinks to its true content height under `--full-page` too — this is intended: "none cropped" applies corpus-wide, and every dimension now reflects true content rather than a fixed floor, not only the six previously-tall forms.
- A form whose measured height comes back as `0` or non-numeric (a malformed page, or a page that never fires `load`) MUST fall back to the fixed `HEIGHT` rather than producing a zero-height or malformed capture.
- An unusually tall form (well beyond the current corpus's 1411px maximum) needs no special handling — Chrome accepts an arbitrarily large `--window-size` height.

### Error Scenarios
- `--dump-dom` exits non-zero on the temp copy: the fallback path applies, and the file is named in a printed warning so the reshoot's own output shows which files degraded.
- The CAP-001 rerun hits a named blocker (no local browser, missing Playwright import for whichever step needs it): recorded as `SKIP` with the exact blocker text as the reason, never an empty-reason `SKIP` (REQ-007).

### State Transitions
- 009's merge has not landed by the time this phase executes: the reshoot targets whatever directory layout is actually on disk (`assets/examples/`+`assets/templates/` or `assets/diagrams/`), and REQ-004's target screenshot path follows whichever source layout is real, read at execution time rather than assumed from this spec.
- 007's fixes have not all landed by the time CAP-001 reruns: the second report legitimately carries the unfixed findings forward with a reason, which REQ-007 treats as a valid, non-blocking outcome for this phase.

## 10. OPEN QUESTIONS

- Whether the measurement pass should apply a small safety margin above the raw measured height, or use the raw value exactly. This authoring pass's own test used the raw value with no margin and produced a clean, uncropped capture — left to the implementer to confirm still holds against the full corpus, since a margin that is too large would just reintroduce a smaller version of today's problem (blank space in every capture).
- Whether the second CAP-001 report's verdict should be forced to `PASS` if 007 has not yet closed all four content findings, or should stay `FAIL` with those specific findings carried forward. REQ-007 accepts either as long as the report is honest about which findings are closed and which are not; left to whoever runs the rerun, since it depends on 007's actual state at that time, not on anything decided here.
