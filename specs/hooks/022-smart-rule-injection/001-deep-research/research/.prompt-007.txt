QUESTION
Which repo rules, if any, are better served by a prompt-time injection hook than by the
Gate 5 load, and what keeps such a hook silent on the turns where it adds nothing?

WHY THIS IS OPEN
Repo rules load at Gate 5, which fires on the FIRST WRITE of a session. A read-only turn
never fires it (AGENTS.md, the Gate 5 block). So a rule whose obligation binds while
reading is silent exactly when it is needed. A prior research round refused two proposed
rules for this reason: a context-gathering rule and a design-loading rule. Both wanted to
bind before any write. Neither could.

THE BAR, ALREADY SET BY THIS REPOSITORY — do not re-derive it, apply it
`.opencode/hooks/injection-contract.md` records that two prompt-time directives were
RETIRED because they "restated a disposition every turn, which is what the system prompt
and AGENTS.md already carry", and that the surviving one stays "because it is not a
disposition — it names a specific prohibition a pre-commit gate enforces, and the gate is
what makes it load-bearing." Read that passage. Any candidate you propose must clear that
same bar, and you must say which side of it the candidate falls on.

THE HARD CONSTRAINT
The operator's requirement, verbatim: injections must not spam every message; they need to
be smart. So a proposal is INCOMPLETE unless it states the SILENCE condition — when the
hook does not fire — with the same precision as the trigger. "Fires when relevant" is not a
silence condition. Name the observable signal.

PORTABILITY
The rule corpus is shared by symlink across three repositories whose skills are independent
directories. Hub names are stable across repos; paths inside hubs are not. A hook that
injects rule content must work in a repo laid out differently. Say how, or say the
candidate cannot.
