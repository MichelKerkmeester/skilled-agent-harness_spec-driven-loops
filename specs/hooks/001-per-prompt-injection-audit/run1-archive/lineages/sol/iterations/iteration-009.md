# Iteration 9: Cross-runtime skill-advisor per-turn brief audit

## Focus
This iteration traced the shared skill-advisor producer, renderer, prompt and score thresholds, runtime transports, and full/ambiguous/no-match/error variants. The dispatch focus takes precedence over the strategy's broader fixture follow-up. It preserves iteration 6's established negative result that computation caching is not context deduplication.

## Findings
1. **The canonical payload combines a small prompt-dependent routing signal with a much larger invariant suffix.** Representative source-derived fixtures measure 802 characters/124 words for `Advisor: live; use sk-code 0.95/0.10 pass.` plus directives, 803/124 for stale, and 829/127 for ambiguous; the directives-only suffix is 760 characters/118 words. Thus the single-match routing signal adds only 42 characters while the invariant suffix accounts for about 95% of the full fixture by characters. These are UTF-8/word fixture boundaries, not tokenizer-specific token claims. [SOURCE: .opencode/skills/system-skill-advisor/mcp-server/lib/render.ts:43-69,196-215] [SOURCE: command `node` source-literal measurement: fallback=760 chars/764 bytes/118 words; full=802/806/124; stale=803/807/124; ambiguous=829/833/127]
2. **No-match, below-threshold, absent freshness, and most errors do not produce an advisor line, but still produce all three directives on every valid non-disabled turn.** `renderAdvisorBrief()` returns null unless status is `ok`, freshness is live/stale, and at least one recommendation passes; Claude then substitutes `renderAdvisorFallbackDirective()`. Codex and Devin proxy this behavior; Cursor has the same configured behavior but unconfirmed delivery; Pi imports it and appends its own dispatch directive; OpenCode independently pushes its byte-mirrored fallback for missing prompts, null briefs, and caught errors. Parse failure, missing prompt, a disabled Claude hook, and an uncaught Claude exception instead return `{}` and inject nothing. [SOURCE: .opencode/skills/system-skill-advisor/mcp-server/lib/render.ts:163-215] [SOURCE: .opencode/skills/system-skill-advisor/hooks/claude/user-prompt-submit.ts:162-199,228-256] [SOURCE: .opencode/plugins/mk-skill-advisor.js:785-865] [SOURCE: .opencode/skills/system-skill-advisor/hooks/pi/prompt-advisor.ts:75-106]
3. **There are two distinct gating layers, and the prompt policy already avoids scoring trivial turns without avoiding payload repetition.** Producer invocation skips empty prompts, `/help|/clear|/exit|/quit`, short casual acknowledgements at <=15 visible characters, and prompts below the policy thresholds; it fires for explicit skill/governance markers, work-intent with >=3 meaningful tokens, >=20 characters with >=4 meaningful tokens, or non-casual prompts >=50 characters. Separately, rendering accepts `passes_threshold === true` or the default dual threshold confidence >=0.8 and uncertainty <=0.35. A producer skip becomes a directives-only payload through valid runtime transports, so compute gating does not reduce the 760-character recurring suffix. [SOURCE: .opencode/skills/system-skill-advisor/mcp-server/data/prompt-policy.default.json:3-90] [SOURCE: .opencode/skills/system-skill-advisor/mcp-server/lib/prompt-policy.ts:99-194] [SOURCE: .opencode/skills/system-skill-advisor/mcp-server/lib/skill-advisor-brief.ts:137-228]
4. **Ambiguity is a bounded diagnostic variant, not a reason for a larger always-on policy capsule.** The renderer emits the two-way exact shape `Advisor: {freshness}; ambiguous: {top} {confidence}/{uncertainty} vs {second} {confidence}/{uncertainty} pass.` only when the cap exceeds 80, a second passing recommendation exists, and precomputed or computed ambiguity is true; otherwise multiple passing recommendations still render only the top. The ambiguous fixture cap is 120 versus 80 normally. A complete regression matrix is `{live,stale} x {single,ambiguous}` plus `{no recommendations,below confidence,above uncertainty,absent freshness,unavailable freshness,invalid label}` and transport fallbacks. [SOURCE: .opencode/skills/system-skill-advisor/mcp-server/lib/render.ts:136-145,174-210] [SOURCE: .opencode/skills/system-skill-advisor/mcp-server/tests/compat/plugin-bridge.vitest.ts:146-176]
5. **Stale advice is intentionally model-visible but underspecified for repeated delivery.** Both `live` and `stale` pass the renderer, and the only model-visible distinction is the freshness word; detailed stale reason remains diagnostic metadata. OpenCode caches successful prompt/session/source-signature results for five minutes but appends the cached brief on every system transform, while Claude-family adapters rebuild or use the warm CLI fallback per submitted prompt. This preserves routing under stale graph state but can repeat an unchanged recommendation across consecutive turns even when the user already loaded the named skill. [SOURCE: .opencode/skills/system-skill-advisor/mcp-server/lib/render.ts:167-210] [SOURCE: .opencode/plugins/mk-skill-advisor.js:30-38,684-752,777-855] [SOURCE: .opencode/skills/system-skill-advisor/hooks/claude/user-prompt-submit.ts:202-244] [INFERENCE: repeated unchanged routing after skill load has diminishing value because no transport records acknowledgement or loaded-skill state]
6. **Minimum useful every-turn payload: emit only a changed, passing routing decision; move invariant directives to session policy and suppress no-match fallbacks.** Keep `Advisor: {freshness}; use {skill} {confidence}/{uncertainty} pass.` or the bounded ambiguous form when the selected route differs from the last delivered route, after compaction/recovery, or when freshness changes. Emit nothing for no-match/below-threshold/error because diagnostics already retain status. Deliver comment hygiene, governor, and proof-over-appearance once at SessionStart/AGENTS policy, with one post-compaction refresh where the runtime may lose context. For OpenCode, dedupe by `(sessionID, route label(s), freshness, source signature)` before `output.system.push`; for command-hook runtimes persist the same small session fingerprint; for Pi retain its independent dispatch directive until its separate policy is redesigned. This removes the 760-character suffix from routine turns without changing prompt scoring, dual thresholds, ambiguity, or error fail-open semantics. [INFERENCE: based on the payload split in findings 1-5 and existing lifecycle delivery surfaces documented in .opencode/hooks/injection-contract.md:44-83,187-217]

## Ruled Out
- Lowering or bypassing confidence/uncertainty thresholds: this increases low-quality routing and does not address the invariant suffix.
- Treating prompt-result or bridge caching as context deduplication: cached text is still appended.
- Moving prompt-dependent selection wholly to SessionStart: the selected skill depends on current user text.
- Using the 80/120 caps as total payload caps: `capText()` applies before directives are concatenated, so the 760-character suffix sits outside that cap.

## Dead Ends
No new source path is exhausted. Runtime transcript capture remains necessary to measure actual tokenizer cost and Cursor editor delivery, but it is not needed to establish the source-level payload split.

## Edge Cases
- Ambiguous input: the strategy proposed a broad shared fixture policy; dispatch explicitly narrowed this iteration to the advisor brief, so unrelated SessionStart axes were deferred.
- Contradictory evidence: comments describe directives as deliberately every-turn, while the same policy is also available through always-on repository instructions; this iteration treats duplication as runtime/context-dependent rather than claiming every host always loads AGENTS.md.
- Missing dependencies: the expected `mcp-server/dist/lib/render.js` import path was absent, so fixture sizes were derived independently from the canonical source literals; no build or out-of-scope write was performed.
- Partial success: tokenizer-specific counts and live consecutive-turn transcripts were not obtained; exact character, UTF-8 byte, word, branch, and threshold boundaries were obtained.
