- **CONFIRMED** — live-run or direct-read evidence collected this phase, cited above.

## Fixed Parity Tiers (feeds phases 003/004/005)

- **Devin (003)**: Injection-only at session/prompt boundaries (confirmed prior packet) **plus verify/continue via `Stop` + `decision:"block"`, now CONFIRMED live**. Devin gets the full injection-plus-verify/continue tier.
- **Cursor (004)**: `sessionStart`-once injection only. `preToolUse` `agent_message` CANNOT deliver a mid-session refresh (confirmed non-delivery into model context this phase). No verify/continue mechanism exists (`stop` never fires; no hook exposes a block/continue decision). Cursor is capped at injection-only, sessionStart-once.
- **Pi (005)**: Injection-plus-verify tier confirmed for the event surface itself — `turn_end`/`agent_end`/`agent_settled` give a real, subscribable turn/agent-boundary verify trigger distinct from `session_shutdown`. However these handlers have no result type (`void`), so Pi's adapter cannot force continuation via a handler return value the way Devin's `Stop` can; an auto-continue mechanism (if any exists, e.g. queuing a follow-up turn) is UNKNOWN and unprobed this phase. Pi gets injection-plus-verify (turn/agent-end observable), auto-continue tier UNKNOWN — phase 005 should probe/design around this before assuming Claude/Devin-style forced continuation.
