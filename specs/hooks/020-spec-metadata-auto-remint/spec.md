## 2. PROBLEM & PURPOSE

### Problem Statement

Every spec packet carries a `graph-metadata.json` holding a fingerprint of the documents it was derived from, plus fields summarised out of them. Editing `spec.md` or any sibling doc invalidates the fingerprint, and nothing local says so. `validate.sh` reports it, but only for the folder someone thinks to run it against, so the staleness accumulates unseen. A repository sweep found 460 of 2,834 packets carrying one, roughly one in six, spread evenly across every track. That is what happens when a derived artifact's regeneration is left to a human who has no reason to remember it at the moment they edit.

### Purpose

The backlog is cleared, and a packet's derived metadata is regenerated in the same commit as the edit that invalidated it, so the count does not climb back.
<!-- /ANCHOR:problem -->

<!-- ANCHOR:scope -->
## 3. SCOPE

### In Scope
- One repository-wide application of the existing repair tool, clearing the stale fingerprints
- One blocking gate block in `.opencode/scripts/git-hooks/pre-commit` that re-derives an edited packet's metadata and stages it
- Refusal paths for the two cases where regenerating would produce a lie rather than a fix
- Test coverage in the existing hook harness, which already covers the routing gate this one is modelled on

### Out of Scope
- **`specs/sk-design/019-sk-design-diagram-upgrade`.** Another session was writing to it during the sweep. Repairing a tree someone is mid-edit in would collide with their work
- **The repair tool itself.** It is correct and already had a `--roots` mode. Nothing about it needed changing, only its being run
- **A CI backstop.** The remote-side check for this class already exists in the validation workflow

### Files to Change

| File Path | Change Type | Description |
|-----------|-------------|-------------|
| `.opencode/scripts/git-hooks/pre-commit` | Modify | The new gate block |
| `.opencode/scripts/git-hooks/tests/pre-commit.test.sh` | Modify | Eight cases, and the harness renamed for two gates |
| `specs/**/graph-metadata.json`, `specs/**/description.json` | Modify | Regenerated by the sweep |

## 4. REQUIREMENTS

### P0 - Blockers (MUST complete)

| ID | Requirement |
|----|-------------|
| REQ-001 | No packet outside the excluded subtree reports a stale fingerprint after the sweep |
| REQ-002 | A commit that stages a spec document leaves that packet's derived metadata regenerated and staged |
| REQ-003 | A packet whose documents are staged and unstaged at once is refused rather than derived from a tree the commit does not carry |
| REQ-004 | A commit whose pathspec narrows it to a throwaway index is refused, because git discards that index |

### P1 - Required (complete OR user-approved deferral)

| ID | Requirement |
|----|-------------|
| REQ-005 | A commit staging no spec document does no work and says nothing |
| REQ-006 | A document's packet is the nearest ancestor carrying `graph-metadata.json`, so a phase child resolves to itself rather than its parent |
| REQ-007 | The gate carries a bypass flag in the house style and fails closed if the repair tool errors |

<!-- ANCHOR:risks -->
## 6. RISKS & DEPENDENCIES

| Type | Item | Impact | Mitigation |
|------|------|--------|------------|
| Risk | The sweep rewrites 460 files at once | Med | Every write is a tracked regenerated file, so `git checkout -- specs` undoes the whole sweep in one command. The tool is the one the validator itself points at |
| Risk | The sweep collides with a session mid-edit | Med | The one subtree with uncommitted work was excluded by name, and the exclusion is recorded rather than left implicit |
| Risk | The gate stages a file the author did not stage | Low | Scoped to two generated files in a packet whose document was already staged, printed by name on every run, and deterministic from those documents |
| Risk | The gate fires on every commit and slows it down | Low | It shells out only when a spec document is staged, and the repair is a no-op for most edits, which the harness covers as its own case |

<!-- ANCHOR:edge-cases -->
## L2: EDGE CASES

### Data Boundaries
- A file under `scratch/`: not a packet document, so it does not trigger the gate
- A file under `z_archive/`: retired history, deliberately not re-derived
- A document with no packet above it: skipped, because the walk ends at `specs/`

### Error Scenarios
- The repair tool errors: the gate blocks and prints the tool's own output
- The repair writes nothing: the common case, and the gate stays silent rather than claiming work
- The staging silently fails: confirmed against the index before the commit is allowed through

### State Transitions
- A phase child and its parent both carry metadata. The nearest ancestor wins, so editing a child never re-derives the parent instead
