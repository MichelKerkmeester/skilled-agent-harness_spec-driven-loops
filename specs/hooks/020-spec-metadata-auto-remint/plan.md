## 1. SUMMARY

### Technical Context

| Aspect | Value |
|--------|-------|
| **Language/Stack** | Bash git hook over a Node repair tool |
| **Framework** | The existing pre-commit gate chain |
| **Storage** | None |
| **Testing** | The hook's own harness, run against the real hook file |

### Overview
Two halves, and the second is what makes the first stay true. The sweep uses the tool the validator already names in its own failure message, so nothing new had to be written to clear 460 packets. The gate is a near-copy of the compiled-routing re-mint gate added days earlier, because the two problems are the same problem: a derived artifact whose regeneration is left to a human at the one moment they have no reason to think about it. Copying that gate's shape also copies its refusals, which are the part that took the measuring.

<!-- ANCHOR:architecture -->
## 3. ARCHITECTURE

### Pattern
Auto-fix rather than block-and-instruct, which is the exception in this hook chain and is confined to derived artifacts whose content follows mechanically from the staged input.

### Key Components
- **The path walk** resolves a staged document to its packet by finding the nearest ancestor carrying `graph-metadata.json`, so depth never has to be assumed
- **The two refusals** cover the cases where regenerating would describe content the commit does not contain
- **The staging proof** confirms the regenerated files reached the index, because no later local gate can see that they did not

### Data Flow
A staged document resolves to its packet. The packet is checked for partial staging, re-derived, and its two generated files staged and confirmed. A no-op repair, which is the common case, stages nothing and says nothing.

## FIX ADDENDUM: AFFECTED SURFACES

| Surface | Current Role | Action | Verification |
|---------|--------------|--------|--------------|
| `pre-commit` | The gate chain every commit runs | One new block | The harness, run against the real file |
| `pre-commit.test.sh` | Covers the routing gate | Eight cases added, harness renamed for two gates | 17 of 17 pass |
| Every packet's `graph-metadata.json` | Carries the fingerprint validate.sh checks | Regenerated where stale | A dry run reports zero repairable |
| `repair-derived.cjs` | The tool doing the work | Unchanged, only run | It is what the validator's own failure message names |
| `sk-design/019` subtree | Another session's live work | Excluded by name | Recorded in scope, not left implicit |

Required inventories:
- Stale packets: `repair-derived.cjs --roots specs` reports the count, and per-track runs localise it.
- Algorithm invariant: a document's packet is the NEAREST ancestor carrying `graph-metadata.json`. Walking to the first or the outermost would re-derive the wrong folder and leave the real one stale, which the harness covers with a phase-child case.

<!-- ANCHOR:rollback -->
## 7. ROLLBACK PLAN

- **Trigger**: the gate blocking commits it should not, or staging something unexpected
- **Procedure**: `git revert` the commit. The hook is a symlink to the tracked file, so the previous behaviour returns with no reinstall. The sweep half reverts with it, restoring 460 stale fingerprints, which is a return to the prior state rather than a new problem
<!-- /ANCHOR:rollback -->
