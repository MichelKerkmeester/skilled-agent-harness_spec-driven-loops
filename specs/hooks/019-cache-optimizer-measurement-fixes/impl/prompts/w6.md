Three separate fixes in `.pi/extensions/pi-cache-optimizer/index.ts`, its tests, and its README.
Read each site before editing. Keep them small.

## Fix 1 — the capability flag can be silently ignored

`message_end` reads the flag as `getCompat(statsModel).reportsCacheUsage` (around `index.ts:9642`).
For a virtual-routing provider, `statsModel` is derived from the assistant message and may carry no
`compat` at all, so a model that declares `reportsCacheUsage: false` would be ignored and its
requests counted as measured misses — exactly what the flag exists to prevent.

Resolve the flag so a declaration is honored: prefer the stats model's compat when it actually
carries the field, and fall back to the active model's compat when it does not. Do not invent a
precedence rule beyond that.

**Test through the handler, not by passing the flag directly.** The existing tests hand the flag
straight to the recording function, which is why this gap survived. Add a test that drives
`message_end` with a virtual-routing shaped model whose stats model lacks compat, and assert the
declaration is still honored.

## Fix 2 — a learned key rejection can never be unlearned

`promptCacheKeyUnsupportedModels` is monotonic. Nothing deletes from it, the `reset` subcommand
(around `index.ts:9867`) does not touch it, and the persist writer merges whatever is already on
disk, so clearing memory cannot remove an entry. One 400 from a transiently misconfigured proxy
therefore disables key injection for that model permanently, until someone hand-edits the state file.

Give it an unlearn path: `reset` must clear the learned rejection for the active model, and that
clearing must survive the merge in the persist writer rather than being reinstated from disk.

Prove it: after a rejection is learned and persisted, `reset` removes it, and a fresh load does not
bring it back.

## Fix 3 — document the flag

`reportsCacheUsage` is undocumented. Add it to the extension README beside the other compat flags:
what it does, what unset means, and that `false` routes requests to unmeasured rather than to a miss.
