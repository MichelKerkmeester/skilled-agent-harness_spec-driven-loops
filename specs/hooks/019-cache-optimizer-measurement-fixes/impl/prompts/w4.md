## The defect

`optimizeSystemPrompt` lifts every uniquely-occurring candidate to the front of the prompt during
the same `before_agent_start` call that first sees it (`index.ts:9136` area). Nothing requires the
content to have been observed unchanged across turns first. A candidate that looks stable once and
then changes has already been promoted, and moving prompt content is precisely what destroys a
cache prefix.

The churn map (`index.ts:8485`) is model-keyed, report-only, and records empty shipments
(`:9145-9151`), so it cannot serve as the authorization record.

## What to build

Gate promotion on having observed the candidate unchanged across at least two turns.

- Keep **authorization state separate from churn state.** Churn is a measurement; authorization is
  a decision. Reusing the churn map for both is the mistake to avoid.
- Authorization must be isolated per session AND per model. Session B must not inherit session A's
  authorization.
- A reset or a disable must clear it.
- First turn is therefore conservative: nothing is lifted on first sight. That is the intended
  behavior change, not a regression.

## Proof required

1. An A/A/B/B turn sequence: turn 1 does not lift, turn 2 lifts, and the sequence is asserted
   explicitly rather than inferred from a hit rate.
2. A candidate occurring twice in one prompt stays unlifted, preserving the existing uniqueness rule.
3. Session isolation: session B does not inherit session A's authorization.
4. Model isolation: the same content under a different model is authorized separately.
5. Reset or disable clears authorization.
