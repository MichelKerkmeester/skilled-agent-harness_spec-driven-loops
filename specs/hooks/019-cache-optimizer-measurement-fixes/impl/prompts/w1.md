## The defect, already traced

Two sub-cases hide under one description, and a fix aimed at either alone misses the other:

- **(a) Omitted fields.** `getPiNormalizedUsage` (`index.ts:2478`) already computes
  `hasCacheSignal = cacheRead !== undefined || cacheWrite !== undefined`, then discards it by
  returning `cacheRead: cacheRead ?? 0`. Absence collapses into a measured zero and is counted as a
  miss. The raw adapter readers (`:2541`, `:2567`, `:2610`) have the same shape.
- **(b) Defined all-zero usage.** Flagged at `:9483` but still counted at `:4188`.
  `hasMissingUsageFields` returns `false` whenever `input > 0` (`:4280-4282`), so a fix wired only
  to that flag never reaches case (a).

## What to build

One rule covering both. Classification is by **field presence**, not by value.

- Add `unmeasuredRequests` to the persisted stats record so the exclusion is visible, not silent.
- **Cost and tokens ALWAYS record.** `totalInputTokens`, `inputCostUsd` and
  `uncachedBaselineCostUsd` must include every request, whether or not a cache signal was reported.
  Real spend happened on those requests; hiding them understates Baseline and Savings, which is a
  worse failure than the ambiguity being fixed.
- **Only the hit ratio excludes.** `hitRequests` and the measured denominator skip an unreported
  sample. `totalRequests` keeps its current meaning so no existing reader shifts under it.
- Migrate the persisted record forward: an existing file must load with counters intact and the new
  field defaulting to 0.
- Update the stats output so an unmeasured count is visible rather than silently folded away.

## Proof required — write these tests

1. `{input: 500}` with no cache fields: `unmeasuredRequests` +1, `totalInputTokens` +500, cost
   recorded, `hitRequests` and the measured denominator unchanged.
2. Negative control: explicit `{cacheRead: 0, cacheWrite: 0, totalInput: 500}` counts as **one
   measured miss**, NOT unmeasured. This is the line the whole change turns on.
3. Negative control: `usage === undefined` adds nothing at all.
4. Migration: a stats record written before this change loads, keeps its counters, and reads the
   new field as 0.

Each new test must fail with your change reverted. Say in your reply which test covers which case.
