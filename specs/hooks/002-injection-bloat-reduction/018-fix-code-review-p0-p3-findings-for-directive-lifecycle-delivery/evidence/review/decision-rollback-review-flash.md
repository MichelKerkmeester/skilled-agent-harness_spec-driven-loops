# Decision and Rollback Review (deepseek-v4-flash)

Scope: `018-fix-code-review-p0-p3-findings-for-directive-lifecycle-delivery`. Reviewed 2026-08-11 packet docs against the shipped code and evidence artifacts. All citations are to files read or grepped during this review; where a claim could not be verified from an artifact, it is marked UNCONFIRMED.

## A. Decision soundness — verdict: still Accepted

ADR-001 (decision-record.md, "Decision" section) chose Option A: host-wired lifecycle epoch, store-wide invalidation generation, transcript high-water state, race-safe no-follow store, conflict-aware identity confirmation, typed evidence classes, and an immutable whole-gate baseline. The shipped implementation matches the decision on every load-bearing element:

- **Epoch + store-wide generation + high-water**: implementation-summary.md "What Was Built" confirms the canonical contract uses "trusted per-session epochs, store-wide invalidation for unidentified boundaries, transcript high-water updates on eligible repeat turns, and deferred full-delivery receipt commits". plan.md §3 Architecture describes the same state machine (`lifecycleEpoch`, `storeGeneration`, `transcriptHighWaterBytes`).
- **Kill-switch (Option C retained as rollback)**: decision-record.md "How to roll back" names both envs. Both are real and wired:
  - `SPECKIT_DIRECTIVE_LIFECYCLE_DEDUP` defined at `.opencode/skills/system-skill-advisor/hooks/lib/directive-lifecycle-contract.ts:5`; consumed by `isDirectiveLifecycleDedupEnabled()` at `.opencode/skills/system-skill-advisor/hooks/lib/directive-lifecycle.ts:38-41` — default ON, `0`/`false`/`off`/`no` restores always-full. The shared Claude shim passes it into the canonical decision at `.opencode/skills/system-skill-advisor/hooks/claude/user-prompt-submit.ts:310-317`; the OpenCode mirror declares the same env at `.opencode/plugins/mk-skill-advisor.js:66`. Kill-switch behavior is tested at `.opencode/skills/system-skill-advisor/mcp-server/tests/hooks/directive-lifecycle.vitest.ts:192,246`, `claude-user-prompt-submit-hook.vitest.ts:406` (DL4), and `mk-skill-advisor-plugin.vitest.ts:831-832` (PL5). Reach to Codex/Cursor/Devin is via the shared shim per `.opencode/hooks/injection-contract.md:65` (documented, not re-verified per-runtime in this review).
  - `SPECKIT_PI_DIRECTIVE_DEDUP` defined at `.opencode/skills/system-skill-advisor/hooks/pi/prompt-advisor.ts:180`; consumed by `isPiDirectiveDedupEnabled()` at `prompt-advisor.ts:186-189`; `decidePiDirectiveDelivery()` returns FULL immediately when disabled at `prompt-advisor.ts:223`.
- **Rejected alternatives still valid**: Option B (heuristic-only) was rejected in decision-record.md "Alternatives Considered" and remains so in plan.md "L3: ARCHITECTURE DECISION RECORD" ("cannot close host epoch or storage injection findings"). Option C was never promoted to final state — implementation-summary.md "Key Decisions" retains it strictly as "always-full delivery as rollback".
- **Stated consequences hold**: route-only high-water writes are bounded — RR-002 (spec.md §4) records file-store p99 65.706 ms under the 100 ms budget; native-host proof stays unconfirmed — the benchmark index lists `cursor-native-host-verified` as SKIP (`.opencode/skills/system-spec-kit/benchmark/reports/README.md` §2); mirror drift is tracked as RR-001 (spec.md §4).

No contradiction between the accepted decision and the shipped code was found. The fresh review (`review/review-report.md`: verdict CONDITIONAL, 0 P0, 2 P1, 19 P2, converged) and its adjudication (`evidence/review/fresh-deep-review-disposition.md`, both P1s resolved or demoted to RR-006) further corroborate the decision. Residuals RR-001…RR-006 are declared risk, not decision reversal.

**A verdict: still Accepted.**

## B. Rollback and evidence supersession — verdict: sufficient (with gaps)

Kill-switch portion — concrete and verified: setting `SPECKIT_DIRECTIVE_LIFECYCLE_DEDUP=0` (Claude/Codex/Cursor/Devin/OpenCode) and `SPECKIT_PI_DIRECTIVE_DEDUP=0` (Pi) restores always-full delivery. Verified at the two decision sites (`directive-lifecycle.ts:38-41`, `prompt-advisor.ts:186-189,223`) and by three test surfaces (see A). The env values stated in decision-record.md "How to roll back" match the feature catalog (`.opencode/skills/system-spec-kit/feature-catalog/ux-hooks/directive-lifecycle-dedup.md:48-49`) and ENV-REFERENCE (`.opencode/skills/system-spec-kit/mcp-server/ENV-REFERENCE.md:206-207`).

Ordering — correct: decision-record.md "How to roll back" and plan.md "L2: ENHANCED ROLLBACK" sequence the same five steps: (1) enable kill-switch and verify two consecutive full deliveries, (2) revert packet-owned changes, (3) rebuild dist + invalidate contained state, (4) rerun the identical whole-gate manifest, (5) reconcile parent/phase status with 017 kept superseded. State and evidence rollback are also concrete: version-mismatched records are rejected and the contained state directory is cleared only after owner/no-follow validation; immutable reports are superseded via append-only manifest entries (plan.md §7 "ROLLBACK PLAN").

Evidence supersession — clearly marked at the index level: `.opencode/skills/system-spec-kit/benchmark/reports/supersession-manifest.json` (schemaVersion 1) maps every superseded run folder to its replacement with `capturedAt`; the reports index README warns "Consult supersession-manifest.json before treating an older row as current" (README.md §1). Old folders remain present and unmodified — the intended append-only design (spec.md REQ-P1-006).

Gaps found:

1. **No stored phase-018 diff snapshot** (medium). The code-rollback step "revert only the phase 018 implementation diff" (decision-record.md "How to roll back") depends on a captured baseline diff, and plan.md "L2: Pre-deployment Checklist" claims "[x] Whole-gate baseline and diff snapshot captured". No diff/patch artifact exists in the packet evidence: `find` for `*diff*`/`*patch*` returned nothing, and `evidence/whole-gate/baseline/` contains only logs, results, manifest, and hashes. The only pre-implementation snapshot is `evidence/inventory/dirty-checkout.txt`, which lists pre-existing dirty paths (a status inventory, not a diff). Given implementation-summary.md "Known Limitations" #5 ("working tree is broad and dirty; nothing is staged, committed, or pushed"), "revert only the phase 018 implementation diff" is not mechanically executable from stored artifacts as written — the operator would have to reconstruct the packet's changes.
2. **Current-state requires chain-walking the manifest** (low). Supersession entries are one-hop mappings; several folders are superseded twice (e.g., `--claude-adapter` → `--claude-registered-path-final` → `--claude-registered-path-verified`, and the Pi chain has three hops ending in `--pi-repeat-suppression-verified`). The manifest has no explicit `isCurrent` flag and the README index carries no per-row superseded marker, so "current" must be derived by resolving to an entry never re-superseded. This is acceptable under the immutable-folder design (spec.md REQ-P1-006) but is a small tooling/maintenance trap.
3. **Stale "Fresh deep review | PENDING" row** (low/informational). implementation-summary.md "Verification" lists the fresh deep review as PENDING while `review/review-report.md` (CONDITIONAL, 0 P0, 2 P1, 19 P2, converged) and `evidence/review/fresh-deep-review-disposition.md` (both P1s adjudicated) already exist. implementation-summary.md "Known Limitations" #6 declares metadata intentionally stale until review, so this is declared drift rather than a false claim; it must be reconciled at closeout.

**B verdict: sufficient with gaps — the kill-switch half of a full revert is concrete, ordered, and verified; the git-revert half is not fully executable as documented because the phase-018 diff was never captured as an artifact. Superseded evidence is externally marked and cannot be mistaken for current if the manifest is consulted; per-row/current-state marking is a minor improvement.**

## Verdict

- **A — Decision soundness: still Accepted.** ADR-001's chosen approach, rejected alternatives, and consequences are all consistent with the shipped code; the only rollback escape (Option C) is implemented and tested on both env surfaces.
- **B — Rollback and evidence supersession: sufficient, with gaps.** Kill-switch revert is concrete, correctly ordered, and fully verified for all five runtimes plus Pi. The git-revert half depends on a phase-018 diff snapshot that was never stored — close that gap (Finding 1) before any code-rollback dependency is relied upon. Superseded evidence is externally marked via manifest + index warning; minor readability gaps (Findings 2-3) do not permit old runs to pass as current when the documented consultation step is followed.
