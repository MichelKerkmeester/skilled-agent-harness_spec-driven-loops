### Overview
The change edits the canonical texts first: the mode's SKILL.md, its README example, its review-core schema, and the review agent in `.skilled/agents`. The Claude fork gets the same three edits by hand, because no generator writes it. The Codex, Pi and Hermes copies are regenerated, never hand-edited. The compiled sk-code manifest is re-minted last, because it fingerprints the skill root, and a copy goes to the archived location the phase 002 pattern uses. A new ES module checker enforces the case line and the single numbering on any review output, with four harness cases that cover pass, missing case, restarted numbering and an output with no findings.

## 3. ARCHITECTURE

### Pattern
Canonical text, then generated and hand-kept copies, then derived manifests. The canonical sources are `.skilled/skills/sk-code/sk-code-review/SKILL.md`, its `references/review-core.md`, and `.skilled/agents/review.md`. Everything else follows from those.

### Key Components
- **Mode contract (`sk-code-review/SKILL.md`)**: holds the Phase 1 connected-code step, the Phase 3 numbering rule and the output template with the Case line.
- **Schema and example (`references/review-core.md`, `README.md`)**: the Case field, the list-number id and the example finding with its Case line.
- **Review agent (`.skilled/agents/review.md`)**: the reproducing case in the evidence table, the connected-code planned reads, and the report order.
- **Hand-kept fork (`.claude/agents/review.md`)**: the same three edits, applied by hand, with the frontmatter and path lines left as they are.
- **Checker (`scripts/check-review-findings.js`)**: reads one review output and fails a numbered finding with no `Case:` sub-line or a number that restarts or skips. It is an ES module with the same exit contract as `check-review-final-line.js`.
- **Harness (`scripts/check-rule-copies.test.sh`)**: runs the canary on the real tree, then the four new checker cases.
- **Generators**: `codex/sync-agents.cjs`, `pi/sync-agents-pi.cjs`, and `hermes/sync-skills-hermes.cjs`, which write only the changed copies.
- **Manifests**: `sk-code/leaf-manifest.json` (regenerated, expected to keep its bytes) and `.skilled/bin/lib/compiled-routing/.../sk-code/manifest.json` (re-minted, then copied to the archived location).

### Data Flow
`SKILL.md` and `review.md` change. `sync-skills-hermes.cjs` writes the two Hermes copies, `sync-agents.cjs` writes the Codex copy, and `sync-agents-pi.cjs` writes the Pi copy. The fork is edited by hand, and the mirror checks confirm the copies agree. The leaf manifest is regenerated from the skill root. The compiled manifest is re-minted from the skill root and copied to its archived location, and `cmp` confirms the copy. A review output passes through `check-review-findings.js` and `check-review-final-line.js`.
