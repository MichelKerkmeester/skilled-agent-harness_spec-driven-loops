## Findings

1. **Hub admission is warn-only by construction: the CI step cannot fail.** `compiled-route-admission.cjs` documents `--warn-only report, but always exit 0` (:19) and "Exit codes: 0 every hub passes (or --warn-only), 1 a hub fails" (:21); `main()` returns 0 whenever `report.ok || args.warnOnly` (:104), and the entry point assigns only `process.exitCode = main()` (:109). The workflow runs exactly that flag combination (`node .skilled/bin/compiled-route-admission.cjs --all --warn-only`, routing-registry-drift.yml:180) with a stated reason: "Warn-only until the first baseline is triaged: it records engine drift and stale gold against admitted hubs, and a blocking step would fail every unrelated push on them" (:175-177). The admission check judges hubs on drift, stale gold and coverage floors — a scored scenario for every declared workflow mode plus at least one negative or defer scenario (:9-12). Net: today's hub admission is telemetry, not enforcement; any parity or evaluation check must not inherit that posture. ## Questions Answered

- **Q3: How do the evaluation set and the parity check stay cheap to run and honest, given ties at confidence 0.82 and hub admission running in CI with --warn-only?** — Cheap: run the scorer-level parity gate inside the full-install job that already pays the advisor install and imports the real scorer, reuse the ratchet's batched Python subprocess plus in-process native calls instead of per-prompt CLI spawns, and keep static checks (corpus pins, overlap set algebra) in the lean python-equipped job (Finding 2, Finding 6). Honest: 0.82 is a floor-collision value, not a measurement; both paths resolve ties deterministically ending on skill-name ascending, so tie-induced divergences are stable and must go through the approved-divergence ledger, not threshold nudging (Finding 3); pin corpus inputs by sha256 and pin floors like the existing corpus gate does (Finding 4); never place the check in or behind the `--warn-only` admission step, which cannot fail by construction (Finding 1). Caveat attached: no CI-minute measurement was performed, so the added cost is structural.
- **Q4: Which existing harnesses, fixtures and CI jobs can each recommendation extend in place, so the move stays as low as possible on the prevent-overengineering reversal-cost order?** — Parity check: extend local-native-divergence-ratchet.vitest.ts plus the approved-divergence ledger fixture, run in the existing golden-prompt-gate job (Finding 2, Finding 6). Evaluation set: extend the existing holdout gate and corpus-pin mechanics in the same job (Finding 4). The one non-extendable piece: the 17+5 battery script in the packet's scratch/ directory has no runtime home yet (Finding 5).
