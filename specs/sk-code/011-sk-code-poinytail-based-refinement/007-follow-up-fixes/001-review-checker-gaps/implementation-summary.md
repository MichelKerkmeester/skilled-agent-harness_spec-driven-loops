## What Was Built

The review final-line checker now rejects the four outputs its contract forbids, and each rejection prints a named reason. A skip status passes only as the whole output. A bare status needs exactly one blank line above it, a `Not checked:` line above that blank line, and exactly one `Not checked:` line in the output. An unreadable input now prints its cause before the usage line, and the banner border is as wide as its title line.

### Phase 1: review-checker-gaps

A live review run found four gaps in the checker. Before this change, it exited 0 for a skip status after a body of findings, for a bare status with no blank line above it, for a bare status with two blank lines above it, and for a bare status with two `Not checked:` lines. An automation caller that reads the exit status would accept each of those outputs. The checker now exits 1 for each one and prints a fixed message that names the cause.

The tamper harness gains five cases, one for each new failure, so its PASS count goes from 38 to 48. The rule-copy canary imports the same rule function, so the two example outputs in `SKILL.md` and `README.md` pass the new spacing rule as well.

## How It Was Delivered

The baseline came first. Before any edit, the harness printed 38 PASS lines with exit 0, the canary printed its OK line with exit 0, and the four gap inputs in `scratch/repro/` exited 0. After the edits, each gap input prints its named message and exits 1. The unreadable-file probe and the stdin-from-directory probe each print a `cannot read` line, then the usage line, and exit 2. The scope diff against the saved copy names exactly the three tracked files.

The build paused once. Its brief asked for a log entry in `goal.md` and also forbade editing that file. The coordinator allowed edits to the LOG section only, and the build resumed there. That decision and the Node and Bash versions are recorded in the `goal.md` LOG section.

The `.opencode/skills` path is a symlink to `.skilled/skills`, so the second canary run reads the same file. It shows the link resolves, not that a second copy agrees.

<!-- ANCHOR:decisions -->
## Key Decisions

| Decision | Why |
|----------|-----|
| A line starts a `Not checked:` count when it starts with that phrase, with no space required after the colon | A bare `Not checked:` line still counts toward the total, so it cannot slip past the count rule. |
| A line is blank when it is empty after trimming | That is the checker's existing meaning of blank, so the new blank-line rules change no current behavior. |
| A skip status with a blank line above it fails the whole-output rule | The whole output of a skip status is one line, so a blank line above it is extra output. No current skip output starts with a blank line. |
| The harness matches the `cannot read` prefix and the path, not the Node error text | Node's error text changes between versions, and asserting on it would make the harness flaky. |
| The four failure messages are fixed text, and the existing wording `no "Not checked:" line above the status line` is kept | The existing harness case matches that exact wording. |

<!-- ANCHOR:limitations -->
## Known Limitations

1. **A quoted `Not checked:` line fails the count.** The count matches any line that starts with the phrase. A finding that quotes such a line at the start of a line therefore trips the rule, and the failure message names the cause.
2. **A line of spaces counts as blank.** This is the existing behavior, kept so trailing-blank handling does not change.
3. **The parent's Files table omits `scripts/README.md`.** This child lists the file. The parent amendment is proposed in the spec's Open Questions and was not made.
4. **No changelog entry.** The parent has no `changelog/` folder, and phase 004 closed without one.
