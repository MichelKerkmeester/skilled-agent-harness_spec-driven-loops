The review reducer only read `- **F###**:` bullets, so an iteration written in the agent's own numbered shape, with no structured rows behind it, reached the registry with no findings. It now reads both shapes, and a cli-pi child receives the one variable that keeps pi-blackhole from compacting it mid-run.

> Spec folder: `specs/sk-code/011-sk-code-poinytail-based-refinement/010-round-three-remediation/006-deep-loop-follow-ups` (Level 1)

&nbsp;

## What's New at a Glance

- **Numbered findings reach the registry.** `reduce-state.cjs` reads `N. **Title** -- file:line -- Description` lines and gives each the delta-row id `R<iteration>-<severity>-<NNN>`, so a later iteration can resolve it.
- **Structured rows still come first.** An iteration that recorded delta finding rows or `findingDetails` keeps those, and its numbered narrative is not counted a second time.
- **Evidence lines stay evidence.** The Finding class, Scope proof, Affected surface hints and Case lines, nested lists and adjudication JSON under a finding are not counted as findings.
- **The F### shape still works.** Older iterations reduce exactly as before.
- **`PI_BLACKHOLE_PASSIVE` passes the cli-pi filter.** `executor-audit.ts` lets that one variable through for cli-pi only and still strips every unlisted variable.
