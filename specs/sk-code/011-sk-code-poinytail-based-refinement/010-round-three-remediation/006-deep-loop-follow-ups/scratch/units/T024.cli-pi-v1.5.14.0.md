The skill told dispatchers to set `PI_BLACKHOLE_PASSIVE=true` so pi-blackhole would not compact a child mid-run, but the deep-loop fan-out dropped that variable before the child started. The fan-out now passes it through, and the dispatch envelope sets it.

> Spec folder: `specs/sk-code/011-sk-code-poinytail-based-refinement/010-round-three-remediation/006-deep-loop-follow-ups` (Level 1)

&nbsp;

## What's New at a Glance

- **The variable reaches the child.** The fan-out's cli-pi environment filter lets `PI_BLACKHOLE_PASSIVE` through and still strips every variable outside its list.
- **The envelope carries it.** The dispatch envelope in `references/providers-and-models.md` now sets `PI_BLACKHOLE_PASSIVE=true` beside the spec-gate variables.

&nbsp;

## Upgrade

Export `PI_BLACKHOLE_PASSIVE=true` in the shell that runs a deep-loop fan-out. Nothing else changes.
