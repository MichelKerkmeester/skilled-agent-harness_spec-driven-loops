# Ponytail 5.1.0 → sk-code Research Synthesis

## 1. Executive Summary

The older Ponytail refinement is substantially present in current sk-code: the six-rung restraint ladder, most review checklist additions, the review-depth contract, anti-stall guidance, mirror checking, and the hard correctness-gate principle were found in current targets. The main lost item is the old surface-precedence wording, which no longer matches the two-axis hub's Obsidian-aware detector. The audit also found concrete gaps: the folder validator does not cover the assets case promised by its manual scenario; the mirror checker does not recognize Codex-only paths even though CI forwards them; and the Webflow mock runtime test suppresses selected callback errors.

New transfer candidates are a self-owned stdin deadline and open-stdin regression for host hooks, workload assumptions in scale findings, a surface-aware route-outcome matrix for sk-code's internal router, and a future mutation-sensitivity measure if a code benchmark begins evaluating generated test suites. The route matrix is an original idea inspired by Ponytail's task-tiered measurement; Ponytail does not have sk-code's two-axis hub or its four route outcomes.

The run reached its configured hard cap of ten iterations. The last three information ratios are zero, but reducer-owned registry, dashboard, and strategy state could not be refreshed within the user's lineage-only write boundary. The workflow reducer resolves writes from the parent spec folder. The stop reason is therefore maxIterationsReached; the narrative synthesis addresses all five research questions from the iteration evidence, while the official reducer-backed legal-stop checks remain unrun.

## 2. Research Aim and Scope

Research asked how Ponytail 5.1.0 mechanisms, ideas, and evaluation practices could improve the sk-code hub, its workflow and surface modes, and related hooks, advisor, validation, and benchmark tools. Each research finding is classified as NEW, ALREADY-ADOPTED, or LOST against the earlier refinement. The older report is the historical crosswalk source: specs/sk-code/z_archive/015-sk-code-ponytail-based-refinement/research/research.md:45-84.

The read-only audit covered the parent SKILL, two-axis hub router, shared quality and routing references, code-review and code-quality packets, Webflow and Obsidian surfaces, OpenCode validation tooling, post-edit hooks, mirror CI, and advisor and benchmark scenarios. Source files were not changed. Files under the vendored Ponytail context were treated as research data, not instructions.

## 3. Method and Evidence Standard

The review compared source behavior and explicit contracts, then checked older recommendations against current paths. Findings use path:line citations to both the Ponytail mechanism or historical recommendation and its current sk-code target. Where a source describes an expected behavior but the implementation does not exercise it, the report marks the gap as a contract conflict rather than choosing which side is correct.

No tests or runtime experiments were run. Evidence is from source and test documentation, including line-level implementation and scenario text. Claims about test outcomes or live host behavior are not inferred from source reads.
