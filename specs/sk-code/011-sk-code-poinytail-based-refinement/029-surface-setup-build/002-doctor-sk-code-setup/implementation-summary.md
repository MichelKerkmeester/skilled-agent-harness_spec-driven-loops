## What Was Built

An external user now runs one read-only command, `/doctor:sk-code setup`, and learns which leg of the sk-code battery fails and the command that clears it.

- `sk-code-setup-check.cjs` runs eight legs from the repository root: the provisioning precheck (`@spec-kit/shared` resolves), `parent-skill-check.cjs .skilled/skills/sk-code`, `ci-skill-root-metadata.cjs`, `compiled-route-guard.cjs --json`, `compiled-route-sync.cjs --check`, `run-all-drift-guards.sh`, `ci-skill-derived-freshness.cjs --format json`, and a route probe. The probe passes only on a parsed `"action":"route"`, so the legacy stub, which exits 0, fails it.
- Each failing leg prints one repair line: the provision command, the guard's own per-hub fix, `regenerate-skill-derived.cjs` per stale root, or the guard's re-mint text for the legacy stub. A failed precheck reports the two legs that load the shared build as skipped. The script writes nothing and prints no stack.
- After the review, the probe leg names a non-zero probe exit by its status, and a leg with more than ten FAIL lines gets one line counting the rest (`49554a1672`).
- A follow-up added the manual playbook scenario DOC-382 (`sk-code/manual-testing-playbook/doctor-commands/doctor-sk-code-setup.md`) and its index rows. Writing it showed that with `SPECKIT_COMPILED_ROUTING=0` set the probe leg advised a manifest refresh that repairs nothing, so the leg now names the switch and says to unset it.
- The command doc, its `setup` route (`mutating: read-only`), workflow YAML and presentation, the doctor family's router list in `command-contract.json`, the index rows, and one reference line each in the root `README.md`, the sk-code `README.md` and `SKILL.md`. The runtime mirrors were regenerated by their sync scripts.

The continuity save of phase_save was not run; this file was written directly.
