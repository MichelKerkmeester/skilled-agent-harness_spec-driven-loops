<!-- ANCHOR:metadata -->
## EXECUTIVE SUMMARY

Phase 2 removes the Webflow and Obsidian surfaces from the shipped sk-code hub, but the advisor still declares them and seven directory scans still read `.skilled/skills/` without deciding what a `local-*` private skill means. This phase strips the surface vocabulary from the scorer, the OpenCode plugin, both tool schemas and their tests, then gives every scan an explicit rule: three include a private skill for the local advisor, four exclude it from every tracked artifact, and a followed link must resolve inside a root the operator trusts.

**Key Decisions**: A `local-*` symlink is followed only when its realpath stays inside the skills root or a root listed in `SPECKIT_PRIVATE_SKILL_ROOTS`; the Python conflict-declaration reader includes a private skill because the local graph does; the tracked fallback graph is regenerated by its compiler and never hand-edited.

**Critical Dependencies**: `002-hub-surface-removal` must be on `main`, because the compiler would otherwise keep the surfaces' signals. The local advisor database must be built before the surface-hint suite runs.

## Phase Context

This is **Phase 3** of the Move the Webflow and Obsidian surfaces out of the shipped sk-code hub into gitignored local-* private skills that only the operator's local advisor routes specification.

**Scope Boundary**: In scope is the sk-code hub tree, the tracked consumers that name `sk-code-webflow`, `sk-code-obsidian` or the `WEBFLOW` / `OBSIDIAN` surface tokens, and the advisor's sk-code surface vocabulary. Out of scope, kept unchanged: generic Webflow/Obsidian words in other skills, dated historical records and git history (the full boundary is D6 in the parent packet and is repeated in §3).

**Dependencies**:
- `002-hub-surface-removal` merged first: the surfaces and their `mode-registry.json` / `hub-router.json` entries must already be gone, because this phase removes the vocabulary those entries declare and regenerates the tracked fallback graph afterwards.
- The local advisor database built in this worktree (`node .skilled/bin/skill-advisor.cjs advisor_rebuild --trusted --force true`). It is gitignored and it is what the advisor tests read; without it `advisor-surface-hint.vitest.ts` fails for an unrelated reason.
- `004-private-local-skills` runs after this phase so that the advisor scan already follows a trusted `local-*` symlink by the time a private skill exists. When phase 4 links a private repository that lives outside the checkout, the operator must name its root in `SPECKIT_PRIVATE_SKILL_ROOTS`; a real folder under `.skilled/skills/local-*` needs no variable.

**Deliverables**:
- No `WEBFLOW` / `OBSIDIAN` surface vocabulary left in the advisor scorer, plugin, tool schemas or their tests.
- Seven directory scans that treat a `local-*` entry by design: the advisor graph scan, the source-signature scan and the Python conflict-declaration reader include it; the compiler, the Hermes sync, the CI root-metadata gate and the doctor freshness panel exclude it. A fourth Python reader, `_load_source_graph_signal_map`, already includes the name and is screened with no change.
- One shared containment helper that follows a top-level `local-*` symlink only when its realpath resolves inside the skills root or a root named in `SPECKIT_PRIVATE_SKILL_ROOTS`.
- A regenerated tracked fallback `runtime/scripts/skill-graph.json` with no sk-code surface signals.
- A recorded screen of `ci-leaf-manifest-freshness.cjs`: no change needed, because neither private source tree carries a `leaf-manifest.json`.

## 2. PROBLEM & PURPOSE

### Problem Statement
Phase 2 removes the Webflow and Obsidian surfaces from the sk-code hub, but the advisor still declares them: the lexical lane carries an `obsidian plugin` hint token for `sk-code`, the OpenCode plugin detects an OBSIDIAN or WEBFLOW workspace, and two tool schemas plus the advisor README advertise `WEBFLOW` as the example surface hint. A prompt for a surface that no longer ships would keep collecting a hint, and the tracked fallback graph keeps the surfaces' trigger phrases. Separately, seven scans read `.skilled/skills/` by name: the advisor graph scan and the freshness signature skip a symlinked skill because `Dirent.isDirectory()` is false for a symlink; the Python conflict-declaration reader follows the link because `os.scandir` does; and the compiler, the Hermes sync, the CI root-metadata gate and the doctor freshness panel would pull a gitignored `local-*` private skill into a tracked file, a committed mirror or a failing gate.

### Purpose
After this phase the advisor speaks only about the surface that still ships, and a `local-*` private skill is either visible to the local advisor or invisible to every tracked artifact, by design rather than by accident. A followed link cannot leave the roots the operator trusts.

## 7. NON-FUNCTIONAL REQUIREMENTS

### Performance
- **NFR-P01**: The graph scan and the source signature add at most one `realpathSync` and one `statSync` per top-level entry whose name starts with `local-`; a tree with no `local-*` entry performs the same calls as today.
- **NFR-P02**: The compiler, Hermes sync, CI gate and doctor panel do no filesystem work for a skipped `local-*` entry beyond the one directory listing they already make.

### Security
- **NFR-S01**: No content from a `local-*` private skill reaches a tracked file: not `skill-graph.json`, not `.hermes/skills/`, not a test fixture.
- **NFR-S02**: No path from a `local-*` entry is printed by the CI gate or the doctor panel, so a private folder name does not leak into CI logs.
- **NFR-S03**: A followed `local-*` link never resolves outside the skills root or a root named in `SPECKIT_PRIVATE_SKILL_ROOTS`, so a link cannot make the advisor read an arbitrary directory.

### Reliability
- **NFR-R01**: Every in-scope suite is green on the final commit; no test is skipped or marked todo to reach green.
- **NFR-R02**: A `local-*` symlink with a missing target leaves the scans green, with the entry simply absent.

## 8. EDGE CASES

### Data Boundaries
- Empty input: a skills root with no `local-*` entry behaves exactly as today in all seven scans.
- Maximum length: the graph scan's recursive walk still descends into a followed `local-*` skill, and only that one level is entered through the symlink.
- Invalid format: a `local-*` entry that is a regular file is not a skill; the compiler's `graph-metadata.json` probe and the Hermes `SKILL.md` probe both reject it without the new condition mattering.

### Error Scenarios
- External service failure: not applicable; every scan is local filesystem work.
- Network timeout: not applicable.
- Concurrent access: the advisor daemon may scan while the graph is rebuilt; the scan is read-only and the containment change adds no write.
- Untrusted target: a `local-*` link whose realpath is outside every trusted root is skipped, and the scan reports no error.
- Unset variable: with `SPECKIT_PRIVATE_SKILL_ROOTS` unset, only the skills root is trusted, so a real folder still works and an external link is skipped.

### State Transitions
- Partial completion: a phase left mid-way has red tests only inside the test-then-code pairs of `tasks.md`; the phase is not closeable until the final `validate.sh --strict` passes.
- Session expiry: not applicable; the phase carries no session state.
