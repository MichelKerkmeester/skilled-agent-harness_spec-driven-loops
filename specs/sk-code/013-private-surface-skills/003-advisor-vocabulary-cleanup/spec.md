## EXECUTIVE SUMMARY

Phase 2 removes the Webflow and Obsidian surfaces from the shipped sk-code hub, but the advisor still declares them and sixteen directory scans still read `.skilled/skills/` without deciding what a `local-*` private skill means. This phase strips the surface vocabulary from the scorer, the OpenCode plugin, both tool schemas and their tests, then gives every scan an explicit rule. Eight scans include a private skill for the local advisor and eight exclude it from every tracked artifact. A followed link must resolve inside a root the operator trusts, and no other link is followed. Section 3 lists the sixteen scans so the count can be checked.

**Key Decisions**: A `local-*` symlink is followed only when its realpath stays inside the skills root or a root listed in `SPECKIT_PRIVATE_SKILL_ROOTS`; the Python conflict-declaration reader includes a private skill because the local graph does; the tracked fallback graph is regenerated by its compiler and never hand-edited.

**Critical Dependencies**: `002-hub-surface-removal` must be on `main`, because the compiler would otherwise keep the surfaces' signals. The local advisor database must be built before the surface-hint suite runs.

## Phase Context

This is **Phase 3** of the Move the Webflow and Obsidian surfaces out of the shipped sk-code hub into gitignored local-* skills that this checkout links to but never tracks, routed only by the operator's local advisor specification.

**Scope Boundary**: In scope is the sk-code hub tree, the tracked consumers that name `sk-code-webflow`, `sk-code-obsidian` or the `WEBFLOW` / `OBSIDIAN` surface tokens, the advisor's sk-code surface vocabulary, and the `@code` / `@review` UNKNOWN-route fallback to an advisor-named `local-*` skill. Out of scope, kept unchanged: generic Webflow/Obsidian words in other skills, dated historical records and git history (the full boundary is D6 in the parent packet and is repeated in §3).

**Dependencies**:
- `002-hub-surface-removal` merged first: the surfaces and their `mode-registry.json` / `hub-router.json` entries must already be gone, because this phase removes the vocabulary those entries declare and regenerates the tracked fallback graph afterwards.
- The local advisor database built in this worktree (`node .skilled/bin/skill-advisor.cjs advisor_rebuild --trusted --force true`). It is gitignored and it is what the advisor tests read; without it `advisor-surface-hint.vitest.ts` fails for an unrelated reason.
- `004-private-local-skills` runs after this phase so that the advisor scan already follows a trusted `local-*` symlink by the time a private skill exists. Phase 4 uses the symlink mode: both `.skilled/skills/local-*` entries link to `local-skills/` folders in two external repositories, so the operator must name both `local-skills/` parents in `SPECKIT_PRIVATE_SKILL_ROOTS`.

**Deliverables**:
- No `WEBFLOW` / `OBSIDIAN` surface vocabulary left in the advisor scorer, plugin, tool schemas or their tests.
- Sixteen directory scans that treat a `local-*` entry by design, listed in the scanner inventory in section 3. Eight include it for the local advisor and follow a symlink only by the containment rule: the advisor graph scan, the source signature, the Python conflict-declaration reader, the Python signal-map reader, the Python skill-record discovery, the daemon watcher, the filesystem projection and the status metadata scan. Eight exclude it by name before any filesystem probe: the compiler, the Hermes sync, the CI root-metadata gate, the doctor freshness panel, the command-bridge deriver, the skill-metadata regenerator, the router-signal generator and the cross-skill edge loader. The compiler and the command-bridge deriver also refuse any top-level symlink, because only a private skill may be a link (REQ-015, REQ-016, REQ-018, REQ-019).
- One shared containment helper that follows a top-level `local-*` symlink only when its realpath resolves inside the skills root or a root named in `SPECKIT_PRIVATE_SKILL_ROOTS`.
- A regenerated tracked fallback `runtime/scripts/skill-graph.json` with no sk-code surface signals.
- A recorded screen of `ci-leaf-manifest-freshness.cjs`: no change needed, because neither private source tree carries a `leaf-manifest.json`.

## 2. PROBLEM & PURPOSE

### Problem Statement
Phase 2 removes the Webflow and Obsidian surfaces from the sk-code hub, but the advisor still declares them: the lexical lane carries an `obsidian plugin` hint token for `sk-code`, the OpenCode plugin detects an OBSIDIAN or WEBFLOW workspace, and two tool schemas plus the advisor README advertise `WEBFLOW` as the example surface hint. A prompt for a surface that no longer ships would keep collecting a hint, and the tracked fallback graph keeps the surfaces' trigger phrases. Separately, sixteen scans read `.skilled/skills/` by name once the review follow-ups are counted, and section 3 lists them. The first seven were these: the advisor graph scan and the freshness signature skip a symlinked skill because `Dirent.isDirectory()` is false for a symlink; the Python conflict-declaration reader follows the link because `os.scandir` does; and the compiler, the Hermes sync, the CI root-metadata gate and the doctor freshness panel would pull a gitignored `local-*` private skill into a tracked file, a committed mirror or a failing gate.

### Purpose
After this phase the advisor speaks only about the surface that still ships, and a `local-*` private skill is either visible to the local advisor or invisible to every tracked artifact, by design rather than by accident. A followed link cannot leave the roots the operator trusts.

## 3. SCOPE

### In Scope
- The advisor's sk-code surface vocabulary: the lexical hint token, the plugin's workspace-surface detection, the `surfaceHint` example in both tool schemas and in the advisor README, and the tests and fixtures that name `WEBFLOW` or `OBSIDIAN`.
- A shared containment helper for a top-level `local-*` symlink: realpath resolution, a directory check, and containment against the skills root plus `SPECKIT_PRIVATE_SKILL_ROOTS`.
- Directory-scan behavior for a top-level `local-*` entry in the advisor graph scan (`skill-graph-db.ts`), the advisor source signature (`freshness.ts`) and the Python conflict-declaration reader (`skill_advisor.py`), which must see the private skill.
- Directory-scan behavior for a top-level `local-*` entry in the compiler (`skill_graph_compiler.py`), the Hermes sync (`sync-skills-hermes.cjs`), the CI root-metadata gate (`ci-skill-root-metadata.cjs`) and the doctor freshness panel (`skill-graph-freshness.cjs`), which must exclude it.
- Regenerating the tracked fallback `runtime/scripts/skill-graph.json` so it no longer carries the surfaces' signals.
- One test per behavior change, each failing before the change and passing after it, plus one characterization test for the Python reader's intended inclusion.
- A recorded screen of `ci-leaf-manifest-freshness.cjs`: no change needed, with the proof command that shows neither private source tree carries a `leaf-manifest.json`.
- The `@code` and `@review` agents' UNKNOWN-route fallback: when `sk-code` cannot route, the advisor CLI runs on the task text, a top pick whose `skillId` starts with `local-` becomes the standards overlay, and a non-local pick keeps the existing escalation or baseline-only behavior; the `.claude` twins are hand-edited and the `.codex` and `.pi` mirrors are regenerated.

- Generic Webflow/Obsidian words in other skills: `mcp-tooling/mcp-obsidian`, `mcp-notion`, the mcp-code-mode Webflow CMS vocabulary at `fusion.ts:600-602`, `explicit.ts:131`, `skill_advisor.py:2181`, the `P1-MCP-002` regression and holdout rows, and the sk-design style bundles — those describe a different product, not the removed sk-code surface.
- Dated historical records: every `changelog/` file, `.skilled/changelog/skilled/*.md`, `benchmark/reports/`, `specs/**/z_archive/`, the `doctor-update-*` playbooks under `.skilled/skills/system-spec-kit/manual-testing-playbook/doctor-commands/` that name units of the past v4.0.0.2 release, and the `anchor-repair-sample` test fixture — history is not rewritten.
- Git history: removed content stays in history; scrubbing it (filter-repo plus a force push) is an optional operator decision recorded as D7.

## 7. NON-FUNCTIONAL REQUIREMENTS

### Performance
- **NFR-P01**: A scan resolves its trusted roots once, and only when it meets its first `local-*` symlink, then adds one `realpathSync` and one `statSync` per such link. A tree with no `local-*` symlink performs the same calls as today. The TypeScript scans and the Python readers share this rule, and a Python test counts one resolution for a scan that meets two links.
- **NFR-P02**: The compiler, Hermes sync, CI gate and doctor panel do no filesystem work for a skipped `local-*` entry beyond the one directory listing they already make.

### Security
- **NFR-S01**: No content from a `local-*` private skill reaches a tracked file: not `skill-graph.json`, not `.hermes/skills/`, not a test fixture.
- **NFR-S02**: No path from a `local-*` entry is printed by the CI gate or the doctor panel, so a private folder name does not leak into CI logs.
- **NFR-S03**: A followed `local-*` link never resolves outside the skills root or a root named in `SPECKIT_PRIVATE_SKILL_ROOTS`, so a link cannot make the advisor read an arbitrary directory.

### Reliability
- **NFR-R01**: Every in-scope suite is green on the final commit; no test is skipped or marked todo to reach green.
- **NFR-R02**: A `local-*` symlink with a missing target leaves the scans green, with the entry simply absent.

## 8. EDGE CASES

### Data Boundaries
- Empty input: a skills root with no `local-*` entry behaves exactly as today in all sixteen scans.
- Maximum length: the graph scan's recursive walk still descends into a followed `local-*` skill, and only that one level is entered through the symlink.
- Invalid format: a `local-*` entry that is a regular file is not a skill; the compiler's `graph-metadata.json` probe and the Hermes `SKILL.md` probe both reject it without the new condition mattering.

### Error Scenarios
- External service failure: not applicable; every scan is local filesystem work.
- Network timeout: not applicable.
- Concurrent access: the advisor daemon may scan while the graph is rebuilt; the scan is read-only and the containment change adds no write.
- Untrusted target: a `local-*` link whose realpath is outside every trusted root is skipped, and the scan reports no error.
- Unset variable: with `SPECKIT_PRIVATE_SKILL_ROOTS` unset, only the skills root is trusted, so a real folder still works and an external link is skipped.

### State Transitions
- Partial completion: a phase left mid-way has red tests only inside the test-then-code pairs of `tasks.md`; the phase is not closeable until the final `validate.sh --strict` passes.
- Session expiry: not applicable; the phase carries no session state.
