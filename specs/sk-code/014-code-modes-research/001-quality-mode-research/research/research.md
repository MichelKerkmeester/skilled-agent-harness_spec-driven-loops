## 1. Answer

The quality gate's P0/P1/P2 model, changed-file workflow and comment checker would run in any repository. Its target-path map, enforcement layers and dist checker assume this framework's `.skilled/` layout. Its always-loaded checklist is a web house style, and one map row names `.opencode/specs/`, a path with no tracked file even in this repository. Its usefulness is unmeasured, because the saved benchmark runs and the single playbook scenario test routing and file presence rather than what the gate catches, costs or misses. Its integration is one-sided: the CI surface says quality applies its rules, but quality never names that surface, its result envelope has no parser and no reader in `sk-code-review`, while the hub playbook documents deep-review as its consumer [SOURCE: .skilled/skills/sk-code/manual-testing-playbook/tooling-and-hooks/comment-hygiene-hook.md:155] `` Where `deep-review` consumes it. ``, and it hands work back to a surface packet the registry marks read-only. A mode an outside user adds can reach the hub through the eleven integration rows, but checklist selection, comment-checker language coverage and the envelope's surface value all live inside quality's packet, outside every row. The five highest-gain changes split the always-loaded checklist into a portable baseline and an opt-in web overlay, let each surface declare its quality checklists, name the CI surface, report skipped checks as skipped and probe for host hooks before promising they block. Only the checklist split touches a fixed input, the P0 floor, so it is the one change in the top five that needs a decision.

A second model family re-checked the ranked rows in iterations 11 to 15. It confirmed 12 of the 14 rows and refuted part of the reasoning behind two of them, rank 4 and rank 10, without rejecting either change. It refuted no row outright and left none untested as a whole, though some sub-claims stay untested, as section 6a lists. It also ran what the first pass never did: the comment checker on a workflow file and three compiled-route replays. Those runs move the CI surface to the top of the refreshed order. A request to fix a GitHub Actions workflow now routes to `sk-code-ci` alone, a read-only evidence packet, and quality's only checker skips YAML. The refreshed order is in section 6b.

## 7. Recommendations

The paragraphs below explain the first-pass top five. Section 6b holds the refreshed order after the second-model pass, and the build order at the end of this section still holds, because it follows dependency rather than rank.

**Split the always-loaded checklist (rank 1).** It removes the largest false block that a JavaScript repository outside this framework meets, since header, IIFE and naming rules become P0 failures there. It also brings quality in line with the shared phase doctrine. It needs the operator's decision on the P0 floor first, because fewer P0 items would bind `.js` files by default, this repository included.

**Let surfaces declare their quality checklists (rank 2).** This fixes the cause behind several symptoms: the hand-kept map, the Obsidian drift, the unserved CI surface and the outside-user gap. Its trade-off is a new contract that every surface must honor. The built-in map stays as the fallback so nothing loses coverage while surfaces adopt it.

**Name the CI surface (rank 3).** It is the cheapest way to make an existing sibling contract true from both sides. It also serves the one layout most repositories share. Once rank 2 exists, the CI packet becomes its first declaring surface.

**Report skipped checks as skipped (rank 4).** A Rust, YAML or Go change can now leave the gate with no violations and nothing checked. Naming the skip costs a sentence in the workflow and a few test cases, and it keeps the advisory envelope advisory.

**Probe host hooks before promising they block (rank 5).** The packet has already shipped one correction for naming hooks that were not installed. A probe turns a fixed list of `.claude`, `.skilled` and `.github` paths into an honest report for any repository.

Rank orders gain, and the build order follows dependency, so a baseline exists before behavior changes.

1. Make the contract true without changing behavior: the handback wording (rank 6), the stale spec row (rank 11), the CI integration point from rank 3 and the dist per-file rule (rank 14).
2. Capture a baseline: the behavior fixtures and measurements (rank 7), with recorded corpus and relative roots (rank 13) once the harness owner agrees.
3. Make reporting honest against that baseline: skipped outcomes (rank 4) and adapter probes (rank 5).
4. Open the extension seam: surface-declared checklists (rank 2) with the CI route as its first user, the open envelope field (rank 9) and the restraint keywords (rank 12), all proven by the canary (rank 8) through both stages.
5. Take the decision-gated items last: the checklist split (rank 1) after the P0 decision, measured against step 2, then the manifest (rank 10) only if step 4 leaves a gap.
