# Iteration 2: the record, bridge, diff, bench, shadow and gate method — and which parts apply to any Rust port checked against an original

## Focus

Key question 2: what rust-anything's verification method actually is, read from `docs/how-it-works.md`, `docs/pitfalls.md`, `DECISIONS.md` and the `gate` implementation, and which of those methods generalise to any Rust port checked against an original. The question is not "what does rust-anything do" but "which of these is a rule sk-code should carry for a port it did not write".

## Findings

## Ruled Out

- **Reading `gate` as a single command.** The first pass looked for one gate implementation. `gate.rs` is a dispatcher that pushes a `Check` per concern and returns a `GateOutcome`; the checks are the unit of design, not the command. Recorded as finding 2 rather than retried.
- **Treating `bench` as a gate check.** `DECISIONS.md:59` says explicitly that it is not, and gives the reason. Recorded as finding 6.

## Reflection

- What worked and why: reading `DECISIONS.md` before `gate.rs` was the right order. The decision table states the reason for each check in one sentence, so when `gate.rs` was read afterwards every constant had a motive attached — `MAX_GROWTH = 3.0` is not an arbitrary number once `DECISIONS.md:48` explains that over-growth means hand-rolled crate code. Reading the implementation first would have produced a list of checks with no argument for adopting them.
- What did not work and why: the `grep -ril "cheat"` coverage probe returned a false positive from a "CHEAT SHEET" heading. A case-insensitive single-word grep over prose is not a reliable coverage test; the reliable form is to grep for the distinctive token the rule would use (`recorded-literal`, `INFALLIBLE`, `SAFETY:`), which is what the other probes did.
- What I would do differently: probe for the escape-marker tokens first. `recorded-literal`, `INFALLIBLE` and `SAFETY:` are the three markers that decide whether sk-code can express a rule with an exception, and their presence or absence predicts the shape of the edit list better than any section heading.
