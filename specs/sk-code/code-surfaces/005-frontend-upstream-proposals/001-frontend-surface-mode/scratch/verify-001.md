## Things that looked wrong

1. **AC-006 is not met on its own wording.** Five of the eleven topic files (all native) carry React Native version Support lines, not a web-features Baseline status. The six web topic files comply. The criterion says "every topic file", while the spec's rewrite sentence is scoped to the web files; the two readings disagree and a `rg -c "Baseline"` sweep follows the criterion. The operator needs to narrow/supersede AC-006 or add Baseline-style citations to the native files (which web-features does not cover).
2. **Stale intent signal.** `.skilled/skills/sk-code/graph-metadata.json:190` still lists `react native list performance`, but the surface router, hub router and registry were renamed to `react native scroll performance` (registry line 142, hub-router line 88, surface ROUTER line 82). No router declares the old phrase any more. `generate-router-intent-signals.cjs --check` passes because it only proves presence, never absence, so this survives green checks.
3. **AC-005's heading and row count disagree on the surface.** `### Five Passes` heads a table with six rows because pass 3 splits into 3a/3b. It is consistent with the core's five-item list, but a reader counting rows sees six and may read it as a defect.
4. **AC-008's liveness cannot be re-observed.** `bdg` 0.6.10 is on PATH, but the run file is the only artifact of the live session; the verdict rests on its completeness (11/11 methods, command + output + exit) and on the failed `bdg dom eval` being demoted to a warning rather than kept as a recipe.
5. **X-2 interpretation.** `Figma`, `Expo`, `Shopify` (in the flash-list docs URL) and `Mozilla` (MDN URLs) appear in the packet. I treated those as public platform/documentation references, not client identity. If "names a company" is meant literally, X-2 would fail on those; the packet contains no client company name, private npm scope or spec-folder id.
6. **The mcp-figma pointer is not a repo-root path.** It names `sk-code/sk-code-frontend/references/figma-to-code.md` without the `.skilled/skills/` prefix. That matches how the same file names sibling skills, so it is not wrong in context, but it is not resolvable from the repository root as written.
