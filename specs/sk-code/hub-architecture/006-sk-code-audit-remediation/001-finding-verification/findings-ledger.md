# Findings Ledger: sk-code audit

This file is the closed list of audit findings. Phase 001 fills every `Unverified` verdict. Phases 002 to 008 fix the rows their number names and write the proof in the last column.

## 1. HOW TO READ A ROW

- **Verdict** is one of `Confirmed`, `Refuted`, `Changed`, `Judgment` or `Unverified`. `Changed` means the cited file moved on since the audit and the row says what is there now. `Judgment` means no command decides it and the row states the reasoning.
- **Evidence** names the command or the file and line that decided the verdict. `TBD` marks a row phase 001 has not reached.
- **Fix phase** is the child folder number that owns the fix.
- **Fix evidence** stays `-` until the owning phase writes the command that proves the fix, or `no change` with a reason for a `Refuted` row.
- The `F` and `H` rows come from the audit's own reads and router probes. The `SK`, `RV` and `QL` rows come from the three DeepSeek V4.1 Flash readers, whose raw reports are in `scratch/deepseek-sk-code-*.log`.
