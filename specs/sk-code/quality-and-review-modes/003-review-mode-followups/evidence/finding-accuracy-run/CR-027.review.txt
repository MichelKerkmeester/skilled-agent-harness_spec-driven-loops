### P1 - High

1. [fixtures/clamp.js:5] The range guard misses non-numeric bounds, so an invalid range returns `NaN` instead of throwing
   - Case: `clamp(5, Number.NaN, 100)` — the shape produced whenever a bound comes from `parseInt`/`Number` over unparsed config or env — returns `NaN` and no error. Symmetrically, `clamp(5, 0, NaN)` returns `NaN` while the equally invalid `clamp(5, 100, 0)` throws `RangeError` at line 6.
   - Risk: `min > max` at line 5 evaluates to `false` for any comparison involving `NaN`, so the guard that line 6 exists to enforce never fires. Control then reaches line 8, where `Number::max`/`Number::min` return `NaN` for a `NaN` argument, so the poison value is returned as if it were a clamp result. Evidence is from the language semantics (no execution in this session, see `Not checked`), not from a run.
   - User impact: a caller that treats the `RangeError` as its bounds-validation signal silently receives `NaN` instead — `array.slice(0, clamp(n, NaN, max))` yields an empty result, a rendered numeric value disappears, a persisted limit becomes `null` after JSON round-trip — all with no error trace to point at the bad bound.
   - Finding class: instance-only
   - Scope proof: `grep -n "clamp"` over `fixtures/` returns only the definition at line 4 and the export at line 11; no caller, no second guard, and no same-class validation in `paginate.js` or `users.js`, so this is not a cross-consumer fix.
   - affectedSurfaceHints: ["clamp utility", "bounds validation", "callers parsing numeric config"]
   - riskScore: 5 (advisory only)
   - Severity note: retained at P1 after adversarial check. If pass-through of non-numeric bounds is the *intended* contract, this downgrades to P2 — but the contract must then be stated, because the throw at line 6 currently promises the opposite.
   - Recommended fix: reject non-numeric bounds in the existing guard, e.g. `if (Number.isNaN(min) || Number.isNaN(max) || min > max) throw new RangeError('min must not exceed max');` (do not switch to `Number.isFinite`, since `±Infinity` bounds are a legitimate clamp range), or document that non-numeric bounds yield `NaN`.
