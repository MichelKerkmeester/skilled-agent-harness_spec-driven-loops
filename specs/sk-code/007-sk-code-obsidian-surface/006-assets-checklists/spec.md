## 2. PROBLEM & PURPOSE

### Problem Statement

`sk-code-obsidian/SKILL.md` §4 already advertises on-demand checklists (`assets/*.md`), and
`001-surface-design-plan/mode-design-plan.md` §7's `RESOURCE_MAP` names five proposed filenames
(`renderer-implementation-checklist.md`, `comment-grammar-checklist.md`,
`folder-docs-checklist.md`, `debug-checklist.md`, `verification-checklist.md`) — but §7 also states
plainly that these are "this plan's proposal for the build packet to adopt or amend — nothing here
is generated by tooling." Before this phase, `sk-code-obsidian/assets/` did not exist at all: a
workflow that bundles this surface and hits one of `SKILL.md` §6's ESCALATE triggers — a `.db-*`
rename, a `src/views/modals/` change with no scenario, an invented fixture class — has nothing to
load.

### Purpose

Author seven `assets/*.md` checklists under `sk-code-obsidian/`, matching `sk-code-mobile-cli`'s
checklist shape exactly (frontmatter, upper-case numbered sections, actionable checkbox items each
carrying a stated proof): `screenshot-coverage-checklist.md`, `db-class-rename-checklist.md`,
`fixture-authoring-checklist.md`, `verification-checklist.md`, `folder-docs-checklist.md`,
`comment-banner-checklist.md`, and `modal-coverage-checklist.md`. This set supersedes the five-name
proposal in `SKILL.md` §4 and `mode-design-plan.md` §7 for the topics both name
(`verification-checklist.md`, `folder-docs-checklist.md`) and replaces the other three proposed
names with checklists that match this plugin's actual traps more precisely — a modal-coverage gap
and a fixture-authoring discipline the five-name proposal only gestured at inside
`renderer-implementation-checklist.md`. Reconciling `SKILL.md` §4's and `mode-design-plan.md` §7's
prose against the delivered set is explicitly out of scope for this phase (see §3).

## 5. SUCCESS CRITERIA

- **SC-001**: All seven checklists exist under `sk-code-obsidian/assets/`, each 90-140 lines.
- **SC-002**: Every checklist's `## N. THE GATE` section restates its preceding sections' checkbox
  items as a single closing bar, matching the template's `THE GATE` pattern.
- **SC-003**: `screenshot-coverage-checklist.md` and `modal-coverage-checklist.md` both name the
  non-recursing-`ls` root cause for the 17 unphotographed modals, without contradicting each other.
- **SC-004**: `db-class-rename-checklist.md` and `fixture-authoring-checklist.md` both cite the
  `ScreenshotFixtures.test.ts` guard test as the mechanism that catches an invented class, without
  duplicating the same prose verbatim.
- **SC-005**: `spec.md`, `plan.md`, and `tasks.md` in this folder contain no scaffold placeholder
  text (`REQUIREMENT_PLACEHOLDER`, bare `**Given**`, or similar).

### Acceptance Scenarios

- **Scenario 1**: **Given** `sk-code-mobile-cli/assets/bem-rename-checklist.md` structures its
  gate as "map is injective; `rg -nw` is 0; dynamic sites resolve; tests pass", **when**
  `db-class-rename-checklist.md`'s THE GATE section is read, **then** it restates the same
  proof-bearing shape for this plugin's single-stylesheet, fixture-coupled rename instead.
- **Scenario 2**: **Given** `audit.json` records 17 files under `src/views/modals/` and states the
  original coverage inventory used a non-recursing `ls src/views/*.ts`, **when**
  `modal-coverage-checklist.md` §2-3 is read, **then** it lists all 17 filenames and names that
  exact root cause, not a guessed one.
- **Scenario 3**: **Given** `SKILL.md` §3 states "never invent a `.db-*` class... `Screenshot
  FixturesTest.ts` fails any that appears in neither `styles.css` nor `src/`", **when**
  `fixture-authoring-checklist.md` §3 is read, **then** it names that exact test file and mechanism
  as the guard, not a paraphrase that loses the "neither styles.css nor src/" precision.
- **Scenario 4**: **Given** `npm run lint` carries a measured baseline of 115 problems (100 errors,
  15 warnings, 42 autofixable), **when** `verification-checklist.md` §6 is read, **then** it states
  that exact baseline and instructs reporting a rerun delta rather than "lint passes."

## 7. EDGE CASES

### Structural Boundaries
- **A checklist needs to reference another checklist in this same set**: cross-references use a
  relative link (`assets/modal-coverage-checklist.md` from `screenshot-coverage-checklist.md`),
  never a spec-folder or phase-number reference.
- **A checklist step depends on a scanner that does not exist yet** (`scan-comments.mjs`,
  `scan-folder-docs.mjs`, phase 008): `comment-banner-checklist.md` and `folder-docs-checklist.md`
  state explicitly that the check is manual today and name the future scanner, rather than
  instructing a command that would currently fail with "file not found."

### Grounding Boundaries
- **A claim that cannot be checked against a real file or `audit.json`**: none is made; every
  measured count, class name, file path, and command in the seven checklists was verified this
  session.
