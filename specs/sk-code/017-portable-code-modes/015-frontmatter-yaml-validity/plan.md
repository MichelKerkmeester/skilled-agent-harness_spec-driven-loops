## 1. SUMMARY

### Technical Context

| Aspect | Value |
|--------|-------|
| **Language/Stack** | Python 3.9.6 on `/usr/bin/python3` with PyYAML 6.0.3, and the Homebrew interpreter without it |
| **Framework** | None |
| **Storage** | None |
| **Testing** | pytest for the fleet test, the file's own `main` for the unit test, `run-script-tests.sh` for the suite |

### Overview
Every block a strict parser rejected is repaired by quoting its value, so the text a reader or the router sees is unchanged and only the quoting differs. The validator gains one function that parses the block it was already handed, and a line check that stands in for the parser where PyYAML is not importable. A unit test pins the verdict and its line, and a fleet test runs the parse over every tracked `.skilled` block so the next broken one fails a test instead of waiting for its document to be edited.

<!-- ANCHOR:architecture -->
## 3. ARCHITECTURE

### Pattern
A strict-parse gate with a parser-free fallback.

### Key Components
- **`validate_frontmatter_yaml`**: parses the block through `yaml.safe_load` and returns one blocking issue carrying the parser's line, or nothing.
- **`_frontmatter_block`**: skips leading trivia and returns the block with the line it starts on, and refuses a fence whose body holds no key line so a thematic break is not read as frontmatter.
- **`_unquoted_colon_line`**: the stand-in verdict where PyYAML is absent, finding the first top-level value that holds `: ` and skipping block scalars, flow collections, list items and trailing comments.
- **`test_frontmatter_fleet.py`**: the door over the whole tree, with the one deliberate fixture excluded by name.

### Data Flow
The validator hands its content to `validate_frontmatter_yaml`, which locates the block and its start line, parses it, and maps the parser's offset onto a file line. A block that parses returns no issue; a block that does not returns one blocking issue with the line and a quoting hint, and the document's verdict carries it the same way every other issue is carried.

| Surface | Current Role | Action | Verification |

| `.skilled/skills/sk-doc/scripts/tests/code-folder/baseline-readme-verdicts.json` | Records the verdict each code-folder fixture gets | update | the baseline now records the issue for the scratch README that carries a broken table block |
| `quick_validate.py` | Reads the same block with regexes | unchanged, still key-by-key | the fleet test is the door that covers every file, whichever checker runs |

| `.hermes/skills/*/SKILL.md` mirrors | Copies the `.skilled` headers into the Hermes tree | regenerated by the sync | the nine mirror headers lose the same line their sources lost |

Required inventories:
- Same-class producers: `rg -n frontmatter .skilled/skills/sk-doc/shared/scripts` names `validate_document.py` and `quick_validate.py`, and only the first parses the block.
- Consumers of changed symbols: `rg -n "validate_document" .skilled .opencode .github` reaches the `n` wrapper, the create-skill assets and the sk-doc tests, none of which read the new issue type by name.
- Matrix axes: two interpreters (PyYAML present, PyYAML absent) by five block shapes (unquoted scalar, quoted scalar, table fixture, list with a trailing version line, no block at all).
- Algorithm invariant: for a block the validator hands over, the check returns exactly one issue when a strict parse raises and none when it does not, and any reported line falls inside the file's frontmatter.
