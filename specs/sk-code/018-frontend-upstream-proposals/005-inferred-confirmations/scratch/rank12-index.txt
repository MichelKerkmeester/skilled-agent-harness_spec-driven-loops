WHAT THE OUTPUT SHOWS
================================================================================
1. Plain run resolves the root from the generator's own location, not cwd.
   The 13,554 specs/ paths it indexed are this worktree's spec tree
   (specs/agents-md/..., specs/sk-code/...), and specs/demo — sitting in the
   process's cwd — is not among them. documents scanned 27,360 against run 2's
   8,674 is the same fact at corpus scale.

   Mechanism, quoted:
   .skilled/skills/system-spec-kit/runtime/cli/retrieval/generate-trigger-index.mjs:73-75
     const SCRIPT_DIR = path.dirname(fileURLToPath(import.meta.url));
     const SKILL_ROOT = path.resolve(SCRIPT_DIR, '..', '..', '..');
   generate-trigger-index.mjs:101
     export const DEFAULT_REPO_ROOT = findRepoRoot();
   generate-trigger-index.mjs:415
     const repoRoot = options.repoRoot ?? DEFAULT_REPO_ROOT;

   findRepoRoot() is called with no argument, so it walks up from SCRIPT_DIR
   (generate-trigger-index.mjs:96-99). Because cwd is never consulted, a project
   that only *links* the source tree gets the source tree's own repository root.
   Note the module header comment claims the walk "keeps that drift impossible"
   (lines 86-95); this run shows the drift it prevents is the hop-count drift,
   not the wrong-repository drift.

2. --repo-root . overrides that default, and it works.
   With the flag, buildIndex resolves the argument against cwd
   (generate-trigger-index.mjs:132 `const repoRoot = path.resolve(options.repoRoot);`),
   corpusRootsFor finds the symlinked source root through the sentinel
   (lib/corpus.mjs:45-51), and the resulting paths table holds exactly one
   specs/ entry: specs/demo/001-demo/spec.md. The demo phrase is in the index.
   So the "even with --repo-root ." clause is not reproduced by this build.
   Worth naming precisely: the flag is a *caller* obligation. Any invocation that
   omits it — including a routine `--out` rebuild invoked from a linked project —
   silently publishes the wrong repository's spec tree with exit 0.

3. Exit status does not distinguish the two builds. Both printed
   "trigger index published" and exited 0; only the counts and the paths table
   differ. Nothing in the report names the resolved repository root, and the
   manifest has no repoRoot field (keys listed above), so the wrong-root build is
   not self-identifying in its artifacts.

VERDICT
  Claim 1 (default root comes from the generator's directory, so a linked
  project's specs/ are omitted): CONFIRMED by idx-1.json — 13,554 worktree
  specs/ paths, zero specs/demo, exit 0.
  Claim 2 (the same happens even with --repo-root .): REFUTED by idx-2.json —

  Both runs used --out; the committed index at
  .skilled/skills/system-spec-kit/runtime/data/trigger-index.json was not written
