QUOTED EVIDENCE
--------------------------------------------------------------------------------
1. The replay extracts a dict literally named INTENT_SIGNALS
   .skilled/skills/sk-doc/sk-create-skill/scripts/leaf-route-replay.cjs:121
     const intents = parseIntentSignals(rootRouter.extractDictBody(source, 'INTENT_SIGNALS'));

   and extractDictBody is a literal string search:
   .skilled/skills/sk-doc/sk-create-skill/scripts/lib/root-router-contract.cjs:202-203
     const start = text.indexOf(`${name} = {`);
     if (start === -1) return null;

   The fundamentals file never contains that name. Its declaration is:
   .skilled/skills/sk-design/sk-design-fundamentals/ROUTER.md:112
     INTENT_MODEL = {

   So extractDictBody returns null, parseIntentSignals returns {} on its first
   line (`if (!body) return signals;`, line 78), and every prompt scores [].
   Command 2 variant A shows exactly that: intentOrder.length 0, scores [].

2. The same parser handles `weight` as a per-intent key and keywords as flat
   quoted strings:
   leaf-route-replay.cjs:82-86
     const weightMatch = /["']weight["']\s*:\s*(\d+(?:\.\d+)?)/.exec(m[2]);
     const kwMatch = /["']keywords["']\s*:\s*\[([^\]]*)\]/.exec(m[2]);
     signals[m[1]] = {
       weight: weightMatch ? Number(weightMatch[1]) : 1,
       keywords: kwMatch ? quotedStrings(kwMatch[1]).map((kw) => kw.toLowerCase()) : []
     };
   leaf-route-replay.cjs:59-61
     const re = /"([^"]*)"|'([^']*)'/g;

   The fundamentals file writes tuples instead:
   .skilled/skills/sk-design/sk-design-fundamentals/ROUTER.md:113-115
     "DIAGNOSE": {"keywords": [("looks off", 4), ("looks amateur", 4), ("feels cheap", 4),
                               ("cluttered", 3), ("feels plain", 3), ("unfinished", 3),
                               ("make this look better", 4), ("improve", 2)]},

3. Isolating the two causes:
   - Variant A (name wrong AND tuples) -> {} intents, [] scores.
   - Variant B (name fixed in memory only, tuples untouched) -> 10 intents and
     87 keywords parse (8,8,8,8,10,9,11,10,8,7 per intent, as printed); the
     phrases are recovered from the tuples by
     quotedStrings; control prompt scores DIAGNOSE 3. So the tuple grammar alone
     does NOT produce a no-intent result.
   - Variant C (synthetic, tuple grammar, no weight key) -> DIAGNOSE weight 1,
     score 3. Same as B: hits counted at 1 each.
   - Variant D (canonical grammar, weight 4) -> same three keyword hits score 8.
   Therefore the tuple reading silently downgrades every signal to weight 1 and
   discards the 2/3/4 weights entirely, which changes ranking whenever intents
   compete (the whole point of the weights), but does not zero the route.

VERDICT
  The no-intent result is caused by the dict name mismatch (INTENT_MODEL vs
  INTENT_SIGNALS). The tuple grammar is a real second defect with a different
  symptom: weight collapse to 1 per hit, verified by variants B and C against D.
  Both statements are shown by the output above; neither is inferred.
