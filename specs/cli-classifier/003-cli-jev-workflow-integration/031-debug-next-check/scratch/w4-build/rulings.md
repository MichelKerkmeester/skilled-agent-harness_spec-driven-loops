# Orchestrator rulings on design.md section 6 (2026-09-29)

1. Question 1 is accepted: the seam search excludes `runtime/cli/retrieval/fixtures/`, because that generated folder mirrors spec trigger phrases and would make the search find this phase's own spec. The closure records it as a deviation against REQ-002 with that reason. Questions 2 to 11 are accepted as proposed.
2. The changelog version is the next after the newest `changelog/` file present at doc time. Earlier phases in this skill (022, then 026) add their own versions first, so list the folder at doc time and never assume `v4.5.0.0.md`.
3. Gate order (parent D1, "Jev first, else Deem"): with both switches, the Jev gate and arm run first, then the Deem gate and arm, each on its own gate and regardless of the other's outcome. A failed gate prints its skip line and never runs the other backend in its place.
4. Docs name only what the code prints. A `verdict` line is claimed nowhere unless a run printed it.
5. Tests run on a machine whose global git config sets `core.hooksPath`, and its commit-msg hook rejects a commit without a body. Every test that creates a git repository passes `-c core.hooksPath=/dev/null` (beside `-c commit.gpgsign=false`) to each `git commit` it runs, as `cli-classifier/benchmark/injection-screen/tests/score-injection-screen.test.mjs` line 48 does. Test code and the scripts never run the machine's hooks.
6. The mined corpus counts hypothesis headings with one `git grep -cE '^### Hypothesis [0-9]' -- 'specs/*.md'`: the number of output lines is `hypothesis_files` and the sum of the counts is `mined rows`. Section 2's two greps over every tracked file under `specs/` (104,521 files) took about 11 s each on this repository, so each test that spawns the script paid about 26 s and two tests hit vitest's 30 s limit. A heading lives in markdown, so the result is the same, in about 6 s.
