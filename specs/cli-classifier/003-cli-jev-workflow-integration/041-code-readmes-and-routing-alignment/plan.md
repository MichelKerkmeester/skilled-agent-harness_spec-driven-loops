### Technical Context

| Aspect | Value |

### Overview

Part A writes eleven code-folder READMEs for the script and test folders this packet created or filled, each per `sk-create-readme`'s code-folder template and each naming a test command that runs from the repository root. Part B aligns the `cli-classifier` hub to the `sk-create-skill` template without moving a route: `ROUTER.md` is promoted to `router_state: active` over the seven intents whose leaves come from `leaf-manifest.json` (D4), both mode `SKILL.md` section 2s are reshaped to the template's one Smart Router Pseudocode block, `cli-jev`'s transport mechanics move to section 3, the `cli-usage-aliases` class becomes `cli-jev-aliases`, thirteen targeted phrases join the two dispatch classes, and the hub, `cli-jev` and `cli-deem` version lines move with one changelog entry each. The ten-prompt compiled-route probe holds its eight baseline-correct rows and routes the two former misses to their mode (D2). The compiled-route manifest and the Hermes mirror are regenerated through their own tools.

## 3. ARCHITECTURE

### Pattern

Two documentation surfaces and one routing surface, all repo-local. Part A is a per-folder README written from the folder's own files. Part B is a canon alignment: the hub's routing artifacts already carry the behavior, so the change moves the declarations to the shape the template and the other six hubs use, reading the leaf set from the committed manifest rather than restating it. The single source of truth stays `leaf-manifest.json` for leaves and `hub-router.json` for the vocabulary, and no routing decision is re-authored.

### Key Components

- **Eleven code-folder READMEs**: one per folder of `spec.md` section 3, each naming the folder's topology, contents, boundaries and the exact test command its validation section documents.
- **`ROUTER.md` promoted to active**: the hub's stage-two control document, declaring the seven intents and mapping each to leaves read from `leaf-manifest.json`.
- **Hub artifacts**: `SKILL.md` carries the surface-router note, `hub-router.json` carries the renamed class and the thirteen dispatch phrases, and the five routing artifacts carry one version line.
- **Mode section 2s**: `cli-jev/SKILL.md` and `cli-deem/SKILL.md`, each reshaped to the template's subsections and one authoritative Smart Router Pseudocode block.
- **Generated mirrors**: the compiled-route manifest for `cli-classifier` and the three `.hermes/skills/` copies, both regenerated by their own tools.
- **The probe**: the ten-prompt corpus, its baseline recording and its final-state replay through `.skilled/bin/compiled-route.cjs`.

### Data Flow

A reader opens a code folder, finds its README and learns what the folder owns and which command runs its tests. Separately, a request reaches the hub: `SKILL.md` resolves the mode through `hub-router.json`, whose vocabulary classes now carry the thirteen targeted phrases; when the compiled front door serves the hub it returns the same decision as before for every baseline-correct row, and the promoted `ROUTER.md` maps the chosen intent to the manifest's leaves. The mode's section 2 describes that second stage in the template's pseudocode shape while section 3 keeps the transport mechanics that act on the judgment.

## FIX ADDENDUM: AFFECTED SURFACES

This is a documentation and canon-alignment pass over a router that already behaves correctly, so the addendum records the producer and consumer inventories around the changed surfaces and the invariant the routing rows must keep.

- Same-class producers: `find .skilled/skills -type f -name '*.mjs' -o -name '*.cjs' | xargs -n1 dirname | sort -u` intersected with a `README.md` existence test names the eleven folders of `spec.md` section 3 on 2026-09-30. Every one gains a README, and the four folders named out of scope are excluded by decision, not by omission (D3).
- Consumers of the renamed class: `rg -n 'cli-usage-aliases' .skilled/skills/cli-classifier` names `hub-router.json` and the hub-routing scenario file at baseline, and both move. A reader of the class name is the compiled router through `hub-router.json`, whose re-minted manifest decides whether the change is live.
- Consumers of the frozen decisions: every caller of `.skilled/bin/compiled-route.cjs --hub cli-classifier`. They observe the same decision before and after on the eight baseline-correct rows, which proof plan 4 proves; the two former misses gain a decision they did not have.
- Consumers of the version line: `parent-skill-check.cjs` 13a reads `SKILL.md`, `ROUTER.md`, `description.json`, `hub-router.json` and `mode-registry.json`, and 13b reads the newest changelog entry. Both are read from the final state.
- Matrix axes: the folder axis (eleven READMEs, four excluded folders), the doc-gate axis (VALID or not, documented command passing or not), the intent axis (seven intents against eight manifest leaves), the vocabulary axis (thirteen added phrases against the eight baseline-correct rows), the version axis (three release lines against their newest changelog) and the generated-artifact axis (manifest fresh, Hermes check clean).
- Algorithm invariant: for the ten probe prompts, the final `(workflowMode, packetId)` tuple equals the baseline tuple on the eight rows that were correct, and the two former misses return a single target whose `workflowMode` is the named transport. Adversarial cases: a prompt that names only the hub, which must still defer; a prompt that names both backends, which must still bundle in tie-break order; and an off-topic prompt, which must still resolve nothing.

## 4. IMPLEMENTATION PHASES

Follow the ordered tasks in `tasks.md`. It owns the task checkboxes and state. The six phases below are the plan of record.

**Who builds (parent D5).** DeepSeek V4.1 Flash on `cli-pi` writes the design note, the eleven READMEs, the `ROUTER.md` promotion, both mode section 2s, the registry edits and the changelog entries, each dispatched through the external orchestration route. A cross-family reviewer on `cli-devin` or `cli-codex` reviews every writer diff read-only, and the writer reviews any reviewer fix. No Claude leaf writes or reviews. The session runs the baselines, the probe and the closure gates, and commits path-scoped. P0 and P1 findings are fixed and rechecked, P2 findings are recorded.

Each phase's observable check:

1. **Design and the fixed corpus.** Read the two mode `SKILL.md` files, the hub's four routing artifacts, `leaf-manifest.json`, `sk-create-readme`, the skill template, the eleven folders with their suites, and the baseline gates, all read-only, then write the design note under `scratch/`. Check: the note fixes the probe's ten prompts with their expected decisions, the seven intents with their manifest leaves, the test command per README, and answers `spec.md` section 10 with a proposed answer per question; every `UNKNOWN` is named, and no read-only source is edited.
2. **Part A, the eleven READMEs.** Write each code-folder README per `sk-create-readme`'s code-folder template. Check: `validate_document.py` exits 0 on all eleven, each documented test command passes from the repository root, and the four out-of-scope folders are untouched.
3. **Part B, the hub surface.** Promote `ROUTER.md` to active with the seven intents and the manifest leaves, add the surface-router note to `SKILL.md`, rename the class to `cli-jev-aliases`, add the thirteen phrases to the two dispatch classes, remove the self-referential folder sentence from current-state docs, move the five routing artifacts to `0.6.0.0` and write the hub changelog entry. Check: `parent-skill-check.cjs` prints 0 warnings with 12a, 13a and 13b passing, `rg -n 'cli-usage-aliases'` prints nothing, and no bare backend word is added.
4. **Part B, the mode section 2s and the mode releases.** Reshape both section 2s to the template's subsections and one Smart Router Pseudocode block with the five named functions, move `cli-jev`'s transport mechanics to section 3, and bump `cli-jev` to `0.1.4.0` and `cli-deem` to `0.1.1.0` with their changelog entries. Check: each of the five names appears once per mode, no request-to-file lookup table remains as the routing contract, and `validate_skill_package.py` passes on the hub and both modes.
5. **Generated artifacts, probe and review.** Regenerate the compiled-route manifest and the Hermes mirror through their own tools, replay the ten prompts through `.skilled/bin/compiled-route.cjs --hub cli-classifier`, and run the cross-family review. Check: the guard reports the hub fresh, `sync-skills-hermes.cjs --check` passes, the eight baseline-correct rows match and the two former misses route, and the review records no open P0 or P1.
6. **Closure.** Record every gate result and the probe comparison in `implementation-summary.md` and `goal.md`'s log, mark each acceptance criterion from its evidence, then run `repair-derived.cjs --apply`, `validate.sh --strict` and `check-goal.cjs`. Check: `RESULT: PASSED` for this phase and the parent, and `RESULT: PASSED (5/5 checks)`.

## 7. ROLLBACK PLAN

- **Trigger**: A probe row that was correct at baseline changes decision, an active `ROUTER.md` names a leaf that does not resolve, a README documents a command that cannot run, a version artifact disagrees with its newest changelog, or a file outside `spec.md` section 3 changes.
- **Procedure**: Stop the phase. Revert its path-scoped commits: the eleven READMEs, the hub routing artifacts, both mode `SKILL.md` edits, the three changelog entries and the regenerated manifest and Hermes copies. Then restore the three version lines from the pre-change commit and rerun `parent-skill-check.cjs`, `validate_skill_package.py` and the probe. No behavior changed at baseline, so the revert returns the tree to a passing state, and no runtime file outside the hub artifacts and the generated mirrors is touched.
