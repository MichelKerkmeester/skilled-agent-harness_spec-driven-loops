# Audit Unused Dependencies

## Overview

Static audit of the dependency manifests (e.g., `package.json`, `requirements.txt`, `go.mod`) to detect packages that are declared but never imported, and produce a verified removal plan. Scope covers direct dependencies only; transitive dependencies are out of scope.

## Problem

Declared dependencies drift out of sync with actual usage over time. Unused packages inflate install time, disk footprint, and vulnerability exposure, and they obscure which packages are truly load-bearing.

## Goals

- Produce a machine-generated report of declared-but-unreferenced direct dependencies.
- Classify each hit as removable, false positive, or needs-review.
- Apply verified removals with no behavioral change to the project.

## Non-Goals

- Transitive dependency analysis or lockfile pruning beyond what removal of direct deps causes.
- Version upgrades or vulnerability remediation of retained dependencies.
- Repo-wide refactors of import statements.

## Requirements

### Functional

1. Enumerate all declared direct dependencies from the manifest(s) for the detected stack.
2. Detect references via static analysis of source, tests, config, and build scripts (imports, requires, dynamic references, CLI usage).
3. Emit a report listing, per dependency: name, declared location, reference count, and classification.
4. Support an explicit allowlist for dependencies used only at runtime, by tooling, or via dynamic loading.
5. Apply removals from the manifest(s) and regenerate the lockfile via the stack's package manager.

### Non-Functional

- Audit script is deterministic: identical repo state yields identical report.
- Report generation runs without modifying the repository.
- Removal changes are isolated to manifest and lockfile; no source edits.

## Acceptance Criteria

1. Report lists every declared direct dependency with a reference count and classification.
2. Zero false positives among packages classified removable, verified by a passing build and full test suite after removal.
3. All removals pass the project's lint, typecheck, and test gates with no behavioral diff.
4. Any dependency failing classification is listed under needs-review rather than auto-removed.
5. A repeat audit run against the cleaned manifest reports no removable dependencies.

## Risks

- Dynamic or reflective imports cause false positives; mitigated by allowlist and needs-review class.
- Runtime-only dependencies (plugins, CLI entry points) appear unused; mitigated by explicit allowlist.
- Lockfile regeneration may surface unrelated version bumps; keep diff minimal and review before commit.

## Open Questions

- Which allowlist entries are required for this repository's dynamic loading paths?
- Should the audit report be committed as a maintenance artifact or generated on demand?
