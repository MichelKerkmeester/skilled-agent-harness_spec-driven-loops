# Iteration 002 — Spec-kit metadata

- **Focus (charter 2):** Frontmatter fields in every doc type, `description.json`, `graph-metadata.json`, `_memory.continuity`, `trigger_phrases`, `importance_tier`, `contextType`, and which validator enforces each.
- **Status:** complete
- **NewInfoRatio:** 0.80
- **Novelty:** First mapping of the three persisted metadata surfaces (frontmatter canon, generated metadata pair, continuity block) to their writers and enforcing rules, including the source-fingerprint freshness mechanism.

## Findings

### F1 — One frontmatter canon, enforced as one rule

- `FRONTMATTER_VALID` (ERROR, spec docs) requires non-empty `title`, `description`, `trigger_phrases`, `importance_tier`, `contextType`; unclosed YAML (`missing closing ---`) is also an issue (`validation-rules.md:60`; `check-frontmatter.sh:9-11`, `check-frontmatter.sh:48-52`, `check-frontmatter.sh:105-109`; remediation text names the five fields at `check-frontmatter.sh:145`).
- Legacy documents are grandfathered through `frontmatter-grandfather-allowlist.json` until a cutoff (`check-frontmatter.sh:23`, `check-frontmatter.sh:114-115`).
- `trigger_phrases` has a dedicated list-aware check: `[]` or `null` counts as empty (`check-frontmatter.sh:105-109`).
- The canon is exactly the five keys documented in `grep-convention.md:56-66` (iteration 1, F5).

### F2 — `description.json`: generated discovery metadata, one per packet

Observed shape at this packet (001-okf-deep-research/description.json:1-16): `specFolder`, `description`, `keywords[]`, `lastUpdated`, `specId`, `folderSlug`, `parentChain[]`, `memorySequence`, `memoryNameHistory[]`, `level`. The parent packet's copy carries the same fields for its own folder (050/description.json:1-14).
- Generated by the save/plan path; every planner mode refreshes it and `graph-metadata.json` (`save-workflow.md:171`, `save-workflow.md:257`, `save-workflow.md:298`). Writer: `runtime/cli/spec-folder/generate-description.ts`.
- It is explicitly a *generated* pair, distinct from authored frontmatter (`save-workflow.md:298` "generated metadata pair").

### F3 — `graph-metadata.json`: packet graph node with a derived rollup

- Leaf shape (001-okf-deep-research/graph-metadata.json:1-20): `schema_version`, `packet_id`, `spec_folder`, `parent_id`, `children_ids[]`, `manual{depends_on,supersedes,related_to}`, `derived{trigger_phrases, key_topics, importance_tier, status, key_files, entities, ...}`.
- Full derived key set observed on the parent (050/graph-metadata.json): `trigger_phrases`, `key_topics`, `importance_tier`, `status`, `key_files`, `entities`, `causal_summary`, `created_at`, `last_save_at`, `save_lineage`, `last_accessed_at`, `source_docs`, `source_fingerprint`, `source_fingerprint_docset`, `source_doc_hashes`, `last_active_at`; parents add `derived.last_active_child_id` (`phase-definitions.md:104-107`).
- Freshness is fingerprint-based: the save refresh hashes the packet's source docs, so a doc changed after the refresh fails the next strict validation with `SOURCE_FINGERPRINT_MISMATCH` (`save-workflow.md:298`).
- Phase-parent pointer walk: a leaf save writes its `_memory.continuity`, then walks up to five ancestor levels writing each parent's `derived.last_active_child_id` + fresh `last_active_at`; a track root keeps its pointer in telemetry only (`save-workflow.md:331`).
- In the observed parent, `children_ids` holds the three phase children (`050/graph-metadata.json`), matching the Phase Documentation Map in `050/spec.md:104-128`.

### F4 — `_memory.continuity`: the machine-owned continuity payload

- Lives in `implementation-summary.md` frontmatter (primary continuity document) (`save-workflow.md:285`, `save-workflow.md:321`).
- Fields with hard limits (`save-workflow.md:237-250`): `recent_action` (≤96 chars / 16 words, one line), `next_safe_action` (same + imperative opener), `blockers` (≤5), `key_files` (≤5 repo-relative paths), `completion_pct` (0-100; 100 only with no blockers/open questions), `open_questions` / `answered_questions` (question ids, disjoint).
- Writer-owned fields: `packet_pointer`, `last_updated_at`, `last_updated_by` (`save-workflow.md:250`). Only `--full-auto` writes continuity fields; planner modes refresh metadata but do not write the block (`save-workflow.md:237`, `save-workflow.md:257`).
- Shape example (`save-workflow.md:305-317`): nested `_memory: continuity:` mapping.
- Recovery ladder consumes it second, after `handover.md` (`save-workflow.md:358`, `save-workflow.md:406`).

### F5 — Cross-surface observations relevant to the OKF comparison (deferred to crosswalk)

- OKF `generated.at` (SPEC.md §5.2) is a single "last meaningful change" timestamp; spec-kit carries `last_updated_at` plus a whole-document `source_fingerprint` / `source_doc_hashes` set — a stronger integrity signal, weaker at expressing *who* changed it (next to `last_updated_by`).
- OKF `status` (draft/stable/deprecated) overlaps the packet `Status` field and the graph `derived.status`, but spec-kit has no per-doc staleness instant like `stale_after`.
- OKF `verified` has no spec-kit counterpart in any of the three surfaces — the candidate that needs the closest scrutiny in iteration 6.
