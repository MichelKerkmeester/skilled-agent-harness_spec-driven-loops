## What Was Built

The four authoring intents now load one 172-line card instead of the 1,200-line template guide, and the guide is reachable on request.

### Phase 5: weak-model-authoring-card

`.skilled/skills/system-spec-kit/references/workflows/spec-authoring-card.md` is the card a weak model follows to author one packet: 11 numbered sections, the longest 18 lines. Four `RESOURCE_MAP` rows in `SKILL.md` (PLAN, IMPLEMENT, INTAKE and TEMPLATE_AUTHORING) load the card, the guide stays in `ON_DEMAND`, and one prose sentence records that exception. `leaf-manifest.json` and `leaf-aliases.json` were regenerated by the shipped scripts and both list the card (46 entries each). One checklist line now sends a reader to a rendered example or a fresh scaffold, and the Task Format line of `templates/core/tasks.md.tmpl` declares the `Verify:` slot. `runtime/cli/spec/check-card-sync.sh` fails on the first disagreement between the four surfaces, `runtime/cli/tests/card-sync.vitest.ts` runs it in the suite, and the card passes `workflow-invariance.vitest.ts` as an extra path.

## How It Was Delivered

One execution agent ran `tasks.md` T001 to T015 and dispatched no subagent. The card, the router rows, the checklist line and the template line were applied by scripts that read `plan.md`, so the shipped text is the plan's text. The guard came from `tasks.md` T009 the same way. The three smoke runs and the review ran on cli-devin swe-2-max, the runs on `--permission-mode dangerous` and the review read-only on `auto`. The conductor owns the commit and the push decision.

<!-- ANCHOR:decisions -->
## Key Decisions

| Decision | Why |
|----------|-----|
| One card replaces the guide as the default load | A weak model samples a long doc, so a short card with one command per step is the only load it finishes |
| The inventory is generated, never hand-edited | Two generated files check each other, and a hand edit passes one check and fails the other |
| A shell guard plus one vitest test | The invariant spans skill files, so a packet validator cannot see it and a post-edit hook cannot block on it |

<!-- ANCHOR:limitations -->
## Known Limitations

1. **The card has two open P1 defects from the review.** Step 2 dead-ends when `recommend-level.sh` prints Level 0, because `create.sh --level` does not accept 0. Steps 3, 8, 9 and 11 write to `goal.md`, which a default scaffold does not create. The card text is frozen, so both wait for a conductor amendment. The proposed fixes are in `goal.md` section 4.
2. **Three smoke runs detect only large effects.** The card either lets a weak model finish a Level 1 packet or it does not. Phase 009 reports the range and the delta, not a significance claim.
3. **The card does not repair the guide.** The guide keeps its defects until phase 2 and phase 3 fix them, and this phase only changes which tier loads it.
