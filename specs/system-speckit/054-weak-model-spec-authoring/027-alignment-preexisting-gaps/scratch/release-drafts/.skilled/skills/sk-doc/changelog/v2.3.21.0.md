# v2.3.21.0, The Hub Lists Changelogs as Global Only

Spec folders no longer hold changelogs, and the hub now says so where a reader picks a mode. The changelog mode itself changed in `sk-create-changelog` v1.3.6.0.

> Spec folders: `specs/system-speckit/054-weak-model-spec-authoring/025-deprecate-nested-changelogs` and `027-alignment-preexisting-gaps` (Level 2)

&nbsp;

## What's New at a Glance

- **The mode table and the command catalog say global only.** The `sk-create-changelog` row and the `/create:changelog` entry drop packet-local changelogs and the `--nested` flag.
- **The changelog mode refuses a packet-local request.** The routing aliases stay so the mode can catch such a request and offer a global entry instead.
- **A packet changelog request reaches sk-doc first.** The changelog intent in `ROUTER.md` gains `changelog entry`, `nested changelog`, `packet changelog` and `packet-local changelog`, and the generator carries them into `graph-metadata.json`. With `system-skill-advisor` v0.17.10.0, such a request ranks the changelog mode first.
- **The frontmatter guide stops sending packet entries to the spec-kit templates.** It says packet changelogs are deprecated and that existing ones keep the block the generator renders.
- **The READMEs point at real files.** The sk-doc README says Level 2 adds `acceptance-criteria.md` as the closure gate, not `checklist.md`. Its structure-extraction example now takes a placeholder path. The `sk-create-frontmatter` README reaches the budget file through the relative path `../shared/assets/skill-contract.json`.

&nbsp;

## Upgrade

No migration required. Rebuild the advisor so it reads the new changelog phrases: `node .skilled/bin/skill-advisor.cjs advisor_rebuild --trusted --force true`.
