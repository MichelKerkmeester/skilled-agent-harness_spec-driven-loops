## 2026-10-24

> Spec folder: `specs/system-speckit/054-weak-model-spec-authoring/005-weak-model-authoring-card` (Level 3)
> Parent packet: `specs/system-speckit/054-weak-model-spec-authoring`

### Summary

The four authoring intents now load one 172-line card instead of the 1,200-line template guide, and the guide is reachable on request.

### Added

- `references/workflows/spec-authoring-card.md`: a 172-line card with 11 numbered sections that walks a model through one packet, from picking the level to closing it.
- `runtime/cli/spec/check-card-sync.sh`: a guard that fails on the first disagreement between the card, the four `RESOURCE_MAP` intents, the two inventory files and the authoring checklist.
- `runtime/cli/tests/card-sync.vitest.ts`: a test that runs the guard in the suite.
- A `Verify:` slot in the Task Format line of `templates/core/tasks.md.tmpl`, so every new `tasks.md` declares a verify clause per task.
- A row for the guard in the package topology list of `runtime/cli/spec/README.md`.

### Changed

- The PLAN, IMPLEMENT, INTAKE and TEMPLATE_AUTHORING intents in `SKILL.md` load the card, and the template guide stays in `ON_DEMAND` only. One prose sentence records that exception.
- `leaf-manifest.json` and `leaf-aliases.json` were regenerated by the shipped scripts and list the card, 46 entries each.
- The authoring checklist sends a reader to a rendered example or a fresh `create.sh` scaffold instead of the templates root.
- Four golden snapshots in `scaffold-golden-snapshots.vitest.ts.snap` were regenerated, and only the Task Format line differs.

### Fixed

- A reader who follows an authoring intent no longer lands on the 1,200-line guide first, and a later edit that drops the card from one intent, moves the guide back into an intent, or leaves the checklist on the templates root now fails the guard.

### Follow-Ups

- The card has two open P1 defects from the review. Step 2 dead-ends when recommend-level.sh prints Level 0, because create.sh --level does not accept 0. Steps 3, 8, 9 and 11 write to goal.md, which a default scaffold does not create. The card text is frozen, so both wait for a conductor amendment. The proposed fixes are in goal.md section 4.
- Three smoke runs detect only large effects. The card either lets a weak model finish a Level 1 packet or it does not. Phase 009 reports the range and the delta, not a significance claim.
- The card does not repair the guide. The guide keeps its defects until phase 2 and phase 3 fix them, and this phase only changes which tier loads it.
