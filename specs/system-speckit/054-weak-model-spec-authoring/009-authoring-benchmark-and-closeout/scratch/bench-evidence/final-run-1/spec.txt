# Feature Specification: Add a quiet flag to recommend-level.sh

<!-- SPECKIT_LEVEL: 3 -->


---

## EXECUTIVE SUMMARY
<!-- FILL: Write three sentences: the problem, the change and the proof. GOOD: Callers parse a 17-line report to read one value. The flag prints one line. A line count proves it. WEAK: This document describes the feature. -->

Callers of `.skilled/skills/system-spec-kit/runtime/cli/spec/recommend-level.sh` that need only the recommended level must parse a multi-line human report — or the full JSON document — to read one value. The change adds a `--quiet` flag that prints only the `Recommended Level: <N> (<Name>)` line. Proof is a line count: `--quiet` prints exactly one line while every non-quiet invocation stays byte-identical.

**Key Decisions**: `--quiet` alters only the default text report — `--json` output is unchanged when the two flags combine. The quiet line reuses the exact `Recommended Level: <N> (<Name>)` string the report already prints, so existing parsers keep one stable label.

**Critical Dependencies**: None — one bash file, no new tools, no external services.

## 2. PROBLEM & PURPOSE
<!-- FILL: State the problem in two sentences: what breaks, and for whom. GOOD: The recommend-level script prints a 17-line report, so a caller that needs only the level cannot parse the answer. WEAK: The script has issues with output. -->

### Problem Statement
`recommend-level.sh` prints a ~15–20 line human-readable report (or a full JSON document under `--json`); it has no minimal machine-readable mode. Dispatch and harness tooling that invokes the script to learn a packet's level must grep the `Recommended Level:` line out of the report — a fragile contract that breaks silently if the report's wording ever moves.

### Purpose
With `--quiet`, the script prints exactly its final recommended-level line and nothing else, so a caller captures the level with zero parsing while every existing invocation keeps its current output.
<!-- /ANCHOR:problem -->

## 3. SCOPE
<!-- FILL: List three to five things this change does, each starting with a verb. GOOD: Add a `--quiet` flag that prints only the recommended-level line. WEAK: Update the script and docs. -->

### In Scope
- Add a `--quiet` boolean flag, with `-q` as its short alias, to the argument parser of `recommend-level.sh`.
- Add a quiet branch in the output dispatch that prints only the `Recommended Level: <N> (<Name>)` line.
- Document the flag in the script's header OPTIONS comment and in `show_help()`.
- Preserve every existing behavior byte-identically: the default report, the `--json` document, all error paths, stderr routing and exit codes.

### Out of Scope
- Changing the report's wording, scoring, or the JSON schema — the flag must not alter existing output contracts, because downstream tooling already parses them.
- A bare-value quiet format (e.g., printing `3` alone) — the spec keeps the existing `Recommended Level:` label so parsers written against today's line keep working.
- Edits to any other spec-kit script or caller — the change is confined to one file.

| `.skilled/skills/system-spec-kit/runtime/cli/spec/recommend-level.sh` | Modify | Add `QUIET` global, `--quiet\|-q` parse case, quiet output branch, and help text |

## 5. SUCCESS CRITERIA
<!-- FILL: Write one measurable outcome per line. A command can prove it. GOOD: `recommend-level.sh --quiet --loc 500 --files 15` prints one line and exits 0. WEAK: The feature is successful. -->

- **SC-001**: `bash .skilled/skills/system-spec-kit/runtime/cli/spec/recommend-level.sh --quiet --loc 1000 --files 20 --architectural --api --db | wc -l` prints `1`, the line reads `Recommended Level: 3 (Full)`, and the exit code is 0.
- **SC-002**: The default (non-quiet) output for a fixed invocation is byte-identical before and after the change — `diff` of the two captures is empty.
- **SC-003**: `--quiet --json` output equals `--json` output for the same inputs — `diff` of the two captures is empty.

**Given** the script runs with `--quiet --loc 1000 --files 20 --architectural --api --db`, **When** it exits, **Then** stdout is exactly the single line `Recommended Level: 3 (Full)` and the exit code is 0.

**Given** the same invocation without `--quiet`, **When** it exits, **Then** stdout equals the pre-change multi-line report byte-for-byte.

**Given** `--quiet --json --loc 100 --files 3`, **When** it exits, **Then** stdout is the same JSON document `--json` alone prints.

**Given** `--quiet` with neither `--loc` nor `--files`, **When** it runs, **Then** it exits 1, the missing-input error goes to stderr, and stdout is empty.

**Given** `--quiet --bogus`, **When** it runs, **Then** it exits 1 with the unknown-option error on stderr.

**Given** `--help` (with or without `--quiet`), **When** it runs, **Then** the help text names `--quiet` and its `-q` alias.
