## 3. ARCHITECTURE
<!-- FILL: Name the pattern in three words, then list the one component that changes. GOOD: Single script branch. The component is `recommend-level.sh`. WEAK: Standard architecture. -->

### Pattern
Single-script flag branch — procedural CLI, additive opt-in flag.

### Key Components
- **Argument parse loop** (`recommend-level.sh`): gains a `--quiet|-q)` case that sets `QUIET=true`, matching the existing `--json|-j)` pattern.
- **Output dispatch** (`recommend-level.sh` §7): gains a quiet branch between the `--json` check and `output_text`, emitting the level line through the same format the report uses.

### Data Flow
`argv` → parse loop sets globals (`QUIET`, `JSON_OUTPUT`, inputs) → scoring functions compute `TOTAL_SCORE` → `determine_level` sets `RECOMMENDED_LEVEL`/`LEVEL_NAME` → dispatch selects `output_json` / quiet line / `output_text` → stdout. `--quiet` changes only the last selection step.

## L3: ARCHITECTURE DECISION RECORD
<!-- FILL: Write one ADR per decision. Name the context, the choice, the consequence and the rejected option. GOOD: ADR-001: a flag, because callers already pass flags. WEAK: We made a decision. -->

### ADR-001: `--quiet` selects a shorter stdout path; it does not touch `--json`

**Status**: Proposed

**Context**: Two caller classes exist: humans reading the report, and scripts wanting one value or a structured document. `--json` already serves the structured case. A `--quiet` that also altered JSON would make one flag change two contracts, and a `--quiet` that printed a bare `3` would force parsers to learn a second format for the same fact.

**Decision**: `--quiet` alters only the default text path: it prints the identical `Recommended Level: <N> (<Name>)` line the report prints, and nothing else. Combined with `--json`, JSON output is unchanged.

**Consequences**:
- One stable label for parsers, one flag for the common "just the level" case.
- Quiet hides score/confidence/phase detail — mitigated because it is opt-in and `--json` covers structured reads.

**Alternatives Rejected**:
- Bare-value output (`3`): rejected — a second format for the same fact invites drift between parsers.
- Environment variable instead of a flag: rejected — callers already pass flags (`--json`, `--loc`); an env var splits the interface.
