# Feature Specification: Add a quiet flag to recommend-level.sh

<!-- SPECKIT_LEVEL: 3 -->


---

## EXECUTIVE SUMMARY

`recommend-level.sh` always prints its full report — a 16-to-18-line text block or a multi-field JSON document — so a caller that needs only the recommended level must parse output meant for humans. This change adds a `--quiet` flag that prints exactly the `Recommended Level: N (Name)` line and nothing else. The proof is a line count: `--quiet` prints one line while a diff of the default output stays empty.

**Key Decisions**: `--quiet` prints the same level line `output_text` already emits (ADR-001); `--quiet` takes precedence over `--json` (ADR-002)

**Critical Dependencies**: None — bash only, and the existing scoring path runs unchanged

## 2. PROBLEM & PURPOSE

### Problem Statement
`recommend-level.sh` prints a 16-to-18-line report (or a multi-field JSON document) even when the caller wants only the recommended level. Automation that needs that one value — for example a script choosing a documentation level — must parse prose or JSON fields it does not use, coupling itself to the report's format.

### Purpose
A caller can run `recommend-level.sh --quiet` and read the recommended level from a stdout that holds exactly one line.
<!-- /ANCHOR:problem -->

---

<!-- ANCHOR:scope -->
## 3. SCOPE

### In Scope
- Add a `--quiet` flag (with a `-q` alias) to the option parser in `recommend-level.sh`
- With `--quiet`, print exactly one line on stdout: `Recommended Level: <N> (<Name>)` — the same line `output_text` emits today
- Document the flag in the header comment's OPTIONS list and in `show_help`
- Keep every non-quiet output path byte-identical to today's output

### Out of Scope
- Changing the scoring algorithm, level thresholds, or phase recommendation — the flag only selects an output format
- A minimal JSON payload for `--quiet --json` — quiet prints the same text line in every mode (ADR-002)
- Adopting `--quiet` in existing callers such as `spec-authoring-card.md` — a separate docs change
- Editing any file other than `recommend-level.sh`

### Files to Change

| File Path | Change Type | Description |
|-----------|-------------|-------------|
| `.skilled/skills/system-spec-kit/runtime/cli/spec/recommend-level.sh` | Modify | Add `QUIET_OUTPUT` global, `--quiet|-q` parser case, quiet output branch, and help text |

## 5. SUCCESS CRITERIA

- **SC-001**: `bash recommend-level.sh --quiet --loc 500 --files 15 | wc -l` prints `1` and the run exits 0
- **SC-002**: A `diff` of default text and JSON runs before and after the change is empty
- **SC-003**: `bash recommend-level.sh --quiet --json --loc 500 --files 15` prints the single text line, not a JSON document

## 7. NON-FUNCTIONAL REQUIREMENTS

### Performance
- **NFR-P01**: `--quiet` adds no measurable time — it skips report rendering but runs the same scoring path

### Security
- **NFR-S01**: No new input surface — the flag takes no value, so argument validation is unchanged

### Reliability
- **NFR-R01**: Exit codes and stderr behavior are unchanged: errors still exit 1 and write to stderr, success exits 0

---

## 8. EDGE CASES

### Data Boundaries
- Empty input: `--quiet` with neither `--loc` nor `--files` hits the existing required-input error (stderr, exit 1); no level line prints
- Maximum length: extreme values such as `--loc 100000 --files 9999 --quiet` still print exactly one line

### Error Scenarios
- External service failure: N/A — the script makes no external calls
- Network timeout: N/A — the script runs fully offline
- Unknown option alongside `--quiet`: the existing `ERROR: Unknown option` path fires during parsing, before any output

### State Transitions
- Partial completion: N/A — the script is atomic: it parses, scores, then prints
- Session expiry: N/A — the script holds no session state
