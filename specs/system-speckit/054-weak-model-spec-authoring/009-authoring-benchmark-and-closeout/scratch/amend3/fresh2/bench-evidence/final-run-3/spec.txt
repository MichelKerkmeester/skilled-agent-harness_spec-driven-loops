# Feature Specification: Add a quiet flag to recommend-level.sh

<!-- SPECKIT_LEVEL: 3 -->

---

## EXECUTIVE SUMMARY

`recommend-level.sh` answers one question, but its human-readable answer is a 17-line report: the recommended level is the second line, followed by the score, a six-row breakdown and the phase section. A caller that needs only the level has to parse the report or switch to `--json` and decode it. This packet adds a `--quiet` flag that prints only the `Recommended Level:` line, keeps the default report byte-identical, and is proved by a baseline diff plus a one-line count.

**Key Decisions**: `--quiet` is an opt-in flag, not an environment variable; `--json` keeps precedence when both flags are passed; both output paths render the level line through one shared helper.

**Critical Dependencies**: `bash` 3.2 or newer, the existing `output_text` report format, and `node` for the phase-system regression suite. No new package.

## 2. PROBLEM & PURPOSE

### Problem Statement

`recommend-level.sh` reports a single recommended level inside a 17-line human report. A build script, CI step or agent prompt that needs only the level must either parse that report or invoke `--json` and run a JSON decoder, and both routes cost more than reading one line. There is no output mode between the full report and a structured document.

### Purpose

Give callers a one-line, stable, greppable answer with `--quiet`, without changing what any existing invocation prints.
<!-- /ANCHOR:problem -->

<!-- ANCHOR:scope -->
## 3. SCOPE

### In Scope
- Add a `--quiet` flag, with `-q` as its short alias, to the argument parser.
- Add a single-line output path that prints `Recommended Level: <N> (<Name>)` and nothing else.
- Document the flag in the script header OPTIONS block and in `show_help`.
- Prove the default report is byte-identical and the quiet output is exactly one line.

### Out of Scope
- Changing scoring, thresholds or phase logic - the request is an output mode, not a behavior change.
- Suppressing stderr - errors must stay visible when stdout is quiet.
- Changing the `--json` document - it is already a compact machine format and its consumers are unaffected.
- Adding the same flag to other scripts - `create.sh`, `validate.sh` and the rest keep their current output.

### Files to Change

| File Path | Change Type | Description |
|-----------|-------------|-------------|
| `.skilled/skills/system-spec-kit/runtime/cli/spec/recommend-level.sh` | Modify | Add the flag, the shared level-line helper, the single-line output path, and the two documentation blocks that describe the flag. |

## 7. NON-FUNCTIONAL REQUIREMENTS

### Performance
- **NFR-P01**: The quiet path adds no subshell and no extra process, so a quiet invocation stays within the measured baseline of 0.01 seconds `real` on the reference machine (`/usr/bin/time -p`).

### Security
- **NFR-S01**: N/A - the script reads no credential and touches no file; `--quiet` changes stdout formatting only.

### Reliability
- **NFR-R01**: Exit codes are unchanged: 0 on success and 1 on invalid input, with or without `--quiet`.

---

## 8. EDGE CASES

### Data Boundaries
- Empty input: `--quiet` alone (no `--loc`, no `--files`) exits 1 with `ERROR: At least --loc or --files must be provided` on stderr and nothing on stdout.
- Maximum input: `--loc 5000 --files 50` caps at the weight totals; the quiet path still prints one line with `Recommended Level: 3 (Full)`.

### Error Scenarios
- External service failure: N/A - the script makes no network call.
- Network timeout: N/A - the script makes no network call.
- Unknown option: `--quiet --bogus` exits 1 with `ERROR: Unknown option: --bogus` on stderr.

### State Transitions
- Partial completion: N/A - the script computes once and writes no state.
- Session expiry: N/A - the script is stateless per invocation.
- Repeated flag: `--quiet --quiet` is idempotent and still prints one line.
- Flag position: `--quiet` before, between or after the other flags yields the same output because parsing is order-independent.
