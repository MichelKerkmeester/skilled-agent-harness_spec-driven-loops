# Feature Specification: Add a quiet flag to recommend-level.sh

<!-- SPECKIT_LEVEL: 3 -->


---

## EXECUTIVE SUMMARY

A caller that wants one number from `recommend-level.sh` reads a report. `--loc 50 --files 2` prints 16 lines and `--loc 500 --files 15 --auth --api --db --architectural` prints 17, measured on this checkout. The level sits on one of those lines, so every caller either parses the report or counts lines. A `--quiet` flag prints only `Recommended Level: N (Name)`, and the default report stays byte-identical.

**Key Decisions**: `--quiet` is a flag on the existing parser, not an environment variable. `--json` keeps precedence when a caller passes both flags.

**Critical Dependencies**: bash, already required by the script. No new package.

## 2. PROBLEM & PURPOSE

### Problem Statement
`recommend-level.sh` prints a human report. Measured on this checkout, `bash recommend-level.sh --loc 50 --files 2` writes 16 lines and the full-flag example writes 17. The recommended level is the second line, behind a blank line. A caller that needs the level either parses text it does not want or pipes the report through `awk`/`sed`. The existing `--json` flag returns a whole object, so it needs a JSON parser and still hands back more than the caller asked for.

### Purpose
One flag prints one line: `Recommended Level: N (Name)`. Callers get the answer without parsing the report, and the default report does not change.
<!-- /ANCHOR:problem -->

## 3. SCOPE

### In Scope
- Add `--quiet` to the argument parser in `recommend-level.sh`.
- Add a quiet renderer that prints only the `Recommended Level: N (Name)` line.
- List `--quiet` in the `--help` output and the script header OPTIONS block.
- Pin the default report and the quiet line with a regression test.

### Out of Scope
- The `--json` output shape. It already serves machine callers and stays untouched.
- Scoring weights, level thresholds and phase scoring. The flag changes rendering only.
- stderr messages and exit codes. They stay as they are so existing error handling keeps working.
- A `-q` short alias. No caller asked for one, and the single-letter namespace is still open.
- Other scripts that might call this one. A repository search found no shell consumer, only two Node test files.

### Files to Change

| File Path | Change Type | Description |
|-----------|-------------|-------------|

## 7. NON-FUNCTIONAL REQUIREMENTS

### Performance
- **NFR-P01**: The flag adds no measurable time. It skips formatting work the default path does, so the quiet run finishes within 5 ms of the default run on the same inputs.

### Security
- **NFR-S01**: N/A. The flag changes stdout only. The script reads no credential, writes no file and makes no network call.

### Reliability
- **NFR-R01**: Output is deterministic. The same arguments produce the same bytes on every run.

---

## 8. EDGE CASES

### Data Boundaries
- Empty input: `--quiet` with neither `--loc` nor `--files` exits 1 and writes `ERROR: At least --loc or --files must be provided` to stderr. stdout stays empty.
- Maximum length: The line is short at every level. `Recommended Level: 3 (Full)` is the longest form, because the level name comes from a fixed set of four words.

### Error Scenarios
- External service failure: N/A. The script calls no service.
- Network timeout: N/A. The script makes no network call.
- Invalid number: `--quiet --loc abc` exits 1 with `ERROR: --loc must be a positive integer` on stderr.
- Unknown option: `--quiet --bogus` exits 1 with `ERROR: Unknown option: --bogus` on stderr.

### State Transitions
- Partial completion: N/A. The script is stateless and writes nothing.
- Session expiry: N/A. There is no session.
- Both flags: `--quiet --json` prints the JSON object. The quiet renderer never runs when JSON is requested.
- Help wins: `--help` exits 0 from inside the parser, so `--quiet --help` prints the full help text.
- No phase section: `--quiet --no-recommend-phases` still prints one line, because the quiet renderer emits no phase fields.

<!-- ANCHOR:questions -->
## 12. OPEN QUESTIONS

- Does `--quiet` need a short `-q` alias? Not now. The plan ships the long form and leaves `-q` free.
- Should `--quiet` suppress stderr warnings? No. Silence on stdout is the request; errors stay visible.
- Does `--quiet` change the exit code? No. It stays 0 on success and 1 on input errors.
