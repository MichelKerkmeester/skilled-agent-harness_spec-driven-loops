## 1. SUMMARY

### Technical Context

| Aspect | Value |
|--------|-------|
| **Language/Stack** | Bash (`set -euo pipefail`; bash 3.2-compatible, no new builtins) |
| **Framework** | None — standalone CLI script |
| **Storage** | None |
| **Testing** | Invocation matrix plus `wc -l` and `diff` byte comparisons; the script has no unit-test harness |

### Overview
The change adds a `QUIET=false` global, a `--quiet)` case in the existing argument-parse loop, a `output_level_line()` helper that both the report and the quiet path call, and a quiet branch in the output dispatch after the JSON check. The header OPTIONS comment and `show_help()` gain the flag. Proof is a line count of 1 under `--quiet` and an empty `diff` for every non-quiet invocation against a captured baseline.

<!-- ANCHOR:architecture -->
## 3. ARCHITECTURE

### Pattern
Single-script flag branch — a procedural CLI with one additive, opt-in flag.

### Key Components
- **Argument parse loop** (`recommend-level.sh` §5): gains a `--quiet)` case that sets `QUIET=true`, following the shape of the existing `--json|-j)` case.
- **Output helpers** (`recommend-level.sh` §4): gain `output_level_line()`, the single format site for the `Recommended Level:` line.
- **Output dispatch** (`recommend-level.sh` §7): gains a quiet branch between the `--json` check and `output_text`, calling the same helper.

### Data Flow
`argv` → the parse loop sets globals (`QUIET`, `JSON_OUTPUT`, inputs) → the scoring functions compute `TOTAL_SCORE` → `determine_level` sets `RECOMMENDED_LEVEL` and `LEVEL_NAME` → the dispatch selects `output_json`, the quiet line, or `output_text` → stdout. `--quiet` changes only the last selection, never the computation.
<!-- /ANCHOR:architecture -->

## FIX ADDENDUM: AFFECTED SURFACES

This is an additive feature rather than a fix, but stdout is a contract, so the producer and consumer inventory is recorded anyway.

| Surface | Current Role | Action | Verification |
|---------|--------------|--------|--------------|
| `recommend-level.sh` `output_text()` | producer — owns the report's level line | update: call `output_level_line()` instead of a second literal | `rg -n 'output_level_line|Recommended Level' recommend-level.sh` shows one literal, in the helper |
| `recommend-level.sh` `show_help()` and header OPTIONS comment | docs surface | update: list `--quiet` | `recommend-level.sh --help` prints the option |
| `recommend-level.sh` `output_json()` | producer — owns the JSON document | unchanged | `diff` of `--json` against `--quiet --json` is empty |
| Scripted callers of `recommend-level.sh` | consumers of stdout | unchanged — the default contract is preserved | `rg -ln 'recommend-level' .skilled --glob '*.sh'` finds the script itself and no caller that parses the report |
| `create.sh`, `validate.sh` and other spec CLIs | sibling CLIs | not a consumer — none of them invokes `recommend-level.sh` | `rg -n 'recommend-level' .skilled/skills/system-spec-kit/runtime/cli/spec --glob '*.sh'` |

Required inventories:
- Same-class producers: `rg -n 'Recommended Level' .skilled/skills/system-spec-kit/runtime/cli/spec/recommend-level.sh` — one site inside `output_text()` today; the change moves it into the helper so the quiet path shares it.
- Consumers of changed symbols: `rg -ln 'recommend-level' .skilled --glob '*.sh' --glob '*.ts' --glob '*.cjs'` — the script itself, plus template snapshots that quote template prose rather than call the script.
- Matrix axes: `{--quiet, absent}` × `{default, --json}` × `{valid args, missing args, unknown flag}` × `{flag before args, flag after args}`; the required rows are the matrix in `tasks.md` T009.
- Algorithm invariant: stdout is a contract — without `--quiet` the bytes are unchanged; with `--quiet` stdout is exactly one line and every diagnostic stays on stderr.

## L3: ARCHITECTURE DECISION RECORD

### ADR-001: `--quiet` shortens the text report and leaves `--json` alone

**Status**: Proposed

**Context**: Two caller classes exist: humans reading the report, and scripts that want one value or a structured document. `--json` already serves the structured case. A `--quiet` that also changed JSON would make one flag alter two contracts, and a `--quiet` that printed a bare `3` would force every parser to learn a second format for the same fact.

**Decision**: `--quiet` changes only the default text path. It prints the identical `Recommended Level: <N> (<Name>)` line the report prints, and nothing else. When `--quiet` and `--json` are both present, the JSON document is printed unchanged.

**Consequences**:
- One stable label for parsers, and one flag for the common "just the level" case.
- Quiet hides the score, confidence and phase detail — acceptable because the flag is opt-in and `--json` covers structured reads.

**Alternatives Rejected**:
- Bare-value output (`3`): rejected — a second format for the same fact invites drift between parsers.
- An environment variable instead of a flag: rejected — callers already pass flags (`--json`, `--loc`), and an environment variable would split the interface.
- A `-q` alias: rejected for this packet — the request names `--quiet`, and the alias can be added later without breaking anything.
