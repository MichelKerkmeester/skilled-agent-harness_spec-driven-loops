### Overview
The change touches one script and one test file. A `QUIET` global is set by a new `--quiet` case in the existing argument loop, a new `output_quiet()` function prints the level line, and the output dispatch chooses that renderer before the JSON and text branches. The proof is a line count: one line with `--quiet`, the same 17 lines without it, and a JSON document that still parses.

<!-- ANCHOR:architecture -->
## 3. ARCHITECTURE

### Pattern
Single-script branch - no new module, no new file.

### Key Components
- **Argument parser** (`while [[ $# -gt 0 ]]` loop, section 5): recognizes flags and sets globals. Gains one `--quiet` case.
- **Output functions** (section 4): `output_text()`, `output_json()`, and the new `output_quiet()`. All three read the same scored globals.
- **Output dispatch** (section 7): picks one renderer after scoring. Gains one branch, checked before the JSON branch.

### Data Flow
Arguments enter the parser, numeric inputs are validated, the four score components are summed, and `determine_level()` sets `RECOMMENDED_LEVEL` and `LEVEL_NAME`. Only then does the dispatch choose a renderer. `output_quiet()` reads those two globals and prints one line; it never touches the report sections, so it cannot reorder or duplicate them.

## L3: ARCHITECTURE DECISION RECORD

### ADR-001: `--quiet` wins over `--json`

**Status**: Accepted

**Context**: Two output selectors can now be passed together. The script needs one rule for that combination, and either rule is defensible: refuse the pair, or let one win.

**Decision**: `--quiet` takes precedence. When both flags are present the script prints the one text line and no JSON.

**Consequences**:
- A caller that appends `--quiet` to an existing command line still receives a level, which is the reason the flag exists.
- A JSON consumer that also passes `--quiet` receives text. Mitigation: the help text states the precedence, and AC-004 pins it.

**Alternatives Rejected**:
- Reject the pair with exit 1: adds a failure mode nobody asked for, and turns a harmless combination into a broken script run.
- Emit one-line JSON under `--quiet`: satisfies "one line" but not "the recommended-level line", and doubles the contract every caller must parse.

### ADR-002: Reuse the `Recommended Level:` label

**Status**: Accepted

**Context**: The quiet line could introduce a terse format such as `3` or `3 Full`, or reuse the label `output_text()` already prints.

**Decision**: Reuse `Recommended Level: <N> (<Name>)` verbatim, built from the same `RECOMMENDED_LEVEL` and `LEVEL_NAME` globals.

**Consequences**:
- One label exists in one shape, so a parser written for the report also reads the quiet line.
- The line is longer than a bare number. Accepted, because stability beats brevity for a value a script parses.

**Alternatives Rejected**:
- Print only the number: shortest, but loses the level name and diverges from the existing label.
- Print the JSON field: forces every caller to parse JSON for one value.
