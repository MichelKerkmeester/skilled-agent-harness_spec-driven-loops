<!-- ANCHOR:architecture -->
## 3. ARCHITECTURE

### Pattern

Single script, three output modes.

### Key Components
- **Argument parser (section 5)**: owns flag acceptance, sets `QUIET`, and is the only place a new flag is admitted.
- **`output_level_line()`**: new. The one producer of the `Recommended Level:` literal, called by both the text report and the quiet path.
- **`output_quiet()`**: new. Calls `output_level_line()` and returns, so it inherits the label rather than restating it.
- **`output_text()` / `output_json()`**: behavior unchanged. The text report swaps its inline echo for the shared call and prints the same bytes.
- **Conflict guard (section 7)**: rejects `--quiet` with `--json` after the parse loop, so flag order cannot change the answer.

### Data Flow

Arguments enter the `while`/`case` loop, which sets `QUIET` and the existing flags. `show_help` exits from inside the loop, so `--help` short-circuits every mode. After the loop, validation rejects a non-numeric or empty input. Scoring runs unchanged, `determine_level` sets `RECOMMENDED_LEVEL` and `LEVEL_NAME`, and the dispatch selects one mode in this order: conflict guard, quiet, JSON, text.

## L3: ARCHITECTURE DECISION RECORD

### ADR-001: The level line has one emitter, and quiet is a third output mode

**Status**: Proposed

**Context**: The level literal appears once today, at `recommend-level.sh:510`, inside `output_text()`. A quiet mode that echoes the same string a second time would create two producers of a contract that callers parse. A quiet mode that filters the text report instead, by suppressing echoes, would couple the flag to the layout of the report and break whenever a line is added.

**Decision**: Extract `output_level_line()`, have `output_text()` call it in place of its inline echo, and have `output_quiet()` call the same function. `--quiet` becomes a third output mode selected in the dispatch, not a filter applied to the first one.

**Consequences**:
- The label has one producer, so the quiet line and the report line cannot drift.
- The text report gains one function call and prints the same bytes, which the baseline diff proves.
- One more function to name and place; it sits in section 4 beside the other output functions.

**Alternatives Rejected**:
- Filter the text report with `grep` or `sed` inside the script: the filter would encode the report's layout, and the phase block already makes that layout conditional.
- Duplicate the echo in a new function: two producers of a parsed contract, and the duplication is exactly the risk R-001 names.

---

### ADR-002: `--quiet` with `--json` is a usage error

**Status**: Proposed

**Context**: The script already has two machine-readable modes. `--quiet` and `--json` each claim stdout, and a caller that passes both has made a mistake that a precedence rule would hide.

**Decision**: After the parse loop, reject the combination with exit 1, a stderr message naming both flags, and an empty stdout. Check it after the loop rather than inside it, so the answer does not depend on flag order.

**Consequences**:
- A caller cannot silently receive the wrong shape, and the failure is immediate and legible.
- The existing `--json` callers are unaffected, because neither passes `--quiet`.
- The guard is one more branch, and it must sit ahead of the quiet branch in the dispatch.

**Alternatives Rejected**:
- Last flag wins: order-dependent behavior that is invisible in the command line a caller writes.
- Quiet wins over JSON: a caller that asked for an object would get a string, and its parser would fail somewhere else with no clue why.
- JSON wins over quiet: the flag would appear to be accepted while doing nothing, which is worse than an error.
