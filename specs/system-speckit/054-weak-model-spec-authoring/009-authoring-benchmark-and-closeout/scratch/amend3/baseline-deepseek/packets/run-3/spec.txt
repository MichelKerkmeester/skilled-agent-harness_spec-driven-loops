# Feature Specification: Add a quiet flag to recommend-level.sh

<!-- SPECKIT_LEVEL: 3 -->


---

## EXECUTIVE SUMMARY

`recommend-level.sh` decides which documentation level a task needs, then prints a sixteen-line report to say so. Any caller that only needs the level has to slice that report with `head`, `grep` or `sed`, and the slice is tied to a layout the script never promised. This packet adds `--quiet`, which prints only the recommended-level line and leaves every existing invocation byte-identical.

**Key Decisions**: `--quiet` is a text-output modifier rather than a fourth report; `--json` takes precedence when both flags are passed; the level line comes from one shared helper so the quiet and default paths cannot drift apart.

**Critical Dependencies**: Bash 3.2 compatibility, because macOS ships 3.2 as `/bin/bash`, and the existing vitest CLI project that holds the script's tests.

<!-- ANCHOR:problem -->
## 2. PROBLEM & PURPOSE

### Problem Statement
`recommend-level.sh` answers one question, which documentation level a task needs, but prints a sixteen-line report to answer it. A caller that needs only the level must slice stdout with `head -1`, `grep '^Recommended Level:'` or `sed`, and every slice depends on a layout no interface promises; for `--loc 50 --files 2` the report is sixteen lines. The script rejects `--quiet` today with `ERROR: Unknown option: --quiet` and exit 1, so slicing is the only option available.

### Purpose
One flag, one line: `--quiet` prints only `Recommended Level: <N> (<Name>)`, so a caller reads the answer without parsing the report, while every invocation that does not pass the flag keeps its exact current output.
<!-- /ANCHOR:problem -->

<!-- ANCHOR:scope -->
## 3. SCOPE

### In Scope
- Accept `--quiet` in the option parser and record it in a `QUIET_OUTPUT` global.
- Add a quiet output path that prints exactly the recommended-level line.
- Document `--quiet` in the file header OPTIONS block and in `--help`, with an example.
- Add a regression test covering the quiet line, unchanged default output, JSON precedence and the error paths.

### Out of Scope
- Scoring, thresholds, confidence and phase logic - the flag changes presentation only, and those functions are not edited.
- The JSON document shape - `--json` keeps its current output, including when `--quiet` is also passed.
- A `-q` short alias - the request names `--quiet`, sibling scripts use `-q`, and adding one is a separate interface decision.
- Callers and documentation outside the script - no caller needs a change because default output is unchanged.
- Commit, push or branch operations - those stay with the operator.

## 4. REQUIREMENTS

| ID | Requirement |
|----|-------------|
| REQ-001 | The parser accepts `--quiet` and sets quiet mode instead of reporting an unknown option. |

- **SC-003**: `recommend-level.sh --help` contains the `--quiet` option and an example that uses it.

## 6. RISKS & DEPENDENCIES

| Type | Item | Impact | Mitigation |
|------|------|--------|------------|
| Dependency | Bash 3.2 (`/bin/bash` on macOS) | A bash 4-only construct would break the default shell on the operator's machine | Use 3.2-compatible syntax only; run `bash -n` and the suite on macOS |
| Dependency | vitest CLI project | Without it the regression has no home and the change ships unverified | Add the test beside the existing CLI script tests |
| Risk | The quiet and default paths drift apart | High: the two lines would disagree after a later edit | Both paths call one shared line-formatting helper |
| Risk | `--json --quiet` is ambiguous | Medium: a caller could receive a different document than it parses today | Decide that JSON wins, state it in help, and test it |

## 7. NON-FUNCTIONAL REQUIREMENTS

### Performance
- **NFR-P01**: The quiet path adds no measurable work; one invocation completes well under 100 ms on the reference machine.

### Security
- **NFR-S01**: The flag adds no input, file or network access, so the script's attack surface is unchanged.

### Reliability
- **NFR-R01**: Exit codes stay as they are - 0 for success, 1 for a usage or validation error - and `set -euo pipefail` stays in force.

---

## 8. EDGE CASES

### Data Boundaries
- Empty input: `--loc 0 --files 0` keeps its `At least --loc or --files must be provided` error and exit 1, with or without `--quiet`.
- Maximum length: no new input is accepted, and numeric handling is untouched, so no new boundary exists.

### Error Scenarios
- Missing or invalid value: `--quiet --loc` still prints `ERROR: --loc requires a numeric value` on stderr and exits 1.
- Unknown option: unaffected; `--quiet` no longer reaches that branch.
- `--help` with `--quiet`: help wins and exits 0 before any output mode runs.
- `--json` with `--quiet`: JSON wins, and the document is byte-identical to a plain `--json` run.
- Repeated `--quiet`: idempotent; the flag sets the same boolean twice.
