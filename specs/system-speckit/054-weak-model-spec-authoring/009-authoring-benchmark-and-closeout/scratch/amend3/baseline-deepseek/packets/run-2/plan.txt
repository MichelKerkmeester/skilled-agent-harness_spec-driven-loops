<!-- ANCHOR:architecture -->
## 3. ARCHITECTURE

### Pattern

Single-file bash CLI with a linear pipeline: parse arguments into globals, calculate scores, determine the level, then dispatch to one output formatter.

### Key Components

- **Argument parser**: the `while [[ $# -gt 0 ]]` loop in section 5 of the script; owns flag acceptance and validation.
- **Scoring functions**: `calculate_loc_score`, `calculate_files_score`, `calculate_risk_score`, `calculate_complexity_score`, and `determine_level`; unchanged.
- **Output dispatch**: the final `if` in section 7 that selects JSON or text; gains the quiet branch.
- **`output_quiet`**: new function in section 4 that prints the single recommended-level line.
- **`output_text` and `output_json`**: existing formatters; unchanged.

### Data Flow

`argv` → parser sets `LOC`, `FILES`, risk flags, `JSON_OUTPUT`, and the new `QUIET` → scoring functions fill `TOTAL_SCORE` → `determine_level` sets `RECOMMENDED_LEVEL` and `LEVEL_NAME` → `calculate_confidence` and `determine_phasing` run as today → dispatch chooses `output_json`, `output_quiet`, or `output_text`.

The dispatch is exclusive and ordered: JSON first, quiet text second, default text last. Quiet mode never modifies scores or reaches the JSON path.

## L3: ARCHITECTURE DECISION RECORD

### ADR-001: JSON output takes precedence over quiet text

**Status**: Accepted

**Context**: `--json` and `--quiet` are both output modifiers. A caller could pass both, and the script must choose one shape. Printing a text line alongside JSON would break every JSON consumer, while ignoring quiet in JSON mode keeps the machine contract intact.

**Decision**: When `JSON_OUTPUT` is true, emit the unchanged JSON object and ignore `--quiet`. Quiet applies only to text mode.

**Consequences**:
- JSON consumers cannot receive mixed output.
- A caller that passes both flags gets the more structured format.
- The behavior is explicit and testable, with no error path added for the combination.

**Alternatives Rejected**:
- **Reject the combination with exit 1**: adds a new failure mode for an otherwise harmless pair.
- **Quiet wins over JSON**: breaks the documented machine-readable contract.
- **Embed the quiet line inside JSON**: changes the schema and every consumer.

---

### ADR-002: Add a dedicated quiet formatter instead of changing output_text

**Status**: Accepted

**Context**: `output_text` owns the leading blank line and the full report. Adding an early return inside it would keep one formatter but would place quiet behavior in the middle of the report code and risk changing the default path.

**Decision**: Add a small `output_quiet` function and select it in the final dispatch. Leave `output_text` and `output_json` untouched.

**Consequences**:
- The default report cannot change as a side effect of the quiet work.
- The recommended-level format appears in two places, so the focused test asserts that both lines are identical.
- The diff stays small and reviewable.

**Alternatives Rejected**:
- **Early return in `output_text`**: couples quiet to the verbose formatter and makes regression review harder.
- **Refactor both formatters onto a shared helper**: wider diff for no user-visible gain in this packet.
