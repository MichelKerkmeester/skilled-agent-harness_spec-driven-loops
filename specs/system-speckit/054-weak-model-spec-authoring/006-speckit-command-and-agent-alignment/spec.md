# Feature Specification: Phase 6: speckit-command-and-agent-alignment

<!-- SPECKIT_LEVEL: 3 -->


---

## EXECUTIVE SUMMARY

Phases 2 to 5 change the templates, the placeholder gate and the authoring guidance. Every speckit command and every agent that writes or checks spec docs still describes the old rules, so a weak writer follows stale text even after the templates improve. This phase audits the whole command and agent surface against six checks, applies 27 exact text rows by script, and regenerates every runtime mirror from the corrected sources.

**Key Decisions**: the audit is done at authoring time and frozen as a row file, so the executor applies text and never judges it. Mirrors are regenerated by their generators and never edited by hand.

**Critical Dependencies**: the authoring card and the two guard scripts from phases 4 and 5, plus the launch preconditions in `../spec.md` section 3.

## 2. PROBLEM & PURPOSE

### Problem Statement
A speckit command tells a writer where to find authoring guidance, how a placeholder is treated and which files a packet holds. Six of those statements are now wrong or incomplete, and the same wrong text is copied into seven runtime trees. A weak model reads the command, follows the stale line and produces the defect that phases 2 to 5 just fixed in the templates.

### Purpose
One corrected command and agent surface, with every runtime mirror regenerated from it, so a writer sees the same rule no matter which command or runtime it uses.

## 7. NON-FUNCTIONAL REQUIREMENTS

### Performance
- **NFR-P01**: The 27 rows are applied by script in one pass, with no model call. The only model call in the phase is the single read-only frontier review.

### Security
- **NFR-S01**: No brief, row or scratch file carries a credential, token or key. The review runs with a read-only sandbox.

### Reliability
- **NFR-R01**: A second apply of any row fails, because the locator is gone. A rerun therefore cannot edit a file twice.

---

## 8. EDGE CASES

### Data Boundaries
- Empty input: a row whose `locator` count is 0 is recorded as `SKIP-GONE` and the phase continues, because an earlier phase may have fixed the same line.
- Maximum length: a row whose `expected_text` holds more than one line is applied as one replacement, and the JSONL encoder writes the line breaks as `\n`.

### Error Scenarios
- External service failure: the frontier review is the only external call. A provider error is recorded with its stderr, and REQ-008 stays open.
- Network timeout: the review is retried once, then recorded as skipped.
- Pre-check failure: a row whose pre-check command exits non-zero is recorded as `SKIP-MISSING` and is not applied.
