### Overview
The audit is already done. Twenty-one stale statements were found in 12 authored files, and six MIRROR rows carry the same body text into four Claude agent siblings. The rows are frozen in `tasks.md` T004. A script applies each one and refuses unless the old text occurs exactly once. The runtime mirror generators then rebuild every generated tree from the corrected sources, and eight read-only checks prove the trees agree.

## 3. ARCHITECTURE

### Pattern
A frozen audit applied by a deterministic script, then a generated-mirror rebuild. No model reads or edits a row.

### Key Components
- **`scratch/audit/rows.jsonl`**: the 27 rows written in `tasks.md` T004.
- **`scratch/tools/apply_row.py`**: the phase 2 exact-match applier, copied in `tasks.md` T005.
- **`scratch/tools/lib.sh`**: the `apply_checked` helper from phase 2, copied in `tasks.md` T005.
- **Conductor**: runs every command, reads every output and edits only this phase folder plus the row files.
- **Reviewer**: one read-only `cli-codex` review at phase close. It writes nothing.

### Row schema (frozen)

One JSON object per line. The applier reads four fields. The other two are for the audit trail and are ignored by the applier.

| Field | Meaning |
|-------|---------|
| `id` | `R-001` to `R-027` |
| `file` | Repository-relative path of the file to change |
| `locator` | The exact current text, which occurs exactly once in `file` |
| `expected_text` | The exact replacement text |
| `check` | `A1` to `A6` |
| `precheck` | A read-only command that proves a phase 2 to 5 artifact exists, or an empty string |

### The applier

`scratch/tools/apply_row.py` is the phase 2 script with one added refusal, written in `tasks.md` T005. It reads a ledger path, a row id and an optional root. It refuses a row whose `expected_text` is `OWNED BY PHASE` or `DELETE FILE`. It refuses when the expected text is already in the file, so an append-style row cannot apply twice. It refuses unless the `locator` occurs exactly once. It replaces that one occurrence and prints `APPLIED <id> <file>`. Every refusal prints `FAIL <id>: <reason>` and exits 1.

`scratch/tools/lib.sh` adds `apply_checked`, which prints the applier result and a `CHECK <id> extra_paths=<n>` line. `extra_paths` counts changed paths the row does not name. It must be 0 for every row.

## L3: ARCHITECTURE DECISION RECORD

### ADR-001: Freeze the audit as exact rows and apply it by script

**Status**: Accepted

**Context**: The audit found 21 stale statements in 12 files. A weak model asked to fix them from a description may reword the new text, change a neighbouring line or skip one. The same text must land in four Claude agent bodies without a second judgment.

**Decision**: Every change is frozen at authoring time as a row with a locator and an exact replacement. `apply_row.py` makes every change and refuses unless the locator occurs exactly once. No model edits a file in this phase.

**Consequences**:
- The 27 rows cost no model call, and each one is checked by its own counts.
- A second apply fails, so a retry can never edit twice.
- A row whose text drifted is skipped and recorded, not guessed.

**Alternatives Rejected**:
- A worker reads each file and edits the prose: it can paraphrase, and the audit would then differ from the text this packet reviewed.
- `sed -i` one-liners: the quoting of backticks, pipes and quotes in these lines is the exact place a weak model slips, and `sed` replaces every match without a count check.

### ADR-002: Edit the authored Claude sibling by row, then regenerate the generated trees

**Status**: Accepted

**Context**: `.claude/agents` is an authored tree in the Claude dialect, not a generated one. `.codex` and `.pi` are generated from `.skilled/agents`. Editing `.skilled/agents` alone leaves the Claude body behind, and `check-agent-mirror-sync.cjs` reports drift.

**Decision**: Six MIRROR rows apply the same body text to `.claude/agents`. The `.codex` and `.pi` trees are rebuilt by their generators. No one hand-edits `.codex`, `.pi`, `.cursor` or `.devin`.

**Consequences**:
- The agent mirror check passes on the corrected tree.
- The Claude sibling stays an authored file, so a future agent change must repeat this two-step shape.

**Alternatives Rejected**:
- Hand-edit `.codex/agents/*.toml` and `.pi/agents/*.md`: the next generator run reverts them, and the hand edit hides the drift until then.
- Skip the Claude sibling: `check-agent-mirror-sync.cjs --all` fails and the phase cannot close.

### ADR-003: Compare the suite and the trigger index with the phase start, not with phase 1

**Status**: Accepted

**Approval**: Approved by the orchestrator on 2026-10-23, because phases 002 to 005 add tests and the phase start is the correct comparison point.

**Context**: Phase 001 records `suite-start.txt` before any template changes. Phases 2 to 5 add tests, so a literal match with phase 1 would block on tests this phase did not write. The trigger index is already stale at the phase start for reasons outside this phase, so a freshness gate would block on a pre-existing condition.

**Decision**: The suite gate compares the `Test Files`, `Tests` and `exit=` lines at the phase start with the same lines at close. The trigger-index gate compares the staleness set before and after. Both record the cumulative difference against phase 1 as information, not as a pass condition.

**Consequences**:
- A regression this phase introduces is caught.
- A known difference from an earlier phase is reported, not mistaken for a defect.
- The conductor cannot claim a clean phase-1 match, and the plan says so.

**Alternatives Rejected**:
- Require an exact phase-1 match: it fails on the tests phases 2 to 5 added, and a weak executor would then try to delete them.
- Require `fresh: true` from the trigger index: the index is stale before the phase starts, so the gate would be red on arrival.
