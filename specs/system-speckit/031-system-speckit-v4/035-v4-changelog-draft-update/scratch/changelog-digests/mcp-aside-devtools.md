### v1.0.0.0

`changelog/v1.0.0.0.md` is the first release, dated 2026-07-16. It delivered the Aside AI browser as a workflow packet with three lanes behind one router: weighted TASK, REPL, MCP, INSTALL and TROUBLESHOOT intents routing across `aside "<task>"`, `aside --session <id> "<task>"`, `aside repl "<code>"` and the Aside MCP `repl` tool through Code Mode, with the CLI as the primary operator surface and MCP as the composition fallback. It documented the registered stdio manual that launches `aside mcp` with an intentionally empty `env`, preserved a byte-true snapshot at `assets/utcp-aside-manual.md`, and treated manual absence as a diagnostic error. A dated discovery fixture recorded the single registry tool as `aside.aside.repl` and the TypeScript callable as `aside.aside_repl(args)`, with per-session rediscovery still required. References covered task starts and continuation, account selection and status commands, `aside mcp`, `aside repl`, a three-layer session model, permission and concurrency rules, and the discovered REPL helpers for tabs, snapshots, display, pages, screenshots, PDF, filesystem utilities, sleep and authenticated fetch, requiring `console.log` for returned values and a single-writer posture while multi-client isolation stayed unresolved. Six feature leaves and six matching playbook scenarios mapped the discovered Playwright `page` API onto Chrome DevTools jobs: DOM inspection, screenshots and PDF, console and network event capture, cookies and storage, performance timing, and navigation with multiple tabs, with bound-session executions left SKIP-valid until an authorized browser session could verify them. The package shipped an 18-capability feature catalog, a 21-scenario manual testing playbook with routing-recall holdouts and recovery cases, three example workflow scripts, a macOS installer wrapper, a read-only doctor with an MCP handshake probe, and CLI/MCP server-package pointers. The release also conformed the whole package to the create-skill and create-readme contracts with kebab-case filesystem names and resolved links. Being a first release there is nothing renamed, removed or moved relative to a predecessor.

## Facts the v4 draft gets wrong or misses

The draft mentions this mode on exactly one line, line 387 of `CHANGELOG-v4.0.0.0.md`.

- Line 387 describes the mode as a bridge that "drives the agentic `aside` browser from its command line, with a server fallback for when the CLI is not enough". That is accurate as far as it goes but it collapses three lanes into two. Per `changelog/v1.0.0.0.md` the CLI surface itself splits into a natural-language agent-task lane and a separate deterministic Playwright-compatible JavaScript REPL lane (`aside repl`), and the REPL lane is the one that exists specifically to keep repeatable evidence work out of the nondeterministic task lane. The draft loses the distinction that motivates the packet.
- Line 387 omits the Chrome DevTools parity family entirely. `changelog/v1.0.0.0.md` documents six feature leaves and six matching playbook scenarios covering DOM inspection, screenshots and PDF, console and network capture, cookies and storage, performance timing, and multi-tab navigation. This is the reason the mode is named `mcp-aside-devtools` rather than `mcp-aside`, and the draft never explains the name.
- The draft omits the mode's stated non-capabilities. `changelog/v1.0.0.0.md` is explicit that the packet does not claim native HAR export, Lighthouse audits, raw-CDP passthrough, dedicated console or network tools, or parallel isolated browser instances, and that bound-session behavior is SKIP-valid rather than verified. A release note that only names the capability overstates it relative to the source entry.
- The draft omits the operator-facing surface described in `changelog/v1.0.0.0.md`: the macOS installer wrapper, the read-only doctor with an MCP handshake probe, the 18-capability feature catalog and the 21-scenario testing playbook. The neighboring paragraph at line 376 credits the hub generally with "feature catalogs, install front doors and worked examples", so this may be intentional compression rather than an error.
- The draft carries nothing from `changelog/v1.1.0.0.md`. That release is documentation-only (a README rewrite), so its absence from a user-facing release note is defensible, but the digest records it here so the omission is a decision rather than an oversight.
- Version-identity mismatch worth surfacing, verified in the entries and the file itself: `changelog/v1.1.0.0.md` states under NOT CHANGED that `SKILL.md` stays at `1.0.0.0` while `README.md` moves to `1.1.0.0`. The mode therefore has two live version numbers depending on which file you read. The draft does not cite a version for this mode, so it is not wrong, but any statement of "current version" needs to say which file it means.
