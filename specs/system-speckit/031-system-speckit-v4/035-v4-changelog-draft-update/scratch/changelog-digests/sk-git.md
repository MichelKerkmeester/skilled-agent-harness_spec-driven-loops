## Per version, newest first

### 1.5.2.0 (2026-08-21) — `v1.5.2.0.md`

The worktree base directory became configurable so worktrees can live outside the primary checkout, which was costing sustained CPU because everything scanning from the repo root walked every worktree's `node_modules`. `worktree-naming.sh` resolves a base through `_wn_base_dir` with precedence env `SPECKIT_WORKTREE_BASE`, then git config `speckit.worktreeBase`, then the default `.worktrees` under the main toplevel. `create` and `create-detached` now emit an absolute directory path. `is_valid_pair` accepts a directory under either the configured base or the legacy `.worktrees` parent so pre-relocation and post-relocation worktrees both validate. The launch wrapper and the reaper resolve the same base, and the reaper's orphan detection canonicalizes each candidate path's parent instead of matching a fixed `.worktrees/` string, which also removes `/var` versus `/private/var` symlink skew. The default is unchanged, so a clone that sets nothing behaves exactly as before. This entry states the current branch grammar as `worktrees/NNN-slug` and `branches/NNN-slug`.

### 1.5.1.0 (2026-08-20) — `v1.5.1.0.md`

A data-loss path in the live-sync reconcilers was closed. When a stale or foreign rebase state directory was present, a blanket `git rebase --abort` reset the branch to that foreign rebase's orig-head, and the fast-forward-only follower then advanced the now-behind branch, so a just-made commit vanished locally while surviving on the remote. `git-primary-reconcile.sh` and `git-sync.sh` now check for an existing `rebase-merge` or `rebase-apply` state directory before rebasing and record a block rather than touching a rebase they did not start. Each also captures its pre-rebase SHA and force-restores HEAD with `git reset --hard` when its own abort lands elsewhere. Previously `git-primary-reconcile.sh` only warned about the drift and `git-sync.sh` logged the rewind as `aborted cleanly`. `git-live-follow.sh` is unchanged and was the collateral advance, never the destructive actor. Disable flags are unchanged.

### 1.5.0.0 (2026-08-15) — `v1.5.0.0.md`

The git safety layer was made loud and a SessionStart reconcile was added. Every pre-push and commit gate now emits a stable `[gate:<name>]` marker naming itself and the exact fix command when it blocks, covering the naming, remote-permission, mass-deletion, skill-root-metadata and test-suite gates, and a broken optional validator no longer exits past the independent gates after it. `git-sync.sh` classifies a blocked autosync push, replays the diagnostics, prints a loud `AUTOSYNC BLOCKED` line and appends a `blocked gate=<name> fix=<command>` record to the common-dir log. New `git-primary-reconcile.sh` keeps the primary checkout current on its live branch, acting only in the main checkout, only on the resolved live branch and only when tracked files are clean, fast-forwarding when behind and rebase-publishing when ahead. It never touches uncommitted work and every internal failure is non-fatal. New `relink-local-specs.sh` recreates the gitignored symlinks for machine-local spec folders and refuses to invent a link when the target is missing. REMOVED the follower daemon as the wired mechanism: this entry states the SessionStart reconcile "replaces the follower daemon that was never auto-started with a reliably wired step", and wires the reconcile into SessionStart for Claude, Codex, OpenCode and Pi. New defaults arrive with it: the reconcile and autosync loop is on by default in the main checkout, disabled wholly with `SYSTEM_LIVE_SYNC_DISABLED=1`, its reconcile leg with `SYSTEM_PRIMARY_RECONCILE_DISABLED=1` and its publish leg with `SPECKIT_AUTOSYNC=0`.

### 1.3.1.0 (2026-07-14) — `v1.3.1.0.md`

Safety hardening of the owner-first worktree tooling after an adversarial review reproduced defects the original harnesses had missed, with no public interface change. The `worktree-naming.sh` lock became genuinely serial under stale-lock contention: reclaim now uses an atomic rename-steal so N concurrent allocations always yield N distinct monotonically increasing numbers, a high-water persistence failure aborts allocation without emitting a number, and validators enforce the documented `0001..9999` bound and the exact `.worktrees/<pair>` path. `worktree-reaper.sh` stopped trusting a malformed marker or a mis-shaped branch: the whole marker file must match a PID grammar, a `work/*` branch is reaped only as an exact `work/<runtime>/<slug>` triple matching the directory basename, and `--reap-daemons` signals only when the referenced path is actually gone and the PID identity still matches. `worktree-session.sh` refuses a runtime identity that cannot form a legal Git ref, stops leaking the diagnostic reason into the runtime argv, and rejects any `SPECKIT_WORKTREE_SHARED_PATHS` entry with `..` or absolute components with containment checks on both ends. The `pre-push` naming validator became tri-state: a genuine invalid name blocks, an internal validator error fails open, and the authorized-owner set derives only from version-controlled `SKILL.md` files so an untracked skill cannot authorize a remote owner. Every reproduced defect became a permanent regression case.

### 1.2.0.0 (2026-07-14) — `v1.2.0.0.md`

BREAKING: the flat `wt/{NNNN}-{name}` worktree and branch namespace was replaced by an owner-first grammar, `{OWNER}/{NNNN}-{slug}` with a matching `.worktrees/{NNNN}-{OWNER}-{slug}` directory, where `{OWNER}` is a canonical skill id taken from the `name:` frontmatter of an `.opencode/skills/**/SKILL.md` or the literal `skilled` for cross-cutting, system and release work. Legacy `wt/{NNNN}-{name}` branches became permitted but non-conformant, to be migrated by renaming and never by rewriting history. `main`, `skilled/vA.B.C.D` release branches and the launch wrapper's `work/{runtime}/{slug}` lane sit outside the task-branch grammar. A new sourceable script and CLI, `.opencode/skills/sk-git/scripts/worktree-naming.sh`, replaced hand-computed counters with a locked clone-wide allocator seeding its max from the stored high-water mark, every registered worktree basename and all local and remote refs. `worktree-session.sh` gained runtime-token validation and an active-session pid marker written outside the worktree, and `worktree-reaper.sh` retargeted onto the primary checkout's actual `HEAD` and restricted auto-reap to the launch-wrapper lane with clean tree, merged branch and a marker proving the pid is dead, everything else being report-only. Cleanup order became worktree-remove before branch-delete and no call passes `--force`. Enforcement moved to a migration-tolerant pre-push hook gating only brand-new remote branches, never blocking existing non-conformant branches or `skilled/v*`.

### 1.1.3.0 (2026-07-10) — `v1.1.3.0.md`

The GitKraken MCP server (`gitkraken/mcp`, `@gitkraken/gk`, stdio) was added as a second remote-collaboration transport alongside GitHub MCP, reaching GitHub, GitLab, Azure DevOps, Bitbucket and Jira from one tool plus the GitLens AI workflows for commit composer, launchpad triage, PR review and work-start. A new `references/gitkraken-mcp-integration.md` documents the full tool surface captured live from `gk mcp --list-tools` against an authenticated install rather than the upstream README, which listed 3 example tools against a real 31. A new `GITKRAKEN_MCP` intent entered the router pseudocode with `gitkraken` and `gitlens` keyword triggers. A new ALWAYS rule #12 carved local mutations out: GitKraken MCP exposes `git_add_or_commit`, `git_push`, `git_branch`, `git_checkout`, `git_worktree` and `git_stash`, which duplicate mutations the skill already gates, so those must go through the existing Bash workflow and GitKraken MCP is reserved for GitLens AI workflows and cross-platform issue, PR and repository work. The former rule #12 on operator direct-push authorization renumbered to #13.

### 1.1.2.1 (2026-06-06) — `v1.1.2.1.md`

The GitHub release-notes H1 contract was encoded.
