The two v2-rollout gates, `candidateCoverageGate` and `graphlessFallbackGate`, were the ones most often missing, and one table also omitted `claimAdjudicationGate`. `convergence.md`, `loop_protocol.md`, `state_format.md`, the `04--severity-system/quality-gates.md` catalog entry and the DRV-018 playbook scenario were each brought to the same nine names, and a stale `convergence.md` Section 10.4 anchor was corrected to §6. The reducer is gate-name-agnostic and unchanged, and the YAMLs were read-only.

### v1.8.0.0

`v1.8.0.0.md` lands four teachings from the upstream `dzianisv/opencode-plugins` auto-review package, all as prompt and dispatcher-config changes with zero source-code files touched. Every iteration must now end with a plain-text final line reading `Review verdict: PASS`, `Review verdict: CONDITIONAL` or `Review verdict: FAIL`, with a fixed mapping where PASS means no P0 and no P1, CONDITIONAL means at least one P1 and no P0, and FAIL means any P0. A new `step_derive_verdict` step re-derives the verdict from the actual counts so a misreported line is corrected before synthesis. A `DEEP-REVIEW` marker was placed on line 1 of `prompt_pack_iteration.md.tmpl` with a `step_marker_scan` that fails fast when it is missing after rendering. The CONSTRAINTS section of SKILL.md now forbids restating a finding already reported in a prior iteration of the same review. The existing synthesis dedup key was extended with `content_hash = sha256(file_path + line_range + finding_type + normalized_description_80chars)`, matching primary on the hash and falling back to the legacy file plus line plus normalized title, so cross-dimension restatements collapse into one entry carrying a `dimensions:` list. The fifth teaching, H-9 bounded evidence, was deferred because the current prompts pass state and metadata pointers rather than embedded file contents, so there is no interpolation path to harden. All mechanisms cleared a 5-of-5 deep-ai-council review before shipping.

### v1.7.0.0

`v1.7.0.0.md` mirrors the `deep-research` v1.10.0.0 hardening pass. Both review YAMLs now run `writeFirstRecordExecutor` before the dispatch branch on every non-native kind, so executor identity is written on the first JSONL record and missing provenance fails fast during post-dispatch validation. A new `dispatch_failure` event preserves executor attribution across crashes and timeouts where no valid iteration record exists. The `if_cli_copilot` branch gained a 16 KB size check that switches to a `Read the instructions in @<path>` wrapper prompt above the threshold, using `review/prompts/` paths. A `description.json` repair helper is packet-agnostic so review packets benefit from it too. The readiness contract in SKILL.md was narrowed to the four trust-state values the seven code-graph handlers actually emit, `live`, `stale`, `absent` and `unavailable`, marking `cached`, `imported`, `rebuilt` and `rehomed` as compatibility vocabulary only. Shared tests went from 54 to 116 with no review-specific TypeScript added.

### v1.6.0.0

`v1.6.0.0.md` wires the two executor kinds that v1.5.0.0 had reserved but rejected at config load. Setting `kind: cli-copilot` dispatches through `copilot -p "PROMPT" --model X --allow-all-tools --no-ask-user` with a positional prompt because copilot has no stdin, and `kind: cli-claude-code` dispatches through `claude -p "PROMPT" --model claude-opus-4-6 --permission-mode acceptEdits --output-format text` with optional `--effort`. The `acceptEdits` permission mode is required so claude-code can write the review narrative and append to the JSONL state log. Per-kind flag validation comes from the shared `executor-config.ts` map, so setting an unsupported flag such as `serviceTier` with `cli-copilot` is rejected at config parse. The Q-Exec question in `review.md` grew from two options to four. A Cross-CLI Delegation subsection documents that an executor may shell out to another CLI, that self-recursion is forbidden, and that auth propagation is user responsibility with no runtime enforcement. Users previously blocked by `ExecutorNotWiredError` on these two kinds can now run them. Shared tests went from 40 to 54.

### v1.5.0.0

`v1.5.0.0.md` introduces executor selection for review iterations, which previously hardcoded a native agent dispatch on Claude Opus. The iteration step now branches on `executor.kind`, with `native` as the default preserving prior behavior exactly and a new `cli-codex` branch running `codex exec` with the model and flags from config, piped through stdin. MOVED PATH: the review iteration context that lived inline inside the YAML was extracted into `assets/prompt-pack-iteration.md.tmpl`, which both dispatch paths render. A new `executor` block was added to `deep_review_config.json`, bit-identical to the research one. Five setup flags appeared in `review.md`, `--executor`, `--model`, `--reasoning-effort`, `--service-tier` and `--executor-timeout`, with precedence of CLI flag, then config file, then schema default. Non-native runs append an `executor: {kind, model, reasoningEffort, serviceTier}` block to the iteration's JSONL record as a new top-level field, leaving the review schema of dimensions, filesReviewed, findingsSummary and newFindingsRatio unchanged. Post-dispatch validation requires both a markdown narrative and a JSONL delta record, firing a canonical `schema_mismatch` conflict when either is missing, and three consecutive failures trigger the existing stuck-recovery path. The kinds `cli-copilot` and `cli-claude-code` are declared in the enum but throw `ExecutorNotWiredError` at config load. Ships as a symmetric pair with `deep-research` v1.8.0.0. Shared tests: 40.
