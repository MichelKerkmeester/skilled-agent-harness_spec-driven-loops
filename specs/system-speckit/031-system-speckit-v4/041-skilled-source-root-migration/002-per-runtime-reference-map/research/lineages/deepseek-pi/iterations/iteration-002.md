# Iteration 2: Map A — `.cursor`, `.devin`, `.hermes`, `.pi`

## Focus

Map A, sections `.cursor` (65 links), `.devin` (34), `.hermes` (2), `.pi` (19): per-link required targets with and without the `.opencode` compatibility link, generator ownership, classification, and reconciliation against the seed.

## Findings

- **Finding 1 — 24 Cursor/Devin agent mirrors do not point into `.opencode` at all, and need no change under either compatibility assumption.** All 12 `.cursor/agents/*.md` and all 12 `.devin/agents/*/AGENT.md` link to `.claude/agents/<name>.md`. `.claude/agents/` is the *real fork* (Map C row, not Map A); it stays where it is. **Classification:** `none` (reason: target is `.claude/agents`, which the move does not touch). **Consequence:** any retarget script keyed on "links that traverse `.opencode`" is already correct for these 24 rows; a blanket `sed .opencode -> .skilled` over symlinks would silently corrupt them. [SOURCE: .opencode/skills/system-spec-kit/runtime/cli/runtime-mirrors/sync-runtime-mirrors.cjs:36-38] [SOURCE: .cursor/SYNC.md:12-23]

- **Finding 2 — Cursor's 33 command mirrors and Cursor/Devin's 39 hook mirrors are generator-owned and need the same `.opencode` -> `.skilled` segment swap as the Claude/Codex families.** Without a compatibility link, each raw target's first `.opencode/` segment moves to `.skilled/` at unchanged relative depth (Cursor commands are one level flat: `../../.opencode/commands/x.md` -> `../../.skilled/commands/x.md`; Devin hooks are `../../.opencode/...` -> `../../.skilled/...`). With the compatibility link, every raw target is unchanged. **Classification:** `regenerate` (51 rows in `.cursor`, 21 in `.devin`). **Consequence:** the generator change from iteration 1 covers all five generated runtime trees at once; no runtime needs its own rewrite script.

- **Finding 3 — four hand-made whole-directory links carry whole runtime surfaces with one edit each.** `.hermes/agents -> ../.opencode/agents` (the authored agent source), `.pi/skills -> ../.opencode/skills`, plus four `manual-testing-playbook` links (`.cursor`, `.devin`, `.hermes`, `.pi`). Without the compatibility link each becomes `../.skilled/...` (or `../.skilled/skills/cli-external-orchestration/cli-<runtime>/manual-testing-playbook`). **Classification:** `mechanical` (one retarget per link; five links). **Consequence:** these are the cheapest rows in Map A and the highest-leverage — one `.pi/skills` retarget preserves 56 skill packets for Pi.

- **Finding 4 — `.pi`'s 17 extension links and `.cursor/rules/sk-vision.md` are hand-made bridges with no generator, so nothing rebuilds them.** `.pi/extensions/README.md` documents each `*.ts` entry as a relative symlink to the real file in its owner's tree and says Pi's loader resolves imports against the symlink path; `sync-hook-registrations.cjs` only *verifies* the links (`verifyPiExtensions`, L192-205) and never creates them. `.cursor/rules/sk-vision.md -> ../../.opencode/skills/sk-vision/hooks/cursor/vision-rule.md` has no creator in any `symlinkSync`/`ln -s` sweep. **Classification:** `mechanical` (retarget by hand or with a one-off script). **Consequence:** a missed `.pi/extensions` retarget silently disables 17 guard extensions, because Pi loads file paths, not registry entries.

- **Finding 5 — `.cursor/commands` holds 35 files but only 33 are mirrors.** The two native commands (`goal-cursor.md`, `vision.md`) are hand-authored and deliberately excluded from mirroring by `command-scope.cjs` (`isCanonicalMirrorExcluded`). **Classification:** `none` (native commands carry no `.opencode` target). **Consequence:** when the canonical command tree moves, the two native commands stay and their runtime-exclusive nature is unaffected.

- **Finding 6 — the seed's `resolves_into_opencode` column is the right filter for this phase, but it undercounts "affected".** In `.cursor`/`.devin`, 24 of 99 links are `no` on that column, yet `sync-runtime-mirrors.cjs` rematerializes all 51 command/hook links from configs that themselves embed `.opencode` (iteration 1, Finding 4). A runtime-manifest view that says "Cursor: 53 links into `.opencode`" is accurate for link objects and incomplete for the change surface. **Classification:** `manual` (change-surface accounting). **Consequence:** the move's checklist needs both the link-object count (53 Cursor, 22 Devin) and the generator/config count.

- **Finding 7 — three manifest-vs-tree disagreements in this set.** `.cursor/SYNC.md` says 13 agents (tree: 12), 36 commands (tree: 35 files, 33 mirrors), and 15 hooks (tree: 18 links). `.devin/SYNC.md` says 13 agents (tree: 12) and does not fix a hook count (tree: 21). `.claude/agents` also holds 12 files where its own manifest says 13. **Classification:** `manual` (manifests need a reconciliation pass). **Consequence:** the seed inventory remains authoritative; the manifests are breadcrumbs.

- **Finding 8 — `.hermes` has exactly two links, so its 69 generated skill folders, prompts, and plugins are Map B rows, not Map A rows.** Its `.hermes/skills/` is real generated markdown, deliberately not a symlink (the Hermes scanner would traverse the whole shared tree). **Classification:** `none` for the decision (documented and load-bearing), `regenerate` for the generated copies in Map B. **Consequence:** do not "fix" Hermes by replacing the copies with a `.skilled` symlink; that recreates the quarantine problem the copies exist to avoid.
