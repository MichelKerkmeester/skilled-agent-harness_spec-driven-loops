# Iteration 3: Hook Registration Parity and CI-to-Script Drift

## Focus

Compare hook registrations across `.claude`, `.codex`, `.cursor`, `.devin`,
`.pi`, and `opencode.json` against the adapters in `runtime/dist/hooks` and
`runtime/hooks`; check CI workflows against the commands/scripts they invoke.

## Findings

### F3-1 (Ruled out as false positive, but worth recording): `runtime/dist/hooks` has no `pi/` directory -- by design, not a gap

`runtime/dist/hooks/` contains compiled output for `claude/`, `codex/`,
`cursor/`, `devin/`, and `shared-provenance.*` only -- no `pi/`.
[SOURCE: file:.opencode/skills/system-spec-kit/runtime/dist/hooks (directory listing)]
This looked like a build gap (Pi hook sources exist at
`runtime/hooks/pi/*.ts`, 7 files) but `runtime/tsconfig.json` explicitly
excludes `hooks/pi/**` from compilation:
[SOURCE: file:.opencode/skills/system-spec-kit/runtime/tsconfig.json:48].
This is deliberate: Pi discovers these hooks through **symlinks** in
`.pi/extensions/*.ts` that point directly at the `.ts` sources (Pi's own
extension loader runs TypeScript directly, unlike Claude/Codex/Cursor/Devin
which shell out to compiled `.js`).
[SOURCE: file:.opencode/skills/system-spec-kit/runtime/hooks/pi/README.md:11]
All 17 `.pi/extensions/*.ts` symlinks (verified via `readlink` + `realpath`)
resolve to real files with no broken links. No fix needed -- ruled out.

### F3-2 (Low): Claude and Cursor hook registrations lack the self-diagnosing drift fallback that Codex and Devin have

Codex's and Devin's hook commands wrap each `node .../dist/hooks/.../*.js`
call in a shell fallback that emits a structured `mkHookDrift: true` JSON
payload (with a human-readable `additionalContext` remediation string) if the
compiled adapter fails to resolve:
[SOURCE: file:.codex/hooks.json:8] (`mk-hook-drift host=codex event=SessionStart adapter=session-start.js`),
[SOURCE: file:.devin/hooks.v1.json:8] (`mk devin hook could not resolve; run npm run build in the spec-kit runtime package`).
Grep for `mk-hook-drift|mkHookDrift` across each runtime's hook registration
file: Codex 17 hits, Devin 4 hits, **Claude 0 hits, Cursor 0 hits**
[SOURCE: file:.claude/settings.json (0 matches), file:.cursor/hooks.json (0 matches)].
Claude's and Cursor's `dist/hooks/*.js` invocations
(e.g. [SOURCE: file:.claude/settings.json:85] `node .../dist/hooks/claude/user-prompt-submit.js`,
[SOURCE: file:.cursor/hooks.json:6] `node .../dist/hooks/cursor/session-start.js`)
have no `||` fallback at all -- a stale/missing compiled artifact on those two
runtimes fails as a raw Node module-not-found error with no structured
signal, instead of surfacing through the same `mkHookDrift` recovery path
that the session-start-advisories tooling and doctor commands already know
how to report.

**Fix:** Apply the same `|| { printf ... mkHookDrift:true ... }` fallback
wrapper used in `.codex/hooks.json` / `.devin/hooks.v1.json` to the
`dist/hooks/claude/*.js` and `dist/hooks/cursor/*.js` invocations in
`.claude/settings.json` and `.cursor/hooks.json`, generated by whatever
script templated the Codex/Devin versions (check
`.opencode/bin/install-codex-hooks.mjs` and its Devin counterpart for a
shared template to extend rather than hand-writing four more copies).

### F3-3 (Verified clean): all 14 CI workflows invoke scripts that exist in the current tree

Extracted every `node`/`bash`/`python3` script path referenced across all 14
`.github/workflows/*.yml` files (excluding `README.md`) and verified each
with a direct existence check: `run-node-tests.mjs`,
`check-agent-mirror-sync.cjs`, `validate.sh`,
`validate-command-tree-parity.sh`, `check-comment-hygiene.sh`,
`check-markdown-links.cjs`, `validate-playbook-package.cjs`,
`check-prompt-quality-card-sync.sh`, `parent-skill-check.cjs`,
`compiled-route-guard.cjs`, `check-no-spec-imports.cjs`,
`check-skill-doc-frontmatter.sh`, `check_no_new_snake_case.py` (+2 test
files), `check-rule-copies.js`, and the inline `strict-pass-freshness.ts`
sweep via `node --import .../tsx/dist/loader.mjs`. All present. No CI-to-script
drift found in this sample.

### F3-4 (Informational/context): a live `codex-hooks drift` advisory fired in this very session

This session's own `SessionStart` hook reported: `[codex-hooks] drift
detected - run: node .opencode/bin/install-codex-hooks.mjs --check`. Running
that check directly returned: `install-codex-hooks: Refusing to anchor hooks
at linked worktree ... Primary checkout: .../Code_Environment/Public. Pass
--allow-worktree to override.`
[SOURCE: command output of `node .opencode/bin/install-codex-hooks.mjs --check` in this session, 2026-09-05].
This is expected, self-explaining behavior for a linked git worktree (the
installer intentionally refuses to anchor hooks away from the primary
checkout) rather than a real drift defect -- but it confirms the drift
detector and its remediation pointer are both live and functioning end to
end. No fix needed; noted for context since it is directly relevant to this
angle.
