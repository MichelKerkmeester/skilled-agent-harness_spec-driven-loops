# Deep Research Strategy - Session Tracking

## 1. OVERVIEW

This is a detached fan-out lineage. The executor is inline in the current session; no nested agent or CLI iteration dispatch is permitted. Reducer-owned sections are refreshed only by the workflow reducer invoked with a lineage-local artifact override.

- tracing names from package metadata and public entrypoints into callers exposed live paths that an old-path grep would miss. (iteration 2)

- comparing a package's declared `main` and root test commands with actual writer and detector imports separated a successor continuity path from a still-live database path. (iteration 12)

- tracing both source-selection branches and the validator's actual entry points exposed a seam that file-by-file documentation review would miss. (iteration 16)

## 8. WHAT FAILED
- using a PASS report as current-tree truth would have repeated two already-fixed P2s; the report is historical evidence, not a live inventory. (iteration 1)
- a single broad lexical sweep over all historical and fixture text produced too many preserved-owner false positives; explicit producer-consumer reads were required. (iteration 2)
- a filename-only session-hook scan undercounted the restored registration surface. (iteration 3)
- broad package-root searches pulled generated index and fixture text into the result set; source directories must be bounded explicitly. (iteration 4)
- treating every `memory-*` test name as obsolete would have conflated active compatibility code with decommission residue. (iteration 5)
- treating all uses of “memory” as retired would erase the documented continuity successor and overstate the defect. (iteration 6)
- a missing source filename alone cannot prove runtime behavior is absent when generated output or an external package may be involved, so the content-router result is split into confirmed reference gap and inferred impact. (iteration 7)
- the route and dispatch guards are intentionally fail-open and do not own completion status, so their behavior could not be promoted into a decommission finding without inventing a caller contract. (iteration 8)
- the historical command-reference debt was not reproducible from the current checker source, so it was ruled out rather than carried forward as a duplicate. (iteration 9)
- the bounded runtime source search did not expose a constructor, so actual database use could not be upgraded from inference. (iteration 10)
- build-output availability was intentionally not tested because `dist` is outside the allowed reading budget. (iteration 11)
- manifest-only dependency analysis could not distinguish intentional compatibility packages from dead dependencies, so sqlite-vec was deliberately not duplicated. (iteration 12)
- source-only inspection cannot determine whether a skipped contract has an equivalent test under a different name. (iteration 13)
- the source tree cannot establish the historical deletion reason, so the finding avoids claiming an accidental code removal. (iteration 14)
- the committed index and live ripgrep result set were intentionally not read/executed under the stated budget, so the report does not quantify the current number of polluted hits. (iteration 15)
- no runtime test was executed because this detached lineage is read/research-only and the requested write surface excludes repository tooling outputs. (iteration 16)
- direct validator execution was out of scope for this detached research run because the user prohibited validation tooling and external writes. (iteration 17)
- the normal reducer invocation could not consume the root state without a compatibility adapter, so no claim is made that an unmodified run would complete synthesis correctly. (iteration 18)
- running the detector on the full repository was intentionally skipped to avoid producing out-of-lineage report artifacts and broad excluded-file reads. (iteration 19)
- no new evidence crossed the threshold for a distinct finding in the final bounded pass. (iteration 20)
