<!-- ANCHOR:what-built -->
## What Was Built

The shared package lane's third round contradicted child 015: the README said its reader table was generated from the code, and no generator existed. The table had been written from a one-off scan, and its text-helpers row named the save pipeline and the hooks as consumers of two helpers only the embedding providers import. This child adds the generator: it scans every `process.env` read under the package, renders one row per variable with the files that read it, rewrites the README on request, and fails in check mode on any drift; a test runs the check under `npm test`, so the sentence is now true on every run.

### Exports that earn their place

`stringifyFrontmatter` and `escapeRegex` had no importer beyond their own tests across the skill, its neighbours, the advisor and the bin scripts; both are gone. The budget-allocator export entry stays: the runtime's test imports it through the package, which is a consumer of the public surface. The validator's own `ParsedFrontmatter` shared a name with the package's exported type while the orchestrator imports both modules; it is renamed for what it is. A comment in the tree-thinning module still described a re-export that a round-two fix removed.

### CI that does what its comments say

The parity workflow built the package for a checker that imports a checked-in source module; the build is gone and the comment says why. The mirror job in the spec-kit check ran three scripts that require the package with no install step, which no run had exposed because the job had never run on a push. It installs the workspace first now; that workflow file lands in child 019's commit, which also adds its push trigger. The retry and chunking helpers gain shared-side tests, and the README's build note tells the two file-dependency consumers to build the package before their tests on a fresh checkout.

## How It Was Delivered

Every row was re-read in the main checkout first; the generator was written before the README changed, and the first run of its write mode found the old header, which is why the check mode reads the header it writes. Consumer searches preceded each removal, and the package was rebuilt from a clean dist before its suite ran. The commit was assembled in a private index.

<!-- ANCHOR:decisions -->
## Key Decisions

| Decision | Why |
|----------|-----|
| Write a real generator instead of rewording the claim | A README that says generated must be generated; the check mode and test keep it so |
| One row per variable | The grouped-union convention made a file appear to read a variable it does not; per-variable rows carry no such ambiguity |
| Keep the budget-allocator export entry | The runtime test imports it through the package; a test of the public surface is a consumer |
| Remove rather than relocate the two helpers | Zero importers; the two local regex escapes in the CLI stay local |
| Record the advisor rows | The advisor is another lane's surface |
