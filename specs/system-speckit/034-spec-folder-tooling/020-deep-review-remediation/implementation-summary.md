## What Was Built

The deep review of phases 016 to 019 returned CONDITIONAL with 0 P0, 9 P1 and 2 P2 findings after deduplication. Each finding has a fix in the working tree, a test or check that shows it, and an acceptance row. The rows and their evidence are in `acceptance-criteria.md`, and the lane tasks are in `tasks.md`.

### Lane A: archive.sh (REQ-001, R2-P1-003)

- A `z_archive` that is a symlink is refused on archive and on restore, before anything is created through it. The resolved archive root must stay under `specs`, and a link named as the archive folder is refused before it is resolved.
- A path with a `.` or `..` segment is refused in both `archive` and `restore`, because a segment can reach a linked `z_archive` that the literal path does not show.
- An existing target is refused when it is a dangling link as well as when it is a folder.

### Lane B: healer and shared target helper (REQ-002, REQ-003, R2-P1-001, R4-P2-001)

- `heal-spec-docs.cjs` refuses a symlinked packet document with `symbolic link, not followed` in its three entry paths: the anchor repair, the lane modes and the default `--apply` path. The default write is atomic now.
- The three entrypoints resolve `--folder`, `--roots` and the default root through one `resolveTargets` helper, and a parity test covers the selections.
- Four transform fixes ship with their cases: a fence inside a list item is recognized, an inline code span blanks its links, a continued continuity value is refused rather than orphaned, and a frontmatter closing line with trailing text is not read as the delimiter.

### Lane C: leaf walker (REQ-004, R2-P1-002)

- `generate-leaf-manifest.cjs` resolves each start scope, the default roots and the declared scopes, and confines it to the skill before `readdirSync` or a file read. The test covers a root and a declared scope symlinked outside the skill.

### Lane D: CI workflows (REQ-005, REQ-006, REQ-007, R2-P1-004, R8-P1-001, SL-006-010)

- `trigger-index-rebuild.yml` runs as two jobs, not two steps, because steps in one job share `.git/config`, `GITHUB_ENV` and the runner's processes. The `rebuild` job holds `contents: read` and no secret. It checks out with `persist-credentials: false`, installs with `npm ci --ignore-scripts`, regenerates and verifies, and uploads the rebuild commit as a bundle when the outputs match a fresh generation. The `push` job, which needs `rebuild`, holds `contents: write` and `PUSH_TOKEN`. It fetches the bundle with `gh run download`, checks that it holds exactly one commit on the checked-out base that changes only the four generated paths, and pushes with git. Hooks stay off for the git calls in both jobs. The operator chose this restructure on 2026-10-10 over leaving the token in place, which the 016/004 spec had decided on 2026-10-08.
- `runtime/cli/tests/trigger-index-rebuild-workflow.vitest.ts` runs the workflow's run blocks under bash against a local bare origin. It passes 59 with 1 skipped on its own, and 74 passed with 1 skipped (75 tests) together with the ci-rule-set file, under bash 3.2 and bash 5.2 (`closure-trigger-solo-bash32.txt`, `closure-trigger-solo-bash52.txt`, `closure-trigger-ci-rule-combined-bash32.txt` and `closure-trigger-ci-rule-combined-bash52.txt` in `scratch/evidence/`). Mutants that move the generator into the push step, persist the header into git config, or drop the non-fast-forward branch each fail it. Its parent-process check accepts an unreadable parent on macOS, so the Linux path needs a real Actions run (Known Limitations item 18).
- A nonzero exit from the regenerate step fails the job before any commit. The verify step generates again into a scratch directory and compares all four outputs, so a stale or partial set never commits. The generator's check output is replayed inside a stop-commands block.
- `strict-pass-freshness-report.yml` wraps the folder names it prints, and the repair report it replays, in a stop-commands block closed by a random token. The reproduction is in `workflow-command-trace.txt`.
- `changed-packet-validation.yml` escapes each per-packet annotation property and message, replays validator stderr inside a stop-commands block, and lists changed packets with `git diff -z`. The stage-two harness ran that listing on the same block, and it lists and grades the control-character, quote and non-ASCII names (`scratch/evidence/changed-packet-listing-controlchar-stage2.txt`).
