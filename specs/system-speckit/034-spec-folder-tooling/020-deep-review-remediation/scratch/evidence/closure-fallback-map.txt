CLOSURE EVIDENCE: fallback cases for CHK-FIX-004 (coordinator decision D5)

Definition used in this map. A fallback is a path the code takes when its primary resolution is absent or fails, such as a default root, a default specs root or a default input. A fallback case is adversarial when a link or a dangling target sits on that fallback path and the test asserts that nothing is written through it. A parity case that only checks that the default root resolves the same packets is not adversarial.

Lane A, archive.sh. Fallback: the specs root falls back to "$PROJECT_ROOT/specs" when resolve_existing_dir fails (archive.sh, mutant F).
  Cases (archive-track.vitest.ts, both names checked with rg -F):
    refuses when the specs root is a dangling link, and creates nothing through it
    refuses in a copy outside any repository whose derived root has no specs folder
  Mutant F removes the fallback and both cases fail (S/k2a/red-F.txt, 2 of 45).
  Verdict: MEETS.

  Case (heal-target-parity.vitest.ts): each entrypoint defaults the specs root to the working directory.
  This case has no link and no dangling target. It checks that the default root resolves the same packets. It is not adversarial.
  No case puts a link or a dangling target on the default root. Matrix row B-11 (linked parent outside the default roots) is MISSING.
  Verdict: DOES NOT MEET.
