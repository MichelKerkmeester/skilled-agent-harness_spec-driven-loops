Route 3 annotation injection: closed.

Before the fix, each per-packet annotation printed the raw packet name in its file property. A folder name holding a percent-encoded line feed followed by "::error::" therefore reached the runner's property decoding, which turns %0A into a line break. The hostile case uses the folder name a%0A::error::PWNED. The old block prints this line (route3-hostile-old.log):

  ::error file=specs/hostile/a%0A::error::PWNED/spec.md::New packet does not validate

After the fix, the property and the message are escaped with the workflow-command rules: % becomes %25, CR becomes %0D, LF becomes %0A, and in properties : becomes %3A and , becomes %2C. The same folder name now prints (route3-hostile-new.log):

  ::error file=specs/hostile/a%250A%3A%3Aerror%3A%3APWNED/spec.md::New packet does not validate

The escaped text decodes back to the literal folder name, so it cannot begin a new command. The regression, normal and stderr cases print escaped annotations with the new block (route3-regression-new.log, route3-normal-new.log, route3-stderr-new.log). The unit-level annotation pairs, old and new, are in route3-unit-annotations.tsv.

Validator output replay: closed. Validator stderr is written between ::stop-commands::<token> and ::<token>::, where the token is a random UUID per run. route3-replay-1.txt and route3-replay-2.txt replay text that contains a fake ::stop-commands::fake and a ::error::PWNED line. Both stay inside the block under two different tokens, and the replayed text is not read as commands.
