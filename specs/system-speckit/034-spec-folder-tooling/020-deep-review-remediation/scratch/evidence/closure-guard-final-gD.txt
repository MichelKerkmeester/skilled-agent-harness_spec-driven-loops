Observation, not changed (production code is outside this lane). The apply closures in repair-derived.cjs read their targets with fs.readFileSync, which follows a link. The reads are at lines 331, 355, 379, 405 and 424. A link that appears after planning is therefore read through before writeAtomic refuses the write. Nothing outside the packet is changed, because the write is refused. The read still happens in that window, which the link refusal is meant to prevent. The race cases exercise exactly this path. A candidate fix is to read those targets through the same link refusal that readIfPresent uses. This is an inference from reading the code, confirmed only in the sense that the race cases pass with the read in place.
