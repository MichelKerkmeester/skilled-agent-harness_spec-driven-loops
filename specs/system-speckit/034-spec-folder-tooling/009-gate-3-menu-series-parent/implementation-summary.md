## What Was Built

An agent that answers the Gate 3 menu now reads the series parent rule inside the menu itself. Option B is for new or unrelated work, option C names the series parent for a different change to the same artifact, and the mutation notice says the same. The old wording offered a plain related folder, so an agent could pick B and open another singleton packet without ever seeing the rule.

### Phase 9: gate-3-menu-series-parent

`spec-gate-core.mjs` carries the new text once and exports the four option labels. The Pi dialog reads those labels from the core instead of keeping its own literal, so the runtime menu and the dialog cannot drift apart. Every other copy of the menu, first named in the file list and then found by a second-opinion review, was updated to the same short form: "B) New (new or unrelated work only)" and "C) Related (a phase child, or a series parent for a different change to the same artifact)".

## How It Was Delivered

The core module and its label exports changed first. The byte pins and the skill-advisor parity fixture were then regenerated against the new text, and the Pi dialog was pointed at the exported labels. A second-opinion review found every remaining copy of the menu, and all of them were updated in the same change set, including the regenerated compiled contracts and the rebuilt Gate 3 box in the root README. The affected suites and the typecheck were rerun from the final state.
<!-- /ANCHOR:how-delivered -->

<!-- ANCHOR:decisions -->
## Key Decisions

| Decision | Why |
|----------|-----|
| Keep one source of truth in `spec-gate-core.mjs` and export the option labels | The Pi dialog no longer keeps a second literal, so the runtime menu and the dialog cannot drift apart |
| Use a short form on one line per option | The menu stays compact while option B names its boundary and option C names the series parent |
| Regenerate the compiled deep contracts instead of editing them | They are generated artifacts, so the presentation stays the one place to edit |
| Fold every copy the second-opinion review found into the same change set | A half-swept menu would leave one runtime showing the old rule while another shows the new one |

## Known Limitations

1. **The `/speckit:plan` intake listing was not updated.** spec.md records it as out of scope for this round, so an agent that follows that listing alone still meets the older wording there while the Gate 3 menu it answers carries the new text.
2. **The sweep is a point-in-time check.** A copy of the menu added after this phase will not carry the new wording until the byte pins or a fresh repository sweep catch it.
