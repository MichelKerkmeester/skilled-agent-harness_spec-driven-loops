# Feature Specification: Add a quiet flag to recommend-level.sh

<!-- SPECKIT_LEVEL: 3 -->


---

## EXECUTIVE SUMMARY

`recommend-level.sh` answers one question — which SpecKit level a task needs — but prints a 16-line report for a simple invocation and 17 lines when phase factors are listed, so a caller that needs only the level must parse the report or take on a JSON parser. The change adds a `--quiet` flag that prints the single `Recommended Level:` line, while the default report and the `--json` document stay byte-identical. A line count on a `--quiet` run plus a `diff` against the captured pre-change baseline proves it.

**Key Decisions**: `--quiet` renders from the same format site as the default report, so the two cannot drift; `--json` takes precedence when both output flags are passed

**Critical Dependencies**: the existing `output_text()` renderer in `recommend-level.sh`

<!-- ANCHOR:problem -->
## 2. PROBLEM & PURPOSE

### Problem Statement
A caller that needs the recommended level currently reads it out of a human report: a simple run prints 16 lines and a run with phase factors prints 17. Shell callers pipe the report through `grep`, `awk` or `sed` to recover one value, which breaks when the surrounding lines change; callers that want structure must switch to `--json` and add a JSON parser.

### Purpose
One flag makes the script emit exactly the line a machine caller needs, with no parser and no change to the existing output modes.
<!-- /ANCHOR:problem -->

---

<!-- ANCHOR:scope -->
## 3. SCOPE

### In Scope
- Add a `--quiet` flag that prints only the recommended-level line
- Keep the default text report and the `--json` document byte-identical to the current release
- Document the flag in the script header OPTIONS block and in `show_help()`
- Verify the flag across the mode matrix (default, `--quiet`, `--json`, `--json --quiet`) and the invalid-input path

### Out of Scope
- Changing scoring, thresholds, confidence, phase computation or exit codes - the flag is a rendering choice, not a scoring change
- Adding a new output format beyond the existing text line and JSON document - a third format would need its own contract
- Refactoring `output_text()` or the argument parser - the change adds one branch and one case arm

### Files to Change

| File Path | Change Type | Description |
|-----------|-------------|-------------|
| `.skilled/skills/system-spec-kit/runtime/cli/spec/recommend-level.sh` | Modify | Add the `QUIET` global, the `--quiet` case arm, the one-line render branch in `output_text()` and the help text |

## 5. SUCCESS CRITERIA

- **SC-001**: `recommend-level.sh --loc 500 --files 15 --auth --api --db --architectural --quiet` writes one line to stdout and exits 0
- **SC-002**: The default report for the same invocation `diff`s clean against the baseline captured before the change (17 lines)
- **SC-003**: The `--json` document `diff`s clean against its baseline, with and without `--quiet`
- **SC-004**: The `--quiet` line equals the first `Recommended Level:` line of the default report for the same inputs

## 6. RISKS & DEPENDENCIES

| Type | Item | Impact | Mitigation |
|------|------|--------|------------|
| Dependency | Bash 3.2+ and the existing `output_text()` renderer | No new runtime; the script already requires both | No action needed; the flag adds one string comparison |
| Risk | The quiet line drifts from the default report's level line | Med - callers would read a different value than operators see | Reuse the default report's format site and assert the two lines match in verification |
| Risk | `--quiet` swallows an error path and exits 0 with no output | High - a caller would read an empty level as success | Keep validation before rendering; assert exit 1 and empty stdout on invalid input |
<!-- /ANCHOR:risks -->

## 7. NON-FUNCTIONAL REQUIREMENTS

### Performance
- **NFR-P01**: The flag adds no measurable time; the run stays within the same tens of milliseconds and adds one string comparison

### Security
- **NFR-S01**: N/A - the script reads no credential, opens no network connection and handles no user data; the flag adds no input surface beyond a boolean switch

### Reliability
- **NFR-R01**: Exit codes are unchanged for every input class; `--quiet` cannot fail independently of the default path because both share the same validation and scoring code

---

## 8. EDGE CASES

### Data Boundaries
- Empty input: with no `--loc` and no `--files`, the script exits 1 with the existing stderr error and stdout stays empty in both modes
- Maximum length: 1000+ LOC and 30+ files still print one line under `--quiet`; the level line has no length dependence on input size

### Error Scenarios
- External service failure: N/A - the script calls no service
- Network timeout: N/A - the script makes no network call
- Unknown option: exits 1 with the existing stderr text; `--quiet` does not suppress or reorder it

### State Transitions
- Partial completion: N/A - the script is a stateless one-shot invocation
- Session expiry: N/A - the script holds no session
