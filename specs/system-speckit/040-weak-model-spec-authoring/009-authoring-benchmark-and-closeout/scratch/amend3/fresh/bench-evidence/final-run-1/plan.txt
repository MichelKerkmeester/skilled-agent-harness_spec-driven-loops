<!-- ANCHOR:architecture -->
## 3. ARCHITECTURE

### Pattern

Single script, one render branch.

### Key Components
- **Argument parser** (`recommend-level.sh` §5): the `case` block that turns argv into globals. `--quiet` joins it as a boolean with no argument.
- **`output_text()`** (§4): the only place the human report is rendered. The quiet branch is an early return here, so the label literal stays beside the full report.
- **`show_help()` and the header comment**: the two documentation surfaces inside the file. Both list every flag, so both must list `--quiet`.

### Data Flow

argv → parser sets `LOC`, `FILES`, the risk flags, `JSON_OUTPUT` and `QUIET_OUTPUT` → numeric validation → `calculate_*_score` → `determine_level` → `calculate_confidence` → output dispatch. `output_json` runs when `JSON_OUTPUT` is true; otherwise `output_text` runs, and its first statement returns the one-line form when `QUIET_OUTPUT` is true. Scoring never reads `QUIET_OUTPUT`.

## L3: ARCHITECTURE DECISION RECORD

### ADR-001: Render the quiet line inside `output_text()`

**Status**: Proposed

**Context**: The quiet output is one line that already exists inside the full report. A separate render function would have to repeat the label literal, and the two copies could drift when the label changes.

**Decision**: Make the quiet branch the first statement of `output_text()`, returning after it prints the same interpolation the full report uses.

**Consequences**:
- The label format is defined once, next to the report that also prints it.
- `output_text()` gains a second exit path; the early return must stay above every other `echo` or a stray blank line breaks the one-line contract.

**Alternatives Rejected**:
- A separate `output_quiet()` function: duplicates the label literal, which is exactly the drift the change should avoid.
- Branching in the main dispatch (`if quiet; then ... else output_text; fi`): moves the label away from the report and gives the script a second output entry point.

---

### ADR-002: `--json` takes precedence over `--quiet`

**Status**: Proposed

**Context**: `--json` is a machine contract with three live callers that parse it. `--quiet` asks for a one-line text form. Combining them has no single obvious meaning.

**Decision**: `--quiet` affects `output_text()` only. When `JSON_OUTPUT` is true, `output_json` runs and `--quiet` has no effect.

**Consequences**:
- No existing JSON caller can receive text, even if it later adds `--quiet` for another reason.
- A caller that wants one JSON field must still parse the document; `--quiet` does not become a second JSON mode.

**Alternatives Rejected**:
- Reject the combination with an error: fails a harmless call for no benefit.
- Quiet over JSON: prints text into a stream every JSON caller parses, which is the one outcome that breaks them.

---

### ADR-003: Long flag only, no `-q`

**Status**: Proposed

**Context**: The script already carries short aliases for `--json` (`-j`) and `--help` (`-h`), so symmetry would suggest `-q`.

**Decision**: Add `--quiet` only.

**Consequences**:
- One spelling to document and to keep in sync with `--help`.
- A caller that wants a short form must wait for a request that justifies it.

**Alternatives Rejected**:
- Add `-q` for symmetry: a second spelling with no caller, and one more line in every help surface.
