# Feature Specification: Add a quiet flag to recommend-level.sh

<!-- SPECKIT_LEVEL: 3 -->


---

## EXECUTIVE SUMMARY

`recommend-level.sh` answers one question — which SpecKit level a task needs — but its default output is a report of sixteen to eighteen lines, and its `--json` mode is a full document. A caller that wants only the level must therefore grep a sentence out of prose, which breaks silently when the wording moves. This change adds a `--quiet` flag that prints the single `Recommended Level: <N> (<Name>)` line, and nothing else. The proof is a line count: `--quiet` prints exactly one line, and every non-quiet invocation stays byte-identical.

**Key Decisions**: `--quiet` selects a shorter stdout path for the text report only; when `--json` is also passed, the JSON document wins. The quiet line and the report's level line are emitted from one shared format site, so the two cannot drift apart.

**Critical Dependencies**: None — one bash script, no new tools, no external services.

## 2. PROBLEM & PURPOSE

### Problem Statement
`.skilled/skills/system-spec-kit/runtime/cli/spec/recommend-level.sh` prints a human-readable report of sixteen to eighteen lines, or a full JSON document under `--json`, and offers no minimal mode. Tooling that runs the script only to learn the level must capture the report and grep the `Recommended Level:` sentence out of it, which couples the caller to the report's layout and fails silently if that layout changes.

### Purpose
With `--quiet`, the script prints exactly its final recommended-level line and nothing else, so a caller reads the level without parsing; without the flag, every existing invocation keeps the output it has today.
<!-- /ANCHOR:problem -->

---

<!-- ANCHOR:scope -->
## 3. SCOPE

### In Scope
- Add a `--quiet` boolean flag to the argument parser of `recommend-level.sh`.
- Add a quiet output path that prints only the `Recommended Level: <N> (<Name>)` line.
- Emit the report's level line and the quiet line from one shared format site so the two cannot diverge.
- Document `--quiet` in the script's header OPTIONS comment and in `show_help()`.
- Preserve existing behavior exactly: the default report, the `--json` document, error text, stderr routing and exit codes.

### Out of Scope
- A `-q` short alias — the request names `--quiet` only, and an alias would widen the public interface without a caller asking for it.
- A bare-value mode that prints `3` alone — it would create a second format for the same fact and break parsers written against today's label.
- Changes to scoring, phase logic, report wording or the JSON schema — the flag must not alter an existing output contract.
- An automated test harness for the script — none exists today, so verification is the command matrix in `tasks.md`; adding a harness is its own packet.
- Edits to any other script or caller — the change is confined to one file.

### Files to Change

| File Path | Change Type | Description |
|-----------|-------------|-------------|
| `.skilled/skills/system-spec-kit/runtime/cli/spec/recommend-level.sh` | Modify | Add a `QUIET` global, a `--quiet` parse case, a shared level-line helper, a quiet dispatch branch, and the help text |

<!-- ANCHOR:success-criteria -->
## 5. SUCCESS CRITERIA

- **SC-001**: `bash .skilled/skills/system-spec-kit/runtime/cli/spec/recommend-level.sh --quiet --loc 1000 --files 20 --architectural --api --db | wc -l` prints `1`, the line reads `Recommended Level: 3 (Full)`, and the exit code is 0.
- **SC-002**: The default output for a fixed invocation is byte-identical before and after the change — the `diff` of the two captures is empty.
- **SC-003**: `--quiet --json` output equals `--json` output for the same inputs — the `diff` of the two captures is empty.

**Given** the script runs with `--quiet --loc 1000 --files 20 --architectural --api --db`, **When** it exits, **Then** stdout is exactly the single line `Recommended Level: 3 (Full)` and the exit code is 0.

**Given** the same invocation without `--quiet`, **When** it exits, **Then** stdout equals the pre-change multi-line report byte-for-byte.

**Given** `--quiet --json --loc 100 --files 3`, **When** it exits, **Then** stdout is the same JSON document `--json` alone prints.

**Given** `--quiet` with neither `--loc` nor `--files`, **When** it runs, **Then** it exits 1, the missing-input error goes to stderr, and stdout is empty.

**Given** `--quiet --bogus`, **When** it runs, **Then** it exits 1 with the unknown-option error on stderr.

**Given** `--help` with or without `--quiet`, **When** it runs, **Then** the help text names `--quiet` and exits 0.

## 7. NON-FUNCTIONAL REQUIREMENTS

### Performance
- **NFR-P01**: `--quiet` adds no measurable runtime — the scoring path is unchanged and only the output selection differs; the script still completes in the same tens of milliseconds.

### Security
- **NFR-S01**: `--quiet` takes no value, so it adds no input-parsing or injection surface; the script performs no authentication and reads no credential.

### Reliability
- **NFR-R01**: The exit-code contract is unchanged: 0 on success, 1 on any usage or input error, with errors on stderr only.

---

## 8. EDGE CASES

### Data Boundaries
- Empty input: `--quiet` alone still fails the required-input check (`--loc` or `--files`), exiting 1 with the error on stderr and nothing on stdout.
- Maximum input: extreme values such as `--loc 100000 --files 999 --quiet` still print exactly one line; there is no buffering or truncation path.
- Flag position: `--quiet` works anywhere in the argument list, matching the script's existing order-independent parse loop.

### Error Scenarios
- External service failure: N/A — the script is fully offline and calls no service.
- Network timeout: N/A — the script makes no network request.

### State Transitions
- Partial completion: N/A — the script is single-shot and keeps no intermediate state.
- Session expiry: N/A — the script has no session concept.
- Output-channel separation: errors never reach stdout, so a caller capturing stdout under `--quiet` cannot capture an error line by accident.

<!-- ANCHOR:questions -->
## 12. OPEN QUESTIONS

- Does `--quiet` change `--json` output? No — JSON is already a single machine-readable document, so it wins when both flags are present.
- Does `--quiet` suppress stderr or skip phase scoring? No — stderr is unchanged and scoring still runs; the flag only selects a shorter stdout path.
- Does the quiet line keep the `Recommended Level:` label instead of a bare number? Yes — the label is the existing contract, and a bare value would be a second format to maintain.
- None blocking.
