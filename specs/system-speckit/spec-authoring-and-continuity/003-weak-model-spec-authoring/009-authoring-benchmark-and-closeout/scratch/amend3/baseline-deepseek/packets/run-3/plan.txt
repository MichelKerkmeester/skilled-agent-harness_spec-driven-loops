### Overview
Add a quiet output mode to `recommend-level.sh`. The change is a `QUIET_OUTPUT` global beside `JSON_OUTPUT`, one `--quiet` case in the existing argument loop, an `output_quiet()` function that prints the level line the full report starts with, and a dispatch branch that prefers JSON, then quiet, then text. Default output and every exit code stay exactly as they are.

<!-- ANCHOR:architecture -->
## 3. ARCHITECTURE

### Pattern
Single-file CLI with one function per concern; the output format is a strategy selected once, at the end of the run.

### Key Components
- **Argument parser**: the `while [[ $# -gt 0 ]]` loop maps flags to globals and rejects unknown options.
- **Scoring functions**: `calculate_loc_score`, `calculate_files_score`, `calculate_risk_score`, `calculate_complexity_score`, `determine_level`, `determine_phasing`, `calculate_confidence`. All unchanged.
- **`output_text()`**: the current human-readable report; unchanged in content.
- **`output_quiet()`**: new; prints the recommended-level line and nothing else.
- **Output dispatch**: the final branch that currently chooses `output_json` or `output_text`; it gains quiet as a third option.
- **`show_help()`**: the usage text that documents every option.

### Data Flow
`argv` -> globals (`LOC`, `FILES`, risk flags, `JSON_OUTPUT`, `QUIET_OUTPUT`, `RECOMMEND_PHASES`) -> score functions -> `determine_level` -> `determine_phasing` (unless `--no-recommend-phases`) -> dispatch -> stdout. Quiet mode changes only the last step.

## L3: ARCHITECTURE DECISION RECORD

### ADR-001: Quiet mode is an output mode, and JSON takes precedence

**Status**: Accepted

**Context**: The script already selects between two output modes with a boolean (`JSON_OUTPUT`). A second boolean creates a four-cell matrix, and two cells need an explicit answer: neither flag, and both flags. Programmatic callers in the speckit command assets pass `--json` and parse the document, and one test asserts that JSON stdout holds the payload and nothing else.

**Decision**: `--quiet` is a text-output modifier. Dispatch order is JSON, then quiet, then text. `--json --quiet` prints the unchanged JSON document.

**Consequences**:
- Callers that pass `--json` keep their exact contract, including the combination with `--quiet`.
- `--quiet` is meaningful only for the human-readable path, which is what the request describes.
- A caller that wants a bare number from JSON must extract `recommended_level` itself; that is the existing JSON contract and not this flag's job.

**Alternatives Rejected**:
- Quiet replaces JSON with the bare level number: breaks existing `--json` consumers and the test that asserts JSON purity.
- Make `--json --quiet` an error: hostile to a caller that sets flags generically, and adds an exit path nobody needs.
- Add a `-q` short alias now: the request names `--quiet`, and the alias is a separate interface decision.
