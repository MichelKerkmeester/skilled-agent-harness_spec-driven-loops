# Feature Specification: Add a quiet flag to recommend-level.sh

<!-- SPECKIT_LEVEL: 3 -->

---

## EXECUTIVE SUMMARY

`recommend-level.sh` is the spec-kit helper that turns LOC, file count, and risk flags into a documentation-level recommendation. It always prints a multi-section human report unless `--json` is supplied, so a caller that wants only the level must grep the report or parse JSON.

This packet specifies a minimal, opt-in `--quiet` flag. With the flag the script prints one line, `Recommended Level: 0 (Quick)` for a Level 0 result, and nothing else on stdout; without the flag every existing output path stays byte-identical.

**Key Decisions**: Keep the flag long-form only; route quiet output through a dedicated function rather than modifying `output_text`; let `--json` take precedence when both flags are present.

**Critical Dependencies**: None outside the script itself. The change uses the existing bash 3.2-compatible parser and output dispatch, with no new libraries, services, or data.

## 2. PROBLEM & PURPOSE

### Problem Statement

The script's text mode opens with a blank line, prints the recommendation, a score and confidence line, a per-factor breakdown, and a phase section. A shell caller that needs only the recommendation must either grep for `Recommended Level:` or invoke `--json` and parse the object with a JSON tool. Both approaches are heavier than the task and couple the caller to the report layout.

There is no compact text mode. Adding one by changing the default report would break every human reader and any caller that compares output, so the capability has to be opt-in.

### Purpose

Provide a stable, one-line text result through `--quiet` so scripts and workflow prompts can capture the recommendation directly, while every existing invocation keeps its current output.
<!-- /ANCHOR:problem -->

## 3. SCOPE

### In Scope

- Accept a boolean `--quiet` option in the existing argument loop, in any position relative to the other options.
- In text mode, write exactly one stdout line in the default report's format, for example `Recommended Level: 0 (Quick)`.
- Document the flag in the file-header OPTIONS block and in `show_help` output.
- Preserve the current default text report, `--json` object, scoring, confidence, phase calculation, exit codes, and stderr messages.
- Add a focused regression test that exercises quiet text, default text, JSON, JSON plus quiet, and the error path.

### Out of Scope

- Changing scoring thresholds, level names, confidence, or phase recommendation logic.
- Adding a short `-q` alias, a `--verbose` counterpart, or any new output format such as key=value or level-only numeric output.
- Refactoring `output_text`, `output_json`, or the argument parser beyond the new branch.
- Editing callers or workflow reference documents outside the script's own header and help text.

| File Path | Change Type | Description |

## 4. REQUIREMENTS

### P0 - Blockers (MUST complete)

| ID | Requirement |
|----|-------------|
| REQ-001 | The argument parser must accept `--quiet` as a boolean flag regardless of option order, and must continue to reject unknown options with the existing message and exit code 1. |
| REQ-002 | In text mode with `--quiet`, stdout must contain exactly one line in the default report's format, for example `Recommended Level: 0 (Quick)`, followed by a newline, with no leading blank line and no score, breakdown, or phase sections. |
| REQ-003 | Without `--quiet`, the default text report and the `--json` object for a given input must remain byte-identical to their pre-change output. |
| REQ-004 | `--quiet` must not change the computed level, total score, confidence, phase fields, exit status, or stderr text for any input; validation errors must still go to stderr only. |

### P1 - Required (complete OR user-approved deferral)

| ID | Requirement |
|----|-------------|
| REQ-005 | The file-header OPTIONS block and `show_help` must document `--quiet`; `--quiet --help` must still print help and exit 0. |
| REQ-006 | When `--quiet` and `--json` are both supplied, the unchanged JSON object must be emitted and no text line must appear. |
| REQ-007 | A focused regression test must cover quiet single-line output, unchanged default text output, JSON with and without quiet, help precedence, and an error path. |

## 6. RISKS & DEPENDENCIES

| Type | Item | Impact | Mitigation |
|------|------|--------|------------|
| Dependency | Bash 3.2 compatibility on macOS | New syntax could break the script on the default shell | Use the existing `[[ ]]` and `case` patterns; run `bash -n` and the real script under `/bin/bash`. |

| Risk | The quiet line drifts from the default recommendation line | Two formats for one value | Assert the quiet line equals the default report's recommendation line in the test. |

## 7. NON-FUNCTIONAL REQUIREMENTS

### Performance

- **NFR-P01**: The change adds one boolean check to the output dispatch and must not introduce measurable runtime cost or new subprocesses.
- **NFR-P02**: Quiet output must be newline-terminated and safe to capture with `$(...)` without stripping meaningful content.

### Security

- **NFR-S01**: The flag adds no new input parsing beyond a boolean and introduces no secrets, environment reads, file writes, or network access.
- **NFR-S02**: Existing validation errors must remain on stderr so quiet stdout stays machine-safe.

### Reliability

- **NFR-R01**: Exit codes must remain `0` for success and `1` for user error, matching the script's documented taxonomy.
- **NFR-R02**: Output selection must be deterministic and exclusive: JSON first, then quiet text, then the default text report.

---

## 8. EDGE CASES

### Data Boundaries

- Empty or missing `--loc`/`--files`: the existing error path applies unchanged, with or without `--quiet`.
- Zero values for both inputs: the existing error path applies unchanged.
- Very large values: scoring is unchanged; quiet prints the same level the default report would print.
- Repeated `--quiet`: the flag is idempotent and sets the same boolean.

### Error Scenarios

- `--quiet` with no `--loc` or `--files`: stderr message and exit 1 unchanged; stdout stays empty.
- `--quiet` with a non-numeric value: the existing numeric validation error and exit 1 apply.
- `--quiet=true`: not a supported form; the unknown-option error applies.
- `--quiet --json`: JSON output wins, per ADR-001 in `plan.md`.
- `--quiet --help`: help wins because `show_help` exits during parsing; exit 0.
- `--no-recommend-phases --quiet`: quiet output is identical, since the phase section is suppressed in quiet mode either way.
