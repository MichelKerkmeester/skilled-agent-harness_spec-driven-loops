<!-- ANCHOR:architecture -->
## 3. ARCHITECTURE

### Pattern

Single script branch. No framework pattern applies: the change is one conditional output path inside an existing linear script.

### Key Components
- **Argument parser** (`while [[ $# -gt 0 ]]` loop, roughly lines 656-719): accepts `--quiet|-q` and sets `QUIET_OUTPUT=true`.
- **Output dispatch** (roughly lines 770-774): selects `output_json`, the new quiet path, or `output_text`.
- **`_level_line()` helper**: renders `Recommended Level: <N> (<Name>)` once, so the report and the quiet path cannot drift apart.
- **`output_text`** (roughly lines 508-558): keeps the full report; its level line now comes from the helper and stays byte-identical.
- **`show_help`** (roughly lines 162-211) and the header OPTIONS block (roughly lines 16-27): document the new flag.

### Data Flow

argv enters the parser, which sets `LOC`, `FILES`, the risk flags, `RECOMMEND_PHASES`, `PHASE_THRESHOLD`, `JSON_OUTPUT` and now `QUIET_OUTPUT`. Scoring is unchanged. `determine_level` sets `RECOMMENDED_LEVEL` and `LEVEL_NAME`. Dispatch reads `JSON_OUTPUT` first, then `QUIET_OUTPUT`, then falls through to `output_text`; `--quiet` therefore changes only the final rendering step.

## L3: ARCHITECTURE DECISION RECORD

### ADR-001: A CLI flag, not an environment variable

**Status**: Accepted

**Context**: Callers need a one-line mode. The script already takes every input as a CLI flag, and an environment variable would leak across invocations in the same shell.

**Decision**: Add `--quiet` with `-q` as the short alias, matching the existing `--json, -j` and `--help, -h` pairs.

**Consequences**:
- The mode is explicit at each call site and composes with the other flags.
- The parser grows by one case arm and the help text by one row.
- The short alias adds a second spelling that must be tested, which AC-005 covers.

**Alternatives Rejected**:
- `RECOMMEND_LEVEL_QUIET=1`: hidden state that survives across unrelated commands in the same shell, and it cannot be discovered from `--help`.
- Always printing the compact form: breaks every caller that reads the report, so it is a breaking change rather than an option.

---

### ADR-002: `--json` wins when both flags are passed

**Status**: Accepted

**Context**: `--quiet` defines a text shape and `--json` defines a document. Passing both leaves two plausible outputs and no defined quiet-JSON shape.

**Decision**: Dispatch order is JSON, then quiet, then text. `--quiet --json` emits the JSON document unchanged.

**Consequences**:
- No half-format exists that a parser would reject.
- A caller that wants one line uses the text form and omits `--json`.
- AC-006 pins the behavior so it cannot flip silently.

**Alternatives Rejected**:
- Exit 1 on the combination: turns flag composition into an error and breaks callers that pass a shared flag set.
- Trim the JSON to the level field: invents a third schema with no consumer.

---

### ADR-003: One helper renders the level line

**Status**: Accepted

**Context**: The quiet output must match the report's `Recommended Level:` line exactly. Two hand-written copies would drift on the first wording change.

**Decision**: Add `_level_line()` and call it from `output_text` and `output_quiet`.

**Consequences**:
- The label and format have one source of truth, so a future change cannot update one path and miss the other.
- `output_text` changes internally while its output stays byte-identical, which the baseline diff proves.
- The helper adds one function call per invocation, below the timer's resolution.

**Alternatives Rejected**:
- Duplicate the `echo` line in both functions: simplest diff, but guarantees future drift.
- Have `output_quiet` call `output_text` and filter with `head -n 2`: adds a pipeline, depends on line position, and changes the process count.
