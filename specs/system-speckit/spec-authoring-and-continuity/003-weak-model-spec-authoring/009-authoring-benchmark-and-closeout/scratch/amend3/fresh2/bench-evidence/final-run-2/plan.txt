<!-- ANCHOR:architecture -->
## 3. ARCHITECTURE

### Pattern
Single-script branch (no application pattern applies)

### Key Components
- **`recommend-level.sh` argument loop**: parses `--quiet` into a `QUIET` boolean and leaves every existing case untouched.
- **`format_level_line()`**: the single producer of `Recommended Level: <N> (<Name>)`.
- **`output_quiet()`**: writes that line once, with no leading blank line.
- **`output_text()`**: the existing report, unchanged except that its level line now comes from the formatter.

### Data Flow

`argv` -> the parser sets `QUIET` -> scoring, confidence and phase calculation run exactly as before -> dispatch chooses `output_json` when `--json` is set, `output_quiet` when `--quiet` is set, and `output_text` otherwise.

## L3: ARCHITECTURE DECISION RECORD

### ADR-001: Share one level-line formatter instead of duplicating the label

**Status**: Accepted

**Context**: Two output paths must print a byte-identical `Recommended Level:` line. A duplicated `echo` in each path is the obvious implementation and the obvious source of drift: a later label or format change lands in one path only.

**Decision**: Extract `format_level_line()` and call it from both `output_text()` and `output_quiet()`.

**Consequences**:
- The label has one definition, so byte equality holds by construction rather than by test alone.
- The script gains one small function, consistent with the helper functions it already defines.
- `output_text()` changes in source while its output stays identical.

**Alternatives Rejected**:
- Duplicate the `echo` in `output_quiet()`: rejected because two copies of a parser-visible label drift.
- Pipe `output_text` through `sed -n '2p'`: rejected because it starts a subprocess, keeps the leading blank line in the pipeline, and breaks if the report's line order changes.

---

### ADR-002: `--json` keeps precedence over `--quiet`

**Status**: Accepted

**Context**: Both flags suppress the human report, so a caller can pass both. The pair needs one deterministic meaning.

**Decision**: The output dispatch checks `JSON_OUTPUT` first, then `QUIET`, then falls back to text. `--quiet` is documented as a modifier of the text output only.

**Consequences**:
- `--json --quiet` prints the unchanged JSON document, so the structured contract never silently downgrades.
- No new error path or exit code is introduced for a harmless pair.
- A caller that wants one line must not pass `--json`; the help text and AC-004 make that explicit.

**Alternatives Rejected**:
- Error on the combination: rejected because it adds a failure mode and a new exit path for a pair with no ambiguity.
- Let `--quiet` win: rejected because it would replace a structured document with plain text for a caller that asked for JSON.
