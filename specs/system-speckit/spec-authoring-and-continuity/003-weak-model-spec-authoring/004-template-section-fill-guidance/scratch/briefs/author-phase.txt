WHAT THE PHASE DOES (frozen)
Phase 003 (before this one) converts every core-template hint to a `[YOUR_VALUE_HERE: ...]` token and bumps the
marker to v2.3. This phase makes each section of the core templates tell a weak model exactly what to write:
a ONE-LINE IMPERATIVE FILL INSTRUCTION plus a GOOD example and a WEAK example, per section, Level 1 sections first.
Level 1 anchors:
   spec (7):         metadata, problem, scope, requirements, success-criteria, risks, questions
   plan (7):         summary, quality-gates, architecture, phases, testing, dependencies, rollback
   tasks (6):        notation, phase-1, phase-2, phase-3, completion, cross-refs
   implementation-summary (6): metadata, what-built, how-delivered, decisions, verification, limitations
Verify these anchor lists against the real templates (`rg -o 'ANCHOR:[a-z0-9-]+' ...templates/core/*.tmpl | sort -u`);
if a name differs, the real template wins and you record the difference. Then cover the Level 2 and Level 3
add-on sections too (templates/addons): at least an instruction line per section, good/weak pairs where cheap.

WRITE THE FILL TEXT LITERALLY in plan.md (a section "FILL TEXT TABLE" or per-template subsections): for every
section, the exact instruction line, the exact good example and the exact weak example, all about ONE fixed
running example feature so the examples are coherent. This is judgment work that must happen NOW at authoring time,
because the DeepSeek executor must copy text, not invent it. Quality bar: instruction names the ONE action
(e.g. "State the problem in two sentences: what breaks, and for whom."); good example is concrete and short; weak
example shows the typical weak-model failure (vague, generic, restating the title). Also fix the known trap:
the scaffold's generic Level 3 sections (feature flag, OWASP, uptime) are a weak-model trap seen while authoring
this packet; the plan must say what the template does instead (e.g. instruct "write N/A with one reason, or delete
the section if the section's gate allows"). Verify what the gate/validator really accepts before choosing.
