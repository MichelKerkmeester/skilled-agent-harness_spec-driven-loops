## What Was Built

You can now archive a packet in a track with `archive.sh` and push straight after. The packet stays inside its track, the track's list drops it, and a restore puts it back in the same track and lists it again.

### Keep a track packet inside its own track when archive.sh archives or restores it, and refresh the track list

Before this, the script knew one archive, `specs/z_archive/`. A track packet left its track, a restore dropped it at the specs root, and the track root's `children_ids` went stale, which the pre-push gate from packet 037 then blocked. Every track here archives into its own `z_archive/` by hand, and since this repository has no root archive, `--list` reported nothing at all.

The script now picks the archive from where the packet sits: a track's own `specs/<track>/z_archive/`, or the root archive for a packet at the specs root. Restore reads the owner back from the archive path and returns the folder there. `--list` shows every archive's entries by the path that restores them, and leaves out a symlinked track, whose packets the script cannot move. After each move it runs `refresh-track-roots.mjs` for the track. When the writer is missing or fails, the move still happens and the script says which list was not refreshed and how to fix it.

## How It Was Delivered

The tests came first and ran red, 6 of 7. The fixture is a throwaway git repository holding copies of `archive.sh`, the writer and its module, because the script takes its root from the working directory's repository. After the change passed, each guarded rule was removed on purpose. One removal survived at first: dropping the check that a restored folder sits under a track's `z_archive/`. Without it, a live phase child such as `specs/tools/001-a/002-p` would be moved out of its parent and into the track. A case for that now fails the removal, and a second case covers the symlinked track the list leaves out. All ten removals now fail the suite.

<!-- ANCHOR:decisions -->
## Key Decisions

| Decision | Why |
|----------|-----|
| A track packet archives into the track's own `z_archive/` | The operator's call, and where every track here already keeps its archive |
| Restore goes to the archive's owner | A folder comes back to the track it left |
| The move never waits on the list | A missing or failing writer leaves a warning with the command to rerun; the gate catches anything left stale |
| Keep "Refusing to archive outside specs root" and "not in archive directory" | `test-phase-validation.js` checks both messages |
| Leave symlinked tracks out of `--list` | Their packets resolve outside this specs root, so the script refuses to move them, and listing them would offer a restore that fails |

<!-- ANCHOR:limitations -->
## Known Limitations

1. **A phase child still archived to the root `specs/z_archive/`.** Only a packet directly in a track used the track's archive. Resolved by packet 039, `039-phase-aware-archive`: a phase now goes into its parent's own `z_archive/` and restores back into the parent.
2. **Symlinked tracks stay out of reach.** `ai-systems`, `anobel.com` and `obsidian` resolve outside this specs root, so the script refuses to archive from them and leaves their archives out of `--list`. Archive in those repositories by hand, then run `refresh-track-roots.mjs --track <name> --apply`.
