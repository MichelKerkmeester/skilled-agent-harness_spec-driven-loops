# Facts for packet 052 research-folder-continuity

- Symptom: `generate-context.js --full-auto` with continuity fields on a research record logged "Continuity not written: <leaf> has no implementation-summary.md yet", so the `_memory.continuity` blocks in 082 children 014-018 `spec.md` kept the values they were scaffolded with ("Scaffolded the research record before the first iteration", completion_pct 0).
- Root cause: commit 0d0f2a0a95 (2026-09-23, "write continuity fields from the save payload") wrote payload continuity only into `implementation-summary.md`. Research records, scaffolded by `create.sh` since commit e1a408ff6b (2026-09-07), keep their continuity block in `spec.md` (template `templates/packet-types/research.spec.md.tmpl`, marker `<!-- SPECKIT_LEVEL: research -->`) and never get an implementation summary.
- Fix: `runtime/cli/core/workflow.ts` gains `continuityHostPath(leafPath)`. It returns the leaf's `implementation-summary.md` when present, else its `spec.md` when that file carries the research level marker, else null. `planContinuityWrite` and `writePlannedContinuity` read, merge and atomically rename into that host; the plan carries it as `hostPath`. A non-research leaf without a summary is still refused with the same message.
- Tests: `runtime/cli/tests/save-continuity-write.vitest.ts` adds two cases: a research record's continuity lands in its spec.md with the scaffold values gone and no implementation summary created; a non-research leaf without a summary still gets no write and the refusal message.
- Evidence: baseline 15 of 15 pass (scratch/before/vitest-baseline.txt). New tests on the old workflow.ts: 1 failed, 16 passed, exit 1, the research case failing (scratch/before/vitest-new-test-on-old-code.txt). With the fix: 17 of 17 pass, exit 0 (scratch/after/vitest.txt). `tsc --noEmit` exit 0. dist rebuilt with `npm run build`, exit 0.
- Writer run: the five 082 research children 014-018 were saved through `generate-context.js --full-auto --json` with continuity fields taken from each `research/research.md` (its answer, its stop state, its fix backlog section) and `research/deep-research-state.jsonl`. All five exit 0, none logged "Continuity not written" (scratch/after/save-runs.txt). The scaffold strings appear in 5 blocks before and 0 after (scratch/before|after/research-continuity-blocks.txt). completion_pct is 80 for 014 (manual stop, key question 2 open) and 90 for 015-018 (open questions stay in each research.md section 12, not in the block, since the block only takes question ids).
- Validation: `validate.sh specs/cli-external-orchestration/082-opencode-v1-v2-dual-compat --recursive --strict` gave 19 of 19 RESULT: PASSED.
- Out of scope: deriving continuity automatically inside the writer from research.md; the save contract has the caller compose the payload, so the payload was composed from research.md and the state log instead.
- Unchanged behavior the fix keeps: `writePlannedContinuity` re-reads the host and rebuilds the merge under the leaf's own canonical-save lock when the leaf is not the save target (`acquireCanonicalSaveLock(plan.leafPath)`, `.skilled/skills/system-spec-kit/runtime/cli/core/workflow.ts:609`), so a save that reached the leaf through its parent cannot interleave with one aimed at the leaf; the save-continuity-write suite's parent-routed cases still pass (scratch/after/vitest.txt).
