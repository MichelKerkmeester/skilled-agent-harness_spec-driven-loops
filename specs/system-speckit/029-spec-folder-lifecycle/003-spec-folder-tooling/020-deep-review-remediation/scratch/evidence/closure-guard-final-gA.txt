Extra 1. The four round-trip cases in describe archive.sh round trip with the real tools.

Diagnosis. The cause is the scratch mirror, not the repository. The earlier failures appear in gs/mut/control-cli-2.txt, which shows 4 failed of 58. Each failure reads "validator unavailable (exit 3): compiled validation orchestrator is stale", and repair-derived then prints a warning, which the assertions reject. The freshness checker in runtime/cli/lib/dist-freshness.cjs names its build record after the absolute dist path, through cachePathFor. A record copied into a mirror is therefore never found. With no record the checker compares file mtimes, and the mirror copy resets every mtime, so the sources look newer than dist and the runtime is reported stale. Probes confirm this. checkPackageFreshness on the gs-built mirror gs/mirrors/gA-control returns stale. The same check on the repository returns fresh. On the mirror built by gA/mkmirror.mjs it returns fresh. The fix in gA/mkmirror.mjs copies the repository build records to the paths the mirror dist produces. It touches no skill file, and gs/ was not edited. After the fix the unmutated control passes all four cases, with 60 passed and 1 skipped. In gs/mut/A-arch-L.log and gs/mut/A-arch-e.log, four of the five failures are these round-trip cases. Only the fifth, a case outside them, counts as a kill there, and the gA runs above confirm that fifth case for each archive mutant.

Extra 2. backfill --root.

Probe 1, unanchored fixture, in the scratchpad. The unmutated gA-control tool ran backfill --all --root against a specs folder with no .opencode anchor. It exited 1 with "Refusing to write graph metadata outside a configured specs root", from graph-metadata-parser.ts:1847. The failed entry was recorded and nothing was written. The writer accepts a root only when a real .opencode directory anchors it.

Probe 2, anchored fixture outside the repository, in the scratchpad at gA/probe/anchored/.opencode/specs. The same command in apply mode, not dry-run, exited 0, reported created 1, and wrote graph-metadata.json under the fixture. The repository specs state showed 54 dirty entries before and after the probe, so the real specs tree was not touched.

Result. --root reaches a graph metadata write for any directory that carries a .opencode anchor. The INFERRED partial now has an observed basis for the graph metadata writer, and the writer's configured-root check is a real but partial control. The prune report writer has no configured-root check at all. That is read from writePruneReportArtifact at backfill-graph-metadata.ts:188-217, and it was not run as a probe, so it stays INFERRED.
