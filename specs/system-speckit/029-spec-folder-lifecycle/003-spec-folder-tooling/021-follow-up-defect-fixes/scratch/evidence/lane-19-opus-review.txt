## Findings (all P2)

**P2-1, CONFIRMED. The outside-root refusal still blames a link when a system link sits at the top of the path (D25 is incomplete).**
- Where: heal-spec-docs.cjs:1034. `hasLinkOnPath` checks every prefix, including /tmp and /var on macOS.
- Command: `node heal-spec-docs.cjs --folder /tmp/r021-wording.X/out/020-plain --roots /tmp/r021-wording.X/repo/specs` (020-plain is a plain directory).
  - Output: "refused ...: symbolic link, not followed (it resolves outside the specs root)", exit 2.
  - The same folder spelled through /private/tmp prints "refused ...: it resolves outside the specs root".
- Why the tests miss it: they build fixtures under realpath'd tmp directories.
- Fix: judge only links below the system prefix, the same way folderRefusal ignores links above the anchor. One way is to skip prefixes whose realpath equals the realpath of their own lexical parent plus name.
- Doc impact: the release-note sentence "A plain folder outside the supplied specs root now gets an outside-root message" (v4.0.0.4.md:190, v2.7.1.0.md:184) is not true for /tmp or /var spellings.

**P2-2, CONFIRMED. A linked parent directory that leaves the packet is followed.**
- Where: graph-metadata-parser.ts:522, generated-metadata-drift.ts:102 and repair-derived.cjs:283. All three test lstat on the final component only.
- Command: probe at scratchpad/review021/probe/dirlink.mts, run with the skill's tsx loader.
  - Setup: a packet whose `research` directory links outside the packet, to a research.md holding the phrase "outside secret phrase".
  - Result: deriveGraphMetadata returned `trigger_phrases ["inside phrase","outside secret phrase"]`, and computeSourceDocHashes hashed `research/research.md`.
  - Control: a file link at research/research.md was correctly refused.
- repair-derived's guard uses the same final-component test, so it would also let the child run. That part is inferred from the code and not run.
- No live packet under specs/ has such a link (`find specs -type l`).
- Fix: apply the realpath containment check to every existing input, whether or not its last component is a link.

**P2-3, CONFIRMED. archive.sh skips the below-specs walk for an absolute argument that spells the repository another way.**
- Where: archive.sh:121 compares the text against "$PROJECT_ROOT/specs". PROJECT_ROOT is the physical path from git.
- Command: `ln -s $REPO /tmp/r021-archlink`, then `archive.sh --force /tmp/r021-archlink/specs/tools-alias/001-a`, where tools-alias links to tools.
  - Result: "SUCCESS: Archived", exit 0.
- No link is left dangling, because a final-component link is still caught by `-L "$argument"`. But D2's rule, "a component below specs is a link", is not enforced for that spelling.
- Fix: walk the argument's prefixes, find the one whose `pwd -P` equals specs_root, and check `-L` on each component after it.

**P2-4, CONFIRMED. The restore refusal tells the user to archive.**
- Where: archive.sh:145. `--restore specs/tools-alias/z_archive/002-b` prints "ERROR: Archive the real folder instead: .../specs/tools/z_archive/002-b".
- Fix: pass the action verb into refuse_linked_argument.

**P2-5, CONFIRMED by reading. The release notes name the wrong file for the upgrade-legacy link refusal.**
- Where: v4.0.0.4.md:204 and v2.7.1.0.md:198 say "`upgrade-legacy` rejects a linked `upgrade-baseline.json` ... with exit 2".
- What the code does: this phase added the refusal for the reversibility manifest `<git-dir>/upgrade-legacy.manifest.json` (upgrade-legacy.mjs:468, path from manifestPathFor at :425). The baseline link handling predates this phase and is already described at v4.0.0.4.md:146.
- Fix: name the reversibility manifest.

**P2-6, CONFIRMED. The rollup lets a stored complete survive a child with no metadata.**
- Trigger: the only loaded child is neither in_progress nor complete, for example planned.
- Where: graph-metadata-parser.ts:1461-1468. When neither branch fires, status keeps derivedStatus, which falls back to the stored status.
- Command: probe at scratchpad/review021/probe/rollup.mts. Child 001 has metadata with status planned, child 002 has none, the stored parent status is complete. Result: complete.
- The narrower D5 rule ("missing counts as not complete") is no worse here than a planned child, and the planned-child case predates this phase. REQ-012 says more: "derives complete only when ... every child has loadable metadata with status complete".
- Fix: when not every child is loaded and complete, never return complete. Use in_progress, or the non-complete stored status.

**P2-7, doc wording.**
- Where: heal-spec-docs-lane-modes.md:38 says the CLI "stops with exit 2 on any other argument" than --folder, --roots and --apply.
- Problem: `--lane-modes` and `--anchor-repair` are accepted, and the next sentence says so.
- Fix: say "any argument outside these and the mode flags".
