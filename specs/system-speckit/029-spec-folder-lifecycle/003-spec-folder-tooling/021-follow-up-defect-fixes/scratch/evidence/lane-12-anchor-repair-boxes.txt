1. outside-root: "a packet outside the named specs root is refused and left byte-identical"
   Runs repairAnchors on a repairable document, then runs --anchor-repair with --roots set to a specs root that does not hold the packet, in the dry run and the apply run. Expects exit 2, stdout containing "refused <packet>" and "it resolves outside the specs root", the packet bytes unchanged and the manifest of the packet's root unchanged.
   Implementation: new optional case field outsideRoot and a helper expectRefusedOutsideRoot. The field is the only change to the table shape.

2. fallback: "fallback: a glued duplicate that does not overlap its neighbor is renamed, not removed"
   Meaning chosen: the removal rule (glued AND overlapping) is the preferred repair. When a glued duplicate does not overlap its neighbor, the repair falls back to the isolated rename in repairDuplicateAnchors. The row expects action "renamed isolated duplicate pair metadata to metadata-2" and the marker names changed, with no marker removed.
   Alternatives not chosen, with reasons:
   - The default-roots fallback in folderRefusal (no --roots given, UNREACHED_REFUSAL). That path needs a CLI run without --roots, and the table is text-level, so it would need a second new mechanism.
   - The "falls back to live" wording in heal-lane-modes.vitest.ts (015 precedent). That is an archive-placement rule, not an anchor-repair path.
