# deepseek-v4-pro-max — iteration 2: Traced the full workspaceRoot → generation-counter path: the advisor resolves state relative to cwd, not the repo root, and auto-creates .opencode/skills/.advisor-state/ inside whatever directory the hook fires from.

## Findings
- ROOT CAUSE — workspaceRoot = cwd, not repo root: user-prompt-submit.ts:138-142 `workspaceRootFor(input)` returns `input.cwd ?? process.cwd()`. When a Claude Code / OpenCode session runs from inside a specs/ subdirectory, cwd points there. This is the entry point of the entire leak chain.
- CRITICAL RESOLVER — hardcoded relative path joined to workspaceRoot: freshness/generation.ts:12 defines `GENERATION_RELATIVE_PATH = join('.opencode', 'skills', '.advisor-state', 'skill-graph-generation.json')`. Line 29-31 `getSkillGraphGenerationPath(workspaceRoot)` = `join(resolve(workspaceRoot), GENERATION_RELATIVE_PATH)`. This blindly joins the hardcoded path to whatever workspaceRoot it receives — no repo-root walk-up, no canonicalization.
- DIRECTORY AUTO-CREATION on write: generation.ts:109-110 `writeGenerationAtomic` calls `mkdirSync(dirname(filePath), { recursive: true })`. Same pattern in freshness/generation.ts:46 `writeJsonAtomic`. Any write to the generation counter creates the full .opencode/skills/.advisor-state/ tree under workspaceRoot.
- FIRST-TIME TRIGGER: generation.ts:184-198 `readAdvisorGeneration` — when the file is absent (ENOENT, which is always true when workspaceRoot is inside specs/ since specs/ dirs don't have a .opencode/skills/ tree), it calls `setGeneration(workspaceRoot, filePath, 0)`. This writes generation=0 with reason='LEGACY_ADVISOR_GENERATION_BUMP', creating the nested dirs. Confirmed: all 3 leaked generation.json files in specs/ show exactly this payload.
- FULL CALL CHAIN: buildSkillAdvisorBrief (skill-advisor-brief.ts:401) → getAdvisorFreshness(workspaceRoot) (freshness.ts:330) → readAdvisorGeneration(workspaceRoot) (generation.ts:184) → getAdvisorGenerationPath(workspaceRoot) (generation.ts:179) → getSkillGraphGenerationPath(resolve(workspaceRoot)) (freshness/generation.ts:29) → join(workspaceRoot, '.opencode/skills/.advisor-state/skill-graph-generation.json'). Every hop passes workspaceRoot through unchanged.
- EXISTING FIX PATTERN ALREADY IN CODEBASE: skill-advisor-cli-fallback.ts:176-198 `findCliFallbackPaths(workspaceRoot)` walks UP from workspaceRoot (up to 14 levels) looking for `.opencode/bin/skill-advisor.cjs` to find the real repo root. This pattern should be replicated for the generation-counter resolver instead of trusting the raw workspaceRoot.
- SUBPROCESS ALSO USES workspaceRoot AS cwd: subprocess.ts:310 spawns the Python advisor with `cwd: options.workspaceRoot`. While the Python script resolves its own REPO_ROOT from its file location (skill_advisor.py:43-45), any relative path operations inside the Python process would also resolve against the wrong base.
- METRICS MODULE USES /tmp CORRECTLY: metrics.ts:178 stores diagnostics at `join(tmpdir(), 'speckit-skill-advisor-metrics')` — this is the correct pattern. The generation counter should similarly use an absolute, repo-root-anchored path.
- DIRECTIVE LIFECYCLE STORE ALSO USES /tmp BY DEFAULT: directive-lifecycle-file-store.ts:46-48 defaults to `join(tmpdir(), 'speckit-advisor')` unless overridden by `SPECKIT_DIRECTIVE_LIFECYCLE_STATE_DIR` env var. This path is safe.

## Answered
- Where exactly does the advisor resolve its state directory? → freshness/generation.ts:29-31 `getSkillGraphGenerationPath(workspaceRoot)` joins `.opencode/skills/.advisor-state/skill-graph-generation.json` to the raw workspaceRoot.
- Why can this resolve inside specs/ instead of the repo root? → user-prompt-submit.ts:138-142 passes `cwd` or `process.cwd()` as workspaceRoot; if the session runs from a specs/ subdirectory, the entire chain inherits that wrong root.
- What creates the actual directories on disk? → generation.ts:109-110 `mkdirSync(dirname(filePath), { recursive: true })` in `writeGenerationAtomic`, triggered when `readAdvisorGeneration` hits ENOENT (generation.ts:194-195).
