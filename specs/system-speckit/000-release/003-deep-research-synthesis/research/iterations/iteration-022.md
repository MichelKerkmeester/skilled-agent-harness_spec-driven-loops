#### Nested MCP server READMEs resynced to real tool sets
The nested reference READMEs inside the skill-advisor and code-graph MCP servers now list the full tool sets their code actually registers, after a QA cross-check found the rewritten top-level docs had outpaced the subpages. Before, the tools page named four skill-graph tools, the handlers page documented only the advisor handlers with no `skill-graph/` subdirectory, and the code-graph entrypoints table ran seven rows, missing `code_graph_classify_query_intent`. After, the fifth tool `skill_graph_propagate_enhances` appears in the overview, key-files, and entrypoints tables with its trusted-caller gate, the handler subdirectory is documented, and the missing entrypoint is added. A framework user now gets an accurate answer to "what can I call here" from the skill docs instead of having to diff them against source. This is internal documentation-only; no runtime behavior or tool surfaces changed.

#### Unified install-and-doctor surface across all mcp skills
The five mcp-* skills now share one install-and-diagnose surface, replacing a patchwork where each skill handled setup and troubleshooting its own way. Before, mcp-figma was pre-1.0, mcp-open-design had no install guide or scripts, and the chrome-devtools and click-up skills shipped an installer but no diagnostic. After, every skill carries an INSTALL_GUIDE.md, a verify-only `install.sh`, and a read-only `doctor.sh`; the central `/doctor:mcp` command knows all of them through a new `cli_skill_diagnostics:` class kept separate from server installs; and the three design skills cross-reference each other in prose and in the skill graph. mcp-figma graduated to 1.0.0.0 with live verification and an embedded install scaffold, and mcp-open-design gained three scripts that detect the CLI bundled inside its desktop app without wiring anything. For a framework user, setup and troubleshooting are now consistent across the family, and diagnostics report app, CLI, and config state without modifying it. **Breaking:** mcp-figma moves to 1.0.0.0 — anything pinned to its pre-1.0 line should adopt the new stable surface and re-read the rewritten changelog.

#### sk-code re-architected as a two-axis parent hub
sk-code was converted from a single flat skill into a two-axis parent hub: five workflow modes — implement, quality, debug, verify, and review — hold the action contracts, while read-only surface packets for webflow, opencode, and animation hold the environment evidence the router bundles with the selected workflow. The conversion shipped across ~19 verified phases: a research-driven five-mode taxonomy, a routing-only hub scaffold at version 4.0.0.0, 128 files relocated into shared/ and mode packets with history preserved, the standalone sk-code-review package folded into the review mode, and four mode contracts authored from the recovered pre-hub doctrine. The moves broke external references, so a ground-truth sweep repointed them — restoring a pre-commit comment-hygiene gate that had been silently skipping — and a deterministic routing benchmark climbed from 44 to 71 after harness corrections. Along the way the release fixed a 29-path content-drift in the routing resource map, a bare "review" keyword that could misroute a genuine review task, and a plugin that was painting stale-build warnings over the chat input. For a framework user, code work now routes to focused, independently invokable contracts with correct evidence bundling; the legacy sk-code-review trigger-phrase alias is retained temporarily. **Breaking:** the standalone sk-code-review skill is folded into sk-code as its review mode — anything invoking it directly must route through the sk-code hub instead.
