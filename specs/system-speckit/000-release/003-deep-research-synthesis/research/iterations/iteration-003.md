#### External CLI hub consolidated under canonical path
The external CLI dispatch hub was renamed in place, making `.opencode/skills/cli-external-orchestration/` the single canonical home for all CLI-executor modes while preserving repository history via `git mv`. Advisor routing, live references, and consumer registries were swept to point at the new hub identity, while concrete executor references such as `cli-opencode` kept their name where the semantics called for it. For users, the change is invisible at the command level: routing behavior is unchanged, only the directory identity and internal pointers were reconciled. This is internal tooling reorganization; targeted rename checks pass, while full validation closeout remains blocked by a stale compiled distribution and unrelated graph prerequisites outside this change's control.

#### Devin CLI revived as fifth dispatch mode
The Devin CLI, previously deprecated, is back as a first-class dispatcher: a new `cli-devin` mode under the external CLI hub and a fifth deep-loop executor kind. The revival pinned the live contract for `devin` v3000.2.17, added a full skill packet (references, prompt templates, prompt-quality card), built ten hook adapters covering seven lifecycle events, and shipped a 20-scenario manual-testing playbook (19 pass, one intentional skip). Devin's hooks were live-verified end to end after correcting the registration schema, and a fail-closed guard keeps the mode unroutable when the `devin` binary is missing, matching the Codex precedent. All 13 repository agents are mirrored into `.devin/agents/` so Devin can dispatch the same roster, and a permission-request handler enforces write-target and dispatch rules with a fail-closed policy. **Breaking:** revives a mode the framework previously removed; projects that stripped Devin wiring under the old deprecation will now find the mode present again.

#### Cursor CLI added as fourth dispatch mode
Cursor becomes a full first-class dispatch target: a new `cli-cursor` mode in the external CLI hub and a fourth deep-loop executor kind, built from a live-verified contract for the `cursor-agent` CLI (2026.07.23-e383d2b). The delivery includes a skill packet with Cursor-specific references, hook adapters proven live (with the notable finding that `beforeSubmitPrompt` and `stop` never fire under CLI dispatch while `preToolUse` reliably does), a Composer-2.5 prompt-craft profile in the model registry, a 19-scenario manual-testing playbook, and all 13 repository agents mirrored into `.cursor/agents/`. Dispatch fails closed when the `cursor-agent` binary is absent or unauthenticated, and since the CLI exits 0 even on auth errors, the guard keys on binary presence and auth state rather than exit codes. Project-level `.cursor/hooks.json` registration was intentionally left uncommitted pending operator choice.
