#### Goal-hook playbooks and live cross-runtime validation
The goal hook that shipped in packet 003 had no manual-testing-playbook coverage and no live proof its injection reached the model turn; this packet closes both gaps. Five goal-hook scenarios are now named, one per goal-capable CLI runtime (Devin, Cursor, Pi, OpenCode, Claude Code), each under its own id prefix, plus a sixth playbook for the shared goal-manage CLI. Live validation used one proof method: seed an active-goal state with a unique canary token, run the CLI, and grep the raw transcript for the canary and the `[active_goal]` marker. Pi and Devin pass with the canary quoted verbatim by the model; Cursor lands in the RECORDED-EVIDENCE tier — its hook fires, but its injection channel is confirmed non-delivering by contract, so the absent canary is correct behavior, not a failure; OpenCode's native mk-goal and Claude-native `/goal` could not be validated headless at all, a structural limitation, not a regression. Every run used an isolated goal-state directory so no validation could touch real state. Largely internal — users see no behavior change, but every goal-capable runtime now carries a playbook and an evidence-backed verdict.

#### PI input-hook latency cut with in-process advisor
The Pi input hook no longer blocks message sends on a synchronous multi-process spawn chain; it now calls the advisor lifecycle in-process, the same code claude/codex/cursor run as a subprocess, removing every process hop from Pi's hot path. A shared cache-invalidation defect was fixed along the way: the 5-minute cache stored labels that could never match the skill-fingerprint map, so it reported a false "deleted skill" on every lookup and never hit — it now stores only graph-backed labels, which is what lets repeat prompts resolve in ~1 ms. The build no longer compiles the pi hook files (Pi loads them directly at runtime), so `npm run build` exits clean instead of emitting type errors. Measured effect: ~1.37–1.49 s per message before → ~1.3 s cold / 1–2 ms repeat after, with the residual ~1.3 s cold tail owned by the advisor's own Python subprocess, unchanged. Injected directive content also became model-agnostic and labeled, with no model-family name in the capsule. Internal performance change — faster, non-blocking message sends on Pi is the user-visible win.

#### Spec-gate question noise quieted on read-only turns
The shared gate classifier no longer re-asks the SPEC FOLDER QUESTION on read-only turns. Previously any non-write turn re-surfaced the question, cascading into repeated prompts on pure read-only sessions — Pi was hit worst, because an injected advisor capsule containing trigger words could open the gate on every message. Now, while the gate is open, read-only non-answer turns keep enforcement intact but return no question, and a new `isAnswerAttempt()` check re-surfaces it only when a turn genuinely looks like an answer that failed to bind. Question text now matches the binding grammar: reply with the folder path, letter E is the skip choice, and a pathless D re-asks instead of silently closing the gate. The Pi adapter was hardened to strip embedded history and the sibling-injected capsule before classification, and both Pi adapters key state on a stable session identity. Internal tooling — the user-visible effect is less noise, with write-time enforcement unchanged.
