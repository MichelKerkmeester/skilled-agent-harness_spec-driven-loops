#### Merge web and full-stack skills into single sk-code
The two legacy code skills (sk-code-web and sk-code-full-stack) were consolidated into one umbrella skill, sk-code. Before, code prompts were split across two skills with an advisor tie-break; after, a single router detects the active stack first (Webflow markers, then Go modules, Swift package files, Expo config, Next config, React, Node, unknown) and only then classifies intent across twelve categories, so words like "test" or "build" mean the right thing per stack. Non-web stacks (React, Node.js, Go, Swift, React Native) surface lightweight placeholder pointers that direct users to canonical content preserved in the old full-stack skill, while shared guidance (error recovery, quality standards, style, multi-agent research) moved into a tightly scoped universal namespace — browser-coupled debugging and verification guides deliberately stayed behind the Webflow route. Advisor scoring, boost tables, and graph metadata were retargeted so every code prompt routes to the umbrella, and the two legacy skills remain on disk with only a deprecated marker plus a zero advisor weight. Narrative-only updates (sister skill cross-references, agent definitions, READMEs) are deferred, and the web smoke test plus the full validation suite still need to run before completion is claimed.

#### Scaffold Next.js and Go stacks under sk-code
The sk-code router went from one live stack to three: Webflow keeps its full live references, while Next.js and Go are now scaffolded as project-agnostic stubs the router can resolve. Forty-three stub files (23 Next.js, 20 Go) were generated under a strict template — status: stub, populated: false, outline-only markdown with no fenced code, and comment-only code files with no function bodies — so future teams fill in real content without inheriting fabricated examples. The naming was reconciled to references/nextjs/ (a brief detour through react/ was corrected), and a canonical Next.js ↔ Go contract covering API/auth pairing, error envelopes, and JWT handoff lives in references/router/cross_stack_pairing.md, ready to surface when API or auth intents fire. Four carry-over files that falsely claimed to be populated and used project-specific phrasing were rewritten as honest stubs, and the kerkmeester keyword was scrubbed everywhere to keep the skill project-agnostic. The smart-routing section was rewritten to match sk-doc's canonical pattern and all reference docs restructured (numbered sections, OVERVIEW first, RELATED RESOURCES last), bumping the skill to version 1.3.0. **Breaking:** anything pointing at the superseded react/ naming or the absorbed 057 placeholder packet now resolves to references/nextjs/ and this merged packet.

#### Fold OpenCode standards into sk-code surfaces
The standalone sk-code-opencode skill was merged into the umbrella sk-code as its OPENCODE surface, so one skill now covers both Webflow frontend work and .opencode/ system-code standards. Single-axis stack detection was replaced with two-axis context-aware detection: a code-surface gate from the current directory plus changed files (Webflow vs OpenCode vs unknown), then intent classification, then per-surface resource loading with the old skill's language sub-detection (JS/TS/Python/Shell/Config) preserved as second-level routing. OpenCode standards moved into sk-code's references/opencode and assets/opencode folders, the alignment verifier relocated to scripts/, and the Go/Next.js placeholder branches plus cross_stack_pairing.md were removed. Advisor scoring, tests, fixtures, telemetry, review/CLI docs, agents, and install guides were all retargeted to the single-skill model, and the obsolete .opencode/skills/sk-code-opencode directory was deleted once live references were confirmed clean. **Breaking:** the standalone sk-code-opencode skill no longer exists — work that previously loaded it now routes through sk-code's OPENCODE surface, and the Go/Next.js placeholder routes were removed.
