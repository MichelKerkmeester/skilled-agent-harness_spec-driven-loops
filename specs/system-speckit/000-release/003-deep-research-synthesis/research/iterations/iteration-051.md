#### Canonical commit-message standard defined and validated
OpenCode Spec-Kit now has a locked, repo-wide commit-message standard, produced by the commit-standards phase of a larger retroactive-rewrite effort. Seven decision records fix the full shape: a 13-type subject taxonomy with five scope shapes, packet-ID prefix handling that strips the subject but keeps the trailer, normalized `Co-Authored-By` formatting that preserves attribution, original tense preserved in retroactive edits, a body policy that never auto-authors content, acceptance of both git-default and authored forms for special cases, and length caps (72 hard, 50 soft, wrap at 72). The standard was validated against 20 random HEAD commits and produced deterministic rewrites for 20/20 with zero cases needing human review. Only the standards-definition phase shipped this cycle — the follow-on phases that embed the standard into the sk-git skill and rewrite the 2,795 HEAD commits were still pending when this entry was written.

#### sk-git hardened for large rename and reorg workflows
The git skill gained concrete guidance and a runbook for big rename-plus-worktree operations, closing the five failure modes hit when a 17-phase reorg renamed roughly 9,000 files. Worktree caveats now warn that `git mv` leaves gitignored files behind on disk, that fresh worktrees lack gitignored build dependencies, and that the memory and vector databases are a single global instance shared across worktrees, with a detection one-liner to confirm a leftover directory is safe to delete. Commit guidance now forbids broad `git add -A` on a dirty tree and ships a pre-commit deny-pattern assertion plus a `git reset --mixed` recovery path, while merge guidance verifies rename-heavy merges via disjoint changed-file lists, raised rename limits, and `git ls-files` tree checks. A new step-ordered reorg playbook leads with a `cp -a` snapshot of the database directory, which is gitignored and therefore the only rollback path. This is documentation-only hardening with no changed behavior, so nothing breaks; operators apply the one-liners and assertions by hand.

#### Worktree convention and advisor routing planned
This entry is internal tooling and ships nothing user-visible yet — the folder is a pre-implementation scaffold, so no sk-git behavior changed in this cycle. The plan is a numbered feature-worktree convention moving to `wt/{NNNN}-name` branches in `.worktrees/{NNNN}-name` directories, with numbers allocated as the previous maximum plus one, documented across four sk-git docs and a checklist. Advisor routing would then add the new worktree vocabulary to sk-git's trigger phrases, reduce overlap with the spec-kit and code skills, and rebuild the advisor index so git and worktree intent reliably lands on sk-git. The wrapper lane stays out of the convention to keep the shared worktree-session lane stable and auto-reaped, and two in-flight worktrees were deliberately deferred to avoid racing live dispatches.
