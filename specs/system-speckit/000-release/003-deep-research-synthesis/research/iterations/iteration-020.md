#### MCP tooling docs aligned to canonical templates
The asIDE DevTools, Refero, and Mobbin documentation now follows the repository's standard skill and README structures, and every automated compliance check passes with no blocking findings. Eleven asset and reference documents gained the overview sections that previously made them hard to navigate, and the three script guides were fully rebuilt with architecture, entry points, and validation sections; their documentation quality score rose from about 52 to 76. The Mobbin guidance was reconciled against a live-discovery fixture: the three confirmed tools for searching screens, flows, and sections are now documented as real, while authenticated sign-in behavior stays honestly labeled as unverified. Framework users get predictable navigation across all three integrations instead of inconsistent layouts. The only remaining advisories are filename style choices, intentionally accepted under an active naming pilot.

#### Obsidian CLI + MCP tooling mode added
A new Obsidian workflow mode joined the MCP tooling hub, mirroring the ClickUp integration by supporting both a headless command-line interface and an MCP server. The mode ships with a current-state feature catalog that separates vault and file operations across the headless CLI, the official app-backed CLI, and the MCP tools, without inventing command names or signatures. Community-plugin references were deepened for the Beancount finance ledger, tables, and BRAT plugins, with routing that prefers a specific plugin intent over the generic one. The included manual testing playbook was validated against a live throwaway vault: eight headless CLI scenarios passed seven of eight, all six MCP round-trip scenarios passed, and the environment was provisioned end-to-end with a seeded Local REST API. Validation surfaced two real-world corrections — the headless title search is broken and should switch to the working body search, and the documented MCP tool catalog targets a different server than the one actually installed — both left as documented findings rather than applied to shipped files.

#### CocoIndex semantic code search across all CLIs
Semantic code search was added to OpenCode as a fourth MCP server, giving every AI assistant a search tool that finds code by concept rather than exact identifier. CocoIndex Code was installed with a repo-local environment and registered in all six CLI configuration files, so Claude Code, Codex, Gemini, Copilot, and the other runtimes share one index; the embedding model runs locally with no API key and no code leaving the machine. An initial index covered 6,792 files across 14 languages in about five minutes. The surrounding tooling was hardened with a read-only health check, an idempotent setup helper, and stable failure codes, and a cross-CLI test showed models pick the semantic search tool automatically from its description alone. Testing also revealed a concurrency bug in the upstream daemon that errors when refresh and concurrent queries overlap, and short natural-language queries outperform keyword-stuffed ones, so follow-up-query guidance now steers users to the reliable form. This is internal framework tooling: the user-visible effect is that assistants now answer intent-based code questions directly instead of falling back to exact-match search.
