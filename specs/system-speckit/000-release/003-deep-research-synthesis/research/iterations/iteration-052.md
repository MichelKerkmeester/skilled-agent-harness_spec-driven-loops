#### sk-prompt becomes a two-mode parent hub
`sk-prompt` is now a single two-mode parent hub instead of two separate skills. The standalone `sk-prompt-models` skill was folded in as a `prompt-models` mode in one atomic 2,616-file move, the old `/prompt` command became `/prompt-improve`, and the prompt-improvement engine relocated into a `prompt-improve` packet with full git history intact across all 47 content files. The hub passes strict parent-hub checks with zero warnings, becoming the fifth canon-clean hub beside sk-code, sk-design, sk-doc, and system-deep-loop, and a deterministic router benchmark scores routing 100/100 across both modes — confirming the `prompt-models` mode keeps its metadata-based routing with no special carve-out. The benchmark also surfaced two real bugs during the fold, one in the hub's own router weighting and one in shared benchmark tooling, both fixed. In a follow-up, `/prompt:improve` shrank from a 28KB monolith into a thin router with a dispatch-context check and separate auto, confirm, and presentation assets. **Breaking:** the `sk-prompt-models` skill path and the `/prompt` command are gone; migrate references to `sk-prompt/prompt-models` and `/prompt-improve`.

#### Prompt improver system becomes an OpenCode skill
The standalone Prompt Improver system (~250KB across 7+ documents) became the OpenCode-native `sk-improve-prompt` skill, reachable through the skill advisor at 0.95 confidence. The skill uses a lean 2,334-word SKILL.md orchestrator that classifies requests into six intents and routes to one of eight reference files (307KB total) adapted from the original knowledge base, covering prompt frameworks, DEPTH methodology, visual/image/video modes, and consolidated format guides. Delivery used parallel agent dispatch across two sessions, and verification confirmed frontmatter, sections, rules, reference files, and advisor routing. This packet is archived, so it records the original creation only: a later audit found just 2 of the 8 reference files actually present on disk, and the skill was subsequently refactored and renamed.

#### sk-improve-prompt renamed to sk-prompt repo-wide
`sk-improve-prompt` was renamed to `sk-prompt` across the entire repo — ~200 references in 58 active files spanning the skill folder, OpenCode internals, runtime mirrors for Claude/Codex/Gemini, root docs, and configs. Work ran in six phases, starting with a discovery impact map that produced a canonical inventory and edge-case ledger, then rotating references phase by phase, and closing with verification: five advisor probe prompts all return `sk-prompt` as top-1, strict validation passes for the parent and all six children, and a final grep finds zero old-name hits in active scope. The agent name `@improve-prompt` and command `/prompt` were deliberately unchanged, so no user-facing invocation changed — only the loaded skill name. Two expected residuals (a symlink and auto-regenerated metadata files) are documented. This packet is archived; it is the origin of the `sk-prompt` identity that later became a parent hub.
