#### Pi dispatch defaults to native subagents

Pi now dispatches subagent work through its native subagent plugin by default instead of external cli-* executors. A per-turn directive injected into every Pi prompt mandates native subagents unless you explicitly request a specific cli-* skill mode. A preflight check enforces the directive: dispatch-shaped calls are denied unless they carry an explicit cli-* authorization or run inside an approved deep-loop executor, while native subagent tools are unaffected. The enforcement only allows executors it can prove from the raw command — quotes, escapes, and separators are parsed, and variables, aliases, substitutions, or malformed input can never become an allow. The skill-advisor governor capsule also renders identically across the native path and both bridge fallback branches, and AGENTS.md documents Pi's runtime directory. This is internal hook tooling, but the visible result is predictable: Pi's default is native subagents, with cli-* modes available on explicit request.

#### DeepSeek caching split across two Pi extensions

The Reasonix-style prompt-caching proposal was researched across multiple independent model lineages and rejected: the headline numbers were unreproducible, and the narrow scope that survived scrutiny already shipped as the existing pi-cache-optimizer extension. Ownership was instead split across two extensions. pi-cache-optimizer gained a narrow guard on all six of its model-specific hooks so it no longer touches DeepSeek's direct API — it matches only the two DeepSeek models by exact id and provider — and the patched fork is vendored inside the repo with no external dependency. The complementary deep-pi extension now owns exactly those two DeepSeek models, pinned and integrity-verified against its published commit and likewise vendored in-repo. deep-pi was also fixed and hardened: silent diagnostic counters now surface and reset per session, an unrecognized DeepSeek model id triggers a one-time warning instead of a crash, cost math is validated before the totals it protects, persistent per-session and daily stats are written to a JSON file, and reports are available as machine-readable JSON as well as a UI notification. A live composition test proved zero overlap — including a mid-conversation model switch — and a 4-model research pass produced a prioritized fix plan covering correctness, observability, and maintainability for both forks.

#### Goals now isolated per runtime session

Goals are now scoped per runtime and session instead of living in one shared global record. The goal core stores one active goal per workspace, runtime, and session triple — identities are hashed into opaque filenames, same-scope updates are serialized across processes, and archived data stays contained under the state root. Pi gained native bindings via its session manager and a /goal-pi command, Cursor injects using its session id, and Devin goal support was removed; OpenCode's persistence was hardened with fixed-length keys and lazy, identity-checked migration of older records. Reads never fall back to the old global goal, and legacy state no longer auto-injects — it is diagnostic-only and must be explicitly bound to a validated scope or archived. This is internal hook tooling; the change is verified (per-runtime registration confirmed across Pi, Cursor, and Devin), with the final delivery still pending at authoring time. **Breaking:** existing legacy goal state must be explicitly migrated or archived; it no longer surfaces automatically.
