#### Documented the maintainer-flags content filter
Added a reference document explaining the `maintainer-flags` content filter that previously shipped with no explanation. It maps the four files the filter rewrites and the five keys it transforms, and makes explicit why the on-disk form deliberately differs from the committed form — so operators stop concluding something is broken. It also lists the commands that show the committed form, and leads with the filter's intent before the mechanics. Verified the advisory fires on all four mapped files. This is a documentation-only change; filter behavior is untouched. **Breaking:** none.

#### Git subprocesses scrub poisoned environment variables
Hardened every write-capable git helper to strip repository- and config-redirecting `GIT_*` variables from its git subprocesses, closing the vector where a poisoned parent environment corrupted the shared worktree `.git/config`. Git honors variables like `GIT_DIR` and `GIT_WORK_TREE` over `-C`/`cwd`, so an "isolated" config write could land in the real repository; the fix scrubs a fixed denylist of those redirectors while preserving benign variables such as author dates and `PATH`. The fix started on three helpers and was extended repo-wide to all twelve in the class, including the production rename tool, test fixtures in Python and JS, and shell hook tests. Regression tests cover poisoned-env cases, with two suites carrying pre-existing unrelated failures that reproduce at the previous revision. This is internal tooling hardening with no user-visible behavior change. **Breaking:** none.

#### Guard blocks mass file deletions in commits
Added a fail-open git-hook guard that refuses commits — and, where wired, pushes — removing an unusually large number of tracked files unless the operator authorizes that one operation. It is defense-in-depth against the stale-tree snapshot that erased 902 tracked files, and against runaway-agent mass deletions. The threshold is configurable via `SPECKIT_MASS_DELETION_THRESHOLD` (default 100), a one-shot authorization exists via `SPECKIT_ALLOW_MASS_DELETION=1`, and blocked operations are written to an audit log. The commit guard is live on this repo; the push-side backstop ships ready but is dormant where `core.hooksPath` symlinks only `pre-commit`. All twelve test cases pass. **Breaking:** none, though operators running legitimate large deletions must set the authorization variable once.
