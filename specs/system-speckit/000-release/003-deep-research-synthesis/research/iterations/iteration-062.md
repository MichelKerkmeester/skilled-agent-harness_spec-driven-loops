#### Rename @improve-agent to @deep-agent-improvement
The `@improve-agent` agent was renamed to `@deep-agent-improvement` across every runtime — `.opencode`, `.claude`, `.gemini`, and `.codex` agent files, plus the `deep_start-agent-improvement-loop_{auto,confirm}.yaml` asset filenames — with ~22 internal references in the `deep-agent-improvement` skill and the public registries (`AGENTS.md`, `README.md`, agents README) migrated in the same pass. Before, the agent was a naming-family outlier; after, skill `deep-agent-improvement` ↔ agent `@deep-agent-improvement` ↔ `/deep:*` command family line up consistently, while the `/deep:start-agent-improvement-loop` slash command keeps its name (mirroring the `/prompt` family pattern). This was a pure semantic rename with no behavior change, verified by zero residual `@improve-agent` references and zero frontmatter hits in active scope. A new skill changelog `v1.5.0.0.md` documents the rename; ~189 historical references in `z_archive` stay verbatim as historical record. **Breaking:** callers referencing the agent as `@improve-agent` must migrate to `@deep-agent-improvement`.

#### deep-review auto mode resolves setup without interactive prompts
`/deep:start-review-loop:auto` can now resolve its setup phase without ever emitting the consolidated interactive question block, so autonomous dispatches no longer stall waiting for input. Setup resolves through a three-tier contract: Tier 1 binds from `$ARGUMENTS`, a `PRE-BOUND SETUP ANSWERS:` block, and defaults, then loads the auto YAML directly; Tier 2 asks a single narrow clarification only for genuinely ambiguous fields; Tier 3 fails fast with a named-missing-inputs error and a non-zero exit. The command doc now specifies the pre-bound marker schema, field precedence, malformed-block and unknown-field handling, and a per-field default-resolution table, and the existing `:confirm` consolidated question path is unchanged. Verification was intentionally dry-run only, tracing each branch rather than dispatching the full review loop. Not breaking.

#### deep-review synthesis dedup gains content-hash two-tier matching
deep-review synthesis now deduplicates findings through a two-tier content-hash matcher, so the same defect surfacing in multiple dimensions collapses into a single registry entry instead of near-duplicate rows. The primary key is a computed `content_hash` — `sha256(file_path + line_range + finding_type + normalized_description_80chars)` — with a `file:line + normalized_title` fallback that keeps every legacy JSONL state file working with no migration. When matching hashes arrive from several dimensions, synthesis merges them into one entry carrying a `dimensions: [dimA, dimB, ...]` array, and new `findingDetails[]` entries must now emit `content_hash`. Both the auto and confirm workflow YAMLs gained the new algorithm step (extract → compute hash → two-tier dedup → lifecycle → contradiction resolution → count). The broader bounded-evidence-interpolation item (H-9) is explicitly deferred to a later packet. Not breaking; records written before the change degrade gracefully through the fallback path.
