#### Deep-loop reliability overhaul for GPT-backed sessions
This release makes GPT-backed sessions run the deep-loop commands (`/deep:research`, `/deep:review`, `/deep:context`, `/deep:ai-council`) as reliably as Claude-backed ones. Two six-lineage research rounds traced GPT's failures to a shared root cause: the framework's contracts assume a model follows intent, whereas GPT executes contract letter — so self-classification gates, free-text routing, and an identity validator that could certify a nonexistent agent as valid all produced real, code-traced defects. Each is now replaced with explicit, registry-checked routing: route-proof validation rejects schema-valid wrong-mode records instead of passing them, dispatch headers name the resolved route before the prompt body, and all seven `/deep:*` command files open with a concrete dispatch-context check instead of an unanswerable self-assessment. A new plugin (`mk-deep-loop-guard`) watches every task dispatch and flags mode mismatches, configurable to warn or hard-block, and `@orchestrate` now resolves its Deep Route field straight from the mode registry. A FIX-5 host-identity feature was benchmarked and closed as unnecessary, since the agent-layer fixes already removed every trigger. **Breaking:** `ai-council` is now subagent-only; invoke it via Task dispatch through `@orchestrate` rather than `--agent ai-council`, which now falls back to the default agent.

#### `/goal` command with persistent session goals
OpenCode now mirrors Claude Code's `/goal`: you set a completion condition for the session and it stays visible in every turn until met. Goals persist per session in a durable state store with atomic writes and serialized mutations, the plugin injects a sanitized active-goal block into system context, and lifecycle tracking charges token usage and marks a goal `budget_limited` once its configured cap is reached. On idle the plugin runs a strict verifier and completes the goal only when the verdict is exactly `met`, with evidence redacted before storage and display; an optional continuation path (off by default) can dispatch further work through strict gates that cap auto-turns and wall-clock time. `/goal set` now rewrites raw input into a deterministic structured goal prompt before injection, and the Speckit plan, complete, implement, and resume commands surface a non-blocking optional session-goal line. A security pass quarantines verifier secrets, clamps the injection block, and blocks stale continuations, and a command-rename sweep settled on `goal_opencode.md` as the final command name.

#### Behavioral benchmark suite for all deep-loop modes
All five deep-loop modes — review, research, context, ai-council, and improvement — now ship durable behavioral benchmark packages with verbatim user-style scenarios, a shared D1-D5 scoring rubric, and captured Claude baselines, so you can measure whether an executor model dispatches its required sub-agents, presents results, stalls, or absorbs the leaf role. A shared zero-dependency harness ran roughly 120 scored runs across a Claude CLI baseline and GPT-5.5-fast at medium and high reasoning, with watchdog timeouts, delegation-evidence capture, and per-run transcripts. The headline finding: reasoning effort, not model ceiling, is the load-bearing variable — high-effort GPT never fabricates delegation and halts honestly where medium stalls or fakes it — but the Gate-3 documentation halt reproduces on every mode at both efforts. This is internal measurement tooling with no direct user-visible effect; the ranked remediation backlog it produced, led by the Gate-3 precedence fix, is queued for future work.
