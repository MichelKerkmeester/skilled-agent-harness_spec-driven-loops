#### ESM migration plus memory-search reliability fixes
This packet migrated the framework's core packages to native ESM: `@spec-kit/shared` and `@spec-kit/mcp-server` now publish ESM-only entrypoints with `.js` import specifiers and NodeNext compilation, while `@spec-kit/scripts` stays CommonJS but gained an interop layer that works with Node 25's `require(esm)` behavior. All four packages were aligned on Node >= 20.11.0, CommonJS globals were replaced with `import.meta` equivalents, importing the server package no longer boots it, and the migration closed at a 100 percent test pass rate with all 18 deep-review findings remediated. The same cycle repaired the memory search pipeline, which had been returning zero results for every query: scope enforcement now activates only via `SPECKIT_MEMORY_SCOPE_ENFORCEMENT=true`, and state filtering no longer compares against a `memoryState` column that does not exist, so `minState` no longer defaults to `WARM`. A repository-wide audit then rebuilt the memory index (removing 13,211 duplicate rows) and fixed bulk reindex, which went from rejecting 1,106 files to accepting all of them after false-positive validation rules were corrected and `contextType` values were migrated from decision/discovery to planning/general. Adaptive ranking now learns from shadow-evaluation results: promotion-gate passes trigger automatic threshold tuning, and those overrides are persisted in SQLite so they survive restarts. **Breaking:** `@spec-kit/shared` and `@spec-kit/mcp-server` are ESM-only and require Node >= 20.11.0.

#### Compaction context injection across every runtime
This packet built the framework's context-preservation layer, which keeps working context across conversation compaction instead of letting it vanish. Before, a compacted session resumed cold; now a two-step hook flow precomputes critical context (PreCompact) and re-injects it into the new session (SessionStart), with source-aware routing across startup, resume, clear, and compact events, plus a Stop hook that tracks tokens and auto-saves context at session end. Runtimes without hook support get the same guarantees through tool-based compaction recovery, MCP first-call auto-priming, and a `session_health` traffic-light monitor fed by four-factor session quality scoring. The Gemini CLI received its own hook suite (SessionStart, PreCompress, BeforeAgent, SessionEnd), instructions were aligned across all four runtimes with a new `@context-prime` agent for OpenCode, and reliability work added injection fencing and SHA-256 session hashing while fixing six high-priority hook bugs. The whole feature is verified by 242 automated tests across 16 files, replacing manual playbook checks.

#### Packet-local changelog generation per spec folder
Packet changelogs can now be generated instead of hand-assembled. The new `nested-changelog` script detects whether the target is a packet root or a child phase, reads the packet's `spec.md`, `implementation-summary.md`, `tasks.md`, and `checklist.md`, and writes a derived changelog into the parent packet's `changelog/` directory using a consistent naming rule (`changelog-<packet>-root.md` for roots, `changelog-<packet>-<phase-folder>.md` for phases), so phase history stays centralized. Dedicated root and phase templates now serve as the single source of truth, and `/create:changelog`, `/spec_kit:implement`, and `/spec_kit:complete` were updated so packet-aware workflows produce a changelog alongside the implementation summary. Generated quality depends on the underlying packet documents, and pre-existing historical changelogs were left untouched.
