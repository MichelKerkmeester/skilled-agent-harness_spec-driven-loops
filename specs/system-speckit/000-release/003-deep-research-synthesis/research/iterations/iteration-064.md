#### Deep-research evolution: review split and runtime truth
This archived bundle traces the full history of the deep-research loop, from the original three-layer build (the `@deep-research` agent, the `/speckit:deep-research` command, and the `sk-deep-research` skill, plus removal of the legacy `@research` alias) through successive refinement, playbook planning, and first-upgrade research packets. The review half of the loop matured separately: durable state moved from `scratch/` to a canonical `review/` packet, then a `research/` root with `review/iterations/` iterations and a review report at the packet root, and finally review was split out into its own `sk-deep-review` skill with the `/speckit:deep-review` command. Later phases gave both loops explicit packet contracts with executable helpers (`runtime-capabilities.cjs`, `reduce-state.cjs`) so lineage vocabulary, artifact names, and reducer ownership are traceable from skill entrypoint down to workflow YAML and runtime mirrors. The runtime-truth foundation then made every loop stop auditable: each stop reports a named reason from a shared taxonomy (converged, max-iterations, blocked, user-stop, error), every stop passes a legal-stop gate checking convergence, coverage, and quality together, and sessions carry explicit resume cursors so continuation is deterministic. Journals, dashboards with timing/tool/token histograms and stop-decision drill-down, and semantic convergence that combines novelty, contradiction density, and citation overlap round out the behavior — the net user gain is loop runs you can trust, pause, resume, and explain.

#### Five deep-loop skills merged into one skill
The five public deep-loop workflow skills — deep-ai-council, deep-context, deep-improvement, deep-research, and deep-review — were consolidated into a single `deep-loop-workflows` skill holding five per-mode packets on top of the frozen `deep-loop-runtime` backend, a two-skill architecture chosen after a deep-context sweep and a gpt-5.5 xhigh research run with adversarial verification. A pristine parity baseline (SHA-256 hashes of 924 files plus per-mode advisor-routing winners) was captured first and verified byte-identical after the merge, so the consolidation provably changed no behavior. Command and agent names stayed stable — only skill references moved — while the seven `/deep:*` command routers, twelve workflow YAML assets, fifteen agent-mirror files across three runtimes, and the advisor graph were repointed to the merged packet. The advisor now routes through one `deep-loop-workflows` identity plus a mode-alias/discriminator layer instead of five flat skill IDs. A follow-up built the missing `/doctor deep-loop` council-graph probe after the destructive old-skill deletion shipped, and a deep review of the trio returned CONDITIONAL PASS (zero P0). **Breaking:** the five old skill packages were deleted; references should point at `deep-loop-workflows` and its concrete modes.

#### Loop runtime hardening from external reference research
A 51-iteration deep-research run mined two vendored reference codebases — a TypeScript daemon-plus-CLI cadence runner and an observe-evaluate-improve-measure loop — into a ranked, evidence-cited 40-item improvement backlog, with every item pointing at a reference `file:line` and a target file for our own loops. The follow-up phases shipped a series of unit-tested `deep-loop-runtime` hardening changes: atomic state writes now skip the fsync-and-rename cycle when content is unchanged, carry SHA-256 integrity stamps, and gain a debounced coalescing writer; a new abortable, chunked sleep primitive enables signal-cancellable waits. Loop machinery got lifecycle taxonomy with legal-transition guards, a lock-held JSONL merge with set-union dedupe for fan-out salvage, heartbeat-hardened loop locks with single-flight acquisition, byte-offset log regions stamped on iteration records and surfaced in dashboards, fixed-rate overrun accounting that records skipped slots instead of catching up, and a convergence score-delta signal. For users this is largely internal runtime tooling, but the effect is concrete: fewer redundant disk writes, crash-safe state with integrity checks, deterministic pause and resume, and more transparent convergence decisions.
