#### GitKraken MCP integration with advisor-routed sk-git utilization
The GitKraken MCP server is now a first-class git surface: registered with Code Mode, documented inside sk-git, and routed to automatically by the skill advisor. Ground-truth research via the locally installed GitKraken CLI found the server exposes 31 tools where the README names only three, and that full inventory now lives in a dedicated integration reference with a tool-selection guide, a read/write safety carve-out, usage examples, and error handling. sk-git's router gained a GitKraken intent, keyword triggers, a new always-follow rule, and a reference-table row, while the advisor now boosts `gitkraken`- and `gitlens launchpad`-shaped requests toward sk-git. Requests mentioning GitKraken previously had no clear owner; now they land in the right skill without a detour. The skill version moved from 1.1.2.1 to 1.1.3.0.

#### Remote push now gated by explicit permission
`origin` is now curated by default: only `main`, `skilled/v*` release branches, and anything listed in a new plain-text allowlist file can be pushed without asking. Every other push — a brand-new branch or a new commit on one already up there — needs a fresh, explicit go-ahead at the moment it happens, enforced twice: a mandatory behavioral rule in sk-git and a pre-push hook that backstops agent and human pushes alike. A new `validate-remote-allowlist` command checks the allowlist directly, and the hook gate can be bypassed per-invocation with `SPECKIT_ALLOW_REMOTE_PUSH=1`, with a narrow exception for the CI autosync's live branch. Local branch and worktree creation is completely unaffected. **Breaking:** existing remote branches outside the allowlist now block on their next push — approve the push, set `SPECKIT_ALLOW_REMOTE_PUSH=1`, or add the branch pattern to the allowlist file to migrate.

#### Advisory hook surfaces sk-git rules at command time
sk-git's written git rules now reach you at the moment a git command runs: a new pre-execution advisory hook reads the rules and prints the relevant one before the command executes, closing the gap where skill docs were only surfaced through prompt routing. The 17 rules are state discriminators rather than verb matchers, so a hard reset warns only when a commit actually moves (about once in a hundred resets) instead of on the 93% of resets that merely unstage. Coverage spans six runtimes — Claude, Codex, OpenCode, Pi, Cursor, and Devin — all sharing one rule engine, and advisories are advisory-only: they never block a command. A noise audit with a control group confirms ordinary commands stay quiet (zero advisories per 25), and new docs plus seven manual-testing playbook scenarios capture deterministic traps such as a directory-scoped commit silently dropping an untracked file.
