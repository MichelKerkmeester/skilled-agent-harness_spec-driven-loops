#### Benchmark folders: one dated convention, results into reports
All 78 benchmark run folders now follow a single dated naming scheme — `<date>--<subject>--<variant>` by execution date, with `baseline/` as the only carve-out — and the validators that previously rejected the separator now enforce the grammar while still refusing dots, underscores, uppercase and the frozen anchor. A run that specifies no output location writes its machine record, rendered report, result table, failure list, grouped findings, and a source map into `<skill>/benchmark/reports/<dated-run>/`, and the index row is appended by the same code path that writes the report, so a same-day rerun takes the next free ordinal instead of overwriting its own evidence. The scaffolder now gives every new skill a `benchmark/reports/` folder with an index, and 6,401 path-shaped references across the repo (spec packets included) were repaired to the renamed folders, with old names left intact only inside historical run logs. Users get run folders that sort, validate, and self-document their results, plus evidence that cannot be silently lost. **Breaking:** the 78 run folders were renamed to the dated grammar; update anything that points at an old folder name.

#### Code-folder README standard, truth gates, orientation READMEs
The code-folder README standard is now settled, mechanically checkable, and enforced by an opt-in validator mode. The rule is shape-conditional: a folder whose immediate subdirectories number more than zero needs a fenced directory tree, a flat folder may pass with a complete inventory table, and a designated orientation file can stand in for README.md when it clears the same overview and inventory checks. Sixteen READMEs (four wave-1, twelve wave-2) were re-derived from directory listings, loader and config files, symlink targets, and implementation files so their claims match source, and two runnable gates now stop the recurring failure modes — broken path references and retyped numeric counts — by checking links and counts from each README's own directory. Four new orientation READMEs at `authored-brand`, `runtime-mirrors`, `command-bridges`, and the `sk-design/shared` parent make previously undiscoverable authored-versus-generated boundaries explicit. A manifest-driven auditor sweeps durable directories across the repo roots with a 21-class exclusion vocabulary so coverage is verifiable rather than assumed.

#### Feature-catalog validation widens to the whole fleet
Catalog validation now covers every `feature-catalog/` directory under the skills tree instead of the small slice it previously checked, closing the gap that let 92% of catalogs drift unguarded. The package validator discovers catalogs by presence, stages four known-backlog packages at warning level, and fails closed on any promoted violation so a drifting catalog can no longer pass unnoticed. It gained rules for phantom root rows, prose paths, root-heading and description parity, packet-history metadata, shipped-label consistency, and volatile measurement snapshots, each backed by paired positive and negative fixtures that also prove coverage discovery, staged exits, and deterministic output. The ClickUp root comparison is now case-insensitive, so `FEATURE-CATALOG.md` counts as a root catalog. Framework users get one gate that reports where catalogs are, what they must contain, and which violations are fatal.
