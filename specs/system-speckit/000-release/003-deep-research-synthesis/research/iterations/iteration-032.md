#### Packet documents Open Design transport mode
The Open Design transport mode shipped with intact source but no spec packet in git or memory; this release adds a Level-2 reconstruction draft that makes the source-defined contract inspectable. It records that Open Design generates while `sk-design` decides, the bundled `od` CLI and desktop-hosted daemon model, WIRE/READ/RUN routing, guarded reads and writes, the mandatory `sk-design` pairing for design work, and the gated multi-turn run from discovery form through build to `entryFile` and `previewUrl`. Before, the transport's contracts existed only inside the skill, references, scripts, and server pointer; after, they are documented as a plan with checklist and task breakdown. The packet is explicitly a reconstruction draft and claims no runtime execution, which matters to a framework user because the boundary responsibilities (guarded proxy, freshness, token handling, cross-CLI evidence) are now traceable instead of implicit. Internal documentation packet: no shipped behavior changed.

#### Packet documents sk-design hub routing layer
The sk-design hub is the public advisor-routable home for the design family, but its routing contract had no tracked spec packet; this release adds a Level-2 reconstruction draft. It records the single advisor identity, the six-mode registry (interface, foundations, motion, audit, md-generator, and the Open Design transport), the `workflowMode`/`packetKind`/`backendKind` discriminator, router policy with default and tie-break order, signal and vocabulary classes, and the transform-verb extension with interface aliases and excluded audit/foundations terms. Before, routing behavior was defined only in `SKILL.md`, `mode-registry.json`, and `hub-router.json`; after, the hub-level contract is documented without flattening child-mode logic. The packet keeps hub identity terms distinct from child-mode evidence and preserves mandatory transport pairing so tool output never substitutes for design judgment. Internal documentation packet: no shipped behavior changed.

#### Packet documents sk-design shared backbone
The sk-design family's shared contracts had no tracked packet even though their intact source defines the register, context-loading, proof, dispatch, token, procedure, script, benchmark, and feature-catalog surfaces. This release adds a Level-2 reconstruction draft covering the Brand-versus-Product register and six dials, context manifests and build bundles, proof fields and hard gates, the design proof and boundary tokens, procedure-card schema and selection, and the deterministic shared scripts with their responsibilities. It also records the benchmark baseline and after snapshots with their trace-mode and measurement-gap caveats, plus the feature catalog's context-first intake and proof cadence, so recorded evidence is never mistaken for fresh verification. Before, these boundaries were implicit in shared files; after, a user can trace which gate blocks which claim (ready, ship, audit, accessibility, release, production-ready) and who owns taste versus transport. Internal documentation packet: no shipped behavior changed.
