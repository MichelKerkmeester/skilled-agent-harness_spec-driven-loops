A documentation-only pass fixed incorrect GitHub MCP examples across the sk-git documentation set, replacing them with the verified `github.github_*` command form and clarifying when remote GitHub MCP operations are needed versus plain local git. #### Superset-style worktree model for sk-git (never shipped)
A Level 3 spec was written to realign sk-git's manual worktree workflow with Superset IDE's agent-first model, but it was never implemented — the folder ships as spec-only with no code or doc changes behind it. The proposal would have introduced centralized storage at `~/.opencode/worktrees/<project>/<branch>/`, a `.opencode/worktree.json` carrying `setup[]`/`teardown[]` lifecycle hooks with a mandatory user-confirmation security gate, a structured verify → fetch → create → copy config → setup → ready init flow, and pre-deletion safety checks for uncommitted or unpushed work. It also kept `.worktrees/` project-local storage working as a backward-compatible fallback. This entry is internal documentation; users saw no behavior change, and the work could be resumed from the spec later.
