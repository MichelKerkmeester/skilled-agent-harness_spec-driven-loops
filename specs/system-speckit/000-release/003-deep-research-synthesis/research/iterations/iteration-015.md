#### Hook reference docs relocated to their owning trees
The four hook reference documents that previously lived in one shared references folder now sit beside the code they describe: `goal-plugin.md` moved into the goal hooks concern, `injection-contract.md` into the unified hooks tree, and both skill-advisor hook docs into the advisor's own hook folder. All 34 in-tree references were repointed and the old paths fully removed, so browsing a hook concern now surfaces its own documentation. The moves preserved git history, and strict validation passes with zero errors and warnings. **Breaking:** bookmarks or external links to the old shared-folder paths no longer resolve; repoint them at the four new owner-tree locations.

#### Per-prompt injection bloat reduction program
A measurement-first program now reduces the per-prompt directive overhead that the framework's hooks inject into every model call, built in shadow so nothing changes until evidence proves a candidate safe. Before, all hook guidance was emitted unconditionally; now a shadow planner assigns every advisory block a canonical ID and delivery receipt, and each reduction candidate ships byte-for-byte inert behind its own off-by-default flag. The candidates cover bounded route lists that collapse to "+K more" plus a short digest, deduplication of repeated system-transform contributions, suppression of repeated full advisories on later turns, and a 165-byte compact Pi dispatch directive in place of the 554-byte original. The work also added fail-open activation governance — a risk matrix and per-cell rollback procedures — and closed the loop by re-running all 30 manual playbook scenarios to zero failures. The overall effort is still in progress (roughly half complete), so this release ships the measurement machinery and governance only; no suppression flag is switched on yet.

#### Cross-runtime goal hooks for Cursor and Pi
The passive session-goal system that was OpenCode-only now works across other runtimes through a runtime-neutral goal core. A single shared active-goal state file plus a manage command (set, show, history, clear, complete, pause, resume) means a goal you set in one supported CLI is honored by the others. Live capability probes fixed an honest tier per runtime: Cursor is injection-only at session start because its pre-tool hook cannot reach model context, while Pi gets full input injection, session-start restore, and observe-only turn-end verification. The dispatch audit now recognizes six CLI invocation shapes instead of two, and error-severity rules now map to blocking. Devin support was decommissioned, removing its goal adapters, registration, and commands. **Breaking:** any workflow that depended on the Devin CLI integration no longer works; migrate to Cursor or Pi.
