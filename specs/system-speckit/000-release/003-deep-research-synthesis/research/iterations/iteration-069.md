#### Semantic similarity lane activates intent-described routing
The skill advisor now scores semantic similarity between your prompt and each skill's description instead of relying only on author-stated triggers, text matches, and dependency signals. Skill descriptions are embedded into the skill-graph database through an idempotent cache (skipped when the content hash and model match), and each incoming prompt is embedded at recommendation time to produce a cosine match with `cosine:` evidence. The lane shipped live at a conservative 0.05 weight, and the four existing lanes were rebalanced so the live total is exactly 1.00 — previously the live weights summed to 1.05. Weight-sweep and corpus harnesses (a 24-prompt set plus a harder 22-prompt misroute set, and an 84-combination damping sweep) showed no configuration beat the baseline, so 0.05 stands and the experimental damping logic was reverted. The same packet unified threshold and rendering behavior across the OpenCode and Codex surfaces and added durable prompt-safe diagnostics. For a framework user the payoff is a scoring system that can match intent-described requests, tuned by real measurements rather than guesses.

#### Sharper intent routing and cross-runtime advisor briefs
Intent routing across the skill advisor was tuned end to end for accuracy. Search fusion now ignores the cross-encoder length penalty (longer skill docs no longer lose points), raises the rerank minimum from 2 to 4, and carries a dedicated continuity weighting profile plus cache telemetry. Phrase routing got its largest cleanup yet: 24 multi-word booster phrases the tokenizer was splitting apart moved to a dedicated phrase table, 15 new phrase routes were added, and a hyphenated-token bug was fixed — the headline is a five-dimension agent-scoring request that misrouted to the prompt-improvement skill at 0.77 now landing on the agent-improvement skill at 0.95, with regression held at perfect top-1. The proactive hook surface that injects a compact skill recommendation on every prompt now runs identically on Claude, Gemini, Copilot, and Codex, verified across 200 prompts with sub-millisecond cache hits and a 66.7% hit rate. Smart-router remediation also fixed five stale route resources, replaced a silent CLI fallback with an explicit unknown-route signal, and shipped a new `/doctor:skill-advisor` command for analyzing skills, tuning scoring tables, and re-indexing the skill graph.

#### Advisor hardening, Devin and Codex hooks, fail-open safety
The skill advisor was hardened for production use. The OpenCode plugin now keeps all runtime state per-instance, deduplicates concurrent identical requests so five simultaneous prompts share a single bridge call, and bounds every payload — prompts at 64KB, briefs at 2KB, and the response cache at 1000 entries with insertion-order eviction. A 200-prompt measurement harness now reports routing readiness, and a release-readiness audit found no stale-context or scoring-corruption risks. Deep-review findings were closed with a trusted-caller gate on the skill-graph re-scan tool and eight scoring-quality fixes, including routing the Codex timeout path through the shared formatter, letting suppressive dependency-conflict evidence reach scoring, and blocking token-stuffed prompts from matching many unrelated skills. Coverage now spans two more runtimes: native Codex startup and prompt hooks inject the same context surfaces as Claude, and a CLI Devin hook plus the renamed `mk-skill-advisor` plugin bring the advisor brief to Devin sessions. **Breaking:** the plugin was renamed from `spec-kit-skill-advisor` to `mk-skill-advisor` (293 references migrated); update integrations referencing the old name, though the legacy environment-variable alias is retained.
