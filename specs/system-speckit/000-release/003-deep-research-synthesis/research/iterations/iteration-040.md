#### Snippet templates migrated to per-feature scaffold
All 32 routing-gold snippet files under `manual-testing-playbook/` were migrated to the per-feature scaffold: numbered `OVERVIEW` / `SCENARIO CONTRACT` / `TEST EXECUTION` / `SOURCE FILES` / `SOURCE METADATA` sections, prose test execution replacing the old nine-column table, and `description`/`stage` frontmatter added while the dead `category`, `created`, and `expected_token_range_*` fields were dropped. A reviewable migration script drove the transform across four source shapes (18 full-old, 8 minimal, 5 minimal-purpose, 1 variant), and the 13 minimal files received sections but no invented commands or evidence, keeping their execution steps prompt-only. The snippet template itself gained the routing-gold fields it had omitted, so a corpus file can now match the template without breaking the topology gate. **Internal:** this is framework test infrastructure — no user-facing behavior changes, but the playbook files now pass package validation and the topology gate.

#### New standalone skill for communication projection
A standalone skill at `.opencode/skills/sk-communication/` gives the framework a routable entry point to the communication-projection package. Its `SKILL.md` dispatches a request to the correct package subsystem and enforces the invariants: canonical bytes stay byte-for-byte unchanged, privacy filtering runs before ranking, every runtime path declares a full-projection or safe-native tier, failures return the exact original text, and telemetry carries no content. The skill's routing metadata declares real projection domains with sibling edges to `sk-code`, `sk-design`, and `sk-doc`, and it now surfaces as the top advisor recommendation for projection intents. **Breaking:** none on its own, but the skill ships bundled with the still-unmerged communication-projection package on a feature branch, so both land on a release branch together.

#### Editorial diagram mode added to sk-doc
The sk-doc hub gained a thirteenth mode: `sk-create-diagram`, forked from an external diagram-design plugin across sixteen phases. It ships all 27 diagram types (architecture, sequence, org-chart, venn, and more) as self-contained HTML/SVG output over a shared editorial design system — connectors, primitives, icons, and an onboarding style guide — plus the source skill's second half: redrawing an existing draw.io or Mermaid diagram and exporting generated ones, driven by stdlib-only extraction scripts. A `/create:diagram` command routes generate, import, and export requests and ends every path at the taste gate; the skill is registered in the hub router, mode registry, and command metadata. The manual-testing-playbook and feature-catalog packages ship as packet-local subdirectories, all nine playbook scenarios were executed for real, and an adherence audit fixed 26 template deviations while a later AST audit closed five missing docstrings. The ASCII/markdown flowchart capability was merged in through an explicit output-format dial, with `sk-create-flowchart` first redirected then deleted outright in a later phase. **Breaking:** for users of the deprecated `sk-create-flowchart` mode — its skill and `/create:flowchart` command were removed; flowchart requests now go through `/create:diagram` with the ASCII/markdown format pre-selected.
