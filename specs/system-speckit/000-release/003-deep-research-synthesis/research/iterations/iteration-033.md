#### sk-design gains Claude-parity manager shell and procedure cards
The sk-design hub was refactored to behave more like Claude's Design workflow while preserving OpenCode-native routing, mode packets, and proof gates. It now makes an intake step, a visible plan, proof expectations, missing-proof blocking, a verifier cadence, and the separation between transport and taste explicit before any mode handoff or ready claim. Fourteen private procedure cards (one per design procedure, from discovery through design-system extraction) were added across the five modes under a shared schema, and each mode packet now carries procedure-card selection and direct-fallback guidance. The router registry was synchronized: token artifact ownership moved from the foundations mode to the design-md-generator mode, and hub-identity was dropped as interface routing evidence. Six README files were aligned to the shipped behavior, 23 manual-testing scenarios were added across the hub and modes, and feature catalogs were completed. The parity benchmark closed with a conditional verdict: router, advisor, and procedure-selection invariants pass, but live, manual, and browser-mode scenarios remain operator follow-up before a READY claim.

#### 1,290-style local design-token library extracted from Refero
A new local styles library was added under `.opencode/skills/sk-design/styles/`, one folder per Refero style following the cursor six-file template. A resumable Node harness enumerates the Refero sitemap and captures each style's four tabs through the browser debugging channel, with throttling, a last-modified resume point, and a byte-match self-test. It was piloted on 50 styles with zero errors, earning a GO, then run to completion across the full set: 1,290 styles, zero errors, all shape-validated and indexed, totaling about 129 MB across 7,744 files. Design work now has a fully offline, local reference and token source instead of round-tripping to Refero.

#### Styles library wired as grounded, non-authoritative evidence
The 1,290-style library became an active evidence system across all five sk-design modes, seeded by three research passes (8 + 5 + 6 iterations, ~48 findings) that chose a layered local retrieval pipeline over any single search substrate. A deterministic eligibility-first retrieval engine with a disposable in-memory FTS/BM25 accelerator, guarded hydration, and a manifest-bound corpus-proof gate ships as a local CLI; a versioned v3 schema authority now governs the design-md-generator output contract (149/149 tests), and a reversible pre-write STUDY phase binds de-literalized corpus observations to locked target facts behind a two-signal source-leak gate that discards and re-authors without the exemplar on any trip. The remaining modes plug into a shared context seam that carries zero hydrated styles and structurally enforces the authority order: user brief, then mode judgment, then target evidence, then corpus reference, then transport. Two contrasting consumer pilots (relational exemplars for design-interface, a non-authoritative comparison lane for design-audit), a compatibility graph plus a restraint-first motion gate for foundations and motion, and an Open Design transport that reduces raw payloads to metadata-only grounding receipts with mandatory reconcile round out the wiring. All of it is additive — no existing routing, mode identity, or extraction backend changed.
