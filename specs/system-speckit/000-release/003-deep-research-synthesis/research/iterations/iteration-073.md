#### Rust rewrite research packet opens
Internal: this packet is a research-only phase parent, so it changes no runtime behavior. It stands up a planned 20-round deep-research investigation into whether the framework's roughly 244K-line TypeScript backend should be rewritten in Rust, with the charter and 16 predefined angles living in the research child. The question is grounded in the current split: performance-critical primitives (vector search, local embeddings, code parsing) are already native, while the CPU-bound compute core (ranking and fusion math, chunking, trigger extraction) is pure TypeScript. The goal is a cited, decision-ready recommendation between a full rewrite, a targeted native module, or no rewrite. Status is Not Started; this is the first commit of the rewrite question, not an answer.

#### Release-readiness audits and security sweep close
Internal tooling program, now closed at 100%. It aggregated ten release-readiness deep-review audits into a single verdict (8 critical, 28 high, 15 medium findings) and then applied surgical remediation: the concrete blockers — a destructive single-record delete that could bypass its confirmation gate, stale graph reads, silent hook bypass, a schema-validation bypass on a health tool, and strict-validator false negatives and positives — were fixed in follow-on packets. Stress-test coverage was closed out, growing from 38 files and 94 tests to 56 files and 159 tests, all passing, with every catalogued feature marked covered. A separate 25-iteration security audit swept the supply chain and dependencies, confirming the public repository is clean of a suspected malware implant while flagging an active credential exposure on the developer host; ten package pins were locked and three memory records updated in response. For framework users the durable wins are stricter argument validation before tools run, more honest health reporting, and a validator that no longer falsely blocks valid spec documents.
