#### Deep-loop fan-out adds Qwen 3.8 Max on opencode-go
Deep-loop dispatch through the Pi CLI can now run Qwen 3.8 Max, and both it and DeepSeek V4 Flash route through the OpenCode `opencode-go` gateway — the subsidized "2x usage" endpoint. Before, `qwen3.8-max` had no enforced roster entry and DeepSeek V4 Flash dispatched over the direct `deepseek` provider; after, qwen3.8-max was added to the source-of-truth roster and its synchronous mirror, and both models now map to `opencode-go` at the fan-out layer. The change closes a fail-closed gap where a missing provider-map entry silently dispatched the wrong model. Both skills' model/provider docs gained an `opencode-go` section, each row citing the live dispatch that confirmed it, and the guard tests pinning the roster moved with the change (they failed first, exactly on the intended pins, then passed). Dispatch was live-verified for both models, and the direct DeepSeek route remains available via `--provider deepseek`.

#### Portable CLI communication projection ships inside sk-communication
A portable communication layer now ships inside the sk-communication skill: it preserves the canonical CLI output bytes unchanged while presenting agent output as plain-English prose instead of terse, model-flavored phrasing. The verified v1 package built out in stages — versioned contracts and fixtures, deterministic normalization and bounded assembly, protected spans with content-free evidence, model-scoped provider adapters with privacy-first routing and exact-original fallback, six runtime adapters over eight concrete paths, an evaluation and observability framework, and a release-hardening pass adding ten subpath exports, a dated support matrix, and a compatibility doctor that fails closed to original-only output. It is **off by default**: projection resolves to off with no opt-in, a private per-machine opt-in is git-ignored and the environment variable wins over it, and sk-communication is held out of skill-advisor routing through an adjustable denylist. Because the release gate blocks on provisional evidence and requires a powered blind human non-inferiority study as the operator-run gate, the rewrite is not yet certified for live use — so no user-visible behavior changes until the per-machine opt-in is set.

#### Pi Remote mobile control plane: planned, not yet built
The Pi Remote program — a private Claude-app-style mobile control plane over the Pi CLI — was scoped and approved as a nine-phase effort covering contract and threat baseline, automated test harness, relay protocol and durable state, auth and tailnet boundary, mobile PWA and reconciliation, approval and remote mutation, push and platform hardening, documentation and runbooks, and release verification and rollout. Every phase currently holds an independently executable planning packet with bounded scope, measurable requirements, owned surfaces, ordered tasks, evidence gates, rollback, and adjacent-phase handoffs — but no production code, service, deployment, device claim, or release capability was created. This matters because the architecture and threat model are pinned before any build: live Pi, host, ingress, browser, storage, and extension contracts are frozen, and the control plane is designed to fail closed. Internal planning only — no user-visible behavior change.
