#### Pi CLI becomes the sixth orchestration executor mode
The cli-external-orchestration hub now ships a sixth executor mode, `cli-pi`, bringing the open-source pi.dev multi-provider coding agent to the same standing as the existing Claude Code, Codex, Cursor, Devin, and OpenCode modes. Everything was live-verified rather than taken from docs: headless dispatch runs via `--print` with text/json/rpc output modes, stdio MCP transport genuinely connects in offline mode, and extensions are validated against a callable-factory contract (a broken extension fails the whole session, not just itself). The most load-bearing finding is that Pi shares the cursor-agent exit-code gotcha — a failed dispatch returned exit 0 on the first run and exit 1 on later ones — so the dispatch guard must never judge success or failure by exit code alone. Dispatch scaffolding is deliberately fail-closed: absent the Pi binary, an unconfirmed invocation contract, or an off-roster model, a dispatch refuses rather than guesses. The packet also adds skill and command discovery bridges, an agent-translation plan, MCP and extension integration, a 7-model enforced roster, and a manual-testing playbook plan. This is internal orchestration tooling — it adds a new dispatchable executor to the framework's own layer, with no breaking change to existing modes.

#### Provider and model reference catalogs per cli mode
Each of the six cli modes now has a dedicated `providers-and-models.md` reference catalog answering which providers, which models, which effort tiers, and how to dispatch, in a uniform seven-section shape. Before, that knowledge was scattered across each mode's SKILL.md roster, its cli-reference model section, and prompt-template pins; now those exhaustive enumerations are trimmed to a compact residue — the mode's own default, its reasoning-effort mechanism, and a prominent pointer to the catalog. Mode-specific mechanics stayed inline where they matter, notably cursor's full enforced 10-id allowlist, since dispatching an off-list id hard-fails and the safety contract must stay readable. The six catalogs are registered as advisor-routable leaves, and the hub's surface router, which previously covered only three of the six modes, now covers all six. Hub docs were reconciled to point at the catalogs, a version skew across hub files was aligned to 1.2.0.0, and a phantom scripts directory was removed from the layout documentation.

#### DeepSeek V4 Flash joins the cli-pi enforced roster
A fanout dispatch naming `deepseek-v4-flash` is now accepted by the cli-pi executor instead of being rejected at the enforced-roster gate. The cli-pi docs already advertised the model, but the enforced allowlist omitted it, so every fanout run naming Flash failed before any subprocess spawned — this packet closes that divergence between the documentation claim and the enforced gate. The id was live-confirmed on the pi install before it was added, keeping the roster's live-only, never-fabricated contract, and it was inserted after `deepseek-v4-pro` so existing behavior is untouched. cli-cursor and cli-devin were deliberately left alone because their providers serve no DeepSeek V4 Flash id at all. The change is additive: a previously-rejected model is now permitted, and no existing dispatch path was altered.
