#### CLI bridge skills guard against self-delegation
`cli-claude-code`, `cli-gemini`, `cli-codex`, and `cli-copilot` now tell each runtime not to hand work back to the bridge that targets itself, closing a circular-delegation trap. Where nesting checks already existed they were reframed; where anti-self-delegation guidance was missing it was added. The same guard wording is now shared across all four skills, so the message stays consistent instead of drifting per runtime. The documentation also points each runtime to its own native capabilities rather than only saying "don't", making the guard actionable instead of purely prohibitive. This is internal, documentation-only tooling — no runtime behavior changes and no migration.

#### CLI skills route prompt quality through local mirror cards
The CLI bridge skills no longer load the full prompt-engineering guidance inline; each now requires a short prompt-quality card check before building any dispatch prompt. A canonical card lives in `sk-improve-prompt`, and guard-safe mirror copies were placed under the assets tree of `cli-claude-code`, `cli-codex`, `cli-copilot`, and `cli-gemini` — a requirement because the skills' `_guard_in_skill()` routing makes cross-skill resource paths invalid. The four prompt-template files also gained `Framework:` annotations. High-complexity and compliance-sensitive prompts now escalate to a new `@improve-prompt` agent, which runs the full methodology in a fresh context instead of polluting the caller's. `/prompt` now supports both Inline mode for ordinary use and Agent mode for escalations, and a drift-check script (`check-prompt-quality-card-sync.sh`) hashes the framework-selection table across canonical card and mirrors so the copies cannot silently diverge.

#### Codex CLI sessions inherit a global voice addendum
Every Codex CLI session now loads a voice file covering Voice, Tone, and Reasoning Visibility only, so responses drop filler openers, hedge when unsure, show reasoning before conclusions, name trade-offs, and correct faulty premises. The version-controlled source lives at `<repo>/.codex/AGENTS.md` and is symlinked from `~/.codex/AGENTS.md`, Codex's documented discovery path, with a precedence header stating the addendum never overrides the project-level framework. This is a pivot from the original plan: two Codex-specific assets were authored and integrated, then removed when discovery of the user-global file made them redundant (ADR-006/007), and scope tightened from seven behavior shifts to three categories so nothing overlaps the repo's gates and scope rules. AI orchestrators delegating through the cli-codex skill do not inject this content into prompts — their own system instructions govern voice. **Breaking:** the `cli-codex` asset files `codex_app_personalization.md` and `codex_voice_module.md` were deleted; anything referencing them should point to `<repo>/.codex/AGENTS.md`, where their content migrated.
