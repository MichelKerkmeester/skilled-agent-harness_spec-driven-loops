#### Release Cleanup: Docs Aligned to Shipped State
The v3.6→v4.0 cycle opened with a twelve-phase release cleanup that aligned the framework's documentation to shipped code: twelve per-directory code READMEs, the skill and root READMEs, fourteen SKILL.md/references/assets docs across cli-opencode, sk-code, sk-design-interface, sk-prompt-models, system-skill-advisor and system-spec-kit, twelve feature-catalog files, nineteen command docs and the system-spec-kit manual-testing playbook. These were edits only — no README or catalog entry was added or deleted — fixing stale references, file counts, renamed paths and broken links, so the catalog's count self-checks still hold. Agent-definition cleanup rewrote three README.txt files that listed retired agents and mis-described the mirrors, and corrected AGENTS.md's mk-spec-memory tool count from 37 to 39 (confirmed three ways); changelogs were left untouched as immutable historical archives, while the deep-research skill docs, command-router and agent_router.md stayed deferred to a concurrent session. The cleanup phases then fed into verification work: a twenty-iteration audit confirmed roughly fifty real catalog/playbook coverage gaps in the three daemon-backed system skills, a 222-of-471-scenario playbook validation surfaced 14 product findings, and eight remediation clusters (A–H) fixed the schema-drift and other defects with per-cluster vitest/typecheck/mutation verification. The benefit is a framework whose shipped skills, commands, agents and catalogs all match reality, so users and models reading the docs get accurate paths, counts and behavior. A whole-suite run across all remediation clusters before the 028 branch merges to main remains the one open gate.

#### Planned: Spec-Root Resolution Hardening
This phase-parent plans the data-before-writers hardening of spec-root resolution, but is currently **Planned** on branch `skilled/v4.0.0.0` — research is complete and the work is decomposed into five phases, so nothing from it shipped this cycle. Today spec-root resolution is implemented at ~20 independent call sites with four different precedences (canonical-first, legacy-first, canonical-only, direct-path-first) and no single contract; a repo-root `specs` symlink masked the disagreement by collapsing both roots to one inode. The confirmed end state is canonical-first with explicit-path preservation, a unique legacy-only read fallback, and fail-closed handling of divergent duplicates. Five sequential phases will build a resolver registry with a fail-closed collision classifier, canonicalize legacy-only packet data under a writer freeze, canonicalize automatic writers, normalize readers with a 28-day zero-hit compatibility window, and retire the `specs` alias proven against an R1–R10 × L1–L4 validation matrix plus fault injection. For a framework user the payoff is predictable, contract-backed resolution of spec-root paths instead of per-call-site behavior; each phase must independently pass `validate.sh --strict`. Internal tooling — no user-visible change until the phases execute.

#### Fix Memory Write-Back Corruption; Harden Daemon
Two sub-scopes of this packet shipped in the cycle: a data-integrity fix (REQ-006) and a daemon/startup/MCP hardening pass (REQ-007–011); the packet's original reindex-performance measurement objective has not started and the packet remains in progress. The bug: a full force scan/reindex of the mk-spec-memory index wrote quality-loop auto-fixes — including destructive content trimming — back to tracked source `.md` docs, violating the rule that generated memory is search-only; `indexMemoryFile()` hardcoded `persistQualityLoopContent: true`, and now gates on the already-computed `indexingOrigin`, so scan-origin indexing never persists while direct `memory_save` calls keep their legitimate auto-fix write-back. An independent review caught that the daemon's own `startupScan()` and file-watcher reindex bypassed the gate, and both were fixed in the same pass, as was the async-ingest worker (REQ-008). The hardening pass collapsed a redundant daemon-ready probe on the warm-owner path (REQ-007), made `memory_index_scan` default to background execution (REQ-009), added `leaseId` fencing against a lease-file race (REQ-010), and pinned a canonical model-server socket default (REQ-011). Verified with 15 new regression tests plus ~521 passing adjacent tests and a clean build; the daemon restart that makes the fixes live is intentionally held pending operator input, so the running daemons still serve pre-fix code until then. For a framework user, scans no longer risk corrupting source spec docs and daemon startup is faster and race-free.
