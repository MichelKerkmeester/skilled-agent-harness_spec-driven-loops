#### Add Kimi K2.7 Code as a first-class small model
Kimi K2.7 Code is now a first-class small model: registered across eight files, dispatchable via `kimi-for-coding/k2p7`, with `kimi-k2.6` retired in place. A five-framework prompt bakeoff initially returned an inconclusive tie because easy test fixtures saturated the correctness check, so it was re-run on stricter validators, which promoted COSTAR as the default (TIDD-EC as fallback) and retired RCAF, the previous convention default. Asset and documentation filenames in sk-prompt-models were renamed from dash- to underscore-style via `git mv` to match the house convention, with every live reference repaired; the four model-profile pages deliberately keep dashed names because the drift guard derives their paths from the dashed model id. The skill now documents a real failure mode: on broad, large-repo dispatches at high variant, Kimi over-explores and exceeds the 600-second timeout without emitting output, so opencode flushes zero bytes and the run looks hung. Mitigations — a hard read cap in the prompt, a 1200s+ timeout, and optionally dropping the variant flag — are recorded alongside repaired stale k2.6 references.

#### Add GLM-5.2 coding model with vision support
GLM-5.2 is now a first-class small model on the Z.AI GLM Coding Plan (`zai-coding-plan/glm-5.2`), registered across ten surfaces and replacing the gateway-only `glm-5.1`. A benchmark of 45 real dispatches named COSTAR the primary prompt framework, TIDD-EC the fallback, and RCAF one to avoid, with the registry flipped from a documentation-guided placeholder to this empirical result. The run also confirmed two dispatch gotchas: latency swings of 6–161 seconds from thinking-on-by-default and about 1-in-45 transient dispatch failures, with subscription billing keeping cost at zero. Native vision-to-code is proven: GLM-5.2 reads image input through the direct Z.AI Coding Plan API, while opencode's `--file` attachment stays broken for this provider, so the direct API is the documented workaround. The planned discriminating re-run was never needed because the first benchmark separated the frameworks cleanly.

#### Retire cli-codex executor from active routing
The cli-codex executor skill has been retired from active OpenCode routing and discovery: the package now lives in an archive path as `SKILL.retired.md`, residual empty directories were removed, and historical records were left intact. The deep-loop runtime no longer accepts or builds dispatch commands for the retired executor kind, and the skill advisor's graph was cleaned and regenerated so a probe for cli-codex now recommends supported skills instead. Documentation, agents, mirrors, feature catalogs, matrix runners, and manual-testing playbooks no longer advertise cli-codex, and generic Codex hook support was removed from the README, hooks, and commands. A Codex Desktop App bridge was added back — a project `.codex/config.toml` with MCP entries plus `.agents`, `.codex/skills`, `.codex/specs`, and `.codex/changelog` symlinks — without restoring the retired executor skill. **Breaking:** the cli-codex executor is no longer dispatchable; migrate to the supported OpenCode plugin and Claude Code hook surfaces, or restore the archived skill for rollback.
