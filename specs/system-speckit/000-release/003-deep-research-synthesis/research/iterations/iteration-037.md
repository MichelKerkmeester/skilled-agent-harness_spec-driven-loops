#### Benchmark authoring consolidated and validation hardened
Benchmark-document authoring is now centralized in a single skill, create-benchmark, which owns the templates, storage guides, and family-routing table across five benchmark families (skill, model, behavior, and agent-improvement), while the deep-loop lanes keep run and scoring logic. The skill-benchmark test suite was repaired back to 56 passing tests, and the design-command surface validator was rebuilt from 10 invalid findings to valid, enforcing a structural choreography contract and catching stale fixtures and self-masking tests. **Breaking:** the skill-benchmark runner now exits 3 on structural or registry blocks instead of 0; automation keyed to the old exit behavior must accommodate the new gated exit.

#### Skill routing made correct across the fleet
This program reworked how the framework's skills are routed to the right packet and leaf resource. A series of deep-research loops corrected the prior diagnosis: sk-doc's alleged coverage gap was falsified (113 of 113 aliases matched) in favor of a path-contract defect between two coordinate systems, the skill-advisor's confidence was shown to be policy-floored rather than a true posterior, with three correctness defects named, and sk-code's routing fault was traced to monolithic leaf selection plus an untyped preamble rather than surface selection. The findings feed typed-pair optimizations led by packet-qualified leaf paths. On the fix side, an audit produced a 14-fix map; existing-document quality actions now route exclusively to create-quality-control so README and flowchart packets no longer collide; broad selector terms were removed and every exclusion names its exact sibling owner; and all ten packet sources now share one trigger and handoff shape with zero drift across the runtime JSON projections. Six flat-resource create-* packets also gained explicit smart-routing notes. Most research packets were findings-only with no source changes, and the system-deep-loop research packet was still in progress.

#### Kebab-case filesystem naming becomes the repo-wide rule
The framework now enforces kebab-case (hyphens) as the sole canonical form for folder, file, and script filenames across the repo, formally reversing the earlier underscore migration and superseding its documentation. Exemptions are explicit: Python files and import-package directories, vendored and third-party trees, generated and lockfile output, tool-mandated filenames, and frozen history; code identifiers, configuration keys, and database columns stay out of scope. The migration runs as a phased program on an isolated worktree pinned to an immutable baseline SHA, starting with a census and green baseline. Consumers now fail closed on ambiguous or unsupported root names before classifying or routing, the create-* generators emit hyphenated catalog, playbook, skill, command, benchmark, and install-guide output paths, and a no-new-snake guard ratchets the tree, immediately catching a leaked underscore name. New tooling turns a reviewed rename map into deterministic dependency-ordered batches: a semantic rename engine, a read-only reference checker producing a compare-and-swap-ready ledger, a disposable fixture corpus proving dry-run safety, and an executor with blob-hash compare-and-swap and journaled rollback confined to opted-in disposable repositories. **Breaking:** existing underscore-named files and references migrate to kebab-case, so tooling, scripts, and docs that hardcode the old snake_case paths must be updated to the hyphenated forms.
