#### sk-design program: style database, interface commands, hallmark
The umbrella packet for the entire sk-design v4 body of work — the style database, the `/interface` creation commands, the hallmark design system, reviews, remediation, and mode consolidation — organized into six phases so every study, build, and review stays navigable. Deep research converged on a SQLite + FTS5 + vector generation that keeps the flat 1,290-style files authoritative (a rebuildable, generation-stamped projection, deliberately not a graph engine), and on five canonical `/interface` commands sharing one 9-stage creation contract while the design modes keep authority. The style database itself shipped as a published generation over the full corpus — parity-proven in shadow mode and roughly 21x faster — while the default read path stayed `legacy` pending a human-gated cutover. A measurement foundation added versioned generation manifests with atomic publish/rollback, residency-honest stage telemetry, a pinned differential oracle, and 1x/10x/100x replay fixtures; the library was then restructured from a flat tree into an ownership tree (code `lib/`, data `library/`, tests, scripts) with kebab-case names and byte-identical retrieval. The remaining roadmap phases — JS capabilities, measured-native experiments, and growth architecture — are fully specified but gated, so nothing ships until measured 10x-100x pressure or an SLO trigger appears. For framework users the payoff is the new `/interface` commands and faster, verified style lookup; the rest is internal engineering rigor that framework users experience only as reliability.

#### Structure and naming cleanup for sk-design
A structure and naming cleanup that tidied the style library and the ten `/interface` command files without changing behavior. It removed a stray `styles/docs/` folder whose misplaced manual-testing playbook duplicated content already in the hub playbook, and renamed the six dunder test/fixture folders to kebab-case (five `__tests__` → `tests`, one `__fixtures__` → `fixtures`), repointing every live import and doc reference while leaving frozen benchmark transcripts untouched. The `/interface` workflow YAMLs were conformed to the shared command-standard vocabulary — adding `operating_mode`, `input_contract`, gate logic, circuit-breaker, error-recovery, and similar sections additively — while preserving each file's original workflow and deliverable values and keeping its delegation to the creation contract. Per-mode manual-testing playbooks were kept rather than consolidated, because evidence showed per-packet playbooks are the codebase-wide doctrine and only the `styles/docs` stray was a real defect. Every change is reversible via git, isolated to sk-design, and verified by green test suites (design-motion 23, design-audit 21, design-interface 22, design-foundations 25, corpus-context 36, transport-grounding 37/37) plus value-identical YAML parsing; there is no user-visible behavior change.
