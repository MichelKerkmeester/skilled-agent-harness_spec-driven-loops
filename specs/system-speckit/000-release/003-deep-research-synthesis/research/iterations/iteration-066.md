#### Deprecate standalone deep context; preserve replacement capabilities
The standalone `/deep:context` command is no longer a working context loop. It now acts as a no-write redirect that emits replacement guidance and writes no context artifacts, while supported routes keep a bounded replacement context snapshot. Registry, advisor, documentation, and generated-index references were removed, and the active OpenCode and Claude agent mirrors became disabled deprecation stubs. Fixtures, benchmarks, and generated contracts no longer keep the feature alive, and the runtime rejects active context fan-out while historical context artifact parsing stays behind with its tests. Users who reach for `/deep:context` for codebase context should follow the replacement routes the redirect points to.

#### Deep-loop runtime: determinism, recovery, reliability hardening
The deep-loop runtime behind research and review got a hardening cycle across its implementation sub-phases. A freshly-copied research strategy now folds its state deterministically on the first reduce instead of hard-failing, because the shipped template carries the seven reducer anchor markers it previously lacked. Fan-out merges are byte-stable regardless of worker arrival order, the pool emits lag/pending/failed gauges and a graceful partial stop on interrupt, and failures now get a bounded taxonomy with transient/fatal retries, orphan-lineage markers, and an explicit recover-vs-fresh gate. Reliability-weighted convergence was marked no-go for this cycle and preserved as the design of record, while stop-input corroboration, continuity threading, near-duplicate finding dedup, and the new gauges all ship default-off behind opt-in flags. Benchmarks returned graduate verdicts for the dedup and gauge capabilities, then fixed a lag metric that false-fired on healthy wide pools (now a true stall signal) and made dedup title-aware so distinct findings with identical bodies no longer collapse. Follow-up fixes also brought orchestrator validation in line with the shell, added a lineage timestamp guard, pinned the session-id handoff contract with tests, and corrected per-document section-count expectations. **Breaking:** none of this changes existing behavior — every new capability is opt-in and byte-identical when off.

#### Research-only: Rust rewrite of the skill-advisor backend
This packet authorizes research, not code — it is the planning root for a two-phase deep-research investigation into whether the ~51K-line TypeScript skill-advisor backend would benefit from a Rust rewrite. Phase one studies the scoring and ranking core; phase two covers embeddings, vector search, and the daemon/MCP/CLI serving layer. Both children ship as 16-round charters with predefined angles tied to concrete files, each ending in a ranked, decision-ready recommendation spanning full rewrite, targeted native module, sidecar, or do-not-rewrite. No Rust is written and no backend source is touched this cycle; the backend is treated as read-only research material. Framework users see no behavior change yet — the deliverable is cited evidence that decides whether anyone should spend engineering time on the rewrite at all.
