#### Hub doc audit and remediation plan
An internal quality program audited the hub documentation for the external-CLI and MCP tooling bridges against the authoring templates and against live CLI and MCP reality — flags, tools, auth, agent routes, links. The review failed every slice, surfacing 67 distinct P0 findings (73 after dedup from 102 raw). Rather than fix anything, the cycle produced a collision-free remediation plan: four work-streams (ClickUp 28 P0, cli-opencode/cli-claude-code 20 P0, Figma/Chrome DevTools 11 P0, cross-cutting root playbooks 8 P0) plus a mandatory verify-first re-validation protocol, so each stream can be dispatched in isolation with no cross-stream file collisions. No hub doc was edited in this cycle. Purely internal; no user-visible behavior changed yet.

#### Document diff engine and create-diff mode
Research is complete for a portable, local-first document diff engine surfaced through the sk-doc create-diff mode. The v1 architecture, runtime, libraries, API, snapshot model, diff strategy, and security model are locked: TypeScript on Node.js 22+ (24 LTS as the dev default), semantic and structural comparison with explicit fidelity warnings, and a self-contained local HTML report as the primary artifact. The engine is embedded directly in the skill rather than shipped as a separate package. The create-diff mode v1 is in progress — automatic snapshot capture by default with explicit-pair fallback, refusal for binary or unsupported inputs, and a redesigned code-diff report — while the HTML/DOCX adapters, text-PDF and standalone CLI, and the cross-cutting validation, security, and quality gates are scaffolded and awaiting their phase gates. Optional OCR remains behind a later go/no-go decision.

#### Template fences widened to stop section leakage
Four authoring templates were silently swallowing their own sections into code blocks: a 3-backtick example fence wrapping nested 3-backtick fences closed early at the first inner fence, so the rest of the example and several of the template's own sections rendered as live document structure. Widening the outer example fences to four backticks keeps the inner fences literal, so examples stay fully contained and every real section parses correctly again. Fixed: install_guide_template.md (six error-example fences plus the complete template), parent_skill_hub_template.md, skill_asset_template.md, and sk-git's pr-template.md. All four pass fence-aware scans and the document validator with zero errors. One cosmetic leftover: skill_asset_template still carries redundant `\##` header escapes inside its widened example, which a follow-up could remove.
