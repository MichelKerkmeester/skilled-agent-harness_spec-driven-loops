#### Deep-context loop ships as the fourth deep loop
deep-context joins the family as a new `/deep` loop for inward codebase context gathering: it fans out native analyzer seats in parallel and converges on cross-executor agreement to produce a reuse-first Context Report, backed by a coverage-graph context layer that keeps it distinct from the research and review loops. It then reached durability parity with those mature siblings, wiring in five deep-loop-runtime features — atomic state writes, JSONL repair, post-dispatch validation, loop locking, and an executor-audit recursion guard — all gated to context loops so research and review behavior is untouched. The `@deep-context` analyzer seat now dispatches from Claude and Codex as well as OpenCode, every `/deep:` command opens with two un-skippable gates (an orchestrator-verification phase and a unified setup blocker), and a context run can now bind to a spec folder named inline in its scope instead of silently writing to a standalone directory. **Breaking:** `/deep:start-context-loop` now defaults to a native-only executor pool of two seats, so paid CLI executors are no longer spawned by default — choose the Custom pool to restore them — and a context run that names a spec folder now fails closed rather than falling back to a standalone run directory.

#### Plan-named workflows now locked as hard blockers
A real failure — an agent silently hand-rolling a manual gather across a codebase instead of running the plan-specified deep-context loop, repeated as twenty-four silent deviations — is now addressed at the governance layer rather than in tooling. AGENTS.md gains a PLAN-WORKFLOW LOCK: a new HARD BLOCKER beside the Four Laws, shared with Claude and Codex through the CLAUDE.md symlink, under which a plan-named workflow is frozen like scope — assumed friction must be verified by reading the workflow's contract, genuine blockers must be flagged to the user, and a substitute may never be silently hand-rolled. Three reinforcing surfaces carry the lesson further: a cross-runtime feedback memory that surfaces at prompt boundaries, an anti-pattern note in the deep-context skill, and a new constitutional rule extending the requirement to all deep skills — research, review, council, and improvement loops included. The shape came from a four-lens AI Council deliberation that converged at 90% and explicitly rejected heavier fixes like a lint hook, so the command surface itself is unchanged.

#### Deep-loop fan-out routes Claude seats through account dirs
Deep-loop fan-out can now route an individual cli-claude-code seat through a caller-provided Claude config directory, so a Fable seat can use a separate account (for example `~/.claude-account2`) without applying that override to Codex, OpenCode, native seats, or the parent process. The research and review loop setup contracts document `--config-dir=PATH` and the `executor_config_dir` marker, and the review auto command carries the field through its single-executor binding. Under the hood the override is injected as `CLAUDE_CONFIG_DIR` into that lineage's spawned environment with `~` expanded, composing with the existing `CLAUDE_` allowlist and per-replica state isolation; the `configDir` field is accepted only for cli-claude-code, so non-Claude executors cannot silently absorb a Claude account setting. The change was proven with focused unit tests and a stubbed `claude` binary rather than a live paid dispatch.
