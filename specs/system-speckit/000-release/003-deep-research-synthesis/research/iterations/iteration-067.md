#### Codex skill advisor now starts with a matching runtime
For Codex users the skill advisor no longer aborts MCP startup. Before, the advisor launched under a Node version whose native database module could not load — the engine mismatch surfaced as a load failure, and the abort cascaded so that several other servers were skipped during startup. After, the advisor's registration pins the exact engine its installed database module requires, and a live initialization handshake now completes and shuts down cleanly. Other servers keep their own verified engine pins and initialized normally once the advisor no longer interrupted the sequence. No config changes are needed beyond the pin; nothing was removed or renamed.

#### Skill advisor: safer routing, faster warm path, lasting gates
This completes the full nine-item refinement of the advisor and moves it from planning to done. Routing keeps uncertainty guarding on by default even when a minimum-confidence threshold is passed, and confidence-only behavior now requires an explicit flag, so plain-language prompts are no longer silently routed on confidence alone. Command bridges are classed separately and deprioritized unless slash-intent is explicit, cutting false-positive routing. Warm-path matching is faster via in-process caching with mtime invalidation, frontmatter-only parsing, and precomputed metadata — the benchmark measured about 0.6 ms in-process versus about 47 ms per subprocess call, roughly a 26x throughput gain. A batch mode plus permanent regression and benchmark harnesses (34 cases, perfect top-1 accuracy, zero command-bridge false positives) make correctness and latency repeatable going forward. **Breaking:** callers that passed a threshold expecting confidence-only behavior must now pass the explicit confidence-only flag.
