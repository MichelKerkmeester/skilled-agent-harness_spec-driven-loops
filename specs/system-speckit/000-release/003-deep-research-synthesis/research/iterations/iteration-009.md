#### New cli-opencode skill joins the CLI orchestrator family
The cli-opencode skill landed as the fifth sibling in the cli-* family, matching the canonical 9-file blueprint of its peers (skill document, README, graph metadata, four reference docs, and two prompt assets). It is now discoverable through the skill advisor: sibling edges at weight 0.5 were added to all four existing CLI skills and the advisor graph was regenerated, so the canonical prompt routes at 0.95 confidence. A layered self-invocation guard (environment variables, process ancestry, lock-file probe) stops the skill from dispatching opencode from inside an opencode session. The framework deliberately skipped a token-boost for the word "opencode" — with 956,946 occurrences repo-wide it would false-positive — and instead relies on intent signals plus derived trigger phrases for discoverability. A v1.0.0.0 changelog and ten line-anchored README patches keep the surrounding documentation current.

#### Manual testing playbooks for all five CLI orchestrators
Every CLI orchestrator skill now ships a matching manual testing playbook, giving operators 129 deterministic per-feature scenarios across 40 numbered category folders so any CLI can be validated end-to-end without inventing test cases. Because the shared categories (invocation, integration patterns, prompt templates) hold fixed positions in every playbook, cross-CLI comparison reads the same regardless of which book you open. A five-iteration deep review surfaced P0 and P1 findings that were closed in a remediation pass: root playbooks were scrubbed of banned phrasing (em-dashes down 61%, semicolons 74%, Oxford commas 66%, banned words 100%), the section heading was renamed from "CURRENT REALITY" to "SCENARIO CONTRACT" across 592 files, and 14 new scenarios closed surface gaps (codex cloud, cost-and-background, extra agent routing). Final per-CLI coverage: cli-claude-code 27, cli-codex 28, cli-copilot 21, cli-gemini 19, cli-opencode 34 scenarios. Cross-AI handback scenarios stay isolated by design, so no playbook requires a companion CLI to be installed.

#### cli-opencode drops github-copilot, gains auth pre-flight
The cli-opencode skill no longer documents the github-copilot provider; default invocation, model tables, agent-dispatch examples, and test scenarios now use `opencode-go/deepseek-v4-pro --variant high`, while the direct DeepSeek API surface (`deepseek/deepseek-v4-pro`, `deepseek/deepseek-v4-flash`) is preserved. A new Provider Auth Pre-Flight protocol runs a one-shot `opencode providers list` check at session start, classifies three states (default available / default missing with fallback ready / both missing), and explicitly asks the user before substituting any model — never silently swapping providers, which protects against unexpected costs or capability mismatches. Auth errors mid-dispatch invalidate the pre-flight cache and rerun the protocol. Twenty-eight playbook scenarios were bulk-replaced to the new default, and the two github-copilot-only test scenarios were deleted. **Breaking:** commands referencing the github-copilot provider (e.g. `--model github-copilot/gpt-5.4` or `--model github-copilot/claude-sonnet-4.6`) are no longer documented; migrate to `opencode-go/deepseek-v4-pro` or name a supported provider.
