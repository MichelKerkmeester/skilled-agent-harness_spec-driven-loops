#### Template conformance sweep across all sk-design modes
Every folder in the sk-design skill was audited against the sk-doc template standards and every confirmed deviation fixed. In the design-interface mode, 11 of 29 reference files were repaired (missing overview sections, over-long intros, missing section separators, a broken link), all 3 asset files got real structural fixes, and a repeating typo in the feature catalog was caught in 4 newly-added files and corrected. The audit also surfaced two genuine bugs that had been silently breaking runs: both the naming and the baseline-rhythm checker computed their shared-scripts path one level too short, throwing on every invocation, now fixed along with a stale path reference. The Apache-2.0 obligation was removed the honest way — borrowed design guidance was re-authored in first-party words before the licence covering it was deleted. Two decisions remain open for the operator: whether 18 relocated manual-testing scenarios must be reformatted to the 9-column template, and whether the scripts folder needs a tests/ directory. This is internal tooling with no user-visible behavior change, but the skill's documentation is now uniform and its legal baggage gone.

#### Open Design transport deprecated and removed
Open Design, the third sk-design transport, was deprecated end-to-end and its files deleted. The 45-file skill tree came down, the open_design MCP server entry was removed from configuration, the transport mode dropped from the skill registry (3→2), and its live-render adapter, commands, agents, install guides, and root-document references were all stripped. Deep-alignment's live-render lane, the related benchmark fixtures, and skill-advisor boosters were cleaned in the same pass, with derived metadata regenerated. Historical records keep mentioning the transport by design for the audit trail. **Breaking:** any workflow using the Open Design transport — the open_design MCP server, the live-render lane, or its related commands and agents — must move to the two remaining sk-design modes; remove the open_design entry from your MCP configuration.

#### sk-doc rebuilt as workflow-only parent hub
sk-doc was converted from a six-mode monolith into a workflow-only parent hub that dispatches to self-contained create-* skill packets, the same two-axis pattern sk-code and sk-design already use. The final packet set was settled by 30 iterations of deep research, all ten sub-skills got a four-iteration deep review with every confirmed finding applied, and 18 router-carrying skill docs were aligned to a canonical resilient-router template scaled to each skill's shape. The doc-quality packet was renamed create-quality-control across roughly 104 references while the public /doc:quality command and its aliases were preserved, and the shared reference docs were flattened out of a redundant global subfolder. The command surface gained three new /create commands and four renamed to /create:<packet>, and 17 redundant asset templates were flattened directly into their packets' assets folders. A deep review of the parent-hub doctrine surfaced 18 findings (one critical: sk-design failing the hub checker) that were triaged into a nine-unit remediation plan. Mostly internal restructuring — the user-visible change is the expanded, consistently-named /create:* command surface.
