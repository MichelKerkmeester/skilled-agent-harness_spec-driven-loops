#### MiMo-V2.5-Pro becomes a selectable cli-opencode executor
MiMo-V2.5-Pro is now a first-class, explicitly selectable model in the cli-opencode tooling. The Xiaomi Token Plan (Europe) provider and its model were wired into the shared small-model registry, the cli-opencode skill, and the prompt-model skill's documentation, mirroring how the MiniMax token-plan model is wired. The deep research, review, and improvement workflows can now dispatch MiMo and MiniMax cleanly, because a hard-coded flag that broke token-plan providers was removed from their dispatch paths. A focused research pass produced seven prioritized efficiency improvements and backfilled the model metadata, then a benchmark of five prompt frameworks on the real model picked COSTAR as the winner (with RACE a statistical tie) and integrated it into the MiMo dispatch path. Notably the result was the opposite of MiniMax, whose guardrail-heavy framework ranked last. The default model is unchanged and MiMo is purely additive, so nothing breaks.

#### Gemini removed end-to-end as runtime and executor
Gemini has been removed end-to-end from the framework. The checked-in `.gemini` runtime surface and the cli-gemini skill were deleted first, then the command layer's leftover Gemini branches and references were cleaned from five command assets and four command documents. Next the cli-gemini executor was purged from the deep-loop runtime and improvement tooling, including audits, dispatch branches, tests, catalogs, and playbooks. Finally Gemini was eradicated as both a host runtime (the hook subsystem and runtime detection) and as a model (`gemini-flash` and related ids) across source, roughly 87 documentation files, and 43 release changelogs, all in verified waves with suites green. The external Gemini-CLI binary installed in the user's home directory was deliberately preserved. **Breaking:** Gemini is no longer a supported executor, host runtime, or model — any workflow that used cli-gemini must be switched to a supported tool such as cli-opencode.

#### Devin skill and executor removed framework-wide
Devin has been fully removed from the framework. The cli-devin skill was deleted together with its roughly 70 files, and every reference was swept across six phases: shared assets were re-homed to the prompt-model skill, the runtime dispatch and executor wiring were stripped, the model registry and skill graph dropped their Devin rows, the Devin hooks were deleted, and docs, agent definitions, and governance files were cleaned. An audit of the roughly 1,760-file historical surface confirmed old records were left intact as history, and a framework-wide scan confirmed no live references remain. An adversarial review of the change-set came back clean. **Breaking:** Devin is no longer an available executor — any workflow that dispatched through cli-devin must be pointed at a supported tool such as cli-opencode.
