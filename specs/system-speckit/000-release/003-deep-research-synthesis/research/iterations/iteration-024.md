#### Conformance gate repair underway; drift sweep pending
The code-standard enforcement gate was itself broken — a dead post-edit hook, a completion gate scoped to a single skill tree, and a header shape left permanently manual — which let roughly 1,400 authored files drift from the file-opening, comment-hygiene, portability, and containment contracts. This packet repairs the gate first, then sweeps the drift in blast-radius order, and amends the one place where the standard itself is the nonconforming artifact. The first phase (about 80% shipped) repairs the installed hook paths, the comment-hygiene matcher, the test-naming table, the Node discovery contract, and the repo-wide scan wrapper, and rules that exact header-shape checking is opt-in and the repository-wide scan ships without fail-on-warnings. A live smoke test and the sweep over the existing backlog remain outstanding. Internal tooling — this governs the framework's own skill tree, not end-user behavior.

#### Dist guard self-heals stale checked-out builds
A recurring session-start hook error traced to a stale compiled output that broke an import — and the guard meant to catch it was itself crashing: an orphaned package entry left by a removed code-graph package made the whole sweep abort, and the fail-open behavior silently swallowed the crash, so the check detected nothing. The orphan is deleted, and the sweep now auto-rebuilds a stale package at session start (bounded at 180 seconds, fail-open), controlled by a kill-switch that defaults to on. Per-edit checks stay warn-only, so a keystroke never triggers a compile. Verified on real packages: one self-healed, another's failing build fell back to a warning, and all watched build trees stayed out of version control. Internal tooling. Set the kill-switch off if you never want a compile at session start; a genuinely broken package build still warns every session.

#### Dist guard skips packages unbuildable in a checkout
A bare worktree was warned every session about packages it cannot build — one package's manifest, dependencies, and build output are all gitignored, so its build cannot run there, and the checker mislabeled that as stale. The checker now distinguishes provisioning gaps from drift: a package missing either its manifest or its installed dependencies is reported as "unprovisioned" with a false stale flag, and the guard stays silent about it, while a provisioned package behaves exactly as before. Fresh packages are never relabeled, and the guard script itself needed no change because it only acts on stale results. Verified on the live workspace (that package flipped from missing/stale to unprovisioned) and with a fixture that runs the same stale package twice, differing only by its installed dependencies. Internal tooling. Provisioning is still your job — this stops the noise but does not build or link a bare worktree's dependencies.
