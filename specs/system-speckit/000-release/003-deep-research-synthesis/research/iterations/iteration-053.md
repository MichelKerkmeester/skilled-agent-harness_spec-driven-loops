#### Manual testing playbook and prompt-improver agent rename
The sk-prompt agent was renamed from `@improve-prompt` to `@prompt-improver` across all four runtime mirrors (opencode, claude, codex, gemini) plus 35 active-scope reference files, retiring the verb-object outlier and aligning the name with the noun-form agent family (`@code`, `@review`, `@debug`, `@context`). It is a pure semantic rename: no behavior, dispatcher-contract, or skill change, and the `/prompt` command name and path are untouched. In parallel, sk-prompt gained a 28-scenario manual testing playbook following the sk-doc templates, with root-index coverage and recorded validation evidence. The rename makes agent identity predictable across runtimes, and the playbook gives maintainers a repeatable acceptance surface for the skill.

#### Small-model optimization: budgets, permissions, profiles, renames
A deep-research loop mined the external smallcode-master corpus and converged after 12 iterations with 389 findings and 41 output-quality patterns, landing on a combined architecture (distributed references plus enhanced skill edges rather than one new skill). The patterns shipped as concrete deltas across the dispatch stack: cli-devin gained per-model context-budget defaults and an opt-in static output-verification pipeline; cli-opencode gained a structured permissions matrix with JSON-Schema definitions and default-deny handling for malformed matrices, unknown tools, and unresolvable symlinks; and a shared model registry added Bayesian scoring with quota-pool-aware fail-fast fallback — all data-only or off by default, so existing recipes run unchanged. The sentinel skill hosting the patterns shipped as `sk-small-model` and was renamed twice (to `sk-prompt-small-model`, then `sk-prompt-models`) across more than 20 surfaces with a regenerated skill index, after which the advisor surfaces it at 0.95 confidence on the canonical small-model dispatch prompt. Small-model dispatch now carries the same guardrails as the frontier lanes — budgets, permission gates, and verification — with zero behavior change to default usage.

#### Prompt-knowledge layering with model-craft hub
A three-layer prompt-knowledge architecture was established: sk-prompt owns the framework-selection table, `sk-prompt-models` is the per-model prompt-craft hub, and the five cli-* executors delegate. Every active model gained a structured `recommended_frameworks` object (primary, fallback, avoid, evidence) in the registry, and eight per-model profiles now live under the hub following a fixed six-section template, starting with empirically grounded MiniMax-M3 and MiMo-V2.5-Pro entries. The five executor prompt-quality cards were thinned from ~90-line inlined duplicates into lean delegating mirrors, a duplication-guard script now passes GREEN on all five cards, and a uniform three-tier prompt-composition precedence block was wired into every cli-* skill so callers can predict which rule wins. STAR and BUILD were reclassified as cli-devin task shapes rather than frameworks, the hub's no-op router became a model-keyed smart router, two sibling MiniMax-vs-MiMo benchmark runs were merged into one with a combined synthesis (~40 stale citations repointed), and the C1–C10 seam-drift backlog was closed with the guard CI-wired so the structure cannot silently regress. Framework selection and model-specific prompt craft now live in exactly one place each, with consistent precedence and enforced synchronization across every executor.
