#### Skill-Advisor CLI: generated fallback, hardened, wired in
Before this work, the skill advisor's 9 tools were reachable only through the MCP server, with a Python facade (`skill_advisor.py`) as a legacy fallback. Feasibility research returned a GO verdict with 10/10 measured scorer parity, and the CLI core shipped as a manifest-backed dispatcher (`skill-advisor-cli.ts` plus the `skill-advisor.cjs` shim) exposing the same 9 commands with byte-identical schemas, a trusted-mutation gate, a 0/1/64/69/75 exit taxonomy, and a stale-dist guard. Hardening added parity, job-semantics, orphan-reaping, and dual-client suites plus an env-gated tri-daemon spawn drill — all passing, including zero-orphan reaping under a killed parent. Runtime integration then wired warm-only CLI fallback into the Claude and Codex prompt-submit hooks and the OpenCode bridge, added read-only doctor probes, and documented facade-vs-CLI selection. Because the one-shot native bridge costs ~825ms, warm-only use keeps it off the prompt path and the prompt path fails open quickly when the socket is absent. The change is additive and non-breaking; the Python facade is reconciled as a legacy facade rather than removed.

#### Advisor routes on reference-doc trigger phrases
The skill advisor now harvests the detailed frontmatter that reference and asset docs carry — title, description, trigger phrases, importance tier, context type — into a new `skill_docs` table in the skill graph, so doc-level phrases become routing signal instead of dead metadata. Ask about something like "deep loop script interface contract" with the feature on and it ranks the right skill first and returns a `matchedDocs` pointer telling you exactly which file to open. Doc scoring rides the existing derived lane with safeguards so volume can't buy weight: only a skill's top-3 strongest doc matches count, each is tier-weighted, and the sum caps at 0.45 — below what a single curated skill-level phrase earns — so doc signal assists and annotates but never hard-routes on its own. The daemon watcher re-indexes edited docs automatically, the Python CLI fallback harvests identically under the same flag, and a CI guard plus a contract checker keep the ~355 docs compliant. The feature is gated behind `SPECKIT_ADVISOR_DOC_TRIGGERS` and is purely additive, so non-breaking, though live adoption by running daemons was still pending at cycle close.

#### Advisor reliability, observability, and scoring hardening
A batch of migrated items hardened the skill advisor across eight fronts. The launcher now recovers from confirmed-dead lease sockets — reaping the wedged child pid under the bootstrap lock and respawning a replacement — instead of silently letting secondary clients exit. The test suite went from 61 failing to 0 by fixing deep-loop merge fallout and retargeting the settings-parity guard, and the workspace-root fallback was hardened so it can never resolve into a `specs/` subtree, cleaning 23 stray `.advisor-state` directories that had leaked into spec folders. Operators can now request prompt-safe attribution (`why_recommended` lane summaries) and semantic-lane health from `advisor_status` without any prompt text leaving the server, and automated edge propagation stamps server-derived provenance while protecting manual provenance from overwrites. Scoring internals gained a default-off packed BM25F lexical shadow helper, a single shared BFS helper for graph traversals, and a default-off shadow calibration reducer that records validate-outcome proposals without touching live weights. All of it is internal tooling with no breaking surface — no user-facing API changed, and `advisor_validate` remains the gate before the BM25 and calibration work could ever influence live ranking.
