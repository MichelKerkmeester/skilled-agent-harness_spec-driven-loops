#### Parallel-session autosync research frozen into a publishable architecture
The research phase for parallel-session git autosync produced no code — its deliverable is a frozen architecture decision. Two independent research lines (five iterations each) were reconciled, then passed through a three-pass verification that surfaced blocking prerequisites and confirmation caveats. The chosen design is a four-plane, single-writer publisher that works from isolated worktrees and always pushes fast-forward-only, with a central invariant that the primary branch is never behind the projected state; when the remote tip has moved, the push is rejected and internally rebuilt rather than forced. A proposed AI conflict resolver is deliberately bounded to a proposer role — it advises but never writes, and a GitKraken integration stays a read-only auxiliary. Six decisions and a testable acceptance matrix are recorded so the implementation phase can proceed against concrete prerequisites. This is an internal research artifact for framework maintainers; no user-visible behavior shipped.

#### Worktree and branch names move to an owner-first grammar with locked allocation
Branch and worktree naming is codified under a new owner-first convention, `<skill>/NNNN-slug` or `skilled/NNNN-slug`, replacing the legacy `wt/` lane and any hand-computed numbering. The prior free-form naming gave way to a locked, clone-wide allocator plus validators that enforce owner, slug, and branch/worktree pairing, backed by a 31-case test harness; the session wrapper and reaper were hardened so only clean, merged, machine-owned worktrees are auto-reaped and nothing is ever force-deleted. A migration-tolerant pre-push hook now gates brand-new remote branch names against the allocator's validators while failing open on a broken validator and never blocking `skilled/v*`. The framework's own cleanup ran under operator gates: 34 stale worktrees and 31 merged branches were removed with every object kept reachable and the recovery OIDs recorded, leaving only per-branch decisions on preserved unmerged branches. **Breaking:** branches and worktrees must follow the owner-first grammar — legacy `wt/*` lanes are no longer allocated, though a bypass flag (`SPECKIT_SKIP_PREPUSH_NAMING=1`) eases migration.

#### Worktree tooling hardened and aligned after adversarial review
An adversarial review judged the previous naming and reaping work unsafe to ship, so every confirmed finding was fixed under a reproduce-first discipline before release. The session script now rejects shared-path escapes and container-boundary violations, the reaper requires an exact machine-owned pair and verifies PIDs and daemon paths before signaling, and the allocator's stale-lock race was root-caused and fixed with an atomic lock takeover proven across 100 clean runs. A pre-push gate now fails open on internal errors instead of blocking a legitimate push. The sourceable shell scripts align with the shared code standards (zero findings), over-claims in the prior packet's docs were corrected, and harnesses pass for session, reaper, pre-push, and naming. This is internal tooling for framework maintainers; no user-facing behavior changed.
