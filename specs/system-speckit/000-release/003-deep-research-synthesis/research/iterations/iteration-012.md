#### cli-devin deep-loop recipes gain enforced reasoning
This release hardens cli-devin's automated deep-loop runs (internal tooling with no user-facing change). Before, the iteration recipes left reasoning and tool discipline to model judgment; now every iteration mandates a step-by-step reasoning tool, registered both in the tool environment and in the recipe's system instructions so the model actually invokes it, and write access is restricted to just the two file paths each iteration needs. The loop commands also gained a 900-second timeout and detection for a refused tool call, so a rejected action surfaces as a failure instead of silently stalling. Cost is roughly +10 seconds per iteration. Existing in-flight runs keep the previous version; the new behavior applies to future deep-loop runs.

#### RCAF becomes the data-driven default CLI prompt framework
cli-devin's prompt scaffolding moved from anecdote to evidence. A 42-dispatch optimization pitting five prompt scaffolds against a seven-case failure benchmark on the SWE 1.6 model found the RCAF structure (Role/Context/Action/Format) outscoring the previous STAR default by 33% (0.58 vs 0.44); a rerun and a 70-dispatch check across two other frontier models confirmed the ranking holds everywhere. So v1.0.5.0 makes RCAF the default for SWE-1.6 dispatches, with medium-density pre-planning (three to four steps — dense plans underperformed) and standard bundle-gate wording, since strict wording pushes the model toward defensive output. STAR stays available for narrative-heavy jobs and BUILD for multi-file refactors, but the two should not be combined. The medium-pre-planning guidance also became the shared standard across the master prompt card and the four sibling CLI skills.

#### MiniMax 2.7 provider, TIDD-EC prompts, Token Plan default
cli-opencode now treats MiniMax 2.7 as a first-class citizen. A new direct-API provider (minimax-2.7) is registered in the shared small-model registry and documented in cli-opencode, and a 10-iteration research loop plus a five-framework benchmark on the real model picked TIDD-EC with dense pre-planning as the winning prompt structure, now the integrated dispatch guidance. The default MiniMax path also switched to the subscription Token Plan provider (MiniMax-M3-highspeed, falling back to MiniMax-M2.7-highspeed) because the old pay-per-token id errors on current installs; the direct pay-per-token provider remains selectable so both billing models coexist. **Breaking:** the default MiniMax provider id changed from minimax/MiniMax-M2.7 to minimax-coding-plan — users who pinned the old id must reconfigure their opencode provider setup.
