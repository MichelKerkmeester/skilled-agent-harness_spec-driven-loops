# Docs-versus-reality audit for system-spec-kit 2.9.4.0

Read-only audit of the docs that describe four behaviors: the add-on set, the authoring card's validate step, the validator repair hint and the REQ/AC id numbering. Paths are relative to the worktree root, and `SSK` stands for `.skilled/skills/system-spec-kit`.

Ground truth read first:
- `SSK/templates/addons/` holds 7 files: acceptance-criteria, debug-delegation, decision-record, goal, handover, research, timeline. `SSK/templates/` holds 15 `.md.tmpl` files: 4 core, 7 add-ons and 4 packet-types. `spec-kit-docs.json` `versions` lists the same 15.
- `spec-kit-docs.json` levels 1, 2, 3 and 3+: `requiredCoreDocs` is spec, plan and tasks at every level. `optionalAddonDocs` is acceptance-criteria at Levels 2 and up. `lazyAddonDocs` is handover, debug-delegation, research/research.md, timeline, decision-record and goal at every numbered level. decision-record is lazy at Level 3, not required. `SSK/runtime/cli/spec/validate.sh:82-83` says the same: "3=+architecture guidance / decision-record.md and other add-ons are on-demand".
- `SSK/runtime/cli/spec/create.sh:692` sets `requested = ['timeline.md', 'decision-record.md']` for `--with-lazy-addons`. `create.sh:432-516` seeds 15 phrase arrays; the resource-map, before-after and roadmap arrays are gone.
- `SSK/references/workflows/spec-authoring-card.md:135-150` (section 9): run `validate.sh <folder> --strict --quiet` once after the last edit. On FAILED, run once without `--quiet`, fix every failing rule in one pass and rerun `--quiet`. That is one round, and the model stops after three rounds. When the output names `repair-derived.cjs ... --apply`, run it, then rerun.
- `SSK/runtime/lib/validation/orchestrator.ts:1485-1503` (`writeRepairHint`) prints the `--apply` command first, then what it rewrites, then "Optional: run it without --apply first".
- `SSK/templates/core/spec.md.tmpl:136` and `SSK/templates/addons/acceptance-criteria.md.tmpl:56,84` say a new id takes the highest id plus one, and the closure note forbids counts and id ranges.
- `SSK/runtime/cli/tests/template-fill-guidance.vitest.ts:8-9,63-94`: 4 levels x 4 docs = 16 cases, plus one case per add-on file (7) and one negative case. That totals 24 tests. This is inferred from the source; I did not run the test, as the brief asked.
