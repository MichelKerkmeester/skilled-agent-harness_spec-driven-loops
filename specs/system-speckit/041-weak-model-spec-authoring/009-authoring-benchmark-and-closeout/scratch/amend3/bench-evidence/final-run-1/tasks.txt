### Pre-Task Checklist

Before starting any task, confirm: the script path resolves, `git rev-parse --abbrev-ref HEAD` names the expected branch, the baseline in T002 is recorded, and the task's `Verify:` command has been run once against the unmodified tree so the "before" output is known.

### Execution Rules

| Rule | Meaning |
|------|---------|
| TASK-SEQ | Run tasks in numeric order; T003, T004, and T010 may run in parallel with their neighbours |
| TASK-SCOPE | Touch only the file named in parentheses on the task line |
| TASK-EVIDENCE | Mark a task `[x]` only after its `Verify:` command printed the expected output |
| TASK-REGRESSION | After T008, rerun T002 before running any other verification |

### Status Reporting Format

Report each task as `T### PASS|FAIL - <observed output>`. A failure names the command, its exit code, and the first differing line. Do not summarise a failure as "does not work".

### Blocked Task Protocol

Mark a task `[B]` when its `Verify:` command fails twice for the same reason, when the script's structure no longer matches the line numbers named in the plan, or when a change would be needed outside the two files in scope. Record the failing command and its output on the task line, then stop and report.
