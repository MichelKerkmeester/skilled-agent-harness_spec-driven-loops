### Execution Rules

| Rule | Applies To | Requirement |
|------|-----------|-------------|
| TASK-SEQ-01 | T004, T005, T006 | The global, the parser branch and the render branch land in that order; each `Verify:` runs before the next task starts. |
| TASK-SCOPE-01 | All tasks | Only `S` is edited. A file outside the scope stops the task and returns to the operator. |
| TASK-VERIFY-01 | T006 onward | No task is marked `[x]` without its `Verify:` command having run and its output read. |
| TASK-BASE-01 | T002, T010 | The default-output diff runs against the pre-change capture, never against a re-run of the changed script. |

### Status Reporting Format

Report each task as `T### <status> - <one-line evidence>`, where status is `done`, `in-progress` or `blocked`. Evidence is the observed command output, not a summary of intent.

### Blocked Task Protocol

Mark the task `[B]`, record the blocking condition and the command that exposed it beneath the task, and stop the phase. A blocked task is never marked `[x]` and never silently dropped; the packet closes with the block recorded.
