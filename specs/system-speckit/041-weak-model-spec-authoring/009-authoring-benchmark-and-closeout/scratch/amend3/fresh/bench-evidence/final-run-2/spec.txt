# Feature Specification: Add a quiet flag to recommend-level.sh

<!-- SPECKIT_LEVEL: 3 -->


---

## EXECUTIVE SUMMARY

The level recommender answers one question inside a 16- or 17-line report, so every caller that needs only the answer has to locate and parse a line within it. A `--quiet` flag prints that line and nothing else. The proof is a line count of one, a byte comparison against line 2 of the default report, and unchanged counts for the three shapes the script already produces.

**Key Decisions**: `--quiet` is a third output mode rather than a filter over the text report. One shared function emits the level line, so its literal has a single producer. `--quiet` combined with `--json` is rejected instead of resolved by precedence.

**Critical Dependencies**: the two `--json` callers in `speckit-plan.yaml` and `speckit-complete.yaml`, which must keep receiving their 36-line JSON object unchanged.

## 2. PROBLEM & PURPOSE

### Problem Statement

`output_text()` prints a blank line, the level line, the score line, a blank line, a six-line breakdown and a phase block: 16 lines for a simple input and 17 for the full flag set, measured today. A caller that needs the level alone cannot take `head -1`, because line 1 is blank, and cannot take `head -2` without also taking the score line, so it falls back to `grep` or `sed` over a report whose shape changes when `--no-recommend-phases` is passed. The `--json` mode is not a substitute for a one-value read: it returns a 36-line object.

### Purpose

Add `--quiet`, which prints exactly the line `Recommended Level: <N> (<Name>)` and exits 0, and leave the text and JSON paths byte-identical to what they print today.
<!-- /ANCHOR:problem -->

## 3. SCOPE

### In Scope
- Parse `--quiet` and its `-q` alias alongside the existing flags in section 5's argument loop.
- Emit the level line from one shared function that both the quiet path and the text report call.
- Reject `--quiet` together with `--json` as a usage error rather than picking a winner.
- List the flag in both help surfaces: the file header's OPTIONS block and `show_help()`.
- Prove the three existing output shapes are unchanged.

### Out of Scope
- Changing the level line's text, the score line or the breakdown - callers parse the label, so a format change belongs in its own packet.
- Suppressing stderr or changing exit codes - `--quiet` governs stdout only.
- Adding `--quiet` to the two YAML command assets - they pass `--json`, and no caller asked for the flag.
- Correcting the broken invocation examples in `references/workflows/execution-methods.md` line 165 and `README.md` line 514, which pass a positional argument the script rejects as an unknown option. That is a documentation defect with its own scope.

## 7. NON-FUNCTIONAL REQUIREMENTS

### Performance
- **NFR-P01**: The quiet path returns before the breakdown and phase echoes, so it cannot be slower than the default path on the same arguments. The flag adds no measurable runtime cost.

### Security
- **NFR-S01**: N/A. The script reads no credential, opens no network connection and writes no file, and the new flag changes none of that.

### Reliability
- **NFR-R01**: Exit codes stay as they are in every output mode: 0 on success and 1 on a usage or input error.

---

## 8. EDGE CASES

### Data Boundaries
- Empty input: `--quiet` with neither `--loc` nor `--files` reaches the existing validation, exits 1 and writes the usage error to stderr, leaving stdout empty.
- Maximum: `--loc 999999 --files 999999` caps each score at its weight and still prints one line.

### Error Scenarios
- Unknown option beside `--quiet`: exit 1, stderr names the option, stdout stays empty.
- `--quiet` with `--json`: exit 1, stderr names both flags, stdout stays empty.

### State Transitions
- Flag order: `--json --quiet` and `--quiet --json` behave identically, because the conflict is checked after the parse loop rather than inside it.
- `--help` with `--quiet`: help wins and exits 0, because `show_help` exits inside the parse loop before any output mode runs.
