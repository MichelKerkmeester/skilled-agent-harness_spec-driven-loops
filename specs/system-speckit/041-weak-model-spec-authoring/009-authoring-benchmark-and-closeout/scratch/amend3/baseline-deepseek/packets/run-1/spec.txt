# Feature Specification: Add a quiet flag to recommend-level.sh

<!-- SPECKIT_LEVEL: 3 -->

---

## EXECUTIVE SUMMARY

`recommend-level.sh` always prints a full report: level, score, confidence, a
four-row breakdown and an optional phase section. A caller that wants only the
level has to capture that report and filter it. This packet adds an opt-in
`--quiet` / `-q` flag that prints exactly one line, `Recommended Level: N (Name)`,
and changes nothing when the flag is absent.

**Key Decisions**: quiet affects the human-readable renderer only; `--json` output
is unchanged. The flag name and short alias follow the `--quiet, -q` convention
already used by sibling spec scripts.

**Critical Dependencies**: None beyond the Bash runtime already required by the
script. No new packages, no configuration.

## 2. PROBLEM & PURPOSE

### Problem Statement

`output_text()` prints seven to fourteen lines for a single answer. Automation
that needs the level, such as a hook or a shell prompt helper, has to capture the
whole report and parse the first line or grep for `Recommended Level:`. That
filtering is repeated in every caller and breaks silently if the report's leading
blank line or section order ever changes.

### Purpose

Give callers a documented, stable one-line output mode so the level can be read
without parsing the report, while leaving every existing invocation unchanged.
<!-- /ANCHOR:problem -->

<!-- ANCHOR:scope -->
## 3. SCOPE

### In Scope

- A `--quiet` flag with the `-q` short alias on `recommend-level.sh`
- A quiet branch in the text renderer that prints only the recommended-level line
- Header comment and `show_help()` entries for the new flag, including how it
  composes with `--json`
- A shell regression harness covering quiet output, default-output parity and
  the error paths

### Out of Scope

- Changing the default report, its wording or its section order - existing
  callers and human readers depend on it
- Changing the JSON schema or adding a quiet-specific JSON payload - JSON is
  already machine-readable and carries `recommended_level`
- Changing scoring, thresholds, phase logic or exit codes - unrelated to the
  flag and out of scope for this packet
- Adding `--quiet` to other spec scripts - `validate.sh`,
  `progressive-validate.sh` and `check-completion.sh` already implement it, and
  each has its own output contract

### Files to Change

| File Path | Change Type | Description |
|-----------|-------------|-------------|
| `.skilled/skills/system-spec-kit/runtime/cli/spec/recommend-level.sh` | Modify | Add `--quiet`/`-q` parsing, a `QUIET_OUTPUT` global, a quiet early return in `output_text()`, and help text |
| `.skilled/skills/system-spec-kit/runtime/cli/tests/recommend-level-quiet-flag.sh` | Create | Regression harness for quiet output, default parity and error paths |

## 4. REQUIREMENTS

### P0 - Blockers (MUST complete)

| ID | Requirement |
|----|-------------|
| REQ-001 | `--quiet` and `-q` are accepted by the argument parser and set quiet mode without consuming a value. |
| REQ-002 | With `--quiet` and text output, stdout contains exactly one line: `Recommended Level: <level> (<name>)`, with no leading blank line, no score line, no breakdown and no phase section. |
| REQ-003 | Without `--quiet`, stdout and stderr are byte-identical to the pre-change script for every input in the test matrix. |
| REQ-004 | Exit codes are unchanged: `0` on a successful recommendation, `1` on the existing usage and validation errors. Quiet mode never suppresses a stderr error message. |

### P1 - Required (complete OR user-approved deferral)

| ID | Requirement |
|----|-------------|
| REQ-005 | `--quiet` composes with the existing flags (`--loc`, `--files`, `--auth`, `--api`, `--db`, `--architectural`, `--recommend-phases`, `--no-recommend-phases`, `--phase-threshold`) in any order, and repeating it is idempotent. |
| REQ-006 | `--quiet` combined with `--json` leaves the JSON payload unchanged; quiet is a documented no-op in JSON mode so the schema stays single and stable. |
| REQ-007 | The script header OPTIONS block and `show_help()` both document `--quiet, -q` and the JSON composition rule. |

<!-- ANCHOR:risks -->
## 6. RISKS & DEPENDENCIES

| Type | Item | Impact | Mitigation |
|------|------|--------|------------|
| Dependency | Bash 3.2 compatibility (macOS system bash) | A construct such as `${var,,}` would fail on the default macOS shell | Use the script's existing `[[ "$VAR" = true ]]` idiom; no new Bash-4-only syntax |
| Dependency | `set -euo pipefail` | An unset `QUIET_OUTPUT` aborts the run | Initialize the global beside `JSON_OUTPUT` before parsing; test the no-flag path first |
| Risk | A quiet branch placed at the wrong layer changes the JSON path too | Breaking change for `speckit-plan.yaml` and `speckit-complete.yaml` callers | Guard inside `output_text()` only; `output_json()` stays untouched and is diff-tested |
| Risk | Option parsing regresses on a value that looks like a flag | Existing `--loc --quiet` style misuse changes behavior | Keep the existing `[[ "$2" =~ ^-- ]]` guards; add matrix rows for missing values |
<!-- /ANCHOR:risks -->

## 7. NON-FUNCTIONAL REQUIREMENTS

### Performance
- **NFR-P01**: The flag adds one boolean branch; total runtime stays within the
  script's current startup cost and adds no measurable latency for either mode.

### Security
- **NFR-S01**: The flag accepts no value and opens no new input surface. The
  script continues to read no environment secrets and writes no files.

### Reliability
- **NFR-R01**: Output is deterministic for identical inputs. Quiet mode emits the
  same level and name the default report's first line emits.
- **NFR-C01**: Default text output and JSON output are backward compatible
  byte-for-byte; no in-repo caller needs a change.

---

## 8. EDGE CASES

### Data Boundaries
- Empty input: `--quiet` alone still fails the existing `At least --loc or --files`
  validation, exits `1`, and writes the error to stderr only.
- Maximum length: not applicable; the flag carries no value.
- Large inputs: `--loc 2000 --files 40 --quiet` still prints one line; phase
  scoring runs exactly as it does today.

### Error Scenarios
- Missing numeric value after `--loc` or `--files`: unchanged `ERROR:` on stderr
  and exit `1`, even when `--quiet` is also present.
- Unknown option: unchanged `ERROR: Unknown option` on stderr and exit `1`.
- `--quiet` repeated: idempotent, one line.
- `--quiet --json`: JSON payload unchanged; quiet has no effect in JSON mode.
- `--quiet --help`: help prints in full and exits `0`; help takes precedence.

## 11. USER STORIES

### US-001: One-line level for automation (Priority: P0)

**As an** automation author wiring `recommend-level.sh` into a hook or prompt
helper, **I want** a flag that prints only the level, **so that** I can read one
value without parsing a report whose formatting I do not control.

**Acceptance criteria:** see `acceptance-criteria.md` (AC-001 through AC-007).

---

### US-002: Quiet answer for a human operator (Priority: P1)

**As an** operator checking a task's level in a terminal, **I want** a concise
answer on demand, **so that** I can see the level without scrolling past a
breakdown I did not ask for.

**Acceptance criteria:** see `acceptance-criteria.md` (AC-003, AC-008).
