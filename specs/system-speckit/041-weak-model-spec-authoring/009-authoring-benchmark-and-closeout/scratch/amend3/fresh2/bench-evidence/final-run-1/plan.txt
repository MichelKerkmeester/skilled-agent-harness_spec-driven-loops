### Overview

<!-- ANCHOR:architecture -->
## 3. ARCHITECTURE

### Pattern
Single-script flag branch.

### Key Components
- **Argument parser**: the `while [[ $# -gt 0 ]]; case "$1"` loop at lines 656-719 of `recommend-level.sh`. It already handles `--json|-j`, `--no-recommend-phases` and `--phase-threshold`.
- **Renderers**: `output_text` at lines 508-558 and `output_json` at lines 562-649. Each reads the scored globals and writes to stdout.
- **Output dispatch**: lines 770-774 choose a renderer from `JSON_OUTPUT`. The quiet branch joins this decision point.

### Data Flow
Arguments set globals, the scoring functions fill `TOTAL_SCORE`, `determine_level` sets `RECOMMENDED_LEVEL` and `LEVEL_NAME`, and one renderer prints. `--quiet` changes only the renderer choice. Scoring, confidence and phase calculation run exactly as they do today.
<!-- /ANCHOR:architecture -->

Required inventories:
- Same-class producers: `rg -n 'Recommended Level' .skilled/skills/system-spec-kit/runtime/cli/spec/recommend-level.sh` returns the header comment, the `output_text` line and the help text. Only `output_text` emits the line at runtime, so the quiet renderer reuses that string.
- Consumers of changed symbols: `rg -n 'recommend-level\.sh' . --glob '*.sh' --glob '*.js' --glob '*.ts' --glob '!node_modules/**' --glob '!specs/**'` returns the script and two test files. No shell caller parses the report.
- Matrix axes: flag combination (none, `--quiet`, `--json`, both) by phase mode (default, `--no-recommend-phases`) by input validity (valid, missing numbers, non-numeric, unknown option). Twelve rows, four of them covered by the new test and the rest by the verification tasks.
- Algorithm invariant: the quiet line equals the first content line of the default report, with the leading blank line removed. The invariant breaks if either renderer builds its own label, so both read `RECOMMENDED_LEVEL` and `LEVEL_NAME` through one shared string.

## L3: ARCHITECTURE DECISION RECORD

### ADR-001: A flag rather than an environment variable or a new format

**Status**: Proposed

**Context**: A caller needs the level without the report. The script already takes options, and `--json` returns a whole object.

**Decision**: Add `--quiet` to the existing parser. It sets a global and selects a renderer.

**Consequences**:
- The caller opts in per invocation, so no state leaks between runs.
- One more option to document and test.

**Alternatives Rejected**:
- Environment variable `SPECKIT_QUIET`: hidden from `--help`, easy to inherit into unrelated runs.
- `--json` piped to a JSON parser: adds a parser dependency and returns more than the caller asked for.
- A new `--format level` option: new vocabulary for a single use.

---

### ADR-002: JSON wins when both `--json` and `--quiet` appear

**Status**: Proposed

**Context**: A shared argument builder can pass both machine-oriented flags.

**Decision**: `--json` takes precedence. The quiet renderer only replaces the human report.

**Consequences**:
- One documented rule: `--quiet` affects text output.
- A caller that asks for JSON still receives parseable JSON.

**Alternatives Rejected**:
- Quiet wins: a JSON request would return a text line, which is surprising and harder to detect.
- Reject the pair with exit 1: breaks argument builders that always append `--quiet`; adds a failure path for no gain.
