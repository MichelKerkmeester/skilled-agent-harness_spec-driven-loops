## Per version, newest first

### v0.23.0.0 (`v0.23.0.0.md`)

The official app-backed `obsidian` CLI was named as one of the skill's three surfaces but was never documented well enough to drive, so this release measured the installed binary and replaced the guesses. It adds `references/official-cli-agent-usage.md`, an agent contract observed against desktop 1.13.7 (installer 1.13.4) that carries the `obsidian version` preflight, the exit-0 failure contract and the stdout check that replaces `$?`, the `obsidian <command> key=value` grammar with the global `vault=` option, a grouped index of all 106 commands and confirmed parameters for the 13 an agent uses most. It adds an `OFFICIAL_CLI` router intent at weight 6 so official-CLI questions stop resolving to `NOTES_CLI`, an `examples/official-cli-workflow.sh` round trip, a live `obsidian version` probe in `scripts/doctor.sh` and two new troubleshooting sections (§5b app-not-running, §5c exit-0-on-error). BREAKING for anyone relying on the old prose: the claim that the CLI launches the desktop app is false and was removed from 17 lines across 8 files, one of them a table row labelled `Confirmed behavior`. With the app down the CLI exits 1 and leaves the app down. RENAME of the documented invocation: `obsidian --help` was replaced with `obsidian help` in 15 files, and the entry corrects its own first reason, noting that `--help` does exit 0 and print full help while `-h`, `-v` and `--version` print `Error: Command "<flag>" not found` on stdout and still exit 0. Positional examples such as `obsidian "<vault/path>"` became `obsidian open file="<name>"`. `SKILL.md` went 0.22.0.0 to 0.23.0.0.

In its place a new `references/plugins/make-md/` 4-file tree plus a catalog entry documents Make.md (`Make-md/makemd`, id `make-md`, v1.3.5+): the Spaces and Contexts model, the formula library and view types, the field types and the `.space` on-disk format (`def.json` plus `context.mdb` and `views.mdb` SQLite over `m_schema` and `m_fields`). ### v0.14.0.0 (`v0.14.0.0.md`)

Closes the deeper findings of the plugin-coverage deep review, two of them genuine safety fixes. BREAKING for any script feeding an unvalidated plugin id: BRAT install now validates `PLUGIN_ID` against `^[A-Za-z0-9._-]+$` before it is interpolated into the vault plugin path, in `references/plugins/obsidian42-brat/workflows.md` and the `brat-headless-install.md` scenario, so a hostile release manifest supplying `../` or `/` in `.id` can no longer escape `.obsidian/plugins/`. Previously only a non-empty and not-`null` check ran. The second fix makes `examples/mcp-roundtrip.sh` fail safe: a non-404 error from `obsidian_get_note` now re-throws instead of falling through to an empty-content write, so a transient auth or transport failure can no longer overwrite a real note. The TLS caveat in `references/mcp-tools.md` and the same script was scoped to loopback, stating that disabling cert verification is safe only because the endpoint is `127.0.0.1` and the bearer token must never go to a non-loopback host with verification off. The human-readable resource-loading display in `SKILL.md` was completed to eleven plugin reference sets, matching the router that already resolved all eleven. `SKILL.md` went 0.13.0.0 to 0.14.0.0.

## Facts the v4 draft gets wrong or misses

The draft is `specs/system-speckit/033-system-speckit-v4/CHANGELOG-v4.0.0.0.md`. It mentions the vault in exactly three places: line 36, line 397 and the `sk-code-obsidian` surface packet at line 307. Line 397 is the only paragraph about this mode.

- **Draft line 397 sells the official CLI as a working surface and misses that this release cycle proved much of its documentation false.** `v0.23.0.0.md` removed the "the CLI launches the desktop app" claim from 17 lines across 8 files, one of them labelled `Confirmed behavior`, and established that the CLI exits 0 on error so `$?` is not a usable check. The draft's phrase "the official app-backed CLI" gives no hint that a user following the older prose would be following measured-false instructions.
- **Draft line 397 misses the 106-command surface and the new agent contract.** `v0.23.0.0.md` added `references/official-cli-agent-usage.md` with the `obsidian version` preflight, the `key=value` grammar, the global `vault=` option and confirmed parameters for the 13 most-used commands. This is the single largest usability change in the covered range and the draft says nothing about it.
- **Draft line 397 says "references for the plugins you are most likely to lean on" and never mentions that three plugins were removed outright.** `v0.21.0.0.md` deleted Excalidraw and Project Manager, and `v0.22.0.0.md` deleted Beancount Finance, each taking a reference tree, a catalog entry, router intents and in two cases assets, examples and playbook scenarios. A reader with habits pinned to those docs gets no warning, which is exactly the class of change the draft flags elsewhere at line 403 and line 444.
- **The draft misses Make.md and Meta Bind entirely.** `v0.22.0.0.md` added the `make-md` tree and `v0.21.0.0.md` added the `meta-bind` tree with the JS Engine companion. Both are now in the mode's own `SKILL.md` description and keyword list, so the draft's plugin picture is a cycle behind.
- **The draft misses the vault roster.** `v0.20.0.0.md` created `references/plugins/installed-plugins.md` covering all enabled vault plugins including the ones that intentionally get no docs, and `v0.21.0.0.md` reconciled it to 24. The draft has no equivalent statement of scope.
- **The draft misses the two security fixes.** `v0.14.0.0.md` added the BRAT path-traversal guard on `PLUGIN_ID` and made the Code Mode round trip fail safe instead of overwriting a real note on a non-404 read error. The draft's own framing at line 13 is that "the failure paths got the same care", so these belong there and are absent.
- **The draft implies a 4.0.0.0 maturity that this mode explicitly disclaims.** `v0.12.0.0.md` reset the whole package from a `1.x` track to a `0.x` track precisely because a 1.0 readiness declaration was never made, and the mode ships at 0.23.0.0. Nothing in the draft reconciles a v4 release note with a pre-1.0 component.
- **Draft line 397's two rough edges are not confirmable from these ten entries.** The claims that title search is broken headlessly and that the installed REST API exposes a different tool set than the documented server appear in none of v0.12 through v0.23. They are neither corrected nor restated in the covered range, so this digest cannot mark them stale or current. `v0.19.0.0.md` does add a dedicated `obsidian-local-rest-api` reference tree, which is adjacent but does not speak to a tool-set gap.
