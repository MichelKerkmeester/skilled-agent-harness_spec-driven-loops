Skill path: `.opencode/skills/system-spec-kit/`. Changelog path: `.opencode/skills/system-spec-kit/changelog/`. Versions covered: v3.5.0.1 (oldest) through v3.9.0.0 (newest), the last 10 of 35 entries. No entry carries an explicit date in its body, so no date range can be stated. The only dated marker found is inside v3.7.0.0.md, which says the search-surfacing work was added late in that cycle on 2026-06-26.

## Per version, newest first

### v3.9.0.0

Five template and context optimizations out of a deep-research packet (`v3.9.0.0.md`). The research template stopped rendering all 944 lines at every level and is now level-gated, so a Level 1 packet gets roughly 175 lines while Level 3, 3+ and phase still render byte-for-byte identically. The spec, plan, tasks and implementation-summary templates each held four near-identical per-level copies and were consolidated into one shared core plus per-level addenda, about 55 percent less source, with a per-level render-hash gate proving identical output. CHANGED DEFAULT: the `AC_COVERAGE` validation rule flipped from disabled to on by default as a non-blocking INFO advisory that never warns, errors or blocks `--strict`. A new opt-in advisory rule `check-scope-adherence.sh` (`SCOPE_ADHERENCE`) was added, driven by `SYSTEM_SCOPE_CHANGED_FILES` or `SYSTEM_SCOPE_BASE`, warning when changed files fall outside a packet's declared "Files to Change". `memory_search` gained a token budget on its own response, dropping lowest-score results first and emitting feedback telemetry only for results actually returned. Documentation was reconciled and the registry rule count is stated as 46. The originating 033 research packet was MOVED into 034, with its synthesis, four fan-out lineages and source context now living under `034/research/`.

### v3.8.0.0

Documentation only (`v3.8.0.0.md`). The system-spec-kit README was rewritten from a tabular reference card into the purpose-first narrative standard, opening with a one-line pitch and a problem-first OVERVIEW modeled on the mcp-obsidian pilot. The validation story was corrected to 45 registered rules with four strict-only rules gated behind `--strict`, replacing stale 36-of-38 counts. The lifecycle diagram was updated to current Gate 3 options including Option E for skip. RENAME of the version field only: the README frontmatter version moved from `3.6.0.99` to `3.8.0.0` to close the gap with the changelog history. The entry explicitly states that every shipped behavior claim survived the rewrite, including the four documentation levels, the phase parent lean trio, the packet-local changelog workflow, the five retrieval channels and the FSRS decay tiers.

### v3.7.0.0

The largest entry of the ten (`v3.7.0.0.md`), covering search honesty, search surfacing, spec metadata quality, the skill advisor, the code graph, the deep loop and a flag reckoning. Search verdicts must now be earned: a lexical-grounding floor requires real keyword evidence behind a top hit, a measured corpus noise floor keyed to nomic-embed-text-v1.5 is subtracted before the verdict is read, thin evidence caps a good verdict down to weak, and the evidence-gap warning was rewired to key off relevance instead of a peakedness statistic. A live `memory_search` that returned one result where it should have returned many was traced to trigger-lane matches being excluded from surfaced results and to budget overflow being deleted rather than degraded, and the same query then returned six. CHANGED DEFAULT: twelve previously default-off flags graduated to default-on or enforcing, covering the metadata integrity gates and the search-honesty suite. REMOVED: the `SPECKIT_DETERMINISTIC_RANKING` flag was deleted, so a set value no longer does anything. CHANGED DEFAULT: the code-graph reverse-dependency degree cap moved from uncapped to fifteen, chosen by a cost sweep. Spec metadata got a closed status set, a real validator and a migration across 2,049 spec folders with zero violations, and reads stopped dirtying the tree. A ten-iteration deep review on opus caught the freshly wired bitemporal edge writer returning both the old and the new edge on every live read, a silent corruption a green test suite never exercised, which was fixed and re-reviewed clean. Eight dark-flag families were measured, four graduated and four were cut, including the per-class retrieval weights, the save reconsolidation, the seeded PageRank and the closed-vocabulary edge governance.

### v3.6.0.0

A broad core release (`v3.6.0.0.md`). Search fixes centered on honest citable answers, a memory-safe keyword fallback that held warmup at 137MB against a prior 687MB spike, full result sets for scoped queries, scope isolation on the broaden-and-rescue path and a single score name on a plain 0-to-1 scale. Memory safety added a fail-closed secret scrubber ahead of hashing and indexing, a provenance guard that blocks automated overwrites of human-authored fields, tier and pin aware retention, and vector self-heal for damaged shards. The three daemons gained recovery, a single-writer lock and scriptable command-line front doors exposing 37 tools for spec-memory, 8 for code-index and 9 for skill-advisor. CHANGED DEFAULT: the daemon connection cap rose from eight to 64, and daemon re-election became on by default in the launcher itself rather than only via config. The five deep-loop skills folded into one hub with every `/deep:*` command and agent name unchanged. RENAME: `SPECKIT_SKILL_ADVISOR_HOOK_DISABLED` became `SYSTEM_SKILL_ADVISOR_HOOK_DISABLED`. REMOVED: the `mcp-magicpath` hosted-canvas skill was removed, leaving `mcp-open-design` as the active design transport, and the upgrade note tells readers to switch design work to `mcp-open-design`. Three new design skills arrived, `sk-design-interface`, `mcp-open-design` and `mcp-figma`. Markdown files were dropped from default code-graph indexing behind a maintainer flag.

### v3.5.0.5

The dual-stack release (`v3.5.0.5.md`). The MCP transport had been the memory system's only door, and a dropped transport lost all 37 tools for the rest of a session because the client never reconnects. This shipped `node .opencode/bin/spec-memory.cjs`, a daemon-backed CLI fronting the identical 37-tool surface over the same unchanged daemon, generated at runtime from `TOOL_DEFINITIONS` so no manifest can drift. A shared exit taxonomy was set across all three sibling CLIs: 0 success, 1 runtime error, 64 usage or schema error, 69 protocol or dist mismatch and 75 retryable daemon error. A `--warm-only` mode probes the socket and exits 75 instead of cold-spawning, so prompt-time hooks fail open at about a millisecond. Claude and Codex hooks gained a shared warm-only CLI fallback helper. A new `system-spec-memory.js` OpenCode plugin closed the gap where OpenCode memory access was MCP-only, using CLI and IPC transport exclusively so the dual-writer hazard cannot return. A 64KB pipe-truncation hazard was fixed with drain-awaited natural exits. The MCP registration was deliberately untouched, and MCP removal was recorded as a separately gated later decision.

### v3.5.0.4

Closed the daemon lifecycle work v3.5.0.2 had deferred (`v3.5.0.4.md`). A converged two-model investigation found the flap was the launcher's own shutdown handler killing the daemon child while a 250ms relaunch timer respawned it under a dying runtime. The relaunch is now gated at fire time on shutdown state and parent pid. Five deferred hardening items shipped as phases 018 through 022: a persistent bounded launcher log (`SPECKIT_LAUNCHER_LOG`, default on), reap hardening requiring N consecutive deep-probe failures (`SPECKIT_LEASE_PROBE_RETRIES`, default 1), a code-index reconnect, a flag-gated default-off orphan sweep, and the daemon survival foundation. CHANGED DEFAULT: daemon re-election was turned on by default in the runtime configs via `SPECKIT_DAEMON_REELECTION=1` across all three runtimes, with the launcher code default staying off so `0` is a one-character revert. An eleven-lineage multi-model review then serialized the stale-reclaim reap under the respawn lock and replaced it with true adoption of a live released daemon. REMOVED from tracking: a tracked local Claude settings file that leaked machine-specific permissions was untracked and gitignored, with its portable hooks moved into shared tracked settings.

### v3.5.0.3

Documentation only (`v3.5.0.3.md`). The 22 skill READMEs were rewritten into one narrative voice, opening with a one-line pitch, an At a Glance table and a problem-first overview, after ranging from 228 to 1084 lines with no shared shape. The sk-doc skill-README template was updated to encode the narrative skeleton, so new skills start in the voice. The system-spec-kit README was restyled in place rather than regenerated to protect its dense reference content, moving from 1084 to 1067 lines. Each README was gathered and verified against the skill's real files by a two-model pass, which caught real drift including a wrong MCP tool namespace and config key, a code skill listing a surface that no longer existed and a scorer README describing a single embedder where the shared registry now holds several. Voice rules were fixed as no em dashes, no double-hyphen separators, no semicolons, no Oxford-comma lists and no filler.

### v3.5.0.2

A session-scoping and integrity patch (`v3.5.0.2.md`). MCP transports had been dying mid-session because `session-cleanup.sh` fell back to the hook's parent pid when `CLAUDE_SESSION_PID` was missing, which under a shared terminal resolved to an ancestor common to every open session, so one session ending swept away its siblings' MCP launchers by name. CHANGED BEHAVIOR: missing session identity now means the cleanup does nothing at all, and ancestry is re-proven against the live parent chain immediately before each kill, with `matched_by=` and `ancestor_ok=` logged. A post-crash integrity gate now runs a whole-database `quick_check` when an `.unclean-shutdown` marker is present at open, writing a `.needs-rebuild` sentinel and refusing to serve rather than serving corrupted rows. The gate immediately found genuine b-tree damage in the live `context-index.sqlite`, which `sqlite3 .recover` salvaged at 9,888 of 9,890 rows with 368 orphaned rows parked in `lost_and_found` and the corrupted original preserved beside it.

### v3.5.0.1

A small configuration and documentation patch (`v3.5.0.1.md`). The live `.codex/hooks.json` had drifted and registered Claude's hook scripts for every event, so Codex sessions ran through the wrong adapters. `SessionStart` and `UserPromptSubmit` now point at the Codex-native hooks. REMOVED: the `PreCompact` registration was removed outright rather than rewired, because the hook contract lists Codex compaction as unsupported. A Codex MCP config note that had the code-graph database default and legacy paths backwards was corrected to match the launcher source. A repair to the broken OpenCode code-graph plugin bridge was applied, smoke-verified and then deliberately reverted, because the runnable bridge initialized the memory database directly in its own process outside the daemon's single-writer lease. The entry states plainly that no code changes ship in this release and that the OpenCode code-graph plugin remains unavailable by deliberate choice.

## Facts the v4 draft gets wrong or misses

- Rule count. Draft line 82 says "Forty rules are registered" for the completion gate. `v3.8.0.0.md` states 45 registered rules with four strict-only, and `v3.9.0.0.md` states the registry rule-count references are "now 46" after `SCOPE_ADHERENCE` was added. The draft never says six rules were removed, so a reader tracking the count sees 45, then 46, then an unexplained 40.
- `SCOPE_ADHERENCE` is missing entirely. `v3.9.0.0.md` documents `check-scope-adherence.sh` as a new opt-in advisory rule with the `SYSTEM_SCOPE_CHANGED_FILES` and `SYSTEM_SCOPE_BASE` inputs. The draft's completion-gate section (line 82) and its migration list (lines 443 to 445) name neither the rule nor the two environment variables.
- `AC_COVERAGE` default change is missing. `v3.9.0.0.md` records the acceptance-coverage rule flipping from disabled to default-on as a non-blocking INFO advisory with a 0.9 floor and a manual-infeasible escape hatch. Draft line 82 introduces `acceptance-criteria.md` as deciding closure at Levels 2 and 3 but never mentions that the coverage check itself now runs by default and never blocks.
- Template consolidation is presented as v4 work. Draft line 100 describes the spec, plan, tasks and implementation-summary consolidation and the level-gated research template as this release's change. `v3.9.0.0.md` already shipped exactly that. The draft's "1,275 lines across four core templates" figure has no counterpart in the changelog, which states "about 55% less source", and the draft drops the concrete research-template numbers (944 lines down to roughly 175 at Level 1).
- The specs move may predate v4. Draft lines 22 and 64 present the move from `.opencode/specs/` to a top-level `specs/` as a v4 breaking change. `v3.5.0.1.md`, `v3.5.0.2.md`, `v3.5.0.4.md` and `v3.5.0.5.md` all cite packet paths under `.opencode/specs/`, but `v3.9.0.0.md` already cites its spec folder as `specs/system-speckit/033-spec-template-context-optimization/`. The move had therefore landed by the v3.9.0.0 entry.
- The decommission inventory is incomplete. Draft lines 23, 70 and 445 list the memory database, the embedder, the spec-memory MCP server, its daemon and the `memory_search` and `memory_save` tools as removed. `v3.5.0.5.md` also shipped `node .opencode/bin/spec-memory.cjs`, a daemon-backed CLI over the same 37 tools, and the `system-spec-memory.js` OpenCode plugin. Neither appears anywhere in the draft, so a reader who adopted the CLI as their transport-down door is not told what became of it.
- MagicPath contradiction. Draft line 36 lists MagicPath among the bridges hanging off `mcp-tooling`, and line 389 describes `mcp-magicpath` as a live component and design-system lookup over a `cli` manual. `v3.6.0.0.md` states the `mcp-magicpath` hosted-canvas skill was removed, with the upgrade note telling readers to switch design work to `mcp-open-design`. The draft also removes Open Design (line 294). The reversal may be real, but the draft never says MagicPath came back, so the two documents read as a straight conflict.
- Environment-variable renames and removals are missing from the migration list. Draft line 443 lists renames to adopt and names only `MK_HOOKS_DISABLED` to `SYSTEM_HOOKS_DISABLED`. `v3.6.0.0.md` records `SPECKIT_SKILL_ADVISOR_HOOK_DISABLED` renaming to `SYSTEM_SKILL_ADVISOR_HOOK_DISABLED`, and `v3.7.0.0.md` records `SPECKIT_DETERMINISTIC_RANKING` being removed outright. Neither appears at lines 443 to 445.
- The advisor CLI front door is dated to v4. Draft line 39 credits this release with giving the skill advisor "a CLI front door". `v3.6.0.0.md` already shipped scriptable command-line front doors for all three daemons, naming 9 tools for skill-advisor, and `v3.5.0.5.md` describes the sibling CLIs sharing one exit taxonomy. Draft line 116 is accurate by contrast, since it correctly names the older specs-only deny-list from `v3.6.0.0.md` as the thing being replaced.
