## Contract mismatches

1. The route metadata's advisor_status command omits required workspaceRoot; this is visible in _routes.yaml:55-56 against the CLI manifest's required input at skill-advisor-cli-manifest.ts:83-86. The workflow adds the root, but the route's own command declaration remains incomplete.
2. The workflow reads data.embeddings.provider and data.embeddings.modelServer, but the strict advisor_status output schema has no embeddings property. The handler returns that schema as data (advisor-status.ts:317-329,360-370; advisor-tool-schemas.ts:319-336). The runtime command with a root could not be observed because the sandbox returned EPERM; see doctor-run.log.
3. The workflow promises a strictly read-only report, while the CLI shim calls fs.mkdirSync for its IPC directory (skill-advisor.cjs:85-92). The default path is /tmp/system-skill-advisor (lines 21-28), outside the allowed scratch path. That directory existed before the check, so the audit did not need to create it; a fresh run may.
4. Provider selection data exists in the embedding factory and model health exists at the model server's /api/health endpoint, but neither is joined into the advisor_status output (factory.ts:602-619,1128-1130; hf-model-server.cjs:45,838-853; advisor-tool-schemas.ts:319-336).
5. The live health values are UNKNOWN because the sandbox denied IPC with EPERM. This is not evidence that the provider or model server is unhealthy.
