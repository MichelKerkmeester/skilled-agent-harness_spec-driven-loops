# Proposal: Code Mode debug workflow

## Verdict: fix

Keep /doctor:mcp debug and narrow it to Code Mode, its seven project registrations and the root .utcp_config.json. The current YAML says “all supported servers”, defaults its filter to all five, lists an empty TOML path and absent VS Code config, and reports System Code Graph (.skilled/commands/doctor/assets/doctor-mcp-debug.yaml:25-31, :53-69, :94-110, :239-247). The actual doctor checks one server, code_mode, and only opencode.json, .claude/mcp.json and .vscode/mcp.json (.skilled/commands/doctor/scripts/mcp-doctor.sh:138-146, :259-303). The saved health run has three failures: unreadable Node engine manifest, missing dist/index.js and missing node_modules (specs/system-speckit/048-doctor-command-audit/002-mcp-debug-code-mode/scratch/doctor-run.log:1-21).

Keep the redesign aligned with the sibling install proposal: require Node 24 from the server manifest, stop before npm install/build if package.json is missing, register only the seven project configs present, leave Hermes user-level, and do not invent a project .hermes/config.yaml or add absent .vscode/mcp.json (specs/system-speckit/048-doctor-command-audit/001-mcp-install-code-mode/scratch/proposal.md:15-17, :23-34). The build command remains npm install followed by npm run build in mcp-server. This audit did not run it (specs/system-speckit/048-doctor-command-audit/001-mcp-install-code-mode/scratch/proposal.md:17; .skilled/commands/doctor/assets/doctor-mcp-debug.yaml:103-110).

## Diagnose sequence

1. Parse only debug and optional --fix. Reject --server because Code Mode is the single target. Run bash .skilled/commands/doctor/scripts/mcp-doctor.sh --json without passing --fix to that script. The script's --fix flag invokes install.sh or npm install/build, so the YAML must not forward the public flag into the read-only diagnostic call (.skilled/commands/doctor/mcp.md:51-54; .skilled/commands/doctor/scripts/mcp-doctor.sh:68-82, :236-253; .skilled/commands/doctor/assets/doctor-mcp-debug.yaml:121-130).

2. Check the Code Mode build without writing. Require .skilled/bin/mcp-code-mode-launcher.cjs, mcp-server/package.json, package-lock.json, tsconfig.json, index.ts, node_modules and dist/index.js. Read engines.node from package.json and use the launcher's resolver. This project requires Node >=24.0.0 and <25.0.0, while the current doctor only checks >=20.11.0 and the package manifest is missing (.skilled/skills/mcp-code-mode/INSTALL-GUIDE.md:144-163; .skilled/skills/mcp-code-mode/mcp-server/package-lock.json:32-34; .skilled/commands/doctor/scripts/mcp-doctor.sh:103-111, :139-146). Run the existing read-only Code Mode helper with --strict to check node_modules, required imports and dist syntax (.skilled/skills/mcp-code-mode/scripts/doctor.sh:5-16, :39-80). Do not treat dist/index.js existence alone as proof that the build is current.

   Define currentness with an input fingerprint created by a successful build. Hash the embedded server source files, package.json, package-lock.json and tsconfig.json into a small build-state file under dist. Diagnosis recomputes the digest and requires a match, then requires node --check to succeed. A missing state file or digest mismatch is stale or unknown and must not display PASS. The current tree has no package.json, dist or node_modules, so it cannot pass today (specs/system-speckit/048-doctor-command-audit/002-mcp-debug-code-mode/scratch/reality-check.md:22-24; specs/system-speckit/048-doctor-command-audit/002-mcp-debug-code-mode/scratch/doctor-run.log:10-14). This is the only extra build artifact proposed. Without it, the existing health helpers check presence and syntax but cannot distinguish an old dist from one produced from the current inputs (.skilled/commands/doctor/scripts/mcp-doctor.sh:192-200; .skilled/skills/mcp-code-mode/scripts/doctor.sh:62-80).

3. Check every project Code Mode registration with a format-aware parser.

   - For opencode.json, require mcp.code_mode.type=local, command node plus .skilled/bin/mcp-code-mode-launcher.cjs, and environment.UTCP_CONFIG_FILE=.utcp_config.json (opencode.json:11-19).

   - For .pi/mcp.json, also preserve transport stdio and lifecycle lazy (.pi/mcp.json:3-10).
   - For .codex/config.toml, parse TOML and require [mcp_servers.code_mode], command node, launcher args and UTCP_CONFIG_FILE=.utcp_config.json (.codex/config.toml:11-16). Use the Python 3.11 tomllib validation specified by the sibling install proposal. If that parser is unavailable, report Codex config as unvalidated and do not claim PASS (specs/system-speckit/048-doctor-command-audit/001-mcp-install-code-mode/scratch/proposal.md:34).

   Do not count a matching key alone as a pass. The current helper checks key presence and uses grep for TOML, not the launcher or UTCP_CONFIG_FILE values (.skilled/commands/doctor/scripts/mcp-doctor-lib.sh:202-240). Hermes is not a project config target. Report that its MCP registration lives in ~/.hermes/config.yaml and is operator-managed; do not create or edit a repo .hermes/config.yaml (.hermes/SYNC.md:8-14, :37-44). Remove .vscode/mcp.json because it is absent (specs/system-speckit/048-doctor-command-audit/002-mcp-debug-code-mode/scratch/reality-check.md:35-47; specs/system-speckit/048-doctor-command-audit/001-mcp-install-code-mode/scratch/proposal.md:23-34).

Require valid JSON, a manual_call_templates array, unique JavaScript-identifier names, a supported call_template_type and the documented config shape for each type. For MCP entries, validate config.mcpServers and the required fields for stdio or SSE. Validate HTTP, CLI and file forms against .skilled/skills/mcp-code-mode/references/configuration.md:162-185, :189-197, :208-252, :254-282. The current file has 14 entries and a CLI entry named magicpath without the required config field; report the exact manual name and missing field (.utcp_config.json:143-149; .skilled/skills/mcp-code-mode/scripts/validate_config.py:217-220; .skilled/skills/mcp-code-mode/references/configuration.md:222-242).    For every environment-variable reference in a manual, compute the required environment key as manual name + underscore + referenced name, following Code Mode's prefix rule. 5. Probe live tools only when debug is already running inside a connected Code Mode host session. Call native list_tools() and compare the returned manual-name prefixes with configured manual names. ## --fix behavior

--fix offers scoped repairs after the full diagnosis. Keep per-repair approval; remove “auto-repair all”, which contradicts the invariant's per-fix approval language (.skilled/commands/doctor/assets/doctor-mcp-debug.yaml:25-31, :74-83, :151-175).

- It may rebuild the embedded server only after package.json, package-lock.json, tsconfig.json and source are present, the manifest's Node range resolves, and the operator approves. Use the sibling sequence: cd .skilled/skills/mcp-code-mode/mcp-server && npm install && npm run build. Then rerun the strict health helper, verify the fingerprint and rerun the read-only doctor. Do not call scripts/install.sh: its verification path runs npm install when node_modules is missing and checks dist existence without building it (specs/system-speckit/048-doctor-command-audit/001-mcp-install-code-mode/scratch/proposal.md:17; .skilled/skills/mcp-code-mode/scripts/install.sh:351-400).
- It may add a missing Code Mode registration to an existing supported project config after showing a minimal patch and receiving approval for that file. Preserve unrelated config values and runtime-specific fields. For an existing incorrect entry, show the exact replacement diff and require approval. Reparse the changed file before reporting it repaired.
- It must only report invalid JSON/TOML, malformed manual objects, missing credential values, unknown build currentness, unsupported Node range and Hermes user-level status. It must not rewrite .utcp_config.json, guess or create manual credentials, alter .env or .env.example, delete manuals, repair absent Hermes config or create .vscode/mcp.json. Manual creation and secret setup belong to the install workflow (.skilled/skills/mcp-code-mode/INSTALL-GUIDE.md:223-245, :405-481, :485-508; .hermes/SYNC.md:8-14, :37-44).
- Never pass --fix to mcp-doctor.sh. After each approved change, run the full diagnostic without --fix and repeat all static checks. Run list_tools() only if the existing connected-host condition above holds (.skilled/commands/doctor/scripts/mcp-doctor.sh:68-82; .skilled/commands/doctor/assets/doctor-mcp-debug.yaml:201-215).
