## What Was Built

Four functions walked up the tree to find the system-spec-kit package root: two byte-identical copies in the eval scripts with different marker lists, and two predicates in the shared package with different caps and fallbacks. One compiled module now carries the walk, `shared/workspace/package-root.ts`, with a nullable `findPackageRoot` and a throwing `resolvePackageRoot`, a fixed three-marker set and an optional depth cap. All four callers use it. The repository resolver and the shell resolver stay because each sits on a boundary the compiled walk cannot cross, and the shared README says so. A parity test builds three fixture repositories and shows the package, repository and shell resolvers naming consistent roots on each.

### Files Changed

| File | Action | Purpose |
|------|--------|---------|
| `shared/workspace/package-root.ts` | Created | The one package-root walk |
| `shared/config.ts`, `shared/embeddings/factory.ts` | Modified | Predicates replaced by calls to the shared walk |
| `runtime/cli/evals/check-source-dist-alignment.ts`, `check-architecture-boundaries.ts` | Modified | Local copies removed; marker list imported |
| `runtime/cli/tests/package-root-parity.vitest.ts` | Created | Package, repository and shell resolvers on the same trees |
| `shared/README.md` | Modified | The surviving count and the boundary that keeps each |

<!-- ANCHOR:how-delivered -->
## How It Was Delivered

The resolver inventory was regenerated by grep before any edit, then narrowed to the walks that find the package root; the many functions that find a specs root, a skill root or a git root are different targets and were left alone. Each caller of the two shared predicates was listed, which showed both to be in-file and collapsible. The shared package was typechecked, built and tested first, then the CLI's `npm run check`, which is the consumer of both eval scripts, then the parity test, then the four research lanes that had touched these files.
<!-- /ANCHOR:how-delivered -->

<!-- ANCHOR:decisions -->
## Key Decisions

| Decision | Why |
|----------|-----|
| The compiled walk lives in shared, not in the CLI | Both shared predicates and both CLI scripts need it, and shared may not import from the CLI |
| One marker set for every caller | A partial checkout without `runtime/cli` is not a root anywhere |
| Keep the repository and shell resolvers | Source-before-build and bash are boundaries a compiled module cannot serve |

## Known Limitations

1. **The eval scripts now need the shared package built.** They import the compiled walk; the CI check job builds shared before it runs them, and a local run needs the same.
2. **Specs-root, skill-root and git-root finders are out of this scope.** They find different targets and were inventoried, not merged.
