# Deep Research Strategy: Rule-corpus consumer census

## Research Topic

Map every live consumer of the repository-root `repo-rules/` corpus and determine what breaks when the corpus moves to `.skilled/repo-rules/` with a tracked per-entry symlink farm left at the root. Three questions:

- **Q1 — in-repo consumers outside `specs/`**: which tracked files name a rule file or the rules directory as a live path, at file:line, and what changes for each (26 router rows in `REPO RULES.md`, 13 rule-body backlinks to `../REPO%20RULES.md`, `AGENTS.md`'s five links, the corpus checker, the sk-doc `sk-create-repo-rule` skill and its manual-testing-playbook, the `/create:repo-rule` command and its assets, the two authored agent files, the sk-communication benchmark generator).
- **Q2 — generators, mirrors, CI and gate inputs**: which of `.claude/agents`, `.pi/agents`, `.codex/agents` and `.hermes/skills` are generated and from which authored source; which script checks each; what `.github/workflows/repo-rules-corpus.yml` and `.github/scripts/check-gate-inputs.sh` key on; whether the trigger index, corpus-manifest, generation-diagnostics and phrase-variants artifacts can be regenerated byte-identically.
- **Q3 — external consumers and portability**: what sibling repositories link into; how `check-repo-rules.cjs` can probe `.skilled/repo-rules` before `repo-rules` while keeping its nine checks and resolving router rows by link target.

## Known Context

- The detached lineage is bound directly to `config.fanout_lineage_artifact_dir`; the `resolveArtifactRoot` node is intentionally skipped.
- All writes are bounded to this lineage directory. Spec writeback, parent/shared telemetry, continuity/memory save, and git staging are out of scope.
- Current pre-migration state at the repository root: `repo-rules/` holds 13 tracked markdown files; `.skilled/repo-rules/` does not exist yet; `repo-rules/` entries are regular files, not symlinks.
- `resource-map.md` was not present at initialization; this lineage emits its own resource map from the completed deltas.
- The packet spec (`../spec.md`) frames this phase as: move the 13-file corpus to `.skilled/repo-rules`, leave a tracked per-entry symlink farm at the root, and re-point every live reference in this repository at the canonical path. Sibling repositories that link into the root path stay untouched because the farm keeps their links resolving.
- Stop policy is `max-iterations` (3): every iteration runs; convergence is telemetry only.

## Answered Questions

- Q1 answered in iteration 1 (see `iterations/iteration-001.md`): 26 `REPO RULES.md` router links (13 trigger rows 40-52 + 13 index rows 60-72); 9 `AGENTS.md` instances on 5 lines (28,116,144,209,261) against the spec's count of 5; 13 rule-body backlinks that each need one extra `../`; the checker's four layout couplings (RULES_DIR:26, findRepoRoot:46-48, loadContext:182-186, error:412) and nine checks; the skill/README/reference/playbook lines; the command's `rules_dir` bindings (auto:113, confirm:126) and presentation strings (103,108); the two authored agent files (orchestrate.md:850, markdown.md:203); and the benchmark generator's two lanes (69,108-113,127).
- Q2 answered in iteration 2 (see `iterations/iteration-002.md`): authored agents at `.skilled/agents/*.md`; `.claude/agents` a required parity mirror and cursor/devin dialect source; `.pi`/`.codex` generated by their sync scripts; `.hermes/skills` generated from skill SKILL.md plus agent personas. Checkers: `check-agent-mirror-sync.cjs` (claude/codex/opencode), `sync-agents.cjs --check` (codex), `agent-roster-mirror-check.cjs` (roster), `sync-skills-hermes.cjs --check` (hermes), `sync-agents-pi.cjs --check` (pi, documented only). `repo-rules-corpus.yml` keys on four path filters plus a fail-closed `.opencode` checker path; `check-gate-inputs.sh` enforces five text rules with strict `.opencode`↔`.skilled` twin matching, so any `.skilled/repo-rules/**` filter needs its `.opencode/repo-rules/**` twin. The trigger-index pipeline walks specs + `.skilled/skills` + `.skilled/hooks`, is tested byte-identical for a fixed corpus, and embeds one `manifestHash` across index, manifest, diagnostics and variants — so the migration must regenerate all four together.
- Q3 answered in iteration 3 (see `iterations/iteration-003.md`): the one observable sibling links with absolute targets into `Public/repo-rules/<rule>.md` (documented shape is relative), the farm keeps them resolving, and re-pointing siblings is out of scope. The checker contract (plan §5.4) probes `.skilled/repo-rules` then `repo-rules`, fails naming both, identifies router rows by resolved containment (following the farm so mid-move passes), and keeps the nine checks and output unchanged. Farm integrity is a separate phase-verification script (planned `scratch/verify.sh`, not yet present).
- All three questions are answered. The "three sibling repositories" count and the two unobserved siblings remain UNKNOWN from this snapshot.

## What Worked

- A single tree-wide `rg repo-rules` excluding `specs/` and the runtime mirrors produced the full outside-specs consumer set in one pass; the runtime mirrors resolve to the same files via symlinks, so counts are not duplicated.
- Reading `check-repo-rules.cjs` end to end pinned the exact couplings (RULES_DIR, findRepoRoot, loadContext, prefix-based row detection, body-link resolution base) instead of inferring them from the spec.
- Reading the packet `spec.md` §2-§4 first converted "what changes" from a guess into the spec's own REQ-002/REQ-003 obligations and Out-of-Scope list.
- Link counting with `rg -o ... | wc -l` settled the 26-link and 9-instance counts exactly and surfaced the spec's `AGENTS.md (5)` count as a line-count interpretation.
- Following each mirror from its generator (`SOURCE_DIR` constants) to its checker gave a closed mapping instead of a guess; the `.hermes` mirror turned out to cover the sk-doc SKILL.md leaves too.
- Reading the filter-twins awk machinery showed the migration's CI filter change is gate-constrained: a `.skilled/repo-rules/**` entry needs an `.opencode/repo-rules/**` twin in the same `paths:` group.
- The trigger-index suite states the determinism contract precisely (byte-identical second run, canonical text, cross-artifact hash equality), which is stronger evidence than generator code alone.
