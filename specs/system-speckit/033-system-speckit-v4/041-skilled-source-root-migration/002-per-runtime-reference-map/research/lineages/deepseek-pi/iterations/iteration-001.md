## Findings

- **Finding 1 — `.claude` is four link families, not one.** 33 generated command mirrors, 21 generated hook mirrors, 3 hand-made whole-directory/root-file links (`skills`, `manual-testing-playbook`, `.utcp_config.json`). 56 of 57 resolve into `.opencode/`; the only exception is `.claude/.utcp_config.json -> ../.utcp_config.json`, whose target (repo-root `.utcp_config.json`) does not move. **Classification:** `regenerate` for the 54 generator-owned rows, `mechanical` for the two whole-dir links, `none` for `.utcp_config.json`. **Consequence:** a literal `grep .opencode` over `.claude` finds 56 rows, but the internal `.claude/skills` split means the whole-tree consumer surface is one link, not a per-skill list. - **Finding 2 — the required target for every into-`.opencode` link splits cleanly by compatibility assumption.** With a surviving `.opencode` compatibility link, **no raw target changes**: every relative target already traverses `.opencode/...`, and that path keeps resolving to the real file. Without it, each relative target must swap the `.opencode/` segment for `.skilled/`; the link's own depth is unchanged (`.claude/commands/create/agent.md` keeps `../../../`, only the first path segment changes), so a single prefix substitution per row is exact. Worked example: `.claude/commands/agent-router.md` is `../../.opencode/commands/agent-router.md` today and must become `../../.skilled/commands/agent-router.md`; `.claude/hooks/spec-gate-enforce.mjs` is `../../.opencode/skills/system-spec-kit/runtime/hooks/claude/spec-gate-enforce.mjs` today and must become `../../.skilled/skills/system-spec-kit/runtime/hooks/claude/spec-gate-enforce.mjs`. **Classification:** `regenerate`. **Consequence:** the two answers differ for all 75 into-`.opencode` rows in these two sections; every row table carries both.

- **Finding 3 — the link generator itself hardcodes `.opencode`, so regeneration before generator retargeting reproduces stale links.** `sync-runtime-mirrors.cjs` sources commands from the literal `OPENCODE_COMMANDS = '.opencode/commands'` (L41) and scans hook config files for the literal pattern `/\.opencode\/[A-Za-z0-9_./-]+?\.(mjs|cjs|js|sh|py)/g` (L110). Hook mirrors are therefore derived from the `.opencode` strings inside `.claude/settings.json` and `.codex/hooks.json`; retargeting the links without retargeting those config strings respawns links to the old tree on the next sync. **Classification:** `manual` for the generator change (it is a code decision), `regenerate` for the links it owns. **Consequence:** the generated-link rows are not independently editable; their fix belongs to the generator row in Map C (`.opencode/skills/system-spec-kit/runtime/cli/runtime-mirrors/sync-runtime-mirrors.cjs`).

- **Finding 4 — `.claude/settings.json` and `.codex/hooks.json` are themselves rendered from `hook-registry.json`, and `.claude/SYNC.md` says otherwise.** `sync-hook-registrations.cjs` renders the hooks key of `.claude/settings.json` (L144-148, L216-226) and the whole of `.codex/hooks.json` (L151-153) from `.opencode/skills/system-spec-kit/runtime/cli/runtime-mirrors/hook-registry.json`. `.claude/SYNC.md` calls `settings.json` "hand-authored", and `.codex/SYNC.md` calls `hooks.json` "hand-authored". The tree and the renderer agree with each other and disagree with the manifests; the manifests are stale. **Classification:** `regenerate` for both config files (regenerate, do not hand-edit). **Consequence:** Map B's rows for `.claude/settings.json` and `.codex/hooks.json` are generator-owned and must be fixed at the registry, not in the rendered file.

- **Finding 5 — `.claude/SYNC.md` lists two whole-directory links that do not exist.** Its surface table names a `specs` link and a `changelog` link; the live `.claude/` directory contains only `.utcp_config.json`, `SYNC.md`, `agents/`, `commands/`, `mcp.json`, `hooks/`, `manual-testing-playbook`, `settings.json`, `skills`, `statusline-command.sh`. It also says "`hooks/*` (18 symlinks)" while the tree has 21. **Classification:** `manual` (the manifest needs correcting as part of the move). **Consequence:** anyone executing the move from the manifest instead of from the tree would create links nobody loads; the seed inventory is the authoritative link set.

- **Finding 6 — `.codex` has one hand-made link and two generated trees that are not links.** 18 of 19 `.codex` links are hook mirrors regenerated by `sync-runtime-mirrors.cjs` from `.codex/hooks.json`; the 19th is the whole-dir `manual-testing-playbook` link. `.codex/agents/*.toml` and `.codex/prompts/*.md` are real generated files (`sync-agents.cjs`, `sync-prompts.cjs`), so they are Map B rows, not Map A rows. **Classification:** `regenerate` (18), `mechanical` (1). **Consequence:** Map A alone does not move Codex; its two owned trees are regenerated from source.

- **Finding 7 — the with-compat answer has one precondition worth stating.** A raw target that traverses `.opencode/` stays correct only while `.opencode/<sub>` exists and resolves to the same real path. If `.opencode` keeps a compatibility link only for some subpaths (for example `skills/`, `commands/`, `agents/` but not `hooks/`), then the with-compat answer applies per-subpath, not per-runtime. The row tables give the no-compat answer unconditionally and flag the with-compat answer as "unchanged, subject to the `.opencode/<sub>` path surviving". **Classification:** `mechanical` when the compatibility surface is defined; `manual` until it is.

- **Finding 8 — dangling and absolute targets in these two sections: none.** Every `.claude` and `.codex` link is relative and resolves today (seed columns `target_kind=relative`, `dangling=no` for all 76). **Classification:** `none` (no pre-existing breakage to repair). **Consequence:** the four dangling links and four absolute-target links reported by the seed live elsewhere (`.opencode`, `specs`), and iteration 3 covers them.
