# Iteration 4: Map B — non-symlink runtime files that reference outdated paths

## Focus

Map B: every non-symlink file under a runtime root that names `.opencode` (231 files: `.claude` 17, `.codex` 50, `.cursor` 7, `.devin` 4, `.hermes` 103, `.pi` 50), plus the home-level configuration each runtime reads.

## Findings

- **Finding 1 — 231 runtime files carry the path, and 197 of them are generated, not authored.** The generated families: Codex prompts 33 (`sync-prompts.cjs`) and agents 12 (`sync-agents.cjs`); Pi prompts 34 (`sync-prompts-pi.cjs`) and agents 12 (`sync-agents-pi.cjs`); Hermes prompts 33 (`sync-prompts-hermes.cjs`) and skills 68 (`sync-skills-hermes.cjs`); the four hook-registration files rendered from `hook-registry.json` (`sync-hook-registrations.cjs`); one generated Gate 1 block (`sync-gate1-pointers.cjs`). **Classification:** `regenerate`. **Consequence:** none of these 197 files should be text-edited during the move; each names its generator in its first line, so the generator constants are the real migration surface.

- **Finding 2 — the pointer stubs embed the canonical path twice, so a naïve retarget doubles the edit.** Each Codex/Pi/Hermes prompt stub carries the source path in a `Generated by … from .opencode/commands/...` comment and again as the body's canonical location. The tracked inventory counts 33+34+33 prompt files; each hit-line count is 2. **Classification:** `regenerate`. **Consequence:** after the generator is retargeted, regeneration rewrites both lines; editing the stubs by hand would leave the provenance comment lying.

- **Finding 3 — the four hook-registration files execute `.opencode` paths on every session, and their content is derived from one registry.** `.claude/settings.json` (22 matching lines), `.codex/hooks.json` (18), `.cursor/hooks.json` (18), `.devin/hooks.v1.json` (23). The registry is `.opencode/skills/system-spec-kit/runtime/cli/runtime-mirrors/hook-registry.json`; editing a rendered file is drift by definition. **Classification:** `regenerate`. **Consequence:** the registry is the single edit point for all four runtimes' hook execution, and `install-codex-hooks.mjs` must run afterward to reconcile `~/.codex/hooks.json`.

- **Finding 4 — five hand-authored MCP/server registrations each hardcode the launcher path `.opencode/bin/mcp-code-mode-launcher.cjs`.** `.claude/mcp.json` (the canonical file the root `.mcp.json` links to), `.cursor/mcp.json`, `.devin/mcp_config.json`, `.pi/mcp.json`, `.codex/config.toml` (which also carries the project trust entry). **Classification:** `mechanical` (one path edit each) with a preference to keep a `.opencode/bin/` compatibility path so all five keep working. **Consequence:** these five are the runtime-side twin of the Map C blocker on the launcher itself; a launcher move without these edits breaks the MCP surface in five places.

- **Finding 5 — `.cursor/mcp.json` is a real file, not the symlink its own manifest documents.** `.cursor/SYNC.md` lists `mcp.json` as "symlink → `../.mcp.json` → `.claude/mcp.json` (double hop)"; the live file is a real 223-byte JSON file with the same content as `.claude/mcp.json`. **Classification:** `manual` (manifest correction), `mechanical` for the path edit. **Consequence:** a retarget that assumes it is a link (delete + relink) would clobber a real file; the seed's symlink census has no row for it, which is consistent with the real-file finding.

- **Finding 6 — `.hermes/plugins/repo-guards/__init__.py` is the only runtime-native code file with hardcoded paths.** Ten path constants under `REPO_ROOT / ".opencode" / ...` (L30-45) shell out to hook cores; the plugin docstring (L6) says so. **Classification:** `mechanical` (segment rewrite in each constant). **Consequence:** it fails silently if left, because Hermes loads project plugins only behind `HERMES_ENABLE_PROJECT_PLUGINS=1`; the guard layer would simply stop covering sessions.

- **Finding 7 — the Claude agent fork is 12 real files and a README, held to `.opencode/agents/` by a gate, and it is Map B's most manual surface.** 18+7+7+3+… matching lines per agent, spanning runnable commands, skill references and prose path citations. There is no generator; `check-agent-mirror-sync.cjs` only verifies the pair. **Classification:** `mechanical` for the path rewrite (a scripted rewrite works), `manual` for the decision to keep the fork in lockstep and for the README's crosswalk references. **Consequence:** the *same* edit has to land in `.opencode/agents/*.md` and `.claude/agents/*.md`, or the pre-commit gate blocks the migration commit; and Cursor's and Devin's agent mirrors resolve through the `.claude` copy, so the fork is transitively load-bearing for three runtimes.

- **Finding 8 — the home-level surface is 10 live locations, and the git hooks are the blocker.** From the count-only inventory (`home-refs.tsv`): `~/.codex/hooks.json` (18 `.opencode` command strings), `~/.codex/config.toml` (1 trust entry), `~/.hermes/config.yaml` (1 launcher reference), `~/.claude.json` (1), `~/.zshrc` (2), `~/.pi/agent/SYNC.md` (2), `~/.pi/agent/trust.json` (1), and the seven absolute symlinks under `~/.config/git/hooks/` that point into the main checkout's `.opencode/scripts/git-hooks/`. `~/.codex/AGENTS.md`, `~/.pi/agent/{settings.json,models.json,modes.json,statusline.sh,pi-cache-optimizer-config.json}` are symlinks back into the repository, so they follow it. `~/.config/devin/*`, `~/.claude/settings.json` and `~/.claude/CLAUDE.md` show zero occurrences. **Classification:** `blocker` for the seven git hooks (they serve every repository on the machine and dangle the moment the checkout moves), `manual` for the other operators' configuration, `none` for the symlinks that follow the repo. **Consequence:** no in-repository validator covers any of this class; the phase-001 finding stands and the move cannot be verified from CI alone.

- **Finding 9 — the seed counts and the rows reconcile exactly, and the per-runtime table below is the full inventory.** `.claude` 17, `.codex` 50, `.cursor` 7, `.devin` 4, `.hermes` 103, `.pi` 50 — the same figures as `summary.md`'s `runtime:*` areas.
