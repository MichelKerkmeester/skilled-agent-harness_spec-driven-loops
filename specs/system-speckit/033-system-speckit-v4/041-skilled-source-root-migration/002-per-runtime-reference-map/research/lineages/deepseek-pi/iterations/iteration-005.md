# Iteration 5: Map C — skills `system-spec-kit` and `system-deep-loop`

## Focus

Map C, the two largest skills: `system-spec-kit` (729 files, 20,027 matching lines) and `system-deep-loop` (787 files, 3,497 matching lines). For each: the artifact classes (SKILL.md, README.md, references, assets, scripts, runtime code, tests and fixtures, feature catalog, manual testing playbook, changelog, benchmark material), every code file that constructs/matches/hardcodes the path with its first matching line, and the runnable/prose/historical split of the documentation.

## Findings

- **Finding 1 — these two skills are 36% of every tracked file naming `.opencode` (1,516 of 4,258) and 63% of all matching lines (23,524 of 37,084).** Any rewrite budget that treats skills uniformly will be dominated by `system-spec-kit`'s trigger index alone: `.opencode/skills/system-spec-kit/runtime/data/trigger-index.json` carries 1,809 matching lines as a list of repository-relative paths (`generate-trigger-index.mjs` output). **Classification:** `regenerate`. **Consequence:** the index is not rewritten; it is regenerated after the corpus moves, and the generator's own `.opencode` corpus marker must be retargeted first. [SOURCE: .opencode/skills/system-spec-kit/runtime/cli/retrieval/generate-trigger-index.mjs:71,61-88]

- **Finding 2 — the root sentinel lives in this skill and is the phase-001 blocker.** `shared/workspace/repo-root.mjs` carries `REPO_ROOT_SENTINEL` as `.opencode/skills/system-spec-kit/SKILL.md` and matches a literal `.opencode` path segment in `hoistAboveOpencodeTree()`. **Classification:** `blocker` (cannot be done as proposed without either keeping `.opencode/skills/system-spec-kit/SKILL.md` resolvable or changing the sentinel contract for every consumer). **Consequence:** Map C cannot fix this with a rewrite; it is a design decision, and phase 001 already recorded it as the load-bearing compatibility requirement. [SOURCE: .opencode/skills/system-spec-kit/shared/workspace/repo-root.mjs:6,26-45]

- **Finding 3 — `system-spec-kit`'s code surface is 323 non-markdown files: 119 source, 129 tests, 31 frozen benchmark JSON, 26 manual test-fixture JSON, 8 generated metadata, and 10 others.** The code rows below carry the first matching construct for each. A mechanical segment rewrite (`.opencode` -> `.skilled`) covers the 258 mechanical rows; the generated metadata rows are rebuilt by their owners; the benchmark reports are frozen records. **Classification:** `mechanical` 258, `freeze` 31, `manual` 26, `regenerate` 8. **Consequence:** the 129 test files are the risk inside this class: a scripted rewrite that skips them leaves the suite asserting the old root, and a rewrite that edits expected-output fixtures silently changes what the tests expect.

- **Finding 4 — `system-deep-loop`'s code surface is 118 non-markdown files: 37 source, 47 tests, 8 frozen benchmark data, 4 manual fixtures, 3 generated metadata.** `compile-command-contracts.cjs` alone carries 79 matching lines, most of them canonical source paths for the compiled command contracts; `legacy-projection-manifest.ts` (6) carries runtime-relative state templates. **Classification:** `mechanical` 103, `freeze` 8, `manual` 4, `regenerate` 3. **Consequence:** the compiled contracts and the legacy projections are derived state with named owners; retargeting the generator and re-running it is the change, not editing the artifacts. [SOURCE: .opencode/skills/system-deep-loop/runtime/scripts/compile-command-contracts.cjs:14] [SOURCE: .opencode/skills/system-deep-loop/runtime/lib/legacy-projections/legacy-projection-manifest.ts:171]

- **Finding 5 — the documentation split is not uniform between the two skills.** `system-spec-kit`: 116 historical files (69 changelog + 47 benchmark) that must not be rewritten, 79 playbook files, 35 feature-catalog files, 35 references, 67 top-level docs, and 59 test docs. `system-deep-loop`: 261 playbook files, 139 feature-catalog files, 77 top-level docs, 87 historical (76 changelog + 11 benchmark), 43 references. Fenced lines (running code) are a small minority in both: 672 of 2,128 counted lines for spec-kit, 271 of 2,218 for deep-loop. **Classification:** `freeze` for changelog and benchmark classes, `mechanical` for references/playbook/catalog/top docs, `manual` for the unclassified remainder. **Consequence:** a bulk `sed` over skill markdown would rewrite history in ~200 files and change what the changelog says happened; the freeze class must be excluded before any rewrite.

- **Finding 6 — the links inside both skill trees travel with the tree and are not part of Map C's code surface.** Map A iteration 3 counted 50 internal `.opencode/skills/` links (shared references, scripts, fixtures, two build links). The docs and code tables here count only non-symlink files, so nothing is double-counted. **Classification:** cross-reference only.

- **Finding 7 — generator ownership inside these skills is specific and citable.** `generate-trigger-index.mjs` owns `runtime/data/trigger-index.json`; `regenerate-skill-derived.cjs` owns `graph-metadata.json` files; `generate-leaf-manifest.cjs` and siblings own `leaf-*.json`; the deep-loop `compile-command-contracts.cjs` owns the compiled contracts; the runtime `dist/` trees are build output (not in the tracked seed, gitignored). **Classification:** `regenerate` for each artifact, `manual` for the generator edits themselves. **Consequence:** the owning-command list from phase 001 is corroborated here file by file, with the difference that all of these generator sources are themselves Map C code rows that hardcode `.opencode`.

- **Finding 8 — the exact row counts reconcile against the seed.** `system-spec-kit`: 406 markdown + 323 non-markdown = 729 files (seed: 729). `system-deep-loop`: 669 + 118 = 787 (seed: 787). Matching lines: 20,027 and 3,497 (seed totals). The class tables below enumerate all 1,516 files.
