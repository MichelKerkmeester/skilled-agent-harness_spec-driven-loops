## Findings

- **Finding 1 — none of the 208 internal links names `.opencode` in its raw target.** Verified by counting `target_names_opencode=yes` over the `.opencode` root: zero. Their raw targets are relative paths inside the tree (`../../skills/...`, `../../../plugins/...`, `../dist`). **Classification:** `mechanical`. **Consequence:** a retarget driven by matching the string `.opencode` in link targets silently skips the entire internal surface; only a directory move or an explicit link-object enumeration reaches it. [SOURCE: symlinks.tsv, `.opencode` rows, `target_names_opencode` column]

- **Finding 2 — for internal links both required-target answers are "the raw target does not change"; the compatibility question decides whether the link object moves.** With a surviving `.opencode/<sub>` path, the link object can stay where it is and resolve through the directory compatibility link. Without it, the link object must move with its target tree into `.skilled/`; the relative raw target is then unchanged because `.skilled/` sits at the same depth as `.opencode/` and the tree topology inside is preserved. **Classification:** `mechanical` (a directory move, not a per-link edit). **Consequence:** the internal surface costs nothing if the move is wholesale, and everything if a hybrid layout leaves some link objects in `.opencode/` while their targets move.

- **Finding 3 — the internal surface is five browsability indexes plus two build artifacts.** 101 hooks index links in `.opencode/hooks/` (documented as the browsable index of every repo-authored hook; the real code stays in its owning skill or plugin), 49 changelog index links in `.opencode/changelog/`, 5 install-guide links, 1 manual-testing-playbook link, 1 `.opencode/specs -> ../specs` link, and 2 build-artifact links (`runtime/cli/runtime -> ../dist`, `runtime/shared -> ../shared/dist`). The remaining 49 skills links are shared-reference, script and test-fixture links inside skill trees. **Classification:** `mechanical` for the hand-made index links, `regenerate` for the 2 build links (`plugin.js`-style links resolve only after a build). [SOURCE: .opencode/hooks/README.md:30,248-260] [SOURCE: .opencode/skills/system-spec-kit/runtime/cli/runtime-mirrors/sync-runtime-mirrors.cjs:154-157]

- **Finding 4 — four internal links are already broken today, before any move.** (a) `.opencode/changelog/sk-design-md-generator -> ../skills/sk-design-md-generator/changelog`; the target skill directory no longer exists. (b) `.opencode/changelog/sk-doc/create-diagram -> ../../skills/sk-doc/sk-create-diagram/changelog`; `sk-create-diagram` no longer exists under `sk-doc/`. (c) `.opencode/skills/sk-doc/scripts/validate-flowchart.sh -> ../sk-create-diagram/scripts/validate-flowchart.sh`; same retired directory. (d) `.opencode/plugins/sk-vision.js -> ../skills/sk-vision/vision-runtime/dist/plugin.js`; the dist build is absent (build artifact, so absence is expected until built). **Classification:** (a)-(c) `manual` (retire the stale index entry or restore the target; not a migration edit), (d) `regenerate` (rebuild sk-vision's vision-runtime). **Consequence:** these four rows must not be counted as migration breakage, and the move must not "fix" them by accident; the seed's `dangling=yes` column identifies them.

- **Finding 5 — `specs/` holds 29 links, all but 3 of them historical run artifacts.** 20 are vendored-reference skill links inside the `evilcharts` reference research context (`.claude/skills/* -> ../../.agents/skills/*`), 4 are absolute links into *different checkouts* (`048-crawlable-commit-history`, and `…/036-goal-unification/…/hostile/outside`), all 4 already dangling, 1 is a deep-research reducer self-link, 1 is a changelog link. **Classification:** `freeze` — historical records of past runs that must not be rewritten. **Consequence:** the move writes nothing under `specs/`; the 4 dangling absolute links stay dangling and are already outside this repository's repair scope.

- **Finding 6 — exactly 3 `specs/` links resolve into `.opencode`, all in `z_archive/022-hybrid-rag-fusion`, and they are the only Map A rows under `specs/` that the move can affect.** `feature_catalog`, `manual_testing_playbook` and `system-spec-kit` link to `.opencode/skills/system-spec-kit` and its `feature-catalog`/`manual-testing-playbook` children. Without a compatibility link they dangle; with one they keep working. **Classification:** `freeze` for the archived packet (do not rewrite historical links), with the dangling outcome named rather than chosen. - **Finding 7 — the two root-level links need no change.** `CLAUDE.md -> AGENTS.md` and `.mcp.json -> .claude/mcp.json` both target files that do not move. **Classification:** `none`. **Consequence:** neither is a migration row, though `.claude/mcp.json` itself carries a `.opencode` path (Map B) and `.cursor/mcp.json` turns out to be a **real file**, not the symlink `.cursor/SYNC.md` documents — recorded here because it belongs to the same MCP hop chain and is corrected in Map B.

- **Finding 8 — the internal index links have no regenerator anywhere in the tree.** An exhaustive `symlinkSync`/`ln -s` sweep over the seven runtime directories plus `.opencode` returns only `sync-runtime-mirrors.cjs` (the five runtime mirror trees), the git-hook installers, and build/migration scripts; nothing recreates `.opencode/hooks/`, `.opencode/changelog/`, `.opencode/install-guides/` or the skill-internal links. **Classification:** `manual` for the decision of who owns each index (hand-edit vs write a generator), `mechanical` for the retarget itself. **Consequence:** if the move deletes and recreates `.opencode/` as a shell, these links are lost unless a script or a person recreates them.
