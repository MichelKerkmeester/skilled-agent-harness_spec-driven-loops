HOW TO WORK

Take one or two sections per iteration and make them complete rather than skimming all of
them. Reconcile your row counts against the seed inventory at the end of each section: a
section that lists fewer links or files than the inventory holds is incomplete, and says which
rows it has not yet mapped. Stop when a further iteration would add no new rows.

Classify every row as one of:
- `mechanical` — a scripted retarget or path rewrite handles it;
- `regenerate` — produced by a named command, so rebuild it rather than edit it;
- `manual` — someone has to decide something;
- `freeze` — a historical record of a past run that must not be rewritten;
- `none` — names the path but needs no change, with the reason;
- `blocker` — cannot be done as proposed, with the reason.

Every row carries a `file:line` citation, or for a symlink the link path. A claim you could
not verify is marked UNKNOWN with what would settle it, never dropped. Where two sources
disagree, name both.

The synthesis presents Map A, Map B and Map C in that order, each with its reconciliation
against the seed counts, then the UNKNOWNs. Do not propose a cutover order: that is the next
phase's work.
