## Per version, newest first

### v3.0.0.0 (`v3.0.0.0.md`)

BREAKING: `sk-prompt` stopped being a parent hub and became a standalone routed-resource skill, and the small-model prompt-craft capability it used to dispatch to was retired with no replacement path. REMOVED: the per-model reference set (DeepSeek-v4-pro, Kimi-k2.7-code, MiniMax-M3, MiMo-V2.5-Pro, GLM-5.2, Composer-2.5), the model registry indexing them, the per-model context budgets, the quota-fallback and output-verification references and the pattern index, so a prompt naming only a model no longer resolves to that model's CLI executor through the advisor's alias table. REMOVED: the whole hub routing surface (`mode-registry.json`, `hub-router.json`, `description.json`, `command-metadata.json` and the stage-two `ROUTER.md`), plus the feature catalog, all forbidden or pointless on a standalone root. REMOVED: the skill is withdrawn from the compiled-routing serving closure and its live-activation fence, so prompt-engineering requests now reach it directly by advisor identity instead of through two-stage hub resolution. RENAME: the nested engine packet's `references/`, `assets/`, `manual-testing-playbook/`, `changelog/`, `SKILL.md` and `README.md` were git-renamed up to the skill root, which is why the version line continues from the engine at 3.0.0.0 rather than restarting as a hub 1.x successor. MOVED PATH: `assets/cli-prompt-quality-card.md` survives as the canonical card every `cli-*` executor delegates to and now lives at `sk-prompt/assets/cli-prompt-quality-card.md`, so consumers pointing at the old nested location must repoint. `graph-metadata.json` moved to the standalone family and kept one enhances edge to the CLI orchestration hub. `leaf-manifest.config.json` was authored and `leaf-manifest.json` plus `leaf-aliases.json` regenerated from it. `/prompt:improve`, the seven frameworks, DEPTH and CLEAR scoring are unchanged.
