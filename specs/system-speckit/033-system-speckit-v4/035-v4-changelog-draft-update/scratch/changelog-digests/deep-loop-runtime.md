# Deep-loop runtime changelog digest

Source: `.opencode/skills/system-deep-loop/runtime/changelog/`. Versions covered: v1.0.0.0 through v1.5.0.1, all 7 entries present (fewer than 10 exist, so this is the complete set). No entry carries a date in its body. Git first-commit dates span 2026-05-22 (`v1.0.0.0.md`) to 2026-06-26 (`v1.5.0.1.md`).

## Per version, newest first

### v1.5.0.1

RENAME the `ai-council` packet path became `deep-ai-council`, and this release only propagates that rename into the runtime surfaces that still pointed at the old path. `v1.5.0.1.md` lists three files touched: `lib/council/README.md`, `references/integration-points.md` and `graph-metadata.json`. It states plainly that these are path references only, so no runtime behavior changed and no migration is required. This is the newest entry in the directory and the last recorded runtime version.

### v1.5.0.0

Two fan-out defects found after a dark-flag graduation benchmark got fixed, both behind flags that stay off. Per `v1.5.0.0.md`, the near-duplicate finding dedup in `scripts/fanout-merge.cjs` was scale-validated on a 75-finding set across six workers and made title-aware: `nearDuplicateContentKey` now gates a collapse on a Jaccard title overlap at `TITLE_DISTINCT_OVERLAP_THRESHOLD = 0.15`, which dropped the measured title-only false-collapse rate from 0.50 to 0 while identical-duplicate collapse held at 7 of 7. Separately the lag-ceiling gauge in `scripts/fanout-pool.cjs` stopped measuring time-since-pool-start, which was queue backpressure, and now measures time-since-last-completion-while-work-is-pending through `lastProgressAtMs`, emitting `metric: 'time_since_last_completion'`. The entry is explicit that the committed gauge defaults remain 0, that both changes are byte-identical when their flags are off, and that the recommended production values (heartbeat 30 seconds, lag-ceiling 120000ms, lowered from 5 minutes) are documented and proven but not enacted.

### v1.4.0.0

Documentation only, closing two sk-doc conformance gaps without touching runtime behavior. `v1.4.0.0.md` records a new SUCCESS CRITERIA section in the SKILL.md giving consumers a concrete health contract (JSON stdout for every script entry point, consumer `lib/` import resolution, SQLite and schema presence, Vitest discovery) and a new REFERENCES AND RELATED RESOURCES section naming the consumer skills, the cross-package Vitest config and the changelog directory. It also records a deliberate decision to keep `references/` flat here while the four reference-heavy deep-* skills moved to thematic subfolders.

### v1.3.0.0

RENAME the runtime SQLite directory `storage/` became `database/` via `git mv`, aligning with the sibling `system-spec-kit/mcp-server/` convention. Per `v1.3.0.0.md` the only load-bearing code change was the `COVERAGE_GRAPH_DATABASE_DIR` constant in `lib/coverage-graph/coverage-graph-db.ts`, since the four `.cjs` scripts and the writer-lock path all derive from it. REMOVED the sqlite binary from git tracking via `git rm --cached`, with new `.gitignore` rules for `database/*.sqlite` plus `-shm`, `-wal` and `.bak`, so a fresh checkout has no DB and it lazy-initializes on first script run. Four missing test-subfolder READMEs were added (`unit/`, `integration/`, `lifecycle/`, `council/`), and `verify_alignment_drift.py` reported PASS over 54 files. Historical changelogs kept their `storage/` references as point-in-time records.

### v1.2.0.0

Closed a 36-finding backlog from a 10-iteration deep-research audit run against the v1.1.0.0 baseline, in four batches. `v1.2.0.0.md` records that three of the worst findings were introduced by the v1.1.0.0 README rewrite itself: a fabricated `code-surface` node kind, a wrong cross-arc citation and a 22-versus-27 vitest count drift. Batch A corrected cross-arc citations from `129/001` to `131/001/008 ADR-001` at six sites and replaced the invented node kind with the 10-kind allow-list. Batch B swept all 17 feature-catalog descriptions against their source modules and corrected three (fallback-router, bayesian-scorer, post-dispatch-validate). Batch C added a whole council surface, 5 catalog entries plus 5 playbook scenarios, raising counts from 17 to 22 and from 7 to 8 categories. Batch D added two new unit test files for `coverage-graph-query` and `coverage-graph-signals` and deepened two council tests. The entry draws the lesson that structural validation is not fact-checking.

### v1.1.0.0

Documentation-only cleanup pass with no code, script, test or storage changes. Per `v1.1.0.0.md` the README was rewritten from 174 to 470 lines onto the 9-section system-spec-kit pattern covering seven runtime domains, and three surgical SKILL.md edits landed: the frontmatter description trimmed from 240 to 124 characters against a 130-character limit, a stray `## Council Primitives` H2 demoted to H3, and a broken changelog path `v1.0.0.md` corrected to `v1.0.0.0.md`. The entry notes consumers holding the broken path should update it. The script interface contract, TS import paths and SQLite schema version 2 were all unchanged.

### v1.0.0.0

BREAKING the four `mcp__system_spec_memory__deep_loop_graph_*` MCP tools were deleted and replaced by direct `.cjs` script invocation. This is the first shipped release, and per `v1.0.0.0.md` it consolidated all deep-loop infrastructure out of `system-spec-kit/mcp-server/` into a standalone peer skill under arc 118 (FULL_ISOLATE_NO_MCP, a user-directive override of an earlier AI Council SPLIT ruling). Ten shared TypeScript modules moved into `lib/deep-loop/` and three coverage-graph modules into `lib/coverage-graph/`, with the SQLite DB at `storage/deep-loop-graph.sqlite`. REMOVED the MCP tool surface entirely: `scripts/convergence.cjs`, `upsert.cjs`, `query.cjs` and `status.cjs` replace `_convergence`, `_upsert`, `_query` and `_status`, turning two-step workflow YAML calls into one-step `bash: node .../scripts/<name>.cjs` calls. Exit codes were standardized as 0 ok, 1 script error, 2 DB error, 3 input validation error. Tests moved into `tests/unit/`, `tests/integration/`, `tests/lifecycle/` and `tests/helpers/`, discovered through the `system-spec-kit/mcp-server/vitest.config.ts` glob. The release also shipped an 18-file feature catalog, an 18-file manual-testing playbook, 4 reference docs and `graph-metadata.json`.

## Facts the v4 draft gets wrong or misses

- REMOVED the deep-loop graph MCP tool surface is absent from the draft. `v1.0.0.0.md` records the deletion of four `mcp__system_spec_memory__deep_loop_graph_*` tools and their replacement by direct `.cjs` entry points with standardized exit codes. Draft line 70 covers only the Spec-Kit Memory decommission (`memory_search` and `memory_save`), and the "Repoint what moved" bullet at draft line 444 lists moved skill and spec paths without naming these tools. Anything still calling a `deep_loop_graph_*` tool gets no warning from the draft.
- RENAME `storage/` to `database/` is missing from the draft. `v1.3.0.0.md` records the `git mv`, the `COVERAGE_GRAPH_DATABASE_DIR` constant change and the advice that consumers with a hardcoded old path switch to the constant. Verified on disk: `.opencode/skills/system-deep-loop/runtime/database` exists and no `storage/` sibling does. Draft line 444 is the natural home for this and does not carry it.
- REMOVED the runtime SQLite from git tracking is missing. `v1.3.0.0.md` records `git rm --cached` plus `.gitignore` rules for `database/*.sqlite`, `-shm`, `-wal` and `.bak`, so external users now get a clean checkout and the DB lazy-initializes on first script run. That is a visible behavior change for anyone who previously found a committed DB, and the draft never mentions it.
- The draft oversells the fan-out gauges. Draft lines 174 to 176 describe fan-out as parallel, contained and reproducible with no mention that the near-duplicate finding dedup and both progress gauges are still default-off. `v1.5.0.0.md` states three times that the committed gauge defaults remain 0, that both fixes are byte-identical when their flags are off, and that flipping the zod defaults is a separate graduation step out of scope. The recommended values it documents but does not enact (heartbeat 30 seconds, lag-ceiling 120000ms) also do not appear in the draft.
- The draft's evidence-ledger claims are not recorded in this changelog. Draft lines 184 to 191 assert an append-only ledger, a fail-closed transition gateway, sealed artifacts, replay fingerprints and all seven ledger modes on the authoritative path. No entry in this directory documents any of that, and the changelog stops at `v1.5.0.1.md`, which is a three-file path-reference update. The supporting scripts do exist on disk (`append-mode-event.cjs`, `verify-authority.cjs`, `check-projection-coverage.cjs`, `check-direct-append.cjs`), so this reads as a changelog gap rather than a draft error, but nothing in these entries corroborates the draft.
- The hub merge itself is unrecorded here. Draft line 165 and draft line 456 both state that `deep-loop-runtime` merged into `system-deep-loop` and that the old skill identity no longer exists. Every one of the 7 entries still writes the runtime path as `.opencode/skills/deep-loop-runtime/`, and no entry records the move. The draft claim is corroborated by the hub SKILL.md, which dates the merge 2026-07-08, and not by the changelog.
- Mode naming nuance, not an error. `v1.5.0.1.md` records the `ai-council` to `deep-ai-council` packet rename, while draft lines 26 and 165 still write the mode as `ai-council`. The draft is right on the mode id, because `mode-registry.json` still declares the `workflowMode` literally as `ai-council`, and the rename applied to the packet folder. Worth a one-clause disambiguation if the draft mentions folder paths.
- The draft's "six modes" count checks out. `mode-registry.json` declares research, review, ai-council, agent-improvement, model-benchmark and skill-benchmark, which matches draft line 26 and draft line 165.

## Current version and identity

`.opencode/skills/system-deep-loop/runtime/package.json` declares `"name": "@deep-loop/runtime"` and `"version": "1.0.0"`, which is stale against the changelog directory whose newest entry is v1.5.0.1. The package is `private`, ESM, requires Node >= 20.11.0, and depends on `@spec-kit/shared` by relative file path, `better-sqlite3`, `tsx` and `zod`, with `vitest` for tests. Its description calls it a self-contained dependency root so lib and scripts resolve their dependencies from this skill rather than reaching into a sibling skill's `node_modules`.

The runtime is no longer a skill in its own right. It has no `SKILL.md` and lives as the nested `runtime/` layer of the `system-deep-loop` hub, whose own `SKILL.md` is at version 3.0.0.0 and describes `runtime/` as the frozen, MCP-free infrastructure layer the hub consumes, formerly the separate `deep-loop-runtime` skill and merged in on 2026-07-08. The hub routes by `workflowMode` through `mode-registry.json` to four mode packets on disk (`deep-research`, `deep-review`, `deep-ai-council`, `deep-improvement`) covering six declared modes, and holds no convergence, state or synthesis logic of its own. That means the runtime version number in `package.json`, the version sequence in `changelog/`, and the hub's own 3.0.0.0 are three separate counters, and only the changelog sequence tracks the runtime's real history.
