# cli-pi changelog digest

Skill path: `.opencode/skills/cli-external-orchestration/cli-pi/`. Versions covered: v1.0.0.0 (oldest) through v1.5.0.0 (newest), 7 entries, the full changelog directory. Date range: none. No entry in `changelog/` carries a date, so no range can be stated.

## Per version, newest first

### v1.5.0.0 (`v1.5.0.0.md`)

BREAKING: a Pi session may now dispatch `cli-pi`, reversing the previous self-invocation prohibition. `v1.5.0.0.md` records the prohibition being removed in three coordinated places, the `self-invocation-prohibited` hard rule and the `CRITICAL - SELF-INVOCATION PROHIBITED` block and the `detect_self_invocation()` guard in `SKILL.md`, the `dispatchSkill === "cli-pi"` deny branch in `.opencode/hooks/dispatch/pi/dispatch-preflight-lint.ts` and a `cli-pi`-keyed exemption set in `system-deep-loop/runtime/lib/deep-loop/executor-audit.ts` consulted by the `ancestry` and `lockfile` layers only. REMOVED: `pi-subagents` is retired because Pi dropped its subagents feature, so the package is gone from the activation trigger, the `AGENT_DELEGATION` router keywords, hard rule 6, the README FAQ, four references, the prompt templates, the playbook index and the hub advisor vocabulary. The `PI-009` agent-bridge scenario was deleted with it, and `references/agent-delegation.md` was rewritten around Pi built-in tools and the CLI dispatch route rather than deleted, because it is a declared leaf. The `lineage` and `stack` guard layers still refuse for every kind including `cli-pi`, the other five executors still refuse on all five layers and `pi-mcp-extension` remains documented as a community package behind the same trust gate. Verification recorded: `executor-audit.vitest.ts` 49 passed up from 35, `cli-pi.vitest.ts` 19 passed 1 skipped, `dispatch-preflight-lint.test.ts` 33 passed. A live dispatch from a real Pi session was not run and is recorded as unverified. Frontmatter moved to 1.5.0.0 in both `SKILL.md` (from 1.3.0.0) and `README.md` (from 1.4.0.0), resolving a drift between them.

### v1.4.1.0 (`v1.4.1.0.md`)

REMOVED: the direct DeepSeek API provider, DeepSeek V4 Pro in every form and GPT-5.6 Terra were dropped from `references/providers-and-models.md`. BREAKING: the `--provider deepseek` dispatch shape no longer exists in any example, and the bare `deepseek-v4-flash` literal is now documented as opencode-go-fronted. The closed roster carries six providers, `openai-codex` (sol and luna), `minimax`, `xiaomi`, `opencode-go` (DeepSeek V4 Flash, Qwen 3.8 Max, GLM-5.3-Flash), `openrouter` with its three-model allowlist unchanged, and `cline-pass` (flash plus GLM-5.3-Flash). Changed default: `PI_DEFAULT_MODEL` in `executor-config.ts` moved from `deepseek-v4-pro` to `deepseek-v4-flash`, and the enforcement allowlists dropped `deepseek-v4-pro` and `gpt-5.6-terra`. Verification recorded: a grep for the retired literals over non-changelog and non-benchmark files returned zero hits, and deep-loop unit tests passed 205. Note an internal inconsistency in the entry itself, it states "Frontmatter version moved from 1.0.0.0 to 1.1.0.0" while the file is `v1.4.1.0.md`, which does not match the version it documents.
