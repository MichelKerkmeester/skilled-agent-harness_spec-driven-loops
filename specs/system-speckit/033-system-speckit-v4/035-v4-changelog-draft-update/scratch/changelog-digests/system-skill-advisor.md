# system-skill-advisor changelog digest

Skill path: `.opencode/skills/system-skill-advisor/`. Versions covered: v0.2.0 through v0.11.0.0 (the last 10 of 11 entries, v0.1.0 excluded). Dated entries span 2026-05-15 (`v0.2.0.md`) to 2026-06-03 (`v0.5.0.md`). The other eight entries carry no release date.

## Per version, newest first

### v0.11.0.0 (`v0.11.0.0.md`)

Documentation only. The README was rewritten from a tabular reference card into the purpose-first narrative voice used across the fleet: a one-line pitch blockquote under the H1, a problem-first "Why This Skill Exists" overview leading with misrouting and prompt-leak, a Five-Lane Scorer table giving each lane its live weight and evidence, Quick Start guidance covering the MCP path plus the legacy Python facade plus the daemon-backed CLI, and a verification close. The README frontmatter version went from 0.8.0.34 to 0.11.0.0. The entry states explicitly that no SKILL.md content, scorer, daemon, MCP server, plugin bridge, hook, registry or vault file changed.

### v0.10.0 (`v0.10.0.md`)

Security and durability hardening from the 20-iteration deep review of the 028 playbook-findings remediation. `sanitizeDerivedMetadata` now sanitizes `derived.trigger_phrases`, `derived.key_topics` and `derived.entities`, which are the highest-weight routing match terms and previously passed through verbatim, so an instruction-shaped phrase in a skill's graph metadata reached the scorer unfiltered. A real index-then-project round-trip test proves an injected phrase is dropped. `writeBoundedJsonl` in `metrics.ts` became an atomic `O_APPEND` write serialized per path through an in-process queue, replacing a lock-free read-modify-write that could lose records under concurrent advisor invocations. The claude and codex `user-prompt-submit` and `prompt-wrapper` hooks got a deliberate `.catch` on the fire-and-forget diagnostic persist, and `emitDiagnostic` was exported and parameterized for testing. The derived-block rollback in `lifecycle/rollback.ts` stopped stripping `lifecycle_status` and `redirect_to`, which had been silently un-deprecating skills and dropping supersession redirects. The entry names one remaining gap rather than hiding it: the `skill_docs` upsert path still writes and reads `title`, `description` and `trigger_phrases` raw.

### v0.9.0 (`v0.9.0.md`)

BREAKING (changed default): the reciprocal-rank-fusion spine and the conflict-rerank seam graduated from dark (default off) to the shipping defaults, on the phase 007 benchmark verdict over a widened 42-prompt set where RRF top-1 went from 37/42 to 38/42 with zero regressions and 0.976 agreement. REMOVED: the separate self-recommendation guard was cut as behaviorally redundant, since it moved 0 of 4 top-1. The implicit `auditRecsAdvisorPenalty` that had been doing the guard's job was then documented with a durable WHY comment and locked with a regression contract test. An opus deep review found the penalty matched only the exact id `system-skill-advisor` by string, so the `skill-advisor` alias still self-recommended to top-1, and the predicate was changed to use the canonical self-recommendation id set so both are demoted. The penalty value is unchanged at -0.25 and the scorer suite stayed green at 119 of 119. The entry notes default-off behavior was byte-identical across the 42 prompts, so no existing routing flips.

### v0.8.0 (`v0.8.0.md`)

Added a runtime consumer for the detailed frontmatter on skill reference and asset docs, behind the new flag `SPECKIT_ADVISOR_DOC_TRIGGERS`, which defaults to off. With the flag on, every `skill_graph_scan` harvests `title`, `description`, `trigger_phrases`, `importance_tier` and `contextType` from each skill's `references/` and `assets/` markdown into a new additive `skill_docs` table, the daemon watcher tracks those docs as `doc-frontmatter` watch targets for freshness, and the scorer turns the phrases into dampened signal inside the existing `derived_generated` lane rather than adding a sixth lane. Per skill the top-3 doc matches are tier-weighted (1.0 for constitutional or critical down to 0.2 for deprecated) and capped at 0.45 combined, deliberately below what one curated skill-level phrase earns, so doc volume assists ranking but cannot hard-route alone. An optional `matchedDocs` field (max 3 sanitized skill-relative paths) and a `doc_reference_signal` evidence type joined the strict schema. `skill_advisor.py` got the same flag-gated harvest for Gate-2 parity, and the SQLite loader now merges the source-metadata signal map it previously skipped. `SPECKIT_ADVISOR_DOC_TRIGGERS` was added to `CHILD_ENV_ALLOWLIST` in `system-skill-advisor-launcher.cjs`, without which the daemon child never sees the flag. Flag-off behavior is byte-identical to v0.7.0 and that invariance is the hard contract of the new 11-case test suite. At release 84 of about 355 docs carried `trigger_phrases`.

### v0.7.0 (`v0.7.0.md`)

Added a daemon-backed CLI front door at `node .opencode/bin/skill-advisor.cjs`, exposing all nine tools (four `advisor_*`, four `skill_graph_*` and the internal propagation tool) over the same IPC socket the MCP registration already used, with that registration unchanged. The CLI shares the exit taxonomy of the sibling `spec-memory` and `code-index` CLIs: 0 success, 1 runtime error, 64 usage or schema error, 69 protocol or dist mismatch, 75 retryable daemon error. A `--warm-only` mode probes the socket and exits 75 rather than cold-starting the daemon from a hook, and a dist-freshness guard refuses a stale build with exit 69 unless `SYSTEM_SKILL_ADVISOR_CLI_DEV_ALLOW_STALE=1` is set. BREAKING for mutation callers: the CLI is fail-closed and untrusted by default, so `advisor_rebuild`, `skill_graph_scan` and apply-mode `skill_graph_propagate_enhances` require `--trusted` or `SYSTEM_SKILL_ADVISOR_CLI_TRUSTED=1`, and native MCP registrations must declare `SYSTEM_SKILL_ADVISOR_TRUST_DEFAULT=trusted` in their env block or their mutations are refused as untrusted. Warm-only CLI fallbacks were wired into the Claude and Codex `user-prompt-submit` hooks through `hooks/lib/skill-advisor-cli-fallback.ts`, so Gate 2 routing survives the MCP transport being down, and the OpenCode plugin gained a CLI fallback route through `plugin-bridges/system-skill-advisor-bridge.mjs`. Codex allowlists the CLI in `.codex/settings.json`, and the Claude allowlist was left in local-only settings by decision.

### v0.6.0 (`v0.6.0.md`)

MOVED PATH (upstream, documentation only here): the canonical `cli_prompt_quality_card.md` moved from `sk-prompt/assets/` to `sk-prompt-models/assets/`, which left the stale canonical-location header comment in `check-prompt-quality-card-sync.sh` pointing at the old home. Only that comment was updated, because the guard's own logic is path-agnostic and keys on the five `cli-*` card filenames, table absence and SKILL.md pointers. CHECK 1 through 4 semantics, the pre-commit orchestrator wiring and the CI workflow are unchanged, and the guard exits 0 on the clean post-relocation tree.

### v0.5.0 (`v0.5.0.md`, released 2026-06-03)

Extended the prompt-quality-card duplication guard from two table checks across the `cli-*` cards to the full "one home per fact" invariant for the 3-layer prompt-knowledge architecture, and wired it to run automatically instead of by hand. CHECK 2 asserts no `cli-*/SKILL.md` re-enumerates the canonical escalation triggers and that each points at the canonical card, catching precedence drift. CHECK 3 asserts every adopted model (a `model-profiles.json` entry carrying `recommended_frameworks`) has both a profile and an `_index.md` row and that every profile maps back to a registry id, catching zero-hub-weight entries, with unadopted stubs exempt. CHECK 4 asserts every adopted model is reachable by name in each dispatching executor's `graph-metadata.json`, catching the model-unreachable-by-name class seen with qwen3.6. The guard became a blocking gate in the pre-commit orchestrator when a prompt-knowledge surface is staged, bypassable with `SPECKIT_SKIP_CARD_SYNC=1`, and a new PR workflow `.github/workflows/prompt-card-sync.yml` runs it in CI. All checks are structural with no semantic matching, and the registry parse uses python3 to avoid a jq dependency. Planted regressions for CHECK 2, 3 and 4 each verified as exit 1.

### v0.4.0 (`v0.4.0.md`)

REMOVED: the MD5 hash-comparison sync logic in `mcp-server/scripts/check-prompt-quality-card-sync.sh` is gone. The script was repurposed from a 3-mirror hash comparison into a duplication guard that scans all four `cli-*` prompt-quality cards (`cli-claude-code`, `cli-codex`, `cli-devin`, `cli-opencode`) and asserts that neither the canonical framework comparison table nor the CLEAR scoring table has been inlined into any of them. The old design needed synchronized copies and a known-good hash baseline and fired false positives whenever a deliberate update had not yet propagated. The new scan uses targeted substring matches against each canonical block's unique table header, which survives minor wording changes. The exit-code contract is preserved at 0 for pass and non-zero for fail, but the meaning of a non-zero exit changed from hash mismatch to duplication detected. Any stored hash baselines are no longer read and can be deleted.

### v0.3.0 (`v0.3.0.md`)

Landed the advisor's share of the 108 plus 110 auto-review uplift program, with four teachings borrowed from the upstream `dzianisv/opencode-plugins` package, each cleared by a unanimous 5-of-5 deep-ai-council review before any code shipped. Metrics persistence in `mcp-server/lib/metrics.ts` moved off synchronous `mkdirSync` plus `writeFileSync`, which blocked the event loop on every advisor invocation, onto awaited `mkdir` plus `writeFile` from `fs/promises`, gated by a closure-scoped `dirReady` flag so the directory check runs once per process. The council forced the writes to stay awaited rather than fire-and-forget so the bounded-retention read-then-rewrite-last-N contract survives. Diagnostic record persistence became opt-in behind `SKILL_ADVISOR_DEBUG=1` while outcome records stay unconditional. The `system-skill-advisor.js` plugin gained a `loadConfig()` with 4-tier precedence: `rawOptions`, then a JSON file at `~/.config/opencode/plugin/system-skill-advisor.json`, then seven new `SYSTEM_SKILL_ADVISOR_*` environment variables, then hardcoded defaults, with the legacy `SPEC_KIT_PLUGIN_NODE_BINARY` preserved as a backward-compatible fallback for the node-binary path. That config loads as a `configPromise` at module init which the plugin factory awaits before option normalization, closing a race where a synchronous factory could report its option surface before the config file finished loading. The existing env-var disable handling was preserved unchanged and the on-disk metrics format did not change.

### v0.2.0 (`v0.2.0.md`, released 2026-05-15)

Production isolation from system-spec-kit. Six production TypeScript files had imported cross-skill helpers, and all six were closed. Seven shared-payload types plus `canonicalFold` and its constants were duplicated locally into new `mcp-server/lib/shared/shared-payload.ts` and `mcp-server/lib/shared/unicode-normalization.ts`, each carrying a header comment naming its upstream source of truth. REMOVED: the `@spec-kit/shared` workspace dependency was deleted from `mcp-server/package.json` and the lockfile regenerated, so that alias now resolves only through tsconfig paths for type checking. MOVED PATH: the heavyweight embeddings stack, too large to duplicate at roughly 3,000 to 5,000 lines, is reached through a deliberately visible git-tracked symlink at `mcp-server/lib/shared/embeddings` pointing to `../../../../system-spec-kit/shared/embeddings`, so deleting system-spec-kit makes the symlink dangle loudly instead of failing obscurely. One test file was isolated with `vi.mock` plus a local errors fixture, and two new blocking audit steps were added to `.github/workflows/isolation-check.yml` covering reverse-direction relative imports and `@spec-kit/*` alias imports, with the embeddings symlink as the single documented exception. Production cross-skill imports went from 6 to 0. The entry is explicit that isolation is partial by design: the embeddings dependency remains intentional, and `mcp-server/tsconfig.json` still extends `system-spec-kit/mcp-server/tsconfig.json`, so `tsc --build` breaks if system-spec-kit is deleted. Runtime API ids stayed stable from v0.1.0.
