## Per-version digest, newest first

### v1.1.0.0 (2026-08-28) - `changelog/v1.1.0.0.md`

This release adds a second lane to the skill. Until this point the skill adapted an explanation on one axis only, register, meaning it said the same thing in plainer words. It now also adapts modality and depth, so a request that words cannot carry becomes a picture instead. The new entry point is `/rewrite:explain-visually`, which explains a named topic, or the previous reply when no topic is given, as the smallest visual that answers the question. A modality dial picks the form that fits the content, covering pseudocode for logic, a call tree for control flow, a component or file tree for structure, Mermaid for flow and sequence, a diff for change, a code block where syntax matters and HTML for dense comparison. A depth dial offers `expert`, `plain` or `novice` and decides how much prior knowledge the explanation may assume, with the standing rule that simplification applies to words and never to facts. Output is display-only by default, and the opt-in `--artifact` flag creates one new self-contained HTML file and never edits an existing one. SKILL.md was rewritten around a two-lane model that states which lane a request belongs to and why their gating differs: Lane A rewrites a byte stream and may reach a model, Lane B synthesizes in-context and carries neither risk, so the enablement flag and egress rules do not apply to Lane B. The on-disk rule was disambiguated, the bar on rewriting durable files now covers editing an existing file only, and creating a new explanatory artifact on explicit request is Lane B behavior. The smart router became lane-aware, selecting a lane before selecting resources, so an explanation request loads the visual rubrics instead of the package map. The projection lane itself was untouched, with no change to the package, its adapters, the enablement flags or the evaluation harness, and the skill stays on the advisor route-exclusions denylist so both lanes are invoked by command and never by recommendation.

### v1.0.0.0 (2026-08-14) - `changelog/v1.0.0.0.md`

Initial release of sk-communication as a portable projection layer that rewrites terse agent output into plain English while keeping the canonical event stream, transcript, tool data and model context byte-for-byte unchanged. The runtime centers on a `projectMessage` orchestrator with a provider-transport seam and a reject-only default judge, so canonical bytes survive every non-approved path. A capability and privacy gate consults the compatibility doctor and fails closed to the exact original on unknown, stale or incapable routes, and never routes to a hosted model without a fresh, capable, privacy-approved decision. An evaluation and release gate composes a blind non-inferiority signal as a reject-only quality check and blocks a runtime rollout without fresh, dated evidence. Wiring landed as an OpenCode native plugin through the `chat.message` hook, default-off and fail-open, plus five CLI-output wrappers for Claude Code, Codex, Pi, Devin and Cursor over a shared wrapper framework with per-runtime stream parsers. Projection is off by default for everyone, and an operator opts in per machine with `COMMUNICATION_PROJECTION_ENABLED` or a git-ignored `enablement.local.json` at the package root. The skill was deliberately held out of advisor routing by adding it to `route-exclusions.json`, so the recommender never surfaces it and you invoke it by hand. New paths added: `.opencode/skills/sk-communication/cli-communication-projection/`, `.opencode/plugins/sk-communication-projection.js` and `.opencode/skills/system-skill-advisor/mcp-server/config/route-exclusions.json`. No upgrade action was required.
