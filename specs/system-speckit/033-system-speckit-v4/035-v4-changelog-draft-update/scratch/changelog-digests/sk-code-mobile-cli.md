## Per version, newest first

### v0.1.11.0 (`v0.1.11.0.md`)

An independent audit against `skill-reference-template.md` found 22 of 34 reference documents deviating from the template contract, and this release fixes all of them. Twelve doubled `---` dividers introduced by the v0.1.10.0 merge script were removed, eleven of them in `svelte/svelte.md`. Five links kept a visible label naming a file that had been merged away while the href pointed elsewhere, so the labels were corrected. `design-system.md` had an intro that near-verbatim repeated its own Core Principle and a description that counted five sibling folders where there are six. Pre-existing fixes: `quality/doc-quality-gate.md` opened with `## 1. PURPOSE` instead of the required `## 1. OVERVIEW`, `setup/install-and-onboarding.md` had unnumbered H2 sections at both ends and now runs sections 1 to 12, four `trigger_phrases` were not lowercase, `comment-grammar.md` carried nine trigger phrases where the cap is eight, and `standards/platform-support.md` plus `install-and-onboarding.md` used `### Key Facts` and `### Key Features` where the template specifies `Key Sources`. Four documents were unreachable from any other document and are now linked: `incident-playbooks.md`, `rollback.md`, `ai-deploy-playbook.md`, and both `quality/` documents. SKILL.md's explainer was corrected because it claimed every folder entry document routes and links the rest, which is true of five folders and false of `verification/` and `svelte/`, which hold merged documents rather than routers.

The rule had been authored on a stranded refactor branch that a fresh rewrite superseded, so the surface had been enforcing a coverage gate it never taught.

### v0.1.3.0 (`v0.1.3.0.md`)

Folder documentation moved from a universal requirement to a measured threshold. A `CODE.md` is required for folders with three or more direct source files or child source folders, while smaller leaf folders keep one `README.md`, and the rationale is part of the convention because documentation ceremony reads as content and rots the same way. The entry also documents the two-way `scripts/naming/scan-folder-docs.mjs` enforcement, which catches both missing and unnecessary code maps, and adds ownership, caller-boundary and change-placement guidance for single-document folders.

## Facts the v4 draft gets wrong or misses

- The draft mentions `sk-code-mobile-cli` exactly once, at line 307, as one of four read-only surface packets. It never says what the surface is. Per `v0.1.6.0.md` and `v0.1.9.0.md` it is the Pi Remote Mobile-CLI SvelteKit app surface covering `app-mobile/`, `app-relay/` and `packages/pi-rpc-protocol/`. A reader of the draft cannot tell which stack this packet covers, while the draft does name the stacks of its siblings (Motion.dev for webflow at line 307, Rust for opencode at lines 319 to 321).
- The draft misses a functional routing bug fix that matches its own "safer paths" theme. Per `v0.1.6.0.md`, the hub's PI_REMOTE surface detection keyed off `apps/pi-remote-web` and "React 19 / Vite / Tailwind 4 / style.css" and therefore never matched the current `app-mobile/` SvelteKit tree, so the surface was effectively unroutable until detection markers were retargeted at Svelte and `app-mobile`. Line 307's claim that surfaces "inform" a code task is only true after that fix.
- The draft misses the React-to-SvelteKit migration entirely. Per `v0.1.6.0.md` and `v0.1.9.0.md`, the paths `apps/pi-remote-web/`, `apps/pi-remote-relay/`, `src/style.css`, `App.tsx` and `catalog.html` are all gone, replaced by `app-mobile/`, `app-relay/`, `app-mobile/src/app.css` and the Storybook catalog. This is a rename class the draft flags for other surfaces (line 307 notes the sk-code move "is breaking" for old flat paths) but not for this one.
- The draft misses the removal of the inline `@ds-*` marker grammar. Per `v0.1.7.0.md` and `v0.1.7.1.md`, `references/ds-grammar.md` was removed and `ds-grammar-routing.md` renamed, so anything still pointing at the retired grammar breaks. The `mode-registry.json` alias list for this mode still carries `"ds grammar editability"`, so the retired vocabulary survives in routing metadata.
- The draft misses the version-scheme renumber. Per `v0.1.7.1.md`, the skill moved from `1.x.y.z` to a pre-release `0.x` scheme with the mapping `W.X.Y.Z` to `0.W.X.Y`. Any v4 statement of this mode's version number needs the new scheme, and the changelog file frontmatter titles still show the old one.
- Line 307 says each surface carries "the shared implement, debug and verify doctrine plus its stack knowledge". For this mode that is accurate but understated: per `v0.1.6.0.md` the surface also ships an executable gate, `scripts/run-source-gates.sh`, running five source scans as one PASS or FAIL, which is behavior rather than doctrine and is the kind of thing the draft's "terminal proof" theme at the top of the file would want named.
- The draft's "Docs that make anything" and template-conformance themes miss that this surface's references were audited to template conformance in `v0.1.11.0.md`, where 22 of 34 documents deviated and four were unreachable from any other document.
