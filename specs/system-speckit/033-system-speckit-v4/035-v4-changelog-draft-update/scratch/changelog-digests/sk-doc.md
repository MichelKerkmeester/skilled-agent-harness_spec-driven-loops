## 1. Per version, newest first

### v2.0.1.0 (`v2.0.1.0.md`)

The hub's second-stage surface router became a first-class root `ROUTER.md` (its own v1.0.1.0) with `router_state: active` and `skill_pointer: SKILL.md`. The machine-readable `INTENT_SIGNALS` and `RESOURCE_MAP` block was carried over byte-identical to the legacy file (sha256 `2ad1469c...`) while the prose around it was rewritten. `SKILL.md` gained a Surface Router pointer in Section 2, a layout-tree entry, an ALWAYS rule pinning `RESOURCE_MAP` in sync with `leaf-manifest.json` and `leaf-aliases.json`, plus a REFERENCES entry. `SKILL.md`, `README.md` and `description.json` all moved 2.0.0.0 to 2.0.1.0, and `leaf-manifest.json` was regenerated through its owner tool, picking up a pre-existing staleness fix. REMOVED: `shared/references/smart-routing.md` was deleted after standalone contract validation, so anything pointing at that path now resolves to nothing. Routing behavior itself was explicitly not changed: `mode-registry.json`, `hub-router.json`, the `null` default mode, bundle rules and the stage-one default `shared/references/quick-reference.md` were all left alone.

### v2.0.0.0 (`v2.0.0.0.md`)

A documentation-only release. The sk-doc `README.md` was rewritten purpose-first on the refined skill README template: a one-line pitch, a problem-first OVERVIEW that states the reader's situation before any feature list, then quick start, the structure-first pipeline, the DQI, integration, troubleshooting, FAQ, verification and related documents, with a dedicated capability table for the type-aware enforcement layer. The README `version` field jumped from 1.8.0.36 to the 2.0.0.0 skill anchor, and a human-voice cleanup removed three Oxford commas. No `SKILL.md` content, template or other skill file was touched, and every `/create:*` command, script path, DQI band and related-document link survived verbatim.

### v1.8.1.0 (`v1.8.1.0.md`)

The skill-authoring contract became enforced instead of merely documented, on both the detection side and the construction side. The trigger was a fast multi-model build of the `sk-design` family that passed the old `package_skill.py` while shipping kebab-case reference names, references and assets missing `version`, and SMART ROUTING sections with no router pseudocode. `scripts/package_skill.py` now validates the full 5-field frontmatter (`title`, `description`, `trigger_phrases`, `importance_tier`, `contextType`) plus `version` on `references/**/*.md` and `assets/**/*.md`, requires `version` in `SKILL.md` and in every reference, asset, feature-catalog, playbook, changelog and README doc that carries frontmatter, and checks `SKILL.md` Section 2 for the markers `discover_markdown_resources`, `_guard_in_skill` and `UNKNOWN_FALLBACK`. Its snake_case filename check became recursive into domain subfolders, where before it scanned only the top level. The new checks emit as warnings rather than hard errors because a blast-radius sweep showed hard-erroring would newly fail 16 of 25 existing skills. On the construction side, `commands/create/assets/create_sk_skill_{auto,confirm}.yaml` now seed the router pseudocode and the versioned template frontmatter, `package_skill.py --check` is a blocking completion gate, the `@markdown` agent mirrors gained a Skill Authoring Contract, and `references/skill_creation/creation-workflow.md` was corrected from an optional 3-part `version` to a mandatory 4-part one.

### v1.8.0.0 (`v1.8.0.0.md`)

sk-doc defined and shipped the 4-part frontmatter versioning standard. New `references/frontmatter-versioning.md` is the single source of truth for the `X.Y.Z.W` format, the changelog-anchored derivation (`anchor = max(frontmatter, changelog)`), the numstat-gated build segment, the line-wise insertion rule and the enforcement rollout. New `scripts/frontmatter-version.mjs` is a self-contained Node engine with `compute`, `apply`, `verify` and `gate` modes that resolves each skill's anchor, normalizes 3-part versions to 4-part and counts real edits from one `git log --follow --numstat` per file. New `scripts/tests/test-frontmatter-version.mjs` carries 21 fixture assertions, and new `scripts/check-frontmatter-versions.sh` is the corpus-wide CI and pre-commit gate. BREAKING: `quick_validate.py` and `package_skill.py` now require a 4-part `version` for skills, with commands keeping it optional, so a skill doc without one fails validation. `assets/frontmatter-templates.md` and the nine doc templates carry `version` as required, so every `/create:*` output is born versioned. The standard was rolled out across the whole corpus, leaving 2,210 in-scope docs versioned and 12 frontmatter-less docs skipped rather than synthesized. A later phase-6 hardening pass raised the git-history `maxBuffer` from 64 to 256 MB, added a fail-closed path-containment guard so `apply` only writes inside the skills root, and made the shell gate fail fast when `node` is missing from PATH.

### v1.7.0.0 (`v1.7.0.0.md`)

A narrow validator fix. `package_skill.py` had a script-extension allowlist of `.py`, `.sh`, `.bash` and `.js` only, so every skill shipping CommonJS or ESM helpers drew false "unexpected file type in scripts/" warnings. `.cjs` and `.mjs` became valid, and a `README.md` inside `scripts/` is now allowed as documentation instead of being flagged. The asset snake_case check was also reading `file.stem`, which left the intermediate `.md` on names like `prompt_pack_round.md.tmpl` and falsely reported them as non-snake_case. It now evaluates the base name before any extension.

### v1.6.0.0 (`v1.6.0.0.md`, 2026-05-19)

Benchmark folder creation became sk-doc's sixth mode. It scaffolds skill-local `mcp-server/benchmarks/benchmark-<YYYY-MM-DD>/` folders that promote curated bake-off results out of a spec packet into the consuming skill, driven by `benchmark_report_template.md` for the ten-section curated narrative and a new 135-LOC `assets/benchmark/source-template.md` for the SOURCE.md wayfinding pointer that maps operator questions back to files in the originating spec packet. The smart router gained a BENCHMARK intent keyed on phrases like benchmark creation and benchmark folder, its RESOURCE_MAP entry grew from two resources to three, and the deprecated benchmarks format keyword was dropped. REMOVED: `references/benchmarks/FORMAT.md` (384 LOC), the now-empty `references/benchmarks/` directory, `references/benchmarks_format.md` (205 LOC) and the two sibling symlinks `system-spec-kit/mcp-server/benchmarks/FORMAT.md` and `mcp-coco-index/mcp-server/benchmarks/FORMAT.md` were all deleted, merged into a single canonical 414-LOC `references/benchmark_creation.md` with no symlink fallback, so any reader of the old paths gets a file-not-found error. The consolidated doc was also generalized to drop stack-specific examples such as Ollama and sentence-transformers so it stays portable across MCP skills.

### v1.5.0.0 (`v1.5.0.0.md`, 2026-05-11)

Five sequential phases restructured the skill surface. RENAME: the documentation executor agent went from `@create` to `@markdown` across all three runtime mirrors (`.opencode/agents/markdown.md`, `.claude/agents/markdown.md`, `.codex/agents/markdown.toml`), and the Codex registry block moved from `[agents.create]` to `[agents.markdown]` with `config_file = "agents/markdown.toml"`. The `/create:*` command family was deliberately left unchanged because this was an agent identity rename, not a command-family rename, which decoupled agent identity from command identity. RENAME: the six sk-doc creation guides moved from `references/specific/` to the references root and the empty `specific/` directory was deleted, with `SKILL.md` routing, README links, asset templates, playbook expected-resources, every `/create:*` command doc and YAML asset, and `graph-metadata.json` source-doc paths all repointed. A new `assets/skill/skill-readme-template.md` scaffold joined the skill-creation flow so skill-package READMEs stop sharing the folder README template, taking the SKILL_CREATION intent from three loaded resources to four. The manual testing playbook gained a `06--agent-dispatch/` section with three scenarios exercising `@markdown` across cli-claude-code, cli-codex and cli-opencode. One structural limitation is recorded: real typed-agent dispatch of `@markdown` through codex `SpawnAgent` is upstream-blocked in codex v0.130.0 because the `codex_core::tools::router` allowlist is a separate baked-in list that does not read `.codex/config.toml` user-defined agents, so that scenario runs as `dispatch_inline_contract` instead. A final phase closed 7 P1 and 9 P2 deep-review findings in a single 129-second pass.

## 2. Facts the v4 draft gets wrong or misses

Draft read: `specs/system-speckit/033-system-speckit-v4/CHANGELOG-v4.0.0.0.md` (463 lines).

- **Missing: the 4-part frontmatter versioning standard is absent from the draft.** `v1.8.0.0.md` ships `references/frontmatter-versioning.md`, `scripts/frontmatter-version.mjs`, `scripts/check-frontmatter-versions.sh` and a corpus rollout over 2,210 docs, and makes a 4-part `version` mandatory in `quick_validate.py` and `package_skill.py` for skills. The draft mentions frontmatter only at line 76 and line 463, and both are about the shared spec-kit frontmatter parser, not the versioning standard or its gate. Line 447 tells adopters to reconcile their own skills to the new skill format without naming the version requirement they will be failed on.
- **Missing: the root `ROUTER.md` is not in the draft's list of what a parent scaffold produces.** `v2.0.1.0.md` makes `ROUTER.md` the first-class stage-two surface router at the hub root. Draft line 134 enumerates the scaffold outputs as "the `mode-registry.json` and `hub-router.json` router files, the packets, the README, the agent mirrors and a routing-drift check" with no `ROUTER.md`. Verified on disk: `.opencode/skills/sk-doc/ROUTER.md` exists at v1.3.1.0.
- **Missing: a deleted path with no fallback.** `v2.0.1.0.md` deletes `shared/references/smart-routing.md`. The draft has no upgrade note for it. Verified on disk: the file is gone.
- **Missing: the benchmark format-doc deletions.** `v1.6.0.0.md` deletes `references/benchmarks/FORMAT.md`, `references/benchmarks_format.md` and two sibling `mcp-server/benchmarks/FORMAT.md` symlinks, stating explicitly that there is no symlink fallback. Draft line 155 says only that benchmark result paths moved to a new dated grammar under `benchmark/reports/` and that `run-skill-benchmark.cjs` now exits 3. A reader with a pinned FORMAT.md path is not warned.
- **Missing: the `references/specific/` relocation.** `v1.5.0.0.md` moves six creation guides out of `references/specific/` and deletes the directory, and its own upgrade section tells downstream consumers to repoint. The draft's rename list at line 443 covers `@create` to `@markdown` and the `/create` command renames but not this path move.
- **Tension the draft should resolve: naming convention.** `v1.8.1.0.md` makes the packaging validator's snake_case filename enforcement recursive into domain subfolders, and names kebab-case reference filenames as one of the defects it was built to catch. Draft lines 147 to 149 say the repo settled on kebab-case as its single filesystem naming form, retired the underscore convention and added a guard that refuses new snake_case names. Both statements cannot describe the same enforced rule, so the draft's kebab-case section needs to say that the older sk-doc snake_case enforcement was reversed, otherwise a reader following `v1.8.1.0.md` will author the wrong names.
- **Internal contradiction the entries can settle.** Draft line 136 says "Four `/create` commands were renamed to match their packet" and then, three sentences later, "The `/create:*` command family itself is untouched." `v1.5.0.0.md` is the source of the untouched claim and it scopes it precisely: the command surface was unchanged *by the agent rename*. The draft should scope it the same way rather than asserting it flatly next to a list of command renames.
- **Missing, minor: the codex typed-dispatch limitation on `@markdown`.** `v1.5.0.0.md` records that codex v0.130.0 cannot dispatch `@markdown` as a typed agent because the `SpawnAgent` allowlist is baked in and ignores `.codex/config.toml`. Draft line 136 and line 443 announce the `@markdown` rename with no note that one of the three runtimes reaches it only through an inline contract.
- **Not contradicted, unverifiable from these entries.** Draft line 463 says sk-doc imports the spec-kit shared package for frontmatter parsing. None of the seven entries mentions that import, so it is neither confirmed nor denied here.
- **Checked and correct.** The draft's counts at line 132, fourteen nested `sk-create-*` workflow packets with twelve bound to a `/create:*` command, match `mode-registry.json`: 14 `workflowMode` entries and 12 with a non-null `command`.
