# sk-create-benchmark changelog digest

Skill path: `.opencode/skills/sk-doc/sk-create-benchmark/`. Versions covered: v1.0.0.0 through v1.5.0.0, the full set of six entries in `changelog/`. Date range: none. No entry in this changelog carries a date in its frontmatter or body, so the digest is ordered by version only.

## Per version, newest first

### v1.5.0.0

A README rewrite and nothing else (`v1.5.0.0.md`). The README was rebuilt to the refined standalone skill README template with a one-line pitch under the title, a problem-first overview, a six-family capability layer, then quick start, navigation, troubleshooting, FAQ, verification and related documents. The prose was cleaned of em dashes, semicolons and Oxford commas, which the entry says the old text failed in six places. The README frontmatter version field was resynced to the changelog sequence for the first time, moving from 1.0.0.0 to 1.5.0.0. The entry states explicitly that `SKILL.md`, the family router behavior, the `assets/` templates and the `references/` guides were untouched.

### v1.4.0.0

A fifth authored benchmark family arrives (`v1.4.0.0.md`). The `conformance_benchmark` family supplies stable input scaffolding for deterministic artifact-conformance checks that a deep-alignment peer adapter runs later. The release added activation triggers, a guarded `FAMILIES` discriminator, a family-table row and a package contract in `SKILL.md`, plus a family-parity regression that checks family directories, table and README registration, required conformance resources and the lane-owned template boundary. The behavior template, workflow and naming block was REMOVED from `SKILL.md` and the existing behavior authoring guide became authoritative for that procedure. A new authoring-command branch `/create:benchmark --family=conformance_benchmark` fills the family index, benchmark contract, lane config and fixture manifest, validates them, then stops before execution. `SKILL.md` moved from 1.3.0.0 to 1.4.0.0.

### v1.3.0.0

The Lane A authoring guide lands and six-family coverage is declared complete (`v1.3.0.0.md`). A new `references/agent-improvement/agent-improvement-authoring-guide.md` covers the doc-only inputs an author fills before an agent-improvement run: the improvement charter and strategy scaffolds, the target-onboarding classification, the candidate proposal format and the profiling and integration-scanning setup. In the `SKILL.md` Smart Routing table Lane A moved from "Nothing, NON-GOAL" in the OWNS column to naming this guide. Missing lane-to-hub back-pointers were added in `deep-alignment/behavior-benchmark/behavior-benchmark.md` and the Lane A `assets/agent-improvement/README.md`. The entry restates the boundary: "single home" means single home for authoring guidance only, and run and scoring ownership stays with the executing lanes per the packet decision record ADR-002.

### v1.2.0.0

Two more authored families plus a structural header normalization (`v1.2.0.0.md`). Skill-benchmark (Lane C) gave the packet ownership of the storage convention for a hub `benchmark/` tree and the template for its `benchmark/README.md` run-label index, with sibling run-label folders and a frozen `baseline/` anchor. Model-benchmark (Lane B) gave it ownership of the input fixtures a model under test answers (code-task oracle, pattern and capability evidence contract, reviewer-prompt) and the run profiles that drive a run. Six new files shipped across `references/skill-benchmark/`, `references/model-benchmark/`, `assets/skill-benchmark/` and `assets/model-benchmark/`. RENAME: the merged `## 1. WHEN TO USE + SMART_ROUTING` header was split into `## 1. WHEN TO USE` and `## 2. SMART ROUTING`, all H2s were renumbered contiguously (MCP-promotion sections 2 to 7 became 3 to 8, behavior 8 became 9), stale intra-file and cross-file section references were updated, and a new `## 12 REFERENCES` section was added so the packet passes `package_skill.py --check`. Per-run `skill-benchmark-report.md` is declared renderer-owned by `build-report.cjs` and is never hand-authored or templated.

### v1.1.0.0

A second benchmark family (`v1.1.0.0.md`). Behavior benchmark authoring was added: an index, per-scenario machine contracts and a Claude baseline for a deep-loop mode, shipped as three templates under `assets/behavior-benchmark/` plus `references/behavior-benchmark/behavior-benchmark-guide.md` and a new `SKILL.md` section 8. The measurement contract itself (five-dimension rubric, terminal buckets, budget formula, entry-surface and clarity enums, per-package ID-prefix table, the runner) stays in `system-deep-loop/shared/behavior-benchmark/framework.md` and is not owned here. MOVED PATH: broken `assets/benchmark/...` template references were corrected to `assets/...` in `SKILL.md`, `README.md` and `references/shared/README.md`, because the `assets/benchmark/` subdirectory does not exist on disk and the templates sit directly under `assets/`. The entry flags the same broken path as still present in `changelog/v1.0.0.0.md` and `references/shared/worked-example.md`.

### v1.0.0.0

The packet is established as one of ten workflow-only packets under the `sk-doc` parent hub (`v1.0.0.0.md`). Its single job at this point is promoting a shipped spec packet's curated MCP benchmark evidence into a consuming skill's `mcp-server/benchmarks/benchmark-<YYYY-MM-DD>/` folder: a ten-section `benchmark_report.md`, a `SOURCE.md` wayfinding pointer back to the authoritative spec packet, and the `results.csv`, `per-probe.jsonl` and `runtime-measurements.md` artifacts. Shipped `SKILL.md`, `references/benchmark_creation.md` and two templates. The entry records that the packet has no packet-local `graph-metadata.json` and no bound `/create:` slash command, with the single advisor identity living at the `sk-doc` hub root and the shared create-quality-control backbone loaded from `../shared/`.

## Facts the v4 draft gets wrong or misses

- The draft's phrase "Benchmark authoring has a single home in `create-benchmark`" (draft line 155) is true only with the qualifier the changelog attaches to it. `v1.3.0.0.md` states under Boundary Held that single home means single home for authoring guidance, and that run and scoring ownership stays with the executing lanes per ADR-002. `v1.2.0.0.md` and `v1.4.0.0.md` repeat the same boundary for the renderer-owned report, the lane-local scorers and the conformance adapter. The draft sentence reads as full ownership.
- The draft says "every run lands in one dated folder grammar under `benchmark/reports/`" (draft line 155). No entry in this changelog names `benchmark/reports/`. The two path grammars the entries do name are `mcp-server/benchmarks/benchmark-<YYYY-MM-DD>/` (`v1.0.0.0.md`, `v1.1.0.0.md`) and a hub `benchmark/` tree of sibling run-label folders with a frozen `baseline/` anchor (`v1.2.0.0.md`). Whether the packet was repointed at `benchmark/reports/` is not recorded in any of the six entries.
- The draft never mentions the `conformance_benchmark` family, which is the packet's newest capability (`v1.4.0.0.md`). Its "Two New Ways to Author" list at draft lines 142 to 143 names `sk-create-repo-rule` and `sk-create-diff` only.
- The draft misses that a `/create:benchmark` command surface now exists with a `--family=conformance_benchmark` branch (`v1.4.0.0.md`). This reverses the "no bound `/create:` slash command" statement carried in `v1.0.0.0.md`, `v1.1.0.0.md` and `v1.2.0.0.md`, so it is a user-visible change the draft omits.
- The draft says at line 165 that "An alignment mode was built during the cycle and removed before release." `v1.4.0.0.md` ships the conformance family as scaffolding for checks "run later through a deep-alignment peer adapter". If the alignment mode is gone, the draft and the shipped conformance family disagree about whether an execution path exists for the family's output. The draft does not address this.
- The draft mentions benchmarks only as deep-loop run modes, "the two benchmarks" at lines 26 and 165. It never states that authoring covers five authored families plus a guide-only sixth lane (`v1.3.0.0.md`, `v1.4.0.0.md`, `v1.5.0.0.md`). Behavior benchmark authoring (`v1.1.0.0.md`) and MCP promotion (`v1.0.0.0.md`) are absent from the draft entirely.
- The draft claims `run-skill-benchmark.cjs` now exits with code 3 on structural or registry blocks instead of 0 (draft line 155). None of the six entries mentions `run-skill-benchmark.cjs` or any exit code. The claim is neither confirmed nor contradicted here, which matters because `v1.2.0.0.md` places the Lane C renderer and runner outside this packet, so this changelog is not the place that would record it.

## Current version and identity

`SKILL.md` frontmatter reads `version: 1.5.0.0`, matching the newest changelog entry. Note one inconsistency worth flagging to the draft author: `v1.5.0.0.md` states that `SKILL.md` was untouched by that release and `v1.4.0.0.md` records `SKILL.md` at 1.4.0.0, yet the file on disk now reads 1.5.0.0. `README.md` frontmatter reads `version: 1.5.0.22`, which does not match `v1.5.0.0.md`'s claim that the README resynced to 1.5.0.0.

Identity: this is a MODE, not a hub and not standalone. There is no `mode-registry.json`, `graph-metadata.json`, `description.json` or `hub-router.json` at `sk-create-benchmark/`. Its root holds only `README.md`, `SKILL.md`, `assets/`, `changelog/`, `manual-testing-playbook/`, `references/` and `scripts/`. The parent `.opencode/skills/sk-doc/` carries `mode-registry.json`, which lists `"workflowMode": "sk-create-benchmark"` at line 275, and `hub-router.json`, which lists the mode at line 15 and routes it to `sk-create-benchmark/SKILL.md` with a `create-benchmark-aliases` alias set. This matches the entries, which say the single advisor identity lives at the `sk-doc` hub root.
