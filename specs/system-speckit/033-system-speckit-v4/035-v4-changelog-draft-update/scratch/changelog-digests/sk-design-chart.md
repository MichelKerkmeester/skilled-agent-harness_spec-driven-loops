## Per version, newest first

### v1.5.0.0 (`v1.5.0.0.md`)

The stock look of every chart became the cursor Style Reference. The palette source `assets/color/palettes.json`, meaning chrome, dark chrome, the corner ladder and all three colour systems, is now derived from `sk-design-md-generator/styles/library/bundles/cursor/DESIGN.md`, and the source file names the four values that had to move to clear a contrast gate. Every stock file sets its body type to `CursorGothic, Inter, system-ui, "Helvetica Neue", sans-serif` while the mono stack for numerals stays as it was. One fix: the ordered ramp's far end moved to `#E64B02` so five rungs clear the separation floor above the parchment ground. Themed copies made with `apply-design-md.cjs --default` now match the stock look because both read the same reference. The entry lists 35 stock HTML files touched plus all palette proof sheets and every screenshot capture regenerated.

### v1.4.0.0 (`v1.4.0.0.md`)

The corpus gained the ability to apply a local v3 `DESIGN.md` Style Reference to delivery copies while leaving the stock palette and templates byte-stable. `scripts/apply-design-md.cjs` parses the documented colour, typography and radius tables, derives the chart role vocabulary and writes deterministic copies under `--forms` or `--all`. The checker only accepts a `design-md` palette block when both themes carry a well-formed SHA-256 provenance comment and clear the inline text, mark, ramp, separation and emphasis gates. `check-corpus.cjs --extra <dir>` was added to run the file-level checks over themed HTML that lives outside the package. `scripts/color-gates.cjs` was added and is required by both the applicator and the checker so their luminance, contrast and rounding arithmetic cannot drift apart. Derivation is fail-closed: a missing v3 heading, a URL input, too few clearing chromatic values or any failed gate stops before anything is written and names the nearest clearing table colour. Extraction stays in `sk-design-md-generator` and this packet never fetches.

### v1.3.0.0 (`v1.3.0.0.md`)

The browser-facing surface was unified across all twenty-six forms and their deliveries on a shadcn-informed card register of five parts in order: headline, subtitle, figure, footer and source. Tooltip-bearing forms now render a padded rounded HTML card inside the figure carrying a per-series indicator, a `READOUT` label and the formatted value, replacing tooltip copy painted as SVG text. Multi-series forms render one centered legend entry per declared series with an 8px keyed swatch, a muted 12px label and a 16px gap. Cartesian marks were unified onto bare axes, muted tabular ticks, an 8px tick margin, horizontal dashed grids, 2px lines and the measured bar and area radii. The corpus checker gained `legend` and `tooltip-card` families and retuned `type-scale`, `radius` and `card-parts`. Gallery frames now pass `?scheme=light` or `?scheme=dark` through to their templates and apply the matching `data-scheme` attribute. Worth noting against v1.0.0.0, which stated flatly that there are no gallery pages: this entry regenerates a 52-frame `assets/gallery.html`, so the no-gallery position was reversed somewhere between the two entries without an entry saying so.

### v1.2.0.0 (`v1.2.0.0.md`)

A seven-phase visual overhaul. One chrome across every file replaced 29 hand-typed `border-radius: 10px` declarations and 21 `rx` values in drawing code with five corner rungs off a 2px knob living in `assets/color/palettes.json`, enforced by a new `radius` check. Motion that settles landed on nine forms and a pointer affordance on twelve, including hover cards, in-figure keys and a dim-to-a-third on five. A dark ground arrived: every file carries a second palette block behind a `prefers-color-scheme` query with its own sentinel pair, and the palette source gained a dark ground, dark text roles and dark series values for all three systems chosen against near-black rather than derived from the light values. Nothing in a delivered file switches themes because a standalone chart has no state to keep a preference in. All twenty-one forms now print one line and draw nothing when the data block holds nothing readable. A twenty-first form, `bar-line-composed`, was added for a count and a rate over the same periods, with the second axis appearing only when the larger peak is ten times or more the smaller. A published type scale of six roles and three named departures is enforced by a `type-scale` check. The corpus check grew from 15 named checks to 25, and from one browser-backed check to three. Fixes: `progress-single` was declaring the `ordered` system while using a fixed fill and now sweeps the ramp with the value, rule 13 had never once fired on a real file and now reads three motion routes, the empty-data guard was coercing `null` to zero through `Number()`, and the composed form's gap notice was drawn outside its own frame. RENAME carried forward rather than applied: two gate keys, `rampDarkestOnSurface` and `rampLightestOnSurface`, are stated to land as `rampFarEndOnSurface` and `rampNearEndOnSurface` across `color-system.md`, `palettes.json` and `check-corpus.cjs` in one edit, and the entry says that edit is the one thing the release deliberately carries forward, so it was not done here.

### v1.1.0.0 (`v1.1.0.0.md`)

Seven of ten fidelity-research recommendations were applied and three refused in writing. Every printed figure now goes through one number formatter per template, with grouping fixed to a comma rather than read from the host locale so a delivered file looks the same on the machine that opens it, and rounding at six decimals so an axis rung reads `0.6` rather than `0.6000000000000001`. A missing reading now breaks the mark instead of being drawn as zero, which was the worst and quietest defect in the corpus: `daily-line` breaks into segments at the gap, `daily-range` leaves the day undrawn while keeping its axis slot, `stacked-area` breaks the whole stack, and each prints how many readings were left out. `scatter` past twenty points and `heat-matrix` past a hundred cells now grow the frame and print the count and the ceiling. The heat matrix gained a five-swatch ramp legend. Rule 14 was added: every file gives its figure region a horizontal scroll and its drawing a minimum width so a narrow screen pans rather than squashes, enforced by a new `narrow-viewport` check. Five forms gained series-to-swatch mapping in the figure description for screen-reader users. Fixes: `progress-single` was measuring its headline number by character count at `String(value).length * 34` and now advances by measured text length, and `daily-line` could pick a gap as the low point because a missing value compares smaller than every real one. Refused in writing: a diverging colour system, pattern fills and a continuous gradient legend.

### v1.0.0.0 (`v1.0.0.0.md`)

First release of the packet. It ships twenty chart forms across six question families, three colour systems separated by what colour encodes (`neutral` for importance, `ordered` for magnitude, `categorical` for identity), six finished deliveries and a catalog checked in both directions so no row names a file it cannot reach and no file on disk lacks a row. A template-first contract of thirteen enforced rules puts the palette in a sentinel-marked block of CSS custom properties and the data in a second sentinel-marked block at the top of the script. `scripts/check-corpus.cjs` enforces every rule with no dependencies and an opt-in `--render` pass that opens each file in a headless browser. Every colour value lives in `assets/color/palettes.json` and nowhere else. A stated boundary against `sk-design-diagram` splits 33 keywords three ways, keeping bare type names such as `bar chart` with the neighbour while claiming data-qualified crossovers such as `bar chart of`. REMOVED before shipping: report mode and its directory were cut, along with gallery pages, on the stated ground that one form is one file and a gallery ships every other form's demo data alongside the one chart somebody asked for. The entry also records the packet as a workflow packet in the `sk-doc` parent hub, with a registry entry, stage-one vocabulary, router intents, a mode-table row, leaf-manifest entries and a single-route canary.

## Facts the v4 draft gets wrong or misses

- **Understates the checker work.** Draft line 278 says "Three decisions from that work are held by checkers rather than by convention". `v1.2.0.0.md` states the corpus check grew from fifteen named checks to twenty-five and from one browser-backed check to three in that release alone, naming eleven new ones including `settled-render`, `dark-render`, `palette-source-dark`, `empty-notice`, `geometry-block`, `catalog-system`, `type-scale`, `interaction-hygiene`, `interaction-state`, `number-format` and `gradient-sweep`. `v1.3.0.0.md` then adds `legend` and `tooltip-card` families. Three is far below what the entries record.
- **Misses dark-ground support entirely.** No line in the draft mentions it. `v1.2.0.0.md` gives every file a second palette block behind a `prefers-color-scheme` query with its own sentinel pair, adds a dark ground plus dark text roles and dark series values for all three systems to the palette source, and adds a `dark-render` check that opens each file with the scheme pinned dark and requires a different picture. This is the single largest reader-facing change in the chart history and the draft is silent on it.
- **States the form count without the history.** Draft lines 32 and 269 say 26 forms. `v1.0.0.0.md` shipped twenty, `v1.2.0.0.md` added the twenty-first, `bar-line-composed`, for a count and a rate over the same periods, and `v1.3.0.0.md` is the first entry to say twenty-six. No entry in this changelog records the move from 21 to 26, so the draft's 26 is correct against the current state and the five-form jump is undocumented here.
- **The `sk-create-chart` rename is not corroborated by these entries.** Draft line 272 says "Chart and diagram used to live under sk-doc as `sk-create-chart` and `sk-create-diagram`". `v1.0.0.0.md` already calls the packet `sk-design-chart` in its title and frontmatter while placing it in the `sk-doc` parent hub, and no entry in this directory ever uses the name `sk-create-chart`. The move from the sk-doc hub to the sk-design hub is also unrecorded in any entry. Both claims need a source outside this changelog.
- **Misses the shared gate arithmetic and the outside-delivery check.** Draft line 282 credits `apply-design-md.cjs` only. `v1.4.0.0.md` also adds `scripts/color-gates.cjs`, required by both the applicator and the checker so their luminance, contrast and rounding cannot drift apart, and `check-corpus.cjs --extra <dir>`, which runs the file-level families over themed HTML outside the package without adding it to the catalog, gallery or stock geometry set. It also records that derivation is fail-closed and that acceptance requires a SHA-256 provenance comment in both themes, which is stronger than the draft's "gated".
- **Misses the correctness work in v1.1.0.0.** Nothing in the draft covers `v1.1.0.0.md`. The null-as-zero defect, where a missing reading dived a line to the baseline on a day nobody measured and printed the word `null` beside it, plus the single number formatter and rule 14's pan-do-not-squash guard, are all user-visible behaviour changes absent from the draft.
- **A rename is still outstanding and unmentioned.** `v1.2.0.0.md` states that `rampDarkestOnSurface` and `rampLightestOnSurface` are to become `rampFarEndOnSurface` and `rampNearEndOnSurface` across `color-system.md`, `palettes.json` and `check-corpus.cjs`, and that this edit is deliberately carried forward. No later entry through `v1.5.0.0.md` records it being done, so the v4 draft may be shipping the old names.
- **Correct as written, for the record.** Draft line 278's "A cursor-derived Style Reference became the stock chart register late in the cycle" matches `v1.5.0.0.md`. Draft line 282's split of extraction to the md generator and application to the chart mode matches `v1.4.0.0.md`.
