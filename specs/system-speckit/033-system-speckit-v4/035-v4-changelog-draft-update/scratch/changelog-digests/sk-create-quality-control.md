## Per-version digest, newest first

### v1.0.2.0 - Runnable commands and repaired cross-references (2026-08-31)

Source: `v1.0.2.0.md`. This was a correctness pass over the packet's documentation, with no workflow, rule or standard changed. Every documented command was unrunnable and every reference file pointed at the wrong `SKILL.md` section. Three fixes to the commands: the interpreter in all 18 script invocations across `SKILL.md`, `README.md`, `references/workflows.md`, `references/validation-and-enforcement.md` and `references/workflow-examples.md` went from bare `python` to `python3`, because `python` is not on PATH in this environment and this packet was the last of the twelve `sk-doc` mode packets still using the bare form. Script paths in `SKILL.md` moved from packet-relative `../shared/scripts/<name>.py` to repo-root-relative `.opencode/skills/sk-doc/shared/scripts/<name>.py`, matching every sibling packet and the packet's own README. The three recipes in `references/workflow-examples.md` were replaced with versions that were actually executed first, because the old ones changed out of the repo root and then used a repo-relative path, fed `quick_validate.py` every directory under `.opencode/skills/` including non-skills, and used a `specs/042/spec.md` folder shape the spec tree does not use. Two corrected claims: `quick_validate.py` takes a skill or packet directory and errors with `SKILL.md not found` on a file path, so the `SKILL.md` §4 Step 6 instruction to run it "for the file" and the `validation-and-enforcement.md` description of it as a lowercase-kebab name check were both wrong, the latter being `check_authored_name_kebab.py`'s job, and a troubleshooting row that sent readers to section 1 now points at section 2. Seven cross-references across `workflows.md`, `optimization.md`, `transformation-patterns.md`, `validation-and-enforcement.md` and `workflow-examples.md` were shifted up by one to undo the fallout of the v1.0.1.0 renumbering. RENAME: the four execution modes in `references/workflows.md` were renamed from script-assisted review, structure checks, content optimization and audit snapshot to the `SKILL.md` §3 Step 1 names report-only audit, structure validation, content optimization and batch snapshot, so one decision no longer carries two vocabularies. REMOVED: stale "Mode 1" labelling was dropped from three reference titles, since it belonged to the pre-packet numbered-mode scheme.

### v1.0.0.0 - Initial Release (2026-07-06)

Source: `v1.0.0.0.md`. First release of `create-quality-control` as the existing-document audit and optimization workflow packet inside what the entry calls the `sk-doc` parent hub's ten-packet workflow-only architecture. It evaluates a target markdown document, extracts structure and metrics, computes a Document Quality Index score and quality band, applies Human Voice Rules, and edits the same document for structure, clarity and AI-friendliness only when edits are explicitly requested. Shipped with `SKILL.md` as the inline workflow contract covering four modes (report-only audit, structure validation, content optimization, batch snapshot) plus a separate content-optimization path, `references/workflows.md` for extended mode examples and troubleshooting, and `references/optimization.md` for transformation patterns and AI-friendly heuristics. The packet deliberately ships no local `assets/` or `scripts/`, running the shared `extract_structure.py`, `validate_document.py` and `quick_validate.py` and reading the shared `references/` standards instead of duplicating them.

## Facts the v4 draft gets wrong or misses

Draft read: `specs/system-speckit/033-system-speckit-v4/CHANGELOG-v4.0.0.0.md` (463 lines). The packet is named in exactly three places, lines 132, 136 and 443.

- **Packet count disagrees with the entries.** Draft line 132 says `sk-doc` "routes to fourteen nested `sk-create-*` workflow packets". `v1.0.0.0.md` describes a "ten-packet workflow-only architecture" as of 2026-07-06 and `v1.0.2.0.md` says "the twelve `sk-doc` mode packets" as of 2026-08-31. Neither entry supports fourteen. The count may have grown after the last entry was written, so this is a flag to re-verify against the live registry rather than a confirmed error.
- **Name inconsistency inside the draft.** Line 132 and line 136 call the packet `sk-create-quality-control`, which matches the directory and the `name:` field in its `SKILL.md` frontmatter. Line 443 lists the rename as "`doc-quality` to `create-quality-control`", dropping the `sk-` prefix. The changelog entries use the unprefixed `create-quality-control` for the packet in prose (`v1.0.0.0.md`, `v1.0.2.0.md`), so both forms are in circulation, but the upgrade-notes line should give the name a reader will actually find on disk.
- **The `doc-quality` predecessor name is unverifiable from these entries.** Draft line 443 asserts a rename from `doc-quality`. `v1.0.0.0.md` presents `create-quality-control` as an initial release and no entry mentions a prior `doc-quality` skill name, so nothing in this changelog corroborates the rename. Not contradicted either, just unsourced here.
- **The `/doc:quality` removal is stated by the draft but recorded in no entry.** Draft line 136 says "the old `/doc:quality` command is gone". None of the four entries records that removal, including `v1.0.2.0.md`, which is the entry that rewrote the packet's command documentation. If the draft keeps the claim, its evidence has to come from `mode-registry.json` or the command tree, not from this changelog.
- **Nothing from `v1.0.2.0.md` reaches the draft.** The draft carries no mention of the `python` to `python3` interpreter correction, the move to repo-root-relative script paths, the corrected `quick_validate.py` semantics or the seven repaired cross-references. Most of that is packet-internal and arguably below release-note altitude, but the `python3` fix is user-facing: a reader following a pre-v1.0.2.0 copy of any of those five files gets `command not found`.
- **The execution-mode rename is missing.** `v1.0.2.0.md` renamed the four mode names in `references/workflows.md` to the `SKILL.md` set. The draft's rename list at line 443 does not include it. Low impact, since the names are internal vocabulary rather than anything typed.
