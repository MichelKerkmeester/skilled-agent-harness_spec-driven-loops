#### R2-P2-001 — The new sibling listing prints repo-controlled strings to the terminal without stripping control characters

- **File:** `.skilled/skills/system-spec-kit/runtime/cli/spec/create.sh:1109` (sanitization), `:1114-1116` (print)
- **Claim:** The listing added by `f53d63e4615` writes two repo-controlled strings to the developer's terminal: the packet folder `name` (only filtered by `^[0-9]{3}-`, never character-sanitized) and `description` from `description.json`, which is whitespace-collapsed with `replace(/\s+/g, " ")`. JavaScript `\s` does not match `ESC` (`\u001b`) or other non-whitespace C0/C1 control bytes, so an ANSI escape sequence in a folder name or `description.json` is emitted verbatim to the terminal by `process.stderr.write` on every top-level `create.sh` run in that track. The class covers OSC 52 clipboard writes, cursor/line rewrites and prompt spoofing — the standard terminal-escape injection surface for CLI tools that print uncontrolled filenames (GNU `ls` quotes unsafe names precisely for this reason).
- **evidenceRefs:**
  - `[SOURCE: .skilled/skills/system-spec-kit/runtime/cli/spec/create.sh:1094]` — folder filter: `/^[0-9]{3}-/.test(name)`, nothing else.
  - `[SOURCE: .skilled/skills/system-spec-kit/runtime/cli/spec/create.sh:1101-1102]` — `description` read verbatim from `description.json`.
  - `[SOURCE: .skilled/skills/system-spec-kit/runtime/cli/spec/create.sh:1109]` — `description.replace(/\s+/g, " ").slice(0, 100)`; `\s` excludes ESC.
  - `[SOURCE: .skilled/skills/system-spec-kit/runtime/cli/spec/create.sh:1114-1116]` — raw `name`/`description` joined into the stderr payload.
  - `[SOURCE: specs/system-speckit/034-spec-folder-tooling/006-series-parent-rule-and-sibling-listing/tasks.md:147-149]` — the packet's security checklist covers only the seeded phrases, not listing output; the surface was never adversarially tested.
  - Counter-check: `rg -n "x1b|u001b"` over `create.sh` finds no control-character handling anywhere.
- **Counterevidence sought:** the exploit requires a hostile or compromised repository whose packet folder name / `description.json` carries escape sequences; the developer must then scaffold in that track; `description.json` is normally generated by repo tooling from the author's own text. Terminal emulator behavior varies (some ignore unknown OSC). These reduce likelihood, not the gap.
- **Alternative explanation:** maintainers may treat everything under the repo's own `specs/` tree as trusted input, in which case printing verbatim is intentional simplicity.
- **Final severity:** P2 (hardening gap; no privilege boundary crossed without attacker-controlled repo content). Escalation trigger: if repo content is declared untrusted consumed input, raise to P1 and add the adversarial test.
- **Confidence:** 0.7
- **Downgrade trigger:** already P2; closes as documentation of accepted trust boundary if maintainers state it.
- **Finding class:** class-of-bug (any future listing/diagnostic that prints filenames or metadata shares the gap).
- **Affected surface hints:** ["stderr sibling listing", "description.json", "packet folder name", "terminal escape sequences"]
- **Recommendation:** strip control characters before printing (e.g. `.replace(/[\u0000-\u001f\u007f-\u009f]/g, " ")` on both `name` and `description`) and add an adversarial test with an ESC-bearing `description.json`.
