WRITING RULES (house style, enforced by reviewers)
- HVR voice: no em dashes, no semicolons in prose, no serial comma, plain words, one idea per sentence.
- Every path repo-relative. Every check is a command with its expected output written next to it.
- Text is for a weak executor: imperative, literal, one action per step, no "as appropriate", no "consider".
- Where a step needs judgment, make the judgment NOW at authoring time and write the result literally.
- Never embed ephemeral labels (spec paths, ADR/REQ/task ids, phase numbers) inside code comments of any
  script or code you put into a doc. Keep the durable WHY in comments.
- Do not invent facts about the repository. For every claim about an existing file, line, script flag or
  behavior, run a READ-ONLY command (rg, sed -n, cat, ls, awk, jq, node --version, script --help) and write
  what you observed. Any command you put into tasks.md must be one you ran (read-only parts) or reasoned
  through against the real tree. If a command mutates, test it only against a COPY in the scratchpad
  (see below), never the real tree.
