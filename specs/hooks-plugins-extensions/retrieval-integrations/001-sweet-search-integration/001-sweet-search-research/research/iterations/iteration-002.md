# Iteration 2: Benchmark claims and Skilled applicability

## Focus

Q2: How credible are its usefulness claims (5-33% cheaper runs, up to 34% less model time)? What do its eval code and data show, and where would the gain be largest or zero for Skilled-style work (large markdown/skill trees, spec folders, TypeScript runtime)?

## Actions Taken

- Read the held-out retrieval and task-completion benchmark tables and their stated sample sizes, comparison arms, confidence intervals, and cost definitions.
- Read the model-time analysis scripts and generated reports to check what “model time” measures, how its interval is calculated, and how subagent use affects the largest claimed reduction.
- Compared the tested TypeScript/code-navigation slices with Skilled’s existing trigger-index and ripgrep retrieval contract.
- Traced the graph-summary call path after the prior iteration’s 2,000-character source-body claim. The active HCGS path uses a different prompt builder from the helper that includes source bodies.

## Findings

1. **The 5–33% cost claim is credible for the reported task benchmark, with a narrow scope.** The held-out comparison covers 200 SWE-rebench tasks across 16 languages, one rollout per arm, and five harness/model setups. Billed-cost reductions range from 5.4% to 33.3%, with the reported 95% intervals excluding zero in all five setups. The pooled arms each solve 481 of 1,000 runs, with no significant solve-rate change; the dollar figures are list-price equivalents for subscription runs, not actual invoices. 4. **Remote graph summaries can send source-derived metadata; full source-body transfer is not established on the active HCGS path.** With Groq or Cerebras credentials configured, provider selection prioritizes those remote services by default, and HCGS calls the selected provider during full or incremental summary generation. The active HCGS prompt includes the symbol name, signature, up to 200 or 500 characters of documentation, and child summaries. It sends that prompt through the provider API. The separate exported createSummaryPrompt helper can include up to 2,000 characters from entity.code, but the repository-wide call-site search found no in-repo caller; HCGS instead uses buildSummaryPrompt. I therefore narrow the prior iteration’s claim: source-derived metadata can leave when a remote provider is selected, but this snapshot does not establish that full function bodies leave through the normal graph-summary path. An explicit caller of the separate helper would be a different path.
