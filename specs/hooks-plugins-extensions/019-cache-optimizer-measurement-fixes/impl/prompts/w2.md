Implement one small change in `.pi/extensions/pi-cache-optimizer/index.ts` plus its tests.

## The defect

`readModelInputPricing` rejects an entire pricing block when the cached-read rate is zero:

```
index.ts:4129   if (cacheReadPerToken === undefined || cacheReadPerToken <= 0) return undefined;
```

So a model whose cost block authoritatively says cached reads are free is indistinguishable from a
model with no cache-read rate configured at all, and the report prints "unpriced" instead of a real
cost and a real savings figure. The cost arithmetic already handles a zero rate correctly
(`index.ts:4168`).

## The semantics to implement

An **explicit** zero is an authoritative statement by whoever wrote the cost block: cached reads
are free. **Absent** means unknown. **Negative** is invalid.

- `=== undefined` -> unpriced, unchanged.
- `< 0` -> unpriced, unchanged.
- `=== 0` -> priced, cached reads cost zero, uncached input still priced normally.

Apply the same reasoning to the input rate only if the same defect exists there — check first and
say what you found. Do not change the input rate's meaning if a zero input price would be nonsense.

## Proof required

1. A cost block with `cacheRead: 0` and a positive input rate prices: cached reads cost zero,
   uncached input is priced, and savings is a real number rather than "unpriced".
2. Negative control: a missing cached-read rate stays unpriced.
3. Negative control: a negative rate stays unpriced.
4. The existing expectation at `tests/cache-economics.test.ts:54` encodes the old behavior — update
   it deliberately and say in your reply that you did, and why it was wrong.
5. Test `readModelInputPricing` in isolation from the registry fallback at `index.ts:4144`, so a
   pass cannot come from the fallback path instead of the predicate.
