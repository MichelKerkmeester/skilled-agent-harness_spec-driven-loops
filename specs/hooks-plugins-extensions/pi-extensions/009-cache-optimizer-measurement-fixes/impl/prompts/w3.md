## Why this exists

The previous item made an unreported cache signal distinguishable per response. But
`getPiNormalizedUsage` carries a comment stating Pi guarantees input, cacheRead and cacheWrite are
always present on assistant messages "at least as zero" (`index.ts:2474`). Where that holds, the
host has already synthesized zeros and per-response detection cannot see the difference.

This item adds the declaration that covers that case. It is a companion to the presence check, NOT
a replacement: presence handles the per-response case, the flag handles the model-level case.

## What to build

Add a `reportsCacheUsage` capability flag to the `CacheCompat` block (the flags live around
`index.ts:246-263`).

- Unset -> current behavior exactly. No existing model changes.
- `false` -> every request for that model routes to unmeasured, never to a miss.
- `true` -> normal presence-based classification.

Do not invent a registry of which providers support caching. One flag, honestly defaulted.

## Proof required

1. A model with `reportsCacheUsage: false` and healthy token counts lands in `unmeasuredRequests`,
   with tokens and cost still recorded.
2. Negative control: a model with the flag unset behaves exactly as before — assert against the
   existing measured-miss case so a regression here is visible.
3. `reportsCacheUsage: true` does not force a hit; presence still decides.

Each new test must fail with your change reverted.
