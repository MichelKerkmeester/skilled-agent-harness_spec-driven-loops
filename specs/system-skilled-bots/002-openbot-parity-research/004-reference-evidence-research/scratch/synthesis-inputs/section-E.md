### 011-messaging-channels

`tinychannels-main` is the only reference with Telegram, Slack, Signal and WhatsApp transports, a durable send queue and a conformance kit. It is GPL-3.0-only [SOURCE: C/tinychannels-main/LICENSE:1-2] [SOURCE: C/tinychannels-main/Cargo.toml:55], and so is its conformance crate [SOURCE: C/tinychannels-main/crates/tinychannels-conformance/Cargo.toml:5]. Every row below is therefore "mirror the design, copy no code". The plan already mirrors most of the reference's design and cites the lines: the adapter contract, the capability matrix with a conservative default, the acknowledge order per transport, the backoff ladder and the five conformance rules. What the references add is a short list of failure paths in the transport and queue code that the plan's wire tables do not carry. OpenMausBot has no transport to mirror. Its only Slack code returns a hosted management URL [SOURCE: C/OpenMausBot-main/server/hosted-slack.ts:4-14]. The vendored `tinyconnectors` is OAuth connector integrations, not a channel transport [SOURCE: C/openhuman-full/vendor/tinyconnectors/README.md:1-4].
