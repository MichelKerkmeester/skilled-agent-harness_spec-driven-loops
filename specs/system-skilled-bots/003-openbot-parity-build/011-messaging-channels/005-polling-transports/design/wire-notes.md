# Telegram and Slack wire notes

The Telegram and Slack transports are written from this note, not from the reference. The reference is under a licence whose code this repository does not copy, so every fact below is restated in plain words with one `[SOURCE: <path>:<line>]` or `[SOURCE: <path>:<first>-<last>]` per fact, where `<path>` starts with `specs/system-skilled-bots/context/tinychannels-main/`. A row whose Value cell says `not stated` carries no citation, because the reference does not answer it.

---

## telegram

| Fact | Value | Source |
|------|-------|--------|
| API base URL and token placement | The base defaults to `https://api.telegram.org` and a trailing slash is trimmed. Every call is a POST to `<base>/bot<token>/<method>`, so the token sits in the URL path between `bot` and the method name. | [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/telegram/channel_core.rs:17-22] [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/telegram/channel_core.rs:178-180] |
| getUpdates | POST to `getUpdates` with three fields: `offset` set to the current offset, `timeout` set to 30 and `allowed_updates` set to `message`, `edited_message`, `message_reaction` and `callback_query`. The body is read as `ok` and `result`, a missing `ok` counts as true, and `result` is an array of updates each carrying `update_id`. | [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/telegram/channel_ops.rs:1870-1875] [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/telegram/channel_ops.rs:1921-1926] [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/telegram/channel_ops.rs:1969-1974] |
| How the offset advances | Only after the update's action succeeded, and to `update_id + 1` when that is above the current offset. A duplicate the seen window drops also moves it to `update_id + 1`. | [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/telegram/channel_ops.rs:1975-1986] |
| Starting offset | `0` when the loop starts. It lives in a local variable, so a restart begins at `0` again and nothing persists it. | [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/telegram/channel_ops.rs:1854] |
| Wait after a failed poll | 5000 ms after a transport error, an unreadable body or a non-409 API error. 2000 ms after an HTTP 409 conflict. | [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/telegram/channel_types.rs:26-29] |
| deleteWebhook | Not called before polling starts. It is called only inside the 409 branch, when the conflict description mentions a webhook, as a POST to `deleteWebhook` with one field, `drop_pending_updates` set to false. A success retries the poll at once. | [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/telegram/channel_core.rs:268-281] [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/telegram/channel_ops.rs:1935-1946] |
| getMe | GET `getMe`. The bot's username is `result.username`. The probe also uses GET `getMe`, with a 5 second timeout, and treats any non-success status as unhealthy. | [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/telegram/channel_core.rs:330-345] [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/telegram/channel_ops.rs:231-250] |
| Update shapes | A message update is read from `message` or `edited_message`: `chat.id` is the chat id, `chat.type` maps `private` to a direct message, `group` or `supergroup` to a group and `channel` to a channel, `from.id` (or `sender_chat.id`) is the sender id, `text` is the text and `date` is seconds, multiplied by 1000 for milliseconds. A callback query is read from `callback_query`: `id` is the query id, `from.id` is the sender id, `message.chat.id` is the chat id, `message.chat.type` the chat type and `data` the button payload, and a `data` that is empty or longer than 64 bytes is dropped. | [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/telegram/channel_ops.rs:408-459] [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/telegram/channel_recv.rs:769-773] [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/telegram/channel_ops.rs:295-330] |
| answerCallbackQuery | Called on receipt, before the allowlist check, so a press from a disallowed user is still answered. POST to `answerCallbackQuery` with one field, `callback_query_id`. | [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/telegram/channel_ops.rs:1993-1996] [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/telegram/channel_ops.rs:378-393] |
| sendMessage | POST to `sendMessage` with `chat_id`, `text` and `reply_markup` holding the inline keyboard. The sent message id is `result.message_id`. | [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/telegram/channel_send.rs:325-343] [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/telegram/channel_send.rs:457-462] |
| inline_keyboard | `reply_markup` is `{"inline_keyboard": [[...]]}`, one inner array per row. One button is `text` plus `callback_data`. `callback_data` must be 1 to 64 bytes and `text` at most 64 characters. | [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/telegram/channel_ops.rs:824-849] |
| Text length limit | `TELEGRAM_MAX_MESSAGE_LENGTH` is 4096. The reference counts it in UTF-16 units, so neither bytes nor characters. | [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/telegram/text.rs:7] [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/telegram/text.rs:15-24] |
| HTTP 401 | No 401 branch. A 401 is handled as any other non-success status: the probe reports `unhealthy` and `getMe` fails with a status message. The reference never names 401 as a rejected token. | [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/telegram/channel_ops.rs:231-250] [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/telegram/channel_ops_tests.rs:3240-3252] |
| HTTP 429 | Retryable. A 429 on a send sets `retryable` true. The wait does not come from `parameters.retry_after` and not from a header, because the reference reads neither: the poll loop waits `poll_error_backoff`, 5000 ms, like any other API error. | [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/telegram/channel_send.rs:377-386] [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/telegram/channel_ops_tests.rs:3912-3921] |
| MarkdownV2 | The reference sends `parse_mode` set to `MarkdownV2` and, when a 400 body says the entities cannot be parsed, retries the same text once with no `parse_mode`. This build sends plain text only, with no `parse_mode`. | [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/telegram/channel_send.rs:325-328] [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/telegram/channel_send.rs:377-400] |

## slack

| Fact | Value | Source |
|------|-------|--------|
| Web API base, method and token header | The base is `https://slack.com/api` with no trailing slash. Every call is a POST to `<base>/<method>`. The bot token travels in the `Authorization` header as a bearer token. | [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/slack/types.rs:12] [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/slack/api.rs:24-33] |
| The two tokens | The app-level token carries the `xapp-` prefix and is the token `apps.connections.open` is called with. The bot token is the token every other Web API call carries, `chat.postMessage` and `auth.test` included. The reference names no prefix for the bot token, so that prefix is `not stated`. | [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/slack/types.rs:95] [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/slack/socket.rs:27-28] [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/slack/api.rs:32-33] |
| auth.test response fields | `user_id` holds the bot's own user id, cached after the first successful read. `ok` is the flag the shared response gate requires to be `true`, and the `auth.test` read itself does not check it. | [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/slack/api.rs:73] [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/slack/api.rs:96] |
| apps.connections.open response field | `url` holds the WebSocket URL. The call is a POST carrying the app-level token, and it is rejected unless `ok` is `true`. | [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/slack/socket.rs:24-37] |
| A rejected token | The HTTP status is read as a number, and 401 or 403 becomes a forbidden error. A `200` body whose `ok` is not `true` is read for its `error` string, and twelve codes become that same forbidden error: `not_in_channel`, `invalid_auth`, `not_authed`, `account_inactive`, `token_revoked`, `token_expired`, `missing_scope`, `is_archived`, `cant_delete_message`, `cant_update_message`, `edit_window_closed` and `restricted_action`. A rejected token is not told apart from the other eleven. | [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/slack/api.rs:145] [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/slack/api.rs:99-104] [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/slack/api.rs:177-188] |
| Socket frame types | Three types are named: `events_api`, `interactive` and `disconnect`. An `interactive` payload is handled only when its own `type` is `block_actions`. `hello` is not named in the module, so it takes the catch-all path, which acknowledges any other type that carries an `envelope_id` and does nothing else. | [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/slack/socket.rs:164-169] [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/slack/socket.rs:206-212] [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/slack/events.rs:469] |
| The acknowledge | The client sends one JSON object over the socket, `{"envelope_id":"<id>"}`, echoing the `envelope_id` of the envelope it answers. | [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/slack/socket.rs:248-251] |
| When the acknowledge is sent | The simple path acknowledges first, before it handles the payload, because Slack redelivers anything not acknowledged within 3 seconds. The typed path acknowledges only after the sink accepts the typed record, and a full queue reconnects without acknowledging. An envelope that is never acknowledged is redelivered by Slack after the next connect. | [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/slack/socket.rs:247-253] [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/slack/socket.rs:58-63] [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/slack/socket.rs:194-199] |
| A disconnect frame | The connection loop breaks on a `disconnect` frame, and the outer loop opens a fresh `apps.connections.open` before it connects again. | [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/slack/socket.rs:164-167] [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/slack/socket.rs:49-54] |
| Reconnect wait | 2 seconds, the default `reconnect_backoff`. | [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/slack/types.rs:88] |
| Dedupe key | A socket delivery is keyed `socket-envelope:<envelope_id>`. A message is keyed `<channel>:<ts>`. Both live in a seen window of 2048 keys. | [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/slack/events.rs:149] [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/slack/events.rs:215] [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/slack/types.rs:21] |
| events_api message fields | `type` is read as `message` or `app_mention`. `channel` is the channel id, `channel_type` decides whether a direct message is in scope, `user` is the sender, `text` is the text and `ts` is the message timestamp. A message is skipped when `bot_id` is present, when `user`, `channel` or `ts` is empty, when `user` equals the bot's own id, or when `subtype` is `bot_message`. | [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/slack/events.rs:173-177] [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/slack/events.rs:193-216] |

The action's `value` is not read. | [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/slack/events.rs:472-485] [SOURCE: specs/system-skilled-bots/context/tinychannels-main/src/providers/slack/inbound.rs:59-72] |
| chat.postMessage | The body carries `channel` and `text`, plus `blocks` when the message has buttons. A plain text send also sets `mrkdwn` to `true`, and a threaded send adds `thread_ts`. | Text escape | `&` becomes `&amp;`, `<` becomes `&lt;` and `>` becomes `&gt;`.
