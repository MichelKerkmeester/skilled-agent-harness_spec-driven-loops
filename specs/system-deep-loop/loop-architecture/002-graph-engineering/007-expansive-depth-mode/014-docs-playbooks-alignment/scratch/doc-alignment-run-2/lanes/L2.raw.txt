function stepText(text: string, step: string): string {
  const start = text.indexOf(`      ${step}:\n`);
  if (start === -1) return '';
  const rest = text.slice(start + 1);
  const end = rest.search(/\n      step_[a-z_]+:\n/);
  return end === -1 ? rest : rest.slice(0, end);
}

### Lineage Timeout Flag

`--lineage-timeout-hours <N>` optionally narrows the per-lineage wall-clock timeout ceiling below the default 4 hours; values above the hard 4-hour maximum are rejected, and omitting the flag keeps the 4h default.

### Stop Policy Flag

`--stop-policy <convergence|max-iterations>` selects whether convergence may stop the loop early. The default `convergence` stops at legal convergence or `config.maxIterations`, whichever comes first; `max-iterations` treats convergence as telemetry only and forces the loop to continue until `config.maxIterations`, which is useful for forced-depth runs.

### Dry-Run Flag

`--dry-run` is a first-class flag in both execution modes, not a third execution mode. It still performs real setup resolution, artifact-root resolution, focus selection, prompt rendering, and convergence reads when those steps can run without side effects.

When `dry_run=true`, the workflow emits `dry_run_halt` JSONL preview lines to terminal output instead of appending to the live state log, and halts before executor dispatch, persistent state mutation, reducer refresh, or child-lineage spawn.

# Completed-run extension (--extend)

## 1. OVERVIEW

`--extend=N` reopens a completed research run in the same session and generation and adds `N` iterations. The run keeps its `sessionId` and generation, records one `run_extended` ledger event, and keeps the prior synthesis as `research/synthesis-v{generation}-r{continuedFromRun}.md`. `--extend-minutes=M` adds minutes to the duration budget of the same extension.

---

## 2. HOW IT WORKS

### Lineage And Preconditions

The extension uses lineage mode `completed-continue`. The run must already be complete. An unfinished run continues with `--lineage-mode=resume` instead. The extension is refused with fan-out.

### Iteration And Duration Budget

The iteration cap rises by `N` over the prior count. `--extend-minutes=M` is valid only with `--extend`. The new duration budget is `max(prior, elapsed) + M`, because the clock counts time since `createdAt`, so an extension started after the old budget still runs.

### Stop Interaction

Under `stopPolicy: convergence`, an extension with nothing new can stop again at once on `all_questions_answered`. Pass `--convergence-mode=off`, use `stopPolicy: max-iterations`, or add questions to `research/inbox.jsonl`.

### Ledger And Reducer Routing

The `run_extended` stem is part of the deep-research ledger schema, and the deep-research reducer routes it. The lifecycle event filters in `deep-research/scripts/reduce-state.cjs` read the same event.

# Expansive depth mode (--depth-mode=expansive)

## 1. OVERVIEW

`--depth-mode` takes `default` or `expansive`. A run without the flag is unchanged. `expansive` turns on a research frontier: the run seeds depth-one nodes from the topic before iteration 1, admits leaf `frontier_proposal` rows as nodes under depth, fan-out, budget, dedupe and cycle caps, and holds a convergence stop while frontier nodes stay open. The live pilot runs that would show this mode on real topics are still open, so this page describes the shipped code and its tests and records no pilot result.

---

## 2. HOW IT WORKS

### Seeding And Admission

The expansive run seeds depth-one nodes before iteration 1. Each iteration's leaf `frontier_proposal` rows go through `runtime/scripts/frontier-admit.cjs`, which admits each proposal into the node store. It applies the depth cap, the fan-out cap, the iteration budget, dedupe and cycle checks, and records a reason for each prune.

### Configuration

`expansiveDepth` in `deep-research-config.json` sets `maxDepth` to 3, `maxChildrenPerNode` to 6, and a 50/35/15 iteration budget across depths. `antiConvergence.depthMode` defaults to `default`. The convergence script adds `depthMode` to its stop-decision config only when the value is `expansive`.

### Stop And Next Focus

While a frontier node is open, a composite convergence stop becomes another iteration. Next Focus steers to the shallowest open node. The iteration cap, the anti-convergence floor, stuck recovery, pause, `--convergence-mode=off` and the max-iterations policy decide before the frontier veto, so the frontier never extends a run past them.

### Fan-Out

Fan-out lineages each receive a share of the seeded nodes. `runtime/scripts/fanout-run.cjs` passes `depthMode` to a lineage only when it is `expansive`. `runtime/scripts/fanout-merge.cjs` merges the lineage frontiers and runs a fan-in guard over the recorded partition.
