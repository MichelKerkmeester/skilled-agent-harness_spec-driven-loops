Each finding carries: id, surface, standard, severity (P0, P1 or P2), fix_class (literal or judgment), file, line, issue, evidence {cmd, exit, out} when a command proved it, and fix {old, new} only for a literal fix.
A failed probe you leave out of upheld_probes is held, not counted: the aggregator lists it in probes-held.json.
overrides is optional. It is how you overturn an earlier finding instead of only describing the problem in a finding: refuted when the finding is wrong, pre-existing when it predates the scope, duplicate when another finding already records it (name that one in the note), severity with a new P0, P1 or P2 when the lane graded it wrong.
Each override names the finding by the id its lane gave it (for example A-1, C-06) or a probe by its id in probes.json, and its note gives the evidence. When a lane used bare numbers as ids, write the lane id in front, for example A-1, because a bare number two lanes share matches nothing. Give each finding at most one override.
Check each lane finding you override by reading the file or running the command yourself.
