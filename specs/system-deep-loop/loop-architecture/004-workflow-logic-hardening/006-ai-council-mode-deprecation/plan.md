## 3. ARCHITECTURE

### Pattern
Standalone leaf agent. The council stops being a hub mode and becomes one agent that owns its own artifact contract.

### Key Components
- **`ai-council` agent**: the only council capability that survives. Today its body points at `deep-ai-council/scripts/persist-artifacts.cjs`, `deep-ai-council/references/structure/*.md` and `runtime/scripts/append-mode-event.cjs --mode ai-council` (`.skilled/agents/ai-council.md:405` to `:809`) and tells the agent to run `node` while its frontmatter says `bash: deny`. Without a rewrite the agent breaks the moment the packet is deleted. The rewrite moves the artifact layout and output schema into the agent body and has the agent write `ai-council/**` with its own Write and Edit tools. This follows the precedent's `003-agent-mirror-checker-relocation`, which moved a needed file out of a packet before the packet was deleted.
- **Agent mirror mechanism (D2)**: `.skilled/bin/agent-mirror-crosswalk.md` section 1 defines it. `.skilled/agents/` is canonical. `.claude/agents/` is a hand-kept twin edited in the same change. `.cursor/agents/ai-council.md` and `.devin/agents/ai-council/AGENT.md` are symlinks onto the `.claude` file. `.opencode/agents` is a directory symlink onto `.skilled/agents`. `.codex`, `.pi` and `.dsh` are generated by `codex/sync-agents.cjs`, `pi/sync-agents-pi.cjs` and `dsh/sync-agents-dsh.cjs` under `.skilled/skills/system-spec-kit/runtime/cli/`. `/doctor:runtime-mirrors` runs all of them in check mode. No new mechanism is added.
- **Council command (D3)**: two options.

| Option | What ships | Gain | Cost |
|--------|-----------|------|------|
| A. Agent only | The agent in eight folders. No command. | Smallest change. Nothing new to mirror or route. | The council is reachable only by naming `@ai-council` or through `@orchestrate`. The advisor can no longer offer a council command, and the user loses the setup step that binds the spec folder before artifacts are written. |
| B. Agent plus one command (recommended) | `.skilled/commands/speckit/ai-council.md`, `assets/speckit-ai-council.yaml` and `assets/speckit-ai-council-presentation.txt`, owned by `system-spec-kit`, single round | One typed entry point in every runtime through the existing command and prompt mirrors. The setup binds the spec folder before any write, as `/speckit:plan` does. | Three new files, their mirrors, a `command-metadata.json` row in `system-spec-kit` and an advisor bridge row. |

B is recommended because every tracked command carries an owner skill (`command-attach.ts:191` sets `ownerSkillId: 'system-deep-loop'` today), and the council writes into a spec folder the way `/speckit:plan` does, so `system-spec-kit` is the owner that fits without a new family. The speckit pattern is one command doc plus `speckit-<name>.yaml` plus `speckit-<name>-presentation.txt`, which already meets the phase 004 one-workflow-file rule. The phase 004 guard in `runtime/tests/unit/compile-command-contracts.vitest.ts` covers `deep/` commands only, so REQ-009 checks the one-file rule for this command with `ls`. The multi-topic session loop is dropped under both options, because it needs the `council` loop type and the session scripts that D4 removes. The name and family are an open question in `goal.md`.

### Data Flow
After the change a council request reaches the agent in one of two ways. The user names `@ai-council`, or, under option B, runs the speckit command, whose workflow binds the spec folder and dispatches the agent once. ## 7. ROLLBACK PLAN

- **Trigger**: a research or review prompt stops routing to its mode, the divergent pivot tests fail or a gate ends worse than its baseline and cannot be repaired in this phase.
- **Procedure**: every deleted file is tracked, so `git revert <sha>` for each commit of this phase restores the packet, the command set, the runtime libraries, the tests and the advisor entries. The same revert turns the moved changelog folder back into the tracked symlink. Then rerun the generators for the agent and command mirrors, `generate-leaf-manifest.cjs`, the command bridges and the trigger index, because derived files follow their sources. The revert does not touch untracked council graph databases, because this phase leaves them in place and never deletes them. `ai-council/**` artifacts inside spec folders are never edited, so they need no restore.
