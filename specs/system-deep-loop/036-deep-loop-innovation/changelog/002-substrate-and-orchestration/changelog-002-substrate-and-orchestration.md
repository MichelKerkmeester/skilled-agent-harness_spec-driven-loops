> Spec folder: `specs/system-deep-loop/036-deep-loop-innovation/002-substrate-and-orchestration` (Level 3)

### Summary

This group covers the substrate and orchestration spine of the 036 deep-loop innovation packet: the early fan-out live-tools unblock, the transition-authorized dark ledger core, the shared evidence and control services, the compatibility/shadow/rollback bridge, durable fan-out/fan-in orchestration, novelty/claims continuity and projections, and convergence/termination/health. Each child owns its own scope, plan, and verification; this parent tracks the shared theme only. Per the parent phase documentation map, phases 005, 006, and 010 are complete; phases 007, 008, 009, and 011 are in progress.

### Included Phases

| Phase | Summary |
|---|---|
| `001-fanout-live-tools-unblock` | Ship the early, backward-compatible fan-out live-tools unblock on fanout-run.cjs: a typed liveTools.webSearch policy, a fail-closed executor capability matrix, per-kind command adapters with invocation fingerprints, and models-by-branches-by-replicas manifest expansion; dispatch-only, with no canonical persistence change. |
| `002-transition-authorized-ledger-core` | Co-land the versioned event envelope, typed append-only ledger, replay fingerprints, and fail-closed transition-authorization gateway as one dark, non-authoritative substrate while legacy writers remain authoritative. |
| `003-shared-evidence-and-control-services` | Plan the seven shared evidence and control services (receipts + effect recovery, sealed reference artifacts, blinded adjudication, hierarchical typed budgets, stream-fold gauges, locks/fencing, continuity identities) behind the phase-006 envelope. |
| `004-compatibility-shadow-and-rollback-bridge` | Define the five compatibility, shadow-parity, in-flight-state, and rollback child contracts that make the dark deep-loop substrate provably safe for a later authority cutover without moving authority in this phase. |
| `005-fanout-fanin-durable-orchestration` | Make fan-out and fan-in durable over the canonical ledger through dispatch receipts, result envelopes, resumable branch orchestration, budget-aware completion policy, and provenance-balanced reduction. |

| `007-convergence-termination-and-health` | Replace count-based stopping with path-covering termination, cycle detection, independent stopping clocks, value-of-computation allocation, and a generic health and degeneration harness. |
