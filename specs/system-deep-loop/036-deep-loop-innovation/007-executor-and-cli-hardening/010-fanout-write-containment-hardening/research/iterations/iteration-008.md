# Iteration 008

**Model:** `llmgateway/glm-5.3-flash` at max thinking  
**Angle:** what coordination remains necessary once lineages are isolated: locks, leases, the append-gateway, and whether any of it can be dropped

## Findings
- **The loop lock is already a lease, not a plain lock** — its record carries `ownerPid`, `ttlMs`, `lastHeartbeatIso` and an `acquireNonce`, refreshed on a 15s cadence, and it is stale when "the owner PID no longer exists or the heartbeat has exceeded twice the TTL" (`runtime/lib/deep-loop/loop-lock.ts:19-28`, `loop-lock.ts:73` `DEFAULT_LOOP_LOCK_HEARTBEAT_INTERVAL_MS = 15_000`, `isStaleLoopLock`). Exclusivity is O_EXCL hard-link publish ("link() either fails because the path already exists (EEXIST…)") plus single-winner rename-claim reclaim ("rename() of a single inode succeeds for only the first caller"), and refresh/release are fenced by nonce+pid (`lockIdentityMatches`: "a guessed or stale owner pid alone can never refresh or release someone else's live lock") — `loop-lock.ts` `writeLoopLockExclusive` / `tryReclaimStaleLoopLock` / `lockIdentityMatches`. Its scope is **one lock file per run's own artifact dir** (`fanout-run.cjs:453-456`).
- **The runner never takes that lock; it only consumes it as a liveness oracle to whitelist co-tenants.** `holdsLiveLoopLock` (`fanout-run.cjs:515-531`) feeds `discoverForeignLiveRunDirs` (`fanout-run.cjs:536-575`), a packet walk bounded at depth 6 / 2000 dirs (`fanout-run.cjs:459-460`), whose results are passed as `unattributableDirs` into the containment call (`fanout-run.cjs:3136-3140`). Its stated reason is purely shared-tree: foreign runs' "lock, ledgers, iterations and receipts … land after this leaf's baseline was taken and a tree diff cannot tell them from the leaf's own" (`fanout-run.cjs:540-545`).
- **The append-gateway is already minimal: lock-free, append-only, producer-partitioned.** The orchestration ledger is one `fs.appendFileSync` JSONL line per event, "one line per lineage lifecycle event" (`fanout-pool.cjs:922-924`, contract note `:916-918`); the observability stream is likewise a bare `appendFileSync` of the derived path (`observability-events.cjs:164-181`, derivation at `fanout-run.cjs:315`). The loop state log (`deep-research-state.jsonl`/`deep-review-state.jsonl`) is written only by the orchestrating session's inline containment (`write-containment.ts` `appendContainmentEvent`, "Logging must never block the containment decision already taken") and by reduce-state's promotion/conflict appends (`deep-research/scripts/reduce-state.cjs:718-721`, `1344-1383`). The runner's own `enforceWriteContainment` call passes **no** `stateLogPath` — it maps findings into its own ledger instead (`fanout-run.cjs:3133-3177`), so each JSONL has exactly one writing process. Atomicity of one very large line (the 1,858-violation event, `045/spec.md` §1) under concurrent writers: UNKNOWN — not verifiable without executing.
- **Coordination that survives isolation #1 — the lease.** The loop lock arbitrates ownership of the packet's shared run dir (ledgers, receipts, the wait-checkpoint `orchestration-wait-checkpoint.json` at `fanout-run.cjs:444`), none of which any worktree replicates; nothing in `loop-lock.ts` mentions worktrees (checked: no `worktree` match in the file).
- **Coordination that survives isolation #2 — the shared CLI home per kind.** The per-kind state-dir env (`SPECKIT_STATE_ENV_BY_KIND`, `fanout-run.cjs:437-444`) is explicitly "DETECTION-ONLY … does NOT relocate the native lockfile. Real same-kind-replica isolation comes from each lineage's unique artifact dir (lineage.label); remapping the CLI home … is deliberately avoided … breaks credential/auth lookup" (`fanout-run.cjs:2856-2861`). So unlimited concurrent same-kind lineages still share one CLI-internal state dir, worktrees notwithstanding.
- **What becomes droppable is exactly the co-tenancy machinery.** Foreign-run discovery and its scan bounds (`fanout-run.cjs:459-460, 515-575`), the attribution carve-outs whose justification is "Under a concurrent fan-out, sibling lineages write their own artifacts while this leaf runs" (`write-containment.ts:64-75`, fed as `unattributableDirs`/`unattributablePaths: orchestratorOwnedPaths` at `fanout-run.cjs:3136-3142`), and the churn sampler — which the spec itself calls "a detector that only earns its place once the structural fix is in" (`045/spec.md` §4 preamble, REQ-004's `shared_checkout_detected`).
- **But they become dormant, not deletable.** The spec freezes detection ("The `unattributableDirs` and `unattributablePaths` carve-outs … are correct and stay as they are", `045/spec.md` §3 Out of Scope) and NFR-R02 keeps the degraded in-checkout fallback ("A worktree that cannot be created or removed degrades to the current in-checkout behaviour under preserve mode", `045/spec.md` §7) — so every isolated run still carries the dual-mode machinery for the preserve-mode path.
- **Isolation adds one coordination point of its own: the worktree-prefix startup sweep.** ADR-003: "The runner sweeps its own prefix at startup so an interrupted run cleans up on the next one" (`045/decision-record.md` ADR-003). The prefix is shared across runs; no lease/liveness gate is specified for the sweep, and no code exists yet to check (iteration-004: worktree operations are "prose, not code"). Whether a sweep would skip a *live* neighbour's worktrees: UNKNOWN.

## What this means for unlimited concurrency
- Per-lineage coordination cost is already ~zero and worktrees make it exactly zero: one lease per **run** (not per lineage), lock-free O_APPEND ledgers each with a single writer, and lineage-local state keyed by unique artifact dir. Nothing in the coordination layer scales with lineage count — the scalars are the copy-back collision (earlier finding) and the runner's shared worktree prefix.
- The two surviving mechanisms are scoped, not sharded: the loop-lock lease binds to the packet run dir, and the kind-shared CLI home (`fanout-run.cjs:2856-2861`) is a deliberate no-remap trade — as same-kind breadth grows, that home becomes the first shared-resource contention point, and the runner's only answer today is credential-preserving restraint, not arbitration.
- Most of the current coordination code is shared-checkout bookkeeping (foreign-run discovery, carve-outs, churn sampler); under worktrees it turns dormant. The "unlimited" path therefore permanently pays a dual-mode tax — it must keep the shared-tree machinery alive because the fallback mode (NFR-R02) and the frozen detection contract (Out of Scope) both require it.
- The lease machinery needed to govern the genuinely shared surfaces (copy-back target, worktree prefix) already exists in `loop-lock.ts` — TTL+heartbeat+nonce+fenced reclaim — but its scope (per-run artifact dir) covers neither; the unspecified arbiter noted for copy-back (earlier finding) extends to the new sweep.
