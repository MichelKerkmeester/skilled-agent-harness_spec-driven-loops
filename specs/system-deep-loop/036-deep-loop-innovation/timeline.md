## Current program state (2026-08-24 to 2026-09-05)

The table above is the frozen M0 baseline — original identity and creation order, with the `status`
column captured when the baseline was generated. Those baseline folders were consolidated into the
current phase tree (`001-research-inputs-and-architecture` … `009-innovation-gap-remediation`).
Post-consolidation, here is where the program actually stands:

- **Substrate — done.** The typed event-ledger substrate — versioned envelope, typed append-only
  ledger, fail-closed transition-authorization gateway, sealed-reference artifacts keyed by a single
  reference-set digest, replay fingerprints, and the shadow-parity harness with its identity
  registry — is built and landed.
- **All eight modes — migrated additive-dark, verified green.** deep-research, deep-review,
  deep-ai-council, deep-improvement-common, agent-improvement, model-benchmark, skill-benchmark, and
  deep-alignment each carry a typed ledger schema, reducers/projections, sealed artifacts,
  certificates/receipts, a resume adapter, a shadow-parity harness, and a rollback-guarded mode-gate.
- **CLI-adapter stress program — built.** A hermetic stress suite across the six external CLI
  adapters plus the fan-out scheduler, operator playbooks, a matrix-bijection validator, and a
  destructive-scope write-containment proof — all additive, touching no shipped adapter.
- **Whole-system gate — run.** Recursive strict validation clean; an independent blocking acceptance
  review confirmed the additive-dark claim, with one accepted, deliberate exception (autonomous
  model-benchmark promotion made advisory-only).
- **Enablement — executed.** Phase `012-runtime-enablement` built the append gateway and per-mode
  projection the modes lacked, migrated every mode's write protocol onto it, then flipped all eight
  modes to `new_authoritative_final`, dropped the legacy shadow writer, ran the whole-system gate to
  a literal PASS, and deleted the rollback and migration scaffolding the direct flip made dead weight.

The ledger is now authoritative for all eight modes; the legacy files remain readable, produced by
projection from the ledger rather than by a separate legacy writer. The new machine is driving; the
old writers are retired. This lands on the mainline with the `012` packet's merge.

### After the enablement cutover (2026-08-25 to 2026-09-02)

Packet `013-runtime-agent-gateway-alignment` migrated the deep-loop leaf agent prompts across all six
runtimes from a direct `*-state.jsonl` bash-append to the authoritative append gateway the `012`
enablement work introduced. A ten-iteration deep-review, `014-gateway-alignment-review`, then hunted
the full gateway-alignment surface, leaf agents in six runtimes, orchestrator YAMLs, deep command
docs, AGENTS.md and the gateway itself, for what the `013` fix and its own read-only audit had
missed, and confirmed ten findings. `015-gateway-contract-remediation` closed those findings so
exactly one path, the append gateway, is instructed, permitted and enforced across prompt-pack
templates, runtime projection refresh, the iteration validator, mode SKILLs, the conformance guard
and the ai-council MCP surface.

A twenty-iteration broad deep-review, `016-system-deep-loop-review`, then swept the whole
system-deep-loop surface beyond the gateway-alignment scope: the runtime, the eight `/deep:*` command
docs and their orchestrator YAMLs, the deep-loop agents across six runtimes, the mode-packet SKILLs
and references, and the `015` changes, hunting for correctness bugs, security gaps,
spec/implementation drift and cross-runtime inconsistency. `017-runtime-latent-issue-remediation`
then verified and fixed the P0 and P1 findings from that audit: the append-gateway
silent-divergence P0, fanout-merge severity/abort bugs, reducer availability and projection-read
issues, salvage/repair data-loss paths, pool retry-credit and sandbox gaps, write-containment edge
cases, convergence loop-type coverage and the residual `015`-drift documentation contradictions.
`018-pre-existing-test-triage` then triaged ten pre-existing runtime test failures that predated the
`016`/`017` work, fixing the one clean data-drift bug (a stale sk-prompt census path) and classifying
the rest as environment-only or risky-unrelated. The two risky failures it deliberately deferred, a
cross-skill better-sqlite3 version drift under an unstable Node ABI and a command rollout-mode
regression from recompiling the `deep/*` contracts, each became their own workstream under the
`019-risky-followup-remediation` phase parent.

A run of executor and CLI hardening packets followed. `020-tsx-boot-spaced-path-hardening` stopped
the runtime crashing with `ERR_MODULE_NOT_FOUND` on a checkout path containing a space under
`NODE_PRESERVE_SYMLINKS=1`, and gave containment an explicit repo-root override.
`021-containment-symlink-autoscope` closed the other half of that catch-22, resolving the containment
repo root to the worktree that physically holds a symlinked artifact instead of the working
directory's worktree, so containment works without requiring the override. `022-phase0-dispatch-anchor`
anchored the `deep/*` Phase-0 dispatch-context gate to the command runner's objective invocation-message
marker so capable orchestrators stopped false-blocking a genuine invocation with a self-classification
question, and `023-cross-runtime-dispatch` then retired that gate entirely as unfixable in-prompt,
defending a case that occurs in zero code and redundant with the deterministic harness guard.
`024-executor-kind-routing` added deterministic per-kind dispatch branches for
`cli-cursor`/`cli-devin`/`cli-pi` so a single-executor request on `/deep:review`, `/deep:research` or
`/deep:alignment` no longer silently degrades to native. `025-deprecate-deep-alignment` then removed
the deep-alignment mode entirely, cascading the removal, per operator approval, to the
conformance-benchmark capability it turned out to be the shared engine behind, while preserving the
behavior/model/skill/agent-improvement benchmarks and the shared behavior-benchmark framework.

Three packets merged in from outside this packet's own numbering on 2026-09-05, each renumbered from
a former top-level path. `026-codex-lineage-auth-isolation`, formerly
`system-deep-loop/038-codex-lineage-auth-isolation`, investigated a per-lineage `CODEX_HOME` fix for a
codex fan-out lineage authenticating as nobody and burning its timeout in a 401 reconnect loop. The
fix was reverted after a review returned FAIL, so the packet is kept as a withdrawn investigation
record rather than a shipped fix. `027-executor-availability-docs`, formerly
`system-deep-loop/039-executor-availability-docs`, corrected the deep-loop command contracts, which
had named a three-item CLI executor set while each command runtime actually accepts a different,
larger set and one contract advertised an executor its resolver rejects, so every contract now states
its own runtime's accepted set and cites the constant that enforces it.
`028-cli-lineage-nesting-and-containment-guard`, formerly
`system-deep-loop/040-cli-lineage-nesting-and-containment-guard`, closed a pair of related defects. A
cli-codex fan-out lineage read its orchestration prompt as an instruction to dispatch codex again, so
every iteration spawned a nested `codex exec` that died in the sandbox and returned no findings, and
write containment compounded the damage by reverting a concurrent operator edit from HEAD with no
recoverable record. The fix adds a pre-spawn refusal that stops the nesting, and makes containment
write a recovery patch before it reverts anything.
