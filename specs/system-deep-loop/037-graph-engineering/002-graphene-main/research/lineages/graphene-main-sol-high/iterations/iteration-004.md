## Findings

1. **REFINE repo-1: a golden corpus manifest must be semantic, not filename-complete.** Graphene's coverage test asserts only that ten stems exist; it never inspects the records behind those names. That lets `claim-lease`, `nogood`, `out-of-order`, and `human-timeout` pass without their advertised mechanisms. A `GoldenScenarioV1` row must declare `requiredEventPattern`, `requiredFieldsByKind`, `forbiddenEventKinds`, `expectedRefusals`, and `expectedStateCheckpoints`; the harness must parse the trace and reject an incomplete row before comparing snapshots. [SOURCE: specs/system-deep-loop/037-graph-engineering/context/graphene-main/crates/graphene-core/tests/golden.rs:104-127] **When not to use:** do not require one universal event sequence for scenarios whose contract intentionally permits commutative ordering; declare a partial order and explicit equivalence class instead.

2. **EXTEND repo-1: every accepted step needs an external prefix oracle, not only a final snapshot or fold-vs-fold-up-to equality.** `every_golden_log_replays_to_any_point` applies the same production transition semantics incrementally and through `fold_up_to`; a shared defect can make both sides agree. Commit an external `checkpoints` map keyed by authoritative sequence, containing normalized projection digest plus load-bearing selectors (truth state, node state, skip set, active claim, gate state). At minimum, assert immediately before and after contradiction/staleness, ask/resolve, expand, revoke, and amendment boundaries. [SOURCE: specs/system-deep-loop/037-graph-engineering/context/graphene-main/crates/graphene-core/tests/golden.rs:75-100] [SOURCE: specs/system-deep-loop/037-graph-engineering/context/blog-posts/Eval Engineering: build the gate that lets your agents merge without you (full 6-step course).md:109-115] **When not to use:** do not snapshot every harmless timestamp-only step; checkpoint contract boundaries, and use a digest for the full normalized state plus readable selectors for diagnosis.

3. **CONTRADICT repo-1 only if “event trace” means committed events alone: refusals require a paired operation-outcome transcript.** Graphene correctly models refusal as `{code,suggestion,reason,detail}` and as a result rather than an event, so a JSONL-only golden cannot prove refused stale completion, nogood admission, invalid human choice, or bound overflow. Each attempted operation needs `OperationOutcomeV1 {requestKind, requestDigest, accepted, refusal?, appendedSeqRange, stateDigestBefore, stateDigestAfter}`. A refusal assertion must match exact code/suggestion/detail and prove `appendedSeqRange=[]`, unchanged authoritative head, and unchanged projection bytes. [SOURCE: specs/system-deep-loop/037-graph-engineering/context/graphene-main/crates/graphene-core/src/refusal.rs:52-64] [SOURCE: specs/system-deep-loop/037-graph-engineering/context/graphene-main/crates/graphene-core/src/refusal.rs:81-121] **When not to use:** do not append a synthetic domain event merely to represent a refused operation; preserve it in the authorization/audit transcript while proving domain non-mutation.

4. **EXTEND repo-1 with exact scenario assertions for the four false-confidence fixtures.** Lease: require `CLAIM(id,node,session,expires_at)` → `CLAIM_REVOKE(id,reason=lease-expired)` → successor claim permutation → old-holder `NODE_DONE` refusal `ClaimRevoked`, with no `NODE_DONE` append. Nogood: register the nogood first, attempt the completing add, expect `WouldCompleteNogood`/`DropAMember` and no ledger change; separately assert `NogoodUnenforceable`. Temporal: append observed times `[14:00,13:00,15:00]` in arrival order and assert the post-second-event temporal projection changes according to 13:00 rather than arrival seq. Timeout: separate `wait`, `expire`, and `escalate` cases, with exactly one `HUMAN_ESCALATE` for escalation and explicit downstream blocked/skipped states. [SOURCE: specs/system-deep-loop/037-graph-engineering/context/graphene-main/specs/10-verification.md:95-100] [SOURCE: specs/system-deep-loop/037-graph-engineering/context/graphene-main/crates/graphene-core/src/event.rs:82-108] [SOURCE: specs/system-deep-loop/037-graph-engineering/context/graphene-main/crates/graphene-core/src/event.rs:128-141] **When not to use:** do not normalize away claim ids, refusal detail, timeout policy, observed time, or multiplicity when those fields are the scenario's discriminating evidence.

Preserve `t`, actor class, semantic ids/causal references, version, refusal shape, effect intent/receipt, budget debit, verdict, and after-state digest; normalize only manifest-declared transport ids, wall timestamps, token chunks, and model prose. The earliest mismatch maps directly to 036's `effective-event`, `execution-outcome`, `projection-semantic`, `missing-observation`, or `nondeterministic` divergence classes. ## Ruled Out

- **Filename presence as mechanism coverage:** a stem proves inventory only, not that required event kinds or refusals occurred. [SOURCE: specs/system-deep-loop/037-graph-engineering/context/graphene-main/crates/graphene-core/tests/golden.rs:104-127]
- **Final-state equality as parity:** terminal-equal paths can differ in denials, retries, effects, budgets, or intermediate unsafe states. [SOURCE: specs/system-deep-loop/036-deep-loop-innovation/008-compatibility-shadow-and-rollback-bridge/003-shadow-parity-harness/spec.md:190-197]
- **Fold-vs-fold-up-to as an external oracle:** both computations share the same reducer semantics and can agree on the same defect. [INFERENCE: an oracle derived exclusively from the system under test cannot detect a semantic defect shared by both evaluation paths]
- **Encoding refusal as a domain event:** Graphene's refusal contract is an operation result; 036 should retain it in the authorization/audit boundary while proving the domain ledger did not change. [SOURCE: specs/system-deep-loop/037-graph-engineering/context/graphene-main/crates/graphene-core/src/refusal.rs:1-12]
- **Normalizing every adapter difference:** removing actor, causal, refusal, effect, budget, or state-transition fields creates terminal-state false parity. [SOURCE: specs/system-deep-loop/036-deep-loop-innovation/008-compatibility-shadow-and-rollback-bridge/003-shadow-parity-harness/spec.md:127-135]
