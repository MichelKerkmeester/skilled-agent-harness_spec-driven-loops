# Iteration 13: P7 Durable Fenced Human Decision and Effect Authorization

## Focus

This iteration closes the remaining P7 composition boundary: turn a human choice into a durable, versioned, fenced, policy-authorized command, then determine exactly what it may authorize before an idempotent external effect. Human intent, graph-edge selection, and effect execution/recovery remain separate authority boundaries.

## Findings

1. **REFINE repo 1 into a durable command → edge → effect chain.** HumanGateDecisionCommandV1 binds command/request identity, gate ID/version, authenticated principal and capability, exact policy identity, option, observed context, expected head/epoch/fence, gate expiry, and idempotency digest. The gateway durably records allow or deny; an allow can authorize exactly one GateEdgeSelectedV1 domain event. Only that committed event—not a browser command or audit allow alone—may causally support a separately authorized EffectIntentV1. The shipped gateway records actor, capability, policy, evidence, head, epoch, idempotency, expiry, and decision digest, while append makes an allow proof single-use.
