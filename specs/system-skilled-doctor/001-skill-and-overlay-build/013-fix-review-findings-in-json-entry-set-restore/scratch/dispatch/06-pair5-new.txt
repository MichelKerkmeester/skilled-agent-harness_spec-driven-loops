The restore reads the pinned copy the run was given. For `apply` that is the checkout the manifest's pin names, and for a re-pin it is the new commit, whether or not the copy writes the file. Before its backup a re-pin plans each `json-entry` destination its copy leaves in place against the new commit, and when one cannot be applied it refuses with exit 2 and writes nothing. Without a pinned copy the overlay is refused, unless the live file holds exactly the bytes the entry's `pinnedSha256` names, because those bytes are the pinned copy. The refusal says to set `pin.checkout` or to put the file back to those bytes.
