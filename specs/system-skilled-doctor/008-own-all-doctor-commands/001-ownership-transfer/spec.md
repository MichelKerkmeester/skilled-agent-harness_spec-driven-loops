# Feature Specification: Phase 1: ownership-transfer

<!-- SPECKIT_LEVEL: 3 -->

---

## EXECUTIVE SUMMARY

Six of the seventeen doctor commands named sk-code, sk-git, sk-doc, system-skill-advisor or system-deep-loop as their owner, so the doctor surface had six owners. Their `skill_agent` tags now name system-skilled-doctor, the advisor's generated command rows follow, and the skill's own docs say it owns all seventeen. The bridge drift check prints `"changed": []` and every advisor command row for a doctor command carries `ownerSkillId: 'system-skilled-doctor'`.

**Key Decisions**: ownership moves through the router tag the deriver already reads, not through hand-edited rows; the skill description keeps the "Doctor commands that…" opening because a wording that starts "Every /doctor command" outranked `/doctor:helper` and `/doctor:update` on their own prompts.

**Critical Dependencies**: the command-bridge deriver `derive-command-bridges.cjs`.

<!-- ANCHOR:problem -->
## 2. PROBLEM & PURPOSE

### Problem Statement
`system-skilled-doctor/SKILL.md` said it owned eleven doctor commands and that six belonged to other skills. The advisor credited those six to sk-code, sk-git, sk-doc, system-skill-advisor and system-deep-loop, so a reader of the advisor brief saw a different owner per command.

### Purpose
Every doctor command names one owner, system-skilled-doctor, in the routers, the advisor and the docs.
<!-- /ANCHOR:problem -->

## 3. SCOPE

### In Scope
- Retag the six routers to `system-skilled-doctor` and regenerate the command bridges.
- Update the tests and the routing baseline that pin the old owner.
- Rewrite the ownership text in the skill's `SKILL.md`, `README.md` and `graph-metadata.json`, the root `README.md`, the spec-kit feature catalog and `commands/README.txt`.

### Out of Scope
- Moving engine scripts or workflow YAML - ownership is a routing and documentation fact, and the files stay in `.skilled/commands/doctor/`.
- History under `specs/` and `changelog/` - it records what was true then.

## 8. EDGE CASES

- Empty input: a router with no `skill_agent` tag fails the deriver with a named error, and all seventeen keep their tag.
- Maximum input: all seventeen routers now share one owner, and the deriver accepts two entries for one runnable only while their owners agree.
- Failure path: a stage invariant broken by a hub that attaches a command it does not own fails `command-routing-slice.vitest.ts`.
