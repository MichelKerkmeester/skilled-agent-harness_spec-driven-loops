## 1. SUMMARY

### Technical Context

| Aspect | Value |
|--------|-------|
| Language/Stack | Markdown, JSON, Git |
| Framework | None |
| Storage | None |
| Testing | The fleet metadata gate, the skill-graph compiler and the link-integrity guard |

### Overview
The class contract decides the file set: a standalone root must not carry a mode registry, a hub router, a description or a command-metadata file, and must carry a manifest config whose derived manifest and alias projection are regenerated rather than authored. The flatten is done with `git mv` so the engine's history follows it up a level, and the two derived files are regenerated by the gate's own fix mode rather than written by hand.

## 3. ARCHITECTURE

### Pattern
Class conversion driven by an authored discriminator: removing the registry and router pair is what reclassifies the root.

### Key Components
- **`leaf-manifest.config.json`**: The authored declaration that names the single workflow mode and its leaf roots
- **`leaf-manifest.json` / `leaf-aliases.json`**: Derived; regenerated from the config and the on-disk corpus
- **The in-SKILL.md router**: A standalone skill's intent signals and resource map live in its own SKILL.md, not a separate router document

### Data Flow
The advisor resolves one identity from `graph-metadata.json` and loads the skill; the skill's own intent signals then select leaf resources from its references and assets. The hub's two-stage resolution collapses to one stage.
