# The refusal case — chosen before the accept case, deliberately borderline

**Request, in a user's words:**

> "We keep forgetting to run the tests before saying something is done. Add a repo rule
> that says you have to run the tests and read the output before claiming completion."

**Why this is borderline rather than obvious.** It is genuinely trigger-shaped ("about to
claim completion"), it names a real recurring failure, it is about discipline rather than
routing, and it is not asking for a skill. Three of the four decision tests pass. A mode
that refuses only nonsense would accept this.

**Prediction before running:** refused by **test 3, part 2** — it already has a home.
`evidence-and-proof.md` covers claiming completion, observed evidence, and reading command
output. Destination: a section in that rule, not a new file.

**Second candidate if the first is wrong:** test 1, always-loaded — `AGENTS.md` §1 Law 3
(VERIFY) already binds this every turn, which would make it a row rather than a rule.
