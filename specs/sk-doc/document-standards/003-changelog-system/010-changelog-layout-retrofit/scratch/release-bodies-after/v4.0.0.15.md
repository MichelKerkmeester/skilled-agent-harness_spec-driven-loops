A spec packet used to need a strong model.

- A fast, cheaper model would leave template text unfilled.
- It would delete sections it should keep.
- It would loop on metadata errors it could not read.

Now the templates show what good looks like.

- The validator catches an unfilled value.
- It repairs a draft's metadata on its own.
- A one-page guide walks a model through the packet.
- Every existing packet keeps the verdict it had.

The release also trims what a model has to carry.

- Three add-on templates are gone.
- Scaffolds lose their filler sections.
- The skill advisor sends typed commands to the skill that owns them.
- It stops calling most prompts ambiguous.

&nbsp;

## Why This Release

Spec-driven work only scales when a cheaper model can do the writing.

- Packets written against the new templates scored higher than packets written before this work.
- That held in every round.

## Spec Kit

Now the templates show what good looks like. The validator catches an unfilled value.

#### Templates That Teach <a id="c-templates-that-teach"></a>

- Each template section opens with a fill note.
- It gives one line on what to write, a good example and a weak one.
- The examples use a neutral task.
- They do not echo whatever the model was asked to build.
- So a model no longer copies them into its own packet.
- Scaffolds lose the sections small work never needs.
- New scaffolds are shorter.
- The effort estimate and the extended rollback are gone.
- Edge cases shrink to three lines.
- Sign-off shrinks to one row.
- A `spec.md` now carries a Measured Behavior block.
- It holds the command the change affects and its real output.
- The validator warns when that block holds neither output nor a reasoned "N/A".
- It does not fail.

#### An Unfilled Value Cannot Ship <a id="c-an-unfilled-value-cannot-ship"></a>

- Templates mark each value a writer must supply with a `[YOUR_VALUE_HERE: ...]` token.
- A token left in a Draft packet is a warning.
- The same token fails the packet at any other status.
- A token quoted inside inline code or a code block counts as an example.
- A code block ends only on its own fence marker.
- So a fence quoted inside another one cannot hide a token after it.
- The check reads only docs built from the new templates.
- So older docs validate as they did.

#### One Validator Run, Then Fix Everything <a id="c-one-validator-run-then-fix-everything"></a>

- The spec authoring card is a one-page path through a packet for a weaker model.
- It is `spec-authoring-card.md` in system-spec-kit.
- It asks for one `validate.sh --strict --quiet` run.
- It asks for a fix for every rule that failed before the next run.
- That replaces one run per rule.
- A run can fail on generated metadata.
- Then the validator's first hint line is the exact repair command.

#### Drafts Repair Their Own Metadata <a id="c-drafts-repair-their-own-metadata"></a>

- When every error in a strict validation of a draft comes from generated metadata, the validator runs the repair once.
- It names every file it rewrote.
- Then it validates again.
- It never touches body text.
- It never runs in CI.
- It never runs for a packet that is not a draft.
- A recursive run repairs each draft child the same way.

#### Three Add-Ons Retired <a id="c-three-addons-retired"></a>

- The three templates are deleted, not just hidden.
- So seven add-ons remain.
- Packets that already hold those files still validate.
- The research and review loops still write their own resource maps.
- Those maps never read the removed template.

#### Scaffolding Stays Inside the Repository <a id="c-scaffolding-stays-inside-the-repository"></a>

- `create.sh --track` refuses an absolute path or one with `..`.
- `create.sh --path` judges an existing folder or link.
- It looks at where it really points.
- So it refuses a link out of the repository.
- It also refuses a broken link, a regular file and the repository root itself.
- A track that already exists as a symlink keeps working by design.

## Skill Advisor

The skill advisor sends typed commands to the skill that owns them.

#### Typed Commands Route to Their Owner <a id="c-typed-commands-route-to-their-owner"></a>

- A prompt that types `/deep:research :auto` used to rank system-spec-kit first.
- That is because the skill borrowed score from the deep loop it supports.
- A skill can borrow from a typed command's owner.
- It can now rise up to the owner.
- It never rises past it.
- Mode suffixes such as `:auto` and `:confirm` no longer count as words in the prompt.
- So they stop matching any skill that happens to mention "auto".

#### Fewer False Ambiguity Flags <a id="c-fewer-false-ambiguity-flags"></a>

- The advisor called 110 of 261 labelled routing prompts ambiguous.
- That was mostly because a confidence floor lifts unrelated skills.
- It lifts them to the same confidence as the top.
- A skill that only reached that floor now counts as tied.
- That holds only when its score is also close.
- A skill held below a typed command's owner never counts as tied with it.
- Flags fell to 78.
- Every top pick stayed the same.
- The hook brief now names a skill that is in the tie.

## Git Worktrees

An operator's private `local-*` commands are git-ignored.

#### Private Commands Reach Every Worktree <a id="c-private-commands-reach-every-worktree"></a>

- So a new worktree used to start without them.
- Worktree provisioning now links each one in from the primary checkout.

## Upgrade Notes

These steps cover the upgrade.

#### Before You Start <a id="c-before-you-start"></a>

1. Stop requesting the retired add-ons. Drop before-after, roadmap and resource-map from any script or prompt that asks for them.

<details>
<summary><b>Spec Kit</b></summary>

- Point a weaker authoring model at the card. Hand it `spec-authoring-card.md` before it starts a packet.
- Turn off draft repair where a run must not write. Set `SPECKIT_DRAFT_AUTO_REPAIR=0`.

</details>
