## Core, Scoring and Providers

Fixes reach core infrastructure, the scoring modules and the embedding providers.

#### Schema Version and Error Codes Fixed <a id="c-schema-version-and-error-codes-fixed"></a>

- The vector index had a schema version mismatch.
- Its schema version moves from 9 to 11.
- `QUERY_TOO_LONG` changes from E040 to E042.
- `QUERY_EMPTY` changes from E041 to E043.
- Their old codes were duplicates.

#### Scoring Uses Only Valid Tiers <a id="c-scoring-uses-only-valid-tiers"></a>

- Folder scoring's `TIER_WEIGHTS` were inconsistent with the authoritative importance tiers.
- They are now aligned with them.
- The composite scoring multipliers named "high" and "low" tiers.
- Those tiers do not exist, and both multipliers are removed.
- The five factor scoring test now uses valid tier names as well.

#### Providers Identify Themselves <a id="c-providers-identify-themselves"></a>

- All 3 embedding providers gain a `getProviderName()` method.
- The README's API documentation for `process_with_retry()` did not match the function's actual parameters.
- It is fixed to match them.

&nbsp;

## Extraction and Error Handling

Fixes reach the extractors and error handling.

#### Extractors Throw Errors Instead of Exiting <a id="c-extractors-throw-errors-instead-of-exiting"></a>

- Null values in `collected_data` and `observations` could crash the file extractor.
- It now runs defensive null checks on both.
- The exits were `process.exit(1)` calls in the file extractor and the diagram extractor.
- Each is now `throw new Error()`.
- An error message in the workflow is also improved.
- It now carries actionable guidance.

#### Sharper Phrase and Contradiction Matching <a id="c-sharper-phrase-and-contradiction-matching"></a>

- Two helpers join the prediction error gate.
- They are `hasWholeWord()` and `areTermsInSameContext()`.
- The trigger extractor's deduplication logic also changes.
- It now prefers longer, more specific phrases over shorter ones.
- The prediction error gate detects contradictions better.
- It raises fewer false positives.

&nbsp;

## Templates

Fixes reach the templates.

#### Templates Follow the Inheritance Chain <a id="c-templates-follow-the-inheritance-chain"></a>

- The checklist carried L3+ sections.
- Those sections belong only in `level_3+`, and they are removed from it.
- Level 3 templates now correctly inherit the L2 addendum content.
- The template source comments are updated to reflect the inheritance chain.

#### Section Numbers and Separators Fixed <a id="c-section-numbers-and-separators-fixed"></a>

- The spec template numbered its OPEN QUESTIONS section 10.
- It is now section 7.
- The L2 and L3 templates used a doubled separator, `------`.
- It is fixed to `---`.

&nbsp;

## Commands and Documentation

Fixes reach the memory commands and the skill documentation.

#### Complete Tool Names and Tables <a id="c-complete-tool-names-and-tables"></a>

- The context, manage, save and learn commands carry the full `spec_kit_memory_` prefix.
- They carry it in their MCP Matrix tables and allowed-tools lists.
- Tool prefixes are now standardized across the commands.
- The skill documentation's tool table lists 22 tools.
- That is up from 14.
- Eight missing tools join the skill documentation's tool table.
- They are `memory_context`, `task_preflight`, `task_postflight`, `memory_drift_why`, `memory_causal_link`, `memory_causal_stats`, `memory_causal_unlink` and `memory_get_learning_history`.

#### Line Counts and Paths Corrected <a id="c-line-counts-and-paths-corrected"></a>

- The skill documentation's template line counts did not match the actual sizes.
- They now read 450 for L1.
- They read 890 for L2 and L3.
- They read 1080 for L3+.
- The decision format path now points to the `validation/` subfolder.
