## Spec Kit

The spec kit changed the most under the surface. The memory database that powered `memory_search` was retired outright. The specs folder moved. The runtime was renamed and nested. The completion gate was made coherent.

Three research rounds cut the kit back to what a machine reads. Most of the depth is in what left. An entire retrieval engine was replaced by two small lexical tools.

#### Specs Move to the Top Level <a id="c-specs-move-to-the-top-level"></a>

> [!WARNING]
> This is a breaking change. Specs move from `.opencode/specs/` to a top-level `specs/`. Old paths resolve through a compatibility symlink.

- Your spec paths have a new root.
- The specs folder moved from `.opencode/specs/` to a physical top-level `specs/` directory.
- Canonical spec paths are now `specs/...`.
- Anything still pointing at `.opencode/specs` keeps working while you catch up.

#### The Memory Database Retired <a id="c-the-memory-database-retired"></a>

- The Spec-Kit Memory engine is gone.
- The SQLite database, the embedder and the spec-memory MCP server were decommissioned end to end.
- Its daemon and the `memory_search` and `memory_save` tools were decommissioned too.
- That work started on a side branch.
- It then landed on the release branch and `main`.
- The `spec-memory` daemon CLI under `.opencode/bin/` went down with it.
- So did the `system-spec-memory` OpenCode plugin.
- Both were doors into the same engine.
- What replaced them is deliberately small:
- A committed trigger index is generated from every document's `trigger_phrases` frontmatter.
- A lookup script reads it with no daemon.
- A set of ripgrep recipes handles free text.
- All of it sits behind `/speckit:search`.
- The kit's own context writer handles continuity.
- Retrieval is lexical now.
- A miss is a clean no-hit rather than a degraded guess.
- The decommission left debt.
- That debt ran from dangling registrations to a package that still called itself an MCP server.
- It was closed across six review passes.

#### The Runtime Renamed and Nested <a id="c-the-runtime-renamed-and-nested"></a>

- The surviving package no longer carries an identity it lost.
- Its engine lives at `.skilled/skills/system-spec-kit/runtime/cli/`:
- `spec/validate.sh`, `spec/create.sh`, `spec/repair-derived.cjs` and `spec/recommend-level.sh` handle the packet lifecycle.
- `continuity/` handles saves.
- `spec-folder/` handles generated metadata.
- `retrieval/` handles the trigger index.
- The old `scripts/` and `mcp-server/` paths are gone.
- Anything you pinned to them needs repointing.
- A shared package underneath carries the Gate-3 classifier and the frontmatter parser.
- Every other skill now imports those rather than copying them.

#### A Completion Gate That Tells the Truth <a id="c-a-completion-gate-that-tells-the-truth"></a>

- The gate decides whether a packet may close.
- It now returns the same verdict whatever the environment.
- It counts one fault once.
- It no longer asks a packet for what it cannot satisfy from inside itself.
- Forty rules are registered.
- A warning is advice that does not fail a run.
- It grew one check of its own.
- That check is acceptance coverage, which runs on by default as an advisory.
- A scope-adherence check was planned for this release and did not ship.
- So no rule compares a packet's changed files with its spec.
- Two documents joined the packet contract.
- `acceptance-criteria.md` decides closure at Levels 2 and 3.
- An optional `goal.md` holds the durable directive you set as the session objective.
- A repair tool fixes facts a packet records wrongly but a machine can recompute.
- Those facts include its folder, level and generated fingerprints.
- It refuses to invent the facts only a person can write.

#### Smaller Templates, Same Output <a id="c-smaller-templates-same-output"></a>

- The spec, plan, tasks and implementation-summary templates were consolidated into one shared core.
- That core carries level-gated addenda.
- The source dropped to 1,275 lines across four core templates.
- Not a single rendered byte changed.
- The research template shrinks by level too.
- A Level 1 spec now gets a short research doc instead of the full one.
- A Level 1 research doc renders at 175 lines instead of 944.
- You see smaller, level-appropriate templates.
- What they produce is identical.

#### Fan-Outs Contain Their Writes <a id="c-fan-outs-contain-their-writes"></a>

- Containment now preserves by default.
- A lane's out-of-scope writes are left where they landed.
- A copy of each goes into a quarantine directory beside the run.
- The lane's outcome is recorded apart from the containment result.
- A lane never fails because a neighbour or you touched a file.
- Restores are targeted at the baseline the lane started from.
- They are never written through a symlink.
- A neighbour's `index.lock` is waited out rather than tripped over.
- Forced-depth runs fail loudly on an empty record set.
- An iteration recorded twice is tolerated once.
- Every direct state-log append now goes through the gateway.
- Per-lineage worktrees were built as well, then measured.
- Four research lanes on four models agreed on one point.
- Attribution cannot be made exact on a shared tree after the fact.
- The operator ruled attribution out as a requirement.
- The worktree mechanism was removed from the default path.

#### A New Evidence Ledger, Now Authoritative <a id="c-a-new-evidence-ledger-now-authoritative"></a>

- The deep loops grew a new spine.

- A research program of recommendations across the loop family converged on a single architecture.
- That architecture is an append-only ledger with a few load-bearing parts:
- A typed, append-only event ledger as the single record of what happened.
- A fail-closed gateway that authorizes every state transition.
- Sealed reference artifacts, versioned replay fingerprints and receipts.
- Blinded adjudication for the judgments the loops make.
- The runtime holds live in-flight state.
- So it could not be swapped in one move.
- The substrate landed the careful way.
- It was additive and dark behind compatibility adapters.
- It proved shadow parity against the existing behavior.
- Then it cut over one mode at a time behind a rollback window.
- Every ledger mode is now on the authoritative path.
- The ledger is the record.
- Legacy files are produced by projection from it.
- A fail-closed guard rejects any out-of-band write to a projected file.
- Every run is replayable and every transition accountable.
- The finding dedup and the two progress gauges in the fan-out runtime stay off by default.
- You flip them deliberately rather than inherit them.

#### The Dispatch Guards Now Actually Guard <a id="c-the-dispatch-guards-now-actually-guard"></a>

- Adding a seventh runtime meant reading the preflight that is supposed to stop a bad dispatch.
- It was approving things it declared forbidden.
- Six conditions were silently passing.
- The worst was Codex.
- The dispatch shape that recognises a `codex exec` command was wrong in two places.
- So no `cli-codex` rule ever loaded.
- Every Codex dispatch went out unchecked.
- Hermes fan-out lineages were unguarded for a different reason.
- The runner never set the project-plugin opt-in.
- So the packet and read-only markers the guards read were never visible.
- The seven `cli-*` packets moved their stdin rule from advice to blocking.
- A reader-toolset requirement was added.
- A preload exemption that excused too much was removed.
- Coverage then widened past the runtimes that had an adapter.
- Cursor gained one.
- OpenCode began enforcing in-process before a tool call rather than only recording after it.
- Both call the same shared rule engine rather than carrying a copy.
- So a rule cannot mean one thing in one runtime and something else in another.
- The last piece is the one that keeps this from rotting.
- A guard asserts a bijection between the rules the packets declare and the checks the engine implements.
- It carries a fixture pair per check.
- A workflow runs it on every change.
- It fails closed when the suite is missing.
- A declared rule with no check now fails the build instead of passing quietly.
- That is exactly how all six holes opened.

#### The Cache Extension Learned What Caching Costs <a id="c-the-cache-extension-learned-what-caching-costs"></a>

- Pi ran two forked cache extensions for most of the cycle.
- They split work by a hand-maintained model allowlist written twice.
- A fixture and a cross-extension test existed only to prove the two copies had not drifted.
- That is gone.
- `deep-pi` is retired.
- Its capabilities were absorbed into the surviving `pi-cache-optimizer` fork.
- One extension now covers every model.
- Cost, not just token counts.
- `/cache-optimizer stats` reports input cost.
- It reports the fully-uncached baseline it is measured against, savings and prefix churn.
- Prices come from the model registry rather than hardcoded rates.
- A model with no cost block reads as unpriced, never as a confident zero.
- Honest measurement.
- A response that reports no cache fields counts as unmeasured.
- It stays out of the hit ratio instead of scoring as a miss.
- Its tokens and cost still count in full, because the request really was billed.
- A model that never reports can declare so once rather than being guessed at per response.
- A retry-loop guard.
- A turn whose tool batch keeps failing used to reissue the same billable request.
- Nothing noticed.
- The guard tracks a whole batch.
- It escalates only when the batch fails repeatedly with no success in between.
- One legitimate retry stays silent.
- The case that actually burns money is a batch that partially succeeds every time and never converges.
- That is the case it catches.
- Hash-verified edits.
- A model reads a file and composes an edit against what it saw.
- The content moves before the edit lands.
- The edit still matches somewhere.
- It succeeds against the wrong lines and reports nothing.
- Read output now carries per-line content hashes and the file's line count.
- An edit that cannot prove its target held still is refused by name.
- There is no fuzzy fallback.
- A looser match is the silent corruption this exists to prevent.
- One experiment was reverted rather than kept.
- A gate was meant to lift a prompt prefix only after it proved stable across turns.
- It turned out to rest on void evidence.
- The hook it used fires once per user prompt rather than once per provider request.
- So the one-shot processes that tested it never reached a second observation.
- They lifted nothing at all.

#### What the Caching Is Actually Worth <a id="c-what-the-caching-is-actually-worth"></a>

- The gateway behind Pi's DeepSeek and GLM routes is DevPass.
- A claim that it is a flat-price subscription was wrong.
- It bills per token at ordinary list rates.
- The plan buys credits at a three-times bonus.
- That discounts the bill rather than removing it.
- That correction matters.
- The flat-price story had been used to argue that no dollar figure could exist for these routes.
- It had also been used to argue that tokens were the only honest metric.
- They can be measured, and were, across thirteen requests in one sitting.

| Model | Cached input | Billed | Uncached baseline | Saving |
|---|---|---|---|---|
| DeepSeek V4 Flash Vision | 169,728 of 172,000 | $0.000793 | $0.024080 | 96.7% |
| GLM-5.3-Flash | 95,296 of 140,317 | $0.006344 | $0.012348 | 48.6% |

- The gap between those two is the part worth carrying away.
- DeepSeek charges two percent of its prompt rate for a cached read.
- So a very high hit rate converts almost directly into the saving.
- GLM charges twenty-eight percent.
- So a good hit rate yields barely half as much.
- Same extension, same optimisation, roughly half the value.
- The rate card decides it.
- The hit rate in your footer is an input to the saving, not the saving itself.

## The Skill Advisor

#### Stricter Workspace Anchoring <a id="c-stricter-workspace-anchoring"></a>

> [!WARNING]
> The CLI front door is fail-closed and untrusted by default now too. A mutation through the CLI needs `--trusted`, or it is refused. The native MCP registration that once carried the same setting is gone with the transport.

- The advisor had been leaving litter in spec folders.
- It wrote its `.advisor-state` next to whatever directory a session happened to run from.
- Two changes pull that back toward the repo root.
- One is a shared anchored root resolver.
- The other switches from the old specs-only deny-list to a structural boundary.
- That boundary hoists state above the outermost `.opencode`.
- The skill graph was tidied in the same pass.
- Its metadata now points at the tracked source file.
- A one-identity ingestion hole was closed.
- A read-only freshness panel shows you whether the compiled graph is current.
- The reciprocal-rank-fusion spine and the conflict rerank graduated from dark flags to shipping defaults.
- The separate self-recommendation guard was cut as redundant once the penalty covered the same ground.
- A document's `trigger_phrases` now feed the advisor too.
- Doc-trigger harvesting reads them into a new `skill_docs` table behind `SPECKIT_ADVISOR_DOC_TRIGGERS`.

#### Short Names Reach the Scorer <a id="c-short-names-reach-the-scorer"></a>

- The scorer discarded any word of two characters or fewer before the token lanes ever saw it.
- That made `pi` invisible to every one of them.
- The hub scored only where an authored phrase happened to spell the wording out.
- So `delegate to pi` resolved.
- `delegate this to pi` returned nothing at all.
- Short filler was already handled by the stop-word list.
- So the length floor was rejecting short content words and nothing else.
- Lowering it one character restores the lanes for names like `pi`.
- It does not let filler back in.
- It was measured against the labelled corpus at no change in accuracy.

#### The CLI Is the Only Front Door <a id="c-the-cli-is-the-only-front-door"></a>
