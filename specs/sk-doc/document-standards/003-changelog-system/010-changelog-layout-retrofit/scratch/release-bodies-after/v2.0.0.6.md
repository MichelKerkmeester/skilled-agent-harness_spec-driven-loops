# OpenCode Environment Update

This release updates the OpenCode environment with three areas of work.

- Code quality and consolidation make agent behavior more consistent across supported runtimes.
- Bug fixes improve how the environment saves, finds and uses context.
- Verification fixes rough edges and makes the environment more dependable.

The goal is to make the platform clearer, more reliable and easier to use day to day.

- That matters because the same instructions now behave more predictably in different runtimes.
- That matters because saved context is easier to find, easier to trust and less likely to get in the way.
- That matters because the environment is easier to maintain and less likely to break in everyday use.

&nbsp;

## Why This Release

This release addresses consistency, context handling and dependability.

- Agent behavior needed to be more consistent across supported runtimes.
- The environment needed to save, find and use context better.
- Rough edges needed fixing to make the environment more dependable.

## Agent Behavior and Consistency

These changes cover shared helpers, safer cleanup and runtime validation.

#### Shared Validation Helpers <a id="c-shared-validation-helpers"></a>

- `workflow.ts` now imports `validateNoLeakedPlaceholders` and `validateAnchors` from `validation-utils.ts`.
- It does this instead of maintaining inline copies.

#### Single Archive Helper <a id="c-single-archive-helper"></a>

- The hardcoded archive regex was replaced.
- `isArchiveFolder()` from `folder-detector.ts` handles it now.

#### One Error Message Helper <a id="c-one-error-message-helper"></a>

- Error messaging was extracted to `printNoSpecFolderError()`.

#### Safer Orphan Cleanup <a id="c-safer-orphan-cleanup"></a>

- `Cleanup-orphaned-vectors.ts` gained `--dry-run` and `--help` flags for safer operation.
- A `require.main` guard prevents accidental execution on import.

#### Runtime Config Validation <a id="c-runtime-config-validation"></a>

- `Config.ts` added a `validateConfig()` function for runtime configuration validation.

&nbsp;

## Context Handling

These changes remove dead code and fix markers and section numbering.

#### Dead Code Removed <a id="c-dead-code-removed"></a>

- 8 dead exports were removed from `workflow.ts`.
- They are `generateContextMemory`, `WorkflowResult`, `ContextMemoryOptions` and `GenerateContextResult`.
- They also include `processConversation`, `ProcessConversationOptions`, `generateMarkdown` and `GenerateMarkdownOptions`.

<details>
<summary><b>Smaller fixes</b></summary>

- The dead `existingDirs` variable was removed from `directory-setup.ts`.
- The dead `SpecFolderInfo` export was removed from `folder-detector.ts`.
- The dead `loadConfig` was removed from `config.ts` and the barrel.
- The vestigial `initializeDataLoaders()` lazy loading pattern was removed.
- Dead exports were removed from the `alignment-validator.ts` barrel.

</details>

#### Consistent Data Markers <a id="c-consistent-data-markers"></a>

- In `Data-loader.ts`, `_source` and `_isSimulation` markers were applied inconsistently across loading paths.
- They were standardized to consistent application.

#### Renumbered Section <a id="c-renumbered-section"></a>

- In `Workflow.ts`, `## 5. Quality and Relevance Score` collided with existing section 5.
- It was renumbered to `## 6`, making it section 6.
