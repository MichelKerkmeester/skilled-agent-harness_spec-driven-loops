# OpenCode Environment: Config-First Architecture Release

This release updates the OpenCode environment with structured config files-first architecture refactoring.

- `.md` files become routing documents.
- Each command now has `_confirm.yaml` and `_auto.yaml` modes.
- `Agent.md` is rebuilt from a 670-line inline workflow.

New architecture sections make the environment more dependable.

- `Workflow_enforcement` runs strict sequential mode with phase gates.
- `Circuit_breaker` uses a 3-failure threshold.
- `Error_recovery` handles four failure types.

Bug fixes make the written guidance easier to follow and trust.

- Step count metadata is fixed in 3 YAMLs.
- sequential_5_step becomes sequential_6_step.

&nbsp;

## Why This Release

The goal is to make the platform clearer, more reliable and easier to use day to day.

- This part of the release improves how the environment saves, finds and uses context.
- This part of the release fixes rough edges and makes the environment more dependable.
- This part of the release makes the written guidance easier to follow and easier to trust.

## Command and Config Architecture

The create commands now load structured config files first.

#### Structured Config Files-First Architecture Refactoring <a id="c-structured-config-filesfirst-architecture-refactoring"></a>

- `.md` files are refactored to routing documents.
- EXECUTION PROTOCOL banner → Phase 0 (@write verification) → Unified Setup Phase → structured config files loading → Reference context.
- Each command now has `_confirm.yaml` (interactive with checkpoints) and `_auto.yaml` (autonomous, no prompts).
- `Agent.md` was a 670-line inline workflow.
- It had an orphaned structured config files file.
- It is now a proper structured config files-first architecture.
- Both mode files were built from scratch.
- That matters because saved context is easier to find, easier to trust and less likely to get in the way.

&nbsp;

## Reliability and Error Handling

Three new sections cover enforcement, circuit breaking and error recovery.

#### New Architecture Sections <a id="c-new-architecture-sections"></a>

- `Workflow_enforcement` provides strict sequential mode with phase gates.
- `Circuit_breaker` uses a 3-failure threshold with closed/open/half-open states.
- `Error_recovery` handles `template_not_found`, `validation_failure`, `file_write_failure` and `user_rejects_approach`.
- That matters because the environment is easier to maintain and less likely to break in everyday use.

&nbsp;

## Guidance Fixes

A metadata fix makes the written guidance easier to follow.

#### Bug Fixes <a id="c-bug-fixes"></a>

- Step count metadata is fixed in 3 YAMLs.
- The YAMLs are `create_install_guide`, `Create_skill_asset` and `Create_skill_reference`.
- sequential_5_step becomes sequential_6_step.
- That matters because people can understand the system faster and use it more confidently.
