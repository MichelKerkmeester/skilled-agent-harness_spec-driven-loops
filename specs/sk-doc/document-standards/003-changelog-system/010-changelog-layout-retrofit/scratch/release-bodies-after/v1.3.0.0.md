# OpenCode Environment Update

This release updates the OpenCode environment with work on structured config files-first architecture refactoring.

- `.md` files became routing documents.
- Each command now has `_confirm.yaml` and `_auto.yaml` modes.
- `Agent.md` was fully rebuilt.

It also covers new architecture sections.

- `Workflow_enforcement` adds strict sequential mode with phase gates.
- `Circuit_breaker` adds a 3-failure threshold with closed/open/half-open states.
- `Error_recovery` adds failure handlers.

It also includes bug fixes.

- Step count metadata was fixed in 3 YAMLs.
- sequential_5_step became sequential_6_step.

&nbsp;

## Why This Release

The goal is to make the platform clearer, more reliable and easier to use day to day.

- This part of the release improves how the environment saves, finds and uses context.
- This part fixes rough edges and makes the environment more dependable.
- This part makes the written guidance easier to follow and easier to trust.

## Context Files

This area covers how the environment saves, finds and uses context.

#### Context Files Become Routing Documents <a id="c-context-files-become-routing-documents"></a>

- The `.md` files were refactored into routing documents.
- EXECUTION PROTOCOL banner → Phase 0 (@write verification) → Unified Setup Phase → structured config files loading → Reference context.
- Each command now has `_confirm.yaml` (interactive with checkpoints) and `_auto.yaml` (autonomous, no prompts).
- `Agent.md` was a 670-line inline workflow with an orphaned structured config files file.
- It is now a proper structured config files-first architecture with both mode files built from scratch.
- That matters because saved context is easier to find, easier to trust and less likely to get in the way.

&nbsp;

## Workflow Controls

This area covers the new sections that make the environment more dependable.

#### Guards Added to the Workflow <a id="c-guards-added-to-the-workflow"></a>

- `Workflow_enforcement`: strict sequential mode with phase gates.
- `Circuit_breaker`: 3-failure threshold with closed/open/half-open states.
- `Error_recovery`: handlers for `template_not_found`, `validation_failure`, `file_write_failure` and `user_rejects_approach`.
- That matters because the environment is easier to maintain and less likely to break in everyday use.

&nbsp;

## Command Metadata

This area covers the written guidance for create commands.

#### Step Counts Corrected in Three YAMLs <a id="c-step-counts-corrected-in-three-yamls"></a>

- Step count metadata was fixed in 3 YAMLs.
- The YAMLs are `create_install_guide`, `Create_skill_asset` and `Create_skill_reference`.
- The count moved from sequential_5_step to sequential_6_step.
- That matters because people can understand the system faster and use it more confidently.
