This release combines two packets.

- One packet is ESM Module Compliance (023, 13 phases).
- It sits at `.opencode/specs/system-spec-kit/023-hybrid-rag-fusion-refinement/` (Level 2).
- The other is Compact Code Graph (024, 28 phases).
- Together, the 41 phases move the shared package and MCP server to native ESM.

The release adds structural and recovery capabilities.

- It adds a structural code graph.
- It extends session recovery through compaction and hookless runtimes.

Search and data work closes several gaps.

- Search recovers from a zero-result outage.
- Structured memory saves now use the information supplied.
- Data cleanup and indexing changes address drift in spec content and search state.

&nbsp;

The goal is to make the workflow safer and easier to trust.

## Runtime & ESM

This release aligns code loading with each package's module system. The shared package and MCP server move to native ESM, while scripts keep CommonJS.

#### Shared code matches its module contract <a id="c-shared-code-matches-its-module-contract"></a>

- `@spec-kit/shared` used modern import syntax in source.
- Its package behavior did not match what Node runs.
- Package metadata, compiler settings and 48 relative import paths were rewritten.
- So consumers get the native ESM behavior the source expects.

#### MCP startup follows its module system <a id="c-mcp-startup-follows-its-module-system"></a>

- The MCP server looked modern in source.
- It relied on CommonJS assumptions such as the require helper, `__dirname`, `__filename` and loose JSON loading.
- The migration rewrote 839 imports across 181 files.
- It replaced CommonJS-only globals.
- It converted the remaining require-helper holdouts.
- It repaired ESM startup details, so runtime behavior matches the package's module system.
- The MCP server package also declares `engines.node >= 20.11.0`.

#### Scripts preserve caller expectations <a id="c-scripts-preserve-caller-expectations"></a>

- Switching `@spec-kit/scripts` to ESM for consistency would have broken callers.
- Those callers rely on its CommonJS behavior.
- Scripts use Node 25's native `require(esm)` where needed.
- Loading blockers were removed at the package boundary.
- The memory-save path was hardened at the same time.

## Session Recovery & Context

This release changes how sessions recover context after compaction, startup and other sources. Recovery branches by source, and hookless runtimes have a path.

#### Compaction restores working context <a id="c-compaction-restores-working-context"></a>

- Claude compaction erased short-term context.
- That included the active spec folder, recent code focus and the rules guiding the work.
- `PreCompact` now caches a compact recovery payload.
- `SessionStart` injects it only for `source=compact`.
- Attention signals, spec-folder detection and token-budget controls keep the recovered brief small enough to use.

#### Each session source gets the right brief <a id="c-each-session-source-gets-the-right-brief"></a>

- Startup, resume, clear and compact previously received too much context or the wrong context.
- That is because they were treated too similarly.
- Priming now restores cached context for compacts.
- It points resumes to the compact-brief flow.
- It surfaces tool and freshness guidance at startup.
- It gives clears minimal recovery instructions.

#### End-of-session state can be saved <a id="c-end-of-session-state-can-be-saved"></a>

- Session usage had little durable tracking.
- End-of-session state was not reliably captured automatically.
- Stop-hook tracking parses transcript usage.
- It records hook-state metrics and estimates token spend.
- Configured thresholds can trigger a best-effort `generate-context.js` save.

#### Hookless runtimes can recover <a id="c-hookless-runtimes-can-recover"></a>

- Runtimes outside the Claude hook family depended on manual priming.
- MCP first-call priming plus `session_resume`, `session_health` and `session_bootstrap` provide one main recovery path.
- That path includes structural bootstrap expected behaviors and startup briefs for OpenCode-style flows.

#### Hook recovery handles stale state <a id="c-hook-recovery-handles-stale-state"></a>

- Cache races, weak temporary-file handling, session-state collisions and insufficient provenance markers made the hook path fragile.
- Several changes tightened the hook-state lifecycle.
- They are TTL checks, SHA-256-based state names, restrictive file permissions, provenance fencing, stale-on-read checks and response-envelope cleanup.

#### Context budgets share unused capacity <a id="c-context-budgets-share-unused-capacity"></a>

- Fixed shares wasted capacity when one source was quiet.
- A pure shared pool could starve important context.
- Floors-plus-overflow budgeting gives constitutional context, graph context, semantic hints and triggered memories a baseline allocation.
- It shares spare capacity.

#### Startup highlights show relevant code <a id="c-startup-highlights-show-relevant-code"></a>

- Early structural highlights repeated symbols.
- They included vendored code and used the wrong ranking rule.
- Follow-on phases added shared startup brief builders.
- They added an explicit structural-bootstrap expectation.
- A final cleanup deduplicates symbols, excludes non-project paths and ranks by incoming callers instead of outgoing callers.

## Structural Code Graph

This release adds a structural view of code alongside semantic search. The graph answers questions that meaning-based search cannot.

#### Structural questions get direct answers <a id="c-structural-questions-get-direct-answers"></a>

- Semantic search could find code by meaning.
- It could not answer questions about callers, imports or dependency chains.
- A structural indexer extracts symbols, relationships and call edges into a SQLite-backed graph.
- Scan, query, status and context-expansion tools are exposed through MCP.

#### Parsing handles more code shapes <a id="c-parsing-handles-more-code-shapes"></a>

- Regex-only parsing misclassified abstract methods, class expressions, multi-import captures and nested class names.
- Parser adapters moved extraction toward tree-sitter.
- They retained regex as a fallback.
- Follow-on fixes improved classification accuracy.

#### Structural answers use fresh state <a id="c-structural-answers-use-fresh-state"></a>

- A stale graph could look authoritative while pointing at the wrong branch.
- Readiness checks, HEAD-change detection and tracked-file modification times now support reindexing before answers drift.
- Status is reported as fresh, stale or empty.

#### Semantic hits expand into structure <a id="c-semantic-hits-expand-into-structure"></a>

- Semantic search, structural search and memory search had little guidance on when to use each one.
- Seed resolution and context orchestration now let CocoIndex hits expand into nearby structural relationships.
- Intent metadata guides semantic, structural and session-history questions to their respective search surfaces.

## Search & Retrieval

This release restores search results and improves how matches are ranked and shown. Exact phrases now match together and scope controls stay inside boundaries.

#### Queries survive broken filters <a id="c-queries-survive-broken-filters"></a>

- Two filters silently discarded every result from a healthy database of 999 memories.
- Unscoped queries were treated as having no owned access.
- A lifecycle-state check used a column that did not exist.
- Scope enforcement now requires deliberate opt-in.
- The lifecycle-state filter was removed.
- State storage remains unimplemented.
- Queries then returned 4-5 results.
- Both vector and FTS5 channels contributed.

#### Top matches stand apart <a id="c-top-matches-stand-apart"></a>

- The reciprocal rank fusion smoothing constant `k=60` was designed for corpora of 10,000 or more documents.
- With 999 memories it left only 0.002 between rank 1 and rank 10.
- Changing `k` to 40 doubled that separation to 0.004.
- That makes higher-ranked results easier to distinguish.

#### Exact phrases match together <a id="c-exact-phrases-match-together"></a>

- Searching for `spec kit` previously matched documents containing `spec` or `kit` individually.
- A double-quoting bug could wrap already-quoted phrases again.
- That created invalid FTS5 syntax, which silently dropped results.
- Multi-word queries now add FTS5 phrase variants beside individual tokens.
- The FTS5 path detects already-quoted terms, so they do not get a second pair of quotes.
- Exact-phrase matches are now boosted properly.

#### Focused searches keep candidates <a id="c-focused-searches-keep-candidates"></a>

- Folder discovery could become a hard search filter.
- Deep mode could mistake an ephemeral `sessionId` for governance scope.
- Folder discovery no longer turns into a hard scope filter.
- An empty discovered-folder pass retries without that scope.
- Stage-1 candidate generation no longer treats a plain `sessionId` as governed input.

#### Long matches use less space <a id="c-long-matches-use-less-space"></a>

- The 1,500-token search budget often cut results down to one of seven or more matches.
- Unusually long matches could cause whole results to be removed too early.
- The budget is now 2,500 tokens.
- Oversized content is shortened before results are dropped.
- Additional matches keep compact metadata after full-content slots run out.

#### Deprecated memories stay excluded <a id="c-deprecated-memories-stay-excluded"></a>

- Vector search excluded deprecated-tier memories.
- FTS5 did not.
- So deprecated content could return through the lexical path.
- Both channels now apply the same exclusion.
- Results stay consistent across search paths.

#### Related memories join results <a id="c-related-memories-join-results"></a>

- Co-activation expected `related_memories` in object form.
- The database stored scalar arrays.
- So the parser silently failed and co-activation never contributed.
- Scalar entries also received similarity `0.5` on a 0-100 scale.
- That made boosts two orders of magnitude weaker than intended.
- The format and scale were corrected.
- Co-activated memories now enter the fusion candidate pool properly.

#### Reranking preserves diversity <a id="c-reranking-preserves-diversity"></a>

- Concatenating a title and body before scoring let a strong title match cancel against a weak body.
- They are now scored separately.
- The MMR diversity pass runs even when the full reranker is unavailable.
- A new `rerankProvider` metadata field records which reranker path was taken.

#### Search traces show active channels <a id="c-search-traces-show-active-channels"></a>

- It was hard to tell which channels contributed.
- It was also hard to tell whether graph signals were active.
- Stage 1 now reports `activeChannels`.
- Stage 2 emits zero-contribution graph diagnostics.
- Per-stage timing is persisted.
- The embedding cache tracks hit and miss statistics.

#### Vector search stays on populated data <a id="c-vector-search-stays-on-populated-data"></a>

- After lazy Voyage-4 initialization, vector search could switch databases.
- It could move from the populated `context-index.sqlite` database to an empty provider-specific one.
- Database selection now stays with the active populated database.
- Startup reports its path.
- It refuses to rebind consumers to an empty database.

## Saving Memories

This release makes structured saves keep the details supplied in the request. Saves without a transcript and shared paths also get clearer handling.

#### Structured saves keep their details <a id="c-structured-saves-keep-their-details"></a>

- JSON and STDIN payloads bypassed normalization.
- So the extractor chain received empty input despite the information in the request.
- Structured payloads now pass through the existing normalization path before extraction.
- JSON-mode structured saves moved from unusable 0/100 output to a repeatable 55-75/100 quality range.

#### Transcript-free saves tell a story <a id="c-transcript-free-saves-tell-a-story"></a>

- Structured saves without a transcript lacked narrative material.
- They collapsed into thin placeholders with generic titles and summaries.
- The extractor stack now synthesizes a minimal structured conversation when prompts are absent.
- It derives title and summary fields from session data.

#### Decision lists scan cleanly <a id="c-decision-lists-scan-cleanly"></a>

- Decision strings could repeat themselves.
- Noisy file lists could bury important references.
- The changes reduce repeated decisions.
- They tighten key-file shaping, so saved memories are easier to scan.

#### Sibling references score fairly <a id="c-sibling-references-score-fairly"></a>

- The quality validator treated valid references as foreign contamination.
- Those references pointed to nearby child phases from the same workstream.
- It now relaxes that check for structured same-parent sibling references.
- It does not open a broad cross-spec bypass.

#### Shared saves respect boundaries <a id="c-shared-saves-respect-boundaries"></a>

- Shared-memory admin operations lacked transport warnings.
- Path handling needed stronger workspace boundaries.
- Admin paths now carry trusted-transport warnings.
- The V-rule bridge stops with an error.
- Shared paths validate workspace boundaries.

## Cross-Runtime Parity

This release gives runtimes outside the Claude hook family the same recovery and routing. Hooks and tools share logic rather than separate recovery models.

#### Hooks and tools share recovery <a id="c-hooks-and-tools-share-recovery"></a>

- A hook-only design would have made recovery strong in Claude and second-class elsewhere.
- Hooks remain where they work well.
- Tool-driven recovery is available to other runtimes.
- Both paths share logic rather than forking the recovery model.

#### Runtime recovery follows one contract <a id="c-runtime-recovery-follows-one-contract"></a>

- Runtime instructions, context-prime agents and bootstrap surfaces had drifted apart.
- They left different wording and guarantees for the same recovery concept.
- Non-hook recovery now defines ready, stale and missing structural states.
- It uses `session_bootstrap` as the main path.
- It mirrors routing and recovery tables across runtime-facing docs and agent definitions.

#### Tool routing follows the question <a id="c-tool-routing-follows-the-question"></a>

- Passive instructions to use CocoIndex let the AI fall back to `Grep` or `Glob`.
- That happened when a better tool was available.
- Routing nudges now reach server instructions, PrimePackage state, tool hints, runtime docs and context-prime agents.
- They direct semantic questions to CocoIndex.
- They direct structural questions to the code graph.
- They direct session-history questions to memory surfaces.

## Security

This release keeps duplicate checks inside the caller's governed boundary. Cross-boundary details are redacted.

#### Duplicate checks honor scope <a id="c-duplicate-checks-honor-scope"></a>

- Duplicate detection did not fully respect governed scope.
- So one scope could learn that matching content existed somewhere it could not inspect.
- Duplicate checks now stay inside the caller's governed boundary.
- They redact cross-boundary details.
- Governed scope and metadata redaction also apply to duplicate-preflight queries.

## Data Quality & Indexing

This release cleans spec and memory data and stabilizes indexing after a repository move. Canonical context types replace legacy aliases.

#### Spec and memory data was cleaned <a id="c-spec-and-memory-data-was-cleaned"></a>

- Spec documents and memory files had frontmatter and anchor drift.
- Some memory files blocked indexing.
- The audit covered 186 spec folders.
- It corrected 2,081 frontmatter issues.
- It added 4,291 anchors and removed 46 hard-block memory files.
- Orphaned vectors were cleaned.
- The memory database was rebuilt from clean inputs.
- Final status was 175/175 in-scope folders at zero validation errors.
- That is down from 97 active and 65 archived.

#### Bulk reindex accepts valid files <a id="c-bulk-reindex-accepts-valid-files"></a>

- The reindex validator rejected 1,106 legitimate files.
- That is because batch inputs lacked file-path context.
- Topic checks also rejected memory notes for describing outcomes in plain language.
- File-path context was added.
- Topic checks no longer apply to memory notes or spec-defining documents.
- Forced rebuilds treat quality issues as warnings.
- Blocked files fell from 1,106 to zero.

#### Context types use canonical names <a id="c-context-types-use-canonical-names"></a>

- Aliases such as `decision` and `discovery` remained where the model expected `planning` and `general`.
- That caused validation noise and brittle migrations.
- Canonical context types now apply across parser logic, migrations, runtime consumers and a database CHECK constraint.
- The schema moves from version 24 to 25.
- It migrates old values before that constraint is enforced.
- `contextType` values use `research`, `implementation`, `planning` or `general`.
- The cleanup migrated 2,009 legacy values and removed 13,211 duplicate rows.

#### Indexing and adaptive fusion stabilized after the repository move <a id="c-indexing-and-adaptive-fusion-stabilized-after-the-repository-move"></a>

- A repository move left CocoIndex on stale state.
- It required a BM25 rebuild.
- It made adaptive-fusion defaults unevenly visible across clients.
- CocoIndex was rebuilt against the active repository with 51,820 files and 663,336 chunks.
- BM25 was re-indexed against 1,228 memories.
- The code-graph database gained first-use lazy initialization.
- Fused output preserves lexical provenance.

## Upgrade Notes

No migration required. Schema changes are backward-compatible and migrate automatically on startup.

#### Before You Start <a id="c-before-you-start"></a>

1. No migration required. Schema changes are backward-compatible and migrate automatically on startup.
2. Expect source-aware recovery. Session recovery branches by `compact`, `startup`, `resume` and `clear`. Each source gets tailored context.
3. Expect tool-routing guidance. Semantic questions are directed toward CocoIndex. Structural questions go toward the code graph. Session-history questions go toward memory surfaces.

<details>
<summary><b>Runtime &amp; ESM</b></summary>

- Keep scripts on their CommonJS contract. `@spec-kit/shared` and `@spec-kit/mcp-server` use native ESM. `@spec-kit/scripts` remains CommonJS.

</details>

<details>
