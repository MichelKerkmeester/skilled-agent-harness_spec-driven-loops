
This release adds infrastructure domain detection. It is a way for the workflow to tell infrastructure work apart from project work. That is what sends each record to the folder it belongs in. It makes the project setup more consistent and easier to work with.

&nbsp;

## Why This Release

Memory files were being saved to incorrect spec folders. That happened when the work was on shared infrastructure. This release fixes that root cause at the source. It does so by recognizing infrastructure work for what it is.

&nbsp;

## What's New at a Glance

- The workflow separates infrastructure work from project work.
  - The new `Detect_work_domain()` function reads the file paths in your observations.
  - The function measures the share of `.opencode/` files.
  - The function identifies the subpath.
  - The function returns the domain with a confidence score and matching patterns.
- Infrastructure folders score higher.
  - The new `Calculate_alignment_score_with_domain()` wraps the base scoring with infrastructure awareness.
  - The function applies a +40 bonus to folders that match infrastructure patterns.
  - The patterns are mapped per subpath.
- Folder alignment now understands infrastructure.
  - `Validate_content_alignment()` and `validate_folder_alignment()` use domain-aware scoring.
  - When they detect an infrastructure mismatch, they warn you.
  - The functions also list better-matching alternatives with boosted scores.
- Content and folder are matched up front.
  - Step 3: Validate Content vs Folder Alignment now validates `key_files` against `spec_folder`.
  - The step does this before recovery runs.
- The step numbering lost its half-steps.
  - What was 2.5 is now 3.
  - The steps after it are renumbered.
- KEY FILES now appear in the recovery summary.
  - They let you verify that the spec folder makes sense for the work.
