This major release implements SpecKit Reimagined.

- It spans 33 features and 107 tasks across five workstreams.
- It adds 5 new memory commands.

The workstreams cover five areas.

- Session management (W-S), search and retrieval (W-R) and decay and scoring (W-D).
- The causal memory graph (W-G) and infrastructure (W-I).
- Alongside them come MCP tool changes.

Supporting assets change with the release.

- There are four database schema versions.
- Templates, commands and YAML workflow assets also get updates.

&nbsp;

## Why This Release

This release focuses on memory, search and recovery.

- It adds session deduplication and a causal memory graph.
- It adds intent-aware retrieval and BM25 (exact word matching) hybrid search.
- It also adds comprehensive crash recovery.

## Sessions and Crash Recovery

Session management gains deduplication and crash recovery.

#### Sessions That Remember and Recover <a id="c-sessions-that-remember-and-recover"></a>

- Session deduplication relies on hash-based tracking.
- Crash recovery rests on a session_state table.
- The SessionStateManager API adds resetInterruptedSessions() and recoverState().
- recoverState() comes with a `_recovered` flag.

&nbsp;

## Search and Retrieval

Search gains hybrid ranking, intent detection and fuzzy matching.

#### Better Ranking for Hybrid Results <a id="c-better-ranking-for-hybrid-results"></a>

- RRF fusion gains a K=60 parameter.
- It also gains a 10% convergence bonus for multi-source results.
- Cross-encoder reranking works with Voyage, Cohere or local providers.
- It applies a length penalty at a 100 character threshold.

#### Retrieval That Reads Intent <a id="c-retrieval-that-reads-intent"></a>

- The five intent types are `add_feature`, `fix_bug`, `refactor`, `security_audit` and `understand`.
- An intent classifier handles intent detection for them.

#### Fuzzy Matching With Acronyms <a id="c-fuzzy-matching-with-acronyms"></a>

- Fuzzy matching accepts a Levenshtein distance of 2 or less.
- It adds an `ACRONYM_MAP` with 30+ entries.
- The fuzzy match module for Levenshtein and acronym expansion was never implemented.

&nbsp;

## Decay and Scoring

Scoring gains factors, and consolidation and archival are added.

#### Decay That Weighs More Factors <a id="c-decay-that-weighs-more-factors"></a>

- Multi-factor decay adds pattern alignment and citation recency as factors.
- Usage boost scoring comes with enhanced 5-factor composite scoring.

#### Consolidation and Automatic Archival <a id="c-consolidation-and-automatic-archival"></a>

- The consolidation pipeline covers duplicate detection and semantic merge in 5 phases.
- Its consolidation module was never implemented.
- An archival manager adds automatic archival as a background job.

&nbsp;

## Causal Memory Graph

Memories link by cause, and the system learns from corrections.

#### Memories Linked by Cause <a id="c-memories-linked-by-cause"></a>

- The relationship types are `caused`, `enabled`, `supersedes`, `contradicts`, `derived_from` and `supports`.
- Decision lineage traces decision run history.
- It uses depth-limited traversal of at most 10 hops, with cycle detection.

#### Learning From Corrections <a id="c-learning-from-corrections"></a>

- Penalties are set at 0.5x and boosts at 1.2x.
- The memory corrections tracking module was never implemented.

&nbsp;

## Infrastructure

Infrastructure covers keys, gates, fallbacks, caching and schema versions.

#### Safer Keys and Pre-Flight Gates <a id="c-safer-keys-and-pre-flight-gates"></a>

- API key validation handles keys securely and gives actionable guidance.
- Pre-flight quality gates run ANCHOR validation, duplicate detection and token budget checks.

#### Fallbacks, Retries and Safe Transactions <a id="c-fallbacks-retries-and-safe-transactions"></a>

- The fallback chain comes with logging.
- The provider chain module for this embedding fallback was never implemented.
- Lazy model loading defers embedding initialization.
- Protocol abstractions give provider-agnostic embedding interfaces.
- Retry logic uses exponential backoff of 1s, 2s and 4s with jitter.
- Transaction atomicity follows SAVEPOINT/ROLLBACK patterns.

#### Organized and Cached Tool Output <a id="c-organized-and-cached-tool-output"></a>

- Tools sit in a 7-layer MCP architecture, L1 to L7.
- Memory context is the unified entry at L1 (orchestration).
- Tool output caching uses a 60s TTL with LRU eviction.
- Incremental indexing makes diff updates based on content hash and mtime.

#### Schema Versions V8 to V11 <a id="c-schema-versions-v8-to-v11"></a>

- V8 adds the causal_edges table with 6 relation types, strength and evidence.
- V9 adds the memory_corrections table for stability tracking and pattern extraction.
- V10 adds the session_state table for crash recovery, with a dirty flag.
- V11 adds the is_archived and archived_at columns.

## Commands, Tools and Templates

New commands, MCP tools and templates carry the release features.

#### Five New Memory Commands <a id="c-five-new-memory-commands"></a>

- `/memory:continue` recovers a session from a crash or compaction.
- `/memory:context` is a unified entry with intent awareness.
- `/memory:why` traces decision run history through the causal graph.
- `/memory:correct` learns from mistakes with stability penalties.
- `/memory:learn` captures explicit learning of patterns, pitfalls and insights.

#### MCP Tools for Causal Queries <a id="c-mcp-tools-for-causal-queries"></a>

- The memory_drift_why tool traces the causal chain for "why" queries.
- The memory_causal_link tool creates causal relationships between memories.
- memory_causal_stats gives graph statistics and coverage metrics.
- The memory_causal_unlink tool removes causal relationships. It was no longer needed in its old form, so the release removes or retires it.
- The memory_drift_context tool (unified context with intent awareness) and the memory_drift_learn tool (capture explicit learning) were never implemented. They were removed from the roadmap.

#### Templates Carry the New Features <a id="c-templates-carry-the-new-features"></a>

- Context template v2.2 adds a CONTINUE_SESSION section, `session_dedup` metadata and `causal_links`.
- The Save template gains Phase 0 pre-flight validation.
- It also gains section 16 on session deduplication and deferred indexing.
- The Search template covers hybrid search architecture, intent-aware retrieval and compression tiers.

#### Commands and Workflows Updated <a id="c-commands-and-workflows-updated"></a>

- The memory commands gain spec 082 cross-references.
- The spec_kit commands pick up the Five Checks Framework.
- The YAML workflow assets gain context loading integration.
- The folder detector now gives CLI arguments priority over alignment validation.
- So it never overrides explicit user intent.
