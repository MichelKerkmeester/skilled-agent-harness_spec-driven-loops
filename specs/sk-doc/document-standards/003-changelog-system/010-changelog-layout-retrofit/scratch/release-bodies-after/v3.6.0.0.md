v3.6.0.0 makes memory and search more trustworthy in everyday use.

- Both are more resilient when their supporting services fail.
- Search cites genuine matches again with honest confidence.
- It keeps answering when its semantic index is damaged.
- It protects memory writes from secrets and unwanted overwrites.

Five deep-loop skills now share one hub.

- Three terminal-driven design skills bring design judgment to the terminal.
- They also bring Open Design and Figma work there.
- Both changes are real.
- Neither asks anything new of you.

Kimi K2.7 joins as a small-model option.

- Shared setup for the MCP skills comes alongside it.
- Nothing changes how you call the system.
- `memory_search`, `memory_save`, the `/deep:*` commands and agent names behave exactly as before.

> [!IMPORTANT]
> 1 change can break an existing setup. Read this before you update.
>

## Why This Release

Memory and search need to tell the truth about matches. The background services behind them need to recover under stress.

- They must do so without duplicating themselves.
- They must do so without corrupting their data.

## Search

Search picked up fixes across matching, result scope and damaged-index recovery. They keep results findable. They make the score and scope tell the truth.

#### Confidence Matches Reality <a id="c-confidence-matches-reality"></a>

- A genuine 0.89 match now reads as a good match.
- It cites its sources and reports real confidence.
- A resolver now reads the right score for confidence.
- Ranking order does not change.

<details>
<summary><b>Why confidence was off</b></summary>

- The confidence step had compared fusion scores against tuned thresholds.
- Those thresholds were tuned for cosine similarity at 0.7 and 0.4.
- Fusion scores cluster near 0.03, because RRF compresses them.
- RRF is a method that blends two ranked result lists.

</details>

#### Keyword Search Uses Less Memory <a id="c-keyword-search-uses-less-memory"></a>

- When the semantic path is unavailable, keyword search packs its data tightly.
- It weights title and trigger matches above body text.
- So the right entry ranks first.
- Ranking is unchanged.

<details>
<summary><b>What it costs</b></summary>

- A realistic warmup once spiked to 687MB.
- It now holds at 137MB, well under budget.

</details>

#### Scoped Queries Return Everything <a id="c-scoped-queries-return-everything"></a>

- A narrow scoped query now returns the full matching set.
- It no longer comes back short.
- The keyword engine gathers all candidates first.
- Then it applies filters.
- Only then does it trim results to the requested limit.

#### Scope Cannot Leak <a id="c-scope-cannot-leak"></a>

- A scoped search no longer pulls in results from outside its scope.
- So injected rows now have that filter applied again.

<details>
<summary><b>Why scope leaked</b></summary>

- The broaden-and-rescue path had re-queried the index without the spec-folder filter.

</details>

#### Punctuation Stays in Queries <a id="c-punctuation-stays-in-queries"></a>

- A `/memory:search` query with shell-special characters now resolves as typed.
- Quoting the query argument makes punctuation behave predictably.

#### Cold Results Stay Reachable <a id="c-cold-results-stay-reachable"></a>

- Cold and deprecated entries flow back into keyword and trigger search.
- That search uses freshness-aware ranking.
- FSRS guides that ranking.
- FSRS is a spaced-repetition scheduler that scores how relevant something still is.
- The semantic lane fills in missing projections.
- So matching cold entries can appear.

#### One Score Across Surfaces <a id="c-one-score-across-surfaces"></a>

- Rendered results now show one score name on a plain 0-to-1 scale.
- It is rounded to two decimals.
- Older confidence values and percentages are gone from the output.
- So callers see the same number for the same result.

#### Ranking Can Be Explained <a id="c-ranking-can-be-explained"></a>

- An opt-in trace now returns a breakdown of the intermediate values behind a result's rank.
- An inline warning also flags when one memory contradicts or supersedes another.

## Memory Safety

These protections keep sensitive content out of search. They preserve human edits. They stop cleanup or repair from silently damaging data.

#### Secrets Stop Before Indexing <a id="c-secrets-stop-before-indexing"></a>

- A scrubber runs before hashing, embedding and keyword indexing.
- It replaces API keys, tokens, bearer values and private-key blocks with typed redaction markers.
- If scrubbing cannot finish, the write is refused.
- The value is not stored in the clear.

#### Human Edits Resist Overwrites <a id="c-human-edits-resist-overwrites"></a>

- A new provenance column records where each field came from.
- It records whether a human or an automated writer wrote it.
- Automated writes skip human-authored content.
- A companion tagger marks automated writers.
- So the protection applies across them.

#### Retention Respects Protected Entries <a id="c-retention-respects-protected-entries"></a>

- Cleanup checks an entry's tier and pinned state before deleting it.
- If a constitutional or critical entry reaches expiry, cleanup logs a refusal.
- It does not remove the entry.

#### Long Sessions Refresh Continuity <a id="c-long-sessions-refresh-continuity"></a>

- An opt-in snapshot refreshes handover and continuity notes.
- It runs just before a long session is compacted.
- `SPECKIT_AUTHORED_CONTINUITY_SNAPSHOT` controls it.
- The flag is off by default.
- Startup reports what it restored.

#### Damaged Vectors Rebuild Safely <a id="c-damaged-vectors-rebuild-safely"></a>

- The system detects, quarantines and rebuilds a damaged vector shard.
- A vector shard is a slice of the semantic search index.
- The repair survives a restart.
- A persisted marker and completeness check decide whether to resume repair.
- They also decide whether to clear a stale flag.
- So a corrupted slice is not silently replaced with an empty one.

## Resilient Daemons

A daemon is a background service that stays running. It answers requests over a socket. The 026 release gave these services a second way in.

This release covers three failures. A connection can drop. A daemon can die. A burst of traffic can hit a limit. In each case the system recovers. It does not duplicate itself or corrupt its data.

#### Advisor Reconnects Safely <a id="c-advisor-reconnects-safely"></a>

- The skill-advisor launcher now recovers the way the memory and code services already do.
- A new session connects to the live daemon.
- It does not spawn a second one.
- A hung daemon is reaped and replaced under a lock.

<details>
<summary><b>Why the launcher could duplicate</b></summary>

- Previously, the launcher could reconnect on a dead socket.
- It then acted as if it had not.
- That let another session start a second writer.

</details>

#### One Writer Owns the Database <a id="c-one-writer-owns-the-database"></a>

- A single-writer lock allows only one process to write to the same database at a time.
- A second writer loses the lock and exits cleanly.
- That protects the shared index.

#### Daemons Gain Scriptable Front Doors <a id="c-daemons-gain-scriptable-front-doors"></a>

- All three daemons expose their full tool sets as scriptable command-line clients.
- They do so over the existing socket.
- These clients are additive to the normal connection.
- That connection stays primary.

<details>
<summary><b>What the clients allow</b></summary>

- Spec-memory has 37 tools, code-index has 8 and skill-advisor has 9.
- At prompt time they are read-only.
- Maintenance and mutation are blocked.
- Advisor changes require an explicit trusted flag.

</details>

#### Busy Connections Have More Room <a id="c-busy-connections-have-more-room"></a>

- The simultaneous-connection limit rose from eight to 64.
- Bursts of parallel work now have more room before reaching the ceiling.

#### Helper Processes Clean Up <a id="c-helper-processes-clean-up"></a>

- Helper processes now exit when their input closes.
- They also exit when their connection drops.
- They also exit at a short watchdog timeout.
- They no longer pile up after their parent is gone.
- Sixteen stranded processes were cleared in the work that landed the fix.

#### Launcher Defaults Align <a id="c-launcher-defaults-align"></a>

- Daemon re-election is now on by default in the launcher itself.
- It no longer waits for a config to enable it.
- Four runtime configs were brought into line.
- Two of them carried a JSON error that left them unparseable, and that is fixed.

#### Advisor State Stays Outside Specs <a id="c-advisor-state-stays-outside-specs"></a>

- The advisor keeps its working files at the repository root, out of spec folders.
- Run inside a packet, its workspace resolver could fall back to that packet.
- That could leave a stray `.state/advisor` directory there.
- The resolver now refuses to write inside a `specs/` subtree.
- Directories that had already leaked were cleaned up.

<details>
<summary><b>Smaller fixes</b></summary>

- The memory and daemon work also fixes a stale-cache bug on delete.
- The save lock reaps only a provably dead owner.
- The history rebuild is wrapped in a transaction.
- A write carries human authorship onto its successor.
- The startup lock reclaims on owner death instead of waiting out a timeout.

</details>

## Skills and Design

The deep loops and design tools gain shared surfaces. They keep their distinct jobs and existing user-facing commands.

#### Deep Loops Share One Hub <a id="c-deep-loops-share-one-hub"></a>

- Their five public identities now live in one hub.
- Those identities are context, research, review, ai-council and improvement.
- The hub sits over a shared, frozen backend.
- It holds no per-mode logic.
- It reads the requested mode and routes to it.
- Each mode keeps its own behavior.
- Every `/deep:*` command and agent name is unchanged.
- The only thing you might notice is that diagnostics now check both loop databases instead of missing one.

<details>
<summary><b>Why the hub was built</b></summary>

- The deep loops had grown into five separate skills.
- They shared a backend and kept drifting apart.
- Advisor routing collapsed five skill identities into one plus a mode alias.
- The old five-skill surface is gone.

</details>

#### Parent Skills Have a Pattern <a id="c-parent-skills-have-a-pattern"></a>

- The hub-over-modes structure is now a documented convention.
- `/create:sk-skill-parent` scaffolds parent skills with mode packets, a README and agent mirrors.
- The doc skill gained matching templates.
- A routing-drift check keeps the registry aligned with the code.

#### Design Judgment Guides the Work <a id="c-design-judgment-guides-the-work"></a>

- `sk-design-interface` is a standalone, Apache-2.0-only skill.
- It is based on Anthropic frontend-design principles.
- It grounds work in the live subject.
- It names the real-world median and deliberately departs from it.
- It critiques before building.
- Design references are read live rather than copied into the tree.
- The two transports are required to defer to this judgment skill.

#### Open Design Builds Through Conversation <a id="c-open-design-builds-through-conversation"></a>

> [!WARNING]
> The `mcp-magicpath` hosted-canvas skill was removed. Move any design work using it to `mcp-open-design`.

- `mcp-open-design` drives the installed Open Design desktop app from the terminal.
- It uses its command-line tool and a small server.
- A run reaches a question.
- Your answer triggers the build.
- A final step writes the file.
- The design-judgment skill is a hard precondition.
- `mcp-open-design` refuses to do interface work without it.

#### Figma Work Uses Safer Defaults <a id="c-figma-work-uses-safer-defaults"></a>

- `mcp-figma` drives Figma Desktop from the terminal.
- It covers install, connect, read, author and export.
- Read-only commands run freely.
- Changes ask first.
- Destructive commands are off by default.
- An optional path supplies design context for code generation.

<details>
<summary><b>Connection safety</b></summary>

- The connection ships safe by default through a plugin.
- It does not patch the app.
- The more invasive option is gated and paired with a rollback.

</details>

## Tooling and Operating Rules

#### Shared MCP Setup and Kimi <a id="c-shared-mcp-setup-and-kimi"></a>

- The five MCP skills now share one install guide.
- They also share a verify-only install script and a read-only doctor check.
- Kimi K2.7 joins as a small-model option with a full prompt-craft profile.
- Prompt-craft evaluation settled on its best prompt framework.
- The Figma skill reached its first stable release at 1.0.0.0.
- Cross-references tie both design transports to the judgment skill.

#### Reviews Name Their Tradeoffs <a id="c-reviews-name-their-tradeoffs"></a>

- `sk-code` review rules now require a replacement when a review recommends removing something.
- They use a marker for deliberate simplification.
- They forbid quietly cutting scope.
- `SK_CODE_REVIEW_DEPTH=lite|full|ultra` lets operators name the existing depth tiers.
- The review contract does not change.

#### Model Provenance Is Checked <a id="c-model-provenance-is-checked"></a>

- With `SPECKIT_PROVENANCE_CHECK=1`, the executor audit fails loudly.
- It fails when the model that ran differs from the one requested.
- A silent model swap can no longer produce a dishonest record.
- That holds when this check is enabled.

#### Operating Discipline Is Written Down <a id="c-operating-discipline-is-written-down"></a>

- Framework docs and constitutional rules now say four things.
- Confirm claims before making them.
- Capture a baseline before claiming no regressions.
- Treat findings as hypotheses until the cited code is opened.
- Name a rollback before irreversible work.
- Both are advisory.
- They never block a valid exchange.

<details>
<summary><b>Where it came from</b></summary>

- This discipline grew out of a Fable 5 review practice.
- A typed agent contract backs it.
- That contract travels with dispatched work.

</details>

#### Code Search Leaves Prose Out <a id="c-code-search-leaves-prose-out"></a>

- Markdown files are no longer part of default code-graph indexing.
- So prose docs are not treated as code nodes.
- A maintainer flag can re-enable them.
- Search over real code is unchanged.

## Upgrade Notes

No migration is required for the common path. Structural protections are on by default. The advisor recovery fix takes effect on your next fresh session.

#### Before You Start <a id="c-before-you-start"></a>

1. If you set `SPECKIT_SKILL_ADVISOR_HOOK_DISABLED`, rename it to `SYSTEM_SKILL_ADVISOR_HOOK_DISABLED`.
2. Move any design work using the removed `mcp-magicpath` skill to `mcp-open-design`.

<details>
<summary><b>Default-off features</b></summary>

- Idempotency, soft-delete tombstones, the acceptance-coverage gate, completion-freshness checking, semantic trigger fallback and learning reducers remain default-off and opt-in.

</details>
