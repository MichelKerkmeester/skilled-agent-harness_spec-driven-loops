# v2.3.0.0, Gemini Runtime Expansion

This release adds features, architecture work and documentation to the OpenCode environment.

- A complete Gemini command-line interface runtime adapter lands in `.gemini/`.
- 8 native agents and 19 command wrappers are added.
- The framework gains a 4-provider runtime matrix.

The goal is to make the platform clearer, more reliable and easier to use day to day.

- The environment can do more useful work without extra setup.
- Saved context is easier to find and easier to trust.
- The same instructions now behave more predictably in different runtimes.

Every change is additive and needs no migration for existing runtimes.

- The 4-provider matrix now includes Gemini.
- The runtime resolution table gains a Gemini row.
- The full changelog lives at `.opencode/changelog/`.

This release covers work across three areas of the OpenCode environment.

## Gemini Runtime

This area covers the Gemini command-line interface runtime adapter.

The change adds a directory layout, agents and wrappers.

#### Features <a id="c-features"></a>

- The `.gemini/` directory is a complete Gemini runtime adapter.
- It holds `agents/`, `commands/`, `skills/`, a `specs` shortcut link and `settings.json`.
- 8 Gemini-native agents are added for this runtime.
- They are `orchestrate`, `context`, `debug`, `research`, `review`, `speckit`, `write`, `handover`.
- Each has Gemini structured config frontmatter with `kind: local` and a `tools` array.
- Each has `max_turns` and `timeout_mins` plus routing-optimized descriptions.
- Each keeps 1:1 OpenCode body content.
- 19 wrappers cover all OpenCode commands in Gemini's `.toml` format.
- They use `@{file}` injection to keep a single source of truth.
- The wrappers span `spec_kit/` (7), `memory/` (5), `create/` (6) and `root` (1).
- These are the main capabilities added in this version.
- That matters because the environment can do more useful work without extra setup.

## Runtime Architecture

This area covers how the environment saves, finds and uses context.

It now spans four runtimes with role-tuned agents.

#### Architecture <a id="c-architecture"></a>

- The framework now supports 4 first-class runtimes.
- They are Copilot, ChatGPT, Claude and the Gemini command-line interface.
- Each has consistent agent, command and skill access.
- All agents are calibrated for the gemini-3.1-pro 400K effective window.
- Role tuning sets `max_turns` to 10-25.
- Role tuning sets `timeout_mins` to 5-15.
- Both come from per-agent token budget analysis.
- Tool access is scoped by role.
- `context` and `review` are read-only with `read_file`, `grep_search` and `list_directory`.
- `research` and `write` include `web_search`.
- `handover` excludes `run_shell_command`.
- `orchestrate` is minimal with `read_file` only.
- This improves how the environment saves, finds and uses context.
- That matters because saved context is easier to find and easier to trust.
- It is less likely to get in the way.

## Agent Documentation

This area covers the instructions that guide agents across runtimes.

It aligns paths, tables and templates.

#### Documentation <a id="c-documentation"></a>

- The runtime resolution table in `AGENTS.md` §7 now includes a Gemini command-line interface row.
- All Gemini agent bodies reference `.gemini/agents/*.md`.
- All 8 agents pass the `workflows-documentation` agent template checklist.
- The checklist covers CORE WORKFLOW, CAPABILITY SCAN, OUTPUT VERIFICATION, ANTI-PATTERNS, RELATED RESOURCES and SUMMARY.
- This makes agent behavior more consistent across supported runtimes.
- That matters because the same instructions now behave more predictably in different runtimes.
