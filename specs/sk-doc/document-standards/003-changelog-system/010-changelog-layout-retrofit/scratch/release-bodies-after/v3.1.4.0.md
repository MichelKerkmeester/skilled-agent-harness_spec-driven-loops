## Search Ranking and Response Size

Two changes cover ranking precision and response size.

#### Ranking Fits the Corpus <a id="c-ranking-fits-the-corpus"></a>

- Reciprocal rank fusion now uses a constant of k=40.
- The previous smoothing constant was k=60.
- This replaces the setting designed for much larger corpora.
- The previous constant was designed for corpora with 10,000 or more documents.
- Its score difference between rank 1 and rank 10 was only 0.002.
- That is essentially flat.
- For a 999-memory database, the new setting doubles that separation to 0.004.
- So top results are meaningfully distinguishable from lower-ranked ones.

#### More Matches Fit <a id="c-more-matches-fit"></a>

- The L2 response budget rises from 1500 to 2500 tokens.
- The larger allowance returns more search matches.
- The old 1500-token response budget often cut results to one match out of seven or more.
- The 2500-token budget accommodates the p95 memory content length.
- So users see three to five results instead of one.

## Recall and Coverage

Three changes cover recall and coverage.

#### Deprecated Memories Stay Out <a id="c-deprecated-memories-stay-out"></a>

- FTS5 text search now excludes deprecated memories.
- Vector search excluded 538 deprecated-tier memories.
- FTS5 text search did not.
- That mismatch let deprecated content leak into results through the lexical path.
- Lexical results follow the same exclusion as vector results.
- So FTS5 received the same exclusion filter.

#### Three-Token Queries Expand <a id="c-threetoken-queries-expand"></a>

- R12 embedding expansion now includes three-token queries.
- It broadens search by finding related terms from the embedding space.
- Its gate previously suppressed queries with three or fewer tokens.
- That blocked useful technical searches such as "mcp runtime hardening".
- Technical searches such as "mcp runtime hardening" can receive expansion.
- The threshold moved from ≤3 to ≤2.
- So three-token queries pass through.

#### Exact Phrases Match <a id="c-exact-phrases-match"></a>

- Multi-word searches now include exact-phrase matching.
- Searches like "spec kit" can favor documents containing the phrase.
- A search for "spec kit" previously matched documents containing "spec" or "kit" separately.
- FTS5 now adds the quoted phrase query `"spec kit"`.
- That boosts exact-phrase matches.

## Reranking and Diversity

One change makes reranking paths visible.

#### Reranking Paths Are Visible <a id="c-reranking-paths-are-visible"></a>

- Reranking metadata now identifies the provider.
- Metadata previously reported only `rerankApplied: true/false`.
- It did not identify which reranker ran.
- The `rerankProvider` field records the actual path.
- Search traces distinguish cross-encoder, local GGUF and fallback sort.
- So search traces and ablation studies are trustworthy.

## Data Quality

Three changes cover data quality.

#### Co-Activation Reads Both Formats <a id="c-coactivation-reads-both-formats"></a>

- Co-activation accepts scalar and object references.
- The co-activation parser expected `related_memories` entries in object form such as `[{id: 39}]`.
- The database stores scalar arrays such as `[39]`.
- The parser silently failed.
- So co-activation never contributed to search results.
- It now accepts both formats.
- Scalar entries previously received a similarity of 0.5.
- Boosts divide the 0-100 scale by 100.
- So this produced `0.5/100 = 0.005`, two orders of magnitude weaker than intended.
- Scalar references use similarity 50.
- Scalar entries now receive 50 to match that scale.

#### Zero Scores Get Backfilled <a id="c-zero-scores-get-backfilled"></a>

- Search scores zero-quality candidates automatically.
- Index-scan ingestion bypassed the quality gate.
- That left 520 of 1002 memories, or 52%, with a quality score of 0.0.
- `computeBackfillQualityScore()` scores content length, trigger phrases, title presence and importance tier.
- It is available for maintenance scripts.
- `computeBackfillQualityScore()` is also available to maintenance scripts.
- It also runs during search when a candidate has `quality_score === 0`.

#### Chunks Keep Their Parent <a id="c-chunks-keep-their-parent"></a>

- Chunk creation records each child's `parent_id`.
- Child chunks previously lacked their parent memory ID.
- This happened when memories were split into smaller pieces.
- That broke run history traversal and made chunks appear as orphans.
- Chunk creation now propagates `parent_id`.
- This connects child chunks to their parent memory.

## Observability

One change makes cache performance measurable.

#### Cache Performance Is Measurable <a id="c-cache-performance-is-measurable"></a>

- The embedding cache now reports hit and miss statistics.
- The embedding cache had no counters.
- So its effectiveness was impossible to measure.
- It now exposes `cacheHits` and `cacheMisses`.
- `getCacheStats()` returns `{hits, misses, hitRate}`.
- The statistics include hits, misses and hit rate.

## Operational Reliability

Two changes cover operational reliability.

#### Replay Uses Search Results <a id="c-replay-uses-search-results"></a>

- Interactive handlers were fixed.
- Shadow evaluation replay still fixed `minState: 'WARM'`.
- That left shadow evaluation, adaptive feedback and replay-based monitoring evaluating empty result sets.
- So the fixed value was removed.
- Shadow evaluation replay no longer fixes `minState` to `WARM`.
- This addresses empty result sets in replay-based evaluation and monitoring.

#### Schema Tests Follow the Simplification <a id="c-schema-tests-follow-the-simplification"></a>

- Tool schema tests match the simplified schemas.
- The schema simplification removed `oneOf` and `not` for Claude compatibility.
- That broke expected-behavior tests.
- Their assertions now match the current schema.
- Their assertions follow the removal of `oneOf` and `not` for Claude compatibility.
