A skill is the instruction file an agent reads before a job.

- Each one carried the routing tables that scripts read to pick reference files.
- The agent loaded those tables every time.
- They now live in a `ROUTER.md` beside each `SKILL.md`.
- An agent reads about 27 percent less. Every request routes as it did.

The release brings doctor commands for your skills and projects.

- `/doctor:sk-skill` converts a skill you wrote yourself.
- `/doctor:install` and `/doctor:symlink` link Skilled into your project.
- `/doctor:agents-md` keeps your root instruction file current.
- Each new command reads only, or writes after a plan and your yes.

`sk-code` gains a web frontend surface, and docs now render in order.

- The surface holds web practice, a five-pass Figma check and design values.
- It ships a starter `tokens.css`.
- Every skill doc was read by hand for layout.
- Render checks now flag a doc that reads wrong.

Your answers reach the decision record, and playbooks test a conversation.

- A full-auto save records each answer as a short decision.
- This works on all five supported runtimes.
- A scenario can script several turns and restart the session.
- Four surfaces are retired. The retirements are the breaking part.

> [!IMPORTANT]
> Two changes can break an existing setup. Read these before you update.
>
> - MagicPath, `sk-vision` and `/vision` are gone. [MagicPath and Vision Leave the Framework](#c-magicpath-and-vision-leave-the-framework)
> - `sk-design-fundamentals` is retired. [Design Values Leave the Design Hub](#c-design-values-leave-the-design-hub)

&nbsp;

## Why This Release

Routing tables made up 22 percent of every word in the skill files. Three skills sat within 25 words of the 5,000-word cap.

- Adopters also had no way to check whether a skill was in the current format.
- They could not link the framework into their own project.
- They could not tell which lines of their root instruction file an update would overwrite.
- An answer you gave to an AI's question reached a decision record only when someone retyped it.
- Spacing, colour and motion values lived on the design hub.
- The code that builds the screen had none of them.

## Skill Routing

Each hub wrote its routing words in four places. Now each hub writes them in one checked place. `SKILL.md` links to the router in one line.

#### The Router Leaves the Skill File <a id="c-the-router-leaves-the-skill-file"></a>

- Intent tables, resource maps and pseudocode that scripts read now sit in a `ROUTER.md`.
- They sit beside each `SKILL.md`.
- `SKILL.md` links to the router in one line.
- Across the 54 skills and modes, the files an agent loads fell from 328,333 tokens to 238,406.
- The advisor scores the same on its three labelled prompt sets.
- Nothing routes differently.

#### Skills You Write Must Use the New Shape <a id="c-skills-you-write-must-use-the-new-shape"></a>

- `/create:skill` and `/create:skill-parent` write the router file for you.
- They score the new docs for clear, plain writing.
- A skill that keeps its router inside `SKILL.md` now fails `package_skill.py --strict`.
- A skill with no `ROUTER.md` fails it too.

#### More Requests Reach the Right Skill <a id="c-more-requests-reach-the-right-skill"></a>

- Each hub now writes its routing words in one checked place instead of four.
- Five generic phrases such as "state machine" and "style guide" no longer pull ordinary prompts to the wrong hub.
- Orca, GitLens, deep-loop reviews, chart choices and DESIGN.md repaints reach the skill that owns them.
- A clarity review of a design doc reaches `sk-doc`.
- A request such as "review this, don't write anything back" no longer counts as a request to write docs.

## Frontend Surface

`sk-code` now carries a web frontend surface. Spacing, type, colour, hierarchy and motion values live with the code.

#### A Web Surface on the Code Hub <a id="c-a-web-surface-on-the-code-hub"></a>

- `sk-code-frontend` holds the frontend practice a web change needs.
- It says which element carries a behavior.
- It says where a focus ring goes.
- It says how a long list stays readable.
- It loads beside a coding workflow when the request is about web UI.
- Six topic files load only when the request touches them.
- A project can replace, extend or switch off any rule under a `Frontend overrides` heading in its own `SKILL.md`.

#### The Figma Check Has Five Passes <a id="c-the-figma-check-has-five-passes"></a>

- A built screen is compared with its Figma frame in five passes.
- They are width, each state and the rendered tokens.
- Then each Figma variable against your token package.
- Then range and access.
- A pass that cannot run leaves the verdict `INCOMPLETE`, never `PASS`.
- Every Figma read that feeds code ends at this check.

#### Design Values Live With the Code <a id="c-design-values-live-with-the-code"></a>

- Spacing, type, colour, hierarchy and motion values now come from `sk-code-frontend`.
- So a screen and its values answer to one owner.
- It ships a starter `tokens.css` to copy into a project and retune.
- Under a reduced-motion preference, movement becomes an instant change or a short fade.
- A design review now loads this surface beside the review workflow.

## Doctor Commands

Each new command only reads, or writes after a plan and your yes.

#### Your Skills, Measured and Converted <a id="c-your-skills-measured-and-converted"></a>

- `/doctor:sk-skill check` reports how far a skill sits from the Skilled format.
- Each finding comes with its repair.
- `/doctor:sk-skill convert <skill>` moves a skill onto the format.
- An older Skilled skill gets its router moved out.
- A plain agent skill is copied in while its source stays untouched.
- Nothing is written until every line of the old body is found in the new files.
- The run ends with an undo block.

#### Your Own Project, Linked In <a id="c-your-own-project-linked-in"></a>

- `/doctor:install` prints the setup steps in order and writes nothing.
- `/doctor:symlink check` reports how each framework folder in your project is linked.
- `link` creates the links after a plan.
- It never overwrites a real file.
- The ignore lines go to your repository's `.git/info/exclude`, so the links stay out of your commits.
- `unlink` undoes one run exactly.
- A linked project now saves, routes and relinks like a checkout.

#### Your Root Instruction File, Kept Current <a id="c-your-root-instruction-file-kept-current"></a>

- `/doctor:agents-md check` shows which shipped sections changed.
- It shows which lines are yours.
- `embed` brings the file current around your own block against a plan you read.
- It restores itself from a backup if any line of yours would be lost.
- `restore` undoes one run.

#### The Right Command for a Problem <a id="c-the-right-command-for-a-problem"></a>

- `/doctor:helper` takes a problem in plain words.
- It ranks the doctor commands that fit it.
- The advisor also suggests the new doctor commands when a prompt describes their problem.

#### The Updater Keeps Its Records Local <a id="c-the-updater-keeps-its-records-local"></a>

- `/doctor:update` now keeps its records in a folder git ignores.
- `.skilled/release/` no longer ships.
- Each clone records its own base.

## Spec Kit

A save now records each answer you gave an AI's question. It works on all five supported runtimes.

#### Your Answers Reach the Decision Record <a id="c-your-answers-reach-the-decision-record"></a>

- A full-auto `/speckit:save` writes each answer into the spec folder's `decision-record.md`.
- It writes it as a short decision.
- The question, the options and your answer are kept word for word.
- Process questions are left out.
- That covers which folder to use or whether to push.
- Claude Code, Codex, Pi, OpenCode and Devin all capture.
- A plain-chat answer is added only after you confirm it.
- A repeat save adds nothing twice.

#### Each Linked Project Keeps Its Own Answers <a id="c-each-linked-project-keeps-its-own-answers"></a>

- Projects linked to one Skilled checkout no longer share one answer folder.
- So a save lists only its own project's sessions.
- "Record this as a decision" now routes to spec-kit.

## Manual Testing Playbooks

Playbooks can now test a whole conversation. A scenario scripts several turns inside a scratch project.

#### A Scenario Can Follow the Conversation <a id="c-a-scenario-can-follow-the-conversation"></a>

- A playbook scenario used to send one prompt and judge the reply.
- It can now script several turns.
- It can give the answers to give and restart the session.
- It can check after each turn.
- `run-conversation-scenario.cjs` plays that script into Claude Code, OpenCode, Codex, Pi or Devin.
- It runs inside a scratch project.
- It keeps the evidence for each turn.
- It stops the run if anything would write to your repository.

#### Docs That Read Wrong Are Caught <a id="c-docs-that-read-wrong-are-caught"></a>

- A doc could pass validation and still read wrong once rendered.
- Two bold labels on consecutive lines join into one paragraph.
- A line above `---` turns into a heading.
- Sixteen render checks now catch these.
- They also catch docs that open or order their sections wrong.
- `package_skill.py --strict` fails a skill on any of them.
- A citation of a section that does not exist is reported in every kind of doc except changelogs and specs.

#### A Rewrite Has to Keep Every Claim <a id="c-a-rewrite-has-to-keep-every-claim"></a>

- `doc-rewrite-guard.py --base <ref>` compares each changed doc with its earlier text before you commit.
- It fails on a changed code sample.
- It fails on a dropped citation.
- It fails on a cited section that was removed or renamed.
- It refuses edits to docs that code reads word for word.
