## Packet Changelogs

Packet-local changelogs now have one generator and three aligned command surfaces. Root packets and phase folders get canonical output paths and templates.

#### One Generator, Two Output Paths <a id="c-one-generator-two-output-paths"></a>

- Spec Kit now ships a nested changelog generator.
- Root packets and direct child phases now have a canonical place.
- That place holds chronological completion history beside their implementation summaries.
- Packet-local changelogs already existed in some specs.
- But there was no main generator and no approved naming rule.
- No single workflow explained how root packets and phase folders should produce those files.
- The new generator detects its target.
- The target is either a packet root or a direct child phase.
- Root output writes to `changelog/changelog-<packet>-root.md`.
- Phase output writes to the parent packet as `changelog/changelog-<packet>-<phase-folder>.md`.

#### Templates That Define Packet History <a id="c-templates-that-define-packet-history"></a>

- Some places were already creating packet changelog files.
- The repo still lacked main templates for what those files should contain.
- It also lacked documentation for how they relate to `implementation-summary.md`.
- Dedicated root and phase changelog templates were added.
- A workflow reference was added too.
- It explains the evidence stack, the output paths and the packet-local intent.
- Packet changelogs are now explicitly documented as additive to `implementation-summary.md`.
- They are not a replacement for it.

#### Closeout Commands Speak With One Voice <a id="c-closeout-commands-speak-with-one-voice"></a>

- `/create:changelog`, `/spec_kit:implement` and `/spec_kit:complete` could not speak consistently about packet-local history.
- That would happen if the generator, templates and workflow docs were updated in isolation.
- All three command surfaces were updated in the same pass.
- The shipped generator now handles root and phase naming instead of manual improvisation.

## Recovery

Packet 029 closed the open review findings on the Compact Code Graph and recovery surfaces.

#### Bootstrap Output Matches Its Docs <a id="c-bootstrap-output-matches-its-docs"></a>

- The public `session_bootstrap` behavior already described recommended next actions.
- But the handler did not return them.
- The docs and the implementation were telling slightly different truths.
- The recovery surface no longer depends on readers inferring behavior from docs.
- The handler itself did not fulfill those docs.
- Its tool schema documents the full output shape.

#### A Startup Budget Enforced in Code <a id="c-a-startup-budget-enforced-in-code"></a>

- The structural startup behavior documented the ceiling.
- But the limit was still advisory.
- It was not enforced in the shared builder.
- Now that the shared structural bootstrap builder applies it as code, startup structural context is truthful.
- It is consistent with the packet docs that promised a hard ceiling.
- The 500-token structural startup ceiling is now enforced in code.
- Startup structural context stays bounded.

#### Safer Provenance and Autosave Targeting <a id="c-safer-provenance-and-autosave-targeting"></a>

- Compact recovery and autosave still had ambiguity at two risky points.
- Recovered text could appear without the shared provenance fence.
- Transcript-tail packet detection could promote uncertain scope matches into autosave targets.
- Compact recovery now wraps recovered text with the shared provenance fence.
- Autosave now retargets only when transcript evidence clearly shows a new unambiguous packet.
- Claude stop-hook autosave now preserves validated active-session state.
- Ambiguous transcript-only matches are no longer treated as authoritative.

#### Agent Copies and Packet Docs Agree <a id="c-agent-copies-and-packet-docs-agree"></a>

- The implementation fixes alone were not enough.
- The recovery story also needed two things to reflect the bootstrap-first behavior and the shipped closeout state.
- Those were the runtime-facing agent copies and the packet documentation.
- Claude and Codex `context-prime` definitions now include the explicit Structural Context guidance.
- The OpenCode version already had it.
- The related Packet 024 root and phase docs were refreshed.
- Now the shipped evidence, phase map and recovery behavior tell the same story.

## Research and Review Contracts

Packet 040 (`.opencode/specs/skilled-agent-orchestration/040-sk-auto-deep-research-review-improvement/`) brought both autonomous workflows onto one stronger contract model.

#### One Packet Model for Deep Research <a id="c-one-packet-model-for-deep-research"></a>

- The deep-research workflow still relied on scattered wording.
- That wording covered run history, lifecycle branches, reducer ownership, packet artifacts and runtime parity.
- That made its behavior easier to drift and harder to audit.
- Deep-research now has main run history fields, lifecycle modes and reducer-owned outputs.
- It also has runtime capability surfaces and executable helpers.
- The workflow YAML, skill docs, runtime mirrors and packet-closeout rules all point at the same packet model.

#### Deep-Review Schemas You Can Verify <a id="c-deep-review-schemas-you-can-verify"></a>

- Deep-review still mixed `deep-research-*` and `deep-review-*` naming.
- That naming ran across docs, assets and workflow surfaces.
- Its release-readiness and reducer schemas were also easier to describe than to verify.
- Deep-review now exposes explicit lifecycle, reducer, severity and release-readiness schemas across its behavior surfaces.
- Legacy `deep-research-*` names are limited to the intentional scratch migration path.

#### Runtime Mirrors Move Together <a id="c-runtime-mirrors-move-together"></a>

- Autonomous workflow instructions can silently diverge across OpenCode, Claude, Codex and compatibility wrappers.
- That happens when each runtime surface is patched separately.
- Packet 040 synchronized all runtime mirrors for both deep-research and deep-review in one pass.
- Lifecycle vocabulary, reducer-owned surfaces and packet file expectations now move together.
- They no longer fragment by runtime.
