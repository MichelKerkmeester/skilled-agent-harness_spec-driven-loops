This small patch release corrects Codex hook registration. It also fixes two documentation errors. The OpenCode code-graph plugin bridge repair was reverted before release.

&nbsp;

## What's New at a Glance

- Codex sessions now use Codex-native hooks.
  - `.codex/hooks.json` had registered Claude's hook scripts for every event.
  - `SessionStart` and `UserPromptSubmit` now point to Codex-native adapters.
  - The Codex-native adapters read the Codex stdin envelope and answer in kind.
  - Unsupported `PreCompact` was removed.
  - `PreCompact` was not rewired to a Claude-envelope script.
- The Codex MCP note now gives the correct code-graph database paths.
  - The note had the skill-local and legacy shared paths backwards.
  - The note now names the skill-local path as the default.
  - The note names the legacy shared path as legacy.
  - Both match launcher source.
- The OpenCode code-graph plugin repair was reverted.
  - Skill extraction moved three imports.
  - That left sessions reporting "Code Graph: unavailable."
  - Repointing them made the bridge run.
  - Repointing them also made the bridge emit the right transport payload.
  - But the resulting bridge initialized the memory database directly in its own process.
  - That ran outside the daemon's single-writer lease.
  - This is the same corruption class the daemon architecture exists to prevent.
  - The bridge stays down until an IPC-backed transport replaces the direct imports.
- A planned sweep of orphaned launcher processes killed nothing.
  - Parent-process classification showed all nine running launchers belonged to live sessions.
  - The true orphan class is launchers that outlive an exited owner.
  - That class is separately scoped daemon-reliability work.

&nbsp;

## Upgrade

No code changes ship in this release. The fixes are configuration and documentation. Start a new Codex session so the hook correction takes effect. No other action is needed.
