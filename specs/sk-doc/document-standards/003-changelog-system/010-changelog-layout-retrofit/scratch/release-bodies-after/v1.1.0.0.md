## Cognitive Memory

#### Power-Law Decay and the Testing Effect <a id="c-power-law-decay-and-the-testing-effect"></a>

- Memory decay follows the FSRS power law.
- It replaces arbitrary exponential decay.
- It is validated on 100M+ users.
- The decay formula is `R(t,S) = (1 + (19/81) * t/S)^(-0.5)`.
- It is implemented in `fsrs-scheduler.js`.
- Attention decay in the MCP server integrates the FSRS decay functions.
- Under the Testing Effect, accessing a memory strengthens its stability through a desirable difficulty bonus.

#### Duplicates Stopped at the Gate <a id="c-duplicates-stopped-at-the-gate"></a>

- Prediction Error Gating prevents duplicate memories.
- It adds duplicate detection.
- It also adds conflict resolution.
- Prediction Error Gating uses four thresholds.
- `DUPLICATE` is at 0.95.
- `HIGH_MATCH` is at 0.90.
- `MEDIUM_MATCH` is at 0.70.
- `LOW_MATCH` is at 0.50.
- The gate is implemented in `prediction-error-gate.js`.

#### Five States From HOT to ARCHIVED <a id="c-five-states-from-hot-to-archived"></a>

- Memories move through five states.
- Each memory is HOT, WARM, COLD, DORMANT or ARCHIVED.
- The tier classifier is extended from a 3-state model to a 5-state model.
- HOT is at 0.8 or above.
- WARM is from 0.25 to 0.8.
- COLD is from 0.05 to 0.25.
- DORMANT covers 0.02 to 0.05.
- ARCHIVED is below 0.02.

#### Composite Scoring and Schema v4 <a id="c-composite-scoring-and-schema-v4"></a>

- Composite scoring now weighs retrievability.
- Similarity counts for less than before.
- Composite scoring adds a retrievability weight of 0.15.
- It lowers the similarity weight from 0.30 to 0.25.
- Schema v4 adds the `stability`, `difficulty`, `last_review` and `review_count` columns.
- Schema v4 also adds a `memory_conflicts` table.

## Memory Reliability

The fixes are ranked by priority, from critical (P0) to low (P3). The remaining fixes cover P1 to P3. They guard against data loss, ReDoS, NaN values and partial transaction commits.

#### Critical Fixes for FSRS and Thresholds <a id="c-critical-fixes-for-fsrs-and-thresholds"></a>

- Three critical (P0) bugs are fixed.
- The FSRS function now executes.
- Two pairs of tiers no longer share a threshold.
- The FSRS function never executed because of a signature mismatch in the tier classifier.
- That mismatch is now fixed (BUG-001).
- `MEDIUM_MATCH` equaled `LOW_MATCH`, so `LOW_MATCH` changed to 0.50 (BUG-002).
- The COLD and DORMANT thresholds were equal, so DORMANT changed to 0.02 (BUG-003).

#### Safer Restores, Parsing and Error Handling <a id="c-safer-restores-parsing-and-error-handling"></a>

- Eight high-priority (P1) bugs are fixed.
- Cache methods: `LRUCache` gains the `keys()` and `delete()` methods it was missing (BUG-004).
- Database checks: The delete and update handlers now await their database check (BUG-005).
- Promise rejections: `reinforce_existing_memory` is wrapped in try/catch, so its promise rejection is no longer unhandled (BUG-006).
- Missing timestamps: With no timestamps, an early return with a 0.5 default stops NaN from propagating (BUG-007).
- Checkpoint restores: A SAVEPOINT/ROLLBACK pattern in checkpoints prevents data loss when a restore fails (BUG-008).
- YAML parsing: The memory parser reads YAML line by line instead of through a regex exposed to ReDoS (BUG-009).
- Trigger patterns: Bounded greedy quantifiers in the trigger extractor remove ReDoS from trigger patterns (BUG-010).
- Delete errors: Delete errors are no longer silent and are logged with `console.warn` (BUG-011).

#### Steadier Caches, Scores and Transactions <a id="c-steadier-caches-scores-and-transactions"></a>

- Nine medium-priority (P2) bugs are fixed.
- Cache loading: A loading flag with try/finally prevents a cache thundering herd (BUG-012).
- Tier weights: Inconsistent tier weights are centralized in importance tiers (BUG-013).
- Environment variables: `isNaN()` validation in working memory stops env vars from producing NaN (BUG-014).
- Negative scores: Co-activation clamps scores with `Math.max(0, score)` (BUG-015).
- Partial commits: A transaction tracks failures and rolls back everything instead of committing part of its work (BUG-016).
- Token metrics: Token metrics were taken in the wrong order and are now captured before reassignment (BUG-017).
- Undo: Undo now checks its result by verifying `changes > 0` in history (BUG-018).
- Migrations: A `database.transaction()` wrapper makes migration transactional (BUG-019).
- UTF-16 BE: Manual byte-swap conversion adds support for UTF-16 BE (BUG-020).
