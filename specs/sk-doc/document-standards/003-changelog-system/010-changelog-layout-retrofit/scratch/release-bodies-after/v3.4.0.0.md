This release changes how the system remembers things between sessions.

- Your memory now lives inside the spec documents you already track.
- Picking up where you left off is faster.
- It is more reliable and easier to reason about.

Alongside the memory rewrite, the search stack got smarter.

- The code graph got safer to traverse.
- The deep-loop skills became fully auditable.
- The CLI skills now check prompt quality before they call external models.

A cleanup pass on the skill advisor removed dead routing code.

- It added coverage for the kinds of phrases people actually type.
- The intake command surface also consolidated around a shared intake contract.

&nbsp;

## Why This Release

Memory used to sit in standalone files beside the spec documents. That meant separate files to maintain. It also meant a parallel history that could drift against the record.

- Keeping continuity in the spec documents gives the record one place.
- It leaves no parallel tree to keep in sync.

## Memory and Commands

#### No More Memory Folders <a id="c-no-more-memory-folders"></a>

- `[spec]/memory/` directories are no longer created.
- New spec folders never get one.
- Older ones stay on disk as a read-only archive.
- So nothing gets deleted out from under you.
- The code that wrote those files is gone.
- The save workflow no longer renders them.
- Indexing now flows directly through your canonical spec docs.

<details>
<summary><b>Smaller fixes</b></summary>

- The old 589-line memory template is deleted.
- Four checklist templates lose their "Findings saved to memory/" row.
- The legacy test fixtures migrated over.

</details>

#### Every Save Finds Its Document <a id="c-every-save-finds-its-document"></a>

- Session notes, decisions and handover hints now go into the spec documents.
- Every save routes into the right document automatically.
- Decisions land in `decision-record.md`.
- Progress updates land in `implementation-summary.md`.
- Handover notes land in `handover.md`.
- A content router picks the destination without you thinking about it.
- Session resume checks one clear order.
- It reads `handover.md` first.
- Then it reads the `_memory.continuity` block inside `implementation-summary.md`.
- Then it reads the spec docs themselves.
- The first source with useful content wins.
- Quick session notes skip the full save pipeline.
- The AI can edit the continuity block directly.
- The full indexed save is reserved for work that needs database visibility.
- Session stop hooks autosave by default.
- So shutting a session no longer loses context.
- Five validation checks run before every save.
- A broken save rolls back instead of corrupting your spec folder.

#### A Metadata File per Folder <a id="c-a-metadata-file-per-folder"></a>

- Each `graph-metadata.json` describes what its folder holds.
- It also describes what it depends on and what it relates to.
- The file has two sections.
- A `manual` block is where you declare relationships (`depends_on`, `supersedes`, `related_to`).
- A `derived` block auto-refreshes with trigger phrases, key files, entities, status and timestamps.
- Saves refresh the metadata automatically.
- Your manual relationships are preserved.
- The derived half regenerates on its own.
- Search, ranking and the causal graph all use this file.
- Searches surface packet roots directly.
- Ranking respects the relationships you have declared.
- Graph queries traverse the tree in a single lookup.

<details>
<summary><b>Smaller fixes</b></summary>

- Entity extraction is clean and bounded.
- Shell commands are filtered out.
- Long or multi-line names are rejected.
- There are no duplicates.
- The initial backfill populated 515 spec-folder roots.

</details>

#### Shared Memory Fully Removed <a id="c-shared-memory-fully-removed"></a>

- The dead shared-memory subsystem is deleted.
- That covers its handlers, storage, governance flags, four MCP tools and all related aliases.
- A one-time cleanup runs on startup.
- It drops the stale database column if it is still there.

#### Fewer Commands and Agents <a id="c-fewer-commands-and-agents"></a>

- Two wrapper commands and two exclusive-writer agents retired in this release.
- They became redundant once continuity moved into canonical spec docs.
- The agents are gone across all four runtimes, 15 paths total.
- The old `@speckit` exclusive-writer rule is replaced with a distributed governance rule.
- Any agent writing spec folder docs must use the provided templates.
- It must run strict validation after every write.
- It must route continuity through `/memory:save`.
- `@deep-research` and `@debug` keep write access only for their own specific files.
- `/memory:save` becomes the canonical maintainer of the handover log.
- `/spec_kit:complete` loses its `:auto-debug` flag.
- If implementation fails three times, the workflow surfaces the diagnostic.
- You then decide whether to dispatch `@debug` yourself.

#### One Intake Contract <a id="c-one-intake-contract"></a>

- The `--intake-only` flag on `/spec_kit:plan` is backed by a shared intake contract.
- That contract consolidates three parallel intake surfaces into one canonical module.

## Search and Ranking

Scoring no longer runs on one hardcoded profile. Save routing is smarter on mixed content.

#### Your Choice of Embedding Backend <a id="c-your-choice-of-embedding-backend"></a>

- The checked-in configs in `.mcp.json`, `.claude/mcp.json`, `.vscode/mcp.json` and `opencode.json` now share `EMBEDDINGS_PROVIDER=auto`.
- The same repo can run with the default cloud path.
- It can also run with a local fallback.
- Both work without rewriting config.

#### A Reranker Tuned for Real Results <a id="c-a-reranker-tuned-for-real-results"></a>

- `getRerankerStatus()` now reports `hits`, `misses`, `staleHits` and `evictions`.
- That makes cache behavior visible when a result moves.
- `applyLengthPenalty` still exists for compatibility.
- It now resolves to a neutral `1.0`.
- Long handover and implementation docs keep their place when they are the best match.
- Stage 3 reranking also waits for enough evidence to matter.
- The cutoff moved from 2 results to 4.
- The same boundary now holds for both the cloud reranker and the local reranker path.

#### Weights Tuned for Resuming Work <a id="c-weights-tuned-for-resuming-work"></a>

- Resume-style lookups use `0.52 / 0.18 / 0.07 / 0.23` weights.
- Those weights cover semantic, keyword, recency and graph signals.
- They do not reuse the generic weights.

<details>
<summary><b>Tests and scenarios</b></summary>

- The profile was checked against a judged 12-query continuity fixture.
- The fixture kept the baseline `K=60` recommendation.

</details>

#### Causal Lineage Keeps Anchor Detail <a id="c-causal-lineage-keeps-anchor-detail"></a>

- Two links between the same docs can now stay separate when they point at different sections.
- Schema version `26` added `source_anchor` and `target_anchor` to `causal_edges` to make that possible.

## Code Graph

Traversal is tighter and easier to trust in multi-file work.

#### Richer Answers, Same Trust Boundaries <a id="c-richer-answers-same-trust-boundaries"></a>

- Bounded traversal stays scoped to graph-owned outputs, not every startup surface.
- You get richer code-graph answers.
- The trust boundaries from the other graph packets still stay in place.

#### Edges That Carry Real Provenance <a id="c-edges-that-carry-real-provenance"></a>

- Every node and edge can now carry a real source label.
- That replaces a loose parser string.
- The runtime serializes a dedicated detector-provenance vocabulary.
- A compatibility mapper maps back to the older `ParserProvenance` names.
- So existing surfaces do not break.
- Graph-local results also carry better evidence.
- Shared payloads can now include `edgeEvidenceClass` and `numericConfidence`.
- That makes it easier to tell whether a relationship came from strong structural evidence.
- It also shows when it came from a weaker graph-local guess.

#### Union Queries Across Many Files <a id="c-union-queries-across-many-files"></a>

- Multi-file union is now a real mode, not an implied merge.
- `unionMode: 'multi'` combines several source files without duplicate results.
- High-degree files add a `hotFileBreadcrumb`.
- So you can see when one file is dominating the walk.

## Skill Advisor

The production skill graph that powers routing is hardened and future-proofed.

#### Missing Skills Fail the Build <a id="c-missing-skills-fail-the-build"></a>

- If a skill is referenced but not defined, the compiler fails the build fast.
- Previously missing edges on central skills are filled.
- Bad sibling pairings are removed.
- The compiler emits intent signals and prerequisite relationships into the runtime graph.
- So callers can tell whether a match came from a graph signal.
- They can also tell when it came from a direct keyword hit.
- All 21 per-skill metadata files migrated to schema v2 with new derived blocks.
- The compiler stays compatible with the old format during the transition.
- So nothing breaks mid-migration.

#### Routing Keys in the Right Dict <a id="c-routing-keys-in-the-right-dict"></a>

- The advisor's broken routing keys were multi-character keys.
- They sat in the wrong routing dict.
- There they never matched anything, because of how the tokenizer works.
- All of them are removed from it.
- 33 moved into the right dict, the one that matches multi-word phrases.
- Three were dropped because the same routing already existed at a higher weight.
- One conflicting routing was resolved.
- `"code audit"` used to point to two different skills in two different dicts.
- The version that was actually working at runtime stays.
- The dead pointer is deleted, so nothing changes at runtime.
- The new phrase routes cover identifiers that were going unrouted.
- A new inline comment warns future contributors.
- They should not put multi-word or hyphenated keys into the wrong dict.

<details>
<summary><b>Tests and scenarios</b></summary>

- For example, the query `"5-dimension agent scoring"` used to misroute to `sk-prompt` at 0.77 confidence.
- That came through a weak keyword hit on `scoring`.
- After the fix it routes to `sk-deep-agent-improvement` at 0.95.

</details>

## Deep-Loop Skills

The runtime behind the deep-research and deep-review skills is now ready to scale. An offline optimizer can tune configs against real traces without ever touching production.

#### An Audit Trail for Every Stop <a id="c-an-audit-trail-for-every-stop"></a>

- The deep-loop runtime now records stop decisions in a form you can inspect.
- Each named reason comes from the same small taxonomy.
- The reasons are `converged`, `max_iterations`, `blocked`, `user_stop` or `error`.
- The legal-stop gate now checks convergence, coverage and quality together.
- Only then is a run allowed to stop.
- That audit trail is no longer implied by scattered notes.
- Blocked and claim-adjudication decisions now persist as explicit events.
- The dashboards stay generated markdown, backed by the same structured state underneath.

#### A Coverage Graph Beneath Convergence <a id="c-a-coverage-graph-beneath-convergence"></a>

- `deep-loop-graph.sqlite` stores nodes, edges and snapshots.
- Four graph tools expose gaps, contradictions, provenance chains, hot nodes and stop blockers directly.
- They do not roll everything up into one abstract score.
- Concurrent runs on the same packet no longer share graph state by accident.
- The graph store now keys records by `(spec_folder, loop_type, session_id, id)`.
- So two sessions can write the same local node id without colliding.

#### Large Targets Split Into Bounded Waves <a id="c-large-targets-split-into-bounded-waves"></a>

- Wave mode turns on only when the scale justifies it.
- That means `1000+` review files or `50+` research domains.
- Smaller runs keep the old single-stream path.
- Deterministic segmentation plus keyed merge lets provenance survive the join.

#### One Resolver for Artifact Folders <a id="c-one-resolver-for-artifact-folders"></a>

- A shared `resolveArtifactRoot(specFolder, mode)` function walks up the directory tree.
- It finds the root parent spec.
- When a deep-review or deep-research targets a child phase, the artifacts go to `{root}/review/{phase-subfolder}/`.
- They do not go to `{child}/review/`.
- Both reducers use the shared resolver.
- So do all four command YAMLs and all eight agent definitions (four runtimes, two skills).
- A standalone spec with no parent behaves the same as before.

## CLI Prompt Quality

#### A Quality Card in Every CLI Skill <a id="c-a-quality-card-in-every-cli-skill"></a>

- A lightweight quality card lives inside each CLI skill (`cli-claude-code`, `cli-codex` and `cli-copilot`).
- Routine prompts pass through it.
- Complex prompts escalate to the shared `@prompt-improver` agent.
- Those are prompts flagged by a complexity score or explicit isolation signals.
- That agent runs the full prompt-engineering methodology in a fresh context.

#### Card Copies Kept in Sync <a id="c-card-copies-kept-in-sync"></a>

- A sync script hashes the canonical card and all three mirror copies.
- Drift fails a local check before it reaches review.
