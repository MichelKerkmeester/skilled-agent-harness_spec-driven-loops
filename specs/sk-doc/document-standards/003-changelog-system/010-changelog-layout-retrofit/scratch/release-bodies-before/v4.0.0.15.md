A spec packet used to need a strong model. A fast, cheaper model would leave template text unfilled. It would delete sections it should keep. It would loop on metadata errors it could not read. Now the templates show what good looks like. The validator catches an unfilled value. It repairs a draft's metadata on its own. A one-page guide walks a model through the packet. Every existing packet keeps the verdict it had.

The release also trims what a model has to carry. Three add-on templates are gone. Scaffolds lose their filler sections. The skill advisor sends typed commands to the skill that owns them. It stops calling most prompts ambiguous.

> Spec folder: `specs/system-speckit/054-weak-model-spec-authoring` (Level 2)

&nbsp;

## Why This Release

Spec-driven work only scales when a cheaper model can do the writing. The work was measured over eight rounds. Packets written against the new templates scored higher than packets written before this work. That held in every round. They scored 24.8 against 22.9 out of 30. Writing them took no measurable extra time.

&nbsp;

## What's New at a Glance

- **Templates show what good looks like.** A model copies the shape of a good answer instead of guessing at it.
- **An unfilled value can no longer ship.** It is allowed while a packet is a draft. It blocks the packet after that.
- **One guide asks for one validator run.** A model stops looping on the validator after three rounds of fixes.
- **Drafts fix their own generated metadata.** A model no longer burns turns on errors it cannot read.
- **Three add-on templates are retired.** Before-after, roadmap and resource-map no longer scaffold. New scaffolds are shorter.
- **Scaffolding stays inside the repository.** `create.sh` refuses any target that points outside it.
- **The advisor sends a typed command to its owner.** It also flags nearly a third fewer prompts as ambiguous.

## Spec Kit

#### Templates That Teach

Each template section opens with a fill note. It gives one line on what to write, a good example and a weak one. The examples use a neutral task. They do not echo whatever the model was asked to build. So a model no longer copies them into its own packet. Scaffolds lose the sections small work never needs. The effort estimate and the extended rollback are gone. Edge cases shrink to three lines. Sign-off shrinks to one row.

A `spec.md` now carries a Measured Behavior block. It holds the command the change affects and its real output. The validator warns when that block holds neither output nor a reasoned "N/A". It does not fail.

#### An Unfilled Value Cannot Ship

Templates mark each value a writer must supply with a `[YOUR_VALUE_HERE: ...]` token. A token left in a Draft packet is a warning. The same token fails the packet at any other status. A token quoted inside inline code or a code block counts as an example. A code block ends only on its own fence marker. So a fence quoted inside another one cannot hide a token after it. The check reads only docs built from the new templates. So older docs validate as they did.

#### One Validator Run, Then Fix Everything

The spec authoring card is a one-page path through a packet for a weaker model. It is `spec-authoring-card.md` in system-spec-kit. It asks for one `validate.sh --strict --quiet` run. It asks for a fix for every rule that failed before the next run. That replaces one run per rule. A run can fail on generated metadata. Then the validator's first hint line is the exact repair command.

#### Drafts Repair Their Own Metadata

When every error in a strict validation of a draft comes from generated metadata, the validator runs the repair once. It names every file it rewrote. Then it validates again. It never touches body text. It never runs in CI. It never runs for a packet that is not a draft. A recursive run repairs each draft child the same way.

#### Three Add-Ons Retired

The three templates are deleted, not just hidden. So seven add-ons remain. Packets that already hold those files still validate. The research and review loops still write their own resource maps. Those maps never read the removed template.

#### Scaffolding Stays Inside the Repository

`create.sh --track` refuses an absolute path or one with `..`. `create.sh --path` judges an existing folder or link. It looks at where it really points. So it refuses a link out of the repository. It also refuses a broken link, a regular file and the repository root itself. A track that already exists as a symlink keeps working by design.

## Skill Advisor

#### Typed Commands Route to Their Owner

A prompt that types `/deep:research :auto` used to rank system-spec-kit first. That is because the skill borrowed score from the deep loop it supports. A skill can borrow from a typed command's owner. It can now rise up to the owner. It never rises past it. Mode suffixes such as `:auto` and `:confirm` no longer count as words in the prompt. So they stop matching any skill that happens to mention "auto".

#### Fewer False Ambiguity Flags

The advisor called 110 of 261 labelled routing prompts ambiguous. That was mostly because a confidence floor lifts unrelated skills. It lifts them to the same confidence as the top. A skill that only reached that floor now counts as tied. That holds only when its score is also close. A skill held below a typed command's owner never counts as tied with it. Flags fell to 78. Every top pick stayed the same. The hook brief now names a skill that is in the tie.

&nbsp;

## Git Worktrees

#### Private Commands Reach Every Worktree

An operator's private `local-*` commands are git-ignored. So a new worktree used to start without them. Worktree provisioning now links each one in from the primary checkout.

&nbsp;

## Upgrade Notes

- **Stop requesting the retired add-ons.** Drop before-after, roadmap and resource-map from any script or prompt that asks for them.
- **Point a weaker authoring model at the card.** Hand it `spec-authoring-card.md` before it starts a packet.
- **Turn off draft repair where a run must not write.** Set `SPECKIT_DRAFT_AUTO_REPAIR=0`.
