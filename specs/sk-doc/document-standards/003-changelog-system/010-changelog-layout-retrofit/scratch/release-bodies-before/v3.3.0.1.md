This patch scopes save-time entity linking to the memory just written. It makes scheduled graph refresh do real work instead of a warning-only no-op. It is a direct runtime patch in `system-spec-kit` memory and causal-graph code paths. It uses no spec folder.

## What's New at a Glance

- **Entity linking now follows the saved memory.** Instead of rescanning the full cross-document entity graph on every save, the incremental path does less. It resolves the saved memory's entities. It expands them through aliases. Then it finds only matching memories in other spec folders. It creates only those cross-document edges. So normal save-time work stays bounded to the changed memory. The full linker stays as a broad fallback.
- **Scheduled refresh now runs its callback.** Scheduled refresh could queue work but log that no refresh function was registered. The MCP server now registers a global refresh function at startup. That function recomputes the dirty-node set against the live database. It clears dirty markers after success. It logs the applied refresh with dirty-node and updated-edge counts.

## Upgrade

No migration required. This patch is runtime-only. It is backward compatible.
