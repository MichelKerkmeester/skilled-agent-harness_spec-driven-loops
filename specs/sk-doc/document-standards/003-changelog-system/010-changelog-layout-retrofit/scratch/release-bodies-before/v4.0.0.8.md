## Why This Release

A fresh clone used to stop short of a working request. The README did not build the spec-kit workspace. The session hooks and the agent mirror check load that workspace. A clone without that build saw the gap reported as mirror drift. That report blocked the commit.

A misspelled option used to be ignored. So a run went on with its defaults. In `create.sh` an option such as `--goal` could become part of a new folder's title. The run still exited 0.

Hooks that read input could hold a tool call open. They held it until the host killed them. The Pi guard could not see a dispatch hidden inside a shell wrapper. The packet tools also used to write through symbolic links. They did not refuse them.

&nbsp;

## What's New at a Glance

- **A fresh clone reaches a working request.** The README names Node 24. That is the one version every part accepts. It adds the build step that the session hooks and the agent mirror check load.
- **Missing builds say so.** Pi names the folder it checked and the build to run. The mirror check reports NOT CHECKABLE and skips. It no longer blocks the commit.
- **Scripts refuse unknown options.** A misspelled option used to be ignored. It could also be folded into a new folder's title. Now the script names it and exits with its usage code.
- **Healer inputs are checked.** A missing path, an unknown flag or a folder outside every repository now stops a healer with exit 2.
- **Packet tools refuse symbolic links.** Archive, restore, heal, upgrade and repair no longer write through a link. A linked argument is refused before any write.
- **Hooks stop waiting for input.** A hook reads until its input ends or three seconds pass. So a host that never closes its input can no longer hold a tool call open.
- **The Pi guard reads wrapped dispatches.** A CLI dispatch inside a shell wrapper no longer slips past. A harmless `mkdir` command is no longer denied.
- **Launched sessions keep their settings.** A launched session now carries its own marker. It keeps your `SYSTEM_SPEC_GATE_ENFORCE` value. It gives `0` only to a dispatched child.

## Install and First Use

#### Install Steps Reach a Working Request

The README now asks for Node 24. That is the one version every part accepts. Code Mode's server needs Node 24. The spec-kit CLI needs 22.12 or newer. The advisor needs 20.19 or newer. A new step builds the spec-kit workspace. The session hooks and the agent mirror check load that workspace. The advisor build step says to run it after the dependency install. That is because it compiles against the types that install brings. A last step sets `skilled.trustRepoHooks`. So a second clone on the same machine runs its pre-commit checks. First Use names all seven runtimes. It names how each one spells `/speckit:complete`.

#### Missing Builds Say So

Pi warns at session start when the built session-prime adapter is missing. It names the folder it checked and the build to run. The Codex hook drift message names the build as well. sk-vision documents its Bun setup.

#### The Mirror Check Skips When It Cannot Run

`check-agent-mirror-sync.cjs` exits 3 with NOT CHECKABLE when its parser is missing. It does the same when the parser fails to load. Both pre-commit hooks then warn and skip the mirror check. Before, a clone without that build saw the gap reported as mirror drift. The commit was blocked.

## Script Options

#### create.sh Refuses Unknown Options

A misspelled option such as `--goal` used to become part of the new folder's title. `--with-goal` was meant. The run still exited 0. `create.sh` now stops on any option it does not know. It prints `Error: unknown option`, points to `--help` and exits 1. It does this before it writes anything. A lone `-` counts as an unknown option too.

#### Every Script Refuses Unknown Options

The same check now covers scripts across the skills. They are the spec-kit CLI, the skill advisor, the deep loop, sk-doc, sk-code, sk-design, sk-git and the shared `.skilled/bin` tools. A misspelled option such as `--modell` used to be ignored. So the run went on with its defaults. Each script now names the unknown option and exits with its usage code. That code is 2 for most. A script that already had a usage code keeps it. One example is 64 for `frontmatter-version.mjs`. The deep-loop scripts keep their JSON error with exit 3. Three scripts that reported a problem and still exited 0 now fail. `worktree-naming.sh create` exits 3 when provisioning fails. `migrate-legacy-branch-names.sh` exits 1 when a dry run skips a taken name. `check-comment-hygiene.sh` exits 3 on a file it cannot read. `create.sh --help` now lists `--path`.

#### Healer Inputs Are Checked

Every healer mode now rejects an unknown flag with exit 2. A nonexistent `--folder` or `--roots` path also exits 2. It names the path. Without `--roots <dir>`, the healer exits 2 for a folder outside every repository. A plain folder outside the supplied specs root now gets an outside-root message. A linked parent keeps the symbolic-link wording.

`heal-spec-docs` also reports a linked `spec.md` as refused. It does this when it reads the packet level. That finding keeps the existing exit 0 for linked-document refusals.

## Symlink Safety

#### Symlinks Are Refused, Not Followed

Archive, restore, heal, upgrade and repair refuse a packet document that is a symlink. They also refuse an archive folder that is a symlink. They do not write through it. An archive folder that resolves outside `specs/` is refused before anything is created through it. So is a path with a `.` or `..` segment. A dangling link counts as an existing target and is refused. `heal-spec-docs` reports a symlinked document as a symbolic link it did not follow. Its default write is atomic.

The upgrade apply guards each move. A packet whose top-level link resolves outside it is refused before any write. A linked `upgrade-baseline.json` is no longer read. The validator reports that case with the `UPGRADE_BASELINE_LINK` warning. The leaf manifest generator confines each start scope to the skill. It does this before it reads a directory. The description and graph metadata loaders refuse linked files. The prune report refuses a linked target. It writes through an exclusive temporary name.

#### A Linked Packet Argument Is Refused Before Any Write

`heal-spec-docs` refuses a `--folder` that is a link. It also refuses one that sits under a link in the specs root. It also refuses one that resolves outside it. It prints that the link was not followed. It writes nothing and exits with status 2 in every mode. `repair-derived` leaves a linked `graph-metadata.json` alone. It reports why. So its dry run and its apply agree. `generate-leaf-manifest --write` refuses a linked `leaf-manifest.json`. It writes through a random temporary file and a rename.

#### Linked Paths Stay Packet-Local

Archive and restore now reject any linked path argument with exit 1. They do this before they copy or move a packet. The message names the real folder. `generate-leaf-manifest --check` rejects linked or dangling `leaf-manifest.json` files with exit 2. `upgrade-legacy` rejects a linked reversibility manifest with exit 2. That manifest is `upgrade-legacy.manifest.json` in the git directory. It also rejects a `--roots` path containing `..` with exit 2.

Graph metadata readers follow links that resolve inside a packet. A linked folder on the way to a document is judged by its real path too. One example is a `research/` folder. When a link leaves the packet or dangles, `readDoc` reports its document as unknown. Source hashing skips the document. A required `repair-derived` step exits 2.

#### Backfill Roots Stay in Scope

`backfill-graph-metadata --root` now requires the target to stay inside the repository. That repository is resolved from the working directory. A prune report also needs a `.opencode`-anchored root. Both checks refuse before metadata or a report is written.

## Hooks and Sessions

#### Hooks Stop Waiting for Input

Hooks that read stdin now stop waiting after a deadline. That covers the shared hooks and the spec-kit runtime hooks. It also covers the sk-git message gate and preflight advisory and the Devin vision hook. A hook reads until its input ends or 3 seconds pass. Then it answers with what it has. So a host that never closes stdin no longer holds a tool call until it kills the hook. The spec-kit readers also cap input at 1 MB. Seven spec-kit entries have a host that stops them at 3 seconds. Those entries wait only 500 ms. A payload written after that is dropped. So the hook answers as if it had no input.

#### The Pi Guard Reads Wrapped Dispatches

The dispatch inspector now reads the payload of a `bash`, `sh`, `zsh` or `dash` `-c` wrapper. That includes escaped quotes and later wrappers. So a CLI dispatch inside a wrapper no longer slips past the Pi guard. A variable counts as an executor only in command position. So `mkdir -p "$DIR"` is no longer denied. When the guard denies an ambiguous command, its message says what passes. One executor named by its own name in the user request passes. A name given through a variable or alias does not.

#### Launched Sessions Keep Their Settings

The launcher now exports `SKILLED_WORKTREE_SESSION=1` for launched sessions. `AI_SESSION_CHILD=1` remains the marker for dispatched children. Hermes repo guards treat `AI_SESSION_CHILD=1` alone as the child marker. Launched and in-worktree sessions preserve the operator's `SYSTEM_SPEC_GATE_ENFORCE` value. Only dispatched children receive `0`.

#### Child Workers Follow One Gate 3 Rule

A session can be a child worker, marked by `AI_SESSION_CHILD=1`. Then Gate 3 is pre-resolved before the worker starts. Inside its lineage directory the worker records a halt. It continues rather than stopping. The `speckit:plan`, `speckit:implement` and `speckit:complete` commands each define this rule under a `child_dispatch` key. The system-spec-kit skill and its Hermes copy state the same text.

#### Doctor Env Reads the Legacy Tables

`ENV-REFERENCE.md` listed `SYSTEM_SPEC_GATE_DISABLED` twice. The second row had a different default and type. So `/doctor:env` stopped on the file. The two rows now agree. The env parser accepts the legacy label rows. It reads boolean polarity. It treats a row with the wrong cell as malformed.

## Upgrade Notes

- **Build the spec-kit workspace after you pull.** Run `npm --prefix .skilled/skills/system-spec-kit run build`. The session hooks and the agent mirror check load that build. Without it they warn and skip.
- **Run Node.js 24 for a full install.** It is the one version every part of the install accepts.
- **Fix calls that pass unknown options.** A script or alias that passes an option a script does not know now stops with a usage error. That is exit 1 for `create.sh` and exit 2 for most other scripts. Use `--with-goal` to add a goal with `create.sh`. Run any script with `--help` for its options.
- **Use real paths, not links, with the packet tools.** Archive and restore refuse a linked argument with exit 1. The `leaf-manifest.json` check and `upgrade-legacy` refuse a linked manifest with exit 2. Keep `upgrade-legacy --roots` values free of `..`. Keep a backfill `--root` inside the working repository. Pass `--roots <dir>` when a healer `--folder` sits outside every repository.
- **Check scripts that read the launcher marker.** Launched sessions set `SKILLED_WORKTREE_SESSION=1` in place of `AI_SESSION_CHILD=1`. That marker now marks only a dispatched child. They keep your `SYSTEM_SPEC_GATE_ENFORCE` value. Only a dispatched child receives `0`.
