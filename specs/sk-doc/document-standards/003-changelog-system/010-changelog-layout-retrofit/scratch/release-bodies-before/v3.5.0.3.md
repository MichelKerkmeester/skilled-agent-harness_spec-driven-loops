This release rewrites the skill READMEs into one narrative voice. It is the same warm, problem-first voice the repo root README and these changelogs use. The release also updates the sk-doc template. New skills start there. The rewrites were grounded in each skill's real files, not invented. The context gather behind them caught real drift along the way. That drift ran from a wrong MCP integration recipe to a stale embedder claim. Every fix landed in the rewrite.

> Spec folder: `.opencode/specs/skilled-agent-orchestration/135-skill-readme-standardization/`

## Why This Release

The repo root README and these changelogs read in one voice. They open with a problem and show an at-a-glance table near the top. They name sections for outcomes and use sparse tables. They close with a verification. But the skill READMEs had drifted apart. Each one was a tabular reference card with no human entry point. Each led with an Overview or a feature inventory. Each hid its key facts in a Key Statistics block. Each named its sections for their function, not the reader's goal. They ranged from 228 to 1084 lines. So a reader moving between skills re-learned the layout every time. New skills inherited the old shape. That is because the sk-doc template still encoded it.

## What's New at a Glance

- **The 22 skill READMEs now open the same way.** Each starts with a frontmatter block, an H1 and a one-line pitch. Then comes an At a Glance table, as Section 1. A reader scans it in five seconds. Then an Overview that states the problem before the solution, as Section 2. The reference detail is kept below.
- **Later sections follow as each skill needs them.** These are Quick Start, How It Works, Integration, Troubleshooting, FAQ and Related Documents. They appear where they fit. Prose carries the explanation. Tables appear only for genuine lookups.
- **Every README follows the same voice rules.** None carries em dashes or double-hyphen separators. None carries semicolons, Oxford-comma lists or filler words.
- **The sk-doc skill-README template was updated to match.** It now encodes the narrative skeleton. It also encodes the writing and validation rules.
- **The system-spec-kit README was restyled in place, not compressed. It stays a complete reference manual.** It is the largest README in the repo. It carries dense reference content. That runs from the 37 memory tools and the five-channel search pipeline. It also covers the index schema history and the environment table. Regenerating that body would have risked dropping or paraphrasing facts. So the restyle reframed the top. It swept the house voice through the existing text. It kept every reference block.
- **Two models drafted each README from a verified map of the skill.** A two-iteration, read-only context gather read the SKILL.md, the code and the references. It mapped the skill's tools, modes, key files and boundaries. Then DeepSeek v4 Pro and MiMo v2.5 Pro each drafted from that map. Each draft followed the locked template and the golden example. The orchestrator merged the stronger draft. It grafted in the best parts of the other. It applied the voice rules and verified the result against source. So the documented facts match the code. Nothing shipped on a model's word alone.
- **Stale claims that had outlived the code were corrected in the same pass.** An MCP integration recipe pointed at the wrong tool namespace and config key. A code skill listed a surface that no longer existed. A scorer README described a single shipped embedder. The shared registry now holds several. Version footers, tool counts and script counts had fallen behind their source. Each correction shipped with the README it belonged to.

## Upgrade

No migration required. This release is documentation only and makes no API changes. No SKILL.md, code or behavior changed. So nothing needs a rebuild or a restart.

- **New skills inherit the voice.** Author a new skill README from the updated sk-doc template. It lands in the narrative shape by default.
- **The skills index is the closing step.** The `.opencode/skills/README.md` catalog is the final piece of the standardization. It ships as the last phase of the packet.
