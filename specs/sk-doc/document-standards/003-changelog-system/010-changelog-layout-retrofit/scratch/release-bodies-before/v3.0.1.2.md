Merged the standalone `/spec_kit:phase` command into `/spec_kit:plan` and `/spec_kit:complete` as an optional `:with-phases` flag, reducing the old three-command flow to a single invocation. This update adds **3 setup questions**, a **4-step phase decomposition pre-workflow**, and refreshed command mirrors for phased spec creation.


---

## What Changed

#### Commands

- **What was broken**: Phase decomposition lived in a separate `/spec_kit:phase` command, so users had to chain commands to create phased specs and then start planning or completion.
- **`:with-phases` integrated into plan and complete**: Added the optional workflow flag to both commands so phase decomposition and planning can run in one command instead of three.
- **Unified setup flow expanded**: Added Q6 (Phase Decomposition), Q7 (Phase Count), and Q8 (Phase Names), and replaced the complete command’s previous inline setup protocol with a full Unified Setup Phase.
- **TOML mirrors regenerated**: Regenerated `plan.toml` and `complete.toml` from their updated Markdown sources so the new phased workflow is reflected in mirrored command definitions.


#### Architecture

- **Phase decomposition workflow standardized**: Added a `phase_decomposition` block to `optional_workflows` in all 4 YAML assets for plan auto/confirm and complete auto/confirm, following the existing `:with-research` pattern.
- **Standalone phase command removed**: Deleted `phase.md`, `spec_kit_phase_auto.yaml`, and `spec_kit_phase_confirm.yaml`, and updated 23 supporting files across agents, templates, nodes, feature catalog, testing playbook, `AGENTS.md`, and install guides to reference `:with-phases` instead.

## Upgrade

No migration required. The `:with-phases` flag is optional and backward-compatible. Existing workflows without it are unaffected. Phase folder infrastructure (`create.sh --phase`, addendum templates, `validate.sh --recursive`) is unchanged.
