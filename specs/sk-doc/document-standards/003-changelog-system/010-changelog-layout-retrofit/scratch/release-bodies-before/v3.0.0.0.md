## Memory Search

The program first defined the overall architecture. It made the 5-channel, 4-stage pipeline the single production search path. That replaced earlier isolated experiments.

#### Five Channels Search at Once

- **Vector search** converts your query into a mathematical representation. It finds memories with similar meaning, even when they use different words. It supports multiple embedding providers: Voyage, OpenAI and HuggingFace.
- **Full-text search (FTS5)** is SQLite's built-in search. It matches exact phrases and word combinations.
- **Keyword search (BM25)** is a ranking algorithm. It scores results by how important your search terms are within each document.
- **Causal graph traversal** follows cause-and-effect links between memories, for example "this decision led to that implementation".
- **Graph importance scoring** ranks memories by how connected they are to other memories. Limits keep overly connected "hub" memories from dominating results.

A minimum representation is enforced for each search channel.

&nbsp;

#### Four Stages From Candidates to Results

- **Gather** runs all channels in parallel. It injects "constitutional" memories, always-relevant rules that should appear in every search. This stage also carries expansion guards.
- **Score and Fuse** combines results using ranked fusion plus 8 additional scoring signals. Ranked fusion merges ranked lists fairly. The signals include how recently a memory was accessed. They include how related memories reinforce each other. They include how well a result matches what the system thinks you are trying to do. This stage also carries graph calibration.
- **Rerank** optionally re-scores the top results using a local AI model for higher accuracy.
- **Filter** applies the final checks. It removes results below a confidence threshold. It respects memory lifecycle states such as active and archived. It makes sure scores from earlier stages are not silently changed.

The fallback starts with simpler search methods and progresses to broader queries.

&nbsp;

#### Retrieval Becomes Pressure-Aware and Measurable

Retrieval is now pressure-aware. A new shadow evaluation runtime measures retrieval. The retry path was improved. The search code received fusion cleanup, fallback wiring and orchestration work.

## Saving and Sharing Memory

#### A Full Manager for Constitutional Rules

Before this release, `/memory:learn` was a simple "create a rule" tool. Constitutional memories get a 3x search boost. They never decay over time.

&nbsp;

#### One Index Entry and Automatic Upkeep

The same document could be indexed multiple times under different paths. It could be broken into overlapping sections. The file watcher for indexing and refresh was updated as well.

After any memory change, cache invalidation, hooks and safety checks now happen automatically. A memory change is a save, update, delete or checkpoint. Cache invalidation, hooks and safety checks used to be scattered across different code paths.

&nbsp;

#### Saves Pass Stricter Checks

Alongside prediction-error gating, the save pipeline now runs structural validation. It also runs semantic sufficiency checks and duplicate detection. The save flow gained fixes and governance. Structural and semantic validation were fixed as well.

&nbsp;

#### Shared Spaces Deny Access by Default

A server-owned admin identity handles administrative operations on shared memory spaces. Multi-tenant database operations were hardened as well. Checkpoints are scoped per tenant. Graph search results get proper composite scoring.

&nbsp;

#### Sessions Carry Less Redundant Content

Follow-up messages deduplicate roughly 50% of redundant content. Anchor-based retrieval can reduce payload sizes by about 93%.

The spec folder hierarchy was repaired as part of the same work. Session continuity and working-memory behavior were updated too.

## Upgrade Notes

- Pull the latest changes and restart MCP services.
- Review your embedding provider configuration (Voyage, OpenAI or HuggingFace). Review any shared-memory admin identity environment variables too.
- Run `npm test` in the memory server to verify the release baseline. The target is 4,500+ tests passing.
- No database migration is required. Before treating this as a routine update, familiarize yourself with the new search pipeline. Learn the fallback behavior and the deny-by-default shared memory model too.
