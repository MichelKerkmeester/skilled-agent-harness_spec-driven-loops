Implements **all 6 follow-on recommendations** from the Codex MCP startup fix and adds **20 new tests** covering database integrity, shutdown lifecycle, fail-open behavior, and error sanitization. This pass hardens credential handling in error responses, removes cleanup side effects, and aligns the supporting documentation and verification work.


---

## What Changed

#### Error responses now sanitize credentials recursively

**What was broken:** Error responses could include sensitive credential patterns in nested objects and arrays, and self-referential payloads could trigger stack overflows while being processed.

**How this fixes it:** `buildErrorResponse()` now strips `sk-*`, `voy_*`, Bearer tokens, and `key=` patterns recursively, including nested objects and arrays. It also guards against circular references, treats Bearer matches case-insensitively, and covers hyphenated `sk-proj-*` keys.


#### Shutdown cleanup no longer leaks side effects into logging paths

**What was broken:** Cleanup and shutdown handling still depended on helper behavior that could introduce side effects into logging and error-cleanup paths.

**How this fixes it:** Shutdown logging now uses `get_error_message()` via an extracted module, keeping the cleanup helpers side-effect-free while preserving the existing shutdown behavior.


#### Regression coverage now matches the hardening work

**What was broken:** The startup-fix follow-on work needed targeted regression coverage across the database, lifecycle, fail-open, and sanitization surfaces so the hardening would stay verified.

**How this fixes it:** The release adds **20 new tests**: 5 database embedding-dimension integrity tests, 4 lifecycle shutdown tests, 3 stage2b fail-open extension tests, and 8 error sanitization tests.


#### Documentation and validation now reflect the new hardening rules

**What was broken:** The supporting documentation and validation artifacts did not fully capture the credential-stripping guidance, transport guidance, and troubleshooting introduced by this hardening pass.

**How this fixes it:** The release adds a feature catalog entry for credential sanitization, a manual testing playbook scenario for stripping verification, Codex `MEMORY_DB_PATH` plus clean-transport guidance across 6 documentation surfaces, install-guide troubleshooting for Codex MCP startup failure, and an updated `descriptions.json` index.


#### Verification confirms the follow-on recommendations are complete

**What was broken:** The startup-fix follow-on set still needed an end-to-end verification pass to confirm the recommendations were fully implemented and preserved in the built output.

**How this fixes it:** Two GPT-5.4 review rounds resolved all P1 findings. All **20/20** new tests pass, **8631/8632** core tests pass with **1 pre-existing unrelated timeout**, the spec folder validates **19/19** checks with **0 errors** and **0 warnings**, and `dist/` was rebuilt and verified against the built module.
