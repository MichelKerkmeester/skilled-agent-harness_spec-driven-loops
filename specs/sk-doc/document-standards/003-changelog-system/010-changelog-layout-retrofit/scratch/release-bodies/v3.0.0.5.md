# Credential Sanitization and Cleanup Hardening

This release hardens how error responses handle credentials.

- Implements all 6 follow-on recommendations from the Codex MCP startup fix.
- Error responses now strip credential patterns recursively.
- Sensitive patterns in nested data are removed.

Cleanup work removes side effects and adds regression tests.

- Cleanup side effects are removed from logging paths.
- 20 new tests cover the hardening work.
- Tests cover database integrity, shutdown lifecycle, fail-open behavior and error sanitization.

Documentation and verification catch up with the hardening work.

- Supporting documentation and verification work are aligned.
- Verification covers all 6 follow-on recommendations.

&nbsp;

## Why This Release

The Codex MCP startup fix left follow-on work open.

- Error responses could include sensitive credential patterns in nested objects and arrays.
- Self-referential payloads could trigger stack overflows while being processed.
- Cleanup and shutdown helpers could introduce side effects into logging and error-cleanup paths.
- The startup-fix follow-on work needed targeted coverage across the database, lifecycle, fail-open and sanitization surfaces.
- Documentation and validation missed credential-stripping guidance, transport guidance and troubleshooting.
- The follow-on set still needed an end-to-end verification pass.

## Error Handling

This area covers how failed requests are reported to callers.

#### Error Responses Now Sanitize Credentials Recursively <a id="c-error-responses-now-sanitize-credentials-recursively"></a>

- Error responses could include sensitive credential patterns in nested objects and arrays.
- Self-referential payloads could trigger stack overflows while being processed.
- `buildErrorResponse()` now strips `sk-*`, `voy_*`, Bearer tokens and `key=` patterns recursively.
- The stripping includes nested objects and arrays.
- It also guards against circular references.
- Bearer matches are treated case-insensitively.
- Hyphenated `sk-proj-*` keys are covered.

&nbsp;

## Shutdown and Cleanup

This area covers what happens when the server shuts down and cleans up.

#### Shutdown Cleanup No Longer Leaks Side Effects Into Logging Paths <a id="c-shutdown-cleanup-no-longer-leaks-side-effects-into-logging-paths"></a>

- Cleanup and shutdown handling still depended on helper behavior.
- The helpers could introduce side effects into logging and error-cleanup paths.
- Shutdown logging now uses `get_error_message()` via an extracted module.
- Cleanup helpers stay side-effect-free.
- The existing shutdown behavior is preserved.
