# v2.7.0.0, Phases Move Into Plan and Complete

The standalone phase command merged into two commands.

- It merged into `/spec_kit:plan` and `/spec_kit:complete`.
- The merge uses an optional `:with-phases` flag.
- The old three-command flow becomes a single invocation.

The update adds setup questions and a decomposition workflow.

- It adds 3 setup questions.
- It adds a 4-step phase decomposition pre-workflow.
- It also refreshed command mirrors for phased spec creation.

## What Changed

Both commands absorb the old phase command. The workflow uses an existing pattern.

#### Commands <a id="c-commands"></a>

- Phase decomposition lived in a separate `/spec_kit:phase` command.
- So users had to chain commands to create phased specs and then start planning or completion.
- The optional workflow flag was added to both commands.
- Phase decomposition and planning can run in one command instead of three.
- Q6 (Phase Decomposition), Q7 (Phase Count) and Q8 (Phase Names) were added.
- The complete command's previous inline setup protocol became a full Unified Setup Phase.
- `plan.toml` and `complete.toml` were regenerated from their updated Markdown sources.
- So the new phased workflow is reflected in mirrored command definitions.

#### Architecture <a id="c-architecture"></a>

- A `phase_decomposition` block was added to `optional_workflows`.
- It was added to all 4 YAML assets.
- The assets cover plan auto/confirm and complete auto/confirm.
- The block follows the existing `:with-research` pattern.

#### Standalone Command Removed <a id="c-standalone-command-removed"></a>

- `phase.md`, `spec_kit_phase_auto.yaml` and `spec_kit_phase_confirm.yaml` were deleted.
- 23 supporting files were updated.
- They span agents, templates, nodes, feature catalog, testing playbook, `AGENTS.md` and install guides.
- They were updated to reference `:with-phases` instead.

## Upgrade

No migration is required.

#### No Migration Needed <a id="c-no-migration-needed"></a>

- The `:with-phases` flag is optional and backward-compatible.
- Existing workflows without it are unaffected.
- Phase folder infrastructure is unchanged.
- It includes `create.sh --phase`, addendum templates and `validate.sh --recursive`.
