# OpenCode Environment Architecture Update

This release updates the OpenCode environment with a structured config files-first refactoring.

- The work also covers new architecture sections and bug fixes.
- `.md` files become routing documents.
- `_confirm.yaml` is interactive with checkpoints.
- `_auto.yaml` runs autonomously with no prompts.

New architecture sections fix rough edges and make the environment more dependable.

- `Workflow_enforcement` adds strict sequential mode with phase gates.
- `Circuit_breaker` uses a 3-failure threshold.
- `Circuit_breaker` has closed, open and half-open states.
- `Error_recovery` adds failure handlers.

Step count metadata is fixed in 3 YAMLs.

- The change moves sequential_5_step to sequential_6_step.
- The fix makes written guidance easier to follow and trust.

## Command Configuration

This area covers how the environment saves, finds and uses context. This release refactors the `.md` files into routing documents.

#### Structured Config Files First <a id="c-structured-config-files-first"></a>

- `.md` files are refactored into routing documents.
- The chain runs `EXECUTION PROTOCOL` banner → Phase 0 (@write verification) → `Unified Setup Phase` → structured config files loading → `Reference context`.
- Each command now has `_confirm.yaml` and `_auto.yaml` modes.
- `_confirm.yaml` is interactive with checkpoints.
- `_auto.yaml` is autonomous with no prompts.
- `Agent.md` was a 670-line inline workflow with an orphaned structured config files file.
- It is now a proper structured config files-first architecture with both mode files built from scratch.
- That matters because saved context is easier to find, easier to trust and less likely to get in the way.

&nbsp;

## Workflow Reliability

This area covers how workflows run and recover from failures. The release adds enforcement, a breaker and error recovery.

#### New Architecture Sections <a id="c-new-architecture-sections"></a>

- `Workflow_enforcement` adds strict sequential mode with phase gates.
- `Circuit_breaker` uses a 3-failure threshold.
- `Circuit_breaker` has closed, open and half-open states.
- `Error_recovery` adds handlers for `template_not_found`, `validation_failure`, `file_write_failure` and `user_rejects_approach`.
- That matters because the environment is easier to maintain and less likely to break in everyday use.

&nbsp;

## Command Metadata

This area covers step count metadata in create commands. The release corrects the metadata in 3 YAMLs.

#### Step Count Metadata Fixed <a id="c-step-count-metadata-fixed"></a>

- The 3 YAMLs are `create_install_guide`, `Create_skill_asset` and `Create_skill_reference`.
- The step values move from sequential_5_step to sequential_6_step.
- That matters because people can understand the system faster and use it more confidently.
