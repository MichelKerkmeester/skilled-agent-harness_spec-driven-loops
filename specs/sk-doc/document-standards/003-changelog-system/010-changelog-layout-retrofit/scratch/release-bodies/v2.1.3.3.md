# Clearer Memory Command Guidance

This release updates the OpenCode environment with three changes.

- It adds explicit scan scope to the retry example.
- It reduces operator ambiguity.
- It aligns memory command guidance.

The changes make context easier to find and guidance easier to trust.

- That matters because saved context is easier to find and easier to trust.
- That matters because saved context is less likely to get in the way.
- That matters because people can understand the system faster and use it more confidently.

## Memory Context and Guidance

These changes touch memory commands, saved context and operator guidance.

#### Explicit Scan Scope In Retry Example <a id="c-explicit-scan-scope-in-retry-example"></a>

- It updates the `/memory:save` full-folder retry snippet.
- The snippet passes `includeSkillRefs: true`.
- This matches new `workflows-code` indexing behavior.

#### Reduced Operator Ambiguity <a id="c-reduced-operator-ambiguity"></a>

- It prevents false-negative expectations.
- It applies when validating `skillRefFiles`.
- That happens after restart and re-scan.

#### Memory Command Alignment <a id="c-memory-command-alignment"></a>

- The `/memory:save` docs now match `/memory:manage`.
- They match on scan source-scope semantics.
- This covers `skill references/` and `assets/` indexing.
