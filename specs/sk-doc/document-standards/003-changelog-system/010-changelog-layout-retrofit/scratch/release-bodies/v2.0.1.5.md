# OpenCode Environment Update

This release updates the OpenCode environment.

- Work covers structured config files-first architecture refactoring.
- It adds new architecture sections.
- It includes bug fixes.

The goal is a better platform.

- The platform should be clearer.
- It should be more reliable.
- It should be easier to use day to day.

The release closes gaps in context handling, reliability and written guidance.

- It improves how the environment saves, finds and uses context.

## Config Architecture

The environment now uses structured config files first.

#### Config Files Become Routing Documents <a id="c-config-files-become-routing-documents"></a>

- This part of the release improves how the environment saves, finds and uses context.
- `.md` files become routing documents.
- The order: EXECUTION PROTOCOL banner → Phase 0 (@write verification) → Unified Setup Phase → structured config files loading → Reference context.
- Each command now has `_confirm.yaml`, interactive with checkpoints.
- Each command now has `_auto.yaml`, autonomous with no prompts.
- `Agent.md` was a 670-line inline workflow.
- It had an orphaned structured config files file.
- It is now a proper structured config files-first architecture.
- Both mode files were built from scratch.
- That matters because saved context is easier to find.
- Saved context is easier to trust.
- Saved context is less likely to get in the way.

&nbsp;

## Reliability Sections

New sections make the environment more dependable.

#### New Architecture Guards <a id="c-new-architecture-guards"></a>

- This part of the release fixes rough edges.
- It makes the environment more dependable.
- Workflow_enforcement: strict sequential mode with phase gates.
- Circuit_breaker: 3-failure threshold with closed/open/half-open states.
- Error_recovery: handlers for template_not_found, validation_failure, file_write_failure, user_rejects_approach.
- That matters because the environment is easier to maintain.
- It is less likely to break in everyday use.

&nbsp;

## Command Metadata

Written guidance is easier to follow and trust.

#### Step Count Metadata Corrected <a id="c-step-count-metadata-corrected"></a>

- This part of the release makes written guidance easier to follow.
- It makes written guidance easier to trust.
- Step count metadata was fixed in 3 YAMLs.
- The YAMLs are create_install_guide, Create_skill_asset and Create_skill_reference.
- sequential_5_step → sequential_6_step.
- That matters because people can understand the system faster.
- People can use it more confidently.
