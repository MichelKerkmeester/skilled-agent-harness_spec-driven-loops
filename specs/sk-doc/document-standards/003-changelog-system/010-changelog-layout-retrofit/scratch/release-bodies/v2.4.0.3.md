# Memory Export Importance Tier Conflict Resolved

This release updates the OpenCode environment.

- It resolves a memory export importance tier conflict.
- It includes a backward-compatible resolution.

These changes improve how the environment saves, finds and uses context.

- Saved context is easier to find and easier to trust.
- Saved context is less likely to get in the way.

&nbsp;

## Why This Release

The goal is to make the platform clearer, more reliable and easier to use day to day.

- Template output had two conflicting importance tier values.
- Existing memory files have dual fields.

## Memory and Context

This area covers how the environment saves, finds and uses context.

#### Memory Export Importance Tier Conflict Resolved <a id="c-memory-export-importance-tier-conflict-resolved"></a>

- This part of the release improves how the environment saves, finds and uses context.
- The template had hardcoded `importance_tier: "normal"` alongside dynamic `importanceTier: "{{IMPORTANCE_TIER}}"`.
- This produced files with two conflicting values.
- Now it emits a single field.
- That matters because saved context is easier to find, easier to trust and less likely to get in the way.

#### Backward-compatible Resolution <a id="c-backward-compatible-resolution"></a>

- This part of the release improves how the environment saves, finds and uses context.
- Existing memory files with dual fields are handled correctly.
- It prefers the non-default value.
- That matters because saved context is easier to find, easier to trust and less likely to get in the way.
