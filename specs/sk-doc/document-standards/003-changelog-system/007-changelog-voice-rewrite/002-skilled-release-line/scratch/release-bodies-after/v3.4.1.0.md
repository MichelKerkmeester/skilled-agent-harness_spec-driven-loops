## Memory Continuity

The memory migration from v3.4.0.0 was only half complete in production. This release closes the remaining write paths. It corrects defects in save and search behavior.

#### Canonical writes and safer saves

Five legacy write paths to `[spec]/memory/*.md` are retired. Canonical spec documents are now the write surface. 183 stale memory-file rows from prior runs were pruned. 1,141 dependent causal edges that referenced them were pruned too. `/memory:save` now defaults to a planner-first, non-mutating dry run with full-auto fallback. Four ancillary subsystems previously fired on every save. They now run only when their opt-in environment flags are set.

Eight JSON-mode save defects are fixed. The corrections cover truncation boundaries and junk phrases in synthesized trigger phrases. They cover predecessor discovery for causal lineage and post-save verification. They also cover metadata drift after partial failures.

&nbsp;

#### Gates catch save drift

Six gates run before a save. They check spec-document structure, anchor parity and trigger-phrase sanity. They check canonical paths in `key-files`, status derivation and continuity-pointer integrity. A failing gate is surfaced instead of allowing a corrupt save.

&nbsp;

#### Search defects are catalogued

A 17-bug catalogue records memory-search runtime defects. Three P0 defects were fixed in this release. They are a truncation-wrapper sanity check and a confidence floor for the intent classifier. The classifier had been routing at 0.098 confidence in some traces. The third fix enforces against forbidden synthesized phrases. The other 14 P1/P2 defects are documented for follow-on remediation.

&nbsp;

#### The memory-indexer review

A deep-review of the memory-indexer packet returned a CONDITIONAL verdict. A live MCP rescan blocker (CHK-T15) gates the FINAL release. It gates it until verified on a freshly restarted daemon.

## The Code Graph

The code graph was missing 60 to 80 percent of the symbols in a codebase. Its production parser path was not running. This release restores parser-backed scans. It adds diagnostics, freshness details and more resilient query behavior.

#### Production scans recover symbols

The tree-sitter grammar path pointed to the source tree. It did not point to the compiled `dist/` location. So production silently used a regex fallback. Broad scans now return 56,843 nodes instead of the fallback's 5,000. That recovers roughly 11 times more symbols.

Broad-scan crash rate fell from 17.5% to 0.72%. That is a 24x improvement. A 9,314-file scan ran with zero B2 cascades. Whole-repo scans now complete reliably. The previous broad-scope failures are gone.

&nbsp;

#### One command checks graph health

`/doctor:code-graph` has `auto`, `confirm` and `apply` modes. Auto and confirm report parser status, scan freshness and scope coverage. They also report known stale areas, without changing data. Apply offers verification-gated repair. It runs a 28-query gold battery before and after each operation. It restores the last known-good snapshot when the post-flight battery fails. Its operations map to a three-procedure recovery playbook. The playbook covers SQLite corruption, partial-scan failure and bad-apply rollback. Exclude rules are tiered by high, medium and low confidence.

&nbsp;

#### Freshness and scope are visible

Code-graph responses now carry freshness status and highlight stale graphs. Default excludes skip `z-future/`, `z_archive/` and CocoIndex internal paths. They skip them unless explicitly requested. `.gitignore` entries are honored. Multi-file queries deduplicate results across files.

The code-graph package is now self-contained at `mcp-server/code-graph/`. Five hardening areas address scan idempotence and query timeouts. They address error recovery, diagnostic accuracy and test isolation.

&nbsp;

#### Hook results carry graph context

`CALLS` resolution now handles fully qualified names when symbol names collide. Blocked reads return a typed `BlockedResult` with an explicit reason. CocoIndex ranking fidelity is preserved through the response path. Startup payloads expose `graphQualitySummary` across the four runtime surfaces.

&nbsp;

#### Three production paths tightened

- **Indexer scope matches the plural roots.** `mcp-server/lib/utils/index-scope.ts` now aligns code-graph indexing to the plural roots. Those are `.opencode/skills/`, `.opencode/agents/` and `.opencode/commands/`. So newly-shipped files are picked up.
- **Layer coverage is complete.** `mcp-server/lib/architecture/layer-definitions.ts` adds `memory_retention_sweep` to the L4 mutation-tool registry.
- **Diagnostics move off the MCP channel.** `mcp-server/code_graph/lib/structural-indexer.ts` now logs through `console.error` instead of `console.info`. That keeps MCP stdio responses clean across runtime surfaces.

## Graph Impact and Trust

Eight packets shipped under graph impact and affordance uplift.

#### Edges explain their impact

Edges can carry `reason` and `step` metadata. `blast_radius` returns depth groups, risk levels, confidence filtering and ambiguity candidates. The result explains why files are implicated. It does not present a flat list.

&nbsp;

#### Memory results show their trust

&nbsp;

#### Affordances use existing routes

Tool and resource affordances now flow through existing scorer lanes after sanitization. They do not expand the graph vocabulary. This lets the advisor route on needs. One example is a skill requiring CocoIndex or writing to the spec folder.

#### License posture is recorded

Umbrella docs were updated to describe the shipped behavior. They span the root README, MCP server docs, install guide, feature catalogs and testing-playbook indexes.

## Skill Advisor

The advisor now has a native daemon runtime. It uses the routing dictionaries v3.4.0.0 cleaned up and the graph compiler it shipped. It also serves live prompt hooks and an MCP interface.

#### A daemon serves recommendations

A native daemon now backs the advisor. It has watcher-driven freshness and a single-writer lease. The lease prevents concurrent processes from corrupting the compiled graph. The previous Python script and OpenCode plugin paths still work. They route through compatibility shims to the native behavior. The new MCP tools are `advisor_recommend`, `advisor_status` and `advisor_validate`. The advisor is now a first-class tool, not a hook-only side effect.

&nbsp;

#### Live hooks fail open

`UserPromptSubmit` hooks in Claude, Copilot and Codex call `buildSkillAdvisorBrief(prompt, {runtime})`. They emit sanitized recommendations with freshness, confidence and uncertainty fields. Errors return `{}`. So an advisor failure does not block a prompt. A reference doc at `.opencode/skills/system-skill-advisor/hooks/skill-advisor-hook.md` documents the contract.

&nbsp;

#### Scoring and routing are aligned

The five-lane fusion scorer is now written in TypeScript. Family affinity and graph-derived transitive boosts flow through the scorer.

The smart router cleans up stale routes and validates the router statically in CI. It tunes `ON_DEMAND` keywords. It asks for disambiguation on `UNKNOWN` instead of silently falling back to a CLI. It keeps telemetry observe-only. Its OpenCode plugin `spec-kit-skill-advisor` uses the same producer and renderer as the hooks. The plugin keeps per-instance closure state. It does not share module state across plugin instances. It deduplicates in-flight bridge calls, so concurrent identical cache misses share one bridge call. It bounds payloads with cache LRU eviction. `ON_DEMAND` hit rate rose from 5.5% to 48.0%.

&nbsp;

#### Advisor setup has a command

`/doctor:skill-advisor` analyzes the current skill set. It optimizes advisor scoring tables and re-indexes the skill graph. A standards pass aligned metadata across 21 skill files. It closed routing inconsistencies that had accumulated as the advisor evolved.

The ambiguity detector now flags a candidate when either the score gap or the confidence gap is at most 0.05. Previously it used the score gap alone.

## Causal Graph Routing

The causal-edge graph holds 1,328 live edges. Before this release, the graph channel only ran for complex queries with more than eight terms. So it went unused on natural one-to-five-term queries.

#### Short queries reach the graph

The router now activates the graph channel for `find_decision` and `find_spec` intents at any tier. It also activates for entity-rich queries. Those name memory rows with three or more outgoing causal edges.

The override sits above the tier classifier. So telemetry tier assignments stay stable while the graph channel serves the newly eligible queries. `memory_health.data.routing.graphChannelInvocationRate` reports channel use over a 200-decision rolling buffer.

&nbsp;

#### The graph-channel override has an opt-out

`SPECKIT_GRAPH_CHANNEL_PRESERVATION` is on by default and allows opt-out. Routing latency stays under 5 ms at p99. Live runs show graph-channel invocation at 0.625 after the new gates take traffic. That is well above the 0.30 floor.

## Spec Authoring

The old Level 1, Level 2, Level 3 and Level 3+ taxonomy combined line count, capability set and template shape. It put them into one flat dimension. That dimension did not scale to phase parents, audit packets or research-only packets. The new manifest separates those concerns. It provides a shared source for scaffolding and validation.

#### A manifest replaces the flat taxonomy

The Level 1/2/3/3+ taxonomy is being retired. A C+F hybrid manifest-driven framework puts capabilities and presets in `spec-kit-docs.json`. Both scaffolders and validators read it. The PARTIAL backward-compat framing was rejected. Five ADRs formalize the decisions.

The framework distinguishes human-authored scaffold documents from command- or agent-owned lazy add-ons. The implementation plan has four phases. They are adding the manifest and resolver (shipped), modifying the scaffolder, modifying the validators and deleting the legacy taxonomy code. The validator stays inclusive of legacy phase parents during the transition. 86 source files collapse into roughly 15 manifest files in the new design.

&nbsp;

#### Authoring references match current behavior

The sweep updated stale references in `SKILL.md` and skill-bundled assets. It also added brief coverage of `SPECKIT_POST_VALIDATE`, exit codes, path hardening and save locking. It covered batch inline rendering and phase-mode syntax.

Three more sweeps ran in parallel. They covered command markdown and YAML alignment. They validated `SPECKIT_LEVEL` and `SPECKIT_TEMPLATE_SOURCE` markers fleet-wide. A separate sweep covered the `z_archive/` corpus.

## CocoIndex Daemon Resilience

The `mcp-coco-index` daemon leaked processes and log volume under load. Disconnect handling, concurrent starts and shutdown now have bounded behavior.

#### Disconnects no longer spiral

Stale daemons had held 244 open file descriptors. Client disconnects caused CPU spikes of about 90% while tracebacks were formatted. Broken-pipe handling now lets the daemon survive client disconnects. It no longer crashes the writer again.

&nbsp;

#### Logs have a fixed ceiling

Logs are limited to 10 MB per file with five backups, for 60 MB total. A logging double-write was also fixed. Each line is not written through both stream and file handlers unless the stream is a TTY.

&nbsp;

#### Concurrent starts converge

Concurrent starts now use an atomic PID-file lock on POSIX and Win32. Sibling detection runs inside the lock before the PID is written. The listener backlog rose from the standard-library default of 1 to 128. So 16-way client storms queue at the OS level instead of failing with connection-refused.

Shutdown now has a 10-second task-join limit. One recovery procedure covers a half-stuck daemon, a fully stuck daemon or duplicate daemons.

## Multi-AI Council

The Multi-AI Council now has an explicit output protocol, state contract and artifact boundary. Its runtime artifacts can be checked without turning the advisory checker into a blocking gate.

#### Council outputs have a contract

The agent now documents the output protocol, invocation contract, state schema and convergence signal. It documents the caller-persistence protocol and summary. Four shared references under `system-spec-kit/references/ai-council/` cover folder layout and seat-diversity patterns. They cover convergence signals and JSONL state format.

The v1.1 state metadata adds `schema_version`, `protocol` and `producer` fields. It remains readable by v1 readers. `--memory-save-payload-out` writes a memory-save payload only when requested.

&nbsp;

#### Completion advice stays advisory

`advise-council-completion.cjs` reports missing artifacts, missing reports and seat-count mismatches. It always exits 0. So it can run in pre-commit hooks without gating strict validation.

&nbsp;

#### Writes stay inside council artifacts

The council writes to its own `ai-council/**` artifact tree. Permission across the three runtime mirrors is `write: allow / edit: allow` and `bash: deny / patch: deny`. The writer rejects an out-of-bounds target with `OUT_OF_SCOPE_WRITE`.

The audit trail adds `artifact_written` and `rollback` event types in v1.2. v1 readers continue to parse v1.2 files. A round-NNN folder is the rollback unit. On a seat error or convergence failure, that round's artifacts move to `failed/round-NNN-<timestamp>/`. The audit trail marks them with `superseded_by: "rollback"`. Three ADRs document the write-permission model, the audit-trail schema and the rollback semantics.

Soft-target validation now sets limits of 130 characters for skill descriptions and 110 for command descriptions. Updated sk-doc authoring docs declare a hard cap of 1,536 characters and a project soft ceiling of 5,600 characters. The checks are wired into `/create:sk-skill` and `/create:agent`.

## CLI and Doctor Commands

The CLI executor choices and doctor surfaces changed to make dispatch less costly and health checks easier to reach. The underlying doctor YAML workflows did not change when the markdown command surface was consolidated.

#### Copilot is retired

`cli-copilot` is retired. GitHub Copilot price increases pushed it above the cost threshold. Its entire skill tree is gone. That includes 50+ playbook scenarios, hooks, the matrix-runner adapter and 2 test files. References were scrubbed from 101 files. They span sibling `cli-*` skills, the advisor, agents, commands and root docs. The advisor no longer recommends it. `cli-codex` is the cost-optimized default external executor.

&nbsp;

#### OpenCode dispatch closes stdin

`opencode run` could hang under stdout and stderr redirection. It reads stdin during startup and blocks when it receives no EOF. Dispatch now adds `</dev/null`. The hang had been costing 12 minutes per dispatch in stuck timeout cycles.

The EOF redirect is applied to deep-research and deep-review auto and confirm workflows. It is applied to the `cli-opencode` skill and stress-test dispatch scripts. The rule is documented as a permanent ALWAYS in `cli-opencode` SKILL.md §4.

&nbsp;

#### Codex config matches 0.130

Codex CLI configuration now matches the 0.130 schema. `[features].hooks = true` replaces the deprecated `codex_hooks` key. The hook-policy detector at `mcp-server/lib/codex-hook-policy.ts` matches both keys for transition compatibility.

Codex profiles for `codex exec -p <name>` live at user level in `~/.codex/config.toml`. That is where Codex actually loads them. Stale `.opencode/skill/` (singular) paths in `~/.codex/hooks.json` are now plural. So are paths in the `spec_kit_memory` MCP server config.

&nbsp;

#### Doctor has three entry points

Ten `/doctor:*` markdown commands collapsed to three. They are `/doctor <target>`, `/doctor:mcp` and `/doctor:update`. `/doctor:mcp` takes the `install` and `debug` sub-actions. The argv-positional router covers memory, causal-graph, code-graph, deep-loop, cocoindex, skill-advisor and skill-budget. It reads them through `.opencode/commands/doctor/_routes.yaml`. `/doctor:update` is unchanged.

The route manifest is the source for each target's YAML asset, setup variables and allowed flags. It also holds the mutation class, MCP tool subset and Skill Advisor trigger phrases. The router reads it, CI validates it and the advisor's lexical lane indexes it. A new `route-validate.{sh,py}` script is PyYAML-based, with no external `yq` required. It checks that every route references an existing asset. It checks that every `mcp_tools` entry is in the `allowed-tools` union of the router. It checks that no target name is duplicated.

&nbsp;

#### Prompts lead with the upgrade

A user arriving from 3.3.0.0 now sees the update path as option 1 in the `/doctor` menu. All 11 interactive prompts use numeric, verb-first, one-line options. Responses accept numbers, letters or verb keywords while preserving defaults.

&nbsp;

#### Command docs match their contracts

The router, MCP and update markdown commands use H2 numbered sections instead of H1 sections. They document `STATUS=OK|FAIL|CANCEL|ROLLED_BACK|RESTART_REQUIRED` values. Six of the ten doctor workflow YAMLs had been missing canonical top-level blocks. All ten now use the canonical top-level block sequence.

The doctor-update orchestrator packet gained `003-router-phase/` for additive ship. It gained `004-cutover-phase/` for hard cutover. The packet is at `.opencode/specs/system-spec-kit/026-graph-and-context-optimization/010-doctor-update-orchestrator/`. The phase-changelog index is at `.opencode/specs/system-spec-kit/026-graph-and-context-optimization/changelog/`. Its relative symlinks are named `changelog-026-<phase>-<slug>.md`.
