## Why This Release

The git hooks are installed once for every repository on a machine. In a repository they did not trust, they still read their helpers from that repository's own tree.

Commit-Id stamping also stopped quietly in those repositories.

Adapting the code skill was not a supported path either. The README told you to replace all three code surfaces. That included the native one. Removing an example broke the checks. A surface you added lost every keyword tie to OpenCode.

## Hook Safety and Commit-Id

#### Untrusted Clones Cannot Run Code Through the Hooks

The git hooks are installed once for every repository on a machine. For a repository they do not trust, they used to read their helpers from a `.skilled-untrusted` folder inside that same repository. So a clone could plant a guard library or a Commit-Id allocator there. That code would run on your next commit, pull or push. An untrusted repository's helpers now resolve under `/dev/null`, which no repository can fill. So the hooks read nothing from its tree. The hooks still trust their own checkout and its worktrees. They also trust any repository whose local config sets `skilled.trustRepoHooks=true`. Trust covers the repository, not a branch. So review an untrusted branch in a separate clone.

#### Every Commit Carries a Commit-Id

The commit hooks used to mint a Commit-Id only through the repository's own allocator. The hook trust gate hides that allocator in an untrusted clone. So commits there went out with no id, and nothing said so. `prepare-commit-msg` now falls back to the allocator shipped beside the hooks. It does that without running code from the repository. It stamps a continued revert and a squash commit too. In a repository that uses ids, `commit-msg` refuses a message without one. `pre-push` refuses any added non-merge commit without one. A repository uses ids when it ships the sk-git allocator or spec-kit. It also uses ids when its last 50 commits carry one. `git config --local skilled.commitId true` or `false` decides before either test. Both checks refuse `0000000`, an id the allocator never mints.

## Adapting the Code Skill

#### OpenCode Is Native and the Examples Are Optional

OpenCode (`sk-code-skilled`) is the native code surface and stays. Webflow (`sk-code-webflow`) and Obsidian (`sk-code-obsidian`) are optional examples you can remove. The README, the hub `SKILL.md` and the hub README now say so. None of them tells you to replace OpenCode. The README block "What Adapting `sk-code` Looks Like" covers the hooks to install and the folders to keep. It covers removing an example and adding a surface. It also covers the checks that prove each step.

#### The Guide Starts From a Fresh Clone

The block's "Before you start" step opens with `bash .skilled/skills/sk-git/scripts/worktree-naming.sh provision .` for a fresh clone. It opens with `git config --local skilled.trustRepoHooks true` for a clone that should run the hooks. The removal steps name the two feature-catalog files. They regenerate `graph-metadata.json` with `regenerate-skill-derived.cjs`. The add steps name `leaf-scopes.json` and the surface-count lines the documentation claim checker reads.

#### A New Surface Lands Ahead of OpenCode

`/create:skill-parent update --surfaces` writes a new surface into `routerPolicy.tieBreak`. It goes after the workflow modes and ahead of the existing surfaces. Several go in the order you give them. So it wins a keyword tie against OpenCode. Its report names the two steps it cannot run for you. They are a canary case with its fixture copy and a commit with the hooks installed. If you edit `hub-router.json` by hand and list your own surface after `sk-code-skilled`, the parent-skill doctor fails. It says to move it ahead.

#### Removing an Example Keeps the Checks Working

The sk-code drift guards read only the surface packets on disk. They skip archived route gold for a mode the hub no longer declares. The documentation claim checker takes the surface count from `mode-registry.json`. So "two surfaces" passes on a hub with two. Removing an example no longer makes a guard throw.

#### Failures Name Their Fix

When a surface folder is missing, the doctor names the README block that finishes the removal. When a hub's routing inputs change without a re-mint, the compiled-route guard used to print only `Re-mint: <hub>`. It now names the `compiled-route-manifest.cjs` refresh command, both manifest paths and the copy that clears it. A missing authored compiled-routing folder under `specs/` stops sync and the guard. Both name the folder to restore. Before, they passed or printed a stack trace. In a fresh clone `ci-skill-root-metadata.cjs` printed a raw Node stack. It now prints one line naming the provision command.

#### One Command Checks the Setup

`/doctor:sk-code setup` runs eight read-only checks from the repository root. They are provisioning, the parent-skill doctor, root metadata, the compiled-route guard, sync, the drift guards, derived freshness and a route probe. Each prints PASS, SKIP or FAIL with a `repair:` line naming the command that clears it. The run ends `STATUS=OK legs=8` or `STATUS=FAIL failed=<n> skipped=<n>`. The probe passes only on a real compiled route. It names `SPECKIT_COMPILED_ROUTING` when that variable has switched compiled routing off. On a checkout older than v4 the run reports the missing layout once. It skips the other seven checks. `--prompt=<text>` sets the probe's prompt. The run writes nothing. The probe line it prints quotes the prompt. So pasting the line reruns the same prompt.

## Pi

#### Pi Starts GPT Targets in Fast Mode

The Pi Fast Mode extension is now on by default, in new worktrees too. It still changes only the provider and model pairs in its configuration. A saved state, the `--fast` flag and the value a parent hands to its subagents still decide over the default. So `/fast off` stays off after a restart.

&nbsp;

## Upgrade Notes

- **Update every machine that has the hooks installed.** A machine on an older copy still lets a cloned repository run its own code through the hooks. Pull this release in the checkout the hooks link to. In a repository of your own that should run the full checks, run `git config --local skilled.trustRepoHooks true`.
- **Expect a Commit-Id check at commit and push.** A repository that uses ids refuses a commit without a `Commit-Id` trailer. Install the hooks so `prepare-commit-msg` stamps one. Or run `git config --local skilled.commitId false` in a repository that should not use them.
- **Run `/doctor:sk-code setup` after you adapt sk-code.** It names the command that clears each failing check.
- **Turn off Pi Fast Mode with `/fast off`.** Run it once. The saved state outlasts a restart.
