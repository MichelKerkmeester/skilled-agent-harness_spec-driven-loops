# v1.3.3.0, README Checkers That Agree With the Audit

The reference checker and the count checker failed most READMEs on things that are not broken. Those things are slash commands, model ids, import specifiers and prose such as "in one file". Both now judge only what they can check. Every link target, inventory row and file tree line is still checked. So a failure points at a real broken path or a stale count.

> Spec folder: `specs/sk-doc/070-repo-doc-debt/007-alignment-fixes` (Level 2)

&nbsp;

## What's New at a Glance

- **Every link target is checked.** A Markdown link that is not a URL or an anchor is checked as before. That holds whatever its form. `[dir](missing-dir/)`, `[noext](missing-file)`, `[deep](sub/missing.md)` and `[img](missing.png)` all fail when the target is gone. Only a target that does not normalize to a path is skipped. One example is a `{placeholder}`.
- **Anchored code spans resolve from three bases.** The audit reads some code spans as a path. Examples are `./run.sh`, `../gone.md` or `.skilled/scripts/absent.sh`. Each resolves from the README folder, its nearest `package.json` folder and the repository root. A bare name or unanchored path keeps that release's resolution. The false-positive rules of v1.3.2.0 still read those. So its `readme-check` markers stay valid. Fenced commands are read by the audit's anchored rule only.
- **Inventory rows and tree lines are claims.** A table cell made only of code spans is one claim. One example is `` `gone.py` ``. Another claim is a file tree entry drawn with box glyphs or ASCII. The glyphs include `+--`, `|--` and `` `-- ``. Both are checked against the README folder, its package root and the repository root. They fail only when none of them holds the file.
- **Git-ignored runtime paths pass.** The repository ignores some paths, such as a log folder. Those are cleared in two batched `git check-ignore` calls per run. That replaces one call per path. A typo of such a path still fails. A README kept inside an ignored folder is not cleared.
- **The count checker counts only the README's own folder.** A number counts files only when a plural term follows it directly. One example is "three scripts". It is skipped only when its own sentence names another path and not the README's folder. So "`.claude/hooks/` contains 25 symlinks" is still checked. That holds beside a link to another README. The label, bound, named-folder and `allow-count` rules of v1.3.2.0 still apply.
- **The git calls no longer wait on fsmonitor.** The audit's `git ls-files` and `git check-ignore` calls pass `-c core.fsmonitor=false`. Both checkers' root lookup does the same. So a checkout with a stalled fsmonitor daemon does not hang a run.
- **The scripts README documents both gates.** `scripts/README.md` now says what each checker checks. It gives each usage line, the `--self-test` flag and the exit codes. Those codes are 0 pass, 1 fail and 2 no README given. It covers the batched git-ignore clearing and the fsmonitor-off git calls. It also says the full sk-doc suite runs both.
- **A stale count still fails.** "Three scripts" over a folder that holds two is still reported. So is a count with no complete file list behind it.

&nbsp;

## Upgrade

No migration required. A README that failed only on slash commands, model ids, import specifiers or prose now passes. A README with a stale inventory row or tree line fails until the row is corrected.
