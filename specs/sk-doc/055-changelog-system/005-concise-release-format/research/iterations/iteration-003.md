# Iteration 3: Q3 — Where the `/create:changelog` command surface pushes toward the long format

## Focus

Q3 only: the `/create:changelog` command doc and its two workflow YAMLs, plus the presentation contract the router defers to. The question had six sub-parts, carried verbatim from the dispatch pack: (1) do the command files duplicate the Compact/Expanded selection or defer to the template; (2) does any setup field or prompt ask for a change count, making Expanded a machine-selected outcome; (3) does any length, body-size or item-count gate exist anywhere on the command surface; (4) does the release step constrain the body; (5) is upgrade-note guidance action-typed, section-ordered or silent; (6) does keep/drop, exemplar or maintainer-detail wording push long.

Scope was the four command-surface files. Q1 (the short entry's format rules) and Q2 (the skill packet's push) were not re-derived; the template was consulted only where the YAMLs explicitly point at it. No file outside the research packet was modified.

Surface read in full: `.skilled/commands/create/changelog.md` (70 lines), `.skilled/commands/create/assets/create-changelog-auto.yaml` (885 lines), `.skilled/commands/create/assets/create-changelog-confirm.yaml` (835 lines), `.skilled/commands/create/assets/create-changelog-presentation.txt` (172 lines), plus `references/README.md:47`, which names the presentation file as a command-surface asset.

## Findings

1. **The command doc carries no format guidance at all — it is a pure router, so no format rule can be fixed there.** It calls itself "a thin router" that separates "execution routing from user-facing presentation" [SOURCE: .skilled/commands/create/changelog.md:9], states that "The YAML owns workflow behavior; the presentation Markdown owns user-visible wording and layout" [SOURCE: .skilled/commands/create/changelog.md:34], and forbids the router from inventing visible wording [SOURCE: .skilled/commands/create/changelog.md:61]. Neither Compact nor Expanded, no ceiling and no exemplar appears in its 70 lines. Consequence for Q5: the command doc is not an edit target for format, only a routing hop.

2. **The command surface duplicates the two-tier threshold instead of deferring, then defers for the rest — three copies in the autonomous path, two in the interactive path.** Auto defines COMPACT at "fewer than 10 changes and no breaking change" and EXPANDED at "10+ changes, a major bump, or any breaking change" in the template comment block [SOURCE: .skilled/commands/create/assets/create-changelog-auto.yaml:287], restates the thresholds in a FORMAT SELECTION comment immediately below [SOURCE: .skilled/commands/create/assets/create-changelog-auto.yaml:293], and encodes them a third time as executable step logic [SOURCE: .skilled/commands/create/assets/create-changelog-auto.yaml:539], while also pointing away for detail: "See template file Section 5 (Format Selection Guide) for full rules" [SOURCE: .skilled/commands/create/assets/create-changelog-auto.yaml:541]. Confirm keeps the comment definition [SOURCE: .skilled/commands/create/assets/create-changelog-confirm.yaml:283] and the executable copy [SOURCE: .skilled/commands/create/assets/create-changelog-confirm.yaml:533] but drops both the FORMAT SELECTION comment and the Section-5 pointer. So the answer to sub-part 1 is *both*: duplicated at the tier level, deferred at the rule level, and the copy that actually decides is the executable one, not the template.

3. **No setup field or prompt asks for a change count, so `change_count` is workflow-computed and Expanded is a machine-selected outcome with no operator decision.** The presentation contract's resolution table has six fields — `source_type`, `spec_folder`, `component_hint`, `version_bump`, `execution_mode`, `publish_release` — and none is a change count [SOURCE: .skilled/commands/create/assets/create-changelog-presentation.txt:69], which the startup prompt mirrors as Q0/Q1/Q2/Q3 with no count question [SOURCE: .skilled/commands/create/assets/create-changelog-presentation.txt:99]. The YAML input contract agrees: required `create_agent_verified` and `source_type`, optional `spec_folder`, `component_hint`, `version_bump`, `publish_release` [SOURCE: .skilled/commands/create/assets/create-changelog-auto.yaml:154]. `change_count` appears only inside step 4, where it is derived locally [SOURCE: .skilled/commands/create/assets/create-changelog-auto.yaml:539]. In the autonomous path nothing intervenes between that derivation and the tier, because approvals are disabled outright [SOURCE: .skilled/commands/create/assets/create-changelog-auto.yaml:31]. In the interactive path a step-4 checkpoint exists, but its options are Approve / Review / Modify / Regenerate [SOURCE: .skilled/commands/create/assets/create-changelog-confirm.yaml:570] — there is no "use the shorter format" option, so even the human-in-the-loop path cannot overrule the tier.

4. **No length, body-size or item-count gate exists anywhere on the command surface; every quantitative cap is per-unit and nothing caps how many units there are.** A grep for `max`, `maximum`, `ceiling`, `cap`, `limit`, `total lines`, `total words` and `prose lines` across both YAMLs returns zero hits. The only numbers are per-unit: summary "1-2 sentences, 3 at most" compact and "1-3 paragraphs, 5 at most" expanded [SOURCE: .skilled/commands/create/assets/create-changelog-auto.yaml:559], H4 headings "10 words at most" and H4 items "7 paragraphs at most" [SOURCE: .skilled/commands/create/assets/create-changelog-auto.yaml:647], and the same limits restated in confirm's content checks [SOURCE: .skilled/commands/create/assets/create-changelog-confirm.yaml:583]. Section count is an output and a report field, never a gate [SOURCE: .skilled/commands/create/assets/create-changelog-auto.yaml:617]. The quality standards set a floor and no ceiling: content quality's minimum is "Summary narrative + at-a-glance + upgrade notes" [SOURCE: .skilled/commands/create/assets/create-changelog-auto.yaml:779] and format compliance's is "All required sections present" [SOURCE: .skilled/commands/create/assets/create-changelog-auto.yaml:773].

5. **The completion display scores the quantities the long format maximises.** The result template reports "Sections: [section_count]" and "Files Tracked: [files_changed_count]" [SOURCE: .skilled/commands/create/assets/create-changelog-presentation.txt:155], and both YAML completion reports repeat the section count [SOURCE: .skilled/commands/create/assets/create-changelog-auto.yaml:812]. "Files Tracked" surfaces a file-count metric that the body rules simultaneously forbid in prose — no Files Changed tables [SOURCE: .skilled/commands/create/assets/create-changelog-auto.yaml:577]. The run is therefore scored on volume while the writer is told to hide volume, and nothing in the report measures the reader-facing property the short entry is built for.

6. **The release step imposes no body constraint, so whatever length the workflow produced is what publishes.** Release-notes preparation strips the YAML frontmatter block and the editorial H1, keeps the entry's spacing, appends an `&nbsp;` rule plus a "Full changelog:" footer and writes the result to a notes file [SOURCE: .skilled/commands/create/assets/create-changelog-auto.yaml:717], [SOURCE: .skilled/commands/create/assets/create-changelog-confirm.yaml:654], which is then handed straight to `gh release create` [SOURCE: .skilled/commands/create/assets/create-changelog-auto.yaml:728]. The only body rules in that step are presentational: no duplicated title H1 [SOURCE: .skilled/commands/create/assets/create-changelog-confirm.yaml:658] and the spacing convention [SOURCE: .skilled/commands/create/assets/create-changelog-confirm.yaml:659]. The answer to sub-part 4 is that the release step does not constrain the body at all — it inherits it, so an over-long entry becomes a public release note verbatim, and the last gate before publication is step 5's per-unit checks from finding 4.

7. **Upgrade-note guidance is action-typed but never section-ordered, and the two files disagree in depth.** The autonomous path specifies Adopt/Repoint/Drop lead-ins, a "No migration required." fallback, one action per line with no rationale, and the `## Upgrade` versus `## Upgrade Notes` name split [SOURCE: .skilled/commands/create/assets/create-changelog-auto.yaml:597]. The interactive path compresses all of that into a single clause [SOURCE: .skilled/commands/create/assets/create-changelog-confirm.yaml:551]. "in section order" occurs exactly once in each file and only for glance bullets in the extend branch — "Add one glance bullet per new theme, in section order" [SOURCE: .skilled/commands/create/assets/create-changelog-auto.yaml:608], [SOURCE: .skilled/commands/create/assets/create-changelog-confirm.yaml:559] — and the adjacent upgrade clause says only "any action to Upgrade Notes" with no ordering [SOURCE: .skilled/commands/create/assets/create-changelog-auto.yaml:609]. Sub-part 5 therefore answers "action-typed, not section-ordered": the ordering rule iteration 1 observed in the short entry has no carrier on the command surface.

8. **Keep/drop wording points short at selection time but never at output size, and the one rule the short entry needs — fold small fixes into a single bullet list — is absent.** The autonomous path selects content by reader impact: "Keep a change only when the reader would notice it, act on it or decide differently because of it", merge same-effect changes, rank by impact, and "Drop test and playbook changes, internal labels, process detail and follow-on housekeeping" [SOURCE: .skilled/commands/create/assets/create-changelog-auto.yaml:533], [SOURCE: .skilled/commands/create/assets/create-changelog-auto.yaml:535]. The omission rules repeat the floor for every format: no Files Changed tables, no test metrics, no schema tables, no internal labels outside the spec-folder line, reverted mid-cycle work compressed to one story sentence, tables only when the numbers are the story [SOURCE: .skilled/commands/create/assets/create-changelog-auto.yaml:577]. The interactive path keeps a compressed version [SOURCE: .skilled/commands/create/assets/create-changelog-confirm.yaml:527]. All of this is per-item elimination; nothing says what to do when the surviving set is still large, and nothing permits folding a group of small fixes into one bullet list. Sub-part 6's answer is split: the keep/drop lists push short, the per-item scope leaves the aggregate body unbounded.

9. **Exemplar and scale clauses push long, and the command surface inherits the template's default instead of counterbalancing it.** `style_reference` names the 535-line v4.0.0.0 entry [SOURCE: .skilled/commands/create/assets/create-changelog-auto.yaml:314], [SOURCE: .skilled/commands/create/assets/create-changelog-confirm.yaml:294], and the section-naming comment authorises scaling to it: "One to five domains for most releases, more for a release the size of the exemplar" [SOURCE: .skilled/commands/create/assets/create-changelog-auto.yaml:322], [SOURCE: .skilled/commands/create/assets/create-changelog-confirm.yaml:302]. The autonomous path further budgets body per item — "H4 items: the detail" [SOURCE: .skilled/commands/create/assets/create-changelog-auto.yaml:584] and "One or two paragraphs, seven at most" [SOURCE: .skilled/commands/create/assets/create-changelog-auto.yaml:573] — with no aggregate cap. Because the YAML defers full rules to template Section 5 [SOURCE: .skilled/commands/create/assets/create-changelog-auto.yaml:541], the command surface adds no counterweight to the template's Expanded default; it localises it three more times.

10. **Contradictory evidence: the two workflow files have drifted, and the unattended path is the stricter one.** Auto carries a WRITING STYLE block of five reader-facing constraints, including "Plain English for a smart person who is not a developer" [SOURCE: .skilled/commands/create/assets/create-changelog-auto.yaml:299], "Lead with why the release matters, never technical stats" [SOURCE: .skilled/commands/create/assets/create-changelog-auto.yaml:300] and "Keep only what the reader would notice or act on" [SOURCE: .skilled/commands/create/assets/create-changelog-auto.yaml:302], plus its own FORMAT SELECTION comment [SOURCE: .skilled/commands/create/assets/create-changelog-auto.yaml:293]. Confirm's corresponding block ends at the tier names and the exemplar lines and contains neither comment [SOURCE: .skilled/commands/create/assets/create-changelog-confirm.yaml:291]. Same source document, two modes, different constraint sets: the autonomous path is told to write plain English for a non-developer, and the interactive path is not. Both sides are cited and the conflict is left unresolved rather than smoothed; direction of resolution is a Q5 decision (probably: hoist the block into the shared template or into both files identically). No operator is present, so this is recorded, not escalated to a halt.

11. **Format compliance is a hard gate whose verification is satisfied most easily by the long format.** `H3_version_contract` states that "Version calculation and content format must be valid before write" [SOURCE: .skilled/commands/create/assets/create-changelog-auto.yaml:343] and its verification is "All required sections present in generated content" [SOURCE: .skilled/commands/create/assets/create-changelog-auto.yaml:347]. Expanded supplies Why This Release, topical H2 sections, H4 items and Upgrade Notes, so it passes that gate by construction; a concise entry that merges sections risks failing it. The gate as written rewards section count.

## Ruled Out

- **Treating the command doc as an edit target for format.** It is 70 lines of routing with an explicit ban on inventing wording [SOURCE: .skilled/commands/create/changelog.md:61]. Any format fix belongs in the YAML step 4/step 5 or the template.
- **Explaining the long output as "the operator chose Expanded".** No surface asks for a change count or a format; the tier is derived and, in autonomous mode, never confirmed [SOURCE: .skilled/commands/create/assets/create-changelog-auto.yaml:31].
- **Attributing the release step as a length gate.** It strips two blocks and preserves spacing [SOURCE: .skilled/commands/create/assets/create-changelog-confirm.yaml:654]; it neither truncates nor summarises.
- **Reading the confirm checkpoint as a format veto.** Its four options do not include a format choice [SOURCE: .skilled/commands/create/assets/create-changelog-confirm.yaml:570].
- **A pure keyword grep as the method.** The earlier offset-mangled listing produced three wrong line anchors that only a second numbered read corrected; keyword hits alone would have missed findings 5, 6 and 11, none of which contains a format keyword.

## Dead Ends

- **A length rule in the YAML at all.** Greps for `max|maximum|ceiling|cap|limit|prose lines|total lines|total words` across both files return zero hits. There is no ceiling to relocate; one has to be authored. Candidate for the reducer's exhausted list: searching the command YAMLs for an existing body ceiling.
- **A setup-level format question.** The six-field contract [SOURCE: .skilled/commands/create/assets/create-changelog-presentation.txt:69] is complete and `version_bump` is the only creative control; adding a format field is a design choice, not a discovery.

## Reflection

- **What worked and why:** diffing auto against confirm *before* attributing lines. The two files share most of their text, so a single-file read would have attributed the WRITING STYLE block to both modes and produced a false generalisation; the diff isolated it to auto and made finding 10 possible. Numbered re-reads after a suspect listing also caught three bad anchors before they reached the narrative — the citation rule is what forced that check.
- **What did not work and why:** a first `sed | cat -n | awk` offset computation mangled blank lines and produced a listing whose numbers could not be trusted. The root cause was reconstructing line numbers through a pipeline instead of asking the tool for them; `awk 'NR>=a && NR<=b'` on the file directly is both simpler and exact, and was used for every citation that survived.
- **What I would do differently:** read the setup contract first and the step bodies second. Half of Q3's sub-parts (2, 3) are answerable from the field list and the gate definitions alone, and starting there would have narrowed the step-body reading to the four regions that actually mattered.
