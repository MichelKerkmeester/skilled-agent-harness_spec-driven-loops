## What Was Built

A release with many changes now comes out in the shape of the 196-line v4.0.1.0 entry, not the 338-line version it replaced. The expanded format has its own ceilings, and a shape gate stops a draft that breaks them before `/create:changelog` writes it.

### Phase 5: concise-release-format

The template used to tell you to copy the 535-line v4.0.0.0 entry and set every ceiling at or above it, so nothing bounded a long release. It now names two model entries. v4.0.1.0 gives length, selection, the section and H4 shape, the Smaller Fixes list, section-ordered upgrade notes and the coverage sentence. v4.0.0.0 gives the voice and the way a major release opens. Length comes only from the template's ceilings: 240 lines below the frontmatter, 26 H4 items and one paragraph per item.

`check_changelog_shape.py` holds those ceilings as errors. It fails an expanded entry past the file total or the H4 ceiling, a glance list past 12 bullets, tagged glance bullets out of section order and a spec-folder line with a level label. Both command YAMLs run it on the draft in step 5 and never write while it exits non-zero.

## How It Was Delivered

The ranked edits went in research order, length authority first, so no ceiling existed while the old calibration sentence could raise it. Every replacement matched its old text exactly once before it was applied. The gate came last and was proved against the three measured entries, then by ten tests and a negative control that raised the H4 ceiling to 27 and watched `test_h4_items_fail_past_26` fail. Nothing was committed. The operator reviews and commits the worktree.

<!-- ANCHOR:decisions -->
## Key Decisions

| Decision | Why |
|----------|-----|
| The gate counts every line below the frontmatter, blank lines included | It is the count a reader can reproduce with `wc -l`, and trigger-phrase lists vary in length, so the frontmatter stays out |
| The gate runs five rules, not the research's seven | The operator named five. Per-section H4 counts and a word ceiling per item were left out, and the research had not settled the per-section number |
| No exemption for v4.0.0.0 | It is the voice model, and the template now says it runs past the ceilings. The gate runs only on new drafts, so failing it blocks nothing |
| Compact glance bullets carry no section tag | A compact entry has no topical section for a tag to name, so research rank 7's compact edit was not applied |
| The section tag is a trailing `<!-- section: {Topical Domain} -->` comment | A visible tag would change how a glance bullet reads, and the operator wanted the v4.0.1.0 look. The comment does not render, so the v4.0.1.0 entry carries it and the order rule runs on the model entry. A visible `({Topical Domain})` tag is still read |
| Three to six domains, eight at most | v4.0.1.0 has eight topical sections. The research's "add a seventh" wording would have made the model entry break its own template |
| Tests live in the hub's `scripts/tests/` | `run-script-tests.sh` collects only that folder, and the mode had no tests of its own |

<!-- ANCHOR:limitations -->
## Known Limitations

1. **The order rule needs section comments.** An entry with no glance comment and no visible tag skips the order check. v4.0.1.0 now carries the comments, so the model entry is checked in full.
2. **The ceilings live in two places.** The template's length table and the gate's constants still hold the same numbers twice, but `test_the_template_ceilings_match_the_checker` fails the suite when they disagree, in either direction.
