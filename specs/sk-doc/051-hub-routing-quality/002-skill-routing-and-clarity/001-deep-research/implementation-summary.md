## What Was Built

You now have a checked answer to which routing shape each skill type should use, and a ten-phase plan to get there. Hubs keep one hub-root `ROUTER.md`. Mode packets keep a short routing section and a final machine-router appendix. Standalone skills keep a short inline router. No skill gets a per-mode `ROUTER.md`, and JSON-only is ruled out by named checks.

### Phase 1: deep research

Two lineages ran five iterations each on DeepSeek V4.1 Flash at max reasoning, one through cli-pi and one through cli-devin, on disjoint halves of the fleet. They reached the same verdict independently. Beyond the shape question, they found correctness defects, such as system-skill-advisor's discovery roots and an unreachable leaf, that a prose pass alone would have hidden. Those defects go first, in phase 002.

## How It Was Delivered

The run followed the `/deep:research` auto workflow's fan-out path: config, `fanout-run.cjs`, `fanout-merge.cjs`, `reduce-state.cjs --emit-resource-map --fanout-resource-map-only`, the merged synthesis, then `synthesis-closeout.cjs` through the append gateway. The orchestrator then re-read every cited line used in a verdict or the plan and marked each finding confirmed or unconfirmed.

<!-- ANCHOR:decisions -->
## Key Decisions

| Decision | Why |
|----------|-----|
| Split the fleet between the lineages with one steer file each | Two lineages on the same topic would repeat each other. The steer file is the runner's lead channel, read before init. |
| Mark each finding confirmed or unconfirmed instead of trusting the lineage | A flash model's citation is a claim until someone reads the line. One lineage claim, a separate `.opencode` mirror, turned out wrong: `.opencode/skills` is a symlink. |
| Put correctness fixes before any shape change | They are cheap, low-risk and independent, and the later phases measure against a baseline that should not include known bugs. |
