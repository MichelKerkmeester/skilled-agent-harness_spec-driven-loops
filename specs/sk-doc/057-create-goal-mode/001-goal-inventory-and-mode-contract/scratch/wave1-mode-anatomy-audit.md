## 6. Proposed phase split

This is a sequencing proposal, not goal-mode content design. I recommend **nine phases**: preserve the contract-before-scaffold and prove-before-close discipline of 040, split routing from command wiring so each routing stage gets its own evidence, and leave final end-to-end use until the mode is reachable. [`040-create-repo-rules/spec.md:134-142`](specs/sk-doc/z_archive/040-create-repo-rules/spec.md:134); [`parent-skills-nested-packets.md:250-259`](.skilled/skills/sk-doc/sk-create-skill/references/parent-skill/parent-skills-nested-packets.md:250)

1. **`001-goal-inventory-and-boundary`** — Establish the existing `goal.md` corpus, its consumers and ownership boundary against session-goal commands. Deliverables: inventory, mode boundary and requirements matrix. Done when every in-scope file and owner is traced to source.
2. **`002-goal-contract-and-template`** — Define the goal artifact contract and its fillable template from the inventory. Deliverables: contract, template and representative fixture. Done when the fixture satisfies the contract and the check distinguishes a known-invalid fixture.
3. **`003-mode-packet-scaffold`** — Scaffold the nested packet and route its references using the existing sk-doc packet pattern. Deliverables: `SKILL.md`, `README.md`, reference index, packet-local references/assets and changelog directory. Done when the packet tree matches its documented target.
4. **`004-authoring-workflow-and-boundaries`** — Specify the authoring workflow and its refusal, ambiguity and change boundaries from phase 001’s contract. Deliverables: ordered workflow and cross-mode routing rules. Done when test cases distinguish goal-file authoring from session-goal management and unrelated spec-kit work.
5. **`005-template-conformance-and-playbook`** — Test generated output and authoring decisions before integration. Deliverables: positive/negative fixtures and a manual test playbook. Done when the structural/contract check passes the valid fixture, rejects the invalid one and the playbook package validates.
6. **`006-hub-routing-integration`** — Add both routing stages and the generated leaf inventory. Deliverables: hub advisor vocabulary, mode registry and tie-break, `hub-router.json`, root `ROUTER.md` leaves and `FULL_INVENTORY`, hub `SKILL.md`/`description.json`, regenerated `leaf-manifest.json`. Done when hub-specific validation and live advisor plus compiled-router replays agree.
7. **`007-command-and-runtime-mirrors`** — Create `/create:goal` through `sk-create-command` and connect it to the mode. Deliverables: router `.md`, auto/confirm/presentation assets, `command-metadata.json`, command-index row and runtime mirrors. Done when the command validates, metadata parses and each mirror resolves.
8. **`008-documentation-and-release-packaging`** — Complete reader documentation and release surfaces after the workflow exists. Deliverables: README, updated hub/command indexes, changelog version file and hub changelog link. Done when document validators pass and the link resolves.
9. **`009-end-to-end-review-and-closeout`** — Exercise a genuine authoring path and a refusal, then reconcile remaining limitations. Deliverables: run evidence, independent review and final packet status. Done when both paths have honest verdicts, both routing stages are rechecked and recursive strict validation passes.

**040 mapping:** keep 002, 003, 004 and 005 as contract, scaffold, quality and integration work; split 006 into phases 006–007 to isolate the two-stage hub route from command authoring; combine 007–008’s packaging/doc work into 008, while retaining real end-to-end closure in 009. Reuse 009’s negative-control lesson in routing checks, but drop its separate generalized rule/check implementation because the existing parent-hub doctrine already defines the surfaces and replay commands. Drop 040-001’s rule-set construction itself; retain only its inventory method as input to phase 001. [`040-create-repo-rules/spec.md:111-121,134-142`](specs/sk-doc/z_archive/040-create-repo-rules/spec.md:111); [`parent-skills-nested-packets.md:222-259`](.skilled/skills/sk-doc/sk-create-skill/references/parent-skill/parent-skills-nested-packets.md:222)
