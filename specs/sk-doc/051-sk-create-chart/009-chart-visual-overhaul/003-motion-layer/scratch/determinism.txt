--- 3. WHAT THE PAUSED FRAME IS FOR ----------------------------------------
A settled render that matches the control could also mean the animation never ran.
scratch/mid-frames holds a copy of each file with the animation paused part way
through, so the third line of every block above is what separates a motion that
settles correctly from a motion that is not there. All nine differ from their
settled state, so all nine move.

--- 5. THE INSTRUMENT'S OWN REPRODUCIBILITY ---------------------------------
A pixel comparison is only evidence if the same file rendered twice gives the same
bytes to begin with. Before the method was trusted, daily-line was rendered twice in
a row and once more minutes later, in scratch/route-test/selfcheck-1.png,
selfcheck-2.png and scratch/pixels-before/daily-line.png. All three hash to
36746fd3ce0b6000..., so the difference this file reports is a difference in the
chart rather than noise in the capture.

scratch/route-test also holds the first attempt at catching a mid-animation frame,
the t-*.png files taken with a short --virtual-time-budget. They are all settled
pictures. The budget advances virtual time and then captures, and it does not hold a
CSS animation part way through, which is why every mid-animation frame in this phase
is a paused negative-delay frame instead.

--- 4. WHAT THIS DOES NOT PROVE --------------------------------------------
Both instruments compare two opens on one machine with one browser build. They say
the file is deterministic. They do not say the picture is the same on a different
browser, and the contract does not claim it is.
