# Investigation: why section dividers and TOC/anchors drifted across the .md fleet

<!-- SPECKIT_LEVEL: 3 -->

---

## 1. STARTING SYMPTOMS

The operator noticed two inconsistencies in the doc fleet:

- Some READMEs carry `<!-- ANCHOR -->` markers and a Table of Contents; others do not. Example pair: `system-spec-kit/templates/README.md` (has both, single-dash links) versus `system-spec-kit/templates/stress-test/README.md` (no anchor markers, double-dash links).
- Not all documents place a `---` divider between numbered ALL-CAPS sections, though the operator believed dividers should always be present.

The scope is not READMEs only. The same numbered-ALL-CAPS-H2 convention governs SKILL.md, references, commands, agents, procedures, constitutional memories and other structured `.md`, so the investigation widened to the whole fleet.

---

## 2. THE DIVIDER RULE IS UNAMBIGUOUS

Every written authority requires `---` between numbered ALL-CAPS H2 sections:

- `core-standards.md` §4 (auto-fix "Add `---` between major H2 sections") and §6 (Divider Usage Rules, with the explicit "never between H3 subsections" caveat).
- `sk-create-readme/references/readme/writing-patterns.md` line 103 and `assets/readme-template.md`.
- `hvr-rules.md` §9 checklist ("`---` dividers between H2 sections").

There is no conflict here. The operator's intuition is correct.

---

## 3. THE ANCHOR/TOC RULE HAS A REAL CONFLICT

Two authorities disagree about READMEs:

| Authority | Position |
|-----------|----------|
| `core-standards.md` §3, `sk-create-readme` (SKILL.md, writing-patterns.md, readme-template.md) | Never add a TOC or `<!-- ANCHOR -->` nav. Navigate by numbered H2. |
| `validate_document.py` + `hvr-rules.md` §9 | README `tocRequired: false` (TOC optional, not forbidden); if a TOC exists it must use double-dash anchors and ALL-CAPS entries. Only the opt-in code-folder path forbids TOC/anchors. HVR §9 still says general docs carry anchors. |

The written standard was updated to "no TOC/anchors"; the validator and HVR §9 were never reconciled. Because the general path neither requires nor forbids a TOC, both styles pass, and the fleet stayed mixed. The single-dash versus double-dash split is the fingerprint of a double-dash auto-fixer that only some files were run through.

---

## 4. THERE ARE TWO DIFFERENT ANCHOR SYSTEMS

This is the distinction that prevents a destructive remediation:

- **Vestigial README/skill nav anchors**: `<!-- ANCHOR:section -->` comments plus a TOC of `#slug` links. This is the drift. The written standard removes them.
- **Functional spec-kit continuity anchors**: the semantic-tagged anchors in `spec.md` / `plan.md` / `tasks.md` / `implementation-summary.md` / `memory/context.md`, generated by `scripts/lib/anchor-generator.ts` and validated by `scripts/spec/validate.sh` at `ANCHORS_VALID=error`. The fixtures `test-fixtures/007-valid-anchors` and `008-invalid-anchors` guard them. These are required and must not be stripped.

Any bulk anchor removal must be scoped by a doc-type/path allowlist so it never touches the second system.

---

## 5. WHY THE DRIFT SLIPS THROUGH THE VALIDATOR

`validate_document.py` has two README-relevant paths:

- **General path** (`--type=readme` and friends): runs `validate_toc`, `validate_h2_headers`, `validate_required_sections`. `validate_toc` returns early because README `tocRequired: false`, and no function checks `---` dividers or forbids anchors. So a general README can lack every divider and still pass.
- **Code-folder path** (`--type=code_folder`, opt-in): `validate_code_folder` enforces `code_folder_h2_separator` (dividers required), `code_folder_no_toc`, and `code_folder_no_anchor`.

The divider and no-TOC/no-anchor rules already exist. They just live only in the opt-in path. Many code-folder READMEs were evidently never run through it either.

## 7. CENSUS METHOD AND ONE CALIBRATION TRAP

The heuristic flags a numbered H2 whose nearest non-blank line above is not `---`. The first run false-positived on `templates/README.md`, which does have dividers but places an `<!-- ANCHOR -->` comment between the `---` and each heading. The fix treats HTML-comment-only lines as transparent. The enforcement code must do the same, and must skip numbered headings inside fenced code examples. `mcp-server/utils/README.md` is a confirmed true positive: nine numbered sections, zero dividers. The reusable script lives in `scratch/census.py`.

---

## 8. OPEN VERIFICATION ITEMS

- GitHub slug output for `## 1. OVERVIEW` is asserted by the validator to be `#1--overview` (double dash) "for GitHub compatibility", but this was not empirically tested. It decides whether the 7 single-dash files are actually broken links.
- The ~54 anchor-comment files must be triaged individually into keep (continuity) versus strip (nav) before any bulk edit.
- Whether constitutional memories should adopt dividers is a separate policy decision.
