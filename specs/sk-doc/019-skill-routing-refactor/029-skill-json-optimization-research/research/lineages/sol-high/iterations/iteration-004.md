# Iteration 4: Metadata-to-route effectiveness

## Focus
Dimension 4 only: trace actual metadata from watcher activation through SQLite/filesystem projection, advisor lane attribution, compiled hub-mode routing, executor delegation, and fallback behavior. The narrow interpretation is effectiveness of the existing metadata and activation boundaries, not scorer-weight or algorithm redesign. Targeted live probes were used only to test source-derived hypotheses against advisor generation 12454.

## Findings
1. **Highest leverage — watched derived key files trigger reindexing but cannot change the indexed candidate unless `graph-metadata.json` was separately regenerated.** The watcher includes every existing `derived.key_files` path and routes changes to `indexSkillMetadata()`, but that indexer hashes and parses `graph-metadata.json` itself, then skips an unchanged node by that hash. For sk-doc this means edits to watched `mode-registry.json` or `hub-router.json` can cause work without updating candidate vocabulary; their content becomes effective only after another producer projects it into root metadata. The load-bearing watcher inputs are therefore `SKILL.md` validity and `graph-metadata.json`; key-file watch membership alone is ineffective as a content projection. 2. **Advisor root selection has a precise load-bearing field set, and hub JSON is outside it.** Projection reads `SKILL.md` name, description, and frontmatter keywords, then combines those with graph `domains`, `intent_signals`, derived triggers/topics/entities/files/docs, lifecycle, and redirects. The explicit-author lane uses authored intent signals and SKILL keywords; lexical additionally uses name, description, and domains; graph edges and derived data feed their own lower-weight lanes. `description.json`, `mode-registry.json`, `hub-router.json`, and generated leaf JSON do not enter normal root candidate scoring. The current live weights make authored exact signals the strongest metadata lever (`explicit_author` 0.42, lexical 0.28, graph 0.13, derived 0.12). 3. **Rich hub-mode vocabulary is effective only after the parent wins, leaving a measurable activation gap at root selection.** The compiled sk-doc router unions commands, mode aliases, and router-class keywords, including distinctive phrases such as `argument-hint`, `swimlane`, `text characters`, and `reviewer-prompt fixture`; the root graph's authored/derived signals carry only a subset. In targeted live probes, capability-inventory and release-note phrases selected sk-doc and then routed correctly, but the distinctive swimlane phrase abstained, the slash-command metadata phrase selected sk-code, and the benchmark-package phrase selected sk-prompt. Because the compiled engine routes *within* an already selected hub, it cannot recover those parent-selection misses. The high-leverage fix class is an automated, validated parent-candidate projection of high-specificity mode aliases—not a scoring redesign or wholesale duplication of every router keyword. 4. **SQLite failure preserves direct/derived root text but drops two whole metadata channels: graph edges and doc triggers.** The SQLite projection loads node fields, `skill_edges`, and optional `skill_docs`; filesystem fallback reconstructs root text and graph-derived fields directly from JSON but returns an empty edge list and never attaches doc triggers. The derived lane can otherwise use up to the three strongest doc matches with a bounded 0.45 contribution, while graph propagation uses authored edge type/weight only after another lane supplies a seed. Thus fallback is intentionally available but not effectiveness-equivalent: niche doc phrases and causal graph support disappear even though recommendations may still look healthy. 5. **Executor delegation is the deliberate exception to normal hub selection, but its metadata cache has no source-change invalidation.** Post-fusion delegation reads workflow executors and aliases directly from `cli-external-orchestration/mode-registry.json`, augments them with active model profiles, suppresses archived executor aliases, and can inject an otherwise absent executor at fixed passing confidence. A missing/malformed hub registry silently becomes zero executors, and the filesystem alias bundle is memoized only by workspace root, so edits to registry aliases, model profiles, or archive metadata remain ineffective until process restart/cache recreation. This is a high-leverage activation/freshness gap because delegation is already strong when loaded; the committed evaluation baseline shows 10/11 delegation cases correct. 6. **Compiled sk-doc routing is genuinely serving and has conservative fallbacks, but current evaluation evidence does not support stronger global effectiveness claims.** The activation manifest is generation 5 with `servingAuthority:"compiled"` and `shadowOnly:false`; once sk-doc is selected, commands dominate, weighted vocabulary selects a single mode, declared exact bundles route, unknown terms defer, and undeclared near-ties clarify. The committed canary set exercises all 12 explicit commands plus only two positive natural-language routes, while the advisor smoke regression has one sk-doc case. More broadly, the executable ratchet freezes filesystem projection and pins exact corpus hashes, with 155/200 corpus and 57/78 holdout correct; this conflicts with the separate narrative claiming 80.5% and 77.5% at another SHA. The evidence supports a strong serving boundary but only moderate, version-sensitive root-selection effectiveness. ## Ruled Out
- **Treating `mode-registry.json` and `hub-router.json` as normal advisor root-selection inputs.** They are compiled into within-hub vocabulary, while the normal projection reads SKILL plus graph fields; only executor delegation directly reads a mode registry. - **Treating key-file watch activation as derived-content refresh.** Watch events invoke the graph indexer, which skips unchanged graph metadata; no derivation runs in that path. - **Redesigning lane weights to address the misses.** The observed failures occur before rich hub vocabulary is visible to candidate selection or after cached delegation metadata becomes stale; changing fusion would treat the symptom rather than activate existing authored intent. ## Dead Ends
- `description.json`, leaf manifests, and command metadata do not provide an advisor root-selection recovery path in the traced runtime; they serve other identity, leaf, and command-contract consumers.
- Filesystem fallback cannot preserve graph/doc lane parity without another projection source; its explicit empty-edge return makes that a designed degradation, not an accidental hidden reader. [SOURCE: .opencode/skills/system-skill-advisor/mcp-server/lib/scorer/projection.ts:639-692]
