### F1.4 — graph-metadata.json shape (the largest, most field-dense file)
A representative H-class graph-metadata.json (sk-code) carries: `schema_version`, `skill_id`, `family`, `category`, `deprecated`, `edges` (depends_on/enhances/siblings/conflicts_with/prerequisite_for), `manual` (depends_on/related_to), `domains` (29 entries), `intent_signals` (64 entries), and a large `derived` block (trigger_phrases 20, key_topics 17, intent_signals 5, source_docs 15, key_files 22, entities 4, causal_summary, created_at, last_updated_at, supported_surfaces, peer_resource_categories).
[SOURCE: .opencode/skills/sk-code/graph-metadata.json:1-267]

The `derived` block is generated by backfill-graph-metadata.js; the top-level `domains`/`intent_signals`/`edges`/`manual` are authored. This is the only file that is partly-authored-partly-generated within a single JSON — a drift surface (see iter 2).

### F1.5 — Advisor ingestion: which graph-metadata fields are load-bearing
The advisor has TWO ingestion paths that both read skill-root graph-metadata.json:
1. **Compiler** (skill_graph_compiler.py) → skill-graph.json: emits `signals` from `intent_signals` + `derived.affordances.derived_triggers` only; emits `adjacency` from edges. It VALIDATES `domains`, `derived.trigger_phrases/key_topics/key_files/entities/source_docs/causal_summary` but does NOT compile them into the graph.
[SOURCE: skill_graph_compiler.py:984-991, 294-396, 939-963]
2. **Runtime scorer** (skill_advisor.py + lib/scorer/projection.ts): reads `domains`, `intent_signals`, `derived.trigger_phrases` (→derivedTriggers), `derived.key_topics+entities+key_files+source_docs` (→derivedKeywords), `derived.demotion`, `derived.redirect_to/redirect_from`, `derived.generated_at`. These ARE load-bearing for routing scores.
[SOURCE: skill_advisor.py:912-921, 1032-1040, 3277-3281; system-skill-advisor/mcp-server/lib/scorer/projection.ts:200-239]

**Inventory gap surfaced:** `derived.causal_summary`, `derived.supported_surfaces`, `derived.peer_resource_categories` are generated + validated but have NO routing consumer found (confirmed absent from both the compiler output and the scorer projection). `manual.related_to` / `manual.depends_on` appear authored but unused by either path. These are candidates for the optimization dimension (iter 2) — recorded here as inventory, not yet scored for leverage.

### F1.6 — Automation coverage summary (current state)
- **Fully generated (no hand-authoring):** leaf-manifest.json (H+S), leaf-aliases.json (S only).
- **Scaffolded then hand-maintained:** graph-metadata.json top-level fields (init_skill.py emits a template; backfill-graph-metadata.js regenerates the `derived` block), description.json, mode-registry.json, hub-router.json, command-metadata.json, leaf-manifest.config.json, leaf-aliases.json (H authored).
- **CI gates present:** ci-skill-root-metadata.cjs (presence/forbidden/freshness/command schema), ci-leaf-manifest-freshness.cjs (generated freshness), skill_graph_compiler.py --validate-only (graph-metadata schema), advisor-validate tool.
- **No CI gate found for:** cross-field consistency between graph-metadata.json `derived` and the SKILL.md frontmatter trigger_phrases (the scorer separately reads doc frontmatter trigger_phrases via _load_doc_trigger_phrases — a second, parallel signal source).
[SOURCE: skill_advisor.py:822-921; contract §5]
