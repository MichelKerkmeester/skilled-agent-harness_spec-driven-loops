The five checker holes the first pass recorded, closed. Every mutation is applied to a passing
copy of the whole package in a scratch directory, the whole check is run, and the copy is thrown
away rather than restored, so no mutation ever touched the tree. Exit status is read from $?
after redirecting to a file, never through a pipe.

Each mutation runs twice. Once against the checker as it now stands, where it has to fail. Once
against a copy of the checker with that one new assertion switched off, where it has to pass,
because a mutation that goes red proves only that something fired and the control is what says
which thing. A check written in the same pass as the thing it checks inherits the problem it was
built to fix unless each assertion is asked separately.
