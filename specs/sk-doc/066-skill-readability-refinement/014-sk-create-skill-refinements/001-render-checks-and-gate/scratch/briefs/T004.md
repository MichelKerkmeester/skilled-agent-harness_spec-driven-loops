One change in one file, plus its test.

File: .skilled/skills/sk-doc/shared/scripts/validate_document.py, function `_render_section_order` (starts near line 1089).

Problem: it decides a heading is "the related section" by substring. Line ~1120 uses `if wanted not in normalize_section_name(name)` and line ~1136 uses `if 'related' not in normalize_section_name(name)`. So "UNRELATED CHANGES", "CORRELATED SIGNALS" and "RELATED SPECS: UPDATE VS CREATE" are wrongly treated as the related section.

Edit:
1. Add a module-level helper `_is_related_section(name: str) -> bool` just above `_render_section_order`. It splits `normalize_section_name(name)` on `_` into tokens (drop empty tokens). It returns True only when the token `related` is present as a whole token AND every other token is in this closed set: and, references, resources, documents, docs, skills, material, catalog, entries, notes, links, further, reading. Give it a one-line docstring with the reason: a topical heading that merely contains the word must not be read as the related-resources section.
2. In the `if last_pattern:` block: when `normalize_section_name(last_pattern) == 'related'`, use `_is_related_section(name)` instead of the substring test. Keep the existing substring behavior for any other `lastSectionPattern` value (for example `machine_router`).
3. In the `if doc_type == 'skill_router':` block, replace `'related' not in normalize_section_name(name)` with `not _is_related_section(name)`.

Test: add to .skilled/skills/sk-doc/scripts/tests/test_render_checks.py, following the style of the existing tests in that file (read its first 60 lines and the test near `test_router_related_before_machine_router_is_ordered` first):
- a reference document whose H2s end `## 9. UNRELATED CHANGES` then `## 10. RELATED RESOURCES` raises no `render_section_order` finding;
- a reference whose `## 3. RELATED RESOURCES` is followed by `## 4. NOTES` still raises `render_section_order`;
- `## 8. RELATED SPECS: UPDATE VS CREATE` followed by another H2 raises no `render_section_order` finding.
