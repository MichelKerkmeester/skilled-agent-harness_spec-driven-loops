<!-- ANCHOR:problem -->
## 2. PROBLEM & PURPOSE

### Problem Statement
Hermes skill copies are generated by frontmatter name (`sync-skills-hermes.cjs:150-152`) and checked in CI by `command-tree-parity.yml:121`, but `/doctor:runtime-mirrors` lists eight checkers and not this one (`.skilled/commands/doctor/_routes.yaml:216-224`), so a local run reports in sync while CI fails. Separately, `skill-leaf-manifest-config-template.json:2` tells authors to keep the leaf roots "the skill's in-SKILL.md router actually routes into", though the machine router now lives in the sibling `ROUTER.md` (`skill-md-template.md:516`).

### Purpose
`/doctor:runtime-mirrors` reports Hermes skill drift the same way CI does, and no template tells an author the router lives in `SKILL.md`.
<!-- /ANCHOR:problem -->

<!-- ANCHOR:measured-behavior -->
### Measured Behavior
```text
$ rg -c "sync-skills-hermes" .skilled/commands/doctor/_routes.yaml .skilled/commands/doctor/assets/doctor-runtime-mirrors.yaml
exit 1
$ rg -n -o "in-SKILL.md router" .skilled/skills
.skilled/skills/sk-doc/sk-create-skill/assets/skill/skill-leaf-manifest-config-template.json:2:in-SKILL.md router
exit 0
```
Run in the worktree on 2026-10-30. A wider sweep over `.skilled/skills/*/assets`, `.skilled/skills/*/*/assets` and `.skilled/skills/system-spec-kit/templates` for router-in-SKILL.md phrasing found no other stale template; the remaining hits describe the sibling `ROUTER.md` correctly (for example `skill-md-template.md:516`, `skill-smart-router.md:26`).
<!-- /ANCHOR:measured-behavior -->

## 3. SCOPE

### In Scope
- Add `'node .skilled/skills/system-spec-kit/runtime/cli/hermes/sync-skills-hermes.cjs --check'` and `'node .skilled/skills/system-spec-kit/runtime/cli/hermes/sync-prompts-hermes.cjs --check'` to the runtime-mirrors route's `script_invocations` (`_routes.yaml:216-224`).
- In `doctor-runtime-mirrors.yaml`, add `hermes_skills` and `hermes_prompts` entries to `upstream_assets` (`:33-41`), a checker step for each beside the others (`:132-139`) that reports n/a when `.hermes/` is absent (decision D4), and a repair line for each beside the others (`:148-156`).
- Add a contract test asserting the route and the YAML both carry both checks.
- Replace "the skill's in-SKILL.md router actually routes into" in `skill-leaf-manifest-config-template.json:2` with wording that names the router in the sibling ROUTER.md, per D9.
- Rerun the template sweep and record it.

### Out of Scope
- Changing any other template - the sweep found no other stale wording.

### Files to Change

| File Path | Change Type | Description |
|-----------|-------------|-------------|
| `.skilled/commands/doctor/_routes.yaml` | Modify | Two `script_invocations` lines in the runtime-mirrors route |
