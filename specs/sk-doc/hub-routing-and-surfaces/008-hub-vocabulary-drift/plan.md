<!-- ANCHOR:architecture -->
## 3. ARCHITECTURE
<!-- FILL: Name the pattern in three words, then list the one component that changes. Name what fails today without each component you add, or drop it. GOOD: Single script branch. The component is `scripts/rotate-logs.sh`. WEAK: Standard architecture. -->

### Pattern
Source then derived. No component is added.

### Key Components
- **Root `ROUTER.md` of sk-doc and system-deep-loop**: the hand-edited source. Its `INTENT_SIGNALS` block is the only thing the hub vocabulary source check reads on the stage-two leg.
- **Hub `graph-metadata.json`**: derived. Without the regeneration the step "Router intent-signal carry" fails with `missing=9`.
- **system-deep-loop compiled-route manifest and its archive copy**: derived. Without the refresh `compiled-route-guard.cjs` reports system-deep-loop stale-manifest. sk-doc stays fresh.
- **Advisor `skill-graph.json`**: derived. Without the recompile `skill-graph-freshness.cjs --strict` reports SIGNAL DRIFT for sk-doc and system-deep-loop.
- **`local-native-approved-divergences.json`**: derived. The parity suite compares it with the live scorer, so it is recaptured after the graph changes.

### Data Flow
`hub-router.json` `vocabularyClasses` is the authored vocabulary and is not touched. The root `ROUTER.md` intents are checked against it. `generate-router-intent-signals.cjs` copies the multi-word `ROUTER.md` phrases into the hub `graph-metadata.json`. `skill_graph_compiler.py` compiles the hub metadata into `skill-graph.json`, which the advisor scorer and the parity fixtures read. `compiled-route-manifest.cjs` hashes the hub's routing inputs into the manifest.
