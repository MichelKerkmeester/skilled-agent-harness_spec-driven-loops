## Considered and rejected

- Fable's rule that tests be committed only where the task asks (`prompting-claude-fable-5-1.md:844`) as a repo-wide norm: it would relax the binding coverage floor that `.skilled/repo-rules/prevent-overengineering.md:130` points at `AGENTS.md` §3, and a rule may only tighten `AGENTS.md`.
- OpenAI's blanket user-over-skill precedence (`openai-gpt-6.md:83`) applied across the corpus: `REPO RULES.md:24` makes the hard blockers non-overridable even by operator instruction; only level-3 rule files yield to an instruction (`REPO RULES.md:25`).
- Anthropic's positive-phrasing rewrite ("tell what to do instead of what not to do", `claude-prompting-best-practices.md:341`): the bans here already name their replacement, e.g. `.skilled/repo-rules/communication-prose.md:92`, so rewriting thirteen files buys little and would itself be scope explosion.
- Opus 5.5's pasted-content tagging scheme (`prompting-claude-opus-5-5.md:135`): it is an API-harness integration, mechanics that `REPO RULES.md:90` deliberately excludes, while the behavioral stance already exists as `AGENTS.md:284`.
- Effort, thinking and token-budget configuration (`prompting-claude-opus-5-5.md` "Calibrate effort", `claude-prompting-best-practices.md` thinking migration): runtime plumbing, same exclusion at `REPO RULES.md:90`, and no behavior rule can set a parameter.
- GPT-6's banned-phrase and anti-contrast list (`openai-gpt-6.md` personality section) as hard rule text: `communication.md:105`–:120 already cuts stock register, and a standing banned-word list is exactly the over-prompting `claude-prompting-best-practices.md:528` warns now overtriggers.

## Contradictions inside the reviewed files

- `.skilled/repo-rules/communication.md:181` (no group above five items) versus `.skilled/repo-rules/communication-decisions.md:106` (state the approach in three to seven bullets): a model with a six-point approach either truncates it to five and hides planned work, or lists seven and breaches the cap it was also given.
- `.skilled/repo-rules/blast-radius.md:61` with `:73` (a new untracked file is trivially reversible: proceed, decide and move on) versus `.skilled/repo-rules/scope-discipline.md:80` (creating a file outside the named area always needs a yes): for a scaffold file just outside the named area the model either stalls on a one-line-revertable file or learns that new out-of-scope files are free to create.
- `.skilled/repo-rules/answer-the-actual-request.md:92` (never open a task with an unasked estimate) versus `.skilled/repo-rules/communication-decisions.md:121` (a long stretch carries a concrete time estimate): opening a long task in one turn both requires and forbids an estimate, so the model silently drops one rule and cannot say which.
- `.skilled/repo-rules/communication-prose.md:92` and `:99` (no em dash, no serial comma) versus `AGENTS.md:13` and `REPO RULES.md:48` (both top documents model exactly that punctuation): the model reading both either keeps the corpus's punctuation voice in replies while believing it compliant, or strips punctuation and diverges from every document whose style it imitates.
- `.skilled/repo-rules/communication.md:113` (naming a visible tool call is filler) versus `.skilled/repo-rules/communication-handoff.md:86` (name the command and its result before any interpretation): during multi-step work the model gets no consistent boundary between the two, so it oscillates between silent turns and narrated calls, and its close-out receipts look either absent or like the filler the other rule bans.
