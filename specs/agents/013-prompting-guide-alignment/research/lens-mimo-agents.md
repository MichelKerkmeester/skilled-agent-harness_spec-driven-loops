## Considered and rejected

- **Long-context layout (longform data at top, query at end)** (`claude-prompting-best-practices.md:244-247`): `AGENTS.md` is a fixed behavior preamble, not a query-plus-documents request (`AGENTS.md:3`), so prompt-assembly ordering has no home here.
- **Model self-knowledge strings** (`claude-prompting-best-practices.md:304`): runtime and model facts are explicitly kept out of this document (`AGENTS.md:225`) and it serves seven runtimes at once (`AGENTS.md:269`), so pinning one model identity would misidentify the other six.
- **Anti-formatting suppression block / "remove anti-formatting rules"** (`prompting-claude-fable-5-1.md:778`): there is no anti-formatting rule to remove, and the framework expects structured replies including tables and checklists (`AGENTS.md:135-147`, `AGENTS.md:189-194`); importing such a block would suppress structure Fable 5.1 needs.
- **Mannered-prose writing block** (`prompting-claude-fable-5-1.md:767`): voice is already bounded by "voice is not a performance" (`AGENTS.md:263`) and sentence mechanics belong to rule files (`communication-prose.md:133`), so a writing-class block would exceed the 3-line budget without an owner gap.
- **Frontend-aesthetics prompts** (`claude-prompting-best-practices.md:1020`, `prompting-claude-opus-5-5.md:159`): product-specific styling already has an owner, the repository's `REPO RULES.md` routing (`AGENTS.md:3`), and SCOPE LOCK keeps style rewrites out of unrelated changes (`AGENTS.md:14`).
- **Random-id `<pasted_content>` tagging** (`prompting-claude-opus-5-5.md:137-153`): it requires the application to wrap user input in generated tags, which an instruction file cannot do from inside the conversation, and `AGENTS.md:284` already covers the same threat behaviorally.

## Contradictions inside the reviewed files

- `AGENTS.md:47` vs `AGENTS.md:98` (with `AGENTS.md:65`): the preamble bars every tool call until the gates pass, but passing Gate 5 is itself a file read and Gate 1 mandates a node command. A literal reader either freezes at "no tools yet" or silently excepts the reads and then distrusts its own compliance for the rest of the session.
- `AGENTS.md:75` vs `AGENTS.md:16`: "Proceed with caveats" at 40–79% confidence authorizes acting while uncertain, but Law 4 orders an immediate stop on uncertainty. A cautious GPT-6-class model halts and asks in the exact band where the table wants action.
- `AGENTS.md:60` vs `AGENTS.md:107` (with `AGENTS.md:61`): the session-hold clause forbids re-asking Gate 3 outside four triggers, Violation Recovery mandates asking and waiting, and the child-dispatch exemption forbids emitting the question at all. A dispatched worker that notices a skipped gate either waits forever, asks a question nobody can answer, or breaks one of the two lines.
- `AGENTS.md:26` vs `AGENTS.md:28`: step 2 demands approval before proceeding when a named workflow blocks, step 4 says proceed and report the fix when it merely misfits, split by one clause about compliance. Combined with the stop-on-uncertainty law at `AGENTS.md:16`, a model will usually stop to ask even in step-4 cases where it should act.
- `AGENTS.md:283` vs `AGENTS.md:125`: the closing mandate asks for "the one thing that is the operator's to do" while Execution forbids ending on future work when a safe path exists. A model either invents an operator task to fill the template, ending the turn early, or grabs work that is genuinely the operator's (a push, an approval) to avoid naming one.
