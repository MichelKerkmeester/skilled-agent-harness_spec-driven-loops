## What Was Built

The orchestrator could previously read its own definition end to end and find nothing about external CLI
executors. That silence was the risk: nothing told it that an executor is the user's choice rather than
its own, that the skill route still owns the work once an executor is named, or that a run reporting
`COMPLETE` has only described itself. Rule 7 closes all three in one place.

### External CLI Delegation, opt-in by explicit user request

You get an orchestrator that will use `cli-opencode`, `cli-claude-code`, `cli-codex`, `cli-cursor`,
`cli-devin` or `cli-pi` when you name one, and will not reach for one when you have not. An advisor
score is not a request, and neither is a judgment that an external run would be faster.

Once you do name one, the rule keeps three things from slipping. The executor is the HOW and never
displaces the skill-owned route, so "use cli-codex" changes who runs the work and not which workflow
governs it, and the dispatch still carries a resolved agent persona rather than a bare task. The brief must pre-resolve every gate the external run cannot ask you about, because nobody
is at its prompt: a gate that waits, waits forever and then reports success. And what comes back is a
claim to check, not a result to quote - including the exit status, which has been wrong in both
directions.

## How It Was Delivered

Every one of the seven semantics was checked against the file that owns it before it was written, not
taken from the request: GATE 4 against `AGENTS.md:118-119`, the preload and self-invocation rules
against the hub `SKILL.md:170` and `:177`, and the sandbox facts against `cli-codex/SKILL.md:260,294`
and `cli-cursor/SKILL.md:216`.

The edit was authored by hand in the two real files, then the `.codex` and `.pi` mirrors were
regenerated by their sync scripts - neither was hand-edited. Verification then ran in two layers: four
mirror gates for propagation and three `sk-doc` validators per hand-edited file for document quality,
each exit code read directly rather than through a pipe. Finally all six runtime surfaces were grepped
for the rule text, because a mirror gate proves the files agree and only the grep proves they agree on
the thing that was added.

The work lands as two commits: the generator correction and its regenerated mirrors first, so the
mirror gates are green before anything depends on them, then Rule 7 across the four agent surfaces
together with this packet.

## Known Limitations

1. **One unrelated line rides along in `.codex/agents/debug.toml`.** A trailing blank line was already
   stale at HEAD, so any codex sync run corrects it. Reverting it was tested and turns the codex
   `--check` gate red, so it stays. It is a one-line deletion in a generated file and was not authored
   here.
2. **`sk-create-agent` names no mirror obligation.** Its ordered creation workflow and validation gate
   mention neither the `.claude` fork, the generated `.codex`/`.pi` mirrors, nor the symlinked
   `.cursor`/`.devin` surfaces. Following that skill alone produces a one-surface edit that passes every
   check the skill lists. Out of scope to fix here.
3. **The scaffolder writes a `scaffold/` packet pointer.** Both scaffolded docs arrived with
   `packet_pointer: "scaffold/008-..."` and were corrected by hand to `agents/008-...`. Sibling 007 shows
   the same defect half-corrected, which is why its two pointers disagree.
4. **The codex regeneration flipped `sandbox_mode`, and the direction is not this packet's to set
   (recorded 2026-09-02).** Regenerating `.codex/agents/orchestrate.toml` changed its header from
   `sandbox_mode = "workspace-write"` to `sandbox_mode = "read-only"`. That is a pre-existing drift this
   packet surfaced rather than caused: the generator's own table has said
   `orchestrate: { sandboxMode: 'read-only' }` since 2026-07-13 (`8e292e451`), while the committed TOML
   was hand-set to `workspace-write` on 2026-08-31 by `ace6d0ee66`, and `8a68a106` later touched the
   same file. The value has been out of step with its generator ever since. The diff therefore carries a
   real runtime-behaviour change for the Codex runtime - a read-only orchestrator cannot write - and its
   direction was chosen by the generator, not by this work. **Resolved 2026-09-02: the operator chose
   `workspace-write`, and the generator's table was corrected to say it, so generator and mirror now
   agree.** Regeneration no longer moves `sandbox_mode`, and the Codex orchestrate runtime keeps the
   write access it has held since `ace6d0ee66`.

5. **Rule 7 is documentation, so nothing enforces it mechanically.** No script checks that a dispatch
   named an executor the user asked for; the rule binds the reading agent, not a gate.
