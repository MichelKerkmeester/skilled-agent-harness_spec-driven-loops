## 1. SUMMARY

### Technical Context

| Aspect | Value |
|--------|-------|
| **Language/Stack** | Markdown (agent definitions) + generated TOML |
| **Framework** | OpenCode / Claude Code runtime agent loading |
| **Storage** | None |
| **Testing** | `sk-doc` validators + four agent-mirror gates |

### Overview
Add exactly one capability to the `orchestrate` agent: external CLI delegation, opt-in by explicit user
request. The edit is authored by hand in the canonical `.opencode` file and applied identically to the
`.claude` fork, then the `.codex` and `.pi` mirrors are regenerated by their sync scripts and the
`.cursor`/`.devin` symlinks inherit the change for free. The rule points at the
`cli-external-orchestration` hub rather than restating it, so the hub stays the single source of truth.

<!-- ANCHOR:architecture -->
## 3. ARCHITECTURE

### Pattern
Canonical source plus mirrors: one hand-authored definition, one hand-maintained fork, two generated
mirrors, two per-file symlinks.

### Key Components
- **`.opencode/agents/orchestrate.md`**: canonical agent definition; the edit originates here.
- **`.claude/agents/orchestrate.md`**: a real forked copy, hand-edited in the same commit.
- **`codex/sync-agents.cjs` / `pi/sync-agents-pi.cjs`**: generators that write the `.codex` and `.pi`
  mirrors; both refuse to be hand-edited and both offer a `--check` drift mode.
- **`cli-external-orchestration/SKILL.md`**: the hub Rule 7 points at; owner of the six mode packets.

### Data Flow
Hand edit lands in `.opencode` and `.claude`; the sync scripts read those and rewrite `.codex` and
`.pi`; `.cursor` and `.devin` resolve through per-file symlinks into `.claude`, so all six surfaces
carry one text.
<!-- /ANCHOR:architecture -->
