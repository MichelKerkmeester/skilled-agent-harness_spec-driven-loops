# Implementation Summary: Retire the decommissioned code-index tool from the review agents and their documentation

<!-- SPECKIT_LEVEL: 1 -->

---

<!-- ANCHOR:outcome -->
## 1. OUTCOME

Every live reference to the retired tool is gone, and all twelve agent mirrors report in sync.

The ordering was the substance of the work. The canonical `.opencode` agents changed first, the Codex and Pi mirrors were regenerated by their own sync scripts, and the Claude dialect files were edited because they are authored per-dialect rather than generated. An earlier attempt that edited only the Claude mirrors failed the commit gate, which is what sent this work to its own packet.
<!-- /ANCHOR:outcome -->

---

<!-- ANCHOR:what-shipped -->
## 2. WHAT SHIPPED

| Surface | Change |
|---|---|
| Both canonical review agents | Permission grant, review-methodology prose and tool-table rows removed |
| Claude, Codex, Pi mirrors | Claude edited as an authored dialect, Codex and Pi regenerated by their sync scripts |
| Review skill | Two preflight steps removed and the remainder renumbered |
| Review playbook | The scenario built on the tool deleted, its category removed, sections and waves renumbered, hand-typed census corrected |
| Mirror verifier | The tool alias removed, leaving the registry empty with its purpose documented |
| Route-guard test | Fixture swapped from the retired server to one that exists |

The verifier's alias registry was emptied rather than deleted. It maps a tool's per-runtime spellings so the same tool does not read as drift across a mirror pair, which is a real mechanism worth keeping. The comment now says what it is for and why it is empty.

<!-- ANCHOR:deviations -->
## 4. DEVIATIONS AND DECISIONS

**One test was removed and not replaced.** The deep-loop suite had a case asserting that a mirror whose body mentions a registered tool must also declare it. That case could only be exercised through a registry entry, and the registry is now empty. The alias map is not exported, so a test cannot inject its own fixture without changing the module's interface, which is a redesign this packet did not ask for. The mechanism and its documentation stay; its coverage does not. Anyone adding the next entry should restore a case alongside it.

**Two surfaces were left alone on purpose.** The spec-kit changelog entry and the benchmark reports describe the server as it was, and they are accounts of a moment rather than live wiring. Editing them would destroy the record this packet depended on to establish that the server had in fact been decommissioned.

**Scope reached past the agents.** The inventory found the tool in the review skill, its playbook and the mirror verifier as well. Removing only the agent references would have left a playbook scenario claiming to test a capability that cannot exist, so the packet covers every live surface rather than only the one it was named for.
<!-- /ANCHOR:deviations -->
