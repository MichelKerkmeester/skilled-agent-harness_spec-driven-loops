It measures **advisor-routing accuracy**: whether a prompt in the skill's projection-intent vocabulary, such as "make CLI output readable", routes to `sk-communication` as the advisor's top match. The harness is the skill-advisor scorer (`system-skill-advisor/runtime/scripts/skill_advisor.py`), runs are produced by the Lane C harness (`run-skill-benchmark.cjs --skill sk-communication`, which reads the skill's manual-testing playbook as its default corpus), and each run is captured as a dated folder under `reports/`. The README is careful to scope this: the underlying `cli-communication-projection` package is *not* measured here, it is verified separately by its own `npm run check` gate.

The same folder holds a second, separate instrument. `reply-harness/` measures reply quality rather than routing. It compares replies produced under a before rule set (assembled from a recorded commit) against replies produced under the after rule set (the working tree), using a frozen case set with a negative control, a seven-dimension weighted rubric with one blocking class, deterministic per-case predicates, and blinded replies so a judge scores without knowing which side is which. The comparison reports per-dimension deltas and exits non-zero if the control moved or a blocking class fired. No script in that harness calls a model, the model step is the operator's.

Nothing here needs anything from you.
