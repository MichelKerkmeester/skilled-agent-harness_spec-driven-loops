The canonical retry policy for network and API calls lives in `.opencode/skills/system-spec-kit/shared/utils/retry.ts`. Its `DEFAULT_CONFIG` (lines 14-19) sets 3 retries with exponential backoff between 1s and 4s, and `classifyError` decides transient versus permanent by HTTP status code, network error code and message pattern before `retryWithBackoff` acts on it. The two embedding providers, `voyage.ts` and `openai.ts`, both import `retryWithBackoff` from this file, so it is the one policy rather than one of several duplicates. The module's own README calls it out directly: "Retry policy, backoff and error classification" (`shared/utils/README.md:32`).

Two other things share the name but answer a different question. `repo-rules/root-cause-and-debugging.md` caps local debugging retries at three failed fixes for the same symptom before you escalate. That governs agent behavior, not code. And `system-skill-advisor/runtime/lib/utils/busy-retry.ts` retries on SQLite lock contention, a separate concern from the HTTP retry policy above.
